# 局域网桌面实时共享工具设计

## 1. 目标

创建一个可在本机启动的轻量网页工具。分享者在浏览器中选择桌面、窗口或标签页后，同一局域网内的 1–5 位同事可通过随机观看链接实时查看画面。

工具只传输视频画面，不采集声音，不录制文件，不把画面上传至外网，也不提供远程控制能力。

## 2. 使用场景与边界

### 2.1 目标场景

- 分享者的电脑可运行 Node.js。
- 分享者和观看者位于同一个可互访的局域网。
- 分享者使用 `localhost` 打开分享页，以满足浏览器屏幕捕获的安全上下文要求。
- 观看者使用现代 Chrome 或 Edge 打开局域网链接，无需安装额外软件。
- 同时观看人数为 1–5 人。

### 2.2 非目标

- 不支持跨公网观看、云端中转或 NAT 穿透保障。
- 不保存、回放或下载录屏。
- 不采集系统声音或麦克风。
- 不提供账号系统、聊天、标注或远程控制。
- 不绕过浏览器授权、公司防火墙、访客 Wi-Fi 隔离或终端安全策略。

## 3. 方案选择

采用 WebRTC 点对点视频传输与 Node.js WebSocket 信令。

选择理由：1–5 人规模下，WebRTC 能以较低延迟直接传输浏览器捕获的视频，服务器只协调连接，不承担视频转发或存储。代价是每位观看者会增加一份分享者的上行带宽和编码压力；该代价在目标规模内可接受。

不采用连续截图转发，因为其帧率、带宽效率和观看体验较差。不采用 OBS/RTMP，因为部署与操作成本超出轻量网页工具的目标。

## 4. 系统架构

### 4.1 静态与信令服务

`server.js` 使用 Node.js 提供以下能力：

- 监听 `0.0.0.0:4173`，使局域网设备可以访问。
- 提供 `index.html`、本地编译的 Tailwind CSS 与浏览器脚本。
- 提供本机可用的局域网 IPv4 地址，帮助页面生成观看链接。
- 通过 WebSocket 转发加入房间、WebRTC offer、answer、ICE candidate、分享结束等信令。
- 仅在内存中保存房间和连接映射；进程退出后全部清除。

服务端不接收 MediaStream，不写入视频、截图或会话日志文件。

### 4.2 浏览器应用

同一页面根据 URL 状态切换两种角色：

- 分享端：默认角色。生成房间密钥，申请屏幕捕获权限，为每位观看者建立独立的 `RTCPeerConnection`，显示本地预览、观看人数和观看链接。
- 观看端：通过包含角色和房间密钥的链接进入。加入房间后接收 WebRTC 视频轨道并自适应播放，只提供观看状态与重新连接操作。

浏览器逻辑按职责拆分为状态展示、信令客户端、分享端连接管理和观看端连接管理。各模块通过明确的事件与消息结构交互，避免把连接状态和界面更新混在单个大函数中。

### 4.3 样式

HTML 使用 Tailwind CSS。样式在本地构建并由 Node 服务提供，运行时不依赖 CDN 或其他外网资源。

## 5. 数据流

### 5.1 创建分享

1. 分享者访问 `http://localhost:4173`。
2. 页面使用 Web Crypto API 生成至少 128 位随机房间密钥。
3. 分享者点击“开始共享”。
4. 页面调用 `navigator.mediaDevices.getDisplayMedia({ video: true, audio: false })`。
5. 浏览器显示原生选择器，分享者主动选择屏幕、窗口或标签页。
6. 授权成功后，页面连接信令服务、注册房间并生成局域网观看链接。

### 5.2 观众加入

1. 观看链接把 `role=viewer` 和房间密钥放在 URL fragment 中，避免密钥随普通 HTTP 请求发送。
2. 观看页从 fragment 读取信息，通过 WebSocket 主动加入对应房间。
3. 服务端把观看者的临时连接 ID 通知分享端。
4. 分享端为该观看者新建一个 `RTCPeerConnection`，添加当前视频轨道并发送 offer。
5. 观看端返回 answer；双方经信令服务交换 ICE candidate。
6. WebRTC 连接建立后，画面直接在两台设备之间传输。

### 5.3 停止与重连

- 分享者点击停止、关闭页面或浏览器停止共享时，分享端停止媒体轨道、关闭全部 PeerConnection，并广播分享结束状态。
- 观看页刷新后重新加入房间，分享端为它创建新的 PeerConnection。
- WebSocket 短暂断开时，页面进行有限次数的自动重连；超过次数后显示可操作的重试按钮。
- 单个观看者断开只清理对应 PeerConnection，不影响其他观看者。

## 6. 信令协议

所有消息使用 JSON，并包含 `type`。与房间相关的消息还包含 `roomId`；点对点消息包含服务端分配的 `clientId`。

主要消息类型：

- `host-room`：分享端注册房间。
- `join-room`：观看端加入房间。
- `viewer-joined` / `viewer-left`：服务端通知分享端更新连接和人数。
- `offer` / `answer`：交换 WebRTC 会话描述。
- `ice-candidate`：交换 ICE candidate。
- `share-ended`：通知观看端分享已停止。
- `room-unavailable`：房间不存在、分享端尚未就绪或已结束。
- `error`：协议错误或角色不合法。

服务端校验消息结构、角色和目标连接，不向房间外转发消息。单条消息设置合理大小上限，防止异常客户端发送超大负载。

## 7. 安全与隐私

- 浏览器屏幕授权必须由分享者点击触发；页面不能静默开始捕获。
- 房间密钥由安全随机数生成器产生，不使用可枚举的短数字房间码。
- 房间密钥位于 URL fragment；Web 服务器访问日志不会自动收到该值。
- 信令和房间状态只保存在内存中，媒体数据不经过 Node 服务。
- 默认不保存应用级访问日志中的完整 URL、房间密钥或 WebRTC 描述。
- 页面不请求音频权限，WebRTC 中不添加音频轨道。
- 工具不配置路由器端口映射，也不主动暴露到公网。
- 随机链接属于访问凭据，分享者应只发给需要观看的同事，并在完成后停止服务。

该安全模型适合可信局域网内的短时共享，但不等同于企业账号鉴权。如果网络本身不可信，应停止使用而不是依赖随机链接承担完整身份认证。

## 8. 界面设计

### 8.1 分享端

- 显示“开始共享”主按钮。
- 共享后显示本地画面预览、当前状态和观看人数。
- 显示观看链接及“复制链接”按钮。
- 显示“停止共享”按钮，并对停止动作给出清晰结果。
- 页面关闭前在存在活动共享时给出浏览器允许范围内的离开提醒。

### 8.2 观看端

- 初始显示“正在连接”。
- 连接成功后以保持宽高比的方式显示视频，适配桌面和移动浏览器窗口。
- 房间未开始、链接无效、网络中断和分享结束分别显示不同状态。
- 可恢复错误提供“重新连接”按钮；分享结束不无限自动重试。

### 8.3 可访问性与反馈

- 控件具有明确文本和键盘焦点样式。
- 状态变化通过可读文本呈现，不只依赖颜色。
- 复制链接、权限拒绝和连接失败均提供即时反馈。
- 深色背景突出桌面画面，同时保证文字和控件对比度。

## 9. 异常处理

- 浏览器不支持 `getDisplayMedia`：提示改用最新版 Chrome 或 Edge。
- 用户拒绝或取消屏幕选择：保持未共享状态并允许重新点击。
- 找不到可用局域网 IPv4：保留服务地址输入或提示用户手动替换链接主机名。
- 观看者早于分享开始加入：显示等待状态；房间建立后允许重新连接。
- PeerConnection 进入 `failed`：关闭该连接并进行一次完整重建，仍失败则提示检查同网互访、防火墙和 Wi-Fi 隔离。
- 分享轨道触发 `ended`：执行与“停止共享”相同的清理路径。
- 服务端收到畸形或越权消息：拒绝并关闭异常连接，不影响其他房间参与者。

## 10. 验证策略

### 10.1 自动化验证

- 对房间创建、加入、离开、错误路由和分享结束的信令逻辑做 Node 单元测试。
- 对随机房间密钥格式、观看链接生成和 fragment 解析做单元测试。
- 对不合法消息、超大消息和错误角色做边界测试。
- 执行 HTML/JavaScript 格式检查、静态检查和 Tailwind 构建。

### 10.2 手工主流程验证

1. 在分享电脑的 Chrome 中通过 `localhost` 打开页面并选择一个窗口。
2. 在同一局域网的另一台设备上打开观看链接。
3. 确认画面实时更新、没有声音、服务端目录没有媒体文件。
4. 增加至 5 个观看窗口，确认人数准确且单个观众退出不影响其他人。
5. 刷新一个观看页，确认能够重新加入。
6. 分别测试浏览器“停止共享”、页面停止按钮和关闭分享页，确认所有观看端进入结束状态。
7. 测试权限拒绝、无效链接和断网重连提示。

自动化测试不能替代跨设备浏览器验证。最终交付会区分本机自动化证据与真实局域网多设备验证结果。

## 11. 验收标准

- 执行启动命令后，分享端可从 `http://localhost:4173` 打开。
- 分享者可选择屏幕、窗口或标签页，并随时停止。
- 同一可互访局域网中的 1–5 位观看者可通过随机链接实时观看。
- 媒体流只包含视频轨道，不包含音频轨道。
- Node 服务不保存、不转发媒体内容，项目目录不产生录屏文件。
- 新观众可加入，观众刷新可重连，单个观众离开不影响其他人。
- 分享停止后，所有观看端收到结束状态且连接被清理。
- Chrome/Edge 主流程通过，自动化测试、静态检查与 Tailwind 构建通过。
