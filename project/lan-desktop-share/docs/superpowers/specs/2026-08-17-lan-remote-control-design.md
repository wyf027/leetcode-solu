# 局域网桌面远程控制扩展设计

## 1. 文档状态与关系

- 状态：已完成对话设计确认，等待书面规格审核。
- 基础设计：`2026-08-14-lan-desktop-share-design.md`。
- 本文扩展现有的局域网只看画面工具，并取代基础设计中“远程控制属于非目标”的约束。
- 基础设计中的局域网限制、1–5 位观看者、视频点对点传输、无声音、无录制、无公网中转和随机房间链接等约束继续有效。

## 2. 目标

在现有 WebRTC 桌面观看功能上增加可选的 macOS 远程控制：一位观看者可以申请控制，分享者在本机明确批准后，观看者可在共享视频上执行鼠标移动、点击、拖动、滚动和受限键盘输入。

控制功能必须保持以下属性：

- 默认关闭；没有分享者的逐次批准不能产生本机输入。
- 同一时间最多一位控制者，其他 1–4 位观看者继续只看画面。
- 控制不可用或发生故障时，现有观看功能继续工作。
- 控制数据不保存、不写入日志，也不经过外部服务。
- macOS 原生助手不监听网络，仅接受本机 Node 进程通过标准输入发送的白名单事件。

## 3. 平台与范围

### 3.1 支持范围

- 分享端操作系统：macOS。
- 分享端浏览器：最新版 Chrome 或 Edge，通过 `http://localhost:4173` 打开。
- 控制端浏览器：桌面版 Chrome 或 Edge，可运行在 macOS 或 Windows。
- 手机浏览器可以继续观看，但第一版不提供触控远程操作。
- 分享电脑必须仅有一个活动显示器，且浏览器选择器中必须共享整个显示器。
- 分享电脑需要安装 Xcode Command Line Tools 或其他可用的 Swift 工具链，以构建本地助手。
- 分享者需要在 macOS“隐私与安全性 → 辅助功能”中允许本地控制助手产生输入事件。

### 3.2 非目标

- 不支持 Windows 或 Linux 分享端。
- 不支持多个活动显示器、窗口共享或浏览器标签页共享下的远程控制。
- 不提供无人值守控制、永久授权、账号鉴权或跨公网控制。
- 不提供声音、聊天、录制、回放、下载、剪贴板同步或文件传输。
- 不转发 Command、Control 或 Option 组合键、功能键、媒体键、亮度键、电源键或其他系统级快捷键。
- 不保证兼容移动端触控、游戏、绘图板、压力感应或高频实时操控场景。

## 4. 方案选择

采用 WebRTC DataChannel、现有 Node 服务和 Swift 命令行助手的三段式架构。

未采用 Node 原生自动化库，因为其二进制依赖容易受到 Node 与 macOS 版本影响，并且会把输入注入能力直接放进对局域网开放的 Node 服务进程。未采用 macOS 屏幕共享或 VNC，因为它们需要独立账号或系统配置，无法保留当前随机链接、浏览器申请和分享端逐次批准的交互。

## 5. 系统架构

### 5.1 观看端控制客户端

每个观看者沿用现有 `RTCPeerConnection` 接收视频。连接协商时，分享端为该连接创建一个标签为 `lan-control-v1` 的 `RTCDataChannel`，用于该观看者与分享端交换控制申请、授权状态和输入事件。

观看端职责：

- 发起或取消控制申请。
- 仅在收到有效授权租约后监听远程视频区域的指针和键盘事件。
- 把视频内容区域中的位置转换为 `0–1` 的归一化坐标。
- 忽略视频 `object-fit: contain` 产生的黑边区域，不把黑边点击发送给分享端。
- 在视频失焦、页面隐藏、DataChannel 关闭或用户点击“结束控制”时停止发送输入。
- 不读取本地剪贴板，不上传文件，不发送浏览器或操作系统保留快捷键。

### 5.2 分享端控制协调器

分享端仍为每位观看者维护独立的 WebRTC 会话，并新增控制协调器管理全房间唯一的控制租约。

分享端职责：

- 接收并展示观看者的控制申请。
- 在分享者点击“允许 10 分钟”后，请求 Node 建立短期控制租约。
- 只接受当前获批观看者、当前租约和单调递增序号匹配的输入消息。
- 把通过第一层校验的消息转发给同一个本机 WebSocket 连接上的 Node 服务。
- 在授权超时、主动撤销、断线、页面隐藏、共享轨道结束或页面卸载时执行统一清理。
- 将控制状态同步给当前控制者和其他观看者，但不泄露房间密钥或本地权限信息。

### 5.3 Node 控制桥接层

现有 Node 服务继续监听 `0.0.0.0:4173` 以提供页面和信令，但控制命令采用更严格的入口规则：

- 只有远端地址为 `127.0.0.1` 或 `::1`、已注册为当前房间分享端的 WebSocket 才能创建、发送或终止控制租约。
- 局域网观看者不能通过 WebSocket 直接调用控制桥接层；其输入必须先经过获批的 WebRTC DataChannel 和分享端浏览器。
- 分享端可发送 `control-probe`。Node 以 `--probe` 模式短暂启动助手，读取一次平台、构建、辅助功能权限和活动显示器状态后立即退出；探测模式不能注入输入。
- 多屏时分享端必须发送带随机 `requestId` 的 `control-identify`，助手在各活动显示器短暂显示编号；Node 只在识别成功后签发内存态 `bindingId`。分享者选择正在共享的编号后，`control-start` 必须同时携带对应 `displayId` 和 `bindingId` 才能创建租约。
- 每个房间最多一个控制租约；租约包含随机标识、观看者连接 ID、签发时间和最长 10 分钟的过期时间。
- Node 对消息大小、协议版本、租约、观看者 ID、序号、事件类型、坐标、文本长度和速率进行第二层校验。
- Node 仅在创建控制租约时启动 Swift 助手，并通过换行分隔 JSON 写入助手标准输入。
- Node 不把房间密钥、租约标识、键盘内容或输入事件写入日志。
- 租约结束时 Node 先发送 `releaseAll`，随后关闭助手标准输入并终止子进程；助手未按时退出时再强制结束该具体子进程。

### 5.4 macOS Swift 助手

Swift 助手是 Swift Package Manager 管理的命令行程序，使用 ApplicationServices/Core Graphics 完成本机输入注入。

助手职责：

- 支持只读的 `--probe`、短时 `--identify` 和显式显示器绑定的租约会话模式；探测与识别模式不读取或执行输入命令。
- 启动时确认操作系统为 macOS、辅助功能权限可用，并校验分享者选择的活动显示器仍存在。
- 读取标准输入中的受限 JSON 行；不创建 TCP、UDP、Unix Socket 或其他网络监听入口。
- 使用已绑定显示器的 Core Graphics 边界，把归一化坐标映射为该屏幕的全局显示器坐标。
- 租约期间监测显示器列表、边界、旋转和镜像关系；配置变化时释放全部输入并退出，由 Node 撤销租约。
- 使用 `CGEvent` 产生鼠标移动、左右键按下/释放、拖动、滚轮、受限按键和 Unicode 文本事件。
- 跟踪已按下的鼠标按钮和按键，在 `releaseAll`、标准输入关闭、解析错误或进程退出前尽可能全部释放。
- 拒绝未知命令、超长行、越界值和不在白名单内的键盘事件。

助手不负责房间、观看者、授权和网络身份判断；这些职责属于浏览器协调器与 Node 控制桥接层。

## 6. 控制协议

### 6.1 DataChannel 消息

所有消息是小型 JSON 对象，包含 `v: 1` 和 `type`。单条序列化消息不得超过 1024 字节。

主要消息：

- `control-request`：观看者申请控制。
- `control-cancel`：观看者取消尚未处理的申请。
- `control-pending`：分享端确认已收到申请。
- `control-granted`：分享端返回租约标识和过期时间。
- `control-denied`：分享端拒绝申请或当前已有控制者。
- `control-revoked`：分享端通知租约已结束及通用原因。
- `control-input`：获批观看者发送序号、租约标识和单个输入事件。

DataChannel 使用可靠、有序模式，避免按键释放排在按键按下之前。指针移动事件在观看端进行合并：动画帧内只发送最新位置，积压时丢弃旧的移动事件，而不丢弃按键或按钮释放事件。

### 6.2 Node 与助手消息

分享端到 Node 的控制消息复用本机分享端 WebSocket，但与现有房间信令使用不同消息类型：

- `control-probe`：以只读方式检查助手、权限和显示器状态。
- `control-capabilities`：Node 返回探测结果及一个不含本机敏感信息的通用不可用原因。
- `control-identify` / `control-identified`：通过 `requestId` 关联请求与响应，短暂显示并返回经过清理的屏幕编号列表及内存态 `bindingId`。
- `control-start`：携带分享者选择的 `displayId` 和本房间、本分享者最近一次识别得到的 `bindingId` 创建租约并启动助手；助手还会复核识别时的显示器配置签名。
- `control-event`：提交已获批事件。
- `control-stop`：撤销租约并释放全部输入。

Node 到 Swift 助手使用换行分隔 JSON：

- `mouseMove`：`x`、`y` 为 `0–1` 数值。
- `mouseButton`：`button` 为 `left` 或 `right`，`state` 为 `down` 或 `up`。
- `scroll`：有限范围内的横向和纵向增量。
- `key`：仅允许导航与编辑白名单键的按下和释放。
- `text`：最多 32 个 Unicode 标量的已提交文本。
- `releaseAll`：释放当前追踪的全部按键与按钮。

## 7. 输入白名单与限流

### 7.1 鼠标

- 支持移动、左键、右键、按住拖动和滚轮。
- 不支持中键、额外鼠标键、手势、压力或指针锁定。
- 指针坐标必须是有限数且位于 `0–1`；Node 和助手都会裁剪或拒绝越界值。
- 指针移动最高 60 条/秒；按钮与滚轮合计最高 30 条/秒。

### 7.2 键盘

- 支持普通已提交文字、方向键、Enter、Tab、Backspace、Delete、Escape、Home、End、PageUp 和 PageDown。
- 文本输入通过已提交 Unicode 文本传输，使英文、数字、常用符号以及观看端输入法最终提交的文字可用。
- 不转发 Meta、Control 或 Option 修饰组合，不转发 F1–F20、媒体键、亮度键和电源相关按键。
- 键盘与文本事件合计最高 30 条/秒；单条文本最多 32 个 Unicode 标量。

超出速率、消息大小或白名单的事件被丢弃；持续违规会撤销当前控制租约，但不会中断视频观看。

## 8. 控制前置条件

只有以下条件全部满足时，“允许控制”按钮才可用：

1. 分享端页面通过 `localhost` 打开，控制 WebSocket 的对端地址是回环地址。
2. 分享端操作系统是 macOS。
3. Swift 助手已构建且能够启动。
4. 助手报告辅助功能权限可用。
5. 助手报告活动显示器数量恰好为一个。
6. 屏幕视频轨道 `getSettings().displaySurface` 明确返回 `monitor`。
7. 当前没有其他控制租约。

如果浏览器没有提供 `displaySurface`，或者返回 `window`、`browser`，控制保持禁用。W3C Screen Capture 标准不提供可映射至 macOS 显示器 ID 的稳定标识，因此多个活动显示器时不允许通过人工确认绕过此限制。

## 9. 控制状态机与生命周期

房间级控制状态为：

- `unavailable`：平台、权限、助手、显示器或捕获类型不满足条件。
- `idle`：可以接收申请，但没有当前控制者。
- `requested`：存在一个待处理申请；后续申请立即收到忙碌响应。
- `granting`：Node 正在创建租约和启动助手。
- `active`：唯一控制者可以发送输入，租约倒计时运行。
- `revoking`：正在停止输入、执行 `releaseAll` 并关闭助手。
- `error`：助手或协议异常；完成清理后回到 `idle` 或 `unavailable`。

以下任一事件必须撤销租约：

- 分享者点击“立即停止控制”。
- 控制者点击“结束控制”。
- 10 分钟租约到期。
- 控制者 DataChannel、PeerConnection 或 WebSocket 断开。
- 分享端 WebSocket 断开、页面隐藏、页面卸载或共享轨道结束。
- Swift 助手退出、标准输入写入失败或权限状态失效。
- 持续出现无效、越权或超限控制消息。
- Node 服务收到退出信号或进程结束。

清理操作必须幂等；多条结束路径同时触发不能启动新助手，也不能留下仍被追踪的按键或鼠标按钮。

## 10. 界面设计

HTML 继续使用本地构建的 Tailwind CSS，并保持现有深色 WebRTC 控制台视觉语言。

### 10.1 分享端

- 未满足前置条件时显示“远程控制不可用”，并给出单一、具体的修复提示，例如构建助手、授予辅助功能权限、断开副屏或改为共享整个显示器。
- 收到申请时显示“观看者 #N 申请控制”，提供“允许 10 分钟”和“拒绝”。观看者编号来自当前房间连接顺序，不承诺真实身份。
- 授权期间在页面顶部固定显示红色状态条，包含当前控制者、剩余时间和“立即停止控制”。状态不能只通过颜色表达。
- 停止共享按钮继续终止视频，同时无条件终止控制。
- 终端 `Ctrl+C` 停止 Node 服务时也会触发助手清理，作为页面不可操作时的最终停止方式。

### 10.2 观看端

- 视频连接成功后显示“申请控制”；已有其他控制者时按钮禁用并显示原因。
- 申请状态区分等待、获批、拒绝、超时、被撤销和连接中断。
- 获批时只有视频实际内容区域可以产生控制事件，并显示明显的焦点边框和“正在控制”状态。
- 提供“结束控制”按钮；视频失焦、页面隐藏或连接中断时立即停止发送输入。
- 控制不可用不影响视频播放、重新连接或只看画面的状态提示。

## 11. 安全模型

- 随机观看链接仍是房间访问凭据，但不是身份系统；“观看者 #N”不能证明同事身份。
- 分享者必须在本机逐次批准，每次授权最长 10 分钟，不保存永久允许列表。
- 视频与控制消息通过 WebRTC 点对点传输；WebRTC DataChannel 使用其标准加密传输。
- 控制注入入口只接受已注册的回环分享端 WebSocket，局域网连接不能直接调用 Swift 助手。
- Swift 助手没有网络监听面，不接收房间密钥，也不解析 WebRTC 或 WebSocket 协议。
- 输入内容、租约标识、完整观看链接、房间密钥和 WebRTC 描述不写入日志或磁盘。
- 辅助功能权限是一项高权限本机授权；README 必须明确说明如何撤销，并建议不用时停止服务。
- 工具适用于可信局域网内的短期协作，不应暴露端口到公网，也不替代企业远程运维产品的账号、审计和设备策略。

## 12. 异常处理

- 助手未构建：分享端显示构建命令，观看功能正常。
- Swift 工具链缺失：提示安装 Xcode Command Line Tools，不自动安装系统软件。
- 辅助功能权限缺失：助手只报告不可用，不注入事件；页面提示授权并要求重新启动服务后重试。
- 多个活动显示器：要求分享者先显示编号并绑定共享中的屏幕；未绑定时控制禁用。
- 租约期间显示器配置变化：立即释放输入并撤销控制，要求重新检测和绑定。
- 共享窗口、标签页或浏览器未报告捕获类型：控制禁用，观看继续。
- 申请时已有控制者：新申请立即拒绝并显示“当前有人控制”。
- DataChannel 未打开或积压：不授权控制或主动撤销，避免在恢复后重放旧输入。
- 助手崩溃或标准输入异常：Node 撤销租约，尝试清理具体子进程，并通知双方；视频连接不关闭。
- 无效或未知输入：单次丢弃并计数，持续违规撤销租约。
- 分享端或服务退出：执行幂等 `releaseAll`，关闭所有租约和 PeerConnection。

## 14. 验证策略

用户明确要求不为远程控制功能编写新的自动化测试。实施时遵循这一约束，不新增远程控制测试文件或测试用例，也不删除现有 27 项观看功能测试。

### 14.1 自动化与静态门禁

- 运行现有 `npm run check`，确认 Tailwind 构建、ESLint、Prettier 和原有 27 项测试仍通过。
- 运行 Swift Release 构建，确认助手可以在目标 Mac 上编译。
- 对最终产物执行密钥和意外媒体文件检查。

这些门禁只能证明构建与原功能未明显回归，不能证明远程控制正确。

### 14.2 手工验证

1. 单活动显示器、整屏共享、辅助功能权限已授予时，观看者申请并由分享者批准。
2. 验证视频内容四角、中心和不同缩放窗口下的点击位置映射。
3. 验证移动、左右键、拖动、滚轮、普通文字、输入法提交文字、导航键和编辑键。
4. 验证黑边点击、系统快捷键、超长文本、未知事件和越界坐标不会注入本机。
5. 验证第二位观看者不能在已有控制者时获批。
6. 验证主动撤销、观看者结束、10 分钟超时、断线、停止共享和终端 `Ctrl+C` 都会终止控制并释放输入。
7. 验证助手缺失、权限缺失、多显示器和非整屏共享时只禁用控制，视频仍可观看。
8. 在真实局域网第二台电脑上复验主要控制流程；如果没有第二台设备，交付时明确标记该项未验证。

本机双浏览器验证与真实局域网跨设备验证分别记录，不互相替代。

## 15. 验收标准

- 现有 1–5 人无声视频观看能力保持可用。
- 满足全部前置条件时，一位观看者可以申请控制，分享者可以批准、拒绝和立即撤销。
- 获批控制者可以可靠执行白名单内的鼠标、滚轮和键盘操作。
- 未获批观看者、第二位观看者、局域网直连 WebSocket 和过期租约不能产生本机输入。
- 多显示器、非整屏、助手不可用或权限缺失时远程控制保持禁用，观看功能不受影响。
- 每次授权最多 10 分钟，不存在永久授权或无人值守控制。
- 所有结束和异常路径都会撤销租约并释放已追踪的按键和鼠标按钮。
- Swift 助手不监听网络，不保存事件，Node 不记录控制内容或敏感标识。
- HTML 使用本地 Tailwind 构建，不引入 CDN 或外部运行依赖。
- 现有 `npm run check` 与 Swift Release 构建通过；手工验证结果和真实跨设备验证状态被如实记录。
