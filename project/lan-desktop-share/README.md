# LAN Desktop Share

在同一局域网内，把本机桌面、窗口或浏览器标签页实时分享给 1–5 位同事。画面通过 WebRTC 在浏览器之间点对点传输；Node.js 服务只负责页面和连接协调。

在满足严格前置条件时，一位观看者还可以申请临时控制分享者的 macOS 桌面。每次控制都要由分享者在本机明确批准，最长 10 分钟，并可随时停止。远程控制是可选能力；不可用时仍可正常看画面。

## 环境要求

- Node.js 20 或更高版本
- 分享者与观看者位于可互相访问的同一局域网
- 最新版 Chrome 或 Edge
- 分享者电脑允许浏览器使用系统屏幕录制权限

如需远程控制，还要求：

- 分享者使用 macOS 13 或更高版本，并已安装 Xcode Command Line Tools 中的 Swift 工具链
- 分享端通过 `http://localhost:4173` 打开
- macOS 辅助功能权限已授予运行服务的终端、Node 或控制助手
- 在浏览器中明确选择“整个屏幕”；多个活动显示器时，还要在分享端识别并绑定正在共享的屏幕
- 控制者使用带鼠标和键盘的桌面版 Chrome 或 Edge；手机仍为只看模式

访客 Wi-Fi、设备隔离、公司防火墙或终端安全策略可能阻止局域网连接。工具不会尝试绕过这些限制。

## 安装与启动

在项目目录执行：

```bash
npm install
npm run control:build
npm start
```

`npm run control:build` 只用于 macOS 远程控制。只看画面时可以跳过；页面会明确显示控制助手不可用，但不会阻止视频共享。

启动成功后，终端会显示：

```text
Share page: http://localhost:4173
LAN access: http://局域网地址:4173
```

不要把端口 `4173` 映射到公网。

## 分享桌面

1. 分享者必须在本机打开 `http://localhost:4173`。局域网 IP 的普通 HTTP 页面通常不能申请屏幕捕获权限。
2. 点击“开始共享”。
3. 在浏览器原生选择器中选择整个屏幕、一个窗口或一个标签页。若要允许远程控制，必须选择“整个屏幕”。
4. 页面显示预览后，点击“复制观看链接”，把链接发给同一网络中的同事。
5. 完成后点击“停止共享”，或使用浏览器自带的停止共享按钮。
6. 在终端按 `Ctrl+C` 停止 Node.js 服务。

页面不会自动开始录屏。每次共享都必须由分享者点击按钮，并在浏览器原生界面中授权。

## 观看

观看者在最新版 Chrome 或 Edge 中打开收到的随机链接。无需安装软件，也不需要摄像头、麦克风或屏幕录制权限。

如果自动播放被浏览器阻止，页面会显示“点击播放”。刷新页面会重新加入仍在进行的分享。

## 临时远程控制（macOS）

### 首次准备

1. 执行 `npm run control:build` 构建本机 Swift 助手。
2. 执行 `npm run control:probe` 检查环境。探测只读取平台、辅助功能权限和活动显示器列表，不会注入任何输入。
3. 如果返回 `accessibility-denied`，打开“系统设置 → 隐私与安全性 → 辅助功能”，允许用于启动服务的终端、Node 或 `lan-control-helper`，然后完全停止并重新执行 `npm start`。
4. 多个活动显示器无需断开；开始共享后，分享端会要求你绑定其中一块。虚拟显示器和 Sidecar 也可能出现在列表中。

### 使用流程

1. 分享者从 `localhost` 打开页面，点击“开始共享”，并在原生选择器中选择“整个屏幕”。
2. 如果检测到多块屏幕，分享者点击“显示屏幕编号”，在共享预览中确认编号，再选择“控制哪块屏幕”。
3. 桌面端观看者点击“申请控制”。
4. 分享者确认申请者身份后，在本机点击“允许 10 分钟”。在分享者批准前，任何观看者输入都不会到达本机助手。
5. 观看者收到授权后，点击远程画面取得控制焦点，再使用鼠标、滚轮和允许的键盘输入。
6. 任一方都可以结束控制；分享者页面顶部持续显示红色提示和“立即停止控制”。授权到期、断线、页面进入后台、显示器配置变化或停止共享也会自动撤销。

支持鼠标移动、左右键、拖动、滚轮、普通已提交文字、方向键、Enter、Tab、Backspace、Delete、Escape、Home、End、PageUp 和 PageDown。不支持系统快捷键、Meta/Control/Option 组合、功能键、媒体键、剪贴板同步、文件传输或无人值守控制。

### 撤销控制权限

- 立即结束当前租约：点击分享端红色提示中的“立即停止控制”，或直接停止共享。
- 停止所有能力：在终端按 `Ctrl+C` 停止服务。
- 撤销系统授权：在 macOS“辅助功能”设置中关闭对应终端、Node 或助手的权限，然后重启服务。

## 隐私与安全边界

- 只采集视频，不请求系统声音或麦克风权限。
- 不录制、不回放、不提供下载按钮。
- Node.js 服务不接收或转发桌面媒体流。
- 房间与连接状态只保存在内存中，服务停止后自动清除。
- 随机房间密钥位于链接的 `#` 片段中，不随普通 HTTP 请求发送。
- 任何拿到有效链接、且能访问该局域网服务的人都可能尝试加入；观看链接不是身份认证，只把链接发给需要观看的同事。
- 拿到观看链接不等于获得控制。每次控制必须由分享者在本机逐次批准，同时最多一位控制者，单次最长 10 分钟。
- 控制消息先经过获批的 WebRTC DataChannel，再由 `localhost` 分享端转发；局域网客户端不能直接调用本机控制桥。
- Swift 助手不监听网络，不保存输入；Node 不记录房间密钥、租约标识或控制内容。
- 多屏控制只映射到分享者明确绑定的一块显示器；显示器连接、分辨率、排列、旋转或镜像状态变化时会释放输入并撤销租约。
- 多屏编号识别会生成仅保存在 Node 内存中的临时绑定；跳过识别、使用旧响应或提交其他屏幕 ID 都不能启动控制助手。
- 不用时停止共享并按 `Ctrl+C` 退出服务。禁止把端口或观看链接映射到公网。

## 常见问题

### 点击开始后没有出现屏幕选择器

- 确认分享者使用的是 `http://localhost:4173`，不是局域网 IP。
- 确认使用最新版 Chrome 或 Edge。
- 在 macOS“系统设置 → 隐私与安全性 → 屏幕与系统音频录制”中允许浏览器；Windows 设备请检查组织安全策略。
- 如果刚修改系统权限，完全退出并重新打开浏览器。

### 同事打不开链接

- 确认双方连接到同一网络，且不是启用了设备隔离的访客 Wi-Fi。
- 允许 Node.js 通过本机防火墙访问专用网络。
- 尝试在观看者电脑打开终端显示的 `LAN access` 基础地址。
- 如果电脑同时连接 VPN、有线网络和 Wi-Fi，终端可能显示多个地址；使用与同事同网段的地址。

### 页面能打开但没有画面

- 分享者确认预览仍在更新，浏览器顶部没有显示“已停止共享”。
- 观看者点击“重新连接”。
- 临时关闭 VPN 后重试，或请网络管理员确认局域网设备允许点对点连接。

### 能看画面但不能申请或批准控制

按以下顺序检查；任何一项不满足都只会禁用控制，不会关闭视频：

1. 分享端地址必须是 `http://localhost:4173`。
2. 在项目目录执行 `npm run control:build`，再执行 `npm run control:probe`。
3. 在 macOS“辅助功能”中授予权限，然后停止并重启 Node 服务。
4. 停止当前共享，重新开始并在原生选择器中选择“整个屏幕”，不能选择窗口或标签页。
5. 多屏时点击“显示屏幕编号”，再选择共享预览中显示的对应屏幕。
6. 控制者使用桌面版 Chrome 或 Edge，并确认视频已开始播放；手机只提供观看。

常见探测原因：

- `helper-missing`：尚未执行 `npm run control:build`。
- `accessibility-denied`：辅助功能权限未授予或服务未在授权后重启。
- `display-selection-required`：检测到多块屏幕，尚未选择正在共享的屏幕。
- `display-configuration-changed`：绑定后显示器连接、分辨率、排列、旋转或镜像状态发生变化。
- `whole-screen-required`：浏览器未明确报告正在分享整个显示器。
- `host-must-use-localhost`：分享端不是通过回环地址打开。

### 没有声音

这是预期行为。本工具按设计只共享画面。

## 开发验证

```bash
npm run control:build
npm run control:probe
npm run check
```

`npm run check` 依次执行 Tailwind 构建、ESLint、Prettier 检查和现有 Node 测试。`control:probe` 会返回经过清理的活动显示器列表；权限未满足时安全返回不可用状态，这不代表构建失败。自动化与本机协议探针不能替代真实多屏输入和跨设备局域网验收。
