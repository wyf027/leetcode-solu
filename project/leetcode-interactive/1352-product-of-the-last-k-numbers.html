最后 K 个数的乘积

Product of the Last K Numbers

MEDIUM设计数组数学数据流前缀积

设计一个接收整数流的数据结构：它既能追加新数字，也能随时返回当前数据流末尾连续 k 个数字的乘积。

01题目要求

实现 ProductOfNumbers 类：

  • ProductOfNumbers()：使用空数据流初始化对象。
  • void add(int num)：把 num 追加到数据流末尾。
  • int getProduct(int k)：返回当前数据流最后 k 个数字的乘积。调用时数据流中保证至少有 k 个数字。
任意连续数字序列的乘积都保证在 32 位整数范围内。进阶目标：让 add 与 getProduct 都达到 O(1) 时间。

约束

  • 0 ≤ num ≤ 100
  • 1 ≤ k ≤ 4 × 10⁴
  • add 与 getProduct 总调用次数最多为 4 × 10⁴。
  • 任意时刻数据流的连续子段乘积均可由 32 位整数表示。

题解

想好如何用常数时间处理查询了吗？

Solution unlocked

零分段 + 前缀积

核心洞察

若一段数字中没有零，最后 k 个数字的乘积等于“整段前缀积 ÷ 去掉末尾 k 个数后的前缀积”。真正棘手的是零，因为不能做除零运算。

解决方法是把零当作分段边界：每遇到零，就把前缀积数组重置为 [1]。于是数组只记录“最近一个零之后”的数据。

判定公式

若 k ≥ prefix.length：答案 = 0

否则：答案 = prefix[n] / prefix[n - k]

这里 prefix[0] = 1 是哨兵，n = prefix.length - 1 表示最近一个零之后已有多少个非零数。

完整过程

1

初始化 prefix = [1]，让第一次累乘和边界查询都有合法除数。

2

执行 add(num)：若 num == 0，重置为 [1]；否则把 prefix[last] × num 追加到数组。

3

执行 getProduct(k)：若最近零之后不足 k 个数，则查询区间跨过零，直接返回 0。

4

否则区间内没有零，用两个前缀积相除，消去查询区间之前的所有因子。

正确性证明

情况一：查询跨过最近的零。 此时最近一个零之后的非零数字少于 k 个，最后 k 个数字必然包含零，因此乘积为 0；算法返回 0，正确。

情况二：查询不跨零。 设最近零后数字为 a₁…aₙ，前缀积 Pᵢ=a₁…aᵢ。最后 k 个数字的乘积为 aₙ₋ₖ₊₁…aₙ=Pₙ/Pₙ₋ₖ；算法正返回该值，正确。

两种情况覆盖全部查询，因此算法始终正确。

边界与复杂度

  • 连续加入多个零：每次都重置为 [1]，行为不变。
  • k 恰好等于最近零后的非零数数量：可除以哨兵 1。
  • k 大于该数量：范围必含零，返回 0。
  • add：时间 O(1)。
  • getProduct：时间 O(1)。
  • 空间：O(n)，n 为最近零后的数字数，最坏为调用次数。

四语言完整代码

JavaLeetCode 可提交
import java.util.ArrayList;
import java.util.List;

class ProductOfNumbers {
    private List<Integer> prefix;

    public ProductOfNumbers() {
        prefix = new ArrayList<>();
        prefix.add(1);
    }

    public void add(int num) {
        if (num == 0) {
            prefix.clear();
            prefix.add(1);
            return;
        }
        prefix.add(prefix.get(prefix.size() - 1) * num);
    }

    public int getProduct(int k) {
        int size = prefix.size();
        if (k >= size) {
            return 0;
        }
        return prefix.get(size - 1) / prefix.get(size - 1 - k);
    }
}

var ProductOfNumbers = function() {
    this.prefix = [1];
};

/**
 * @param {number} num
 * @return {void}
 */
ProductOfNumbers.prototype.add = function(num) {
    if (num === 0) {
        this.prefix = [1];
        return;
    }
    const last = this.prefix[this.prefix.length - 1];
    this.prefix.push(last * num);
};

/**
 * @param {number} k
 * @return {number}
 */
ProductOfNumbers.prototype.getProduct = function(k) {
    const n = this.prefix.length;
    if (k >= n) {
        return 0;
    }
    return this.prefix[n - 1] / this.prefix[n - 1 - k];
};

C++LeetCode 可提交
#include <vector>
using namespace std;

class ProductOfNumbers {
private:
    vector<int> prefix;

public:
    ProductOfNumbers() : prefix{1} {}

    void add(int num) {
        if (num == 0) {
            prefix.assign(1, 1);
            return;
        }
        prefix.push_back(prefix.back() * num);
    }

    int getProduct(int k) {
        int n = static_cast<int>(prefix.size());
        if (k >= n) {
            return 0;
        }
        return prefix[n - 1] / prefix[n - 1 - k];
    }
};

替代方案

  • 直接保存所有数字并倒序相乘：add 为 O(1)，但每次查询为 O(k)，无法满足进阶要求。
  • 全局前缀积 + 记录零的位置：也可实现，但需额外判断区间是否含零，状态更复杂；按零重置更简洁。
  • 对数求和：能把乘法转为加法，却会引入浮点误差，无法保证精确整数答案。

面试追问

  • 如果允许负数，方案是否仍成立？——成立，只要没有零且保证整数除法精确。
  • 如果乘积可能溢出 64 位怎么办？——需要大整数、模运算（若题意允许）或改变查询语义。
  • 如果还要删除最早的数字呢？——需重新设计为可维护窗口的结构，并单独管理窗口内的零。

常见错误

  • 遇到零仍继续累乘，导致后续所有前缀积永久为零且无法相除。
  • 把跨零条件写成 k > prefix.length；正确条件是 k ≥ prefix.length，因为数组包含哨兵 1。
  • 索引误写为 prefix[n-k]。若 n 表示数组长度，分母应为 prefix[n-1-k]。
  • 用浮点近似计算精确整数乘积，造成舍入错误。
