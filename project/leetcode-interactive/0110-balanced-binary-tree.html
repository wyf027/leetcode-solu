Problem brief

检测任务

给定一棵二叉树的根节点 root，判断它是否为高度平衡二叉树。

这里关心的是树中每一个节点，而不是只检查根节点。空树也被视为平衡。

Acceptance rule 任意节点的左右子树高度差都不超过 1。

高度按从当前节点到最深叶子的节点层数计算；空子树高度记为 0。

官方样例 2 / 输入 root = [1,2,2,3,3,null,null,4,4] 输出 false
官方样例 3 / 输入 root = [] 输出 true

Recommended approach

一次后序，双重汇报

-1

让递归函数不只返回高度：正常时返回当前子树高度；发现任何失衡时返回哨兵值 -1。父节点一旦收到故障信号，就立即停止后续计算并继续向上传递。

为什么必须是后序？

当前节点要先知道左右子树的高度与安全状态，才能给出自己的结论，因此数据流天然是“左 → 右 → 根”。

height(node) = -1，若子树故障或 |L - R| > 1；否则为 max(L, R) + 1

    Full process

    完整过程

    1. 定义返回协议。空节点返回高度 0；正常子树返回正高度；失衡子树返回 -1。
    2. 递归检查左子树。若左侧已返回 -1，当前节点无需再计算，直接上传故障。
    3. 递归检查右子树。同样对右侧故障执行短路返回。
    4. 检查当前连接点。若 |leftHeight - rightHeight| > 1，返回 -1；否则返回较大高度加 1。
    5. 读取根节点信号。根返回 -1 表示整棵树失衡，否则整棵树通过检测。

    Complexity report

    复杂度

    Time O(n)

    每个节点最多完成一次高度汇报；遇到故障还可能提前结束部分分支。

    Stack O(h)

    递归栈与树高相同；平衡树为 O(log n)，最坏链状树为 O(n)。

    Boundary inspection

    边界与停止条件

    必须正确处理

    • 空树返回 true：空节点高度为 0，没有违规节点。
    • 单节点树返回 true：两侧高度都是 0。
    • 高度差恰好为 1 仍然平衡，只有大于 1 才故障。
    • 节点值与平衡性无关，不要把 BST 性质混进来。

    短路传播

    • 左子树已失衡时，可立刻返回，无需继续检查右子树。
    • 右子树失衡时，也无需再比较当前高度差。
    • -1 不是真实高度，只是全链路约定的故障码。
    • 最坏深度为 5000，递归空间必须纳入复杂度说明。

    Alternative routes

    替代方案取舍

    方案 时间 额外空间 面试取舍
    后序 + -1 哨兵 O(n) O(h) 一次遍历同时得到高度和安全状态，最推荐。
    自顶向下重复求高度 最坏 O(n²) O(h) 直观但链状树反复扫描，不宜作为主解。
    迭代后序 + 哈希表 O(n) O(n) 避免语言递归深度限制，但状态管理更复杂。

    Interview follow-ups

    追问与常见错误

    为什么不能只比较根节点的左右高度？

    根节点可能满足高度差不超过 1，但某个更深的子树已经失衡；定义要求每个节点都通过。

    能否使用布尔变量记录是否失衡？

    可以，但哨兵返回值把“高度”和“故障状态”合并在一个清晰协议里，也更容易短路。

    如何避免递归栈过深？

    使用显式栈模拟后序遍历，并用映射保存每个节点的高度；代价是 O(n) 额外存储与更多状态。

    常见错误：把差值条件写成 >= 1

    高度差等于 1 仍然合法，故障条件必须是严格大于 1。

    常见错误：失衡后仍计算高度

    -1 是故障信号，不应参与 max；收到后要立即继续向上传递。

    常见错误：声称空间复杂度是 O(1)

    递归调用栈真实存在，空间是 O(h)，最坏可达到 O(n)。
