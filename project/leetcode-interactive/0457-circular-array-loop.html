环形数组是否存在循环

457 · Circular Array Loop

MEDIUM 非付费题 目标 O(n) / O(1) 快速生成模式：待补验证

Problem

题目转述

给定一个不含 0 的整数数组 nums，把它首尾相连看作环。站在下标 i 时，正数表示向下标增大的方向移动，负数表示向下标减小的方向移动，越界后从另一端继续。

请判断是否存在一个长度大于 1 的下标循环，并且循环内每一步的方向完全一致：要么对应元素全为正数，要么全为负数。存在则返回 true，否则返回 false。

两个容易漏掉的资格条件： 单点自环不算；正负方向混合的闭环也不算。

Contract

函数与约束

参数：nums: integer[]

返回：boolean

1 ≤ nums.length ≤ 5000
-1000 ≤ nums[i] ≤ 1000
nums[i] ≠ 0

进阶：在 O(n) 时间和 O(1) 额外空间内完成。

Solution

Floyd 判圈 + 原地清理

核心建模： 每个下标都唯一指向 next(i)，因此数组是一张“每点出度为 1”的函数图。对每个尚未处理的起点，在固定方向内运行快慢指针；相遇说明存在环，但还要提前拒绝单点自环。

三个关键洞察

1

规范化环形下标

使用 ((i + nums[i]) % n + n) % n，保证负向移动在 Java / JavaScript / C++ 中也得到非负下标。

2

移动前做资格检查

辅助函数只允许与本轮方向一致且不为 0 的节点；若下一位置仍是自己，也立即判为无效。

3

失败路径原地归零

一轮未找到环后，把同方向访问路径标为 0。它们不可能再属于有效环，后续起点可以直接跳过。

完整过程

  1. 从左到右枚举起点 i；若 nums[i] == 0，说明该点已被证明无效，直接跳过。
  2. 记录起点方向 forward = nums[i] > 0，令快、慢指针都从 i 出发。
  3. 慢指针调用一次 advance，快指针连续调用两次。任何一次遇到归零点、方向不一致或单点自环，就终止本轮。
  4. 如果两个有效指针相遇，函数图性质保证它们位于一个长度大于 1、方向一致的环中，返回 true。
  5. 若本轮失败，沿起点方向继续前进，把本路径节点原地设为 0；随后检查下一个起点。最终仍未找到则返回 false。

正确性说明

引理 1： advance 返回有效下标时，该边与起点方向一致，且不是自环。因此算法探索到的每条有效边都满足题目对方向和长度的局部要求。

引理 2： 若快慢指针相遇，则从起点可达路径进入了一个环。由于所有移动都通过 advance 检查，该环方向一致；自环已经被拒绝，所以环长大于 1。

引理 3： 一轮失败后清零的节点不可能属于有效环。失败原因发生在这条确定路径的唯一后继上：要么方向改变、要么进入已知无效区、要么是自环；从路径中任何节点出发都会沿相同后继到达同一失败处。

结论： 算法只在发现合格环时返回 true（可靠性）；任意合格环上的节点不会被无关方向的清理误删，从其自身或可达起点出发时 Floyd 必会相遇（完备性），所以返回值正确。

复杂度

时间复杂度O(n)

每个节点只会被常数次访问，失败路径随后被归零。

额外空间O(1)

只使用若干下标和方向变量；代价是会修改输入数组。

边界情况

单元素或整圈步长

若 next(i) == i，即便数值非零，也只是长度 1 的环，必须排除。

正负交界

闭合并不等于有效。辅助移动函数必须检查“当前节点”与固定方向一致。

负数取模

Python 的模天然非负；Java、JavaScript、C++ 需要再加 n 并取模。

输入被修改

原地归零满足 O(1) 空间，但调用后数组不再保持原值；若接口要求保留输入，应改用状态数组。

JavaOfficial signature
class Solution {
    public boolean circularArrayLoop(int[] nums) {
        int n = nums.length;
        for (int i = 0; i < n; i++) {
            if (nums[i] == 0) continue;
            boolean forward = nums[i] > 0;
            int slow = i, fast = i;

            while (true) {
                slow = advance(nums, slow, forward);
                if (slow == -1) break;
                fast = advance(nums, fast, forward);
                if (fast == -1) break;
                fast = advance(nums, fast, forward);
                if (fast == -1) break;
                if (slow == fast) return true;
            }

            int cur = i;
            while (nums[cur] != 0 && (nums[cur] > 0) == forward) {
                int next = nextIndex(nums, cur);
                nums[cur] = 0;
                cur = next;
            }
        }
        return false;
    }

    private int advance(int[] nums, int i, boolean forward) {
        if (nums[i] == 0 || (nums[i] > 0) != forward) return -1;
        int next = nextIndex(nums, i);
        return next == i ? -1 : next;
    }

    private int nextIndex(int[] nums, int i) {
        int n = nums.length;
        return ((i + nums[i]) % n + n) % n;
    }
}

var circularArrayLoop = function(nums) {
    const n = nums.length;
    const nextIndex = (i) => ((i + nums[i]) % n + n) % n;
    const advance = (i, forward) => {
        if (nums[i] === 0 || (nums[i] > 0) !== forward) return -1;
        const next = nextIndex(i);
        return next === i ? -1 : next;
    };

    for (let i = 0; i < n; i++) {
        if (nums[i] === 0) continue;
        const forward = nums[i] > 0;
        let slow = i;
        let fast = i;

        while (true) {
            slow = advance(slow, forward);
            if (slow === -1) break;
            fast = advance(fast, forward);
            if (fast === -1) break;
            fast = advance(fast, forward);
            if (fast === -1) break;
            if (slow === fast) return true;

            nums[cur] = 0;
            cur = next;
        }
    }

替代方案

每个起点维护 Set

思路直接：沿路径记录本轮访问下标，并单独验证方向和环长。最坏可能达到 O(n²) 时间；若复用全局状态可优化，但空间为 O(n)。

三色状态 / 访问轮次

用数组记录“未访问、当前路径、已完成”，同样可做到 O(n) 时间，实现更易解释且不修改输入，但需要 O(n) 额外空间。

常见错误

  • 只检查快慢指针相遇，没有排除 next(i) == i 的单点自环。
  • 只在起点检查方向；指针跨过正负交界后仍继续判圈，导致把混向闭环误判为有效。
  • 直接使用 (i + nums[i]) % n，忽略部分语言的负余数。
  • 清理路径时不限制方向，错误地把反方向的潜在起点也归零。
  • 宣称 O(1) 空间却悄悄复制数组；或原地修改输入却没有说明副作用。

面试追问

为什么总时间不是 O(n²)？

失败路径会被归零，之后不会被完整重走；快慢指针与清理对每个节点只贡献常数次访问。

如果不能修改输入怎么办？

用 O(n) 状态数组记录已完成节点，或者用“访问轮次”标识当前 DFS 路径，保持 O(n) 时间。

为什么出度为 1 很重要？

它保证从任意起点只有唯一后继路径，最终要么失效，要么进入环，因此 Floyd 判圈适用。

如果允许 0 呢？

0 天然指向自身，应作为无效自环处理；若仍以 0 充当已处理标记，语义恰好兼容。
