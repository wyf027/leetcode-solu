01 · Problem

题目转述

任务

表 Sessions 记录用户每次访问应用的会话时长，单位为秒。请按时长把所有会话分到四个固定区间，并返回每个区间对应的会话数量。

输出两列：bin 为固定标签，total 为该区间中的会话数。即使某个区间没有任何会话，也必须输出该区间，计数为 0。结果行可以按任意顺序返回。

读区间：[0-5> 表示大于等于 0 分钟且小于 5 分钟。因为原始单位是秒，四条分界线分别是 300、600、900 秒。

05 · Solution

准备好核对思路了吗？

先用上面的演示确认四条边界。展开后将看到 SQL 主解、证明、复杂度，以及四种语言的本地语义参考。

完整题解

先造四行，再分别计数

核心洞察

不能只对实际数据做 CASE + GROUP BY：如果某个区间没有会话，那一组根本不会产生，因而缺失“0”行。最直接且稳妥的办法，是写四个独立聚合；聚合查询即使匹配 0 行，也会返回一行 COUNT(*) = 0。

完整过程

  1. 固定写出四个输出标签。
  2. 每一支查询使用对应的半开区间过滤。
  3. 用 COUNT(*) 统计该桶会话数。
  4. 用 UNION ALL 拼接四行，避免无谓去重。

边界处理

  • 299 秒仍在第一桶，300 秒进入第二桶。
  • 599 / 600、899 / 900 同理。
  • 使用整数秒直接比较，不做除法与四舍五入。
  • 返回顺序不限；如业务端要求固定顺序，可额外添加排序键。

复杂度

四个聚合各扫描一次表，时间复杂度为 O(4n) = O(n)；只维护四个计数，额外空间为 O(1)。常数扫描次数可以用条件聚合优化，但需要先生成固定桶集合。

正确性证明

完备性：对任意合法的非负 duration，它要么小于 300，要么依次落在 [300,600)、[600,900)，否则必然大于等于 900，因此每条会话至少进入一个桶。

互斥性：四个范围的上下界采用左闭右开，并且相邻边界完全衔接，所以任意会话不可能同时满足两个桶的条件。

空桶性：每个分支都是无分组的聚合查询。即使过滤后为空，COUNT(*) 仍产生值为 0 的一行；因此四个标签始终全部出现。综上，输出中每个桶的 total 恰好等于属于该桶的会话数量。

代码实现

本题为数据库题；以下 MySQL 查询是可提交实现。

SELECT '[0-5>' AS bin, COUNT(*) AS total
FROM Sessions
WHERE duration < 300

UNION ALL

SELECT '[5-10>' AS bin, COUNT(*) AS total
FROM Sessions
WHERE duration >= 300 AND duration < 600

UNION ALL

SELECT '[10-15>' AS bin, COUNT(*) AS total
FROM Sessions
WHERE duration >= 600 AND duration < 900

UNION ALL

SELECT '15 or more' AS bin, COUNT(*) AS total
FROM Sessions
WHERE duration >= 900;

本地语义参考：LeetCode 本题不接受 Java 提交；此代码在内存中复现相同分桶规则。

import java.util.ArrayList;
import java.util.List;

class Solution {
    static class BinCount {
        final String bin;
        final int total;

        BinCount(String bin, int total) {
            this.bin = bin;
            this.total = total;
        }
    }

    public List<BinCount> createBarChart(int[][] sessions) {
        int[] counts = new int[4];

        for (int[] session : sessions) {
            int duration = session[1];
            if (duration < 300) {
                counts[0]++;
            } else if (duration < 600) {
                counts[1]++;
            } else if (duration < 900) {
                counts[2]++;
            } else {
                counts[3]++;
            }
        }

        String[] labels = {
            "[0-5>", "[5-10>", "[10-15>", "15 or more"
        };
        List<BinCount> result = new ArrayList<>();
        for (int i = 0; i < labels.length; i++) {
            result.add(new BinCount(labels[i], counts[i]));
        }
        return result;
    }
}

本地语义参考：LeetCode 本题不接受 JavaScript 提交；输入行格式为 [session_id, duration]。

function createBarChart(sessions) {
  const labels = ["[0-5>", "[5-10>", "[10-15>", "15 or more"];
  const counts = [0, 0, 0, 0];

  for (const [, duration] of sessions) {
    if (duration < 300) counts[0] += 1;
    else if (duration < 600) counts[1] += 1;
    else if (duration < 900) counts[2] += 1;
    else counts[3] += 1;
  }

  return labels.map((bin, index) => ({
    bin,
    total: counts[index],
  }));
}

from typing import List, Dict


def create_bar_chart(sessions: List[List[int]]) -> List[Dict[str, int]]:
    labels = ["[0-5>", "[5-10>", "[10-15>", "15 or more"]
    counts = [0, 0, 0, 0]

    for _, duration in sessions:
        if duration < 300:
            counts[0] += 1
        elif duration < 600:
            counts[1] += 1
        elif duration < 900:
            counts[2] += 1
        else:
            counts[3] += 1

    return [
        {"bin": label, "total": count}
        for label, count in zip(labels, counts)
    ]

替代方案

先构造包含四行的桶表，再对 Sessions 做条件左连接并分组，可以只扫描数据表一次且仍保留空桶。单纯 CASE + GROUP BY 较短，但不会自动补出空桶，不能直接满足题意。

常见错误

遗漏零计数桶

按实际数据分组只会返回出现过的桶，样例中的 [10-15> 会整行消失。

边界重叠或断层

同时在相邻桶使用 <=，会重复计算 300、600、900；两边都用严格不等号则会漏掉它们。

把秒除成分钟再取整

不同数据库的整数除法、浮点比较和舍入规则会引入不必要的不确定性。

用 UNION 做无意义去重

四个标签本来就不同，UNION ALL 更直接，也不会多一次去重工作。
