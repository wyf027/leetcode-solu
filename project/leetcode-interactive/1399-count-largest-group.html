Count Largest Group —— 数字排成长队，数位和是它们各自的“分组号码”。最大的组不一定只有一个。

哈希表数学计数
1 → n把每个整数送到对应数位和的组，观察哪些组最终并列最大。

Problem

先读懂任务

给定整数 n，将区间 [1, n] 中的整数按照它们的数位之和分组。例如，14 与 5 的数位和都是 5，所以属于同一组；13 与 3 的数位和不同，因此属于不同组。

返回元素数量最多的组有多少个。如果多个组并列达到最大大小，它们都要计入答案。

核心洞察

分组规则只取决于数位和。遍历 1 到 n，用计数数组记录每种数位和出现的次数；更新计数后同步维护“最大组大小”和“达到该大小的组数”。

因为 n ≤ 10⁴，区间内数字最多 5 位，数位和很小；即使直接准备长度为 46 的数组也足够（10000 的数位和为 1，其余不超过 9999 的 36）。为了让实现更通用，下面代码使用哈希表或按 9 × 位数 + 1 分配数组。

完整过程

  1. 初始化计数容器 count、最大组大小 maxSize = 0、并列组数 answer = 0。
  2. 对每个 x = 1..n，循环取个位 x % 10 并整除 10，求出数位和 s。
  3. 令 count[s] 加一，得到该组的新大小 size。
  4. 若 size > maxSize，发现新的最大值：更新 maxSize，并把 answer 重置为 1。
  5. 若 size == maxSize，该组刚刚追平最大值：令 answer 加一。

digitSum(x) = (x % 10) + digitSum(⌊x / 10⌋)

正确性证明

引理 1：每个整数被放入且只放入一个正确分组。数位和函数对任意整数产生唯一结果，遍历又恰好处理 1 到 n 各一次，因此结论成立。
引理 2：处理任意前缀 1..x 后，count[s] 等于该前缀中数位和为 s 的整数数量。初始全为 0；每处理一个数，只给它唯一对应的 s 加一，归纳成立。
引理 3：每轮结束时，maxSize 是当前最大组大小，answer 是达到该大小的组数。组大小只会单调加一；超过旧最大值时它成为唯一新最大组，追平时最大组数增加一，其他情况二者不变。

定理：循环结束覆盖完整区间 1..n。由引理 2，所有组大小准确；由引理 3，answer 正是最终元素数最多的组的数量，所以算法返回正确答案。

边界与复杂度

  • n = 1：只有数位和为 1 的组，答案为 1。
  • 跨十进制进位：例如 9 → 10，数位和从 9 变 1，必须逐位计算，不能简单递增。
  • 多个组并列：更新到同一最大大小时要累加答案；出现更大大小时必须重置答案为 1。
  • 上界：n = 10000 仍可直接遍历。

设 n 的十进制位数为 d。时间复杂度为 O(n · d)，在本题范围内可视为 O(n)；计数数组空间复杂度为 O(d)（最大数位和值域），若按题目上界固定分配则为 O(1)。

四语言完整代码

class Solution {
    public int countLargestGroup(int n) {
        int[] count = new int[46];
        int maxSize = 0;
        int answer = 0;

        for (int value = 1; value <= n; value++) {
            int sum = digitSum(value);
            int size = ++count[sum];

            if (size > maxSize) {
                maxSize = size;
                answer = 1;
            } else if (size == maxSize) {
                answer++;
            }
        }
        return answer;
    }

    private int digitSum(int value) {
        int sum = 0;
        while (value > 0) {
            sum += value % 10;
            value /= 10;
        }
        return sum;
    }
}

var countLargestGroup = function(n) {
    const count = new Array(46).fill(0);
    let maxSize = 0;
    let answer = 0;

    for (let value = 1; value <= n; value++) {
        let current = value;
        let sum = 0;
        while (current > 0) {
            sum += current % 10;
            current = Math.floor(current / 10);
        }

        const size = ++count[sum];
        if (size > maxSize) {
            maxSize = size;
            answer = 1;
        } else if (size === maxSize) {
            answer++;
        }
    }
    return answer;
};

替代方案

先统计，再二次扫描

完成所有分组后，再找最大值并统计出现次数。逻辑更直白，时间仍是 O(n · d)，代码也很稳健。

递推数位和

可利用 sum(i) = sum(⌊i/10⌋) + i%10 预计算，额外使用 O(n) 空间，把数位和计算降为 O(1)，但本题没有必要。

面试追问

  • 如果 n 非常大，无法逐个枚举？可考虑数位 DP，按数位和统计 1..n 的数字数量，再从各和的计数中找最大组。
  • 为何数组长度 46 足够？n ≤ 10000；1..9999 的最大数位和是 36，10000 的数位和是 1，46 留有安全余量。
  • 能否一次遍历完成？可以。当前实现更新组大小时同步维护最大值和并列数，不需要二次扫描。

常见错误

  • 返回最大组的大小，而不是达到最大大小的组数。
  • 遇到新最大值时只更新 maxSize，忘记把 answer 重置为 1。
  • 把数位和相同误写成数字本身相同，或漏掉区间端点 n。
  • 用字符串求和时直接累加字符，造成字符串拼接而非数字加法。
