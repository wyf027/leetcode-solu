01 / Problem

题目与输入

无限数轴上有若干堆水果。二维数组 fruits 中的每项 [positionᵢ, amountᵢ] 给出坐标与水果数量；坐标已经严格升序排列，没有重复位置。

你从 startPos 出发，每一步向左或向右移动一个单位，总步数不超过 k。到达一个坐标时，摘走该处全部水果，之后再次经过不会重复获得。求能够摘到的最大水果总数。

可以少走、可以转向，不必回到起点。起点若有水果，无需移动就能采摘。

约束

  • 1 ≤ fruits.length ≤ 10⁵
  • fruits[i].length == 2
  • 0 ≤ startPos, positionᵢ ≤ 2 × 10⁵
  • 任意 i > 0，都有 positionᵢ₋₁ < positionᵢ，下标从 0 开始。
  • 1 ≤ amountᵢ ≤ 10⁴
  • 0 ≤ k ≤ 2 × 10⁵

02 / Examples

官方示例

示例 1 · 向右采摘

fruits = [[2,8],[6,3],[8,6]]
startPos = 5
k = 4
输出：9

路线 5 → 6 → 8，移动 3 步，摘到 3 + 6 = 9 个水果。

示例 2 · 经过起点

fruits = [[0,9],[4,1],[5,7],[6,2],[7,4],[10,9]]
startPos = 5
k = 4
输出：14

起点先摘 7 个，接着 5 → 4 → 6 → 7，总共移动 1 + 3 = 4 步，摘到 7 + 1 + 2 + 4 = 14 个。坐标 0 与 10 都无法到达。

示例 3 · 空手而归

fruits = [[0,3],[6,4],[8,5]]
startPos = 3
k = 2
输出：0

两步内无法到达任意一个有水果的位置。

Insight

将路线压缩为一段区间

数轴上的路线访问的是连续区间。对于选中的最左水果坐标 L、最右水果坐标 R，区间内的水果都会经过，且数量均为正；只需判断覆盖这段区间的最少步数。

访问 L、R 时，先到某个端点再走到另一个端点即可。无论先访问谁，两个端点之间的 R − L 都要走；先到端点的代价取较小值。因此统一公式为：

cost(L, R) = (R - L) + min(|startPos - L|, |startPos - R|)
  • 全部在左侧：最少步数为 startPos − L。
  • 全部在右侧：最少步数为 R − startPos。
  • 跨越起点：记 a = startPos − L、b = R − startPos，代价为 min(2a + b, a + 2b)。

最优路线至多转向一次。区间跨度本身不是总代价，还必须算上从起点走到第一个端点的距离。

完整过程：滑动窗口
  1. 令左指针 left = 0，窗口水果和 sum = 0，答案 best = 0。
  2. 右指针 right 依次遍历每一堆水果，将它的数量加入 sum。
  3. 若非空窗口的 cost > k，移除左端水果并令 left++；重复直到窗口可达或变空。
  4. 用当前窗口和更新答案。窗口为空时和为 0，不访问越界端点。
  5. 返回 best。原数组已经有序，不必排序，也不必枚举每一个坐标。
以示例 2 为例：坐标 0 不可达，被移除；窗口随后从 [4,4] 扩到 [4,7]，水果和依次为 1、8、10、14，最少步数分别为 1、1、3、4。加入坐标 10 后超预算，逐个移除左端，最终窗口为空；最大值仍为 14。


为什么正确
1. 区间最少代价准确
任意覆盖两个端点的路线，都至少走完端点距离 R − L，并先从起点走到某一端点，总代价下界为上述公式。选择较近端点作为首次到达的端点，再走到另一个端点，恰好达到下界。
2. 收缩不会丢掉未来答案
固定左端，右端向右扩展时，必须覆盖的区间变大，所需最少步数不会减小。因此当前不可达的左端，未来也不可能因右端继续增大而重新可达，左指针可以只向右移动。
3. 每个右端都取到最优可达窗口
收缩停止时，留下的是当前右端能配对的最靠左可达端点。更靠左都不可达，更靠右会丢掉正数水果，不可能得到更大水果和。遍历所有右端，就覆盖了最优采摘区间的右端，并取得全局最大值。


边界与复杂度
  • k = 0：只有起点水果能保留；没有起点水果则为 0。
  • 所有水果在同一侧：公式自动化简为最远端到起点的距离，不强制来回。
  • 全部不可达或只有一堆水果：允许窗口变空，先判断 left ≤ right 再计算代价。
  • 恰好耗尽步数仍可行：收缩条件是 cost > k，不是大于等于。
  • 最大总量为 10⁵ × 10⁴ = 10⁹，Java/C++ 的 32 位有符号整数足够，JavaScript Number 也可精确表示。
时间 O(n)
每堆水果加入和移除各至多一次。
额外空间 O(1)
仅用左右指针与累加器；演示保存历史帧的空间不计入提交算法。

Java
class Solution {
    public int maxTotalFruits(int[][] fruits, int startPos, int k) {
        int left = 0, sum = 0, best = 0;
        for (int right = 0; right < fruits.length; right++) {
            sum += fruits[right][1];
            while (left <= right &&
                   cost(fruits[left][0], fruits[right][0], startPos) > k) {
                sum -= fruits[left++][1];
            }
            best = Math.max(best, sum);
        }
        return best;
    }

    private int cost(int l, int r, int s) {
        return r - l + Math.min(Math.abs(s - l), Math.abs(s - r));
    }
}

Python 3
from typing import List

class Solution:
    def maxTotalFruits(self, fruits: List[List[int]], startPos: int, k: int) -> int:
        def cost(l: int, r: int) -> int:
            return r - l + min(abs(startPos - l), abs(startPos - r))

        left = total = best = 0
        for right, (position, amount) in enumerate(fruits):
            total += amount
            while left <= right and cost(fruits[left][0], position) > k:
                total -= fruits[left][1]
                left += 1
            best = max(best, total)
        return best


C++
#include <vector>
#include <algorithm>
#include <cstdlib>
using namespace std;

class Solution {
public:
    int maxTotalFruits(vector<vector<int>>& fruits, int startPos, int k) {
        auto cost = [startPos](int l, int r) {
            return r - l + min(abs(startPos - l), abs(startPos - r));
        };
        int left = 0, sum = 0, best = 0;
        for (int right = 0; right < static_cast<int>(fruits.size()); ++right) {
            sum += fruits[right][1];
            while (left <= right &&
                   cost(fruits[left][0], fruits[right][0]) > k) {
                sum -= fruits[left++][1];
            }
            best = max(best, sum);
        }
        return best;
    }
};


替代方案
  • 前缀和 + 二分端点：枚举一个水果端点，在另一侧二分满足代价约束的最远端点，再用前缀和求区间总量。时间 O(n log n)，空间 O(n)，适合先从区间查询理解问题。
  • 枚举转向距离：枚举先向左或右走的距离 d。若转向并越过起点，另一侧最多走 k − 2d，需保证其非负；同时单独考虑只向一侧行走。利用坐标前缀和查询，时间可做到 O(n + U + k)，空间 O(U)，U 是坐标范围大小，依赖本题坐标上限。
  • 枚举所有水果区间：前缀和求量、公式判定，O(n²) 时间、O(n) 空间，只适合小规模思考，无法用于 10⁵ 个位置。


常见错误
  • 只比较 R − L ≤ k：遗漏起点到端点的距离。
  • 只计算先左后右：起点更靠近右端时可能漏掉更短路线。
  • 用下标差当步数：相邻水果的坐标可能相差很远。
  • 窗口超预算只移除一次：必须用 while，直到重新可达。
  • 在收缩前更新答案：会把不可达窗口的水果计入结果。
  • 额外减掉起点水果：窗口求和本来每堆只计一次，重走路线无需重复累加或扣除。
面试追问
  • 要求回到起点怎么办？令 a = max(0, startPos − L)，b = max(0, R − startPos)，代价改为 2(a + b)；仍可利用区间可达性的单调性。
  • 如果水果数量允许为负呢？“最靠左的可达窗口和最大”不再成立，需要重新处理区间权值优化，不能照搬当前窗口和结论。
  • 如何返回实际路线？更新答案时记录最佳 L、R，先去距离起点更近的端点，再走到另一个；空答案可直接停留原地。
  • 坐标不排序或者重复呢？先排序并合并重复位置，预处理 O(n log n)，再运行窗口；这与本题已排序且唯一的输入保证不同。
