01 / PROBLEM

题目描述

给定一个正整数 n。把它写成二进制，并从最右侧最低位开始，以 0 为起点给每一位编号。

even 是值为 1 且下标为偶数的位数；odd 是值为 1 且下标为奇数的位数。返回 [even, odd]。

Constraints

1 <= n <= 1000

位下标从右向左递增：最右侧是下标 0。

Example 01

输入
n = 50
输出
[1, 2]

50 的二进制是 110010，其中下标 1、4、5 的位为 1。

Example 02

输入
n = 2
输出
[0, 1]

2 的二进制是 10，只有下标 1 的位为 1。

04 / SOLUTION

按位检查，一次完成

&1

核心洞察

最低位可以用 n & 1 读取。每处理一位就把 n 右移，同时让下标加一；当该位为 1 时，根据下标奇偶更新对应计数。

完整过程

  1. 建立 ans = [0, 0]，其中位置 0、1 分别保存偶数和奇数下标计数。
  2. 从下标 i = 0 开始，只要 n > 0 就读取最低位。
  3. 若最低位为 1，执行 ans[i & 1]++。
  4. 将 n 右移一位，并进入下一个下标。

边界与复杂度

n = 1 时只访问下标 0，结果为 [1, 0]。题目保证 n 为正数，无需定义 0 的特殊计数。

时间 O(log n)额外空间 O(1)

正确性证明

第 i 次循环开始时，当前 n 的最低位正是原数下标 i 的位，因为之前已经右移了 i 次。算法仅在该位为 1 时更新，并用 i & 1 唯一确定它属于偶数下标计数还是奇数下标计数。右移后继续处理下一位，既不遗漏也不重复。循环结束时所有二进制位都已处理，因此返回的两个计数正确。

替代方案

约束很小时，也可以用两个交替掩码分别与 n 做按位与，再统计 1 的数量。它能并行筛位，但需要额外的掩码或语言内置 popcount；逐位扫描更直接，也不依赖位宽。

常见错误

  • 按二进制字符串的从左到右位置编号，忘记下标从最低位开始。
  • 把值为 0 的位也计入对应下标。
  • 先右移再检查，导致所有下标错开一位。

面试追问

  • 能否不用显式下标？ 可以每次处理两位：先累计偶数位，再右移并累计奇数位。
  • 如果整数非常大？ 可对任意精度整数重复取最低位与右移，复杂度仍与有效位数成正比。
  • 如何一次处理固定字长？ 使用交替位掩码配合 popcount。

Java

官方可提交签名
class Solution {
    public int[] evenOddBit(int n) {
        int[] ans = new int[2];
        int index = 0;

        while (n > 0) {
            if ((n & 1) == 1) {
                ans[index & 1]++;
            }
            n >>= 1;
            index++;
        }
        return ans;
    }
}
