矩阵区域和

一个格子的答案，来自它周围被矩阵边界裁剪后的方形区域。先用交互演示观察区域如何移动，再决定怎样把重复求和变快。

英文题名Matrix Block Sum
参数mat, k
返回值integer[][]
标签数组 · 矩阵 · 前缀和
1

题目要求

给定一个 m × n 整数矩阵 mat 和整数 k，返回同样大小的矩阵 answer。对每个位置 (i, j)，把所有仍在矩阵内、且行号位于 [i-k, i+k]、列号位于 [j-k, j+k] 的元素相加，所得总和就是 answer[i][j]。

answer[i][j] = Σ mat[r][c]，其中 |r-i| ≤ k、|c-j| ≤ k 且坐标合法

约束

  • m == mat.length
  • n == mat[i].length
  • 1 ≤ m, n, k ≤ 100
  • 1 ≤ mat[i][j] ≤ 100

官方示例 1

输入：mat = [[1,2,3],[4,5,6],[7,8,9]], k = 1
输出：[[12,21,16],[27,45,33],[24,39,28]]

官方示例 2

输入：mat = [[1,2,3],[4,5,6],[7,8,9]], k = 2
输出：[[45,45,45],[45,45,45],[45,45,45]]

二维前缀和题解

核心洞察：先预处理从左上角到任意位置的矩形总和，之后每个目标格的区域和都能用四次查询通过容斥得到。

定义与容斥

建立大小为 (m + 1) × (n + 1) 的前缀和矩阵 pre，额外的第 0 行与第 0 列全为 0。pre[i+1][j+1] 表示原矩阵中行 0..i、列 0..j 的总和。

pre[i+1][j+1] = mat[i][j] + pre[i][j+1] + pre[i+1][j] - pre[i][j]

目标格 (i,j) 对应闭区间 [r1,r2] × [c1,c2]，其中端点经过边界裁剪。由于前缀矩阵使用半开边界，区域和为：

pre[r2+1][c2+1] - pre[r1][c2+1] - pre[r2+1][c1] + pre[r1][c1]

完整过程

  1. 初始化前缀矩阵。创建额外一行一列的零边界，避免查询时出现负下标和大量分支。
  2. 一次遍历完成预处理。对每个 mat[i][j]，加上上方与左方前缀，再减去被重复计算的左上前缀。
  3. 裁剪每个区域。r1=max(0,i-k)、r2=min(m-1,i+k)，列边界同理。
  4. 用四个前缀值求和。大矩形减去上方和左方，多减一次的左上角再加回来。

正确性：前缀定义成立

按行列顺序计算时，上方、左方和左上方前缀均已知。上方与左方的并集覆盖目标前缀矩形，左上区域被计算两次，减去一次后再加当前格，恰好得到全部元素一次。

正确性：查询公式成立

从截至右下角的大前缀中减去目标上方与左方区域；两者共同包含的左上区域被减了两次，所以补回一次。最终只保留裁剪矩形内的元素，且每个恰好一次。

边界处理

k 可能覆盖整个矩阵；用 max/min 统一裁剪即可。额外零边界让 r1=0 或 c1=0 时公式仍然有效。单行、单列、单元素矩阵无需特判。

复杂度

构建前缀和需要 O(mn)，查询全部 mn 个位置仍为 O(mn)；前缀矩阵和答案矩阵使用 O(mn) 空间。若不计必须返回的答案，辅助空间为 O(mn)。

替代方案

直接枚举：每个位置遍历最多 (2k+1)² 个格子，时间为 O(mnk²)，实现直观但在上限下重复工作明显。两次滑动窗口：先对每行计算宽度为 2k+1 的横向和，再对列做同样处理，也能达到 O(mn)；但二维前缀和更直接地支持任意矩形查询。

class Solution {
    public int[][] matrixBlockSum(int[][] mat, int k) {
        int m = mat.length;
        int n = mat[0].length;
        int[][] pre = new int[m + 1][n + 1];

        for (int i = 0; i < m; i++) {
            for (int j = 0; j < n; j++) {
                pre[i + 1][j + 1] = mat[i][j]
                    + pre[i][j + 1]
                    + pre[i + 1][j]
                    - pre[i][j];
            }
        }

        int[][] answer = new int[m][n];
        for (int i = 0; i < m; i++) {
            for (int j = 0; j < n; j++) {
                int r1 = Math.max(0, i - k);
                int c1 = Math.max(0, j - k);
                int r2 = Math.min(m - 1, i + k);
                int c2 = Math.min(n - 1, j + k);
                answer[i][j] = pre[r2 + 1][c2 + 1]
                    - pre[r1][c2 + 1]
                    - pre[r2 + 1][c1]
                    + pre[r1][c1];
            }
        }
        return answer;
    }
}

    const m = mat.length;
    const n = mat[0].length;
    const pre = Array.from({ length: m + 1 },
        () => Array(n + 1).fill(0));

    for (let i = 0; i < m; i++) {
        for (let j = 0; j < n; j++) {
            pre[i + 1][j + 1] = mat[i][j]
                + pre[i][j + 1]
                + pre[i + 1][j]
                - pre[i][j];
        }
    }

    const answer = Array.from({ length: m },
        () => Array(n).fill(0));
    for (let i = 0; i < m; i++) {
        for (let j = 0; j < n; j++) {
            const r1 = Math.max(0, i - k);
            const c1 = Math.max(0, j - k);
            const r2 = Math.min(m - 1, i + k);

                - pre[r1][c2 + 1]
                - pre[r2 + 1][c1]
                + pre[r1][c1];
        }
    }
    return answer;

from typing import List


class Solution:
    def matrixBlockSum(
        self, mat: List[List[int]], k: int
    ) -> List[List[int]]:
        m, n = len(mat), len(mat[0])
        pre = [[0] * (n + 1) for _ in range(m + 1)]

        for i in range(m):
            for j in range(n):
                pre[i + 1][j + 1] = (
                    mat[i][j]
                    + pre[i][j + 1]
                    + pre[i + 1][j]
                    - pre[i][j]
                )

        answer = [[0] * n for _ in range(m)]
        for i in range(m):
            for j in range(n):
                r1, c1 = max(0, i - k), max(0, j - k)
                r2, c2 = min(m - 1, i + k), min(n - 1, j + k)
                answer[i][j] = (
                    pre[r2 + 1][c2 + 1]
                    - pre[r1][c2 + 1]
                    - pre[r2 + 1][c1]
                    + pre[r1][c1]
                )
        return answer

常见错误

  • 混淆原矩阵的闭区间下标与前缀矩阵的半开边界，导致 +1 漏写。
  • 容斥时减去上方和左方后，忘记把重复减去的左上区域加回来。
  • 用 i+k、j+k 直接访问而未通过 min 裁剪。
  • 原地覆盖 mat 后又读取尚未处理的原值，破坏后续计算。
  • 在更宽松的数据范围中忽略整数溢出；本题上限下 int 足够。

面试追问

如果矩阵会被频繁单点更新呢？

静态前缀和每次更新都可能影响右下的大量位置。可讨论二维树状数组或二维线段树，以更高实现复杂度换取更新和区域查询的对数级性能。

能否减少辅助空间？

可用两次一维滑动窗口，先横向、再纵向聚合，仍需要保存中间结果。若允许修改输入或输出复用，能降低额外分配，但代码可读性和接口约束需要权衡。

为什么要多一行一列？

零边界把所有矩形查询统一成同一个公式。当区域贴着上边或左边时，无需访问负下标，也无需单独判断。

如果每个格子的 k 不同呢？

只要矩阵静态，二维前缀和仍然适用；每个位置用自己的 k 计算并裁剪边界，再进行同样的 O(1) 矩形查询。
