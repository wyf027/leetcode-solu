910.
最小差值 II

Smallest Range II · 把每个数推向中心，寻找最紧的一段区间。

题目

给定整数数组 nums 和整数 k。对每个下标恰好选择一次：把 nums[i] 改为 nums[i] + k 或 nums[i] - k。数组分数等于最大元素减最小元素，返回所有选择中可能得到的最小分数。

示例 1
输入：nums = [1], k = 0
输出：0
解释：[1] 的最大值与最小值相同。
示例 2
输入：nums = [0,10], k = 2
输出：6
解释：变为 [2,8]，分数为 8 - 2。
示例 3
输入：nums = [1,3,6], k = 3
输出：3
解释：可变为 [4,6,3]，分数为 6 - 3。
约束
1 ≤ nums.length ≤ 10⁴
0 ≤ nums[i] ≤ 10⁴
0 ≤ k ≤ 10⁴

分界线实验室

使用示例 [1,3,6], k=3。排序后，在每个相邻位置切一刀：左侧统一 +k，右侧统一 −k。

完整题解

准备好后再展开，不打断你先独立思考。

核心洞察

先排序。任意最优选择都可以整理成一种“单调选择”：较小的一段加 k，较大的一段减 k。若存在一对较小值减、较大值加，把它们的方向交换只会让两端更靠近，不会扩大范围。因此只需枚举排序数组的相邻分界。

切在 i 与 i+1 之间：
候选最小值 min(nums[0] + k, nums[i+1] - k)
候选最大值 max(nums[n-1] - k, nums[i] + k)

完整过程

  1. 升序排列数组，先用原始跨度 nums[n-1] - nums[0] 初始化答案。
  2. 枚举 i = 0 ... n-2，令左半段加 k，右半段减 k。
  3. 新范围的两端只可能来自四个边界值，按上式计算并更新答案。

正确性

引理：排序后存在一个最优解，使所有选择 +k 的元素都位于所有选择 -k 的元素之前。若较小元素选 -k、较大元素选 +k，交换二者方向会提升较小值并降低较大值，所以整体最大值不会增大、最小值不会减小。

完备性：这种单调方案必对应某个相邻分界；算法枚举了每个分界以及全体同向时等价的原始跨度。每个分界的最大、最小值计算准确，故取到的最小候选就是全局最优。

边界

  • 单元素：答案为 0。
  • k=0：答案就是原始跨度。
  • 重复元素：排序与分界公式仍成立。
  • 允许结果为负数；题目没有非负限制。

复杂度

排序耗时 O(n log n)，扫描耗时 O(n)；排序若原地进行，额外空间通常为语言排序实现所需的 O(log n) 到 O(n)。

替代方案

暴力枚举每个元素的正负选择需 O(2ⁿ)；它只适合极小输入，无法满足 10⁴ 的约束。

四语言实现

import java.util.Arrays;

class Solution {
    public int smallestRangeII(int[] nums, int k) {
        Arrays.sort(nums);
        int n = nums.length;
        int answer = nums[n - 1] - nums[0];
        for (int i = 0; i < n - 1; i++) {
            int low = Math.min(nums[0] + k, nums[i + 1] - k);
            int high = Math.max(nums[n - 1] - k, nums[i] + k);
            answer = Math.min(answer, high - low);
        }
        return answer;
    }
}

面试追问

为什么不需要枚举每个元素的两个选择？

交换论证把任意最优解规整为“前缀加、后缀减”，选择空间从指数级降为 n 个分界。

为什么初始答案是原始跨度？

所有元素统一加 k 或统一减 k 时跨度不变；这也覆盖分界落在数组两端之外的方案。

如果每个元素可以选择不变呢？

那是另一道题（Smallest Range I 风格的区间选择），当前交换与分界模型不能直接照搬。

常见错误

  • 没有排序就枚举“相邻”分界。
  • 把新最小值只写成 nums[i+1]-k，漏掉 nums[0]+k。
  • 枚举到 i=n-1 后访问越界。
  • 误以为变换后元素必须非负。
  • 忘记考虑所有元素同向变化的原始跨度。
