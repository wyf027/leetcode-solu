适合野炊的日子

Find Good Days to Rob the Bank

↘↗

寻找一个日子：此前一路不升，此后一路不降。

先理解条件，再展开题解。所有日子使用从 0 开始的下标。

01 / 题目

你和朋友计划野炊。整数数组 security 记录每天的建议出行指数，security[i] 对应第 i 天。给定整数 time，返回所有满足下列要求的日子下标，结果顺序不限。

  • 候选日左右各有至少 time 天，即 time ≤ i < n − time。
  • 从第 i − time 天到第 i 天，指数逐日不增加。
  • 从第 i 天到第 i + time 天，指数逐日不减少。
security[i − time] ≥ … ≥ security[i] ≤ … ≤ security[i + time]

两段都包含候选日。相邻值相等也符合要求；time = 0 时无需比较邻日。

参数与返回

goodDaysToRobBank(security, time)
参数：整数数组、非负整数
返回：合格日下标数组

官方约束

1 ≤ security.length ≤ 10⁵
0 ≤ security[i] ≤ 10⁵
0 ≤ time ≤ 10⁵

题意与示例依据本轮官方元数据转述。官方题目 ↗

题解 / 两条连续计数带

核心洞察

同一对相邻元素会被许多候选窗口重复比较。把“从这里可以连续走多远”预先记下来，每个候选日只需查看两个数字。

L[i] 表示以第 i 天结束的连续非递增相邻比较次数；R[i] 表示从第 i 天开始的连续非递减相邻比较次数。计数不包含当天本身，所以边界从 0 开始。

L[0] = 0
L[i] = security[i] ≤ security[i−1] ? L[i−1] + 1 : 0

R[n−1] = 0
R[i] = security[i] ≤ security[i+1] ? R[i+1] + 1 : 0

合格 ⇔ L[i] ≥ time 且 R[i] ≥ time

完整过程

  1. 创建两个长度为 n 的零数组。
  2. 从左向右填写 L，遇到上升就断开并归零。
  3. 从右向左填写 R，比较的仍是原数组中“左值 ≤ 右值”；不满足就归零。
  4. 扫描所有下标，把两个计数都不少于 time 的下标加入结果。

示例 1：L = [0,1,2,3,0,0,1]，R = [0,4,3,2,1,0,0]。time = 2 时，仅下标 2 和 3 同时达到阈值。

INTERACTIVE / 三遍扫描

让两条计数带在候选日相遇

为什么正确

左侧不变量：L[0] = 0。假设 L[i−1] 正确，若 security[i−1] ≥ security[i]，原连续段可向右延长一次，因此 L[i] = L[i−1]+1；否则最后一对已违反条件，任何非空连续段都不能跨越它，故 L[i] = 0。归纳可得整个 L 数组正确。

右侧不变量：从 n−1 开始同理反向归纳。当 security[i] ≤ security[i+1] 时，可以接上右边的连续段；否则归零。于是 R[i] 正好描述所需方向上的最大连续长度。

充分性：两个计数均不少于 time 时，取各自连续段中靠近 i 的 time 次比较，正好得到题目要求的两条不等式链。计数不可能超过实际存在的邻日数，所以边界也满足。

必要性：若 i 是合格日，其左右至少各有 time 次连续有效比较，最大连续计数必然均不少于 time。扫描遍历每个下标一次，因此不遗漏也不重复。

边界与复杂度

  • time = 0：L 和 R 始终非负，返回所有下标。
  • n < 2 × time + 1：没有完整窗口，条件自然筛空；也可提前返回空数组。
  • 全相等数组：L[i] = i，R[i] = n−1−i；恰好选中内部可容纳窗口的日子。
  • n = 1：仅 time = 0 时返回 [0]。比较使用 ≤ / ≥，不能替换成严格不等号。
  • 时间 O(n)，三遍线性扫描；辅助空间 O(n)，输出最多 O(n)。

替代方案

直接检查每个候选日的左右窗口，最坏 O(n × time)，重复比较较多。也可对“左侧上升违例”和“右侧下降违例”建立前缀和，区间违例数为 0 即合格，同样 O(n) 时间、O(n) 空间。若只保存 L，反向扫描时用一个标量维护当前 R 并收集结果，可减少一组数组；返回顺序不限。

进阶可维护两个滑动窗口的违例次数：左窗口计数 security[j] < security[j+1]，右窗口计数 security[j] > security[j+1]；移动候选日时移出旧边、加入新边。初始化和边界处理后，可做到 O(n) 时间、O(1) 辅助空间（不计输出）。

常见错误

  • 把连续长度当成元素个数，却仍与 time 比较；本解法计数的是相邻比较次数。
  • 只比较两个端点，漏掉中途上升或下降。
  • 反向扫描 R 时把不等号也反转，误算成右侧非递增。
  • 跳过相等元素，导致平台上的合格日遗漏。
  • 遇到断点没有归零，错误地拼接不连续的比较。

面试追问

如果 time 经常变化呢？先算 capacity[i] = min(L[i], R[i])，单次查询可按阈值筛选；若只求数量，可对 capacity 排序后二分或构建频次后缀和。

能否流式立即输出当天结果？不能在看到未来之前判定当前日，需要等待后续 time 天数据。离线数组可使用本解法；流式版本必须处理延迟和窗口信息。

如果要求严格下降后严格上升呢？把两个递推中的 ≤ 改为 <，其余计数定义和证明保持相同。

JavaScript

/**
 * @param {number[]} security
 * @param {number} time
 * @return {number[]}
 */
var goodDaysToRobBank = function(security, time) {
    const n = security.length;
    const left = new Array(n).fill(0);
    const right = new Array(n).fill(0);
    for (let i = 1; i < n; i++) {
        if (security[i] <= security[i - 1]) {
            left[i] = left[i - 1] + 1;
        }
    }
    for (let i = n - 2; i >= 0; i--) {
        if (security[i] <= security[i + 1]) {
            right[i] = right[i + 1] + 1;
        }
    }
    const answer = [];
    for (let i = 0; i < n; i++) {
        if (left[i] >= time && right[i] >= time) {
            answer.push(i);
        }
    }
    return answer;
};

from typing import List

class Solution:
    def goodDaysToRobBank(self, security: List[int], time: int) -> List[int]:
        n = len(security)
        left = [0] * n
        right = [0] * n
        for i in range(1, n):
            if security[i] <= security[i - 1]:
                left[i] = left[i - 1] + 1
        for i in range(n - 2, -1, -1):
            if security[i] <= security[i + 1]:
                right[i] = right[i + 1] + 1
        return [i for i in range(n)
                if left[i] >= time and right[i] >= time]
