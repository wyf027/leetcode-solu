题意

翻转一个 0，最长能连起多少个 1？

给定一个 32 位整数 num，你可以把其中一个二进制位从 0 变为 1。返回操作后能够得到的最长连续 1 的长度。所有输入都按完整的 32 位补码处理。

示例 1

输入

num = 1775 (0b11011101111)

输出

8

示例 2

输入

num = 7 (0b0111)

输出

4

边界口径

  • 输入是有符号 32 位整数，负数同样要检查全部位。
  • num = 0 时，翻转任意一位，答案为 1。
  • num = -1 的 32 位全是 1，答案封顶为 32。

题解

先亲手移动接续夹

核心洞察、完整推导和四语言代码默认隐藏。

核心洞察

两个滚动状态足够

plain 表示以当前位结尾、尚未翻转时的连续 1 长度； flipped 表示已经用掉翻转机会的最长尾段。读到 1 时二者都延长；读到 0 时， flipped = plain + 1，而 plain 清零。

完整过程

  1. 把输入解释成完整的 32 位补码，从位 0 扫到位 31。
  2. 当前位为 1：plain 与 flipped 同时加一。
  3. 当前位为 0：在此放置接续夹，令 flipped = plain + 1，再把 plain 置零。
  4. 每一步用 flipped 更新答案，最终结果不超过 32。

边界

不能用 while (num > 0)，否则负数和高位前导 0 会被漏掉；必须固定扫描 32 次。

复杂度

固定扫描 32 位，严格说是 O(32)=O(1) 时间；只维护三个整数，空间 O(1)。

替代方案

枚举每个 0 再统计会退化到 O(32²)；保存所有连续 1 段更直观，但需要额外数组。

面试追问

  • 如果允许翻转至多 k 个 0？使用含零数不超过 k 的滑动窗口。
  • 为什么扫描恰好 32 次？因为输入语义是固定宽度补码，高位同样属于整数。
  • 如果位宽改为 64？替换位类型并扫描 64 次，状态转移不变。

常见错误

  • 使用算术右移导致负数左侧不断补 1，却又不限制循环次数。
  • 连续两个 0 时仍保留上一段 1，错误地跨越两个断点。
  • 全 1 时返回 33，没有把答案限制在 32 位。

class Solution {
    public int reverseBits(int num) {
        int plain = 0;
        int flipped = 0;
        int best = 1;

        for (int i = 0; i < 32; i++) {
            if ((num & 1) == 1) {
                plain++;
                flipped++;
            } else {
                flipped = plain + 1;
                plain = 0;
            }
            best = Math.max(best, flipped);
            num >>>= 1;
        }
        return Math.min(best, 32);
    }
}
