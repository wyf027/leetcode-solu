01题目

给定一个用行程长度编码表示的整数数组 nums。从下标 0 开始，每两个相邻元素构成一对：

[freq, val] = [nums[2 × i], nums[2 × i + 1]]

这一对表示在解压后的子列表中连续放入 freq 个 val。按原顺序连接所有子列表，返回完整的解压列表。

示例 1

输入
nums = [1,2,3,4]
输出
[2,4,4,4]
解释
[1,2] → [2]；[3,4] → [4,4,4]

示例 2

输入
nums = [1,1,2,3]
输出
[1,3,3]

02约束

  • 2 <= nums.length <= 100
  • nums.length % 2 == 0
  • 1 <= nums[i] <= 100

函数签名：
decompressRLElist(nums) → integer[]

偶数长度保证每个频次后面一定有对应的数值；所有频次至少为 1。

05题解

核心洞察

输入天然按二元组排列。每次从偶数下标读取频次，从紧邻的奇数下标读取值，把这个值追加指定次数即可；无需先构造所有子列表。

完整过程

  1. 创建空结果数组。
  2. 令 i 从 0 开始，每次加 2。
  3. 读取 freq = nums[i] 与 val = nums[i+1]。
  4. 循环 freq 次，把 val 追加到结果。
  5. 处理完所有数对后返回结果。

正确性

对第 i 个数对，算法恰好追加 freq 个 val，因此生成的子序列与编码定义完全一致。数对按输入顺序处理，追加操作保持各子序列的先后关系。故全部处理后，结果正是所有解压子列表从左到右的连接。

复杂度

设解压后长度为 L = Σ freq。时间复杂度为 O(L)，因为每个输出元素都必须写入一次；除返回数组外，额外空间复杂度为 O(1)。若计入返回值则为 O(L)。

边界情况

  • 只有一个数对，例如 [1,7]。
  • 多个数对的值相同，仍需分别按频次展开。
  • 频次或值达到 100。
  • 输出可能明显长于输入，应以总频次决定容量。

替代方案

可以先把每一对映射成重复数组，再扁平化；表达简洁，但会产生临时数组。也可先求总频次并预分配结果，在 Java/C++ 中减少扩容。两遍扫描更偏工程优化，本题规模下单遍追加已足够。

面试追问

  • 数据以流的形式到达时，如何边读边输出？
  • 若频次可能极大，怎样改为迭代器避免一次占满内存？
  • 怎样预估并预分配输出容量？
  • 编码可能非法时要验证哪些条件？

常见错误

  • 把 freq 和 val 写反。
  • 外层下标每次只加 1，导致数对重叠。
  • 把一个值追加为字符串，产生类型错误。
  • 复杂度误写为 O(nums.length)；实际工作量取决于输出长度。
class Solution {
    public int[] decompressRLElist(int[] nums) {
        int length = 0;
        for (int i = 0; i < nums.length; i += 2) {
            length += nums[i];
        }

        int[] answer = new int[length];
        int index = 0;
        for (int i = 0; i < nums.length; i += 2) {
            int freq = nums[i];
            int val = nums[i + 1];
            for (int count = 0; count < freq; count++) {
                answer[index++] = val;
            }
        }
        return answer;
    }
}

from typing import List

class Solution:
    def decompressRLElist(self, nums: List[int]) -> List[int]:
        answer = []
        for i in range(0, len(nums), 2):
            freq = nums[i]
            val = nums[i + 1]
            answer.extend([val] * freq)
        return answer
