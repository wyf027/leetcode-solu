两个列表的
最小索引总和

在两个各不重复的字符串列表中，找出共同出现、且所在位置之和最小的全部字符串。答案顺序不限。

非会员题 数组 哈希表 字符串 findRestaurant(list1, list2)

先理解问题，再向下探索过程；完整题解默认收起。

01 · Problem

题意

给定字符串数组 list1 和 list2。公共字符串是同时出现在两个列表中的字符串。若某个公共字符串分别位于 list1[i] 与 list2[j]，它的索引和为 i + j。请返回索引和达到全局最小值的所有公共字符串，返回顺序任意。

示例 1 
输入：
list1 = ["Shogun", "Tapioca Express", "Burger King", "KFC"]
list2 = ["Piatti", "The Grill at Torrey Pines", "Hungry Hunter Steakhouse", "Shogun"]

输出：["Shogun"]

解释：唯一的公共字符串是 "Shogun"。
示例 2 
输入：
list1 = ["Shogun", "Tapioca Express", "Burger King", "KFC"]
list2 = ["KFC", "Shogun", "Burger King"]

输出：["Shogun"]

解释："Shogun" 的索引和为 0 + 1 = 1，是最小值。
示例 3 
输入：
list1 = ["happy", "sad", "good"]
list2 = ["sad", "happy", "good"]

输出：["sad", "happy"]

解释：
"happy": 0 + 1 = 1
"sad":   1 + 0 = 1
"good":  2 + 2 = 4
最小索引和为 1，因此前两者都应返回。

约束

  • 1 <= list1.length, list2.length <= 1000
  • 1 <= list1[i].length, list2[i].length <= 30
  • 字符串仅由空格和英文字母组成。
  • list1 内的字符串互不相同；list2 内的字符串也互不相同。
  • 两个列表之间至少存在一个公共字符串。

04 · Solution

准备好看完整题解了吗？

展开后包含思路、证明、复杂度、四种语言实现与面试延伸。

Core Insight

一次建表，一次扫描

核心洞察是：字符串在 list1 中的索引可以预先存进哈希表。随后扫描 list2，即可用近似常数时间判断是否公共，并立刻计算索引和。整个过程中只维护“目前最小索引和”及所有并列字符串。

完整过程

  1. 遍历 list1，建立 字符串 → 索引 的哈希表。
  2. 设置 minSum = ∞，结果数组初始化为空。
  3. 按索引 j 遍历 list2；如果字符串不在哈希表中，就跳过。
  4. 若公共字符串在 list1 中的索引为 i，计算 sum = i + j。
  5. 若 sum < minSum，更新最小值并用当前字符串替换结果；若相等，则追加当前字符串。

正确性证明

不遗漏候选：扫描 list2 的每个元素，并借助哈希表判断其是否也属于 list1，因此每个公共字符串都恰好被考察一次。

保持最优：处理任意前缀后，minSum 等于该前缀内所有已见公共字符串的最小索引和；结果数组恰好保存达到该值的全部字符串。遇到更小值时清空旧结果，遇到相等值时追加，遇到更大值时不变，所以此不变式持续成立。

结论：扫描结束后，前缀就是整个 list2，结果数组因此正好包含全局最小索引和对应的所有公共字符串。

时间复杂度O(n + m)

其中 n、m 分别是两个列表的长度；哈希操作按均摊 O(1) 计。

空间复杂度O(n + k)

哈希表占 O(n)，答案占 O(k)；若不计返回值，则额外空间为 O(n)。

边界情况

  • 只有一个公共字符串：直接成为唯一答案。
  • 多个字符串具有同一最小索引和：必须全部保留，顺序不限。
  • 公共字符串很晚才出现：初始无穷大保证首个公共项可正确更新。
  • 字符串含空格或大小写不同：按完整字符串精确匹配，不做裁剪或大小写归一化。

替代方案

可以用双重循环枚举两个列表的所有配对，空间 O(1)，但时间为 O(nm)，在两边长度均为 1000 时明显更慢。也可以同时为两个列表建表，再遍历其中一个表；逻辑可行，但第二张表并非必要。

import java.util.ArrayList;
import java.util.HashMap;
import java.util.List;
import java.util.Map;

class Solution {
    public String[] findRestaurant(String[] list1, String[] list2) {
        Map<String, Integer> indexByName = new HashMap<>();
        for (int i = 0; i < list1.length; i++) {
            indexByName.put(list1[i], i);
        }

        int minSum = Integer.MAX_VALUE;
        List<String> answer = new ArrayList<>();

        for (int j = 0; j < list2.length; j++) {
            Integer i = indexByName.get(list2[j]);
            if (i == null) {
                continue;
            }

            int sum = i + j;
            if (sum < minSum) {
                minSum = sum;
                answer.clear();
                answer.add(list2[j]);
            } else if (sum == minSum) {
                answer.add(list2[j]);
            }
        }

        return answer.toArray(new String[0]);
    }
}

/**

 * @param {string[]} list2

var findRestaurant = function(list1, list2) {
    const indexByName = new Map();
    for (let i = 0; i < list1.length; i++) {
        indexByName.set(list1[i], i);
    }

    let minSum = Infinity;
    let answer = [];

    for (let j = 0; j < list2.length; j++) {
        const name = list2[j];
        if (!indexByName.has(name)) {
            continue;
        }

        const sum = indexByName.get(name) + j;
        if (sum < minSum) {
            minSum = sum;
            answer = [name];
        } else if (sum === minSum) {
            answer.push(name);
        }
    }

    return answer;
};

from typing import List


class Solution:
    def findRestaurant(
        self, list1: List[str], list2: List[str]
    ) -> List[str]:
        index_by_name = {
            name: index for index, name in enumerate(list1)
        }

        min_sum = float("inf")
        answer: List[str] = []

        for j, name in enumerate(list2):
            if name not in index_by_name:
                continue

            index_sum = index_by_name[name] + j
            if index_sum < min_sum:
                min_sum = index_sum
                answer = [name]
            elif index_sum == min_sum:
                answer.append(name)

        return answer

#include <climits>
#include <string>
#include <unordered_map>
#include <vector>
using namespace std;

class Solution {
public:
    vector<string> findRestaurant(
        vector<string>& list1,
        vector<string>& list2
    ) {
        unordered_map<string, int> indexByName;
        for (int i = 0; i < static_cast<int>(list1.size()); ++i) {
            indexByName[list1[i]] = i;
        }

        int minSum = INT_MAX;
        vector<string> answer;

        for (int j = 0; j < static_cast<int>(list2.size()); ++j) {
            auto it = indexByName.find(list2[j]);
            if (it == indexByName.end()) {
                continue;
            }

            int sum = it->second + j;
            if (sum < minSum) {
                minSum = sum;
                answer.clear();
                answer.push_back(list2[j]);
            } else if (sum == minSum) {
                answer.push_back(list2[j]);
            }
        }

        return answer;
    }
};

常见错误

  • 只返回第一个最小值，遗漏与它索引和相同的字符串。
  • 遇到更小索引和时只追加、不清空旧答案。
  • 把“最小索引和”误解为两个索引分别都最小。
  • 用哈希表取值后以索引 0 作为“不存在”判断，导致漏掉 list1[0]。
  • 对答案排序后误以为题目要求固定顺序；实际上任意顺序都有效。

面试追问

  • 若列表内允许重复字符串？ 需要先保留每个字符串的最小索引，或明确重复项的配对语义。
  • 能否提前结束？ 当扫描到 j > minSum 时，后续索引和至少为 j，不可能再达到当前最小值，可安全结束。
  • 若内存紧张？ 可为较短的列表建表，但要谨慎保持索引含义；若完全不建表，通常要接受 O(nm) 时间。
  • 若数据以流形式到达？ 固定一侧的索引表，流式扫描另一侧，并在线维护最小值和并列答案。
