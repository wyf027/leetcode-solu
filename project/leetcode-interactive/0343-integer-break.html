整数拆分Integer Break

把一个整数拆成至少两个正整数。真正的挑战不是“能不能拆”，而是如何让各部分相乘后尽可能大。

数学 动态规划 非付费题
Problem brief

给定整数 n，将它表示成 k 个正整数之和，其中 k ≥ 2。

在所有合法拆分中，返回各部分乘积的最大值。

参数

返回
int
范围
2…58

你能否定义一个状态，让每次切出第一段后，剩余部分既可以继续拆，也可以选择不拆？

Complete solution

动态规划：决定“继续拆”还是“到此为止”

用前面已经算好的最优结果构造更大的整数；枚举第一刀的位置，就能覆盖所有合法拆分。

核心洞察

  • 令 dp[i] 表示把整数 i 拆成至少两个正整数后能得到的最大乘积。
  • 第一段取 j 时，剩余的 i - j 有两种选择：不再拆，或继续使用它的最优拆分。
  • 因此一次转移要同时比较 j × (i - j) 与 j × dp[i - j]。
dp[i] = max(dp[i], j × (i − j), j × dp[i − j])
Why both?

为什么必须保留“不再拆”？

因为 dp[x] 强制把 x 再拆一次，但当前整体已经通过第一刀满足了“至少两段”。有时直接使用 x 比继续拆更大，例如把 4 看作 2 + 2 时，右侧的 2 不拆即可。

Procedure

完整过程

建立状态。 创建长度为 n + 1 的数组，所有位置初始为 0。
从小到大计算。 对每个 i = 2…n，枚举第一段长度 j = 1…i-1。
比较两条路径。 右侧不拆得到 j × (i-j)；右侧继续拆得到 j × dp[i-j]。
保留最大值。 所有第一刀位置都处理完后，dp[i] 就是整数 i 的答案。
返回结果。 最终返回 dp[n]。
Correctness

正确性说明

归纳假设： 假设对所有小于 i 的正整数，数组已经记录其合法拆分的最大乘积。
覆盖性： 任意一个 i 的合法拆分，都有一个确定的第一段 j。剩余部分要么作为整体出现，要么被继续拆分，两种情况分别对应转移中的两个候选值。
最优性： 若剩余部分继续拆，按归纳假设 dp[i-j] 已经是它能取得的最大乘积。枚举全部 j 并取最大值，因此不会遗漏更优拆分。
结论： 从 i = 2 递推到 n，可得 dp[n] 正是所求最大乘积。
Edges

边界处理

  • n = 2 时只能拆成 1 + 1，答案为 1。
  • n = 3 的最大乘积为 2，而不是 3，因为必须拆分。
  • dp[0] 与 dp[1] 保持 0；转移会显式比较“不拆剩余部分”。
  • 在约束 n ≤ 58 下，答案不超过 32 位有符号整数范围。
Cost

复杂度

时间复杂度
O(n²)

每个 i 枚举所有第一刀位置 j。

空间复杂度
O(n)

使用一维 dp 数组保存子问题答案。

Implementations

四种语言完整代码

均采用相同的动态规划转移
Solution.javaLeetCode 提交格式
class Solution {
    public int integerBreak(int n) {
        int[] dp = new int[n + 1];

        for (int i = 2; i <= n; i++) {
            for (int j = 1; j < i; j++) {
                int keepRemainder = j * (i - j);
                int splitRemainder = j * dp[i - j];
                dp[i] = Math.max(dp[i],
                        Math.max(keepRemainder, splitRemainder));
            }
        }

        return dp[n];
    }
}

class Solution {
public:
    int integerBreak(int n) {
        vector<int> dp(n + 1, 0);

        for (int i = 2; i <= n; ++i) {
            for (int j = 1; j < i; ++j) {
                int keepRemainder = j * (i - j);
                int splitRemainder = j * dp[i - j];
                dp[i] = max(
                    dp[i],

    }

Alternative

替代方案：数学贪心

当 n ≥ 5 时，优先切出 3 通常更有利；若最后剩下 4，应保留为 2 × 2，避免出现乘积较差的 3 + 1。这样可以做到 O(n) 时间、O(1) 空间。

不过面试中需要能解释为什么 3 优于更大的因子，以及为什么余数 1 要改成 2 + 2。动态规划更通用，也更容易从定义严谨推导。

Common mistakes

常见错误

  • 把 dp[i] 允许为 i 本身，导致忘记“至少拆成两段”。
  • 转移时只写 j × dp[i-j]，遗漏右侧不再拆的情况。
  • 循环边界没有覆盖 j = i - 1。
  • 贪心方案直接处理余数 1，得到不必要的乘积损失。
Interview follow-ups

面试追问

能把 DP 的内层循环减半吗？

可以利用左右对称只枚举一半，但必须同时妥善处理两侧“拆或不拆”的状态，代码反而更复杂，数量级仍是 O(n²)。

为什么数学解偏爱 3？

对足够大的整数，拆出 3 后保留的乘积增长更优；任何大于 4 的因子都可以继续拆而不减小乘积，最终结构主要由 3 和少量 2 组成。

若要求输出具体拆分呢？

额外保存每个状态取得最大值时的第一刀位置，以及余数是否继续拆，最后沿决策回溯即可。

若 n 的范围大幅扩大呢？

结果会迅速溢出普通整数；需要明确返回大整数、取模还是比较对数，并据此调整数据类型和算法。
