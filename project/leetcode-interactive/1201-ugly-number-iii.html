丑数 III

在由三种整除规则共同形成的数字序列中，找到排在第 n 位的正整数。

先读题目 打开交互实验室

题目

如果一个正整数能被 a、b 或 c 中至少一个整除，就称它为丑数。给定四个整数 n、a、b、c，返回按从小到大排列后的第 n 个丑数。

函数签名：nthUglyNumber(n, a, b, c) → integer

示例 1

输入：n = 3, a = 2, b = 3, c = 5
输出：4
解释：序列为 2, 3, 4, 5, 6, 8, 9, 10…
      第 3 个数是 4。

示例 2

输入：n = 4, a = 2, b = 3, c = 4
输出：6
解释：序列为 2, 3, 4, 6, 8, 9, 10, 12…
      第 4 个数是 6。

示例 3

输入：n = 5, a = 2, b = 11, c = 13
输出：10
解释：序列为 2, 4, 6, 8, 10, 11, 12, 13…
      第 5 个数是 10。

约束

  • 1 ≤ n, a, b, c ≤ 10⁹
  • 1 ≤ a × b × c ≤ 10¹⁸
  • 结果保证在 [1, 2 × 10⁹] 范围内。

先自己思考：如何快速判断某个数之前一共有多少个丑数？

完整题解

核心洞察

不必逐个生成丑数。对任意候选值 x，可以计算区间 [1, x] 中有多少个数能被 a、b 或 c 整除。这个计数随 x 单调不减，因此答案是“计数第一次达到 n 的位置”。

容斥计数

count(x) = ⌊x/a⌋ + ⌊x/b⌋ + ⌊x/c⌋ − ⌊x/lcm(a,b)⌋ − ⌊x/lcm(a,c)⌋ − ⌊x/lcm(b,c)⌋ + ⌊x/lcm(a,b,c)⌋

两两交集被重复计入，所以减去；三个集合的共同交集被多减一次，所以再加回来。

完整过程

  1. 1. 用欧几里得算法求最大公约数，并以 lcm(x,y)=x/gcd(x,y)×y 计算最小公倍数，先除后乘降低溢出风险。
  2. 2. 预先算出 ab、ac、bc 和 abc 四个最小公倍数。
  3. 3. 在闭区间 [1, 2×10⁹] 上二分。令 mid = low + (high-low)/2。
  4. 4. 若 count(mid) ≥ n，说明第 n 个丑数不大于 mid，令 high=mid；否则令 low=mid+1。
  5. 5. 当 low=high 时，它就是计数第一次达到 n 的最小位置，也就是答案。

正确性证明

引理 1：容斥公式准确给出不超过 x 的丑数个数。三个单集合计数相加后，两两交集各被重复一次；减去三组两两交集后，三者共同交集净计数为 0；最后加上三者共同交集，使每个满足条件的数恰好计数一次。

引理 2：count(x) 单调不减。增大 x 只会让集合 [1,x] 扩张，不会移除已有丑数。

循环不变式：二分搜索的答案始终位于 [low, high]。当 count(mid)≥n 时，最早达标位置不大于 mid；否则所有不大于 mid 的位置都未达标，答案只能在右侧。

结论：区间最终收敛到一个位置。由不变式和更新条件，该位置正是使计数达到 n 的最小整数，因此是第 n 个丑数。

边界处理

  • a/b/c=1 时所有正整数均可能直接满足。
  • 除数相同或互为倍数时，容斥仍然成立。
  • Java/C++ 使用 64 位整数；JavaScript 使用 BigInt 处理最小公倍数与计数。

复杂度

预处理 GCD 为 O(log M)。二分最多约 31 轮，每轮常数次整除，总时间 O(log 2×10⁹ + log M)，额外空间 O(1)。

替代方案

最小堆逐个生成并去重，复杂度依赖 n，当 n 接近 10⁹ 时不可行。利用一个完整 LCM 周期直接跳跃也能推导，但实现和溢出处理更复杂，二分更稳健。

四语言完整实现

class Solution {
    public int nthUglyNumber(int n, int a, int b, int c) {
        long ab = lcm(a, b);
        long ac = lcm(a, c);
        long bc = lcm(b, c);
        long abc = lcm(ab, c);
        long low = 1, high = 2_000_000_000L;

        while (low < high) {
            long mid = low + (high - low) / 2;
            long count = mid / a + mid / b + mid / c
                    - mid / ab - mid / ac - mid / bc + mid / abc;
            if (count >= n) high = mid;
            else low = mid + 1;
        }
        return (int) low;
    }

    private long gcd(long x, long y) {
        while (y != 0) {
            long next = x % y;
            x = y;
            y = next;
        }
        return x;
    }

    private long lcm(long x, long y) {
        return x / gcd(x, y) * y;
    }
}

 * @param {number} n
 * @param {number} a
 * @param {number} b
 * @param {number} c
 * @return {number}
 */
var nthUglyNumber = function(n, a, b, c) {
    const gcd = (x, y) => {
        while (y !== 0n) [x, y] = [y, x % y];
        return x;
    };
    const lcm = (x, y) => x / gcd(x, y) * y;

    const target = BigInt(n);
    const A = BigInt(a), B = BigInt(b), C = BigInt(c);
    const ab = lcm(A, B), ac = lcm(A, C), bc = lcm(B, C);
    const abc = lcm(ab, C);
    let low = 1n, high = 2000000000n;

    while (low < high) {
        const mid = low + (high - low) / 2n;
        const count = mid / A + mid / B + mid / C
            - mid / ab - mid / ac - mid / bc + mid / abc;
        if (count >= target) high = mid;
        else low = mid + 1n;
    }
    return Number(low);
};
class Solution:
    def nthUglyNumber(self, n: int, a: int, b: int, c: int) -> int:
        def gcd(x: int, y: int) -> int:
            while y:
                x, y = y, x % y
            return x

        def lcm(x: int, y: int) -> int:
            return x // gcd(x, y) * y

        ab, ac, bc = lcm(a, b), lcm(a, c), lcm(b, c)
        abc = lcm(ab, c)
        low, high = 1, 2_000_000_000

        while low < high:
            mid = low + (high - low) // 2
            count = (mid // a + mid // b + mid // c
                     - mid // ab - mid // ac - mid // bc
                     + mid // abc)
            if count >= n:
                high = mid
            else:
                low = mid + 1
        return low

常见错误

  • 只把三个整除计数相加，忘记用容斥去重。
  • 把 lcm(a,b,c) 写成 a×b×c，在除数有公共因子时出错。
  • 使用 32 位整数计算乘积，导致溢出。
  • 二分更新写成 high=mid-1 却仍采用左闭右闭的“首个满足”模板，错过答案。
  • JavaScript 全程使用 Number 计算最高达 10¹⁸ 的 LCM，产生精度风险。

面试追问

为什么二分上界可以固定为 2×10⁹？

题目保证答案位于该范围内，因此它是合法且统一的右边界。也可以取 min(a,b,c)×n 并进行安全的 64 位运算。

如何推广到 k 个除数？

计数仍可二分，但直接容斥需要枚举非空子集，复杂度为 O(2ᵏ)。当 k 较大时要利用重复 LCM 合并、莫比乌斯思想或针对约束设计其他计数方式。

为什么返回的是第 n 个而不是第一个“大于”等位置？

我们寻找最小的 x 使 count(x)≥n。计数只在丑数位置增加，因此这个最小达标位置本身必然是丑数，且恰好排第 n。
