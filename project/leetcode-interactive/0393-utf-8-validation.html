393. UTF-8 编码验证

把每个整数看成一个字节，只检查它的二进制前缀。你能在不解码字符的情况下，判断整段数据是否符合 UTF-8 的结构规则吗？

中等 题号 393 非付费题 validUtf8(data)
1—4 字节每个字符的合法长度
0 / 110 / 1110 / 11110首字节前缀
10所有延续字节前缀
O(n)一次线性扫描
Problem

题目描述

给定整数数组 data，其中每个整数只代表一个字节（使用最低 8 位），请判断整段数据是否是一个有效的 UTF-8 编码序列。

UTF-8 中一个字符占 1 到 4 个字节。单字节字符以 0 开头；多字节字符的首字节先出现与总字节数相同数量的连续 1，随后是一个 0，剩余每个延续字节都必须以 10 开头。所有 x 位均可为 0 或 1。

1 字节0xxxxxxx
2 字节110xxxxx 10xxxxxx
3 字节1110xxxx 10xxxxxx 10xxxxxx
4 字节11110xxx 10xxxxxx 10xxxxxx 10xxxxxx
函数形式：输入 data: integer[]，返回 boolean。本题按给定的位模式验证结构，不要求真正还原 Unicode 码点。

约束

  • 1 <= data.length <= 2 × 10⁴
  • 0 <= data[i] <= 255

Core Insight

核心洞察：只维护“还欠几个延续字节”

1

识别首字节

从最高位开始数连续的 1。0 个表示单字节字符；2、3、4 个分别声明对应长度的多字节字符。

2

拒绝非法声明

恰好 1 个前导 1 表示孤立的延续字节；超过 4 个则超出题目允许范围，两者立即无效。

3

核对延续字节

首字节声明长度为 k 后，紧随的 k−1 个字节必须满足 (byte & 0b11000000) == 0b10000000。

4

按字符跳跃

当前字符完整合法后，索引一次跳过 k 个字节，继续检查下一个字符，直到数组末尾。

Process

完整过程

  1. 令索引 i = 0，从左到右扫描。
  2. 取 data[i] 的最低 8 位。如果最高位为 0，这是一个完整的单字节字符，令 i += 1。
  3. 否则，从掩码 10000000 开始右移，统计首字节开头连续 1 的个数 count。
  4. 若 count == 1 或 count > 4，返回 false；若剩余数组不足 count - 1 个字节，也返回 false。
  5. 依次检查接下来的 count - 1 个字节是否都以 10 开头；任意一个不满足就返回 false。
  6. 令 i += count。扫描结束仍未发现冲突，返回 true。
本题语义边界：这里验证的是题目列出的字节前缀结构，不额外拒绝过长编码、代理项或超过 Unicode 最大码点的序列。若面试官要求严格遵守现代 Unicode 标准，需要增加码点范围规则。
Correctness

正确性证明

  1. 首字节分类正确。算法数最高位开始的连续 1，因此会把 0xxxxxxx 识别为 1 字节字符，把 110 / 1110 / 11110 分别识别为 2、3、4 字节字符；1 个或超过 4 个前导 1 不属于任何合法首字节形式。
  2. 单个多字节字符验证正确。首字节声明 k 后，算法准确检查后续 k−1 个位置是否存在且前两位为 10，这与题目对延续字节的条件完全相同。
  3. 扫描不会重叠或遗漏。每次成功时，算法恰好前进当前字符占用的字节数；所以已检查字节不会重复，下一次检查从下一个字符首字节开始。
  4. 结论正确。若算法返回 true，数组被完整划分成符合规则的字符；若输入有效，每个字符都会通过上述两类检查，算法不会误拒绝。因此算法当且仅当输入有效时返回 true。
Complexity

复杂度

O(n)时间：每个字节最多被检查一次
O(1)空间：只使用索引、计数和位掩码
Boundaries

关键边界

  • 数组只含 ASCII 字节，如 [0] 或 [65, 66]。
  • 首字节位于末尾，却声明还需要延续字节，如 [194]。
  • 以孤立延续字节开头，如 [128]。
  • 首字节有 5 个或更多连续 1，如 [248, 128, 128, 128, 128]。
  • 一个字符结束后紧接下一个字符，索引必须落到新的首字节。
Implementation

四语言完整代码

Java · LeetCode 可提交
class Solution {
    public boolean validUtf8(int[] data) {
        int i = 0;

        while (i < data.length) {
            int first = data[i] & 0xFF;
            int count = 0;
            int mask = 0x80;

            while ((first & mask) != 0) {
                count++;
                mask >>= 1;
            }

            if (count == 0) {
                i++;
                continue;
            }
            if (count == 1 || count > 4 || i + count > data.length) {
                return false;
            }

            for (int j = 1; j < count; j++) {
                int next = data[i + j] & 0xFF;
                if ((next & 0xC0) != 0x80) {
                    return false;
                }
            }
            i += count;
        }
        return true;
    }
}

    bool validUtf8(vector<int>& data) {
        int i = 0;
        const int n = static_cast<int>(data.size());

        while (i < n) {
            int first = data[i] & 0xFF;

                ++count;
                mask >>= 1;
            }

            if (count == 0) {
                ++i;
                continue;
            }
            if (count == 1 || count > 4 || i + count > n) {
                return false;

                int next = data[i + j] & 0xFF;
                if ((next & 0xC0) != 0x80) {
                    return false;
                }
            }
            i += count;
        }
        return true;
    }
};
Alternatives

替代方案

状态机：维护变量 remaining。遇到首字节时设置还需多少个延续字节，之后每读到一个合法的 10xxxxxx 就减一。这与按字符跳跃本质相同，也很适合流式数据。

字符串前缀：把每个数转成 8 位二进制字符串再检查 startsWith，可读性直观，但会产生额外字符串，空间与常数开销都更大，面试中通常不如位运算方案。

Interview Follow-ups

面试追问

如果数据分块到达，当前数组可能在字符中间结束怎么办？

保留 remaining 状态，不在分块末尾立即判错；只有输入流明确结束而 remaining 仍大于 0 时才判无效。

如何升级为严格的 Unicode UTF-8 验证器？

除结构前缀外，还要拒绝过长编码、UTF-16 代理项 U+D800—U+DFFF，以及超过 U+10FFFF 的码点，并对部分首字节约束后续字节范围。

为什么不能只数整个数组里 10 开头字节的总数？

延续字节必须紧跟在对应首字节之后。只比较总数会丢失顺序与字符边界，可能错误接受局部排列不合法的数据。

Common Mistakes

常见错误

  • 把 10xxxxxx 当成合法首字节，没有拒绝 count == 1。
  • 未检查数组剩余长度，访问了不存在的延续字节。
  • 延续字节只检查最高位是 1，却忘记第二高位必须是 0。
  • 验证完多字节字符后只把索引加 1，导致延续字节被再次当作首字节。
  • 混淆本题的“结构有效”与完整 Unicode 标准中的“码点有效”。
