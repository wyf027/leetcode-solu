最大化花园的美观度

一排花、一把剪刀、两个必须相同的端点。先弄清楚什么能留下，再决定哪一段值得成为你的花园。

Problem · 题目

从一条花径中，修出最美的有效花园

给定整数数组 flowers，其中 flowers[i] 是第 i 朵花的美观度，花朵按原顺序排成一列。你可以删除任意朵花，也可以一朵不删。

删除后得到的花园必须至少有两朵花，而且第一朵与最后一朵的美观度相同。花园的总美观度等于所有保留花朵的美观度之和。返回所有可行删除方案中的最大总美观度。

顺序不会改变：删除可以不连续；选定两端后，中间每一朵花都可以独立决定保留或移除。题目保证至少能构成一个有效花园。

函数签名： maximumBeauty(flowers: integer[]) → integer

示例 1选择更好的端点
输入：flowers = [1,2,3,1,2]
输出：8
解释：保留 [2,3,1,2]，总和为 8。
示例 2删去负数
输入：flowers = [100,1,1,-3,1]
输出：3
解释：保留 [1,1,1]，总和为 3。
示例 3答案可为负
输入：flowers = [-1,-2,0,-1]
输出：-2
解释：保留 [-1,-1]，总和为 -2。

约束

  • 2 ≤ flowers.length ≤ 10⁵
  • -10⁴ ≤ flowers[i] ≤ 10⁴
  • 一定可以通过删除若干朵花（也可能不删）得到有效花园。

Solution · 独立题解

准备好以后，再揭开剪枝法则

题解默认折叠，包含证明、复杂度、四语言实现与面试延伸。

01 · Core insight

固定相等端点后，内部只保留正数

若端点为位置 i < j 且 flowers[i] = flowers[j] = x，两个端点必须保留。对每个内部元素：正数保留只会增大总和，负数删除只会增大总和，零保留与否均可。因此该端点对的最优值是：

2x + Σ max(0, flowers[k])，其中 i < k < j

于是问题变成：扫描每个可能的右端点，快速取得它与同值左端点之间的正数和。

02 · Linear scan

一次扫描 + 哈希表

  1. 维护前缀
    prefix 表示扫描位置之前所有正数的总和。
  2. 记录第一次出现
    对值 x，保存第一次处理完它之后的 prefix。这样做恰好排除了左端点自身。
  3. 遇到重复值
    候选值为 prefix - firstPrefix[x] + 2*x，再更新全局答案。
  4. 推进扫描
    执行 prefix += max(0, x)；仅在 x 首次出现时写入哈希表。
03 · Why earliest

为什么只记最早的同值花？

prefix 只累加非负数，因此单调不减。对固定右端点和值 x，候选式中的当前 prefix 与 2x 固定，要让结果最大，就要减去尽可能小的 firstPrefix[x]。

同一个值第一次出现后记录的前缀最小；之后出现只会相等或更大，所以无需覆盖。即使端点值为负数，这一结论仍成立。

复杂度：扫描一次，时间 O(n)；哈希表最多记录不同值数，空间 O(n)。

04 · Correctness

正确性证明

引理 1：固定合法端点 i,j 后，保留所有内部正数、删除所有内部负数可获得该端点对的最大美观度。因为每个内部元素均可独立删除，保留正数增加总和，删除负数增加总和，零不影响总和。

引理 2：对扫描到的右端点 j，哈希表所存的同值左端点可产生所有同值左端点中的最大候选值。因为正数前缀和单调不减，第一次出现后保存的前缀最小，而候选值会减去该前缀。

定理：算法返回全局最优值。任意有效花园都有一对相等端点；根据引理 1，它在固定端点下的最优值由候选式精确计算。扫描到其右端点时，根据引理 2，算法计算的候选值不小于该端点方案，并用答案取最大值。另一方面，每个候选都对应一对真实相等端点及合法删除方案，不会超过全局最优值。因此最终答案恰为全局最优值。

05 · Edges

边界情况

  • 所有数都为负：答案也可能为负，不能把答案初始化为 0。
  • 恰好两个相同元素：内部和为零，结果就是两个端点之和。
  • 零作为端点或内部值：它不改变前缀，仍能正常形成合法花园。
  • 很大的正数在端点外：不能保留，因为删除不能改变相对顺序，也不能让它越过选定端点。
  • 整数范围内最大总和不超过约 10⁹，Java/C++ 的 32 位有符号整数可容纳；实现仍需用真正的负无穷初始化答案。
06 · Alternatives

替代方案与取舍

枚举端点：枚举所有同值下标对，再扫描内部元素，最坏可达 O(n³)；用前缀和可降到 O(n²)，仍无法应对 10⁵。

完整前缀数组：先建正数前缀数组，再为每个值取最早和最晚位置，也能做到 O(n)，但需要额外数组；流式写法只保留一个前缀标量。

状态 DP：可把哈希表理解为“以值 x 为左端点时的最佳基线”。本质仍是同一前缀差公式，表达更抽象但没有复杂度优势。

07 · Implementations

四种语言完整实现

Java
import java.util.HashMap;
import java.util.Map;

class Solution {
    public int maximumBeauty(int[] flowers) {
        int answer = Integer.MIN_VALUE;
        int positivePrefix = 0;
        Map<Integer, Integer> firstPrefix = new HashMap<>();

        for (int beauty : flowers) {
            if (firstPrefix.containsKey(beauty)) {
                int candidate = positivePrefix
                        - firstPrefix.get(beauty)
                        + 2 * beauty;
                answer = Math.max(answer, candidate);
            }

            positivePrefix += Math.max(0, beauty);
            firstPrefix.putIfAbsent(beauty, positivePrefix);
        }

        return answer;
    }
}

        }

    return answer;

Python
from typing import List


class Solution:
    def maximumBeauty(self, flowers: List[int]) -> int:
        answer = float("-inf")
        positive_prefix = 0
        first_prefix = {}

        for beauty in flowers:
            if beauty in first_prefix:
                candidate = (
                    positive_prefix
                    - first_prefix[beauty]
                    + 2 * beauty
                )
                answer = max(answer, candidate)

            positive_prefix += max(0, beauty)
            if beauty not in first_prefix:
                first_prefix[beauty] = positive_prefix

        return int(answer)
C++
#include <algorithm>
#include <climits>
#include <unordered_map>
#include <vector>
using namespace std;

class Solution {
public:
    int maximumBeauty(vector<int>& flowers) {
        int answer = INT_MIN;
        int positivePrefix = 0;
        unordered_map<int, int> firstPrefix;

        for (int beauty : flowers) {
            auto it = firstPrefix.find(beauty);
            if (it != firstPrefix.end()) {
                int candidate = positivePrefix
                    - it->second
                    + 2 * beauty;
                answer = max(answer, candidate);
            }

            positivePrefix += max(0, beauty);
            firstPrefix.emplace(beauty, positivePrefix);
        }

        return answer;
    }
};

09 · Pitfalls

常见错误

  • 把保留结果误认为必须连续，从而被内部负数拖低。
  • 允许删除端点负数；端点是合法性条件，必须保留。
  • 把答案初始化成 0，导致全负数组返回非法结果。
  • 在看到重复值后覆盖最早前缀，丢掉更优的左端点。
  • 先更新前缀再计算候选，错误地把右端点当作内部正数重复计入。
  • 只选择某个值的最左与最右位置，却忘记解释为什么这是最优的。
