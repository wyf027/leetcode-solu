可互换矩形的组数

Number of Pairs of Interchangeable Rectangles

大小可以不同，形状是否相同？找出所有宽高比一致的矩形对。

237 / 300 · 本地交互学习页 · 官方题目

01 / 题目

给定二维整数数组 rectangles，共有 n 个矩形。第 i 个矩形是 rectangles[i] = [widthᵢ, heightᵢ]，分别表示宽和高，下标从 0 开始。

对任意 i < j，若 widthᵢ / heightᵢ = widthⱼ / heightⱼ，这两个矩形就可以互换。这里比较的是数学上的实数比值，不能用整数除法截断。

返回满足条件的下标对总数。相同尺寸但下标不同的矩形仍是不同元素；宽、高的位置固定，不允许旋转后再比较。

官方示例 1

输入：rectangles = [[4,8],[3,6],[10,20],[15,30]]
输出：6

四个矩形的宽高比都为 1/2。合法下标对为 (0,1)、(0,2)、(0,3)、(1,2)、(1,3)、(2,3)，共 6 对。

官方示例 2

输入：rectangles = [[4,5],[7,8]]
输出：0

4/5 与 7/8 不相等，因此没有可互换的矩形对。

约束

  • n == rectangles.length
  • 1 ≤ n ≤ 10⁵
  • rectangles[i].length == 2
  • 1 ≤ widthᵢ, heightᵢ ≤ 10⁵

03 / 准备好探索解法了吗？

先独立思考，再展开分组演示、正确性推导与四语言实现。

题解 / 把同一种形状放在一起

核心洞察

宽高同时除以它们的最大公约数，得到唯一的最简整数比 (w/g, h/g)。宽高比相等的矩形一定得到同一个键。用哈希表保存每个键已经出现的次数。

当前矩形到来时，如果同组已有 c 个矩形，就增加 c 对，然后才把组内计数增加 1。这样每一对只在较大下标到来时计数。

完整过程与正确性

  1. 初始化空哈希表 count 和答案 ans = 0。
  2. 对当前 [w,h] 用欧几里得算法求 gcd(w,h)。
  3. 构造最简比值键；取出之前出现的数量 c，不存在则为 0。
  4. 执行 ans += c，再令 count[key] = c + 1。
  5. 遍历结束，返回 ans。

例如四个矩形都属于 1:2 组，新增对数依次是 0、1、2、3，答案就是 6。

为什么约分键准确？

正整数分数具有唯一的最简表示。两个宽高比相等，当且仅当约分后的宽和高分别相等。因此哈希表中的组恰好对应所有可能的可互换关系。

循环不变式

处理下标 i 前，表中记录的恰好是所有下标小于 i 的组内数量，答案恰好包含这些下标之间的合法对。初始时表和答案都为空，成立。处理 i 时，只有同组的旧成员能够与它形成新对，数量正好为 c；全部加入后再登记当前元素，不会自配对，也不会重复计数。不变式继续成立。遍历完成时，所有合法下标对都已被统计。

复杂度

设 M 是最大边长，k 是不同比例数。每次 gcd 花费 O(log M)，哈希操作平均 O(1)，总时间为期望 O(n log M)，额外空间 O(k)，最坏 O(n)。这里采用定长整数运算模型。

边界与数值范围

单个矩形输出 0；完全不同比例输出 0；全部同组输出 n(n−1)/2。最大为 4,999,950,000，超过 32 位有符号整数。Java 使用 long，C++ 使用 long long；Python 整数可直接承载；JavaScript Number 的安全整数范围足够。边长为正，gcd 不会为 0。

替代方案

  • 先按最简比统计数量，再对每组求 c(c−1)/2：同样复杂度，但需要最后遍历所有组。
  • 约分后排序，相同键连续计数：O(n log M + n log n) 时间，存储约分结果通常需要 O(n) 空间，可避免哈希的平均复杂度假设。
  • 双循环比较 wᵢhⱼ = wⱼhᵢ：精确但时间 O(n²)，不适合十万规模；乘积最高 10¹⁰，需要足够宽的整数。

常见错误

  • 用整数除法把 1/2 和 1/3 都算成 0。
  • 将比例四舍五入或格式化成有限小数作为键，可能合并不同组；最简整数比更稳妥。
  • 先增加组内数量再累加答案，把当前矩形和自身也计入。
  • 把 1:2 与 2:1 合并，本题不允许旋转。
  • 拼接键不加分隔符，或数字编码的基数太小导致碰撞。
  • 答案使用 int；或者在赋值给 long 之前，乘法已在 int 中溢出。

面试追问

如果允许旋转？ 先将两条边按大小排序，再约分。如果流式删除一个矩形？ 从当前大小为 c 的组删除会消失 c−1 对；先确认该矩形确实存在。如果边长可能是小数？ 必须先明确精度与相等语义，可把固定精度输入转为整数；不能直接沿用本题的整数 gcd。如果要列出所有配对？ 组内保存下标，但输出本身最坏有 Θ(n²) 项。

四语言完整实现

对应官方函数签名。代码仅生成，未编译或运行。Java / C++ 将约分后的 (a,b) 编码成 a × 100001 + b；因为 1 ≤ b ≤ 100000，编码不会碰撞。

Java

import java.util.HashMap;
import java.util.Map;

class Solution {
    public long interchangeableRectangles(int[][] rectangles) {
        Map<Long, Integer> count = new HashMap<>();
        long answer = 0;
        for (int[] r : rectangles) {
            int g = gcd(r[0], r[1]);
            long key = (long) (r[0] / g) * 100001 + r[1] / g;
            int c = count.getOrDefault(key, 0);
            answer += c;
            count.put(key, c + 1);
        }
        return answer;
    }

    private int gcd(int a, int b) {
        while (b != 0) {
            int remainder = a % b;
            a = b;
            b = remainder;
        }
        return a;
    }
}

JavaScript

/**
 * @param {number[][]} rectangles
 * @return {number}
 */
var interchangeableRectangles = function(rectangles) {
    const gcd = (a, b) => {
        while (b !== 0) [a, b] = [b, a % b];
        return a;
    };
    const count = new Map();
    let answer = 0;
    for (const [w, h] of rectangles) {
        const g = gcd(w, h);
        const key = `${w / g}:${h / g}`;
        const c = count.get(key) ?? 0;
        answer += c;
        count.set(key, c + 1);
    }
    return answer;
};

from math import gcd
from typing import List

class Solution:
    def interchangeableRectangles(self, rectangles: List[List[int]]) -> int:
        count = {}
        answer = 0
        for w, h in rectangles:
            g = gcd(w, h)
            key = (w // g, h // g)
            c = count.get(key, 0)
            answer += c
            count[key] = c + 1
        return answer

#include <vector>

class Solution {

    long long interchangeableRectangles(vector<vector<int>>& rectangles) {
        unordered_map<long long, int> count;
        long long answer = 0;
        for (const auto& r : rectangles) {
            int g = gcd(r[0], r[1]);
            long long key = 1LL * (r[0] / g) * 100001 + r[1] / g;
            answer += count[key];
            ++count[key];
        }
        return answer;
    }
};
