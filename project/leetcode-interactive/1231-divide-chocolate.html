LEETCODE 1231HARDPREMIUM数组 · 二分查找

DIVIDE CHOCOLATE分享巧克力

把一整排甜度不同的巧克力切成连续的 k + 1 份。你永远拿最不甜的那份——怎样切，才能让自己的甜度尽可能高？

题目转述

给定整数数组 sweetness，其中每个元素表示一块连续巧克力的甜度。你需要恰好切 k 刀，得到 k + 1 个非空、连续的片段。把其中 k 份送给朋友，自己拿片段甜度总和最小的一份。

目标：选择切法，使你最终拿到的甜度（所有片段和的最小值）最大，并返回这个最大值。

官方方法签名：maximizeSweetness(sweetness, k) → integer

约束

  • 0 ≤ k < sweetness.length ≤ 10⁴
  • 1 ≤ sweetness[i] ≤ 10⁵
  • 每份必须由原数组中至少一个连续元素组成。
  • 答案在 1 到 ⌊sum(sweetness)/(k+1)⌋ 之间。

官方示例

完整参数形式，先观察输入输出，不提前展开题解。

示例 1
输入：sweetness = [1,2,3,4,5,6,7,8,9], k = 5
输出：6
解释：可切成 [1,2,3] / [4,5] / [6] / [7] / [8] / [9]，最小片段和为 6。
示例 2
输入：sweetness = [5,6,7,8,9,1,2,3,4], k = 8
输出：1
解释：需要分成 9 份，每个元素只能单独成份，最小甜度为 1。
示例 3
输入：sweetness = [1,2,2,1,2,2,1,2,2], k = 2
输出：5
解释：一种最优切法是 [1,2,2] / [1,2,2] / [1,2,2]。

题解：二分答案 + 贪心判定

核心洞察

直接枚举切点组合代价太高。换一个问题：若要求每一份的甜度都至少为 x，能否切出至少 k + 1 份？这个可行性具有单调性——x 可行时，更小的值也一定可行，因此可以二分最大的可行 x。

可行(x) ⇔ 从左到右累计，一旦当前和 ≥ x 就立即切一份，最终份数 ≥ k + 1

完整过程

  1. 答案下界设为 1，上界设为总甜度除以份数后的下取整。
  2. 取中点 mid，从左到右累加甜度。
  3. 累计值首次达到 mid 时立即切出一份并清零；这是为后续保留最多甜度的贪心选择。
  4. 若能得到至少 k + 1 份，说明 mid 可行，记录答案并搜索更大的值；否则搜索更小的值。
  5. 二分结束时，最后一个可行值就是最大化后的最小片段和。

正确性证明

  1. 贪心份数最大。 对固定阈值 x，每次一达到 x 就切分，当前切点不会晚于任何其他可行方案的对应切点，所以给余下元素留下的范围最多。归纳可知它能产生最多的合格片段。
  2. 判定等价。 若贪心产生至少 k + 1 份，多余相邻份可以合并，合并后的和仍不少于 x，故能得到恰好 k + 1 份；若贪心都不足，依据上一步，没有其他切法能达到要求。
  3. 单调性成立。 若阈值 x 可行，则同一切法对任意 y ≤ x 也可行；若 x 不可行，任意 y > x 也不可能可行。
  4. 二分返回最优值。 二分始终排除不可能优于已知答案的区间，并保留最大的可行阈值；结束时记录值恰为所有切法中最小片段和的最大值。

边界情况

  • k = 0：不切，答案是整个数组之和。
  • k = n - 1：每块单独一份，答案是数组最小值。
  • 所有甜度相同：最优切分尽量让各片段包含相近数量的元素。
  • 总和可能达到 10⁹；Java/C++ 使用足够宽的整数处理中间和更稳妥。

复杂度

设 n 为数组长度，S 为甜度总和。每次判定为 O(n)，二分执行 O(log(S/(k+1))) 次，总时间 O(n log S)，额外空间 O(1)。

四语言完整代码

class Solution {
    public int maximizeSweetness(int[] sweetness, int k) {
        long total = 0;
        for (int value : sweetness) total += value;

        long left = 1;
        long right = total / (k + 1);
        long answer = 0;

        while (left <= right) {
            long mid = left + (right - left) / 2;
            if (canDivide(sweetness, k + 1, mid)) {
                answer = mid;
                left = mid + 1;
            } else {
                right = mid - 1;
            }
        }
        return (int) answer;
    }

    private boolean canDivide(int[] sweetness, int needed, long target) {
        int pieces = 0;
        long current = 0;
        for (int value : sweetness) {
            current += value;
            if (current >= target) {
                pieces++;
                current = 0;
                if (pieces >= needed) return true;
            }
        }
        return false;
    }
}

替代方案

可以用动态规划枚举前缀、份数和切点，求最大最小值，但常见写法至少需要 O(k·n²) 时间，无法承受 n = 10⁴。回溯枚举所有切点则是组合爆炸。二分答案利用了判定的单调性，是本题规模下的合适选择。

面试追问

  • 为什么贪心达到阈值就立刻切？ 越早切，留给后续片段的元素越多，不会降低最终可形成的合格份数。
  • 切出了多于 k + 1 份怎么办？ 合并任意相邻的多余份；正数之和只会增大，阈值仍满足。
  • 若数组允许负数呢？ 当前贪心与单调结构会失效，需要重新建模，通常考虑动态规划或其他约束。
  • 如何恢复一组切点？ 用最优阈值再贪心扫描，记录前 k 个达标位置，把剩余元素归入最后一份。

常见错误

  • 把目标误写成最大化所有片段和的最大值，而不是最大化最小片段和。
  • 判定时要求恰好形成 k + 1 个贪心片段；正确条件是“至少”，多出的可以合并。
  • 二分上界使用总和而不是 sum/(k+1)，虽可能仍正确但浪费搜索，并更容易写错边界。
  • 可行后没有保存 mid，或错误地向左搜索，导致求成最小可行值。
  • 在 Java/C++ 中忽略求和的整数范围。
