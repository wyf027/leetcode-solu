1680. 连接连续二进制数字

Concatenation of Consecutive Binary Numbers — 先观察比特如何“左移腾位”，再决定是否展开完整题解。

Problem

题目描述

函数：concatenatedBinary(n)

给定整数 n，把 1, 2, …, n 各自的二进制表示按顺序首尾连接。将得到的整段二进制串视为一个整数，返回它对 10⁹ + 7 取模后的十进制值。

输入：整数 n　输出：整数，表示连接结果模 1,000,000,007。

示例 1

输入：n = 1
输出：1
解释："1"₂ = 1。

示例 2

输入：n = 3
输出：27
解释：1 → "1"
      2 → "10"
      3 → "11"
连接："11011"₂ = 27。

示例 3

输入：n = 12
输出：505379714
连接：
"1101110010111011110001001101010111100"
十进制：118505380540
取模后：505379714

约束

  • 1 ≤ n ≤ 10⁵
  • 结果始终对 10⁹ + 7 取模。

Solution

逐个左移并追加

核心洞察

若当前答案是 ans，要在末尾追加整数 i 的二进制表示，设 i 占 k 位，则：

ans = (ans × 2ᵏ + i) mod M

乘 2ᵏ 等价于左移 k 位，恰好为 i 腾出空间；再加上 i 就完成了拼接。

位数如何维护

从 1 递增扫描。只有当 i 是 2 的幂时，它的二进制位数才比前一个数多 1。

(i & (i - 1)) == 0

所以无需对每个数转字符串，也无需调用对数函数；命中 1、2、4、8……时把 bits 加一即可。

完整过程

  1. 初始化 ans = 0、bits = 0，模数 M = 1,000,000,007。
  2. 枚举 i = 1…n。若 i 是 2 的幂，说明进入了更长的二进制区间，令 bits++。
  3. 把旧答案左移 bits 位，再加上 i：ans = ((ans << bits) + i) mod M。
  4. 循环结束后返回 ans。

正确性证明

循环不变式：处理完整数 i 后，ans 等于二进制串 bin(1)bin(2)…bin(i) 所表示整数对 M 的余数。

初始：尚未处理任何数时，空串对应值为 0，ans = 0，不变式成立。

保持：设 bin(i) 长 k 位。把已有串末尾追加它，数值必从 x 变为 x·2ᵏ+i。更新式正计算该值并取模；模运算与加法、乘法相容，因此保存余数不会影响以后结果。

终止：循环结束时已处理到 n，由不变式可知返回值正是完整连接串对应整数对 M 的余数。

复杂度与边界

  • 时间：O(n)，每个整数只处理一次。
  • 额外空间：O(1)。
  • n = 1：首次命中 2 的幂，位数变为 1，答案为 1。
  • 2 的幂：必须先增加位数，再进行本轮左移。
  • 溢出：在定宽语言中用 64 位整数保存乘移后的中间值。

替代方案

  • 字符串拼接：把所有二进制串连起来再转换；概念直接，但巨型字符串和巨型整数都不适合 n = 10⁵。
  • 逐比特滚动：对每个二进制位做 ans = (ans·2+bit)%M；正确，但总操作量为 O(n log n)。
  • 按位数分段：可利用等比数列继续推导，不过实现复杂，面试中通常不如线性扫描稳妥。

class Solution {
    public int concatenatedBinary(int n) {
        final long MOD = 1_000_000_007L;
        long ans = 0L;
        int bits = 0;

        for (int i = 1; i <= n; i++) {
            if ((i & (i - 1)) == 0) {
                bits++;
            }
            ans = ((ans << bits) + i) % MOD;
        }
        return (int) ans;
    }
}

常见错误

  • 在处理 2、4、8 时，先拼接再增加 bits。
  • 误写成只左移 1 位，而不是左移当前整数的完整位数。
  • Java/C++ 使用 32 位 int 保存中间值，导致取模前溢出。
  • JavaScript 用 << 操作普通 Number；它会把操作数截为 32 位。代码中应使用 BigInt。
  • 先构造完整二进制串，造成不必要的时间与空间消耗。
