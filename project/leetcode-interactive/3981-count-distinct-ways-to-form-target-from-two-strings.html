LeetCode 3981 · Hard · 动态规划

统计从两个字符串形成目标字符串的不同方案数

每个 target 字符可从 word1 或 word2 挑一个相同字符；同一来源内的下标必须严格递增，且两边都至少使用一次。来源或下标不同，就是不同方案。

状态的视角

固定已拼出前缀长度 k，再记录两串还能使用的后缀起点 i, j。

推荐解法

按 k 倒推，在 i/j 方向维护后缀和，把“下一次选哪里”压成 O(|target|·|word1|·|word2|)。

题意、示例与约束

示例

word1 = "abc"

word2 = "bac"

target = "abc"

输出 5。例如可选 word1[0], word2[0], word1[2]；两个来源各自的索引都递增。

约束

1 ≤ word1.length, word2.length, target.length ≤ 100；三个字符串只含小写英文字母。结果对 1_000_000_007 取模。

可视化实验室：给每个目标字符选来源

实验室枚举小输入的所有合法选择，并用紫色/青色标出来自两条字符串的下标。它直观看到：跨来源可以交替，但每条轨道内部绝不能回头。

测试与验证

题解（默认收起）

首屏只展示规则与实验；需要时再打开完整动态规划推导。

核心洞察：设 F(k,i,j) 为从两串后缀 word1[i:]、word2[j:] 拼出 target[k:] 的所有方法。下一字符只能从任一串中某个匹配位置取得。对每个 k，把这些“所有后继匹配位置”的求和用后缀累加维护，即可避免再扫描整条后缀。

完整过程

  1. 先计算“不限制两边都使用”的总数 F(0,0,0)。
  2. 倒序处理 k。对每个 (i,j)，分别累积 word1 中 i 右侧的匹配项和 word2 中 j 右侧的匹配项。
  3. 两项相加正好表示下一字符从任一来源取得；不同下标或来源落在不同转移上，因此不会合并。
  4. 总数会包含“全从 word1”与“全从 word2”的方案；各自用普通子序列 DP 计算后相减，剩下的恰为两边至少各用一次。

边界

目标比任何可拼长度更长、无匹配字符、所有字符只能来自一边、重复字符导致多种下标选择，以及答案取模。

复杂度

三维状态表：O(t·n·m) 时间和 O(n·m) 滚动空间，其中 t=|target|、n=|word1|、m=|word2|。

替代方案、追问与常见错误

替代：直接记忆化枚举每个下一匹配位置，概念更直白但会多一层循环。追问：若有三条来源字符串，状态会继续加维，需寻找更强的结构或更小约束。常见错误：把跨字符串的下标也强行递增；忘记扣掉单来源方案；把相同字符但不同下标错误合并。
