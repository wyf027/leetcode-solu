01 / 题意控制单

只能碰 Read4，不能碰文件

已知接口 read4(buf4) 每次从当前文件指针连续读取最多 4 个字符，并返回实际读取数。实现 read(buf, n)，把最多 n 个字符写入目标缓冲区并返回实际写入数。

  • · 每个测试用例只调用一次 read。
  • · buf 空间足以容纳 n 个字符。
  • · 1 ≤ file.length ≤ 500，文件只含英文字母和数字。
  • · 1 ≤ n ≤ 1000。

官方样例 1

输入

file = "abc", n = 4

输出

return = 3, buf = "abc"

官方样例 2

输入

file = "abcde", n = 5

输出

return = 5, buf = "abcde"

官方样例 3

输入

file = "abcdABCD1234", n = 12

输出

return = 12, buf = "abcdABCD1234"

可见空格约定：若输入包含空格，页面会用 ␠ 显示；本题约束只允许字母和数字，官方样例不含空格。

04 / 题解保险柜

先推演，再开锁

核心洞察、完整过程、边界、复杂度、追问、错误与四语言代码默认隐藏。

核心洞察

两级缓冲，复制量取最小值

read4 的返回值 k 可能是 0–4。每轮真正能写入 buf 的字符数是 min(k, n - total)。这样既不越过 n，也不把文件尾之外的槽位当成有效字符。

完整过程

  1. 1. 建立长度为 4 的临时数组 buf4，累计写入量 total = 0。
  2. 2. 当 total < n 时调用 read4(buf4)。
  3. 3. 复制本轮仍需要的字符，更新 total。
  4. 4. 若本轮读取少于 4 个字符，说明到达文件尾，立即结束。

边界

  • · n 大于文件长度：返回文件长度。
  • · n 小于 4：仍可调用一次 read4，只复制前 n 个。
  • · 文件长度恰为 4 的倍数：达到 n 时停止，避免多余调用。
  • · 最后一批小于 4：这是 EOF 信号。

复杂度

时间 O(min(n, L))，其中 L 是文件长度；额外空间 O(1)，临时缓冲固定为 4 个字符。

替代方案取舍

逐字符向 buf4 取值本质相同；面试中用“批量读 + 限量复制”更直接，也更容易证明边界正确。

面试追问

  • · 如果 read 会被调用多次怎么办？
  • · 为什么本题未消费字符可以丢弃？
  • · 如何证明不会写越 buf？

多次调用版本是第 158 题：必须把 buf4 的剩余字符和下标保存为对象状态。

常见错误

· 固定复制 4 个字符，导致超过 n 或复制无效槽位。

· 只判断 k === 0，却在 k < 4 后继续多调用一次。

· 忘记累计目标下标，后续批次覆盖 buf 开头。

· 把第 158 题的跨调用缓存强加到本题，增加不必要状态。

/**
 * The read4 API is defined in the parent class Reader4.
 * int read4(char[] buf4);
 */
public class Solution extends Reader4 {
    public int read(char[] buf, int n) {
        char[] buf4 = new char[4];
        int total = 0;

        while (total < n) {
            int count = read4(buf4);
            int copyCount = Math.min(count, n - total);
            for (int i = 0; i < copyCount; i++) {
                buf[total++] = buf4[i];
            }
            if (count < 4) {
                break;
            }
        }
        return total;
    }
}
