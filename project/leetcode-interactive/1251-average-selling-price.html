平均售价Average Selling Price

价格会随日期变化，销售记录只告诉你“哪天卖了多少”。你的任务是为每种商品给出精确到两位小数的平均售价。

Problem

题目描述

给定商品的分时段价格表 Prices 与销售记录表 UnitsSold，求每个商品的平均售价。结果列名为 average_price，四舍五入到小数点后两位；某商品没有任何销量时，平均售价按 0 计算。结果表顺序不限。

Solution

题解：按有效日期连接，再做加权平均

核心洞察普通平均数不够。每笔销量的贡献是 price × units，最后用总销售额除以总销量。
关键连接除商品编号相等外，还必须满足 purchase_date BETWEEN start_date AND end_date。
保留零销量从 Prices 出发做 LEFT JOIN，再用 COALESCE 把空结果变成 0。

完整过程

  1. 以 Prices 为左表，确保价格表里出现过的每个商品都能留在结果中。
  2. 按 product_id 相等，且购买日期落在闭区间 [start_date, end_date] 内连接销售记录。
  3. 对每个商品汇总 price × units 得到总销售额，同时汇总 units 得到总销量。
  4. 用 NULLIF(SUM(units), 0) 避免除以零，用 COALESCE(..., 0) 处理未售商品，最后保留两位小数。

正确性说明

同一商品的价格时段互不重叠，因此任意一条有效销售记录至多匹配一个价格行；日期连接为它选择了购买当日唯一适用的单价。汇总的 SUM(price × units) 恰好等于该商品全部销售收入，SUM(units) 恰好等于全部售出数量，两者相除就是按销量加权的平均售价。左连接保留无销售匹配的商品，空值回退为 0，故所有要求均得到满足。

边界情况

  • 商品没有销售记录：返回 0.00（判题通常接受数值 0）。
  • 销售发生在 start_date 或 end_date 当天：边界包含在内。
  • UnitsSold 有重复行：每行都代表一笔销量，应全部参与汇总。
  • 同一商品跨多个价格时段销售：每笔销量按它自己的购买日匹配单价。

复杂度

设价格行数为 P、销售行数为 U。SQL 的实际复杂度取决于数据库执行计划与索引；有合适的商品编号和日期索引时，可避免朴素的 O(P × U) 全量比较。额外结果空间与商品数成正比。下方本地语义参考实现为直观的双层匹配，时间复杂度 O(P × U)，额外空间 O(K)，其中 K 为商品数。

代码

官方可提交语言 · MySQL

SELECT
    p.product_id,
    ROUND(
        COALESCE(
            SUM(p.price * u.units) / NULLIF(SUM(u.units), 0),
            0
        ),
        2
    ) AS average_price
FROM Prices AS p
LEFT JOIN UnitsSold AS u
    ON u.product_id = p.product_id
   AND u.purchase_date BETWEEN p.start_date AND p.end_date
GROUP BY p.product_id;

本地语义参考 · 本题官方判题不接受 Java 提交

import java.time.LocalDate;
import java.util.ArrayList;
import java.util.LinkedHashMap;
import java.util.List;
import java.util.Map;

public class AverageSellingPrice {
    record Price(int productId, LocalDate start, LocalDate end, int price) {}
    record Sale(int productId, LocalDate purchaseDate, int units) {}
    record Result(int productId, double averagePrice) {}

    public static List<Result> solve(List<Price> prices, List<Sale> sales) {
        Map<Integer, long[]> totals = new LinkedHashMap<>();
        for (Price price : prices) {
            totals.putIfAbsent(price.productId(), new long[2]);
            for (Sale sale : sales) {
                boolean sameProduct = sale.productId() == price.productId();
                boolean inRange = !sale.purchaseDate().isBefore(price.start())
                        && !sale.purchaseDate().isAfter(price.end());
                if (sameProduct && inRange) {
                    long[] total = totals.get(price.productId());
                    total[0] += (long) price.price() * sale.units(); // revenue
                    total[1] += sale.units();                       // units
                }
            }
        }

        List<Result> answer = new ArrayList<>();
        for (Map.Entry<Integer, long[]> entry : totals.entrySet()) {
            long revenue = entry.getValue()[0];
            long units = entry.getValue()[1];
            double average = units == 0 ? 0.0 : revenue * 1.0 / units;
            average = Math.round(average * 100.0) / 100.0;
            answer.add(new Result(entry.getKey(), average));
        }
        return answer;
    }
}

本地语义参考 · 本题官方判题不接受 JavaScript 提交

/**
 * @param {Array<{productId:number,startDate:string,endDate:string,price:number}>} prices
 * @param {Array<{productId:number,purchaseDate:string,units:number}>} sales
 * @returns {Array<{productId:number,averagePrice:number}>}
 */
function averageSellingPrice(prices, sales) {
  const totals = new Map();

  for (const price of prices) {
    if (!totals.has(price.productId)) {
      totals.set(price.productId, { revenue: 0, units: 0 });
    }
    for (const sale of sales) {
      const sameProduct = sale.productId === price.productId;
      const inRange = sale.purchaseDate >= price.startDate
        && sale.purchaseDate <= price.endDate;
      if (sameProduct && inRange) {
        const total = totals.get(price.productId);
        total.revenue += price.price * sale.units;
        total.units += sale.units;
      }
    }
  }

  return Array.from(totals, ([productId, total]) => ({
    productId,
    averagePrice: total.units === 0
      ? 0
      : Math.round((total.revenue / total.units) * 100) / 100,
  }));
}

本地语义参考 · 官方 Python 入口为 Pandas DataFrame，并非此列表函数

from dataclasses import dataclass
from datetime import date


@dataclass(frozen=True)
class Price:
    product_id: int
    start_date: date
    end_date: date
    price: int


@dataclass(frozen=True)
class Sale:
    product_id: int
    purchase_date: date
    units: int


def average_selling_price(
    prices: list[Price], sales: list[Sale]
) -> list[tuple[int, float]]:
    totals: dict[int, list[int]] = {}

    for price in prices:
        totals.setdefault(price.product_id, [0, 0])
        for sale in sales:
            same_product = sale.product_id == price.product_id
            in_range = price.start_date <= sale.purchase_date <= price.end_date
            if same_product and in_range:
                totals[price.product_id][0] += price.price * sale.units
                totals[price.product_id][1] += sale.units

    result = []
    for product_id, (revenue, units) in totals.items():
        average = 0.0 if units == 0 else round(revenue / units + 1e-12, 2)
        result.append((product_id, average))
    return result

#include <cmath>
#include <map>
#include <string>
#include <utility>
#include <vector>
using namespace std;

struct Price {
    int productId;
    string startDate;
    string endDate;
    int price;
};

struct Sale {
    int productId;
    string purchaseDate;
    int units;
};

vector<pair<int, double>> averageSellingPrice(
    const vector<Price>& prices,
    const vector<Sale>& sales
) {
    map<int, pair<long long, long long>> totals; // revenue, units

    for (const Price& price : prices) {
        totals.try_emplace(price.productId, 0LL, 0LL);
        for (const Sale& sale : sales) {
            bool sameProduct = sale.productId == price.productId;
            bool inRange = price.startDate <= sale.purchaseDate
                        && sale.purchaseDate <= price.endDate;
            if (sameProduct && inRange) {
                totals[price.productId].first += 1LL * price.price * sale.units;
                totals[price.productId].second += sale.units;
            }
        }
    }

    vector<pair<int, double>> answer;
    for (const auto& [productId, total] : totals) {
        double average = total.second == 0
            ? 0.0
            : static_cast<double>(total.first) / total.second;
        average = round(average * 100.0) / 100.0;
        answer.emplace_back(productId, average);
    }
    return answer;
}

替代方案

可先在子查询中把每条销售记录匹配到价格，再按商品聚合；逻辑更分层，但仍需从完整商品集合左连接聚合结果，才能保留零销量商品。若数据库支持，也可用相关子查询逐商品计算，但通常不如一次连接聚合直观。

面试追问

  • 为什么不是 AVG(price)？ 不同价格对应销量不同，必须按销量加权。
  • 为什么日期条件要写在 ON 而不是 WHERE？ 放进 WHERE 会过滤掉左连接产生的空行，使零销量商品消失。
  • 如果价格时段允许重叠会怎样？ 一笔销售可能被重复匹配并重复计入，需要先定义优先级或清洗重叠区间。
  • 可加什么索引？ 可考虑 UnitsSold(product_id, purchase_date)；价格表已有以商品和日期组成的联合主键。

常见错误

  • 使用内连接，遗漏完全没有销量的商品。
  • 只按 product_id 连接，没有用购买日期限定价格时段。
  • 计算 AVG(price) 或对每笔平均值再次平均，忽略销量权重。
  • 先用 WHERE u.purchase_date ... 过滤，意外破坏左连接。
  • 整数除法、除以零或在中间步骤过早四舍五入。
