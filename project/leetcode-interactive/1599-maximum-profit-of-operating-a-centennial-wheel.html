经营摩天轮的最大利润

Maximum Profit of Operating a Centennial Wheel

MEDIUM 在每次轮转与候客变化中，找出利润最高时最早停下的时刻。
Problem

题目描述

一座摩天轮有 4 个座舱，每个座舱最多容纳 4 人。每轮转一次需要支付 runningCost；游客登舱时每人支付 boardingCost。

customers[i] 表示第 i 次轮转前新到达的游客数（下标从 0 开始）。每次最多让 4 人登上最靠近地面的座舱；有空位时不能故意让游客等待，超过容量的人继续排队。你可以在任意时刻停止营业，之后只为让座舱内游客安全下车而进行的轮转不再收费，也不计入经营利润。

目标：返回利润达到最大值所需的最小轮转次数；若利润从未为正，返回 -1。

函数签名

minOperationsMaxProfit(customers, boardingCost, runningCost) -> integer

官方示例

输入：customers = [8,3], boardingCost = 5, runningCost = 6
输出：3
解释：
第 1 轮：4 人登舱，利润 4 × 5 - 1 × 6 = 14。
第 2 轮：4 人登舱，累计利润 8 × 5 - 2 × 6 = 28。
第 3 轮：3 人登舱，累计利润 11 × 5 - 3 × 6 = 37。
最高利润 37 首次出现在第 3 轮。
输入：customers = [10,9,6], boardingCost = 6, runningCost = 4
输出：7
解释：
前三轮每轮 4 人登舱，之后继续消化等待队列。
各轮累计利润依次为 20、40、60、80、100、120、122，
最高利润 122 首次出现在第 7 轮。
输入：customers = [3,4,0,5,1], boardingCost = 1, runningCost = 92
输出：-1
解释：
五轮累计利润依次为 -89、-177、-269、-357、-447。
利润从未为正，因此返回 -1。

约束

  • n == customers.length
  • 1 <= n <= 10^5
  • 0 <= customers[i] <= 50
  • 1 <= boardingCost, runningCost <= 100

完整题解

先独立思考，再按需展开。

核心洞察

真正需要保存的状态只有三个：尚在等待的人数、当前累计利润、历史最高利润首次出现的轮次。每轮先加入新到游客，再让 min(4, waiting) 人登舱，最后把“本轮票款 − 本轮成本”计入利润。

即使数组中的到客记录已经读完，只要仍有人等待，就必须继续模拟，因为后续轮转仍可能提高利润。历史最佳只在利润严格变大时更新，这自然保留了取得最大值的最小轮数。

完整过程

  1. 初始化 waiting = 0、profit = 0、maxProfit = 0、answer = -1。
  2. 当仍有尚未处理的到客记录，或 waiting > 0 时，开启下一轮。
  3. 若对应到客记录存在，把人数加入 waiting。
  4. 令 boarded = min(4, waiting)，从候客中扣除并更新 profit += boarded * boardingCost - runningCost。
  5. 若 profit > maxProfit，保存当前利润和轮次。循环结束后返回保存的轮次；从未出现正利润时仍为 -1。

正确性证明

  1. 候客状态正确：每轮开始加入当轮新客，再让最多 4 人登舱，恰好符合容量限制与“有空位不能等待”的规则。因此每轮结束后的 waiting 等于真实候客数。
  2. 利润状态正确：每轮收入仅来自该轮登舱人数，支出恰为一次运行成本，所以增量 boarded × boardingCost - runningCost 正确；归纳可知累计利润始终正确。
  3. 枚举范围完整：循环覆盖所有有新客到达的轮次，并在到客结束后继续到候客清空。此后再经营只会空转并减少运行成本，不可能产生更优利润，故所有可能的最优停止点均被检查。
  4. 最小轮数正确：仅在利润严格高于历史最大值时更新答案；相同最大利润再次出现不会覆盖先前轮次，因此保留最早轮次。初始最大利润为 0，保证没有正利润时返回 -1。

边界情况

  • 所有轮次利润都不大于 0：返回 -1。
  • 某轮没有新客但之前仍有候客：照常登舱并支付运行成本。
  • 到客数组结束时仍有大量候客：继续轮转直到队列清空。
  • 单轮净收益为 0：不会因为相同利润而把答案推迟。
  • 虽然摩天轮有 4 个座舱，但经营决策按“每次只有地面座舱最多登 4 人”建模，无需追踪游客何时下舱。

复杂度

设输入长度为 n，总游客数为 S。模拟轮数最多为 max(n, ceil(S/4))，时间复杂度为 O(n + S/4)；在本题 customers[i] <= 50 下可写作 O(n)。额外空间复杂度为 O(1)。

四种语言实现

class Solution {
    public int minOperationsMaxProfit(int[] customers,
                                      int boardingCost,
                                      int runningCost) {
        int waiting = 0;
        int profit = 0;
        int maxProfit = 0;
        int answer = -1;
        int rotation = 0;

        while (rotation < customers.length || waiting > 0) {
            if (rotation < customers.length) {
                waiting += customers[rotation];
            }

            int boarded = Math.min(4, waiting);
            waiting -= boarded;
            rotation++;
            profit += boarded * boardingCost - runningCost;

            if (profit > maxProfit) {
                maxProfit = profit;
                answer = rotation;
            }
        }
        return answer;
    }
}

替代方案

可以先求总游客数，再预估最多轮数，按固定次数模拟；也可在满载单轮收益 4 × boardingCost - runningCost <= 0 时做提前判断。但这些优化会引入额外分支，收益有限。统一使用“还有输入或还有候客”的循环更短、更稳健。

面试追问

  • 为什么不用追踪四个座舱？ 票款在登舱时确认，停业后的安全下车轮转免费，因此利润只依赖每轮登舱人数。
  • 为何最大值相等时不更新？ 题目要求取得最大利润的最小轮数。
  • 能否提前结束？ 当输入耗尽、候客为 0 时，后续只能空转亏损，必然可以结束。
  • 若容量改为 k？ 将常数 4 替换为 k，其余不变。

常见错误

  • 到客数组遍历结束便停止，漏掉排队游客带来的后续利润。
  • 用 >= 更新答案，错误地返回了更晚轮次。
  • 把“停业后的免费轮转”理解为经营中也可免除成本。
  • 以 0 为有效答案；题目规定无正利润必须返回 -1。
  • 先登舱再加入当轮新客，颠倒题目给定的事件顺序。
