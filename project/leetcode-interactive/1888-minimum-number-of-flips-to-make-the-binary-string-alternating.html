Minimum Number of Flips to Make the Binary String Alternating

移动可以任意次，反转要尽可能少。先理解两种操作，再自己寻找最优策略。

01 / 题目

给定只由 0 和 1 组成的字符串 s，可以按任意顺序执行任意次以下操作：

  • 类型 1 · 循环左移：把首字符取出并放到字符串末尾。
  • 类型 2 · 反转一位：任选一个字符，把 0 改成 1，或把 1 改成 0。

使最终字符串任意两个相邻字符都不同，返回所需的最少类型 2 操作次数。类型 1 不计入答案；这里的相邻不包括首尾之间。

参数：s: string　返回：integer
约束：1 ≤ s.length ≤ 10⁵，每个 s[i] 都是 '0' 或 '1'。

04 / 题解 · 把旋转变成移动的窗口

核心洞察

每个旋转都能在 s + s 中表示为一个长度为 n 的窗口，起点为 0 到 n − 1。交替串只有两种模式：0101… 和 1010…。固定一个窗口后，它与某个模式的不同位数，就是变成该模式所需的最少反转数。

在虚拟双倍串的绝对下标上定义 A[i] = i mod 2，B[i] = 1 − A[i]。维护窗口与 A 不同的位数 d；因为 A、B 每一位互补，与 B 不同的位数必然是 n − d。因此该窗口的答案是 min(d, n − d)。

窗口起点是奇数时，A 在窗口内从 1 开始，这没有关系：A 与 B 仍覆盖全部两种交替目标。用 s[i % n] 访问虚拟双倍串，无需真的拼接。

完整过程

  1. 令 n 为字符串长度，d = 0，答案初始化为 n。
  2. 枚举右端点 i = 0…2n − 2，把当前字符与 A[i] 的不匹配贡献加入 d。
  3. 若 i ≥ n，移除绝对下标 i − n 的贡献，保持窗口长度至多为 n。
  4. 当 i ≥ n − 1，窗口已满，更新答案为 min(答案, d, n − d)。
  5. 最后一个窗口起点是 n − 1，一共处理 n 个旋转；返回所有窗口的最小值。

以 s = "001" 为例，起点 0 的窗口 001 与 A=010 有 2 位不同，成本为 1；滑到起点 1，移出下标 0 的匹配位、加入下标 3 的不匹配位，d 从 2 变为 3。窗口 010 此时完全匹配 B，成本为 0。奇数长度时旋转确实可能改善答案。

正确性说明

  1. 旋转覆盖：类型 1 只会循环改变起点，所有最终排列都对应 n 个窗口之一。任意穿插的反转可以按字符身份移到全部旋转之后，反转次数不增加，所以枚举最终旋转不会遗漏最优解。
  2. 固定窗口最优：交替目标只能是 A 或 B 的窗口片段。每个不同位至少要反转一次，相同位无需反转；分别反转所有不同位就能达到目标，因此最少成本为 min(d, n − d)。
  3. 计数不变量：每轮先加新字符的贡献，再删除离开窗口的贡献，d 始终等于当前窗口与 A 的不匹配数。只在长度恰为 n 时更新答案。
  4. 全局最优：所有旋转均被覆盖，每个旋转的成本均精确计算，取最小值即为所求。

复杂度与边界

  • 时间 O(n)：恰好访问 2n − 1 个虚拟字符。
  • 额外空间 O(1)：不构造双倍串或模式数组；不计语言的输入参数存储。
  • n = 1：单字符天然交替，答案 0。
  • 全为同一字符：答案为 ⌊n/2⌋。
  • 原串交替：至少有一个窗口成本为 0。
  • 偶数 n：旋转只会保留或交换两种模式的成本，最小值不会改善。奇数 n 则可能改善。

替代方案

  • 枚举旋转后逐位比较两模式：O(n²) 时间、O(1) 额外空间（通过取模访问）。思路直接，但不适合 10⁵ 长度。
  • 构造双倍串并预处理错位前缀和：O(n) 时间、O(n) 空间，查询每个窗口成本；更便于随机查询。
  • 偶数长度可仅比较原串的两种模式；统一滑窗则无需区分奇偶，仍为 O(n)。

常见错误

  • 把循环移动的次数也计入答案：题目只统计类型 2。
  • 只考虑原串：遗漏奇数长度旋转后的更优结果。
  • 删除字符时使用相对下标判断奇偶：应使用它原来的绝对下标 i − n。
  • 在窗口不足 n 时使用 n − d 更新答案：此时互补成本还不是 n − d。
  • 要求首尾也不同：题目要求的是线性相邻；奇数长度交替串合法。
  • 反转所有字符顺序：这里的 flip 是单个位 0/1 互换，不是字符串逆序。

面试追问

为什么偶数长度旋转没收益？跨过连接点时奇偶仍连续，旋转仅交换或保留目标模式；两种成本的最小值不变。

如何恢复操作方案？记录最优窗口起点及选择的模式；先左移到该起点，再逐位输出与选定目标不同的位置。方案输出最多需要 O(n) 空间。

不同字符的反转有不同成本呢？若成本跟随字符移动，可以维护加权错位和，互补成本为窗口总权重减去该和；若权重绑定最终位置，原来的简单增删公式通常不再适用。

Java

class Solution {
    public int minFlips(String s) {
        int n = s.length(), diff = 0, answer = n;
        for (int i = 0; i < 2 * n - 1; i++) {
            char expected = (i % 2 == 0) ? '0' : '1';
            if (s.charAt(i % n) != expected) diff++;
            if (i >= n) {
                int left = i - n;
                char oldExpected = (left % 2 == 0) ? '0' : '1';
                if (s.charAt(left % n) != oldExpected) diff--;
            }
            if (i >= n - 1) {
                answer = Math.min(answer, Math.min(diff, n - diff));
            }
        }
        return answer;
    }
}
