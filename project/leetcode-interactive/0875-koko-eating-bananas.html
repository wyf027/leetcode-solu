爱吃香蕉的珂珂
Koko Eating Bananas

速度太慢，警卫回来时还没吃完；速度太快，又不符合珂珂“能慢则慢”的原则。你的任务，是找出刚刚好的最小整数速度。

题目现场

有 n 堆香蕉，第 i 堆含 piles[i] 根。警卫将在 h 小时后回来。珂珂选择一个固定整数速度 k（根/小时）；每小时只选一堆，最多吃 k 根。若该堆不足 k 根，她吃完这一堆后，本小时不再吃别堆。

返回能在不超过 h 小时内吃完全部香蕉的最小整数速度 k。

题解：在答案空间上二分

核心洞察

给定速度 k，吃完一堆 p 需要 ⌈p / k⌉ 小时。随着 k 增大，总耗时只会不增，因此“能否在 h 小时内完成”具有单调性。答案范围是 [1, max(piles)]。

hours(k) = Σ ⌈piles[i] / k⌉

完整过程

  1. 令 left = 1，right = max(piles)。
  2. 取中点 mid，累加每堆所需小时。
  3. 若总耗时不超过 h，说明 mid 可行，继续向左寻找更小速度。
  4. 否则 mid 太慢，令 left = mid + 1。
  5. 两端相遇时，该值就是最小可行速度。

正确性说明

不变式：搜索区间始终包含最小可行速度。mid 可行时，答案不大于 mid，保留左半边（含 mid）；mid 不可行时，所有不大于 mid 的速度同样不可行，可以整体排除。区间每轮严格缩小，最终 left = right，由不变式可知它恰为最小可行速度。

边界与复杂度

  • 单堆香蕉：答案为 ceil(pile / h)。
  • h = piles.length：每堆最多占一小时，答案为最大堆。
  • 小时累加可能很大，Java/C++ 使用 64 位整数，或在超过 h 时提前停止。
  • 时间：O(n log M)，其中 M 为最大堆；空间：O(1)。

替代方案

从速度 1 线性尝试也正确，但最坏需检查到 10⁹，代价为 O(nM)。排序香蕉堆不会改善答案空间搜索，而且会引入不必要的 O(n log n)。

面试追问

  • 为什么上界可以取最大香蕉堆？
  • 如何避免 (left + right) 溢出？
  • 若每小时允许切换香蕉堆，模型与答案会怎样变化？
  • 如何抽象成“最小化最大值”的通用二分模板？

常见错误

  • 把每堆耗时写成整数除法 p / k，漏掉向上取整。
  • 用香蕉总数除以 h；这忽略了每小时只能吃一堆。
  • 可行时写成 right = mid - 1，却又使用闭区间收敛模板，导致漏解。
  • 用浮点 ceil 处理极大整数，增加精度风险。

四语言完整代码

class Solution {
    public int minEatingSpeed(int[] piles, int h) {
        int left = 1, right = 0;
        for (int pile : piles) right = Math.max(right, pile);

        while (left < right) {
            int mid = left + (right - left) / 2;
            long hours = 0;
            for (int pile : piles) {
                hours += (pile + (long) mid - 1) / mid;
                if (hours > h) break;
            }
            if (hours <= h) right = mid;
            else left = mid + 1;
        }
        return left;
    }
}

    let left = 1;
