2506. 统计相似字符串对的数目

Count Pairs Of Similar Strings

相同的字符，能组成多少对？先理解“相似”的含义，再自己尝试。

前往 LeetCode 原题 ↗
01 / Problem

题意

给定一个从下标 0 开始的字符串数组 words。两个字符串出现过的字符种类完全相同，就称它们相似；字符顺序和每种字符出现的次数不影响判断。

例如 "abca" 与 "cba" 相似；"abacba" 与 "bcfd" 不相似。返回满足 0 ≤ i < j < words.length 且 words[i] 与 words[j] 相似的下标对数量。

按下标计数：即使字符串内容相同，不同位置仍是不同元素。每对只计一次，不能与自身配对。

参数与返回值

similarPairs(words: string[]) → integer

约束

  • 1 ≤ words.length ≤ 100
  • 1 ≤ words[i].length ≤ 100
  • 每个字符串仅含小写英文字母 a–z。

官方示例

示例 1

输入：words = ["aba","aabb","abcd","bac","aabc"]
输出：2

有效下标对是 (0, 1) 和 (3, 4)，对应字符种类分别为 {a, b} 与 {a, b, c}。

示例 2

输入：words = ["aabb","ab","ba"]
输出：3

三对 (0, 1)、(0, 2)、(1, 2) 都满足条件。

示例 3

输入：words = ["nba","cba","dba"]
输出：0

任意两个字符串出现的字符种类都不完全相同。

03 / Explanation

准备好再看题解

展开后可逐步观察算法、阅读证明及四种语言实现。

核心洞察：把字符集合编码成一个整数

用 26 位二进制数记录哪些字母出现过：第 0 位代表 a，第 25 位代表 z。遇到字符 c 时执行 mask |= 1 << (c - 'a')，只把对应位置为 1。重复字母不会改变结果。

相似 ⇔ 掩码相同。用哈希表 count[mask] 记录之前遇到的相同掩码数量。当前单词能与这些单词各形成一对，所以先累加已有数量，再把当前单词计入表。

  1. 答案 ans = 0，计数表为空。
  2. 为当前单词构建掩码，每个单词都从 0 开始。
  3. 读取此前同掩码数量 k，执行 ans += k。
  4. 执行 count[mask] = k + 1，继续下一个单词。

字符指纹分拣台

逐字符 → 查桶 → 入桶

每一步点亮一个字母位；同一字母再次出现时，该位保持 1。查询时只与已入桶的下标配对。

键盘：Tab 切换控件，Enter / 空格激活按钮。减少动态效果偏好下，自动播放使用较慢节奏。

当前单词与 26 个字符位

格子从 a 到 z 排列，对应位 0 到位 25。

累计下标对

0

已处理的指纹桶

完整过程 · 示例 1

  1. aba → 3 → {a,b}：桶为空，加 0，桶计数变为 1。
  2. aabb → 3：此前有 1 个，加 1；得到 (0,1)，计数变为 2。
  3. abcd → 15：新桶，加 0。
  4. bac → 7 → {a,b,c}：新桶，加 0。
  5. aabc → 7：此前有 1 个，加 1；得到 (3,4)。答案为 2。

正确性证明

掩码的每一位准确表示一个字母是否出现，因此两个掩码相等当且仅当两个字符串相似。

处理下标 j 前，保持不变式：计数表包含所有 i < j 的掩码频次，ans 已统计所有右端点小于 j 的合法对。当前桶的 k 个已有单词恰好是能与 j 配对的全部左端点，累加 k 无遗漏且无重复。随后插入当前单词，不变式继续成立。遍历结束，所有合法对均被统计一次。

复杂度

设 n 为单词数，S 为总字符数，U 为不同掩码数。构建掩码用 O(S)，哈希操作平均 O(n)，总时间平均 O(S + n) = O(S)（字符串非空）；额外空间 O(U)，U ≤ min(n, 2²⁶)。这是算法复杂度，不包含演示界面保存的交互状态。

边界

  • 只有 1 个字符串：结果为 0。
  • 全部 n 个字符串相似：结果 n(n−1)/2；n = 100 时最多 4950。
  • 字符次数、顺序不同但集合相同：仍配对。
  • z 使用第 25 位，26 位掩码在 Java、JavaScript、C++ 的 32 位位运算范围内安全。

四种语言实现

Java

import java.util.HashMap;
import java.util.Map;

class Solution {
    public int similarPairs(String[] words) {
        Map<Integer, Integer> count = new HashMap<>();
        int ans = 0;
        for (String word : words) {
            int mask = 0;
            for (int i = 0; i < word.length(); i++) {
                mask |= 1 << (word.charAt(i) - 'a');
            }
            int k = count.getOrDefault(mask, 0);
            ans += k;
            count.put(mask, k + 1);
        }
        return ans;
    }
}

/**

var similarPairs = function(words) {
    const count = new Map();
    let ans = 0;
    for (const word of words) {
        let mask = 0;
        for (const c of word) {
            mask |= 1 << (c.charCodeAt(0) - 97);
        }
        const k = count.get(mask) ?? 0;
        ans += k;
        count.set(mask, k + 1);
    }
    return ans;
};

Python 3

from typing import List

class Solution:
    def similarPairs(self, words: List[str]) -> int:
        count = {}
        ans = 0
        for word in words:
            mask = 0
            for c in word:
                mask |= 1 << (ord(c) - ord('a'))
            k = count.get(mask, 0)
            ans += k
            count[mask] = k + 1
        return ans

C++

#include <string>
#include <vector>
#include <unordered_map>
using namespace std;

class Solution {
public:
    int similarPairs(vector<string>& words) {
        unordered_map<int, int> count;
        int ans = 0;
        for (const string& word : words) {
            int mask = 0;
            for (char c : word) {
                mask |= 1 << (c - 'a');
            }
            ans += count[mask];
            ++count[mask];
        }
        return ans;
    }
};

替代方案与面试追问

  • 去重再排序作为键：把每个词的字符集合排序并连接成字符串。更直观，也适合不局限于 26 个字母的场景；若字符集大小为 A，单词去重后排序多花 O(A log A)。
  • 预处理掩码后两两比较：时间 O(S + n²)，空间 O(n)。本题 n ≤ 100 时可行，但哈希计数更容易扩展。
  • 先统计所有桶再组合计数：每个频次为 k 的桶贡献 k(k−1)/2，与逐个累加 0+1+…+(k−1) 等价。
  • 如何在线处理无限单词流？保留频次表与当前答案，每个新词查询并更新一次；超大规模注意答案整数范围。
  • 如果要求字符次数也相同？那是另一种等价关系，需使用 26 维频次数组等键，存在性掩码不再足够。
  • 如果字符包含 Unicode？先明确按码点还是字素比较，再使用集合规范化；不能沿用固定 26 位映射。

常见错误

  • 使用 XOR：重复字符会把位翻回 0；应使用 OR。
  • 累加 1 << offset：重复字符造成进位，破坏集合含义。
  • 先增加频次再累加答案：把当前单词与自己配对。
  • 仅排序原字符串：没有消除重复次数，误判相似字符串。
  • 没有为每个单词重置 mask，或者把有序对计成两次。
