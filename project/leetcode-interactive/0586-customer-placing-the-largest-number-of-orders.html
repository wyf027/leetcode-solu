订单最多的客户

Customer Placing the Largest Number of Orders

把订单表压缩成“每位客户一行”，再让订单数最高的一行浮到最上面。先亲手走一遍数据管道，题解留到最后。

01

题目档案

任务

给定 Orders 表，找出下单数量最多的客户，并返回该客户的 customer_number。

唯一性保证：测试数据保证恰好有一位客户的订单数严格多于其他客户，因此基础题只需要返回一行。

约束与数据语义

  • order_number 为整数主键，每笔订单的编号唯一。
  • customer_number 为整数，表示下单客户。
  • 官方题面未给出具体行数上下界；解法应按整张表聚合。
  • 结果列名必须为 customer_number。

03 · 解法档案

准备好核对思路了吗？

题解默认收起。展开后包含证明、复杂度、替代方案与四语言本地语义参考。

A

核心洞察

目标不是寻找最大的订单编号，而是比较每位客户拥有的行数。因此先用 GROUP BY customer_number 把订单按客户分组，再用 COUNT(*) 得到每组大小，降序排序后取第一行。

关键辨析：MAX(customer_number) 找到的是编号最大的客户，和订单数量没有关系。

完整过程

  1. 扫描 Orders，按 customer_number 建组。
  2. 对每个组执行 COUNT(*)，得到客户订单数。
  3. 按计数结果降序排列，让最大计数位于首行。
  4. 使用 LIMIT 1 返回唯一冠军的客户编号。

正确性证明

引理：按客户编号分组后，每个分组恰好包含该客户的全部订单，因此该组的 COUNT(*) 等于其订单总数。

结论：将所有分组按该计数降序排列后，首组的订单数不小于任意其他组。题目又保证最大值唯一，因此首组对应的 customer_number 正是唯一答案。

复杂度

设订单数为 n、不同客户数为 k。

  • 分组扫描通常为 O(n)。
  • 对聚合结果排序为 O(k log k)。
  • 聚合结果需要 O(k) 空间；数据库实际执行计划可能使用哈希聚合、排序聚合与索引优化。

边界情况

  • 只有一笔订单：唯一客户自然为答案。
  • 客户编号不连续或很大：不影响分组逻辑。
  • 同一客户订单编号分散出现：GROUP BY 仍会统一聚合。
  • 若业务允许空表，基础查询返回空结果；官方题意按存在可比较订单理解。

实现

MySQL 是官方可提交语言；其余四份是对“分组计数取最大”的完整本地语义参考，不能作为本数据库题的 LeetCode 提交。

SQL FIRST 
SELECT customer_number
FROM Orders
GROUP BY customer_number
ORDER BY COUNT(*) DESC
LIMIT 1;
本地语义参考：输入为二维整数数组，每行是 [order_number, customer_number]；非本题官方提交语言。
import java.util.HashMap;
import java.util.Map;

class Solution {
    public int largestOrders(int[][] orders) {
        Map<Integer, Integer> counts = new HashMap<>();
        for (int[] order : orders) {
            int customer = order[1];
            counts.put(customer, counts.getOrDefault(customer, 0) + 1);
        }

        int answer = -1;
        int bestCount = -1;
        for (Map.Entry<Integer, Integer> entry : counts.entrySet()) {
            if (entry.getValue() > bestCount) {
                answer = entry.getKey();
                bestCount = entry.getValue();
            }
        }
        return answer;
    }
}

function largestOrders(orders) {
  const counts = new Map();
  for (const [, customerNumber] of orders) {
    counts.set(customerNumber, (counts.get(customerNumber) ?? 0) + 1);
  }

  let answer = null;
  let bestCount = -1;
  for (const [customerNumber, count] of counts) {
    if (count > bestCount) {
      answer = customerNumber;
      bestCount = count;
    }
  }
  return answer;
}

def largest_orders(orders: pd.DataFrame) -> pd.DataFrame:

#include <unordered_map>
#include <vector>
using namespace std;

class Solution {
public:
    int largestOrders(const vector<vector<int>>& orders) {
        unordered_map<int, int> counts;
        for (const auto& order : orders) {
            ++counts[order[1]];
        }

        int answer = -1;
        int bestCount = -1;
        for (const auto& [customer, count] : counts) {
            if (count > bestCount) {
                answer = customer;
                bestCount = count;
            }
        }
        return answer;
    }
};

替代方案与进阶

窗口函数：可先统计每位客户，再用 DENSE_RANK() OVER (ORDER BY order_count DESC) 排名，筛选排名 1。它更适合“返回全部并列冠军”的进阶题。

子查询比较最大值：将每位客户的计数与最大计数相等比较，也能返回并列者，但写法更长。

方言差异：MySQL/PostgreSQL 使用 LIMIT 1；SQL Server 常用 TOP 1；Oracle 可使用 FETCH FIRST 1 ROW ONLY。

面试追问

  • 如果要返回并列第一的所有客户，你会怎样改写？
  • 若需要同时返回订单数，SELECT 列表应增加什么？
  • 数据量极大时，聚合和排序分别可能怎样执行？索引能帮到哪里？
  • 如果 customer_number 允许 NULL，NULL 组应该保留还是过滤？

常见错误

  • 写成 MAX(customer_number)，比较错了维度。
  • 按 order_number 分组；主键唯一，所有组计数都会是 1。
  • 忘记 DESC，结果取到了订单最少的客户。
  • 在要求处理并列时仍使用 LIMIT 1，会漏掉其他冠军。

进阶 SQL（并列全部返回）

WITH customer_counts AS (
  SELECT customer_number, COUNT(*) AS order_count
  FROM Orders
  GROUP BY customer_number
)
SELECT customer_number
FROM customer_counts
WHERE order_count = (
  SELECT MAX(order_count)
  FROM customer_counts
);
