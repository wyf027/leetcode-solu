宝石补给

按给定顺序执行赠送：勇者 x 将自己当前宝石数的一半（向下取整）送给勇者 y。全部完成后返回最大值与最小值之差。

数组模拟原地更新O(n + q)

题意

gem[i] 是第 i 位勇者当前拥有的宝石数；operations[j] = [x, y] 表示第 j 次操作由 x 向 y 赠送。赠送量必须用操作发生时的 gem[x] / 2 向下取整，且操作不可交换顺序。

示例 1

gem = [3,1,2], operations = [[0,2],[2,1],[2,0]]

输出：2

示例 2

gem = [100,0,50,100], operations = [[0,2],[0,1],[3,0],[3,0]]

输出：75

示例 3

gem = [0,0,0,0], operations = [[1,2],[3,1],[1,2]]

输出：0

约束：2 ≤ gem.length ≤ 10³，0 ≤ gem[i] ≤ 10³，operations.length ≤ 10⁴，下标均合法。

题解：严格按序模拟

核心洞察

  1. 遍历每个 [x,y]。
  2. 先保存 give = gem[x] / 2。
  3. gem[x] -= give，gem[y] += give。
  4. 最后扫描一次得到 max − min。

复杂度与边界

设勇者数为 n、操作数为 q。时间 O(n + q)，额外空间 O(1)（原地更新）。操作为空时直接计算初始极差；赠送者为 0 或 1 颗宝石时赠送量为 0。

常见错误

  • 预先用初始数组算全部赠送量。
  • 用浮点除法或四舍五入。
  • 更新 x 后再计算赠送量，导致少送一次。
  • 只维护历史最大最小；宝石转移后旧极值可能失效。

替代方案与面试追问

可以复制数组避免修改输入，代价是 O(n) 空间。追问：能否动态维护极差？平衡树可做 O(q log n)，但最终只需一次结果，线性末扫描更简单且渐进复杂度更优。
