日志速率限制器

Logger Rate Limiter

让重复消息安静十秒。你要设计一个 Logger，在持续到来的时间有序日志流中，判断每条消息此刻是否允许输出。

开始读题 ↓ 体验时间线

01 · Problem

题目描述

请设计一个日志记录系统。日志消息会按照时间顺序到达；只有当同一条消息在此前 10 秒内没有被成功输出时，它才可以被输出。

实现 Logger 类：

  • Logger()：初始化日志记录器。
  • boolean shouldPrintMessage(int timestamp, string message)：当消息在给定时间戳允许输出时返回 true，否则返回 false。
边界语义：若消息上次在时刻 t 被输出，那么在 t + 10 时已经可以再次输出；被拦截的消息不会重置这十秒等待期。

03 · Constraints

约束与输入特征

时间戳

0 ≤ timestamp ≤ 10⁹，所有调用的时间戳按非递减顺序给出。

消息

1 ≤ message.length ≤ 30，消息由小写英文字母组成。

调用次数

最多调用 shouldPrintMessage 约 10⁴ 次。

判断窗口

只需区分每个消息自己的最近一次成功输出时间，不同消息互不影响。

完整题解

Core insight

为每条消息记住“下一次允许输出的时刻”

哈希表以消息为键，值为 nextAllowed。消息首次出现，或当前 timestamp ≥ nextAllowed[message] 时允许输出，并把下一次允许时间更新为 timestamp + 10。若被拦截，什么也不更新。

完整过程

1

查询消息

在哈希表中读取该消息的下一次允许时间；不存在说明它从未成功输出。

2

比较时间

不存在记录，或当前时间已经到达允许时间，返回 true。

3

只在放行时更新

记录新的 timestamp + 10；拦截时保留原值，避免把冷却窗口错误延长。

正确性证明

不变式：处理任意前缀后，对每个已成功输出的消息 m，表中保存的值恰好等于它最近一次成功输出时刻加 10。

初始化：尚未处理事件，表为空，不变式成立。

保持：若当前时间早于记录值，最近一次输出仍在十秒内，算法拒绝且不改表；否则允许输出并将值设为当前时间加 10。两种情况都保持不变式。

结论：返回值与题目规定的十秒输出条件完全一致。

复杂度与边界

时间：每次调用平均 O(1)。

空间：O(M)，其中 M 是曾被成功输出的不同消息数量。

  • timestamp == nextAllowed 时必须允许。
  • 相同时间戳可出现多次，顺序处理即可。
  • 拦截事件不能更新状态。
  • 消息字符串本身就是键，大小写若存在则应视为不同消息。

JavaHashMap<String, Integer>
import java.util.HashMap;
import java.util.Map;

class Logger {
    private final Map<String, Integer> nextAllowed;

    public Logger() {
        nextAllowed = new HashMap<>();
    }

    public boolean shouldPrintMessage(int timestamp, String message) {
        int allowedAt = nextAllowed.getOrDefault(message, 0);
        if (timestamp < allowedAt) {
            return false;
        }

        nextAllowed.put(message, timestamp + 10);
        return true;
    }
}

C++unordered_map<string, int>
#include <string>
#include <unordered_map>
using namespace std;

class Logger {
private:
    unordered_map<string, int> nextAllowed;

public:
    Logger() = default;

    bool shouldPrintMessage(int timestamp, string message) {
        auto it = nextAllowed.find(message);
        if (it != nextAllowed.end() && timestamp < it->second) {
            return false;
        }

        nextAllowed[message] = timestamp + 10;
        return true;
    }
};

替代方案

队列 + 集合：借助时间戳单调性，用队列保存最近十秒成功输出的消息，并用集合快速判断重复。每次先弹出过期项，再检查当前消息。

它也能做到摊还 O(1)，并可自动淘汰旧消息；但状态同步更复杂。哈希表方案更短、更不易写错，代价是不会主动回收历史键。

常见错误

  • 使用 timestamp - last > 10，错误拒绝恰好第十秒。
  • 每次消息到来都更新时间，导致被拦截事件延长等待期。
  • 只保存全局最近时间，没有按消息分别维护状态。
  • 用列表线性扫描所有历史日志，使单次调用退化为 O(N)。

面试追问

若时间戳不再有序？

先明确语义：按事件时间还是到达时间限流。若按事件时间，单个“最近时间”不足以处理乱序回溯，通常要引入水位线、缓冲或有序结构。

如何限制内存？

利用时间有序条件，增加队列并清理十秒前的键；或给哈希表配置带过期时间的缓存策略。

分布式 Logger 怎么做？

需要按消息做一致性路由，或使用支持原子“若不存在则设置过期”的共享存储，并讨论时钟与网络故障。

改为每十秒最多 K 条？

每个消息维护滑动窗口计数，可用时间戳队列、固定窗口计数器或令牌桶，依据精度与吞吐取舍。
