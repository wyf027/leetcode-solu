Elimination Game

消除游戏

一列从 1 到 n 的数字，两端交替发起淘汰。真正需要追踪的，不是整张名单，而是每轮之后仍在队列里的结构。

输入
n：整数
范围
1 ≤ n ≤ 10⁹
目标
返回最后剩余数字
Problem

题目描述

给定整数 n，构造严格递增列表 arr = [1, 2, …, n]。先从左向右删除第一个数以及之后每隔一个数；下一轮改为从右向左，同样先删除最右侧的数，再每隔一个删除。两个方向交替执行，直到列表只剩一个数，返回这个数。

操作规则

  1. 左向轮：从最左端开始删除，删一个、留一个，直到末尾。
  2. 右向轮：从最右端开始删除，删一个、留一个，直到开头。
  3. 持续交替方向，直到仅有一个元素。

Solution

从“完整队列”压缩到三个变量

核心洞察

每轮结束后，剩余数字仍然构成等差数列。因此无需保存所有元素，只要维护当前最左端数字 head、相邻元素间距 step、剩余数量 remaining 和方向即可。

完整过程

  1. 初始化 head = 1、step = 1、remaining = n，方向为从左到右。
  2. 从左删除时，当前最左端一定被删，所以新的 head 必须向右移动一个 step。
  3. 从右删除时，若剩余个数为奇数，删除会落到当前最左端，head 也要右移；若为偶数，最左端会保留。
  4. 每轮后元素数量减半，间距翻倍，并切换方向。
  5. 当 remaining = 1 时，head 就是答案。

状态转移

若 left == true 或 remaining 为奇数： head = head + step 随后每轮都执行： remaining = ⌊remaining / 2⌋ step = step × 2 left = !left

边界处理

  • n = 1 时不进入循环，直接返回 1。
  • 上限为 10⁹，循环轮数约为 30；四份实现中的整数范围均足够。
  • 不要真的构造 1 到 n 的数组，否则空间和删除成本都无法承受。

正确性证明

不变式：每轮开始时，所有候选数构成以 head 为首项、step 为公差、共有 remaining 项的等差数列。

保持：一次隔项删除后，保留下来的元素仍按原顺序排列，相邻幸存者相隔两个旧公差，所以新公差为 2 × step，项数为 ⌊remaining / 2⌋。从左删除必删首项；从右删除仅在项数为奇数时会删到首项。因此算法对 head 的更新与真实新首项完全一致，不变式继续成立。

终止：每轮至少将数量减半，最终 remaining = 1。根据不变式，唯一候选数就是 head，故返回值正确。

时间复杂度
O(log n)

每轮把剩余数量减半。

空间复杂度
O(1)

只维护固定数量的状态变量。

四种语言完整代码

class Solution {
    public int lastRemaining(int n) {
        int head = 1;
        int step = 1;
        int remaining = n;
        boolean left = true;

        while (remaining > 1) {
            if (left || remaining % 2 == 1) {
                head += step;
            }
            remaining /= 2;
            step *= 2;
            left = !left;
        }
        return head;
    }
}

替代方案

递归映射：第一轮后剩下的都是偶数，可把它们除以 2，转化为规模 ⌊n/2⌋ 的反向问题。可得到：

f(1) = 1 f(n) = 2 × (1 + ⌊n/2⌋ − f(⌊n/2⌋))

递归同样是 O(log n) 时间、O(log n) 调用栈；迭代状态法空间更稳妥。

常见错误

  • 误以为从右删除时 head 永远不变，漏掉奇数项场景。
  • 先更新 remaining 再判断奇偶，使用了错误轮次的数量。
  • 忘记每轮把 step 翻倍。
  • 实际创建列表并逐项删除，导致 O(n) 空间甚至更差的时间开销。

面试追问

  1. 为什么“从右且项数为偶数”时，最左端一定保留？请用下标奇偶说明。
  2. 如何从迭代状态推导递推式？两者的空间复杂度为什么不同？
  3. 若每轮改为“删两个、留一个”，哪些状态仍可复用，转移规则如何变化？
  4. 如果方向不再交替，而由外部序列决定，算法接口应如何设计？
