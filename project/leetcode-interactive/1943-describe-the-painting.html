01 / 题目与规则

给定二维整数数组 segments，每一项 [start, end, color] 表示在数轴的 [start, end) 上涂一种颜色。每个输入线段的颜色编号互不相同。左端点包含在内，右端点不包含在内。

重叠处的颜色组成一个集合。请用最少的、不重叠的半开区间描述绘画结果，每段内的颜色集合必须保持不变。返回 painting = [[left, right, mix], ...]，其中 mix 是集合元素之和；未涂色部分不输出，结果顺序不限。

例如 segments = [[1,4,5],[1,7,7]]：区间 [1,4) 的颜色集合为 {5,7}，之后 [4,7) 为 {7}，所以返回 [[1,4,12],[4,7,7]]。颜色和只是输出表示，并不等同于颜色集合。

约束

  • 1 ≤ segments.length ≤ 2 × 10⁴
  • segments[i].length == 3
  • 1 ≤ startᵢ < endᵢ ≤ 10⁵
  • 1 ≤ colorᵢ ≤ 10⁹
  • 所有 colorᵢ 互不相同。

05 / 独立题解

准备好后，展开算法推导和四种语言实现。

核心洞察：边界不可丢，集合不用存

颜色集合只会在输入线段的起点或终点发生变化。收集所有端点，排序后，任意两个相邻端点之间的集合恒定。只维护颜色和即可生成答案，但必须保留每一个端点，即使该点颜色和的净变化为 0。

完整过程

  1. 建立差分映射 delta。每段 [l,r,c] 在 l 加 c，在 r 减 c。映射保留所有端点，不删除值为 0 的键。
  2. 将端点按数值升序排列为 x₀、x₁、…。
  3. 从左到右处理 xᵢ：先将 delta[xᵢ] 加入当前和 sum。这意味着结束于 xᵢ 的颜色退出，开始于 xᵢ 的颜色进入。
  4. 若存在下一个端点且 sum > 0，输出 [xᵢ, xᵢ₊₁, sum]；sum 为 0 时跳过空白。
  5. 最后一个端点后没有区间，不输出。不要因相邻段的和相等而合并。

示例 3 的差分为：1 → +12，4 → 0，7 → −12。扫描 1 后输出 [1,4,12]；扫描 4 后仍为 12，但必须输出新段 [4,7,12]，因为颜色集合已经替换。

正确性说明

不变式：处理端点 x 后，sum 等于所有满足 start ≤ x < end 的颜色之和。起点增加、终点减少恰好实现半开区间语义；初始无活跃颜色，因此归纳成立。

覆盖与无重叠：相邻端点之间没有颜色进入或退出，故整个小区间都可用同一颜色和描述。只输出正和区间，恰好覆盖所有涂色位置，且相邻小区间互不重叠。

最少分段：每个输入颜色唯一且只出现在一个连续线段中，因此任何实际端点都有至少一种颜色进入或退出，端点两侧集合必然不同。涂色结果不能跨过这样的边界合并。算法恰好输出所有非空的相邻端点区间，段数最少。净变化为零不代表集合不变。

边界与数值

  • 同点多个事件：先汇总净变化，再描述右侧区间，不产生零长度段。
  • 不相交段：颜色均为正数，sum = 0 就是空白。
  • 相同起止点、嵌套、输入无序：统一由差分和排序处理。
  • 颜色和上界不超过 2 × 10¹³。Java 用 long，C++ 用 long long；Python 整数足够，JavaScript Number 在安全整数范围内精确。

复杂度

设 n 为输入段数，m 为不同端点数，m ≤ 2n。总时间 O(n log n)，辅助空间 O(n)，结果最多 m−1 段。Java / C++ 有序映射插入为 O(log n)；JavaScript / Python 先汇总再排序。

Java

import java.util.*;

class Solution {
    public List<List<Long>> splitPainting(int[][] segments) {
        TreeMap<Integer, Long> delta = new TreeMap<>();
        for (int[] s : segments) {
            delta.merge(s[0], (long) s[2], Long::sum);
            delta.merge(s[1], -(long) s[2], Long::sum);
        }
        List<Integer> xs = new ArrayList<>(delta.keySet());
        List<List<Long>> answer = new ArrayList<>();
        long sum = 0;
        for (int i = 0; i + 1 < xs.size(); i++) {
            int x = xs.get(i);
            sum += delta.get(x);
            if (sum > 0) {
                answer.add(Arrays.asList((long) x,
                    (long) xs.get(i + 1), sum));
            }
        }
        return answer;
    }
}

JavaScript

/**
 * @param {number[][]} segments
 * @return {number[][]}
 */
var splitPainting = function(segments) {
    const delta = new Map();
    for (const [l, r, c] of segments) {
        delta.set(l, (delta.get(l) ?? 0) + c);
        delta.set(r, (delta.get(r) ?? 0) - c);
    }
    const xs = [...delta.keys()].sort((a, b) => a - b);
    const answer = [];
    let sum = 0;
    for (let i = 0; i + 1 < xs.length; i++) {
        sum += delta.get(xs[i]);
        if (sum > 0) answer.push([xs[i], xs[i + 1], sum]);
    }
    return answer;
};

Python 3

from typing import List
from collections import defaultdict

class Solution:
    def splitPainting(self, segments: List[List[int]]) -> List[List[int]]:
        delta = defaultdict(int)
        for left, right, color in segments:
            delta[left] += color
            delta[right] -= color
        xs = sorted(delta)
        answer = []
        total = 0
        for i in range(len(xs) - 1):
            total += delta[xs[i]]
            if total > 0:
                answer.append([xs[i], xs[i + 1], total])
        return answer

C++

#include <vector>
#include <map>
using namespace std;

class Solution {
public:
    vector<vector<long long>> splitPainting(vector<vector<int>>& segments) {
        map<int, long long> delta;
        for (const auto& s : segments) {
            delta[s[0]] += s[2];
            delta[s[1]] -= s[2];
        }
        vector<int> xs;
        for (const auto& entry : delta) xs.push_back(entry.first);
        vector<vector<long long>> answer;
        long long sum = 0;
        for (size_t i = 0; i + 1 < xs.size(); ++i) {
            sum += delta[xs[i]];
            if (sum > 0) answer.push_back({xs[i], xs[i + 1], sum});
        }
        return answer;
    }
};

替代方案

坐标最大为 10⁵，可使用长度 U+1 的差分数组，并另设端点标记数组；按坐标顺序扫描，只在标记点切分，时间 O(n+U)，空间 O(U)。不能仅判断差分非零来寻找边界。也可以将 2n 个起止事件排序，同坐标成组处理。

面试追问

  • 如果需要输出集合本身？维护活跃颜色集合并在区间生成时复制；时间和空间要加上集合输出总大小。
  • 如果允许颜色重复？本题的简单求和不再等于集合元素和，需要每种颜色的计数，只在计数 0↔1 时调整颜色和；最少分段也须重新判断集合是否变化。
  • 坐标达到 10⁹？继续使用有序端点，不遍历整个坐标域。
  • 为什么不能把颜色和当集合哈希？不同集合可得到同一个和，示例 3 即为反例。

常见错误

  • 删掉差分为 0 的键，导致丢失真实集合变化的边界。
  • 按相同 sum 合并相邻结果，错误吞掉示例 3 的端点 4。
  • 在更新差分前输出右侧区间，错用左侧颜色。
  • 输出 sum = 0 的空白或最后端点后的虚构区间。
  • Java / C++ 用 32 位累加；JavaScript 用位运算强制转成 32 位整数。
  • JavaScript 忘记数值排序比较器，导致端点按字符串排序。
