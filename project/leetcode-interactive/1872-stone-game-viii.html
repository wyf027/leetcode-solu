HARD1872 / Stone Game VIII

石子游戏 VIII

拿走一段，把总和放回。每一步都改变眼前的石子，也改变留给对手的选择。

−12−34−5

先思考：一次获得更高的分数，是否一定能得到更好的最终分差？

01 / 游戏规则

你需要求什么

给定整数数组 stones，Alice 先手，双方轮流操作且初始得分均为 0。每次选择当前最左侧的 x 个石子，要求 2 ≤ x ≤ 当前石子数：

  1. 移除这 x 个石子。
  2. 把它们的价值总和加到当前玩家的得分中。
  3. 在队列最左端放回一个价值等于该总和的新石子。

剩下一个石子时立即结束。Alice 最大化、Bob 最小化 Alice 得分 − Bob 得分。返回双方都采用最优策略时的这个整数分差。

输入与边界

  • n == stones.length
  • 2 ≤ n ≤ 10⁵
  • −10⁴ ≤ stones[i] ≤ 10⁴

负数石子合法，得分可以减少；玩家不能选择不操作，也不能只取一个石子。

参数：stones: integer[]
返回：integer

02 / 官方示例

示例 1 · 对手也可能得到负分

输入：stones = [-1,2,-3,4,-5]
输出：5

Alice 取前 4 个，获得 2 分，石子变为 [2,-5]；Bob 只能取两个，获得 −3 分，石子变为 [-3]。最终分差为 2 − (−3) = 5。

示例 2 · 一步结束

输入：stones = [7,-6,5,10,5,-2,-6]
输出：13

Alice 一次取走全部石子，获得 13 分，放回价值为 13 的石子。Bob 没有回合，分差为 13 − 0 = 13。

示例 3 · 没有跳过回合的选项

输入：stones = [-10,-12]
输出：-22

Alice 只能合并这两个石子，得到 −22 分；游戏结束，分差为 −22 − 0 = −22。

04 / 推导与交互实验

准备好后再展开：从合并边界理解最优决策，并观察逆序计算如何压缩所有选择。

题解 / 把一排石子变成一个边界

核心洞察

每次合并后的最左石子，始终是原数组某个前缀的总和。设 P[k] 表示原数组前 k 个石子的和。若前 t 个已经合成一个，下次必须把边界推进到 k > t，本次得分就是 P[k]。无须真的移动或复制石子。

初始至少取两个，所以第一次边界在 [2,n]。之后双方目标都可写成“最大化自己相对对手的后续分差”。因此，本次收入减去对手的最优优势，才是这个选择的净价值。

状态、转移与完整过程

定义 F(k)：当前玩家下一次合并的终点可选 k…n 时，能取得的最大后续分差。它对应前 k−1 个原始石子已经被压成一颗的局面；k=2 则对应初始局面。

  1. 求总和。只能选终点 n 时，游戏立刻结束，故 F(n)=P[n]。
  2. 从 k=n−1 到 2 逆序处理：若本次选终点 k，净优势是 P[k]−F(k+1)；若选更远的终点，最优值已经由 F(k+1) 覆盖。
  3. 合并两类：F(k)=max(F(k+1), P[k]−F(k+1))。
  4. 返回 F(2)。只保存上一个 F，并从总和不断减去右端元素，即可使用常数额外空间。

“沿用更远终点”是在枚举本回合的其他合法选择，并不是允许当前玩家跳过回合。

示例 1 的完整递推

P[1…5] = [−1,1,−2,2,−3]。初始 F(5)=−3。

  • k=4：max(−3, 2−(−3)) = 5。
  • k=3：max(5, −2−5) = 5。
  • k=2：max(5, 1−5) = 5，得到答案。

更远的最优终点最终保留下来：Alice 先取 4 个，Bob 随后取完；递推步骤本身并不是玩家的实际回合顺序。

正确性证明

局面充分性：归纳可知，合并前缀后最左石子的值恰为该原始前缀的和，后面的原始石子保持不变。因此边界唯一决定所有未来操作与分数，过去得分只贡献固定常量。

归纳基础：在 F(n) 中只剩取到 n 的选择，获得 P[n] 后没有对手回合，所以 F(n)=P[n]。

归纳步骤：假设 F(k+1) 正确。F(k) 的合法选择恰分为终点等于 k 和大于 k 两类。前者获得 P[k]，把后续局面交给对手，故价值为 P[k]−F(k+1)；后者的最优价值就是 F(k+1)。二者取最大涵盖所有且仅有合法选择，因此 F(k) 正确。逆序归纳到 k=2，得到 Alice 相对 Bob 的最优分差。

边界与复杂度

  • n=2：循环不执行，直接返回两数之和，即使和为负也必须接受。
  • 全零、全负、正负混合都使用同一递推，不能把初值设为 0。
  • 时间 O(n)，额外空间 O(1)，不修改输入；可视化为了展示轨迹额外保存 O(n) 状态。
  • 前缀和绝对值至多 10⁹。可由递推和后缀绝对值预算归纳得 |F(k)| ≤ 原数组绝对值之和，因此答案在 32 位有符号整数内。Java / C++ 仍用 64 位中间量；JavaScript Number 足够精确。

替代方案

直接用“已经合并到 t”的状态，枚举下一终点 j，转移为 G(t)=max(P[j]−G(j))，其中 j>t、G(n)=0。这是 O(n²) 时间、O(n) 空间的动态规划，适合推导，但不能满足最大规模。保存完整前缀和与 F 数组可得到 O(n) 时间、O(n) 空间版本，便于恢复策略；只求分差时使用下面的滚动版本。

常见错误

  • 只选当前得分最大的前缀：忽略对手后续优势。
  • 把每次选取的原始新区间之和当收入：合并石子会再次参与求和。
  • 循环走到 k=1：首回合取一个石子不合法。
  • 先覆盖 best，再算 P[k]−best：减数必须是旧的 F(k+1)。
  • 把两分支解释成“取与不取”：本回合不能不取，另一分支是取到更远终点。

面试追问

如何恢复一条最优操作序列？存下每个 F(k) 选择的终点：当前分支获胜记录 k，否则继承 F(k+1) 的终点。从 k=2 开始，选 j 后令 k=j+1，交替玩家，直到 j=n；恢复时需要 O(n) 空间。

如果要求至少取三个？边界至少前进两位，直接选当前终点后的对手状态不再是 F(k+1)；需要重新定义合法终止条件与转移，不能原样套用此式。

只问分差为什么不分别维护两个人得分？零和目标使后续局面能统一成当前玩家优势，交换行动方时取相反数即可。

Java

class Solution {
    public int stoneGameVIII(int[] stones) {
        long prefix = 0;
        for (int value : stones) prefix += value;
        long best = prefix;
        for (int i = stones.length - 2; i >= 1; --i) {
            prefix -= stones[i + 1];
            best = Math.max(best, prefix - best);
        }
        return (int) best;
    }
}
