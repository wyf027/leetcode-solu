加密数字.

给定一个非负整数 num，按照题目规定的分组编码规则返回它对应的二进制字符串。先从样例观察规律，再通过交互演示逐步揭开编码机制。

编码表按字符串长度分组：空串对应 0；接着依次使用所有长度为 1 的二进制串，再使用所有长度为 2 的二进制串，以此类推。也就是说，整数按从小到大的顺序，与 ""、"0"、"1"、"00"、"01"……一一对应。

Deep Dive

题解：给序号补上隐藏的最高位

核心洞察：把 num + 1 写成二进制，再删除最左侧的最高位 1，剩余部分就是答案。即 encode(num) = binary(num + 1).substring(1)。

为什么会出现这个规律？

长度为 k 的编码一共有 2^k 个，它们从全 0 到全 1。此前所有更短编码（包含空串）的数量是 1 + 2 + … + 2^(k-1) = 2^k - 1。因此长度为 k 的第一项恰好是数字 2^k - 1。

令 offset = num - (2^k - 1)，将偏移量补成 k 位二进制就是编码。与此同时，num + 1 = 2^k + offset，它的最高位是固定的 1，后面的 k 位正好就是偏移量。

完整过程

  1. 计算 x = num + 1。
  2. 把 x 转为不带前导零的二进制字符串。
  3. 删除字符串的第一个字符（它一定是最高位 1）。
  4. 返回剩余字符串；当 num = 0 时自然得到空串。

正确性证明

分组定位。设答案长度为 k。长度小于 k 的编码共有 2^k - 1 个，所以这一组对应的数字范围是 [2^k - 1, 2^(k+1) - 2]。
组内次序。令 d = num - (2^k - 1)。因为 0 ≤ d < 2^k，d 的恰好 k 位二进制表示按数值递增依次枚举了本组所有编码。
等价变换。num + 1 = 2^k + d。它的二进制形式等于一个最高位 1 后接 d 的 k 位表示。删除最高位后，所得字符串就是本组中 num 对应的编码。因此算法对任意合法 num 都正确。

边界情况

  • num = 0：num + 1 = 1₂，删去最高位得到空串。
  • 位于新分组开头（如 3、7）：结果是相应长度的全 0。
  • 位于分组末尾（如 2、6）：结果是相应长度的全 1。
  • 上界 10^9 不会超过常见 32 位有符号整数范围；仍应先确认语言中的数值类型。

复杂度

设答案长度为 k = Θ(log num)。

  • 时间复杂度：O(log num)，用于生成二进制字符串。
  • 空间复杂度：O(log num)，用于保存返回值；若不计输出本身，额外空间可视为 O(1)。

替代方案

可以先求最大的 k 使 2^k - 1 ≤ num，再计算组内偏移 num - (2^k - 1)，最后补齐为 k 位二进制。它更直观地模拟分组，但代码更长，也更容易在幂与边界上出现偏一错误。

面试追问

  • 如果输入可能接近语言整数上限，num + 1 如何避免溢出？
  • 若编码字母表从二进制扩展到 b 进制，公式如何推广？
  • 能否实现逆函数，把编码字符串还原为原数字？

常见错误

  • 直接把 num 转成二进制；正确对象是 num + 1。
  • 删除的是最左侧最高位，不是末尾字符。
  • 把 num = 0 错写成 "0"，忽略空串是第一个编码。
  • 分组方案没有补前导零，例如数字 4 应得到 "01"。
  • 在 JavaScript 中把结果误当作数值，导致前导零丢失；返回值必须是字符串。

class Solution {
public:
    string encode(int num) {
        int value = num + 1;
        string binary;

        while (value > 0) {
            binary.push_back(char('0' + (value & 1)));
            value >>= 1;
        }

        reverse(binary.begin(), binary.end());
        return binary.substr(1);
    }
};
