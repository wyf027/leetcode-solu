完成所有任务的最少时间

一台能并行处理无限任务的电脑，何时开机、何时关机？先读懂区间与持续时间，再进入时间轴亲手安排。

HARD 非付费题 数组 排序 贪心 二分查找 栈
Problem

题意

给定二维整数数组 tasks。每个元素 tasks[i] = [startᵢ, endᵢ, durationᵢ] 表示：任务 i 必须在闭区间 [startᵢ, endᵢ] 内运行恰好 durationᵢ 个整数时间点，这些时间点不必连续。

电脑在同一个时间点可以同时运行任意多个任务。只有开机的时间点才能处理任务；空闲时可以关机。返回完成所有任务所需的最少开机时间。

关键语义：区间两端都包含；同一个开机时间点可以被多个任务共享；任务持续时间按整数时间点计数。
Signature

函数形式

findMinimumTime(tasks: integer[][]): integer
  • 1 ≤ tasks.length ≤ 2000
  • tasks[i].length == 3
  • 1 ≤ startᵢ, endᵢ ≤ 2000
  • 1 ≤ durationᵢ ≤ endᵢ - startᵢ + 1

Solution

贪心：按结束时间排序，尽量靠右开机

核心洞察：先处理结束更早的任务。若当前任务还缺开机时间，就从它的结束时间向左选择最晚的未开机点。越晚的点越可能同时落入后续任务的区间，因此不会比选择更早的点差。

完整过程

  1. 按 end 从小到大排序全部任务。
  2. 用布尔数组 on[t] 记录整数时间点 t 是否已开机。
  3. 对当前 [start, end, duration]，统计区间内已经开机的点数 used。
  4. 若 used < duration，从 end 向 start 扫描，在最晚的未开机点补齐差额。
  5. 所有任务处理完后，新增开机点的总数就是答案。

为什么正确

可行性：处理某个任务时会补到恰好拥有至少 duration 个已开机点；之后只会增加开机点，不会破坏已经满足的任务。

最优性：设当前按结束时间排序后的任务还缺 k 个点。任何可行方案都必须在当前区间新增至少 k 个点。若某个最优方案选择了较早点 x，而贪心选择了更晚且尚未选择的点 y，可将 x 换成 y。已处理任务的结束时间不晚于当前任务，贪心在满足它们后才补点；这次交换不减少已处理任务已有的满足度，而 y 对尚未处理且可能向右延伸的任务至少同样有利。反复交换即可得到包含贪心选择且大小不变的最优方案。因此每一步都可嵌入某个最优解，最终答案最优。

复杂度

令 n 为任务数，M 为最大时间点（本题 M ≤ 2000）。排序为 O(n log n)，逐点统计与补齐为 O(nM)，总时间 O(n log n + nM)；布尔时间轴占用 O(M) 空间。

边界情况

  • 单点区间：start == end 时该点必须按需开启。
  • 完全重叠：后处理任务可以复用先前所有开机点。
  • 持续时间等于区间长度：区间内每个点都必须开启。
  • 多个任务结束时间相同：任意相对顺序都不影响正确性。

import java.util.Arrays;

class Solution {
    public int findMinimumTime(int[][] tasks) {
        Arrays.sort(tasks, (a, b) -> Integer.compare(a[1], b[1]));
        boolean[] on = new boolean[2001];
        int answer = 0;

        for (int[] task : tasks) {
            int start = task[0], end = task[1], used = 0;
            for (int time = start; time <= end; time++) {
                if (on[time]) used++;
            }
            for (int time = end; used < task[2]; time--) {
                if (!on[time]) {
                    on[time] = true;
                    used++;
                    answer++;
                }
            }
        }
        return answer;
    }
}

class Solution:
    def findMinimumTime(self, tasks: List[List[int]]) -> int:
        tasks.sort(key=lambda task: task[1])
        on = [False] * 2001
        answer = 0

        for start, end, duration in tasks:
            used = sum(on[start:end + 1])
            time = end
            while used < duration:
                if not on[time]:
                    on[time] = True
                    used += 1
                    answer += 1
                time -= 1

        return answer

替代方案

可以用树状数组统计区间内已选点，再配合并查集跳过已经选中的时间点；也可以使用线段结构维护已选区间。它们能在时间上进一步优化，但本题时间点上限仅 2000，布尔数组更短、更直观，也足以通过。

常见错误

  • 按开始时间排序，导致早期选择挤占共享机会。
  • 从左向右补点；应尽量靠近当前任务的结束位置。
  • 忘记先统计已经开启的点，重复计算可复用时间。
  • 把闭区间写成半开区间，漏掉 end。

面试追问

为什么“靠右选择”比“靠左选择”更好？

任务已按结束时间排序。未来任务的结束点不会更早，而它们的开始点可能更晚；当前区间里越晚的点，被未来区间覆盖的机会越大。

若时间坐标上限变成 10⁹ 怎么办？

不能再开坐标大小的数组。可用坐标压缩与树状数组统计选择数，并用并查集寻找前一个未选择坐标；或维护不相交的已选区间。

如果同一时间电脑只能运行一个任务呢？

共享开机点这一核心性质消失，问题会变成带时间窗的单机调度，当前贪心不再适用，需要重新建模。

排序中结束时间相同需要特殊处理吗？

不需要。它们共享相同右边界；任意顺序逐个补齐，都只会增加可被另一个任务复用的点。
