等差数列中缺失的数字

Missing Number In Arithmetic Progression

EASY 付费题 数组 数学

一列等差数列被拿走了一个既不是首项也不是末项的数字。你得到余下、仍按原顺序排列的整数数组，需要找回那个数字。

Problem

题目与输入

函数签名：missingNumber(arr)

给定整数数组 arr。在删除一个内部元素之前，所有元素按相同的公差组成等差数列；删除后，其余元素保持原顺序。返回被删除的整数。

数组可能递增、递减，也可能所有元素相同。题目保证输入来自一个满足上述条件的数列，因此答案是确定且有效的。

约束

  • 3 ≤ arr.length ≤ 1000
  • 0 ≤ arr[i] ≤ 10⁵
  • 被移除的元素不是原数列的第一项或最后一项。

官方示例

示例 1

输入：arr = [5,7,11,13]

输出：9

补回 9 后为 5, 7, 9, 11, 13。

示例 2

输入：arr = [15,13,12]

输出：14

补回 14 后公差为 −1。

Full Solution

端点定公差，一次扫描找断点

核心洞察

当前数组长度为 n，完整数列原本有 n + 1 项，因此首项到末项之间恰有 n 个等长间隔。公差必为：

d = (arr[n − 1] − arr[0]) / n

首尾都未被删除，所以端点跨度不会变；这比猜测相邻差值更直接，也自然支持递减数列。

完整过程

  1. 用首项、末项和当前长度计算原数列公差 d。
  2. 从 i = 1 开始比较 arr[i] − arr[i−1] 与 d。
  3. 第一次不相等时，缺失值就是 arr[i−1] + d。
  4. 若所有差值都相等，则公差只能为 0，返回任意已有元素。

正确性证明

引理 1：计算得到的 d 是原数列公差。完整数列有 n 个间隔，且首尾均保留，所以端点差等于 n·d，由此公式成立。

引理 2：删除点之外的任意一对当前相邻元素，在原数列中也相邻，其差为 d；跨过删除点的那一对相隔两个原始间隔，其差为 2d。

结论：当 d ≠ 0 时，扫描遇到的第一个异常间隔必定跨过缺失值，补上左端点加 d 即为唯一答案。当 d = 0 时所有值相同，返回该共同值正确。因此算法总能返回缺失数字。

边界处理

  • 递减：d 为负，公式无需修改。
  • 常数列：d = 0，直接返回 arr[0]。
  • 缺失值紧邻首项或末项：异常间隔仍会出现在扫描范围内。
  • 使用整数除法是安全的，因为题目保证输入源自合法等差数列。

复杂度

时间：O(n)，最坏扫描全部相邻对。

空间：O(1)，只维护公差和索引。

若利用数组有序性，可通过比较期望值与实际值做二分，达到 O(log n)；但线性方案更直观、常数更小，也更不易写错。

class Solution {
    public int missingNumber(int[] arr) {
        int n = arr.length;
        int d = (arr[n - 1] - arr[0]) / n;

        for (int i = 1; i < n; i++) {
            if (arr[i] - arr[i - 1] != d) {
                return arr[i - 1] + d;
            }
        }
        return arr[0];
    }
}

替代方案

  • 二分：期望值为 arr[0] + i·d；寻找第一个实际值偏离期望的位置。时间 O(log n)。
  • 总和：完整等差数列和减去当前数组和。时间 O(n)，但固定宽度整数可能溢出。
  • 最大绝对间隔：能找到断点，但必须谨慎处理负公差和全相等数列。

面试追问

  • 怎样把线性扫描优化为二分搜索？
  • 若首项或末项也可能缺失，答案还能唯一确定吗？
  • 若数组无序，最低需要什么复杂度或额外信息？
  • 如何避免求和方案中的整数溢出？

常见错误

  • 用前两个元素之差直接当公差：缺失值可能恰好位于它们之间。
  • 只寻找“更大的正差”：递减数列的相邻差是负数。
  • 把除数写成 n − 1：完整数列比当前数组多一项，因此首尾之间有 n 个间隔。
  • 忽略公差为 0，导致扫描结束后没有返回值。
