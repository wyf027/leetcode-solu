Core weave

dummy + tail，把局部选择串成答案

COMPARE比较 p1.val 与 p2.val

两边当前结点都是各自剩余部分的最小值。

LINKtail.next 接较小者

移动被选中的输入指针，再移动 tail。

REMAINDER整段接上剩余链

一边为空后，另一边本身已排序。

循环不变量：每轮开始时，dummy.next 到 tail 是所有已处理结点的完整有序归并；p1 与 p2 分别指向两条输入链尚未处理的最小结点。

Walkthrough

完整过程

  1. 1

    建立 dummy，令 tail 指向 dummy。

  2. 2

    当 p1、p2 都非空时，比较当前值。

  3. 3

    tail.next 接较小结点，推进对应指针和 tail。

  4. 4

    循环结束后接上非空剩余链，返回 dummy.next。

Edge cases

边界情况

  • 两表都空：dummy.next 仍为 null。
  • 只有一表为空：直接把另一条完整链接到 tail。
  • 重复值：使用 ≤ 时相等先取 list1，不影响有序性。
  • 全负数：比较逻辑与符号无关。
  • 一表完全更小：连续取完后一次接上另一表。

Complexity

复杂度

O(m+n) 时间

O(1) 额外空间

复用原链表结点；返回链表本身不计入额外空间。

Alternatives

替代方案取舍

递归归并

代码短，但调用栈最坏 O(m+n)，长链有栈风险。

新建所有结点

不改输入，但额外空间 O(m+n)，不符合复用结点本意。

收集后排序

浪费输入已排序条件，时间退化到 O((m+n)log(m+n))。

Interview

面试高频追问

为什么 dummy 能简化代码？

它让第一次连接与后续连接完全相同，避免单独决定结果头结点。

相等时应该取哪一边？

两边都正确。若要求稳定地优先 list1，则使用 ≤。

如何扩展到 k 条链表？

可用最小堆做到 O(N log k)，或分治两两归并，同样 O(N log k)。

Pitfalls

常见错误

  • 忘记推进输入指针：会形成死循环。
  • 忘记移动 tail：后续连接不断覆盖同一位置。
  • 漏接剩余链：长度不同的尾段会丢失。
  • 返回 dummy：应返回 dummy.next，跳过虚拟结点。

class Solution {
    public ListNode mergeTwoLists(ListNode list1, ListNode list2) {
        ListNode dummy = new ListNode();
        ListNode tail = dummy;

        while (list1 != null && list2 != null) {
            if (list1.val <= list2.val) {
                tail.next = list1;
                list1 = list1.next;
            } else {
                tail.next = list2;
                list2 = list2.next;
            }
            tail = tail.next;
        }

        tail.next = list1 != null ? list1 : list2;
        return dummy.next;
    }
}
