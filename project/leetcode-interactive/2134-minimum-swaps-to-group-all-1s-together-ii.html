Minimum Swaps to Group All 1's Together II

首尾相接以后，“连续”会有什么不同？先理解目标，再展开下方题解探索。

打开官方题目 ↗

题意

给定只包含 0 和 1 的环形数组 nums，下标 0 与下标 n − 1 相邻。一次操作可以选取任意两个不同位置，交换其中的值。求让数组中所有的 1 占据一段连续环形区间所需的最少操作次数，区间可以从任意位置开始。

交换的位置不要求相邻；只返回次数，不要求返回操作方案。没有 1 时无需交换。

参数与约束

  • minSwaps(nums) → integer，参数为整数数组。
  • 1 ≤ nums.length ≤ 105
  • nums[i] ∈ {0, 1}

官方示例

示例 1

输入：nums = [0,1,0,1,1,0,0]
输出：1

交换下标 1 和 2 后，得到 [0,0,1,1,1,0,0]，所有 1 连在一起；原数组尚未满足目标，因此至少需要一次。

示例 2

输入：nums = [0,1,1,1,0,0,1,1,0]
输出：2

例如分别交换下标 0 与 6、下标 4 与 7，得到 [1,1,1,1,1,0,0,0,0]。最少需要两次。

示例 3

输入：nums = [1,1,0,0,1]
输出：0

下标 4 → 0 → 1 已是一段连续的环形区间，无需操作。

题解 · 在环上寻找最少的空位

核心洞察

设整个数组中共有 k 个 1。最终它们必定填满某个长度为 k 的环形区间。固定这个区间，其中每个 0 都要与区间外的一个 1 交换。因此，区间内的 0 的个数就是所需交换次数。

枚举全部 n 个起点，维护一个长度固定为 k 的滑动窗口，求窗口中 0 数量的最小值。用取模访问环形位置，不必复制数组。

完整过程

  1. 统计 k = sum(nums)。若 k ≤ 1，返回 0。
  2. 计算起点为 0、长度为 k 的窗口中 0 的数量 zeros，作为初始答案。
  3. 起点从 start − 1 移到 start 时，移出 nums[start − 1]，移入 nums[(start + k − 1) % n]。
  4. 移出的是 0 就令 zeros −= 1；移入的是 0 就令 zeros += 1。更新答案。
  5. 处理起点 0 … n − 1 后返回最小值。
示例 1：k = 3
起点       0  1  2  3  4  5  6
窗口零数   2  1  1  1  2  3  2
最小值 = 1

起点 1 的区间是 [1,0,1]（下标 1,2,3）。
交换区间内下标 2 的 0 与区间外下标 4 的 1 即可。

正确性证明

固定区间的下界：如果长度 k 的目标区间有 z 个 0，就必须让其中的 1 的数量增加 z。一次交换至多增加一个，因此至少要交换 z 次。

下界可以达到：区间内有 k − z 个 1，整个数组有 k 个 1，所以区间外恰好有 z 个 1。逐一将这些 1 与区间内的 0 配对交换，恰好 z 次即可填满区间。

覆盖所有结果：每种合法聚集结果都对应一个长度 k 的环形区间。算法枚举全部 n 个起点，且每次仅删除离开的元素、加入进入的元素，始终准确维护窗口零数。因此取最小零数就得到全局最少交换次数。

边界与复杂度

  • 无 1 或仅一个 1：本就无需操作；提前返回可避免空窗口语义。
  • 全部为 1：每个窗口覆盖全数组，零数始终为 0。
  • 最优区间跨越末尾：取模确保它仍被枚举；仅检查普通子数组会漏解。
  • 时间 O(n)：统计与初始化最多 n 步，再做 n − 1 次常数更新。
  • 额外空间 O(1)：代码只保存计数与下标，不修改输入。演示界面为显示历史另存帧，与提交代码空间无关。

Java

class Solution {
    public int minSwaps(int[] nums) {
        int n = nums.length, k = 0;
        for (int x : nums) k += x;
        if (k <= 1) return 0;
        int zeros = 0;
        for (int i = 0; i < k; i++) {
            if (nums[i] == 0) zeros++;
        }
        int answer = zeros;
        for (int start = 1; start < n; start++) {
            if (nums[start - 1] == 0) zeros--;
            if (nums[(start + k - 1) % n] == 0) zeros++;
            answer = Math.min(answer, zeros);
        }
        return answer;
    }
}

var minSwaps = function(nums) {
    const n = nums.length;
    const k = nums.reduce((sum, x) => sum + x, 0);
    if (k <= 1) return 0;
    let zeros = 0;
    for (let i = 0; i < k; i++) {
        if (nums[i] === 0) zeros++;
    }
    let answer = zeros;
    for (let start = 1; start < n; start++) {
        if (nums[start - 1] === 0) zeros--;
        if (nums[(start + k - 1) % n] === 0) zeros++;
        answer = Math.min(answer, zeros);
    }
    return answer;
};

Python

from typing import List

class Solution:
    def minSwaps(self, nums: List[int]) -> int:
        n, k = len(nums), sum(nums)
        if k <= 1:
            return 0
        zeros = sum(nums[i] == 0 for i in range(k))
        answer = zeros
        for start in range(1, n):
            zeros -= int(nums[start - 1] == 0)
            zeros += int(nums[(start + k - 1) % n] == 0)
            answer = min(answer, zeros)
        return answer

        }

替代方案

  • 最大化窗口中的 1：维护窗口内 1 的最大数 maxOnes，答案为 k − maxOnes，同样 O(n) 时间、O(1) 空间。
  • 复制数组 + 前缀和：把数组接在自身后面，用前缀和计算每个长度 k 区间中的 1。时间 O(n)，额外空间 O(n)，容易理解但无需实际复制。
  • 逐窗口重新计数：O(nk) 时间、O(1) 空间，最坏 O(n²)，不适合 10⁵ 的规模。

常见错误

  • 把任意位置交换误读为相邻交换，使用距离累加或中位数模型。
  • 窗口长度取成最长连续 1 的长度；正确长度是整个数组的 1 总数。
  • 把窗口内的 0 与外面的 1 都计入答案，导致翻倍；一对只需一次交换。
  • 遗漏取模，或只枚举到 n − k，漏掉跨界窗口。
  • 滑动更新时将进入下标写成 start + k，造成偏移一位。

面试追问

如何返回交换方案？记录最优起点，再收集窗口内的 0 下标和窗口外的 1 下标，逐对输出；输出本身需要 O(z) 空间。

如果只能交换相邻位置？窗口的空位数不再等于代价，元素移动距离必须计入，需要改用位置与距离模型。

如果数组不是环形？只枚举起点 0 到 n − k，访问下标无需取模。

能提前结束吗？可以。一旦最小值为 0 就已达到理论下界，可直接返回；这里保留完整枚举方便理解。
