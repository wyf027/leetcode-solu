Problem

题意

定义 f(x) 为 x! 末尾连续零的数量，其中 x! = 1 × 2 × 3 × … × x，并约定 0! = 1。

给定整数 k，返回所有满足 f(x) = k 的非负整数 x 的数量。

例：f(3)=0，因为 3!=6；f(11)=2，因为 11!=39916800。

Complete solution

单调函数上的两个下界

核心不是算出阶乘，而是定位 f(x) 的台阶边界。

核心洞察

01 · 数 5

末尾零来自因子 10=2×5。阶乘里 2 足够多，所以只需统计因子 5。

02 · 单调台阶

f(x) 随 x 单调不减，可对“首次达到某个值”的位置做二分。

03 · 两界相减

满足 f(x)=k 的数量等于首次达到 k+1 与首次达到 k 的位置差。

完整过程

  1. 计算末尾零数：每个 5 的倍数至少贡献一个因子 5，每个 25 的倍数再贡献一个，依此类推。
  2. 定义 lowerBound(t)：最小的、满足 f(x) ≥ t 的非负整数 x。
  3. 在闭开区间 [0, 5t+5) 内二分。若 f(mid) ≥ t，答案在左半边（包含 mid）；否则排除 mid 及其左侧。
  4. 最终答案是 lowerBound(k+1) - lowerBound(k)。差为 5 表示存在一组解，差为 0 表示该台阶被跳过。
f(x) = ⌊x/5⌋ + ⌊x/25⌋ + ⌊x/125⌋ + …

正确性证明

引理 1：公式正确计算 f(x)。每个 5^i 的倍数都为 x! 额外贡献一个因子 5；将所有层级相加，恰好计数全部因子 5，也就是全部末尾零。

引理 2：lowerBound(t) 返回最小满足 f(x) ≥ t 的 x。二分始终保留该最小位置：条件成立时收缩右界，否则由单调性可安全丢弃 [left, mid]。区间收敛时左右边界相等，即所求位置。

定理：所有满足 f(x)=k 的整数形成区间 [lowerBound(k), lowerBound(k+1))。区间左侧的函数值小于 k，区间内部至少为 k 且尚未达到 k+1，因此恰好等于 k；右侧则至少为 k+1。所以区间长度就是答案。

边界处理

  • k=0 时，lowerBound(0)=0、lowerBound(1)=5，答案为 5，对应 x=0..4。
  • k=10⁹ 时搜索上界约为 5×10⁹，Java/C++ 必须使用 64 位整数；JavaScript 的安全整数范围足够，但实现仍避免乘法溢出式写法。
  • f(x) 在 25、125 等位置会一次跳过某些值，因此答案可能为 0。

复杂度

时间 · O(log² k)

二分约 O(log k) 轮，每轮计算 f(x) 需要 O(log₅ x) 次除法。对固定 32 位范围也可视为极小常数。

空间 · O(1)

只保存边界、中点与累计零数，不随输入规模增加额外空间。

替代方案

也可以只二分寻找任意一个满足 f(x)=k 的位置：找到就返回 5，否则返回 0。理由是若某个值能取到，它会在连续五个整数上保持不变。不过“两次下界相减”更统一：无需单独依赖“答案只能是 0 或 5”的结论，也直接表达了单调函数等值区间的长度。

Javalong 防溢出
class Solution {
    public int preimageSizeFZF(int k) {
        long left = lowerBound(k);
        long right = lowerBound((long) k + 1);
        return (int) (right - left);
    }

    private long lowerBound(long target) {
        long left = 0;
        long right = 5 * target + 5;

        while (left < right) {
            long mid = left + (right - left) / 2;
            if (trailingZeroes(mid) >= target) {
                right = mid;
            } else {
                left = mid + 1;
            }
        }
        return left;
    }

    private long trailingZeroes(long x) {
        long count = 0;
        while (x > 0) {
            x /= 5;
            count += x;
        }
        return count;
    }
}

var preimageSizeFZF = function(k) {
  const lowerBound = (target) => {
    let left = 0;
    let right = 5 * target + 5;

    while (left < right) {
      const mid = left + Math.floor((right - left) / 2);
      if (trailingZeroes(mid) >= target) {
        right = mid;
      } else {
        left = mid + 1;
      }
    }
    return left;
  };

  const trailingZeroes = (x) => {
    let count = 0;
    while (x > 0) {
      x = Math.floor(x / 5);
      count += x;
    }
    return count;
  };

  return lowerBound(k + 1) - lowerBound(k);
};

面试追问

为什么上界可取 5t+5？

因为到达约 5t 时，仅 5 的倍数就足以贡献至少 t 个因子 5；额外的 25、125 只会让零更多。加 5 让闭开区间写法对 t=0 也自然成立。

为何答案只有 0 或 5？

f(x) 只在 5 的倍数处改变。在相邻两个 5 的倍数之间，它会连续保持五个位置；若跳幅大于 1，则被跳过的值没有原像。

能把时间降到 O(log k) 吗？

若把机器整数位数视为常数，计算 f(x) 就是常数次除法，整体常写作 O(log k)；严格按数值规模分析则是 O(log² k)。

这是什么通用模板？

对单调函数 g，等值集合大小可用 first(g ≥ v+1) - first(g ≥ v) 求得；它与排序数组中 upper_bound-lower_bound 同源。

常见错误

  • 直接计算 x!，既会溢出，也完全无法覆盖搜索范围。
  • 只累加 ⌊x/5⌋，漏掉 25、125 等数贡献的额外因子 5。
  • 二分条件写成 f(mid) > target，导致找成“第一个严格大于”而不是“第一个大于等于”。
  • Java/C++ 用 32 位整数保存右边界，5×10⁹ 会溢出。
  • 找到某个命中值后向两边线性扩展；虽然最多只有五个，但不如边界定义清晰稳定。
