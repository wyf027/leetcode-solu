01 / PROBLEM

题意：给每个中间字符串打分

已知最终字符串 s，长度为 n。从空串开始，每次向当前字符串的最前面放入一个字符，最终得到 s。长度恰好为 i 的中间结果记作 sᵢ。它的得分是它与完整字符串 s = sₙ 的最长公共前缀长度。返回全部 n 个中间结果的得分之和。

最长公共前缀必须从两个字符串的第一个字符开始，遇到首次不同就停止。例如构造 s = "abaca" 时，依次得到 "a" → "ca" → "aca" → "baca" → "abaca"。

官方示例 1

输入：s = "babab"
输出：9

按构造顺序："b" 得 1 分，"ab" 得 0 分，"bab" 得 3 分，"abab" 得 0 分，"babab" 得 5 分。总计 1 + 0 + 3 + 0 + 5 = 9。

官方示例 2

输入：s = "azbazbzaz"
输出：14

s₂ = "az" 得 2 分，s₆ = "azbzaz" 与完整字符串共有开头 "azb"，得 3 分，s₉ = "azbazbzaz" 得 9 分；其余得分为 0。总计 2 + 3 + 9 = 14。

完整约束：1 ≤ s.length ≤ 10⁵；s 只包含小写英文字母。参数为字符串 s，返回整数得分和。

04 / SOLUTION

准备好理解高效解法了吗？

展开后包含算法推导、边界复用演示与四语言代码。

INSIGHT

所有中间串，恰好就是所有后缀

长度为 k 的构造结果只能是 s[n-k..n-1]。因此无需真正构造字符串。将每个后缀与完整字符串比较，就能得到得分；这些后缀仅仅按与下标相反的顺序出现，求和不受顺序影响。

定义 z[i] = LCP(s, s[i..n-1])。完整串自身贡献 n，其余由 Z 算法在线性时间求出。本页代码令 z[0] = 0，将完整串单独计入。

answer = n + Σ z[i]，其中 1 ≤ i < n

如何跳过已经知道相等的字符？

维护右端点最远的匹配区间 [l, r]（两端都包含），满足 s[l..r] = s[0..r-l]。当 i ≤ r，令 k = i-l，先复用 z[i] = min(z[k], r-i+1)。盒子外的字符尚无保证，接着从 z[i] 处继续比较。

  1. 初始 answer = n，l = 0, r = -1 表示空盒子。
  2. 从 i = 1 向右扫描。盒内取复用下界，盒外从 0 开始。
  3. 当 i + z[i] < n 且 s[z[i]] == s[i+z[i]]，将 z[i] 加一。
  4. 若 i + z[i] - 1 > r，更新 l = i、r = i+z[i]-1。
  5. 累加 z[i]。所有后缀处理完成后返回总和。

示例 "babab"：有效得分数组为 [5, 0, 3, 0, 1]。处理下标 2 后盒子是 [2, 4]；到下标 4 时，镜像下标是 2，已有 z[2]=3，但盒子只剩 1 个字符，所以只能复用 min(3,1)=1。

为什么正确，为什么是 O(n)？

正确性：盒子保存的是已经证明的相等关系

归纳假设：在处理 i 前，已计算的 Z 值正确，且当前盒子内的子串与等长前缀相同。盒外从 0 比较自然安全；盒内，由盒子的相等关系，可以将 i 映射到前缀中的 i-l，保证前 min(z[i-l], r-i+1) 个字符匹配。如果镜像匹配在盒内结束，对应的不匹配也成立；如果触及盒子边界，边界之外必须重新比较。逐字符扩展直到不匹配或到达末尾，故得到的恰是最长公共前缀。更新盒子保持不变量。

每个构造结果与一个后缀一一对应，n 恰好补上完整字符串自身，因而求和不遗漏也不重复。

复杂度：成功扩展推动最右边界

盒内提前结束的复用不会带来成功扩展；其他成功扩展会越过当前最右边界，而右边界总共只能向右移动 O(n) 次。每个 i 至多产生一次失败比较，所以总时间 O(n)，Z 数组辅助空间 O(n)。页面为可回退演示保存快照，最多接受 32 个字符，快照空间 O(m²)；这不属于提交算法的复杂度。

边界与数值

  • n=1：循环不执行，直接返回 1。
  • 所有字符相同：后缀得分为 n,n-1,…,1，总和为 n(n+1)/2。
  • 所有字符互不相同：非完整串得分全为 0，答案为 n。
  • 最大答案为 100000×100001/2 = 5,000,050,000，Java 使用 long，C++ 使用 long long；Python 整数自动扩展，JavaScript 的 Number 在此范围内精确。
  • 空字符串不在官方输入范围内；可视化入口会拒绝空串和非小写字母。

四语言提交代码

四份代码均采用闭区间 [l, r] 和单独计入 n 的约定；仅提供代码，未运行验证。

Java

class Solution {
    public long sumScores(String s) {
        int n = s.length();
        int[] z = new int[n];
        int l = 0, r = -1;
        long answer = n;
        for (int i = 1; i < n; i++) {
            if (i <= r) {
                z[i] = Math.min(z[i - l], r - i + 1);
            }
            while (i + z[i] < n
                    && s.charAt(z[i]) == s.charAt(i + z[i])) {
                z[i]++;
            }
            if (i + z[i] - 1 > r) {
                l = i;
                r = i + z[i] - 1;
            }
            answer += z[i];
        }
        return answer;
    }
}

Python 3

class Solution:
    def sumScores(self, s: str) -> int:
        n = len(s)
        z = [0] * n
        left, right = 0, -1
        answer = n
        for i in range(1, n):
            if i <= right:
                z[i] = min(z[i - left], right - i + 1)
            while i + z[i] < n and s[z[i]] == s[i + z[i]]:
                z[i] += 1
            if i + z[i] - 1 > right:
                left, right = i, i + z[i] - 1
            answer += z[i]
        return answer

C++

#include <algorithm>
#include <string>
#include <vector>
using namespace std;

class Solution {
public:
    long long sumScores(string s) {
        int n = static_cast<int>(s.size());
        vector<int> z(n, 0);
        int l = 0, r = -1;
        long long answer = n;
        for (int i = 1; i < n; ++i) {
            if (i <= r) {
                z[i] = min(z[i - l], r - i + 1);
            }
            while (i + z[i] < n && s[z[i]] == s[i + z[i]]) {
                ++z[i];
            }
            if (i + z[i] - 1 > r) {
                l = i;
                r = i + z[i] - 1;
            }
            answer += z[i];
        }
        return answer;
    }
};

替代方案与常见错误

可以怎么替代？

  • 逐个后缀直接比较：O(n²) 时间、O(1) 额外空间（用索引而非复制字符串）。适合理解题意，全相同字符串会退化。
  • 滚动哈希 + 二分 LCP：O(n log n) 时间、O(n) 空间。实现需处理溢出和哈希碰撞；双哈希只能降低风险，不能提供绝对正确性保证。
  • 前缀函数 + 出现次数传播：O(n) 时间与空间。将所有前缀在 s 中的出现次数相加也得到答案，但计数传播比本题的 Z 定义更间接。

容易错在哪里？

  • 把中间串当成前缀；每次向前加字符，实际得到的是后缀。
  • 漏算完整串贡献 n，或将 z[0]=n 后又额外加 n。
  • 直接复用 z[i-l]，没有用 r-i+1 截断。
  • 混用闭区间与半开区间，更新右端点时少减或多减 1。
  • 将 Java/C++ 的总和放入 32 位整数。
  • 把最长公共前缀误作最长公共子串；首次不匹配后不能继续累计。

面试追问

为什么 Z 总和等于所有前缀的出现次数之和？ 一个后缀得分为 k，意味着长度 1 到 k 的每个前缀都在此起点出现一次。按起点求和与按前缀长度求和，是同一组匹配的两种计数方式。

能否将空间降到 O(1) 并保持线性时间？ 当前算法会随机访问历史 z[i-l]，不能简单删除数组。改用直接比较可降空间，但最坏时间回到 O(n²)。

如果字符集包含 Unicode 呢？ 先明确“字符”是码点还是字素簇。JavaScript 的字符串索引和 Java 的 char 按 UTF-16 代码单元操作；本题限定小写英文字母，因此不会出现这种歧义。
