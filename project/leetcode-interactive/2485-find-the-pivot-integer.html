找出中枢整数

Find the Pivot Integer

从 1 走到 n，能否找到一个整数，让它左右两侧的区间和恰好相等？注意：这个整数同时属于两侧。

同一个 x，参与两次求和

参数：n: integer　返回：integer

约束：1 ≤ n ≤ 1000

示例 1

输入：n = 8
输出：6

示例 2

输入：n = 1
输出：1

示例 3

输出：-1

04 / 深入理解

准备好看完整推导了吗？

包含过程、证明、四语言代码与数学优化。

题解 · 一次遍历维护前缀和

核心洞察

令总和 T = n(n + 1) / 2，左区间和为 L。因为 x 在左右区间中都出现，右区间和是 R = T - L + x。从 1 枚举到 n，累计 L 即可在每个候选处用常数时间检查。

完整过程

  1. 计算总和 T，令 L = 0。
  2. 依次枚举 x = 1, 2, …, n，先执行 L += x。
  3. 计算 R = T - L + x。若 L = R，立即返回 x。
  4. 所有候选都未满足条件时返回 -1。

以 n = 8 为例，T = 36，各步的左右和如下。演示中的每次“下一步”对应这里的一行。

x     L     R     结论
1     1    36     不相等
2     3    35     不相等
3     6    33     不相等
4    10    30     不相等
5    15    26     不相等
6    21    21     返回 6

正确性证明

循环不变式：每次比较前，L 恰好是 1 到 x 的和。初始 L = 0；每轮添加当前 x，因此不变式成立。T - L 是 x + 1 到 n 的和，再加 x 就得到 x 到 n 的和，所以比较的两个值正是题目要求的两个区间和。

返回 x 时两和相等，故返回值合法。若没有提前返回，循环检查了 [1, n] 的每个整数，故确实不存在合法解，返回 -1 正确。

唯一性也可由差值看出：当候选从 x 变为 x + 1，左和增加 x + 1，右和减少 x，因此 L - R 增加 2x + 1，严格递增，最多有一次等于零。

边界与复杂度

  • n = 1 时首次比较为 1 = 1，返回 1；必须允许端点作为候选。
  • 无解时遍历结束返回 -1；两个区间都必须包含 x。
  • n ≤ 1000，总和最大为 500500，四种语言代码中的数值类型均可容纳。
  • 时间 O(n)，额外空间 O(1)。可视化的数字节点只是教学展示，不计入算法空间。

四语言完整提交代码

Java

class Solution {
    public int pivotInteger(int n) {
        int total = n * (n + 1) / 2;
        int left = 0;
        for (int x = 1; x <= n; x++) {
            left += x;
            if (left == total - left + x) {
                return x;
            }
        }
        return -1;
    }
}

替代方案 · 从区间和变成平方数

由 L = T - L + x 得 2L - x = T；代入 L = x(x + 1)/2，可得 x² = T。因此，只有总和 T 是完全平方数时才有解。取 r = floor(sqrt(T))，检查 r * r === T，成立则返回 r，否则返回 -1。

对 n ≥ 1，有 1 ≤ T ≤ n²，所以存在的正平方根必然在 [1, n] 内。固定宽度数值与常数时间平方根模型下，数学法时间 O(1)、额外空间 O(1)。如果避免浮点平方根，可二分寻找整数平方根，时间 O(log n)、额外空间 O(1)。任意精度大整数下，算术和开方成本不能再简单视为常数。

最朴素的方法是每个 x 都重新累加两段区间，时间 O(n²)，额外空间 O(1)。本页主算法复用前缀和，保留直观过程并消除重复求和。

常见错误

  • 写成 R = T - L，遗漏右区间也应包含 x。
  • 先比较再执行 L += x，使左区间少一个元素。
  • 循环使用 x < n，漏掉 n = 1 的合法端点。
  • 只把平方根取整就返回，没有确认它的平方等于 T。
  • 扩大约束后仍用窄整数做 n * (n + 1)；Java/C++ 应在乘法前提升类型，JavaScript 超过安全整数时考虑 BigInt。

面试追问

差值大于零可以提前退出吗？可以。差值严格递增，后续不可能回到零；主代码为直观展示完整枚举，省略这一优化。

推广到任意数组呢？仍可用前缀和与总和比较两侧，但 x 不再表示元素值，也没有 x² = T 的连续整数性质；含负数时唯一性与单调性也可能消失。

n 特别大怎么办？使用足够宽的整数或大整数，结合整数平方根与精确平方检查，避免溢出和浮点精度误判。
