向公司 CEO 汇报工作的所有人

从一张员工—直属经理关系表出发，找出所有直接或间接向公司负责人汇报的员工。先读懂关系，再让查询落地。

#1270

题目

01 / BRIEF

给定关系表 Employees。每一行记录一名员工的编号、姓名，以及这名员工直属经理的编号。公司负责人固定为 employee_id = 1。

请查询所有直接或通过经理链间接向公司负责人汇报的员工编号 employee_id。公司规模较小，间接汇报链最多经过 3 名经理；结果可按任意顺序返回，且不应包含 CEO 本人。

这是一道数据库题。LeetCode 提交时返回一条查询语句，而不是实现一个接收参数的普通函数。

完整题解

06 / SOLUTION
核心洞察 把同一张表看成“员工、经理、经理的经理”三种角色。

一次自连接沿汇报链向上走一步。连续两次自连接，再检查最上层记录的 manager_id 是否为 1，就覆盖了直接、二级与三级汇报。示例中 CEO 的记录是 (1, Boss, 1)，自指关系可以为较短链补齐步数。

完整过程

  1. 给角色起别名。令 e1 表示待判断员工，e2 表示其直属经理，e3 表示再上一级经理。
  2. 向上连接两次。用 e1.manager_id = e2.employee_id 与 e2.manager_id = e3.employee_id 拼出最长三段汇报链。
  3. 检查链顶。若 e3.manager_id = 1，则从 e1 向上至多三名经理即可到 CEO。
  4. 排除 CEO。增加 e1.employee_id != 1，避免 CEO 的自指记录进入结果。

示例如何流过查询

Bob（2）

2 → 1 → 1 → 1

Daniel（4）

4 → 2 → 1 → 1

Luis（7）

7 → 4 → 2 → 1

Angela（9）

9 → 8 → 3 → 3（不抵达 1）

正确性证明

充分性

查询返回 e1 时，连接条件给出一条从 e1 经 e2、e3 再到编号 1 的汇报链，因此 e1 确实直接或间接向 CEO 汇报；CEO 本人又被显式排除。

必要性

若某员工向 CEO 汇报，题目保证链最多涉及 3 名经理。对不足三步的链，CEO 的自指记录补齐剩余步数，所以总能找到满足两个连接及 e3.manager_id = 1 的 e2、e3。

结论

查询既不会收进无关员工，也不会漏掉合法员工，因此返回集合恰好是所有直接或间接向 CEO 汇报的人。

边界情况

  • 表中只有 CEO：排除编号 1 后返回空集。
  • 员工直接向 CEO 汇报：CEO 自指可补齐连接链。
  • 恰好三级汇报：三段关系完整匹配。
  • 独立分支或自管理分支：链顶不是 1，不会入选。
  • 输出无需排序；不要为迎合示例顺序添加无意义排序。

复杂度

设员工数为 n。在 employee_id 有唯一索引的常见数据库执行计划中，两次等值连接都可按键查找，预期时间为 O(n)；若缺少可用索引，具体代价由优化器与连接策略决定，最坏可显著更高。

查询文本自身只使用常数个别名，额外逻辑空间为 O(1)；数据库执行器的哈希表、缓冲与临时结果不在此抽象计数内。

SELECT e1.employee_id
FROM Employees AS e1
JOIN Employees AS e2
  ON e1.manager_id = e2.employee_id
JOIN Employees AS e3
  ON e2.manager_id = e3.employee_id
WHERE e1.employee_id <> 1
  AND e3.manager_id = 1;

本地语义参考：以员工数组模拟层级遍历，不可提交到本题数据库判题器。

import java.util.*;

public class Solution {
    static class Employee {
        int id;
        String name;
        int managerId;

        Employee(int id, String name, int managerId) {
            this.id = id;
            this.name = name;
            this.managerId = managerId;
        }
    }

    public static List<Integer> findReportingPeople(List<Employee> employees) {
        Map<Integer, List<Integer>> reports = new HashMap<>();
        for (Employee employee : employees) {
            if (employee.id != employee.managerId) {
                reports.computeIfAbsent(employee.managerId, k -> new ArrayList<>())
                       .add(employee.id);
            }
        }

        List<Integer> answer = new ArrayList<>();
        Queue<Integer> queue = new ArrayDeque<>();
        queue.offer(1);

        for (int depth = 0; depth < 3 && !queue.isEmpty(); depth++) {
            int width = queue.size();
            while (width-- > 0) {
                int manager = queue.poll();
                for (int employeeId : reports.getOrDefault(manager, List.of())) {
                    answer.add(employeeId);
                    queue.offer(employeeId);
                }
            }
        }
        return answer;
    }
}

本地语义参考：输入为对象数组，不可提交到本题数据库判题器。

/**
 * @param {{employee_id:number, employee_name:string, manager_id:number}[]} employees
 * @return {number[]}
 */
function findReportingPeople(employees) {
  const reports = new Map();
  for (const employee of employees) {
    if (employee.employee_id === employee.manager_id) continue;
    if (!reports.has(employee.manager_id)) reports.set(employee.manager_id, []);
    reports.get(employee.manager_id).push(employee.employee_id);
  }

  const answer = [];
  let frontier = [1];
  for (let depth = 0; depth < 3 && frontier.length; depth += 1) {
    const next = [];
    for (const managerId of frontier) {
      for (const employeeId of reports.get(managerId) ?? []) {
        answer.push(employeeId);
        next.push(employeeId);
      }
    }
    frontier = next;
  }
  return answer;
}

        next_frontier = []

替代方案

递归 CTE：从 CEO 的直接下属作为锚点，每轮连接下一层，并用深度列限制到 3 层。它更容易扩展到未知深度，但不同数据库语法略有差异。

集合子查询：嵌套三层 IN 也能表达固定深度，不过角色关系不如显式自连接直观，排查重复与空值时也更费力。

常见错误

  • 只写 manager_id = 1，遗漏间接汇报者。
  • 忘记排除 CEO，导致编号 1 因自指记录进入结果。
  • 连接方向写反：应由员工的 manager_id 匹配经理的 employee_id。
  • 把题目“最多三名经理”误解为只需要两层员工。
  • 把本地四语言模拟代码误当作 LeetCode 数据库题提交答案。

面试追问

如果层级深度不固定，如何修改？

使用递归 CTE，锚点选择 CEO 的直接下属，递归项连接下一层；如果数据可能存在环，还要记录路径或使用数据库提供的环检测能力。

为什么这里的内连接不会漏掉直接下属？

示例与本题模型中 CEO 行的 manager_id 为 1。直接下属先连接到 CEO，随后 CEO 可以继续连接到自己，为短链补齐固定的连接次数。

如何应对脏数据里的循环汇报？

固定三层自连接天然只走有限步，不会无限循环；递归 CTE 则应加入深度上限或访问路径去重，并由数据约束从源头阻止非 CEO 的自环与多节点环。

是否需要 DISTINCT？

employee_id 唯一且每位员工只有一个直属经理时，从每个 e1 出发的上行链唯一，本查询不会为同一 e1 生成多条路径，因此无需 DISTINCT。
