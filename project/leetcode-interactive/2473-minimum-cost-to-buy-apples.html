购买苹果的最低成本

Minimum Cost to Buy Apples

一张城市地图，一次购入与返回。对每个出发城市，算清买到一个苹果的最低总开销。

先独立思考；交互推演与四语言实现都放在页面底部的折叠题解中。

01 / 题目

买完后，还要回到起点

有 n 个城市，编号为 1 到 n。每条 roads[t] = [a, b, cost] 是一条双向道路，空手经过它需支付 cost。城市 i 的一个苹果售价记录在代码数组 appleCost[i - 1] 中。

从任意城市出发，到某个可到达的城市购买恰好一个苹果，然后回到出发地。买到苹果之后，每条道路的通行费变为原来的 k 倍。也可以直接在出发城市购买，不产生路费。

返回长度为 n 的数组：answer[i - 1] 表示从城市 i 出发所需的最低总费用，包括去程、苹果和回程。各个起点独立计算，不是一次旅行遍历所有城市。

minCost(n, roads, appleCost, k) → long[]
城市编号：1..n    代码中的数组下标：0..n-1

02 / 官方示例

示例 1 · 走出去可能更便宜

n = 4
roads = [[1,2,4],[2,3,2],[2,4,5],
         [3,4,1],[1,3,4]]
appleCost = [56,42,102,301]
k = 2
输出 = [54,42,48,51]

城市 1 去城市 2 购买再返回，花费 4 + 42 + 8 = 54。城市 4 经城市 3 到城市 2，往返与购买合计 3 + 42 + 6 = 51。

示例 2 · 就地购买

n = 3
roads = [[1,2,5],[2,3,1],[3,1,2]]
appleCost = [2,3,1]
k = 3
输出 = [2,3,1]

三个城市都在本地购买最划算。外地价格即使更低，也未必能抵消往返路费。

03 / 约束与思考

  • 2 ≤ n ≤ 1000
  • 1 ≤ roads.length ≤ 2000
  • 1 ≤ a, b ≤ n，且 a ≠ b
  • 1 ≤ cost ≤ 10⁵；没有重复边
  • appleCost.length = n
  • 1 ≤ appleCost[i] ≤ 10⁵
  • 1 ≤ k ≤ 100

05 / 深入推演

准备好再打开答案

包含交互城市图、完整证明、复杂度分析和四语言代码。

核心洞察 · 让便宜的购买方案向外传播

固定起点 i 与购买城市 j。设原图最短距离为 d(i,j)，无向道路让两个方向的最短距离相等；回程所有边统一乘 k，不改变最短路径的选择。因此最低去程是 d，最低回程是 k·d。

answer[i] = min over j { appleCost[j] + (k + 1) · d(i,j) }

把每条路改成 (k+1) 倍路费。想象一个超级源点向每座城市连边，边权就是该城市的苹果售价。超级源点到 i 的最短路，恰好是在某地买苹果后，把该购买方案传播到 i 的费用。

无需真的创建超级源点：直接令 dist[i] = appleCost[i]，所有城市都有初始候选值，再执行一次多源 Dijkstra。这里每轮线性扫描选取最小的未确定城市，以简化四语言实现。

完整过程

  1. 构建双向邻接表，路费在松弛时乘 (k+1)。
  2. 每个城市的候选值初始化为本地苹果价；全部标记为未确定。
  3. 扫描所有未确定城市，选择 dist 最小的 u，并确定它。
  4. 对每条 u—v 的路，计算 dist[u] + (k+1)·w；若 v 未确定且此值更小，更新 dist[v]。
  5. 重复 n 轮，返回 dist。

示例 1：从 [56,42,102,301] 开始，选城市 2，得到 [54,42,48,57]；选城市 3 后把城市 4 降到 51；再依次选 4、1，得到 [54,42,48,51]。

正确性

建模等价：任意去 j 购买并返回 i 的行程，其路费至少为 (k+1)·d(i,j)，取最短路径往返可以达到此下界。超级源点经过 j 到 i 的最短路成本正是售价加该往返路费，因此两个问题最优值相同。

初始化等价：松弛超级源点的所有出边后，每座城市的距离就是其售价，恰与本算法初值相同。

贪心成立：假设已确定的城市距离均正确，选择未确定的最小候选 u。若另有更短路径，则它离开已确定区域的第一个未确定城市 x 已被松弛（也可以直接来自超级源点）。非负边权保证 x 的候选值不超过该路径到 u 的总长，便会严格小于 dist[u]，与选择 u 矛盾。归纳可知每次确定均正确，最终全部答案正确。

复杂度与替代方案

令 m = roads.length。本文四份实现均为扫描版多源 Dijkstra：选点总计 O(n²)，遍历邻接表总计 O(m)，时间 O(n²+m)，额外空间 O(n+m)。n ≤ 1000 时可避免手写优先队列。

更大稀疏图可使用多源最小堆，时间 O((n+m) log(n+m))、空间 O(n+m)（允许过期堆项）。也可以对每个起点单独执行 Dijkstra，再枚举购买城市，时间 O(n(n+m) log n)；Floyd 全源距离需 O(n³) 时间、O(n²) 空间，当前范围不优先采用。

边界与数值

  • 非连通图：各连通分量独立传播，孤立城市保留本地售价。
  • 本地购买：距离为零，因此 answer[i] ≤ appleCost[i]。
  • 相同费用：任选一个最小城市均正确，无需在相等时反复更新。
  • Java 用 long，C++ 用 long long，先转宽类型再乘。Python 整数自动扩展；JavaScript 的 Number 足以精确表示本题整数。
  • 本实现候选值最多为 10⁵ + 101·10⁵ = 10,200,000；若改用枚举起点的累计路径，长路径中间值可能超过 32 位整数。

常见错误

  • 把往返费写成 2k·d 或 k·d；应为 (k+1)·d。
  • 只在全局最便宜的城市初始化源点，漏掉路费更省的本地或邻城方案。
  • 所有 dist 初始化为 0，把购买费用丢失。
  • 城市编号未减 1，或只添加单向边。
  • 只按苹果售价选目的地，忽略路费；或者每轮同时确定全部城市，破坏贪心顺序。

面试追问

如何返回购买地点和路线？记录来源城市 source 与松弛前驱 parent；沿前驱即可到达购买城市，无向图中反向走回。

道路改成有向图？去程与回程距离不一定相等，不能继续统一乘 (k+1)；需分别计算 d(i,j) 与 d(j,i)，再最小化售价 + d(i,j) + k·d(j,i)。

k 每个起点都不同？不再共享一套统一边权，可先获得原图全源距离，再按每个起点的系数取最小值。

四语言完整实现

同一套扫描版多源 Dijkstra，按官方 minCost 参数与返回值语义提供。代码仅生成，尚未提交或执行。

Java

import java.util.*;

class Solution {
    public long[] minCost(int n, int[][] roads, int[] appleCost, int k) {
        List<int[]>[] graph = new ArrayList[n];
        for (int i = 0; i < n; i++) graph[i] = new ArrayList<>();
        for (int[] r : roads) {
            graph[r[0] - 1].add(new int[]{r[1] - 1, r[2]});
            graph[r[1] - 1].add(new int[]{r[0] - 1, r[2]});
        }
        long[] dist = new long[n];
        boolean[] done = new boolean[n];
        for (int i = 0; i < n; i++) dist[i] = appleCost[i];
        // ponytail: n <= 1000; use a heap if the graph grows much larger.
        for (int step = 0; step < n; step++) {
            int u = -1;
            for (int i = 0; i < n; i++)
                if (!done[i] && (u == -1 || dist[i] < dist[u])) u = i;
            done[u] = true;
            for (int[] e : graph[u]) {
                int v = e[0];
                long candidate = dist[u] + (k + 1L) * e[1];
                if (!done[v] && candidate < dist[v]) dist[v] = candidate;
            }
        }
        return dist;
    }
}

/**
 * @param {number} n
 * @param {number[][]} roads
 * @param {number[]} appleCost
 * @param {number} k
 * @return {number[]}
 */
var minCost = function(n, roads, appleCost, k) {
    const graph = Array.from({length: n}, () => []);
    for (const [a, b, w] of roads) {
        graph[a - 1].push([b - 1, w]);
        graph[b - 1].push([a - 1, w]);
    }
    const dist = appleCost.slice();
    const done = Array(n).fill(false);
    // ponytail: n <= 1000; larger sparse graphs can use a min-heap.
    for (let step = 0; step < n; step++) {
        let u = -1;
        for (let i = 0; i < n; i++) {
            if (!done[i] && (u === -1 || dist[i] < dist[u])) u = i;
        }
        done[u] = true;
        for (const [v, w] of graph[u]) {
            const candidate = dist[u] + (k + 1) * w;
            if (!done[v] && candidate < dist[v]) dist[v] = candidate;
        }
    }
    return dist;
};

Python

from typing import List

class Solution:
    def minCost(self, n: int, roads: List[List[int]],
                appleCost: List[int], k: int) -> List[int]:
        graph = [[] for _ in range(n)]
        for a, b, w in roads:
            graph[a - 1].append((b - 1, w))
            graph[b - 1].append((a - 1, w))
        dist = appleCost[:]
        done = [False] * n
        # ponytail: n <= 1000; switch to heapq for larger sparse graphs.
        for _ in range(n):
            u = -1
            for i in range(n):
                if not done[i] and (u == -1 or dist[i] < dist[u]):
                    u = i
            done[u] = True
            for v, w in graph[u]:
                candidate = dist[u] + (k + 1) * w
                if not done[v] and candidate < dist[v]:
                    dist[v] = candidate
        return dist

#include <vector>
#include <utility>
using namespace std;

class Solution {
public:
    vector<long long> minCost(int n, vector<vector<int>>& roads,
                              vector<int>& appleCost, int k) {
        vector<vector<pair<int, int>>> graph(n);
        for (const auto& r : roads) {
            graph[r[0] - 1].push_back({r[1] - 1, r[2]});
            graph[r[1] - 1].push_back({r[0] - 1, r[2]});
        }
        vector<long long> dist(appleCost.begin(), appleCost.end());
        vector<bool> done(n, false);
        // ponytail: n <= 1000; use a priority_queue for larger sparse graphs.
        for (int step = 0; step < n; ++step) {
            int u = -1;
            for (int i = 0; i < n; ++i)
                if (!done[i] && (u == -1 || dist[i] < dist[u])) u = i;
            done[u] = true;
            for (auto [v, w] : graph[u]) {
                long long candidate = dist[u] + (k + 1LL) * w;
                if (!done[v] && candidate < dist[v]) dist[v] = candidate;
            }
        }
        return dist;
    }
};
