Core insight

同一个数字异或两次会被抵消

利用 x ^ x = 0、x ^ 0 = x 与异或的交换律、结合律，把 A 与 B 的信息暂时叠加在一个数组槽位中。三次原地异或后，两边各自恢复出对方的原值；没有临时变量，也没有算术溢出。

Complete process

完整过程

  1. 1. 执行 A = A ^ B，A 暂存两数的异或组合。
  2. 2. 执行 B = A ^ B，B 恢复为旧 A。
  3. 3. 执行 A = A ^ B，A 恢复为旧 B。
  4. 4. 返回原数组，两个槽位完成交换。

Boundaries

边界检查

  • 两个值相等时仍正确：第一次异或得到 0，后两步恢复原值。
  • 0 与任意数交换时，利用 x ^ 0 = x 正常工作。
  • 正负边界值只参与按位运算，不发生加减法溢出。
  • 数组两个槽位不同，因此不存在“同一内存位置自异或清零”的别名问题。

Alternatives

替代方案

  • 加减法交换：三步直观，但 Java、C++ 与 JavaScript 中可能溢出，不推荐作为主答案。
  • 新数组 / 解构：代码最短，却绕开了“不用临时变量直接交换”的面试考点。
  • 普通临时变量：生产代码可读性最好，但不满足题设限制。

Common mistakes

常见错误

  • 把第二步写成 B ^= B，直接把 B 清零。
  • 改变三步顺序，导致恢复时使用了错误的中间值。
  • 使用 A + B 却没有说明整型溢出风险。
  • 异或同一个数组下标；同一存储位置会在第一步变为 0。

Interview follow-ups

面试追问

为什么能恢复？

展开第二步：(oldA ^ oldB) ^ oldB = oldA。

真实项目会这样写吗？

通常不会。临时变量或语言原生交换更清晰；本题考察位运算性质。

异或交换的隐患？

两处引用若指向同一存储位置，第一步会清零；本题固定为两个不同数组槽位。
