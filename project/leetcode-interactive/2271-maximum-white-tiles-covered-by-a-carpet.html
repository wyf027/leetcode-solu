2271. 毯子覆盖的
最多白色砖块数

Maximum White Tiles Covered by a Carpet

一块固定长度的毯子，若干段白色砖块。找出能覆盖最多白砖的放置位置。

先理解问题，再展开推导。算法、演示与代码均在页面底部的题解中。

题目说明

给定二维整数数组 tiles，每个元素 [lᵢ,rᵢ] 表示位置 lᵢ 到 rᵢ 的所有砖块均为白色，两个端点都计入。区间互不重叠，输入顺序不保证有序。

另给定整数 carpetLen，表示唯一一块毯子的长度。毯子可以放在任意位置，但不能拆分。返回它最多能覆盖的白色砖块数；区间之间的空隙不贡献白砖数，却会占用毯子长度。

参数与返回值
maximumWhiteTiles(tiles, carpetLen) → integer
tiles：整数区间数组；carpetLen：整数长度；返回值：最大白砖覆盖数量。

约束

  • 1 ≤ tiles.length ≤ 5 × 10⁴
  • tiles[i].length == 2
  • 1 ≤ lᵢ ≤ rᵢ ≤ 10⁹
  • 1 ≤ carpetLen ≤ 10⁹
  • 所有区间互不重叠，允许相邻。

示例 1

tiles = [[1,5],[10,11],[12,18],[20,25],[30,32]]
carpetLen = 10
输出：9

从位置 10 铺到位置 19，覆盖 [10,11] 的 2 块和 [12,18] 的 7 块，共 9 块。其他放置也可能达到这个最大值。

示例 2

tiles = [[10,11],[1,1]]
carpetLen = 2
输出：2

从位置 10 铺到位置 11，两块均为白色，因此最多覆盖 2 块。

准备好推导了吗？

展开区间演示、正确性证明与四语言实现。

核心洞察：只枚举白色区间的左端点

存在一个最优放置，使毯子左端恰好位于某段白砖的左端点。排序后，每次固定起点 lᵢ，右端就是 E = lᵢ + carpetLen − 1。覆盖内容分成若干完整区间，加上最多一个右侧残段。

前缀和快速累加完整区间；二分查找第一个 rⱼ > E 的区间。它可能仅部分覆盖，也可能完全位于毯子右侧。

交互实验 · 完整段 + 右侧残段

每个候选起点按“定位 → 二分 → 计数”推进。青色框是毯子，绿色为完整段，黄色为残段；图形颜色信息也会在文字和表格中呈现。

完整过程

  1. 按左端点排序。不重叠保证右端点也严格递增。
  2. 建立 prefix[0]=0，prefix[k+1]=prefix[k]+rₖ−lₖ+1。
  3. 枚举区间 i，将毯子放在 [lᵢ,E]。
  4. 在半开下标区间 [i,n) 中二分查找首个右端点大于 E 的下标 j；不存在则 j=n。
  5. 完整段为 [i,j)，覆盖数为 prefix[j]−prefix[i]。
  6. 若 j<n，残段贡献为 max(0,E−lⱼ+1)；否则为 0。因为 rⱼ>E，无需再与整段长度取最小值。
  7. 完整段加残段，更新最大值，枚举完毕后返回。

示例 1：排序后长度为 [5,2,7,6,3]，前缀和为 [0,5,7,14,20,23]。当 i=1，E=19，j=3，完整部分 prefix[3]−prefix[1]=9；下一段从 20 开始，残段 max(0,19−20+1)=0。总计 9。

正确性论证

1. 候选起点包含最优放置

取一个覆盖到白砖的最优放置。若左端在空隙内，把它右移到覆盖到的第一段白砖起点，丢掉的都是非白砖，覆盖数不降。若左端在某段白砖内部，则将其左移到该段起点。设左移 d 格：当 d 小于毯长，左侧新增 d 块白砖、右侧最多损失 d 块；当 d 不小于毯长，移动后的毯子完全位于该段内，已达到毯长上界。因此总有一个最优解从某段白砖起点开始。

2. 每个候选的计数准确

i 到 j−1 的区间均从毯子起点之后开始，且结束于 E 以内，全部覆盖。第 j 段的右端超过 E，交集长度是 max(0,E−lⱼ+1)。后续段因互不重叠而从 rⱼ 之后开始，不能再被覆盖。完整段与残段互不重叠，前缀和差值加残段恰等于真实覆盖数。

3. 取最大值正确

枚举包含最优候选，每个候选计数准确，所以返回所有候选的最大值就是全局最优覆盖数。

边界、复杂度与替代方案

  • 长区间：j 可以等于 i，此时完整部分为 0，残段为 carpetLen。
  • 落入空隙：残段贡献必须取 max(0, …)，避免负数。
  • 末尾：j=n 时只取前缀和差，不访问 tiles[n]。
  • 相邻区间：无需合并，闭区间长度始终是 r−l+1。
  • 数值：Java / C++ 使用宽整数计算端点和前缀和；JavaScript Number 可精确表达本题所需整数。
  • 复杂度：排序 O(n log n)，前缀和 O(n)，n 次二分 O(n log n)，总时间 O(n log n)，额外空间 O(n)，含前缀数组和排序开销。
  • 输入修改：四语言实现均原地排序 tiles；需要保留原始顺序时先复制。

替代方案：滑动窗口

随着 i 增大，E 递增，j 也只向右移动。用双指针维护完整区间长度和，排序后可在线性时间扫描，总时间仍为 O(n log n)。需要特别处理 j=i 的长区间，避免从空窗口中扣减长度。前缀和 + 二分更容易直接对应计数公式。

逐块展开会依赖最高 10⁹ 的坐标，空间和时间不可接受；每个起点重新扫描所有段则会退化为 O(n²)。

JavaScript

/**
 * @param {number[][]} tiles
 * @param {number} carpetLen
 * @return {number}
 */
var maximumWhiteTiles = function(tiles, carpetLen) {
    tiles.sort((a, b) => a[0] - b[0]);
    const n = tiles.length;
    const prefix = Array(n + 1).fill(0);
    for (let i = 0; i < n; i++)
        prefix[i + 1] = prefix[i] + tiles[i][1] - tiles[i][0] + 1;
    let answer = 0;
    for (let i = 0; i < n; i++) {
        const end = tiles[i][0] + carpetLen - 1;
        let lo = i, hi = n;
        while (lo < hi) {
            const mid = Math.floor((lo + hi) / 2);
            if (tiles[mid][1] <= end) lo = mid + 1;
            else hi = mid;
        }
        const j = lo;
        const partial = j < n ? Math.max(0, end - tiles[j][0] + 1) : 0;
        answer = Math.max(answer, prefix[j] - prefix[i] + partial);
    }
    return answer;
};

class Solution {

        }
        return (int) answer;
    }
}

Python

from typing import List
from bisect import bisect_right

class Solution:
    def maximumWhiteTiles(self, tiles: List[List[int]], carpetLen: int) -> int:
        tiles.sort()
        ends = [r for _, r in tiles]
        prefix = [0]
        for l, r in tiles:
            prefix.append(prefix[-1] + r - l + 1)
        answer = 0
        for i, (start, _) in enumerate(tiles):
            end = start + carpetLen - 1
            j = bisect_right(ends, end, lo=i)
            partial = max(0, end - tiles[j][0] + 1) if j < len(tiles) else 0
            answer = max(answer, prefix[j] - prefix[i] + partial)
        return answer

常见错误

  • 闭区间长度写成 r−l，或毯子右端写成 start+carpetLen，导致差一错误。
  • 二分左端点却套用完整段前缀和公式，错误把最后一段全部计入。
  • 未排序就二分，或忽略不重叠这个必要前提。
  • 直接用 E−start+1 作为白砖数，错误计入空隙。
  • 混淆前缀和下标：prefix[j] 对应前 j 段，即 0 至 j−1。

面试追问

为什么右端点有序？
左端有序且不重叠意味着 rᵢ < lᵢ₊₁ ≤ rᵢ₊₁，所以右端点严格递增。

输入允许重叠怎么办？
先排序并合并重叠区间，避免重复计数，并恢复二分所需的单调性。

怎样返回具体放置位置？
更新最大覆盖数时同时记录 lᵢ；并列时可以保留最左起点。

两块毯子能直接把答案乘二吗？
不能，覆盖区域可能重叠。需另外考虑两次放置之间的关系；单块毯子的最优值不足以决定结果。
