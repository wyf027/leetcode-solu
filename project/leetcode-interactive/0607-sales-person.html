607. 销售员

从三张关系表中找出符合业务条件的销售人员。先读懂数据关系，再亲手沿着订单链路排除不符合条件的人。

01 / Statement

题目要你找什么？

给定销售员、公司和订单三张表，返回所有从未产生过与公司名为 “RED” 相关订单的销售员姓名。结果可以按任意顺序返回。

注意量词：条件是“没有任何 RED 订单”。只要某位销售员存在一笔 RED 订单，即使同时服务过其他公司，也不能出现在结果中。

准备好看完整题解了吗？

题解独立收起，先自行写出查询，再展开核对核心机制、证明与代码。

反连接：保留“不存在”的人

最直接的表达是相关子查询 NOT EXISTS：对每位销售员询问，“是否不存在一笔由他负责、且公司名为 RED 的订单？”

核心洞察

本题不是找“有非 RED 订单”的人，而是找“不存在 RED 订单”的人。这是典型反连接语义。将当前销售员的 sales_id 关联到订单，再关联公司名；如果内层找不到行，外层销售员就应保留。

完整过程

  1. 外层遍历 SalesPerson，当前行为 sp。
  2. 内层连接 Orders 与 Company。
  3. 只检查同时满足 o.sales_id = sp.sales_id 与 c.name = 'RED' 的行。
  4. NOT EXISTS 在内层结果为空时为真，输出 sp.name。

复杂度

逻辑扫描
O(S + C + O)
辅助集合
O(R)

这是将 RED 公司和订单物化为集合时的抽象复杂度；数据库优化器可用连接计划与索引避免逐行全表扫描。S/C/O 分别为三表行数，R 为 RED 订单涉及的不同销售员数。

建议索引

Company(name, com_id)、Orders(sales_id, com_id) 可支持公司定位与相关条件。是否新增索引仍应依据真实数据分布和执行计划。

正确性证明

1

若某销售员被输出，则其相关子查询不存在结果，所以不存在同时关联该销售员与 RED 公司的订单；他满足题意。

2

若某销售员满足题意，则没有任何 RED 订单能通过内层连接与筛选，相关子查询为空，NOT EXISTS 为真，因此他一定被输出。

∎

由充分性与必要性，查询输出恰好是所有没有 RED 订单的销售员。

边界情况

  • 完全没有订单：所有销售员都应返回。
  • 没有名为 RED 的公司：内层对所有人都为空，所有销售员返回。
  • 同一销售员有多笔 RED 订单：仍只排除一次，不影响语义。
  • 销售员只有其他公司订单：仍应返回。
  • 一人兼有 RED 与非 RED 订单：必须排除，不能因非 RED 订单而保留。

MySQL · 官方可提交NOT EXISTS
SELECT sp.name
FROM SalesPerson AS sp
WHERE NOT EXISTS (
    SELECT 1
    FROM Orders AS o
    JOIN Company AS c
      ON c.com_id = o.com_id
    WHERE o.sales_id = sp.sales_id
      AND c.name = 'RED'
);

import java.util.*;

public class SalesPersonFilter {
    record SalesPerson(int salesId, String name) {}
    record Company(int companyId, String name) {}
    record Order(int companyId, int salesId) {}

    static List<String> salesPerson(
            List<SalesPerson> people,
            List<Company> companies,
            List<Order> orders) {
        Set<Integer> redCompanyIds = new HashSet<>();
        for (Company company : companies) {
            if (company.name().equals("RED")) {
                redCompanyIds.add(company.companyId());
            }
        }

        Set<Integer> blockedSalesIds = new HashSet<>();
        for (Order order : orders) {
            if (redCompanyIds.contains(order.companyId())) {
                blockedSalesIds.add(order.salesId());
            }
        }

        List<String> answer = new ArrayList<>();
        for (SalesPerson person : people) {
            if (!blockedSalesIds.contains(person.salesId())) {
                answer.add(person.name());
            }
        }
        return answer;
    }

    public static void main(String[] args) {
        List<SalesPerson> people = List.of(
            new SalesPerson(1, "John"), new SalesPerson(2, "Amy"),
            new SalesPerson(3, "Mark"), new SalesPerson(4, "Pam"),
            new SalesPerson(5, "Alex")
        );
        List<Company> companies = List.of(
            new Company(1, "RED"), new Company(2, "ORANGE"),
            new Company(3, "YELLOW"), new Company(4, "GREEN")
        );
        List<Order> orders = List.of(
            new Order(3, 4), new Order(4, 5),
            new Order(1, 1), new Order(1, 4)
        );
        System.out.println(salesPerson(people, companies, orders));
    }
}

'use strict';

function salesPerson(people, companies, orders) {
  const redCompanyIds = new Set(
    companies.filter((company) => company.name === 'RED')
      .map((company) => company.comId)
  );
  const blockedSalesIds = new Set(
    orders.filter((order) => redCompanyIds.has(order.comId))
      .map((order) => order.salesId)
  );
  return people
    .filter((person) => !blockedSalesIds.has(person.salesId))
    .map((person) => person.name);
}

from dataclasses import dataclass

@dataclass(frozen=True)
class SalesPerson:
    sales_id: int
    name: str

@dataclass(frozen=True)
class Company:
    com_id: int
    name: str

@dataclass(frozen=True)
class Order:
    com_id: int
    sales_id: int

def sales_person(people, companies, orders):
    red_company_ids = {
        company.com_id for company in companies
        if company.name == "RED"
    }
    blocked_sales_ids = {
        order.sales_id for order in orders
        if order.com_id in red_company_ids
    }
    return [
        person.name for person in people
        if person.sales_id not in blocked_sales_ids
    ]

#include <iostream>
#include <string>
#include <unordered_set>
#include <vector>
using namespace std;

struct SalesPerson { int salesId; string name; };
struct Company { int companyId; string name; };
struct Order { int companyId; int salesId; };

vector<string> salesPerson(
    const vector<SalesPerson>& people,
    const vector<Company>& companies,
    const vector<Order>& orders) {
  unordered_set<int> redCompanyIds;
  for (const auto& company : companies) {
    if (company.name == "RED") {
      redCompanyIds.insert(company.companyId);
    }
  }

  unordered_set<int> blockedSalesIds;
  for (const auto& order : orders) {
    if (redCompanyIds.contains(order.companyId)) {
      blockedSalesIds.insert(order.salesId);
    }
  }

  vector<string> answer;
  for (const auto& person : people) {
    if (!blockedSalesIds.contains(person.salesId)) {
      answer.push_back(person.name);
    }
  }
  return answer;
}

int main() {
  vector<SalesPerson> people = {
    {1, "John"}, {2, "Amy"}, {3, "Mark"},
    {4, "Pam"}, {5, "Alex"}
  };
  vector<Company> companies = {
    {1, "RED"}, {2, "ORANGE"},
    {3, "YELLOW"}, {4, "GREEN"}
  };
  vector<Order> orders = {{3, 4}, {4, 5}, {1, 1}, {1, 4}};
  for (const auto& name : salesPerson(people, companies, orders)) {
    cout << name << '\n';
  }
  return 0;
}

替代方案

LEFT JOIN + IS NULL

先得到所有与 RED 关联的销售员，再左连接回 SalesPerson，保留连接结果为空的行。写法可行，但连接层级更长，需谨慎放置筛选条件。

NOT IN

也可以排除子查询返回的 sales_id。本题外键约束降低了空值风险，但通用 SQL 中子查询若含 NULL，NOT IN 会受三值逻辑影响；NOT EXISTS 通常更稳健、语义也更贴题。

面试追问

为什么不筛选 c.name != 'RED'？那会保留拥有非 RED 订单的人，即使他同时也有 RED 订单，违反“不存在任何”的要求。
如果公司名不唯一怎么办？当前结构只声明 com_id 唯一，查询按名称匹配所有 RED 公司，语义仍正确。
如何确认性能？查看执行计划、基数估计和实际扫描行数，再结合数据分布决定索引，而不是仅凭 SQL 外观判断。

常见错误

把“没有 RED”写成“有非 RED”两者不是等价命题，兼有两类订单的人会被错误保留。
漏掉没有任何订单的人从 Orders 作为主表出发通常会天然丢失这些销售员。
在 WHERE 中破坏 LEFT JOIN对右表字段直接加普通 WHERE 条件，可能把外连接意外变成内连接。

记忆锚点

看到“没有任何”“从未”“不存在”时，先考虑反连接：

  • 外层是完整候选集。
  • 内层描述禁止出现的证据。
  • NOT EXISTS 保留找不到禁止证据的候选。

一句话模板：保留不存在违规关联行的主体。
