Zigzag Iterator

把两个不同长度的序列看成两条轨道：每次从当前轨道取一个值，再把机会交给仍有元素的另一条轨道。

Problem

题意

给定两个整数向量 v1 和 v2，实现一个迭代器，使它按两条向量交替的顺序返回元素。某条向量耗尽后，继续返回另一条向量中的剩余元素。

实现 ZigzagIterator：

  • ZigzagIterator(v1, v2)：用两个整数向量初始化迭代器。
  • next()：返回当前应输出的整数，并推进迭代状态。调用方只会在仍有元素时调用它。
  • hasNext()：如果仍存在尚未返回的元素，返回 true；否则返回 false。

进阶：如果输入扩展为 k 个向量，如何让遍历保持循环轮转，并让代码自然扩展？

Solution

队列保存“仍然活跃的游标”

核心洞察：队列里不放所有元素，只放仍有剩余值的迭代器（或“数组 + 下一下标”游标）。队首取一个值；若还有剩余，就回到队尾。

这样，队列的顺序本身就是下一轮访问顺序。空向量从不入队，耗尽的向量不再回队，因此 hasNext() 只需判断队列是否非空。它也天然从两个向量扩展到 k 个向量。

完整过程

1
初始化：按输入顺序检查 v1、v2；只把非空向量的起始游标放入队列。
2
取值：next() 弹出队首游标，读取它指向的值，再把游标推进一格。
3
轮转：推进后若该向量还有元素，把更新后的游标压回队尾；否则永久移除。
4
结束：队列为空时，说明每个向量都已耗尽，hasNext() 返回 false。

正确性证明

不变式：每次调用 next() 前，队列恰好包含所有未耗尽向量的游标，而且从队首到队尾的顺序就是它们下一次应被访问的循环顺序。

初始化成立：每个非空向量以起始游标按输入顺序入队；空向量没有可返回元素，不入队。因此不变式成立。

保持：弹出队首会选择循环顺序中当前应访问的向量，并返回该向量尚未使用的最前元素。若它仍未耗尽，将更新后的游标放到队尾，恰好排在其他活跃向量之后；若已耗尽则不再入队。队列仍恰好包含所有未耗尽向量，并保持下一轮顺序。

终止：每次 next() 都且只消耗一个元素。有限个元素全部消耗后队列为空；在此之前至少一个游标仍在队列中。因此算法不重不漏，并按要求交替返回所有元素。

边界与复杂度

边界处理

  • 某个向量为空：初始化时跳过，另一个向量连续输出。
  • 长度不同：较短向量耗尽后不再回队，较长向量继续输出。
  • 负数、零与整数极值：仅搬运值，不做算术，不受符号影响。
  • next() 的前置条件：调用者先确认 hasNext()。

复杂度

  • 构造：两个向量时 O(1)；推广到 k 个向量时 O(k)。
  • next()：每次 O(1)。
  • hasNext()：O(1)。
  • 额外空间：两个向量为 O(1)，k 个向量为 O(k)；不计输入本身。

四语言完整代码

四份实现都采用同一个活跃游标队列思路。使用下方标签切换；代码容器可独立横向和纵向滚动。

Java · LeetCode 提交形式
import java.util.ArrayDeque;
import java.util.Deque;
import java.util.Iterator;
import java.util.List;

public class ZigzagIterator {
    private final Deque<Iterator<Integer>> queue = new ArrayDeque<>();

    public ZigzagIterator(List<Integer> v1, List<Integer> v2) {
        addIfActive(v1);
        addIfActive(v2);
    }

    private void addIfActive(List<Integer> values) {
        Iterator<Integer> iterator = values.iterator();
        if (iterator.hasNext()) {
            queue.offerLast(iterator);
        }
    }

    public int next() {
        Iterator<Integer> iterator = queue.pollFirst();
        int value = iterator.next();

        if (iterator.hasNext()) {
            queue.offerLast(iterator);
        }
        return value;
    }

    public boolean hasNext() {
        return !queue.isEmpty();
    }
}

JavaScript · LeetCode 提交形式
/**
 * @param {number[]} v1
 * @param {number[]} v2
 */
var ZigzagIterator = function (v1, v2) {
    this.queue = [];

    if (v1.length > 0) {
        this.queue.push({ values: v1, index: 0 });
    }
    if (v2.length > 0) {
        this.queue.push({ values: v2, index: 0 });
    }
};

/**
 * @return {number}
 */
ZigzagIterator.prototype.next = function () {
    const cursor = this.queue.shift();
    const value = cursor.values[cursor.index];
    cursor.index += 1;

    if (cursor.index < cursor.values.length) {
        this.queue.push(cursor);
    }
    return value;
};

/**
 * @return {boolean}
 */
ZigzagIterator.prototype.hasNext = function () {
    return this.queue.length > 0;
};

/**
 * const iterator = new ZigzagIterator(v1, v2);
 * while (iterator.hasNext()) {
 *     result.push(iterator.next());
 * }
 */
Python · LeetCode 提交形式
from collections import deque
from typing import Deque, List, Tuple


class ZigzagIterator:
    def __init__(self, v1: List[int], v2: List[int]):
        self.queue: Deque[Tuple[List[int], int]] = deque()

        if v1:
            self.queue.append((v1, 0))
        if v2:
            self.queue.append((v2, 0))

    def next(self) -> int:
        values, index = self.queue.popleft()
        value = values[index]
        index += 1

        if index < len(values):
            self.queue.append((values, index))
        return value

    def hasNext(self) -> bool:
        return bool(self.queue)

C++ · LeetCode 提交形式
#include <deque>
#include <utility>
#include <vector>

using std::deque;
using std::pair;
using std::vector;

class ZigzagIterator {
private:
    using Cursor = pair<vector<int>::iterator,
                        vector<int>::iterator>;
    deque<Cursor> queue;

    void addIfActive(vector<int>& values) {
        if (!values.empty()) {
            queue.push_back({values.begin(), values.end()});
        }
    }

public:
    ZigzagIterator(vector<int>& v1, vector<int>& v2) {
        addIfActive(v1);
        addIfActive(v2);
    }

    int next() {
        Cursor cursor = queue.front();
        queue.pop_front();

        int value = *cursor.first;
        ++cursor.first;
        if (cursor.first != cursor.second) {
            queue.push_back(cursor);
        }
        return value;
    }

    bool hasNext() {
        return !queue.empty();
    }
};

替代方案

双下标 + turn 标记：保存 i、j 和当前轮次。对两个向量可做到常数空间，但每次必须处理“当前向量已耗尽则跳转”的分支，推广到 k 个向量时还要扫描空向量，最坏单次调用可退化。

预先合并：构造时把答案全部写进新数组，随后只移动一个下标。实现直观，但构造需要 O(n) 时间和额外空间，失去迭代器按需消费的优势，也不适合超大或惰性输入。

为什么优先队列不合适：题目需要固定循环顺序，不需要按数值或时间比较优先级；普通双端队列更直接，常数也更小。

面试追问

  • 推广到 k 个向量时，只需依次把每个非空游标入队，核心逻辑不变。
  • 如果支持无限流，队列方案仍可惰性消费，但必须讨论终止语义与阻塞读取。
  • 如果调用 next() 时为空，是抛异常、返回哨兵，还是使用可选值？接口契约要明确。
  • 输入集合在遍历期间被修改时，迭代器应快速失败、复制快照，还是容忍弱一致性？
  • 多线程共享一个迭代器时，队列操作与游标推进必须作为同一临界区。

常见错误

  • 把空向量也入队，导致第一次读取就越界。
  • 取值后无条件回队，使已耗尽游标再次被访问。
  • 用固定奇偶决定来源，没处理某条向量提前耗尽。
  • hasNext() 扫描或修改复杂状态，使它不再是稳定的只读判断。
  • 为方便实现而复制全部元素，忽略迭代器应具备的惰性特征。
