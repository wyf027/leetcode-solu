Problem

题目说明

给定一个按严格升序排列的正整数数组 arr，以及正整数 k。返回没有出现在数组中的正整数里，按从小到大排列后的第 k 个。

findKthPositive(arr: integer[], k: integer) → integer
1官方示例
输入arr = [2,3,4,7,11], k = 5 输出9 解释缺失序列为 [1,5,6,8,9,10,12,...]，第 5 个是 9。
2官方示例
输入arr = [1,2,3,4], k = 2 输出6 解释缺失序列从 5 开始，第 2 个是 6。

约束

  • 1 ≤ arr.length ≤ 1000
  • 1 ≤ arr[i] ≤ 1000
  • 1 ≤ k ≤ 1000
  • 对所有 1 ≤ i < j ≤ arr.length，满足 arr[i] < arr[j]。

Solution

寻找第一个“缺得够多”的位置

核心洞察

若数组从 1 开始且没有缺失，下标 i（从 0 开始）本应放着 i + 1。实际值是 arr[i]，两者的差就是到该位置为止缺失的正整数个数：

missing(i) = arr[i] - (i + 1)

arr 严格递增，所以 missing(i) 单调不减。我们二分寻找第一个满足 missing(i) ≥ k 的下标 left。

完整过程

  1. 令 left = 0, right = n，搜索半开区间。
  2. 计算 mid 及 arr[mid] - mid - 1。
  3. 若缺失数少于 k，令 left = mid + 1；否则令 right = mid。
  4. 边界重合后返回 left + k。

复杂度

时间：O(log n)

空间：O(1)

为什么答案是 left + k？

1

搜索结束时，前 left 个数组元素都位于答案之前。

2

在从 1 到答案的所有数里，有 left 个存在于数组，另有 k 个缺失。

3

因此该范围共有 left + k 个正整数，末端也就是答案。

边界与特殊情况

  • 答案在数组第一个元素之前：left = 0，直接得到 k。
  • 答案在数组末尾之后：left = n，答案为 n + k。
  • 缺失数量出现平台：单调不要求严格递增，二分仍然成立。
  • k 很大：无需真的生成缺失序列。

替代方案

线性修正：从 answer = k 开始扫描；每遇到 arr[i] ≤ answer 就把答案加一。时间 O(n)，空间 O(1)，更直观但没有满足进阶要求。

逐个枚举：用集合判断每个正整数是否缺失，时间依赖答案大小且需要额外空间，不推荐。

四种语言完整实现

Java官方签名
class Solution {
    public int findKthPositive(int[] arr, int k) {
        int left = 0;
        int right = arr.length;

        while (left < right) {
            int mid = left + (right - left) / 2;
            int missing = arr[mid] - mid - 1;

            if (missing < k) {
                left = mid + 1;
            } else {
                right = mid;
            }
        }

        return left + k;
    }
}

面试追问与常见错误

为什么搜索区间是 [0, n)？

答案可能落在最后一个数组元素之后，此时合法边界是 n。半开区间能自然容纳这个结果，不需要单独分支。

如果数组不是严格递增呢？

重复值会破坏题目定义下的计数关系。需要先澄清输入契约，或去重排序后再使用该公式；后者会改变复杂度。

常见错误：写成 arr[i] - i

下标从 0 开始，而无缺失时下标 i 的理想值是 i + 1，因此应减去 i + 1。

常见错误：返回 arr[left] + k

left 表示答案之前已有多少个数组元素；计数恒等式给出的是 left + k，不是基于某个数组值直接相加。
