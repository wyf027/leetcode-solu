卖木头块

Selling Pieces of Wood

一块木头，一张价目表。如何安排切割，才能把有限的面积卖出最多的钱？

先理解规则并思考。算法、交互推演与四语言代码收在页面底部。

打开官方题目 ↗
m × n

01题目与规则

给定整数 m 和 n，表示原始木块的高和宽；数组 prices 的每一项 [hᵢ, wᵢ, priceᵢ] 表示一块高 hᵢ、宽 wᵢ 的木块可以卖 priceᵢ 元。返回原始木块能够获得的最大总收入。

一刀分成两块
可以横切或竖切，但必须贯穿当前整块木头；得到两块矩形后，可继续切任意次，也可以不切。
方向固定，销售不限量
不能旋转木块交换高宽；同一种尺寸可卖多块，剩余木块也可以不卖。

参数约束

  • 1 ≤ m, n ≤ 200
  • 1 ≤ prices.length ≤ 2 × 10⁴，每项恰好包含 3 个整数。
  • 1 ≤ hᵢ ≤ m，1 ≤ wᵢ ≤ n。
  • 1 ≤ priceᵢ ≤ 10⁶。
  • 价目表中的所有 (hᵢ, wᵢ) 两两不同。

02官方示例

示例 1

m = 3
n = 5
prices = [[1,4,2],[2,2,7],[2,1,3]]
输出：19

可售出两块 2 × 2、一块 2 × 1 和一块 1 × 4，收入为 2 × 7 + 3 + 2 = 19。剩余 1 × 1 不卖。

示例 2

m = 4
n = 6
prices = [[3,2,10],[1,4,2],[4,1,3]]
输出：32

可售出三块 3 × 2 和一块 1 × 4，收入为 3 × 10 + 2 = 32。1 × 4 与 4 × 1 是不同尺寸，不能互换报价。

04题解 · 让每个矩形都拥有最优报价

核心洞察

观察最先发生的一刀：它把整块问题分成两个互不影响的小矩形。一个尺寸的最优收入只依赖其高和宽，与它在原木中的位置无关。因此记录 dp[h][w]：高为 h、宽为 w 的木块最多能卖多少钱。

dp[h][w] = max(
　price[h][w]（无报价为 0）,
　dp[k][w] + dp[h-k][w]，1 ≤ k ≤ ⌊h/2⌋,
　dp[h][k] + dp[h][w-k]，1 ≤ k ≤ ⌊w/2⌋
)

切在 k 与切在 h − k（或 w − k）得到同一对尺寸，只是顺序相反，所以每个方向只枚举一半。这里没有旋转任何木块。

切割实验室 · 看一刀怎样更新收益

完整过程
  1. 建立大小为 (m+1) × (n+1) 的全零表，把每条报价放在对应尺寸上。没有报价可选择丢弃，收入为 0。
  2. 从高 1 到 m、宽 1 到 n 遍历。整块出售的收入已经在表中。
  3. 枚举横切位置 k，尝试 dp[k][w] + dp[h-k][w]；两个子块高度都更小，已经算好。
  4. 枚举竖切位置 k，尝试 dp[h][k] + dp[h][w-k]；高度相同但宽度更小，也已经算好。
  5. 每次仅保留更大收入，最终返回 dp[m][n]。
示例 1 中，1 × 5 的最佳收入为 2，2 × 5 可以由两个 2 × 2 和一个 2 × 1 得到 17。将 3 × 5 横切为 1 × 5 与 2 × 5，合计 19；遍历所有第一刀候选后取最大值，才能确定它最优。


正确性证明
对木块面积作归纳。对于 1 × 1，无法切割，只能直接出售或丢弃，初始化恰好给出最优值。假设所有更小面积的状态都正确。
任取 h × w 的一个合法方案。若没有切割，收入不超过直接报价与 0 的最大值。若切割，其第一刀必定横向或纵向贯穿，得到两个面积更小的矩形。按归纳假设，两块后续收入分别不超过对应 dp 值，所以方案收入不超过转移枚举到的候选值。
反过来，直接出售或丢弃都是合法操作；任意转移候选也可以先完成对应一刀，再对两块实施各自最优方案，实际取得该收入。因此转移既不遗漏最优方案，也不引入无法实现的收入。归纳成立，返回值就是答案。


边界与数值范围
  • h = 1 时没有横切，w = 1 时没有竖切；两个循环自然跳过。
  • 某个子尺寸没有报价，仍可能切成有报价的小块；不能直接判它收入为 0 并停止。
  • 整块出售可能最好，不强制切割；不可售出的余料可以丢弃。
  • 同一尺寸不限销售数量，不要把价格项当作只能选择一次的商品。
  • 最多 40,000 块单位木块，每块价格至多 10⁶，因此答案上界为 4 × 10¹⁰。Java 用 long，C++ 用 long long；Python 整数可直接使用；JavaScript Number 的安全整数范围足够，不应使用位运算保存收入。


复杂度
设 P 为报价条数。初始化 O(P + mn)，转移时间 O(P + mn(m+n))，辅助空间 O(mn)。只枚举一半切点降低常数，不改变数量级。所有代码采用同一转移。


四语言完整代码

Java
class Solution {
    public long sellingWood(int m, int n, int[][] prices) {
        long[][] dp = new long[m + 1][n + 1];
        for (int[] p : prices) {
            dp[p[0]][p[1]] = p[2];
        }
        for (int h = 1; h <= m; h++) {
            for (int w = 1; w <= n; w++) {
                for (int k = 1; k <= h / 2; k++) {
                    dp[h][w] = Math.max(dp[h][w],
                        dp[k][w] + dp[h - k][w]);
                }
                for (int k = 1; k <= w / 2; k++) {
                    dp[h][w] = Math.max(dp[h][w],
                        dp[h][k] + dp[h][w - k]);
                }
            }
        }
        return dp[m][n];
    }
}

var sellingWood = function(m, n, prices) {
    const dp = Array.from({length: m + 1},
        () => Array(n + 1).fill(0));
    for (const [h, w, price] of prices) {
        dp[h][w] = price;
    }
    for (let h = 1; h <= m; h++) {
        for (let w = 1; w <= n; w++) {
            for (let k = 1; k <= Math.floor(h / 2); k++) {
                dp[h][w] = Math.max(dp[h][w],
                    dp[k][w] + dp[h - k][w]);
            }
            for (let k = 1; k <= Math.floor(w / 2); k++) {
                dp[h][w] = Math.max(dp[h][w],
                    dp[h][k] + dp[h][w - k]);
            }
        }
    }
    return dp[m][n];
};


Python 3
from typing import List

class Solution:
    def sellingWood(self, m: int, n: int,
                    prices: List[List[int]]) -> int:
        dp = [[0] * (n + 1) for _ in range(m + 1)]
        for h, w, price in prices:
            dp[h][w] = price
        for h in range(1, m + 1):
            for w in range(1, n + 1):
                for k in range(1, h // 2 + 1):
                    dp[h][w] = max(dp[h][w],
                                   dp[k][w] + dp[h - k][w])
                for k in range(1, w // 2 + 1):
                    dp[h][w] = max(dp[h][w],
                                   dp[h][k] + dp[h][w - k])
        return dp[m][n]

#include <algorithm>
#include <vector>
using namespace std;

class Solution {
public:
    long long sellingWood(int m, int n,
                          vector<vector<int>>& prices) {
        vector<vector<long long>> dp(
            m + 1, vector<long long>(n + 1, 0));
        for (const auto& p : prices) {
            dp[p[0]][p[1]] = p[2];
        }
        for (int h = 1; h <= m; ++h) {
            for (int w = 1; w <= n; ++w) {
                for (int k = 1; k <= h / 2; ++k) {
                    dp[h][w] = max(dp[h][w],
                        dp[k][w] + dp[h - k][w]);
                }
                for (int k = 1; k <= w / 2; ++k) {
                    dp[h][w] = max(dp[h][w],
                        dp[h][k] + dp[h][w - k]);
                }
            }
        }
        return dp[m][n];
    }
};




替代方案
记忆化搜索：递归函数 f(h,w) 按同一公式求解，缓存每个尺寸；最坏时间、空间与二维动态规划同阶，另有最坏 O(m+n) 递归栈。自底向上写法更直接，不受递归深度影响。
不缓存的递归：相同尺寸会反复求解，产生大量重复分支，不适合本题范围。按单价或单位面积价值贪心：忽略剩料的形状和后续可切性，无法保证最优。


常见错误
  • 同时写入 dp[h][w] 和 dp[w][h]：违反禁止旋转的规则，且可能越界。
  • 只考虑价目表上的尺寸：中间尺寸未必能直接卖，却可能承载最优切法。
  • 状态从大到小填：读取了尚未完成的子问题。
  • 把二维数组的同一行重复引用：JavaScript 必须用 Array.from 创建独立行；Python 必须使用列表推导式。
  • 用 32 位整型存总收入：会溢出。
  • 只贪心选最贵木块：例如 2 × 2 报价 7、1 × 1 报价 2，四个小块可以得到 8。


面试追问
  • 怎样恢复切割方案？为每个状态记录整售、横切 k 或竖切 k，再从 (m,n) 递归输出对应操作。
  • 每切一刀收取固定费用 c？把每个切割候选改为两个子状态之和减 c，仍保留不切与丢弃的候选。
  • 如果允许旋转？报价初始化时将反向尺寸也纳入合法范围内的状态；原题不可这样做。
  • 每种尺寸限售一块还能直接相加吗？不能，两个子块会争抢同一销售额度，需要额外记录额度，当前二维状态不再充分。
  • 为什么不做一维滚动数组？横切会同时访问多种历史高度，通常不能仅保留上一行；保留二维表更清楚可靠。
