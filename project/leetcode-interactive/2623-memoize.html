LeetCode 2623 MEDIUM

记忆函数
Memoize

让函数记住已经处理过的参数：相同输入再次出现时，直接返回先前结果，不再调用原函数。

函数与闭包 缓存行为 非付费题

Problem

题意

给定函数 fn，返回它的记忆化版本。对完全相同的一组输入，原函数最多执行一次；之后应直接返回缓存值。

输入函数只会是以下三类之一：

  • sum(a, b) 返回 a + b。参数顺序属于输入的一部分，因此 (3, 2) 与 (2, 3) 必须分别计算。
  • fib(n)：当 n <= 1 时返回 1，否则返回 fib(n - 1) + fib(n - 2)。
  • factorial(n)：当 n <= 1 时返回 1，否则返回 factorial(n - 1) * n。

函数签名

function memoize(fn) {
  return function (...args) {
    // 返回缓存值或执行 fn
  };
}

Limits

约束

  • 0 <= a, b <= 105
  • 1 <= n <= 10
  • 1 <= actions.length <= 105
  • actions.length === values.length
  • actions[i] 只能是 "call" 或 "getCallCount"
  • fnName 只能是 "sum"、"factorial" 或 "fib"

关键语义

“相同输入”要求参数数量、顺序和值都相同。

Official examples

官方示例

每个示例保留完整的 fnName、actions 与 values 参数形式。

示例 1 · sum

输入：
fnName = "sum"
actions = ["call","call","getCallCount",
           "call","getCallCount"]
values = [[2,2],[2,2],[],[1,2],[]]

输出：[4,4,1,3,2]

第二次 (2,2) 命中缓存；(1,2) 是新输入，原函数总调用数最终为 2。

示例 2 · factorial

输入：
fnName = "factorial"
actions = ["call","call","call",
           "getCallCount","call",
           "getCallCount"]
values = [[2],[3],[2],[],[3],[]]

输出：[2,6,2,2,6,2]

2 与 3 各只触发一次原函数，后续两次调用均复用对应结果。

示例 3 · fib

输入：
fnName = "fib"
actions = ["call","getCallCount"]
values = [[5],[]]

输出：[8,1]

外层记忆函数仅接收一次 fib(5) 调用，因此被包装的原函数调用计数为 1。

Solution

题解：用闭包保留参数缓存

核心洞察

每次调用时，把完整参数列表转换为稳定且保序的键。若键已存在，就返回缓存结果；否则执行原函数并保存结果。缓存定义在外层函数中，返回的闭包可在多次调用之间持续访问它。

完整过程

  1. 在 memoize(fn) 内创建一个空缓存。
  2. 返回一个接收任意数量参数的包装函数。
  3. 将 args 序列化为键；数组序列化保留元素顺序，所以 [3,2] 与 [2,3] 不会混淆。
  4. 先判断键是否存在。存在就直接返回缓存值，不能只用真假值判断，因为结果可能为 0。
  5. 未命中时以原上下文执行 fn，缓存结果并返回。

正确性

首次出现：键不在缓存中，包装函数调用 fn，保存并返回正确结果。

再次出现：完全相同的参数产生同一键，包装函数返回首次保存的结果，不再执行 fn。

不同输入：不同的参数序列产生不同键，分别计算并存储。因此每组输入最多调用一次原函数，且所有返回值都与直接调用 fn 一致。

复杂度

设一次调用有 k 个参数，序列化键需要 O(k) 时间与临时空间；缓存查询平均为 O(1)。若出现 m 组不同输入，缓存占用 O(m · k) 空间，不计结果对象自身大小。

本题参数都是数字，因此 JSON 序列化可安全地区分题目允许的参数序列。

边界情况

结果为 0

使用 cache.has(key)，不能把缓存值的真假当作是否命中。

参数顺序

[a,b] 与 [b,a] 必须生成不同键，即使结果刚好相同。

调用上下文

JavaScript 用 fn.apply(this, args) 保留调用者的 this。

四语言实现

官方可提交语言实现。
/**
 * @param {Function} fn
 * @return {Function}
 */
function memoize(fn) {
  const cache = new Map();

  return function (...args) {
    const key = JSON.stringify(args);
    if (cache.has(key)) return cache.get(key);

    const result = fn.apply(this, args);
    cache.set(key, result);
    return result;
  };
}

import java.util.HashMap;
import java.util.List;
import java.util.Map;
import java.util.function.Function;

public final class Memoizer {
    private Memoizer() {}

    public static <R> Function<List<Integer>, R> memoize(
            Function<List<Integer>, R> fn) {
        Map<List<Integer>, R> cache = new HashMap<>();

        return args -> {
            List<Integer> key = List.copyOf(args);
            if (cache.containsKey(key)) return cache.get(key);

            R result = fn.apply(key);
            cache.put(key, result);
            return result;
        };
    }
}

from functools import wraps
from typing import Callable


def memoize(fn: Callable) -> Callable:
    cache: dict[tuple, object] = {}

    @wraps(fn)
    def wrapped(*args):
        if args in cache:
            return cache[args]

        result = fn(*args)
        cache[args] = result
        return result

    return wrapped

#include <cstddef>
#include <functional>
#include <unordered_map>
#include <utility>
#include <vector>

struct VectorHash {
    std::size_t operator()(const std::vector<int>& values) const {
        std::size_t seed = values.size();
        for (int value : values) {
            seed ^= std::hash<int>{}(value) + 0x9e3779b9
                    + (seed << 6) + (seed >> 2);
        }
        return seed;
    }
};

template <class Fn>
auto memoize(Fn fn) {
    using Result = std::invoke_result_t<Fn, const std::vector<int>&>;
    return [fn = std::move(fn),
            cache = std::unordered_map<std::vector<int>, Result, VectorHash>{}]
           (const std::vector<int>& args) mutable -> Result {
        if (auto it = cache.find(args); it != cache.end()) return it->second;
        Result result = std::invoke(fn, args);
        cache.emplace(args, result);
        return result;
    };
}

替代方案与取舍

嵌套 Map

每个参数作为一层 Map 的键，可支持对象引用并避免字符串序列化；但实现更长，还要用特殊标记区分“此处已有结果”。本题仅有数字参数，无此必要。

普通对象

也能用序列化后的字符串作属性名，但 Map 的键存在性检查更直接，也不会碰到原型属性问题。

面试追问

如果参数中包含对象怎么办？

JSON 字符串不一定能表达引用身份、循环结构或所有值类型。若按引用判等，可使用嵌套 Map / WeakMap；若按结构判等，则需要明确的稳定序列化规则。

如何限制缓存无限增长？

可以引入容量上限与 LRU 淘汰，或按业务需要增加 TTL。只有在缓存生命周期和压力明确后才值得加入。

异步函数失败时应缓存 Promise 吗？

可先缓存进行中的 Promise 来合并并发请求；若 Promise 被拒绝，通常应删除该条目，使后续调用可以重试。

常见错误

  • 只用参数和作为键，导致 (1,2) 与 (2,1) 冲突。
  • 写成 if (cache.get(key))，让值为 0 的缓存被当作未命中。
  • 把缓存声明在返回函数内部，导致每次调用都重新创建缓存。
  • 命中后仍然调用一次原函数，失去记忆化的意义。
  • 用箭头函数包装需要 this 的方法，意外丢失动态调用上下文。
