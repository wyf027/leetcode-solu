窥视迭代器

Peeking Iterator

在不破坏原有迭代器语义的前提下，增加一个能够“看一眼但不前进”的 peek() 操作。

开始读题 交互演示

Problem

题目描述

请设计一个包装现有整数迭代器的 PeekingIterator。除了保留原迭代器的 next() 与 hasNext() 行为外，它还需要支持 peek()：返回下一个元素，但不让使用者眼中的迭代位置前进。

实现以下完整接口：

  • PeekingIterator(Iterator<int> nums)：用给定的整数迭代器初始化对象。
  • int next()：返回下一个元素，并将迭代位置向后移动一位。
  • boolean hasNext()：仍有元素可返回时为 true，否则为 false。
  • int peek()：返回下一个元素，但不移动使用者可观察到的迭代位置。
接口说明：不同语言的构造器与 Iterator 定义可能不同，但底层迭代器都提供 next() 和 hasNext()。

官方示例 1

输入
["PeekingIterator", "next", "peek", "next", "next", "hasNext"]
[[[1, 2, 3]], [], [], [], [], []]

输出
[null, 1, 2, 2, 3, false]

解释
PeekingIterator peekingIterator = new PeekingIterator([1, 2, 3]);
peekingIterator.next();    // 返回 1，指针移动到 2
peekingIterator.peek();    // 返回 2，指针不移动
peekingIterator.next();    // 返回 2，指针移动到 3
peekingIterator.next();    // 返回 3，迭代结束
peekingIterator.hasNext(); // 返回 false

约束

  • 1 <= nums.length <= 1000
  • 1 <= nums[i] <= 1000
  • 所有对 next() 和 peek() 的调用均有效。
  • next()、hasNext() 与 peek() 合计最多调用 1000 次。

    Solution

    用一个前瞻缓存保存“偷看”的元素

    核心洞察：peek() 必须知道下一个值，却不能让调用者感知位置变化。我们可以从底层迭代器取出这个值，并把它放入一个单元素缓存；后续 peek() 重用缓存，后续 next() 消费缓存。
    1

    缓存为空时 peek

    调用底层 next() 一次，把结果放入缓存并返回。

    2

    缓存非空时 next

    返回缓存值并清空缓存，不再推进底层迭代器。

    3

    hasNext 的合并语义

    缓存有值或底层还有元素，调用者就仍有下一项。

    完整过程

    1. 保存底层 iterator、布尔变量 hasPeeked 和缓存值 peekedValue。
    2. peek()：若缓存为空，从底层取一项并标记缓存有效；返回缓存值。
    3. next()：若缓存有效，返回缓存并清空标记；否则直接调用底层 next()。
    4. hasNext()：返回 hasPeeked || iterator.hasNext()。

    边界情况

    • 连续多次 peek()：只第一次访问底层，返回值始终相同。
    • peek() 后紧接 next()：两次返回相同元素，底层总共仅推进一次。
    • 缓存保存了最后一个元素：即使底层已耗尽，hasNext() 仍应为 true。
    • 题目保证 peek() 与 next() 调用合法，无需定义越界返回值。

    正确性证明

    I

    不变式

    每次公开方法调用前，若缓存有效，缓存值就是调用者尚未消费的下一项；若缓存无效，调用者的下一项就是底层迭代器的下一项。

    P

    peek() 保持不变式

    缓存有效时直接返回它，不改变任何位置；缓存无效时，从底层取出下一项并存入缓存。该值仍未被调用者消费，因此它仍是调用者的下一项。

    N

    next() 保持不变式

    缓存有效时返回并清空它；底层已经指向再下一项。缓存无效时直接消费底层下一项。两种分支都恰好向调用者返回一项，并让下一项关系继续成立。

    H

    hasNext() 判断准确

    若缓存有效，至少有缓存项可供返回；否则是否存在下一项完全由底层 hasNext() 决定。因此返回两者的逻辑或恰好覆盖全部情况。

    时间复杂度

    O(1) / 次调用

    每个公开操作只执行常数次判断与底层调用。

    空间复杂度

    O(1)

    仅保存迭代器引用、一个标记和一个元素。

    四语言完整代码

    Java 
    import java.util.Iterator;

class PeekingIterator implements Iterator<Integer> {
    private final Iterator<Integer> iterator;
    private boolean hasPeeked;
    private Integer peekedValue;

    public PeekingIterator(Iterator<Integer> iterator) {
        this.iterator = iterator;
        this.hasPeeked = false;
    }

    public Integer peek() {
        if (!hasPeeked) {
            peekedValue = iterator.next();
            hasPeeked = true;
        }
        return peekedValue;
    }

    @Override
    public Integer next() {
        if (hasPeeked) {
            Integer result = peekedValue;
            hasPeeked = false;
            peekedValue = null;
            return result;
        }
        return iterator.next();
    }

    @Override
    public boolean hasNext() {
        return hasPeeked || iterator.hasNext();
    }
}

    Python 3 
    class PeekingIterator:
    def __init__(self, iterator):
        """
        :type iterator: Iterator
        """
        self.iterator = iterator
        self.has_peeked = False
        self.peeked_value = None

    def peek(self):
        """
        :rtype: int
        """
        if not self.has_peeked:
            self.peeked_value = self.iterator.next()
            self.has_peeked = True
        return self.peeked_value

    def next(self):
        """
        :rtype: int
        """
        if self.has_peeked:
            result = self.peeked_value
            self.has_peeked = False
            self.peeked_value = None
            return result
        return self.iterator.next()

    def hasNext(self):
        """
        :rtype: bool
        """
        return self.has_peeked or self.iterator.hasNext()

            hasPeeked = false;

    替代方案

    构造时预取：初始化就把第一项读入缓存，以后每次 next() 返回当前缓存并预取下一项。这同样能做到常数复杂度，状态甚至更紧凑；但构造器会立刻推进底层迭代器，且需要额外表示“缓存是否存在”。懒加载方案只在首次 peek() 时预取，更贴近最小副作用原则。

    泛型扩展

    把缓存类型从整数替换为类型参数 T 即可。例如 Java 使用 PeekingIterator<T> 与 Iterator<T>。缓存有效性必须由独立布尔值表示，不能用 null 判断，因为 null 本身可能是合法元素。

    面试追问

    如果需要 peek(k)？

    用双端队列缓存前 k 个元素，按需从底层补齐；空间变为 O(k)。

    底层元素允许为 null？

    必须保留独立的 hasPeeked 标记，不能把空值当作“没有缓存”。

    线程安全吗？

    当前实现不是。若多个线程共享实例，需要同步状态读写与底层迭代器调用。

    能否支持 remove？

    需明确 peek() 预取后 remove() 的语义；简单转发可能违反底层迭代器约定。

    常见错误

    • 每次 peek() 都调用底层 next()，导致连续窥视跳过元素。
    • next() 返回缓存后又调用一次底层 next()，造成双重推进。
    • hasNext() 只查询底层迭代器，忽略“底层已空但缓存还有最后一项”的状态。
    • 复制原数组并自行维护下标，违反题目只能通过迭代器接口工作的要求。
    • 用缓存值是否为 null 代替独立有效标记，使泛型版本无法保存合法空值。
