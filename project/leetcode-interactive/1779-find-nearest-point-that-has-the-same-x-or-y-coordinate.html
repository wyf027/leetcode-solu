找到最近的有相同 X 或 Y 坐标的点

Find Nearest Point That Has the Same X or Y Coordinate

简单免费题坐标 · 曼哈顿距离
Problem

题意

给定当前位置 (x, y)，以及点数组 points，其中 points[i] = [aᵢ, bᵢ]。

若某个点与当前位置拥有相同的 x 坐标或相同的 y 坐标，它就是有效点。请返回与当前位置曼哈顿距离最小的有效点下标（从 0 开始）。若距离相同，返回下标较小者；若不存在有效点，返回 -1。

distance = |x − aᵢ| + |y − bᵢ|

注意：点可以与当前位置完全重合，此时距离为 0。

Constraints

约束

  • 1 ≤ points.length ≤ 10⁴
  • points[i].length == 2
  • 1 ≤ x, y, aᵢ, bᵢ ≤ 10⁴
目标输出
一个整数下标；无有效点时返回 -1。

官方示例

保留完整参数形式，便于直接对照调用。

示例 1
输入：x = 3, y = 4, points = [[1,2],[3,1],[2,4],[2,3],[4,4]]
输出：2
解释：有效点为 [3,1]、[2,4]、[4,4]；后两者距离均为 1，取下标更小的 2。

输出：-1
解释：没有与当前位置共享 x 或 y 坐标的点。

Core insight

核心洞察

只有满足 aᵢ == x 或 bᵢ == y 的点才参与比较。按原下标从左到右扫描，并且只在距离严格更小时更新答案，就会自然保留下标最小的并列点。
Walkthrough

完整过程

  1. 初始化答案下标为 -1，最小距离为无穷大。
  2. 从下标 0 开始访问每个点 [aᵢ, bᵢ]。
  3. 若 aᵢ != x 且 bᵢ != y，该点无效，直接跳过。
  4. 对有效点计算 |x-aᵢ| + |y-bᵢ|。
  5. 仅当距离严格小于当前最小距离时，同时更新最小距离与答案下标。
  6. 扫描结束后返回答案下标；未更新过时仍为 -1。
Proof & bounds

正确性与边界

正确性证明

维护不变式：处理完下标 0..i 后，answer 是这些点中距离最小的有效点；若有并列，它是下标最小者。初始集合为空，-1 正确。处理第 i 个点时，无效点不会改变候选集合；有效点距离更小时更新会得到新的唯一最优，更大时保持原最优，相等时不更新则保留更早下标。因此不变式持续成立。处理全部点后，它正好给出题目要求的答案。

关键边界

  • 无有效点：答案保持 -1。
  • 点与当前位置重合：距离为 0，之后不可能出现更小距离。
  • 多个点距离相同：使用严格小于号，保留最先出现的点。
  • 仅共享一个坐标也有效；判断条件必须是“或”。
时间复杂度
O(n)，每个点检查一次。
空间复杂度
O(1)，仅维护常数个变量。
Submissions

四语言完整代码

均遵循官方函数签名。

JavaO(n) / O(1)
class Solution {
    public int nearestValidPoint(int x, int y, int[][] points) {
        int answer = -1;
        int minDistance = Integer.MAX_VALUE;

        for (int i = 0; i < points.length; i++) {
            int px = points[i][0];
            int py = points[i][1];
            if (px != x && py != y) {
                continue;
            }

            int distance = Math.abs(x - px) + Math.abs(y - py);
            if (distance < minDistance) {
                minDistance = distance;
                answer = i;
            }
        }
        return answer;
    }
}

Alternative

替代方案

可以先收集全部有效点，再按“距离、下标”排序并取第一项，但需要 O(n) 额外空间和 O(n log n) 时间。题目只需要一个最优下标，单次扫描更直接。

Common mistakes

常见错误

  • 把有效条件写成共享 x 且共享 y。
  • 并列时使用 <= 更新，错误地选择更大下标。
  • 返回点坐标或距离，而不是原数组下标。
  • 没有有效点时忘记返回 -1。
Interview follow-ups

面试追问

  1. 数据流持续到来怎么办？ 维护当前最优距离、最优下标和全局计数即可在线处理。
  2. 需要回答很多不同查询点怎么办？ 可分别按 x、y 建索引，并在有序坐标集合中寻找邻近候选，避免每次扫描全部点。
  3. 为什么相同 x 或 y 时仍使用完整曼哈顿公式？ 公式始终正确；共享一维时其中一项自然为 0，也可仅计算另一维差值。
  4. 如果要求返回全部并列最近点？ 遇到更小距离时清空结果集，遇到相等距离时追加下标。
