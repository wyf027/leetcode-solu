Core insight

答案就是 lower_bound

第一个满足 nums[i] ≥ target 的下标，同时覆盖两种情况：若相等就是命中下标；若更大就是 target 应插在它前面。若所有值都更小，答案自然是 n。

Invariant

半开区间四步法

  1. 01初始化 left = 0，right = n。
  2. 02nums[mid] < target：答案在右侧，left = mid + 1。
  3. 03否则 mid 仍可能是答案，right = mid。
  4. 04left === right 时返回 left。

边界情况

  • target 小于最小值：返回 0。
  • target 大于最大值：返回 n。
  • 单元素命中、插在前、插在后。
  • 负数与零不影响单调性。

复杂度

TIMEO(log n)
SPACEO(1)

替代方案

线性扫描：首个 ≥ target 即返回，简单但为 O(n)，不满足题目要求。

闭区间二分：同样正确，但需要额外 answer 变量；半开区间 lower_bound 更容易复用。

面试高频追问

为什么不先普通二分，找不到再计算插入位？
lower_bound 一次就统一两种语义，分支更少、证明更简单。
为什么 right 初始化为 n？
target 可能应插在数组末尾，n 必须属于候选答案。
有重复元素怎么办？
同一模板返回第一个不小于 target 的位置，即最左插入点。

常见错误

  • right 设为 n - 1，却无法自然表达尾部插入位置 n。
  • nums[mid] ≥ target 时写成 right = mid - 1，丢掉可能答案。
  • 循环使用 left ≤ right，却仍套用半开区间更新规则。
  • 找到相等值就返回，使模板无法泛化到重复元素的最左位置。

class Solution {
    public int searchInsert(int[] nums, int target) {
        int left = 0;
        int right = nums.length;

        while (left < right) {
            int mid = left + (right - left) / 2;
            if (nums[mid] < target) {
                left = mid + 1;
            } else {
                right = mid;
            }
        }
        return left;
    }
}
