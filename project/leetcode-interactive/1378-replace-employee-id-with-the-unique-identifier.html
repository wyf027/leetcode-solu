1378. 使用唯一标识码
替换员工ID

Replace Employee ID With The Unique Identifier

◌ 先理解数据关系并亲手走一遍连接过程，题解仍在页面底部折叠。

Problem

题目描述

任意顺序返回

给定员工主表 Employees 与员工唯一标识映射表 EmployeeUNI，为每位员工展示 unique_id 和 name。若员工没有对应的唯一标识码，结果中的 unique_id 应为 null。

Employees

员工主表
列名类型约束 / 含义
idint主键，员工 ID
namevarchar员工姓名

EmployeeUNI

标识映射表
列名类型约束 / 含义
idint关联员工 ID
unique_idint唯一标识码
(id, unique_id) 为联合主键

约束

  • Employees.id 是 Employees 表的主键。
  • (EmployeeUNI.id, EmployeeUNI.unique_id) 是 EmployeeUNI 表的联合主键。
  • 输出列为 unique_id、name；没有匹配记录时保留员工并填入 null。
  • 结果表可以按任意顺序返回。

Solution

完整题解

核心洞察

输出必须包含 每一位 员工，而映射表可能缺少某些员工。因此让 Employees 做左表，对 EmployeeUNI 按 id 做 LEFT JOIN。未命中的右表列会由 SQL 自动产生 NULL。

完整过程

  1. 从 Employees 读取每个员工的 id 与 name。
  2. 用员工 id 查找 EmployeeUNI.id。
  3. 命中时输出对应 unique_id；未命中时输出 NULL。
  4. 只投影题目需要的 unique_id 与 name。

正确性说明

完整性：左连接为 Employees 中的每一行至少保留一条结果，因此不会遗漏员工。

匹配性：连接条件只接受 Employees.id = EmployeeUNI.id 的记录，所以命中时标识码属于当前员工。

缺失处理：没有匹配右行时，左连接将右侧字段置为 NULL，恰好满足题意。

边界情况

  • 映射表为空：所有员工的 unique_id 都是 NULL。
  • 所有员工均有映射：结果中没有由缺失匹配产生的 NULL。
  • 员工表只有一行：仍按相同连接规则处理。
  • 题目允许任意顺序，无需额外 ORDER BY。

复杂度

设员工表有 n 行、映射表有 m 行。查询的实际代价取决于数据库优化器、索引与连接算法。常见的哈希连接可视作平均 O(n + m) 时间并需要 O(m) 哈希空间；若可利用适当索引，优化器也可能采用索引连接。结果本身至少需要输出 n 行（在数据语义为每名员工至多一个映射时）。

SELECT u.unique_id, e.name
FROM Employees AS e
LEFT JOIN EmployeeUNI AS u
  ON e.id = u.id;
import java.util.*;

public class Solution {
    public record Employee(int id, String name) {}
    public record EmployeeUni(int id, int uniqueId) {}
    public record Result(Integer uniqueId, String name) {}

    public static List<Result> replaceEmployeeId(
            List<Employee> employees, List<EmployeeUni> employeeUni) {
        Map<Integer, List<Integer>> lookup = new HashMap<>();
        for (EmployeeUni row : employeeUni) {
            lookup.computeIfAbsent(row.id(), key -> new ArrayList<>())
                  .add(row.uniqueId());
        }

        List<Result> output = new ArrayList<>();
        for (Employee employee : employees) {
            List<Integer> ids = lookup.get(employee.id());
            if (ids == null || ids.isEmpty()) {
                output.add(new Result(null, employee.name()));
            } else {
                for (Integer uniqueId : ids) {
                    output.add(new Result(uniqueId, employee.name()));
                }
            }
        }
        return output;
    }
}
// 本地语义参考：数组模拟 LEFT JOIN
function replaceEmployeeId(employees, employeeUni) {
  const lookup = new Map();
  for (const row of employeeUni) {
    if (!lookup.has(row.id)) lookup.set(row.id, []);
    lookup.get(row.id).push(row.unique_id);
  }

  const output = [];
  for (const employee of employees) {
    const ids = lookup.get(employee.id);
    if (!ids || ids.length === 0) {
      output.push({ unique_id: null, name: employee.name });
      continue;
    }
    for (const uniqueId of ids) {
      output.push({ unique_id: uniqueId, name: employee.name });
    }
  }
  return output;
}
import pandas as pd

def replace_employee_id(
    employees: pd.DataFrame,
    employee_uni: pd.DataFrame
) -> pd.DataFrame:
    result = employees.merge(
        employee_uni,
        on="id",
        how="left"
    )
    return result[["unique_id", "name"]]
#include <optional>
#include <string>
#include <unordered_map>
#include <vector>
using namespace std;

struct Employee { int id; string name; };
struct EmployeeUni { int id; int uniqueId; };
struct Result { optional<int> uniqueId; string name; };

vector<Result> replaceEmployeeId(
    const vector<Employee>& employees,
    const vector<EmployeeUni>& employeeUni) {
    unordered_map<int, vector<int>> lookup;
    for (const auto& row : employeeUni) {
        lookup[row.id].push_back(row.uniqueId);
    }

    vector<Result> output;
    for (const auto& employee : employees) {
        auto it = lookup.find(employee.id);
        if (it == lookup.end() || it->second.empty()) {
            output.push_back({nullopt, employee.name});
        } else {
            for (int uniqueId : it->second) {
                output.push_back({uniqueId, employee.name});
            }
        }
    }
    return output;
}

Trade-offs

替代方案与面试追问

替代方案

  • 相关子查询：可在 SELECT 中按员工查找标识码，但可读性与优化路径通常不如直接表达左连接清晰。
  • RIGHT JOIN：交换表的位置后也能做到，但会弱化“Employees 是必须完整保留的集合”这一语义。
  • INNER JOIN：只能用于业务明确允许丢弃无映射员工的场景；不符合本题。

面试追问

  • 如果一位员工存在多条映射，LEFT JOIN 会发生什么？——会为每条匹配产生一行结果。
  • 为什么不需要 COALESCE？——题目要求的正是 SQL 原生 NULL。
  • 如何稳定排序？——显式加入 ORDER BY，但本题没有此要求。
  • 怎样分析性能？——查看执行计划，并关注连接键上的索引、表规模与连接算法。

Pitfalls

常见错误

把 LEFT JOIN 写成 INNER JOIN

Alice、Bob 这类没有映射的员工会直接消失，而不是保留并显示 NULL。

左右表顺序颠倒

左连接保留的是左表全部记录；应把必须完整出现的 Employees 放在左侧。

错误连接 unique_id 与员工 id

正确条件是 e.id = u.id；unique_id 是输出值，不是本题的关联键。

额外使用 COALESCE 替换成 0 或字符串

题目明确要求缺失值为 null，不要改变它的类型或含义。
