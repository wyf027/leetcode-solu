Fibonacci Decomposition

和为 K 的最少斐波那契数字数目

给定一个正整数，把它表示成若干斐波那契数字之和；你的目标不是找出任意表示，而是让使用的数字个数尽可能少。

题目说明

给你整数 k，请返回和恰好等于 k 的斐波那契数字的最少数目。同一个斐波那契数字允许使用多次。

斐波那契数字按下面的方式定义：

F1 = 1，F2 = 1；当 n > 2 时，Fn = Fn−1 + Fn−2。

数据保证：在给定约束下，一定存在满足条件的表示。

函数与约束

findMinFibonacciNumbers(k)

  • 参数：k，整数
  • 返回：最少数字数目，整数
  • 1 ≤ k ≤ 109

官方示例

示例 1

输入：k = 7
输出：2
解释：2 + 5 = 7

示例 2

输入：k = 10
输出：2
解释：2 + 8 = 10

示例 3

输入：k = 19
输出：3
解释：1 + 5 + 13 = 19

Greedy Insight

题解：每次取不超过剩余值的最大斐波那契数

核心洞察

  • 先生成所有不超过 k 的斐波那契数字。
  • 令 remaining = k，每轮选择不超过 remaining 的最大斐波那契数字。
  • 减去它并把答案加一，直到剩余值为零。

完整过程：k = 19

  1. 最大可取值为 13，剩余 6。
  2. 最大可取值为 5，剩余 1。
  3. 最大可取值为 1，剩余 0。

19 = 13 + 5 + 1，因此答案为 3。

为什么贪心一定最优

  1. 贪心生成标准分解。 每次拿最大可行斐波那契数后，新的剩余值小于它的前一个斐波那契数。因此后续不会选到相邻项，最终得到不含相邻项的斐波那契分解。
  2. 任意表示都能正规化。 对任何允许重复项的表示，可以反复合并相邻项 Fᵢ + Fᵢ₊₁ = Fᵢ₊₂，并处理重复项；这些变换不会增加项数，最终可化为不重复且不相邻的标准分解。
  3. 标准分解唯一。 Zeckendorf 定理说明，每个正整数都有唯一的不相邻斐波那契分解（采用 1, 2, 3, 5, … 的记法）。贪心得到的正是它。
  4. 得到最小项数。 任意可行表示正规化后都不会比原表示使用更多项，而其结果只能是贪心分解，所以原表示的项数不可能少于贪心答案。

边界与实现细节

  • k = 1 时直接选 1。
  • k 本身是斐波那契数时，答案为 1。
  • 生成数列时从唯一值序列 1, 2, 3, 5, … 开始即可；两个 1 对最少数量没有区别。
  • 上限是 10⁹，32 位有符号整数足够容纳所需数列；仍应在生成下一项时留意更大约束下的溢出。

复杂度

时间
O(log k)

斐波那契数按指数速度增长。

空间
O(log k)

保存不超过 k 的数列。

若只维护两个相邻数并反向寻找，可进一步做到 O(1) 额外空间。

四语言完整代码

import java.util.ArrayList;
import java.util.List;

class Solution {
    public int findMinFibonacciNumbers(int k) {
        List<Integer> fib = new ArrayList<>();
        int a = 1;
        int b = 2;

        while (a <= k) {
            fib.add(a);
            int next = a + b;
            a = b;
            b = next;
        }

        int count = 0;
        for (int i = fib.size() - 1; i >= 0 && k > 0; i--) {
            int value = fib.get(i);
            if (value <= k) {
                k -= value;
                count++;
            }
        }
        return count;
    }
}

var findMinFibonacciNumbers = function(k) {
    const fib = [];
    let a = 1;
    let b = 2;

    while (a <= k) {
        fib.push(a);
        [a, b] = [b, a + b];
    }

    let count = 0;
    for (let i = fib.length - 1; i >= 0 && k > 0; i--) {
        if (fib[i] <= k) {
            k -= fib[i];
            count++;
        }
    }
    return count;
};
class Solution:
    def findMinFibonacciNumbers(self, k: int) -> int:
        fib = []
        a, b = 1, 2

        while a <= k:
            fib.append(a)
            a, b = b, a + b

        count = 0
        for value in reversed(fib):
            if value <= k:
                k -= value
                count += 1
            if k == 0:
                break

        return count

替代方案

  • 二分定位：每轮在数列中二分查找最大可取值，表达清晰，但本题数列极短，收益有限。
  • 动态规划：把斐波那契数当作完全背包可求最少项数，但需要 O(k) 时间和空间，面对 10⁹ 不可行。
  • 常量空间：先找到不超过 k 的最大斐波那契数，再用相邻项逆推；空间降为 O(1)，实现细节更多。

面试追问

  • 如果可选数字不是斐波那契数，贪心还成立吗？需要什么结构性质？
  • 如何把额外空间降到 O(1)？
  • 若要求输出具体分解，接口与数据结构怎么设计？
  • 若每个斐波那契数有不同成本，问题会如何变化？

常见错误

  • 生成数列时把两个 1 都保留并写出依赖下标的特殊逻辑，徒增出错点。
  • 用逐个减法模拟“同一数字可重复使用”，忽略贪心分解中实际上不会需要重复选择同一项。
  • 直接写 O(k) 动态规划，无法覆盖 k = 10⁹。
  • 先生成超过 k 的下一项却没有考虑整数溢出；约束扩大后尤其危险。
  • 只说明“取最大的显然最好”，却没有交代斐波那契标准分解为何保证全局最优。
