从任意含金矿格出发，在不能重复踏入同一格的条件下，规划一条上下左右移动的路线，让带回的黄金总量尽可能多。

输入m × n 金矿网格
移动方式上 / 下 / 左 / 右
目标最大可收集黄金

任务说明

一次不走回头路的采矿行动

给定整数矩阵 grid，每个正整数代表该格的黄金数量，0 代表空地。进入一个矿格时立即收集其中全部黄金。

  • 01矿工每次只能向相邻的上、下、左、右移动一步。
  • 02不能进入值为 0 的空格，同一矿格也不能访问第二次。
  • 03可以从任意含金矿格开始，也可以在任意时刻结束；返回所有合法路线中最大的黄金总量。
官方参数形式
getMaximumGold(grid: integer[][]) → integer

示例 1

输入：grid = [[0,6,0],[5,8,7],[0,9,0]]
输出：24
解释：路线 9 → 8 → 7，共收集 24。

示例 2

输入：grid = [[1,0,7],[2,0,6],[3,4,5],
             [0,3,0],[9,0,20]]
输出：28
解释：路线 1 → 2 → 3 → 4 → 5 → 6 → 7，
共收集 28。

约束

  • m == grid.length
  • n == grid[i].length
  • 1 <= m, n <= 15
  • 0 <= grid[i][j] <= 100
  • 最多有 25 个非零矿格

答案封存区

准备好再揭开路线图

题解默认折叠，先独立思考：怎样确保从每个可能的入口出发，又不重复踏入同一矿格？

完整题解

枚举起点 + 原地标记的深度优先搜索

核心洞察：一条合法采矿路线就是非零网格图中的一条简单路径。入口和出口都不固定，所以从每个含金格出发，枚举下一步的四个方向，并在离开分支时恢复现场，即可覆盖所有合法路线。

完整过程

  1. 枚举入口。扫描整个矩阵，每遇到一个非零格，就以它为起点发起一次搜索。
  2. 收下当前黄金。保存当前格的值，并暂时把该格改为 0。这样后续递归既不会走进空格，也不会重复访问当前格。
  3. 试探四个方向。递归进入边界内且仍为非零的相邻格，取四条后续分支能获得的最大值。
  4. 恢复现场。当前分支计算完毕后，把原值写回网格，让其他起点或其他分支仍能使用该矿格。
  5. 更新全局答案。当前格黄金加上最佳后续收益，就是以当前状态出发的最优收益；所有起点取最大值。

正确性说明

完备性：外层循环把每个含金格都作为起点；对任意起点，搜索在每一步都枚举上下左右四个合法邻格，因此任意合法简单路径的每次移动都会出现在某条递归分支中。

合法性：当前格进入递归后被临时置为 0，这条分支不可能再次进入它；搜索也只进入非零且未越界的格子，所以产生的每条路径都满足题目规则。

最优性：每个状态返回其所有合法后继中的最大收益，外层再对所有起点取最大值。由于所有合法路线均被覆盖，最终结果就是可收集黄金的最大总量。

边界情况

全为 0 时答案为 0；只有一个矿格时返回它本身；互不连通的矿区会由不同起点分别搜索；在单行或单列网格中，边界判断仍然成立。

复杂度

设非零矿格数为 k ≤ 25。搜索路径最坏呈指数增长，可写作 O(mn · 3^k) 的宽松上界（第一步至多 4 个方向，此后通常至多 3 个未访问方向）；递归栈为 O(k)。原地标记除栈外只用 O(1) 空间。

时间：指数级，宽松上界 O(mn · 3^k)空间：O(k)

JavaLeetCode 提交格式
class Solution {
    private int rows;
    private int cols;
    private final int[][] directions = {{1, 0}, {-1, 0}, {0, 1}, {0, -1}};

    public int getMaximumGold(int[][] grid) {
        rows = grid.length;
        cols = grid[0].length;
        int answer = 0;

        for (int row = 0; row < rows; row++) {
            for (int col = 0; col < cols; col++) {
                if (grid[row][col] != 0) {
                    answer = Math.max(answer, dfs(grid, row, col));
                }
            }
        }
        return answer;
    }

    private int dfs(int[][] grid, int row, int col) {
        int gold = grid[row][col];
        grid[row][col] = 0;
        int bestNext = 0;

        for (int[] direction : directions) {
            int nextRow = row + direction[0];
            int nextCol = col + direction[1];
            if (nextRow >= 0 && nextRow < rows &&
                nextCol >= 0 && nextCol < cols &&
                grid[nextRow][nextCol] != 0) {
                bestNext = Math.max(bestNext, dfs(grid, nextRow, nextCol));
            }
        }

        grid[row][col] = gold;
        return gold + bestNext;
    }
}

/**

var getMaximumGold = function(grid) {
    const rows = grid.length;
    const cols = grid[0].length;
    const directions = [[1, 0], [-1, 0], [0, 1], [0, -1]];

    function dfs(row, col) {
        const gold = grid[row][col];
        grid[row][col] = 0;
        let bestNext = 0;

        for (const [dr, dc] of directions) {
            const nextRow = row + dr;
            const nextCol = col + dc;
            if (nextRow >= 0 && nextRow < rows &&
                nextCol >= 0 && nextCol < cols &&
                grid[nextRow][nextCol] !== 0) {
                bestNext = Math.max(bestNext, dfs(nextRow, nextCol));
            }
        }

        grid[row][col] = gold;
        return gold + bestNext;
    }

    let answer = 0;
    for (let row = 0; row < rows; row++) {
        for (let col = 0; col < cols; col++) {
            if (grid[row][col] !== 0) {
                answer = Math.max(answer, dfs(row, col));
            }
        }
    }
    return answer;
};

from typing import List


class Solution:
    def getMaximumGold(self, grid: List[List[int]]) -> int:
        rows, cols = len(grid), len(grid[0])
        directions = ((1, 0), (-1, 0), (0, 1), (0, -1))

        def dfs(row: int, col: int) -> int:
            gold = grid[row][col]
            grid[row][col] = 0
            best_next = 0

            for dr, dc in directions:
                next_row, next_col = row + dr, col + dc
                if (0 <= next_row < rows and
                        0 <= next_col < cols and
                        grid[next_row][next_col] != 0):
                    best_next = max(best_next, dfs(next_row, next_col))

            grid[row][col] = gold
            return gold + best_next

        answer = 0
        for row in range(rows):
            for col in range(cols):
                if grid[row][col] != 0:
                    answer = max(answer, dfs(row, col))
        return answer

方案对比

还有哪些思路？

显式 visited

使用同尺寸布尔数组记录访问状态，逻辑直观；空间增加到 O(mn)，适合不允许修改输入的场景。

位掩码记忆化

给至多 25 个矿格编号，以状态 (位置, 已访问集合) 做记忆化。某些重叠子问题多的图上有用，但最坏状态量可达 k·2^k。

图压缩

可以先把非零格建图，但网格本身已经提供紧凑邻接关系；额外建图通常不能降低指数级路径枚举成本。

面试追问

从这道题继续深挖

为什么不能只从黄金最多的格子开始？

局部最大的单格可能位于很短的孤立分支，而较小的入口可能连接一条总和更大的长路线；起点必须完整枚举。

为什么恢复网格值很重要？

置零只应该约束当前递归分支。若不恢复，后续兄弟分支和其他起点会错误地把该格当作不可用，导致漏解。

如果允许走八个方向，代码怎样改？

把方向数组扩展为八组偏移即可；搜索框架、访问标记和恢复逻辑都不变，但分支因子会增大。

如果不能修改输入网格怎么办？

改用 boolean[][] visited，进入时标记、返回时取消标记，语义与原地置零完全一致。

常见错误

别把黄金留在递归栈里

  • 只从某一个入口搜索，遗漏其他连通块或不同入口的路径。
  • 递归返回前忘记恢复当前格，使后续分支基于被污染的网格继续计算。
  • 把四个方向的收益全部相加；一条路线只能选择其中一个后继分支，应取最大值。
  • 先访问再判断边界，造成数组越界；必须先确认坐标合法。
  • 用全局 visited 且从不回退，错误地把“本路径已访问”扩大成“所有路径永久禁用”。
