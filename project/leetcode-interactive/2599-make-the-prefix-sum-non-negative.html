Problem

题意

给你一个从 0 开始编号的整数数组 nums。每次可选取其中一个元素，将它从当前位置取出并放到数组末尾。

定义同长度数组 prefix，其中：

prefix[i] = nums[0] + nums[1] + … + nums[i]
  • 1你可以执行任意次“把一个元素移到末尾”的操作。
  • 2目标是让最终数组的每一个前缀和都为非负数。
  • 3返回达到目标所需的最少操作次数；数据保证一定有解。

约束与签名

  • 1 ≤ nums.length ≤ 10⁵
  • −10⁹ ≤ nums[i] ≤ 10⁹
  • 测试数据保证存在可行排列。

官方函数：makePrefSumNonNegative(nums) → 整数

输入：nums = [2,3,-5,4]
输出：0

Solution

贪心 + 最小堆

扫描时先把元素计入前缀；一旦余额为负，就从已经见过的负数中撤回最小的那个，把它推迟到数组末尾。

核心洞察

若当前前缀和 sum < 0，必须让至少一个已扫描元素离开当前前缀。正数移走只会让余额更差，所以只考虑负数；移走数值最小（绝对值最大）的负数，能让 sum 一次回升最多。

因此：用最小堆保存扫描过的负数；前缀变负时弹出堆顶，令 sum -= heap.pop()，并把答案加一。

完整过程

  1. 初始化前缀和 sum = 0、操作数 ans = 0 和一个最小堆。
  2. 从左到右遍历 nums，把当前值加入 sum；若它为负数，同时压入最小堆。
  3. 若 sum < 0，弹出堆中最小的负数 y，视为把它移到末尾；从当前前缀撤掉它：sum -= y，并令 ans++。
  4. 遍历结束后返回 ans。被撤掉的数都为负数，追加到保留序列末尾时，中间余额只会逐步下降；最终总和非负，所以尾部也安全。

一次修复足够：变负前的余额非负，而堆顶不大于本轮加入的负数；撤掉堆顶后，余额至少恢复到变负前的水平。

正确性证明

1
不变量：每轮结束时，未被推迟的已扫描元素之和非负。若加入当前数后仍非负，不变量直接保持；若变负，撤掉最小负数会使余额恢复为非负。
2
局部最优：发生负前缀时，任何可行方案都必须从该前缀中至少移走一个元素。移走正数无益；在负数中移走最小值带来的余额增量最大，不会比移走其他负数更早需要下一次操作。
3
交换论证：若某个最优方案在此处移走另一个负数 z，而堆顶为 y ≤ z，用 y 替换 z 后，后续每个保留前缀的余额只会更大，操作数不变，方案仍可行。
4
结论：每次负前缀都执行一个必要且可嵌入最优方案的选择，故最终操作次数最少。

边界与复杂度

  • 全为非负数或前缀始终非负：堆可能有元素，但不会弹出，答案为 0。
  • 0 不必入堆；它既不会破坏也不会修复余额。
  • 最大累计和可达约 10¹⁴：Java / C++ 必须使用 64 位整数；JavaScript 的安全整数范围足够。
  • 题目保证有解，等价地确保最终总和可达到非负；否则仅靠重排无法改变总和。
时间复杂度O(n log n)每个负数至多入堆、出堆一次。
空间复杂度O(n)最坏保存全部负数。

四语言完整代码

import java.util.PriorityQueue;

class Solution {
    public int makePrefSumNonNegative(int[] nums) {
        PriorityQueue<Integer> negatives = new PriorityQueue<>();
        long sum = 0;
        int operations = 0;

        for (int value : nums) {
            sum += value;
            if (value < 0) negatives.offer(value);
            if (sum < 0) {
                sum -= negatives.poll();
                operations++;
            }
        }
        return operations;
    }
}

 * @param {number[]} nums

var makePrefSumNonNegative = function(nums) {
    const heap = [];

    const push = value => {
        heap.push(value);
        for (let i = heap.length - 1; i > 0;) {
            const parent = (i - 1) >> 1;
            if (heap[parent] <= heap[i]) break;
            [heap[parent], heap[i]] = [heap[i], heap[parent]];
            i = parent;
        }
    };

    const pop = () => {
        const smallest = heap[0];
        const last = heap.pop();
        if (heap.length) {
            heap[0] = last;
            for (let i = 0;;) {
                let child = i * 2 + 1;
                if (child >= heap.length) break;
                if (child + 1 < heap.length && heap[child + 1] < heap[child]) child++;
                if (heap[i] <= heap[child]) break;
                [heap[i], heap[child]] = [heap[child], heap[i]];
                i = child;
            }
        }
        return smallest;
    };

    let sum = 0;
    let operations = 0;
    for (const value of nums) {
        sum += value;
        if (value < 0) push(value);
        if (sum < 0) {
            sum -= pop();
            operations++;
        }
    }
    return operations;
};

替代方案

  • 有序多重集合：同样保存见过的负数并取最小值，复杂度仍为 O(n log n)，但堆更直接。
  • 枚举移动：每次尝试移走不同元素并检查所有前缀，会产生组合爆炸，不适合 n = 10⁵。
  • 只移当前负数：可得到可行方案，却未必最少；更早出现、数值更小的负数可能一次释放更多余额。

面试追问

  • 如何恢复最终数组？堆中同时保存值和原下标，标记每个被弹出的下标；最后输出未标记元素，再按移出顺序追加标记元素。
  • 为什么不需要 while？本轮之前的余额非负，且弹出的最小负数不大于导致失衡的当前负数，撤销后至少回到本轮之前的余额。
  • 若每个元素移动成本不同？“最负优先”不再直接保证最小总成本，需要重新定义优化目标，通常会变成带成本选择或动态规划问题。

常见错误

  • 使用最大堆直接存负数，弹出的反而是最接近 0、修复能力最弱的值。
  • 前缀变负时只移动当前元素，忽略先前更小的负数。
  • Java / C++ 用 32 位整数保存前缀和，极端数据会溢出。
  • 把堆中所有负数都当作已移动；只有被弹出的元素才计入操作数。
