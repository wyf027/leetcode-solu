规定时间内到达终点的
最小花费

Minimum Cost to Reach Destination in Time

一笔旅行预算，一条时间红线。先理解规则，再探索路线选择。

官方题目 ↗

01 / THE PROBLEM

任务与规则

有 n 个城市，编号 0 到 n − 1，所有城市通过双向道路连通。每条道路以 edges[i] = [xᵢ, yᵢ, timeᵢ] 表示，走过它需要 timeᵢ 分钟。同一对城市之间可以有多条不同耗时的道路，但不存在自环。

从城市 0 出发，每次经过城市 j 都支付 passingFees[j]。起点和终点也收费；若再次进入某城市，需要再次收费。要求在 maxTime 分钟内（含恰好等于）到达城市 n − 1。

返回满足时间限制的最小总费用；没有可行路线时返回 -1。

minCost(maxTime, edges, passingFees) → integer

约束

  • 1 ≤ maxTime ≤ 1000
  • n = passingFees.length，2 ≤ n ≤ 1000
  • n − 1 ≤ edges.length ≤ 1000
  • 0 ≤ xᵢ, yᵢ ≤ n − 1，xᵢ ≠ yᵢ
  • 1 ≤ timeᵢ ≤ 1000
  • 1 ≤ passingFees[j] ≤ 1000
  • 图连通，可能含重边，不含自环。

官方示例

示例 1

maxTime = 30
edges = [[0,1,10],[1,2,10],[2,5,10],[0,3,1],[3,4,10],[4,5,15]]
passingFees = [5,1,2,20,20,3]

输出：11

走 0 → 1 → 2 → 5，用时 10 + 10 + 10 = 30 分钟，费用 5 + 1 + 2 + 3 = 11。

03 / SOLUTION LAB

沿时间轴展开城市

核心洞察

不能只记录城市的最低费用：较贵但更快的前缀，可能是唯一按时到达的选择。定义 dp[t][v] 为恰好用 t 分钟到达城市 v 的最小费用。

道路耗时严格为正，每次转移均来自更早的时间层。即使原图有环，展开后的状态依赖仍按时间递增，适合动态规划。

完整过程

  1. 将 (T + 1) × n 的表初始化为 ∞，其中 T = maxTime。设 dp[0][0] = passingFees[0]，起点费不能漏。
  2. 按 t = 1…T 递增遍历；枚举每条道路 [u,v,w]，只处理 w ≤ t 的道路。
  3. 用 dp[t-w][u] + passingFees[v] 更新 dp[t][v]，再对 v → u 对称更新。不可达来源不产生有效候选。
  4. 取所有 0 ≤ t ≤ T 的 dp[t][n-1] 的最小值。若全为 ∞，返回 −1。

“恰好 t”与“最多 t”不同。不要直接复制上一行代表等待；答案也不能只取最后一行。

正确性证明
基例：t = 0 时，道路耗时均为正，只有起点可达，费用为 passingFees[0]。
归纳：假设小于 t 的所有层已正确。任一恰好 t 分钟到达 v 的路线，其末边必为 [u,v,w]，之前恰好用 t − w 分钟到达 u。根据归纳假设，最优前缀费用已知，加上 v 的费用就是该末边的最优候选。枚举全部道路覆盖所有末边，每个有限候选也都能由真实路径构造，因此取最小值恰好得到 dp[t][v]。
结论：合法路线的终点到达时间均在 0…T 内，扫描所有终点状态得到全局最优；若均不可达，则不存在合法路线。
复杂度与边界
设 m = edges.length。初始化 O(Tn)，转移 O(Tm)，答案扫描 O(T)。总时间 O(T(n + m))；因 m ≥ n − 1，本题也可写成 O(Tm)。空间 O(Tn)。
  • 恰好等于时间预算的路线合法。
  • 图连通不代表能在预算内到达。
  • 平行道路分别枚举；无须去重。
  • 道路耗时可能大于 1，不能只保留前后两行。
  • 最优路线无需正代价绕环，但状态表仍能正确处理重复收费。
  • 整数版本使用 10⁹ 表示不可达并跳过该来源；有限状态费用至多约 1,001,000，不会溢出。


替代方案
在 (城市, 已用时间) 状态上运行按费用排序的 Dijkstra。每条转移的费用为进入城市的费用，均为正；第一个有效出堆的终点状态就是最优答案。仍应维护二维距离，不能只按城市标记访问。扩展图有 O(Tn) 个状态和 O(Tm) 条转移，典型堆实现时间 O(Tm log(Tn))。这里 T ≤ 1000，按时间 DP 更直接。
常见错误
  • 把最短时间路线当成最小费用路线，或忽略时间限制。
  • 每城市只保留最低费用，丢弃更快但稍贵的前缀。
  • 漏算起点通行费，或在转移中加上离开城市的费用。
  • 无向道路只更新一个方向。
  • 仅返回 dp[T][n−1]，漏掉提前到达的最优路线。
  • 二维数组的多行共享同一数组，导致所有时间层一起变化。
面试追问
如何恢复路线？改进状态时保存前驱的时间和城市，从最佳终点状态逆序回溯。
T 很大怎么办？考虑状态搜索与 Pareto 标签剪枝。同城的 A 若时间、费用均不大于 B，就可丢弃 B；最坏标签数量仍可能很大。
若有零耗时边？层间严格递增的前提失效，同层状态也互相依赖，需要层内最短路或完整状态图搜索。

Java
import java.util.Arrays;

class Solution {
    public int minCost(int maxTime, int[][] edges, int[] passingFees) {
        int n = passingFees.length, INF = 1_000_000_000;
        int[][] dp = new int[maxTime + 1][n];
        for (int[] row : dp) Arrays.fill(row, INF);
        dp[0][0] = passingFees[0];
        for (int t = 1; t <= maxTime; t++) {
            for (int[] e : edges) {
                int u = e[0], v = e[1], w = e[2];
                if (w > t) continue;
                if (dp[t - w][u] != INF)
                    dp[t][v] = Math.min(dp[t][v], dp[t - w][u] + passingFees[v]);
                if (dp[t - w][v] != INF)
                    dp[t][u] = Math.min(dp[t][u], dp[t - w][v] + passingFees[u]);
            }
        }
        int ans = INF;
        for (int t = 0; t <= maxTime; t++) ans = Math.min(ans, dp[t][n - 1]);
        return ans == INF ? -1 : ans;
    }
}

class Solution:
    def minCost(self, maxTime: int, edges: List[List[int]], passingFees: List[int]) -> int:
        n = len(passingFees)
        inf = float("inf")
        dp = [[inf] * n for _ in range(maxTime + 1)]
        dp[0][0] = passingFees[0]
        for t in range(1, maxTime + 1):
            for u, v, w in edges:
                if w > t:
                    continue
                dp[t][v] = min(dp[t][v], dp[t - w][u] + passingFees[v])
                dp[t][u] = min(dp[t][u], dp[t - w][v] + passingFees[u])
        ans = min(dp[t][n - 1] for t in range(maxTime + 1))
        return -1 if ans == inf else ans
