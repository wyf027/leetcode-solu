Problem brief

题目说明

困难数组哈希表动态规划计数

任务

给定整数数组 nums 与整数 k，把数组拆成若干个连续且非空的子数组。一次拆分的总代价，是所有子数组“重要性”的总和。

对子数组删除所有只出现一次的数，剩余序列记作 trimmed(subarray)。这个子数组的重要性为：

importance = k + trimmed(subarray).length

例如，[3,1,2,4,3,4] 中只保留重复值，得到 [3,4,3,4]。请返回所有合法拆分中的最小总代价。

函数签名

minCost(nums: integer[], k: integer) → integer

约束

  • 1 ≤ nums.length ≤ 1000
  • 0 ≤ nums[i] < nums.length
  • 1 ≤ k ≤ 10⁹

子数组必须连续且非空；相同的值在不同子数组中分别计数。

输入：nums = [1,2,1,2,1,3,3], k = 2
输出：8

两段重要性分别为 2 + 0 = 2，

Complete solution

动态规划 + 反向计数

O(n²)

核心洞察

设 dp[i] 为前 i 个元素的最小拆分代价。枚举最后一段的左端点 j，上一部分的最优解是 dp[j]，最后一段是 nums[j..i-1]。

dp[i] = min(dp[j] + k + trim(j, i − 1))

关键是固定右端点后从右向左移动 j，用频次数组增量维护裁剪长度：某值第一次出现不增加；第二次出现时，它的两次出现都进入裁剪数组，所以增加 2；第三次及以后每次增加 1。

完整过程

  1. 初始化 dp[0] = 0，其余为无穷大。
  2. 依次计算每个前缀终点 i = 1..n。
  3. 清空频次数组与 trim = 0，令左端点从 i-1 递减到 0。
  4. 按当前值的新频次更新 trim，再用当前最后一段更新 dp[i]。
  5. 答案为 dp[n]。

正确性证明

命题：dp[i] 等于前 i 个元素的最小拆分代价。

基础：dp[0] = 0，空前缀无需任何子数组，结论成立。

归纳：假设更短前缀的状态都正确。任一覆盖前 i 个元素的最优拆分，其最后一段必为某个 nums[j..i-1]；最后一段之前必须采用前 j 个元素的最优拆分，否则替换后会得到更小总代价，与原方案最优矛盾。转移枚举了所有 j，并精确加入该段的重要性，因此既不会漏掉最优方案，也不会产生非法方案。

结论：由数学归纳法，dp[n] 即全数组的最小代价。

边界与复杂度

  • 单个元素：裁剪长度为 0，答案为 k。
  • 所有元素互异：任一段的裁剪长度都为 0，少切最好，答案为 k。
  • 所有元素相同：同一段中从第二次出现开始产生重复代价，转移仍适用。
  • 时间：两层枚举，共 O(n²)。
  • 空间：dp 与频次数组共 O(n)。

替代方案

可以先用三重循环为每个区间重新统计重要性，再做同样的前缀动态规划，时间为 O(n³)。它更直观，但在 n = 1000 时通常过慢。也可以预处理全部区间代价，仍需 O(n²) 额外空间；反向计数把这部分空间省掉了。

Implementations

四种语言完整代码

JavaLeetCode
import java.util.Arrays;

class Solution {
    public int minCost(int[] nums, int k) {
        int n = nums.length;
        int[] dp = new int[n + 1];
        Arrays.fill(dp, Integer.MAX_VALUE);
        dp[0] = 0;

        for (int i = 1; i <= n; i++) {
            int[] freq = new int[n];
            int trim = 0;
            for (int j = i - 1; j >= 0; j--) {
                int count = ++freq[nums[j]];
                if (count == 2) trim += 2;
                else if (count > 2) trim++;
                dp[i] = Math.min(dp[i], dp[j] + k + trim);
            }
        }
        return dp[n];
    }
}

class Solution:

        dp = [float("inf")] * (n + 1)
        dp[0] = 0

        for i in range(1, n + 1):

                dp[i] = min(dp[i], dp[j] + k + trim)

常见错误

  • 某个值第二次出现时只把裁剪长度加 1；实际上前后两次都应保留，所以要加 2。
  • 把频次跨不同右端点复用，导致区间计数污染；每次计算新 i 都要清空。
  • 转移写成 dp[j-1]，在 j = 0 时越界；本题状态按“元素个数”定义，应使用 dp[j]。
  • 把“删除只出现一次的值”误解成去重；重复值的所有出现都保留。
  • 只计算重复值的种类数，而不是重复元素出现的总个数。

面试追问

为什么固定右端点后要向左扫描？

新加入的只有一个元素，它的频次变化可在 O(1) 时间反映到裁剪长度；所有候选最后一段便能在线得到。

如果 nums[i] 不保证小于 n 呢？

把长度为 n 的频次数组换成哈希表即可，渐进复杂度保持不变。

如何恢复具体拆分位置？

每次更新 dp[i] 时记录取得最小值的 j，最后从 n 沿这些前驱位置反向回溯。

固定费用 k 变大时，最优拆分有什么趋势？

每多一段都多付一次 k，因此较大的 k 会抑制切分；但重复代价仍可能让某些切分更优。
