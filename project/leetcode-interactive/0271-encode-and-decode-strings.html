字符串的编码与解码

设计一份可靠的传输协议：机器一把字符串列表变成一个字符串，机器二再把它完整还原。内容可能为空，也可能含有常见分隔字符。

#271MEDIUM🔒 付费题手动判题接口

先独立想一想：如果字符串本身能包含你选的分隔符，接收方如何知道边界？

Problem brief

任务契约

请设计一个 Codec，实现两个互逆操作：

  • encode(strs)：接收字符串列表，将它编码为单个字符串，以便通过网络发送。
  • decode(s)：接收编码结果，恢复出与原列表完全相同、顺序不变的字符串列表。

不要求编码结果具有人类可读性，但必须能无歧义地恢复空字符串、重复字符串，以及内容中出现分隔符的字符串。请勿使用把整个列表直接序列化的现成机制来规避协议设计。

接口说明

判题器会先调用 encode(dummy_input) 得到消息，再把该消息交给 decode；最终比较解码列表与原输入是否一致。

约束

  • 1 <= strs.length <= 200
  • 0 <= strs[i].length <= 200
  • 每个字符串可包含 256 个有效 ASCII 字符中的任意字符。
  • 返回值必须足以让另一个 Codec 实例精确还原输入。

官方元数据中的题面与代码片段为空；此处依据官方手动签名和稳定公开契约进行精炼转述。

Editorial

长度前缀：让边界成为数据

核心洞察

不要猜正文里哪个字符“不会出现”。在每个字符串前写入它的长度，再用一个固定字符结束长度字段。解码时先读长度，再精确读取这么多个正文字符。

编码片段形式为 长度#正文。例如 "a#b" 变成 3#a#b；正文中的 # 不参与分割，因此没有歧义。

完整过程

  1. 编码每一项
    对字符串 s，依次追加十进制长度、字符 # 与 s 本身。
  2. 直接拼接片段
    所有片段首尾相接，不需要额外的列表分隔符；空字符串会贡献 0#。
  3. 解析长度字段
    解码指针从当前位置向右找到第一个 #，其前面的十进制数字就是正文长度 length。
  4. 按长度截取正文
    从 # 后取恰好 length 个字符，加入答案，指针移动到下一片段。

正确性说明

引理 1：长度字段可唯一定位编码器只在十进制长度之后写入首个边界符；解码器从片段起点找到的第一个 #，因此必然结束该长度字段。
引理 2：正文可精确恢复长度为 L 时，解码器从边界符后读取恰好 L 个字符，与编码器追加的原字符串范围完全相同。正文即使含 # 也不会被解释。
归纳到整个列表第一段可由两条引理正确恢复，指针随后恰好落在下一段起点。对全部片段重复后，得到顺序和内容均与输入一致的列表。

时间复杂度

编码与解码均为 O(C)，其中 C 是所有字符串的总字符数（另含很小的长度数字开销）。

空间复杂度

除返回的编码串或答案外，额外空间为 O(1)；构造返回值本身需要 O(C)。

关键边界

空字符串、正文含 #、连续空串、长度超过一位、重复项与最大规模。

import java.util.ArrayList;
import java.util.List;

public class Codec {
    public String encode(List<String> strs) {
        StringBuilder encoded = new StringBuilder();
        for (String str : strs) {
            encoded.append(str.length()).append('#').append(str);
        }
        return encoded.toString();
    }

    public List<String> decode(String s) {
        List<String> result = new ArrayList<>();
        int i = 0;

        while (i < s.length()) {
            int delimiter = i;
            while (s.charAt(delimiter) != '#') {
                delimiter++;
            }

            int length = Integer.parseInt(s.substring(i, delimiter));
            int start = delimiter + 1;
            int end = start + length;
            result.add(s.substring(start, end));
            i = end;
        }
        return result;
    }
}

替代方案

转义分隔符：选一个分隔符，并对正文里的同字符进行转义。可行，但转义与反转义规则更容易出现边界漏洞。

固定宽度长度头：长度字段固定占若干位，解析简单，但需要预先约定最大长度并浪费部分空间。长度前缀更自然地适应变化范围。

常见错误

  • 直接用逗号或 # 分割，忽略正文也可能包含它。
  • 读取到边界符后忘记将正文起点移动一位。
  • 处理空字符串时错误地跳过 0#。
  • 把多位长度逐字符当成多个独立数字。
  • 指针移动到 start + length + 1，额外跳过下一段首字符。

面试追问

1. 流式网络怎么做？

维护解析状态：先累计长度字段，再等待缓冲区拥有足够正文；不必等整条消息到齐。

2. 消息损坏怎么办？

为帧增加版本、总长度、校验和或认证标签，并在解析前限制长度上限，避免恶意超大分配。

3. Unicode 怎么定义长度？

跨语言协议应统一按 UTF-8 字节数计长；本题限定 ASCII，因此字符数与字节数一致。
