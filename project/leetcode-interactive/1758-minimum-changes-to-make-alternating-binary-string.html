生成交替二进制字符串的最少操作数

一次只能翻转一个字符。目标是让相邻字符永不相同，并求所需的最少操作数。

简单题号 1758非付费题Minimum Changes To Make Alternating Binary String
Problem

题目描述

给你一个只包含字符 0 和 1 的字符串 s。一次操作可以把任意一个 0 改成 1，或把任意一个 1 改成 0。

如果一个字符串中任意两个相邻字符都不相等，则称它为交替字符串。返回把 s 变成交替字符串所需的最少操作数。

函数形式： minOperations(s: string) -> integer
Official examples

官方示例

示例 1
输入：s = "0100" 输出：1

把最后一位改为 1，得到 0101。

示例 2
输入：s = "10" 输出：0

10 本身已经交替，无需操作。

示例 3
输入：s = "1111" 输出：2

两次操作可以得到 0101 或 1010。

Constraints

约束

  • 1 <= s.length <= 104
  • s[i] 只能是 0 或 1。

Solution

题解：只需比较两个确定目标

核心洞察

二进制交替字符串的首字符一旦确定，后续每一位也随之确定。因此长度为 n 的目标只有两种：

A = 010101…（从 0 开始） B = 101010…（从 1 开始）

逐位统计 s 与 A 的不同位数 diff。由于 B 在每一位都与 A 相反，s 与 B 的不同位数必为 n - diff，答案是两者较小值。

完整过程

  1. 令 diff = 0。
  2. 遍历下标 i，A 在偶数位期望 0，奇数位期望 1。
  3. 若 s[i] 与期望字符不同，令 diff++。
  4. A 需要 diff 次；B 需要 n - diff 次。
  5. 返回 min(diff, n - diff)。

示例 0100 的逐位推演

下标 is[i]A 期望是否错位累计 diff
000否0
111否0
200否0
301是1

A 的代价为 1；B 的代价为 4 - 1 = 3，所以最少操作数为 1。

正确性证明

引理 1：长度固定的二进制交替字符串恰有两个。首位只能取 0 或 1；之后每一位必须与前一位相反，因此两种首位分别唯一确定 A 和 B。

引理 2：把 s 变成某个固定目标 T 的最少操作数，等于二者不同字符位置的数量。每个不同位置至少要翻转一次；各翻转一次又足以得到 T。

结论：任何合法结果只能是 A 或 B。算法分别得到到达 A、B 的最小代价并取较小值，因此返回全局最少操作数。

边界与复杂度

  • 长度为 1：天然交替，答案为 0。
  • 已经交替：某个候选的错位数为 0。
  • 全为同一字符：答案接近一半，奇数长度时取决于起始字符。
  • 最大长度 10⁴：单次线性扫描足够。
时间复杂度：O(n) 空间复杂度：O(1)
Implementations

四种语言完整代码

JavaLeetCode 可提交
class Solution {
    public int minOperations(String s) {
        int diff = 0;

        for (int i = 0; i < s.length(); i++) {
            char expected = (i % 2 == 0) ? '0' : '1';
            if (s.charAt(i) != expected) {
                diff++;
            }
        }

        return Math.min(diff, s.length() - diff);
    }
}

var minOperations = function(s) {
    let diff = 0;

    for (let i = 0; i < s.length; i++) {
        const expected = i % 2 === 0 ? '0' : '1';
        if (s[i] !== expected) {
            diff++;
        }
    }

    return Math.min(diff, s.length - diff);
};

class Solution:
    def minOperations(self, s: str) -> int:
        diff = 0

        for i, char in enumerate(s):
            expected = '0' if i % 2 == 0 else '1'
            if char != expected:
                diff += 1

        return min(diff, len(s) - diff)

class Solution {
public:
    int minOperations(string s) {
        int diff = 0;

        for (int i = 0; i < static_cast<int>(s.size()); i++) {
            char expected = (i % 2 == 0) ? '0' : '1';

            }

        return min(diff, static_cast<int>(s.size()) - diff);

替代方案

可以同时维护两个计数器，分别与 0101… 和 1010… 比较。这种写法更直观，但第二个计数器并非必需，因为每一位对两个候选必定“一边匹配、一边错位”。

也可以先构造两个目标字符串再比较，不过会使用 O(n) 额外空间，没有必要。

常见错误

  • 只统计相邻相等的对数；一次翻转可能同时影响左右两对，不能直接等价。
  • 只尝试从 0 开始的候选，漏掉从 1 开始可能更优的情况。
  • 把字符 '0'、'1' 与数字 0、1 混用。
  • 额外修改字符串；本题只需计数，不必真正执行翻转。

面试追问

  • 如果字符集不止 0/1？ 需要明确交替规则；若只要求相邻不同，候选不再只有两个。
  • 如果翻转不同位置的成本不同？ 分别累加两个候选中错位位置的权重，再取最小值。
  • 如果允许旋转字符串？ 偶数长度可用双倍字符串与滑动窗口统计；奇数长度的处理会不同。

一句话记忆

交替二进制串只有两个候选；统计到其中一个的汉明距离，另一个就是补集距离，取二者最小值。
