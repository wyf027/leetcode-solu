3852. 不同频率的最小数对

先锁定最小值 x，再在右侧找第一个频率不同的值 y。可视化会把“先选 x、再选 y”的字典序优先级直接显示出来。

题意

给定整数数组 nums，选择两个不同值 x < y，且它们在数组中出现次数不同。先让 x 尽可能小；在同一 x 下再让 y 尽可能小。不存在时返回 [-1, -1]。

频率只与值出现的次数有关；排序后的不同值让“最小优先”的规则可以顺序执行。

官方示例

nums = [1, 1, 2, 2, 3, 4]
输出：[1, 3]
nums = [1, 5]
输出：[-1, -1]

约束：1 ≤ nums.length ≤ 100，1 ≤ nums[i] ≤ 100。

交互：频率阶梯

输入逗号分隔的整数。用“下一步”观察最小值如何成为锚点，再寻找第一个不同频率。

空格会被忽略；仅接受 1 到 100 的整数。

准备就绪：先统计每个不同值的出现次数。

完整过程

1用哈希表统计每个值的频率。
2将不同值升序排列；第一个值就是唯一的最小候选 x。
3从它右边依序找第一个频率不相同的值，立即返回。

边界与复杂度

nums 只有一个不同值，或所有不同值频率相同：没有合法数对。

设不同值数量为 k：计数 O(n)，排序 O(k log k)，扫描 O(k)；空间 O(k)。

题解：排序后的首次分歧

题目按 (x, y) 的字典序要求最小答案。因而无需枚举所有数对：最小不同值必然是唯一应尝试的 x。只要从第二个不同值开始找第一个频率不同者，就已经得到最小 y。

替代方案与面试追问

由于数值范围是 1..100，也可用长度 101 的频率数组并直接从小到大扫描，复杂度是 O(n + 100)。若值域扩大，哈希表加排序更通用。追问：若要返回全部频率不同的数对，应如何避免二次枚举？可按频率分组后组合。

常见错误

  • 只找任意频率不同的两个值，忽略先最小化 x。
  • 未对不同值排序，哈希表遍历顺序不保证字典序。
  • 把值不同误当成频率不同。
