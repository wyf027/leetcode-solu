寻找文件副本

一个长度为 n 的整数数组中，所有数字都在 [0, n - 1] 范围内。数组中某些数字重复，找出任意一个重复的数字。

原地交换数组O(1) 空间

示例

输入：documents = [2, 3, 1, 0, 2, 5, 3]
输出：2 或 3

说明：2 和 3 都在数组中出现了两次。

约束

  • 2 ≤ documents.length ≤ 100000
  • 数组元素均在 [0, n - 1] 内。
  • 至少存在一个重复数字；返回任意一个即可。

分步交互：让数字回到自己的下标

目标是使 documents[i] = i。当前下标的值若不在正确位置，就与它应在的位置交换；若该位置已有相同值，就找到重复项。

核心洞察

数值范围刚好对应下标范围。对于下标 i，值 x 的正确位置就是 x。当 documents[x] 已经等于 x 时，两个相同的值发生了碰撞，x 就是答案。

复杂度

每次交换至少让一个数字归位，因此总操作次数是线性的：时间 O(n)；除少量变量外不需要额外容器：空间 O(1)。

完整过程

  1. 从下标 0 开始遍历数组。
  2. 若 documents[i] == i，该位置正确，继续下一个下标。
  3. 否则令 x = documents[i]：若 documents[x] == x，返回 x。
  4. 若未重复，交换 documents[i] 与 documents[x]，继续检查当前下标。

边界情况

  • 重复项可以是 0。
  • 多个重复数字时，返回先碰撞到的任意一个。
  • 全排列直到末尾才发现重复也无需特殊处理。

替代方案

哈希集合可在一次扫描中找到重复项，代码更直观，但需要 O(n) 额外空间。排序后比较相邻元素也可行，却会改变顺序且需要 O(n log n) 时间。

追问与常见错误

          
追问

          
    
            
  • 若不能修改数组，使用哈希集合或 Floyd 判圈思路。
    • 
            
  • 若数组值域不等于下标范围，原地交换前提不再成立。
    • 
          

          
常见错误

          
    
            
  • 交换一次后直接递增下标，遗漏了新换来的值。
    • 
            
  • 
              没有先判断 documents[x] == x，导致重复项被错误交换。
            
    •
