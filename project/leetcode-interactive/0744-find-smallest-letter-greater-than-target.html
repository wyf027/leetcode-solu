Problem 744

寻找比目标字母大的最小字母

Find Smallest Letter Greater Than Target

01 · The brief

题目说明

在一个已经排好序的字母表里，找到严格越过目标字母的第一个位置。

题意

给定一个按非递减顺序排列的字符数组 letters，以及一个字符 target。数组中至少存在两个不同的字符。

返回 letters 中按字典序严格大于 target 的最小字符。如果不存在这样的字符，则环绕到数组开头，返回 letters[0]。

官方函数形式：nextGreatestLetter(letters, target) → character

  • 2 ≤ letters.length ≤ 104
  • letters[i] 是小写英文字母。
  • letters 按非递减顺序排列，允许重复。
  • letters 至少包含两个不同字母。
  • target 是小写英文字母。

04 · Solution

准备好核对思路了吗？

题解默认收起。展开后可查看证明、复杂度、四种语言实现与面试追问。

!

核心洞察：找右侧边界，而不是找目标本身

真正要找的是第一个满足 letters[i] > target 的位置。由于数组有序，条件 letters[i] > target 会从某个位置开始持续成立，因此可以对这个真假分界做二分查找。 若分界落在数组末尾之后，用 left % n 自然环绕到索引 0。

完整过程

  1. 初始化半开区间 [left, right) = [0, n)。
  2. 取 mid = left + floor((right - left) / 2)。
  3. 若 letters[mid] ≤ target，答案一定在右侧，令 left = mid + 1。
  4. 否则当前项可能是答案，保留它并令 right = mid。
  5. 当 left == right 时，它就是第一个严格大于目标的位置；返回 letters[left % n]。

正确性证明

维护不变式：索引小于 left 的元素都不大于 target；索引不小于 right 的已知数组位置都大于 target。

若中点值不大于目标，丢弃 [left, mid] 不会漏掉答案；若中点值大于目标，令 right = mid 会保留中点及其左侧可能更小的合格字符。因此每轮都保持不变式且区间严格缩短。 终止时 left == right，该位置正是第一个大于目标的索引。若位置等于 n，说明数组内无合格字符，取模后返回首项，符合环绕规则。

边界情况

  • 目标小于首项：搜索停在索引 0，直接返回首项。
  • 目标等于某些项：使用 ≤ 向右移动，跳过全部相等项。
  • 目标大于等于末项：搜索停在 n，取模环绕到 0。
  • 存在重复字母：寻找的是第一个严格大于目标的位置，重复不影响正确性。

复杂度

O(log n)时间：每轮将候选区间减半。
O(1)空间：只使用几个索引变量。

四语言完整代码

class Solution {
    public char nextGreatestLetter(char[] letters, char target) {
        int left = 0;
        int right = letters.length;

        while (left < right) {
            int mid = left + (right - left) / 2;
            if (letters[mid] <= target) {
                left = mid + 1;
            } else {
                right = mid;
            }
        }

        return letters[left % letters.length];
    }
}

替代方案

可以从左到右线性扫描，返回遇到的第一个大于 target 的字符，否则返回首项。它更直观，时间复杂度为 O(n)，空间复杂度仍为 O(1)。在输入很小或数组无序时更容易改造；但本题明确给出有序数组，二分更能利用条件。

标准库也可使用“上界”操作：C++ 的 upper_bound、Java 的自定义上界搜索、Python 的 bisect_right。面试中最好能解释其内部仍是同一个二分边界模型。

常见错误

  • 使用 letters[mid] < target，导致可能返回与目标相等的字符。
  • 把 right 初始化为 n - 1，却继续套用半开区间更新方式。
  • 搜索结束后直接访问 letters[left]，忽略 left == n 的环绕情况。
  • 先去重再搜索，增加无必要的时间和空间，并掩盖边界理解。

面试追问

为什么判断条件是 ≤，不是 <？

因为题目要求严格大于目标。中点与目标相等时，它也不合格，必须连同更左侧一起排除。

为什么使用半开区间 [left, right)？

它允许把 right 初始化为 n，因此“答案不存在”可由 left == n 自然表达；每次更新也不需要额外保留答案变量。

如果数组不是有序的怎么办？

真假条件不再具有单调性，不能直接二分。应线性扫描所有字符，维护当前最小且严格大于目标的候选。

如何扩展到大量查询？

保持数组有序，对每个查询独立做上界搜索，单次 O(log n)。若字符集始终只有 26 个小写字母，也可预处理每个目标字母的下一字符。
