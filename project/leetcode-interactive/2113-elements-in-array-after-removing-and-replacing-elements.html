查询删除和添加元素后的数组

Elements in Array After Removing and Replacing Elements

让时间前进，看元素离开，再依次回来。先观察数组，最后再揭开规律。

01 / 题目说明

从 0 开始计时与索引

给定初始整数数组 nums。第 0 分钟它保持原样。随后每分钟删除当前最左侧的一个元素，直到数组为空；接着每分钟将一个元素追加到末尾，追加顺序与刚才删除的顺序相同。恢复初始数组后，继续重复这两段操作。

每条查询 queries[j] = [time_j, index_j] 要求得到第 time_j 分钟的数组在下标 index_j 处的值；若该位置不存在，返回 -1。返回与查询顺序对应的整数数组。查询只读取状态，不改变数组。

函数：elementInNums(nums: integer[], queries: integer[][]) → integer[]

官方示例 1

nums = [0,1,2]
queries = [[0,2],[2,0],[3,2],[5,0]]
输出 = [2,2,-1,0]

时刻 0、2、3、5 的数组分别为 [0,1,2]、[2]、[]、[0,1]。依次读取指定位置，第三条查询越界。

官方示例 2

nums = [2]
queries = [[0,0],[1,0],[2,0],[3,0]]
输出 = [2,-1,2,-1]

数组在 [2] 与 [] 之间交替，空数组没有下标 0。

约束

  • 1 ≤ nums.length ≤ 100，0 ≤ nums[i] ≤ 100。
  • n == queries.length，1 ≤ n ≤ 10⁵，每条查询长度为 2。
  • 0 ≤ time_j ≤ 10⁵，0 ≤ index_j < nums.length。此处上界是初始长度，当前长度可能更短。

04 / 题解：时间取模，再映射下标

核心洞察

令初始长度为 m，查询数为 q。删除 m 次后为空，再添加 m 次后恢复原数组与下一步动作，因此整个状态每 2m 分钟重复。元素相等也不会改变删除与添加的操作节奏。将查询时间压缩为 r = time % (2m) 后，当前数组永远是原数组的一段后缀或前缀。

0 ≤ r < m：当前数组 nums[r … m-1]，长度 m-r m ≤ r < 2m：当前数组 nums[0 … r-m-1]，长度 r-m 删除段：index < m-r ? nums[r+index] : -1 回填段：index < r-m ? nums[index] : -1

完整过程

  1. 保留原数组，不实际删除或追加元素。
  2. 逐条读取 [time, index]，计算余数 r。
  3. 若 r < m，已有 r 个头部元素被移走；合法位置 i 对应原位置 r+i。
  4. 否则已回填 r−m 个元素；合法位置 i 仍对应原位置 i。
  5. 先判定 i 是否严格小于当前长度，再读取；否则填 −1。按原查询顺序返回结果。

示例 1 中 m=3。四条查询的余数依次为 0、2、3、5：读取原下标 2、2，遇到空数组返回 −1，最后从长度为 2 的前缀读取下标 0，得到 [2,2,−1,0]。

正确性证明

周期性：从完整数组开始，m 次头删按原顺序移走全部元素；接着 m 次尾部追加按同一顺序还原全部元素，此时下一个动作仍为头删。故时间 t 与 t mod 2m 的数组及后续过程相同。

区间不变式：删除段第 r 步后恰好删除原位置 0 到 r−1，故留下 nums[r…m−1]；添加段第 k 步后恰好追加原位置 0 到 k−1，故得到 nums[0…k−1]。两者都可由每步只删头或添尾归纳得到。

查询结论：分支中的长度判断恰好判断该位置是否存在；存在时对应下标由上述区间确定，不存在时返回 −1。因此每条查询正确，逐条处理得到正确答案数组。

边界与常见错误

  • r=0 是完整数组；r=m 是空数组，此时回填长度为 0。
  • time=2m 已恢复完整数组，取模后为 0。
  • index == 当前长度 已越界；应使用严格小于，不能使用小于等于。
  • 删除是从头部发生，回填是按原顺序追加到尾部；不能倒序恢复，也不能认为回填会同时删除。
  • 查询下标合法于初始数组，不代表合法于当前数组；零是有效元素，不能用真假值判断元素存在。
  • 查询可能乱序或重复，各条独立读取，不能沿输入顺序维护一个只前进的模拟时钟。
  • m≥1，不存在取模零问题。当前约束下整数计算在四种语言中均能表示；若时间扩展到更大，Java/C++ 应考虑 64 位，JS 超过安全整数需 BigInt。

复杂度

每条查询常数次算术和一次读数组，时间 O(q)。除返回数组外额外空间 O(1)，返回数组占 O(q)；无需修改 nums。

替代方案

可以预存一个周期的所有数组再查询，预处理时间与空间为 O(m²)，查询 O(1)，但这些数组已经能用两个端点表示。也可以将查询按时间排序后用双端队列逐分钟模拟，约 O(q log q + T + m)，其中 T 为最大时间；实现更长且需恢复查询顺序。直接取模映射更适合本题。

Java

class Solution {
    public int[] elementInNums(int[] nums, int[][] queries) {
        int m = nums.length;
        int[] answer = new int[queries.length];
        for (int j = 0; j < queries.length; j++) {
            int r = queries[j][0] % (2 * m);
            int i = queries[j][1];
            if (r < m) {
                answer[j] = i < m - r ? nums[r + i] : -1;
            } else {
                answer[j] = i < r - m ? nums[i] : -1;
            }
        }
        return answer;
    }
}

Python

from typing import List

class Solution:
    def elementInNums(self, nums: List[int],
                      queries: List[List[int]]) -> List[int]:
        m = len(nums)
        answer = []
        for time, i in queries:
            r = time % (2 * m)
            if r < m:
                answer.append(nums[r + i] if i < m - r else -1)
            else:
                answer.append(nums[i] if i < r - m else -1)
        return answer

C++

#include <vector>
using namespace std;

class Solution {
public:
    vector<int> elementInNums(vector<int>& nums,
                              vector<vector<int>>& queries) {
        int m = static_cast<int>(nums.size());
        vector<int> answer;
        answer.reserve(queries.size());
        for (const auto& query : queries) {
            int r = query[0] % (2 * m);
            int i = query[1];
            if (r < m) {
                answer.push_back(i < m - r ? nums[r + i] : -1);
            } else {
                answer.push_back(i < r - m ? nums[i] : -1);
            }
        }
        return answer;
    }
};

面试追问

  • 能否不排序查询？可以。状态只由时间决定，取模后直接计算，与上一次查询无关。
  • 每分钟处理 k 个元素怎么办？先明确最后不足 k 个时是否仍占一分钟，再重新推导阶段时长与端点；不能直接沿用 2m。
  • 恢复顺序变成逆序呢？一次恢复后数组可能反转，原来的 2m 状态周期证明失效，需要把方向也计入状态。
  • 为何不按数值寻找元素？重复值不影响位置映射；本题问的是当前下标，不是元素身份搜索。
