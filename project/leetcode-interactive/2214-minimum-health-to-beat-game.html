01 / 任务说明

数组 damage 给出每一关造成的生命损失。必须依照下标 0 到 n − 1 的顺序完成全部关卡；从开始到结束，生命值都必须严格大于 0。你有一次可选的护甲机会，可以在某一关抵消至多 armor 点伤害，但不能抵消超过该关原本的伤害，也不能把剩余额度留给另一关。返回能够通关的最小初始生命值。

函数契约

minimumHealth(damage: integer[], armor: integer)
→ long

输入不会改变。下标从 0 开始；说明中的“第几关”从 1 开始。

约束

  • n == damage.length
  • 1 ≤ n ≤ 10⁵
  • 0 ≤ damage[i] ≤ 10⁵
  • 0 ≤ armor ≤ 10⁵

05 / 独立题解

准备好后再打开：思路、证明与四语言实现。

核心洞察：只需累计总伤害与最大单关伤害

设总伤害为 S，最大单关伤害为 M。在第 j 关使用护甲，节省的生命是 min(damage[j], armor)。这个量随该关伤害增大而不减，所以在最大伤害关使用护甲一定最优。由于每次实际扣血都非负，生命值不会回升，最后一关结束时的生命值就是全程最低值。

Minimum starting health

S − min(M, armor) + 1

最后的 +1 保证严格存活；生命值等于 0 已经失败。

完整过程

  1. 初始化总和 total = 0，最大值 peak = 0。
  2. 依次读取每个伤害 d，将 d 加入 total，并以 max(peak, d) 更新 peak。
  3. 一次护甲最多节省 min(peak, armor)。从总伤害中减去这个数。
  4. 再加 1，即为所需最小初始生命值。

示例 1 的扫描状态 (total, peak) 为 (0,0) → (2,2) → (9,7) → (13,7) → (16,7)。可抵消 min(7,4) = 4，答案为 13。把护甲用在第 2 关时，生命轨迹为 13 → 11 → 8 → 4 → 1；官方示例在第 3 关使用也同样最优，因为该关已足够消耗全部 4 点护甲。

正确性证明

下界：任何策略只能在一关抵消伤害，抵消量不超过 min(M, armor)，因此总扣血至少为 S − min(M, armor)。最终仍需生命值 ≥ 1，所以初始生命值至少为该数加 1。

可达：在一处最大伤害关使用护甲，恰好达到上述抵消量。取初始生命值为 S − min(M, armor) + 1，最终剩余 1。所有关的实际伤害非负，任意前缀扣血都不超过总扣血，因此之前的生命值也都至少为 1。这个下界能够实现，故答案最优。

边界与数值范围

  • armor = 0：没有抵消，答案为 S + 1。
  • 全零数组：无论护甲多少，都必须从 1 开始。
  • 单个关卡：答案为 max(0, damage[0] − armor) + 1。
  • 护甲超过单关伤害时不能回血；多余护甲浪费，不能挪到别的关卡。
  • 最大值重复可任选一个。甚至不取最大值也可能最优：当伤害已不小于 armor 时，抵消量已达上限。
  • S 最大为 10¹⁰，答案最大可到 10000000001。Java 用 long、C++ 用 long long；Python 整数无需额外处理；JavaScript Number 可精确表示这里的整数，避免使用会转为 32 位的位运算。

复杂度

一次扫描，时间 O(n)，额外空间 O(1)。不排序、不复制数组。读取全部元素在最坏情况下不可避免。

替代方案

枚举护甲落点并逐关模拟是 O(n²)，便于理解但会超时；先求总和，再枚举每关抵消量可以降为 O(n)，与维护最大值等价。二分初始生命值配合“是否可通关”的判定也能做，但多了对数因子与判定状态。按伤害排序需要 O(n log n)，对此题没有必要，也不应按排序后的顺序误述实际关卡过程。

四语言完整实现

均为 LeetCode 提交形式，函数名与官方元数据一致；不包含本地输入驱动。代码未编译、未运行。

Java

class Solution {
    public long minimumHealth(int[] damage, int armor) {
        long total = 0L;
        int peak = 0;
        for (int d : damage) {
            total += d;
            peak = Math.max(peak, d);
        }
        return total - Math.min(peak, armor) + 1L;
    }
}

常见错误

  • 直接减去 armor：护甲不能抵消超过单关伤害的数值。
  • 忘记 +1：生命降到 0 不能算通关。
  • 每关都减一次 armor：护甲只能使用一次。
  • 使用 32 位整数累加：伤害数组较长时会溢出。
  • 认为最优落点只能是最大伤害关：最大值一定可选，但不是唯一可能。
  • JavaScript 用 Math.max(...damage)：大数组展开存在参数数量上限，循环更稳妥。

面试追问

可以使用 k 次护甲呢？如果每关至多一次且每次有同样额度，取最大的 k 个单关抵消量；可用大小为 k 的堆，空间 O(k)。若有回血关呢？生命不再单调，总和不够，需要考虑最大前缀净损失；护甲落点也需重新分析。只关心最终答案，关卡能重排会改变结果吗？在本题非负伤害和单次护甲规则下不会，但题目仍要求原顺序通关。
