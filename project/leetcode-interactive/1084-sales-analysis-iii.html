销售分析 III

Sales Analysis III · 找出所有销售记录都严格落在 2019 年第一季度内的商品。

EASY数据库分组聚合区间边界

题目

给定商品表 Product 与销售表 Sales，报告那些只在 2019 年第一季度销售过的商品，也就是该商品的每一条销售日期都位于 2019-01-01 至 2019-03-31（含端点）。结果可按任意顺序返回 product_id 和 product_name。

Sales

列类型说明

约束

  • Product.product_id 唯一；Sales.product_id 引用商品表。
  • Sales 可能出现重复行。
  • 日期判断包含 2019-01-01 与 2019-03-31 两个端点；官方元数据未列出额外数值范围。

官方示例（完整参数形式）

输入：
Product = [[1,"S8",1000],[2,"G4",800],[3,"iPhone",1400]]
Sales = [[1,1,1,"2019-01-21",2,2000],
         [1,2,2,"2019-02-17",1,800],
         [2,2,3,"2019-06-02",1,800],
         [3,3,4,"2019-05-13",2,2800]]

输出： [[1,"S8"]]

商品 1 的销售日期全部在第一季度；商品 2 虽在第一季度卖过，但六月也卖过；商品 3 只在五月出现。因此只有商品 1 合格。

题解

核心洞察

“只在区间内销售”包含两个条件：至少有销售记录，并且所有销售日期都在闭区间内。按商品分组后，等价于最早日期不早于起点，且最晚日期不晚于终点。

MIN(sale_date) >= '2019-01-01' AND MAX(sale_date) <= '2019-03-31'

完整过程

  1. 将 Product 与 Sales 按 product_id 内连接；没有销售记录的商品自然不会出现。
  2. 按商品编号与名称分组。
  3. 计算组内最早、最晚日期，并在 HAVING 中检查闭区间边界。

正确性证明

充分性：若某组最早日期 ≥ 起点且最晚日期 ≤ 终点，那么组内任意日期都夹在最早与最晚之间，故所有销售均在第一季度。

必要性：若商品只在第一季度销售，其每条日期都在闭区间中，因此其中最早日期不会早于起点，最晚日期也不会晚于终点。算法恰好选中且只选中目标商品。

边界情况

  • 恰好在 1 月 1 日或 3 月 31 日销售：应保留。
  • 区间内有很多次销售但没有越界：保留。
  • 只要存在一次区间外销售，即使也在区间内卖过：淘汰。
  • 完全没有销售记录：不属于“只在该季度售出”的商品。
  • 重复销售行不会改变最早/最晚日期判定。

复杂度

设销售记录数为 S。数据库执行代价取决于执行计划与索引；典型哈希聚合约为时间 O(S)、额外空间 O(P)（P 为有销售的商品数）。

官方可提交语言：MySQL

SELECT p.product_id, p.product_name
FROM Product AS p
JOIN Sales AS s ON s.product_id = p.product_id
GROUP BY p.product_id, p.product_name
HAVING MIN(s.sale_date) >= '2019-01-01'
   AND MAX(s.sale_date) <= '2019-03-31';

四语言本地语义参考

本题是数据库题，LeetCode 应提交 SQL。以下四份代码完整演示相同的内存分组语义，但不是本题官方提交语言。

import java.util.*;

class Solution {
  List<List<Object>> salesAnalysis(List<List<Object>> product,
                                    List<List<Object>> sales) {
    Map<Integer, List<String>> dates = new HashMap<>();
    for (List<Object> s : sales)
      dates.computeIfAbsent((Integer)s.get(1), k -> new ArrayList<>())
           .add((String)s.get(3));
    List<List<Object>> ans = new ArrayList<>();
    for (List<Object> p : product) {
      List<String> ds = dates.get((Integer)p.get(0));
      if (ds != null && ds.stream().allMatch(d ->
          d.compareTo("2019-01-01") >= 0 && d.compareTo("2019-03-31") <= 0))
        ans.add(Arrays.asList(p.get(0), p.get(1)));
    }
    return ans;
  }
}
function salesAnalysis(product, sales) {
  const dates = new Map();
  for (const [, productId, , saleDate] of sales) {
    if (!dates.has(productId)) dates.set(productId, []);
    dates.get(productId).push(saleDate);
  }
  return product
    .filter(([id]) => dates.has(id) && dates.get(id).every(
      d => d >= "2019-01-01" && d <= "2019-03-31"))
    .map(([id, name]) => [id, name]);
}
from collections import defaultdict

def sales_analysis(product, sales):
    dates = defaultdict(list)
    for _, product_id, _, sale_date, _, _ in sales:
        dates[product_id].append(sale_date)
    return [[product_id, name] for product_id, name, _ in product
            if product_id in dates and all(
                "2019-01-01" <= date <= "2019-03-31"
                for date in dates[product_id])]
#include <algorithm>
#include <string>
#include <unordered_map>
#include <vector>
using namespace std;

struct Product { int id; string name; int unitPrice; };
struct Sale { int sellerId, productId, buyerId; string date; int quantity, price; };

vector<pair<int,string>> salesAnalysis(const vector<Product>& products,
                                        const vector<Sale>& sales) {
  unordered_map<int, vector<string>> dates;
  for (const auto& s : sales) dates[s.productId].push_back(s.date);
  vector<pair<int,string>> ans;
  for (const auto& p : products) {
    auto it = dates.find(p.id);
    if (it != dates.end() && all_of(it->second.begin(), it->second.end(),
        [](const string& d) { return d >= "2019-01-01" && d <= "2019-03-31"; }))
      ans.push_back({p.id, p.name});
  }
  return ans;
}

替代方案

可用 NOT EXISTS 排除存在区间外销售的商品，并再用 EXISTS 保证确实卖过；也可条件聚合统计越界记录数为 0。MIN/MAX 最紧凑，但 NOT EXISTS 往往更直观地表达“没有反例”。

面试追问

  • 如果季度边界由参数给出，如何避免时区或时间戳的末日边界问题？可用半开区间 [start, nextQuarter)。
  • 若要同时返回季度内销量，怎样避免把区间外记录提前过滤掉而误判？先保留全量记录判资格，再条件聚合销量。
  • 什么索引有帮助？通常可考虑 Sales(product_id, sale_date)。

常见错误

  • 在 WHERE 中只保留第一季度记录：会看不到同一商品的越界销售。
  • 只判断“存在一条季度内记录”，误把商品 2 算入。
  • 使用严格不等号，错误排除两个边界日。
  • 用左连接却未排除无销售商品，且忽略空值聚合语义。
