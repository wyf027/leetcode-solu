Paths in Maze That Lead to Same Room

走过三条走廊，回到出发的房间。换一个起点，或反着走，算不算一条新路线？先读题，再动手推演。

01 / 题目

迷宫有 n 个房间，编号为 1…n。数组 corridors 中的每个 [u, v] 表示一条可以双向通行的走廊。

请返回迷宫中不同的长度为 3 的环的数量，即经过三个不同房间、走三条走廊后回到起点。只要使用的房间集合相同，就视作同一个环，起点和行走方向不影响计数。

例如 1 → 2 → 3 → 1 与 3 → 2 → 1 → 3 是同一个环；1 → 2 → 3 → 4 没有回到起点，不计入答案。

接口
numberOfPaths(n: integer, corridors: integer[][]) → integer

约束

  • 2 ≤ n ≤ 1000
  • 1 ≤ corridors.length ≤ 5 × 10⁴
  • corridors[i].length = 2
  • 每个端点编号在 1…n 中，且同一条走廊的两个端点不同。
  • 不存在重复走廊；走廊是无向边。

02 / 官方示例

示例 1

n = 5
corridors = [[1,2],[5,2],[4,1],[2,4],[3,1],[3,4]]
输出 = 2

两个房间集合分别是 {1, 2, 4} 和 {1, 3, 4}。重复从同一集合的其他房间出发，不增加答案。

示例 2

n = 4
corridors = [[1,2],[3,4]]
输出 = 0

两条走廊彼此分离，无法构成长度为 3 的环。

04 / 独立题解

准备好后，展开思路、交互推演与四语言实现。

给每个环一个唯一的编号顺序

核心洞察：长度为 3 的环就是三个房间两两相连。将编号固定为 u < v < w，每个环只在它最小的两个房间组成的走廊上被计数一次。

完整过程

  1. 建立无向邻接矩阵 adj，让查询两房间是否相连成为常数时间操作。
  2. 依次枚举每条走廊，将两个端点规范为 u = min(a,b)、v = max(a,b)。不修改输入数组。
  3. 枚举 w = v + 1…n。边 u—v 已存在，只需检查 u—w 和 v—w。
  4. 两条边均存在时答案加一；扫描全部走廊后返回答案。

示例 1 的计数路径

对于边 (1,2)，候选 3 缺少边 2—3；候选 4 与两端均相连，记录 {1,2,4}；候选 5 缺少边 1—5。对于边 (1,3)，候选 4 同时连接 1 和 3，记录 {1,3,4}。其余走廊没有合格的更大编号候选，最终为 2。

正确性证明

  • 可靠性：一次累加对应 u—v、u—w、v—w 三条真实存在的边，且 u < v < w 保证房间互异，因此确实形成一个合法三环。
  • 完整性：任取合法环，将三个编号排序为 a < b < c。枚举到必然存在的走廊 (a,b) 时，候选 c 会被遍历，两次邻接查询均成立，所以该环一定被统计。
  • 唯一性：同一组三个编号只有一个递增顺序。边 (a,c) 的候选不能是 b，边 (b,c) 的候选不能是 a，因为候选必须大于边的较大端点。走廊又无重复，因此该环恰计一次。

复杂度与边界

令 m = corridors.length。矩阵初始化耗时 O(n²)，建边 O(m)，扫描不超过 mn 次，因此总时间为 O(n² + mn)，额外空间为 O(n²)。此实现选择直接的矩阵查询，在题目上限下最多扫描约 5 × 10⁷ 个候选；实际耗时待补验证。

n = 2 时没有第三个房间；无环图及仅含长环的图返回 0；不连通图无需特殊处理；共享边的不同三环分别计数。上界 C(1000,3) = 166,167,000，足以说明答案可存入 32 位有符号整数，JavaScript Number 也可精确表示。

Java

class Solution {
    public int numberOfPaths(int n, int[][] corridors) {
        boolean[][] adj = new boolean[n + 1][n + 1];
        for (int[] edge : corridors) {
            adj[edge[0]][edge[1]] = true;
            adj[edge[1]][edge[0]] = true;
        }
        int answer = 0;
        for (int[] edge : corridors) {
            int u = Math.min(edge[0], edge[1]);
            int v = Math.max(edge[0], edge[1]);
            for (int w = v + 1; w <= n; w++) {
                if (adj[u][w] && adj[v][w]) {
                    answer++;
                }
            }
        }
        return answer;
    }
}

from typing import List

class Solution:

        self, n: int, corridors: List[List[int]]
    ) -> int:
        adj = [bytearray(n + 1) for _ in range(n + 1)]
        for a, b in corridors:
            adj[a][b] = adj[b][a] = 1

        answer = 0
        for a, b in corridors:
            u, v = min(a, b), max(a, b)
            row_u, row_v = adj[u], adj[v]
            for w in range(v + 1, n + 1):
                if row_u[w] and row_v[w]:
                    answer += 1
        return answer

替代方案

  • 三重枚举：直接枚举 u < v < w 并检查三条边。时间 O(n³)，空间 O(n²)，容易理解但会扫描没有基础走廊的三元组。
  • 公共邻居集合：对每条边，遍历较小的邻居集合，查询另一个集合。每个三环在三条边处各出现一次，最后除以 3；哈希查询按期望 O(1) 计算，时间 O(n + m + Σ min(deg(u),deg(v)))，空间 O(n+m)。若使用编号过滤避免重复，则不能再除以 3。
  • 按度数定向：按 (度数, 编号) 给节点建立全序，只保留向更高顺序节点的边，再求出邻居交集。可将三角形计数优化到 O(n + m√m) 量级，适合规模更大的稀疏图；本题的直接实现更短。

常见错误

  • 只存单向邻接，导致输入端点颠倒时漏计。
  • 把起点和方向当成不同环，重复统计同一组三个房间。
  • 已经限制 u < v < w，却仍除以 3 或 6。
  • 只检查两条边，没有确认三条边闭合；连通不等于存在三环。
  • 使用普通 DFS 的全局 visited 找环，无法枚举所有互相重叠的三环。
  • 在 JavaScript 中用 fill 创建共享行，或在 Python 中重复引用同一行，导致矩阵各行相互污染。

面试追问

  • 如何输出所有环？累加时保存 [u,v,w]；额外空间增加 O(T)，T 是环的数量。
  • 动态添加一条走廊会怎样？一条原本不存在的边 (u,v) 会新增 |N(u) ∩ N(v)| 个三环；先求交集再更新邻接关系。
  • 长度改成 4 呢？三个房间两两相连的判定不再适用，需要新的枚举与去重方式，不能直接复用本题计数公式。
  • 有重边或自环呢？要先明确“不同环”的定义；若按不同房间集合计数，可先移除自环并对无向边去重。
