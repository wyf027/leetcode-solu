2410. 运动员和训练师的最大匹配数

Maximum Matching of Players With Trainers

每一份训练资源只能交给一个人。你能让多少名运动员找到合适的训练师？

查看 LeetCode 原题 ↗

题目 · 一对一的能力匹配

给定两个下标从 0 开始的整数数组：players[i] 是第 i 名运动员的能力值，trainers[j] 是第 j 位训练师的训练能力值。只有当 players[i] ≤ trainers[j] 时，两者才能匹配。

每名运动员至多匹配一位训练师，每位训练师至多匹配一名运动员。返回能同时成立的最大匹配数量，无需返回具体配对。

先自己想一想

训练师能力足够就可以配对，但如何安排，才能把有限的名额用得最多？题解与演示默认收起。

参数与约束

  • matchPlayersAndTrainers(players, trainers) → integer
  • 1 ≤ players.length, trainers.length ≤ 10⁵
  • 1 ≤ players[i], trainers[j] ≤ 10⁹
  • 能力值可以重复；值相同的人仍是不同个体。

官方示例

示例 1

players = [4,7,9]
trainers = [8,2,5,8]
输出：2

例如将原下标为 0 的运动员交给原下标为 0 的训练师，将运动员 1 交给训练师 3：4 ≤ 8、7 ≤ 8。能力为 9 的运动员没有合适的训练师，最多匹配 2 对。

示例 2

players = [1,1,1]
trainers = [10]
输出：1

唯一的训练师能带任意一名运动员，但只有一个名额。因此最多匹配 1 对。

题解 · 把最小够用的名额留给当前运动员

SORTING / GREEDY / TWO POINTERS

核心洞察

把两组能力值都从小到大排序。对于当前最弱的未匹配运动员，小于其能力的训练师连他都无法训练，更不可能服务后面更强的运动员，可以直接跳过。遇到第一个够用的训练师时立即匹配，就能保留更强的训练师。

完整过程

  1. 将 players 和 trainers 升序排序。
  2. 令 i = 0 指向尚未匹配的最弱运动员；依次扫描训练师 j。
  3. 若 players[i] ≤ trainers[j]，匹配成功，i++；否则跳过这个训练师。
  4. 每轮训练师指针都前进。运动员全部匹配或训练师耗尽时结束，i 就是答案。

为什么一定最优？

循环不变量：每次处理训练师前，已经选定的配对可以包含在某个全局最优方案中；被跳过的训练师对剩余运动员无用。

跳过是安全的：设当前最弱运动员为 p，最弱训练师为 t。如果 t < p，则所有剩余运动员都至少为 p，t 不可能参加任何剩余合法配对。

配对是安全的：如果 p ≤ t，考虑剩余问题的任一最优方案。如果 p 与 t 已配对，无需修改；若其中一个未匹配，可把另一个原来的配对替换为 p–t，数量不变。两者都未匹配则可以增加一对，与最优矛盾。若 p 配给 t′，而 t 配给 q，则用 p–t 和 q–t′ 替换：因为 t′ ≥ t ≥ q，新的两对都合法，数量不变。

因此总能找到包含当前贪心选择的最优方案。每步维持不变量，直到一侧耗尽，剩余部分无法再匹配，累计数量就是全局最大值。

边界与常见错误

  • 相等允许匹配，判断应为 ≤，不是 <。
  • 重复能力不能去重；每个元素代表一个独立名额。
  • 训练师太弱时只前进训练师指针，不能放弃当前运动员。
  • 读取 players[i] 前先判断 i 是否越界。
  • JavaScript 必须使用 sort((a, b) => a - b)；默认排序按字符串比较。
  • 下面代码均原地排序，会改变输入顺序；需要保留原数组时先复制。

复杂度

设运动员数为 n，训练师数为 m。排序为 O(n log n + m log m)，扫描为 O(n + m)，总时间由排序主导。双指针自身仅用 O(1) 额外空间；排序工作空间需另计：C++ 通常为 O(log n + log m) 栈空间；Java 原始整数数组排序取决于 JDK 实现，保守可按 O(n + m) 上界计；Python 排序最坏 O(n + m)，JavaScript 则取决于引擎实现，不能保证总额外空间为常数。

替代方案

可用有序多重集合保存训练师，对每名运动员查找并删除最小的够用值，时间约 O((n + m) log m)，额外空间 O(m)。也可建二分图求最大匹配，但这里的“能力阈值”让邻接关系有序，无需承担图算法的开销。值域达到 10⁹，不适合直接开计数数组。

面试追问

  • 要返回原下标配对？排序前保存 (能力值, 原下标)，每次成功匹配记录两个原下标。
  • 每位训练师能带 k 人？排序后保留剩余名额，耗尽后才前进训练师指针；当前运动员能力超过该训练师时直接跳过。
  • 输入已经有序？省略排序，扫描时间 O(n + m)、辅助空间 O(1)。
  • 如果匹配有收益权重？最大匹配数量不等于最大收益，当前交换论证不能直接推广，需要新的目标和算法。

Java

import java.util.Arrays;

class Solution {
    public int matchPlayersAndTrainers(int[] players, int[] trainers) {
        Arrays.sort(players);
        Arrays.sort(trainers);
        int i = 0;
        for (int capacity : trainers) {
            if (i == players.length) break;
            if (players[i] <= capacity) i++;
        }
        return i;
    }
}

        if (players[i] <= capacity) i++;
    }
    return i;
};

from typing import List

class Solution:
    def matchPlayersAndTrainers(
        self, players: List[int], trainers: List[int]
    ) -> int:
        players.sort()
        trainers.sort()
        i = 0
        for capacity in trainers:
            if i == len(players):
                break
            if players[i] <= capacity:
                i += 1
        return i

C++

#include <algorithm>
#include <vector>
using namespace std;

class Solution {
public:
    int matchPlayersAndTrainers(vector<int>& players,
                               vector<int>& trainers) {
        sort(players.begin(), players.end());
        sort(trainers.begin(), trainers.end());
        int i = 0;
        for (int capacity : trainers) {
            if (i == static_cast<int>(players.size())) break;
            if (players[i] <= capacity) ++i;
        }
        return i;
    }
};
