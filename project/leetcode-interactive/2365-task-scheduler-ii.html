任务调度器 II

Task Scheduler II

顺序不能变，日历该怎样安排？

先理解规则，再亲手推进日历。完整分析与四语言代码在页面底部按需展开。

01 / 题意与规则

给定从下标 0 开始的正整数数组 tasks，其中每个数代表一种任务类型。必须按数组顺序完成任务，每天只能完成下一个任务，或者休息。完成某类型任务后，至少要隔 space 个完整的日子，才能再次完成同类型任务。求完成整个数组所需的最少天数。

冷却期间可以执行其他类型的任务；“隔 space 天”指两次执行之间的天数，不包含执行当天。任务不能重排，也不能跳过队首去执行后面的任务。

约束

  • 1 ≤ tasks.length ≤ 10⁵
  • 1 ≤ tasks[i] ≤ 10⁹
  • 1 ≤ space ≤ tasks.length

返回值表示天数；官方返回类型为 long。题目内容依据随任务提供的官方元数据转述。

02 / 官方示例

示例 1

输入：tasks = [1,2,1,2,3,1], space = 3
输出：9

官方给出的一种安排：第 1、2 天执行任务下标 0、1；第 3、4 天休息；第 5、6 天执行下标 2、3；第 7 天休息；第 8、9 天执行下标 4、5。无法少于 9 天完成。

05 / 独立题解

准备好后，展开分析与完整代码。

核心洞察：把日期跳到最早可执行日

任务顺序固定，因此只需决定当前任务何时执行。设已完成前缀的最后一天为 day，该类型上次执行日为 last[x]。它既不能早于 day + 1，又不能早于 last[x] + space + 1。取两个下界的较大者，第一次出现的类型只受前一个下界限制。

day = day + 1
若 x 曾出现：day = max(day, last[x] + space + 1)
last[x] = day

完整过程

  1. 日期从 0 开始，哈希表为空。
  2. 按原顺序读取类型 x，先考虑紧接着的下一天。
  3. 如果这个日期尚未过冷却期，直接跳到允许日期；中间全部是不得不休息的日子。
  4. 写入 x 的最近执行日，继续下一个任务。最后的日期就是总天数。

示例 1 的执行日期依次为 1, 2, 5, 6, 7, 9。类型 1 在第 1 天执行后，只能从第 5 天起再次执行；第 5 天执行后，下一次至少要到第 9 天。

正确性：前缀最早完成的归纳证明

设贪心安排第 i 个任务的日期为 gᵢ，任意合法安排对应日期为 sᵢ。第一个任务贪心在第 1 天执行，必有 g₀ ≤ s₀。假设此前所有任务都有 gⱼ ≤ sⱼ。若当前类型的上一次出现下标为 p，则合法安排必须满足 sᵢ ≥ sᵢ₋₁ + 1 以及 sᵢ ≥ sₚ + space + 1。由归纳假设，贪心使用的两个下界分别不大于这两个值，因此 gᵢ ≤ sᵢ；首次出现时只有前一个下界。贪心每一步也满足这两个约束，因而合法。归纳得到最后一个任务不晚于任何合法安排，答案最优。

边界与数值范围

  • 只有一个任务时答案为 1；类型各不相同时答案为任务数量。
  • 所有 n 个任务相同时，答案为 1 + (n − 1) × (space + 1)。
  • 在最大约束下答案可达 10¹⁰，Java 使用 long，C++ 使用 long long。Python 整数自然支持；JavaScript Number 对该范围整数可精确表示。
  • space 为 1 时，相同类型不能连续两天执行。无需处理空数组或 space 为 0，它们不在本题约束内。
  • 类型值可达 10⁹，使用哈希表，不能直接按类型值开大数组。

复杂度

设 n 为任务数、k 为不同类型数。哈希表操作平均 O(1)，整体期望时间 O(n)，额外空间 O(k)。直接跳过休息段，运行时间不依赖最终天数。哈希表极端碰撞时不能保证最坏线性时间。

替代方案

  • 逐天模拟：容易理解，但时间 O(答案)，最大可达 10¹⁰ 步，无法适应完整约束。
  • 记录 nextAllowed[x]：存最早再执行日，执行日为 max(day + 1, nextAllowed[x])，执行后更新为 day + space + 1；与当前方法等价。
  • 有序映射：可以获得 O(n log k) 的确定性操作界，但本题一般无需付出额外开销。
  • 频次排序或最大堆适合研究可重排版本；这里顺序固定，不能直接套用任务调度器 I 的公式。

常见错误

  • 漏掉 +1：若第 1 天执行、space = 3，应在第 5 天再执行，而不是第 4 天。
  • 用数组下标差判断冷却：实际日期中包含休息，数组下标不能代替日期。
  • 未出现的类型默认 last = 0 后仍计算冷却下界，导致第一次任务也被迫等待。
  • 只记录所有类型共用的上次日期，或者更新为跳转前的日期，都会破坏记录含义。
  • 为填补空闲跳过队首、提前执行后续任务，违反必须按顺序完成的规则。

面试追问

  • 每种类型的冷却期不同？ 把 space 替换为该类型对应的冷却期，归纳证明仍成立。
  • 输入作为流到达？ 只保留 day 与哈希表，读取一个任务即可推进一次，无需存整个数组。
  • 需要输出完整日程？ 返回“休息区间 + 执行事件”的压缩形式；逐天展开需要 O(答案) 输出量。
  • 任务允许重排？ 前缀归纳的固定顺序前提消失，需要重新建模，不能沿用这一递推的最优性结论。

Java

import java.util.HashMap;
import java.util.Map;

class Solution {
    public long taskSchedulerII(int[] tasks, int space) {
        Map<Integer, Long> last = new HashMap<>();
        long day = 0;
        for (int task : tasks) {
            day++;
            Long previous = last.get(task);
            if (previous != null) {
                day = Math.max(day, previous + space + 1L);
            }
            last.put(task, day);
        }
        return day;
    }
}

C++

#include <vector>
#include <unordered_map>
#include <algorithm>
using namespace std;

class Solution {
public:
    long long taskSchedulerII(vector<int>& tasks, int space) {
        unordered_map<int, long long> last;
        long long day = 0;
        for (int task : tasks) {
            ++day;
            auto it = last.find(task);
            if (it != last.end()) {
                day = max(day, it->second + space + 1LL);
            }
            last[task] = day;
        }
        return day;
    }
};
