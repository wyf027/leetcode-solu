题解

先自己操作装配台。准备好后再展开完整思路、复杂度、追问与四语言代码。

Core insight

每一层负责一个位置

选择

遍历所有未使用数字，把当前数字加入 path，并将 used[i] 标为 true。

探索

递归进入下一层。path 的长度就是当前决定了多少个位置。

撤销

递归返回后弹出最后一个数字，并恢复 used[i]，让其他分支继续使用它。

树高 = n；第 0 层有 n 个选择，第 1 层有 n - 1 个选择……叶子总数 = n!
Full process

完整解题过程

  1. STEP 1

    准备 answer、path 和 used

    answer 收结果，path 保存当前排列，used 防止同一路径重复选数字。

  2. STEP 2

    检查叶子

    当 path.length === nums.length，必须复制 path 放入 answer。

  3. STEP 3

    枚举本层候选

    从 0 到 n - 1 扫描；used[i] 为 true 就跳过，否则做选择并递归。

  4. STEP 4

    恢复现场

    递归返回后 pop，并把 used[i] 改回 false。回溯的关键就是状态对称恢复。

边界情况

  • 只有一个数字：递归一层就收集，如 nums = [1] 得到 [[1]]。
  • 包含负数或 0：数值不参与判断，不影响回溯。
  • 输入无重复：无需同层去重；若允许重复，则要排序并增加剪枝条件。
  • 复制 path：不能直接存同一个可变列表引用。

复杂度

TIME

O(n × n!)

共有 n! 个答案，每个答案复制长度 n。

SPACE

O(n)

不计输出，递归栈、path 与 used 都是 O(n)。

替代方案

原地交换：让索引 first 表示待确定位置，把后面的元素逐个交换到 first。空间同样 O(n) 递归栈且少一个 used，但修改原数组，讲解时状态恢复稍难观察。

迭代插入：逐个把新数字插入已有排列的每个位置，直观但会创建大量中间列表。面试主线优先回溯。

面试高频追问

  • 为什么是 n × n!？输出本身就有 n! 个长度为 n 的排列。
  • 如果 nums 有重复？先排序，同层跳过相同且前一个未使用的数字。
  • 为什么要复制 path？之后会继续 pop/push，直接存引用会让历史答案一起变化。

常见错误

  • 递归返回后只 pop，却忘记 used[i] = false。
  • 在 path 未装满时提前加入答案。
  • 把 path 本体而不是副本放入 answer。
  • 把“同一路径不能重复选”误写成“全局只能选一次”。
