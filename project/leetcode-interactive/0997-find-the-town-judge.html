谁是所有人信任、却不信任任何人的那个人？

把每一条信任关系看成一张有向图中的箭头。先观察关系如何改变每个人的“信任净分”，再决定是否查看完整题解。

EASY找到小镇的法官Find the Town Judge非付费题

题目

小镇中有 n 个人，编号为 1..n。关系 trust[i] = [aᵢ, bᵢ] 表示 aᵢ 信任 bᵢ。

法官必须同时满足：不信任任何人；除自己外，每个人都信任他；而且满足这两点的人恰好一个。

若能确定法官，返回其编号；否则返回 -1。

约束

  • 1 ≤ n ≤ 1000
  • 0 ≤ trust.length ≤ 10⁴
  • trust[i].length == 2
  • 所有信任对互不相同，且 aᵢ ≠ bᵢ
  • 1 ≤ aᵢ, bᵢ ≤ n

官方示例

示例 1

输入：n = 2, trust = [[1,2]]

输出：2

示例 2

输入：n = 3, trust = [[1,3],[2,3]]

输出：3

示例 3

输入：n = 3, trust = [[1,3],[2,3],[3,1]]

输出：-1

SOLUTION

一张净分表就够了

score[x] = 入度 − 出度

法官的入度必须是 n − 1，出度必须是 0，因此净分恰好为 n − 1。每条关系让信任者减 1、被信任者加 1；扫描后寻找该净分即可。

完整过程

  1. 建立长度为 n + 1 的零数组。
  2. 对每条 [a,b]：score[a]--，score[b]++。
  3. 返回唯一满足 score[i] == n-1 的编号；没有则返回 -1。

正确性

若 i 是法官，它收到 n−1 条信任且不发出信任，故净分为 n−1。反过来，任意人最多收到 n−1 条信任；若净分达到 n−1，他必须收到全部 n−1 条且出度为 0，因此满足法官条件。题意保证信任对唯一，所以不会重复计数。

边界与复杂度

空 trust 仅在 n=1 时能找到法官 1；有环、候选人信任别人、或无人被所有人信任都会返回 -1。

时间：O(n + m)；空间：O(n)，其中 m 为 trust 长度。

替代方案

可分别维护入度与出度两个数组，可读性直接但多一份空间；也可用集合做候选人消除，再二次扫描验证，空间可能更小，但实现与证明更绕。

面试追问

  • 若关系流式到达，如何在线维护候选人？
  • 若存在重复边，如何去重后再计数？
  • 若允许多个“法官”，返回列表时怎样修改？

常见错误

  • 只检查入度 n−1，忘记法官出度必须为 0。
  • 把目标净分写成 n。
  • 从下标 0 开始寻找居民。
  • trust 为空时直接返回 -1，漏掉 n=1。

四种语言完整实现

class Solution {
    public int findJudge(int n, int[][] trust) {
        int[] score = new int[n + 1];
        for (int[] edge : trust) {
            score[edge[0]]--;
            score[edge[1]]++;
        }
        for (int person = 1; person <= n; person++) {
            if (score[person] == n - 1) return person;
        }
        return -1;
    }
}

class Solution {
public:
    int findJudge(int n, vector<vector<int>>& trust) {
        vector<int> score(n + 1, 0);
        for (const auto& edge : trust) {
            --score[edge[0]];
            ++score[edge[1]];
        }
        for (int person = 1; person <= n; ++person) {
            if (score[person] == n - 1) return person;
        }
        return -1;
    }
};
