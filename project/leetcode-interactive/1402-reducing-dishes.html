做菜顺序
Reducing Dishes

一道菜值不值得加入菜单，不只取决于它自己的满意度，还取决于它会让已经选中的每一道菜等待多久。

阅读题目 进入厨房实验室
01

题目

给定整数数组 satisfaction，其中每个元素表示一道菜的满意度。每道菜恰好需要 1 个单位时间；若一道菜在第 t 个时间单位完成，它贡献的 like-time 系数为 t × satisfaction[i]。

你可以舍弃任意菜肴，并将保留的菜肴按任意顺序烹饪。返回所有已烹饪菜肴的 like-time 系数之和能达到的最大值；一道菜也不做是允许的。

函数形式： maxSatisfaction(satisfaction) → 整数

示例 1

输入：satisfaction = [-1,-8,0,5,-9]
输出：14
解释：舍弃 -8 和 -9，按 [-1,0,5] 烹饪：
      (-1×1) + (0×2) + (5×3) = 14

示例 2

输入：satisfaction = [4,3,2]
输出：20
解释：按 [2,3,4] 烹饪：
      (2×1) + (3×2) + (4×3) = 20

示例 3

输入：satisfaction = [-1,-4,-5]
输出：0
解释：所有菜都不做，收益为 0。

约束

  • n == satisfaction.length
  • 1 ≤ n ≤ 500
  • -1000 ≤ satisfaction[i] ≤ 1000

Solution

排序 + 逆序贪心

核心洞察

固定要做的一组菜后，满意度较低的菜应更早、较高的菜应更晚完成，因此最优顺序一定是满意度升序。接着从最高满意度开始向左扩展菜单。若当前已选菜的满意度和为 prefix，在最前面加入一道新菜后，所有已选菜的完成时间都增加 1，因此总收益恰好增加新的 prefix + 当前满意度。

只要这个新累计和大于 0，加入就会改善答案；一旦它不大于 0，更左侧的候选值只会更小，后续累计和也不可能重新变为正数，可以停止。

完整过程

  1. 将 satisfaction 升序排序。
  2. 从数组末尾向前扫描，用 prefix 记录当前候选菜单的满意度总和，用 answer 记录 like-time 总收益。
  3. 尝试令 prefix += satisfaction[i]。若 prefix ≤ 0，立即结束。
  4. 否则新菜值得放到菜单最前面，令 answer += prefix。
  5. 扫描结束后返回 answer。

正确性证明

引理 1：对任意两道相邻菜，若前一道满意度大于后一道，交换它们会让总收益增加两者满意度之差。因此最优菜单可按满意度升序排列。

引理 2：在一个升序菜单最前面加入满意度为 x 的菜，会让旧菜单每道菜的时间系数加 1，收益变化等于 x + 旧菜单满意度总和，即新的累计和。

停止正确：逆序扫描时，若加入当前值后累计和不大于 0，则后面尚未考察的值都不大于当前值；继续向左加入只会让累计和更小，因此不可能再带来正增益。

结论：算法按最优顺序选取所有且仅有正增益的前置菜肴，所以得到全局最大总收益。

边界与复杂度

  • 全为负数：第一轮累计和不大于 0，返回 0。
  • 含 0：单独加入 0 没有收益，但它可能因后面的正数而被纳入。
  • 全为正数：全部保留，并按升序烹饪。
  • 时间复杂度：O(n log n)，排序占主导。
  • 额外空间：取决于语言排序实现；算法变量本身为 O(1)。

四语言完整代码

Java可提交
import java.util.Arrays;

class Solution {
    public int maxSatisfaction(int[] satisfaction) {
        Arrays.sort(satisfaction);
        int prefix = 0;
        int answer = 0;

        for (int i = satisfaction.length - 1; i >= 0; i--) {
            prefix += satisfaction[i];
            if (prefix <= 0) {
                break;
            }
            answer += prefix;
        }
        return answer;
    }
}

替代方案：动态规划

排序后定义 dp[j] 为选了 j 道菜时的最大收益。处理满意度 x 时，倒序更新 dp[j] = max(dp[j], dp[j-1] + j×x)。该方案更通用，但时间复杂度为 O(n²)、空间复杂度为 O(n)，不如贪心精炼。

常见错误

  • 只保留正数：某些负数放在最前面，可能因推迟多道高满意度菜而产生净正收益。
  • 降序烹饪：较大的满意度应乘更大的完成时间。
  • 累计和等于 0 时继续：不会提升答案，并且更左侧只会让累计和下降。
  • 用默认 JavaScript 排序：默认按字符串字典序，必须传 (a, b) => a - b。

面试追问

  • 为什么选中的菜一定形成排序数组的一个后缀？ 因为逆序加入的边际收益随候选值向左单调不增，一旦停止便无需再选更小元素。
  • 如果每道菜耗时不同怎么办？ 交换论证会变为比较满意度与耗时的比例，当前后缀贪心不再直接成立。
  • 能否线性时间完成？ 值域已知时可计数排序；一般比较模型下仍需要处理顺序关系。
  • 为什么答案累加的是累计和？ 每次前插会统一把已选菜的完成时间加 1，同时新菜处于时间 1，净变化正好是所有已选满意度之和。
