Problem 1629 · Slowest Key

按键持续时间最长的键

每次松开，也是下一次按下的瞬间。根据累计的松开时间，找出持续最久的那一次按键；若时长并列，字母更大的键胜出。

非会员题单次扫描离线交互页
cbcd
01 / PROBLEM

先读懂时间轴

函数签名：slowestKey(releaseTimes, keysPressed)

题意转述

测试人员依次按下 n 个键。keysPressed[i] 是第 i 次按键的字符，严格递增的 releaseTimes[i] 是它被松开的时刻。第一次按键从时刻 0 开始；之后每次按键，都恰好从前一次松开时开始。

duration(0) = releaseTimes[0]
duration(i) = releaseTimes[i] − releaseTimes[i − 1]，i > 0

返回单次按键中持续时间最长的键。若多个按键时长相同，返回其中字典序最大的字符。同一个字符可出现多次，且各次时长可以不同。

约束

  • releaseTimes.length == n
  • keysPressed.length == n
  • 2 ≤ n ≤ 1000
  • 1 ≤ releaseTimes[i] ≤ 10⁹
  • releaseTimes[i] < releaseTimes[i+1]
  • keysPressed 仅含小写英文字母

官方示例 1

存在并列
输入：releaseTimes = [9,29,49,50],
      keysPressed = "cbcd"
输出："c"

时长：c→9，b→20，c→20，d→1
b 与 c 都为 20；字典序更大的 c 胜出。

官方示例 2

唯一最长
输入：releaseTimes = [12,23,36,46,62],
      keysPressed = "spuda"
输出："a"

时长：s→12，p→11，u→13，d→10，a→16
最长的一次是 a，持续 16。

03 / SOLUTION

准备好再揭晓

先尝试把每段时长写出来，并想清楚“并列时更新”的判断。题解默认收起，不会在首屏泄露。

SOLUTION REVEALED

一次扫描，维护最优二元组

O(n) 时间 · O(1) 空间

核心洞察

累计松开时间的相邻差，才是单次按键时长。扫描时同时维护当前最优的 (最长时长, 对应字符)。

若 duration > maxDuration，一定更新；若时长相等且 key > answer，也更新。可以合并成一个完整判断。

初始化

用第 0 次按键初始化：maxDuration = releaseTimes[0]，answer = keysPressed[0]。这样后续扫描从下标 1 开始，不需要虚构前一个时间，也不会漏掉第一段。

完整过程

  1. 接住第一段。
    把第 0 次的时长 releaseTimes[0] 与字符 keysPressed[0] 设为当前答案。
  2. 扫描后续下标。
    对每个 i = 1...n-1，计算 releaseTimes[i] - releaseTimes[i-1]。
  3. 按两级规则比较。
    更长时更新；等长且当前字符字典序更大时也更新。
  4. 返回记录的字符。
    扫描结束后，记录中就是所有已处理按键里的最优选择。

正确性说明

循环不变式：处理完下标 0...i 后，maxDuration 是这些按键的最大持续时间；answer 是所有达到该最大时长的按键中，字典序最大的字符。

初始化：只处理下标 0 时，第一段显然同时满足两个条件。

保持：加入第 i 段后，若它更长就取代旧解；若等长，只在字符更大时取代；否则旧解仍优。因此不变式继续成立。

终止：当 i = n-1 被处理后，不变式覆盖全部按键，所以返回字符正是题目要求的答案。

时间复杂度
O(n)

每次按键只访问一次。

空间复杂度
O(1)

只维护时长、答案和循环变量。

边界与常见错误

  • 第一段：起点是 0，不能访问 releaseTimes[-1]。
  • 末尾最长：扫描必须覆盖 n-1。
  • 重复字符：比较的是每次按键，不是字符总时长。
  • 并列：要选字符更大者，而不是最早出现者。
  • 误把 releaseTimes[i] 本身当成本次时长。
  • 只用 > 比较时长，遗漏字典序规则。
  • 用 >= 无条件更新，错误依赖出现顺序。
  • 先汇总同字符时长，改变“单次按键”的题意。

替代方案

构造并排序所有记录：先生成 (duration, key) 数组，再按时长、字符降序排序，取首项。它直观但需要 O(n) 额外空间和 O(n log n) 时间；本题只求一个最优项，线性扫描更合适。

二元组比较：某些语言可直接比较 (duration, key)；显式写出两级条件通常更易读、跨语言也更稳妥。

class Solution {
    public char slowestKey(int[] releaseTimes, String keysPressed) {
        int maxDuration = releaseTimes[0];
        char answer = keysPressed.charAt(0);

        for (int i = 1; i < releaseTimes.length; i++) {
            int duration = releaseTimes[i] - releaseTimes[i - 1];
            char key = keysPressed.charAt(i);
            if (duration > maxDuration
                    || (duration == maxDuration && key > answer)) {
                maxDuration = duration;
                answer = key;
            }
        }
        return answer;
    }
}

06 / FOLLOW-UP

面试追问

如果输入是实时流，无法一次拿到完整数组怎么办？

保留上一次松开时刻、当前最大时长和答案字符即可。每到一条新记录，用当前松开时刻减去上一次时刻，仍然是 O(1) 额外空间。

如果并列规则改成最早出现的按键呢？

只在时长严格更大时更新；等长时保持旧答案，天然保留最早出现者。

如果要求返回全部并列最长的不同字符呢？

维护最大时长和一个字符集合：更长时清空集合并加入当前字符，等长时加入集合。最后按题目要求排序或直接返回集合。

为什么不需要为每个字符记录最大时长？

目标是所有“单次按键”里的全局最优，只需要一个全局候选。按字符分组会增加状态，却不会帮助最终比较。
