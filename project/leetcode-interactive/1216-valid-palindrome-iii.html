验证回文串 III

Valid Palindrome III

给定字符串 s 与整数 k。如果最多删除 k 个字符后，剩余字符按原顺序能够组成回文串，就返回 true；否则返回 false。

题目速览
函数isValidPalindrome(s, k)
返回boolean
难度Hard
关键词字符串 · 动态规划
Problem

题目说明

“删除”可以发生在字符串的任意位置，被保留字符的相对次序不变。空操作也属于“至多删除 k 个字符”的范围；判断目标只是能否做到，不需要返回具体删除方案。

示例 1
输入：s = "abcdeca", k = 2
输出：true

删除 'b' 与 'e' 后得到 "acdca"，它是回文串。

示例 2
输入：s = "abbababa", k = 1
输出：true

例如删除第二个字符后可得到 "abababa"，删除次数不超过 1。

约束

  • 1 <= s.length <= 1000
  • s 只包含小写英文字母。
  • 1 <= k <= s.length

Solution

最少删除次数的区间动态规划

直接围绕“最少要删多少个字符”建模。设 dp[i][j] 表示子串 s[i..j] 变成回文串的最少删除次数，最终只需判断 dp[0][n - 1] <= k。

核心洞察

一个区间的两端只有两种情况：

  • 两端字符相同：它们可以一起保留，答案由内部区间决定。
  • 两端字符不同：最终至少要删掉其中一端，选择代价更小的方向。
s[i] == s[j] ? dp[i+1][j-1] : 1 + min(dp[i+1][j], dp[i][j-1])

完整过程

  1. 所有长度为 1 的区间本身就是回文串，初始化为 0。
  2. 按区间长度从短到长计算，确保依赖项已经得到。
  3. 根据两端是否相等，套用对应转移。
  4. 得到整个字符串的最少删除数后，与 k 比较。

为什么正确

归纳基础：长度为 0 或 1 的区间已经是回文串，最少删除数为 0。

归纳步骤：假设所有更短区间的答案都正确。若两端相等，存在保留两端的最优方案，内部只需达到回文；删除相等端点不会优于保留它们。若两端不同，任意回文结果不可能同时把这两个字符放在首尾，因此至少删除一端；取两种删除选择的较小值再加 1，恰好覆盖全部最优可能。

结论：按照区间长度递增计算后，dp[0][n-1] 就是全串的最少删除次数，因此与 k 的比较正确。

边界与复杂度

  • 长度为 1：无需删除，结果一定为 true。
  • 原串已是回文：最终代价为 0。
  • k 足够大：最多保留一个字符即可形成回文。
  • 时间复杂度：O(n²)。
  • 空间复杂度：代码使用一维压缩，为 O(n)。

一维压缩时的变量含义

外层让 left 从右向左移动，内层让 right 从左向右移动。更新前的 dp[right] 是二维表里的 dp[left+1][right]；更新后的 dp[right-1] 是 dp[left][right-1]；变量 previousDiagonal 保存更新前的左下对角值 dp[left+1][right-1]。更新顺序不能颠倒。

Implementations

四语言完整代码

class Solution {
    public boolean isValidPalindrome(String s, int k) {
        int n = s.length();
        int[] dp = new int[n];

        for (int left = n - 2; left >= 0; left--) {
            int previousDiagonal = 0;
            for (int right = left + 1; right < n; right++) {
                int oldBelow = dp[right];
                if (s.charAt(left) == s.charAt(right)) {
                    dp[right] = previousDiagonal;
                } else {
                    dp[right] = 1 + Math.min(dp[right], dp[right - 1]);
                }
                previousDiagonal = oldBelow;
            }
        }

        return dp[n - 1] <= k;
    }
}

替代方案

最长回文子序列：求长度 LPS，若 n - LPS <= k 则可行。它与最少删除模型等价，同样是 O(n²) 时间。

记忆化搜索：递归尝试删除左端或右端，并缓存 (left, right)。表达直观，但递归深度与函数调用开销更高。

带预算剪枝：状态中加入剩余删除额度可提前失败，但状态维度更复杂；本题 n <= 1000 时区间 DP 更稳定。

面试追问

  • 如何恢复一组实际删除的字符？——保留二维表并从 dp[0][n-1] 反向追踪。
  • 为什么空间能压缩到一维？——每个状态只依赖当前行左侧、上一行同列和上一行左下角。
  • 如果要求恰好删除 k 个字符呢？——需明确空串是否允许；额外删除回文中的成对字符通常可维持回文，但不能直接沿用“至多”的判断。
  • 能否在最坏情况下做到亚二次时间？——通用字符串上，本类 LPS/LCS 结构通常仍以二次 DP 为标准答案。

常见错误

  • 把“删除字符”误解为只能删除连续子串；实际上删除位置可以离散。
  • 两端不同时只固定删除某一端，丢失另一条可能更优的路径。
  • 一维压缩时从右向左更新 right，导致读到错误阶段的状态。
  • 把条件写成最少删除数严格小于 k；题意是“至多”，应使用 <=。
  • 用枚举删除集合的暴力方案，复杂度会随字符串长度指数增长。
