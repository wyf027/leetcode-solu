复写零

Duplicate Zeros

EASY原地修改双指针

题目

给定一个长度固定的整数数组 arr，把其中每个零复写一次，并把后续元素向右移动。超出原数组长度的内容直接丢弃。必须就地修改输入数组，函数不返回结果。

示例 1
输入：arr = [1,0,2,3,0,4,5,0] 输出：[1,0,0,2,3,0,0,4]
调用后，原数组变为上述输出。
示例 2
输入：arr = [1,2,3] 输出：[1,2,3]
没有零，因此数组保持不变。

约束

  • 1 <= arr.length <= 104
  • 0 <= arr[i] <= 9

题解：虚拟扩容 + 倒序双指针

核心洞察

若正向搬运，刚写出的副本会覆盖尚未读取的元素。先数出零的数量，把每个零视为占两个位置，就能得到一个可能超过边界的“虚拟末尾”。随后从后向前搬运，覆盖的永远是已经读取过的位置。

完整过程

  1. 统计数组中的零数 zeros。
  2. 令读指针 i = n - 1，虚拟写指针 j = n + zeros - 1。
  3. 从右向左扫描：若 j < n，将 arr[i] 写到 arr[j]。
  4. 若当前值为零，再将 j 左移一次，并在仍位于边界内时写入第二个零。
  5. 每轮同时左移读指针和写指针，直到读取结束。

正确性说明

循环开始时，所有虚拟位置大于 j 的元素都已按规则放好；而 i 左侧及当前位置尚未被破坏。非零值贡献一个虚拟位置，零贡献连续两个虚拟位置。倒序写入保持两者的相对顺序，越界位置被忽略。循环结束后，原数组范围内恰好等于完整复写序列的前 n 项，因此结果正确。

边界与复杂度

  • 全是零、没有零、长度为 1、末尾为零都由同一逻辑处理。
  • 时间复杂度 O(n)：统计与倒序扫描各一次。
  • 额外空间复杂度 O(1)。

替代方案

可新建数组，正序追加元素和零的副本，再复制前 n 项，思路直观但需要 O(n) 额外空间。也可遇零后逐段右移，但最坏会退化为 O(n²)。

面试追问

  • 如果每个零要复写 k 次，虚拟长度和写指针如何变化？
  • 如果数组容量可增长，是否仍需边界判断？
  • 能否只统计“最终能影响原数组”的零，减少无效步骤？

常见错误

  • 正序原地写入，覆盖未处理数据。
  • 忘记虚拟写指针可能在数组外，导致越界访问。
  • 零的第二次写入后没有再次左移 j。
  • 返回新数组，而不是修改传入数组。

完整代码

class Solution {
    public void duplicateZeros(int[] arr) {
        int zeros = 0;
        for (int value : arr) if (value == 0) zeros++;
        int i = arr.length - 1, j = arr.length + zeros - 1;
        while (i >= 0) {
            if (j < arr.length) arr[j] = arr[i];
            if (arr[i] == 0) {
                j--;
                if (j < arr.length) arr[j] = 0;
            }
            i--; j--;
        }
    }
}
