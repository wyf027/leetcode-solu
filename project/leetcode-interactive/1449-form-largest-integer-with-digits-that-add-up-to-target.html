Form Largest Integer With Digits That Add up to Target
01 / Problem

题意与约束

给定 cost 和 target。添加数位 i+1 的成本为 cost[i]，返回成本总和恰好为目标值时能组成的最大整数。

  • 数字仅为 1…9，每种可重复使用。
  • 答案以字符串返回；无解返回 "0"。
  • cost.length == 9；1 <= cost[i], target <= 5000。

largestNumber(cost, target) → string

示例 1
输入：cost=[4,3,2,5,6,7,2,5,5], target=9
输出："7772"

7 的成本为 2，2 的成本为 3：2×3+3=9；7772 大于同样合法的 977。

示例 2
输入：cost=[7,6,5,5,5,6,8,7,8], target=12
输出："85"
示例 3
输入：cost=[2,4,6,2,4,6,4,4,4], target=5
输出："0"

没有组合能恰好花费 5。

示例 4
输入：cost=[6,10,15,40,40,40,40,40,40], target=47
输出："32211"

04 / Full Solution

先求最长，再取字典序最大

核心洞察

正整数位数越多越大；位数相同时，字典序越大越大。令 dp[t] 为恰好花费 t 时的最大数位数，不可达为负无穷，dp[0]=0。

dp[t]=max(dp[t-cost[d]]+1)

再从 9 到 1 选满足 dp[t]=dp[t-cost[d]]+1 的数字。

完整过程
  1. 初始化一维状态，只让预算 0 可达。
  2. 预算递增，枚举九个可无限复用的数字更新最大长度。
  3. 目标不可达则返回 "0"。
  4. 从 9 到 1 重建；条件成立就反复追加并扣除成本。
正确性

长度：任一非空最优解去掉末位后，余下必是剩余成本的最优长度；转移枚举所有末位，故归纳得到正确最大长度。

数值：重建在每一位选择仍可完成最优长度的最大数字，因此不存在首个不同位更大的合法结果。两者合并即为全局最大整数。

边界与复杂度
  • 不可达返回 "0"，不能把不可达状态初始化为 0。
  • 相同成本无需去重，逆序重建自然选更大数位。
  • 答案可能数千位，始终使用字符串。

时间 O(9×target+L)，空间 O(target)。

替代方案

字符串 DP 直观但反复比较、复制长字符串；二维完全背包可以恢复路径但空间冗余；只按成本贪心不能保证恰好花完，也忽略高位优先。

import java.util.*;
class Solution {
 public String largestNumber(int[] cost,int target){
  int N=-1000000,dp[]=new int[target+1]; Arrays.fill(dp,N); dp[0]=0;
  for(int t=1;t<=target;t++) for(int d=1;d<=9;d++){int c=cost[d-1]; if(t>=c&&dp[t-c]!=N) dp[t]=Math.max(dp[t],dp[t-c]+1);}
  if(dp[target]<0)return "0"; StringBuilder a=new StringBuilder();
  for(int d=9,t=target;d>=1;d--){int c=cost[d-1];while(t>=c&&dp[t]==dp[t-c]+1){a.append(d);t-=c;}}
  return a.toString();
 }
}

面试追问与常见错误
为什么不在 dp 中保存字符串？

答案可能数千位，每次转移的比较和复制都很昂贵；保存长度再重建更省。

若每个数字最多用一次？

会变成 0/1 背包，预算需倒序更新，并额外记录恢复信息。

最常见错误是什么？

把不可达初始化为 0、重建时每个数字只取一次、或把超长答案转成整数。
