跳跃游戏 III

从一个下标出发，每次只能按当前格的数值向左或向右跳。目标很简单：找到任意一个值为 0 的位置——但别让重复访问把你困在环里。

英文题名Jump Game III
函数canReach(arr, start)
返回值boolean
标签数组图搜索

Problem

题目描述

给定一个由非负整数组成的数组 arr，你最初位于下标 start。

站在下标 i 时，可以跳到 i + arr[i] 或 i - arr[i]。请判断能否到达任意一个元素值为 0 的下标。任何一次跳跃都不能越出数组边界。

完整参数形式
canReach(arr: integer[], start: integer) → boolean

约束

  • 1 ≤ arr.length ≤ 5 × 10⁴
  • 0 ≤ arr[i] < arr.length
  • 0 ≤ start < arr.length

官方示例

示例 01
输入arr = [4,2,3,0,3,1,2], start = 5
输出true

可按 5 → 4 → 1 → 3 到达值为 0 的下标 3；5 → 6 → 4 → 1 → 3 也可以。

示例 02
输入arr = [4,2,3,0,3,1,2], start = 0
输出true

一种可行路线为 0 → 4 → 1 → 3。

示例 03
输入arr = [3,0,2,1,2], start = 2
输出false

无法到达值为 0 的下标 1。

Solution

把数组看成一张隐式图

核心洞察

每个数组下标都是一个图节点；下标 i 最多有两条有向边，分别连向 i - arr[i] 与 i + arr[i]。问题因此等价于：从 start 出发，能否搜索到一个值为 0 的节点。

用 BFS 或 DFS 遍历都可以。关键是维护 visited：一个下标一旦发现便标记，之后不再入队，从而避免在两个位置之间反复跳跃。

完整过程

  1. 创建队列，将 start 放入，并立即标记为已访问。
  2. 队列非空时，取出队首下标 i。
  3. 若 arr[i] == 0，已经到达目标，返回 true。
  4. 计算两个候选位置 i - arr[i] 和 i + arr[i]。
  5. 仅把位于数组内且尚未访问的候选位置标记并入队。
  6. 队列耗尽仍未看到 0，说明所有可达位置都已搜索完，返回 false。

正确性证明

1
可达性保持。

初始入队的 start 显然可达。若队列中的 i 可达，那么算法加入的合法邻居正是题目允许从 i 一步跳到的位置，因此新加入的位置也可达。由归纳可知，队列中的每个位置都可从起点到达。

2
不会漏掉可达位置。

对任意从 start 可达的位置 x，取一条到达它的跳跃路径。BFS 会处理路径上的起点；每次处理路径上的一个位置时，都会考察下一跳，所以路径上的所有位置最终都会被发现（除非此前已发现）。因此 x 不会被遗漏。

3
返回值正确。

若算法返回 true，依据可达性保持，找到的 0 位置确实可达。若返回 false，队列已耗尽；依据不会漏掉可达位置，所有可达下标都已检查且值均不为 0。因此答案必为 false。

边界情况

  • 起点就是 0：第一次出队立即返回 true。
  • 跳跃越界：负下标与不小于 arr.length 的位置必须丢弃。
  • 出现环：例如两个位置能互相跳回；visited 保证每个下标最多处理一次。
  • 数组中有多个 0：只需到达任意一个，无需找到全部。
  • 不可达的 0：数组里存在 0 不代表答案为真，必须从 start 可达。

复杂度

时间复杂度O(n)每个下标最多入队并展开一次，每次只看两个邻居。
空间复杂度O(n)访问标记与队列在最坏情况下容纳线性数量的下标。

替代方案

迭代 DFS

把队列换成栈即可，正确性与复杂度相同。它不保证按跳跃次数分层，但本题只问能否到达，因此完全适用。

递归 DFS

代码更短，但当数组长度达到 5 × 10⁴ 时，递归深度可能超过语言栈限制。面试和线上提交中更推荐迭代写法。

原地标记

若允许修改数组，可通过把访问过的非零值改成负数来省去布尔数组。不过题目给定非负值，仍需谨慎处理 0，且修改入参通常不如显式 visited 清晰。

面试追问

为什么 BFS 不需要记录跳跃路径？

目标只要求返回能否到达，不要求输出路径。队列与访问标记足以完成判定；若追问具体路径，再增加 parent 数组，在首次发现邻居时记录来源即可。

如果要返回最少跳跃次数呢？

BFS 天然按层推进。可以让队列同时携带距离，或逐层处理队列长度；首次发现值为 0 的位置时，其层数就是最少跳数。

为什么在入队时就标记，而不是出队时？

入队时标记能阻止多个父节点重复加入同一个邻居，保证队列规模和总处理次数都是线性的。

能用并查集吗？

不合适。这里需要从单一源点沿有向跳跃关系做可达性搜索；BFS/DFS 直接表达问题，而并查集主要处理无向连通性与集合合并。

常见错误

  • 只判断数组里是否存在 0，却没有判断它能否从起点到达。
  • 忘记边界检查，直接访问负下标或 arr.length 之外。
  • 没有访问标记，遇到环后无限循环。
  • 直到出队才标记，导致同一下标被重复入队多次。
  • 使用 Array.shift() 实现 JavaScript 队列，造成额外搬移开销；应用头指针推进。
