HARDStamping The Sequence非付费题最多 10 × n 次

题目

给定小写字符串 stamp 和 target。初始字符串 s 的长度等于 target.length，每个位置都是 ?。一次操作可选择合法起点，把完整的 stamp 覆盖到 s 对应区间。

返回每次盖章起点组成的数组，使最终得到 target，且操作数不超过 10 × target.length；若做不到，返回空数组。答案可能不唯一。

函数形式

movesToStamp(stamp: string, target: string): integer[]

约束

  • 1 ≤ stamp.length ≤ target.length ≤ 1000
  • stamp 与 target 仅含小写英文字母。

官方示例

示例 1 输入：stamp = "abc", target = "ababc" 输出：[0,2] 说明："?????" → "abc??" → "ababc" 另如 [1,0,2] 也可被接受。
示例 2 输入：stamp = "abca", target = "aabcaca" 输出：[3,0,1] 说明："???????" → "???abca" → "abcabca" → "aabcaca"

题解：逆向贪心消除

核心洞察：正向盖章会覆盖旧字符，难以决定先后；倒过来则只需寻找一个与印章不冲突、且至少能新消除一个字符的窗口，把它变成问号。最后将消除顺序反转。

完整过程

  1. 把 target 转成可修改字符数组，并准备 used 标记与答案列表。
  2. 反复扫描所有长度为 stamp.length 的窗口。窗口中每个非问号字符必须与印章对应字符相同，同时至少含一个非问号字符。
  3. 符合条件就把窗口全部改为问号，记录起点，并累计新消除的字符数。
  4. 某一整轮没有任何进展时停止。若尚未全部消除则无解；否则反转记录，即为正向盖章顺序。

为什么正确

安全性：逆向消除窗口时，仍存在的字符都与印章一致；已变成问号的位置代表它们可由更早的盖章负责。因此把本窗口放到正向序列的更后方，不会破坏最终目标。

完备性：若存在某个合法正向序列，观察它的最后一次盖章：其覆盖区间与最终目标必然一致，因此逆向时至少存在一个可消除窗口。不断应用这一论证，能够逐层移除全部字符。算法尝试全部窗口，只要某个窗口可消除就不会漏掉。

终止性：每次成功操作至少新增一个问号，最多成功 n 次。全部消除后，反转顺序逐次盖章即可还原目标，且 n ≤ 10n。

边界与复杂度

  • stamp == target：一次消除，答案为 [0]。
  • 没有任何初始匹配窗口：立即返回空数组。
  • 必须要求窗口至少消除一个新字符，否则会重复记录全问号窗口。
  • 最朴素实现至多成功 n 轮，每轮扫描约 n 个窗口、每窗比较 m 个字符：时间 O(n²m)，额外空间 O(n)。在 n ≤ 1000 下可用。

替代方案

可为每个窗口维护“不匹配位置集合”，并建立字符位置到相关窗口的反向索引；某个位置被消除后，只更新受影响窗口，配合队列把复杂度优化到约 O(nm)，但实现明显更复杂。面试中可先给出贪心扫描，再说明队列优化。

面试追问

  • 为何答案要反转？因为记录的是从最终字符串撤销盖章的顺序。
  • 贪心选择任意可消除窗口会错吗？不会；问号是通配符，消除只放宽后续条件。
  • 如何证明操作数限制？每次至少新消除一位，所以记录数最多为 n。
  • 怎样降到 O(nm)？预处理窗口依赖关系，用队列传播已消除位置。

常见错误

  • 把问号当作必须与印章匹配，而不是通配符。
  • 未检查“至少一个新字符”，导致死循环。
  • 忘记反转逆向记录。
  • 只判断是否有窗口成功，却不统计是否真的消除了全部 n 个位置。
