获得分数的方法数

Number of Ways to Earn Points

一张试卷，多种题型，每类题的数量与分值都有限。你能用多少种选题组合，恰好抵达目标分数？先理解规则，再到下方亲手推演。

困难 数组 动态规划 多重背包

题目

函数：waysToReachTarget(target, types)

考试包含 n 种题型。给定整数 target 与下标从 0 开始的数组 types，其中 types[i] = [counti, marksi]，表示第 i 类最多有 counti 道题，每题值 marksi 分。

请返回恰好得到 target 分的选题方法数，答案对 109 + 7 取余。同一题型中的题目不可区分，因此每类只关心选了几道，而不关心具体选了哪几道。

关键语义：若某类有 3 道同分题，选择其中任意 2 道只算一种方法。

官方示例

示例 1

输入：target = 6,
types = [[6,1],[3,2],[2,3]]
输出：7

可选数量三元组为 (6,0,0)、(4,1,0)、(2,2,0)、(3,0,1)、(1,1,1)、(0,3,0)、(0,0,2)，共 7 种。

示例 2

输入：target = 5,
types = [[50,1],[50,2],[50,5]]
输出：4

对应 5×1、3×1+1×2、1×1+2×2、1×5 四种选法。

示例 3

输入：target = 18,
types = [[6,1],[3,2],[2,3]]
输出：1

只有把所有题目都答完才能获得 18 分。

约束

  • 1 ≤ target ≤ 1000
  • n == types.length
  • 1 ≤ n ≤ 50
  • types[i].length == 2
  • 1 ≤ counti, marksi ≤ 50

独立题解区

题解默认收起，展开后包含推导、证明与四种语言代码。

核心洞察

同类题目不可区分，因此第 i 类只需枚举“选 0 到 count[i] 道”。这正是有数量上限的多重背包计数。

令 dp[s] 表示处理完前若干类题后，恰好得到 s 分的方法数。初始只有不选任何题的一种方式，所以 dp[0] = 1。处理一类 [count, marks] 时，对每个分数 s 汇总选择 k = 0..count 道该类题后的来源 dp[s - k × marks]。

完整过程

  1. 创建长度为 target + 1 的数组，令 dp[0] = 1。
  2. 依次处理每一种题型 [count, marks]。
  3. 让总分 s 从 target 降到 0；枚举本类选 1 到 count 道，并把旧状态的方法数加入 dp[s]。
  4. 所有加法随时取模；最终返回 dp[target]。

为什么倒序枚举分数？

更新 dp[s] 时只读取更小的分数。倒序保证这些更小位置仍是“加入当前题型之前”的值，从而不会在同一轮重复使用已更新结果，也就不会突破该类的数量上限。

等价且更直观的写法是每轮复制一份旧数组；倒序写法省掉了这份额外数组。

正确性证明

不变式：处理完前 i 类题后，dp[s] 恰好等于只使用这 i 类题取得 s 分的方法数。

初始：尚未处理题型时，只有空集合得到 0 分，故 dp[0]=1，其余为 0。

转移：任何使用前 i 类题得到 s 分的方案，都唯一对应“第 i 类选 k 道”与“前 i-1 类得到 s-k×marks 分”的组合。不同 k 互斥且覆盖所有合法方案，因此求和既不遗漏也不重复。

结论：处理全部题型后，不变式给出 dp[target] 正是答案。

复杂度与边界

  • 时间：O(n × target × C)，其中 C 是单类题目数量上限，至多 50。
  • 空间：O(target)。
  • 0 分：dp[0]=1 是所有转移的根。
  • 分值超界：当 k × marks > s 时立即停止枚举。
  • 大答案：每次累加后取模，避免溢出并满足题意。

四语言实现

class Solution {
    public int waysToReachTarget(int target, int[][] types) {
        final int MOD = 1_000_000_007;
        int[] dp = new int[target + 1];
        dp[0] = 1;

        for (int[] type : types) {
            int count = type[0], marks = type[1];
            for (int score = target; score >= 0; score--) {
                for (int used = 1;
                     used <= count && used * marks <= score;
                     used++) {
                    dp[score] = (dp[score]
                        + dp[score - used * marks]) % MOD;
                }
            }
        }
        return dp[target];
    }
}

from typing import List


class Solution:
    def waysToReachTarget(
        self, target: int, types: List[List[int]]
    ) -> int:
        mod = 1_000_000_007
        dp = [0] * (target + 1)
        dp[0] = 1

        for count, marks in types:
            for score in range(target, -1, -1):
                for used in range(1, count + 1):
                    if used * marks > score:
                        break
                    dp[score] = (
                        dp[score] + dp[score - used * marks]
                    ) % mod

        return dp[target]

替代方案

  • 二维 DP：ways[i][s] 语义最直观，空间为 O(n × target)。
  • 同余类滑动窗口：按 score % marks 分组维护窗口和，可将时间优化到 O(n × target)，但实现与证明更复杂；本题约束下无需使用。
  • 生成函数：每类对应 1 + x^marks + … + x^(count×marks)，答案是乘积中 x^target 的系数，适合理解但不利于直接编码。

面试追问

  • 若 target 提升到 105，如何用滑动窗口优化？
  • 若同类题目可以区分，转移中的组合数应如何加入？
  • 若要求输出一种可行选法，需要额外保存哪些前驱信息？
  • 为什么正序原地更新会污染“上一层”状态？

常见错误

  • 把同类的具体题目当成不同方案，错误乘上组合数。
  • 原地更新时正序遍历分数，导致当前题型被重复累计。
  • 忘记 dp[0] = 1，所有合法状态都无法启动。
  • 枚举数量时未同时限制 used ≤ count 与总分不越界。
  • 只在最终结果取模，中间累加可能溢出。
  • 把“恰好 target”误写成“不超过 target”的方法数。
