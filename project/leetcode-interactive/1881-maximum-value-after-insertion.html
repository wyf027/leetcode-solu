插入后的最大值

Maximum Value after Insertion

只多放入一个数字，结果可以相差很远。

给定表示大整数的字符串 n 和整数数字 x。将 x 恰好插入一次，保留原数字的相对顺序，使最终整数尽可能大，并返回它的字符串表示。允许插在数字序列的开头、末尾或中间；如果有负号，不能插到负号左侧。

n 的数字部分与 x 都只包含 1 到 9。整数可能很长，也可能为负数。

官方示例 1

输入：n = "99", x = 9
输出："999"

三个合法插入位置都会得到同一个结果。

官方示例 2

输入：n = "-13", x = 2
输出："-123"

候选为 -213、-123、-132，其中 -123 最大。

完整约束与参数
  • 1 ≤ n.length ≤ 100000，长度包含可能存在的负号。
  • 1 ≤ x ≤ 9，类型为整数。
  • n 是有效的整数字符串，数字均在 [1, 9]。
  • 负数以字符 '-' 开头；符号后至少有一个数字。
  • 函数：maxValue(n: string, x: integer) → string。

03 / DEEP DIVE

独立题解

准备好后再展开，查看决策规则、证明和四种语言的实现。

核心洞察：第一处不同决定大小

所有候选结果长度相同、符号相同。正数比较时，高位的第一次差异决定谁更大；负数比较时，绝对值越小，实际数值越大。因此无需把整个字符串转为整数。

  • 正数：在第一个严格小于 x 的数字前插入。
  • 负数：跳过负号，在第一个严格大于 x 的数字前插入。
  • 相等时：继续扫描；找不到严格满足条件的位置，则在末尾插入。

完整过程

  1. 记录是否为负数。起点为正数的索引 0 或负数的索引 1。
  2. 将 x 转为一个数字字符，从起点逐位扫描。
  3. 按符号使用严格比较。遇到有利于插入的位置立即停止。
  4. 若扫描结束仍未停止，让插入索引等于字符串长度。
  5. 返回 前缀 + x + 后缀，负号自然保留在前缀中。

例如 n = "-13", x = 2：跳过负号；1 小于 2，先保留 1；遇到 3 大于 2，于 3 前插入，得到 "-123"。正数 "73" 插入 6 时，保留 7，遇到 3 时插入，得到 "763"。

正确性证明

先考虑正数，设算法选择的位置为 p。在 p 之前每位都大于等于 x。若在更早的位置 q 插入：从 q 起遇到第一个大于 x 的原数字时，算法保留的该数字胜过提前插入方案中的 x；若中间全等于 x，两种位置插入的效果相同。因此提前插入不会更优。

如果 p 不是末尾，原数字 n[p] < x。任何在 p 之后插入的方案都在 p 保留 n[p]，而算法在此放 x；在共同前缀之后，算法立即胜出。若 p 是末尾，前一段比较已排除了所有更优的提前插入方案。因此算法得到最大正数。

负数只比较符号后的绝对值，并把上述大小方向全部反转：p 前各位小于等于 x，提前插入不能减小绝对值；p 处原数字大于 x，延后插入会增大绝对值。算法得到最小绝对值，也就得到最大负数。两种情况下都恰好插入一次，且不会破坏负号位置。

边界与复杂度

  • 全部相等、没有触发位置：追加到末尾，不能返回原串。
  • 只含一位数字、紧接负号插入、正数首位插入：统一由起点和切片处理。
  • 负号不参与数位比较；题目不含 0，不存在额外的前导零处理。
  • 设 L = n.length。扫描和一次结果构造均为 O(L) 时间。扫描仅需 O(1) 额外变量；计入结果及语言切片/构造缓冲，空间为 O(L)。

四语言完整代码

均使用官方函数签名；代码尚未执行或验证。字符串操作避免整数溢出。

Java

class Solution {
    public String maxValue(String n, int x) {
        boolean negative = n.charAt(0) == '-';
        char digit = (char) ('0' + x);
        int i = negative ? 1 : 0;
        while (i < n.length()) {
            char current = n.charAt(i);
            if (negative ? current > digit : current < digit) {
                break;
            }
            i++;
        }
        return new StringBuilder(n.length() + 1)
            .append(n, 0, i)
            .append(digit)
            .append(n, i, n.length())
            .toString();
    }
}

/**

var maxValue = function(n, x) {
    const negative = n[0] === '-';
    const digit = String(x);
    let i = negative ? 1 : 0;
    while (i < n.length) {
        if (negative ? n[i] > digit : n[i] < digit) break;
        i++;
    }
    return n.slice(0, i) + digit + n.slice(i);
};

C++

#include <string>
using namespace std;

class Solution {
public:
    string maxValue(string n, int x) {
        bool negative = n[0] == '-';
        char digit = static_cast<char>('0' + x);
        size_t i = negative ? 1 : 0;
        while (i < n.size()) {
            if (negative ? n[i] > digit : n[i] < digit) break;
            ++i;
        }
        n.insert(i, 1, digit);
        return n;
    }
};

替代方案

枚举每个合法插入位置，构造候选字符串，再按同符号、等长数字的字典序挑选最优值。负数要反转比较方向。共有 O(L) 个位置，每次构造或比较 O(L)，总时间 O(L²)，逐个保留最优时额外空间 O(L)。它适合小输入解释候选，无法高效处理十万位规模。也可以在扫描时逐字符写入缓冲并维护“已插入”标记，复杂度仍为 O(L)，但控制分支更多。

常见错误

  • 把 n 转为 Number、long 或 int，导致溢出或精度丢失。
  • 正负数都用同一个比较方向，误把更负的数选为最大值。
  • 在等于 x 时立刻插入：例如 n = "-223", x = 2，在首个 2 前插入得到 -2223，这个例子恰巧正确；但 n = "-212", x = 2 时提前插入得 -2212，正确结果是 -2122。严格比较才能安全越过所有相等前缀。
  • 把 x 拼到负号之前，或遗漏扫描到末尾的追加操作。
  • 每轮反复构造完整字符串，额外引入 O(L²) 复制开销。

面试追问

  • 为什么数字字符可以直接比较？四种语言里字符 '1' 到 '9' 的顺序与数值一致，并且每次比较的都是单个数字。
  • 若要最小值？反转正负两种情况下的严格比较方向，仍跳过负号。
  • 允许 x = 0 时呢？必须先明确前导零是否允许、结果是否要求规范化；不能直接沿用当前输入规则。
  • 插入一个多位串或多个数字呢？单字符的局部比较证明不再直接适用，需要考虑插入片段与后缀的首次差异，重新证明策略。
  • 最优位置唯一吗？不一定。相同数字连续出现时，多处插入可产生相同最大字符串。
