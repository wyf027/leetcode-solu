01 · Problem

题意与接口

给定一个只读的单链表头节点 head。你不能读取字段或修改指针，只能调用节点提供的两个方法。请从尾到头依次打印每个节点的值。

node.getNext()
返回下一个节点；尾节点返回空。
node.printValue()
打印当前节点保存的值。

参数形式：printLinkedListInReverse(head: ImmutableListNode)。函数不返回链表；答案通过调用 printValue() 产生。平台元数据以数组模拟输入，并收集打印序列作为结果。

官方元数据示例

示例 1
输入：head = [1, 2, 3, 4]
输出：[4, 3, 2, 1]
示例 2
输入：head = [0, -4, -1, 3, -5]
输出：[-5, 3, -1, -4, 0]
示例 3
输入：head = [-2, 0, 6, 4, 4, -6]
输出：[-6, 4, 4, 6, 0, -2]

约束

  • 链表节点数 n 满足 1 ≤ n ≤ 1000。
  • 节点值满足 -1000 ≤ value ≤ 1000。
  • 链表不可变：只能使用公开的 getNext() 与 printValue()。

04 · Solution

递归：回溯顺序就是逆序

一路向后
每层先用 getNext() 递归访问后继。
触底返回
尾节点之后遇到空引用，递归开始退栈。
回程打印
当前层最后调用 printValue()，天然得到尾到头顺序。

完整过程

  1. 若当前节点为空，直接返回，作为递归边界。
  2. 递归处理当前节点的后继：visit(node.getNext())。
  3. 后继全部处理完后，调用当前节点的 printValue()。

正确性证明

对链表长度作归纳。长度为 1 时，递归访问空后打印唯一节点，结果正确。假设算法能把长度为 k 的后缀逆序打印；对长度 k+1 的链表，算法先递归打印后继组成的长度 k 后缀，按归纳假设其顺序正确，再打印头节点。因此整体恰为从尾到头。归纳成立。

边界情况

  • 单节点：递归一次后立即打印。
  • 重复值、负数和零：算法只关心节点位置，不受值影响。
  • 最长链表：递归深度为 n，需留意语言栈空间。

复杂度

  • 时间：O(n)，每个节点访问和打印一次。
  • 额外空间：O(n)，来自递归调用栈。
  • 链表本身保持完全不变。

四种语言完整实现

以下均按 LeetCode 的 ImmutableListNode 接口书写；接口由平台提供，不要自行修改节点。

Java
/**
 * // This is the ImmutableListNode's API interface.
 * // You should not implement it, or speculate about its implementation.
 * interface ImmutableListNode {
 *     void printValue();
 *     ImmutableListNode getNext();
 * }
 */
class Solution {
    public void printLinkedListInReverse(ImmutableListNode head) {
        if (head == null) return;
        printLinkedListInReverse(head.getNext());
        head.printValue();
    }
}

06 · Go deeper

替代方案与面试追问

替代方案

  • 显式栈：正向遍历时保存每个节点，再反向弹出打印；同样是 O(n) 时间、O(n) 空间，避免递归深度风险。
  • 平方根分块：保存每个块的起点，再按块逆序、块内重复向前定位，可在 O(n) 时间与 O(√n) 空间之间取得折中。
  • 常数空间：可反复从头寻找尚未打印的最右节点，空间 O(1)，但时间退化为 O(n²)。

面试追问

  • 为什么普通的原地反转链表在这里不可用？
  • 如果禁止递归，如何用显式栈保持线性时间？
  • 怎样推导 O(√n) 空间的分块方案？
  • 若链表可能很长，语言的调用栈限制如何影响选择？

常见错误

  • 在递归调用之前打印，得到的仍是正序。
  • 尝试访问 value 或 next 字段，违反不可变接口约束。
  • 忘记空节点边界，导致在尾节点之后调用方法。
  • 声称递归是 O(1) 空间；调用栈也必须计入额外空间。
