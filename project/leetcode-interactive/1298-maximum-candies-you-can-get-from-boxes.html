Maximum Candies You Can Get from Boxes

你能从盒子里获得的最大糖果数

有些盒子在手里却打不开，有些钥匙已经找到却还没拿到对应盒子。真正的关键，是等待“拥有盒子”和“能够打开”这两个条件在同一时刻成立。

题号1298
难度Hard
核心状态 BFS

Problem

题意

有 n 个编号为 0 到 n - 1 的盒子。数组 status 表示盒子初始是否打开，candies 表示糖果数，keys[i] 是打开盒子 i 后获得的钥匙，containedBoxes[i] 是盒子 i 内发现的其他盒子。

你最初只拥有 initialBoxes 中的盒子。每当一个盒子既已拥有又处于可打开状态时，可以取走其中全部糖果，并获得其中的钥匙和盒子。求最终能获得的最大糖果总数。

输入函数：
maxCandies(status, candies, keys, containedBoxes, initialBoxes)
返回：整数，表示最多可取得的糖果数。

五组数据分别控制什么？

status[i]
1 表示盒子可打开，0 表示关闭。
candies[i]
打开盒子后一次性取走的糖果数。
keys[i]
获得后会永久解锁对应编号的盒子。
containedBoxes[i]
打开后新增到“已拥有”集合的盒子。
initialBoxes
起点盒子集合；拥有不代表一定能打开。

官方示例

示例 1

输入：
status = [1,0,1,0]
candies = [7,5,4,100]
keys = [[],[],[1],[]]
containedBoxes = [[1,2],[3],[],[]]
initialBoxes = [0]
输出：16
解释：依次打开 0、2、1，盒子 3 没有钥匙，合计 7+4+5。

containedBoxes = [[1,2,3,4,5],[],[],[],[],[]]
initialBoxes = [0]
输出：6
解释：盒子 0 同时给出其余盒子及对应钥匙。

示例 3

输入：
status = [1,1,1]
candies = [100,1,100]
keys = [[],[0,2],[]]
containedBoxes = [[],[],[]]
initialBoxes = [1]
输出：1

示例 4

输入：
status = [1]
candies = [100]

initialBoxes = []

示例 5

输入：
status = [1,1,1]

containedBoxes = [[],[],[]]
initialBoxes = [2,1,0]
输出：7

约束

  • n == status.length == candies.length == keys.length == containedBoxes.length
  • 1 <= n <= 1000
  • status[i] 只能是 0 或 1
  • 1 <= candies[i] <= 1000
  • 0 <= keys[i].length, containedBoxes[i].length <= n
  • 0 <= keys[i][j], containedBoxes[i][j] < n
  • 每个 keys[i] 内的编号互不相同；每个 containedBoxes[i] 内的编号互不相同
  • 每个盒子最多被一个盒子包含
  • 0 <= initialBoxes.length <= n，且每个初始编号均在 [0, n) 内

    Solution vault

    准备好揭开题解了吗？

    先自己想一想：一个关闭的盒子，应该在什么时候重新检查？

    完整题解：可执行状态的广度优先搜索

    核心洞察

    盒子能被打开必须同时满足两个独立条件：我们拥有这个盒子，以及它初始开放或已经拿到了钥匙。钥匙和盒子的到达顺序不确定，所以分别维护 haveBox 与 canOpen；任何一个条件刚变为真时，都检查另一个条件是否已经满足。满足双条件且尚未处理的盒子才入队。

    完整过程

    1. 用 canOpen 复制初始 status，并建立 haveBox、used 与队列。
    2. 登记所有 initialBoxes；其中已经可打开的盒子立即入队。
    3. 每次出队一个未处理盒子，将其标记为 used 并累加糖果。
    4. 遍历盒子里的钥匙：标记对应盒子可打开；若那个盒子已拥有且未处理，就入队。
    5. 遍历盒子里的内含盒子：标记为已拥有；若它已经可打开且未处理，就入队。
    6. 队列为空后，剩余盒子至少缺一个条件，无法再产生新状态，累加值即答案。

    实现中允许同一盒子在真正处理前被重复加入队列，出队时由 used 跳过即可；也可以额外维护 queued 去重。前者代码更短，整体仍然是线性级别。

    正确性证明

    引理 1：算法只会打开合法盒子

    盒子只有在 haveBox[i] 与 canOpen[i] 同时为真时才会入队。前者证明盒子已经到手，后者证明盒子初始开放或钥匙已经取得，因此每次实际处理都符合规则。

    引理 2：每个最终可打开的盒子都会被算法处理

    对任意最终满足双条件的盒子 i，考虑两个条件中较晚成立的那个时刻。若较晚获得钥匙，钥匙分支会检查已经拥有的盒子；若较晚获得盒子，内含盒子分支会检查已经可打开的状态。两种情况都会把未处理的 i 加入队列。

    定理：算法返回最大糖果数

    由引理 1，累加的糖果全部可合法获得；由引理 2，所有通过规则可到达并打开的盒子都被处理。糖果数均为正，取得所有可打开盒子的糖果必然最优，因此返回值就是最大值。

    边界情况

    • initialBoxes 为空：队列为空，答案为 0。
    • 拥有盒子但没有钥匙：先保留在 haveBox 中，未来拿到钥匙再激活。
    • 先拿到钥匙、后拿到盒子：canOpen 会保留解锁状态，盒子到手时立即激活。
    • 盒子本来开放但永远拿不到：不能处理，因为缺少“拥有”条件。
    • 钥匙或内含关系形成环：used 保证每个盒子至多真正处理一次。

    复杂度

    设所有 keys 列表与所有 containedBoxes 列表的元素总数为 E。每个盒子至多被处理一次，每条关系只在其来源盒子处理时扫描一次，因此时间复杂度为 O(n + E)，额外空间复杂度为 O(n)。

    替代方案

    可以反复扫描所有已经拥有但未打开的盒子，只要一轮有进展就继续。这种写法直观，却可能产生 O(n² + E) 的重复检查。也可以将题目建模为单调状态传播或固定点迭代；本质与队列 BFS 相同，但双布尔数组更贴近代码和面试表达。

    面试追问

    • 如果每个盒子需要多把钥匙才能打开？将 canOpen 攭为剩余钥匙计数，计数归零且已拥有时入队。
    • 如果打开盒子有成本、糖果允许为负数？“能开就开”不再必然最优，可能转化为带收益的状态搜索。
    • 如何输出打开顺序？在实际处理盒子时追加编号；多个合法顺序都能得到同一最大总数。
    • 怎样避免重复入队？增加 queued 数组，在入队时标记。

    常见错误

    • 把“拿到钥匙”误认为“已经拥有盒子”，导致打开尚未发现的盒子。
    • 只在发现盒子时检查状态，忘记钥匙可能更晚到达。
    • 只在获得钥匙时检查盒子，忘记钥匙也可能更早到达。
    • 没有 used，在环或重复触发下重复累加糖果。
    • 直接修改输入 status 却未说明副作用；复制为 canOpen 更稳妥。

    import java.util.ArrayDeque;
import java.util.Queue;

class Solution {
    public int maxCandies(int[] status, int[] candies, int[][] keys,
                          int[][] containedBoxes, int[] initialBoxes) {
        int n = status.length;
        boolean[] canOpen = new boolean[n];
        boolean[] haveBox = new boolean[n];
        boolean[] used = new boolean[n];
        Queue<Integer> queue = new ArrayDeque<>();

        for (int i = 0; i < n; i++) canOpen[i] = status[i] == 1;
        for (int box : initialBoxes) {
            haveBox[box] = true;
            if (canOpen[box]) queue.offer(box);
        }

        int answer = 0;
        while (!queue.isEmpty()) {
            int box = queue.poll();
            if (used[box]) continue;
            used[box] = true;
            answer += candies[box];

            for (int key : keys[box]) {
                canOpen[key] = true;
                if (haveBox[key] && !used[key]) queue.offer(key);
            }
            for (int inside : containedBoxes[box]) {
                haveBox[inside] = true;
                if (canOpen[inside] && !used[inside]) queue.offer(inside);
            }
        }
        return answer;
    }
}
    /**
 * @param {number[]} status
 * @param {number[]} candies
 * @param {number[][]} keys
 * @param {number[][]} containedBoxes
 * @param {number[]} initialBoxes
 * @return {number}
 */
var maxCandies = function(status, candies, keys, containedBoxes, initialBoxes) {
    const n = status.length;
    const canOpen = status.map(value => value === 1);
    const haveBox = new Array(n).fill(false);
    const used = new Array(n).fill(false);
    const queue = [];
    let head = 0;

    for (const box of initialBoxes) {
        haveBox[box] = true;
        if (canOpen[box]) queue.push(box);
    }

    let answer = 0;
    while (head < queue.length) {
        const box = queue[head++];
        if (used[box]) continue;
        used[box] = true;
        answer += candies[box];

        for (const key of keys[box]) {
            canOpen[key] = true;
            if (haveBox[key] && !used[key]) queue.push(key);
        }
        for (const inside of containedBoxes[box]) {
            haveBox[inside] = true;
            if (canOpen[inside] && !used[inside]) queue.push(inside);
        }
    }
    return answer;
};
    from collections import deque
from typing import List

class Solution:
    def maxCandies(
        self,
        status: List[int],
        candies: List[int],
        keys: List[List[int]],
        containedBoxes: List[List[int]],
        initialBoxes: List[int],
    ) -> int:
        n = len(status)
        can_open = [value == 1 for value in status]
        have_box = [False] * n
        used = [False] * n
        queue = deque()

        for box in initialBoxes:
            have_box[box] = True
            if can_open[box]:
                queue.append(box)

        answer = 0
        while queue:
            box = queue.popleft()
            if used[box]:
                continue
            used[box] = True
            answer += candies[box]

            for key in keys[box]:
                can_open[key] = True
                if have_box[key] and not used[key]:
                    queue.append(key)

            for inside in containedBoxes[box]:
                have_box[inside] = True
                if can_open[inside] and not used[inside]:
                    queue.append(inside)

        return answer
    #include <queue>
#include <vector>
using namespace std;

class Solution {
public:
    int maxCandies(vector<int>& status, vector<int>& candies,
                   vector<vector<int>>& keys,
                   vector<vector<int>>& containedBoxes,
                   vector<int>& initialBoxes) {
        int n = status.size();
        vector<bool> canOpen(n, false), haveBox(n, false), used(n, false);
        queue<int> q;

        for (int i = 0; i < n; ++i) canOpen[i] = status[i] == 1;
        for (int box : initialBoxes) {
            haveBox[box] = true;
            if (canOpen[box]) q.push(box);
        }

        int answer = 0;
        while (!q.empty()) {
            int box = q.front();
            q.pop();
            if (used[box]) continue;
            used[box] = true;
            answer += candies[box];

            for (int key : keys[box]) {
                canOpen[key] = true;
                if (haveBox[key] && !used[key]) q.push(key);
            }
            for (int inside : containedBoxes[box]) {
                haveBox[inside] = true;
                if (canOpen[inside] && !used[inside]) q.push(inside);
            }
        }
        return answer;
    }
};
