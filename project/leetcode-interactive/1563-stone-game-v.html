石子游戏 VStone Game V

每次切成两段，价值更大的那段会被丢弃。真正的选择不是“这一刀能拿多少”，而是“留下哪段，能把未来也一起变得更好”。

先读规则并亲手走几步。完整状态转移、证明与代码被刻意放在页面底部，不会在首屏直接泄露。
Problem

题意

函数形式：stoneGameV(stoneValue)，返回 Alice 能获得的最大总分。

一排石子由整数数组 stoneValue 表示。每轮 Alice 必须在相邻石子之间切一刀，得到两个非空连续段；Bob 比较两段元素和，丢弃和值更大的段，Alice 把留下段的和值加入总分，并在留下段上继续游戏。若两段和值相等，Alice 可以决定留下哪一段。只剩一块石子时结束。

01 / 切分当前连续区间必须被切成两个非空区间。
02 / 取舍较大和被丢弃；相等时 Alice 选择保留方向。
03 / 得分保留段的和立即计分，并成为下一轮状态。
Examples & constraints

官方示例与约束

示例 1
输入：stoneValue = [6,2,3,4,5,5]
输出：18
解释：先切为 [6,2,3] / [4,5,5]，保留左段得 11；
再切为 [6] / [2,3]，保留右段累计到 16；
最后切为 [2] / [3]，保留 [2]，总分 18。
示例 2
输入：stoneValue = [7,7,7,7,7,7,7]
输出：28
示例 3
输入：stoneValue = [4]
输出：0

  • 1 <= stoneValue.length <= 500
  • 1 <= stoneValue[i] <= 106

Core insight

核心洞察

设 dp[i][j] 为区间 [i,j] 的最大后续得分。切分点决定本轮保留哪一边；本轮所得区间和，加上那一边已经求出的最优值，就是候选答案。

直接枚举所有区间和所有切分点是 O(n³)。要降到 O(n²)，对每个区间只找“左右和的分界点”，再用两个辅助最大值表一次取出分界点两侧的最佳候选。

leftBest[i][j] = max(dp[i][t] + sum(i,t)), i ≤ t ≤ j rightBest[i][j] = max(dp[t][j] + sum(t,j)), i ≤ t ≤ j
Process

完整过程

前缀和

用 prefix[r+1]-prefix[l] 在 O(1) 时间得到任意连续区间的和。

确定分界点 k

对固定左端点 i，右端点 j 从小到大扩张。维护最大的 k，满足 sum(i,k) ≤ sum(k+1,j)。由于元素全为正，k 只会右移。

左侧候选

所有切分点不超过 k 时，左段和不大于右段，必然保留左段。最佳值可直接读取 leftBest[i][k]。

右侧候选与相等情况

更右的切分保留右段，从 rightBest 读取。若在 k 处恰好相等，右段也合法，起点是 k+1；否则从 k+2 开始。

更新辅助表

得到 dp[i][j] 后，将 dp[i][j]+sum(i,j) 合并进左右辅助最大值。按 i 递减、j 递增的顺序，依赖状态都已就绪。

Correctness

正确性证明

状态完备

游戏进行中剩余石子始终是原数组的一个连续区间，因此 dp[i][j] 覆盖所有可能状态。

转移完备

任意切分要么左和较小、要么右和较小、要么相等。分界点把这些切分无遗漏地分为两组；相等切分同时允许两侧。

最优子结构

首轮留下某一段后，后续选择只与该段有关。将本轮得分与该段的最优子问题相加，再对全部合法首刀取最大，即得到全局最优。

Complexity

复杂度与边界

  • 时间：O(n²)。每个 i 的分界指针总共右移 O(n) 次。
  • 空间：O(n²)，用于 DP 与两个辅助最大值表。
  • n=1：无法切分，答案为 0。
  • 相等和：Alice 可选两边，必须同时考虑。
  • 最大总分可能超过 32 位有符号整数的安全推导范围；实现内部统一使用 64 位数值（JavaScript 的 Number 对本题范围精确）。
Alternative

替代方案

朴素区间 DP：枚举 i、j、k，实现直观，时间 O(n³)、空间 O(n²)。它很适合推导和小规模演示，但在 n=500 时不够稳妥。

记忆化搜索：同样可直接表达游戏过程，但若每个状态仍扫描全部切分点，时间仍为 O(n³)，并有递归开销。

class Solution {
    public int stoneGameV(int[] stoneValue) {
        int n = stoneValue.length;
        long[] pre = new long[n + 1];
        for (int i = 0; i < n; i++) pre[i + 1] = pre[i] + stoneValue[i];

        long[][] dp = new long[n][n];
        long[][] leftBest = new long[n][n];
        long[][] rightBest = new long[n][n];

        for (int i = n - 1; i >= 0; i--) {
            leftBest[i][i] = rightBest[i][i] = stoneValue[i];
            int k = i - 1;
            for (int j = i + 1; j < n; j++) {
                while (k + 1 < j && sum(pre, i, k + 1) <= sum(pre, k + 2, j)) k++;
                long best = k >= i ? leftBest[i][k] : 0;
                int rightStart = k + 2;
                if (k >= i && sum(pre, i, k) == sum(pre, k + 1, j)) rightStart = k + 1;
                if (rightStart <= j) best = Math.max(best, rightBest[rightStart][j]);
                dp[i][j] = best;
                long whole = sum(pre, i, j);
                leftBest[i][j] = Math.max(leftBest[i][j - 1], best + whole);
                rightBest[i][j] = Math.max(rightBest[i + 1][j], best + whole);
            }
        }
        return (int) dp[0][n - 1];
    }

    private long sum(long[] pre, int l, int r) {
        return pre[r + 1] - pre[l];
    }
}

from typing import List

class Solution:
    def stoneGameV(self, stoneValue: List[int]) -> int:
        n = len(stoneValue)
        prefix = [0] * (n + 1)
        for i, value in enumerate(stoneValue):
            prefix[i + 1] = prefix[i] + value

        def interval_sum(left: int, right: int) -> int:
            return prefix[right + 1] - prefix[left]

        dp = [[0] * n for _ in range(n)]
        left_best = [[0] * n for _ in range(n)]
        right_best = [[0] * n for _ in range(n)]

        for i in range(n - 1, -1, -1):
            left_best[i][i] = right_best[i][i] = stoneValue[i]
            k = i - 1
            for j in range(i + 1, n):
                while k + 1 < j and interval_sum(i, k + 1) <= interval_sum(k + 2, j):
                    k += 1
                best = left_best[i][k] if k >= i else 0
                right_start = k + 2
                if k >= i and interval_sum(i, k) == interval_sum(k + 1, j):
                    right_start = k + 1
                if right_start <= j:
                    best = max(best, right_best[right_start][j])
                dp[i][j] = best
                whole = interval_sum(i, j)
                left_best[i][j] = max(left_best[i][j - 1], best + whole)
                right_best[i][j] = max(right_best[i + 1][j], best + whole)

        return dp[0][n - 1]

Interview follow-ups

追问与常见错误

面试追问

  • 为什么正数条件能保证分界点单调？
  • 如果数组允许负数，O(n²) 优化还成立吗？
  • 怎样先写 O(n³) 版本，再安全演进到辅助最大值版本？
  • 能否压缩三个二维数组的空间？依赖顺序会受到什么影响？

常见错误

  • 把被丢弃的较大段计入得分。
  • 左右和相等时只考虑固定一边，漏掉最优路径。
  • 把 dp 定义成“已得分”而不是“当前区间的最大后续得分”，导致状态混乱。
  • 分界点下标偏移一位，尤其是右侧候选的 k+1 / k+2。
  • 使用 32 位中间值计算区间和与累积分数。
