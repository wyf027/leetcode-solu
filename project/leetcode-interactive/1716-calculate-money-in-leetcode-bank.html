Solution

把日历拆成完整周与剩余天

核心洞察

每个完整星期都是长度为 7 的等差数列。第一周从 1 开始，第二周从 2 开始；因此第 i 周（从 0 开始）的总额是 28 + 7i。把 n 拆成完整周数 w = floor(n / 7) 和剩余天数 r = n % 7，即可分别求和。

总额 = 28w + 7w(w−1)/2 + r(w+1) + r(r−1)/2

完整过程

  1. 计算 w = n / 7 的整数部分与 r = n % 7。
  2. 完整周的首周和为 28，此后每周整体增加 7；其总和为 28w + 7w(w−1)/2。
  3. 剩余天属于第 w + 1 周，从 w + 1 开始连续递增，共 r 项；其总和为 r(w+1) + r(r−1)/2。
  4. 相加并返回。

正确性说明

对任意一天，它唯一属于某个完整周或最后一个不完整周。完整周公式逐周覆盖前 7w 天，每周内部的 7 个存款值全部计入一次；剩余项公式恰好覆盖第 7w + 1 天到第 n 天，也全部计入一次。两部分互不重叠且并集是前 n 天，所以相加所得就是第 n 天结束时的总额。

边界与复杂度

  • n = 1：没有完整周，只计算 1 个剩余日。
  • n % 7 = 0：剩余日为 0，后一部分自然为 0。
  • n = 1000：公式仍只做固定次数的整数运算。
  • 时间复杂度 O(1)，空间复杂度 O(1)。

替代方案

可以从第 1 天模拟到第 n 天，每天用“周序号 + 星期序号 + 1”得到存款额。它更直观，时间复杂度为 O(n)；约束只有 1000 时也足够，但公式法更能体现规律。

四种语言实现

Java
class Solution {
    public int totalMoney(int n) {
        int weeks = n / 7;
        int days = n % 7;
        int fullWeeks = 28 * weeks
                + 7 * weeks * (weeks - 1) / 2;
        int remainder = days * (weeks + 1)
                + days * (days - 1) / 2;
        return fullWeeks + remainder;
    }
}

面试追问

  • 如果一周不是 7 天，如何把公式参数化？
  • 如何仅用模拟写法，并清晰表达星期切换？
  • 当 n 极大时，应选择什么整数类型来避免溢出？

常见错误

  • 把第二个周一误写成接着周日的 8，而不是 2。
  • 剩余周起点写成 w，漏掉 +1。
  • 等差数列项数误用 r + 1。
  • 在除以 2 前过早使用错误的整数除法组合。
