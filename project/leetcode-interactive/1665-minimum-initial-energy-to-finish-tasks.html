LeetCode 1665 · Greedy / Sorting

完成所有任务的
最少初始能量

每个任务都有一道“准入门槛”，完成后还会消耗能量。顺序可以自由决定：你需要找到一个最小的起点，让整段任务链不断电。

HARD 非付费题 数组 贪心 排序
Problem

题目描述

给定二维数组 tasks，其中 tasks[i] = [actuali, minimumi]：

  • actuali 表示完成第 i 个任务实际消耗的能量。
  • minimumi 表示开始第 i 个任务时至少需要拥有的能量。
  • 只有当前能量不低于 minimumi 才能开始；完成后能量减少 actuali。

任务可以按任意顺序完成。返回完成全部任务所需的最少初始能量。

注意：门槛不是消耗量。任务 [10,12] 在能量为 11 时不能开始；能量为 13 时可以完成，完成后剩余 3。
Contract

函数签名

minimumEffort(tasks)

参数：tasks: integer[][]
返回：integer

约束

1 <= tasks.length <= 105
1 <= actuali <= minimumi <= 104

Solution

准备好再揭晓

先形成自己的排序猜想。题解、证明、复杂度、四语言代码和面试追问都收在下面。

Core insight

按“能量缓冲”从大到小排序

对任务 [actual, minimum] 定义缓冲量 minimum - actual。缓冲越大，说明它对“开始时的能量”要求相对越苛刻，应越早完成。

tasks.sort((a, b) => (b[1]-b[0]) - (a[1]-a[0]))
Accumulator

把前置消耗叠加到当前门槛

排序后依次扫描。设 spent 是此前任务总消耗；要顺利开始当前任务，初始能量至少为 spent + minimum。

answer = max(answer, spent + minimum)

完整过程

  1. 计算每个任务的缓冲量 minimum - actual。
  2. 按缓冲量降序排列任务。缓冲相等时，任意相对顺序都不影响最优性。
  3. 从前向后扫描。对当前任务，用 spent + minimum 更新所需初始能量的下界。
  4. 把当前任务的 actual 累加进 spent。扫描结束后的最大下界就是答案。
排序后： [4,8] → [2,4] → [1,2]
spent = 0：需要至少 0 + 8 = 8
spent = 4：需要至少 4 + 4 = 8
spent = 6：需要至少 6 + 2 = 8
答案 = 8

正确性：相邻交换论证

考虑相邻任务 A、B，记其消耗为 aA, aB，门槛为 mA, mB。若 A 的缓冲不小于 B，即：

mA - aA ≥ mB - aB

A 在前需要的局部初始能量为 max(mA, aA + mB)；B 在前则为 max(mB, aB + mA)。

由缓冲关系得 aA + mB ≤ aB + mA，且 mA ≤ aB + mA，所以 A 在前的两个下界都不超过 B 在前时的下界 aB + mA。把每一对逆序任务交换掉都不会让答案变差，最终得到缓冲量降序，因此该顺序最优。扫描精确计算此顺序的最小可行初始能量，故答案正确。

复杂度与边界

  • 时间复杂度：排序 O(n log n)，扫描 O(n)。
  • 空间复杂度：忽略排序实现栈，额外空间 O(1)；不同语言的排序可能需要 O(log n) 或 O(n) 辅助空间。
  • 单任务时答案就是它的 minimum。
  • actual = minimum 时缓冲为 0，通常排在更有缓冲的任务之后。
  • 最多 105 个任务，总消耗可达 109；32 位有符号整数仍可容纳，但比较器中要避免不必要的溢出写法。

四语言完整代码

import java.util.Arrays;

class Solution {
    public int minimumEffort(int[][] tasks) {
        Arrays.sort(tasks, (a, b) -> {
            int slackA = a[1] - a[0];
            int slackB = b[1] - b[0];
            return Integer.compare(slackB, slackA);
        });

        int answer = 0;
        int spent = 0;
        for (int[] task : tasks) {
            answer = Math.max(answer, spent + task[1]);
            spent += task[0];
        }
        return answer;
    }
}

class Solution {

    int minimumEffort(vector<vector<int>>& tasks) {
        sort(tasks.begin(), tasks.end(),
             [](const vector<int>& a, const vector<int>& b) {
                 return a[1] - a[0] > b[1] - b[0];
             });

        int answer = 0;
        int spent = 0;
        for (const auto& task : tasks) {
            answer = max(answer, spent + task[1]);
            spent += task[0];
        }
        return answer;
    }

替代方案

二分答案：“初始能量为 x 是否可行”具有单调性，因此可以二分最小 x；每次仍要按合适顺序验证，整体通常为 O(n log V + n log n)，不如直接贪心简洁。

倒推补能量：也可以按相反方向构造，维护为了完成后缀还差多少能量。它与当前贪心本质等价，但更容易在排序方向上写错。

面试追问

  • 为什么不是按 minimum 最大优先？请构造反例。
  • 缓冲相等时为什么任意顺序都可以？
  • 若任务完成后能量可能增加，交换论证是否仍成立？
  • 如果任务之间有依赖关系，问题会发生什么变化？

常见错误

把 minimum 当消耗：完成后应减去 actual，不是减去 minimum。
排序方向颠倒：应让 minimum - actual 大的任务先做。
只求消耗总和：总消耗无法覆盖中途的启动门槛。
扫描时忘记前置消耗：当前下界是 spent + minimum，不是只有 minimum。
