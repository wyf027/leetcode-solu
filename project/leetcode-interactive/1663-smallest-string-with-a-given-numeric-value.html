Problem

题意

函数：getSmallestString(n, k)

小写字母的数值等于它在字母表中的位置：a = 1、b = 2，一直到 z = 26。一个字符串的数值是其中每个字符数值的总和。

给定整数 n 和 k，请返回一个长度恰为 n、字符数值总和恰为 k 的小写字符串；在所有符合条件的字符串中，它必须拥有最小字典序。

两个候选字符串长度相同时，从左向右找到第一个不同字符；该位置字符更靠前的字符串，字典序更小。

Full solution

贪心：从右向左投放额外数值

核心洞察

长度为 n 的字符串，每个位置至少是 a = 1，先放满 a 会消耗 n；还需分配的额外值是 extra = k - n。

为了让字典序尽可能小，应尽量不增大靠左字符，所以从最右端开始分配 extra。每个字符从 a 最多再增加 25，当前位增加 min(25, extra) 即可。

完整过程

  1. 创建长度为 n、全部为 a 的字符数组。
  2. 令 extra = k - n。
  3. 从下标 n − 1 递减遍历；当前位加入 min(25, extra)。
  4. 从 extra 中减去本次加入值；extra 为 0 时结束。
  5. 拼接字符数组并返回。

正确性证明

可行性：初始 n 个 a 的总值为 n。算法只分配 k − n 个额外单位，而且任一位置至多增加 25，因此最终总值为 k，所有字符仍在 a～z 之间，长度也始终是 n。

字典序最小：考虑算法第一次必须把额外值放到某个较靠左位置 i 的时刻。它意味着 i 右侧的所有位置都已达到 z；否则仍可把至少一个单位从 i 移到更右的位置，使位置 i 的字符更小，同时保持长度与总值不变，从而得到更小字典序，产生矛盾。由此，任何可行答案在第一个不同位置都不可能比算法的字符更小，所以算法答案字典序最小。

边界情况

  • k = n：没有额外值，答案全为 a。
  • k = 26n：每一位都达到 z。
  • n = 1：唯一字符直接对应 k。
  • n 可达 105，应避免反复在字符串头部拼接。

JavaLeetCode
class Solution {
    public String getSmallestString(int n, int k) {
        char[] answer = new char[n];
        java.util.Arrays.fill(answer, 'a');

        int extra = k - n;
        for (int i = n - 1; i >= 0 && extra > 0; i--) {
            int add = Math.min(25, extra);
            answer[i] = (char) ('a' + add);
            extra -= add;
        }
        return new String(answer);
    }
}

var getSmallestString = function(n, k) {
    const answer = new Array(n).fill('a');
    let extra = k - n;

    for (let i = n - 1; i >= 0 && extra > 0; i--) {
        const add = Math.min(25, extra);
        answer[i] = String.fromCharCode(97 + add);
        extra -= add;
    }
    return answer.join('');
};
Python 3LeetCode
class Solution:
    def getSmallestString(self, n: int, k: int) -> str:
        answer = ['a'] * n
        extra = k - n

        for i in range(n - 1, -1, -1):
            if extra == 0:
                break
            add = min(25, extra)
            answer[i] = chr(ord('a') + add)
            extra -= add

        return ''.join(answer)

class Solution {
public:
    string getSmallestString(int n, int k) {
        string answer(n, 'a');
        int extra = k - n;

        for (int i = n - 1; i >= 0 && extra > 0; --i) {
            int add = min(25, extra);
            answer[i] = static_cast<char>('a' + add);
            extra -= add;
        }
        return answer;
    }

面试追问

  • 如果要求字典序最大，遍历方向如何变化？
  • 如果每个位置允许的字符范围不同，如何判断剩余部分的可行容量？
  • 能否用左到右方式写出等价贪心，并证明当前字符的下界？
  • 若 k 不保证可行，入口处应增加什么判断？

常见错误

  • 忘记先扣除每个 a 已贡献的 n。
  • 从左侧投放较大字符，得到数值正确但字典序更大的结果。
  • 单个位置增加超过 25，生成 z 之后的非法字符。
  • JavaScript 反复拼接或头插大型数组，制造不必要开销。
  • 把字符值当作从 0 开始，造成整体偏差。
