Complement of Base 10 Integer。先观察每一个二进制位如何翻转，再思考怎样只翻转有效位。

题目

整数的反码，是把其二进制表示中的每个 0 换成 1、每个 1 换成 0 后得到的整数。给定非负整数 n，返回它的反码。

只处理有效位：正数的二进制表示没有前导零；n = 0 的表示是单独一位 0。

官方示例

输入：n = 5
输出：2
解释：101 → 010
输入：n = 7
输出：0
解释：111 → 000
输入：n = 10
输出：5
解释：1010 → 0101

  • bitwiseComplement(n: integer) → integer

先自己发现规律

把所有有效位都设成 1，就得到“全 1 掩码”。想一想：原数与反码在每一位上恰好互补，可以用哪一种位运算直接转换？

提示：1010 所需掩码是 1111，而不是无限多个 1。

题解：构造有效位掩码

核心洞察

若 n 有 k 个有效二进制位，mask = 2^k - 1 恰好是 k 个 1。因此 n XOR mask 只会翻转有效位。

完整过程

  1. 特殊处理 n = 0：一位 0 的反码为 1。
  2. 从 mask = 0 开始，反复执行 mask = (mask << 1) | 1，直到覆盖 n 的全部有效位。
  3. 返回 n ^ mask。

正确性

  1. 循环构造出与 n 有效位数相同、且每位均为 1 的掩码。
  2. 与 1 异或会翻转该位，因此每个有效位都被正确翻转。
  3. 更高位的掩码为 0，不会引入额外高位，故结果正是所求反码。

边界与复杂度

n = 0 返回 1。循环次数为二进制位数，时间复杂度 O(log n)，额外空间 O(1)。

替代方案

也可找到第一个大于 n 的 2 的幂 p，返回 (p - 1) - n。直接使用 ~n 会翻转固定位宽的所有高位，常得到负数，不符合题意。

面试追问

  • 为什么 n + complement = mask？
  • 如何用最高有效位的位置一次构造掩码？
  • 扩展到 64 位时如何避免移位溢出？

常见错误

  • 遗漏 n = 0。
  • 直接返回 ~n。
  • 循环条件错误，使掩码多一位或少一位。

四种语言完整代码

Java
class Solution {
    public int bitwiseComplement(int n) {
        if (n == 0) return 1;
        int mask = 0, value = n;
        while (value > 0) {
            mask = (mask << 1) | 1;
            value >>= 1;
        }
        return n ^ mask;
    }
}
