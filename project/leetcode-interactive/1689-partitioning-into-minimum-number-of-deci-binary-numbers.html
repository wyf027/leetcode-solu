Problem

题目描述

如果一个十进制数不含前导零，而且每一位只能是 0 或 1，就称它为十-二进制数。例如 101、1100 符合定义，而 112、3001 不符合。

给定字符串 n，它表示一个正十进制整数。请返回最少需要多少个正十-二进制数，才能让它们的和恰好等于 n。

函数形式

minPartitions(n: string) -> integer

约束

  • 1 <= n.length <= 105
  • n 只由数字 0–9 组成。
  • n 没有前导零，并且表示正整数。
示例 1
输入：n = "32"
输出：3
解释：10 + 11 + 11 = 32
示例 2
输入：n = "82734"
输出：8
示例 3
输入：n = "27346209830709182346"
输出：9

Solution

题解：答案就是最大数位

核心洞察

答案是字符串 n 中的最大数字。不需要把可能长达 105 位的 n 转成整数，只需扫描字符。

answer = max(n[0], n[1], …, n[n.length - 1])

为什么不能更少：下界

设某一位是数字 d。每个十-二进制数在这一位最多贡献 1，所以要把这一位累加到 d，至少需要 d 个数。对所有数位都成立，因此至少需要最大数位那么多个。

为什么一定够用：构造上界

设最大数位为 m。构造 m 层：第 k 层在原数字位值大于等于 k 的位置放 1，否则放 0。每一列恰好出现所需数量的 1，所以总和就是 n。

完整过程

  1. 从左到右读取字符串的每个字符。
  2. 维护目前见过的最大数字 best。
  3. 若读到 9，可立即返回，因为十进制数字不可能超过 9。
  4. 扫描结束后返回 best。

正确性证明

命题：算法返回的最大数位 m 等于表示 n 所需的最少十-二进制数个数。

证明：取一个值为 m 的数位。任意一个十-二进制数在该位只能贡献 0 或 1，要得到 m 至少需要 m 个数，故最优值不小于 m。另一方面，按第 k 层在数位值至少为 k 时放 1 的方式构造 m 个数；任一值为 d 的数位会在前 d 层各得到一个 1，总贡献恰为 d。因此这 m 个数之和为 n，最优值不大于 m。上下界相同，命题成立。∎

复杂度

时间：O(L)，其中 L = n.length。最坏扫描一次字符串。

额外空间：O(1)。

边界情况

  • 单个数字：答案就是这个数字本身。
  • 只含 0、1：由于 n 为正数，答案是 1。
  • 非常长的字符串：不要做大整数转换。
  • 读到 9：可安全提前结束扫描。

四种语言实现

class Solution {
    public int minPartitions(String n) {
        int best = 0;

        for (int i = 0; i < n.length(); i++) {
            int digit = n.charAt(i) - '0';
            best = Math.max(best, digit);

            if (best == 9) {
                return 9;
            }
        }

        return best;
    }
}

替代方案与取舍

可以真的构造出每一层十-二进制数，这正是上方实验台的做法；但题目只要求数量，构造会额外消耗 O(L × m) 时间与空间，其中 m ≤ 9。也可以排序字符后取最大值，但排序需要 O(L log L)，明显没有必要。

面试追问

为什么各个数位可以独立考虑，不用处理进位？

构造时每一列只叠加 0 或 1，而且恰好叠出原数位的值，范围仍是 0–9；列本身不产生额外进位，因此各列可以独立完成，再合并成同一批十-二进制数。

如果真的要求输出一种最优分解，怎么改？

先求最大数位 m，再生成 m 个等宽位串。第 k 个位串在原数位 d ≥ k 时写 1，否则写 0；最后移除每个串的对齐前置 0。

输入长度 10⁵ 时，哪种实现细节最重要？

保持字符串形式逐字符扫描，避免数值转换；看到 9 可直接返回。这样既不会溢出，也只使用常数额外空间。

常见错误

  • 把整个字符串转换为普通整数，导致溢出或精度丢失。
  • 误以为要做背包、动态规划或枚举所有十-二进制数。
  • 返回不同数字的数量，而不是最大数位的值。
  • 构造对齐位串时把前置 0 当成数值的一部分；它们只用于展示列位置。
