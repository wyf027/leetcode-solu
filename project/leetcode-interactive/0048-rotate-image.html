The brief

题意转述

输入一定是正方形，因此每个像素旋转后仍能落回同一张方格纸。这道题真正考察的不是“得到答案”，而是能否在原矩阵上完成变换。

任务

MODIFY IN PLACE

给定一个 n × n 整数矩阵 matrix，将它顺时针旋转 90°。函数不返回新矩阵，直接改写传入的矩阵。

The answer

转置，再翻转每一行

MEMORY CARD

顺时针 90°
= 主对角线转置
+ 水平镜像

(r, c) → (c, n − 1 − r)

Core insight

核心洞察

目标位置公式虽然是 new[c][n - 1 - r] = old[r][c]，但直接照公式写往往需要新矩阵。把它拆成两个可原地执行的几何变换：转置把 (r,c) 送到 (c,r)；再水平镜像，把列 r 送到 n-1-r，两步合成正好是顺时针旋转。

Full process

完整解题过程

  1. 1

    沿主对角线转置

    只遍历对角线上方的元素，交换 matrix[i][j] 与 matrix[j][i]。令 j = i + 1，避免同一对交换两次。

  2. 2

    逐行左右翻转

    每行使用左右指针交换，直到相遇。此时矩阵已经完成顺时针 90° 旋转。

  3. 3

    原地结束

    不创建第二个二维矩阵，也不返回新值；只使用临时变量完成交换。

边界情况

  • • n = 1：两轮交换都自然跳过。
  • • n 为奇数：中心像素保持不动。
  • • 含负数或重复值：只移动位置，不依赖数值。
  • • n 为偶数：每个像素都参与旋转。

复杂度

时间
O(n²)
额外空间
O(1)

输出仍在输入矩阵中，因此不计输入本身占用。

替代方案与取舍

逐层四点轮换

同样是 O(n²) / O(1)，一次直接搬动上、右、下、左四点；少一次完整遍历，但下标更容易写错，面试表达成本高。

额外矩阵映射

公式最直观，但空间为 O(n²)，违反“原地”要求。适合用于测试时充当独立对拍 oracle。

常见错误

  • • 转置时让 j 从 0 开始，导致交换被撤销。
  • • 转置后翻转“列”，得到的方向不是顺时针 90°。
  • • JavaScript 用 matrix.reverse() 后误以为完成旋转。
  • • 返回新矩阵，忽略题目要求函数原地修改。

面试高频追问

  • • 逆时针 90° 怎么组合？转置后上下翻转。
  • • 旋转 180° 怎么做？上下翻转 + 左右翻转。
  • • 为什么是 O(1)？只有若干循环变量和临时交换变量。
  • • 非正方形矩阵能否原地？通常尺寸会改变，原地定义需要重新讨论。
