Scene Brief

题意

给定等长数组 height 与 weight，第 i 位演员的身高、体重分别由两数组的第 i 项给出。人塔中，上方演员必须同时比下方演员更矮、更轻。返回最多能选择多少位演员组成合法人塔。

官方样例

输入height = [65,70,56,75,60,68], weight = [100,150,90,190,95,110]
输出6

从上到下可以依次选择：(56,90)、(60,95)、(65,100)、(68,110)、(70,150)、(75,190)。

OFFICIAL CONSTRAINT

height.length == weight.length <= 10000

题面未额外限定数值范围；解法只比较大小，不依赖具体上界。

Full Solution

题解

核心洞察

固定身高顺序后，问题就变成体重的严格最长递增子序列。关键是：身高升序时，同身高必须按体重降序，否则同高演员可能被错误地纳入递增体重序列。

面试最推荐：排序 + 二分 LIS

维护 tails[k]：长度为 k + 1 的严格递增体重子序列中，可能的最小末尾体重。对每个体重用 lower_bound 找第一个不小于它的位置并覆盖。

完整过程

  1. 把每个人合并为 (height, weight)。
  2. 身高升序；身高相同时体重降序。这样同一身高组的体重不可能贡献两个严格上升项。
  3. 按排序后的顺序扫描体重，在 tails 中二分第一个 >= weight 的位置。
  4. 若位置等于 tails.length，追加新层；否则覆盖该位置，让相同长度的序列留下更轻、更容易延伸的末尾。
  5. tails.length 就是最大人数。注意 tails 不一定是一座真实的人塔，它编码的是各长度的最优末尾。

边界

  • · 空数组（若平台调用）返回 0。
  • · 单人返回 1。
  • · 全部同高最多选 1 人。
  • · 重复体重不能形成严格递增。

复杂度

排序与 LIS 都是 O(n log n)；演员数组与 tails 使用 O(n) 空间。

常见错误

  • · 同高体重也升序。
  • · 使用 upper_bound，误把相等体重纳入。
  • · 把 tails 当成实际选择序列。
  • · 用减法比较器导致整数溢出。

替代方案

O(n²) DP 直观，适合解释状态，但 n 可达 10000，容易超时。坐标压缩 + 树状数组可做，但实现更重，面试不如二分 LIS 简洁。

面试追问

为什么同高要体重降序？

让同高组的体重呈非递增，严格 LIS 最多只能选一个，避免产生不合法的同高上下关系。

为什么覆盖不会丢掉答案？

相同长度下，更小的末尾体重永远不比更大的差；未来能接在大末尾后的值，也一定能接在小末尾后。

如果允许身高或体重相等呢？

排序的同值方向以及 lower_bound / upper_bound 的选择都要随“不严格”维度调整。

如何恢复实际人塔？

额外记录每个元素的前驱索引、每个长度的尾元素索引，最后从最长长度反向回溯。
