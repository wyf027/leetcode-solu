求出最多标记下标

把数组里的数两两配对：每一对都要满足“小数的两倍不超过大数”。你能让多少个下标被标记？先读题、亲手走几步，再决定是否展开题解。

MEDIUM数组贪心双指针排序

Problem

题目说明

给定一个下标从 0 开始的整数数组 nums。初始时所有下标都未标记。每次可以选择两个互不相同且未标记的下标 i、j；若 2 × nums[i] ≤ nums[j]，就同时标记它们。

可以执行任意次操作。请返回最多能够被标记的下标数量。每个下标至多参与一对，答案一定是偶数。

示例 1

输入：nums = [3,5,2,4]
输出：2
说明：可取 i = 2、j = 1，
2 × nums[2] = 4 ≤ 5。

示例 2

输入：nums = [9,2,5,4]
输出：4
说明：可配 (4,9) 与 (2,5)，
四个下标全部被标记。

示例 3

输入：nums = [7,6,8]
输出：0
说明：不存在满足条件的配对。

函数签名

maxNumOfMarkedIndices(nums: integer[]) → integer

约束

  • 1 ≤ nums.length ≤ 10⁵
  • 1 ≤ nums[i] ≤ 10⁹

    Full solution

    排序 + 双指针贪心

    核心洞察

    一次操作消耗一个较小值和一个至少为其两倍的较大值。排序后，让较小的一半依次寻找后半段中最小的可用搭档。搭档太小就跳过；能配上就立即配对，把更大的数留给后面更难满足的小值。

    完整过程

    1. 将 nums 升序排序。
    2. i = 0 指向较小一侧；j = ceil(n / 2) 指向较大一侧。
    3. 若 2 × nums[i] ≤ nums[j]，配成一对并同时右移；否则只右移 j。
    4. 直到小值候选用完或 j 越界。若成功配出 i 对，答案为 2 × i。

    正确性证明

    不满足时：若当前最小候选 x 都有 2x > y，其余小值不小于 x，所以 y 不可能与任何剩余小值配对；跳过 y 不会损失答案。

    满足时：若 2x ≤ y，考虑任意最优匹配。若它未使用 x 或 y，可直接把相关配对替换为 (x,y)；若 x 与更大的 y' 配对、y 与某个 x' 配对，则改成 (x,y) 与 (x',y') 仍合法，因为 y' ≥ y。因此总存在包含当前贪心配对的最优解。反复应用两种情况，算法得到最大配对数。

    复杂度与边界

    • 时间复杂度：排序 O(n log n)，双指针扫描 O(n)。
    • 额外空间：取决于语言排序实现，通常为 O(log n) 或 O(n)。
    • n = 1 时无法配对，返回 0。
    • 奇数长度时，中间元素自然不进入两侧的初始候选区。
    • 重复值、全部不可配对或全部可配对都由相同逻辑覆盖。
    • 实现乘法时注意整数范围；Java/C++ 示例显式使用 64 位整数。

    替代方案：二分配对数

    也可以二分最多能组成的对数 k。检查时将最小的 k 个数与最大的 k 个数按顺序比较，要求每一项都满足两倍关系。该方案同样先排序，但检查会重复扫描，代码更长；双指针已能在线性扫描中直接得到最大值。

    四种语言完整代码

    JavaScriptLeetCode 提交格式
    /**
 * @param {number[]} nums
 * @return {number}
 */
var maxNumOfMarkedIndices = function(nums) {
    nums.sort((a, b) => a - b);
    const n = nums.length;
    let i = 0;
    let j = Math.ceil(n / 2);

    while (i < Math.floor(n / 2) && j < n) {
        if (2 * nums[i] <= nums[j]) {
            i++;
        }
        j++;
    }
    return 2 * i;
};

    面试追问

    为什么大指针从 ceil(n / 2) 开始？
    答案最多包含 floor(n / 2) 对。把这些对的较小成员放在前半、较大成员放在后半不会变差；奇数长度时跳过正中位置，保证两侧候选不重叠。
    为什么不是为每个小值选最大的数？
    最大的数最珍贵。当前小值只需最小的可行搭档，保留更大元素才能提高后续较大“小值”的成功机会。
    能否不排序？
    一般不能直接保证最优。排序建立了单调性，才允许在某个大值过小时永久丢弃它，并让两个指针各只向右移动。

    常见错误

    • 将答案返回为配对数，而不是被标记的下标数；最终要乘 2。
    • 大指针从 n / 2 开始，导致奇数长度时两侧重叠。
    • 配对失败时同时移动两个指针，错误地丢掉仍可能成功的小值。
    • 配对成功时只移动一个指针，让同一个下标被重复使用。
    • 忘记数值排序，或在 JavaScript 中使用默认的字典序排序。
    • 在更宽约束下直接用 32 位整数计算两倍，可能溢出。
