MEDIUM1993 / Design · Tree

树上的操作

Operations on Tree

一棵树，多位用户。管理节点的锁，判断一次升级能否发生。

先理解操作规则，再展开底部题解探索状态如何变化。

01 / Problem

题意与接口

给定合法树的父节点数组 parent，节点编号为 0 … n − 1。根为节点 0，且 parent[0] = -1。初始所有节点均未上锁。实现 LockingTree，保存各次调用带来的状态变化。

LockingTree(int[] parent)
boolean lock(int num, int user)
boolean unlock(int num, int user)
boolean upgrade(int num, int user)

lock(num, user)

仅当节点 num 未锁时，交给 user 上锁并返回 true；否则返回 false。

unlock(num, user)

仅当节点恰由这个 user 持锁时，释放该锁并返回 true；否则返回 false。

upgrade(num, user)

同时满足：目标未锁、至少一个严格子孙已锁、所有祖先未锁。成功后给目标上锁，并释放所有子孙的锁，不论持锁人是谁。

返回 false 的操作不改变任何锁。普通 lock 只看当前节点；祖先或子孙的锁不会阻止它。祖先、子孙都不包含节点自身。

约束（官方元数据）

  • n == parent.length，2 ≤ n ≤ 2000。
  • parent[0] == -1；当 i ≠ 0 时，0 ≤ parent[i] ≤ n − 1。
  • parent 表示一棵合法的树。
  • 0 ≤ num ≤ n − 1，1 ≤ user ≤ 10⁴。
  • lock、unlock、upgrade 的调用次数总和不超过 2000。

准备好拆解它了吗？

题解包含逐步演示、正确性论证与四语言实现。默认收起，留出独立思考的空间。

核心洞察：锁属于节点，升级涉及两条方向

用 owner[v] = 0 表示空闲，正整数表示持锁用户。保留 parent 以向上走祖先，再建立 children 邻接表以向下遍历子孙。普通上锁与解锁仅更新一个位置。

升级先读取并检查，最后统一修改：检查目标 → 向上检查祖先 → 用显式栈遍历严格子孙并收集持锁节点 → 如果集合非空，再清除这些锁并锁住目标。显式栈不会受到链形树递归深度的限制。

完整过程
  1. 构造时，将每个非根节点 i 加入 children[parent[i]]，所有持锁人置为 0。
  2. lock 只检查 owner[num] == 0；unlock 只检查 owner[num] == user。条件不成立直接返回。
  3. upgrade 先检查目标空闲。从 parent[num] 开始走到 -1，任一祖先已锁就返回 false。
  4. 将目标的直接孩子压栈。每次弹出一个节点，若已锁便记录其编号；无论它是否已锁，都继续压入它的孩子。
  5. 全部子孙读完后，记录为空则返回 false。否则释放记录中的所有锁，再设 owner[num] = user 并返回 true。


为什么正确
状态不变量：每次操作前后，owner[v] 恰好表示题意中的持锁人；0 恰好表示未锁。初始化成立。上锁与解锁的判断和更新与定义一致，因此保持不变量。
遍历覆盖：祖先循环每次走一条父边，恰好访问全部严格祖先。子孙遍历从孩子开始；树中每个节点只有一个父节点，因此每个严格子孙恰好入栈一次，目标与树外节点不会进入记录。
升级充分必要：返回 true 前，目标检查排除了目标已锁，祖先循环排除了祖先已锁，非空记录证明至少有一个已锁子孙。三条件全部成立时不会提前返回，收集阶段必能找到锁，随后正确清除所有已锁子孙并给目标上锁。未锁子孙保持未锁，其余节点不受影响。任一条件不成立均在写入前返回，失败不产生副作用。由操作次数归纳，任意合法调用序列均满足题意。


复杂度
  • 构造：时间 O(n)，持久空间 O(n)。
  • lock / unlock：时间与额外空间均 O(1)。
  • upgrade：祖先数为 h、严格子孙数为 d，时间 O(h + d + 1)，最坏 O(n)；栈与记录的额外空间最坏 O(n)。
  • q 次调用总时间上界 O(n + qn)。题目 n、q 均不超过 2000，直接遍历足够。


边界与常见错误
  • 根没有祖先，向上检查自然结束；叶子没有严格子孙，升级必定失败。
  • 同一用户不能重复 lock；unlock 必须匹配用户。普通 lock 不检查祖先或子孙。
  • 子孙持锁人可以不同于升级者，升级应清除全部子孙锁。
  • 找到第一把锁后不能停止，否则其他分支会留下锁；遇到已锁节点时也不能跳过它的孩子。
  • 不要先清除子孙锁再检查祖先。失败路径必须完全保留原状态。
  • 父节点编号不保证小于子节点编号。先为所有节点建 children 容器，再连边。
  • 链形树深度可接近 2000；四份代码均使用显式栈，避免依赖递归栈。


替代方案
递归 DFS 更短，但 Python 等环境的默认递归深度可能不足；层序 BFS 也能完成相同收集，时间复杂度不变。规模显著增长时，可用 Euler 序把严格子树映射成连续区间，结合有序已锁节点集合与祖先覆盖计数结构查询并删除锁；删除 k 把锁仍需计入更新成本。懒标记线段树可以进一步支持区间清锁，但节点持锁人查询与祖先锁判断必须一起设计，不能只优化“是否存在已锁子孙”。


面试追问
  • 为何用 0 表示未锁？用户 ID 从 1 开始，0 不与合法用户冲突。
  • 能边遍历边解锁吗？目标与祖先已经检查通过，剩下唯一失败条件是没有锁时，可以记录是否见过锁并同步清除。本实现先收集再写，方便明确展示无副作用的失败路径。
  • 父关系动态改变怎么办？当前方案假定静态树；移动子树需同步 children 与 parent 并保证无环。预计算 Euler 序的方案还需处理区间失效。
  • 并发时是否安全？题目按顺序调用。真实并发下，“检查—修改”需要原子化，避免操作在检查后交错；顺序执行保证不等于线程安全。

JavaScript
class LockingTree {
  constructor(parent) {
    this.parent = parent.slice();
    this.owner = Array(parent.length).fill(0);
    this.children = Array.from({ length: parent.length }, () => []);
    for (let i = 1; i < parent.length; i++) {
      this.children[parent[i]].push(i);
    }
  }

  lock(num, user) {
    if (this.owner[num] !== 0) return false;
    this.owner[num] = user;
    return true;
  }

  unlock(num, user) {
    if (this.owner[num] !== user) return false;
    this.owner[num] = 0;
    return true;
  }

  upgrade(num, user) {
    if (this.owner[num] !== 0) return false;
    for (let p = this.parent[num]; p !== -1; p = this.parent[p]) {
      if (this.owner[p] !== 0) return false;
    }
    // ponytail: O(n) scan fits n <= 2000; use Euler order for larger inputs.
    const stack = [...this.children[num]], locked = [];
    while (stack.length) {
      const v = stack.pop();
      if (this.owner[v] !== 0) locked.push(v);
      for (const child of this.children[v]) stack.push(child);
    }
    if (locked.length === 0) return false;
    for (const v of locked) this.owner[v] = 0;
    this.owner[num] = user;
    return true;
  }
}


Java
import java.util.ArrayList;
import java.util.ArrayDeque;
import java.util.List;
import java.util.Deque;

class LockingTree {
    private final int[] parent;
    private final int[] owner;
    private final List<List<Integer>> children;

    public LockingTree(int[] parent) {
        this.parent = parent.clone();
        owner = new int[parent.length];
        children = new ArrayList<>();
        for (int i = 0; i < parent.length; i++) children.add(new ArrayList<>());
        for (int i = 1; i < parent.length; i++) children.get(parent[i]).add(i);
    }

    public boolean lock(int num, int user) {
        if (owner[num] != 0) return false;
        owner[num] = user;
        return true;
    }

    public boolean unlock(int num, int user) {
        if (owner[num] != user) return false;
        owner[num] = 0;
        return true;
    }

    public boolean upgrade(int num, int user) {
        if (owner[num] != 0) return false;
        for (int p = parent[num]; p != -1; p = parent[p]) {
            if (owner[p] != 0) return false;
        }
        // ponytail: O(n) scan fits n <= 2000; use Euler order for larger inputs.
        Deque<Integer> stack = new ArrayDeque<>(children.get(num));
        List<Integer> locked = new ArrayList<>();
        while (!stack.isEmpty()) {
            int v = stack.removeLast();
            if (owner[v] != 0) locked.add(v);
            for (int child : children.get(v)) stack.addLast(child);
        }
        if (locked.isEmpty()) return false;
        for (int v : locked) owner[v] = 0;
        owner[num] = user;
        return true;
    }
}


Python
from typing import List

class LockingTree:
    def __init__(self, parent: List[int]):
        self.parent = parent[:]
        self.owner = [0] * len(parent)
        self.children = [[] for _ in parent]
        for i in range(1, len(parent)):
            self.children[parent[i]].append(i)

    def lock(self, num: int, user: int) -> bool:
        if self.owner[num] != 0:
            return False
        self.owner[num] = user
        return True

    def unlock(self, num: int, user: int) -> bool:
        if self.owner[num] != user:
            return False
        self.owner[num] = 0
        return True

    def upgrade(self, num: int, user: int) -> bool:
        if self.owner[num] != 0:
            return False
        p = self.parent[num]
        while p != -1:
            if self.owner[p] != 0:
                return False
            p = self.parent[p]
        # ponytail: O(n) scan fits n <= 2000; use Euler order for larger inputs.
        stack = self.children[num][:]
        locked = []
        while stack:
            v = stack.pop()
            if self.owner[v] != 0:
                locked.append(v)
            stack.extend(self.children[v])
        if not locked:
            return False
        for v in locked:
            self.owner[v] = 0
        self.owner[num] = user
        return True


C++
#include <vector>
using namespace std;

class LockingTree {
    vector<int> parent, owner;
    vector<vector<int>> children;

public:
    LockingTree(vector<int>& parent)
        : parent(parent), owner(parent.size(), 0), children(parent.size()) {
        for (int i = 1; i < (int)parent.size(); ++i)
            children[parent[i]].push_back(i);
    }

    bool lock(int num, int user) {
        if (owner[num] != 0) return false;
        owner[num] = user;
        return true;
    }

    bool unlock(int num, int user) {
        if (owner[num] != user) return false;
        owner[num] = 0;
        return true;
    }

    bool upgrade(int num, int user) {
        if (owner[num] != 0) return false;
        for (int p = parent[num]; p != -1; p = parent[p]) {
            if (owner[p] != 0) return false;
        }
        // ponytail: O(n) scan fits n <= 2000; use Euler order for larger inputs.
        vector<int> stack = children[num], locked;
        while (!stack.empty()) {
            int v = stack.back();
            stack.pop_back();
            if (owner[v] != 0) locked.push_back(v);
            for (int child : children[v]) stack.push_back(child);
        }
        if (locked.empty()) return false;
        for (int v : locked) owner[v] = 0;
        owner[num] = user;
        return true;
    }
};
