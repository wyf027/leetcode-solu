2419. 按位与最大的
最长子数组

Longest Subarray With Maximum Bitwise AND

数组·位运算·先读题，再探索

01题目

给定长度为 n 的整数数组 nums。对每一个非空连续子数组，将其中的所有元素进行按位与运算。设这些结果中最大的值为 k，返回按位与结果等于 k 的子数组的最大长度。

比较顺序：先让按位与结果最大，再在满足条件的子数组中选择最长的一个。返回值是长度。

按位与 &：同一个二进制位只有在所有参与数的对应位均为 1 时，结果才为 1。子数组必须连续，且至少包含一个元素。

官方示例 1

输入：nums = [1,2,3,3,2,2]
输出：2

最大按位与结果为 3；子数组 [3,3] 达到该结果，最长长度为 2。

官方示例 2

输入：nums = [1,2,3,4]
输出：1

最大按位与结果为 4；最长的符合条件的子数组为 [4]，长度为 1。

约束与接口

  • 1 ≤ nums.length ≤ 105
  • 1 ≤ nums[i] ≤ 106
longestSubarray(nums: integer[]) → integer

04独立题解

核心洞察：按位与的上界

令 M = max(nums)。对非负整数，按位与只能保留原有的 1 位，因此结果不大于任一参与元素，也就不大于 M。单元素子数组 [M] 又能达到 M，故题目中的最大值 k 恰好等于 M。

如果某个子数组含有 x < M，它的按位与至多是 x，必然小于 M。反过来，全部元素都是 M 时，按位与仍为 M。所以答案就是数组中最大元素的最长连续段长度。

两遍扫描：第一遍确定全局最大值；第二遍遇到最大值就延长连续段，遇到其他值就归零。

交互实验 · 最大值扫描与连续段扫描

第 1 遍观察上界逐步确定，第 2 遍观察连续段延长或断开。深绿外框表示当前元素；绿色底色表示第 2 遍的当前连续段；底边灰线表示本遍已访问。二进制面板展示 M 与当前值的按位与。

完整过程

  1. 初始化 M = nums[0]，遍历数组更新 M。
  2. 初始化 run = 0 与 best = 0。
  3. 每读到一个 x：若 x == M 则 run += 1，否则 run = 0。
  4. 更新 best = max(best, run)。循环结束返回 best。

示例 1 中，M = 3，第二遍的 run 依次为 0, 0, 1, 2, 0, 0，因此返回 2。

正确性证明

目标等价：上界论证说明最大按位与为 M；充要条件说明只有完全由 M 组成的子数组能达到 M。故原问题等价于最长连续 M 段。

循环不变式：处理完下标 i 后，run 是以 i 结尾的连续 M 段长度，best 是前缀 nums[0..i] 内所有连续 M 段的最大长度。初始空前缀时二者为 0。若当前值为 M，旧段延长一位；否则以当前位置结尾的有效段不存在，run 置 0。再取 best 与 run 的最大值，就包含了所有旧候选与新候选。

终止：扫描覆盖整个数组，不变式保证 best 是全局最长连续 M 段长度，也就是所求答案。

边界与复杂度

  • 只有一个元素时，答案为 1；全部相等时，答案为 n。
  • 最大值分散时分别计段，不能把多个不连续的位置相加。
  • 最长段在数组末尾也无需额外结算，因为每一步都更新 best。
  • 非空、正整数是官方前提；空数组不在接口要求内。
  • 时间 O(n)，额外空间 O(1)。可视化为回退而保存步骤，使用 O(n) 辅助空间；提交算法不保存步骤。

Java

class Solution {
    public int longestSubarray(int[] nums) {
        int max = nums[0];
        for (int x : nums) max = Math.max(max, x);
        int run = 0, best = 0;
        for (int x : nums) {
            run = x == max ? run + 1 : 0;
            best = Math.max(best, run);
        }
        return best;
    }
}

替代方案

  • 一遍扫描：维护前缀最大值。遇到更大值时令最大值为当前值，run 和 best 都重置为 1；相等时延长 run 并更新 best；更小时令 run = 0。旧最大值的所有连续段在发现更大值后都失效。时间 O(n)、空间 O(1)，但状态更新更容易写错。
  • 枚举区间：固定左端点，向右累积按位与，比较结果大小和长度。时间 O(n²)、空间 O(1)，只适合小数据推导，无法满足 n = 105。

常见错误

  • 统计 M 的总出现次数：忽略了“连续”。
  • 先求全数组按位与：题目允许只选局部区间。
  • 遇到非 M 时不清零 run：把相隔的段拼在了一起。
  • 只在段结束时更新答案：容易漏掉末尾段。
  • JavaScript 用 Math.max(...nums)：大数组展开可能触及参数数量限制；循环取最大值更稳妥。
  • 把结论直接用于负整数：有符号数的数值顺序下，按位与“不大于任一参与数”的证明不再通用。

面试追问

为什么没有真正计算按位与？ 先利用运算性质把目标化简为连续段计数，就能省去区间运算。

如何返回区间？ run 增大并严格超过 best 时，记录右端点 i 与左端点 i − run + 1；严格大于可保留第一个最长区间。

如果目标换成给定的 K？ K 不一定是全局最大值，元素不必都等于 K，上述等价关系失效，需要重新利用逐位约束或维护各右端点的不同 AND 值。

如果是流式输入？ 使用上述一遍扫描方案，发现更大的数就淘汰旧答案，无需保存整个数组。
