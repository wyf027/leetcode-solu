Problem statement

题目说明

花园是一个 height × width 的二维网格。树、松鼠和每颗坚果都占据一个不同的网格位置。

准确转述

松鼠从给定位置出发，每次最多携带一颗坚果；它只能向上、下、左、右移动到相邻格子。每取到一颗坚果后，必须把这颗坚果放到树下，才能继续收集下一颗。请返回把所有坚果逐一送到树下所需的最小移动次数。

网格中没有障碍物，因此两点之间的最短移动次数就是它们的曼哈顿距离：行坐标差的绝对值加列坐标差的绝对值。

函数签名

minDistance(height, width, tree, squirrel, nuts)

height, width
整数，花园的行数与列数。
tree
长度为 2 的整数数组，树的位置 [row, col]。
squirrel
长度为 2 的整数数组，松鼠的初始位置。
nuts
二维整数数组，每一项是一颗坚果的位置。
return
整数，收集全部坚果的最小总距离。

约束

  • 1 <= height, width <= 100
  • tree.length == 2
  • squirrel.length == 2
  • 1 <= nuts.length <= 5000
  • 每一项 nuts[i].length == 2
  • 所有行坐标都满足 0 <= row < height
  • 所有列坐标都满足 0 <= col < width
  • 树、松鼠和所有坚果的位置互不重叠；至少有一颗坚果。

Greedy · Manhattan distance

题解：只替换第一趟

关键不是枚举所有收集顺序，而是看清哪些路程无论如何都必须发生，以及松鼠的初始位置只影响哪一段行程。

!

核心洞察

假设每颗坚果都从树出发取回，基准距离是每颗坚果到树距离的两倍。真实行程只有第一次不是从树出发：选定第一颗坚果后，用“松鼠到该坚果”的距离替换“树到该坚果”的去程。

answer = Σ 2 × dist(tree, nutᵢ) − max(dist(tree, nutᵢ) − dist(squirrel, nutᵢ))

完整过程

  1. 遍历每颗坚果，计算它到树的曼哈顿距离 treeDist。
  2. 把 2 × treeDist 加入基准总距离，表示从树去取再返回。
  3. 计算选它作为第一颗坚果时可替换的距离差：treeDist - squirrelDist。
  4. 保留最大的距离差；遍历结束后用基准总距离减去它。

示例 1 的数字

两颗坚果到树的距离都为 3，因此基准距离是 2 × 3 + 2 × 3 = 12。

对坚果 [3,0]，差值为 3 - 5 = -2；对 [2,5]，差值为 3 - 3 = 0。

最大差值是 0，所以答案仍为 12。

正确性证明

引理 1：第一颗坚果被送回树后，松鼠位于树下。此后每颗坚果都必须经历“树 → 坚果 → 树”，其代价固定为该坚果到树距离的两倍，与收集顺序无关。

引理 2：若第一颗选择坚果 i，它的代价是 dist(squirrel, i) + dist(i, tree)；与基准中的 2 × dist(tree, i) 相比，减少了 dist(tree, i) - dist(squirrel, i)。

结论：基准总距离固定，要使真实总距离最小，只需选择差值最大的坚果作为第一颗。算法枚举了所有坚果并取最大值，因此得到全局最优解。

边界情况

  • 只有一颗坚果：公式自动退化为“松鼠 → 坚果 → 树”。
  • 所有差值都为负：仍必须选一颗作为第一颗，最大负值代表额外路程最少的选择。
  • 多颗坚果差值相同：任选其一作为第一颗，答案相同。
  • 花园很窄或只有一行：曼哈顿距离依然适用。
  • height 与 width 只限定坐标合法性，不参与距离公式。
时间复杂度 O(n) 只遍历一次全部坚果。
额外空间 O(1) 除累计值外不需要额外结构。

四语言完整代码

使用标签或左右方向键切换语言。四份实现都遵循同一套线性扫描逻辑。

class Solution {
    public int minDistance(int height, int width, int[] tree,
                           int[] squirrel, int[][] nuts) {
        int baseDistance = 0;
        int bestSaving = Integer.MIN_VALUE;

        for (int[] nut : nuts) {
            int treeDistance = distance(tree, nut);
            int squirrelDistance = distance(squirrel, nut);

            baseDistance += 2 * treeDistance;
            bestSaving = Math.max(
                bestSaving,
                treeDistance - squirrelDistance
            );
        }

        return baseDistance - bestSaving;
    }

    private int distance(int[] a, int[] b) {
        return Math.abs(a[0] - b[0]) + Math.abs(a[1] - b[1]);
    }
}

替代方案

枚举第一颗坚果：可以对每个候选第一颗坚果重新累加全部路程，容易理解，但时间复杂度是 O(n²)，在 5000 颗坚果时没有必要。

排列 / 搜索：看似需要枚举收集顺序，实际在第一颗之后每趟都从树出发并回到树，顺序不影响总和；全排列会把固定代价误当成状态空间。

常见错误

  • 把所有坚果都按“松鼠 → 坚果”计算，忘记第一颗之后松鼠在树下。
  • 把最大差值初始化为 0；当所有差值为负时会得到不存在的“零损失”。
  • 误以为应选择离松鼠最近的坚果；真正比较的是两种出发点的距离差。
  • 使用欧氏距离，而不是四方向移动对应的曼哈顿距离。

面试追问

为什么坚果的收集顺序只有第一颗重要？

第一颗送到树后，松鼠就在树下。此后每次都从树出发、带着坚果回树，每颗坚果的往返代价固定，彼此顺序不会改变总和。

如果松鼠一次可以携带两颗坚果，结论还成立吗？

不成立。一次路线可能串联两颗坚果，后续代价不再能拆成独立的树到坚果往返，需要考虑配对或更复杂的路径状态。

如果网格中出现障碍物，应该怎样调整？

曼哈顿距离不再一定等于最短路。可先用 BFS 求松鼠、树与各坚果之间需要的最短距离；若每趟仍必须回树，之后的“只替换第一趟”结构仍可能保留。

为什么最大差值可能是负数？

松鼠可能比树离每颗坚果都远。即便如此，它仍必须先取一颗；选择最大的负差值，等价于让额外付出的路程尽量少。
