Problem

题意与数据模型

给定好友表 Friendship 与点赞表 Likes。一条好友记录表示两名用户互为好友，关系没有方向。请为固定用户 1 返回推荐页面：这些页面至少被用户 1 的一位朋友喜欢，同时没有被用户 1 自己喜欢。结果列名为 recommended_page，同一页面只出现一次。

关键语义：好友可能出现在 user1_id 或 user2_id 任一侧；推荐集合要排除自己的点赞并去重，输出顺序不限。

Friendship

列名类型含义
user1_idINT好友关系的一端
user2_idINT好友关系的另一端

Likes

列名类型含义
user_idINT点赞用户
page_idINT被喜欢的页面

约束

  • Friendship 的每行连接两名不同用户，同一好友关系只记录一次。
  • Likes 中同一用户与页面的组合不重复。
  • 用户编号、页面编号均为整数；正式目标用户固定为 1。
  • 输出必须去重，可以按任意顺序返回。

Solution

题解：先统一好友方向，再做集合差

核心洞察

1
好友关系是无向的，表结构却有左右两列。

分别取“用户 1 在左侧时的右端”和“用户 1 在右侧时的左端”，用 UNION 合成好友集合；连接点赞表，再排除用户 1 自己喜欢的页面并去重。

完整过程

  1. 扫描 Friendship，从每条包含用户 1 的关系中取出另一端。
  2. 用 UNION 合并两侧好友。
  3. 将好友编号连接到 Likes.user_id，获得好友点赞页面。
  4. 用 NOT EXISTS 排除用户 1 已喜欢的页面。
  5. 用 DISTINCT 消除多个好友造成的同页重复。

官方可提交语言：MySQL

SELECT DISTINCT l.page_id AS recommended_page
FROM Likes AS l
JOIN (
    SELECT user2_id AS friend_id
    FROM Friendship
    WHERE user1_id = 1

    UNION

    SELECT user1_id AS friend_id
    FROM Friendship
    WHERE user2_id = 1
) AS f ON f.friend_id = l.user_id
WHERE NOT EXISTS (
    SELECT 1
    FROM Likes AS mine
    WHERE mine.user_id = 1
      AND mine.page_id = l.page_id
);

正确性证明

引理 1：好友子查询恰好得到用户 1 的全部好友。

用户 1 在任意关系中必处于左列或右列，两个分支分别取另一端，所以既不遗漏，也不会引入非好友。

引理 2：连接后恰好得到至少一位好友喜欢的页面。

连接条件要求点赞用户属于引理 1 的集合；每条好友点赞记录也都会满足条件。

引理 3：过滤后不含用户 1 已喜欢的页面。

NOT EXISTS 只保留不存在同页用户 1 点赞记录的候选项。

结论。

由引理 2、3，结果恰是“好友喜欢且用户 1 未喜欢”的页面；DISTINCT 保证每页仅一行，因此查询正确。

边界情况

  • 用户 1 没有好友或好友没有点赞：结果为空。
  • 好友只喜欢用户 1 已点赞的页面：全部排除。
  • 多个好友喜欢同一页：最终只返回一次。
  • 用户 1 出现在好友表任一列：两个方向都覆盖。

复杂度

时间复杂度O(F + L)在适当索引和哈希/集合连接的抽象下扫描好友记录 F 与点赞记录 L；真实计划由数据库优化器决定。
额外空间O(D + R)D 是目标好友数，R 是候选或去重页面数；数据库可能使用临时结构。

建议索引：Friendship(user1_id)、Friendship(user2_id)、Likes(user_id, page_id)。

替代方案

  • CASE 单次扫描：一条查询取关系另一端，但含 OR 的条件可能不利于索引。
  • LEFT JOIN 反连接：再次左连接用户 1 的点赞，过滤空值；语义等价，NOT EXISTS 通常更直观。
  • UNION ALL：若约束保证好友关系不重复，可减少一次中间去重；最终页面仍需 DISTINCT。

import java.util.*;

public class PageRecommendations {
    static List<Integer> recommend(int target, int[][] friendship, int[][] likes) {
        Set<Integer> friends = new HashSet<>();
        for (int[] edge : friendship) {
            if (edge[0] == target) friends.add(edge[1]);
            else if (edge[1] == target) friends.add(edge[0]);
        }
        Set<Integer> owned = new HashSet<>();
        for (int[] like : likes) if (like[0] == target) owned.add(like[1]);
        Set<Integer> answer = new TreeSet<>();
        for (int[] like : likes)
            if (friends.contains(like[0]) && !owned.contains(like[1])) answer.add(like[1]);
        return new ArrayList<>(answer);
    }

function recommendPages(target, friendship, likes) {
  const friends = new Set();
  for (const [a, b] of friendship) {
    if (a === target) friends.add(b);
    else if (b === target) friends.add(a);
  }
  const owned = new Set(likes.filter(([u]) => u === target).map(([, p]) => p));
  const answer = new Set();
  for (const [user, page] of likes)
    if (friends.has(user) && !owned.has(page)) answer.add(page);
  return [...answer].sort((a, b) => a - b);
}

from typing import List

def recommend_pages(target: int, friendship: List[List[int]],
                    likes: List[List[int]]) -> List[int]:
    friends = set()
    for left, right in friendship:
        if left == target:
            friends.add(right)
        elif right == target:
            friends.add(left)
    owned = {page for user, page in likes if user == target}
    answer = {page for user, page in likes
              if user in friends and page not in owned}
    return sorted(answer)

vector<int> recommendPages(int target,
    const vector<pair<int,int>>& friendship,
    const vector<pair<int,int>>& likes) {
    set<int> friends, owned, answer;
    for (auto [a, b] : friendship) {
        if (a == target) friends.insert(b);
        else if (b == target) friends.insert(a);
    }
    for (auto [user, page] : likes)
        if (user == target) owned.insert(page);
    for (auto [user, page] : likes)
        if (friends.count(user) && !owned.count(page)) answer.insert(page);
    return {answer.begin(), answer.end()};
}

面试追问

  • 如何按喜欢该页的好友数排序？按页面分组，计算不同好友数，再按计数降序。
  • 为什么不用 NOT IN？若子查询出现 NULL，三值逻辑容易造成意外；NOT EXISTS 更稳健。
  • 数据很大如何优化？增加方向列索引与点赞复合索引，检查执行计划；高频推荐可离线生成候选集。
  • 如何推广到任意用户？把常量 1 替换为绑定参数，并在所有位置复用同一参数。

常见错误

  • 只检查好友表一侧，漏掉 (6, 1)。
  • 忘记排除用户 1 自己已喜欢的页面。
  • 忘记 DISTINCT，让页面 77 重复。
  • 把无向好友关系误当作单向边。
  • 误把结果顺序不同判断成答案错误。
