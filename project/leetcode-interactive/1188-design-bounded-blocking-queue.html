设计有限阻塞队列Design Bounded Blocking Queue

一道不靠忙等、同时守住容量与 FIFO 语义的并发设计题。先理解接口与阻塞契约，再进入可视化实验；完整解法默认收起。

01

题目要求

有限、FIFO、线程安全，并在条件不满足时真正阻塞调用线程。

实现一个容量固定的阻塞队列。多个生产者线程会调用 enqueue，多个消费者线程会调用 dequeue；它们可能以任意顺序交错。队列已满时，入队线程必须等待到出现空位；队列为空时，出队线程必须等待到出现元素。

元素按照 FIFO 规则流动：从逻辑队首加入、从逻辑队尾移除（也可以用常见的“尾部追加、头部移除”实现，只要可观察顺序一致）。评测会在一组并发调用结束后调用 size()。不能直接使用语言自带的有限阻塞队列容器。

BoundedBlockingQueue(int capacity)以最大容量 capacity 初始化空队列。
void enqueue(int element)加入元素；队满则阻塞，直到有空位。
int dequeue()移除并返回最早入队元素；队空则阻塞。
int size()线程安全地返回当前元素数量。
并发输出说明：多生产者、多消费者场景中，操作开始顺序不等于真正获得锁的顺序；若若干返回排列都满足一次合法调度，评测可接受其中任意一种。

约束规模很小，真正考查的是同步语义，而非数据量。

  • 1 ≤ producer threads ≤ 8
  • 1 ≤ consumer threads ≤ 8
  • 1 ≤ capacity ≤ 30
  • 0 ≤ element ≤ 20
  • enqueue 调用次数不少于 dequeue 调用次数
  • enqueue、dequeue 与 size 合计最多调用 40 次

05

完整题解

一个共享锁、两个条件变量：notFull 与 notEmpty。

核心洞察

队列正确性的两个维度必须分开：锁保证“同一时刻只有一个线程改变状态”，条件变量保证“状态不允许时线程睡眠，状态改变后再回来检查”。

notFull
生产者等待 size < capacity
mutex + deque
唯一共享状态
notEmpty
消费者等待 size > 0

完整过程

  1. 构造：保存容量，队列为空；两个条件变量绑定同一把互斥锁。
  2. 入队：加锁；当队列仍然满时在 notFull 上等待。被唤醒后必须用 while 重新检查条件。加入元素后通知一个等待元素的消费者。
  3. 出队：加锁；当队列仍然空时在 notEmpty 上等待。取出最早元素后通知一个等待空位的生产者。
  4. 查询大小：同样在锁保护下读取。否则读操作也可能与容器修改发生数据竞争。

正确性说明

容量不变量：所有读写都在同一互斥锁内。入队只有在 size < capacity 时发生，出队只有在 size > 0 时发生，所以始终有 0 ≤ size ≤ capacity。

FIFO：每次入队只向一端追加，每次出队只从另一端取最早元素；锁把每次修改线性化，因此存在一个与并发执行一致的串行 FIFO 顺序。

阻塞与唤醒：满队列上的生产者只等待 notFull，一次成功出队会使该谓词成立并发出通知；空队列上的消费者同理。即使发生伪唤醒，while 会拒绝不满足条件的线程继续执行。

边界情况

  • 容量为 1 时，生产和消费严格交替，仍不能死锁。
  • 多个生产者同时被唤醒时，只有重新获得锁且看到空位的线程能够入队。
  • 元素可以是 0；不能把元素值当成“空”的哨兵。
  • size() 只承诺调用瞬间的快照，返回后队列可能立刻变化。
  • 通知必须发生在共享状态修改之后；否则被唤醒者可能观察不到它等待的条件。

复杂度

用双端队列时，enqueue 与 dequeue 的实际队列操作均为 O(1)，size 为 O(1)；等待时间取决于线程调度，不计入算法操作复杂度。空间为 O(capacity)。

替代方案

  • 两个计数信号量：一个初值为 capacity 表示空位，另一个初值为 0 表示元素；仍需确保底层容器的互斥访问。Java 的 Semaphore 配合并发安全队列、POSIX semaphore 配合受保护容器都可实现。
  • 单条件变量：可行，但入队和出队都唤醒同一等待集合，容易产生无效唤醒；两个条件更清楚、更精准。
  • 自旋/轮询：不推荐。队列满或空时持续占用 CPU，违背“阻塞”设计目的。

面试追问

  • 为什么等待条件必须写成 while 而不是 if？——伪唤醒，以及其他线程可能先一步消费条件。
  • signal/notify_one 和 broadcast/notify_all 如何选择？——状态一次通常只释放一个对侧操作，通知一个足够；复杂谓词或关闭队列时常需全部通知。
  • 如何支持关闭与超时？——新增 closed 状态和带截止时间的等待；关闭时唤醒所有线程并定义剩余元素的排空策略。
  • 公平性是否保证？——本实现保证安全与活性，但通常不保证严格先到先服务；若需要公平性，要选择公平锁/信号量或维护等待者队列。

常见错误

  • 只用锁，不在满/空时等待，导致越界或返回非法值。
  • 等待期间仍持有普通锁，消费者/生产者永远无法改变条件。
  • 把 wait 放进 if，遇到伪唤醒后破坏容量或空队列约束。
  • 更新队列前就通知，或者忘记通知对侧。
  • size() 不加锁，产生数据竞争。
  • 在锁内执行与队列无关的慢操作，放大临界区并降低吞吐。

四语言完整实现

JavaScript 不在该题官方元数据语言列表中，以下 Node.js 版本诚实标注为本地并发语义参考。

Java · ReentrantLock + Condition可提交形式
import java.util.ArrayDeque;
import java.util.Deque;
import java.util.concurrent.locks.Condition;
import java.util.concurrent.locks.ReentrantLock;

class BoundedBlockingQueue {
    private final int capacity;
    private final Deque<Integer> queue = new ArrayDeque<>();
    private final ReentrantLock lock = new ReentrantLock();
    private final Condition notFull = lock.newCondition();
    private final Condition notEmpty = lock.newCondition();

    public BoundedBlockingQueue(int capacity) {
        this.capacity = capacity;
    }

    public void enqueue(int element) throws InterruptedException {
        lock.lock();
        try {
            while (queue.size() == capacity) {
                notFull.await();
            }
            queue.addLast(element);
            notEmpty.signal();
        } finally {
            lock.unlock();
        }
    }

    public int dequeue() throws InterruptedException {
        lock.lock();
        try {
            while (queue.isEmpty()) {
                notEmpty.await();
            }
            int value = queue.removeFirst();
            notFull.signal();
            return value;
        } finally {
            lock.unlock();
        }
    }

    public int size() {
        lock.lock();
        try {
            return queue.size();
        } finally {
            lock.unlock();
        }
    }
}
JavaScript · Promise waiters本地语义参考，非该题官方提交语言
class BoundedBlockingQueue {
  constructor(capacity) {
    this.capacity = capacity;
    this.queue = [];
    this.waitingEnqueue = [];
    this.waitingDequeue = [];
  }

  _wakeOne(waiters) {
    const resolve = waiters.shift();
    if (resolve) resolve();
  }

  async enqueue(element) {
    while (this.queue.length === this.capacity) {
      await new Promise((resolve) => this.waitingEnqueue.push(resolve));
    }
    this.queue.push(element);
    this._wakeOne(this.waitingDequeue);
  }

  async dequeue() {
    while (this.queue.length === 0) {
      await new Promise((resolve) => this.waitingDequeue.push(resolve));
    }
    const value = this.queue.shift();
    this._wakeOne(this.waitingEnqueue);
    return value;
  }

  size() {
    return this.queue.length;
  }
}

Python · threading.Condition可提交形式
from collections import deque
from threading import Condition, Lock


class BoundedBlockingQueue(object):
    def __init__(self, capacity: int):
        self.capacity = capacity
        self.queue = deque()
        self.lock = Lock()
        self.not_full = Condition(self.lock)
        self.not_empty = Condition(self.lock)

    def enqueue(self, element: int) -> None:
        with self.not_full:
            while len(self.queue) == self.capacity:
                self.not_full.wait()
            self.queue.append(element)
            self.not_empty.notify()

    def dequeue(self) -> int:
        with self.not_empty:
            while not self.queue:
                self.not_empty.wait()
            value = self.queue.popleft()
            self.not_full.notify()
            return value

    def size(self) -> int:
        with self.lock:
            return len(self.queue)
C++17 · mutex + condition_variable可提交形式
#include <condition_variable>
#include <deque>
#include <mutex>

class BoundedBlockingQueue {
public:
    explicit BoundedBlockingQueue(int capacity) : capacity_(capacity) {}

    void enqueue(int element) {
        std::unique_lock<std::mutex> lock(mutex_);
        not_full_.wait(lock, [this] {
            return queue_.size() < static_cast<std::size_t>(capacity_);
        });
        queue_.push_back(element);
        lock.unlock();
        not_empty_.notify_one();
    }

    int dequeue() {
        std::unique_lock<std::mutex> lock(mutex_);
        not_empty_.wait(lock, [this] { return !queue_.empty(); });
        int value = queue_.front();
        queue_.pop_front();
        lock.unlock();
        not_full_.notify_one();
        return value;
    }

    int size() {
        std::lock_guard<std::mutex> lock(mutex_);
        return static_cast<int>(queue_.size());
    }

private:
    int capacity_;
    std::deque<int> queue_;
    std::mutex mutex_;
    std::condition_variable not_full_;
    std::condition_variable not_empty_;
};
