环形链表 II 入口定位仪

先让快慢指针在环中相遇，再把一个指针送回头节点；二者同步前进，下一次会合处就是环入口。

任务边界

只接收 head。测试数据里的 pos 仅用于构造尾节点回连位置，不会传入函数；链表不得修改。

Problem / 题意

返回环开始的节点

给定单链表头节点：若沿 next 最终会重复访问节点，返回第一次进入环的那个节点；若没有环，返回 null。节点数为 0～10⁴，节点值在 −10⁵～10⁵。

示例 1
head = [3,2,0,-4], pos = 1

输出：索引 1 的节点

示例 2
head = [1,2], pos = 0

输出：索引 0 的节点

示例 3
head = [1], pos = -1

输出：null

核心洞察

相遇点不是答案，但它校准了路程

设头到入口距离为 a，入口到首次相遇点为 b，环长为 c。相遇时快指针路程是慢指针两倍， 可推出 a = (k−1)c + (c−b)。因此一个指针从头走 a 步，另一个从相遇点走同样步数（绕若干整圈后再走 c−b），恰在入口会合。

完整过程

  1. slow 每次走 1 步，fast 每次走 2 步。
  2. fast 或 fast.next 为空：无环，返回 null。
  3. 二者相遇后，将 slow 重置到 head。
  4. slow 与 fast 都每次走 1 步，再次相遇即入口。

边界与复杂度

  • 空链表、单节点无自环：返回 null。
  • 入口就是 head、自环：正确返回 head。
  • 时间 O(n)，额外空间 O(1)，不修改链表。

替代方案取舍

哈希集合更直观：首次重复节点就是入口，时间 O(n)，但空间 O(n)。 面试主线推荐 Floyd，因为满足常数空间追问。

常见错误

  • 把首次相遇点直接当成入口。
  • 第二阶段仍让 fast 每次走两步。
  • 忘记检查 fast.next，导致空指针。
  • 把测试构造参数 pos 当作函数参数。

面试追问

如何证明一定相遇？环内速度差为 1，每轮缩短一个节点。
如何求环长？相遇后固定一点，另一指针绕一圈计步。
能否修改链表？本题明确禁止；即使允许也会破坏输入。 
public class Solution {
    public ListNode detectCycle(ListNode head) {
        ListNode slow = head;
        ListNode fast = head;
        while (fast != null && fast.next != null) {
            slow = slow.next;
            fast = fast.next.next;
            if (slow == fast) {
                slow = head;
                while (slow != fast) {
                    slow = slow.next;
                    fast = fast.next;
                }
                return slow;
            }
        }
        return null;
    }
}
