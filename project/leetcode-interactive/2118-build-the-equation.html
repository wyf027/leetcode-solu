01 / 题目与数据契约

你要生成什么？

表 Terms 的每行给出一个多项式项的幂次与系数。返回一行、一列名为 equation 的结果，把全部项放在左侧，右侧固定为零。

各项按幂次从大到小排列；每项显式保留正负号和系数的绝对值，系数为 1 时也不省略。使用大写 X，无空格，最后接 =0。

  • 幂次大于 1：符号、系数、X^幂次。
  • 幂次为 1：只写 X，不写 ^1。
  • 幂次为 0：只写带符号的常数。

输入表：Terms

列类型含义
powerint幂次，唯一键
factorint非零系数
  • 0 ≤ power ≤ 100。
  • −100 ≤ factor ≤ 100，且 factor ≠ 0。
  • 同一幂次不会重复；原始行顺序没有保证。
  • 公开题面未单列行数下限；唯一性和幂次范围推出最多 101 行。空表输出未明确规定。

题名、表结构和样例输入来自本轮官方元数据；付费题面为空，格式与约束据公开题面资料转述。官方题目入口。

以下保留完整参数形式：headers 确定列顺序，rows 给出 Terms 的全部行。

输出：

{"headers":["equation"],

首项的 + 与 1 均保留；一次项省略指数，常数项省略 X。

示例 2 · 缺失幂次

{"headers":{"Terms":["power","factor"]},
 "rows":{"Terms":[[4,-4],[2,1],[1,-1]]}}

输出：

{"headers":["equation"],
 "values":[["-4X^4+1X^2-1X=0"]]}

不存在的三次项与常数项无需补零，负一次项仍保留系数 1。

题解 / 有序字符串聚合

核心洞察

这里不需要解方程或计算幂。每行是一个文本片段：符号由 factor 决定，后缀由 power 决定；唯一的全局要求是片段顺序。先定义单项编码，再在聚合函数内部按幂次降序连接。

完整过程

  1. 从 Terms 取出每个 power 和 factor，不做数值求幂。
  2. 正系数添加 +，负系数保留自身的 -，不要再叠加一个负号。
  3. 用 CASE 区分幂次 0、1 和其他值，生成空后缀、X 或 X^power。
  4. 使用 GROUP_CONCAT(... ORDER BY power DESC SEPARATOR '') 将全表聚合为一个字符串。
  5. 追加 =0，把结果列命名为 equation。

为什么一定正确？

单项正确性：系数符号和绝对值由 factor 唯一确定，三个互斥的幂次分支覆盖所有允许值，所以每个片段精确满足格式约定。顺序正确性：聚合内部按唯一的 power 降序排列，故相邻片段的幂次严格递减。

完整性：无过滤的聚合恰好包含每一行一次，空分隔符不会插入逗号或空格。逐步拼接的不变量是：处理前 k 行后，缓冲区正好等于按降幂排列的前 k 个合法项。初始化为空成立，每一步追加下一个合法项保持不变量；处理完所有行并追加 =0，即为要求的完整方程。

复杂度与边界

设 n 为行数，L 为输出字符数。一般排序实现耗时 O(n log n + L)，保存排序行和字符串需要 O(n + L) 空间；数据库执行计划可能利用已有顺序，具体资源消耗取决于引擎。范围固定时最多 101 项，但保留参数化分析更便于讨论扩展。

不要补上缺失的幂次，也不要删去 ±1。空表未定义官方期望；下方 SQL 和本地参考统一保留 NULL / null / None / nullopt 语义，交互输入则要求至少一项并明确提示。

MySQL · 本题可提交主解

SELECT CONCAT(
    GROUP_CONCAT(
        CONCAT(
            CASE WHEN factor > 0 THEN '+' ELSE '' END,
            factor,
            CASE
                WHEN power = 0 THEN ''
                WHEN power = 1 THEN 'X'
                ELSE CONCAT('X^', power)
            END
        )
        ORDER BY power DESC SEPARATOR ''
    ),
    '=0'
) AS equation
FROM Terms;

不加 GROUP BY：要把全表合成一行。只在最外层加 ORDER BY 并不能保证聚合内部的文本顺序。

MySQL 的 GROUP_CONCAT 有长度上限，默认 group_concat_max_len 为 1024。按本题范围计算，最多 101 项、每项至多 9 字符，保守上界 909 字符，默认值足够；若实际会话被调低或题目范围扩展，应增大该会话配置。空表聚合返回 NULL。依据：MySQL 8.0 官方聚合函数文档。

Java

import java.util.Arrays;
import java.util.Comparator;

public class Main {
    public static String buildEquation(int[][] terms) {
        if (terms.length == 0) return null;
        int[][] rows = terms.clone();
        Arrays.sort(rows, Comparator.comparingInt((int[] r) -> r[0]).reversed());
        StringBuilder out = new StringBuilder();
        for (int[] row : rows) {
            int power = row[0], factor = row[1];
            if (factor > 0) out.append('+');
            out.append(factor);
            if (power > 0) out.append('X');
            if (power > 1) out.append('^').append(power);
        }
        return out.append("=0").toString();
    }

    public static void main(String[] args) {
        int[][] terms = {{2, 1}, {1, -4}, {0, 2}};
        System.out.println(buildEquation(terms));
    }
}

JavaScript

function buildEquation(terms) {
  if (terms.length === 0) return null;
  const rows = [...terms].sort((a, b) => b[0] - a[0]);
  const parts = rows.map(([power, factor]) => {
    const signed = (factor > 0 ? '+' : '') + factor;
    const suffix = power === 0 ? '' : power === 1 ? 'X' : `X^${power}`;
    return signed + suffix;
  });
  return parts.join('') + '=0';
}

Python

from typing import List, Optional


def build_equation(terms: List[List[int]]) -> Optional[str]:
    if not terms:
        return None
    parts = []
    for power, factor in sorted(terms, key=lambda row: -row[0]):
        suffix = "" if power == 0 else "X" if power == 1 else f"X^{power}"
        parts.append(f"{factor:+d}{suffix}")
    return "".join(parts) + "=0"


if __name__ == "__main__":
    print(build_equation([[2, 1], [1, -4], [0, 2]]))

替代方案

在应用层可以创建 101 个幂次槽位，再从 100 扫描到 0，时间为 O(n + 101 + L)，空间为 O(101 + L)。它利用固定范围，范围扩展后排序更自然。

SQL 方言迁移可用 PostgreSQL 的 string_agg 并在聚合内部排序；不要把 MySQL 的 GROUP_CONCAT 原样当作跨数据库语法。递归拼接也可实现，但本题已有原生聚合，无需递归状态。

面试追问

power 不再唯一时？先按 power 分组 SUM(factor)，合并同类项，然后过滤和为零的项，再执行格式化聚合。若全部抵消，要先与需求方约定是否输出 0=0；这属于扩展约定。

为什么不能只给子查询排序？中间关系的行顺序不能替代聚合函数自身的顺序约束。应把 ORDER BY 放在有序聚合内部。

常见错误

  • 首个正项省略 +，或把 +1X 简写为 X。
  • 常数仍添加 X^0，一次项仍添加 ^1。
  • 负号与负 factor 同时拼接，得到 --4。
  • 使用默认分隔符，输出里混入逗号。
  • 用字符串顺序排列幂次，使 9 排在 10 前面。
  • 每个 power 单独 GROUP BY，结果变成多行。
  • 把题目误解为求根，调用 pow 计算数值。
  • 将交互演示或静态期望视为已执行的测试结果。
