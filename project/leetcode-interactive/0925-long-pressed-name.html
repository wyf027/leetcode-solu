长按键入

一次正常按键可能在输出中重复出现。你能判断屏幕上的字符，是否仍可能来自朋友输入的名字吗？

先观察，再揭晓。
先用下方实验室移动两个指针，找出“正常匹配”和“长按重复”的区别。
Problem

题目说明

任务

朋友要输入名字 name。输入某个字符时，按键可能被长按，因此这个字符会连续出现一次或多次。

给定键盘最终记录的字符串 typed，判断它是否可能由 name 产生。允许没有任何字符被长按。

函数形式： isLongPressedName(name, typed) → boolean

约束

  • 1 <= name.length, typed.length <= 1000
  • name 与 typed 只包含小写英文字母。
示例 1
输入：name = "alex", typed = "aaleex"
输出：true
解释：name 中的 'a' 和 'e' 被长按。
示例 2
输入：name = "saeed", typed = "ssaaedd"
输出：false
解释：name 中连续两个 'e' 无法被 typed 满足。

Solution

线性扫描：让 typed 解释自己

核心洞察
扫描 typed[j]：它要么匹配尚未消费的 name[i]，要么必须等于 typed[j-1]，才能被解释为上一个字符的长按重复。

完整过程

  1. 令 i = 0，逐个扫描 typed。
  2. 若当前字符等于 name[i]，消费 name 字符并令 i 前进。
  3. 否则，若它等于 typed 的前一个字符，则视为长按重复，i 不动。
  4. 两者都不是时立即返回 false；扫描结束后，只有 i 到达 name 末尾才返回 true。

正确性说明

每个 typed 字符只可能属于两类：对应 name 中下一个待输入字符，或重复最近已经输入的字符。算法分别接受这两种情况，并拒绝其他字符。

若最终所有 name 字符均被消费，则每个 typed 字符都有合法来源，构造成立；若仍有 name 字符未消费，typed 不可能表示完整名字。因此返回值当且仅当输入可能由长按产生。

边界与复杂度

  • 第一个 typed 字符不能凭空成为“重复”。
  • 连续相同字符仍须优先消费 name，例如 name="leelee"。
  • typed 可以更长，但不能比完整匹配所需更短。
  • 时间复杂度 O(|typed|)，额外空间 O(1)。

替代方案

可把两个字符串分别做游程编码，比较字符组是否相同且 typed 中每组计数不少于 name。逻辑直观，但需要额外存储；双指针更精炼。

面试追问

  • 若允许删除误输入字符，如何改成动态规划？
  • 若字符串以流式分块到达，怎样维护有限状态？
  • 如何输出具体哪些字符发生了长按？

常见错误

  • 只比较字符集合或出现次数，忽略顺序。
  • 发生不匹配时与 name 的前一个字符比较；更直接可靠的是与 typed 的前一个字符比较。
  • 扫描完 typed 后忘记确认 name 已全部消费。
