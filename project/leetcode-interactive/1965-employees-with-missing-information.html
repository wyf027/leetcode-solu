05 / 独立题解

准备好揭开规则了吗？

包含 SQL、推导与四语言本地语义参考。

只出现在一张表中的编号

核心洞察

令 E 为姓名表中的编号集合，S 为薪水表中的编号集合。缺少信息的编号恰好是两者的对称差 (E − S) ∪ (S − E)。两张表各自编号唯一，因此将所有编号保留重复地合并后：完整档案出现 2 次，缺失档案出现 1 次。

这里的“缺失”按本题的跨表记录缺失理解。它不是检测 name = ''、salary = 0，也不是额外检测已存在行中的字段 NULL。若业务把字段 NULL 也算缺失，需要另加规则；官方没有提供单独的 NULL 值示例。

完整过程

  1. 从 Employees 投影出 employee_id。
  2. 用 UNION ALL 合并 Salaries 的 employee_id，保留同一编号在两表中各出现一次的证据。
  3. 按 employee_id 分组，使用 HAVING COUNT(*) = 1 保留只出现一次的编号。
  4. ORDER BY employee_id，生成升序单列表。

官方示例中，合并序列为 [2, 4, 5, 5, 1, 4]；分组后 2→1 次、4→2 次、5→2 次、1→1 次；筛选得 2、1，再排序得到 1、2。交互账本展示的正是这个累计过程。

官方可提交语言 · SQL

以下写法适用于官方列出的 MySQL、PostgreSQL、MS SQL Server 与 Oracle；派生表别名省略 AS，以兼容 Oracle。

SELECT employee_id
FROM (
    SELECT employee_id FROM Employees
    UNION ALL
    SELECT employee_id FROM Salaries
) all_ids
GROUP BY employee_id
HAVING COUNT(*) = 1
ORDER BY employee_id;

正确性说明

覆盖性：任何已知雇员至少存在于一张表，因而进入合并结果。计数性质：由于每张表编号唯一，一个编号总计只会出现 1 次或 2 次。出现 1 次，当且仅当其中一张表没有该编号，恰好缺失一类信息；出现 2 次，当且仅当两类记录都存在。结果：HAVING 保留且仅保留需要的雇员，GROUP BY 保证每个编号一行，ORDER BY 保证升序。

边界与复杂度

两表都空时输出空表；只有一表非空时输出该表全部编号的升序结果；两表编号一致时输出为空；完全不相交时所有编号都输出。薪水为 0 不代表缺失。两表均未记录的编号无法从输入推知。

设两表行数为 n、m，不同编号数为 u，结果大小为 k。采用哈希分组时，预期时间为 O(n + m + k log k)，额外空间为 O(u)。若数据库选择排序分组，可能需要 O((n + m) log(n + m)) 时间；索引、聚合方式与执行计划决定实际性能。这些是算法估计，不是已测量的数据库耗时。

替代方案 · 双向反连接

SELECT e.employee_id
FROM Employees e
WHERE NOT EXISTS (
    SELECT 1 FROM Salaries s
    WHERE s.employee_id = e.employee_id
)
UNION
SELECT s.employee_id
FROM Salaries s
WHERE NOT EXISTS (
    SELECT 1 FROM Employees e
    WHERE e.employee_id = s.employee_id
)
ORDER BY employee_id;

也可用两次 LEFT JOIN 检测对侧连接键缺失。支持 FULL OUTER JOIN 的数据库可一次外连接后筛选单侧缺失；MySQL 不原生支持 FULL OUTER JOIN。若不再保证表内编号唯一，应先对每张表去重，或使用上述存在性查询，不能直接沿用 COUNT(*) = 1。

Java · 本地语义参考

本题不提供普通 Java / JavaScript / Python / C++ 提交通道。以下四份代码以完整两表行数据为输入，返回编号列表，仅用于本地理解，不冒充官方提交答案。Python 示例是标准库参考，非官方 Pandas 签名。

import java.util.*;

public class Main {
    static class Employee {
        int employeeId;
        String name;
        Employee(int id, String name) {
            this.employeeId = id;
            this.name = name;
        }
    }
    static class Salary {
        int employeeId;
        int salary;
        Salary(int id, int salary) {
            this.employeeId = id;
            this.salary = salary;
        }
    }
    static List<Integer> findEmployees(
            List<Employee> employees, List<Salary> salaries) {
        Map<Integer, Integer> count = new HashMap<>();
        for (Employee e : employees)
            count.merge(e.employeeId, 1, Integer::sum);
        for (Salary s : salaries)
            count.merge(s.employeeId, 1, Integer::sum);
        List<Integer> result = new ArrayList<>();
        for (Map.Entry<Integer, Integer> e : count.entrySet())
            if (e.getValue() == 1) result.add(e.getKey());
        Collections.sort(result);
        return result;
    }
    public static void main(String[] args) {
        List<Employee> employees = Arrays.asList(
            new Employee(2, "Crew"), new Employee(4, "Haven"),
            new Employee(5, "Kristian"));
        List<Salary> salaries = Arrays.asList(
            new Salary(5, 76071), new Salary(1, 22517),
            new Salary(4, 63539));
        System.out.println(findEmployees(employees, salaries));
    }
}

// 每行分别为 [employee_id, name] 或 [employee_id, salary]。
function findEmployees(employees, salaries) {
  const count = new Map();
  for (const table of [employees, salaries]) {
    for (const [id] of table) {
      count.set(id, (count.get(id) || 0) + 1);
    }
  }
  return [...count]
    .filter(([, times]) => times === 1)
    .map(([id]) => id)
    .sort((a, b) => a - b);
}
const employees = [[2, "Crew"], [4, "Haven"], [5, "Kristian"]];
const salaries = [[5, 76071], [1, 22517], [4, 63539]];
console.log(findEmployees(employees, salaries));

from collections import Counter


def find_employees(employees, salaries):
    # 每行分别为 (employee_id, name) 或 (employee_id, salary)。
    count = Counter(row[0] for row in employees)
    count.update(row[0] for row in salaries)
    return sorted(id_ for id_, times in count.items() if times == 1)

C++ · 本地语义参考

#include <algorithm>
#include <iostream>
#include <string>
#include <unordered_map>
#include <vector>
using namespace std;

struct Employee { int employee_id; string name; };
struct Salary { int employee_id; int salary; };

vector<int> findEmployees(const vector<Employee>& employees,
                          const vector<Salary>& salaries) {
    unordered_map<int, int> count;
    for (const auto& e : employees) ++count[e.employee_id];
    for (const auto& s : salaries) ++count[s.employee_id];
    vector<int> result;
    for (const auto& entry : count)
        if (entry.second == 1) result.push_back(entry.first);
    sort(result.begin(), result.end());
    return result;
}

int main() {
    vector<Employee> employees = {
        {2, "Crew"}, {4, "Haven"}, {5, "Kristian"}
    };
    vector<Salary> salaries = {
        {5, 76071}, {1, 22517}, {4, 63539}
    };
    for (int id : findEmployees(employees, salaries))
        cout << id << '\n';
    return 0;
}

常见错误

  • 把 UNION ALL 写成 UNION：合并时就去重，所有编号的计数都会变成 1。
  • 只查 Employees 中缺薪水的人：会遗漏仅在 Salaries 中出现的缺姓名雇员。
  • 在 WHERE 中使用聚合 COUNT：分组后的条件应写在 HAVING。
  • 认为 GROUP BY 自带排序：必须显式 ORDER BY。
  • 在 JavaScript 中省略数值比较器：默认字符串排序可能把 10 排到 2 前。
  • 使用 NOT IN 却忽视 NULL 的三值逻辑：更稳妥的存在性写法是 NOT EXISTS。

面试追问

  • 允许重复编号怎么办？计数策略先做表内去重，或切换到双向 NOT EXISTS。
  • 改成三张表怎么办？各表编号唯一时合并后统计出现次数，小于 3 即缺少至少一种记录；有重复则应统计来源表种类。
  • 数据特别大怎么办？比较执行计划中的哈希聚合、排序聚合与带编号索引的反连接，关注内存、扫描量和排序开销，不仅比较 SQL 行数。
  • 需要输出缺失项名称怎么办？保留来源信息，分别生成“缺姓名”和“缺薪水”两类结果。
