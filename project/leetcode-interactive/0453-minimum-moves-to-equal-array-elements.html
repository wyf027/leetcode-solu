Minimum Moves to Equal Array Elements

最小操作次数
使数组元素相等

一次操作能照顾数组里的几乎所有元素。目标看似简单，但“每次选择谁”会让搜索空间迅速膨胀。先从规则和一段可控实验开始，试着发现真正不变的关系。

Problem statement

题目在要求什么？

给定一个长度为 n 的整数数组 nums。每次操作必须选出其中 n - 1 个元素，并让这些被选元素都增加 1。

请返回使数组中所有元素相等所需的最少操作次数。

操作必须完整：每一步恰好增加 n - 1 个元素，不能少选，也不能一次增加多个单位。

参数与返回值

函数题
函数
minMoves(nums)
参数
nums: integer[]
返回
integer，最少操作次数

Example 01

需要三次操作

输入：nums = [1,2,3]
输出：3
解释：每次增加两个元素：
[1,2,3] → [2,3,3] → [3,4,3] → [4,4,4]

Example 02

无需操作

输入：nums = [1,1,1]
输出：0

Constraints

数据范围

  • n == nums.length
  • 1 <= nums.length <= 105
  • -109 <= nums[i] <= 109
  • 答案保证在 32 位整数范围内。

Complete solution

把群体增加，翻译成单点减少

如果所有元素都加一，元素之间的相对差值不会变化。因此，“给 n - 1 个元素加一”等价于“先给全部元素加一，再让唯一没选中的元素减一”。忽略对差值毫无影响的全体加一，每次操作就等价于让一个元素减一。

核心公式

答案 = Σ nums[i] − n × min(nums)

于是问题变成：每次把一个元素减一，最少多少次能让全部元素相等？最优目标只能是数组原本的最小值。

完整过程

  1. 扫描数组，求出最小值 minValue。
  2. 再次累加每个元素到最小值的距离 nums[i] - minValue；也可在一次扫描中同时求和与最小值。
  3. 所有距离之和就是最少操作次数。
nums = [1,2,3]
minValue = 1
差距 = (1-1) + (2-1) + (3-1)
     = 0 + 1 + 2
     = 3

为什么目标是最小值？

在等价模型中，唯一允许的动作是把某个元素减一，不能增加元素。因此最终公共值不可能高于当前最小值。若目标低于最小值，所有元素还要额外下降同样的距离，只会增加操作数；所以取原最小值最优。

关键不是模拟：我们只需计算每个元素与最小值之间有多少单位差距。

正确性证明

1

等价性：一次增加除一个元素外的所有元素，与“全体加一后让该元素减一”产生相同的相对差值。

2

下界：在单点减少模型中，每次只能消除一个单位的总差距，因此至少需要 Σ(nums[i]-min) 次。

3

可达：逐一把每个元素减到最小值，恰好使用上述次数。下界可达，所以算法最优。

时间复杂度

O(n)

一次线性扫描即可。

空间复杂度

O(1)

只维护总和与最小值。

数值安全

64-bit

中间总和可能超过 32 位。

class Solution {
    public int minMoves(int[] nums) {
        long sum = 0;
        int minValue = Integer.MAX_VALUE;

        for (int num : nums) {
            sum += num;
            minValue = Math.min(minValue, num);
        }

        return (int) (sum - (long) minValue * nums.length);
    }
}

    def minMoves(self, nums: List[int]) -> int:

        return sum(num - min_value for num in nums)
class Solution {
public:
    int minMoves(vector<int>& nums) {
        long long sum = 0;
        int minValue = nums[0];

        for (int num : nums) {
            sum += num;
            minValue = min(minValue, num);
        }

        return static_cast<int>(
            sum - 1LL * minValue * nums.size()
        );
    }
};

边界情况

  • 只有一个元素时，答案为 0。
  • 所有元素已经相等时，全部差距都是 0。
  • 存在负数不影响推导，差值仍然成立。
  • 计算 sum 与乘积时应使用 64 位中间值。

常见错误

  • 把题目误读为“每次只增加一个元素”。
  • 以最大值为目标并直接累加差距，忽略操作的等价方向。
  • 用优先队列逐步模拟，导致复杂度和实现都不必要地膨胀。
  • 用 32 位变量保存数组总和，造成中间值溢出。

替代方案

可以排序后取首元素为最小值，再累加差距，但时间复杂度为 O(n log n)。也可直接模拟每次操作，但步数可能很大，无法满足数据范围。线性数学解法更直接。

面试追问

  • 若一次可以增加任意 k 个元素，等价关系如何变化？
  • 若允许给单个元素加一或减一，最优目标为什么变成中位数？
  • 若要求返回具体操作序列，应如何在答案规模可控时构造？
