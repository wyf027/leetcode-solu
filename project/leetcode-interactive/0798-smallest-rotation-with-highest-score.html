得分最高的
最小轮调

让数组向左转动，值不超过新下标的元素就得 1 分。你的目标是在所有转法中找到得分最高、且轮调下标最小的那个 k。

HARD 非付费题 1 ≤ n ≤ 10⁵ 返回整数 k
Problem

先把计分规则看清

官方函数：bestRotation(nums)

给定整数数组 nums。选择一个非负整数 k 后，把数组向左轮调 k 位，得到：

[nums[k], nums[k + 1], …, nums[n - 1], nums[0], …, nums[k - 1]]

在轮调后的数组中，如果某个元素的值 小于或等于它的新下标，就记 1 分。请返回能够取得最高总分的轮调下标 k；若多个 k 并列，返回其中最小者。

01

向左轮调

原下标 i 会来到新下标 (i-k+n)%n。

02

逐项计分

只有 value ≤ newIndex 时，该项贡献 1 分。

03

最小者优先

得分相同不覆盖旧答案，自然保留更小的 k。

Solution

差分事件：只记录得分变化

时间 O(n) · 空间 O(n)

核心洞察

原下标为 i、值为 x 的元素，在轮调 k 后的新下标是：

j(k) = (i - k + n) % n

当 j(k) ≥ x 时它得分。把 k 从 0 增加到 1、2、… 时，大多数元素的得分状态保持不变；每个元素一轮中只有两个关键事件：

  • 当新下标从 x 变成 x-1 时，它失去 1 分。该事件发生在新轮调量 (i-x+1+n)%n。
  • 当新下标从 0 绕回 n-1 时，它重新得到 1 分。该事件发生在新轮调量 (i+1)%n。

因此可用差分数组 change 汇总每个 k 相比 k-1 的净得分变化。

完整过程

  1. 直接计算 k=0 的初始得分。
  2. 遍历每个 nums[i]=x，在失分位置记 -1。
  3. 在元素绕回数组尾部的位置记 +1。
  4. 从 k=1 开始累加变化量，得到各轮调的分数。
  5. 只在分数严格更高时更新答案，于是并列时自动保留最小 k。

正确性证明

  1. 单个元素：随着 k 每次加 1，新下标减 1；它只会在从 x 到 x−1 时由得分变为不得分，在从 0 绕到 n−1 时回到得分。x=0 时两事件重合并相互抵消，符合它始终得分的事实。
  2. 全部元素：差分数组把所有元素在同一 k 发生的变化相加，所以累加后的值恰好等于总分从 k−1 到 k 的净变化。
  3. 最优答案：初始得分正确，逐步累加得到每个 k 的准确分数；扫描所有 k 并只在严格增大时更新，最终答案就是最高分对应的最小 k。

边界与复杂度

  • n=1：唯一轮调是 0；差分事件同点抵消。
  • nums[i]=0：该元素在任何下标都得分，失分与得分事件重合。
  • 多个 k 并列：使用 score > bestScore，不在相等时更新。
  • 时间复杂度 O(n)：两次线性扫描。
  • 空间复杂度 O(n)：差分数组。

class Solution {
    public int bestRotation(int[] nums) {
        int n = nums.length;
        int[] change = new int[n];
        int score = 0;

        for (int i = 0; i < n; i++) {
            int x = nums[i];
            if (x <= i) {
                score++;
            }

            int loseAt = (i - x + 1 + n) % n;
            int gainAt = (i + 1) % n;
            change[loseAt]--;
            change[gainAt]++;
        }

        int bestScore = score;
        int answer = 0;
        for (int k = 1; k < n; k++) {
            score += change[k];
            if (score > bestScore) {
                bestScore = score;
                answer = k;
            }
        }
        return answer;
    }
}

            if (x <= i) {
                ++score;

            int loseAt = (i - x + 1 + n) % n;
            int gainAt = (i + 1) % n;
            --change[loseAt];
            ++change[gainAt];

                bestScore = score;
                answer = k;
            }
        }
        return answer;

替代方案

暴力枚举：对每个 k 生成轮调结果并扫描计分，时间 O(n²)、空间可做到 O(1)。它适合用来理解题意或对小数据核对，但无法通过 n=10⁵ 的约束。

区间贡献差分：也可以直接求每个元素“在哪些 k 下不得分”，把环形区间拆成至多两个线性区间做差分。复杂度同为 O(n)，但边界拆分更容易写错。

常见错误

  • 把“值 ≤ 下标”写成严格小于。
  • 把左轮调的新下标误写成 (i+k)%n。
  • 漏掉取模前的 +n，导致负数取模。
  • 分数相等时也更新答案，破坏“最小 k”要求。
  • 把 change[k] 当成分数，而不是相邻轮调间的分数变化。

面试追问

为什么一个元素只需两个事件？

新下标随 k 增大而逐次减 1，只有跨过值 x 的门槛时会失分，绕回 n−1 时会恢复得分；其余移动不改变布尔状态。

如果要求返回所有最佳 k 呢？

先扫描得到最高分，再进行一次线性扫描，把等于最高分的 k 全部收集起来；仍是 O(n)。

能否优化到 O(1) 额外空间？

一般不能在保持 O(n) 时间的同时省掉所有事件存储，因为需要按 k 汇总分散的变化；可以复用允许修改的输入存储事件，但会破坏 nums，通常不推荐。

为什么 change[0] 不参与扫描？

它描述从 k=n−1 环回 k=0 的变化；我们已经直接计算了 k=0 的分数，线性扫描只需累加 change[1…n−1]。
