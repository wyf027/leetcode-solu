完整题解

在“答案值域”上二分

核心洞察

矩阵的行列有序，并不意味着它能直接展平成一个已排序数组；但它允许我们快速回答一个更有用的问题：给定候选值 x，矩阵里有多少个元素不大于 x？

记这个数量为 count(x)。随着 x 增大，count(x) 单调不减。于是可以在值域 [matrix[0][0], matrix[n−1][n−1]] 上寻找满足 count(x) ≥ k 的最小值；它恰好是第 k 小元素。

完整过程

  1. 令 low 为左上角最小值，high 为右下角最大值。
  2. 取 mid = low + (high − low) / 2。
  3. 从左下角出发统计不大于 mid 的元素数：若当前位置不大于 mid，则它上方同列的元素全部满足条件，一次加入 row + 1，再向右；否则向上。
  4. 若数量小于 k，答案比 mid 大，令 low = mid + 1；否则保留 mid，令 high = mid。
  5. 当边界相遇，low 就是答案。

正确性证明

引理 1：阶梯扫描准确得到 count(x)。若左下扫描点 matrix[row][col] ≤ x，因为该列向上非递减地更小或相等，所以第 0 到 row 行都可一次计入；若该值大于 x，则同一行右侧只会更大，只需上移。每一步排除一行或一列，因此既不遗漏也不重复。
引理 2：谓词 count(x) ≥ k 单调。任何不大于 x 的元素在更大的候选值下仍会被计数。
定理：二分始终保留“使 count(x) ≥ k 的最小值”。当数量不足 k 时，mid 不可能是答案；否则答案不大于 mid。循环终止于唯一边界，而该边界按定义就是排序后的第 k 个元素。重复值参与计数，因此结论同样成立。

边界情况

  • n = 1 或 k = 1：边界可立即相遇，返回最小值。
  • k = n²：最终返回右下角最大值。
  • 负数、重复值和跨行交错均不影响值域二分与计数。
  • 计算中点时使用 low + (high − low) / 2；Java/C++ 用更宽整数保存边界，避免中间计算溢出。

复杂度

每次计数最多移动 2n 步，为 O(n)。二分次数为值域宽度的对数，整体时间 O(n · log(max − min))；额外空间 O(1)。

替代方案

最小堆归并行：把每行看作一个有序序列，先放入每行首元素，弹出 k 次并补入同行后继。时间 O(k log n)，空间 O(n)，当 k 很小时直观有效。直接收集并排序全部元素需 O(n²) 空间，不满足题目的空间要求。

面试追问

  • 为什么返回的是矩阵中的真实元素，而不是值域中的空隙？因为满足计数阈值的最小整数一定落在一次计数跳变处，跳变只会发生在矩阵元素值上。
  • 若矩阵是 m × n 呢？计数仍从左下或右上扫描，单次为 O(m+n)。
  • 什么时候堆更好？值域极宽但 k 很小，且可接受 O(n) 空间时。
  • 能否做到理论上的 O(n)？存在针对有序矩阵选择问题的高级算法，但实现复杂，通常超出面试预期。

常见错误

  • 把问题误读成第 k 个不同元素，错误地去重。
  • 计数等于 k 时立即返回 mid；mid 可能不在矩阵中，正确做法仍是收紧右边界。
  • 二分写成 high = mid − 1，破坏“寻找第一个满足谓词的位置”的边界定义。
  • 阶梯扫描方向与一次计入的数量不匹配，造成漏计或重复计数。
