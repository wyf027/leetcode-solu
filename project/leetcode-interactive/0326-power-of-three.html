Solution

题解：不断消去因子 3

核心洞察

正整数若是 3 的幂，它的质因子只有 3。只要当前值能被 3 整除，就把它除以 3；所有因子都被消去后，最终必须恰好得到 1。先排除 n ≤ 0，因为 3 的任意整数次幂在本题整数定义下都不会是非正数。

完整过程

  1. 若 n ≤ 0，立即返回 false。
  2. 当 n % 3 == 0 时，令 n = n / 3。
  3. 循环结束后判断 n == 1。是则返回 true，否则说明残留了其他质因子。

边界提示：1 = 30，所以 1 是 3 的幂；0 和负数都不是。

正确性证明

循环不变式：每次循环开始时，当前值乘以已经消去的若干个 3，等于原始输入。因此，循环只移除因子 3，不会改变“是否还含有其他质因子”这一事实。

若算法返回 true，最终值为 1，原数便等于若干个 3 的乘积，即 3k。反之，若原数是 3k，每轮都能整除 3，经过 k 轮必然到达 1 并返回 true。所以算法当且仅当输入是 3 的幂时返回真。

复杂度

每轮把 n 缩小为三分之一，时间复杂度为 O(log₃ n)，额外空间复杂度为 O(1)。

边界情况

  • n = 1：循环不执行，直接返回真。
  • n = 0 或负数：提前返回假，避免 0 无限除以 3。
  • 能被 3 整除但含其他因子，例如 45：最终停在 5，返回假。
  • 32 位最大整数：循环只做整除，不涉及乘法溢出。

替代方案

在题目限定的 32 位有符号整数范围内，最大的 3 的幂是 319 = 1162261467。所有正的 3 的幂都是它的约数，因此可用 n > 0 && 1162261467 % n == 0 在常数时间内判断，满足“不使用循环或递归”的进阶要求。该技巧依赖固定整数范围；若类型或上界改变，常量也必须更新。

也可以用对数判断，但浮点误差会让接近整数的结果产生误判，面试中通常不如整数方案稳健。递归写法与迭代机制相同，但会使用 O(log n) 调用栈。

四语言完整代码

JavaLeetCode
class Solution {
    public boolean isPowerOfThree(int n) {
        if (n <= 0) {
            return false;
        }
        while (n % 3 == 0) {
            n /= 3;
        }
        return n == 1;
    }
}

面试追问

  • 如何泛化到 k 的幂？ 对 k > 1 持续整除 k，最后判断是否为 1；同时明确 0、1、负底数等定义边界。
  • 为什么最大幂取模法只适用于质数底数？ 若底数为合数，其最大幂可能还有并非该底数幂的约数，例如 16 的约数 8。
  • 若输入改为任意精度整数呢？ 迭代整除仍正确；最大 3 的幂常量法不再适用。
  • 能否使用递归？ 可以，但需要说明调用栈空间以及极端输入下的栈深度。

常见错误

  • 忘记排除 0，导致 0 % 3 == 0 且 0 / 3 == 0，循环永不结束。
  • 误认为指数必须大于 0，从而把 1 = 30 判为假。
  • 使用浮点对数后直接比较小数是否为整数，忽略舍入误差。
  • 用乘法枚举 3 的幂却没有处理整数溢出。
