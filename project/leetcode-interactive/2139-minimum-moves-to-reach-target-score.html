Minimum Moves to Reach Target Score

从数字 1 出发，每次可以 加 1 或 乘 2。加 1 不限次数，乘 2 最多使用 maxDoubles 次。求恰好到达 target 的最少行动次数。

先观察操作与预算，思考如何安排有限的加倍机会。题解和交互推演位于页面底部，默认收起。

官方题目 ↗

输入与约束

minMoves(target, maxDoubles) → integer

  • target：目标整数，1 ≤ target ≤ 10⁹。
  • maxDoubles：加倍次数上限，0 ≤ maxDoubles ≤ 100。
  • 每次递增或加倍均计为一次行动；预算是上限，不必全部用完。

官方示例

01 · 没有加倍机会

输入：target = 5, maxDoubles = 0
输出：4

路径：1 → 2 → 3 → 4 → 5，递增四次。

02 · 两次加倍

输入：target = 19, maxDoubles = 2
输出：7

从 1 递增三次到 4，加倍到 8，递增到 9，加倍到 18，递增到 19，共七次行动。

03 · 预算可以剩余

输入：target = 10, maxDoubles = 4
输出：4

路径：1 → 2 → 4 → 5 → 10。先递增，再加倍，再递增，再加倍，共四次行动。

逆向贪心：把目标退回 1

正向要决定何时加倍；反过来，每个奇数的最后一步必定来自加 1。把 +1 反转为 −1，把 ×2 反转为偶数上的 ÷2，便能逐步消去目标值。

核心洞察与完整过程

  1. 当前值为 1：已完成，立即停止。
  2. 配额为 0：只能减 1，剩余成本直接加上 target − 1。
  3. 配额尚有且当前值为奇数：减 1，成本加 1，配额不变。
  4. 配额尚有且当前值为偶数：除以 2，成本加 1，配额减 1。

示例 2 的逆向轨迹为 19 → 18 → 9 → 8 → 4 → 1。最后一段代表三次减 1，因此总成本是 1 + 1 + 1 + 1 + 3 = 7，不是五次。将逆向操作倒序反转即可恢复正向路径。

正确性：为何偶数可以立即减半？

合法的正向路径与逆向路径一一对应，且操作数、加倍配额消耗保持一致。奇数不能由整数加倍得到，因此逆向必须先减 1。

设当前偶数为 t > 1，且仍有配额。若某条方案先减 2r 次再首次除以 2，它到达 t/2 − r，花费 2r + 1 步。改为立即除以 2，再减 r 次，可到达同一个值，只花 r + 1 步，且消耗同样的一次配额。首次除以 2 前的减法次数必为偶数，所以该交换覆盖所有延后减半的方案。

若方案完全不再减半，它需要 t − 1 步；立即减半后只用减法即可在 t/2 步内完成，满足 t/2 ≤ t − 1。因此存在最优方案在偶数处立即减半。每一步均可选取最优决策，值严格下降，最终到达 1；配额耗尽时剩余减法又是唯一选择，算法正确。

边界与复杂度

  • target = 1 返回 0。
  • 零预算直接返回 target − 1，避免十亿次循环。
  • 预算过多也只执行必要操作，值为 1 时停止。
  • 答案不超过 10⁹ − 1，Java / C++ 的 32 位有符号整数足够，JavaScript Number 精确表示这些整数。

每次减半最多伴随一次奇数减 1。时间 O(1 + min(maxDoubles, log target))，通常写为 O(log target)；提交代码额外空间 O(1)。交互轨迹为展示保存各状态，使用 O(log target) 空间。

替代方案

可以用 BFS 枚举 (当前值, 已加倍次数)，按层数寻找最短路，或用动态规划保存各值和预算的最少成本。状态量约为 O(target × (maxDoubles + 1))，在十亿级目标下不实用。

常见错误

  • 正向一开始就不断加倍：有限预算可能浪费在小数值上。
  • 把“最多”理解为必须用完配额。
  • 奇数直接向下取整除 2，却只计一步。
  • 预算耗尽后仍循环逐次减 1。

Java

class Solution {
    public int minMoves(int target, int maxDoubles) {
        int moves = 0;
        while (target > 1 && maxDoubles > 0) {
            if (target % 2 == 1) {
                target--;
            } else {
                target /= 2;
                maxDoubles--;
            }
            moves++;
        }
        return moves + target - 1;
    }
}

面试追问

如何输出最优路径？记录逆向操作再反转；对于十亿级纯递增路径，应输出压缩段而不是逐项展开。

若加倍和递增成本不同？需重新比较交换前后代价，尤其“从不加倍”的方案可能更便宜，不能直接沿用当前贪心。

若改为乘 3？可研究逆向按余数减到 3 的倍数再整除，但必须重新证明决策和处理成本，不能只替换运算符就宣称正确。
