核心洞察

按“最后一跨”划分，三类走法互不重叠

最后跨 1 阶

此前必须站在第 i - 1 阶，贡献 f(i - 1)。

最后跨 2 阶

此前必须站在第 i - 2 阶，贡献 f(i - 2)。

最后跨 3 阶

此前必须站在第 i - 3 阶，贡献 f(i - 3)。

f(i) = (f(i - 1) + f(i - 2) + f(i - 3)) mod 1,000,000,007

完整过程

只保留最近三张票

  1. 01

    定义地面

    设 f(0) = 1，表示“不走也是一种到达地面的方案”。

  2. 02

    准备初值

    f(1) = 1、f(2) = 2。

  3. 03

    循环汇总

    从第 3 阶开始，把最近三项相加并立即取模。

  4. 04

    滚动前进

    三个变量依次右移，循环结束时最新值就是答案。

边界

最小输入与取模

  • n = 1 返回 1，n = 2 返回 2。
  • f(0) = 1 是递推哨兵，不是题目允许的输入。
  • 每轮三项相加后取模；Java/C++ 使用 long/long long。
  • n = 1,000,000 不能用递归栈或存满无必要的表。

复杂度

一次线性扫描

时间

O(n)

空间

O(1)

替代方案

数组 DP

同样是 O(n) 时间，但占 O(n) 空间；若需要查询所有中间状态才值得保留。

替代方案

记忆化递归

递推关系清晰，但百万规模会遇到调用栈问题，不适合作为本题提交主线。

替代方案

矩阵快速幂

可降到 O(log n)，但常数与实现复杂度更高；当前约束下线性滚动更适合面试。

面试追问

  • 如果步长集合变成任意数组？ 对所有允许步长求和，空间可压到最大步长。
  • 如果 n 远大于一百万？ 使用矩阵快速幂或线性递推加速。
  • 为何是相加而不是相乘？ 三类按最后一步划分，是互斥的“或”关系。

常见错误

  • 把 f(0) 写成 0，导致第 1、2、3 阶初值错位。
  • 最后才取模，Java/C++ 中间和可能溢出。
  • 原地更新三个变量的顺序错误，覆盖了仍需使用的旧值。
  • 用指数级暴力递归，无法通过最大输入。

class Solution {
    public int waysToStep(int n) {
        final int MOD = 1_000_000_007;
        if (n == 1) return 1;
        if (n == 2) return 2;

        long a = 1; // f(0)
        long b = 1; // f(1)
        long c = 2; // f(2)
        for (int i = 3; i <= n; i++) {
            long next = (a + b + c) % MOD;
            a = b;
            b = c;
            c = next;
        }
        return (int) c;
    }
}

    def waysToStep(self, n: int) -> int:

        if n == 1:
