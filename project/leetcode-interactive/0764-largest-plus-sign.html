Problem 764 · Largest Plus Sign

最大加号标志在满是 1 的方格里，寻找四条臂都足够长的中心。

01 · Problem

题目说明

坐标从 0 开始；加号必须与行、列方向对齐，斜线不计入。

给定整数 n。一个 n × n 的二进制矩阵最初全部为 1；数组 mines 中的每个位置 [xᵢ, yᵢ] 会被置为 0。

请返回矩阵中只由 1 组成的、轴对齐的最大加号标志的阶数。如果不存在任何加号，返回 0。

k 阶加号

中心 grid[r][c] 为 1，并且从中心向上、下、左、右各有连续 k − 1 个 1。中心本身也计入阶数，所以单个 1 是 1 阶加号。四条臂以外的格子可以是 0，也可以是 1。

函数参数

  • n: integer矩阵的边长，矩阵共有 n² 个格子。
  • mines: integer[][]所有矿点坐标；每个元素完整形式为 [xᵢ, yᵢ]。
  • 返回值: integer最大加号标志的阶数。

约束

  • 1 ≤ n ≤ 500
  • 1 ≤ mines.length ≤ 5000
  • 0 ≤ xᵢ, yᵢ < n
  • 所有坐标对 (xᵢ, yᵢ) 互不重复

官方函数签名

orderOfLargestPlusSign(n, mines) → integer

关键辨析

返回的是“阶数”，不是加号覆盖的格子数。k 阶加号覆盖 4k − 3 个格子。

05 · Solution

四次扫描，取四向最小值

核心洞察

固定一个非矿点 (r,c)。若分别知道从该格出发向左、右、上、下能连续包含多少个 1（都包含中心），那么它能作为的最大加号阶数，就是这四个计数的最小值。

order(r,c) = min(L, R, U, D)

原因很直接：四条臂必须等长，最短的方向决定了所有方向共同能够延伸到哪里。

完整过程

1
建立计数矩阵

所有格先填 n，矿点置 0；0 会自然切断连续计数。

2
扫描每一行

先从左到右，再从右到左；每次把当前位置更新为旧值与当前连续计数的较小者。

3
扫描每一列

从上到下、从下到上做同样的更新。扫描结束后，每格已是四向最小值。

4
维护全局最大值

遍历或在最后一次扫描时更新答案，得到最大阶数。

正确性证明

  1. 每个方向的扫描计数，恰好等于从当前格向该方向延伸时，包含当前格在内的最大连续 1 数量；遇到矿点归零，因此不会跨过 0。
  2. 对任意中心，k 阶加号存在，当且仅当四个方向的连续计数都至少为 k。因此该中心可形成的最大阶数等于四个计数的最小值。
  3. 算法对每个格子都求出上述最小值，再取全局最大值，所以既不会漏掉更大的合法加号，也不会返回不可实现的阶数。

结论：算法返回的值正是整个矩阵中最大轴对齐加号标志的阶数。

边界与复杂度

时间复杂度O(n²)
空间复杂度O(n²)
  • 全部是矿点：方向计数始终为 0，答案为 0。
  • 只有一个 1：四向计数均为 1，答案为 1。
  • 没有邻接臂：单个 1 仍是合法的 1 阶加号。
  • 加号触碰边界：方向计数会受边界自然限制，无需额外分支。
  • n = 500：四次线性矩阵扫描仍为 O(n²)。

Implementation

四种语言完整代码

都复用一张 n × n 矩阵，依次合并四个方向的连续计数。

Java
官方可提交
import java.util.Arrays;

class Solution {
    public int orderOfLargestPlusSign(int n, int[][] mines) {
        int[][] arm = new int[n][n];
        for (int[] row : arm) {
            Arrays.fill(row, n);
        }
        for (int[] mine : mines) {
            arm[mine[0]][mine[1]] = 0;
        }

        for (int i = 0; i < n; i++) {
            int count = 0;
            for (int j = 0; j < n; j++) {
                count = arm[i][j] == 0 ? 0 : count + 1;
                arm[i][j] = Math.min(arm[i][j], count);
            }

            count = 0;
            for (int j = n - 1; j >= 0; j--) {
                count = arm[i][j] == 0 ? 0 : count + 1;
                arm[i][j] = Math.min(arm[i][j], count);
            }
        }

        int answer = 0;
        for (int c = 0; c < n; c++) {
            int count = 0;
            for (int r = 0; r < n; r++) {
                count = arm[r][c] == 0 ? 0 : count + 1;
                arm[r][c] = Math.min(arm[r][c], count);
            }

            count = 0;
            for (int r = n - 1; r >= 0; r--) {
                count = arm[r][c] == 0 ? 0 : count + 1;
                arm[r][c] = Math.min(arm[r][c], count);
                answer = Math.max(answer, arm[r][c]);
            }
        }
        return answer;
    }
}

替代方案

A
四张方向 DP 表

分别保存 L、R、U、D，逻辑最直观，时间同为 O(n²)，但额外空间约为四倍。

B
枚举中心与阶数

从候选中心向四边扩展或逐阶验证，容易重复扫描，最坏可退化到 O(n³)。

C
矿点集合 + 二分臂长

可对候选加号做查询，但仍需处理大量中心；对 n ≤ 500，本题的四向 DP 更清晰稳定。

常见错误

  • 把阶数 k 误当成单条臂的格子数；方向计数必须包含中心。
  • 只比较横向和纵向总长度，没有分别保证四条臂都至少为 k。
  • 扫描遇到矿点时没有把连续计数清零，导致计数跨过 0。
  • 只做左、上两个方向，遗漏右边或下边更近的矿点。
  • 使用字符串拼接坐标却未设置可靠分隔符，造成矿点键冲突。
  • 返回覆盖格子数 4k−3，而不是题目要求的阶数 k。

Follow-ups

面试追问

为什么“取四向最小值”一定能得到该中心的最大阶数？

k 阶要求四个方向都至少连续 k 个 1；因此所有可行 k 的上界是四个计数的最小值。取到该最小值时，四个方向又都满足要求，所以这个上界可以实现。

能否把额外空间降到 O(n)？

如果必须一次性给出所有中心的四向最小值，反向信息需要与先前方向信息汇合，通常要保存 O(n²) 状态。可以用更复杂的逐行/逐列组织或位集优化常数，但在本题约束下，一张 n² 表是清晰可靠的折中。

如果要返回所有最大加号的中心怎么办？

完成四向更新后先得到全局最大阶数，再扫描矩阵收集所有值等于最大阶数的位置；若答案为 0，则返回空集合。

如果加号允许旋转 45° 呢？

把四个方向改为左上、右上、左下、右下四条对角线，并按对应遍历顺序计算连续 1；最终仍然取四向最小值。

为什么初始值填 n，而不是填 1？

n 是任一方向连续长度的安全上界。后续每次取最小值时，它不会错误限制真实计数；若初始填 1，所有大于 1 的阶数都会被过早截断。
