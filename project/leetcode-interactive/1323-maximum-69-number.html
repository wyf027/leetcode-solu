Solution

贪心：改变最靠左的 6

核心洞察

若要让数字变大，只应做 6 → 9；而相同增量 3 出现在越高的数位，带来的数值增益越大。

从左到右，第一个 6 所在的位置权重最大。把它改成 9，增量是 3 × 10ᵏ。任何更靠右的 6 权重都更小，因此无法产生更大的结果。如果不存在 6，就保持原数。

完整过程

转成字符序列。
数字的每一位都能直接按从左到右的顺序访问。
寻找第一个 6。
跳过所有 9；遇到首个 6 时把它替换为 9。
立即停止。
操作额度只有一次，且这一位已经提供最大可能增益。
转回整数。
若未找到 6，序列不变，返回原数字。

正确性证明

设从左到右第一个 6 位于十进制权重 10ᵏ。把这一位由 6 改为 9，结果增加 3 × 10ᵏ。

在它左侧的每一位都是 9，若翻成 6 只会使结果变小；在它右侧若存在 6，其权重至多为 10ᵏ⁻¹，对应增量严格小于 3 × 10ᵏ。因此，没有其他单次翻转能得到更大的结果。若没有 6，任何可做的翻转都只能把 9 变成 6，所以不操作最优。故算法总能返回合法操作下的最大数字。

边界与复杂度

边界情况
  • 只有一位：6 → 9，9 保持不变。
  • 首位就是 6：直接改变首位。
  • 全部是 9：不执行任何翻转。
  • 末位才是 6：扫描到末位再改变。
时间O(d)d 为数字位数
额外空间O(d)字符数组方案

数学方案可以做到 O(1) 额外空间；在本题约束下，两者都非常轻量。

替代方案

数学定位

从高位到低位检查数位，找到首个 6 后加上对应的 3 × 10ᵏ。空间 O(1)，但代码可读性略低。

枚举每一位

分别翻转每个位置并比较所有结果。容易想到，时间约为 O(d²)（若每次重建字符串），没有利用结构信息。

class Solution {
    public int maximum69Number(int num) {
        char[] digits = String.valueOf(num).toCharArray();

        for (int i = 0; i < digits.length; i++) {
            if (digits[i] == '6') {
                digits[i] = '9';
                break;
            }
        }

        return Integer.parseInt(new String(digits));
    }
}

面试追问

  • 如果必须翻转一次呢？ 有 6 仍改最左侧 6；若全为 9，则应把最右侧 9 改成 6，使损失最小。
  • 如果最多翻转 k 次呢？ 从左到右把最多 k 个 6 改成 9。
  • 如果数字由任意两种数字组成呢？ 仍需比较替换的增量方向，并优先选择最高位的正增益。
  • 能否不用字符串？ 可以，用除法和取模从高位检查，并加上首个 6 对应的 3 倍位权。

常见错误

改变最右边的 6

十进制高位权重更大，应优先处理最左边的 6。

继续改变多个 6

题目限制最多一次，完成替换后必须立即退出循环。

全为 9 时仍翻转

“最多一次”允许零次操作；此时保留原数最大。

用字符串比较结果

本题位数相同虽通常可行，但直接按数位贪心更清晰，也避免不必要的候选构造。
