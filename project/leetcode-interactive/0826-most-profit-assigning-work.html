安排工作以达到最大收益

Most Profit Assigning Work

一组岗位有不同的门槛和收益，一组工人有不同的能力。你的任务，是在“每人最多做一份、同一岗位可重复安排”的规则下，让总收益尽可能高。

分配规则卡

  1. 1工人只能选择难度不超过其能力的工作。
  2. 2每个工人最多被安排一份工作，也可以不安排。
  3. 3同一份工作可以由多个工人分别完成。
  4. 4无法胜任任何工作时，该工人的收益为 0。

Problem Brief

先把任务边界看清楚

给定 difficulty、profit 与 worker。第 i 份工作的难度和收益分别是 difficulty[i] 与 profit[i]；第 j 个工人的能力是 worker[j]。返回所有工人完成分配后能够取得的最大总收益。

官方示例

示例 1典型分配
输入：difficulty = [2,4,6,8,10], profit = [10,20,30,40,50], worker = [4,5,6,7]
输出：100
解释：四名工人选择难度 [4,4,6,6] 的工作，分别取得 [20,20,30,30] 的收益。
示例 2无人胜任
输入：difficulty = [85,47,57], profit = [24,66,99], worker = [40,25,25]
输出：0

参数与约束

函数：maxProfitAssignment(difficulty, profit, worker)

返回：一个整数，表示最大总收益。

  • n == difficulty.length
  • n == profit.length
  • m == worker.length
  • 1 <= n, m <= 104
  • 1 <= difficulty[i], profit[i], worker[i] <= 105

Full Solution

排序后，用一条单调扫描线

把可选范围随着工人能力增长而扩大的性质利用起来：每份岗位只进入候选集合一次，每名工人直接拿到当下的最高收益。

核心洞察

同一岗位可以重复完成，因此工人之间不会争抢资源。 对每名工人，只需在“难度不超过能力”的岗位中选择最高收益；把所有人的最佳值相加即可。

若按难度升序排列岗位、按能力升序排列工人，处理下一名能力更强的工人时，之前可做的岗位仍然可做，候选集合只会扩大。于是可以用一个指针扫描新解锁的岗位，并持续维护见过的最大收益 best。

完整过程

  1. 把每份岗位整理成 (difficulty, profit)，按难度升序排列。
  2. 将工人能力升序排列。改变处理顺序不影响总收益，因为每名工人的选择彼此独立。
  3. 令岗位指针 i = 0、当前最高可得收益 best = 0、答案 total = 0。
  4. 依次处理能力 ability：当 jobs[i].difficulty <= ability 时，把该岗位纳入范围，用其收益更新 best，然后右移指针。
  5. 此时所有能被该工人完成的岗位都已扫描，给 total 加上 best。若没有岗位可做，best 仍为 0。

示例 1：排序后依次处理能力 4、5、6、7；对应最佳收益为 20、20、30、30，总和为 100。

正确性证明

1
不变量：处理能力为 ability 的工人之前完成内层扫描后，指针左侧恰好包含所有难度不超过 ability 的岗位，best 等于这些岗位中的最大收益。
2
保持：工人按能力升序处理。下一名工人的可行岗位包含之前所有可行岗位；内层循环只需继续加入新满足难度条件的岗位，并取收益最大值，所以不变量继续成立。
3
单人最优：根据不变量，加入答案的 best 是该工人所有可行选择中的最大收益；选择其他工作不会更优。
4
全局最优：岗位允许重复完成，给某个工人选择工作不会减少其他工人的选择。因此每名工人的单人最优可以同时实现，其总和就是最大总收益。

边界与复杂度

  • 最弱工人无法完成最简单岗位：本轮没有岗位进入候选范围，贡献 0。
  • 多个岗位难度相同：扫描时会全部纳入，并保留其中最高收益。
  • 更难的岗位收益可能更低：不能用“最后一个可做岗位”代替最大值，必须维护 best。
  • 多个工人能力相同：每人都可独立取得同一个最佳收益。
  • 在给定约束下，总收益最大为 10^4 × 10^5 = 10^9，32 位有符号整数可容纳。
时间复杂度O(n log n + m log m)
额外空间O(n + m)

排序完成后的双指针扫描是 O(n + m)。这里按四份实现创建的岗位对与工人副本统一计为 O(n + m)；若原地排序工人数组，实际额外空间可更低。

替代方案

岗位前缀最大值 + 二分查找

岗位按难度排序后，构造收益前缀最大值。对每名工人二分查找最后一个不超过其能力的难度，再读取前缀最大收益。复杂度为 O(n log n + m log n)，不需要排序工人，适合工人查询在线到达的场景。

按能力值建表

由于能力和难度不超过 105，可以为每个难度记录收益，再做前缀最大值，使查询接近 O(1)。总复杂度约为 O(n + m + V)、空间 O(V)，其中 V 是最大取值；它依赖数值上界，不如排序方案通用。

逐人枚举全部岗位

直接为每名工人扫描所有岗位虽然容易想到，但复杂度为 O(nm)；当 n、m 都为 104 时会达到 108 次比较，不是理想解法。

四语言完整代码

JavaLeetCode 可提交
import java.util.Arrays;

class Solution {
    public int maxProfitAssignment(int[] difficulty, int[] profit, int[] worker) {
        int n = difficulty.length;
        int[][] jobs = new int[n][2];

        for (int i = 0; i < n; i++) {
            jobs[i][0] = difficulty[i];
            jobs[i][1] = profit[i];
        }

        Arrays.sort(jobs, (a, b) -> Integer.compare(a[0], b[0]));
        Arrays.sort(worker);

        int jobIndex = 0;
        int best = 0;
        int total = 0;

        for (int ability : worker) {
            while (jobIndex < n && jobs[jobIndex][0] <= ability) {
                best = Math.max(best, jobs[jobIndex][1]);
                jobIndex++;
            }
            total += best;
        }

        return total;
    }
}

/**
 * @param {number[]} difficulty
 * @param {number[]} profit
 * @param {number[]} worker
 * @return {number}
 */
var maxProfitAssignment = function(difficulty, profit, worker) {
    const jobs = difficulty.map((level, index) => [level, profit[index]]);
    jobs.sort((a, b) => a[0] - b[0]);

    const sortedWorkers = [...worker].sort((a, b) => a - b);
    let jobIndex = 0;
    let best = 0;
    let total = 0;

    for (const ability of sortedWorkers) {
        while (jobIndex < jobs.length && jobs[jobIndex][0] <= ability) {
            best = Math.max(best, jobs[jobIndex][1]);
            jobIndex++;
        }
        total += best;
    }

    return total;
};

from typing import List


class Solution:
    def maxProfitAssignment(
        self,
        difficulty: List[int],
        profit: List[int],
        worker: List[int]
    ) -> int:
        jobs = sorted(zip(difficulty, profit))
        sorted_workers = sorted(worker)

        job_index = 0
        best = 0
        total = 0

        for ability in sorted_workers:
            while job_index < len(jobs) and jobs[job_index][0] <= ability:
                best = max(best, jobs[job_index][1])
                job_index += 1
            total += best

        return total
C++LeetCode 可提交
class Solution {
public:
    int maxProfitAssignment(
        vector<int>& difficulty,
        vector<int>& profit,
        vector<int>& worker
    ) {
        vector<pair<int, int>> jobs;
        jobs.reserve(difficulty.size());

        for (int i = 0; i < static_cast<int>(difficulty.size()); ++i) {
            jobs.push_back({difficulty[i], profit[i]});
        }

        sort(jobs.begin(), jobs.end());
        sort(worker.begin(), worker.end());

        int jobIndex = 0;
        int best = 0;
        int total = 0;

        for (int ability : worker) {
            while (jobIndex < static_cast<int>(jobs.size())
                   && jobs[jobIndex].first <= ability) {
                best = max(best, jobs[jobIndex].second);
                ++jobIndex;
            }
            total += best;
        }

        return total;
    }
};

面试追问

  • 如果一份岗位只能被完成一次？ 工人之间开始争抢资源，当前独立贪心不再成立；需要结合具体规则考虑匹配、堆或动态规划。
  • 如果工人查询不断在线到达？ 预处理“难度有序 + 收益前缀最大值”，每次用二分查找回答。
  • 为什么可以排序工人？ 总收益只是每名工人独立最优值的和，处理次序不会改变任一工人的可选集合。
  • 能否不保存排序后的工人副本？ 若允许修改输入，可以原地排序；否则复制可避免副作用。
  • 为什么 best 不在每轮清零？ 能力递增时，可行岗位集合只扩大，之前的最佳岗位仍然可行。

常见错误

  • 误以为岗位不能复用，把已分配岗位从候选集中删除。
  • 只取难度最大的可行岗位，却忽略收益不随难度单调增加。
  • 岗位排序时只排序 difficulty，导致它与 profit 的对应关系被破坏。
  • 内层条件写成 difficulty < ability，漏掉难度恰好等于能力的岗位。
  • 处理新工人时把 best 重置为 0，重复扫描或丢失之前的最佳收益。
  • 直接使用嵌套循环，未结合 104 的数据规模评估最坏复杂度。
