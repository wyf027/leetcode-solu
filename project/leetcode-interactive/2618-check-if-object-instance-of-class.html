检查是否是类的对象实例

编写 checkIfInstanceOf(obj, classFunction)：判断给定值是否拥有目标类或其超类提供的方法。参数类型不受限制，值或类甚至可能是 undefined。

Check if Object Instance of Class · 非付费题
01

题目说明

对本题而言，只要一个值能够沿其继承关系访问某个类的方法，就把它视为该类的实例；超类同样有效。
函数签名
checkIfInstanceOf(obj, classFunction): boolean
返回值
满足实例关系时返回 true，否则返回 false。
参数 obj
任意 JavaScript 值，包括对象、函数、原始值、null 或 undefined。
参数 classFunction
任意值；有效类通常是具有 prototype 的函数。

约束

  • 传入函数的数据类型没有限制。
  • obj 或 classFunction 都可能是 undefined。
  • 需要识别超类关系，并覆盖可访问类方法的原始值情形。
02

官方示例

示例 1 · Date 对象

输入：func = () =>
  checkIfInstanceOf(new Date(), Date)
输出：true

Date 构造器创建的对象是 Date 的实例。

示例 2 · 子类与超类

输入：func = () => {
  class Animal {}
  class Dog extends Animal {}
  return checkIfInstanceOf(new Dog(), Animal)
}
输出：true

Dog 继承 Animal，因此 Dog 对象也是 Animal 的实例。

示例 3 · 构造函数本身

输入：func = () =>
  checkIfInstanceOf(Date, Date)
输出：false

Date 构造函数本身并不是由自己创建的实例。

示例 4 · 原始数字

输入：func = () =>
  checkIfInstanceOf(5, Number)
输出：true

数字 5 能访问 Number 的方法，例如 toFixed()，因此本题视为实例。

05

完整题解

核心洞察

实例关系本质上是：classFunction.prototype 是否出现在该值的原型链中。先用 Object(obj) 装箱原始值，再沿链向上查找即可。

完整过程

  1. 若 obj 是 null/undefined，或目标不是函数，直接返回 false。
  2. 执行 Object(obj)：对象保持原样，数字等原始值获得对应包装对象。
  3. 从包装后对象的直接原型开始，逐层调用 Object.getPrototypeOf。
  4. 任一层严格等于 classFunction.prototype 时返回 true；走到 null 则返回 false。

正确性

循环依次访问且只访问 Object(obj) 的每一级原型。若目标原型存在，有限步内必然命中并返回真；若不存在，链最终到达 null 并返回假。因此结果与本题的原型链实例定义一致。

边界

  • null、undefined：不可装箱为可用实例，返回假。
  • 非函数目标：没有合法类语义，返回假。
  • 原始值：装箱后可命中 Number.prototype 等原型。
  • 构造函数自身：沿函数对象的链查找，通常不会命中自己的 prototype。

复杂度

设原型链高度为 h：时间复杂度 O(h)，额外空间复杂度 O(1)。

四语言代码

JavaScript · 官方可提交语言

直接实现题目要求；手动遍历可自然支持原始值装箱，并避免 instanceof 对原始值返回假的差异。

JavaScript
/**
 * @param {*} obj
 * @param {*} classFunction
 * @return {boolean}
 */
var checkIfInstanceOf = function(obj, classFunction) {
  if (obj == null || typeof classFunction !== "function") {
    return false;
  }

  let prototype = Object.getPrototypeOf(Object(obj));
  while (prototype !== null) {
    if (prototype === classFunction.prototype) return true;
    prototype = Object.getPrototypeOf(prototype);
  }
  return false;
};

Java · 本地语义参考

官方仅提供 JavaScript/TypeScript。Java 用运行时 Class.isInstance 表达相近语义；原始类型传入 Object 参数时由语言自动装箱。

Java · semantic reference
public class Solution {
  public static boolean checkIfInstanceOf(
      Object obj, Class<?> classFunction) {
    return obj != null
        && classFunction != null
        && classFunction.isInstance(obj);
  }
}

Python · 本地语义参考

Python 没有 JavaScript 原型链；这里用内建 isinstance 展示其本地类继承语义，并对非类目标返回假。

Python · semantic reference
def check_if_instance_of(obj, class_function):
    if not isinstance(class_function, type):
        return False
    return isinstance(obj, class_function)

C++ · 本地语义参考

C++ 无通用原型链反射。以下对多态类指针使用 dynamic_cast，仅表达运行时继承关系，不复刻 JavaScript 原始值装箱。

C++ · semantic reference
#include <type_traits>

template <class Target, class Source>
bool checkIfInstanceOf(Source* obj) {
  if (obj == nullptr) return false;
  if constexpr (std::is_polymorphic_v<Source>) {
    return dynamic_cast<Target*>(obj) != nullptr;
  }
  return std::is_same_v<Target, Source>;
}

替代方案

obj instanceof classFunction 写法很短，但原始数字 5 instanceof Number 为假，不符合示例 4；目标不可调用时还可能抛错。

也可读取 __proto__，但它是历史访问器；Object.getPrototypeOf 更明确。

常见错误

  • 只比较第一层原型，漏掉超类。
  • 没有先排除 null 与 undefined。
  • 直接使用 instanceof，导致原始值案例失败。
  • 比较构造函数名称；名称可重复、可修改，不代表继承关系。

面试追问

为什么从 Object.getPrototypeOf(Object(obj)) 开始，而不是从 Object(obj) 开始？

目标是匹配类的 prototype 对象；实例本身不是原型链节点，因此先取得它的直接原型。

为什么使用 obj == null，而不是 obj === null？

这里有意同时拦截 null 与 undefined。这是宽松相等少数清晰、受控的用途之一。

算法会不会无限循环？

正常 JavaScript 对象的原型链是有限且以 null 结束的；引擎也不允许创建原型环。
