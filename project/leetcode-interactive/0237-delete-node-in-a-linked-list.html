删除链表中的节点
Delete Node in a Linked List

没有头节点、也没有前驱？把后继的身份“搬”到当前节点，再绕开后继节点。

题意

给定单链表中待删除节点 node，但不能访问头节点。链表值互异且 node 保证不是尾节点。删除后，该值不再出现，节点数减一，node 前后其他值的相对顺序保持。

约束
节点数为 2 到 1000；节点值范围 −1000 到 1000；传入节点确实在链表中且不是尾节点。

官方样例（转述）

输入head = [4, 5, 1, 9], node = 5输出[4, 1, 9]
输入head = [4, 5, 1, 9], node = 1输出[4, 5, 9]

逐步可视化：复制后继，再跨过后继

演示 head = [4, 5, 1, 9], node = 5。橙色节点是传入的 node；绿色代表它已接管后继的值。

题解：让当前节点伪装成后继

因为拿不到前驱，不能执行常规的 prev.next = node.next。但 node 不是尾节点，所以它必有 node.next：将后继值复制给 node，再令 node.next = node.next.next。链表观察到的值序列恰好少了原 node 的值。

  1. node.val = node.next.val：当前位置展示后继值。
  2. node.next = node.next.next：从链上跳过原后继节点。
注意：题目所谓“删除”是链表语义，而非立刻从内存释放对象。被跳过的后继节点可能仍由局部引用指向。

完整过程

4 → 5 → 1 → 9 中，传入值为 5 的节点。先将其值改为 1，短暂显示 4 → 1 → 1 → 9；再令它 next 指向 9，最终为 4 → 1 → 9。

边界与复杂度

目标是倒数第二个节点同样适用。尾节点没有后继，无法使用此技巧，这也是题目明确保证 node 非尾节点的原因。时间 O(1)，额外空间 O(1)。

替代方案与取舍

若给了 head，常规遍历找前驱后断链更直观，且可以删除尾节点，但时间 O(n)。本题刻意不给 head，考查对链表身份与值的区分。

面试追问

若节点持有不能复制的资源或身份字段，这种方法可能不满足业务语义；应改 API 传入前驱或头节点。双链表则可以直接用 prev 指针断开。

常见错误

  • 只写 node = node.next：仅改变局部变量，不会修改原链。
  • 只复制值却不跳过后继，造成重复值且长度不变。
  • 尝试处理尾节点，访问 node.next.val 会失败。
