统计好子数组的数目

Count the Number of Good Subarrays

连续的一段数字中，能找到多少对相等的元素？先理解“好”，再探索如何统计。

打开官方题目 ↗

01 / 题目

给定整数数组 nums 和整数 k，统计其中所有“好子数组”的数量。子数组必须是原数组中连续且非空的一段。

如果某段子数组内，满足 i < j 且 arr[i] == arr[j] 的下标对至少有 k 个，这段子数组就是“好”的。统计的是下标对，同一个元素可以参与多个不同的数对。

例如 [7,7,7] 共有 3 对：(0,1)、(0,2)、(1,2)，不是只有 1 对或 2 对。

参数与返回值

countGood(nums, k) → 返回好子数组的总数（可能超过 32 位整数）。

约束

  • 1 ≤ nums.length ≤ 10⁵
  • 1 ≤ nums[i], k ≤ 10⁹

02 / 官方示例

示例 1

输入：nums = [1,1,1,1,1], k = 10
输出：1

只有整个数组达标，5 个相同数字构成 10 个下标对。

示例 2

输入：nums = [3,1,4,3,2,2,4], k = 2
输出：4

04 / 题解 · 数对驱动的滑动窗口

核心洞察

一个值出现 c 次，会贡献 c(c−1)/2 对。新加入同值元素时，新增 c 对；移除一个时，减少的是移除后的频次。

维护窗口 [left, right]、频次表 freq 和数对总数 pairs。一旦 pairs ≥ k，所有以 left 为起点、终点在 right…n−1 的子数组都有效，一次累加 n−right，随后移除左端元素，继续尝试。

完整过程

  1. 初始化 left = 0, pairs = 0, answer = 0 和空频次表。
  2. 每次右移 right：先让 pairs += freq[x]，再令 freq[x]++。
  3. 当窗口达标时，累加 n−right。这同时统计了保持起点、将终点向右扩展的所有情况。
  4. 令左端元素频次减一，再从 pairs 减去它的新频次，最后 left++。重复直到窗口不再达标。
  5. 继续扩展右端，遍历结束后返回答案。

示例 2 中，右端到 5 时为起点 0 贡献 2 段；右端到 6 时，起点 1 和 2 各贡献 1 段，共 4 段。

正确性

数对不变量：加入值 x 时，它与窗口内每个 x 各形成一个新数对；移除 x 时，恰好删除它与剩余 x 的所有数对。因此频次表和 pairs 始终准确描述当前窗口。

单调性：向右添加元素不会减少数对，所以窗口达标后，所有更靠右的终点也达标。收缩左端不会增加数对。

不重不漏：处理一个起点 left 时，当前 right 是它首次达标的最早终点。此前各右端下该起点未被移除，说明此前均未达标；如果刚移除较早起点才轮到它，较早起点在先前右端都不达标，其内部的更短窗口也不可能达标。因此它恰有 n−right 个合法终点，一次统计后永久移除该起点，不会重复。未被移除的起点直到结尾仍未达标，贡献为 0。

边界与复杂度

  • 长度 1 或全不重复：数对为 0，答案为 0。
  • k 大于全数组的数对数：没有合法子数组，答案为 0。
  • 所有值相同：频次组合数增长很快，必须使用 while 连续收缩。
  • n ≤ 10⁵ 时，数对与答案均可能超过 32 位。Java 用 long，C++ 用 long long；Python 整数和 JavaScript Number（本题量级小于 2⁵³）可安全表示。
  • 哈希表操作平均 O(1)，双指针各移动至多 n 次：期望时间 O(n)，空间 O(n)。演示为展示全部数对而额外枚举，不代表提交算法的复杂度。

替代方案

固定右端，持续收缩到 pairs < k 后，将 left 加入答案：起点 0…left−1 恰好合法，复杂度同为 O(n)。也可以枚举每个起点并扩展终点，频次增量统计为 O(n²)，只适合小数据理解。不要把两种滑动窗口的计数公式混用。

常见错误

  • 把“至少 k 对”写成“恰好 k 对”。
  • 把值的种类数、重复元素数误当成下标对数。
  • 加入时先增频次，导致多算自己与自己的配对。
  • 移除时减去旧频次，导致多减 1。
  • 一次达标只加 1，漏掉所有右侧扩展。
  • 只用 if 收缩一次，漏掉同一右端对应的其他起点。

面试追问

恰好 k 对怎么做？利用 atLeast(k) − atLeast(k+1)；本题 k ≥ 1，若泛化到 k = 0，atLeast(0) 应直接返回 n(n+1)/2，避免空窗口继续收缩。

能改用定长数组记录频次吗？值域达到 10⁹，直接开数组不合适；哈希表最直接，离散化可行但通常增加排序成本。

为什么不能排序？排序改变原数组的连续关系，会改变哪些片段是子数组。

Java

import java.util.HashMap;
import java.util.Map;

class Solution {
    public long countGood(int[] nums, int k) {
        Map<Integer, Integer> freq = new HashMap<>();
        long pairs = 0, answer = 0;
        int left = 0;
        for (int right = 0; right < nums.length; right++) {
            int x = nums[right];
            int count = freq.getOrDefault(x, 0);
            pairs += count;
            freq.put(x, count + 1);
            while (pairs >= k) {
                answer += nums.length - right;
                int y = nums[left++];
                int remaining = freq.get(y) - 1;
                freq.put(y, remaining);
                pairs -= remaining;
            }
        }
        return answer;
    }
}

from typing import List
from collections import defaultdict

class Solution:
    def countGood(self, nums: List[int], k: int) -> int:
        freq = defaultdict(int)
        left = pairs = answer = 0
        for right, x in enumerate(nums):
            pairs += freq[x]
            freq[x] += 1
            while pairs >= k:
                answer += len(nums) - right
                y = nums[left]
                freq[y] -= 1
                pairs -= freq[y]
                left += 1
        return answer

C++

#include <vector>
#include <unordered_map>
using namespace std;

class Solution {
public:
    long long countGood(vector<int>& nums, int k) {
        unordered_map<int, int> freq;
        long long pairs = 0, answer = 0;
        int left = 0, n = static_cast<int>(nums.size());
        for (int right = 0; right < n; ++right) {
            int x = nums[right];
            pairs += freq[x];
            ++freq[x];
            while (pairs >= k) {
                answer += n - right;
                int y = nums[left++];
                --freq[y];
                pairs -= freq[y];
            }
        }
        return answer;
    }
};
