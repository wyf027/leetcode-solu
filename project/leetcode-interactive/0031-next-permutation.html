    Core insight

    核心洞察：最小幅度升高

    从右往左的非递增后缀已经是该前缀下的最大排列。要得到下一个排列，必须提升它左边的支点；选后缀中刚好大于支点的最小值交换，再把后缀变为最小升序。

    Why reverse?

    为什么反转就等于排序？

    找到支点时，右侧原本非递增；与从右侧找到的后继交换后，右侧仍保持非递增。双指针反转即可得到升序，无需调用排序。

    Three checkpoints

    完整解题过程

    1. 1 · PIVOT

      找最右支点

      从 n−2 左移，找首个 nums[i] < nums[i+1]。

    2. 2 · SUCCESSOR

      找刚好更大

      从末尾找首个 nums[j] > nums[i] 并交换。

    3. 3 · REVERSE

      尾部降到最低

      双指针反转 [i+1, n−1]；无支点时反转整个数组。

    边界情况

    • • 长度 1：反转自身，保持不变。
    • • 完全非递增：不存在更大排列，整体反转。
    • • 重复数字：支点条件必须严格小于。
    • • 后继必须严格大于支点。
    • • 原地修改，不返回新数组。

    复杂度

    Time
    O(n)
    Space
    O(1)

    三段扫描总计线性；交换与反转都原地完成。

    替代方案取舍

    • 生成全部排列：O(n! · n)，完全不可取。
    • 后缀排序：O(n log n)，正确但浪费“后缀已非递增”的结构。
    • 主线贪心：O(n)/O(1)，面试最推荐。

    面试高频追问

    Q：为什么后继从最右侧找？
    A：后缀非递增，最右侧第一个大于支点的值，就是可用值中最小的。
    Q：如何证明没有跳过排列？
    A：提升的是最右可提升位，且提升幅度最小；之后尾部取最小排列，因此得到严格更大中的最小者。
    Q：能否用标准库排序？
    A：能得到正确结果但为 O(n log n)，面试应利用单调后缀反转到 O(n)。

    常见错误

    • ✗ 支点用 <=，重复元素时选错位置。
    • ✗ 从左侧找第一个更大元素，增幅可能过大。
    • ✗ 交换后忘记反转后缀。
    • ✗ 无支点时直接返回，没有改为最小排列。
    • ✗ 额外创建排序数组，违反 O(1) 空间要求。

    class Solution {
    public void nextPermutation(int[] nums) {
        int pivot = nums.length - 2;
        while (pivot >= 0 && nums[pivot] >= nums[pivot + 1]) {
            pivot--;
        }

        if (pivot >= 0) {
            int successor = nums.length - 1;
            while (nums[successor] <= nums[pivot]) {
                successor--;
            }
            swap(nums, pivot, successor);
        }

        reverse(nums, pivot + 1, nums.length - 1);
    }

    private void reverse(int[] nums, int left, int right) {
        while (left < right) {
            swap(nums, left++, right--);
        }
    }

    private void swap(int[] nums, int i, int j) {
        int temp = nums[i];
        nums[i] = nums[j];
        nums[j] = temp;
    }
}
