04 / SOLUTION

格雷码，再异或起点

内容导航 核心洞察完整过程正确性证明边界与复杂度四语言代码替代方案面试追问常见错误

核心洞察

标准 n 位格雷码天然是一条首尾相接的“一位变化”环。 把环上每个值都与 start 做异或，既能让第一项变成 start，又不会改变任意两项之间哪些二进制位不同。
gray(i) = i ^ (i >> 1)
answer[i] = gray(i) ^ start

完整过程

  1. 枚举 i = 0 ... 2n-1。
  2. 用 i ^ (i >> 1) 得到第 i 个 n 位格雷码。
  3. 再与 start 异或，把整条格雷码环统一“平移”到以 start 开头。
  4. 按枚举顺序加入答案。因为格雷码首尾也只差一位，结果自动满足闭环条件。

以 n = 3, start = 2 (010) 为例，标准格雷码前几项为 000, 001, 011, 010...；统一异或 010 后得到 010, 011, 001, 000...，十进制即 2, 3, 1, 0...。

正确性证明

  1. 起点正确：gray(0) = 0，所以 answer[0] = 0 ^ start = start。
  2. 没有重复且没有遗漏：标准格雷码是 [0, 2n-1] 的一个排列；与固定值异或是双射，因此转换后的序列仍是这个区间的排列。
  3. 相邻只差一位：相邻标准格雷码的异或值只有一个二进制位为 1。对两项同时异或 start，二者的异或差不变。
  4. 首尾闭合：反射格雷码的最后一项为最高位为 1、其余位为 0 的数，它与第一项 0 只差最高位；统一异或后，这个关系仍保持。

四点合并，所得序列满足题目全部条件。

边界与复杂度

n = 1只有 0 和 1。无论起点是哪一个，另一个数紧随其后即可闭环。
start = 0与 0 异或不改变值，答案就是标准格雷码序列。
n = 16答案固定包含 65,536 项；输出本身决定了线性时间和线性空间。
复杂度时间 O(2n)，返回数组空间 O(2n)；除答案外额外空间 O(1)。

class Solution {
    public List<Integer> circularPermutation(int n, int start) {
        int size = 1 << n;
        List<Integer> answer = new ArrayList<>(size);

        for (int i = 0; i < size; i++) {
            int gray = i ^ (i >> 1);
            answer.add(gray ^ start);
        }
        return answer;
    }
}

替代方案

旋转标准格雷码：先生成格雷码，找到值为 start 的位置，再从该位置循环读取。它同样正确，但需要查找或额外的下标换算；直接统一异或更短。

回溯搜索：从 start 出发，每次尝试翻转一个未访问值对应的位，直到覆盖全部数且能回到起点。虽然能表达图上的哈密顿环搜索，但状态规模为 2n，远不如格雷码构造稳定高效。

面试追问

  • 为什么异或固定值不会破坏相邻关系？
    因为 (a ^ start) ^ (b ^ start) = a ^ b，相同的掩码被抵消。
  • 能否只返回第 k 项，而不生成整个数组？
    可以，直接计算 (k ^ (k >> 1)) ^ start，时间和额外空间都是 O(1)。
  • 如何判断两个数是否只差一位？
    令 x = a ^ b，检查 x != 0 && (x & (x - 1)) == 0。
  • 若要求字典序最小怎么办？
    当前构造只保证任意合法答案；字典序目标会改变选择策略，需要进一步分析环的等价变换或搜索。

常见错误

  • 只检查相邻项，忘记首尾。题目要求的是环，不是普通路径。
  • 把 start 加到每个格雷码上。普通加法可能产生进位并改变多位；这里需要异或。
  • 生成后把 start 直接换到数组首位。交换一个元素会破坏它两侧的邻接关系；应旋转整条环或整体异或。
  • 写成 i ^ i >> 1 而忽略可读性。不同语言的优先级容易令人误判，明确写成 i ^ (i >> 1)。
