链表组件Linked List Components

沿着链表的唯一方向前进，观察被 nums 选中的节点如何聚成一段又一段。先理解“连续”和“最长”的含义，再进入交互实验。

中等 链表 哈希表 数组 非付费题

30 秒读题

给定一个值互不相同的单链表，以及由部分链表值组成的数组 nums。请统计：这些被选中的节点在原链表中形成了多少段互不相连的最大连续区间。

只看输入输出，暂不看题解 head = [0,1,2,3] nums = [0,1,3] 输出 = 2

Problem

题意与官方示例

组件必须非空、在链表上连续，并且是不能再向两边扩展的最大序列。

准确转述

链表 head 中每个节点的整数值都唯一。数组 nums 中的值也都唯一，且一定来自该链表。若链表中一段相邻节点的值全部属于 nums，并且这段序列已经无法继续向前或向后扩展，它就是一个连通组件。返回组件总数。

约束

  • 链表节点数为 n，1 ≤ n ≤ 10⁴。
  • 0 ≤ Node.val < n，所有节点值互不相同。
  • 1 ≤ nums.length ≤ n。
  • 0 ≤ nums[i] < n，nums 中所有值互不相同。
  • nums 是链表节点值集合的子集。

示例 1

输入：head = [0,1,2,3], nums = [0,1,3]
输出：2

0 → 1 连在一起；2 未被选择，因此 [0,1] 与 [3] 是两个组件。

示例 2

输入：head = [0,1,2,3,4], nums = [0,3,1,4]
输出：2

按链表顺序看，被选中的是连续的 [0,1] 和连续的 [3,4]，共两个组件；nums 自身的排列顺序不影响答案。

无论一段包含一个节点还是很多节点，都只能为答案贡献一次。

Solution

把每个组件的末端数出来

使用哈希集合快速判断当前值和下一个值是否属于 nums。

核心洞察与完整过程

一个组件只拥有一个末端节点。因此，与其维护整段组件，不如在遍历链表时判断“当前节点是不是某个组件的末端”。

current ∈ nums 且（next 为空 或 next ∉ nums）→ 答案 + 1
  1. 把 nums 的全部值放入哈希集合。
  2. 从头到尾遍历链表。
  3. 当前值在集合中，并且下一个节点不存在或其值不在集合中，就确认一个组件结束。
  4. 遍历结束后返回计数。

正确性证明

引理：每个组件恰好有一个节点满足“自身被选中，下一节点未被选中或不存在”。因为组件是链表上一段最大连续的被选节点序列，它的最后一个节点满足该条件；段内其他节点的下一节点仍被选中，不满足条件。

完备性：算法会遍历每个节点，因此不会漏掉任何组件的最后一个节点。

唯一性：算法只在组件最后一个节点计数一次，同一组件不会重复计数；不属于任何组件的节点也不会被计数。因此最终计数恰好等于组件数。

边界情况

  • nums 只含一个节点：它自身构成一个组件。
  • 所有链表节点都被选中：整条链表只有一个组件。
  • 被选节点两两不相邻：每个节点各自构成一个组件。
  • 组件延伸到链表尾部：next == null 必须触发计数。
  • nums 顺序被打乱：哈希集合不依赖数组顺序。

复杂度

设链表节点数为 n，nums 长度为 m。建集合需要 O(m)，遍历需要 O(n)；总时间为 O(n + m)，额外空间为 O(m)。

替代方案：数每段的起点

也可以维护布尔值 previousSelected。当当前节点被选中且前一节点未被选中时，说明进入了一个新组件，于是计数。该方案时间、空间复杂度相同。

末端计数法更直接地利用 current.next，无需额外状态；起点计数法则适用于流式扫描或更容易表达“状态切换”的场景。两者都不应先将链表值过滤成数组，因为过滤会丢失未选节点所代表的断点。

常见错误

  • 按 nums 的数组顺序判断相邻，而不是按链表顺序。
  • 只判断相邻数值之差为 1；链表相邻与数值连续不是一回事。
  • 只统计被选节点数量，没有把连续节点合并为一个组件。
  • 漏掉以链表尾节点结束的组件。

/**
 * Definition for singly-linked list.
 * public class ListNode {
 *     int val;
 *     ListNode next;
 *     ListNode() {}
 *     ListNode(int val) { this.val = val; }
 *     ListNode(int val, ListNode next) { this.val = val; this.next = next; }
 * }
 */
class Solution {
    public int numComponents(ListNode head, int[] nums) {
        Set<Integer> selected = new HashSet<>();
        for (int value : nums) {
            selected.add(value);
        }

        int components = 0;
        for (ListNode current = head; current != null; current = current.next) {
            if (selected.contains(current.val)
                    && (current.next == null || !selected.contains(current.next.val))) {
                components++;
            }
        }
        return components;
    }
}

 *     this.next = (next === undefined ? null : next);
 * }

/**
 * @param {ListNode} head
 * @param {number[]} nums
 * @return {number}
 */
var numComponents = function(head, nums) {
    const selected = new Set(nums);
    let components = 0;

    for (let current = head; current !== null; current = current.next) {
        if (selected.has(current.val)
            && (current.next === null || !selected.has(current.next.val))) {
            components++;
        }
    }
    return components;
};

class Solution:
    def numComponents(self, head: Optional[ListNode], nums: List[int]) -> int:
        selected = set(nums)
        components = 0
        current = head

        while current is not None:
            if (current.val in selected
                    and (current.next is None or current.next.val not in selected)):
                components += 1
            current = current.next

        return components
/**
 * Definition for singly-linked list.
 * struct ListNode {
 *     int val;
 *     ListNode *next;
 *     ListNode() : val(0), next(nullptr) {}
 *     ListNode(int x) : val(x), next(nullptr) {}
 *     ListNode(int x, ListNode *next) : val(x), next(next) {}
 * };
 */
class Solution {
public:
    int numComponents(ListNode* head, vector<int>& nums) {
        unordered_set<int> selected(nums.begin(), nums.end());
        int components = 0;

        for (ListNode* current = head; current != nullptr; current = current->next) {
            if (selected.count(current->val)
                && (current->next == nullptr
                    || !selected.count(current->next->val))) {
                ++components;
            }
        }
        return components;
    }

面试追问

为什么不用并查集？

本题的图结构已经退化成一条单链表，组件只能是连续区间。一次线性扫描就能识别边界，并查集会增加实现和空间成本。

如果节点值不唯一，算法还成立吗？

若 nums 仍按“值”选择节点，那么集合判断依然可用；所有相同值的节点都会一起被选中。但若题意改为选择具体节点身份，就必须改用节点引用或唯一 ID。

如果不能使用额外哈希空间呢？

利用本题 0 ≤ Node.val < n 的范围，可原地排序 nums 后二分查找，使额外空间降至排序实现所需空间，但时间会变为 O((n+m) log m)；也可用位图，以更紧凑的常数空间换取仍为 O(n+m) 的时间。

为什么“过滤出选中节点再比较”可能错？

过滤会移除未选节点，而这些节点恰恰是组件之间的断点。例如链表 0→1→2、nums=[0,2]，过滤后看似相邻，实际却是两个组件。
