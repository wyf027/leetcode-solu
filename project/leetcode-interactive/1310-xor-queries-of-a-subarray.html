子数组异或查询

面对最多 30,000 次区间询问，如何让每次回答不再重复扫描？先理解任务，再进入实验室寻找区间与“前面那一段”的关系。

任务给定正整数数组 arr 与查询 [left, right]，返回每段闭区间内所有元素的异或结果。

Problem

题目说明

对每个 queries[i] = [Lᵢ, Rᵢ]，计算 arr[Lᵢ] XOR arr[Lᵢ+1] XOR … XOR arr[Rᵢ]。按照查询原有顺序，返回全部结果组成的数组。

示例 1

输入：arr = [1,3,4,8],
      queries = [[0,1],[1,2],[0,3],[3,3]]
输出：[2,7,14,8]
解释：[0,1] → 1 XOR 3 = 2
      [1,2] → 3 XOR 4 = 7
      [0,3] → 1 XOR 3 XOR 4 XOR 8 = 14
      [3,3] → 8

示例 2

输入：arr = [4,8,2,10],
      queries = [[2,3],[1,3],[0,0],[0,3]]
输出：[8,0,4,4]

约束

  • 1 ≤ arr.length ≤ 3 × 10⁴
  • 1 ≤ arr[i] ≤ 10⁹
  • 1 ≤ queries.length ≤ 3 × 10⁴
  • queries[i].length == 2
  • 0 ≤ queries[i][0] ≤ queries[i][1] < arr.length

Solution

前缀异或：让重复区间成对消失

核心洞察

异或满足结合律，并且 x XOR x = 0、0 XOR y = y。因此，若先记录每个位置之前所有元素的异或值，就能用两次查表回答任意区间。

prefix[0] = 0 prefix[i + 1] = prefix[i] XOR arr[i] XOR(L…R) = prefix[R + 1] XOR prefix[L]

完整过程

  1. 创建长度为 n + 1 的 prefix，令 prefix[0] = 0。
  2. 依次计算 prefix[i + 1] = prefix[i] XOR arr[i]。
  3. 对每个查询 [L, R]，写入 prefix[R + 1] XOR prefix[L]。
  4. 按查询顺序返回结果数组。

正确性证明

前缀含义

prefix[k] 等于 arr[0]…arr[k-1] 的异或，递推定义直接保证这一点。

公共部分消去

prefix[R+1] 与 prefix[L] 都含有 arr[0]…arr[L-1]；两者再次异或时，相同元素各出现两次，全部变成 0。

只剩目标区间

消去公共前缀后，仅余 arr[L]…arr[R]，恰是该查询需要的值。逐条查询成立，返回数组也正确。

边界与复杂度

边界

当 L = 0 时使用哨兵 prefix[0]；当 L = R 时公共前缀仍会正确消去；相同数值相邻不会影响推导。

复杂度

设数组长度为 n、查询数为 q。预处理 O(n)，回答 O(q)，总时间 O(n + q)；前缀数组空间 O(n)，结果数组不计或为 O(q)。

四语言完整代码

class Solution {
    public int[] xorQueries(int[] arr, int[][] queries) {
        int[] prefix = new int[arr.length + 1];
        for (int i = 0; i < arr.length; i++) {
            prefix[i + 1] = prefix[i] ^ arr[i];
        }
        int[] answer = new int[queries.length];
        for (int i = 0; i < queries.length; i++) {
            int left = queries[i][0], right = queries[i][1];
            answer[i] = prefix[right + 1] ^ prefix[left];
        }
        return answer;
    }
}
/**
 * @param {number[]} arr
 * @param {number[][]} queries
 * @return {number[]}
 */
var xorQueries = function(arr, queries) {
    const prefix = new Array(arr.length + 1).fill(0);
    for (let i = 0; i < arr.length; i++) {
        prefix[i + 1] = prefix[i] ^ arr[i];
    }
    return queries.map(([left, right]) =>
        prefix[right + 1] ^ prefix[left]
    );
};
from typing import List

class Solution:
    def xorQueries(
        self, arr: List[int], queries: List[List[int]]
    ) -> List[int]:
        prefix = [0] * (len(arr) + 1)
        for i, value in enumerate(arr):
            prefix[i + 1] = prefix[i] ^ value
        return [
            prefix[right + 1] ^ prefix[left]
            for left, right in queries
        ]
class Solution {
public:
    vector<int> xorQueries(
        vector<int>& arr,
        vector<vector<int>>& queries
    ) {
        vector<int> prefix(arr.size() + 1, 0);
        for (int i = 0; i < (int)arr.size(); ++i) {
            prefix[i + 1] = prefix[i] ^ arr[i];
        }
        vector<int> answer;
        answer.reserve(queries.size());
        for (const auto& query : queries) {
            answer.push_back(prefix[query[1] + 1] ^ prefix[query[0]]);
        }
        return answer;
    }
};

替代方案

逐查询扫描

每次遍历区间，实现直接但最坏 O(nq)，在 3 × 10⁴ 规模下不可取。

线段树

可在 O(log n) 回答并支持单点更新，但本题数组不更新，结构与常数开销都没有必要。

面试追问

如果查询期间会修改 arr 呢？

前缀数组会整体失效。可改用维护区间异或的线段树；单点更新与区间查询都是 O(log n)。

为什么不能用普通前缀和的减法？

因为这里的聚合运算是 XOR。对应的“逆操作”仍是 XOR，而不是算术减法。

JavaScript 位运算有何注意点？

JavaScript 位运算按 32 位有符号整数执行。本题元素小于 10⁹，异或结果适用于题目约束。

常见错误

  • 把答案写成 prefix[R] XOR prefix[L]，产生右端点偏移错误。
  • 前缀数组只开 n 个位置，使 R = n - 1 时无法访问 prefix[n]。
  • 忘记 prefix[0] = 0，从而对 L = 0 增加特殊分支。
  • 对每条查询重新遍历区间，无法利用大量查询共享的重复工作。
