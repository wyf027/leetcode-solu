Problem

题意与输入输出

两种瓷砖均可旋转。每个方格都必须被覆盖，瓷砖之间不能重叠，也不能伸出面板。

准确转述

给定整数 n，计算铺满一块 2 × n 面板的方案数。可使用 2 × 1 多米诺，以及占据三个格子的 L 形托米诺；两者都允许旋转。

若存在一对上下或左右相邻的格子，在一种铺法中属于同一块瓷砖、而在另一种铺法中不属于同一块瓷砖，则这两种铺法不同。

函数参数形式
numTilings(n: integer) -> integer

由于方案数可能很大，返回结果对 1,000,000,007 取模。

约束
  • 1 <= n <= 1000

Solution

状态压缩动态规划

困难之处不在于“最后放哪块砖”，而在于 L 形托米诺可能留下一个延迟到后续列才能补齐的角。只记录完整面板会丢失这类必要信息。

核心洞察

令 F[i] 为完整铺满 2 × i 面板的方案数；令 G[i] 为铺到第 i 列、只缺右上角这一指定格的方案数。缺右下角的数量因上下对称与 G[i] 相同，所以不必再开一组数组。

F[i] = F[i-1] + F[i-2] + 2 × G[i-1]
G[i] = G[i-1] + F[i-2]

完整过程

  1. 初始化空面板：F[0] = 1、G[0] = 0；一列面板有 F[1] = 1、G[1] = 0。
  2. 构造 F[i]：在 F[i-1] 后竖放一块多米诺；或在 F[i-2] 后横放两块多米诺；或用一块托米诺补掉两种镜像缺口，贡献 2 × G[i-1]。
  3. 构造指定缺口 G[i]：旧缺口向右延伸一列，贡献 G[i-1]；或从 F[i-2] 放一块托米诺新造出指定缺口。
  4. 每一步对 10^9 + 7 取模，最终返回 F[n]。

正确性证明

引理 1：所有得到完整状态 F[i] 的铺法，按最右侧结构可唯一分成三类：末列为竖多米诺、末两列由两块横多米诺封口、或由一块托米诺补齐此前的上/下缺口。三类互斥，且覆盖所有可能，因此第一条转移既不遗漏也不重复。

引理 2：所有得到指定缺口 G[i] 的铺法，最右侧要么由横多米诺延续同向缺口，要么由一块托米诺从完整的 F[i-2] 新建缺口。两类互斥且完备，因此第二条转移正确。

归纳：基准 i = 0, 1 显然成立。假设更小下标的状态计数正确，根据两个引理，转移精确计数第 i 列的全部状态。因此对所有 i ≤ n 都正确，算法返回的 F[n] 就是所求方案数。

边界与复杂度

  • n = 1 直接落在初始化范围，答案为 1。
  • 空面板的 1 种铺法是递推单位元，并不是题目输入用例。
  • 每次只依赖前两列，可把数组滚动为常数个变量。
  • 时间复杂度 O(n)，空间复杂度 O(1)。

四种语言完整代码

class Solution {
    public int numTilings(int n) {
        final long MOD = 1_000_000_007L;
        if (n == 1) return 1;

        long fullPrev2 = 1; // F[0]
        long fullPrev1 = 1; // F[1]
        long gapPrev1 = 0;  // G[1]

        for (int i = 2; i <= n; i++) {
            long full = (fullPrev1 + fullPrev2
                    + 2L * gapPrev1) % MOD;
            long gap = (gapPrev1 + fullPrev2) % MOD;

            fullPrev2 = fullPrev1;
            fullPrev1 = full;
            gapPrev1 = gap;
        }
        return (int) fullPrev1;
    }
}

替代方案

消去 G 后可得到一维递推 F[i] = 2 × F[i-1] + F[i-3]。代码更短，但从零推导较不直观，也更难解释为何没有漏掉 L 形瓷砖。另一个通用方案是用两位掩码表示列缺口并做轮廓线 DP；它适合扩展到更多瓷砖形状，但对本题显得偏重。

面试追问

  • 为什么只需要记录一种缺角方向？如果面板不是上下对称，还能合并吗？
  • 如何从两状态递推严格推导出 F[i] = 2F[i-1] + F[i-3]？
  • 当 n 扩大到 10^18 时，如何用矩阵快速幂把复杂度降为 O(log n)？
  • 新增一种瓷砖后，怎样系统地枚举轮廓状态与合法转移？

常见错误

只写斐波那契式转移：忽略托米诺制造并延续的缺口状态。
忘记乘 2：右上缺口和右下缺口是镜像的两组铺法。
基准状态混乱：F[0] = 1 是递推需要的空铺法，G[0] = 0。
溢出后再取模：Java/C++ 应使用 64 位整数承接加法与乘 2。
原地覆盖过早：滚动变量更新前要先算完当前 full 与 gap。
