困难Best Position for a Service Centre非付费题
01 / 题目

为所有客户找到最短的总路程

给定二维数组 positions，其中 positions[i] = [xᵢ, yᵢ] 表示第 i 位客户的位置。你可以把服务中心放在平面上的任意实数坐标 [x, y]，请返回服务中心到所有客户的欧几里得距离之和的最小值。

换句话说，需要最小化：

F(x, y) = Σᵢ √((x − xᵢ)² + (y − yᵢ)²)

返回值与真实最小值的误差不超过 10⁻⁵ 即可接受。

示例 1 · 对称十字

输入
positions = [[0,1],[1,0],[1,2],[2,1]]
输出
4.00000

选择 [1,1]，到四位客户的距离都为 1，总和为 4，且无法更小。

示例 2 · 两个端点

输入
positions = [[1,1],[3,3]]
输出
2.82843

线段上任一点都能取得最小值，距离和为 2√2 ≈ 2.82843。

约束

  • 1 ≤ positions.length ≤ 50
  • positions[i].length == 2
  • 0 ≤ xᵢ, yᵢ ≤ 100

03 / 题解

准备好揭开地形背后的算法了吗？

题解默认收起。展开后包含证明、复杂度、四种语言的完整代码与面试追问。

核心洞察：凸函数可以逐维三分

每个距离项都是凸函数，它们的和 F(x,y) 仍然凸。固定 x 后，F(x,y) 关于 y 是单谷的；先用三分搜索求这个 x 下的最优 y，即可得到 g(x)=minᵧF(x,y)。

对凸函数做部分最小化后，g(x) 仍然凸，因此再对 x 做一次三分搜索即可。

完整过程

  1. 用客户坐标的最小值和最大值建立 x、y 搜索范围。
  2. 给定一个 x，在 y 范围内重复三分，比较两个纵向候选的距离和。
  3. 将内层搜索返回的最小距离记为 g(x)。
  4. 外层对 x 重复同样的三分过程。
  5. 固定迭代 80 次，返回最终中点对应的距离和。

边界与数值处理

  • 只有一个客户时，中心放在该点，答案为 0。
  • 所有点共线或重合时，最优位置可能不唯一，但最小距离和唯一。
  • 比较浮点数时不判断坐标是否“恰好相等”；固定次数迭代可稳定控制精度。
  • 搜索范围取客户坐标包围盒即可；凸函数的最优点不会需要跑到包围盒外。

复杂度

设客户数为 n，每层三分迭代 K=80 次。时间复杂度为 O(nK²)；因为 K 是固定常数，也常写作 O(n)。额外空间复杂度为 O(1)（不计输入）。

若按精度表达，则约为 O(n · log²(R/ε))。

正确性说明

引理 1：单点距离 √((x−xᵢ)²+(y−yᵢ)²) 是凸函数；有限个凸函数相加仍然凸，所以目标函数 F 在整个平面上凸。

引理 2：固定任意 x，函数 F(x,·) 凸且单谷。内层三分每次比较两个三等分点：较大值一侧不可能包含唯一更优区间，因此保留另一侧不会丢失最小值。反复收缩后得到该 x 下的最优距离。

引理 3：g(x)=minᵧF(x,y) 是联合凸函数 F 对 y 做部分最小化的结果，因此仍然凸。外层三分同理由始终保留 g 的最小值所在区间。

结论：两层区间长度都按固定比例趋近于 0；最终中点对应的距离和趋近全局最小值。80 次迭代的误差远小于题目允许的 10⁻⁵。

LeetCode 官方签名：double getMinDistSum(int[][] positions)
class Solution {
    private double distanceSum(int[][] positions, double x, double y) {
        double sum = 0.0;
        for (int[] p : positions) {
            sum += Math.hypot(x - p[0], y - p[1]);
        }
        return sum;
    }

    private double bestAtX(int[][] positions, double x,
                           double minY, double maxY) {
        double left = minY, right = maxY;
        for (int iteration = 0; iteration < 80; iteration++) {
            double y1 = left + (right - left) / 3.0;
            double y2 = right - (right - left) / 3.0;
            if (distanceSum(positions, x, y1)
                    < distanceSum(positions, x, y2)) {
                right = y2;
            } else {
                left = y1;
            }
        }
        return distanceSum(positions, x, (left + right) / 2.0);
    }

    public double getMinDistSum(int[][] positions) {
        double minX = positions[0][0], maxX = positions[0][0];
        double minY = positions[0][1], maxY = positions[0][1];
        for (int[] p : positions) {
            minX = Math.min(minX, p[0]);
            maxX = Math.max(maxX, p[0]);
            minY = Math.min(minY, p[1]);
            maxY = Math.max(maxY, p[1]);
        }

        double left = minX, right = maxX;
        for (int iteration = 0; iteration < 80; iteration++) {
            double x1 = left + (right - left) / 3.0;
            double x2 = right - (right - left) / 3.0;
            if (bestAtX(positions, x1, minY, maxY)
                    < bestAtX(positions, x2, minY, maxY)) {
                right = x2;
            } else {
                left = x1;
            }
        }
        return bestAtX(positions, (left + right) / 2.0, minY, maxY);
    }
}

LeetCode 官方签名：getMinDistSum(self, positions)
from typing import List
from math import hypot

class Solution:
    def getMinDistSum(self, positions: List[List[int]]) -> float:
        def distance_sum(x: float, y: float) -> float:
            return sum(hypot(x - px, y - py) for px, py in positions)

        min_x = min(x for x, _ in positions)
        max_x = max(x for x, _ in positions)
        min_y = min(y for _, y in positions)
        max_y = max(y for _, y in positions)

        def best_at_x(x: float) -> float:
            low, high = min_y, max_y
            for _ in range(80):
                y1 = low + (high - low) / 3.0
                y2 = high - (high - low) / 3.0
                if distance_sum(x, y1) < distance_sum(x, y2):
                    high = y2
                else:
                    low = y1
            return distance_sum(x, (low + high) / 2.0)

        left, right = min_x, max_x
        for _ in range(80):
            x1 = left + (right - left) / 3.0
            x2 = right - (right - left) / 3.0
            if best_at_x(x1) < best_at_x(x2):
                right = x2
            else:
                left = x1

        return best_at_x((left + right) / 2.0)

替代方案

Weiszfeld 算法：直接迭代几何中位数，通常收敛很快，时间近似 O(nK)；但迭代点恰好落在客户点上时会出现除零，需要专门处理。

模拟退火 / 步长爬山：实现直观，适合交互演示；不过精度和收敛证明不如凸优化下的三分搜索规整。

常见错误

  • 把横坐标、纵坐标分别取中位数——这只对曼哈顿距离成立。
  • 只在整数坐标中搜索——真正最优点可能是小数。
  • 内层三分没有针对每个外层候选重新计算。
  • 迭代次数太少，导致误差超过 10⁻⁵。

面试追问

为什么搜索范围只需客户点的包围盒？

若中心位于所有客户的左侧，把它向右移动不会增大到任何客户的距离；其余三个方向同理。因此至少存在一个最优点位于横纵坐标的最小值与最大值之间。

为什么不能直接分别取 x、y 的中位数？

分别取中位数最小化的是曼哈顿距离 |x−xᵢ|+|y−yᵢ|。欧几里得距离把两个维度耦合在平方根中，不能拆开独立求解。

如果需要返回中心坐标怎么办？

让内层搜索同时返回最优 y，外层结束后使用最终 x 再调用一次内层搜索，即可得到近似的 [x,y]。最优坐标可能不唯一。
