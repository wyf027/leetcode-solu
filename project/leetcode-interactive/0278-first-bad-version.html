第一个错误的版本

一条从“正常”突然切换为“错误”的版本时间线。你的目标不是检查每个版本，而是在尽量少调用质量检测 API 的前提下，锁定那个转折点。

Problem

题目说明

以下内容依据官方元数据准确转述，保留完整示例参数与提交接口语义。

你正在带领团队开发产品。最新版本没有通过质量检测，并且每个版本都基于前一个版本开发，因此一旦某个版本出错，它之后的所有版本也都会出错。

给定从 1 到 n 的版本序列，以及系统已经提供的接口 bool isBadVersion(version)，请实现函数找出第一个错误版本，并尽量减少 API 调用次数。

提交函数：接收整数 n，返回第一个错误版本号。示例里的 bad 用于描述隐藏的错误起点，并不是大多数语言提交函数的显式参数。

约束与接口

  • 1 <= bad <= n
  • n <= 231 - 1
  • isBadVersion(version) 返回布尔值
  • 版本状态具有单调性：正常版本全部位于错误版本之前

官方示例 1

输入
n = 5, bad = 4
输出
4
调用
isBadVersion(3) → false
isBadVersion(5) → true
isBadVersion(4) → true
说明
第 4 个版本是第一个错误版本。

官方示例 2

输入
n = 1, bad = 1
输出
1
说明
只有一个版本时，它就是第一个错误版本。

Solution

完整题解：寻找单调边界

把 API 返回值看成一串先 false、后 true 的布尔序列，目标就是第一个 true。

核心洞察

版本状态满足单调性：存在唯一边界 bad，使得 [1, bad - 1] 都是正常版本， [bad, n] 都是错误版本。因此可以在闭区间 [left, right] 中做二分边界查找。

mid = left + (right - left) / 2

完整过程

  1. 初始化 left = 1、right = n。
  2. 当 left < right 时计算中点 mid。
  3. 若 isBadVersion(mid) 为 true，边界可能是 mid，令 right = mid。
  4. 否则 mid 一定正常，令 left = mid + 1。
  5. 循环结束时区间只剩一个版本，返回 left。

正确性证明

维护不变量：第一个错误版本始终位于闭区间 [left, right]。初始时题目保证 bad ∈ [1, n]，不变量成立。

若 mid 错误，则第一个错误版本不晚于 mid，保留 [left, mid]；若 mid 正常，则第一个错误版本一定晚于 mid，保留 [mid + 1, right]。两种更新都维持不变量，并严格缩小区间。终止时 left = right，区间中的唯一版本必为第一个错误版本。

边界与复杂度

  • 单版本：循环不执行，直接返回 1。
  • 首个版本错误：右边界持续左移，最终返回 1。
  • 最后版本错误：左边界持续右移，最终返回 n。
  • 时间：O(log n)，API 调用次数同阶。
  • 空间：O(1)。
  • 溢出：用 left + (right - left) / 2 计算中点。
Java · 官方提交接口O(log n) / O(1)
/* The isBadVersion API is defined in the parent class VersionControl.
   boolean isBadVersion(int version); */

public class Solution extends VersionControl {
    public int firstBadVersion(int n) {
        int left = 1;
        int right = n;

        while (left < right) {
            int mid = left + (right - left) / 2;
            if (isBadVersion(mid)) {
                right = mid;
            } else {
                left = mid + 1;
            }
        }

        return left;
    }
}

替代方案

从版本 1 开始线性调用 API，遇到第一个 true 即返回，思路直观但最坏需要 n 次调用，时间为 O(n)。在 API 昂贵或 n 很大时明显不如二分查找。

也可写成“寻找第一个满足条件的位置”的通用 lower bound 模板；本题的条件谓词就是 isBadVersion。

面试追问

  • 为什么错误时不能写成 right = mid - 1？
  • 若 API 偶发返回错误结果，如何通过重复采样与多数投票提高可信度？
  • 若不知道 n，只能不断探测版本，能否先指数扩张再二分？
  • 如何抽象成寻找任意单调谓词的第一个 true？

常见错误

  • 中点错误时丢掉 mid，导致恰好跳过答案。
  • 混用 left < right 与 left <= right 模板，造成死循环或越界。
  • 写成 (left + right) / 2，在 32 位整数中可能溢出。
  • 误以为 bad 是提交函数参数，忽略它由平台 API 隐式决定。

记忆锚点

错误版本 mid 仍可能是第一个错误版本，所以要保留它；正常版本 mid 一定不是答案，所以跳到 mid + 1。 这两句话决定了两个边界更新式。
