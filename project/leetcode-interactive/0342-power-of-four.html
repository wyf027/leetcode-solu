Power of Four

342. 4的幂

判断一个整数是否恰好落在序列 1、4、16、64……中。先动手观察数字，再决定如何写出常数时间判断。

Solution

常数时间的三道检测门

核心洞察

4 的幂在二进制中只有一个 1，而且这个 1 只会出现在从低位起编号为 0、2、4……的偶数位置。

因此同时验证：n > 0；n & (n - 1) == 0；以及 n & 0x55555555 != 0。掩码 0x55555555 的二进制是交替的 0101…0101，恰好覆盖允许位置。

以 n = 16 为例
16             = 0001 0000
15             = 0000 1111
16 & 15        = 0000 0000
0x55555555     = 0101 0101 ...
16 & mask      ≠ 0

完整过程

排除非正数

幂指数要求为整数且结果为正；在本题整数范围内，0 和负数都不是 4 的幂。

确认是 2 的幂

若正整数只有一个二进制 1，减一会把该位变 0、低位全变 1，因此与运算后为 0。

限定唯一 1 的位置

2 的幂可能是 2¹、2³ 等；掩码只保留偶数位，从中筛出 2²ᵏ = 4ᵏ。

正确性证明

充分性：算法返回 true 时，n 为正且二进制只有一个 1；掩码条件又保证该 1 位于偶数下标 2k。因此 n = 2²ᵏ = 4ᵏ，是 4 的幂。

必要性：若 n = 4ᵏ = 2²ᵏ，则 n 为正，二进制只有第 2k 位为 1。它通过单比特检测，也必与覆盖偶数位的掩码相交，因此算法返回 true。

充分性与必要性均成立，算法正确。

边界与复杂度

  • n = 1：即 4⁰，返回 true。
  • n ≤ 0：直接返回 false。
  • 32 位最大可表示的 4 的幂为 4¹⁵ = 1073741824。
  • 时间复杂度 O(1)，空间复杂度 O(1)。

替代方案

  • 循环除以 4：直观，时间 O(log₄n)，但不满足进阶目标。
  • 模 3：正的 2 的幂中，指数为偶数时才有 n % 3 == 1；可替换掩码条件。
  • 对数：浮点误差使边界判断更脆弱，通常不推荐。

四语言完整代码

JavaLeetCode 提交格式
class Solution {
    public boolean isPowerOfFour(int n) {
        return n > 0
            && (n & (n - 1)) == 0
            && (n & 0x55555555) != 0;
    }
}

  • 如果整数宽度变成 64 位，掩码应该如何调整？

常见错误

  • 只判断 2 的幂，会把 2、8、32 误判为 true。
  • 忘记 n > 0，容易让 0 或符号位参与错误判断。
  • 把允许位理解反：最低位下标为 0，是偶数位。
  • 依赖浮点对数做精确整数判定，可能受舍入影响。
