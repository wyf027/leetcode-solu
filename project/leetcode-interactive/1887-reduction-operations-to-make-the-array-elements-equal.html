ONE OPERATION AT A TIMEMEDIUM · 中等公开题

使数组元素相等的减少操作次数

Reduction Operations to Make the Array Elements Equal

每次只能让一个最大值降到当前的次大值。观察数字逐渐靠拢，思考如何计算整个过程需要的操作次数。

先读规则，再手动操作。完整推导与四语言代码位于页面底部，默认收起。

01 / 题目与规则

给定整数数组 nums，返回让所有元素变得相等所需的减少操作次数。每次操作严格遵循：

  1. 找出当前最大值 largest。如果它出现多次，选择下标最小的那个元素；下标从 0 开始。
  2. 在当前数组中寻找严格小于 largest 的最大值，记为 nextLargest。
  3. 仅把刚选中的 nums[i] 改成 nextLargest，计一次操作。
所有元素已经相等时，过程结束，不再寻找次大值。这里的“减少”不是减 1，也不是把全部最大值同时改掉。

参数：nums: integer[]　返回：integer

约束：1 ≤ nums.length ≤ 5 × 10⁴；1 ≤ nums[i] ≤ 5 × 10⁴。

04 / 独立题解

准备好之后，再看洞察、证明与代码。

把数值变成“层级”

核心洞察：一个元素需要减少多少次，取决于它下面有多少种不同的值，而不是它与最小值相差多少。把不同值从小到大编号为 0、1、2……，答案就是所有元素的层级之和。

完整过程：排序后数层级

  1. 将数组升序排序。最小值层级为 0，不需要操作。
  2. 从第二个元素开始扫描，维护 levels 和 answer，初始都为 0。
  3. 如果当前值不等于前一个值，说明跨到一个新层级，令 levels += 1。
  4. 无论是否出现新值，都把 levels 加入答案。相同值的每个元素都要贡献操作次数。
  5. 返回 answer。
排序后元素11223
层级00112
累计答案00124

示例 3 中，3 先降到 2，再降到 1，贡献 2；两个原始的 2 分别贡献 1。总计 2 + 1 + 1 = 4。表中每列对应一个元素，重复值不能合并后只计算一次。

为什么正确？

① 每次恰好下降一个层级。设初始不同值为 v₀ < v₁ < … < vₖ。当最大值仍为 vⱼ 时，所有更低层的值都还存在：它们尚未成为最大值而被消去。因此严格次大值一定是 vⱼ₋₁。

② 用层级总和衡量剩余工作。把每个当前值映射到上述初始层级，得到非负整数和 S。一次操作只改变一个元素，且将其层级减 1，因此 S 恰好减 1。

③ 终点只能是初始最小值。最小值不会被减少，因为存在更大值时它不是最大值，而全部相等时已经停止。因此终点的所有层级为 0，S = 0，操作次数正好等于初始 S。

④ 扫描计算了这个 S。升序扫描每跨过一个不同值就把层级加 1，再为每个元素累加其层级，得到初始 S。相同最大值按最小下标选取会改变操作顺序，但不会改变每次 S 减 1 的结论。

边界与复杂度

  • 长度为 1 或全部相等：没有新层级，答案为 0。
  • 只有两个不同值：每个较大值都只减少一次，与两值之间的差无关。
  • 全部互不相同时答案最大，为 n(n−1)/2。n = 50000 时为 1,249,975,000，在 Java / C++ 的 32 位有符号整数范围内；JavaScript Number 也可精确表示。
  • 排序加线性扫描：时间 O(n log n)；扫描阶段额外空间 O(1)。总辅助空间受内置排序影响：Java / C++ 通常有 O(log n) 栈开销；Python 排序最坏 O(n)；JavaScript 依引擎实现而定，不能统一声称总空间 O(1)。
  • 下面四份实现都会原地排序输入。若必须保留原数组，先复制，额外占用 O(n) 空间。

四语言完整提交代码

使用官方函数名 reductionOperations；代码仅生成，尚未编译或执行。

Java

import java.util.Arrays;

class Solution {
    public int reductionOperations(int[] nums) {
        Arrays.sort(nums);
        int levels = 0;
        int answer = 0;
        for (int i = 1; i < nums.length; i++) {
            if (nums[i] != nums[i - 1]) {
                levels++;
            }
            answer += levels;
        }
        return answer;
    }
}

替代方案

  • 从右向左累计高值组大小：排序后，当 nums[i] != nums[i−1] 时加上 n−i。这条边界右侧的每个元素都要跨过它一次，与层级求和等价。
  • 频次数组：题目值域上限 U = 50000，可记录每个值的频次，再按值升序遍历；只在频次非零时推进层级，累加 频次 × 层级。时间 O(n + U)，空间 O(U)。值域很大时排序更适合。
  • 直接模拟：本页交互使用此方法以保留真实下标。每一步扫描数组找最大值和次大值，时间为 O(n × 操作次数)，最坏 O(n³)，适合小样例，不适合完整规模。

常见错误

  • 累加 nums[i] − min：计算成了每次减 1 的另一道题。
  • 只累加不同值的层级：漏掉重复元素的贡献。
  • 把一批最大值的下降算成一次操作：一批有几个元素，就需要几次。
  • “次大值”取到另一个相等的最大值：题目要求严格更小。
  • JavaScript 使用无比较器的 sort()：默认按字符串顺序排序，数字顺序可能错误。
  • 每遇到新值才累加答案：层级只在新值时增加，但答案要对每个元素累加。

面试追问

如果相同最大值任选一个，次数会变化吗？不会；每一步依然只让层级总和下降 1。

如果一回合允许同时修改全部最大值呢？每回合消去最高的不同值，共需要“不同值个数 − 1”回合，但这不是原题的操作定义。

能否不排序？可以利用有限值域统计频次；若只用哈希统计，仍要处理不同值的有序关系。

扩大数组长度后如何处理溢出？根据 n(n−1)/2 重新评估范围；Java / C++ 可用 long / long long，JavaScript 超过安全整数范围后使用 BigInt 累加。
