01 / Problem

题目说明

若一个整数数列包含至少三个元素，并且每对相邻元素的差都相同，就称它为等差数列。给定整数数组 nums，返回其中构成等差数列的连续子数组数量。子数组必须连续。

函数签名

numberOfArithmeticSlices(nums: integer[]) -> integer
同一位置可以属于多个答案。例如一个长度为 4 的等差子数组，同时包含两个长度为 3 的等差子数组。

约束

  • 1 <= nums.length <= 5000
  • -1000 <= nums[i] <= 1000
  • 答案统计的是连续子数组，不是任意子序列。

示例 1

3 slices 
输入：nums = [1,2,3,4]
输出：3
解释：[1,2,3]、[2,3,4] 和 [1,2,3,4]
      均为等差子数组。

示例 2

too short 
输入：nums = [1]
输出：0
解释：数组不足三个元素，无法形成等差子数组。

Solution Unlocked

一次扫描，累计每个右端点的新贡献

关键不是枚举所有子数组，而是回答一个更小的问题：当扫描到位置 i 时，有多少个新的等差子数组恰好以 i 结尾？

核心洞察

设 dp 为以上一个位置结尾的等差子数组数量。若最新两个相邻差相等，之前每个有效子数组都能向右延长，另外三个尾部元素还会新组成一个长度为 3 的子数组，所以当前贡献是 dp + 1；否则连续性被打断，贡献归零。

nums[i] - nums[i-1] == nums[i-1] - nums[i-2] ? dp = dp + 1 : dp = 0

每一步把 dp 加到答案 total 中。

为什么贡献会递增？

对 [1,2,3,4]，扫描到 3 时新增 [1,2,3]，贡献为 1；扫描到 4 时，原有切片可以延长为 [1,2,3,4]，尾部又新增 [2,3,4]，贡献为 2。总数正好是 1 + 2 = 3。

长度为 L 的完整等差段一共贡献 (L-1)(L-2)/2 个切片；逐点累计得到同一结果。

完整过程

  1. 长度少于 3 时直接返回 0；一般情况下从索引 2 开始扫描。
  2. 比较 nums[i] - nums[i-1] 与 nums[i-1] - nums[i-2]。
  3. 相等时令 dp += 1，否则令 dp = 0。
  4. 执行 total += dp，直到数组末尾，返回 total。

复杂度

时间 O(n) 只扫描一次数组
空间 O(1) 仅使用常数变量

边界情况

  • 数组长度为 1 或 2：答案为 0。
  • 所有元素相同：公差为 0，整段都有效。
  • 负数或负公差：判断方式完全相同。
  • 差值中途改变：dp 归零，下一段重新累计。

正确性证明

引理：dp 精确计数

扫描到 i 后，dp 等于所有以 i 结尾的等差子数组数量。若两段相邻差不同，不可能存在以 i 结尾且长度至少 3 的等差子数组，因此为 0。若相同，所有以 i-1 结尾的有效子数组都能唯一延长到 i，并且尾部三个元素形成唯一的新长度 3 子数组，因此数量恰为旧值加 1。

定理：total 是最终答案

每个等差子数组都有唯一的右端点。根据引理，每一步的 dp 恰好计数当前右端点对应的所有答案。把所有右端点的贡献相加，既不会遗漏，也不会重复，因此 total 等于数组中的全部等差子数组数量。

四语言完整代码

class Solution {
    public int numberOfArithmeticSlices(int[] nums) {
        int total = 0;
        int dp = 0;

        for (int i = 2; i < nums.length; i++) {
            if (nums[i] - nums[i - 1] == nums[i - 1] - nums[i - 2]) {
                dp++;
                total += dp;
            } else {
                dp = 0;
            }
        }

        return total;
    }
}

替代方案与取舍

按完整等差段计数

可以维护当前相同公差段的长度 L，每当差值改变时，用 (L-1)(L-2)/2 汇总该段，再开始新段。时间和空间复杂度同样最优，但边界处理更集中，面试中需要解释为什么公式成立。

枚举起点和终点

从每个起点向右扩展，并在差值改变时停止，可做到最坏 O(n²)。它直观、适合先建立正确性基线，但没有利用相邻答案之间的重叠结构，不是本题推荐解法。

面试追问

如果改为统计等差子序列，而不是连续子数组呢？

连续性消失后，单个滚动变量不再够用。通常需要为每个下标维护“公差 → 数量”的哈希表动态规划，复杂度约为 O(n²)。

是否需要担心整数差值溢出？

本题 nums[i] 只在 [-1000, 1000]，差值不会溢出 32 位整数。若约束扩大，应在 Java/C++ 中先转为 64 位再做减法。

能否用流式数据完成？

可以。只需保留最近两个数、当前 dp 和累计答案，不需要存下整个数组。

常见错误

  • 把“子数组”误读成“子序列”，统计了不连续元素。
  • 差值相等时只给答案加 1，遗漏更长等差段带来的多重贡献。
  • 差值断开后忘记将 dp 清零。
  • 从索引 1 开始却访问 i - 2，造成越界。
  • 使用浮点斜率或除法比较；本题只需比较整数差值。
