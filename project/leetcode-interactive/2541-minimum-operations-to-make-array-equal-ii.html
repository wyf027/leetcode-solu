01 / PROBLEM

目标是逐项相等

给定两个长度均为 n 的整数数组 nums1、nums2，以及整数 k。一次操作选择下标 i 和 j，对 nums1[i] 加上 k，同时对 nums1[j] 减去 k。

求让每个位置都满足 nums1[i] == nums2[i] 的最少操作数；无法做到时返回 -1。这里的“相等”指两个数组对应位置一致，不要求数组内部所有数字相同，也不允许直接交换位置。

官方示例 1

nums1 = [4,3,1,4]
nums2 = [1,3,7,1]
k = 3
输出：2

先选择 i=2, j=0，得到 [1,3,4,4]；再选择 i=2, j=3，得到 [1,3,7,1]。最少需要 2 次。

官方示例 2

nums1 = [3,8,5,2]
nums2 = [2,4,1,6]
k = 1
输出：-1

没有任何操作序列能把第一个数组变成第二个数组。

完整约束

  • n == nums1.length == nums2.length
  • 2 ≤ n ≤ 105
  • 0 ≤ nums1[i], nums2[j] ≤ 109
  • 0 ≤ k ≤ 105

04 / SOLUTION

想好后，再打开题解

核心洞察、证明、边界与四语言实现。

把多余的 k 搬给不足的位置

核心洞察：两个可行条件，一个计数

记 d[i] = nums1[i] − nums2[i]。正差值是多余量，负差值是缺口。一次操作把一份 k 从多余的位置交给不足的位置。

  • 总量守恒：一次增加 k、一次减少 k，所以必须有 Σd[i] = 0。
  • 每格只能跳 k：当 k > 0 时，每个 d[i] 都必须能被 k 整除。
  • 只数一侧：满足前两条后，最少操作数为 Σ max(d[i], 0) / k。

k = 0 必须优先处理：任何操作都不能改变数组。逐项相等返回 0，否则返回 -1；不能对 0 取余或除法。

完整过程

  1. 初始化 balance = 0 与 moves = 0。
  2. 遍历对应元素，计算差值 d。k 为 0 时，仅检查差值是否为 0。
  3. k 大于 0 时，若 d % k != 0，立即返回 -1。
  4. 累加 balance += d；若 d 大于 0，累加 moves += d / k。
  5. 遍历结束后，balance 为 0 返回 moves，否则返回 -1。
示例 1：d = [3,0,-6,3]，k = 3
单位差值： [1,0,-2,1]
多余单位：下标 0 有 1 份，下标 3 有 1 份
不足单位：下标 2 缺 2 份
转移 0 → 2，再转移 3 → 2，共 2 次

示例 2：sum(nums1) = 18，sum(nums2) = 13
总量不同，返回 -1。

正确性证明

必要性。操作不改变总和，也不改变任一位置对 k 的余数。因此只要总和不一致或某个差值不是 k 的整数倍，就无解。k=0 时数组完全不变。

最优下界。对 k>0，把正差值按 k 换算为份数，总份数为 P。每次操作最多从一个多余位置移走一份，因此最多使剩余多余份数减少 1；到达目标至少需要 P 次。

可达构造。若差值整除且总和相等，多余份数必等于不足份数。只要还存在多余位置，就同时存在不足位置；从前者向后者转移 k。每次恰好减少一份多余量，且不会越过目标。重复 P 次恰好到达目标，所以下界可以达到，答案就是 P。

边界与数值范围

  • 原本相等时返回 0，无论 k 是否为 0。
  • 总和相等只是必要条件；例如 [1,3] → [2,2], k=2 的单点差值无法整除。
  • n 最大为 105，差值累计量级可达 1014。Java 用 long，C++ 用 long long，Python 整数自动扩展；JavaScript Number 的精确整数范围足够覆盖本题。
  • 负差值取余的符号因语言而异，但这里只判断是否为 0，不影响结果。
  • 不要求模拟，也不修改输入数组；多余位置转出后仍不低于其非负目标。

复杂度

时间 O(n)，扫描一次；额外空间 O(1)，仅保存差值、总差值和计数。教学演示使用预设帧，与提交算法的空间复杂度分开计算。

四语言完整实现

均使用官方 minOperations 参数形式，可按对应语言提交；以下代码尚未执行验证。

Java long 返回值

class Solution {
    public long minOperations(int[] nums1, int[] nums2, int k) {
        long balance = 0, moves = 0;
        for (int i = 0; i < nums1.length; i++) {
            long d = (long) nums1[i] - nums2[i];
            if (k == 0) {
                if (d != 0) return -1;
                continue;
            }
            if (d % k != 0) return -1;
            balance += d;
            if (d > 0) moves += d / k;
        }
        return balance == 0 ? moves : -1;
    }
}

替代方案

绝对值法：先检查同样的可行条件，再算 Σ|d[i]| / (2k)。一次转移同时修复供给和需求两端，所以绝对值总量把每次操作算了两遍。代码中只累计正差值更直接。

供需双指针：分别记录多余与不足位置，每次匹配两端的最小份数，批量构造转移记录，时间 O(n)、额外空间 O(n)。适合要求输出具体操作安排的扩展题；逐次输出则可能需要与答案一样多的输出时间。

面试追问

  • 为什么不排序？目标固定在对应下标；排序会改变要匹配的位置，破坏问题语义。
  • 若只允许相邻位置转移？总量与整除仍必要，但次数还取决于经过多少条边，可累计前缀单位差值的绝对值。
  • 如何输出方案而避免 1014 量级逐次模拟？输出“源下标、目标下标、重复次数”的批量记录，每次至少消耗完一个供需位置。

常见错误

  • 把题意理解为让 nums1 内部的所有元素相等。
  • 在处理 k=0 之前做取余，导致除零错误。
  • 只看总和，漏掉每个位置的整除条件。
  • 把正负差值的绝对值直接相加而忘记除以 2。
  • 对每一步进行真实模拟，时间随数值大小膨胀。
  • 使用 32 位累计器，或在 JavaScript 中通过位运算截断到 32 位整数。
