院系无效的学生

两张表，一次登记核对。找出那些仍在学生名册中、但其院系编号已不存在的学生。

Easy Database Paid only Students With Invalid Departments

Problem

题意与数据结构

目标：输出院系记录已不存在的学生

学校维护 Departments 与 Students 两张表。每名学生通过 department_id 指向一个院系。请查询所有 department_id 在院系表中找不到对应 id 的学生，并返回学生的 id 和 name；结果顺序不限。

Departments

id INT — 院系唯一标识（主键）

name VARCHAR(30) — 院系名称

Students

id INT — 学生唯一标识（主键）

name VARCHAR(30) — 学生姓名

department_id INT — 登记的院系编号

约束转述：两表的 id 各自唯一；姓名长度不超过 30；学生登记的 department_id 可能在 Departments.id 中不存在。只需找出这些失去有效院系对应关系的学生。

Solution

题解：保留学生，排除有匹配的院系

Anti Join
01

核心洞察

我们关心的不是“成功匹配了谁”，而是“谁完全没有匹配”。以 Students 为左表做 LEFT JOIN，匹配条件是 s.department_id = d.id。未匹配的右表行会被补为 NULL，因此筛选 d.id IS NULL 即可。

1

从 Students 出发

每名学生都必须保留到连接结果中，即使院系表没有对应记录。

2

左连接 Departments

用学生登记的 department_id 匹配院系主键 id。

3

筛选右表缺失

右侧主键本应非空；连接后为 NULL 就能可靠说明没有院系行。

4

只投影所需列

返回 s.id 和 s.name，不要把辅助匹配列带入结果。

官方可提交语言：MySQL

Primary
SELECT s.id, s.name
FROM Students AS s
LEFT JOIN Departments AS d
  ON s.department_id = d.id
WHERE d.id IS NULL;

正确性

若学生的院系存在，连接会得到非空 d.id，因此被过滤；若院系不存在，左连接保留学生且右列为 NULL，因此被选中。输出恰好是全部无效登记学生。

边界

空学生表输出为空；所有院系都有效时输出为空；院系表为空时所有学生都会入选。筛选右表主键，避免可空普通列造成误判。

复杂度

设学生数为 S、院系数为 D。数据库通常借助 Departments.id 的主键索引，约为 O(S log D)；哈希连接可达期望 O(S + D)，额外空间取决于执行计划。

替代方案

NOT EXISTS 同样直接表达反连接，并可避免 NOT IN 遇到 NULL 时的三值逻辑陷阱：

SELECT s.id, s.name
FROM Students AS s
WHERE NOT EXISTS (
  SELECT 1
  FROM Departments AS d
  WHERE d.id = s.department_id
);

public class Main {
    record Department(int id, String name) {}
    record Student(int id, String name, int departmentId) {}

    static List<Student> findInvalid(
            List<Department> departments, List<Student> students) {
        Set<Integer> validIds = new HashSet<>();
        for (Department department : departments) {
            validIds.add(department.id());
        }

        List<Student> answer = new ArrayList<>();
        for (Student student : students) {

function findInvalid(departments, students) {

  return students
    .filter((student) => !validIds.has(student.department_id))

}

面试追问：为什么不用 INNER JOIN？

INNER JOIN 只留下匹配成功的学生，恰好丢掉本题要找的未匹配行。必须使用反连接语义，如 LEFT JOIN … IS NULL 或 NOT EXISTS。

面试追问：NOT IN 有什么风险？

若子查询结果含 NULL，NOT IN 的比较会变成 UNKNOWN，可能意外返回空结果。主键按定义不含 NULL，但 NOT EXISTS 往往更直接、更稳健。

常见错误：筛选 s.department_id IS NULL

这只检查学生自身字段是否为空，不代表它在院系表中找不到。应该检查左连接后的右表主键 d.id IS NULL。

常见错误：把条件放进 WHERE 后误伤左连接

对右表普通字段再做非空筛选，可能把左连接退化成内连接。匹配关系放在 ON，缺失判断使用右表不可空主键。
