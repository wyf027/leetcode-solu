3995. 转换字符串的最小成本 III

一次规则会“锁住”整段下标。把每个可用规则看成一条不重叠的区间边，动态规划就能找出覆盖所有差异字符的最低成本。

题意

给定等长的 source 与 target，每条规则 [pattern, replacement] 可在某个起点使用一次：pattern 的普通字符必须匹配当前字符，* 可匹配任意字符；该段会被替换成 replacement，并且这段位置之后不能再参与规则。

规则代价是基础 costs[i] 加上 pattern 中 * 的数量。求把 source 变成 target 的最小成本；无解返回 -1。

示例 1
source = "hello"
target = "world"
rules = [["he","wo"],["llo","rld"]]
costs = [3,4]
输出：7
示例 2（通配符）
source = "cat"
target = "dog"
rules = [["c*t","dog"]]
costs = [2]
输出：3（基础 2 + 一个 *）

约束：n ≤ 5000，规则数 ≤ 200，单条规则长度 ≤ 20，每条模式至少有一个普通字母，至多 5 个 *。

核心洞察：每条规则就是一条“前缀跳边”

已经被使用的位置绝不能重用，因此每个下标段最多被一条规则覆盖。若规则从 i 覆盖长度 L，它只能把原始 source[i..i+L) 直接变成目标 target[i..i+L)；不可能依赖之前的转换结果。于是从前缀 i 到 i+L 连一条边，边权为基础成本加通配符数。

状态：dp[i] = 把前 i 个字符变成目标的最小成本。
转移：若 source[i] == target[i]，dp[i+1] = min(dp[i+1], dp[i])；每个可用规则给出 dp[i+L] = min(dp[i+L], dp[i] + cost + stars)。

完整过程与正确性

  1. 从左到右扫描每个前缀边界 i。
  2. 相同字符可以不消耗规则，前缀自然延长一位。
  3. 枚举每条规则，检查长度、replacement == target 对应片段，以及 pattern 是否匹配 source 对应片段。
  4. 可用规则覆盖的段互不重叠，因为 DP 每次只向右跳过整段；故每个构造的路径都是合法方案。

完备性：任意合法方案按从左到右的首个未处理位置切分，要么该字符原本相同且不改，要么从这里开始一条规则。DP 恰好枚举这两种选择并取最小值，因此得到全局最优。

边界与复杂度

  • 没有覆盖某个不同字符：该前缀不可达，最终为 -1。
  • 规则可以覆盖原本相同的字符，但不能与其他规则相交。
  • * 仅影响匹配与额外费用；replacement 不能含通配符。

时间：O(n × R × L)，其中 n≤5000、R≤200、L≤20。
空间：O(n)。

替代方案 / 面试追问 / 常见错误

替代：可按长度或 replacement 哈希分组，减少不可能规则；当前约束下直接检查已足够。

追问：若规则允许重叠并连续修改，同一位置会有依赖，应改为图最短路或更高维状态，不再是这个简单 DP。

错误：把规则匹配到“已被修改”的字符串；忘记 * 的额外费用；只覆盖不相同位置而没有同时锁住区间内相同位置。
