Problem

题目描述

Alice 有 n 枚糖，第 i 枚糖的类型是 candyType[i]。医生建议她只吃总数的一半，即恰好 n / 2 枚；题目保证 n 为偶数。

Alice 希望在遵守数量限制的同时，吃到尽可能多的不同糖果类型。给定长度为 n 的整数数组 candyType，返回她最多能吃到的不同类型数。

在恰好选择 n / 2 枚时，最大化不同类型数

约束

  • n == candyType.length
  • 2 <= n <= 104
  • n 为偶数
  • -105 <= candyType[i] <= 105

示例 1

输入：candyType = [1,1,2,2,3,3]
输出：3

只能吃 6 / 2 = 3 枚，而数组恰有 3 种类型，因此可以每种吃一枚。

示例 2

输入：candyType = [1,1,2,3]
输出：2

只能吃 4 / 2 = 2 枚；无论选择 [1,2]、[1,3] 还是 [2,3]，都只能覆盖 2 种。

示例 3

输入：candyType = [6,6,6,6]
输出：1

虽然可以吃 2 枚，但全部糖都属于类型 6，所以最多只有 1 种。

Solution

答案是两个上限的较小值

核心洞察

设不同糖果类型数为 k。答案同时受两个无法突破的上限约束：

  1. Alice 只吃 n / 2 枚，因此不同类型数不可能超过 n / 2。
  2. 数组中一共只有 k 种，因此也不可能超过 k。
answer = min(k, n / 2)

哈希集合能在线性扫描中去重，从而得到 k。

完整过程

  1. 建立集合。创建空的哈希集合 types。
  2. 扫描数组。把每个 candyType[i] 插入集合，重复值自动被忽略。
  3. 取得种类数。扫描结束后，types.size 就是数组的不同类型数 k。
  4. 合并限制。返回 min(k, n / 2)。

正确性证明

上界：Alice 只选 n / 2 枚，每枚最多贡献一种类型，所以结果不超过 n / 2；数组只有 k 种，所以结果也不超过 k。因此结果至多为 min(k, n / 2)。

可达性：若 k <= n / 2，先从每种类型选一枚，共选 k 枚，再用任意糖补足到 n / 2 枚，可覆盖全部 k 种。若 k > n / 2，从任意 n / 2 个不同类型中各选一枚，可覆盖 n / 2 种。

结论：两个分支都能达到上界，故算法返回值就是最大不同类型数。

边界情况

  • 全部相同：k = 1，答案为 1。
  • 全部不同：k = n，选择数量成为瓶颈，答案为 n / 2。
  • 负数类型：类型编号可为负数，集合照常处理。
  • 最小输入：n = 2 时只能吃一枚，答案必为 1。
  • 大输入：n = 104 时线性扫描足够高效。
O(n)时间复杂度：遍历一次数组；哈希集合插入的平均时间为 O(1)。
O(k)空间复杂度：集合最多保存 k 个不同类型，且 k ≤ n。

四种语言完整代码

import java.util.HashSet;
import java.util.Set;

class Solution {
    public int distributeCandies(int[] candyType) {
        Set<Integer> types = new HashSet<>();
        for (int type : candyType) {
            types.add(type);
        }
        return Math.min(types.size(), candyType.length / 2);
    }
}

替代方案

排序后计数：先排序，再统计相邻元素变化的次数，同样可得到不同类型数。它不需要哈希表，但通常需要 O(n log n) 时间，并可能修改输入数组。

布尔数组：由于类型值范围已知，可通过偏移量映射到布尔数组。它具有确定性的线性时间，但会占用与值域相关的空间，表达也不如集合直接。

面试追问

为什么不需要真正构造 Alice 吃的糖果集合？

题目只询问最大类型数。上界可以被构造性证明达到，因此知道类型总数和可选数量后就足以确定答案。

如果改为最多吃 n / 2 枚，答案会变吗？

不会。为了最大化不同类型数，每种只需吃一枚；选择 min(k, n / 2) 枚即可达到同样答案。

如果每种糖有不同热量限制呢？

简单的两个上限不再充分，问题可能转化为带容量约束的选择问题，需要根据新规则考虑贪心或动态规划。

常见错误

  • 只返回集合大小，忘记 Alice 最多只能吃 n / 2 枚。
  • 只返回 n / 2，忽略数组可能只有很少的不同类型。
  • 把重复糖的数量当成类型数，或手写去重时漏掉负数。
  • 使用浮点除法而不是整数意义下的 n / 2；虽然本题保证 n 为偶数，仍应保持语义清晰。
  • 为了找具体组合而进行回溯，导致不必要的指数级复杂度。
