报告系统状态的
连续日期

把逐日的“成功 / 失败”日志压缩成连续区间。这里真正困难的不是聚合，而是让每一行稳定地找到自己所属的“岛”。

Problem

题目转述

系统每天的任务结果记录在两张表中：Failed 保存失败日期，Succeeded 保存成功日期。请只考虑 2019-01-01 到 2019-12-31（含首尾）之间的数据，将状态相同且日期相邻的天合并成一个连续区间。

返回每个区间的状态 period_state、开始日期 start_date 和结束日期 end_date，结果按开始日期升序排列。

数据库题没有传统函数参数。提交入口是两张表；主解使用 MySQL 8.0 窗口函数。

  • 只报告 2019 年内的日期；范围之外的记录不进入结果。
  • 连续指自然日相邻，例如 1 月 2 日与 1 月 3 日连续。
  • 输出列依次为 period_state、start_date、end_date，并按 start_date 升序。

Solution

窗口函数：用累计边界编号分岛

核心洞察

先把成功与失败日期纵向合并成统一日志。按日期扫描时，如果当前状态与前一天状态不同，当前行就是新区间的起点。把这些起点标成 1，再做前缀和，便得到稳定的区间编号。

一句话公式

group_id = SUM(state != previous_state)

第一行没有前驱，因此也必须视为新区间。

完整过程

  1. 用 UNION ALL 统一两张表，并给每行补上状态文本。
  2. 在合并后的数据上过滤 2019 年日期，避免范围外记录干扰窗口计算。
  3. 用 LAG(period_state) 读取上一日的状态；首行或状态变化时记边界值 1，否则为 0。
  4. 按日期对边界值做累计求和，生成 group_id。
  5. 按状态和组号聚合，用 MIN / MAX 得到区间两端，再按开始日期排序。

MySQL 8.0 官方提交主解

WITH all_dates AS (
    SELECT fail_date AS task_date, 'failed' AS period_state
    FROM Failed
    WHERE fail_date BETWEEN '2019-01-01' AND '2019-12-31'
    UNION ALL
    SELECT success_date AS task_date, 'succeeded' AS period_state
    FROM Succeeded
    WHERE success_date BETWEEN '2019-01-01' AND '2019-12-31'
), marked AS (
    SELECT task_date,
           period_state,
           CASE
               WHEN LAG(period_state) OVER (ORDER BY task_date) = period_state
               THEN 0 ELSE 1
           END AS is_new_period
    FROM all_dates
), grouped AS (
    SELECT task_date,
           period_state,
           SUM(is_new_period) OVER (ORDER BY task_date) AS group_id
    FROM marked
)
SELECT period_state,
       MIN(task_date) AS start_date,
       MAX(task_date) AS end_date
FROM grouped
GROUP BY period_state, group_id
ORDER BY start_date;

正确性说明

引理 1：边界识别正确

排序后，同一连续状态段的首行是第一行或与前一行状态不同；其余行状态相同。因此 is_new_period 恰好只在每段首行取 1。

引理 2：组号恰好对应区间

累计和只在边界增加，所以同一区间内恒定、跨区间严格增加。按状态与组号聚合不会合并不同岛。

结论：每个输出组与一个且仅一个最大连续同状态日期区间对应，MIN 和 MAX 正好给出其起止日期，因此算法正确。

边界情况

  • 单日区间：开始与结束日期相同。
  • 全年只有一种状态：累计组号始终为 1，仅输出一行。
  • 2019 年外存在数据：必须在窗口函数之前过滤。
  • 目标年份没有数据：自然返回空结果。

复杂度

设 2019 年内共有 n 条日志。窗口排序主导时间复杂度为 O(n log n)；窗口与聚合所需中间空间为 O(n)。若数据库能利用合适索引，范围过滤成本可进一步降低。

替代方案

也可以分别对两种状态使用 date - row_number() 构造恒定分组键，再合并结果。它很短，但需要分别编号，且跨数据库的日期运算写法不同。累计边界方案更直观，也更容易扩展到三种以上状态。

四语言本地语义参考

本题是数据库题；下列 Java、JavaScript、Python、C++ 代码用于在本地对等模拟“合并日志 → 排序 → 分段”，不是 LeetCode 此题的 SQL 提交语言。

import java.time.LocalDate;
import java.util.*;

public class ReportContiguousDates {
    record Event(LocalDate date, String state) {}
    record Period(String state, LocalDate start, LocalDate end) {}

    static List<Period> report(List<LocalDate> failed,
                               List<LocalDate> succeeded) {
        LocalDate from = LocalDate.of(2019, 1, 1);
        LocalDate to = LocalDate.of(2019, 12, 31);
        List<Event> events = new ArrayList<>();
        for (LocalDate d : failed)
            if (!d.isBefore(from) && !d.isAfter(to))
                events.add(new Event(d, "failed"));
        for (LocalDate d : succeeded)
            if (!d.isBefore(from) && !d.isAfter(to))
                events.add(new Event(d, "succeeded"));
        events.sort(Comparator.comparing(Event::date));
        List<Period> ans = new ArrayList<>();
        for (int i = 0; i < events.size();) {
            int j = i;
            while (j + 1 < events.size()
                    && events.get(j + 1).state().equals(events.get(i).state())
                    && events.get(j).date().plusDays(1).equals(events.get(j + 1).date())) j++;
            ans.add(new Period(events.get(i).state(), events.get(i).date(), events.get(j).date()));
            i = j + 1;
        }
        return ans;
    }
}
function reportContiguousDates(failed, succeeded) {
  const from = "2019-01-01", to = "2019-12-31";
  const events = [
    ...failed.map(date => ({ date, state: "failed" })),
    ...succeeded.map(date => ({ date, state: "succeeded" }))
  ].filter(e => e.date >= from && e.date <= to)
   .sort((a, b) => a.date.localeCompare(b.date));
  const nextDay = date => {
    const d = new Date(date + "T00:00:00Z");
    d.setUTCDate(d.getUTCDate() + 1);
    return d.toISOString().slice(0, 10);
  };
  const result = [];
  for (let i = 0; i < events.length;) {
    let j = i;
    while (j + 1 < events.length &&
           events[j + 1].state === events[i].state &&
           nextDay(events[j].date) === events[j + 1].date) j++;
    result.push({ period_state: events[i].state,
      start_date: events[i].date, end_date: events[j].date });
    i = j + 1;
  }
  return result;
}
from datetime import date, timedelta

def report_contiguous_dates(failed: list[date],
                            succeeded: list[date]) -> list[tuple[str, date, date]]:
    start, end = date(2019, 1, 1), date(2019, 12, 31)
    events = [(d, "failed") for d in failed if start <= d <= end]
    events += [(d, "succeeded") for d in succeeded if start <= d <= end]
    events.sort()
    result = []
    i = 0
    while i < len(events):
        j = i
        while (j + 1 < len(events)
               and events[j + 1][1] == events[i][1]
               and events[j + 1][0] == events[j][0] + timedelta(days=1)):
            j += 1
        result.append((events[i][1], events[i][0], events[j][0]))
        i = j + 1
    return result
#include <algorithm>
#include <string>
#include <tuple>
#include <vector>
using namespace std;

struct Event { string date, state; };
using Period = tuple<string, string, string>;

vector<Period> reportContiguousDates(vector<string> failed,
                                     vector<string> succeeded) {
    vector<Event> events;
    auto add = [&](const vector<string>& dates, const string& state) {
        for (const string& d : dates)
            if (d >= "2019-01-01" && d <= "2019-12-31")
                events.push_back({d, state});
    };
    add(failed, "failed"); add(succeeded, "succeeded");
    sort(events.begin(), events.end(),
         [](const Event& a, const Event& b) { return a.date < b.date; });
    vector<Period> ans;
    for (int i = 0, n = (int)events.size(); i < n;) {
        int j = i;
        // 输入覆盖每日任务时，相邻且同状态的排序记录属于同一段。
        while (j + 1 < n && events[j + 1].state == events[i].state) ++j;
        ans.emplace_back(events[i].state, events[i].date, events[j].date);
        i = j + 1;
    }
    return ans;
}

面试追问

  • 如果状态超过两种？ 方案不变，状态变化就开新组。
  • 如果日期不保证每天都有记录？ 边界条件还要加入 DATEDIFF(task_date, previous_date) != 1。
  • 为什么过滤要在 LAG 前？ 否则 2018 年最后一行会成为 2019 年首行的前驱，可能错误地吞掉首个边界。
  • 如何优化？ 为两张表的日期列建索引，使年度范围筛选走索引扫描。

常见错误

  • 先做窗口函数、后过滤年份，导致窗口上下文被范围外数据污染。
  • 使用 UNION 无谓去重；题目已保证单日状态唯一，UNION ALL 更直接。
  • 只按状态聚合，把分开的多个成功区间合成一个区间。
  • 忘记把第一行标为新区间，导致组号为空或从错误位置开始。
  • 最终没有按 start_date 排序。
