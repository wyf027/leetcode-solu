游戏玩法分析 IV

从每位玩家的第一次登录出发，追踪“第二天是否回来”。先通过交互观察数据，再决定如何把它翻译成查询。

目标指标次日留存率首登次日回访人数 ÷ 总玩家数

题意

Activity 记录玩家在某天使用某设备登录并游玩的情况。对每位玩家找出最早的 event_date；如果该玩家也在这个日期的次日出现，就算作一名次日回访玩家。

返回次日回访玩家数占全部玩家数的比率，结果四舍五入到小数点后两位，输出列名为 fraction。

关键边界：只看“首次登录的紧邻下一天”。首次登录两天后回来、或连续登录但缺少次日记录，都不计入。

表结构与约束

列类型含义

games_playedint当天游玩局数，可为 0

(player_id, event_date) 为主键，因此同一玩家同一天最多一条记录。题目未额外给出数值范围；输入保证符合上述模式。

核心洞察

统计单位是“玩家”，不是活动记录。先用 MIN(event_date) 把每位玩家压缩为唯一的首次登录日，再判断原表中是否存在 首日 + 1 天 的记录。符合条件的玩家自然只贡献一次。

完整过程

  1. 子查询按 player_id 分组，得到每人的 first_date。
  2. 把首登结果与 Activity 按同一玩家、日期恰好相差一天连接。
  3. 连接成功的行数是次日回访玩家数；首登子查询行数是总玩家数。
  4. 用条件平均值可直接表达比例：命中为 1，未命中为 0，再 ROUND(..., 2)。

正确性说明

引理 1：按玩家取最小日期，得到且只得到该玩家的首次登录日期，因为每位玩家至少有一条活动记录，且日期有全序。

引理 2：对首登行连接日期为 first_date + 1 day 的原表记录，恰好识别题目定义的次日回访玩家。主键保证该玩家在目标日期至多一条记录，因此不会重复计数。

结论：条件平均值的分母是全部玩家，分子等价于次日回访玩家数，所以查询返回的就是所求比例；最后按要求保留两位小数。

边界与复杂度

  • 仅一位玩家且没有次日记录：结果为 0.00。
  • 玩家首日后隔一天才回来：不计入。
  • games_played = 0 仍是一次登录活动。
  • 跨月、跨年由数据库日期运算正确处理。

设活动记录数为 n、玩家数为 p。逻辑工作量为 O(n) 级扫描与分组；实际执行受索引和数据库优化器影响。首登中间结果占 O(p) 空间。主键 (player_id, event_date) 可支持连接查找。

SELECT ROUND(AVG(a.event_date IS NOT NULL), 2) AS fraction
FROM (
    SELECT player_id, MIN(event_date) AS first_date
    FROM Activity
    GROUP BY player_id
) AS f
LEFT JOIN Activity AS a
  ON a.player_id = f.player_id
 AND a.event_date = DATE_ADD(f.first_date, INTERVAL 1 DAY);
import java.time.LocalDate;
import java.util.*;

class Solution {
    record Activity(int playerId, int deviceId,
                    LocalDate eventDate, int gamesPlayed) {}

    public static double gameplayAnalysis(List<Activity> rows) {
        Map<Integer, LocalDate> first = new HashMap<>();
        Set<String> logged = new HashSet<>();
        for (Activity row : rows) {
            first.merge(row.playerId(), row.eventDate(),
                (a, b) -> a.isBefore(b) ? a : b);
            logged.add(row.playerId() + "@" + row.eventDate());
        }
        long retained = 0;
        for (var entry : first.entrySet()) {
            String key = entry.getKey() + "@" + entry.getValue().plusDays(1);
            if (logged.contains(key)) retained++;
        }
        if (first.isEmpty()) return 0.0;
        return Math.round(retained * 100.0 / first.size()) / 100.0;
    }
}
function gameplayAnalysis(activity) {
  const first = new Map();
  const logged = new Set();
  const dayMs = 24 * 60 * 60 * 1000;
  for (const row of activity) {
    const day = Date.parse(row.event_date + "T00:00:00Z");
    const old = first.get(row.player_id);
    if (old === undefined || day < old) first.set(row.player_id, day);
    logged.add(row.player_id + "@" + day);
  }
  let retained = 0;
  for (const [player, firstDay] of first) {
    if (logged.has(player + "@" + (firstDay + dayMs))) retained++;
  }
  if (first.size === 0) return 0;
  return Math.round((retained / first.size) * 100) / 100;
}
from datetime import date, timedelta
from typing import Iterable, TypedDict

class Activity(TypedDict):
    player_id: int
    device_id: int
    event_date: date
    games_played: int

def gameplay_analysis(rows: Iterable[Activity]) -> float:
    rows = list(rows)
    first: dict[int, date] = {}
    logged = {(r["player_id"], r["event_date"]) for r in rows}
    for row in rows:
        player, day = row["player_id"], row["event_date"]
        if player not in first or day < first[player]:
            first[player] = day
    if not first:
        return 0.0
    retained = sum(
        (player, day + timedelta(days=1)) in logged
        for player, day in first.items()
    )
    return round(retained / len(first) + 1e-12, 2)
#include <algorithm>
#include <cmath>
#include <map>
#include <set>
#include <string>
#include <vector>
using namespace std;

struct Activity {
    int playerId, deviceId, gamesPlayed;
    string eventDate; // ISO YYYY-MM-DD
};

double gameplayAnalysis(const vector<Activity>& rows) {
    map<int, string> first;
    set<pair<int, string>> logged;
    for (const auto& row : rows) {
        if (!first.count(row.playerId) || row.eventDate < first[row.playerId])
            first[row.playerId] = row.eventDate;
        logged.insert({row.playerId, row.eventDate});
    }
    auto nextDay = [](const string& iso) {
        tm t{};
        t.tm_year = stoi(iso.substr(0, 4)) - 1900;
        t.tm_mon = stoi(iso.substr(5, 2)) - 1;
        t.tm_mday = stoi(iso.substr(8, 2)) + 1;
        mktime(&t);
        char out[11];
        strftime(out, sizeof(out), "%Y-%m-%d", &t);
        return string(out);
    };
    int retained = 0;
    for (const auto& [player, day] : first)
        retained += logged.count({player, nextDay(day)});
    if (first.empty()) return 0.0;
    return round(100.0 * retained / first.size()) / 100.0;
}

替代方案

可以用窗口函数 MIN(event_date) OVER (PARTITION BY player_id) 标记首日，再做条件聚合；表达直观，但会让首日值重复出现在每条活动行中，需要额外去重。也可以使用相关 EXISTS，通常最贴近“是否存在次日记录”的语义。相比之下，首登子查询加左连接兼容性好、计数单位清晰。

面试追问

  • 为什么不能直接统计相邻两条记录？ 相邻记录可能相隔多天，且题目锚点必须是首次登录。
  • 如果要算第 7 日留存？ 把日期偏移改为 7 天；若定义为第 1～7 天内回访，则改为日期范围判断并按玩家去重。
  • 如何返回每天的 cohort 留存？ 以 first_date 分组，同时统计各 cohort 的玩家数和命中数。
  • 索引如何设计？ 已有主键 (player_id, event_date) 正好覆盖按玩家求首日及按玩家、日期查找。

常见错误

  • 用所有活动行做分母，导致按活跃次数而非玩家计数。
  • 判断“之后任意一天回来”，遗漏“紧邻第二天”的限制。
  • 内连接后再以连接结果计分母，造成比例恒为 1。
  • 没有先压缩到每位玩家一行，重复计入回访玩家。
  • 使用整数除法，结果只剩 0 或 1。
