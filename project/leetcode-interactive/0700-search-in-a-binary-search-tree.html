01 / Problem

任务是什么？

给定一棵二叉搜索树的根节点 root 和整数 val，请找到值等于 val 的节点，并返回以该节点为根的整棵子树。

如果树中不存在这样的节点，返回 null。在数组展示中，空结果记作 []。

searchBST(root: TreeNode, val: integer) → TreeNode | null
IN root一棵满足 BST 性质的二叉树根节点
IN val需要搜索的整数目标值
OUT TreeNode 或 null命中节点所代表的子树；未命中返回空

EXAMPLE 01

输入
root = [4,2,7,1,3], val = 2
输出
[2,1,3]

EXAMPLE 02

输入
root = [4,2,7,1,3], val = 5
输出
[]

约束

  • 树中节点数在 [1, 5000] 范围内。
  • 1 ≤ Node.val ≤ 107。
  • root 是一棵二叉搜索树。
  • 1 ≤ val ≤ 107。

    已经形成自己的思路了吗？

    题解包含完整过程、证明、复杂度、四种语言代码和面试追问。展开后仍可随时收起，回到独立思考。

    Solution

    把 BST 的顺序性变成“导航”

    搜索过程中无需检查整棵树。每次比较都能排除一个完整子树，因此真正决定成本的是树高，而不是节点总数本身。

    “

    核心洞察

    对任意 BST 节点：左子树所有值更小，右子树所有值更大。若目标小于当前值，只可能在左子树；若目标更大，只可能在右子树；相等时当前节点就是答案。

    完整过程

    1. 令指针 current 指向根节点。
    2. 当 current 非空时，将 val 与 current.val 比较。
    3. 相等就返回 current；目标更小就移动到左孩子；目标更大就移动到右孩子。
    4. 若指针最终变为 null，说明搜索路径上没有目标值，返回 null。

    正确性证明

    1. 循环开始时，若目标存在，它必定位于 current 所代表的子树中；初始时该不变量显然成立。
    2. 当目标小于当前值，BST 性质保证目标不可能位于当前节点或右子树，移动到左子树不会丢失答案；大于时同理。
    3. 若值相等，返回的正是值为 val 的节点及其原有子树；若走到空指针，根据不变量，原树中不存在目标。因此算法总是返回正确结果。

    边界情况

    • 目标就在根节点：第一次比较后直接返回根。
    • 目标位于叶子：返回该叶子节点，其左右孩子均为空。
    • 目标小于最小值或大于最大值：路径最终落到空孩子。
    • 树退化成链：仍然正确，但路径长度可能达到节点数。
    • 题目保证输入是 BST；若此条件不成立，定向排除子树将不再可靠。

    复杂度

    设树高为 h，算法只沿一条根到叶的路径前进。

    时间
    O(h)
    额外空间
    O(1)

    平衡树中 h = O(log n)；最坏的链状树中 h = O(n)。

    替代方案

    • 递归搜索：代码更贴近树定义，但调用栈会占用 O(h) 空间；极深树还可能触发栈深限制。
    • 普通 DFS / BFS：也能找到目标，却没有使用 BST 的有序性，最坏需要访问 O(n) 个节点。

    常见错误

    • 只返回目标值，而不是返回目标节点所代表的子树。
    • 比较方向写反：目标更小时应进入左子树。
    • 未命中时返回原根节点，正确结果应是 null。
    • 递归版本忘记返回递归调用的结果。
    • 误写成完整遍历，失去 BST 搜索的优势。

    四语言完整代码

    均保持 LeetCode 官方提交签名；默认展示 Java，可通过标签切换。

    Java · IterativeTime O(h) · Space O(1)
    /**
 * Definition for a binary tree node.
 * public class TreeNode {
 *     int val;
 *     TreeNode left;
 *     TreeNode right;
 *     TreeNode() {}
 *     TreeNode(int val) { this.val = val; }
 *     TreeNode(int val, TreeNode left, TreeNode right) {
 *         this.val = val;
 *         this.left = left;
 *         this.right = right;
 *     }
 * }
 */
class Solution {
    public TreeNode searchBST(TreeNode root, int val) {
        TreeNode current = root;

        while (current != null) {
            if (current.val == val) {
                return current;
            }
            current = val < current.val
                    ? current.left
                    : current.right;
        }

        return null;
    }
}

    /**
 * Definition for a binary tree node.
 * struct TreeNode {
 *     int val;
 *     TreeNode *left;
 *     TreeNode *right;
 *     TreeNode() : val(0), left(nullptr), right(nullptr) {}
 *     TreeNode(int x) : val(x), left(nullptr), right(nullptr) {}
 *     TreeNode(int x, TreeNode *left, TreeNode *right)

 */
class Solution {
public:
    TreeNode* searchBST(TreeNode* root, int val) {
        TreeNode* current = root;

        while (current != nullptr) {
            if (current->val == val) {
                return current;
            }
            current = val < current->val
                ? current->left
                : current->right;
        }

        return nullptr;
    }
};

    面试追问

    为什么返回节点，而不是只返回布尔值？

    题目要求返回以命中节点为根的子树。返回节点引用既保留了命中值，也保留了它下面的完整结构。

    如果 BST 允许重复值怎么办？

    必须先明确重复值的插入约定。若只需返回任意一个相等节点，当前算法仍可在首次相等时返回；若要找最左或最右重复项，则相等后仍需按约定继续向一侧搜索并记录候选。

    如何同时支持插入操作？

    沿同样的比较路径寻找空孩子；未命中时，把新节点挂到最后一个非空节点的左侧或右侧。若需要长期保持对数复杂度，还要考虑使用 AVL 树或红黑树维持平衡。

    为什么平均复杂度不能一律写成 O(log n)？

    普通 BST 不保证平衡。只有树高为对数级时才是 O(log n)；退化为单链后，树高和搜索时间都会变成 O(n)。
