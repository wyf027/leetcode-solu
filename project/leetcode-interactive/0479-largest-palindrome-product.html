最大回文数乘积Largest Palindrome Product

从两个相同位数的整数出发，寻找它们能够组成的最大回文乘积。先读题，再通过镜像实验观察搜索过程；完整推导保持折叠，按自己的节奏揭晓。

难度：困难 参数：1 ≤ n ≤ 8 返回：答案 mod 1337 非付费题
01 / Problem

问题定义

给定整数 n，返回能表示为两个 n 位整数乘积的最大回文整数。结果可能很大，因此只返回它对 1337 取余后的值。

官方函数形式
largestPalindrome(n: integer) → integer

示例

输入
n = 2
输出
987
解释
99 × 91 = 9009，9009 % 1337 = 987
输入
n = 1
输出
9
Input contract

约束与语义

  • 1 ≤ n ≤ 8
  • 两个因子都必须恰好有 n 位。
  • 先找到真实的最大回文乘积，再做取余。
  • 回文数从左向右、从右向左读取相同。
注意

不能比较“取余后的大小”来决定原始乘积谁更大；取余只发生在答案确定之后。

04 / Solution

准备好揭晓了吗？

题解默认收起，避免第一眼看到核心机制。展开后可阅读证明、复杂度、四语言完整代码与面试追问。

Solution revealed

从“枚举乘积”切换到“枚举回文”

核心洞察：

答案必须是回文。与其枚举近似平方数量的因子对，不如从大到小构造回文候选，再询问“它能否分解成两个 n 位整数”。第一个可分解的候选就是最大答案。

完整过程

  1. 特判 n = 1：最大乘积回文是 9 = 9 × 1，直接返回 9。
  2. 令 upper = 10ⁿ - 1、lower = 10ⁿ⁻¹。对 left 从 upper 递减。
  3. 把 left 的十进制字符反转并拼接到自身后面，得到偶数位回文 pal。例如 90 → 9009。
  4. 若 pal > upper²，它不可能由两个 n 位数相乘，直接跳过。
  5. 让较大因子 factor 从 upper 向下检查。只要 factor² ≥ pal 就仍可能存在因子对；若整除且商不少于 lower，便找到合法分解。
  6. 按回文从大到小搜索，首次命中时返回 pal % 1337。

对于题目限定的 2 ≤ n ≤ 8，最大答案都在上述偶数位镜像序列中。若要把方法推广到任意位数，可按数字长度继续生成奇数位回文；本题不需要那条分支。

为什么正确

引理 1：候选顺序严格递减

固定长度下，前半段 left 越大，镜像得到的完整回文也越大。因此从 upper 向下递减 left，会按严格递减顺序访问所有相关偶数位回文。

引理 2：因子检查不会漏掉合法分解

若 pal = a × b 且令 a ≥ b，则必有 a² ≥ pal。循环检查从 upper 到 ceil(sqrt(pal)) 的每个可能较大因子；一旦整除，再检查商是否仍为 n 位数，因此所有合法因子对都会被覆盖。

定理：返回值对应最大合法回文乘积

由引理 1，搜索顺序从大到小；由引理 2，每个候选是否可由两个 n 位数相乘都被完整判定。因此首次命中的候选不可能存在更大的合法回文。算法最后才取模，所以返回值满足题意。

边界处理

  • n = 1 单独返回 9，避免进入偶数位镜像搜索。
  • 候选大于 upper² 时跳过，避免无意义的因子试除。
  • 整除后必须确认商 ≥ lower；上界自动由被除数与另一因子范围约束，代码中仍显式检查更清楚。
  • JavaScript 的中间值可能超过安全整数范围，必须使用 BigInt。

复杂度

设命中前生成了 H 个回文，每个候选最多试除 F 个可能的较大因子。时间复杂度为 O(H × F × n)（n 来自镜像构造），额外空间为 O(n)。题目把 n 限制到 8，且搜索从乘积上界附近开始，通常很早命中。

class Solution {
    public int largestPalindrome(int n) {
        if (n == 1) return 9;

        long upper = pow10(n) - 1;
        long lower = pow10(n - 1);

        for (long left = upper; left >= lower; left--) {
            long palindrome = mirror(left);
            if (palindrome > upper * upper) continue;

            for (long factor = upper;
                 factor * factor >= palindrome;
                 factor--) {
                if (palindrome % factor == 0) {
                    long other = palindrome / factor;
                    if (other >= lower && other <= upper) {
                        return (int) (palindrome % 1337);
                    }
                }
            }
        }
        return -1;
    }

    private long mirror(long left) {
        long result = left;
        for (long x = left; x > 0; x /= 10) {
            result = result * 10 + x % 10;
        }
        return result;
    }

    private long pow10(int exponent) {
        long value = 1;
        while (exponent-- > 0) value *= 10;
        return value;
    }
}

class Solution:
    def largestPalindrome(self, n: int) -> int:
        if n == 1:
            return 9

        upper = 10 ** n - 1
        lower = 10 ** (n - 1)

        for left in range(upper, lower - 1, -1):
            palindrome = self._mirror(left)
            if palindrome > upper * upper:
                continue

            factor = upper
            while factor * factor >= palindrome:
                if palindrome % factor == 0:
                    other = palindrome // factor
                    if lower <= other <= upper:
                        return palindrome % 1337
                factor -= 1

        return -1

    def _mirror(self, left: int) -> int:
        result = left
        x = left
        while x:
            result = result * 10 + x % 10
            x //= 10
        return result

替代方案

枚举所有因子对

从 upper 开始枚举两个因子，计算乘积后判断回文。直观但重复乘积很多，搜索空间接近平方级。

按约束查表

因为 n 只有 1 到 8，可预先存储八个答案并 O(1) 返回。线上最快，但无法展示答案如何产生，扩展性也弱。

面试追问

  • 为什么只检查到平方根？ 每对因子总有一个不小于平方根，检查较大的那个即可覆盖整对。
  • 偶数位回文还有什么性质？ 它一定能被 11 整除；可据此进一步设计因子步长优化，但要谨慎处理“11 的倍数可能是较小因子”的情况。
  • 如何推广到任意位数？ 按数字长度从大到小，同时生成偶数位与奇数位回文，并使用大整数或溢出检查。
  • 为何不能先取模？ 取模不保序，较大的原数可能得到更小的余数。

常见错误

  • 把 palindrome % 1337 放进最大值比较，破坏原数顺序。
  • 整除后没有检查商是否仍是 n 位数。
  • 用 32 位整数保存 n=8 的乘积，发生溢出。
  • 在 JavaScript 中使用普通 Number 保存 16 位候选，越过安全整数边界。
  • 盲目令因子每次减 11，却没有证明较大因子一定是 11 的倍数，从而漏解。
