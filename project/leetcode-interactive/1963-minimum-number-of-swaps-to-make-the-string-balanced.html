使字符串平衡的
最小交换次数

Minimum Number of Swaps to Make the String Balanced

任意两个位置，一次交换。如何让每一个括号都找到合适的归属？

官方题目 ↗先思考，再展开底部题解

01 / 题目

给定从下标 0 开始的字符串 s，长度 n 为偶数，恰好包含 n / 2 个 [ 和 n / 2 个 ]。一次操作可以交换任意两个下标的字符，操作次数不限。返回让字符串平衡的最少交换次数。

平衡串递归定义为：空串；两个平衡串的连接 AB；或将平衡串 C 包在括号内得到的 [C]。满足其中一种即可。

交换不要求相邻；一次交换无论跨越多远都只计 1 次。你只需返回次数，无需返回操作序列。

参数与约束

  • 参数：s: string；返回：integer；函数名：minSwaps。
  • n == s.length，2 ≤ n ≤ 10⁶，且 n 是偶数。
  • s[i] 只能是 [ 或 ]。
  • 两类括号的数量都恰好是 n / 2。

02 / 官方示例

示例 1

输入：s = "][]["
输出：1

交换下标 0 与 3，得到 [[]]。

示例 2

输入：s = "]]][[["
输出：2

示例 3

输入：s = "[]"
输出：0

已经平衡，无需交换。

04 / 独立题解

准备好后，打开推导、可视化与代码。

核心洞察：修复最深的前缀缺口

把 [ 看作 +1，] 看作 −1，记前缀和为 balance。总和恒为 0；字符串平衡恰好等价于所有前缀和都非负。

设 d = max(0, -所有前缀和的最小值)，也就是某个前缀中右括号比左括号最多多出多少个。最少交换次数为 ⌈d / 2⌉。负前缀的个数并不是答案。

一次把前面的 ] 与后面的 [ 交换，会让两位置之间的前缀和整体增加 2。它能同时修复一整段缺口。

完整过程

  1. 初始化 balance = 0、d = 0。
  2. 从左往右扫描：遇到 [，余额加 1；遇到 ]，余额减 1。
  3. 每次更新 d = max(d, -balance)，保留最深缺口。
  4. 扫描结束后返回 (d + 1) / 2 的整数下取整，也就是向上取整的 d / 2。

例如 s = "]]][[[" 的余额依次是 −1、−2、−3、−2、−1、0，最大缺口为 3，因此需要 2 次交换。字符串总余额虽然是 0，中间仍可能不平衡。

正确性：下界与可达构造

下界。选取原串余额为 −d 的那个前缀。一次任意交换最多让该前缀余额增加 2（把其中的右括号与外面的左括号交换）。最终它必须非负，所以至少需要 ⌈d / 2⌉ 次交换。

可达性。反复消去已经能匹配的 []，剩下的括号一定形如 ]]…][[…[，即 d 个右括号后接 d 个左括号。这里 d 等于扫描时不得不留下的未匹配右括号数量，也等于最大前缀缺口。

当 d ≥ 2 时，将剩余序列的第一个右括号与最后一个左括号交换，两端各能消去一对，剩余规模从 d 降至 d − 2。d = 1 时交换一次即可；d = 0 时不用操作。因此总共 ⌈d / 2⌉ 次可完成。

这些交换可映射回原串中对应的未匹配位置。被消去的部分都是平衡块；把平衡块插回平衡序列任意位置不会破坏平衡。因此这个构造对原串也成立，上界与下界相同。

边界与复杂度

  • 已经平衡时 d = 0，返回 0；最短输入 ][ 时返回 1。
  • d 为奇数时必须向上取整，例如 d = 3 需要 2 次。
  • 最坏输入是所有右括号在前，答案为 ⌈n / 4⌉。
  • 题目保证数量相等，提交代码不需处理非法输入；若两类数量不等，仅交换无法使它平衡。
  • 提交算法时间 O(n)，额外空间 O(1)。演示为支持回放保存前缀状态，使用 O(n) 空间，与提交版本不同。

Java

class Solution {
    public int minSwaps(String s) {
        int balance = 0, deficit = 0;
        for (int i = 0; i < s.length(); i++) {
            balance += s.charAt(i) == '[' ? 1 : -1;
            deficit = Math.max(deficit, -balance);
        }
        return (deficit + 1) / 2;
    }
}

替代方案

未匹配计数：遇到左括号就累加可匹配数；右括号优先抵消可用左括号，否则记录一个未匹配右括号。最终未匹配右括号数量就是 d。时间 O(n)、空间 O(1)。显式栈也可实现，但需要 O(n) 空间。

双指针实际交换：从左向右扫描可变字符数组。余额为负时，将当前右括号与右端尚未使用的左括号交换，计数加 1，余额加 2。右指针只向左移动，总时间 O(n)；若需要复制字符串，空间 O(n)。这适合要求输出交换位置的变体。

常见错误

  • 将负前缀出现次数当答案：][][ 有两个负前缀，但只需一次交换。
  • 使用 d / 2 下取整：d 为奇数时少算一次。
  • 只看最终 balance：本题所有合法输入的最终余额都是 0。
  • 套用相邻交换的距离之和：本题任意远的两位置交换只计一次。
  • 直接把普通前缀余额的负值清零，却仍使用最大缺口公式：这改变了变量含义，不能混用。

面试追问

  • 若只能相邻交换？需要累计左括号向左移动的距离，可维护左括号位置与匹配指针；本题公式不再适用。
  • 如何返回实际操作？采用双指针，把每次选中的两个下标记录下来。
  • 能流式处理吗？能。只需保留余额与最大缺口；若无数量保证，还需检查最终余额。
  • 多种括号能直接套用吗？不能。单一余额无法表达括号类型和嵌套次序。
