字符串中的单词数

Number of Segments in a String

空格看似简单，却很擅长制造边界陷阱。先读清“单词”的特殊定义，再用下方的字符扫描仪观察字符串如何被切成连续片段。

题号 #434 难度：简单 标签：字符串 非付费题

Problem

题目描述

给定一个字符串 s，返回字符串中的片段数量。

片段（segment）定义为一段连续的非空格字符。标点符号、数字和英文字母都可以属于片段；只有普通空格字符 ' ' 会分隔片段。

函数参数：countSegments(s: string) -> integer

官方示例

示例 1

输入s = "Hello, my name is John"
输出5
解释

五个片段为 ["Hello,", "my", "name", "is", "John"]。

示例 2

输入s = "Hello"
输出1
解释

整段字符串是一段连续的非空格字符。

约束

  • 0 <= s.length <= 300
  • s 由大小写英文字母、数字以及 "!@#$%^&*()_+-=',.:" 中的字符组成。
  • s 中唯一可能出现的空白分隔字符是普通空格 ' '。

Solution

一次扫描，统计片段起点

与其把字符串真正切开，不如问一个更轻量的问题：每个片段从哪里开始？只要准确识别所有起点，起点的数量就是片段数量。

核心洞察

位置 i 是片段起点，当且仅当 s[i] != ' '，并且 i == 0 或 s[i - 1] == ' '。

第一个条件保证当前字符属于某个片段；第二个条件保证它前面没有紧邻的非空格字符。因此每个片段只在第一个字符处被计数一次。

完整过程

  1. 初始化计数器 count = 0。
  2. 从左到右遍历字符串的每个位置 i。
  3. 若当前字符不是空格，且它位于字符串开头或前一字符是空格，则发现一个新片段，令 count++。
  4. 遍历结束后返回 count。

正确性证明

  • 不会漏计：任意片段都有唯一的第一个字符。它不是空格，且它要么位于索引 0，要么前一字符是空格，所以算法一定会在这里计数。
  • 不会重复：一个片段中除第一个字符外，其余字符的前一字符都不是空格，因而不会满足计数条件。
  • 不会误计：算法只在非空格字符处计数，所以空格本身不可能被视为片段。

综上，算法计数的位置与所有片段的起点一一对应，因此返回值正确。

边界情况

空字符串

循环不执行，结果为 0。

全部为空格

没有任何非空格字符，结果为 0。

连续多个空格

只有空格后的第一个非空格字符会触发计数。

标点与数字

它们不是分隔符，会和相邻非空格字符属于同一片段。

复杂度

时间复杂度
O(n)

每个字符只访问常数次。

额外空间复杂度
O(1)

只使用索引和计数器。

四种语言完整代码

Java

LeetCode 提交格式
class Solution {
    public int countSegments(String s) {
        int count = 0;

        for (int i = 0; i < s.length(); i++) {
            boolean isNonSpace = s.charAt(i) != ' ';
            boolean startsSegment = i == 0 || s.charAt(i - 1) == ' ';

            if (isNonSpace && startsSegment) {
                count++;
            }
        }

        return count;
    }
}

面试追问

如果分隔符扩展为所有 Unicode 空白字符呢？

把字符是否为空白的判定抽成语言可靠的 Unicode-aware 函数，同时明确按码点还是 UTF-16 代码单元遍历。

如果字符串以流的形式到达，不能整体保存呢？

只需保存“前一个字符是否为空格”的布尔状态和计数器，仍可在线完成，额外空间保持 O(1)。

如何同时返回每个片段的起止位置？

在进入片段时记录起点，在遇到空格或流结束时记录终点；输出本身需要 O(k) 空间，k 为片段数。

常见错误

  • 直接用单个空格分割后返回数组长度，没有处理连续空格产生的空字符串。
  • 把标点符号错误地当成分隔符；本题只有普通空格会分隔片段。
  • 访问 s[i - 1] 前没有先处理 i == 0，导致越界或错误判断。
  • 只在“从片段进入空格”时计数，却忘了字符串可能以片段结尾。
