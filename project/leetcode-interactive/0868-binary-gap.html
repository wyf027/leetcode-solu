二进制间距Binary Gap

在一串 0 与 1 里，真正重要的不是有多少个 0，而是每次遇见 1 时，距离上一次遇见 1 有多远。

单参数：n返回：整数1 ≤ n ≤ 10⁹非付费题
Problem brief

题目要求

先理解“相邻”的特殊含义，再动手扫描。

给定正整数 n，返回它的二进制表示中，任意两个相邻的 1 之间的最大距离；若不足两个 1，返回 0。

这里的“相邻”：在这两个 1 之间不能再出现其他 1，中间可以有任意数量的 0。距离等于两个 1 所在位下标之差。例如 1001 中两个 1 的距离是 3。
Constraints

输入与签名

1 ≤ n ≤ 10⁹

binaryGap(n: integer) → integer

示例 1

输入：n = 22 输出：2

22 = 10110₂；相邻 1 的间距依次为 2、1，最大值为 2。

示例 2

输入：n = 8 输出：0

8 = 1000₂；只有一个 1，不存在可计算的相邻 1 对。

示例 3

输入：n = 5 输出：2

5 = 101₂；两个 1 的位下标之差为 2。

Complete solution

一次扫描，只记住上一个 1

核心洞察

当扫描到当前的 1 时，它只会与“上一个 1”组成一对相邻的 1。因此无需保存所有位置：维护 last 与 answer 两个变量即可。

完整过程

  1. 从最低位开始逐位检查 n。
  2. 遇到 1，若已有 last，用当前下标减去它并更新最大值。
  3. 把当前下标记为新的 last，继续右移。
  4. 扫描结束后返回最大值。

正确性说明

按位下标递增扫描。每当处理到一个 1，last 恰好记录它前面最近的 1，所以二者正是定义中的相邻 1。算法考察每一对相邻 1 并取最大距离，既不会遗漏合法候选，也不会纳入中间夹有其他 1 的非法候选，因此结果正确。

边界与复杂度

  • 只有一个 1：从未形成配对，返回 0。
  • 连续两个 1：距离为 1。
  • 最高位与最低位都为 1：照常由下标差计算。

时间：O(log n)　空间：O(1)

替代方案

也可以先把数字转为二进制字符串，再遍历字符并记录 1 的位置。它同样是 O(log n) 时间，但字符串需要 O(log n) 额外空间；位运算版本更贴合题目主题。还可用“移除最低位 1”的技巧枚举 1，但需要额外计算位位置，可读性未必更好。

class Solution {
    public int binaryGap(int n) {
        int last = -1;
        int answer = 0;
        int index = 0;

        while (n > 0) {
            if ((n & 1) == 1) {
                if (last != -1) {
                    answer = Math.max(answer, index - last);
                }
                last = index;
            }
            n >>= 1;
            index++;
        }
        return answer;
    }
}

常见错误

  • 把任意两个 1 都配对，忽略“中间不能有其他 1”。
  • 把间距误写成中间 0 的个数，少算 1。
  • 用 0 表示“尚未见过 1”，与合法位下标 0 冲突。
  • 更新答案后忘记把 last 移到当前 1。

快速复盘

为什么只比较连续遇到的两个 1？

如果跳过中间某个 1，所选两端之间就包含了另一个 1，不再符合题目对“相邻”的定义。

为什么初始 last 使用 -1？

0 是合法的最低位下标，不能拿来表示“尚未遇到 1”；-1 可以清晰地区分状态。

可以直接使用二进制字符串吗？

可以，复杂度仍然足够好；位运算只是把额外空间降为常数，并更直接地展示逐位扫描。
