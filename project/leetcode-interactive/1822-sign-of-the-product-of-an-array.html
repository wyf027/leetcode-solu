数组元素积的符号

Sign of the Product of an Array 简单

只返回一个符号：1、−1 或 0。先理解问题，再打开底部题解探索过程。

题目

给定整数数组 nums，设所有元素相乘得到 product。请返回 signFunc(product)：乘积为正数时返回 1，为负数时返回 -1，为零时返回 0。

参数：nums: integer[]；返回：integer。函数名：arraySign。

约束

  • 1 ≤ nums.length ≤ 1000
  • -100 ≤ nums[i] ≤ 100

所有元素的乘积为 -1，故返回 -1。

准备好探索了吗？

题解 · 符号翻转机

核心洞察：我们只需要乘积的符号，无需计算乘积本身。正数保持符号，负数翻转符号，零让结果立即归零。

交互：让符号在三条轨道之间移动

每一步读取一个元素。蓝框标记刚处理的元素；符号轨道展示已处理前缀的状态。遇到零就停止，后续元素无需读取。

−1
负数
0
零
+1
正数

完整过程

  1. 初始化 sign = 1，代表尚未处理元素时的乘法单位元。
  2. 从左到右扫描。当前数为 0，立即返回 0。
  3. 当前数小于 0，令 sign = -sign；大于 0 则保持。
  4. 扫描结束后返回 sign。

示例 1 中符号依次为：初始 +1 → −1 → +1 → −1 → +1 → +1 → +1 → +1。四个负数翻转四次，最终为 +1。

正确性

循环不变量：未提前返回时，sign 等于已处理前缀的乘积符号。初始空前缀的乘积为 1，不变量成立。乘以正数不改变符号，乘以负数恰好翻转符号，因此每次更新后不变量继续成立。若读到零，整个数组乘积必为零，提前返回正确。否则遍历完成时前缀就是整个数组，返回值即所求。

边界与复杂度

单元素直接由该元素符号决定；任何位置出现零都返回 0；没有零时负数个数的奇偶性决定答案。数组按约束非空。最坏时间 O(n)，零在前部时可以提前结束；额外空间 O(1)。交互页面保存步骤用于回退，所用 O(n) 空间不属于提交算法。

替代方案

统计负数数量并检查零，最后用奇偶性返回 −1 或 1，同样是 O(n) 时间、O(1) 空间。直接计算完整乘积会在 Java/C++ 中溢出，JavaScript 也会超出数值范围；Python 虽有大整数，却计算了不需要的大数。逐个维护符号更直接。

常见错误

  • 把初始符号设成 0：后续操作无法得到正确的非零符号。
  • 只数负数而忘记零：零的优先级最高。
  • 用 x ≤ 0 统一翻转：零不能作为负数处理。
  • 先求乘积再取符号：中间溢出可能使结果不可靠。

四语言完整提交代码

Java

class Solution {
    public int arraySign(int[] nums) {
        int sign = 1;
        for (int x : nums) {
            if (x == 0) return 0;
            if (x < 0) sign = -sign;
        }
        return sign;
    }
}

JavaScript

/**
 * @param {number[]} nums
 * @return {number}
 */
var arraySign = function(nums) {
    let sign = 1;
    for (const x of nums) {
        if (x === 0) return 0;
        if (x < 0) sign = -sign;
    }
    return sign;
};

面试追问

  • 输入是数据流？只维护一个符号，读到零即可确定答案。
  • 支持修改元素后的查询？维护零的数量及负数数量，替换时扣除旧元素贡献、加入新元素贡献，查询 O(1)。
  • 支持区间查询？使用线段树保存区间符号，合并操作是符号相乘，零自然传播。
