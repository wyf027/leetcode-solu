Complete solution

题解：从最长的全 1 表示开始

核心洞察

若 n 在 k 进制下由 m + 1 个 1 组成，那么：

n = 1 + k + k² + … + kᵐ = (kᵐ⁺¹ − 1) / (k − 1)

对固定的 m，上式左边关于 k 严格递增，因此可以二分候选进制。为了得到最小进制，应从最大的 m 向下枚举：位数越多，对应进制越小。

完整过程

  1. 把字符串解析为整数 N。因为 N ≤ 10¹⁸，全 1 表示的最大指数为 ⌊log₂N⌋。
  2. 令 m 从 ⌊log₂N⌋ 递减到 2，尝试寻找拥有 m + 1 位的表示。
  3. 固定 m 后，在合法区间内二分 k。每次用逐项乘法计算 1 + k + … + kᵐ，并在超过 N 时及时停止或使用更宽整数，避免溢出。
  4. 若几何和等于 N，立即返回当前 k。
  5. 若所有 m ≥ 2 都失败，返回 N − 1；因为任何 N 在 N − 1 进制下都是 11。

复杂度

时间：O((log N)²)。外层至多 O(log N) 个指数；每个指数的“二分次数 × 求和项数”为 O(log N)。

空间：O(1) 额外空间，不计语言大整数的内部存储。

边界

  • N = 3 时答案是 2。
  • N = 2ᵗ − 1 时答案是 2。
  • 若不存在三位以上的表示，兜底答案必为 N − 1。
  • JavaScript 必须用 BigInt，不能直接依赖 Number。

正确性证明

引理 1：方程等价N 的 k 进制是 m + 1 个 1，当且仅当 N = Σᵢ₌₀ᵐ kⁱ；这正是进制位权展开。
引理 2：固定 m 时二分完备当 k ≥ 2 时，Σkⁱ 随 k 严格递增。二分比较不会跳过唯一可能的解。
引理 3：先找到的进制最小若位数更多的解使用的进制不小于位数更少的解，它的几何和会严格更大，不可能都等于同一个 N。所以按 m 降序找到的首个解拥有最小进制。
定理算法对每个可能的多位长度完整搜索并返回首个解；若没有更长表示，N = 1 + (N − 1) 保证兜底成立。故返回值恰为最小好进制。

替代方案

可对每个 m 只取 ⌊N^(1/m)⌋ 附近的整数候选并校验，省掉内层二分。但浮点开方在 10¹⁸ 附近可能舍入，必须检查相邻值或实现整数开方。

也可以使用整数牛顿法求 m 次根。它更快但实现复杂度更高，面试里通常不如“整数边界 + 二分 + 防溢出求和”稳妥。

常见错误

  • 把位数和最高指数混淆：m + 1 位对应最高次 kᵐ。
  • 从短表示开始枚举，提前返回了较大的进制。
  • 使用浮点几何公式直接判断相等，产生精度误判。
  • 逐项乘法未防溢出，比较方向被破坏。
  • JavaScript 用 Number 解析 10¹⁸。

class Solution {
    public String smallestGoodBase(String n) {
        long target = Long.parseLong(n);
        int maxExponent = 63 - Long.numberOfLeadingZeros(target);

        for (int m = maxExponent; m >= 2; m--) {
            long left = 2;
            long right = Math.min(target - 1,
                    (long) Math.pow(target, 1.0 / m) + 1);

            while (left <= right) {
                long base = left + (right - left) / 2;
                int cmp = compareSeries(base, m, target);
                if (cmp == 0) {
                    return Long.toString(base);
                }
                if (cmp < 0) {
                    left = base + 1;
                } else {
                    right = base - 1;
                }
            }
        }
        return Long.toString(target - 1);
    }

    private int compareSeries(long base, int m, long target) {
        long sum = 1;
        long term = 1;
        for (int i = 1; i <= m; i++) {
            // term * base + sum > target：提前返回并避免 long 溢出。
            if (term > (target - sum) / base) {
                return 1;
            }
            term *= base;
            sum += term;
        }
        return Long.compare(sum, target);
    }
}

var smallestGoodBase = function(n) {
    const target = BigInt(n);
    const bitLength = target.toString(2).length;

    const compareSeries = (base, m) => {
        let sum = 1n;
        let term = 1n;
        for (let i = 1; i <= m; i++) {
            term *= base;
            sum += term;
            if (sum > target) return 1;
        }
        if (sum === target) return 0;
        return -1;
    };

    for (let m = bitLength - 1; m >= 2; m--) {
        let left = 2n;
        // target < 2^bitLength，因此该 2 的幂是安全的整数上界。
        let right = 1n << BigInt(Math.ceil(bitLength / m));

        while (left <= right) {
            const base = left + (right - left) / 2n;
            const cmp = compareSeries(base, m);
            if (cmp === 0) return base.toString();
            if (cmp < 0) left = base + 1n;
            else right = base - 1n;
        }
    }
    return (target - 1n).toString();
};

    def smallestGoodBase(self, n: str) -> str:

        max_exponent = target.bit_length() - 1

        def compare_series(base: int, m: int) -> int:
            total = 1
            term = 1
            for _ in range(m):
                term *= base
                total += term
                if total > target:
                    return 1
            return (total > target) - (total < target)

面试追问

为什么最大位数由二进制决定？

合法进制至少为 2。同样位数下，二进制的数值最小；若连二进制的几何和都超过 N，更大进制只会更大。

为什么输入和输出都是字符串？

10¹⁸ 已超过 JavaScript 的安全整数上限。字符串能跨语言无损传输；计算时应转为 BigInt 或足够宽的整数。

能否只检查一个 k？

理论上可取整数 m 次根附近的候选，但需要精确整数开方或校验邻居。二分更容易保证不受浮点误差影响。

怎样进一步强化防溢出？

在乘法前比较 term > (target - sum) / base，或使用更宽整数。超过目标后无需继续累加。
