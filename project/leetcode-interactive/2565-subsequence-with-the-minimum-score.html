最少得分
子序列

从 t 中删掉一些字符，让剩余内容成为 s 的子序列。真正计分的不是删除数量，而是覆盖所有删除位置的最短区间。

Problem

题意

给定两个只含小写英文字母的字符串 s 与 t。可以从 t 中删除任意多个字符；目标是让删除后得到的字符串成为 s 的子序列。

若不删除字符，得分为 0。否则，设所有被删除位置中的最小下标为 left、最大下标为 right，得分为 right - left + 1。返回能达到的最小得分。

子序列：可以删除若干字符，但保留下来的字符相对顺序不能改变。

官方示例

Example 01

删去一个无法衔接的字符

输入：s = "abacaba", t = "bzaa"
输出：1

删除 t[1] = 'z' 后得到 "baa"，它是 s 的子序列；得分为 1 - 1 + 1 = 1，且无法更小。

Example 02

整段删除

输入：s = "cde", t = "xyz"
输出：3

删除下标 0、1、2 的全部字符后得到空串；空串是任意字符串的子序列，得分为 2 - 0 + 1 = 3。

Constraints

约束

  • 1 ≤ s.length, t.length ≤ 10⁵
  • s 和 t 仅由小写英文字母组成。

Core Insight

把任意删除化成一个连续区间

若某个可行方案删除了若干离散位置，那么从最左删除位置到最右删除位置之间的字符全部删掉，得分不变；新字符串只是原可行字符串的子序列，因此仍是 s 的子序列。于是只需寻找最短连续区间 t[l..r)，使：

t[0..l) + t[r..m) 是 s 的子序列

从右向左贪心匹配 t，得到 right[r]：后缀 t[r..m) 能在 s 中匹配时，其首字符可以放到的最靠右位置。再从左向右贪心匹配前缀，并用第二个指针寻找首个能接在前缀之后的后缀。

Walkthrough

完整过程

  1. 1. 令 n = s.length、m = t.length，初始化 right[m] = n，它代表空后缀。
  2. 2. 从 s 与 t 的末尾向前匹配。匹配到 t[j] 时记录它在 s 中的位置到 right[j]；无法匹配的位置保留为 -1。
  3. 3. 枚举保留前缀长度 l。变量 p 是该前缀最后一个字符在 s 中的最早匹配位置，初始为 -1。
  4. 4. 维护不回退的后缀起点 r ≥ l。当 right[r] ≤ p 时，后缀无法接在前缀后面，继续右移 r。
  5. 5. 首个满足 right[r] > p 的位置就是当前 l 下最短可行删除段，长度为 r - l，据此更新答案。
  6. 6. 在 s 中继续寻找 t[l] 来扩展前缀；若找不到，后续更长前缀也不可能，直接结束。

Correctness

正确性证明

引理 1：一定存在删除连续区间的最优方案。对任意可行删除集合，取其最左、最右删除位置并删除整个闭区间，得分不变。新结果是原结果的子序列，而子序列关系具有传递性，所以仍可嵌入 s。

引理 2：固定前缀长度 l 与后缀起点 r，拼接串可嵌入 s 当且仅当 p < right[r]。正向贪心让前缀结束得尽量早，反向贪心让后缀开始得尽量晚，因此若这两个位置仍无法严格错开，就不存在其他匹配方式能错开；若能错开，两段匹配直接拼接即可。

引理 3：对固定 l，循环找到的第一个 r 给出最短可行删除段。更小的 r 已因位置冲突或后缀不可匹配被排除，而删除长度 r-l 随 r 增大。

结论：算法枚举每个可匹配前缀，并取该前缀下最短可行删除段。由引理 1，所有最优答案都在这些连续区间中；由引理 2、3，每次判断与选择都正确，因此最终最小值就是答案。

Complexity

复杂度

时间：O(n + m)。三次指针扫描都只前进或后退，不会重复遍历。

空间：O(m)，用于记录各个后缀的反向贪心位置。

Boundaries

边界情况

  • t 已是子序列：取 l = r，答案为 0。
  • 一个字符也匹配不上：空前缀与空后缀总可行，答案为 m。
  • 只删前缀或后缀：哨兵 p = -1、right[m] = n 自然覆盖。
  • 必须用严格不等式 p < right[r]，同一个 s 位置不能匹配两次。

Implementations

四种语言完整代码

Java 
import java.util.Arrays;

class Solution {
    public int minimumScore(String s, String t) {
        int n = s.length(), m = t.length();
        int[] right = new int[m + 1];
        Arrays.fill(right, -1);
        right[m] = n;

        for (int i = n - 1, j = m - 1; i >= 0 && j >= 0; i--) {
            if (s.charAt(i) == t.charAt(j)) right[j--] = i;
        }

        int answer = m, p = -1, r = 0;
        for (int l = 0; l <= m; l++) {
            r = Math.max(r, l);
            while (r < m && right[r] <= p) r++;
            answer = Math.min(answer, r - l);
            if (l == m) break;

            do { p++; } while (p < n && s.charAt(p) != t.charAt(l));
            if (p == n) break;
        }
        return answer;
    }
}

                p += 1
            if p == n:

Alternatives

替代方案

可以二分删除长度 k，再用前后缀匹配位置检查是否存在某个长度为 k 的可删区间，时间为 O((n + m) log m)。它能通过约束，但线性双指针更直接。

也可以分别构造完整的前缀最早位置数组与后缀最晚位置数组，再用双指针合并；逻辑清晰，但前缀数组并非必需，当前实现用一个位置变量即可。

Pitfalls

常见错误

  • 把目标误解为“删除字符个数最少”，忽略得分覆盖的是整个区间。
  • 只判断前缀和后缀各自可匹配，却没检查二者在 s 中是否前后错开。
  • 把 right[r] > p 写成 ≥ 方向相反或允许相等。
  • 漏掉空前缀、空后缀和答案为零的情况。
  • 对每个 l 都让 r 从头扫描，退化到 O(m²)。

Interview Follow-ups

面试追问

为什么能整段删除？

要求候选人用“继续删除仍保持子序列”证明，而不是凭直觉替换。

为什么两个指针都不回退？

前缀变长时结束位置只会右移，可衔接的后缀起点也不可能左移。

若改为最少删除数量？

问题会变成长公共子序列：答案为 m - LCS(s,t)，一般需要不同方法。

能否把额外空间降到常数？

需要反复重算后缀匹配位置，通常会牺牲线性时间；O(m) 是清晰的时间空间权衡。
