寻找排列Find Permutation

给一串由 I 与 D 组成的方向提示，寻找满足全部相邻大小关系的字典序最小排列。

I当前位置的数小于下一个数（increase）
D当前位置的数大于下一个数（decrease）
Function
findPermutation(s)
Input
s: string
Return
integer[]

01 / BRIEF

题目描述

先把关系读准确，再决定如何构造；这一部分不展开解法。

给定只含字符 'I' 和 'D' 的字符串 s。令 n = s.length，需要返回由整数 1 到 n + 1 各使用一次构成的排列 perm。

s[i] = 'I' ⇒ perm[i] < perm[i + 1]　　s[i] = 'D' ⇒ perm[i] > perm[i + 1]

在所有满足条件的排列中，返回字典序最小的一个。下标按从 0 开始理解。

Example 01
输入s = "I"
输出[1, 2]

唯一的关系要求是 perm[0] < perm[1]，最小排列为 [1, 2]。

Example 02
输入s = "DI"
输出[2, 1, 3]

排列满足 2 > 1 < 3，并且是所有有效排列中字典序最小的。

Constraints
  • 1 <= s.length <= 100000
  • s[i] 只能是 'I' 或 'D'
  • 答案包含 1..s.length + 1 中的每个整数且仅一次

完整题解

核心洞察、证明与代码独立收起，先给你保留思考空间。

Spoiler Gate

准备好后再展开。展开区域包含构造过程、正确性证明、复杂度、替代方案与四种语言实现。

核心洞察：只反转连续下降段

先从最小的自然排列 [1, 2, ..., n + 1] 出发。字符 I 本来就满足；每一段连续的 D 则要求对应的数字区间严格递减。把该区间原地反转，就能满足这一整段下降关系。

关键是：每次只使用当前还未使用的最小一组连续数字，因此不会为了满足关系而提前放入不必要的大数。

完整过程

  1. 构造数组 ans = [1, 2, ..., n + 1]。
  2. 用 start 记录当前待处理片段的左端点，初值为 0。
  3. 从左到右扫描 s。遇到 I 时，把 ans[start..i] 反转，并令 start = i + 1。
  4. 扫描到字符串末尾后，再反转最后的 ans[start..n]，覆盖以 D 结尾的情况。

例如 s = "DIDDI"，自然排列是 [1,2,3,4,5,6]。三个片段依次为 [1,2]、[3,4,5]、[6]，反转后得到 [2,1,5,4,3,6]。

正确性证明

  1. 排列性：算法只反转初始数组中的区间，不增删或重复任何元素，所以结果仍恰好包含 1..n+1。
  2. 关系成立：一个最大连续 D 段对应的连续数字区间被反转，因此段内每一对相邻数字严格递减。两个片段之间由 I 分隔；前片段使用的所有数都小于后片段使用的所有数，所以边界严格递增。
  3. 字典序最小：设当前下降段含 k 个 D，它需要 k+1 个数严格递减。若当前最小未用数为 a，首位至少要到 a+k 才能在其后放下 k 个更小的不同数字。选择连续的 a..a+k 并降序排列，逐位都达到可行的最小值。对每个片段重复这一选择，整个排列即为字典序最小。

边界情况

  • 全是 I：每个片段长度为 1，答案就是自然升序。
  • 全是 D：最后一次反转覆盖整个数组，答案为完全降序。
  • 只有一个字符：分别得到 [1,2] 或 [2,1]。
  • 末尾是 D：必须在扫描结束时处理尚未关闭的下降段。

复杂度

Time
O(n)
每个位置最多参与一次区间反转。
Extra space
O(1)
不计必须返回的答案数组，仅使用常数变量。

四语言完整代码

以下实现都采用“自然排列 + 反转最大下降段”的同一策略。

class Solution {
    public int[] findPermutation(String s) {
        int n = s.length();
        int[] ans = new int[n + 1];
        for (int i = 0; i <= n; i++) {
            ans[i] = i + 1;
        }

        int start = 0;
        for (int i = 0; i <= n; i++) {
            if (i == n || s.charAt(i) == 'I') {
                reverse(ans, start, i);
                start = i + 1;
            }
        }
        return ans;
    }

    private void reverse(int[] nums, int left, int right) {
        while (left < right) {
            int temp = nums[left];
            nums[left++] = nums[right];
            nums[right--] = temp;
        }
    }
}

var findPermutation = function(s) {
    const n = s.length;
    const ans = Array.from({ length: n + 1 }, (_, i) => i + 1);
    let start = 0;

    for (let i = 0; i <= n; i++) {
        if (i === n || s[i] === 'I') {
            let left = start;
            let right = i;
            while (left < right) {
                [ans[left], ans[right]] = [ans[right], ans[left]];
                left++;
                right--;
            }
            start = i + 1;
        }
    }
    return ans;
};

        vector<int> ans(n + 1);
        iota(ans.begin(), ans.end(), 1);

        for (int i = 0; i <= n; ++i) {

                reverse(ans.begin() + start, ans.begin() + i + 1);

替代方案

可以把数字 1..n+1 依次压栈；每当遇到 I 或到达末尾时，将栈全部弹入答案。栈的后进先出恰好翻转当前下降段，时间复杂度同为 O(n)，但显式使用 O(n) 额外空间。上方推演台采用的正是这一等价视角。

面试追问

  • 为什么不能仅在看到一个 D 时交换相邻元素？连续多个 D 会让局部交换难以保持字典序最小，需要识别完整下降段。
  • 若允许使用任意一组互不相同的整数，怎样定义“最小”？必须先明确候选集合或比较规则，否则问题没有唯一最小答案。
  • 能否流式输出？栈方案可以在遇到 I 时输出已关闭片段，但连续 D 段关闭前必须暂存。

常见错误

  • 把长度为 n 的方向串误配成长度为 n 的排列；答案长度应为 n+1。
  • 只在遇到 I 时反转，漏掉字符串末尾未关闭的 D 段。
  • 反转右端点少一位：字符区间 s[start..i-1] 对应数字区间 ans[start..i]。
  • 构造出任意有效排列，却没有验证它是否为字典序最小。
