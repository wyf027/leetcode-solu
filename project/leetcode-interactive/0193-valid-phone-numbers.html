Core insight

整行匹配两种格式

锚点是边界

使用 ^ 与 $ 锁定整行，避免合法片段藏在额外字符中也被误收。

MySQL 不是本题答案：官方提交语言是 Bash

这是 Shell 文件过滤题，没有 Java、JavaScript、Python、C++ 或 SQL 提交入口。主提交使用扩展正则；[0-9] 明确限制 ASCII 数字。

Bash · LeetCode 主提交
grep -E '^(\([0-9]{3}\) |[0-9]{3}-)[0-9]{3}-[0-9]{4}$' file.txt

正则逐段拆解

  • ^：行首；$：行尾。
  • (\([0-9]{3}\) |[0-9]{3}-)： 前缀二选一，分别对应 "(xxx) " 与 "xxx-"。
  • [0-9]{3}-[0-9]{4}：两种格式共用的后七位。
  • grep 默认按输入顺序打印每个匹配行，重复合法行也保留。

兼容实现

awk
awk '/^(\([0-9]{3}\) |[0-9]{3}-)[0-9]{3}-[0-9]{4}$/' file.txt
sed -E
sed -n -E '/^(\([0-9]{3}\) |[0-9]{3}-)[0-9]{3}-[0-9]{4}$/p' file.txt
纯 Bash 循环
pattern='^(\([0-9]{3}\) |[0-9]{3}-)[0-9]{3}-[0-9]{4}$'
while IFS= read -r line; do
    if [[ $line =~ $pattern ]]; then
        printf '%s\n' "$line"
    fi
done < file.txt

复杂度与边界

设文件总字符数为 N，流式扫描时间 O(N)，额外空间为常数级。

  • 括号格式中右括号后必须恰好一个普通空格。
  • 空行、字母、额外国家码、首尾多余字符均不匹配。
  • 题面保证无首尾空白，因此无需先 trim。

常见错误与追问

  • 缺少行首行尾锚点，误收含合法子串的长行。
  • 使用 \d，但基础 grep ERE 不支持该写法。
  • 写成 grep -P，降低跨环境兼容性。
  • 使用 sort/uniq，破坏原顺序或错误删除重复行。
  • 追问：若允许可选国家码，怎样保持整行匹配？
