01 / 题目

只比较区间和，找出唯一的“大数”

题意转述

存在一个长度为 n 的隐藏整数数组。除一个元素外，其余元素都相等；那个例外元素严格更大。你不能直接读取数组，只能通过 ArrayReader 查询数组长度，或比较两个等长子数组的元素和。

实现 getIndex(reader)，返回更大元素的下标。整个过程中调用 compareSub 的次数不得超过 20 次。

交互规则
评测器持有真实数组；提交代码只与 reader 对话，不负责创建或打印数组。

ArrayReader 接口

length()返回隐藏数组的长度。
compareSub(l,r,x,y)比较 [l,r] 与 [x,y] 两个等长闭区间的元素和；左侧更大返回 1，相等返回 0，右侧更大返回 -1。
getIndex(reader)返回唯一较大元素的 0-based 下标。

官方示例 1

隐藏数组（为说明输入而展示）
nums = [7,7,7,7,10,7,7,7]
输出
4

下标 4 的值为 10，其余元素均为 7。

官方示例 2

隐藏数组（为说明输入而展示）
nums = [6,6,12]
输出
2

下标 2 的值 12 是唯一较大的整数。

约束

  • 2 ≤ n ≤ 5 × 10⁵
  • 1 ≤ nums[i] ≤ 100
  • 恰有一个元素严格大于所有其他元素，其他元素彼此相等。
  • compareSub 的两个区间长度必须相同；最多调用 20 次。

03 / 核心洞察

等长区间消掉相同项，只留下“大数在哪边”

每次从候选区间两端取等长的两半比较。较重的一半必含大数；若奇数长度的两半相等，被单独留下的中点就是答案。

令候选区间为 [left, right]，取 half = floor(length / 2)。

若长度为偶数，比较完整覆盖候选区间的左右两半；保留区间和更大的一半。

若长度为奇数，暂时跳过中点，比较其两侧的等长区间。若比较相等，中点就是唯一大数；否则保留更大的一侧。

每次候选规模至少减半。区间缩成一个下标时，返回它。

04 / 正确性

为何每次都不会丢掉答案

不变式

每轮开始时，唯一较大元素的下标始终位于当前候选区间 [left,right] 内。

保持

两侧等长且普通元素相等，因此区间和的差只可能来自较大元素。比较不等时保留较重侧；奇数长度且相等时，大数既不在左侧也不在右侧，只能在中点。

终止

每次保留至多一半候选；若未提前返回，最终 left = right。由不变式，该唯一位置就是答案。

复杂度

时间 / 查询：O(log n) 次 compareSub。

额外空间：O(1)。

当 n ≤ 5 × 10⁵ 时，最多 19 次二分比较，小于 20 次限制。

边界处理

  • 长度为 2：直接比较两个单元素区间。
  • 奇数长度：左右各取 floor(length/2) 个元素，中点不参与比较。
  • 左右和相等只会在奇数长度、且大数位于中点时出现。
05 / 实现

四种语言，同一个区间不变式

/**
 * // This is ArrayReader's API interface.
 * // You should not implement it, or speculate about its implementation.
 * interface ArrayReader {
 *   int compareSub(int l, int r, int x, int y);
 *   int length();
 * }
 */
class Solution {
    public int getIndex(ArrayReader reader) {
        int left = 0, right = reader.length() - 1;

        while (left < right) {
            int len = right - left + 1;
            int half = len / 2;

            if (len % 2 == 0) {
                int leftEnd = left + half - 1;
                int cmp = reader.compareSub(left, leftEnd,
                                            leftEnd + 1, right);
                if (cmp > 0) right = leftEnd;
                else left = leftEnd + 1;
            } else {
                int mid = left + half;
                int cmp = reader.compareSub(left, mid - 1,
                                            mid + 1, right);
                if (cmp == 0) return mid;
                if (cmp > 0) right = mid - 1;
                else left = mid + 1;
            }
        }
        return left;
    }
}

06 / 延伸

替代方案、追问与常见错误

替代方案

逐个比较：把单元素区间两两比较，最坏需要 O(n) 次调用，无法满足最多 20 次查询。

三分思路：也能利用区间和缩小范围，但二分每次保留至多一半，边界更直接，也天然满足查询预算。

面试追问

  • 如果“异常值”可能更小，返回值 0/±1 如何利用？
  • 如果允许两个异常值，这个不变式哪里失效？
  • 为什么 5 × 10⁵ 的规模下 20 次一定够？
  • 怎样把奇偶长度统一成一套下标公式？

常见错误

  • 奇数长度时让左右区间长度不一致，违反 API 前提。
  • 忽略 compareSub 返回 0 的情形，错过中点答案。
  • 更新边界时仍包含已比较分割点，导致死循环。
  • 尝试访问隐藏数组或自行求和；交互题中这些数据不可读。

查询次数推导

每次把候选规模从 m 缩到不超过 ceil(m/2)。所以最多需要 ceil(log₂ n) 次比较。

对 n = 500000，有 2¹⁸ < n < 2¹⁹，故最多 19 次。
