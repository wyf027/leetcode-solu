题意

裁判任务

设计 WordsFrequency 类：构造函数接收由字符串数组表示的一本书； get(word) 返回指定单词出现次数，未出现则返回 0。

  • book[i] 只包含小写字母。
  • 1 <= book.length <= 100000。
  • 1 <= book[i].length <= 10。
  • get 的调用次数不超过 100000。

核心洞察：把重复查询的工作前置

构造函数一次性拿到完整的 book，而 get 最多调用十万次。若每次查询都重新扫描整本书，会重复做同一份工作。构造时建立 单词 → 出现次数 的哈希表，查询只做一次键查找。

完整过程

  1. 创建空哈希表 frequency。
  2. 从左到右遍历 book 中的每个单词。
  3. 把计数设为旧值加一；不存在时旧值按 0 处理。
  4. get(word) 查表；键不存在就返回 0。

第二次遇到 "have" 时不创建新抽屉，而把已有计数从 1 加到 2。

边界

  • 只有一个单词：该词频率为 1，其他词为 0。
  • 全部单词相同：同一个键持续累加。
  • 查询未出现的词：接口要求返回 0，不能返回空值。
  • 严格按完整字符串区分，不做前缀或模糊匹配。
  • 调用次数大时仍不能在 get 内扫描书。

复杂度

构造时间 O(n) 次哈希操作
单次查询 期望 O(1)
额外空间 O(k)，k 为不同单词数

展开字符串哈希成本时还要计入单词长度；本题长度最多 10，通常按常数处理。

替代方案

  • 每次暴力扫描：单次查询 O(n)，多查询不可取。
  • 排序后二分：构造 O(n log n)，查询 O(log n)。
  • 字典树：适合前缀操作；只查完整单词时哈希表更直接。

面试追问

  • 书无法一次载入内存？——流式读取并持续更新哈希表。
  • 还要查询前缀频率？——字典树节点保存经过计数。
  • 需要动态新增单词？——增加 add(word) 并累加。
  • 多线程更新？——并发映射或原子化保护计数。
  • 哈希冲突？——平均 O(1) 依赖良好哈希，容器负责冲突处理。

常见错误

  • 保存书，却在每次 get 中重新遍历。
  • 查不到键时返回 undefined 或抛异常。
  • 忘记累加，只写成 frequency[word] = 1。
  • 误用字典树后返回前缀经过次数。
  • 类名或方法签名与平台要求不一致。

class WordsFrequency {
    private final Map<String, Integer> frequency = new HashMap<>();

    public WordsFrequency(String[] book) {
        for (String word : book) {
            frequency.put(word, frequency.getOrDefault(word, 0) + 1);
        }
    }

    public int get(String word) {
        return frequency.getOrDefault(word, 0);
    }
}

  this.frequency = new Map();
  for (const word of book) {
    this.frequency.set(word, (this.frequency.get(word) || 0) + 1);
  }
};

class WordsFrequency {
private:
    unordered_map<string, int> frequency;

public:
    WordsFrequency(vector<string>& book) {
        for (const string& word : book) {
            ++frequency[word];
        }
    }

    int get(string word) {
        auto it = frequency.find(word);
        return it == frequency.end() ? 0 : it->second;
    }
};
