Solution

一次扫描，记录最近位置

核心洞察

固定右端点 i。分别记录 a、b、c 最近一次出现的位置。如果三者都出现过，设其中最小的位置为 m，那么起点在 0..m 的所有子字符串都包含三种字符，本轮恰好新增 m + 1 个答案。

贡献(i) = min(lastA, lastB, lastC) + 1

为什么看“最小的最近位置”？

三个最近位置中最靠左的那个是瓶颈。起点只要不越过它，另外两个最近位置也一定仍在区间内；一旦越过它，瓶颈字符就会缺失。因此合法起点恰好是一段连续前缀。

Process

完整过程

初始化

令三个最近位置都为 -1，答案为 0。-1 表示该字符尚未出现。

移动右端点

从左到右遍历字符串。读到字符后，只更新对应字符的最近位置。

计算本轮贡献

取三个最近位置的最小值 m。若有字符未出现，m = -1，贡献自然为 0；否则加入 m + 1。

返回累计值

每个合法子字符串都有唯一右端点，因此按右端点分组累加，不重不漏。

正确性证明

引理

固定右端点 i 且三种字符均已出现。设 m 是三个最近位置的最小值，则对任意 l ≤ m，区间 [l, i] 包含三个最近位置，所以包含三种字符。

排除

若 l > m，位于 m 的那种字符在 m 之后、i 之前没有再次出现，否则 m 就不是它的最近位置。因此 [l, i] 缺少该字符。

结论

右端点为 i 的合法起点恰为 0..m，数量为 m+1。遍历全部右端点后覆盖所有合法子字符串，算法正确。

边界与复杂度

→尚未集齐三种字符时，最小值为 -1，贡献为 0。
→重复字符只更新一个最近位置，不会破坏其他状态。
→最短输入长度为 3；若恰含三种字符，答案为 1。
→时间复杂度 O(n)，额外空间复杂度 O(1)。

Implementations

四种语言完整代码

JavaO(n) / O(1)
class Solution {
    public int numberOfSubstrings(String s) {
        int[] last = {-1, -1, -1};
        int answer = 0;

        for (int i = 0; i < s.length(); i++) {
            last[s.charAt(i) - 'a'] = i;
            int earliest = Math.min(last[0],
                    Math.min(last[1], last[2]));
            answer += earliest + 1;
        }
        return answer;
    }
}

PythonO(n) / O(1)
class Solution:
    def numberOfSubstrings(self, s: str) -> int:
        last = [-1, -1, -1]
        answer = 0

        for i, char in enumerate(s):
            last[ord(char) - ord('a')] = i
            answer += min(last) + 1

        return answer

class Solution {

替代方案：滑动窗口

维护窗口内三种字符的计数。每当窗口集齐三种字符，就不断收缩左边界；在固定右端点下，每次收缩前都能推导出一批合法起点。该方案同样为 O(n)，更容易推广到“至少包含给定字符集”的一般问题，但状态和证明略多。

常见错误

×只在第一次集齐三种字符时加 1，漏掉不同起点。
×把相同文本的子字符串去重；题目按位置计数。
×使用最大最近位置计算贡献；瓶颈应是最小最近位置。
×枚举所有子字符串，复杂度达到 O(n²) 或更高。

Interview Follow-ups

面试追问

如果字符集合不再固定为 a、b、c 呢？

可以维护目标字符到最近位置的映射，并追踪所有目标字符最近位置的最小值。目标集合很大时，可用有序结构或带惰性删除的最小堆降低每轮求最小值的成本；也可以改用通用滑动窗口。

为什么答案用 int 足够？

当长度为 5×10⁴ 时，所有子字符串数量上界约为 1.25×10⁹，小于 32 位有符号整数上限。不过在更宽松的变体中，应使用 64 位整数。

如何改成“恰好包含三种字符各一次”？

最近位置公式不再直接适用，因为重复次数也有限制。可用滑动窗口维护各字符频次，并对满足精确频次的窗口做专门计数。
