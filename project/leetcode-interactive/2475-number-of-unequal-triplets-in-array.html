数组中不等三元组的数目

Number of Unequal Triplets in Array

三个下标，三个互不相同的值。先判断什么算一个合法三元组，再打开实验台探索。

01 · 题目

给定下标从 0 开始的正整数数组 nums，返回满足下列两个条件的下标三元组 (i, j, k) 的总数：

  • 0 ≤ i < j < k < nums.length。
  • 选中的三个值两两不同：nums[i] ≠ nums[j]、nums[i] ≠ nums[k] 且 nums[j] ≠ nums[k]。

统计的是下标组合。即使两个合法组合取出的值相同，只要下标组合不同，就分别计数。

示例 1

输入：nums = [4,4,2,4,3]
输出：3

合法下标为 (0,2,4)、(1,2,4)、(2,3,4)，对应的值均两两不同。(2,0,4) 不满足递增下标要求。

示例 2

输入：nums = [1,1,1,1,1]
输出：0

任意三个位置取出的值都相同，没有合法三元组。

约束：3 ≤ nums.length ≤ 100；1 ≤ nums[i] ≤ 1000。

函数：unequalTriplets(nums: integer[]) → integer

04 · 独立题解

核心洞察 · 按下标递增枚举

规模最多 100，只需要枚举全部 i < j < k。三个值的每一对都不相同，就为答案加一。最多检查 C(100,3) = 161700 个候选，因此直接枚举足够。

完整过程

  1. 初始化 ans = 0。
  2. 让 i 从 0 遍历到 n−3。
  3. 固定 i，令 j 从 i+1 遍历到 n−2。
  4. 固定 i、j，令 k 从 j+1 遍历到 n−1。
  5. 三个不等式全部成立时执行 ans++，所有枚举结束后返回 ans。

对 [4,4,2,4,3]，十个候选中只有 (0,2,4)、(1,2,4)、(2,3,4) 各贡献 1，所以答案为 3。数组保持原序，不必排序或去重。

正确性证明

覆盖：任意合法三元组都满足 i < j < k，因此一定落在三层循环的范围内。

唯一：每个递增下标组合恰好对应一次循环迭代；同一组下标的其他排列不会被枚举。

判定：只有三个不等式同时成立才加一，这与题目的两两不同完全等价。每个合法组合被计数一次，每个非法组合被计数零次，所以最终计数正确。

复杂度

时间 O(n³)；额外空间 O(1)。只维护循环下标和计数器。

扫描台为了回退保存候选与前缀计数，额外使用 O(n³) 空间；这属于演示实现，不是提交算法。

边界与数值范围

n = 3 只检查一次；不同值少于三种时答案为 0；全部不同时答案为 C(n,3)。最大答案 161700，四份代码中的计数类型均可容纳。

替代方案 · 按值分组计数

先统计每种值出现的次数，再以任意固定顺序遍历值组。设当前组大小为 b，先前组的元素总数为 a，后续组的元素总数为 c，则当前贡献为 a × b × c。更新 a 并继续。

任何三个不同值组都有唯一的“中间组”，从三组各选一个位置得到一个下标集合，将这三个下标递增排列就对应一个合法三元组。因此无需让值组顺序与原数组下标顺序相同。

哈希统计的期望时间 O(n)，额外空间 O(d)，d 为不同值个数。也可以排序后按连续等值段处理，时间 O(n log n)，空间取决于排序实现；排序会改变原数组。当前约束下三层循环更直接。

四种语言 · 可提交代码

均采用同一套递增下标枚举逻辑；以下代码尚未编译或执行。

Java

class Solution {
    public int unequalTriplets(int[] nums) {
        int n = nums.length, ans = 0;
        for (int i = 0; i < n - 2; i++) {
            for (int j = i + 1; j < n - 1; j++) {
                for (int k = j + 1; k < n; k++) {
                    if (nums[i] != nums[j] &&
                        nums[i] != nums[k] &&
                        nums[j] != nums[k]) {
                        ans++;
                    }
                }
            }
        }
        return ans;
    }
}

常见错误

  • 只比较 i、j 和 j、k：会错误接受 [1,2,1]，必须比较 i、k。
  • 直接写 a != b != c：不能表达三对都不同。Python 链式比较也不包含 a 与 c 的比较。
  • 给数组去重：会丢失原位置的多种选择；[1,1,2,3] 的答案是 2。
  • 让三层循环都从 0 开始：会选到重复下标并重复计算不同排列。
  • 对已有的递增枚举答案再除以 6：每个组合已经只出现一次。

面试追问

如果 n 扩大到十万？改用频次分组法，避免立方级枚举，并检查乘积是否需要 64 位整数；JavaScript 超过安全整数范围时使用 BigInt。

需要返回三元组本身？在判定成功时保存 (i,j,k)，输出量最坏为 Θ(n³)，不能只靠频次总数恢复具体位置。

为什么不按值去重？题目统计位置组合，相同值所在的不同位置可以分别与另外两个值形成合法组合。
