抛掷硬币

Toss Strange Coins — 每枚硬币的正面概率都不同。目标不是模拟运气，而是精确计算正面次数的概率分布。

题号 1230中等会员题动态规划概率与统计
01 · Problem

题目说明

有 n 枚彼此独立的硬币，第 i 枚硬币抛出正面的概率为 prob[i]。每枚硬币恰好抛一次，请返回最终恰好出现 target 个正面的概率。

函数签名： probabilityOfHeads(prob, target) → double
返回浮点数；与正确结果绝对误差不超过 10⁻⁵ 即可接受。

约束

  • 1 ≤ prob.length ≤ 1000
  • 0 ≤ prob[i] ≤ 1
  • 0 ≤ target ≤ prob.length
Official examples

完整参数示例

示例 1

输入：prob = [0.4], target = 1
输出：0.40000
解释：唯一的硬币以 0.4 的概率为正面。

示例 2

输入：prob = [0.5, 0.5, 0.5, 0.5, 0.5], target = 0
输出：0.03125
解释：五枚硬币都为反面的概率是 0.5⁵。

03 · Solution

准备好揭晓确定性解法了吗？

先在实验室里看懂概率如何分流，再展开完整题解。展开后将直接聚焦到题解正文。

Dynamic programming

一维动态规划：让概率沿状态流动

核心洞察

把随机结果压缩成一个确定状态：dp[j] 表示处理完当前若干枚硬币后，恰好出现 j 个正面的概率。

加入正面概率为 p 的新硬币时，旧状态 j 有两条去路：

  • 出反面，正面数不变：贡献 dp[j] × (1-p)。
  • 出正面，正面数加一：贡献 dp[j-1] × p。
next[j] = dp[j] × (1-p) + dp[j-1] × p

完整过程

  1. 初始化 dp[0] = 1，其余为 0。
  2. 依次处理每枚硬币。
  3. 让 j 从 min(i+1,target) 倒序到 0，避免本轮刚更新的值被重复使用。
  4. 所有硬币处理完后返回 dp[target]。

正确性证明

循环不变式：处理完前 i 枚硬币后，dp[j] 等于其中恰好 j 枚为正面的概率。

基础：i=0 时只有空结果，故 dp[0]=1。

归纳：第 i+1 枚硬币要么反面并从旧 j 状态到达，要么正面并从旧 j-1 状态到达；两事件互斥，概率相加正好得到转移式。

终止：处理完全部 n 枚硬币，不变式保证 dp[target] 就是所求。

边界处理

  • target = 0：答案等于所有反面概率之积。
  • p = 0 或 p = 1：转移仍然成立，无需特判。
  • 每轮只更新到当前可能的最大正面数，避免无意义状态。
时间 O(n × target)空间 O(target)

class Solution {
    public double probabilityOfHeads(double[] prob, int target) {
        double[] dp = new double[target + 1];
        dp[0] = 1.0;

        for (int i = 0; i < prob.length; i++) {
            double p = prob[i];
            int upper = Math.min(i + 1, target);
            for (int heads = upper; heads >= 0; heads--) {
                double fromTail = dp[heads] * (1.0 - p);
                double fromHead = heads > 0 ? dp[heads - 1] * p : 0.0;
                dp[heads] = fromTail + fromHead;
            }
        }
        return dp[target];
    }
}

替代方案

二维 DP：dp[i][j] 直接表示前 i 枚硬币恰好 j 个正面，最直观，但空间为 O(n × target)。

递归 + 记忆化：按“当前位置、已有正面数”搜索，易于从题意推导，但函数调用与缓存开销更高。

生成函数：答案是多项式 ∏((1-pᵢ)+pᵢx) 中 xᵗᵃʳᵍᵉᵗ 的系数；数学表达漂亮，本题规模下普通 DP 更实用。

面试追问与常见错误

  • 为什么倒序？ 正序会读到本轮已更新的 dp[j-1]，相当于一枚硬币被重复使用。
  • 能否提前截断？ 可以，只保留 0 到 target；正面数一旦超过 target，不可能再减少。
  • 错误：把不同路径概率直接平均，或忘记反面因子 1-p。
  • 错误：用排列组合公式假设所有硬币概率相同。
  • 数值问题：使用浮点数累加；不要转成整数百分比。
