查找可享受优惠的用户

The Users That Are Eligible for Discount

一张购买记录表，一个活动时间窗口。请找出真正获得优惠资格的用户，注意活动结束的那个瞬间。

先读规则并预测结果，再逐步观察。完整题解位于页面底部，默认折叠。

01 / Problem

任务与数据契约

给定 Purchases 表及参数 startDate DATE、endDate DATE、minAmount INT。如果某用户至少有一笔购买同时满足时间处于指定闭区间、金额不少于门槛，则该用户可以享受优惠。输出一列 user_id，每位用户仅出现一次，按数值升序排列。

Purchases 表结构
字段类型含义
user_idINT用户编号
time_stampDATETIME购买时间
amountINT单笔支付金额
时间边界属于题意，不是实现细节。

两个 DATE 参数都转换为当天 00:00:00。结束日期当天午夜可计入，午夜之后的记录不可计入；金额恰等于 minAmount 可计入。

约束与接口说明

  • (user_id, time_stamp) 是组合主键，同一用户可有不同时间的多笔购买。
  • 资格由单笔购买决定，不能将多笔小额购买相加后判断。
  • 题目公开资料未列出行数、金额或日期的具体数值范围；本页不编造这些上限。
  • MySQL 公开模板为 getUserIDs(startDate DATE, endDate DATE, minAmount INT) 存储过程。元数据内部名称为 find_valid_users，且代码签名字段为空；提交时以平台当前 SQL 编辑器模板为准。

05 / Solution

完成思考，再展开题解

包含 SQL、正确性论证与四语言本地语义参考。

题解：筛选记录，再生成用户名单

核心洞察

资格是“存在一笔合格购买”。因此先在购买记录上同时判断时间和金额，再对用户编号去重、升序排列。两项条件必须由同一行满足。

完整过程

  1. 把起止日期理解为两个午夜时间点。
  2. 保留 startDate ≤ time_stamp ≤ endDate 且 amount ≥ minAmount 的行。
  3. 投影出 user_id，使用 DISTINCT 消除同一用户的重复记录。
  4. 使用 ORDER BY user_id ASC 排序。官方示例只保留用户 3 的 3 月 18 日购买，因此得到一行 3。

正确性

可靠性：输出的每个编号均来自被筛选保留的某条记录；该行同时满足闭区间与单笔金额要求，因此该用户有优惠资格。

完整性：任何有资格的用户都存在至少一笔满足要求的购买，该行不会被筛掉，其编号必定进入输出集合。

唯一与有序：DISTINCT 只删除重复编号，不删除用户的唯一代表；ORDER BY 保证剩余编号升序。因此返回的表恰好满足所有输出要求。逐行模型的不变式为：处理前 k 行后，集合恰好包含这 k 行中存在合格购买的用户。

边界与常见错误

  • 不能写成严格大于金额门槛，否则漏掉相等金额。
  • 不能写 DATE(time_stamp) <= endDate 或把结束时间延长到次日；这会纳入结束日午夜之后的购买。
  • 不能用 SUM(amount) 判断，也不能让一行满足日期、另一行满足金额。
  • 不能省略去重或排序。JavaScript 默认排序按字符串比较，必须提供数值比较器。
  • 没有合格购买或表为空时返回空结果表；起止日期相等时只覆盖当日午夜。
  • 参考代码假定输入类型正确且非空；SQL 对 NULL 比较得到 UNKNOWN，不会通过 WHERE。通用语言如需处理可空源数据，须另行映射这一语义。

复杂度与数据库执行差异

设购买记录数为 n，合格用户数为 u。线性扫描加哈希集合的本地模型通常为期望 O(n + u log u) 时间、O(u) 额外空间；Java TreeSet 与 C++ set 的插入为 O(log(u+1))，总时间 O(n log(u+1) + u)。空输出时仍需 O(n) 扫描。

SQL 不保证具体执行计划。无合适索引时需要扫描数据，去重可能使用排序或哈希，排序实现可达 O(n log n)，临时空间可达 O(n)。已有时间索引可能减少读取量，实际成本取决于选择率、索引和执行计划，不能将本地模型的复杂度直接当作数据库保证。

替代方案

在相同 WHERE 条件后写 GROUP BY user_id ORDER BY user_id 也能去重；这里 DISTINCT 更直接。如果业务已有完整用户表，可用相关 EXISTS 判断该用户是否存在合格购买。没有必要为本题额外引入用户表或先聚合购买金额。

面试追问

  • 改成包含结束日全天？ 改用小于结束日次日午夜的半开区间，避免依赖秒或微秒精度；这属于新需求。
  • 只求人数？ 用 COUNT(DISTINCT user_id)，不再返回明细列表。
  • 数据量很大？ 结合时间过滤选择率考察 time_stamp 起始的索引与覆盖索引，并用执行计划评估；不能假定两个范围条件都能充分使用同一复合索引。
  • 需要按地区时区理解日期？ 先明确业务时区并统一比较基准。原题的 DATETIME 不携带时区。

MySQL · 可提交的存储过程

CREATE PROCEDURE getUserIDs(
    startDate DATE, endDate DATE, minAmount INT
)
BEGIN
    SELECT DISTINCT user_id
    FROM Purchases
    WHERE time_stamp >= startDate
      AND time_stamp <= endDate
      AND amount >= minAmount
    ORDER BY user_id ASC;
END;

Java · 本地语义参考

import java.time.LocalDate;
import java.time.LocalDateTime;
import java.util.ArrayList;
import java.util.List;
import java.util.TreeSet;

// 本地语义参考；不是本题的 Java 提交接口。Java 17+
public class Solution {
    public record Purchase(int userId, LocalDateTime timeStamp, int amount) {}

    public static List<Integer> getUserIDs(
            List<Purchase> purchases, LocalDate startDate,
            LocalDate endDate, int minAmount) {
        LocalDateTime start = startDate.atStartOfDay();
        LocalDateTime end = endDate.atStartOfDay();
        TreeSet<Integer> ids = new TreeSet<>();
        for (Purchase p : purchases) {
            if (!p.timeStamp().isBefore(start)
                    && !p.timeStamp().isAfter(end)
                    && p.amount() >= minAmount) {
                ids.add(p.userId());
            }
        }
        return new ArrayList<>(ids);
    }
}

JavaScript · 本地语义参考

// 本地语义参考；不是本题的 JavaScript 提交接口。
// purchases: [{user_id, time_stamp, amount}]
// 日期为 YYYY-MM-DD，时间戳为 YYYY-MM-DD HH:mm:ss；同一时区、非空。
function getUserIDs(purchases, startDate, endDate, minAmount) {
  const start = startDate + " 00:00:00";
  const end = endDate + " 00:00:00";
  const ids = new Set();
  for (const p of purchases) {
    if (p.time_stamp >= start && p.time_stamp <= end
        && p.amount >= minAmount) {
      ids.add(p.user_id);
    }
  }
  return [...ids].sort((a, b) => a - b);
}

Python · 本地语义参考

from datetime import date, datetime, time

# 本地语义参考；不是本题的 Python/Pandas 提交接口。
# purchases: [(user_id: int, time_stamp: datetime, amount: int)]
# 所有时间采用无时区 datetime，字段非空。
def get_user_ids(purchases: list[tuple[int, datetime, int]],
                 start_date: date, end_date: date,
                 min_amount: int) -> list[int]:
    start = datetime.combine(start_date, time.min)
    end = datetime.combine(end_date, time.min)
    return sorted({
        user_id for user_id, stamp, amount in purchases
        if start <= stamp <= end and amount >= min_amount
    })

C++ · 本地语义参考

#include <set>
#include <string>
#include <vector>
using namespace std;

// 本地语义参考；不是本题的 C++ 提交接口。
// 固定 YYYY-MM-DD HH:mm:ss 格式、同一时区、非空。
struct Purchase {
    int user_id;
    string time_stamp;
    int amount;
};

vector<int> getUserIDs(const vector<Purchase>& purchases,
                       const string& startDate,
                       const string& endDate, int minAmount) {
    const string start = startDate + " 00:00:00";
    const string end = endDate + " 00:00:00";
    set<int> ids;
    for (const auto& p : purchases) {
        if (p.time_stamp >= start && p.time_stamp <= end
            && p.amount >= minAmount) {
            ids.insert(p.user_id);
        }
    }
    return vector<int>(ids.begin(), ids.end());
}
