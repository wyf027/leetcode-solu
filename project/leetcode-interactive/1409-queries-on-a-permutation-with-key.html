查询带键的排列

Queries on a Permutation With Key

每次查询一个数字：先报告它当前的位置，再把它提到队首。看似只是“找一下、挪一下”，核心是保持排列状态与查询结果的先后顺序。

题目描述

给定正整数数组 queries，其中每个值都在 1 到 m 之间。初始排列为 P = [1, 2, 3, …, m]。

按顺序处理每个 queries[i]：找到该值在当前排列 P 中的零基下标，把这个下标加入答案，然后把该值移动到排列开头。返回全部查询对应的下标。

函数形式：processQueries(queries, m) → int[]
记录的是移动前的位置；移动会影响后续查询。

官方示例

示例 1
输入：queries = [3,1,2,1], m = 5
输出：[2,1,2,1]
过程：
3 位于 2 → P = [3,1,2,4,5]
1 位于 1 → P = [1,3,2,4,5]
2 位于 2 → P = [2,1,3,4,5]
1 位于 1 → P = [1,2,3,4,5]
示例 2
输入：queries = [4,1,2,2], m = 4
输出：[3,1,2,0]
示例 3
输入：queries = [7,5,5,8,3], m = 8
输出：[6,5,0,7,5]

约束

  • 1 ≤ m ≤ 10³
  • 1 ≤ queries.length ≤ m
  • 1 ≤ queries[i] ≤ m

题解：直接模拟排列

核心洞察题目要求的就是一次真实的列表操作；约束只有 10³，线性查找与移动足够快。
状态定义用数组 P 保存此刻的排列，并保持它始终与题意中的排列完全一致。
更新顺序必须先记录下标，再删除该元素并插入数组头部。

完整过程

  1. 构造 P = [1, 2, …, m]，并准备答案数组。
  2. 对每个查询值 x，在线性数组中找到 x 的下标 pos。
  3. 把 pos 加入答案。
  4. 从 P 删除 x，再把 x 插入最前面。
  5. 处理完所有查询后返回答案。

正确性证明

初始化：算法的 P 是 [1,2,…,m]，与题目规定的初始排列相同。
保持：假设某轮开始时算法的 P 与题目排列一致。算法找到查询值在这个排列中的下标，因此加入答案的值正确；随后删除该值并插到开头，得到的排列也恰好是题目要求的下一状态。
终止：由归纳法，每轮结果都正确，且下一轮状态一致。处理全部查询后，答案数组就是所有查询的正确位置。

边界情况

  • m = 1：唯一元素始终位于下标 0。
  • 查询值已经在队首：记录 0，移动后排列不变。
  • 连续查询同一值：第一次后它已在队首，后续结果为 0。
  • 查询当前末尾元素：记录最大下标 m - 1，再移至队首。

复杂度

设 n = queries.length。每次查找、删除及队首插入均可能扫描或移动 O(m) 个元素，总时间 O(nm)；排列与答案占用 O(m + n) 空间，若不计返回数组则辅助空间为 O(m)。

替代方案

可以给初始元素安排靠后的虚拟位置，把每次查询的元素放到逐渐递减的前置位置，再用树状数组维护每个位置是否被占用。查询某元素前方的占用数就是答案，单次查询和更新均为 O(log(m+n))，总时间 O((m+n)log(m+n))。本题范围较小，直接模拟更短、更稳，也更符合官方提示；当数据规模显著增大时才值得采用树状数组。

面试追问

  • 若 m 和查询数都达到 10⁵，如何用树状数组完成位置统计？
  • 为什么仅保存“值到下标”的映射仍不足以高效处理队首插入？
  • 如果规则改成“移动到末尾”，状态更新和可选数据结构会怎样变化？

常见错误

  • 先移动元素再记录位置，导致答案几乎总是 0。
  • 把题目的零基下标误当成从 1 开始计数。
  • 只计算初始排列中的位置，没有在每轮后更新 P。
  • 删除时按下标或按值处理混淆，尤其在 JavaScript 的 splice 中。

四语言完整代码

import java.util.ArrayList;
import java.util.List;

class Solution {
    public int[] processQueries(int[] queries, int m) {
        List<Integer> permutation = new ArrayList<>();
        for (int value = 1; value <= m; value++) {
            permutation.add(value);
        }

        int[] answer = new int[queries.length];
        for (int i = 0; i < queries.length; i++) {
            int position = permutation.indexOf(queries[i]);
            answer[i] = position;
            int value = permutation.remove(position);
            permutation.add(0, value);
        }
        return answer;
    }
}
/**
 * @param {number[]} queries
 * @param {number} m
 * @return {number[]}
 */
var processQueries = function(queries, m) {
    const permutation = Array.from({ length: m }, (_, i) => i + 1);
    const answer = [];

    for (const value of queries) {
        const position = permutation.indexOf(value);
        answer.push(position);
        permutation.splice(position, 1);
        permutation.unshift(value);
    }
    return answer;
};
from typing import List


class Solution:
    def processQueries(self, queries: List[int], m: int) -> List[int]:
        permutation = list(range(1, m + 1))
        answer = []

        for value in queries:
            position = permutation.index(value)
            answer.append(position)
            permutation.pop(position)
            permutation.insert(0, value)

        return answer
class Solution {
public:
    vector<int> processQueries(vector<int>& queries, int m) {
        vector<int> permutation(m);
        iota(permutation.begin(), permutation.end(), 1);
        vector<int> answer;

        for (int value : queries) {
            auto it = find(permutation.begin(), permutation.end(), value);
            int position = static_cast<int>(it - permutation.begin());
            answer.push_back(position);
            permutation.erase(it);
            permutation.insert(permutation.begin(), value);
        }
        return answer;
    }
};
