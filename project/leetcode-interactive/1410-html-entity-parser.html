HTML 实体解析器HTML Entity Parser

六张“字符替身券”藏在普通文本里。你的任务不是解析整个 HTML，而是精确识别这六种实体，并保持所有其他字符原样。

主题 字符串 · 哈希表参数 text: string返回 string付费 否

01 / Problem

题目说了什么

给定字符串 text，把其中下列六种合法 HTML 字符实体替换为对应字符；不属于清单的内容必须保留。返回替换后的字符串。

&amp;quot;"
&amp;apos;'
&amp;amp;&
&amp;gt;>
&amp;lt;<
&amp;frasl;/

约束

  • 1 <= text.length <= 10^5
  • text 可能包含 256 个 ASCII 字符中的任意字符。

输入text = "&amp; is an HTML entity but &ambassador; is not."

05 / Solution

单次从左到右扫描

核心洞察

实体只可能从 & 开始。因此维护下标 i：若当前位置不是 &，直接加入答案；若是，则检查从这里开始的文本是否等于六个合法实体之一。匹配时写入对应字符并一次跨过整个实体，否则只写入当前的 &。

替换必须“同时发生”。 如果先把 &amp;amp; 变为 &，再处理 &amp;quot;，输入 &amp;amp;quot; 会被错误地二次解码成双引号。单次扫描不会回头处理刚写入答案的字符。

完整过程

  1. 建立六种实体到字符的固定映射，并准备结果缓冲区。
  2. 从左向右扫描。当 text[i] 不是 & 时，复制它并令 i += 1。
  3. 当 text[i] 是 & 时，逐个检查六种实体是否从 i 开始完整匹配。
  4. 若匹配，追加对应字符并让 i 跨过实体；否则追加原字符 &，继续扫描。

正确性说明

循环不变式：每轮开始时，结果缓冲区恰好是前缀 text[0..i) 按题意解析后的文本。

初始化：i = 0，空前缀解析结果为空，不变式成立。

保持：若当前位置开始于合法实体，算法追加其唯一对应字符并越过整个实体；否则，当前位置不构成应替换对象，算法原样追加当前字符。两种情况下，新缓冲区都恰好是扩展后前缀的正确解析结果。

终止：当 i = text.length 时，该前缀就是完整字符串，因此返回值正确。

时间复杂度

O(n)。实体集合及每个实体长度都是常数。

空间复杂度

O(n)，用于构造返回字符串；不计返回值时额外空间为 O(1)。

边界

无实体、连续实体、未知实体、孤立 &、实体样式但缺少分号、&amp;amp;quot;。

class Solution {
    public String entityParser(String text) {
        String[] entities = {
            "&quot;", "&apos;", "&amp;", "&gt;", "&lt;", "&frasl;"
        };
        String[] chars = {"\"", "'", "&", ">", "<", "/"};
        StringBuilder answer = new StringBuilder();

        int i = 0;
        while (i < text.length()) {
            boolean matched = false;
            if (text.charAt(i) == '&') {
                for (int k = 0; k < entities.length; k++) {
                    String entity = entities[k];
                    if (text.startsWith(entity, i)) {
                        answer.append(chars[k]);
                        i += entity.length();
                        matched = true;
                        break;
                    }
                }
            }
            if (!matched) {
                answer.append(text.charAt(i));
                i++;
            }
        }
        return answer.toString();
    }
}

/**
 * @param {string} text
 * @return {string}
 */
var entityParser = function(text) {
    const entities = [
        ["&quot;", '"'],
        ["&apos;", "'"],
        ["&amp;", "&"],
        ["&gt;", ">"],
        ["&lt;", "<"],
        ["&frasl;", "/"]
    ];
    const answer = [];
    let i = 0;

    while (i < text.length) {
        let match = null;
        if (text[i] === "&") {
            match = entities.find(([entity]) => text.startsWith(entity, i));
        }
        if (match !== null) {
            answer.push(match[1]);
            i += match[0].length;
        } else {
            answer.push(text[i]);
            i++;
        }
    }
    return answer.join("");
};

class Solution:
    def entityParser(self, text: str) -> str:
        entities = {
            "&quot;": '"',
            "&apos;": "'",
            "&amp;": "&",
            "&gt;": ">",
            "&lt;": "<",
            "&frasl;": "/",
        }
        answer = []
        i = 0

        while i < len(text):
            match = None
            if text[i] == "&":
                for entity, char in entities.items():
                    if text.startswith(entity, i):
                        match = (entity, char)
                        break

            if match is not None:
                entity, char = match
                answer.append(char)
                i += len(entity)
            else:
                answer.append(text[i])
                i += 1

        return "".join(answer)
C++LeetCode signature
class Solution {
public:
    string entityParser(string text) {
        const vector<pair<string, char>> entities = {
            {"&quot;", '"'},
            {"&apos;", '\''},
            {"&amp;", '&'},
            {"&gt;", '>'},
            {"&lt;", '<'},
            {"&frasl;", '/'}
        };
        string answer;

        for (int i = 0; i < static_cast<int>(text.size());) {
            bool matched = false;
            if (text[i] == '&') {
                for (const auto& [entity, ch] : entities) {
                    if (text.compare(i, entity.size(), entity) == 0) {
                        answer.push_back(ch);
                        i += entity.size();
                        matched = true;
                        break;
                    }
                }
            }
            if (!matched) {
                answer.push_back(text[i]);
                i++;
            }
        }
        return answer;
    }
};

替代方案

  • 字典树：当实体种类很多或会动态扩展时，可以从 & 沿 Trie 匹配。当前只有六个短实体，固定数组更直接。
  • 正则替换：可一次匹配六种实体再回调映射，但不同语言的正则 API 差异更大，且不如显式扫描易于证明。
  • 连续全局替换：实现短，却可能二次解码，除非精心安排顺序；不推荐把正确性依赖在替换顺序上。

面试追问

  • 如果实体集合扩大到几万种，如何把匹配成本与实体长度关联？
  • 如果输入是无法一次装入内存的数据流，怎样处理跨分块的半个实体？
  • 如果要求递归解码（直到不再变化），如何防止无效循环并定义终止条件？
  • 若支持数字实体（如十进制或十六进制字符引用），如何安全校验码点？

常见错误

  • 把所有形如 &...; 的片段都删除或替换，破坏未知实体。
  • 匹配成功后仍只让下标加一，导致实体剩余字符再次进入结果。
  • 对替换后的结果继续扫描，错误地把 &amp;quot; 解码两次。
  • 忘记处理孤立的 &、结尾处不完整实体或相邻实体。
