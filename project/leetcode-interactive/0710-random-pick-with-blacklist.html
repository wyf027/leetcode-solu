黑名单中的随机数

在一个可能大到 109 的整数范围中，避开黑名单，并让每个合法数字被选中的概率完全相同。

01 / 题目

先理解任务，不急着看答案

给定整数 n 和一个元素互不重复的整数数组 blacklist。请从 [0, n - 1] 中随机返回一个不在黑名单里的整数；每个合法整数都必须拥有相同的返回概率。

实现 Solution(int n, int[] blacklist) 完成初始化，并实现无参数方法 int pick()。算法还应尽量减少调用语言内置随机函数的次数。

真正的难点：不能创建长度为 n 的数组，因为 n 可能达到 109；同时也不能靠不断重抽来保证稳定性能。

示例解释

初始化 Solution(7, [2,3,5]) 后，合法集合是 {0,1,4,6}。每次 pick() 都可返回其中任意一个，且四个数字的概率都必须是 1/4。

示例输出只是一条可能的随机序列，并非固定答案。

约束

  • 1 ≤ n ≤ 109
  • 0 ≤ blacklist.length ≤ min(105, n - 1)
  • 0 ≤ blacklist[i] < n
  • blacklist 中所有值互不相同
  • pick 最多被调用 2 × 104 次

03 / 完整题解

压缩随机域，修补黑名单洞

令 bound = n - blacklist.length。每次只在 [0, bound) 中均匀抽一个数：普通白名单数原样返回；落在低区黑名单时，通过哈希表把它换成高区中的白名单数。

1. 随机域恰好够大

合法数字总数就是 bound，因此只需要 bound 个等概率“入口”。

2. 只修补低区坏点

低区白名单直接返回；只有低区黑名单需要映射，空间与黑名单规模相关。

3. 高区白点刚好够用

低区黑点数与高区白点数相等，因此能建立一一对应，不重不漏。

x = uniform integer in [0, bound) answer = remap.contains(x) ? remap[x] : x

完整过程

  1. 计算边界。设 bound = n - B，其中 B 是黑名单长度。
  2. 记录全部黑名单。使用哈希集合，以便 O(1) 判断高区候选值是否不可用。
  3. 从高区末端找白点。指针从 n - 1 向左移动；遇到黑名单就跳过。
  4. 修补低区黑点。对每个小于 bound 的黑名单值 b，令 remap[b] = 当前高区白点，随后继续左移指针。
  5. 一次随机调用完成抽取。均匀生成 x ∈ [0, bound)；若 x 在 remap 中就返回映射值，否则返回 x。

正确性证明

合法性

低区未映射入口本身不是黑名单；映射入口的目标是在高区中显式跳过全部黑名单后选出的白名单。因此算法永远不会返回黑名单值。

一一对应

低区每个白点映射到自身，低区每个黑点映射到互不相同的高区白点。低区黑点数等于高区白点数，所以这些入口恰好覆盖全部合法值。

等概率

随机变量 x 在 bound 个入口上均匀分布，而入口到合法值是一一对应，因此任一合法值的返回概率都是 1 / bound。

终止性

为每个低区黑点寻找目标时，高区始终存在同样数量的白点；指针有限次左移后一定能找到下一个目标。

复杂度

初始化时间O(B)B = blacklist.length
单次 pickO(1)一次随机调用 + 一次哈希查询
额外空间O(B)集合与映射

边界情况

  • 黑名单为空：bound = n，映射表为空。
  • 只剩一个合法数：所有入口（仅一个）最终返回该数。
  • 黑名单集中在高区：无需创建低区映射，但构造时仍要跳过它们。
  • n 极大：算法不创建长度为 n 的数组。
  • 映射顺序可以不同；只要目标互异且均为高区白点，正确性不变。

替代方案

  • 拒绝采样：反复随机直到命中白名单。实现简单，但当黑名单密集时，期望调用次数和尾延迟变差。
  • 排序 + 二分：把抽到的白名单序号还原为实际数字，单次通常为 O(log B)，无需显式重映射。
  • 完整白名单数组：抽取 O(1)，但 O(n) 空间在 n = 109 时不可接受。

四语言完整代码

import java.util.HashMap;
import java.util.HashSet;
import java.util.Map;
import java.util.Random;
import java.util.Set;

class Solution {
    private final int bound;
    private final Map<Integer, Integer> remap = new HashMap<>();
    private final Random random = new Random();

    public Solution(int n, int[] blacklist) {
        bound = n - blacklist.length;
        Set<Integer> black = new HashSet<>();
        for (int value : blacklist) black.add(value);

        int candidate = n - 1;
        for (int value : blacklist) {
            if (value >= bound) continue;
            while (black.contains(candidate)) candidate--;
            remap.put(value, candidate);
            candidate--;
        }
    }

    public int pick() {
        int x = random.nextInt(bound);
        return remap.getOrDefault(x, x);
    }
}

#include <random>
#include <unordered_map>
#include <unordered_set>
#include <vector>
using namespace std;

class Solution {
    int bound;
    unordered_map<int, int> remap;
    mt19937 generator{random_device{}()};

public:
    Solution(int n, vector<int>& blacklist) {
        bound = n - static_cast<int>(blacklist.size());
        unordered_set<int> black(blacklist.begin(), blacklist.end());
        int candidate = n - 1;

        for (int value : blacklist) {
            if (value >= bound) continue;
            while (black.count(candidate)) candidate--;
            remap[value] = candidate;
            candidate--;
        }
    }

    int pick() {
        uniform_int_distribution<int> distribution(0, bound - 1);
        int x = distribution(generator);
        return remap.count(x) ? remap[x] : x;
    }
};

面试追问与常见错误

为什么高区白点数量一定够？

整个合法集合有 bound 个数。低区共 bound 个位置，其中每少一个白点，就会多一个低区黑点；这个缺口恰好由高区白点补上。

如何证明随机性没有被映射破坏？

证明入口到合法值是一一对应即可。对等概率入口应用一个双射，输出仍然等概率。

错误：只记录低区黑名单

构造目标时若不知道高区有哪些黑名单，可能把低区黑点映射到另一个黑点。

错误：使用随机拒绝采样

结果可以等概率，但不满足稳定 O(1) 抽取，也可能每次调用内置随机函数多次。

错误：边界写成 n - B - 1

随机区间应是左闭右开 [0, bound)，共 bound 个入口；Java 的 nextInt(bound) 正好符合。

如果需要可复现随机序列？

将随机数生成器和种子注入 Solution；算法结构不变，但线上安全场景还需选择合适的随机源。
