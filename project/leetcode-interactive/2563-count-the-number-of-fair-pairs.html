统计公平数对的数目

在所有满足 i < j 的下标组合中，统计两数之和落入闭区间 [lower, upper] 的数对数量。

函数countFairPairs
返回类型long
规模上限n = 10⁵
Problem

题目描述

给定一个下标从 0 开始、长度为 n 的整数数组 nums，以及整数 lower、upper。若一对下标 (i, j) 同时满足以下条件，它就是公平数对：

  • 0 ≤ i < j < n
  • lower ≤ nums[i] + nums[j] ≤ upper

返回公平数对的总数。相同数值位于不同下标时，仍属于不同的下标数对。

函数参数

countFairPairs(nums, lower, upper) -> long

nums:  integer[]
lower: integer
upper: integer

约束

  • 1 ≤ nums.length ≤ 10⁵
  • nums.length = n
  • −10⁹ ≤ nums[i] ≤ 10⁹
  • −10⁹ ≤ lower ≤ upper ≤ 10⁹
Examples

官方示例

示例 1

输入：nums = [0,1,7,4,4,5], lower = 3, upper = 6
输出：6
解释：公平数对为 (0,3)、(0,4)、(0,5)、
      (1,3)、(1,4)、(1,5)，共 6 对。

示例 2

输入：nums = [1,7,9,2,5], lower = 11, upper = 11
输出：1
解释：只有 (2,3) 这一对满足条件。

下方内容包含算法洞察、证明、复杂度与四种语言实现。

Solution

排序 + 双指针 + 上界计数

核心洞察

把闭区间计数拆成两个“至多”计数。令 F(x) 表示满足 i < j 且 nums[i] + nums[j] ≤ x 的数对数量，则答案为：

F(upper) − F(lower − 1)

数组排序后，用左右指针计算 F(x)。若两端和不超过 x，那么固定左端时，从 left + 1 到 right 都合法，可一次加入 right − left 对；否则只能把右指针左移。

完整过程

  1. 将 nums 升序排序。
  2. 以 left = 0、right = n − 1 开始计算 F(x)。
  3. 若当前和 ≤ x，累加 right − left，再右移 left；否则左移 right。
  4. 分别求 F(upper) 与 F(lower − 1)，两者相减。

正确性证明

引理 1当 nums[left] + nums[right] ≤ x 时，因数组有序，所有 k∈[left+1,right] 都满足 nums[left]+nums[k]≤x，因此恰好新增 right−left 对。
引理 2当两端和 > x 时，nums[right] 与当前区间内任何更大的左端配对都不合法，因此丢弃 right 不会漏掉合法数对。
结论每一步都完整计入或安全排除至少一个端点；循环结束时 F(x) 恰好统计所有和不超过 x 的数对。区间差因此恰为公平数对数。
时间复杂度
O(n log n)

排序主导；两次扫描均为 O(n)。

额外空间
O(log n)

取决于语言排序实现；双指针本身 O(1)。

计数类型
64 位

最多 n(n−1)/2 对，可能超过 32 位。

边界情况

  • 数组长度小于 2 时，双指针循环不会进入，答案自然为 0。
  • 重复值按下标组合计数，批量加入 right − left 不会去重。
  • 负数不影响排序后的单调性。
  • lower − 1 在题目范围内仍安全；Java/C++ 中仍建议使用 64 位目标值。
  • 实现会对输入数组排序；若调用方必须保留原顺序，应先复制数组。

四语言完整实现

Java

long
import java.util.Arrays;

class Solution {
    public long countFairPairs(int[] nums, int lower, int upper) {
        Arrays.sort(nums);
        return countAtMost(nums, (long) upper)
             - countAtMost(nums, (long) lower - 1);
    }

    private long countAtMost(int[] nums, long target) {
        int left = 0, right = nums.length - 1;
        long count = 0;
        while (left < right) {
            if ((long) nums[left] + nums[right] <= target) {
                count += right - left;
                left++;
            } else {
                right--;
            }
        }
        return count;
    }
}

var countFairPairs = function(nums, lower, upper) {
    nums.sort((a, b) => a - b);

    const countAtMost = (target) => {
        let left = 0;
        let right = nums.length - 1;

                left++;
            } else {
                right--;
            }
        }
        return count;

};

class Solution:

        nums.sort()

        def count_at_most(target: int) -> int:
            left, right = 0, len(nums) - 1
            count = 0
            while left < right:
                if nums[left] + nums[right] <= target:
                    count += right - left

class Solution {
public:
    long long countFairPairs(vector<int>& nums,
                             int lower, int upper) {
        sort(nums.begin(), nums.end());
        return countAtMost(nums, upper)
             - countAtMost(nums, (long long) lower - 1);
    }

private:
    long long countAtMost(const vector<int>& nums,
                          long long target) {
        int left = 0, right = (int) nums.size() - 1;
        long long count = 0;
        while (left < right) {
            if ((long long) nums[left] + nums[right] <= target) {
                count += right - left;
                left++;
            } else {
                right--;
            }
        }
        return count;
    }
};

替代方案

排序后枚举每个右端点 j，在前缀 [0, j) 中分别二分寻找不小于 lower − nums[j] 和大于 upper − nums[j] 的位置，两位置之差就是本轮贡献。总复杂度同为 O(n log n)，但常数通常高于线性双指针扫描。

常见错误

  • 把下标数对误当成不同数值对，错误地去重。
  • 直接计算区间内数量，导致左右边界反复二分或漏掉等号。
  • 批量增加 right − left + 1，把元素与自身配对。
  • Java/C++ 用 32 位类型保存总数或两数之和。

面试追问

为什么能批量计数？追问排序后固定一端时，合法区间为何连续，以及单调性如何保证不漏不重。
若不能修改输入？复制数组再排序，时间不变，显式增加 O(n) 空间。
若有大量区间查询？当前方法每个查询仍需 O(n) 扫描；可讨论值域、频次卷积或离线查询，但需结合约束选择。
