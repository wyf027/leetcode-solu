题目

示例 1
输入：n = "123"
输出："121"
示例 2
输入：n = "1"
输出："0"
0 与 2 同样近，按规则取更小的 0。

约束

  • 1 <= n.length <= 18
  • n 只包含数字且没有前导零
  • n 表示的整数位于 [1, 10^18 - 1]

Solution

题解：五个候选覆盖所有可能

核心洞察

长度为 L 的最近回文，通常由前 ceil(L/2) 位镜像得到。若直接镜像偏在原数一侧，只需再考察“前缀减一”和“前缀加一”的镜像。另有长度改变时的两个边界：10^(L-1)-1（全 9）与 10^L+1（首尾为 1）。因此候选集合至多五个。

完整过程

  1. 把 n 转为整数 x，记长度为 L。
  2. 加入两个跨位数边界候选。
  3. 截取长度 (L+1)/2 的前缀 p。
  4. 分别镜像 p-1、p、p+1。偶数长度镜像整个前缀；奇数长度跳过前缀末位再反转。
  5. 删除 x 自身，按“距离更小优先；距离相同时数值更小优先”选择答案。

正确性说明

固定长度的回文由其左前缀唯一决定，并随前缀单调递增。设原数对应的前缀为 p，任何前缀小于 p-1 的同长度回文都不可能比 mirror(p-1) 更靠近，任何大于 p+1 的也同理；所以同长度只需三个前缀。若最近答案改变位数，唯一靠近边界的回文分别是较短的全 9 和较长的 100...001。候选因此完备。最终比较规则严格实现题目要求，故返回正确答案。

边界处理

  • n = "1" 时较短边界为 0。
  • 10...0 附近，前缀减一可能缩位，边界候选保证得到全 9。
  • 全 9 附近，较长候选 10^L+1 必不可少。
  • 原数本身已经是回文时必须从候选中排除。
  • JavaScript 使用 BigInt，避免超过安全整数范围。

复杂度

只生成常数个、每个长度为 L 的候选：时间 O(L)，额外空间 O(L)（字符串镜像所需）。

class Solution {
    public String nearestPalindromic(String n) {
        long x = Long.parseLong(n);
        int len = n.length(), half = (len + 1) / 2;
        long prefix = Long.parseLong(n.substring(0, half));
        java.util.Set<Long> set = new java.util.HashSet<>();
        set.add(pow10(len - 1) - 1);
        set.add(pow10(len) + 1);
        for (long p = prefix - 1; p <= prefix + 1; p++)
            set.add(mirror(p, len % 2 == 1));
        set.remove(x);
        long best = -1;
        for (long v : set) {
            if (v < 0) continue;
            if (best == -1 || Math.abs(v - x) < Math.abs(best - x)
                || Math.abs(v - x) == Math.abs(best - x) && v < best) best = v;
        }
        return Long.toString(best);
    }
    private long mirror(long p, boolean odd) {
        long result = p, tail = odd ? p / 10 : p;
        while (tail > 0) { result = result * 10 + tail % 10; tail /= 10; }
        return result;
    }
    private long pow10(int e) { long r = 1; while (e-- > 0) r *= 10; return r; }
}

var nearestPalindromic = function(n) {
    const x = BigInt(n), len = n.length, half = Math.ceil(len / 2);
    const prefix = BigInt(n.slice(0, half));
    const candidates = new Set([10n ** BigInt(len - 1) - 1n, 10n ** BigInt(len) + 1n]);
    const mirror = (p) => {
        const s = p.toString();
        const tail = (len % 2 ? s.slice(0, -1) : s).split('').reverse().join('');
        return BigInt(s + tail);
    };
    for (const d of [-1n, 0n, 1n]) if (prefix + d >= 0n) candidates.add(mirror(prefix + d));
    candidates.delete(x);
    let best = null;
    const abs = v => v < 0n ? -v : v;
    for (const v of candidates) {
        if (best === null || abs(v - x) < abs(best - x)
            || (abs(v - x) === abs(best - x) && v < best)) best = v;
    }
    return best.toString();
};
class Solution:
    def nearestPalindromic(self, n: str) -> str:
        x, length = int(n), len(n)
        prefix = int(n[:(length + 1) // 2])
        candidates = {10 ** (length - 1) - 1, 10 ** length + 1}

        def mirror(p: int) -> int:
            s = str(p)
            tail = s[:-1] if length % 2 else s
            return int(s + tail[::-1])

        for p in (prefix - 1, prefix, prefix + 1):
            if p >= 0:
                candidates.add(mirror(p))
        candidates.discard(x)
        return str(min(candidates, key=lambda v: (abs(v - x), v)))

替代方案

从原数向两侧逐个枚举并检查回文，写法直观，却可能走非常远；生成所有同长度回文也会指数级增长。二分查找回文序列可行，但实现和边界处理比常数候选法更复杂。

常见错误

  • 遗漏 999 → 1001 和 1000 → 999 这类跨位数候选。
  • 未排除输入本身，导致回文输入返回自己。
  • 奇数长度镜像时重复中间位。
  • 用 JavaScript Number 处理 18 位整数造成精度损失。
  • 距离相同却没有按数值较小者打破平局。
