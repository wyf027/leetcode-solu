若一个数组的最大值与最小值之差恰好等于 1，称它为和谐数组。给定整数数组 nums，请返回它的所有子序列中，最长和谐子序列的长度。

参数与约束

函数签名

Complete Walkthrough

题解：频次表与相邻值配对

子序列只要求保留相对顺序，不要求连续。对于确定的两个相邻整数，可以把它们在原数组中的所有出现位置全部选入。

核心洞察

和谐子序列的最大值与最小值相差恰好为 1，所以它只能包含两种值：x 与 x + 1。只要两者都出现，最佳长度就是它们出现次数之和。

answer = max(freq[x] + freq[x + 1])

完整过程

  1. 遍历 nums，用哈希表统计每个整数的出现次数。
  2. 遍历频次表中的每个键 x。
  3. 若 x + 1 存在，使用两者频次之和更新答案。
  4. 不存在相邻值时保持答案为 0。

示例推演

[1,3,2,2,5,2,3,7] 的频次是：

1→1 · 2→3 · 3→2 · 5→1 · 7→1

候选 (1,2) 长度为 4，候选 (2,3) 长度为 5；其他值没有右侧相邻值，所以答案为 5。

边界情况

  • 只有一个元素：不存在两种相邻值，返回 0。
  • 所有元素相同：极差为 0，不和谐，返回 0。
  • 负数：哈希键仍可直接使用，不影响判断。
  • 多组候选并列：只需返回共同的最大长度。
  • 值域很大：不要按数值范围创建数组，使用哈希表。

正确性证明

  1. 形态必然性：任意和谐子序列的最大值记为 b、最小值记为 a。由定义 b - a = 1，整数之间没有第三个整数，因此子序列只可能含 a 和 a + 1。
  2. 固定配对的最优性：对任意同时存在的 x 和 x + 1，选取原数组中所有等于这两个值的元素，按原有顺序即构成合法子序列，长度为 freq[x] + freq[x + 1]。少选任何一个都不会得到更长结果。
  3. 全局覆盖：算法枚举每个出现过的 x 并检查 x + 1，因此覆盖所有可能的和谐值对。
  4. 结论：算法对每个候选取得固定值对的最大长度，再取全局最大值，故返回的恰是最长和谐子序列长度。

复杂度

  • 时间：O(n)，统计与枚举频次表各一次。
  • 空间：O(k)，其中 k 是不同整数的数量，最坏为 O(n)。

为什么不是滑动窗口？

原数组未排序时，合法元素不必连续，直接滑窗无法覆盖子序列。排序后可以使用双指针滑窗，但会产生 O(n log n) 的排序成本；哈希计数更直接。

四语言完整实现

JavaHashMap · O(n)
import java.util.HashMap;
import java.util.Map;

class Solution {
    public int findLHS(int[] nums) {
        Map<Integer, Integer> frequency = new HashMap<>();

        for (int value : nums) {
            frequency.put(value, frequency.getOrDefault(value, 0) + 1);
        }

        int best = 0;
        for (Map.Entry<Integer, Integer> entry : frequency.entrySet()) {
            int value = entry.getKey();
            if (frequency.containsKey(value + 1)) {
                best = Math.max(
                    best,
                    entry.getValue() + frequency.get(value + 1)
                );
            }
        }

        return best;
    }
}
JavaScriptMap · O(n)
/**
 * @param {number[]} nums
 * @return {number}

var findLHS = function (nums) {
    const frequency = new Map();

    for (const value of nums) {
        frequency.set(value, (frequency.get(value) ?? 0) + 1);
    }

    let best = 0;
    for (const [value, count] of frequency) {
        if (frequency.has(value + 1)) {
            best = Math.max(best, count + frequency.get(value + 1));
        }
    }

    return best;
};
Python 3Counter · O(n)
from collections import Counter
from typing import List


class Solution:
    def findLHS(self, nums: List[int]) -> int:
        frequency = Counter(nums)
        best = 0

        for value, count in frequency.items():
            if value + 1 in frequency:
                best = max(best, count + frequency[value + 1])

        return best
C++unordered_map · O(n)
#include <algorithm>
#include <unordered_map>
#include <vector>
using namespace std;

class Solution {
public:
    int findLHS(vector<int>& nums) {
        unordered_map<int, int> frequency;

        for (int value : nums) {
            ++frequency[value];
        }

        int best = 0;
        for (const auto& [value, count] : frequency) {
            auto neighbor = frequency.find(value + 1);
            if (neighbor != frequency.end()) {
                best = max(best, count + neighbor->second);
            }
        }

        return best;
    }
};

替代方案：排序 + 双指针

先排序，再维护窗口，使窗口最大值与最小值不超过 1；差值恰好为 1 时更新答案。时间复杂度 O(n log n)，额外空间取决于排序实现。它适合继续追问“如果数据已经有序怎么办”。

替代方案：单遍计数

插入当前值后，立即用 value - 1 与 value + 1 的已有计数更新答案，也能达到 O(n)。但两阶段写法更容易证明，也更不容易漏掉条件。

面试追问

  • 如果“恰好相差 1”改成“不超过 k”，该如何设计？
  • 如果输入是数据流，怎样在线维护当前答案？
  • 若必须返回具体子序列，而不只是长度，需要保存什么信息？
  • 排序方案能否原地完成？它与哈希方案如何权衡？

常见错误

  • 把“子序列”误当成连续“子数组”。
  • 在只有一种值时返回其频次，忽略差值必须恰好为 1。
  • 同时检查 x - 1 和 x + 1 虽不影响最大值，却让逻辑重复。
  • 根据 10⁹ 的值域创建计数数组，造成巨大空间浪费。
  • 在 Java/C++ 中对极端键直接计算 x + 1 时忽视通用整数溢出风险；本题上界为 10⁹，处于安全范围。
