等差三元组的数目

Number of Arithmetic Triplets

从一列递增数字中，找出两段间距都恰好为 diff 的三个位置。

阅读题目动手观察测试与验证官方题目 ↗

01 / PROBLEM

题意与输入边界

给定从下标 0 开始的严格递增整数数组 nums，以及正整数 diff。统计满足以下全部条件的不同下标三元组 (i, j, k) 的数量，返回一个整数。

  • i < j < k
  • nums[j] − nums[i] = diff
  • nums[k] − nums[j] = diff

注意：三元组指的是三个下标。下面会分别标出下标与对应数值，避免混淆。

官方示例 1

输入：nums = [0,1,4,6,7,10], diff = 3
输出：2

下标 (1,2,4) → 数值 (1,4,7)；下标 (2,4,5) → 数值 (4,7,10)。两组的相邻差都为 3。

官方示例 2

输入：nums = [4,5,6,7,8,9], diff = 2
输出：2

下标 (0,2,4) → 数值 (4,6,8)；下标 (1,3,5) → 数值 (5,7,9)。两组的相邻差都为 2。

完整约束

  • 3 ≤ nums.length ≤ 200
  • 0 ≤ nums[i] ≤ 200
  • 1 ≤ diff ≤ 50
  • nums 严格递增，即 nums[i] < nums[i+1]。

04 / SOLUTION

独立题解

准备好后再展开：思路、推导与四语言实现。

核心洞察：起点确定，另外两点就确定

设起点的值为 x，另外两个值只能是 x + diff 和 x + 2 * diff。将全部数值放入哈希集合，然后枚举每个起点，检查这两个值是否都存在即可。

因为数组严格递增且 diff > 0，值的大小关系直接保证下标关系 i < j < k。因此无需搜索所有下标组合，也不要求这三个元素在数组中连续。

完整过程

  1. 建立集合 values = Set(nums)，答案初始化为 0。
  2. 依次枚举数组中的起点值 x。
  3. 如果集合同时包含 x + diff 与 x + 2 * diff，答案加 1。
  4. 枚举完所有起点后，返回答案。可视化的每一步对应一次起点枚举，三格分别表示三个候选值。
nums = [0,1,4,6,7,10], diff = 3
x = 0  → 目标 3、6   → 缺少 3       → 累计 0
x = 1  → 目标 4、7   → 都存在        → 累计 1
x = 4  → 目标 7、10  → 都存在        → 累计 2
x = 6  → 目标 9、12  → 都不存在      → 累计 2
x = 7  → 目标 10、13 → 缺少 13      → 累计 2
x = 10 → 目标 13、16 → 都不存在      → 累计 2

正确性证明

  • 可靠性：每次计数都找到了 x, x+diff, x+2*diff。这三个数的相邻差都等于 diff，且严格增大的值对应严格增大的下标，所以一定合法。
  • 完整性：对任意合法三元组，枚举到其首元素时，另外两个值必然在集合中，因此一定会计数。
  • 唯一性：严格递增使每个值只出现一次。每个三元组的起点唯一，固定起点后另外两个值也唯一，因此不会重复计数。

复杂度与边界

设数组长度为 n。哈希集合构建与遍历的期望总时间为 O(n)，额外空间为 O(n)；哈希查找按平均 O(1) 计算，不承诺退化时仍为线性。没有匹配时自然返回 0；目标大于 200 时，集合查找自然失败。包含 0 不需特殊处理。题目数值范围内，目标最大为 300，四语言代码均无整数溢出问题。

Java

import java.util.HashSet;
import java.util.Set;

class Solution {
    public int arithmeticTriplets(int[] nums, int diff) {
        Set<Integer> values = new HashSet<>();
        for (int x : nums) values.add(x);
        int answer = 0;
        for (int x : nums) {
            if (values.contains(x + diff)
                    && values.contains(x + 2 * diff)) {
                answer++;
            }
        }
        return answer;
    }
}

替代方案

  • 三重枚举：枚举所有 i < j < k 并比较两段差，时间 O(n³)，空间 O(1)。约束小，易理解，但重复检查较多。
  • 有界布尔表：用长度 201 的布尔表标记值是否存在。查询目标前先判断是否 ≤ 200，时间 O(n+U)、空间 O(U)，其中 U=201；本题固定值域下可视为线性时间、常数额外空间。
  • 单调指针：枚举起点，用两个只向右移动的指针分别寻找 x+diff、x+2*diff，比较前检查数组边界。总时间 O(n)，额外空间 O(1)，实现更容易写错边界。

面试追问

  • 如果允许重复值？集合会丢失下标组合数量。若数组仍有序、diff 为正，可以统计各值频次，并对每个不同起点贡献 freq[x] × freq[x+diff] × freq[x+2*diff]。
  • 如果数组无序？值存在不再保证下标顺序。可按中间下标扫描，维护左侧与右侧频次，对每个位置累加 left[x-diff] × right[x+diff]。
  • 如何改成流式处理？在严格递增数据流中，把当前值看作终点，检查已见集合是否包含 x-diff 和 x-2*diff，计数后再插入 x。
  • 如果 diff=0？不属于本题约束；严格递增数组没有合法三元组。如果进一步允许重复，应单独处理三个不同下标的组合。

常见错误

  • 只检查一段差，忘记检查第三个值。
  • 把 diff 理解为下标间隔，或只检查相邻三个元素。
  • 认为共享元素的三元组只能算一次；不同下标组合应分别计数。
  • 使用 Set 后仍用 includes 线性搜索数组，失去期望 O(n) 的优势。
  • 在布尔表方案中直接访问超过 200 的位置，或将有序、无重复的前提遗漏到推广问题中。
