求团队人数Find the Team Size

每位员工都属于一个团队。你的任务不是只统计每个团队，而是为每位员工带回其所在团队的总人数。

EASY付费题MySQL / SQL窗口聚合
Problem brief

题意与数据结构

先理解输入和目标；核心查询与完整题解暂时收在页面底部。

有一张 Employee 表，每行表示一位员工及其所属团队。查询每位员工的 employee_id，并给出其所在团队的成员总数 team_size。

结果包含 employee_id 与 team_size，返回顺序不限。

约束与语义

  • employee_id 是主键，每位员工只出现一次。
  • team_id 是整数；相同值代表同一团队。
  • 输出保留每位员工，而不只是每个团队一行。
  • 官方元数据没有额外数值范围，因此不虚构行数或取值上限。

核心洞察

团队人数是团队级聚合，但输出是员工级明细。普通 GROUP BY 会折叠员工行；窗口函数能计算团队人数，同时保留每一位员工。

关键表达式：

COUNT(*) OVER (PARTITION BY team_id)

完整过程

保留员工明细。
读取原始 employee_id 与 team_id，不先聚合。
按团队划分窗口。
PARTITION BY team_id 将团队 8、7、9 分成独立分区。
计算分区行数。
COUNT(*) 分别得到 3、1、2。
附回每一行。
窗口函数不减少行数，同队员工获得相同 team_size。
SELECT
    employee_id,
    COUNT(*) OVER (PARTITION BY team_id) AS team_size
FROM Employee;

正确性证明

引理：对任意团队 t，按 team_id 划出的对应窗口，包含所有且仅包含 team_id=t 的员工行。

结论：任取员工 e，其窗口恰为所属团队的完整成员集合，COUNT(*) 因而等于团队人数。窗口函数保留 e 的行并附上该计数，所以每位员工的 team_size 都正确。证毕。

边界与复杂度

  • 单人团队计数为 1。
  • 所有人同队时，每行都是总人数。
  • 每人不同队时，每行都是 1。
  • 空表自然返回空结果。

复杂度：逻辑工作量需处理 n 行，时间 O(n)，输出 O(n)。实际数据库可能为分区排序或哈希，排序路径可达 O(n log n)；工作空间通常 O(n)，取决于执行器与索引。

SELECT
    employee_id,
    COUNT(*) OVER (PARTITION BY team_id) AS team_size
FROM Employee;
import java.util.*;

class Solution {
    public int[][] teamSize(int[][] employee) {
        Map<Integer, Integer> count = new HashMap<>();
        for (int[] row : employee) count.merge(row[1], 1, Integer::sum);
        int[][] answer = new int[employee.length][2];
        for (int i = 0; i < employee.length; i++) {
            answer[i][0] = employee[i][0];
            answer[i][1] = count.get(employee[i][1]);
        }
        return answer;
    }
}
/** @param {number[][]} employee @return {number[][]} */
function teamSize(employee) {
  const count = new Map();
  for (const [, teamId] of employee) {
    count.set(teamId, (count.get(teamId) ?? 0) + 1);
  }
  return employee.map(([employeeId, teamId]) =>
    [employeeId, count.get(teamId)]
  );
}
from collections import Counter
from typing import List

class Solution:
    def team_size(self, employee: List[List[int]]) -> List[List[int]]:
        count = Counter(team_id for _, team_id in employee)
        return [[employee_id, count[team_id]]
                for employee_id, team_id in employee]
#include <unordered_map>
#include <vector>
using namespace std;

class Solution {
public:
    vector<vector<int>> teamSize(
        const vector<vector<int>>& employee
    ) {
        unordered_map<int, int> count;
        for (const auto& row : employee) ++count[row[1]];
        vector<vector<int>> answer;
        answer.reserve(employee.size());
        for (const auto& row : employee)
            answer.push_back({row[0], count[row[1]]});
        return answer;
    }
};

替代方案

先聚合再连接：适用于没有窗口函数的数据库，但要将统计表与 Employee 再连接。

SELECT e.employee_id, t.team_size
FROM Employee AS e
JOIN (
  SELECT team_id, COUNT(*) AS team_size
  FROM Employee
  GROUP BY team_id
) AS t ON e.team_id = t.team_id;

相关子查询：对每位员工重新计数同队成员，直观但可能重复扫描，通常不如前两种方案。

面试追问

为什么不用 GROUP BY？

它会把一个团队折叠为一行，丢失员工级输出。

COUNT(*) 还是 COUNT(team_id)？

题目中每行都有团队，结果相同；COUNT(*) 更直接表达行数。

team_id 可为 NULL 呢？

所有 NULL 会处于同一窗口，是否合理要按业务确认。

如何稳定排序？

本题允许任意顺序；有需要可加 ORDER BY employee_id。

常见错误

  • 只 GROUP BY team_id，丢失 employee_id 明细。
  • 写成 COUNT(*) OVER ()，误算全公司人数。
  • 窗口查询之后再次分组，破坏正确粒度。
  • 相关子查询误把同名字段自己与自己比较。
  • 输出 team_id，却遗漏要求的 team_size。
