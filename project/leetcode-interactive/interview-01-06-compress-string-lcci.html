字符串压缩

扫描连续相同字符的每一段，写出“字符 + 次数”；但只有候选结果严格更短时才接受压缩。

双指针游程编码n ≤ 50,000O(n)

题意

把每段连续字符编码为字符和出现次数：s = "aabcccccaaa" 得到 "a2b1c5a3"。若候选没有更短，返回原串：s = "abbccd" 的候选是 "a1b2c2d1"，所以返回 "abbccd"。

官方约束：s.length ∈ [0, 50000]，仅包含大小写英文字母。交互实验台额外允许空格，以 ␠ 可视化；这不改变提交代码的官方前提。

先记住这件事

不能在看到游程后立刻返回。先完成候选串，再判断 candidate.length < s.length。

等长时也要返回原串；这是本题最常见的判定错误。

核心洞察与完整过程

  1. 用 i 指向当前游程的第一个字符。
  2. 右移 j，直到末尾或 s[j] !== s[i]。
  3. 追加 s[i] 和十进制次数 j - i。
  4. 令 i = j，直至全部游程结束；最后严格比较长度。

边界

  • 空串直接返回空串。
  • 单字符的候选 a1 更长。
  • 次数可以是两位或更多位，如 a10。
  • 不要遗漏最后一段。

复杂度、替代方案、面试追问

时间 O(n)：每个指针只向右走。空间 O(n)：候选在最坏情况下可能接近两倍长。替代方案是先计算候选长度，若不可能收益就提前返回；它能减少无效构造，但实现不如主线直接。

追问：如果输入改为可修改字符数组，如何像 443 题一样用写指针原地覆盖？若字符集扩展至 Unicode，应先定义按 UTF-16 码元还是按 Unicode code point 计数。

常见错误

  • 用 <= 接受等长候选。
  • 把次数当作一位数字，漏掉 10 以上的情况。
  • 把不连续的相同字符合并。
  • 循环提前结束，遗漏最后一个游程。
  • 在 Java/Python 中反复不可变字符串相加，造成不必要的二次开销。

class Solution {
    public String compressString(String s) {
        StringBuilder out = new StringBuilder();
        for (int i = 0; i < s.length();) {
            int j = i;
            while (j < s.length() && s.charAt(j) == s.charAt(i)) j++;
            out.append(s.charAt(i)).append(j - i);
            i = j;
        }
        return out.length() < s.length() ? out.toString() : s;
    }
}
var compressString = function (s) {
  const out = [];
  for (let i = 0; i < s.length;) {
    let j = i;
    while (j < s.length && s[j] === s[i]) j++;
    out.push(s[i], String(j - i));
    i = j;
  }
  const candidate = out.join("");
  return candidate.length < s.length ? candidate : s;
};
