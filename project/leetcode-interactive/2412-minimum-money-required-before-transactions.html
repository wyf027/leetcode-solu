Minimum Money Required Before Transactions

钱会先付出，再返还。你能为所有可能的交易顺序准备足够的初始资金吗？

数组·任意顺序保证·官方题目 ↗

01 / THE CHALLENGE

题目说明

给定二维整数数组 transactions，每个元素 transactions[i] = [cost_i, cashback_i] 表示一笔交易：先支付 cost_i，然后收到 cashback_i。每笔交易必须且只能完成一次。

支付前必须满足 money ≥ cost_i；完成后余额变成 money - cost_i + cashback_i。求最小初始金额，使得无论交易以什么顺序执行，都能完成全部交易。返回一个整数。

思考边界：找到一种能完成的顺序，还不足以满足题目要求。

官方示例 1

输入：transactions = [[2,1],[5,0],[4,2]]
输出：10

初始金额为 10 时，每一种顺序都能完成；小于 10 时，存在无法完成的顺序。

官方示例 2

输入：transactions = [[3,0],[0,3]]
输出：3

先做 [3,0] 需要初始 3；先做 [0,3] 则可以从 0 开始。为了保证两种顺序都可行，答案为 3。

约束

  • 1 ≤ transactions.length ≤ 100000
  • transactions[i].length == 2
  • 0 ≤ cost_i, cashback_i ≤ 1000000000

04 / OPTIONAL EDITORIAL

准备好推导了吗？

先尝试说明“任意顺序”与“一种顺序”的差别，再展开核心洞察与实现。

题解 · 累计损失 + 关键交易门槛

1. 核心洞察

只把亏损交易带来的净损失累计起来，记为 L = Σ max(cost - cashback, 0)。对任意一笔关键交易 i，最坏的前缀会先执行其他所有亏损交易，并把赚钱交易留到后面。

令 loss_i = max(cost_i - cashback_i, 0)。在关键交易之前，其他交易最多损失 L - loss_i，因此需要的初始金额是 L - loss_i + cost_i。

答案 = L + max(min(cost_i, cashback_i))

亏损交易贡献的是 cashback；不亏损交易贡献的是 cost。两者统一成 min(cost, cashback)。

2. 完整计算过程

  1. 初始化总损失 loss = 0、额外门槛 extra = 0。
  2. 逐笔读入 [cost, cashback]，把 max(cost - cashback, 0) 加入 loss。
  3. 用 min(cost, cashback) 更新 extra 的最大值。
  4. 返回 loss + extra，无需排序，也不修改输入数组。
读入交易本笔损失累计 lossmin(cost, cashback)extra
[2,1]1111
[5,0]5601
[4,2]2822

结果为 8 + 2 = 10。取 [4,2] 为关键交易，先做 [2,1] 和 [5,0]：初始 9 会变成 8、3，接着无法支付 4；初始 10 则变成 9、4，恰好能继续。这个顺序给出了少 1 元会失败的具体见证。

3. 正确性证明

必要性：固定交易 i，将除 i 以外的所有亏损交易放在最前面，再执行 i。若前缀就失败，已经说明初始金额不够；若前缀成功，到 i 前净损失恰好为 L - loss_i。支付 i 要求初始金额至少为 L - loss_i + cost_i。因此必须对所有 i 取最大值。

充分性：设初始金额为上述最大值 M。对于任意顺序，在执行尚未完成的交易 i 前，已经完成的亏损交易总损失不超过 L - loss_i；不亏损交易只会使余额更多。因此当前余额至少为 M - (L - loss_i) ≥ cost_i。第一笔可执行，且每执行完一笔，下一笔也满足同一不等式，归纳得到全部交易可执行。

化简：cost_i - max(cost_i - cashback_i, 0) = min(cost_i, cashback_i)，所以必要且充分的最小值就是公式中的答案。

4. 边界与数值范围

  • 只有一笔交易时，答案恒为 cost，包括赚钱交易。
  • 所有交易都不亏损时，L = 0，答案为最大的 cost；最大支付额可能排在第一笔。
  • 全部返现为 0 时，答案为所有 cost 的总和。
  • cost = cashback 也需要先垫付，不能直接丢弃。
  • 金额总量可达 1014。Java 用 long，C++ 用 long long；Python 整数自动扩展，JavaScript Number 在此范围内能精确表示整数。不要用 JavaScript 位运算截断金额。

5. 复杂度

时间 O(n)，只扫描一次；额外空间 O(1)，只保留两个累积量。四份代码均不对输入排序。

6. 替代方案

排序构造最坏顺序：亏损交易放在前面，按 cashback 升序排列；不亏损交易放在后面，按 cost 降序排列。再维护前缀净变化 delta，用 need = max(need, cost - delta) 计算固定顺序所需资金。亏损组最后覆盖最大 cashback 的候选，不亏损组第一笔覆盖最大 cost 的候选，因此得到同一答案。时间 O(n log n)，排序空间依语言实现而定。

枚举排列：对每种排列求其最低初始金额，最后取最大值，时间 O(n · n!)、递归空间 O(n)。仅适合很小的数据做后续对照；本轮未执行。

7. 四语言完整代码

Java

class Solution {
    public long minimumMoney(int[][] transactions) {
        long loss = 0;
        long extra = 0;
        for (int[] transaction : transactions) {
            long cost = transaction[0];
            long cashback = transaction[1];
            loss += Math.max(cost - cashback, 0L);
            extra = Math.max(extra, Math.min(cost, cashback));
        }
        return loss + extra;
    }
}

8. 常见错误

  • 把目标理解为“自己挑一个最省钱的顺序”。这里需要防住最坏顺序。
  • 只计算总亏损，漏掉最后一笔交易发生返现之前的支付门槛。
  • 使用 L + max(cost)，对亏损交易把它自身的损失重复算了一次。
  • 把赚钱交易的收益提前扣除；它可能排在最后，无法保证预先拿到。
  • 用 32 位整数累计，或对金额使用位运算，导致溢出或截断。

9. 面试追问

如何给出一个最坏顺序？找到使 min(cost, cashback) 最大的交易 i，先放所有其他亏损交易，再放 i，其余交易随后执行；该顺序要求的初始金额至少为答案。

如果顺序固定？维护已执行交易的净变化 delta，答案为所有 cost_i - delta 的最大值，初值为 0，每步随后累加 cashback_i - cost_i。

如果改成可以自主挑选最好顺序？量词从所有排列改为存在一个排列，本题公式不再适用，需要另行推导顺序策略。

可以流式处理吗？可以。总损失相加、额外门槛取最大值即可，甚至能把不同分片的这两个统计量分别求和与取最大后合并。
