在 LR 字符串中
交换相邻字符

把 X 看作空位，让 L 与 R 在一条轨道上移动。先理解允许的局部交换，再亲手观察两个字符串能否抵达彼此。

XL→LX

L 借空位向左移动一格

RX→XR

R 借空位向右移动一格

Problem

题意

给定两个等长字符串 start 与 result，它们只由 'L'、'R' 和 'X' 组成。每一步可以把一处 "XL" 替换为 "LX"，或把一处 "RX" 替换为 "XR"。

当且仅当存在一系列合法移动，可以把 start 转换为 result 时返回 true，否则返回 false。

函数形式
canTransform(start: string, result: string): boolean

约束

  • 1 <= start.length <= 104
  • start.length == result.length
  • start 与 result 仅包含 'L'、'R'、'X'

示例 1

输入：start = "RXXLRXRXL", result = "XRLXXRRLX"
输出：true
解释：
RXXLRXRXL → XRXLRXRXL → XRLXRXRXL
→ XRLXXRRXL → XRLXXRRLX

示例 2

输入：start = "X", result = "L"
输出：false

Complete Solution

双指针：只追踪真正会移动的字符

1

相对顺序不变

任何操作都只是让字符与 X 交换，L 和 R 彼此无法跨越。因此删掉全部 X 后，两个字符串必须完全相同。

2

L 只能向左

XL → LX 让 L 的下标减小，所以同一个 L 在 start 的位置不能小于它在 result 的位置。

3

R 只能向右

RX → XR 让 R 的下标增大，所以同一个 R 在 start 的位置不能大于它在 result 的位置。

完整过程

  1. 令双指针 i、j 分别从两个字符串的开头出发。
  2. 分别跳过 start 与 result 中的所有 X。
  3. 若两边同时到达末尾，所有有效字符都匹配，返回 true；若仅一边到达末尾，返回 false。
  4. 若 start[i] != result[j]，说明非 X 字符的相对顺序不同，返回 false。
  5. 若当前为 L 且 i < j，它需要向右移动，不合法；若当前为 R 且 i > j，它需要向左移动，也不合法。
  6. 当前字符合法时同时移动两个指针，继续检查下一对非 X 字符。

正确性证明

必要性

合法操作从不交换两个非 X 字符，所以它们的相对顺序不变；同时 L 的位置只能减小，R 的位置只能增大。算法检查的三个条件对任何可达转换都必须成立。

充分性

若非 X 序列相同，并且每个 L 的目标位置不在其右侧、每个 R 的目标位置不在其左侧，那么可按非 X 字符的顺序处理：每个 L 都能连续跨过左侧所需的 X，每个 R 都能连续跨过右侧所需的 X。由于字符相对次序一致，它们不会要求彼此穿越，故能得到目标串。

结论

算法返回 true 当且仅当上述必要且充分的条件全部满足，因此算法正确。

复杂度

时间：O(n)
额外空间：O(1)

边界情况

  • 全部是 X
  • 只有一个非 X 字符
  • 非 X 序列不同
  • 字符序列相同但移动方向非法

替代方案

可以先构造两个非 X 字符及其下标数组，再逐项检查，逻辑更直观但需要 O(n) 空间。BFS 只适合极小输入，不适用于长度 10⁴。

class Solution {
    public boolean canTransform(String start, String result) {
        int n = start.length();
        int i = 0, j = 0;

        while (true) {
            while (i < n && start.charAt(i) == 'X') i++;
            while (j < n && result.charAt(j) == 'X') j++;

            if (i == n || j == n) {
                return i == n && j == n;
            }

            char token = start.charAt(i);
            if (token != result.charAt(j)) return false;
            if (token == 'L' && i < j) return false;
            if (token == 'R' && i > j) return false;

            i++;
            j++;
        }
    }
}

面试追问

为什么只检查位置就足够？

因为非 X 字符的相对顺序锁定了配对关系，而单向位置条件精确描述了每个字符能跨越空位的方向；两类条件合起来既必要又充分。

若规则改成双向移动呢？

如果 L、R 都能与相邻 X 双向交换，那么方向约束消失，只需比较删除 X 后的序列是否相同。

常见错误

  • 只比较删除 X 后的字符串，漏掉 L/R 的单向移动限制。
  • 把方向条件写反：L 非法条件是 startIndex < resultIndex，R 非法条件是 startIndex > resultIndex。
  • 一边先到末尾时直接返回 true；必须确认两边都没有剩余非 X 字符。
  • 真的模拟每一步交换，最坏可能退化为平方级时间。
