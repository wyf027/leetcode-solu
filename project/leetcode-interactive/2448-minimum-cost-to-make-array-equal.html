使数组相等的最小开销

Minimum Cost to Make Array Equal

每一步的价格各不相同。你会让所有数字在哪里相遇？

01 / PROBLEM

题意

给定两个长度均为 n、下标从 0 开始的正整数数组 nums 和 cost。一次操作可以将任意 nums[i] 增加 1 或减小 1，代价为 cost[i]。操作次数不限，返回让所有元素变为同一个数所需的最小总开销。

官方示例 1

nums = [1,3,5,2]
cost = [2,3,1,14]
输出：8

全部变为 2：第 0 项加 1 花费 2；第 1 项减 1 花费 3；第 2 项减 3 花费 3；第 3 项不动。总开销为 8，是最小值。

官方示例 2

nums = [2,2,2,2,2]
cost = [4,2,8,1,3]
输出：0

所有元素已经相等，无须操作。

约束与参数

  • n == nums.length == cost.length
  • 1 ≤ n ≤ 10⁵
  • 1 ≤ nums[i], cost[i] ≤ 10⁶
  • 题目保证输出不超过 2⁵³ − 1。
  • 函数 minCost(nums, cost) 返回最小总开销。

04 / SOLUTION

让开销成为重量：加权中位数

固定共同目标 x 后，第 i 项需要 |nums[i] − x| 步，总开销为 F(x) = Σ cost[i] × |nums[i] − x|。开销越大的元素，拉动目标的力量越大。

把数值和开销配对，按数值排序，依次累计权重。第一个使累计权重达到总权重一半的数值，就是一个最优目标，即加权中位数。使用整数门槛 ceil(W / 2) 即可。

交互实验 · 权重带上的分界线

每段按数值顺序排列，宽度代表开销占比；虚线是 50%。扫描到第一次触及或跨过一半时选定目标，再结算每项代价。极小权重保留最小像素宽度，精确数值以表格为准。

完整过程

  1. 构建 (nums[i], cost[i]) 配对并按数值排序，保持数值与开销一一对应。
  2. 求总权重 W，门槛为 (W + 1) // 2。
  3. 从左向右累加权重，首次满足 prefix ≥ 门槛时，将当前数值设为 target，停止扫描。
  4. 遍历原数组，计算并返回 Σ |nums[i] − target| × cost[i]。

示例 1 排序后为 (1,2), (2,14), (3,3), (5,1)。W = 20，门槛为 10；累计从 2 到 16，选定 2。结算 1×2 + 1×3 + 3×1 + 0×14 = 8。

正确性证明

固定目标：每次操作只改变 1，元素 a 变成 x 至少需要 |a−x| 步，单向移动恰好实现。各项互不干扰，所以 F(x) 是该目标的最小开销。

相邻差分：目标从整数 x 移到 x+1 时，所有 a ≤ x 的元素距离增加 1，所有 a > x 的元素距离减少 1。因此 F(x+1) − F(x) = 2 × Σ(a≤x) w − W。随着 x 增大，差分单调不减，F 先下降、可能持平、再上升。

扫描位置最优：设首次达到门槛的数值为 t。在 t 左侧，累计权重小于一半，继续向右会降低 F；到达 t 后，包含所有等于 t 的元素的累计权重至少为一半，再向右不会降低 F。因此 t 是全局最优目标。重复值不影响这个结论。

恰好一半：某一数值的完整累计权重等于 W/2 时，直到下一个不同数值之前差分都为 0；两个端点及中间整数均最优。选择左端点即可。

边界与复杂度

  • 单元素、全部相等：开销为 0。
  • 某项开销很大：它可能决定目标位置。
  • 重复值可保留，无须专门合并。
  • 排序 O(n log n)，扫描和结算 O(n)，总时间 O(n log n)。
  • 配对数组需要 O(n) 额外空间，四份代码不修改输入。
  • W 至多 10¹¹；任意候选总开销可接近 10¹⁷。Java / C++ 用 64 位，Python 用整数。JavaScript 用 BigInt，最终按题目保证转为 Number。

常见错误

  • 用平均值：它对应平方距离，不是加权绝对距离。
  • 用普通中位数：忽略了权重。
  • 单独排序 nums：破坏与 cost 的配对关系。
  • 乘法后才转 long：可能早已溢出，应先提升类型。
  • JavaScript 用位运算取一半：会缩到 32 位。
  • 将最终答案的安全整数保证误用于所有候选开销。

Java

import java.util.Arrays;

class Solution {
    public long minCost(int[] nums, int[] cost) {
        int n = nums.length;
        int[][] pairs = new int[n][2];
        long total = 0;
        for (int i = 0; i < n; i++) {
            pairs[i][0] = nums[i];
            pairs[i][1] = cost[i];
            total += cost[i];
        }
        Arrays.sort(pairs, (a, b) -> Integer.compare(a[0], b[0]));
        long half = (total + 1) / 2, prefix = 0;
        int target = pairs[0][0];
        for (int[] pair : pairs) {
            prefix += pair[1];
            if (prefix >= half) {
                target = pair[0];
                break;
            }
        }
        long answer = 0;
        for (int i = 0; i < n; i++) {
            answer += Math.abs((long) nums[i] - target) * cost[i];
        }
        return answer;
    }
}

var minCost = function(nums, cost) {
    const pairs = nums.map((v, i) => [v, BigInt(cost[i])]);
    pairs.sort((a, b) => a[0] - b[0]);
    const total = pairs.reduce((sum, p) => sum + p[1], 0n);
    const half = (total + 1n) / 2n;
    let prefix = 0n, target = pairs[0][0];
    for (const [value, weight] of pairs) {
        prefix += weight;
        if (prefix >= half) {
            target = value;
            break;
        }
    }
    let answer = 0n;
    for (let i = 0; i < nums.length; i++) {
        answer += BigInt(Math.abs(nums[i] - target)) * BigInt(cost[i]);
    }
    // 题目保证最优答案不超过 2^53 - 1。
    return Number(answer);
};

from typing import List

class Solution:
    def minCost(self, nums: List[int], cost: List[int]) -> int:
        pairs = sorted(zip(nums, cost))
        half = (sum(cost) + 1) // 2
        prefix = 0
        target = pairs[0][0]
        for value, weight in pairs:
            prefix += weight
            if prefix >= half:
                target = value
                break
        return sum(abs(value - target) * weight
                   for value, weight in zip(nums, cost))

class Solution {

    long long minCost(vector<int>& nums, vector<int>& cost) {

        pairs.reserve(nums.size());
        long long total = 0;
        for (int i = 0; i < (int)nums.size(); ++i) {
            pairs.emplace_back(nums[i], cost[i]);

替代方案

  • 凸函数二分：在 [min(nums), max(nums)] 上寻找第一个差分非负的整数。每次 O(n) 求左右权重，总时间 O(n log V)，额外空间 O(1)，V 为值域长度。直接算权重差比计算两个大开销 F 更稳妥。
  • 排序后递推：先求最小值处开销，再跨过间距 d，用 F(next) = F(cur) + d × (左侧权重 − 右侧权重) 更新并取最小。O(n log n) 时间、O(n) 空间，中间结果要用宽整数。
  • 加权快速选择：根据枢轴两侧权重决定保留哪一侧，期望 O(n)，最坏 O(n²)；实现更复杂，排序更易解释。

面试追问

cost 全为 1？
退化为普通中位数；偶数长度时两个中间值之间均最优。

如何返回所有最优目标？
先按相同数值聚合权重。若累计严格跨过一半，目标唯一；若恰好一半，当前值到下一不同值的闭区间都最优。

允许权重为 0？
零权重元素不影响目标；全部为 0 时任意目标的开销都是 0。本题权重严格为正。

增加与减少的单步开销不同？
仍然分析相邻目标的差分，但左右贡献不对称，要寻找新的平衡位置，不能直接套用一半。

为什么不用模拟加减？
距离乘单步开销一次就能结算全部操作；逐步模拟会产生大量无意义循环。
