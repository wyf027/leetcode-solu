INTERVIEW 17.11 · ARRAY / STRING

单词距离让最近的位置替你记忆

一卷十万词的长纸带，只需要两枚定位针。每遇到目标词就移动对应针， 两针都出现后收紧一次答案——不回头，不保存整份索引。

O(n)

记录 word1 与 word2 最近一次出现的位置； 每次命中后用两位置之差更新最短距离。

Problem brief

题意

中等 · 官方可见信息核实

任务

给定一个单词数组 words，以及两个不同的目标词 word1、word2，返回它们任意一次出现位置之间的最小下标距离。 题目还追问：若同一份超大文本需要反复查询不同词对，如何预处理以复用工作？

官方示例输入
words = ["I", "am", "a", "student", "from", "a", "university", "in", "a", "city"], word1 = "a", word2 = "student"
官方示例输出
1

可见字符说明：若字符串含空格，页面统一用 ␠ 表示一个空格；本题示例中的单词均不含空格。

约束与语义

  • words.length <= 100000
  • word1 与 word2 不同。
  • 返回值按题目样例采用下标差；相邻位置的答案为 1。
  • 单次提交的方法签名只接收一组查询。

Solution

最近位置单次扫描

面试首选

核心洞察

扫描到某个目标词时，只需关心另一个目标词“最近一次”的位置。 更早的位置一定更远，不可能产生更优答案，因此可以被安全丢弃。

完整过程

  1. 令 p1 = -1、p2 = -1、ans = n。
  2. 从左到右扫描；命中哪个目标词，就更新哪个最近位置。
  3. 两位置都有效时，用 |p1 - p2| 收紧答案。
  4. 答案为 1 时可提前结束，因为不同下标不可能更近。

边界与复杂度

  • 目标词重复出现：始终覆盖为最近位置。
  • 连续出现同一目标词：只移动同一枚针，不错误计算同词距离。
  • 相邻目标词：立即得到理论下界 1。
  • 时间 O(n)，额外空间 O(1)。

替代方案取舍

若同一文档需要大量不同查询，可预处理 Map<word, sorted positions>，构建耗时与空间均为 O(n)；每次查询用双指针合并两份位置表，耗时 O(a + b)。单次查询则没有必要承担这份额外空间。

面试追问

  • 若输入是不能回退的流，当前 O(1) 状态仍然成立吗？成立。
  • 多次查询如何缩短？倒排索引 + 两有序位置表双指针。
  • 若允许 word1 === word2？需记录该词最近两次出现位置。

常见错误

  • 每命中一个词就与另一个词的所有历史位置比较，退化为平方级。
  • 未判断两个位置是否都有效，拿 -1 参与答案。
  • 把“相隔单词数”误写成 |p1-p2|-1，与官方样例冲突。 
class Solution {
    public int findClosest(String[] words, String word1, String word2) {
        int p1 = -1;
        int p2 = -1;
        int answer = words.length;

        for (int i = 0; i < words.length; i++) {
            if (words[i].equals(word1)) {
                p1 = i;
            } else if (words[i].equals(word2)) {
                p2 = i;
            }

            if (p1 != -1 && p2 != -1) {
                answer = Math.min(answer, Math.abs(p1 - p2));
                if (answer == 1) return 1;
            }
        }
        return answer;
    }
}
