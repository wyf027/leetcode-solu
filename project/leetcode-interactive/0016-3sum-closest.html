SOLUTION CALIBRATION · DEFAULT CLOSED

题解

核心洞察、完整过程、边界、复杂度、追问、错误清单与四语言代码默认隐藏。

CORE INSIGHT

不记录组合，只维护离 target 最近的和

排序后固定 i，用 L / R 枚举剩余两数。每次计算当前和，若 |sum - target| 更小就刷新 closest；随后根据 sum 与 target 的大小定向移动指针。

POINTER COMPASS

sum < target：L++

sum > target：R--

sum = target：立即返回

FULL WALKTHROUGH

完整解题过程

  1. 1. 排序：使双指针移动具有单调性。
  2. 2. 初始化：用前三个数之和作为合法 closest。
  3. 3. 固定锚点：令 L = i + 1，R = n - 1。
  4. 4. 比较距离：更近时刷新 closest。
  5. 5. 定向收缩：小则 L++，大则 R--。
  6. 6. 精确命中：距离为 0 已是最优，直接返回 target。

EDGE CASES

边界情况

  • • 恰好三个数：它们的和就是答案。
  • • target 很远：仍返回可取得的最接近三数和。
  • • 精确命中：立即返回，无需继续扫描。
  • • 重复元素：本题返回和，不要求组合去重。

COMPLEXITY

复杂度

TIME
O(n²)
POINTER PHASE
O(1)

不计排序内部开销；不同语言排序实现通常额外占 O(log n) 到 O(n)。

ALTERNATIVE

替代方案取舍

暴力枚举全部三元组需要 O(n³)，只能作为小规模对拍基准。排序双指针将每个锚点后的搜索降到 O(n)，是面试主线。

COMMON MISTAKES

常见错误

  • • 用极大整数初始化 closest，随后做减法导致溢出。
  • • 比较 sum 本身，而不是比较绝对距离。
  • • sum 偏大却移动 L，破坏指针方向。
  • • JavaScript 排序遗漏 (a, b) => a - b。

INTERVIEW FOLLOW-UPS

面试高频追问

为什么 closest 用前三数初始化？它始终是一个真实可选的三数和，避免哨兵溢出。

为什么命中 target 可直接返回？绝对距离的理论下界是 0，不可能更优。

要跳过重复元素吗？不是正确性的必要条件；可做剪枝，但会增加实现复杂度。

class Solution {
    public int threeSumClosest(int[] nums, int target) {
        Arrays.sort(nums);
        int closest = nums[0] + nums[1] + nums[2];

        for (int i = 0; i < nums.length - 2; i++) {
            int left = i + 1;
            int right = nums.length - 1;

            while (left < right) {
                int sum = nums[i] + nums[left] + nums[right];
                if (Math.abs(sum - target) < Math.abs(closest - target)) {
                    closest = sum;
                }
                if (sum < target) {
                    left++;
                } else if (sum > target) {
                    right--;
                } else {
                    return target;
                }
            }
        }
        return closest;
    }
}
