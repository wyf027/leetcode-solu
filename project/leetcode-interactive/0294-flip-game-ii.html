Problem

给定字符串 currentState，其中每个字符都是 '+' 或 '-'。 两名玩家轮流操作，每次必须选择一对相邻的 "++"，并把它翻转为 "--"。

无法继续操作的玩家输掉游戏。假设你先手，且双方始终选择对自己最有利的操作；若你能保证获胜，返回 true，否则返回 false。

boolean canWin(string currentState)

约束与边界

  • 1 ≤ currentState.length ≤ 60
  • currentState[i] 只会是 '+' 或 '-'
  • 一次操作恰好消耗两个相邻的加号
  • 没有合法操作时，当前玩家立即失败

Solution

记忆化极小化极大搜索

把“我是否必胜”改写成“是否存在一步，让对手进入必败状态”。

01

定义状态

dfs(state) 表示轮到当前玩家面对 state 时能否必胜。

02

寻找反转点

枚举每个连续的 ++。只要某个后继状态让对手必败，当前状态就是必胜。

03

缓存结论

不同操作顺序可能到达同一字符串；记忆化避免再次搜索整棵重复子树。

Process

完整过程

  1. 检查缓存；若当前字符串已计算，直接返回结论。
  2. 从左到右扫描所有相邻字符，找出每个 ++。
  3. 临时翻成 --，递归判断对手面对新状态是否能赢。
  4. 若对手不能赢，立即缓存并返回 true。
  5. 若所有合法操作都让对手获胜，缓存并返回 false。

Invariant

正确性证明

命题：dfs(state) 返回 true，当且仅当当前玩家从 state 出发存在必胜策略。
  1. 基础情况：若没有 ++，当前玩家无法操作并失败；算法返回 false，结论成立。
  2. 归纳假设：假设所有操作后可达的更短博弈状态均被递归正确判断。
  3. 必胜方向：若算法返回 true，存在一步使递归返回 false；按归纳假设，对手在该后继状态必败，所以当前玩家可获胜。
  4. 必败方向：若算法返回 false，所有合法一步都使递归返回 true；对手总能获胜，因此当前玩家不可能保证获胜。

Cost

复杂度与边界

以所有长度为 n 的加减号字符串作为保守状态上界。实际可达状态通常远少于该上界。

时间复杂度 O(n · 2ⁿ)
空间复杂度 O(2ⁿ + n)
  • 长度小于 2 或不存在 ++：直接为必败状态。
  • 每步把两个加号永久变成减号，所以递归深度不超过 ⌊n / 2⌋。
  • 遇到第一个让对手必败的分支即可剪枝，无需枚举余下选择。

Implementation

四语言完整代码

四份实现均采用同一套“尝试一步 → 对手必败即当前必胜”的记忆化递归。

import java.util.HashMap;
import java.util.Map;

class Solution {
    private final Map<String, Boolean> memo = new HashMap<>();

    public boolean canWin(String currentState) {
        return dfs(currentState);
    }

    private boolean dfs(String state) {
        Boolean cached = memo.get(state);
        if (cached != null) {
            return cached;
        }

        char[] chars = state.toCharArray();
        for (int i = 0; i + 1 < chars.length; i++) {
            if (chars[i] == '+' && chars[i + 1] == '+') {
                chars[i] = '-';
                chars[i + 1] = '-';
                String nextState = new String(chars);

                if (!dfs(nextState)) {
                    memo.put(state, true);
                    return true;
                }

                chars[i] = '+';
                chars[i + 1] = '+';
            }
        }

        memo.put(state, false);
        return false;
    }
}

var canWin = function (currentState) {
    const memo = new Map();

    const dfs = (state) => {
        if (memo.has(state)) {
            return memo.get(state);
        }

        for (let i = 0; i + 1 < state.length; i++) {
            if (state[i] === '+' && state[i + 1] === '+') {
                const nextState =
                    state.slice(0, i) + '--' + state.slice(i + 2);

                if (!dfs(nextState)) {
                    memo.set(state, true);
                    return true;
                }
            }
        }

        memo.set(state, false);
        return false;
    };

    return dfs(currentState);
};
class Solution:
    def canWin(self, currentState: str) -> bool:
        memo: dict[str, bool] = {}

        def dfs(state: str) -> bool:
            if state in memo:
                return memo[state]

            for i in range(len(state) - 1):
                if state[i : i + 2] == "++":
                    next_state = state[:i] + "--" + state[i + 2 :]
                    if not dfs(next_state):
                        memo[state] = True
                        return True

            memo[state] = False
            return False

        return dfs(currentState)

#include <unordered_map>

using namespace std;

class Solution {
private:
    unordered_map<string, bool> memo;

    bool dfs(string& state) {
        auto it = memo.find(state);
        if (it != memo.end()) {
            return it->second;
        }

        for (int i = 0; i + 1 < static_cast<int>(state.size()); i++) {
            if (state[i] == '+' && state[i + 1] == '+') {
                state[i] = '-';
                state[i + 1] = '-';

                if (!dfs(state)) {
                    state[i] = '+';
                    state[i + 1] = '+';
                    memo[state] = true;
                    return true;
                }

                state[i] = '+';
                state[i + 1] = '+';
            }
        }

        memo[state] = false;
        return false;
    }

public:
    bool canWin(string currentState) {
        return dfs(currentState);
    }
};

Alternatives

替代方案

  • 朴素回溯：逻辑最直接，但会反复求解相同状态，容易超时。
  • Sprague–Grundy：按减号把字符串拆成若干连续加号段，预计算每个段长的 Grundy 值，再对各段异或。段长上限为 60 时可做到约 O(n²) 时间与 O(n) 空间。
  • 位掩码记忆化：可用比特表示加减号，减少字符串构造；状态空间本质不变，代码可读性略低。

Pitfalls

常见错误

  • 只判断“是否能走一步”，没有考虑对手的最优回应。
  • 把“存在一个让对手输的后继”误写成“所有后继都让对手输”。
  • 原地修改字符后忘记恢复，污染后续分支。
  • 只缓存必胜状态，不缓存必败状态，导致大量重复搜索。
  • 用当前玩家身份作为缓存键；本题规则对双方完全相同，字符串本身已足够描述状态。

Interview Follow-ups

面试追问

为什么状态键不需要记录“轮到谁”？

双方拥有完全相同的合法操作，目标也相同。dfs(state) 始终从“轮到当前玩家”的相对视角定义，因此字符串已经完整描述问题。

记忆化为什么不会改变博弈结论？

同一字符串的合法后继集合恒定，胜负只取决于这些后继的胜负，与到达它的历史顺序无关。因此复用结果等价于重新搜索。

如何推导 Sprague–Grundy 解法？

减号把棋盘切分为互不影响的连续加号子游戏。对长度为 L 的段，在位置 i 翻转会得到长度 i 与 L-i-2 的两个子段；枚举所有异或结果并取 mex 得到 Grundy 值。所有段的 Grundy 值异或不为零时先手必胜。

如果规则允许把“--”重新翻成“++”会怎样？

状态图可能出现环，递归深度不再单调下降；仅用布尔记忆化不足以处理搜索中的环，需要重新定义胜负/和局并使用带访问状态的图博弈算法。
