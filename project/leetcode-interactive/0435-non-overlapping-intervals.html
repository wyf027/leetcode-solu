Non-overlapping Intervals

无重叠区间

给定一组区间，移除尽可能少的区间，让留下的任意两个区间都不重叠。仅在端点接触算作不重叠，例如 [1,2] 与 [2,3] 可以同时保留。

输入：integer[][] intervals 输出：integer n ≤ 100,000

本题任务

最少移除数

不是求合并后的区间，也不是删除所有相交对。需要在整组区间中做全局选择。

关键语义

前一区间结束点 ≤ 后一区间起点

题目说明

参数 intervals 中的每个元素都是 [startᵢ, endᵢ]，并且 startᵢ < endᵢ。请返回需要移除的最小区间数量，使剩余区间互不重叠。

示例 1

输入：intervals = [[1,2],[2,3],[3,4],[1,3]] 输出：1

移除 [1,3] 后，其余区间互不重叠。

示例 2

输入：intervals = [[1,2],[1,2],[1,2]] 输出：2

三个相同区间只能保留一个，因此移除两个。

示例 3

输入：intervals = [[1,2],[2,3]] 输出：0

两个区间只在端点 2 接触，不算重叠。

约束

  • 1 ≤ intervals.length ≤ 10⁵
  • intervals[i].length == 2
  • -5 × 10⁴ ≤ startᵢ < endᵢ ≤ 5 × 10⁴

Solution

按结束点排序的贪心

核心洞察

想让可保留区间尽量多，就让每次保留的区间尽量早结束。早结束会为后续区间留下最大的时间空间。最少移除数等于总区间数减去最多可保留数。

因此，先按结束点升序排序。从左到右扫描：若当前起点不小于上一个保留区间的结束点，就保留当前区间并更新边界；否则移除当前区间。

完整过程

  1. 将 intervals 按结束点从小到大排序。
  2. 令 end 为第一个区间的结束点，移除数 removed = 0。
  3. 从第二个区间开始扫描。若 start < end，两者重叠，移除当前区间，removed++。
  4. 否则当前区间可以保留，将 end 更新为当前结束点。
  5. 扫描结束后返回 removed。

为什么相等时保留？题目规定端点接触不算重叠，所以兼容条件是 start ≥ end，真正冲突的条件是 start < end。

正确性证明

引理：在所有可选的第一个区间中，选择结束点最早的区间，不会减少之后能够保留的区间数量。

证明：设某个最优方案的第一个区间为 A，而全局结束最早的区间为 G。由于 end(G) ≤ end(A)，将方案中的 A 替换成 G 后，原先能接在 A 后的每个区间也一定能接在 G 后；方案大小不会变小。因此存在一个以 G 开始的最优方案。

归纳：选择 G 后，问题缩小为所有起点不早于 end(G) 的区间上的同类问题。算法在子问题中再次选择结束最早者。反复应用引理，算法保留的区间数达到最大，因此移除数 n - kept 最小。证毕。

边界情况

  • 只有一个区间：无需移除。
  • 所有区间互不重叠：返回 0。
  • 所有区间相同：只保留一个，返回 n - 1。
  • 区间相互嵌套：优先保留结束最早的内层区间。
  • 端点相接：例如 [1,2] 与 [2,3] 均可保留。
  • 负坐标不影响排序和比较。

复杂度

时间：O(n log n)，排序占主导；扫描为 O(n)。

空间：除排序实现所需空间外为 O(1)。不同语言的内置排序可能使用 O(log n) 到 O(n) 辅助空间。

替代方案

动态规划：按起点或结束点排序，令 dp[i] 表示以第 i 个区间结尾时最多保留多少个区间，枚举前驱转移。该方案时间为 O(n²)、空间为 O(n)，在 n = 10⁵ 时不可接受，但有助于理解“最大不重叠子集”。

按起点排序：遇到重叠时保留结束点更小的那个，也能得到相同答案。但状态更新更绕，按结束点排序的写法更直接、更容易证明。

四种语言完整实现

JavaLeetCode 签名
import java.util.Arrays;

class Solution {
    public int eraseOverlapIntervals(int[][] intervals) {
        Arrays.sort(intervals, (a, b) -> Integer.compare(a[1], b[1]));

        int removed = 0;
        int end = intervals[0][1];

        for (int i = 1; i < intervals.length; i++) {
            if (intervals[i][0] < end) {
                removed++;
            } else {
                end = intervals[i][1];
            }
        }
        return removed;
    }
}

Python 3LeetCode 签名
from typing import List

class Solution:
    def eraseOverlapIntervals(self, intervals: List[List[int]]) -> int:
        intervals.sort(key=lambda interval: interval[1])

        removed = 0
        end = intervals[0][1]

        for start, current_end in intervals[1:]:
            if start < end:
                removed += 1
            else:
                end = current_end

        return removed
C++LeetCode 签名
#include <algorithm>
#include <vector>
using namespace std;

class Solution {
public:
    int eraseOverlapIntervals(vector<vector<int>>& intervals) {
        sort(intervals.begin(), intervals.end(),
             [](const vector<int>& a, const vector<int>& b) {
                 return a[1] < b[1];
             });

        int removed = 0;
        int end = intervals[0][1];

        for (int i = 1; i < static_cast<int>(intervals.size()); ++i) {
            if (intervals[i][0] < end) {
                ++removed;
            } else {
                end = intervals[i][1];
            }
        }
        return removed;
    }
};

面试追问

如果端点接触也算重叠？

把冲突条件从 start < end 改为 start ≤ end。

如何输出被删除的区间？

给原区间附带索引；扫描时记录所有发生冲突的当前区间索引。

区间带权重怎么办？

简单贪心不再成立，需要按结束点排序后做带权区间调度 DP，并二分查找兼容前驱。

为什么不按长度最短选？

短区间可能结束得很晚，反而堵住更多后续区间；结束点才直接决定剩余空间。

常见错误

  • 把 start == end 判成重叠，导致端点相接用例出错。
  • 按起点排序后，冲突时无条件保留前一个，而没有比较两个结束点。
  • 使用 a[1] - b[1] 写 Java 比较器，在更大数值范围下可能溢出；使用 Integer.compare 更稳妥。
  • 误把题目写成“合并区间”，返回合并次数而非最少删除数。
  • 尝试 O(n²) 检查所有区间对，无法满足 10⁵ 的规模。
