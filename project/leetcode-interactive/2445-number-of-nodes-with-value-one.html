值为 1 的节点数

Number of Nodes With Value One

一棵初始全为 0 的树，每次选择一个节点，翻转它的整棵子树。
所有操作结束后，还有多少个节点的值是 1？

先观察操作，再展开题解。节点的编号始终不变，改变的是它的值。

01问题说明

给定整数 n 和整数数组 queries。树包含编号 1 到 n 的节点，根为 1；对任意非根节点 v，父节点编号为 ⌊v / 2⌋。所有节点初值为 0。每个查询 q 将 q 自身及它的全部后代的值取反（0 变 1、1 变 0）。返回全部查询完成后，值为 1 的节点总数。

numberOfNodes(n: integer, queries: integer[]) → integer

官方示例 1

输入：n = 5, queries = [1, 2, 5]
输出：3

依次操作后，值为 1 的节点编号为 1、3、5。

官方示例 2

输入：n = 3, queries = [2, 3, 3]
输出：1

节点 3 被翻转两次后回到 0，最终只有节点 2 为 1。

约束

  • 1 ≤ n ≤ 10⁵
  • 1 ≤ queries.length ≤ 10⁵
  • 1 ≤ queries[i] ≤ n

04题解 · 让翻转信息沿父子关系传递

核心洞察

节点 v 只会受到“v 自身或它的祖先被查询”的影响。翻转偶数次回到 0，奇数次变成 1，因此只需保留次数的奇偶性。设 local[v] 是直接查询 v 的次数模 2，最终状态满足：

value[0] = 0                    // 虚拟父节点，不计入答案
value[v] = local[v] XOR value[floor(v / 2)]

父节点编号总小于子节点。按编号从 1 到 n 扫描时，父节点的最终值已经算出；无需建立树，也无需真的遍历每个查询的子树。

完整过程

  1. 创建长度 n + 1 的全零数组 state。
  2. 遍历 queries，对每个 q 执行 state[q] ^= 1，得到直接查询的奇偶标记。
  3. 按 v = 1…n 扫描，执行 state[v] ^= state[v // 2]。此时 state[v] 从局部标记变为最终状态。
  4. 累加每个最终状态，返回总和。输入 queries 保持不变。

交互推导 · 从局部标记到最终值

使用观察台已应用的输入。局部奇偶标记已汇总；每一步只结算一个节点。橙色行显示当前节点，它从父节点继承翻转状态。

节点 v父节点local[v]父最终值当前状态

示例 1 的推导

n = 5、queries = [1,2,5] 时，local[1…5] = [1,1,0,0,1]。依次得到 state[1] = 1，state[2] = 1 XOR 1 = 0，state[3] = 0 XOR 1 = 1，state[4] = 0 XOR 0 = 0，state[5] = 1 XOR 0 = 1，总和为 3。

正确性证明

影响集合：查询 q 能翻转 v，当且仅当 q 位于根到 v 的路径上。异或满足交换律、结合律，且两次翻转抵消，所以路径上的局部奇偶标记的异或就是 v 的最终值。

归纳：v = 1 时只有根自己的查询影响它，虚拟父节点值为 0，公式正确。假设编号小于 v 的节点均已正确结算，v 的父节点 ⌊v/2⌋ 必在其中。根到 v 的路径等于根到父节点的路径加上 v，因此父节点的最终值异或 local[v] 正好是 v 的最终值。扫描结束时所有节点状态正确，累加 0/1 状态得到所求数量。

复杂度与边界

  • 令 m = queries.length，时间 O(n + m)，额外空间 O(n)。两个阶段都仅做一次线性扫描。
  • n = 1 仍使用 state[0] = 0。根被查询奇数次会影响整棵树。
  • 重复查询不能去重：相同节点查询两次的效果为零。
  • n 不必等于 2ᵏ − 1；末层可以不满，只处理编号 ≤ n 的节点。
  • 结果至多 n ≤ 10⁵。JavaScript 的 32 位异或用于 0/1 和该范围内的编号是安全的。

四语言完整提交代码

接口遵循官方元数据 numberOfNodes(n, queries)。以下实现为独立编写，尚未编译或执行。

Java

class Solution {
    public int numberOfNodes(int n, int[] queries) {
        int[] state = new int[n + 1];
        for (int q : queries) {
            state[q] ^= 1;
        }
        int answer = 0;
        for (int v = 1; v <= n; v++) {
            state[v] ^= state[v / 2];
            answer += state[v];
        }
        return answer;
    }
}

替代方案

  • 逐查询遍历子树：最直观，最坏 O(nm) 时间、O(n) 空间，适合小规模观察台。
  • DFS / BFS 传递奇偶值：先统计局部标记，再从根携带祖先异或值向下遍历，也为 O(n + m)。这棵树按编号即可处理，循环更直接。
  • 逐节点向根追溯：汇总查询标记后，每个节点沿父指针计算路径异或，时间 O(m + n log n)。重复计算了共同祖先。

面试追问

  • 每次操作后都要返回答案？当前方法只计算最终结果。一般树可用 DFS 序将子树变成连续区间，再使用支持区间翻转与区间 1 数量的懒标记线段树。
  • 节点初值并非全为 0？先用同样的方法计算路径翻转奇偶，再与每个节点自己的初值异或；不能把父节点的最终初始值一起传给孩子。
  • 换成任意树结构？父节点编号未必更小，应改用从根出发的 DFS / BFS，确保先处理父节点。
  • 为什么可以重排查询？每个节点承受的翻转次数不变，异或顺序不会影响最终状态。

常见错误

  • 把“翻转”写成赋值 1，丢失重复操作的抵消效果。
  • 从 n 递减扫描，错误读取尚未结算的父节点局部标记。
  • 认为堆编号下的子树一定是连续编号区间：例如 n = 7 时节点 2 的子树为 {2,4,5}。
  • 忘记查询节点自身也属于子树，或把编号 0 算进答案。
  • 原地更新时混淆 state 的含义：当前节点更新前是 local，父节点已经是最终状态。
