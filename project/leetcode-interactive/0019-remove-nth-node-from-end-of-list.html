01 · Core insight

固定间距，把“倒数”翻译成“同步”

SETUPdummy → head

虚拟头结点统一删除头、中、尾。

GAPfast 先走 n + 1

多出的 1 让 slow 最终停在目标前驱。

UNLINKslow.next 跳一格

指向 slow.next.next，目标结点脱链。

正确性不变量：同步移动期间，fast 始终比 slow 领先 n + 1 条边。因此 fast 为 null 时，slow.next 距链尾恰好 n 个结点，就是应删除的结点。

02 · Walkthrough

完整过程

  1. 1

    建立 dummy，令 fast、slow 都从 dummy 出发。

  2. 2

    fast 先移动 n + 1 次，建立固定间距。

  3. 3

    fast 与 slow 同步前进，直到 fast 走到 null。

  4. 4

    执行 slow.next = slow.next.next，返回 dummy.next。

03 · Edge cases

边界情况

  • 删除头结点：n = length，slow 停在 dummy，照常跳过 head。
  • 删除尾结点：n = 1，slow 停在倒数第二个结点。
  • 单结点：dummy.next 从唯一结点改为 null，返回空链表。
  • 重复值：依据位置而非结点值删除，不受重复值影响。

04 · Cost

复杂度

O(L) 时间

O(1) 额外空间

fast 和 slow 的移动总量为线性级别，只使用常数个指针。

05 · Alternatives

替代方案取舍

两次扫描

先求长度再定位。好写，但不满足“一趟扫描”追问。

栈

定位直观，却需要 O(L) 额外空间。

递归

回溯天然倒数，但调用栈 O(L)，且有栈深风险。

06 · Interview

面试高频追问

为什么是 n + 1，不是 n？

因为删除需要目标的前驱。领先 n + 1 条边，fast 到 null 时 slow 才会停在目标前一位。

dummy 真有必要吗？

不是理论必需，但它消除了删除 head 的特殊分支，面试代码更短、更稳。

若 n 可能非法怎么办？

在 fast 预走时检查 null；若不足 n + 1 步，则按接口约定抛错或原样返回。本题约束保证 n 合法。

07 · Pitfalls

常见错误

  • 差一格：fast 只走 n 步，却仍使用 while (fast)，slow 会停在目标本身。
  • 忘记 dummy：删除头结点时访问不到前驱，不得不额外分支。
  • 返回错头：应返回 dummy.next，不能总返回原 head。
  • 按值删除：链表可能有重复值，必须按指针位置脱链。

class Solution {
    public ListNode removeNthFromEnd(ListNode head, int n) {
        ListNode dummy = new ListNode(0, head);
        ListNode fast = dummy;
        ListNode slow = dummy;

        for (int i = 0; i <= n; i++) {
            fast = fast.next;
        }

        while (fast != null) {
            fast = fast.next;
            slow = slow.next;
        }

        slow.next = slow.next.next;
        return dummy.next;
    }
}
