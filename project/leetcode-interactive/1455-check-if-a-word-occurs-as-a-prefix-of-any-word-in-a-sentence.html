String · Prefix Match

检查单词是否为句中
其他单词的前缀

给定一个由单个空格分隔的句子和检索词，找到第一个以该检索词开头的单词，并返回它从 1 开始的下标。

简单双指针字符串字符串匹配
Problem

题目说明

函数：isPrefixOfWord(sentence, searchWord)

句子 sentence 由若干小写英文单词组成，相邻单词之间恰好有一个空格。请判断 searchWord 是否为其中某个单词的前缀。

若存在匹配，返回最先匹配单词的 1-based 下标；若多个单词都匹配，只返回最小下标；若一个都没有，返回 -1。

前缀是从一个字符串首字符开始的连续子串。例如，burg 是 burger 的前缀，而 urge 不是。

约束

  • 1 <= sentence.length <= 100
  • 1 <= searchWord.length <= 10
  • sentence 只含小写英文字母和空格。
  • searchWord 只含小写英文字母。
  • 句中单词由单个空格分隔。
示例 01
输入sentence = "i love eating burger", searchWord = "burg"
输出4

burg 是第 4 个单词 burger 的前缀。

示例 02
输入sentence = "this problem is an easy problem", searchWord = "pro"
输出2

第 2、6 个单词均匹配，返回较小下标 2。

示例 03
输入sentence = "i am tired", searchWord = "you"
输出-1

没有任何单词以 you 开头。

Core Insight

核心洞察：按顺序检查每个单词的开头

题目只关心“第一个”匹配位置，所以从左向右遍历天然满足最小下标要求。对每个单词判断它是否以 searchWord 开头；一旦成功即可立即返回。

  1. 拆分句子

    按单个空格将 sentence 拆成单词数组。

  2. 顺序扫描

    从数组下标 0 开始，对每个单词执行前缀判断。

  3. 命中即返回

    若匹配，返回数组下标加一；遍历结束仍未命中则返回 -1。

正确性证明

命中时正确：算法对第 i 个单词确认其开头与 searchWord 完全一致后返回 i。因此返回位置对应的单词必然满足前缀条件。

位置最小：单词按 1 到 i 的顺序检查；返回 i 前，所有更小位置都已被判定为不匹配，所以 i 是最小匹配下标。

无解时正确：若遍历完所有单词都未返回，说明不存在匹配，返回 -1。

边界情况

  • 第一个单词就匹配，应返回 1。
  • searchWord 与完整单词相等，仍属于前缀。
  • 检索词比当前单词长时，该单词不可能匹配。
  • 多个单词匹配，只保留第一次命中。
  • 没有任何匹配时返回 -1。
O(n)时间；n 为句子字符总数
O(n)空间；拆分后的单词数组

class Solution {
    public int isPrefixOfWord(String sentence, String searchWord) {
        String[] words = sentence.split(" ");
        for (int i = 0; i < words.length; i++) {
            if (words[i].startsWith(searchWord)) {
                return i + 1;
            }
        }
        return -1;
    }
}

class Solution:
    def isPrefixOfWord(self, sentence: str, searchWord: str) -> int:
        words = sentence.split()
        for index, word in enumerate(words, start=1):
            if word.startswith(searchWord):
                return index
        return -1

替代方案

直接扫描原字符串：维护当前单词的 1-based 编号，只在句首或空格后的单词起点比较 searchWord。这样可以避免拆分数组，将额外空间降为 O(1)，但边界处理更繁琐。

内置搜索：可以查找 searchWord 的出现位置，再确认它是否位于句首或前一字符为空格；需要小心跳过单词中部的伪匹配，代码未必更清晰。

面试追问

  • 如果句子包含连续空格、制表符或首尾空格，应如何稳健分词？
  • 如何在不创建单词数组的情况下完成扫描？
  • 如果要返回所有匹配下标，应修改哪一处提前返回逻辑？
  • 若有大量 searchWord 查询，如何预处理单词以加速？可讨论 Trie。
  • 若需要忽略大小写或支持 Unicode，应如何定义“字符”和规范化规则？

常见错误

  • 返回数组的 0-based 下标，忘记加一。
  • 使用“包含”判断代替“前缀”判断，误把单词中部出现视为匹配。
  • 找到多个匹配后返回最后一个，而不是首次命中。
  • 检索词无匹配时遗漏 -1。
  • 手写字符比较时未先处理检索词比当前单词更长的情况。
