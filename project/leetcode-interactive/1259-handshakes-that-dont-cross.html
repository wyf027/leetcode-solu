01 · Problem

问题是什么

给定偶数 numPeople，这些人均匀站在一个圆周上。每个人恰好与另一人握手，因此共有 numPeople / 2 次握手。

把每次握手画成连接两人的线段。返回所有线段互不相交的完整配对方案数。由于答案可能很大，结果对 1,000,000,007 取模。

官方函数形式

numberOfWays(numPeople: integer) → integer
示例 1
输入
numPeople = 4
输出
2
说明
四个人有两种不会交叉的完整握手安排。
示例 2
输入
numPeople = 6
输出
5
说明
六个人共有五种满足条件的配对。

约束

  • 2 ≤ numPeople ≤ 1000
  • numPeople 为偶数
  • 每个人恰好参与一次握手
  • 只统计连线互不相交的方案
  • 返回值对 10⁹ + 7 取模
观察提示

固定一个人以后，他选择的搭档会把圆周上的其余人分成两组。

03 · Think

展开前，试着回答

为什么搭档不能随便选？

某些选择会让一侧留下奇数个人，无法完成一一配对。

两侧为什么能分别计数？

一条握手线成为边界；不相交要求让其两侧互不干扰。

空的一侧有几种方案？

它必须贡献一个乘法单位元，否则贴着边缘的握手会被漏掉。

需要区分旋转后的图形吗？

需要。人有固定位置与编号，配对关系不同就是不同方案。

Solution

把一条线变成两个子问题

动态规划，本质上是卡特兰数。

核心洞察

1固定编号 1 的人，并枚举他的握手对象。
2这条线把剩余的人切成左右两个互不影响的连续区间。
3左右方案数相乘；再对所有合法搭档求和。

状态与转移

令 dp[n] 表示圆周上 n 个人完成不相交握手的方案数，只考虑偶数 n。规定 dp[0] = 1。固定一个人后，若握手线一侧有 left 个人，另一侧就有 n - 2 - left 个人；两边都必须是偶数。

dp[n] = Σ dp[left] × dp[n - 2 - left]，left = 0, 2, 4, …, n - 2

从 n = 2 开始递增计算到 numPeople，每次加法和乘法都对 1,000,000,007 取模。

完整过程：以 6 人为例

  1. dp[0] = 1：空区间只有一种“什么都不做”的完成方式。
  2. dp[2] = dp[0] × dp[0] = 1。
  3. dp[4] = dp[0] × dp[2] + dp[2] × dp[0] = 2。
  4. dp[6] = dp[0] × dp[4] + dp[2] × dp[2] + dp[4] × dp[0] = 2 + 1 + 2 = 5。

正确性证明

引理：固定某人的一条握手线后，任何合法方案都不会出现跨过该线的其他握手，因此剩余人被唯一分成两侧的独立子问题。

归纳：假设所有更小偶数规模的 dp 都准确计数。对规模 n，枚举固定人的每个合法搭档，左右两侧分别有 dp[left] 与 dp[n-2-left] 种方案，根据乘法原理得到该搭档下的全部方案。不同搭档的方案互斥，求和既不会遗漏也不会重复。由归纳法，dp[n] 正确。

边界与复杂度

  • 空区间：dp[0] = 1，保证一侧无人时仍能正确相乘。
  • 最小输入：numPeople = 2，答案为 1。
  • 取模：乘法使用足够宽的整数；JavaScript 使用 BigInt 避免精度丢失。
  • 时间复杂度：O(numPeople²)。
  • 空间复杂度：O(numPeople)。

四种语言完整代码

JavaLeetCode
class Solution {
    private static final long MOD = 1_000_000_007L;

    public int numberOfWays(int numPeople) {
        long[] dp = new long[numPeople + 1];
        dp[0] = 1;

        for (int people = 2; people <= numPeople; people += 2) {
            for (int left = 0; left <= people - 2; left += 2) {
                int right = people - 2 - left;
                dp[people] = (dp[people] + dp[left] * dp[right]) % MOD;
            }
        }
        return (int) dp[numPeople];
    }
}

C++LeetCode
class Solution {
public:
    int numberOfWays(int numPeople) {
        static constexpr long long MOD = 1'000'000'007LL;
        vector<long long> dp(numPeople + 1, 0);
        dp[0] = 1;

        for (int people = 2; people <= numPeople; people += 2) {
            for (int left = 0; left <= people - 2; left += 2) {
                int right = people - 2 - left;
                dp[people] = (
                    dp[people] + dp[left] * dp[right]
                ) % MOD;
            }
        }
        return static_cast<int>(dp[numPeople]);
    }
};

替代方案

令 m = numPeople / 2，答案是第 m 个卡特兰数。可以用组合公式 C(2m, m) - C(2m, m - 1)，配合模逆元在 O(m) 时间内计算。不过它需要快速幂、阶乘或逐项组合数处理，边界更多；本题上限为 1000，二维枚举的动态规划更直观稳健。

面试追问

如果人数上升到 10⁷？

需要转向卡特兰数组合公式，并利用模数为质数求逆元；还要核对规模与模数的关系。

如何恢复一种具体配对？

在状态中记录第一个可行分割点，随后递归恢复左右区间的配对。

如果允许至多一次交叉？

原先的独立子问题结构被破坏，需要额外描述交叉端点或使用区间动态规划。

为什么只枚举偶数 left？

一侧人数若为奇数，不可能在该侧内部完成两两配对。

常见错误

  • 忘记设置 dp[0] = 1，导致边界分割全部贡献 0。
  • 左右人数写成 n - left，没有减去已经握手的两个人。
  • 把人数当成握手对数使用，使状态下标整体错位。
  • JavaScript 直接用 Number 做大整数乘法，在取模前已经丢失精度。
  • 只在最终答案取模，中间乘法溢出。
