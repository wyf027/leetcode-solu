避免洪水泛滥

城市里有十亿个湖泊。每场雨都可能把一个湖泊装满，而晴天只有一次抽干机会。你能安排每个晴天，让任何湖泊都不在满水时再次遇雨吗？

中等 Avoid Flood in The City 非付费题
Problem

题目说明

函数：avoidFlood(rains)

目标

给定整数数组 rains。所有湖泊初始为空。若 rains[i] > 0，第 i 天会在编号为 rains[i] 的湖泊下雨：空湖变满，满湖再次遇雨则洪水泛滥。

若 rains[i] == 0，当天没有雨，但必须选择一个湖泊抽干。抽干满湖会使其变空；抽干空湖没有影响。

返回值

返回长度与 rains 相同的整数数组 ans：

  • 雨天必须令 ans[i] = -1；
  • 晴天令 ans[i] 为当天抽干的湖泊编号；
  • 多种合法安排可返回任意一种；无法避免洪水时返回空数组。
完整参数形式：输入 rains: integer[]，调用 avoidFlood(rains)，返回 integer[]。
Examples

官方示例

持续降雨Example 01
输入：rains = [1,2,3,4]
输出：[-1,-1,-1,-1]

解释：四天分别装满湖泊 1、2、3、4。
没有湖泊重复遇雨，因此无需晴天也不会洪水。
可行调度Example 02
输入：rains = [1,2,0,0,2,1]
输出：[-1,-1,2,1,-1,-1]

解释：第 3 天抽干湖 2，第 4 天抽干湖 1，
随后两湖再次遇雨时均为空。
[-1,-1,1,2,-1,-1] 也合法。
无法避免Example 03
输入：rains = [1,2,0,1,2]
输出：[]

解释：湖 1、2 都已满，但重复遇雨前只有一个晴天。
无论抽干哪一个，另一个都会洪水。

Solution

准备好核对思路了吗？

题解、证明、复杂度与四种语言代码默认收起，避免在读题时直接泄露答案。

Greedy + Priority Queue

题解：优先处理最近会再次遇雨的湖

核心洞察：晴天是一台每天只能处理一个任务的“抽水机”。已满湖泊的下一次降雨日就是它的截止期限；每个晴天抽干截止期限最早的湖泊，最不容易留下无法补救的风险。

预处理未来降雨

为每个湖泊记录全部下雨日期，并维护指针，随扫描推进得到该湖的下一次降雨日。

雨天登记风险

若湖已经满水，立即判定无解；否则将其标记为满。若它还会再次遇雨，把“下次日期 + 湖号”放入最小堆。

晴天处理最近期限

清理堆顶中过期条目；若堆非空，抽干下次遇雨最早的满湖。堆为空时可任意选择湖泊，例如湖 1。

构造答案

雨天写入 -1，晴天写入选中的湖号；一旦洪水不可避免就返回空数组。

正确性证明

引理：在某个晴天，若有若干满湖未来还会遇雨，那么存在可行安排时，也一定存在一个可行安排在今天抽干其中截止期限最早的湖泊。

证明：设湖 A 的下次降雨最早。取任意可行安排：若它今天已经抽干 A，无需改变；否则它今天抽干湖 B，并在不晚于 A 的截止期限前某天抽干 A。交换这两次抽干，让今天抽干 A、原先抽干 A 的那天改为抽干 B。由于 B 的截止期限不早于 A，交换后 A 与 B 都仍能在各自再次遇雨前变空，其余湖不受影响。因此交换后的安排仍可行。

定理：算法能返回合法安排，当且仅当存在避免洪水的安排。

证明：每个晴天依据引理选择最早截止期限，不会破坏可行性。若算法在雨天发现该湖仍满，说明此前所有晴天已按最紧迫顺序使用，却仍未在期限前抽干它；任何其他选择也无法挽回。反之，算法结束且未触发洪水时，每次重复遇雨前该湖都已被抽干，所得答案合法。

边界情况

  • 全是雨天但湖号不重复：直接全部填 -1。
  • 晴天时没有带期限的满湖：抽干任意湖，写 1 即可。
  • 同一湖连续两天下雨：中间没有晴天，必定无解。
  • 湖泊编号可达 10⁹：必须用哈希结构，不能按湖号开数组。
时间复杂度O(n log n)

每次降雨至多入堆一次、出堆一次。

空间复杂度O(n)

保存降雨位置、湖泊状态与优先队列。

JavaPriorityQueue
import java.util.*;

class Solution {
    public int[] avoidFlood(int[] rains) {
        int n = rains.length;
        int[] ans = new int[n];
        Arrays.fill(ans, 1);

        Map<Integer, List<Integer>> days = new HashMap<>();
        for (int i = 0; i < n; i++) {
            if (rains[i] > 0) {
                days.computeIfAbsent(rains[i], k -> new ArrayList<>()).add(i);
            }
        }

        Map<Integer, Integer> cursor = new HashMap<>();
        Set<Integer> full = new HashSet<>();
        PriorityQueue<int[]> pq = new PriorityQueue<>(
            Comparator.comparingInt(a -> a[0])
        );

        for (int i = 0; i < n; i++) {
            int lake = rains[i];
            if (lake > 0) {
                ans[i] = -1;
                if (full.contains(lake)) return new int[0];
                full.add(lake);

                int nextPos = cursor.getOrDefault(lake, 0) + 1;
                cursor.put(lake, nextPos);
                List<Integer> positions = days.get(lake);
                if (nextPos < positions.size()) {
                    pq.offer(new int[]{positions.get(nextPos), lake});
                }
            } else {
                while (!pq.isEmpty() && !full.contains(pq.peek()[1])) pq.poll();
                if (!pq.isEmpty()) {
                    int chosen = pq.poll()[1];
                    ans[i] = chosen;
                    full.remove(chosen);
                } else {
                    ans[i] = 1;
                    full.remove(1);
                }
            }
        }
        return ans;
    }
}
JavaScriptBinary Heap
/**
 * @param {number[]} rains
 * @return {number[]}
 */
var avoidFlood = function (rains) {
  class MinHeap {
    constructor() { this.data = []; }
    get size() { return this.data.length; }
    peek() { return this.data[0]; }
    push(item) {
      const a = this.data;
      a.push(item);
      let i = a.length - 1;
      while (i > 0) {
        const p = (i - 1) >> 1;
        if (a[p][0] <= item[0]) break;
        a[i] = a[p];
        i = p;
      }
      a[i] = item;
    }
    pop() {
      const a = this.data;
      const root = a[0];
      const last = a.pop();
      if (a.length > 0) {
        let i = 0;
        while (true) {
          let left = i * 2 + 1;
          if (left >= a.length) break;
          let right = left + 1;
          let child = right < a.length && a[right][0] < a[left][0]
            ? right : left;
          if (a[child][0] >= last[0]) break;
          a[i] = a[child];
          i = child;
        }
        a[i] = last;
      }
      return root;
    }
  }

  const positions = new Map();
  for (let i = 0; i < rains.length; i++) {
    if (rains[i] > 0) {
      if (!positions.has(rains[i])) positions.set(rains[i], []);
      positions.get(rains[i]).push(i);
    }
  }

  const ans = Array(rains.length).fill(1);
  const cursor = new Map();
  const full = new Set();
  const heap = new MinHeap();

  for (let i = 0; i < rains.length; i++) {
    const lake = rains[i];
    if (lake > 0) {
      ans[i] = -1;
      if (full.has(lake)) return [];
      full.add(lake);

      const nextPos = (cursor.get(lake) || 0) + 1;
      cursor.set(lake, nextPos);
      const list = positions.get(lake);
      if (nextPos < list.length) heap.push([list[nextPos], lake]);
    } else {
      while (heap.size && !full.has(heap.peek()[1])) heap.pop();
      if (heap.size) {
        const chosen = heap.pop()[1];
        ans[i] = chosen;
        full.delete(chosen);
      } else {
        ans[i] = 1;
        full.delete(1);
      }
    }
  }
  return ans;
};
Pythonheapq
from collections import defaultdict
from typing import List
import heapq


class Solution:
    def avoidFlood(self, rains: List[int]) -> List[int]:
        positions = defaultdict(list)
        for day, lake in enumerate(rains):
            if lake > 0:
                positions[lake].append(day)

        answer = [1] * len(rains)
        cursor = defaultdict(int)
        full = set()
        urgent = []  # (next_rain_day, lake)

        for day, lake in enumerate(rains):
            if lake > 0:
                answer[day] = -1
                if lake in full:
                    return []
                full.add(lake)

                cursor[lake] += 1
                if cursor[lake] < len(positions[lake]):
                    next_day = positions[lake][cursor[lake]]
                    heapq.heappush(urgent, (next_day, lake))
            else:
                while urgent and urgent[0][1] not in full:
                    heapq.heappop(urgent)
                if urgent:
                    _, chosen = heapq.heappop(urgent)
                    answer[day] = chosen
                    full.remove(chosen)
                else:
                    answer[day] = 1
                    full.discard(1)

        return answer
C++priority_queue
#include <bits/stdc++.h>
using namespace std;

class Solution {
public:
    vector<int> avoidFlood(vector<int>& rains) {
        int n = static_cast<int>(rains.size());
        vector<int> answer(n, 1);
        unordered_map<int, vector<int>> positions;

        for (int day = 0; day < n; ++day) {
            if (rains[day] > 0) positions[rains[day]].push_back(day);
        }

        unordered_map<int, int> cursor;
        unordered_set<int> full;
        using Event = pair<int, int>; // (next rain day, lake)
        priority_queue<Event, vector<Event>, greater<Event>> urgent;

        for (int day = 0; day < n; ++day) {
            int lake = rains[day];
            if (lake > 0) {
                answer[day] = -1;
                if (full.count(lake)) return {};
                full.insert(lake);

                int nextPos = ++cursor[lake];
                if (nextPos < static_cast<int>(positions[lake].size())) {
                    urgent.push({positions[lake][nextPos], lake});
                }
            } else {
                while (!urgent.empty() && !full.count(urgent.top().second)) {
                    urgent.pop();
                }
                if (!urgent.empty()) {
                    int chosen = urgent.top().second;
                    urgent.pop();
                    answer[day] = chosen;
                    full.erase(chosen);
                } else {
                    answer[day] = 1;
                    full.erase(1);
                }
            }
        }
        return answer;
    }
};
Trade-offs

替代方案与面试追问

替代方案：有序晴天集合

记录每个湖的上次降雨日，并把所有晴天日期放入有序集合。某湖再次下雨时，二分查找“上次降雨之后的第一个晴天”并分配给它。这是同样的贪心，复杂度也是 O(n log n)；Java/C++ 有现成 TreeSet/set，JavaScript 则需自行实现有序结构或 Fenwick 树。

为什么不能随便抽一个满湖？

因为不同湖的下一次降雨期限不同。先抽一个很晚才会再下雨的湖，可能让明天就要遇雨的湖错过唯一机会。

能否只看相邻两天？

不能。一个湖的两次降雨可能相隔很远，而中间的晴天还要和其他湖竞争；必须保留跨天状态和期限顺序。

如果晴天允许不抽水呢？

算法无需改变实质逻辑：危急队列为空时跳过即可。题目要求答案在晴天写一个湖号，因此这里用 1 作为无风险占位。

常见错误

把湖号当数组下标导致内存爆炸；在雨天后才判断湖是否已满；晴天只按湖号而非期限选择；忘记雨天答案必须是 -1；无风险晴天漏填合法正整数。

如何证明失败一定无解？

把每次“首次下雨到再次下雨”视作一个有释放时间和截止期限的单机任务。最早截止期限贪心已经给所有更紧迫任务最高优先级，仍逾期就说明可用晴天数量不足。
