替换后的最长重复字符

给定只含大写英文字母的字符串 s 和整数 k。你最多可以把其中 k 个字符替换成任意其他大写字母，求替换后可形成的、全部字符相同的最长连续子串长度。

Longest Repeating Character Replacement非付费题O(n) 目标
01 · Problem Brief

先理解任务，不急着看答案

示例 1

输入：s = "ABAB", k = 2
输出：4
解释：把两个 A 替换成 B，或把两个 B 替换成 A，
即可让整个字符串成为长度为 4 的重复字符子串。

示例 2

输入：s = "AABABBA", k = 1
输出：4
解释：将中间一个 A 替换为 B，可得到 "AABBBBA"；
其中连续的 "BBBB" 长度为 4。

约束与函数形式

  • 1 <= s.length <= 105
  • s 仅由大写英文字母组成。
  • 0 <= k <= s.length
  • 官方函数：characterReplacement(s, k) -> integer

03 · Full Solution

把“最多替换 k 次”翻译成窗口条件

核心洞察

窗口长度 − 窗口内最高字符频次 ≤ k
左边是把整个窗口统一成出现最多的那个字符所需的最少替换次数。条件成立，窗口就可行。
  1. 扩张右边界。把新字符计入 26 长度的频次数组。
  2. 检查替换成本。用窗口长度减去最高频次，得到必须替换的字符数。
  3. 不合法就收缩。移出左端字符并重算最高频次，直到成本重新不超过 k。
  4. 记录最长窗口。每轮收缩结束后的窗口都合法，用其长度更新答案。

为什么选择最高频字符？

固定一个窗口后，若最终统一成字符 X，需要替换“窗口长度 − X 的频次”个位置。要让替换次数最少，自然选择当前出现最多的字符。

复杂度

时间 O(26n) = O(n)：每个字符最多被左右指针各处理一次；收缩时扫描固定 26 个计数。
空间 O(26) = O(1)。

正确性证明

  1. 合法性：循环收缩结束时，窗口长度减最高频次不超过 k，因此把其他字符全部替换成最高频字符即可，当前窗口一定可行。
  2. 不会漏解：右指针逐个访问所有可能的右端点；对每个右端点，左指针只在窗口不合法时右移，所以保留了该过程中能达到的最长合法窗口。
  3. 最优性：算法记录的每个候选都合法，因此答案不大于真正最优值；任意最优窗口在其右端点被访问时不会被无故越过，因此答案也不小于最优值。两者相等。

边界情况

  • k = 0：退化为最长连续相同字符。
  • 字符串本身全相同：答案就是 s.length。
  • k = s.length：整个字符串都能统一。
  • 频率相同的主字符不影响结果，只需要最高频次数值。
Implementation

四种官方可提交语言

JavaLeetCode
class Solution {
    public int characterReplacement(String s, int k) {
        int[] freq = new int[26];
        int left = 0;
        int answer = 0;

        for (int right = 0; right < s.length(); right++) {
            freq[s.charAt(right) - 'A']++;
            int maxFreq = getMax(freq);

            while (right - left + 1 - maxFreq > k) {
                freq[s.charAt(left) - 'A']--;
                left++;
                maxFreq = getMax(freq);
            }

            answer = Math.max(answer, right - left + 1);
        }
        return answer;
    }

    private int getMax(int[] freq) {
        int result = 0;
        for (int count : freq) {
            result = Math.max(result, count);
        }
        return result;
    }
}

class Solution:
    def characterReplacement(self, s: str, k: int) -> int:
        freq = [0] * 26
        left = 0
        answer = 0

        for right, char in enumerate(s):
            freq[ord(char) - ord("A")] += 1
            max_freq = max(freq)

            while right - left + 1 - max_freq > k:
                freq[ord(s[left]) - ord("A")] -= 1
                left += 1
                max_freq = max(freq)

            answer = max(answer, right - left + 1)

        return answer
C++LeetCode
class Solution {
public:
    int characterReplacement(string s, int k) {
        array<int, 26> freq{};
        int left = 0;
        int answer = 0;

        for (int right = 0; right < static_cast<int>(s.size()); ++right) {
            ++freq[s[right] - 'A'];
            int maxFreq = *max_element(freq.begin(), freq.end());

            while (right - left + 1 - maxFreq > k) {
                --freq[s[left] - 'A'];
                ++left;
                maxFreq = *max_element(freq.begin(), freq.end());
            }

            answer = max(answer, right - left + 1);
        }
        return answer;
    }
};

替代方案与取舍

枚举目标字符：对 A 到 Z 分别跑一次窗口，统计窗口内非目标字符数。实现直观，时间 O(26n)，仍可通过，但重复扫描字符串。

单调历史最大频次：常见优化不会在左移时降低 maxFreq，可省去重算。它维护的是“可达到长度”的门槛而非当前窗口的精确合法性，证明更绕；本页采用精确重算版本，便于演示与解释。

常见错误

  • 把“子字符串”误当成可以跳跃选取的子序列。
  • 用不同替换目标拼凑一个窗口；最终必须统一成同一字符。
  • 窗口非法时只移动一次左指针，却没有用 while 保证恢复合法。
  • 用普通对象计数但遗漏删除或初始化，导致 NaN。
Deep Dive

面试追问

如果字符集不止 26 个？

改用哈希表记录频次。若仍每次重算最高频，最坏复杂度会受窗口内不同字符数影响；可以使用单调历史最大频次技巧，或额外维护频次的有序结构。

如果要求返回具体子串？

在更新答案时同时保存最佳窗口的左端点。最终返回 s.substring(bestLeft, bestLeft + answer)；若还要输出替换方案，再选择该窗口的最高频字符并列出其余位置。
