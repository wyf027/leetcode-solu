数组中的
最长山脉

在起伏的数字地形里，找出一段严格上升后又严格下降的最长连续轨迹。先读题、观察，再决定是否展开题解。

中等数组双指针一趟扫描非付费题
题解不会在首屏直接出现
01 / Problem

什么才算一座山？

山脉必须是连续子数组，且山顶两侧都至少有一个元素。

题意

给定整数数组 arr。若一个连续子数组长度至少为 3，并且存在一个既不是首项也不是末项的山顶：从起点到山顶严格递增、从山顶到终点严格递减，那么它是一段山脉。返回最长山脉子数组的长度；不存在时返回 0。

arr[l] < … < arr[peak] > … > arr[r]
l < peak < r

示例 1

输入：arr = [2,1,4,7,3,2,5]
输出：5
解释：最长山脉为 [1,4,7,3,2]。

示例 2

输入：arr = [2,2,2]
输出：0
解释：数组中不存在山脉。

约束与签名

  • 1 ≤ arr.length ≤ 10⁴
  • 0 ≤ arr[i] ≤ 10⁴
  • 输入参数：arr: integer[]
  • 返回值：integer

03 / Solution

准备好越过山顶了吗？

以下内容包含完整算法、证明与可提交代码。

核心洞察

把每个可能的山脉看成“最长上坡 + 紧接着的最长下坡”。扫描指针从一座候选山的左脚出发：先跳过无法作为上坡起点的平地或下降段；若能严格上升，就走到峰顶；只有峰顶后还能严格下降时，才形成合法山脉。

下降结束时，区间长度为 right - left + 1。随后直接从当前右端继续寻找下一座山，不回头。

完整过程

  1. 令 base = 0，答案 best = 0。
  2. 若 arr[base] >= arr[base+1]，当前位置没有上坡，右移 base。
  3. 否则沿严格上升关系前进至峰顶。
  4. 记录峰顶后沿严格下降关系前进；必须至少下降一步。
  5. 若确有下降，更新最长长度；将 base 移到本段末端继续。

正确性证明

  1. 候选区间完整。算法从左脚沿所有连续的严格上升边走到局部峰顶，所以不会漏掉以该左脚开始、包含在此坡面中的更高峰。
  2. 合法性。只有上坡之后至少出现一条严格下降边时才更新答案，因此被计数区间长度至少为 3，且峰顶两侧严格单调。
  3. 最优性。任意合法山脉都有一个左脚。扫描到该左脚时，算法会走完整个上坡和下坡，得到不短于它的极大山脉；所有极大山脉都被考察，最大值即全局最优。

边界与复杂度

  • 长度小于 3：直接返回 0。
  • 全相等、全递增或全递减：缺少完整两侧，返回 0。
  • 相等元素会截断严格坡面，不能跨越平台。
  • 相邻山脉可以共享山脚，指针仍可从该位置继续。

时间：O(n)，每条边被常数次访问。
空间：O(1)。

替代方案

可以建立两个长度为 n 的数组：up[i] 表示以 i 结尾的连续上升长度，down[i] 表示以 i 开始的连续下降长度。若两者都大于 0，则山长为 up[i] + down[i] + 1。

它更直观，也方便回答“每个位置作为山顶时的长度”，但需要 O(n) 额外空间。

面试追问与常见错误

  • 追问：如何输出最长山脉的左右端点？更新答案时同步保存 base 与 end。
  • 追问：若允许平台呢？必须重新定义比较规则与峰顶区间。
  • 错误地使用 <= / >=，把平台算进山脉。
  • 只有上坡没有下坡时也更新答案。
  • 把“子数组”误作可跳元素的“子序列”。
  • 下降结束后无条件多加一，造成越界或重复计数。

class Solution {
    public int longestMountain(int[] arr) {
        int n = arr.length;
        int best = 0;
        int base = 0;

        while (base < n - 1) {
            int end = base;
            if (arr[end] < arr[end + 1]) {
                while (end + 1 < n && arr[end] < arr[end + 1]) {
                    end++;
                }
                int peak = end;
                while (end + 1 < n && arr[end] > arr[end + 1]) {
                    end++;
                }
                if (end > peak) {
                    best = Math.max(best, end - base + 1);
                }
            }
            base = Math.max(end, base + 1);
        }
        return best;
    }
}
