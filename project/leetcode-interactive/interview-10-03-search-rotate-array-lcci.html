01 / 题意

剪开，旋转，再定位

给定一个原本非递减的整数数组，它经历了未知次数的循环旋转。找到 target；不存在时返回 -1。若目标出现多次，必须返回索引最小的那一次。

“旋转”可以理解为在某个位置剪开数组，再交换两段，例如 [1,3,5,7,10,14,15,16,19,20,25] 变为 [15,16,19,20,25,1,3,5,7,10,14]。

示例 1

arr = [15,16,19,20,25,1,3,4,5,7,10,14], target = 5

输出：8

示例 2

arr = [15,16,19,20,25,1,3,4,5,7,10,14], target = 11

输出：-1

本题输入均为整数；若在其他题目中出现字符串，本页约定用成对直引号表示，空格写作 ␠。

    核心洞察

    先检查左端，再辨认有序半边

    每轮先看 arr[left]。它若等于目标，当前 left 就是尚未排除范围里最小的索引，可以立即返回。

    若中点命中，不立刻返回，而把右边界收至 mid，继续寻找更小索引。

    左端与中点不同时，至少能确认一个半边严格有序；若它们相等，重复值挡住了断点，只能安全地执行 left++。

    不变量

    • ① 若答案存在，它始终位于闭区间 [left, right]。
    • ② 所有小于 left 的索引都已确认不是目标。
    • ③ 中点命中时保留 mid，避免丢掉当前最小候选。
    • ④ 重复值无法定向时只删除一个已确认不命中的左端点。

    完整过程

    五步决策回路

    1. 01 · 左端命中

      若 arr[left] == target，立即返回 left。

    2. 02 · 中点命中

      令 right = mid，继续向更小索引收缩。

    3. 03 · 左半有序

      arr[left] < arr[mid] 时，按值域判断目标是否在左半。

    4. 04 · 右半有序

      arr[left] > arr[mid] 时，按右半值域定向。

    5. 05 · 重复迷雾

      arr[left] == arr[mid] 且未命中，只能安全右移左端。

    复杂度

    平均对数，最坏线性

    无大量重复值时为 O(log n)；全是相同值且目标缺席时，每轮只能移动一次左端，退化为 O(n)。空间为 O(1)。

    边界

    最容易漏的四类

    • • 单元素数组
    • • 未发生旋转
    • • 目标跨断点重复
    • • 全部元素相同且目标缺席

    正确性要点

    只丢弃不可能区间

    严格有序半边可由端点值域排除；重复迷雾时左端已知不等于目标，因此删除它不影响答案。区间终将缩小并终止。

    替代方案

    什么时候不该坚持二分

    线性扫描：实现最短，天然返回最小索引；时间固定为 O(n)。若数据规模小或重复值极多，它反而更稳定。

    先找旋转点再二分：无重复值时结构清晰；重复值会让旋转点查找同样退化，而且还要处理目标跨断点重复。

    常见错误

    四个高频陷阱

    • • 中点命中就返回，忽略“最小索引”。
    • • arr[left] == arr[mid] 时随意丢掉半边。
    • • 用严格/非严格不等号混错，漏掉端点目标。
    • • 宣称重复值场景仍保证 O(log n)。

    面试追问

    把问题再推进一步

    为什么先检查 left？

    因为题目要最小索引。只要当前左端命中，就没有更小的未排除索引；同时它让中点命中后的 right = mid 不会死循环。

    能否从两端一起跳过重复值？

    可以，但必须先检查左端是否命中。双端跳过可能减少常数，却不改变最坏 O(n)。

    若保证元素互异呢？

    不再出现迷雾分支，每轮至少排除一半，最坏时间恢复为 O(log n)。

    如何证明返回的是当前数组最小索引？

    所有小于 left 的位置都已证明不命中；中点命中不丢弃左半；最终只有左端命中时返回，所以它必是最小索引。
