用户分组

把每个人送进“标有目标容量的候车区”：一个候车区坐满，立刻封组离场。先观察这个过程，再决定是否展开完整题解。

中等贪心数组哈希表非付费题
Problem

题意与输入输出

函数：groupThePeople(groupSizes)

有 n 个人，编号为 0 到 n - 1。数组 groupSizes 给出每个人期望加入的小组人数：groupSizes[i] 就是编号 i 所在组的大小。

请返回一个分组列表，使得：

  • 每个人恰好出现一次，且没有人遗漏；
  • 每个人所在组的实际人数，等于他在 groupSizes 中声明的人数；
  • 若答案不唯一，返回任意一种即可。
有效性保证：输入保证至少存在一种合法分组，不需要处理无解情形。
示例 1
输入：groupSizes = [3,3,3,3,3,1,3]
输出：[[5],[0,1,2],[3,4,6]]
解释：[5] 的人数为 1；另外两组人数均为 3。
只要满足条件，组和成员的顺序都可以不同。
示例 2
输入：groupSizes = [2,1,3,3,3,2]
输出：[[1],[0,5],[2,3,4]]

约束

  • groupSizes.length == n
  • 1 <= n <= 500
  • 1 <= groupSizes[i] <= n

Solution

哈希桶：装满即出队

核心洞察

目标组大小相同的人才可能进入同一组。用哈希表把“目标大小”映射到一个尚未装满的人员列表；列表长度达到目标大小时，立即把它加入答案并清空。

完整过程

  1. 从左到右枚举人员编号 i。
  2. 令 size = groupSizes[i]，把 i 放入 buckets[size]。
  3. 若桶长等于 size，将桶加入答案，再换成空桶。
  4. 枚举结束后返回答案。

边界与细节

  • 组大小为 1：加入桶后立即成组。
  • 同一大小有多组：每次装满就清空，自然切成多组。
  • 答案顺序：题目允许任意合法顺序。
  • 无解：题目已保证不会出现。

复杂度

每个人只进入一次桶、进入一次答案，因此时间复杂度为 O(n)。桶和答案存放所有编号，辅助空间为 O(n)；若不计输出，未完成桶仍合计至多 O(n)。

正确性证明

合法大小：某个桶只接收声明大小相同的人，且仅在人数恰好达到该声明值时输出，所以每个输出组的实际人数满足组内所有人的要求。

不重不漏：每个人在遍历到其唯一编号时恰好加入一个桶；桶输出后成员整体进入答案且桶清空，因此没有人重复。输入保证存在合法解，也就保证遍历结束时不会残留无法成组的成员。综上，算法返回合法分组。

四语言完整实现

class Solution {
    public List<List<Integer>> groupThePeople(int[] groupSizes) {
        Map<Integer, List<Integer>> buckets = new HashMap<>();
        List<List<Integer>> answer = new ArrayList<>();

        for (int person = 0; person < groupSizes.length; person++) {
            int size = groupSizes[person];
            List<Integer> bucket = buckets.computeIfAbsent(
                size, key -> new ArrayList<>()
            );
            bucket.add(person);
            if (bucket.size() == size) {
                answer.add(new ArrayList<>(bucket));
                bucket.clear();
            }
        }
        return answer;
    }
}
/**
 * @param {number[]} groupSizes
 * @return {number[][]}

var groupThePeople = function(groupSizes) {
    const buckets = new Map();
    const answer = [];

    for (let person = 0; person < groupSizes.length; person++) {
        const size = groupSizes[person];
        if (!buckets.has(size)) buckets.set(size, []);

        const bucket = buckets.get(size);
        bucket.push(person);
        if (bucket.length === size) {
            answer.push([...bucket]);
            buckets.set(size, []);
        }
    }
    return answer;
};
from collections import defaultdict
from typing import List

class Solution:
    def groupThePeople(self, groupSizes: List[int]) -> List[List[int]]:
        buckets = defaultdict(list)
        answer = []

        for person, size in enumerate(groupSizes):
            buckets[size].append(person)
            if len(buckets[size]) == size:
                answer.append(buckets[size])
                buckets[size] = []

        return answer

替代方案

可以先把所有人按目标大小完整归类，再把每类按固定长度切片；复杂度同样是 O(n)。“边扫边成组”更节省中间结构，写法也更贴近在线处理。

常见错误

  • 按人数值排序后忘记保留原始人员编号。
  • 桶装满后没有清空，导致成员重复出现。
  • 把桶的键误写成人员编号，而不是目标组大小。
  • 错误地要求答案顺序与示例完全一致。

面试追问

为什么“装满就输出”不会破坏后续选择？

同一目标大小的人彼此可互换；任何恰好 size 个人的组合都合法，当前选出的成员不会限制其他尺寸，也不会让剩余同尺寸成员失去可行性。

如果输入不保证有解，如何处理？

遍历结束后检查每个桶是否为空；只要存在非空桶，就说明该目标大小对应的人数不是组大小的整数倍，可返回错误或空结果。

能否不用哈希表？

因为 size 不超过 n，可创建长度 n + 1 的数组作为桶集合，用空间换取更低的常数开销；哈希表则只为实际出现的 size 建桶。
