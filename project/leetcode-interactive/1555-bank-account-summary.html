银行账户概要Bank Account Summary

从初始授信额出发，把每笔转账拆成“付款方扣减”和“收款方增加”，为每位用户汇总当前余额，并识别是否跌破零线。

MEDIUM会员题主题：数据库MySQL

Problem

题目转述

给定用户表 Users 与转账表 Transactions。每个用户在 Users.credit 中有一笔初始余额；每笔交易由 paid_by 用户向 paid_to 用户支付 amount。

请输出每个用户的 user_id、user_name、交易完成后的 credit，以及 credit_limit_breached：若最终余额严格小于 0，则为 Yes，否则为 No。结果行顺序不限。

Users 用户与初始余额
字段类型说明
user_id KEYINT用户唯一标识
user_nameVARCHAR(20)用户名
creditINT初始余额
Transactions 转账流水
字段类型说明
trans_id KEYINT交易唯一标识
paid_byINT付款用户
paid_toINT收款用户
amountINT转账金额
transacted_onDATE交易日期

约束与数据关系

  • Users.user_id 与 Transactions.trans_id 分别唯一。
  • paid_by、paid_to 引用已存在的用户；交易金额用于从付款方扣减并向收款方增加。
  • 没有交易的用户也必须保留，其最终余额等于初始余额。
  • 只在最终余额 严格小于 0 时标记为 Yes；恰好为 0 时为 No。

Editorial

汇总两端资金流

核心洞察

同一用户可能在不同交易中既是付款方又是收款方。最清晰的做法是先把每笔交易规范化为两条“余额变化”：付款方一条负数、收款方一条正数；再按用户求和，最后与 Users.credit 相加。

final_credit(user) = initial_credit(user) + SUM(all signed transaction deltas)

完整过程

  1. 在派生表中选出 paid_by AS user_id 与 -amount AS change_amount。
  2. 用 UNION ALL 追加 paid_to AS user_id 与 amount AS change_amount。不能使用会去重的 UNION。
  3. 按 user_id 汇总所有变化。
  4. 从 Users 左连接汇总结果，用 COALESCE(..., 0) 保留无交易用户。
  5. 根据最终余额是否小于 0 生成 Yes / No。

正确性证明

  1. 对任意交易，派生表恰好为付款方记录 -amount，为收款方记录 +amount，与交易对两端余额的真实影响一致。
  2. 按用户求和后，该用户参与的每笔交易影响都被计入一次，且符号正确，因此得到其交易净变化。
  3. 净变化加初始余额，恰好得到全部交易结束后的余额；左连接与零值补全又保证无交易用户也得到正确余额。
  4. CASE 精确判断最终余额小于 0 的情形，所以输出的越界标记正确。

边界情况

  • 用户没有任何交易：变化量为 0，余额保持不变。
  • 最终余额恰好为 0：不是负数，应输出 No。
  • 同额、同方向的重复交易：每一笔都有效，必须由 UNION ALL 保留。
  • 用户同时付款和收款：正负变化统一汇总，不会相互遗漏。

复杂度

设用户数为 U、交易数为 T。逻辑处理量为 O(U + T)；汇总结果与输出占用 O(U) 额外空间。数据库实际执行代价会受索引、执行计划和聚合实现影响。

替代方案

可以分别汇总付款与收款，再把两份结果都左连接到 Users。它容易理解，但会扫描/聚合交易表两次，并需处理更多空值。也可把 Transactions 以 paid_by = user_id OR paid_to = user_id 连接后用条件聚合；不过 OR 连接通常不利于优化，也更容易写错。规范化为带符号流水更直接。

官方可提交方案 · MySQL

WITH balance_changes AS (
    SELECT paid_by AS user_id, -amount AS change_amount
    FROM Transactions

    UNION ALL

    SELECT paid_to AS user_id, amount AS change_amount
    FROM Transactions
),
net_changes AS (
    SELECT user_id, SUM(change_amount) AS net_amount
    FROM balance_changes
    GROUP BY user_id
),
account_summary AS (
    SELECT
        u.user_id,
        u.user_name,
        u.credit + COALESCE(n.net_amount, 0) AS credit
    FROM Users AS u
    LEFT JOIN net_changes AS n
        ON n.user_id = u.user_id
)
SELECT
    user_id,
    user_name,
    credit,
    CASE WHEN credit < 0 THEN 'Yes' ELSE 'No' END
        AS credit_limit_breached
FROM account_summary;

import java.util.*;

class Solution {
    record User(int id, String name, long credit) {}
    record Transaction(int paidBy, int paidTo, long amount) {}
    record Summary(int id, String name, long credit, String breached) {}

    static List<Summary> summarize(
            List<User> users, List<Transaction> transactions) {
        Map<Integer, Long> delta = new HashMap<>();
        for (Transaction t : transactions) {
            delta.merge(t.paidBy(), -t.amount(), Long::sum);
            delta.merge(t.paidTo(), t.amount(), Long::sum);
        }

        List<Summary> answer = new ArrayList<>();
        for (User user : users) {
            long credit = user.credit()
                    + delta.getOrDefault(user.id(), 0L);
            answer.add(new Summary(
                    user.id(), user.name(), credit,
                    credit < 0 ? "Yes" : "No"));
        }
        return answer;
    }
}

function summarize(users, transactions) {
  const delta = new Map();

  for (const { paidBy, paidTo, amount } of transactions) {
    delta.set(paidBy, (delta.get(paidBy) ?? 0) - amount);
    delta.set(paidTo, (delta.get(paidTo) ?? 0) + amount);
  }

  return users.map(({ id, name, credit }) => {
    const currentCredit = credit + (delta.get(id) ?? 0);
    return {
      userId: id,
      userName: name,
      credit: currentCredit,
      creditLimitBreached: currentCredit < 0 ? "Yes" : "No",
    };
  });
}

from collections import defaultdict
from typing import NamedTuple


class Summary(NamedTuple):
    user_id: int
    user_name: str
    credit: int
    credit_limit_breached: str


def summarize(users: list[dict], transactions: list[dict]) -> list[Summary]:
    delta: dict[int, int] = defaultdict(int)
    for transaction in transactions:
        delta[transaction["paid_by"]] -= transaction["amount"]
        delta[transaction["paid_to"]] += transaction["amount"]

    answer = []
    for user in users:
        credit = user["credit"] + delta[user["user_id"]]
        answer.append(Summary(
            user["user_id"],
            user["user_name"],
            credit,
            "Yes" if credit < 0 else "No",
        ))
    return answer

本地语义参考 · 非该 SQL 题的官方提交语言

#include <string>
#include <unordered_map>
#include <vector>
using namespace std;

struct User { int id; string name; long long credit; };
struct Transaction { int paidBy; int paidTo; long long amount; };
struct Summary {
    int id;
    string name;
    long long credit;
    string breached;
};

vector<Summary> summarize(
    const vector<User>& users,
    const vector<Transaction>& transactions
) {
    unordered_map<int, long long> delta;
    for (const auto& t : transactions) {
        delta[t.paidBy] -= t.amount;
        delta[t.paidTo] += t.amount;
    }

    vector<Summary> answer;
    answer.reserve(users.size());
    for (const auto& user : users) {
        long long credit = user.credit + delta[user.id];
        answer.push_back({user.id, user.name, credit,
                          credit < 0 ? "Yes" : "No"});
    }
    return answer;
}

面试追问

  • 为什么必须用 UNION ALL？ 两笔金额相同的流水仍是两笔真实交易，去重会丢失资金变化。
  • 为什么从 Users 出发？ 输出要求覆盖全部用户，包括完全没有交易的人。
  • 若数据量很大？ 关注交易表对付款方、收款方的访问与聚合策略，也可维护经过审计的账户流水/余额快照，但需处理一致性与重放。
  • 如何校验系统守恒？ 若不考虑外部入金/出金，所有交易的带符号变化总和应为 0。

常见错误

  • 只统计付款或只统计收款。
  • 使用 INNER JOIN，漏掉无交易用户。
  • 用 UNION 去重，导致合法的重复金额流水丢失。
  • 在别名尚不可见的同层表达式中重复引用 credit，或忘记 COALESCE。
  • 把余额等于 0 误判为越界。
