可怜的小猪。

真正稀缺的不是实验次数，而是每只小猪能够传回多少种不同的信号。先在交互实验室里观察信号，再决定是否展开题解。

HARD 数学 动态规划 组合数学 非付费题
Function signature

poorPigs(buckets, minutesToDie, minutesToTest) → integer

题目

有 buckets 桶外观相同的液体，恰好一桶有毒。你可以让若干只活猪同时饮用任意多桶液体；一桶也可以被多只猪饮用。每次喂完后必须等待 minutesToDie 分钟，期间不能再次喂食。等待结束时，喝到毒液的猪会死亡，其余存活。可以重复“喂食—等待”，但总时间不超过 minutesToTest。求必然识别毒桶所需的最少猪数。

实验规则

  1. 每轮开始时选择仍存活的猪，并为每只猪安排任意桶的混合液。
  2. 饮用瞬间完成，之后等待完整的 minutesToDie 分钟。
  3. 等待期间不能喂食；轮末观察每只猪死亡或存活。
  4. 在总时间耗尽前，可以继续下一轮。

约束

  • 1 <= buckets <= 1000
  • 1 <= minutesToDie <= minutesToTest <= 100
  • 输入均为整数，且恰好存在一桶毒液。

示例 1

输入：buckets = 1000,
      minutesToDie = 15,
      minutesToTest = 60
输出：5

示例 2

输入：buckets = 4,
      minutesToDie = 15,
      minutesToTest = 15
输出：2

一次等待产生 4 种双猪生死组合：仅猪 1 死、仅猪 2 死、都死、都活，分别映射四个桶。

示例 3

输入：buckets = 4,
      minutesToDie = 15,
      minutesToTest = 30
输出：2

可进行两轮等待；两只猪已足够覆盖四桶，虽然一只猪的 3 种状态仍不够。

题解：把死亡时间当作一位数字

从“每只猪只能生或死”升级为“每只猪在哪一轮死，或者始终存活”。

核心洞察

能完整等待的轮数是 rounds = floor(minutesToTest / minutesToDie)。对一只猪而言，它可能在第 1 至第 rounds 轮末死亡，也可能测试结束仍存活，因此共有 states = rounds + 1 种可观察状态。

若使用 p 只猪，状态向量共有 states^p 种。每个桶分配一个不同向量，就能由最终观察唯一定位毒桶。所以答案是满足 states^p >= buckets 的最小非负整数 p。

完整过程

  1. 计算完整轮数 rounds，再得到每只猪的状态数 states = rounds + 1。
  2. 从 p = 0、capacity = 1 开始；只要容量小于桶数，就令容量乘以 states 并增加一只猪。
  3. 构造上，可把桶编号减一后写成 states 进制。第 i 位为 0 时，第 i 只猪不喝该桶；为 k 时，它在第 k 轮喝该桶。
  4. 毒桶对应的饮用安排会让每只猪在指定轮次死亡或始终存活。收集这些数字，按相同进制还原桶编号。
answer = min p such that (⌊minutesToTest / minutesToDie⌋ + 1)p ≥ buckets

正确性证明

引理 1：在给定时间内，一只猪至多表达 rounds + 1 种状态。因为死亡只能首次出现在某一轮末，或从未出现，共这些可能。

引理 2：p 只猪可以实现全部 states^p 个状态向量。给每个目标向量安排饮用：向量第 i 位为 k>0，就让第 i 只猪在第 k 轮喝该桶；为 0 则不喝。若该桶有毒，观察恰好等于目标向量。

必要性：若 states^p < buckets，鸽巢原理保证至少两个桶共享同一观察结果，无法必然区分。

充分性：若 states^p >= buckets，由引理 2 可为每个桶分配不同向量，观察后唯一解码毒桶。因此循环找到的最小 p 既可行又不可能再小，算法正确。

边界情况

  • buckets = 1 时，无须实验，循环返回 0。
  • minutesToTest = minutesToDie 时只有一轮，每只猪仅有“死 / 活”两种状态。
  • 时间不能整除时，余下不足一个致死周期的时间无法提供新观察轮次，必须向下取整。
  • 题目约束保证 minutesToDie <= minutesToTest，因此至少一轮。

复杂度

循环次数就是答案 p = ceil(log_states buckets)。

  • 时间：O(log buckets)
  • 额外空间：O(1)

代码使用整数乘法，避免浮点对数在精确幂边界附近的舍入风险。

替代方案与面试追问

替代方案：可以直接计算 ceil(log(buckets) / log(states))，代码更短，但需要谨慎处理浮点误差；也可以定义 dp[p] = states^p，本质仍是同一个容量递推。

  • 如果有多桶毒液？单个状态向量不再对应唯一桶，需要组合设计 / 群组测试，并重新定义死亡信号模型。
  • 为什么不是每轮重新使用所有猪的二进制结果？猪一旦死亡就不能参与后续轮次；正确的信息量是“首次死亡轮次或存活”，不是独立轮次的任意比特串。
  • 能否输出具体喂法？可以：把每个桶的零基编号转为 states 进制，各位就是各猪的喂食轮次。
  • 如果饮用本身耗时？有效轮数的计算和调度模型都会改变，不能沿用当前公式。

常见错误

  • 误用 2^p，忽略多轮实验让一只猪具备多于两种状态。
  • 把轮数写成 minutesToTest / minutesToDie + 1 后又额外加一次状态，造成重复加一。
  • 认为 2 轮可产生 4 种独立生死序列；事实上猪第一轮死后不能第二轮再“存活”。
  • 用浮点对数直接取整，未处理恰好为整数幂时的精度偏差。
  • 为了构造喂法枚举所有组合，而题目只要求最少猪数。

四语言完整代码

均使用整数容量递增，保持与官方函数签名一致。

JavaLeetCode
class Solution {
    public int poorPigs(int buckets, int minutesToDie,
                        int minutesToTest) {
        int states = minutesToTest / minutesToDie + 1;
        int pigs = 0;
        int capacity = 1;

        while (capacity < buckets) {
            capacity *= states;
            pigs++;
        }
        return pigs;
    }
}
