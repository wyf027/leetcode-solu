可由多种立方和构造的整数

把每个 a³ + b³ 当作一张“配方卡”，出现至少两次的数就是可查询的好整数。

n ≤ 10⁹

题意

给定整数 n。若 x ≤ n 能由至少两组不同的正整数对 (a,b) 表示，且 a ≤ b、x = a³ + b³，则 x 是好整数。返回所有好整数，按升序排列。

示例：n = 4104，答案为 [1729, 4104]。

首屏提示

一个查询不必重新枚举。因为 1001³ > 10⁹，所有可能的正整数底数都在 1…1000 内；先一次性收集碰撞的和，再用二分截取不大于 n 的前缀。

题解

默认收起，避免首屏直接展示完整解法。

核心洞察

  1. 只枚举 1 ≤ a ≤ b ≤ 1000，固定 a 后若和超过 LIMIT，b 更大只会更大，可提前停止。
  2. 哈希表记录每个和出现次数。枚举已限制 a ≤ b，所以交换同一对不会被误算成两种表示。
  3. 把次数至少为 2 的键排序为 GOOD；查询对 GOOD 做 upper_bound / bisect_right，返回前缀。

完整过程

预先建表成本与查询次数无关。先算 cubes[i]，扫描三角形区域，按和累加次数；扫描结束后筛选、排序。面对任意 n，只找第一个大于 n 的位置。

边界

n 小于 1729 时返回空数组；使用整数范围：1000³ = 10⁹，两个正立方和与 LIMIT 的比较仍在 32 位有符号整数范围内。

复杂度

预处理 O(1000² + k log k)，其中 k 为好整数数量；每次查询 O(log k + ans)，额外存储 O(k)（计数表在预处理期使用）。

替代方案

若只有一个很小的 n，可按 ⌊∛n⌋ 当场枚举；多次查询时重复建表会浪费，预处理更合适。

常见错误

  • 让 b 从 1 开始，会把 (a,b) 和 (b,a) 当作两种表示。
  • 只筛选一次出现的和，而没有要求次数至少 2。
  • 每次查询都重新枚举，忽略 LIMIT 固定带来的可复用性。

面试追问

若 LIMIT 变为 10¹²，应使用 long / long long，并把枚举上界改为立方根；若要返回具体的两组配方，哈希表值从计数变为小数组，首次保存一组，第二次命中时再记录答案。
