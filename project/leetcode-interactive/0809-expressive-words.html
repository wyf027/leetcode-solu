情感丰富的文字 Expressive Words

同一个字母，多写几次就像把情绪拉长了。现在要判断：哪些查询词可以通过合法的字母组扩张，变成目标字符串？

中等 数组 双指针 字符串 非付费题
先读题并亲手走一遍分组对齐；完整题解默认收在页面底部。

Problem

题目说明

把连续相同字母看成一个“字母组”。查询词只能向组内添加相同字母，不能删、不能换，也不能改变组的先后顺序。

给定字符串 s 和查询词数组 words。如果一个查询词经过任意次扩张操作后能与 s 完全相同，就称它是可扩张的（stretchy）。返回可扩张查询词的数量。

一次扩张操作选择查询词中的某个字母组（由连续相同字符 c 构成），向组中添加若干个 c；操作完成后，该组的长度必须达到 3 或以上。

例如，hello 可以把末尾的 o 扩张成 ooo，得到 hellooo；却不能只扩成 oo，因为扩张后的组长没有达到 3。还可以把 ll 扩张为更长的同字符组。

示例 1

输入：s = "heeellooo", words = ["hello", "hi", "helo"]
输出：1

hello 的 e、o 组可扩张到目标；hi 字母组不一致；helo 无法得到目标中长度为 2 的 ll。

示例 2

输入：s = "zzzzzyyyyy", words = ["zzyy", "zy", "zyy"]
输出：3

目标的 z 组和 y 组长度都不少于 3，因此三个查询词都能分别补足到目标组长。

函数契约

expressiveWords(s, words) → integer

s: string
words: string[]

扩张边界

  1. 1对应组的字符必须相同。
  2. 2查询组不能比目标组更长，因为操作不允许删除字符。
  3. 3若两组长度不同，目标组长度必须至少为 3。

约束

  • 1 <= s.length, words.length <= 100
  • 1 <= words[i].length <= 100
  • s 与所有 words[i] 仅由小写英文字母组成。

准备好看完整题解了吗？

下面包含核心判定、正确性证明、四种语言实现与面试延伸。建议先用上面的实验器解释一次为什么 helo 不成立。

Two Pointers · Run-length groups

双指针按组同步扫描

无需真的执行扩张。只要同步读取目标串与查询词中的每个连续字母组，检查组字符和组长是否满足扩张的必要且充分条件。

01 · 结构不变

组字符序列必须相同

扩张只会增加当前字符，不会引入新字符组，也不会重排已有组。

02 · 只能增加

目标组不能更短

如果查询组长度大于目标组，就必须删除字符才能对齐，而题目不允许删除。

03 · 短组锁定

目标组小于 3 时必须等长

目标组只有 1 或 2 个字符时，任何增加都会违反“扩张后至少 3 个”的规则。

完整过程

  1. 对每个查询词建立两个指针，分别指向 s 与查询词的当前未处理位置。
  2. 若当前字符不同，立即判定失败。
  3. 向右扫描至字符改变，得到目标组长 lenS 和查询组长 lenW。
  4. 若 lenS < lenW，失败；若 lenS != lenW 且 lenS < 3，也失败。
  5. 两组合法就继续。最后只有两个字符串同时扫描完，查询词才可扩张。
合法 ⇔ 字符相同 ∧ lenW ≤ lenS ∧ (lenW = lenS ∨ lenS ≥ 3)

正确性说明

必要性：扩张不会改变各组的字符及顺序，所以两串的组字符序列必须一致；操作只添加字符，因此查询组不能长于目标组；若组长发生改变，最终目标组必须至少为 3。因此算法的每项检查都是任何合法扩张必须满足的条件。

充分性：若每对组都通过检查，等长组无需操作；不等长组满足 lenW < lenS 且 lenS ≥ 3，可以向查询组补入恰好 lenS - lenW 个相同字符，扩张后组长合法且与目标一致。逐组执行后，整个查询词就等于 s。因此算法不会漏掉任何可扩张词。

复杂度与边界

复杂度

设目标串长度为 |s|，所有查询词总长度为 L，查询词数量为 m。时间复杂度为 O(m·|s| + L)，额外空间为 O(1)（不计输入）。

关键边界

  • 两串字符组数量不同。
  • 目标短组长度 1 或 2，查询组与它不等长。
  • 查询组比目标组长。
  • 最后一个组处理完后只有一个字符串到达末尾。

四语言完整实现

class Solution {
    public int expressiveWords(String s, String[] words) {
        int answer = 0;
        for (String word : words) {
            if (isStretchy(s, word)) {
                answer++;
            }
        }
        return answer;
    }

    private boolean isStretchy(String s, String word) {
        int i = 0;
        int j = 0;

        while (i < s.length() && j < word.length()) {
            if (s.charAt(i) != word.charAt(j)) {
                return false;
            }

            int startS = i;
            int startW = j;
            char current = s.charAt(i);

            while (i < s.length() && s.charAt(i) == current) {
                i++;
            }
            while (j < word.length() && word.charAt(j) == current) {
                j++;
            }

            int lenS = i - startS;
            int lenW = j - startW;
            if (lenS < lenW || (lenS != lenW && lenS < 3)) {
                return false;
            }
        }

        return i == s.length() && j == word.length();
    }
}

function isStretchy(s, word) {
    let i = 0;
    let j = 0;

    while (i < s.length && j < word.length) {
        if (s[i] !== word[j]) {
            return false;
        }

        const startS = i;
        const startW = j;
        const current = s[i];

        while (i < s.length && s[i] === current) i++;
        while (j < word.length && word[j] === current) j++;

        const lenS = i - startS;
        const lenW = j - startW;
        if (lenS < lenW || (lenS !== lenW && lenS < 3)) {
            return false;
        }
    }

    return i === s.length && j === word.length;
}

class Solution:
    def expressiveWords(self, s: str, words: List[str]) -> int:
        def is_stretchy(word: str) -> bool:
            i = 0
            j = 0

            while i < len(s) and j < len(word):
                if s[i] != word[j]:
                    return False

                start_w = j

        return sum(is_stretchy(word) for word in words)

替代方案

可以先把 s 与每个查询词都编码为“字符数组 + 组长数组”，再逐组比较。判定更直观，但会为每个字符串分配额外数组，空间复杂度不再是常数。若同一个目标串要处理大量批次查询，可预先编码目标串，减少重复扫描。

常见错误

  • 只检查目标组长是否至少为 3，却忘了查询组不能更长。
  • 把“不少于 3”错误地理解为查询词原组也必须不少于 3。
  • 只比较相同位置字符，没有按连续组跳跃。
  • 循环结束时未确认两个指针同时到达末尾。

面试追问

  • 若目标串固定、查询量达到百万级？ 先对目标串做游程编码；对查询词仍需线性读取，但无需重复扫描目标原串。
  • 若允许删除字符？ 当前局部组长判定不再充分，需要重新定义操作可达性；若删除也只能在组内发生，则对应组字符序列仍必须一致，但长度条件会改变。
  • 能否流式处理？ 可以。判定只依赖当前两组及是否同时结束，不必保留完整分组数组。
