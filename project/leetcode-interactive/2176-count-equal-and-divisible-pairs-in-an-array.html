01 / 题目

两个条件，同时成立

给定下标从 0 开始的整数数组 nums 和正整数 k。统计满足下列所有条件的下标对 (i, j)，返回它们的数量：

  • 0 ≤ i < j < nums.length；
  • 两个位置上的元素相等：nums[i] == nums[j]；
  • 两个下标的乘积可被 k 整除：(i * j) % k == 0。

参数：nums: 整数数组，k: 整数。返回：整数。数对按下标区分，即使数值相同，不同的位置组合也可能分别计数。

官方示例 1

输入：nums = [3,1,2,2,2,1,3], k = 2
输出：4

合法数对为 (0,6)、(2,3)、(2,4)、(3,4)。对应下标乘积为 0、6、8、12，均可被 2 整除，且每一对的元素值相等。

官方示例 2

输入：nums = [1,2,3,4], k = 1
输出：0

数组中没有重复值，因此没有满足相等条件的数对。

约束

  • 1 ≤ nums.length ≤ 100
  • 1 ≤ nums[i], k ≤ 100

04 / 独立题解

准备好再揭晓

展开后可阅读算法推导、正确性说明与四种语言的完整实现。

枚举每一对，检查两个条件

核心洞察

数组长度最多 100，合法下标对总数最多为 100 × 99 / 2 = 4950。直接枚举全部 i < j，对每一对做常数次判断，足够解决本题。元素值用于判断相等，原始下标用于整除判断，不能混淆。

完整过程

  1. 令计数器 answer = 0。
  2. 枚举左下标 i，范围为 0 到 n - 1。
  3. 枚举右下标 j，从 i + 1 到 n - 1，避免重复和自身配对。
  4. 若 nums[i] == nums[j] 且 (i * j) % k == 0，令 answer 加 1。
  5. 所有下标对检查完毕，返回计数器。

示例 1 中，值为 3 的 (0,6) 命中；值为 1 的 (1,5) 因乘积 5 不能被 2 整除而淘汰；值为 2 的 (2,3)、(2,4)、(3,4) 全部命中，总数为 4。

正确性

覆盖：任意合法数对满足 i < j，因此必定出现在外层枚举 i、内层枚举 j 的某次迭代中。不重复：每个有序下标组合仅枚举一次，且不枚举反向组合。筛选准确：只有题目要求的两个条件同时为真时才加 1。因此，计数器在任意时刻恰好等于已枚举数对中的合法数量；遍历结束后得到全部合法数对的数量。

边界与复杂度

  • n = 1 时内层循环没有迭代，返回 0。
  • k = 1 时整除条件总成立，但仍需判断值相等。
  • i = 0 时乘积是 0，可被任意正整数 k 整除；只有值相等的数对才计入。
  • 本题下标乘积和答案都可用普通整数安全表示；扩展到更大下标时 Java / C++ 应在乘法前转为 64 位整数。
  • 时间复杂度 O(n²)，额外空间 O(1)，不修改输入。页面演示为支持回退而保存数对状态，其空间开销不属于提交算法。

Java

class Solution {
    public int countPairs(int[] nums, int k) {
        int answer = 0;
        // ponytail: n ≤ 100; 大规模输入可按值与 gcd 分组。
        for (int i = 0; i < nums.length; i++) {
            for (int j = i + 1; j < nums.length; j++) {
                if (nums[i] == nums[j] && (i * j) % k == 0) {
                    answer++;
                }
            }
        }
        return answer;
    }
}

class Solution {
public:
    int countPairs(vector<int>& nums, int k) {
        int answer = 0;
        int n = static_cast<int>(nums.size());
        // ponytail: n ≤ 100; 大规模输入可按值与 gcd 分组。
        for (int i = 0; i < n; ++i) {
            for (int j = i + 1; j < n; ++j) {

                    ++answer;
                }
            }
        }
        return answer;
    }
};

替代方案

可以先按元素值分组，在每组原始下标中枚举数对，时间为 O(n + Σ mᵥ²)，最坏仍为 O(n²)，额外空间为 O(n)。不要对数组原地排序后使用新下标。

若规模显著变大，可按 (元素值, gcd(下标, k)) 统计历史频次。对当前下标 j，令 d = gcd(j,k)，仅累计满足 (g*d) % k == 0 的历史类别 g，然后加入当前下标。它利用了 k | i*j 当且仅当 k | gcd(i,k)*gcd(j,k)，且先查询再加入可避免自身配对。设 k 的约数个数为 τ(k)、不同元素值个数为 V，哈希计数的期望时间为 O(n(log k + τ(k)))，额外空间不超过 O(V·τ(k))。当前题目范围使用直接枚举更简单。

面试追问

  • 能否只统计每个值的出现次数？一般不能，因为整除条件依赖下标；当 k = 1 时可对每个频次 m 累加 m(m-1)/2。
  • 能否边读边统计？可以，使用上述按值与 gcd 的历史计数，并在查询后插入当前位置。
  • 为什么 i = 0 要保留？0 = k × 0，完全满足整除定义。

常见错误

  • 计算 nums[i] * nums[j] 的余数，而不是下标乘积。
  • 把两个条件用“或”连接，导致只满足一项就计数。
  • 令 j 从 0 或 i 开始，重复计数或把元素与自身配对。
  • 把合法数对按数值去重，遗漏不同下标的组合。
  • 要求 i 或 j 单独被 k 整除：这是充分条件，不是必要条件。例如 i = 2、j = 3、k = 6。
