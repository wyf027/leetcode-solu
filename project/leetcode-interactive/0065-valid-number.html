合法语法

  • integer := [sign] digits
  • decimal := [sign] (digits. | digits.digits | .digits)
  • number := (integer | decimal) [exponent]
  • exponent := (e | E) integer

题解

Core insight

核心洞察

这不是数值计算，而是语法识别。把「读到某个前缀后，接下来允许什么」编码为状态；每个字符归类为 digit、sign、dot 或 exp，再查唯一转移。不存在转移立即失败。

Accepting states

结束态同样重要

字符全部合法仍不一定是数字，例如 "1e+" 会停在 EXP_SIGN。只有 INTEGER、POINT、FRACTION、EXP_NUMBER 四个状态可以在字符串结束时接收。

完整过程

  1. 1. 从 START 状态开始。
  2. 2. 把当前字符归类为 digit / sign / dot / exp。
  3. 3. 用当前状态和字符类型查询下一状态。
  4. 4. 转移不存在则立即返回 false。
  5. 5. 扫描结束，检查当前状态是否属于接收态。

边界

  • "4." 合法：POINT 是接收态。
  • ".9" 合法：点后至少一个数字。
  • "." 非法：POINT_NO_INT 不是接收态。
  • 指数只能出现一次，且指数部分不允许小数点。
  • 符号只允许在开头或指数标记之后。

复杂度

TIME

替代方案

  • 布尔标记：跟踪数字、点、指数和指数后数字；代码短，但规则更分散。
  • 正则表达式：适合生产校验；面试中可读性和推导过程较弱。
  • 递归下降：语法映射最直接，但本题规模下显得过重。

面试追问

  • 若允许首尾空格？在进入状态机前明确 trim，但不要吞掉内部空格。
  • 若加入十六进制？增加前缀状态和十六进制 digit 类型。
  • 如何从语法系统化构造 DFA？先画 NFA，再合并等价状态。
  • 为何不用解析浮点数？库函数可能接受题目语法之外的表示法。

常见错误

  • 只检查字符是否合法，忘记检查最终状态。
  • 允许指数后出现小数点，误判 "99e2.5"。
  • 让符号出现在任意位置，误判 "--6"。
  • 直接 trim 输入，掩盖当前约束外的非法空格。

class Solution {
    private static final int[][] NEXT = {
        {2, 1, 4, -1}, {2, -1, 4, -1}, {2, -1, 3, 6},
        {5, -1, -1, 6}, {5, -1, -1, -1}, {5, -1, -1, 6},
        {8, 7, -1, -1}, {8, -1, -1, -1}, {8, -1, -1, -1}
    };
    private static final boolean[] ACCEPT = {
        false, false, true, true, false, true, false, false, true
    };

    public boolean isNumber(String s) {
        int state = 0;
        for (char ch : s.toCharArray()) {
            int type = typeOf(ch);
            if (type == -1 || NEXT[state][type] == -1) {
                return false;
            }
            state = NEXT[state][type];
        }
        return ACCEPT[state];
    }

    private int typeOf(char ch) {
        if (ch >= '0' && ch <= '9') return 0;
        if (ch == '+' || ch == '-') return 1;
        if (ch == '.') return 2;
        if (ch == 'e' || ch == 'E') return 3;
        return -1;
    }
}
