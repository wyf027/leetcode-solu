Problem 661 · Easy

图片平滑器Image Smoother

把一张灰度图看成整数矩阵。对每个像素，观察它与周围有效像素的灰度，得到新的平滑图像。

Problem statement

先定义每一个新像素

以下为官方题意的准确转述，参数形式为 imageSmoother(img)。

题意

给定一个 m × n 的整数矩阵 img，其中每个元素表示一个像素的灰度。对每个单元格，取它自身以及周围八个方向中实际存在的单元格，计算这些灰度的平均值并向下取整，作为该位置的新灰度。

矩阵边缘或角落之外的位置不存在，因此不计入总和，也不计入数量。所有位置都基于原始矩阵计算，最终返回完整的新矩阵。

约束

  • m == img.length
  • n == img[i].length
  • 1 <= m, n <= 200
  • 0 <= img[i][j] <= 255

官方示例 1

输入：img = [[1,1,1],[1,0,1],[1,1,1]]
输出：[[0,0,0],[0,0,0],[0,0,0]]
解释：角落取 4 格，边取 6 格，中心取 9 格；
各自平均值向下取整后均为 0。

官方示例 2

输入：img = [[100,200,100],[200,50,200],[100,200,100]]
输出：[[137,141,137],[141,138,141],[137,141,137]]
解释：例如左上角为 floor((100+200+200+50)/4)
     = floor(137.5) = 137；
中心为 floor(1250/9) = 138。

Solution

九格扫描：只读原图，另写结果

对每个输出位置，枚举相对位移 [-1, 0, 1] × [-1, 0, 1]，只把坐标仍在矩阵内的单元格纳入平均。

核心洞察

每个位置最多只依赖 9 个固定邻居。与其为角落、边和内部写三套逻辑，不如统一枚举 9 个偏移，并通过边界判断筛掉不存在的坐标。

关键纪律：计算期间始终读取原矩阵。若边算边覆盖，后面的像素会错误地读到已经平滑过的值。

完整过程

  1. 创建与 img 同尺寸的结果矩阵。
  2. 按行遍历每个目标坐标 (r, c)。
  3. 枚举 dr、dc 从 -1 到 1，得到候选邻居。
  4. 候选坐标合法时累加灰度，同时把有效数量加一。
  5. 把 sum / count 向下取整后写入结果矩阵。

正确性说明

邻域完整性：双重偏移循环恰好访问当前单元格及八个方向，每个候选坐标出现一次；边界判断恰好排除矩阵外的单元格。因此 sum 与 count 分别等于题目定义的有效灰度和与有效格数。

单格正确性：整数除法（或显式向下取整）产生该有效邻域平均值的下取整，正是目标位置的答案。

整体正确性：算法对全部 m × n 个位置执行上述过程，并只读取未改变的原矩阵，所以结果矩阵的每个位置都正确。

边界与复杂度

  • 单格 / 单行 / 单列：统一边界判断自然适用。
  • 全 0 或全 255：平均后仍保持相同灰度。
  • 时间：O(mn)，每格最多检查 9 次，常数 9 被省略。
  • 空间：O(mn)，用于返回结果；除返回值外辅助空间为 O(1)。
  • 数值安全：最大局部和为 9 × 255 = 2295。

Java

class Solution {
    public int[][] imageSmoother(int[][] img) {
        int m = img.length;
        int n = img[0].length;
        int[][] answer = new int[m][n];

        for (int r = 0; r < m; r++) {
            for (int c = 0; c < n; c++) {
                int sum = 0;
                int count = 0;

                for (int dr = -1; dr <= 1; dr++) {
                    for (int dc = -1; dc <= 1; dc++) {
                        int nr = r + dr;
                        int nc = c + dc;
                        if (nr >= 0 && nr < m &&
                            nc >= 0 && nc < n) {
                            sum += img[nr][nc];
                            count++;
                        }
                    }
                }
                answer[r][c] = sum / count;
            }
        }
        return answer;
    }
}

var imageSmoother = function(img) {
    const m = img.length;
    const n = img[0].length;
    const answer = Array.from(
        { length: m },
        () => Array(n).fill(0)
    );

    for (let r = 0; r < m; r++) {
        for (let c = 0; c < n; c++) {
            let sum = 0;
            let count = 0;

            for (let dr = -1; dr <= 1; dr++) {
                for (let dc = -1; dc <= 1; dc++) {
                    const nr = r + dr;
                    const nc = c + dc;
                    if (nr >= 0 && nr < m &&
                        nc >= 0 && nc < n) {
                        sum += img[nr][nc];
                        count++;
                    }
                }
            }
            answer[r][c] = Math.floor(sum / count);
        }
    }
    return answer;
};

from typing import List


class Solution:
    def imageSmoother(
        self, img: List[List[int]]
    ) -> List[List[int]]:
        m, n = len(img), len(img[0])
        answer = [[0] * n for _ in range(m)]

        for r in range(m):
            for c in range(n):
                total = 0
                count = 0

                for dr in range(-1, 2):
                    for dc in range(-1, 2):
                        nr, nc = r + dr, c + dc
                        if 0 <= nr < m and 0 <= nc < n:
                            total += img[nr][nc]
                            count += 1

                answer[r][c] = total // count

        return answer

替代方案

二维前缀和：先构建前缀和，再用矩形查询取得每个截断后的 3×3 邻域总和。时间仍为 O(mn)，空间也为 O(mn)；当窗口固定为 3×3 时，直接枚举更短、更易验证。

原地编码：由于灰度仅占 8 位，可以在高位临时存新值、低位保留旧值，最后统一右移。这样可降辅助空间，但可读性与移植性较差，面试中应先说明位宽前提。

常见错误

  • 把矩阵外的缺失位置当成灰度 0，并错误地计入除数。
  • 角落、边缘仍固定除以 9，而没有使用有效邻居数量。
  • 直接覆盖 img，导致后续位置读取到新值。
  • 忘记向下取整，或在 JavaScript 中直接保留小数。
  • 行列边界混淆，把 m 与 n 用反。

面试追问

如果平滑窗口改成 k × k 呢？

直接枚举会变成 O(mnk²)；二维前缀和可以把每个窗口求和降到 O(1)，总时间保持 O(mn)。

如何把额外空间降到 O(1)？

利用输入值位于 0 到 255：低 8 位保存原灰度，高位写入新灰度。计算时始终读取 value & 255，完成后整体右移 8 位。需要明确语言的整数位运算语义。

为什么不用卷积库？

题目的边界规则要求按“实际存在的格数”重新确定除数，且输入规模最多 200 × 200。手写邻域扫描最直接，也能清楚展示边界处理。
