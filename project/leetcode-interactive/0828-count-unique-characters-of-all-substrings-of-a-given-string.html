01 / Problem

题目要求

把每个位置不同的子串都计入答案，即使两个子串的文本内容相同，也要按它们在原字符串中的不同出现位置分别统计。

准确转述

定义 countUniqueChars(t) 为字符串 t 中只出现一次的字符个数。给定只含大写英文字母的字符串 s，求它的所有连续子串 t 的 countUniqueChars(t) 之和。

例如 LEETCODE 中，L、T、C、O、D 各出现一次，因此 countUniqueChars("LEETCODE") = 5。

题目保证最终答案可以放进 32 位整数。

函数签名与约束

uniqueLetterString(s) → integer

  • 1 <= s.length <= 105
  • s 只包含大写英文字母 A-Z
  • 重复出现的同内容子串也要分别计数
Example 01
输入s = "ABC"
输出10

子串为 A、B、C、AB、BC、ABC；每个字符均唯一，贡献和为 1+1+1+2+2+3。

Example 02
输入s = "ABA"
输出8

与示例 1 类似，但完整子串 ABA 中只有 B 出现一次，因此该子串的计数为 1。

Example 03
输入s = "LEETCODE"
输出92

对每个位置不同的连续子串分别计算唯一字符数，再将结果累加。

Unlocked

一次扫描，结算每次出现的贡献

不枚举子串，改为枚举“某个字符的某次出现被哪些子串唯一包含”。

核心洞察：从子串视角切换到出现位置视角

假设字符 s[i] 上一次出现的位置是 prev，下一次出现的位置是 next；不存在时分别使用哨兵 -1 与 n。

要让 s[i] 在一个子串中恰好出现一次，子串起点 L 必须落在 [prev + 1, i]，终点 R 必须落在 [i, next - 1]。左右选择独立，因此：

contribution(i) = (i - prev) × (next - i)

每个“子串—唯一字符位置”二元组都会被唯一地分配给某个位置 i，所以累加所有位置的贡献，正好得到题目所求。

完整过程：新出现负责结算旧出现

直接预处理每个位置的前后同字符位置已经可以做到线性复杂度。为了只扫描一次并使用常数额外空间，可以为 26 个字母各维护最近两次出现位置：

  1. prev1[c] 记录字符 c 最近一次出现，prev2[c] 记录倒数第二次出现，初始均为 -1。
  2. 扫描到字符 c 的新位置 i 时，prev1[c] 的右侧同字符边界终于确定为 i。
  3. 结算旧位置 prev1[c] 的贡献：(prev1[c] - prev2[c]) × (i - prev1[c])。
  4. 窗口前移：令 prev2[c] = prev1[c]，prev1[c] = i。
  5. 扫描结束后，每个字符最后一次出现还没有右边界，用哨兵 n 统一完成尾部结算。

用 ABA 走一遍

  • 读到 A@0、B@1：还不知道它们的下一次出现，暂不结算。
  • 读到 A@2：结算 A@0，得到 (0-(-1))×(2-0)=2。
  • 扫描结束：用 n=3 结算 B@1 得 4，结算 A@2 得 2，总计 8。

正确性证明

引理 1：公式计数的子串中，当前出现一定唯一。

起点严格位于前一次相同字符之后，终点严格位于后一次相同字符之前，同时区间包含位置 i。因此区间内含 s[i]，却不含它相邻的任何同字符出现；更远的同字符也必然在这两个相邻边界之外。

引理 2：所有使当前位置唯一的子串都会被公式计数。

若包含 i 的子串让 s[i] 唯一，它不可能越过 prev 或 next 把相同字符纳入区间，所以其起点、终点必分别落入上述两个选择区间。

定理：算法返回所有子串唯一字符数之和。

由两个引理，每个位置的公式恰好计数它作为唯一字符出现的全部子串。任何子串的每个唯一字符对应唯一的位置，不会漏计或重复计数。对所有位置求和，等于对所有子串的唯一字符个数求和。

边界、数据类型与复杂度

  • 长度为 1：两侧直接使用 -1 与 n，贡献为 1。
  • 字符全相同：只有长度为 1 的子串对答案有贡献，窗口仍能正确结算。
  • 字符全不同：每个位置的边界都是两个哨兵，公式覆盖所有包含该位置的子串。
  • 尾部处理：循环结束后的统一结算不可遗漏，否则每种字符的最后一次出现都会丢失。
  • 数值安全：题目保证最终答案为 32 位整数；Java/C++ 的乘法中间值仍显式使用 64 位，JavaScript 的 Number 在本题范围内精确。
TimeO(n)主扫描一次，收尾仅遍历 26 个字母。
Extra SpaceO(1)两个长度为 26 的位置数组。

四语言完整代码

以下实现均采用“最近两次位置 + 尾部结算”，函数签名与官方提交形式一致。

import java.util.Arrays;

class Solution {
    public int uniqueLetterString(String s) {
        int[] prev2 = new int[26];
        int[] prev1 = new int[26];
        Arrays.fill(prev2, -1);
        Arrays.fill(prev1, -1);

        long answer = 0L;
        for (int i = 0; i < s.length(); i++) {
            int c = s.charAt(i) - 'A';
            answer += (long) (prev1[c] - prev2[c])
                    * (i - prev1[c]);
            prev2[c] = prev1[c];
            prev1[c] = i;
        }

        int n = s.length();
        for (int c = 0; c < 26; c++) {
            answer += (long) (prev1[c] - prev2[c])
                    * (n - prev1[c]);
        }
        return (int) answer;
    }
}

public:

        array<int, 26> prev1;

        prev1.fill(-1);

            answer += 1LL * (prev1[c] - prev2[c])
                    * (n - prev1[c]);

        return static_cast<int>(answer);

替代方案与取舍

1. 位置列表贡献法

为每个字母收集全部下标，并在首尾补 -1、n。随后枚举每次真实出现，使用同一个乘法公式。它同样是 O(n)，逻辑直观，但需要 O(n) 额外空间。

2. 以右端点递推

维护所有以当前位置结尾的子串，其唯一字符总数相对上一步发生的变化。该方法也可做到线性时间，但状态推导更容易写错，贡献法通常更适合解释和证明。

3. 枚举子串

固定左端点并向右扩展，可以用频次表维护唯一字符数，时间仍为 O(n²)；在 n = 10⁵ 时不可行，仅适合作为小规模思考或对拍参考。

面试追问

为什么左右选择可以相乘？

每个合法起点可以搭配任意合法终点，二者没有额外依赖，按乘法原理得到组合数。

为什么只需要最近两次位置？

扫描到新位置时，它只负责结算同字符的上一次出现；那次出现的左右边界正是倒数第二次位置与当前新位置。

字符集不是 26 个大写字母怎么办？

把固定数组替换成映射，键为字符，值为最近两次位置；时间仍为 O(n)，空间变为 O(字符种类数)。

若改成统计“恰好出现 k 次”呢？

需要保留更长的相同字符位置窗口，组合能容纳目标 k 次出现、同时排除窗口外相邻出现的左右边界。

可以边读流边给最终答案吗？

中途只能结算已经看到下一次同字符的位置；流结束后仍需一次尾部结算，因此必须知道输入结束。

最容易出现的 off-by-one 在哪里？

哨兵应是 -1 与 n，起点数量是 i-prev，终点数量是 next-i；不是再额外加 1。

常见错误

  • 把相同文本的子串去重，误解了题目按出现位置计数的要求。
  • 统计字符在原字符串中是否唯一，而不是在每个子串中是否唯一。
  • 只在遇到下一个同字符时累加，忘记用 n 结算各字符最后一次出现。
  • 先计算差值再在 32 位整数中完成乘法，可能让中间表达式溢出。
  • 使用双重循环枚举全部子串，无法通过 10⁵ 的规模。
