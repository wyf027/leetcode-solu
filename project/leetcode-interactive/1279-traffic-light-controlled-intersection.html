红绿灯路口

两条道路共享一个十字路口。你的任务不是规划最短路径，而是为并发到达的车辆守住一条简单却关键的安全规则：任何时刻，只能放行当前绿灯道路上的一辆车。

EASY多线程互斥锁付费题返回值 void

题目转述

十字路口由道路 A 与道路 B 相交组成。道路 A 对应方向 1、2，道路 B 对应方向 3、4。初始时道路 A 为绿灯、道路 B 为红灯。每辆车到达时，系统会并发调用 carArrived。

你需要按安全顺序调用两个回调：若该车所在道路当前不是绿灯，先调用 turnGreen 将它切为绿灯；随后调用 crossCar 让车通过。实现必须避免两条路上的车辆同时进入路口，也不能产生死锁。

关键语义：题目不要求公平调度，也不要求返回固定的车辆顺序；只要求每次回调序列合法、安全，并让所有已进入方法的车辆最终能够通过。

标准调用参数

carArrived(
  carId: int,
  roadId: int,
  direction: int,
  turnGreen: Runnable,
  crossCar: Runnable
) -> void
carId车辆的唯一编号。
roadId车辆所在道路：1 表示 A，2 表示 B。
direction行驶方向 1～4；方向 1、2 属于道路 A，方向 3、4 属于道路 B。本解法无需依赖它。
turnGreen把当前车辆所在道路切为绿灯；只有确实需要切换时才调用。
crossCar让当前车辆通过路口。

官方元数据中的完整样例参数

样例 1
cars        = [1, 3, 5, 2, 4]
directions  = [2, 1, 2, 4, 3]
arrivalTimes= [10, 20, 30, 40, 50]

解释：车辆 1、3、5 从道路 A 到达，随后车辆 2、4 从道路 B 到达。一个合法回调轨迹是：前三辆依次 crossCar，车辆 2 到来时调用一次 turnGreen，然后车辆 2、4 依次通过。方法本身返回 void。

样例 2
cars        = [1, 2, 3, 4, 5]
directions  = [2, 4, 3, 3, 1]
arrivalTimes= [10, 20, 30, 40, 40]

解释：最后两辆车在同一时刻到达，线程获得锁的先后次序可以不同，因此合法输出并不唯一；无论调度如何，两条道路都不能同时放行。

约束

  • 1 ≤ n ≤ 20
  • cars = [1, 2, …, n]，每个车辆编号唯一。
  • directions.length = n，且每项是 1、2、3、4 之一。
  • arrivalTimes.length = n，到达时间按非递减顺序给出。
  • 每辆车恰好触发一次 carArrived；回调由评测器提供。

    准备好揭开互斥锁了吗？

    题解默认收起。先尝试用一句话描述临界区，再展开核对。

    题解：用一把锁串行化整个路口

    核心洞察

    危险不只发生在切灯瞬间。若切灯后立即释放锁，另一条路可能切回绿灯，而第一辆车仍在执行 crossCar。因此，读取当前绿灯、必要时切换、车辆通过必须属于同一个临界区。

    完整过程

    1. 线程进入 carArrived 后先获取同一把互斥锁。
    2. 比较 greenRoad 与当前 roadId。
    3. 不同则调用 turnGreen，并同步更新状态。
    4. 在仍持锁时调用 crossCar。
    5. 使用 finally / RAII 释放锁，下一辆车才能进入。

    正确性说明

    安全性：互斥锁保证任意时刻至多一个线程处于临界区，因此不可能有两辆来自不同道路的车同时执行通过回调。

    灯色合法：执行 crossCar 前，若当前绿灯不属于该车道路，算法已先调用切灯回调并更新状态；否则保持原灯色即可。

    无死锁：算法只获取一把锁，不存在循环等待；异常安全写法还能保证锁被释放。

    复杂度

    每辆车执行常数次判断与回调，时间复杂度 O(1)（不计等待锁的调度时间），额外空间 O(1)。

    边界情况

    • 只有一辆车：初始在 A 路时无需切灯；在 B 路时切一次。
    • 所有车来自同一路：第一次可能切灯，之后不重复切换。
    • 两路交替到达：可能频繁切灯，但始终安全。
    • 多车同时到达：通过顺序由锁调度决定，合法顺序不唯一。
    • 回调抛出异常：Java / JavaScript / Python 的 finally 与 C++ 的 RAII 负责释放锁。

    替代方案与取舍

    可以用信号量、条件变量或显式队列做公平调度，但本题没有要求严格公平或最高吞吐量。单互斥锁状态最少、证明最短，也避免条件变量的丢失唤醒与复杂状态转换。

    常见错误

    • 只给 turnGreen 加锁，没有覆盖 crossCar。
    • 每辆车或每条路使用不同的锁，无法保护共享路口。
    • 每次到车都切灯，违反“仅在必要时调用”的语义。
    • 忘记初始绿灯是道路 A（greenRoad = 1）。

    四语言完整实现

    import java.util.concurrent.locks.Lock;
import java.util.concurrent.locks.ReentrantLock;

class TrafficLight {
    private final Lock lock = new ReentrantLock();
    private int greenRoad = 1;

    public void carArrived(
            int carId,
            int roadId,
            int direction,
            Runnable turnGreen,
            Runnable crossCar) {
        lock.lock();
        try {
            if (greenRoad != roadId) {
                turnGreen.run();
                greenRoad = roadId;
            }
            crossCar.run();
        } finally {
            lock.unlock();
        }
    }
}

    JavaScript 不在该题官方可提交语言列表中；以下是保持同一并发语义的本地参考实现。

    class Mutex {
  constructor() {
    this.locked = false;
    this.waiters = [];
  }

  lock() {
    return new Promise((resolve) => {
      if (!this.locked) {
        this.locked = true;
        resolve();
      } else {
        this.waiters.push(resolve);
      }
    });
  }

  unlock() {
    const next = this.waiters.shift();
    if (next) next();
    else this.locked = false;
  }
}

class TrafficLight {
  constructor() {
    this.mutex = new Mutex();
    this.greenRoad = 1;
  }

  async carArrived(carId, roadId, direction, turnGreen, crossCar) {
    await this.mutex.lock();
    try {
      if (this.greenRoad !== roadId) {
        await turnGreen();
        this.greenRoad = roadId;
      }
      await crossCar();
    } finally {
      this.mutex.unlock();
    }
  }
}
    from threading import Lock
from typing import Callable


class TrafficLight:
    def __init__(self):
        self._lock = Lock()
        self._green_road = 1

    def carArrived(
        self,
        carId: int,
        roadId: int,
        direction: int,
        turnGreen: Callable[[], None],
        crossCar: Callable[[], None],
    ) -> None:
        with self._lock:
            if self._green_road != roadId:
                turnGreen()
                self._green_road = roadId
            crossCar()

    面试追问

    • 如何保证严格公平？维护 FIFO 等待队列，或使用具备公平策略的锁；代价是实现与调度开销上升。
    • 能否同时放行同一路多辆车？若题目允许并发通过，可将“道路占用”与“单车通过”拆分，并用读写/计数协议；当前接口语义下无需扩大临界区并发。
    • 为什么 direction 没被使用？道路编号已经足够决定绿灯；方向只描述车在该道路上的行驶方向。
    • 回调很慢怎么办？不能简单把它移出锁外，否则会破坏安全性；需要改变接口或引入路口占用状态与完成通知。
