同时运行 N 台电脑的
最长时间

2141 / Maximum Running Time of N Computers

电池可以换位置，电量不会再生。如何让所有电脑一起坚持到最后？

01 / 题目

LeetCode 原题 ↗

给定整数 n 和下标从 0 开始的整数数组 batteries。你有 n 台电脑，第 i 块电池可以独立供一台电脑运行 batteries[i] 分钟。求全部电脑同时持续运行的最大整数分钟数。

  • 初始每台电脑至多连接一块电池；同一块电池不能同时给多台电脑供电。
  • 可在任意整数时刻换电池，次数不限，换电池不耗时。
  • 可以使用新电池，也可以使用从其他电脑换下的剩余电池；不能充电。
参数与返回值

maxRunTime(n, batteries) → 最大运行分钟数，返回值可能超过 32 位整数。

约束

1 ≤ n ≤ batteries.length ≤ 10⁵
1 ≤ batteries[i] ≤ 10⁹

官方示例 1

输入：n = 2, batteries = [3,3,3]
输出：4

电脑 A 先用电池 0，电脑 B 先用电池 1。第 2 分钟时，B 换成电池 2，电池 1 留有 1 分钟电量；第 3 分钟时，A 换成电池 1。两台电脑一起运行到第 4 分钟。

官方示例 2

输入：n = 2, batteries = [1,1,1,1]
输出：2

第一分钟分别使用电池 0、2，第二分钟分别换用电池 1、3。两台电脑均能连续运行 2 分钟。

03 / 题解 · 二分运行时长

核心洞察：先问 T 分钟能不能做到

在长度为 T 的时间窗口内，一块电池最多贡献 min(b, T) 分钟。即使容量远大于 T，它也不能同时服务两台电脑。全部电脑需要 n × T 分钟供电，因此判定条件为：

sum(min(batteries[i], T)) ≥ n × T

可行时长构成从 0 开始的连续整数区间：能够持续 T 分钟，就一定能提前停止在更短时间。于是二分查找最后一个可行值。

完整过程

  1. 累计容量总和 S。答案不能超过 floor(S / n)，令 lo = 0、hi = floor(S / n)。
  2. 当 lo < hi，取上中位数 mid = lo + floor((hi - lo + 1) / 2)。
  3. 遍历所有电池，累加 min(b, mid)。
  4. 若供电总量 ≥ n × mid，则 mid 可行，令 lo = mid；否则令 hi = mid − 1。
  5. 区间缩成一个整数时返回 lo。

示例 1：S = 9，上界为 4。区间 [0,4] 取 T = 2，贡献 6 ≥ 4；接着 T = 3，贡献 9 ≥ 6；最后 T = 4，贡献 9 ≥ 8，得到答案 4。

正确性：为什么总贡献足够就能排班？

必要性。每块电池在 T 分钟内至多运行 T 分钟，也不能超过自身容量；所以它最多贡献 min(b,T)。如果贡献之和小于 nT，就无法覆盖全部电脑。

充分性。对 T > 0，从各块电池的截断容量中取整数使用量，使总和恰好为 nT，每块用量不超过 T。把这些电池使用段依次填进 n 条长度为 T 的电脑时间线，填满一条就转到下一条。

若某块用量为 d 的电池从一条时间线的 a 时刻开始并跨过末端，它的两段分别在旧电脑的 [a,T) 和新电脑的 [0,d−(T−a))。因为 d ≤ T，新段终点 ≤ a，两段不会在真实时间上重叠。同一块电池不会同时供两台电脑，所有切换点又都是整数，因此这个排班合法。T = 0 则自然可行。

二分正确性。合法排班可以截短，因此可行性单调。始终保持 lo 可行且最优值在 [lo,hi]：可行时去掉 mid 左侧，不可行时去掉 mid 及右侧。上中位数保证 lo < hi 时区间严格缩小，最终唯一值就是最大可行时长。

边界与数值安全

  • n = 1：所有电池依次使用，答案就是 S。
  • 电池数恰好等于 n：答案等于最小容量；一旦耗尽一块，无法同时维持 n 台。
  • 容量悬殊：n = 2、[100,1] 的答案是 1，而不是总量平均值 50。
  • S 最大为 10¹⁴，Java 使用 long，C++ 使用 long long。JavaScript Number 对这里的整数精确；本实现的 n × mid ≤ S ≤ 10¹⁴。
  • JavaScript 不能用位运算求中点，位运算会截成 32 位整数。

复杂度

令 m 为电池数量、U = floor(S/n)。时间 O(m log(U+1))，额外空间 O(1)。下面四份代码均不排序、不修改输入；演示为保留可回退轨迹，会另外保存每轮数据。

替代方案：排序后剥离超大电池

将容量排序，设剩余电脑数为 k、剩余容量为 S。如果最大容量 b 大于 S/k，就把它单独分配给一台电脑，令 S 减去 b、k 减 1，并继续处理剩余电池。没有超大电池时，答案是 floor(S/k)。

理由是原问题的最优时长不超过 S/k，所以这块超大电池始终足以独占一台电脑；去掉它后，其余电池必须且足以支撑剩下 k−1 台。停止时所有容量都不超过平均值：对整数 T = floor(S/k)，所有整数容量均 ≤ T，总贡献就是 S ≥ kT。时间 O(m log m)，空间取决于语言排序实现。这种方法代码也短，但要解释剥离不变式。

常见错误

  • 直接返回 floor(S/n)：忽略电池不能同时服务多台电脑。
  • 只保留最大的 n 块：丢掉了小电池通过轮换贡献的能量。
  • 用下中位数且更新 lo = mid：只剩两个候选值时可能死循环。
  • 用 32 位变量累计，或在转成长整数前先做 32 位乘法。
  • 按“分钟”模拟答案：时间上界可达 10¹⁴，无法逐分钟遍历。

面试追问

  • 能输出换电池安排吗？可以用充分性证明中的时间线填充构造，保存每段的电脑编号及起止时刻，无需逐分钟模拟。
  • 换电池需要时间怎么办？贡献总量不再足以证明可行，需要把切换停机及覆盖关系纳入模型。
  • 不同电脑耗电速度不同呢？统一的 nT 需求模型不再直接适用，必须明确电池容量单位及连接限制，再重新推导判定。

Java

class Solution {
    public long maxRunTime(int n, int[] batteries) {
        long sum = 0;
        for (int b : batteries) sum += b;
        long lo = 0, hi = sum / n;
        while (lo < hi) {
            long mid = lo + (hi - lo + 1) / 2;
            long supply = 0;
            for (int b : batteries) supply += Math.min((long) b, mid);
            if (supply >= mid * n) lo = mid;
            else hi = mid - 1;
        }
        return lo;
    }
}

#include <algorithm>
#include <vector>
using namespace std;

class Solution {
public:
    long long maxRunTime(int n, vector<int>& batteries) {
        long long sum = 0;
        for (int b : batteries) sum += b;
        long long lo = 0, hi = sum / n;
        while (lo < hi) {
            long long mid = lo + (hi - lo + 1) / 2;
            long long supply = 0;
            for (int b : batteries)
                supply += min(static_cast<long long>(b), mid);
            if (supply >= mid * n) lo = mid;
            else hi = mid - 1;
        }
        return lo;
    }
