Jump Game VII

一条二进制跑道，一段允许的跳跃距离。你能抵达最后一格吗？

先独立思考，再打开页面底部的交互题解。

01 / 任务与规则

给定从下标 0 开始的二进制字符串 s，以及整数 minJump、maxJump。起点是下标 0，且起点字符保证为 '0'。每次从位置 i 跳到位置 j，必须同时满足：

  • i + minJump ≤ j ≤ min(i + maxJump, s.length − 1)。
  • 落点必须是 s[j] == '0'；中途跨过的字符不影响跳跃。

判断能否经过若干次合法跳跃到达最后一个下标 s.length − 1，返回布尔值 true 或 false。

参数与返回

canReach(s, minJump, maxJump) → boolean

s：二进制字符串；minJump：最小跳距；maxJump：最大跳距。

完整约束

  • 2 ≤ s.length ≤ 10⁵
  • s[i] ∈ {'0', '1'}
  • s[0] == '0'
  • 1 ≤ minJump ≤ maxJump < s.length

02 / 官方示例

示例 1

输入：s = "011010", minJump = 2, maxJump = 3
输出：true

从下标 0 跳到 3，再从 3 跳到 5，两次跳距分别为 3 和 2，落点都是 '0'。

输出：false

虽然终点是 '0'，但从可达的位置无法继续连接到终点。

题解 / 用一个窗口统计可达起跳点

核心洞察

与其从每个起点枚举落点，不如反过来问：对当前落点 i，哪些位置能够跳过来？答案恰好是闭区间 [i − maxJump, i − minJump] 与合法下标范围的交集。

令 dp[i] 表示位置 i 是否可达。只有字符是 '0'，且上述区间里至少存在一个可达位置，i 才可达。用 count 维护区间内 dp 为真的数量，每次右移只需加入一个位置、移除一个位置。

dp[0] = true
L = max(0, i - maxJump), R = i - minJump
count = Σ dp[k]，其中 L ≤ k ≤ R（空区间为 0）
dp[i] = (s[i] == '0') 且 (count > 0)

完整过程

  1. 建立长度 n 的布尔数组，初始只有 dp[0] = true，窗口计数为 0。
  2. 从 i = 1 扫描到 n − 1。若 i − minJump ≥ 0，把新进入窗口的 dp[i − minJump] 加入计数。
  3. 若 i − maxJump − 1 ≥ 0，把刚离开窗口的 dp[i − maxJump − 1] 从计数扣除。
  4. 两次更新完成后，根据字符是否为 '0' 以及 count 是否大于 0 设置 dp[i]。
  5. 返回 dp[n − 1]。

示例 1：i = 1 时窗口为空；i = 2 时窗口含起点，但字符为 '1'，仍不可达。i = 3 时窗口为 [0,1]，起点可达，所以 dp[3] 为真。i = 4 时窗口 [1,2] 没有可达点。i = 5 时窗口 [2,3] 包含可达的 3，终点因此可达。

正确性证明

基础：dp[0] 为真，符合初始站在 0 的条件。扫描前 count 为 0；i = 1 的窗口至多包含下标 0，加入步骤会正确处理它。

窗口不变量：从 i − 1 到 i，右边界从 i − 1 − minJump 移到 i − minJump，左边界从 i − 1 − maxJump 移到 i − maxJump。因此加入 i − minJump，移除 i − maxJump − 1 后，count 恰为当前合法起跳区间里的可达点数，负下标不计入。

归纳：minJump ≥ 1，窗口内下标都小于 i，其 dp 已正确求出。若算法标记 i 可达，则它是 '0' 且窗口有可达起点，连接一跳即可到达；若 i 确实可达，其最后一跳的起点一定在窗口内且可达，所以 count > 0，算法必将它标记为真。由归纳可知最终返回正确。

边界与复杂度

  • 窗口右边界小于 0 时为空；不得读取负下标。
  • 终点是 '1' 时必为 false，可选择提前返回；本实现由统一转移处理。
  • minJump = maxJump 时窗口大小为 1，算法仍成立；全是 '0' 也不意味着固定跳距一定能到终点。
  • 每个下标仅被加入、移除各一次，时间 O(n)，dp 数组占空间 O(n)。交互演示保存每帧状态，仅面向最多 60 位的小输入，不是提交实现。

Java

class Solution {
    public boolean canReach(String s, int minJump, int maxJump) {
        int n = s.length();
        boolean[] dp = new boolean[n];
        dp[0] = true;
        int count = 0;
        for (int i = 1; i < n; i++) {
            int add = i - minJump;
            int remove = i - maxJump - 1;
            if (add >= 0 && dp[add]) count++;
            if (remove >= 0 && dp[remove]) count--;
            dp[i] = s.charAt(i) == '0' && count > 0;
        }
        return dp[n - 1];
    }
}

var canReach = function(s, minJump, maxJump) {
    const n = s.length;
    const dp = new Uint8Array(n);
    dp[0] = 1;
    let count = 0;
    for (let i = 1; i < n; i++) {
        const add = i - minJump;
        const remove = i - maxJump - 1;
        if (add >= 0) count += dp[add];
        if (remove >= 0) count -= dp[remove];
        dp[i] = s[i] === '0' && count > 0 ? 1 : 0;
    }
    return dp[n - 1] === 1;
};

        }

};

替代方案、错误与追问

替代方案

  • 朴素 DP：逐一检查候选起点，时间 O(n · (maxJump − minJump + 1))，最坏 O(n²)，空间 O(n)。适合理解转移，不适合最大规模。
  • 前缀和：令 prefix[t] 为 dp[0..t−1] 的和。非空窗口中的可达数量为 prefix[R+1] − prefix[L]，时间 O(n)，空间 O(n)。更直接地表达区间查询，但需要额外前缀数组。
  • BFS + 最远扫描边界：将可达位置入队，用一个全局边界避免重复扫描已检查的落点；每个字符只扫描一次，时间 O(n)，空间 O(n)。普通 BFS 若反复扫描重叠区间仍可能退化。

常见错误

  • 移除的是 i − maxJump − 1，不是仍处于窗口内的 i − maxJump。
  • 统计窗口内的字符 '0'，而非可达的 dp 值：落点合法不代表能走到。
  • 先判定 dp[i] 再更新窗口，会使用前一个落点的候选范围。
  • 始终跳最远的 '0' 并不可靠。s="0011010", minJump=2, maxJump=4 中，先跳到 4 会卡住，但 0 → 2 → 6 可以成功。
  • 只因中间遇到 '1' 就停止扫描：障碍可以跨越；某个位置不可达也不代表后续位置都不可达。

面试追问

如何输出一条路径？维护候选窗口内的可达下标队列；当 i 可达时，记录一个有效起点为 parent[i]。从终点回溯到 0 再反转，额外空间 O(n)。

能减少空间吗？dp 只需保留尚可能进入或离开窗口的位置，可用大小 maxJump + 1 的环形缓冲；时间 O(n)，空间 O(maxJump)。写入前必须完成当前轮加入和移除，防止覆盖还要读取的值。

为什么不能照搬 Jump Game 的最远可达贪心？本题存在最小跳距和不可落脚的位置，不能把所有较小下标都视为可达。维护真实的可达起点集合或其计数才能保证正确。
