K 连续位的最小翻转次数

Minimum Number of K Consecutive Bit Flips

题目交互演示题解测试与验证

题目描述

给定二进制数组 nums 和整数 k。一次 k 位翻转会选择一个长度恰为 k 的连续子数组，同时将其中每个 0 变为 1、每个 1 变为 0。

求使数组中不再存在 0 所需的最少翻转次数；若无法做到，返回 -1。

函数形式

minKBitFlips(nums: integer[], k: integer) → integer

约束

  • 1 ≤ nums.length ≤ 10⁵
  • 1 ≤ k ≤ nums.length
  • nums[i] 为 0 或 1

目标：在大规模输入下做到线性时间。

官方示例

输入：nums = [0,1,0], k = 1
输出：2
解释：依次翻转 nums[0] 与 nums[2]。
输入：nums = [1,1,0], k = 2
输出：-1
解释：任意长度为 2 的翻转组合都无法得到 [1,1,1]。
输入：nums = [0,0,0,1,0,1,1,0], k = 3
输出：3
解释：翻转区间 [0,2] → [1,1,1,1,0,1,1,0]
      翻转区间 [4,6] → [1,1,1,1,1,0,0,0]
      翻转区间 [5,7] → [1,1,1,1,1,1,1,1]

题解：贪心 + 差分记录翻转

核心洞察：从左向右走到位置 i 时，任何从更右侧开始的操作都不再能改变它。因此若它在已有翻转影响下仍为 0，就必须立刻从 i 开启一次长度为 k 的翻转。

完整过程

  1. 维护奇偶性
    用 flipped 表示当前位置被此前窗口覆盖的次数是奇数还是偶数。
  2. 决定是否翻
    当前实际位为 nums[i] XOR flipped；若为 0，则必须从 i 开启翻转。
  3. 及时移出窗口
    用数组记录每次翻转的起点；走到 i 时移除 i-k 处翻转的影响。

为什么正确

必要性：扫描到 i 时，所有可影响 i 且起点小于 i 的选择都已确定。若当前实际位是 0，唯一仍能修正它的操作只能从 i 开始，所以该翻转不可省略；若为 1，此时翻转反而会把它变为 0。

最优性：算法每一步只执行上述不可省略的翻转，不做多余操作。由左到右归纳，每个已越过的位置都已固定为 1，且所用操作数最少；完成扫描后得到全局最优解。若剩余长度不足 k 却必须翻转，则任何方案都不可能成功。

边界情况

  • k = 1：每个 0 都独立翻转。
  • k = nums.length：只能翻整个数组，最多尝试一次。
  • 数组已经全为 1：返回 0。
  • 在 i + k > n 时仍遇到实际 0：立即返回 -1。

复杂度

每个位置仅进入和离开影响区间一次：时间 O(n)，记录翻转起点的辅助空间 O(n)。也可用固定长度队列将空间写成 O(k)。

替代方案

直接对每个选中窗口逐位取反需要 O(nk)，在 n = 10⁵ 时不可取。差分数组的本质是把一次区间翻转压缩成“起点标记 + 到期撤销”。还可原地把已作为翻转起点的位置改为特殊值，以做到 O(1) 额外空间，但会修改输入且可读性较差。

面试追问

  • 为什么局部选择不会妨碍后续？因为离开 i 后再也没有操作能修改 i。
  • 如何改成流式输入？保留长度 k 的翻转起点队列和当前奇偶性即可。
  • 若每个区间翻转成本不同呢？“遇 0 必翻”的起点仍被固定，但模型若允许不同长度，便需动态规划或其他结构。

常见错误

  • 先读取当前实际位，却忘记先移除恰好在 i 到期的翻转影响。
  • 把翻转次数本身与奇偶状态混用；实际位只取决于奇偶性。
  • 发现尾部空间不足时继续扫描，而不是直接返回 -1。
  • 真实修改整个窗口，造成 O(nk) 超时。

四种语言完整实现

class Solution {
    public int minKBitFlips(int[] nums, int k) {
        int n = nums.length, parity = 0, answer = 0;
        int[] starts = new int[n];
        for (int i = 0; i < n; i++) {
            if (i >= k) parity ^= starts[i - k];
            if ((nums[i] ^ parity) == 0) {
                if (i + k > n) return -1;
                starts[i] = 1;
                parity ^= 1;
                answer++;
            }
        }
        return answer;
    }
}

        starts = [0] * len(nums)
        parity = 0
        answer = 0

            if i >= k:

            if bit ^ parity == 0:
                if i + k > len(nums):

                starts[i] = 1
                parity ^= 1
                answer += 1
        return answer
