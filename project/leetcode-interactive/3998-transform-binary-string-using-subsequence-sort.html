使用子序列排序转换二进制字符串

给定二进制源串 s 与若干含 ? 的目标模式。一次操作可挑任意子序列并按 0, 1 排序。逐个判断：能否填充问号，让该模式从 s 可达？

操作的真实含义

选中的 0 只会向左移动，选中的 1 只会向右移动；字符数量永远不变。

推荐解法

把 ? 尽量放成靠左的 0、靠右的 1，再比较每个第 k 个 1 的位置。

题意、示例与约束

选择下标不必连续；排序后仍写回原下标。问号可独立替换。目标必须与源串拥有相同数量的 0/1，且每个 1 不能被迫向左走。

示例

s = "101"

strs = ["1?1", "0?1", "0?0"]

答案 [true, true, false]。第二项填成 "011"，整体排序即可。

约束

1 ≤ |s| ≤ 2000，1 ≤ strs.length ≤ 2000，每个模式长度均为 |s|，字符仅为 0/1/?。

可视化实验室：第 k 个 1 只能右移

填充策略：设源串有 ones(s) 个 1；若模式已有 fixedOnes 个 1，就将最右边的 ones(s) − fixedOnes 个问号填成 1，其余填 0。这样所有 1 的位置最靠右，最容易满足可达性。

源串填充后的目标第 k 个 1 向左，失败

s = "101"; pattern = "0?1"

用例 2

题解（默认收起）

需要时展开，避免首屏直接泄露思路。

核心洞察：排序任何子序列只会消除 1 在 0 左边的逆序。因此，按出现顺序编号后，目标的第 k 个 1 必须不早于源串的第 k 个 1；该条件与计数一致时也充分。

完整过程

  1. 记录 s 中 1 的总数 need。
  2. 模式中固定 1 多于 need，立即失败；固定 0 多于源串 0，也会在问号数量不匹配时失败。
  3. 从右向左，将恰好 need - fixedOnes 个问号改成 1，其余改成 0。
  4. 同步扫描源串与填充目标：第 k 个目标 1 的下标若小于第 k 个源 1，下移不了，失败；否则成功。

边界

没有问号、全 0、全 1、固定字符数量超额、长度非法。每个模式独立处理。

复杂度

每个模式两到三次线性扫描：O(n) 时间、O(n) 用于构造填充串（可原地优化）。总计 O(n · |strs|)。

替代方案、追问与常见错误

替代：可用前缀 1 计数比较；等价但实现更绕。追问：若改成连续子串排序，条件不再充分，需要分析局部可达性。错误：把问号随便填；把 1 填到左侧会制造不可修复的左移；只核对总数而不核对位置。
