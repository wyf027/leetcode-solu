01 / PROBLEM

题意与输入契约

输入整数数组 nums，元素互不相同，原顺序可能无序。对某个目标值执行以下搜索：在当前区间任意挑选一个下标作为枢轴；相等则返回成功，目标较小则只保留枢轴左侧，目标较大则只保留枢轴右侧。枢轴本身被排除；区间为空则失败。

返回数组中满足以下要求的值的个数：对所有可能的枢轴选择序列，搜索都成功。不允许预先排序，也不是只尝试固定中点。

binarySearchableNumbers(nums: integer[]) → integer
  • 1 ≤ nums.length ≤ 10⁵
  • −10⁵ ≤ nums[i] ≤ 10⁵
  • nums 中所有元素互不相同。

04 / SOLUTION

先观察，再揭开判定条件

推导、证明与四种语言实现，都在这里。

题解 · 把所有搜索路径压缩为两个极值

核心洞察

设目标位于下标 i。左边若有更大的数，选它会错误地向左搜索并扔掉目标；右边若有更小的数，选它会错误地向右搜索并扔掉目标。只要任一反例存在，就不能保证成功。

max(nums[0..i−1]) < nums[i] < min(nums[i+1..n−1])

左右区间均不包含当前元素。空左区间视为 −∞，空右区间视为 +∞。

完整过程

  1. 从右向左构造 rightMin。令 rightMin[n] = +∞，并计算 rightMin[i] = min(nums[i], rightMin[i+1])。
  2. 从左向右扫描，维护严格位于当前下标之前的最大值 leftMax，初始为 −∞。
  3. 若 leftMax < nums[i] && nums[i] < rightMin[i+1]，答案加一。
  4. 完成判定后，更新 leftMax = max(leftMax, nums[i])，最后返回答案。
nums                 [-1, 5, 2]
rightMin（含自身）    [-1, 2, 2, +∞]

 i   nums[i]   左侧最大   右侧最小   是否计数
 0      -1       −∞         2         是
 1       5       -1         2         否
 2       2        5        +∞         否

答案 = 1

正确性证明

必要性：如果左侧存在值大于目标的枢轴，把它选为第一次枢轴，搜索保留它左侧，目标立即被移除。右侧存在更小值时对称。因此所有左值小于目标、所有右值大于目标是必要条件。

充分性：假设条件成立且当前区间包含目标。选中目标则成功；选目标左侧枢轴，其值必然更小，保留右侧后目标仍在；选目标右侧枢轴同理。每轮区间严格缩小，目标始终保留，因此最终一定命中。两侧极值恰好表达上述条件，所以算法精确计数。

循环不变式：判定下标 i 时，leftMax 已包含且只包含所有左侧元素的最大值；rightMin[i+1] 是完整右侧最小值。判定后再更新 leftMax，保证不把自身纳入比较。

复杂度

时间 O(n)：两个线性扫描。额外空间 O(n)：长度 n+1 的后缀数组。输入不会被修改。

边界情况

单元素答案为 1。严格升序全部计入；严格降序且 n>1 时答案为 0。首尾仍须检查非空的那一侧。负数不影响比较；Java/C++ 整数极值哨兵超出题目值域，使用安全。

替代方案

  • 直接检查两侧：逐个目标扫描其他元素，时间 O(n²)、空间 O(1)，更适合解释定义。
  • 标记数组：左扫排除不是前缀新最大值的位置，右扫排除不是后缀新最小值的位置，O(n) 时间与空间。
  • 单调候选栈：维护全局前缀最大值。新元素到来时弹出所有比它大的候选；只有当前值大于此前全局最大值时才入栈。每个候选至多入栈、出栈一次，总计 O(n) 时间，O(n) 空间。即使栈顶被弹出，也不能忘记历史最大值。

常见错误

  • 只跑固定中点二分：它只覆盖一种路径，无法证明任意枢轴都成功。
  • 把“存在成功路径”当作“所有路径成功”：每个目标本身都能作为第一次枢轴。
  • 先排序再统计，或者只检查排序后下标是否不变：会丢失原来的左右阻碍关系，例如 [3,2,1] 中 2 排名没变却不合格。
  • 用 rightMin[i] 做严格右侧比较，或先更新 leftMax：把当前值和自身比较会错误排除它。
  • 拿一次可视化成功当成整体保证：找到失败路径能反证，成功路径不能穷尽所有选择。

面试追问

为什么题名有二分却不用实际二分？任意枢轴带来大量路径；分析“何时目标被删掉”能把路径量化转成局部判定，避免枚举。

如果元素重复呢？先明确统计不同值还是出现次数，且“找到某个相同值”是否算成功。不能简单把严格不等号改成非严格：例如 [2,3,1,2]，目标 2 可先选 3，再命中左侧 2；或先选 1，再命中右侧 2；直接选 2 也成功，但没有任何一个 2 同时满足两侧非严格极值条件。重复值下应研究目标的所有出现位置是否会一起被移除，重新建立证明。

数组持续追加能在线维护吗？可以沿用候选栈：追加值会淘汰左侧比它大的旧候选，同时前缀最大值决定新值能否成为候选。

JAVA

class Solution {
    public int binarySearchableNumbers(int[] nums) {
        int n = nums.length;
        int[] rightMin = new int[n + 1];
        rightMin[n] = Integer.MAX_VALUE;
        for (int i = n - 1; i >= 0; --i) {
            rightMin[i] = Math.min(nums[i], rightMin[i + 1]);
        }
        int leftMax = Integer.MIN_VALUE;
        int answer = 0;
        for (int i = 0; i < n; ++i) {
            if (leftMax < nums[i] && nums[i] < rightMin[i + 1]) {
                ++answer;
            }
            leftMax = Math.max(leftMax, nums[i]);
        }
        return answer;
    }
}

PYTHON

from typing import List

class Solution:
    def binarySearchableNumbers(self, nums: List[int]) -> int:
        n = len(nums)
        right_min = [float("inf")] * (n + 1)
        for i in range(n - 1, -1, -1):
            right_min[i] = min(nums[i], right_min[i + 1])

        left_max = float("-inf")
        answer = 0
        for i, value in enumerate(nums):
            if left_max < value < right_min[i + 1]:
                answer += 1
            left_max = max(left_max, value)
        return answer
