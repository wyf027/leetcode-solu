Problem brief

题意

给定整数数组 arr 与整数 k，找出数组中最小的 k 个数并返回。答案内部不要求排序，只要元素及其出现次数正确即可。

Official example

输入
arr = [1,3,5,7,2,4,6,8], k = 4
输出
[1,2,3,4]

Array length

0 ≤ n ≤ 100000

空数组是合法输入。

Selection size

0 ≤ k ≤ min(100000, n)

必须单独处理 k = 0。

Spoiler gate

题解

核心洞察、完整过程、边界、复杂度、替代方案与四语言代码默认隐藏。

Core insight

只确定一道分界线

快速选择沿用快速排序的分区动作：枢轴落位后，左侧都小于枢轴、右侧都不小于枢轴。若枢轴位置恰为 k - 1，前 k 个槽位已经装着答案，无需再排序两侧。

Recommended

迭代式快速选择

主线使用区间中点作为枢轴并执行 Lomuto 分区，代码短、原地修改、容易在面试白板上保证边界正确。平均只处理一侧，期望线性。

Full process

完整过程

  1. 01 将目标位置设为 target = k - 1。
  2. 02 在当前区间选择枢轴，临时移到右端。
  3. 03 把严格小于枢轴的数换到 store 左侧。
  4. 04 枢轴与 store 交换，获得其最终分区位置。
  5. 05 只保留包含 target 的一侧，继续迭代。
  6. 06 命中 target 后返回前 k 个元素。

Boundaries

边界

  • k = 0 直接返回空数组。
  • k = n 可直接返回全部元素。
  • 重复值使用严格小于比较，仍会逐步命中目标。
  • 返回的前 k 个元素不保证有序。

Complexity

复杂度

  • 平均时间：O(n)
  • 最坏时间：O(n²)
  • 额外空间：O(1)，不计结果数组

Alternatives

替代方案

  • 最大堆：O(n log k)，O(k)；适合数据流与不改原数组。
  • 完整排序：O(n log n)；最易写，但做了多余工作。

Interview follow-ups

面试追问

  • 怎样用随机枢轴降低构造最坏输入的风险？
  • 输入持续到达且内存只能保留 k 个数时如何改造？
  • 如果不能修改原数组，空间与接口该如何调整？
  • 为什么结果无需有序仍然可以判定正确？

Common mistakes

常见错误

  • 把目标写成 k，产生一位偏移。
  • 未处理 k = 0，继续访问下标 -1。
  • 分区后同时递归两侧，退化成快速排序。
  • 用集合比较答案，错误地丢失重复元素次数。
