Problem

题意与数据结构

容量上限 1000 kg

表 Queue 记录所有候车乘客。乘客必须按 turn 从小到大依次上车，每一轮只能上一人。当加入下一位乘客会让总重量超过 1000 千克时，上车过程停止。请返回最后一位成功上车乘客的 person_name。

关键语义：不能跳过超重乘客再尝试后面的人。题目保证 turn=1 的乘客不会超重，因此答案一定存在。

约束

  • person_id 唯一；若有 n 行，person_id 与 turn 都恰好包含 1 到 n。
  • turn=1 最先上车，turn=n 最后尝试。
  • weight 以千克计；巴士总重量不能超过 1000。
  • 每个 turn 只处理一位乘客，且第一位乘客的重量不超过上限。

题解：把上车过程变成前缀和

核心洞察

按照 turn 排序后，某位乘客能否上车，只取决于从第 1 位到他为止的体重总和。这个总和就是有序前缀和。我们只需找到“前缀和不超过 1000”的最大 turn。

prefix(turn) = SUM(weight) OVER (ORDER BY turn)

完整过程

  1. 用窗口函数按 turn 升序计算每一行的累计重量 total_weight。
  2. 保留 total_weight <= 1000 的行。
  3. 在这些行中按 turn 降序取第一行，即最后成功上车的人。

示例的前缀和为 250 → 600 → 1000 → 1200 → 1375 → 1875。前三项合法，第四项第一次越界，所以答案是 turn=3 的 John Cena。

正确性证明

引理：对任意乘客 p，他能上车当且仅当截至 p 的前缀重量不超过 1000。因为所有更早 turn 的乘客必须先上车，车上总重量恰为该前缀和。

结论：查询过滤出全部且仅有能成功上车的乘客，再选择其中最大的 turn。因此返回的人既能上车，也不存在更晚还能上车的人，正是题目所求。

边界与复杂度

  • 第一位恰好 1000：直接返回第一位。
  • 所有人都能上车：返回最大 turn 的乘客。
  • 某次累计恰好 1000：必须保留，条件是 <= 而不是 <。
  • 输入表物理顺序无关：窗口必须显式 ORDER BY turn。

设 n 为乘客数。数据库通常需要按 turn 排序，时间复杂度 O(n log n)，窗口扫描 O(n)，中间结果空间 O(n)。若 turn 上有合适索引，数据库可进一步优化访问。

Java 17本地语义参考
import java.util.*;

public class Main {
    record Person(int id, String name, int weight, int turn) {}

    static String lastPassenger(List<Person> queue, int limit) {
        List<Person> ordered = new ArrayList<>(queue);
        ordered.sort(Comparator.comparingInt(Person::turn));
        int total = 0;
        String last = null;
        for (Person person : ordered) {
            if (total + person.weight() > limit) break;
            total += person.weight();
            last = person.name();
        }
        return last;
    }

    public static void main(String[] args) {
        List<Person> queue = List.of(
            new Person(5, "Alice", 250, 1),
            new Person(4, "Bob", 175, 5),
            new Person(3, "Alex", 350, 2),
            new Person(6, "John Cena", 400, 3),
            new Person(1, "Winston", 500, 6),
            new Person(2, "Marie", 200, 4)
        );
        System.out.println(lastPassenger(queue, 1000));
    }
}

function lastPassenger(queue, limit = 1000) {
  const ordered = [...queue].sort((a, b) => a.turn - b.turn);
  let total = 0;
  let last = null;
  for (const person of ordered) {
    if (total + person.weight > limit) break;
    total += person.weight;
    last = person.person_name;
  }
  return last;
}

替代方案

  • 相关子查询：对每位乘客求 turn <= 当前 turn 的重量和。更直观，但无索引时可能退化到 O(n²)。
  • 用户变量：旧版 MySQL 可用变量滚动累加，但求值顺序和可移植性较差，不是首选。
  • Pandas：先按 turn 排序，再用 cumsum() 计算累计重量并取合法行尾部。

面试追问与常见错误

追问：若允许跳过超重者，问题会改变为按序扫描、遇到超重则跳过；此时“前缀和不超过上限”不再等价。若同一 turn 允许多人同时上车，需明确并列行的窗口 frame。

  • 按表的物理行顺序累计，而不是按 turn。
  • 写成 total_weight < 1000，漏掉恰好坐满的情况。
  • 只找单人体重小于 1000 的最后一人，忽略之前乘客已经占用容量。
  • 超重后仍继续挑选后面的轻乘客，违背严格排队语义。
  • 窗口结果未带 turn，导致无法稳定选出最后一行。
