最后一块石头的重量 II

Last Stone Weight II

把每一次“粉碎”看作重量的正负抵消。先亲手观察可达重量如何扩张，再决定是否揭开题解。

题目

给定整数数组 stones，其中每个元素是一块石头的重量。每回合任选重量为 x ≤ y 的两块石头：若相等则两者消失，否则留下重量 y - x。最终至多剩一块石头，请返回它能够达到的最小重量；若全部消失则返回 0。

示例 1

输入：stones = [2,7,4,1,8,1]
输出：1
解释：可依次把 (2,4)、(7,8)、(2,1)、(1,1) 粉碎，最终剩 1。

示例 2

输入：stones = [31,26,33,21,40]
输出：5
约束：1 ≤ stones.length ≤ 30；1 ≤ stones[i] ≤ 100。函数形式：lastStoneWeightII(stones: integer[]) → integer。

完整题解

包含证明、复杂度、四语言实现与面试延伸。

核心洞察

一系列粉碎最终等价于给每块石头分配正号或负号，使最后重量为 |Σ(+组) - Σ(-组)|。设总重量为 S，若一组的重量为 P ≤ S/2，答案就是 S - 2P。所以目标变成：从每块石头最多选一次，在容量 ⌊S/2⌋ 内取得尽可能大的子集和——标准 0-1 背包。

完整过程

  1. 计算总和 S 与容量 target = ⌊S/2⌋。
  2. 令 dp[j] 表示容量不超过 j 时能装入的最大重量，初始全为 0。
  3. 遍历每块重量 w，容量必须从 target 倒序到 w，更新 dp[j] = max(dp[j], dp[j-w] + w)。
  4. 返回 S - 2 × dp[target]。

正确性证明

引理 1：任意粉碎序列的最终重量可写成所有石头重量分别取正负号后的绝对和；反过来，一个正负分组对应两组重量的差，因此寻找最小最终重量等价于寻找最接近的二分。

引理 2：处理前 i 块石头后，dp[j] 是容量 j 内可取得的最大子集和。归纳地，第 i 块要么不选，保留旧值；要么选，得到旧状态 dp[j-w]+w。倒序保证旧状态不含当前石头。

结论：dp[target] 是不超过半数的最大分组重量，故 S-2×dp[target] 是所有分组差中的最小值，即答案。

边界与复杂度

  • 单块石头：容量内可能无法选中它，答案就是自身。
  • 总和为偶数且能恰好取半：答案为 0。
  • 重复重量仍是不同物品，各自只能使用一次。
  • 时间 O(nS)，空间 O(S)；这里容量实际为 S/2。

替代方案

也可维护一个布尔集合，记录所有可达子集和；或用位集合做 bits |= bits << w，更紧凑但不同语言的实现可读性各异。直接模拟粉碎顺序会陷入贪心误区，不能保证全局最优。

四语言完整代码

class Solution {
    public int lastStoneWeightII(int[] stones) {
        int sum = 0;
        for (int stone : stones) sum += stone;
        int target = sum / 2;
        int[] dp = new int[target + 1];
        for (int stone : stones) {
            for (int j = target; j >= stone; j--) {
                dp[j] = Math.max(dp[j], dp[j - stone] + stone);
            }
        }
        return sum - 2 * dp[target];
    }
}

};
from typing import List

class Solution:
    def lastStoneWeightII(self, stones: List[int]) -> int:
        total = sum(stones)
        target = total // 2
        dp = [0] * (target + 1)
        for stone in stones:
            for capacity in range(target, stone - 1, -1):
                dp[capacity] = max(
                    dp[capacity],
                    dp[capacity - stone] + stone
                )
        return total - 2 * dp[target]

面试追问

  • 为什么容量要倒序？正序会把同一块石头重复使用，退化为完全背包。
  • 能否只记录可达性？可以，最后从 target 向下找首个可达和。
  • 如果重量总和很大怎么办？考虑位集合、稀疏集合或 meet-in-the-middle。

常见错误

  • 把题目当成“每次砸最重两块”的贪心。
  • 返回 target-dp[target]，遗漏另一半差值；正确式是 S-2P。
  • 容量正序更新导致一块石头被选多次。
  • 用浮点半数或忘记对总和取整。
