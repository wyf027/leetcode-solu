A quiet moment in the event loop

Problem

题目要求

编写异步函数 sleep(millis)：接收正整数 millis，返回一个在约 millis 毫秒后完成的 Promise；Promise 可以解析为任意值。

准确转述

调用函数后，调用方应立即得到 Promise，而不是同步阻塞执行线程。经过指定时长后，该 Promise 进入完成状态，调用方即可继续执行后续异步逻辑。

允许误差：实际经过时间可以比 millis 略长；运行时调度并不保证回调恰好在目标毫秒到达时执行。

Solution

准备好看题解了吗？

先在脑中回答：怎样把计时器的回调，转化为调用方可以等待的异步完成信号？

Answer unlocked

题解：用 Promise 包装计时器

计时器负责“何时通知”，Promise 负责“如何被异步等待”。把 resolve 交给计时器即可连接两者。

核心洞察

setTimeout 会在至少经过指定延迟后安排回调。以 Promise 的 resolve 作为回调，回调执行时 Promise 就完成。

完整过程

  1. 创建并立即返回一个 Promise。
  2. 注册延迟为 millis 的计时器。
  3. 计时结束后运行 resolve。
  4. 等待该 Promise 的调用方继续执行。

边界与复杂度

  • 下边界：millis = 1 仍通过计时器异步完成。
  • 上边界：millis = 1000 不需要特殊处理。
  • 时间：函数自身工作量 O(1)，墙钟等待 O(millis)。
  • 空间：O(1)，由运行时保存一个计时任务与回调。

常见错误

  • 忘记返回 Promise，调用方无法 await。
  • 写忙等待循环，阻塞事件循环且浪费 CPU。
  • 立即调用 resolve()，再把结果传给计时器。
  • 断言实际耗时必须等于 millis，忽略调度延迟。

正确性说明

安全性：Promise 只在计时器回调执行时被解析；计时器回调不会早于所请求的延迟阈值进入可执行阶段，因此函数不会同步完成。

终止性：在事件循环继续运行且宿主正常调度计时器的前提下，延迟到期后回调最终被执行并调用 resolve，所以 Promise 最终完成。事件循环忙碌只会让完成时间略晚，不影响结论。

四种语言实现

本题官方提交语言为 JavaScript / TypeScript。Java、Python、C++ 代码仅用于本地语义对照，不能冒充本题的 LeetCode 官方提交。

JavaScript官方可提交 
/**
 * @param {number} millis
 * @return {Promise<void>}
 */
async function sleep(millis) {
  return new Promise(resolve => setTimeout(resolve, millis));
}
Java本地语义参考 
import java.util.concurrent.CompletableFuture;

class Solution {
    public CompletableFuture<Void> sleep(int millis) {
        return CompletableFuture.runAsync(() -> {
            try {
                Thread.sleep(millis);
            } catch (InterruptedException error) {
                Thread.currentThread().interrupt();
                throw new RuntimeException(error);
            }
        });
    }
}
Python本地语义参考 
import asyncio

async def sleep(millis: int) -> None:
    await asyncio.sleep(millis / 1000)
C++本地语义参考 
#include <chrono>
#include <future>
#include <thread>

std::future<void> sleepMillis(int millis) {
    return std::async(std::launch::async, [millis] {
        std::this_thread::sleep_for(std::chrono::milliseconds(millis));
    });
}

替代方案

可以在 async 函数中写 await new Promise(...)，语义相同但多一层语句。忙等待、阻塞主线程或轮询时间都不适合浏览器与 Node.js 的异步主流程。
