    Self join

    同表双别名，把组织关系变成一行

    e.managerId = m.id 先找直属经理，e.salary > m.salary 再筛工资倒挂。

    核心洞察与完整过程

    1. 把 Employee 取别名 e，代表正在被审计的员工。
    2. 再取别名 m，代表经理角色。
    3. 用 e.managerId = m.id 做内连接。没有经理或经理行不存在的员工不会进入结果。
    4. 保留 e.salary > m.salary 的行，并把 e.name 别名设为 Employee。 
    SELECT e.name AS Employee
FROM Employee AS e
JOIN Employee AS m
  ON e.managerId = m.id
WHERE e.salary > m.salary;

    边界

    • managerId IS NULL：内连接自然排除。
    • 员工与经理平薪：条件是严格大于，不返回。
    • 同一经理可管理多人：每名员工独立比较。
    • 结果允许任意顺序，无需额外排序。

    复杂度

    • 逻辑上扫描员工行一次，并按经理主键查找匹配。
    • 若优化器利用 id 主键索引，常见执行成本接近 O(n)。
    • 实际计划由数据库统计信息和连接算法决定，不把 SQL 物理成本写死。

    Pandas 官方函数签名
    import pandas as pd

def find_employees(employee: pd.DataFrame) -> pd.DataFrame:
    pairs = employee.merge(
        employee,
        left_on="managerId",
        right_on="id",
        suffixes=("_employee", "_manager"),
    )
    return pairs.loc[
        pairs["salary_employee"] > pairs["salary_manager"],
        ["name_employee"],
    ].rename(columns={"name_employee": "Employee"})

    替代方案与取舍

    • 相关子查询同样可做，但表达更绕，优化器仍可能改写为连接。
    • WHERE EXISTS 适合只判断关系存在，本题还需比较经理工资，自连接更直接。
    • 左连接没有收益，因为无经理的员工本来就不应返回。

    面试追问

    • 如果要同时返回员工工资、经理姓名与差额，如何扩展投影列？
    • 怎样找工资高于所有上级而不只是直属经理的员工？
    • 如果经理记录可能缺失，如何输出异常组织关系？

    常见错误

    • 把条件写成 e.id = m.managerId，连接方向反了。
    • 使用 >=，错误包含平薪员工。
    • 只查一张表却直接比较经理工资，没有第二个表别名。
    • 输出 name 而未设置列别名 Employee。
    • 额外排序，虽然不一定错，但题目没有要求，增加无意义工作。
