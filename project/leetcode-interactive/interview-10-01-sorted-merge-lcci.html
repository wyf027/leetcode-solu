Dispatch order

题意：把 B 原地并入 A，保持整体有序

给定两个已排序数组 A 与 B。A 的末尾预留了足够空间， 请把 B 合并进 A，并让 A 仍然有序。

m 和 n 分别表示 A、B 中有效元素的数量；官方说明 A.length == m + n。

Core insight

核心洞察：空位在右侧，所以从右往左写

A 的有效段和 B 都已排序。每次只需比较两个未处理尾部，较大者必然是当前整体最大值，应写入最右空位。 写指针始终位于未处理元素之后，因此不会覆盖仍需比较的 A 元素。

Correctness

循环不变量

每轮开始时，A[write+1…m+n-1] 已放好最终结果中最大的若干元素，且顺序正确； A[0…i] 与 B[0…j] 尚未处理。取两端较大值写入 A[write] 后，不变量继续成立。 当 j<0 时，B 已全部写入；A 剩余前缀本就在正确位置，因此算法完成。

Full process

完整过程

  1. 1. 令 i=m-1、j=n-1、write=m+n-1。
  2. 2. j≥0 时比较 A[i] 与 B[j]。
  3. 3. 较大值写入 A[write]，对应指针左移。
  4. 4. write 左移，继续直到 B 全部并入。

Complexity & boundaries

复杂度与边界

时间复杂度
O(m+n)，每个元素最多处理一次。
额外空间
O(1)，直接复用 A 的缓冲区。
边界
m=0、n=0、重复值、负数都无需特殊分支。

Alternatives

替代方案

  • 正向归并：需要额外数组保存 A 的有效段，时间 O(m+n)、空间 O(m)。
  • 拼接后排序：实现短，但时间 O((m+n)log(m+n))，浪费已有有序性。

Interview follow-ups

面试追问

  • 为什么只需 while (j≥0)？ A 的剩余前缀已在原位。
  • 相等时取谁？ 取 B 可简化逻辑；稳定性不是本题要求。
  • A 没有缓冲区呢？ 使用额外数组或支持扩容的容器。

Common mistakes

常见错误

  • • 从左向右原地写，覆盖 A 尚未比较的元素。
  • • i<0 后仍读取 A[i]，导致越界。
  • • 忘记复制 B 的剩余元素。
  • • 把 A 尾部占位 0 当成有效输入。
class Solution {
    public void merge(int[] A, int m, int[] B, int n) {
        int i = m - 1;
        int j = n - 1;
        int write = m + n - 1;

        while (j >= 0) {
            if (i >= 0 && A[i] > B[j]) {
                A[write--] = A[i--];
            } else {
                A[write--] = B[j--];
            }
        }
    }
}

        j = n - 1
        write = m + n - 1

            if i >= 0 and A[i] > B[j]:
                A[write] = A[i]
                i -= 1
            else:
                A[write] = B[j]
                j -= 1
            write -= 1
