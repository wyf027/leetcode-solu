题解

核心洞察

排序把“最近”变成单向追赶

两数组分别升序后，若 a[i] < b[j]，继续增大 b[j] 只会让差更大；唯一可能缩小差值的动作是让 i 右移。反之移动 j。因此每个指针最多走完整条轨道一次。

完整过程

  1. 分别排序 a 与 b。
  2. 令 i = 0、j = 0，最佳差为正无穷。
  3. 用 64 位数计算 |a[i] - b[j]| 并更新答案。
  4. 相等时立即返回 0；否则右移数值较小的一侧。
  5. 任一指针越界时结束，返回最佳差。

边界

  • 数组非空，但可能只含一个元素。
  • 负数、重复值和两个数组中的相同值都要处理。
  • 32 位极值相减会溢出，必须先提升到 64 位。
  • 题目保证最终答案不超过 2³¹ − 1。

复杂度

排序耗时 O(n log n + m log m)，双指针扫描为 O(n + m)。除排序实现所需栈空间外，扫描额外空间为 O(1)。

替代方案

  • 对较短数组的每个值在另一排序数组二分：O((n + m) log max(n,m))，常数更大。
  • 合并两数组并保留来源，再检查异源相邻项：同样正确，但需额外存储来源。
  • 暴力枚举所有数值对为 O(nm)，无法承受 100000 的长度。

面试追问

  • 如果不能修改输入数组，如何调整空间复杂度？
  • 如何返回最佳数值对，而不只返回差值？
  • 如果两个数组本身已排序，复杂度会变成什么？
  • 若输入来自数据流，如何维护近似或动态答案？

常见错误

先用 32 位 int 相减，再转 64 位；溢出已经发生。

移动较大的指针，使两数距离只会更远。

发现差为 0 后仍继续扫描，错失最强剪枝。

忽略排序会修改原数组这一副作用。 

import java.util.Arrays;

class Solution {
    public int smallestDifference(int[] a, int[] b) {
        Arrays.sort(a);
        Arrays.sort(b);
        int i = 0, j = 0;
        long best = Long.MAX_VALUE;

        while (i < a.length && j < b.length) {
            long left = a[i];
            long right = b[j];
            best = Math.min(best, Math.abs(left - right));
            if (best == 0) return 0;
            if (left < right) i++;
            else j++;
        }
        return (int) best;
    }
}
