从一串数字，复原坐标。

逗号、小数点与空格都消失了。你能在不制造多余零的前提下，找回每一种可能的二维坐标吗？

MEDIUM 非付费题 字符串 回溯 / 枚举
(1, 2.3) (12, 3) (1.2, 3)

Problem

题目转述

先理解数据发生了什么，不急着展开题解。

原本有一个二维坐标，例如 (1, 3) 或 (2, 0.5)。现在把其中的逗号、小数点和空格全部删除，只留下外层括号和数字字符串 s。

请返回所有可能的原始坐标字符串。答案顺序任意，但每个结果的逗号后必须恰好有一个空格。

原始数字采用最短、规范的十进制表示：不能含多余的前导零或末尾零，因此 00、0.0、1.0、001、00.01 等都不合法；小数点前也必须至少有一位数字，所以 .1 不合法。

约束

  • 4 <= s.length <= 12
  • s[0] == '('
  • s[s.length - 1] == ')'
  • 其余字符全部为数字。
  • 函数参数为 s: string，返回 list<string>。

示例 1

输入s = "(123)"
输出["(1, 2.3)", "(1, 23)", "(1.2, 3)", "(12, 3)"]

输入s = "(0123)"
输出["(0, 1.23)", "(0, 12.3)", "(0, 123)", "(0.1, 2.3)", "(0.1, 23)", "(0.12, 3)"]

输出["(0, 0.011)", "(0.001, 1)"]

枚举切分，再生成规范数字

把“逗号放哪里”和“每一半的小数点放哪里”拆成两个清晰问题。

核心洞察

去掉外层括号后，在数字串的每个内部位置尝试一次逗号。对左右两个子串分别生成所有规范数字形式，再做笛卡尔积。

对子串 part，整数不能有多位前导零；小数的整数部分同样不能有多位前导零，且小数部分不能以 0 结尾。小数点位置本身已经保证左右各至少一位。

快速判定表

  • 单个字符：只保留它本身。
  • 首尾都是 0：没有合法形式。
  • 首字符是 0：只能是 0.xxx。
  • 末字符是 0：只能是整数。
  • 其他情况：整数与每个小数点位置都可行。

完整过程

  1. 删除 s 的首尾括号，得到纯数字串 digits。
  2. 令切分点 i 从 1 到 digits.length - 1，左侧为 digits[0:i]，右侧为 digits[i:n]。
  3. 辅助函数 forms(part) 枚举整数形式及所有内部小数点位置，只保留没有多余零的表示。
  4. 遍历每个左候选 x 与右候选 y，加入 "(" + x + ", " + y + ")"。
  5. 遍历完全部切分点后返回结果；题目允许任意顺序，因此无需排序。

正确性证明

引理 1（合法性）：forms(part) 输出的整数没有多位前导零；输出的小数其整数部分没有多位前导零、小数部分不以零结尾，并且点两侧都有数字。因此每个输出都是规范数字。
引理 2（完备性）：任何由 part 还原出的规范数字，要么不含小数点，要么小数点位于某个内部位置。辅助函数逐一检查整数情况及所有内部位置，只拒绝违反规范的候选，所以不会漏掉合法形式。
定理：任何合法原坐标都有唯一的逗号切分点。外层循环一定访问该点；由引理 2，左右数字都在各自候选集合中，笛卡尔积会生成该坐标。反过来，由引理 1，算法拼接出的左右数字都规范，格式也固定为逗号后一个空格。因此算法输出恰好是全部合法坐标。

复杂度与边界

时间O(n⁴)坐标数量最多为 O(n³)，构造每个长度 O(n) 的字符串。
额外空间O(n)不计返回结果；输出本身最多占 O(n⁴) 个字符。
  • 最短输入含两位数字，唯一逗号位置仍会被访问。
  • 单字符 0 合法，但多位整数不能以 0 开头。
  • 小数部分末尾为零意味着能用更短表示，必须拒绝；中间出现零不受影响。
  • 某一半没有合法形式时，该切分点自然产生零个坐标。

import java.util.ArrayList;
import java.util.List;

class Solution {
    public List<String> ambiguousCoordinates(String s) {
        String digits = s.substring(1, s.length() - 1);
        List<String> answer = new ArrayList<>();

        for (int split = 1; split < digits.length(); split++) {
            List<String> leftForms = forms(digits.substring(0, split));
            List<String> rightForms = forms(digits.substring(split));

            for (String x : leftForms) {
                for (String y : rightForms) {
                    answer.add("(" + x + ", " + y + ")");
                }
            }
        }
        return answer;
    }

    private List<String> forms(String part) {
        List<String> result = new ArrayList<>();
        int n = part.length();

        if (n == 1) {
            result.add(part);
            return result;
        }

        if (part.charAt(0) == '0') {
            if (part.charAt(n - 1) != '0') {
                result.add("0." + part.substring(1));
            }
            return result;
        }

        result.add(part);
        if (part.charAt(n - 1) != '0') {
            for (int dot = 1; dot < n; dot++) {
                result.add(part.substring(0, dot) + "." + part.substring(dot));
            }
        }
        return result;
    }
}

function forms(part) {
    if (part.length === 1) {
        return [part];
    }

    if (part[0] === '0') {
        return part.at(-1) === '0' ? [] : [`0.${part.slice(1)}`];
    }

    const result = [part];
    if (part.at(-1) !== '0') {
        for (let dot = 1; dot < part.length; dot++) {
            result.push(`${part.slice(0, dot)}.${part.slice(dot)}`);
        }
    }
    return result;
}
from typing import List


class Solution:
    def ambiguousCoordinates(self, s: str) -> List[str]:
        digits = s[1:-1]
        answer: List[str] = []

        for split in range(1, len(digits)):
            left_forms = self._forms(digits[:split])
            right_forms = self._forms(digits[split:])

            for x in left_forms:
                for y in right_forms:
                    answer.append(f"({x}, {y})")

        return answer

    def _forms(self, part: str) -> List[str]:
        if len(part) == 1:
            return [part]

        if part[0] == "0":
            return [] if part[-1] == "0" else ["0." + part[1:]]

        result = [part]
        if part[-1] != "0":
            for dot in range(1, len(part)):
                result.append(part[:dot] + "." + part[dot:])
        return result

public:

            for (const string& x : leftForms) {
                for (const string& y : rightForms) {

                }
            }
        }
        return answer;

private:
    vector<string> forms(const string& part) {
        int n = static_cast<int>(part.size());
        if (n == 1) {
            return {part};

替代方案与取舍

统一暴力枚举：先枚举逗号，再枚举左右是否放小数点以及放置位置，最后用一个通用校验器过滤。它同样正确，规则集中在校验器里，但会生成更多明知不合法的临时候选。

当前方案：让 forms 直接按首尾零的结构生成合法形式。候选更少、意图更清楚，也更容易在面试中证明完备性。

是否需要回溯？不需要维护深层搜索状态；问题只有一个逗号位置和每半边至多一个小数点，直接枚举更自然。把它称为“回溯”也能实现，但抽象偏重。

面试追问

为什么不需要 Set 去重？

一个结果中的逗号位置由左右数字所含的原始位数唯一确定；同一半的小数点位置也唯一，因此不同枚举路径不会产生相同字符串。

若只求方案数呢？

每个切分点只需累加 leftForms.length × rightForms.length，无需构造坐标字符串。

能否流式返回？

可以把每个笛卡尔积结果逐个 yield，减少同时保留中间结果的需求；不过题目接口要求最终列表。

若允许科学计数法？

数字文法会显著扩大，应先定义规范化规则，再用专门的生成器替换 forms；外层逗号枚举仍可复用。

常见错误

  • 忘记先去掉外层括号，导致把括号参与切分。
  • 把 0 与 00 一并判为非法；前者其实合法。
  • 只检查整数部分的前导零，却漏掉小数部分末尾零，例如错误接受 1.0。
  • 允许小数点出现在子串两端，产生 .1 或 1.。
  • 得到左右候选后忘记做完整笛卡尔积，从而漏解。
  • 输出写成 (x,y)；题目要求逗号后恰好一个空格。
