Problem brief

题意与接口

非付费题

实现一个固定容量为 k 的循环队列。它遵循 FIFO（先进先出）：新元素从队尾加入，旧元素从队首移除；当队首向后移动后，数组前部腾出的空间应当能够再次用于入队。不得直接使用语言内置的队列结构。

类名为 MyCircularQueue，需要提供下列完整接口：

MyCircularQueue(k)

创建容量恰好为 k 的空队列。

boolean enQueue(int value)

队未满时将 value 加到队尾并返回 true；否则返回 false。

boolean deQueue()

队非空时删除队首并返回 true；否则返回 false。

int Front()

返回队首元素；空队返回 -1。

int Rear()

返回队尾元素；空队返回 -1。

boolean isEmpty()

队列没有元素时返回 true。

boolean isFull()

队列元素数达到容量时返回 true。

注意：值本身允许为 0，所以不能仅凭槽位数值判断该位置是否有效。

示例 1

输入

  • 0 <= value <= 1000
  • 对 enQueue、deQueue、Front、Rear、isEmpty、isFull 的调用总数最多为 3000。
  • 不能使用编程语言内置的队列数据结构。

先独立思考：如何仅凭固定数组区分“队空”和“队满”？

Solution unlocked

固定数组 + 队首下标 + 元素个数

核心洞察

不必真的移动元素。用长度为 k 的数组保存数据，记录队首下标 head 和当前元素数 count。所有越过数组末尾的下标都用取模回到开头。

完整过程

  1. 初始化长度为 k 的数组，令 head = 0、count = 0。
  2. 入队前检查 count === k。若未满，把新值写到逻辑队尾之后的位置，再令 count++。
  3. 出队前检查 count === 0。若非空，将 head 向后移动一格，再令 count--。
  4. 队首直接读取 data[head]；队尾通过逻辑偏移定位。
入队写入位置 = (head + count) % k 队尾位置 = (head + count - 1) % k 出队后 head = (head + 1) % k 空队 = count == 0 满队 = count == k

边界处理

  • 空队：Front、Rear 返回 -1；deQueue 返回 false。
  • 满队：enQueue 不修改任何状态并返回 false。
  • 容量 1：队首与队尾会指向同一槽位，计数仍能准确区分空与满。
  • 值为 0：有效性由 count 决定，不使用哨兵值。
  • 回绕：每次下标移动都取模，避免访问数组边界之外。

正确性证明

  1. 状态不变量：始终有 0 <= count <= k；当队列非空时，head 指向最早尚未出队的元素。初始化显然满足。
  2. 入队保持不变量：未满时，(head + count) % k 恰好是所有有效元素之后的第一个空槽。写入后计数加一，已有元素的相对顺序不变，新元素成为最后一个。
  3. 出队保持不变量：非空时删除的逻辑元素正是 head 所指的最早元素。将 head 前移一格后，若仍非空，它会指向新的最早元素；计数同步减一。
  4. 查询正确：由不变量，队首位于 head；从队首向后偏移 count - 1 即为队尾。空、满状态分别由计数为 0、k 唯一确定。因此所有接口均满足题意。

复杂度

操作时间额外空间原因
enQueue / deQueueO(1)O(1)只计算下标并更新常数个状态。
Front / RearO(1)O(1)直接按下标读取。

Java固定数组实现
class MyCircularQueue {
    private final int[] data;
    private final int capacity;
    private int head;
    private int count;

    public MyCircularQueue(int k) {
        data = new int[k];
        capacity = k;
        head = 0;
        count = 0;
    }

    public boolean enQueue(int value) {
        if (isFull()) {
            return false;
        }
        int insertIndex = (head + count) % capacity;
        data[insertIndex] = value;
        count++;
        return true;
    }

    public boolean deQueue() {
        if (isEmpty()) {
            return false;
        }
        head = (head + 1) % capacity;
        count--;
        return true;
    }

    public int Front() {
        return isEmpty() ? -1 : data[head];
    }

    public int Rear() {
        if (isEmpty()) {
            return -1;
        }
        int rearIndex = (head + count - 1) % capacity;
        return data[rearIndex];
    }

    public boolean isEmpty() {
        return count == 0;
    }

    public boolean isFull() {
        return count == capacity;
    }
}

替代方案

  • 额外预留一个数组槽位：让底层数组长度为 k + 1，用 front === rear 表示空、(rear + 1) % n === front 表示满。优点是不需要 count，代价是多用一个槽位且下标语义更绕。
  • 循环双向链表：可完成接口，但需要额外节点与指针，局部性较差，也没有体现固定容量数组的优势。
  • 移动数组元素：逻辑简单，但每次出队要 O(k) 搬移，不满足高效队列的目标。

常见错误

  • 用 head === tail 同时表示空和满，却没有增加计数或预留槽位。
  • 队尾写入位置误用 head + count - 1，覆盖当前最后一个元素。
  • 出队时移动所有元素，丢失 O(1) 优势。
  • 忘记对下标取模，回绕时越界。
  • 空队调用 Rear 时直接计算负数下标。
