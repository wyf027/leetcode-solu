2043. 简易银行系统

Simple Bank System

把每一笔操作，变成一张清晰的交易回执。

先读规则，再逐步观察账户变化；分析与四语言代码位于底部，默认收起。

01 / 业务规则

银行有 n 个账户，编号为 1 到 n。输入数组 balance 从下标 0 开始，balance[i] 表示账户 i + 1 的初始余额。实现 Bank 类，按调用顺序处理转账、存款和取款。

交易涉及的所有账户必须存在。取款或转账还要求转出账户余额不少于 money。有效操作修改余额并返回 true；无效操作返回 false，所有账户余额保持不变。

  • Bank(long[] balance)：使用初始余额创建对象。
  • boolean transfer(int account1, int account2, long money)：从 account1 向 account2 转账 money。
  • boolean deposit(int account, long money)：向 account 存入 money。
  • boolean withdraw(int account, long money)：从 account 取出 money。

约束

  • n == balance.length
  • 1 ≤ n, account, account1, account2 ≤ 10⁵。注意：参数上界并不保证账户存在，还须满足编号 ≤ n。
  • 0 ≤ balance[i], money ≤ 10¹²
  • transfer、deposit、withdraw 各自最多调用 10⁴ 次。

05 / 独立题解

想好如何维护状态后，再展开对照。

核心洞察：余额就是全部状态

账户编号连续，用数组即可直接定位。编号 account 对应下标 account - 1。每次操作先确认所有失败条件，再修改余额；失败路径不做写入，避免一半完成的转账。

完整过程

  1. 构造时复制初始余额，避免调用者对原数组的修改影响对象。
  2. 存款：检查账户编号，成功后增加余额。
  3. 取款：先检查编号，再检查余额 ≥ money，成功后扣款。
  4. 转账：先检查两个编号，再检查转出账户资金。全部满足后依次扣款、加款，返回 true。

官方示例余额依次为：

初始化             [10, 100, 20, 50, 30]
withdraw(3,10)     [10, 100, 10, 50, 30] → true
transfer(5,1,20)   [30, 100, 10, 50, 10] → true
deposit(5,20)      [30, 100, 10, 50, 30] → true
transfer(3,4,15)   [30, 100, 10, 50, 30] → false
withdraw(10,50)    [30, 100, 10, 50, 30] → false

正确性

对调用次数归纳：初始化复制输入，因此状态正确。假设一次操作前所有余额均正确。编号或余额检查失败时，不写入任何元素，与无效交易的定义一致。检查成功时，存款增加指定金额，取款减少指定金额，转账在对应账户各减、加同一金额，恰好实现题意；其余账户不变。因此这次操作后余额及返回值正确，归纳得到整个调用序列正确。

取款和转出前有余额检查，故不会产生负余额。转账中的扣款与加款金额相同，故总余额不变；存款使总额增加 money，取款使总额减少 money。

边界与数值范围

  • 同账户转账仍须先检查余额，即使最终余额不变；余额不足时返回 false。
  • money = 0 时，合法账户操作成功；不存在的账户仍失败。
  • 余额恰等于 money 时允许转出或取出。
  • 先验证编号，再访问数组；短路逻辑保障越界编号不会触发下标访问。
  • 账户可能积累初始总额与全部存款，保守总额上界为 10⁵ × 10¹² + 10⁴ × 10¹² = 1.1 × 10¹⁷，64 位有符号整数足够。Java 使用 long，C++ 使用 long long，Python int 可精确表示；JavaScript 内部使用 BigInt，不能依赖 Number 保存累计余额。
  • 题目保证金额非负、参数为整数，因此提交代码不额外接受负金额或非整数输入。

复杂度

四份代码均复制输入：构造时间 O(n)，对象存储 O(n)。单次转账、存款、取款时间 O(1)，额外工作空间 O(1)。执行 q 次操作共 O(n + q)。这里按题目有界整数的固定宽度算术计数。

替代方案

直接保存传入数组的引用可省掉复制，将构造降为 O(1)，但会与调用者共享可变状态。哈希表也能维护余额，适合稀疏账户编号；本题编号连续，数组更直接。无需树状数组、线段树或逐笔重算。

常见错误

  • 把账户编号直接当作数组下标，漏掉减一。
  • 转账先扣款再验证收款账户，失败却遗留余额变化。
  • 用余额 > money 判断，错误拒绝恰好取空的交易。
  • 把同账户转账直接返回 true，绕过余额不足检查。
  • Java / C++ 使用 32 位整数，或 JavaScript 累计余额仍使用 Number。

面试追问

并发转账怎么办？ 当前题目是顺序调用；真实并发服务需用事务或按固定账户顺序加锁，使检查与写入整体不可被插入，并避免死锁。这里的先检查后更新仅保证顺序模型下的语义。

如何处理重试与小数金额？ 重试可用交易唯一编号实现幂等；金额使用最小货币单位的整数表示。流水、持久化、权限与故障恢复属于真实系统扩展，不是本题要求。

Java

class Bank {
    private final long[] balance;
    public Bank(long[] balance) {
        this.balance = balance.clone();
    }
    private boolean valid(int account) {
        return account >= 1 && account <= balance.length;
    }
    public boolean transfer(int account1, int account2, long money) {
        if (!valid(account1) || !valid(account2)
                || balance[account1 - 1] < money) return false;
        balance[account1 - 1] -= money;
        balance[account2 - 1] += money;
        return true;
    }
    public boolean deposit(int account, long money) {
        if (!valid(account)) return false;
        balance[account - 1] += money;
        return true;
    }
    public boolean withdraw(int account, long money) {
        if (!valid(account) || balance[account - 1] < money) return false;
        balance[account - 1] -= money;
        return true;
    }
}

Python

from typing import List

class Bank:
    def __init__(self, balance: List[int]):
        self.balance = balance.copy()

    def valid(self, account: int) -> bool:
        return 1 <= account <= len(self.balance)

    def transfer(self, account1: int, account2: int, money: int) -> bool:
        if (not self.valid(account1) or not self.valid(account2)
                or self.balance[account1 - 1] < money):
            return False
        self.balance[account1 - 1] -= money
        self.balance[account2 - 1] += money
        return True

    def deposit(self, account: int, money: int) -> bool:
        if not self.valid(account):
            return False
        self.balance[account - 1] += money
        return True

    def withdraw(self, account: int, money: int) -> bool:
        if not self.valid(account) or self.balance[account - 1] < money:
            return False
        self.balance[account - 1] -= money
        return True
