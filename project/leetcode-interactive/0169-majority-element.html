01 / Brief

题意与约束

多数的定义

若值出现次数大于数组长度一半的向下取整，它就是多数元素。严格“大于”意味着一个数组最多只有一个多数元素。

题目保证

输入一定存在多数元素；官方追问要求在线性时间内、仅用常数额外空间完成。

约束

  • n == nums.length
  • 1 ≤ n ≤ 5 × 10⁴
  • -10⁹ ≤ nums[i] ≤ 10⁹
  • 输入保证多数元素存在

Official examples

nums = [3,2,3]             → 3
nums = [2,2,1,1,1,2,2]     → 2

Boyer–Moore 投票

关键前提：题目保证多数元素存在，所以第一遍结束的候选可以直接返回；若没有这项保证，必须再计数验证。

核心洞察：成对抵消

维护 candidate 和净票数 count。当票数归零，当前元素成为新候选；遇到候选就加一，遇到不同值就减一。

可以把一次减一理解成“候选的一票”和“反对者的一票”成对删除。多数元素出现超过一半，即使把它与所有非多数元素尽可能配对抵消，仍至少剩下一票，因此最终候选必然是多数元素。

完整过程

  1. 初始化 count = 0。
  2. 遍历每个值；若 count == 0，先令它成为候选。
  3. 当前值等于候选则 count++，否则 count--。
  4. 扫描结束，依据题目保证直接返回候选。

若不保证多数存在

第一遍只产生“可能的候选”，不能证明它超过一半。第二遍统计候选实际出现次数；仅当次数大于 ⌊n/2⌋ 时返回，否则按接口约定返回空值或错误。

Boyer–Moore 的候选阶段仍是 O(n) / O(1)；验证再做一遍，渐进复杂度不变。

复杂度与边界

时间 O(n)

每个元素处理一次。

空间 O(1)

只保存候选与票数。

单元素

第一票直接成为候选。

负数与大值

只比较相等性，不做数值运算。

替代方案

哈希计数

O(n) 时间、O(n) 空间；最直观，也适合无保证时确认频率。

排序取中位

排序后多数元素必覆盖中间位置，时间 O(n log n)；原地排序空间取决于实现，并会修改输入。

分治

递归求左右候选再计数合并，通常 O(n log n) 时间与递归栈空间。

随机抽样

多数元素抽中概率超过一半，期望很快，但不是确定性最坏界，面试主线不如投票法。

面试追问

  • 没有多数保证时怎样验证？
  • 如何扩展到出现次数大于 n/3 的元素？
  • 数据流太大无法存储时为何仍可处理？
  • 如何解释抵消不改变“多数仍有剩余”的性质？

常见错误

  • 票数为零时更新候选，却忘记再给当前票加一。
  • 没有多数保证时仍直接返回第一遍候选。
  • 把多数误解为出现次数最多，而不是严格超过一半。
  • 使用哈希表后声称空间是 O(1)。

class Solution {
    public int majorityElement(int[] nums) {
        int candidate = 0;
        int count = 0;

        for (int value : nums) {
            if (count == 0) {
                candidate = value;
            }
            count += value == candidate ? 1 : -1;
        }
        return candidate;
    }
}
