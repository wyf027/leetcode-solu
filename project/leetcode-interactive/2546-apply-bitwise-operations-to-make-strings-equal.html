执行逐位运算使字符串相等

在两个位置之间同时运行 OR 与 XOR。先观察一次操作怎样改写比特，再决定两个二进制字符串能否互相抵达。

中等 字符串 位运算 非付费题
Problem

题意

Apply Bitwise Operations to Make Strings Equal

给定两个长度都为 n、下标从 0 开始的二进制字符串 s 与 target。你可以对 s 执行任意次下面的操作：

  • 选择两个不同的下标 i 和 j。
  • 同时令 s[i] = s[i] OR s[j]，并令 s[j] = s[i] XOR s[j]；右侧都使用操作前的两个旧值。

判断是否能够把 s 变成 target。

约束

  • n == s.length == target.length
  • 2 <= n <= 105
  • s 和 target 只包含字符 0 与 1

Solution · Spoiler

完整题解

先独立思考，再按需展开核心结论与代码。

核心洞察

一次操作无法改变“整个字符串是否至少含有一个 1”。因此答案只取决于 s 与 target 是否同为全零，或同为非全零。

四种输入对

  • 00 → 00：不变
  • 01 → 11：产生第二个 1
  • 10 → 11：产生第二个 1
  • 11 → 10：仍至少保留一个 1

完整过程

  1. 分别检查 s 和 target 中是否存在字符 '1'。
  2. 若只有一个字符串含 1，返回 false：全零字符串经过任何操作仍全零，而非全零字符串也无法失去最后一个 1。
  3. 若两者都全零，无需操作，返回 true。
  4. 若两者都含 1，返回 true：可以把一个 1 当作锚点，逐位调出需要的形态。

正确性证明

必要性：对任意被选中的二元组，只要旧值中至少有一个 1，新值 (a OR b, a XOR b) 中仍至少有一个 1；而 00 只能变成 00。所以“是否含 1”是不变量，两个字符串该属性不同则不可达。

充分性：若两串都含 1，先用当前的某个 1 把目标中选定的 1 位置设为 1。以该位置为第一个下标 i 时，(1,0) → (1,1)、(1,1) → (1,0)，所以锚点保持为 1，并可逐个切换其他位置，最终得到 target。

边界与复杂度

  • 两串都全零：直接可达。
  • 一串全零、另一串非全零：一定不可达。
  • 两串相同：结论自然成立，不必特判。
  • 时间复杂度：O(n)。
  • 额外空间复杂度：O(1)。

四语言完整代码

Java官方签名
class Solution {
    public boolean makeStringsEqual(String s, String target) {
        return s.indexOf('1') >= 0 == (target.indexOf('1') >= 0);
    }
}
JavaScript官方签名
/**
 * @param {string} s
 * @param {string} target
 * @return {boolean}
 */
var makeStringsEqual = function(s, target) {
    return s.includes('1') === target.includes('1');
};
Python 3官方签名
class Solution:
    def makeStringsEqual(self, s: str, target: str) -> bool:
        return ('1' in s) == ('1' in target)
C++官方签名
class Solution {
public:
    bool makeStringsEqual(string s, string target) {
        return (s.find('1') != string::npos) ==
               (target.find('1') != string::npos);
    }
};

替代方案

可以从操作真值表出发构造具体变换序列，但本题只问“是否可达”，无需真的模拟。对所有字符串做 BFS 需要指数级状态空间，在 n = 105 时不可行。

常见错误

  • 把两个赋值当作先后执行，忘记题目要求同时更新。
  • 误以为 1 的数量不变；实际上 01 → 11 会增加一个 1。
  • 只比较两串的 1 的数量，而没有寻找真正的不变量。
  • 用指数级搜索模拟全部状态。

面试追问

为什么存在一个 1 就足够？
它可以充当不消失的锚点；作为第一个下标时，与另一个位置操作即可切换那个位置的比特。
如果 OR 与 XOR 改为顺序赋值呢？
状态转移表会改变，当前不变量和结论不能直接沿用，必须重新分析。
能否提前结束扫描？
可以分别在找到第一个 1 时停止；语言内置的查找通常已经这样表达，代码也更清晰。
