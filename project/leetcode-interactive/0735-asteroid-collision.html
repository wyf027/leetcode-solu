小行星碰撞

一排速度相同、方向各异的小行星即将相遇。观察碰撞链如何展开，并推断最终仍在轨道上的成员。

10向右 →
-5← 向左

Problem

题目描述

给定整数数组 asteroids，每个元素代表同一行中的一颗小行星，数组下标表示它们从左到右的相对位置。

  • 绝对值表示大小；正数向右移动，负数向左移动。
  • 所有小行星速度相同。相撞时较小者爆炸；大小相同则双方都爆炸。
  • 同向移动的小行星不会相撞。返回所有碰撞结束后的排列。

函数签名

asteroidCollision(asteroids: integer[]) → integer[]

正负号只表示方向，不影响数组中的初始相对位置。

官方示例

示例 1

输入：asteroids = [5,10,-5] 输出：[5,10]

10 与 -5 相撞后留下 10；5 与 10 同向。

示例 2

输入：asteroids = [8,-8] 输出：[]

双方大小相同，因此同时爆炸。

示例 3

输入：asteroids = [10,2,-5] 输出：[10]

-5 先摧毁 2，随后又与 10 相撞并消失。

示例 4

输入：asteroids = [3,5,-6,2,-1,4] 输出：[-6,2,4]

-6 连续摧毁 5、3；右侧的 2 摧毁 -1。

约束

  • 2 <= asteroids.length <= 104
  • -1000 <= asteroids[i] <= 1000
  • asteroids[i] != 0

Solution

单调碰撞链：用栈保留稳定前缀

核心洞察：只有“左边向右（正数）、右边向左（负数）”这一种相邻方向组合可能相撞。按从左到右扫描时，新来的负数只需要与当前幸存序列末尾的正数反复比较。

完整过程

  1. 维护数组 stack，表示已经扫描部分在内部碰撞结束后的稳定状态。
  2. 扫描当前小行星 a。若 a > 0，或栈顶不是正数，则不会与栈顶迎面相撞，可以直接入栈。
  3. 当 a < 0 且栈顶为正数时，比较二者绝对大小：较小者删除；相等则二者同时删除。
  4. 若栈顶被删除而 a 仍存在，就继续与新的栈顶比较，形成一条连续碰撞链。
  5. 扫描结束后，栈中元素从左到右就是最终答案。

边界情况

  • 全同向：不会发生碰撞，原样返回。
  • 先负后正：二者背向而行，不会相撞。
  • 相同大小：栈顶与当前小行星同时消失。
  • 一个负数可能连续摧毁多个较小正数。

复杂度

时间：O(n)。每颗小行星至多入栈一次、出栈一次。

空间：O(n)，最坏情况下所有小行星都留下。

正确性：不变式

每次开始处理新元素前，stack 恰好等于已扫描前缀完成所有内部碰撞后的结果，并且内部不存在仍可发生的迎面碰撞。

正确性：保持与终止

新元素唯一可能首先撞到的是幸存序列末尾的正数。循环逐次准确处理这对碰撞，直到当前元素消失或再无可撞对象；此时不变式恢复。全部元素处理完后，不变式直接说明栈就是全数组最终状态。

Implementations

四语言完整代码

import java.util.Arrays;

class Solution {
    public int[] asteroidCollision(int[] asteroids) {
        int[] stack = new int[asteroids.length];
        int top = 0;

        for (int asteroid : asteroids) {
            boolean alive = true;

            while (alive && asteroid < 0 && top > 0 && stack[top - 1] > 0) {
                int rightSize = stack[top - 1];
                int leftSize = -asteroid;

                if (rightSize < leftSize) {
                    top--;
                } else if (rightSize == leftSize) {
                    top--;
                    alive = false;
                } else {
                    alive = false;
                }
            }

            if (alive) {
                stack[top++] = asteroid;
            }
        }

        return Arrays.copyOf(stack, top);
    }
}

var asteroidCollision = function (asteroids) {
    const stack = [];

    for (const asteroid of asteroids) {
        let alive = true;

        while (
            alive &&
            asteroid < 0 &&
            stack.length > 0 &&
            stack[stack.length - 1] > 0
        ) {
            const rightSize = stack[stack.length - 1];
            const leftSize = -asteroid;

            if (rightSize < leftSize) {
                stack.pop();
            } else if (rightSize === leftSize) {
                stack.pop();
                alive = false;
            } else {
                alive = false;
            }
        }

        if (alive) {
            stack.push(asteroid);
        }
    }

    return stack;
};

#include <vector>
using namespace std;

class Solution {
public:
    vector<int> asteroidCollision(vector<int>& asteroids) {
        vector<int> stack;
        stack.reserve(asteroids.size());

        for (int asteroid : asteroids) {
            bool alive = true;

            while (alive && asteroid < 0 &&
                   !stack.empty() && stack.back() > 0) {
                int rightSize = stack.back();
                int leftSize = -asteroid;

                if (rightSize < leftSize) {
                    stack.pop_back();
                } else if (rightSize == leftSize) {
                    stack.pop_back();
                    alive = false;
                } else {
                    alive = false;
                }
            }

            if (alive) {
                stack.push_back(asteroid);
            }
        }

        return stack;
    }
};

Trade-offs

替代方案

反复扫描相邻对

每轮寻找一对可碰撞元素并删除，再从头扫描。直观，但最坏会退化到 O(n²)。

双向链表模拟

删除邻居很快，但仍需复杂的事件维护；在本题相同速度模型下没有优势。

原数组复用作栈

可以用写指针把额外空间降到 O(1)（不计返回值），代价是修改输入、可读性下降。

Interview Follow-ups

面试追问

为什么总时间不是 O(n²)？while 看起来嵌套在 for 里。

用摊还分析：每个元素最多入栈一次、出栈一次。所有 while 的弹栈次数加起来不超过 n。

如果速度不同，还能用这个方法吗？

通常不能。不同速度会让同向小行星也可能追撞，并且事件顺序依赖位置、速度与碰撞时间，需要按时间管理事件。

怎样原地实现？

把输入数组前缀当作栈，用一个 top 写指针覆盖已经确定无用的位置，最后返回有效前缀。

Pitfalls

常见错误

  • 把所有异号相邻元素都当作会碰撞；实际只有“正数在左、负数在右”。
  • 当前负数摧毁一个正数后就停止，没有继续检查新的栈顶。
  • 相等时只删除一方，或误把当前元素再次入栈。
  • 用 abs 比较后忘记保留方向信息。
  • 在遍历原数组时频繁删除元素，导致索引错乱或二次复杂度。
