准时到达的列车
最小时速

Minimum Speed to Arrive on Time

车程之外，还有等整点的时间。先亲手安排一段通勤，再思考怎样找到所需的最小时速。

01 / 任务说明

从第 0 小时出发，按顺序搭乘 n 趟列车。数组 dist 给出各段距离（千米），hour 是到办公室的时限（小时）。所有列车使用同一个正整数时速。

列车只能在整数小时出发：若上一趟在 1.5 小时抵达，要等到 2 小时才能换乘；恰好整点抵达则可立即换乘。终点到达后无需等待。求到达时间不超过 hour 的最小正整数时速；无法实现时返回 -1。

参数：dist: integer[]，hour: double → integer。题目保证存在答案时不超过 10⁷。

完整约束

  • n == dist.length
  • 1 ≤ n ≤ 10⁵
  • 1 ≤ dist[i] ≤ 10⁵
  • 1 ≤ hour ≤ 10⁹
  • hour 的小数点后最多两位数字。

05 / 独立题解

完成自己的推理后，再展开核心思路、证明和四语言实现。

核心洞察：判定时速，再找第一个可行值

给定时速 v，前 n − 1 段都把“行驶 + 等待”合并为整数小时；最后一段只算真实行驶时间：

T(v) = Σ ceil(dist[i] / v) + dist[n−1] / v
       i = 0 ... n−2

每次发车时间都是整数，所以各段向上取整后相加就是前缀耗时。时速越高，各项用时不会增加，可行性呈现“不可行 → 可行”的单调序列，可以二分查找第一个可行时速。

完整过程

  1. 若 hour ≤ n − 1，返回 −1。前 n − 1 段至少各占 1 小时，末段距离为正，还需要额外时间。
  2. 令 left = 1、right = 10⁷。官方保证存在答案时不超过这个上界。
  3. 取中点 mid，累加前缀整数耗时 S，再判断末段能否在剩余时间内完成。
  4. 可行则 right = mid；不可行则 left = mid + 1。
  5. 当 left == right，返回 left。

用整数处理两位小数

令 H = round(hour × 100)。先判断 100S > H，若成立则不可行；否则比较 100 × dist[n−1] ≤ (H − 100S) × v。这等价于总时间不超过时限，不需要随意添加浮点 epsilon。

H 最大 10¹¹，与时速相乘最大 10¹⁸；Java 使用 long，C++ 使用 long long，Python 使用整数，JavaScript 在最后的交叉乘法使用 BigInt，避免超过 Number 的安全整数范围。

实例推演

dist = [1,3,2]，hour = 2.7。速度 2 的耗时为 1 + 2 + 1 = 4，不可行；速度 3 的耗时为 1 + 1 + 2/3 ≤ 2.7，可行。单调性使答案定位到 3。

正确性与边界

耗时公式正确

初始在整数小时 0 出发。若一段在整数小时 k 出发，则下一段出发时间为 k + ceil(dist[i]/v)。归纳可得前缀出发时刻等于各段向上取整之和；末段抵达即结束，不再取整。

单调判定正确

增大 v 时，每个 dist[i]/v 非增，向上取整仍非增。因此 T(v) 非增；某个速度可行时，更大速度也可行。

二分不会丢失答案

排除无解后，官方上界保证最小可行速度位于初始闭区间。mid 可行时，答案不大于 mid；否则所有不大于 mid 的速度都不可行。两种更新都保留答案并缩短区间，最终单点即为最小可行速度。

重点边界

  • n = 1：前缀为空，没有换乘等待。
  • hour = n − 1：末段不能零耗时，仍然无解。
  • 恰好整点抵达：无需额外等待，不能无条件加 1。
  • 最后一段：不能向上取整，否则会误判可行性。
  • 答案可达 10⁷，交叉乘法要使用足够宽的整数类型。

复杂度

每次判定 O(n)，二分 O(log U) 轮，U = 10⁷，总时间 O(n log U)，约 24 轮；四份代码均只保留常数个变量，额外空间 O(1)。这里采用固定范围整数运算模型。

Java

class Solution {
    public int minSpeedOnTime(int[] dist, double hour) {
        long h = Math.round(hour * 100);
        if (h <= 100L * (dist.length - 1)) return -1;
        int left = 1, right = 10_000_000;
        while (left < right) {
            int mid = left + (right - left) / 2;
            if (canArrive(dist, h, mid)) right = mid;
            else left = mid + 1;
        }
        return left;
    }

    private boolean canArrive(int[] dist, long h, int speed) {
        long whole = 0;
        for (int i = 0; i < dist.length - 1; i++) {
            whole += (dist[i] + speed - 1) / speed;
        }
        if (100L * whole > h) return false;
        return 100L * dist[dist.length - 1]
            <= (h - 100L * whole) * speed;
    }
}

var minSpeedOnTime = function(dist, hour) {
    const h = Math.round(hour * 100);
    if (h <= 100 * (dist.length - 1)) return -1;
    function canArrive(speed) {
        let whole = 0;
        for (let i = 0; i < dist.length - 1; i++) {
            whole += Math.floor((dist[i] + speed - 1) / speed);
        }
        if (100 * whole > h) return false;
        // Cross products can exceed Number's safe integer range.
        return 100n * BigInt(dist[dist.length - 1]) <=
            BigInt(h - 100 * whole) * BigInt(speed);

        const mid = left + Math.floor((right - left) / 2);
        if (canArrive(mid)) right = mid;
        else left = mid + 1;
    }
    return left;
};

from typing import List

class Solution:
    def minSpeedOnTime(self, dist: List[int], hour: float) -> int:
        h = round(hour * 100)
        n = len(dist)
        if h <= 100 * (n - 1):
            return -1

        def can_arrive(speed: int) -> bool:
            whole = 0
            for i in range(n - 1):
                whole += (dist[i] + speed - 1) // speed
            if 100 * whole > h:
                return False
            return 100 * dist[-1] <= (h - 100 * whole) * speed

        left, right = 1, 10_000_000
        while left < right:
            mid = left + (right - left) // 2
            if can_arrive(mid):
                right = mid
            else:
                left = mid + 1
        return left

C++

#include <vector>
#include <cmath>
using namespace std;

class Solution {
public:
    int minSpeedOnTime(vector<int>& dist, double hour) {
        long long h = llround(hour * 100);
        int n = static_cast<int>(dist.size());
        if (h <= 100LL * (n - 1)) return -1;
        auto canArrive = [&](int speed) {
            long long whole = 0;
            for (int i = 0; i < n - 1; ++i)
                whole += (dist[i] + speed - 1) / speed;
            if (100LL * whole > h) return false;
            return 100LL * dist.back() <= (h - 100LL * whole) * speed;
        };
        int left = 1, right = 10'000'000;
        while (left < right) {
            int mid = left + (right - left) / 2;
            if (canArrive(mid)) right = mid;
            else left = mid + 1;
        }
        return left;
    }
};

替代方案、常见错误与面试追问

替代方案

线性枚举速度也正确，但最坏 O(nU)，范围过大。若没有官方答案上界，可以先倍增速度直到找到可行上界，再二分；必须先处理 hour ≤ n − 1，并考虑数值溢出。直接用总距离 / hour 只能估算下界，因为没有计算换乘等待。

常见错误

  • 对整条线路只取一次整：忽略了逐段换乘。
  • 对所有段都取整：末段没有等待。
  • 可行时更新 right = mid − 1，却沿用本页闭区间模板：可能排除答案。
  • JavaScript 用位运算处理大范围时间或乘积：位运算会压缩为 32 位整数。
  • 截断 hour 或添加任意浮点容差：可能改变可行性边界。

面试追问

为什么不能直接解方程？ 前缀向上取整产生阶梯函数，用单调判定更直接。

hour 小数位数不固定怎么办？ 可以从十进制字符串构造精确有理数，或分析浮点误差后再选择判定方式；本题实现依赖两位小数约束。

若每隔半小时发车呢？ 将前缀取整单位改为 0.5 小时，并重新推导无解条件；时间仍随速度非增，可以继续二分。

可以提前终止判定吗？ 可以。累加前缀时一旦超过时限，剩余距离为正，直接返回不可行。
