1147 · Longest Chunked Palindrome Decomposition

段式回文

把一条字符串切成若干非空片段，让第一个片段等于最后一个、第二个等于倒数第二个……求最多能切出多少段。

HARD 贪心 双指针 字符串 滚动哈希

Formal definition

镜像片段规则

将 text 拆成 (subtext₁, subtext₂, …, subtextₖ)：

  • 每个 subtextᵢ 都非空；
  • 依次连接后恰好等于 text；
  • 所有合法 i 均满足 subtextᵢ = subtextₖ₋ᵢ₊₁。
返回：满足条件时最大的 k。

  • text 仅由小写英文字母组成。

Solution

题解：尽早锁定最短镜像片段

核心洞察：从左右两端同步向中间扩展。一旦左暂存串与右暂存串相等，立刻把它们作为一对片段锁定；最短的可匹配前后缀会给中间留下最多的继续切分机会。

完整过程

  1. 令 i = 0、j = n - 1，并令左右暂存串为空。
  2. 每轮把 text[i] 追加到左暂存串末尾，把 text[j] 放到右暂存串开头，然后 i++、j--。
  3. 若两暂存串相等，说明找到一对最短的相同前后缀。若这两个暂存串来自不相交的两侧，答案增加 2；若它们在正中间会合，答案只增加 1。
  4. 匹配后清空两边暂存串，继续处理尚未归档的中间区间。
  5. 扫描结束后若仍有未匹配内容，它整体只能成为一个中央片段，答案增加 1。

为什么“尽早匹配”正确？

设当前剩余串存在某个合法分解。它最外侧的第一段必须同时是剩余串的前缀和后缀。算法找到的是最短的相同非空前后缀 x。

如果某个最优分解的最外段比 x 更长，那么从这两个更长外段的开头分别切出 x，两侧仍相等；这样至少不会减少片段数，并为中间保留更多字符。因此选择最短可匹配前后缀存在一个同样最优的解。

锁定这对 x 后，问题缩小为中间子串上的同类问题。重复交换论证与归纳，就得到全局最大段数。

边界处理

  • 长度为 1：唯一字符是中央段，返回 1。
  • 完全没有相同的真前后缀：整串作为一段。
  • 两侧正好在中心相遇：只计一个中央片段，不能加 2。
  • 所有字符相同：每个字符均可独立成段，答案为 n。

复杂度

下面代码直接构造并比较暂存字符串。由于字符串拼接、头部插入或切片可能是线性的，最坏时间复杂度为 O(n²)；暂存字符串及返回前的中间状态需要 O(n) 空间。

在 n ≤ 1000 的约束下足够直接。若用双滚动哈希维护两侧，可把期望时间降到 O(n)，附加空间降到 O(1)。

常见错误

  • 右暂存串也在末尾追加，导致比较方向反了。
  • 匹配后忘记清空暂存串。
  • 中心会合仍加 2，产生偶数答案错误。
  • 只检查等长固定块，遗漏不同长度的合法片段。
  • 使用单哈希却不讨论碰撞风险。

继续命中 abcdef

第三对镜像片段归档，累计 6 段。

中央剩余 adam

它作为唯一中央片段计 1，最终得到 7。

四语言完整代码

class Solution {
    public int longestDecomposition(String text) {
        int i = 0;
        int j = text.length() - 1;
        int answer = 0;
        StringBuilder left = new StringBuilder();
        StringBuilder right = new StringBuilder();

        while (i <= j) {
            left.append(text.charAt(i++));
            right.insert(0, text.charAt(j--));

            if (left.toString().equals(right.toString())) {
                // i - 1 与 j + 1 是本轮刚读取的位置。
                // 若读取后仍有间隔，则是两段；否则是中央的一段。
                answer += (i - 1 < j + 1) ? 2 : 1;
                left.setLength(0);
                right.setLength(0);
            }
        }

        // 扫描结束仍未匹配的内容整体成为中央段。
        if (left.length() > 0) {
            answer++;
        }
        return answer;
    }
}

 * @param {string} text

var longestDecomposition = function(text) {
    let i = 0;
    let j = text.length - 1;
    let answer = 0;
    let left = "";
    let right = "";

    while (i <= j) {
        left += text[i++];
        right = text[j--] + right;

        if (left === right) {
            answer += (i - 1 < j + 1) ? 2 : 1;
            left = "";
            right = "";
        }
    }

    if (left.length > 0) {
        answer++;
    }
    return answer;
};
class Solution:
    def longestDecomposition(self, text: str) -> int:
        i, j = 0, len(text) - 1
        answer = 0
        left = ""
        right = ""

        while i <= j:
            left += text[i]
            right = text[j] + right
            i += 1
            j -= 1

            if left == right:
                answer += 2 if i - 1 < j + 1 else 1
                left = ""
                right = ""

        if left:
            answer += 1
        return answer
class Solution {
public:
    int longestDecomposition(string text) {
        int i = 0;
        int j = static_cast<int>(text.size()) - 1;
        int answer = 0;
        string left;
        string right;

        while (i <= j) {
            left.push_back(text[i++]);
            right.insert(right.begin(), text[j--]);

            if (left == right) {
                answer += (i - 1 < j + 1) ? 2 : 1;
                left.clear();
                right.clear();
            }
        }

        if (!left.empty()) {
            ++answer;
        }
        return answer;
    }
};

替代方案

双滚动哈希

同步更新左缓冲的正向哈希和右缓冲的对应哈希；哈希相等时再锁定片段。时间可达期望 O(n)，但必须处理碰撞：使用双模数，或在哈希命中时再做字符串确认。

区间动态规划

令状态表示某个子串能拆出的最大段数，枚举相同前后缀长度并递归中间区间。它更直观地表达最优子结构，但状态和转移更重，通常不如贪心简洁。

面试追问

  • 如何证明最短匹配不会破坏最优解？ 用前后缀交换论证，把任意较长外层片段先切出最短公共前后缀。
  • 怎样做到线性时间？ 维护两端滚动哈希，匹配时归零并进入下一层。
  • 怎样消除哈希碰撞？ 双哈希降低概率；要求严格确定性时，命中后比较对应区间，或使用确定性字符串算法辅助。
  • 能否输出具体分段？ 匹配时把左片段放入前半列表、右片段放入后半列表，最后夹入中央片段并拼接。
  • 若允许空片段会怎样？ 片段数将失去有限上界，所以“非空”约束不可缺少。
