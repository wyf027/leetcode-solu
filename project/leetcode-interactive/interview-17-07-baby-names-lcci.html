题意

给定名字及其出现频次列表 names，以及本质相同的名字对 synonyms。同义关系具有对称性和传递性。合并每组同义名字的频次，并用该组中字典序最小的名字作为输出代表。

官方样例
输入
names = ["John(15)","Jon(12)","Chris(13)","Kris(4)","Christopher(19)"], synonyms = ["(Jon,John)","(John,Johnny)","(Chris,Kris)","(Chris,Christopher)"]
输出
["John(27)","Chris(36)"]
提示与格式 names.length <= 100000

输出顺序不作要求；页面为便于核对保留各分量首次出现在 names 中的顺序。

可见空格约定：若字符串含空格，页面会用 ␠ 展示；本题官方样例字符串没有空格。

题解

核心洞察

同义词对就是无向边；每个连通分量是一组真实姓名。并查集无需显式保存整组成员，只要维护父指针，并让字典序更小的根始终成为父节点。

面试最推荐：哈希表 + 并查集

名字是字符串，用哈希表维护 parent[name]。路径压缩让后续查找接近常数；合并时比较两个根，较小者成为新根。

完整过程

  1. 解析 Name(count)，记录名字与频次。
  2. 将 names 与 synonyms 中出现的所有名字注册为独立集合。
  3. 对每个同义词对查找两个根；若不同，把字典序较大的根指向较小根。
  4. 再次遍历 names，把频次累加到压缩后的根。
  5. 把每个根和总频次格式化为 Root(total)。

边界

  • · synonyms 为空，各名字独立。
  • · 同义词可出现 names 中没有的零频别名。
  • · 同一对重复或形成环，不重复计数。
  • · 代表名可能只出现在 synonyms 中。

复杂度

设字符串总长度为 L、名字和关系数规模为 N。解析 O(L)，并查集近似 O(N α(N))，空间 O(N)。字符串比较还与名字长度相关。

常见错误

  • · 只合并直接关系，漏掉传递性。
  • · 只初始化 names，找不到未计数别名。
  • · 按秩合并后忘记维护最小代表名。
  • · 边合并边累加，环导致重复计数。

替代方案

建无向图后 DFS/BFS 每个连通分量同样正确，概念直观但要保存全部邻接边。反复更新整组映射会退化，面试不推荐。

面试追问

按秩合并更快，为什么不用？

可以按秩维护结构，同时为每个根额外保存最小名字；本题直接让最小名字做根更简洁，路径压缩已足够。

为什么最后才汇总频次？

关系图可能成环或重复，先完成集合结构再把每个原始频次恰好累加一次，可避免重复。

输出顺序怎么处理？

题目不要求顺序。若系统需要稳定输出，可按代表名排序，或保留组件首次出现顺序。

如何支持在线新增关系？

并查集天然支持追加 union；频次可维护在根上，合并时把两个根的计数相加。
