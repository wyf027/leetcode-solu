判断子序列 Is Subsequence

题目描述

给定两个只包含小写英文字母的字符串 s 和 t。如果 s 是 t 的子序列，返回 true；否则返回 false。

子序列是从原字符串中删除任意数量的字符（也可以一个都不删除）后得到的新字符串； 剩余字符的相对位置必须保持不变。例如，"ace" 是 "abcde" 的子序列，而 "aec" 不是。
示例 1 
输入：s = "abc", t = "ahbgdc"
输出：true
示例 2 
输入：s = "axc", t = "ahbgdc"
输出：false

约束

  • 0 <= s.length <= 100
  • 0 <= t.length <= 10⁴
  • s 和 t 仅由小写英文字母组成。

Solution

双指针：只让匹配指针前进

关键不是寻找所有组合，而是始终为 s 的当前字符选择 t 中最早可用的相同字符。越早完成一次匹配，留给后续字符的空间越大。

核心洞察

两个指针分别指向待匹配字符与当前扫描字符。扫描指针每轮都前进；只有字符相同时，匹配指针才前进。

终止判断

如果匹配指针最终到达 s.length，说明所有字符都按顺序出现；否则扫描结束时仍有字符缺失。

贪心含义

每次使用最靠左的可用位置不会损害后续选择，因此无需回退，也无需枚举删除方案。

完整过程

  1. 令 i = 0 指向 s，令 j = 0 指向 t。
  2. 当两个指针都未越界时，比较 s[i] 与 t[j]。
  3. 若相等，当前字符已按顺序找到，令 i++；无论是否相等，都令 j++。
  4. 扫描结束后返回 i == s.length。

正确性说明

维护不变式：每轮比较前，s[0..i-1] 已经匹配到 t[0..j-1] 中一组严格递增的位置，并且这些位置对已处理前缀而言尽可能靠左。若当前字符相等，选择 t[j] 是尚未扫描位置中最早的合法选择，不会减少后续字符可使用的位置；若不相等， t[j] 不可能匹配当前的 s[i]，跳过它是安全的。由此不变式持续成立。 当 i == s.length 时，所有字符已按相对顺序匹配，答案为真；若 t 扫描完仍有未匹配字符，则不存在其他更早但被遗漏的合法选择，答案为假。

边界情况

  • s 为空：空串是任意字符串的子序列，直接得到 true。
  • t 为空但 s 非空：没有字符可匹配，结果为 false。
  • s.length > t.length：双指针会自然返回 false，也可以提前结束。
  • 重复字符：每次只消费 t 中当前位置，保证同一字符位置不会被重复使用。
  • 两串完全相同：每次比较均匹配，最终返回 true。
时间复杂度O(|t|)
额外空间O(1)

四语言完整代码

Java 
class Solution {
    public boolean isSubsequence(String s, String t) {
        int i = 0;

        for (int j = 0; j < t.length() && i < s.length(); j++) {
            if (s.charAt(i) == t.charAt(j)) {
                i++;
            }
        }

        return i == s.length();
    }
}

class Solution:
    def isSubsequence(self, s: str, t: str) -> bool:
        i = 0

        for char in t:
            if i < len(s) and s[i] == char:
                i += 1

        return i == len(s)

class Solution {
public:
    bool isSubsequence(string s, string t) {
        int i = 0;

        for (int j = 0; j < static_cast<int>(t.size()) &&
                        i < static_cast<int>(s.size()); ++j) {
            if (s[i] == t[j]) {
                ++i;
            }
        }

        return i == static_cast<int>(s.size());
    }
};

替代方案

  • 动态规划：可以定义前缀状态判断能否完成匹配，但本题单次查询只需线性扫描， 二维状态会引入不必要的时间与空间开销。
  • 预处理位置 + 二分：先记录 t 中每个字母出现的全部下标。对 s 的每个字符，二分寻找严格大于上次位置的最小下标。单次查询更复杂， 但大量查询复用同一 t 时更合适。

面试追问：如果有十亿个 s？

先用 O(|t|) 时间把 t 预处理为 26 个有序下标列表。每次查询时， 对 s 中每个字符使用二分查找下一个合法位置，单次约为 O(|s| log |t|)，预处理结果可被所有查询复用。

若字符集固定，也可构造“从位置 j 开始，下一个字符 c 在哪里”的跳转表，使单次查询达到 O(|s|)，代价是约 O(|t| × 字符集大小) 的预处理空间。

常见错误

  • 字符不相等时错误地同时移动两个指针，从而跳过 s 中仍待匹配的字符。
  • 只检查字符是否都出现，却忽略它们在 t 中的相对顺序。
  • 在 s 为空时直接访问 s[0]，造成越界。
  • 每次调用字符串查找都从头开始，导致重复位置被使用或复杂度退化。
  • 把子序列误解为子串；子序列允许中间跳过字符，不要求连续。
