PROBLEM BRIEF

只操作字符，印出乘积

给定两个用字符串表示的非负整数 num1 与 num2，返回同样以字符串表示的乘积。不能直接把输入转换为整数，也不能使用内置 BigInteger。

竖式坐标口诀

p1 = i + j
p2 = i + j + 1

两数最长各 200 位；乘积最多 m + n 位，所以准备固定长度的数字槽即可。

    CORE INSIGHT

    乘积位数固定，坐标可以预定

    长度为 m 与 n 的整数相乘，结果至多 m+n 位。num1[i] 与 num2[j] 的乘积，个位必落在 i+j+1，十位进位落在 i+j。从右向左遍历时，p2 中已有的旧值一起加入 sum，再重新拆出个位和进位。

    sum = digit1 × digit2 + ans[p2]
    ans[p1] += sum / 10
    ans[p2] = sum % 10

    COMPLEXITY

    每一对数字恰好相乘一次

    双层循环覆盖 m×n 对数字；结果数组长度为 m+n。最后线性跳过至多一个前导 0。

    TIME

    O(mn)

    SPACE

    O(m+n)

    FULL PROCESS & PROOF

    完整过程与正确性

    1. 1. 零捷径：任一输入是 "0"，直接返回 "0"。
    2. 2. 建槽：创建长度 m+n 的全 0 数组，覆盖乘积的全部可能位。
    3. 3. 逐对压印：i、j 都从右向左。将本次乘积加上 p2 已累计的值，再把新的个位写回 p2、进位累加至 p1。
    4. 4. 为什么正确：十进制中第 i、j 位的权重相乘后，只会影响相邻的 p1/p2。循环处理完全部数字对，结果数组正好等于所有部分积按位相加。
    5. 5. 输出：跳过唯一可能的首位 0，将剩余数字连接成字符串。

    BOUNDARIES

    边界情况

    • • 任一输入为 "0"：避免输出多枚 0。
    • • 单位数相乘：仍使用相同槽位公式。
    • • 连续进位，如 "99" × "99"。
    • • 200 位上限：结果至多 400 位。

    ALTERNATIVES

    替代方案取舍

    也可先生成每一行部分积，再做字符串加法，可读但代码更长、临时字符串更多。直接转整数或 BigInteger 违反题意。面试主线优先固定数组竖式模拟。

    INTERVIEW FOLLOW-UPS

    面试高频追问

    Q：为什么数组长度是 m+n？
    m 位数小于 10^m，n 位数小于 10^n，乘积小于 10^(m+n)，最多 m+n 位。
    Q：为什么 p1 用 +=，p2 用 =？
    p2 先合入旧累计值再拆分；个位已归一化后覆盖，进位要叠加到更高位。
    Q：能否进一步降空间？
    返回值本身可能有 m+n 位；若计入输出，渐进空间已是最优量级。

    COMMON MISTAKES

    常见错误

    • • 把位置写成 i+j 与 i+j-1，导致整体错位。
    • • 计算 sum 时漏掉 result[p2] 已有的累计值。
    • • 把 result[p1] 写成赋值，覆盖先前进位。
    • • 忘记零快捷路或首位 0，输出 "000"。
    • • 使用语言大整数偷算，违反限制且失去考点。
