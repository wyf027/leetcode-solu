01 · Problem

题目说明

给你一个整数数组 nums 和整数 k，返回所有元素的乘积严格小于 k 的连续子数组数量。子数组必须连续；单个元素也算子数组。

官方示例 1

典型窗口
输入：nums = [10,5,2,6], k = 100
输出：8
解释：符合条件的 8 个连续子数组为
[10]、[5]、[2]、[6]、[10,5]、[5,2]、[2,6]、[5,2,6]。
[10,5,2] 的乘积等于 100，并非严格小于 100，因此不计入。

官方示例 2

阈值边界
输入：nums = [1,2,3], k = 0
输出：0

约束

  • 1 ≤ nums.length ≤ 3 × 10⁴
  • 1 ≤ nums[i] ≤ 1000
  • 0 ≤ k ≤ 10⁶
提交签名
numSubarrayProductLessThanK(nums, k) → integer

注意两个词：连续与严格小于。等于 k 的窗口不能计数。

Complete Walkthrough

滑动窗口：维护一个始终合法的最长后缀

核心洞察

数组元素全部为正数。右端加入新元素时乘积只会不减；如果乘积达到或超过 k，不断移走左端元素，直到窗口重新满足条件。此时以右端 right 结尾、起点位于 left...right 的所有子数组都合法，一共有 right - left + 1 个。

完整过程

  1. 若 k ≤ 1，直接返回 0；正整数乘积至少为 1。
  2. 初始化 left = 0、product = 1、answer = 0。
  3. 枚举右端 right，将 nums[right] 乘入窗口。
  4. 当 product ≥ k 时，除去 nums[left] 并右移 left。
  5. 窗口合法后，将 right - left + 1 加入答案。

为什么一次加一批？

收缩结束后，整个窗口 [left, right] 的乘积小于 k。由于所有元素都为正整数，从左侧继续删元素不会让乘积变大，所以：

[left,right]、[left+1,right] …… [right,right] 全部合法，恰好有 right-left+1 个。

正确性证明

不变式：每轮计数前，窗口 [left, right] 的乘积严格小于 k，且所有以 right 结尾、起点小于 left 的子数组都不合法。

保持：加入右端后，循环移除左端直到乘积合法。因为元素均为正数，移动左端只会使乘积不增；循环停止时窗口合法。若存在更靠左的合法起点，收缩就不应越过它，因此更靠左的起点均不合法。

计数完整且不重复：本轮准确计入所有以当前 right 结尾的合法子数组。不同轮的右端不同，因此不会重复。遍历所有右端后，每个合法连续子数组恰好被计入一次，答案正确。

终止：right 单调扫描到数组末尾，left 也只向右移动，算法必然结束。

边界与复杂度

  • k ≤ 1：答案必为 0。
  • 等于 k 也要收缩，因为条件是严格小于。
  • 单个元素不小于 k 时，窗口会收缩为空。
  • 时间复杂度 O(n)：每个元素至多进、出窗口各一次。
  • 额外空间复杂度 O(1)。

常见错误

  • 用 product > k 收缩，错误地把乘积等于 k 的窗口算进去。
  • 每轮只加 1，漏掉同一右端对应的多个合法起点。
  • 忘记处理 k ≤ 1，导致空窗口或指针越界。
  • 在 Java/C++ 中用过小的乘积类型；使用 long/long long 更稳妥。
  • 把“子数组”误解为不连续的子序列。

替代方案

暴力枚举：固定每个左端，逐步累乘所有右端，最坏 O(n²)，在 n = 3 × 10⁴ 时不可接受。

对数前缀和 + 二分：把乘积取对数转为区间和，对每个端点二分边界，可做到 O(n log n)。它更复杂，还需小心浮点精度；本题正整数和单调窗口使 O(n) 滑动窗口更直接。

class Solution {
    public int numSubarrayProductLessThanK(int[] nums, int k) {
        if (k <= 1) {
            return 0;
        }

        int left = 0;
        int answer = 0;
        long product = 1L;

        for (int right = 0; right < nums.length; right++) {
            product *= nums[right];

            while (product >= k) {
                product /= nums[left];
                left++;
            }

            answer += right - left + 1;
        }

        return answer;
    }
}

Interview Follow-ups

面试追问

  • 为什么本题要求正整数？零或负数会破坏“右扩乘积不减、左缩乘积不增”的单调性；包含零时可分段处理，包含负数时需要完全不同的计数方法。
  • 答案会不会溢出？最多有 n(n+1)/2 个子数组；本题 n ≤ 3 × 10⁴，最大约 4.5 亿，32 位有符号整数仍可容纳。
  • 能否输出所有合法子数组？可以在每轮枚举 left...right 的起点，但输出量本身可达 O(n²)，时间与空间下界都会随输出规模增长。
  • 如果条件改成乘积小于等于 k？把收缩条件从 product ≥ k 改为 product > k，并重新审视极端阈值。
