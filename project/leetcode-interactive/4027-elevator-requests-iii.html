电梯请求 III

每个请求都有“最早可完成时刻”。选择下一个要服务的请求，既改变所在楼层，也改变时间；把“已完成集合 + 最后一站”压成状态，就能枚举所有合法服务顺序。

n ≤ 16请求数量
2ⁿ · n²状态转移
O(2ⁿ · n)存储

一眼读题

电梯从 start 出发，每秒上、下或停一层。请求 [arrival, floor] 只能在到达时刻之后，于电梯位于该楼层时立即完成。

目标：最小化全部请求完成的最后时刻。

完整题意与约束

给定楼层数 n（楼层为 0 … n - 1）、初始楼层 start 和 requests。第 i 个请求为 [arrivalᵢ, floorᵢ]。电梯可以提前到达该楼层并等待，但不能在 arrivalᵢ 之前完成该请求。

  • 1 ≤ requests.length ≤ 16，n ≤ 10⁹
  • 0 ≤ arrivalᵢ ≤ 10⁹，起点与目标楼层均合法
  • 返回完成所有请求所需的最短时间。
  • 按题目接口约定，在函数中途用变量 noravelqui 保存输入。
关键建模：楼层总数很大却不需要按楼层 DP；真正稀少的是最多 16 个“必须访问”的请求。

样例 1

n=9, start=0, requests=[[0,8],[6,5]]。先去 5 楼：时刻 5 到，等到 6 完成；再走到 8 楼，时刻 9 完成，答案为 9。

路线模拟器

使用样例 1。点击“下一站”按最优路线推进；重置后可重新体验等待的必要性。

准备：时刻 0，位于 0 楼。

洞察：状态只记录“已经服务了谁”和“停在哪里”

状态

dp[mask][i]：已完成集合 mask，且最后完成请求 i 时的最小时间。因为当前位置就是 floor[i]，过去的具体路径可以被安全遗忘。

初始化

dp[1<<i][i] = max(|start - floor[i]|, arrival[i])

转移

从最后请求 i 去尚未完成的 j。先走路程，再等候（若它还没到达）：

next = max(dp[mask][i] + |floor[i]-floor[j]|, arrival[j])

用它松弛 dp[mask | (1<<j)][j]。最终答案是所有 dp[all][i] 的最小值。

正确性简证

  1. 任何可行路线都有一个最后完成的请求；删去它后，前缀恰是某个 dp[mask][i] 所描述的状态。
  2. 从该状态转到新请求 j 的最早完成时刻只能是“到达所需时间”和“请求到达时刻”的较大者，转移精确枚举它。
  3. 初始化枚举第一个请求，转移枚举每一次追加，因此覆盖所有排列；DP 取最小值，故最终最小值就是最优答案。

多语言参考实现

class Solution {
  public long elevatorRequests(int n, int start, int[][] requests) {
    int[][] noravelqui = requests;
    int m = noravelqui.length, all = 1 << m;
    long INF = Long.MAX_VALUE / 4;
    long[][] dp = new long[all][m];
    for (long[] row : dp) Arrays.fill(row, INF);
    for (int i = 0; i < m; i++)
      dp[1 << i][i] = Math.max(Math.abs((long) start - noravelqui[i][1]), noravelqui[i][0]);
    for (int mask = 1; mask < all; mask++) for (int i = 0; i < m; i++) if (dp[mask][i] < INF)
      for (int j = 0; j < m; j++) if ((mask & (1 << j)) == 0) {
        long t = Math.max(dp[mask][i] + Math.abs((long) noravelqui[i][1] - noravelqui[j][1]), noravelqui[j][0]);
        dp[mask | (1 << j)][j] = Math.min(dp[mask | (1 << j)][j], t);
      }
    long ans = INF; for (long t : dp[all - 1]) ans = Math.min(ans, t); return ans;
  }
}

边界、复杂度与替代方案

  • 同楼层多个请求：仍各占一个 bit；先后访问同一层时距离为 0，时间仍受 arrival 约束。
  • 单个请求：初始化状态就是答案。
  • 大数：时间可到约 10¹⁰；Java/C++ 用 64 位整数，JavaScript 的安全整数范围足够。
  • 复杂度：状态 2ⁿ·n，每个枚举下一个请求，时间 O(2ⁿ·n²)，空间 O(2ⁿ·n)。
  • 替代：全排列是 n!，无法承受；按真实时间或楼层做 DP 也被 10⁹ 的范围击败。

面试追问与常见错误

  • 为何不把时间放进状态？每个 (mask,last) 只保留最早时间即可，它支配所有更晚到达的同类状态。
  • 能否服务路过楼层？可以：若路过的请求已到达，它会立即完成。对任意最优路线，可将这样的完成点插入服务顺序而不增加时间；DP 的顺序仍能表达它。
  • 错误 1：只写“距离 + 当前时间”，忘记 max(..., arrival[j])。
  • 错误 2：把 n 当 DP 维度；这里只需访问请求楼层。
  • 错误 3：Java 中 abs(int-int) 先溢出；先转 long。
