1837. K 进制表示下的各位数字总和

Sum of Digits in Base K · EASY · 数学

同一个整数，换一种记法。先读题，再探索各位数字。

题目

给定用十进制表示的整数 n 和基数 k，求 n 的 k 进制表示中所有数位的数字之和。每一位按其十进制数值参与求和，最终返回的和也用十进制表示。

示例 1

输入：n = 34, k = 6
输出：9

34 的六进制表示为 54，各位相加：5 + 4 = 9。

示例 2

输入：n = 10, k = 10
输出：1

十进制表示仍为 10，各位相加：1 + 0 = 1。

约束：1 ≤ n ≤ 100；2 ≤ k ≤ 10。

参数：sumBase(n: integer, k: integer) → integer

官方题目 ↗

先想一想

改变进制会改变整数本身吗？数位的和与整数的值相同吗？尝试手写 34 的六进制表示，并区分“表示形式”与“返回值”。

下方展开后包含逐步演示、推导及四语言代码。

题解 · 一次剥离一位

核心洞察：整数除以 k 的余数就是最低位；商是去掉最低位后的数。只要求和，不必构造完整进制字符串。

除基取余工作台

数字卡片按正常书写顺序排列；新取出的更高位出现在左侧。每一步展示商、余数和累计和。

所有按钮支持 Tab 聚焦及 Enter / 空格操作。减少动态效果偏好下，默认仍为手动逐步操作；自动播放需主动开启。

完整过程

  1. 令累计和 sum = 0。
  2. 只要 n > 0，将 n % k 加入 sum。
  3. 令 n = floor(n / k)，继续处理剩余高位。
  4. 商为 0 时，返回 sum。

以 n = 34、k = 6 为例：34 = 5 × 6 + 4，先加 4；5 = 0 × 6 + 5，再加 5；最终得到 9。提取顺序为 4、5，而表示形式为 54。

为什么正确

每个非负整数都可唯一写成 n = qk + r，其中 0 ≤ r < k，所以 r 正是 k 进制最低位，q 保留其余高位。循环不变式：sum 等于已去掉各位之和，当前 n 的各位是尚未处理的部分。初始未去掉任何位，sum = 0；每轮加入恰好一个最低位并用商替换 n，不变式保持。k ≥ 2 使正数 n 严格变小，最终为 0，此时所有位恰好处理一次，sum 即所求。

边界与复杂度

n < k 时只有一位，答案就是 n；n 是 k 的幂时只有一个非零位，答案为 1；余数为 0 也要继续除法。本题 n ≥ 1；若扩展到 n = 0，此写法也返回 0。

设位数 d = ⌊logₖ n⌋ + 1，时间 O(d)，也常写作 O(logₖ n)；算法额外空间 O(1)。演示为回退保存状态，使用 O(d) 空间，与提交代码不同。

替代方案

可先转成 k 进制字符串，再逐字符累加，时间 O(d)、空间 O(d)。JavaScript 可用 n.toString(k)，但本题直接取余不需要字符串。递归也能写为 n % k + sumBase(floor(n/k), k)，基例为 n = 0；递归栈需 O(d) 空间。

常见错误

  • JavaScript 使用 n / k 而不向下取整，无法正确移除最低位。
  • 仍对 10 取余，得到的是十进制位。
  • 把答案再次转换成 k 进制；返回值应为十进制整数。
  • 遇到余数 0 就结束，会漏掉更高位；终止条件是商为 0。

面试追问

要输出完整表示呢？保存余数并反转；求和因顺序无关而不必反转。k > 10 呢？算术取余仍有效，表示时需设计字符映射。n 超过安全整数范围呢？JavaScript 使用 BigInt 并统一运算类型；字符串输入也可用大整数除法处理。

Java

class Solution {
    public int sumBase(int n, int k) {
        int sum = 0;
        while (n > 0) {
            sum += n % k;
            n /= k;
        }
        return sum;
    }
}

JavaScript

/**
 * @param {number} n
 * @param {number} k
 * @return {number}
 */
var sumBase = function(n, k) {
    let sum = 0;
    while (n > 0) {
        sum += n % k;
        n = Math.floor(n / k);
    }
    return sum;
};
