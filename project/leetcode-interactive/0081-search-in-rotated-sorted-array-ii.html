  • -10⁴ ≤ nums[i], target ≤ 10⁴
  • nums 保证由非降序数组旋转得到

Core insight

先辨有序半边，重复时剥掉迷雾

中点命中就返回。若 nums[L]、nums[M]、nums[R] 三者相等，无法判断哪边有序，只能令 L++、R--；否则至少有一半保持有序，再依据目标是否落在该半边的闭开区间里舍弃另一半。

Complexity

平均时间

O(log n)

最坏时间

O(n)

额外空间

O(1)

完整过程

  1. 1. 维护闭区间 L..R，计算 M。
  2. 2. 若 nums[M] 等于 target，返回 true。
  3. 3. 三端相等时同时收缩 L、R。
  4. 4. 判断左半或右半有序，并按目标值域取舍。
  5. 5. 区间为空仍未命中，返回 false。

边界与常见错误

  • ✓ 单元素、全部相同、目标位于旋转点。
  • ✓ 区间判断严格区分 < 与 ≤。
  • ✗ 三端相等时直接认定左半有序。
  • ✗ 返回下标；本题只要求布尔值。
  • ✗ 声称最坏仍是 O(log n)。

替代方案与面试追问

  • 线性扫描：O(n)，最简单但没有利用结构。
  • 先找旋转点：重复值同样会让定位退化。
  • 追问：为什么重复元素破坏严格二分保证？
  • 追问：能否构造最坏 O(n) 的输入？
  • 推荐：面试主线使用单次改造二分。

class Solution {
    public boolean search(int[] nums, int target) {
        int left = 0, right = nums.length - 1;

        while (left <= right) {
            int mid = left + (right - left) / 2;
            if (nums[mid] == target) return true;

            if (nums[left] == nums[mid] && nums[mid] == nums[right]) {
                left++;
                right--;
            } else if (nums[left] <= nums[mid]) {
                if (nums[left] <= target && target < nums[mid]) {
                    right = mid - 1;
                } else {
                    left = mid + 1;
                }
            } else {
                if (nums[mid] < target && target <= nums[right]) {
                    left = mid + 1;
                } else {
                    right = mid - 1;
                }
            }
        }
        return false;
    }
}
