Problem

题意

给定一个整数 n，你可以重复执行下面两种操作，将它转换为 0。请返回所需的最少操作次数。

1

翻转最低位

任何时候都可以翻转二进制表示最右侧的第 0 位。

2

有条件地翻转第 i 位

当第 i - 1 位为 1，并且第 i - 2 位到第 0 位全为 0 时，才可以翻转第 i 位。

示例 1
输入
n = 3
输出
2
过程
11 → 01 → 00

先依据第 0 位为 1 翻转第 1 位，再翻转第 0 位。

示例 2
输入
n = 6
输出
4
过程
110 → 010 → 011 → 001 → 000

每一步都满足上述规则，共 4 次操作。

约束：0 <= n <= 109。函数形式为 minimumOneBitOperations(n: integer) → integer。

Full solution

逆格雷码：把路径编号还原出来

核心洞察

题目的两种合法翻转恰好让所有非负整数按二进制反射格雷码的顺序相连：相邻状态只差一位。于是，从 n 到 0 的最短步数，就是把格雷码 n 解码成普通二进制后的编号。

answer = n XOR (n >> 1) XOR (n >> 2) XOR …

实现时不断把 n 右移，并异或到答案中；最多处理 30 位。

完整过程

初始化。令 answer = 0，保留当前片段 x = n。
吸收当前前缀。执行 answer ^= x。这会让答案的每一位等于原数从最高有效位到该位的异或前缀。
缩短片段。执行 x >>= 1，去掉已对齐的最低位置；只要 x != 0 就继续。
返回编号。循环结束时，answer 就是逆格雷码结果，也就是到 0 的最短距离。

正确性证明

引理：题目允许的状态转移与反射格雷码序列中相邻编号的转移完全一致。最低位总可翻转；更高位 i 只有在低位形态为 10…0 时可翻转，这正是格雷码递归反射边界的条件。

推论：状态 n 在该序列中的编号等于 n 的逆格雷码。序列是一条无捷径的路径，因此到编号 0 的最短距离就是该编号。

算法：格雷码位满足 g[i] = b[i+1] XOR b[i]，故 b[i] 是从最高位到 i 的所有 g 位异或。循环异或 n, n>>1, … 正好计算所有这些前缀位。因此算法返回的就是最少操作数。

边界与复杂度

  • n = 0：循环不执行，直接返回 0。
  • 只有一个最高位为 1：结果为 2k+1 - 1。
  • n = 109：仍只需约 30 轮。

时间复杂度：O(log n)；空间复杂度：O(1)。

四语言完整代码

JavaLeetCode 可提交
class Solution {
    public int minimumOneBitOperations(int n) {
        int answer = 0;
        while (n != 0) {
            answer ^= n;
            n >>= 1;
        }
        return answer;
    }
}

替代方案：最高位递归

若最高位是 2k，从该状态到 0 需要走完整段 2k+1 - 1；其余低位对应一段反向路径，因此：

f(n) = (2^(k+1) - 1) - f(n XOR 2^k)

递归同样是 O(log n)，但迭代逆格雷码更短、更不易写错，也没有递归调用。

常见错误

  • 把答案误当成 popcount(n)；高位翻转需要先精确布置低位。
  • 贪心清除最低位或最高位，却忽略第二条操作的前置条件。
  • 只计算 n XOR (n >> 1)；这是二进制转格雷码，方向反了。
  • JavaScript 用除法移位；本题范围可安全使用 32 位位运算，直接 >> 更清楚。

面试追问

  1. 为什么不会出现更短路径？ 尝试从“每个状态在合法转移图中的度数不超过 2”以及格雷码序列覆盖全部状态来回答。
  2. 怎样从答案重新得到 n？ 普通二进制编号 x 对应格雷码 x XOR (x >> 1)。
  3. 如果 n 扩大到 64 位？ Java/C++ 改用 64 位整数；JavaScript 可使用 BigInt 和 BigInt 位运算。
  4. 能否输出完整操作序列？ 可以按格雷码编号逐项生成，但输出规模本身可能等于答案，最坏呈指数级增长。
