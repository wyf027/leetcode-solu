1029Two City Scheduling
非付费题 · 返回 integer

题意

公司要安排 2n 人去 A、B 两座城市面试。costs[i] = [aCostᵢ, bCostᵢ] 表示第 i 人去两座城市各自的机票费用。请让恰好 n 人抵达 A、另外 n 人抵达 B，并求所有人的最低总费用。

函数签名

twoCitySchedCost(costs: integer[][]): integer

约束

  • 2 × n == costs.length
  • 2 <= costs.length <= 100
  • costs.length 为偶数
  • 1 <= aCostᵢ, bCostᵢ <= 1000
先别急着看题解
试着想：如果先假设所有人都去 B，怎样挑出最适合改去 A 的 n 个人？

02题解

核心洞察

定义差值 dᵢ = aCostᵢ − bCostᵢ。差值越小，说明相较于去 B，让这个人去 A 越省钱（或额外花费越少）。因此按差值升序排列，前 n 人去 A，剩余 n 人去 B。

等价视角：先让所有人去 B，得到基线费用；再选择 n 个最小的差值加回去。

完整过程

  1. 为每个人计算 A − B。
  2. 按差值从小到大排序。
  3. 排序后前一半累加 A 费用。
  4. 后一半累加 B 费用，返回总和。

正确性证明

考虑任意一个被安排去 B 的人 x 与被安排去 A 的人 y。若 dₓ < dᵧ，交换两人的城市后，费用变化为 dₓ − dᵧ < 0，总费用会下降，因此原安排不可能最优。最优安排必然让差值最小的 n 人去 A；排序算法恰好构造了这一安排，所以结果最优。

复杂度与边界

时间：O(m log m)，其中 m = costs.length。
空间：依语言排序实现，通常为 O(log m) 到 O(m)。

差值可相同，任意相对顺序都不影响总费用；所有费用相同、差值为负或为正都无需特殊处理；数组长度保证为偶数。

03四语言实现

import java.util.Arrays;

class Solution {
    public int twoCitySchedCost(int[][] costs) {
        Arrays.sort(costs, (x, y) ->
            Integer.compare(x[0] - x[1], y[0] - y[1]));
        int n = costs.length / 2;
        int total = 0;
        for (int i = 0; i < costs.length; i++) {
            total += i < n ? costs[i][0] : costs[i][1];
        }
        return total;
    }
}

from typing import List

class Solution:
    def twoCitySchedCost(self, costs: List[List[int]]) -> int:
        costs.sort(key=lambda cost: cost[0] - cost[1])
        n = len(costs) // 2
        return sum(costs[i][0] if i < n else costs[i][1]
                   for i in range(len(costs)))

替代方案

动态规划：dp[i][j] 表示处理前 i 人、其中 j 人去 A 的最低费用，可做但时间、空间更高。

最大流 / 最小费用流：能表达容量约束，适合推广到多城市或复杂配额；本题属于明显的过度设计。

面试追问

  • 为什么直接按 A 费用排序不成立？因为选择必须衡量放弃 B 的机会成本。
  • 若两城人数配额不是各一半？排序后取 A 配额数量即可。
  • 若扩展到三座城市？单一差值不再足够，可考虑 DP 或最小费用流。

常见错误

  • 按 aCost 或 bCost 单独排序，忽略相对代价。
  • 把差值排序方向写反，导致最适合去 B 的人占用 A 名额。
  • 没有严格分配各 n 人，只逐人选择更便宜城市。
  • Java 比较器直接做复杂减法可能溢出；本题范围安全，但通用代码宜用 Integer.compare。
