找到数据流中的
连续整数

Find Consecutive Integers from a Data Stream

整数逐个到达。每次收到一个数，你都要回答：最后 k 个数，是否全部等于 value？

先理解规则，再用时间轴观察每次返回值。实现与证明在页面底部，默认收起。

官方题目 ↗

01 / 题目与接口

  • DataStream(int value, int k)：记录目标值 value 和窗口长度 k，创建空数据流。
  • boolean consec(int num)：先把 num 加入数据流，再判断最后 k 个数是否全部等于 value，返回布尔值。
  • 已收到的数不足 k 个时，一律返回 false。“连续”指数据流中相邻出现，并非数值递增。

官方示例 · 完整调用参数

输入：
["DataStream", "consec", "consec", "consec", "consec"]
[[4, 3], [4], [4], [4], [3]]
输出：
[null, false, false, true, false]

构造器没有返回值，以 null 表示。前两次调用分别只有 1、2 个数；第三次末尾为 [4,4,4]，返回 true；第四次末尾为 [4,4,3]，返回 false。

约束

  • 1 ≤ value, num ≤ 10⁹
  • 1 ≤ k ≤ 10⁵
  • consec 至多调用 10⁵ 次。

思考：一个不匹配的数进入末尾窗口后，什么时候才可能再次得到 true？

04 / 题解工作区

准备好自己的思路后，再展开。

核心洞察：只记住末尾连续匹配的长度

窗口内部具体有哪些数并不重要。设 streak 为数据流末尾连续等于 value 的个数。如果它至少为 k，最后 k 个数必然全部匹配。遇到任何其他数，连续段立刻中断。

初始 streak = 0
收到 num：
  num == value → streak += 1
  否则         → streak = 0
返回 streak >= k

完整过程

  1. 构造时保存 value、k，并将 streak 置为 0。
  2. 每次调用先根据新数更新 streak，不能先返回旧状态。
  3. 比较 streak 与 k。不足 k 时返回 false；达到或超过 k 都返回 true。
  4. 不需要保存完整流或删除旧元素；计数描述的是末尾连续段。
调用streak 更新返回原因
构造 (4,3)0null空流
consec(4)0 → 1false1 < 3
consec(4)1 → 2false2 < 3
consec(4)2 → 3true3 ≥ 3
consec(3)3 → 0false末尾不匹配

正确性证明

不变式：每次调用结束，streak 恰好等于以当前末尾结尾、所有数都为 value 的最长连续段长度。空流时为 0，成立。若新数等于 value，原末尾连续段延长 1；否则任何匹配段都不能以该数结尾，长度归零。因此不变式一直成立。

若 streak ≥ k，则该连续段覆盖最后 k 个数，返回 true 正确。反过来，最后 k 个数若全等于 value，末尾连续段至少长 k，必有 streak ≥ k。收到的数不足 k 时，streak 不超过已收到数量，也一定返回 false。因此判定充要。

边界与复杂度

  • k = 1：只判断本次 num 是否匹配。
  • 连续匹配超过 k：仍返回 true，应使用 ≥，不能使用 ==。
  • 中途出现不匹配：归零，不是减一；后续须重新积累 k 次。
  • 最多 10⁵ 次调用，streak 至多 10⁵，四种语言的这些数值类型都足够。
  • 构造 O(1)，每次 consec 时间 O(1)，额外空间 O(1)；n 次调用共 O(n)。页面为回放保留数据并绘制窗口，其开销不代表提交算法。

四语言完整实现

Java

class DataStream {
    private final int value;
    private final int k;
    private int streak;

    public DataStream(int value, int k) {
        this.value = value;
        this.k = k;
        this.streak = 0;
    }

    public boolean consec(int num) {
        streak = num == value ? streak + 1 : 0;
        return streak >= k;
    }
}

class DataStream:

替代方案

  • 队列 + 不匹配计数：保留最后 k 个数，新数加入、旧数移出时更新不匹配数量。窗口已满且不匹配数量为 0 时返回 true。环形队列下每次 O(1)，空间 O(k)，适合需要保留窗口信息的扩展需求。
  • 最近不匹配位置：使用从 1 开始的调用序号 i，lastBad 初始为 0。遇到不匹配时令 lastBad = i，返回 i − lastBad ≥ k。同样每次 O(1) 时间、O(1) 空间。
  • 逐次扫描末尾 k 个数：最坏每次 O(k)，空间 O(k)，本题不需要这项重复工作。

常见错误

  • 累计所有等于 value 的数，忽略被其他数隔开的情况。
  • 使用 streak == k，导致第 k+1 个匹配数返回 false。
  • 遇到不匹配只减一，保留了已经失效的连续记录。
  • 只检查现有窗口内全相等，却漏掉元素总量必须达到 k。
  • 把连续整数理解为 4、5、6；题意要求每个整数都等于同一个 value。

面试追问

无限流如何防止计数溢出？固定 k 时可用 min(streak + 1, k) 饱和计数，超出阈值的精确长度不影响答案。

允许窗口内最多一个数不同呢？单个末尾长度不够，可维护不匹配位置队列，删除窗口外的位置，然后判断队列长度。

如果动态修改目标 value 呢？旧目标的 streak 不能回答新目标的历史窗口问题；应按查询需求保留窗口及频次，或明确修改后重新开始计数。
