01 · 理解题目

什么是“平衡”？

给定一个仅包含 0 和 1 的字符串 s。一个连续子字符串被称为平衡子字符串，当且仅当其中所有 0 都排在所有 1 之前，并且两种字符数量相等。

返回 s 中最长平衡子字符串的长度。空子字符串也算平衡，所以当不存在非空答案时返回 0。

子字符串必须连续；不能从原字符串中跳着选字符。

目标结构
0…01…1
0 的数量 = 1 的数量
1 
输入：s = "01000111"
输出：6
解释：最长平衡子字符串为
      "000111"。
2 
输入：s = "00111"
输出：4
解释：最长平衡子字符串为
      "0011"。
3 
输入：s = "111"
输出：0
解释：只有空子字符串满足条件。
1 ≤ s.length ≤ 50 s[i] ∈ {'0', '1'}

03 · 完整题解

一次扫描，维护相邻的两段

合法的非空答案必然是某个连续 0 段的后缀，加上紧随其后的连续 1 段的前缀。

核心洞察

只需统计当前相邻的 0 段长度 zero 与 1 段长度 one。两段能组成的最长平衡长度是 2 × min(zero, one)。

状态何时重置

扫描到 1 时继续增长当前 1 段；扫描到 0 且之前已经进入 1 段时，说明新一组相邻段开始，两个计数清零后再记录这个 0。

一句话算法：从左到右计数，在每个 1 到来时用 2 × min(zero, one) 更新答案。

完整过程

  1. 初始化 zero = 0、one = 0、answer = 0。
  2. 若当前字符为 0：当 one > 0 时先结束上一组并清零；随后令 zero + 1。
  3. 若当前字符为 1：令 one + 1，再用 2 × min(zero, one) 更新答案。
  4. 扫描结束后返回 answer。

正确性证明

  1. 候选的合法性：当前相邻段形如 0^zero 1^one。各取靠近边界的 min(zero, one) 个字符，就得到所有 0 在前、所有 1 在后且数量相同的连续子字符串。
  2. 候选的最优性：任何平衡子字符串只能跨越一个从 0 到 1 的边界；在该边界两侧，它最多分别取两段长度的较小值，因此长度不超过 2 × min(zero, one)。
  3. 覆盖全部边界：扫描会依次访问每组相邻的 0 段与 1 段，并在 1 段增长时更新答案。因此每个可能产生最优解的边界都被计算。

由合法性、上界和完整覆盖可知，最终答案正是最长平衡子字符串的长度。

边界情况

全是同一字符

缺少一侧字符，min(zero, one) = 0，答案保持 0。

以 1 开头

在出现首个 0 之前，zero = 0，不会产生错误候选。

1 比 0 多

多出的 1 无法配对，较小值仍是 zero。

多次 1 → 0

每次进入新的 0 段都重置计数，旧段不会与新段跨区拼接。

复杂度

O(n)时间：每个字符只访问一次。
O(1)空间：只维护三个整数。

四语言完整代码

Java
class Solution {
    public int findTheLongestBalancedSubstring(String s) {
        int zero = 0, one = 0, answer = 0;

        for (char c : s.toCharArray()) {
            if (c == '0') {
                if (one > 0) {
                    zero = 0;
                    one = 0;
                }
                zero++;
            } else {
                one++;
                answer = Math.max(answer, 2 * Math.min(zero, one));
            }
        }
        return answer;
    }
}

替代方案

枚举子字符串

枚举每个区间并判断是否平衡，容易想到，但朴素实现需要 O(n³) 时间；利用前缀统计也仍要 O(n²)。约束较小时可行，却没有必要。

按字符段分组

先把连续字符压缩成段长数组，再检查每个 0 段及其后的 1 段，同样是 O(n) 时间，但需要 O(n) 额外空间。一次扫描就是它的常数空间版本。

面试追问

如果要求返回子字符串本身？

更新最优长度时同时记录其起点；最终用起点和长度截取即可。

为什么不能用 0 和 1 的全局数量？

题目要求连续且顺序固定，全局数量会忽略字符被其他段隔开的事实。

能否推广到 a…ab…b？

可以。只要目标仍是两个固定字符的相邻连续段，计数逻辑完全相同。

流式输入可以处理吗？

可以。状态只依赖当前计数和历史答案，不需要保存完整字符串。

常见错误

  • 只检查 0 与 1 的总数相等，遗漏“所有 0 必须在 1 前面”。
  • 允许跳过中间字符，误把子序列当成子字符串。
  • 遇到 1 → 0 时没有重置，导致跨越多个字符段配对。
  • 返回配对数量 min(zero, one)，忘记答案是字符总长度，需要乘以 2。
