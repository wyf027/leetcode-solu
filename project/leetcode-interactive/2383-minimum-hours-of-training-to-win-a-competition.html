精力会消耗，经验会积累。面对一条固定的对手序列，你需要在出发前准备多少？

官方题目 ↗

01 / 题目规则

给定初始精力 initialEnergy、初始经验 initialExperience，以及长度均为 n 的数组 energy 和 experience。按下标从 0 到 n − 1 的顺序挑战对手，不能调整顺序。

  • 开战时，你的精力和经验必须分别严格大于对手对应的数值；相等也不能获胜。
  • 获胜后，精力减去 energy[i]，经验加上 experience[i]。
  • 全部训练都发生在比赛开始前。每训练 1 小时，只能选择让初始精力或初始经验增加 1。

返回击败全部对手所需的最少训练小时数，返回值为整数。

官方示例 1

initialEnergy = 5
initialExperience = 3
energy = [1,4,3,2]
experience = [2,6,3,1]
输出：8

赛前精力训练 6 小时、经验训练 2 小时，从 (11, 5) 出发；每场胜利后的 (精力, 经验) 依次为 (10, 7)、(6, 13)、(3, 16)、(1, 17)。总计 8 小时。

官方示例 2

initialEnergy = 2
initialExperience = 4
energy = [1]
experience = [3]
输出：0

2 > 1 且 4 > 3，无需训练就能击败唯一的对手。

约束

  • n == energy.length == experience.length
  • 1 <= n <= 100
  • 1 <= initialEnergy, initialExperience, energy[i], experience[i] <= 100

04 / 独立题解

准备好了再展开，包含推导与四语言实现。

核心洞察：分别补足，恰好越过门槛

两个资源互不影响，可以独立决定最少训练量再相加。设当前资源为 E、X，对手要求为 e、x：如果 E ≤ e，至少需要 e + 1 − E 小时；如果 X ≤ x，至少需要 x + 1 − X 小时。每次只补到严格大于对手的最小整数，然后结算比赛。

代码中的“临场补足”只是计算技巧。题目不允许在比赛中训练；把所有算出的补足量统一移到赛前，资源变化都是加减法，仍然可以完成同样的比赛。

完整过程

  1. 令累计训练 H = 0，当前精力 E = initialEnergy，当前经验 X = initialExperience。
  2. 按原顺序遍历对手。计算 dE = max(0, energy[i] + 1 − E)，dX = max(0, experience[i] + 1 − X)。
  3. 累计 H += dE + dX；执行 E += dE − energy[i]，X += dX + experience[i]。
  4. 全部对手处理完毕，返回 H。
示例 1 的计算过程（补足只是记账）
对手 i    开始 E,X    补精力,补经验    获胜后 E,X    累计 H
0         5,3        0,0              4,5           0
1         4,5        1,2              1,13          3
2         1,13       3,0              1,16          6
3         1,16       2,0              1,17          8

汇总：精力训练 6，经验训练 2。
真实比赛在赛前完成全部训练，从 E=11、X=5 出发。

为什么一定最优？

必要下界：用 Si 表示第 i 场之前消耗的精力之和，用 Pi 表示此前获得的经验之和。任何赛前训练量 TE、TX 都必须满足：

T_E ≥ energy[i] + 1 + S_i − initialEnergy
T_X ≥ experience[i] + 1 − P_i − initialExperience
T_E ≥ 0，T_X ≥ 0

达到下界：按场补足时，若当前资源不足，增加的恰好是新约束超过已有训练量的差值；若足够，就不增加。因此累计训练量始终是截至当前所有约束下界与 0 的最大值。遍历结束便分别达到两类资源的最小可行训练量。

可行性：把最终累计训练都提前到赛前，每一场的资源均满足上述约束。两个训练项目每小时只能二选一，因此总小时数是两个独立最小值之和，没有更小的方案。

复杂度与边界

  • 时间 O(n)，只遍历一次；额外空间 O(1)，只保存若干整数，不修改输入数组。
  • 资源相等也要补 1；无缺口时补 0；最后一场同样要严格大于。
  • 经验越打越多，但之后可能遇到更强对手，不能只检查第一场。
  • 本题正数约束下，精力训练最多 10000、经验训练最多 100，总答案最多 10100；四份代码中的整数表示均足够。

替代方案：精力求和，经验看前缀

精力一直减少且消耗为正，所以只需保证赛前精力大于总消耗：TE = max(0, sum(energy) + 1 − initialEnergy)。经验则扫描前缀和，求 max(0, maxi(experience[i] + 1 − Pi − initialExperience))。同样为 O(n) 时间、O(1) 空间。也能二分最小训练量并判定可行性，但此处直接求下界即可，无需额外的对数因子。

常见错误

  • 把 > 写成 ≥，漏掉 +1。
  • 精力获胜后做加法，或经验获胜后做减法。
  • 排序对手，改变题目规定的挑战顺序。
  • 以为一小时能同时增加两种资源，把训练小时数取最大值。
  • 只考虑经验的总和，忽略每场开战前的门槛。
  • 把计算时补足误当作比赛中真的允许训练，没有解释赛前等价性。

面试追问

为什么精力可以只看总和？每个消耗为正，完整前缀最大；赛前精力超过总和，就超过每个开战门槛。

允许改变顺序会怎样？精力总消耗不变，经验训练量却可能变化。例如初始经验 1，经验序列 [1,10] 需 9 小时，[10,1] 需 10 小时；不能直接照搬固定顺序的结论。

如果胜利还会损失经验？单调增长的直觉不再适用，需要重新写出每个前缀的资源约束；不能沿用本题经验最多训练 100 小时的界限。

Java

class Solution {
    public int minNumberOfHours(int initialEnergy, int initialExperience,
                                int[] energy, int[] experience) {
        int hours = 0;
        int e = initialEnergy, x = initialExperience;
        for (int i = 0; i < energy.length; i++) {
            int de = Math.max(0, energy[i] + 1 - e);
            int dx = Math.max(0, experience[i] + 1 - x);
            hours += de + dx;
            e += de - energy[i];
            x += dx + experience[i];
        }
        return hours;
    }
}

from typing import List

class Solution:
    def minNumberOfHours(self, initialEnergy: int, initialExperience: int,
                         energy: List[int], experience: List[int]) -> int:
        hours = 0
        e, x = initialEnergy, initialExperience
        for need_e, need_x in zip(energy, experience):
            de = max(0, need_e + 1 - e)
            dx = max(0, need_x + 1 - x)
            hours += de + dx
            e += de - need_e
            x += dx + need_x
        return hours

            x += dx + experience[i];
