1535. 找出数组游戏的赢家

数字排队上擂台：每回合队首两数较量，大者守擂，小者去队尾。谁先取得连续 k 胜，谁就是赢家。

题目说明

给定互不相同的整数数组 arr 和整数 k，返回游戏最终赢家。

游戏规则

比较数组前两个元素。较大的元素赢下本回合并留在下标 0；较小的元素移到数组末尾。

当某个元素连续赢得 k 回合时游戏结束。数据保证一定存在赢家。

约束

  • 2 ≤ arr.length ≤ 10⁵
  • 1 ≤ arr[i] ≤ 10⁶
  • arr 中的整数互不相同
  • 1 ≤ k ≤ 10⁹

示例 1

输入：arr = [2,1,3,5,4,6,7], k = 2
输出：5
解释：4 回合后，5 连续赢得 2 回合。

示例 2

输入：arr = [3,2,1], k = 10
输出：3
解释：3 连续赢得前 10 回合。

示例 3

输入：arr = [1,9,8,2,3,7,6,4,5], k = 7
输出：9

示例 4

输入：arr = [1,11,22,33,44,55,66,77,88,99],
      k = 1000000000
输出：99

核心洞察

01

队首就是当前冠军

每回合只需比较冠军与下一个挑战者，无需真的移动整个数组。

02

失败者暂时无关

较小值去队尾以后，冠军仍在最前；继续扫描原数组的下一个元素即可。

03

最大值是终点保险

全局最大值一旦成为冠军就不会再输，即使 k 极大也不必继续模拟。

完整过程

初始化：champion = arr[0]，wins = 0。
依次挑战：从 arr[1] 开始。冠军较大就将 wins 加一；否则挑战者成为新冠军，wins = 1。
提前结束：一旦 wins === k，返回当前冠军。
扫描结束：此时冠军一定是全局最大值，直接返回。

正确性证明

不变式：处理完 arr[i] 后，champion 是前缀 arr[0..i] 的最大值，wins 是它成为当前冠军后的连续胜场。

初始化：arr[0] 是长度为 1 的前缀最大值，尚无胜场，不变式成立。

保持：冠军胜出时仍是新前缀最大值且胜场加一；挑战者胜出时，它成为新前缀最大值，并已取得成为冠军的第一场胜利。

终止：胜场达到 k 时，规则直接认定当前冠军获胜。若扫描结束，冠军是全局最大值，此后永不失败，最终必达成所需连胜。因此返回值正确。

边界与复杂度

边界

  • k = 1：第一回合较大者立即获胜。
  • 首项为最大值：它一路守擂。
  • k ≥ arr.length：赢家一定是最大值。
  • k 可达 10⁹：不能逐回合硬模拟。

复杂度

时间：O(n)，每个元素至多挑战一次。

空间：O(1)，只记录冠军与连胜。

四种语言实现

均使用官方函数签名，代码区域可独立滚动。

JavaO(n) / O(1)
class Solution {
    public int getWinner(int[] arr, int k) {
        int champion = arr[0];
        int wins = 0;
        for (int i = 1; i < arr.length; i++) {
            if (champion > arr[i]) {
                wins++;
            } else {
                champion = arr[i];
                wins = 1;
            }
            if (wins == k) return champion;
        }
        return champion;
    }
}

替代方案与面试追问

替代：双端队列完整模拟每回合弹出前两项，赢家放回队首、输家放到队尾。它贴近题意，却可能随巨大 k 做无谓循环，并需要 O(n) 空间。
为什么扫描结束就能返回？所有元素都挑战过，留下的冠军就是全局最大值。它永远不会输，继续比赛只是累积必然到来的连胜。

如果允许重复值？

本题保证互异。若允许重复，必须先规定相等时谁赢，否则游戏规则不完整。

能否总是先求最大值？

不能。较小的 k 可能让非最大元素在最大值上场前提前获胜。

常见错误

新擂主连胜设为 0

挑战者刚刚已赢一场，成为新冠军时连胜应设为 1。

真的循环到 k 场

k 最大为 10⁹，到达最大值后必须利用其永不再输的性质。

答案总是最大值

k 较小时，前面的元素可能在最大值出场前就达成连胜。

移动整个数组

这样一次回合可能退化为 O(n)；只追踪冠军与连胜即可。
