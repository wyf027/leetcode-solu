Problem / 题意

逐层改写父子关系，返回新的树根

给定二叉树根节点 root，将整棵树上下翻转。对左链上的每一层：原左孩子接替当前位置，原父节点成为它的右孩子，原右孩子成为它的左孩子。题目保证每个右节点都有同父左兄弟，且右节点自身没有孩子。

Solution / 题解

先自己翻一次，再打开工艺图纸

核心洞察

左链是唯一会成为新主干的路径

走到每个 current 时，先保存 next = current.left。旧右孩子不能丢，它会在下一轮成为新左孩子；已经处理过的 parent 会成为新右孩子。

循环不变量

身后已翻好，手中保留右兄弟

每轮开始时，parent 是已翻转部分的根，carriedRight 是当前节点即将接到左侧的旧右孩子，current 仍指向未处理的左链节点。

完整过程

  1. 1. 保存 next = current.left，避免改指针后丢失下一层。
  2. 2. 让 current.left = carriedRight，接住旧右兄弟。
  3. 3. 先保存当前旧右孩子，再令 current.right = parent。
  4. 4. parent 与 current 同步前进；current 为空时 parent 就是新根。

边界

  • 空树返回 null。
  • 单节点没有左孩子，原样返回。
  • 纯左链时 carriedRight 一直为 null。
  • 必须先保存 next 和旧右孩子。

复杂度

O(n) 时间

O(1) 额外空间

只沿左链访问节点，原地改写指针。

替代方案

递归写法更短：先递归到最左节点，再在回溯时接线；但调用栈需要 O(h)，且忘记清空旧指针会造环。面试主线采用迭代版，状态更显式。

常见错误

  • 先覆盖 current.left，随后才找 next，导致剩余左链丢失。
  • 更新 carriedRight 的顺序错误，把刚改过的左指针当成旧右孩子。
  • 递归版本未把旧父节点左右指针清空，形成环。
  • 把本题误当成 226 翻转二叉树；本题不是交换每个节点左右子树。

面试追问

  • 如何证明 parent 最终一定是左下角节点？
  • 如果右节点也可能有孩子，原算法为什么不再安全？
  • 递归版的空间复杂度为什么是 O(h) 而不是 O(1)？
  • 怎样检测错误接线导致的环？

class Solution {
    public TreeNode upsideDownBinaryTree(TreeNode root) {
        TreeNode current = root;
        TreeNode parent = null;
        TreeNode carriedRight = null;

        while (current != null) {
            TreeNode next = current.left;
            current.left = carriedRight;
            carriedRight = current.right;
            current.right = parent;
            parent = current;
            current = next;
        }
        return parent;
    }
}
