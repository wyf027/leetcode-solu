三项属性每天只增不减。把“同时达标”拆成三个独立的首次达标日，再取最晚的那个。

题意 动手推演 题解

Problem

题意

游戏从第 0 天开始，文明等级 C、资源储备 R、人口数量 H 都是 0。

increase[i] 表示第 i + 1 天三项属性分别增加的值。对于每条剧情条件 [c, r, h]，找出最早满足 C ≥ c、R ≥ r、H ≥ h 的天数；若永远无法满足，返回 -1。

官方示例 1

increase =
[[2,8,4],[2,5,0],[10,9,8]]
requirements =
[[2,11,3],[15,10,7],[9,17,12],[8,1,14]]
输出 =
[2,-1,3,-1]

Constraints

约束与目标

  • 1 ≤ increase.length ≤ 10,000
  • 1 ≤ requirements.length ≤ 100,000
  • 0 ≤ increase[i][k] ≤ 10
  • 0 ≤ requirements[i][k] ≤ 100,000
需求数量最多十万。逐天尝试每条剧情会超时；我们需要利用“属性单调不减”做快速定位。

Spoiler gate

准备好查看完整题解了吗？

先自己想一想：为什么分别找到三个首次达标日后，要取最大值而不是最小值？

Solution

前缀和 + 三次二分

核心洞察

属性每天只会增加，所以 C、R、H 的累计数组都单调不减，天然适合 lower bound。

如何合并

分别得到首次满足 C、R、H 的天数 dC、dR、dH，同时达标的最早日就是 max(dC,dR,dH)。

失败条件

任一维度的最终累计值仍低于需求，这条剧情就永远不会触发，直接返回 -1。

完整过程

  1. 01 · 包含第 0 天

    建立长度 n + 1 的三组前缀数组，索引 0 的三项值都是 0。

  2. 02 · 累加每日增量

    第 day 天使用 increase[day - 1]，逐维加到前一天的累计值上。

  3. 03 · 三次 lower bound

    对一条需求的三个门槛，分别找第一处累计值大于等于门槛的位置。

  4. 04 · 合并答案

    任何一维找不到就返回 -1；否则返回三个位置中的最大值。

为什么一定正确？

对任意属性，累计值单调不减，因此 lower bound 找到的是该属性首次达到门槛的最早天数。早于 max(dC,dR,dH) 的任何一天，至少有一项尚未达标；到达这个最大值时，三项都已经达到各自门槛。所以它恰好是剧情最早触发日。若任一属性始终无法达到门槛，三项不可能同时满足，答案只能是 -1。

class Solution {
    public int[] getTriggerTime(int[][] increase, int[][] requirements) {
        int days = increase.length;
        int[][] prefix = new int[days + 1][3];

        for (int day = 1; day <= days; day++) {
            for (int attr = 0; attr < 3; attr++) {
                prefix[day][attr] = prefix[day - 1][attr]
                        + increase[day - 1][attr];
            }
        }

        int[] answer = new int[requirements.length];
        for (int i = 0; i < requirements.length; i++) {
            int triggerDay = 0;
            boolean possible = true;

            for (int attr = 0; attr < 3; attr++) {
                if (prefix[days][attr] < requirements[i][attr]) {
                    possible = false;
                    break;
                }

                int left = 0;
                int right = days;
                while (left < right) {
                    int mid = left + (right - left) / 2;
                    if (prefix[mid][attr] >= requirements[i][attr]) {
                        right = mid;
                    } else {
                        left = mid + 1;
                    }
                }
                triggerDay = Math.max(triggerDay, left);
            }

            answer[i] = possible ? triggerDay : -1;
        }
        return answer;
    }
}

var getTriggerTime = function (increase, requirements) {
  const days = increase.length;
  const prefix = Array.from({ length: days + 1 }, () => [0, 0, 0]);

  for (let day = 1; day <= days; day++) {
    for (let attr = 0; attr < 3; attr++) {
      prefix[day][attr] =
        prefix[day - 1][attr] + increase[day - 1][attr];
    }
  }

  return requirements.map((need) => {
    let triggerDay = 0;

    for (let attr = 0; attr < 3; attr++) {
      if (prefix[days][attr] < need[attr]) return -1;

      let left = 0;
      let right = days;
      while (left < right) {
        const mid = left + Math.floor((right - left) / 2);
        if (prefix[mid][attr] >= need[attr]) right = mid;
        else left = mid + 1;
      }
      triggerDay = Math.max(triggerDay, left);
    }

    return triggerDay;
  });
};
from bisect import bisect_left
from typing import List


class Solution:
    def getTriggerTime(
        self,
        increase: List[List[int]],
        requirements: List[List[int]],
    ) -> List[int]:
        days = len(increase)
        prefix = [[0] * (days + 1) for _ in range(3)]

        for day, delta in enumerate(increase, 1):
            for attr in range(3):
                prefix[attr][day] = prefix[attr][day - 1] + delta[attr]

        answer = []
        for need in requirements:
            trigger_day = 0
            for attr in range(3):
                day = bisect_left(prefix[attr], need[attr])
                if day == days + 1:
                    trigger_day = -1
                    break
                trigger_day = max(trigger_day, day)
            answer.append(trigger_day)

        return answer
#include <algorithm>
#include <vector>
using namespace std;

class Solution {
public:
    vector<int> getTriggerTime(
        vector<vector<int>>& increase,
        vector<vector<int>>& requirements
    ) {
        int days = static_cast<int>(increase.size());
        vector<vector<int>> prefix(3, vector<int>(days + 1, 0));

        for (int day = 1; day <= days; ++day) {
            for (int attr = 0; attr < 3; ++attr) {
                prefix[attr][day] =
                    prefix[attr][day - 1] + increase[day - 1][attr];
            }
        }

        vector<int> answer;
        answer.reserve(requirements.size());

        for (const auto& need : requirements) {
            int triggerDay = 0;
            bool possible = true;

            for (int attr = 0; attr < 3; ++attr) {
                auto it = lower_bound(
                    prefix[attr].begin(), prefix[attr].end(), need[attr]
                );
                if (it == prefix[attr].end()) {
                    possible = false;
                    break;
                }
                triggerDay = max(
                    triggerDay,
                    static_cast<int>(it - prefix[attr].begin())
                );
            }

            answer.push_back(possible ? triggerDay : -1);
        }
        return answer;
    }
};

Analysis

复杂度与边界

时间复杂度

O(n + m log n)

额外空间

O(n)

  • • 需求 [0,0,0] 在第 0 天触发。
  • • 每日增量可以为 0；非严格单调仍能 lower bound。
  • • 任一门槛超过最终累计值，返回 -1。
  • • 三维达标早晚不同，必须取首次达标日的最大值。

Trade-offs

替代方案

也可以对每个维度分别按门槛排序需求，随后按天推进累计属性，批量记录每条需求的首次达标日。总复杂度约为 O(n + m log m)。它避免逐条二分，但要维护需求原下标和三组结果，实现更复杂。固定三维时，前缀和加二分更清晰。

Interview follow-up

面试追问

如果属性允许减少呢？
累计序列不再单调，二分“首次达标”失效，需要改用事件扫描或更复杂的数据结构。
维度从 3 扩展为 d 呢？
为每个维度建立前缀数组并二分，最后取 d 个首次达标日中的最大值。
要在线追加天数呢？
每个维度的单调前缀数组可以持续追加，查询仍在当前数组范围内二分。

Pitfalls

常见错误

  • 忽略第 0 天，导致全零需求错答为第 1 天。
  • 把大于等于误写为严格大于。
  • 只比较三项总和，忘记每个属性都必须单独达标。
  • 把三个首次达标日取最小值，实际应该取最大值。
  • 二分未找到时仍返回末尾索引，没有输出 -1。
