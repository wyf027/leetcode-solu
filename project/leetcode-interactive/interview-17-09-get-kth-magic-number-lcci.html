Interview solution

题解

面试推荐：三指针动态规划。机制清楚、线性扫描、天然有序且无需哈希去重。

核心洞察

已知有序序列 dp 后，下一个合格数一定来自 dp[p3] × 3、dp[p5] × 5、dp[p7] × 7 的最小值。三个指针分别指向“尚未被该倍数用完”的最早位置。

若最小值同时来自多条轨道（例如 15 = 3 × 5 = 5 × 3）， 必须把命中的指针全部前移，而不是使用 else if。

完整过程

  1. 令 dp[0] = 1，三个指针都为 0。
  2. 计算三条轨道的当前候选。
  3. 取最小值写入 dp[i]。
  4. 所有候选等于该最小值的指针同时加一。
  5. 重复直到写出第 k 个数。

边界

  • k = 1 时直接返回基准值 1。
  • 重复来源必须同时推进，例如 15、21、35、45。
  • 官方页面未列数值范围；代码使用更宽的临时乘积类型降低中间溢出风险。
  • 题目函数签名要求整数答案，不处理非法的 k ≤ 0。

常见错误

  • 把 1 排除在序列之外，导致整体错一位。
  • 三个命中判断写成 if / else if，重复数再次入列。
  • 只判断最小值是否能整除 3、5、7，而不比较当前候选。
  • 暴力枚举正整数并分解素因子，无法利用有序生成结构。

复杂度

维度 结论
时间 O(k)，每轮常数次比较和推进
空间 O(k)，保存已生成的有序序列

替代方案取舍

最小堆 + 去重集合更容易扩展到任意因子集合，但需要 O(k log k) 时间和额外哈希空间。三队列方案同样可达 O(k)，不过队列入队规则更绕；面试中三指针最简洁。

面试追问

  • 若允许的因子变成动态数组，如何改造成堆或多指针？
  • 怎样证明不会漏掉任何 3^a5^b7^c？
  • 为什么命中多条轨道时必须全部推进？
  • 若只要求第 k 个值，能否把空间降到 O(1)？为什么困难？

正确性要点

归纳假设 dp[0..i-1] 是所有合格数中最小的前 i 个。任何下一合格数都可除去一个末尾因子 3、5 或 7，得到已在前缀中的更小合格数，因此一定出现在三条候选轨道上；取三者最小即不会漏数或乱序。

class Solution {
    public int getKthMagicNumber(int k) {
        int[] dp = new int[k];
        dp[0] = 1;
        int p3 = 0, p5 = 0, p7 = 0;

        for (int i = 1; i < k; i++) {
            long next3 = (long) dp[p3] * 3;
            long next5 = (long) dp[p5] * 5;
            long next7 = (long) dp[p7] * 7;
            long next = Math.min(next3, Math.min(next5, next7));
            dp[i] = (int) next;

            if (next == next3) p3++;
            if (next == next5) p5++;
            if (next == next7) p7++;
        }
        return dp[k - 1];
    }
}
