LC 1419 / 数青蛙

听见重叠的 croak，数出最少的青蛙。

声音混在一起，但每只青蛙都必须严格唱完 c → r → o → a → k。先亲手推进字符流，再决定是否揭开题解。

Problem

题目说明

返回完成全部蛙鸣所需的最少青蛙数

准确转述

给定字符串 croakOfFrogs，它是若干只青蛙发出的字符串 croak 的交错组合。多只青蛙可以同时鸣叫，所以不同蛙鸣的字符可能相互穿插。

每次有效蛙鸣必须依次出现 c、r、o、a、k，并完整结束。请返回解释整段声音至少需要多少只不同的青蛙；若无法拆成若干个有效的 croak，返回 -1。

约束

  • 1 ≤ croakOfFrogs.length ≤ 10⁵
  • 字符串只含 'c'、'r'、'o'、'a'、'k'。

官方示例

输入：croakOfFrogs = "croakcroak"
输出：1

示例 2
输入：croakOfFrogs = "crcoakroak"
输出：2

输出：-1
无法拆成完整、顺序正确的蛙鸣。

Solution

一次扫描，维护发声阶段

核心洞察：每个字符都必须接在前一阶段之后。记录正处于 c、r、o、a 四个未完成阶段的数量；遇到 k 时，一只青蛙完成并可被复用。扫描时的最大并发数，就是最少青蛙数。

完整过程

映射阶段

令 croak 的下标为 0..4。计数数组 count[i] 表示最后发出该阶段字符的蛙鸣数。

验证前驱

遇到非 c 字符时，其前一阶段计数必须大于 0，否则没有青蛙能合法发出当前字符，立即返回 -1。

迁移状态

遇到 c，新蛙鸣开始，并发数加一；遇到 r/o/a/k，将一只青蛙从前一阶段移到当前阶段；遇到 k 后并发数减一。

记录峰值并收尾

持续更新最大并发。扫描结束后，并发必须为 0，否则存在未唱完的 croak；合法时返回峰值。

正确性与边界

合法性

算法仅允许 c 开始新蛙鸣；每个 r/o/a/k 都消耗一个紧邻前驱阶段，因此被接受的每条字符链一定严格构成 croak。扫描结束要求无未完成链，所以所有蛙鸣完整。

最优性

任一时刻，每条未完成链都必须由不同青蛙发出，因此峰值并发是必要下界。完成 k 的青蛙立即可复用，算法始终只在 c 出现时占用一只青蛙，恰好达到该下界。

边界情况

首字符不是 c、阶段跳跃、某阶段数量透支、结尾仍有未完成鸣叫都返回 -1。单个 croak 返回 1；连续多个完整 croak 可由同一只青蛙完成。

复杂度

只扫描字符串一次，时间复杂度 O(n)。计数数组固定长度为 5，额外空间复杂度 O(1)。

替代方案

可以只维护四个前缀余额，例如要求任意前缀始终满足 c ≥ r ≥ o ≥ a ≥ k，并用“已开始减已结束”得到并发量。它与状态迁移本质相同。也可以显式维护每只青蛙的当前字符，但查找可接续青蛙更繁琐，若实现不当会退化到 O(n²)。

class Solution {
    public int minNumberOfFrogs(String croakOfFrogs) {
        String word = "croak";
        int[] count = new int[5];
        int active = 0, answer = 0;

        for (char ch : croakOfFrogs.toCharArray()) {
            int stage = word.indexOf(ch);
            if (stage == 0) {
                count[0]++;
                active++;
                answer = Math.max(answer, active);
            } else {
                if (stage == -1 || count[stage - 1] == 0) return -1;
                count[stage - 1]--;
                count[stage]++;
                if (stage == 4) {
                    count[4]--;
                    active--;
                }
            }
        }
        return active == 0 ? answer : -1;
    }
}

面试追问

为什么答案是最大并发，而不是 c 的总数？

已完成 k 的青蛙可以继续发出新的 c，因此顺序出现的多次 croak 能复用同一只青蛙；只有时间上重叠的未完成鸣叫才要求不同青蛙。

能否不用五个计数？

可以维护 c/r/o/a 四个未完成阶段，k 只负责结束；甚至可用相邻前缀差表示各阶段。但固定长度数组更直观，空间仍为 O(1)。

如果目标单词不是 croak 呢？

对无重复字符的固定目标词，可直接推广状态数组。若目标词自身有重复字符，就不能只用 indexOf 判断阶段，需要按状态可用性选择合法前驱，或使用自动机。

常见错误

  • 只检查总字符频次相等，忽略顺序非法，例如某个 r 出现在可用 c 之前。
  • 把 c 的总数当成青蛙数，忘记完成后的青蛙可以复用。
  • 没有在结尾检查仍在 c/r/o/a 阶段的未完成鸣叫。
  • 只判断局部前驱存在，却忘记消耗前驱计数，导致同一只青蛙被重复匹配。
