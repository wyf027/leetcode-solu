有时间限制的 Promise 对象

Promise Time Limit

给异步函数套上一段等待期限：函数及时完成，就沿用它的结果；等待超过期限，就以指定字符串拒绝。先观察行为，再决定如何实现。

JavaScript异步编程Promise非付费题

Problem

题意

给定异步函数 fn 和毫秒数 t，返回一个新的限时函数。调用新函数时，应把收到的全部参数原样传给 fn。

  • 若 fn 在 t 毫秒内完成，新函数以相同结果兑现；若 fn 先拒绝，也应保留原拒绝原因。
  • 若等待超过 t 毫秒，新函数以字符串 "Time Limit Exceeded" 拒绝。
官方函数形式： var timeLimit = function(fn, t) { return async function(...args) { /* ... */ }; };

Examples

官方示例

示例 1 · 超时

fn = async (n) => {
  await new Promise(res => setTimeout(res, 100));
  return n * n;
}
inputs = [5]
t = 50

输出：{"rejected":"Time Limit Exceeded","time":50}

原函数约 100ms 才完成，而等待上限是 50ms，因此限时函数约在 50ms 拒绝。

示例 2 · 正常兑现

fn = async (n) => {
  await new Promise(res => setTimeout(res, 100));
  return n * n;
}
inputs = [5]
t = 150

输出：{"resolved":25,"time":100}

原函数约在 100ms 返回 25，早于 150ms 的限制。

示例 3 · 多参数

fn = async (a, b) => {
  await new Promise(res => setTimeout(res, 120));
  return a + b;
}
inputs = [5, 10]
t = 150

输出：{"resolved":15,"time":120}

两个实参都被传给原函数，结果 15 在限制前产生。

示例 4 · 原错误

fn = async () => {
  throw "Error";
}
inputs = []
t = 1000

输出：{"rejected":"Error","time":0}

原函数立即拒绝，因此保留原始原因，不改写成超时错误。

Constraints

约束

  • 0 <= inputs.length <= 10
  • 0 <= t <= 1000
  • fn 返回一个 Promise 对象。

Core Insight

让原 Promise 与超时 Promise 竞争

创建一个在 t 毫秒后以固定字符串拒绝的 Promise，再用 Promise.race 取得两者中最先落定的结果。原任务若先兑现或拒绝，结果都会原样传播；计时器若先触发，则得到超时拒绝。

01

启动计时

构造超时 Promise，并保存计时器标识。

02

同时等待

把 fn(...args) 与超时 Promise 放入竞争。

03

清理计时器

竞争结束后取消尚未触发的定时任务，避免无谓等待。

完整过程

  1. timeLimit(fn, t) 返回一个异步包装函数，并通过剩余参数接收任意数量的实参。
  2. 每次调用包装函数时，单独创建一个计时器和超时 Promise，保证并发调用互不干扰。
  3. 调用 fn(...args)，与超时 Promise 一起交给 Promise.race。
  4. 等待最先落定者；无论成功还是拒绝，finally 都清除本次计时器。

正确性说明

情形最先落定者包装函数结果
fn 在限制前兑现原 Promise 兑现竞争以同一值兑现，符合要求。
fn 在限制前拒绝原 Promise 拒绝竞争以同一原因拒绝，保留原错误。
fn 超过限制仍未完成超时 Promise 拒绝竞争以 "Time Limit Exceeded" 拒绝。

这三种情形覆盖了原 Promise 在期限前兑现、期限前拒绝和期限内仍挂起的所有可能。因此返回函数始终满足题意。

边界与语义

  • t = 0：计时器会尽快排入任务队列；已经兑现的 Promise 回调属于微任务，可能先于零延时计时器执行。
  • 原函数立即抛错：异步包装函数会把同步抛错转成拒绝，并在 finally 中清理计时器。
  • 不会取消原任务：Promise.race 只决定调用者看到的结果。超时后，fn 仍可能在后台继续；通用取消需要原函数主动支持 AbortSignal 等协议。
  • 重复调用：每次调用都拥有自己的 Promise 竞争和计时器，不共享状态。

复杂度

除原函数自身消耗外，每次调用只创建固定数量的 Promise 和一个计时器，额外时间开销为 O(1)，额外空间为 O(1)。

提交语言说明：官方元数据仅提供 JavaScript / TypeScript 签名。JavaScript 可直接按官方签名提交；Java、Python、C++ 是等价等待语义的本地参考，不是本题平台提交模板。
JavaScript · 官方可提交 
/**
 * @param {Function} fn
 * @param {number} t
 * @return {Function}
 */
var timeLimit = function(fn, t) {
  return async function(...args) {
    let timer;
    const timeout = new Promise((_, reject) => {
      timer = setTimeout(() => reject("Time Limit Exceeded"), t);
    });

    try {
      return await Promise.race([fn(...args), timeout]);
    } finally {
      clearTimeout(timer);
    }
  };
};
Java · 本地语义参考（Java 9+） 
import java.util.concurrent.CompletableFuture;
import java.util.concurrent.CompletionException;
import java.util.concurrent.TimeUnit;
import java.util.concurrent.TimeoutException;

public class Solution {
  @FunctionalInterface
  public interface AsyncFn {
    CompletableFuture<Object> apply(Object... args);
  }

  public static AsyncFn timeLimit(AsyncFn fn, long t) {
    return args -> fn.apply(args)
        .orTimeout(t, TimeUnit.MILLISECONDS)
        .handle((value, error) -> {
          if (error == null) return value;

          Throwable cause = error instanceof CompletionException
              ? error.getCause()
              : error;
          if (cause instanceof TimeoutException) {
            throw new CompletionException(
                new RuntimeException("Time Limit Exceeded"));
          }
          throw new CompletionException(cause);
        });
  }
}
Python · 本地语义参考（Python 3.8+） 
import asyncio
from functools import wraps


def time_limit(fn, t):
    @wraps(fn)
    async def limited(*args):
        task = asyncio.create_task(fn(*args))
        try:
            return await asyncio.wait_for(
                asyncio.shield(task),
                timeout=t / 1000,
            )
        except asyncio.TimeoutError as exc:
            raise RuntimeError("Time Limit Exceeded") from exc

    return limited
C++ · 本地语义参考（C++17） 
#include <chrono>
#include <exception>
#include <future>
#include <functional>
#include <stdexcept>
#include <thread>
#include <tuple>
#include <type_traits>
#include <utility>

template <class F>
auto timeLimit(F fn, std::chrono::milliseconds limit) {
  return [fn = std::move(fn), limit](auto&&... args) mutable {
    using Result = std::invoke_result_t<F&, decltype(args)...>;
    std::promise<Result> promise;
    auto result = promise.get_future();

    std::thread(
        [fn, promise = std::move(promise),
         values = std::make_tuple(
             std::forward<decltype(args)>(args)...)]() mutable {
          try {
            if constexpr (std::is_void_v<Result>) {
              std::apply(fn, std::move(values));
              promise.set_value();
            } else {
              promise.set_value(std::apply(fn, std::move(values)));
            }
          } catch (...) {
            promise.set_exception(std::current_exception());
          }
        })
        .detach();

    if (result.wait_for(limit) != std::future_status::ready) {
      throw std::runtime_error("Time Limit Exceeded");
    }
    if constexpr (std::is_void_v<Result>) {
      result.get();
    } else {
      return result.get();
    }
  };
}

替代方案

  • 手写新 Promise：在构造器中启动计时器，并用 fn(...args).then(resolve, reject) 转发结果。它可行，但要在成功、失败和同步抛错路径正确清理计时器，分支更多。
  • AbortController：仅当原函数接受并响应 AbortSignal 时，才能在超时后真正中止底层工作；这超出了题目给定的通用函数契约。

面试追问

  • 超时后如何真正取消网络请求？让 fn 接收 AbortSignal。
  • 怎样区分超时和业务错误？生产代码可拒绝专用 TimeoutError，但本题必须使用指定字符串。
  • 并发调用是否安全？是，每次调用都创建独立计时器和竞争。

常见错误

  • 超时时返回字符串而不是拒绝 Promise。
  • 丢失 ...args，导致多参数示例失败。
  • 把原函数的业务拒绝统一改成超时错误。
  • 认为竞争结束会自动取消原异步任务。
  • 所有调用共享同一个计时器，产生相互干扰。
