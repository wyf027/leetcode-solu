01 / 读懂时间

给定长度同为 n 的整数数组 plantTime 和 growTime，下标从 0 开始。第 i 枚种子需要你累计劳动 plantTime[i] 个完整天才算播种完成。这些天可以不连续，但每天只能给一枚种子播种。

种子完全种好后，独立生长 growTime[i] 个完整天，随后开花且永不凋谢。种子的生长可以互相重叠，也可以与你播种其他种子的时间重叠。从第 0 天开始安排，返回全部种子都已开花的最早日期。

日期按时间边界计算：播种 1 天占用区间 [0,1)，再生长 1 天占用 [1,2)，因此第 2 天开花。不是第 1 天，也不额外加一天。

参数与约束

  • earliestFullBloom(plantTime, growTime) → integer
  • n == plantTime.length == growTime.length
  • 1 ≤ n ≤ 105
  • 1 ≤ plantTime[i], growTime[i] ≤ 104

官方示例（完整参数）

示例 1

plantTime = [1,4,3]
growTime = [2,3,1]
输出：9

按 0 → 1 → 2 播种，分别在第 1、5、8 天完成播种，第 3、8、9 天开花。全部开花在第 9 天。

示例 2

plantTime = [1,2,3,2]
growTime = [2,1,2,1]
输出：9

一种安排：种子 0 在第 1 天播种；种子 1 在第 0、3 天；种子 2 在第 2、4、5 天；种子 3 在第 6、7 天。开花日期为 4、5、8、9。

示例 3

plantTime = [1]
growTime = [1]
输出：2

第 0 天播种，第 1 天生长，第 2 天开花。

04 / 留一点思考空间

哪些时间可以重叠？交换两枚种子的顺序，会影响后面种子的播种起点吗？

题解 / 让等待最长的种子先出发

核心洞察

按 growTime 从大到小播种。生长不占用播种资源，所以优先启动最长的生长过程，让它与后续播种重叠。不要按播种耗时排序，也不要把全部生长耗时相加。

维护累计播种时间 planted，播种一枚后更新 answer = max(answer, planted + growTime[i])。答案取所有开花日期的最大值，不一定是最后播种的那一枚。

使用当前已应用的数据，更新顺序并回到第 0 天。

完整过程 · 官方示例 1

  1. 种子 0、1、2 的生长时间分别为 2、3、1；选择顺序 1 → 0 → 2。
  2. 种子 1：累计播种 4 天，开花日期 4 + 3 = 7，当前最晚为 7。
  3. 种子 0：累计播种 5 天，开花日期 5 + 2 = 7，当前最晚仍为 7。
  4. 种子 2：累计播种 8 天，开花日期 8 + 1 = 9，当前最晚为 9。
  5. 返回 9。官方示例给出的 0 → 1 → 2 也能达到 9，最优顺序不要求唯一。

正确性证明

第一步：连续播种不会更差。

取任意允许交错播种的日程，将种子按播种完成时间排序为 i₁,…,iₙ。第 k 枚完成时，至少已经做完前 k 枚种子的全部播种工作，所以它的完成时间 Cₖ ≥ Σⱼ₌₁ᵏ plantTime[iⱼ]。现在按此顺序无空闲、连续播种，每枚种子的完成时间都不晚于原日程，开花也不会更晚。因此只需考虑连续播种的排列。

第二步：相邻逆序交换不会更差。

设相邻种子为 a、b，生长时间 gₐ < gᵦ，之前累计播种时间为 T，播种时间为 pₐ、pᵦ。原顺序 a → b 的两枚最晚开花时间：

M = max(T + pₐ + gₐ, T + pₐ + pᵦ + gᵦ)

交换后 b → a 的两个开花日期都不超过 M：

T + pᵦ + gᵦ ≤ T + pₐ + pᵦ + gᵦ ≤ M
T + pᵦ + pₐ + gₐ ≤ T + pₐ + pᵦ + gᵦ ≤ M

前面的种子不受影响；这两枚的总播种时间没变，后面的种子也不受影响。反复交换所有生长时间逆序对，就得到生长期非递增顺序，答案不增，因此该顺序最优。

第三步：扫描正确计算答案。

每次处理后，planted 恰为该种子的播种完成时间；answer 始终是已处理种子开花日期的最大值。遍历全部种子后，answer 正是全部开花日期，结合最优顺序即得全局最优答案。

边界与复杂度

  • 只有一枚种子：返回 plantTime[0] + growTime[0]。
  • 生长时间相同：相互顺序任意，不需要特殊的第二排序键。
  • 总播种时间最多 10⁹，答案最多 1,000,010,000；Java / C++ 的 32 位有符号整数可容纳，JavaScript 的整数精度也足够。
  • 四份实现都排序种子下标，保留原数组和两组时间的对应关系。
  • 时间复杂度 O(n log n)；额外空间 O(n)，用于下标数组和排序所需空间。

替代方案与适用范围

  • 桶聚合：已知生长时间上限 U = 10⁴，可把相同生长期的播种时间累加到桶里，再按生长期从大到小扫描非空桶。相同生长期中最后播种完成者决定该组的最晚开花时间。时间 O(n + U)，空间 O(U)。
  • 全排列：对每个顺序计算最晚开花日期，时间 O(n! · n)，仅适合很小规模的理解或后续对拍，不能处理官方上限。
  • 二分日期：给定目标日 D，每枚种子的播种截止时间为 D − growTime[i]。按截止时间升序检查累计播种时间是否超限，顺序仍是生长期降序；可行但多了二分过程，本题直接扫描更简洁。

常见错误

  • 把生长期升序排列：会让长生长过程启动太晚。例如 p=[2,1]、g=[1,5]，顺序 0 → 1 得 8，顺序 1 → 0 得 6。
  • 将 planted 加上 growTime：生长与后续播种并行，累计变量只加播种耗时。
  • 只返回最后一枚开花日期：例如 p=[1,1]、g=[10,1]，正确答案为 11，而最后种下的种子第 3 天已开花。
  • 分别排序两个数组：会破坏同一枚种子的耗时配对。
  • 在 planted + growTime[i] 后额外加 1：混淆了完整天区间与日期边界。
  • 看到题面允许中断，就尝试复杂的抢占调度：连续化论证表明不需要它。

Java

import java.util.Arrays;

class Solution {
    public int earliestFullBloom(int[] plantTime, int[] growTime) {
        int n = plantTime.length;
        Integer[] order = new Integer[n];
        for (int i = 0; i < n; i++) order[i] = i;
        Arrays.sort(order, (a, b) -> Integer.compare(growTime[b], growTime[a]));
        int planted = 0, answer = 0;
        for (int i : order) {
            planted += plantTime[i];
            answer = Math.max(answer, planted + growTime[i]);
        }
        return answer;
    }
}

var earliestFullBloom = function(plantTime, growTime) {
    const order = Array.from({length: plantTime.length}, (_, i) => i);
    order.sort((a, b) => growTime[b] - growTime[a]);
    let planted = 0, answer = 0;
    for (const i of order) {
        planted += plantTime[i];
        answer = Math.max(answer, planted + growTime[i]);
    }
    return answer;
};

C++

#include <algorithm>
#include <numeric>
#include <vector>
using namespace std;

class Solution {
public:
    int earliestFullBloom(vector<int>& plantTime, vector<int>& growTime) {
        vector<int> order(plantTime.size());
        iota(order.begin(), order.end(), 0);
        sort(order.begin(), order.end(), [&](int a, int b) {
            return growTime[a] > growTime[b];
        });
        int planted = 0, answer = 0;
        for (int i : order) {
            planted += plantTime[i];
            answer = max(answer, planted + growTime[i]);
        }
        return answer;
    }
};

面试追问

  • 若有多个播种工人？单机相邻交换证明不能直接覆盖并行分配问题，需要重新建模，不能简单沿用本算法。
  • 若生长也占用同一位工人？并行假设消失；若全部工作都独占同一资源，完成总时间就是所有播种与生长时间之和。
  • 如何返回具体日程？保存排序后的下标及每次累计时间，种子 i 的播种区间是 [此前累计时间, 当前累计时间)，开花日为当前累计时间 + gᵢ。
  • 为什么不按 pᵢ + gᵢ 排序？交换论证比较的是后置生长期；播种耗时只贡献双方相同的总占用，不决定应优先谁。
