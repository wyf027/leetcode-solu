替换子串得到平衡字符串

找到最短的连续片段：只要允许把它替换成同长度的任意字符串，剩余部分就能被补齐为 Q、W、E、R 各占四分之一。

中等字符串滑动窗口非会员题
Problem

题目描述

函数：balancedString(s)

给定字符串 s，长度为 n，且只包含 'Q'、'W'、'E'、'R'。当四种字符都恰好出现 n / 4 次时，称字符串是平衡的。

你可以选择一个连续子串，用任意一个长度相同的字符串替换它。返回能使整个字符串平衡的待替换子串的最小长度；若 s 已经平衡，返回 0。

Full Solution

滑动窗口题解

核心洞察：真正需要检查的不是窗口里放什么，而是窗口外留下什么。只要窗口外 Q、W、E、R 的数量都不超过 n / 4，窗口内就能被重新填写，补足所有缺口。

完整过程

  1. 统计整串四种字符的数量，令目标值 target = n / 4。
  2. 若所有计数已不超过 target，字符串已经平衡，返回 0。
  3. 把计数数组解释为“当前窗口外”的计数。右端点纳入窗口时，从计数中减去该字符。
  4. 当窗口外全部计数不超过 target，记录窗口长度，并持续右移左端点以尝试缩短。
  5. 左端点移出窗口时，把对应字符加回窗口外计数。

边界处理

  • 已经平衡：必须直接返回 0，不能误判为长度 1。
  • 同一种字符占满字符串：答案可能达到 3n / 4。
  • 最短窗口可能位于开头、结尾或中间。
  • 窗口收缩条件要同时检查四种字符。

正确性证明

  1. 可行性等价。 若某窗口可被替换后得到平衡串，那么窗口外每种字符必不超过 target，否则无论窗口内填什么都无法减少窗口外的超额字符。反过来，若窗口外每种字符均不超过 target，则每种字符距 target 的缺口总和恰等于窗口长度，因此可在窗口中填入这些缺口，得到平衡串。
  2. 窗口枚举完整。 右指针从左到右遍历所有可能右端点。每个右端点下，左指针只在窗口可行时右移，并记录收缩过程中遇到的每个可行窗口，直到再收缩就不可行。
  3. 最优性。 对每个右端点，算法取得该阶段能达到的最小可行窗口；所有右端点都被处理，因此全局记录值不大于任意可行窗口。结合记录值自身可行，它就是最短替换长度。

class Solution {
    public int balancedString(String s) {
        int n = s.length();
        int target = n / 4;
        int[] count = new int[128];
        for (char c : s.toCharArray()) count[c]++;

        if (valid(count, target)) return 0;

        int answer = n;
        int left = 0;
        for (int right = 0; right < n; right++) {
            count[s.charAt(right)]--;
            while (left <= right && valid(count, target)) {
                answer = Math.min(answer, right - left + 1);
                count[s.charAt(left)]++;
                left++;
            }
        }
        return answer;
    }

    private boolean valid(int[] count, int target) {
        return count['Q'] <= target && count['W'] <= target
            && count['E'] <= target && count['R'] <= target;
    }
}

var balancedString = function(s) {
    const n = s.length;
    const target = n / 4;
    const count = { Q: 0, W: 0, E: 0, R: 0 };
    for (const char of s) count[char]++;

    const valid = () =>
        count.Q <= target && count.W <= target &&
        count.E <= target && count.R <= target;

    if (valid()) return 0;

    let answer = n;

        while (left <= right && valid()) {
            answer = Math.min(answer, right - left + 1);
            count[s[left]]++;
            left++;
        }
    }
    return answer;
};

class Solution:
    def balancedString(self, s: str) -> int:
        n = len(s)
        target = n // 4
        count = Counter(s)

        def valid() -> bool:
            return all(count[c] <= target for c in "QWER")

        if valid():
            return 0

        answer = n
        left = 0
        for right, char in enumerate(s):
            count[char] -= 1
            while left <= right and valid():
                answer = min(answer, right - left + 1)
                count[s[left]] += 1
                left += 1

        return answer

替代方案

可用前缀计数配合二分答案：对固定长度检查是否存在覆盖全部超额字符的窗口，时间复杂度 O(n log n)、空间复杂度 O(n) 或优化为 O(1) 额外计数。它更容易从“判定长度”出发推导，但不如双指针直接。

常见错误

  • 要求窗口内计数恰好等于超额量；窗口可以更长，替换内容也可以补其他字符。
  • 只检查总超额字符数，没有逐字符检查窗口是否覆盖。
  • 移动左端点时忘记把字符加回“窗口外”计数。
  • 没有提前处理已平衡字符串，最终错误返回 1。

面试追问

  • 为什么“窗口外不超标”足以保证一定能填写窗口？
  • 若字符种类从 4 种扩展到 k 种，复杂度如何变化？
  • 若 n 不是字符种类数的倍数，怎样重新定义“尽量平衡”？
  • 能否输出一个实际的替换后字符串，而不仅是最短长度？

延伸理解

这类题的关键转换是把“修改窗口内部”改写为“保留窗口外部”。替换内容是自由变量，窗口外才是不允许改变的约束。类似思路也常见于最短覆盖、删除一段使剩余满足限制等问题。
