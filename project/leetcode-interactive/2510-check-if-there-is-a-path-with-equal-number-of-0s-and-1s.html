检查是否有路径经过
相同数量的 0 和 1

Check if There is a Path With Equal Number of 0's And 1's

从左上角走到右下角，只能向右或向下。能否找到一条路径，让经过的 0 和 1 一样多？先独立思考，再展开页面底部的题解与演示。

01 / PROBLEM

题意与接口

给定下标从 0 开始的二进制矩阵 grid，大小为 m × n。从 (0, 0) 出发，每次走到下方 (row + 1, col) 或右方 (row, col + 1) 的相邻格子，且不能越界。在到达 (m − 1, n − 1) 的路径中，只要有一条经过的 0、1 数量相同，就返回 true；否则返回 false。起点与终点都计入。

isThereAPath(grid: integer[][]) → boolean

约束

  • m == grid.length
  • n == grid[i].length，每行长度相同。
  • 2 ≤ m, n ≤ 100
  • grid[i][j] 只能是 0 或 1。

官方示例 1

输入：grid = [[0,1,0,0],[0,1,0,0],[1,0,1,0]]
输出：true

例如沿坐标 (0,0) → (0,1) → (1,1) → (2,1) → (2,2) → (2,3)，经过值为 0、1、1、0、1、0，两种值各有 3 个。

官方示例 2

输入：grid = [[1,1,0],[0,0,1],[1,0,0]]
输出：false

不存在满足两种值数量相同的路径。

03 / SOLUTION

准备好再揭晓

核心洞察：记录数量，不记录整条路径

每条路径恰好经过 L = m + n − 1 个格子。若 L 是奇数，不能平均分成 0 和 1，直接返回 false。否则令 T = L / 2：问题等价于“是否有一条路径经过恰好 T 个 1”。

到达同一个格子的不同路径可能含有不同数量的 1，不能只保留“是否到达”。用 S[i][j] 保存到达此格时可能的 1 的数量；从上方和左方的集合出发，统一加上当前格子的值，再合并去重。超过 T 的数量可以丢弃，因为后续数量不会减少。

S[0][0] = { grid[0][0] }
S[i][j] = { k + grid[i][j] | k ∈ S[i-1][j] ∪ S[i][j-1],
                             k + grid[i][j] ≤ T }
答案 = T ∈ S[m-1][n-1]

越界的前驱视为空集合；起点单独初始化。实现用布尔数组表示集合，并按行滚动保存。

STATE FLOW / 可达数量合流

看见每一格的状态集合

青色粗边是当前格，金色虚线是它的前驱。格子底部显示可达的 1 的数量。下方数量带同步显示当前集合，金框标出目标 T。

教学演示限 2～8 行、2～8 列，元素仅 0/1；下方提交代码支持官方上限 100。修改后点击“载入矩阵”。

完整过程与正确性

  1. 计算 L；奇数长度立即拒绝，偶数长度设置 T。
  2. 为每列维护长度 T+1 的布尔数组。处理格子前，dp[j] 仍是上方状态，dp[j-1] 已是本行左方状态。
  3. 创建全新的 cur。起点只置其对应计数为真；其余格子将有效前驱的计数加上当前值。
  4. 用 cur 替换 dp[j]，遍历到终点后返回 dp[n-1][T]。

归纳证明

起点仅有包含自己的路径，初始集合精确。假设上方与左方状态精确：每条到达当前格的路径必定来自其中一个前驱，其 1 的数量恰为前驱数量加当前值；每个这样产生的状态也确实能由对应前驱路径延伸得到，因此转移既无遗漏，也不制造不存在的路径。丢弃大于 T 的状态不会丢失答案，因为 1 的数量只能保持或增加。最终路径长度固定为 2T，恰有 T 个 1 就等价于恰有 T 个 0。

边界与复杂度

2×2 矩阵的路径含 3 个格子，必为 false。全零或全一不会达到平衡；起点和终点都必须计数。输入按题目约束为非空规则矩阵。时间为 O(mnT) = O(mn(m+n))，滚动数组空间为 O(nT)。演示为支持回放保留完整快照，空间额外增加，不能据此推断提交代码的空间。

替代方案

记忆化 DFS 保存 (行、列、1 的数量)，可在任一种值超过 T 时剪枝，最坏时间、空间均 O(mnT)。位集合 DP 可将“计数加一”变成左移，再用按位或合并；需要注意各语言位宽与大整数成本。也可只维护最小/最大 1 数量，将时间压至 O(mn)，但必须证明可达计数无空洞：任意两条单调路径可通过相邻 RD/DR 交换互相变换，每次只替换一个中间格，计数至多改变 1，因此最小与最大之间的整数都能出现。该性质依赖本题无障碍且格值为 0/1。

常见错误

  • 将路径长度写成 m+n−2：那是步数，漏掉起点。
  • 用一个 visited[i][j] 合并所有历史：丢掉计数信息。
  • 原地更新当前计数数组：可能在同一格重复加值。使用新的 cur。
  • 只检查总长度是偶数就返回 true：仍需确认 T 可达。
  • 用“终点为 0”或“全矩阵数量平衡”代替路径条件。

面试追问

如何输出路径？保存每个可达状态的前驱 (i,j,k)，从终点 T 倒推，空间增至 O(mnT)。如果要数路径？将布尔或改为计数求和，并按要求取模。允许四向移动怎么办？单调 DAG 与固定长度不再成立，需先明确能否重复经过格子，再重新建模；不能直接复用本解法。

JAVA

class Solution {
    public boolean isThereAPath(int[][] grid) {
        int m = grid.length, n = grid[0].length;
        int length = m + n - 1;
        if (length % 2 == 1) return false;
        int target = length / 2;
        boolean[][] dp = new boolean[n][target + 1];
        for (int i = 0; i < m; i++) {
            for (int j = 0; j < n; j++) {
                int value = grid[i][j];
                boolean[] cur = new boolean[target + 1];
                if (i == 0 && j == 0) {
                    cur[value] = true;
                } else {
                    for (int k = value; k <= target; k++) {
                        cur[k] = (i > 0 && dp[j][k - value])
                              || (j > 0 && dp[j - 1][k - value]);
                    }
                }
                dp[j] = cur;
            }
        }
        return dp[n - 1][target];
    }
}

PYTHON

from typing import List

class Solution:
    def isThereAPath(self, grid: List[List[int]]) -> bool:
        m, n = len(grid), len(grid[0])
        length = m + n - 1
        if length % 2:
            return False
        target = length // 2
        dp = [[False] * (target + 1) for _ in range(n)]
        for i in range(m):
            for j in range(n):
                value = grid[i][j]
                cur = [False] * (target + 1)
                if i == 0 and j == 0:
                    cur[value] = True
                else:
                    for k in range(value, target + 1):
                        cur[k] = ((i > 0 and dp[j][k - value]) or
                                  (j > 0 and dp[j - 1][k - value]))
                dp[j] = cur
        return dp[n - 1][target]
