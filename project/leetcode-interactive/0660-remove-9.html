把序号读成九进制

每一位只有 0 到 8 共九种合法选择；合法十进制数与九进制表示之间恰好形成保序映射。

核心洞察

一个十进制位若不能使用 9，就只剩 0～8，正好是九种选择。这与九进制每一位的合法数字完全一致。 因此，把序号 n 写成九进制，再把同一串字符按十进制读取，得到的就是答案。

例如 100 = 121₉；把数字串 121 当作十进制外观返回，即得到 121。

完整过程

  1. 准备 answer = 0 与十进制位权 place = 1。
  2. 反复取 digit = n % 9，它一定落在 0～8。
  3. 把该数字放入答案当前十进制位：answer += digit × place。
  4. 令 n = floor(n / 9)，同时把 place 乘 10。
  5. 当 n = 0 时，返回答案。

正确性证明

映射得到的数一定合法。
九进制表示的每一位都属于 0～8。把这些位原样当作十进制数字时，不可能出现 9。
映射是一一对应。
每个正整数都有唯一的九进制表示；每个不含 9 的十进制数字串，也能唯一解释成一个九进制数。因此不会遗漏或重复合法数。
映射保持大小顺序。
对不含 9 的等长数字串，九进制与十进制的大小都由第一处不同的位决定；位数更多时两边也都更大。所以第 n 个九进制表示映射后，正是第 n 个合法十进制数。

综上，算法返回的数合法、无重复无遗漏且次序一致，故返回值就是移除所有含 9 数字后的第 n 个正整数。

边界与复杂度

  • n = 1…8 时只有一位，答案就是 n 本身。
  • n = 9 首次产生进位，九进制为 10，答案也为 10。
  • 中间余数可以为 0；0 是合法数字，不能跳过。
  • 题目只接收正整数，不需要为 0 或负数定义排名。
时间复杂度 O(log₉ n) 每次将 n 除以 9。
额外空间 O(1) 数值拼接只用常数变量。

Java

Solution.java可提交实现
class Solution {
    public int newInteger(int n) {
        int answer = 0;
        int place = 1;

        while (n > 0) {
            int digit = n % 9;
            answer += digit * place;
            n /= 9;
            place *= 10;
        }

        return answer;
    }
}

替代方案

可以对答案做二分，并用数位 DP 统计“不大于 x 且不含 9 的正整数”数量，再寻找计数首次达到 n 的 x。 这种方案能推广到更复杂的禁用数字集合或附加数位约束，但本题中实现更长，复杂度也高于直接进制映射。

也可以先得到九进制字符串，再把它按十进制整数解析。思路很直观，但数值位权写法避免了字符串转换，并保持常数额外空间。

面试追问

  • 若移除数字 7 而不是 9 呢？ 仍有九种合法数字，但需要把九进制位 7、8 分别映射成十进制字符 8、9。
  • 若同时移除多个数字呢？ 基数变为“合法数字的数量”，再建立按升序排列的位映射。
  • 为什么不能把 n − 1 转换后再加 1？ 本题序列从正整数 1 开始，n 的九进制表示本身就对应第 n 个；额外偏移会破坏 n = 9 等边界。
  • 数据范围扩大怎么办？ 使用 64 位整数，或直接用字符串收集余数后反转，避免位权溢出。

常见错误

  • 把问题误解为“从 n 的十进制表示中删除字符 9”。
  • 逐个枚举正整数并检查是否含 9，导致在大输入上做大量无效工作。
  • 取出余数后按产生顺序追加，忘记余数先对应低位。
  • 把余数 0 当成应移除的数字；本题只禁用 9。
  • 在语言的数据范围扩大后仍使用 32 位位权，造成溢出。
