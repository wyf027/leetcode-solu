股票平滑下跌阶段的数目

Number of Smooth Descent Periods of a Stock

一段走势，可以藏着多少个连续区间？从每天的价格开始观察。

01 / 题目

只认“恰好下降 1”

给定整数数组 prices，prices[i] 表示第 i 天的股价。一个平滑下跌阶段由连续的一天或多天构成：从第二天开始，每天的价格都必须比前一天恰好少 1。阶段的第一天没有这个要求，因此任意单独一天都符合定义。

返回所有平滑下跌阶段的数量。阶段按起止日期区分；价格相同的不同日期仍然是不同阶段。

参数与返回值

getDescentPeriods(prices)
输入：整数数组 prices
返回：阶段总数（长整数语义）

官方约束

1 ≤ prices.length ≤ 105
1 ≤ prices[i] ≤ 105

官方示例

示例 1

输入：prices = [3,2,1,4]
输出：7

四个单日阶段，加上 [3,2]、[2,1]、[3,2,1]，共 7 个。

示例 2

输入：prices = [8,6,7,7]
输出：4

只有四个单日阶段：[8]、[6]、[7]、[7]。[8,6] 下降了 2，不满足条件；相邻两个 7 也不满足条件。

示例 3

输入：prices = [1]
输出：1

唯一的单日阶段 [1] 符合要求。

04 / 独立题解

准备好再揭开思路

核心洞察：按右端点计数

每个阶段都有唯一的最后一天。令 run 表示以当前日期结束的最长平滑下降段的长度；这一段的每个后缀都合法，恰好提供 run 个新阶段。把每天的 run 加入答案即可。

完整过程

  1. 初始化 run = 0、total = 0，从左到右处理每个日期。
  2. 若不是第一天且 prices[i - 1] - prices[i] == 1，令 run += 1。
  3. 否则连续关系断开，令 run = 1，保留当天自身构成的阶段。
  4. 累加 total += run；遍历完成后返回 total。
prices       3   2   1   4
run          1   2   3   1
total        1   3   6   7

例如读到价格 1 的那一天，新阶段为 [1]、[2,1]、[3,2,1]。读到 4 时无法连接前一天，只新增 [4]。

正确性证明

归纳维护不变式：处理完下标 i 后，run 等于以 i 结束的合法阶段数量。第一天只有单日阶段，run = 1。若相邻价格差为 1，所有以上一天结束的合法阶段都可追加今天，再加今天自身，因此数量为上一轮 run + 1；反过来，每个长度大于 1 的合法阶段去掉今天后，都属于这些旧阶段。若差不为 1，任何跨过这条相邻边的阶段都不合法，只剩单日阶段，数量为 1。

因此每轮新增计数准确。不同右端点对应的阶段互不重叠，所有合法阶段都拥有某个右端点，所以累计值无遗漏、无重复。

边界与数值

  • 单元素返回 1；题目不包含空数组。
  • 上升、相等或下降超过 1 都必须重新计数。
  • 最大值是 100000 × 100001 / 2 = 5000050000，超过 32 位有符号整数。
  • Java 用 long、C++ 用 long long；Python 整数自动扩展；JavaScript Number 的安全整数范围足够容纳本题最大值。

复杂度与替代方案

  • 时间 O(n)，每个价格只处理一次。
  • 额外空间 O(1)，只维护两个计数器。
  • 分段法：把数组切成极大平滑下降段，每段长度 k 贡献 k(k+1)/2；同样 O(n) 时间、O(1) 空间。
  • DP 数组可保存每天的贡献，但会使用 O(n) 空间，没有必要。
  • 暴力枚举起点并向右延伸，最坏 O(n²)，不适合 10⁵ 的规模。

Java

class Solution {
    public long getDescentPeriods(int[] prices) {
        long total = 0, run = 0;
        for (int i = 0; i < prices.length; i++) {
            if (i > 0 && prices[i - 1] - prices[i] == 1) {
                run++;
            } else {
                run = 1;
            }
            total += run;
        }
        return total;
    }
}

    long long getDescentPeriods(vector<int>& prices) {
        long long total = 0, run = 0;
        for (int i = 0; i < static_cast<int>(prices.size()); ++i) {

常见错误

  • 把“恰好少 1”误写成任意下降，或用绝对值判断而接受上升。
  • 只数极大下降段，遗漏其中更短的子区间。
  • 断开时清零而不是设为 1，漏掉单日阶段。
  • 按价格值去重，错误合并了不同日期的区间。
  • 用 32 位类型累加；分段公式中也要在相乘前提升为 64 位。

面试追问

  • 价格流式到达怎么办？ 保存前一天价格、run 和 total，每条新数据 O(1) 更新。
  • 若要求每次恰好下降 d？ 将相邻差判断改成 d，计数不变式不变。
  • 只数长度至少 L 的阶段？ 每天贡献改为 max(0, run - L + 1)。
  • 要求列出所有区间呢？ 可输出每个右端点对应的合法起点；输出本身最坏有 O(n²) 个区间，无法保持线性总时间。
