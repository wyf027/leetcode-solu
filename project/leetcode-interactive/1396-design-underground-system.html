设计地铁系统Design Underground System

实时记录每位乘客的进站状态，在出站瞬间把一次行程压缩成路线的总耗时与次数；查询时只做一次除法。

O(1)三种操作的平均时间复杂度
两张哈希表，各司其职
01 / Problem

题目要求

系统保证调用合法、事件按时间递增；路线有方向，A → B 与 B → A 必须分开统计。

实现 UndergroundSystem。系统需要跟踪乘客在某站、某时刻进站，在另一站、另一时刻出站，并能返回指定起点到终点的历史直达行程平均耗时。

一次“直达行程”指某次进站紧接着对应的出站。查询前保证目标路线至少已有一条完整行程。若乘客在 t₁ 进站、在 t₂ 出站，则 t₁ < t₂。

checkIn(id, stationName, t)

记录该乘客当前进站的站名和时间；同一时刻只会处于一个站内。

checkOut(id, stationName, t)

结束该乘客的当前行程，把耗时累计到有方向的路线统计中。

getAverageTime(start, end)

返回该路线全部历史完整行程的平均耗时。

Core Insight

只保留查询真正需要的信息

01

乘客表

id → (startStation, startTime)。只记录仍在途的人，出站后即可删除。

02

路线表

(start, end) → (total, count)。无需保存每次行程，只保留总和与次数。

03

有向键

把起点和终点组成有方向的复合键，确保 Leyton → Waterloo 不会与反向路线混淆。

Process

完整过程

初始化

建立 active 与 routes 两张空哈希表。

处理 checkIn

用乘客 ID 作为键，保存进站站名和时刻。题目保证不会重复进站。

处理 checkOut

按 ID 取出进站信息，计算 duration = t - startTime，然后更新该有向路线的总耗时与次数，并删除乘客的在途记录。

处理 getAverageTime

取得路线的 total 和 count，返回 total / count。题目保证数据存在。

Correctness

正确性证明

不变式

处理任意事件前后：① active 精确包含所有已进站但尚未出站的乘客及其进站信息；② 对每条路线，routes 中的总耗时与次数，精确等于此前所有已完成的该方向行程之和与数量。

初始化：尚无事件，两张表为空，不变式成立。进站：加入唯一乘客的准确站名和时刻，只改变在途集合，不影响完整行程统计。出站：由不变式可取到唯一且准确的进站信息，因此算出的耗时正确；把它累加到对应有向路线并删除在途记录后，两部分仍准确。查询：由第二条不变式，total / count 正是全部历史该路线行程的算术平均值。因此所有返回结果正确。

Complexity

复杂度

O(1)

三种操作的平均时间复杂度，基于哈希表平均查找与更新。

O(P + R)

空间复杂度：P 为同时在途乘客数，R 为出现过的不同有向路线数。

Java官方可提交签名
import java.util.*;

class UndergroundSystem {
    private static class CheckIn {
        String station;
        int time;
        CheckIn(String station, int time) {
            this.station = station;
            this.time = time;
        }
    }

    private static class Stats {
        long total;
        int count;
    }

    private final Map<Integer, CheckIn> active = new HashMap<>();
    private final Map<String, Stats> routes = new HashMap<>();

    public UndergroundSystem() {}

    public void checkIn(int id, String stationName, int t) {
        active.put(id, new CheckIn(stationName, t));
    }

    public void checkOut(int id, String stationName, int t) {
        CheckIn in = active.remove(id);
        String key = in.station + "\u0000" + stationName;
        Stats stats = routes.computeIfAbsent(key, k -> new Stats());
        stats.total += t - in.time;
        stats.count++;
    }

    public double getAverageTime(String startStation, String endStation) {
        Stats stats = routes.get(startStation + "\u0000" + endStation);
        return (double) stats.total / stats.count;
    }
}

        key = (start, stationName)

C++官方可提交签名
class UndergroundSystem {
    unordered_map<int, pair<string, int>> active;
    unordered_map<string, pair<long long, int>> routes;

    string key(const string& start, const string& end) {
        return start + '\0' + end;
    }

public:
    UndergroundSystem() {}

    void checkIn(int id, string stationName, int t) {
        active[id] = {stationName, t};
    }

    void checkOut(int id, string stationName, int t) {
        auto [start, startTime] = active[id];
        active.erase(id);
        auto& [total, count] = routes[key(start, stationName)];
        total += t - startTime;
        count++;
    }

    double getAverageTime(string startStation, string endStation) {
        auto [total, count] = routes[key(startStation, endStation)];
        return static_cast<double>(total) / count;
    }
};
Edges & Follow-ups

边界、替代方案与追问

边界与常见错误

  • 路线键必须保留方向，不能把两个站名排序。
  • 不要只存平均值；更新平均值时容易丢失精度或缺少权重，存总和与次数更直接。
  • 总耗时建议使用 64 位整数，避免多次累计产生溢出风险。
  • 出站后删除乘客记录，否则空间随历史乘客数持续增长。
  • 字符串拼接键要使用不会出现在站名中的分隔符，或直接使用 pair/tuple。

替代方案

可以保存每条路线的所有单次耗时，查询时再求和；但查询会变成 O(k)，空间也保存了不必要的历史明细。也可用在线均值公式更新平均值，但浮点误差更早介入，且仍需次数。

若业务要求审计每次出行，明细存储才有意义；本题只查询平均值，聚合统计是最小充分信息。

面试追问：并发怎么办？

需要保证同一乘客状态更新和路线累计的原子性。可按乘客 ID 与路线键分片加锁，或通过事件流按键分区；分布式场景还需考虑重复事件的幂等键。

面试追问：滑动窗口平均值？

若只统计最近 N 次，可为每条路线维护定长队列与窗口和；若统计最近一小时，可维护按时间有序的队列，查询或写入时淘汰过期行程。
