配对交换 把 32 位拆成两条反向传送带

面试题 05.07：交换整数的奇数位与偶数位。先观察每一对位如何换座，再操作整条位带完成一次并行交换。

位运算 双掩码 O(1) / O(1)

交换规约

偶数位

0 → 1

奇数位

1 → 0

位编号从最低位 0 开始：0 与 1、2 与 3、4 与 5……两两交换。

题意

每一对相邻二进制位互换

给定非负整数 num，交换它的奇数位和偶数位，尽量使用较少指令。返回交换后的整数。

示例 1

输入

num = 2（0b10）

输出

1（0b01）

示例 2

输入

num = 3

输出

3

约束与读法

  • 0 ≤ num ≤ 2³⁰ − 1，题目保证不会发生整数溢出。
  • 位 0 是最低位；“奇数位 / 偶数位”指位编号，不是位上的数值。
  • 页面统一显示 32 位，左侧是位 31，右侧是位 0。

    核心洞察

    一条指令处理 16 对位

    0x55555555 在偶数位为 1，选出所有偶数位；0xAAAAAAAA 在奇数位为 1，选出所有奇数位。前者整体左移一位，后者整体右移一位，再按位或即可。

    完整过程

    1. 1. even = num & 0x55555555
    2. 2. odd = num & 0xAAAAAAAA
    3. 3. even << 1，让偶数位去右邻居的编号。
    4. 4. odd >>> 1，让奇数位去左邻居的编号。
    5. 5. 两条互不重叠的位带按位或。

    边界

    0 保持 0；相邻位相同则交换后数值不变；约束只使用低 30 位。

    复杂度

    固定次数位运算，时间 O(1)；只用常量临时量，空间 O(1)。

    替代方案

    逐对读取并写回 15 对位也能做，但指令更多，核心模式不如双掩码清晰。

    常见错误

    混淆位编号；两个掩码写反；先移动再掩码；JavaScript 忘记无符号化。

    面试追问

    为什么不会串位？

    两条掩码的 1 完全互斥，移动后仍落到互补位置。

    为什么 Java 用 >>>？

    逻辑右移补 0，不让符号位扩散；本题非负输入下也能明确表达意图。

    能推广吗？

    可以。交换更大的固定分组时，用分层掩码与多级位移完成置换。

    可提交代码

    四种语言，同一条位带 

    class Solution {
    public int exchangeBits(int num) {
        int even = (num & 0x55555555) << 1;
        int odd = (num & 0xAAAAAAAA) >>> 1;
        return even | odd;
    }
}
