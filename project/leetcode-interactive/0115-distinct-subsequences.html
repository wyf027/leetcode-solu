一维动态规划协议

核心洞察

设 dp[j] 表示已扫描的源前缀中，能组成 t[0..j) 的方案数。空目标始终只有一种选择，所以 dp[0] = 1。

当 s[i] == t[j - 1]：dp[j] = dp[j] + dp[j - 1]

为什么必须倒序

dp[j - 1] 必须来自处理当前源字符之前的旧状态。若 j 正序更新，同一个 s[i] 会先生成较短前缀，再在本轮被重复用于更长前缀。

完整过程

  1. 创建长度为 t.length + 1 的计数数组，令 dp[0] = 1。
  2. 从左到右扫描源字符串 s。
  3. 对每个源字符，从 t.length 到 1 倒序检查目标字符。
  4. 字符相等时，把形成较短目标前缀的方案数加到当前前缀。
  5. 扫描完毕后返回 dp[t.length]。

边界

  • t.length > s.length 时结果自然为 0。
  • 完全相同时只有 1 种选法。
  • 重复字符会产生组合数，例如 5 个 a 选 2 个是 10。
  • 英文字母区分大小写，A 与 a 不匹配。

复杂度

时间 O(mn) m = |s|，n = |t|
额外空间 O(n) 只保留目标前缀计数

替代方案取舍

  • 二维 DP：状态最直观、便于推导，但额外空间为 O(mn)。
  • 记忆化 DFS：贴合“选或不选”，但递归深度与缓存开销更高。
  • 一维 DP：面试推荐提交版，空间更稳；代价是必须解释倒序更新。

常见错误

  • 把内容相同的子序列去重；本题按下标选择计数。
  • 将 dp[0] 初始化为 0，导致所有状态无法产生。
  • 正序更新一维数组，让单个源字符在同一轮被复用。
  • 字符不等时清零 dp[j]；正确做法是保留“不选当前字符”的旧计数。

面试追问

  • 如何从二维转移式压缩到一维？为什么循环方向随依赖关系改变？
  • 如果答案不保证适配 32 位整数，各语言应使用什么大整数策略？
  • 如何剪枝 t.length > s.length，以及它是否改变复杂度上界？
  • 若要求输出一组具体下标选择，应如何在二维表上回溯？

class Solution {
    public int numDistinct(String s, String t) {
        long[] dp = new long[t.length() + 1];
        dp[0] = 1;

        for (int i = 0; i < s.length(); i++) {
            for (int j = t.length(); j >= 1; j--) {
                if (s.charAt(i) == t.charAt(j - 1)) {
                    dp[j] += dp[j - 1];
                }
            }
        }
        return (int) dp[t.length()];
    }
}
