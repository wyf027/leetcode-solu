统计具有相反奇偶性的较小元素

从每个位置向右看：只统计数值更小、且奇偶性与当前数不同的元素。这里用“两条 Fenwick 计数轨道”把右侧信息压缩成可查询的前缀和。

坐标压缩两棵 Fenwick Tree从右向左

题意

给定整数数组 nums。对于每个下标 i，计算右侧下标 j 的数量：i < j、nums[j] < nums[i]，且两数奇偶性不同。返回所有得分。

示例：nums = [5, 2, 4, 1, 3]

输出：[2, 1, 2, 0, 0]

值域可达 10⁹，而数组长度可达 10⁵；不能逐对枚举。

读题边界

  • • “更小”是严格小于，所以查询 rank - 1。
  • • 只看右侧，因此必须先处理 i 右边的元素。
  • • 相同数值可能重复，Fenwick 树保存的是频次，不是集合。
  • • 正整数下，x & 1 可区分奇偶；另一组是 parity ^ 1。

核心洞察

  1. 反向扫描时，两个树中恰好保存了当前下标右侧的元素。
  2. 把数值压缩为 1..m 的排名；同一数值使用同一排名。
  3. 当前值为偶数就查询“奇数树”中排名小于它的频次，奇数同理。
  4. 查询后，把当前值写入自己的奇偶树。

复杂度与替代方案

压缩排序为 O(n log n)，每次查询/更新为 O(log n)，总时间 O(n log n)，空间 O(n)。

若用两份平衡有序表也可完成；暴力双循环是 O(n²)，仅适合小数组对拍。

常见错误

  • 查询写成 query(rank)，会把相等元素误算。
  • 先更新再查询，会把自己误当作右侧元素。
  • 只维护一棵树，丢失奇偶筛选条件。
