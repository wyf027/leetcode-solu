Problem

498. 对角线遍历

给定一个大小为 m × n 的整数矩阵 mat，请按对角线遍历的顺序返回包含矩阵全部元素的一维数组。

题意转述

从左上角出发，在相邻的右上与左下方向之间交替移动。触碰矩阵上边界、下边界、左边界或右边界时，先移到下一条对角线的起点，再改变方向；直到每个单元格恰好被收集一次。

函数形式

findDiagonalOrder(mat: integer[][]) → integer[]

约束

  • m == mat.length
  • n == mat[i].length
  • 1 ≤ m, n ≤ 10⁴
  • 1 ≤ m × n ≤ 10⁴
  • −10⁵ ≤ mat[i][j] ≤ 10⁵

Core Insight

核心洞察：方向决定边界优先级

矩阵中的每个位置都属于唯一一条对角线，并满足 r + c 相同。直接模拟时只需要维护当前位置 (r, c) 和方向 dir：右上为 (−1, +1)，左下为 (+1, −1)。

关键不是普通移动，而是越界时如何落到下一条对角线。右上移动要先判断右边界、再判断上边界；左下移动要先判断下边界、再判断左边界。角点会同时触碰两条边，优先级错误就会重复或漏掉单元格。

完整过程

  1. 创建长度为 m × n 的结果数组，从 (0, 0) 开始，初始方向为右上。
  2. 每轮先把当前元素写入结果，再根据方向计算下一个坐标。
  3. 向右上时：若到达右边界则下移；否则若到达上边界则右移；否则右上移动。
  4. 向左下时：若到达下边界则右移；否则若到达左边界则下移；否则左下移动。
  5. 每次处理边界后翻转方向；收集满 m × n 个元素即结束。

正确性证明

引理 1：非边界移动保持 r + c 不变，所以游标只会沿当前对角线前进。

引理 2：到达边界时，规则把游标移动到下一条尚未处理的对角线端点，并翻转方向。右边界优先于上边界、下边界优先于左边界，使右上角和左下角也只推进一次。

定理：初始游标位于第一条对角线。由引理 1，每条对角线内部的元素按指定方向连续访问；由引理 2，各对角线按 r + c = 0, 1, …, m+n−2 依次衔接且不重叠。因此恰好访问全部 m × n 个元素一次，输出即为所求顺序。

复杂度

时间 O(mn)；除返回数组外，额外空间 O(1)。

class Solution {
    public int[] findDiagonalOrder(int[][] mat) {
        int m = mat.length;
        int n = mat[0].length;
        int[] answer = new int[m * n];
        int row = 0, col = 0;
        int direction = 1; // 1: 右上，-1: 左下

        for (int i = 0; i < m * n; i++) {
            answer[i] = mat[row][col];

            if (direction == 1) {
                if (col == n - 1) {
                    row++;
                    direction = -1;
                } else if (row == 0) {
                    col++;
                    direction = -1;
                } else {
                    row--;
                    col++;
                }
            } else {
                if (row == m - 1) {
                    col++;
                    direction = 1;
                } else if (col == 0) {
                    row++;
                    direction = 1;
                } else {
                    row++;
                    col--;
                }
            }
        }
        return answer;
    }
}

边界情况

  • 1 × 1：第一次收集后立刻结束，不能再推进越界坐标。
  • 单行：每次在上边界与右边界之间切换，结果保持从左到右。
  • 单列：每次在左边界与下边界之间切换，结果保持从上到下。
  • 非方阵：方向规则完全相同，不能假设 m == n。
  • 负数与重复值：遍历只依赖坐标，与元素数值无关。

替代方案：按对角线分组

依次枚举对角线编号 d = 0 … m+n−2，收集所有满足 r+c=d 的元素；当 d 为偶数时逆序加入，奇数时正序加入。

它更容易从“不变量”推导，但临时保存一条对角线需要最多 O(min(m,n)) 额外空间。也可以通过调整枚举起点与步长避免临时数组。

面试追问

  • 如果矩阵通过数据流逐行到达，如何输出已经确定的对角线？需要缓存多少行或元素？
  • 如果要求从右下角反向遍历，边界优先级如何对称变换？
  • 能否只根据输出下标 k 直接计算坐标，而不保存游标状态？代价是什么？
  • 若矩阵是稀疏的，并且只输出存在的元素，分组方案应如何调整？

常见错误

  • 右上角同时满足“上边界”和“右边界”时先右移，导致列坐标越界。
  • 左下角同时满足“左边界”和“下边界”时先下移，导致行坐标越界。
  • 在移动后才写入当前值，使首元素丢失或末尾多走一步。
  • 循环条件依赖坐标而非已写入数量，单行、单列时提前结束。
  • 分组法忘记偶数对角线需要反转，输出方向整体错位。
