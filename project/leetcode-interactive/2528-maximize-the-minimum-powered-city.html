HARD免费题 · 城市供电规划

最大化城市的
最小电量

Maximize the Minimum Powered City

城市连成一条线，供电会向两侧延伸。有限的新电站，怎样让电量最少的那座城市也尽可能充足？先读题，再展开下方的交互推演与题解。

01 / THE PROBLEM

题意与输入

给定长度为 n 的整数数组 stations，城市编号为 0…n−1，stations[i] 是城市 i 已有的电站数量。每座电站同时为距离它不超过 r 的所有城市供电，每覆盖一座城市，就为该城市贡献 1 单位电量。

因此，城市 i 的电量是区间 [max(0,i−r), min(n−1,i+r)] 内的电站总数。你可再建 k 座电站，位置任意，同一城市可建多座，新电站的覆盖半径也为 r。返回最优建造后，所有城市电量的最小值能够达到的最大值。

电量是“能覆盖该城市的电站总数”，并非该城市自身的电站数；电站的供电无需在覆盖城市之间分摊。

约束

  • n == stations.length，1 ≤ n ≤ 10⁵
  • 0 ≤ stations[i] ≤ 10⁵
  • 0 ≤ r ≤ n−1
  • 0 ≤ k ≤ 10⁹

参数形式：maxPower(stations, r, k)，返回整数；Java 返回 long，C++ 返回 long long。

官方示例

示例 1

stations = [1,2,4,5,0], r = 1, k = 2
输出：5

把两座新电站都建在城市 1，电站数量变为 [1,4,4,5,0]；各城市电量为 [5,9,13,9,5]，最小值为 5，且无法更高。

示例 2

stations = [4,4,4,4], r = 0, k = 3
输出：4

半径为 0 时，每座新电站只能提升所在城市。要让四座城市都达到 5，至少需要四座新电站；预算为 3，所以答案仍为 4。

02 / THINK FIRST

先想一想

如果只问“每座城市能否都达到某个目标电量”，会不会比直接寻找最优建造方案更容易？当左边第一座不达标的城市出现时，新电站有哪些可选位置？

题解 · 二分答案 + 从左到右贪心 + 差分

把优化变为判定

固定目标电量 X，求达到它至少要补多少电站。目标越高越难，可行性具有单调性。

补站尽量靠右

扫描城市 i，有缺口就补在 p = min(n−1, i+r)，覆盖当前城市，同时尽可能帮助后面的城市。

记录影响何时结束

新站对后续扫描的贡献到 p+r 为止。在 p+r+1 设置负差分，让有效增量及时到期。

完整过程

  1. 计算初始电量。 构造前缀和 prefix[i+1] = prefix[i] + stations[i]，得到 power[i] = prefix[min(n,i+r+1)] − prefix[max(0,i−r)]，耗时 O(n)。
  2. 确定搜索范围。 设 m = min(power)。无需新增时 m 可行；原本电量最少的城市最多从 k 座新站获得 k 点电量，所以答案不超过 m+k。
  3. 检查目标 X。 清零长为 n+1 的差分数组。扫描 i 时，先令 active += diff[i]，当前电量为 power[i]+active。
  4. 补足当前缺口。 令 need = X−power[i]−active。若 need>0，必须再补至少 need 座站；用量超过 k 就立即返回 false。否则把 need 座放在 p=min(n−1,i+r)，执行 active += need 与 diff[min(n,p+r+1)] -= need。
  5. 完成判定与二分。 全部城市完成就返回 true。取偏右中点 mid = low + floor((high−low+1)/2)；可行则 low=mid，不可行则 high=mid−1，最终返回 low。

示例 1 的初始电量是 [3,7,11,9,5]。区间 [3,5] 先检查 4，再检查 5，都可行。目标 5 在城市 0 缺 2，补在城市 1，贡献到城市 2，进入城市 3 时到期；剩余城市无需新增。若尝试 6，城市 0 就需要 3 座，超过预算 2。

这里用“至多 k 座”判定即可：额外建设不会降低电量；若必须恰好用完 k，剩余电站任意放置即可。

为什么正确

1. 最右补站可以替换任何可行补法

扫描到 i 时，先前城市均已达标。如果 i 还缺 need，任意完成方案都至少要有 need 座尚未计入、且覆盖 i 的新站。能覆盖 i 的最右位置为 p=min(n−1,i+r)。把这些站移到 p 后，对任意未处理城市 j≥i，原站若能覆盖 j，则 j≤原位置+r≤p+r，且 p−r≤i≤j，因此新位置仍能覆盖 j。已处理城市靠已有的贪心站已达标，不依赖这些未计入站。这样的替换不会破坏可行性。

2. 扫描判定等价于存在可行方案

依次应用上述替换，若存在预算内完成方案，就能转为包含每一步贪心选择的方案。贪心只补当前不可避免的缺口，因而超预算时不存在更省的可行方案；扫描完成且用量不超预算，则所构造的放置方案本身就是可行证据。

3. 差分维护有效新增贡献

active 表示已放置新站对当前城市的总贡献。补站时立即加上 need，贡献于 p+r+1 到期时减去 need。每步先处理到期事件，故计算缺口时的 active 始终准确。最终方案可能也提升左侧城市，但扫描无需回访已满足的城市。

4. 二分返回最大可行值

能达到 X 的方案一定也能达到更小目标。初始区间包含最优答案，判定后保留的区间仍包含它；偏右中点确保区间不断缩小。low=high 时即为最大可行目标。

复杂度与数值范围

前缀和 O(n)，每次判定 O(n)，最多 O(log(k+1)) 轮二分。含预处理的总时间为 O(n · (1+log(k+1)))，额外空间 O(n)。k=0 时直接返回初始最小值。

电站总数可能到 10¹⁰，搜索上界不超过 1.1×10¹⁰。Java/C++ 用 64 位整数保存电量、差分和用量；Python 整数足够；JavaScript Number 可精确表示这些整数，禁止用位运算求中点，以免转为 32 位。

边界与常见错误

  • r=0：只能补当前城市；差分在 i+1 到期。
  • r=n−1：所有站覆盖所有城市，答案是 sum(stations)+k。
  • n=1、全零数组、k=0 均无需特别分支。
  • 不要把 stations 当 power，先统计半径覆盖。
  • 到期下标是 p+r+1，不是 p+r；n 处为哨兵。
  • 每个二分目标都要清空差分和 used。
  • 先处理 diff[i] 再计算 need；已有电量充足时不撤站。
  • 补站位置必须截断到 n−1，避免越界。

替代方案与面试追问

  • 滑动窗口： 初始电量可以用双指针窗口求和，替代前缀和；同样 O(n)。
  • 到期队列： 用队列保存新增贡献的到期位置，也能在每轮 O(n) 完成判定；差分更直接。
  • 线段树： 支持范围加和点查询，但每轮会变为 O(n log n)，本题顺序扫描无需这种通用结构。
  • 直接更新覆盖区间： 更直观，但一轮最坏 O(n²)，不适合 n=10⁵。
  • 如何输出建设方案？ 二分结束后，用最优目标再扫描一次，记录每个 p 的 need；剩余预算任意安排。
  • 若城市有建设容量限制或不同造价？ “总放最右”未必可用，交换论证的前提被破坏，需按新约束重新设计判定。
  • 为何上界不是总电站数+k？ 那也是合法上界，但 min(power)+k 更紧，直接限制最弱城市的最高可能增量。

Java

long · LeetCode Solution
class Solution {
    public long maxPower(int[] stations, int r, int k) {
        int n = stations.length;
        long[] prefix = new long[n + 1];
        for (int i = 0; i < n; i++)
            prefix[i + 1] = prefix[i] + stations[i];
        long[] power = new long[n];
        long low = Long.MAX_VALUE;
        for (int i = 0; i < n; i++) {
            power[i] = prefix[Math.min(n, i + r + 1)]
                     - prefix[Math.max(0, i - r)];
            low = Math.min(low, power[i]);
        }
        long high = low + k;
        while (low < high) {
            long mid = low + (high - low + 1) / 2;
            if (can(power, r, k, mid)) low = mid;
            else high = mid - 1;
        }
        return low;
    }

    private boolean can(long[] power, int r, int k, long target) {
        int n = power.length;
        long[] diff = new long[n + 1];
        long active = 0, used = 0;
        for (int i = 0; i < n; i++) {
            active += diff[i];
            long need = target - power[i] - active;
            if (need <= 0) continue;
            used += need;
            if (used > k) return false;
            int p = Math.min(n - 1, i + r);
            active += need;
            diff[Math.min(n, p + r + 1)] -= need;
        }
        return true;
    }
}

var maxPower = function(stations, r, k) {
    const n = stations.length;
    const prefix = new Array(n + 1).fill(0);
    for (let i = 0; i < n; i++)
        prefix[i + 1] = prefix[i] + stations[i];
    const power = new Array(n);
    let low = Infinity;
    for (let i = 0; i < n; i++) {
        power[i] = prefix[Math.min(n, i + r + 1)]
                 - prefix[Math.max(0, i - r)];
        low = Math.min(low, power[i]);
    }
    function can(target) {
        const diff = new Array(n + 1).fill(0);
        let active = 0, used = 0;
        for (let i = 0; i < n; i++) {
            active += diff[i];
            const need = target - power[i] - active;
            if (need <= 0) continue;
            used += need;
            if (used > k) return false;
            const p = Math.min(n - 1, i + r);
            active += need;
            diff[Math.min(n, p + r + 1)] -= need;
        }
        return true;
    }
    let high = low + k;
    while (low < high) {
        const mid = low + Math.floor((high - low + 1) / 2);
        if (can(mid)) low = mid;
        else high = mid - 1;
    }
    return low;
};

Python

Python 3 · 任意精度整数
from typing import List

class Solution:
    def maxPower(self, stations: List[int], r: int, k: int) -> int:
        n = len(stations)
        prefix = [0] * (n + 1)
        for i, count in enumerate(stations):
            prefix[i + 1] = prefix[i] + count
        power = [prefix[min(n, i + r + 1)] - prefix[max(0, i - r)]
                 for i in range(n)]

        def can(target: int) -> bool:
            diff = [0] * (n + 1)
            active = used = 0
            for i in range(n):
                active += diff[i]
                need = target - power[i] - active
                if need <= 0:
                    continue
                used += need
                if used > k:
                    return False
                p = min(n - 1, i + r)
                active += need
                diff[min(n, p + r + 1)] -= need
            return True

        low = min(power)
        high = low + k
        while low < high:
            mid = low + (high - low + 1) // 2
            if can(mid):
                low = mid
            else:
                high = mid - 1
        return low

C++17 · long long
#include <algorithm>
#include <vector>
using namespace std;

class Solution {
public:
    long long maxPower(vector<int>& stations, int r, int k) {
        int n = stations.size();
        vector<long long> prefix(n + 1, 0), power(n);
        for (int i = 0; i < n; ++i)
            prefix[i + 1] = prefix[i] + stations[i];
        for (int i = 0; i < n; ++i)
            power[i] = prefix[min(n, i + r + 1)]
                     - prefix[max(0, i - r)];
        auto can = [&](long long target) {
            vector<long long> diff(n + 1, 0);
            long long active = 0, used = 0;
            for (int i = 0; i < n; ++i) {
                active += diff[i];
                long long need = target - power[i] - active;
                if (need <= 0) continue;
                used += need;
                if (used > k) return false;
                int p = min(n - 1, i + r);
                active += need;
                diff[min(n, p + r + 1)] -= need;
            }
            return true;
        };
        long long low = *min_element(power.begin(), power.end());
        long long high = low + k;
        while (low < high) {
            long long mid = low + (high - low + 1) / 2;
            if (can(mid)) low = mid;
            else high = mid - 1;
        }
        return low;
    }
};
