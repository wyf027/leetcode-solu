01 / Problem

题目与数据契约

以下为基于官方元数据的简明转述。原题为付费数据库题；页面保留完整表结构、输入与输出形式，不大段复制受限题面。

任务

表 Point 的每一行表示 X 轴上的一个整数坐标。编写查询，返回表中任意两个不同点之间的最短距离，结果列名必须为 shortest。

在一维数轴上，两点 a 与 b 的距离是 |a - b|。

Point 表结构

Column NameTypeKey
xintPrimary Key

主键保证坐标唯一；每行对应数轴上的一个点。

约束与约定

  • x 为整数主键，因此表中不会出现重复坐标。
  • 距离必须来自两条不同记录；判题数据提供足以形成点对的记录。
  • 坐标可以是负数、零或正数，结果是非负整数。
  • 进阶问题：如果点已经按 X 轴从左到右排列，怎样减少不必要的点对比较？

05 / Solution

排序后，只看邻居

把一维结构转化成数据库窗口：先定义稳定的顺序，再让每行看见它的前一个坐标。

INSIGHT 01

建立顺序

按 x 升序排列。无序表的物理行顺序没有语义，必须在窗口中明确写出 ORDER BY x。

INSIGHT 02

连接邻居

LAG(x) 为每个坐标取出紧挨着它的左邻居。当前值减去前值，就是相邻间距。

INSIGHT 03

聚合最小值

首行没有前驱，会产生 NULL；MIN 自动忽略它，并返回其余间距的最小值。

完整过程

  1. 从 Point 读取全部坐标。
  2. 用 LAG(x) OVER (ORDER BY x) 得到每个点的左邻居。
  3. 计算 x - prev_x。升序保证差值非负，无需 ABS。
  4. 对所有相邻差值取 MIN，别名设为 shortest。

正确性证明

设升序坐标为 x₁ < x₂ < … < xₙ。考虑任意非相邻点 xᵢ 与 xⱼ，其中 j > i + 1。

因为 xᵢ < xᵢ₊₁ < xⱼ，所以 xᵢ₊₁ − xᵢ < xⱼ − xᵢ。也就是说，每个非相邻点对都包含一个更短的相邻间距，因此全局最近点对一定出现在排序后的相邻元素之间。

查询枚举了全部相邻间距并取最小值，所以返回值恰为任意两点的最短距离。

边界情况

  • 只有两个点：唯一相邻差值就是答案。
  • 含负数与零：排序后的减法仍然正确。
  • 间距并列：只返回最短距离，不要求返回点对。
  • 重复坐标：由主键约束排除，否则答案可能为 0。
  • 首行的 LAG 为 NULL：聚合时被忽略。

复杂度

时间O(n log n)通用模型，主要来自排序
额外空间O(n)通用模型，排序/窗口执行状态

数据库的真实成本由执行计划、主键索引与引擎实现决定。若能沿 x 的有序索引扫描，排序成本可能被消除，核心扫描接近 O(n)。

完整代码

MySQL 是官方可提交语言。Java、JavaScript、Python、C++ 接收坐标数组，仅用于本地复现同一算法语义，不能作为本数据库题的 LeetCode 提交。

官方提交版本：窗口函数按 x 排序，并汇总相邻差。

# Write your MySQL query statement below
SELECT MIN(x - prev_x) AS shortest
FROM (
    SELECT
        x,
        LAG(x) OVER (ORDER BY x) AS prev_x
    FROM Point
) AS ordered_points;

本地语义参考：参数为 int[]，使用 long 保存坐标差。

import java.util.Arrays;

class Solution {
    public long shortestDistance(int[] points) {
        if (points == null || points.length < 2) {
            throw new IllegalArgumentException("At least two points are required");
        }

        int[] sorted = points.clone();
        Arrays.sort(sorted);
        long best = Long.MAX_VALUE;

        for (int i = 1; i < sorted.length; i++) {
            long gap = (long) sorted[i] - sorted[i - 1];
            best = Math.min(best, gap);
        }
        return best;
    }
}

本地语义参考：参数为 number[]；SQL INT 范围内的差值可由 Number 精确表示。

/** @param {number[]} points @return {number} */
function shortestDistance(points) {
  if (!Array.isArray(points) || points.length < 2) {
    throw new TypeError("At least two points are required");
  }

  const sorted = [...points].sort((a, b) => a - b);
  let best = Number.POSITIVE_INFINITY;

  for (let i = 1; i < sorted.length; i += 1) {
    best = Math.min(best, sorted[i] - sorted[i - 1]);
  }
  return best;
}

本地语义参考：参数为 list[int]，返回最小相邻差。

from typing import List


class Solution:
    def shortestDistance(self, points: List[int]) -> int:
        if len(points) < 2:
            raise ValueError("At least two points are required")

        ordered = sorted(points)
        return min(
            ordered[i] - ordered[i - 1]
            for i in range(1, len(ordered))
        )

本地语义参考：参数为 vector<int> 的副本，使用 long long 计算差值。

#include <algorithm>
#include <climits>
#include <stdexcept>
#include <vector>
using namespace std;

class Solution {
public:
    long long shortestDistance(vector<int> points) {
        if (points.size() < 2) {
            throw invalid_argument("At least two points are required");
        }

        sort(points.begin(), points.end());
        long long best = LLONG_MAX;

        for (size_t i = 1; i < points.size(); ++i) {
            long long gap =
                static_cast<long long>(points[i]) - points[i - 1];
            best = min(best, gap);
        }
        return best;
    }
};

替代方案：自连接

把每个点与右侧所有点连接：p1.x < p2.x，再取 MIN(p2.x - p1.x)。它兼容不支持窗口函数的旧版 MySQL，但逻辑候选点对为 O(n²)，数据变大时不如相邻扫描。

替代方案：相关子查询

为每个点寻找“大于它的最小 x”，再计算差值。写法能表达“右邻居”，但优化器相关，通常不如窗口函数清晰；需要检查执行计划与索引使用。

面试追问

  • 为什么窗口函数必须写 ORDER BY x？
  • 如果还要返回最近点对本身，怎样处理并列？
  • 若坐标允许重复、且 x 不再是主键，答案与查询要怎样变？
  • 怎样用 EXPLAIN 判断主键索引是否避免了额外排序？

常见错误

  • 写 LAG(x) OVER ()，错误依赖表的物理行顺序。
  • 自连接只排除相同值，却忘记控制方向，产生重复点对。
  • 窗口查询直接取第一行，未处理首行 NULL。
  • 通用语言版本原地排序，意外修改调用者传入的数组。
