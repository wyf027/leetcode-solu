质因数分解：把乘法拆到最划算

04 / 04

核心洞察

一次 Copy All 后连续粘贴若干次，会把屏幕字符数乘上一个整数。若这一段把数量乘以 k，那么它恰好需要 1 + (k - 1) = k 次操作。

因此问题等价于：把 n 写成若干整数因子的乘积，并让这些因子的和最小。合数因子还能继续拆小；最终最优代价就是 n 的所有质因数之和（含重复次数）。

n = p₁ × p₂ × … × pₖ
answer = p₁ + p₂ + … + pₖ

以 n = 12 为例

12 = 2 × 2 × 3，所以最少操作数是 2 + 2 + 3 = 7。

  • 1 → 2：复制一次、粘贴一次，共 2 步。
  • 2 → 4：复制一次、粘贴一次，共 2 步。
  • 4 → 12：复制一次、粘贴两次，共 3 步。

完整过程

  1. 从最小因子开始

    令试除因子 d = 2，答案 ans = 0。

  2. 反复提取

    只要 n % d == 0，就把 d 加入答案，并令 n /= d。

  3. 继续增大 d

    直到剩余 n = 1。每个被提取的 d 都是当前剩余数的最小因子，因此一定是质数。

正确性证明

  1. 轨迹可表示为因子乘积。 每段从一次复制开始，随后粘贴若干次。若该段共花费 k 步，它会把屏幕数量乘以 k。所以任意有效轨迹对应一组乘积为 n 的整数因子，其总操作数等于因子之和。
  2. 合数因子不优于拆分。 若某因子 k = a × b，其中 a,b ≥ 2，则 a + b ≤ a × b = k。把一段乘 k 拆成先乘 a、再乘 b，不会增加操作数。
  3. 质因数分解达到下界。 反复拆分所有合数因子后，只剩质因数；它们的乘积仍为 n，总和不大于任何原方案。算法恰好累加这些质因数，并能按相应分段构造轨迹，因此结果最优。

边界与复杂度

  • n = 1：初始即满足，答案为 0。
  • n 为质数：只能从 1 复制后粘贴 n - 1 次，答案为 n。
  • 重复质因数必须重复计入，例如 8 = 2 × 2 × 2，答案为 6。
时间O(√n) 级试除
空间O(1)

替代方案：动态规划

定义 dp[i] 为得到 i 个 A 的最少操作数。枚举 i 的因子 j：先用 dp[j] 步得到 j 个 A，再复制并粘贴，使数量扩大到 i，新增代价为 i / j。于是可用 dp[i] = min(dp[i], dp[j] + i / j) 转移。

这个方案更直观地复用了子问题，但通常需要 O(n²) 的朴素时间和 O(n) 空间；利用因子枚举可以优化。质因数分解写法更短、空间更省。

Implementations

四语言完整代码

JavaLeetCode 可提交
class Solution {
    public int minSteps(int n) {
        int answer = 0;

        for (int factor = 2; factor * factor <= n; factor++) {
            while (n % factor == 0) {
                answer += factor;
                n /= factor;
            }
        }

        // 若仍大于 1，剩余的 n 本身就是质因数。
        if (n > 1) {
            answer += n;
        }
        return answer;
    }
}

面试追问

为什么最小因子一定是质数？

若最小因子还是合数，它必然含有一个更小的非 1 因子，与“最小”矛盾。

若允许删除一个 A 呢？

单纯的乘法分段模型失效，需要把字符数和剪贴板内容一起作为状态，考虑 BFS 或动态规划。

能否只试除到 √n？

可以。试除结束后若剩余值大于 1，它必然是最后一个质因数，直接加入答案。

怎样构造具体按键序列？

对每个质因数 p，执行一次 Copy All，再执行 p−1 次 Paste；按质因数顺序串联即可。

常见错误

  • 把 Copy All 当成可以复制部分字符。
  • 忘记 n = 1 时答案是 0，而不是 1。
  • 质因数只累加一次；重复因子也必须重复加入。
  • 试除到平方根后，遗漏仍然大于 1 的最后质因数。
  • 使用贪心时只描述“尽量翻倍”，却没有证明它对非 2 的倍数成立。
