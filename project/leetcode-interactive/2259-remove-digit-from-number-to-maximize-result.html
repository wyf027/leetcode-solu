01 / THE CHALLENGE

题目说明

给定表示正整数的字符串 number，以及字符 digit。从字符串中删除恰好一个与 digit 相同的字符，其余字符顺序不变。返回能得到的最大十进制数对应的字符串。

只允许删除指定字符的一次出现；输入保证至少存在一个可删位置。结果类型仍是字符串。

参数与返回值

removeDigit(number: string, digit: character) → string

INPUT BOUNDARIES

约束

  • 2 ≤ number.length ≤ 100
  • number 只包含 '1' 到 '9'。
  • digit 是 '1' 到 '9' 中的一个字符。
  • digit 至少在 number 中出现一次。

思考：相同的字符出现在不同位置，删除后一定得到相同的结果吗？

官方示例

01 · 唯一位置

number = "123", digit = '3'
输出："12"

唯一的 '3' 在末尾，移除后得到 "12"。

02 · 不同结果

number = "1231", digit = '1'
输出："231"

删除第一个 '1' 得到 "231"，删除最后一个得到 "123"；前者更大。

03 · 相同结果

number = "551", digit = '5'
输出："51"

删除任意一个 '5'，结果均为 "51"。

04 / DEEP DIVE

准备好看题解了吗？

展开核心思路、正确性证明与四语言实现。

题解 · 枚举每一个合法删除位置

核心洞察

最多只有 100 个字符，直接尝试所有合法位置已经足够。每次删除一个字符，得到的字符串长度都是 n − 1；且没有前导零。因此按字典序比较字符串，就等价于比较十进制大小，无需转换为整数。

完整过程

  1. 用空字符串初始化 best。
  2. 从左到右遍历每个下标 i；若字符不等于 digit，跳过。
  3. 拼接 number[0:i] 与 number[i+1:n]，只删除当前位置。
  4. 若候选字符串比 best 大，更新 best；相等时保留原值即可。
  5. 遍历结束后返回 best。

以 number = "1231", digit = '1' 为例：删除下标 0 得 "231"，设为当前最大；删除下标 3 得 "123"，首位 1 小于 2，因此保留 "231"。实验台使用同样的候选枚举和比较过程。

正确性证明

覆盖性：任何合法结果都由删除某个等于 digit 的位置得到，遍历会访问这些位置且只生成合法结果。不变式：处理完前 k 个合法位置后，best 是这 k 个候选中的最大值。初次候选非空，必替换空字符串；此后每次取原 best 与新候选中的较大者，所以不变式成立。全部位置处理完成时，best 就是所有合法结果的最大值。等长数字串的字典序由第一个不同数字决定，与十进制大小一致，因此比较方式正确。

边界与复杂度

  • 目标只出现一次：直接得到唯一候选。
  • 连续相同数字、所有字符相同：可能有多个最优删除位置，返回相同字符串即可。
  • 删除首位或末位：允许一侧切片为空；n ≥ 2 保证结果非空。
  • 长度可到 100：不要转成 JavaScript Number、Java long 或 C++ long long。
  • 设合法位置有 k 个，每次构造与比较需 O(n)，总时间 O(n + kn)，最坏 O(n²)；仅保留当前候选和 best，额外空间 O(n)。可视化为回退保存历史状态，空间可能为 O(kn)，不代表提交算法。

四语言完整代码

以下均为对应语言的 LeetCode 提交形式；未编译、未运行。

Java

class Solution {
    public String removeDigit(String number, char digit) {
        String best = "";
        for (int i = 0; i < number.length(); i++) {
            if (number.charAt(i) != digit) continue;
            String candidate = number.substring(0, i)
                             + number.substring(i + 1);
            if (candidate.compareTo(best) > 0) best = candidate;
        }
        return best;
    }
}

/**

var removeDigit = function(number, digit) {
    let best = "";
    for (let i = 0; i < number.length; i++) {
        if (number[i] !== digit) continue;
        const candidate = number.slice(0, i) + number.slice(i + 1);
        if (candidate > best) best = candidate;
    }
    return best;
};

Python 3

class Solution:
    def removeDigit(self, number: str, digit: str) -> str:
        best = ""
        for i, char in enumerate(number):
            if char != digit:
                continue
            candidate = number[:i] + number[i + 1:]
            if candidate > best:
                best = candidate
        return best

C++

#include <string>
using namespace std;

class Solution {
public:
    string removeDigit(string number, char digit) {
        string best;
        for (int i = 0; i < static_cast<int>(number.size()); ++i) {
            if (number[i] != digit) continue;
            string candidate = number.substr(0, i) + number.substr(i + 1);
            if (candidate > best) best = candidate;
        }
        return best;
    }
};

替代方案 · O(n) 贪心

扫描时记录 digit 最后出现的位置。如果遇到某个 digit，且它右侧紧邻的字符更大，就立即选这个位置删除；若一直没有遇到，就删除最后一次出现的 digit。只在最后构造一次结果，时间 O(n)，包括结果字符串在内空间 O(n)，索引变量空间 O(1)。

理由：比较删除两个相同 digit 的结果，跳过它们之间开头连续的 digit 后，第一个不同字符决定优劣。若这个字符更大，提前删除使大字符左移；若更小，保留前面的 digit 更优。连续相等的位置删除效果相同，可以一路推迟到连续段末尾。因此第一个紧邻更大字符的 digit 可确定最优选择；若不存在这样的上升，删除位置越靠后越不差。

常见错误

  • 使用 replaceAll：会删除多次，不符合“恰好一次”。
  • 直接删第一次或最后一次："1231" 和 "54354" 展示了不同选择的影响。
  • 使用数值转换比较：长字符串可能溢出或失去精度。
  • 字符串长度不同时仍无条件按字典序比较：本题可行的前提是候选长度相同。
  • 贪心看到相等的下一位就立即返回："1151" 中过早返回会错过更合适的位置。

面试追问

  • 如果要返回删除下标？枚举时同时记录 best 的来源；相等时按题目要求决定是否更新。
  • 如果允许数字 0？保留原题“固定长度字符串”比较时仍可比较数值，但若要求规范化去前导零，需要单独处理返回格式。
  • 如果能删 k 个任意数字？可考虑单调栈，让较大数字尽早出现；这已经改变删除约束，不能直接照搬本题逻辑。
  • 为什么先讲枚举？它直接对应全部合法选择，n ≤ 100 时足够简单，且正确性容易说明；更大规模再选线性方案。
