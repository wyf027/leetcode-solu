Number of Ways to Stay in the Same Place After Some Steps

01 / Problem

题目是什么？

一个长度为 arrLen 的数组中，指针最初位于索引 0。每一步可以向左移动一格、向右移动一格，或停在原位；任何时候都不能越过数组边界。

给定整数 steps 与 arrLen，求恰好执行 steps 步后仍位于索引 0 的不同操作序列数量。结果对 10⁹ + 7 取模。

函数签名

numWays(steps, arrLen) → integer

关键字是“恰好”：少走或多走都不计入答案。

约束

  • 1 ≤ steps ≤ 500
  • 1 ≤ arrLen ≤ 10⁶

05 / Editorial

准备好查看完整题解了吗？

下面将揭示状态定义、转移方程、证明与完整代码。

Full Solution

动态规划：只保留可能返回原点的位置

核心洞察

完成全部 steps 步后要回到索引 0，那么走到最远位置 p 至少需要 p 次向右和 p 次向左。因此 p ≤ floor(steps / 2)。即使 arrLen 很大，也只需计算索引 0…min(arrLen - 1, floor(steps / 2))。

状态与完整过程

  1. 令 dp[i] 表示走完当前轮操作后，指针位于索引 i 的方案数。
  2. 初始尚未走任何一步，只有 dp[0] = 1。
  3. 新一轮到达 i，上一轮只能位于 i、i - 1 或 i + 1；越界项视为 0。
  4. 逐轮生成 next，每次相加后取模，再用 next 替换 dp。
  5. 完成 steps 轮后返回 dp[0]。
next[i] = (dp[i - 1] + dp[i] + dp[i + 1]) mod (10⁹ + 7)

正确性证明

引理 1：转移恰好覆盖所有合法序列

任何在本轮结束于索引 i 的序列，其最后一次操作只可能是：从 i - 1 向右、在 i 停留，或从 i + 1 向左。这三类按最后一次操作互斥，且覆盖全部可能，所以三项方案数之和既不遗漏也不重复。

引理 2：截断状态空间不会丢失答案

一条最终回到 0 的长度为 steps 的路径若到过索引 p，至少包含 p 次右移和 p 次左移，因此 2p ≤ steps。所以比 floor(steps / 2) 更远的位置不可能出现在有效路径上；数组右边界同样要求索引不超过 arrLen - 1。

定理

由初始状态可知 0 步时计数正确。假设上一轮所有位置计数正确，根据引理 1，转移后本轮计数正确；由数学归纳法，全部轮次均正确。引理 2 保证剪枝不改变回到原点的方案集合，因此最终 dp[0] 正是所求。

边界处理

  • arrLen = 1 时只能原地停留。
  • 索引 0 没有左侧来源。
  • 截断后的最右位置没有右侧来源。
  • 每轮求和都取模，避免数值膨胀。

复杂度

令 m = min(arrLen, floor(steps / 2) + 1)。

  • 时间复杂度：O(steps × m)
  • 空间复杂度：O(m)

四种语言完整代码

class Solution {
    private static final int MOD = 1_000_000_007;

    public int numWays(int steps, int arrLen) {
        int maxPos = Math.min(arrLen - 1, steps / 2);
        long[] dp = new long[maxPos + 1];
        dp[0] = 1;

        for (int step = 0; step < steps; step++) {
            long[] next = new long[maxPos + 1];
            for (int i = 0; i <= maxPos; i++) {
                next[i] = dp[i];
                if (i > 0) next[i] += dp[i - 1];
                if (i < maxPos) next[i] += dp[i + 1];
                next[i] %= MOD;
            }
            dp = next;
        }
        return (int) dp[0];
    }
}

替代方案

  • 二维动态规划：dp[step][position] 更直观，适合第一次推导，但空间为 O(steps × m)。
  • 记忆化搜索：以“剩余步数、当前位置”为状态递归，语义清晰，但有递归开销，也要注意剪枝与栈深。
  • 矩阵快速幂：能把步数维度降为对数，但状态矩阵仍与有效数组宽度相关；在本题 steps ≤ 500 下实现复杂度不划算。

面试追问

  1. 为什么上界是 floor(steps / 2)，而不是 steps？
  2. 滚动数组为什么必须使用全新的 next，不能从左到右原地更新？
  3. 如果每个位置允许的操作不同，状态转移怎样改？
  4. 若要查询许多不同的 steps，是否值得预处理或使用矩阵方法？

常见错误

  • 直接开长度为 arrLen 的数组，忽略其最大可达 10⁶。
  • 把“最多 steps 步”误读为“恰好 steps 步”。
  • 原地更新一维数组，导致本轮的新值污染同一轮后续计算。
  • 忘记过滤左边界或右边界，产生越界访问。
  • 等到最后才取模，使固定宽度整数发生溢出。
