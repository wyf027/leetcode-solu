完成所有工作的
最短时间 II

Find Minimum Time to Finish All Jobs II

同样的一组工作，交给不同的人，会在哪一天全部完成？

01 / PROBLEM

题意

给定等长整数数组 jobs 与 workers。jobs[i] 表示第 i 项工作所需的总工作时间，workers[j] 表示第 j 位工人每天可投入的工作时间。把工作与工人一一对应：每项工作只交给一人，每人只负责一项。

所有工人可以并行工作，未完成的工作可以延续到后续天数。返回使全部工作完成的最少整数天数。一天内有余力，也不能再接另一项工作。

参数：minimumTime(jobs, workers) → integer
先思考：最后收工的那个人，会如何影响整体完成时间？

约束

  • n == jobs.length == workers.length
  • 1 ≤ n ≤ 105
  • 1 ≤ jobs[i], workers[i] ≤ 105

04 / SOLUTION

同序配对，寻找最慢的一组

核心洞察

一组的用时为 ⌈工作量 / 每日能力⌉；所有组同时进行，所以整体用时取最大值。将两个数组分别升序排序，让较小工作对应较小能力，较大工作对应较大能力，就能最小化这个最大值。

答案 = maxi ⌈sorted(jobs)[i] / sorted(workers)[i]⌉

完整过程

  1. 分别将 jobs、workers 按数值从小到大排序。
  2. 依次配对同位置元素 j 和 w。
  3. 用整数公式 (j + w − 1) / w 向下取整，得到向上取整的天数。
  4. 维护最大天数，扫描结束后返回。

示例 1：排序后 jobs = [2,4,5]、workers = [1,5,7]；三组用时为 [2,1,1]，答案为 2。排序后的下标与原始身份不同，演示保留 J / W 原始编号。

正确性：交换一对交叉分配

设两项工作 a ≤ b，两位工人的能力 x ≤ y。若大工作 b 交给较弱工人 x、小工作 a 交给较强工人 y，旧方案的用时为 T = max(⌈b/x⌉, ⌈a/y⌉)。改为 a→x、b→y 后：

  • 由于 a ≤ b，有 ⌈a/x⌉ ≤ ⌈b/x⌉ ≤ T。
  • 由于 x ≤ y，有 ⌈b/y⌉ ≤ ⌈b/x⌉ ≤ T。

因此交换不会增加整体完成时间。把工作按大小排好后，反复消除其对应工人能力序列中的逆序对，最终得到两个数组同序配对。任意最优方案都能这样转换且不会变差，所以同序配对也是最优的。最后取各组用时最大值，恰好等于所有人完成工作的时间。

边界与常见错误

  • 只有一组：直接向上取整；工作量小于每日能力也至少需要 1 天。
  • 重复值：顺序不影响最优值，稳定排序不是必要条件。
  • 不要求所有组天数的和：工人是并行工作的。
  • 不要一升一降：jobs=[2,10]、workers=[1,5] 同序只需 2 天，反序需要 10 天。
  • 不要把 workers 当成“每单位工作的耗时”：它表示每日能工作多少时间，越大越强。
  • JS 的 sort() 默认按字符串排列，必须传入 (a,b) => a-b。
  • 向下取整会漏掉最后一天；例如 7/3 应为 3 天。
  • 下列实现会修改两个输入数组。若调用方需要原数组，请先复制。

复杂度与数值范围

排序占主导，时间为 O(n log n)，扫描为 O(n)。扫描只维护一个答案，额外空间 O(1)；总辅助空间取决于排序实现：C++ 常见实现 O(log n)，Python 排序最坏 O(n)，Java 与 JavaScript 随运行时实现而异，保守预留 O(n)。不能把所有语言的总空间统一写成 O(1)。

答案范围是 [1,100000]，j+w−1 ≤ 199999，因此这些代码中的整数计算安全。若扩展数值范围，Java/C++ 可用 64 位；检查 D×w 时也要注意可能达到 1010。

替代方案

可以二分天数 D。先同序排序，再检查每一组是否满足 jobs[i] ≤ D×workers[i]；可行性随 D 单调，二分区间为 [1,max(jobs)]。时间 O(n log n + n log M)，M=max(jobs)。本题可直接求比值的最大值，二分增加了不必要的重复扫描。枚举工人排列则约需 O(n!·n)，只适合极小规模推导。

面试追问

如果还要返回具体的原始分配呢？

排序时携带原始下标，例如 [value,index]，按排序位置配对后返回原工作编号与原工人编号。需要 O(n) 的索引存储。

可以仅比较总工作量和总每日能力吗？

不行。jobs=[1,10]、workers=[5,6] 总量看起来 1 天足够，但没有人能在一天完成工作量 10，而且工作不能拆给两个人。

如果每个人可以接多项工作？

一一配对的条件消失，交换证明也不再覆盖累积负载问题，需要根据新约束重新设计调度算法，不能直接复用这段排序结论。

最优配对一定唯一吗？

不一定。重复值、向上取整以及最大值的掩盖效应，都可能使不同方案具有相同完成天数。同序配对只保证给出其中一个最优方案。

四种语言实现

函数签名与官方元数据一致。以下代码面向 LeetCode 提交环境，无需额外 main；均待补验证。

Java

import java.util.Arrays;

class Solution {
    public int minimumTime(int[] jobs, int[] workers) {
        Arrays.sort(jobs);
        Arrays.sort(workers);
        int answer = 0;
        for (int i = 0; i < jobs.length; i++) {
            int days = (jobs[i] + workers[i] - 1) / workers[i];
            answer = Math.max(answer, days);
        }
        return answer;
    }
}

JavaScript

/**
 * @param {number[]} jobs
 * @param {number[]} workers
 * @return {number}
 */
var minimumTime = function(jobs, workers) {
    jobs.sort((a, b) => a - b);
    workers.sort((a, b) => a - b);
    let answer = 0;
    for (let i = 0; i < jobs.length; i++) {
        answer = Math.max(answer, Math.ceil(jobs[i] / workers[i]));
    }
    return answer;
};

Python

from typing import List

class Solution:
    def minimumTime(self, jobs: List[int], workers: List[int]) -> int:
        jobs.sort()
        workers.sort()
        answer = 0
        for job, worker in zip(jobs, workers):
            answer = max(answer, (job + worker - 1) // worker)
        return answer

C++

#include <algorithm>
#include <vector>
using namespace std;

class Solution {
public:
    int minimumTime(vector<int>& jobs, vector<int>& workers) {
        sort(jobs.begin(), jobs.end());
        sort(workers.begin(), workers.end());
        int answer = 0;
        for (int i = 0; i < static_cast<int>(jobs.size()); ++i) {
            int days = (jobs[i] + workers[i] - 1) / workers[i];
            answer = max(answer, days);
        }
        return answer;
    }
};
