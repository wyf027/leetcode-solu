Interview 04.06

后继者 在中序跑道上锁定第一个更大的航标

不必展开整条中序序列。沿着 BST 向下：更大的节点先进入候选区，再向左寻找更近的落点； 小于等于目标时向右追赶。最终留下的就是严格大于 p.val 的最小节点。

Before solution

先问自己两个问题

  1. 01 当前值比 p.val 大时，为什么可以安全地向左？
  2. 02 当前值不够大时，哪一整侧子树可以直接排除？

完整题解默认隐藏，可先独立推演。

Problem

题意

给定一棵二叉搜索树 root 和其中一个节点 p，返回 p 在中序遍历中的下一个节点；如果不存在后继，返回 null。

中序后继等价于：整棵树里所有严格大于 p.val 的节点中，值最小的那一个。

  • 输入是一棵合法 BST，节点值唯一。
  • p 是树中的真实节点。
  • 返回值必须是节点对象，而不是只返回节点值。

官方示例 1

输入

root = [2,1,3], p = 1

输出

2

官方示例 2

输入

root = [5,3,6,2,4,null,null,1], p = 6

输出

null

可见字符说明：若字符串输入包含普通空格，本页统一显示为 ␠；本题没有字符串参数。

Solution

题解：维护“严格更大”的最近候选

推荐 · BST 定向搜索

Core insight

核心洞察

若 root.val > p.val，当前节点满足“更大”，可以先记为候选； 但左子树可能有更小且仍然更大的节点，所以继续向左。否则当前节点和它的左子树都不可能成为后继，直接向右。

Invariant

循环不变量

每轮开始时，answer 要么为空，要么是所有已访问节点中 严格大于 p.val 的最小值；尚未搜索的唯一可能更优区域就是当前子树。

Full process

完整过程与正确性

  1. 令 answer = null，从根节点开始。
  2. 当前值更大：它有资格成为后继，更新候选并进入左子树寻找更小答案。
  3. 当前值小于等于目标：它以及左子树都不够大，进入右子树。
  4. 走到空节点时，所有可能更优的区域均已排除，候选就是答案。

每一步都基于 BST 的区间性质删除不可能区域，同时保持候选为已见的最小合法值；循环结束时不存在未检查的更小合法节点，因此结果正确。

Complexity

复杂度

时间 O(h)；平衡树为 O(log n)，退化树最坏 O(n)。 额外空间 O(1)。

Boundary

边界

最大节点没有后继；目标有右子树时答案是右子树最左节点；祖先也可能成为答案；单节点树返回 null。

Alternative

替代方案

完整中序遍历再找下一个节点，时间 O(n)、栈空间 O(h)；逻辑直观但没有利用 BST。

Follow-up

面试追问

若节点带父指针怎么办？若允许重复值怎么办？若连续查询很多次，是否值得预处理整条中序链？

Common mistakes

常见错误

  • 把条件写成 root.val >= p.val，错误地允许目标自身。
  • 遇到更大值后直接返回，错过左侧更小的合法节点。
  • 只检查 p.right，忽略后继可能来自祖先。
  • 返回整数值而不是题目要求的 TreeNode。 
class Solution {
    public TreeNode inorderSuccessor(TreeNode root, TreeNode p) {
        TreeNode answer = null;

        while (root != null) {
            if (root.val > p.val) {
                answer = root;
                root = root.left;
            } else {
                root = root.right;
            }
        }

        return answer;
    }
}
