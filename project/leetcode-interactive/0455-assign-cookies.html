分发饼干

每个孩子最多拿一块饼干。你能让多少个孩子得到满足？先理解规则，再亲手推进分配过程。

Problem

题目描述

有一组孩子和一组饼干。孩子 i 的胃口值为 g[i]，表示能让他满足的饼干最小尺寸；饼干 j 的尺寸为 s[j]。当 s[j] >= g[i] 时，这块饼干可以满足这个孩子。

每个孩子最多获得一块饼干，每块饼干也只能分给一个孩子。请返回最多能被满足的孩子数量。

示例 1

输入：g = [1,2,3], s = [1,1]
输出：1
解释：两块饼干尺寸均为 1，只能满足胃口值为 1 的孩子。

示例 2

输入：g = [1,2], s = [1,2,3]
输出：2
解释：饼干的数量和尺寸足以满足两个孩子。

Limits

参数与约束

函数形式

findContentChildren(g, s) -> integer
  • 1 <= g.length <= 3 * 104
  • 0 <= s.length <= 3 * 104
  • 1 <= g[i], s[j] <= 231 - 1
参数含义

g 是孩子胃口数组，s 是饼干尺寸数组；返回值是最多可满足的孩子数。

Solution

准备好看完整题解了吗？

先尝试用上面的实验台归纳规律，再展开答案。

Greedy · Sorting · Two Pointers

排序 + 双指针

核心洞察

把孩子和饼干都从小到大排序。面对当前胃口最小、尚未满足的孩子：如果当前最小饼干能满足他，就完成配对；否则这块饼干连胃口最小的孩子都无法满足，只能跳过。

完整过程

  1. 升序排序 g 和 s。
  2. 令 i = 0 指向当前孩子，j = 0 指向当前饼干。
  3. 若 s[j] >= g[i]，配对成功，同时移动 i 与 j。
  4. 否则仅移动 j，舍弃过小的饼干。
  5. 任一数组遍历结束时，i 就是最大满足人数。

正确性说明

配对时：能满足当前最小胃口孩子的最小饼干，是最节省资源的选择。若改用更大的饼干，不会增加当前收益，还可能削弱后续选择。

跳过时：若当前饼干小于最小未满足胃口，它也必然小于所有后续更大的胃口，因此不可能参与任何有效配对。不断执行这两个安全选择，最终得到最大匹配数。

边界情况

  • 饼干数组为空：答案为 0。
  • 所有饼干都太小：不断跳过，答案为 0。
  • 饼干足够多且足够大：所有孩子都可满足。
  • 存在重复胃口或重复尺寸：排序与比较逻辑不变。
  • 数值可达 231 - 1，仅比较，不做可能溢出的减法。

复杂度

设孩子数为 m，饼干数为 n。

时间：O(m log m + n log n)，主要来自排序；双指针扫描为 O(m + n)。

空间：取决于语言排序实现，通常为 O(log m + log n) 到 O(m + n)；双指针本身为 O(1)。

替代方案

可以将某一侧放入平衡树或有序多重集合，再为每个孩子寻找最小可用饼干，复杂度通常为 O((m+n) log n)。它更适合动态加入或删除饼干的场景；对静态数组，本题的排序双指针更简单。

也可以从大到小匹配最大胃口与最大饼干，本质上仍是同一个贪心交换逻辑。

常见错误

  • 不排序就直接双指针，导致选择依赖原数组顺序。
  • 饼干太小时移动孩子指针，错误地放弃了仍可能被更大饼干满足的孩子。
  • 配对成功后只移动一个指针，重复使用孩子或饼干。
  • 用两数相减判断大小，在固定宽度整数语言里引入溢出风险。

import java.util.Arrays;

class Solution {
    public int findContentChildren(int[] g, int[] s) {
        Arrays.sort(g);
        Arrays.sort(s);

        int child = 0;
        int cookie = 0;
        while (child < g.length && cookie < s.length) {
            if (s[cookie] >= g[child]) {
                child++;
            }
            cookie++;
        }
        return child;
    }
}

面试追问

  1. 为什么不能优先把最大饼干给最小胃口？
    这可能浪费能满足大胃口孩子的稀缺大饼干；最小可行资源更稳妥。
  2. 如果每个孩子可以拿多块饼干呢？
    问题结构已经改变，当前“一对一匹配”的贪心证明不再适用，需要根据是否允许组合、是否要求连续等条件重新建模。
  3. 如果数据持续流入、不能一次排序呢？
    可考虑平衡树、堆或计数结构维护未匹配项，选择取决于值域、到达顺序与是否允许延迟决策。
  4. 能否稳定保留原始下标？
    可以排序 (值, 原下标) 对并记录配对；最大人数不变，但额外需要存储下标。
