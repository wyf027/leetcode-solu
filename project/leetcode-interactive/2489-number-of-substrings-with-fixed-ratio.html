STRING / FIXED RATIO

固定比率的子字符串数

Number of Substrings With Fixed Ratio

在一串 0 与 1 中，寻找数量配比恰好吻合的连续片段。
相同内容出现在不同位置，也要分别计数。

连续子字符串计数问题先思考，再展开题解

01 / PROBLEM

题意与输入范围

给定只含 0、1 的字符串 s，以及互质正整数 num1、num2。统计所有非空连续子字符串，使其中 0 的个数 : 1 的个数 = num1 : num2，返回满足条件的子字符串数量。互质表示两个整数的最大公约数为 1。

参数与返回值

fixedRatio(s, num1, num2) → long

s：二进制字符串；num1：0 的配比；num2：1 的配比。子字符串按起止位置区分，允许相互重叠。

约束

  • 1 ≤ s.length ≤ 105
  • s[i] ∈ {'0', '1'}
  • 1 ≤ num1, num2 ≤ s.length
  • gcd(num1, num2) = 1

02 / EXAMPLES

官方示例

示例 1

输入：s = "0110011", num1 = 1, num2 = 2
输出：4

以 0 为起点编号，符合条件的区间为 [0,2]、[1,3]、[4,6]、[1,6]，内容依次是 011、110、011、110011。最后一个片段有 2 个 0 和 4 个 1，配比仍为 1:2。

示例 2

输入：s = "10101", num1 = 3, num2 = 1
输出：0

整个字符串只有 2 个 0，无法取到 3 个 0 与 1 个 1 的最小配比，因此没有符合条件的片段。

思考起点

04 / SOLUTION

把配比变成“回到同一高度”

核心洞察

用 Z(i)、O(i) 表示前 i 个字符中的 0 和 1 数量，定义加权前缀值 D(i) = num2 × Z(i) − num1 × O(i)。读到 0 就上升 num2，读到 1 就下降 num1。

区间 [l, r) 合法
⇔ (Z(r) − Z(l)) × num2 = (O(r) − O(l)) × num1
⇔ D(r) = D(l)，且 l < r

因此每遇到一个新前缀，只需查询此前同一高度出现了几次；每个旧前缀都贡献一个合法片段。哈希表保存次数，无需保存所有片段。

    完整过程

    1. 令高度 d = 0、答案 ans = 0，初始化频次表 {0: 1}，表示空前缀。
    2. 从左至右读取每个字符：0 使 d 加 num2，1 使 d 减 num1。
    3. 取出旧频次 k = freq[d]（没有则为 0），把 k 加入答案。
    4. 把当前前缀存入表：freq[d] = k + 1。
    5. 扫描结束后返回答案。

    示例 1 的前缀高度依次为 0, 2, 1, 0, 2, 4, 3, 2。r = 3 时增加 1，r = 4 时增加 1，r = 7 时增加 2，合计 4。

    正确性论证

    不变量：处理右边界 r 之前，表中记录的恰好是 D(0)…D(r−1) 的频次。

    充分必要：两个前缀等高，当且仅当它们之间 0、1 的数量满足交叉相乘的配比条件。由于比例双方为正且片段非空，这也保证两种字符都存在。

    无漏无重：旧表中的每个等高前缀给出唯一左边界，因而本步恰好统计所有以 r 结束的合法片段。不同 r 的右边界不同，不会重复。查询后再入表维持不变量，并排除空片段。

    边界与复杂度

    • 单字符、全 0、全 1 都不可能满足正比例，答案为 0。
    • 互质时合法长度必须为 num1 + num2 的正倍数；若该和超过 n，则答案为 0。
    • 不能只统计精确的 num1 个 0、num2 个 1；共同倍数也符合。
    • 哈希操作平均 O(1)，总时间期望 O(n)，空间 O(n)。极端碰撞下哈希性能不保证。
    • |D| ≤ 10¹⁰，答案 ≤ n(n+1)/2。Java 用 long，C++ 用 long long；Python 整数自动扩展；JavaScript Number 在此范围内精确。

    替代方案

    • 枚举左、右端点并递增统计字符：O(n²) 时间、O(1) 辅助空间，只适合小输入。
    • 收集 n+1 个前缀并排序：同一高度有 k 个前缀，贡献 k(k−1)/2。O(n log n) 时间、O(n) 空间，避免依赖哈希平均性能。
    • 普通滑动窗口不适用：加入 0 或 1 会让差值朝相反方向变化，没有统一的单调收缩规则。

    面试追问与常见错误

    • 比例不互质怎么办？原公式依然成立；可先除以 gcd，缩小高度数值。
    • 如果要求最长片段？保存每个高度最早出现的前缀位置，再最大化距离。
    • 能否处理字符流？可以，只保留当前高度、频次表和累计答案。
    • 不要把 0 的权重写成 num1；正确权重是 +num2 与 −num1。
    • 不要忘记空前缀，也不要先入表再计数，后者会把空区间算进去。
    • 不要用浮点除法比较比率，或用 Set 代替频次表；同高度的多个位置都要计数。

    Java

    import java.util.HashMap;
import java.util.Map;

class Solution {
    public long fixedRatio(String s, int num1, int num2) {
        Map<Long, Long> freq = new HashMap<>();
        freq.put(0L, 1L);
        long d = 0, ans = 0;
        for (int i = 0; i < s.length(); i++) {
            d += s.charAt(i) == '0' ? num2 : -num1;
            long count = freq.getOrDefault(d, 0L);
            ans += count;
            freq.put(d, count + 1);
        }
        return ans;
    }
}
