Problem

题目描述

给定用户表 Users 与赛事注册表 Register，统计每个已出现在注册表中的赛事，其注册用户数占全部用户数的百分比，并将结果四舍五入到两位小数。

结果先按 percentage 降序排列；百分比相同时，再按 contest_id 升序排列。

约束与数据保证

  • Users.user_id 唯一，且 Users 至少包含一名用户。
  • Register 中的 (contest_id, user_id) 组合唯一，因此同一用户不会在同一赛事被重复计数。
  • Register.user_id 对应 Users 中存在的用户。
  • 仅需输出注册表中实际出现过的赛事；百分比按要求保留两位小数。

Solution

题解：一次分组，一次全局计数

核心洞察

分子来自 Register：每个赛事有多少条唯一用户注册记录。分母来自 Users：全站一共有多少用户。分母对所有分组相同，可以用一个不相关子查询取得。

排序是结果的一部分

先按计算后的百分比降序，再按赛事编号升序。不能只写第一个排序键，否则并列结果的顺序不满足题意。

完整过程

  1. 扫描 Register，按 contest_id 分组。
  2. 每组执行 COUNT(user_id)，得到赛事注册人数。
  3. 用子查询 SELECT COUNT(*) FROM Users 得到共同分母。
  4. 计算 注册人数 * 100.0 / 总用户数，再用 ROUND(..., 2) 保留两位小数。
  5. 按 percentage DESC, contest_id ASC 输出。

官方可提交语言 · MySQL

MySQL主答案
SELECT
    contest_id,
    ROUND(COUNT(user_id) * 100.0 / (SELECT COUNT(*) FROM Users), 2) AS percentage
FROM Register
GROUP BY contest_id
ORDER BY percentage DESC, contest_id ASC;

正确性说明

对任意赛事 c，联合主键保证 Register 中赛事 c 的每一行对应一名不同的注册用户，因此分组后的 COUNT(user_id) 正好等于赛事 c 的注册用户数。子查询得到全部用户数，两者相除并乘 100 即为所求注册率；ROUND 完成两位小数处理。最后两个排序键分别实现百分比降序和并列时赛事编号升序，所以返回结果完全符合要求。

边界情况

  • 某赛事只有 1 人注册。
  • 全部用户都注册，结果为 100。
  • 多个赛事百分比相同，必须按编号升序。
  • 百分比出现循环小数，需要四舍五入。

复杂度

设注册记录数为 R，用户数为 U，赛事数为 C。概念上聚合为 O(R)，计数用户为 O(U)，结果排序为 O(C log C)；额外聚合空间约 O(C)。数据库实际代价取决于索引和执行计划。

替代方案

可将用户总数写成 CROSS JOIN (SELECT COUNT(*) ...)，使“共同分母”更显式；也可用窗口聚合构造总数，但对本题两张表而言通常更绕。不要把 Users 与 Register 直接无条件连接后再计数，那会放大行数。

诚实标注：本题是数据库题，LeetCode 官方提交语言以 SQL（及 Pandas）为主。以下四份代码只是在本地集合上复现相同“分组 → 百分比 → 排序”语义，不能作为本题的官方语言提交。

import java.util.*;

public class ContestPercentage {
    public record Registration(int contestId, int userId) {}
    public record Result(int contestId, double percentage) {}

    public static List<Result> solve(
            List<Integer> users, List<Registration> registrations) {
        Map<Integer, Integer> counts = new HashMap<>();
        for (Registration row : registrations) {
            counts.merge(row.contestId(), 1, Integer::sum);
        }
        List<Result> answer = new ArrayList<>();
        for (Map.Entry<Integer, Integer> entry : counts.entrySet()) {
            double raw = entry.getValue() * 100.0 / users.size();
            double rounded = Math.round(raw * 100.0) / 100.0;
            answer.add(new Result(entry.getKey(), rounded));
        }
        answer.sort(Comparator.comparingDouble(Result::percentage).reversed()
                .thenComparingInt(Result::contestId));
        return answer;
    }
}
function usersPercentage(users, registrations) {
  const counts = new Map();
  for (const { contestId } of registrations) {
    counts.set(contestId, (counts.get(contestId) ?? 0) + 1);
  }

  return [...counts].map(([contestId, count]) => ({
    contestId,
    percentage: Math.round((count * 100 / users.length) * 100) / 100,
  })).sort((a, b) =>
    b.percentage - a.percentage || a.contestId - b.contestId
  );
}
from collections import Counter
from typing import NamedTuple

class Registration(NamedTuple):
    contest_id: int
    user_id: int

def users_percentage(users: list[int], registrations: list[Registration]):
    counts = Counter(row.contest_id for row in registrations)
    result = [
        (contest_id, round(count * 100 / len(users) + 1e-12, 2))
        for contest_id, count in counts.items()
    ]
    return sorted(result, key=lambda row: (-row[1], row[0]))
#include <algorithm>
#include <cmath>
#include <unordered_map>
#include <utility>
#include <vector>

struct Registration { int contestId; int userId; };

std::vector<std::pair<int, double>> usersPercentage(
    const std::vector<int>& users,
    const std::vector<Registration>& registrations) {
    std::unordered_map<int, int> counts;
    for (const auto& row : registrations) ++counts[row.contestId];

    std::vector<std::pair<int, double>> answer;
    for (const auto& [contestId, count] : counts) {
        double raw = count * 100.0 / users.size();
        answer.push_back({contestId, std::round(raw * 100.0) / 100.0});
    }
    std::sort(answer.begin(), answer.end(), [](const auto& a, const auto& b) {
        if (a.second != b.second) return a.second > b.second;
        return a.first < b.first;
    });
    return answer;
}

面试追问

  • 若允许重复报名，如何改成 COUNT(DISTINCT user_id)？
  • 若还要展示零报名赛事，需要从哪张赛事维表出发？
  • 如何避免整数除法导致百分比被截断？
  • 数据量很大时，哪些索引有助于分组？

常见错误

  • 分母误写为注册表的总行数。
  • 遗漏乘以 100 或使用整数除法。
  • 只按百分比排序，遗漏并列规则。
  • 先四舍五入人数比例，再乘以 100，造成精度损失。
