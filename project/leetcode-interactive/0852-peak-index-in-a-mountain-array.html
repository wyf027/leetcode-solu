核心洞察

比较 mid 与右邻居

斜率就是方向标。若 arr[mid] < arr[mid + 1]，当前位置仍在上坡，峰顶必在 mid 右侧；否则已在下坡或正位于峰顶，峰顶位于 [left, mid]。因此每次都能安全丢弃一半区间。
完整过程

保留峰顶所在的闭区间

  1. 初始化：令 left = 0，right = n - 1。闭区间 [left, right] 一定包含峰顶。
  2. 取中点：当 left < right，取 mid = left + (right - left) / 2 的向下取整。此时 mid < right，所以 mid + 1 不越界。
  3. 判断坡向：若 arr[mid] < arr[mid + 1]，说明仍在上坡，令 left = mid + 1；否则令 right = mid。
  4. 收敛：循环结束时 left == right，候选区间只剩一个位置，它就是峰顶下标。
正确性

循环不变量证明

不变量

每轮循环开始时，唯一峰顶下标始终位于闭区间 [left, right] 内。

初始化

开始时区间覆盖整个数组，因此峰顶必然在其中。

保持

上坡时峰顶严格在 mid 右侧；非上坡时，凭山脉的单峰性质，峰顶不可能在 mid 右侧，所以两种更新都不会丢掉峰顶。

终止

区间长度每轮严格缩短。终止时仅剩 left == right，由不变量知该唯一位置就是峰顶。

边界与复杂度

为什么不会越界

  • 仅在 left < right 时取中点，向下取整保证 mid < right，因此读取 arr[mid + 1] 安全。
  • 山脉数组长度至少为 3，峰顶不会位于首尾；算法本身仍可从完整闭区间开始。
  • 时间复杂度：O(log n)，每次将候选区间大约减半。
  • 空间复杂度：O(1)，只使用常数个变量。
完整代码

四种语言，同一不变量

class Solution {
    public int peakIndexInMountainArray(int[] arr) {
        int left = 0;
        int right = arr.length - 1;

        while (left < right) {
            int mid = left + (right - left) / 2;
            if (arr[mid] < arr[mid + 1]) {
                left = mid + 1;
            } else {
                right = mid;
            }
        }
        return left;
    }
}

替代方案

能做，但不都是最优选择

线性扫描

从左向右找到第一个满足 arr[i] > arr[i + 1] 的位置即可，思路直观，时间为 O(n)，不满足本题指定的 O(log n) 要求。

三分查找

单峰函数也可用三分思想缩小区间，但每轮比较与边界处理更复杂；利用相邻斜率的二分查找更简洁，也拥有相同的对数级时间复杂度。

面试追问

把不变量讲清楚

为什么下降时令 right = mid，而不是 mid - 1？

因为 mid 自己可能就是峰顶。令 right = mid - 1 会错误地把答案排除。

为什么上升时可以排除 mid？

既然 arr[mid] < arr[mid + 1]，mid 就不可能是峰顶；唯一峰顶必在更右侧。

如果数组不保证是山脉，算法还正确吗？

它仍可能找到某个局部峰值，但不再保证符合本题的唯一峰顶语义。正确性证明依赖“先严格增、后严格减”的输入前提。

能否把搜索范围设为 1 到 n - 2？

可以，因为合法山脉的峰顶不在首尾；不过从 0 到 n - 1 开始更统一，并且同样安全。

常见错误

四个容易滑坡的细节

  • 循环写成 left <= right，却仍访问 mid + 1，可能越界。
  • 下降时写成 right = mid - 1，遗漏 mid 恰为峰顶的情况。
  • 上升时写成 left = mid，在相邻两元素区间中无法收敛。
  • 扫描最大值虽能得出答案，但复杂度为 O(n)，不符合题目要求。
