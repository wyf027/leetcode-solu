K 次增加后的最大乘积

Maximum Product After K Increments

把有限的增加次数，分配给一组数字。怎样才能让最终的乘积最大？

01 / PROBLEM

题目要做什么

给定非负整数数组 nums 和整数 k。一次操作可以选择数组中的任意一个元素，将其加 1。你可以执行至多 k 次操作，求最终数组能达到的最大乘积。

返回这个最大乘积对 1,000,000,007 取余的结果。先比较真实乘积的大小，最后才取余。

输入：nums: 整数数组、k: 整数
输出：integer · 函数名：maximumProduct
BOUNDARIES

约束与思考

  • 1 ≤ nums.length ≤ 10⁵
  • 1 ≤ k ≤ 10⁵
  • 0 ≤ nums[i] ≤ 10⁶

同一个位置可以被多次选择。不同的操作方案可能获得相同的最大乘积。

先想一想：当数组中有多个零时，一次增加一定能让乘积变大吗？

02 / EXAMPLES

官方示例

示例 1

输入：nums = [0,4], k = 5
输出：20

把第一个元素增加 5 次，得到 [5,4]，乘积为 5 × 4 = 20。这是可达到的最大值。

示例 2

输入：nums = [6,3,3,2], k = 2
输出：216

第二个、第四个元素各增加一次，得到 [6,4,3,3]，乘积为 6 × 4 × 3 × 3 = 216。

核心洞察：先增加当前最小值

只看两个元素 a ≤ b：给较小值加一，得到 (a+1)b；给较大值加一，得到 a(b+1)。前者减后者为 b−a ≥ 0。再乘上其余非负元素，这个大小关系仍然成立。

因此，每次把当前最小的数加一。用最小堆维护这些数，每次更新堆顶后恢复堆序，最后累乘取模。单步比较提供直觉，下面的交换论证说明它在多步分配中也成立。

  1. 把全部元素放入最小堆。
  2. 重复 k 次：取出最小值 x，放回 x+1。
  3. 遍历堆中所有元素，用足够宽的整数逐项相乘并取模。

[0,4] → [1,4] → [2,4] → [3,4] → [4,4] → [5,4]。前四步逐渐补齐较小值，最后一次在两个 4 中任选一个，最终乘积为 20。示例 2 则可以走成 [6,3,3,2] → [6,3,3,3] → [6,4,3,3]。

交换论证：存在以贪心操作开头的最优方案

增加非负元素不会降低乘积，所以总存在用满 k 次的最优方案。设当前最小值为 a，考虑任意一个最优分配。如果它给 a 至少分配一次增加，就可以把这次操作移到最前面。

否则，从另一个获得增加的元素 b 中挪一次给 a。设 b 在原方案结束后的值为 B，则 B ≥ b+1 ≥ a+1。变更前后这两个位置的乘积差为：

(a+1)(B−1) − aB = B−a−1 ≥ 0

其他位置的最终值不变且非负，所以总乘积不会下降。于是总能找到一个先增加当前最小值的最优方案。执行这一步后，对剩余 k−1 次操作重复同样的论证，归纳得到整体最优。这个证明不使用除法，零也适用。

堆的不变量

堆中始终恰好存放当前数组的所有元素，堆顶是最小值。每次替换堆顶并恢复堆序，正好实现上面的贪心选择。只增加堆顶时，新值不可能违反与父节点的关系，因此 JavaScript 实现只需向下调整。

边界、复杂度与替代方案

  • 多个零：若 k 小于零的数量，最后仍有零，最大乘积为 0；单步乘积不变不代表该步无效。
  • 相等最小值：任取一个增加即可，不要求输出唯一的最终数组。
  • 单元素：答案就是 nums[0]+k 再取模；堆操作退化为常数时间。
  • 数值范围：元素最多为 1,100,000。Java/C++ 每步的“已取模结果 × 元素”小于 1.1×10¹⁵，可用 64 位整数；JavaScript 使用 BigInt，避免 Number 超出精确整数范围。

复杂度：令 n 为数组长度。统一上界为 O((n+k) log(n+1)) 时间、O(n) 辅助空间。Java 逐个入堆用 O(n log(n+1)) 建堆；本页 Python、C++ 和 JavaScript 使用线性建堆，时间可写为 O(n+k log(n+1))（包含最终 O(n) 累乘）。

替代方案：先排序，把最小的一组数批量抬升到下一个不同的高度。预算不足时，将剩余次数除以组大小：每个元素加商，再让余数个元素多加 1。排序 O(n log n)、扫描 O(n)，适合 k 极大时；需仔细处理抬升成本与余数。每次线性找最小值的 O(nk) 方案只适合小规模演示。

四语言完整实现

对应官方 maximumProduct 签名。以下为待验证实现；JavaScript 不依赖在线判题环境的优先队列库。

Java

import java.util.PriorityQueue;

class Solution {
    public int maximumProduct(int[] nums, int k) {
        PriorityQueue<Integer> heap = new PriorityQueue<>();
        for (int x : nums) heap.offer(x);
        while (k-- > 0) {
            heap.offer(heap.poll() + 1);
        }
        long answer = 1;
        for (int x : heap) {
            answer = answer * x % 1_000_000_007L;
        }
        return (int) answer;
    }
}

JavaScript

/**
 * @param {number[]} nums
 * @param {number} k
 * @return {number}
 */
var maximumProduct = function(nums, k) {
    const heap = nums.slice();
    const n = heap.length;
    function siftDown(i) {
        while (2 * i + 1 < n) {
            let child = 2 * i + 1;
            if (child + 1 < n && heap[child + 1] < heap[child]) {
                child++;
            }
            if (heap[i] <= heap[child]) break;
            [heap[i], heap[child]] = [heap[child], heap[i]];
            i = child;
        }
    }
    for (let i = Math.floor(n / 2) - 1; i >= 0; i--) {
        siftDown(i);
    }
    for (let step = 0; step < k; step++) {
        heap[0]++;
        siftDown(0);
    }
    const MOD = 1000000007n;
    let answer = 1n;
    for (const x of heap) answer = answer * BigInt(x) % MOD;
    return Number(answer);
};

Python

from typing import List
from heapq import heapify, heapreplace

class Solution:
    def maximumProduct(self, nums: List[int], k: int) -> int:
        heap = nums.copy()
        heapify(heap)
        for _ in range(k):
            heapreplace(heap, heap[0] + 1)
        answer = 1
        for x in heap:
            answer = answer * x % 1_000_000_007
        return answer

C++

#include <vector>
#include <queue>
#include <functional>
using namespace std;

class Solution {
public:
    int maximumProduct(vector<int>& nums, int k) {
        priority_queue<int, vector<int>, greater<int>>
            heap(nums.begin(), nums.end());
        while (k-- > 0) {
            int x = heap.top();
            heap.pop();
            heap.push(x + 1);
        }
        // 直接遍历原数组不代表最终堆；用副本保留最终元素并线性累乘。
        // priority_queue 不提供迭代器，因此改用可遍历的堆容器见下方实现。
        long long answer = 1;
        while (!heap.empty()) {
            answer = answer * heap.top() % 1000000007LL;
            heap.pop();
        }
        return static_cast<int>(answer);
    }
};

C++ 的 priority_queue 取出全部元素还需 O(n log(n+1))，因此上面 C++ 总时间为 O((n+k) log(n+1))；可用 vector + make_heap / pop_heap / push_heap 后直接遍历，将最终乘积阶段降为 O(n)。

常见错误与面试追问

常见错误

  • 优先增加最大值：两元素比较已经说明它不如增加较小值。
  • 遇到零就提前返回：后续预算可能消除全部零。
  • 在堆内存取模后的值：取模会破坏真实大小，导致选错元素。
  • 只对最后的巨大乘积取模：固定宽度整数会溢出；应逐次累乘取模。
  • JavaScript 用 Number 做乘法后才转 BigInt：精度已丢失。应先转成 BigInt 再乘。
  • 把堆数组当成已排序数组：只有根节点保证最小，其他位置不保证全局顺序。

面试追问

k 达到 10¹² 怎么办？改用排序与批量抬升，并使用足够宽的整数计算组大小乘高度差。

为什么“至多”可以按“恰好”处理？所有因子非负，多一次增加不会使乘积下降，因此存在用满预算的最优解。

如果允许负数呢？两数差值还要乘其余因子，符号可能翻转，这里的交换论证不再适用，需要重新分析。

能否不弹出再插入？可以，直接将堆顶加一并下沉；这就是 JavaScript 的实现。
