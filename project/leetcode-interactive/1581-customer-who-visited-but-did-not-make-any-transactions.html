Solution

题解：先排除，再聚合

MySQL 官方可提交

核心洞察

判断的是“一次访问是否没有任何交易”，而不是“一个顾客是否从未交易”。所以必须先在访问粒度排除所有能关联到交易的记录，再按 customer_id 计数。

完整过程

  1. 保留每条访问记录。
  2. 左连接同一 visit_id 的交易。
  3. 只保留连接后交易主键为空的访问。
  4. 按顾客分组并统计访问行数。

官方提交方案 · MySQL

SELECT
    v.customer_id,
    COUNT(*) AS count_no_trans
FROM Visits AS v
LEFT JOIN Transactions AS t
    ON v.visit_id = t.visit_id
WHERE t.transaction_id IS NULL
GROUP BY v.customer_id;

正确性说明

左连接保证每次访问至少保留一行。若某次访问有交易，连接结果中的 t.transaction_id 必不为空，过滤条件会排除该访问产生的所有行；若没有交易，该访问恰好形成一行右侧全为空的记录并被保留。因此过滤后的每一行与一次“无交易访问”一一对应。按顾客分组后的 COUNT(*) 正好得到各顾客这类访问的次数。

复杂度

设访问数为 V、交易数为 T。数据库采用哈希连接时，期望时间为 O(V + T)，连接哈希结构额外空间为 O(T)；实际计划由数据库、统计信息和索引决定。若 Transactions.visit_id 有索引，也可高效执行反连接。

边界情况

  • 同一次访问有多笔交易：全部被排除，不能重复计数。
  • 同一顾客有多次无交易访问：每次保留一行并正确累加。
  • 所有访问都有交易：返回空结果。
  • 结果无需排序，不应依赖数据库默认行序。

常见错误

  • 用内连接：无交易访问恰好无法连接，会全部丢失。
  • 按顾客直接判断是否有交易：会误伤“有的访问交易、有的访问没交易”的顾客。
  • 写 COUNT(t.transaction_id) = 0 却在错误层级分组。
  • 左连接后在 WHERE 中加入右表普通条件，意外退化为内连接。

替代方案

SELECT v.customer_id, COUNT(*) AS count_no_trans
FROM Visits AS v
WHERE NOT EXISTS (
    SELECT 1
    FROM Transactions AS t
    WHERE t.visit_id = v.visit_id
)
GROUP BY v.customer_id;

这是语义直接的反连接写法，能避免一对多连接生成中间重复行；许多优化器会把它转换为高效的 anti join。

import java.util.*;

public class LocalReference {
    record Visit(int visitId, int customerId) {}
    record Transaction(int transactionId, int visitId, int amount) {}

    static Map<Integer, Integer> findCustomers(
            List<Visit> visits, List<Transaction> transactions) {
        Set<Integer> paidVisitIds = new HashSet<>();
        for (Transaction transaction : transactions) {
            paidVisitIds.add(transaction.visitId());
        }

        Map<Integer, Integer> result = new LinkedHashMap<>();
        for (Visit visit : visits) {
            if (!paidVisitIds.contains(visit.visitId())) {
                result.merge(visit.customerId(), 1, Integer::sum);
            }
        }
        return result;
    }
}
/**
 * 本地语义参考。
 * visits: Array<{visitId: number, customerId: number}>
 * transactions: Array<{transactionId: number, visitId: number, amount: number}>
 */
function findCustomers(visits, transactions) {
  const paidVisitIds = new Set(
    transactions.map((transaction) => transaction.visitId)
  );
  const counts = new Map();

  for (const visit of visits) {
    if (!paidVisitIds.has(visit.visitId)) {
      counts.set(visit.customerId, (counts.get(visit.customerId) ?? 0) + 1);
    }
  }

  return Array.from(counts, ([customerId, countNoTrans]) => ({
    customerId,
    countNoTrans,
  }));
}
from collections import Counter
from dataclasses import dataclass

@dataclass(frozen=True)
class Visit:
    visit_id: int
    customer_id: int

@dataclass(frozen=True)
class Transaction:
    transaction_id: int
    visit_id: int
    amount: int

def find_customers(
    visits: list[Visit],
    transactions: list[Transaction],
) -> dict[int, int]:
    paid_visit_ids = {transaction.visit_id for transaction in transactions}
    return dict(Counter(
        visit.customer_id
        for visit in visits
        if visit.visit_id not in paid_visit_ids
    ))
#include <unordered_map>
#include <unordered_set>
#include <vector>

struct Visit {
    int visitId;
    int customerId;
};

struct Transaction {
    int transactionId;
    int visitId;
    int amount;
};

std::unordered_map<int, int> findCustomers(
    const std::vector<Visit>& visits,
    const std::vector<Transaction>& transactions) {
    std::unordered_set<int> paidVisitIds;
    for (const auto& transaction : transactions) {
        paidVisitIds.insert(transaction.visitId);
    }

    std::unordered_map<int, int> counts;
    for (const auto& visit : visits) {
        if (!paidVisitIds.contains(visit.visitId)) {
            ++counts[visit.customerId];
        }
    }
    return counts;
}

面试追问

  1. 为什么检查交易主键为空，而不是 amount 为空？ 主键按题意唯一且代表交易是否存在；业务字段可能允许空值，不能可靠表示“没有关联行”。
  2. LEFT JOIN 与 NOT EXISTS 怎么选？ 两者语义都正确；NOT EXISTS 更直接表达反连接，LEFT JOIN 更方便展示缺失匹配。最终看执行计划和团队可读性规范。
  3. 如果要同时返回总到访次数呢？ 可先分别聚合总到访与无交易到访，再按 customer_id 连接；也可用条件聚合，但要小心一对多交易造成访问重复。
  4. 推荐什么索引？ Transactions(visit_id) 能支持按访问快速判断交易是否存在；题面已声明两个表各自主键唯一。
