访问完所有房间的第一天

First Day Where You Have Been in All the Rooms

一天一扇门。记住每个房间的访问次数，观察下一天会走向哪里。

LeetCode 官方题目 ↗

01 / 规则与任务

有 n 个房间，编号为 0…n−1。日期从第 0 天开始，每天访问一个房间，第 0 天访问房间 0。

给定数组 nextVisit。当天访问房间 i 后，按包含当天的累计访问次数决定第二天的位置：

  • 奇数次：前往 nextVisit[i]，它一定不大于 i。
  • 偶数次：前往 (i + 1) % n。

返回第一次已经访问过所有房间的日期编号，对 1,000,000,007 取余。题目保证答案存在。

第 0 天也算一次访问，但答案是日期编号，不是访问的总天数。

约束

  • n == nextVisit.length
  • 2 ≤ n ≤ 10⁵
  • 0 ≤ nextVisit[i] ≤ i

05 / 想清楚后，再打开题解

包含推导、正确性证明与四种语言实现。

用首次到达的日期，压缩重复旅程

核心洞察

只能从房间 i 的偶数次访问前进到 i+1，因此新房间必然按 0、1、2、… 的顺序首次出现。令 D[i] 表示首次到达房间 i 的真实日期，则答案是 D[n−1]。

首次到达 i 时，所有编号小于 i 的房间都已被访问偶数次，i 本身是第 1 次。设 j = nextVisit[i]：下一天回到 j，从那里重新走回 i。只看 j…i−1 的访问奇偶性，这段路与第一次从 j 走到 i 完全相同，所需时间为 D[i] − D[j]。

D[0] = 0
D[i+1] = D[i] + 1 + (D[i] − D[nextVisit[i]]) + 1
　　　 = 2 × D[i] − D[nextVisit[i]] + 2

完整过程

  1. 创建长度为 n 的数组 dp，dp[0] = 0，存储首次到达日期对 M 的余数。
  2. 枚举 i = 0…n−2，读取已经算出的 dp[nextVisit[i]]。
  3. 计算 dp[i+1] = (2 * dp[i] - dp[nextVisit[i]] + 2 + M) % M。
  4. 返回 dp[n−1]。抵达最后一个房间即结束，不再使用它的 nextVisit 值。

示例 2 的“回程账本”

当前 i回到 j首次日期 D[i]重复路程 D[i]−D[j]首次到达 i+1
00000 + 1 + 0 + 1 = 2
10222 + 1 + 2 + 1 = 6

在实验室切换第 2 天到第 6 天：第 2 天首次到 1；第 3 天回到 0；两天后再次到 1；再过一天进入 2。这正是“回退一步 + 重走旧路 + 前进一步”。

正确性证明

奇偶不变量：首次到达 i 时，所有更小房间的次数为偶数。i=0 时显然成立。假设对 i 成立；要首次进入 i+1，必须从 i 的偶数次访问出发。对任意 k<i，从首次到达 i 到再次回到 i 这一闭合路程中，若 k 曾被访问，其最后一次离开必须向右跨越到 k+1，才能最终回到 i；此时 k 的访问次数为偶数。未被访问的房间保持偶数。因此首次到达 i+1 时不变量仍成立。

重放相同：第一次到达 j 和从 i 回退后到达 j，j 都为奇数，j+1…i−1 都为偶数，更小房间也均为偶数。路由仅依赖奇偶性。在尚未到达 i 前，这两个过程在所有会访问的房间上状态相同，故走相同的路，耗时 D[i]−D[j]。i 自身的不同状态在到达 i 时才参与决策，不影响到达耗时。

递推与终点：从首次到达 i，到回退 j，再次到达 i，最后前进到 i+1，分别耗时 1、D[i]−D[j]、1。由归纳可知递推计算的首次日期正确；新房间按编号出现，所以首次到达 n−1 就是所求。加减乘对取模保持同余，因此逐步存余数可得到正确的最终余数。

边界与数值

  • nextVisit[i] = i 时直接在本房间再停一天，递推简化为 D[i+1] = D[i]+2。
  • n=2 时答案恒为 2；最后一项 nextVisit 不影响结果。
  • 全部回到 0 时，D[i] = 2^(i+1)−2，逐日模拟的规模会指数增长。
  • 取模后的 dp 不一定递增；不要把模后的差值当作真实旅程长度。代码加 M 以消除负余数。
  • Java / C++ 用 64 位中间值。JavaScript 每一步取模，中间值小于约 3M，远小于 Number 的安全整数上限。

复杂度与替代方案

动态规划耗时 O(n)，空间 O(n)。nextVisit[i] 可以指向任意先前下标，因此不能直接用两个滚动变量替代整个数组。

逐日模拟适合小输入的规则演示，最坏需要指数级天数。也可定义相邻房间首次日期的间隔，用前缀和求“重走一段”的耗时，复杂度同为 O(n)，实际上与当前日期递推等价。直接维护 dp 日期更简洁。

常见错误

  • 从第 1 天开始计数，或把最后日期再加 1。
  • 用访问前的次数判奇偶，导致第一次访问后直接前进。
  • 漏掉递推里的两步移动，把常数 2 写成 1。
  • 假定取模后的差值仍非负；Java、JavaScript、C++ 中负数 % M 仍可能为负。
  • 模拟全部天数，或先计算巨大真实日期、最后才取模。

面试追问

为什么不能允许 nextVisit[i]>i？可能直接跳过新房间，按编号首次到达及先前 dp 可用的前提失效，需要重新分析状态。
是否需要执行最后房间的跳转？不需要，第一次进入它时所有房间已经访问。
能从 dp 余数恢复实际路径吗？不能，取模会丢失真实时间；要演示路径需要独立的小规模模拟。

Java

class Solution {
    public int firstDayBeenInAllRooms(int[] nextVisit) {
        final long MOD = 1_000_000_007L;
        int n = nextVisit.length;
        long[] dp = new long[n];
        for (int i = 0; i < n - 1; i++) {
            dp[i + 1] = (2L * dp[i] - dp[nextVisit[i]] + 2 + MOD) % MOD;
        }
        return (int) dp[n - 1];
    }
}
