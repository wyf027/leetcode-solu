交易逆序对的总数

当较早的交易价格高于较晚的价格，就形成一个交易逆序对。请统计一段交易记录中满足条件的下标对总数。

数组困难严格大于长度至多 50000

题意

给定交易记录 record，统计满足 i < j 且 record[i] > record[j] 的下标对数量。相同价格不构成逆序对。

官方示例

record = [9, 7, 5, 4, 6]

返回 = 8

9 分别与 7、5、4、6 形成四对。

约束

0 <= record.length <= 50000

双重循环在完全递减时需要约 12.5 亿次比较，必须利用有序区间。

题解控制

题解：归并时把一串比较合并成一次加法

左右半区已经各自有序。若 right[j] < left[i]，那么 left[i..mid] 全都大于 right[j]，立即增加 mid - i + 1 对，然后取走右值。

完整过程

  1. 递归切分到长度 0 或 1，内部没有逆序对。
  2. 分别统计左右内部逆序对，并让两半各自排序完成。
  3. 双指针归并；右值更小时批量增加左侧剩余长度。
  4. 写回有序区间，让上一层也能利用有序半区。

边界与复杂度

  • 空数组、单元素和所有相等元素都返回 0。
  • 比较是严格大于；left[i] <= right[j] 时先取左边，避免误算相等值。
  • 时间 O(n log n)，辅助空间 O(n)。最大答案约 1.25×10⁹，Java 中间累计用 long 更稳妥。

替代方案

离散化后可用树状数组从右到左查询已有更小值，同样是 O(n log n)。本题推荐归并排序：不依赖值域，且计数与排序自然复用。

面试追问

  • 如何仅统计距离不超过 K 的逆序对？在归并外维护窗口。
  • 若要输出所有逆序对？答案数量可能本身就是 O(n²)。
  • 若数据流持续到达？用平衡树或树状数组维护秩和累计答案。

常见错误

  • 右值更小时只加 1，漏掉左侧剩余的一整段。
  • 归并后没有写回原数组，上一层失去有序前提。
  • 把相等值当逆序对。
  • JavaScript 使用没有数值比较器的 sort()。

class Solution {
    private int[] temp;
    public int reversePairs(int[] record) {
        temp = new int[record.length];
        return (int) sort(record, 0, record.length - 1);
    }
    private long sort(int[] a, int left, int right) {
        if (left >= right) return 0;
        int mid = left + (right - left) / 2;
        long count = sort(a, left, mid) + sort(a, mid + 1, right);
        int i = left, j = mid + 1, k = left;
        while (i <= mid && j <= right) {
            if (a[i] <= a[j]) temp[k++] = a[i++];
            else { count += mid - i + 1; temp[k++] = a[j++]; }
        }
        while (i <= mid) temp[k++] = a[i++];
        while (j <= right) temp[k++] = a[j++];
        for (int p = left; p <= right; p++) a[p] = temp[p];
        return count;
    }
}

            i, j, k = left, mid + 1, left

                temp[k], j, k = record[j], j + 1, k + 1
