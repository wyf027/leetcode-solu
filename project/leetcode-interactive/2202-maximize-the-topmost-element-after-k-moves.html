K 次操作后
最大化顶端元素

Maximize the Topmost Element After K Moves

移走顶端，或让已移走的元素重新登顶。关键限制是：操作次数必须恰好为 k。

01 / 任务说明

整数数组 nums 从顶部到底部描述一个元素堆，nums[0] 是当前顶部。这里的“堆”没有大小排序要求，可以按栈来理解。

每一步只能做一件事：堆非空时移走顶部元素；或者从已移走、尚未放回的元素中任选一个，将它放到顶部。每个元素实例只能存在于堆或移除池的一处。

求恰好执行 k 次操作后，所有可行非空堆的最大顶部值；如果最终一定为空，返回 -1。

参数与约束
maximumTop(nums, k) → integer
1 ≤ nums.length ≤ 10⁵
0 ≤ nums[i] ≤ 10⁹，0 ≤ k ≤ 10⁹

03 / 官方示例
示例 1
输入：nums = [5,2,2,4,0,6], k = 4
输出：5
依次移走 5、2、2，再把 5 放回，共 4 次操作。堆成为 [5,4,0,6]，顶部为 5，这是能取得的最大值。
示例 2
输入：nums = [2], k = 1
输出：-1
第一步只能移走唯一的 2，此时堆为空，操作次数也已用完，因此返回 -1。

05 / 题解：最后的顶部来自哪里？


核心洞察
不需要模拟多达 10⁹ 次的操作。先处理 k = 0 与单元素，再枚举“最终顶部可能来自的原始位置”。对于 n ≥ 2、k ≥ 1，只有两类候选：
  • 移走后再放回：原下标满足 0 ≤ i < min(n, k − 1)。
  • 从未移走，直接露出：当 k < n 时，原下标 i = k。
取这两类候选的最大值即可。nums[k − 1] 是特别容易误取的位置：刚好用 k 步移走它后，已经没有一步可以将它放回。


示例 1 的候选位置带 · k = 4
5
i=0 · 放回
2
i=1 · 放回
2
i=2 · 放回
4
i=3 · 排除
0
i=4 · 露出
6
i=5 · 太深
候选最大值为 max(5, 2, 2, 0) = 5。“排除”指元素实例；若同值出现在其他可达位置，该数值仍可能成为答案。


完整过程
  1. 若 k = 0，返回原顶部 nums[0]。
  2. 若 n = 1，操作只能移走、放回交替发生。k 为奇数时为空，返回 -1；偶数时返回唯一元素。
  3. 令 answer = -1，扫描前 min(n, k − 1) 个元素，更新最大值。
  4. 若 k < n，再用 nums[k] 更新答案。
  5. 返回答案。无需排序、额外数组或堆结构。


正确性：必要性与可达性
必要性。设最终顶部来自原下标 i。如果它曾被移走，就至少要先移走它及上方的 i 个元素，再花一步放回，故 i + 2 ≤ k，属于第一类。如果它从未被移走，至少要移走其上方 i 个元素，所以 i ≤ k。其中 i = k 属于第二类；i ≤ k − 2 已在第一类位置集合中；而 i = k − 1 不可行：不碰该元素而最终让它露出的过程中，移走次数减放回次数必须为 i，总次数与 i 同奇偶，不能是 i + 1。因此没有遗漏其他可能位置。
可达性，k ≤ n。连续移走 k 次即可露出 nums[k]（仅 k < n 时）。对第一类任意元素，先连续移走 k − 1 次，再把目标放回，恰好 k 次操作。k = n 时，这正好只允许前 n − 1 个元素，不能选原底部。
可达性，k > n 且 n ≥ 2。此时第一类包含所有元素。任选目标：先移走全部 n 个，再放回目标，共 n + 1 步。若剩余次数为偶数，通过反复移走并放回目标补足；若剩余次数为奇数，则 k ≥ n + 2，改成先移走全部、放回另一个元素、再放回目标，共 n + 2 步，余下次数为偶数，同样可以补足。另一个元素必须是不同的实例，数值可以相同。故所有候选都能恰好到达，取最大值正确。


边界与复杂度
  • k = 0：不动顶部；k = 1 且 n > 1：只能返回第二个元素。
  • 单元素只有奇偶性；多元素且 k > n：全数组都可作为候选。
  • k = n：不能直接返回全数组最大值，底部可能无法成为答案。
  • 允许 0 和重复值，所以以 -1 为初始值，并按下标而非数值判断可达性。
  • 扫描时间 O(min(n, k) + 1)，最坏 O(n)；额外空间 O(1)。下方四份代码均不创建切片。


Java
class Solution {
    public int maximumTop(int[] nums, int k) {
        int n = nums.length;
        if (k == 0) return nums[0];
        if (n == 1) return k % 2 == 0 ? nums[0] : -1;
        int answer = -1;
        for (int i = 0; i < Math.min(n, k - 1); i++) {
            answer = Math.max(answer, nums[i]);
        }
        if (k < n) answer = Math.max(answer, nums[k]);
        return answer;
    }
}

        if (k < n) answer = max(answer, nums[k]);
        return answer;
    }
};


替代方案
按 k 与 n 的关系分类：k = 0、单元素、k < n、k = n、k > n，然后分别求对应区间最大值，时间与空间复杂度相同，但分支更多。穷举操作序列只能用于极小规模理解：每次放回可有多个选择，路径数会迅速增长，不适合本题约束。排序还会丢失决定可达性的原始位置。


常见错误
  • 把“恰好 k 次”理解成“最多 k 次”，导致单元素奇数次仍保留原值。
  • 扫描前 k 个元素，而正确的放回候选只有前 k − 1 个。
  • 漏掉 nums[k] 这条连续移走路线，或在 k ≥ n 时越界访问。
  • 认为所有情况下都受奇偶限制：n ≥ 2 时，另一个元素可以帮助调整操作步数。
  • 使用 Math.max(...nums) 处理大数组，有参数数量风险，且直接取全局最大值并非普遍正确。


面试追问
  • 若是“最多 k 次”呢？可以不操作，原顶部始终可行；其他位置 i 只要 i ≤ k，就能通过连续移走 i 次露出，因此答案为前 min(n, k + 1) 个元素的最大值。
  • 同一数组有很多 k 查询呢？预先保存前缀最大值，O(n) 预处理与空间，再按相同候选公式 O(1) 回答每个查询。
  • 能输出具体操作序列吗？可以记录最大候选的下标，再使用上面的可达性构造。但输出 k 步本身需要 O(k) 时间；k 很大时可返回“移走/放回一对操作重复若干次”的压缩描述。
