游戏玩法分析 V

从每位玩家的首次登录日出发，按安装日期汇总安装量，并计算次日仍登录的玩家比例。

HARD付费题SQL · 留存分析

题目

表 Activity 记录玩家在某设备、某日期的游戏活动。对每位玩家，将其最早的 event_date 视为安装日期。请按安装日期返回：

  1. installs：当天首次出现的玩家数；
  2. Day1_retention：这些玩家中，在安装日期的下一自然日也有活动的比例，四舍五入保留两位小数。

结果可按任意顺序返回，列名为 install_dt、installs、Day1_retention。

表结构

列名类型含义
player_idINT玩家编号
device_idINT设备编号
event_dateDATE活动日期
games_playedINT当日游戏局数

约束：同一玩家同一天至多一条记录；(player_id, event_date) 唯一。games_played 可为 0；留存由“是否有活动记录”判断，而不是由局数判断。

安装队列 · 次日扫描器

逐步观察“首次活动 → 次日命中 → 按安装日聚合”。

题解

核心洞察

先把明细压缩为每位玩家唯一的安装日期，再用一次左连接寻找恰好发生在安装次日的活动。此时每名玩家只贡献一行，分母可直接计数，分子则统计连接成功的行。

完整过程

  1. CTE first_login 按玩家取最早活动日期。
  2. 将它与 Activity 按玩家及 install_dt + 1 day 左连接；左连接保留没有次日记录的玩家。
  3. 按安装日期分组，COUNT(*) 得安装量；布尔命中取平均得到比例，最后保留两位小数。

正确性说明

对任意玩家，MIN(event_date) 唯一确定其安装日期，因此玩家只进入一个安装日分组。连接条件仅接受安装后的下一自然日，命中当且仅当该玩家满足 Day-1 回访定义。每组命中数除以该组玩家总数，正是该安装日的次日留存率，所以算法对每个分组均返回所需结果。

边界情况

  • 仅有首次活动：计入安装量，留存贡献 0。
  • 隔多日回访：不算次日留存。
  • games_played = 0：仍是一条活动记录。
  • 日期跨月、跨年：使用日期运算，不手工拼日期。

复杂度

设活动行数为 n、玩家数为 p。逻辑处理为 O(n) 聚合加一次连接；数据库实际开销依执行计划与索引而定。CTE 结果空间 O(p)。推荐索引 (player_id, event_date)。

MySQL（官方提交语言）

MySQL 8+
WITH first_login AS (
  SELECT player_id, MIN(event_date) AS install_dt
  FROM Activity
  GROUP BY player_id
)
SELECT
  f.install_dt,
  COUNT(*) AS installs,
  ROUND(AVG(a.player_id IS NOT NULL), 2) AS Day1_retention
FROM first_login AS f
LEFT JOIN Activity AS a
  ON a.player_id = f.player_id
 AND a.event_date = DATE_ADD(f.install_dt, INTERVAL 1 DAY)
GROUP BY f.install_dt;

Java 17 · 本地语义参考
import java.time.*;
import java.util.*;

class Solution {
  record Row(int playerId, int deviceId, LocalDate date, int games) {}
  record Result(LocalDate installDt, int installs, double retention) {}
  public List<Result> analyze(List<Row> rows) {
    Map<Integer, LocalDate> first = new HashMap<>();
    Set<String> active = new HashSet<>();
    for (Row r : rows) {
      first.merge(r.playerId(), r.date(), (a,b) -> a.isBefore(b) ? a : b);
      active.add(r.playerId() + "|" + r.date());
    }
    Map<LocalDate, int[]> groups = new TreeMap<>();
    for (var e : first.entrySet()) {
      int[] g = groups.computeIfAbsent(e.getValue(), k -> new int[2]);
      g[0]++;
      if (active.contains(e.getKey() + "|" + e.getValue().plusDays(1))) g[1]++;
    }
    List<Result> out = new ArrayList<>();
    groups.forEach((d,g) -> out.add(new Result(d, g[0], Math.round(100.0*g[1]/g[0])/100.0)));
    return out;
  }
}
JavaScript · 本地语义参考
function gamePlayAnalysis(rows) {
  const first = new Map(), active = new Set();
  for (const r of rows) {
    const old = first.get(r.player_id);
    if (!old || r.event_date < old) first.set(r.player_id, r.event_date);
    active.add(`${r.player_id}|${r.event_date}`);
  }
  const nextDay = s => {
    const d = new Date(`${s}T00:00:00Z`);
    d.setUTCDate(d.getUTCDate() + 1);
    return d.toISOString().slice(0, 10);
  };
  const groups = new Map();
  for (const [id, day] of first) {
    const g = groups.get(day) || { installs: 0, returned: 0 };
    g.installs++;
    if (active.has(`${id}|${nextDay(day)}`)) g.returned++;
    groups.set(day, g);
  }
  return [...groups].sort().map(([install_dt, g]) => ({
    install_dt, installs: g.installs,
    Day1_retention: Number((g.returned / g.installs).toFixed(2))
  }));
}

from collections import defaultdict
from datetime import date, timedelta

def game_play_analysis(rows):
    first, active = {}, set()
    for player, device, event_date, games in rows:
        day = date.fromisoformat(event_date)
        first[player] = min(first.get(player, day), day)
        active.add((player, day))
    groups = defaultdict(lambda: [0, 0])
    for player, install in first.items():
        groups[install][0] += 1
        groups[install][1] += (player, install + timedelta(days=1)) in active
    return [{"install_dt": str(day), "installs": installs,
             "Day1_retention": round(returned / installs + 1e-12, 2)}
            for day, (installs, returned) in sorted(groups.items())]
C++20 · 本地语义参考
#include <algorithm>
#include <chrono>
#include <map>
#include <set>
#include <string>
#include <tuple>
#include <vector>
using namespace std;
using Day = chrono::sys_days;
struct Row { int player, device; Day day; int games; };
struct Result { Day install; int installs; double retention; };

vector<Result> analyze(const vector<Row>& rows) {
  map<int, Day> first;
  set<pair<int, Day>> active;
  for (const auto& r : rows) {
    auto [it, fresh] = first.emplace(r.player, r.day);
    if (!fresh) it->second = min(it->second, r.day);
    active.insert({r.player, r.day});
  }
  map<Day, pair<int,int>> groups;
  for (auto [player, install] : first) {
    auto& [total, returned] = groups[install];
    ++total;
    returned += active.count({player, install + chrono::days{1}});
  }
  vector<Result> out;
  for (auto [day, g] : groups)
    out.push_back({day, g.first, round(100.0*g.second/g.first)/100.0});
  return out;
}

替代方案

可用窗口函数 MIN(event_date) OVER (PARTITION BY player_id) 标记安装日，再条件聚合；也可用相关 EXISTS 判断次日记录。前者容易保留多条玩家明细导致分母重复，后者可读性好但性能更依赖优化器。

面试追问

  • 如何扩展为 D1、D7、D30 留存矩阵？
  • 如果一天允许多条活动，如何避免重复计数？
  • 为何不能把次日条件放进 WHERE？（会把左连接退化为内连接。）
  • 若业务按用户时区而非 UTC 切日，数据模型应怎样调整？

常见错误

  • 把玩家所有后续活动都当作次日回访。
  • 用 games_played > 0 作为活跃条件。
  • 整数除法得到 0；应显式产生小数。
  • 先内连接，导致未回访玩家从分母消失。
