Check If N and Its Double Exist

Problem

题目说明

给定一个整数数组 arr，判断是否存在两个下标 i 与 j，使一个位置上的数等于另一个位置上的数的两倍。找到则返回 true，否则返回 false。

  • i != j，两个数必须来自不同位置
  • 0 <= i, j < arr.length
  • arr[i] == 2 * arr[j]

约束

  • 2 <= arr.length <= 500
  • -10³ <= arr[i] <= 10³

函数签名：checkIfExist(arr) → boolean

示例 1

输入：arr = [10,2,5,3]
输出：true

10 是 5 的两倍，且它们位于不同下标。

示例 2

输入：arr = [7,1,14,11]
输出：true

14 是 7 的两倍。

示例 3

输入：arr = [3,1,7,11]
输出：false

不存在满足两倍关系的一对数。

01 · Insight

核心洞察：只与已经出现的数配对

从左到右扫描。处理当前值 x 时，若此前见过 2x，它就是当前值的两倍；若 x 为偶数且此前见过 x/2，当前值就是它的两倍。两种情况命中任意一种即可返回 true。

检查完成后再把 x 放入集合，因此命中的元素必定来自不同下标；这也自然处理了 [0,0]。

02 · Process

完整过程

  1. 建立空哈希集合 seen。
  2. 依次读取当前元素 x。
  3. 查询 seen 是否含 2 * x。
  4. 仅当 x 是偶数时，查询是否含 x / 2。这个偶数判断在强类型语言中可避免错误的整数截断。
  5. 若均未命中，把 x 加入集合并继续；扫描结束仍未命中则返回 false。

03 · Correctness

为什么它一定正确？

若算法返回 true：返回发生在当前值与 seen 中某值构成两倍关系时。集合只存储更早位置的元素，所以两个下标不同，且关系满足题意。

若答案确实存在：取那一对中较晚被扫描的元素为当前值。较早元素已经在 seen 中。无论当前值是较小数还是较大数，相应的 2x 或偶数条件下的 x/2 查询都会命中。因此算法不会漏掉合法配对。

04 · Boundaries

边界与复杂度

  • 零：一个零不能和自身复用；第二个零到来时才能命中。
  • 负数：倍数关系同样成立，例如 -4 = 2 × -2。
  • 奇数：不检查整数除法得到的 x/2，避免把 3/2 错当成 1。
时间复杂度
O(n)
每个元素执行常数次集合查询。
空间复杂度
O(n)
最坏存储全部已扫描元素。

05 · Code

四种语言完整实现

JavaHashSet<Integer>
class Solution {
    public boolean checkIfExist(int[] arr) {
        Set<Integer> seen = new HashSet<>();
        for (int x : arr) {
            if (seen.contains(2 * x) ||
                (x % 2 == 0 && seen.contains(x / 2))) {
                return true;
            }
            seen.add(x);
        }
        return false;
    }
}

06 · Alternatives

替代方案

排序 + 双指针

排序后可针对正负数分别移动指针寻找两倍关系，时间通常为 O(n log n)，实现细节比哈希集合更多。

暴力枚举

检查所有不同下标对，时间 O(n²)、空间 O(1)。约束较小时可通过，但没有利用“快速查找配对值”的结构。

08 · Pitfalls

常见错误

  • 先插入再查询：当前值为 0 时会错误地与自身配对。
  • 只查 2x：当较小的数先出现、较大的数后出现时会漏解；还要查合法的 x/2。
  • 强类型语言直接查 x/2：奇数整数除法可能截断，制造不存在的配对。
  • 忽略溢出：本题范围安全；若范围扩大，应提升数值类型或改写判断。
