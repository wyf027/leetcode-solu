网络爬虫 Web Crawler

从一个网址出发，调用受限的解析器探索网页链接；只收集与起点同主机名、且实际可达的页面。

01 · Problem

先读清边界，再开始探索

返回顺序不限

给定起始网址 startUrl，以及一个只能通过 HtmlParser.getUrls(url) 取得某页面直接链接的解析器。请返回从起点出发能够访问到的所有网址，但结果中只能包含与 startUrl 具有相同 hostname 的网址。

爬取过程可以沿链接继续深入。每个符合条件的网址只应出现一次；遇到不同主机名的链接时，不访问它，也不从它继续扩展。

hostname 怎么看？
在 http://news.yahoo.com/news 中，hostname 是 news.yahoo.com；路径 /news 不属于 hostname。

交互接口

htmlParser.getUrls(url)

返回该页面包含的全部直接链接。你不需要、也不能自行访问网络。

输出要求

  • 包含起始网址。
  • 只包含相同 hostname。
  • 只包含从起点可达的网址。
  • 去重，顺序任意。
示例 1完整参数形式
urls = [
  "http://news.yahoo.com",
  "http://news.yahoo.com/news",
  "http://news.yahoo.com/news/topics/",
  "http://news.google.com",
  "http://news.yahoo.com/us"
]
edges = [[2,0],[2,1],[3,2],[3,1],[0,4]]
startUrl = "http://news.yahoo.com/news/topics/"
输出：
["http://news.yahoo.com/news/topics/", "http://news.yahoo.com", "http://news.yahoo.com/news", "http://news.yahoo.com/us"]

从索引 2 可到 0、1，再从 0 到 4；它们都属于 news.yahoo.com。

示例 2完整参数形式
urls = [
  "http://news.yahoo.com",
  "http://news.yahoo.com/news",
  "http://news.yahoo.com/news/topics/",
  "http://news.google.com"

edges = [[0,2],[2,1],[3,2],[3,1],[3,0]]

输出：
["http://news.google.com"]

约束

1 ≤ urls.length ≤ 1000
1 ≤ urls[i].length ≤ 300
startUrl 一定存在于网址集合中
网址以 http:// 或 https:// 开头
解析器返回的链接属于题目给定的网址集合
边表示页面间的有向链接；结果顺序不作要求

核心洞察

网址是顶点，页面中的超链接是有向边。目标就是从 startUrl 做一次图遍历，但只有 hostname 与起点相同的顶点才能进入队列。把“检查域名”和“加入 visited”放在入队时完成，就能同时阻断跨域扩展与重复访问。

完整过程（BFS）

  1. 解析 startUrl 的 hostname。
  2. 创建队列与集合，把起点同时加入两者。
  3. 取出队首网址，调用 getUrls。
  4. 逐个检查邻接网址：hostname 相同且未访问，立即标记并入队。
  5. 队列为空时，返回 visited 中的全部网址。

为什么在入队时去重？

若等到出队才标记，同一个网址可能被多个父页面重复放入队列。入队即标记保证每个网址最多入队一次，队列更小，也不会重复调用解析器。

边界处理

  • 起点没有链接：只返回起点。
  • 存在环或自环：visited 阻止无限循环。
  • 相似域名不是同域名，例如 news.yahoo.com.evil.org。
  • 协议或路径不同不影响 hostname 判断。

正确性证明

1
结果中不会出现非法网址。
除起点外，一个网址只有在 hostname 与起点相同后才会加入 visited；起点显然与自身同 hostname。因此返回集合中的每个网址都满足域名条件。
2
所有返回网址都从起点可达。
起点可达。其余网址只有在处理某个已可达网址的直接链接时才入队，所以按路径长度归纳，它们也都从起点可达。
3
每个合法可达网址最终都会被找到。
对任意合法可达网址，取起点到它的一条路径。沿路径归纳：前一个顶点出队时，解析器会返回下一个顶点；它同域且未访问时必然入队。故路径终点最终进入 visited。
4
算法终止且答案恰好正确。
每个网址最多入队一次，网址数有限，所以遍历终止。结合前三点，visited 恰好等于所有同 hostname 的可达网址。

复杂度

时间
O(V + E)
检查每个可访问页面及其链接
空间
O(V)
visited、队列与结果

这里的 V、E 指遍历过程中同域页面及从这些页面读取到的链接规模；解析 hostname 的字符成本可并入所处理 URL 的总长度。

替代方案：DFS

递归或显式栈同样能遍历所有合法可达页面，时间与空间量级不变。递归写法更短，但深链可能触发调用栈上限；BFS 的显式队列更稳妥。

常见错误

  • 用字符串前缀判断域名，误收子串相似的网址。
  • 过滤跨域网址，却仍对其调用 getUrls。
  • 忘记 visited，遇到环时无限爬取。
  • 出队后才标记，造成大量重复入队。
  • 把路径或协议也当成 hostname 的一部分。

import java.net.URI;
import java.util.*;

class Solution {
    public List<String> crawl(String startUrl, HtmlParser htmlParser) {
        String targetHost = URI.create(startUrl).getHost();
        Set<String> visited = new HashSet<>();
        Queue<String> queue = new ArrayDeque<>();

        visited.add(startUrl);
        queue.offer(startUrl);

        while (!queue.isEmpty()) {
            String current = queue.poll();
            for (String next : htmlParser.getUrls(current)) {
                String nextHost = URI.create(next).getHost();
                if (targetHost.equals(nextHost) && visited.add(next)) {
                    queue.offer(next);
                }
            }
        }
        return new ArrayList<>(visited);
    }
}

 * @param {string} startUrl
 * @param {HtmlParser} htmlParser
 * @return {string[]}

var crawl = function (startUrl, htmlParser) {
  const targetHost = new URL(startUrl).hostname;
  const visited = new Set([startUrl]);
  const queue = [startUrl];
  let head = 0;

  while (head < queue.length) {
    const current = queue[head++];
    for (const next of htmlParser.getUrls(current)) {
      if (
        new URL(next).hostname === targetHost &&
        !visited.has(next)
      ) {
        visited.add(next);
        queue.push(next);
      }
    }
  }
  return [...visited];
};

class Solution:

        target_host = urlparse(startUrl).hostname

        head = 0

        while head < len(queue):
            current = queue[head]
            head += 1

class Solution {
    string hostname(const string& url) {
        size_t scheme = url.find("://");
        size_t begin = (scheme == string::npos) ? 0 : scheme + 3;
        size_t end = url.find('/', begin);
        return url.substr(begin, end - begin);
    }

public:
    vector<string> crawl(
        string startUrl,
        HtmlParser htmlParser
    ) {
        const string targetHost = hostname(startUrl);
        unordered_set<string> visited{startUrl};
        queue<string> pending;
        pending.push(startUrl);

        while (!pending.empty()) {
            string current = pending.front();
            pending.pop();

            for (const string& next : htmlParser.getUrls(current)) {
                if (
                    hostname(next) == targetHost &&
                    !visited.count(next)
                ) {
                    visited.insert(next);
                    pending.push(next);
                }
            }
        }
        return vector<string>(visited.begin(), visited.end());
    }
};
Interview follow-ups

面试追问

如果网页数量极大？

把队列和 visited 分片或外置；批量拉取链接，限制并发，加入超时、重试与速率控制。分布式场景还要保证 URL 去重的原子性。

如果允许并发调用解析器？

使用工作池消费线程安全队列；在提交新任务前原子地检查并写入 visited。还需记录进行中的任务数，避免队列短暂为空时过早结束。

如何处理 URL 规范化？

真实爬虫应统一默认端口、大小写、尾斜杠、片段和相对路径。本题给定完整 URL，通常按原字符串去重即可，hostname 则应使用 URL 解析器提取。

BFS 与 DFS 如何选？

两者在本题都正确。BFS 便于控制层级和显式并发；迭代 DFS 可能占用更窄的前沿。递归 DFS 要考虑栈深限制。
