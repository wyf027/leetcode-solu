01 · Problem

题意重述

给定整数数组 nums，统计它的全部等差子序列。等差序列至少包含三个元素，且每一对相邻元素的差相同。

子序列保留原数组中的相对顺序，可以删除任意个元素。即使取出的数值序列相同，只要选用的原数组索引不同，也应视为不同的子序列。

返回值口径

只统计长度至少为 3 的等差子序列；题目保证最终答案可用 32 位整数表示。

快速辨认

[1, 3, 5, 7, 9] [7, 7, 7, 7] [3, -1, -5, -9]

[1, 1, 2, 5, 7] 不是等差序列，因为相邻差值并不一致。

示例 1

7 条
输入：nums = [2,4,6,8,10] 输出：7 解释：[2,4,6]、[4,6,8]、[6,8,10]、 [2,4,6,8]、[4,6,8,10]、 [2,4,6,8,10]、[2,6,10]

示例 2

16 条
输入：nums = [7,7,7,7,7] 输出：16 解释：任取至少 3 个元素都会构成等差子序列。

03 · Boundaries

约束与边界

  • 1 ≤ nums.length ≤ 1000
  • -231 ≤ nums[i] ≤ 231 - 1

思考提示

数组元素是 32 位整数，但两个元素相减可能越过 32 位范围。状态设计必须同时保留“结尾位置”和“公共差值”。

04 · Editorial

准备好查看完整题解了吗？

下面的内容默认收起，包含状态定义、证明、复杂度、替代方案、四语言代码与面试追问。

Core insight

以“结尾 + 差值”压缩过去

状态

dp[i][d] 表示以索引 i 结尾、公差为 d、长度至少为 2 的子序列数。

延长

处理 j < i 时，所有 dp[j][d] 都能接上 nums[i]，并首次成为长度至少 3 的答案。

新起点

二元组 (nums[j], nums[i]) 先记入状态，但长度只有 2，不能立即计入答案。

d = nums[i] - nums[j] cnt = dp[j][d] answer += cnt dp[i][d] += cnt + 1

完整过程

  1. 为每个索引创建一个“差值 → 计数”的哈希表，并把答案初始化为 0。
  2. 按右端点 i 从左到右遍历；对每个 i，枚举全部 j < i。
  3. 用宽整数计算 d = nums[i] - nums[j]，避免 32 位减法溢出。
  4. 读取 cnt = dp[j][d]。这 cnt 条序列接上 nums[i] 后长度都至少为 3，因此加入答案。
  5. 向 dp[i][d] 加入 cnt + 1：前者是延长的旧序列，额外的 1 是刚形成的长度 2 二元组。
  6. 遍历结束后返回答案。

正确性证明

  1. 状态不变式：处理完所有右端点不超过 i 的索引对后，dp[i][d] 恰好等于所有以 i 结尾、公差为 d、长度至少为 2 的索引子序列数量。长度 2 的序列由当前索引对贡献 1；更长序列由 dp[j][d] 中的序列唯一延长而来，所以不多不少。
  2. 计数正确：每次读取的 dp[j][d] 对应长度至少为 2 的序列，接上索引 i 后都成为合法等差子序列，因此应全部加入答案。
  3. 无重复无遗漏：每条长度至少为 3 的等差子序列都有唯一的最后两个索引 (j,i)，它只会在处理该索引对时被计数一次；反之，每次加入答案的序列都保持相同差值与索引顺序，必然合法。故算法返回且仅返回全部目标子序列的数量。

复杂度

时间：O(n²)，枚举全部 j < i 的索引对。

空间：O(n²)，最坏情况下每个结尾记录 O(n) 个不同差值。

边界处理

n < 3 时答案自然为 0；重复元素对应差值 0；差值必须用 64 位整数（JavaScript 的安全整数范围覆盖两端 32 位数之差）。

四语言完整代码

import java.util.HashMap;
import java.util.Map;

class Solution {
    public int numberOfArithmeticSlices(int[] nums) {
        int n = nums.length;
        @SuppressWarnings("unchecked")
        Map<Long, Integer>[] dp = new HashMap[n];
        for (int i = 0; i < n; i++) {
            dp[i] = new HashMap<>();
        }

        long answer = 0;
        for (int i = 0; i < n; i++) {
            for (int j = 0; j < i; j++) {
                long diff = (long) nums[i] - nums[j];
                int extendable = dp[j].getOrDefault(diff, 0);
                int existing = dp[i].getOrDefault(diff, 0);

                answer += extendable;
                dp[i].put(diff, existing + extendable + 1);
            }
        }
        return (int) answer;
    }
}
/**
 * @param {number[]} nums
 * @return {number}
 */
var numberOfArithmeticSlices = function(nums) {
    const dp = Array.from({ length: nums.length }, () => new Map());

            const existing = dp[i].get(diff) ?? 0;

            dp[i].set(diff, existing + extendable + 1);
        }
    }

from collections import defaultdict
from typing import List


class Solution:
    def numberOfArithmeticSlices(self, nums: List[int]) -> int:
        dp = [defaultdict(int) for _ in nums]
        answer = 0

        for i in range(len(nums)):
            for j in range(i):
                diff = nums[i] - nums[j]
                extendable = dp[j][diff]

                answer += extendable
                dp[i][diff] += extendable + 1

        return answer
#include <unordered_map>
#include <vector>
using namespace std;

class Solution {
public:
    int numberOfArithmeticSlices(vector<int>& nums) {
        int n = static_cast<int>(nums.size());
        vector<unordered_map<long long, int>> dp(n);
        long long answer = 0;

        for (int i = 0; i < n; ++i) {
            for (int j = 0; j < i; ++j) {
                long long diff = static_cast<long long>(nums[i]) - nums[j];
                int extendable = dp[j].count(diff) ? dp[j][diff] : 0;

                answer += extendable;
                dp[i][diff] += extendable + 1;
            }
        }
        return static_cast<int>(answer);
    }
};

替代方案与取舍

枚举所有子序列

逐个生成再检查，时间接近 O(2ⁿ · n)，在 n = 1000 时完全不可行；只适合极小输入的思维校验。

二维稀疏哈希 DP

只保存实际出现的差值，达到 O(n²) 时间。差值范围极大，不能用按差值开辟的稠密数组替代。

常见错误

  • 把长度 2 的二元组直接加入答案，导致多计。
  • 更新 dp[i][d] 时只加 cnt，漏掉当前二元组贡献的 +1。
  • 用 32 位整数计算差值；例如最大值减最小值会溢出。
  • 误把“数值序列相同”当作同一条答案，忽略不同索引选择应分别计数。
  • 原地读取错误端点的状态，或者遗漏 j < i 的顺序限制。

面试追问

为什么状态统计长度至少为 2，而不是至少为 3？

长度 2 的序列虽然还不是答案，却是未来延长成合法序列的最小“种子”。把它放入状态，转移才能统一处理，不需要额外枚举第三个点。

为什么答案只增加 cnt，而状态增加 cnt + 1？

cnt 条旧序列接上新元素后都达到至少 3 个元素，可以计入答案；新增二元组只有 2 个元素，只能进入状态等待后续延长。

能把空间降到 O(n) 吗？

通常不能直接滚动，因为后续每个右端点都可能查询任意旧索引 j 的差值账本。合并不同索引会丢失子序列结尾信息并造成错误计数。

如果只问最长等差子序列长度，状态如何变化？

仍可使用 (i,d) 状态，但值改为最长长度，而不是方案数；转移取最大值，并把新二元组初始化为长度 2。
