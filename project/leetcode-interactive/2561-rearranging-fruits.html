01 · 题目

让两个果篮拥有相同的水果成本集合

给定两个长度均为 n 的整数数组 basket1 与 basket2。数组元素表示水果的成本。一次操作可从两篮各选一个水果并交换，操作成本为这两个水果成本的较小值。可执行任意次操作；当两篮分别排序后完全一致时视为相等。求达到相等状态的最小总成本，若无法做到则返回 -1。

示例 1

输入：basket1 = [4,2,2,2]
      basket2 = [1,4,1,2]
输出：1

交换 basket1 下标 1 的 2 与 basket2 下标 0 的 1，成本为 1；重排后两篮一致。

示例 2

输入：basket1 = [2,3,4,1]
      basket2 = [3,2,5,1]
输出：-1

某些成本的总出现次数无法被两篮平分，因此不存在合法重排。

约束

  • basket1.length == basket2.length
  • 1 ≤ basket1.length ≤ 10⁵
  • 1 ≤ basket1[i], basket2[i] ≤ 10⁹

04 · 题解

准备好再揭晓完整思路

展开后包含贪心证明、四语言实现、边界与面试追问。

排序 + 贪心：只为必须迁移的副本付费

核心洞察

先把同一成本在两个篮子中的出现次数作差。某成本在两篮中的总次数若为奇数，就不可能平均分配，直接返回 -1。否则，差值绝对值的一半就是该成本必须从某一篮迁出的副本数。

设所有水果中的最小成本为 m。交换一对待迁水果 x、y 有两种选择：

  • 直接交换，成本 min(x, y)；
  • 借助全局最小水果进行两次交换，成本 2m。
因此一对水果的最优成本是 min(min(x, y), 2m)。把所有必须迁出的副本放进同一数组并排序，只需累加较小的一半：它们恰好可以分别与较大的一半配对。

完整过程

  1. 遍历 basket1，令对应频次差加一；遍历 basket2，令其减一，同时记录全局最小值 m。
  2. 若任一频次差为奇数，返回 -1。
  3. 对每个成本 x，向待迁列表加入 |diff[x]| / 2 个 x。
  4. 升序排列待迁列表。设长度为 k，只遍历前 k / 2 个元素 x，累加 min(x, 2m)。
  5. 返回累计成本。

为什么正确

引理 1：奇偶性决定可行性

最终两个篮子中某成本的数量必须相等，所以该成本在两篮的总数量必须为偶数。反之，当每个成本的总数都是偶数时，把每种成本的总数各分一半即可形成共同目标多重集合，因此频次层面一定可行。

引理 2：任意一对待迁水果的最低可用成本

直接交换的成本为两者较小值。也可让全局最小水果作为中转，经过两次交换完成等价迁移，成本为 2m。这两种方式取较小者即可。

引理 3：应让较小的一半承担成本

每次交换会从待迁列表中消去两个元素，且直接成本只由二者中较小者决定。将较小元素与较大元素配对，不会比让两个较小元素互相配对更贵，并能避免较大元素成为另一对的最小值。交换论证反复应用后，存在一个最优配对，使排序后前一半的每个元素都与后一半配对。

结论

算法先准确识别所有必须迁移的副本，再对一个最优配对逐对选择直接交换或最小值中转。每一步均取可实现的最低成本，因此总和即为全局最小成本。

复杂度

设两篮长度均为 n。统计频次为 O(n)，排序待迁列表为 O(n log n)；空间复杂度为 O(n)。

边界情况

  • 两篮原本相同：待迁列表为空，答案为 0。
  • 任一总频次为奇数：立即返回 -1。
  • 全局最小值本身无需迁移：仍可以作为中转水果使用，交换后再恢复。
  • 答案可能超过 32 位整数：Java/C++ 使用 long/long long；JavaScript 的最大可能答案仍在安全整数范围内。

四语言完整代码

import java.util.*;

class Solution {
    public long minCost(int[] basket1, int[] basket2) {
        Map<Integer, Integer> diff = new HashMap<>();
        int minimum = Integer.MAX_VALUE;

        for (int x : basket1) {
            diff.merge(x, 1, Integer::sum);
            minimum = Math.min(minimum, x);
        }
        for (int x : basket2) {
            diff.merge(x, -1, Integer::sum);
            minimum = Math.min(minimum, x);
        }

        List<Integer> moves = new ArrayList<>();
        for (Map.Entry<Integer, Integer> entry : diff.entrySet()) {
            int count = entry.getValue();
            if (Math.abs(count) % 2 == 1) return -1;
            for (int i = 0; i < Math.abs(count) / 2; i++) {
                moves.add(entry.getKey());
            }
        }

        Collections.sort(moves);
        long answer = 0;
        for (int i = 0; i < moves.size() / 2; i++) {
            answer += Math.min((long) moves.get(i), 2L * minimum);
        }
        return answer;
    }
}

var minCost = function(basket1, basket2) {
    const diff = new Map();
    let minimum = Infinity;

    for (const x of basket1) {
        diff.set(x, (diff.get(x) || 0) + 1);
        minimum = Math.min(minimum, x);
    }
    for (const x of basket2) {
        diff.set(x, (diff.get(x) || 0) - 1);
        minimum = Math.min(minimum, x);
    }

    const moves = [];
    for (const [value, count] of diff) {
        if (Math.abs(count) % 2 === 1) return -1;
        for (let i = 0; i < Math.abs(count) / 2; i++) {
            moves.push(value);
        }
    }

    moves.sort((a, b) => a - b);
    let answer = 0;
    for (let i = 0; i < moves.length / 2; i++) {
        answer += Math.min(moves[i], 2 * minimum);
    }
    return answer;
};
from collections import Counter
from typing import List


class Solution:
    def minCost(self, basket1: List[int], basket2: List[int]) -> int:
        diff = Counter(basket1)
        diff.subtract(basket2)
        minimum = min(min(basket1), min(basket2))
        moves = []

        for value, count in diff.items():
            if abs(count) % 2:
                return -1
            moves.extend([value] * (abs(count) // 2))

        moves.sort()
        return sum(min(value, 2 * minimum)
                   for value in moves[:len(moves) // 2])
class Solution {
public:
    long long minCost(vector<int>& basket1, vector<int>& basket2) {
        unordered_map<int, int> diff;
        int minimum = INT_MAX;

        for (int x : basket1) {
            ++diff[x];
            minimum = min(minimum, x);
        }
        for (int x : basket2) {
            --diff[x];
            minimum = min(minimum, x);
        }

        vector<int> moves;
        for (auto [value, count] : diff) {
            if (abs(count) % 2 == 1) return -1;
            for (int i = 0; i < abs(count) / 2; ++i) {
                moves.push_back(value);
            }
        }

        sort(moves.begin(), moves.end());
        long long answer = 0;
        for (int i = 0; i < static_cast<int>(moves.size()) / 2; ++i) {
            answer += min<long long>(moves[i], 2LL * minimum);
        }
        return answer;
    }

替代方案

也可分别建立“A 多出的水果”和“B 多出的水果”两个数组，将前者升序、后者降序后逐对计算 min(a, b, 2m)。它与把所有待迁值合并、排序并取前一半等价，但需要维护两份列表，代码略长。

常见错误

  • 只计算直接交换成本，漏掉通过全局最小水果中转的 2m。
  • 把频次差的绝对值全部加入列表，而不是只加入一半，导致迁移次数翻倍。
  • 检查单篮频次的奇偶，而不是检查两篮合计频次能否平分。
  • 累加答案时遍历整个待迁列表；每次交换消去两个元素，所以只取排序后的前一半。
  • 用 32 位整数保存总成本。

面试追问

  • 为什么中转成本是两倍最小值？ 因为需要两次以最小水果为便宜一方的交换，才能完成目标水果迁移并恢复中转关系。
  • 为什么不必真的构造交换序列？ 题目只求最小成本；频次差已确定必须迁移的多重集合，而贪心配对足以计算其最优成本。
  • 能否做到线性时间？ 若成本范围很小，可用计数数组替代排序；但在成本上限为 10⁹ 的一般情形下，哈希统计加排序更直接。
  • 若交换成本改为两数之和呢？ 当前“较小者决定成本”的配对证明失效，需要重新分析配对结构。
