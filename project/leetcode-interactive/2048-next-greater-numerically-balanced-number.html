Next Greater Numerically Balanced Number

一个数字出现的次数，能否刚好等于它自身？从给定整数出发，寻找满足这个规则的下一个数。

01 / PROBLEM

先理解规则

给定整数 n，返回严格大于 n 的最小数值平衡数。所谓数值平衡：对这个数中实际出现的每个数字 d，它都必须恰好出现 d 次。没有出现的数字不需要满足次数要求。

参数：n: integer；返回值：integer。约束：0 ≤ n ≤ 10⁶。

示例 1

输入：n = 1
输出：22

22 中数字 2 出现两次；它是大于 1 的最小合格整数。

示例 2

输入：n = 1000
输出：1333

1 出现一次，3 出现三次。1022 不合格，因为 0 出现了一次，无法满足“出现零次”。

示例 3

输入：n = 3000
输出：3133

3133 中 1 出现一次，3 出现三次，且是大于 3000 的最小合格整数。

04 / SOLUTION

准备好再打开题解

先尝试解释：哪些数字绝不可能出现在答案中？如何保证找到的是最小值？

递增枚举 + 数位计数

核心洞察

判定一个整数只需要十格计数数组。对每个数字 d，合法条件是 count[d] = 0 或 count[d] = d。因此 0 不能出现：只要出现，次数就大于 0。

从 n + 1 开始按整数递增，第一次遇到合法候选就返回。题目范围足够小，无需生成所有排列。

完整过程

  1. 令候选 x = n + 1，新建全零计数数组。
  2. 复制 x 到 y；不断取 y % 10 计数，再整除 10。
  3. 检查 d = 0…9；若某个 count[d] 非零且不等于 d，候选不合格。
  4. 全部满足则返回 x，否则 x 加一，重新清空计数。

面板从左到右读数字，代码从右到左取余；两者统计结果相同。

为什么一定能结束？

1,224,444 中 1 出现一次、2 出现两次、4 出现四次，是合法数，并且大于所有允许的 n。因此把它作为搜索上界 U，就一定能遇到答案。这里的 U 是一个保证可达的上界，不是所有平衡数的最大值。

正确性证明

判定正确：逐位取余恰好统计每个数位一次。忽略未出现的数字，对所有出现的数字要求次数等于自身，正好与定义一致。

最小性：开始检查 x 时，区间 [n + 1, x − 1] 内的整数均已被判为不合格。首次返回的 x 合格、严格大于 n，且没有更小的合格候选。可达上界保证循环终止。

边界与复杂度

n = 0 从 1 开始；n 本身平衡也必须跳过；含 0 的候选必不合格。n = 10⁶ 时也需要允许答案为七位数，不能把答案上界误设成 n 的最大值。

设答案为 A，每个候选最多 L 位，耗时 O((A − n) · (L + 10))；使用 U 可写为 O((U − n) log U)。十格计数数组占 O(1) 额外空间。这里 U = 1,224,444，L ≤ 7。

替代方案

选择若干数字 d，并规定每个被选中的 d 恰好用 d 次；用回溯生成相应多重集合的不同排列，排序后查找第一个大于 n 的值。当前搜索只需生成至七位，但一般化到更大 n 时必须重新确定长度上界。

若有很多次查询，预生成并排序有效候选，单次二分查找可降为 O(log M)，M 为候选数量；一次查询用递增枚举更直接。

过程示例：n = 20

21 的计数为 count[1] = 1、count[2] = 1。数字 2 需要出现两次，因此拒绝。接着 22 的 count[2] = 2，其余均为 0，于是返回 22。

Java

class Solution {
    public int nextBeautifulNumber(int n) {
        for (int x = n + 1; x <= 1224444; x++) {
            int[] count = new int[10];
            for (int y = x; y > 0; y /= 10) {
                count[y % 10]++;
            }
            boolean valid = true;
            for (int d = 0; d < 10; d++) {
                if (count[d] != 0 && count[d] != d) {
                    valid = false;
                    break;
                }
            }
            if (valid) return x;
        }
        return -1; // 在官方输入范围内不会到达
    }
}

class Solution:
    def nextBeautifulNumber(self, n: int) -> int:
        for x in range(n + 1, 1224445):
            count = [0] * 10
            y = x
            while y > 0:
                count[y % 10] += 1
                y //= 10
            if all(count[d] == 0 or count[d] == d

常见错误

  • 从 n 开始搜索，返回了与输入相等的数。
  • 要求未出现的数字也满足 count[d] = d。
  • 只检查 1…9，漏掉不允许出现的 0。
  • 把“恰好”理解为至少，错误接收过量数字。
  • 对候选 x 本身反复整除，丢失返回值。
  • 计数数组跨候选复用却忘记清零。
  • Python 使用 / 而非 //，或遗漏 range 的右端排除规则。

面试追问

如果 n 大得多？逐个整数扫描会变慢，改为枚举数字集合和排列，或用计数约束搜索严格大于 n 的最小构造。

怎样避免重复排列？按数字剩余次数回溯，每次只选择一种数字，不把相同数字视为不同对象。

为什么最大输入的期望值是 1224444？最小七位合法数应尽量从 1 开始；总数位数为 7、包含 1 的数字集合只有 {1,6} 与 {1,2,4}。各集合的最小排列分别为 1666666、1224444；不含 1 的七位数更大。
