题解

核心洞察、完整过程、边界、复杂度、替代方案、追问、常见错误和四语言代码默认隐藏。

核心洞察

设从 array1 取出 a，从 array2 取出 b。交换后等和，把等式整理后，二重枚举被压缩成单个候选值。

sum₁ − a + b = sum₂ − b + a 2(a − b) = sum₁ − sum₂ Δ = (sum₁ − sum₂) / 2 b = a − Δ

完整过程

  1. 分别计算两数组总和，使用更宽的整数类型。
  2. 若差值为奇数，除以 2 后不是整数，直接返回空数组。
  3. 把 array2 的值放入哈希集合。
  4. 遍历每个 a，计算唯一候选 b = a − Δ。
  5. 若集合包含 b，返回 [a, b]；遍历结束仍未命中则无解。

边界与复杂度

  • 差值为 0 时，需要在两个数组中找到相同的值。
  • 差值为奇数时必定无解，不必建集合。
  • 重复值不影响存在性判断，哈希集合足够。
  • 时间复杂度：O(n + m)。
  • 空间复杂度：O(m)。

替代方案与面试追问

可以排序后用双指针比较 a − b 与 Δ，时间为 O(n log n + m log m)；若允许原地排序，额外空间可更低。面试中优先推荐哈希法，因为它线性、直接且不修改输入。

追问：若内存受限怎么办？选择较短数组建集合，或改用排序双指针。若要求全部答案，则需要去重并继续扫描，而不是首次命中就返回。

常见错误

  • 把符号写反：正确候选是 b = a − Δ。
  • 忽略奇偶性，直接进行整数除法。
  • 返回下标而不是题目要求的两个数值。
  • 用 32 位整数累加，数组较长时总和溢出。
  • 把官方样例输出当成唯一答案，误判其他合法交换。

为什么哈希法适合面试

推导、数据结构与复杂度之间存在清晰因果链：等式给出唯一候选，哈希集合负责 O(1) 平均查找。代码短，但可以自然延伸到溢出、重复值、全部答案和内存约束等追问。

class Solution {
    public int[] findSwapValues(int[] array1, int[] array2) {
        long sum1 = 0;
        long sum2 = 0;
        for (int value : array1) sum1 += value;
        for (int value : array2) sum2 += value;

        long difference = sum1 - sum2;
        if ((difference & 1L) != 0) return new int[0];
        long delta = difference / 2;

        Set<Long> values = new HashSet<>();
        for (int value : array2) values.add((long) value);

        for (int a : array1) {
            long b = (long) a - delta;
            if (values.contains(b)) return new int[] {a, (int) b};
        }
        return new int[0];
    }
}

var findSwapValues = function (array1, array2) {
    const sum1 = array1.reduce((sum, value) => sum + value, 0);
    const sum2 = array2.reduce((sum, value) => sum + value, 0);
    const difference = sum1 - sum2;

    if (difference % 2 !== 0) return [];
    const delta = difference / 2;
    const values = new Set(array2);

    for (const a of array1) {
        const b = a - delta;
        if (values.has(b)) return [a, b];
    }
    return [];
};
