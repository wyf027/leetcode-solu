Count Primes
埃氏筛的删倍数实验室

把“逐个试除”换成一张候选表：每发现一个素数，就划掉它从平方开始的所有倍数。观察筛子如何让合数自动出局。

题意

给定整数 n，返回严格小于 n 的素数个数。素数大于 1，且只有 1 和自身两个正因数。

官方样例 1
n = 10
输出：4；小于 10 的素数为 2、3、5、7。
官方样例 2
n = 0
输出：0
官方样例 3
n = 1
输出：0

约束：0 ≤ n ≤ 5 × 10⁶

交互：筛掉合数

当前示例使用 n = 30。每一步选一个尚未划掉的素数。

题解：埃拉托斯特尼筛

主线：Sieve of Eratosthenes

核心洞察

如果 m 是合数，它有一个不大于 √m 的因子。因此扫到 p × p ≥ n 即可停止。对素数 p，所有小于 p² 的倍数早已被更小的因子划掉，所以从 p² 起步。

完整过程

  1. 建立长度 n 的 isPrime，先将 2..n-1 设为真。
  2. 遍历 p，条件为 p × p < n。
  3. 若 p 仍为真，标记 p²、p²+p、… 为假。
  4. 统计为真的下标。

边界与复杂度

n ≤ 2 直接为 0。循环条件写成 p * p < n 时，Java/C++ 应注意极大整数溢出；本题约束安全，通用写法可用 p < n / p。

时间：O(n log log n)
空间：O(n)

替代方案取舍

逐个试除只需 O(1) 额外空间，却约为 O(n√n)，在 n=5×10⁶ 时明显不合适。分段筛适合 n 极大、内存吃紧的场景，本题普通筛更直接。

常见错误

  • 把 n 本身也计入：题目要的是严格小于 n。
  • 从 2p 开始而非 p²：正确但重复标记很多。
  • 遗漏 0、1：它们不是素数。
  • 将已划掉的 p 继续当作素数标记：浪费工作。

面试追问

如何把空间降下来？ 用分段筛，只保留一个区间；先求 √R 以内的素数，再标记区间。
如何处理只关心奇数？ 用索引 i 表示 2i+1，可约省一半空间，代码复杂度相应提高。

class Solution {
    public int countPrimes(int n) {
        boolean[] isPrime = new boolean[n];
        java.util.Arrays.fill(isPrime, true);
        for (int p = 2; p * p < n; p++) {
            if (isPrime[p]) {
                for (int multiple = p * p; multiple < n; multiple += p) isPrime[multiple] = false;
            }
        }
        int answer = 0;
        for (int i = 2; i < n; i++) if (isPrime[i]) answer++;
        return answer;
    }
}

    def countPrimes(self, n: int) -> int:
        is_prime = [True] * n
        for p in range(2, int(n ** 0.5) + 1):
            if is_prime[p]:
                for multiple in range(p * p, n, p):
