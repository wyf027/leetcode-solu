01 / 题意与运行契约

同一列车，多张查询票

文件只能通过 read4(buf4) 访问。实现 read(buf, n)，每次最多写入 n 个字符并返回实际写入数；同一个 Solution 实例会被连续调用多次。

  • · 不能直接操作文件，read4 自己维护文件指针。
  • · 同一测试用例会复用目标缓冲区，空间保证足够。
  • · 需要把 read4 多读但本次未交付的字符保存到下一次调用。
  • · 每个新测试用例都要重置 Solution 的实例状态。

04 / 题解区域

先跑车票，再查调度表

核心洞察、完整过程、边界、复杂度、替代方案、追问、错误与四语言代码默认隐藏。

核心洞察

把 buf4 从局部变量升级为实例状态

三个字段必须跨调用保留：cache[4]、 cacheIndex 和 cacheSize。区间 [cacheIndex, cacheSize) 就是下一次 read 应先消费的余量。

完整过程

  1. 1. 本次 written 从 0 开始，但持久缓存位置不重置。
  2. 2. 缓存空时调用 read4，令 cacheIndex = 0。
  3. 3. 从缓存逐字符复制，直到本次达到 n 或缓存耗尽。
  4. 4. read4 返回 0 时结束；剩余缓存自然留给下一次调用。

边界

  • · n 小于缓存余量：不调用 read4。
  • · 文件尾落在一批中间：cacheSize 小于 4。
  • · 文件已读完且缓存空：返回 0。
  • · 新测试实例必须从空状态开始。

复杂度

单次调用最多复制 n 个字符，时间 O(n)；所有调用合计 O(实际读取字符数)。持久缓存固定 4 格，额外空间 O(1)。

替代方案取舍

队列保存余量更直观，但会引入容器操作；固定数组加双指针最贴合 read4 契约，也是面试最推荐的实现。

面试追问

  • · 为什么第 157 题的局部 buf4 在这里会丢字符？
  • · 如何证明每个文件字符恰好交付一次？
  • · 如果 read 可以并发调用，当前实例字段还安全吗？
  • · 如果底层 API 变为 readK，哪些字段和不变量不变？

常见错误

  • · 每次 read 都创建新 buf4，直接丢掉多读字符。
  • · 补给后忘记把 cacheIndex 归零。
  • · 把 cacheSize 当成剩余量，而不是有效区间终点。
  • · read4 返回不足 4 就立刻退出，遗漏刚读到的字符。
/**
 * The read4 API is defined in the parent class Reader4.
 * int read4(char[] buf4);
 */
public class Solution extends Reader4 {
    private final char[] cache = new char[4];
    private int cacheIndex = 0;
    private int cacheSize = 0;

    public int read(char[] buf, int n) {
        int written = 0;

        while (written < n) {
            if (cacheIndex == cacheSize) {
                cacheSize = read4(cache);
                cacheIndex = 0;
                if (cacheSize == 0) {
                    break;
                }
            }

            while (written < n && cacheIndex < cacheSize) {
                buf[written++] = cache[cacheIndex++];
            }
        }

        return written;
    }
}
