题解：统计补集

核心洞察

把问题改写为：答案 = n − [1, n] 中各位互不相同的正整数个数。不重复数字可以用排列数直接计数。

完整过程

  1. 设 s = String(n + 1)，统计区间变为 [0, n] 中小于 n + 1 的数；最后不计 0。
  2. 先统计长度小于 s.length 的正整数。长度为 k 时，首位 9 种，之后依次有 9、8、… 种：9 × P(9, k−1)。
  3. 再从高位到低位匹配 s。当前位置尝试所有比当前位小、且未用过的数字；每种前缀后面有 P(剩余数字种类, 剩余位置) 种填法。
  4. 若当前数字已经在前缀出现，停止；否则标记已用并继续。
  5. 所得为无重复的正整数数量，用 n 减去它。

正确性证明

  1. 分类完备：每个小于 n+1 的正整数，要么位数更短，要么与其等长；两类互斥且覆盖全部候选。
  2. 较短数计数正确：首位不能为 0，有 9 种；后续每位从尚未使用的数字中选择，所以乘积恰为全部无重复排列。
  3. 等长数计数正确：在首个小于边界的位置选定后，后缀任意无重复排列都合法；按首个不同位置分类不会重计。
  4. 补集成立：[1,n] 中每个数恰好属于“有重复”或“无重复”之一，因此相减即为所求。

边界与复杂度

n=1 时答案为 0；遇到前导位置时不允许选 0；前缀自身重复时立即停止。最多处理 10 位，每位至多枚举 10 个数字。时间 O(L×10)，空间 O(10)，其中 L 为十进制位数。

替代方案

可写标准数位 DP，状态为 (pos, mask, tight, started)，更通用但状态与代码更繁。也可直接 DP 统计“已经重复”，不过补集排列法更短、更容易证明。

面试追问

  • 若要求恰好出现两次，状态如何扩充？
  • 若数字改为任意进制 B，排列公式如何变化？
  • 为什么使用 n+1 能统一“小于边界”的处理？

常见错误

  • 把首位 0 当成合法选择，造成重复计数。
  • 计算排列数时剩余数字与剩余位置错一位。
  • 当前位已用后仍继续扫描，计入不可能的前缀。
  • 忘记最终统计的是补集，需要用 n - unique。

class Solution {
    public int numDupDigitsAtMostN(int n) {
        char[] s = String.valueOf(n + 1).toCharArray();
        int unique = 0;
        for (int len = 1; len < s.length; len++)
            unique += 9 * perm(9, len - 1);
        boolean[] used = new boolean[10];
        for (int i = 0; i < s.length; i++) {
            int cur = s[i] - '0';
            for (int d = (i == 0 ? 1 : 0); d < cur; d++)
                if (!used[d]) unique += perm(9 - i, s.length - i - 1);
            if (used[cur]) break;
            used[cur] = true;
        }
        return n - unique;
    }
    private int perm(int m, int k) {
        int ans = 1;
        for (int i = 0; i < k; i++) ans *= m - i;
        return ans;
    }
}
