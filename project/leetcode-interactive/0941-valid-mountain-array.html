有效的山脉数组

Valid Mountain Array · 找到一座严格上升、再严格下降的山峰。

题目

给定整数数组 arr，判断它是否为有效山脉数组。数组长度至少为 3，并且必须存在一个既不是首项也不是末项的峰顶：峰顶之前严格递增，峰顶之后严格递减。相邻元素相等、只有上坡、只有下坡都不成立。

示例 1

输入：arr = [2,1]
输出：false

示例 2

输入：arr = [3,5,5]
输出：false

示例 3

输入：arr = [0,3,2,1]
输出：true

约束

  • 1 <= arr.length <= 10⁴
  • 0 <= arr[i] <= 10⁴

登山指针实验室

先上坡，再下坡；观察指针能否恰好抵达终点。

准备

仅接受 1～30 个非负整数。

已走过当前指针违规位置

载入后，从左端开始寻找严格上升段。

双阶段一次扫描

核心洞察

用同一个指针先尽可能沿严格上升边移动，再尽可能沿严格下降边移动。有效答案要求上升至少一步、下降至少一步，并最终到达最后一个元素。

完整过程

  1. 若长度小于 3，返回 false。
  2. 当 arr[i] < arr[i+1] 时右移，得到峰顶候选。
  3. 若峰顶位于首项或末项，返回 false。
  4. 当 arr[i] > arr[i+1] 时继续右移。
  5. 只有指针抵达 n-1 才返回 true。

正确性

第一阶段越过且仅越过所有连续的严格上升边；中间检查保证峰顶两侧都有元素。第二阶段越过且仅越过所有连续的严格下降边。若最终到达末尾，整个数组正好由非空上升段和非空下降段组成；反之，有效山脉的两段都会被指针完整越过，所以必然到达末尾。

边界

  • 少于 3 项。
  • 峰在首项或末项。
  • 相邻元素相等。
  • 下降后再次上升。

复杂度

时间 O(n)；额外空间 O(1)。

替代方案

也可用状态机记录“上坡/下坡”，或从两端分别爬到峰顶并检查是否相遇；前者分支更多，后者同样是线性时间。

面试追问

  • 若允许平台（相邻相等），比较条件如何改变？
  • 如何返回峰顶下标或第一处违规边？
  • 流式数据无法回看时，怎样用状态机判断？

常见错误

  • 把非严格比较写成 <= 或 >=。
  • 忘记排除全递增、全递减数组。
  • 下降段结束后没有检查是否到达末尾。

class Solution {
    public boolean validMountainArray(int[] arr) {
        int n = arr.length, i = 0;
        while (i + 1 < n && arr[i] < arr[i + 1]) i++;
        if (i == 0 || i == n - 1) return false;
        while (i + 1 < n && arr[i] > arr[i + 1]) i++;
        return i == n - 1;
    }
}
