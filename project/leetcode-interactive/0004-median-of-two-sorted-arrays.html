01

题意转述

给你两个分别按非递减顺序排列的整数数组，返回它们合在一起后的中位数。题目要求整体时间复杂度达到 O(log(m+n))， 因此真的合并或线性扫描都不是最终答案。

EXAMPLE A

[1, 3] + [2] → 2.0

EXAMPLE B

[1, 2] + [3, 4] → 2.5

约束：两数组长度均为 0～1000，但总长度至少为 1、至多为 2000；元素范围为 −106～106。

THE ONE INSIGHT

中位数 = 一道合法切口

  1. 1 左舱元素数量固定为 (m+n+1)/2。
  2. 2 只需保证两条交叉边界：A左 ≤ B右 且 B左 ≤ A右。
  3. 3 条件不满足时，移动短数组上的切口；另一个切口自动反向配平。

02

完整解题过程

  1. A

    保证 A 是短数组

    若 A 更长就交换，确保二分范围最小，且 B 的切口不会越界。

  2. B

    锁定左舱容量

    leftSize = (m+n+1)/2。选 A 的切口 i，B 的切口就是 j = leftSize-i。

  3. C

    检查交叉边界

    若 A左 > B右，A 切多了，向左；否则若 B左 > A右，A 切少了，向右。

  4. D

    从四个边界取答案

    奇数取 max(A左,B左)；偶数再与 min(A右,B右) 求平均。

WHY IT WORKS

证明只抓两件事

数量正确：由 i+j=leftSize 保证。奇数时多出的那个元素被刻意留在左舱。

顺序正确：数组内部本就有序，所以只需检查两个跨数组边界。两条都成立，整个左舱必然不大于整个右舱。

二分单调性：A 切口向右时，A左只会变大、A右只会变大，而 B 切口向左，B左与B右只会变小。因此“切多/切少”有明确方向。

03

边界情况与哨兵

EMPTY SIDE

一个数组为空

切口可以落在 0；边界外用 ±∞，无需特判返回逻辑。

CUT AT EDGE

切口在头或尾

左侧不存在视作 −∞，右侧不存在视作 +∞。

DUPLICATES

大量重复值

合法条件必须用 ≤，相等就是正确切分，不能继续移动。

OVERFLOW

偶数平均值

先转浮点或除以 2.0；泛化到大整数时防止两数相加溢出。

TIME

O(log min(m,n))

二分只发生在较短数组，强于题目要求的 O(log(m+n))。

SPACE

O(1)

只维护切口与四个边界，不创建合并数组。

ALTERNATIVE

双指针 / 第 k 小

双指针更直观但 O(m+n)；递归淘汰第 k 小同样对数级，但边界与奇偶调用更绕。面试主推切分法。

class Solution {
    public double findMedianSortedArrays(int[] nums1, int[] nums2) {
        if (nums1.length > nums2.length) {
            return findMedianSortedArrays(nums2, nums1);
        }

        int m = nums1.length, n = nums2.length;
        int leftSize = (m + n + 1) / 2;
        int lo = 0, hi = m;

        while (lo <= hi) {
            int i = lo + (hi - lo) / 2;
            int j = leftSize - i;

            int leftA = i == 0 ? Integer.MIN_VALUE : nums1[i - 1];
            int rightA = i == m ? Integer.MAX_VALUE : nums1[i];
            int leftB = j == 0 ? Integer.MIN_VALUE : nums2[j - 1];
            int rightB = j == n ? Integer.MAX_VALUE : nums2[j];

            if (leftA <= rightB && leftB <= rightA) {
                int maxLeft = Math.max(leftA, leftB);
                if ((m + n) % 2 == 1) return maxLeft;
                int minRight = Math.min(rightA, rightB);
                return ((double) maxLeft + minRight) / 2.0;
            } else if (leftA > rightB) {
                hi = i - 1;
            } else {
                lo = i + 1;
            }
        }
        throw new IllegalArgumentException("Input arrays must be sorted");
    }
}

  const m = nums1.length;
  const n = nums2.length;
  const leftSize = Math.floor((m + n + 1) / 2);
  let lo = 0;
  let hi = m;

  while (lo <= hi) {
    const i = lo + Math.floor((hi - lo) / 2);
    const j = leftSize - i;
    const leftA = i === 0 ? -Infinity : nums1[i - 1];
    const rightA = i === m ? Infinity : nums1[i];
    const leftB = j === 0 ? -Infinity : nums2[j - 1];

    if (leftA <= rightB && leftB <= rightA) {
      const maxLeft = Math.max(leftA, leftB);
      if ((m + n) % 2 === 1) return maxLeft;
      return (maxLeft + Math.min(rightA, rightB)) / 2;
    }
    if (leftA > rightB) hi = i - 1;
    else lo = i + 1;
  }

面试高频追问

为什么一定在短数组上二分？

复杂度最优；同时 m≤n 能保证当 i∈[0,m] 时，配平后的 j 不会落到 B 的有效范围之外。

为什么 leftSize 要加 1 再除 2？

整数除法向下取整。总长为奇数时让左舱多一个，中位数就统一为左舱最大值。

能否改成找第 k 小？

可以，每轮淘汰某个数组的 k/2 个元素，复杂度同为对数级；但偶数中位数需调用两次或复用状态，切分法更利于面试表达。

常见错误雷达

  • ❌ 在长数组上二分：配平切口可能越界，复杂度也不够精确。
  • ❌ j 写成 (m+n)/2-i：奇数总长时左右数量分配错一位。
  • ❌ 只检查一条不等式：无法保证跨数组的另一侧仍然有序。
  • ❌ 边界直接取下标：i 或 j 位于 0/末尾时会越界，必须使用哨兵。
  • ❌ 移动方向反了：A左太大就向左；B左太大说明 A右太小，要向右。

60-SECOND RECAP

“我会在较短数组上二分切口 i，并用 j=(m+n+1)/2−i 让左半数量固定。读取四个边界，若 A左>B右就把 i 左移；若 B左>A右就右移。两条交叉不等式都成立时，奇数取左半最大值，偶数取左半最大与右半最小的平均值。时间 O(log min(m,n))，空间 O(1)。”
