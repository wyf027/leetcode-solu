01 / Problem

先明确要计算什么

两个整数的汉明距离，是它们二进制表示中对应位不同的位置数量。给定整数数组 nums，返回其中每一对整数的汉明距离之和。

官方示例

示例 1

输入
nums = [4,14,2]
输出
6
解释
4 = 0100，14 = 1110，2 = 0010；三对距离分别为 2、2、2，总和为 6。

示例 2

输入
nums = [4,14,4]
输出
4

约束

  • 1 <= nums.length <= 104
  • 0 <= nums[i] <= 109
  • 给定输入的答案在 32 位整数范围内。
totalHammingDistance(nums: integer[]) → integer

04 / Solution

不要枚举数对，改为枚举位列

0×1

核心洞察

固定某个二进制位：若这一位有 ones 个 1、n - ones 个 0，那么恰有 ones × (n - ones) 对整数在该位不同。把所有可能位的贡献相加即可。

完整过程

  1. 从第 0 位扫描到第 30 位；因为 nums[i] <= 10^9 < 2^30，31 位足够覆盖所有输入。
  2. 在每一位 bit，统计数组中该位为 1 的元素个数 ones。
  3. 该位为 0 的元素个数是 n - ones。
  4. 将两组之间的配对数加入答案。
answer = Σ(bit=0..30) ones(bit) × (n − ones(bit))

边界处理

  • 数组只有一个元素：不存在整数对，每一位贡献都为 0。
  • 所有元素相同：每一位要么全 0、要么全 1，总和为 0。
  • 元素可以是 0：右移与按位与仍然直接适用。
  • JavaScript 位运算按有符号 32 位执行；本题只检查 0～30 位且输入不超过 10^9，是安全的。
时间O(31n)等价于 O(n)
空间O(1)只用常数变量

正确性证明

单个位列的计数正确。固定第 bit 位，只有从“该位为 1”的集合中选一个数、从“该位为 0”的集合中选一个数，才会在这一位产生汉明距离 1。无序数对数量正好为 ones × zeros，且每对只被计数一次。
各位贡献可独立相加。一对整数的汉明距离等于它们所有不同位的个数，因此对每一位分别统计所有数对的贡献，再求和，与先对每个数对求距离再求和等价。
算法覆盖全部贡献。算法扫描了输入可能出现的全部二进制位，并在每位加入准确贡献，所以最终答案恰好是所有整数对汉明距离的总和。

替代方案

逐对计算：枚举所有 n(n-1)/2 个数对，对异或结果统计 1 的个数。它直观但时间复杂度为 O(n² · W)，当 n = 10^4 时不合适。位列计数把“先看数对”改成“先看位”，消除了二次枚举。

05 / Implementations

四种语言完整实现

代码均遵循官方函数签名；每份实现扫描 31 个二进制位。

JavaLeetCode 提交格式
class Solution {
    public int totalHammingDistance(int[] nums) {
        int answer = 0;
        int n = nums.length;

        for (int bit = 0; bit < 31; bit++) {
            int ones = 0;
            for (int num : nums) {
                ones += (num >> bit) & 1;
            }
            answer += ones * (n - ones);
        }

        return answer;
    }
}

07 / Interview Notes

面试追问与常见错误

为什么不是除以 2？

ones × zeros 是从两个互不相交的集合各选一个元素，天然对应一个无序数对；没有先后顺序导致的重复，因此无需除以 2。

能否只扫描到最大值的最高位？

可以。先求最大值，在它变为 0 前逐位扫描；固定扫描 31 位更简洁，仍是常数位宽。

如果输入扩展到 64 位整数呢？

扫描位数要扩展到对应宽度，并使用足以容纳乘积与答案的数据类型。Java 用 long，C++ 可用 long long；JavaScript 可考虑 BigInt 并避免普通位运算的 32 位截断。

能否在线支持不断加入新数字？

维护每一位已有的 1 数量和总元素数。加入新数时，第 bit 位若为 1，就新增当前 zeros 个差异；否则新增当前 ones 个差异，然后更新计数。

常见错误：枚举有序数对

双层循环若同时计算 (i,j) 与 (j,i) 会重复计数。位列公式避开了这个问题。

常见错误：位数少扫一位

10^9 的最高有效位下标是 29，但扫描 0～30 位最直观且安全。不要把“位数”和“最大下标”混淆。

常见错误：用异或汇总所有数字

所有数字的异或只能表达各位 1 数量的奇偶性，无法恢复不同数对的数量，信息不足。

常见错误：答案类型随意缩小

本题保证答案适配 32 位整数，但扩展约束后，单列的 ones × zeros 就可能溢出，应先提升运算类型。
