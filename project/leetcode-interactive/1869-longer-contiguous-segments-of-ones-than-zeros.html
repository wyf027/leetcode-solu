哪种连续子字符串更长

Longer Contiguous Segments of Ones than Zeros

比较两种字符的最长连续段。先观察和预测，再打开底部题解。

01 / 题目

给定只包含 0 和 1 的字符串 s。分别找到全由 1 构成的最长连续子字符串、全由 0 构成的最长连续子字符串。只有前者长度严格大于后者时返回 true，否则返回 false。不存在某种字符时，该字符的最长段长度记为 0。

参数：s: string　返回：boolean　函数：checkZeroOnes(s)

约束：1 ≤ s.length ≤ 100；每个 s[i] 只能是 '0' 或 '1'。

示例 1

输入：s = "1101"
输出：true

最长 1 段为 2，最长 0 段为 1；2 > 1。

示例 2

输入：s = "111000"
输出：false

两种最长段均为 3；相等不算严格更长。

示例 3

输入：s = "110100010"
输出：false

最长 1 段为 2，最长 0 段为 3；2 < 3。

04 / 思路与实现

准备好后再揭晓完整推导。

一次扫描，记录当前段与历史纪录

核心洞察

连续段遇到另一种字符就结束，不能跨段相加。用 ones、zeros 表示当前前缀末尾连续 1 和连续 0 的长度；用 maxOne、maxZero 保存扫描至今各自最长的长度。

完整过程

  1. 将四个计数器初始化为 0，自然覆盖某种字符不存在的情况。
  2. 读到 1：ones += 1，zeros = 0；读到 0：zeros += 1，ones = 0。
  3. 每一步更新两个最大值：当前连续段可能刷新对应纪录。
  4. 扫描全部字符后返回 maxOne > maxZero，相等时返回 false。

例如 s = "1101"：当前末尾段依次为 1×1、1×2、0×1、1×1；最长纪录最终为 (2, 1)，因此返回 true。末尾段在最后一个字符处已经参与更新，无须额外结算。

正确性证明

循环不变量：处理前 i 个字符后，ones 与 zeros 分别等于这个前缀末尾连续 1 与连续 0 的长度，maxOne 与 maxZero 分别等于这个前缀内两种最长连续段的长度。

初始前缀为空，四个值为 0，成立。加入一个新字符时，同种尾段延长一格，另一种尾段变为 0，两个尾段计数仍然正确。新增的连续段只能以新字符结尾，因此用旧纪录与新尾段长度取最大值后，历史纪录也正确。扫描结束时前缀就是整个 s，严格比较两个纪录正好满足题目要求。

边界与复杂度

单字符、全 0、全 1、交替串和并列最长都由同一逻辑处理。不存在的字符纪录保持 0。空串不在官方输入范围内；观察台会拒绝它。时间 O(n)，额外空间 O(1)，四语言实现均只保留四个计数器。演示为支持回退保存 O(n) 个状态，与提交算法的空间不同。

四语言完整代码

采用官方函数签名；下列代码尚未编译或执行验证。

Java

class Solution {
    public boolean checkZeroOnes(String s) {
        int ones = 0, zeros = 0, maxOne = 0, maxZero = 0;
        for (int i = 0; i < s.length(); i++) {
            if (s.charAt(i) == '1') {
                ones++;
                zeros = 0;
            } else {
                zeros++;
                ones = 0;
            }
            maxOne = Math.max(maxOne, ones);
            maxZero = Math.max(maxZero, zeros);
        }
        return maxOne > maxZero;
    }
}

替代方案

可只用“前一个字符 + 当前段长 + 两个最大值”，遇到字符改变时将段长重置为 1，同样 O(n) 时间、O(1) 额外空间。也可用两个指针一次跳过一整段，段结束时更新对应纪录。按另一种字符 split 后求最长片段比较简短，但会生成临时片段，通常需要 O(n) 额外空间，还需处理空片段。

常见错误

  • 比较 1 与 0 的总数：1100011 中 1 的数量更多，但最长段 2 小于 3。
  • 写成大于等于：111000 必须返回 false。
  • 字符切换后不清零另一计数器，导致跨段累加。
  • 只在字符改变时更新纪录，却忘记处理字符串最后一段。
  • 中途发现 maxOne 更大就返回 true，后面的 0 段仍可能反超。

面试追问

能处理流式输入吗？可以，持续保留四个计数器，流结束时比较；分块之间不要清零。

要返回最长段的位置呢？刷新纪录时同时保存末尾索引 i，起点为 i − 当前段长 + 1；并列时约定保留最早或最晚一段。

推广到更多字符？维护当前字符、当前长度，并在映射中记录每种字符的最大段长，时间 O(n)，空间 O(k)，k 是不同字符数。

能提前返回吗？仅凭当前纪录不能直接下结论；若要提前结束，必须用剩余长度推导对手可能达到的上界。本题 n ≤ 100，完整扫描足够直接。
