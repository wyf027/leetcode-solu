字符串中的最大奇数

Largest Odd Number in String

一串很长的数字，寻找其中数值最大的奇数。先理解问题，再展开下方的推演与题解。

01 / 问题

从连续片段中作出选择

给定表示大整数的字符串 num，从它的所有非空连续子字符串中，选出数值最大的奇数，并以字符串返回。若没有任何奇数片段，返回空字符串 ""。子字符串必须连续，不能跳过中间字符，也不能重新排列数字。

参数：num: string
返回：string
函数：largestOddNumber(num)
  • 1 ≤ num.length ≤ 10⁵。
  • num 只包含数字，且不含前导零。
  • 输入可能远超普通整数类型的表示范围。

04 / 独立题解

核心洞察：先找能当结尾的数字

十进制整数的奇偶性只由末位决定。因此合法片段必须以 1、3、5、7、9 结尾。对同一个结尾，尽量向左延长到字符串开头，得到数值最大的候选；再选择最靠右的奇数结尾，保留最长前缀。

从右向左找第一个奇数字符，返回到它为止的前缀。找不到就返回 ""。

完整过程
  1. 令 i = num.length - 1，从最后一位开始。
  2. 判断 num[i] 是否为奇数字符。若是，返回 num[0..i]，右端点包含在结果中。
  3. 否则将 i 减 1，继续向左。
  4. 当 i < 0，说明每位都是偶数，返回空字符串。
例如 num = "203040"：依次检查索引 5 的 0、4 的 4、3 的 0，均不能作为奇数结尾；索引 2 的 3 是奇数，返回 "203"。前缀内部的 2、0 必须保留。
正确性证明
合法性：找到的索引 r 对应奇数字符，因此前缀 num[0..r] 是非空奇数；输入无前导零，该前缀也无前导零。
最大性：设任意合法子串为 num[l..j]。由于 r 是最右侧奇数位置，必有 j ≤ r。若该子串不是 num[0..r]，则其长度严格小于 r + 1。无前导零的 r + 1 位正整数，大于任意更短的非负十进制数字串所表示的数。因此此候选最大。
无解与终止：若扫描完仍未命中奇数，所有可能末位均为偶数，不存在合法奇数片段。每轮索引减 1，最多检查 n 位，必然终止。
边界与复杂度
  • 末位为奇数：立即确定整串是答案；构造返回字符串仍可能有复制成本。
  • 全偶数：返回 ""，而不是 "0"。
  • 只有一位：按该位奇偶返回本身或空串。
  • 超长输入：只读字符，不把整个字符串转换为数值。
  • 时间：最坏 O(n)，包含扫描与结果复制。辅助空间 O(1)；若计入返回字符串的物化存储，最多 O(n)。字符串切片是否共享存储由语言运行时决定。

Java
class Solution {
    public String largestOddNumber(String num) {
        for (int i = num.length() - 1; i >= 0; i--) {
            if ((num.charAt(i) - '0') % 2 == 1) {
                return num.substring(0, i + 1);
            }
        }
        return "";
    }
}

替代方案
从左向右记录最后一个奇数的位置：每次遇到奇数就更新下标，最后截取前缀。时间 O(n)、辅助空间 O(1)，但即使末位为奇数，也要扫描全部字符。
枚举所有子串：共有 O(n²) 个片段，还需要比较数值或字符串；朴素复制与比较可达 O(n³)。它忽略了末位与长度结构，不适合 10⁵ 位输入。
常见错误
  • 返回最大奇数字符，而不是最大奇数片段；例如 "203040" 的答案是 "203"。
  • 删除字符串内部所有偶数，破坏连续性。
  • 使用 Number(num)、parseInt(num) 或普通整数类型处理整串，产生精度或溢出问题。
  • 切片终点写成 i，漏掉刚找到的奇数；半开区间终点应为 i + 1。
  • C++ 用无符号索引倒序并判断 i ≥ 0，会在减至 0 后下溢。
面试追问
如果允许前导零？仍可保留到最右奇数的前缀，但最长不再保证严格更大，可能出现数值相等；还需明确输出是否必须去掉前导零。
如果必须返回固定长度 k 的片段？最长前缀的论证不再适用，需要比较所有长度为 k 且末位为奇数的候选。
如果要找能被 3 整除的最大子串？末位不足以决定合法性，应考虑数字和模 3，当前贪心不能直接套用。
