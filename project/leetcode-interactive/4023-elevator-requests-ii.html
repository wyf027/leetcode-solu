4023. 电梯请求 II

所有请求同时到达。电梯每秒只能移动一层；请求被经过时立即完成，代价是所有请求的完成时刻之和。

关键词：排序、连续已服务区间、两端位置、剩余请求数加权距离。

题意，先把“惩罚”翻译成可计算的量

楼层编号为 0…n-1，起点为 start，requests 内楼层互异。电梯从时间 0 起移动；到达一个请求楼层就完成该请求。若 start 本身是请求，则它的完成时刻为 0。

总惩罚 = Σ 每个请求的完成时刻。等价地：每移动 1 秒，就为“仍未完成”的每个请求支付 1；本秒增量 = 剩余请求数。
例 1
n=6, start=4, [1,5]
4→5→1：1 + 5 = 6
例 2
n=8, start=3, [3,7,1]
3 时刻 0 完成：0 + 2 + 8 = 10
约束
requests.length ≤ 1500
需要 O(m²)，不能枚举访问排列。

核心洞察

  1. 排序后，任何一次移动若越过一个请求，它就已被服务。
  2. 因此已服务的请求总是排序数组中包含 start 的连续区间。
  3. 下一次只可能把区间向左或向右扩张一个端点。
  4. 移动距离乘以当前未完成请求数，就是本段对答案的贡献。
别把 n 带进 DP：没有请求的楼层只影响坐标差；状态规模只与请求数 m 有关。

状态与转移

将 start 加入并去重排序为 a，其位置为 s。weight[i] 表示该点是否真是请求（起点被额外加入时权重 0）。

dp[l][r][side]：已覆盖 [l,r]，人位于 a[l]/a[r] 的最小惩罚。
remain = totalRequests − sum(weight[l..r])
扩张到新端点：newCost = old + distance × remain

初值 dp[s][s][0] = dp[s][s][1] = 0。终点取 min(dp[0][k-1][0], dp[0][k-1][1])。

完整过程：样例 start=5, requests=[0,2,9]

0 秒：已覆盖虚拟区间 [5,5]，还有 3 个请求。
选左端 2：走 3 层，增量 3×3=9；2 在 t=3 完成。
继续左端 0：走 2 层，增量 2×2=4；0 在 t=5 完成。
最后右端 9：走 9 层，增量 9×1=9；9 在 t=14 完成。
总惩罚 9+4+9=22，与 3+5+14=22 完全一致。

/** @param {number} n @param {number} start @param {number[]} requests */
var minPenalty = function(n, start, requests) {
  const req = new Set(requests), a = [...new Set([...requests, start])].sort((x, y) => x - y);
  const s = a.indexOf(start), k = a.length, total = requests.length;
  const pref = [0]; for (const x of a) pref.push(pref.at(-1) + (req.has(x) ? 1 : 0));
  const dp = Array.from({length:k}, () => Array.from({length:k}, () => [Infinity, Infinity]));
  dp[s][s] = [0, 0];
  for (let len = 1; len <= k; len++) for (let l = 0; l + len <= k; l++) {
    const r = l + len - 1; if (l > s || r < s) continue;
    const remain = total - (pref[r + 1] - pref[l]);
    for (let side = 0; side < 2; side++) { const cur = dp[l][r][side], p = a[side ? r : l]; if (!Number.isFinite(cur)) continue;
      if (l) dp[l - 1][r][0] = Math.min(dp[l - 1][r][0], cur + (p - a[l - 1]) * remain);
      if (r + 1 < k) dp[l][r + 1][1] = Math.min(dp[l][r + 1][1], cur + (a[r + 1] - p) * remain);
    }
  } return Math.min(...dp[0][k - 1]);
};

边界、复杂度与替代方案

  • start 是请求：权重 1 但在初始区间已完成，代价 0。
  • 只有一个请求：如果等于 start，答案 0；否则距离就是答案。
  • 答案最大量级约为 1500 × 1e9，用 64 位整数。
  • 时间 O(m²)，空间 O(m²)，m ≤ 1500 可行。
  • 替代：递归记忆化表达相同状态，更直观但可能有栈深度问题；贪心“最近优先”不保证最优。

常见错误与追问

  • 错误：转移后用新的剩余数。正确：整段移动期间原来的未完成请求都在等待。
  • 错误：只记录 l,r 不记录端点。下一段距离依赖当前位置。
  • 错误：把经过的请求漏算。排序后扩张端点正是在一次性服务所有被跨过的点。
  • 追问：若每个请求权重不同？把 remain 换成剩余权重和即可。
  • 追问：若请求有到达时刻？“已服务连续区间”不再足够，需要显式处理时间。
