732. 我的日程安排表 III

My Calendar III —— 每加入一段半开时间区间，就回答此刻日历中的最高重叠层数。

HARD 非付费题 设计 前缀和 有序集合

Problem

先把日程规则说清楚

当 k 个日程拥有一段非空的公共时间，就形成一次 k 重预订。现在按顺序加入若干日程 [startTime, endTime)；每次加入后，返回迄今所有日程能达到的最大重叠数 k。

半开区间很重要：日程包含开始时刻、不包含结束时刻。因此 [10, 20) 与 [20, 30) 首尾相接，但并不重叠。

  • MyCalendarThree() 初始化一个空日历。
  • int book(int startTime, int endTime) 加入区间 [startTime, endTime)，返回日历当前最大 k 重预订。

约束

  • 0 ≤ startTime < endTime ≤ 10⁹
  • 每个测试用例最多调用 book 400 次。

数值范围很宽，但调用次数有限；你需要维护不断变化的日历状态。

官方示例 · 完整参数形式

Solution

准备好再揭开方法

题解与四种语言代码默认收起。建议先在上方播放完整个示例，并尝试解释为什么第五次预订没有把答案推到 4。

Sweep Line

差分事件 + 有序扫描

把每段日程压缩成两个边界变化；按时间累加变化量，就能恢复每一段时间的同时进行数量。

核心洞察

区间 [start, end) 会让“正在进行的日程数”从 start 起增加 1，并从 end 起减少 1。因此只需在有序映射中记录两个变化：

delta[start] += 1
delta[end] -= 1

从最早时间向后累加 delta，当前前缀和就是该处活跃日程数；扫描过程中出现的最大前缀和就是答案。

完整过程

  1. 维护一个按时间点排序的变化表 delta。
  2. 收到 book(startTime, endTime) 时，在开始点加 1，在结束点减 1。
  3. 按时间从小到大遍历全部变化点，累加得到 active。
  4. 持续更新 best = max(best, active)，扫描结束后返回 best。
  5. 变化表不会在调用之间清空，因此自然保留了之前所有预订。

正确性证明

1

边界变化正确

每个日程在 start 处进入活跃集合，在 end 处离开。结束点记 −1 恰好符合右端不包含的半开区间定义。

2

前缀和等于重叠数

扫描到任意时间点时，累计变化量等于此前开始但尚未结束的日程数量，也就是该处的重叠层数。

3

最大值就是答案

重叠数只可能在边界处发生改变。遍历所有有序边界并取最大前缀和，不会遗漏任何可能的最大重叠区间。

结论：每次 book 返回的值恰好是加入当前日程后，整个日历中的最大 k 重预订。

边界与细节

  • 相邻区间在同一时间点发生 −1 与 +1，净变化可为 0，不会被误判为重叠。
  • 相同区间可重复预订，每次都会再贡献一对变化量。
  • 时间值达到 10⁹ 也无妨：算法只处理出现过的边界，不展开整条时间轴。
  • 变化量为 0 的键可以保留，不影响前缀和与答案。
  • 空日历只存在于构造完成、尚未调用 book 的状态。

复杂度

设当前不同边界点数量为 P，P ≤ 2m，m 为已预订次数。

  • Java / C++：更新边界 O(log P)，随后有序扫描 O(P)，单次总体 O(P)。
  • JavaScript / Python：普通映射更新 O(1) 均摊，调用时排序并扫描 O(P log P)。
  • 空间复杂度均为 O(P)。

在最多 400 次调用的约束下，这一实现清晰且足够高效。

替代方案

  • 动态开点线段树：在 [0, 10⁹] 上做区间加、查询全局最大值，单次约 O(log 10⁹)。适合调用次数更大，但节点与懒标记实现更复杂。
  • 坐标压缩 + 树状结构：如果全部区间能离线获得，可先收集边界再压缩；本题在线逐次返回答案，后续新坐标会让维护更麻烦。
  • 分段有序映射：维护每个连续片段的计数并在新边界处分裂。可以避免每次全量扫描，但正确处理分裂、合并更容易出错。

四种语言完整代码

均遵循官方 MyCalendarThree 类与 book(startTime, endTime) 签名。

JavaTreeMap 保持边界有序
import java.util.Map;
import java.util.TreeMap;

class MyCalendarThree {
    private final TreeMap<Integer, Integer> delta;

    public MyCalendarThree() {
        delta = new TreeMap<>();
    }

    public int book(int startTime, int endTime) {
        delta.merge(startTime, 1, Integer::sum);
        delta.merge(endTime, -1, Integer::sum);

        int active = 0;
        int best = 0;
        for (Map.Entry<Integer, Integer> entry : delta.entrySet()) {
            active += entry.getValue();
            best = Math.max(best, active);
        }
        return best;
    }
}
JavaScriptMap + 数值排序
var MyCalendarThree = function() {
    this.delta = new Map();
};

/**
 * @param {number} startTime
 * @param {number} endTime
 * @return {number}
 */
MyCalendarThree.prototype.book = function(startTime, endTime) {
    this.delta.set(startTime, (this.delta.get(startTime) || 0) + 1);
    this.delta.set(endTime, (this.delta.get(endTime) || 0) - 1);

    const times = Array.from(this.delta.keys()).sort((a, b) => a - b);
    let active = 0;
    let best = 0;

    for (const time of times) {
        active += this.delta.get(time);
        best = Math.max(best, active);
    }
    return best;
};
Pythondict + sorted
class MyCalendarThree:
    def __init__(self):
        self.delta = {}

    def book(self, startTime: int, endTime: int) -> int:
        self.delta[startTime] = self.delta.get(startTime, 0) + 1
        self.delta[endTime] = self.delta.get(endTime, 0) - 1

        active = 0
        best = 0
        for time in sorted(self.delta):
            active += self.delta[time]
            best = max(best, active)
        return best
C++std::map 有序遍历
#include <algorithm>
#include <map>

class MyCalendarThree {
private:
    std::map<int, int> delta;

public:
    MyCalendarThree() = default;

    int book(int startTime, int endTime) {
        ++delta[startTime];
        --delta[endTime];

        int active = 0;
        int best = 0;
        for (const auto& [time, change] : delta) {
            active += change;
            best = std::max(best, active);
        }
        return best;
    }
};

  • 为什么结束点必须减 1？闭区间 [start, end] 又该如何处理？
  • 如何同时返回“最大重叠发生在哪个时间段”？
  • 如果支持取消一条已存在的预订，状态结构要怎样修改？
  • 动态线段树中的区间加与全局最大值应维护哪些字段？

常见错误

  • 把右端点当成包含，导致首尾相接的日程被算作重叠。
  • 每次调用重新创建变化表，丢掉了历史预订。
  • 按字符串而非数值排序 JavaScript 的时间点，例如 100 会排在 20 前。
  • 只在 start 点检查计数，却没有按所有边界顺序做完整前缀累加。
  • 试图开辟长度 10⁹ 的数组，忽略了坐标范围远大于调用次数。
