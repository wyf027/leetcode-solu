Problem brief

先读档案，再看算法

死亡年份仍计入生存人数，这是差分落点最容易写错的地方。

任务

给定等长数组 birth 和 death，第 i 个人从 birth[i] 到 death[i]（两端都包含）均应计入当年人口。 返回生存人数最多的年份；若并列，返回最早年份。

1900 ≤ birth[i] ≤ death[i] ≤ 2000 0 < birth.length = death.length ≤ 10,000

官方示例

1901 年第一次达到 2 人；1950 和 1951 年虽也有 2 人，但更晚。

输入 birth = [1900, 1901, 1950]
输入 death = [1948, 1951, 2000]
输出 1901

核心洞察

年份范围只有 101 个。无需逐人覆盖每个生存年份，只记录区间端点变化： 出生年 +1，死亡年份之后的第一年 −1。 对差分数组求前缀和，就得到每年的生存人数。

为什么是 death + 1

题目明确死亡当年仍算生存。因此区间是 [birth, death]，人口减少必须从 death + 1 开始。即使死亡年份是 2000，也可在长度 102 的差分数组末尾安全登记。

完整过程

  1. 创建长度 102 的 delta，对应 1900 到 2001。
  2. 对每个人执行 delta[birth - 1900]++。
  3. 再执行 delta[death - 1900 + 1]--。
  4. 从 1900 扫到 2000，将差分累加为当年人口。
  5. 仅在人口严格大于历史峰值时更新答案，因此并列时自然保留最早年份。

边界

  • 同年出生并死亡：当年必须计 1 人。
  • 死亡年份 2000：减一事件写入 2001，不参与答案扫描。
  • 峰值并列：判断必须使用 >，不能使用 >=。
  • 数组至少含一人，所以答案必在 1900 到 2000 之间。

复杂度

时间 O(n + 101) 登记 n 人，再扫固定年份
空间 O(101) 固定大小差分数组

替代方案

  • 逐年统计每个人：直观但为 O(101n)。
  • 分别排序出生与死亡年份后双指针：O(n log n)，适合年份范围很大时。
  • 事件哈希表加排序：能处理稀疏、无固定上下界的年份。

面试追问

  • 若年份范围扩展到 64 位整数，怎样改成排序事件或双指针？
  • 若死亡当年不计入，差分的减一位置如何改变？
  • 若要返回所有峰值年份，如何记录连续区间与离散年份？

常见错误

  • 在 death 当年减一，漏掉死亡当年的生存计数。
  • 并列时用 >= 更新，错误返回最后一个峰值年。
  • 只开 101 个位置，导致死亡于 2000 时写越界。
  • 把实际年份直接作为数组下标，浪费空间或越界。
