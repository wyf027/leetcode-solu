到达终点数字 Reach a Number

你从无限数轴上的位置 0 出发。第 i 次移动必须恰好走 i 步，但方向可以向左或向右。给定整数终点 target，求抵达它所需的最少移动次数。

reachNumber(target: integer) → integer
01

先把规则走清楚

方向自由选择，步长却由移动序号严格决定。

任务

从 0 开始进行若干次移动。每次只能二选一：向左或向右；第 i 次移动的距离固定为 i。返回恰好到达 target 的最小移动次数 numMoves。

↔
方向可选 每轮都能独立选择向左或向右。
i
距离固定 第 i 次一定移动 i 步，不能少也不能多。

题解入口

已经形成自己的判断了吗？题解会从“为什么只看距离与奇偶”开始完整展开。

把“选方向”改写成“翻转步长”

先假设所有移动都朝目标方向进行，得到一段连续增长的总距离；再把若干步翻到反方向。一次翻转会让最终位置减少该步长的两倍，因此能否到达只剩两个条件：距离够、差值为偶数。

Sₙ = 1 + 2 + ⋯ + n = n(n + 1) / 2
可达 ⇔ Sₙ ≥ |target| 且 (Sₙ − |target|) % 2 = 0

核心洞察

  • 数轴左右完全对称，所以先令 goal = |target|，只讨论正方向。
  • 走完 n 步且全部向右时，总和是三角数 Sₙ，这是 n 步能达到的最远距离。
  • 若把长度为 x 的若干步从右改成左，最终位置从 Sₙ 变成 Sₙ − 2x。
  • 因而 Sₙ − goal 必须为非负偶数；反过来，只要满足这两个条件，就能选出步长总和为 (Sₙ − goal) / 2 的步进行翻转。

完整过程

  1. 取目标绝对值，初始化 moves = 0、sum = 0。
  2. 只要距离不够，或差值为奇数，就再走一步，并把新步长累加到 sum。
  3. 第一次同时满足距离条件与偶数条件时，当前 moves 就是答案。

正确性证明

  1. 必要性。固定移动次数 n 后，所有步向目标方向时位置为 Sₙ。改变一组步的方向，相当于从 Sₙ 中减去这些步长总和的两倍。因此若能到达 goal，必有 Sₙ ≥ goal，且 Sₙ − goal 为偶数。
  2. 充分性。若 Sₙ ≥ goal 且差值为偶数，令 x = (Sₙ − goal) / 2。连续整数 1…n 可以组成区间 [0, Sₙ] 内的任意整数：加入 k 时，原来的 [0, Sₖ₋₁] 与加 k 后的 [k, k + Sₖ₋₁] 相接。故能选出总和为 x 的若干步并翻转，最终位置恰为 goal。
  3. 最小性。循环按 n = 1, 2, 3… 依次检查。所有更小 n 都至少违反必要条件之一；循环首次停止的 n 可由充分性保证可达，所以它就是最小移动次数。
  4. 负目标。把上述全部方向镜像，就能以相同移动次数到达 −goal，因此取绝对值不会改变答案。

边界与实现细节

  • target = ±1 时第一步即可抵达。
  • 刚超过目标并不一定可达，还必须检查差值的奇偶性。
  • 负数取绝对值后统一处理，最终不需要真的构造移动方向。
  • Java 与 C++ 中用 64 位整数保存绝对值和累加和，更稳妥地避免溢出习惯问题。
  • 超过距离门槛后，三角数奇偶按固定节奏变化，至多再增加两步就会得到偶数差。

复杂度

时间复杂度 O(√|target|)

三角数达到目标时，n 约为 √(2·|target|)。

空间复杂度 O(1)

只维护目标绝对值、步数与累加和。

四语言完整代码

class Solution {
    public int reachNumber(int target) {
        long goal = Math.abs((long) target);
        long sum = 0;
        int moves = 0;

        while (sum < goal || ((sum - goal) & 1L) != 0) {
            moves++;
            sum += moves;
        }

        return moves;
    }
}

替代方案

  • 二分三角数：先二分最小 n，使 n(n + 1)/2 ≥ goal，再根据差值奇偶继续增加至多两步。它把寻找距离门槛降到 O(log |target|)，但代码更长，仍需同样的奇偶修正。
  • 公式近似：可用平方根估算 n，再校准边界。浮点舍入容易埋下边界错误，面试中通常不如简单累加稳妥。
  • BFS：虽然能枚举位置，却会产生大量重复状态，目标可达 10⁹，时间和空间都不现实。
推荐主解使用顺序累加：证明短、实现小，而且约 4.5 万轮就能覆盖最大输入。

面试追问

  • 为什么翻转一步会改变偶数距离，而不是任意距离？
  • 怎样实际构造一条最短方向序列，而不只返回步数？
  • 第一次超过目标后，为什么最多再检查两步？
  • 若每一步的长度不再是连续整数 1…n，充分性还成立吗？
  • 如何用整数二分避免平方根带来的浮点误差？

常见错误

只检查 sum ≥ goal

例如 target = 2，走两步时 sum = 3 已超过目标，但奇数差无法通过翻转方向消掉。

忘记取绝对值

左右对称却分开写逻辑，会让循环条件和取模判断变得混乱。

把翻转理解成减去 x

原本贡献 +x，翻转后贡献 −x，净变化其实是 −2x。

忽略整数容量

在可扩展版本或语言边界中，累加三角数应优先使用 64 位整数。
