找出给定方程的
正整数解

面对一个公式未知、但沿两个坐标方向都严格递增的函数，找出所有让它恰好等于目标值的正整数坐标。

01

题目

给定可调用接口 CustomFunction.f(x, y) 与整数 z。函数的具体公式不可见，但对任意正整数参数都满足：

沿 x 方向

f(x, y) < f(x + 1, y)

沿 y 方向

f(x, y) < f(x, y + 1)

请返回所有满足 f(x, y) == z 的正整数数对 [x, y]，顺序不限。你只能调用接口，不能实现或猜测隐藏公式。

提交函数： findSolution(customfunction, z) → List<List<Integer>> / integer[][]

官方示例

Example 1 · 加法函数 
输入：function_id = 1, z = 5
输出：[[1,4],[2,3],[3,2],[4,1]]
解释：隐藏公式为 f(x, y) = x + y。
四组正整数数对的函数值都等于 5。
Example 2 · 乘法函数 
输入：function_id = 2, z = 5
输出：[[1,5],[5,1]]
解释：隐藏公式为 f(x, y) = x * y。
两组正整数数对的函数值都等于 5。

约束

  • 1 <= function_id <= 9
  • 1 <= z <= 100
  • 所有解都位于 1 <= x, y <= 1000。
  • 当 1 <= x, y <= 1000 时，f(x, y) 保证落在 32 位有符号整数范围内。

    04

    完整题解

    核心洞察：把所有 f(x,y) 看成一个行列都严格递增的矩阵。从左下角 (1,1000) 出发，每次比较都能安全排除一整段候选方向。
    小于 z

    x 必须增大

    若 f(x,y) < z，当前固定 x 下更小的 y 只会让值更小，因此令 x++。

    大于 z

    y 必须减小

    若 f(x,y) > z，当前固定 y 下更大的 x 只会让值更大，因此令 y--。

    完整过程

    1
    初始化

    令 x = 1、y = 1000，结果数组为空。

    2
    调用并比较

    计算 value = customfunction.f(x, y)。小于目标就右移（x++），大于目标就下移（y--）。

    3
    记录命中

    若等于 z，记录 [x,y]。严格递增意味着同一行、同一列不会再有第二个命中，所以同时执行 x++ 与 y--。

    4
    结束

    当 x > 1000 或 y < 1 时，搜索边界相交，所有可能解都已处理。

    正确性证明

    循环不变式：每轮开始时，所有尚未排除的解都位于当前指针右下侧尚未越过的矩形边界中。

    • 若 f(x,y) < z，对任何 y' <= y 都有 f(x,y') <= f(x,y) < z，所以第 x 行剩余位置不可能是解，排除该行安全。
    • 若 f(x,y) > z，对任何 x' >= x 都有 f(x',y) >= f(x,y) > z，所以第 y 列剩余位置不可能是解，排除该列安全。
    • 若相等，则当前数对被正确加入；严格单调保证当前行与列的其余候选都不可能再次等于 z，两边同时推进安全。

    每轮至少让 x 增加或让 y 减少，最终越界终止。由不变式，终止时没有未检查的潜在解；同时算法只记录函数值恰等于 z 的数对，因此结果恰好包含全部解。

    复杂度

    时间：O(M + N)，这里 M=N=1000，最多约 1999 次接口调用。
    额外空间：O(1)（不计输出）。

    边界

    z=1、无解、解在 x=1000 或 y=1000、仅一个解，以及多个解都由同一循环自然覆盖。

    Java
    /* CustomFunction 由判题环境提供，不要实现。 */
class Solution {
    public List<List<Integer>> findSolution(CustomFunction customfunction, int z) {
        List<List<Integer>> answer = new ArrayList<>();
        int x = 1;
        int y = 1000;

        while (x <= 1000 && y >= 1) {
            int value = customfunction.f(x, y);
            if (value == z) {
                answer.add(Arrays.asList(x, y));
                x++;
                y--;
            } else if (value < z) {
                x++;
            } else {
                y--;
            }
        }
        return answer;
    }
}

    替代方案

    枚举：遍历 1000×1000 个数对，时间 O(MN)，简单但接口调用多。
    逐行二分：对每个 x 在 y 上二分，时间 O(M log N)；可行，但没有充分利用跨行的单调边界。

    常见错误

    • 从 (1,1) 出发，却无法根据一次比较唯一决定移动方向。
    • 命中后只移动一个指针，产生无效额外调用。
    • 把坐标 0 纳入搜索，违反正整数约束。
    • 尝试根据 function_id 猜公式，而不是只依赖接口单调性。

    面试追问

    • 如果函数只是非严格单调？ 同一行或列可能有多个相等值，命中后双向推进会漏解，需要处理平台区间。
    • 如果上界未知？ 可先对 y 做指数扩张找到覆盖目标的上界，再执行阶梯搜索，但要明确接口定义域和溢出边界。
    • 为什么答案顺序不重要？ 题目允许任意顺序；该遍历自然按 x 递增、y 递减产生结果。
