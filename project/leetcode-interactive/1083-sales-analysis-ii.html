销售分析 II

先理解筛选目标，再按步骤观察“买过 S8”与“买过 iPhone”两个买家集合如何做差。

题目

给定产品表 Product 与销售表 Sales，查询所有购买过 S8、但从未购买过 iPhone 的买家编号 buyer_id。结果行顺序不作要求。

Product(product_id, product_name, unit_price)

  • product_id INT：产品编号
  • product_name VARCHAR(10)：产品名
  • unit_price INT：单价

Sales(seller_id, product_id, buyer_id, sale_date, quantity, price)

  • 记录卖家、产品、买家及销售日期
  • 同时包含数量与本次销售总价
约束说明：官方付费题面正文未包含在本地元数据中；可确认的约束为上述官方字段类型与两表通过 product_id 关联。输入数据应满足这些表结构。

完整题解

核心洞察

这不是“存在一条 S8 记录”这么简单，还必须证明同一买家不存在任何 iPhone 记录。用一次连接取得产品名，再按买家分组；条件聚合分别统计两类购买记录即可。

完整过程

  1. 通过 Sales.product_id = Product.product_id 连接销售与产品。
  2. 按 buyer_id 分组。
  3. 用条件聚合确保 S8 计数大于 0。
  4. 用条件聚合确保 iPhone 计数等于 0。

正确性说明

对任意输出的买家，第一条 HAVING 条件保证其连接记录中至少存在一条 S8，第二条保证不存在 iPhone，因此满足题意。反过来，任何满足题意的买家都至少贡献一次 S8 计数且 iPhone 计数为零，必然通过两条条件并被输出。因此结果恰好是所有目标买家。

边界

  • 同一买家重复买 S8：分组后只返回一次
  • 先后购买顺序不影响结果
  • 没有 S8 销售时结果为空

复杂度

设销售记录数为 S、产品数为 P。典型哈希连接与聚合时间 O(S + P)，辅助空间 O(B + P)，B 为不同买家数；实际取决于数据库执行计划与索引。

替代方案

也可用 EXISTS + NOT EXISTS，语义直接；或对两个买家集合做差集。条件聚合通常最紧凑。

MySQL（官方可提交语言）

SELECT s.buyer_id
FROM Sales AS s
JOIN Product AS p
  ON p.product_id = s.product_id
GROUP BY s.buyer_id
HAVING SUM(CASE WHEN p.product_name = 'S8' THEN 1 ELSE 0 END) > 0
   AND SUM(CASE WHEN p.product_name = 'iPhone' THEN 1 ELSE 0 END) = 0;

四语言本地语义参考

本题官方提交类型是数据库。下面四份代码只是在内存数组上复现同一筛选语义，不能直接提交到该 SQL 题。

import java.util.*;

class Solution {
    // products: [product_id, name]；sales: [seller_id, product_id, buyer_id]
    public List<Integer> buyers(List<Object[]> products, List<int[]> sales) {
        Map<Integer, String> name = new HashMap<>();
        for (Object[] p : products) name.put((Integer) p[0], (String) p[1]);
        Set<Integer> s8 = new HashSet<>(), iphone = new HashSet<>();
        for (int[] s : sales) {
            String n = name.get(s[1]);
            if ("S8".equals(n)) s8.add(s[2]);
            if ("iPhone".equals(n)) iphone.add(s[2]);
        }
        s8.removeAll(iphone);
        return new ArrayList<>(s8);
    }
}
function buyers(products, sales) {
  const name = new Map(products.map(([id, productName]) => [id, productName]));
  const s8 = new Set();
  const iphone = new Set();
  for (const [, productId, buyerId] of sales) {
    if (name.get(productId) === "S8") s8.add(buyerId);
    if (name.get(productId) === "iPhone") iphone.add(buyerId);
  }
  return [...s8].filter((buyerId) => !iphone.has(buyerId));
}
def buyers(products, sales):
    name = {product_id: product_name for product_id, product_name in products}
    s8, iphone = set(), set()
    for _, product_id, buyer_id in sales:
        if name.get(product_id) == "S8":
            s8.add(buyer_id)
        if name.get(product_id) == "iPhone":
            iphone.add(buyer_id)
    return list(s8 - iphone)
#include <string>
#include <unordered_map>
#include <unordered_set>
#include <vector>
using namespace std;

vector<int> buyers(const vector<pair<int,string>>& products,
                   const vector<vector<int>>& sales) {
    unordered_map<int,string> name;
    for (const auto& p : products) name[p.first] = p.second;
    unordered_set<int> s8, iphone;
    for (const auto& s : sales) {
        if (name[s[1]] == "S8") s8.insert(s[2]);
        if (name[s[1]] == "iPhone") iphone.insert(s[2]);
    }
    vector<int> answer;
    for (int id : s8) if (!iphone.count(id)) answer.push_back(id);
    return answer;
}

面试追问

  • 若产品名不唯一，怎样改为按产品编号或产品类别筛选？
  • NOT IN 遇到 NULL 会有什么三值逻辑问题？
  • 哪些索引有助于连接与按买家聚合？

常见错误

  • 只筛选 product_name = 'S8'，忘记排除买过 iPhone 的买家。
  • 在 WHERE 中同时写产品名是 S8 且不是 iPhone；单行条件无法观察同一买家的其他行。
  • 未分组或去重，导致重复输出买家编号。
  • 用 NOT IN 时忽略子查询 NULL 的影响。
