01 · 题目

规则很少，选择很重

返回 boolean

给定一个整数数组 piles，表示从左到右排成一行的石子堆。石子堆数量为偶数，每堆石子数为正整数，且全部石子总数为奇数，因此不会平局。

  • Alice 先手，Bob 后手，二人轮流行动。
  • 每回合只能拿走当前行最左端或最右端的整堆石子。
  • 所有石子堆取完后，石子总数更多的人获胜。
  • 双方都采用最优策略，判断 Alice 是否获胜。
约束
2 <= piles.length <= 500
piles.length % 2 == 0
1 <= piles[i] <= 500
sum(piles) % 2 == 1
示例 1
输入：piles = [5,3,4,5]
输出：true
解释：Alice 若先取左端 5，无论 Bob 接着取 3 还是右端 5，Alice 都能在下一步取得足够石子并最终获胜。
示例 2
输入：piles = [3,7,2,3]
输出：true

03 · 题解

区间 DP：把“我能拿多少”改写成“我能领先多少”

拿走一端以后，原来的对手就成了新区间的“当前玩家”。

因此最自然的状态不是分别记录 Alice、Bob 的分数，而是记录当前玩家相对另一人的最大净胜分。角色交换会自动表现为一次减法。

  1. 定义状态
    dp[i][j]：面对区间 [i,j]，当前玩家最终最多比对手多得的石子数。
  2. 枚举选择
    取左端得到 piles[i] - dp[i+1][j]；取右端得到 piles[j] - dp[i][j-1]。
  3. 选择最优
    dp[i][j] = max(左方案, 右方案)。最终 dp[0][n-1] > 0 即为 Alice 获胜。

正确性证明

基础情形：当区间只有一堆 [i,i] 时，当前玩家直接取走它，净胜分为 piles[i]，所以状态定义成立。

归纳步骤：假设所有长度小于 L 的区间状态都正确。对长度为 L 的 [i,j]，当前玩家只有取左或取右两种合法选择。取左后，对手在 [i+1,j] 能取得的最大净胜分是 dp[i+1][j]，故当前玩家的净胜分是 piles[i]-dp[i+1][j]；右侧同理。选择两者较大值覆盖全部合法首步，因此 dp[i][j] 正确。由数学归纳法，最终状态正确。

结论：总数为奇数，不会出现净胜分 0；dp[0][n-1] > 0 当且仅当 Alice 在双方最优时获胜。

时间复杂度O(n²)枚举全部区间
空间复杂度O(n)滚动压缩 DP
判定条件dp[0] > 0先手净胜

边界与细节

  • 长度最小为 2，初始化时每个 dp[i] 对应单堆区间。
  • 必须按区间长度从短到长更新；一维写法中 i 从小到大即可保留所需的旧状态。
  • 虽然本题特定约束下 Alice 可用奇偶位置策略必胜，但 DP 更能迁移到“堆数可奇可偶”或其他类似博弈。
  • 正整数与奇数总和保证没有平局；通用版本若允许平局，应明确返回条件仍是严格大于 0。

替代方案对比

方案核心时间空间取舍

class Solution {
    public boolean stoneGame(int[] piles) {
        int n = piles.length;
        int[] dp = piles.clone();

        for (int len = 2; len <= n; len++) {
            for (int i = 0; i + len <= n; i++) {
                int j = i + len - 1;
                dp[i] = Math.max(piles[i] - dp[i + 1],
                                 piles[j] - dp[i]);
            }
        }
        return dp[0] > 0;
    }
}

面试追问

为什么状态用“分差”比用“总分”更自然？

因为每走一步玩家身份都会交换。分差在身份交换后只需取负，恰好转化为“当前所得 − 对手未来最优分差”，无需额外记录轮次与两份分数。

为什么本题可以直接返回 true？

初始有偶数堆，Alice 可以选择始终拿原数组偶数下标的堆或奇数下标的堆。两组总和不相等，她选择总和更大的一组，并能通过端点选择始终控制该奇偶组，因此必胜。

如何恢复每一步的最优选择？

保留二维 DP；在区间 [i,j] 比较两条转移的值，相等时任选，否则沿较大值对应的端点前进，直到区间为空。

常见错误

  • 贪心地每次拿较大端点；局部最大不保证最终最大。
  • 转移时忘记减去对手在子区间的净胜分，误写成加法。
  • 一维压缩时更新顺序错误，覆盖了仍需使用的旧状态。
  • 把 > 0 写成比较 Alice 获得的石子数与总和一半，却没有真正维护 Alice 的总分。
