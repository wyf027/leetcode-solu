Core insight

排序把“相同选择”排到一起

1. 先排序

例如 [2, 1, 1] 变成 [1, 1, 2]，两个 1 成为邻居。

2. 同路径防重复使用

used[i] 为 true 时跳过，保证每个索引只进入当前排列一次。

3. 同层剪掉等价分支

若 nums[i] 与左邻相等且左邻未使用，说明两者正竞争同一位置，只保留左边分支。

if (i > 0 && nums[i] === nums[i - 1] && !used[i - 1]) continue;
Why left unused?

关键是“同层”，不是永久禁止第二个重复值

LEFT UNUSED → PRUNE

左边相同值未进当前路径

两者处在同一层做同一个位置的选择，分支完全等价，当前项必须跳过。

LEFT USED → ALLOW

左边相同值已在当前路径

当前项正在更深一层填另一个位置，两个重复值都应被使用，因此允许选择。

Full process

完整解题过程

  1. STEP 1

    排序 nums

    让相同数字相邻，后续只需比较左邻。

  2. STEP 2

    准备 path、used、answer

    path 记录当前排列，used 按索引记录使用状态。

  3. STEP 3

    两次判断后做选择

    先跳过已使用索引，再执行同层去重条件；通过后 push 并递归。

  4. STEP 4

    到叶子复制，返回时撤销

    path 长度等于 n 时存副本；随后 pop 并恢复 used[i]。

边界情况

  • 全部相同：[0, 0, 0] 只有一个唯一排列。
  • 没有重复：剪枝条件从不触发，退化为第 46 题。
  • 未排序输入：必须先排序，否则相同元素不相邻，左邻判断会漏剪。
  • 重复值按索引区分：used 仍按索引记录，不能按数值记录。

复杂度

TIME

O(n × n!)

排序 O(n log n) 被排列枚举主项覆盖。

SPACE

O(n)

不计输出，递归、path、used 均为线性。

替代方案

每层 HashSet：每次递归用集合记录本层已经尝试的值，能避免排序依赖，但多出哈希空间和操作。

结果集合事后去重：会先生成大量重复叶子，浪费时间与内存，不推荐作为面试主线。

面试高频追问

  • 为什么必须排序？让相同值连续，才能 O(1) 判断同层重复。
  • 能写 used[i-1] 吗？那是另一种保留顺序；推荐固定记忆 !used[i-1]。
  • 答案数是多少？若计数为 c₁…cₖ，则为 n! / (c₁!…cₖ!)。

常见错误

  • 忘记排序就直接比较相邻值。
  • 把 !used[i - 1] 写成 used[i - 1]，导致错误剪枝。
  • 按数值记录 used，重复元素无法分别使用。
  • 回溯后忘记恢复 used 或 path。
