有限数字池、不可重复选择、双方都采取最优策略。你面对的不是一道“凑数题”，而是一棵由选择权驱动的对抗状态树。

01 · Problem

规则很短，分支很多

先理解选择如何改变公共状态，再考虑如何判断“当前玩家是否存在必胜选择”。

题意转述

两名玩家轮流从公共整数池 1..maxChoosableInteger 中选一个尚未被使用的整数，并把它加入累计和。某位玩家一旦使累计和达到或超过 desiredTotal，该玩家立即获胜。

给定 maxChoosableInteger 与 desiredTotal，判断先手在双方都采用最优策略时，能否保证获胜。每个整数最多只能被选择一次。

canIWin(maxChoosableInteger: integer, desiredTotal: integer) → boolean

约束与语义

  • 1 ≤ maxChoosableInteger ≤ 20
  • 0 ≤ desiredTotal ≤ 300
  • 选出的数字不放回，数字池由双方共享。
  • “稳赢”表示无论对手怎样最优应对，先手都有获胜策略。
示例 1
输入：maxChoosableInteger = 10,
      desiredTotal = 11
输出：false

先手无论选哪个数，后手都能选择与之互补到 11 的数并获胜。

示例 2
输入：maxChoosableInteger = 10,
      desiredTotal = 0
输出：true

目标已经达到，按题目定义直接返回真。

示例 3
输入：maxChoosableInteger = 10,
      desiredTotal = 1
输出：true

先手第一次选择任意可用正整数即可达到目标。

04 · Full solution

记忆化搜索：把输赢交给下一回合

核心洞察

对任意局面，只要当前玩家能选到一个数字，使自己立即达标，或使对手进入“必败局面”，当前局面就是必胜；如果所有合法选择都会把对手送入必胜局面，当前局面就是必败。

win(used) = 存在未使用的 i：i ≥ remaining，或 win(used ∪ {i}) = false

累计和可以由 used 中的数字唯一恢复，所以缓存键只需要位掩码，无需再拼接 remaining。

完整过程

先做三个快速判断

目标不大于 0 时直接返回真；最大可选数字已能达到目标时直接返回真；数字池总和仍小于目标时，无人能够达标，返回假。

用一位表示一个数字

第 i - 1 位为 1，表示数字 i 已被使用。最多 20 个数字，整数位掩码足够容纳全部状态。

枚举当前玩家的合法选择

若数字 i 未使用，则尝试选择它。若它立即达到剩余目标，当前状态必胜；否则递归询问对手在新状态能否获胜。

从对手的失败推出自己的胜利

只要某个分支令递归结果为假，就找到了当前玩家的必胜策略，立即缓存并返回真。

所有分支都不行则必败

当每个合法选择都能被对手最优反制时，缓存当前状态为假。记忆化避免从不同选择顺序反复计算同一数字集合。

正确性证明

命题：搜索函数返回真，当且仅当轮到当前玩家时存在必胜策略。

基础情况：若存在未使用数字 i ≥ remaining，当前玩家可立即达到目标，函数返回真，与规则一致。

归纳步骤：假设所有更深状态的结果正确。若某个选择使下一状态为假，则对手无必胜策略，当前玩家可保证获胜。反之，若每个下一状态都为真，则对手对每种选择都有必胜策略，当前玩家必败。

由有限状态树上的逆向归纳，根状态的结果正确。

复杂度与边界

时间：O(m · 2^m)，最多 2^m 个状态，每个枚举至多 m 个数字。

空间：O(2^m + m)，分别来自缓存与递归栈。

  • desiredTotal ≤ 0：直接为真。
  • m ≥ desiredTotal：先手一步获胜。
  • m(m+1)/2 < desiredTotal：总和不足，返回假。
  • 恰好达到与超过目标都算获胜。

替代方案与取舍

方案可行性取舍
纯回溯逻辑正确不同选择顺序会抵达同一使用集合，重复展开严重。
记忆化 DFS + 位掩码推荐直接表达“存在一个让对手输的选择”，适配 m ≤ 20。
自底向上状态 DP可以实现状态顺序更难安排，通常不如递归自然，仍需指数空间。
只看总和或奇偶不可行相同总和可能由不同数字集合形成，后续可选项不同。

Solution.java官方可提交
class Solution {
    private int maxNumber;
    private byte[] memo;

    public boolean canIWin(int maxChoosableInteger, int desiredTotal) {
        if (desiredTotal <= 0) return true;
        if (maxChoosableInteger >= desiredTotal) return true;
        int total = maxChoosableInteger * (maxChoosableInteger + 1) / 2;
        if (total < desiredTotal) return false;

        maxNumber = maxChoosableInteger;
        memo = new byte[1 << maxNumber];
        return dfs(0, desiredTotal);
    }

    private boolean dfs(int usedMask, int remaining) {
        if (memo[usedMask] != 0) return memo[usedMask] == 1;

        for (int number = 1; number <= maxNumber; number++) {
            int bit = 1 << (number - 1);
            if ((usedMask & bit) != 0) continue;
            if (number >= remaining
                    || !dfs(usedMask | bit, remaining - number)) {
                memo[usedMask] = 1;
                return true;
            }
        }

        memo[usedMask] = -1;
        return false;
    }
}

        if maxChoosableInteger >= desiredTotal:
            return True

        if total < desiredTotal:
            return False

        @lru_cache(maxsize=None)
        def dfs(used_mask: int, remaining: int) -> bool:
            for number in range(1, maxChoosableInteger + 1):
                bit = 1 << (number - 1)
                if used_mask & bit:
                    continue
                if number >= remaining or not dfs(
                    used_mask | bit, remaining - number
                ):
                    return True
            return False

        return dfs(0, desiredTotal)

class Solution {
private:
    int maxNumber;
    vector<int8_t> memo;

    bool dfs(int usedMask, int remaining) {
        if (memo[usedMask] != 0) return memo[usedMask] == 1;

        for (int number = 1; number <= maxNumber; ++number) {
            int bit = 1 << (number - 1);
            if ((usedMask & bit) != 0) continue;
            if (number >= remaining
                    || !dfs(usedMask | bit, remaining - number)) {
                memo[usedMask] = 1;
                return true;
            }
        }

        memo[usedMask] = -1;
        return false;
    }

public:
    bool canIWin(int maxChoosableInteger, int desiredTotal) {
        if (desiredTotal <= 0) return true;
        if (maxChoosableInteger >= desiredTotal) return true;
        int total = maxChoosableInteger * (maxChoosableInteger + 1) / 2;
        if (total < desiredTotal) return false;

        maxNumber = maxChoosableInteger;
        memo.assign(1 << maxNumber, 0);
        return dfs(0, desiredTotal);
    }
};

面试追问

  • 为什么缓存键不需要包含累计和或剩余目标？
  • 若数字允许重复选择，状态与解法会怎样变化？
  • 为什么不能仅根据已选数字的数量判断输赢？
  • 若最大可选整数提升到 40，状态空间会遇到什么问题？
  • 数字不再连续而是给定数组时，哪些部分仍可复用？

常见错误

  • 把数字当作可重复使用，误写成普通取石子游戏。
  • 忘记“达到或超过”都算赢，只判断严格相等。
  • 看到某一步不能立即获胜就判败，没有考虑对手反应。
  • 使用累计和作为唯一状态，丢失可选集合。
  • 总和不足时仍进入指数搜索。
  • 把缓存的“未知”与“必败”编码为同一个值。
