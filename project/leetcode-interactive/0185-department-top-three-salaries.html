    Dense ranking

    按部门分区，为不同工资连续编号

    DENSE_RANK() 让同薪员工共享名次，后一个不同工资紧接下一名，恰好匹配“前三个不同工资”。

    核心洞察与完整过程

    1. 连接 Employee 与 Department，取得部门名称。
    2. 按 departmentId 分区，按 salary DESC 排序。
    3. 用 DENSE_RANK() 给不同工资档位编号；同薪员工得到相同名次。
    4. 在外层保留 salary_rank <= 3，投影规定的三列。 
    WITH ranked AS (
  SELECT d.name AS Department,
         e.name AS Employee,
         e.salary AS Salary,
         DENSE_RANK() OVER (
           PARTITION BY e.departmentId
           ORDER BY e.salary DESC
         ) AS salary_rank
  FROM Employee e
  JOIN Department d ON d.id = e.departmentId
)
SELECT Department, Employee, Salary
FROM ranked
WHERE salary_rank <= 3;

    边界

    • 同薪多人：全部返回，名次只占一个档位。
    • 部门少于三个不同工资：返回现有全部档位。
    • 第四个不同工资及之后：全部排除。
    • 结果顺序任意，不需要额外排序。

    复杂度

    • 窗口排名通常需要按部门和工资排序，常见上界为 O(n log n)。
    • 窗口与连接的中间结果需要额外空间，常见为 O(n)。
    • 实际物理计划取决于索引、统计信息与数据库优化器。

    替代方案与取舍

    • 相关子查询可统计当前员工之上的不同工资数量，小于 3 即保留；兼容旧数据库，但通常更难读。
    • ROW_NUMBER() 会把同薪员工拆成不同名次，语义错误。
    • RANK() 在并列后跳号，可能让第三个不同工资名次大于 3，语义错误。

    常见错误

    • 按部门取前三行，漏掉与第三档同薪的员工。
    • 窗口未按部门分区，导致全公司统一排名。
    • 用 RANK() 或 ROW_NUMBER() 代替 DENSE_RANK()。
    • 忘记连接 Department，无法输出部门名称。
    • 输出列名与题目要求不一致。
