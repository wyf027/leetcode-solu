2424. 最长上传前缀

Longest Uploaded Prefix

视频可以乱序到达。但从第 1 个开始，有多少个已经连续就绪？

LeetCode 官方题目 ↗

01 / 题意与接口

共有 n 个视频，编号为 1…n，按任意顺序上传。当编号 1…i 全部已上传时，i 是一个上传前缀长度。返回满足条件的最大值；如果视频 1 尚未上传，则返回 0。

  • LUPrefix(int n)：初始化视频流。
  • void upload(int video)：上传指定编号的视频。
  • int longest()：查询当前最长上传前缀长度。

前缀必须从 1 开始。已上传数量、最大已上传编号，以及任意一段连续视频，都不一定是答案。

官方示例 1 · 完整调用形式

输入操作：
["LUPrefix", "upload", "longest", "upload", "longest", "upload", "longest"]
输入参数：
[[4], [3], [], [1], [], [2], []]
期望输出：
[null, null, 0, null, 1, null, 3]

初始化 n=4。上传 3 后，1 缺失，查询为 0；上传 1 后，查询为 1；上传 2 后，1、2、3 均已上传，查询为 3。构造和上传操作的输出位置用 null 表示。

约束

  • 1 ≤ n ≤ 10⁵。
  • 1 ≤ video ≤ n，每个上传编号互不相同。
  • upload 和 longest 的总调用次数至多 2 × 10⁵。
  • 至少调用一次 longest。

元数据的中文版提示将 video 上界写为 10⁵；这里采用英文官方约束的精确上界 n，与视频编号定义一致。

04 / 独立题解

先想一想：每次查询时，哪些已经确认的信息可以保留？

核心洞察：上传状态 + 只向右移动的边界

用 uploaded[v] 记录编号是否到达，用 p 保存当前最长前缀长度。上传不会撤销，已确认的前缀永远有效，因此 p 无须回退。上传 v 后将其标记为已上传，只要 uploaded[p+1] 为真，就继续增加 p。查询直接返回 p。

完整过程

  1. 构造时创建长度 n+2 的全假数组，令 p=0。额外的 n+1 位置是永远为假的哨兵。
  2. 上传 video：设置 uploaded[video]=true。
  3. 循环检查边界右侧：若已上传，执行 p++；遇到首个未上传编号时停止。
  4. longest() 直接返回 p，不修改状态。

示例中上传 3 时 p 仍为 0；上传 1 时 p 从 0 到 1；上传 2 时 p 先到 2，再利用之前到达的 3 前进到 3，最后因 4 缺失而停止。可视化把一次上传内部的边界移动拆成多个教学步骤；真实接口调用结束后才可查询。

正确性证明

不变量：每次公开操作完成后，1…p 全部已上传，且 p=n 或 p+1 未上传。初始化时 p=0，空前缀成立，编号 1 未上传。

上传操作不会破坏 1…p 的已上传状态。每次循环只有在 p+1 已上传时才增加 p，所以新前缀依然完整。循环终止时，下一个编号未上传（全部完成时为哨兵），任意更长前缀都必须包含这个缺口，因此不可能有效。返回的 p 恰是最大有效前缀。查询不改变状态，不变量继续保持。

边界与常见错误

  • 尚未上传视频 1 时，答案为 0，即使其他视频全部到达。
  • n=1 与全部上传后都要正确终止；长度 n+2 的数组确保可读取哨兵 n+1。
  • 必须使用 while，单次 if 会漏掉已经就绪的多个连续编号。
  • 答案不是上传数量或最大编号；不要跳过缺口。
  • 每次从 1 重新扫描可达 O(n) 查询；保留边界避免重复扫描。
  • 题目保证编号合法且不重复；若用于真实服务，另加输入校验与并发保护。

复杂度

构造时间 O(n)，空间 O(n)。单次 upload 最坏 O(n)，例如最后才上传 1；但所有上传期间 p 总共至多前进 n 次。若实际上传 k 个不同视频，p 至多前进 k 次，所以这些上传总计 O(k)，摊还每次 O(1)。longest 最坏 O(1)。包含初始化与 q 次公开调用，总时间 O(n+q)。

替代方案与选择

  • 哈希集合 + 同一个边界：保存已上传编号，按期望 O(1) 查询下一个位置。适合稀疏编号，连续且有界的本题数组更直接。
  • 未上传编号的有序集合：删除上传编号，最小剩余编号减 1 即答案；集合空则为 n。通常每次上传 O(log n)，需要有序结构。
  • 线段树：维护未上传位置并找首个缺口，更新和查询 O(log n)。若支持撤销上传，这种结构更有价值。

面试追问

  • 如果允许撤销上传？边界可能回退，单调指针不再适用，可用有序缺失集合或线段树。
  • 如果上传编号重复？布尔标记本身幂等，重复设置不会改变答案。
  • 能否把工作移到查询？可以在 upload 中只打标，在 longest 中推进边界；总时间不变，但单次查询可能 O(n)。
  • 多线程怎么办？标记与边界推进需要一致的同步策略，不能直接假设普通变量读写足够。

Java

class LUPrefix {
    private final boolean[] uploaded;
    private int p = 0;

    public LUPrefix(int n) {
        uploaded = new boolean[n + 2];
    }

    public void upload(int video) {
        uploaded[video] = true;
        while (uploaded[p + 1]) {
            p++;
        }
    }

    public int longest() {
        return p;
    }
}

Python 3

class LUPrefix:
    def __init__(self, n: int):
        self.uploaded = [False] * (n + 2)
        self.p = 0

    def upload(self, video: int) -> None:
        self.uploaded[video] = True
        while self.uploaded[self.p + 1]:
            self.p += 1

    def longest(self) -> int:
        return self.p
