The Answer

换个视角：让元素主动贡献

不再枚举每个子数组，而是统计每个元素会出现几次。

核心洞察

对下标 i，包含 arr[i] 的子数组需要从左边界的 i + 1 种选择、右边界的 n - i 种选择中各取一种，因此共有 (i + 1)(n - i) 个。

这些子数组中，奇数长度与偶数长度的数量尽量成对；总数为奇数时，奇数长度多一个。因此奇数长度个数就是总数向上取整的一半。

countᵢ = ((i + 1) × (n - i) + 1) // 2
answer = Σ arr[i] × countᵢ

完整过程

  1. 令答案 ans = 0。
  2. 从左到右扫描下标 i。
  3. 算出覆盖该位置的全部子数组数 total = (i+1)(n-i)。
  4. 取 odd = (total+1)/2 的整数除法结果。
  5. 把 arr[i] * odd 加入答案。

正确性证明

每个包含位置 i 的子数组，唯一对应一对“左端点、右端点”，所以乘法计数没有遗漏或重复。左右扩展长度的奇偶组合决定子数组长度奇偶：一奇一偶与一偶一奇给出奇数长度。两类组合数量之和恰为全部选择数的一半向上取整。因此 countᵢ 精确等于 arr[i] 在所有奇数长度子数组中出现的次数。对所有位置累加其值乘出现次数，等价于对所有目标子数组逐项求和，故算法正确。

边界情况

  • 只有一个元素：总选择数为 1，它贡献一次。
  • 长度为偶数：左右位置仍用同一公式，无需特判。
  • 所有值相同：位置靠中间的元素覆盖次数更多。
  • 约束下最大答案可安全放入 32 位有符号整数；实现仍可按语言习惯使用普通整数。

复杂度

只扫描数组一次，时间复杂度 O(n)；只使用常数个变量，额外空间复杂度 O(1)。

替代方案

  • 三层枚举：枚举起点、奇数长度，再逐项求和，最直观但可达 O(n³)。
  • 前缀和：每个窗口的和可在 O(1) 得到，总时间 O(n²)，空间 O(n)。
  • 滑动窗口：对每种奇数长度维护窗口和，仍为 O(n²)，但额外空间可为常数。

面试追问

  • 若只统计偶数长度子数组，次数是多少？答案是 total - odd。
  • 为什么“向上取整一半”成立？可按左右扩展长度的奇偶性分类证明。
  • 若要求所有子数组之和？直接使用 (i+1)(n-i) 次贡献。

常见错误

把 i 当成左边界选择数、遗漏单元素子数组；使用普通除法却忘记取整；或只数窗口、不乘当前元素值。
Implementations

四种语言

均保持官方函数签名，使用同一个 O(n) 贡献公式。

Java · LeetCode 可提交
class Solution {
    public int sumOddLengthSubarrays(int[] arr) {
        int answer = 0;
        int n = arr.length;

        for (int i = 0; i < n; i++) {
            int total = (i + 1) * (n - i);
            int oddCount = (total + 1) / 2;
            answer += arr[i] * oddCount;
        }
        return answer;
    }
}

Python 3 · LeetCode 可提交
from typing import List


class Solution:
    def sumOddLengthSubarrays(self, arr: List[int]) -> int:
        answer = 0
        n = len(arr)

        for i, value in enumerate(arr):
            total = (i + 1) * (n - i)
            odd_count = (total + 1) // 2
            answer += value * odd_count

        return answer
