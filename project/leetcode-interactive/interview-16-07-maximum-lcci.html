核心洞察

符号位就是 0 / 1 选择器

先用 64 位保存 a - b，避免 32 位溢出。差值非负时最高位为 0，令 k = 0；差值为负时最高位为 1，令 k = 1。再设 q = k ^ 1，于是 a × q + b × k 恰好只保留较大的一项。

完整过程

  1. 把 a 和 b 提升到 64 位后相减。
  2. 无符号右移 63 位，取得差值符号位 k。
  3. 计算 q = k ^ 1，让两个选择器一开一关。
  4. 返回 a × q + b × k。

边界

  • a == b 时差值为 0，选择 a，结果仍正确。
  • 两数异号时 32 位差值最容易溢出，必须先扩位再减。
  • 极值差最大为 4,294,967,295，能安全容纳在 64 位有符号整数中。
  • JavaScript 位运算会强制转 32 位，需用 BigInt 模拟 64 位符号位。

复杂度

只执行固定次数的算术与位运算，时间复杂度 O(1)，额外空间复杂度 O(1)。

替代方案

(a + b + abs(a - b)) / 2 同样可以不用比较，但 Java/C++ 仍要把加减提升到 64 位，并小心语言的取整语义。数组索引法可用符号位直接选 [a, b][k]，但会引入额外容器。

面试追问

  • 若不允许乘法，可以把 0/1 掩码扩展成全 0/全 1，再用按位与、或选择。
  • 若输入本身是 64 位，需要使用更宽类型或基于输入符号规避直接相减。
  • 解释为什么算术右移与无符号右移在各语言中表现不同。

常见错误

先用 int 相减，再把结果转 long

JavaScript 直接使用 >>> 63

把 k 与 q 的含义写反

C++ 对负数做有符号右移后假设跨平台一致 

class Solution {
    public int maximum(int a, int b) {
        long diff = (long) a - (long) b;
        int k = (int) (diff >>> 63);
        int q = k ^ 1;
        return a * q + b * k;
    }
}
/**
 * @param {number} a
 * @param {number} b
 * @return {number}
 */
var maximum = function (a, b) {
  const diff = BigInt(a) - BigInt(b);
  const k = Number(BigInt.asUintN(64, diff) >> 63n);
  const q = k ^ 1;
  return a * q + b * k;
};
class Solution:
    def maximum(self, a: int, b: int) -> int:
        diff = a - b
        k = (diff >> 63) & 1
        q = k ^ 1
        return a * q + b * k

public:
    int maximum(int a, int b) {
