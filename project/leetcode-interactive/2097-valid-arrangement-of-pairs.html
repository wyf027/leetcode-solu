合法重新排列数对

Valid Arrangement of Pairs

把一组有方向的数对接成一条链：前一对的终点，必须恰好等于后一对的起点。所有数对都要用上。

二维整数数组 pairs返回任意合法排列保证至少有一个答案

01 / 题目要求

给定下标从 0 开始的数组 pairs，其中 pairs[i] = [startᵢ, endᵢ]。重新排列这些数对，使每个 1 ≤ i < pairs.length 都满足 endᵢ₋₁ = startᵢ。

只改变数对之间的排列顺序，不改变数对内部方向；每个输入数对必须恰好出现一次。返回任意一种符合条件的二维数组，不要求字典序最小。

先独立思考：当两个数对都能接在当前末尾，应该怎么处理？底部题解和算法演示默认收起。

02 / 官方示例

示例 1 · 链式衔接

输入：pairs = [[5,1],[4,5],[11,9],[9,4]]
输出：[[11,9],[9,4],[4,5],[5,1]]

相邻的连接值依次是 9、4、5：前一对终点均等于后一对起点。

示例 2 · 首尾相接

输入：pairs = [[1,3],[3,2],[2,1]]
输出：[[1,3],[3,2],[2,1]]

连接值依次为 3、2。[[2,1],[1,3],[3,2]] 和 [[3,2],[2,1],[1,3]] 也合法。

示例 3 · 同一起点

输入：pairs = [[1,2],[1,3],[2,1]]
输出：[[1,2],[2,1],[1,3]]

连接值依次为 2、1。两个从 1 出发的数对在最终结果中处于不同位置。

03 / 约束与接口

  • 1 ≤ pairs.length ≤ 10⁵。
  • pairs[i].length = 2。
  • 0 ≤ startᵢ, endᵢ ≤ 10⁹。
  • startᵢ ≠ endᵢ。
  • 不存在两个完全相同的数对。
  • 输入保证至少存在一个合法重新排列。

接口：validArrangement(pairs: integer[][]) → integer[][]。

INSIGHT / EULERIAN TRAIL

把数对看成有向边，寻找欧拉路径

每个数值是顶点，每个 [u,v] 是有向边 u → v。合法排列就是经过所有边且每条边恰好一次的路径。顶点可以重复，边不能重复。

起点由出入度决定

记录 balance[v] = 出度 − 入度。如果某顶点的差值为 1，就必须从它出发；终点差值为 −1，其余顶点平衡。若所有顶点的差值都是 0，则是欧拉回路，从任意有出边的点，例如 pairs[0][0]，开始即可。题目保证有解。

核心洞察：走边时，不立即决定最终顺序

使用迭代版 Hierholzer 算法：当前栈顶还有出边，就删除一条边并把终点压栈；没有出边时，才弹出顶点并追加到逆序结果。最后反转顶点数组，再将相邻顶点组成数对。提前走到终点并不意味着失败：退栈顺序会把剩余环插入正确位置。

完整过程
  1. 建立邻接表并统计每个顶点的出入度差。
  2. 优先选差值为 1 的起点，否则用首个数对的起点。
  3. 起点压栈。只看栈顶：还有边就取走一条并压入终点；没有边就弹出并记录这个顶点。
  4. 栈清空后，反转记录的 E + 1 个顶点，再输出 E 个相邻数对。
示例 3：先走 1 → 3，3 无出边，记录 3；回到栈中的 1 后继续走 1 → 2 → 1。完整退栈记录为 [3,1,2,1]，反转后是 [1,2,1,3]，输出 [[1,2],[2,1],[1,3]]。


正确性说明
  1. 每条边最多用一次：取边时从邻接表删除，此后无法再次取到。压栈操作与消耗一条输入边一一对应。
  2. 起点合法：非闭合路径必须从出度多 1 的顶点出发，其他中间点进入与离开配对；闭合路径各顶点平衡，因此可从任意有出边的顶点出发。
  3. 逆序回收保证衔接：从合法起点持续走未用边，第一次走不动时得到路径末尾。若之前路径上的顶点还有未用边，它们构成能插入该位置的闭合片段。栈保存这些位置，顶点只有在出边耗尽后才退栈。逆序记录相当于先固定末尾，再把后探索的片段放到末尾之前；反转后得到连续的有向路径。
  4. 所有边都会被用到：有解保证所有有边顶点处于同一弱连通分量，且度数满足欧拉条件。若探索完的路径外还有剩余边，则必有路径顶点与剩余部分相接。在剩余图平衡的条件下，该连接处必有待探索出边；但栈中的顶点要耗尽出边才能离开，因此这些边也会被探索，矛盾。
所以结果覆盖全部输入边恰好一次，且每一对都与下一对首尾相接，满足题意。


边界与复杂度
  • 单边：退栈得到两个顶点，照常反转。
  • 回路：没有差值为 1 的顶点，任选有出边的点。
  • 终点可能只有入边，邻接表不存在时视为空。
  • 节点数值可达 10⁹，用哈希表而非按数值开数组。
  • 长链可达 10⁵ 条边，显式栈避免递归溢出。
令 E 为边数、V 为不同端点数。哈希访问平均 O(1) 时，时间为 O(V + E) = O(E)；额外空间为 O(V + E) = O(E)，包含图、栈和路径。输出另需 O(E)。每条边取走一次，每个压栈项弹出一次。
替代方案
  • 递归 Hierholzer：写法短，但递归深度可能达到 E + 1，本题优先用显式栈。
  • 排列回溯：枚举数对顺序，最坏阶乘级，只适合极小规模理解题目。
  • Fleury 思路：动态避免走桥会增加可达性检查，有向场景也更复杂，朴素实现可达 O(E²)。
  • 坐标压缩：把稀疏端点映射成连续编号再用数组，可行，但 Map 已能直接表达邻接表。


常见错误
  • 始终从第一条数对开始：非闭合路径应先寻找度差为 1 的起点。
  • 按数值排序后直接输出，或直接输出探索时的取边顺序：分支可能提前到终点。
  • 给顶点做 visited 去重：允许重复经过顶点，不允许重复用边。
  • 忘记反转，或返回顶点数组而非数对数组。
  • 使用 shift 或反复删除数组头部取边，引入不必要的搬移；末尾 pop 即可。
  • 误以为不同数对不能共享端点：只禁止完全相同的数对。

JavaScript
/**
 * @param {number[][]} pairs
 * @return {number[][]}
 */
var validArrangement = function(pairs) {
    const graph = new Map(), balance = new Map();
    for (const [u, v] of pairs) {
        if (!graph.has(u)) graph.set(u, []);
        graph.get(u).push(v);
        balance.set(u, (balance.get(u) || 0) + 1);
        balance.set(v, (balance.get(v) || 0) - 1);
    }
    let start = pairs[0][0];
    for (const [v, d] of balance) {
        if (d === 1) { start = v; break; }
    }
    const stack = [start], route = [];
    while (stack.length) {
        const u = stack[stack.length - 1];
        const edges = graph.get(u);
        if (edges && edges.length) stack.push(edges.pop());
        else route.push(stack.pop());
    }
    route.reverse();
    const answer = [];
    for (let i = 1; i < route.length; i++) {
        answer.push([route[i - 1], route[i]]);
    }
    return answer;
};


Java
import java.util.*;

class Solution {
    public int[][] validArrangement(int[][] pairs) {
        Map<Integer, Deque<Integer>> graph = new HashMap<>();
        Map<Integer, Integer> balance = new HashMap<>();
        for (int[] p : pairs) {
            graph.computeIfAbsent(p[0], k -> new ArrayDeque<>()).addLast(p[1]);
            balance.merge(p[0], 1, Integer::sum);
            balance.merge(p[1], -1, Integer::sum);
        }
        int start = pairs[0][0];
        for (Map.Entry<Integer, Integer> e : balance.entrySet()) {
            if (e.getValue() == 1) { start = e.getKey(); break; }
        }
        Deque<Integer> stack = new ArrayDeque<>();
        List<Integer> route = new ArrayList<>();
        stack.addLast(start);
        while (!stack.isEmpty()) {
            int u = stack.peekLast();
            Deque<Integer> edges = graph.get(u);
            if (edges != null && !edges.isEmpty()) {
                stack.addLast(edges.removeLast());
            } else {
                route.add(stack.removeLast());
            }
        }
        Collections.reverse(route);
        int[][] answer = new int[pairs.length][2];
        for (int i = 0; i < pairs.length; i++) {
            answer[i][0] = route.get(i);
            answer[i][1] = route.get(i + 1);
        }
        return answer;
    }
}


Python
from typing import List
from collections import defaultdict

class Solution:
    def validArrangement(self, pairs: List[List[int]]) -> List[List[int]]:
        graph = defaultdict(list)
        balance = defaultdict(int)
        for u, v in pairs:
            graph[u].append(v)
            balance[u] += 1
            balance[v] -= 1

        start = pairs[0][0]
        for v, d in balance.items():
            if d == 1:
                start = v
                break

        stack, route = [start], []
        while stack:
            u = stack[-1]
            if graph[u]:
                stack.append(graph[u].pop())
            else:
                route.append(stack.pop())
        route.reverse()
        return [[route[i - 1], route[i]] for i in range(1, len(route))]


C++
#include <vector>
#include <unordered_map>
#include <algorithm>
using namespace std;

class Solution {
public:
    vector<vector<int>> validArrangement(vector<vector<int>>& pairs) {
        unordered_map<int, vector<int>> graph;
        unordered_map<int, int> balance;
        for (const auto& p : pairs) {
            graph[p[0]].push_back(p[1]);
            ++balance[p[0]];
            --balance[p[1]];
        }
        int start = pairs[0][0];
        for (const auto& [v, d] : balance) {
            if (d == 1) { start = v; break; }
        }
        vector<int> stack{start}, route;
        while (!stack.empty()) {
            int u = stack.back();
            auto& edges = graph[u];
            if (!edges.empty()) {
                int v = edges.back();
                edges.pop_back();
                stack.push_back(v);
            } else {
                route.push_back(u);
                stack.pop_back();
            }
        }
        reverse(route.begin(), route.end());
        vector<vector<int>> answer;
        answer.reserve(pairs.size());
        for (int i = 1; i < (int)route.size(); ++i) {
            answer.push_back({route[i - 1], route[i]});
        }
        return answer;
    }
};


面试追问
如果输入不保证有解？
核对所有非孤立顶点弱连通，且度差要么全为 0，要么恰好一个 +1、一个 −1，其余为 0。也可在构造后完整核对输出数量、边的多重集合和相邻衔接；不能只看是否生成了一段路径。
为什么任意取出边也能成立？
任意的是探索顺序，最终顺序由退栈结果反转得到。走到终点后，之前栈顶上的剩余环仍会被处理，并被插在已确定的末尾之前。
如果要求字典序最小？
先明确起点和字典序定义，然后按终点升序取边（可降序排序后 pop），仍在退栈时记录。排序通常引入 O(E log E) 时间；不能对最终边列表直接排序。
如果允许重复数对？
邻接表保留每次出现，不用集合去重。本算法按重数取边，仍适用；如果需要区分边的身份，另存输入下标。
