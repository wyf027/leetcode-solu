Brief

题意转述

给定整数数组 nums 和整数 val，在原数组中移除所有等于 val 的元素。假设剩余元素数量为 k，需要让数组前 k 个位置保存这些元素并返回 k。前缀之外的内容无需处理，剩余元素顺序也不要求固定。

官方样例 1

输入 nums = [3, 2, 2, 3], val = 3
输出 k = 2, nums = [2, 2, _, _]

官方样例 2

输入 nums = [0, 1, 2, 2, 3, 0, 4, 2], val = 2
输出 k = 5, nums[0..4] = [0, 1, 3, 0, 4]

约束：0 ≤ nums.length ≤ 100， 0 ≤ nums[i] ≤ 50， 0 ≤ val ≤ 100。下划线 _ 表示评测器忽略的位置，并不是字符串内容。

Judge contract

评测器究竟检查什么？

  1. 1. 返回值必须等于未命中 val 的元素数量 k。
  2. 2. 排序 nums 的前 k 项后，应与期望的幸存元素一致。
  3. 3. 索引 k 之后的值和数组物理长度都不参与判定。

Core insight

核心洞察：k 既是答案，也是下一次写入位置

用读指针遍历每个元素。若当前值等于 val，跳过；否则写入 nums[k] 并令 k 加一。任何时刻， nums[0..k-1] 都恰好保存已扫描区间中所有不等于 val 的元素。这条不变式让正确性一眼可证。

Walkthrough

完整过程

  1. 初始化：k = 0，有效前缀为空。
  2. 扫描：读指针从左到右检查 nums 中每个值。
  3. 命中 val：不写入，k 不变。
  4. 未命中：执行 nums[k] = nums[read]，随后 k++。
  5. 结束：返回 k，前 k 项就是有效结果。

Complexity

复杂度

time

O(n)

每项恰好扫描一次

space

O(1)

只维护 k

Edge cases

边界情况

  • • 空数组：循环不执行，直接返回 0。
  • • 全部等于 val：k 始终为 0。
  • • 完全不含 val：每次可以原位自赋值，最终 k = n。
  • • 单元素：分别验证命中与未命中。
  • • val 可大于 nums[i] 上界：此时数组原样保留。

Alternative

替代方案取舍

若不要求顺序，可用左右指针：左侧命中 val 时，用末尾元素覆盖并缩短右边界。它在 val 很少时可能减少写操作，但状态更绕、结果顺序不稳定。面试主线优先选择稳定写指针：代码短、证明直接、适配所有语言。

Interview follow-ups

面试高频追问

为什么不需要真的缩短数组？
评测契约只读取返回的 k 与前 k 项；固定长度语言也无法直接改变数组长度。
覆盖会不会破坏尚未读取的数据？
不会。始终有 k ≤ read，写入位置不会落在 read 右侧。
为什么顺序允许改变却仍保持稳定？
允许改变不代表必须改变；稳定方案更直观，复杂度仍最优。

Common mistakes

常见错误

  • • 在遍历时调用 remove / splice，导致索引移动并跳过元素。
  • • 新建过滤数组，违反 O(1) 额外空间的原地要求。
  • • 只统计 k，却没有把幸存元素写到 nums 的前 k 项。
  • • 返回 k - 1，混淆“最后索引”和“元素数量”。
  • • 多余地清空尾部；评测器根本不检查这部分。

class Solution {
    public int removeElement(int[] nums, int val) {
        int k = 0;

        for (int num : nums) {
            if (num != val) {
                nums[k] = num;
                k++;
            }
        }

        return k;
    }
}
