石子游戏 VI

同一颗石子，两个人眼中却有不同价值。先不要急着找策略：先看规则、亲手走完一盘，再决定“拿走什么”究竟意味着什么。

stoneGameVI(aliceValues, bobValues) 返回 1 / 0 / -1
Problem

题目描述

题号
1686
难度
Medium
输入
两个等长数组
目标
判断胜负

Alice 与 Bob 轮流从一堆 n 个石子中取走一个，Alice 先手。第 i 个石子对 Alice 的价值是 aliceValues[i]，对 Bob 的价值是 bobValues[i]。取走石子的人获得自己所认定的分值，双方都知道彼此的估值并采用最优策略。

全部石子取完后，Alice 得分更高返回 1，同分返回 0，Bob 得分更高返回 -1。

约束
n == aliceValues.length == bobValues.length
1 ≤ n ≤ 10⁵
1 ≤ aliceValues[i], bobValues[i] ≤ 100

官方示例

示例 1 · Alice 获胜
输入：aliceValues = [1,3]
bobValues = [2,1]
输出：1
解释：Alice 先取下标 1，得 3 分；
Bob 只能取下标 0，得 2 分。
示例 2 · 平局
输入：aliceValues = [1,2]
bobValues = [3,1]
输出：0
解释：Alice 取下标 0，Bob 取下标 1，
双方各得 1 分。
示例 3 · Bob 获胜
输入：aliceValues = [2,4,3]
bobValues = [1,6,7]
输出：-1
解释：例如依次取下标 1、2、0，
Alice 得 6 分，Bob 得 7 分。

Solution

把“得到”与“阻止”合成一个优先级

核心洞察：拿走石子 i 的影响不只有自己的得分，还包括让对手永远失去这颗石子的价值。因此双方对石子的共同紧迫度是 aliceValues[i] + bobValues[i]。
计算共同优先级
为每颗石子记录下标，并计算两方估值之和。
按估值之和降序排列
优先处理对当前局面总影响最大的石子。
交替计分
排序后偶数位归 Alice，奇数位归 Bob，分别累加自己的估值。
比较总分
Alice 高返回 1，相等返回 0，否则返回 -1。
Complexity

O(n log n)

排序主导时间复杂度；显式下标数组需要 O(n) 额外空间。若语言排序实现允许，也可原地组织二元组。

priority(i) = A[i] + B[i]
diff = AliceScore − BobScore

正确性证明

引理：若相邻两个取石位置分别属于 Alice 与 Bob，把石子 i 放在前、j 放在后，对 Alice 净胜分的贡献是 A[i] − B[j]；交换后是 A[j] − B[i]。前一种顺序不差，当且仅当 A[i] + B[i] ≥ A[j] + B[j]。

结论：因此任意逆序的相邻石子都可交换为估值和更大的石子在前，且不会让先取该位置的玩家变差。双方在自己的回合都会优先拿剩余估值和最大的石子，最终顺序等价于按 A[i]+B[i] 降序排列。算法在此顺序上交替计入双方实际所得，故得到双方最优博弈下的正确胜负。

边界与替代方案

  • 只有一颗石子：Alice 直接获得其价值，返回 1。
  • 优先级相同：同和石子的相对次序不影响最终净胜分，排序无需稳定。
  • 总分相等：必须返回 0，不能仅判断 Alice 是否大于 Bob。
  • 替代方案：可把全部下标放入按 A[i]+B[i] 排序的最大堆，每回合弹出一个；复杂度仍为 O(n log n)，但常数和实现复杂度通常更高。

class Solution {
    public int stoneGameVI(int[] aliceValues, int[] bobValues) {
        int n = aliceValues.length;
        Integer[] order = new Integer[n];
        for (int i = 0; i < n; i++) order[i] = i;

        java.util.Arrays.sort(order, (i, j) ->
            Integer.compare(aliceValues[j] + bobValues[j],
                            aliceValues[i] + bobValues[i]));

        int alice = 0, bob = 0;
        for (int turn = 0; turn < n; turn++) {
            int i = order[turn];
            if ((turn & 1) == 0) alice += aliceValues[i];
            else bob += bobValues[i];
        }
        return Integer.compare(alice, bob);
    }
}
/**
 * @param {number[]} aliceValues
 * @param {number[]} bobValues
 * @return {number}
 */
var stoneGameVI = function(aliceValues, bobValues) {
    const order = aliceValues.map((_, i) => i);
    order.sort((i, j) =>
        aliceValues[j] + bobValues[j] -
        aliceValues[i] - bobValues[i]
    );

    let alice = 0;
    let bob = 0;
    order.forEach((i, turn) => {
        if (turn % 2 === 0) alice += aliceValues[i];
        else bob += bobValues[i];
    });
    return Math.sign(alice - bob);
};
from typing import List

class Solution:
    def stoneGameVI(
        self, aliceValues: List[int], bobValues: List[int]
    ) -> int:
        order = sorted(
            range(len(aliceValues)),
            key=lambda i: aliceValues[i] + bobValues[i],
            reverse=True,
        )

        alice = sum(aliceValues[i] for i in order[::2])
        bob = sum(bobValues[i] for i in order[1::2])
        return (alice > bob) - (alice < bob)
class Solution {
public:
    int stoneGameVI(vector<int>& aliceValues,
                    vector<int>& bobValues) {
        int n = aliceValues.size();
        vector<int> order(n);
        iota(order.begin(), order.end(), 0);

        sort(order.begin(), order.end(), [&](int i, int j) {
            return aliceValues[i] + bobValues[i] >
                   aliceValues[j] + bobValues[j];
        });

        int alice = 0, bob = 0;
        for (int turn = 0; turn < n; ++turn) {
            int i = order[turn];
            if (turn % 2 == 0) alice += aliceValues[i];
            else bob += bobValues[i];
        }
        return (alice > bob) - (alice < bob);
    }
};

面试追问

  • 为什么不能只按 Alice 的价值降序？
  • 如果两人各自能跳过一次回合，结论还成立吗？
  • 如何用最大堆改写？与排序相比有什么取舍？
  • 若价值允许为负数，证明中的交换关系是否仍成立？

常见错误

  • 按双方价值差 A[i]-B[i] 排序，忽略“阻止对手获得”的收益。
  • Bob 回合仍把 Bob 的分数算进 Alice，或直接交替加减同一个数组。
  • 比较器方向写反，变成升序。
  • Java 比较器直接做大数相减可能溢出；本题范围虽安全，仍推荐 Integer.compare。
