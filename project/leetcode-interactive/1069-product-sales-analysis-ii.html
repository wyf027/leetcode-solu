Product Sales Analysis II

产品销售分析 II

先理解数据与目标，再亲手走一遍“按商品归组并累加”的过程。题解在页面末尾默认收起。

题意

给定销售表 Sales。请为每个出现过销售记录的 product_id，计算它在所有年份、所有销售记录中的总销售数量，并返回 product_id 与汇总后的 total_quantity。结果顺序不作要求。

注意：Product 表是题目数据模型的一部分，但本问只需要商品编号和数量，答案无需连接该表。

Sales 表

product_idINT商品编号
yearINT销售年份

priceINT单价

Product 表

列类型含义

约束与结果约定

  • 输入列遵循上表类型；每行 Sales 记录描述某商品的一次销售。
  • 只统计 Sales 中实际出现的商品；同一商品可能跨年份出现多次。
  • 输出列名必须为 product_id 和 total_quantity；行顺序任意。

题解

核心洞察

答案只取决于两个字段：用 product_id 划分组，再对每组的 quantity 求和。SQL 的 GROUP BY 与 SUM 正好直接表达这件事。

完整过程

  1. 从 Sales 读取商品编号与销售数量。
  2. 按 product_id 分组。
  3. 对每组的 quantity 使用 SUM。
  4. 将聚合列别名设为题目要求的 total_quantity。

正确性说明

分组后，每条销售记录恰好进入其 product_id 对应的唯一组，不会遗漏或重复归组。SUM(quantity) 将该组中所有销售数量各加一次，所以得到该商品全部记录的总数量。每个非空商品组产生一行，故结果恰好包含所有有销售记录的商品及其正确总量。

边界情况

  • 商品只有一条销售记录时，总量就是该行的 quantity。
  • 同一商品跨多个年份时仍应合并，不能把 year 放进分组键。
  • 没有销售记录的 Product 不应出现；因此无需从 Product 做外连接。
  • 若执行平台允许空表，则结果自然为空。

复杂度

设 Sales 有 n 行、不同商品有 k 个。概念上扫描为 O(n)，哈希聚合额外空间 O(k)；具体数据库也可能选择排序聚合，时间约 O(n log n)。

官方可提交语言：SQL（MySQL）

SELECT
    product_id,
    SUM(quantity) AS total_quantity
FROM Sales
GROUP BY product_id;

Java（本地语义参考，非本题数据库提交语言）

import java.util.*;

class Solution {
    public Map<Integer, Long> totalQuantity(int[][] sales) {
        Map<Integer, Long> totals = new LinkedHashMap<>();
        for (int[] row : sales) {
            int productId = row[1];
            int quantity = row[3];
            totals.merge(productId, (long) quantity, Long::sum);
        }
        return totals;
    }
}

JavaScript（本地语义参考，非本题数据库提交语言）

function totalQuantity(sales) {
  const totals = new Map();
  for (const [, productId, , quantity] of sales) {
    totals.set(productId, (totals.get(productId) ?? 0) + quantity);
  }
  return [...totals].map(([product_id, total_quantity]) => ({
    product_id,
    total_quantity,
  }));
}

Python（本地语义参考，非本题数据库提交语言）

from collections import defaultdict

def total_quantity(sales: list[list[int]]) -> list[tuple[int, int]]:
    totals = defaultdict(int)
    for _, product_id, _, quantity, _ in sales:
        totals[product_id] += quantity
    return list(totals.items())

C++（本地语义参考，非本题数据库提交语言）

#include <unordered_map>
#include <utility>
#include <vector>
using namespace std;

vector<pair<int, long long>> totalQuantity(
    const vector<vector<int>>& sales) {
    unordered_map<int, long long> totals;
    for (const auto& row : sales) totals[row[1]] += row[3];
    return {totals.begin(), totals.end()};
}

替代方案

可以先按商品排序，再顺序累加同一商品；但 SQL 中手写窗口函数或相关子查询都会更绕。连接 Product 也不是错误语法，却增加了无用工作，并可能因连接方式改变结果范围。

面试追问

  • 若要求每个商品每年的销量，应把 year 也放入 SELECT 和 GROUP BY。
  • 若要求列出零销量商品，应从 Product 左连接 Sales，并用 COALESCE(SUM(quantity), 0)。
  • 数据量很大时，可以讨论 Sales(product_id) 索引、分区、预聚合与执行计划。

常见错误

  • 误求 SUM(price) 或 SUM(quantity * price)。
  • 按 sale_id 分组，导致每条记录仍独占一行。
  • 额外按 year 分组，使跨年总量被拆开。
  • 忘记将聚合列命名为 total_quantity。
