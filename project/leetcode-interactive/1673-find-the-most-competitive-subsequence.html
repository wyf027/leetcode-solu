1673 MEDIUM Find the Most Competitive Subsequence

Problem

先把“竞争力”说清楚

给定整数数组 nums 和正整数 k，请返回 nums 的一个长度为 k 的子序列。子序列可以通过删除零个或多个元素得到，但剩余元素的相对顺序必须保持不变。

比较规则：对于两个等长子序列，从左向右比较；在第一个不同的位置，数值更小的那个序列更具竞争力。
[1, 3, 4] 优于 [1, 3, 5] 因为末位首次不同，4 < 5

约束

  • 1 <= nums.length <= 105
  • 0 <= nums[i] <= 109
  • 1 <= k <= nums.length

函数形式：mostCompetitive(nums, k)，返回整数数组。

示例 1

k = 2
输入nums = [3,5,2,6], k = 2
输出[2,6]
解释所有长度为 2 的子序列中，[2,6] 的字典序最小。

示例 2

k = 4
输入nums = [2,4,3,3,5,4,9,6], k = 4
输出[2,3,3,4]
说明顺序保持不变，并优先让更小的元素出现在靠左位置。

Solution

贪心 + 单调栈：把更小的数尽量提前

字典序首先取决于最左边的不同位置。因此，只要后面仍有足够元素补满长度，就应该撤回左侧较大的选择，让当前更小的元素前移。

核心洞察完整过程正确性复杂度四语言代码测试与验证

Core insight

三个条件，决定栈顶能否被替换

当前更小

只有当 nums[i] < stack.top 时，替换才能让首次不同的位置变小。

长度补得回来

弹出前若 stack.length + (n - i) > k，弹出后仍能用当前及后续元素凑满 k 个。

每个元素只进出一次

栈保持“可优化的候选前缀”。虽然有内层循环，总操作次数仍是线性的。

等价安全条件：弹出一个栈顶后，现有元素数 stack.length - 1 加上从下标 i 开始尚可选的 n - i 个元素，至少为 k。

Walkthrough

完整过程

建立候选栈

从左向右扫描 nums。栈中始终保存目前看来最有竞争力的前缀，同时不破坏原数组顺序。

尽可能移走更大的栈顶

当栈非空、栈顶大于当前值，并且弹出后仍能凑满 k 个元素时，持续弹出。持续弹出处理的是一串连续偏大的尾部。

有空位才压入

完成弹出后，若栈长小于 k，压入当前值；若已经有 k 个且不能改善前缀，就跳过当前值。

扫描结束即得答案

补位条件保证最终长度恰好为 k，栈内顺序与原数组一致，直接返回即可。

Correctness

为什么这个贪心选择正确？

交换论证

扫描到 nums[i] 时，若栈顶 x > nums[i] 且删掉 x 后仍有足够元素组成长度 k 的子序列，那么把 x 换成 nums[i] 不会破坏可行性。两份候选在更早的位置完全相同，在这个首次可能变化的位置，新候选放入了更小的数，因此字典序严格更小。故保留 x 不可能优于替换。

反之，如果补位条件不成立，删除栈顶将导致最终长度不足；此时即使当前值更小也不能弹出。算法只执行所有安全且能改善字典序的交换，因此每个前缀都保持可达到的最优状态。扫描结束后得到全局最小的长度 k 子序列。

Cost

复杂度

时间复杂度O(n)

每个元素至多入栈一次、出栈一次。

空间复杂度O(k)

候选栈最多保存 k 个元素。

Boundaries

边界情况

k = nums.length

没有删除额度，补位条件始终阻止弹出，答案就是原数组。

k = 1

可以持续替换更大的候选，最终留下数组最小值。

存在重复值

使用严格大于 > 才弹出。相等时保留更早出现的值，不会损失竞争力。

单调递增或递减

递增时取前 k 个；递减时会在可补位范围内持续弹出，得到最后 k 个。

Alternatives

替代方案与取舍

逐位扫描可选窗口

每一位都在确保剩余长度足够的窗口中找最小值。思路直观，但朴素实现最坏为 O(nk)；可用线段树等结构优化，不过实现更重。

优先队列 + 下标

可维护窗口最小值并保证下标递增，通常达到 O(n log n) 或 O(n log k)，仍不如单调栈简洁且线性。

Pitfalls

常见错误

  • 只判断当前值更小就弹栈：忽略剩余数量，可能最后凑不满 k 个。
  • 把子序列当子数组：元素不必连续，但必须保持原相对顺序。
  • 栈满后不再处理：即使已有 k 个，后续较小元素仍可能替换栈尾。
  • 使用 >= 弹出相等值：通常仍可能得到同值答案，但会做无意义替换，也更容易把容量条件写错。
  • 把 while 写成 if：当前小值可能需要连续移除多个更大的栈尾。

JavaLeetCode signature
class Solution {
    public int[] mostCompetitive(int[] nums, int k) {
        int n = nums.length;
        int[] stack = new int[k];
        int size = 0;

        for (int i = 0; i < n; i++) {
            while (size > 0
                    && stack[size - 1] > nums[i]
                    && size + (n - i) > k) {
                size--;
            }

            if (size < k) {
                stack[size++] = nums[i];
            }
        }

        return stack;
    }
}

var mostCompetitive = function(nums, k) {
    const stack = [];
    const n = nums.length;

    for (let i = 0; i < n; i++) {
        while (
            stack.length > 0 &&
            stack[stack.length - 1] > nums[i] &&
            stack.length + (n - i) > k
        ) {
            stack.pop();
        }

        if (stack.length < k) {
            stack.push(nums[i]);
        }
    }

    return stack;
};

from typing import List


class Solution:
    def mostCompetitive(
        self, nums: List[int], k: int
    ) -> List[int]:
        stack: List[int] = []
        n = len(nums)

        for i, value in enumerate(nums):
            while (
                stack
                and stack[-1] > value
                and len(stack) + (n - i) > k
            ):
                stack.pop()

            if len(stack) < k:
                stack.append(value)

        return stack
C++LeetCode signature
class Solution {
public:
    vector<int> mostCompetitive(
        vector<int>& nums, int k
    ) {
        vector<int> stack;
        stack.reserve(k);
        int n = static_cast<int>(nums.size());

        for (int i = 0; i < n; ++i) {
            while (!stack.empty()
                   && stack.back() > nums[i]
                   && static_cast<int>(stack.size())
                          + (n - i) > k) {
                stack.pop_back();
            }

            if (static_cast<int>(stack.size()) < k) {
                stack.push_back(nums[i]);
            }
        }

        return stack;
    }
};

Interview follow-ups

面试追问

为什么内层 while 不是 O(n²)？

用摊还分析：每个元素最多压栈一次，也最多弹栈一次，所以所有 while 的弹出总次数不超过 n。

如果要求字典序最大呢？

反转比较方向：当栈顶小于当前值且补位安全时弹出，其余逻辑不变。

能否原地完成？

如果允许修改输入数组，可把它的前 k 个位置当作栈空间，额外空间降为 O(1)，但会破坏入参。

与“移掉 k 位数字”有何联系？

核心都是在删除额度允许时，用后来的更小数字替换前面的较大数字；容量条件只是换了一种表达。
