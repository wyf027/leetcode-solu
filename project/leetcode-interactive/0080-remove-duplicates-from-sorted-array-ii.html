核心洞察

只看输出中倒数第二个值

数组有序，所以相同值必定连续。若有效前缀不足两个元素，当前值必然可写；否则把当前值与 nums[write - 2] 比较：不同则最多只出现一次，可以写入；相同则前缀末尾已经有两个相同值，必须跳过。

RULE A

write < 2

前两个元素无条件保留。

RULE B

x ≠ nums[write−2]

当前值尚未在有效前缀中出现两次，写入并推进。

RULE C

否则跳过

只推进读指针，写指针保持不动。

完整过程

  1. 1

    令 write = 0，依次让 read 从 0 遍历到 n - 1。

  2. 2

    若 write < 2，直接把 nums[read] 写到 nums[write]。

  3. 3

    否则比较 nums[read] 与 nums[write - 2]。不同才允许写入。

  4. 4

    每次写入后执行 write++；跳过时只继续下一个 read。

  5. 5

    遍历结束后，write 就是有效前缀长度 k。

复杂度

时间
O(n)

读指针只扫描一次。

额外空间
O(1)

直接覆盖输入数组，不建立新数组。

关键边界

  • · 长度 1 或 2：全部保留。
  • · 所有值相同：结果长度最多为 2。
  • · 全部不同：每项都保留。
  • · 负数和零不影响比较。
  • · 只保证前 k 项，尾部无需清理。

替代方案

显式计数当前段

记录当前值和连续次数也能完成，但状态更多；利用有序性和 write - 2 能把规则压缩成一个判断。

面试追问

最多保留 m 次？

把常数 2 替换为 m：write < m || nums[read] !== nums[write - m]，其余流程不变。

取舍

为什么不建新数组？

新数组最直观但违反 O(1) 额外空间。双指针既满足原地要求，也保持稳定顺序，是面试首选。

常见错误

比较 nums[read - 2]：读区仍含待跳过元素，不能代表有效前缀。

跳过时也增加 write：会把无效位置计入返回长度。

返回 write - 1：write 是数量和下一写入下标，直接返回即可。

清空数组尾部：题目明确不检查 k 之后的内容，额外工作没有必要。

class Solution {
    public int removeDuplicates(int[] nums) {
        int write = 0;
        for (int read = 0; read < nums.length; read++) {
            if (write < 2 || nums[read] != nums[write - 2]) {
                nums[write] = nums[read];
                write++;
            }
        }
        return write;
    }
}
