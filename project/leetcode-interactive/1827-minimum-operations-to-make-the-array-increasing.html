最少操作使数组递增

Minimum Operations to Make the Array Increasing

只能向上调整，怎样用最少的次数，让每个数字都比前一个大？先思考，再打开页面底部的题解实验室。

题目

给定下标从 0 开始的整数数组 nums。每次操作可以任选一个元素，将它加 1。返回让数组严格递增需要的最少操作次数。

严格递增要求每一对相邻元素满足 nums[i] < nums[i + 1]。长度为 1 的数组天然满足条件；元素不能减小，也不能重排。

约束：1 ≤ nums.length ≤ 5000；1 ≤ nums[i] ≤ 10⁴。

官方示例

示例 1

输入：nums = [1,1,1]
输出：3

依次增加下标 2、1、2，得到 [1,1,2] → [1,2,2] → [1,2,3]，共 3 次。

示例 2

输入：nums = [1,5,2,4,1]
输出：14

示例 3

输入：nums = [8]
输出：0

单元素无需调整。

题解 · 搭一座最低的阶梯

核心洞察

从左向右确定最终值。前一个最终值为 prev 时，当前元素既不能低于原值，又必须至少为 prev + 1。所以取 current = max(nums[i], prev + 1)，把 current - nums[i] 加到答案。

第一个元素保持原值。把任何位置抬得更高，只会增加当前代价，并可能进一步推高右边的最低门槛。

交互 · 逐格抬升

每步处理一个下标，一次汇总这个位置的所有 +1 操作。青色表示已确定，黄色边框表示当前格；柱高按最终最大值缩放。

完整过程

以 [1,5,2,4,1] 为例：保留 1；5 已大于 1，保留；2 必须抬到 6，增加 4；4 必须抬到 7，增加 3；1 必须抬到 8，增加 7。最终为 [1,5,6,7,8]，总次数为 0 + 4 + 3 + 7 = 14。

正确性：逐项最小的归纳证明

记算法得到的数组为 b，任意合法最终数组为 c。第一项满足 c[0] ≥ nums[0] = b[0]。若 c[i−1] ≥ b[i−1]，由于只能增加且必须严格递增，有 c[i] ≥ max(nums[i], c[i−1]+1) ≥ max(nums[i], b[i−1]+1) = b[i]。因此任意合法方案的每一项都至少与 b 一样大。操作次数等于各项增量之和，算法逐项达到下界，所以总次数最少。

边界与复杂度

单元素和已严格递增数组返回 0；相等时也必须增加；下降序列需要使用调整后的前值。最终值可以超过输入上限 10000。仅扫描一次，时间 O(n)，辅助空间 O(1)，不修改输入。最坏总增量可由 [10000,1,…,1] 达到 62,482,501（n=5000），32 位有符号整数足够。

替代方案

原地更新 nums[i] 并累加差值也能达到 O(n) 时间、O(1) 空间，但会修改输入。逐次 +1 模拟直观，却需要 O(n + 答案) 时间；直接算差值即可。排序会改变元素位置，不是合法解法。

常见错误

  • 将严格递增误写成允许相等，忘记 +1。
  • 用原始 nums[i−1] 比较，遗漏前面调整的连锁影响。
  • 统计被改动的元素个数，而非所有增量之和。
  • 把第一项也增加，产生不必要的代价。

面试追问

若相邻差至少为 k？ 当 k 为正整数，把 prev+1 改成 prev+k。能否处理流输入？ 可以，只需前值与累计次数。若允许减少？ 当前逐项下界不再成立，需要重新分析双向修改成本，不能照搬此贪心。

Java

class Solution {
    public int minOperations(int[] nums) {
        int prev = nums[0], answer = 0;
        for (int i = 1; i < nums.length; i++) {
            int current = Math.max(nums[i], prev + 1);
            answer += current - nums[i];
            prev = current;
        }
        return answer;
    }
}
