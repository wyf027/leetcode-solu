Mission brief

输入

n 个互不相同的整数

范围

[0, n]

目标

找出唯一未出现的整数

标签：数组 · 位运算 · 数学 · 哈希表

01 · Problem

题意与输入契约

给定整数数组 nums。数组长度为 n，其中包含范围 [0, n] 内的 n 个互不相同的数。该范围共有 n + 1 个候选数，因此恰有一个数没有出现在数组中；请返回它。

示例 1

输入：nums = [3,0,1]
输出：2
解释：n = 3，范围为 [0,3]，其中 2 未出现。

示例 2

输入：nums = [0,1]
输出：2
解释：n = 2，范围为 [0,2]，其中 2 未出现。

示例 3

输入：nums = [9,6,4,2,3,5,7,0,1]
输出：8
解释：n = 9，范围为 [0,9]，其中 8 未出现。

约束

  • n == nums.length
  • 1 <= n <= 104
  • 0 <= nums[i] <= n
  • nums 中所有数字互不相同

进阶目标

尝试把运行时间控制在 O(n)，并且只使用 O(1) 额外空间。

先想一想：如果某种运算能让相同的数字两两抵消，会发生什么？

04 · Solution

准备好核对思路了吗？

题解默认收起。展开后将看到证明、复杂度、四种语言代码与面试追问。

Core insight

核心洞察：让重复值自行消失

异或满足 x ⊕ x = 0、x ⊕ 0 = x，并且交换顺序不影响结果。将完整范围 0…n 与数组中所有值一起异或，每个已出现的数字都恰好出现两次，最终只留下缺失数字。

missing = n ⊕ (0 ⊕ nums[0]) ⊕ (1 ⊕ nums[1]) ⊕ … ⊕ (n−1 ⊕ nums[n−1])

完整过程

  1. 1

    初始化

    令 acc = n，先补上索引序列中没有包含的末端值 n。

  2. 2

    单次扫描

    对每个下标 i，执行 acc ^= i ^ nums[i]。

  3. 3

    返回剩余值

    扫描结束后，成对数字均抵消，acc 就是唯一缺失值。

正确性证明

索引集合 {0,…,n−1} 再加入初值 n，正好构成完整集合 {0,…,n}。

设缺失值为 m。数组 nums 恰好包含完整集合中除 m 之外的所有值。

因此总异或中，每个非 m 的值分别来自完整集合和 nums，各出现两次并异或为 0；m 只来自完整集合，出现一次。

所有成对项消失后结果为 0 ⊕ m = m，故算法返回的正是缺失值。

时间复杂度

O(n)

仅遍历数组一次。

额外空间

O(1)

只维护累积器和下标。

数值安全

无求和溢出

异或不产生算术进位。

边界情况

  • 缺失 0：例如 [1]，所有数组值仍能与完整集合中的同值抵消，留下 0。
  • 缺失 n：例如 [0,1]，初始累积器 n 没有数组项与之抵消，因此保留下来。
  • 数组无序：异或满足交换律和结合律，不依赖排列顺序。
  • 最大规模：算法单次线性扫描，不创建随 n 增长的辅助容器。

Implementation

四种语言完整代码

class Solution {
    public int missingNumber(int[] nums) {
        int acc = nums.length;

        for (int i = 0; i < nums.length; i++) {
            acc ^= i ^ nums[i];
        }

        return acc;
    }
}

替代方案

等差数列求和

计算 n(n+1)/2 − sum(nums)，同样是 O(n) 时间和 O(1) 空间；在某些语言或更大范围中要注意整数溢出。

哈希集合

记录数组元素后扫描 0…n，直观但需要 O(n) 额外空间。

排序后二分或扫描

可定位首个下标与数值不相等的位置，但排序通常需要 O(n log n) 时间，且可能改变输入。

常见错误

  • 只异或下标 0…n−1 与数组，忘记把 n 加入累积器。
  • 把题意误读为数组长度 n + 1，导致范围和循环边界偏移。
  • 使用求和法时先以较窄整数类型计算 n*(n+1)，再转宽类型，转换已经太晚。
  • 为追求 O(1) 空间而原地排序，却忽略调用方可能要求保留输入顺序。

面试追问

为什么初值是 n？

循环下标只覆盖 0…n−1，而完整范围还有 n；初值负责补上它。

若有两个数字缺失呢？

总异或只得到两者的异或值；可利用其中一个不同的二进制位分组，再分别异或恢复两数。

求和法与异或法如何选择？

在约束较小且有安全宽整数时求和更直观；担心溢出或希望展示位运算性质时可选异或。

如果输入不保证唯一呢？

当前证明不再成立，需要重新明确重复值、缺失数量等契约，可能改用计数或集合。
