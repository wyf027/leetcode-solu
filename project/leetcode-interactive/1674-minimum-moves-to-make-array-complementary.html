Problem brief

先把题目说清楚

给定偶数长度数组 nums 与上界 limit。一次操作可以把任意元素替换成 [1, limit] 内的另一个整数。

如果对每个下标 i，镜像位置 nums[i] 与 nums[n - 1 - i] 的和都等于同一个数，那么数组就是互补数组。请返回把 nums 变成互补数组所需的最少操作次数。

参数形式
minMoves(nums, limit) → integer
nums: integer[]  ·  limit: integer  ·  return: integer

约束

  • n == nums.length
  • 2 ≤ n ≤ 10⁵
  • 1 ≤ nums[i] ≤ limit ≤ 10⁵
  • n 为偶数

官方示例

示例 1

输入：nums = [1,2,4,3], limit = 4
输出：1
解释：把 4 改成 2，可得 [1,2,2,3]；
两组镜像对的和都为 4。

示例 2

输入：nums = [1,2,2,1], limit = 2
输出：2
解释：把首尾的 1 都改成 2；
不能改成 3，因为它超过 limit。

示例 3

输入：nums = [1,2,1,2], limit = 2
输出：0
解释：两组镜像对的和都为 3，
数组已经互补。

Solution

差分数组：一次记录整段代价

把每一对元素对所有候选目标和的贡献，看成一条分段常数函数；用区间加减记录拐点，最后做一次前缀和。

核心洞察完整过程正确性边界与复杂度四语言代码替代方案面试追问常见错误

核心洞察

对镜像对 (a, b) 和目标和 x，操作次数只可能是 0、1、2。若不改，唯一命中 a+b；若只改一个数，可覆盖一段连续区间；其余目标必须改两个数。

令 low = min(a,b) + 1，high = max(a,b) + limit。只改一个元素时，目标和恰好可落在 [low, high]。于是单对代价是：

cost(x) = 2                         x ∉ [low, high]
          1                         x ∈ [low, high] 且 x ≠ a+b
          0                         x = a+b

完整过程

  1. 候选目标和只可能是 2..2×limit。
  2. 对每一对 (a,b)，先让全区间代价增加 2。
  3. 在 [low, high] 上减 1，表示该区间内最多只改一个元素。
  4. 在单点 a+b 再减 1，表示原本已经满足，无须操作。
  5. 用差分数组完成区间更新，再从 2 到 2×limit 求前缀和并取最小值。
对每一对 (a, b)：
diff[2]             += 2
diff[2*limit + 1]   -= 2
diff[low]           -= 1
diff[high + 1]      += 1
diff[a + b]         -= 1
diff[a + b + 1]     += 1

正确性证明

  1. 单对代价完整。不改时仅能得到 a+b；改一个数时，新值在 [1,limit]，两种修改方向合并后恰好覆盖 [low,high]；区间外至少要改两个数。
  2. 差分贡献准确。全区间基线 2，在一改区间减 1，在零改单点再减 1，恢复出的每个位置正好等于该对的真实代价。
  3. 各对可以相加。镜像对之间不共享元素；选定同一目标和后，每对的最少修改互不影响，总操作数就是各对代价之和。
  4. 扫描得到全局最优。算法检查了所有合法目标和，并取总代价最小值，因此返回使数组互补的最少操作次数。

边界与复杂度

  • 最小长度：n=2 时仅一对，原数组天然满足某个目标和，答案为 0。
  • 端点：差分数组要容纳 2×limit+1 这个右开端点，通常分配 2×limit+2。
  • 相等元素：a=b 不影响公式，一改区间仍然连续。
  • 时间：O(n + limit)；空间：O(limit)。

class Solution {
    public int minMoves(int[] nums, int limit) {
        int[] diff = new int[2 * limit + 2];

        for (int i = 0; i < nums.length / 2; i++) {
            int a = nums[i];
            int b = nums[nums.length - 1 - i];
            int low = Math.min(a, b) + 1;
            int high = Math.max(a, b) + limit;
            int sum = a + b;

            diff[2] += 2;
            diff[2 * limit + 1] -= 2;
            diff[low] -= 1;
            diff[high + 1] += 1;
            diff[sum] -= 1;
            diff[sum + 1] += 1;
        }

        int answer = nums.length;
        int moves = 0;
        for (int target = 2; target <= 2 * limit; target++) {
            moves += diff[target];
            answer = Math.min(answer, moves);
        }
        return answer;
    }
}

替代方案

枚举目标和 + 枚举每对

直接计算每个目标和的总成本，时间复杂度 O(n × limit)。逻辑直观，但在 10⁵ 规模下不可行，可作为小数据思维起点。

端点事件计数

也可分别统计原始和、一步可达区间的左右端点，本质仍是扫描线/差分。表达稍有不同，复杂度同为 O(n + limit)。

面试追问

为什么目标和不用考虑 2 到 2×limit 之外？

最终每个元素都必须处于 [1,limit]，两个元素的和最小为 2、最大为 2×limit。

如果一次操作的代价不是 1，而与改变量有关呢？

单对代价函数不再只有 0/1/2 三段常数，当前的区间差分模型不能直接套用；需分析新的分段线性结构，可能使用斜率差分或凸优化。

可以只记录“一步可达”的次数吗？

可以。对每个目标，以所有对都需两步为基线，再减去一步可达对数，最后对原始和命中的对再减一次，和当前写法等价。

为什么镜像对只遍历前一半？

i 与 n-1-i 描述的是同一对，遍历全部下标会重复计数。偶数长度确保没有中心单点。

常见错误

一步区间端点写错
low=min(a,b)+1，high=max(a,b)+limit，两端都包含。
忘记右开事件
区间在 high+1 恢复，单点在 sum+1 恢复。
数组少开一格
需要访问 2×limit+1，至少分配到该下标。
把原数组直接排序
镜像配对由位置决定；排序会改变配对关系，不能保留问题语义。
