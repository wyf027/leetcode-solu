装满石头的背包
的最大数量

Maximum Bags With Full Capacity of Rocks

一堆额外的石头，一组尚未装满的背包。怎样分配，才能让最多的背包达到容量上限？

LeetCode 官方题目 ↗

01 / THE PROBLEM

问题与输入

有 n 个背包，编号从 0 到 n − 1。数组 capacity 给出各背包的容量，rocks 给出对应背包当前已有的石头数。另有 additionalRocks 块石头，可以加入任意背包，但不能超出容量。

返回最终装满的背包的最大数量。现有石头不能在背包之间搬运；额外石头不必全部用完。

maximumBags(capacity: integer[], rocks: integer[], additionalRocks: integer) → integer

约束

  • n == capacity.length == rocks.length
  • 1 ≤ n ≤ 5 × 10⁴
  • 1 ≤ capacity[i] ≤ 10⁹
  • 0 ≤ rocks[i] ≤ capacity[i]
  • 1 ≤ additionalRocks ≤ 10⁹

02 / 官方示例

示例 1

capacity = [2,3,4,5]
rocks = [1,2,4,4]
additionalRocks = 2
输出：3

向背包 0 和 1 各放 1 块，得到 [2,3,4,4]。背包 0、1、2 装满，共 3 个；无法装满更多背包。最优分配方式可能不唯一。

示例 2

capacity = [10,2,2]
rocks = [2,2,0]
additionalRocks = 100
输出：3

向背包 0 放 8 块，向背包 2 放 2 块，得到 [10,2,2]，全部装满。只用了 10 块，剩下 90 块不必放置。

03 / SOLUTION

把空位看成成本

核心洞察：背包 i 还差 capacity[i] − rocks[i] 块石头。每装满一个背包都只增加 1 个答案，因此优先支付较小的缺口。

  1. 计算每个背包的缺口 need[i]。
  2. 按缺口从小到大排序。
  3. 逐个处理：若缺口不大于剩余石头，扣除缺口并将答案加 1。
  4. 若当前缺口无法支付，停止；后面的缺口更大，也无法支付。
缺口为 0 时无需消耗石头，答案直接加 1。不要在预算为 0 时无条件提前结束，否则可能漏掉尚未计数的零缺口。

为什么一定最优？
交换论证：若一个方案选择了缺口较大的背包 b，却没有选择缺口较小的背包 a，把 b 换成 a 不增加用石量，装满数量也不减少。重复交换，就能把任意装满 k 个背包的可行方案变成选择 k 个最小缺口的方案。
前缀结论：排序后前 k 个缺口之和，是装满 k 个背包所需的最小额外石头数。算法支付能承担的最长前缀。若第 k + 1 个缺口无法支付，说明最小的 k + 1 个缺口总和也超过预算，任何方案都不能装满 k + 1 个背包，故答案最优。
边界与数值
  • 全部已满：所有缺口为 0，返回 n。
  • 最小正缺口也付不起：只统计原本已满的背包。
  • 预算恰好等于缺口：应允许支付，判断使用 ≤。
  • 预算足够填满全部：返回 n，额外石头可以剩余。
  • 单个缺口不超过 10⁹，逐项扣减使预算保持非负。若累计所有缺口，总和可达 5 × 10¹³，Java/C++ 应使用 64 位整数。
复杂度
计算和扫描 O(n)，排序 O(n log n)，总时间 O(n log n)。四份实现都创建缺口数组，辅助空间 O(n)，不修改输入数组。排序本身的临时空间包含在这一上界中；JavaScript 内置排序的具体实现由引擎决定。

Java
import java.util.Arrays;

class Solution {
    public int maximumBags(int[] capacity, int[] rocks, int additionalRocks) {
        int[] need = new int[capacity.length];
        for (int i = 0; i < capacity.length; i++) {
            need[i] = capacity[i] - rocks[i];
        }
        Arrays.sort(need);
        int answer = 0;
        for (int cost : need) {
            if (cost > additionalRocks) break;
            additionalRocks -= cost;
            answer++;
        }
        return answer;
    }
}

from typing import List

class Solution:
    def maximumBags(self, capacity: List[int], rocks: List[int],
                    additionalRocks: int) -> int:
        need = sorted(c - r for c, r in zip(capacity, rocks))
        answer = 0
        for cost in need:
            if cost > additionalRocks:
                break
            additionalRocks -= cost
            answer += 1
        return answer
C++
#include <algorithm>
#include <vector>
using namespace std;

class Solution {
public:
    int maximumBags(vector<int>& capacity, vector<int>& rocks,
                    int additionalRocks) {
        vector<int> need(capacity.size());
        for (int i = 0; i < static_cast<int>(capacity.size()); ++i) {
            need[i] = capacity[i] - rocks[i];
        }
        sort(need.begin(), need.end());
        int answer = 0;
        for (int cost : need) {
            if (cost > additionalRocks) break;
            additionalRocks -= cost;
            ++answer;
        }
        return answer;
    }
};


替代方案与面试追问
替代方案
  • 最小堆：建堆 O(n)，弹出 k 个最小缺口 O(k log n)，空间 O(n)。只需少量背包时可以考虑。
  • 计数桶：缺口上界 M 很小时可做到 O(n + M) 时间、O(M) 空间；本题 M 可达 10⁹，不适合直接开桶。
  • 动态规划：预算 B 可达 10⁹，按预算做 O(nB) 的背包动态规划不实用；本题等收益性质允许贪心。
面试追问
装满不同背包的收益不同？按缺口排序不再保证最优，需要结合约束考虑 0/1 背包等带权选择算法。
同一组背包查询多个预算？排序一次并计算 64 位前缀和，每次二分寻找不超过预算的最长前缀，单次查询 O(log n)。
需要返回装满的背包编号？排序时携带原始下标，并记录接受的背包。交互队列使用的就是这种表示。
常见错误
  • 按容量或已有石头数排序，而非按二者之差排序。
  • JavaScript 使用没有比较器的 sort()，按字符串顺序排列。
  • 平均分配石头，花掉预算却没有新增装满的背包。
  • 预算比较使用严格小于，漏掉恰好装满的情况。
  • 只统计新装满的背包，漏掉初始已经装满的背包。
