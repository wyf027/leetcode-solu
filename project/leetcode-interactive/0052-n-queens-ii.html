CORE INSIGHT

只计数，就让状态变轻

每层递归天然固定一行，因此只需记录哪些列、左斜线和右斜线已被攻击。 三个整数的每一位对应一列，合法位一次由按位运算筛出。 

available = mask & ~(columns | left | right)
bit = available & -available

WHY LOWBIT

一次取出一个候选列

`x & -x` 保留最低位的 1。递归后把左斜线左移、右斜线右移， 使攻击范围自动对齐下一行；随后从 available 中删掉该位继续枚举。

完整过程

  1. 1. `mask = (1 << n) - 1` 保留低 n 位。
  2. 2. 合并三类攻击位并取反，再与 mask 相交。
  3. 3. lowbit 逐个枚举本行安全列。
  4. 4. 更新三组掩码并递归到下一行。
  5. 5. 所有列位都占用时，方案数加一。

边界与复杂度

  • `n = 1`：唯一位置即一个方案。
  • `n = 2 / 3`：搜索完毕但计数为零。
  • `n = 9`：低 9 位仍安全落在常规整数范围。
  • 时间：上界 O(n!)，剪枝后实际节点显著减少。
  • 空间：O(n) 递归栈；位掩码状态为 O(1)。

替代方案

  • 三个集合：语义最直观，面试中容易先写对，但常数更高。
  • 扫描棋盘：验证一次要检查多条方向，不推荐。
  • 对称剪枝：可将首行搜索近似减半，但代码更复杂，属于进阶优化。

常见错误

  • 对取反结果忘记再次与 mask 相交，导致高位也变成候选位。
  • 左右斜线移位方向写反，或忘记左移后裁掉高位。
  • 取出 bit 后没有从 available 中删除，造成死循环。
  • 把第 51 题的棋盘结果集原样保留，浪费本题不需要的空间。

面试追问

  • 为什么 `available & -available` 能取得最低位的 1？
  • 为什么递归终点可以判断 `columns == mask`？
  • 若 n 超过语言整数位宽，应如何改成 BigInt 或更宽整数？
  • 如何利用镜像对称减少首行一半搜索？

class Solution {
    private int mask;

    public int totalNQueens(int n) {
        mask = (1 << n) - 1;
        return dfs(0, 0, 0);
    }

    private int dfs(int columns, int left, int right) {
        if (columns == mask) {
            return 1;
        }

        int available = mask & ~(columns | left | right);
        int count = 0;

        while (available != 0) {
            int bit = available & -available;
            available -= bit;
            count += dfs(
                columns | bit,
                ((left | bit) << 1) & mask,
                (right | bit) >> 1
            );
        }
        return count;
    }
}

  const mask = (1 << n) - 1;

  function dfs(columns, left, right) {
    if (columns === mask) return 1;

    let available = mask & ~(columns | left | right);
    let count = 0;

    while (available !== 0) {
      const bit = available & -available;
      available -= bit;
      count += dfs(
        columns | bit,
        ((left | bit) << 1) & mask,
        (right | bit) >> 1,
      );
    }
    return count;
  }

  return dfs(0, 0, 0);
};
