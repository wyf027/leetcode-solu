Prison Cells After N Days

N 天后的牢房

八间牢房排成一列。每天，每个内部牢房只根据昨天左右邻居是否相同，决定今天是占用还是空置。

转移规则：若左右两侧同时为 0 或同时为 1，则当前牢房次日为 1；否则为 0。首尾没有两个邻居，因此从第 1 天起恒为 0。

给定长度为 8 的整数数组 cells 与天数 n，返回同步变化 n 次后的状态。

状态实验台
第 0 天
点击牢房可修改第 0 天
跳转使用状态判重加速；更改初始牢房后会重建轨迹。
新状态：等待第一次转移

输入：cells = [0,1,0,1,1,0,0,1], n = 7
输出：[0,0,1,1,0,0,0,0]
解释：从第 0 天开始同步更新 7 次，

准备好看题解了吗？

先在实验台观察几天。注意：状态总数有限，但 n 可以达到十亿。

题解：把十亿天折叠成一个环

核心洞察

每次转移完全由当前 8 位状态决定，是确定性的。首尾从第 1 天起固定为 0，所以后续最多只有 2^6 = 64 种状态。不断模拟必然遇到旧状态；一旦找到环，就可以用取模一次跳过大量整环。

完整过程

把当前数组序列化为字符串，记录它第一次出现时剩余多少天。
若当前状态见过，则两次出现之间经过的天数就是环长；令剩余天数对环长取模。
若尚未见过，登记当前状态，计算下一天。更新必须写入新数组，避免同一天内前后互相污染。
剩余天数归零时返回当前状态。

正确性证明

转移正确：对每个内部位置 i，算法当且仅当旧状态的 cells[i-1] == cells[i+1] 时写入 1，与题意完全一致；首尾写 0。

跳环正确：相同状态之后的所有未来状态必然相同。若两个相同状态相隔 L 天，则跳过任意个完整的 L 天不会改变最终状态，只需继续模拟 remaining mod L 天。

因此算法返回的正是第 n 天状态。

边界与复杂度

  • 边界牢房从第 1 天起始终为 0。
  • n 很大时不能逐日模拟。
  • 初始状态允许首尾为 1；只在第一次更新后归零。
  • 时间：O(min(n, 2^6) × 8)，可视为常数。
  • 空间：O(2^6 × 8)。

import java.util.*;

class Solution {
    public int[] prisonAfterNDays(int[] cells, int n) {
        Map<String, Integer> seen = new HashMap<>();
        while (n > 0) {
            String key = Arrays.toString(cells);
            if (seen.containsKey(key)) {
                int cycle = seen.get(key) - n;
                n %= cycle;
            }
            seen.put(key, n);
            if (n > 0) {
                n--;
                int[] next = new int[8];
                for (int i = 1; i < 7; i++)
                    next[i] = cells[i - 1] == cells[i + 1] ? 1 : 0;
                cells = next;
            }
        }
        return cells;
    }
}

    vector<int> prisonAfterNDays(vector<int>& cells, int n) {
        unordered_map<int, int> seen;
        auto encode = [](const vector<int>& a) {
            int mask = 0;
            for (int bit : a) mask = (mask << 1) | bit;
            return mask;

                n %= cycle;

                cells = next;

替代方案

固定 14 天周期：本题在首次更新后实际进入长度为 14 的规律，可用 (n - 1) % 14 + 1 压缩天数。它更短，但依赖本题特性；通用判环更容易解释和迁移。

位掩码：用 8 位整数编码状态，转移和哈希常数更小，但数组写法更直观。

常见错误

  • 原地更新数组，导致右侧计算读到“今天”的值。
  • 忘记首尾始终写 0。
  • 发现重复后使用错误的环长或剩余天数。
  • 盲目写死 14，却没有处理 n 与第 0 天的偏移。

面试追问

为什么状态上限是 64，而不是 256？

初始状态确实有 256 种；但第一次转移之后，首尾固定为 0，只剩中间 6 位可变，所以后续至多 64 种。

怎样不用 Map 找环？

可以用 Floyd 快慢指针先求环入口和环长，再按天数跳转；空间降为 O(1)，但实现更复杂。也可利用已知 14 天周期。

如果牢房长度不再固定为 8 呢？

判环思路仍成立，但状态数增长为约 2^(m-2)。当 m 很大时，不能再把“状态数很少”视为常数，需要寻找线性代数或位运算优化。
