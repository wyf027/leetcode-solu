Core protocol

把匹配表的结果压栈

OPEN遇左括号

直接压入它期待的右括号。

CLOSE遇右括号

弹出栈顶，必须等于当前字符。

FINISH扫描结束

只有栈为空才全部闭合。

循环不变量：扫描完任意前缀后，栈从底到顶保存这个前缀中尚未闭合的左括号，按未来必须出现的右括号顺序排列；栈顶就是下一枚允许通过的右括号。

Walkthrough

完整过程

  1. 1

    建立匹配表：(→)、[→]、{→}，初始化空栈。

  2. 2

    遇到左括号，把对应右括号压栈。

  3. 3

    遇到右括号；若栈空或弹出值不等于它，立即返回 false。

  4. 4

    完整扫描后返回栈是否为空。

Edge cases

边界情况

  • 首字符是右括号：栈为空，立即失败。
  • 类型错误：(] 的栈顶期待 )，却读到 ]。
  • 顺序交叉：([)] 类型虽成对，但违反后进先出。
  • 只有左括号：扫描结束栈非空，仍是 false。
  • 奇数长度：一定无效，可提前判断，但不是必要条件。

Complexity

复杂度

O(n) 时间

O(n) 空间

最坏情况下字符串全是左括号，栈保存 n 个期待字符。

Alternatives

替代方案取舍

循环替换

不断删除 ()、[]、{}；直观但最坏 O(n²)。

压左括号

弹栈后再查匹配表，同为 O(n)，条件略长。

计数器

只适合单一括号类型；三种类型无法表达嵌套顺序。

Interview follow-ups

面试高频追问

为什么最后还要检查栈为空？

像 (( 没遇到错误右括号，但仍有未闭合期待。

能否 O(1) 空间？

一般输入流下需要记住未闭合嵌套，最坏深度为 n；若允许原地改写字符数组，可借输入空间模拟栈。

为什么先压“期待字符”？

右括号分支只做一次相等判断，省去弹出左括号后再次映射，代码更贴近不变量。

Failure modes

常见错误

  • 空栈先 pop：以右括号开头会越界或抛异常。
  • 只比较数量：([)] 数量正确但顺序错误。
  • 扫描完直接 true：漏掉只有左括号的情况。
  • 把队列当栈：括号嵌套要求最近打开者最先关闭。

class Solution {
    public boolean isValid(String s) {
        Map<Character, Character> pairs = Map.of(
            '(', ')', '[', ']', '{', '}'
        );
        Deque<Character> stack = new ArrayDeque<>();

        for (char ch : s.toCharArray()) {
            if (pairs.containsKey(ch)) {
                stack.push(pairs.get(ch));
            } else if (stack.isEmpty() || stack.pop() != ch) {
                return false;
            }
        }

        return stack.isEmpty();
    }
}
