Deep Dive

完整题解

核心洞察：只和相同值的下标打交道

把每个值出现的下标按扫描顺序收集为 p[0..m-1]。对当前下标 p[k]，左边下标都不大于它，右边下标都不小于它，绝对值可以分别拆开，再用前缀和一次求出。

公式

设 prefix[k] 表示 p[0..k-1] 的和，total 是全部下标之和。

left = p[k] × k − prefix[k]

right = (total − prefix[k] − p[k]) − p[k] × (m − k − 1)

answer[p[k]] = left + right

为什么前缀和有效

左边每项是 p[k] − p[t]，合并后就是“当前下标 × 左侧数量 − 左侧下标总和”。右侧同理，是“右侧下标总和 − 当前下标 × 右侧数量”。

分组下标天然递增，无需额外排序。

完整过程

按值分组

从左到右扫描 nums，哈希表把值映射到它出现的下标列表。

为每组准备总和

求出该组所有下标之和 total，并令左侧前缀和 prefix = 0。

逐个位置结算

在组内从左到右计算 left 与 right，写回原数组下标对应的答案，再把当前下标加入 prefix。

正确性证明

左侧：对所有 t < k，因 p[t] ≤ p[k]，距离为 p[k] − p[t]；求和得到 p[k]·k − prefix。

右侧：对所有 t > k，距离为 p[t] − p[k]；求和得到右侧下标和减去 p[k]·(m-k-1)。

两部分恰好覆盖全部且仅覆盖与 nums[p[k]] 相同的其他位置，因此相加就是题目定义的答案。对每个分组和每个位置均成立，算法正确。

复杂度与边界

  • 时间：O(n)，每个下标被收集和结算各一次。
  • 空间：O(n)，保存分组下标与答案。
  • 单元素或只出现一次的值：左右贡献均为 0。
  • 所有元素相同：仍只线性遍历一个分组。
  • 距离总和可能约为 10¹⁰，需要 64 位结果。

import java.util.*;

class Solution {
    public long[] distance(int[] nums) {
        Map<Integer, List<Integer>> groups = new HashMap<>();
        for (int i = 0; i < nums.length; i++) {
            groups.computeIfAbsent(nums[i], key -> new ArrayList<>()).add(i);
        }

        long[] answer = new long[nums.length];
        for (List<Integer> positions : groups.values()) {
            long total = 0;
            for (int position : positions) total += position;

            long prefix = 0;
            int size = positions.size();
            for (int k = 0; k < size; k++) {
                int position = positions.get(k);
                long left = (long) position * k - prefix;
                long right = total - prefix - position
                        - (long) position * (size - k - 1);
                answer[position] = left + right;
                prefix += position;
            }
        }
        return answer;
    }
}

var distance = function(nums) {
    const groups = new Map();
    nums.forEach((value, index) => {
        if (!groups.has(value)) groups.set(value, []);
        groups.get(value).push(index);
    });

    const answer = Array(nums.length).fill(0);
    for (const positions of groups.values()) {
        const total = positions.reduce((sum, index) => sum + index, 0);
        let prefix = 0;
        positions.forEach((position, k) => {
            const left = position * k - prefix;
            const right = total - prefix - position
                - position * (positions.length - k - 1);
            answer[position] = left + right;
            prefix += position;
        });
    }
    return answer;
};

class Solution:
    def distance(self, nums: List[int]) -> List[int]:
        groups = defaultdict(list)
        for index, value in enumerate(nums):
            groups[value].append(index)

        answer = [0] * len(nums)
        for positions in groups.values():
            total = sum(positions)
            prefix = 0
            size = len(positions)

                right = total - prefix - position \

替代方案

左右各扫描一次：哈希表分别维护每个值已出现的次数与下标和。正向累计左侧贡献，反向累计右侧贡献，也能做到 O(n) 时间。

它省去下标列表，但需要两套扫描逻辑；分组写法更贴近推导与可视化。

面试追问

能否原地返回？
输入是整数数组而输出需要 64 位，通常仍要新建答案数组。
下标列表为何有序？
因为按原数组从左到右加入，每个新下标都更大。
若输入以流形式到达？
只能立即得到左侧贡献；完整答案还依赖未来同值位置，需要延迟输出或保存状态。

常见错误

逐对计算

同值元素很多时退化为 O(n²)，无法通过 10⁵ 规模。

忘记 64 位

Java/C++ 中乘法前就要转为 long/long long。

右侧和多减或少减当前下标

右侧总和应为 total - prefix - position。

误以为分组后还要排序

只要按原数组顺序收集，下标已经递增。
