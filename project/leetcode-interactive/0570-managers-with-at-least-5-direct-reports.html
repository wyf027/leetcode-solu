#570 MEDIUM 数据库

至少有 5 名直接下属的经理

Managers with at Least 5 Direct Reports

给定员工与经理的自关联数据，返回拥有至少五名直接下属的经理姓名；结果顺序不限。

题解：自连接后按经理分组

这是一道数据库题。官方可提交语言是 SQL（以及 Pandas），因此下面以 MySQL 查询作为正式答案；Java、JavaScript、Python、C++ 代码仅用于在内存对象上表达同一语义，不能直接提交到本题的 SQL 判题器。

核心洞察

关系在下属行上employee.managerId 指向经理的 manager.id。
人数来自分组把下属按经理主键分组，组内行数就是直属下属数。
姓名来自自连接同一张表分别扮演“下属”和“经理”，连接后可直接返回经理姓名。

完整过程

  1. 把 Employee 命名为 employee，表示每一名可能的下属。
  2. 再把 Employee 命名为 manager，用 employee.managerId = manager.id 找到直属经理。
  3. 按 manager.id 与 manager.name 分组，避免仅按可能重复的姓名混合不同经理。
  4. 使用 HAVING COUNT(*) >= 5 保留至少五条直属汇报记录的经理组。

MySQL · 官方可提交答案

MySQL可提交
SELECT manager.name
FROM Employee AS employee
JOIN Employee AS manager
  ON employee.managerId = manager.id
GROUP BY manager.id, manager.name
HAVING COUNT(*) >= 5;

正确性说明

引理 1：连接后的每一行恰好对应一条有效的直属汇报关系。因为连接条件要求下属行的 managerId 等于经理行的唯一主键 id；managerId 为空的行不会连接，也就不会被误计。

引理 2：同一 manager.id 分组中的行数，恰好等于该经理的直属下属数。依据引理 1，每名直属下属贡献且只贡献一行。

定理：HAVING COUNT(*) >= 5 保留且仅保留拥有至少五名直属下属的经理；选择该组的 manager.name，所得结果正是题目所求。

复杂度

时间：典型 O(n) 额外空间：典型 O(n)

这里的复杂度以常见哈希连接与哈希聚合执行计划估算；实际数据库代价取决于索引、统计信息和优化器。id 作为主键通常已有索引。

边界情况

  • 恰好五名直属下属必须入选，因此条件是 >= 5，不是 > 5。
  • managerId IS NULL 的员工没有经理，内连接会自然排除这类汇报关系。
  • 只计算直接指向经理 id 的行；组织层级更深的间接下属不会被计入。
  • 姓名不一定唯一，所以分组中保留经理主键，不能只用 name 识别经理。
  • 空表或无人达到阈值时，结果为空。

替代方案

可以先在子查询中按 managerId 聚合，再用 IN 回到 Employee 取姓名：

MySQL · 子查询替代方案
SELECT name
FROM Employee
WHERE id IN (
  SELECT managerId
  FROM Employee
  WHERE managerId IS NOT NULL
  GROUP BY managerId
  HAVING COUNT(*) >= 5
);

它更接近“先找达标 managerId，再取姓名”的两阶段思路；自连接版本则把关系和姓名一次表达清楚。具体性能应以目标数据库的执行计划为准。

Java本地语义参考
import java.util.ArrayList;
import java.util.HashMap;
import java.util.List;
import java.util.Map;

public class ManagersWithFiveReports {
    public static final class Employee {
        final int id;
        final String name;
        final String department;
        final Integer managerId;

        public Employee(int id, String name, String department, Integer managerId) {
            this.id = id;
            this.name = name;
            this.department = department;
            this.managerId = managerId;
        }
    }

    public static List<String> findManagers(List<Employee> employees) {
        Map<Integer, Integer> reportCount = new HashMap<>();
        Map<Integer, String> nameById = new HashMap<>();

        for (Employee employee : employees) {
            nameById.put(employee.id, employee.name);
            if (employee.managerId != null) {
                reportCount.merge(employee.managerId, 1, Integer::sum);
            }
        }

        List<String> answer = new ArrayList<>();
        for (Map.Entry<Integer, Integer> entry : reportCount.entrySet()) {
            if (entry.getValue() >= 5 && nameById.containsKey(entry.getKey())) {
                answer.add(nameById.get(entry.getKey()));
            }
        }
        return answer;
    }
}
JavaScript本地语义参考
/**
 * @param {{id: number, name: string, department: string,
 *          managerId: number | null}[]} employees
 * @return {string[]}
 */
function findManagers(employees) {
  const reportCount = new Map();
  const nameById = new Map();

  for (const employee of employees) {
    nameById.set(employee.id, employee.name);
    if (employee.managerId !== null) {
      reportCount.set(
        employee.managerId,
        (reportCount.get(employee.managerId) ?? 0) + 1
      );
    }
  }

  const answer = [];
  for (const [managerId, count] of reportCount) {
    if (count >= 5 && nameById.has(managerId)) {
      answer.push(nameById.get(managerId));
    }
  }
  return answer;
}
Python本地语义参考
from collections import Counter
from dataclasses import dataclass
from typing import Optional


@dataclass(frozen=True)
class Employee:
    id: int
    name: str
    department: str
    manager_id: Optional[int]


def find_managers(employees: list[Employee]) -> list[str]:
    report_count = Counter(
        employee.manager_id
        for employee in employees
        if employee.manager_id is not None
    )
    name_by_id = {employee.id: employee.name for employee in employees}

    return [
        name_by_id[manager_id]
        for manager_id, count in report_count.items()
        if count >= 5 and manager_id in name_by_id
    ]
C++本地语义参考
#include <optional>
#include <string>
#include <unordered_map>
#include <vector>

struct Employee {
    int id;
    std::string name;
    std::string department;
    std::optional<int> managerId;
};

std::vector<std::string> findManagers(
    const std::vector<Employee>& employees
) {
    std::unordered_map<int, int> reportCount;
    std::unordered_map<int, std::string> nameById;

    for (const Employee& employee : employees) {
        nameById[employee.id] = employee.name;
        if (employee.managerId.has_value()) {
            ++reportCount[*employee.managerId];
        }
    }

    std::vector<std::string> answer;
    for (const auto& [managerId, count] : reportCount) {
        auto name = nameById.find(managerId);
        if (count >= 5 && name != nameById.end()) {
            answer.push_back(name->second);
        }
    }
    return answer;
}

面试追问

  • 为什么用 HAVING 而不是 WHERE？人数是聚合后的结果，必须在分组完成后过滤。
  • 只按 name 分组有什么风险？同名经理会被错误合并；经理主键才是实体身份。
  • 如何统计所有层级下属？需要递归 CTE 或闭包表等层级查询策略，当前自连接只覆盖一层。
  • 如何判断 JOIN 与 IN 谁更快？查看真实数据规模下的执行计划、索引命中和中间结果，而不是仅凭语法猜测。
  • 若阈值可配置呢？把常量 5 改为绑定参数，避免拼接 SQL。

常见错误

  • 写成 COUNT(*) > 5，漏掉恰好五人的经理。
  • 用 WHERE COUNT(*) 过滤聚合值，导致 SQL 语义错误。
  • 统计 department 或经理表行数，而不是直属汇报关系数。
  • 只返回 managerId，忘记回到 Employee 取得经理姓名。
  • 将间接下属也计入，偏离“direct reports”的一层关系。
