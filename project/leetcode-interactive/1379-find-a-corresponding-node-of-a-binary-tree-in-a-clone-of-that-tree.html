找出克隆二叉树中的相同节点

两棵结构完全一致的树，一个只属于原树的目标引用。你的任务不是找到相同的值，而是返回克隆树里对应位置的那个节点。

简单 树 深度优先搜索 广度优先搜索 非付费题
Problem

题意

给定原始二叉树 original、它的完整克隆 cloned，以及原树中的非空节点引用 target。请返回克隆树中与 target 位于相同结构位置的节点引用。

不能修改两棵树或目标节点；返回值必须是 cloned 中原本就存在的节点，而不是新建节点，也不能返回原树里的节点。

官方示例

示例 1
输入：original = [7,4,3,null,null,6,19]
      cloned   = [7,4,3,null,null,6,19]
      target   = original 中值为 3 的节点
输出：cloned 中值为 3 的节点引用
解释：两棵树结构一致，答案位于根的右孩子。
示例 2
输入：original = [7]
      cloned   = [7]
      target   = original 的根节点
输出：cloned 的根节点引用
示例 3
输入：original = [8,null,6,null,5,null,4,
                  null,3,null,2,null,1]
      cloned   = 同结构副本
      target   = original 中值为 4 的节点
输出：cloned 中值为 4 的节点引用

约束

  • 树中节点数量在 [1, 10⁴] 范围内。
  • 题目基础版本中，同一棵树的节点值互不相同。
  • target 属于 original 且不为 null。
  • cloned 与 original 结构、节点值完全一致。

Solution

同步遍历：位置才是稳定身份

核心洞察

克隆树复制了原树的结构。只要始终成对访问 (originalNode, clonedNode)，当原树节点与 target 是同一个对象时，同一对里的克隆节点就是答案。判断必须使用引用相等，而不是值相等，因此即使节点值重复也成立。

完整过程

成对进入。

递归函数同时接收原树当前节点和克隆树当前节点，两者永远处于相同结构位置。

比较引用。

若 original === target，立即返回当前的 cloned。

同步深入。

先同步搜索左右子树中的一侧；若未找到，再搜索另一侧。也可用队列进行同步 BFS。

传回答案。

一旦某个子树返回非空克隆节点，沿递归链直接返回，不再访问无关节点。

正确性证明

不变式：每次调用中，参数 original 与 cloned 都处在各自树的同一结构位置。

根节点对显然满足不变式。若一对节点满足不变式，则它们的左孩子彼此对应、右孩子也彼此对应，所以递归调用继续满足不变式。

遍历必然到达 target。到达时，由不变式可知配对的克隆节点恰好位于相同位置；算法返回它。算法只有在原树当前节点引用等于 target 时返回，因此不会返回错误位置。故算法正确。

复杂度与边界

  • 时间复杂度：最坏 O(n)。
  • 空间复杂度：递归栈 O(h)；斜树最坏 O(n)。
  • 单节点树：根节点引用直接匹配。
  • 目标在深层叶子：同步遍历仍会抵达对应位置。
  • 重复值：不受影响，因为比较的是节点引用。
Implementations

四语言完整代码

均采用同步 DFS，并保留 LeetCode 官方提交签名。

/**
 * Definition for a binary tree node.
 * public class TreeNode {
 *     int val;
 *     TreeNode left;
 *     TreeNode right;
 *     TreeNode(int x) { val = x; }
 * }
 */
class Solution {
    public final TreeNode getTargetCopy(
            final TreeNode original,
            final TreeNode cloned,
            final TreeNode target) {
        if (original == null) {
            return null;
        }
        if (original == target) {
            return cloned;
        }

        TreeNode found = getTargetCopy(original.left, cloned.left, target);
        if (found != null) {
            return found;
        }
        return getTargetCopy(original.right, cloned.right, target);
    }
}

/**

 * @return {TreeNode}
 */
var getTargetCopy = function (original, cloned, target) {
    if (original === null) {
        return null;
    }
    if (original === target) {
        return cloned;
    }

    const found = getTargetCopy(original.left, cloned.left, target);
    return found !== null
        ? found
        : getTargetCopy(original.right, cloned.right, target);
};

替代方案

同步 BFS

队列中保存节点对，逐层取出并比较原树引用。时间同为 O(n)，额外空间最坏为树的最大宽度 O(w)，并避免深递归栈风险。

按值查找

在“节点值唯一”的基础约束下可行，但依赖了不必要的条件，且无法回答重复值进阶。引用匹配更稳健。

记录路径后重放

先在原树找到从根到目标的左右路径，再沿相同路径走克隆树。正确但要保存路径；同步遍历更直接。

常见错误

  • 用 original.val === target.val 判断，在重复值场景会找错节点。
  • 命中后返回 original 或 target，违反答案必须来自克隆树的要求。
  • 只遍历一棵树，再尝试凭值去另一棵树中搜索，丢失结构对应关系。
  • 递归左右子树时没有同步移动两棵树的指针。
  • 新建一个相同值节点返回；题目要求返回克隆树中现有节点的引用。

面试追问

  • 如果有重复值？同步遍历仍然正确，因为它比较原树节点的对象身份。
  • 树深达到 10⁴，担心栈溢出？改用显式栈或同步 BFS。
  • 如果两棵树不保证完全同构？需要先定义“对应”的语义；当前算法依赖克隆关系保证同步位置存在。
  • 能否提前结束？可以，一旦找到非空答案立刻返回，避免继续扫描。
  • 如何证明答案属于 cloned？算法唯一的返回候选是与当前原树节点成对传入的克隆树节点。
