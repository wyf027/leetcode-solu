灌溉花园的
最少水龙头数目

Minimum Number of Taps to Open to Water a Garden

一座花园铺在数轴上。每个水龙头能覆盖一段不同的区间：你要决定打开哪些水龙头，让每一寸土地都被灌溉，同时打开的数量尽可能少。

  • 输出最少数量 / -1
  • 标签贪心 · 数组 · DP
  • 状态非付费题
Problem

题目描述

先理解输入与目标。算法思路被放在页面底部，默认不会展开。

在 x 轴上有一座长度为 n 的一维花园，范围是闭区间 [0, n]。花园中有 n + 1 个水龙头，分别位于整数点 0, 1, …, n。

长度为 n + 1 的数组 ranges 描述灌溉半径：打开位于 i 的水龙头后，它能灌溉区间 [i − ranges[i], i + ranges[i]]。区间超出花园的部分不影响结果。

返回覆盖整座花园所需打开的最少水龙头数；若无法完整覆盖 [0, n]，返回 -1。

示例 1

输入n = 5, ranges = [3,4,1,1,0,0]
输出1
解释点 1 的水龙头覆盖 [-3, 5]，单独打开它即可覆盖整座花园。

示例 2

输入n = 3, ranges = [0,0,0,0]
输出-1
解释所有水龙头都只能覆盖单点，无法覆盖点与点之间的花园。

约束

  • 1 ≤ n ≤ 10⁴
  • ranges.length = n + 1
  • 0 ≤ ranges[i] ≤ 100

Solution

准备好揭晓最优策略了吗？

题解包含贪心模型、正确性证明、复杂度、替代方案、四种语言代码和面试追问。

核心洞察：把水龙头变成“最远跳跃”

水龙头 i 对应区间 [max(0, i-ranges[i]), min(n, i+ranges[i])]。对每个左端点 left，只保留能到达的最大右端点。问题就变成：从 0 出发，每次在当前可达范围内选择能把下一段推得最远的区间，最少几次到达 n。

完整过程

  1. 建立长度为 n + 1 的数组 maxReach。遍历所有水龙头，把对应区间的右端点记录到它的左端点上，并取最大值。
  2. 维护 currentEnd（当前已选择水龙头能保证覆盖到的位置）与 farthest（扫描过的左端点中，候选区间最远能到的位置）。
  3. 从 0 扫描到 n − 1，不断用 maxReach[i] 更新 farthest。当 i == currentEnd 时，说明旧选择已经走到尽头，必须开启一个候选水龙头。
  4. 若此时 farthest ≤ i，任何已见区间都跨不过当前位置，存在覆盖缺口，返回 −1；否则计数加一，并令 currentEnd = farthest。
  5. 当 currentEnd ≥ n，整座花园已经覆盖，返回计数。

为什么正确

覆盖连续

只有左端点不超过当前确认边界的区间才可无缝接上；扫描到边界前收集这些候选，始终不会跳过合法选择。

局部最优可交换

在必须新增水龙头时，选择右端点最远者。任何最优方案此时选的区间都不会到得更远，把它替换为当前候选不会增加数量，也不会破坏覆盖。

最少次数

每次加一都发生在旧覆盖无法继续时，因此任何方案都至少需要再开一个；而我们的选择把下一边界推到最远。逐段归纳后，最终计数最小。

边界情况

  • 所有半径为 0：当 n ≥ 1 时无法覆盖连续区间，应返回 −1。
  • 某个区间越过 0 或 n：裁剪到花园边界即可，不改变覆盖能力。
  • 多个水龙头拥有相同左端点：只需保留最远右端点。
  • 到达 n 后立即结束；无需在位置 n 再触发一次计数。

复杂度

时间
O(n)：建立最远端点并线性扫描。
空间
O(n)：存储每个左端点的最远右端点。

替代方案

排序区间 + 贪心：先生成所有区间并按左端点排序，再从当前边界内选最远右端点，时间复杂度 O(n log n)。思路直观，但没有利用端点都是有限整数这一条件。

动态规划：令 dp[x] 表示覆盖到 x 的最少水龙头数，再用区间转移。通常达到 O(n²)，容易写对但无法充分利用本题规模。

class Solution {
    public int minTaps(int n, int[] ranges) {
        int[] maxReach = new int[n + 1];
        for (int i = 0; i <= n; i++) {
            int left = Math.max(0, i - ranges[i]);
            int right = Math.min(n, i + ranges[i]);
            maxReach[left] = Math.max(maxReach[left], right);
        }

        int taps = 0;
        int currentEnd = 0;
        int farthest = 0;
        for (int i = 0; i < n; i++) {
            farthest = Math.max(farthest, maxReach[i]);
            if (i == currentEnd) {
                if (farthest <= i) return -1;
                taps++;
                currentEnd = farthest;
                if (currentEnd >= n) return taps;
            }
        }
        return currentEnd >= n ? taps : -1;
    }
}

class Solution:
    def minTaps(self, n: int, ranges: List[int]) -> int:
        max_reach = [0] * (n + 1)
        for i, radius in enumerate(ranges):
            left = max(0, i - radius)
            right = min(n, i + radius)
            max_reach[left] = max(max_reach[left], right)

        taps = 0
        current_end = 0
        farthest = 0
        for i in range(n):
            farthest = max(farthest, max_reach[i])
            if i == current_end:
                if farthest <= i:
                    return -1
                taps += 1
                current_end = farthest
                if current_end >= n:
                    return taps
        return taps if current_end >= n else -1

面试追问

如何把空间降到 O(1)？

若不允许改动输入并仍要 O(n)，通常做不到直接按左端点聚合；可以原地复用 ranges 存聚合结果，但会破坏输入。排序区间则需要额外结构或原地重排。

它与 Jump Game II 有什么关系？

maxReach[i] 相当于站在位置 i 能跳到的最远点；每次走到当前层边界就增加一步，并把下一层边界更新为已见最远点。

为什么扫描到 n − 1？

目标是覆盖到 n，而不是从 n 再向外扩展。若扫描 n 并在边界处计数，可能多开一个无用水龙头。

若水龙头有不同成本呢？

“数量最少”的交换论证不再成立，可转为带权区间覆盖，考虑最短路或动态规划，状态与转移需按成本设计。

常见错误

  • 只记录以 i 为中心的右端点，却没有把区间映射到真正的左端点。
  • 在每个位置都给 taps 加一，而不是只在走到 currentEnd 时提交一次选择。
  • 缺口判断写成 farthest < i；当两者相等时同样无法覆盖 i 右侧，应使用 farthest ≤ i。
  • 循环跑到 n 并再次触发边界更新，导致答案多 1。
  • 使用未经裁剪的端点绘图或索引，造成越界。
