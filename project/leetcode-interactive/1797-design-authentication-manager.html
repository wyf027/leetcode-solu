MEDIUM1797 / Design Authentication Manager

设计一个验证系统

生成、续期、失效。先沿时间轴观察验证码的生命周期，再展开实现思路。

01 / 任务说明

实现一个验证码管理器。每个新验证码从生成时刻起有效 timeToLive 秒；只有仍有效的验证码可以续期，续期后的过期时刻以本次操作的时间为起点重新计算。

  • AuthenticationManager(int timeToLive)：构造对象并固定有效时长。
  • void generate(string tokenId, int currentTime)：在指定时刻创建新验证码。
  • void renew(string tokenId, int currentTime)：给仍有效的验证码续期；不存在或已过期时忽略请求。
  • int countUnexpiredTokens(int currentTime)：返回该时刻未过期的验证码数量。

同一时刻，过期先于续期或计数发生。例如在 7 秒过期的验证码，在第 7 秒就已经无效。

约束

  • 1 ≤ timeToLive ≤ 10⁸，1 ≤ currentTime ≤ 10⁸。
  • 1 ≤ tokenId.length ≤ 5，字符仅为小写英文字母。
  • 每次 generate 使用的 tokenId 在所有 generate 调用中唯一。
  • 所有方法调用的 currentTime 严格递增。
  • 所有函数的调用总次数不超过 2000。

官方示例 1 · 完整输入

["AuthenticationManager", "renew", "generate", "countUnexpiredTokens", "generate", "renew", "renew", "countUnexpiredTokens"]
[[5], ["aaa", 1], ["aaa", 2], [6], ["bbb", 7], ["aaa", 8], ["bbb", 10], [15]]

期望输出：

[null, null, null, 1, null, null, null, 0]

构造后，第一次续期因 aaa 不存在而被忽略。aaa 在 2 秒生成，于 7 秒过期，因此 6 秒计数为 1。bbb 在 7 秒生成；8 秒不能再续期 aaa；10 秒成功续期 bbb 至 15 秒。15 秒计数为 0。null 表示构造或无返回值的方法。

04 / 独立题解

先思考：系统需要记住什么，才能在任意后续时刻判断验证码是否有效？

核心洞察 · 保存绝对过期时刻

用哈希表保存 tokenId → expireTime，无需逐秒倒计时。验证码有效的唯一判据是 expireTime > currentTime。总调用数仅 2000，计数时扫描整个表足够简单。

完整过程

  1. 构造时保存 TTL，创建空表。
  2. generate：写入 currentTime + TTL。
  3. renew：先查找；只有存在且旧到期时间严格大于当前时间，才覆盖为 currentTime + TTL。
  4. count：遍历所有过期时间，累加严格大于当前时间的条目。这里保留过期条目，每次查询根据时间判断。

示例中的表从空开始，写入 aaa→7；6 秒扫描得到 1；再写入 bbb→12；8 秒不能更新 aaa；10 秒将 bbb→15；15 秒两个条目都不满足严格大于，返回 0。

正确性证明

不变量：对每个已经生成的 token，表里保存最近一次合法生成或续期确定的到期时刻。初始空表满足不变量。generate 按定义写入到期时刻；renew 在 token 有效时写入新的正确时刻，无效时不改变表，所以每次操作都保持不变量。计数遍历每个唯一 token，并且仅当其到期时刻大于查询时间时计入，恰好覆盖全部有效 token 且没有重复，因此返回值正确。

边界与常见错误

  • 把 > 写成 >= 会让到期瞬间的 token 仍然有效。
  • 不存在或过期的 token 不可被 renew 复活。
  • 续期是 当前时间 + TTL，不是旧过期时间再加 TTL。
  • 保留了过期记录时，不能直接返回哈希表大小。
  • TTL 为 1 时，下一秒即过期。过期时间最大为 2×10⁸，四份代码所用整数表示均足够。
  • 不必检查重复 generate 或逆序时间：题目已保证唯一 ID 与时间严格递增。

复杂度

令 G 为已生成的 token 数。generate 和 renew 的哈希操作平均 O(1)；count 为 O(G)；空间 O(G)。若有 Q 次调用，总体最坏 O(Q²)，这里 Q ≤ 2000。哈希操作的 O(1) 是平均复杂度，极端碰撞时可能退化。

替代方案

需要更快计数时，可以用哈希表加按到期时间排序的队列：时间严格递增且 TTL 固定，所有成功生成和续期的新到期时刻也严格递增。队列存 (tokenId, 到期时刻)，每次先弹出已到期项，只有该项仍等于表中的最新时刻才删除表项，避免旧续期记录误删新记录。计数取清理后的表大小，总操作可做到均摊 O(1)，队列空间 O(Q)。若时间或 TTL 不满足这种单调性，应考虑最小堆，更新 O(log Q)。哈希表加双向链表也可移除旧节点并将续期节点移到尾部，维持有序有效列表。

面试追问

  • 为何队列旧记录需要校验？同一个 token 续期后，早先的到期事件已经失效。
  • 过期条目一定要即时删除吗？无需即时删除，只要所有读写按到期条件过滤；大规模服务应考虑回收策略。
  • 能用于真实身份验证吗？此题仅模拟生命周期；实际系统还涉及不可预测的 token、可信时钟、并发原子性和持久化。

Java

import java.util.HashMap;
import java.util.Map;

class AuthenticationManager {
    private final int ttl;
    private final Map<String, Integer> expires = new HashMap<>();

    public AuthenticationManager(int timeToLive) {
        ttl = timeToLive;
    }

    public void generate(String tokenId, int currentTime) {
        expires.put(tokenId, currentTime + ttl);
    }

    public void renew(String tokenId, int currentTime) {
        Integer end = expires.get(tokenId);
        if (end != null && end > currentTime) {
            expires.put(tokenId, currentTime + ttl);
        }
    }

    public int countUnexpiredTokens(int currentTime) {
        // ponytail: O(G) scan for at most 2000 calls; use an expiry queue at scale.
        int count = 0;
        for (int end : expires.values()) {
            if (end > currentTime) count++;
        }
        return count;
    }
}

class AuthenticationManager:
    def __init__(self, timeToLive: int):
        self.ttl = timeToLive
        self.expires = {}

    def generate(self, tokenId: str, currentTime: int) -> None:
        self.expires[tokenId] = currentTime + self.ttl

    def renew(self, tokenId: str, currentTime: int) -> None:
        if self.expires.get(tokenId, 0) > currentTime:
            self.expires[tokenId] = currentTime + self.ttl

    def countUnexpiredTokens(self, currentTime: int) -> int:
        # ponytail: O(G) scan for at most 2000 calls; use an expiry queue at scale.
        return sum(end > currentTime for end in self.expires.values())

C++

#include <string>
#include <unordered_map>
using namespace std;

class AuthenticationManager {
    int ttl;
    unordered_map<string, int> expires;
public:
    AuthenticationManager(int timeToLive) : ttl(timeToLive) {}

    void generate(string tokenId, int currentTime) {
        expires[tokenId] = currentTime + ttl;
    }

    void renew(string tokenId, int currentTime) {
        auto it = expires.find(tokenId);
        if (it != expires.end() && it->second > currentTime) {
            it->second = currentTime + ttl;
        }
    }

    int countUnexpiredTokens(int currentTime) {
        // ponytail: O(G) scan for at most 2000 calls; use an expiry queue at scale.
        int count = 0;
        for (const auto& entry : expires) {
            if (entry.second > currentTime) ++count;
        }
        return count;
    }
};
