分数验证器

按出现顺序处理记分事件；数字事件增加得分，W 只让计数器加一，WD 与 NB 各加一分。当计数器到达 10，余下事件不再处理。

这是单状态机模拟：每一步只更新 score、counter，并及时检查停止条件。

题意速览

输入 events 中只可能是 0,1,2,3,4,6,W,WD,NB。

返回 [score, counter]。

约束：1 ≤ events.length ≤ 1000。

交互分步可视化

预置示例：events = ["1","4","W","6","WD"]。使用按钮或键盘 ←/→ 逐步移动。

    准备从第一个事件开始。

    规则对照

    • 数字字符串：数值加入 score。
    • W：只令 counter += 1。
    • WD、NB：各让得分加 1。
    • 一旦 counter === 10，立即停止扫描。
    空格展示约定：若输入字符串含空格，页面会显示 ␠；本题合法事件本身不含空格。

    测试与验证

    每张卡保留输入、期望、实际和状态字段；快速生成模式不将未执行的验证表述为结果。

    快速生成模式：UI、算法对拍、四语言编译和交互验收待补

    题解：一次扫描的有限状态机

    事件的含义互不依赖历史，唯一会截断后缀的状态是 counter。因此从左到右扫描；先按事件类别更新，再在每轮末尾检测计数器是否达到 10。

    完整过程

    1. 初始化 score = 0、counter = 0。
    2. 读取当前事件：W 增加计数器；WD/NB 增加一分；其余合法字符串转换为数字相加。
    3. 若计数器为 10，退出循环；最后返回二元数组。

    边界与复杂度

    全是加分事件时计数器保持 0；第十个 W 后的事件必须忽略。时间复杂度 O(n)，额外空间 O(1)。

    替代方案与面试追问

    可以先切出第十个 W 之前的前缀再统计，但会增加一次扫描且更容易产生边界错误。追问：若事件规则动态配置，可用映射表保存增量与是否改变计数器；若需回放，则记录每步快照。

    常见错误

    • 把 WD 当作数字解析。
    • 到达第十个 W 后仍处理本轮之后的事件。
    • 把停止检查放在循环开始处，导致第十个 W 未被计入。
