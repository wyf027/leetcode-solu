最多奖品

数轴上的奖品允许重叠摆放。你有两段长度固定的线段——如何摆放，才能把奖品尽可能多地收入囊中？

01 / Problem

先把规则钉在数轴上

同一坐标可以放多件奖品，端点上的奖品也算；两条线段甚至可以互相重叠。

题意转述

给定按非递减顺序排列的整数数组 prizePositions，其中每一项代表一件奖品在 X 轴上的坐标。重复坐标代表同一位置有多件奖品。

选择两个端点均为整数、长度恰好为 k 的闭区间。落在至少一个区间内的奖品都会被收集，重复覆盖只计一次。返回最优摆放时可收集的最多奖品数。

判定细节

  • 线段为闭区间，左右端点都计入。
  • 长度是坐标差 right − left = k。
  • 两段允许相交，但奖品不会重复计数。
  • k = 0 时，每段只能覆盖一个坐标。

Official example 01

输入prizePositions = [1,1,2,2,3,3,5], k = 2
输出7

可选区间 [1, 3] 与 [3, 5]，全部 7 件奖品都能收入。

Official example 02

输入prizePositions = [1,2,3,4], k = 0
输出2

例如选择 [3, 3] 与 [4, 4]，两条零长度线段各取得一件奖品。

约束

  • 1 ≤ prizePositions.length ≤ 105
  • 1 ≤ prizePositions[i] ≤ 109
  • 0 ≤ k ≤ 109
  • prizePositions 按非递减顺序排列

05 / Solution

准备好，再揭开完整题解

核心推导、证明与四种语言实现均收在独立区域中。

建议先在上方交互实验里走完一轮，再对照推导。

Core insight

滑动窗口统计当前段，前缀最优拼接另一段

排序后，一条线段覆盖的奖品必然对应数组中的连续区间。枚举当前区间的右端点，用单调左指针找到能被长度 k 覆盖的最长窗口；再把窗口左侧互不重复的最佳单段成绩接上。

current = right − left + 1
answer = max(answer, current + best[left])
best[right + 1] = max(best[right], current)
时间 O(n)空间 O(n)

完整过程

  1. 令 left = 0，从左到右枚举 right。
  2. 若两端坐标差大于 k，持续右移 left，直到窗口可以被一条线段覆盖。
  3. 窗口奖品数为 right - left + 1。
  4. best[t] 表示前 t 件奖品中，一条线段最多能拿多少。用 best[left] 与当前窗口拼接，两部分下标不相交。
  5. 更新总答案与 best[right + 1]，继续向右。

边界处理

  • k = 0：窗口可包含所有坐标相同的奖品。
  • 重复坐标：数组下标仍对应独立奖品，窗口长度自然计数。
  • 只有一件奖品：当前窗口贡献 1，另一条线段无需新增奖品。
  • 坐标很大：算法只比较坐标差，不建立坐标值大小的数组。
  • 两条线段相交：重叠奖品不应重复计数；按下标分界统计仍能覆盖最优并集。

正确性说明

窗口最优性：处理任意 right 后，left 是满足 prizePositions[right] - prizePositions[left] ≤ k 的最小下标。因此 [left, right] 是所有以 right 为最右奖品的可覆盖窗口中，奖品数最多的一个。

前缀不变式：处理完下标 right 后，best[right + 1] 等于前 right + 1 件奖品里单条线段能取得的最大数量。这由“沿用旧最优”与“采用当前窗口”二者取最大得到。

组合完备性：把任意两条最优线段取得的奖品按数组顺序分给左段与右段，分界点之前的贡献不超过对应的 best[left]，分界点之后的贡献不超过某次枚举到的当前窗口。算法检查每个右端点及其分界，故不会小于最优值；每次候选又来自两个下标不相交、实际可覆盖的窗口，故不会大于最优值。两边合并，返回值恰为最优答案。

class Solution {
    public int maximizeWin(int[] prizePositions, int k) {
        int n = prizePositions.length;
        int[] best = new int[n + 1];
        int answer = 0;
        int left = 0;

        for (int right = 0; right < n; right++) {
            while (prizePositions[right] - prizePositions[left] > k) {
                left++;
            }
            int current = right - left + 1;
            answer = Math.max(answer, current + best[left]);
            best[right + 1] = Math.max(best[right], current);
        }
        return answer;
    }
}

替代方案与面试追问

  • 二分 + 前缀最优：对每个左端点二分最远右端点，可做到 O(n log n)，思路直观但不如双指针紧凑。
  • 若改成 m 条线段？可考虑以线段数量为维度的动态规划，复用每个窗口的前驱边界。
  • 若坐标未排序？先排序，整体复杂度变为 O(n log n)。
  • 能否 O(1) 额外空间？本题拼接需要查询多个前缀状态；压缩空间会失去这些历史信息。

常见错误

  • 把长度 k 错当成可覆盖 k 个整数；闭区间 [x, x+k] 的坐标跨度才是 k。
  • 去重坐标，导致同一位置的多件奖品只计一次。
  • 直接相加两个可能重叠的窗口，重复统计交集奖品。
  • 用 best[left - 1] 造成下标语义错位；这里 best[left] 表示前 left 件。
  • 窗口超长时只移动一次左指针，而不是持续移动到合法。
