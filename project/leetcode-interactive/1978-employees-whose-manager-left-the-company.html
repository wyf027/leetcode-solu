上级经理已离职的公司员工

Employees Whose Manager Left the Company

一张员工表，一条仍然保留的汇报关系。谁的上级已不在公司？

01 / 任务说明

给定员工表 Employees，找出薪水严格小于 30000、且上级经理已离职的员工编号。经理离职后，他自己的记录会从员工表中移除，但下属的 manager_id 仍保留原来的编号。结果仅含 employee_id，按编号升序返回。

字段类型含义
employee_idint员工编号，SQL 主键
namevarchar员工姓名
manager_idint直属经理编号，可为 NULL
salaryint薪水

约束：employee_id 唯一且非空；manager_id 为 NULL 表示没有上级，不表示上级离职。元数据建表签名使用 VARCHAR(20)。官方未给出行数、编号或薪资范围，也未额外声明 salary 非空；SQL 中 NULL 薪资不满足“小于 30000”。

05 / 独立题解

准备好后再展开思路、证明和代码。

核心洞察：引用仍在，目标记录不在

“经理离职”是反连接：员工确实有经理编号，但这个编号在完整 Employees 的主键集合中不存在。经理是否高薪、是否有自己的经理，都不影响他仍然在职这一事实。

  1. 遍历员工 e，只考虑 e.salary < 30000 的记录。
  2. 要求 e.manager_id IS NOT NULL，排除没有上级的员工。
  3. 在完整表中寻找 m.employee_id = e.manager_id；不存在匹配时保留 e。
  4. 输出 e.employee_id，按升序排序。

官方可提交主解 · SQL

下列查询使用通用 SQL 语法，适用于官方列出的 MySQL、PostgreSQL、MS SQL Server 和 Oracle。未实际提交。

SELECT e.employee_id
FROM Employees e
WHERE e.salary < 30000
  AND e.manager_id IS NOT NULL
  AND NOT EXISTS (
      SELECT 1
      FROM Employees m
      WHERE m.employee_id = e.manager_id
  )
ORDER BY e.employee_id ASC;

正确性

可靠性：每条输出记录都通过三个条件，因此薪水低于 30000、有上级编号且该编号没有对应在职员工，恰好满足题意。

完备性：任意符合题意的员工，薪资条件成立、经理编号非空、经理记录已删除；对应子查询无行，NOT EXISTS 成立，所以一定被选中。主键保证员工不重复，ORDER BY 保证升序。

边界与常见错误

  • 30000 不满足严格小于，不能写成 <=。
  • NOT EXISTS 对 NULL 经理也会成立，必须显式排除 NULL 经理。
  • 查经理时必须用完整表，不能只在低薪员工子集中查；高薪经理也仍在职。
  • 只检查直属经理，不沿管理链递归。经理的经理离职，不代表直属经理离职。
  • 空表或全不满足时，返回空结果表；不要返回一行 NULL。
  • 不依赖输入顺序；即使样例只有一个结果，也不能省略 ORDER BY。
  • SQL 中 NULL 薪资的比较结果为 UNKNOWN，WHERE 不保留该行。

复杂度

令 n 为员工数，k 为结果数。SQL 的具体成本取决于执行计划：B-tree 主键逐行查找常见约 O(n log n)，再加 O(k log k) 排序；哈希反连接可约 O(n + k log k) 时间、O(n + k) 额外空间。无索引的逐行嵌套扫描可能退化到 O(n²)。数据库也可能利用索引顺序省去显式排序，不能把所有 SQL 计划视为同一复杂度。

下方四语言参考用哈希集合：平均 O(n + k log k) 时间，O(n + k) 额外空间；集合查询的平均 O(1) 为通常假设。

替代方案

LEFT JOIN 后筛选右侧主键为空，也能表达反连接：

SELECT e.employee_id
FROM Employees e
LEFT JOIN Employees m ON m.employee_id = e.manager_id
WHERE e.salary < 30000
  AND e.manager_id IS NOT NULL
  AND m.employee_id IS NULL
ORDER BY e.employee_id;

manager_id NOT IN (SELECT employee_id FROM Employees) 在这里也可用，因为 employee_id 是非空主键；若换成可能包含 NULL 的列，NOT IN 的三值逻辑会导致意外过滤。NOT EXISTS 的语义更直接。

官方可提交补充 · Pandas

import pandas as pd

def find_employees(employees: pd.DataFrame) -> pd.DataFrame:
    mask = (
        employees["salary"].lt(30000)
        & employees["manager_id"].notna()
        & ~employees["manager_id"].isin(employees["employee_id"])
    ).fillna(False)
    return (employees.loc[mask, ["employee_id"]]
            .sort_values("employee_id"))

Java

import java.util.*;

public class Main {
    static class Employee {
        int id;
        String name;
        Integer managerId, salary;
        Employee(int id, String name, Integer managerId, Integer salary) {
            this.id = id;
            this.name = name;
            this.managerId = managerId;
            this.salary = salary;
        }
    }
    static List<Integer> findEmployees(List<Employee> employees) {
        Set<Integer> ids = new HashSet<>();
        for (Employee e : employees) ids.add(e.id);
        List<Integer> result = new ArrayList<>();
        for (Employee e : employees) {
            if (e.salary != null && e.salary < 30000
                    && e.managerId != null && !ids.contains(e.managerId)) {
                result.add(e.id);
            }
        }
        Collections.sort(result);
        return result;
    }
    public static void main(String[] args) {
        List<Employee> employees = Arrays.asList(
            new Employee(3, "Mila", 9, 60301),
            new Employee(12, "Antonella", null, 31000),
            new Employee(13, "Emery", null, 67084),
            new Employee(1, "Kalel", 11, 21241),
            new Employee(9, "Mikaela", null, 50937),
            new Employee(11, "Joziah", 6, 28485)
        );
        System.out.println(findEmployees(employees));
    }
}

// Each row: [employee_id, name, manager_id, salary].
function findEmployees(employees) {
    const ids = new Set(employees.map(row => row[0]));
    return employees
        .filter(([, , manager, salary]) =>
            salary != null && salary < 30000 &&
            manager != null && !ids.has(manager))
        .map(row => row[0])
        .sort((a, b) => a - b);
}

def find_employees(employees):
    ids = {row[0] for row in employees}
    return sorted(
        employee_id
        for employee_id, name, manager_id, salary in employees
        if salary is not None and salary < 30000
        and manager_id is not None and manager_id not in ids
    )

#include <algorithm>

struct Employee {
    int id;
    string name;
    optional<int> managerId, salary;
};
vector<int> findEmployees(const vector<Employee>& employees) {
    unordered_set<int> ids;
    for (const auto& e : employees) ids.insert(e.id);
    vector<int> result;
    for (const auto& e : employees) {
        if (e.salary && *e.salary < 30000 && e.managerId
                && !ids.count(*e.managerId)) {
            result.push_back(e.id);
        }
    }
    sort(result.begin(), result.end());
    return result;
}

面试追问

  • 外键能阻止这种数据吗？启用强制外键且限制删除时，可能无法产生悬空引用；本题明确允许经理行删除而引用保留，要遵循这一数据模型。
  • 改成软删除怎么办？经理是否存在应改成经理是否处于在职状态，并按需求过滤员工自身状态。
  • 怎样优化大表？利用 employee_id 主键索引，结合执行计划比较索引查找与哈希反连接；salary 索引是否合算取决于选择性。
  • 需要查整个管理链吗？当前题目不需要；若变成任一祖先经理离职，需要递归查询并处理循环引用。
