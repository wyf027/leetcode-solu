函数：longestPrefix(s)

快乐前缀是一个非空字符串：它既是 s 的前缀，也是 s 的后缀，但不能等于 s 本身。

Full Solution

KMP 前缀函数：一次扫描保留所有有效线索

核心洞察：整串的最长快乐前缀，恰好就是前缀函数最后一项 π[n - 1] 所表示的边界。失配时沿回退链跳到次长、仍有希望的边界，避免重新比较。

完整过程

  1. 建立长度为 n 的数组 pi，初始为 0。
  2. 从 i = 1 开始，令 j = pi[i - 1]。
  3. 当 s[i] != s[j] 且 j > 0，令 j = pi[j - 1] 持续回退。
  4. 若最终 s[i] == s[j]，令 j++；记录 pi[i] = j。
  5. 返回 s[0..pi[n-1])。

边界情况

  • 长度为 1：返回空字符串。
  • 所有字符相同：答案长度是 n - 1。
  • 没有公共首尾：最后一项为 0。
  • 前后缀可以重叠，如 "aaaa" 的答案是 "aaa"。

正确性说明

  1. 循环含义：处理位置 i 后，pi[i] 是 s[0..i] 的最长相等真前缀与后缀长度。
  2. 回退不会漏解：长度 j 无法延长时，仍可能成功的候选必然也是这个长度 j 前缀的边界，其中最长者正是 pi[j - 1]。
  3. 扩展保持最优：遇到 s[i] == s[j] 时已有边界延长一位；更长候选已依序失败，因此新长度最长。
  4. 结论：循环结束时 pi[n - 1] 是整串最长真边界的长度，截取它就是最长快乐前缀。

复杂度

时间：O(n)；指针前进和沿边界链回退的总量为线性级别。

空间：O(n)，用于前缀函数数组。

替代方案

双滚动哈希可在期望 O(n) 时间、O(1) 额外空间内比较首尾哈希，但存在碰撞风险。双哈希可降低风险；KMP 则是确定性方案。

class Solution {
    public String longestPrefix(String s) {
        int n = s.length();
        int[] pi = new int[n];
        for (int i = 1; i < n; i++) {
            int j = pi[i - 1];
            while (j > 0 && s.charAt(i) != s.charAt(j)) {
                j = pi[j - 1];
            }
            if (s.charAt(i) == s.charAt(j)) j++;
            pi[i] = j;
        }
        return s.substring(0, pi[n - 1]);
    }
}

常见错误

  • 把整个字符串当作快乐前缀。
  • 失配时直接把 j 清零，漏掉较短边界。
  • 只回退一次，而不是持续回退。
  • 返回长度，而不是对应字符串。
  • 误以为前缀和后缀不能重叠。

面试追问

为什么不是 O(n²)？

每次回退都让 j 严格变小，结合 i 只前进不后退，可用势能分析证明总比较次数为 O(n)。

如何得到所有快乐前缀？

从 k = pi[n-1] 开始，反复令 k = pi[k-1] 直到 0，链上每个 k 都是一个答案长度。

能否 O(1) 额外空间？

滚动哈希可以做到，但通常只有概率正确性；确定性线性方案使用前缀函数数组。
