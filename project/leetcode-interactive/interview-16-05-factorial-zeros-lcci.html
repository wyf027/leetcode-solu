题意

给定一个非负整数 n，计算 n! 的十进制表示末尾连续有多少个零。题目要求算法达到 O(log n) 时间复杂度；不需要、也不应该真的构造阶乘。

官方示例

输入n = 3
输出0
说明3! = 6
输入n = 5
输出1
说明5! = 120

核心洞察

每个尾随零需要一对 2 × 5。在阶乘中，偶数提供的因子 2 远多于因子 5，因此答案只取决于 n! 中因子 5 的总数量。

⌊n / 5⌋ + ⌊n / 25⌋ + ⌊n / 125⌋ + …

为什么要重复除以 5

⌊n/5⌋ 先给每个 5 的倍数记一份；25 的倍数还藏着第二个 5，于是再由 ⌊n/25⌋ 补记。125 的倍数同理继续补记，直到商变成 0。

完整过程：n = 125

  1. 第一层：125 / 5 = 25，累计 25。
  2. 第二层：25 / 5 = 5，补记 25 的倍数，累计 30。
  3. 第三层：5 / 5 = 1，补记 125 自身的第三个 5，累计 31。
  4. 下一次商为 0，结束；125! 有 31 个尾随零。

正确性说明

第 k 层统计能被 5^k 整除的整数数量，因此为每个至少包含 k 个因子 5 的数补记一次。每个整数含有的全部因子 5 恰好在对应层各记一次，没有遗漏或重复。

复杂度

时间：O(log₅ n)，每轮把当前值除以 5。

空间：O(1)，只维护当前商与累计答案。

边界

  • n < 5：第一次除法即为 0，答案为 0。
  • n = 5^k：必须进入第 k 层，不能只数 5 的倍数。
  • 循环写成先除再加，可避免不断计算 5^k 时的乘法溢出。

替代方案

从 1 扫到 n，并对每个数反复拆出因子 5，能够得到正确答案，但最坏需要线性级遍历，不满足题目要求。直接计算 n! 则会迅速溢出，且做了大量无关工作。

面试追问

  • 若问末尾有多少个 0（以其他进制 b 表示），如何分解 b 并统计各质因子指数？
  • 为何统计 2 与 5 时可以直接忽略 2？如何形式化说明？
  • 若输入改为 64 位整数，代码需要修改哪些类型？

常见错误

  • 只返回 n / 5，漏掉 25、125 等额外因子。
  • 真的计算阶乘后数零，导致溢出和高复杂度。
  • 用 power *= 5 控制循环，却没防止 power 溢出。
  • 把循环条件写成 n > 5，漏掉恰好等于 5 的情况。

class Solution {
    public int trailingZeroes(int n) {
        int answer = 0;
        while (n > 0) {
            n /= 5;
            answer += n;
        }
        return answer;
    }
}

var trailingZeroes = function (n) {
    let answer = 0;
    while (n > 0) {
        n = Math.floor(n / 5);
        answer += n;
    }
    return answer;
};
