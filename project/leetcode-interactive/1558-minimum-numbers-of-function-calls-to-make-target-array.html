MEDIUM 数组 贪心 位运算

得到目标数组的最少函数调用次数

Minimum Numbers of Function Calls to Make Target Array

从全零数组出发，每次只能执行一次“给某个元素加一”或“把所有元素翻倍”。目标是用尽可能少的调用得到指定数组。

题目描述

先理解可用操作与目标，不在首屏直接展开解法。

初始数组 arr 与 nums 等长，且所有值均为 0。一次函数调用可以选择以下一种操作：
  1. 选择一个下标 i，令 arr[i] += 1；
  2. 令数组中的每一个元素同时乘以 2。
返回把 arr 变为 nums 所需的最少调用次数。答案保证可放入 32 位有符号整数。

官方示例

示例 1

输入：nums = [1,5]
输出：5
解释：[0,0] → [0,1] → [0,2] → [0,4] → [1,4] → [1,5]，共 5 次。

示例 2

输入：nums = [2,2]
输出：3
解释：[0,0] → [0,1] → [1,1] → [2,2]，共 3 次。

示例 3

输入：nums = [4,2,5]
输出：6
解释：[0,0,0] → [1,0,0] → [1,0,1] → [2,0,2]
     → [2,1,2] → [4,2,4] → [4,2,5]。

示例 4

输入：nums = [3,2,2,4]
输出：7

示例 5

输入：nums = [2,4,8,16]
输出：8

约束

  • 1 <= nums.length <= 10^5
  • 0 <= nums[i] <= 10^9

Solution

位计数 + 最高位深度

O(n log V)

核心洞察

倒着看操作更清楚：奇数的最后一步必然来自一次单点加一，所以需要把它减一；当所有数都是偶数时，一次整体除二恰好撤销一次整体翻倍。每个二进制 1 都对应一次单点加一，而最高数的二进制位数减一，就是所有数共享的翻倍次数。

答案 = Σ popcount(nums[i]) + floor(log₂(max(nums)))　（max(nums) = 0 时后半项为 0）

完整过程

1
统计每个数的 1 位。
对每个 x，不断检查最低位并右移；所有 1 的总数就是单点加一的最少次数。
2
记录最长二进制长度。
若最大值需要 L 位表示，从最高位构造到最低位只需 L - 1 次整体翻倍。
3
两部分相加。
翻倍由整个数组共享，不能按元素重复计算，因此只取最大位深。

正确性证明

下界：每次单点加一只可能为一个元素贡献一个新的二进制 1，因此至少需要所有元素的 popcount 之和次。若最大值有 L 位，从 0 构造出最高位后，至少还需 L-1 次翻倍把它移到目标位。

可达：按二进制从高位到低位构造。除最高位轮外，每轮先整体翻倍，再对当前位为 1 的元素各加一。共使用 L-1 次翻倍和恰好 Σ popcount 次加一。

结论：构造达到上述下界，因此操作数最少。

边界与复杂度

  • 全零数组：没有加一和翻倍，答案为 0。
  • 只有 0/1：最长位深为 0，只需为每个 1 加一次。
  • 2 的幂：只有一个 1，但需要对应次数的整体翻倍。
  • 时间复杂度：O(n log V)，其中 V=max(nums)；在固定 32 位整数下也可视作 O(n)。
  • 额外空间复杂度：O(1)。

四语言完整代码

JavaLeetCode
class Solution {
    public int minOperations(int[] nums) {
        int increments = 0;
        int maxValue = 0;

        for (int value : nums) {
            increments += Integer.bitCount(value);
            maxValue = Math.max(maxValue, value);
        }

        int doubles = 0;
        while (maxValue > 1) {
            maxValue >>= 1;
            doubles++;
        }
        return increments + doubles;
    }
}

/**
 * @param {number[]} nums
 * @return {number}

var minOperations = function(nums) {
    let increments = 0;
    let maxValue = 0;

    for (const value of nums) {
        let current = value;
        maxValue = Math.max(maxValue, value);
        while (current > 0) {
            increments += current % 2;
            current = Math.floor(current / 2);
        }
    }

    let doubles = 0;
    while (maxValue > 1) {
        maxValue = Math.floor(maxValue / 2);
        doubles++;
    }
    return increments + doubles;
};

from typing import List


class Solution:
    def minOperations(self, nums: List[int]) -> int:
        increments = sum(value.bit_count() for value in nums)
        max_value = max(nums)
        doubles = max_value.bit_length() - 1 if max_value else 0
        return increments + doubles

class Solution {
public:
    int minOperations(vector<int>& nums) {
        int increments = 0;
        int maxValue = 0;

        for (int value : nums) {
            increments += __builtin_popcount(value);
            maxValue = max(maxValue, value);
        }

        int doubles = 0;
        while (maxValue > 1) {
            maxValue >>= 1;
            ++doubles;
        }
        return increments + doubles;
    }

替代方案：直接逆向模拟

复制数组并循环：遇到奇数就逐个减一；全部为偶数后整体除二；直到全零。它和可视化完全一致，容易理解，时间同为 O(n log V)，但会修改副本并反复扫描数组。

常见错误

  • 把多个元素各加一误算成一次调用；一次只能选择一个下标。
  • 为每个元素分别统计翻倍次数；整体翻倍可被所有元素共享。
  • 全零时计算 log₂(0)，导致非法或负值。
  • 正向贪心选择元素，忽略二进制结构而陷入复杂状态搜索。

面试追问

  • 如果“整体翻倍”的成本与数组长度有关呢？ 两类操作不再只是简单计数，需要比较共享操作与逐点构造的加权成本。
  • 如果允许整体乘以任意整数 k？ 二进制分解会变成基于可选乘数的因子分解或最短路问题。
  • 为何最大位长足以决定翻倍次数？ 所有较短数字可在高位轮保持 0，并从更低位开始参与，仍共享同一串翻倍。
  • 能否一趟完成？ 可以；扫描每个数时同时累计置位数并更新最大值，最后只处理最大值的位长。
