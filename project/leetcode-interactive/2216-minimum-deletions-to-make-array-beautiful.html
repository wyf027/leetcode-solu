美化数组的最少删除数

Minimum Deletions to Make Array Beautiful

删除会改变下标。哪些元素应该留下，才能用最少的删除得到符合规则的数组？

01 / 题目

给定从 0 开始编号的整数数组 nums。你可以删除其中任意元素；每次删除后，右侧元素会向左补位，保留元素的相对顺序不变。请返回使最终数组成为“美丽数组”所需的最少删除次数。

美丽数组必须同时满足：

  • 长度为偶数；空数组也符合要求。
  • 对最终数组的每个偶数下标 i，都有 nums[i] != nums[i + 1]。

规则约束的是 (0, 1)、(2, 3)、(4, 5) 等位置对；不同位置对之间的相邻元素可以相等。

输入、输出与约束

  • 参数：nums: integer[]；返回值：最少删除数，类型为整数。
  • 1 ≤ nums.length ≤ 10⁵
  • 0 ≤ nums[i] ≤ 10⁵

02 / 官方示例

示例 1

输入：nums = [1,1,2,3,5]
输出：1

删除原下标 0 或 1 处的一个 1，可以得到 [1,2,3,5]。长度为 4，两个位置对分别为 (1,2)、(3,5)，都不相等。原数组长度为奇数，因此至少删除一次。

示例 2

输入：nums = [1,1,2,2,3,3]
输出：2

删除原下标 0 与 5 的元素，得到 [1,2,2,3]。中间的两个 2 位于不同位置对，不影响合法性。原数组不合法，删一个又会变成奇数长度，所以最少删除两个。

04 / 题解：尽早完成每一对

目标等价于保留尽可能多的“不相等元素对”。从左向右扫描，保留序列为空或已经有偶数个元素时，先留下当前数作为新一对的左端。等待右端时，只接受与左端不同的数；相同的数删除。扫描结束后，如果留下了一个孤立左端，再把它删除。

核心状态

kept 表示已经保留的元素数。它为奇数时，first 是等待配对的左端；它为偶数时，下一个数可以成为新左端。答案为 n - kept + kept % 2。

配对工作台

原下标轨道保留来源；下方按新下标每两格装入一组，直观看到删除如何改变配对。演示上限 60 个元素，正式算法支持题目完整规模。

输入 1–60 个 0–100000 的整数，按 Enter 或“应用数组”。

绿格：保留　红色划线：删除　白格：未处理

支持 Tab、Enter、空格；输入框支持 Enter 应用。自动播放可随时暂停，减少动态效果偏好下也不使用过渡动画。

完整过程

  1. 初始化 kept = 0，first = 0；此时 first 的值尚无意义。
  2. 若 kept 为偶数，保留当前值 x，设置 first = x，并让 kept 加一。
  3. 若 kept 为奇数且 x ≠ first，保留 x，完成一对，kept 加一。
  4. 若 kept 为奇数且 x = first，跳过 x，相当于删除它。左端继续等待。
  5. 最终 kept 若为奇数，需要删掉孤立左端；返回 n − kept + kept % 2。

以 [1,1,2,2,3,3] 为例：保留第一个 1，删除第二个 1；遇到 2 完成 (1,2)；下一个 2 开启新对，遇到 3 完成 (2,3)；最后一个 3 孤立，删除。共删 2 个，得到 [1,2,2,3]。

为什么一定最少？

合法性：每次完成一对时，两个数都不同；孤立尾部在结束时删除。因此最终序列长度为偶数，每个偶数下标与后一位都不同。

最优性（交换论证）：考虑尚未处理的后缀，设其第一个值为 a，第一次出现与 a 不同的值的位置为 t。t 之前全部是 a，故任何合法的第一对都必须在 t 或更晚结束。贪心用后缀首元素与 t 组成第一对。把任意最优方案的第一对换成这对，会让第一对结束得更早或一样早，不会影响后续对的顺序与合法性，所以仍能保留同样多的对。

然后对 t 后的后缀重复同样的论证。如果找不到 t，整个剩余后缀的值都相同，无法组成任何合法对。由此贪心保留了最多的完整对，也就删除了最少的元素。

循环不变式：已保留的前偶数个元素组成合法对；若保留数为奇数，仅最后一个元素等待配对。相同值的跳过不会破坏任何已完成的对。

边界与常见错误

  • 只有一个元素时，答案为 1；空数组是合法结果，但不是本题合法输入。
  • 全部相等时无法组成一对，必须全部删除。
  • 跨对相邻元素允许相等，例如 [1,2,2,3]。
  • 不要按原下标奇偶决定配对，应按 kept 的奇偶。
  • 不要仅返回扫描中跳过的个数，必须处理孤立尾部。
  • 值可以是 0，不能以 first 的真假判断是否有待配对元素。
  • 不必真的从数组中间删除元素，反复移动可能导致 O(n²)。

复杂度与替代方案

四份参考代码均单次遍历：时间 O(n)，额外空间 O(1)，不修改输入。

可用栈或结果数组存放保留元素：长度为偶数时入栈；为奇数且与栈顶不同时入栈；最后去掉孤立项。时间 O(n)，额外空间 O(n)，适合需要返回具体结果的情况。

可视化为支持回退，保存小规模状态快照，使用 O(m²) 时间与空间（m ≤ 60）；这不是正式提交算法的空间复杂度。

四语言参考代码

均采用官方方法名 minDeletion 与参数 nums；代码尚未编译或运行。

Java

class Solution {
    public int minDeletion(int[] nums) {
        int kept = 0, first = 0;
        for (int x : nums) {
            if (kept % 2 == 0) {
                first = x;
                kept++;
            } else if (x != first) {
                kept++;
            }
        }
        return nums.length - kept + kept % 2;
    }
}

面试追问

  • 如何返回删除的原下标？额外记录跳过项与最终孤立项的原下标；返回列表需要 O(n) 输出空间。
  • 可以流式处理吗？可以。维护总长度、kept 和 first；数据结束时处理孤立项即可。
  • 如果删除有不同代价呢？当前交换论证只保证对数最多，不能保证总代价最低；需要重新设计带权状态转移。
  • 能排序后处理吗？不能。允许的是删除，不是重排，保留元素必须遵循原顺序。
