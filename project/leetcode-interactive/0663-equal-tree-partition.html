哪一条边值得被剪断？

一棵树有很多条边，但每条边都天然对应一个完整子树。先不要展开答案，试着想清楚：要比较的两个量究竟是什么？

01 / Problem

题目说明

给定一棵非空二叉树，判断是否存在一条边：移除它之后，原树被分成两棵非空树，且两棵树的节点值之和相等。

输入与返回

输入参数 root 是二叉树根节点。你只能删除恰好一条父子边；若能得到两个节点值总和相同的连通部分，返回 true，否则返回 false。

注意：不能删除根节点上方并不存在的边，所以“整棵树本身”不能单独作为候选子树。

checkEqualTree(root: TreeNode): boolean

约束

  • 树中节点数范围为 [1, 10⁴]。
  • -10⁵ ≤ Node.val ≤ 10⁵。
  • 节点值可以为负数或零。
  • 删除后得到的两部分都必须非空。

示例 1

输入 
root = [5,10,10,null,null,2,3]
输出 
true
说明

可以删除根节点与右子节点之间的边。左侧部分节点值之和为 5 + 10 = 15，右侧部分为 10 + 2 + 3 = 15。

示例 2

输入 
root = [1,2,10,null,null,2,20]
输出 
false
说明

无论删除哪条现有边，都无法得到节点值总和相等的两个非空部分。

04 / Solution

后序遍历，寻找一半

O(n) time · O(n) space

核心洞察

删除父节点到某个非根节点的边后，其中一部分一定恰好是“以该节点为根的完整子树”。设整棵树总和为 total，该子树和为 sub，另一部分就是 total - sub。

sub = total - sub ⇔ 2 × sub = total

因此只需算出每个节点的子树和，并在除根节点外的候选中检查是否存在 2 × sub == total。

复杂度

时间 O(n)
空间 O(n)

每个节点访问一次；子树和数组最多保存 n 项，递归栈最坏也可达 n 层。

完整过程

  1. 执行后序 DFS，先递归左右孩子，再把“左子树和 + 右子树和 + 当前值”记入数组。
  2. 后序数组最后一项必然是根节点对应的整树总和 total。
  3. 只遍历数组的前 n - 1 项，从而排除根节点这个非法切分。
  4. 若某项满足 2 × sub == total，立即返回真；否则返回假。

正确性证明

  • 充分性：若算法找到非根子树和 sub 且 2 × sub = total，删除它与父节点之间的边后，两部分和分别为 sub 与 total - sub = sub，所以切分有效。
  • 必要性：若存在有效切边，边的下端节点定义了一棵非根完整子树。两部分和相等，必有 sub = total - sub，即该子树和会满足算法检查的条件。
  • 后序 DFS 精确计算了每个节点的子树和，并枚举所有非根候选，因此算法不会漏掉有效切分，也不会接受无效切分。

边界情况

  • 只有一个节点：没有边可删，必须返回 false。
  • 总和为奇数：整数子树和不可能等于总和的一半。
  • 总和为零：仍应检查是否存在非根的零和子树。
  • 负数节点：不影响等式，不能使用只适合正数的剪枝。
  • 链状树：递归深度可能达到节点数。

替代方案

可以用哈希表统计所有子树和的出现次数，再把整树总和对应的计数减一，最后查询 total / 2。这与“数组中排除最后一项”本质相同。

也可两遍 DFS：第一遍求总和，第二遍再次求子树和并检查。它省去显式数组，但时间仍为 O(n)，递归栈仍需 O(h)。

常见错误

  • 把根节点对应的整树和也当作候选，尤其会误判单节点零值树。
  • 只判断 total 是否为偶数，却忘记真的查找目标子树。
  • 使用前序遍历，在孩子的子树和尚未得到时就做判断。
  • 在固定宽度整数较小的语言里忽略求和或乘二的溢出风险。

四语言完整实现

均使用后序遍历收集子树和，并显式排除数组中的最后一项（整棵树）。

import java.util.ArrayList;
import java.util.List;

/**
 * Definition for a binary tree node.
 * public class TreeNode {
 *     int val;
 *     TreeNode left;
 *     TreeNode right;
 *     TreeNode() {}
 *     TreeNode(int val) { this.val = val; }
 *     TreeNode(int val, TreeNode left, TreeNode right) {
 *         this.val = val;
 *         this.left = left;
 *         this.right = right;
 *     }
 * }
 */
class Solution {
    private final List<Long> subtreeSums = new ArrayList<>();

    public boolean checkEqualTree(TreeNode root) {
        postorder(root);
        long total = subtreeSums.get(subtreeSums.size() - 1);

        // The last sum belongs to the root and cannot represent a cut edge.
        for (int i = 0; i + 1 < subtreeSums.size(); i++) {
            if (subtreeSums.get(i) * 2L == total) {
                return true;
            }
        }
        return false;
    }

    private long postorder(TreeNode node) {
        if (node == null) {
            return 0L;
        }

        long sum = node.val + postorder(node.left) + postorder(node.right);
        subtreeSums.add(sum);
        return sum;
    }
}
/**
 * Definition for a binary tree node.
 * function TreeNode(val, left, right) {
 *     this.val = (val === undefined ? 0 : val);
 *     this.left = (left === undefined ? null : left);
 *     this.right = (right === undefined ? null : right);
 * }
 */
/**
 * @param {TreeNode} root
 * @return {boolean}
 */
var checkEqualTree = function (root) {
    const subtreeSums = [];

    const postorder = (node) => {
        if (node === null) {
            return 0;
        }

        const sum = node.val + postorder(node.left) + postorder(node.right);
        subtreeSums.push(sum);
        return sum;
    };

    const total = postorder(root);

    // Exclude the final entry: it is the whole tree, not a removable subtree.
    for (let i = 0; i + 1 < subtreeSums.length; i += 1) {
        if (subtreeSums[i] * 2 === total) {
            return true;
        }
    }
    return false;
};
from typing import Optional

# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right
class Solution:
    def checkEqualTree(self, root: Optional[TreeNode]) -> bool:
        subtree_sums = []

        def postorder(node: Optional[TreeNode]) -> int:
            if node is None:
                return 0

            subtree_sum = (
                node.val
                + postorder(node.left)
                + postorder(node.right)
            )
            subtree_sums.append(subtree_sum)
            return subtree_sum

        total = postorder(root)

        # The last item is the root's sum, so it is not a valid cut candidate.
        return any(
            subtree_sum * 2 == total
            for subtree_sum in subtree_sums[:-1]
        )
#include <vector>
using namespace std;

/**
 * Definition for a binary tree node.
 * struct TreeNode {
 *     int val;
 *     TreeNode *left;
 *     TreeNode *right;
 *     TreeNode() : val(0), left(nullptr), right(nullptr) {}
 *     TreeNode(int x) : val(x), left(nullptr), right(nullptr) {}
 *     TreeNode(int x, TreeNode *left, TreeNode *right)
 *         : val(x), left(left), right(right) {}
 * };
 */
class Solution {
private:
    vector<long long> subtreeSums;

    long long postorder(TreeNode* node) {
        if (node == nullptr) {
            return 0LL;
        }

        long long sum = static_cast<long long>(node->val)
                      + postorder(node->left)
                      + postorder(node->right);
        subtreeSums.push_back(sum);
        return sum;
    }

public:
    bool checkEqualTree(TreeNode* root) {
        long long total = postorder(root);

        // Exclude the root sum stored at the final position.
        for (size_t i = 0; i + 1 < subtreeSums.size(); ++i) {
            if (subtreeSums[i] * 2LL == total) {
                return true;
            }
        }
        return false;
    }
};

面试追问

为什么必须使用后序遍历？

一个节点的子树和依赖左右孩子的子树和。后序遍历先完成孩子，再处理父节点，恰好满足这个依赖顺序。

能否只做一遍 DFS 且不用数组？

通常需要先知道整树总和，才能判断某个子树是否为一半。可以第一遍求总和、第二遍检查，从而不用数组；仍是线性时间。

总和为零时为什么容易写错？

整棵树本身也是一个零和“子树”，但它上方没有可删除的边。若不排除根，就会把不存在的切分误判为有效。

进一步讨论

如果要求返回被删除的边呢？

在后序遍历时同时保存每个子树和及其根节点；找到一半时，返回该节点与其父节点构成的边。

如果树非常深，递归有风险怎么办？

改用显式栈模拟后序遍历，并为每个节点保存访问状态或反向处理顺序，可避免语言调用栈溢出。

推广到多叉树是否成立？

成立。删除任意父子边仍会分离出一个完整子树，判断式保持不变；只需在求和时累加所有孩子。
