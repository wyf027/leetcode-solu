01 / 题目

先看关系，不急着写查询

基于官方表结构与示例数据准确转述；付费题官方题面未随元数据返回，因此不复刻原文。

给定顾客表 Customers、联系人表 Contacts 和发票表 Invoices。对每张发票，输出发票编号、开票顾客姓名、价格、该顾客的联系人总数，以及其中的“可信联系人”数量。

如果某位联系人的邮箱也出现在 Customers.email 中，则该联系人可信。结果按 invoice_id 升序排列；没有联系人的顾客，其两个计数都应为 0。

约束与关系

  • customer_id 与 invoice_id 分别是所属表主键，顾客邮箱互不重复。
  • 联系人和发票的 user_id 对应顾客；一个顾客可有多位联系人和多张发票。
  • 可信与否按邮箱是否存在于顾客表判断，不按姓名判断。
  • 必须保留所有发票，包括联系人数量为 0 的发票。

04 / 题解

两次左连接，一次条件聚合

以发票为结果粒度，用联系人邮箱是否命中顾客邮箱决定“可信”计数。

核心洞察

  • 从 Invoices 出发，先找到开票顾客。
  • 左连接联系人，确保零联系人发票仍被保留。
  • 再以联系人邮箱匹配顾客；命中的顾客主键非空。
  • 分别计数联系人邮箱和命中的顾客主键。

完整过程

  1. 发票内连接顾客得到姓名。
  2. 左连接联系人，展开开票顾客的联系人。
  3. 左连接顾客别名，判定联系人是否可信。
  4. 按发票字段分组并做两次计数。
  5. 按发票编号升序输出。

边界与常见错误

  • 零联系人时不能把联系人表写成内连接。
  • 不要用 COUNT(*)，否则左连接占位行会被计为 1。
  • 可信依据是邮箱，而不是姓名。
  • 同一顾客的多张发票必须分别输出。
  • 可信顾客应使用独立表别名。

复杂度与替代方案

设发票、联系人、顾客数为 I、K、C。哈希连接下时间近似 O(I + K + C)，空间与连接、聚合中间数据相关；实际取决于索引与优化器。

替代方案是先按 Contacts.user_id 聚合，再连接发票；数据量大时可减少同一顾客多张发票造成的重复展开。

正确性说明

联系人计数准确

每张发票连接到所属顾客的全部联系人，每个非空联系人邮箱恰贡献一次；无联系人时非空邮箱数为 0。

可信计数准确

顾客邮箱唯一。联系人邮箱命中时恰连接一位顾客，其主键被计一次；未命中时为 NULL，不被计入。

结论

以发票字段分组保留每张发票，两个计数分别准确，最后排序即得到所需结果。

MySQL · 官方可提交
SELECT
    i.invoice_id,
    c.customer_name,
    i.price,
    COUNT(ct.contact_email) AS contacts_cnt,
    COUNT(tc.customer_id) AS trusted_contacts_cnt
FROM Invoices AS i
JOIN Customers AS c
    ON c.customer_id = i.user_id
LEFT JOIN Contacts AS ct
    ON ct.user_id = i.user_id
LEFT JOIN Customers AS tc
    ON tc.email = ct.contact_email
GROUP BY i.invoice_id, c.customer_name, i.price
ORDER BY i.invoice_id;
Java 17 · 本地语义参考
import java.util.*;
public class TrustedContacts {
  record Customer(int id, String name, String email) {}
  record Contact(int userId, String name, String email) {}
  record Invoice(int id, int price, int userId) {}
  record Row(int invoiceId, String customerName, int price,
             int contactsCnt, long trustedContactsCnt) {}
  static List<Row> solve(List<Customer> customers,
      List<Contact> contacts, List<Invoice> invoices) {
    Map<Integer, Customer> byId = new HashMap<>();
    Set<String> emails = new HashSet<>();
    Map<Integer, List<Contact>> byUser = new HashMap<>();
    for (Customer c : customers) {
      byId.put(c.id(), c); emails.add(c.email());
    }
    for (Contact c : contacts)
      byUser.computeIfAbsent(c.userId(), k -> new ArrayList<>()).add(c);
    List<Row> answer = new ArrayList<>();
    for (Invoice in : invoices) {
      List<Contact> list = byUser.getOrDefault(in.userId(), List.of());
      long trusted = list.stream().filter(c -> emails.contains(c.email())).count();
      answer.add(new Row(in.id(), byId.get(in.userId()).name(),
          in.price(), list.size(), trusted));
    }
    answer.sort(Comparator.comparingInt(Row::invoiceId));
    return answer;
  }
}
JavaScript ES2022 · 本地语义参考
function trustedContacts(customers, contacts, invoices) {
  const byId = new Map(customers.map(c => [c.customer_id, c]));
  const emails = new Set(customers.map(c => c.email));
  const byUser = new Map();
  for (const contact of contacts) {
    if (!byUser.has(contact.user_id)) byUser.set(contact.user_id, []);
    byUser.get(contact.user_id).push(contact);
  }
  return invoices.map(invoice => {
    const list = byUser.get(invoice.user_id) ?? [];
    return {
      invoice_id: invoice.invoice_id,
      customer_name: byId.get(invoice.user_id).customer_name,
      price: invoice.price,
      contacts_cnt: list.length,
      trusted_contacts_cnt:
        list.filter(c => emails.has(c.contact_email)).length
    };
  }).sort((a, b) => a.invoice_id - b.invoice_id);
}

from collections import defaultdict
def trusted_contacts(customers, contacts, invoices):
    by_id = {c["customer_id"]: c for c in customers}
    emails = {c["email"] for c in customers}
    by_user = defaultdict(list)
    for contact in contacts:
        by_user[contact["user_id"]].append(contact)
    answer = []
    for invoice in invoices:
        people = by_user[invoice["user_id"]]
        answer.append({
            "invoice_id": invoice["invoice_id"],
            "customer_name": by_id[invoice["user_id"]]["customer_name"],
            "price": invoice["price"],
            "contacts_cnt": len(people),
            "trusted_contacts_cnt": sum(
                p["contact_email"] in emails for p in people
            ),
        })
    return sorted(answer, key=lambda row: row["invoice_id"])

#include <algorithm>
#include <string>
#include <unordered_map>
#include <unordered_set>
#include <vector>
using namespace std;
struct Customer { int id; string name, email; };
struct Contact { int userId; string name, email; };
struct Invoice { int id, price, userId; };
struct Row { int invoiceId; string customerName; int price, contacts, trusted; };
vector<Row> solve(const vector<Customer>& customers,
    const vector<Contact>& contacts, const vector<Invoice>& invoices) {
  unordered_map<int, Customer> byId;
  unordered_set<string> emails;
  unordered_map<int, vector<Contact>> byUser;
  for (const auto& c : customers) { byId.emplace(c.id, c); emails.insert(c.email); }
  for (const auto& c : contacts) byUser[c.userId].push_back(c);
  vector<Row> answer;
  for (const auto& in : invoices) {
    const auto& list = byUser[in.userId];
    int trusted = 0;
    for (const auto& c : list) trusted += emails.count(c.email) ? 1 : 0;
    answer.push_back({in.id, byId.at(in.userId).name, in.price,
                      static_cast<int>(list.size()), trusted});
  }
  sort(answer.begin(), answer.end(),
       [](const Row& a, const Row& b) { return a.invoiceId < b.invoiceId; });
  return answer;
}
06 / 深挖

面试追问

从“会写”继续走向“理解数据库行为”。

为什么不能 COUNT(*)？

左连接没有联系人也保留占位行；COUNT(*) 会计为 1，而 COUNT(contact_email) 忽略 NULL。

怎样减少中间结果？

先在联系人子查询中按用户聚合，再连接发票，避免同一顾客的联系人因多张发票重复展开。

推荐哪些索引？

除主键外，关注 Contacts(user_id) 与 Customers(email)，分别服务归属连接与可信匹配。

顾客邮箱若不唯一？

直接连接会放大行数，应改用 EXISTS 或先对顾客邮箱去重。
