设计井字棋Design Tic-Tac-Toe

设计一个可持续接收落子的棋局对象：每次移动后，立即回答当前玩家是否已经完成一条长度为 n 的横线、竖线或对角线。

Problem

题意与接口

系统设计题

实现 TicTacToe 类，管理一个 n × n 的井字棋棋盘。构造器 TicTacToe(int n) 初始化棋盘；之后每次调用 move(row, col, player)，表示玩家 player 在坐标 (row, col) 落子。

若该步让当前玩家占满任意一整行、一整列、主对角线或副对角线，返回该玩家编号；若尚无人获胜，返回 0。输入保证每一步都落在未占用的位置，并且获胜后不会继续调用 move。

参数形式

  • TicTacToe(int n)：创建边长为 n 的棋局。
  • int move(int row, int col, int player)：记录一步合法落子并返回 0 / 1 / 2。

约束

  • 2 ≤ n ≤ 100
  • player ∈ {1, 2}
  • 0 ≤ row, col < n
  • 每个位置至多落子一次；move 最多调用 n² 次。

官方示例（完整参数形式）

输入

说明

创建 3 × 3 棋盘后依次执行七步移动。最后一步玩家 1 落在 (2,1)，占满第 2 行的三个位置，因此返回 1；此前各步均返回 0。

Solution

有符号计数：不存棋盘也能判胜

每步 O(1)

核心洞察

新胜线一定经过刚落子的格子，所以每步只需更新当前行、当前列，以及至多两条经过该格子的对角线。把玩家 1 的棋子记为 +1，玩家 2 记为 −1；某个计数的绝对值达到 n，就说明它被同一玩家完全占据。

score = player == 1 ? +1 : −1；若 |rows[row]|、|cols[col]|、|diag|、|antiDiag| 中任一项等于 n，则当前玩家获胜。

完整过程

初始化状态

准备长度为 n 的 rows 与 cols 数组，并用两个整数记录主、副对角线；所有值从 0 开始。

编码当前玩家

玩家 1 对统计量增加 1，玩家 2 减少 1。相反符号让双方的棋子自然抵消。

更新受影响的线

总是更新 rows[row] 和 cols[col]；当 row == col 时更新主对角线，当 row + col == n - 1 时更新副对角线。中心格可能同时属于两条对角线，二者都要更新。

立即判胜

检查刚更新的四类统计量。任一绝对值达到 n 就返回当前 player，否则返回 0。

正确性证明

不变式：处理任意若干步后，rows[r] 等于第 r 行中玩家 1 棋子数减玩家 2 棋子数；列与两条对角线同理。

保持：一次合法移动只给该玩家所在的行、列及相应对角线贡献一个同符号单位，更新规则恰好保持不变式。

充分性：计数绝对值为 n 时，该线上的 n 个位置必然全属于同一玩家，因为共有且仅有 n 个格子。

必要性：若当前玩家因本步获胜，新完成的线必经过新落子；算法检查所有经过它的候选线，因此一定检测到。故返回结果正确。

复杂度与边界

  • 每次 move：时间 O(1)。
  • 对象额外空间：O(n)，不需要存储 n² 棋盘。
  • (0,0)、(n-1,n-1) 属于主对角线；(0,n-1)、(n-1,0) 属于副对角线。
  • 奇数阶中心格同时影响两条对角线，不能使用互斥分支。
  • 题目保证落子有效；若工程接口不保证，需要另存占用状态并校验。

四语言完整实现

class TicTacToe {
    private final int n;
    private final int[] rows;
    private final int[] cols;
    private int diagonal;
    private int antiDiagonal;

    public TicTacToe(int n) {
        this.n = n;
        this.rows = new int[n];
        this.cols = new int[n];
    }

    public int move(int row, int col, int player) {
        int score = player == 1 ? 1 : -1;

        rows[row] += score;
        cols[col] += score;

        if (row == col) {
            diagonal += score;
        }
        if (row + col == n - 1) {
            antiDiagonal += score;
        }

        if (Math.abs(rows[row]) == n
                || Math.abs(cols[col]) == n
                || Math.abs(diagonal) == n
                || Math.abs(antiDiagonal) == n) {
            return player;
        }
        return 0;
    }
}

var TicTacToe = function(n) {

    this.antiDiagonal = 0;

/**
 * @param {number} row
 * @param {number} col
 * @param {number} player
 * @return {number}
 */
TicTacToe.prototype.move = function(row, col, player) {
    const score = player === 1 ? 1 : -1;

    this.rows[row] += score;
    this.cols[col] += score;

    if (row === col) {
        this.diagonal += score;
    }
    if (row + col === this.n - 1) {
        this.antiDiagonal += score;
    }

    if (Math.abs(this.rows[row]) === this.n
            || Math.abs(this.cols[col]) === this.n
            || Math.abs(this.diagonal) === this.n
            || Math.abs(this.antiDiagonal) === this.n) {
        return player;
    }
    return 0;
};

替代方案

存完整棋盘：每次落子后扫描相关行、列和对角线，空间 O(n²)、单步 O(n)。逻辑直观，但没有利用“只需计数”的条件。

每位玩家各自计数：维护两套行列数组，同样能做到单步 O(1)，但空间常数更大；有符号计数更紧凑。

面试追问

  • 如果输入可能重复落子，怎样验证并保持 O(1)？
  • 如果玩家数量扩展到 k 个，如何调整数据结构？
  • 如果获胜条件变成连续 m 子而非占满整线，计数为何失效？
  • 如何支持撤销最后一步？

常见错误

  • 用 else if 更新两条对角线，漏掉中心格。
  • 只判断计数等于 n，忘记玩家 2 对应 −n。
  • 每次扫描整个棋盘，使移动退化为 O(n²)。
  • 返回符号而不是题目要求的玩家编号。

Quick review

离开前再问自己四件事

为什么不需要存棋盘？

题目保证落子合法且不重复；判胜只依赖每条候选线的双方棋子数量，因此行、列和对角线计数已经足够。

为什么计数绝对值达到 n 就一定获胜？

一条线只有 n 个位置，每格贡献只能是 +1 或 −1。总和的绝对值达到 n，意味着所有贡献符号相同。

一次移动最多更新几个统计量？

行和列各一个；若在主对角线或副对角线上再分别更新，最多共四个。

这套方法依赖什么输入保证？

每次落子坐标有效且未被占用，并且胜负产生后不再继续移动。若缺少这些保证，需要额外存储占用状态。
