最小操作次数使数组元素相等 II

给定整数数组 nums，每次可以让任意一个元素增加或减少 1。求让所有元素相等所需的最少操作数。

难度：中等 非付费题 返回 32 位整数

先读题，再动手

  1. 1一次操作只改变一个元素，变化量恰好为 1。
  2. 2最终相等的数值并未预先指定，需要选择最省操作的汇合点。
  3. 3下方实验台可以逐步观察每一次移动，题解仍保持折叠。

函数形式：minMoves2(nums)。输入参数是整数数组 nums，返回最少操作次数。

输出：2
解释：[1,2,3] → [2,2,3] → [2,2,2]

  • 1 <= nums.length <= 10^5
  • -10^9 <= nums[i] <= 10^9
  • 测试数据保证答案位于 32 位整数范围内。

Solution

排序后选择中位数

核心洞察

若最终都变为 x，操作数就是 Σ |nums[i] - x|。绝对距离之和在中位数处取得最小值。因此排序后取任一中位数，再累加每个元素到它的绝对距离即可。

完整过程

  1. 将 nums 按升序排序。
  2. 取 nums[n / 2] 作为中位数；偶数长度时取两个中位数中的任意一个都可以。
  3. 遍历数组，将 |num - median| 累加到答案。
  4. 返回总和。

边界情况

  • 只有一个元素：无需操作，答案为 0。
  • 元素已经全部相等：每项距离都是 0。
  • 存在负数：绝对距离的结论不变。
  • 偶数长度：两个中位数之间的任意整数都能得到相同最小值。
  • 实现时可用更宽的累加类型，避免中间计算溢出。

正确性证明

  1. 操作数等于绝对距离和。 把元素 a 变成目标值 x 至少需要 |a-x| 次 ±1 操作，并且逐步增减恰能达到这个下界。
  2. 目标值向中位数靠近不会变差。 设数组已排序。如果目标值位于中位数左侧，向右移动 1 时，目标左侧元素贡献至多增加一份，而右侧至少有同样多的元素各减少一份，因此总距离不会增加；右侧情形对称。
  3. 中位数最优。 重复上述移动可将任意目标值移到中位数而不增加总距离，所以中位数取得全局最小值。算法累加到该中位数的距离，故返回最少操作数。

复杂度

时间：O(n log n)，主要来自排序。

空间：取决于语言排序实现；若忽略排序栈，可视作 O(1) 额外空间。

替代方案

用 Quickselect 在期望 O(n) 时间内找到中位数，再线性求和；最坏复杂度与实现有关。面试中先给可靠的排序解，再讨论选择算法通常更清晰。

另一种累加视角

排序后从两端配对，累加 nums[right] - nums[left]。每对跨过中位数的距离恰好贡献到答案，省去显式读取目标值。

四语言完整代码

import java.util.Arrays;

class Solution {
    public int minMoves2(int[] nums) {
        Arrays.sort(nums);
        int median = nums[nums.length / 2];
        long moves = 0;

        for (int num : nums) {
            moves += Math.abs((long) num - median);
        }

        return (int) moves;
    }
}
/**
 * @param {number[]} nums
 * @return {number}
 */
var minMoves2 = function(nums) {
    nums.sort((a, b) => a - b);
    const median = nums[Math.floor(nums.length / 2)];
    let moves = 0;

    for (const num of nums) {
        moves += Math.abs(num - median);
    }

    return moves;
};

class Solution:
    def minMoves2(self, nums: List[int]) -> int:
        nums.sort()
        median = nums[len(nums) // 2]
        return sum(abs(num - median) for num in nums)

public:

        const int median = nums[nums.size() / 2];

面试追问

  • 能否把时间复杂度从 O(n log n) 降到期望 O(n)？
  • 为什么偶数长度时两个中位数之间都最优？
  • 如果一次操作允许同时改变 n-1 个元素，结论会如何变化？
  • 如果代价改为距离的平方，最优汇合点是什么？

常见错误

  • 选择平均数；平均数最小化的是平方误差，不是绝对距离。
  • 在比较器中直接相减但忽略可能的整数溢出。
  • 忘记排序就读取中间下标。
  • 用较窄类型计算差值或累加中间结果。
  • 逐次模拟到原题的大数值，导致时间不可接受。
