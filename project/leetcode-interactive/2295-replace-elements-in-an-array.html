Replace Elements in an Array

数值会变化，数组顺序如何保留？按给定顺序完成每一次替换，观察结果。

公开题目函数：arrayChange(nums, operations)官方题目 ↗

01 / 题目

给定从下标 0 开始的数组 nums，其中有 n 个互不相同的正整数。另有 m 个操作 operations；依次处理每个二元组 [oldValue, newValue]，把数组中等于 oldValue 的元素改为 newValue，保留它所在的位置。返回全部操作完成后的数组。

对每一步的当前数组，题目保证旧值存在、新值不存在。某个值被替换离开后，后续可以再次作为新值出现。

官方示例 1

输入：nums = [1,2,4,6], operations = [[1,3],[4,7],[6,1]]
输出：[3,2,7,1]
过程：[1,2,4,6] → [3,2,4,6] → [3,2,7,6] → [3,2,7,1]

官方示例 2

输入：nums = [1,2], operations = [[1,3],[2,1],[3,2]]
输出：[2,1]
过程：[1,2] → [3,2] → [3,1] → [2,1]

完整约束

  • n == nums.length，m == operations.length。
  • 1 ≤ n, m ≤ 10⁵。
  • nums 中的所有数字互不相同。
  • operations[i].length == 2。
  • 1 ≤ nums[i], operations[i][0], operations[i][1] ≤ 10⁶。
  • 执行第 i 个操作时，operations[i][0] 存在于当前数组，operations[i][1] 不存在于当前数组。

04 / 独立题解

准备好后再展开，含交互与四语言实现。

核心洞察：数值换名字，位置不挪动

维护哈希表 pos[value] = index。因为所有当前数值互不相同，一个值只对应一个位置。对操作 [a,b]，查到 j = pos[a] 后，将 nums[j] 改为 b，删除旧键 a，添加 pos[b] = j。

完整过程
  1. 遍历初始数组，为每个数建立“值 → 下标”映射。
  2. 依次取出 [a,b]，通过 pos[a] 找到位置 j。
  3. 执行 nums[j] = b；删除 a 的位置记录，令 pos[b] = j。
  4. 全部操作完成后，返回原数组。数组顺序一直由下标保存。
示例 1 的三次定位下标分别为 0、2、3。最后一步可以把 6 改为 1，因为第一步后旧数值 1 已离开数组；此时必须让新键 1 指向下标 3。


正确性证明
不变式：每次完整操作开始前，数组等于此前所有替换后的结果；哈希表恰好包含当前数组的数值，且每个键映射到该值的实际下标。
初始化：遍历数组建立表，所有数值互异，因此映射唯一且准确，数组还未进行操作。
保持：假设不变式成立。旧值 a 存在，所以 pos[a] 精确定位应修改的元素。只把该位置改为 b，符合本次操作。新值原本不存在；删除旧键并添加新键后，不会与其他元素冲突，其他位置与映射不变，不变式继续成立。
终止：恰好执行完 m 个操作后，数组即为所有替换按顺序作用后的结果，返回它正确。


边界与复杂度
  • 只有一个元素时同样适用。
  • 同一位置可连续被改名；旧数值可以在其他位置重新出现。
  • 元素下标可能为 0，不能用真假值判断它是否存在。
  • 数值最大为 10⁶，四种语言中的所用整数表示足够。
建表 O(n)，每次哈希操作平均 O(1)，总时间平均 O(n + m)，额外空间 O(n)。哈希退化时，单次操作可能达到 O(n)，总计可达 O(n² + mn)；平均界不是所有实现的最坏保证。
实现直接修改 nums。如果调用者需要保留原输入，先复制数组，会额外使用 O(n) 空间。


替代方案
  • 逐次线性查找：每次扫描数组，时间 O(nm)，额外空间 O(1)，适合小数据理解题意。
  • 直接寻址表：用长度 U+1 的数组记录位置，空位标为 -1，U=10⁶。时间 O(U+n+m)，空间 O(U)，以更多空间换确定的常数访问。
  • 倒序值映射：倒着处理替换，将旧值映射到新值的最终去向，最后转换初始数组。平均时间 O(n+m)，空间 O(m)，但值复用时的语义更绕。


常见错误
  • 把操作中的数值当成下标：nums[a] = b 含义错误。
  • 只更新数组，忘记更新位置表，下一次定位会使用过期信息。
  • 留下旧键会破坏“表恰好代表当前数组”的不变式，并让表随操作增长；应及时删除。
  • 在 JavaScript 中用 if (pos.get(a)) 检查存在性，下标 0 会被误判。
  • 排序或只返回哈希表键会丢失原数组的下标顺序。
  • 通过多次 indexOf 查找，最坏会扫描约 10¹⁰ 个元素。


面试追问
允许重复值怎么办？先明确替换一个还是全部。若替换全部，维护“值 → 下标集合”，合并与遍历的成本需按受影响的元素总次数计入。
新值允许已存在怎么办？数组可能出现重复值，单下标映射就失效，需要更换数据结构与不变式。
怎样支持撤销？每次保存下标、旧值与新值，按逆序恢复数组和位置表；历史记录需要 O(m) 空间。

Java
import java.util.HashMap;
import java.util.Map;

class Solution {
    public int[] arrayChange(int[] nums, int[][] operations) {
        Map<Integer, Integer> pos = new HashMap<>();
        for (int i = 0; i < nums.length; i++) {
            pos.put(nums[i], i);
        }
        for (int[] op : operations) {
            int index = pos.remove(op[0]);
            nums[index] = op[1];
            pos.put(op[1], index);
        }
        return nums;
    }
}

var arrayChange = function(nums, operations) {
    const pos = new Map();
    for (let i = 0; i < nums.length; i++) {
        pos.set(nums[i], i);
    }
    for (const [oldValue, newValue] of operations) {
        const index = pos.get(oldValue);
        nums[index] = newValue;
        pos.delete(oldValue);
        pos.set(newValue, index);
    }
    return nums;
};

from typing import List

class Solution:
    def arrayChange(self, nums: List[int],
                    operations: List[List[int]]) -> List[int]:
        pos = {value: i for i, value in enumerate(nums)}
        for old_value, new_value in operations:
            index = pos.pop(old_value)
            nums[index] = new_value
            pos[new_value] = index
        return nums


C++
#include <vector>
#include <unordered_map>
using namespace std;

class Solution {
public:
    vector<int> arrayChange(vector<int>& nums,
                            vector<vector<int>>& operations) {
        unordered_map<int, int> pos;
        for (int i = 0; i < static_cast<int>(nums.size()); ++i) {
            pos[nums[i]] = i;
        }
        for (const auto& op : operations) {
            int index = pos.at(op[0]);
            nums[index] = op[1];
            pos.erase(op[0]);
            pos[op[1]] = index;
        }
        return nums;
    }
};
