Problem

题目说明

给定整数数组 coins，其中每个元素代表一种硬币面额；再给定整数 amount，代表需要凑出的总金额。每种面额的硬币都可以使用任意多枚。

返回恰好凑成 amount 所需的最少硬币数量。如果不存在任何组合能够恰好凑出该金额，返回 -1。

函数参数形式

coinChange(coins: integer[], amount: integer) → integer

约束

  • 1 ≤ coins.length ≤ 12
  • 1 ≤ coins[i] ≤ 2³¹ − 1
  • 0 ≤ amount ≤ 10⁴

注意：面额可能远大于目标金额；目标金额也可能为 0。

示例 1

可达
输入：coins = [1,2,5], amount = 11
输出：3
解释：11 = 5 + 5 + 1

示例 2

不可达
输入：coins = [2], amount = 3
输出：-1

示例 3

边界
输入：coins = [1], amount = 0
输出：0

Solution

一维动态规划：让小金额托起大金额

核心洞察

令 dp[x] 表示恰好凑成金额 x 的最少硬币数。若最后拿的一枚硬币面额为 c，那么拿它之前必须已经用最少硬币凑出了 x − c。

因此，只要 x ≥ c 且 x − c 可达，就得到候选值 dp[x − c] + 1；在所有硬币产生的候选值中取最小值。

dp[x] = min(dp[x], dp[x − c] + 1)

完整过程

  1. 创建长度为 amount + 1 的数组，先用不可达哨兵 amount + 1 填充。
  2. 设 dp[0] = 0，因为凑成 0 元需要 0 枚硬币。
  3. 按金额 1…amount 递增枚举。
  4. 对每个金额尝试所有硬币；如果硬币不超过当前金额，就用较小子问题更新当前状态。
  5. 若 dp[amount] 仍为哨兵，返回 -1；否则返回该最小值。

正确性证明

命题：对每个 x ∈ [0, amount]，算法完成金额 x 的计算后，dp[x] 等于恰好凑成 x 的最少硬币数；若不可达，则保持为哨兵。

基础情况：x = 0 时，空组合恰好凑成 0，使用 0 枚硬币；任何硬币数都不可能小于 0，因此 dp[0] = 0 正确。

归纳步骤：假设所有小于 x 的状态都正确。任取一个凑成 x 的最优组合，拿掉它最后一枚面额为 c 的硬币，剩余组合凑成 x − c。若剩余组合不是该金额的最优解，用更优解替换它会得到更少硬币的 x 组合，与原组合最优矛盾。因此最优值一定出现在某个 dp[x − c] + 1 候选中。反过来，每个有限候选都对应一个合法组合。算法枚举所有硬币并取最小值，故得到且只得到最优值；没有有限候选时，x 不可达。

结论：根据数学归纳法，最终 dp[amount] 正确；哨兵按题意转换为 -1。

复杂度

设硬币种类数为 n，目标金额为 A。

时间复杂度：O(nA)
空间复杂度：O(A)

边界处理

  • amount = 0 时直接得到 0。
  • 面额大于当前金额时跳过。
  • 不可达状态不能参与 +1 更新。
  • 用 amount + 1 作有限安全哨兵。

替代方案

BFS：把金额看作节点，每加一枚硬币扩展一层；首次到达目标即为最少枚数。最坏复杂度同样约为 O(nA)，但队列和去重开销更大。

记忆化搜索：递归表达自然，但深度可达 A，需注意栈深。

import java.util.Arrays;

class Solution {
    public int coinChange(int[] coins, int amount) {
        int unreachable = amount + 1;
        int[] dp = new int[amount + 1];
        Arrays.fill(dp, unreachable);
        dp[0] = 0;

        for (int current = 1; current <= amount; current++) {
            for (int coin : coins) {
                if (coin <= current) {
                    dp[current] = Math.min(
                        dp[current],
                        dp[current - coin] + 1
                    );
                }
            }
        }

        return dp[amount] == unreachable ? -1 : dp[amount];
    }
}

常见错误

  • 贪心选最大硬币：普通面额系统不保证贪心最优，例如 [1,3,4] 凑 6。
  • 把 0 当作未计算：dp[0] = 0 是有效起点，其他状态才应初始化为不可达。
  • 返回哨兵：最终不可达时必须转换为 -1。
  • 循环边界错一位：需要计算到 amount，数组长度是 amount + 1。
  • 使用整数最大值再加 1：可能溢出；本题用 amount + 1 足够表示不可能值。
