按字典序排在最后的子串

Last Substring in Lexicographical Order · 从所有子串中，找出字典序最大的那个。

Before the solution

先问自己：如果某个子串还可以继续向右延长，它会不会变得更小？这个问题会把候选范围悄悄缩窄。

01 · Problem

题目说明

任务

给定一个只包含小写英文字母的字符串 s。考虑 s 的所有非空连续子串，将它们按字典序排列，返回其中排在最后的子串。

字典序比较时，从左到右寻找第一个不同字符：该位置字符更大的字符串更大；若其中一个字符串是另一个的前缀，则更长的字符串更大。

lastSubstring(s: string) → string

约束

  • 1 <= s.length <= 4 × 105
  • s 仅包含小写英文字母。

示例 1

输入s = "abab"
输出"bab"
解释7 个不同位置产生的子串中，"bab" 的字典序最大。

示例 2

输入s = "leetcode"
输出"tcode"

03 · Solution

线性双指针筛选最大后缀

核心洞察

答案一定是 s 的某个后缀。若最优子串在末尾之前结束，把它继续延长仍以原子串为前缀，字典序只会更大。

三个指针

  • i：当前最优候选后缀的起点。
  • j：等待挑战 i 的后缀起点。
  • k：两后缀已经相同的前缀长度。

边界情况

  • 长度为 1：唯一字符就是答案。
  • 字符全部相同：最长后缀，也就是原串最大。
  • 严格递减：第一个字符已经决定原串最大。
  • 重复周期：必须跳过整段已比较区间，避免退化成平方复杂度。
时间O(n)指针只向右移动
空间O(1)返回值之外

完整过程

  1. 令 i = 0、j = 1、k = 0。
  2. 比较 s[i + k] 与 s[j + k]。若相同，递增 k，继续寻找首个差异。
  3. 若左字符更小，当前候选以及这段相同前缀覆盖的起点都不可能获胜。把 i 移到 max(i + k + 1, j)，再令 j = i + 1。
  4. 若左字符更大，挑战者所在的整段可被排除，令 j = j + k + 1。
  5. 每次淘汰后令 k = 0。当挑战者已比较到字符串末尾时，返回 s.substring(i)。

为什么能整段跳过？

两后缀前 k 个字符相同，而第 k 个位置首次分出大小。已知相同块内部的移位候选，会在同一字符关系下被更优一侧压过；因此这段起点不会产生新的最大后缀，可以随败者一起排除。

面试时的一句话

“我不排序所有后缀，而是让候选后缀两两比赛；利用已知最长公共前缀，一次淘汰一整段起点。”

04 · Correctness

正确性说明

答案属于后缀集合。 任意子串都可向右延长到同起点的后缀；原子串是该后缀的前缀，所以延长后的字符串不会更小。
比较能确定败者区间。 两个后缀在偏移 k 前完全相同，首个不同字符决定大小。结合这段相同前缀，败者一侧从其起点到偏移 k 覆盖的候选都不可能超过胜者。
不变量持续成立。 每次更新后，i 保留所有已处理起点中的最大后缀，j 指向下一个尚未淘汰的挑战者；被跳过的起点均已有更优后缀作为证据。
终止即得到全局最优。 当 j + k = n 时，挑战者在相同前缀后先结束，因此不大于候选；其余起点也已淘汰，故从 i 开始的后缀就是最大子串。

05 · Code

四语言完整实现

class Solution {
    public String lastSubstring(String s) {
        int n = s.length();
        int i = 0, j = 1, k = 0;

        while (j + k < n) {
            char left = s.charAt(i + k);
            char right = s.charAt(j + k);
            if (left == right) {
                k++;
            } else if (left < right) {
                i = Math.max(i + k + 1, j);
                j = i + 1;
                k = 0;
            } else {
                j = j + k + 1;
                k = 0;
            }
        }
        return s.substring(i);
    }
}

06 · Trade-offs

替代方案与追问

后缀数组可以吗？

可以。构造后缀数组后取字典序最后的后缀即可。常见实现需要 O(n log n) 时间与 O(n) 空间，代码和常数都比本题的专用线性扫描更重。

直接枚举并比较所有后缀呢？

概念简单，但逐个字符串比较可能反复扫描相同前缀，最坏达到 O(n²)，无法承受 4 × 10⁵ 的输入。

与 Lyndon 分解有什么关系？

它们都利用字典序与周期结构批量排除候选。也可用 Duval 风格的最大表示思路推导线性解法，但双指针版本更直接地对应“最大后缀”。

面试追问：为什么返回后缀而不是中间子串？

因为继续向右延长不会降低字典序：短串若为长串前缀，长串更大。

面试追问：算法为什么是线性的？

i 与 j 都只向右移动；每次首个不同字符出现后，已比较的区间被整体跳过，不会从其内部重新作为候选逐字符扫描。

常见错误
  • 败者只移动一格，导致最坏 O(n²)。
  • 候选更新后忘记保证 j > i。
  • 淘汰后忘记把 k 清零。
  • 把“子串”误当成可跳字符的“子序列”。
