PROBLEM BRIEF

找第一张缺席的正数行李牌

给定一个无序整数数组 nums，返回其中没有出现的最小正整数。 算法必须是线性时间，并且只能使用常数级辅助空间，因此不能额外建立集合或布尔数组。

范围结论

长度为 n 的数组，答案一定落在 [1, n + 1]。只需关心 1..n 是否回到对应下标；若全部存在，答案就是 n + 1。

    CORE INSIGHT

    把数组本身当哈希表

    对长度 n，只关心 1..n。 值 x 的唯一正确位置是 x - 1。 只要当前值在范围内，且目标位置还不是同一个值，就交换；交换后继续检查当前位置，因为换回来的值仍可能需要归位。

    while 1 ≤ nums[i] ≤ n
      and nums[nums[i] − 1] ≠ nums[i]:
        swap(nums[i], nums[nums[i] − 1])

    WHY LINEAR?

    while 不是 O(n²)

    每次真正交换，至少把一个范围内的正整数送到它的最终位置。一个柜位被正确占用后不会被不同值反复抢走，因此总交换次数不超过 n 量级。归位扫描与答案扫描各一次，总计仍是 O(n)。

    FULL WALKTHROUGH

    完整解题过程

    1. 01

      确定有效值域

      答案在 [1, n + 1]；归位阶段忽略 ≤ 0 或 > n 的值。

    2. 02

      原地循环归位

      遍历 i；只要 nums[i] 有效且目标格不是相同值，就与 nums[nums[i] - 1] 交换。

    3. 03

      防止重复值死循环

      目标位置已经等于当前值时立即停止；例如 [1, 1] 的第二个 1 不再交换。

    4. 04

      从左向右查缺口

      第一个 nums[i] != i + 1 的位置返回 i + 1；若全部匹配，返回 n + 1。

    BOUNDARIES

    边界情况

    • • 全是负数、0 或大数：直接返回 1。
    • • 数组为 [1]：归位后无缺口，返回 2。
    • • 存在重复值：目标相同即停，避免无限交换。
    • • 1..n 全齐：答案是唯一可能的 n + 1。

    ALTERNATIVES

    替代方案取舍

    哈希集合最直观但需要 O(n) 空间；排序后扫描是 O(n log n)；符号标记法也能 O(n)/O(1)，但要先处理 1 是否存在并归一化无效值，分支更多。面试主线优先选原地归位，映射最直接。

    COMMON FAILURES

    常见错误

    • • 用 if 只交换一次；换回来的数还没归位，必须用 while。
    • • 漏掉 nums[target] != nums[i]，重复值会无限交换。
    • • 先计算 nums[i] - 1 再检查范围，可能越界。
    • • 把答案范围写成 1..n，漏掉所有数齐全时的 n + 1。
    • • JavaScript 解构交换时重复读取变化后的下标；先保存 target 更稳。

    INTERVIEW FOLLOW-UPS

    面试高频追问

    为什么答案不超过 n + 1？
    n 个位置最多覆盖 n 个不同正整数；若 1..n 都在，最小缺失只能是 n + 1。
    原数组会被修改吗？
    会。这正是常数空间的代价；若禁止修改输入，只能复制数组或使用额外结构。
    为什么重复值不影响答案？
    存在性只关心“是否有一个 x”；一个正确柜位容纳一个 x 已足够。
