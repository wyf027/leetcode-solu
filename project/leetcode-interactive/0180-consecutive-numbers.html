    LAG 构造三行窗口

    当前值等于前一行和前两行的值，就证明有一个长度至少为 3 的连续尾段。

    MySQL 主提交

    WITH compared AS (
    SELECT
        num,
        LAG(num, 1) OVER (ORDER BY id) AS prev1,
        LAG(num, 2) OVER (ORDER BY id) AS prev2
    FROM Logs
)
SELECT DISTINCT num AS ConsecutiveNums
FROM compared
WHERE num = prev1 AND num = prev2;

    LAG 按 id 排列行，DISTINCT 让长度大于 3 的连续段只输出一次。结果顺序任意，无需 ORDER BY。

    LAG/LEAD 与三表自连接

    • LEAD 检查后两行同样正确。
    • 三表自连接写成 l2.id=l1.id+1、l3.id=l2.id+1，直观但更冗长，并依赖连续 id。
    • LAG 表达的是“按 id 排序后的相邻行”，对存在 id 间隙的推广更稳健。

    五种官方提交入口

    Pandas · 官方支持
    import pandas as pd

def consecutive_numbers(logs: pd.DataFrame) -> pd.DataFrame:
    ordered = logs.sort_values("id").copy()
    nums = ordered["num"]
    mask = nums.eq(nums.shift(1)) & nums.eq(nums.shift(2))
    return (
        ordered.loc[mask, ["num"]]
        .drop_duplicates()
        .rename(columns={"num": "ConsecutiveNums"})
    )

    自连接与 Pandas

    SELECT DISTINCT l1.num AS ConsecutiveNums
FROM Logs l1
JOIN Logs l2 ON l2.id = l1.id + 1 AND l2.num = l1.num
JOIN Logs l3 ON l3.id = l2.id + 1 AND l3.num = l1.num;

    官方 Pandas 可按 id 排序后，用 num.eq(num.shift(1)) & num.eq(num.shift(2)) 筛选并去重。

    复杂度与执行计划

    设日志行数为 n。若数据库需要按 id 排序，窗口方案通常为 O(n log n) 时间；主键顺序可被执行计划直接利用时，扫描部分为 O(n)。窗口状态与去重结构最多占用 O(n) 工作空间。

    常见错误

    • 仅 GROUP BY num，忽略连续性。
    • 忘记 DISTINCT，长连续段重复输出。
    • 未按 id 排序窗口。
    • 输出列别名不正确。
