数组中两个数的最大异或值

Maximum XOR of Two Numbers in an Array

先读题、观察异或的“高位优先”特征，再用交互探索器逐位做选择。完整算法与代码默认收起，不会在首屏直接揭晓。

Problem

题意

给定整数数组 nums，在所有满足 0 ≤ i ≤ j < n 的下标对中，求 nums[i] XOR nums[j] 的最大值。XOR 表示按位异或：同一位不同为 1，相同为 0。

示例 1

输入：nums = [3,10,5,25,2,8]
输出：28
解释：5 XOR 25 = 28，是可取得的最大结果。

示例 2

输入：nums = [14,70,53,83,49,91,36,80,92,51,66,70]
输出：127

约束

  • 1 ≤ nums.length ≤ 2 × 10⁵
  • 0 ≤ nums[i] ≤ 2³¹ − 1

Complete solution

贪心构造答案 + 前缀哈希集合

核心洞察

数值大小首先由最高个不同的二进制位决定，所以答案可以从第 30 位到第 0 位逐位贪心确定。假设更高位已经确定为 answer，当前位先尝试置 1，得到 candidate。用掩码只保留每个数截至当前位的前缀。

若两个前缀 x、y 满足 x XOR y = candidate，则等价于 y = x XOR candidate。把所有前缀放进哈希集合后，就能在线性时间判断候选是否可实现。

完整过程

  1. 初始化 answer = 0、mask = 0。
  2. 从位 30 下降到位 0，把当前位加入 mask。
  3. 计算所有 num & mask，将截至当前位的前缀加入哈希集合。
  4. 令 candidate = answer | (1 << bit)，即尝试让当前答案位为 1。
  5. 若存在前缀 prefix，使集合包含 prefix XOR candidate，接受候选；否则保持当前答案。
  6. 处理完最低位后，answer 即最大异或值。

正确性证明

循环不变式：处理完第 bit + 1 位后，answer 的已确定高位，等于任意数对异或结果在这些高位上的最大可能前缀。

进入当前位时，所有更高位已最优。二进制数的当前位权重大于所有更低位权重之和，因此只要在不破坏已确定高位的前提下能让当前位为 1，任何当前位为 0 的结果都不可能更大。 哈希判定枚举了每个可见前缀 x，并精确检查所需搭档 x XOR candidate 是否存在，所以它当且仅当某对前缀能够实现候选值时接受候选。 若可实现，接受 1 得到当前位的最优选择；若不可实现，该位只能为 0。故不变式继续成立。所有 31 位处理完毕后，没有未决低位，answer 就是全局最大异或值。

边界情况

  • 只有一个元素时允许 i = j，元素与自身异或为 0。
  • 所有元素相同时，任意数对的异或值都是 0。
  • 数组包含 0 时无需特殊处理；0 的前缀自然进入集合。
  • 最大元素可达 2³¹ − 1，只需处理非符号位 30 到 0。
  • 重复元素放入集合会去重，但不影响“某前缀是否存在”的判定。

复杂度

固定处理 31 个二进制位，每一位扫描 n 个元素：时间复杂度 O(31n) = O(n)，哈希集合最多保存 n 个前缀，空间复杂度 O(n)。

四语言完整代码

Java

import java.util.HashSet;
import java.util.Set;

class Solution {
    public int findMaximumXOR(int[] nums) {
        int answer = 0;
        int mask = 0;

        for (int bit = 30; bit >= 0; bit--) {
            mask |= 1 << bit;
            Set<Integer> prefixes = new HashSet<>();
            for (int num : nums) {
                prefixes.add(num & mask);
            }

            int candidate = answer | (1 << bit);
            for (int prefix : prefixes) {
                if (prefixes.contains(prefix ^ candidate)) {
                    answer = candidate;
                    break;
                }
            }
        }
        return answer;
    }
}

Python

from typing import List


class Solution:
    def findMaximumXOR(self, nums: List[int]) -> int:
        answer = 0
        mask = 0

        for bit in range(30, -1, -1):
            mask |= 1 << bit
            prefixes = {num & mask for num in nums}
            candidate = answer | (1 << bit)

            if any((prefix ^ candidate) in prefixes
                   for prefix in prefixes):
                answer = candidate

        return answer

C++

#include <unordered_set>
#include <vector>
using namespace std;

class Solution {
public:
    int findMaximumXOR(vector<int>& nums) {
        int answer = 0;
        int mask = 0;

        for (int bit = 30; bit >= 0; --bit) {
            mask |= 1 << bit;
            unordered_set<int> prefixes;
            for (int num : nums) {
                prefixes.insert(num & mask);
            }

            int candidate = answer | (1 << bit);
            for (int prefix : prefixes) {
                if (prefixes.count(prefix ^ candidate)) {
                    answer = candidate;
                    break;
                }
            }
        }
        return answer;
    }
};

替代方案：二进制字典树

还可以把每个数的 31 位二进制表示插入 Trie。查询一个数时，每一位都优先走与它相反的分支，从而让异或结果该位为 1。该方案同样是 O(31n) 时间与 O(31n) 空间；它更直观地构造搭档，但节点对象的常数开销通常高于前缀哈希法。

面试追问

  • 为什么不能排序后只比较相邻元素？ 数值接近不等于二进制位差异大，最大异或数对不具备普通排序的相邻性质。
  • 如果允许负数怎么办？ 需要先明确“最大值”按有符号还是无符号解释，并相应处理符号位及语言的位运算语义。
  • 如何返回具体的两个数？ 前缀判定时保存前缀到原数的映射，最终答案确定后再查找满足 a XOR b = answer 的数对。
  • 如何处理数据流？ 可维护二进制 Trie，每到一个新数先查询当前最佳搭档，再插入该数。

常见错误

  • 把候选答案直接永久设为 1，却没有检查是否存在一对前缀可以实现。
  • 集合里存原数而不是 num & mask，导致逐位不变式失效。
  • 只检查集合中是否有 candidate，而不是检查 prefix XOR candidate。
  • 从低位向高位贪心；低位选择不能优先于权重更大的高位。
  • 在 JavaScript 中把范围扩展到符号位后忽略 32 位有符号位运算语义。
