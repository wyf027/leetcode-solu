Find All Possible Recipes from Given Supplies

一份食谱，也可能是另一道菜的原料。哪些菜最终能端上餐桌？

阅读题目测试与验证官方题目 ↗

01 / PROBLEM

题目与参数

有 n 道菜。recipes[i] 是第 i 道菜的名称，ingredients[i] 列出制作它所需的全部原料。只有每一种原料都已拥有，才能做出这道菜。做出的菜也能成为其他菜的原料。

supplies 表示最初拥有的原料，每一种都无限供应，不会因为制作而耗尽。返回所有可以做出的菜名，顺序不限。食谱可能互相依赖，不能假设不存在循环。

findAllRecipes(recipes: string[], ingredients: string[][], supplies: string[]) → string[]

完整约束

  • n == recipes.length == ingredients.length，且 1 ≤ n ≤ 100。
  • 1 ≤ ingredients[i].length ≤ 100，1 ≤ supplies.length ≤ 100。
  • 1 ≤ recipes[i].length, ingredients[i][j].length, supplies[k].length ≤ 10。
  • 所有名称只含小写英文字母。
  • recipes 与 supplies 合在一起，所有名称互不相同。
  • 每个 ingredients[i] 内没有重复名称。

04 / EXPLANATION

先思考，再揭开制作过程

展开后可查看交互推演、正确性说明和四种语言的完整实现。

从已有原料出发，逐步解锁菜谱

核心洞察

把原料到依赖它的菜连成有向边。为每道菜记录“尚未收到可用通知的原料数” remaining[i]。初始只让 supplies 进入队列；每处理一种可用原料，就沿它的出边把对应计数减一。计数降到零，菜可以做出，也成为新的可用原料。

这是由 supplies 驱动的拓扑传播。不能把所有没有前置边的名称都视为已有：缺失的原料虽然没有食谱，也不代表你拥有它。

完整过程

  1. 遍历每个食谱。令 remaining[i] = ingredients[i].length，建立 dependents[item]，记录用到 item 的菜谱下标。
  2. 把全部 supplies 加入 FIFO 队列。答案开始为空。
  3. 取出一个名称 item。只访问 dependents[item] 中的菜，将各自 remaining 减一。
  4. 某菜的 remaining 首次变成 0 时，把它加入答案及队列，让它之后继续通知其他菜。
  5. 队列为空时结束。未归零的菜缺少原料，或被依赖环及其下游阻塞。

示例 3：yeast 通知 bread 后，bread 的剩余数为 1；flour 使它降到 0，bread 入队。meat 让 sandwich 从 2 变 1、burger 从 3 变 2。bread 出队后解锁 sandwich，并使 burger 剩 1；sandwich 再解锁 burger。

正确性

不变式：remaining[i] 等于该菜所有原料中，还未沿对应边处理可用通知的数量。初始没有通知，计数等于原料总数；每条边只处理一次，恰好扣除一个，因此不变式始终成立。

可靠性：初始队列中的名称来自 supplies，确实可用。若一份菜谱归零，其所有原料均来自已经处理的可用名称，所以它一定能做出。归纳可知，答案不会包含不能制作的菜。

完备性：任意实际能做出的菜，都有一个有限制作过程。按这一过程归纳：最先制作的菜所需原料都在 supplies 中，通知必会处理；之后的菜依赖的先前菜也必会入队并通知。因此每个可做菜最终归零，都会进入答案。

终止性：supplies 名称互异，且不与 recipes 重合；原料列表无重复。每道菜的计数只会从正数经过零一次，每道菜至多入队一次。队列长度有限，算法终止。循环里没有初始可用入口时不会被凭空解锁。

复杂度

记 n 为菜谱数，E 为所有原料列表的总长度，S 为 supplies 长度。哈希表操作按均摊 O(1)、名称长度按题目上限 10 计：时间 O(n + E + S)，辅助空间 O(n + E + S)（包含队列，不含返回答案）。若把字符串长度 L 当变量，字符串哈希成本需额外计入。

边界与常见错误

  • 无菜可做：返回 []；不能因为有食谱就默认它可用。
  • 环与缺失原料：不必为了答案额外检测环；剩余计数会自然保留。独立分支仍正常解锁。
  • 多道菜共享原料：每条依赖边都要通知；不要消耗 supplies，也不要删除已可用的菜。
  • 计数定义混用：本实现统计全部原料，supplies 也必须出队扣减。若初始化时已扣除 supplies，就不能再扣一次。
  • 边方向写反：从原料指向使用它的菜，才能直接找到受影响的计数。
  • 只扫描一轮食谱：输入顺序可能与制作顺序相反，会漏掉后续才解锁的菜。
  • JS 队列：使用 head 下标，不要反复 shift；也不要边遍历 supplies 原数组边追加新菜。

替代方案

反复扫描 + 可用集合：每轮扫描未完成食谱，全部原料在集合中就解锁，直到一轮没有新增。逻辑直观，但最坏需要 n 轮，时间 O(nE + S)，可用集合及标记空间 O(n + S)。

DFS + 记忆化：从菜向它的原料递归判断，使用“未访问、访问中、可做、不可做”状态，遇到访问中表示循环；不存在于 supplies 或菜谱表的原料直接失败。可达依赖只处理一次时也能达到 O(n + E + S)，但要正确处理环和递归栈。

面试追问

  • 如何输出实际制作顺序？保留本算法的解锁顺序；被依赖的菜总会先解锁。
  • 新补充一种原料怎么办？保留图、剩余计数及已传播集合，对首次变成可用的新原料继续传播，防止重复扣减。
  • 原料变成有限数量呢？本题的单调可用性不再足够，必须建模用量、消耗与制作选择，不能直接套本算法。
  • 怎样解释做不出的原因？遍历尚未满足的依赖；若需要区分循环阻塞与原料缺失，可额外用强连通分量分析。

Java

import java.util.*;

class Solution {
    public List<String> findAllRecipes(String[] recipes,
            List<List<String>> ingredients, String[] supplies) {
        Map<String, List<Integer>> dependents = new HashMap<>();
        int[] remaining = new int[recipes.length];
        for (int i = 0; i < recipes.length; i++) {
            remaining[i] = ingredients.get(i).size();
            for (String item : ingredients.get(i)) {
                dependents.computeIfAbsent(item, k -> new ArrayList<>()).add(i);
            }
        }
        Deque<String> queue = new ArrayDeque<>();
        Collections.addAll(queue, supplies);
        List<String> result = new ArrayList<>();
        while (!queue.isEmpty()) {
            String item = queue.removeFirst();
            List<Integer> next = dependents.get(item);
            if (next == null) continue;
            for (int i : next) {
                if (--remaining[i] == 0) {
                    result.add(recipes[i]);
                    queue.addLast(recipes[i]);
                }
            }
        }
        return result;
    }
}

/**
 * @param {string[]} recipes
 * @param {string[][]} ingredients
 * @param {string[]} supplies
 * @return {string[]}
 */
var findAllRecipes = function(recipes, ingredients, supplies) {
    const dependents = new Map();
    const remaining = ingredients.map(items => items.length);
    for (let i = 0; i < recipes.length; i++) {
        for (const item of ingredients[i]) {
            if (!dependents.has(item)) dependents.set(item, []);
            dependents.get(item).push(i);
        }
    }
    const queue = [...supplies];
    const result = [];
    // 使用头下标，避免 shift() 导致反复移动数组。
    for (let head = 0; head < queue.length; head++) {
        for (const i of dependents.get(queue[head]) || []) {
            if (--remaining[i] === 0) {
                result.push(recipes[i]);
                queue.push(recipes[i]);
            }
        }
    }
    return result;
};

Python

from collections import defaultdict, deque
from typing import List

class Solution:
    def findAllRecipes(self, recipes: List[str],
                       ingredients: List[List[str]],
                       supplies: List[str]) -> List[str]:
        dependents = defaultdict(list)
        remaining = [len(items) for items in ingredients]
        for i, items in enumerate(ingredients):
            for item in items:
                dependents[item].append(i)
        queue = deque(supplies)
        result = []
        while queue:
            item = queue.popleft()
            for i in dependents.get(item, ()):
                remaining[i] -= 1
                if remaining[i] == 0:
                    result.append(recipes[i])
                    queue.append(recipes[i])
        return result

C++

#include <queue>
#include <string>
#include <unordered_map>
#include <vector>
using namespace std;

class Solution {
public:
    vector<string> findAllRecipes(vector<string>& recipes,
            vector<vector<string>>& ingredients, vector<string>& supplies) {
        unordered_map<string, vector<int>> dependents;
        vector<int> remaining(recipes.size());
        for (int i = 0; i < (int)recipes.size(); ++i) {
            remaining[i] = (int)ingredients[i].size();
            for (const string& item : ingredients[i]) {
                dependents[item].push_back(i);
            }
        }
        queue<string> q;
        for (const string& item : supplies) q.push(item);
        vector<string> result;
        while (!q.empty()) {
            string item = q.front();
            q.pop();
            auto it = dependents.find(item);
            if (it == dependents.end()) continue;
            for (int i : it->second) {
                if (--remaining[i] == 0) {
                    result.push_back(recipes[i]);
                    q.push(recipes[i]);
                }
            }
        }
        return result;
    }
};
