题意与接口

设计 TwoSum 类，接收整数数据流，并判断仓内是否存在两个不同位置的整数之和等于查询值。同一个数值只有在实际加入至少两次时才能与自身配对。

核心洞察：库存数量决定补数是否可用

用哈希表记录每个数出现的频次。add 只需把对应计数加一；find(value) 遍历每个不同数字 x，查询补数 value - x。若两数不同，只要补数存在即可；若两数相同，则频次必须至少为 2，避免同一个元素被使用两次。

不同数配对

x != value - x

两个仓位都存在即可。

同值配对

x == value - x

该仓位计数必须至少为 2。

完整过程

  1. 1

    初始化频次表

    构造函数创建空哈希表，不预设任何数字。

  2. 2

    入库时累加计数

    每次 add(number) 把该数字的频次加一。

  3. 3

    查询补数

    对每个 x 计算 value - x 并检查库存。

  4. 4

    核对同值数量

    补数等于自身时要求计数至少为 2；否则立即返回 true。

边界与不变量

空仓查询：没有任何数时始终返回 false。
只加入一次：add(3) 后 find(6) 仍为 false。
加入两次：第二次 add(3) 后才允许 3 + 3。
负数与零：补数公式无需特殊分支。
溢出：Java/C++ 用长整数计算补数，再检查能否落回整数键范围。

替代方案：预计算所有和

维护数字频次外，再维护所有已存在配对的和。加入新数时，把它与仓内每个已有数字组成的和写入集合，随后 find 可在平均 O(1) 完成。代价是 add 变为 O(u)，所有和集合最坏达到 O(u²)。只有查询远多于入库且内存允许时才值得考虑。

面试追问

为什么不能只用 Set？

Set 会丢失重复次数，无法区分只有一个 3 与有两个 3 的情况。

如何根据调用比例选方案？

写多查少时优先频次表；查多写少时可以讨论预计算所有和，用写入时间与空间换查询速度。

能否提前用最小值和最大值剪枝？

可以作为常数优化，但会增加状态维护，核心哈希解法已满足本题约束。

常见错误

只存是否出现

无法判断同值配对是否真的有两个元素。

先命中自身

看到补数存在就返回 true，遗漏计数至少为 2 的条件。

补数溢出

固定宽度整数直接做 value - x 可能环绕。

误删查询数据

find 只读，不应改变频次表。

import java.util.HashMap;
import java.util.Map;

class TwoSum {
    private final Map<Integer, Integer> counts = new HashMap<>();

    public TwoSum() {}

    public void add(int number) {
        counts.put(number, counts.getOrDefault(number, 0) + 1);
    }

    public boolean find(int value) {
        for (Map.Entry<Integer, Integer> entry : counts.entrySet()) {
            int number = entry.getKey();
            long complementValue = (long) value - number;
            if (complementValue < Integer.MIN_VALUE ||
                complementValue > Integer.MAX_VALUE) {
                continue;
            }

            int complement = (int) complementValue;
            if (complement != number && counts.containsKey(complement)) {
                return true;
            }
            if (complement == number && entry.getValue() >= 2) {
                return true;
            }
        }
        return false;
    }
}
var TwoSum = function () {
  this.counts = new Map();
};

TwoSum.prototype.add = function (number) {
  this.counts.set(number, (this.counts.get(number) || 0) + 1);
};

TwoSum.prototype.find = function (value) {
  for (const [number, count] of this.counts) {
    const complement = value - number;
    if (complement !== number && this.counts.has(complement)) {
      return true;
    }
    if (complement === number && count >= 2) {
      return true;
    }
  }
  return false;
};
class TwoSum:
    def __init__(self):
        self.counts = {}

    def add(self, number: int) -> None:
        self.counts[number] = self.counts.get(number, 0) + 1

    def find(self, value: int) -> bool:
        for number, count in self.counts.items():
            complement = value - number
            if complement != number and complement in self.counts:
                return True
            if complement == number and count >= 2:
                return True
        return False
#include <climits>
#include <unordered_map>
using namespace std;

class TwoSum {
private:
    unordered_map<int, int> counts;

public:
    TwoSum() = default;

    void add(int number) {
        counts[number]++;
    }

    bool find(int value) {
        for (const auto& [number, count] : counts) {
            long long complementValue = static_cast<long long>(value) - number;
            if (complementValue < INT_MIN || complementValue > INT_MAX) {
                continue;
            }

            int complement = static_cast<int>(complementValue);
            if (complement != number && counts.count(complement)) {
                return true;
            }
            if (complement == number && count >= 2) {
                return true;
            }
        }
        return false;
    }
};
