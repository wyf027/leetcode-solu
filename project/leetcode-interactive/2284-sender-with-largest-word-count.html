2284. 最多单词数的发件人

Sender With Largest Word Count

谁在聊天中贡献了最多单词？先理解消息与发件人的对应关系，再亲手推进聊天记录。

阅读题目 ↓

01 / 题目

给定两个等长字符串数组 messages 和 senders。第 i 条消息为 messages[i]，由 senders[i] 发出。同一个人可以发送多条消息。

每条消息由一个或多个单词组成，单词之间恰好一个空格，首尾没有空格。把同一发件人的所有消息的单词数加起来，返回总数最多的发件人名字。如果总数并列，返回名字字典序最大的发件人。

名字区分大小写；大写英文字母排在小写英文字母前。"Alice" 与 "alice" 是两个人。比较到公共前缀末尾时，较长的名字字典序更大。

参数与返回：largestWordCount(messages: string[], senders: string[]) → string

约束

  • n == messages.length == senders.length，1 ≤ n ≤ 10⁴。
  • 1 ≤ messages[i].length ≤ 100。
  • 1 ≤ senders[i].length ≤ 10。
  • messages[i] 只含大小写英文字母和空格；单词用单个空格分隔，无前导或尾随空格。
  • senders[i] 只含大小写英文字母。

02 / 官方示例

示例 1

messages = ["Hello userTwooo","Hi userThree","Wonderful day Alice","Nice day userThree"]
senders = ["Alice","userTwo","userThree","Alice"]
输出 = "Alice"

Alice 两条消息共 2 + 3 = 5 个单词，userTwo 为 2 个，userThree 为 3 个，因此返回 Alice。

示例 2

messages = ["How is leetcode for everyone","Leetcode is useful for practice"]
senders = ["Bob","Charlie"]
输出 = "Charlie"

Bob 与 Charlie 都发送了 5 个单词，Charlie 的字典序更大，因此返回 Charlie。

05 / 独立题解

先尝试描述自己的统计规则，再展开推导与四种语言实现。

核心洞察

有效消息的单词数恰好是“空格数 + 1”。用哈希表保存每个名字的累计单词数，最终选出二元组 (累计单词数, 名字) 最大的人。先比数量，只有数量相等才比名字。

完整过程

  1. 建立名字到总词数的映射，初始为空。
  2. 遍历每一对消息和发件人，扫描消息字符，令单词数从 1 开始，每遇到一个空格加 1。
  3. 把这一条消息的词数加到该发件人已有总数上。
  4. 遍历汇总表。总数更大时替换答案；总数相同且名字字典序更大时也替换。
  5. 返回答案。官方示例 1 的账本依次变为 Alice:2、userTwo:2、userThree:3，最后 Alice:5。

实验台会显示已处理前缀的领先者，便于观察；下方提交代码先完整累计，再统一选最大值。

正确性说明

计数引理：含 k 个单词的有效消息有 k − 1 个分隔空格，因此空格数加 1 得到准确词数。

累计不变式：处理前 i 条消息后，每个名字在映射中的值等于它在这 i 条消息中的总词数。初始时为空成立；处理下一条时只给对应名字加上准确词数，其他名字不变，所以归纳成立。全部处理后得到真实总数。

选择不变式：遍历汇总项时，答案始终为已遍历项中按“总数优先、字典序次之”排序的最大项。只在新项更优时替换，因此遍历结束后答案就是题目要求的全局最大项。

边界与复杂度

单条单词消息没有空格，但词数仍为 1。多条消息可能属于同一人；不同大小写的名字必须分别统计。并列比较采用英文字母的字符顺序，不使用本地化排序。

令 L 为所有消息的字符总数，U 为不同发件人数，K 为最长名字长度。考虑名字哈希与比较，期望时间为 O(L + nK + UK)，额外空间为 O(UK)（计入名字存储）。本题 K ≤ 10，可写为期望时间 O(L + n)、空间 O(U)。哈希操作按通常的平均情况分析。

消息长至多 100，每条至多 50 个单词，累计不超过 500000；这些语言的常规整数足够容纳。

替代方案

  • 按空格 split 后取长度：表达直接，但会产生临时单词数组；扫描空格可避免分配。
  • 对汇总项按词数和名字排序：同样可行，但需要额外 O(U log U) 次比较；只找最大值不需要整体排序。
  • 边累计边维护领先者：因为词数只增加，更新后只需比较当前发件人与已有领先者，可省去最后一遍汇总扫描。

Java

import java.util.HashMap;
import java.util.Map;

class Solution {
    public String largestWordCount(String[] messages, String[] senders) {
        Map<String, Integer> totals = new HashMap<>();
        for (int i = 0; i < messages.length; i++) {
            int words = 1;
            for (int j = 0; j < messages[i].length(); j++) {
                if (messages[i].charAt(j) == ' ') words++;
            }
            totals.put(senders[i], totals.getOrDefault(senders[i], 0) + words);
        }
        String best = "";
        int max = -1;
        for (Map.Entry<String, Integer> entry : totals.entrySet()) {
            String name = entry.getKey();
            int count = entry.getValue();
            if (count > max || (count == max && name.compareTo(best) > 0)) {
                best = name;
                max = count;
            }
        }
        return best;
    }
}

from typing import List

class Solution:
    def largestWordCount(self, messages: List[str], senders: List[str]) -> str:
        totals = {}
        for message, sender in zip(messages, senders):
            words = message.count(' ') + 1
            totals[sender] = totals.get(sender, 0) + words
        best = ''
        maximum = -1
        for name, count in totals.items():
            if count > maximum or (count == maximum and name > best):
                best = name
                maximum = count
        return best

class Solution {

    string largestWordCount(vector<string>& messages, vector<string>& senders) {
        unordered_map<string, int> totals;
        for (size_t i = 0; i < messages.size(); ++i) {
            int words = 1;
            for (char ch : messages[i]) {
                if (ch == ' ') ++words;
            }
            totals[senders[i]] += words;
        }
        string best;
        int maximum = -1;
        for (const auto& entry : totals) {
            const string& name = entry.first;
            int count = entry.second;
            if (count > maximum || (count == maximum && name > best)) {
                best = name;
                maximum = count;
            }
        }
        return best;
    }
};

常见错误

  • 统计消息条数或字符数，忽略题目要求的是单词数。
  • 给同一发件人直接赋值覆盖，丢失旧消息贡献。
  • 并列时选字典序最小，或一律按最后出现的人更新。
  • 把名字转小写，导致不同发件人被合并。
  • Java 使用 == 比较字符串内容，或 JavaScript 使用 localeCompare 引入与本题字符顺序不同的本地化规则。

面试追问

消息是流式到达的？保存汇总表和当前领先者，更新一个发件人的总数后只比较它与领先者。

允许撤回消息呢？领先者的总数可能下降；仅比较被修改的人不够，可重新扫描全部发件人，或用有序结构维护排名。

允许连续空格、制表符或空消息？空格数加 1 不再正确，应按明确的单词边界规则处理，不能沿用本题格式假设。
