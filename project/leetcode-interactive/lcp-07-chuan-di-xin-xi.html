LCP 07 · EASY · GRAPH / DP

传递信息

第 0 位小朋友把信息沿有向关系传递。经过恰好 k 轮后，信息有多少条不同路径到达第 n - 1 位？

题目目标

计算信息在恰好 k 轮后，到达最后一位小朋友的路径数量。

开始演示 ↓

01 / 题意与约束

数的是“路径”，不是“能否到达”

每一轮必须传一次；同一终点若通过不同边序列到达，要分别计数。关系 relation[i] = [src, dst] 是有向边，节点编号为 0…n-1。

2 ≤ n ≤ 10节点
1 ≤ k ≤ 5轮数
边可重复?题目关系按条处理

02 / 状态定义

把“第几轮”放进状态

dp[t][u]
恰好传递 t 轮后，信息位于节点 u 的路径数。
初始化
dp[0][0] = 1；还没传时，只有起点拥有一条空路径。
转移
对每条 u → v：dp[t + 1][v] += dp[t][u]。
答案
dp[k][n - 1]，严格要求是第 k 轮，不可提前返回。

03 / LIVE LAB

逐轮传播：n = 5，k = 3

关系：0→2，2→1，3→4，2→3，1→4，2→0，0→4。

本轮路径分布

ROUND 0 / 3

初始时只有节点 0 有 1 条空路径。

dp[0] = [1, 0, 0, 0, 0]

演示已就绪

04 / 示例推演

三轮后为何是 3？

  1. 第 1 轮：0 可到 2、4。
  2. 第 2 轮：从 2 到 0、1、3；4 无出边。
  3. 第 3 轮：0→4、1→4、3→4，共 3 条。

05 / 复杂度

滚动数组即可

每轮扫描所有 m 条边，时间 O(km)；只保留上一轮和下一轮，空间 O(n)。二维表 O(kn) 更直观，但不是必需。

06 / 易错点

下一轮必须清零

不能原地更新同一个 dp，否则本轮新增值会继续传播，错误地多走边；也不能用 visited，因为不同路径需要累积，节点可重复到达。

四语言完整实现

统一使用一维滚动 DP；每段代码可直接提交。 

class Solution {
    public int numWays(int n, int[][] relation, int k) {
        int[] dp = new int[n];
        dp[0] = 1;
        for (int round = 0; round < k; round++) {
            int[] next = new int[n];
            for (int[] edge : relation) next[edge[1]] += dp[edge[0]];
            dp = next;
        }
        return dp[n - 1];
    }
}

08 / 自检清单

提交前，用这四问校验状态

  • ✓ 初值是否仅为 dp[0] = 1？
  • ✓ 每一轮是否创建全新的 next？
  • ✓ 每条边是否从上一轮读取、向下一轮累加？
  • ✓ 返回的是否是 dp[n - 1]？

快速生成模式：UI、算法对拍、四语言编译和交互验收待补。

隐藏解法：为什么 BFS 的 visited 不适用？
普通 BFS 求最短距离时，同一节点首次到达后可标记 visited。但本题要求统计恰好 k 条边的所有路径：两条不同路径抵达同一节点后，后续还会各自贡献路径数。因此保留的是“数量”而非“是否访问过”。本题规模很小，邻接矩阵快速幂也能建模为矩阵乘法，但滚动 DP 最直观、常数也更小。
