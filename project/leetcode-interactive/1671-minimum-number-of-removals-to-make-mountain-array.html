Mountain subsequence lab

得到山形数组的最少删除次数

不要急着删除元素。先把数组中每个位置都当成候选峰顶，观察它左边能爬多高、右边能下降多远，再决定哪座“山”值得保留。

Problem

题目描述

若数组长度至少为 3，并且存在一个既不是首项也不是末项的下标 i，使得数组从开头到 i 严格递增、再从 i 到末尾严格递减，那么它是山形数组。

给定整数数组 nums，你可以删除任意元素而保持其余元素的相对顺序。返回把它变为山形数组所需的最少删除次数。题目保证答案存在。

示例 1
输入：nums = [1,3,1]
输出：0
解释：数组本身已严格上升后严格下降。
示例 2
输入：nums = [2,1,1,5,6,2,3,1]
输出：3
解释：可删除原下标 0、1、5，
得到 [1,5,6,3,1]。

约束

  • 3 <= nums.length <= 1000
  • 1 <= nums[i] <= 109
  • 一定可以通过删除若干元素得到山形数组。

Solution

把最少删除，反过来看成最多保留

核心洞察

删除后保留下来的元素仍然是原数组的一个子序列。因此问题等价于：寻找最长的山形子序列。若它的长度为 best，答案就是 n - best。

对每个位置 i 预计算两个量：

left[i] = 以 i 结尾的最长严格递增子序列长度
right[i] = 以 i 开始的最长严格递减子序列长度

只有 left[i] > 1 且 right[i] > 1 时，i 才能成为真正的峰顶。以它为峰的最长山形长度为 left[i] + right[i] - 1；峰顶在两边都计算过，所以减一。

完整过程

  1. 把 left 全部初始化为 1。由左到右枚举 i，再枚举所有 j < i；若 nums[j] < nums[i]，用 left[j] + 1 更新 left[i]。
  2. 把 right 全部初始化为 1。由右到左枚举 i，再枚举所有 j > i；若 nums[j] < nums[i]，用 right[j] + 1 更新 right[i]。
  3. 枚举所有非首尾位置，只考虑两侧长度都大于 1 的峰顶，取最大山形长度。
  4. 返回数组长度减去最大山形长度。

正确性证明

  1. 左半边最优。 按状态转移，left[i] 枚举了递增子序列在 i 之前可能的最后一个位置，因此恰好是以 i 结尾的最长严格递增子序列。
  2. 右半边最优。 对称地，right[i] 枚举了下降子序列中紧随 i 的位置，因此恰好是以 i 开始的最长严格递减子序列。
  3. 固定峰顶最优。 当两侧长度均大于 1 时，把上述两个最优子序列在共同峰顶 i 处拼接，得到长度 left[i] + right[i] - 1 的合法山形子序列。任何以 i 为峰的山形子序列，其两半都不可能超过这两个最优值。
  4. 全局最优。 每个合法山形子序列都有且只有一个峰顶。算法枚举所有可能峰顶并取最大值，所以找到最长山形子序列；删去其余元素的次数 n - best 必然最少。

边界处理

  • 相等元素不能连接，因为两侧都要求严格单调。
  • left[i] == 1 或 right[i] == 1 的位置不是峰顶。
  • 首尾无需作为峰顶检查。
  • 题目保证至少存在一个合法答案。

复杂度

朴素动态规划时间复杂度 O(n²)，空间复杂度 O(n)。在 n <= 1000 的约束下足够直接、稳定。

class Solution {
    public int minimumMountainRemovals(int[] nums) {
        int n = nums.length;
        int[] left = new int[n];
        int[] right = new int[n];
        java.util.Arrays.fill(left, 1);
        java.util.Arrays.fill(right, 1);

        for (int i = 0; i < n; i++) {
            for (int j = 0; j < i; j++) {
                if (nums[j] < nums[i]) {
                    left[i] = Math.max(left[i], left[j] + 1);
                }
            }
        }
        for (int i = n - 1; i >= 0; i--) {
            for (int j = n - 1; j > i; j--) {
                if (nums[j] < nums[i]) {
                    right[i] = Math.max(right[i], right[j] + 1);
                }
            }
        }

        int best = 0;
        for (int i = 1; i < n - 1; i++) {
            if (left[i] > 1 && right[i] > 1) {
                best = Math.max(best, left[i] + right[i] - 1);
            }
        }
        return n - best;
    }
}

        left = [1] * n
        right = [1] * n

        for i in range(n):
            for j in range(i):
                if nums[j] < nums[i]:
                    left[i] = max(left[i], left[j] + 1)

        for i in range(n - 1, -1, -1):
            for j in range(n - 1, i, -1):

        for i in range(1, n - 1):
            if left[i] > 1 and right[i] > 1:
                best = max(best, left[i] + right[i] - 1)

替代方案

可用“耐心排序 + 二分查找”分别计算每个位置的 LIS/LDS 长度，把时间复杂度降为 O(n log n)。关键是记录每个位置的长度，而不只是全局 LIS 长度。当前约束只有 1000，O(n²) 更容易在面试中解释和证明。

面试追问

  • 为什么不能只找一个 LIS 再找下降段？ 因为全局 LIS 的结尾未必能接上合法下降段，必须按同一个峰顶配对。
  • 如何优化到 O(n log n)？ 维护最小结尾数组，用二分得到每个位置作为结尾的 LIS 长度；反向再做一次。
  • 如何恢复实际删除方案？ 在两侧 DP 中额外记录前驱/后继，从最优峰顶分别回溯并合并索引。
  • 若允许非严格单调呢？ 比较符号和二分边界都要调整；本题必须严格，重复值不能直接相连。

常见错误

  • 把比较写成 <=，错误接纳相等元素。
  • 遗漏 left[i] > 1 && right[i] > 1，把单边序列当成山。
  • 合并两边长度时忘记减去重复计算的峰顶。
  • 误把“删除”理解为连续区间删除；实际保留的是任意子序列。
  • 反向 DP 的比较方向写反：需要寻找位于右侧且值更小的元素。
