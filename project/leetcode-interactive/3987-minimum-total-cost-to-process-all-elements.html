处理所有元素的成本

资源不够时按固定步长 k 补给；补给次数越多，边际成本越高。真正要最小化的，是整个过程必须发生的补给次数。

难度：Medium时间：O(n)空间：O(1)资源模拟

01题意

给定 nums 与固定补给量 k。初始资源为 k，必须从左到右处理每个元素；处理 nums[i] 要消耗同样多的资源。

若当前资源不足，可以反复执行补给：每次资源增加 k，而第 1、2、3… 次补给的成本分别是 1、2、3…。求处理完所有元素的最小总成本（模 1_000_000_007）。

可见空格：nums = [1, 2, 3, 4] 中逗号后的普通空格仅用于阅读；输入框中会按原样解析数字。

约束

  • 1 ≤ nums.length ≤ 10^5
  • 1 ≤ nums[i], k ≤ 10^9
  • 计数和中间资源必须使用 64 位整数。

02示例

示例 A

输入：nums = [1, 2, 3, 4]

k = 4，输出：3

需要 2 次补给，成本为 1 + 2。

示例 B

输入：nums = [1, 1, 7, 14]

k = 4，输出：15

总共补 5 次，成本为 1 + … + 5。

示例 C

输入：nums = [1, 2, 3, 4]

k = 10，输出：0

05题解

核心洞察

第 t 次补给的成本固定为 t。因此若一共补给 cnt 次，总成本必为 cnt × (cnt + 1) / 2；要让成本最小，只要每次资源不足时恰好补到能处理当前元素即可。

完整过程

  1. 维护当前资源 cur = k 与总补给次数 cnt = 0。
  2. 遇到 x，若 cur < x，补 m = ceil((x - cur) / k) 次。
  3. cur += m × k，cnt += m，然后 cur -= x。
  4. 最后返回 cnt(cnt+1)/2 mod MOD。

边界

  • 一个元素可以一次触发多次补给。
  • 所有元素总和很大，cur 与 cnt 用 64 位。
  • 先对 cnt 取模再算三角数，避免乘法过大。

复杂度

O(n) 时间，O(1) 额外空间。

替代方案

可以把总缺口折算为补给次数，但仍需按前缀判断何时资源不足；直接模拟更不易漏掉“跨元素剩余资源”。

常见错误

  • 把不足量除以 k 向下取整。
  • 每次只补一次，忘记 x 可能远大于 cur + k。
  • 将补给成本逐次累加，导致不必要的慢循环。

面试追问

若每次补给量不固定，或成本不是线性递增，贪心是否仍成立？此时要先检查“补到刚够用”是否仍支配其他方案。

四种可提交代码

class Solution {
    public int minimumCost(int[] nums, int k) {
        final long MOD = 1_000_000_007L;
        long cur = k, cnt = 0;
        for (int x : nums) {
            if (cur < x) {
                long add = ((long) x - cur + k - 1) / k;
                cur += add * k;
                cnt += add;
            }
            cur -= x;
        }
        cnt %= MOD;
        return (int) (cnt * (cnt + 1) / 2 % MOD);
    }
}
var minimumCost = function(nums, k) {
  const MOD = 1000000007n;
  let cur = BigInt(k), cnt = 0n, step = BigInt(k);
  for (const value of nums) {
    const x = BigInt(value);
    if (cur < x) {
      const add = (x - cur + step - 1n) / step;
      cur += add * step;
      cnt += add;
    }
    cur -= x;
  }
  cnt %= MOD;
  return Number(cnt * (cnt + 1n) / 2n % MOD);
};
