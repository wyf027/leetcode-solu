LEETCODE · 4014 MEDIUM

GREEDY · EXCHANGE ARGUMENT

应用折扣后的
最低总价

商品与折扣券都只能使用一次。秘诀不是枚举配对，而是把“最小付款”翻译成“最大节省”：让最大的百分比命中最高的价格。

打开配对实验台

题目契约

输入
prices 与 discounts 两个正整数数组。
规则
每张券、每件商品至多匹配一次；商品也可不打折。
结算
价格 p 用 d% 后为 p × (100-d) / 100，不四舍五入。
约束
1 ≤ n,m ≤ 10⁵，价格 ≤ 10⁵，折扣为 1..100。

OBJECTIVE SHIFT

付款最小 = 节省最大

一对 (p,d) 节省 p×d/100。原价总和固定，只需最大化这些乘积之和。

EXCHANGE

大的配大的，交换不会更差

若 p₁≤p₂、d₁≤d₂，则 p₂d₂+p₁d₁ − (p₂d₁+p₁d₂)=(p₂-p₁)(d₂-d₁)≥0。

完整过程

  1. 1. 排序

    两个数组升序排列；不会改变可用商品或券的集合。

  2. 2. 取末端

    每次让当前最大价格配当前最大折扣，两个指针左移。

  3. 3. 补原价

    券或商品耗尽后，剩余商品按原价计入。

洞察、边界与替代方案

为什么所有折扣都应使用？

折扣为正且不超过 100，应用任何未使用折扣都不会增大价格；最多只能给 min(n,m) 件商品。配对后的乘积越大，节省越多。

边界

  • • 券比商品多：只取最大的 n 张券。
  • • 商品比券多：剩余商品按原价计入。
  • • 100% 折扣：对应商品结算为 0。
  • • 结果是小数：使用浮点数并按题意允许 10⁻⁵ 误差。

复杂度与替代

排序主导，时间 O(n log n + m log m)；若忽略语言排序实现的栈，额外空间为 O(1)。暴力枚举匹配是阶乘级；二分图最大权匹配也能做却远重于本题结构。

追问与常见错误

若商品有类别限制或一张券可叠加，交换论证的前提被破坏，需要重新建模。常见错误是给便宜商品先用最大券、遗漏未打折商品、或把最终价格错误四舍五入。

class Solution {
  public double minPrice(int[] prices, int[] discounts) {
    Arrays.sort(prices); Arrays.sort(discounts);
    double ans = 0; int j = discounts.length - 1;
    for (int i = prices.length - 1; i >= 0; --i)
      ans += j >= 0 ? prices[i] * (100 - discounts[j--]) / 100.0 : prices[i];
    return ans;
  }
}
