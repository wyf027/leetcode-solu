FIND SMALLEST COMMON ELEMENT IN ALL ROWS

找出所有行中最小公共元素

给定一个按行严格递增的整数矩阵 mat，找出每一行都出现过的最小整数；如果不存在这样的整数，返回 -1。

先自己想一想： 行内无重复。如果把每个值“遇到过的行数”记下来，什么时候可以确认它属于所有行？又怎样保证返回的是最小值？
函数
smallestCommonElement(mat)
返回
最小公共整数；不存在则 -1

示例 1

输入：mat = [[1,2,3,4,5],
             [2,4,5,8,10],
             [3,5,7,9,11],
             [1,3,5,7,9]]
输出：5
解释：5 出现在每一行，并且是满足条件的最小值。

示例 2

输入：mat = [[1,2,3],
             [2,3,4],
             [2,3,5]]
输出：2
解释：2 和 3 都出现在每一行，较小者为 2。

约束

  • m == mat.length，n == mat[i].length
  • 1 ≤ m, n ≤ 500
  • 1 ≤ mat[i][j] ≤ 10⁴
  • 每一行中的元素严格递增，因此同一行没有重复值。

完整题解

计数：把“出现次数”变成“出现行数”

O(mn) 时间 · O(U) 空间

核心洞察

每行严格递增意味着一个值在同一行最多出现一次。因此遍历所有单元格并累加频次时，count[x] 恰好等于包含 x 的行数。若它等于总行数 m，x 就是公共元素。

全部计数完成后，从第一行由左到右检查。第一行本身递增，所以遇到的第一个 count[x] == m 的值就是最小公共元素；若没有则返回 -1。

完整过程

  1. 创建频次数组（或哈希表）count。
  2. 遍历矩阵中的每个值 x，执行 count[x]++。
  3. 按严格递增顺序扫描第一行。
  4. 若某个值的计数等于行数，立即返回；扫描结束仍未找到则返回 -1。

正确性证明

引理 1：频次就是包含该值的行数

由于任意一行都严格递增，同一个值不可能在一行内重复。每行包含某值时只会为其频次贡献一次，不包含则不贡献。因此 count[x] 精确等于包含 x 的行数。

引理 2：算法返回的值属于所有行

算法只在 count[x] == m 时返回 x。由引理 1，恰有全部 m 行包含它，所以它是公共元素。

引理 3：算法返回最小公共元素

算法按第一行的递增次序检查候选值。任何公共元素必然在第一行；第一个满足条件的值因此小于所有尚未检查的第一行元素，即为最小公共元素。

结论

若存在公共元素，算法返回其中最小者；若不存在，没有计数能达到 m，算法返回 -1。故算法正确。

边界情况

  • 只有一行：这一行的最小值就是答案。
  • 只有一列：仅当所有行的该值相等时返回它。
  • 没有交集：第一行所有值的计数都小于行数，返回 -1。
  • 答案较大：不能看到早期重复就返回，必须确认它出现于每一行。

复杂度

令矩阵有 m 行、n 列，值域上界为 U。遍历矩阵耗时 O(mn)，扫描第一行耗时 O(n)，总时间为 O(mn)。计数数组空间为 O(U)；改用哈希表时为 O(k)，其中 k 是不同值数量。

class Solution {
    public int smallestCommonElement(int[][] mat) {
        int[] count = new int[10001];
        for (int[] row : mat) {
            for (int value : row) {
                count[value]++;
            }
        }

        for (int value : mat[0]) {
            if (count[value] == mat.length) {
                return value;
            }
        }
        return -1;
    }
}

替代方案

逐值二分：遍历第一行的每个值，在其余每行用二分查找。时间 O(nm log n)，额外空间 O(1)。它利用了行有序，但通常比值域计数慢；当值域很大、希望节省计数空间时更合适。

多指针归并：为每行维护一个指针，不断把落后的行推进到当前最大值，直至所有行相等或某行耗尽。时间可达 O(mn)、空间 O(m)，但实现与证明更复杂。

面试追问

  • 如果每行允许重复，如何避免同一行对频次重复贡献？（按行去重，或记录某值最后一次计数的行号。）
  • 如果值域不再是 10⁴，计数数组应如何替换？（哈希表或逐值二分。）
  • 如果数据以流式逐行到达，怎样尽早淘汰不可能成为公共元素的候选？
  • 能否只用第一行作为候选集合，并在每处理一行后缩小集合？

常见错误

  • 把总出现次数等于 m 直接当作公共元素，却忽略“行内无重复”这一必要前提。
  • 按哈希表的遍历顺序返回第一个公共值，无法保证最小。
  • 只统计第一行与第二行的交集，没有继续和剩余行求交。
  • 使用固定长度数组时忽略题目的值域上界，导致越界。
