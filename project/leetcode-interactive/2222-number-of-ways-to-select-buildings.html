01 / 题目

按街道顺序选择 3 栋建筑

给定下标从 0 开始的二进制字符串 s。'0' 代表办公楼，'1' 代表餐厅。选出三个不同下标 i < j < k，要求选中序列中相邻建筑类型不同，即 s[i] ≠ s[j] 且 s[j] ≠ s[k]。返回有效下标组合的数量。

“相邻”指选出来的建筑在所选序列中相邻，不要求它们在原街道上连续。不同下标组合即不同方案，即使建筑类型序列相同。

官方示例 1

输入：s = "001101"
输出：6

合法下标集合为 [0,2,4]、[0,3,4]、[1,2,4]、[1,3,4]、[2,4,5]、[3,4,5]。前四组形成 010，后两组形成 101。

官方示例 2

输入：s = "11100"
输出：0

任意选择都无法使相邻的所选建筑类型不同，因此没有合法方案。

参数与约束

  • 参数：s: string；返回值：方案数（整数）。
  • 3 ≤ s.length ≤ 10⁵。
  • s[i] 只能是 '0' 或 '1'。

03 / 题解与计数实验室

让每栋建筑轮流站在中间

核心洞察

合法的类型序列只有 010 和 101。固定中间下标 j，左边和右边都必须选与 s[j] 相反的类型。若左边有 L 栋可选、右边有 R 栋可选，这个中点就贡献 L × R 个方案。

答案 = Σ（左侧异类数量 × 右侧异类数量）。每个三元组只归属于它唯一的中间下标。

街道实验 · 左右配对

轮廓框标出中点；深绿色标出左右可选建筑，文字同时标记角色。每一对左右建筑与中点组成一个方案。

演示限制 3–24 个 0/1，以便逐一展示；提交算法支持题目完整规模。

按钮支持 Tab 聚焦、Enter / 空格操作。自动播放可随时暂停；减少动态效果偏好下使用更慢的离散切换。

完整过程

  1. 先遍历字符串，统计每种类型的总数，存入 right[0]、right[1]；初始化 left = [0, 0] 和答案 0。
  2. 从左到右枚举中点。令当前类型为 x，先执行 right[x]--，让 right 只包含中点右侧的建筑。
  3. 另一类型为 y = 1 - x。将 left[y] × right[y] 加入答案。
  4. 执行 left[x]++，把当前建筑放入下一轮的左侧。遍历完返回答案。

对于 s = "001101"，中点从 0 到 5 的贡献依次是 0, 0, 2, 2, 2, 0，因此总数是 6。以 j = 2 为例，左侧办公楼下标为 0、1，右侧办公楼下标为 4，贡献 2 × 1 = 2。

正确性证明

计数不变量：处理下标 j、扣除当前建筑后，left 与 right 分别准确表示区间 [0,j) 与 (j,n) 的类型数量。初始左侧为空，右侧从总数扣除当前项；每轮结束把当前项加入 left，下一轮再从 right 移走新中点，不变量持续成立。

合法性：每次贡献只从 j 左右两侧选异类，故 i < j < k，且相邻所选类型不同。左右选择相互独立，乘法原理得到 L×R。

完备且无重复：任意合法三元组都有唯一中点 j，其左右端点都在本轮异类候选中，因此一定被计入；不同中点不可能计入同一个三元组。累加所有贡献便恰好得到全部合法方案。

边界与数值范围

  • 最左和最右的建筑不能贡献方案，因为其中一侧为空。
  • 全为一种类型，或者只有 000…111… 这样的两段，答案为 0。
  • 长度为 3 时，仅 010 和 101 返回 1，其余返回 0。
  • 答案不超过 C(n,3)，在 n = 10⁵ 时小于 1.67 × 10¹⁴。Java 用 long、C++ 用 long long；JavaScript 的 Number 在此范围内仍可精确表示整数，Python 整数可直接使用。

复杂度

两次线性遍历，时间 O(n)；只维护两个长度为 2 的计数数组和答案，额外空间 O(1)。演示为展示组合而枚举左右配对，其开销不代表提交算法。

四种语言 · 完整提交代码

使用官方函数签名；四份代码实现同一中点计数法，均待补验证。

Java

class Solution {
    public long numberOfWays(String s) {
        long[] left = new long[2];
        long[] right = new long[2];
        for (int i = 0; i < s.length(); i++) {
            right[s.charAt(i) - '0']++;
        }
        long answer = 0;
        for (int i = 0; i < s.length(); i++) {
            int x = s.charAt(i) - '0';
            right[x]--;
            answer += left[1 - x] * right[1 - x];
            left[x]++;
        }
        return answer;
    }
}

var numberOfWays = function(s) {
    const left = [0, 0];
    const right = [0, 0];
    for (const c of s) right[Number(c)]++;
    let answer = 0;
    for (const c of s) {
        const x = Number(c);
        right[x]--;
        answer += left[1 - x] * right[1 - x];
        left[x]++;
    }
    return answer;
};

Python

class Solution:
    def numberOfWays(self, s: str) -> int:
        left = [0, 0]
        right = [s.count('0'), s.count('1')]
        answer = 0
        for c in s:
            x = int(c)
            right[x] -= 1
            answer += left[1 - x] * right[1 - x]
            left[x] += 1
        return answer

C++

#include <string>
using std::string;

class Solution {
public:
    long long numberOfWays(string s) {
        long long left[2] = {0, 0};
        long long right[2] = {0, 0};
        for (char c : s) ++right[c - '0'];
        long long answer = 0;
        for (char c : s) {
            int x = c - '0';
            --right[x];
            answer += left[1 - x] * right[1 - x];
            ++left[x];
        }
        return answer;
    }
};

替代方案

流式动态规划：维护单字符数量 n0、n1，二字符子序列数量 n01、n10 和答案。遇到 0 时按顺序执行 answer += n01、n10 += n1、n0++；遇到 1 时执行 answer += n10、n01 += n0、n1++。这同样是 O(n) 时间、O(1) 空间，而且不需要预先知道右侧总数，适合流式输入。

前缀和数组：预存每个位置前的 0/1 数量，用总数减去前缀得到右侧，仍枚举中点；时间 O(n)，额外空间 O(n)，方便多次区间计数。直接枚举所有三元组则是 O(n³)，仅适合很短输入的概念演示。

常见错误

  • 把子序列当成连续子串，只检查长度为 3 的窗口，会漏掉跨越建筑的方案。
  • 只统计 010，遗漏 101；或者按类型串去重，错误合并不同下标方案。
  • 把 L + R 当贡献，忽略每个左端点都能与每个右端点组合。
  • 使用 32 位整数存储答案；Java 中先进行 int 乘法再转 long 也可能已溢出。
  • 混用“包含中点”的计数与严格左右区间计数。按照先移出 right、计算、再加入 left 的统一顺序最容易维护不变量。

面试追问

  • 输入只能读取一次？改用上述流式动态规划，不需要右侧信息。
  • 要选 k 栋且类型交替？按已选长度和末尾类型维护 DP，每读一个字符从大到小更新长度；时间 O(nk)，空间 O(k)，同时重新评估整数范围。
  • 为什么不需要集合去重？组合由下标确定，固定唯一中点已经实现互不重叠的划分。
  • 字符串规模变大，JS 仍能用 Number 吗？先比较答案上界与 2⁵³−1，超出时计数与乘法统一改用 BigInt。
