01 / Problem

任务说明

实现一个不依赖内建哈希表库的映射。

设计 MyHashMap：保存整数键和值，支持插入或更新、查询与删除。查询不存在的键时返回 -1。

  • MyHashMap()用空映射初始化对象。
  • put(key, value)插入键值对；若键已存在，则更新它的值。
  • get(key)返回键对应的值；不存在时返回 -1。
  • remove(key)若键存在，删除它及其对应的值。

约束

  • 0 <= key, value <= 106
  • put、get 和 remove 合计最多调用 104 次。
官方示例 · 完整参数形式
输入
["MyHashMap","put","put","get","get","put","get","remove","get"]
[[],[1,1],[2,2],[1],[3],[2,1],[2],[2],[2]]

输出
[null,null,null,1,-1,null,1,null,-1]

解释
MyHashMap myHashMap = new MyHashMap();
myHashMap.put(1, 1); // [[1,1]]
myHashMap.put(2, 2); // [[1,1],[2,2]]
myHashMap.get(1);    // 1
myHashMap.get(3);    // -1
myHashMap.put(2, 1); // [[1,1],[2,1]]，更新旧值
myHashMap.get(2);    // 1
myHashMap.remove(2); // [[1,1]]
myHashMap.get(2);    // -1

Solution unlocked

分离链表：桶定位 + 桶内查找

Separate Chaining

核心洞察

哈希函数只负责把键送到某个桶，不能保证不同键落在不同桶。每个桶保存若干 [key, value]，碰撞时就在该桶内按键查找。

为什么选 1009 个桶？

1009 是质数，在本题整数键范围内能得到较均匀的余数分布。它不是唯一选择，关键是控制装载因子与碰撞长度。

完整过程

  1. 初始化长度为 1009 的桶数组，每个桶是空链/空列表。
  2. 用 index = key % 1009 找到目标桶。
  3. put：桶内命中同键就更新；否则追加新键值对。
  4. get：桶内逐个比较键，命中返回值，否则返回 -1。
  5. remove：桶内命中同键后摘除对应节点。

边界处理

  • key = 0、value = 0 都是合法输入，不能把 0 当作“空”。
  • 重复 put 必须更新，不能保留两个相同键。
  • 删除不存在的键应保持原状，不报错。
  • 值可能为 10^6，而 -1 专门表示未找到。

正确性说明

不变式：每个已存键 k 恰好出现于桶 k % 1009 中，且该桶内只有一个节点的键等于 k。初始化时不变式显然成立。put 只在目标桶更新唯一同键节点或新增一个节点；remove 只删除该唯一节点，因此不变式保持。get 检查目标桶的全部节点：若键存在必被找到，若遍历结束仍未命中，则依据不变式该键不在映射中，所以返回 -1。因此三个操作均符合接口定义。

O(1)平均 put / get / remove
O(n)极端碰撞时单次最坏
O(n + B)空间，B = 1009 个桶

Implementations

四语言完整代码

Java 
class MyHashMap {
    private static final int SIZE = 1009;
    private final Node[] buckets = new Node[SIZE];

    private static class Node {
        int key;
        int value;
        Node next;

        Node(int key, int value, Node next) {
            this.key = key;
            this.value = value;
            this.next = next;
        }
    }

    public MyHashMap() {}

    public void put(int key, int value) {
        int index = key % SIZE;
        for (Node node = buckets[index]; node != null; node = node.next) {
            if (node.key == key) {
                node.value = value;
                return;
            }
        }
        buckets[index] = new Node(key, value, buckets[index]);
    }

    public int get(int key) {
        int index = key % SIZE;
        for (Node node = buckets[index]; node != null; node = node.next) {
            if (node.key == key) return node.value;
        }
        return -1;
    }

    public void remove(int key) {
        int index = key % SIZE;
        Node dummy = new Node(-1, -1, buckets[index]);
        Node current = dummy;
        while (current.next != null) {
            if (current.next.key == key) {
                current.next = current.next.next;
                break;
            }
            current = current.next;
        }
        buckets[index] = dummy.next;
    }
}
JavaScript 
var MyHashMap = function() {
    this.size = 1009;
    this.buckets = Array.from({ length: this.size }, () => []);
};

/** @param {number} key @param {number} value @return {void} */
MyHashMap.prototype.put = function(key, value) {
    const bucket = this.buckets[key % this.size];
    for (const pair of bucket) {
        if (pair[0] === key) {
            pair[1] = value;
            return;
        }
    }
    bucket.push([key, value]);
};

/** @param {number} key @return {number} */
MyHashMap.prototype.get = function(key) {
    const bucket = this.buckets[key % this.size];
    for (const [storedKey, value] of bucket) {
        if (storedKey === key) return value;
    }
    return -1;
};

/** @param {number} key @return {void} */
MyHashMap.prototype.remove = function(key) {
    const bucket = this.buckets[key % this.size];
    const index = bucket.findIndex((pair) => pair[0] === key);
    if (index !== -1) bucket.splice(index, 1);
};
Python 
class MyHashMap:
    SIZE = 1009

    def __init__(self):
        self.buckets = [[] for _ in range(self.SIZE)]

    def put(self, key: int, value: int) -> None:
        bucket = self.buckets[key % self.SIZE]
        for pair in bucket:
            if pair[0] == key:
                pair[1] = value
                return
        bucket.append([key, value])

    def get(self, key: int) -> int:
        bucket = self.buckets[key % self.SIZE]
        for stored_key, value in bucket:
            if stored_key == key:
                return value
        return -1

    def remove(self, key: int) -> None:
        bucket = self.buckets[key % self.SIZE]
        for index, (stored_key, _) in enumerate(bucket):
            if stored_key == key:
                bucket.pop(index)
                return
C++ 
#include <list>
#include <utility>
#include <vector>
using namespace std;

class MyHashMap {
private:
    static const int SIZE = 1009;
    vector<list<pair<int, int>>> buckets;

public:
    MyHashMap() : buckets(SIZE) {}

    void put(int key, int value) {
        auto& bucket = buckets[key % SIZE];
        for (auto& entry : bucket) {
            if (entry.first == key) {
                entry.second = value;
                return;
            }
        }
        bucket.push_back({key, value});
    }

    int get(int key) {
        auto& bucket = buckets[key % SIZE];
        for (const auto& entry : bucket) {
            if (entry.first == key) return entry.second;
        }
        return -1;
    }

    void remove(int key) {
        auto& bucket = buckets[key % SIZE];
        for (auto it = bucket.begin(); it != bucket.end(); ++it) {
            if (it->first == key) {
                bucket.erase(it);
                return;
            }
        }
    }
};

Alternatives

替代方案

直接寻址数组

创建长度 1,000,001 的数组，所有操作严格 O(1)，实现最短；但空间按键域分配，即使只存很少键也会占用大量内存。

动态扩容 + 开放寻址

更接近工业 HashMap，通过探测处理碰撞并按装载因子扩容；空间局部性更好，但删除标记、再哈希与摊还分析更复杂。

Pitfalls

常见错误

把 value = 0 当空位

0 是合法值。应通过节点是否存在判断，而不是通过值判断。

重复键继续追加

put 命中同键时要更新并立即返回，否则查询会遇到多个版本。

只按哈希值判断相等

不同键可能同桶，桶内仍必须比较原始 key。

删除链表头时断链

使用哑节点，或单独处理头节点，确保删除后桶头指针正确。

Interview follow-ups

面试追问

如果键允许为负数，取模要注意什么？

某些语言的负数余数仍为负，需要归一化为 ((key % size) + size) % size，再作为数组下标。

如何避免最坏情况退化为 O(n)？

使用更均匀的哈希函数、随机化、按装载因子扩容；也可在长链达到阈值时把桶转换为平衡树，将桶内查找降为 O(log n)。

什么时候需要扩容？

当元素数与桶数之比（装载因子）超过设定阈值时，创建更大的桶数组并重新哈希所有元素。扩容单次昂贵，但可摊还。

并发环境下还缺什么？

需要同步策略，例如分段锁、桶级锁或无锁结构；同时要处理扩容期间的可见性与迁移一致性。
