数组拆分

Array Partition · 把排好序的数字两两相邻配对，让每一对的较小值尽可能“少受损”。

EASY · 免费题

题目

给定一个包含 2n 个整数的数组 nums。将它们分成 n 对 (aᵢ, bᵢ)，使所有数对较小值之和 Σ min(aᵢ, bᵢ) 最大，返回这个最大和。

函数形式

arrayPairSum(nums: integer[]) -> integer

约束

  • 1 ≤ n ≤ 10⁴
  • nums.length == 2 * n
  • -10⁴ ≤ nums[i] ≤ 10⁴

官方示例

示例 1
输入：nums = [1,4,3,2]
输出：4
解释：最优配对为 (1,2)、(3,4)，较小值之和为 1 + 3 = 4。
示例 2
输入：nums = [6,2,6,5,1,2]
输出：9
解释：可配成 (1,2)、(2,5)、(6,6)，较小值之和为 1 + 2 + 6 = 9。

Solution

排序 + 贪心

核心洞察

一个数只有在它是数对中的较小值时才贡献分数。排序后，把相邻元素配对，便能让每个较小元素牺牲给“离它最近”的较大元素，避免用过大的数去陪很小的数。答案正是排序后下标 0, 2, 4, ... 的元素之和。

完整过程

  1. 将 nums 按非降序排序。
  2. 从下标 0 开始，每隔一个元素累加一次。
  3. 返回累加结果。

正确性证明

设排序结果为 x₁ ≤ x₂ ≤ … ≤ x₂ₙ。全体元素中最小的 x₁ 无论和谁配对，都会成为较小值；让它与 x₂ 配对，不会降低 x₁ 的贡献，同时把更大的元素留给后续数对。移除这两个元素后，对剩余有序序列重复同一论证。由归纳可得，相邻配对最优，其和为 x₁ + x₃ + … + x₂ₙ₋₁。

边界与复杂度

  • 负数同样适用；排序关系和论证不变。
  • 重复值无需特殊处理。
  • 时间复杂度 O(n log n)，主要来自排序；额外空间取决于语言排序实现，累加本身为 O(1)。

替代方案

由于值域固定在 [-10⁴, 10⁴]，可用计数排序按出现次数扫描值域，并交替选择元素，达到 O(n + K) 时间、O(K) 空间，其中 K = 20001。

面试追问

  • 如果数值范围极小，如何用计数排序避免比较排序？
  • 若目标改成最大化每对较大值之和，选择规律如何变化？
  • 如何用交换论证严格说明交叉配对不会更优？

常见错误

  • 排序后累加奇数下标，而不是从 0 开始的偶数下标。
  • 只考虑正数，误以为负数需要反向排序。
  • 枚举所有配对，导致指数级复杂度。

四语言完整代码

Java
import java.util.Arrays;

class Solution {
    public int arrayPairSum(int[] nums) {
        Arrays.sort(nums);
        int sum = 0;
        for (int i = 0; i < nums.length; i += 2) {
            sum += nums[i];
        }
        return sum;
    }
}

from typing import List

class Solution:
    def arrayPairSum(self, nums: List[int]) -> int:
        nums.sort()
        return sum(nums[::2])
C++
#include <algorithm>
#include <vector>
using namespace std;

class Solution {
public:
    int arrayPairSum(vector<int>& nums) {
        sort(nums.begin(), nums.end());
        int sum = 0;
        for (int i = 0; i < nums.size(); i += 2) {
            sum += nums[i];
        }
        return sum;
    }
};
