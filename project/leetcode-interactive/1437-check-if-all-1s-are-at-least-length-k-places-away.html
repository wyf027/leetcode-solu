是否所有 1 都至少相隔 k 个元素

Check If All 1's Are at Least Length K Places Away

Problem

题目描述

给定一个只包含 0 和 1 的数组 nums，以及整数 k。如果任意两个相邻出现的 1 之间都至少有 k 个元素，返回 true；否则返回 false。

函数签名：kLengthApart(nums, k) → boolean

示例 1

输入：nums = [1,0,0,0,1,0,0,1], k = 2
输出：true

每一对相邻的 1 之间都有至少 2 个元素。

示例 2

输入：nums = [1,0,0,1,0,1], k = 2
输出：false

第二个 1 和第三个 1 之间只有 1 个元素。

约束

  • 1 <= nums.length <= 105
  • 0 <= k <= nums.length
  • nums[i] 只能是 0 或 1

先尝试找出：扫描到新的 1 时，真正需要记住的信息是什么？

Full solution

一次扫描，只记住上一枚 1

核心洞察：是否违规只取决于相邻的两枚 1。扫描到索引 i 的 1 时，若上一枚 1 在 prev，中间元素数就是 i - prev - 1；它小于 k 即可立刻返回 false。

完整过程

  1. 将 prev 初始化为一个表示“还没遇到 1”的值，例如 -1。
  2. 从左到右访问数组。遇到 0 时继续；遇到 1 时才做判断。
  3. 如果已有上一枚 1，并且 i - prev - 1 < k，说明间隔不足，立即返回 false。
  4. 否则把 prev 更新为当前索引。扫描结束仍未发现冲突，就返回 true。

正确性证明

充分性：算法检查了按索引顺序出现的每一对相邻 1。若全部相邻对之间至少有 k 个元素，那么任意非相邻的两枚 1 之间包含一个或多个合法间隔，其距离只会更大，因此所有 1 都满足要求。

必要性：若某两枚 1 不满足要求，按出现顺序选择造成违规的相邻一对。当扫描到后一枚 1 时，prev 恰好是前一枚 1 的索引，算法会算出小于 k 的间隔并返回 false。因此算法不会漏掉违规情况。

边界情况

  • 数组中没有 1 或只有一枚 1：不存在需要比较的配对，返回 true。
  • k = 0：任何合法二进制数组都满足条件。
  • 相邻元素都是 1：中间元素数为 0；仅在 k = 0 时合法。
  • 首尾的 0 不影响判断；只比较相邻 1 的索引。
时间复杂度
O(n)

每个元素至多访问一次。

空间复杂度
O(1)

只保存上一枚 1 的索引。

四种语言实现

class Solution {
    public boolean kLengthApart(int[] nums, int k) {
        int prev = -1;
        for (int i = 0; i < nums.length; i++) {
            if (nums[i] != 1) continue;
            if (prev != -1 && i - prev - 1 < k) {
                return false;
            }
            prev = i;
        }
        return true;
    }
}

替代方案

也可以维护“自上一枚 1 之后连续出现了多少个 0”的计数器。遇到 0 就递增；遇到非首枚 1 时检查计数是否至少为 k，再清零。它同样是 O(n) 时间、O(1) 空间，但索引差写法通常更直接。

面试追问

  • 为什么只检查相邻的 1？因为非相邻 1 的距离一定不小于其中任一相邻间隔。
  • 数据以流的形式到达怎么办？仍只需保留当前位置和上一枚 1 的位置，空间不变。
  • 若需要返回第一对冲突索引？把 false 改为返回 [prev, i]，扫描逻辑无需改变。

常见错误

  • 把两枚 1 的索引差 i - prev 误当成中间元素数；正确值要再减 1。
  • 使用 <= k 判断违规，错误拒绝“恰好相隔 k 个元素”的合法情况。
  • 首枚 1 也参与距离比较，导致哨兵值制造假冲突。
