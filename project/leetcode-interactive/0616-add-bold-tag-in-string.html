给字符串添加加粗标签

Add Bold Tag in String

在原字符串中找出字典单词的每一次出现，并用字面标签 <b> 与 </b> 包住所有命中字符。重叠或首尾相接的命中必须合成一段。

题目转述

给定一个只含英文字母和数字的字符串 s，以及字符串数组 words。只要 s 的某个子串与 words 中任意单词完全相同，就应让该子串的字符处于加粗范围内。

  • 两个命中范围若有重叠，只使用一对加粗标签包住它们的并集。
  • 两个命中范围若恰好相邻，也要合并为同一段。
  • 返回插入标签后的字符串；标签本身是返回值中的普通字符。

参数

  • s: string — 原字符串
  • words: string[] — 待匹配单词集合

返回

string — 将所有命中并集用最少数量的 <b>…</b> 包裹后的字符串。

示例 1

输入：s = "abcxyz123", words = ["abc", "123"]
输出："<b>abc</b>xyz<b>123</b>"

abc 与 123 分别命中，中间的 xyz 不在加粗范围内。

示例 2

输入：s = "aaabbb", words = ["aa", "b"]
输出："<b>aaabbb</b>"

aa 的重叠出现覆盖前三个字符，多个 b 的相邻命中紧接其后，最终合成一段。

约束

  • 1 <= s.length <= 1000
  • 0 <= words.length <= 100
  • 1 <= words[i].length <= 1000
  • s 和 words[i] 仅包含英文字母和数字。
  • words 中的字符串互不相同。

完整题解

核心洞察：先求覆盖并集，再插标签

不要一边搜索一边修改字符串。先用布尔数组 bold 标记每个原始字符是否属于任意一次单词出现；最终每一段连续的 true 恰好只需一对标签。

对每个单词，用字符串查找枚举它在 s 中的全部起点。下一次查找从 start + 1 开始，因而不会漏掉重叠出现。每找到一次，就把对应字符范围全部标记为 true。最后从左到右扫描布尔数组：遇到一段连续覆盖，输出开标签、整段字符和闭标签；未覆盖字符直接输出。

完整过程

  1. 建立长度为 n 的布尔数组 bold，初值全为 false。
  2. 对每个 word，反复查找它在 s 中的出现位置 start。
  3. 把半开区间 [start, start + word.length) 内的标记设为 true；随后从 start + 1 继续查找。
  4. 再次扫描 s。若当前位置未覆盖，原样追加；若已覆盖，追加 <b>，一次性追加整段连续覆盖字符，再追加 </b>。
  5. 返回构造结果。

正确性证明

引理 1：覆盖标记准确

若字符位置被标为 true，它一定落在某个已找到的单词出现区间内，所以确应加粗。反之，任何应加粗字符都属于至少一个单词出现；算法枚举每个单词的所有起点并标记整个区间，因此它一定会被标为 true。

引理 2：每个最大覆盖段只产生一对标签

构造阶段一旦遇到 true，就持续消费到下一个 false 或字符串末尾。因此同一连续覆盖段不会被拆开，相邻或重叠命中自然共用一对标签；两个覆盖段之间至少有一个未覆盖字符，也不会被错误合并。

结论

由引理 1，算法加粗的字符集合与题目要求完全相同；由引理 2，标签恰好包住这些字符集合的所有最大连续段。所以返回字符串正确，并使用了满足要求的合并形式。

复杂度

设 n = s.length，所有单词长度总和为 L，命中区间长度总和为 K。若底层朴素字符串查找一次最坏为线性，则保守上界可写为 O(n · L + K)；额外空间为布尔数组和结果串的 O(n)。在本题上限下，这种直接方法足够清晰。

边界情况

  • words 为空或没有任何命中：直接返回原字符串。
  • 单词长于 s：不会命中，不应越界。
  • 同一单词自重叠，如 "aa" 出现在 "aaa" 的 0 和 1：查找起点必须只增加 1。
  • 命中首尾相接：连续的 true 会自动合并。
  • 整串都被覆盖：只生成一对标签。

替代方案

          
    
            
  • 区间收集 + 排序合并：记录每次出现的 [l, r)，排序后合并，再输出。适合直接操作区间，但要额外存储命中。

  • 逐起点尝试：对每个位置匹配全部单词并维护最远右端点，逻辑直观。
    • 
            
  • Trie / Aho–Corasick：字典和文本规模很大时可批量匹配；本题规模下实现成本通常不划算。

常见错误

          
    
            
  • 命中后把下次起点移动整个单词长度，漏掉重叠匹配。
    • 
            
  • 只合并重叠区间，却没有合并 next.left == current.right 的相邻区间。
    • 
            
  • 边匹配边插标签，导致后续索引全部偏移。
    • 
            
  • 把 <b> 当成需要转义的输入内容，而不是题目要求追加的字面结果片段。
    • 
            
  • JavaScript 用正则直接匹配，却忘记转义特殊字符或处理重叠。
