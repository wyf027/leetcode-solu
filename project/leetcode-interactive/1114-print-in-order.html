LeetCode 1114 · Concurrency

按序打印

三个线程可能以任意顺序到达，但输出必须始终穿过两道同步闸门，形成唯一顺序：first → second → third。

EASYPrint in Order多线程非付费题

题目

同一个 Foo 实例交给三个不同线程：线程 A 调用 first()，线程 B 调用 second()，线程 C 调用 third()。请加入同步机制，保证第二个方法在第一个之后执行，第三个方法在第二个之后执行。

操作系统的调度顺序不可预测。输入数组只描述三个调用的触发次序，不代表可以依赖该次序完成同步。

参数形式

nums: integer[]，是 [1, 2, 3] 的一个排列；1、2、3 分别代表调用 first、second、third。

约束

  • nums 是 [1, 2, 3] 的一组排列。
  • 三个方法在同一个 Foo 实例上、由不同线程调用。

官方示例

示例 1
输入：nums = [1,2,3]
输出："firstsecondthird"
解释：线程依次触发 first、second、third，输出符合要求。
示例 2
输入：nums = [1,3,2]
输出："firstsecondthird"
解释：third 虽先于 second 到达，也必须等待 second 完成。
交互实验室

让乱序线程依次过闸

模拟到达顺序 [3, 2, 1]。闸门关闭时线程等待；前序完成后，下一道闸门打开。

🔒线程 C · third()
最先到达，等待第二道闸门
🔒线程 B · second()
随后到达，等待第一道闸门
🔓线程 A · first()
最后到达，但可立即执行
步骤 0 / 5：三个线程尚未进入调度。
Solution

题解：两道一次性同步闸门

核心洞察

真正需要表达的是两个先行发生关系：first → second 与 second → third。用两个初始关闭的闸门即可直接建模；每个前序方法打印后再打开下一道闸门。

完整过程

  1. first 无需等待；打印后打开闸门 1。
  2. second 等待闸门 1，获准后打印，再打开闸门 2。
  3. third 等待闸门 2，获准后打印。

正确性

在闸门 1 打开前，second 不可能越过等待；闸门 1 只在 first 打印之后打开，因此 first 必先于 second。同理，闸门 2 只在 second 打印之后打开，因此 second 必先于 third。由传递性，输出只能是 firstsecondthird。

边界与复杂度

  • 任意到达排列（包括完全逆序）都成立。
  • 同步对象必须属于同一个共享实例，不能在方法内临时创建。
  • 时间复杂度 O(1)，额外空间 O(1)；等待由同步原语阻塞，不应忙等。

替代方案

还可使用条件变量配合阶段状态、信号量、事件或倒计时门闩。条件变量通用但代码更长；忙等原子变量虽直观，却会浪费 CPU；单线程队列则改变了题目给定的调用模型。

面试追问

  • 如果三个方法需要被循环调用多轮，如何为每一轮重置同步状态？
  • 回调抛出异常时，是否仍应释放后继线程，怎样定义失败语义？
  • 如何推广到 N 个有依赖关系的任务？可考虑依赖计数或 DAG 调度。

常见错误

  • 相信输入数组或线程启动顺序等于实际执行顺序。
  • 只用普通布尔值而没有正确的内存可见性与阻塞机制。
  • 先释放后继，再执行当前打印，造成输出颠倒。
  • 持锁执行不可控的长回调，扩大临界区甚至诱发死锁。

四语言完整实现

import java.util.concurrent.CountDownLatch;

class Foo {
    private final CountDownLatch firstDone = new CountDownLatch(1);
    private final CountDownLatch secondDone = new CountDownLatch(1);

    public Foo() {}

    public void first(Runnable printFirst) throws InterruptedException {
        printFirst.run();
        firstDone.countDown();
    }

    public void second(Runnable printSecond) throws InterruptedException {
        firstDone.await();
        printSecond.run();
        secondDone.countDown();
    }

    public void third(Runnable printThird) throws InterruptedException {
        secondDone.await();
        printThird.run();
    }
}

class Deferred {
  constructor() {
    this.promise = new Promise(resolve => { this.resolve = resolve; });
  }
}

class Foo {
  constructor() {
    this.firstDone = new Deferred();
    this.secondDone = new Deferred();
  }

  async first(printFirst) {
    printFirst();
    this.firstDone.resolve();
  }

  async second(printSecond) {
    await this.firstDone.promise;
    printSecond();
    this.secondDone.resolve();
  }

  async third(printThird) {
    await this.secondDone.promise;
    printThird();
  }
}
from threading import Event
from typing import Callable

class Foo:
    def __init__(self):
        self.first_done = Event()
        self.second_done = Event()

    def first(self, printFirst: Callable[[], None]) -> None:
        printFirst()
        self.first_done.set()

    def second(self, printSecond: Callable[[], None]) -> None:
        self.first_done.wait()
        printSecond()
        self.second_done.set()

    def third(self, printThird: Callable[[], None]) -> None:
        self.second_done.wait()
        printThird()
#include <condition_variable>
#include <functional>
#include <mutex>
using namespace std;

class Foo {
    mutex m;
    condition_variable cv;
    int stage = 0;
public:
    Foo() = default;

    void first(function<void()> printFirst) {
        printFirst();
        { lock_guard<mutex> lock(m); stage = 1; }
        cv.notify_all();
    }

    void second(function<void()> printSecond) {
        unique_lock<mutex> lock(m);
        cv.wait(lock, [this] { return stage >= 1; });
        printSecond();
        stage = 2;
        lock.unlock();
        cv.notify_all();
    }

    void third(function<void()> printThird) {
        unique_lock<mutex> lock(m);
        cv.wait(lock, [this] { return stage >= 2; });
        printThird();
    }
};
