设计浏览器
历史记录

只有一个标签页，却要记住来路与去向。你需要实现一个浏览历史对象：访问新页面、向后退、向前进，并在越界时停在最远可达的位置。

01 / 问题定义

把浏览器的时间线装进一个类

用 homepage 初始化单标签页浏览器。访问 url 时从当前页跳转，并永久清空当前页之后的前进记录。后退或前进至多 steps 步；如果可移动的距离不足，就停在对应边界，返回最终页面 URL。

BrowserHistory(string homepage)创建对象，当前页为首页。
void visit(string url)访问新 URL，并清除所有前进历史。
string back(int steps)至多后退指定步数，返回抵达的 URL。
string forward(int steps)至多前进指定步数，返回抵达的 URL。

06 / 题解 · 默认收起

一条数组，一枚指针

核心洞察：有效历史始终是一条线。数组保存页面顺序，指针指向当前页；访问新页时先截断指针右侧，再追加新页。

状态表示

用 history 保存当前仍有效的历史，用 current 表示当前页面下标。初始化为 [homepage] 与 0。

边界钳制

后退取 max(0, current - steps)；前进取 min(history.length - 1, current + steps)，天然处理越界。

完整过程

初始化：数组中只有首页，指针位于下标 0。
visit(url)：丢弃 current + 1 之后的内容，将 url 写到下一格，并让指针加一。
back(steps)：指针向左移动，但不能小于 0；返回指针所指 URL。
forward(steps)：指针向右移动，但不能超过最后一个有效下标；返回指针所指 URL。

正确性说明

不变式：每次操作完成后，history 按访问顺序保存全部且仅保存当前有效的浏览历史，current 指向当前页面。

初始化：数组只含首页，指针为 0，不变式成立。

保持：visit 删除全部前进记录并紧接当前页追加新 URL，因此得到新的完整有效历史；back 和 forward 不修改数组，只在合法区间内移动指针。因此三种操作都保持不变式。

结论：每次返回 history[current] 都是按要求至多移动 steps 步后所在的页面。

复杂度与边界

时间：back、forward 为 O(1)；visit 在不同语言的截断实现下可视为 O(k)，k 为清理的前进记录数，使用覆盖式数组与有效末端指针可做到摊还 O(1)。

空间：O(n)，n 为保留的页面数量。

关键边界：首页后退、末页前进、大于可达距离的 steps、后退后访问新页、只有一个页面。

四种语言完整实现

import java.util.ArrayList;
import java.util.List;

class BrowserHistory {
    private final List<String> history = new ArrayList<>();
    private int current = 0;

    public BrowserHistory(String homepage) {
        history.add(homepage);
    }

    public void visit(String url) {
        while (history.size() > current + 1) {
            history.remove(history.size() - 1);
        }
        history.add(url);
        current++;
    }

    public String back(int steps) {
        current = Math.max(0, current - steps);
        return history.get(current);
    }

    public String forward(int steps) {
        current = Math.min(history.size() - 1, current + steps);
        return history.get(current);
    }
}
/**
 * @param {string} homepage
 */
var BrowserHistory = function(homepage) {
    this.history = [homepage];
    this.current = 0;
};

/** @param {string} url @return {void} */
BrowserHistory.prototype.visit = function(url) {
    this.history.length = this.current + 1;
    this.history.push(url);
    this.current++;
};

/** @param {number} steps @return {string} */
BrowserHistory.prototype.back = function(steps) {
    this.current = Math.max(0, this.current - steps);
    return this.history[this.current];
};

/** @param {number} steps @return {string} */
BrowserHistory.prototype.forward = function(steps) {
    this.current = Math.min(this.history.length - 1, this.current + steps);
    return this.history[this.current];
};
class BrowserHistory:
    def __init__(self, homepage: str):
        self.history = [homepage]
        self.current = 0

    def visit(self, url: str) -> None:
        del self.history[self.current + 1:]
        self.history.append(url)
        self.current += 1

    def back(self, steps: int) -> str:
        self.current = max(0, self.current - steps)
        return self.history[self.current]

    def forward(self, steps: int) -> str:
        self.current = min(len(self.history) - 1,
                           self.current + steps)
        return self.history[self.current]
class BrowserHistory {
private:
    vector<string> history;
    int current;

public:
    BrowserHistory(string homepage)
        : history{homepage}, current(0) {}

    void visit(string url) {
        history.resize(current + 1);
        history.push_back(url);
        ++current;
    }

    string back(int steps) {
        current = max(0, current - steps);
        return history[current];
    }

    string forward(int steps) {
        current = min(static_cast<int>(history.size()) - 1,
                      current + steps);
        return history[current];
    }
};

替代方案与面试追问

双栈

一个栈保存后退历史，一个栈保存前进历史，当前页单独存放。语义直观，但一次移动 steps 步需要逐个弹栈，时间为 O(steps)。

覆盖式数组

除了 current，再保存有效历史末端 end。visit 直接覆盖 current + 1 并更新 end，不做物理截断，可让每次操作严格 O(1)。

常见追问：如果要支持多个标签页怎么办？可以让每个标签页各自持有 BrowserHistory，再由上层管理活跃标签；若需要持久化或跨设备同步，还要为事件加入时间戳、设备标识与冲突合并策略。

常见错误

  • 后退后访问新页面，却没有清空前进历史。
  • 把 steps 当作目标下标，没有相对当前指针移动。
  • 边界判断出现 off-by-one，让指针等于数组长度。
  • 用链表逐步移动却误报 O(1)；移动 steps 个节点实际为 O(steps)。
  • 截断后忘记把新 URL 追加到历史，或忘记更新 current。
