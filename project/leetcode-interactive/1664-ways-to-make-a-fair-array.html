MEDIUM数组 · 前缀和

Ways to Make a Fair Array

生成平衡数组的方案数

删除恰好一个元素后，原数组右侧元素会整体左移。哪些删除位置能让新数组的偶数下标和与奇数下标和相等？先读题，再亲手逐个试。

Problem

题目描述

给定整数数组 nums，选择恰好一个下标并删除该元素。删除后，后续元素会重新编号。

若新数组中所有偶数下标元素之和等于所有奇数下标元素之和，则称它为平衡数组。返回可以选择的删除下标数量。

函数签名：waysToMakeFair(nums)
参数：nums: integer[]
返回：integer

约束

  • 1 <= nums.length <= 105
  • 1 <= nums[i] <= 104

示例 1

输入： nums = [2,1,6,4]
输出： 1
解释： 只有删除下标 1 后得到 [2,6,4]，
偶数下标和 2 + 4 = 6，奇数下标和 6。

示例 2

输入： nums = [1,1,1]
输出： 3
解释： 删除任一元素都平衡。

示例 3

输入： nums = [1,2,3]
输出： 0
解释： 没有可行删除位置。

观察任务：删除一个元素时，它左边的下标不变；它右边的元素会向左移动一格。留意颜色发生了什么变化，再判断哪一项让两边总和相等。

Solution

完整题解

默认收起，准备好后再揭晓线性解法。

核心洞察：删除点右侧的奇偶性互换

设正在考虑删除下标 i。删除点左侧的下标保持不变，而右侧所有元素的新下标都比原来小 1，因此右侧原本位于偶数下标的元素会变成奇数下标，原本位于奇数下标的元素会变成偶数下标。

新偶数和 = 左侧偶数和 + 右侧奇数和
新奇数和 = 左侧奇数和 + 右侧偶数和

完整过程

  1. 先统计整个数组原始偶数下标和 rightEven 与奇数下标和 rightOdd。
  2. 从左到右枚举删除位置 i。先把 nums[i] 从对应的右侧总和中移除，此时右侧变量只代表删除点之后的元素。
  3. 比较 leftEven + rightOdd 与 leftOdd + rightEven；相等就计数。
  4. 最后把当前元素加入对应的左侧总和，供下一个删除位置使用。

正确性证明

循环不变量：每次判断下标 i 前，leftEven/leftOdd 恰好包含所有下标小于 i 的元素；从右侧总和移除 nums[i] 后，rightEven/rightOdd 恰好包含所有下标大于 i 的元素。
单点判断：删除 i 后，左侧元素下标不变，所以它们对新奇偶和的贡献分别是 leftEven、leftOdd；右侧元素下标减一，奇偶性互换，所以它们对新偶数和贡献 rightOdd，对新奇数和贡献 rightEven。因此算法的等式恰好等价于删除后数组平衡。
完备性：算法逐一检查全部下标且每个下标只检查一次，所以不会漏掉或重复计算任何合法删除方案。故返回值正确。

边界情况

  • 长度为 1：删除后为空数组，两类下标和都为 0，因此答案为 1。
  • 所有元素相同：答案仍由长度和位置决定，不能仅凭总和相等直接下结论。
  • 答案可能为 0，也可能等于数组长度。
  • 题目上界下总和可达 10^9；Java 的 int 尚可容纳，但使用更宽整数也很稳妥。

复杂度

时间复杂度 O(n)：两次线性扫描。空间复杂度 O(1)：只维护四个和与答案。

替代方案

可以分别构造偶数下标和、奇数下标和的前缀数组，再用 O(1) 时间判断每个删除点，总时间仍为 O(n)，但需要 O(n) 额外空间。直接滚动维护左右总和更简洁。

面试追问

  • 如果允许删除一个连续区间，区间右侧的奇偶性是否互换取决于被删区间长度的奇偶性。
  • 如果要支持多次在线修改与查询，可考虑用两个 Fenwick Tree 或线段树分别维护原始奇偶位之和。
  • 为什么必须“先从右侧移除当前元素，再判断，最后加入左侧”？因为被删除元素不能属于任一侧。

常见错误

  • 删除后仍按原下标奇偶性累加右侧元素，遗漏了整体左移带来的翻转。
  • 判断时把待删除元素仍算在右侧，或提前加入左侧。
  • 只比较删除前的全局偶数和与奇数和。
  • 额外真的构造每个删除后的数组，导致 O(n²) 超时。

class Solution {
    public int waysToMakeFair(int[] nums) {
        int rightEven = 0, rightOdd = 0;
        for (int i = 0; i < nums.length; i++) {
            if ((i & 1) == 0) rightEven += nums[i];
            else rightOdd += nums[i];
        }

        int leftEven = 0, leftOdd = 0, answer = 0;
        for (int i = 0; i < nums.length; i++) {
            if ((i & 1) == 0) rightEven -= nums[i];
            else rightOdd -= nums[i];

            if (leftEven + rightOdd == leftOdd + rightEven) {
                answer++;
            }

            if ((i & 1) == 0) leftEven += nums[i];
            else leftOdd += nums[i];
        }
        return answer;
    }
}

from typing import List


class Solution:
    def waysToMakeFair(self, nums: List[int]) -> int:
        right_even = sum(nums[::2])
        right_odd = sum(nums[1::2])
        left_even = left_odd = 0
        answer = 0

        for i, value in enumerate(nums):
            if i % 2 == 0:
                right_even -= value
            else:
                right_odd -= value

            if left_even + right_odd == left_odd + right_even:
                answer += 1

            if i % 2 == 0:
                left_even += value
            else:
                left_odd += value

        return answer
