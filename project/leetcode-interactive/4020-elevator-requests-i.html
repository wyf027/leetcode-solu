4020. 电梯请求 I

在一条数轴上完成所有楼层请求。最短路线只需决定：先去左端，还是先去右端？

关键词：最小值、最大值、覆盖区间、两种顺序。

题意：所有请求都必须被经过

楼层编号为 0…n−1。电梯起点是 start，requests 给出要停靠的楼层（可视为同时出现）。每移动一层耗时 1；到达或经过请求楼层即完成。返回完成全部请求的最少移动时间。

例 1
start=5, [2,8]
先右后左：3 + 6 = 9
例 2
start=6, [2,8]
先右后左：2 + 6 = 8
关键约束
只要覆盖 [min, max]，中间请求会自然完成。

交互：比较两条候选路线

输入楼层后按“计算路线”；可用 ←/→ 逐步回放。橙色是请求，绿色是已完成，青色边框是当前电梯。

请输入 0 以上的整数；重复楼层会自动合并。

准备就绪。

最少时间：—

等待输入。

候选顺序 先到端点 扫过区间 总时间

洞察：答案只看两个端点

  1. 令 L=min(requests)、R=max(requests)。
  2. 任何可行路线都必须访问 L 和 R；L 到 R 的 R−L 不可避免。
  3. 第一次触及端点前，只需从 start 去 L 或去 R 之一。
  4. 比较两种顺序即可：|start−L|+(R−L) 与 |start−R|+(R−L)。
ans = (R − L) + min(|start − L|, |start − R|)

隐藏题解

展开查看贪心证明

取任意最优路线，第一次碰到两个极值中的一个后，另一个极值仍未完成，最终必须横跨完整区间。把到第一个端点之前的绕路删除，只会更短；因此最优解必是“起点 → 一个端点 → 另一个端点”。只剩两种顺序。

复杂度

扫描一次得到 L、R：时间 O(m)，额外空间 O(1)。

过程：start=5，requests=[2,8]

聚合：L=2，R=8，完整区间长度是 6。
左优先：5→2 需 3，再从 2→8 需 6，总计 9。
右优先：5→8 需 3，再从 8→2 需 6，总计也是 9。
选择：最小值为 9；相同成本时演示固定展示“先左”。

四语言实现

/** @param {number} start @param {number[]} requests */
var minTime = function(start, requests) {
  let left = Infinity, right = -Infinity;
  for (const floor of requests) { left = Math.min(left, floor); right = Math.max(right, floor); }
  return right - left + Math.min(Math.abs(start - left), Math.abs(start - right));
};
class Solution {
  public int minTime(int start, int[] requests) {
    int left = Integer.MAX_VALUE, right = Integer.MIN_VALUE;
    for (int floor : requests) { left = Math.min(left, floor); right = Math.max(right, floor); }
    return right - left + Math.min(Math.abs(start - left), Math.abs(start - right));
  }
}

    def minTime(self, start: int, requests: list[int]) -> int:
        left, right = min(requests), max(requests)

class Solution {
public:
    int minTime(int start, vector<int>& requests) {
        int left = *min_element(requests.begin(), requests.end());
        int right = *max_element(requests.begin(), requests.end());
        return right - left + min(abs(start - left), abs(start - right));
    }
};

边界与替代方案

  • 一个请求：区间长度为 0，答案就是起点距离。
  • 起点在区间内：走向更近端点后必须扫到另一端。
  • 重复请求：对“全部经过一次”目标没有影响；极值不变。
  • 替代：排序后取首尾也能做，但多了 O(m log m)，这里不需要。

常见错误与追问

  • 错误：只返回 R−L，漏了从 start 接入区间的成本。
  • 错误：只选距离最近的请求；最近请求未必是端点，之后仍要覆盖两端。
  • 追问：若每个请求有权重、代价是完成时刻之和？状态不再只剩两个端点，见后续的区间 DP 版本。
  • 追问：若请求带到达时间？需要把时间合法性加入状态，端点贪心不再充分。
