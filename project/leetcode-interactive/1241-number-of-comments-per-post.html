每个帖子的
评论数

从一张混合记录表中，辨认帖子与评论，并为每个真实帖子给出不重复评论数。

Problem

题目

官方题面未随元数据提供；以下依据官方表结构与样例准确转述。

表：Submissions

列名类型
sub_idint
parent_idint

表中每行是一条投稿记录。parent_id 为 NULL 时，该行代表帖子；否则该行代表对编号为 parent_id 的帖子的评论。

目标

统计每个帖子的不同评论数量，输出 post_id 与 number_of_comments，并按 post_id 升序排列。

注意重复：这张表没有主键，可能包含完全相同的行；相同 sub_id 的帖子或评论只应计一次。

约束与数据语义

  • sub_id、parent_id 均为整数列，parent_id 可以为 NULL。
  • 表中可以出现重复记录。
  • 只输出由 parent_id IS NULL 标识的真实帖子；没有评论的帖子也要输出 0。

Solution

准备好看题解了吗？

核心 SQL、证明、复杂度与四种本地语义参考都藏在这里。

核心洞察

① 左侧只留帖子

只有 parent_id IS NULL 的记录能成为最终结果中的帖子。

② 自连接挂评论

把帖子 ID 与评论的 parent_id 相等，便能找到属于该帖子的评论。

③ 两处处理重复

按帖子 ID 分组消除重复帖子；COUNT(DISTINCT ...) 消除重复评论。

完整过程

  1. 从 Submissions p 中筛选 p.parent_id IS NULL，得到候选帖子。
  2. 使用 LEFT JOIN 连接 Submissions c，条件为 p.sub_id = c.parent_id。左连接保证无评论的帖子仍保留。
  3. 按 p.sub_id 分组，使重复帖子行聚合为一个结果组。
  4. 用 COUNT(DISTINCT c.sub_id) 只数不同评论；未匹配时评论 ID 为 NULL，COUNT 自然得到 0。
  5. 最后按帖子 ID 升序排序。

正确性

完整性

每个帖子行都进入左表；左连接不会丢弃没有匹配评论的帖子，因此所有帖子都出现。

准确性

连接条件只把 parent_id 等于当前帖子 ID 的评论纳入该组，不相关记录无法进入。

唯一性

分组让每个帖子 ID 只产生一行，DISTINCT 让每个评论 ID 只贡献一次计数。

边界与复杂度

边界：空表返回空结果；孤立评论不创建帖子；重复帖子不产生重复结果；无评论帖子计 0；重复评论只计一次。
复杂度：设记录数为 n。数据库执行计划依索引和实现而定；概念上需扫描记录并聚合，空间用于连接与去重。常见哈希实现平均时间 O(n)，额外空间 O(n)。

MySQL · 官方可提交自连接 + 去重聚合
SELECT p.sub_id AS post_id,
       COUNT(DISTINCT c.sub_id) AS number_of_comments
FROM Submissions AS p
LEFT JOIN Submissions AS c
  ON p.sub_id = c.parent_id
WHERE p.parent_id IS NULL
GROUP BY p.sub_id
ORDER BY p.sub_id;
Java 17 · 本地语义参考List<int[]>；-1 表示 NULL
import java.util.*;

class Solution {
    public List<int[]> countComments(List<int[]> rows) {
        Set<Integer> posts = new TreeSet<>();
        Map<Integer, Set<Integer>> comments = new HashMap<>();

        for (int[] row : rows) {
            if (row[1] == -1) posts.add(row[0]);
            else comments.computeIfAbsent(row[1], k -> new HashSet<>())
                         .add(row[0]);
        }

        List<int[]> answer = new ArrayList<>();
        for (int postId : posts) {
            int count = comments.getOrDefault(postId, Collections.emptySet()).size();
            answer.add(new int[]{postId, count});
        }
        return answer;
    }
}
JavaScript · 本地语义参考null 表示 SQL NULL
function countComments(rows) {
  const posts = new Set();
  const comments = new Map();

  for (const [subId, parentId] of rows) {
    if (parentId === null) posts.add(subId);
    else {
      if (!comments.has(parentId)) comments.set(parentId, new Set());
      comments.get(parentId).add(subId);
    }
  }

  return [...posts]
    .sort((a, b) => a - b)
    .map((postId) => [postId, comments.get(postId)?.size ?? 0]);
}

from collections import defaultdict

def count_comments(rows: list[tuple[int, int | None]]) -> list[tuple[int, int]]:
    posts: set[int] = set()
    comments: dict[int, set[int]] = defaultdict(set)

    for sub_id, parent_id in rows:
        if parent_id is None:
            posts.add(sub_id)
        else:
            comments[parent_id].add(sub_id)

    return [(post_id, len(comments[post_id])) for post_id in sorted(posts)]

class Solution {

    vector<pair<int, int>> countComments(const vector<pair<int, int>>& rows) {
        set<int> posts;
        map<int, set<int>> comments;
        for (const auto& [subId, parentId] : rows) {
            if (parentId == -1) posts.insert(subId);
            else comments[parentId].insert(subId);

        vector<pair<int, int>> answer;

            answer.push_back({postId, static_cast<int>(comments[postId].size())});
        }

替代方案

预去重后连接

分别用两个 CTE 对帖子与评论去重，再左连接并 COUNT。逻辑更显式，适合复杂查询，但代码更长。

相关子查询

对每个不同帖子运行一个计数子查询，表达直观；数据量大时通常不如一次连接聚合容易优化。

面试追问与常见错误

为什么不是 INNER JOIN？

内连接会删除没有评论的帖子，无法输出要求中的 0。

为什么需要 DISTINCT？

表没有主键，评论行可重复；普通 COUNT(c.sub_id) 会把重复行重复计数。

能写 COUNT(*) 吗？

不能。左连接对无评论帖子仍生成一行，COUNT(*) 会误计为 1。

只 DISTINCT 帖子够吗？

不够。重复帖子解决结果行问题，重复评论仍需在计数时去重。

索引怎么建？

真实系统可考虑覆盖连接与筛选列的索引，例如围绕 parent_id、sub_id 设计，最终要看执行计划。

常见错误

漏掉排序、把孤立评论当帖子、在 WHERE 中筛右表导致左连接退化、忘记重复数据。
