处理用时最长的那个任务的员工

The Employee That Worked on the Longest Task

一份下班时刻日志，一条连续的任务时间线。找出完成最长单个任务的员工。

01 / 题目与约束

共有 n 名员工，编号为 0 到 n - 1。二维数组 logs 按任务执行顺序记录日志，logs[i] = [idᵢ, leaveTimeᵢ] 表示第 i 个任务由员工 idᵢ 处理，在 leaveTimeᵢ 时刻结束。

第一个任务从时刻 0 开始；之后每个任务在上一个任务结束时立即开始，任务之间没有空档。返回用时最长的单个任务对应的员工编号；如果多人并列，返回其中最小编号。

参数与返回值

  • n: integer：员工数量。
  • logs: integer[][]：每行包含员工编号和结束时刻。
  • hardestWorker(n, logs) → integer：员工编号。

官方约束

  • 2 ≤ n ≤ 500
  • 1 ≤ logs.length ≤ 500
  • logs[i].length == 2
  • 0 ≤ idᵢ ≤ n - 1
  • 1 ≤ leaveTimeᵢ ≤ 500
  • 相邻任务的员工不同：idᵢ ≠ idᵢ₊₁。
  • 结束时刻严格递增，因此互不相同。

02 / 官方示例

示例 1

输入：n = 10, logs = [[0,3],[2,5],[0,9],[1,15]]
输出：1

四个任务的时间区间依次为 [0,3]、[3,5]、[5,9]、[9,15]，耗时为 3、2、4、6。最后一个任务最长，员工为 1。

示例 2

任务依次耗时 1、6、5、5；耗时 6 的任务由员工 3 处理。

示例 3

输入：n = 2, logs = [[0,10],[1,20]]
输出：0

两个任务分别在 [0,10]、[10,20] 执行，都耗时 10。员工 0 和 1 并列，返回 0。

05 / 独立题解


准备好后展开，阅读推导与四种语言实现。






核心洞察：相邻结束时刻之差


日志保存的是结束时刻，不是持续时间。设上一个任务的结束时刻为 prev，当前任务耗时就是 duration = end - prev。由于任务连续，首个任务的起点设为 0 即可统一处理。


每个任务独立参加比较，不需要按员工累加。维护最长耗时 best 和候选编号 ans；遇到更长任务就更新，耗时相等时只保留更小编号。


完整过程


  1. 初始化 prev = 0、best = 0、ans = n。编号 n 是大于所有合法编号的哨兵。
  2. 按原顺序遍历每一行 [id, end]，计算 duration = end - prev。
  3. 如果 duration > best，或 duration == best 且 id < ans，令 best = duration，ans = id。
  4. 无论是否更新候选，都设置 prev = end。
  5. 遍历结束返回 ans。至少一条日志且耗时为正，首项必定替换哨兵。


以示例 1 为例：读到 [0,3] 得到耗时 3，候选 0；读到 [2,5] 得到耗时 2，保持；读到 [0,9] 得到耗时 4，更新最长耗时；读到 [1,15] 得到耗时 6，候选变为 1。


正确性：扫描前缀的不变式


处理完前 k 条日志后，prev 等于第 k 条任务的结束时刻；best 等于这些任务的最大耗时，ans 是达到该耗时的员工中最小的编号。


  • 起始：首项从 0 开始，耗时为正，一定更新 best 和 ans，结论成立。
  • 保持：下一项的起点由 prev 准确给出。若更长，替换最大值与编号；若等长，保留较小编号；若更短，原最优结果不变。随后更新 prev，所有条件仍成立。
  • 结束：扫描覆盖全部日志，不变式直接给出全局最长任务对应的最小员工编号。


边界与复杂度


单条日志返回该员工；全部耗时相同则选最小编号；同一员工可以非连续出现，仍逐个任务比较。结束时刻严格递增，不会有零耗时任务。令 m = logs.length，时间复杂度 O(m)，额外空间 O(1)。n 只提供编号范围，无需遍历 n 名员工；可视化保存展示记录所用的空间不属于提交算法。

Java


class Solution {
    public int hardestWorker(int n, int[][] logs) {
        int prev = 0, best = 0, ans = n;
        for (int[] log : logs) {
            int id = log[0], end = log[1];
            int duration = end - prev;
            if (duration > best || (duration == best && id < ans)) {
                best = duration;
                ans = id;
            }
            prev = end;
        }
        return ans;
    }
}

替代方案


  • 先算出所有 (耗时, 员工编号)，按耗时降序、编号升序排序取首项。时间 O(m log m)，存储 O(m)。必须先计算差值，不能先打乱原始日志。
  • 用长度为 n 的数组存每位员工的最大单次耗时，再扫描员工数组。时间 O(m + n)、空间 O(n)；适合还需要查询每位员工个人最长任务的场景。此题直接维护全局候选即可。


常见错误


  • 把最后的结束时刻当作最大耗时，忽略任务起点。
  • 按员工累加：在 [[0,4],[1,10],[0,14]] 中，员工 0 累计 8，但员工 1 的单任务耗时 6 才是最大。
  • 并列时无条件覆盖，导致结果依赖日志顺序。
  • 只在刷新候选时更新 prev，导致下一项错误地跨越多个任务。
  • 先按员工编号排序，破坏任务相邻关系。


面试追问


  • 日志以流的形式到达？每次仅更新 prev、best、ans，仍是常量状态。
  • 任务之间可能有空档或并发？仅凭结束时刻无法恢复耗时，需要额外的开始时刻或成对的开始/结束事件。
  • 改为总工作时间最多？先用相邻结束时刻求出耗时，再按员工累加，并在总和上使用最小编号规则。
  • 需要返回全部并列员工？记录最长耗时并维护去重集合，更长时清空集合，等长时加入；按输出要求排序。
