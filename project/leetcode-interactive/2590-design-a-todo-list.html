2590. Design a Todo List

先理解接口，再决定存储。 本题的关键不是复杂数据结构，而是让任务归属、完成状态、标签过滤和截止日期顺序始终一致。

Problem

题意转述

系统设计题

实现一个多用户待办清单。每个任务包含描述、全局递增的任务 ID、截止日期和零个或多个标签。系统需要添加任务、按截止日期返回某位用户的未完成任务、按标签筛选未完成任务，并在任务确实属于该用户时将它标记完成。

TodoList()

初始化空清单；首个新增任务的 ID 为 1。

addTask(userId, taskDescription, dueDate, tags)

为用户新增任务，返回从 1 开始全局递增的任务 ID。

getAllTasks(userId)

返回该用户所有未完成任务的描述，按截止日期升序排列；没有则返回空列表。

getTasksForTag(userId, tag)

只返回同时未完成且包含指定标签的任务描述，仍按截止日期升序排列。

completeTask(userId, taskId)

仅当任务存在、属于该用户且尚未完成时生效；否则不做任何事。

返回内容：查询接口返回的是任务描述列表，不是任务 ID；所有 dueDate 保证互不相同。

Official example

官方样例

输入

["TodoList","addTask","addTask","getAllTasks","getAllTasks","addTask","getTasksForTag","completeTask","completeTask","getTasksForTag","getAllTasks"]
[[],[1,"Task1",50,[]],[1,"Task2",100,["P1"]],[1],[5],[1,"Task3",30,["P1"]],[1,"P1"],[5,1],[1,2],[1,"P1"],[1]]

输出

[null,1,2,["Task1","Task2"],[],3,["Task3","Task2"],null,null,["Task3"],["Task3","Task1"]]

关键过程

  • 任务 1、2 属于用户 1，截止日期分别为 50、100。
  • 任务 3 的截止日期为 30，因此标签查询中排在任务 2 前。
  • completeTask(5, 1) 不生效：任务 1 不属于用户 5。
  • completeTask(1, 2) 完成任务 2；之后所有查询都排除它。

Constraints

约束

  • 1 ≤ userId, taskId, dueDate ≤ 100
  • 0 ≤ tags.length ≤ 100
  • 1 ≤ taskDescription.length ≤ 50
  • 1 ≤ tags[i].length, tag.length ≤ 20
  • 所有截止日期 dueDate 互不相同。
  • 所有字符串仅由大小写英文字母和数字组成。
  • 每个方法至多被调用 100 次。

    Spoiler gate

    准备好再看题解

    先想一想：如何同时支持按用户查询和按任务 ID 快速完成？

    Solution

    双索引 + 查询时排序

    核心洞察

    维护两份轻量索引：用户 ID → 任务 ID 列表负责缩小查询范围，任务 ID → 任务对象负责常数时间定位完成操作。查询时过滤未完成任务，再按唯一的截止日期排序。约束很小，无需堆、平衡树或复杂缓存。

    完整过程

    1. 添加：用 nextId 分配 ID，将任务写入任务表，并把 ID 追加到所属用户的列表。
    2. 查询：遍历该用户的任务 ID，排除已完成任务；标签查询再排除不含目标标签的任务。
    3. 排序：按 dueDate 升序排列保留下来的任务，提取描述。
    4. 完成：从任务表定位 ID，只在任务存在、归属一致且未完成时更新状态。

    边界情况

    • 用户不存在或没有未完成任务：返回空列表。
    • 任务没有标签：普通查询仍可返回，标签查询不会命中。
    • 任务不存在、用户不匹配或重复完成：保持原状态。
    • 截止日期唯一，因此排序无需额外的平局规则。

    正确性说明

    1. 存储不变量：每次添加都产生唯一递增 ID；任务表保存该任务，且该 ID 恰好追加到所属用户的列表，所以之后能从任一索引找到正确任务。
    2. 查询正确：查询只遍历指定用户的列表，并严格过滤完成状态；标签查询额外检查标签成员关系，因此结果集合恰好是题目要求的任务集合。
    3. 顺序正确：结果按互不相同的截止日期升序排序，所以每个更早到期的任务一定排在更晚到期的任务前。
    4. 完成正确：只有任务存在、所有者匹配且尚未完成时才修改状态，因此合法请求生效，所有非法请求都不会破坏清单。

    复杂度

    设某用户共有 k 个任务，本次查询保留 r 个任务，新增任务含 t 个标签。

    addTask
    时间 O(t)，额外空间 O(t)
    查询方法
    时间 O(k + r log r)，结果外空间 O(r)
    completeTask
    平均时间 O(1)
    总空间
    O(n + 所有标签数)

    替代方案

    每个用户维护有序集合：添加变为 O(log k)，查询可按顺序线性扫描；但还要处理可变完成状态与语言差异。题目每个方法最多 100 次，查询时排序更短、更稳妥。

    只用全局任务数组：实现最短，但每次查询要扫描所有用户的任务；约束下也可通过，却没有利用按用户查询的天然边界。

    常见错误

    • 返回任务 ID，而不是任务描述。
    • 按任务 ID 排序，而不是按截止日期排序。
    • 完成任务时不校验所属用户。
    • 标签查询忘记排除已完成任务。
    • 为每个用户重置 ID，破坏全局递增规则。

    面试追问

    • 调用量增大怎么办？为每位用户维护按截止日期排序的结构，或为未完成任务建立复合索引。
    • 截止日期允许相同怎么办？明确二级排序规则，例如按任务 ID 升序。
    • 如何支持删除与改期？任务表仍是事实来源；同步维护用户索引，或改用支持删除和更新的有序结构。
    • 并发添加如何保证 ID 唯一？单机用原子计数器；分布式场景交给数据库序列或专用 ID 服务。
