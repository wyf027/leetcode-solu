知道秘密的人数

Number of People Aware of a Secret

秘密会传播，也会被遗忘。观察每天结束时，还有多少人记得它。

01 / 题目与规则

第 1 天，只有一个人知道秘密。每个在第 s 天得知秘密的人，会从第 s + delay 天起，每天告诉一个此前不知道秘密的新人；到第 s + forget 天就忘记秘密，而且当天已经不能再分享。求第 n 天结束时仍知道秘密的人数，对 1,000,000,007 取余。

官方示例 1

输入：n = 6, delay = 2, forget = 4
输出：5

第 1、2 天只有 A；第 3 天 A 告诉 B，第 4 天 A 告诉 C。第 5 天 A 遗忘，B 告诉 D；第 6 天 B、C 各告诉一个新人 E、F，最终 B、C、D、E、F 知道秘密。

官方示例 2

输入：n = 4, delay = 1, forget = 3
输出：6

第 1 天 A 知道，第 2 天 A 告诉 B，第 3 天 A、B 告诉 C、D。第 4 天 A 遗忘，B、C、D 各告诉一个新人，仍知道秘密的共 6 人。

完整约束：2 ≤ n ≤ 1000；1 ≤ delay < forget ≤ n。参数顺序为 peopleAwareOfSecret(n, delay, forget)，返回整数。

04 / 想好之后，再看题解

先尝试解释：为何“曾经知道”的人数和“现在知道”的人数不同？

题解 / 维护每天可以分享的人数

核心洞察

同一天得知秘密的人，开始分享与遗忘的日期完全相同，无需逐人模拟。定义 dp[d] 为第 d 天新得知秘密的人数，dp[1] = 1。在第 d 天，一个第 s 天得知秘密的人可分享，当且仅当 delay ≤ d − s < forget。

可分享批次：d − forget + 1 ≤ s ≤ d − delay
share(d) = share(d − 1) + dp[d − delay] − dp[d − forget]
dp[d] = share(d)                     （d ≥ 2）
答案 = sum(dp[s])，max(1, n − forget + 1) ≤ s ≤ n
越界的历史批次按 0 处理；所有人数对 M = 1,000,000,007 取模。

完整过程

  1. 建立长度 n + 1 的数组，令 dp[1] = 1，分享者 share = 0。
  2. 从第 2 天到第 n 天：加入第 d − delay 天的批次，他们今天开始分享。
  3. 减去第 d − forget 天的批次，他们今天已经遗忘，不能再分享。
  4. 规范化取模后，将分享者人数赋给 dp[d]，因为每个分享者恰好告诉一个新人。
  5. 累加尚未遗忘的批次，得到第 n 天结束时的知晓人数。

示例 1 的每日新增为 [1, 0, 1, 1, 1, 2]。第 5 天加入第 3 天的一人、移除第 1 天的一人，分享者仍是 1；第 6 天分享者增到 2。答案只统计第 3 至第 6 天的批次：1 + 1 + 1 + 2 = 5。

正确性说明

不变量：处理第 d 天时，share 恰好是所有满足 d − forget < s ≤ d − delay 的批次人数之和。第 1 天无人能分享，初始 share = 0 正确。日期从 d − 1 变为 d 时，该窗口只新增批次 d − delay、移除批次 d − forget；这正是更新操作，因此不变量逐日保持。每个可分享者产生一位新人，所以 dp[d] 正确。最后仍记得秘密的批次恰好满足 s + forget > n，即 s ≥ n − forget + 1，求和没有遗漏，也不会计入已遗忘的人。加减法与取模兼容，计算得到真实人数的模值。

边界与常见错误

  • 遗忘当天不能分享：要减去 dp[d − forget]，不是再晚一天减。
  • 第 1 天的那个人是初始条件，不由分享产生。
  • delay ≥ 1，新人在得知的当天不能继续分享。
  • delay = forget − 1 时，每批只有一天可分享，窗口仍适用。
  • 最终下界是 n − forget + 1，不是 n − forget；不能累加历史上所有新增人数。
  • Java、JavaScript、C++ 的余数可能为负，用 (share + M) % M 规范化；每日更新中 share、加入与移除项均已在 [0, M) 内，加一次 M 足够。
  • Java/C++ 用 long / long long 避免中间加法溢出；JavaScript 每步取模，中间值远低于 2⁵³，Number 可精确计算这些整数。

复杂度

主循环 O(n)，末尾求和 O(n)，总时间 O(n)；记录每日新增数组，额外空间 O(n)。

替代方案

直接把每个 dp[s] 分发给 [s + delay, s + forget − 1] 内的未来天数，时间 O(n · (forget − delay))、最坏 O(n²)，空间 O(n)，容易理解。前缀和可以 O(1) 求每一天的分享区间和，同样达到 O(n) 时间和 O(n) 空间。也可用长度 forget 的环形数组把空间缩到 O(forget)，但覆盖前必须先读取当天遗忘的旧值。

面试追问

  • 若每天每人告诉 k 个新人？分享窗口不变，dp[d] 改为 k × share，再取模，并使用适合乘法范围的数值类型。
  • 若每个人的 delay、forget 不同？按开始分享与遗忘日期安排人数增减事件，单一固定长度窗口就不够了。
  • 为何不直接创建“人”对象？人数可能快速增长，而同日得知者行为一致，按批次计数保留了所有需要的信息。

四语言完整代码

均采用官方函数签名，可作为提交代码使用；本轮未运行。

Java

class Solution {
    public int peopleAwareOfSecret(int n, int delay, int forget) {
        final long MOD = 1_000_000_007L;
        long[] dp = new long[n + 1];
        dp[1] = 1;
        long share = 0;
        for (int day = 2; day <= n; day++) {
            if (day - delay >= 1) share += dp[day - delay];
            if (day - forget >= 1) share -= dp[day - forget];
            share = (share + MOD) % MOD;
            dp[day] = share;
        }
        long answer = 0;
        for (int day = Math.max(1, n - forget + 1); day <= n; day++) {
            answer = (answer + dp[day]) % MOD;
        }
        return (int) answer;
    }
}

C++

#include <algorithm>
#include <vector>
using namespace std;

class Solution {
public:
    int peopleAwareOfSecret(int n, int delay, int forget) {
        const long long MOD = 1000000007LL;
        vector<long long> dp(n + 1, 0);
        dp[1] = 1;
        long long share = 0;
        for (int day = 2; day <= n; ++day) {
            if (day - delay >= 1) share += dp[day - delay];
            if (day - forget >= 1) share -= dp[day - forget];
            share = (share + MOD) % MOD;
            dp[day] = share;
        }
        long long answer = 0;
        for (int day = max(1, n - forget + 1); day <= n; ++day) {
            answer = (answer + dp[day]) % MOD;
        }
        return static_cast<int>(answer);
    }
};
