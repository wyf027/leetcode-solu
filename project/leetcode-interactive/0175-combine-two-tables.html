Core insight

Person 是必须完整保留的左表

从 Person 出发，对每一行按 personId 寻找 Address。匹配时拼接地址列；没有匹配时仍输出 Person 行，只把右表字段补为 SQL NULL。

这正是 LEFT JOIN 的语义。INNER JOIN 会丢掉 Allen；RIGHT JOIN 的保留方向相反；FULL JOIN 还会错误保留 personId=3 的孤立地址。

Canonical query 

SELECT p.firstName,
       p.lastName,
       a.city,
       a.state
FROM Person AS p
LEFT JOIN Address AS a
  ON p.personId = a.personId;

完整过程

  1. 01 / DRIVE

    以 Person 为驱动表，确保每个人至少产生一行。

  2. 02 / MATCH

    在 ON 中用 personId 匹配 Address。

  3. 03 / PRESERVE

    无匹配时保留左行，右表列由引擎补 NULL。

  4. 04 / PROJECT

    只选择要求的四列，不输出 personId。

ON 与 WHERE

ON 决定右表哪些行能参与匹配；匹配失败后 LEFT JOIN 仍生成 NULL 扩展行。

若把 p.personId = a.personId 放到 WHERE，NULL 扩展行无法满足条件，效果退化为 INNER JOIN。对右表的筛选若仍需保留未匹配 Person，也应写在 ON 内。

NULL 与重复匹配

  • 返回数据库 NULL，不是字符串 "Null" 或空串。
  • 官方只声明 addressId 唯一，并未声明 Address.personId 唯一。
  • 若同一 personId 有多条地址，标准连接会为该 Person 产生多行；不可擅自去重。
  • 孤立 Address 行不在结果中，因为只保留左表。

复杂度与索引

逻辑结果由连接决定。实际执行计划取决于引擎：对 Address.personId 建索引时，可从 Person 做索引查找；哈希连接通常为 O(P+A) 期望时间并使用 O(A) 哈希空间。

本题不要求建索引或固定结果顺序。不要添加无必要的 ORDER BY。

题型特例与面试追问

本题属于 LeetCode Database 分类，官方当前提供 MySQL、MS SQL Server、PostgreSQL、Oracle 与 Pandas 编辑器。下面不是 Java/JS/Python/C++ 算法答案，而是对应数据库方言；Pandas 作为官方支持的替代入口单列。

为什么 SELECT 不写 personId？

输出契约只要求 firstName、lastName、city、state；额外列可能导致判题不匹配。

为什么不用 COALESCE？

题目明确要求无地址时返回 NULL，COALESCE 会替换它并改变语义。

结果顺序稳定吗？

没有 ORDER BY 就不保证顺序；题目允许任意顺序，因此比较应视为集合/多重集。

WHERE a.city IS NULL 会怎样？

它会只保留无匹配行以及真实 city 为 NULL 的匹配行，不能单独区分两者；可改查 a.addressId IS NULL。

import pandas as pd


def combine_two_tables(
    person: pd.DataFrame, address: pd.DataFrame
) -> pd.DataFrame:
    address_columns = address[["personId", "city", "state"]]
    result = person.merge(address_columns, on="personId", how="left")
    return result[["firstName", "lastName", "city", "state"]]
