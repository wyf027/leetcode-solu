使序列递增的
最小交换次数

Minimum Swaps To Make Sequences Increasing

困难 数组 动态规划 O(n) 时间
Problem

题目描述

函数：minSwap(nums1, nums2)

任务

给定两个长度相同的整数数组 nums1 和 nums2。一次操作可以选择某个下标 i，交换 nums1[i] 与 nums2[i]。

请返回使两个数组都成为严格递增序列所需的最少交换次数。测试数据保证一定存在可行方案。

严格递增：对每个有效的 i > 0，都有 arr[i - 1] < arr[i]。
每次只能交换同一下标上的一对数，不能交换不同下标，也不能只移动其中一个数组的元素。
Constraints

约束

  • 2 <= nums1.length <= 10^5
  • nums2.length == nums1.length
  • 0 <= nums1[i], nums2[i] <= 2 × 10^5
  • 输入保证可以通过若干次合法交换得到答案。
1

官方示例 1

输入：nums1 = [1,3,5,4], nums2 = [1,2,3,7] 输出：1

交换下标 3 的两个元素后，得到 nums1 = [1,3,5,7]、nums2 = [1,2,3,4]，两者均严格递增。

2

官方示例 2

输入：nums1 = [0,3,5,8,9], nums2 = [2,1,4,6,9] 输出：1

最少只需要一次同下标交换，即可让两条序列同时严格递增。

准备好再揭开状态转移

下面的独立区域包含完整思路、证明、复杂度和四种语言代码，默认不会显示。

Dynamic Programming

只记住当前位置的两种结局

关键不是枚举交换集合，而是记录“到当前下标为止，当前列保持/交换时的最优代价”。

核心洞察

K

keep

处理到下标 i，且不交换第 i 列时的最少交换数。

S

swap

处理到下标 i，且交换第 i 列时的最少交换数。

2

只看相邻列

严格递增只约束相邻元素，因此转移只需要上一列的两个状态。

状态转移

初始时，第 0 列保持的代价是 0，交换的代价是 1。对每个 i > 0，检查两类连接：

straight = nums1[i-1] < nums1[i] 且 nums2[i-1] < nums2[i] cross = nums1[i-1] < nums2[i] 且 nums2[i-1] < nums1[i] 若 straight： nextKeep = min(nextKeep, keep) nextSwap = min(nextSwap, swap + 1) 若 cross： nextKeep = min(nextKeep, swap) nextSwap = min(nextSwap, keep + 1)

直连成立时，前后两列的交换状态相同；交叉连接成立时，前后两列的交换状态相反。两种连接可能同时成立，要同时尝试并取最小值。

完整过程：示例 1

i当前列直连交叉keepswap
0(1, 1)——01
1(3, 2)成立成立01
2(5, 3)成立不成立02
3(4, 7)不成立成立21

最后答案为 min(keep, swap) = min(2, 1) = 1。

正确性证明

状态完备性：任一可行方案在下标 i 只有“交换”或“不交换”两种结局，分别被 swap 和 keep 覆盖。

转移正确性：若相邻两列同状态，合法性恰由直连条件决定；若状态不同，合法性恰由交叉条件决定。转移枚举了所有合法前驱并取最小代价。

归纳结论：初始状态显然最优；假设上一列两状态最优，按上述穷尽且取最小的转移，当前列两状态也最优。最终两种结局取小值即为全局最优。

边界与细节

  • 必须使用严格小于号，等于也不满足严格递增。
  • 用足够大的有限值表示不可达，避免加 1 溢出。
  • 两种连接条件可能同时成立，不能写成互斥的 if / else。
  • 题目保证有解；否则最终两个状态可能都不可达。
复杂度：时间 O(n)，滚动变量将额外空间降为 O(1)。

替代方案

二维 DP 数组

保存每个下标的 dp[i][0/1]，转移最直观，也便于还原具体交换位置；时间 O(n)、空间 O(n)。

暴力 / 回溯

每列交换或不交换共有 2^n 种组合，即使剪枝也无法承受 10^5 的规模，只适合作为理解状态的起点。

class Solution {
    public int minSwap(int[] nums1, int[] nums2) {
        int keep = 0;
        int swap = 1;
        final int INF = nums1.length + 1;

        for (int i = 1; i < nums1.length; i++) {
            int nextKeep = INF;
            int nextSwap = INF;

            if (nums1[i - 1] < nums1[i]
                    && nums2[i - 1] < nums2[i]) {
                nextKeep = Math.min(nextKeep, keep);
                nextSwap = Math.min(nextSwap, swap + 1);
            }

            if (nums1[i - 1] < nums2[i]
                    && nums2[i - 1] < nums1[i]) {
                nextKeep = Math.min(nextKeep, swap);
                nextSwap = Math.min(nextSwap, keep + 1);
            }

            keep = nextKeep;
            swap = nextSwap;
        }

        return Math.min(keep, swap);
    }
}

面试追问

如何还原具体交换位置？

保留完整 DP 数组，并为每个状态记录来自 keep 还是 swap，最后从较小的终态逆向回溯。

如果交换每个位置的成本不同？

把 +1 改为 +cost[i]，状态与合法性判断不变。

为什么不需要知道更早的元素？

当前前缀已经严格递增时，追加一列是否合法只取决于它与紧邻上一列的大小关系。

常见错误

把直连与交叉写成 else-if

二者可以同时成立；漏掉一条转移可能丢失更优路径。

交换后真的修改原数组

滚动 DP 只需要比较原始相邻值，并通过状态解释是否交换，无需改动数组。

原地更新 keep 后再计算 swap

会混用当前轮与上一轮状态。必须先算 nextKeep、nextSwap，再一起覆盖。
