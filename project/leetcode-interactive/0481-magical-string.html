Problem

题意

神奇字符串 s 只含字符 '1' 与 '2'。把其中连续相同字符划为一组，再依次写下每组的长度，得到的数字序列恰好仍是 s 自身。

给定整数 n，返回神奇字符串前 n 个数字中 1 的数量。

1 · 22 · 11 · 2 · 1 · 22 · 1 · 22 · 11 · …
组长 → 1, 2, 2, 1, 1, 2, 1, 2, 2, …，仍与原串相同。

Solution

双指针自描述构造

真正有用的不是预先知道整串，而是利用已经生成的部分继续生成后面的部分。

核心洞察

从确定的种子 122 出发，令读指针 head = 2。s[head] 同时也是下一组的长度；待写数字从 1 开始，每轮在 1、2 之间切换。写到长度达到 n 即可停止，并在写入 1 时累计答案。

完整过程

  1. 若 n <= 3，直接返回种子 122 中对应前缀的结果 1。
  2. 初始化数组为 [1, 2, 2]，读指针指向下标 2，下一组数字设为 1。
  3. 读取 s[head]，把下一组数字追加相应次数；只追加到长度 n。
  4. 翻转下一组数字：next = 3 - next，再让 head 右移。
  5. 重复直到已有 n 个数字，返回累计的 1 的数量。

边界处理

  • n = 1, 2, 3 都落在种子内部，答案均为 1。
  • 一组可能跨过第 n 位；循环写入时必须同时检查当前长度是否仍小于 n。
  • 约束上限是 10^5，线性数组可以安全容纳所需前缀。
  • 输入保证至少为 1，无需为零或负数定义额外语义。
Correctness

正确性证明

1

循环不变式

每轮开始时，数组是神奇字符串的一个正确前缀；head 指向尚未用于生成新组的第一个长度描述；next 是紧接当前前缀之后那一组应使用的数字。

2

保持

根据自描述规则，s[head] 正是下一组的长度。追加 s[head] 个 next，得到的仍是正确前缀；因为相邻组数字交替出现，令 next = 3 - next 后，不变式对下一轮继续成立。

3

终止

每轮至少追加一个数字，长度严格增加，最终达到 n。此时数组前 n 位就是神奇字符串所需前缀，而计数器恰在这些位置写入 1 时增加，因此返回值正确。

Cost

复杂度

O(n) 时间

最多生成并访问前 n 个数字，每个数字只承担常数次工作。

O(n) 空间

读指针必须回看已经生成的长度描述，因此保存至多 n 个数字。

Implementations

四种语言完整代码

Java · 官方签名
class Solution {
    public int magicalString(int n) {
        if (n <= 3) return 1;

        int[] s = new int[n];
        s[0] = 1;
        s[1] = 2;
        s[2] = 2;

        int head = 2;
        int tail = 3;
        int next = 1;
        int ones = 1;

        while (tail < n) {
            int groupLength = s[head];
            for (int i = 0; i < groupLength && tail < n; i++) {
                s[tail++] = next;
                if (next == 1) ones++;
            }
            next = 3 - next;
            head++;
        }
        return ones;
    }
}

class Solution:
    def magicalString(self, n: int) -> int:
        if n <= 3:
            return 1

        s = [1, 2, 2]
        head = 2
        next_digit = 1
        ones = 1

        while len(s) < n:
            group_length = s[head]
            for _ in range(group_length):
                if len(s) == n:
                    break
                s.append(next_digit)
                if next_digit == 1:
                    ones += 1
            next_digit = 3 - next_digit
            head += 1

        return ones

替代方案

预生成全局前缀：若要回答大量查询，可以一次生成到所有查询中的最大 n，再建立前缀和，使单次查询降为 O(1)。代价是需要提前知道最大范围，并维护额外计数数组。

游程编码视角：也可维护显式的“组”，但每组仍需要由既有序列的数字决定，状态更多，并不会改善渐进复杂度。

面试追问

  • 为什么不能只保留常数个最近数字？
  • 若有十万个不同的 n 查询，怎样复用一次构造？
  • 怎样把计数目标改为前 n 个 2 的数量？
  • 如果组长允许大于 2，自描述构造还需改变哪些条件？
Pitfalls

常见错误

  • 把读指针当成字符组编号；实际上它是数组下标，数组中的值才是组长。
  • 追加完整一组后才判断长度，导致跨越 n 的多余数字也被计入答案。
  • 忘记每轮把待写数字从 1 切换为 2，或从 2 切回 1。
  • 使用字符串拼接构造大量中间对象；数组写入更直接，也更容易控制边界。
  • 对 n <= 3 仍创建长度为 n 的数组并写入三个种子元素，造成越界。
