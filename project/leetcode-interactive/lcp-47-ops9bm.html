LCP 47. 入场安检

安检室可设为 FIFO 或 LIFO。FIFO 不改变编号顺序，容量为 c 的 LIFO 会把目标观众向前移动 c - 1 位——于是问题化成 0/1 背包计数。

0/1 背包计数 DPO(nk)

题意

有若干安检室，capacities[i] 是第 i 室容量，总容量为 M。编号 0…M 的 M + 1 名观众依次进入。每个房间可任意设成先进先出或后进先出；问让编号 k 的观众第一个通过最后一间安检室的类型设定数，答案模 1_000_000_007。

示例 1

capacities = [2, 2, 3], k = 2

输出：2

示例 3

capacities = [4, 3, 2, 2], k = 6

输出：2

约束：1 ≤ capacities.length ≤ 200，1 ≤ capacities[i] ≤ 200，0 ≤ k ≤ sum(capacities)。

交互：背包位移

题解：每个 LIFO 是一件位移物品

核心洞察

FIFO 保持队列顺序。容量为 c 的 LIFO 房间会使第 k 位观众相对队首前进 c - 1 位。要让其成为最后出口第一人，只需选一批 LIFO 房间，使这些位移之和恰为 k。

完整过程

  1. dp[s]：位移和为 s 的设定数。
  2. 初始 dp[0] = 1。
  3. 每间房要么 FIFO（不变），要么 LIFO（加 c-1）。
  4. 倒序更新，确保每间房只选一次。

边界与复杂度

容量 1 的房间位移为 0，但 FIFO/LIFO 仍是两种类型设定，所以更新会把每个 dp[s] 翻倍。k 大于可达位移时答案为 0。时间 O(nk)，空间 O(k)。

替代方案

可用二维 DP 显式记录前 i 个房间，但空间会增至 O(nk)；一维倒序更新正是其压缩。

常见错误

  • 把重量误写成 c，应是 c - 1。
  • 正序更新，导致同一房间被重复选择。
  • 漏掉容量 1 的双倍方案数。

面试追问

如果 LIFO 只能选固定数量，可扩展 DP 维度记录已选房间数；若每种类型有成本，则把计数改为最小成本或最大收益 DP。

四语言可提交代码

// Java
class Solution {
  public int securityCheck(int[] capacities, int k) {
    final int MOD = 1_000_000_007; long[] dp = new long[k + 1]; dp[0] = 1;
    for (int c : capacities) for (int s = k; s >= c - 1; s--) dp[s] = (dp[s] + dp[s - (c - 1)]) % MOD;
    return (int) dp[k];
  }
}
// JavaScript
var securityCheck = function (capacities, k) {
  const MOD = 1000000007n, dp = Array(k + 1).fill(0n); dp[0] = 1n;

};

class Solution:
    def securityCheck(self, capacities: List[int], k: int) -> int:
        mod = 1_000_000_007; dp = [0] * (k + 1); dp[0] = 1
        for c in capacities:
            for s in range(k, c - 2, -1): dp[s] = (dp[s] + dp[s - (c - 1)]) % mod
        return dp[k]
