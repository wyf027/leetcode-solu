题意

32 个字符内，能否精确打印？

给定一个介于 0 和 1 之间的实数 num，返回它的二进制小数表达式。如果无法在 32 个字符内精确表示，返回 "ERROR"。长度限制包含开头的 "0."，因此最多只能打印 30 个小数位。

示例 1

输入

num = 0.625

输出

"0.101"

示例 2

输入

num = 0.1

输出

"ERROR"

字符配额

32

  • • 输入小数位最多 6 位。
  • • 必须精确表示，不能用近似值冒充成功。
  • • 一旦余数归零，立即停止并返回当前纸带。

题解

先看纸带，再打开机盖

核心洞察、完整过程与四语言代码默认隐藏。

核心洞察：十进制的“乘十取整”，换成二进制就是“乘二取整”

对小数反复乘 2。结果的整数部分只能是 0 或 1，它正是下一位二进制字符； 去掉整数部分后的余数继续参与下一轮。余数归零说明已经精确表示；打印 30 位后仍有余数，说明总长度会超过 32，返回 "ERROR"。

完整过程

  1. 1. 用 "0." 初始化答案，已经占用 2 格。
  2. 2. 在余数大于 0 且答案长度小于 32 时，执行 num *= 2。
  3. 3. 若结果至少为 1，打印 1 并减去 1；否则打印 0。
  4. 4. 循环结束后，余数为 0 就返回纸带，否则返回 "ERROR"。

边界与精度

  • • 32 位包含 "0."，最多追加 30 位。
  • • 恰好在第 30 位后余数归零，仍然合法。
  • • 不使用 epsilon；题目要求精确，容差会把不可精确表示的数误判为成功。
  • • 0.5 第一轮就归零，输出 "0.1"。

复杂度

最多 30 轮，时间 O(min(k, 30))；除输出字符串外，辅助空间 O(1)。

替代方案

可逐项比较 1/2、1/4、1/8 等权值，但仍需维护余数；乘二取整更直接。

面试追问

若没有 32 位上限，可用余数集合检测循环；若输入是十进制字符串，可转成整数分数避免浮点语义。

常见错误

把 32 当成小数位数、忘记减整数部分、用近似阈值提前归零，都会得到错误答案。

class Solution {
    public String printBin(double num) {
        StringBuilder answer = new StringBuilder("0.");

        while (num > 0 && answer.length() < 32) {
            num *= 2;
            if (num >= 1) {
                answer.append('1');
                num -= 1;
            } else {
                answer.append('0');
            }
        }

        return num == 0 ? answer.toString() : "ERROR";
    }
}
