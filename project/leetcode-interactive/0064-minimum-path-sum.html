MISSION BRIEF

题意

给定一个由非负整数组成的 m × n 网格，从左上角走到右下角，每次只能向右或向下。返回沿途所有格子数字之和的最小值。

官方样例 1

输入
grid = [[1,3,1],[1,5,1],[4,2,1]]
输出
7
路线
1 → 3 → 1 → 1 → 1

官方样例 2

输入
grid = [[1,2,3],[4,5,6]]
输出
12
路线
1 → 2 → 3 → 6

约束

  • m == grid.length
  • n == grid[i].length
  • 1 ≤ m, n ≤ 200
  • 0 ≤ grid[i][j] ≤ 200

题解

Core insight

核心洞察

抵达 (row, col) 的最后一步只可能来自上方或左侧。于是最低累计成本等于当前格成本，加上这两个前驱中的较小值。按从左上到右下的顺序扫描时，前驱已经计算完成。

grid[r][c] += min(grid[r - 1][c], grid[r][c - 1])

Interview mainline

为什么主推原地 DP

网格本身正好可以保存每格的最优子问题答案，因此额外空间为常数。面试时先确认「允许修改输入吗」；若不允许，切换为一维数组，逻辑完全相同，额外空间为 O(n)。

完整过程

  1. 1. 起点保持原值，因为路线必然从这里开始。
  2. 2. 第一行只能从左边来，累加左侧累计成本。
  3. 3. 第一列只能从上边来，累加上方累计成本。
  4. 4. 其余格子取上、左较小者，再加自身成本。
  5. 5. 右下角即全局最小路径和。

边界

  • 单格：答案就是该格本身，包括 0。
  • 单行：没有上方来源，只能一路向右累加。
  • 单列：没有左侧来源，只能一路向下累加。
  • 非负权重保证数值单调，但 DP 并不依赖贪心选择。

复杂度

TIME
O(mn)
EXTRA SPACE
O(1)

替代方案

  • 一维 DP：不修改输入，空间 O(n)，最适合输入需复用的场景。
  • 二维 DP：最直观且便于恢复路径，但空间 O(mn)。
  • 记忆化搜索：易从递归定义出发，但有栈开销且实现更重。
  • 局部贪心：不可行；当前较小的格子可能把后续引向高成本区域。

面试追问

  • 若还要返回具体路径？保存前驱，或从二维累计表反向选择较小前驱。
  • 若允许四个方向？依赖关系不再是 DAG，应考虑 Dijkstra。
  • 若存在障碍？障碍格设为不可达的无穷大，并谨慎处理边界。
  • 若有负权值？仅右/下仍是 DAG，当前 DP 依然成立。

常见错误

  • 第一行或第一列错误地同时读取两个前驱，造成越界。
  • 从右下往左上更新，却仍使用上方和左侧，破坏依赖顺序。
  • 忘记原地写法会修改输入，后续逻辑仍使用原始网格。
  • 用「每步选较小邻居」替代 DP，忽略未来成本。

class Solution {
    public int minPathSum(int[][] grid) {
        int rows = grid.length;
        int cols = grid[0].length;

        for (int row = 0; row < rows; row++) {
            for (int col = 0; col < cols; col++) {
                if (row == 0 && col == 0) {
                    continue;
                }
                if (row == 0) {
                    grid[row][col] += grid[row][col - 1];
                } else if (col == 0) {
                    grid[row][col] += grid[row - 1][col];
                } else {
                    grid[row][col] += Math.min(
                        grid[row - 1][col],
                        grid[row][col - 1]
                    );
                }
            }
        }
        return grid[rows - 1][cols - 1];
    }
}
