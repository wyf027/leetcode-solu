字符串的总引力

Total Appeal of A String

一段字符串，多少种不同的字符？
把这个问题，问遍它的每一个连续片段。

题目理解

01 / READ

字符串的引力是其中不同字符的数量。例如 "abbca" 中有 a、b、c 三种字符，引力是 3。

给定字符串 s，求它的所有非空连续子串的引力之和，返回一个整数。子串由起止位置确定；即使内容相同，只要位置不同，也分别计入。

先想一想：相邻位置的两个 "b" 是两个子串，而 "bb" 只有一种字符。

参数：s: string · 返回：整数总和（官方返回类型 long）

输入边界

1 ≤ s.length ≤ 10⁵

s 仅包含小写英文字母 a–z。

子串必须连续，不是任意选择字符得到的子序列。

题解 · 只计算新增加的引力

令 endSum 表示所有以当前位置 i 结尾的子串的引力之和。把前一位置的子串全部向右扩展一格，再加入单字符子串，就得到这一组子串。

p = last[s[i]]（此前最近位置，未出现为 −1）
endSum += i − p
answer += endSum
last[s[i]] = i

关键在于起点：起点 l ≤ p 的子串已经包含当前字符，引力不增加；p < l ≤ i 的子串会多出一种字符，共有 i − p 个。这个计数也包括新建的单字符子串。

完整过程

  1. 初始化 26 个最近位置为 −1，endSum = answer = 0。
  2. 从左到右读取字符，先取出它此前的最近位置 p。
  3. 用 i − p 更新本组引力，再把本组引力累加到答案。
  4. 最后更新当前字符的最近位置。处理完全部位置后返回答案。

为什么正确

不变式：处理位置 i 后，last 记录前缀中各字符最后一次出现的位置，endSum 等于所有以 i 结尾的子串引力之和。

基础：空前缀时 endSum 为 0，last 全为 −1。i = 0 时增量为 1，恰好得到单字符子串的引力。

归纳：假设前一步成立。把旧子串扩展后，只可能增加当前字符这一种。按起点是否大于 p 分组，恰有 i − p 个子串增加 1（含新单字符子串），因此递推维持不变式。

完备：每个非空子串有且只有一个右端点。累加各组 endSum，所有子串都恰好统计一次。

复杂度与边界

时间 O(n)：每个字符进行固定次数更新。辅助空间 O(26) = O(1)。

全部相同：每步 endSum 增加 1，答案为 n(n+1)/2。全部不同：每步增量为 i+1，累计结果为 n(n+1)(n+2)/6（本题此情形 n ≤ 26）。

答案不超过 26 × n(n+1)/2；n = 100000 时上界为 130001300000，超出 32 位整数。

Java 使用 long，C++ 使用 long long，Python 整数自动扩展；JavaScript Number 的安全整数范围足够，无需 BigInt。空串不在官方约束内。

四语言实现

均采用官方函数签名，可按对应语言提交；代码仅生成，尚未运行。

Java

import java.util.Arrays;

class Solution {
    public long appealSum(String s) {
        int[] last = new int[26];
        Arrays.fill(last, -1);
        long endSum = 0, answer = 0;
        for (int i = 0; i < s.length(); i++) {
            int c = s.charAt(i) - 'a';
            endSum += i - last[c];
            answer += endSum;
            last[c] = i;
        }
        return answer;
    }
}

替代方案

按字符出现位置贡献：令 p 为 s[i] 上次出现的位置。把 i 视为某个子串内该字符的第一次出现，则左端点有 i − p 种选择，右端点有 n − i 种选择。累加 (i − p) × (n − i)，同样 O(n) 时间、O(26) 空间。Java/C++ 乘法须先转为 64 位。

按末次位置求和：每个右端点上，字符 c 存在于 last[c]+1 个子串中。累加 26 项再累加到答案，时间 O(26n)，思路直观。

枚举：固定起点，逐步扩展右端点并维护集合，时间 O(n²)、空间 O(26)。适合理解题意，不适用于长度 10⁵。

常见错误

  • 把引力理解成“只出现一次的字符数”；bb 的引力仍然是 1。
  • last 初值设为 0，导致首次出现时少算一个起点。
  • 先更新 last 再计算差值，使增量变成 0。
  • 只把 i − p 加进答案；它是本组的增量，不是本组总引力。
  • 对相同内容的子串去重，漏掉不同位置的贡献。
  • 用 32 位 answer，长字符串发生溢出。

面试追问

如果字符集变大？用 Map / 字典存最近位置；复杂度为 O(n) 期望时间，O(k) 空间，k 为出现过的不同字符数。Unicode 场景还要先约定按码点还是用户可见字符计数。

如果输入是流？递推只依赖 last、endSum 和当前下标，可逐字符输出前缀总引力，无需保存历史字符串。

如果每种字符有不同权重？把增量改为 weight[c] × (i − p)，并重新评估整数范围。

能否只用滑动窗口？常规窗口通常维护一种约束下的区间；这里要统计所有子串，最近位置将所有合法起点的增量压缩成一次计算。
