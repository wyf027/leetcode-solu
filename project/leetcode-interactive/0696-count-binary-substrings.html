当字符从 0 切换到 1，或从 1 切换到 0 时，边界两侧能组合出多少个合法子串？

01 / Problem

题目说明

给定一个二进制字符串 s，返回满足以下条件的非空连续子字符串数量：

  • 子串中的 0 和 1 数量相同；
  • 其中所有 0 连成一组，所有 1 也连成一组。
相同文本若出现在不同位置，要按出现次数分别计数。子串必须连续。

函数签名与约束

参数：s: string
返回：integer

  • 1 ≤ s.length ≤ 10⁵
  • s[i] 只能是 '0' 或 '1'
官方示例 1重复位置计数
输入s = "00110011"
输出6
解释合法子串为 "0011"、"01"、"1100"、"10"、"0011"、"01"。整个字符串不合法，因为同类字符并非各自只形成一组。
官方示例 2交替字符
输入s = "10101"
输出4
解释四个合法位置片段依次是 "10"、"01"、"10"、"01"。

03 / Solution

完整解析

相邻分组，贡献取短

把连续相同字符视为一组。每个合法子串只跨越一个 0/1 边界，而每个边界能贡献多少个答案，只取决于它两侧的组长。

核心洞察

设某个边界左侧连续组长度为 a，右侧连续组长度为 b。合法子串可以各取 1 个、各取 2 个……最多各取 min(a, b) 个，因此该边界贡献：

contribution = min(a, b)

完整过程

  1. 令 prev = 0、curr = 1，从第二个字符开始扫描。
  2. 若当前字符与前一个相同，当前组长度 curr 加一。
  3. 若字符改变，旧的相邻组对已完整确定：把 min(prev, curr) 加入答案，再令 prev = curr、curr = 1。
  4. 循环结束后，别忘了结算最后一对相邻组。

示例走读

00110011 的组长为 [2, 2, 2, 2]。

三个相邻边界分别贡献 min(2,2)=2，总计 2+2+2=6。

每个贡献对应一个唯一边界和一个唯一半长，不会重复归属。

正确性证明

引理 1：任意合法子串恰好包含两个连续字符组。因为 0 必须成一组、1 必须成一组，且二者都出现，所以它恰好跨越一个字符切换边界。

引理 2：对于长度为 a、b 的相邻组，恰有 min(a,b) 个合法子串。选择相同数量 k 的左右字符时，k 可且仅可取 1..min(a,b)；每个 k 唯一确定一个贴着边界的子串。

结论：算法逐一结算所有相邻组对。由引理 1，每个合法子串被覆盖；由唯一边界与唯一 k，没有重复计数；由引理 2，每次贡献准确，因此总答案正确。

边界与复杂度

  • 长度为 1：没有两个字符组，答案为 0。
  • 全是同一字符：始终只有一个组，答案为 0。
  • 完全交替：每个相邻字符形成一个贡献，答案为 n - 1。
  • 最后一对组不会在循环内自然结算，必须在循环后补一次。

时间：O(n)；额外空间：O(1)。

替代方案

可以先把所有连续组长度存入数组，再累加每对相邻组的最小值。这同样是 O(n) 时间，但需要最坏 O(n) 空间；优点是更直观，也便于调试和可视化。

还可以从每个边界向两侧扩张，不过最坏会重复扫描大量字符，容易退化到 O(n²)，不适合长度上限 10⁵。

常见错误

  • 把题意误读成“0 和 1 数量相同”即可，忽略同类字符必须各自连续成组。
  • 用 max(prev, curr) 或两组之和；正确上限由更短的一组决定。
  • 切换字符时先覆盖 curr，导致丢失刚结束组的长度。
  • 漏掉扫描结束后的最后一次结算。
  • 用集合去重；本题按出现位置计数，文本相同也不能去重。

Implementation

四语言完整代码

四份实现都只保留前一组长度、当前组长度与累计答案。

Java
class Solution {
    public int countBinarySubstrings(String s) {
        int previous = 0;
        int current = 1;
        int answer = 0;

        for (int i = 1; i < s.length(); i++) {
            if (s.charAt(i) == s.charAt(i - 1)) {
                current++;
            } else {
                answer += Math.min(previous, current);
                previous = current;
                current = 1;
            }
        }

        return answer + Math.min(previous, current);
    }
}

Interview follow-ups

面试追问

为什么不需要真正截取子串？

答案只依赖相邻连续组的长度。截取字符串既不参与判断，也会产生额外分配；扫描并维护两个计数器就足够。

如果字符不止 0 和 1，这个方法还能用吗？

若要求仍是“恰好两个不同字符、各自连续成组且数量相同”，相邻组取最小值的方法仍成立；每个相邻分组对都贡献相应数量。

如何输出所有合法子串的位置？

在每个相邻组边界处，对 k = 1..min(a,b) 生成区间 [boundary-k, boundary+k-1]。输出量本身可能很大，额外空间至少与结果数成正比。
