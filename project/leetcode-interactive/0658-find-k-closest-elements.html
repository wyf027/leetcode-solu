Problem 658 · Find K Closest Elements

找到 K 个
最接近的元素

给定一个已经升序排列的整数数组 arr，以及整数 k 和 x。选出最接近 x 的 k 个整数，并将结果保持为升序。

Array Binary Search Sliding Window Two Pointers
输入
arr, k, x
输出
List<Integer>
关键规则
等距时取更小值

先理解判定规则，再向下探索过程；完整题解位于页面底部并默认收起。

01 · 题意

什么叫“更接近”？

对于任意两个整数 a 和 b，先比较它们与 x 的距离；距离相同时，更小的整数优先。最终答案必须按升序返回。

RULE 01
距离更小

|a - x| < |b - x| 时，a 比 b 更接近 x。

RULE 02
距离相等，较小者优先

|a - x| == |b - x| 且 a < b 时，优先选择 a。

官方示例 01
输入arr = [1,2,3,4,5], k = 4, x = 3
输出[1,2,3,4]
官方示例 02
输入arr = [1,1,2,3,4,5], k = 4, x = -1
输出[1,1,2,3]

约束

  • 1 <= k <= arr.length
  • 1 <= arr.length <= 104
  • arr 按升序排列。
  • -104 <= arr[i], x <= 104

Solution · Binary Search on Window

二分“窗口起点”，不是二分元素

答案一定是原数组中的一段连续子数组。问题因此转化为：在 0 到 n-k 之间，找到最佳长度为 k 的窗口起点。

核心洞察

假设当前尝试的窗口起点是 mid。长度为 k 的窗口为 [mid, mid+k-1]，而 arr[mid+k] 是窗口右侧紧邻的第一个元素。

比较 x - arr[mid] 与 arr[mid+k] - x：如果左边更大，说明左端元素比右侧候选更不合适，窗口应该右移；否则窗口保留向左的可能。相等时走左侧，恰好落实“等距时较小值优先”。

完整过程

  1. 令 left = 0、right = n - k。每个整数都代表一个合法的长度为 k 的窗口起点。
  2. 当 left < right 时，取 mid = left + (right-left)/2 的下取整值。
  3. 若 x - arr[mid] > arr[mid+k] - x，丢弃 mid 及其左侧起点，令 left = mid + 1。
  4. 否则令 right = mid。这里保留 mid，因为它仍可能是最左的最佳起点，且等距时应该偏左。
  5. 循环结束时 left == right，返回 arr[left ... left+k-1]。

正确性证明

引理 1

答案必连续

若选了数组两端的两个元素，却漏掉它们之间的元素，中间元素到 x 不会比两端都更远。因此总能把答案写成长度为 k 的连续窗口。

引理 2

比较决定方向

若 x-arr[mid] 更大，则窗口左端比右侧新元素更远，最佳窗口不可能从 mid 或更左开始，所以可以令 left=mid+1。

引理 3

不变量保证答案

每次更新都保留至少一个最佳起点在闭区间 [left,right] 中。区间最终缩为单点，该点就是最左的最佳窗口起点。

由三个引理，算法返回的连续窗口恰含最接近 x 的 k 个元素；窗口沿原升序数组截取，因此输出也保持升序。

边界与复杂度

时间复杂度
O(log(n-k) + k)

二分起点区间，再复制长度为 k 的答案。

额外空间
O(1)

不计返回数组；只维护少量下标。

边界：k == n 时起点区间只有 0，直接返回全数组；x 在数组范围外时比较式仍然成立；重复元素不会破坏单调性；相等时必须收缩右边界以偏向较小元素。

四语言完整代码

class Solution {
    public List<Integer> findClosestElements(int[] arr, int k, int x) {
        int left = 0;
        int right = arr.length - k;

        while (left < right) {
            int mid = left + (right - left) / 2;

            if (x - arr[mid] > arr[mid + k] - x) {
                left = mid + 1;
            } else {
                right = mid;
            }
        }

        List<Integer> answer = new ArrayList<>(k);
        for (int i = left; i < left + k; i++) {
            answer.add(arr[i]);
        }
        return answer;
    }
}

        if (x - arr[mid] > arr[mid + k] - x) {

        } else {

        }
    }

    return arr.slice(left, left + k);

替代方案

收缩双指针

从整个数组的左右端开始，每次移除更远的一端，直到剩下 k 个元素。

O(n-k) 时间 · O(1) 空间

按距离排序

将元素按“距离、数值”排序，取前 k 个后再升序排列。直观但未利用原数组有序性。

O(n log n) 时间

二分定位 + 双指针扩张

先找到 x 的插入位置，再从两侧选出更近者，共选择 k 次。

O(log n + k) 时间

面试追问

  1. 为什么答案必然是一段连续子数组？如果数组没有排序，这个结论还成立吗？
  2. 比较式为什么不写绝对值？当 x 小于所有元素或大于所有元素时还安全吗？
  3. 为什么相等时执行 right = mid，而不是向右移动？
  4. 若只需返回元素、不要求升序，你会选择堆吗？在什么规模下更合适？
  5. 怎样把算法改造成流式输入版本？内存限制会改变哪部分设计？

常见错误

  • 把右边界设成 n-k-1。合法起点包含 n-k，会因此漏掉最右窗口。
  • 访问 arr[mid+k-1]。比较对象应该是窗口左端 arr[mid] 与右侧紧邻元素 arr[mid+k]。
  • 相等时向右移动，破坏“距离相同时取更小值”的规则。
  • 二分结束后重新排序答案。窗口本来就在升序数组中，直接切片即可。
  • 忽略 k == n。此时 right == 0，循环自然跳过，不应访问 arr[k]。
