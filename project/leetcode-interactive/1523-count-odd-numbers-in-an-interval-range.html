Solution

完整题解

核心洞察

从 0 到 x（含两端）一共有 ⌊(x + 1) / 2⌋ 个奇数。于是闭区间答案等于前缀计数之差：

⌊(high + 1) / 2⌋ − ⌊low / 2⌋

右侧第二项正好是在数 [0, low - 1] 的奇数个数。

完整过程

  1. 把目标区间写成“大前缀减去不需要的小前缀”。
  2. 计算 [0, high] 的奇数数目：(high + 1) / 2 向下取整。
  3. 计算 [0, low - 1] 的奇数数目：low / 2 向下取整。
  4. 两者相减即可，无需遍历任何数字。

正确性证明

任意一对连续非负整数 (2k, 2k+1) 中恰有一个奇数。因此 [0, x] 中每两个数贡献一个奇数；若末尾多出一个数，只有当它为奇数时才额外贡献，合并后计数就是 ⌊(x+1)/2⌋。

区间 [0, high] 可拆成互不相交的 [0, low-1] 与 [low, high]。从前者的前缀计数中减去后者以外的部分，所得恰为目标区间的奇数个数，所以算法正确。

边界与复杂度

  • low = high：由唯一数字的奇偶性决定答案。
  • low = 0：被减前缀为空，low / 2 = 0。
  • 两个端点都为奇数时，首尾都会被计入。
  • 时间复杂度 O(1)，空间复杂度 O(1)。

替代方案

按区间长度判断：令 length = high - low + 1。答案至少为 length / 2 向下取整；当长度为奇数且 low 为奇数时再加一。它同样是 O(1)，但前缀差公式更统一，也更容易迁移到其他区间计数题。

逐个枚举：能得到正确结果，但最坏需要检查约 10⁹ 个数，不符合本题数据范围所暗示的常数时间目标。

四语言实现

JavaLeetCode 提交格式
class Solution {
    public int countOdds(int low, int high) {
        return (high + 1) / 2 - low / 2;
    }
}
JavaScriptLeetCode 提交格式
/**
 * @param {number} low
 * @param {number} high
 * @return {number}
 */
var countOdds = function(low, high) {
    return Math.floor((high + 1) / 2)
        - Math.floor(low / 2);
};

常见错误

  • 忘记题目是闭区间，漏掉奇数端点。
  • 误把被减项写成 (low + 1) / 2，实际上要数到 low - 1。
  • 用循环遍历，在最大范围上超时。
  • 把 JavaScript 的普通除法结果直接返回，忘记向下取整。
