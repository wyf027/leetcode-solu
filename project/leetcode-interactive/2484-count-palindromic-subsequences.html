01 / THE PROBLEM

题意与输入范围

给定数字字符串 s，统计长度恰好为 5 的回文子序列，返回数量对 1,000,000,007 取余的结果。子序列允许删除字符，但保留下来的下标必须严格递增；回文表示正向与反向读法一致。

按选择的位置组合计数。同样的数字内容，如果来自不同下标，也要分别计数。

  • 参数：s: string；返回值：integer。
  • 1 ≤ s.length ≤ 10⁴。
  • s 仅包含数字字符 '0' 至 '9'。

官方示例

EXAMPLE 01
输入：s = "103301"
输出：2

六种长度为 5 的选法得到 10330、10331、10301、10301、13301、03301。其中两种得到回文 10301，使用不同位置的 3。

EXAMPLE 02
输入：s = "0000000"
输出：21

任选五个位置，都得到 00000。共 C(7,5) = 21 种选法。

EXAMPLE 03
输入：s = "9999900000"
输出：2

只有全部五个 9 或全部五个 0 能组成回文，分别得到 99999 和 00000。

02 / SOLUTION LAB

固定中心，配对两侧的有序数对

五位回文一定长成 a b · c · b a。当中心下标确定后，中心字符可以是任意数字。左侧选一个 (a,b)，右侧选一个 (b,a)，就得到一个合法回文。

核心状态

  • left[d] / right[d]：左右区间中数字 d 的个数。
  • lp[a][b] / rp[a][b]：各区间按下标递增形成 (a,b) 的选法数。
  • 当前中心贡献：Σ lp[a][b] × rp[b][a]，遍历 100 种 (a,b)。

示例 1：中心分别为下标 2、3 时，左侧都有一个 (1,0)，右侧都有一个 (0,1)，各贡献 1，总计 2。

完整更新过程

  1. 初始化右侧：从左到右读数字 x，先将 right[a] 加到 rp[a][x]，再增加 right[x]。
  2. 移到中心 x：先减少 right[x]，再令 rp[x][b] -= right[b]，删除以当前下标为首位的数对。
  3. 累加左右镜像数对乘积，每加一项就取模。
  4. 令 lp[a][x] += left[a]，再增加 left[x]，进入下一个中心。

正确性：唯一中心与独立选择

状态不变式：统计中心 i 时，左表恰好覆盖下标小于 i 的位置，右表恰好覆盖下标大于 i 的位置。移除中心时，它是右区间最左的位置，因此只删除以它为第一位的数对；加入左侧时，它是最右的位置，因此只新增以它为第二位的数对。

不漏计：每个合法五下标序列有唯一第三个下标 i，其两侧必为 (a,b) 与 (b,a)，会在该中心的对应乘积中被计入。

不重计：每个序列只属于一个中心和一类 (a,b)。左右下标区间严格分离，每组左右数对组合唯一决定五个下标，因此乘法原理及对中心求和恰好得到全部答案。

边界与数值安全

  • 长度不足 5 时，两侧不可能都选出数对，自然返回 0。
  • 全部数字相同时，答案为 C(n,5) 取模。前导零不影响处理。
  • 数对表保留精确计数，最大为 C(10⁴,2) = 49,995,000，不需要取模。
  • 任意两个数对计数的乘积小于 2.5 × 10¹⁵。Java / C++ 使用 64 位整数。JavaScript 每项取模，乘积加已取模答案仍小于 2⁵³，可用 Number 精确表示。
  • JavaScript 不能先把全部乘积相加后再取模，否则可能失去整数精度。

复杂度与替代方案

设字符集大小 σ = 10。初始化 O(nσ)，每个中心匹配 σ² 类数对，总时间 O(nσ²) = O(100n)，额外空间 O(σ²) = O(100)；固定十种数字时也可写为 O(n) 时间、O(1) 空间。

另一种方案：枚举 100 种 (a,b)，以五层子序列 DP 匹配模式 a b ? b a。每读一个字符，从后往前更新已匹配长度；通配位匹配任意字符。时间 O(100 × 5n)，额外空间 O(5)。

保存每个下标的前后缀数对表也可行，但需要 O(100n) 空间。暴力枚举五下标为 O(n⁵)，只适合很短输入。

常见错误

  • 把子序列当成连续子串，漏掉跨位置选择。
  • 用集合去重数字字符串，合并了不同下标方案。
  • 匹配 rp[a][b]，正确方向应为 rp[b][a]。
  • 未移除中心就统计，或统计前已加入左侧，重复使用同一下标。
  • 先增加单个数字计数，再添加数对，导致 x 与自身配对。
  • Python 用 [[0]*10]*10 造成共享行；Java/C++ 用 32 位乘法导致溢出。

面试追问

为什么不记录中心数字？
中间位没有对称约束，固定位置即可。

长度变成 7 呢？
匹配左右三元组及其逆序，将状态扩展到 σ³，同时维护长度 1、2、3 的有序子序列计数。

字符种类增加呢？
可以先离散化，或用稀疏映射保存非零数对，但状态和匹配代价也随字符集增长。

Java

class Solution {
    public int countPalindromes(String s) {
        final long MOD = 1_000_000_007L;
        long[] left = new long[10], right = new long[10];
        long[][] lp = new long[10][10], rp = new long[10][10];
        for (int i = 0; i < s.length(); i++) {
            int x = s.charAt(i) - '0';
            for (int a = 0; a < 10; a++) rp[a][x] += right[a];
            right[x]++;
        }
        long ans = 0;
        for (int i = 0; i < s.length(); i++) {
            int x = s.charAt(i) - '0';
            right[x]--;
            for (int b = 0; b < 10; b++) rp[x][b] -= right[b];
            for (int a = 0; a < 10; a++)
                for (int b = 0; b < 10; b++)
                    ans = (ans + lp[a][b] * rp[b][a]) % MOD;
            for (int a = 0; a < 10; a++) lp[a][x] += left[a];
            left[x]++;
        }
        return (int) ans;
    }
}

        mod = 10**9 + 7
        left, right = [0] * 10, [0] * 10
        lp = [[0] * 10 for _ in range(10)]
        rp = [[0] * 10 for _ in range(10)]
        for ch in s:
            x = int(ch)

            x = int(ch)

#include <string>
using namespace std;

class Solution {
public:
    int countPalindromes(string s) {
        const long long MOD = 1000000007LL;
        long long left[10] = {}, right[10] = {};
        long long lp[10][10] = {}, rp[10][10] = {};
        for (char ch : s) {
            int x = ch - '0';
            for (int a = 0; a < 10; ++a) rp[a][x] += right[a];
            ++right[x];
        }
        long long ans = 0;
        for (char ch : s) {
            int x = ch - '0';
            --right[x];
            for (int b = 0; b < 10; ++b) rp[x][b] -= right[b];
            for (int a = 0; a < 10; ++a)
                for (int b = 0; b < 10; ++b)
                    ans = (ans + lp[a][b] * rp[b][a]) % MOD;
            for (int a = 0; a < 10; ++a) lp[a][x] += left[a];
            ++left[x];
        }
        return static_cast<int>(ans);
    }
};
