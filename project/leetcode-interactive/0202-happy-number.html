快乐数

把一个正整数不断替换为“各位数字平方和”。它会到达 1，还是掉进一个永不经过 1 的循环？

题意

给定正整数 n，重复计算每一位数字的平方和。若最终得到 1，返回 true；若过程进入不含 1 的循环，返回 false。

官方样例 1

n = 19

输出：true

19 → 82 → 68 → 100 → 1

官方样例 2

n = 2

输出：false

约束：1 ≤ n ≤ 2³¹ − 1。

题解

首屏默认折叠，展开后查看推理与可提交代码。

核心洞察：有限状态 + Floyd 判环

设 next(x) 为各位数字平方和。任意 n ≤ 2³¹−1 至多 10 位，因此一次变换后不超过 10 × 9² = 810。后续状态只会在一个很小的有限集合中移动：不是到 1，就是重复。

用快慢指针即可不存集合：慢指针每轮走一步，快指针每轮走两步。若快指针遇到 1 则成功；若二者相遇，则进入了非 1 的环。

完整过程（n = 19）

  1. 1. next(19) = 1² + 9² = 82
  2. 2. next(82) = 8² + 2² = 68
  3. 3. next(68) = 6² + 8² = 100
  4. 4. next(100) = 1² + 0² + 0² = 1，返回 true。

边界

  • • n = 1 立刻成功。
  • • 0 的平方仍为 0，但题目保证 n 为正。
  • • 不要把“遇到重复”误判成成功；只有 1 是成功终点。

复杂度

单次变换消耗 O(log n) 数位；状态上界很小，整体可写为 O(log n) 时间。Floyd 额外空间 O(1)。

替代方案

哈希集合更直观：记录访问过的值，重复即失败，空间 O(log n)。面试中优先讲集合以保证可读性，再给出 Floyd 的 O(1) 空间优化。

面试追问与常见错误

追问：为什么一定会停？因为变换后很快进入有限范围，有限状态序列必然重复或到达 1。

错误：快指针只走一步，或把 slow == fast 当作 true；相遇恰恰代表检测到环。 

class Solution {
    public boolean isHappy(int n) {
        int slow = n;
        int fast = next(n);
        while (fast != 1 && slow != fast) {
            slow = next(slow);
            fast = next(next(fast));
        }
        return fast == 1;
    }
    private int next(int n) {
        int sum = 0;
        while (n > 0) { int d = n % 10; sum += d * d; n /= 10; }
        return sum;
    }
}
