猜数字大小

Guess Number Higher or Lower

你负责提出数字，预定义接口负责告诉你方向。先读懂接口的三种反馈，再到下方亲手推进一次猜数过程。

阅读题目 进入猜数实验台
Problem

题目描述

系统从闭区间 [1, n] 中选定一个整数 pick，且这个数在整场游戏中不变。你的任务是找出它。

每次调用预定义接口 int guess(int num)，会得到一种反馈：

  • -1：本次猜测太大，即 num > pick。
  • 1：本次猜测太小，即 num < pick。
  • 0：猜中，即 num == pick。

返回系统选定的数字。在线提交时，guess 接口由判题系统提供，不需要自行实现。

官方示例

示例 1
输入：n = 10, pick = 6
输出：6
示例 2
输入：n = 1, pick = 1
输出：1
示例 3
输入：n = 2, pick = 1
输出：1

约束

  • 1 <= n <= 231 - 1
  • 1 <= pick <= n

参数说明

题面示例会写出 pick 方便理解，但提交函数只接收 n；隐藏值通过 guess(num) 间接访问。

Solution

二分查找：把一次反馈变成一半的排除

核心洞察

guess(mid) 不只判断一个点，还能排除半个有序区间。始终维护“答案一定在 [left, right] 中”的不变量，每轮取中点并依据返回值保留唯一可能的一侧。

完整过程

  1. 初始化 left = 1、right = n。
  2. 当 left <= right 时，计算 mid = left + (right - left) / 2 的向下取整结果。
  3. 调用 guess(mid)。
  4. 返回 0 就直接返回 mid；返回 -1 说明答案更小，令 right = mid - 1；否则令 left = mid + 1。

边界处理

  • 只有一个数：left == right 时仍会检查该点并命中。
  • 极大 n：用 left + (right - left) / 2 避免 Java/C++ 中 left + right 溢出。
  • 排除中点：反馈已经证明中点不等于答案，所以更新为 mid - 1 或 mid + 1，避免死循环。

正确性证明

1
初始化

由题意 1 <= pick <= n，因此开始时答案位于 [1, n]，不变量成立。

2
保持

若接口返回 -1，则 mid > pick，答案只能在 [left, mid - 1]；若返回 1，答案只能在 [mid + 1, right]。两种更新都保留答案并排除不可能区域。

3
终止

每次未命中都会严格缩短有限区间，而答案始终留在区间内，所以最终必定出现 mid == pick 并返回正确答案。

复杂度

时间复杂度 O(log n)：每轮至多保留一半候选数。空间复杂度 O(1)：只维护常数个变量。

替代方案

从 1 开始线性调用接口也能找到答案，但最坏需要 n 次调用。随机猜测没有稳定的最坏界；对于有序且提供方向反馈的区间，二分查找更可靠。

四语言完整代码

以下均使用判题环境已经提供的 guess API。

Java · LeetCode 可提交
/**
 * The guess API is defined in the parent class GuessGame.
 * int guess(int num);
 */
public class Solution extends GuessGame {
    public int guessNumber(int n) {
        int left = 1;
        int right = n;

        while (left <= right) {
            int mid = left + (right - left) / 2;
            int result = guess(mid);

            if (result == 0) {
                return mid;
            } else if (result < 0) {
                right = mid - 1;
            } else {
                left = mid + 1;
            }
        }

        return -1; // 题目保证答案存在
    }
}

面试追问

  • 为什么中点要写成 left + (right - left) / 2？
  • 如果接口可能临时失败，怎样设计重试而不破坏复杂度分析？
  • 若没有“更大 / 更小”反馈，只能知道是否相等，最坏需要多少次调用？
  • 闭区间写法与左闭右开写法各自如何更新边界？

常见错误

  • 把接口的 -1 / 1 含义写反。
  • 更新为 right = mid 或 left = mid，导致边界无法继续收缩。
  • 用 (left + right) / 2，在固定宽度整数中产生溢出风险。
  • 自行实现线上提交所需的 guess，与判题器提供的接口冲突。
