设计日志存储系统

Design Log Storage System — 用固定格式的时间戳保存日志，并按指定时间粒度检索闭区间内的日志编号。

先读题目 进入粒度扫描台
01 / PROBLEM

题目是什么

先理解接口，不提前展开题解。

题意转述

设计一个日志系统。每条日志由唯一编号 id 和时间戳 YYYY:MM:DD:HH:mm:ss 组成。系统需要支持写入日志，以及给定开始时间、结束时间和时间粒度后，返回落在该闭区间内的日志编号。

检索时只精确到指定粒度：例如粒度为 Year，则月份到秒不参与区间判定；开始与结束边界均包含在内。

LogSystem()
初始化日志存储系统。
void put(int id, String timestamp)
用给定编号和时间戳存储一条日志。
List<Integer> retrieve(String start, String end, String granularity)
返回指定粒度下位于 [start, end] 的日志编号。

约束与格式

  • 1 ≤ id ≤ 500，日志编号唯一。
  • 年份范围为 2000 到 2017。
  • 月 1–12，日 1–31，时 0–23，分与秒 0–59。
  • 时间字段均为固定宽度并以冒号分隔。
  • put 与 retrieve 的调用总数至多 500。

04 / SOLUTION

独立题解

准备好再揭晓

建议先在扫描台走完两次检索，想一想“粒度”究竟改变了时间戳的哪一部分。

Prefix Window

固定宽度时间戳，就是可比较的前缀

这道题的关键不是复杂的日期运算，而是格式。年、月、日、时、分、秒都定宽且从高位到低位排列，所以同长度前缀的字典序与对应粒度下的时间顺序一致。

核心洞察

为每种粒度记录需要保留的前缀长度：

Year   →  4    Month  →  7    Day    → 10
Hour   → 13    Minute → 16    Second → 19

将日志时间戳、start、end 都截到相同长度。如果 startPrefix ≤ logPrefix ≤ endPrefix，这条日志就命中。

完整过程

  1. put 时保存 (timestamp, id)。
  2. retrieve 根据粒度取得前缀长度 k。
  3. 截取 start 与 end 的前 k 个字符。
  4. 扫描日志并用同样长度的前缀做闭区间判断。
  5. 为了稳定复现示例，将命中项按完整时间戳升序排列，再返回编号。

正确性说明

引理：对任一粒度 G，两个合法时间戳截取到 G 对应的固定长度后，其字典序等于它们在 G 粒度下的时间先后顺序。原因是字段按年到秒排列、每个字段定宽补零，第一次不同的字段正是决定先后的最高有效字段。

充分性：若日志前缀位于 startPrefix 与 endPrefix 之间，则它在粒度 G 下不早于开始边界且不晚于结束边界，应该返回。

必要性：若日志应该返回，那么它在粒度 G 下位于闭区间内。由引理，其前缀必满足同一字典序闭区间判断，因此不会漏掉。

结论：算法返回且仅返回所有满足指定粒度闭区间的日志编号。

边界情况

  • start 与 end 在目标粒度上相同：该整段粒度单位都应包含。
  • 粒度为 Second：比较完整 19 位时间戳。
  • 粒度为 Year：只比较前 4 位，忽略其余字段。
  • 没有日志命中：返回空列表。
  • 日志落在 start 或 end 边界：闭区间要求包含。

复杂度

putO(1)追加到数组
retrieveO(n log n)扫描后稳定排序
spaceO(n)保存 n 条日志

若题目不要求确定的返回顺序，可省略排序，使单次检索为 O(n)。时间戳长度固定，前缀处理视为 O(1)。

import java.util.ArrayList;
import java.util.Collections;
import java.util.Comparator;
import java.util.HashMap;
import java.util.List;
import java.util.Map;

class LogSystem {
    private static class Log {
        String timestamp;
        int id;

        Log(String timestamp, int id) {
            this.timestamp = timestamp;
            this.id = id;
        }
    }

    private final List<Log> logs;
    private final Map<String, Integer> prefixLength;

    public LogSystem() {
        logs = new ArrayList<>();
        prefixLength = new HashMap<>();
        prefixLength.put("Year", 4);
        prefixLength.put("Month", 7);
        prefixLength.put("Day", 10);
        prefixLength.put("Hour", 13);
        prefixLength.put("Minute", 16);
        prefixLength.put("Second", 19);
    }

    public void put(int id, String timestamp) {
        logs.add(new Log(timestamp, id));
    }

    public List<Integer> retrieve(String start, String end, String granularity) {
        int k = prefixLength.get(granularity);
        String left = start.substring(0, k);
        String right = end.substring(0, k);
        List<Log> matches = new ArrayList<>();

        for (Log log : logs) {
            String current = log.timestamp.substring(0, k);
            if (current.compareTo(left) >= 0 && current.compareTo(right) <= 0) {
                matches.add(log);
            }
        }

        Collections.sort(matches, Comparator.comparing(log -> log.timestamp));
        List<Integer> answer = new ArrayList<>();
        for (Log log : matches) {
            answer.add(log.id);
        }
        return answer;
    }
}
var LogSystem = function () {
  this.logs = [];
  this.prefixLength = {
    Year: 4,
    Month: 7,
    Day: 10,
    Hour: 13,
    Minute: 16,
    Second: 19
  };
};

/**
 * @param {number} id
 * @param {string} timestamp
 * @return {void}
 */
LogSystem.prototype.put = function (id, timestamp) {
  this.logs.push({ id: id, timestamp: timestamp });
};

/**
 * @param {string} start
 * @param {string} end
 * @param {string} granularity
 * @return {number[]}
 */
LogSystem.prototype.retrieve = function (start, end, granularity) {
  const k = this.prefixLength[granularity];
  const left = start.slice(0, k);
  const right = end.slice(0, k);

  return this.logs
    .filter((log) => {
      const current = log.timestamp.slice(0, k);
      return current >= left && current <= right;
    })
    .slice()
    .sort((a, b) => {
      if (a.timestamp < b.timestamp) return -1;
      if (a.timestamp > b.timestamp) return 1;
      return 0;
    })
    .map((log) => log.id);
};
from typing import List, Tuple


class LogSystem:
    def __init__(self):
        self.logs: List[Tuple[str, int]] = []
        self.prefix_length = {
            "Year": 4,
            "Month": 7,
            "Day": 10,
            "Hour": 13,
            "Minute": 16,
            "Second": 19,
        }

    def put(self, id: int, timestamp: str) -> None:
        self.logs.append((timestamp, id))

    def retrieve(
        self, start: str, end: str, granularity: str
    ) -> List[int]:
        k = self.prefix_length[granularity]
        left = start[:k]
        right = end[:k]

        matches = [
            (timestamp, id)
            for timestamp, id in self.logs
            if left <= timestamp[:k] <= right
        ]
        matches.sort(key=lambda item: item[0])
        return [id for _, id in matches]

using namespace std;

class LogSystem {
private:
    vector<pair<string, int>> logs;
    unordered_map<string, int> prefixLength;

public:
    LogSystem() {
        prefixLength = {
            {"Year", 4},
            {"Month", 7},
            {"Day", 10},
            {"Hour", 13},
            {"Minute", 16},
            {"Second", 19}
        };
    }

    void put(int id, string timestamp) {
        logs.push_back({timestamp, id});
    }

    vector<int> retrieve(string start, string end, string granularity) {
        int k = prefixLength[granularity];
        string left = start.substr(0, k);
        string right = end.substr(0, k);
        vector<pair<string, int>> matches;

        for (const auto& log : logs) {
            string current = log.first.substr(0, k);
            if (left <= current && current <= right) {
                matches.push_back(log);
            }
        }

        sort(matches.begin(), matches.end());
        vector<int> answer;
        for (const auto& log : matches) {
            answer.push_back(log.second);
        }
        return answer;
    }
};

替代方案

  • 有序映射：按完整时间戳维护 TreeMap / map，再构造该粒度的完整左右边界，可做范围查询；写入更贵，但数据量大时更合适。
  • 转整数：把年月日时分秒转换为单调整数，再按粒度补齐边界。可行但更容易在月份、日期和进位上出错。
  • 直接扫描：本题调用至多 500 次，前缀扫描短小、透明，通常是面试中最稳妥的实现。

常见错误

  • 用完整时间戳比较，却忘记忽略粒度之后的字段。
  • 把 end 当成开区间，漏掉结束粒度内的日志。
  • 前缀长度写错，忽略冒号也占一个字符。
  • 手动做日期加一，制造月底、闰年和进位问题。
  • 时间字段不补零时仍使用字典序；本题成立依赖固定宽度。

面试追问

如果日志数量从 500 增长到一亿，怎么改？

按时间建立 B+ 树或 LSM-tree 索引，查询时把粒度范围扩展为完整的最小/最大时间戳，再做范围扫描；同时考虑分区、冷热分层和分页。

如果时间戳不再固定宽度呢？

先解析为结构化字段或标准时间值，不能继续依赖原字符串字典序。若涉及时区，还要先统一到同一时间基准。

为什么不必真正解析日期是否合法？

题目保证输入时间字段在给定范围内且格式固定。算法只需要维持目标粒度下的顺序关系，前缀已经足够。

如何支持删除与重复时间戳？

用 id 到日志的反向索引支持删除；时间索引的同一键下保存多个 id。删除时同步更新两侧，必要时使用事务或写前日志保证一致性。
