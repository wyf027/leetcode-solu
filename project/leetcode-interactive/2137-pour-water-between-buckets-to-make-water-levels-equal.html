题目任务

整数数组 buckets 表示各桶的初始水量，单位为加仑。一次操作可以从一个桶向另一个桶倒出任意非负实数水量 k，源桶减少 k，目标桶只增加 k × (100 − loss) / 100，余下部分损失。

进行任意次操作（也可以零次），使所有桶的水量相等。返回能够实现的最大共同水量，答案误差在 10⁻⁵ 以内可接受。

参数与返回值

equalizeWater(buckets: integer[], loss: integer)
→ double

约束

  • 1 ≤ buckets.length ≤ 10⁵
  • 0 ≤ buckets[i] ≤ 10⁵
  • 0 ≤ loss ≤ 99；loss 是损失百分比。

本地官方元数据提供题名、签名与示例输入，题面字段为空。规则、输出和约束参考公开题目资料独立转述；LeetCode 官方页面需要订阅查看。

从目标水位，倒推是否够用

核心洞察

设保留比例 q = (100 − loss) / 100。给定候选水位 x，高桶提供富余水，低桶需要补水。所有富余量扣除损耗后，能否覆盖全部缺口？

S(x) = Σ max(b − x, 0)
D(x) = Σ max(x − b, 0)
F(x) = q × S(x) − D(x)

当 F(x) ≥ 0，能够使每个桶至少达到 x；否则水量不够。注意，判定并非“能恰好停在任意较低水位”：loss = 0 时总量守恒，最终共同水量只能是平均值。

完整过程

  1. 初始化区间 [0, max(buckets)]。水量非负，转移不会增加总量，最优值必在其中。
  2. 取中点 mid；遍历每桶，累计有效供给 qS(mid) 与缺口 D(mid)。
  3. 供给足够，令 lo = mid；否则令 hi = mid。每轮都读取原始 buckets。
  4. 执行 60 轮后返回 lo，作为最优水位的近似下界。

以 [2,4,6]、loss = 50 为例：x = 3 时供给 2，缺口 1，可以抬高下界；x = 4.5 时供给 0.75，缺口 3，需要压低上界。x = 3.5 时供给 (0.5 + 2.5) × 0.5 = 1.5，恰好等于缺口。

正确性证明

  1. 判定有依据。把低桶补到 x 需要接收到 D(x)，高桶在不低于 x 的前提下可倒出 S(x)。每单位源水直接转移最多留下 q；中转只会再损耗。若 qS ≥ D，逐个将高桶富余水分配到缺口即可使所有桶至少达到 x；反之无法达到。
  2. 存在唯一平衡点。F 连续且分段线性。分组固定时其斜率为 −q × 高桶数 − 低桶数；q > 0，桶数至少为 1，所以严格递减。F(0) ≥ 0、F(max) ≤ 0，因此有唯一零点 x*。
  3. 零点可实现且最优。在 x* 处 qS = D，直接分配全部富余水即可恰好补齐所有缺口，让每桶都停在 x*。任何更高目标供给不足；绕路、先倒空再补回都不会创造有效水量。
  4. 二分保持答案。始终维持 lo ≤ x* ≤ hi；按 F(mid) 的符号保留包含零点的一半。区间不断收缩，返回 lo 即逼近最大共同水位。

边界与精度

  • 单桶或所有桶相等，无需操作；全零时搜索区间退化为 [0,0]。
  • loss = 0 时零点就是平均值；loss = 99 时 q = 0.01，仍适用。约束不含 loss = 100。
  • 总水量最高可达 10¹⁰，不能用 32 位整数累计。四语言实现均使用双精度浮点累计供需。
  • 理想实数下 60 轮后区间宽度不超过 10⁵ / 2⁶⁰；实际还受浮点舍入影响。固定次数避免中点舍入后循环停滞，不在每轮四舍五入。
  • 返回数值，不返回 toFixed 等方法产生的字符串；界面显示的小数位仅用于阅读。

复杂度

时间 O(60n)，固定轮数下为 O(n)；若按目标精度 ε 表述，则是 O(n log(M/ε))，M 为最大初始水量。额外空间 O(1)。可视化保存轮次以支持回退，其空间开销不属于提交代码。

替代方案

排序后枚举低桶与高桶的分割点，用前缀和解线性方程。若低桶有 k 个、总和 P，高桶有 n−k 个、总和 H，则 x = (P + qH) / (k + q(n−k))。只接受落在该分组相邻水量之间的 x。时间 O(n log n)，需要处理重复值与分割边界；二分无需排序。

常见错误

  • 直接用平均值，忽略损耗；或将 loss / 100 当作保留比例。
  • 在 Java / C++ 中使用整数除法，导致 q 变成 0。
  • 把接收缺口再乘 q；应让缺口与扣除损耗后的有效供给比较。
  • 检查候选值时修改 buckets，污染后续轮次。
  • 使用整数二分的 mid ± 1，或等待浮点值严格相等才退出。
  • JavaScript 对大数组使用 Math.max(...buckets)，可能超出参数数量限制；循环取最大值更稳妥。

面试追问

  • 能收紧初始区间吗？可以用 [min(buckets), 平均值]，最低水位是下界，平均值是总量上界。
  • 如何输出倒水步骤？得到 x* 后维护富余桶与缺水桶两组，每次倒出 min(富余量, 缺口/q)，直到某组中的当前桶处理完；用容差消除尾差。
  • 损耗因桶而异呢？若只依赖源桶，可按源桶自己的比例累计供给；若取决于源和目标组合，则涉及路由，不能直接沿用统一 q。

四语言完整实现

使用官方方法名 equalizeWater 与参数 buckets、loss；以下为独立编写的提交形式，均未运行或提交验证。

Java

class Solution {
    public double equalizeWater(int[] buckets, int loss) {
        double lo = 0, hi = 0, keep = (100 - loss) / 100.0;
        for (int b : buckets) hi = Math.max(hi, b);
        for (int step = 0; step < 60; step++) {
            double mid = (lo + hi) / 2;
            double supply = 0, need = 0;
            for (int b : buckets) {
                if (b > mid) supply += (b - mid) * keep;
                else need += mid - b;
            }
            if (supply >= need) lo = mid;
            else hi = mid;
        }
        return lo;
    }
}
