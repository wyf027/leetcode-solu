Count Subarrays With Score Less Than K

一段连续数字，有多“重”？用元素和 × 长度定义得分，数出所有得分严格低于阈值的非空片段。

正整数数组严格小于 k连续且非空官方题目 ↗

01 / 题意与约束

给定正整数数组 nums 和整数 k，返回得分严格小于 k 的非空连续子数组数量。

score = sum(subarray) × length(subarray) < k

不同起止位置视为不同子数组，即使内容完全相同。返回数量，而不是子数组列表。例如 [1,2,3,4,5] 的得分为 15 × 5 = 75。

  • 1 ≤ nums.length ≤ 10⁵
  • 1 ≤ nums[i] ≤ 10⁵
  • 1 ≤ k ≤ 10¹⁵

02 / 官方示例

示例 1

输入：nums = [2,1,4,3,5], k = 10
输出：6

五个单元素子数组得分依次为 2、1、4、3、5；[2,1] 的得分为 6，共 6 个。[1,4] 的得分恰为 10，不合法；[4,3,5] 的得分为 36，也不合法。

示例 2

输入：nums = [1,1,1], k = 5
输出：5

三个长度为 1 的片段与两个长度为 2 的片段合法；完整数组得分为 9，不计入。

04 / 题解工作台

核心洞察 · 逐帧推演 · 四语言实现

核心洞察：固定右端点，找最左合法起点

因为数字全为正数，向右扩张时元素和、长度都增加，得分严格增加；从左端删除元素时，两者都减小，得分严格减少。利用这个单调性，两个端点都只需要向右移动。

维护窗口 [left,right] 与元素和 sum。加入右端点后，只要得分 ≥ k，就持续移除左端点。窗口合法后，它的所有非空后缀也合法，因此本轮增加 right-left+1 个答案。

完整过程与正确性

  1. 初始化 left、sum、answer 均为 0。
  2. 枚举 right，把 nums[right] 加入 sum。
  3. 只要 sum × (right-left+1) ≥ k，就从 sum 减去 nums[left]，再递增 left。
  4. 把 right-left+1 加入答案；空窗口的贡献为 0。
  5. 推进 right，最后返回累计数量。

为什么不漏、不重？

窗口不变式：每轮收缩后，sum 是窗口元素和，窗口为空或得分小于 k，且 left 左侧的起点均不合法。此前被排除的起点，随着右端点扩张得分只会变大，不会重新合法；本轮移除的起点也都在得分不合法时才被排除。

完整性：合法窗口的每个非空后缀都有更小或相等的和与长度，因此也合法。左侧起点均已排除，所以本轮恰有 right-left+1 个合法子数组。

唯一性：每个子数组只有一个右端点，只会在相应轮次计数一次。遍历全部 right，便覆盖所有合法子数组。

复杂度

时间 O(n)：right 移动 n 次，left 总共最多移动 n 次。虽然有嵌套 while，总工作量仍是线性的。提交代码额外空间 O(1)。动画保存推演帧、列出后缀，限 20 项演示，不计入提交算法的空间复杂度。

四语言完整实现

Java

class Solution {
    public long countSubarrays(int[] nums, long k) {
        long sum = 0, answer = 0;
        int left = 0;
        for (int right = 0; right < nums.length; right++) {
            sum += nums[right];
            while (sum * (right - left + 1) >= k) {
                sum -= nums[left++];
            }
            answer += right - left + 1;
        }
        return answer;
    }
}

from typing import List

class Solution:
    def countSubarrays(self, nums: List[int], k: int) -> int:
        left = total = answer = 0
        for right, value in enumerate(nums):
            total += value
            while total * (right - left + 1) >= k:
                total -= nums[left]
                left += 1
            answer += right - left + 1
        return answer

class Solution {
public:
    long long countSubarrays(vector<int>& nums, long long k) {
        long long sum = 0, answer = 0;
        int left = 0;
        for (int right = 0; right < static_cast<int>(nums.size()); ++right) {
            sum += nums[right];
            while (sum * (right - left + 1) >= k) {
                sum -= nums[left++];
            }
            answer += right - left + 1;
        }
        return answer;
    }
};

边界与常见错误

  • 严格小于：得分等于 k 时也要收缩，判断必须用 ≥。
  • 连续收缩：移除一个元素后可能仍不合法，用 while，不能用 if。
  • 空窗口：单元素 ≥ k 时，left 会前进至 right+1，sum 和长度均为 0。因为 k ≥ 1，循环自然结束，不会继续越界。
  • 计数单位：每轮加窗口长度，不是加 1，也不是重新统计整个窗口的所有内部子数组。
  • 整数范围：sum 最大 10¹⁰，score 最大 10¹⁵，答案最大 5,000,050,000。Java 用 long，C++ 用 long long，并确保乘法操作数已是 64 位。
  • JavaScript：所有整数中间值至多 10¹⁵，小于 2⁵³−1，因此 Number 在官方约束下足够精确；扩大范围后再考虑 BigInt。
  • 连续性：不能先排序，否则会改变原数组中的子数组。

替代方案

前缀和 + 二分：利用前缀和 O(1) 求区间和。固定 right，随着起点右移得分减少，可二分第一个合法起点。时间 O(n log n)，空间 O(n)。双指针可复用上一轮边界，因此更简洁。

暴力枚举：枚举起点并逐渐延长终点，维护区间和；遇到不合法时可停止继续延长。最坏时间 O(n²)、额外空间 O(1)，仅适合小规模参考。

面试追问

  • 允许 0 呢？得分不再严格变化，但仍保持单调不减或不增，k ≥ 1 时同一方法仍成立。
  • 允许负数呢？单调性失效。例如 [10,-10] 整段得分为 0，虽然首元素可能不合法。需要重新分析，不能直接沿用窗口。
  • 统计得分恰为 k？整数得分下，可用 countLess(k+1) − countLess(k)，同时检查阈值加一与乘法的类型范围。
  • 数据流怎么办？右端点可以在线推进，但收缩时必须知道被移除元素；若不能随机访问原数组，需要队列保存窗口，额外空间可能达到 O(n)。
