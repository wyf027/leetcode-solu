Solution

Full solution

摩尔投票：让不同编号成对抵消

Boyer–Moore Majority Vote

核心洞察

超过半数的编号比所有其他编号加起来还多。每次删除一对不同编号，真正的多数编号依然不会失去多数地位，因此它最终一定会留下。

相同：votes + 1　不同：votes - 1　归零：更换 candidate

完整过程

  1. 准备候选值 candidate 与净票数 votes。
  2. votes == 0 时，让当前值成为新的候选值。
  3. 当前值与候选相同就加一，否则减一。
  4. 遍历结束后返回候选值；本题保证答案存在。

边界与正确性

  • 单元素数组在第一步建立候选并直接保留。
  • 编号可以是 0 或负数，不能把 0 当作“未设置”的特殊值。
  • 如果题目不保证答案存在，需要第二次遍历验证候选出现次数。
  • 配对删除不同值不会消灭原来的绝对多数，最终候选必是答案。

复杂度

  • 时间复杂度：O(n)，只扫描一次数组。
  • 额外空间复杂度：O(1)，只保存候选值和净票数。

真正的替代方案

  • 哈希计数：O(n) 时间、O(n) 空间，直观且能保留全部频次。
  • 排序取中位数：O(n log n) 时间，通常会修改输入数组。
  • Quickselect：期望 O(n)，但实现更复杂且会改变元素顺序。

面试追问

  • 如果不保证多数元素存在，怎样验证并表示“不存在”？
  • 阈值改为三分之一时，为什么最多保留两个候选？
  • 分片数据如何合并候选值与净票数？

常见错误

  • 把“出现次数最多”误当成“严格超过一半”。
  • 净票数归零后没有在下一项重新建立候选，造成漏计。
  • 在无多数元素的变体中省略第二次计数验证。
  • 使用排序方案却没有说明它会修改原数组。
class Solution {
    public int inventoryManagement(int[] stock) {
        int candidate = 0;
        int votes = 0;

        for (int value : stock) {
            if (votes == 0) {
                candidate = value;
            }
            votes += value == candidate ? 1 : -1;
        }
        return candidate;
    }
}
