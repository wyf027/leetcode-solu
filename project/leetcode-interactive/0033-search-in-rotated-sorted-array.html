数组虽然被旋转，但每次切一刀，至少有一半仍然升序。先确认哪边有序，再判断目标是否落在它的值域里。

Mission brief

题意转述

一个严格递增、元素互不相同的整数数组，在未知位置旋转后得到 nums。请在 O(log n) 时间内寻找 target，找到返回下标，否则返回 -1。

Radar rule

不要先找断点

每轮直接用 nums[left] ≤ nums[mid] 判断左半边是否有序，继续保持一次二分。

    Core insight

    每轮至少一半有序

    元素互不相同，所以 nums[left] ≤ nums[mid] 能明确判定左半边升序；否则右半边必然升序。检查目标是否落入该有序值域，就能安全丢弃另一半。

    Decision

    先认路，再选边

    不要直接比较 target 和 nums[mid] 后机械左右移动；旋转会破坏全局单调性。

    完整解题过程

    1. 1. 计算 mid

      mid = left + (right-left)/2，先检查是否命中。

    2. 2. 识别有序半边

      比较 nums[left] 和 nums[mid]。

    3. 3. 收缩区间

      目标落在有序值域则保留它，否则保留另一边。

    边界情况

    • 单元素命中或缺失。
    • 数组没有旋转。
    • 目标在旋转点两侧或不存在。
    • 循环条件必须是 left ≤ right。

    复杂度

    时间 O(log n)：每轮区间减半。
    空间 O(1)：只维护三个下标。

    替代方案

    先二分找旋转点、再普通二分同样 O(log n)，但代码分两段；线性搜索更直观却不满足题目要求。

    面试高频追问

    为什么元素唯一很重要？
    有重复值时 nums[left] == nums[mid] 可能无法判断有序侧，最坏会退化到 O(n)。
    为什么左侧用闭区间？
    判断条件必须与更新式 mid ± 1 保持一致。

    常见错误

    • ❌ 只比较目标与中点，忽略旋转。
    • ❌ 有序值域边界写成双闭，重复保留 mid。
    • ❌ 循环使用 left < right，漏查最后一个元素。
    • ❌ 把题 81 的重复元素逻辑直接套进来。

    class Solution {
    public int search(int[] nums, int target) {
        int left = 0;
        int right = nums.length - 1;
        while (left <= right) {
            int mid = left + (right - left) / 2;
            if (nums[mid] == target) return mid;
            if (nums[left] <= nums[mid]) {
                if (nums[left] <= target && target < nums[mid]) right = mid - 1;
                else left = mid + 1;
            } else {
                if (nums[mid] < target && target <= nums[right]) left = mid + 1;
                else right = mid - 1;
            }
        }
        return -1;
    }
}
