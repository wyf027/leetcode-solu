2187. 完成旅途的最少时间

Minimum Time to Complete Trips

同一时刻出发，各自重复旅途。车队什么时候才能完成目标？

先阅读题目并独立思考。算法、交互演示与四语言代码位于底部，默认收起。

01 / 题目

给定整数数组 time，time[i] 表示第 i 辆公交车完成一趟旅途所需的时间。所有公交车从时刻 0 开始独立运行，可以同时行驶；每完成一趟，便立即开始下一趟。

给定整数 totalTrips，求整个车队累计完成至少 totalTrips 趟旅途所需的最少时间。正在进行而尚未结束的一趟不计入完成数。

官方示例 1

输入：time = [1,2,3], totalTrips = 5
输出：3

时刻 1：分别完成 [1,0,0] 趟，总计 1。
时刻 2：分别完成 [2,1,0] 趟，总计 3。
时刻 3：分别完成 [3,1,1] 趟，总计 5。最少需要 3 单位时间。

官方示例 2

输入：time = [2], totalTrips = 1
输出：2

唯一一辆车在时刻 2 完成第一趟，故最少需要 2 单位时间。

约束与接口

  • 1 ≤ time.length ≤ 10⁵
  • 1 ≤ time[i], totalTrips ≤ 10⁷
  • 参数：time: integer[]、totalTrips: integer；返回最少时间（长整数语义）。

03 / 题解工作台

准备好后，展开推导、公交车队演示和代码。

核心洞察：把“求时间”换成“检查时间”

固定一个整数时刻 T，第 i 辆车完成 ⌊T / time[i]⌋ 趟。因此 F(T) = Σ⌊T / time[i]⌋。时间增加时，每一项都不会减少，条件 F(T) ≥ totalTrips 便具有“先不满足、后满足”的单调性。

我们对答案时间二分，找第一个可行时刻，而不是逐趟模拟。最快的车单独完成所有任务只需 min(time) × totalTrips，这是可靠的可行上界。

车队计数器 × 时间区间折半

每一步选一个候选时刻：查看各车完成趟数，再观察下一步保留的区间。进度条表示当前未完成旅途的进度。教学面板支持 1–12 辆车，单趟时间及目标均为 1–10⁷；提交代码支持完整题目规模。

完整过程

  1. 扫描数组，获得最快单趟用时 m；初始化闭区间 [L,R] = [1,m × totalTrips]。
  2. 当 L < R，取 mid = L + ⌊(R−L)/2⌋。
  3. 遍历公交车，累加 ⌊mid / time[i]⌋。一旦达到目标，就提前结束计数。
  4. 若趟数足够，令 R = mid，保留这个可能最早的可行时间；否则令 L = mid + 1。
  5. 当 L 与 R 相遇，返回 L。

示例 1：区间 [1,5] → mid=3，完成 5 趟，保留 [1,3] → mid=2，完成 3 趟，保留 [3,3] → 答案 3。

正确性说明

令最优答案为 A。初始时 A ≥ 1，最快的车在 R 时刻已完成目标，因此 A ∈ [L,R]。假设某轮开始前 A 在区间内：若 F(mid) 足够，mid 可行，所以 A ≤ mid，更新 R 不丢失 A；否则所有不大于 mid 的时间都不可行，所以 A ≥ mid+1，更新 L 仍保留 A。每轮区间严格缩短；最终 L=R，区间内唯一的整数必为 A。

边界与数值范围

  • 数组无需排序；相同用时的车也要分别计数，不能去重。
  • 目标为 1 时答案是最快单趟用时；只有一辆车时答案是其用时乘目标。
  • 完成数可能跳过目标，判断应使用 ≥，而不是等于。
  • 上界最多 10¹⁴，Java 用 long，C++ 用 long long，乘法前提升类型；Python 整数自动扩展。
  • JavaScript 的 Number 可精确表示这里的时间整数。达到目标就停止计数，使累计值不超过 10¹⁴ + 10⁷，避免全量求和可能超过安全整数范围。不要用位运算求中点，也不要对 10⁵ 个元素使用 Math.min(...time)。

复杂度与替代方案

设 n 为车数，U = min(time) × totalTrips。时间复杂度 O(n log(U+1))，额外空间 O(1)；最多约 47 轮二分。可用最小堆按下一次完成时刻模拟，耗时 O(n + totalTrips log n)、空间 O(n)，但目标可达 10⁷ 时逐趟处理昂贵。逐单位时间扫描依赖答案大小，同样不适合 10¹⁴ 的上界。

四语言完整提交代码

以下代码采用官方 minimumTime 参数形式；均未运行验证。

Java

class Solution {
    public long minimumTime(int[] time, int totalTrips) {
        int fastest = time[0];
        for (int t : time) fastest = Math.min(fastest, t);
        long left = 1, right = (long) fastest * totalTrips;
        while (left < right) {
            long mid = left + (right - left) / 2;
            long trips = 0;
            for (int t : time) {
                trips += mid / t;
                if (trips >= totalTrips) break;
            }
            if (trips >= totalTrips) right = mid;
            else left = mid + 1;
        }
        return left;
    }
}

var minimumTime = function(time, totalTrips) {
    let fastest = time[0];
    for (const t of time) fastest = Math.min(fastest, t);
    let left = 1, right = fastest * totalTrips;
    while (left < right) {
        const mid = left + Math.floor((right - left) / 2);
        let trips = 0;
        for (const t of time) {
            trips += Math.floor(mid / t);
            if (trips >= totalTrips) break;
        }
        if (trips >= totalTrips) right = mid;
        else left = mid + 1;
    }
    return left;
};

常见错误

  • 将每辆车时间相加，误把并行旅途看作串行。
  • 用向上取整，将正在进行的旅途算作完成。
  • 可行时令 R=mid−1，却依旧使用本页 L<R 的闭区间模板，可能丢失答案。
  • 不可行时令 L=mid，可能在相邻整数区间中停滞。
  • 整型乘法已经溢出后才赋给 long；或使用 JavaScript >> 导致 32 位截断。

面试追问

各车有不同出发延迟怎么办？ 完成数改为 max(0, ⌊(T−start[i])/time[i]⌋)，仍然单调；上界可取任意一辆车的出发时刻加上它独自完成目标的时间。

无法直接确定上界怎么办？ 从 1 开始倍增，直到判定可行，再进行二分，注意数值范围。

如何确认找到的是最早时刻？ 答案 A 应满足 F(A) ≥ 目标且 F(A−1) < 目标，这是后续验证可用的边界性质。
