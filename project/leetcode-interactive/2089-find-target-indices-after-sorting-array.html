2089 / 找出数组排序后的目标下标

Find Target Indices After Sorting Array

排序会改变位置。请找出目标值在排序完成后的所有下标，注意它们与原数组中的位置并不相同。

01题目

给定从下标 0 开始的整数数组 nums 和整数 target。将数组按非递减顺序排列后，返回所有值等于 target 的元素下标。返回的下标必须严格递增；目标值不存在时返回空列表。

参数：nums: integer[]、target: integer
返回：list<integer>，内容为排序后的位置。

约束

  • 1 ≤ nums.length ≤ 100
  • 1 ≤ nums[i], target ≤ 100

官方示例

输入：nums = [1,2,5,2,3], target = 2
输出：[1,2]

示例 3
输入：nums = [1,2,5,2,3], target = 5
输出：[4]

排序后为 [1,2,2,3,5]，目标值位于下标 4。

输入：nums = [1,2,5,2,3], target = 4

03独立题解

先尝试写下自己的思路，再展开交互推演、证明与参考代码。

用两个计数定位整个目标区间

核心洞察

无需真正排序。设 less 是小于 target 的元素个数，equal 是等于 target 的元素个数。排序后先放所有较小值，再放所有目标值，因此目标下标恰为半开区间 [less, less + equal) 内的整数。

交互推演 · 三个分区，一条下标带

每步读取一个原数组元素，按与 target 的关系归类；最后将计数映射到排序后的下标。分区内保持扫描顺序，仅表示分类，不表示完成排序。

1–100 个元素，每个元素及 target 均为 1–100 的整数。修改后点击“应用输入”。

完整过程

  1. 初始化 less = 0、equal = 0。
  2. 遍历 nums。元素小于 target 时增加 less；等于 target 时增加 equal；大于 target 时跳过。
  3. 从 less 开始，依次加入 equal 个下标。
  4. 返回列表。示例 1 得到 less = 1、equal = 2，所以返回 [1,2]。

正确性

扫描不变式：处理前 k 个元素后，less 与 equal 分别准确记录这 k 个元素中小于和等于 target 的数量。初始为空，计数均为 0；每步仅更新当前元素所属的计数，因此不变式始终成立。

扫描完成后，任何非递减排列都必须将全部 less 个较小值置于目标值之前，将全部较大值置于目标值之后。相等值连续占据 equal 个位置，首个位置为 less，最后一个为 less + equal − 1。枚举这个区间不会遗漏或加入其他元素，且天然递增。equal = 0 时区间为空，正好返回空列表。

边界

  • 目标缺失：equal = 0，循环不执行；less 可以是 0、中间值或 n。
  • 全部元素都是目标：less = 0，返回 0 到 n − 1。
  • 只有一个元素：相等返回 [0]，否则返回 []。
  • 目标是最小值：区间从 0 开始；目标是最大值：区间结束于 n。

复杂度

设 n 为数组长度、k 为目标出现次数。扫描 O(n)，生成答案 O(k)，总时间 O(n + k) = O(n)。除返回列表外额外空间 O(1)，返回列表占 O(k)。不修改输入数组。

四语言完整提交代码

Java

import java.util.ArrayList;
import java.util.List;

class Solution {
    public List<Integer> targetIndices(int[] nums, int target) {
        int less = 0, equal = 0;
        for (int x : nums) {
            if (x < target) less++;
            else if (x == target) equal++;
        }
        List<Integer> answer = new ArrayList<>();
        for (int i = less; i < less + equal; i++) {
            answer.add(i);
        }
        return answer;
    }
}

from typing import List

class Solution:
    def targetIndices(self, nums: List[int], target: int) -> List[int]:
        less = 0
        equal = 0
        for x in nums:
            if x < target:
                less += 1
            elif x == target:
                equal += 1
        return list(range(less, less + equal))

替代方案

  • 排序后扫描：先数值排序，再收集相等值的下标。通常时间 O(n log n + k)，排序额外空间依语言实现而定；复制数组会额外占用 O(n)。实现直观，但本题仅问位置，不需要获得完整排序结果。
  • 排序后二分：分别找第一个 ≥ target 和第一个 > target 的位置，返回两者之间的下标。若输入尚未排序，总成本仍由排序主导；已有排序数组时单次查询 O(log n + k)。
  • 值域频次：针对 1–100 维护频次数组，多次查询可复用前缀和；单次查询没有必要引入这份结构。

面试追问

  • 是否需要稳定排序？不需要。我们只关心值对应的区间，不关心相等元素原来的身份。
  • target 要查询很多次？可先排序再二分，或利用小值域统计频次与前缀和；输出 k 项本身仍需要 O(k) 时间。
  • 若要求返回原数组中的下标？直接遍历并收集匹配位置，不能使用本题的排序后区间。
  • 能否一边读数据一边统计？可以，只保留两个计数；数据流结束后再生成答案。

常见错误

  • 返回目标值在原数组中的位置，混淆“排序后”要求。
  • 把首个下标写成 less + 1，忘记下标从 0 开始。
  • 枚举到 less + equal（包含上界），多返回一个位置。
  • 只返回第一个匹配位置，遗漏重复目标。
  • JavaScript 使用默认 sort() 做数值排序；排序方案应传入 (a, b) => a - b。
  • 将含返回结果的空间复杂度写成 O(1)；答案列表需要 O(k)。
