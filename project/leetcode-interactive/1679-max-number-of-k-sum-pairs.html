K 和数对的最大数目

从数组中不断移除和为 k 的两个数。目标不是找出某一对，而是让互不复用元素的有效配对尽可能多。

Problem

题目说明

给你一个整数数组 nums 和一个整数 k。每次操作选择数组中两个和恰好为 k 的整数并移除；返回最多可以执行多少次操作。

示例 1

输入：nums = [1,2,3,4], k = 5
输出：2
解释：先移除 1 和 4，再移除 2 和 3；一共 2 次。

示例 2

输入：nums = [3,1,3,4,3], k = 6
输出：1
解释：移除两个 3 后，剩余 [1,4,3]，无法继续配对。

参数与约束

maxOperations(nums, k)

  • nums：整数数组
  • k：目标和，整数
  • 1 ≤ nums.length ≤ 10⁵
  • 1 ≤ nums[i] ≤ 10⁹
  • 1 ≤ k ≤ 10⁹

同一元素一旦被移除，就不能在后续操作中再次使用。

准备好看题解了吗？

先自己想一想：当当前数字的补数尚未出现时，究竟需要保存什么信息？展开后可查看证明、复杂度、四语言实现与面试追问。

Explanation

题解：哈希计数，遇见补数就配对

一次扫描足够。哈希表记录已经出现、但还没有组成数对的数字及其剩余个数。

核心洞察

扫描到 x 时，唯一能与它组成目标和的值是 k - x。若仓库中有这个补数，就立即消耗一个补数并增加答案；否则把 x 存入仓库，等待未来元素。

完整过程

  1. 初始化空哈希表 waiting 与答案 operations = 0。
  2. 依次读取每个数字 x，计算补数 need = k - x。
  3. 若 waiting[need] > 0，消耗一个补数并令答案加一。
  4. 否则令 waiting[x] 加一，让当前数字等待后续配对。
  5. 扫描结束后返回 operations。

为什么正确

  • 不重复使用：每次成功配对都会从计数中消耗一个补数；当前元素也不再入库，所以每个元素最多使用一次。
  • 不会错过机会：值为 x 的元素只能和 k-x 配对。已有补数时立即配对，不会影响其他类型的配对选择。
  • 达到最大值：对每一种互补值组合，算法尽可能匹配两侧的元素；对于 x = k-x，它每遇到第二个相同值就完成一对。因此所有可组成的互不相交数对都会被计入。
平均时间复杂度O(n)每个元素执行常数次哈希操作
空间复杂度O(n)最坏情况下所有元素都在等待

边界情况

  • 数组长度不足 2 时，答案为 0。
  • 所有数字都无法互补时，答案为 0。
  • 当 k 为偶数且 x = k / 2，两个相同值才能组成一对。
  • 重复值很多时，计数必须逐个增加和消耗。
  • 语言实现应使用足以容纳 k - x 的整数类型；本题范围在常见 32 位有符号整数内。

替代方案：排序 + 双指针

先排序，再用左右指针比较两数之和：等于 k 时同时收缩；小于 k 时左指针右移；大于 k 时右指针左移。

时间 O(n log n)，额外空间取决于排序实现。它便于解释指针移动，但会改变数组顺序；哈希法通常更快且无需排序。

四语言完整代码

import java.util.HashMap;
import java.util.Map;

class Solution {
    public int maxOperations(int[] nums, int k) {
        Map<Integer, Integer> waiting = new HashMap<>();
        int operations = 0;

        for (int x : nums) {
            int need = k - x;
            int available = waiting.getOrDefault(need, 0);

            if (available > 0) {
                operations++;
                if (available == 1) {
                    waiting.remove(need);
                } else {
                    waiting.put(need, available - 1);
                }
            } else {
                waiting.put(x, waiting.getOrDefault(x, 0) + 1);
            }
        }

        return operations;
    }
}

var maxOperations = function(nums, k) {
    const waiting = new Map();
    let operations = 0;

    for (const x of nums) {
        const need = k - x;
        const available = waiting.get(need) || 0;

        if (available > 0) {
            operations++;
            if (available === 1) {
                waiting.delete(need);
            } else {
                waiting.set(need, available - 1);
            }
        } else {
            waiting.set(x, (waiting.get(x) || 0) + 1);
        }
    }

    return operations;

class Solution {
public:
    int maxOperations(vector<int>& nums, int k) {
        unordered_map<int, int> waiting;
        int operations = 0;

        for (int x : nums) {
            int need = k - x;
            auto it = waiting.find(need);

            if (it != waiting.end() && it->second > 0) {
                ++operations;
                if (--it->second == 0) {
                    waiting.erase(it);
                }
            } else {
                ++waiting[x];
            }
        }

        return operations;
    }
};

常见错误

  • 只用集合记录出现过的值，丢失重复元素的数量。
  • 成功配对后忘记减少补数计数，导致同一元素被复用。
  • 先把当前数入库再找补数；当 2x = k 时可能错误地让元素和自己配对。
  • 统计所有满足条件的下标组合，而不是互不相交的数对。
  • 排序解法中，配对成功后只移动一侧指针。

面试追问

  • 如果不允许额外 O(n) 空间，你会怎样改写？
  • 如果数据以流的形式到达，哈希法能否在线返回当前答案？
  • 若需要输出具体下标对，哈希表中应保存什么？
  • 如果数组已排序，如何把空间降到 O(1)？
  • 为什么“有补数就立即配对”不会损失最优解？

Quick review

收尾复盘

一句话记忆法

当前数字有补数就结对，没有补数就登记等待；登记的是数量，而不只是“见过”。

哈希法和双指针如何选择？

追求平均 O(n) 时间且允许额外空间时选哈希；数组已排序或额外空间受限时选双指针。

最关键的不变量是什么？

哈希表里只保存已扫描但仍未配对的元素；答案只统计已经消耗两个不同数组元素的数对。
