2509. 查询树中环的长度

Cycle Length Queries in a Tree

一棵按编号生长的二叉树，一条临时加入的边。

01 / 题目与输入输出

给定整数 n，树有 2ⁿ − 1 个节点，共 n 层且每层填满，根编号为 1。编号 val 在 [1, 2ⁿ⁻¹ − 1] 内的节点，其左、右孩子分别编号为 2 × val 和 2 × val + 1。

另给长度为 m 的二维数组 queries，每项为 [aᵢ, bᵢ]。对每项查询，临时在这两个节点间加一条边，求产生的环的长度，然后移除这条新边。按查询顺序返回整数数组 answer。

环从某节点出发回到该节点，每条边只经过一次，长度按边数计算。允许两节点间存在平行边：如果它们原本相邻，新边与旧边也能组成长度为 2 的环。查询互不影响。

约束

  • 2 ≤ n ≤ 30
  • m == queries.length，1 ≤ m ≤ 10⁵
  • queries[i].length == 2
  • 1 ≤ aᵢ, bᵢ ≤ 2ⁿ − 1
  • aᵢ ≠ bᵢ

02 / 官方示例

示例 1

输入：n = 3, queries = [[5,3],[4,7],[2,3]]
输出：[4,5,3]

三次加边分别形成 5 → 2 → 1 → 3 → 5、4 → 2 → 1 → 3 → 7 → 4、2 → 1 → 3 → 2，环长为 4、5、3。每次计算后都删除新边。

示例 2

输入：n = 2, queries = [[1,2]]
输出：[2]

节点 1 与 2 原本有一条边，新增另一条边后形成 1 → 2 → 1 的环。往返使用的是不同的两条边。

题解 / 沿编号回到共同祖先

核心洞察

树上两点之间恰有一条简单路径。新增边把这条路径闭合，因此 环长 = 原树距离 + 1。不必建树：节点 x 的父节点就是 ⌊x / 2⌋。

维护两个编号 a, b。只要它们不同，就把较大的编号换成父编号，并把计数加 1；相遇时停止。计数初始为 1，预先计入新边。

为什么可以直接比较编号？

深度为 d 的节点编号区间为 [2ᵈ, 2ᵈ⁺¹ − 1]。较大的编号深度不会更浅；若深度相同、两点不同，那么较大节点也不可能是另一节点的祖先。所以上移较大者不会越过最近公共祖先（LCA）。不需要显式计算深度。

编号回溯实验室

n = 3 · 7 个节点

编辑两个不同节点（1–7），观察编号如何沿父边收缩。青色边为已走过的树边；虚线是最初添加的新边；圆环标出当前 A、B。二进制编号每次上移去掉末位。

完整过程


  1. 为每个查询复制端点到局部变量，令 length = 1。
  2. 当 a ≠ b，若 a > b，令 a = ⌊a/2⌋；否则令 b = ⌊b/2⌋。
  3. 本轮正好走过一条树边，因此 length++。
  4. 两指针相遇，已经走完从两端到 LCA 的路径，记录长度。下一次查询重新开始。


例：[5,3]，length 初始为 1
(5,3) → (2,3)，length = 2
(2,3) → (2,1)，length = 3
(2,1) → (1,1)，length = 4
相遇于 1，返回 4。


正确性证明


不变量：设原始两端点的最近公共祖先为 L。循环中的两个指针始终在各自端点至 L 的路径上；计数等于 1 加上已走过的树边数。初始时显然成立。


保持：两指针不同，较大的那个不可能已经是 L：L 的编号小于所有真后代。如果一个指针为 L，另一个真后代才是较大者。因而上移较大者沿着通往 L 的路径前进一步，不会越过 L，并准确增加一条边。


终止与结论：每一步使深度总和减 1，最终相遇于 L；两条路径在 L 之前没有公共节点，所以没有重复计数。累积的是原始两点的唯一树路径长度，再加 1 条新边，正是所求环长。


边界与复杂度


  • 相邻节点：一次上移即相遇，答案为 2，平行边必须分别计算。
  • 祖先与后代：只需后代逐步上移；根不应被移到 0。
  • 相同端点不属于合法输入。交互页面拒绝该输入。
  • 最多各上移 n − 1 次，答案最多 2n − 1 ≤ 59。
  • 每次查询时间 O(n)，总时间 O(mn)（也可写为 O(m log V)，V 为最大节点编号）。辅助空间 O(1)，返回数组占 O(m)。
  • n 仅界定编号范围与树高，核心计算无需用到它。最多约十亿个节点，不能真的创建整棵树。


替代方案


  • 深度对齐：先把更深节点提到同层，再同时向上直到相遇，用 depth(a) + depth(b) − 2depth(LCA) + 1 计算，仍为每次 O(n)。
  • 二进制公共前缀：节点编号去掉最后一位等同于找父节点，LCA 对应最长公共前缀。两边需删除的位数之和再加 1 即答案；字符串实现需 O(n) 额外空间。
  • 一般树的倍增 LCA：适合显式给出且规模可管理的树，用预处理换取大量查询速度。本题父节点可直接算、层数至多 30，无需构造倍增表。


面试追问


  • 若边有权重？累加两端到 LCA 的路径权重与新边权重，不能仅用上移次数。
  • 如果节点编号是随机的？大小比较不再反映深度；需要父关系、深度或 LCA 结构。
  • 新增边不删除会怎样？后续图可能已有多个环，“唯一树路径 + 新边”的模型不再适用，必须重新明确查询语义。


常见错误


  • 计数从 0 开始却忘了在结束后加 1，漏掉新增边。
  • 每轮无条件同时移动两端，深度不同可能跳过 LCA。
  • 把较大编号误认为一定更深；它也可能同深，但仍然可以安全上移。
  • JavaScript 使用普通除法而不取整，产生小数编号。这里明确用 Math.floor。
  • 保留上次查询的指针、计数或临时边，造成查询之间相互干扰。

Java
class Solution {
    public int[] cycleLengthQueries(int n, int[][] queries) {
        int[] answer = new int[queries.length];
        for (int i = 0; i < queries.length; i++) {
            int a = queries[i][0], b = queries[i][1];
            int length = 1;
            while (a != b) {
                if (a > b) a /= 2;
                else b /= 2;
                length++;
            }
            answer[i] = length;
        }
        return answer;
    }
}

var cycleLengthQueries = function(n, queries) {
    return queries.map(([a, b]) => {
        let length = 1;
        while (a !== b) {
            if (a > b) a = Math.floor(a / 2);
            else b = Math.floor(b / 2);
            length++;
        }
        return length;
    });
};

C++
#include <vector>
using namespace std;

class Solution {
public:
    vector<int> cycleLengthQueries(int n, vector<vector<int>>& queries) {
        vector<int> answer;
        answer.reserve(queries.size());
        for (const auto& query : queries) {
            int a = query[0], b = query[1], length = 1;
            while (a != b) {
                if (a > b) a /= 2;
                else b /= 2;
                ++length;
            }
            answer.push_back(length);
        }
        return answer;
    }
};
