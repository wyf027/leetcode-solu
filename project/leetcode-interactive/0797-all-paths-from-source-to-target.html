所有可能的路径All Paths From Source to Target

把邻接表看作一张只向前延伸的路线图：任务是列出从起点 0 抵达终点 n - 1 的每一条完整路线，顺序不限。

有向无环图 深度优先搜索 回溯 输出所有解

01 · Mission brief

先读懂路线图

给定一个包含 n 个节点的有向无环图，节点编号为 0 到 n - 1。找出并返回所有从节点 0 到节点 n - 1 的路径，返回顺序不限。

输入如何表达图？

graph[i] 列出从节点 i 出发可以直接到达的所有节点。也就是说，对每个 graph[i][j]，图中存在一条 i → graph[i][j] 的有向边。

目标：不是判断“能否到达”，也不是只找一条最短路径，而是枚举每一条完整的源点到终点路径。

 [0,1,2,3,4],[0,1,4]]

约束

  • n == graph.length
  • 2 <= n <= 15
  • 0 <= graph[i][j] < n
  • graph[i][j] != i，即不存在自环
  • graph[i] 中的所有元素互不相同
  • 保证输入图是有向无环图（DAG）

    03 · Solution field notes

    深度优先搜索 + 回溯

    沿当前路线一直向前；抵达终点时复制路线；返回上一层时撤销刚刚加入的节点。这正好把搜索空间中的每条源点到终点路径枚举一次。

    核心洞察：路径是递归状态

    递归函数位于节点 u 时，数组 path 始终保存从 0 到 u 的当前路径。遍历 graph[u] 中的每个后继，就能覆盖从这个前缀延伸出的所有可能路径。

    DAG 让搜索保持简单

    题目保证没有环，因此沿边递归不会无限绕圈，也不需要全局 visited。若错误地全局标记访问过的节点，反而会漏掉由不同前缀抵达同一节点的合法路径。

    完整过程

    1. 1

      初始化 path = [0] 与空结果集 ans，从源点 0 开始 DFS。

    2. 2

      若当前节点等于终点 n - 1，把 path 的副本加入答案，然后结束当前分支。

    3. 3

      否则依次枚举当前节点的每个后继 v，先把 v 加到 path，再递归搜索 v。

    4. 4

      递归返回后删除路径末尾的 v，恢复进入该分支之前的状态，继续探索下一个后继。

    5. 5

      源点的所有分支处理结束时，ans 就包含全部源点到终点路径。

    正确性证明

    不变式：每次调用 dfs(u) 时，path 恰好是一条从源点 0 到当前节点 u 的合法路径。

    初始化：首次调用前 path = [0]，显然是不变式要求的源点到自身路径。

    保持：对任意 v ∈ graph[u]，边 u → v 存在。把 v 追加到 path 后，得到从 0 到 v 的合法路径，所以递归调用 dfs(v) 时不变式成立；调用返回后弹出 v，又恢复为到 u 的路径。

    完备性：任意一条从 0 到 n - 1 的路径，其下一节点必在当前节点的邻接表中。算法在每层枚举所有后继，因此会沿这条路径的每一条边递归，最终抵达终点并记录它。

    唯一性与可靠性：每次递归选择都对应一个确定的边序列。不同源点到终点路径至少有一条边不同，因此不会由同一选择序列重复产生。抵达终点时记录的路径依据不变式必然合法。故算法恰好返回所有合法路径。

    边界与复杂度

    最坏时间

    O(n · 2ⁿ)

    DAG 可能拥有指数级路径；每次写入答案还需复制最长为 n 的路径。

    辅助空间

    O(n)

    不计返回结果，递归深度与当前路径长度最多为 n。

    输出空间

    O(n · 2ⁿ)

    最坏情况下答案本身就是指数级，这是枚举所有路径无法避免的成本。

    关键边界

    无路可达 → []

    节点可能没有出边；源点也可能无法抵达终点。直接边 0 → n-1 则形成长度为 2 的路径。

    Reference implementations

    四种完整实现

    四份代码都使用相同的不变式：进入分支前追加节点，返回后弹出节点；保存答案时复制当前路径。

    Java

    class Solution {
    public List<List<Integer>> allPathsSourceTarget(int[][] graph) {
        List<List<Integer>> answer = new ArrayList<>();
        List<Integer> path = new ArrayList<>();
        path.add(0);
        dfs(0, graph, path, answer);
        return answer;
    }

    private void dfs(int node, int[][] graph,
                     List<Integer> path,
                     List<List<Integer>> answer) {
        if (node == graph.length - 1) {
            answer.add(new ArrayList<>(path));
            return;
        }

        for (int next : graph[node]) {
            path.add(next);
            dfs(next, graph, path, answer);
            path.remove(path.size() - 1);
        }
    }
}

    JavaScript

    /**
 * @param {number[][]} graph
 * @return {number[][]}
 */
var allPathsSourceTarget = function(graph) {
    const answer = [];
    const path = [0];
    const target = graph.length - 1;

    function dfs(node) {
        if (node === target) {
            answer.push(path.slice());
            return;
        }

        for (const next of graph[node]) {
            path.push(next);
            dfs(next);
            path.pop();
        }
    }

    dfs(0);
    return answer;
};

    Python 3

    from typing import List


class Solution:
    def allPathsSourceTarget(
        self, graph: List[List[int]]
    ) -> List[List[int]]:
        answer: List[List[int]] = []
        path = [0]
        target = len(graph) - 1

        def dfs(node: int) -> None:
            if node == target:
                answer.append(path.copy())
                return

            for nxt in graph[node]:
                path.append(nxt)
                dfs(nxt)
                path.pop()

        dfs(0)
        return answer

    C++

    class Solution {
public:
    vector<vector<int>> allPathsSourceTarget(
        vector<vector<int>>& graph
    ) {
        vector<vector<int>> answer;
        vector<int> path{0};
        dfs(0, graph, path, answer);
        return answer;
    }

private:
    void dfs(
        int node,
        const vector<vector<int>>& graph,
        vector<int>& path,
        vector<vector<int>>& answer
    ) {
        if (node == static_cast<int>(graph.size()) - 1) {
            answer.push_back(path);
            return;
        }

        for (int next : graph[node]) {
            path.push_back(next);
            dfs(next, graph, path, answer);
            path.pop_back();
        }
    }
};

    Other routes

    替代方案与取舍

    广度优先搜索（BFS）

    队列中的每个元素都保存一条“尚未扩展完成的路径”。取出一条路径后，按末尾节点的所有后继生成新路径；末尾是终点时加入答案。逻辑直观，但队列可能同时保存很多路径副本，内存通常高于 DFS 回溯。

    记忆化：缓存节点到终点的后缀路径

    定义 paths(u) 返回从 u 到终点的全部后缀路径，并缓存结果。多个前缀汇入同一节点时能复用计算，但仍需构造指数级输出，且缓存本身占用大量空间。本题规模很小，直接回溯更简洁。

    Interview follow-ups

    追问与常见错误

    如果图中允许有环怎么办？

    需要维护“当前递归路径上的节点集合”，进入节点时加入、回溯时移除；发现下一节点已经在当前路径上就跳过。不能简单使用永久全局 visited，否则仍可能漏掉合法路径。

    如果只问路径数量呢？

    不必保存具体路径。对 DAG 可用记忆化 DFS 或按拓扑序动态规划，令 count[u] 表示从 u 到终点的路径数。

    如果只要最多 k 条路径？

    记录到第 k 条后提前终止递归；可让 DFS 返回布尔值，逐层把“已经足够”的信号向上传递。

    常见错误清单

    • 保存了同一个可变数组引用：加入答案时必须复制 path，否则之后的回溯会改掉已保存结果。
    • 忘记回溯：递归返回后必须弹出刚加入的节点，否则不同分支会串在一起。
    • 使用全局 visited：同一节点可以由不同合法路径抵达，全局去重会漏解。
    • 抵达终点仍继续扩展：终点路径应立即记录并返回；题意只接受以 n - 1 结束的路径。
    • 低估输出规模：所有路径数量可能是指数级，不能宣称线性时间。
