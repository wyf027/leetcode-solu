Problem brief

题意

给定两个长度同为 n 的整数数组 fronts 和 backs。第 i 张卡片正面写着 fronts[i]，背面写着 backs[i]；初始时所有正面朝上。你可以翻转任意数量的卡片，也可以一张都不翻。

“好数字”的定义：完成翻转后，某个整数在至少一张卡片上朝下，同时没有出现在任何朝上的卡片上。

返回所有可能好数字中的最小值；如果不存在好数字，返回 0。

Function contract

函数签名

flipgame(fronts, backs) → integer

参数

  • fronts：每张卡片初始朝上的数字
  • backs：对应卡片初始朝下的数字
  • 返回值：最小可行好数字，或 0

Example 01

翻转第二张卡

输入：fronts = [1,2,4,4,7]
      backs  = [1,3,4,1,3]
输出：2

翻转第二张卡后，朝上数字为 [1,3,4,4,7]，朝下数字为 [1,2,4,1,3]。数字 2 朝下且未在任何卡片上朝上，并且它是能做到这一点的最小数字。

Example 02

两面相同

输入：fronts = [1]
      backs  = [1]
输出：0

无论是否翻转，数字 1 都会朝上，因此不存在好数字，返回 0。

Constraints

约束

  • n == fronts.length == backs.length
  • 1 <= n <= 1000
  • 1 <= fronts[i], backs[i] <= 2000

Complete solution

抓住永远朝上的数字

核心洞察：若某张卡片两面都是同一个数 x，无论如何翻转，这张卡上总有一个 x 朝上，所以 x 永远不可能成为好数字。除此以外，只要一个数出现在任意一面，就总能把所有包含它的卡片都调整为该数朝下。
  1. 扫描所有卡片，把满足 fronts[i] == backs[i] 的数字放入禁用集合 forbidden。
  2. 再次扫描 fronts 与 backs 中出现的每个数字。
  3. 忽略禁用集合中的数字；在其余数字里维护最小值。
  4. 如果始终没有合法候选，返回 0。

正确性证明

  • 必要性：如果存在一张两面都为 x 的卡片，那么无论是否翻转，该卡片朝上的一面都是 x，故 x 不可能是好数字。
  • 充分性：设 x 出现在某一面，且没有任何卡片两面都为 x。对每张含 x 的卡片，将其摆成 x 朝下；其他卡片任意摆放。此时至少一个 x 朝下，且没有 x 朝上，因此 x 可行。
  • 最小性：算法枚举所有出现过且不在禁用集合中的数字，并取其最小值，所以返回值正是最小可行好数字。

边界情况

  • 只有一张卡且两面相同：候选集合为空，返回 0。
  • 所有数字都被两面相同的卡片禁用：返回 0。
  • 某数字多次出现，只要没有“两面同时等于它”的卡片，它仍然可行。
  • 答案可能来自原始正面，也可能来自原始背面，因此两组数组都必须扫描。
时间：O(n) 空间：O(n)，也可利用数值上界降为固定 O(2000)

Java
import java.util.HashSet;
import java.util.Set;

class Solution {
    public int flipgame(int[] fronts, int[] backs) {
        Set<Integer> forbidden = new HashSet<>();

        for (int i = 0; i < fronts.length; i++) {
            if (fronts[i] == backs[i]) {
                forbidden.add(fronts[i]);
            }
        }

        int answer = Integer.MAX_VALUE;
        for (int i = 0; i < fronts.length; i++) {
            if (!forbidden.contains(fronts[i])) {
                answer = Math.min(answer, fronts[i]);
            }
            if (!forbidden.contains(backs[i])) {
                answer = Math.min(answer, backs[i]);
            }
        }

        return answer == Integer.MAX_VALUE ? 0 : answer;
    }
}

from typing import List


class Solution:
    def flipgame(self, fronts: List[int], backs: List[int]) -> int:
        forbidden = {
            front
            for front, back in zip(fronts, backs)
            if front == back
        }

        answer = float("inf")
        for front, back in zip(fronts, backs):
            if front not in forbidden:
                answer = min(answer, front)
            if back not in forbidden:
                answer = min(answer, back)

        return 0 if answer == float("inf") else answer

#include <algorithm>
#include <climits>
#include <unordered_set>
#include <vector>

using namespace std;

class Solution {
public:
    int flipgame(vector<int>& fronts, vector<int>& backs) {
        unordered_set<int> forbidden;

        for (int i = 0; i < static_cast<int>(fronts.size()); ++i) {
            if (fronts[i] == backs[i]) {
                forbidden.insert(fronts[i]);
            }
        }

        int answer = INT_MAX;
        for (int i = 0; i < static_cast<int>(fronts.size()); ++i) {
            if (!forbidden.count(fronts[i])) {
                answer = min(answer, fronts[i]);
            }
            if (!forbidden.count(backs[i])) {
                answer = min(answer, backs[i]);
            }
        }

        return answer == INT_MAX ? 0 : answer;
    }
};

替代方案

由于数字范围只有 1..2000，可以用长度为 2001 的布尔数组替代哈希集合：先标记禁用数字，再从 1 到 2000 找到第一个“出现过且未禁用”的数字。复杂度仍为 O(n + 2000)，空间为固定大小。

面试追问

  • 为什么只检查两面相同的卡片，就足以判断一个数字是否永远不可行？
  • 若数字上界未知，哈希集合与排序方案分别有什么权衡？
  • 如果要求输出一种具体翻牌方案，如何在线性时间内构造？

常见错误

  • 只在 backs 中寻找答案，漏掉翻转后可朝下的原始正面数字。
  • 把“当前正面出现过”误当成永久禁用；大部分卡片都可以翻转。
  • 认为重复出现的数字一定无效；真正永久阻塞它的是某张卡片两面都等于它。
  • 没有候选时返回无穷大或最大整数，而不是题目要求的 0。

如何构造翻牌方案

得到答案 x 后，逐张检查卡片：若 fronts[i] == x，就翻转该卡；若 backs[i] == x，则保持不动。因为 x 不在禁用集合中，不会出现同一张卡两面都是 x 的冲突。
