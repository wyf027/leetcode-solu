函数形式numberOfSubarrays(nums, k) → integer
约束

  • 1 ≤ nums[i] ≤ 100,000
  • 1 ≤ k ≤ nums.length

Solution

前缀奇数计数 + 频次表

核心洞察：把每个数只看成“奇数贡献 1、偶数贡献 0”。若当前位置的前缀奇数数为 odd，任何历史前缀值等于 odd - k，二者之间的连续区间就恰好含 k 个奇数。

完整过程

  1. 令 count[0] = 1，表示扫描前的空前缀已出现一次。
  2. 从左到右扫描；遇到奇数时令 odd += 1，偶数不改变它。
  3. 把 count[odd - k] 加到答案：这些历史前缀分别构成一个合法起点。
  4. 最后令 count[odd] += 1，把当前前缀登记给未来使用。

正确性说明

记前缀 P[i] 为前 i 个元素中的奇数数量。子数组 nums[l..r] 的奇数数量为 P[r+1] - P[l]。它等于 k 当且仅当 P[l] = P[r+1] - k。

扫描到 r 时，频次表已准确保存所有可选 l 的前缀值，因此加入的频次恰好等于以 r 结尾的优美子数组数；各子数组按右端点唯一计数，所以无遗漏也无重复。

边界与细节

  • 全偶数：前缀奇数数始终为 0；因 k ≥ 1，答案为 0。
  • k 大于奇数总数：永远查不到目标前缀，答案为 0。
  • 连续偶数：会让同一前缀计数多次出现，正好代表多个可选边界。
  • 初始化：漏掉 count[0] = 1 会错过从下标 0 开始的合法区间。

复杂度

时间：O(n)，每个元素只处理一次。

空间：O(n)；前缀奇数数最大为 n。用长度 n + 1 的数组即可替代哈希表。

替代方案

也可以计算 atMost(k) - atMost(k - 1)，用双指针求“至多含 k 个奇数”的子数组数，时间仍为 O(n)，额外空间降为 O(1)。另一种做法记录所有奇数下标，并对每组连续的 k 个奇数计算左右边界选择数的乘积。

class Solution {
    public int numberOfSubarrays(int[] nums, int k) {
        int[] count = new int[nums.length + 1];
        count[0] = 1;
        int odd = 0;
        int answer = 0;

        for (int num : nums) {
            odd += num & 1;
            if (odd >= k) {
                answer += count[odd - k];
            }
            count[odd]++;
        }
        return answer;
    }
}

面试追问与常见错误

为什么不能只用一个普通窗口？

“恰好 k 个”在移动左边界时可能存在多个合法起点。应改写为两个“至多”之差，或直接统计前缀频次。

怎样做到 O(1) 空间？

写一个 atMost(limit) 双指针函数，答案为 atMost(k) - atMost(k - 1)。

最常见的错误

先更新当前前缀频次、后查询目标值；或忘记登记空前缀。这会在特殊情况下把当前状态误当历史状态，或漏计从 0 开始的区间。
