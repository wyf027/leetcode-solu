601. 体育馆的人流量

Human Traffic of Stadium — 从一张门禁流水表中，找出真正形成连续高峰的记录。先读题、亲手推进演示；题解留在页面底部，默认不展开。

HARD 数据库 免费题 窗口函数

Problem brief

找出连续三次以上的高人流记录

给定 Stadium 表。请返回所有属于某个有效连续段的记录：该段至少包含三行、行与行之间的 id 连续，并且每行的 people 都不少于 100。最终按 visit_date 升序排列。

关键口径： 连续的是 id，不是日历日期。只要 id 连续，即使相邻记录的日期不相邻，也仍属于同一段。

Table schema

Stadium

  • idINT
  • visit_dateDATE
  • peopleINT

输入与返回形式

  • 输入参数是一张 Stadium(id, visit_date, people) 表。
  • 返回列保持为 id, visit_date, people。
  • 同一个长度不少于 3 的连续段中，所有行都应返回，而不只是其中三行。
  • 结果必须按 visit_date ASC 排序。

官方元数据中的约束

  • visit_date 的值唯一。
  • 随着 id 增大，日期也增大。
  • 每行记录一次到访及对应人流量。
  • 官方元数据未给出数值范围；本页不额外杜撰上下界。

Full solution

分组键：id - ROW_NUMBER()

先只保留达标行，再让连续 id 自动落进同一个分组。窗口函数把“连续性”变成了一个可聚合的常量。

核心洞察

对筛选后的行按 id 排序并编号 rn。同一段连续 id 中，id 与 rn 同步加 1，所以 id - rn 保持不变；遇到 id 缺口，这个差值就会改变。

完整过程

  1. 筛选
    只保留 people >= 100 的记录。
  2. 编号
    按 id 升序计算 ROW_NUMBER()。
  3. 分段
    用 id - rn 作为连续段分组键。
  4. 计数
    只保留组内行数不少于 3 的段。
  5. 排序
    返回原始三列并按日期升序。

正确性说明

引理 1 · 同段同键

在达标记录的任意连续 id 段内，相邻 id 与行号都增加 1，因此差值 id - rn 不变。

引理 2 · 断点换键

达标记录之间一旦存在 id 缺口，id 的增量大于行号增量，差值随即改变，不会把两个段误合并。

结论 · 恰好返回答案

按分组键计数后保留大小至少为 3 的组，既不会漏掉有效段，也不会混入短段或低于 100 的记录。

Time complexity
O(n log n)

窗口排序通常主导复杂度。若数据库可直接利用合适的 id 索引与执行计划，实际代价可能更低。

Space complexity
O(n)

逻辑上需保存筛选、窗口与分组的中间结果；数据库具体内存/临时空间取决于优化器。

官方可提交方案 · MySQL 8+

MySQLLeetCode 官方可提交语言
WITH eligible AS (
    SELECT
        id,
        visit_date,
        people,
        id - ROW_NUMBER() OVER (ORDER BY id) AS group_key
    FROM Stadium
    WHERE people >= 100
),
qualified_groups AS (
    SELECT group_key
    FROM eligible
    GROUP BY group_key
    HAVING COUNT(*) >= 3
)
SELECT e.id, e.visit_date, e.people
FROM eligible AS e
INNER JOIN qualified_groups AS q
    ON e.group_key = q.group_key
ORDER BY e.visit_date ASC;

Java本地语义参考 · 非本题提交语言
import java.time.LocalDate;
import java.util.ArrayList;
import java.util.Comparator;
import java.util.List;

public class Solution {
    public record Visit(int id, LocalDate visitDate, int people) {}

    public static List<Visit> humanTraffic(List<Visit> stadium) {
        List<Visit> rows = new ArrayList<>(stadium);
        rows.sort(Comparator.comparingInt(Visit::id));

        List<Visit> answer = new ArrayList<>();
        int start = 0;
        while (start < rows.size()) {
            if (rows.get(start).people() < 100) {
                start++;
                continue;
            }

            int end = start + 1;
            while (end < rows.size()
                    && rows.get(end).people() >= 100
                    && rows.get(end).id() == rows.get(end - 1).id() + 1) {
                end++;
            }

            if (end - start >= 3) {
                answer.addAll(rows.subList(start, end));
            }
            start = end;
        }

        answer.sort(Comparator.comparing(Visit::visitDate));
        return answer;
    }
}

/**
 * @typedef {{ id: number, visit_date: string, people: number }} Visit
 * @param {Visit[]} stadium
 * @returns {Visit[]}
 */
function humanTraffic(stadium) {
  const rows = stadium.map((row) => ({ ...row }))
    .sort((a, b) => a.id - b.id);
  const answer = [];

  let start = 0;
  while (start < rows.length) {
    if (rows[start].people < 100) {
      start += 1;
      continue;
    }

    let end = start + 1;
    while (
      end < rows.length &&
      rows[end].people >= 100 &&
      rows[end].id === rows[end - 1].id + 1
    ) {
      end += 1;
    }

    if (end - start >= 3) {
      answer.push(...rows.slice(start, end));
    }
    start = end;
  }

  return answer.sort((a, b) =>
    a.visit_date.localeCompare(b.visit_date)
  );
}

from dataclasses import dataclass
from datetime import date
from typing import Iterable, List


@dataclass(frozen=True)
class Visit:
    id: int
    visit_date: date
    people: int


def human_traffic(stadium: Iterable[Visit]) -> List[Visit]:
    rows = sorted(stadium, key=lambda row: row.id)
    answer: List[Visit] = []
    start = 0

    while start < len(rows):
        if rows[start].people < 100:
            start += 1
            continue

        end = start + 1
        while (
            end < len(rows)
            and rows[end].people >= 100
            and rows[end].id == rows[end - 1].id + 1
        ):
            end += 1

        if end - start >= 3:
            answer.extend(rows[start:end])
        start = end

    return sorted(answer, key=lambda row: row.visit_date)
C++本地语义参考 · 非本题提交语言
#include <algorithm>
#include <string>
#include <vector>

struct Visit {
    int id;
    std::string visit_date;  // ISO YYYY-MM-DD
    int people;
};

class Solution {
public:
    static std::vector<Visit> humanTraffic(std::vector<Visit> stadium) {
        std::sort(stadium.begin(), stadium.end(),
                  [](const Visit& a, const Visit& b) { return a.id < b.id; });

        std::vector<Visit> answer;
        std::size_t start = 0;
        while (start < stadium.size()) {
            if (stadium[start].people < 100) {
                ++start;
                continue;
            }

            std::size_t end = start + 1;
            while (end < stadium.size()
                   && stadium[end].people >= 100
                   && stadium[end].id == stadium[end - 1].id + 1) {
                ++end;
            }

            if (end - start >= 3) {
                answer.insert(answer.end(), stadium.begin() + start,
                              stadium.begin() + end);
            }
            start = end;
        }

        std::sort(answer.begin(), answer.end(),
                  [](const Visit& a, const Visit& b) {
                      return a.visit_date < b.visit_date;
                  });
        return answer;
    }
};

边界情况与常见错误

  • 把日期连续当作判断条件：题目只要求 id 连续；示例中的 7 与 8 已明确日期可跳跃。
  • 只返回三行：有效段若有 4 行或更多，整段都要返回。
  • 先在全表算行号再筛选：行号必须针对 people >= 100 的结果计算，否则低人流记录不会正确形成断点。
  • 遗漏最终排序：无论中间按什么顺序处理，最终都必须显式 ORDER BY visit_date ASC。
  • 用日期减行号分组：这会错误排除日期不连续但 id 连续的合法记录。
  • 忽略空结果：没有任何长度至少为 3 的段时，应返回空表而不是 NULL 行。

替代方案

三表自连接：可枚举连续三 id 的窗口，再把命中的行合并去重。它能工作，但 SQL 更冗长、扩展到“连续 k 行”也更笨重。

窗口累计断点：先用 LAG 标记 id 是否断开，再对断点做累计和得到组号。语义直观，适合连续规则更复杂的场景。

应用层扫描：四语言参考实现按 id 排序后线性扫描。适合数据已在内存，但数据库题优先让数据库完成过滤与分组。

面试追问

如果“连续”改成日期连续，方案如何变化？
应把分组基准改为日期与行号的差，例如在支持日期运算的数据库中使用 DATE_SUB(visit_date, INTERVAL rn DAY)，不能继续用 id 差值。
如果门槛和最短长度是动态参数呢？
把 100 与 3 参数化；窗口分组机制不变。注意使用绑定参数，避免把用户输入直接拼入 SQL。
为什么不用 COUNT(*) OVER 直接完成？
可以。在算出 group_key 后，再用 COUNT(*) OVER (PARTITION BY group_key) 得到段长，外层过滤段长至少为 3；部分数据库不允许在同层 WHERE 中引用窗口结果，仍需子查询或 CTE。
哪些索引可能有帮助？
id 上的索引有利于排序/扫描；是否增加包含 people 与 visit_date 的复合或覆盖索引，要结合表规模、选择性与实际执行计划决定。
