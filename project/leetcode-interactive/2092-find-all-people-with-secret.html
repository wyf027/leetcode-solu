2092 · 找出知晓秘密的所有专家

Find All People With Secret

一条秘密，若干场会议。有人在同一瞬间接收、再分享；有人错过了时间，就再也无法沿过去的会议获知秘密。

官方题目 ↗探索会议时间线 ↓测试与验证
01 / THE PROBLEM

先理解规则

共有 n 位专家，编号为 0…n−1。数组中的一项 meetings[i] = [xᵢ, yᵢ, timeᵢ] 表示两人在 timeᵢ 会面。同一专家可以在同一时刻参加多场会议。

时间 0，专家 0 已知秘密，并立即告诉 firstPerson。之后，每场会议只要一方知晓秘密，就会告诉另一方；传播是双向且瞬时的。

返回所有会议结束后知晓秘密的专家编号，顺序任意。

同一时刻刚获知秘密的人，可以马上在这个时刻的另一场会议中继续分享。会议结束后不会保留一个持续通信的通道。

输入与约束

findAllPeople(n, meetings, firstPerson)
→ 专家编号数组
  • 2 ≤ n ≤ 10⁵
  • 1 ≤ meetings.length ≤ 10⁵
  • meetings[i].length = 3
  • 0 ≤ xᵢ, yᵢ ≤ n−1，且 xᵢ ≠ yᵢ
  • 1 ≤ timeᵢ ≤ 10⁵
  • 1 ≤ firstPerson ≤ n−1

输入会议不保证按时间排列。输出按集合比较；本页用升序列出，方便阅读。

官方示例 · 完整参数

示例 1
n = 6
meetings = [[1,2,5],[2,3,8],[1,5,10]]
firstPerson = 1

输出：[0,1,2,3,5]

时间 0：0 告诉 1；时间 5：1 告诉 2；时间 8：2 告诉 3；时间 10：1 告诉 5。专家 4 没有收到秘密。

示例 2
n = 4
meetings = [[3,1,3],[1,2,2],[0,3,3]]
firstPerson = 3

输出：[0,1,3]

时间 2 的 1 与 2 都未知。时间 3，3 告诉 1；0 原本就知道秘密。1 无法回到时间 2 告诉 2。

示例 3
n = 5
meetings = [[3,4,2],[1,2,1],[2,3,1]]
firstPerson = 1

输出：[0,1,2,3,4]

时间 1，秘密从 1 经 2 传给 3，两次传播发生在同一时刻。时间 2，3 再告诉 4。

04 / SOLUTION · ON YOUR TERMS
准备好再看题解
先尝试描述：同一时刻刚拿到秘密的人，如何继续传递？不同时间的会议能否一直相连？




按时间分组，再做多源 BFS


核心洞察：每个时刻是一张临时无向图。一个连通分量只要在这一刻开始时含有知情者，秘密就能瞬间覆盖整个分量。只永久保存“谁知道”，不永久保存“谁与谁见过”。


完整过程
    

  1. 将 meetings 按时间升序排列。创建布尔数组 known，仅将 0 与 firstPerson 标为真。
    2. 

  2. 用双指针取出相同时间的全部会议，构建这一组参与者的无向邻接表。
    3. 

  3. 把本组中所有已经知晓秘密的人加入队列。他们是这一时刻的多个传播源；未参与本组的人不用入队。
    4. 

  4. 取出队头，检查所有邻居。如果邻居尚未知晓，则立即标为已知并入队。持续到队列为空。
    5. 

  5. 丢弃本组的临时图，处理下一个时刻。所有时间结束后遍历 known，输出为真的编号。


以官方示例 3 串起过程
开始集合是 {0,1}。t=1 建立 1—2—3，队列起初只有 1；弹出 1 后标记 2，弹出 2 后标记 3。本组结束时集合是 {0,1,2,3}。删除这两条会议边，t=2 仅建立 3—4，从 3 出发标记 4，最终所有专家均知晓秘密。


正确性证明
不变量：处理完前若干个时刻后，known 恰好记录这些时刻结束后所有知情者。
初始成立：会议前只有 0 与 firstPerson 知道秘密，与初始化完全相同。
归纳步骤：假设处理当前时刻前不变量成立。临时图的边恰好是当前时刻可交流的会议。BFS 从此前已知的参与者出发，每次沿一条有效会议边传播，因此新标记的人都确实能获知秘密，不会误报。反过来，任何此时能获知秘密的人，必然位于包含某个已知源的连通分量中；BFS 会遍历该分量的全部可达节点，因此不会遗漏。同一时刻传播可以连续发生，所以路径长度不构成限制。丢弃临时边后不再使用过去的会议，不会产生跨时间的虚假传播。故不变量在该组结束后仍成立。
结束：由归纳，遍历完所有时刻后 known 就是所求集合。


复杂度
令 m = meetings.length。排序 O(m log m)；每组顶点入队至多一次、每条边检查两次，累计图遍历 O(m)；初始化与收集结果 O(n)。总时间 O(m log m + n)。
临时图最多 O(m) 条邻接项，知情数组 O(n)，队列不超过当前参与人数。含排序工作空间，额外空间按上界计为 O(n + m)。哈希邻接表操作按通常均摊 O(1) 分析。四份代码均原地排序输入会议。
边界处理
  • 同时间逆序链：先建完整图，再传播。
  • 互不连通的分量：没有已知源就不会入队。
  • 没有参会的初始知情者：仍保留在结果。
  • 重复会议与环：标记后入队，防止重复扩展。
  • 最小 n=2：两位初始知情者不会丢失。
  • 同组无人知道：队列为空，直接换时间。


为什么全局 known 也能防止本组重复入队？
本组开始时，图中所有已知节点都已作为种子入队。之后每个未知节点只会经历一次 false → true，并在标记的同时入队。因此每个参与者在这一组最多入队一次，不需要另设本组 visited 数组。下一组会重新收集其已知参与者。


替代方案与取舍
  • 并查集：同时间先合并所有会议对，再将与 0 不连通的本组参与者重置，避免保存过期关系。可以达到排序主导的复杂度，但“整组合并后再统一重置”更易写错；重置时还要维护正确的秩或大小信息。
  • 时间最短路：记录每个人最早获知时间，用最小堆扩展；只有会议时间 ≥ 当前获知时间的边可用。完整静态邻接表保留会议时间，允许相等以支持瞬时接力。一般为 O((n+m) log(n+m)) 的安全上界，代码与堆管理比按时间 BFS 更繁琐。
  • 组内 DFS：与 BFS 等价。大规模长链优先显式栈，避免递归栈溢出。


常见错误
  1. 排序后只逐场扫描一次：同时间逆序排列时，早处理的会议可能需要再次传播。
  2. 把所有会议无条件合并：错误地利用过去的边，官方示例 2 会把专家 2 加入答案。
  3. 每个时间重建长度 n 的访问数组：不同时间很多时可能退化到 O(nm)。本解只遍历当前参与者。
  4. 出队才标记：重复边或环可能导致大量重复入队。应先标记，再入队。
  5. JavaScript 队列反复 shift()：改用递增头索引，避免数组整体移动。
  6. 忘记双向建边，或遗漏从未参会的 0 与 firstPerson。

/**
 * @param {number} n
 * @param {number[][]} meetings
 * @param {number} firstPerson
 * @return {number[]}
 */
var findAllPeople = function(n, meetings, firstPerson) {
    meetings.sort((a, b) => a[2] - b[2]);
    const known = new Uint8Array(n);
    known[0] = known[firstPerson] = 1;
    let i = 0;
    while (i < meetings.length) {
        let j = i;
        const graph = new Map();
        while (j < meetings.length &&
               meetings[j][2] === meetings[i][2]) {
            const [a, b] = meetings[j++];
            if (!graph.has(a)) graph.set(a, []);
            if (!graph.has(b)) graph.set(b, []);
            graph.get(a).push(b);
            graph.get(b).push(a);
        }
        const queue = [];
        for (const person of graph.keys()) {
            if (known[person]) queue.push(person);
        }
        for (let head = 0; head < queue.length; head++) {
            for (const person of graph.get(queue[head])) {
                if (!known[person]) {
                    known[person] = 1;
                    queue.push(person);
                }
            }
        }
        i = j;
    }
    const answer = [];
    for (let person = 0; person < n; person++) {
        if (known[person]) answer.push(person);
    }
    return answer;
};


Java
import java.util.*;

class Solution {
    public List<Integer> findAllPeople(
            int n, int[][] meetings, int firstPerson) {
        Arrays.sort(meetings, (a, b) -> Integer.compare(a[2], b[2]));
        boolean[] known = new boolean[n];
        known[0] = known[firstPerson] = true;
        int i = 0;
        while (i < meetings.length) {
            int j = i;
            Map<Integer, List<Integer>> graph = new HashMap<>();
            while (j < meetings.length &&
                   meetings[j][2] == meetings[i][2]) {
                int a = meetings[j][0], b = meetings[j][1];
                graph.computeIfAbsent(a, k -> new ArrayList<>()).add(b);
                graph.computeIfAbsent(b, k -> new ArrayList<>()).add(a);
                j++;
            }
            Deque<Integer> queue = new ArrayDeque<>();
            for (int person : graph.keySet()) {
                if (known[person]) queue.addLast(person);
            }
            while (!queue.isEmpty()) {
                int person = queue.removeFirst();
                for (int next : graph.get(person)) {
                    if (!known[next]) {
                        known[next] = true;
                        queue.addLast(next);
                    }
                }
            }
            i = j;
        }
        List<Integer> answer = new ArrayList<>();
        for (int person = 0; person < n; person++) {
            if (known[person]) answer.add(person);
        }
        return answer;
    }
}


Python 3
from collections import defaultdict, deque
from typing import List

class Solution:
    def findAllPeople(self, n: int, meetings: List[List[int]],
                      firstPerson: int) -> List[int]:
        meetings.sort(key=lambda meeting: meeting[2])
        known = [False] * n
        known[0] = known[firstPerson] = True
        i = 0
        while i < len(meetings):
            j = i
            graph = defaultdict(list)
            while j < len(meetings) and meetings[j][2] == meetings[i][2]:
                a, b, _ = meetings[j]
                graph[a].append(b)
                graph[b].append(a)
                j += 1
            queue = deque(person for person in graph if known[person])
            while queue:
                person = queue.popleft()
                for neighbor in graph[person]:
                    if not known[neighbor]:
                        known[neighbor] = True
                        queue.append(neighbor)
            i = j
        return [person for person in range(n) if known[person]]


C++
#include <algorithm>
#include <queue>
#include <unordered_map>
#include <vector>
using namespace std;

class Solution {
public:
    vector<int> findAllPeople(int n, vector<vector<int>>& meetings,
                              int firstPerson) {
        sort(meetings.begin(), meetings.end(),
             [](const vector<int>& a, const vector<int>& b) {
                 return a[2] < b[2];
             });
        vector<bool> known(n, false);
        known[0] = known[firstPerson] = true;
        int i = 0, m = static_cast<int>(meetings.size());
        while (i < m) {
            int j = i;
            unordered_map<int, vector<int>> graph;
            while (j < m && meetings[j][2] == meetings[i][2]) {
                int a = meetings[j][0], b = meetings[j][1];
                graph[a].push_back(b);
                graph[b].push_back(a);
                ++j;
            }
            queue<int> q;
            for (const auto& entry : graph) {
                if (known[entry.first]) q.push(entry.first);
            }
            while (!q.empty()) {
                int person = q.front();
                q.pop();
                for (int next : graph.at(person)) {
                    if (!known[next]) {
                        known[next] = true;
                        q.push(next);
                    }
                }
            }
            i = j;
        }
        vector<int> answer;
        for (int person = 0; person < n; ++person) {
            if (known[person]) answer.push_back(person);
        }
        return answer;
    }
};


面试追问
  • 为什么不是每场会议只处理一次？同一时刻必须完成可达闭包，单次顺序扫描依赖输入顺序。
  • 如果输入按时间有序流式到达？缓存当前时间组，确认该时间组完整后处理，随后丢弃；无需全局排序。不能在同组数据尚未到齐时过早结算。
  • 如何记录每个人最早获知的时间？初始两人为 0，其他人为未知；节点首次入队标记时同时保存当前组时间。
  • 如果传播不是瞬时的？当前连通分量规则不再直接成立，需要明确传播延迟与会议持续规则，再用按事件时间推进的方法求最早到达时间。
