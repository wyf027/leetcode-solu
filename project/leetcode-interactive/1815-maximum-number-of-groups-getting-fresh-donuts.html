得到新鲜甜甜圈的
最多组数

Maximum Number of Groups Getting Fresh Donuts

同样的顾客，换一种排队顺序，有多少组能从新的一批开始？

免费题 交互学习 · 约 15 分钟

01 / 题目约定

商店每批制作 batchSize 个甜甜圈，当前一批必须全部售完才能供应下一批。groups[i] 是第 i 组的人数，每人恰好购买一个；一组必须全部买完，才能轮到下一组。

如果一组的第一位顾客拿到的不是上一组留下的甜甜圈，这组就被计为开心。允许重新排列所有组，返回开心组数的最大值。

“开心”只看这一组开始时是否有上一组的剩余。组内可以跨越多批，不要求整组只吃同一批。

约束

  • 1 ≤ batchSize ≤ 9
  • 1 ≤ groups.length ≤ 30
  • 1 ≤ groups[i] ≤ 10⁹

为什么某些组人数很大，却对下一组的开始状态产生相同影响？

05 / 题解 · 余数计数 + 记忆化搜索

核心洞察

令 b = batchSize。只需关心人数对 b 的余数。定义 rem 为此前所有已服务人数之和 mod b，它表示当前批次已售出的数量，而不是剩余数量。只有 rem = 0 时，下一组开心；选余数 r 后，rem 变为 (rem + r) mod b。

同余数组对后续状态的影响相同，把它们压缩成计数 c[r]。余数 0 的组可以全部先服务，每组贡献 1，记为 base。删除这些组不改变任何非零组开始时的余数；它们原本的贡献最多也是 base，因此这种前置安排不会降低最优值。

完整过程与状态转移

  1. 统计余数 0 的组数 base，压缩余数 1…b−1 的频次。
  2. 每个频次最多 30，使用 5 位存一个计数，最多 8 个字段共 40 位。第 r 桶使用位偏移 5(r−1)。初始状态是各组对应字段单位的累加。
  3. dfs(state, rem) 返回剩余组还能贡献的最大开心数。state = 0 时返回 0，不能在空队伍上奖励 1。
  4. 枚举所有计数非零的余数 r，递减这一桶，转移到新余数；奖励根据转移前的 rem 判断。
  5. 缓存最优值，最终返回 base + dfs(initialState, 0)。
F(c, rem) = max over r with c[r] > 0:
    [rem == 0] + F(c - e_r, (rem + r) % b)
F(empty, rem) = 0

为什么缓存只用 state？固定本次输入后，设非零组总余数和为 T，则 rem = (T − Σ r·c[r]) mod b。剩余计数唯一确定已服务总和的余数，路径顺序不影响它。Java / JS / C++ 显式传递 rem 以快速转移，Python 每个新状态直接推导 rem。

本组奖励：1  1  0  1  0  1
结束 rem：0  2  0  2  0  0

压缩后 c[0]=2、c[1]=2、c[2]=2。先拿到两组余数 0 的奖励，余下可按 1,2,1,2 排列，再得到 2 组，合计 4。

正确性证明

状态充分性：每组只通过余数影响下一组，且奖励只依赖当前 rem。因此同一个剩余频次数组代表等价的后续问题。

最优子结构：对剩余组数作归纳。空状态最优值为 0。非空状态中，任何合法排列必定以某个有剩余的余数 r 开始；其第一组奖励固定为 [rem=0]，其余部分由归纳假设得到最优值。枚举所有这样的 r 既覆盖全部首组选项，也不引入非法排列，取最大值即为全局最优。

预处理保持最优：将余数 0 的组前置后，各组都开心，非零组的相对顺序及开始余数不变，故上述 base 与搜索结果之和就是原题答案。

复杂度与边界

设 k=b−1，n 为组数，S=∏(c[r]+1)，r 从 1 到 k。时间 O(n + bS)，空间 O(S+n+b)，包含记忆化表与最多 n 层递归。最多 30 个非零组分配到 8 个桶，乘积在尽量均分时最大，为 5⁶×4²=250,000；每个状态最多尝试 8 个余数。

b=1 时所有组都计入 base；全是整批组时搜索状态为空；单组无论多大都至少贡献 1；余数不为 0 的最终状态没有额外惩罚。人数可达 10⁹，按人模拟不可行，但取模不受人数大小影响。

四语言完整提交代码

均使用官方 maxHappyGroups 签名。代码为生成稿，未执行；JavaScript 使用 BigInt 保存 40 位状态，避免普通位运算的 32 位截断。

JavaScript
/** @param {number} batchSize @param {number[]} groups @return {number} */
var maxHappyGroups = function(batchSize, groups) {
    let base = 0, state = 0n;
    for (const g of groups) {
        const r = g % batchSize;
        if (r === 0) base++;
        else state += 1n << BigInt(5 * (r - 1));
    }
    const memo = new Map();
    function dfs(s, rem) {
        if (s === 0n) return 0;
        if (memo.has(s)) return memo.get(s);
        let best = 0;
        for (let r = 1; r < batchSize; r++) {
            const shift = BigInt(5 * (r - 1));
            if (((s >> shift) & 31n) === 0n) continue;
            best = Math.max(best, (rem === 0 ? 1 : 0) +
                dfs(s - (1n << shift), (rem + r) % batchSize));
        }
        memo.set(s, best);
        return best;
    }
    return base + dfs(state, 0);
};
Python
from typing import List
from functools import lru_cache

class Solution:
    def maxHappyGroups(self, batchSize: int, groups: List[int]) -> int:
        base, state = 0, 0
        for g in groups:
            r = g % batchSize
            if r == 0:
                base += 1
            else:
                state += 1 << (5 * (r - 1))

        # rem is derived from the remaining state within this invocation.
        total = sum(groups) % batchSize

        @lru_cache(None)
        def dfs(s: int) -> int:
            if s == 0:
                return 0
            remaining = sum(r * ((s >> (5 * (r - 1))) & 31)
                            for r in range(1, batchSize))
            rem = (total - remaining) % batchSize
            best = 0
            for r in range(1, batchSize):
                shift = 5 * (r - 1)
                if (s >> shift) & 31:
                    best = max(best, int(rem == 0) + dfs(s - (1 << shift)))
            return best

        return base + dfs(state)
Java
import java.util.HashMap;
import java.util.Map;

class Solution {
    private int b;
    private final Map<Long, Integer> memo = new HashMap<>();

    public int maxHappyGroups(int batchSize, int[] groups) {
        b = batchSize;
        memo.clear();
        int base = 0;
        long state = 0;
        for (int g : groups) {
            int r = g % b;
            if (r == 0) base++;
            else state += 1L << (5 * (r - 1));
        }
        return base + dfs(state, 0);
    }

    private int dfs(long state, int rem) {
        if (state == 0) return 0;
        Integer cached = memo.get(state);
        if (cached != null) return cached;
        int best = 0;
        for (int r = 1; r < b; r++) {
            int shift = 5 * (r - 1);
            if (((state >>> shift) & 31L) == 0) continue;
            best = Math.max(best, (rem == 0 ? 1 : 0) +
                dfs(state - (1L << shift), (rem + r) % b));
        }
        memo.put(state, best);
        return best;
    }
}

替代方案

直接枚举组排列需要 O(n!)；按每组做子集 DP 需要 O(n·2ⁿ)，n=30 时过大。使用频次数组的元组或字符串作缓存键更直观，但每次创建键有额外开销。5 位编码保留同样状态含义而减少键构造。可以进一步研究互补余数配对预处理以缩小搜索，但仅做配对不能解决所有组合，例如 b=3 的三个余数 1 也能组成整批。

常见错误

  • 在服务结束后判断开心：应检查服务开始前的 rem。
  • 把 rem 当成剩余甜甜圈：实际剩余为 (b−rem) mod b。
  • 空状态 rem=0 时仍加 1：没有组可服务时奖励为 0。
  • 只用人数排序或只找互补对：遗漏更长的整批组合。
  • 用 32 位整数存 40 位字段，或用不足 5 位表示计数 30。
  • 不同输入共用旧缓存：state 推导 rem 依赖本次输入，缓存必须重新建立。

面试追问

如何返回最优排列？为每个状态额外记录达到最大值的余数，沿选择恢复路径，再从对应余数桶取出实际组编号。

何时必须把 rem 放进键？如果同一剩余状态可能由不同初始总和或外部指定开始余数到达，就必须显式纳入，或固定这些外部条件后重建缓存。

组数大幅增加怎么办？5 位计数与当前状态上界都不再适用，需要更宽编码，并重新评估计数状态的组合增长，不能只扩大整数类型。
