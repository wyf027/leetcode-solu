Solution

一次关联，三次过滤，最后去重

把“何时播放”与“内容属性”放回同一行判断。

核心洞察

TVProgram 提供日期，Content 提供标题、儿童属性和类型。两表连接后同时筛选：

  • 日期在 [2020-06-01, 2020-07-01)。
  • Kids_content = 'Y'。
  • content_type = 'Movies'。
  • DISTINCT 消除重复片名。

完整过程与边界

  1. 按 content_id 连接两表。
  2. 保留六月播放记录。
  3. 保留儿童适宜的电影。
  4. 投影片名并去重。
边界：包含 6 月 1 日，排除 7 月 1 日；无合格行则返回空表；重复播放只输出一次。

MySQL · 官方可提交答案

主语言
SELECT DISTINCT c.title
FROM TVProgram AS t
JOIN Content AS c
  ON t.content_id = c.content_id
WHERE t.program_date >= '2020-06-01'
  AND t.program_date <  '2020-07-01'
  AND c.Kids_content = 'Y'
  AND c.content_type = 'Movies';

正确性

1

完备：任意合格电影必有六月播放行；连接后其三个筛选条件都成立，标题会被选中。

2

可靠：任意被选标题都来自六月播放行，且对应内容儿童适宜、类型为电影，故一定合格。

3

唯一：DISTINCT 折叠相同标题。因此结果恰是目标片名集合。

复杂度

设两表行数为 P、C，连接后的候选数为 K。有合适连接键和日期索引时，优化器可先缩小六月集合再连接；哈希去重约需 O(K) 空间，排序去重则约需 O(K log K) 时间。

SQL 的实际代价取决于索引、统计信息和执行计划，不能机械等同于固定循环。

Java · 本地语义参考（非本题官方提交形式）

集合模拟 SQL
import java.time.LocalDate;
import java.util.*;

class Solution {
  record Program(LocalDate date, int contentId, String channel) {}
  record ContentRow(int contentId, String title,
                    String kidsContent, String contentType) {}

  List<String> friendlyMovies(List<Program> programs,
                              List<ContentRow> contents) {
    Map<Integer, ContentRow> byId = new HashMap<>();
    for (ContentRow c : contents) byId.put(c.contentId(), c);
    LocalDate start = LocalDate.of(2020, 6, 1);
    LocalDate end = LocalDate.of(2020, 7, 1);
    Set<String> answer = new LinkedHashSet<>();
    for (Program p : programs) {
      ContentRow c = byId.get(p.contentId());
      if (c != null && !p.date().isBefore(start)
          && p.date().isBefore(end) && "Y".equals(c.kidsContent())
          && "Movies".equals(c.contentType())) {
        answer.add(c.title());
      }
    }
    return new ArrayList<>(answer);
  }
}

function friendlyMovies(programs, contents) {
  const byId = new Map(contents.map(c => [c.content_id, c]));
  const titles = new Set();
  for (const p of programs) {
    const day = p.program_date.slice(0, 10);
    const c = byId.get(p.content_id);
    if (c && day >= "2020-06-01" && day < "2020-07-01"
        && c.Kids_content === "Y" && c.content_type === "Movies") {
      titles.add(c.title);
    }
  }
  return [...titles];
}

字典与集合
from datetime import date, datetime

def friendly_movies(programs, contents):
    by_id = {c["content_id"]: c for c in contents}
    start, end = date(2020, 6, 1), date(2020, 7, 1)
    titles = set()
    for p in programs:
        day = datetime.strptime(p["program_date"][:10], "%Y-%m-%d").date()
        c = by_id.get(p["content_id"])
        if (c and start <= day < end
                and c["Kids_content"] == "Y"
                and c["content_type"] == "Movies"):
            titles.add(c["title"])
    return list(titles)

C++ · 本地语义参考（非本题官方提交形式）

哈希连接模拟
#include <string>
#include <unordered_map>
#include <unordered_set>
#include <vector>
using namespace std;

struct Program { string date; int contentId; string channel; };
struct ContentRow {
  int contentId; string title, kidsContent, contentType;
};

vector<string> friendlyMovies(const vector<Program>& programs,
                              const vector<ContentRow>& contents) {
  unordered_map<int, ContentRow> byId;
  for (const auto& c : contents) byId.emplace(c.contentId, c);
  unordered_set<string> titles;
  for (const auto& p : programs) {
    string day = p.date.substr(0, 10);
    auto it = byId.find(p.contentId);
    if (it == byId.end()) continue;
    const auto& c = it->second;
    if (day >= "2020-06-01" && day < "2020-07-01"
        && c.kidsContent == "Y" && c.contentType == "Movies") {
      titles.insert(c.title);
    }
  }
  return vector<string>(titles.begin(), titles.end());
}

替代方案

可写 YEAR(program_date)=2020 AND MONTH(program_date)=6，但对列调用函数可能妨碍普通日期索引的范围查找。半开区间更稳，也兼容带时间值。

还可从 Content 出发使用 EXISTS 判断六月播放是否存在，但直接连接更简洁。

面试追问

为什么不写 BETWEEN？

BETWEEN '2020-06-01' AND '2020-06-30' 在字段带时间时可能漏掉 6 月 30 日零点之后的数据。

DISTINCT 能去掉吗？

除非约束保证每个标题最多一条合格播放，否则不能；题目明确要求不同片名。

连接键类型不一致怎么办？

官方各数据库元数据存在类型差异。生产系统应统一类型；必要时显式转换并留意索引影响。

常见错误

只筛月份

仅写 MONTH(...)=6 会混入其他年份。

把 Series 算成电影

儿童适宜不等于电影，还要检查类型。

忘记去重

重复播放会产生重复片名。
