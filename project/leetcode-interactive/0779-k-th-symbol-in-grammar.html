Solution

题解：只走一条祖先路径

不生成长度为 2^(n-1) 的整行，只保存当前坐标与一个翻转位。

核心洞察

01 / PARENT两个孩子共享一个父位置

第 k 个符号的父位置是 ceil(k / 2)，整数形式为 (k + 1) / 2。

02 / PARITY奇偶决定是否翻转

k 为奇数时是左孩子，等于父符号；k 为偶数时是右孩子，等于父符号取反。

03 / ROOT根符号已知

持续回溯到第 1 行后，根符号固定为 0。路径上的翻转次数奇偶性就是答案。

parent(k) = (k + 1) / 2；若 k 为偶数，则 value ^= 1

完整过程

  1. 初始化 value = 0，把它看作从第 1 行根符号出发所需累计的翻转奇偶性。
  2. 当 n > 1 时检查当前 k：若为偶数，说明当前点是右孩子，将 value 翻转一次；若为奇数则不变。
  3. 令 k = (k + 1) / 2 移到父位置，并令 n = n - 1 移到上一行。
  4. 到达第 1 行后返回 value。

正确性证明

1

局部关系成立。 任意父符号 x 展开后，第一个孩子仍为 x，第二个孩子为 1 - x。因此奇数位置继承父符号，偶数位置翻转父符号。

2

每一步保持答案等价。 算法把当前位置映射到唯一父位置；若当前是右孩子，就同步翻转 value。所以“父位置的符号再叠加累计翻转”始终等于原目标位置的符号。

3

终止时得到答案。 每次行号减 1，最终到达第 1 行，其符号为 0。此时 value 恰好记录整条路径上所有右孩子造成的翻转奇偶性，因此返回值就是第 n 行第 k 个符号。

时间 O(n)额外空间 O(1)

四语言完整代码

class Solution {
    public int kthGrammar(int n, int k) {
        int value = 0;

        while (n > 1) {
            if ((k & 1) == 0) {
                value ^= 1;
            }
            k = (k + 1) / 2;
            n--;
        }

        return value;
    }
}

边界与常见错误

  • n = 1：循环不执行，直接返回根符号 0。
  • 1-based 位置：这里的奇数是左孩子、偶数是右孩子；若先把 k 减 1，判断公式也要随之调整。
  • 不要构造整行：第 30 行长度为 2^29，时间与内存都会浪费在无关符号上。
  • 父位置上取整：应使用 (k + 1) / 2，不是直接使用 k / 2 的下取整。

替代方案

位计数：答案等于 k - 1 的二进制中 1 的个数奇偶性，即 popcount(k - 1) % 2。它把“走到右孩子就翻转”压缩成对路径位的计数。

递归：可递归到父坐标，再根据当前 k 的奇偶决定是否取反。逻辑直接，但会使用 O(n) 调用栈。

镜像递推：利用每行后半段是前半段取反的性质缩小 k。同样正确，但边界推导更容易出错。

面试追问

为什么答案其实与 n 没有直接关系？

只要约束保证第 n 行包含位置 k，通往该位置的左右路径已经由 k - 1 的二进制位唯一决定；增加更高的行只会在路径前补左孩子，不改变翻转奇偶性。

如何把复杂度进一步写成与 k 有关？

若使用位计数，只需处理 k - 1 的有效二进制位，时间可写为 O(log k)，额外空间仍为 O(1)。

如果替换规则改成 0→10、1→01 呢？

左右孩子的“继承/翻转”关系会交换：左孩子翻转、右孩子继承。祖先路径框架仍可复用，只需改变何时切换累计翻转位。
