使数组元素全部相等的
最少操作次数

Minimum Operations to Make All Array Elements Equal

把每个查询看作一条目标线：所有数字到这条线的垂直距离之和，就是答案。

Problem

题目

数组 · Binary Search · Prefix Sum · Sorting

给定一个由正整数组成的数组 nums，以及长度为 m 的整数数组 queries。

对于第 i 个查询，需要把 nums 的每个元素都变为 queries[i]。一次操作可以选择一个数组元素，将它增加 1 或减少 1，操作次数不限。

返回长度为 m 的数组 answer，其中 answer[i] 是完成第 i 个查询所需的最少操作次数。每个查询都从原始的 nums 开始，查询之间互不影响。

示例 1

输入：nums = [3,1,6,8], queries = [1,5]
输出：[14,10]
解释：
查询 1：|3-1| + |1-1| + |6-1| + |8-1|
       = 2 + 0 + 5 + 7 = 14
查询 5：|3-5| + |1-5| + |6-5| + |8-5|
       = 2 + 4 + 1 + 3 = 10

示例 2

输入：nums = [2,9,6,3], queries = [10]
输出：[20]
解释：
|2-10| + |9-10| + |6-10| + |3-10|
= 8 + 1 + 4 + 7
= 20

约束

  • n == nums.length
  • m == queries.length
  • 1 <= n, m <= 105
  • 1 <= nums[i], queries[i] <= 109

Solution

排序 + 二分 + 前缀和

O((n + m) log n)

核心洞察

对某个查询值 q，答案本质上是 Σ |nums[j] - q|。先将 nums 升序排列，并建立前缀和。二分找到第一个大于等于 q 的位置 i 后：

1

左侧统一增加

nums[0..i-1] < q，代价为 q × i - prefix[i]。

2

右侧统一减少

nums[i..n-1] >= q，代价为 prefix[n] - prefix[i] - q × (n-i)。

3

两侧相加

两个区间没有重叠也没有遗漏，左代价与右代价之和就是最少操作数。

完整过程

  1. 将 nums 升序排序。
  2. 建立长度为 n + 1 的前缀和：prefix[0] = 0，prefix[k+1] = prefix[k] + nums[k]。
  3. 对每个查询 q，用二分查找得到第一个 nums[i] >= q 的下标 i。
  4. 用前缀和 O(1) 求出左侧需要增加的总量和右侧需要减少的总量。
  5. 把两侧代价相加，按查询原顺序写入答案。

示例拆解：nums = [3,1,6,8]，q = 5

排序后为 [1,3,6,8]，前缀和为 [0,1,4,10,18]。二分得到 i = 2。

左侧代价：5 × 2 - 4 = 6；右侧代价：18 - 4 - 5 × 2 = 4；总计 10。

正确性证明

引理 1：把单个元素 x 变成 q 至少需要 |x-q| 次操作，并且连续增加或减少正好可以在这么多次内完成，因此该代价既是下界也是可达值。

引理 2：排序后，以第一个大于等于 q 的位置 i 为界，左侧每个元素的代价都是 q-nums[j]，右侧每个元素的代价都是 nums[j]-q。前缀和公式分别精确求出了这两组代价之和。

结论：不同元素上的操作互不影响。算法对每个元素都取到了引理 1 的最小代价，并由引理 2 完整求和，所以返回的是每个查询的最少总操作次数。

边界情况

  • q 小于所有元素时，i = 0，左侧代价为 0，全部代价由右侧公式计算。
  • q 大于所有元素时，i = n，右侧代价为 0，全部代价由左侧公式计算。
  • 元素等于 q 时贡献为 0；使用 lower_bound 放在哪一侧都不会改变答案。
  • 答案最大可达约 1014；Java/C++ 必须使用 64 位整数。JavaScript 的安全整数范围足够覆盖本题上界。

复杂度

排序耗时 O(n log n)，建立前缀和耗时 O(n)；每个查询二分耗时 O(log n)，总时间为 O(n log n + m log n)。除排序与答案外，前缀和使用 O(n) 额外空间。

Java

long 防溢出
class Solution {
    public List<Long> minOperations(int[] nums, int[] queries) {
        Arrays.sort(nums);
        int n = nums.length;
        long[] prefix = new long[n + 1];
        for (int i = 0; i < n; i++) {
            prefix[i + 1] = prefix[i] + nums[i];
        }

        List<Long> answer = new ArrayList<>(queries.length);
        for (int q : queries) {
            int left = 0, right = n;
            while (left < right) {
                int mid = left + (right - left) / 2;
                if (nums[mid] < q) {
                    left = mid + 1;
                } else {
                    right = mid;
                }
            }

            int i = left;
            long lowerCost = (long) q * i - prefix[i];
            long upperCost = prefix[n] - prefix[i]
                    - (long) q * (n - i);
            answer.add(lowerCost + upperCost);
        }
        return answer;
    }
}

/**
 * @param {number[]} nums
 * @param {number[]} queries
 * @return {number[]}
 */
var minOperations = function(nums, queries) {
    nums.sort((a, b) => a - b);
    const n = nums.length;
    const prefix = new Array(n + 1).fill(0);

    for (let i = 0; i < n; i++) {
        prefix[i + 1] = prefix[i] + nums[i];
    }

    return queries.map(q => {
        let left = 0;
        let right = n;
        while (left < right) {
            const mid = left + Math.floor((right - left) / 2);
            if (nums[mid] < q) {
                left = mid + 1;
            } else {
                right = mid;
            }
        }

        const i = left;
        const lowerCost = q * i - prefix[i];
        const upperCost =
            prefix[n] - prefix[i] - q * (n - i);
        return lowerCost + upperCost;
    });
};

Python 3

bisect_left
from bisect import bisect_left
from itertools import accumulate
from typing import List


class Solution:
    def minOperations(
        self, nums: List[int], queries: List[int]
    ) -> List[int]:
        nums.sort()
        prefix = [0] + list(accumulate(nums))
        n = len(nums)
        answer = []

        for q in queries:
            i = bisect_left(nums, q)
            lower_cost = q * i - prefix[i]
            upper_cost = (
                prefix[n] - prefix[i] - q * (n - i)
            )
            answer.append(lower_cost + upper_cost)

        return answer

C++

long long
class Solution {
public:
    vector<long long> minOperations(
        vector<int>& nums,
        vector<int>& queries
    ) {
        sort(nums.begin(), nums.end());
        int n = nums.size();
        vector<long long> prefix(n + 1);

        for (int i = 0; i < n; ++i) {
            prefix[i + 1] = prefix[i] + nums[i];
        }

        vector<long long> answer;
        answer.reserve(queries.size());
        for (int q : queries) {
            int i = lower_bound(nums.begin(), nums.end(), q)
                    - nums.begin();
            long long lowerCost = 1LL * q * i - prefix[i];
            long long upperCost = prefix[n] - prefix[i]
                                - 1LL * q * (n - i);
            answer.push_back(lowerCost + upperCost);
        }
        return answer;
    }
};

替代方案与取舍

逐查询、逐元素计算

直接对每个 q 累加所有 |nums[j]-q|，实现最直观，但时间为 O(nm)；在 n,m = 105 时不可行。

离线排序查询 + 双指针

将查询连同原下标排序，可按目标值递增维护左右元素和，把查询部分降为 O(m log m + n)。总渐进复杂度仍受排序影响，实现却更绕；标准二分方案更适合作为首选。

动态数组场景

如果查询之间会插入、删除或修改 nums，静态前缀和不再适用。可以离散化后用两个树状数组分别维护元素个数与元素总和。

面试追问

1. 为什么必须排序？

排序让小于 q 和大于等于 q 的元素各自形成连续区间，才能二分分界点并用两个前缀和差式整段结算。

2. 可以用 upper_bound 吗？

可以。等于 q 的元素代价为 0，放在左侧或右侧都不影响总和；只要区间长度与区间和公式保持一致即可。

3. 如果只问一个查询，是否仍值得排序？

不一定。单个查询直接扫描是 O(n)，比排序的 O(n log n) 更简单；本题的优化价值来自查询数量可达 105。

4. 如何恢复每个元素具体执行了多少次操作？

第 j 个元素的次数就是 |nums[j]-q|，方向由它与 q 的大小关系决定。题目只要总数，因此无需存储操作序列。

常见错误

  • 误以为上一个查询会改变下一个查询的数组；题目明确每次查询后恢复原数组。
  • 只用中位数思路。中位数适用于“目标值可自由选择”，本题每个目标值由 queries[i] 指定。
  • 前缀和下标错一位。推荐约定 prefix[k] 表示前 k 个元素之和。
  • Java/C++ 使用 32 位整数保存前缀和或答案，导致溢出。
  • 二分得到位置后，左右区间元素个数写错：分别是 i 与 n-i。
