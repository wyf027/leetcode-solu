文件的最长绝对路径

把一段由换行与制表符编码的文件系统，读成清晰的层级关系。你的任务只有一个：找出抵达某个文件的最长路径长度。

Problem brief

先读懂这份“文本文件系统”

输入不是磁盘上的真实目录，而是用换行分隔条目、用行首制表符表达深度的一段字符串。

题意转述

给定字符串 input。每一行是一个目录名或文件名；行首每个 \t 表示它比根层多一层深度。文件名形如 name.extension，目录名不含点号。

一个文件的绝对路径由沿途目录和文件名通过 / 连接。返回所有文件绝对路径中的最大字符数；若系统中没有文件，则返回 0。

关键格式：换行 \n 切分条目，行首制表符 \t 决定深度。测试数据保证文件系统有效，名称长度均为正数。

函数签名

lengthLongestPath(input: string) → integer

约束

  • 1 ≤ input.length ≤ 10⁴
  • input 可含大小写英文字母、数字、空格、点号、换行符与制表符。
  • 所有文件名与目录名长度均为正数。
  • 文件名符合 name.extension；数据保证文件系统表示有效。

Official examples

完整示例

示例 1 · 单个文件
输入 
input = "dir\n\tsubdir1\n\tsubdir2\n\t\tfile.ext"
输出
20

唯一文件路径为 dir/subdir2/file.ext，长度为 20。

示例 2 · 多个分支
输入 
input = "dir\n\tsubdir1\n\t\tfile1.ext\n\t\tsubsubdir1\n\tsubdir2\n\t\tsubsubdir2\n\t\t\tfile2.ext"
输出
32

两条文件路径长度分别为 21 与 32，最长的是 dir/subdir2/subsubdir2/file2.ext。

示例 3 · 没有文件
输入
input = "a"
输出
0

只有一个名为 a 的目录，因此返回 0。

示例 4 · 根层文件
输入
input = "file1.txt\nfile2.txt\nlongfile.txt"
输出
12

根层文件的绝对路径就是文件名本身，最长的 longfile.txt 长度为 12。

      Prefix length · one pass

      用“深度 → 前缀长度”压缩整条路径

      无需真的拼接每一条绝对路径。扫描到某个深度时，只要知道它的父目录路径已有多长，就能在常数时间算出当前条目的完整路径长度。

      核心洞察

      令 prefix[d] 表示到达深度 d 条目之前，父目录路径（已包含末尾分隔符）的长度。若当前名称长度为 m：文件候选长度是 prefix[d] + m；目录则令 prefix[d+1] = prefix[d] + m + 1。

      完整过程

      1. 按 \n 切分输入。
      2. 数每行开头的 \t，得到深度并取出名称。
      3. 名称含点号时视为文件，用父前缀加名称长度更新答案。
      4. 否则视为目录，记录下一层的父前缀长度，并继续扫描。

      边界处理

      • 没有文件时答案从 0 开始并保持不变。
      • 根层文件深度为 0，父前缀恰为 0。
      • 回到较浅层时直接覆盖更深位置；旧值之后不会被错误读取。
      • 空格属于名称的一部分，长度必须计入。

      常见错误

      • 把输入中的字面字符 \\t 与真实制表符混为一谈。
      • 目录前缀漏掉路径分隔符 / 的 1 个字符。
      • 将最长目录路径也计入答案；题目只统计抵达文件的路径。
      • 重复拼接完整字符串，造成不必要的额外开销。

      正确性证明

      不变式：处理每一行前，对任意将被访问的深度 d，prefix[d] 等于当前行父目录绝对路径的长度，并且已经包含连接当前名称所需的末尾 /。

      根层的 prefix[0] = 0，不变式初始成立。若当前条目是目录，写入 prefix[d+1] = prefix[d] + name.length + 1，正好得到其子条目的父目录前缀；若当前条目是文件，prefix[d] + name.length 正好是其绝对路径长度。逐行扫描覆盖所有文件并取最大值，因此最终答案就是最长文件绝对路径长度。

      时间 O(n)空间 O(h) ≤ O(n)

      Java · LeetCode 可提交prefix length
      class Solution {
    public int lengthLongestPath(String input) {
        int[] prefix = new int[input.length() + 1];
        int answer = 0;

        for (String line : input.split("\\n", -1)) {
            int depth = 0;
            while (depth < line.length() && line.charAt(depth) == '\t') {
                depth++;
            }

            String name = line.substring(depth);
            if (name.indexOf('.') >= 0) {
                answer = Math.max(answer, prefix[depth] + name.length());
            } else {
                prefix[depth + 1] = prefix[depth] + name.length() + 1;
            }
        }

        return answer;
    }
}

      Python 3 · LeetCode 可提交prefix length
      class Solution:
    def lengthLongestPath(self, input: str) -> int:
        prefix = [0] * (len(input) + 1)
        answer = 0

        for line in input.split('\n'):
            depth = len(line) - len(line.lstrip('\t'))
            name = line[depth:]

            if '.' in name:
                answer = max(answer, prefix[depth] + len(name))
            else:
                prefix[depth + 1] = prefix[depth] + len(name) + 1

        return answer
      C++ · LeetCode 可提交prefix length
      class Solution {
public:
    int lengthLongestPath(string input) {
        vector<int> prefix(input.size() + 1, 0);
        int answer = 0;
        int start = 0;

        while (start <= static_cast<int>(input.size())) {
            int end = input.find('\n', start);
            if (end == static_cast<int>(string::npos)) {
                end = input.size();
            }

            int depth = 0;
            while (start + depth < end && input[start + depth] == '\t') {
                depth++;
            }

            int nameLength = end - start - depth;
            bool isFile = input.find('.', start + depth) < static_cast<size_t>(end);
            if (isFile) {
                answer = max(answer, prefix[depth] + nameLength);
            } else {
                prefix[depth + 1] = prefix[depth] + nameLength + 1;
            }

            if (end == static_cast<int>(input.size())) break;
            start = end + 1;
        }

        return answer;
    }
};

      替代方案

      可以维护目录名栈并在遇到文件时用 join('/') 构造路径；它更直观，但反复创建字符串。也可以维护“当前路径长度栈”，本质与前缀数组相同。若输入以字符流到达，还可逐字符扫描，在不先执行 split 的情况下保持 O(h) 辅助空间。

      面试追问

      为什么可以用点号判断文件？

      题目明确保证文件名为 name.extension，而目录名只含字母、数字和空格，因此这里点号就是可靠判据。若真实系统允许目录含点，需要额外元数据区分。

      空间复杂度能否更严格地写成 O(h)？

      可以。只需为当前可能的深度保存一个前缀长度，因此空间由树高 h 决定；最坏情况下 h 与输入长度同阶，所以也可写 O(n)。

      若输入非常大，怎样避免 split 产生额外字符串？

      用两个下标逐字符寻找行尾，同时统计制表符、名称长度和是否出现点号；每行结束时更新对应深度的前缀即可。

      为什么回到浅层后无需清空深层数据？

      有效输入中，新条目只会读取其父深度的值；当它重新进入某个更深层时，该层值会由刚处理的父目录覆盖，因此旧数据不会参与计算。
