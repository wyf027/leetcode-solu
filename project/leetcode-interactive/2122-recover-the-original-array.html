还原原数组

Recover the Original Array

两组数字被打乱，只留下同一段偏移的痕迹。你能找回它们原来的中心吗？

LeetCode 官方题目 ↗
01 / Problem

题目与约束

Alice 原有一个长度为 n、下标从 0 开始的正整数数组 arr。选定同一个正整数 k 后，对每个 0 ≤ i < n，生成：

lower[i] = arr[i] − k
higher[i] = arr[i] + k

两个数组中的全部元素混合成长度为 2n 的 nums，归属和原顺序都已丢失。请返回一个有效的原数组 arr；答案不唯一时，任意有效答案均可。输入保证至少存在一种解。

  • 2 * n == nums.length
  • 1 ≤ n ≤ 1000
  • 1 ≤ nums[i] ≤ 10⁹
  • k 必须是正整数，不能取 0；返回数组也由正整数组成。

函数参数：nums（整数数组）　返回：整数数组。重复元素需要保留各自的次数。

官方示例

示例 1 · 答案不唯一

输入：nums = [2,10,6,4,8,12]
输出：[3,7,11]

取 k = 1，lower = [2,6,10]，higher = [4,8,12]，混合后与 nums 的元素及次数一致。也可返回 [5,7,9]：取 k = 3 时，lower = [2,4,6]，higher = [8,10,12]。

示例 2 · 次数不能丢

输入：nums = [1,1,3,3]
输出：[2,2]

取 k = 1，lower = [1,1]，higher = [3,3]。[1,3] 不能作为答案，因为只有 k = 0 才能生成给定元素，而题目要求 k > 0。

示例 3 · 最小规模

输入：nums = [5,435]
输出：[220]

唯一的组合为 arr = [220]、k = 215，得到 lower = [5]、higher = [435]。

03 / Solution

固定间距，寻找每一对的中点

核心洞察

同一个原数生成的两端相差 d = 2k，因此 d 必须是正偶数。排序后最小数一定是某个 lower；它的 higher 一定在剩余元素中。所以只需枚举 nums[j] − nums[0]，无须遍历 k 的整个数值范围。

完整过程

  1. 将 nums 升序排序；枚举最小数与其余数的差值，跳过非正、奇数及重复差值。
  2. 为当前差值重新建立频次表，并清空答案。
  3. 从小到大扫描。若 x 已耗尽则跳过，否则将 x 作为剩余最小 lower；必须还有一个 x + d。
  4. 若找不到配对，丢弃本轮全部结果；否则各消耗一次，记录中点 x + d / 2。
  5. 收集到 n 个中点即可返回。题目保证有解，必有候选成功。

为什么一定正确？

1. 候选覆盖真实答案

设排序后的最小数为 m。若 m 是 higher，它的 lower = m − 2k 会更小，矛盾。因此它是 lower。真实 higher 必为某个 nums[j]，真实 d 必被枚举，且满足正偶数要求。

2. 固定 d 后，最小剩余元素的选择是强制的

假设剩余多重集合存在合法分解，最小元素 x 不可能是 higher，否则它所需的 x − d 也必须仍在集合中。故 x 只能与 x + d 配对。没有 x + d 就不存在该 d 的解；存在时，移除这两个元素保留一个合法的剩余问题。重复值的各个副本可以互换，频次足以表示状态。

3. 返回结果合法且必能找到

对每次移除应用上述结论，归纳可知固定真实 d 时不会误拒绝。成功轮次消耗恰好 2n 个元素，每个中点 a = x + d/2 为正整数，且 a − k = x、a + k = x + d。由此生成的两个数组与 nums 的多重集合一致；枚举覆盖真实 d，所以必能返回合法解。

复杂度

以原数组长度 n 计，输入长度为 2n。排序 O(n log n)，最多 O(n) 个候选，每次建表和扫描期望 O(n)，总时间期望 O(n²)，辅助空间 O(n)。哈希操作按期望 O(1) 分析；不声称对抗哈希下的最坏常数时间。展示代码原地排序 nums，若需保留入参，应先复制。

边界与常见错误

  • n = 1 也走同样流程；有效输入的唯一差值为正偶数。
  • 不能使用 Set 替代频次表；[1,1,3,3] 中每个副本都要消耗。
  • 不能接受 d = 0，也不能把奇数差值取整后当作 2k。
  • 候选失败后必须重新建立计数，不能沿用上一次消耗结果。
  • 不能只取第一个正偶数差值；实验室默认数据中 d = 2 会失败。
  • x + d 最大不到 2 × 10⁹，在 Java / C++ 有符号 32 位范围内；JavaScript Number 对本题整数精确。若扩大范围需采用更宽整数。
  • 答案可能不唯一，返回一个有效结果即可，不要求恢复原顺序。

替代方案

排序后，对每个候选用两个单调指针加 used 数组匹配 x 与 x + d，可做到确定性的 O(n²) 时间、O(n) 空间，但跳过已使用位置的处理更繁琐。用有序多重集合实现也直观，代价为 O(n² log n)。暴力枚举 k 到 10⁹ 则与数据数量脱钩，代价过高。

面试追问

  • 如何判定返回的另一种答案正确？寻找正整数 k，使两侧生成值的频次与 nums 完全一致，而不是仅比较示例数组。
  • 为什么遇到缺失配对不能尝试将当前最小数当 higher？它需要更小且仍未消耗的配偶，与最小性矛盾。
  • 若不保证有解呢？穷尽候选后返回约定的失败值；下面代码采用空数组。
  • 若允许 k = 0？需要额外处理 d = 0，且每个值的频次必须为偶数；当前实现明确排除它。

JavaScript

/**
 * @param {number[]} nums
 * @return {number[]}
 */
var recoverArray = function(nums) {
    nums.sort((a, b) => a - b);
    for (let j = 1; j < nums.length; j++) {
        const d = nums[j] - nums[0];
        if (d <= 0 || d % 2 || nums[j] === nums[j - 1]) continue;
        const count = new Map();
        for (const x of nums) count.set(x, (count.get(x) || 0) + 1);
        const ans = [];
        for (const x of nums) {
            if (!count.get(x)) continue;
            if (!count.get(x + d)) break;
            count.set(x, count.get(x) - 1);
            count.set(x + d, count.get(x + d) - 1);
            ans.push(x + d / 2);
        }
        if (ans.length * 2 === nums.length) return ans;
    }
    return [];
};

from collections import Counter
from typing import List

class Solution:
    def recoverArray(self, nums: List[int]) -> List[int]:
        nums.sort()
        for j in range(1, len(nums)):
            d = nums[j] - nums[0]
            if d <= 0 or d % 2 or nums[j] == nums[j - 1]:
                continue
            count = Counter(nums)
            ans = []
            for x in nums:
                if count[x] == 0:
                    continue
                if count[x + d] == 0:
                    break
                count[x] -= 1
                count[x + d] -= 1
                ans.append(x + d // 2)
            if len(ans) * 2 == len(nums):
                return ans
        return []

Java

import java.util.Arrays;
import java.util.HashMap;
import java.util.Map;

class Solution {
    public int[] recoverArray(int[] nums) {
        Arrays.sort(nums);
        int n = nums.length / 2;
        for (int j = 1; j < nums.length; j++) {
            int d = nums[j] - nums[0];
            if (d <= 0 || d % 2 != 0 || nums[j] == nums[j - 1]) continue;
            Map<Integer, Integer> count = new HashMap<>();
            for (int x : nums) count.put(x, count.getOrDefault(x, 0) + 1);
            int[] ans = new int[n];
            int size = 0;
            for (int x : nums) {
                if (count.get(x) == 0) continue;
                if (count.getOrDefault(x + d, 0) == 0) break;
                count.put(x, count.get(x) - 1);
                count.put(x + d, count.get(x + d) - 1);
                ans[size++] = x + d / 2;
            }
            if (size == n) return ans;
        }
        return new int[0];
    }
}

C++

#include <algorithm>
#include <unordered_map>
#include <vector>
using namespace std;

class Solution {
public:
    vector<int> recoverArray(vector<int>& nums) {
        sort(nums.begin(), nums.end());
        int m = static_cast<int>(nums.size());
        for (int j = 1; j < m; ++j) {
            int d = nums[j] - nums[0];
            if (d <= 0 || d % 2 || nums[j] == nums[j - 1]) continue;
            unordered_map<int, int> count;
            for (int x : nums) ++count[x];
            vector<int> ans;
            for (int x : nums) {
                if (count[x] == 0) continue;
                if (count[x + d] == 0) break;
                --count[x];
                --count[x + d];
                ans.push_back(x + d / 2);
            }
            if (static_cast<int>(ans.size()) * 2 == m) return ans;
        }
        return {};
    }
};
