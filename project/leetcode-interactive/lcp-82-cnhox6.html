LCP 82 · HARD · cnhox6

万灵之树

枚举完整二叉树与宝石排列会爆炸。正解以树重心把方案分成两块，用模逆元反解中间子树的编码值，再用 meet-in-the-middle 合并。

MECHANISM / 树形数字编码

把子树当成可拼接的模 p 片段

步骤 0：选择一个重心切分。

记录每一块的余数和十进制长度；连接 A、x、B 后可写成一元线性同余式。

拼接公式：num = 1 · 10^(len(A)+len(B)) + A · 10^len(B) + x · 10^len(B) + B
合并查询：由 target 和已知片段反解 x mod p，再查另一半的余数桶。

为什么是重心分治 + Meet-in-the-Middle？

完整二叉树

每个内部节点恰有两个孩子；DFS 记录首达的 1、叶子值和回退的 9，形成一个十进制编码。

可逆连接

模数 p 是素数。固定两侧片段后，连接结果对中间余数 x 是线性的，可用费马逆元反解。

避免重复

按重心位置与子树规模分类，确保每种有根有序树的组装方案只被统计一次。

关键状态

  • 子集掩码：哪些带编号宝石已被使用。
  • 余数：该子树 DFS 数字对 p 的模。
  • 长度：拼接时每块要乘的 10 的幂。
  • 形态类别：保证重心分割的唯一归属。

复杂度

n ≤ 9。利用重心使两侧规模受到控制，预处理子集树形片段后以哈希表匹配余数；这比卡特兰数乘 n! 的暴力枚举更可行。

验证状态

快速生成模式：UI、算法对拍、四语言编译和交互验收待补。

SOLUTION / 默认隐藏

分治合并的提交骨架

四个版本均以“生成受限片段 → 反解所需余数 → 哈希桶匹配 → 按重心类别去重”为同一主线。实现细节需要在完整验收阶段结合约束做对拍。
