Scene brief

题意

给定单链表头结点 head，将链表整体向右旋转 k 个位置，并返回旋转后的头结点。

官方样例 1

输入
head = [1,2,3,4,5], k = 2
输出
[4,5,1,2,3]

官方样例 2

输入
head = [0,1,2], k = 4
输出
[2,0,1]

节点数：0 <= n <= 500

节点值：-100 <= Node.val <= 100

旋转次数：0 <= k <= 2 × 10^9

Final cut notes

题解

Core insight

把线性链表暂时接成环，只需剪开一次

先遍历得到长度 n 和原尾结点，再令 tail.next = head 成环。有效旋转量是 k % n；从旧尾结点继续走 n - k % n 步，就到达新尾结点。

Invariant

节点顺序没有被复制或搬动

成环后所有原有 next 相对顺序保持不变，只新增“旧尾 → 旧头”一条连接。定位到新尾后，令 newHead = newTail.next，再把 newTail.next = null，即可恢复为合法单链表。

Full process

完整过程

  1. TAKE 01

    空链表、单结点或 k = 0 可直接返回。

  2. TAKE 02

    遍历到旧尾结点，同时统计链表长度 n。

  3. TAKE 03

    计算 shift = k % n，将旧尾接回旧头形成环。

  4. TAKE 04

    从旧尾走 n - shift 步到新尾，保存新头并断开。

Boundaries

边界情况

  • head = []：直接返回空链表。
  • 单结点：无论 k 多大，结果不变。
  • k % n = 0：旋转整圈，直接返回原头。
  • k 很大：必须先取模，不能真的旋转 k 次。

Complexity

复杂度

时间：O(n)，测量链表和定位新尾都至多走一圈。

空间：O(1)，只修改指针。

Alternatives

替代方案取舍

也可先算长度，再用快慢指针保持 shift 间距寻找新尾；无需显式成环，但分支和指针关系更难直观看清。把节点存入数组再重连虽容易实现，却需要 O(n) 额外空间。面试推荐成环后一次断开。

Interview follow-ups

面试追问

为什么从旧尾走 n - shift 步？

旧尾接到旧头后，从旧尾前进一步就是原索引 0。走 n - shift 步最终落在原索引 n - shift - 1，也就是旋转后最后一个结点。

如果链表原本可能有环怎么办？

本题保证输入是普通单链表。若不保证，应先用 Floyd 算法检测环并定义如何处理，否则测量长度会无限循环。

如何实现向左旋转 k 位？

左旋 k 等价于右旋 n - (k % n)；也可成环后从旧尾走 k 步确定新的尾结点。

Bad cuts

常见错误

  • 忘记 k %= n：大 k 会造成无意义循环甚至超时。
  • 偏移一位：混淆新头和新尾，应该先定位新尾，再取 newTail.next。
  • 忘记断环：返回的链表会永远循环。
  • 空链表先取模：在 n = 0 时执行 k % n 会除零。

class Solution {
    public ListNode rotateRight(ListNode head, int k) {
        if (head == null || head.next == null || k == 0) {
            return head;
        }

        int length = 1;
        ListNode tail = head;
        while (tail.next != null) {
            tail = tail.next;
            length++;
        }

        int shift = k % length;
        if (shift == 0) {
            return head;
        }

        tail.next = head;
        int steps = length - shift;
        while (steps-- > 0) {
            tail = tail.next;
        }

        ListNode newHead = tail.next;
        tail.next = null;
        return newHead;
    }
}
