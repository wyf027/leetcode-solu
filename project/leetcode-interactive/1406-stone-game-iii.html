石子游戏 III

一排带正负价值的石子，三个看似简单的选择，却会让每一步都牵动余下整局。先读规则，再亲手推演。

The game

题意

双方都足够聪明，因此一次局部高分不一定意味着最终获胜。

规则转述

Alice 与 Bob 面对一排石子，第 i 堆的价值为整数 stoneValue[i]。Alice 先手，双方轮流从当前队首拿走连续的 1、2 或 3 堆。

每人的分数等于自己拿到的石子价值总和，初始均为 0；石子取尽时结束。双方都采用最优策略。

Alice 分数更高返回 "Alice"，Bob 更高返回 "Bob"，相等返回 "Tie"。

你需要判断什么

  • 每回合只能从剩余队首取石子。
  • 可取数量只能是 1、2、3，且不能越过末尾。
  • 石子价值可为负数；“多拿”可能反而更糟。
  • 函数形式：stoneGameIII(stoneValue) → string

示例 1

输入：stoneValue = [1,2,3,7] 输出："Bob"

Alice 最好拿前三堆得到 6，Bob 随后拿到 7，Bob 获胜。

示例 2

输入：stoneValue = [1,2,3,-9] 输出："Alice"

Alice 应先拿前三堆，把负值石子留给 Bob；取一堆或两堆都会输。

示例 3

输入：stoneValue = [1,2,3,6] 输出："Tie"

Alice 拿前三堆可把最终结果维持为平局，其他选择会输。

Solution

净胜分动态规划

把“两个人各得多少分”压缩成“当前玩家最终能领先对手多少分”。

核心洞察

定义 dp[i]：面对从下标 i 开始的剩余石子时，当前行动者在双方最优的前提下，最终相对另一人的最大净胜分。

若当前拿走 k 堆、价值和为 take，轮到对手面对位置 i+k。对手能取得 dp[i+k] 的净胜分，所以当前选择的净胜分是：

take − dp[i + k]

枚举合法的 k ∈ {1,2,3} 并取最大值。边界 dp[n] = 0，计算顺序为从右到左。

完整过程

  1. 定义状态
    只记录当前玩家相对对手的最大分差，无须分别维护 Alice、Bob 总分。
  2. 从右向左枚举起点
    这样访问 dp[i+1..i+3] 时，后续局面已经求出。
  3. 尝试拿 1～3 堆
    边累加本回合得分，边计算 take - dp[i+k]，保留最大值。
  4. 解释起点符号
    dp[0] > 0 为 Alice，等于 0 为 Tie，小于 0 为 Bob。

正确性证明

基础情形：当 i=n 时没有石子，双方后续均得 0，所以 dp[n]=0 正确。

归纳假设：假设所有 j>i 的 dp[j] 都正确表示对应局面中当前玩家的最优净胜分。

归纳步骤：在位置 i，当前玩家只能拿 1～3 堆。选择 k 堆后，他本回合得到 take；余下局面对手最优可领先 dp[i+k]，从当前玩家视角必须减去它。因此该动作的最终净胜分恰为 take-dp[i+k]。取全部合法动作的最大值就是最优策略，故 dp[i] 正确。由逆向归纳，dp[0] 正确，返回值也正确。

复杂度

时间 O(n)
每个位置只尝试最多 3 个动作。

空间 O(n)
代码保留完整 dp，便于理解；也可滚动压缩为 O(1)。

边界清单

  • 只有一堆时，结果由该值与 0 比较。
  • 全部为负数时，仍要选“损失最小”的合法动作。
  • 末尾不足 3 堆时，不得越界。
  • 分差为 0 必须返回 "Tie"。
  • Java 用 int 足够：总绝对值不超过 5×10⁷。

替代方案

后缀和 + 当前最大总分：可定义当前玩家从后缀能拿到的最大总分，用后缀总和减去对手最优值转移；同样 O(n)。

极小化极大搜索：能表达博弈，但裸递归指数级；加记忆化后本质上仍是这里的 DP。

Implementations

四语言完整代码

均遵循官方函数签名，使用 O(n) 状态数组。

JavaO(n) / O(n)
class Solution {
    public String stoneGameIII(int[] stoneValue) {
        int n = stoneValue.length;
        int[] dp = new int[n + 1];

        for (int i = n - 1; i >= 0; i--) {
            int best = Integer.MIN_VALUE;
            int take = 0;
            for (int k = 1; k <= 3 && i + k <= n; k++) {
                take += stoneValue[i + k - 1];
                best = Math.max(best, take - dp[i + k]);
            }
            dp[i] = best;
        }

        if (dp[0] > 0) return "Alice";
        if (dp[0] < 0) return "Bob";
        return "Tie";
    }
}

from typing import List

class Solution:
    def stoneGameIII(self, stoneValue: List[int]) -> str:
        n = len(stoneValue)
        dp = [0] * (n + 1)

        for i in range(n - 1, -1, -1):
            best = float("-inf")
            take = 0
            for k in range(1, 4):
                if i + k > n:
                    break
                take += stoneValue[i + k - 1]
                best = max(best, take - dp[i + k])
            dp[i] = best

        if dp[0] > 0:
            return "Alice"
        if dp[0] < 0:
            return "Bob"
        return "Tie"

class Solution {
public:
    string stoneGameIII(vector<int>& stoneValue) {
        int n = static_cast<int>(stoneValue.size());
        vector<int> dp(n + 1, 0);

        return "Tie";
    }
};
Interview depth

追问与常见错误

面试追问

  • 如何把空间从 O(n) 压缩到 O(1)？只保留后面三个状态。
  • 如果每次可取 1～k 堆？转移不变，枚举上限改为 k，时间 O(nk)。
  • 为什么分差状态不需要知道当前是 Alice 还是 Bob？状态始终站在“当前行动者”视角，换手由减号完成。
  • 若要恢复完整最优拿取序列？额外记录每个 i 的最佳 k，再从 0 顺着跳转。

常见错误

  • 贪心拿眼前和最大的 1～3 堆，忽略给对手留下的局面。
  • 转移写成 take + dp[i+k]；换手后应减去对手优势。
  • 数组全负时把 best 初始化为 0，导致错误地允许“什么都不拿”。
  • 只比较 Alice 得分与总分一半，却没有正确处理负数与最优对抗。
  • 忘记单独处理 dp[0] == 0 的平局。
