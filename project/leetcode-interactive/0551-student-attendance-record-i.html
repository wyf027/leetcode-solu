学生出勤记录 I

沿着时间线逐日扫描：同时追踪累计缺勤次数与当前连续迟到长度，任一条件越界便立即判定不符合奖励资格。

EASYStudent Attendance Record I单次扫描非付费题

题目

给定字符串 s，其中每个字符表示学生某天的出勤情况：

AAbsent，缺勤
LLate，迟到
PPresent，到场

只有同时满足以下条件，学生才有资格获得出勤奖励：

  • 整个记录中缺勤总天数严格少于 2 天；
  • 从未出现连续 3 天或更多天迟到。

符合条件返回 true，否则返回 false。

参数与约束

函数：checkRecord(s)

参数：s: string

返回：boolean

  • 1 <= s.length <= 1000
  • s[i] 只可能是 'A'、'L' 或 'P'

官方示例

示例 1 输入：s = "PPALLP" 输出：true 解释：缺勤少于 2 次，并且没有连续 3 天或以上迟到。
示例 2 输入：s = "PPALLL" 输出：false 解释：最后 3 天连续迟到，因此不符合奖励条件。

题解：一次扫描，两个状态

核心洞察

奖励条件只依赖两个量：到目前为止的 缺勤总数，以及以当前位置结尾的 连续迟到长度。扫描字符时同步维护它们；一旦缺勤达到 2 次，或连续迟到达到 3 天，后续字符不可能让违规消失，可以立即返回 false。

关键区别：缺勤看的是全局累计，迟到看的是连续区间。遇到 P 或 A 时，连续迟到计数必须清零。

完整过程

  1. 初始化 absences = 0、lateStreak = 0。
  2. 从左到右读取字符。
  3. 若字符为 A，缺勤数加一；若达到 2，返回 false。
  4. 若字符为 L，连续迟到数加一；否则将连续迟到数清零。若达到 3，返回 false。
  5. 扫描结束仍未违规，返回 true。

正确性证明

  1. 缺勤条件：absences 在且仅在读到 A 时加一，因此处理任意前缀后，它恰好等于该前缀的缺勤总数。达到 2 即违反“严格少于 2”。
  2. 迟到条件：lateStreak 在读到 L 时递增，读到非 L 时清零，因此它始终等于当前前缀末尾的连续 L 数。达到 3 当且仅当出现至少三个连续迟到。
  3. 结论：算法发现任一违规便返回 false；若扫描结束未发现，则两个奖励条件都满足，返回 true 正确。

边界情况

  • 长度为 1：任何合法单字符记录都符合条件。
  • 恰好两个不相邻的 A：仍然不符合，因为缺勤按总数计算。
  • LL 合法，LLL 不合法；超过三个也会在第三个时提前结束。
  • LAL 的两个迟到段互不连续，遇到 A 后连续计数清零。

复杂度

时间复杂度 O(n)，最多扫描字符串一次；额外空间复杂度 O(1)。

替代方案

可以分别统计 A 的数量并检查是否包含子串 LLL，代码更短；也可以用正则表达式完成。面试中手写单次扫描更容易解释状态、不依赖语言特定 API，并自然支持提前返回。

四种语言完整代码

Java

class Solution {
    public boolean checkRecord(String s) {
        int absences = 0;
        int lateStreak = 0;

        for (char c : s.toCharArray()) {
            if (c == 'A' && ++absences >= 2) {
                return false;
            }
            if (c == 'L') {
                if (++lateStreak >= 3) return false;
            } else {
                lateStreak = 0;
            }
        }
        return true;
    }
}

面试追问

  • 如果奖励规则变为“最多 K 次缺勤、最多连续 M 次迟到”，如何参数化计数器？
  • 如果字符来自数据流、无法一次获得完整字符串，算法是否仍可工作？（可以，状态是常数空间。）
  • 若要求统计所有违规区间，而不是首次违规就返回，应如何改造？
  • 本题与“学生出勤记录 II”的计数动态规划有何区别？

常见错误

  • 把“少于 2 次缺勤”误写为“少于等于 2 次”。
  • 把所有 L 的总数当成条件，而不是检查连续 L。
  • 只在遇到 P 时清零迟到段，却忘了 A 也会中断连续迟到。
  • 发现第二个 A 或第三个连续 L 后仍继续扫描，虽然结果不变但错过提前结束。
