大礼包Shopping Offers

单价、大礼包和一张不能多买的购物清单同时出现时，目标不是买得多，而是用最低价格恰好满足每一种需求。

题意 交互演示 四语言代码

Order schema

单价price[i]
礼包内容special[k][0..n-1]
礼包价格special[k][n]
目标数量needs[i]
返回最低总价

Problem brief

先看清购物规则

有 n 种物品。每种物品既可以按单价购买，也可能包含在某些大礼包中；同一礼包可以购买任意多次。

1

三组输入

price 给出各物品单价，special 的每一行给出各物品数量与礼包价，needs 给出目标数量。

2

必须恰好满足

每一种物品最终购买量都必须与清单一致。即使某个超量礼包看起来更便宜，也不能购买。

3

求最低花费

可以混合使用单买和任意次数的礼包，返回恰好完成购物清单需要支付的最低价格。

Official examples

官方示例

输入保留完整的 price、special 与 needs 参数形式。

示例 1

输入：price = [2,5] special = [[3,0,5],[1,2,10]] needs = [3,2] 输出：14

说明：花 10 购买礼包 [1,2]，再花 4 单买 2 个 A，恰好得到 3A、2B。

示例 2

输入：price = [2,3,4] special = [[1,1,0,4],[2,2,1,9]] needs = [1,2,1] 输出：11

说明：花 4 购买 1A、1B 礼包，再单买 1B 和 1C。价格为 9 的第二个礼包会多买 A，因此不可用。

约束

  • n == price.length == needs.length
  • 1 <= n <= 6
  • 0 <= price[i], needs[i] <= 10
  • 1 <= special.length <= 100
  • special[i].length == n + 1
  • 0 <= special[i][j] <= 50
  • 每个礼包在前 n 个位置中至少有一个非零数量。

Solution

记忆化搜索：把剩余清单当作状态

真正需要记录的不是“买过哪些礼包”，而是“每种物品还差多少”。只要剩余清单相同，后续最低花费就相同。

状态 dfs(state) 表示恰好补齐剩余需求 state 的最低花费。
保底答案 把剩余物品全部按单价买下，得到当前状态一定可行的上界。
状态转移 对每个不导致超买的礼包，尝试“礼包价 + 新剩余状态的最低花费”。

完整过程

  1. 预处理礼包。去掉包含数量超过初始需求的礼包；若礼包价不低于其中物品逐件购买的价格，也可以安全去掉，因为单买永远不差。
  2. 定义搜索状态。用长度为 n 的剩余需求数组作为状态，并为它生成稳定的记忆化键。
  3. 计算保底费用。对每一项计算 state[i] × price[i] 并求和。
  4. 尝试每个可用礼包。若礼包的所有商品数量都不超过当前剩余需求，就逐项相减得到下一状态。
  5. 取最小值并缓存。比较保底费用与所有礼包分支，将最小值记入缓存后返回。

正确性证明

命题：对任意剩余需求状态 s，算法返回恰好满足 s 的最低花费。

证明：任一合法购买方案的第一次选择只有两类：不再使用礼包、把所有剩余物品单买；或先使用某个不会超量的礼包，再完成相减后的剩余状态。算法显式考虑了第一类方案，并枚举了第二类方案中的每个合法礼包。礼包至少含一件物品，因此相减后的物品总需求严格变小。根据对剩余物品总数的归纳假设，递归值是下一状态的最低花费；加上当前礼包价便是以该礼包开头的最优费用。算法在这些互斥且完备的选择中取最小值，所以得到状态 s 的全局最低花费。初始状态即 needs，结论成立。

边界与复杂度

边界处理

  • 需求全为 0 时，保底费用为 0，所有非空礼包都不可应用。
  • 某些单价为 0 时，非优惠礼包会在预处理阶段被去掉。
  • 礼包可无限次使用，但每次都会严格减少至少一种剩余需求，因此搜索不会形成环。
  • 任何导致某项剩余需求为负数的礼包都必须跳过。

复杂度

令 S = ∏(needs[i] + 1) 为可能状态数，m 为保留的礼包数。每个状态最多检查 m 个礼包，每次检查与构造新状态需要 O(n)。

时间：O(S × m × n)
空间：O(S × n)（缓存键与递归栈的保守计法）。

import java.util.*;

class Solution {
    private List<Integer> price;
    private List<List<Integer>> offers;
    private Map<List<Integer>, Integer> memo;

    public int shoppingOffers(List<Integer> price,
                              List<List<Integer>> special,
                              List<Integer> needs) {
        this.price = price;
        this.offers = new ArrayList<>();
        this.memo = new HashMap<>();
        int n = price.size();

        for (List<Integer> offer : special) {
            int regularCost = 0;
            boolean withinInitialNeeds = true;
            for (int i = 0; i < n; i++) {
                regularCost += offer.get(i) * price.get(i);
                if (offer.get(i) > needs.get(i)) {
                    withinInitialNeeds = false;
                }
            }
            if (withinInitialNeeds && offer.get(n) < regularCost) {
                offers.add(offer);
            }
        }
        return dfs(needs);
    }

    private int dfs(List<Integer> state) {
        Integer cached = memo.get(state);
        if (cached != null) return cached;

        int n = price.size();
        int best = 0;
        for (int i = 0; i < n; i++) {
            best += state.get(i) * price.get(i);
        }

        for (List<Integer> offer : offers) {
            List<Integer> next = new ArrayList<>(n);
            boolean valid = true;
            for (int i = 0; i < n; i++) {
                if (offer.get(i) > state.get(i)) {
                    valid = false;
                    break;
                }
                next.add(state.get(i) - offer.get(i));
            }
            if (valid) {
                best = Math.min(best, offer.get(n) + dfs(next));
            }
        }

        memo.put(new ArrayList<>(state), best);
        return best;
    }
}

 * @param {number[]} needs

var shoppingOffers = function(price, special, needs) {
    const n = price.length;
    const offers = special.filter((offer) => {
        let regularCost = 0;
        for (let i = 0; i < n; i++) {
            if (offer[i] > needs[i]) return false;
            regularCost += offer[i] * price[i];
        }
        return offer[n] < regularCost;
    });

    const memo = new Map();

    const dfs = (state) => {
        const key = state.join(",");
        if (memo.has(key)) return memo.get(key);

        let best = 0;
        for (let i = 0; i < n; i++) {
            best += state[i] * price[i];
        }

        for (const offer of offers) {
            const next = new Array(n);
            let valid = true;
            for (let i = 0; i < n; i++) {
                if (offer[i] > state[i]) {
                    valid = false;
                    break;
                }
                next[i] = state[i] - offer[i];
            }
            if (valid) {
                best = Math.min(best, offer[n] + dfs(next));
            }
        }

        memo.set(key, best);
        return best;
    };

    return dfs(needs);
};
from functools import lru_cache
from typing import List


class Solution:
    def shoppingOffers(
        self,
        price: List[int],
        special: List[List[int]],
        needs: List[int]
    ) -> int:
        n = len(price)
        offers = []

        for offer in special:
            within_initial_needs = all(
                offer[i] <= needs[i] for i in range(n)
            )
            regular_cost = sum(
                offer[i] * price[i] for i in range(n)
            )
            if within_initial_needs and offer[n] < regular_cost:
                offers.append(offer)

        @lru_cache(None)
        def dfs(state: tuple[int, ...]) -> int:
            best = sum(state[i] * price[i] for i in range(n))

            for offer in offers:
                if all(offer[i] <= state[i] for i in range(n)):
                    next_state = tuple(
                        state[i] - offer[i] for i in range(n)
                    )
                    best = min(best, offer[n] + dfs(next_state))

            return best

        return dfs(tuple(needs))
#include <algorithm>
#include <map>
#include <vector>
using namespace std;

class Solution {
private:
    vector<int> price;
    vector<vector<int>> offers;
    map<vector<int>, int> memo;

    int dfs(const vector<int>& state) {
        auto found = memo.find(state);
        if (found != memo.end()) return found->second;

        int n = static_cast<int>(price.size());
        int best = 0;
        for (int i = 0; i < n; ++i) {
            best += state[i] * price[i];
        }

        for (const vector<int>& offer : offers) {
            vector<int> next(n);
            bool valid = true;
            for (int i = 0; i < n; ++i) {
                if (offer[i] > state[i]) {
                    valid = false;
                    break;
                }
                next[i] = state[i] - offer[i];
            }
            if (valid) {
                best = min(best, offer[n] + dfs(next));
            }
        }

        memo[state] = best;
        return best;
    }

public:
    int shoppingOffers(vector<int>& price,
                       vector<vector<int>>& special,
                       vector<int>& needs) {
        this->price = price;
        int n = static_cast<int>(price.size());

        for (const vector<int>& offer : special) {
            int regularCost = 0;
            bool withinInitialNeeds = true;
            for (int i = 0; i < n; ++i) {
                regularCost += offer[i] * price[i];
                if (offer[i] > needs[i]) withinInitialNeeds = false;
            }
            if (withinInitialNeeds && offer[n] < regularCost) {
                offers.push_back(offer);
            }
        }

        return dfs(needs);
    }
};

替代方案

  • 自底向上状态 DP：按混合进制编码所有需求状态并迭代转移，避免递归，但实现更繁琐，也可能遍历大量不可达状态。
  • 纯回溯：逻辑直接，却会反复计算同一剩余清单；缺少记忆化时容易指数级重复。
  • 位掩码/整数编码：因每项需求不超过 10，可用固定进制把状态压成一个整数，键更紧凑，但可读性稍差。

常见错误

  • 允许礼包把某一项需求减成负数，违反“不能多买”。
  • 只枚举礼包，忘记“剩余部分按单价购买”这个必需的保底方案。
  • 直接修改共享的需求数组，回溯后没有恢复，污染其他分支。
  • 记忆化键拼接不带分隔符，使 [1,10] 与 [11,0] 之类状态混淆。
  • 把礼包当作只能使用一次，而题目允许无限次使用。

面试追问

如果每个礼包有购买次数上限？

状态还需加入各礼包剩余次数，或按礼包顺序做带上限的背包式 DP；状态维度和复杂度都会增大。

如果需要输出具体购买方案？

在更新最优值时同时记录当前状态选择了哪个礼包；从初始状态沿决策指针回放，剩余部分即按单价购买。

为什么能去掉不便宜的礼包？

礼包中的每件物品都可以按单价单买。若礼包价不低于逐件单买价，用单买替换它不会超量且费用不增加。

需求值非常大时怎么办？

完整状态空间会过大，需要利用礼包结构做整数规划、分支定界或问题特定的降维；当前约束下的状态 DP 不再合适。
