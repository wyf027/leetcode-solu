Randomized selection

随机数索引Random Pick Index

当同一个数字出现在多个位置时，返回哪一个都可以——但每一个有效索引都必须拥有完全相同的机会。

Problem

题目描述

给定一个可能包含重复元素的整数数组 nums。请设计一个对象，使它能针对给定的 target，随机返回一个满足 nums[i] == target 的索引 i。题目保证每次查询的目标值都存在于数组中。

如果目标值对应多个索引，这些索引被返回的概率必须相等。

Solution(int[] nums)：使用数组 nums 初始化对象。
int pick(int target)：等概率返回一个值为 target 的索引。

官方示例

随机调用可能得到不同的合法索引，下面的输出只是其中一次可能结果。

输入 
["Solution", "pick", "pick", "pick"]
[[[1, 2, 3, 3, 3]], [3], [1], [3]]
输出（一次可能结果） 
[null, 4, 0, 2]
解释 
Solution solution = new Solution([1, 2, 3, 3, 3]);
solution.pick(3); // 随机返回 2、3、4 之一，各自概率为 1/3
solution.pick(1); // 只有索引 0 合法，因此返回 0
solution.pick(3); // 再次随机返回 2、3、4 之一，各自概率为 1/3

约束

  • 1 <= nums.length <= 2 * 104
  • -231 <= nums[i] <= 231 - 1
  • target 一定是 nums 中的整数
  • 最多调用 pick 104 次

真正的要求

返回值不是固定答案。评判重点是：所有合法索引都有机会被选中，且长期来看频率趋于均匀。

Deep dive

题解：水塘抽样

目标是在不知道匹配项总数的扫描过程中，只用常数额外空间，最终让每个匹配索引等概率留下。

核心洞察

扫描数组并维护 count（目前遇到的目标值个数）和 answer（当前保留索引）。遇到第 count 个匹配项时，以 1 / count 的概率用它替换答案。

第 k 个匹配项到来时：随机取 [0, k)；仅当结果为 0 时替换

非目标元素直接跳过。扫描完成后，answer 就是一次合法且均匀的随机选择。

完整过程

  1. 构造对象时保存数组引用（或数组本身）。
  2. 每次调用 pick(target)，令 count = 0、answer = -1。
  3. 从左到右扫描数组；若当前值不是 target，继续。
  4. 若匹配，先将 count 加一，再在 [0, count) 中均匀取整数。
  5. 随机数为 0 时，将当前索引写入 answer。
  6. 扫描结束后返回 answer。题目保证目标存在，因此最终不会返回 -1。

正确性证明

设某个目标值一共出现 m 次，考虑第 j 个匹配索引：

它被选中：到来时被替换进答案的概率是 1 / j。
它未被后来替换：从第 j+1 个到第 m 个匹配项，它每次保留的概率依次是 j/(j+1), (j+1)/(j+2), …, (m-1)/m。
连乘消去：(1/j) × (j/(j+1)) × … × ((m-1)/m) = 1/m。

所以任意一个匹配索引最终留下的概率都是 1/m，算法满足等概率要求。

复杂度与边界

  • 初始化：O(1)（保存数组引用）。
  • 每次 pick：时间 O(n)，额外空间 O(1)。
  • 唯一匹配：首次命中以概率 1 被选中，必然正确。
  • 全部匹配：算法退化为从整个数组中均匀选一个索引，仍然正确。
  • 整数边界：只做相等判断，不对数组值进行算术运算。

替代方案：预处理哈希表

初始化时建立 值 → 所有索引 的映射，查询时直接在对应索引列表里随机选一个。

  • 初始化时间和额外空间均为 O(n)。
  • 每次查询为 O(1)。
  • 数组固定且查询非常多时，这通常更快；强调常数空间或数据以流形式到达时，水塘抽样更合适。

常见错误

  • 总是返回第一个或最后一个匹配索引，完全没有随机性。
  • 对第 k 个匹配项使用固定概率，而不是 1/k。
  • 把数组下标数量当作匹配数量，导致概率受非目标元素影响。
  • 使用取模作用于有偏随机源，却没有考虑均匀性。
  • 每次查询都收集所有匹配索引，虽然正确，但额外空间变成 O(n)。

Implementations

四种语言完整代码

四份实现都使用同一套水塘抽样机制，并遵循官方构造器与 pick 方法签名。

import java.util.Random;

class Solution {
    private final int[] nums;
    private final Random random;

    public Solution(int[] nums) {
        this.nums = nums;
        this.random = new Random();
    }

    public int pick(int target) {
        int answer = -1;
        int count = 0;

        for (int i = 0; i < nums.length; i++) {
            if (nums[i] != target) {
                continue;
            }

            count++;
            if (random.nextInt(count) == 0) {
                answer = i;
            }
        }

        return answer;
    }
}

from typing import List
import random


class Solution:
    def __init__(self, nums: List[int]):
        self.nums = nums

    def pick(self, target: int) -> int:
        answer = -1
        count = 0

        for index, value in enumerate(self.nums):
            if value != target:
                continue

            count += 1
            if random.randrange(count) == 0:
                answer = index

        return answer

class Solution {

    Solution(vector<int>& nums)
        : nums(nums), generator(random_device{}()) {}

    int pick(int target) {
        int answer = -1;
        int count = 0;

        for (int i = 0; i < static_cast<int>(nums.size()); i++) {
            if (nums[i] != target) {
                continue;
            }

            count++;
            uniform_int_distribution<int> distribution(1, count);
            if (distribution(generator) == 1) {
                answer = i;
            }
        }

        return answer;
    }
};

面试追问

  • 如果数组可以预处理？讨论哈希表方案的时空权衡。
  • 如果输入是一条无限流？水塘抽样仍能工作，因为不需要提前知道匹配总数。
  • 如何选 k 个样本？把大小为 1 的水塘扩展为大小为 k 的水塘。
  • 如何验证随机性？大量独立调用后做频数统计或卡方检验，但统计验证不能替代概率证明。
  • 线程安全吗？数组不可变时读取安全；随机数生成器的共享与并发语义需按语言和运行环境处理。

一句话记忆

“第 k 个候选，以 1/k 的概率上位。”

这个局部规则看似偏爱后来者，但每个候选还要承受后续替换；概率连乘后，所有人最终恰好都是 1/m。
