01 · Problem

先把“下一个”说清楚

这里的下一个不是相邻位置，而是从当前位置向右、按循环顺序遇到的第一个严格更大的数字。

题目描述

给定循环整数数组 nums，数组末尾的下一个位置会回到开头。请返回一个等长数组，其中第 i 项是从 nums[i] 之后开始、沿循环遍历方向遇到的第一个严格大于 nums[i] 的值；如果不存在，返回 -1。

关键词：“第一个”限定遍历顺序，“更大”要求严格大于，且每个位置最多绕数组一圈。
nextGreaterElements(nums: integer[]): integer[]
示例 1发生回绕
输入：nums = [1,2,1]
输出：[2,-1,2]

前一个 1 向右遇到 2；2 没有更大值；末尾的 1 回到数组开头后遇到 2。

示例 2完整参数形式
输入：nums = [1,2,3,4,3]
输出：[2,3,4,-1,4]

约束

  • 1 <= nums.length <= 104
  • -109 <= nums[i] <= 109
  • 答案与输入数组长度相同。

读题检查

  • 相等的数字不是“更大元素”。
  • 可以从末尾回到开头继续找。
  • 找不到时必须保留 -1。

04 · Solution

题解：两圈扫描 + 单调栈

把“每个位置向后寻找”换个方向：当一个更大的新值到来时，一次解决所有仍在等待且比它小的位置。

  1. 核心洞察

核心洞察

栈里不保存“已经找到答案的人”，只保存“还在等待第一个更大值的位置”。新值一旦更大，就从栈顶连续结算。

从左到右扫描时，让栈中对应的数值保持单调不增。遇到 nums[i]，只要它严格大于栈顶位置的值，栈顶的下一个更大元素就必然是它。为了模拟循环，将索引扫描到 2n - 1，每次使用 i % n 访问原数组；但只在第一圈把索引入栈。

完整过程

  1. 创建长度为 n 的答案数组并填充 -1；创建一个存索引的空栈。
  2. 令 i 从 0 走到 2n - 1，当前原数组索引为 j = i % n。
  3. 当栈非空且 nums[stack.top] < nums[j] 时，弹出位置 k，写入 answer[k] = nums[j]。
  4. 仅当 i < n 时把 j 入栈，避免第二圈重复保存同一个位置。
  5. 两圈结束后，仍在栈中的位置不存在更大元素，答案保持 -1。

正确性证明

1

栈内位置都尚未遇到更大值

一个位置只会在遇到严格更大的当前值时弹出；因此，仍在栈里的位置在已扫描区间内没有更大元素。

2

弹出时得到的一定是“第一个”更大值

扫描遵循原数组向右的循环顺序。若更早出现过更大值，该位置早已被弹出，与它此刻仍在栈中矛盾。所以当前值就是遍历顺序中的第一个更大值。

3

两圈覆盖所有合法候选

任一位置向后最多查看其余 n - 1 个位置；从第一圈进入栈到第二圈走完，所有这些候选都已按序出现。仍未弹出说明不存在严格更大值，保留 -1 正确。

结论：算法为每个位置返回其循环遍历中的第一个严格更大元素，不存在时返回 -1。

边界与复杂度

  • 单个元素：第二圈遇到的是它自己，不严格更大，答案为 [-1]。
  • 全部相等：比较必须使用 <，任何位置都不会被相等值结算。
  • 严格递增：除最大值外都在第一圈得到答案，最大值保留 -1。
  • 负数：算法只依赖大小比较，不依赖数值正负。
时间复杂度O(n)每个索引至多入栈、出栈各一次。
额外空间O(n)答案之外，栈最坏保存 n 个索引。

import java.util.ArrayDeque;
import java.util.Arrays;
import java.util.Deque;

class Solution {
    public int[] nextGreaterElements(int[] nums) {
        int n = nums.length;
        int[] answer = new int[n];
        Arrays.fill(answer, -1);
        Deque<Integer> stack = new ArrayDeque<>();

        for (int i = 0; i < 2 * n; i++) {
            int index = i % n;
            while (!stack.isEmpty()
                    && nums[stack.peek()] < nums[index]) {
                answer[stack.pop()] = nums[index];
            }
            if (i < n) {
                stack.push(index);
            }
        }
        return answer;
    }
}

var nextGreaterElements = function(nums) {

    const answer = new Array(n).fill(-1);

    for (let i = 0; i < 2 * n; i++) {

from typing import List


class Solution:
    def nextGreaterElements(self, nums: List[int]) -> List[int]:
        n = len(nums)
        answer = [-1] * n
        stack: List[int] = []

        for i in range(2 * n):
            index = i % n
            while stack and nums[stack[-1]] < nums[index]:
                answer[stack.pop()] = nums[index]
            if i < n:
                stack.append(index)

        return answer
#include <vector>
using namespace std;

class Solution {
public:
    vector<int> nextGreaterElements(vector<int>& nums) {
        const int n = static_cast<int>(nums.size());
        vector<int> answer(n, -1);
        vector<int> stack;

        for (int i = 0; i < 2 * n; ++i) {
            const int index = i % n;
            while (!stack.empty()
                    && nums[stack.back()] < nums[index]) {
                answer[stack.back()] = nums[index];
                stack.pop_back();
            }
            if (i < n) {
                stack.push_back(index);
            }
        }
        return answer;
    }
};

替代方案

单调栈 · 推荐

一次处理一批等待位置，时间 O(n)，最符合数据规模。

逐位置向后扫描

实现直观，但最坏每个位置都绕一圈，总时间 O(n²)，在 n = 10⁴ 时不理想。

面试追问

  • 为什么第二圈不再入栈？同一位置只需要一个答案；重复入栈会制造冗余状态，并破坏“每个索引只入栈一次”的复杂度证明。
  • 能否从右向左做？可以。倒序扫描两遍，维护候选值的单调栈；不过保存索引的正向写法更容易直接写答案。
  • 如何返回下一个更大元素的距离？栈仍保存索引，弹出时写入 (i - oldIndex) % n，并避免把自身当成候选。
  • 如果题目改成下一个更大或相等？将弹栈条件从严格 < 改为 <=，同时重新确认“自己”是否允许成为答案。

常见错误

  • 只扫描一圈，导致末尾元素无法利用数组开头的候选值。
  • 把数值而不是索引压栈，失去向答案数组精确回填的位置。
  • 使用 <= 弹栈，把相等元素错误地当成更大元素。
  • 第二圈继续入栈，使索引重复并增加不必要的处理。
  • 先复制一份双倍数组；虽然可行，却多占一份 O(n) 空间，取模即可避免。
