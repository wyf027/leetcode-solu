字母组合迭代器Iterator for Combination

设计一个只会向前走的组合游标：它每次给出固定长度的下一个组合，顺序必须严格遵循字典序。

题号 1286中等非会员题回溯 / 迭代器
Interface contract

                    combinationLength)
next() -> string
hasNext() -> boolean
  • 输入字符已升序排列且互不相同

01 · Problem

题目要求

给定一个由有序、互不相同的小写字母组成的字符串，以及组合长度，实现下面三个接口。

接口语义

  • constructorCombinationIterator(string characters, int combinationLength)：使用字符集与固定组合长度初始化迭代器。
  • next()返回长度为 combinationLength 的下一个组合，所有返回值整体遵循字典序。
  • hasNext()当且仅当仍有下一个组合可返回时，返回 true。

约束

  • 1 <= combinationLength <= characters.length <= 15
  • characters 只含互不相同的小写英文字母，并已按升序排列。
  • next 与 hasNext 合计最多调用 104 次。
  • 每次调用 next() 时都保证存在下一个组合。

官方示例 1

输入
["CombinationIterator", "next", "hasNext", "next", "hasNext", "next", "hasNext"]
[["abc", 2], [], [], [], [], [], []]

输出
[null, "ab", true, "ac", true, "bc", false]

解释
CombinationIterator iterator = new CombinationIterator("abc", 2);
iterator.next();    // "ab"
iterator.hasNext(); // true
iterator.next();    // "ac"
iterator.hasNext(); // true
iterator.next();    // "bc"
iterator.hasNext(); // false

04 · Solution

把索引当成“组合里程表”

不必预先保存所有字符串。只保存当前组合的 k 个递增索引，每次返回当前值，再把索引推进到紧邻的下一个合法状态。

核心洞察

如果选择索引 indices = [i₀, i₁, ..., iₖ₋₁]，它们必须严格递增。第 p 位能够达到的最大值是 n - k + p。从右向左找到第一个尚未到上限的位置，把它加一，再把右侧恢复成连续的最小值，就得到字典序的直接后继。

例："abcd", k = 2[0,3] 对应 ad。末位已到上限 3，向左找到位置 0；令它从 0 变成 1，并把后缀设为 2，得到 [1,2]，即 bc。

完整过程

  1. 初始化索引为 [0, 1, ..., k-1]，并标记仍有可返回组合。
  2. next() 先按当前索引拼出答案。
  3. 从右向左寻找满足 indices[p] < n-k+p 的位置 p。
  4. 若不存在该位置，当前答案就是最后一个组合；否则令该位加一，并依次重置其右侧。
  5. hasNext() 直接返回可用标记，不改变状态。

正确性说明

不变式：每次调用 next() 前，索引严格递增，且指向尚未返回的最小字典序组合。

保持：选择最右侧仍可增加的位置，使尽可能长的前缀不变；该位只增加 1，再把后缀放到允许的最小连续值。因此新状态合法，且不存在夹在二者之间的合法组合。

终止：当所有位置都达到各自上限时，当前状态是唯一的最大组合。返回它后标记耗尽。于是每个组合恰好返回一次，顺序严格递增。

边界与复杂度

  • k = 1：索引像普通字符指针一样移动。
  • k = n：只存在一个组合，第一次返回后立即耗尽。
  • 最后一个组合是字符集末尾的连续 k 个字符。
  • 题目保证不会在耗尽后调用 next()。
初始化O(k)
nextO(k)
额外空间O(k)

由于返回长度为 k 的字符串本身就需要 Ω(k) 时间，next() 的复杂度在渐进意义上已经最优；hasNext() 为 O(1)。

替代方案

预生成全部组合：用回溯或位掩码生成所有 C(n,k) 个组合并排序，之后用数组下标迭代。实现直观，next() 可视为 O(1) 取引用（返回字符串仍涉及长度），但会使用 O(C(n,k)·k) 空间。本题 n ≤ 15 时能够通过，不过在线推进更贴合迭代器语义，也避免一次性物化全部结果。

四语言完整代码

class CombinationIterator {
    private final String characters;
    private final int[] indices;
    private boolean available = true;

    public CombinationIterator(String characters, int combinationLength) {
        this.characters = characters;
        this.indices = new int[combinationLength];
        for (int i = 0; i < combinationLength; i++) {
            indices[i] = i;
        }
    }

    public String next() {
        StringBuilder answer = new StringBuilder(indices.length);
        for (int index : indices) {
            answer.append(characters.charAt(index));
        }

        int n = characters.length();
        int k = indices.length;
        int pivot = k - 1;
        while (pivot >= 0 && indices[pivot] == n - k + pivot) {
            pivot--;
        }
        if (pivot < 0) {
            available = false;
        } else {
            indices[pivot]++;
            for (int i = pivot + 1; i < k; i++) {
                indices[i] = indices[i - 1] + 1;
            }
        }
        return answer.toString();
    }

    public boolean hasNext() {
        return available;
    }
}

常见错误

  • 把某一位增加后，没有把右侧重置为连续索引，导致跳过组合或产生重复。
  • 使用所有位置相同的上限；正确上限依赖位置，是 n-k+p。
  • hasNext() 意外推进游标，造成“查询”改变结果。
  • 返回最后一个组合前就把可用标记清除，使最后一次合法调用丢失。
  • 位掩码按整数递增生成后直接输出，却误以为天然符合字符组合的字典序。

面试追问

为什么要从右向左寻找 pivot？

字典序直接后继应尽量保留更长的前缀。从最右边开始，找到可增加的最靠右位置，正好满足这一点。

能把 next() 做到严格 O(1) 吗？

若返回完整字符串，写出 k 个字符本身需要 Ω(k)。可以把索引推进的摊还代价讨论得更细，但整体返回代价仍是 O(k)。

若输入字符未排序或有重复怎么办？

这超出题目约束。工程接口可在构造时校验；若允许规范化，则需明确排序、去重是否会改变调用者语义。

若要支持 previous() 呢？

可对称地寻找最右侧能够减小的位置，减一后把右侧设成尽可能大的合法连续尾部；也可以保存历史状态，换取更直接的实现。
