你可以安排的
最多任务数目

Maximum Number of Tasks You Can Assign

有限的工人，有限的药丸。每一次力量提升，应该留给谁？

01 / Problem

任务规则

数组 tasks 中每个数表示一项任务需要的力量；数组 workers 中每个数表示一名工人的力量。只有工人的最终力量不小于任务要求时，才能分配该任务。每名工人最多完成一项任务，每项任务最多分配一次。

你有 pills 片药丸，每片可让一名工人的力量增加 strength。每名工人至多吃一片，也可以不吃。返回能够完成的任务数量的最大值，无须返回具体分配方案。

maxTaskAssign(tasks, workers, pills, strength) → integer

约束

  • n == tasks.length，m == workers.length
  • 1 ≤ n, m ≤ 5 × 10⁴
  • 0 ≤ pills ≤ m
  • 0 ≤ tasks[i], workers[j], strength ≤ 10⁹

04 / Solution lab

准备好再展开

二分答案 + 贪心双端队列

把“最大能完成多少项”改成“能否完成 k 项”。先对两个数组升序排序：只考虑最容易的 k 项任务，以及最强的 k 名工人。

核心洞察

  • 若 k 项可行，删掉一项就得到 k − 1 项的可行方案，因而答案具有单调性。
  • 工人从弱到强处理。队列按任务要求升序保存当前工人吃药后能够完成的所有未分配候选任务。
  • 若队首任务不超过工人的原始力量，不用药，取队首。
  • 否则必须用药，此时取队尾，即吃药可完成的最难任务，为后续更强的工人留下容易的任务。

完整过程与不变量
  1. 排序后初始化 lo = 0，hi = min(n, m)。取上中位数 mid = (lo + hi + 1) // 2。
  2. 判定 k 时，任务仅用 tasks[0:k]，工人仅用 workers[m-k:m]，工人仍按升序处理。
  3. 维护只向右移动的任务指针 next。把所有 tasks[next] ≤ w + strength 的候选任务放入队尾。
  4. 队列为空说明当前工人即使吃药也无法承担剩余任何候选任务，判定失败。
  5. 队首可直接完成时弹出队首；否则若有药，消耗一片并弹出队尾；无药则失败。
  6. k 名工人全部成功分配则判定成功，令 lo = mid；否则 hi = mid − 1。直到 lo == hi。
队列始终有序且只保存已扫描、未分配的任务。随着工人力量递增，可入队的阈值也不下降；每项候选任务最多入队、出队各一次。


为什么正确
候选集合可替换。 任意 k 项可行任务，替换为最容易的 k 项不会更难；任意 k 名工人替换为最强的 k 名，也不会损害可行性。因此只判定这两个固定集合足够。
不用药时取最容易的任务。 设当前最弱工人为 w，最容易任务为 t，且 w ≥ t。在某个可行方案中，若 w 已做 t，则无需调整。否则 w 原本做 a，另一位更强工人 v 做 t。让 w 做 t，v 做 a：如果 w 做 a 不用药，v 也能；如果 w 原来吃药，可把这片药转给 v（v 已有药则不用新增）。所需药丸不增加。于是存在符合贪心选择的方案。
必须用药时取最难的可达任务。 队首超过 w，则所有剩余任务都超过 w，任何方案都必须让 w 吃药。设队尾可达任务为 b，某可行方案让 w 做 a，让后续工人 v 做 b（若 w 已做 b 则无须调整）。因为 a ≤ b，把 w 改为做 b，v 改为做 a，v 保留原本用药状态即可，药丸数量不变。
失败与归纳。 队列为空，说明没有任务能被 w 在最多一片药下完成；必须用药却无药时也不存在满足当前状态的方案。两种成功选择均保留可行方案，逐个工人归纳可得判定准确。结合可行数量的单调性，二分得到最大值。


复杂度与边界
设 K = min(n, m)。排序耗时 O(n log n + m log m)；一次判定 O(k)；总时间为 O(n log n + m log m + K log(K + 1))。队列额外空间 O(K)，排序辅助空间依语言实现而异；Python 排序可额外占用 O(n + m)。四份代码均原地排序输入。
  • k = 0 自动可行，答案可以是 0；药丸为 0 时只能用原始力量。
  • strength = 0 时吃药没有意义，无法直接完成就应判定失败。
  • 力量要求为 0、重复任务、重复工人都需要保留各自数量。
  • 当前约束下 w + strength ≤ 2 × 10⁹；Java/C++ 仍用宽整数计算提升后的力量。
替代方案
同样二分 k，但从最难任务往下处理工人有序多重集合：最强工人能直接完成就取最强；否则吃药，选择力量至少为 task − strength 的最弱工人。C++ multiset、Java TreeMap 可实现，每次判定 O(k log k)。它较直观，但比线性队列判定多一个对数因子；普通数组删除或 JavaScript shift 可能退化到 O(k²)。

Java
import java.util.Arrays;

class Solution {
    public int maxTaskAssign(int[] tasks, int[] workers,
                             int pills, int strength) {
        Arrays.sort(tasks);
        Arrays.sort(workers);
        int lo = 0, hi = Math.min(tasks.length, workers.length);
        while (lo < hi) {
            int mid = lo + (hi - lo + 1) / 2;
            if (can(tasks, workers, pills, strength, mid)) lo = mid;
            else hi = mid - 1;
        }
        return lo;
    }

    private boolean can(int[] tasks, int[] workers,
                        int pills, int strength, int k) {
        int[] q = new int[k];
        int head = 0, tail = 0, next = 0;
        for (int i = workers.length - k; i < workers.length; i++) {
            int w = workers[i];
            while (next < k && tasks[next] <= (long) w + strength) {
                q[tail++] = tasks[next++];
            }
            if (head == tail) return false;
            if (q[head] <= w) head++;
            else {
                if (pills == 0) return false;
                pills--;
                tail--;
            }
        }
        return true;
    }
}

/**
 * @param {number[]} tasks
 * @param {number[]} workers
 * @param {number} pills
 * @param {number} strength
 * @return {number}
 */
var maxTaskAssign = function(tasks, workers, pills, strength) {
    tasks.sort((a, b) => a - b);
    workers.sort((a, b) => a - b);
    const m = workers.length;
    function can(k) {
        const q = new Array(k);
        let head = 0, tail = 0, next = 0, left = pills;
        for (let i = m - k; i < m; i++) {
            const w = workers[i];
            while (next < k && tasks[next] <= w + strength) {
                q[tail++] = tasks[next++];
            }
            if (head === tail) return false;
            if (q[head] <= w) head++;
            else {
                if (left === 0) return false;
                left--;
                tail--;
            }
        }
        return true;
    }
    let lo = 0, hi = Math.min(tasks.length, m);
    while (lo < hi) {
        const mid = Math.floor((lo + hi + 1) / 2);
        if (can(mid)) lo = mid;
        else hi = mid - 1;
    }
    return lo;
};


Python
from typing import List
from collections import deque

class Solution:
    def maxTaskAssign(self, tasks: List[int], workers: List[int],
                      pills: int, strength: int) -> int:
        tasks.sort()
        workers.sort()
        m = len(workers)

        def can(k: int) -> bool:
            q = deque()
            next_task = 0
            left = pills
            for i in range(m - k, m):
                w = workers[i]
                while next_task < k and tasks[next_task] <= w + strength:
                    q.append(tasks[next_task])
                    next_task += 1
                if not q:
                    return False
                if q[0] <= w:
                    q.popleft()
                else:
                    if left == 0:
                        return False
                    left -= 1
                    q.pop()
            return True

        lo, hi = 0, min(len(tasks), m)
        while lo < hi:
            mid = (lo + hi + 1) // 2
            if can(mid):
                lo = mid
            else:
                hi = mid - 1
        return lo


C++
#include <algorithm>
#include <deque>
#include <vector>
using namespace std;

class Solution {
public:
    int maxTaskAssign(vector<int>& tasks, vector<int>& workers,
                      int pills, int strength) {
        sort(tasks.begin(), tasks.end());
        sort(workers.begin(), workers.end());
        int m = static_cast<int>(workers.size());
        auto can = [&](int k) {
            deque<int> q;
            int next = 0, left = pills;
            for (int i = m - k; i < m; ++i) {
                int w = workers[i];
                while (next < k && tasks[next] <= (long long)w + strength) {
                    q.push_back(tasks[next++]);
                }
                if (q.empty()) return false;
                if (q.front() <= w) q.pop_front();
                else {
                    if (left == 0) return false;
                    --left;
                    q.pop_back();
                }
            }
            return true;
        };
        int lo = 0, hi = min(static_cast<int>(tasks.size()), m);
        while (lo < hi) {
            int mid = lo + (hi - lo + 1) / 2;
            if (can(mid)) lo = mid;
            else hi = mid - 1;
        }
        return lo;
    }
};




常见错误与面试追问
常见错误
  • 药丸被迫使用时仍拿最容易任务。例如 tasks=[5,8]、workers=[4,5]、pills=1、strength=4：应让 4 吃药做 8，5 直接做 5。
  • 直接按全部工人从弱到强尝试，让多余的弱工人导致错误失败；固定 k 时必须选最强 k 人。
  • 每轮判定没有重置药丸、队列和任务指针，污染下一轮。
  • 二分使用下中位数配合 lo=mid，可能在只剩两个候选值时停滞。
  • JS 使用默认字典序 sort()，或在判定中反复 shift()/splice()。
面试追问
  • 要输出实际安排呢？ 排序时保留原始任务和工人下标，确定最终答案后再做一次判定并记录配对及用药标记。
  • 输入不能改变呢？ 先复制数组再排序，需要额外 O(n + m) 空间。
  • 每名工人最多吃多片药呢？ 本页交换论证依赖“一人最多一片、固定增量”；需要重新设计判定，不能直接沿用两端规则。
  • 为什么允许药丸不全用完？ 目标仅为任务数量，某项任务可能超过所有工人的提升后上限，剩余药丸也无法解决。
