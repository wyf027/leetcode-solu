好因子的最大数目

1808 · Maximize Number of Nice Divisors

HARD数学 · 数论免费题

一份有限的质因数预算，能换来多少个好因子？先理解定义，再进入下方实验。

01 / 题目

给定正整数 primeFactors，选择一个正整数 n。将 n 完全分解成质数后，质因数的总个数（重复的也计数）不能超过 primeFactors。我们希望 n 的好因子数量尽可能大。

好因子首先必须是 n 的正因子，而且必须能被 n 的每一种质因数整除。例如 n = 12 = 2² × 3，好因子是 6、12；3 缺少质因数 2，4 缺少质因数 3。重复出现的 2 不意味着好因子一定要包含 2²。

返回最大数量对 1,000,000,007 取模的结果，无须返回构造出的 n。质数是大于 1、只能被 1 和自身整除的整数。

参数：primeFactors: integer；返回：integer。
约束：1 ≤ primeFactors ≤ 10⁹。

官方示例 1

输入：primeFactors = 5
输出：6

可选 n = 200，其质因数为 [2, 2, 2, 5, 5]。好因子为 [10, 20, 40, 50, 100, 200]，共 6 个；预算不超过 5 时无法取得更多。

官方示例 2

输入：primeFactors = 8
输出：18

需要返回数量，不需要枚举 n 或全部好因子。

04 / 独立题解

核心洞察：把数论换成整数拆分

设 n = p₁ᵃ¹ × p₂ᵃ² × … × pₖᵃᵏ，其中 pᵢ 互不相同、aᵢ ≥ 1。好因子中每种质数的指数 bᵢ 必须满足 1 ≤ bᵢ ≤ aᵢ。各维选择独立，所以好因子数量为 a₁ × a₂ × … × aₖ，质因数预算为 a₁ + a₂ + … + aₖ ≤ m。

普通因子的数量才是 ∏(aᵢ + 1)，本题不能选零指数。由于可以增大任一指数而不减少乘积，存在用满预算的最优解。题目因此变成：把 m 拆成一个或多个正整数，使乘积最大；允许不拆分。

完整过程

  1. m ≤ 3 时，答案就是 m。
  2. m > 3 时尽量使用 3，令 q = ⌊m / 3⌋，r = m mod 3。
  3. r = 0：答案为 3ᑫ。
  4. r = 1：避免最后剩下 1，将一个 3 与 1 合成 4（或 2 + 2），答案为 3ᑫ⁻¹ × 4。
  5. r = 2：答案为 3ᑫ × 2。
  6. 先确定最大整数乘积的结构，再用快速幂求模；不能用取模后的大小来选择结构。

例如 m = 10：单组 [10] → [3, 7] → [3, 3, 4]，总和一直为 10，乘积从 10 → 21 → 36。m = 8 得到 [3, 3, 2]，乘积为 18。

正确性证明

计数等价：每组指数选择都唯一对应一个好因子，因此上述乘积准确且无重复；任意正整数拆分也能用不同质数作为底数构造出合法 n。

局部改进：m > 3 时最优解不必含 1：将 1 合并到另一项 x，会使 x × 1 变为 x + 1；全为 1 也可合并改进。任何 x ≥ 5 都可以换为 3 和 x − 3，因为 3(x − 3) > x。4 可以等价写成 2 + 2。故存在仅含 2、3 的最优解。

确定结构：三个 2 可换成两个 3，总和仍是 6，乘积从 8 增至 9。因此最优解最多有两个 2。根据总和模 3 的余数，只能分别使用零个、两个、一个 2，恰好得到三种公式，覆盖全部情况。

快速幂：循环保持 res × baseᵉ 与目标幂模 M 同余。指数为奇数时先将一个 base 乘入 res；随后 base 平方、指数减半。e 归零时 res 即所求模值。

边界与复杂度

m = 1、2、3 单独返回；m = 4 走余 1 分支，此时幂指数为 0。m 最大为 10⁹，无须创建 n、列举质数或储存全部分组。快速幂时间 O(log m)，额外空间 O(1)（固定宽度模运算模型）。交互中的逐项拆分只用于小预算展示。

替代方案

小规模可用动态规划：dp[s] = max(x × dp[s − x])，1 ≤ x ≤ s，dp[0] = 1；时间 O(m²)、空间 O(m)，无法适用 10⁹，且精确大整数乘积还有额外开销。逐次取出 3 的贪心是 O(m)，同样应改为商余数加快速幂。直接枚举 n 没有可用的数值上界。

四语言可提交代码

使用官方方法签名。JavaScript 模乘使用 BigInt，最后转换为 Number；Java / C++ 用 64 位中间值。

Java

class Solution {
    private static final long MOD = 1_000_000_007L;

    private long powMod(long base, int exp) {
        long result = 1;
        while (exp > 0) {
            if ((exp & 1) != 0) result = result * base % MOD;
            base = base * base % MOD;
            exp /= 2;
        }
        return result;
    }

    public int maxNiceDivisors(int primeFactors) {
        if (primeFactors <= 3) return primeFactors;
        int q = primeFactors / 3, r = primeFactors % 3;
        if (r == 1) return (int) (powMod(3, q - 1) * 4 % MOD);
        return (int) (powMod(3, q) * (r == 2 ? 2 : 1) % MOD);
    }
}

JavaScript

/**
 * @param {number} primeFactors
 * @return {number}
 */
var maxNiceDivisors = function(primeFactors) {
    if (primeFactors <= 3) return primeFactors;
    const MOD = 1000000007n;
    let exp = Math.floor(primeFactors / 3);
    const rem = primeFactors % 3;
    let result = rem === 1 ? 4n : rem === 2 ? 2n : 1n;
    if (rem === 1) exp--;
    let base = 3n;
    while (exp > 0) {
        if (exp % 2 === 1) result = result * base % MOD;
        base = base * base % MOD;
        exp = Math.floor(exp / 2);
    }
    return Number(result);
};

Python

class Solution:
    def maxNiceDivisors(self, primeFactors: int) -> int:
        if primeFactors <= 3:
            return primeFactors
        mod = 1_000_000_007
        q, r = divmod(primeFactors, 3)
        if r == 1:
            return pow(3, q - 1, mod) * 4 % mod
        return pow(3, q, mod) * (2 if r == 2 else 1) % mod

    static constexpr long long MOD = 1000000007LL;

    long long powMod(long long base, int exp) {
        long long result = 1;
        while (exp > 0) {
            if (exp & 1) result = result * base % MOD;
            base = base * base % MOD;
            exp /= 2;
        }
        return result;
    }

public:
    int maxNiceDivisors(int primeFactors) {
        if (primeFactors <= 3) return primeFactors;
        int q = primeFactors / 3, r = primeFactors % 3;
        if (r == 1) return static_cast<int>(powMod(3, q - 1) * 4 % MOD);
        return static_cast<int>(powMod(3, q) * (r == 2 ? 2 : 1) % MOD);
    }
};

常见错误

  • 把好因子计数写成 ∏(aᵢ + 1)，混淆普通因子。
  • 强制拆成至少两项，使 m = 2、3 的答案偏小。
  • 余 1 时保留 3 × 1，忽略 2 × 2 更优。
  • 使用 JavaScript Number 进行接近 10¹⁸ 的模乘，丢失整数精度。
  • 先算出 3 的完整大幂再取模，或使用浮点 pow；应逐步模乘。
  • Java / C++ 使用 32 位乘法。两余数乘积小于约 10¹⁸，64 位足够。

面试追问

为什么不关心质数具体值？它们只影响 n 的大小，计数只依赖指数。
如何给出一种构造？取若干不同质数，把最优拆分项作为指数；完整输入下只需描述构造，无须生成巨大整数。
若必须恰好使用 k 种不同质数？在 m ≥ k 时，指数总和固定，平衡各项可最大化乘积，因此各指数之差至多 1，当前优先取 3 的公式不再适用。
模数必须是质数吗？不必，本算法只有乘法和取模，不使用逆元。
