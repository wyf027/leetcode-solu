连接木棍的
最低费用

每次连接两根木棍，都要支付它们长度之和。如何安排连接顺序，才能让所有木棍最终连成一根，并让总费用尽可能低？

先别急着看答案尝试在脑中安排 [1, 8, 3, 5] 的连接顺序。长度较大的木棍应该更早还是更晚参与重复连接？

Problem

题意与输入输出

函数题

准确转述

给定一个正整数数组 sticks，其中每个元素是一根木棍的长度。一次操作可以选择任意两根木棍，将它们连接成一根新木棍；本次费用等于这两根木棍的长度之和，新木棍的长度也等于该和。

不断执行连接，直到只剩一根木棍。返回完成全部连接所需的最小总费用。若开始时木棍不足两根，则无需连接，费用为 0。

函数签名
connectSticks(sticks)
参数
sticks: integer[]
返回
integer，最小总费用

约束

  • 1 ≤ sticks.length ≤ 10⁴
  • 1 ≤ sticks[i] ≤ 10⁴
  • 输入数组仅包含正整数长度。
  • 连接后生成的新木棍可以继续参与后续连接。
思考：一根木棍越早被合并，它的长度就越可能被计入后续费用多次。

    Solution

    贪心 + 最小堆

    Huffman 式合并

    核心洞察

    一根木棍如果很早被合并，它的长度会成为新木棍的一部分，并在后续合并中反复计入费用。因此，应让较短的木棍承担更多次计费，让较长的木棍尽可能晚加入。

    每一步取当前最短的两根木棍 a、b，支付 a + b，再把长度 a + b 放回候选集合。动态取最小值最适合用最小堆。

    完整过程

    1. 将所有木棍放入最小堆。
    2. 当堆中至少有两根木棍时，弹出最短的两根。
    3. 把它们的和累加到答案中。
    4. 将合并后的新长度压回最小堆。
    5. 堆中只剩一根时，累计费用即为最小值。

    正确性证明

    交换论证：考虑任意一种最优合并树。每根原始木棍的长度对总费用的贡献，等于“长度 × 它在合并树中的深度”。深度越大，长度被重复计费的次数越多。

    设当前最短的两根为 x、y。在一棵最优二叉合并树中，最深层必有一对兄弟叶子。若它们不是 x、y，把更长的叶子与 x、y 交换，不会增加加权路径长度。因此存在一棵最优树让 x、y 先合并。把二者收缩成长度 x+y 的新木棍后，剩余问题仍是同型子问题。递归应用该结论，算法每一步都可属于某个最优解，所以最终总费用最小。

    复杂度与边界

    • 时间：建堆 O(n)；共进行 n-1 次合并，每次两次弹出、一次插入，合计 O(n log n)。
    • 空间：堆保存至多 n 个长度，为 O(n)。
    • 单元素：循环不执行，返回 0。
    • 整数范围：中间和及总费用可能大于单根长度；语言实现应使用足够宽的整数类型。Java 使用 long 做内部计算。

    替代方案

    每轮对数组排序后取前两个也能得到正确答案，但重复排序通常是 O(n² log n) 或接近该量级；线性扫描找两个最小值则为 O(n²)。若所有长度的值域很小，可考虑计数结构，但合并会生成超出原值域的新长度，实现复杂度更高。最小堆是通用且清晰的选择。

    常见错误

    • 一次性排序后按顺序相加，却没有把“新木棍”重新放回候选集合。
    • 每次连接最长的两根，导致大长度被重复计费。
    • 只累加最终木棍长度，漏掉每一步的连接费用。
    • 堆的上浮或下沉边界写错，特别是只有一个孩子时。
    • 忽略 sticks.length === 1 的零费用边界。

    Java
    import java.util.PriorityQueue;

class Solution {
    public int connectSticks(int[] sticks) {
        PriorityQueue<Long> minHeap = new PriorityQueue<>();
        for (int length : sticks) {
            minHeap.offer((long) length);
        }

        long totalCost = 0L;
        while (minHeap.size() > 1) {
            long first = minHeap.poll();
            long second = minHeap.poll();
            long merged = first + second;
            totalCost += merged;
            minHeap.offer(merged);
        }
        return (int) totalCost;
    }
}
    JavaScript
    class MinHeap {
  constructor(values = []) {
    this.data = [];
    for (const value of values) this.push(value);
  }

  get size() {
    return this.data.length;
  }

  push(value) {
    this.data.push(value);
    let index = this.data.length - 1;
    while (index > 0) {
      const parent = Math.floor((index - 1) / 2);
      if (this.data[parent] <= this.data[index]) break;
      [this.data[parent], this.data[index]] =
        [this.data[index], this.data[parent]];
      index = parent;
    }
  }

  pop() {
    const root = this.data[0];
    const last = this.data.pop();
    if (this.data.length > 0) {
      this.data[0] = last;
      let index = 0;
      while (true) {
        let smallest = index;
        const left = index * 2 + 1;
        const right = left + 1;
        if (left < this.data.length &&
            this.data[left] < this.data[smallest]) smallest = left;
        if (right < this.data.length &&
            this.data[right] < this.data[smallest]) smallest = right;
        if (smallest === index) break;
        [this.data[index], this.data[smallest]] =
          [this.data[smallest], this.data[index]];
        index = smallest;
      }
    }
    return root;
  }
}

/**
 * @param {number[]} sticks
 * @return {number}
 */
var connectSticks = function(sticks) {
  const minHeap = new MinHeap(sticks);
  let totalCost = 0;

  while (minHeap.size > 1) {
    const merged = minHeap.pop() + minHeap.pop();
    totalCost += merged;
    minHeap.push(merged);
  }
  return totalCost;
};

class Solution:

    #include <functional>
#include <queue>
#include <vector>
using namespace std;

class Solution {
public:
    int connectSticks(vector<int>& sticks) {
        priority_queue<long long,
                       vector<long long>,
                       greater<long long>> minHeap;
        for (int length : sticks) {
            minHeap.push(length);
        }

        long long totalCost = 0;
        while (minHeap.size() > 1) {
            long long first = minHeap.top();
            minHeap.pop();
            long long second = minHeap.top();
            minHeap.pop();
            long long merged = first + second;
            totalCost += merged;
            minHeap.push(merged);
        }
        return static_cast<int>(totalCost);
    }
};

    Follow-ups

    面试追问

    为什么不是先排序一次，然后从左到右累加？

    因为每次合并都会产生一根新木棍，它可能比尚未使用的木棍更短，必须重新参与下一轮的最小值选择。最小堆正好支持这个动态过程。

    这和 Huffman 编码有什么关系？

    二者都是反复合并权重最小的两个节点，目标都是最小化加权路径长度。这里木棍长度就是权重，总连接费用就是所有叶子“权重 × 深度”的总和。

    如果一次可以连接 k 根木棍呢？

    可以推广为 k 叉 Huffman 合并：每次取最小的 k 个权重。为保证能构成完整 k 叉树，可能要先补若干个权重为 0 的虚拟节点，再重复合并。

    输入以数据流形式到达，还能立即得到最终答案吗？

    如果数据流尚未结束，新的极小值可能改变先前最优合并顺序，因此通常不能不可逆地提前完成合并。可以先维护堆，流结束后再执行完整过程；若有额外的值域或到达顺序保证，才可能在线优化。
