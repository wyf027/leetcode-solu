01 · 题目

先把规则摆清楚

有 n 枚硬币。第 1 行放 1 枚，第 2 行放 2 枚，依次类推；最后一行可以不完整。返回能形成的完整行数。

题意转述

目标是构造一个由 k 行组成的硬币阶梯，其中第 i 行恰好需要 i 枚硬币。只有从第 1 行起连续摆满的行才算完整行。

给定整数 n，返回可摆出的完整行总数；剩余硬币不足以填满下一行时，直接忽略该残缺行。

arrangeCoins(n: integer) → integer

约束

1 ≤ n ≤ 2³¹ − 1
n 为整数答案非负仅完整行计数

示例 1

输入n = 5
输出2

前两行需要 1 + 2 = 3 枚；余下 2 枚无法填满需要 3 枚的第三行。

示例 2

输入n = 8
输出3

前三行共用 1 + 2 + 3 = 6 枚；余下 2 枚无法填满需要 4 枚的第四行。

完整题解

寻找最大的可行行数

INSIGHT 01

行数与总硬币数的关系

摆满 k 行需要的硬币数是从 1 到 k 的和，等于一个三角数。

need(k) = k × (k + 1) / 2
INSIGHT 02

可行性具有单调性

若 k 行能摆满，那么更少的行一定也能摆满；若 k 行摆不满，更多行也一定摆不满。

INSIGHT 03

搜索最后一个可行值

在候选行数范围中二分，记录目前最大的可行 k，直到范围为空。

过程

二分查找怎么走

为了让边界最直观，搜索范围设为 [0, n]。虽然上界还能缩得更紧，但不会改变渐进复杂度。

  1. 初始化区间

    令 left = 0、right = n、answer = 0。答案一定落在这个闭区间内。

  2. 选择中点

    计算 mid = left + (right - left) / 2，再计算摆满 mid 行所需的三角数。

  3. 判断可行性

    若 need(mid) ≤ n，说明 mid 可行：记录它并搜索右半边；否则搜索左半边。

  4. 区间结束即得到答案

    当 left > right 时，没有未检查的候选值；answer 就是最大的可行行数。

正确性

为什么一定找得到

定义：若 need(k) ≤ n，称 k 为可行行数。因为 need(k) 随 k 严格递增，可行值必定是一段从 0 开始的连续前缀。

循环不变式：每轮开始时，answer 是已经确认可行的最大候选值；若仍存在比它更大的最优可行值，该值一定仍位于当前搜索区间 [left, right] 中。

保持：当 mid 可行时，将其记为 answer 并丢弃不可能更优的左侧；当 mid 不可行时，由单调性可知它及右侧都不可行，因此丢弃右侧。两种更新都保持不变式。

终止：每轮至少排除一个候选值，区间最终为空。此时不存在尚未检查且更优的可行值，所以 answer 正是最大完整行数。

边界与代价

实现时最容易漏掉什么

算法本身很短，数值范围和边界更新才是可靠实现的重点。

边界情况

  • n = 1：恰好摆满第一行，答案为 1。
  • 恰好是三角数：必须把等号归入可行分支。
  • 只差一枚：不能把残缺的下一行计入答案。
  • n = 2³¹ − 1：中间乘法必须使用足够宽的整数类型。

常见错误

  • 用 32 位 int 计算 mid × (mid + 1)，导致溢出。
  • 可行时只移动左边界，却忘记先保存当前候选答案。
  • 使用 < n 而不是 ≤ n，错过恰好填满的情况。
  • 边界写成 left = mid 或 right = mid，造成死循环。
时间复杂度O(log n)
额外空间O(1)

代码

四种语言完整实现

均保持官方函数签名。Java、C++ 使用 64 位中间量；JavaScript 使用 BigInt 保护整数比较。

class Solution {
    public int arrangeCoins(int n) {
        long left = 0;
        long right = n;
        long answer = 0;

        while (left <= right) {
            long mid = left + (right - left) / 2;
            long needed = mid * (mid + 1) / 2;

            if (needed <= n) {
                answer = mid;
                left = mid + 1;
            } else {
                right = mid - 1;
            }
        }

        return (int) answer;
    }
}
使用 long 承载乘法结果，最终答案安全转回 int。

替代方案

还可以直接解方程

由 k(k + 1) / 2 ≤ n 可得 k ≤ (√(8n + 1) − 1) / 2，向下取整即可。

数学公式法

为什么主解仍用二分

二分只做整数比较，证明路径清晰，也能迁移到没有闭式公式、但仍具有单调可行性的题目。公式法在更大的数值范围下还需谨慎处理浮点舍入。

面试追问

把这道 Easy 讲完整

短题更考验表达的精度：不只报出公式，还要能说明单调性、边界和数值安全。

为什么二分范围可以写成 [0, n]？

每一行至少需要 1 枚硬币，所以完整行数绝不可能超过硬币总数。这个上界虽不紧，却一定正确。

能否把右边界设得更小？

可以，例如利用答案约为 √(2n) 构造更紧上界；但这会引入额外推导，对渐进复杂度没有影响。

如何避免乘法溢出？

Java/C++ 用 64 位整数；也可把判断改写为除法形式。JavaScript 可用 BigInt 保持整数比较精确。

如果 n 大到超过 64 位怎么办？

可使用任意精度整数，或在比较 k(k+1)/2 ≤ n 时用安全除法、约分等方式避免直接构造巨大乘积。
