压缩字符串

一串连续字符，一块必须复用的数组空间。你的目标不是返回新字符串，而是让旧数组的前缀准确表达压缩结果。

Problem brief

443 · String Compression

compress(chars: character[]) → integer

返回压缩后的有效长度；返回值之后的数组内容可忽略。

01 / Read the brief

先把任务边界看清

中等 双指针 字符串 原地修改

题意转述

给定字符数组 chars，按连续相同字符分组。每组先写入该字符；若组长度大于 1，再紧接着写入长度的十进制数字。长度可能超过 9，因此每一位数字都必须占用一个数组位置。

压缩结果必须直接写回 chars 的前部，不能另行返回字符串。最后返回有效前缀的长度；超过该长度的原数组内容无需关心。算法要求只使用常量级额外空间。

  1. 单个字符保持原样，例如 ["x"] → ["x"]。
  2. 重复组写成“字符 + 次数”，例如 aaaa → a4。
  3. 多位次数逐位写入，例如 12 个 b 写成 b12。

官方示例

示例 1

输入：chars = ["a","a","b","b","c","c","c"]
输出：6
修改后有效前缀：["a","2","b","2","c","3"]
解释：连续组为 "aa"、"bb"、"ccc"，压缩为 "a2b2c3"。

示例 2

输入：chars = ["a"]
输出：1
修改后有效前缀：["a"]
解释：唯一一组长度为 1，不附加数字。

示例 3

输入：chars = ["a","b","b","b","b","b","b","b","b","b","b","b","b"]
输出：4
修改后有效前缀：["a","b","1","2"]
解释：连续组为 "a" 和 12 个 "b"，压缩为 "ab12"。

约束

  • 1 <= chars.length <= 2000
  • chars[i] 是小写字母、大写字母、数字或符号。
  • 必须在输入数组上原地写入。
  • 仅允许常量级额外空间。

Solution unlocked

双指针，原地写回

核心洞察 完整过程 正确性 边界与复杂度 替代方案 四语言代码 面试追问与常见错误

核心洞察

用 read 扫描并确定每个连续组的右边界，用 write 指向下一个可写位置。先写字符；若组长大于 1，再把组长转成十进制表示并逐位写入。

压缩结果不会比原数组更长：单字符组写 1 个字符；长度大于 1 的组写 1 + digits(count) 个字符，而它不会超过该组原长度。因此写指针不会越过尚未读取的数据边界。

完整过程

  1. 初始化 read = 0、write = 0。
  2. 记录当前组字符和起点 start = read。
  3. 不断右移 read，直到数组结束或遇到不同字符。
  4. 组长度为 read - start；在 chars[write] 写入组字符并右移 write。
  5. 若组长度大于 1，将其十进制字符串逐字符写入，并相应右移 write。
  6. 继续处理下一组；当 read == chars.length 时返回 write。

正确性证明

循环不变量：每次外层循环开始时，chars[0..write) 恰好是原输入 chars[0..read) 的正确压缩结果。

初始化：read = write = 0，空前缀的压缩仍为空，不变量成立。

保持：一次循环完整识别从 read 开始的下一连续组，并按规则写入组字符及可选的组长数字。于是写入后的前缀，正是新增该组之后的正确压缩结果，不变量继续成立。

终止：循环结束时 read = n，不变量说明 chars[0..write) 是整个输入的正确压缩；因此返回的 write 就是新长度。

边界情况

  • 单字符：只写字符，不写数字 1。
  • 全部不同：每组长度均为 1，返回原长度。
  • 全部相同：仅处理一个组，注意多位计数。
  • 字符本身是数字：它仍是普通组字符，与随后写入的计数字符按位置区分。
  • 数组末尾：内层扫描要同时检查 read < n。

复杂度

时间：O(n)。每个输入字符只被读取有限次，写入量不超过 n。

额外空间：O(1)。除若干变量及计数的十进制表示外，不随输入规模线性增长。

若严格避免创建计数字符串，也可通过计算最高位除数逐位写数字；渐进空间仍为常量级。

替代方案与取舍

最直观的方法是扫描分组并把结果追加到新字符串或新数组，再复制回 chars。实现容易，但需要 O(n) 额外空间，违反题目要求。

也可以在遇到“组末尾”时再计算组长：用一个指针顺序遍历，比较当前字符与下一个字符。这种写法同样是 O(n) / O(1)，但对数组尾部的哨兵判断更易出现越界；显式寻找右边界通常更清晰。

四语言完整实现

Java 官方签名 
class Solution {
    public int compress(char[] chars) {
        int read = 0;
        int write = 0;

        while (read < chars.length) {
            char current = chars[read];
            int start = read;

            while (read < chars.length && chars[read] == current) {
                read++;
            }

            int count = read - start;
            chars[write++] = current;

            if (count > 1) {
                char[] digits = Integer.toString(count).toCharArray();
                for (char digit : digits) {
                    chars[write++] = digit;
                }
            }
        }

        return write;
    }
}

class Solution:

        read = 0
        write = 0

        while read < len(chars):
            current = chars[read]
            start = read

            while read < len(chars) and chars[read] == current:

            count = read - start
            chars[write] = current

C++ 官方签名 
class Solution {
public:
    int compress(vector<char>& chars) {
        int read = 0;
        int write = 0;
        const int n = static_cast<int>(chars.size());

        while (read < n) {
            const char current = chars[read];
            const int start = read;

            while (read < n && chars[read] == current) {
                ++read;
            }

            const int count = read - start;
            chars[write++] = current;

            if (count > 1) {
                const string digits = to_string(count);
                for (char digit : digits) {
                    chars[write++] = digit;
                }
            }
        }

        return write;
    }
};

  • 如果不允许把计数转成字符串，怎样从最高位开始写入？
  • 若规则改成单字符也要写 1，复杂度与原地可行性有什么变化？
  • 若输入来自字符流、无法回看，如何把方案改成流式输出？

常见错误

  • 把组长 12 当成一个数组元素写入，而不是字符 '1'、'2'。
  • 长度为 1 时错误地追加数字 '1'。
  • 返回原数组长度或返回压缩字符串，而不是有效前缀长度。
  • 内层扫描没有先判断边界，读取 chars[n]。
  • 使用与输入等长的结果数组，违反常量额外空间要求。
