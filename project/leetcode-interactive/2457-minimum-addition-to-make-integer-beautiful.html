美丽整数的最小增量

Minimum Addition to Make Integer Beautiful

从一个整数出发，找到让它的数位和达标的最小增量。

打开 LeetCode 原题 ↗

01 / 题目

给定正整数 n 和 target。如果一个整数的十进制各位数字之和不超过 target，就称它为美丽整数。返回最小的非负整数 x，使 n + x 满足这一条件。输入保证存在答案。

返回的是增加了多少，即 x，而不是最终的整数 n + x。

参数与约束

  • makeIntegerBeautiful(n, target) → 最小非负整数增量。
  • 1 ≤ n ≤ 10¹²
  • 1 ≤ target ≤ 150
  • 输入保证总能使 n 变成美丽整数。

官方示例

示例 1

输入：n = 16, target = 6
输出：4

16 的数位和为 7；增加 4 后得到 20，数位和为 2。小于 4 的增量都不能满足要求。

示例 2

输入：n = 467, target = 6
输出：33

467 的数位和为 17；增加 33 后得到 500，数位和为 5。不存在更小的可行增量。

示例 3

输入：n = 1, target = 1
输出：0

1 的数位和已经等于 1，无须增加。

03 / 独立题解

先独立思考，再展开推导、数位进位实验和四种语言实现。

核心洞察：把低位归零，跳到下一条十进制边界

逐个增加太慢。若当前数位和不达标，就把它向上取整到 10 的倍数，再尝试 100、1000……低位归零时，高位产生进位，数位和可能迅速下降。每次只跨过能够证明没有答案的区间。

完整过程

  1. 保存原数 n，令 m = n、p = 10。
  2. 计算 m 的数位和。如果已经不超过 target，返回 m - n。
  3. 否则令 m = ceil(m / p) × p，即向上取整到 p 的倍数。
  4. 令 p *= 10，继续判断。整数语言用 ((m + p - 1) / p) * p 实现向上取整。

例如 n = 467, target = 6：467（和 17）→ 470（和 11，增量 3）→ 500（和 5，总增量 33），于是返回 33。若当前已经是 p 的倍数，该轮 m 不变，但 p 仍扩大；这不影响终止。

正确性：为什么跳过的数都不行？

维护不变式：所有位于 [n, m) 的整数都不合法；准备处理 p = 10ᵏ 时，m 的低 k−1 位为 0。初始 m=n、k=1，不变式成立。

令 b = ceil(m / p) × p。若 b=m，本次没有跳过任何整数。否则，对任意 y ∈ [m, b)，第 k 位左边的前缀不会改变；第 k 位上的数字不会小于 m 的对应数字，更低各位的和至少为 0。因此 digitSum(y) ≥ digitSum(m) > target，这一整段都没有答案。

更新为 b 后，低 k 位为 0，不变式继续成立。第一次数位和达标时，此前所有较小候选已被排除，所以 m 是最小合法整数，m−n 就是最小增量。target 至少为 1，而足够大的 10 的幂数位和为 1，因此一定终止。

边界与数值类型

  • 原数已达标：直接返回 0；判断必须使用 ≤。
  • 连续 9：允许连锁进位，例如 999 → 1000，只增加 1。
  • 末尾为 0：某轮取整可能不改变 m，仍需扩大 p。
  • Java 使用 long，C++ 使用 long long；32 位 int 装不下 10¹²。
  • JavaScript 使用 Number 足够：本题 m 不超过 10¹²，p 及计算中的整数也远低于 2⁵³−1。不要使用 32 位位运算取整。扩展至更大整数时应改用 BigInt。

复杂度

设 n 有 d 位。至多进行 O(d) 次取整，每次数位求和需要 O(d)，总时间 O(d²)，数值版本额外空间 O(1)。此处按固定宽度整数模型分析；页面为回放保存历史状态，另占用 O(d) 条记录。

替代方案

  • 字符串维护数位与数位和，原地处理进位；摊还可做到 O(d) 时间、O(d) 空间，但实现细节更多。
  • 逐个尝试 x：时间依赖答案大小，不适合本题范围。
  • 数位 DP 可以求大于等于 n 的最小合法数字，但状态和边界管理明显更复杂。
  • 不能直接二分“数位和是否达标”：它不单调。例如 target=1 时，10 合法、11 不合法、100 又合法。

常见错误

把结果返回成 m；遗漏初始达标分支；把向上取整写成向下取整；只看个位而不重新计算进位后的数位和；用 int 或 JavaScript 位运算导致溢出；把本实现的时间复杂度误写成 O(d)。

面试追问

  • 换成 B 进制？将取模、整除和进位基数 10 换成 B，区间证明仍成立。
  • 允许 target=0？正整数 n 加上非负 x 后仍为正数，数位和至少为 1，因而无解。
  • 怎样支持千位整数？用字符串或任意精度整数，并重新分析算术操作代价。
  • 如何降到 O(d)？从右往左维护数位和；清除低位并传播进位，避免每轮扫描所有数字。

class Solution {
    private int digitSum(long value) {
        int sum = 0;
        while (value > 0) {
            sum += (int) (value % 10);
            value /= 10;
        }
        return sum;
    }

    public long makeIntegerBeautiful(long n, int target) {
        long m = n, p = 10;
        while (digitSum(m) > target) {
            m = ((m + p - 1) / p) * p;
            p *= 10;
        }
        return m - n;
    }
}
