非递减数列

只允许改动至多一个元素。真正的难点不是发现下降，而是判断这次局部修正会不会破坏另一侧的顺序。

Non-decreasing Array 官方可免费作答 一维数组

Problem

题目描述

函数：checkPossibility(nums)

给定一个长度为 n 的整数数组 nums，判断它能否在至多修改一个元素后成为非递减数列。

非递减的定义：对每个满足 0 ≤ i ≤ n - 2 的下标 i，都必须有 nums[i] ≤ nums[i + 1]。
官方示例 1
输入
nums = [4,2,3]
调用
checkPossibility([4,2,3])
输出
true
解释
把第一个元素 4 改为 1，可得到非递减数组 [1,2,3]。
官方示例 2
输入
nums = [4,2,1]
调用
checkPossibility([4,2,1])
输出
false
解释
无论修改哪一个元素，都无法只用一次改动消除全部下降关系。

约束

  • n == nums.length
  • 1 ≤ n ≤ 104
  • -105 ≤ nums[i] ≤ 105

Solution

贪心：把一次修改留在局部冲突处

时间 O(n) · 空间 O(1)

核心洞察

从左到右扫描，只在发现 nums[i - 1] > nums[i] 时消耗一次修改机会。冲突超过一次即可返回 false。

第一次冲突时，要选择修改哪一边：

  • 若 i < 2 或 nums[i - 2] ≤ nums[i]，把左侧 nums[i - 1] 降到 nums[i]。
  • 否则不能降低左侧，否则会破坏它与 nums[i - 2] 的关系；应把右侧 nums[i] 抬到 nums[i - 1]。

为什么局部修改足够

扫描到下标 i 时，前缀已经被维护为非递减。新冲突只涉及相邻的 i - 1 与 i；选择对前后约束都安全的那一侧后，前缀仍然有序，后续可继续用同一不变量判断。

完整过程

  1. 初始化。令修改次数 changes = 0，从第二个元素开始扫描。
  2. 正常前进。若 nums[i - 1] ≤ nums[i]，当前相邻关系合法，直接检查下一对。
  3. 记录冲突。若左值大于右值，令 changes++；一旦大于 1，立即返回 false。
  4. 选择安全修正。能让左值降低且不破坏更左侧关系时，修改左值；否则抬高右值。
  5. 完成扫描。若没有出现第二次冲突，返回 true。

正确性证明

不变量：每次开始检查 nums[i - 1] 与 nums[i] 前，数组前缀 nums[0..i - 1] 已非递减，且 changes 是该前缀实际使用的修改次数。

无冲突时，不变量自然延伸。发生第一次冲突时，任何可行解都必须修改这两个元素之一。若 nums[i - 2] ≤ nums[i]，降低左值不会破坏前缀；否则降低左值必然失败，只能抬高右值，而这不会破坏已有前缀。故贪心修正保留了可行性并恢复不变量。

若出现第二次冲突，就需要另一次修改，与“至多一次”矛盾；若扫描结束仍未超过一次，构造出的数组已经非递减。因此算法返回值正确。

边界与复杂度

  • 长度为 1：没有相邻对，直接为 true。
  • 冲突位于开头：没有 i - 2，可直接降低第一个元素。
  • 冲突位于结尾：仍按同一规则检查左侧邻居。
  • 相等元素合法，因为目标是非递减而非严格递增。
  • 负数、大数不影响比较逻辑。

时间复杂度：O(n)，只扫描一次。

额外空间：O(1)，原地模拟至多一次修改。

Java · 官方签名原地贪心
class Solution {
    public boolean checkPossibility(int[] nums) {
        int changes = 0;

        for (int i = 1; i < nums.length; i++) {
            if (nums[i - 1] <= nums[i]) {
                continue;
            }

            changes++;
            if (changes > 1) {
                return false;
            }

            if (i < 2 || nums[i - 2] <= nums[i]) {
                nums[i - 1] = nums[i];
            } else {
                nums[i] = nums[i - 1];
            }
        }

        return true;
    }
}

from typing import List


class Solution:
    def checkPossibility(self, nums: List[int]) -> bool:
        changes = 0

        for i in range(1, len(nums)):
            if nums[i - 1] <= nums[i]:
                continue

            changes += 1
            if changes > 1:
                return False

            if i < 2 or nums[i - 2] <= nums[i]:
                nums[i - 1] = nums[i]
            else:
                nums[i] = nums[i - 1]

        return True

替代方案

枚举修改位置：尝试修改每个位置并重新检查数组，直观但最坏需要 O(n²)。

只计下降次数：仅统计 nums[i - 1] > nums[i] 的次数是不够的。例如 [3,4,2,3] 只有一个直接下降点，却无法通过一次修改变为非递减。还必须判断修改方向是否与左侧关系兼容。

不修改原数组：可用变量记录“修正后的前一个值”，但分支更绕；面试中原地模拟通常更清晰。

常见错误

  • 把非递减误写成严格递增，错误拒绝相等元素。
  • 冲突时总是降低左值，没有检查 nums[i - 2]。
  • 只数下降点，不实际维护修正后的比较状态。
  • 访问 nums[i - 2] 前漏掉 i < 2 的边界。
  • 修改次数达到 1 就返回，忘了题目允许“至多一次”且仍需检查后缀。

面试追问

  • 如果不能修改输入数组？用额外变量保存扫描到当前位置时的有效前驱值，维持同一不变量。
  • 如果允许修改至多 k 个元素？简单计数不再总是充分，需要明确修改代价与目标值范围；可讨论动态规划或最长非递减子序列。
  • 为什么冲突时只需考虑相邻两项？因为扫描不变量保证更早的前缀已经有序，新产生的不合法关系只位于当前边界。
  • 怎样构造实际修改后的数组？当前原地算法已经构造一个可行结果；若要返回修改下标和值，可在第一次冲突分支中记录。
