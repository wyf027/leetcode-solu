使数组非递减需要的最小累计值

区间整体加法看似自由；真正不可回避的花费，只发生在相邻元素向下掉落的位置。

nums = [3, 3, 2, 1] 的答案是 2。

题意

每次可选择一个连续、非空子数组，并将其中每个数同时增加任意正整数 x。所有操作的 x 之和是成本；求把数组变为非递减数组的最小成本。

输入约束：1 ≤ nums.length ≤ 10⁵，1 ≤ nums[i] ≤ 10⁹。示例中的参数完整写法：nums = [3, 3, 2, 1]。

下降边扫描器

每一步只观察 nums[i - 1] → nums[i]。若下降 d，任何方案都至少要为从 i 开始的某个区间付出 d。

键盘：←/→ 步进，Space 自动播放。

累计成本

0

扫描完毕即得到 Σ max(0, nums[i - 1] - nums[i])。

为何可以相加？
修复一条下降边的加法可以延伸到右侧，但不可能免费消除它需要的高度差；不同下降边的最低必付高度正好相加。

测试与验证

输入 期望输出 实际输出 状态
nums = [3, 3, 2, 1] 2 — 待补
nums = [5, 1, 2, 3] 4 — 待补

快速生成模式：UI、算法对拍、四语言编译和交互验收待补

题解：把区间加法投影为下降差分

核心洞察

若 nums[i - 1] ≤ nums[i]，这条边不用处理；否则右端至少需要补 nums[i - 1] - nums[i]。给包含 i 的后缀区间加这段高度，既能填平当前下降，也不会破坏左侧已非递减的相邻关系。因此只需累计所有正下降。

完整过程

  1. 令 answer = 0。
  2. 从 i = 1 扫到末尾。
  3. 若 nums[i - 1] > nums[i]，加上差值。

边界与复杂度

长度为 1 或本身非递减时答案为 0。最大答案可到约 10¹⁴，使用 64 位整数。时间 O(n)，额外空间 O(1)。

替代方案

可以显式模拟对后缀的差分加法，但它保存了本题不需要的中间数组，空间更大；贪心差分式即是其压缩结果。

面试追问

若每次只能增加 1，最小操作次数仍为相同的差分和；若成本与区间长度有关，则各下降边不再能独立相加，需要重新建模。

常见错误

  • 把所有元素直接抬到前缀最大值：那计算的是元素增量总和，不是每次区间加的 x 总和。
  • 用 32 位整数累计答案。
  • 在非下降边也累加绝对差。
