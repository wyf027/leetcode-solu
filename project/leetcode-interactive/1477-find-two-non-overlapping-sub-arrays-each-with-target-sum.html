找两个和为目标值且不重叠的子数组

在一条数组轨道上寻找两段互不相交的区间：它们各自的元素和恰好等于目标值，并让两段长度之和尽可能小。

2 段必须找到的子数组数量
= target每一段的元素和
最短优化两段长度之和

Problem

题目说明

函数：minSumOfLengths(arr, target)

任务

给定整数数组 arr 和整数 target，找出两个互不重叠的连续子数组，并要求每个子数组的元素和都等于 target。

在所有可行组合中，返回两个子数组长度之和的最小值；如果不存在这样的两段子数组，返回 -1。

“不重叠”表示两段区间没有共享下标；两段可以相邻。

约束

  • 1 ≤ arr.length ≤ 10⁵
  • 1 ≤ arr[i] ≤ 1000
  • 1 ≤ target ≤ 10⁸

示例 1

输入arr = [3,2,2,4,3], target = 3
输出2

选择首尾两个单元素子数组 [3]。

示例 2

输入arr = [7,3,4,7], target = 7
输出2

选择第一个和最后一个 [7]，总长度为 2。

示例 3

输入arr = [4,3,2,6,2,3,4], target = 6
输出-1

只有一个和为 6 的子数组，无法组成两段互不重叠的区间。

Core idea

一次滑动窗口 + 前缀最优

因为 arr[i] 全为正数，窗口和随右端扩展只会增大，随左端收缩只会减小。因此可以用滑动窗口在线性时间内枚举所有和为 target 的子数组。

01

把“不重叠”变成一道分界线

当当前目标区间为 [left, right] 时，任何结束位置不晚于 left - 1 的目标区间都与它不重叠。记录 best[i]：在下标 0...i 范围内，和为 target 的子数组的最短长度。

02

命中时立即组合

若窗口 [left, right] 的和等于 target，长度为 len。当 left > 0 且 best[left - 1] 有效时，用 len + best[left - 1] 更新答案。

03

把最短记录向右传播

处理完下标 right 后，令 best[right] 等于此前最短值；若当前窗口命中，再与当前长度取最小值。这样之后的任意右区间都能在 O(1) 时间查询其左侧最优搭档。

Process

完整过程

  1. 初始化 left = 0、sum = 0、answer = ∞，并创建长度为 n 的 best 数组。
  2. 让 right 从 0 扫描到 n - 1，每次把 arr[right] 加入窗口。
  3. 只要 sum > target，持续移除 arr[left] 并右移 left。正数约束保证不会漏掉可行窗口。
  4. 先令 best[right] 继承 best[right - 1]；若此时 sum == target，得到当前区间长度。
  5. 用 best[left - 1] 尝试与当前区间组合，再用当前长度更新 best[right]。
  6. 扫描结束后，若答案仍为无穷大则返回 -1，否则返回答案。

Correctness

正确性说明

引理 1：窗口不会漏解

数组元素均为正数。当窗口和大于 target 时，不移动左端就不可能通过继续扩展恢复到 target；因此收缩左端是唯一必要方向。每个右端对应的目标窗口都会被发现。

引理 2：best 查询合法

best[left - 1] 只来自完全落在 [0, left - 1] 内的区间，所以与当前 [left, right] 必然不重叠；它还是这些合法左区间里长度最短的。

结论：答案全局最优

任取最优解中靠右的区间。当扫描发现它时，算法会用其左侧所有合法区间中的最短者组合，所得长度不大于该最优解；同时每次组合都合法，故最终答案恰为全局最小值。

时间复杂度 O(n)
空间复杂度 O(n)

Edges

边界与常见错误

  • 只有一个目标区间：best 会有记录，但没有第二段可组合，最终仍返回 -1。
  • 两段紧邻：左区间结束于 left - 1 是合法的，查询不能错误地写成 best[left - 2]。
  • 先组合再更新：当前窗口不能先写入 best 再拿来与自己组合；组合必须查询 left - 1。
  • 无穷大溢出：组合前先判断左侧记录是否有效，避免哨兵值参与加法。
  • 忽略正数约束：滑动窗口成立依赖 arr[i] > 0；若允许负数，应改用前缀和与哈希表等方法。

Implementations

四语言完整代码

Java官方签名
class Solution {
    public int minSumOfLengths(int[] arr, int target) {
        int n = arr.length;
        int inf = n + 1;
        int[] best = new int[n];
        int left = 0, sum = 0, answer = inf;

        for (int right = 0; right < n; right++) {
            sum += arr[right];
            while (sum > target) {
                sum -= arr[left++];
            }

            best[right] = right == 0 ? inf : best[right - 1];
            if (sum == target) {
                int length = right - left + 1;
                if (left > 0 && best[left - 1] != inf) {
                    answer = Math.min(answer, length + best[left - 1]);
                }
                best[right] = Math.min(best[right], length);
            }
        }
        return answer == inf ? -1 : answer;
    }
}

    const INF = n + 1;

from typing import List


class Solution:
    def minSumOfLengths(self, arr: List[int], target: int) -> int:
        n = len(arr)
        inf = n + 1
        best = [inf] * n
        left = 0
        window_sum = 0
        answer = inf

        for right, value in enumerate(arr):
            window_sum += value
            while window_sum > target:
                window_sum -= arr[left]
                left += 1

            if right > 0:
                best[right] = best[right - 1]
            if window_sum == target:
                length = right - left + 1
                if left > 0 and best[left - 1] != inf:
                    answer = min(answer, length + best[left - 1])
                best[right] = min(best[right], length)

        return -1 if answer == inf else answer

Alternatives & interview

替代方案与面试追问

前后缀两次扫描

分别构造前缀最短数组和后缀最短数组，再枚举分界点组合。思路直观，同样是 O(n) 时间与 O(n) 空间，但需要两次方向相反的扫描。

前缀和 + 哈希表

若数组允许负数，滑动窗口失去单调性。可以用前缀和定位以每个位置为端点的目标区间，再结合前缀最优记录；这是更通用的延伸。

追问：能把空间降到 O(1) 吗？

单向扫描要在未来查询任意 left - 1 的历史最优值，因此通常需要 O(n) 记录。可以改成保存所有目标区间再做双指针，但最坏仍有 O(n) 个区间。

追问：为什么当前命中后不立刻移动 left？

因为元素全为正，下一次加入新元素后若超出 target，while 会自然收缩。保留当前窗口不会漏解，也让状态转移更直接。

追问：如果要找 k 个互不重叠区间呢？

可把状态扩展为 dp[count][i]，表示前 i 个位置选择 count 段的最小总长度，并在发现目标区间时进行转移；时间与空间会随 k 增长。
