唯一元素的和

Problem

题目描述

给你一个整数数组 nums。数组中的“唯一元素”是指在整个数组中恰好出现一次的元素。请返回所有唯一元素之和。

示例 1

输入：nums = [1,2,3,2]
输出：4
解释：唯一元素是 [1,3]，总和为 4。

示例 2

输入：nums = [1,1,1,1,1]
输出：0
解释：没有唯一元素，总和为 0。

示例 3

输入：nums = [1,2,3,4,5]
输出：15
解释：唯一元素是 [1,2,3,4,5]，总和为 15。

约束

  • 1 <= nums.length <= 100
  • 1 <= nums[i] <= 100

Solution

题解：两阶段计数

核心洞察：“唯一”由全局出现次数决定。先完整统计每个值的频次，再只累加频次等于 1 的值，就不会被扫描途中的局部信息误导。

完整过程

  1. 建立映射 count，遍历 nums，记录每个值出现的次数。
  2. 遍历映射中的“值—频次”对。
  3. 若频次为 1，将该值加入答案；否则忽略。
  4. 返回累计和。

正确性说明

第一次遍历结束后，count[x] 等于元素 x 在数组中的实际出现次数。因此，第二次遍历中条件 count[x] == 1 当且仅当 x 是唯一元素。算法把每个且仅每个唯一元素累加一次，所以最终结果恰好等于所有唯一元素之和。

复杂度

  • 时间：O(n)，统计与汇总各进行一次。
  • 空间：O(k)，k 为不同元素个数；本题值域固定时也可视为 O(1)。

边界情况

  • 数组只有一个元素：它必然唯一。
  • 所有元素相同：答案为 0。
  • 所有元素互不相同：答案是数组总和。
  • 某元素出现三次以上：仍然不能计入。

四种语言实现

class Solution {
    public int sumOfUnique(int[] nums) {
        int[] count = new int[101];
        for (int num : nums) {
            count[num]++;
        }

        int answer = 0;
        for (int value = 1; value <= 100; value++) {
            if (count[value] == 1) {
                answer += value;
            }
        }
        return answer;
    }
}

 * @param {number[]} nums
 * @return {number}
 */
var sumOfUnique = function(nums) {
    const count = new Map();
    for (const num of nums) {
        count.set(num, (count.get(num) ?? 0) + 1);
    }

    let answer = 0;
    for (const [value, frequency] of count) {
        if (frequency === 1) {
            answer += value;
        }
    }
    return answer;
};
from typing import List
from collections import Counter


class Solution:
    def sumOfUnique(self, nums: List[int]) -> int:
        count = Counter(nums)
        return sum(value for value, frequency in count.items()
                   if frequency == 1)

public:

替代方案

固定计数数组利用 nums[i] ≤ 100，创建长度 101 的数组。常数小、实现直观。
排序后分组排序后检查相邻元素，可做到额外空间较少，但时间上升到 O(n log n)，且可能修改输入。
在线维护和首次出现时加上该值，第二次出现时减去该值，之后不变；仍需频次表，但可省去第二轮汇总。

面试追问

  • 如果元素可能是负数或范围很大，计数结构如何选择？
  • 能否在一次扫描中维护正确答案？状态如何变化？
  • 如果数据以流形式到来且最终需要查询，如何设计接口？
  • 若“唯一”改为“恰好出现 k 次”，代码如何泛化？

常见错误

  • 把“唯一元素”误解为“不同元素”，用集合后直接求和。
  • 首次看到元素就永久加入答案，却没在第二次出现时撤销。
  • 遍历计数映射时把频次加进答案，而不是把元素值加进答案。
  • 固定数组长度没有覆盖值域端点 100。
