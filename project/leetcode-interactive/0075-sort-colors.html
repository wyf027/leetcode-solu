CORE INSIGHT

核心洞察：维护四个连续分区

当前位置只可能是 0、1、2。0 应交换到左边界，1 已属于中间区，2 应交换到右边界。每次处理至少缩小一格未检查区，因此一次扫描即可完成。

LOOP INVARIANT

循环不变量

  • [0, low) 全是 0。
  • [low, scan) 全是 1。
  • [scan, high] 尚未检查。
  • (high, n) 全是 2。

完整过程

  1. 1. 初始化 low = scan = 0，high = n - 1。
  2. 2. 遇到 0：交换 low 与 scan，二者都右移。
  3. 3. 遇到 1：只让 scan 右移。
  4. 4. 遇到 2：交换 scan 与 high，只让 high 左移。
  5. 5. 当 scan > high 时结束。

关键边界

  • 单元素与全同色数组仍按相同逻辑运行。
  • 交换 2 后不能移动 scan：换回来的元素尚未检查。
  • low 可以与 scan 重合，空的 1 区仍满足不变量。
  • 循环条件必须是 scan <= high。

复杂度

时间复杂度
O(n)：每步都会推进 scan 或收缩 high。
空间复杂度
O(1)：仅使用三个指针和交换临时量。

替代方案取舍

计数排序先统计三种数量、再覆盖数组，同样是 O(n) 时间与 O(1) 空间，但需要两趟。荷兰国旗算法一次扫描完成，更符合进阶要求，也更适合面试主线。

常见错误

  • 处理 2 后错误地让 scan++，漏检换回元素。
  • 把 high 当成开区间却仍以 n−1 初始化。
  • 使用 scan < high，漏掉最后一格。
  • 调用 sort，违背题目限制。

面试追问

  • 如何严格证明交换后四个分区仍成立？
  • 为什么处理 0 后可以同时推进 low 和 scan？
  • 若颜色种类从 3 种扩展到 k 种，该如何选择算法？
  • 怎样估算交换次数上界？
class Solution {
    public void sortColors(int[] nums) {
        int low = 0, scan = 0, high = nums.length - 1;
        while (scan <= high) {
            if (nums[scan] == 0) {
                swap(nums, low++, scan++);
            } else if (nums[scan] == 1) {
                scan++;
            } else {
                swap(nums, scan, high--);
            }
        }
    }

    private void swap(int[] nums, int i, int j) {
        int temp = nums[i];
        nums[i] = nums[j];
        nums[j] = temp;
    }
}
