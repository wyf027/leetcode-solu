文章浏览 II Article Views II

从一张允许重复记录的浏览表里，找出那些在同一天真正看过不止一篇文章的人。 这是一道关于“分组口径”与“去重计数”的数据库题。

中等 数据库 付费题 #1149

01 / Problem

题意与数据契约

输入是一张 Views 表；输出只有一列 id，表示满足条件的浏览者。

准确转述

表中每一行表示：浏览者 viewer_id 在 view_date 这一天浏览了文章 article_id；文章作者为 author_id。

请找出所有在同一个自然日浏览过至少两篇不同文章的人， 输出列命名为 id，并按 id 升序排列。每个人在结果中只出现一次。

表允许出现重复行，所以“多条浏览记录”不一定代表“多篇不同文章”。作者是否等于浏览者不影响本题判断。

参数 / 表结构

  • article_id INT：被浏览的文章编号
  • author_id INT：文章作者编号
  • viewer_id INT：浏览者编号
  • view_date DATE：浏览日期

约束与语义

  • Views 没有保证唯一的主键，可能含重复行。
  • 各 ID 为整数；日期值按 YYYY-MM-DD 表示。
  • author_id 可以等于 viewer_id。
  • 同一文章的重复浏览只算一篇；不同日期之间不能合并计数。

05 / Solution

题解：先定粒度，再做去重

官方题型为数据库题；SQL 是可提交答案，四种通用语言仅用于本地理解同一语义。

MySQL / SQL

Core insight

分组键必须同时包含人和日期。

“同一天”决定聚合粒度是 (viewer_id, view_date)； “多篇文章”要求统计 DISTINCT article_id，而不是行数。

一个浏览者可能在多个日期都达标，所以内层先筛选达标分组，外层再对 viewer_id 去重并排序。

完整过程

  1. 按浏览者和日期组合分组，使每组只代表“某人在某一天”的浏览。
  2. 对每组的文章编号去重计数，过滤出不同文章数大于 1 的组。
  3. 从达标组中取浏览者编号；再次去重，防止同一人因多个达标日期重复出现。
  4. 将列改名为 id，最后升序排序。

正确性证明

1

对任意达标浏览者 v，存在日期 d，使 v 在 d 浏览至少两篇不同文章。对应分组 (v,d) 的不同文章数大于 1，内层必保留它，外层因此输出 v。

2

对任意被输出的 v，必来自某个通过 HAVING 的分组 (v,d)。该组至少含两个不同 article_id，所以 v 确实在同一天浏览了多篇文章。

3

外层 DISTINCT 保证每个 v 只出现一次，ORDER BY 保证结果升序；因此输出与题目要求完全一致。

边界情况

  • 空表或仅一条记录：没有人达标。
  • 完全重复的行：相同文章只计一次。
  • 同一人跨日期看不同文章：不同日期分别统计，不能合并。
  • 同一人在多个日期达标：结果仍只保留一个 id。
  • 作者自己浏览文章：author_id 与 viewer_id 相等不影响统计。

复杂度

设记录数为 n。数据库实际成本取决于执行计划与索引：哈希聚合通常接近 O(n)，排序聚合通常为 O(n log n)；聚合状态空间最坏为 O(n)。最终对 k 个候选 id 排序约为 O(k log k)。

四种本地参考实现用哈希集合聚合，期望时间为 O(n + k log k)，额外空间为 O(n)。

完整代码

选择语言；代码容器可独立横向与纵向滚动。

可提交语言 · MySQL / 标准关系查询思路
SELECT DISTINCT viewer_id AS id
FROM (
    SELECT viewer_id
    FROM Views
    GROUP BY viewer_id, view_date
    HAVING COUNT(DISTINCT article_id) > 1
) AS qualifying_viewers
ORDER BY id;

import java.time.LocalDate;
import java.util.ArrayList;
import java.util.HashMap;
import java.util.HashSet;
import java.util.List;
import java.util.Map;
import java.util.Set;
import java.util.TreeSet;

public class ArticleViewsII {
    public static final class View {
        final int articleId;
        final int authorId;
        final int viewerId;
        final LocalDate viewDate;

        public View(int articleId, int authorId, int viewerId, LocalDate viewDate) {
            this.articleId = articleId;
            this.authorId = authorId;
            this.viewerId = viewerId;
            this.viewDate = viewDate;
        }
    }

    private static final class GroupKey {
        final int viewerId;
        final LocalDate viewDate;

        GroupKey(int viewerId, LocalDate viewDate) {
            this.viewerId = viewerId;
            this.viewDate = viewDate;
        }

        @Override
        public boolean equals(Object other) {
            if (this == other) return true;
            if (!(other instanceof GroupKey)) return false;
            GroupKey key = (GroupKey) other;
            return viewerId == key.viewerId && viewDate.equals(key.viewDate);
        }

        @Override
        public int hashCode() {
            return 31 * viewerId + viewDate.hashCode();
        }
    }

    public static List<Integer> findViewers(List<View> views) {
        Map<GroupKey, Set<Integer>> distinctArticles = new HashMap<>();

        for (View view : views) {
            GroupKey key = new GroupKey(view.viewerId, view.viewDate);
            distinctArticles
                .computeIfAbsent(key, ignored -> new HashSet<>())
                .add(view.articleId);
        }

        TreeSet<Integer> answer = new TreeSet<>();
        for (Map.Entry<GroupKey, Set<Integer>> entry : distinctArticles.entrySet()) {
            if (entry.getValue().size() > 1) {
                answer.add(entry.getKey().viewerId);
            }
        }
        return new ArrayList<>(answer);
    }
}

/**
 * @param {Array<{article_id:number, author_id:number,
 *   viewer_id:number, view_date:string}>} views
 * @returns {number[]} 升序且不重复的 viewer_id
 */
function articleViewsII(views) {
  const groups = new Map();

  for (const row of views) {
    const key = `${row.viewer_id}|${row.view_date}`;
    if (!groups.has(key)) {
      groups.set(key, {
        viewerId: row.viewer_id,
        articles: new Set(),
      });
    }
    groups.get(key).articles.add(row.article_id);
  }

  const qualifying = new Set();
  for (const group of groups.values()) {
    if (group.articles.size > 1) {
      qualifying.add(group.viewerId);
    }
  }

  return [...qualifying].sort((a, b) => a - b);
}

from collections import defaultdict
from dataclasses import dataclass
from datetime import date
from typing import Iterable


@dataclass(frozen=True)
class View:
    article_id: int
    author_id: int
    viewer_id: int
    view_date: date


def article_views_ii(views: Iterable[View]) -> list[int]:
    groups: dict[tuple[int, date], set[int]] = defaultdict(set)

    for row in views:
        key = (row.viewer_id, row.view_date)
        groups[key].add(row.article_id)

    qualifying = {
        viewer_id
        for (viewer_id, _), articles in groups.items()
        if len(articles) > 1
    }
    return sorted(qualifying)

#include <algorithm>
#include <string>
#include <unordered_map>
#include <unordered_set>
#include <vector>

struct View {
    int articleId;
    int authorId;
    int viewerId;
    std::string viewDate;
};

std::vector<int> articleViewsII(const std::vector<View>& views) {
    using ArticleSet = std::unordered_set<int>;
    std::unordered_map<std::string, ArticleSet> groups;
    std::unordered_map<std::string, int> viewerByGroup;

    for (const View& row : views) {
        const std::string key =
            std::to_string(row.viewerId) + "|" + row.viewDate;
        groups[key].insert(row.articleId);
        viewerByGroup[key] = row.viewerId;
    }

    std::unordered_set<int> qualifying;
    for (const auto& [key, articles] : groups) {
        if (articles.size() > 1) {
            qualifying.insert(viewerByGroup.at(key));
        }
    }

    std::vector<int> answer(qualifying.begin(), qualifying.end());
    std::sort(answer.begin(), answer.end());
    return answer;
}

替代方案

  • 去重 CTE + 窗口函数：先对三元组 viewer_id, view_date, article_id 去重，再用窗口计数。表达清楚，但层次更多。
  • 自连接：让同一浏览者、同一天但不同文章的两行相连，也能找出答案；通常产生更多中间行，不如聚合直接。
  • 省略外层查询：只有能保证每个浏览者最多一个达标日期时才安全，本题没有这个保证，因此不推荐。

常见错误

  • 用 COUNT(*)，把重复浏览误当作不同文章。
  • 只按 viewer_id 分组，把跨日浏览错误合并。
  • 按 author_id 分组；作者列并不是本题筛选对象。
  • 忘记外层 DISTINCT，导致同一浏览者出现多次。
  • 忘记 ORDER BY id，结果顺序不满足要求。

面试追问

  • 如果要求“连续 3 天每天至少看 2 篇”，如何在聚合结果上识别日期岛？
  • 如果一篇文章一天内多次浏览要按会话数计数，表结构还需要什么字段？
  • 数据量极大时，什么复合索引更利于分组？可讨论以 viewer_id、view_date、article_id 为前缀的覆盖索引。
  • 若输出还要包含达标日期和文章数，如何移除外层去重并扩展 SELECT？
