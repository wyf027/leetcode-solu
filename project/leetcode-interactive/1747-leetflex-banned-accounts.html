题意

LogInfo 的每一行记录某个账户通过一个 IP 地址登录与退出的时间。若同一账户在至少一个时刻同时通过两个不同 IP 地址在线，该账户应被禁止。

返回所有应被禁止的 account_id，结果顺序不限。

时间边界也算“同一时刻”：一段会话恰好在另一段开始时退出，两段在该时间点仍有交集。

约束与保证

  • logout 严格晚于 login。
  • 表中可能存在重复行。
  • 相同 IP 的重叠会话本身不构成封禁条件。

04 / SOLUTION

不同 IP + 闭区间相交

把每条日志看作闭区间。我们只需找到一对属于同一账户、IP 不同且时间有交集的会话。

核心洞察

两个闭区间 [login₁, logout₁] 与 [login₂, logout₂] 相交，当且仅当：

login₁ ≤ logout₂ AND login₂ ≤ logout₁

再加上账户相同、IP 不同，便得到完整判断。使用 SELECT DISTINCT 去掉同一账户由多对会话造成的重复结果。

完整过程

自连接

令同一张 LogInfo 分别扮演会话 a 与会话 b。

约束候选对

要求账户相同但 IP 不同，排除无关组合。

检测相交

用两个不等式覆盖部分重叠、包含和边界接触。

结果去重

一个账户无论命中多少对，仅返回一次。

可提交主答案

本题是数据库题，官方提交语言为 SQL。

MySQL
solution.sql自连接
SELECT DISTINCT a.account_id
FROM LogInfo AS a
JOIN LogInfo AS b
  ON a.account_id = b.account_id
 AND a.ip_address <> b.ip_address
 AND a.login <= b.logout
 AND b.login <= a.logout;

正确性证明

充分性：查询返回账户 x，说明连接中存在 x 的两行 a、b。它们 IP 不同，且两个相交不等式成立，所以两个闭区间共享至少一个时刻；x 符合封禁条件。

必要性：若账户 x 应被禁止，则必存在两个不同 IP 的在线会话共享某时刻。共享时刻意味着二者互不完全位于对方之外，因此两个相交不等式都成立；自连接必能枚举到这对记录并返回 x。

DISTINCT 只合并相同账户编号，不会删除任何应返回的账户。因此算法正确。

边界与复杂度

  • 边界接触使用 ≤，仍算相交。
  • 同一 IP 即使时间重叠也必须排除。
  • 重复行不会单独触发封禁，且 DISTINCT 保证输出唯一。
  • 完全包含也是相交，无需单独分支。

逻辑复杂度：朴素执行可视为 O(n²) 会话对比较；实际数据库可能利用账户列上的索引与优化器降低扫描成本。输出去重需要额外聚合/排序或哈希空间。

Solution.java时间使用 ISO 字符串，字典序即时间序
import java.util.*;

class Solution {
    // 每行: [account_id, ip_address, login, logout]
    public List<Integer> bannedAccounts(List<String[]> logs) {
        Map<Integer, List<String[]>> groups = new HashMap<>();
        for (String[] row : logs) {
            int account = Integer.parseInt(row[0]);
            groups.computeIfAbsent(account, k -> new ArrayList<>()).add(row);
        }

        List<Integer> answer = new ArrayList<>();
        for (Map.Entry<Integer, List<String[]>> entry : groups.entrySet()) {
            List<String[]> sessions = entry.getValue();
            boolean banned = false;
            for (int i = 0; i < sessions.size() && !banned; i++) {
                for (int j = i + 1; j < sessions.size(); j++) {
                    String[] a = sessions.get(i), b = sessions.get(j);
                    boolean differentIp = !a[1].equals(b[1]);
                    boolean overlap = a[2].compareTo(b[3]) <= 0
                                   && b[2].compareTo(a[3]) <= 0;
                    if (differentIp && overlap) {
                        banned = true;
                        break;
                    }
                }
            }
            if (banned) answer.add(entry.getKey());
        }
        Collections.sort(answer);
        return answer;
    }
}
solution.js原生数组实现
/**
 * 每行: [accountId, ipAddress, login, logout]
 * login/logout 为 YYYY-MM-DD HH:mm:ss 字符串。
 */
function bannedAccounts(logs) {
  const groups = new Map();
  for (const row of logs) {
    const accountId = row[0];
    if (!groups.has(accountId)) groups.set(accountId, []);
    groups.get(accountId).push(row);
  }

  const answer = [];
  for (const [accountId, sessions] of groups) {
    let banned = false;
    for (let i = 0; i < sessions.length && !banned; i += 1) {
      for (let j = i + 1; j < sessions.length; j += 1) {
        const a = sessions[i];
        const b = sessions[j];
        const differentIp = a[1] !== b[1];
        const overlap = a[2] <= b[3] && b[2] <= a[3];
        if (differentIp && overlap) {
          banned = true;
          break;
        }
      }
    }
    if (banned) answer.push(accountId);
  }
  return answer.sort((a, b) => a - b);
}
solution.py分组后枚举会话对
from collections import defaultdict
from typing import List, Tuple

Row = Tuple[int, int, str, str]


class Solution:
    def bannedAccounts(self, logs: List[Row]) -> List[int]:
        groups = defaultdict(list)
        for account_id, ip_address, login, logout in logs:
            groups[account_id].append((ip_address, login, logout))

        answer = []
        for account_id, sessions in groups.items():
            banned = False
            for i in range(len(sessions)):
                ip_a, login_a, logout_a = sessions[i]
                for j in range(i + 1, len(sessions)):
                    ip_b, login_b, logout_b = sessions[j]
                    different_ip = ip_a != ip_b
                    overlap = login_a <= logout_b and login_b <= logout_a
                    if different_ip and overlap:
                        banned = True
                        break
                if banned:
                    break
            if banned:
                answer.append(account_id)

        return sorted(answer)
solution.cpp结构体建模
#include <algorithm>
#include <map>
#include <string>
#include <vector>
using namespace std;

struct Session {
    int accountId;
    int ipAddress;
    string login;
    string logout;
};

class Solution {
public:
    vector<int> bannedAccounts(const vector<Session>& logs) {
        map<int, vector<Session>> groups;
        for (const Session& row : logs) groups[row.accountId].push_back(row);

        vector<int> answer;
        for (const auto& [accountId, sessions] : groups) {
            bool banned = false;
            for (int i = 0; i < static_cast<int>(sessions.size()) && !banned; ++i) {
                for (int j = i + 1; j < static_cast<int>(sessions.size()); ++j) {
                    const Session& a = sessions[i];
                    const Session& b = sessions[j];
                    bool differentIp = a.ipAddress != b.ipAddress;
                    bool overlap = a.login <= b.logout && b.login <= a.logout;
                    if (differentIp && overlap) {
                        banned = true;
                        break;
                    }
                }
            }
            if (banned) answer.push_back(accountId);
        }
        return answer;
    }
};

替代方案

窗口函数：按账户、登录时间排序后，用前缀最大退出时间思考扫描线。但还要正确处理“不同 IP”；只比较相邻两行在复杂嵌套会话下容易漏解。

EXISTS：用相关子查询寻找任意匹配会话，语义直接，且无需外层 DISTINCT；实际性能取决于索引和优化器。

面试追问

为何是 ≤ 而不是 <？退出与登录时间相等时，官方示例将边界点视为同时在线。
如何设计索引？可从 (account_id, login, logout, ip_address) 的组合索引讨论过滤与覆盖。
海量日志怎么办？按账户分区、缩小时间候选范围，并考虑流式事件扫描。
如何返回证据？额外选择两条会话的 IP 与相交起止点，而非只返回账户。

常见错误

只比较登录时间是否相等会漏掉开始时间不同但区间重叠的会话。
使用严格小于号会漏掉账户 4 这种恰好在边界接触的情况。
忘记 IP 不同相同 IP 的并发记录不满足封禁定义。
忘记 DISTINCT同一账户可能由多对记录命中，从而重复输出。
