最小化数对的最大差值

2616 · Minimize the Maximum Difference of Pairs

从互不复用下标的数对中，寻找那个尽可能小的“最坏差值”。先理解目标，再亲手探索阈值如何改变可配对数量。

阅读题目 进入交互实验室

Problem

题目描述

给定下标从 0 开始的整数数组 nums 和整数 p。请选择恰好 p 个下标对，并保证任何下标至多被使用一次。

下标 i 与 j 构成的数对差值为 |nums[i] - nums[j]|。目标是让所选数对中最大的差值尽可能小，并返回这个最小值。若 p = 0，空集的最大值定义为 0。

函数形式：minimizeMax(nums, p) -> integer

示例 1

输入：nums = [10,1,2,7,1,3], p = 2
输出：1
解释：选择下标对 (1,4) 与 (2,5)。
差值分别是 |1-1| = 0、|2-3| = 1，
其中最大值为 1。

示例 2

输入：nums = [4,2,1,2], p = 1
输出：0
解释：选择下标对 (1,3)，两处数值均为 2，
差值为 0，已经是可能的最小值。

约束

  • 1 <= nums.length <= 105
  • 0 <= nums[i] <= 109
  • 0 <= p <= nums.length / 2

Solution

二分答案 + 贪心判定

核心洞察

不要直接枚举数对。先猜一个允许的最大差值 limit，再问：能否组成至少 p 对、且每对差值都不超过它？

如果某个阈值可行，更大的阈值也一定可行，因此答案具有单调性，可以二分。排序后，从左到右遇到满足阈值的相邻元素就立刻配对；这种选择不会挤占更优的前缀机会。

完整过程

  1. 将 nums 升序排序。
  2. 在 [0, max(nums)-min(nums)] 中二分最小可行阈值。
  3. 判定时从左向右扫描；若相邻差值不超过阈值，就选中两者并跳过这两个位置，否则只右移一个位置。
  4. 配对数达到 p 时阈值可行，收缩右边界；否则提高左边界。

为什么正确

引理 1：贪心判定得到给定阈值下的最大配对数。 排序后，设当前最左的未处理位置为 i。若 nums[i+1]-nums[i] > limit，那么 nums[i] 与更右元素的差值只会更大，它不可能参与合法配对，跳过它是安全的。若相邻两数合法，选择 (i,i+1) 不会变差：任何使用 i 或 i+1 的方案，都可以把其最靠左的一对替换为这对，剩余元素不受影响。因此该选择保留了后缀可达到的最大配对数。

引理 2：可行性关于阈值单调。 若阈值 x 已能组成 p 对，则同一组数对在任意 y >= x 下仍合法。

结论：贪心判定准确回答每个阈值是否可行；二分最终停在第一个可行阈值，所以它正是所有方案中最小的最大差值。

复杂度

  • 排序：O(n log n)
  • 每次判定：O(n)
  • 二分次数：O(log V)，其中 V = max(nums)-min(nums)
  • 总时间：O(n log n + n log V)
  • 额外空间：取决于语言的排序实现；扫描本身为 O(1)

边界情况

  • p = 0：答案为 0。
  • 存在重复值：答案可能为 0。
  • p = floor(n/2)：几乎所有元素都必须被使用。
  • 数值跨度可达 10^9，二分边界和差值需使用安全的整数类型。

import java.util.Arrays;

class Solution {
    public int minimizeMax(int[] nums, int p) {
        Arrays.sort(nums);
        int left = 0;
        int right = nums[nums.length - 1] - nums[0];

        while (left < right) {
            int mid = left + (right - left) / 2;
            if (canForm(nums, p, mid)) {
                right = mid;
            } else {
                left = mid + 1;
            }
        }
        return left;
    }

    private boolean canForm(int[] nums, int p, int limit) {
        int pairs = 0;
        for (int i = 1; i < nums.length && pairs < p; ) {
            if (nums[i] - nums[i - 1] <= limit) {
                pairs++;
                i += 2;
            } else {
                i++;
            }
        }
        return pairs >= p;
    }
}

替代方案

动态规划：排序后，可以针对固定阈值计算前缀最多能配多少对；但判定本身用贪心已经足够，DP 会增加不必要的状态与空间。

枚举差值：排序后收集相邻差值再逐个尝试，最坏会进行过多次扫描；二分直接利用单调性更稳定。

常见错误

  • 忘记排序，导致“相邻最优”的贪心依据不存在。
  • 选中一对后只移动一个位置，重复使用了下标。
  • 二分更新写成 left = mid，在相邻边界时死循环。
  • 寻找“恰好” p 对；判定只需确认能组成“至少” p 对。

面试追问

Q：为什么只看相邻元素？
排序后，如果最左元素连紧邻元素都无法在阈值内配对，那么它与更远元素也不可能；若能配，与最近元素配对为后缀保留的选择最多。

Q：如何恢复具体的 p 个数对？
求出最小阈值后再执行一次相同的贪心扫描，并记录排序后元素携带的原下标，收集前 p 对即可。

Q：如果要求最小化所有差值之和呢？
目标不再是单一阈值可行性，当前二分模型失效，通常需要排序后的动态规划。
