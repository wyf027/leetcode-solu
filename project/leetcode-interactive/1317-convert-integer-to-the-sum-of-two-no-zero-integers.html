Problem

题目描述

无零整数是十进制表示中不包含数字 0 的正整数。给定整数 n，返回两个整数组成的数组 [a, b]，使得 a 与 b 都是无零整数，并且 a + b = n。

题目保证至少存在一个有效答案；若答案不唯一，返回任意一组即可。

官方示例

示例 1
输入：n = 2
输出：[1, 1]

取 a = 1、b = 1，二者均不含 0，且和为 2。

示例 2
输入：n = 11
输出：[2, 9]

也可以返回其他满足条件的组合，例如 [8, 3]。

示例 3
输入：n = 10000
输出：[1, 9999]
示例 4
输入：n = 69
输出：[1, 68]
示例 5
输入：n = 1010
输出：[11, 999]

约束

◆2 <= n <= 104

Solution

题解：枚举第一项，检查十进制数字

核心洞察

一旦固定 a，另一项只能是 b = n - a。因此无需枚举两个变量，只需从 a = 1 开始尝试，并检查两数是否含 0。

停止条件

当 a 与 b 都是正整数且十进制表示均不含 0 时，立即返回 [a, b]。

边界意识

a 只需枚举到 n - 1，这样 b 始终为正。题目保证范围内存在答案。

完整过程

  1. 从 a = 1 开始，计算唯一对应的 b = n - a。
  2. 逐位检查 a：若末位为 0，则它不是无零整数；否则令整数除以 10，继续检查。
  3. 用同样方式检查 b。两者都通过时立即返回；否则将 a 加一。

正确性证明

引理：辅助函数当且仅当输入整数的十进制表示不含 0 时返回真。因为它依次检查从个位到最高位的每一位；遇到 0 立即返回假，所有位检查完仍未遇到 0 才返回真。

定理：算法返回的数组一定满足题目要求。算法只返回某个 [a, n-a]，所以两数之和恒为 n；返回前又通过辅助函数确认两数均不含 0，并且枚举范围保证二者为正。因此返回值合法。题目保证合法解存在，而算法按顺序覆盖所有正整数拆分，所以最终必然返回一组答案。

复杂度

最坏尝试 O(n) 组候选，每次检查两数各需 O(log n) 位，因此时间复杂度为 O(n log n)；只使用常数个变量，空间复杂度为 O(1)。

替代方案

也可把整数转为字符串并判断是否包含字符 '0'，写法更直观，但会创建临时字符串，额外空间为 O(log n)。还可按十进制位构造拆分，但实现和证明都更复杂，本题范围下没有必要。

class Solution {
    public int[] getNoZeroIntegers(int n) {
        for (int a = 1; a < n; a++) {
            int b = n - a;
            if (isNoZero(a) && isNoZero(b)) {
                return new int[] {a, b};
            }
        }
        return new int[0];
    }

    private boolean isNoZero(int value) {
        while (value > 0) {
            if (value % 10 == 0) return false;
            value /= 10;
        }
        return true;
    }
}

常见错误

  • 只检查 n 是否含 0，而没有分别检查 a 与 b。
  • 让 a 取到 n，导致 b = 0，违反正整数条件。
  • 在找到合法答案后仍继续枚举，或误以为必须返回字典序最小答案。
  • 逐位检查时忘记更新 value /= 10，形成死循环。

面试追问

  • 如果 n 的范围扩大很多，能否按位构造两个无零数？
  • 若禁止使用字符串，如何证明逐位检查覆盖了所有十进制位？
  • 如果要求返回全部合法组合，复杂度和接口应如何调整？
  • 若“禁用数字”从 0 变成任意集合，辅助函数如何泛化？
