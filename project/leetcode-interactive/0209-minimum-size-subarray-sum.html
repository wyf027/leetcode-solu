Minimum Size Subarray Sum

所有数字均为正数时，窗口和只会随右边界右移而变大、随左边界右移而变小。一旦达到目标，就立刻向内收缩，直到失效为止；每次有效窗口都在刷新最短长度。

题意与约束

↔️ 正数 · 滑动窗口

给定正整数数组 nums 和正整数 target，找到和大于等于 target 的最短连续子数组，并返回其长度；没有则返回 0。

1 <= nums.length <= 10⁵

题解 · 只前进、不回头的双指针

核心洞察

因为 nums[i] > 0，加入右端元素后窗口和不会减少；移除左端元素后窗口和不会增加。右指针每个位置只访问一次，左指针也只会单调前进，所以可在线性时间内枚举所有“刚好仍有效”的候选窗口。

完整过程

  1. left = 0、sum = 0、答案设为无穷大。
  2. 右指针逐个加入元素：sum += nums[right]。
  3. 当 sum >= target，窗口有效：记录长度。
  4. 移除 nums[left] 并右移左指针，继续尝试更短窗口。
  5. 遍历结束；答案仍无穷大则返回 0。

复杂度与边界

两个指针均最多从左到右移动 n 次：时间 O(n)，额外空间 O(1)。

  • 单个元素已达标：答案是 1。
  • 全数组和仍小于目标：答案是 0。
  • 收缩后可立即失效，这是停止内循环的正确时机。

替代方案取舍

前缀和 + 二分可做到 O(n log n)，但这里正数条件足以支持更快的双指针。若数组允许负数，普通滑动窗口失效，应改用前缀和与单调队列等方法。

常见错误：把收缩写成 if 而不是 while，会遗漏同一右端点下更短的窗口；在收缩前后更新长度顺序错误；或误用于包含负数的数组。

面试追问

若要返回区间而非长度？保存刷新答案时的 left 和 right。若要窗口和“恰好等于”目标？正数数组仍可双指针，但收缩条件与记录位置不同。若含负数？解释为什么单调性消失，并切换算法。

class Solution {
    public int minSubArrayLen(int target, int[] nums) {
        int left = 0, sum = 0, best = Integer.MAX_VALUE;
        for (int right = 0; right < nums.length; right++) {
            sum += nums[right];
            while (sum >= target) {
                best = Math.min(best, right - left + 1);
                sum -= nums[left++];
            }
        }
        return best == Integer.MAX_VALUE ? 0 : best;
    }
}
