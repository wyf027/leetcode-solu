整数的各位积和之差

给定一个整数 n，计算它的所有十进制数位之积与所有数位之和，再返回两者的差。

输入：n（整数）返回：整数1 ≤ n ≤ 105
01

官方示例

示例 1

输入：n = 234
输出：15
解释：
各位之积 = 2 × 3 × 4 = 24
各位之和 = 2 + 3 + 4 = 9
结果 = 24 - 9 = 15

示例 2

输入：n = 4421
输出：21
解释：
各位之积 = 4 × 4 × 2 × 1 = 32
各位之和 = 4 + 4 + 2 + 1 = 11
结果 = 32 - 11 = 21

约束

1 <= n <= 10^5

完整题解

核心洞察

十进制整数的末位可以用 n % 10 得到，去掉末位可用整数除法 n / 10。不断重复，就能只用常量额外空间遍历所有数位。积的单位元是 1，和的单位元是 0，因此分别以 1 和 0 初始化。

完整过程

  1. 设置 product = 1、sum = 0。
  2. 当 n > 0 时，取 digit = n % 10。
  3. 执行 product *= digit 和 sum += digit。
  4. 用整数除法令 n /= 10，删除已经处理的末位。
  5. 循环结束后返回 product - sum。

正确性证明

循环不变式：每轮开始时，product 等于已处理数位的乘积，sum 等于已处理数位的和。

初始化：尚未处理数位时，空积为 1、空和为 0，不变式成立。

保持：当前末位 digit 被分别乘入积、加进和，因此新状态恰好覆盖此前数位与当前数位，不变式继续成立。

终止：每轮删除一位，最终 n = 0。此时所有数位都已处理，不变式说明两个变量就是全部数位的积与和，所以两者之差正是题目要求。

边界情况

  • 单个数位：例如 7，积与和都是 7，答案为 0。
  • 包含 0：例如 101，积会变成 0，但仍须继续累计数位和。
  • 最大输入：100000 只有 6 位，普通整数类型足够容纳中间结果。

复杂度

若 n 有 d 个十进制数位，则时间复杂度为 O(d)（亦可写作 O(log n)），额外空间复杂度为 O(1)。

替代方案

也可以先把整数转成字符串，再逐字符转回数字并累计。它更直观，但需要 O(d) 的字符串空间；数值取模方案更贴近本题的数学标签。

面试追问

  • 如果允许 n = 0，循环应如何兼容？可以特判，或使用至少执行一次的循环。
  • 如果输入可能为负数，应先取绝对值，并说明最小整数取绝对值时的溢出问题。
  • 如果整数有数百万位，应改用字符串流式扫描，避免数值类型溢出。

常见错误

  • 把乘积初始化为 0，导致答案中的乘积永远是 0。
  • 遇到数位 0 就提前退出，遗漏了其余数位对“和”的贡献。
  • 在 JavaScript 或 Python 中用普通除法后未取整，导致循环状态错误。
  • 计算完数位却忘记更新 n，形成死循环。

class Solution {
    public int subtractProductAndSum(int n) {
        int product = 1;
        int sum = 0;

        while (n > 0) {
            int digit = n % 10;
            product *= digit;
            sum += digit;
            n /= 10;
        }

        return product - sum;
    }
}

var subtractProductAndSum = function(n) {
    let product = 1;
    let sum = 0;

        product *= digit;
        sum += digit;
        n = Math.floor(n / 10);

    return product - sum;
};
