游戏玩法分析 III

Game Play Analysis III · 用窗口函数追踪玩家每次登录后的累计游戏数

题目

表 Activity 记录玩家在某台设备、某一天登录时完成的游戏数量。对每位玩家的每条活动记录，求截至该日期（包含当天）累计完成的游戏数。

返回 player_id、event_date 和 games_played_so_far。每位玩家每天至多一条记录；结果顺序不作要求。

列名类型含义
player_idINT玩家编号
device_idINT设备编号
event_dateDATE登录日期
games_playedINT当天完成游戏数

约束

  • (player_id, event_date) 唯一标识一条记录。
  • games_played ≥ 0；累计值包含当前日期。

题解

核心洞察：这不是按玩家压缩成一行的普通聚合；每条原记录都要保留，同时让 SUM 只看到同一玩家中日期不晚于当前行的记录。

完整过程

  1. 用 PARTITION BY player_id 为每位玩家建立独立窗口。
  2. 用 ORDER BY event_date 确定时间方向。
  3. 使用从分区开头到当前行的窗口帧，计算累计和。
  4. 投影题目要求的三列；外层排序仅用于稳定展示。

正确性说明

固定任意玩家与日期。分区排除了其他玩家；按日期排列且窗口帧从第一行延伸至当前行，因此窗口恰好包含该玩家所有不晚于当前日期的记录。对其中 games_played 求和，正好等于题目定义的截至当日累计游戏数。该论证对每一行成立，故查询正确。

边界

  • 第一次登录：累计值就是当天值。
  • 当天为 0：累计值保持不变。
  • 玩家之间完全隔离。
  • 日期有唯一性，但显式 ROWS 仍更清晰。

复杂度

数据库通常需要按玩家和日期排序：时间 O(n log n)，窗口扫描 O(n)；排序空间通常为 O(n)。合适索引可降低排序代价。

官方可提交语言：MySQL

SELECT
    player_id,
    event_date,
    SUM(games_played) OVER (
        PARTITION BY player_id
        ORDER BY event_date
        ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
    ) AS games_played_so_far
FROM Activity;

四语言本地语义参考

本题为数据库题；以下 Java、JavaScript、Python、C++ 仅演示对内存记录进行同等累计，不是 LeetCode 本题的官方提交语言。

Java

import java.util.*;

class Solution {
  record Row(int playerId, int deviceId, String date, int games) {}
  record Out(int playerId, String date, int total) {}

  static List<Out> cumulative(List<Row> rows) {
    rows = new ArrayList<>(rows);
    rows.sort(Comparator.comparingInt(Row::playerId)
        .thenComparing(Row::date));
    List<Out> ans = new ArrayList<>();
    int player = -1, sum = 0;
    for (Row r : rows) {
      if (r.playerId() != player) { player = r.playerId(); sum = 0; }
      sum += r.games();
      ans.add(new Out(player, r.date(), sum));
    }
    return ans;
  }
}

JavaScript

function cumulative(activity) {
  const rows = activity.slice().sort((a, b) =>
    a.player_id - b.player_id ||
    a.event_date.localeCompare(b.event_date));
  let player = null, sum = 0;
  return rows.map(row => {
    if (row.player_id !== player) {
      player = row.player_id;
      sum = 0;
    }
    sum += row.games_played;
    return { player_id: player,
      event_date: row.event_date,
      games_played_so_far: sum };
  });
}

def cumulative(activity):

C++

#include <algorithm>
#include <string>
#include <tuple>
#include <vector>
using namespace std;

struct Row { int player, device, games; string date; };
vector<tuple<int,string,int>> cumulative(vector<Row> rows) {
  sort(rows.begin(), rows.end(), [](const Row& a, const Row& b) {
    return tie(a.player, a.date) < tie(b.player, b.date);
  });
  vector<tuple<int,string,int>> ans;
  int player = -1, total = 0;
  for (const auto& r : rows) {
    if (r.player != player) player = r.player, total = 0;
    total += r.games;
    ans.emplace_back(player, r.date, total);
  }
  return ans;
}

替代方案

可用相关子查询，对每行累加同玩家且日期不晚于它的记录；逻辑直观但常退化为 O(n²)。也可自连接后分组，通常产生更大的中间结果。窗口函数最贴合“保留明细行并累计”的语义。

面试追问

  • 如果同一天可有多条记录，ROWS 与 RANGE 的结果有何不同？
  • 什么复合索引有利于该查询？通常是以 (player_id, event_date) 开头。
  • 如何只输出每位玩家的最终累计值？可先聚合，或对窗口结果再筛最后一行。

常见错误

  • 只写 GROUP BY player_id，丢失每日明细。
  • 遗漏 PARTITION BY，把所有玩家混在一起。
  • 遗漏日期顺序，得到玩家总和而非逐日累计。
  • 使用未来日期也进入窗口的帧范围。
