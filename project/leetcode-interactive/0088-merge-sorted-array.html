题意

给定两个按非递减顺序排列的整数数组。nums1 前 m 项有效，尾部另有 n 个预留位置；nums2 有 n 项。把两者合并后直接写入 nums1，函数不返回新数组。

  • nums1.length = m + n
  • nums2.length = n
  • 0 ≤ m, n ≤ 200，且 1 ≤ m+n ≤ 200
  • 元素范围为 [-10⁹, 10⁹]

输入代码中的 ␠ 表示一个可见空格，便于核对完整参数格式。

题解

核心洞察、完整过程、边界、复杂度、替代方案、面试追问、常见错误与四语言代码默认封存。

Core insight

空位在右侧，所以从右侧填

若从左向右写，nums2 的较小元素可能覆盖 nums1 尚未比较的有效元素。从右向左时，写入位置 k 总位于所有未处理有效元素之后；选择两个尾部的较大值，就能安全写回且保持最终顺序。

Loop invariant

k 右侧永远已经就位

每轮开始时，nums1[k+1…m+n−1] 已是合并结果中最大的那一段。比较 nums1[i] 与 nums2[j]，把较大者放到 k，随后左移对应指针与 k，不变量继续成立。

完整过程

  1. 令 i=m−1、j=n−1、k=m+n−1。
  2. 只要 j≥0，就比较两个尚未处理的尾部。
  3. 较大值写入 nums1[k]，并左移它的来源指针。
  4. 每轮左移 k；j<0 时结束。

边界

  • n=0：无需写入，nums1 保持不变。
  • m=0：依次把 nums2 全部写入 nums1。
  • i<0：之后只能从 nums2 取值。
  • j<0：nums1 剩余前缀已经在正确位置。
  • 重复值与负数不改变比较逻辑。

复杂度

时间 O(m+n)
每个有效元素最多写入一次。
空间 O(1)
只使用三个指针，直接修改 nums1。

替代方案取舍

前向双指针 + 副本：同为 O(m+n)，但需要 O(m) 额外空间，适合先讲归并思想。

拼接后排序：实现短，却退化到 O((m+n)log(m+n))，没有利用已排序条件。

面试追问

  • 为什么循环条件只需 j≥0？
  • 若 nums1 没有预留空间怎么办？
  • 如何证明 k 右侧始终有序且最终正确？
  • 输入改成链表时策略如何变化？

常见错误

  • 从左侧原地写回，覆盖未处理的 nums1 元素。
  • 误把 nums1 尾部的 0 当作有效值。
  • 在 i<0 后仍访问 nums1[i]。
  • 重新给 nums1 赋新数组，未按题意原地修改。

class Solution {
    public void merge(int[] nums1, int m, int[] nums2, int n) {
        int i = m - 1;
        int j = n - 1;
        int k = m + n - 1;

        while (j >= 0) {
            if (i >= 0 && nums1[i] > nums2[j]) {
                nums1[k--] = nums1[i--];
            } else {
                nums1[k--] = nums2[j--];
            }
        }
    }
}
