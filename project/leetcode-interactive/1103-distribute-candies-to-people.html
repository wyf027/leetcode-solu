题目

有 candies 颗糖，要依次分给排成一列的 num_people 个人。第一次给第 1 个人 1 颗，第二次给第 2 个人 2 颗，如此递增；走到队尾后回到队首，下一次仍比上一次计划多给 1 颗。若剩余糖果少于本次计划数，就把所有剩余糖果交给当前的人并结束。

返回长度为 num_people 的数组 ans，其中 ans[i] 是第 i + 1 个人最终得到的糖果数，且数组元素之和等于 candies。

示例 1

输入：candies = 7, num_people = 4
输出：[1,2,3,1]
解释：依次实际发出 1、2、3、1 颗。

示例 2

输入：candies = 10, num_people = 3
输出：[5,2,3]
解释：依次发出 1、2、3、4 颗，
第 1 个人累计得到 1 + 4 = 5 颗。
约束：1 ≤ candies ≤ 10⁹；1 ≤ num_people ≤ 1000。

Solution

题解：让一次循环对应一次发放

核心洞察

题目描述本身就是一个状态机。用 give 表示本轮计划发放量，从 1 开始递增；用 i % num_people 让接收者循环回到队首。真正发出的数量必须是 min(give, candies)，这一步统一处理正常轮次与最后一次不足额发放。

完整过程

  1. 创建全 0 数组 ans，长度为 num_people。
  2. 令 give = 1、i = 0。
  3. 还有糖时，将 min(give, candies) 累加给 ans[i % num_people]。
  4. 从剩余糖果中扣除实际发放量，然后让 give 与 i 各加 1。
  5. 糖果归零后返回 ans。

正确性说明

循环不变式：每次循环开始前，数组恰好记录此前所有轮次的发放结果，candies 是尚未发出的数量，give 是本轮规则要求的数量，i % num_people 是本轮接收者。循环按规则发出两者较小值，因此不变式继续成立。若糖果够，本轮完整发放并进入下一轮；若不够，本轮发完全部余量，循环结束。于是返回数组包含且仅包含全部原始糖果，并与题目顺序一致。

边界情况

  • 只有 1 颗：第一次发完。
  • 只有 1 个人：每轮都累加到同一位置。
  • 恰好在某轮发完：最后一轮实际量等于计划量。
  • 最后不足额：min 防止剩余量变成负数。
  • candies = 10⁹ 时，轮次数约为 √(2·candies)，模拟仍远小于十亿次。

复杂度

若一共进行 k 次发放，则 1 + 2 + … + k ≤ candies，所以 k = O(√candies)。时间复杂度 O(√candies)，返回数组之外的额外空间为 O(1)（返回数组占 O(num_people)）。

四语言完整实现

class Solution {
    public int[] distributeCandies(int candies, int num_people) {
        int[] ans = new int[num_people];
        int give = 1;
        int index = 0;
        while (candies > 0) {
            int actual = Math.min(give, candies);
            ans[index % num_people] += actual;
            candies -= actual;
            give++;
            index++;
        }
        return ans;
    }
}

替代方案

可以用二次公式先求能完整发放多少次，再按“完整轮 + 等差数列”直接计算每个人所得，最后处理余量。它可做到 O(num_people)，但推导更复杂；在本题约束下，简洁模拟通常更适合面试书写。

面试追问

  • 如何用二分或平方根求最大完整发放次数？
  • 如何推导每个人在若干完整轮中的等差数列和？
  • 若发放增量不再恒为 1，代码需要改哪一处？

常见错误

  • 用 give 直接扣减，导致最后一次出现负数。
  • 忘记用取模回到第一个人。
  • 覆盖 ans[pos] 而不是累加。
  • 把“第几个人”和数组下标混淆，造成偏移一位。
