DOSSIER 01

题意转述

给定整数数组 nums 和目标值 target，找出两个不同位置，使对应数字之和等于 target，返回它们的下标。题目保证恰好一组答案，顺序不限。

CASE A

[2,7,11,15], 9

→ [0,1]

CASE B

[3,2,4], 6

→ [1,2]

DUPLICATE

[3,3], 6

→ [0,1]

约束：2 ≤ nums.length ≤ 10⁴；元素与 target 均在 ±10⁹ 范围内。

CORE INSIGHT

一遍扫描，两种动作

查：need = target − nums[i] 是否在表中？

存：若没找到，登记 nums[i] → i。

查必须发生在存之前，否则 target = 2×nums[i] 时可能把同一个下标使用两次。

DOSSIER 02

完整解题过程

  1. 1. 初始化 value→index 哈希表。
  2. 2. 对每个 i 计算 need=target−nums[i]。
  3. 3. need 已出现则立即返回 [map[need], i]。
  4. 4. 否则登记 nums[i]→i，继续扫描。

WHY IT WORKS

循环不变量

处理 i 前，表中恰好保存所有 j<i 的值与下标。若 need 在表中，就得到两个不同下标；若不在，登记当前值供未来元素查询。唯一解保证最终必命中。

边界情况与复杂度

重复值

[3,3] 可正确返回两个下标。

负数

补数计算同样适用，无需特判。

时间 O(n)

每个元素查询、插入各一次。

空间 O(n)

最坏保存 n−1 个元素。

替代方案：暴力枚举 O(n²) 空间 O(1)；排序双指针会丢原下标，需额外保存索引。面试主推一遍哈希。

class Solution {
    public int[] twoSum(int[] nums, int target) {
        Map<Integer, Integer> seen = new HashMap<>();
        for (int i = 0; i < nums.length; i++) {
            int need = target - nums[i];
            if (seen.containsKey(need)) return new int[] {seen.get(need), i};
            seen.put(nums[i], i);
        }
        return new int[0];
    }
}

面试高频追问

为什么哈希表里存下标而不是布尔值？

命中补数时必须返回原下标，所以 value 需要映射到 index。

重复值会覆盖下标吗？

即使覆盖，只要题目保证唯一答案，先查后存仍会在第二个重复值到来时命中第一个。

常见错误

  • ❌ 先存后查：可能使用同一个元素两次。
  • ❌ 返回数字：题目要求下标。
  • ❌ 排序后丢索引：原下标关系被破坏。
  • ❌ 用 set：无法取回补数的下标。
