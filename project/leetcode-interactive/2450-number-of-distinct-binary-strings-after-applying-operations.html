01题目与输入

给定仅含 0 和 1 的字符串 s，以及正整数 k。每次可以选取一个长度恰为 k 的连续片段，将片段中的每一位取反。允许操作零次、一次或多次。

返回所有能够得到的不同最终字符串的数量，对 1,000,000,007 取模。同一结果即使有多种操作顺序，也只计一次。

函数接口

countDistinctStrings(s, k) → integer

s：二进制字符串；k：每次翻转长度。

完整约束
  • 1 ≤ k ≤ s.length ≤ 100000
  • s[i] ∈ {'0', '1'}

官方示例 1

输入：s = "1001", k = 3
输出：4

不翻转得到 1001；翻转起点 0 的窗口得到 0111；翻转起点 1 的窗口得到 1110；两个窗口各翻转一次得到 0000。共有四个不同结果，下标从 0 开始。

官方示例 2

输入：s = "10110", k = 5
输出：2

只有整个字符串可以被选中：原串 10110 与取反后的 01001，共两个结果。

04准备好推导了吗？

先想一想：操作次数没有上限，为什么不同结果的数量仍可直接计算？不同窗口的重叠是否会造成重复计数？

题解 · 用最左侧差异证明唯一性

核心洞察

记 n = s.length，长度为 k 的窗口共有 m = n − k + 1 个。对同一个位置取反相当于与 1 异或；异或的顺序无关，重复两次归零。因此，每个窗口只需记录翻转次数的奇偶性。

答案 = 2n − k + 1 mod 1,000,000,007

每个窗口有“偶数次”和“奇数次”两种选择。但要得到上述公式，必须证明：两组不同的奇偶选择不会产生相同字符串。

完整过程

  1. 读取长度 n，计算合法窗口起点数量 m；起点从 0 到 n − k，包含两端。
  2. 将所有操作序列归约为 m 个二进制选择，1 代表该窗口翻转奇数次。
  3. 通过下面的最左差异证明，这些选择与可达字符串一一对应。
  4. 从 ans = 1 开始，重复 m 次执行 ans = ans × 2 mod MOD，返回 ans。

例如 s = "1001"、k = 3：窗口 0 的翻转向量为 1110，窗口 1 为 0111。选择向量 (0,0)、(1,0)、(0,1)、(1,1) 分别得到 1001、0111、1110、0000。

正确性证明

覆盖所有操作序列：翻转可交换，且同一窗口翻转两次不改变任何位。任意操作序列都能化为每个窗口最多翻转一次，因而一定属于这些二进制选择之一。反过来，任意选择都可以通过逐个执行所选窗口实现。

不同选择产生不同结果：任取两组不同选择，令 i 为它们第一个不同的窗口起点。起点小于 i 的窗口选择相同，对位置 i 的贡献相同；起点大于 i 的窗口无法覆盖位置 i；起点恰为 i 的窗口覆盖位置 i，而两组选择在此不同。所以两个最终字符串在位置 i 必然不同。

计数与计算：m 个选择独立地取 0 或 1，一共 2m 组，且全部可达、互不重复。循环处理 j 个窗口后，ans 等于 2j 对 MOD 的余数；初始化 j = 0 成立，每次乘 2 保持不变式，结束时返回所需结果。

边界与复杂度

  • k = n：只有一个窗口，原串和整串取反共 2 种。
  • k = 1：每个字符都能独立取反，共 2n 种，返回取模结果。
  • n = k = 1：答案为 2；题目不含空串或 k > n。
  • 全 0、全 1 或任意其他内容：固定 n 和 k 时计数相同。
  • 下列四份代码统一采用逐次倍增。时间 O(n − k + 1)，最坏 O(n)；额外空间 O(1)，不计输入存储。
  • JavaScript 每次只计算小于 2 × MOD 的整数，处于 Number 的安全整数范围。无需指数运算或 BigInt。

四语言完整提交代码

接口名来自官方元数据。代码为独立编写的 LeetCode 提交形式；未编译或运行。

Java

class Solution {
    public int countDistinctStrings(String s, int k) {
        final int MOD = 1_000_000_007;
        int ans = 1;
        int windows = s.length() - k + 1;
        for (int i = 0; i < windows; i++) {
            ans = (ans * 2) % MOD;
        }
        return ans;
    }
}

替代方案

模快速幂：用反复平方将算术时间降为 O(log m)，迭代实现额外空间 O(1)。Python 可直接使用 pow(2, m, 1_000_000_007)。Java/C++ 的模乘需要 64 位中间值；JavaScript 的一般模乘可能超出安全整数范围，应使用 BigInt。当前上限为 105，逐次倍增更简洁。

BFS / 枚举：适合小输入的教学探索，最坏有 2m 个状态，无法用于题目上限。实验室使用格雷码 t ^ (t >> 1) 遍历选择向量，相邻两步仅改变一个窗口，便于看清重叠翻转；限制 12 位仅为交互可读性，算法代码支持完整约束。

常见错误

  • 只说“每个窗口选或不选”就直接计数：缺少证明不同选择不会碰撞。
  • 把窗口数量写成 n − k，遗漏最后一个合法起点。
  • 把 k 当成允许执行的操作次数，或认为窗口不能重叠。
  • 按操作顺序计数：同一窗口两次抵消，交换操作顺序也不改变结果。
  • 先求完整 2m 再取模，导致溢出或不必要的大整数开销；JS 的 ^ 是异或，不是幂。
  • 用“有多少个 1”推答案：字符串内容只改变可达集合，不改变集合大小。

面试追问

  • 如果窗口允许环绕字符串尾部？最左起点的证明失效。把操作写成 GF(2) 上的向量，答案为 2 的矩阵秩次方；窗口可能线性相关。
  • 如何判断目标串 t 是否可达？从左到右贪心：当前位置不同且还能开始窗口时，必须翻转；最后 k − 1 位必须吻合。结合差分奇偶标记可做到 O(n)。
  • 要求恰好执行 r 次呢？某个选择向量有 h 个 1 时，可行条件为 h ≤ r 且 r − h 为偶数，因为可以添加成对的重复操作。对符合条件的 h 累加组合数 C(m,h)。
  • 为什么与 s 无关？所有翻转效果与固定的 s 异或，这是一个可逆映射，不改变数量。
