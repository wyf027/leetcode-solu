题意与样例

“链表”仍使用原来的 TreeNode。所有节点只通过 right 相连，顺序必须与原树前序遍历一致。

Dispatch manual / Solution

题解：前驱换轨法

主线采用迭代原地改指针：若当前节点有左子树，就把左子树的最右节点当作前驱，将原右子树接到它后面，再把整棵左子树挪到右侧。

核心洞察

前序顺序是“根、左、右”。因此在当前节点之后，左子树应整体排在原右子树之前。左子树前序序列的最后一个节点正是沿右指针能到达的最右节点；让它指向原右子树，就能无损拼接两段。

完整过程

  1. 从 current = root 开始沿右指针前进。
  2. 若 current.left 为空，直接进入下一个右节点。
  3. 否则从左孩子出发，沿 right 找到最右节点 predecessor。
  4. 令前驱的右指针接到当前节点原来的右子树。
  5. 把左子树整体移到 current.right，并清空 current.left。

边界

  • 空树直接结束。
  • 单节点树保持不变。
  • 已经只有右链的树只需线性扫描，不改任何指针。
  • 纯左链会在每层执行一次换轨，最终按从上到下连接。
  • 必须复用原节点，不能创建新的链表节点替代它们。

复杂度

时间 O(N) 每条边只被常数次访问；前驱查找总成本仍为线性。
额外空间 O(1) 只维护 current 与 predecessor 两个节点指针。

替代方案取舍

显式栈按“先压右、再压左”可直观生成前序链，但需要 O(H) 到 O(N) 空间；递归逆前序“右、左、根”配合前驱指针代码简洁，却使用 O(H) 调用栈。前驱换轨法满足官方 O(1) 追问，面试展示力更强。

面试追问

  • 为什么左子树的最右节点一定是这一段前序序列的最后节点？
  • 嵌套查找最右节点为何不会退化成 O(N²)？
  • 如何证明换轨后节点身份与数量完全不变？
  • 如果要求中序或后序顺序展开，指针策略如何变化？

常见错误

  • 先覆盖 current.right，导致原右子树引用丢失。
  • 把原右子树接到左孩子而不是左子树最右节点，破坏前序顺序。
  • 忘记把 current.left 置空，结果仍不是合法右链。
  • 换轨后沿旧指针前进，重复访问或漏掉节点。
  • 误判嵌套循环为 O(N²)，没有分析每条右边的摊还访问次数。

class Solution {
    public void flatten(TreeNode root) {
        TreeNode current = root;

        while (current != null) {
            if (current.left != null) {
                TreeNode predecessor = current.left;
                while (predecessor.right != null) {
                    predecessor = predecessor.right;
                }

                predecessor.right = current.right;
                current.right = current.left;
                current.left = null;
            }
            current = current.right;
        }
    }
}
