2303. 计算应缴税款总额

Calculate Amount Paid in Taxes

一份收入，多个税级。先理解每个区间的计税规则，再亲手拆开这张税单。

阅读题目 ↓交互实验 ↓测试与验证 ↓

01 / THE BRIEF

题目与输入约定

给定从下标 0 开始的二维整数数组 brackets，其中 brackets[i] = [upper_i, percent_i] 表示第 i 个税级的收入上限及百分比税率。上限严格递增。

收入从 0 开始划入各个税级：第一段长度为 upper_0，第二段长度为 upper_1 − upper_0，后面依此类推。每段只对落入这一段的收入收取对应比例的税款。税率本身不保证递增。

给定整数总收入 income，返回总税款（浮点数），允许与标准答案误差不超过 10⁻⁵。

参数形式：calculateTax(brackets, income) → double / number / float。这是题目定义的计税模型。

约束

  • 1 ≤ brackets.length ≤ 100
  • 1 ≤ upper_i ≤ 1000
  • 0 ≤ percent_i ≤ 100
  • 0 ≤ income ≤ 1000

数组保证

  • 所有数值均为整数。
  • 各上限互不相同，按递增顺序排列。
  • 最后一个税级上限大于等于总收入。

官方示例

示例 1

brackets = [[3,50],[7,10],[12,25]]
income = 10

输出：2.65000

三段收入分别为 3、4、3；对应税款 1.50、0.40、0.75，合计 2.65。

示例 2

brackets = [[1,0],[4,25],[5,50]]
income = 2

输出：0.25000

前 1 的税率为 0%，剩余 1 的税率为 25%，合计 0.25。

示例 3

brackets = [[2,50]]
income = 0

输出：0.00000

总收入为 0，无需缴税。

    04 / EDITORIAL

    独立题解

    准备好后展开，阅读推导与四语言实现。

    核心洞察：对收入区间求交集

    当前税级对应区间 (prev, upper]，实际收入覆盖 (0, income]。只有交集需要按当前税率计税。顺序扫描时，若 income ≤ prev 就结束，否则本段计税收入为 min(income, upper) − prev。

    累加整数 weighted += amount × percent，扫描完成后统一除以 100.0。这样避免逐段浮点累加；weighted 是“收入乘百分数”的总和，不是已经换算好的税款。

    完整过程

    1. 设置 prev = 0、weighted = 0。
    2. 按数组顺序读取 [upper, percent]。若收入不超过 prev，所有收入都已计税，立即结束。
    3. 算出 amount = min(income, upper) − prev，累加 amount × percent。
    4. 令 prev = upper，进入下一个税级。
    5. 返回 weighted / 100.0。
    税级prevupper计税收入税率weighted 累计
    003min(10,3) − 0 = 350%150
    137min(10,7) − 3 = 410%190
    2712min(10,12) − 7 = 325%265

    最终返回 265 / 100 = 2.65。

    正确性：循环不变式

    每轮开始，前面所有税级与收入范围的交集都已按各自税率恰好计算一次，weighted 等于这些交集的加权总额；prev 是前一税级的上限。初始没有处理任何税级，累计为 0，成立。

    若 income > prev，本轮交集长度恰为 min(income, upper) − prev。税级互不重叠，所以累加这一项不会重复计税，并保持不变式。若 income ≤ prev，后续税级均在收入范围之外，可以安全终止。最后上限覆盖收入，循环结束后所有收入均已处理；除以 100 即得到总税款。

    边界与精度

    • 收入为 0：首轮直接结束，返回 0。
    • 收入恰好等于上限：该段完整计税，后续没有贡献。
    • 收入在首段或中间段：只结算该段已覆盖的部分。
    • 税率可以是 0%、100%，也可以先高后低；代码无需特殊分支。
    • 整数累计最多 1000 × 100 = 100000，本题中 32 位整数足够，最后使用浮点除法。

    复杂度

    令 n = brackets.length。时间复杂度 O(n)，最多逐个访问税级；额外空间 O(1)。交互页面为展示保留步骤记录，不属于提交算法的空间开销。

    替代方案

    可以维护剩余收入，每段取 min(remaining, upper − prev) 后扣除，仍为 O(n) 时间和 O(1) 空间。也可以对所有税级使用 max(0, min(income, upper) − prev) 而不提前结束。单次查询直接顺序扫描最简单；多次查询同一税表时可预计算各完整税段前缀和，再二分定位收入所在税级，实现 O(n) 预处理、O(log n) 每次查询、O(n) 空间。

    常见错误

    • 用总收入乘以最后税级的税率，忽略分段规则。
    • 把上限当成本段宽度，漏掉减去 prev。
    • 遍历超过收入的税级却不提前停止或截断，得到负税款。
    • 先做整数除法 percent / 100，使不足 100% 的税率变成 0。
    • 因税率不递增而重新排序，破坏原来的区间与税率对应关系。

    面试追问

    • 为什么不需要排序？输入已经按上限严格递增。
    • 能否处理小数收入？保留同样的区间思路；若扩展到真实金额，可按最小货币单位使用整数或十进制定点数，并明确舍入规则。
    • 若收入超过最后上限？本题保证不会发生；扩展模型应先定义超出部分的税率，不能自行假设。
    • 如何优化大量收入查询？复用税表前缀加权和与二分查找。

    Java

    class Solution {
    public double calculateTax(int[][] brackets, int income) {
        int prev = 0, weighted = 0;
        for (int[] bracket : brackets) {
            if (income <= prev) break;
            int amount = Math.min(income, bracket[0]) - prev;
            weighted += amount * bracket[1];
            prev = bracket[0];
        }
        return weighted / 100.0;
    }
}

    let prev = 0, weighted = 0;
    for (const [upper, percent] of brackets) {
