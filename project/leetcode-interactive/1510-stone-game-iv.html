04 / SOLUTION

把输赢压缩成一维状态

不必枚举完整博弈树。每个局面只由“当前剩余多少石子”决定，且所有转移都会落到更小的状态。

核心洞察

定义 dp[i]：还剩 i 个石子、轮到当前玩家行动时，当前玩家能否必胜。只要存在一个合法平方数 j² ≤ i，使取走后对手面对负态 dp[i-j²] = false，那么 i 就是胜态。

dp[0] = false
dp[i] = 存在 j ≥ 1，j² ≤ i 且 dp[i-j²] = false

完整过程

  1. 创建长度 n + 1 的布尔数组，默认均为 false。
  2. 从 i = 1 递增到 n，枚举不超过 i 的所有平方数 j²。
  3. 若发现 dp[i-j²] 为 false，立即把 dp[i] 设为 true 并停止当前枚举。
  4. 最终返回 dp[n]。

正确性证明

基础：i = 0 时没有合法操作，当前玩家必输，所以 dp[0] = false 正确。

归纳：假设所有小于 i 的状态均已正确。若存在一次操作到负态 i-j²，当前玩家可选该操作，随后无论对手如何都处于必败局面，因此 dp[i] 为 true。反之，若所有合法操作都到达胜态，则每种选择都会把必胜局面交给对手，当前玩家无法强制获胜，因此 dp[i] 为 false。由归纳法，dp[n] 正确。

边界与复杂度

  • n = 1：可直接拿走 1，结果为 true。
  • 完全平方数：可一步转移到 dp[0]，一定是胜态。
  • 时间：外层 n 个状态，每个状态至多枚举 √n 个平方数，O(n√n)。
  • 空间：保存 n + 1 个状态，O(n)。

常见错误

  • 把“存在一个负态后继”误写成“所有后继都是负态”。
  • 忘记 dp[0] 是负态，导致完全平方数判断错误。
  • 使用 j < √i，漏掉 j² = i。
  • 只做贪心，默认总拿最大的平方数；最优策略并不满足该贪心性质。
  • 递归搜索不做记忆化，导致指数级重复计算。

替代方案与面试追问

替代方案：可以用自顶向下 DFS + 记忆化搜索，状态和转移完全相同，复杂度仍为 O(n√n)，但递归深度和函数开销更高。直接展开 Minimax 树则会重复访问大量相同剩余量。

  • 如果允许拿走的数来自任意集合，如何改动转移？
  • 如何恢复一条双方最优操作序列？
  • 若有多堆石子，状态还能否保持一维？何时需要 Sprague–Grundy？
  • 能否用预生成平方数列表减少重复乘法？

class Solution {
    public boolean winnerSquareGame(int n) {
        boolean[] dp = new boolean[n + 1];

        for (int stones = 1; stones <= n; stones++) {
            for (int root = 1; root * root <= stones; root++) {
                int next = stones - root * root;
                if (!dp[next]) {
                    dp[stones] = true;
                    break;
                }
            }
        }
        return dp[n];
    }
}
