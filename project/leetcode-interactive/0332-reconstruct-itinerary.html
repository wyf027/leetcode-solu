01 · Briefing

先确认任务边界

输入中的每张机票是一条有方向的航线。返回从 JFK 开始、使用完全部机票的机场序列；若答案不唯一，选择整体字典序最小者。

题意转述

给定航线列表 tickets，其中 tickets[i] = [fromᵢ, toᵢ] 表示一张从出发机场到到达机场的机票。

行程必须从 "JFK" 开始，并且每张机票都要使用一次且只能使用一次。题目保证至少存在一条合法行程。

如果有多条合法行程，返回把机场代码序列从左到右比较时字典序最小的一条。例如 ["JFK","LGA"] 小于 ["JFK","LGB"]。

约束

  • 1 <= tickets.length <= 300
  • tickets[i].length == 2
  • fromᵢ.length == 3
  • toᵢ.length == 3
  • fromᵢ 与 toᵢ 只含大写英文字母
  • fromᵢ != toᵢ

重新安排行程完整题解

核心洞察

把机场看成顶点、机票看成有向边，题目要求从 JFK 出发恰好使用每条边一次，本质上是在找一条有向欧拉路径。

不能只做“每次选字典序最小的下一站”的普通贪心，因为较小的边可能太早走进死路。Hierholzer 算法的关键是：先持续消耗边；只有当前顶点无边可走时，才把它加入答案。加入顺序与最终行程相反，所以最后反转。

完整过程

  1. 按出发机场建立邻接表；每个机场的目的地按字典序组织。
  2. 从 JFK 开始深度探索。每次取走当前机场字典序最小的未使用机票。
  3. 当某机场已无未使用的出边，把该机场加入逆序结果并返回上一层。
  4. 所有边都被消耗后，反转逆序结果，得到最终行程。

正确性证明

引理 1：每张机票恰好使用一次。

一张机票在从邻接结构中取出时被使用，取出后不会再次出现。算法持续到从 JFK 可达的未使用边全部耗尽；题目保证所有机票能组成合法行程，因此所有机票最终都被取出一次。

引理 2：反转后的相邻机场由有效机票连接。

顶点只有在无剩余出边时才加入逆序结果。回溯拼接会把已经完成的闭合子路径插入其进入点；因此反转后的每对相邻顶点都对应探索时实际取走的一条边。

引理 3：所得合法行程字典序最小。

对任一尚未确定的分叉点，算法优先消耗字典序最小的可用目的地。若该边进入临时死路，回溯机制会把已完成片段放到最终序列的正确后部，而不会破坏可行性。于是最终序列在第一个可能产生差异的位置选择了可行的最小目的地。

结论。

由三个引理，算法返回从 JFK 出发、恰好使用所有机票且字典序最小的合法行程。

复杂度与边界

设机票数为 E，机场数为 V。

  • 时间：排序或优先队列使总复杂度为 O(E log E)；遍历本身为 O(E)。
  • 空间：邻接表、递归栈与答案共 O(E + V)。
  • 重复机票：每张边独立入表，重复航线会被逐张消耗，不能用集合去重。
  • 终点无出边：它会最先进入逆序结果，反转后自然位于行程末尾。
  • 最多 300 张票：递归深度至多 301 个机场；四份实现均按题目规模设计。

四语言完整实现

Java · PriorityQueue 
class Solution {
    private final Map<String, PriorityQueue<String>> graph = new HashMap<>();
    private final LinkedList<String> route = new LinkedList<>();

    public List<String> findItinerary(List<List<String>> tickets) {
        for (List<String> ticket : tickets) {
            graph.computeIfAbsent(ticket.get(0), key -> new PriorityQueue<>())
                 .offer(ticket.get(1));
        }

        visit("JFK");
        return route;
    }

    private void visit(String airport) {
        PriorityQueue<String> destinations = graph.get(airport);
        while (destinations != null && !destinations.isEmpty()) {
            visit(destinations.poll());
        }
        route.addFirst(airport);
    }
}
JavaScript · 逆序排序后 pop 
/**
 * @param {string[][]} tickets
 * @return {string[]}
 */
var findItinerary = function (tickets) {
    const graph = new Map();

    for (const [from, to] of tickets) {
        if (!graph.has(from)) graph.set(from, []);
        graph.get(from).push(to);
    }

    // 降序排列后从尾部弹出，可在 O(1) 时间取得最小目的地。
    for (const destinations of graph.values()) {
        destinations.sort((a, b) => b.localeCompare(a));
    }

    const reversed = [];

    function visit(airport) {
        const destinations = graph.get(airport);
        while (destinations && destinations.length > 0) {
            visit(destinations.pop());
        }
        reversed.push(airport);
    }

    visit("JFK");
    reversed.reverse();
    return reversed;
};
Python · 最小堆 
from collections import defaultdict
import heapq
from typing import List


class Solution:
    def findItinerary(self, tickets: List[List[str]]) -> List[str]:
        graph = defaultdict(list)

        for source, destination in tickets:
            heapq.heappush(graph[source], destination)

        reversed_route = []

        def visit(airport: str) -> None:
            while graph[airport]:
                visit(heapq.heappop(graph[airport]))
            reversed_route.append(airport)

        visit("JFK")
        return reversed_route[::-1]
C++ · 小顶优先队列 
class Solution {
private:
    unordered_map<
        string,
        priority_queue<string, vector<string>, greater<string>>
    > graph;
    vector<string> reversedRoute;

    void visit(const string& airport) {
        auto& destinations = graph[airport];
        while (!destinations.empty()) {
            string next = destinations.top();
            destinations.pop();
            visit(next);
        }
        reversedRoute.push_back(airport);
    }

public:
    vector<string> findItinerary(vector<vector<string>>& tickets) {
        for (const auto& ticket : tickets) {
            graph[ticket[0]].push(ticket[1]);
        }

        visit("JFK");
        reverse(reversedRoute.begin(), reversedRoute.end());
        return reversedRoute;
    }
};

替代方案

  • 回溯枚举：逐步尝试未使用机票并在失败时撤销，思路直接，但最坏会枚举大量排列，接近指数级，300 张票不可取。
  • 迭代 Hierholzer：用显式栈替代递归；当栈顶仍有出边时压入下一站，否则弹出到逆序结果。复杂度相同，也能避免语言的递归深度限制。

面试追问

  • 为什么不是普通 DFS 后序？ 本题 DFS 还必须在遍历时删除边，且多重边不能被 visited 顶点数组代替。
  • 如何避免递归？ 维护机场栈；有边就压入，无边就弹出到答案。
  • 若不保证存在合法行程？ 需要检查欧拉路径的入度/出度条件、起点条件和相关顶点的连通性，并确认最终使用了全部 E 条边。
  • 若要在线加入机票？ 动态维护全局字典序最小欧拉路径并不等同于局部插入，通常需重新计算或采用更复杂的动态结构。

常见错误

  • 每到一个机场就贪心选最小目的地并立即写入最终答案，可能提前进入无法继续的终点。
  • 使用 Set 保存航线，导致完全相同的重复机票被合并。
  • 忘记答案是后序收集，遗漏最后的反转或头插。
  • JavaScript 将目的地升序排序后反复 shift()，会产生额外搬移成本；可改为降序排序配合 pop()。
  • 只按当前出发机场排序输入，却没有为每个邻接表保持稳定的字典序取边结构。
