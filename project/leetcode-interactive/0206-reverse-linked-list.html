反转链表
Reverse Linked List

每轮只改变一条 next 指针：先保住后继，再把箭头调头，最后推进两个指针。

题意

给定单链表头节点 head，将整个链表反转，并返回反转后的头节点。

约束
节点数量范围为 0 到 5000；节点值范围为 −5000 到 5000。

官方样例（转述）

输入head = [1, 2, 3, 4, 5]输出[5, 4, 3, 2, 1]
输入head = [1, 2]输出[2, 1]
输入head = []输出[]

题解：迭代地翻转一条边

维护两个指针：prev 是已反转部分的头，curr 是尚未处理部分的头。关键是在改写 curr.next 前，先用 next 保存原来的后继。

  1. next = curr.next：防止剩余链断失。
  2. curr.next = prev：让当前节点的箭头反向。
  3. prev = curr; curr = next：两指针同步前进。
循环不变量：每轮开始时，prev 指向已反转的前缀，curr 指向还保持原顺序的后缀；两者覆盖全部节点且不重叠。

完整过程

对 1 → 2 → 3：先得到 1 → null；接着 2 → 1 → null；最后 3 → 2 → 1 → null。循环结束时 curr 为 null，prev 正是新头。

边界与复杂度

空链表与单节点无需特殊分支；循环自然返回原头。时间 O(n)，额外空间 O(1)。

替代方案

递归写法更短：反转后继后把后继的 next 指向当前节点。但递归调用栈为 O(n)，链表很长时迭代更稳健；题目追问要求了解两者。

面试追问

若只反转区间 [left, right]，先走到区间前驱，再在区间内做同样的头插翻转。若链表可能成环，先用快慢指针判断环再讨论反转语义。

常见错误

  • 未保存 next 就改写 curr.next，会丢失后半段。
  • 返回 curr 而不是最终的 prev。
  • 递归中忘记 head.next = null，会产生环。
