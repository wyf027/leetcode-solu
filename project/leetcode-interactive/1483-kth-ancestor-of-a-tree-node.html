树节点的第 K 个祖先Kth Ancestor of a Tree Node

把一棵树装进可重复查询的数据结构：每次给出节点 node 和距离 k，返回沿父链向上的第 k 个节点；越过根节点则返回 -1。

树设计动态规划位运算至多 50,000 次查询
01 / Problem

先把接口读准确

题意

给定一棵包含 n 个节点的有根树，节点编号为 0 到 n - 1。数组 parent 描述父子关系：parent[i] 是节点 i 的父节点，根节点为 0，且 parent[0] = -1。

第 k 个祖先：从当前节点出发，沿父指针恰好向上走 k 条边后到达的节点。若途中已经越过根节点，则答案为 -1。

需要实现的接口

  • TreeAncestor(int n, int[] parent)
    用节点数量与父数组初始化对象。
  • int getKthAncestor(int node, int k)
    返回 node 的第 k 个祖先，不存在时返回 -1。

约束

  • 1 ≤ k ≤ n ≤ 5 × 10⁴
  • parent.length == n
  • parent[0] == -1
  • 对所有 0 < i < n，0 ≤ parent[i] < n
  • 0 ≤ node < n
  • 查询次数至多为 5 × 10⁴

官方示例（完整参数形式）

输入
["TreeAncestor", "getKthAncestor", "getKthAncestor", "getKthAncestor"]
[[7, [-1, 0, 0, 1, 1, 2, 2]], [3, 1], [5, 2], [6, 3]]

输出
[null, 1, 0, -1]

解释
TreeAncestor treeAncestor = new TreeAncestor(7, [-1, 0, 0, 1, 1, 2, 2]);
treeAncestor.getKthAncestor(3, 1); // 1：节点 3 的父节点
treeAncestor.getKthAncestor(5, 2); // 0：节点 5 的祖父节点
treeAncestor.getKthAncestor(6, 3); // -1：不存在这样的祖先

03 / Solution

准备好看完整解法了吗？

题解被刻意放在首屏之后并默认收起。先用实验室形成直觉，再展开证明与实现。

Core insight

倍增：预处理每个节点的 2j 级祖先

父节点能让我们向上走 1 步；如果同时记住向上走 2、4、8…步会到哪里，那么任意 k 都能按二进制拆分，在对数次跳跃内完成查询。

预处理时间O(n log n)
单次查询O(log n)
空间O(n log n)

完整过程

  1. 确定层数。
    令 LOG = ⌈log₂ n⌉（实现中可取能覆盖 n 的位数），保证每个合法的 k 都能被表示。
  2. 建立倍增表。
    up[v][0] = parent[v]；若 up[v][j-1] 存在，则 up[v][j] = up[up[v][j-1]][j-1]，否则为 -1。
  3. 拆解查询。
    从低位到高位检查 k。若第 j 位为 1，就把 node 更新为 up[node][j]。
  4. 处理越界。
    任一步得到 -1 即可直接返回；否则扫描完成后的节点就是答案。

正确性证明

引理：对任意节点 v 和有效下标 j，up[v][j] 等于 v 的第 2^j 个祖先；不存在时为 -1。

基础情形 j=0 由定义成立。归纳假设 j-1 成立：先从 v 到达其第 2^(j-1) 个祖先，再从该节点向上走同样距离，合计恰为 2^j；因此递推式保持结论。

定理：查询按 k 的二进制置位依次跳跃。各跳跃距离之和恰为 k，而祖先关系沿唯一父链可组合，所以最后得到的正是第 k 个祖先；若某段不存在，完整的第 k 个祖先也必不存在，返回 -1 正确。

边界情况

  • 根节点查询：根的任何正数级祖先均不存在。
  • k 大于节点深度：跳跃过程中得到 -1。
  • 链状树：倍增仍保持相同复杂度，不会退化为逐级遍历。
  • 最小 n：构造层数至少为 1，避免空表。

常见错误

  • 把“第 k 个祖先”误解为路径上包含自己在内的第 k 个节点；本题是向上走 k 条边。
  • 递推时没有先判断中间祖先是否为 -1，导致非法数组下标。
  • LOG 少开一列，无法覆盖 k = n 的最高位。
  • 每次查询沿父指针逐级走，最坏总复杂度达到 O(qn)。

替代方案与取舍

逐级沿父链：无需额外预处理，但单次 O(k)，在 50,000 次查询下可能超时。欧拉序 + 层级祖先结构：可扩展到更复杂的树查询，但对本题接口过重。倍增利用树静态、查询多的特征，代码规模与性能最均衡。

class TreeAncestor {
    private final int[][] up;
    private final int log;

    public TreeAncestor(int n, int[] parent) {
        log = 32 - Integer.numberOfLeadingZeros(n);
        up = new int[n][log];

        for (int v = 0; v < n; v++) {
            up[v][0] = parent[v];
        }
        for (int j = 1; j < log; j++) {
            for (int v = 0; v < n; v++) {
                int middle = up[v][j - 1];
                up[v][j] = middle == -1 ? -1 : up[middle][j - 1];
            }
        }
    }

    public int getKthAncestor(int node, int k) {
        for (int j = 0; j < log && node != -1; j++) {
            if (((k >> j) & 1) == 1) {
                node = up[node][j];
            }
        }
        return node;
    }
}

var TreeAncestor = function (n, parent) {
    this.log = Math.max(1, Math.ceil(Math.log2(n + 1)));
    this.up = Array.from({ length: n }, () => Array(this.log).fill(-1));

    for (let v = 0; v < n; v++) {
        this.up[v][0] = parent[v];
    }
    for (let j = 1; j < this.log; j++) {
        for (let v = 0; v < n; v++) {
            const middle = this.up[v][j - 1];
            this.up[v][j] = middle === -1 ? -1 : this.up[middle][j - 1];
        }
    }
};

/**
 * @param {number} node
 * @param {number} k
 * @return {number}

TreeAncestor.prototype.getKthAncestor = function (node, k) {
    for (let j = 0; j < this.log && node !== -1; j++) {
        if ((k & (2 ** j)) !== 0) {
            node = this.up[node][j];
        }
    }
    return node;
};
from typing import List


class TreeAncestor:
    def __init__(self, n: int, parent: List[int]):
        self.log = max(1, n.bit_length())
        self.up = [[-1] * self.log for _ in range(n)]

        for node in range(n):
            self.up[node][0] = parent[node]

        for jump in range(1, self.log):
            for node in range(n):
                middle = self.up[node][jump - 1]
                if middle != -1:
                    self.up[node][jump] = self.up[middle][jump - 1]

    def getKthAncestor(self, node: int, k: int) -> int:
        bit = 0
        while k and node != -1:
            if k & 1:
                node = self.up[node][bit]
            k >>= 1
            bit += 1
        return node
class TreeAncestor {
    vector<vector<int>> up;
    int log;

public:
    TreeAncestor(int n, vector<int>& parent) {
        log = 1;
        while ((1 << log) <= n) ++log;
        up.assign(n, vector<int>(log, -1));

        for (int v = 0; v < n; ++v) {
            up[v][0] = parent[v];
        }
        for (int j = 1; j < log; ++j) {
            for (int v = 0; v < n; ++v) {
                int middle = up[v][j - 1];
                if (middle != -1) {
                    up[v][j] = up[middle][j - 1];
                }
            }
        }
    }

    int getKthAncestor(int node, int k) {
        for (int j = 0; j < log && node != -1; ++j) {
            if (k & (1 << j)) {
                node = up[node][j];
            }
        }
        return node;
    }
};

面试追问

  • 如果还要支持最低公共祖先（LCA）？先把两节点提升到同深度，再从高位向低位同时跳跃。
  • 如果树会动态添加叶子？可为新节点在线计算其整行倍增表；若允许改父节点，则需要更强的动态树结构。
  • 为什么不必 DFS？parent 已直接给出每个节点的一阶祖先，倍增表不依赖遍历顺序。
  • 能否从高位扫描 k？可以；沿同一条唯一父链，合法跳跃距离相加的顺序不影响终点。

复杂度展开

表共有 n × LOG 个状态，每个状态由至多一次查表得到，因此预处理时间与空间均为 O(n log n)。每次查询最多检查 LOG 个二进制位，时间为 O(log n)。

!
实现提示
JavaScript 位运算是 32 位有符号语义；本题 n ≤ 5 × 10⁴，因此位数安全。示例实现也用 2 ** j 构造掩码，语义更直观。
