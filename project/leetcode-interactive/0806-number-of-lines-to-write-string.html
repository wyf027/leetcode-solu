写字符串需要的行数

Number of Lines To Write String — 把每个字母当成一段真实宽度，在 100 像素的纸带上逐个排版。

● 简单 数组 字符串 非会员题
01 / PROBLEM

题意与边界

先理解纸带如何换行。解法被放在页面底部，默认不会提前展开。

给定只含小写英文字母的字符串 s，以及长度为 26 的数组 widths。其中 widths[0] 表示字母 a 的像素宽度，依次对应到 widths[25] 的 z。

从 s 的开头开始书写。每一行最多容纳 100 像素：当前行能放下某个字母时就继续写；如果加入该字母会超过 100 像素，则把它写到下一行，再继续处理后面的字母。

返回一个长度为 2 的整数数组：

  • result[0]：写完整个字符串所使用的总行数；
  • result[1]：最后一行已经使用的像素宽度。

最终要回答

  1. 用了多少行？
    行宽上限始终是 100。
  2. 最后一行多宽？
    只统计实际写入的宽度。

示例 1

输入：
widths = [10,10,10,10,10,10,10,10,10,10,10,10,10,10,10,10,10,10,10,10,10,10,10,10,10,10]
s = "abcdefghijklmnopqrstuvwxyz"

输出： [3,60]

abcdefghij 与 klmnopqrst 各占 100 像素，uvwxyz 占 60 像素。

已经形成自己的思路了吗？

题解包含线性模拟、正确性说明、复杂度、四种语言实现与面试延伸。展开前，可以先用上方排版台走完两个示例。

题解：一次扫描，维护当前行

把写字过程原样翻译成状态更新，不需要真的保存每一行的字符串。

核心洞察 遍历到一个字符时，只需要知道两个状态：目前已经使用的行数，以及最后一行当前占了多宽。若“当前宽度 + 新字符宽度”超过 100，就新增一行，并让新行宽度等于该字符宽度；否则直接累加。

完整过程

  1. 初始化 lines = 1、lastWidth = 0。
  2. 按从左到右的顺序读取 s 中的字符。
  3. 用字符与 'a' 的编码差找到它在 widths 中的下标。
  4. 如果加入后大于 100，令行数加一，并把末行宽度重置为当前字符宽度。
  5. 否则，把当前字符宽度累加到末行。
  6. 遍历结束后返回 [lines, lastWidth]。

边界与不变量

  • 单字符：初始的一行直接容纳它。
  • 恰好 100：条件必须是 > 100，等于 100 仍在当前行。
  • 下一字符溢出：该字符必须立即成为新一行的第一个字符，不能遗漏。
  • 字符映射：widths[c - 'a'] 与 26 个小写字母一一对应。
  • 合法宽度：每个字符最多 10，因此单个字符总能放进空行。

正确性说明

循环不变量：处理完前 i 个字符后，lines 等于按题目规则写完这段前缀所需的行数，lastWidth 等于其最后一行的准确宽度。

开始时还没有写字符，一条宽度为 0 的当前行满足不变量。处理下一个字符时：若它能放入当前行，累加宽度与题目规则一致；若不能放入，题目强制另起一行，算法同样让行数加一并以该字符宽度开始新行。因此每一步都保持不变量。所有字符处理完毕时，不变量直接给出题目要求的两个返回值。

时间复杂度 O(n) 额外空间 O(1)

四语言完整实现

Java · 官方可提交签名
class Solution {
    public int[] numberOfLines(int[] widths, String s) {
        int lines = 1;
        int lastWidth = 0;

        for (char c : s.toCharArray()) {
            int charWidth = widths[c - 'a'];
            if (lastWidth + charWidth > 100) {
                lines++;
                lastWidth = charWidth;
            } else {
                lastWidth += charWidth;
            }
        }

        return new int[] {lines, lastWidth};
    }
}

替代方案

可以真的构造一个“行数组”，把每个字符放进对应行，最后读取行数与末行宽度。它更接近排版模型，但会保存题目没有要求的内容，额外空间达到 O(n)。只维护两个整数更直接。

不能简单用所有字符总宽度除以 100：字符不可拆分，某行末尾留下的空隙无法自动转移给下一行。

面试追问

  • 如果行宽上限不是 100，如何改成参数化实现？
  • 如果字符流非常长、无法一次放进内存，如何在线处理？
  • 如果字符集扩展到 Unicode，宽度映射应如何存储？
  • 如果要求返回每一行的起止下标，需要增加哪些状态？

常见错误

  • 把溢出条件写成 >= 100，导致恰好占满的字符错误换行。
  • 换行时把宽度清零，却忘记把当前字符写入新行。
  • 从 0 开始统计行数，最后对非空字符串得到少一行。
  • 直接返回所有字符宽度对 100 取余，忽略行尾碎片。

可迁移思路

这类题的重点不是复杂数据结构，而是把自然语言里的“当前容器还能不能放下”精确翻译为状态机。相同模式也会出现在分页、装箱、文本折行和按容量分批处理中。
