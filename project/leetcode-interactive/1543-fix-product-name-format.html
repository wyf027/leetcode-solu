01 · Challenge

题意与数据契约

MySQL

任务：给定销售表 Sales。由于数据在 2000 年人工录入，同一产品的名称可能混用大小写，并在首尾带空格。

编写 SQL，按以下规则报告每种产品每月的销售情况：

  • product_name：移除首尾空格并转为小写；
  • sale_date：输出为 YYYY-MM；
  • total：该规范化产品在该月份出现的销售记录数。

结果先按 product_name 升序，再按 sale_date 升序。

关键语义：必须先规范化再分组，否则 LCPHONE、LCPhone 与 LcPhOnE 会被拆成不同产品。

Sales 表

约束与输出形式

  • sale_id 是具有唯一值的列。
  • 官方元数据给出的字段长度约束为 VARCHAR(30)。

05 · Full solution

题解与实现

O(n log n) 含排序
1

先造规范化键

名称的空格与大小写都属于表面差异，需在分组前消除；日期只保留年月。

2

再按双键聚合

使用“规范化产品名 + 月份”作为复合键。每条销售记录恰好进入一个桶。

3

最后稳定排序

先按产品名、再按月份升序，得到题目要求的确定性顺序。

完整过程

  1. 对每行计算 LOWER(TRIM(product_name))。
  2. 对销售日期计算 DATE_FORMAT(sale_date, '%Y-%m')。
  3. 用这两个表达式分组，并用 COUNT(*) 统计桶内记录。
  4. 按两个输出键依次升序排序。

正确性证明

引理 1：对于仅首尾空格或字母大小写不同的同一产品，TRIM 去除首尾空格，LOWER 统一字母大小写，因此得到相同名称键。

引理 2：DATE_FORMAT(..., '%Y-%m') 对且仅对同一自然月内的日期产生相同月份键。

聚合：按上述两个键分组后，每个组恰好包含某规范化产品在某月份的全部销售记录，COUNT(*) 因而等于所求月销量。

排序：最后的双字段 ORDER BY 与题目顺序完全一致。综上，查询返回且只返回所需结果。

可提交 · MySQL
SELECT
    LOWER(TRIM(product_name)) AS product_name,
    DATE_FORMAT(sale_date, '%Y-%m') AS sale_date,
    COUNT(*) AS total
FROM Sales
GROUP BY
    LOWER(TRIM(product_name)),
    DATE_FORMAT(sale_date, '%Y-%m')
ORDER BY product_name ASC, sale_date ASC;
本地语义参考 · Java 17
import java.time.LocalDate;
import java.time.format.DateTimeFormatter;
import java.util.*;

class Solution {
    record Sale(int saleId, String productName, LocalDate saleDate) {}
    record Result(String productName, String saleDate, long total) {}

    public List<Result> fixNameFormat(List<Sale> sales) {
        Map<String, Long> counts = new HashMap<>();
        DateTimeFormatter month = DateTimeFormatter.ofPattern("yyyy-MM");
        for (Sale sale : sales) {
            String name = sale.productName().trim().toLowerCase(Locale.ROOT);
            String date = sale.saleDate().format(month);
            counts.merge(name + "\u0000" + date, 1L, Long::sum);
        }
        List<Result> answer = new ArrayList<>();
        for (var entry : counts.entrySet()) {
            String[] key = entry.getKey().split("\u0000", -1);
            answer.add(new Result(key[0], key[1], entry.getValue()));
        }
        answer.sort(Comparator.comparing(Result::productName)
                              .thenComparing(Result::saleDate));
        return answer;
    }
}
本地语义参考 · JavaScript
function fixNameFormat(sales) {
  const counts = new Map();
  for (const { product_name, sale_date } of sales) {
    const name = product_name.trim().toLowerCase();
    const month = sale_date.slice(0, 7);
    const key = JSON.stringify([name, month]);
    counts.set(key, (counts.get(key) ?? 0) + 1);
  }
  return [...counts].map(([key, total]) => {
    const [product_name, sale_date] = JSON.parse(key);
    return { product_name, sale_date, total };
  }).sort((a, b) =>
    a.product_name.localeCompare(b.product_name) ||
    a.sale_date.localeCompare(b.sale_date)
  );
}
本地语义参考 · Python 3
from collections import Counter
from datetime import date

def fix_name_format(sales: list[dict]) -> list[dict]:
    counts = Counter()
    for sale in sales:
        name = sale["product_name"].strip().lower()
        value = sale["sale_date"]
        month = value.strftime("%Y-%m") if isinstance(value, date) else value[:7]
        counts[(name, month)] += 1

    return [
        {"product_name": name, "sale_date": month, "total": total}
        for (name, month), total in sorted(counts.items())
    ]
本地语义参考 · C++17
#include <algorithm>
#include <cctype>
#include <map>
#include <string>
#include <tuple>
#include <vector>
using namespace std;

struct Sale { int saleId; string productName; string saleDate; };
using Result = tuple<string, string, int>;

vector<Result> fixNameFormat(const vector<Sale>& sales) {
    map<pair<string, string>, int> counts;
    for (const auto& sale : sales) {
        string name = sale.productName;
        auto left = name.find_first_not_of(" \t\r\n");
        auto right = name.find_last_not_of(" \t\r\n");
        name = left == string::npos ? "" : name.substr(left, right - left + 1);
        transform(name.begin(), name.end(), name.begin(),
                  [](unsigned char c) { return tolower(c); });
        counts[{name, sale.saleDate.substr(0, 7)}]++;
    }
    vector<Result> answer;
    for (const auto& [key, total] : counts)
        answer.emplace_back(key.first, key.second, total);
    return answer;
}

边界情况

  • 只有一条销售记录：仍输出一组，total = 1。
  • 产品名两侧有多个空格：TRIM 一次性移除。
  • 同名产品跨月：月份键不同，必须拆成多组。
  • 同月不同产品：名称键不同，不能合并。
  • 月或日为一位数：MySQL 的 %m 自动补零。

复杂度

设表有 n 行、产生 g 个分组。概念上扫描与聚合为 O(n)；输出排序为 O(g log g)，故总时间可写为 O(n + g log g)，最坏 O(n log n)。聚合结构占 O(g) 额外空间。

实际执行计划与空间由数据库优化器、索引和排序策略决定。

替代方案

可先在 CTE 或子查询中生成规范化字段，再在外层 GROUP BY，可读性更强；也可以按年份与月份分别分组后用 CONCAT 拼接。直接按表达式分组最短，CTE 版本更适合复用复杂规范化逻辑。

常见错误

  • 只 LOWER 不 TRIM，空格仍会拆组。
  • 聚合后才清洗名称，已经分裂的桶无法自动合并。
  • 按完整日期分组，得到每日销量而非每月销量。
  • 使用 COUNT(product_name) 时忽略其与 COUNT(*) 的空值语义差异。
  • 遗漏第二排序键，导致同一产品的月份顺序不确定。

面试追问

  1. 如果产品名中间也有多余空格？ 题目仅要求首尾清理；扩展场景需用正则把连续内部空白折叠成一个。
  2. 如何优化大表？ 可考虑持久化规范化产品键与月份键，并为分组/排序设计合适索引；需权衡写入成本。
  3. 为何不用 DISTINCT？ DISTINCT 只能去重，不能计算每个分组的销售次数。
  4. 跨数据库怎么办？ 日期格式函数不同：PostgreSQL 可用 TO_CHAR，SQL Server 可组合 YEAR/MONTH 或使用合适转换。
