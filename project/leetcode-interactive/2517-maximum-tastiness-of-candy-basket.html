礼盒的最大甜蜜度

Maximum Tastiness of Candy Basket

选出 k 类糖果，让最接近的两个价格，也尽量离得远。

约 15 分钟阅读·独立思考 → 动手选糖 → 展开题解
01 / 理解问题

价格之间的“最短距离”

给定正整数数组 price 和正整数 k。数组的每个位置代表一类糖果，price[i] 是该类糖果的价格。从中选出恰好 k 类不同糖果，组成礼盒。

礼盒甜蜜度是所选糖果中，任意两类糖果价格绝对差的最小值。返回所有选法中最大的甜蜜度，返回值为整数。

注意：“不同”指不同糖果类别（数组位置），不要求价格不同。同价糖果可以同时选入，此时礼盒甜蜜度为 0。

参数与返回值

maximumTastiness(price: integer[], k: integer) → integer

官方约束

  • 2 ≤ k ≤ price.length ≤ 10⁵
  • 1 ≤ price[i] ≤ 10⁹

05 / 题解

排序 + 二分答案 + 贪心判定

核心洞察

直接枚举选哪 k 类很贵。换一个问题：给定最低间距 d，能否选出 k 类，让任意两类价格至少相差 d？如果 d 可以做到，更小的间距也能做到；如果 d 做不到，更大的间距也不可能。可行性是一段连续的“可行”，后接一段“不可行”。

先按价格升序排列。对于一个已选序列，任意非相邻差是若干相邻差的和，因此只需保证相邻选中价格的差 ≥ d。从最小价格开始，之后总是选择第一个距离上次选中价格至少 d 的糖果，就能尽量给后续选择留空间。

完整过程

  1. 对 price 升序排序，设跨度 R = max − min。
  2. 设 lo = 0，hi = floor(R / (k − 1))。k 个价格有 k−1 个相邻间隔，故最小间距不可能超过这个上界。
  3. 当 lo < hi，取上中位数 mid = lo + floor((hi − lo + 1) / 2)。
  4. 贪心扫描：先选第一个；若当前价格减去上次选中价格 ≥ mid，则选中并更新计数与上次价格。
  5. 计数 ≥ k，令 lo = mid；否则令 hi = mid − 1。最终返回 lo。

判定只问“至少 d”是否可行。贪心选出的礼盒实际甜蜜度可能大于 d，不要把 d 直接当成该礼盒的实际最小差。

为什么一定正确？

1. 相邻差足以约束全部价格对

升序选中价格为 x₁ ≤ … ≤ xₖ。任意 xⱼ − xᵢ 等于这段相邻差的总和，所有差非负，所以所有价格对中的最小差必然在相邻位置上取得。

2. 贪心能选出最多的糖果

固定 d。设任意可行序列为 a₁,…,aₜ，贪心序列为 g₁,…。按排序后的下标归纳：贪心第一个位置最早；若第 j 个贪心位置不晚于 aⱼ，则其价格不大于 aⱼ。aⱼ₊₁ 在它之后且满足与贪心上次价格之差 ≥ d，因此下一次贪心选择存在，位置不晚于 aⱼ₊₁。故任何可行方案能选 t 个，贪心也至少能选 t 个。这对 d=0 和重复价格同样成立，因为每次扫描使用不同下标。

3. 二分保持最优值在区间内

初始 0 总可行，跨度上界覆盖最优值。可行的 mid 排除所有比它更小的答案候选；不可行的 mid 排除 mid 及以上。上中位数保证当 lo 与 hi 相邻时仍会收缩区间，最终 lo=hi 就是最大可行间距。

复杂度与边界

令 n 为糖果类别数，R 为价格跨度，U=⌊R/(k−1)⌋。排序 O(n log n)，每次判定 O(n)，二分 O(log(U+1)) 次，总时间 O(n log n + n log(U+1))。扫描变量仅 O(1) 额外空间；总辅助空间依赖排序实现：C++ 常见实现 O(log n) 栈，Python Timsort 最坏 O(n)，Java / JavaScript 以运行库为准，可保守按 O(n) 预算。示例代码均原地排序输入。

  • k=2：答案是最大价格减最小价格。
  • k=n：全部必须选，答案是排序后的最小相邻差。
  • 全部同价：hi=0，直接返回 0；重复价格不可去重。
  • 大数：本题价格与差值在 32 位有符号整数范围内。中点使用 lo + 差值形式；JavaScript 用 Math.floor，避免泛化到更大范围时的位运算截断。

Java

import java.util.Arrays;

class Solution {
    public int maximumTastiness(int[] price, int k) {
        Arrays.sort(price);
        int lo = 0;
        int hi = (price[price.length - 1] - price[0]) / (k - 1);
        while (lo < hi) {
            int mid = lo + (hi - lo + 1) / 2;
            int count = 1, last = price[0];
            for (int i = 1; i < price.length; i++) {
                if (price[i] - last >= mid) {
                    count++;
                    last = price[i];
                }
            }
            if (count >= k) lo = mid;
            else hi = mid - 1;
        }
        return lo;
    }
}

C++

#include <algorithm>
#include <vector>
using namespace std;

class Solution {
public:
    int maximumTastiness(vector<int>& price, int k) {
        sort(price.begin(), price.end());
        int lo = 0;
        int hi = (price.back() - price.front()) / (k - 1);
        while (lo < hi) {
            int mid = lo + (hi - lo + 1) / 2;
            int count = 1, last = price[0];
            for (int i = 1; i < static_cast<int>(price.size()); ++i) {
                if (price[i] - last >= mid) {
                    ++count;
                    last = price[i];
                }
            }
            if (count >= k) lo = mid;
            else hi = mid - 1;
        }
        return lo;
    }
};

替代方案、易错点与面试追问

替代方案

  • 枚举所有 k 元子集，计算最小相邻差：约 O(C(n,k)·k)，只适合极小 n 的思路说明。
  • 逐一枚举整数答案再做贪心判定：O(n log n + nR)，跨度可接近 10⁹，不适合本题。
  • 二分上界直接用 R 也正确，O(n log n + n log(R+1))；用 R/(k−1) 可少搜一些候选值。

常见错误

  • 最大化价格总和或最大的一对差值：目标其实是所有价格对中的最小差。
  • 与数组中前一个价格比较：必须与上一次选中的价格比较。
  • 把差值条件写成 > d：应为 ≥ d，否则错过恰好相差 d 的糖果。
  • 对数组去重：会丢掉不同类别且同价的糖果，破坏 d=0 的可行性。
  • JavaScript 默认 sort() 按字符串排序：必须给出数值比较函数。
  • 使用下中位数却在可行时更新 lo=mid：相邻边界可能无限循环。

面试追问

  • 如何返回所选类别？排序时保留原下标，在答案 d 上再做一轮贪心，收集前 k 个下标。
  • 选了超过 k 类怎么办？任取其中 k 类都不会降低最小差，判定仍然成立。
  • 为什么能先选最便宜的？它在满足约束的同时结束位置最早，不会压缩后续可选空间，交换论证见上方归纳。
  • 价格变为实数呢？整数二分需改为固定轮数或精度阈值搜索，并明确误差要求。
  • 如果不能修改 price？先复制再排序，额外需要 O(n) 空间。
