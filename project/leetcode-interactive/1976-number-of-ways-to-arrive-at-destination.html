到达目的地的方案数

Number of Ways to Arrive at Destination

相同的最短时间，可能对应不同的行程。你能数清它们吗？

官方题目 ↗阅读示例思考后查看题解

01 / 题意

城市有 n 个路口，编号为 0 到 n - 1。roads[i] = [uᵢ, vᵢ, timeᵢ] 描述一条连接两个路口的双向道路，经过它需要 timeᵢ 分钟。道路网络连通，两个路口之间至多一条道路。

从 0 出发到 n - 1，只考虑总耗时最少的行程。返回这样的不同路径有多少条，答案对 1,000,000,007 取余。返回的是路径数量，不是最短耗时。

先想一想：两条路线到达同一个路口时，如果它们耗时相同，后面的道路会如何影响最终的路线数量？

约束

  • 1 ≤ n ≤ 200
  • n - 1 ≤ roads.length ≤ n × (n - 1) / 2
  • roads[i].length == 3
  • 0 ≤ uᵢ, vᵢ ≤ n - 1，且 uᵢ ≠ vᵢ
  • 1 ≤ timeᵢ ≤ 10⁹
  • 任意两个路口之间至多一条道路；任意两点之间可达。

02 / 官方示例

示例 1 · 多条等时路线

n = 7
roads = [[0,6,7],[0,1,2],[1,2,3],[1,3,3],[6,3,3],[3,5,1],[6,5,1],[2,5,1],[0,4,5],[4,6,2]]

输出：4

最短耗时为 7 分钟，四条路线分别是：

  • 0 → 6
  • 0 → 4 → 6
  • 0 → 1 → 2 → 5 → 6
  • 0 → 1 → 3 → 5 → 6

示例 2 · 唯一道路

n = 2
roads = [[1,0,10]]

输出：1

道路是双向的，因此可由 0 前往 1，耗时 10 分钟，只有一条路线。

04 / 独立题解

准备好后再展开：包含逐步演示、推导和四语言实现。

Dijkstra：把“最短距离”和“方案数”一起维护

边权严格为正，每次取出距离最小的未确定路口时，它的最短距离已经确定。所有能构成其最短路径的前驱距离都更小，已经处理过，所以它的最短路径计数也已完整。

dist[v]
当前已知的从 0 到 v 的最短耗时。
ways[v]
达到该耗时的路径数，始终对 10⁹ + 7 取余。

三种松弛结果

  • 更短：dist[u] + t < dist[v]，替换距离，同时令 ways[v] = ways[u]，旧的较长路径作废。
  • 同长：dist[u] + t == dist[v]，累加 ways[u]。最后一条边来自 u，是一组新的路径。
  • 更长：既不改距离，也不改计数。

完整过程

  1. 为每条道路建立两个邻接表条目，因为道路双向。
  2. 初始化 dist[0] = 0、ways[0] = 1，其余距离为无穷大、计数为 0。空路径给起点贡献一种方案。
  3. 扫描所有未确定路口，选择距离最小的 u，将其标记为已确定。
  4. 遍历 u 的邻边，按“更短替换、同长累加、更长忽略”更新。
  5. 重复最多 n 次，返回 ways[n - 1]。

示例 1 中，确定路口的次序可为 0, 1, 2, 3, 4, 5, 6。2、3、4 的距离同为 5，顺序可互换；它们之间不可能有属于最短路径的正权边。路口 5 收到来自 2 和 3 的两种方案；路口 6 则得到直达的 1 种、经 4 的 1 种，以及经 5 的 2 种，总计 4 种。

正确性

距离不变式：已确定集合中每个路口的 dist 等于真实最短距离。对于未确定且 dist 最小的 u，如果有更短路径，则该路径第一次从已确定集合跨出的路口应当已有不大于这条路径长度的候选距离，与选择 u 最小矛盾。因此 u 的距离可以确定。

计数归纳：起点有且仅有一条耗时为 0 的空路径。对于任意其他 u，最短路径的最后一个前驱 p 满足 dist[p] + w = dist[u]；由于 w > 0，p 一定先被处理。各前驱贡献的路径按最后一条边划分，互不重复。更短候选覆盖掉无效旧计数，同长候选累加所有合法前驱贡献。故确定 u 时 ways[u] 正好计入其所有最短路径。终点确定后结论成立，逐次取模保留正确余数。

边界与数值

  • n = 1、roads = [] 时返回 1。
  • 所有权重为正，最短路径不会包含环。最长简单路径至多含 199 条边，耗时至多 199 × 10⁹。
  • Java 用 long、C++ 用 long long 存距离；Python 整数不溢出。JavaScript 的安全整数上界大于这里的距离和每次取模前的计数和，Number 足够。
  • 只对计数取模，绝不对距离取模。两者混淆会破坏距离比较。
  • 代码保留“无可达候选则退出”的保护，但本题保证图连通。

复杂度与替代方案

令 m 为道路数。下方四语言均使用邻接表 + 线性选点：选点共 O(n²)，遍历邻边共 O(m)，总时间 O(n² + m)，额外空间 O(n + m)。n ≤ 200 时无需手写堆。

  • 堆优化 Dijkstra：对大规模稀疏图更合适，时间 O((n + m) log n)，空间 O(n + m)；弹出过期距离必须跳过。同长更新只加计数，不再次入堆。
  • 先求距离，再在最短路 DAG 上计数：仅保留满足 dist[u] + w = dist[v] 的方向，再按距离升序做动态规划。正权使距离严格递增，因此无环。
  • 不适用普通 BFS：每条路耗时不同；也不宜枚举所有路径，数量可能指数增长。

常见错误

  • 更短时仍累加旧 ways，混入非最短路径；相等时直接覆盖 ways，丢失其他路线。
  • 只建立单向边，或将边权误当成边的数量。
  • 使用 32 位整数保存总距离，长链会溢出。
  • 在“第一次发现终点”时提前返回；此时距离和计数都可能尚未完整。
  • ways[0] 初始化为 0，导致后续计数全部为 0。

面试追问

  • 何时可以提前返回？取出并确定终点时，所有最短前驱因距离更小都已处理，正权条件下可以返回。
  • 允许零权边会怎样？同距离节点间会存在依赖，以上计数归纳失效；若允许重复经过零权环，最短游走甚至可能无限多，需要先明确路径定义。
  • 只想恢复一条最短路线？更短更新时记录一个父节点，终点向前回溯即可；列举所有最短路径则可能需要指数级输出。
  • 加入负权边呢？Dijkstra 的确定顺序不再可靠；而无向负权边在允许重复经过时形成负环，最短游走不再有有限最小值。

Java

import java.util.*;

class Solution {
    public int countPaths(int n, int[][] roads) {
        final long MOD = 1_000_000_007L;
        List<List<int[]>> g = new ArrayList<>();
        for (int i = 0; i < n; i++) g.add(new ArrayList<>());
        for (int[] e : roads) {
            g.get(e[0]).add(new int[]{e[1], e[2]});
            g.get(e[1]).add(new int[]{e[0], e[2]});
        }
        long[] dist = new long[n], ways = new long[n];
        boolean[] done = new boolean[n];
        Arrays.fill(dist, Long.MAX_VALUE);
        dist[0] = 0;
        ways[0] = 1;
        // ponytail: n <= 200; use a heap for a much larger sparse graph.
        for (int step = 0; step < n; step++) {
            int u = -1;
            for (int v = 0; v < n; v++)
                if (!done[v] && (u == -1 || dist[v] < dist[u])) u = v;
            if (u == -1 || dist[u] == Long.MAX_VALUE) break;
            done[u] = true;
            for (int[] e : g.get(u)) {
                int v = e[0];
                long nd = dist[u] + e[1];
                if (nd < dist[v]) {
                    dist[v] = nd;
                    ways[v] = ways[u];
                } else if (nd == dist[v]) {
                    ways[v] = (ways[v] + ways[u]) % MOD;
                }
            }
        }
        return (int) ways[n - 1];
    }
}

/**
 * @param {number} n
 * @param {number[][]} roads
 * @return {number}
 */
var countPaths = function(n, roads) {
    const MOD = 1000000007;
    const g = Array.from({length: n}, () => []);
    for (const [u, v, t] of roads) {
        g[u].push([v, t]);
        g[v].push([u, t]);
    }
    const dist = Array(n).fill(Infinity);
    const ways = Array(n).fill(0);
    const done = Array(n).fill(false);
    dist[0] = 0;
    ways[0] = 1;
    // ponytail: n <= 200; use a heap for a much larger sparse graph.
    for (let step = 0; step < n; step++) {
        let u = -1;
        for (let v = 0; v < n; v++) {
            if (!done[v] && (u === -1 || dist[v] < dist[u])) u = v;
        }
        if (u === -1 || dist[u] === Infinity) break;
        done[u] = true;
        for (const [v, t] of g[u]) {
            const nd = dist[u] + t;
            if (nd < dist[v]) {
                dist[v] = nd;
                ways[v] = ways[u];
            } else if (nd === dist[v]) {
                ways[v] = (ways[v] + ways[u]) % MOD;
            }
        }
    }
    return ways[n - 1];
};

Python

from typing import List

class Solution:
    def countPaths(self, n: int, roads: List[List[int]]) -> int:
        mod = 10**9 + 7
        g = [[] for _ in range(n)]
        for u, v, t in roads:
            g[u].append((v, t))
            g[v].append((u, t))
        dist = [float("inf")] * n
        ways = [0] * n
        done = [False] * n
        dist[0], ways[0] = 0, 1
        # ponytail: n <= 200; use heapq for a much larger sparse graph.
        for _ in range(n):
            u = -1
            for v in range(n):
                if not done[v] and (u == -1 or dist[v] < dist[u]):
                    u = v
            if u == -1 or dist[u] == float("inf"):
                break
            done[u] = True
            for v, t in g[u]:
                nd = dist[u] + t
                if nd < dist[v]:
                    dist[v] = nd
                    ways[v] = ways[u]
                elif nd == dist[v]:
                    ways[v] = (ways[v] + ways[u]) % mod
        return ways[n - 1]

C++

#include <vector>
#include <utility>
#include <limits>
using namespace std;

class Solution {
public:
    int countPaths(int n, vector<vector<int>>& roads) {
        const long long MOD = 1000000007LL;
        const long long INF = numeric_limits<long long>::max();
        vector<vector<pair<int, int>>> g(n);
        for (const auto& e : roads) {
            g[e[0]].push_back({e[1], e[2]});
            g[e[1]].push_back({e[0], e[2]});
        }
        vector<long long> dist(n, INF), ways(n, 0);
        vector<bool> done(n, false);
        dist[0] = 0;
        ways[0] = 1;
        // ponytail: n <= 200; use a heap for a much larger sparse graph.
        for (int step = 0; step < n; ++step) {
            int u = -1;
            for (int v = 0; v < n; ++v)
                if (!done[v] && (u == -1 || dist[v] < dist[u])) u = v;
            if (u == -1 || dist[u] == INF) break;
            done[u] = true;
            for (auto [v, t] : g[u]) {
                long long nd = dist[u] + t;
                if (nd < dist[v]) {
                    dist[v] = nd;
                    ways[v] = ways[u];
                } else if (nd == dist[v]) {
                    ways[v] = (ways[v] + ways[u]) % MOD;
                }
            }
        }
        return static_cast<int>(ways[n - 1]);
    }
}
