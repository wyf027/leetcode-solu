字典序最小的字符串

在十进制环上累加，在字符串环上轮转。有限状态不断重逢，而最小答案藏在所有可达状态之中。

输入s, a, b
返回string
长度2 ≤ n ≤ 100

Problem

题意

给定一个长度为偶数、只含数字的字符串 s，以及整数 a 和 b。以下操作可以按任意顺序执行任意次：

  1. 累加：给所有奇数下标（下标从 0 开始）的数字加上 a，结果对 10 取模。
  2. 轮转：将整个字符串向右轮转 b 位。

返回所有能够到达的字符串中，字典序最小的那个。比较两个等长字符串时，从左向右找到首个不同字符，数字较小的一方字典序更小。

Limits

约束

  • 2 ≤ s.length ≤ 100
  • s.length 为偶数
  • s 仅含 0-9
  • 1 ≤ a ≤ 9
  • 1 ≤ b ≤ s.length - 1

Example 03
输入：s = "0011", a = 4, b = 2

广度优先搜索所有可达状态

1

把字符串看作节点

一次“累加”或“轮转”会产生一条有向边。

2

状态数是有限的

操作都在环上重复；用集合去重后搜索一定会停止。

3

遍历时维护最小值

每发现一个可达字符串，就与当前答案做字典序比较。

核心洞察

不需要猜操作顺序。将每个字符串作为状态，从初始状态出发，每个状态只有两个后继：奇数位累加后的字符串，以及右移后的字符串。BFS 配合 visited 会恰好处理每个可达状态一次；搜索过程中记录最小字符串即可。

完整过程

  1. 队列放入 s，同时加入访问集合，答案初始化为 s。
  2. 弹出一个状态 cur，用它更新当前最小答案。
  3. 构造 add(cur)：只修改下标 1, 3, 5, ...，每位计算 (digit + a) % 10。
  4. 构造 rotate(cur)：拼接末尾 b 个字符与前面的字符。
  5. 若后继从未出现，则标记访问并入队。队列为空时返回答案。

正确性证明

  1. 后继完整：对任意已处理状态，算法同时生成题目允许的两种一步操作结果，所以没有漏掉任何一步可达边。
  2. 所有可达状态都会被访问：初始状态已入队。若一个状态能用 k 步到达，根据归纳假设，其第 k−1 步前驱会被访问；处理该前驱时便会生成并入队该状态。
  3. 只访问可达状态：初始状态显然可达；每个新状态都由一个可达状态执行合法操作得到，因此仍然可达。
  4. 答案最小：算法比较了全部且仅全部可达状态，并维护其中字典序最小值，所以最终返回的就是目标答案。

复杂度

设可达状态数为 M，字符串长度为 n。每个状态构造两个长度为 n 的后继。

时间：O(M · n)
空间：O(M · n)

本题的状态结构使 M 至多约为 100n。

边界情况

  • 初始字符串本身可能就是答案。
  • b 为奇数时，轮转会交换下标奇偶性。
  • a 与 10 不互质时，单个数字只会落在一个较短循环中。
  • 访问集合必须在入队时更新，避免重复入队。

import java.util.*;

class Solution {
    public String findLexSmallestString(String s, int a, int b) {
        Queue<String> queue = new ArrayDeque<>();
        Set<String> visited = new HashSet<>();
        queue.offer(s);
        visited.add(s);
        String answer = s;

        while (!queue.isEmpty()) {
            String current = queue.poll();
            if (current.compareTo(answer) < 0) answer = current;

            char[] chars = current.toCharArray();
            for (int i = 1; i < chars.length; i += 2) {
                chars[i] = (char) ('0' + (chars[i] - '0' + a) % 10);
            }
            String added = new String(chars);

            int n = current.length();
            String rotated = current.substring(n - b) + current.substring(0, n - b);

            if (visited.add(added)) queue.offer(added);
            if (visited.add(rotated)) queue.offer(rotated);
        }
        return answer;
    }
}

 * @param {string} s
 * @param {number} a

var findLexSmallestString = function(s, a, b) {
    const queue = [s];
    const visited = new Set([s]);
    let head = 0;
    let answer = s;

    while (head < queue.length) {
        const current = queue[head++];
        if (current < answer) answer = current;

        const chars = current.split('');
        for (let i = 1; i < chars.length; i += 2) {
            chars[i] = String((Number(chars[i]) + a) % 10);
        }
        const added = chars.join('');
        const n = current.length;
        const rotated = current.slice(n - b) + current.slice(0, n - b);

        for (const next of [added, rotated]) {
            if (!visited.has(next)) {
                visited.add(next);
                queue.push(next);
            }
        }
    }
    return answer;
};
from collections import deque


class Solution:
    def findLexSmallestString(self, s: str, a: int, b: int) -> str:
        queue = deque([s])
        visited = {s}
        answer = s

        while queue:
            current = queue.popleft()
            answer = min(answer, current)

            chars = list(current)
            for i in range(1, len(chars), 2):
                chars[i] = str((int(chars[i]) + a) % 10)
            added = ''.join(chars)

            rotated = current[-b:] + current[:-b]

            for nxt in (added, rotated):
                if nxt not in visited:
                    visited.add(nxt)
                    queue.append(nxt)

        return answer

替代方案：利用周期枚举

右移只会产生 n / gcd(n, b) 种位置排列；对某一组下标反复加 a，只会产生 10 / gcd(10, a) 种数字偏移。可以枚举这些周期组合并取最小值。若 b 为奇数，轮转会交换奇偶下标，因此奇、偶位置都可能被独立累加；若 b 为偶数，只有当前奇数位置可变。该方法常数小，但分支推导更容易写错，面试中 BFS 更稳健。

面试追问

  • 为什么搜索一定终止？如何给状态数上界？
  • 能否把 BFS 换成 DFS？答案：可以，只要完整遍历并去重。
  • 若字符串长度不是偶数，奇偶下标在轮转后的规律如何变化？
  • 如何用最大公约数直接枚举而不存所有状态？

常见错误

  • 把“奇数下标”误解成“奇数数字”。
  • 右移切片位置写成 b，而不是 n−b。
  • 忘记数字对 10 取模。
  • 只尝试固定操作顺序，漏掉交错操作。
  • 先出队再去重，导致队列膨胀。
