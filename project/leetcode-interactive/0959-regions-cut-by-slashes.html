Problem

题目描述

给定一个由 n × n 个单位方格组成的网格。每个方格中是斜杠 /、反斜杠 \ 或空格。斜杠会把方格内部切开；求整个网格最终形成的共边连通区域数。

参数：grid: string[]　返回：integer。字符串中的反斜杠需要转义，例如代码里的 "\\" 表示一个反斜杠。

约束

  • n == grid.length == grid[i].length
  • 1 ≤ n ≤ 30
  • grid[i][j] 只会是 '/'、'\' 或空格

Official examples

示例

示例 1
输入：grid = [" /", "/ "]
输出：2
示例 2
输入：grid = [" /", "  "]
输出：1
示例 3
输入：grid = ["/\\", "\\/"]
输出：5
解释：两个字符串分别表示 /\ 与 \/。

Solution

三倍扩图 + 洪泛搜索

核心洞察：不要直接描述斜线两侧的三角形。把每个原格扩大成 3 × 3 像素，斜杠恰好能用三个像素表示成一道连续的墙；剩余像素的连通块数量就是答案。

完整过程

  1. 创建大小为 3n × 3n 的整数矩阵，初始全为 0（可通行）。
  2. 若原格是 /，标记扩展格的右上、中间、左下三个位置；若是 \，标记左上、中间、右下。
  3. 从左到右、从上到下扫描扩展矩阵。每遇到一个尚未访问的 0，区域数加一，并从它开始 DFS/BFS，把四方向相连的全部 0 标记为已访问。
  4. 扫描结束时，每个可通行像素恰属于一次洪泛，因此计数就是区域总数。

正确性

表示等价：3 × 3 中的三点斜线首尾接触相邻边界，能隔断斜线两侧，同时不会虚构额外通道。

连通等价：原图中可通过共边到达的任意两点，在扩展图中存在四方向路径；被斜线分隔的点则必被墙像素阻断。

计数完备：洪泛搜索恰好访问一个极大连通块；外层扫描为每个连通块启动一次且仅一次搜索，所以答案正确。

复杂度与边界

扩展图含 9n² 个像素，每个最多访问一次：时间 O(n²)，空间 O(n²)。

边界包括：全空格（答案为 1）、单格斜杠（答案为 2）、连续斜杠形成封闭区域，以及字符串中反斜杠的转义。

替代方案

也可把每个方格拆成上、右、下、左四个三角形，用并查集合并格内与相邻格的三角形，最后统计根节点。它同样是 O(n²)，空间常数更小，但索引与合并规则更容易写错。另一种欧拉公式计数法更精巧，却更难在面试中快速证明。

面试追问

  • 为何放大 2 倍不稳妥，而 3 倍能保证斜线连续且不误连？
  • 怎样把递归 DFS 改成队列 BFS，避免深递归风险？
  • 如果方格还能出现 X，扩图法与四三角并查集各如何调整？

常见错误

  • 把 \ 的三个扩展坐标写成 / 的方向。
  • 只统计封闭圈，漏掉网格外边界共同形成的区域。
  • DFS 只在出队时标记，导致同一像素被重复加入栈或队列。
  • JavaScript / Java 字符串里忘记转义反斜杠。
