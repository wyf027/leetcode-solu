Problem

题目描述

给定一个按非递减顺序排列的整数数组 arr。数组中恰好有一个整数的出现次数严格超过数组长度的 25%，请返回这个整数。

“超过 25%”是严格大于，而不是大于等于；题目保证目标元素唯一存在。

官方示例 1

输入：arr = [1,2,2,6,6,6,6,7,10]
输出：6

官方示例 2

输入：arr = [1,1]
输出：1

约束

  • 1 <= arr.length <= 104
  • 0 <= arr[i] <= 105
  • arr 按非递减顺序排列。
  • 恰好有一个整数出现次数超过数组长度的 25%。

Solution

四分位候选 + 二分边界

核心洞察

目标元素占据一个长度大于 n / 4 的连续区间，因此它不可能躲开下标 ⌊n/4⌋、⌊n/2⌋、⌊3n/4⌋ 这三个探针。答案一定是三个位置上的某个值。

完整过程

  1. 取三个候选：arr[n/4]、arr[n/2]、arr[3n/4]（下标做整数除法）。
  2. 对每个候选，用二分查找求第一次出现位置 lowerBound 和第一个大于它的位置 upperBound。
  3. 频次为 upperBound - lowerBound。若频次严格大于 n/4，立即返回。
  4. 题目保证答案存在且唯一；兜底返回数组首元素仅用于满足完整函数返回路径。

正确性证明

1 · 连续性数组有序，所以同一数值的全部出现位置组成一个连续区间。
2 · 必命中若该区间长度大于 n/4，它跨越的下标宽度足以覆盖三个四分位探针中的至少一个。
3 · 精确确认二分得到候选区间两端，差值就是其真实频次；严格比较 > n/4 后返回的必然是答案。

边界情况

  • 只有一个元素：三个探针都落在下标 0，频次 1 严格大于 0。
  • 数组很短：整数除法仍能给出合法下标，重复候选不会影响正确性。
  • 频次恰为 25%：不符合条件，必须使用严格大于号。
  • 答案位于首尾：第一或第三个四分位探针仍会命中其连续区间。

复杂度

只检查常数个候选，每个候选做两次二分：时间复杂度 O(log n)，额外空间复杂度 O(1)。

class Solution {
    public int findSpecialInteger(int[] arr) {
        int n = arr.length;
        int[] indices = {n / 4, n / 2, 3 * n / 4};

        for (int index : indices) {
            int candidate = arr[index];
            int left = lowerBound(arr, candidate);
            int right = upperBound(arr, candidate);
            if (right - left > n / 4) {
                return candidate;
            }
        }
        return arr[0];
    }

    private int lowerBound(int[] arr, int target) {
        int left = 0, right = arr.length;
        while (left < right) {
            int mid = left + (right - left) / 2;
            if (arr[mid] >= target) right = mid;
            else left = mid + 1;
        }
        return left;
    }

    private int upperBound(int[] arr, int target) {
        int left = 0, right = arr.length;
        while (left < right) {
            int mid = left + (right - left) / 2;
            if (arr[mid] > target) right = mid;
            else left = mid + 1;
        }
        return left;
    }
}

var findSpecialInteger = function(arr) {
    const n = arr.length;
    const candidates = [arr[Math.floor(n / 4)], arr[Math.floor(n / 2)], arr[Math.floor(3 * n / 4)]];

    const lowerBound = (target) => {
        let left = 0, right = n;
        while (left < right) {
            const mid = left + Math.floor((right - left) / 2);
            if (arr[mid] >= target) right = mid;
            else left = mid + 1;
        }
        return left;
    };

    const upperBound = (target) => {
        let left = 0, right = n;
        while (left < right) {
            const mid = left + Math.floor((right - left) / 2);
            if (arr[mid] > target) right = mid;
            else left = mid + 1;
        }
        return left;
    };

    for (const candidate of candidates) {
        if (upperBound(candidate) - lowerBound(candidate) > n / 4) {
            return candidate;
        }
    }
    return arr[0];
};

替代方案

方案做法时间空间取舍
一次线性扫描统计连续相同元素的长度O(n)O(1)最直观，未充分利用 25% 阈值
跨距检查检查 arr[i] == arr[i+n/4]O(n)O(1)代码极短，证明需解释严格阈值

面试追问

  • 如果阈值变为 1/k，应检查多少个分位点？
  • 如果数组无序，如何在 O(n) 时间内处理？
  • 能否只用一次 lower_bound 验证候选？
  • 为什么三个探针足够，而不是四个？

常见错误

  • 把“超过 25%”写成 >= n/4。
  • 二分右边界时仍使用 >=，导致频次少算。
  • 只检查中位数；答案可能集中在数组两端。
  • 用浮点数比较比例，徒增精度风险。
