01 / 任务

沿着小路，依次浇水

有 n 株植物，第 i 株位于 x = i，需要 plants[i] 单位水。河流位于 x = -1。你从河边出发，水罐最初装满，容量为 capacity。

  • 严格按编号从小到大浇水，每株必须一次完全浇足。
  • 若剩余水量不足以浇下一株，先返回河边装满；水够时不能提前补水。
  • 沿横轴移动一个单位计一步。浇水、装水不计步数，最后一株浇完即结束，无需返回河边。

输入：整数数组 plants 与整数 capacity。返回：浇完所有植物所走的总步数。

约束

  • n == plants.length
  • 1 ≤ n ≤ 1000
  • 1 ≤ plants[i] ≤ 10⁶
  • max(plants[i]) ≤ capacity ≤ 10⁹

04 / 深入理解

把走过的路变成代码

准备好后展开：推导、证明与四种语言实现。

题解 · 按植物模拟

核心洞察

处理第 i 株前，你位于 i − 1。水够时，向前走 1 步；水不够时，先走 i 步回到 −1，再走 i + 1 步到第 i 株，一共 2i + 1 步。补水条件必须是 water < plants[i]，相等时直接浇水。

完整过程

  1. 初始化 water = capacity、steps = 0。
  2. 依次访问每株植物。若水量不足，累计 2 * i + 1 步并把水量设为容量；否则累计 1 步。
  3. 扣除当前植物需求 plants[i]，继续下一株。
  4. 遍历结束返回 steps，不增加返程。
plants = [2,2,3,3], capacity = 5
 i   浇前水量   行为              新增步数   浇后水量   累计
 0      5      直接前进              1         3        1
 1      3      直接前进              1         1        2
 2      1      返回补水，再前进      5         2        7
 3      2      返回补水，再前进      7         2       14

正确性

循环不变式：第 i 次迭代开始时，编号小于 i 的植物均已浇好，人位于 i−1，water 是真实余水，steps 是已经走过的总路程。初始 i=0 时位于 −1，水罐满、路程为 0，不变式成立。

若 water 足够，规则不允许提前补水，只能前进一步并扣水；若不足，规则要求返回 −1 补满再到 i，距离恰为 i+(i+1)。容量至少等于当前需求，因此补满后必能浇足。两种分支都精确更新距离和余水，使不变式对下一次成立。遍历结束时所有植物已浇好，累计值就是要求的总步数。这里模拟的是规则确定的过程，无需另做路径优化。

边界与复杂度

  • n=1 时只需走 1 步；首株永远无需补水，因为容量不小于最大需求。
  • 余水恰好够用时不补水；浇完最后一株即使余水为 0 也直接结束。
  • 算法时间 O(n)，额外空间 O(1)，不修改数组。页面为回退保存的演示快照不属于提交算法空间。
  • 最坏每株前都补水，总步数为 1+3+…+(2n−1)=n²，最多 10⁶；Java/C++ 的 int 可容纳步数和容量。

替代方案

也可先设 steps = n，预付每株向前一步的基础路程；每当第 i 株水不够时，只额外加 2 * i，补满后扣水。其时间、空间复杂度不变。逐格行走也能模拟，但最坏要 O(n²) 次移动，没有必要。

常见错误

  • 把不足判断写成 ≤，导致水刚好够时违规补水。
  • 返回距离误写成 i+1：此时人还在 i−1，回河边只要 i 步。
  • 已在所有分支加 1，又在补水分支加 2i+1，重复计算一步。
  • 先扣水再判断不足，或补水时把容量加到余水上；补水应直接赋值为 capacity。
  • 最后再返回河边，或者提前补水，都会改变题目规定的路程。

Java

class Solution {
    public int wateringPlants(int[] plants, int capacity) {
        int water = capacity;
        int steps = 0;
        for (int i = 0; i < plants.length; i++) {
            if (water < plants[i]) {
                steps += 2 * i + 1;
                water = capacity;
            } else {
                steps++;
            }
            water -= plants[i];
        }
        return steps;
    }
}

from typing import List

class Solution:
    def wateringPlants(self, plants: List[int], capacity: int) -> int:
        water = capacity
        steps = 0
        for i, need in enumerate(plants):
            if water < need:
                steps += 2 * i + 1
                water = capacity
            else:
                steps += 1
            water -= need
        return steps

C++

#include <vector>

class Solution {
public:
    int wateringPlants(vector<int>& plants, int capacity) {
        int water = capacity;
        int steps = 0;
        for (int i = 0; i < static_cast<int>(plants.size()); ++i) {
            if (water < plants[i]) {
                steps += 2 * i + 1;
                water = capacity;
            } else {
                ++steps;
            }
            water -= plants[i];
        }
        return steps;
    }
};

面试追问

为什么不是贪心选择？浇水顺序和补水时机都已固定，模拟即可。允许提前补水会怎样？原来的强制分支不再描述全部可选行为，需要重新分析决策。容量小于某株需求怎么办？原约束排除了这种输入；若扩展题意且仍要求一次浇足，应报告无法完成。河流换到 x=−d 呢？初始走到 0 为 d 步，之后不足时从 i−1 回河再到 i 的距离是 2i+2d−1，不能直接沿用原式。
