可以被一步捕获的棋子数

Available Captures for Rook · 从白车出发，观察四条直线上的第一个棋子。

题目

给定一个 8 × 8 棋盘：唯一的白车为 'R'，白象为 'B'，黑卒为 'p'，空格为 '.'。车能沿上、下、左、右移动任意格，但不能越过棋子。返回白车能在一步内捕获的黑卒数量。

约束

  • board.length == 8 且 board[i].length == 8
  • board[i][j] 是 'R'、'.'、'B' 或 'p'
  • 恰有一个格子为 'R'

题解

首屏之外，默认收起。

核心洞察

每个方向只关心从车出发遇到的第一个非空格：它是卒则加一，是象则贡献零；遇到棋子后立即停止。

完整过程

  1. 遍历棋盘定位白车。
  2. 依次使用四个方向向量 (-1,0)、(1,0)、(0,-1)、(0,1)。
  3. 越过空格；遇卒计数并停止，遇象直接停止，到边界也停止。

正确性

固定一个方向。若第一个棋子是卒，此前全是空格，车能一步到达它；若第一个棋子是象，它会挡住后方所有卒。算法恰好判断第一个棋子，所以该方向计数正确。四个方向覆盖车的全部一步攻击范围，求和即为答案。

边界与复杂度

车可在边缘；方向上可全为空格；相邻棋子会立即终止。通用 m × n 棋盘时间 O(mn)，额外空间 O(1)；固定 8 × 8 时开销为常数。

替代方案

可以切出车所在行列后寻找两侧最近棋子，但容易混淆方向和索引。四向向量法更统一。稀疏超大棋盘可把棋子按行列排序，再二分寻找最近邻。

面试追问

  • 允许斜向攻击：再加入四个对角方向。
  • 存在多个车：分别扫描，或预处理每行每列的障碍。
  • 棋盘动态更新：维护行列有序集合。

常见错误

  • 忽略更近棋子的阻挡。
  • 吃到一个卒后继续扫描并重复计数。
  • 边界判断错误导致越界。

class Solution {
    public int numRookCaptures(char[][] board) {
        int rr = 0, rc = 0;
        outer: for (int r = 0; r < 8; r++)
            for (int c = 0; c < 8; c++)
                if (board[r][c] == 'R') { rr = r; rc = c; break outer; }
        int ans = 0;
        int[][] dirs = {{-1,0},{1,0},{0,-1},{0,1}};
        for (int[] d : dirs) {
            int r = rr + d[0], c = rc + d[1];
            while (r >= 0 && r < 8 && c >= 0 && c < 8) {
                if (board[r][c] != '.') {
                    if (board[r][c] == 'p') ans++;
                    break;
                }
                r += d[0]; c += d[1];
            }
        }
        return ans;
    }
}
