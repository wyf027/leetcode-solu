两个字符串的最小 ASCII删除和

字符不是等价的代价单位：删掉 z 比删掉 a 更贵。你的任务，是让两个字符串最终相同，同时让被删除字符的 ASCII 值总和尽可能小。

先读题、亲手推进状态，再决定是否展开题解。
a 低代价字符 97
s 示例中的删除 115
t 示例中的删除 116
z 高代价字符 122

01 / Problem

题目要求

给定两个字符串 s1 和 s2，可以从任一字符串中删除任意字符。返回使两者相等时，被删除字符的 ASCII 值总和的最小值。

函数签名

minimumDeleteSum(s1: string, s2: string) -> integer

约束

  • 1 <= s1.length, s2.length <= 1000
  • s1 与 s2 仅由小写英文字母组成。
  • 只允许删除字符，不能插入、替换或调整字符顺序。

示例 1

输入：s1 = "sea", s2 = "eat" 输出：231

从 sea 删除 s（115），从 eat 删除 t（116），两者都变为 ea；总代价为 231。

示例 2

输入：s1 = "delete", s2 = "leet" 输出：403

可把两个字符串都变为 let：从第一个字符串删除 dee，从第二个删除一个 e，总代价为 403。

Core idea

把“让两个串相等”拆成后缀状态

定义 dp[i][j] 为把后缀 s1[i:] 与 s2[j:] 变得相等所需的最小 ASCII 删除和。答案是 dp[0][0]。

01 / MATCH

字符相同就一起保留

若 s1[i] == s2[j]，无需删除它们，直接转到 dp[i+1][j+1]。

02 / CHOOSE

字符不同时二选一

删除 s1[i] 或删除 s2[j]；两条路径都覆盖所有可能的最优首步。

03 / BASE

一个后缀为空

另一个后缀的所有字符只能全部删除，代价就是这些字符的 ASCII 值之和。

状态转移

dp[i][j] = dp[i+1][j+1] 当 s1[i] == s2[j] dp[i][j] = min( ASCII(s1[i]) + dp[i+1][j], ASCII(s2[j]) + dp[i][j+1] ) 当 s1[i] != s2[j]

边界：dp[m][j] 是 s2[j:] 的 ASCII 总和；dp[i][n] 是 s1[i:] 的 ASCII 总和。按 i、j 从后向前填表，就能保证依赖状态已经计算。

完整过程

  1. 先初始化两个字符串的空后缀边界：另一个后缀只能全部删掉。
  2. 从 i = m - 1 到 0 遍历 s1，每一行再从 j = n - 1 到 0 遍历 s2。
  3. 字符相同，保留这对字符；字符不同，比较删除左侧字符与删除上方字符的总代价。
  4. 最终 dp[0][0] 覆盖两个完整字符串。实现时可把二维表压缩为一维数组。

正确性证明

  1. 基例成立：当一个后缀为空时，为使两者相等，另一个后缀中的每个字符都必须删除；边界值因此既可行又最小。
  2. 相同首字符：若 s1[i] = s2[j]，保留两者不增加代价，剩余问题正是 dp[i+1][j+1]。删除其中任一个相同字符不会优于免费保留这对字符。
  3. 不同首字符：最终相等字符串不可能同时保留这两个不同的首字符，所以至少要删除其中一个。转移分别枚举这两种完备的首步，并取更小值。
  4. 归纳结论：假设所有更短后缀状态均为最优，上述转移使用它们得到当前状态的最优值。按后缀长度归纳，dp[0][0] 即全局最优答案。
O(mn) 时间复杂度：每对字符状态恰好处理一次。
O(n) 空间复杂度：使用一维滚动数组；可令较短字符串作为第二维进一步节省空间。

四语言完整实现

class Solution {
    public int minimumDeleteSum(String s1, String s2) {
        int m = s1.length();
        int n = s2.length();
        int[] dp = new int[n + 1];

        for (int j = n - 1; j >= 0; --j) {
            dp[j] = dp[j + 1] + s2.charAt(j);
        }

        for (int i = m - 1; i >= 0; --i) {
            int diagonal = dp[n];
            dp[n] += s1.charAt(i);

            for (int j = n - 1; j >= 0; --j) {
                int below = dp[j];
                if (s1.charAt(i) == s2.charAt(j)) {
                    dp[j] = diagonal;
                } else {
                    dp[j] = Math.min(
                        s1.charAt(i) + below,
                        s2.charAt(j) + dp[j + 1]
                    );
                }
                diagonal = below;
            }
        }
        return dp[0];
    }
}

边界情况

两个字符串完全相同

每一对字符都直接保留，答案为 0。

没有公共字符

所有字符最终都要删除，答案是两个字符串所有 ASCII 值之和。

一个串是另一个的子序列

可保留该子序列，但仍需确认是否存在代价更优的其他公共子序列。

长度达到 1000

二维状态仍有约百万格；一维压缩显著降低额外空间。

替代方案

最大 ASCII 权重公共子序列

先求可共同保留字符的最大 ASCII 权重，再用两串 ASCII 总和减去两倍保留权重。时间同为 O(mn)，但从“保留收益”而非“删除成本”建模。

自顶向下记忆化搜索

状态定义与转移相同，代码贴近递归推理；但最长可产生约 2000 层递归，在部分语言中有栈深风险。

常见错误

把字符数当作代价

目标不是最少删除字符个数；不同字符的 ASCII 代价不同。

边界只填成长度

空后缀边界应累计字符 ASCII 值，而不是剩余字符数量。

一维数组覆盖顺序错误

本状态依赖当前行右侧与下一行同列，因此 j 必须从右向左，并单独保存旧对角值。

相同字符仍枚举删除

相同首字符可免费共同保留，直接取对角状态即可，逻辑更简洁。

面试追问

为什么相同字符时可以直接保留，不必比较删除？

共同保留的代价为 0，并把问题缩小为两个剩余后缀。若某方案删除了其中一个相同字符，可以把这对字符共同保留而不破坏后续相对顺序，代价不会更高。

如何把空间从 O(mn) 降到 O(n)？

每个状态只依赖下一行同列、当前行右侧和下一行右下角。使用一维数组保存下一行/当前行，并用一个变量保存覆盖前的对角值。

如果删除代价由外部权重表给出，算法需要怎样改？

状态结构不变，只需把 ASCII(c) 替换为 weight[c]。只要每次删除的代价可独立相加，转移仍成立。

如何恢复具体删除了哪些字符？

保留完整二维表，从 dp[0][0] 沿最优转移回溯；相同字符走对角线，不同字符根据哪条删除转移达到当前值记录相应字符。
