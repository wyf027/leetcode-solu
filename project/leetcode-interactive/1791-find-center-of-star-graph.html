Find Center of Star Graph · 题号 1791

nodes1 → n一颗星，一处中心
Problem brief

题目说明

任务

给定一个由 n 个节点构成的无向星型图，节点编号为 1 到 n。图中恰有一个中心节点，并有 n - 1 条边把它与其余每个节点相连。

二维整数数组 edges 中的每一项 edges[i] = [uᵢ, vᵢ] 表示节点 uᵢ 与 vᵢ 之间存在一条边。请返回这张有效星型图的中心节点编号。

函数形式

findCenter(edges: integer[][]) → integer

示例 1

输入：edges = [[1,2],[2,3],[4,2]]

输出：2

解释：节点 2 与其余每个节点相连，因此中心节点为 2。

示例 2

输入：edges = [[1,2],[5,1],[1,3],[1,4]]

输出：1

约束

  • 3 ≤ n ≤ 10⁵
  • edges.length == n - 1
  • edges[i].length == 2
  • 1 ≤ uᵢ, vᵢ ≤ n
  • uᵢ != vᵢ
  • 输入的 edges 一定表示一张有效的星型图。

Solution

两条边的公共端点

中心节点与每条边相连，所以任取前两条边，它们唯一重复出现的端点就是中心。

核心洞察

设前两条边为 [a, b] 与 [c, d]。由于输入保证是有效星型图，这两条不同的边必然共享中心节点。因此只需判断 a 是否等于 c 或 d：若是，答案为 a；否则答案为 b。

完整过程

  1. 读取 edges[0] 的两个端点 a、b。
  2. 读取 edges[1] 的两个端点 c、d。
  3. 若 a == c 或 a == d，返回 a。
  4. 否则返回 b。

正确性证明

  1. 星型图的每一条边都连接中心节点与一个非中心节点，因此中心节点同时属于前两条边。
  2. 两个非中心节点之间不存在边，且不同的边连接不同的非中心节点，所以前两条边不会共享非中心节点。
  3. 于是前两条边的唯一公共端点恰好是中心节点。算法返回该公共端点，因此结果正确。

边界与复杂度

  • 最小规模：n = 3 时仍有两条边，判断成立。
  • 边顺序：端点顺序与边的排列均不影响公共端点。
  • 时间复杂度：O(1)，只查看两条边。
  • 空间复杂度：O(1)。

替代方案

可以遍历所有边并统计每个节点的度数，最后返回度数为 n - 1 的节点。该方案更通用，也适合输入不保证为星型图时做校验，但本题中会把时间和空间提高到 O(n)。

面试追问

  • 如果输入可能无效，如何验证它确实是一张星型图？
  • 若边以数据流形式到达，最早什么时候能够确定中心？
  • 若图中允许重边或自环，当前结论需要怎样调整？

常见错误

  • 遍历全部边后才返回，虽然正确，但错过了题目保证带来的常数解。
  • 只比较 edges[0][0] 与 edges[1][0]，忽略公共端点可能位于第二条边的另一侧。
  • 根据节点编号大小猜中心；编号与图结构无关。

一句话记忆

有效星型图的任意两条边，都只在中心节点处相交。

class Solution {
    public int findCenter(int[][] edges) {
        int a = edges[0][0];
        int c = edges[1][0];
        int d = edges[1][1];
        return (a == c || a == d) ? a : edges[0][1];
    }
}
