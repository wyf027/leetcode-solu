数组美丽值求和

Sum of Beauty in the Array

一个位置的美丽，取决于它与两侧数字的关系。

先理解评分规则，再自行思考。交互推演与四语言题解位于页面底部，默认收起。

01 /题目说明

给定从下标 0 开始的整数数组 nums，只评价内部位置 1 ≤ i ≤ nums.length − 2。每个位置按以下优先顺序获得一个分数，返回这些分数之和。

2 分

左侧所有数字都严格小于当前值，右侧所有数字都严格大于当前值。

对任意 j < i < k，均有 nums[j] < nums[i] < nums[k]。

1 分

不满足 2 分条件，但紧邻的三个数字严格递增。

nums[i−1] < nums[i] < nums[i+1]

0 分

以上两种条件都不满足。

首尾元素不参与评分；相等不算严格小于。

参数与返回值：sumOfBeauties(nums: integer[]) → integer

约束：3 ≤ nums.length ≤ 10⁵；1 ≤ nums[i] ≤ 10⁵。

02 /官方示例

示例 1

输入：nums = [1,2,3]
输出：2

只评价 i = 1，该位置获得 2 分。

示例 2

输入：nums = [2,4,6,4]
输出：1

i = 1 获得 1 分；i = 2 获得 0 分，总和为 1。

示例 3

输入：nums = [3,2,1]
输出：0

只评价 i = 1，该位置不满足任何加分条件。

04 /题解 · 把“全部”压缩成两个边界

核心洞察

左边所有数字都小于 x，等价于左边的最大值小于 x；右边所有数字都大于 x，等价于右边的最小值大于 x。因此每个位置只需判断 leftMax < nums[i] < rightMin[i+1]。全局条件失败后，再检查相邻元素。

完整过程
  1. 设 n 为数组长度。创建 rightMin，令 rightMin[n−1] = nums[n−1]。
  2. 从 n−2 逆序到 0，计算 rightMin[i] = min(nums[i], rightMin[i+1])。
  3. 令 leftMax = nums[0]，总分 ans = 0。遍历 i = 1 到 n−2。
  4. 若 leftMax < nums[i] 且 nums[i] < rightMin[i+1]，加 2；否则若 nums[i−1] < nums[i] < nums[i+1]，加 1；否则不加。
  5. 评分后更新 leftMax = max(leftMax, nums[i])，最后返回 ans。


正确性说明
后缀不变量：rightMin[n−1] 显然是末尾单元素的最小值。若 rightMin[i+1] 已正确，取它与 nums[i] 的较小者恰好得到区间 [i,n−1] 的最小值，逆序归纳成立。
前缀不变量：评分 i = 1 时 leftMax 是 nums[0]。若评分前它等于 [0,i−1] 的最大值，评分后并入 nums[i] 就得到下一轮所需的最大值。
评分与总和：上述两条不变量使 2 分判断恰好等价于题目的全部左右比较；否则，相邻判断恰好决定 1 分或 0 分。if / else if 确保每个内部位置只计一次，遍历覆盖且仅覆盖所有内部位置，故总和正确。


边界与复杂度
n = 3 时只处理中间元素。重复值必须用严格不等号处理。严格递增时每个内部位置为 2 分，总分是 2(n−2)；严格递减或全部相等时为 0 分。最大答案 199996，32 位有符号整数足够。
时间复杂度 O(n)：一次逆序预处理和一次正序评分。额外空间 O(n)：一个后缀数组，前缀只需一个变量。


替代方案
  • 逐位置扫描左右两侧：O(n²) 时间、O(1) 额外空间，容易理解，但不适合 10⁵ 的上限。
  • 同时存储前缀最大值数组与后缀最小值数组：仍为 O(n) 时间和空间，表达对称，但可以省掉前缀数组。
  • 从左向右预存前缀最大值，再逆序维护右侧最小值：与主解法对称。


常见错误
  • 只看相邻数字就给 2 分：远处的元素仍可能破坏全局条件。
  • 使用 rightMin[i]：它包含当前值，会让严格小于判断无法成立；必须取 rightMin[i+1]。
  • 评分前就将 nums[i] 并入 leftMax：同样会把自身纳入左侧。
  • 分别用两个独立的 if 累加 2 和 1：满足全局条件时会重复计分。
  • 使用 ≤，或把首尾也加入遍历：均不符合定义。


面试追问
为什么不能只看邻居？例如 [2,4,6,4] 的 nums[1] 比两个邻居适中，却与远处的 4 相等，只能得 1 分。
一次流式读取就能立即确定当前得分吗？不能，尚未读到的右侧元素可能推翻 2 分条件；需要预处理或延迟结算。
为何先判断 2 分？全局条件成立必然蕴含邻居条件成立，先判 1 分会漏掉更高分。


Java
class Solution {
    public int sumOfBeauties(int[] nums) {
        int n = nums.length;
        int[] rightMin = new int[n];
        rightMin[n - 1] = nums[n - 1];
        for (int i = n - 2; i >= 0; i--) {
            rightMin[i] = Math.min(nums[i], rightMin[i + 1]);
        }
        int leftMax = nums[0], ans = 0;
        for (int i = 1; i < n - 1; i++) {
            if (leftMax < nums[i] && nums[i] < rightMin[i + 1]) {
                ans += 2;
            } else if (nums[i - 1] < nums[i] && nums[i] < nums[i + 1]) {
                ans++;
            }
            leftMax = Math.max(leftMax, nums[i]);
        }
        return ans;
    }
}

from typing import List

class Solution:
    def sumOfBeauties(self, nums: List[int]) -> int:
        n = len(nums)
        right_min = [0] * n
        right_min[-1] = nums[-1]
        for i in range(n - 2, -1, -1):
            right_min[i] = min(nums[i], right_min[i + 1])
        left_max = nums[0]
        ans = 0
        for i in range(1, n - 1):
            if left_max < nums[i] < right_min[i + 1]:
                ans += 2
            elif nums[i - 1] < nums[i] < nums[i + 1]:
                ans += 1
            left_max = max(left_max, nums[i])
        return ans
