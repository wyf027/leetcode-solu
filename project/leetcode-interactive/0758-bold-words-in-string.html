01 · 理解任务

题意与规则

给定关键词数组 words 和只含小写字母的字符串 s，在 s 中所有关键词出现的位置外添加 <b> 与 </b>，并返回添加标签后的字符串。

输出必须满足

  • 关键词的每一次出现都要覆盖，包括彼此重叠的出现。
  • 重叠或首尾相接的加粗片段应合并，用尽可能少的标签。
  • 标签必须正确配对；未被任何关键词覆盖的字符保持原样。

示例 1

输入
words = ["ab", "bc"], s = "aabcd"
输出
"a<b>abc</b>d"
说明
ab 与 bc 的命中重叠，合并覆盖 abc。

示例 2

输入
words = ["ab", "cb"], s = "aabcd"
输出
"a<b>ab</b>cd"
说明
这里只有 ab 命中，cb 没有出现在 s 中。

函数参数

boldWords(words: string[], s: string): string

约束

  • 1 <= s.length <= 500
  • 0 <= words.length <= 50
  • 1 <= words[i].length <= 10
  • s 与 words[i] 仅由小写英文字母组成。

读题提醒

words 可以为空；同一关键词也可能在 s 中多次出现或自重叠。

04 · 完整题解

布尔标记，把匹配与输出解耦

先回答“哪些字符要加粗”，再回答“标签放在哪里”。这个拆分让重叠与相邻合并自然发生。

核心洞察

建立长度为 n 的布尔数组 bold。每找到一个从 i 开始的关键词 word，就把半开区间 [i, i + word.length) 全部标为真。

多个命中写入同一张地图，所以交叠位置不会重复；相邻位置连续为真，输出时也不会被拆开。

完整过程

  1. 初始化 bold[0...n-1] = false。
  2. 枚举每个起点和每个关键词，命中就标记对应区间。
  3. 从左向右扫描；遇到一段连续的真值，只包一对标签。
  4. 其余字符按原顺序直接写入答案。

正确性证明

引理 1：某个字符位置被标为真，当且仅当它属于至少一个关键词命中。 算法只在完整匹配成功后标记该匹配覆盖的位置，因此不会误标；同时枚举了每个起点和每个关键词， 所以任意真实命中都会被处理，不会漏标。

引理 2：输出阶段会为每个极大的连续真值区间恰好生成一对标签。 扫描遇到首个真值时写入开始标签，并持续写到下一处假值或字符串末尾才写结束标签。

结论：由引理 1，所有且仅有应加粗的字符位于这些连续区间中；由引理 2， 每个区间只用一对标签。任何更少的标签都会迫使两个被未加粗字符隔开的区间合并并误加粗， 因此算法结果正确且标签数量最少。

边界情况

  • words 为空或没有任何命中：原样返回 s。
  • 一个关键词完全包含另一个：重复标记不影响结果。
  • 命中彼此重叠或相邻：连续真值自动合并。
  • 整个字符串都被覆盖：答案只有一对最外层标签。
  • 同一关键词多次出现、自重叠：逐起点检查可以全部捕获。

复杂度

时间 O(n · m · L)
额外空间 O(n)
输出扫描 O(n)

其中 n = s.length、m = words.length、L 是关键词最大长度；不计返回字符串本身。

四语言完整代码

Java 
class Solution {
    public String boldWords(String[] words, String s) {
        int n = s.length();
        boolean[] bold = new boolean[n];

        for (int i = 0; i < n; i++) {
            for (String word : words) {
                if (s.startsWith(word, i)) {
                    int end = Math.min(n, i + word.length());
                    for (int j = i; j < end; j++) {
                        bold[j] = true;
                    }
                }
            }
        }

        StringBuilder answer = new StringBuilder();
        int i = 0;
        while (i < n) {
            if (!bold[i]) {
                answer.append(s.charAt(i));
                i++;
                continue;
            }

            answer.append("<b>");
            while (i < n && bold[i]) {
                answer.append(s.charAt(i));
                i++;
            }
            answer.append("</b>");
        }
        return answer.toString();
    }
}

from typing import List


class Solution:
    def boldWords(self, words: List[str], s: str) -> str:
        n = len(s)
        bold = [False] * n

        for i in range(n):
            for word in words:
                if s.startswith(word, i):
                    for j in range(i, i + len(word)):
                        bold[j] = True

        answer = []
        i = 0
        while i < n:
            if not bold[i]:
                answer.append(s[i])
                i += 1
                continue

            answer.append("<b>")
            while i < n and bold[i]:
                answer.append(s[i])
                i += 1
            answer.append("</b>")

        return "".join(answer)

class Solution {

    string boldWords(vector<string>& words, string s) {

        vector<bool> bold(n, false);

替代方案

可把所有关键词建成 Trie，从 s 的每个起点沿 Trie 向后走；路径中断就提前停止， 到达单词结尾就标记区间。若关键词数量和总长度更大，还可用 AC 自动机一次扫描找出多模式匹配。

在本题 m ≤ 50、L ≤ 10 的约束下，直接枚举更短、更稳，也更适合面试现场表达。

常见错误

  • 找到一个匹配就立刻插标签，导致后续索引偏移且难以合并。
  • 只合并重叠区间，却忘了首尾相接的区间也必须合并。
  • 用集合去重关键词后误以为解决了“多次出现”，没有枚举所有起点。
  • 在构造答案时漏掉字符串结尾的 </b>。
  • 把半开区间的右端点当成可标记位置，造成越界或多标一个字符。

面试追问

如果关键词有十万条？

考虑 Trie 或 AC 自动机，把逐词比较替换为一次多模式匹配。

如果 s 是流式输入？

需要保留最长关键词长度相关的窗口，并延迟输出尚可能与后续匹配相连的尾部。

能不用布尔数组吗？

可以收集所有命中区间、排序后合并，但本题布尔数组更直接，且 n 只有 500。

为什么相邻也会自动合并？

两个区间之间没有假值，输出扫描不会关闭标签，因此它们属于同一连续真值段。
