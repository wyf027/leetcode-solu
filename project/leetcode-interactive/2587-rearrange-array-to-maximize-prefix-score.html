01 / PROBLEM

题意与约束

你可以任意重排数组。目标不是让最终总和最大——总和不会因排列改变——而是让严格大于 0 的前缀和出现得尽可能多。

给定一个下标从 0 开始的整数数组 nums。你可以把所有元素重排成任意顺序，包括保持原顺序。

重排后，定义前缀和数组 prefix：

prefix[i] = nums[0] + nums[1] + … + nums[i]

数组的分数等于 prefix 中严格为正的元素个数。返回所有重排方案里可达到的最大分数。

约束

  • 1 <= nums.length <= 105
  • -106 <= nums[i] <= 106
  • 计分条件是 prefix[i] > 0，等于 0 不计分。

示例 1

输入：nums = [2,-1,0,1,-3,3,-3]
输出：6
解释：可重排为 [2,3,1,-1,-3,0,-3]。
前缀和为 [2,5,6,5,2,2,-1]，
其中 6 个为正，且这是最大值。

示例 2

输入：nums = [-2,-3,0]
输出：0
解释：无论如何重排，都不存在正的前缀和。

04 / SOLUTION

降序排列，逐个累加

让较大的数尽早贡献给所有后续前缀；排序后，统计严格为正的前缀和即可。

核心洞察

将 nums 按从大到小排列。对于任意长度 k，降序数组的前 k 项恰好是原数组中最大的 k 个数，因此它们的和不小于任何其他排列的前 k 项之和。

于是，如果某个排列在位置 k - 1 的前缀和为正，降序排列在同一位置的前缀和也一定为正。降序排列逐位置支配所有其他排列。

完整过程

  1. 把数组按降序排序。
  2. 从左到右把元素加入 sum。
  3. 若 sum > 0，答案加一；否则可以直接停止。
  4. 返回计数。累加和必须能容纳最坏情况下的 1011。

正确性证明

设降序排列为 d，任意排列为 p。对每个 k ∈ [1,n]，d 的前 k 个元素是数组中最大的 k 个元素，所以：

sum(d[0..k-1]) ≥ sum(p[0..k-1])

若 p 的第 k 个前缀为正，则右侧大于 0，左侧也大于 0。因此任意排列获得的每一个正前缀，降序排列在相同长度上都能获得。故降序排列的分数不少于任何排列，算法最优。

边界与常见错误

  • 全为非正数：第一个前缀就不为正，答案为 0。
  • 前缀和等于 0：不计分；条件必须写成 > 0。
  • 整数溢出：Java 用 long，C++ 用 long long。
  • 排错方向：升序会让负数过早消耗前缀余额。
  • 误算正元素个数：负数也可能位于正前缀中并贡献分数。

复杂度与替代方案

时间复杂度O(n log n)
额外空间O(1) 或 O(log n)

排序后的扫描是 O(n)；总复杂度由排序主导。额外空间取决于语言的排序实现。

替代方案：暴力枚举全部排列并计算前缀需要约 O(n! · n)，只适合极小规模验证。也可用最大堆逐个取最大元素，复杂度仍为 O(n log n)，但代码与常数开销更大，没有必要。

import java.util.Arrays;

class Solution {
    public int maxScore(int[] nums) {
        Arrays.sort(nums);
        long sum = 0;
        int score = 0;
        for (int i = nums.length - 1; i >= 0; i--) {
            sum += nums[i];
            if (sum <= 0) break;
            score++;
        }
        return score;
    }
}

面试追问

为什么可以在前缀和不为正时停止？

降序扫描到这里时，当前元素及后续元素都不大于它；此处不为正后，继续加入不会使和重新变正。

稳定排序重要吗？

不重要。相等元素交换不会改变任何前缀和。

若计分条件改成前缀和 ≥ 0？

排列策略仍可用同一支配关系证明，但计数条件与提前停止条件都要改为围绕 0 的非严格比较。

能否做到 O(n)？

在一般整数比较模型中，需要确定从大到小的取值次序，排序是直接且稳妥的方案；若值域很小，可用计数排序降到 O(n + V)。
