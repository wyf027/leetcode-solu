Shortest Distance to Target String in a Circular Array

单词排成一圈。从指定位置出发，每次走向相邻单词。要走多少步，才能遇见目标？先思考首尾相连会怎样改变路线。

01 / 题目与规则

给定从下标 0 开始的字符串数组 words、目标字符串 target 和起点 startIndex。数组首尾连接，长度为 n。在位置 i 时，一步可走到 (i + 1) % n 或 (i - 1 + n) % n。

返回从起点到任意一个等于 target 的单词所需的最少步数；没有目标则返回 -1。移动次数可以是 0。

官方约束

  • 1 ≤ words.length ≤ 100
  • 1 ≤ words[i].length ≤ 100
  • words[i] 和 target 仅由小写英文字母组成。
  • 0 ≤ startIndex < words.length

02 / 官方示例

示例 1 · 多个目标

words = ["hello","i","am","leetcode","hello"]
target = "hello"
startIndex = 1
输出：1

到下标 0，向左走 1 步或向右走 4 步；到下标 4，向左走 2 步或向右走 3 步。最短为 1。

示例 2 · 跨越首尾

words = ["a","b","leetcode"]
target = "leetcode"
startIndex = 0
输出：1

向右走 2 步，或跨过首尾向左走 1 步，后者更短。

示例 3 · 目标不存在

words = ["i","eat","leetcode"]
target = "ate"
startIndex = 0
输出：-1

eat 与 ate 不相等，数组中没有目标。

05 / 想清楚后，再看题解

尝试解释：为什么有时下标相差很远，实际却只隔一步？

题解 / 扫描目标，比较两段环路

核心洞察

固定起点 s 和目标下标 i，令 d = |i - s|。沿普通下标区间走需要 d 步，沿另一侧绕过首尾需要 n - d 步，所以两点距离为 min(d, n - d)。目标可出现多次，还要在所有目标位置中取最小值。

完整过程

  1. 用 n 作为“尚未找到目标”的哨兵值。
  2. 从下标 0 到 n - 1 扫描；不是目标就跳过。
  3. 遇到目标，计算 d，用 min(ans, d, n - d) 更新答案。
  4. 扫描结束，若答案仍为 n 返回 -1，否则返回答案。

示例 1：起点 1，扫描到目标下标 0 时两路为 1、4，答案更新成 1；扫描到目标下标 4 时两路为 3、2，答案仍为 1。下标扫描只是枚举候选，不是实际移动轨迹。

正确性证明

对任意目标位置，最短行走不需要绕完整一圈，也不需要往返折返：删去这些多余移动不会增加步数。剩余路线就是两点之间的两个方向之一，长度分别为 d 和 n-d；起点就是目标时，长度 0 最小。故公式得到该目标位置的最短距离。

循环不变量：处理完前 k 个位置后，ans 是这些位置中所有目标的最短距离的最小值；若不存在目标则为哨兵 n。初始化成立，每次跳过或取最小值都保持成立。全部扫描后覆盖所有目标，所以答案全局最优。合法距离小于 n，哨兵不变当且仅当目标不存在。

边界与复杂度

  • 起点命中得到 0；长度为 1 时同样成立。
  • 重复目标须全部考虑；两条路等长时任选一条。
  • 目标不存在返回 -1；不要把未找到的初值设成 0。
  • 按单次字符串比较计，时间 O(n)、额外空间 O(1)。细计字符串比较，若最大比较长度为 L，最坏时间为 O(nL)。可视化存储步骤及节点的空间不计入提交算法。

四语言提交代码

使用官方 closestTarget 签名。以下代码仅生成，尚未编译或运行。

Java

class Solution {
    public int closestTarget(String[] words, String target, int startIndex) {
        int n = words.length, ans = n;
        for (int i = 0; i < n; i++) {
            if (words[i].equals(target)) {
                int d = Math.abs(i - startIndex);
                ans = Math.min(ans, Math.min(d, n - d));
            }
        }
        return ans == n ? -1 : ans;
    }
}

替代方案

按距离 k = 0…⌊n/2⌋ 逐层检查 (s+k)%n 与 (s-k+n)%n，首次命中即可返回 k。仍是 O(n) 时间、O(1) 空间，邻近目标可更早结束；偶数环对面位置会被检查两次，但不影响答案。也可用 BFS，但此题已知环的结构，无需队列和访问集合。

常见错误

  • 只用 |i-s|，遗漏跨首尾的短路。
  • 找到第一个目标就返回，忽略后面可能更近的目标。
  • Java 用 == 比较字符串，应该用 equals。
  • 把下标差当成含端点的元素数量，多加了 1。
  • 双向模拟写 (s-k)%n，在 Java/JS/C++ 中可能得到负数；应先加 n。

面试追问

多次查询同一个数组？ 按字符串保存有序下标列表，二分找起点附近的前驱、后继，并考虑环形首尾候选。

只能向右走？ 每个目标距离改为 (i-s+n)%n。

每条边有不同的非负代价？ 无向环可用边权前缀和计算两条弧的总权重；下标差不再代表代价。
