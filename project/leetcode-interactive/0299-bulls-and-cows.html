猜数字游戏

秘密数字与一次猜测之间，藏着两种命中：位置也正确的公牛，以及数字正确但位置错开的奶牛。你能给出不重复计数的提示吗？

Problem brief

题意与输入输出

给定长度相同、只包含数字的字符串 secret 和 guess。逐位比较时，数字与位置都相同的位称为“公牛（Bull）”；排除所有公牛后，猜测中数字存在于秘密数字剩余部分、但位置不同且可以一一配对的位称为“奶牛（Cow）”。

返回格式为 "xAyB" 的提示，其中 x 是公牛数，y 是奶牛数。两个字符串都可能包含重复数字，因此同一个秘密数字位置不能被重复配对。

函数签名

getHint(secret: string, guess: string) -> string

示例 1

输入secret = "1807", guess = "7810"

输出"1A3B"

只有数字 8 的位置完全正确；其余 1、0、7 都能在剩余位置中一一配对。

示例 2

输入secret = "1123", guess = "0111"

输出"1A1B"

索引 1 的 1 是公牛；剩余的两个猜测 1 中只有一个能与秘密数字中尚未使用的 1 配对。

约束

  • 1 <= secret.length, guess.length <= 1000
  • secret.length == guess.length
  • secret 与 guess 仅由数字 0-9 组成

Solution vault

完整题解

这里包含核心算法、证明与四种语言实现。建议先在鉴定台中走完一个示例，再主动展开。

核心洞察：先拿走公牛，再计算多重集合交集

公牛必须优先确定，因为它们不能再参与奶牛配对。对于每个数字 0-9，奶牛贡献等于“秘密串非公牛部分的出现次数”和“猜测串非公牛部分的出现次数”的较小值。

完整过程

  1. 建立两个长度为 10 的计数数组，并令 bulls = 0。
  2. 同时遍历两个字符串：若同位置数字相同，公牛加一；否则分别记录这两个未匹配数字。
  3. 枚举数字 0 到 9，把两侧计数的较小值累加到 cows。
  4. 拼接并返回 bulls + "A" + cows + "B"。

边界情况

  • 全部命中：奶牛必须为 0。
  • 完全无交集：两项计数都为 0。
  • 大量重复数字：按出现次数的较小值配对。
  • 前导零：输入是字符串，不做整数转换。
  • 长度为 1：同样适用，无需特判。

正确性证明

  1. 公牛计数准确。第一次遍历逐一检查所有索引，且仅当 secret[i] == guess[i] 时增加公牛，因此每个且仅有每个公牛被计数一次。
  2. 公牛不会污染奶牛。只有不同位置的两个数字才进入计数数组，所以所有已作为公牛使用的位置都被排除。
  3. 每种数字的奶牛数准确。对任一数字 d，最多只能配对两侧剩余出现次数的较小值；同时总能任意一一配对这么多次，所以贡献恰为两者最小值。
  4. 总结果正确。数字种类互不重叠，对 0 到 9 的贡献求和不会重复使用任何位置。因此返回的公牛数与奶牛数都准确。

复杂度

时间：O(n) 额外空间：O(1)

计数数组固定为 10 个槽位，因此不随输入长度增长。

替代方案

单计数数组的一次遍历：遇到非公牛时，用数组保存此前 secret 与 guess 的数字净差；根据相反方向的余量即时识别奶牛。它仍是 O(n) / O(1)，但符号与更新顺序更容易写错。

哈希映射：思路相同，适合字符集合未知的推广题；本题只有十个数字，数组更简洁且常数更小。

常见错误

  • 直接统计两串的所有公共数字，再忘记减去公牛。
  • 对每个猜测数字用 includes 判断，导致重复数字被超额计数。
  • 先把字符串转成整数，丢失前导零。
  • 用集合而非频次，无法处理重复数字。
  • 在单数组写法中先修改余额，再判断旧余额。

面试追问

  • 能否把两个计数数组压成一个？如何证明更新顺序正确？
  • 如果字符集扩展到任意 Unicode 字符，数据结构如何调整？
  • 如果输入以流形式到达，能否在线维护答案？公牛与奶牛分别需要什么信息？
  • 若需要返回一组具体的奶牛配对索引，而不只是数量，算法要保存哪些额外状态？
Java · 官方提交签名O(n) / O(1)
class Solution {
    public String getHint(String secret, String guess) {
        int bulls = 0;
        int[] secretCount = new int[10];
        int[] guessCount = new int[10];

        for (int i = 0; i < secret.length(); i++) {
            char s = secret.charAt(i);
            char g = guess.charAt(i);
            if (s == g) {
                bulls++;
            } else {
                secretCount[s - '0']++;
                guessCount[g - '0']++;
            }
        }

        int cows = 0;
        for (int digit = 0; digit < 10; digit++) {
            cows += Math.min(secretCount[digit], guessCount[digit]);
        }
        return bulls + "A" + cows + "B";
    }
}

/**
 * @param {string} secret
 * @param {string} guess

var getHint = function(secret, guess) {
    let bulls = 0;
    const secretCount = new Array(10).fill(0);
    const guessCount = new Array(10).fill(0);

    for (let i = 0; i < secret.length; i++) {
        if (secret[i] === guess[i]) {
            bulls++;
        } else {
            secretCount[Number(secret[i])]++;
            guessCount[Number(guess[i])]++;
        }
    }

    let cows = 0;
    for (let digit = 0; digit < 10; digit++) {
        cows += Math.min(secretCount[digit], guessCount[digit]);
    }
    return bulls + "A" + cows + "B";
};
Python 3 · 官方提交签名O(n) / O(1)
class Solution:
    def getHint(self, secret: str, guess: str) -> str:
        bulls = 0
        secret_count = [0] * 10
        guess_count = [0] * 10

        for secret_digit, guess_digit in zip(secret, guess):
            if secret_digit == guess_digit:
                bulls += 1
            else:
                secret_count[ord(secret_digit) - ord("0")] += 1
                guess_count[ord(guess_digit) - ord("0")] += 1

        cows = sum(
            min(secret_count[digit], guess_count[digit])
            for digit in range(10)
        )
        return f"{bulls}A{cows}B"

};

Interview lens

把“重复数字”当作题眼

为什么不能直接用集合？

集合只记录“是否存在”，会丢掉出现次数。奶牛是带容量的一一配对问题，需要频次或显式占用标记。

为什么先统计公牛？

同位置命中具有最高优先级。若不先排除，某个位置可能既被算作公牛，又被剩余频次再次算作奶牛。
