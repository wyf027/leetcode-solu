有效的快递序列数目

Count All Valid Pickup and Delivery Options

困难数学动态规划组合数学

Problem

先把规则说清楚

有 n 笔互不相同的订单。第 i 笔订单包含一次取货 Pᵢ 和一次交付 Dᵢ，因此完整序列一共有 2n 个事件。

请统计有多少种事件排列满足：对每一笔订单，交付 Dᵢ 都严格出现在对应取货 Pᵢ 之后。答案可能很大，返回其对 10⁹ + 7 取余的结果。

1
订单彼此可穿插
不同订单的取货和交付没有固定先后。
2
同一订单不可倒置
唯一硬约束是每个 Pᵢ 必须早于 Dᵢ。

示例 3

Solution

组合计数：逐笔插入新订单

核心洞察
假设已有 i - 1 笔订单组成的任意有效序列。加入第 i 笔订单时，最终长度为 2i。只要从这 2i 个最终位置中选两个，把较早位置放 Pᵢ、较晚位置放 Dᵢ，新序列就仍然有效。

完整过程

  1. 用 f(i) 表示 i 笔订单的有效序列数，空序列为 f(0) = 1。
  2. 固定一条含 i - 1 笔订单的有效序列。加入新订单后共有 2i 个位置。
  3. 为新订单选择两个不同位置，共有 C(2i, 2) 种；较早位置必须放取货，较晚位置必须放交付，无须再乘 2。
  4. 因此 f(i) = f(i - 1) × C(2i, 2) = f(i - 1) × i × (2i - 1)。
  5. 从 i = 1 迭代到 n，每一步取模，最终返回 f(n)。

正确性证明

命题

递推式 f(i)=f(i-1)×C(2i,2) 恰好、不重不漏地计算所有 i 笔订单的有效序列。

基础情况

当 i=0 时只有空序列，故 f(0)=1。

归纳步骤

假设所有 i-1 笔订单的有效序列均被恰好计数。对其中任一序列，从最终 2i 个位置中选两个，较早处插入 Pᵢ、较晚处插入 Dᵢ，旧订单的相对次序和合法性不变，新订单也满足先取后送，因此得到有效序列。

反过来，从任意含 i 笔订单的有效序列中删除 Pᵢ 与 Dᵢ，会唯一还原一条 i-1 笔订单的有效序列以及被删除的两个位置。因此上述构造是一一对应，不重不漏。命题成立。

边界与数值安全

  • n = 1：循环执行一次，得到 1。
  • n = 500：每轮立即对 10⁹+7 取模，避免结果无限增长。
  • Java / C++：乘法前使用 64 位整数。JavaScript：每次乘一个因子后立即取模，使中间整数低于安全整数上限。

复杂度

时间复杂度O(n)

只需一次线性循环。

额外空间复杂度O(1)

仅维护累计答案。

class Solution {
    public int countOrders(int n) {
        final long MOD = 1_000_000_007L;
        long answer = 1L;

        for (long i = 1; i <= n; i++) {
            answer = answer * i % MOD;
            answer = answer * (2L * i - 1L) % MOD;
        }
        return (int) answer;
    }
}

替代方案

  • 全排列视角：2n 个不同事件共有 (2n)! 种排列；每一对 Pᵢ、Dᵢ 的相对顺序各淘汰一半，因此答案为 (2n)! / 2ⁿ。模意义下需使用 2 的逆元。
  • 状态 DP：按时间轴逐位放事件，记录已取货但未交付的订单数，也可推导相同计数，但状态更多。

常见错误

  • 把两个位置选好后再乘 2；实际上早位只能放 P，晚位只能放 D。
  • 直接计算巨大阶乘后再除以 2ⁿ；取模后不能使用普通整数除法。
  • Java/C++ 使用 32 位整数执行乘法，导致取模前溢出。
  • 把不同订单当成相同订单，漏掉订单编号带来的排列差异。

面试追问

  • 如果允许部分订单的交付先于取货呢？可以按违规订单数量分类，或用更细的组合状态计数。
  • 为什么删除最后编号订单能构成双射？因为订单编号唯一，删除的两个事件和它们的位置都能唯一识别。
  • 如何用阶乘公式实现？预计算 (2n)!，再乘 2ⁿ 的模逆元；单次查询更繁琐，多次查询时可统一预处理。
  • 若要回答多个 n 查询？预计算前缀 f(0…maxN)，每次查询 O(1)。
