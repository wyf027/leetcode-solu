Two fingers, one shortest route

二指输入的的最小距离

把 A–Z 摆在 6 列键盘上。两根手指可以从任意位置免费起步；你要决定每个字母交给哪根手指，让总曼哈顿移动距离最小。

Minimum Distance to Type a Word Using Two Fingers · 函数 minimumDistance(word)

题目转述

键盘按从左到右、从上到下的顺序排列 26 个大写字母，每行 6 个字母。字母编号为 0…25 时，它的坐标是 (⌊编号 / 6⌋, 编号 mod 6)。

给定只含大写英文字母的字符串 word，依次键入所有字符。每次可选择任意一根手指移动到目标字母，移动代价是两坐标的曼哈顿距离。两根手指第一次落到任意字母都不产生代价。返回可能的最小总代价。

distance = |x₁ − x₂| + |y₁ − y₂|

输入与约束

  • 参数：word: string
  • 返回：integer，最小移动总距离
  • 2 ≤ word.length ≤ 300
  • word[i] 均为大写英文字母
  • 两根手指的初始位置均为“未放置”，首次落键代价为 0

Solution · Dynamic Programming

让一根手指成为“刚按下的手指”

核心洞察

处理完 word[i] 后，一定有一根手指停在刚输入的 word[i] 上。无需记录两根手指的所有排列：把这根称为“当前手指”，状态只需记录另一根手指停在哪里。

用编号 0…25 表示 A…Z，再用 26 表示“尚未放置”。定义 dp[p]：已经输入到当前字符、当前手指停在当前字符、另一根手指停在 p 时的最小总距离。

完整过程

输入第一个字符时，任选一根手指免费落下，因此初始化 dp[26] = 0，其余为无穷大。随后从第二个字符开始转移。设上一个字符为 prev，本次目标为 cur，遍历另一根手指位置 p：

当前手指继续输入
next[p] = dp[p] + dist(prev, cur)
另一根手指不动。
或
另一根手指接力
next[prev] = dp[p] + dist(p, cur)
原当前手指留在 prev；若 p=26，距离为 0。

每轮只依赖上一轮，用两个长度为 27 的数组滚动。处理完所有字符后，答案是 min(dp)。

为什么正确

  1. 状态覆盖：处理完任意前缀后，最后一次按键必由某根手指完成，它必停在当前字符；另一根手指的位置由 p 完整描述，因此所有可能指法都落入某个状态。
  2. 转移完备：输入下一个字符时，只有两种选择：仍由当前手指输入，或由另一根手指接力。两个转移恰好覆盖这两类且没有遗漏。
  3. 最优子结构：到达同一状态时，未来只关心两指当前位置，不关心此前路径，所以只保留最小代价不会损失全局最优解。
  4. 归纳结论：初始状态正确；若 dp 包含当前前缀的全部最优状态，两类转移就得到下一前缀的全部最优状态。最终所有结束位置中的最小值即全局最优值。

边界处理

  • p = 26 表示手指尚未落键，从该状态移动到任意字母的代价必须是 0。
  • 相同字母之间距离为 0；连续重复字符不会增加移动成本。
  • 字母 Z 位于最后一行的第 2 列，但坐标公式仍直接适用，不需要补齐虚拟按键。
  • 题目约束长度至少为 2；实现对长度 0 或 1 也会自然返回 0。

复杂度

每个字符枚举 27 个“另一根手指”位置，时间复杂度为 O(26n)，通常写作 O(n)；滚动数组占 O(26) 额外空间，即常数空间。

四语言完整代码

Java 
import java.util.Arrays;

class Solution {
    private int distance(int from, int to) {
        if (from == 26) return 0;
        return Math.abs(from / 6 - to / 6)
             + Math.abs(from % 6 - to % 6);
    }

    public int minimumDistance(String word) {
        if (word.length() <= 1) return 0;

        final int INF = 1_000_000_000;
        int[] dp = new int[27];
        Arrays.fill(dp, INF);
        dp[26] = 0;

        for (int i = 1; i < word.length(); i++) {
            int prev = word.charAt(i - 1) - 'A';
            int cur = word.charAt(i) - 'A';
            int[] next = new int[27];
            Arrays.fill(next, INF);

            for (int other = 0; other <= 26; other++) {
                if (dp[other] == INF) continue;

                next[other] = Math.min(
                    next[other],
                    dp[other] + distance(prev, cur)
                );

                next[prev] = Math.min(
                    next[prev],
                    dp[other] + distance(other, cur)
                );
            }
            dp = next;
        }

        int answer = INF;
        for (int cost : dp) answer = Math.min(answer, cost);
        return answer;
    }
}

/**

var minimumDistance = function (word) {
    if (word.length <= 1) return 0;

    const FREE = 26;
    const distance = (from, to) => {
        if (from === FREE) return 0;
        return Math.abs(Math.floor(from / 6) - Math.floor(to / 6))
             + Math.abs((from % 6) - (to % 6));
    };

    let dp = Array(27).fill(Infinity);
    dp[FREE] = 0;

    for (let i = 1; i < word.length; i++) {
        const prev = word.charCodeAt(i - 1) - 65;
        const cur = word.charCodeAt(i) - 65;
        const next = Array(27).fill(Infinity);

        for (let other = 0; other <= 26; other++) {
            if (!Number.isFinite(dp[other])) continue;

            next[other] = Math.min(
                next[other],
                dp[other] + distance(prev, cur)
            );

            next[prev] = Math.min(
                next[prev],
                dp[other] + distance(other, cur)
            );
        }
        dp = next;
    }

    return Math.min(...dp);
};

        FREE = 26

        def distance(start: int, end: int) -> int:
            if start == FREE:
                return 0
            return (abs(start // 6 - end // 6)

                    next_dp[prev],
                    dp[other] + distance(other, cur),

替代方案

可以使用三维动态规划 dp[i][left][right]，表示已输入前 i 个字符且两指分别位于 left/right 的最小代价。它更直观，也便于回溯具体路径，但状态和转移更大。还可以计算“单指输入总代价 − 第二根手指带来的最大节省”，本质上与压缩 DP 等价，但推导更绕。

面试追问

  • 如何还原具体指法？ 为每轮每个状态额外记录来源状态和本轮使用哪根手指，最后从最小结束状态逆推。
  • 如果键盘布局任意？ 预先保存每个字符的坐标；DP 不变，只替换距离函数。
  • 如果有 k 根手指？ 固定一根为刚按键的手指，状态记录其余 k−1 根的位置；状态数会随 k 指数增长。
  • 为何能把两指身份交换？ 手指没有不同属性或专属代价；转移后把刚按键者统一称为当前手指，只是规范化命名。

常见错误

  • 把第一次落键算成从 A 或键盘原点出发；题意明确初始位置自由。
  • 接力后仍把另一根手指记在旧位置；正确的新“另一指”应是 prev。
  • 原地更新 dp，让同一字符被重复转移；每轮必须写入新的数组。
  • 把坐标的行列写反不会影响曼哈顿距离，但若只反一处或错误使用每行 5 键，就会得到错误答案。
