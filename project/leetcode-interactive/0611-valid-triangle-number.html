03 / Solution

排序 + 固定最长边 + 双指针

核心洞察

将数组升序排序。对任意三个选中的正数，设它们满足 a ≤ b ≤ c，只要最小两边之和大于最长边，即 a + b > c，另外两个三角形不等式自然成立。零无法成为有效边，也会在这个判断中自然被排除。

固定最长边 nums[k]：若 nums[left] + nums[right] > nums[k]，则 left…right-1 共 right-left 个位置全部有效。

原因是数组已排序：对任何 p ∈ [left, right - 1]，都有 nums[p] ≥ nums[left]，所以 nums[p] + nums[right] ≥ nums[left] + nums[right] > nums[k]。

完整过程

  1. 将 nums 升序排序。
  2. 让 k 从数组末尾向前移动，把 nums[k] 固定为当前三元组的最长边。
  3. 在区间 [0, k - 1] 放置 left = 0 与 right = k - 1。
  4. 若 nums[left] + nums[right] > nums[k]，一次加入 right - left，随后令 right--，尝试更短的第二大边。
  5. 否则当前最小边太短。即使配上当前可用的最大第二边也不够，只能令 left++。
  6. 当 left == right 时处理下一个 k，最终返回累计值。

正确性证明

1
批量加入的都有效。 成功分支中，排序保证区间内每个候选最小边不小于 nums[left]，因此与 nums[right] 的和都大于 nums[k]。
2
失败分支不会漏解。 若 nums[left] + nums[right] ≤ nums[k]，对固定的 left、k，任何不超过 right 的第二条边只会让和更小，所以这个 left 不可能产生有效组合，可以安全右移。
3
没有重复计数。 每个三元组具有唯一的最长边下标 k 和唯一的第二大边下标 right。成功分支只在处理这对下标时，把所有可行的较小边下标各加入一次。
4
覆盖全部解。 对每个可能的 k，双指针遍历并分类其左侧的候选下标对；结合前两点，所有且仅有有效三元组被累计，因此返回值正确。

复杂度

排序为 O(n log n)。每个最长边对应一次线性双指针扫描，总时间 O(n²)。除排序栈空间外，额外空间为 O(1)；具体排序空间取决于语言实现。

边界处理

  • 长度小于 3 时直接返回 0。
  • 零会被不等式自然排除。
  • 重复边长按不同下标计数。
  • 全等边如 [2,2,2,2] 的答案是组合数 C(4,3)=4。
  • 本题最大答案 C(1000,3) 可放入 32 位有符号整数。

四语言完整代码

import java.util.Arrays;

class Solution {
    public int triangleNumber(int[] nums) {
        Arrays.sort(nums);
        int count = 0;

        for (int k = nums.length - 1; k >= 2; k--) {
            int left = 0;
            int right = k - 1;

            while (left < right) {
                if (nums[left] + nums[right] > nums[k]) {
                    count += right - left;
                    right--;
                } else {
                    left++;
                }
            }
        }
        return count;
    }
}

替代方案

  • 枚举两边 + 二分：排序后枚举前两条边，二分查找第一个不小于二者之和的位置，可得到 O(n² log n) 时间。容易理解，但慢于双指针。
  • 三重枚举：检查所有下标三元组，时间为 O(n³)，在 n = 1000 时不可取。
  • 计数数组：元素值上界只有 1000，可研究基于频率的组合计数；但需要细分相等边情况，代码更复杂，面试中通常不如排序双指针稳健。

面试追问

为什么成功时移动 right，而不是 left？

成功时，固定 right、k 已经一次统计了所有从 left 到 right - 1 的最小边。继续增大 left 只会重复这些组合；减小 right 才会进入下一组尚未处理的第二大边。

如果数组允许负数会怎样？

三角形边长必须为正。若输入域扩展到负数，应明确过滤非正数，或证明排序后的判断仍不会把它们计入。本题官方约束为非负整数。

能否提前跳过某些最长边？

可以做小优化，例如 nums[k] == 0 时更小的边也不可能有效；但不需要这类剪枝也能达到目标复杂度，保持主循环统一通常更清晰。

常见错误

  • 忘记排序，却直接使用双指针的单调性。
  • 成功时只加 1，丢失了 right - left 个批量组合。
  • 使用 >=；两边之和等于第三边只能形成退化图形，不是三角形。
  • 把重复数值去重；题目按数组下标选取，重复值可能代表不同组合。
  • 循环边界写错：最长边至少位于下标 2，且内部条件应为 left < right。
