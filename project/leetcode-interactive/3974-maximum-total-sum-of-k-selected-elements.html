3974. K 个元素的最大总和

在递减的乘数时间轴上，把最大的元素放到最有价值的位置。

难度：中等核心：排序 + 交换论证输出：64 位整数

题意

给定正整数数组 nums、k 与 mul。恰好选 k 个元素，按任意顺序逐个处理：每次可直接加该值，或乘以当前 mul 后加入总和；处理后 mul 减 1。求最大总和。

当 mul ≤ 1 时，乘法不会优于直接相加；只需把递减乘数中大于 1 的部分配给最大的数。

示例与约束

nums = [6, 1, 2, 9]，k = 3，mul = 2：选 9, 6, 2，贡献为 9×2 + 6×1 + 2 = 26。

约束：1 ≤ nums.length ≤ 10⁵，1 ≤ nums[i], mul ≤ 10⁵，1 ≤ k ≤ nums.length。

乘数分配实验室

按“下一步”观察：先排序，再把当前最大有效乘数配给当前最大元素。

题解：从乘数槽位出发

核心洞察

先选前 k 大的元素一定不差：任何较小的被选数都可替换为未选的大数。再按从大到小处理；若两个数 a ≥ b 分给 x ≥ y，则 ax + by − (ay + bx) = (a-b)(x-y) ≥ 0。

完整过程

  1. 将数组升序排序。
  2. 从末尾取 k 个，factor = max(1, mul)。
  3. 累加 num × factor，随后 mul--。

边界

mul=1 时乘或加相同；之后必须加。使用 long long / long 保存结果。

复杂度

排序 O(n log n)，扫描 O(k)；额外空间取决于排序实现。

替代方案

可用大小为 k 的最小堆维护前 k 大数，再排序这 k 个数；当 n 很大且 k 很小时可降低常数，但主方案更简洁。

面试追问

若元素允许负数，需重新比较“直接加”和“乘当前 mul”的选择，不能只固定选最大 k 个。

常见错误

把 mul≤0 也用于乘法；忽略处理顺序；或用 32 位整数溢出。
