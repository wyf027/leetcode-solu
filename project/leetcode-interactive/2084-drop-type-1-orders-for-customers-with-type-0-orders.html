01 / 题目与输入约定

输入表 Orders 记录订单、客户与类型。对每位客户：只要他有类型 0 的订单，结果中就排除他的所有类型 1 订单；如果没有类型 0，则保留他的所有订单。返回原表的三个字段，行顺序不限。

“删除”指从查询结果中排除；本题编写 SELECT 查询，不修改源表。

05 / 独立题解

完成自己的判断后，再展开推导与代码。

核心洞察：资格属于客户，保留的是订单

对于一行订单，保留条件是“本行类型为 0，或者同一客户不存在类型为 0 的订单”。必须观察客户的全部订单，不能在看到第一条类型 1 时就作最终判断。

完整过程

  1. 以外层别名 o 枚举每条订单。
  2. 类型为 0 的行符合保留条件。
  3. 对其他行，在 Orders 中查找同客户且类型为 0 的证据行 z。
  4. NOT EXISTS 表示没有找到证据，此时保留该类型 1 订单；否则排除。
  5. 输出 o 的三个原始字段，无需 DISTINCT，也无需排序。

正确性

固定任意客户 c。若 c 有 0 型订单，所有 0 型行满足第一个条件，所有 1 型行的 NOT EXISTS 为假，因此只保留 0 型；若 c 没有 0 型订单，每条行的 NOT EXISTS 均为真，全部保留。两种情况覆盖所有客户，且原始行只被外层枚举一次，所以没有漏单或重复造单。

边界与常见错误

  • 全 0：全部保留。全 1：也全部保留。空表：返回空表。
  • 一个客户有多个 0 型订单，必须全部保留，不能 GROUP BY 后随意取一行。
  • 只写 WHERE order_type = 0 会误删仅有 1 型订单的客户。
  • 子查询缺少 customer_id 关联，会让某个客户的 0 型订单影响所有客户。
  • 直接连接每条 0 型证据会放大结果行数；EXISTS 只检查存在性。
  • 不要执行 DELETE；查询结果过滤与持久删除不同。

复杂度

令 n 为订单数，c 为不同客户数。四语言参考实现先建立“有 0 型订单的客户集合”，再过滤：哈希集合平均时间 O(n)，辅助空间 O(c)，另需 O(n) 输出空间。SQL 性能依赖执行计划：无索引的逐行相关扫描最坏 O(n²)；优化器可能改写为反连接或半连接。索引 (customer_id, order_type) 可支持存在性检索，常见计划约为 O(n log n)，不能把这一估计当作数据库的固定保证。

替代方案

窗口函数 MIN(order_type) OVER (PARTITION BY customer_id) 给出每位客户最小类型，再保留 order_type 等于最小值的行；这依赖类型只含 0、1。也可先聚合有 0 型的客户再做反连接。NOT IN 在子查询可能含 NULL 时存在三值逻辑陷阱，NOT EXISTS 更直接表达本题。

面试追问

  • 增加类型 2 后规则是否仍是“只去掉 1”？需要明确新类型保留规则，不能直接沿用“只保留最小类型”。
  • 输入作为流抵达，能立即输出 1 型订单吗？不能保证，因为同客户的 0 型订单可能稍后到达，需要缓冲或结束信号。
  • 表达到千万行如何优化？查看实际执行计划与客户类型联合索引；结合数据分布评估预聚合。

MySQL · 官方可提交语言

SELECT o.order_id, o.customer_id, o.order_type
FROM Orders AS o
WHERE o.order_type = 0
   OR NOT EXISTS (
       SELECT 1
       FROM Orders AS z
       WHERE z.customer_id = o.customer_id
         AND z.order_type = 0
   );

Java · 本地语义参考

import java.util.*;

public class Solution {
    // 每行依次为 order_id, customer_id, order_type。
    public static List<int[]> dropSpecificOrders(int[][] orders) {
        Set<Integer> zeroCustomers = new HashSet<>();
        for (int[] row : orders) {
            if (row[2] == 0) zeroCustomers.add(row[1]);
        }
        List<int[]> result = new ArrayList<>();
        for (int[] row : orders) {
            if (row[2] == 0 || !zeroCustomers.contains(row[1])) {
                result.add(row.clone());
            }
        }
        return result;
    }
}

JavaScript · 本地语义参考

// orders: Array<[order_id, customer_id, order_type]>
function dropSpecificOrders(orders) {
  const zeroCustomers = new Set();
  for (const [, customerId, type] of orders) {
    if (type === 0) zeroCustomers.add(customerId);
  }
  return orders
    .filter(([, customerId, type]) => type === 0 || !zeroCustomers.has(customerId))
    .map(row => [...row]);
}

Python · 本地语义参考（非 Pandas 提交签名）

def drop_specific_orders(orders: list[list[int]]) -> list[list[int]]:
    # 每行依次为 order_id, customer_id, order_type。
    zero_customers = {customer for _, customer, kind in orders if kind == 0}
    return [row.copy() for row in orders
            if row[2] == 0 or row[1] not in zero_customers]

C++ · 本地语义参考

#include <array>
#include <vector>
#include <unordered_set>

using Order = std::array<int, 3>;

std::vector<Order> dropSpecificOrders(const std::vector<Order>& orders) {
    std::unordered_set<int> zeroCustomers;
    for (const auto& row : orders) {
        if (row[2] == 0) zeroCustomers.insert(row[1]);
    }
    std::vector<Order> result;
    for (const auto& row : orders) {
        if (row[2] == 0 || zeroCustomers.count(row[1]) == 0) {
            result.push_back(row);
        }
    }
    return result;
}
