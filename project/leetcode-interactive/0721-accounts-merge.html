账户合并Accounts Merge

同名不等于同一个人；真正可靠的线索，是账户之间是否共享邮箱。请把散落的记录还原成互不重复、邮箱有序的真实账户组。

难度：MEDIUM 参数：accounts: string[][] 返回：string[][] 非付费题

Problem

先把规则读准确

题意转述

给定二维字符串列表 accounts。每行的第一个字符串 accounts[i][0] 是姓名，后续字符串都是该账户登记的有效邮箱。

如果两个账户至少共享一个邮箱，它们就确定属于同一个人；这种关系具有传递性：A 与 B 共享邮箱、B 与 C 共享邮箱时，A、B、C 都应合并。仅仅姓名相同不能作为合并依据，因为不同的人可能同名。

返回合并后的账户。每组第一个元素仍是姓名，后续邮箱必须按字符顺序升序排列且不重复；不同账户组之间的返回顺序任意。

关键判定

共享邮箱才建立身份联系；姓名只用于最终输出，不用于判断两个账户是否相连。

约束

  • 1 <= accounts.length <= 1000
  • 2 <= accounts[i].length <= 10
  • 1 <= accounts[i][j].length <= 30
  • accounts[i][0] 仅含英文字母
  • j > 0 时 accounts[i][j] 是有效邮箱
官方示例 1组间顺序任意
输入：accounts =
[["John","johnsmith@mail.com","john_newyork@mail.com"],
 ["John","johnsmith@mail.com","john00@mail.com"],
 ["Mary","mary@mail.com"],
 ["John","johnnybravo@mail.com"]]

输出：
[["John","john00@mail.com","john_newyork@mail.com",
  "johnsmith@mail.com"],
 ["Mary","mary@mail.com"],
 ["John","johnnybravo@mail.com"]]
前两个 John 共享 johnsmith@mail.com，因此合并；另一位 John 没有共享邮箱，必须保留为独立组。

Deep Dive

并查集：让共享邮箱传递连接

把每一行账户看成一个节点。扫描邮箱时，记录它第一次出现在哪个账户；若再次遇到同一邮箱，就把当前账户与首次出现的账户合并。

核心洞察

1

节点选账户

最多 1000 个账户，用账户下标作为并查集节点直接、稳定；邮箱只负责建立连接。

2

邮箱是连接证据

emailOwner[email] 保存首次拥有该邮箱的账户下标，再次出现就执行合并。

3

连通性自动传递

并查集会把 A—B、B—C 压成同一个代表元，因此无需枚举所有账户对。

4

最后统一归档

再次扫描全部邮箱，按账户根节点收集、去重、排序，再在最前面放入该组姓名。

完整过程

  1. 初始化。 为每个账户建立独立集合，令 parent[i] = i，并准备邮箱到首次账户的映射。
  2. 建立连接。 遍历第 i 个账户的每个邮箱。首次出现就记录 i；否则合并 i 与记录中的账户。
  3. 压缩身份组。 所有邮箱扫描完成后，同一人的所有账户都拥有相同根节点。
  4. 收集邮箱。 再遍历每个账户，把其邮箱放入对应根节点的集合，集合自然消除重复邮箱。
  5. 整理输出。 对每组邮箱排序，在开头添加该根节点账户的姓名，并加入答案。组间顺序不作要求。

正确性证明

引理 1：若两个账户共享邮箱，算法会把它们合并到同一并查集。扫描该邮箱时，第一次出现会记录账户；之后每次出现都会与已记录账户执行合并，因此所有拥有该邮箱的账户最终同根。

引理 2：若两个账户属于同一个人，它们最终同根。题目给出的身份关系由一条或多条“共享邮箱”边连接。根据引理 1，每条边两端都会合并；并查集关系具有传递性，所以整条路径上的账户同根。

引理 3：算法不会合并不属于同一人的账户。算法只在发现相同邮箱时合并，而题目保证共享邮箱的账户确定属于同一个人，因此每次合并都安全。

定理：最终每个并查集恰好对应一个真实的人。由引理 2，同一人的账户不会被拆开；由引理 3，不同人的账户不会被合并。随后按根收集所有邮箱并去重、排序，故输出完全符合题意。

复杂度

指标结论原因
时间O(E · α(N) + E log E)E 为邮箱出现总次数，N 为账户数；并查集近似常数，排序总量上界为 E log E。
空间O(N + U)并查集使用 O(N)，邮箱映射和分组共保存 U 个不同邮箱。

更精确的排序项是各组 kᵢ log kᵢ 之和；这里给出易于面试表达的总体上界。

边界情况

同名但邮箱不同

不能合并；姓名从不参与连接判断。

链式共享

A 与 B、B 与 C 分别共享不同邮箱时，三者仍要合并。

邮箱重复出现

集合负责去重，避免最终账户中出现相同邮箱两次。

单独账户

从未发生合并的根也必须正常输出。

替代方案

邮箱图 + DFS / BFS：把邮箱作为图节点，同一账户中的邮箱互相连边，再枚举连通分量。实现时无需真的构造完全图，只需把每个账户的第一个邮箱与其余邮箱相连即可。

何时选择：如果题目继续要求输出邮箱之间的路径、邻接信息或做其他图遍历，DFS/BFS 更自然；只求分组时，并查集通常更紧凑。

class Solution {
    private static class UnionFind {
        private final int[] parent;
        private final int[] size;

        UnionFind(int n) {
            parent = new int[n];
            size = new int[n];
            for (int i = 0; i < n; i++) {
                parent[i] = i;
                size[i] = 1;
            }
        }

        int find(int x) {
            if (parent[x] != x) {
                parent[x] = find(parent[x]);
            }
            return parent[x];
        }

        void union(int a, int b) {
            int rootA = find(a);
            int rootB = find(b);
            if (rootA == rootB) return;
            if (size[rootA] < size[rootB]) {
                int temp = rootA;
                rootA = rootB;
                rootB = temp;
            }
            parent[rootB] = rootA;
            size[rootA] += size[rootB];
        }
    }

    public List<List<String>> accountsMerge(
            List<List<String>> accounts) {
        int n = accounts.size();
        UnionFind uf = new UnionFind(n);
        Map<String, Integer> firstOwner = new HashMap<>();

        for (int i = 0; i < n; i++) {
            for (int j = 1; j < accounts.get(i).size(); j++) {
                String email = accounts.get(i).get(j);
                Integer owner = firstOwner.putIfAbsent(email, i);
                if (owner != null) {
                    uf.union(i, owner);
                }
            }
        }

        Map<Integer, Set<String>> grouped = new HashMap<>();
        for (int i = 0; i < n; i++) {
            int root = uf.find(i);
            grouped.computeIfAbsent(root, key -> new HashSet<>())
                   .addAll(accounts.get(i).subList(1, accounts.get(i).size()));
        }

        List<List<String>> answer = new ArrayList<>();
        for (Map.Entry<Integer, Set<String>> entry : grouped.entrySet()) {
            List<String> emails = new ArrayList<>(entry.getValue());
            Collections.sort(emails);
            List<String> merged = new ArrayList<>();
            merged.add(accounts.get(entry.getKey()).get(0));
            merged.addAll(emails);
            answer.add(merged);
        }
        return answer;
    }
}

var accountsMerge = function (accounts) {
    const n = accounts.length;
    const parent = Array.from({ length: n }, (_, i) => i);
    const size = Array(n).fill(1);

    const find = (x) => {
        if (parent[x] !== x) {
            parent[x] = find(parent[x]);
        }
        return parent[x];
    };

    const union = (a, b) => {
        let rootA = find(a);
        let rootB = find(b);
        if (rootA === rootB) return;
        if (size[rootA] < size[rootB]) {
            [rootA, rootB] = [rootB, rootA];
        }
        parent[rootB] = rootA;
        size[rootA] += size[rootB];
    };

    const firstOwner = new Map();
    for (let i = 0; i < n; i++) {
        for (let j = 1; j < accounts[i].length; j++) {
            const email = accounts[i][j];
            if (firstOwner.has(email)) {
                union(i, firstOwner.get(email));
            } else {
                firstOwner.set(email, i);
            }
        }
    }

    const grouped = new Map();
    for (let i = 0; i < n; i++) {
        const root = find(i);
        if (!grouped.has(root)) grouped.set(root, new Set());
        for (let j = 1; j < accounts[i].length; j++) {
            grouped.get(root).add(accounts[i][j]);
        }
    }

    const answer = [];
    for (const [root, emailSet] of grouped) {
        const emails = [...emailSet].sort();
        answer.push([accounts[root][0], ...emails]);
    }
    return answer;
};
from typing import List


class Solution:
    def accountsMerge(
        self, accounts: List[List[str]]
    ) -> List[List[str]]:
        n = len(accounts)
        parent = list(range(n))
        size = [1] * n

        def find(x: int) -> int:
            if parent[x] != x:
                parent[x] = find(parent[x])
            return parent[x]

        def union(a: int, b: int) -> None:
            root_a = find(a)
            root_b = find(b)
            if root_a == root_b:
                return
            if size[root_a] < size[root_b]:
                root_a, root_b = root_b, root_a
            parent[root_b] = root_a
            size[root_a] += size[root_b]

        first_owner = {}
        for i, account in enumerate(accounts):
            for email in account[1:]:
                if email in first_owner:
                    union(i, first_owner[email])
                else:
                    first_owner[email] = i

        grouped = {}
        for i, account in enumerate(accounts):
            root = find(i)
            grouped.setdefault(root, set()).update(account[1:])

        answer = []
        for root, email_set in grouped.items():
            answer.append([accounts[root][0]] + sorted(email_set))
        return answer
class Solution {
    class UnionFind {
        vector<int> parent;
        vector<int> size;

    public:
        explicit UnionFind(int n) : parent(n), size(n, 1) {
            iota(parent.begin(), parent.end(), 0);
        }

        int find(int x) {
            if (parent[x] != x) {
                parent[x] = find(parent[x]);
            }
            return parent[x];
        }

        void unite(int a, int b) {
            int rootA = find(a);
            int rootB = find(b);
            if (rootA == rootB) return;
            if (size[rootA] < size[rootB]) swap(rootA, rootB);
            parent[rootB] = rootA;
            size[rootA] += size[rootB];
        }
    };

public:
    vector<vector<string>> accountsMerge(
        vector<vector<string>>& accounts
    ) {
        int n = static_cast<int>(accounts.size());
        UnionFind uf(n);
        unordered_map<string, int> firstOwner;

        for (int i = 0; i < n; ++i) {
            for (int j = 1; j < static_cast<int>(accounts[i].size()); ++j) {
                const string& email = accounts[i][j];
                auto [it, inserted] = firstOwner.emplace(email, i);
                if (!inserted) uf.unite(i, it->second);
            }
        }

        unordered_map<int, set<string>> grouped;
        for (int i = 0; i < n; ++i) {
            int root = uf.find(i);
            for (int j = 1; j < static_cast<int>(accounts[i].size()); ++j) {
                grouped[root].insert(accounts[i][j]);
            }
        }

        vector<vector<string>> answer;
        for (auto& [root, emails] : grouped) {
            vector<string> merged;
            merged.push_back(accounts[root][0]);
            merged.insert(merged.end(), emails.begin(), emails.end());
            answer.push_back(move(merged));
        }
        return answer;
    }
};

面试追问

为什么不能按姓名直接分组？

姓名不是唯一标识，不同的人可能同名。题目只承诺“共享邮箱”能确认身份。

为什么不需要比较所有账户对？

邮箱映射直接定位已见账户，让每次连接由邮箱触发，避免 O(N²) 的账户两两比较。

如果数据持续流入，怎么扩展？

可维护持久化的邮箱到身份根映射，并对新账户做增量合并；同时要设计根标识迁移、并发冲突与审计记录。

组间顺序需要排序吗？

不需要，题目允许账户组任意顺序；每个组内部的邮箱必须排序。

常见错误

  • 只合并直接共享邮箱的账户，遗漏 A—B—C 的传递连接。
  • 看到姓名相同就合并，错误合并同名的不同用户。
  • 按合并前下标收集邮箱，没有先 find(i) 取得最终根。
  • 忘记邮箱去重或组内排序。
  • 错误要求不同账户组也必须按固定顺序返回。
