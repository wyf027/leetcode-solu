Race briefing

判断赛道是否闭环

给定链表头节点 head，判断沿 next 是否会再次访问某个节点。题面里的 pos 只描述尾节点接回的位置，并不是函数参数。

题意转述

若从某个节点不断跟随 next 能回到已访问节点，链表存在环，返回 true；否则返回 false。

  • 节点数范围：[0, 10^4]。
  • 节点值范围：[-10^5, 10^5]。
  • pos = -1 表示尾节点指向 null。

核心追问：能否只用常数额外空间？Floyd 快慢指针正是面试最推荐答案。

官方样例 1

输入 head = [3,2,0,-4], pos = 1
期望输出 true
解释 tail.next → node[1]

本题输入不含字符串空格；若页面展示含空格文本，会用 ␠ 表示可见空格。

Floyd playbook

核心洞察

              

                慢指针每轮走 1 步，快指针每轮走 2 步。若没有环，快指针会先到
                null；若存在环，两者进入环后，快指针每轮相对慢指针靠近 1
                个节点，所以至多再经过一个环长就会相遇。
              

            


            

              
完整过程

              
    
                
  1. 令 slow = head、fast = head。
    2. 
                
  2. 
                  只要 fast 和
                  fast.next 都存在，就能继续。
                
    3. 
                
  3. 
                  slow = slow.next，fast = fast.next.next。
                
    4. 
                
  4. 若两者引用同一节点，立即返回 true。
    5. 
                
  5. 循环结束仍未相遇，返回 false。
    6. 
              

            


            

              
边界

              
    
                
  • 空链表：循环不进入，返回 false。
    • 
                
  • 
                  单节点且指向 null：返回 false。
                
    • 
                
  • 
                  单节点自环：第一次移动后两指针仍是同一节点，返回
                  true。
                
    • 
                
  • 比较的是节点引用，不是节点值；值重复并不表示成环。
    • 
              

            


            

              
复杂度

              

                设节点数为
                n。快慢指针在进入环或走到链表末端前只经过线性数量节点，时间复杂度
                O(n)；只维护两个指针，额外空间复杂度
                O(1)。
              

            


            

              
替代方案取舍

              
    
                
  • 
                  哈希集合：逐个记录访问过的节点，直观但需要
                  O(n) 额外空间。
                
    • 
                
  • 
                  修改节点标记：会破坏输入结构，面试和工程中通常不可接受。
                
    • 
                
  • 
                  Floyd：不改链表且常数空间，是本题主线。
                
    • 
              

            


            

              
面试追问

              
    
                
  • 为什么进入环后一定相遇？用模环长的相对距离说明。
    • 
                
  • 
                  如何进一步找到入环节点？相遇后让一指针回到头节点，再同速前进。
                
    • 
                
  • 如何计算环长度？相遇后固定一指针，让另一指针绕环计数。
    • 
                
  • 
                  为什么循环条件必须同时检查 fast 与
                  fast.next？
                
    • 
              

            


            

              
常见错误

              
    
                
  • 
                  初始时就比较
                  slow === fast，会把所有非空链表误判为有环。
                
    • 
                
  • 
                  只检查 fast，随后访问
                  fast.next.next 导致空指针。
                
    • 
                
  • 
                  比较 slow.val === fast.val，重复值会产生假阳性。
                
    • 
                
  • 
                  把题面中的 pos 写进提交函数参数；真实接口只接收
                  head。
                
    •

public class Solution {
    public boolean hasCycle(ListNode head) {
        ListNode slow = head;
        ListNode fast = head;

        while (fast != null && fast.next != null) {
            slow = slow.next;
            fast = fast.next.next;
            if (slow == fast) {
                return true;
            }
        }
        return false;
    }
}

            slow = slow->next;
