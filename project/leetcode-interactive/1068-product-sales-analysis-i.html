产品销售分析 I

Product Sales Analysis I

从销售事实表中保留每一笔销售，通过共同的 product_id 查到产品名称，输出产品名、年份与单价。先观察数据关系，再决定如何连接。

题目

Sales 的每一行是一笔商品在某年的销售记录，price 是单位价格；Product 保存商品编号与名称。请报告 Sales 中每个 sale_id 对应的 product_name、year 和 price，结果顺序不限。

product_idint外键 → Product
yearint销售年份
quantityint数量
priceint单位价格

约束与关系

  • (sale_id, year) 在 Sales 中唯一。
  • Product.product_id 唯一，且 Sales.product_id 引用它。
  • 每条 Sales 记录都应产生一条结果；quantity 不属于输出。

题解

核心洞察

输出字段横跨两张表：年份、价格来自 Sales，商品名来自 Product；它们唯一自然的关联键是 product_id。因此对两表做等值内连接，再投影所需三列即可。

完整过程

  1. 从 Sales 读取一条销售记录。
  2. 用该行的 product_id 在 Product 中匹配同编号商品。
  3. 组合 product_name、year、price。
  4. 对每条销售记录重复；不添加排序。

正确性说明

Sales 的 product_id 是指向 Product 主键的外键，所以每条销售记录恰好匹配一个商品名称。内连接产生的每一行对应原 Sales 的一笔销售，投影后三个字段也分别等于该销售对应的商品名、年份和单位价格。因此结果既不遗漏合法销售，也不会为同一销售引入错误商品，满足要求。

边界

  • 同一商品可跨年份或有多笔销售，均需保留。
  • Product 中没有销售的商品不会出现在结果里。
  • 结果允许任意顺序，不应依赖默认排序。

复杂度

数据库执行计划通常以哈希连接实现：设两表行数为 S、P，期望时间 O(S+P)，额外空间 O(P)；索引嵌套循环时取决于索引与优化器。SQL 声明本身不规定具体执行算法。

官方可提交语言：SQL

SELECT p.product_name, s.year, s.price
FROM Sales AS s
JOIN Product AS p
  ON s.product_id = p.product_id;

import java.util.*;

class Solution {
  record Sale(int saleId, int productId, int year, int quantity, int price) {}
  record Product(int productId, String name) {}
  record Result(String name, int year, int price) {}

  static List<Result> analyze(List<Sale> sales, List<Product> products) {
    Map<Integer, String> names = new HashMap<>();
    for (Product p : products) names.put(p.productId(), p.name());
    List<Result> ans = new ArrayList<>();
    for (Sale s : sales) ans.add(new Result(names.get(s.productId()), s.year(), s.price()));
    return ans;
  }
}
function salesAnalysis(sales, products) {
  const names = new Map(products.map(p => [p.product_id, p.product_name]));
  return sales.map(s => ({
    product_name: names.get(s.product_id),
    year: s.year,
    price: s.price

}
def sales_analysis(sales, products):
    names = {p["product_id"]: p["product_name"] for p in products}
    return [
        {"product_name": names[s["product_id"]],
         "year": s["year"], "price": s["price"]}
        for s in sales
    ]
#include <string>
#include <unordered_map>
#include <vector>
using namespace std;
struct Sale { int saleId, productId, year, quantity, price; };
struct Product { int productId; string name; };
struct Result { string name; int year, price; };

vector<Result> analyze(const vector<Sale>& sales,
                       const vector<Product>& products) {
  unordered_map<int, string> names;
  for (const auto& p : products) names[p.productId] = p.name;
  vector<Result> ans;
  for (const auto& s : sales) ans.push_back({names.at(s.productId), s.year, s.price});
  return ans;
}

替代方案

INNER JOIN 的显式写法最清楚。旧式逗号连接加 WHERE 虽等价，但更容易漏写连接条件；LEFT JOIN 在外键有效时结果相同，却弱化了“必须匹配”的语义。Pandas 可用 merge 后选择三列。

面试追问

  • 若外键不能保证存在，INNER JOIN 与 LEFT JOIN 的结果有何不同？
  • 若要求总销售额，应计算 quantity * price 还是只取 price？
  • 如何按商品和年份聚合？需要哪些 GROUP BY 字段？

常见错误

  • 把 sale_id 当作连接键。
  • 误将 price 乘 quantity，改变了题目要求。
  • 输出 quantity 或 product_id 等多余列。
  • 使用 NATURAL JOIN，使查询隐式依赖同名列。
