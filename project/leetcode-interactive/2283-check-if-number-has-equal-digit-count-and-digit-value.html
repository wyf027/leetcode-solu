01 / 题目

每个位置都是一条声明

给定只包含十进制数字的字符串 num，长度为 n，下标从 0 开始。对于每个 0 ≤ i < n，检查数字 i 在整个字符串中的出现次数，是否等于字符 num[i] 所表示的数值。全部相等返回 true；只要有一处不等就返回 false。

区分两个角色：下标 i 指定“要找哪个数字”；字符 num[i] 声明“它应该出现几次”。字符串可以以 0 开头。

官方示例 1

输入：num = "1210"
输出：true

下标 0 声明数字 0 出现 1 次；下标 1 声明数字 1 出现 2 次；下标 2 声明数字 2 出现 1 次；下标 3 声明数字 3 出现 0 次。四项都与实际相符。

官方示例 2

输入：num = "030"
输出：false

数字 0 声明出现 0 次，实际 2 次；数字 1 声明出现 3 次，实际 0 次；数字 2 声明出现 0 次，实际 0 次。下标 0、1 的声明不成立。

约束与接口

  • n == num.length
  • 1 ≤ n ≤ 10
  • num 只包含字符 '0' 至 '9'。
  • 参数：num: string；返回值：boolean；函数名：digitCount。

核心洞察：先数实际，再读声明

同一个字符串有两种读法：字符的值决定它给哪个数字贡献一次出现；字符的位置决定它在描述哪个数字。用长度为 10 的数组 count 统计实际频次，然后检查 count[i] == int(num[i])。

完整过程

  1. 创建 10 个初值为 0 的计数格，覆盖全部十进制数字。
  2. 遍历 num，把字符转成整数 d，执行 count[d]++。
  3. 再次遍历下标 i = 0 .. n-1，将声明转换为整数，与 count[i] 比较。
  4. 任意一次不等立即返回 false；所有位置相等才返回 true。

对 "1210"：读入 1、2、1、0 后，计数数组是 [1,2,1,0,0,0,0,0,0,0]。依次将前四项与 1、2、1、0 比较，全部相等。

为什么正确

计数不变式：读完前 k 个字符时，count[d] 等于数字 d 在此前缀中的出现次数。初始空前缀次数为 0；每读一个字符，只增加其对应数字的计数，因此不变式始终成立。读完整串后获得准确的全局频次。

核对结论：第二遍检查的每一项正是题目对下标 i 的要求。不等时已经找到违反条件的下标，返回 false 正确；若检查完毕没有不等，则所有要求均成立，返回 true 正确。

边界与复杂度

  • 保留字符串形式，否则 "030" 的前导零和下标关系会丢失。
  • 没有出现的数字计数为 0；声明为 0 也必须参与核对。
  • 计数数组长度是 10，不能仅按 n 分配：短串也可能包含数字 9。
  • 比较范围仅为 0 ≤ i < n，不读取不存在的 num[i]。
  • n = 1 也按相同步骤处理；如 "0" 声明零次却实际出现一次。
  • 两次遍历，时间 O(n)；固定 10 个计数格，额外空间 O(1)。虽然本题 n 至多 10，仍按输入长度描述遍历成本。

Java

class Solution {
    public boolean digitCount(String num) {
        int[] count = new int[10];
        for (int i = 0; i < num.length(); i++) {
            count[num.charAt(i) - '0']++;
        }
        for (int i = 0; i < num.length(); i++) {
            if (count[i] != num.charAt(i) - '0') {
                return false;
            }
        }
        return true;
    }
}

var digitCount = function(num) {
    const count = Array(10).fill(0);

        count[Number(digit)]++;
    }
    for (let i = 0; i < num.length; i++) {

    }
    return true;

class Solution:

            ++count[digit - '0'];
        }
        for (int i = 0; i < static_cast<int>(num.size()); ++i) {

替代方案

对每个 i 单独扫描字符串，计算字符 i 出现几次，再比较声明。它不需要计数数组，但要重复扫描，时间 O(n²)、额外空间 O(1)。本题很短，这样也可行。哈希表也能统计频次，但固定的 10 个数字直接用数组更简单。

常见错误

  • 写成 count[num[i]] == i：把“目标数字”和“声明次数”反过来了。
  • 边统计边判断：尚未读完的后缀仍可能增加当前数字的频次。
  • JavaScript 严格比较时不做数值转换：数字 1 与字符串 '1' 不相等。
  • 只检查声明次数之和等于 n：这是必要条件，却不足以说明每个数字都符合。例如 "22" 的和为 4，本已不符；而 "11" 的和为 2，却仍不符合逐位频次。
  • 跳过数字 0 或仅核对字符串中出现过的数字，漏掉声明不成立的位置。

面试追问

为什么有效字符串的声明总和一定等于 n？若全部相等，声明总和就是数字 0 到 n-1 的出现次数之和。若存在大于等于 n 的字符，其数值至少为 n，仅这一项声明就达到 n，但范围内的实际总次数至多 n-1，矛盾。因此有效串没有范围外的数字，声明总和等于 n；反过来仅有总和相等仍不充分，如 "11"。

如果字符集不再是 10 个数字？先明确定义“位置如何对应符号”和“次数如何编码”。固定大小字符集可扩展数组；稀疏的大字符集可用哈希表，时间 O(n + m)、空间 O(m)，m 为需要核对的符号数。

可以提前返回吗？计数完成后，首个不等就可返回 false；不能在仅有前缀频次时直接判定全局频次不符。
