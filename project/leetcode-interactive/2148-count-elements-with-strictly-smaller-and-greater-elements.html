01 / 题目

给定整数数组 nums，返回满足以下条件的元素个数：在同一个数组中，既能找到一个比它严格小的元素，也能找到一个比它严格大的元素。

比较对象可以在任意位置；相等的值不满足严格大小关系。按元素出现次数计数，重复值的每次出现都单独考虑。

官方示例 1

输入：nums = [11,7,2,15]
输出：2

11 可以找到更小的 7 和更大的 15；7 可以找到更小的 2 和更大的 11。共有 2 个元素符合条件。

官方示例 2

输入：nums = [-3,3,3,90]
输出：2

两个 3 都有更小的 -3 和更大的 90；它们分别计数，因此答案是 2。

约束与接口

  • 1 ≤ nums.length ≤ 100
  • -100000 ≤ nums[i] ≤ 100000
  • 参数：整数数组 nums；返回值：整数。

04 / 独立题解

尝试给出自己的判断条件，再展开分析。

核心洞察：严格位于两端之间

记全局最小值为 lo，最大值为 hi。某个值 x 符合条件，当且仅当 lo < x && x < hi。不需要为每个元素分别搜索两个比较对象，极值就是通用的见证。

完整过程

  1. 把 lo 与 hi 都初始化为 nums[0]。
  2. 第一遍扫描，更新 lo 和 hi。扫描结束时得到整个数组的极值。
  3. 第二遍扫描，遇到严格位于 lo 和 hi 之间的元素就将计数加一。
  4. 返回计数。每个数组位置独立判断，重复的内部值不会丢失。

以 [11,7,2,15] 为例：第一遍得到 lo = 2、hi = 15；第二遍依次计入 11、计入 7、排除 2、排除 15，答案为 2。

正确性证明

极值扫描不变式：每处理完一个前缀，lo 和 hi 分别是此前缀的最小值与最大值。初始化对第一个元素成立；取 min / max 的更新保持该性质，因此扫描结束时它们是全局极值。

必要性：若 x 存在较小元素 a 和较大元素 b，则 lo ≤ a < x < b ≤ hi，所以 lo < x < hi。

充分性：若 lo < x < hi，数组中值为 lo 和 hi 的元素分别提供严格较小与严格较大的见证。

第二遍恰好对满足这个充要条件的每次出现加一，因此返回值等于题目要求的元素数目。

边界与复杂度

  • 只有一个元素、全相等或只有两个不同值：不存在严格内部值，结果为 0。
  • 最小值或最大值重复出现时，每个副本都排除；内部值重复出现时，每个副本都计入。
  • 负数使用相同的比较逻辑；不修改原数组。
  • 时间 O(n)：两次线性扫描。额外空间 O(1)：仅保存极值与计数。演示界面的状态保存不属于提交算法的空间开销。

四语言实现

以下均为官方接口形式，可作为提交代码；本轮未编译或执行。

Java

class Solution {
    public int countElements(int[] nums) {
        int lo = nums[0], hi = nums[0];
        for (int x : nums) {
            lo = Math.min(lo, x);
            hi = Math.max(hi, x);
        }
        int answer = 0;
        for (int x : nums) {
            if (lo < x && x < hi) answer++;
        }
        return answer;
    }
}

Python

from typing import List

class Solution:
    def countElements(self, nums: List[int]) -> int:
        lo, hi = min(nums), max(nums)
        return sum(lo < x < hi for x in nums)

C++

#include <algorithm>
#include <vector>
using namespace std;

class Solution {
public:
    int countElements(vector<int>& nums) {
        int lo = nums[0], hi = nums[0];
        for (int x : nums) {
            lo = min(lo, x);
            hi = max(hi, x);
        }
        int answer = 0;
        for (int x : nums) {
            if (lo < x && x < hi) ++answer;
        }
        return answer;
    }
};

Python 的 min、max 各扫描一次，再用生成器计数；仍为 O(n) 时间、O(1) 额外空间。

替代方案

  • 逐个寻找见证：为每个位置扫描所有元素，分别记录是否有较小值和较大值；O(n²) 时间、O(1) 空间。
  • 排序：排序后跳过两端所有等于极值的元素，统计剩余区间。时间通常为 O(n log n)，空间依语言排序实现而定；复制数组会额外使用 O(n) 空间。
  • 极值频次：lo ≠ hi 时可用 n − 最小值出现次数 − 最大值出现次数。lo = hi 必须单独返回 0，否则重复扣减。

面试追问

能否只扫描一次？可以维护当前极值和各自的出现次数，结束后使用上面的频次公式，并处理 lo = hi。它节省一遍扫描，但分支更多。

如果比较改为非严格且要求不同位置？原来的判定不能直接套用；还要明确两个见证能否是同一位置，并根据该定义考虑频次。

能否低于 O(n)？对任意未排序输入，通常必须读取所有元素；遗漏的位置可能改变极值或内部元素个数。

常见错误

  • 将 < 写成 ≤，把边界值也算入答案。
  • 只从总长度减去 2，忽略极值可能重复。
  • 使用 Set 去重，丢掉应该按出现次数统计的内部元素。
  • 把“较小 / 较大”误解为“左侧 / 右侧”。
  • 在极值尚未确定时直接累计内部值，却没有处理极值变化带来的旧元素重分类。
  • 把 JavaScript 的链式比较写成 lo < x < hi；应使用两个条件和 &&。
