MEDIUM#2554

Maximum Number of Integers to Choose From a Range I

从一个范围内
选择最多整数 I

有限预算、禁选清单、每个数字只用一次。先读规则，再用交互实验观察不同选择会怎样影响数量。

数组哈希表贪心排序二分查找

Problem

题目要求

给定整数数组 banned、整数 n 和 maxSum，从闭区间 [1, n] 中选出尽可能多的整数，并同时满足：

  • 每个整数至多选择一次；
  • 选择的整数不能出现在 banned 中；
  • 所有已选整数之和不能超过 maxSum。
返回值：满足全部条件时，能够选择的最大整数数量。

Function

maxCount

maxCount(
  banned: integer[],
  n: integer,
  maxSum: integer
) -> integer

范围中的数只考虑一次；banned 中超出 [1,n] 的值不影响选择。

官方示例

Example 01
输入：banned = [1,6,5],
      n = 5, maxSum = 6
输出：2

可选择 2 和 4；它们都在范围内且未被禁用，总和为 6。

Example 02
输入：banned = [1,2,3,4,5,6,7],
      n = 8, maxSum = 1
输出：0

任何可选数字都会让条件无法满足，因此一个也不能选。

Example 03
输入：banned = [11],
      n = 7, maxSum = 50
输出：7

1 到 7 均可选，总和 28 不超过 50。

约束

1 ≤ banned.length ≤ 10⁴
1 ≤ banned[i], n ≤ 10⁴
1 ≤ maxSum ≤ 10⁹

Solution

从小到大的贪心选择

核心洞察

目标是让选择的数量最大，而每个数字的收益都相同（都只增加 1 个计数）。因此，在预算有限时应优先选择代价更小的可用数字。把 banned 放入哈希集合，然后从 1 扫描到 n：跳过禁选数字；如果加入当前数字不会超预算，就加入；否则立即停止。

为什么遇到超预算可以停止？

扫描顺序递增。若当前最小的剩余可选数字都无法加入，那么后面的任何可选数字只会更大，同样无法加入。

复杂度

时间：O(b + n)

空间：O(b)

其中 b 是 banned.length。哈希集合让禁选判断平均为 O(1)。

完整过程

  1. 建立禁选集合。将 banned 的元素加入哈希集合，重复值自然合并。
  2. 按升序扫描。依次检查 1, 2, …, n，遇到集合中的数直接跳过。
  3. 尝试加入预算。若 sum + value ≤ maxSum，更新总和与计数。
  4. 及时结束。若最小的当前候选都超出预算，返回已有计数。

正确性证明

引理：对任意固定的选择数量 k，按升序取出的前 k 个可用数字具有最小总和。

证明：若某个含 k 个数的可行选择没有使用最小的某个可用数字 x，却使用了更大的数字 y，用 x 替换 y 不会增加总和，也不会违反禁选或重复限制。反复交换即可得到升序的前 k 个可用数字。因此，如果贪心选出的前 k+1 个可用数字总和已经超过预算，其他任何 k+1 个数字的总和都不会更小，也就不可能可行。贪心返回的 k 因而是最大数量。

边界情况

全部禁选

若 [1,n] 中没有可选数字，答案为 0。

第一个候选就超预算

无法选取任何数，立即返回 0。

禁选值超出范围

集合可以保留它们；扫描不到，因此不影响结果。

禁选数组有重复值

哈希集合自动去重，不会重复产生影响。

四语言实现

import java.util.HashSet;
import java.util.Set;

class Solution {
    public int maxCount(int[] banned, int n, int maxSum) {
        Set<Integer> blocked = new HashSet<>();
        for (int value : banned) {
            blocked.add(value);
        }

        int sum = 0;
        int count = 0;
        for (int value = 1; value <= n; value++) {
            if (blocked.contains(value)) continue;
            if (sum + value > maxSum) break;
            sum += value;
            count++;
        }
        return count;
    }
}

替代方案

可以先过滤并排序禁选数组，再用指针跳过禁选值；这避免哈希表，但排序需要 O(b log b)。也可以用长度为 n+1 的布尔数组标记禁选值，查询稳定为 O(1)，空间为 O(n)。

面试追问

  • 若 n 达到 10⁹，如何跳过连续区间并用等差数列求和？
  • 若每个数字拥有不同价值，贪心依据是否仍成立？
  • 若允许多次查询不同的 maxSum，如何预处理前缀和并二分？

常见错误

  • 优先选择大数，导致相同预算下可选数量减少。
  • 把 sum + value == maxSum 错误地判为超预算。
  • 先加入再检查，造成一次越界选择或回滚逻辑遗漏。
  • 每次用数组线性查找禁选值，使最坏时间退化为 O(n × b)。
