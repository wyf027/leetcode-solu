凸多边形Convex Polygon

给一组按边界顺序连接的平面点，判断它们围成的简单多边形是否为凸多边形。

  • 数组
  • 数学
  • 几何
  • 多边形
01 / Problem

题目描述

给定二维整数数组 points，其中 points[i] = [xᵢ, yᵢ]。依次连接相邻点，并连接最后一个点与第一个点，即得到一个多边形。

若该多边形为凸多边形，返回 true；否则返回 false。

输入保证：这些点构成简单多边形。除相邻边在公共顶点相交外，其余边不会相交，因此无需额外判断自交。

官方函数形式

isConvex(points) → boolean

points: List<List<Integer>>

示例

示例 1凸
输入points = [[0,0],[0,5],[5,5],[5,0]]
输出true

四个顶点围成没有凹陷的正方形。

示例 2非凸
输入points = [[0,0],[0,10],[10,10],[10,0],[5,5]]
输出false

点 [5,5] 形成向内的凹陷。

约束

  • 3 ≤ points.length ≤ 10⁴
  • points[i].length == 2
  • -10⁴ ≤ xᵢ, yᵢ ≤ 10⁴
  • 所有给定点互不相同，且按多边形边界顺序给出。
  • 这些点组成简单多边形。

03 / Solution

叉积符号的一致性

核心洞察

沿多边形边界依次行走时，凸多边形的所有非零局部转向必定朝同一方向。取连续三个点 A、B、C，计算向量 AB 与 BC 的二维叉积：

cross = (B.x - A.x) × (C.y - B.y) - (B.y - A.y) × (C.x - B.x)
  • cross > 0：逆时针转向。
  • cross < 0：顺时针转向。
  • cross = 0：三点共线，不提供新的转向方向，跳过。
一句话判断

只要出现正、负两种非零叉积，多边形就存在反向拐弯，因此不是凸多边形。

完整过程

  1. 令 sign = 0，表示还没有遇到非零转向。
  2. 对每个下标 i，循环取 points[i]、points[(i+1)%n]、points[(i+2)%n]，这样最后两组也会跨过数组末尾，覆盖闭合处。
  3. 计算当前叉积。若为零则继续；若 sign 尚未确定，就记录当前符号。
  4. 若当前非零叉积与已记录符号相反，立即返回 false。
  5. 完整扫描后仍未发现符号冲突，返回 true。
时间复杂度
O(n)

每个顶点参与常数次计算。

空间复杂度
O(1)

只保存下标、叉积和符号。

数值范围
64-bit

Java / C++ 使用长整型，避免乘法扩展时的风险。

正确性证明

引理：对一个按边界顺序给出的简单多边形，若它是凸多边形，则所有非零相邻边叉积同号。因为沿凸多边形边界行走时，边界方向只会持续顺时针或持续逆时针改变，不会出现反向凹折。

反向：若所有非零相邻边叉积同号，则每个顶点的局部转向都不与遍历方向相反。简单多边形中不存在反向凹折顶点，也就不存在大于 180° 的凹角，因此多边形为凸多边形。

结论：算法恰好检测是否出现两种相反的非零叉积；出现时返回 false，否则返回 true，所以判断正确。

边界情况

顺时针或逆时针

不预设正负；第一个非零叉积决定基准方向。

跨数组末尾

用取模补上“倒数第二、最后、第一”和“最后、第一、第二”两组。

连续点共线

叉积为零时跳过，不把它误判成方向改变。

负坐标与大坐标

几何关系不受坐标正负影响；定宽语言优先使用长整型。

四语言完整代码

import java.util.List;

class Solution {
    public boolean isConvex(List<List<Integer>> points) {
        int n = points.size();
        long direction = 0;

        for (int i = 0; i < n; i++) {
            List<Integer> a = points.get(i);
            List<Integer> b = points.get((i + 1) % n);
            List<Integer> c = points.get((i + 2) % n);

            long abX = (long) b.get(0) - a.get(0);
            long abY = (long) b.get(1) - a.get(1);
            long bcX = (long) c.get(0) - b.get(0);
            long bcY = (long) c.get(1) - b.get(1);
            long cross = abX * bcY - abY * bcX;

            if (cross == 0) {
                continue;
            }
            if (direction != 0 && (cross > 0) != (direction > 0)) {
                return false;
            }
            direction = cross;
        }
        return true;
    }
}

var isConvex = function(points) {
    const n = points.length;
    let direction = 0;

    for (let i = 0; i < n; i++) {
        const a = points[i];
        const b = points[(i + 1) % n];
        const c = points[(i + 2) % n];
        const abX = b[0] - a[0];
        const abY = b[1] - a[1];
        const bcX = c[0] - b[0];
        const bcY = c[1] - b[1];
        const cross = abX * bcY - abY * bcX;

        if (cross === 0) continue;
        if (direction !== 0 && Math.sign(cross) !== Math.sign(direction)) {
            return false;
        }
        direction = cross;
    }
    return true;
};

替代方案

显式计算内角

可用点积和反三角函数检查角度，但会引入浮点精度与角度方向问题；复杂度仍为 O(n)，实现却更脆弱。

所有点相对每条边同侧

对每条边检查其余顶点是否都在同侧，思路直观但需要 O(n²)，在 10⁴ 个点时不合适。

先求凸包

求凸包后比较顶点集合可做到 O(n log n)，但丢掉了输入已按简单多边形边界排序这一关键信息。

常见错误

漏掉闭合处

只遍历到 n-3，没有检查最后两个顶点附近的转向。

把叉积大小当角度

这里需要比较符号；大小同时受边长影响，不能直接代表夹角。

把零当成反向

共线时没有左右方向，应跳过并保留上一个非零方向。

先假定固定方向

输入可能顺时针也可能逆时针，不能要求叉积只能为正或只能为负。

面试追问

  • 如果输入不保证是简单多边形，需要怎样额外检测边相交？
  • 若题目要求“严格凸”，连续三点共线时应该如何处理？
  • 为什么只检查相邻边的转向，在简单多边形前提下就足够？
  • 坐标扩大到 10⁹ 时，Java / C++ 的乘法是否仍然安全？
  • 如果顶点没有按边界顺序给出，为什么本算法不再适用？
