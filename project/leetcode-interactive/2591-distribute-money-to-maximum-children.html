将钱分给最多的儿童

每个人至少拿到 1 美元，没有人可以恰好拿到 4 美元。目标不是平均，而是让尽可能多的儿童恰好拿到 8 美元。

Problem

给定整数 money 和 children，把全部钱分给所有儿童，返回最多能有多少人恰好得到 8 美元；若根本无法满足分配规则，返回 -1。

输出：2

贪心：先保底，再制造尽可能多的 8

核心洞察

先给每个儿童 1 美元。此后，把一个儿童从 1 美元提升到 8 美元恰好需要额外 7 美元。因此候选答案直接由“额外金额能完成多少次 +7”决定，只需处理两个会破坏答案的尾部形态。

为什么只有两个修正

贪心结束后，未用于制造 8 美元的余数小于 7。若没有普通儿童却仍有余钱，就必须破坏一个 8；若只剩一个普通儿童且余数为 3，他会得到 4 美元，也必须牺牲一个 8 来重新分配。

完整过程

  1. 若 money < children，连每人 1 美元都做不到，返回 -1。
  2. 先扣除每人的 1 美元：money -= children，现在 money 表示可自由使用的额外金额。
  3. 最多制造 min(money / 7, children) 个 8 美元儿童，并同步扣掉对应额外金额与儿童数。
  4. 若所有儿童都已是 8 美元但还有余钱，必须把余钱给其中一人，答案减 1。
  5. 若只剩一名普通儿童且余数恰为 3，他会拿到 4 美元；把一名 8 美元儿童改为 7 美元，腾出的 1 美元让最后一人拿到 5 美元，答案减 1。

正确性证明

上界：每个儿童至少需要 1 美元；让其中一人变成 8 美元还需 7 美元。因此任何方案中，8 美元儿童数都不超过 min(⌊(money - children) / 7⌋, children)。

可达性：按该上界先制造尽量多的 8。若不落入两个特殊尾部，剩余金额可交给至少一名非 8 美元儿童，并避开 4 美元；有多名普通儿童且余数为 3 时，可拆成额外的 1 与 2。两个特殊尾部分别必然破坏一个 8，修正后的分配合法。

结论：算法达到理论上界，或只在上界不可能合法实现时恰好减 1，因此返回值最优。

边界情况

  • money < children：无法保证每人至少 1 美元。
  • 钱刚好等于儿童数：每人 1 美元，答案为 0。
  • 所有儿童都先得到 8 美元且仍有余钱：余钱无法凭空放置，必须破坏一个 8。
  • 恰剩一名普通儿童和 3 美元：直接给他会得到被禁止的 4 美元。
  • 有至少两名普通儿童和 3 美元：可将额外金额拆成 1 与 2，不会产生 4 美元。

class Solution {
    public int distMoney(int money, int children) {
        if (money < children) return -1;

        money -= children;
        int answer = Math.min(money / 7, children);
        money -= answer * 7;
        children -= answer;

        if (children == 0 && money > 0) answer--;
        if (children == 1 && money == 3) answer--;
        return answer;
    }
}

替代方案

可从 children 向下枚举候选的 8 美元儿童数，检查剩余金额是否能合法分给其余儿童。它更贴近定义，时间复杂度为 O(children)，但检查条件仍要处理“4 美元”与“钱必须分完”，不如常数时间贪心直接。

常见错误

  • 只计算 money / 8，忘了其他儿童也至少需要 1 美元。
  • 制造完 8 美元后忽略剩余的钱，但题目要求全部分完。
  • 漏掉“最后一人得到 4 美元”的特殊情况。
  • 看到余数 3 就一律减 1；实际上有至少两名普通儿童时可以拆成额外的 1 和 2。

面试追问

目标金额从 8 改为 t 呢？保底后，每个目标儿童需要额外 t - 1；禁止金额带来的尾部修正需要重新分类。
如果禁止多个金额呢？常数个禁值可分析余数；禁值很多时，更适合枚举候选答案或用动态规划检查可行性。
为什么不能简单平均？目标是最大化恰好为 8 的人数，平均会把可集中制造 8 的金额分散掉。
能构造具体分配吗？可以：先放置所有 8，再把余数给普通儿童；命中特殊尾部时按证明中的 7 与 5 重排。
