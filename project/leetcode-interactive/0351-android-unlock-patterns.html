01 / Problem

题意与规则

给定两个整数 m 与 n，返回长度在 [m, n] 之间的所有有效图案数量。图案是按顺序连接点阵中若干不同按键得到的序列。

3 × 3 点阵

1  2  3
4  5  6
7  8  9
  1. 每个图案至少包含 m 个、至多包含 n 个按键。
  2. 同一个按键在一条图案中最多使用一次；按键顺序不同，图案也不同。
  3. 若从当前按键到下一按键的直线正好穿过另一个按键，则中间按键必须已经出现在当前图案中。例如，1 → 3 需要先访问 2，1 → 9 需要先访问 5。
  4. 不穿过其他点的连线可直接使用；已经访问过的中间点允许被跨越，但它不能再次成为新按键。
参数形式：输入整数 m、n，输出一个整数。官方元数据给出的提交签名为 numberOfPatterns(m, n)。

04 / Solution

回溯 + 中间点表 + 对称性

把几何规则预处理为一个很小的“中间点表”。搜索时只需检查候选点是否未使用，以及所需中间点是否已经访问；再利用九宫格的旋转、镜像对称性减少重复起点。

核心洞察

  • 只有 8 组无向连线需要中间点：1↔3 经 2，1↔7 经 4，3↔9 经 6，7↔9 经 8，以及 1↔9、3↔7、4↔6、2↔8 均经 5。
  • 用 skip[a][b] 保存从 a 到 b 所需的中间点；值为 0 表示无需中间点。
  • 四个角的搜索数量相同，四条边中点的搜索数量相同，中心独立。因此每个目标长度只需从 1、2、5 各搜一次，再乘 4、4、1。

状态与转移

定义 dfs(cur, remain)：当前已站在 cur，还要再选择 remain 个按键。进入函数时标记 cur 已访问；若 remain = 0，当前序列就是一个完整图案。

枚举所有未访问的 next。当 skip[cur][next] = 0，或对应中间点已经访问时，才能递归进入 next。返回前撤销 cur 的访问标记，让同级分支复用状态。

完整过程

  1. 初始化双向中间点表，并创建长度为 10 的访问数组。
  2. 依次枚举目标长度 len = m..n。
  3. 计算角起点 dfs(1, len - 1)，乘 4。
  4. 计算边中点起点 dfs(2, len - 1)，乘 4。
  5. 计算中心起点 dfs(5, len - 1)，直接加入。
  6. 累计所有目标长度的结果并返回。

边界处理

  • m = n = 1：递归深度为 1，每个起点恰好产生一个图案。
  • m = n = 9：访问数组自然阻止重复按键，只统计用完九个点的序列。
  • 跨越线只有在所需中间点已访问时合法；不要误判为“中间点只要最终会访问即可”。
  • 中间点表必须双向设置，因为 1 → 3 与 3 → 1 受同一约束。

正确性证明

引理一：转移判定恰好刻画合法的下一步

候选点必须未访问，保证按键不重复。若连线需要中间点，则中间点必须已经访问；若无需中间点则可直接连接。这与题目对单步移动的两项限制完全一致，因此判定既必要又充分。

引理二：一次 DFS 恰好枚举指定起点、指定长度的所有合法图案

由引理一，递归只扩展合法移动，所以不会生成非法图案。反过来，任意合法图案的每个后继都能通过判定；DFS 枚举全部候选，因此会沿该图案唯一的按键顺序到达终点。不同递归路径对应不同序列，不会重复计数。

引理三：对称倍数保持计数

旋转或镜像九宫格会保持“是否经过中间点”的关系。四个角彼此可映射，四个边中点也彼此可映射，所以同长度下它们的图案数分别相等；中心映射到自身。

定理：算法返回长度位于 [m, n] 的全部有效图案数量

对每个目标长度，引理二保证三个代表起点的计数准确，引理三保证乘数覆盖九个起点且不重不漏。最后对所有互不相同的长度求和，因此结果正是所求。

复杂度

时间
O(9 · 9!) 上界

点数固定为 9；更细地说，访问的搜索节点受各长度排列数之和约束，规则剪枝会显著减少实际分支。

递归空间
O(9)

递归栈最深 9 层，访问数组也只有 10 个位置。

规则表
O(1)

10 × 10 的固定中间点表不随输入扩大。

Java 
class Solution {
    private final int[][] skip = new int[10][10];
    private final boolean[] used = new boolean[10];

    public int numberOfPatterns(int m, int n) {
        buildSkipTable();
        int answer = 0;

        for (int length = m; length <= n; length++) {
            answer += dfs(1, length - 1) * 4;
            answer += dfs(2, length - 1) * 4;
            answer += dfs(5, length - 1);
        }
        return answer;
    }

    private int dfs(int current, int remaining) {
        if (remaining == 0) {
            return 1;
        }

        used[current] = true;
        int count = 0;

        for (int next = 1; next <= 9; next++) {
            int middle = skip[current][next];
            if (!used[next] && (middle == 0 || used[middle])) {
                count += dfs(next, remaining - 1);
            }
        }

        used[current] = false;
        return count;
    }

    private void buildSkipTable() {
        connect(1, 3, 2);
        connect(1, 7, 4);
        connect(3, 9, 6);
        connect(7, 9, 8);
        connect(1, 9, 5);
        connect(3, 7, 5);
        connect(4, 6, 5);
        connect(2, 8, 5);
    }

    private void connect(int a, int b, int middle) {
        skip[a][b] = middle;
        skip[b][a] = middle;
    }
}

替代方案：位掩码动态规划

令 dp[mask][last] 表示已访问集合为 mask、最后一个按键为 last 的合法序列数。枚举未访问的下一点，并用同一张中间点表检查：所需中间点的位是否已在 mask 中。

该方案的状态上界为 2^9 × 9，转移再枚举 9 个下一点，时间为 O(2^9 × 9^2)，空间为 O(2^9 × 9)。它适合展示集合状态复用；本题点数固定时，回溯更短、更直观。

面试追问

  • 如果点阵扩展为 k × k，怎样自动计算任意两点之间的中间格点？可从坐标差的最大公约数入手。
  • 如何去掉对称优化仍保证正确？直接对 1 到 9 的每个起点调用 DFS。
  • 怎样按长度分别输出数量？把每次目标长度的计数保存到数组，而不是只累计总和。
  • 如果允许重复按键，状态与终止条件要怎样修改？需要移除访问限制，并防止无限长度输入。

常见错误

  • 只列出经过中心 5 的跨越，漏掉 1↔3、1↔7、3↔9、7↔9。
  • 中间点表只设置一个方向，导致反向移动被错误放行。
  • 递归结束后忘记撤销访问标记，使后续同级分支少算。
  • 把“中间点已访问”误写成“中间点未访问”，或把候选点本身的状态与中间点状态混淆。

实现检查清单

  • 剩余步数为 0 时立即返回 1，不再枚举候选。
  • 乘 4 只用于代表角点 1 与代表边点 2，中心 5 不乘。
  • 每个目标长度都传入 length - 1，因为起点已经占用一个位置。
  • 最终返回所有长度的和，而不是仅返回最后一个长度的结果。
