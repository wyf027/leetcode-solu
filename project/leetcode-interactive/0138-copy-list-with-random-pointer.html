任务说明

输入只会给出原链表头节点；页面用 [val, random_index] 展示结构，索引为 null 表示没有 random 指向。

深拷贝的合格线

  • 复制链表必须有完全相同数量的全新节点。
  • 每个新节点的值、next 关系和 random 关系都与原结构对应。
  • 新链表的任何指针都不能回到原链表节点。
约束 0 ≤ n ≤ 1000 -10⁴ ≤ Node.val ≤ 10⁴ random = null 或链内某个节点

题解已封存

核心洞察、完整过程、复杂度、替代方案、边界、面试追问、常见错误与四语言代码都在下方，默认隐藏。

核心洞察

若把克隆节点 Cᵢ 紧贴在原节点 Oᵢ 后面，那么任何原节点 X 的克隆都是 X.next。 因此原节点 random 指向谁，其克隆的 random 就指向“那个人的 next”。

Oᵢ.random = Oⱼ ⇒ Cᵢ.random = Oᵢ.random.next = Cⱼ

完整过程

  1. 遍历原链表，在每个原节点后插入一个同值克隆节点。
  2. 再次遍历原节点，令克隆节点的 random 指向原 random 后面的克隆节点。
  3. 第三次遍历，恢复原链表 next，同时串起独立的克隆链表。

复杂度

  • 时间：O(n)，三次线性遍历。
  • 额外空间：O(1)，不计算必须返回的 n 个新节点。
  • 原链表：算法结束后恢复为输入时的结构。

替代方案取舍

哈希表可建立“原节点 → 克隆节点”的映射，逻辑更直白，也是工程中很稳妥的实现；但它需要 O(n) 额外空间。面试若追问常数额外空间，节点交织法更能展示对结构的掌控。

边界清单

  • 空链表直接返回 null。
  • random 为 null 时不能访问 random.next。
  • random 可以指向自身、前方或后方节点。
  • 节点值可以重复，绝不能用 val 识别节点身份。

常见错误

  • 只复制值和 next，忘记 random。
  • 让克隆 random 指到原节点，做成了浅拷贝。
  • 拆链顺序错误，导致原链表丢节点或克隆链断开。
  • 把输出节点计入“额外空间”，误判复杂度。

面试追问

  • 为什么交织后能 O(1) 找到对应克隆？ 因为每个原节点的 next 临时就是它的克隆。
  • 如果不允许修改原链表呢？ 使用哈希表映射，或明确需要额外约束/空间。
  • 如何证明是深拷贝？ 结构序列相同，且每个克隆节点与所有原节点对象身份都不同。
  • 能否一趟完成？ random 可能指向尚未创建的节点，交织法需要分阶段建立可寻址关系。

class Solution {
    public Node copyRandomList(Node head) {
        if (head == null) return null;

        for (Node cur = head; cur != null; cur = cur.next.next) {
            Node copy = new Node(cur.val);
            copy.next = cur.next;
            cur.next = copy;
        }

        for (Node cur = head; cur != null; cur = cur.next.next) {
            if (cur.random != null) {
                cur.next.random = cur.random.next;
            }
        }

        Node copyHead = head.next;
        for (Node cur = head; cur != null; ) {
            Node copy = cur.next;
            cur.next = copy.next;
            cur = cur.next;
            copy.next = cur == null ? null : cur.next;
        }
        return copyHead;
    }
}
