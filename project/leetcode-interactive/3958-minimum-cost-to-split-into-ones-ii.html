拆分到 1 的最小总代价 II

给定 n；每次把 x 拆成正整数 a、b（a+b=x），付 a×b。把 n 拆成 n 个 1 的最小总费用是多少？

题意与示例

n = 3：3 → 1+2 付 2，2 → 1+1 付 1，答案 3。
n = 4：无论先拆 1+3 或 2+2，总代价均为 6。

约束 1 ≤ n ≤ 5×10⁷，返回值必须使用 64 位整数。

完整题解

核心洞察

最终有 n 个单位 1。任意两个最终 1 在拆分树中都会在某一次分裂落到不同两侧；该次分裂的 a×b 正好计数跨两侧的单位对。因此所有操作费用总和恒为全部单位对数 C(n,2)=n(n-1)/2，与拆分顺序无关，故也是最小值。

完整过程

1. 不要枚举 a、b 或做 DP：n 可达 5×10⁷。
2. 将每次费用解释成此次分开的一对 1 的数量。
3. 每一对最终 1 恰好在 LCA 对应分裂处计一次，得到组合数。

边界、替代方案与常见错误

  • n=1 时公式自然给出 0。
  • 先乘再除须提升到 64 位；Java/C++ 的 int 会溢出。
  • 递归/记忆化会超时；“每次剥 1”可解释公式但无需真的循环。
  • 面试追问：若费用不再是 a×b，此“对数不变量”可能失效。

复杂度：O(1) 时间，O(1) 空间。
