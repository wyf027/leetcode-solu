Minimum Bit Flips to Convert Number

01 / 题目

给定两个整数 start 和 goal。每次操作可以任选一个二进制位，把 0 改成 1，或把 1 改成 0；也可以选择尚未显示的前导零。返回将 start 变成 goal 所需的最少操作次数。

参数：minBitFlips(start, goal) → 整数

约束：0 ≤ start, goal ≤ 10⁹。输入为整数，0 也是合法值。

官方示例 1

输入：start = 10, goal = 7
输出：3

补齐位宽后：1010 → 1011 → 1111 → 0111。依次翻转从右起第 1、3、4 位，共 3 次。

官方示例 2

输入：start = 3, goal = 4
输出：3

补齐位宽后：011 → 010 → 000 → 100。依次翻转从右起第 1、2、3 位，共 3 次。

上述路径都达到最少次数。本题与 461「汉明距离」等价。

04 / 独立题解

准备好后，展开推导与可提交代码。

核心洞察：每个不同的位，都必须翻转一次

相同位不需要动，不同位至少动一次。异或 x = start ^ goal 将不同位标记为 1，因此答案是 x 的二进制中 1 的个数。

完整过程 · 每步清除一个差异

  1. 计算差异掩码 x = start ^ goal，计数器设为 0。
  2. 只要 x 不为 0，执行 x &= x - 1，计数加 1。
  3. x 归零时，返回计数。这就是 Brian Kernighan 计数法。

为什么能清除最低位的 1？将 x 减 1，会把最低位的 1 变成 0，并把其右侧的 0 变成 1；再与原数按位与，右侧重新变为 0，高位保持不变。

start = 10 = 1010
 goal =  7 = 0111
    x =      1101
第 1 步：1101 & 1100 = 1100，count = 1
第 2 步：1100 & 1011 = 1000，count = 2
第 3 步：1000 & 0111 = 0000，count = 3

实验台同时翻转当前值中对应的位，依次得到 11、15、7；代码只需清除掩码中的位，不必真的修改 start。

正确性

下界：若共有 k 个不同位，每个不同位必须被翻转奇数次，至少一次。每次操作只改一个位，因此任何方案至少需要 k 次。

可达：将这 k 个不同位各翻转一次，其余位保持不变，就能得到 goal，恰好用 k 次。

循环不变式：每轮开始时，x 只保留尚未计数的差异位，count 等于已经清除的差异位数。一次操作恰好清除一个 1，保持两者之和为 k；结束时 x 为 0，count 就是最优值 k。

边界与复杂度

  • start 等于 goal 时，初始 x 为 0，循环不执行，返回 0。
  • 某个数为 0 或二进制长度不同：把较短数左侧视为补零，异或会自然处理。
  • 约束内数字最多占 30 位，JavaScript 的 32 位有符号位运算不会触及符号位。扩大范围时应使用 BigInt 或明确固定位宽。
  • 设 k 是差异位数、B 是有效位宽。按固定字长位运算计，时间 O(k)，最坏 O(B)，额外空间 O(1)。本题 B ≤ 30，可视为常数时间；相等时只需 O(1)。任意精度整数下，大整数位运算本身的成本也需计入。

四语言代码

均使用官方函数签名和同一清位过程；以下代码未编译、未运行。

Java

class Solution {
    public int minBitFlips(int start, int goal) {
        int x = start ^ goal;
        int count = 0;
        while (x != 0) {
            x &= x - 1;
            count++;
        }
        return count;
    }
}

替代方案

  • 逐位扫描：检查 x & 1 并累加，再右移 x，直到为 0。时间 O(B)，更适合首次学习位操作。
  • 内置计数：Java 使用 Integer.bitCount(start ^ goal)；支持的 Python 版本可用 (start ^ goal).bit_count()；C++20 可用 std::popcount（包含 <bit> 并转换为无符号整数）。JavaScript 没有标准的整数 popcount 方法。
  • 二进制字符串：补齐长度后逐位比较可得到相同答案，但引入 O(B) 存储，通常没有必要。

常见错误

  • 计算十进制差值，或比较两数各自的 1 的个数：位置不同也要翻转，例如 3 和 4。
  • 用 OR 或 AND 代替 XOR：它们不能恰好标记“不同”。
  • 把 x - 1 当成清位结果，忘记再与原 x 按位与。
  • 二进制字符串没有右对齐；忽略较高位的前导零。
  • 把本题的 JavaScript 位操作直接推广到超过 32 位的输入，导致截断。

面试追问

  • 如何输出翻转位置？逐位扫描异或结果并记录为 1 的下标，或每轮提取最低位的 1；返回列表需要 O(k) 空间。
  • 如果每一位翻转成本不同？在位之间独立、成本非负的条件下，累加所有不同位的成本；无需翻转相同位。
  • 如果一次可以翻转连续区间？独立计数的证明不再适用。对差异位串，每个连续的 1 区间翻转一次；需改用区间边界推导。
  • 负数怎么办？先约定补码位宽。无限前导位的含义与本题不同，不能直接套用非负整数终止条件。
