完成所有任务需要的最少轮数

Minimum Rounds to Complete All Tasks

同样的难度，一起完成。每轮只能选 2 个或 3 个任务，怎样安排轮次？

01 / PROBLEM

题目与规则

给定下标从 0 开始的整数数组 tasks，每个元素表示一个任务的难度。每轮必须完成恰好 2 个或 3 个难度相同的任务。求完成全部任务的最少轮数；如果不存在合法安排，返回 -1。

任务不要求相邻，数组顺序不限制每轮的选择。所有任务都必须完成。

输入与输出

minimumRounds(tasks)
参数：整数数组 tasks
返回：整数，最少轮数或 -1

  • 1 ≤ tasks.length ≤ 10⁵
  • 1 ≤ tasks[i] ≤ 10⁹
官方题目 ↗

官方示例

示例 1

输入：tasks = [2,2,3,3,2,4,4,4,4,4]
输出：4

一种安排：难度 2 的 3 个任务用一轮；难度 3 的 2 个任务用一轮；难度 4 的 5 个任务分成 3 个和 2 个，用两轮，共 4 轮。

示例 2

输入：tasks = [2,3,3]
输出：-1

难度 2 只有一个任务，无法组成一轮允许的数量，所以无法完成全部任务。

04 / EDITORIAL

先想一想，再看题解

哪些任务能放在同一轮？任务的位置重要吗？

计数 + 按余数构造

核心洞察

不同难度不能混在一轮，因此每种难度独立求最优，再相加。设某难度出现 c 次：c = 1 时无解；其余情况下最少轮数是 ⌈c / 3⌉ = floor((c + 2) / 3)。

完整过程

  1. 遍历 tasks，用哈希表统计每个难度的出现次数。
  2. 遍历次数；如果发现 1，立即返回 -1。
  3. 否则累加 floor((c + 2) / 3)，返回总和。

示例 1 的次数是 {2:3, 3:2, 4:5}，对应轮数为 1 + 1 + 2 = 4。计数为 4 时应拆成 2 + 2，不能先取 3 再留下 1。

为什么正确

每轮最多完成 3 个任务，所以任意合法方案至少需要 ⌈c / 3⌉ 轮。下面对 c ≥ 2 构造达到下界的方案：

  • c = 3q：用 q 组三个，恰好 q 轮。
  • c = 3q + 2：用 q 组三个和一组两个，共 q+1 轮。
  • c = 3q + 1 且 c≥4：q≥1，把一个三数组和余下的一个改成两组两个，即 (q−1)×3 + 2 + 2，共 q+1 轮。

以上覆盖所有 c≥2，且都达到下界；c=1 无法组成任何合法轮。各难度独立，任何全局方案的轮数都至少是各组下界之和，而各组的构造可直接串联，故相加即为全局最优。

边界与复杂度

单元素数组返回 -1；任意难度只出现一次都使整个任务无解。2、3 次均为 1 轮，4 次为 2 轮。难度可达 10⁹，不应按难度最大值开数组。输入不为空，无需额外定义空数组结果。

设 n 为任务数、k 为不同难度数，哈希表实现的期望时间为 O(n)，额外空间为 O(k)。哈希操作按均摊常数计；不依赖遍历顺序，输入无需修改。

四种语言 · 可提交代码

Java

import java.util.HashMap;
import java.util.Map;

class Solution {
    public int minimumRounds(int[] tasks) {
        Map<Integer, Integer> counts = new HashMap<>();
        for (int task : tasks) {
            counts.merge(task, 1, Integer::sum);
        }
        int rounds = 0;
        for (int count : counts.values()) {
            if (count == 1) return -1;
            rounds += (count + 2) / 3;
        }
        return rounds;
    }
}

JavaScript

/**
 * @param {number[]} tasks
 * @return {number}
 */
var minimumRounds = function(tasks) {
    const counts = new Map();
    for (const task of tasks) {
        counts.set(task, (counts.get(task) || 0) + 1);
    }
    let rounds = 0;
    for (const count of counts.values()) {
        if (count === 1) return -1;
        rounds += Math.floor((count + 2) / 3);
    }
    return rounds;
};

Python 3

from collections import Counter
from typing import List

class Solution:
    def minimumRounds(self, tasks: List[int]) -> int:
        rounds = 0
        for count in Counter(tasks).values():
            if count == 1:
                return -1
            rounds += (count + 2) // 3
        return rounds

C++

#include <vector>
#include <unordered_map>
using namespace std;

class Solution {
public:
    int minimumRounds(vector<int>& tasks) {
        unordered_map<int, int> counts;
        for (int task : tasks) ++counts[task];
        int rounds = 0;
        for (const auto& entry : counts) {
            int count = entry.second;
            if (count == 1) return -1;
            rounds += (count + 2) / 3;
        }
        return rounds;
    }
};

替代方案

先排序，再统计连续相同值，时间 O(n log n)，扫描阶段额外空间 O(1)，总辅助空间取决于语言的排序实现；原地排序会改变输入。也可用动态规划 dp[c] = 1 + min(dp[c−2], dp[c−3])，令 dp[0]=0、不可达状态为无穷；适合轮次大小更一般的变体，但本题的余数公式更直接。

常见错误

  • 对任务总数直接向上取整：忽略不同难度不能混合。
  • 只有相邻元素才合并：题目允许任选同难度任务。
  • 每次机械地拿三个：遇到 4 会留下单个，应改为 2+2。
  • 只算向上取整却漏掉 count=1 的无解判断。
  • JavaScript 用普通除法直接累加，或 Python 用 /：需要整数轮数。

面试追问

  • 如何输出具体轮次？记录同难度任务索引，余数为 1 时预留 4 个拆成 2+2，再输出其余三数组。
  • 若每轮可完成 2 或 5 个？原公式不适用，例如 3 个无法完成；使用可达性分析或按次数动态规划。
  • 若 2 个与 3 个一轮的代价不同？目标改为最小成本，应比较组合成本或使用带权动态规划。
  • 若输入是数据流？持续更新频次；流结束后按最终频次求和，中途单例可能被后续任务补齐。
