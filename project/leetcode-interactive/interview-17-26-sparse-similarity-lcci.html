面试题 17.26 · Hard

稀疏不等于空白

找出真正共享词元的文档对。

给每篇文档一组互不重复的整数词元，只输出相似度大于 0 的文档对，并把 Jaccard 相似度保留四位小数。

相似度定义

交集 共同词元数
÷
并集 去重词元数

空文档忽略；输出格式固定为 id1,id2: 0.0000。

Problem brief

题意

输入二维数组 docs，其中 docs[i] 是编号为 i 的文档，且同一文档内的整数互不相同。对每一对有共同词元的文档，输出 交集大小 ÷ 并集大小，精确到小数点后四位。结果顺序不限。

官方样例

4 DOCUMENTS
输入
docs = [[14, 15, 100, 9, 3], [32, 1, 9, 3, 5], [15, 29, 2, 6, 8, 7], [7, 10]]
期望输出
["0,1: 0.2500", "0,2: 0.1000", "2,3: 0.1429"]

文档内没有重复整数；本页输入均使用完整参数名。若字符串含空格，将以 ␠ 显示并在旁说明；本题输入不含字符串。

Spoiler gate

题解

核心洞察、完整过程、复杂度、替代方案与四语言代码均在下方，默认收起。

核心洞察

只让共享词元的文档相遇

为每个词元维护包含它的文档编号列表。一个词元的倒排桶中，任意两个文档都共享该词元，因此直接给对应文档对的交集计数加一。完全不共享词元的文档对不会被创建，正好利用“相似度稀疏”。

完整过程

  1. 1. 扫描所有文档，建立词元到文档列表的倒排索引。
  2. 2. 枚举每个倒排桶中的文档对，累加交集大小。
  3. 3. 对每个正交集文档对计算并集：|A| + |B| - |A ∩ B|。
  4. 4. 计算比值并格式化为四位小数。

边界

  • 空文档不会进入任何倒排桶，自然被忽略。
  • 没有共享词元时，结果为空数组。
  • 两个相同集合的相似度为 1.0000。
  • 题目保证单篇文档内词元互异；若无此保证需先去重。
  • 格式化时固定英文小数点，避免系统 Locale 产生逗号。

复杂度

设总词元数为 N，词元 w 出现在 f₍w₎ 篇文档中，正相似文档对数为 P。

时间为 O(N + Σ f₍w₎² + P log P)；最后一项仅用于稳定排序，题目允许任意顺序时可省略。空间为 O(N + P)。

替代方案取舍

可以先排序每篇文档，再用双指针逐对求交集；单次比较线性，但仍要检查 O(D²) 个文档对，没有利用“稀疏”。面试最推荐倒排索引，它把工作集中在真正共享词元的候选对上。

面试追问

如果单篇文档可能含重复词元？
先对每篇文档去重，否则同一词元会重复累加交集。
如果某个高频词出现在几乎所有文档？
该桶会产生二次方候选；可讨论停用词、分块处理或外存聚合，但是否允许过滤取决于业务定义。
如何并行化？
按词元桶分片统计局部文档对计数，最后按文档对 key 归并。

常见错误

  • 把并集写成 |A| + |B|，忘记减去交集。
  • 枚举所有文档对，虽然结果正确，却没有利用稀疏性。
  • 文档对 key 未统一小编号在前，导致同一对被拆成两项。
  • 直接截断小数或依赖默认 Locale，输出格式不符合要求。
  • 输出交集为 0 的文档对，违背题目要求。
