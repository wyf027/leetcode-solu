恰有 K 根木棍
可以看到的排列数目

Number of Ways to Rearrange Sticks With K Sticks Visible

先站到木棍左侧，观察哪些高度能露出来。把“看得见”理解清楚，再展开计数方法。

01 / PROBLEM

题意与输入

长度分别为 1, 2, …, n 的 n 根木棍互不相同，需要全部排成一排。如果一根木棍左侧没有更长的木棍，就能从左边看到它。

给定整数 n 和 k，求恰好能看到 k 根木棍的排列总数，结果对 1,000,000,007 取余。

例如 [1,3,2,5,4] 中能看到 1、3、5，2 和 4 被左侧更高的木棍遮住。

参数：rearrangeSticks(n, k) → integer

约束：1 ≤ n ≤ 1000，1 ≤ k ≤ n。

05 / SOLUTION

准备好推导计数方法了吗？

下方包含完整推导、交互拆解与四语言代码。建议先想一想：把一根特殊长度的木棍取走，会发生什么？

从最短木棍出发的动态规划

核心洞察

在 i 根木棍的排列中，最短木棍只有位于最左端才可见；放在其余任一位置时，左边必有更长木棍。删除它不会改变其他木棍的可见性。把剩下的长度统一减 1，就得到一个标准的 i−1 根木棍排列。

定义 dp[i][j] 为 i 根木棍恰好 j 根可见的排列数。插入最短木棍时，两个互斥分支覆盖全部情况：

  • 插在最左：增加一个可见记录，由 dp[i−1][j−1] 转移，只有一个插入位置。
  • 插在其他位置：最短木棍不可见，其余可见性不变，共有 i−1 个位置，贡献 (i−1) × dp[i−1][j]。
dp[i][j] = dp[i−1][j−1] + (i−1) × dp[i−1][j] (mod M)

插入实验：最短木棍能藏在哪里？

以剩余排列 [2,4,3] 为例，它有两根可见。把长度 1 插入四个空隙，观察可见数是否变化。黄色为新插入的最短木棍；这个局部实验展示转移机制，不枚举全部答案。

完整过程与手工推导

  1. 初始化空排列：dp[0][0] = 1，其余状态为 0。空排列是递推基底，不是合法题目输入。
  2. 依次考虑 i = 1 到 n，更新 j = 1 到 min(i,k)，每次求和后取模。
  3. 使用一维数组保存上一行。j 必须从大到小更新，这样右侧的 dp[j] 与 dp[j−1] 都仍是上一行的值。
  4. 每一行结束后令 dp[0] = 0，因为非空排列不可能没有可见木棍。
  5. 最后返回 dp[k]。
每行按 j = 1, 2, 3 列出（手工推导）
i = 1：1, 0, 0
i = 2：1, 1, 0
i = 3：2, 3, 1

dp[3][2] = dp[2][1] + 2 × dp[2][2]
         = 1 + 2 × 1 = 3

正确性证明

基底：空排列只有一种，恰好有 0 根可见，因此 dp[0][0]=1 正确。

归纳：假设 i−1 根木棍的各状态正确。任取一个 i 根、j 根可见的排列，删除最短木棍。若它原在最左，剩下 j−1 根可见；否则剩下 j 根可见。反向插入分别有 1 个和 i−1 个位置。两个分支互斥，且删除和插入相互唯一对应，所以既不漏计也不重复。由此递推得到的 dp[i][j] 正确。

存储优化：降序更新保留递推所需的上一行两个值，因此一维实现与上述二维递推等价。模运算保持加法和乘法的同余关系，最终返回所求余数。

边界与复杂度

  • n = 1, k = 1：只有一根，答案为 1。
  • k = n：只有严格递增排列，答案为 1。
  • k = 1：最长木棍必须放最左，其余任意排列，答案为 (n−1)! mod M。
  • j > i 或非空排列的 j = 0：计数为 0；输入约束保证 k 不大于 n。
  • 时间 O(nk)；一维数组额外空间 O(k)。

四语言完整代码

均对应官方函数签名。Java / C++ 乘法使用 64 位整数。JavaScript 每步操作的整数小于 10¹²，低于 Number 的精确整数上限 2⁵³，因此这里无需 BigInt。

Java

class Solution {
    public int rearrangeSticks(int n, int k) {
        final long MOD = 1_000_000_007L;
        long[] dp = new long[k + 1];
        dp[0] = 1;
        for (int i = 1; i <= n; i++) {
            for (int j = Math.min(i, k); j >= 1; j--) {
                dp[j] = (dp[j - 1] + (i - 1L) * dp[j]) % MOD;
            }
            dp[0] = 0;
        }
        return (int) dp[k];
    }
}

class Solution:
    def rearrangeSticks(self, n: int, k: int) -> int:
        mod = 1_000_000_007
        dp = [0] * (k + 1)
        dp[0] = 1
        for i in range(1, n + 1):
            for j in range(min(i, k), 0, -1):
                dp[j] = (dp[j - 1] + (i - 1) * dp[j]) % mod
            dp[0] = 0
        return dp[k]

C++

#include <algorithm>
#include <vector>
using namespace std;

class Solution {
public:
    int rearrangeSticks(int n, int k) {
        const long long MOD = 1000000007LL;
        vector<long long> dp(k + 1, 0);
        dp[0] = 1;
        for (int i = 1; i <= n; ++i) {
            for (int j = min(i, k); j >= 1; --j) {
                dp[j] = (dp[j - 1] + (i - 1LL) * dp[j]) % MOD;
            }
            dp[0] = 0;
        }
        return static_cast<int>(dp[k]);
    }
};

替代方案

二维 DP 使用相同递推，时间 O(nk)、空间 O(nk)，便于观察整张表。记忆化递归也可表达同一递推，但 n = 1000 时要注意语言的递归深度限制。枚举排列需 O(n!·n) 时间，仅适合很小的输入，不适合题目规模。

数学上，答案是第一类无符号斯特林数 c(n,k)，也是多项式 x(x+1)…(x+n−1) 的 xᵏ 系数。逐项乘法的系数更新正是此递推。

常见错误

  • 把“可见”理解为只比紧邻的左侧木棍高：实际要超过左侧所有木棍。
  • 直接把最长木棍放在末尾/其他位置来套用两个分支：最长木棍会挡住其右侧，不能照搬最短木棍的论证。
  • 把隐藏插入位置写成 i：总共 i 个位置，最左那个必须单独算，因此隐藏位置仅 i−1 个。
  • 一维数组升序更新：会读到本轮已修改的 dp[j−1]，导致重复计数。
  • 每轮忘记把 dp[0] 清零，或在第一轮更新之前就清零，都会破坏边界。
  • 乘法使用 32 位 int，或在 JavaScript 中用位运算取模，会造成溢出或截断。

面试追问

为什么所有 k 的答案加起来是 n!？每个排列恰好属于一个可见数分类；所有分类完整划分全部排列。

改为从右侧观察呢？将排列反转可建立一一对应，因此计数相同。

同时限制左右可见数呢？增加一个状态维度。插入最短木棍时区分最左、最右和内部位置；i ≥ 2 时分别增加左侧、右侧或两边均不增加的可见数，内部有 i−2 个位置，i=1 需单独初始化。
