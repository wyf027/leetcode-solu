简单Divide Array Into Equal Pairs

将数组划分成相等数对

同样的数字，能否都有一个搭档？

题目要求

给定含有 2 * n 个整数的数组 nums，判断能否把全部元素分成恰好 n 对。每个数组元素必须且只能使用一次，每对中的两个数必须相等。可以完成则返回 true，否则返回 false。

数对不要求在原数组中相邻，也不要求保留原来的排列顺序。返回值是布尔值，无需返回具体数对。

官方示例 1

输入：nums = [3,2,3,2,2,2]
输出：true

6 个元素需要组成 3 对，可以得到 (2, 2)、(3, 3)、(2, 2)。

官方示例 2

输入：nums = [1,2,3,4]
输出：false

需要组成 2 对，但无法使每对的两个数都相等。

约束与接口

  • nums.length == 2 * n
  • 1 <= n <= 500
  • 1 <= nums[i] <= 500

参数：nums（整数数组） · 返回：boolean · 函数名：divideArray

03 / 独立题解

准备好后，再打开推导

核心洞察：每一种数都必须出现偶数次

相同数值才能组成一对，每次正好消耗该数值的两个元素。因此，某个值的出现次数为奇数时，至少会剩下一个元素；如果所有值的出现次数均为偶数，就能分别把它们两两配对。

完整过程

  1. 建立长度为 501 的计数数组 count，全部初始化为 0；下标对应数值，下标 0 留空。
  2. 遍历 nums，对每个数 x 执行 count[x]++。
  3. 遍历数值 1 到 500，遇到奇数计数就返回 false。
  4. 全部计数均为偶数，返回 true。

示例 1：count[2] = 4，count[3] = 2，其余为 0。对应 2 对数字 2 和 1 对数字 3，总计 3 对。工作台中的成对数量是 ⌊count[x] / 2⌋，等待数量是 count[x] % 2。

正确性证明

计数不变式：处理完前 i 个元素时，count[x] 等于值 x 在这 i 个元素中的出现次数。初始化时成立，每次只增加当前元素对应的计数，所以遍历结束后得到精确频数。

必要性：若存在合法划分，每个值 x 都只会被含两个 x 的数对消耗，因此 x 的出现次数必须是 2 的倍数。算法遇到奇数计数返回 false 是正确的。

充分性：若每个 count[x] 都是偶数，为每个值独立构造 count[x] / 2 对，不会混用不同数值，也不会重复或遗漏元素。总对数为 Σcount[x] / 2 = nums.length / 2 = n，满足题目要求。

边界与复杂度

  • 最短输入有两个元素，相等时成功，不相等时失败。
  • 未出现的数字计数为 0，也是偶数，无需特殊处理。
  • 500 是合法数值，数组长度必须为 501；总长度为偶数不代表每种值都出现偶数次。
  • 空数组、奇数长度、范围外数值不属于官方输入；交互输入框会拒绝这些输入。
  • 记 m = nums.length，U = 500。时间 O(m + U)，额外空间 O(U)。固定值域下可写作时间 O(m)、空间 O(1)。输入数组不变。

Java

class Solution {
    public boolean divideArray(int[] nums) {
        int[] count = new int[501];
        for (int x : nums) {
            count[x]++;
        }
        for (int x = 1; x <= 500; x++) {
            if (count[x] % 2 != 0) return false;
        }
        return true;
    }
}

替代方案

  • 奇偶集合：每读入 x，若集合包含 x 就删除，否则加入。集合表示当前出现奇数次的数；最后为空则成功。哈希操作平均 O(1)，总时间平均 O(m)，空间 O(k)，k 为不同值个数。
  • 排序后检查相邻对：排序后按下标 0、2、4…检查 nums[i] 与 nums[i+1]。时间 O(m log m)，排序空间由语言实现决定；原地排序会改变输入。JavaScript 需使用数值比较器。
  • 按值翻转奇偶位：使用 501 个布尔位置，逐值翻转，最后全部为 false 即可。它保留每个值的独立奇偶状态。

常见错误

  • 只检查总长度是否为偶数：这是已有约束，不能保证可配对。
  • 要求每种数字恰好出现两次：出现四次、六次等同样合法。
  • 只看整个数组的异或值：1 ^ 2 ^ 4 ^ 7 == 0，但四个数均只出现一次，无法配对。全局异或丢失了每种数的独立频数信息。
  • 读到某个奇数计数就提前返回 false：后续可能再次出现该数，必须读完数组后判断。
  • 直接检查原数组相邻元素：合法数对不要求原本相邻。

面试追问

  • 如果数值范围很大或有负数？使用哈希频数表或奇偶集合，避免按最大值分配数组。
  • 若每组要求 k 个相同元素？把判断条件改成每种频数能被 k 整除，且总长度必须能被 k 整除。
  • 需要返回具体下标对？为每种值记录一个未配对下标，再遇到相同值时输出两个下标并清空等待项。
  • 流式输入能提前断言失败吗？通常不能，当前剩余项可能被后续匹配；流结束时再检查奇偶状态。
