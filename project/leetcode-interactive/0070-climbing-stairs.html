Core insight

核心洞察：按最后一步分类

到达第 i 阶的最后一步只有两种：从 i - 1 走 1 阶，或从 i - 2 走 2 阶。两类路线互不重叠，所以数量相加： dp[i] = dp[i - 1] + dp[i - 2]

Interview choice

为什么主推滚动动态规划

状态只依赖前两项，无需保留整张数组。用 prev2 和 prev1 滚动更新，逻辑直观、边界清晰，同时把额外空间压到常数级。

完整过程

  1. n = 1 或 n = 2 时直接返回 n。
  2. 初始化 prev2 = 1、prev1 = 2。
  3. 从第 3 阶开始，令 current = prev1 + prev2。
  4. 窗口前移：prev2 = prev1，prev1 = current。
  5. 循环结束后返回 prev1。

边界与复杂度

  • 最小输入：n = 1，答案为 1。
  • 上界：n = 45，答案 1836311903，仍在 32 位有符号整数内。
  • 时间复杂度：O(n)。
  • 额外空间：O(1)。

替代方案取舍

  • 递归：最贴近定义，但重复计算导致指数级时间。
  • 记忆化 / DP 数组：同为 O(n) 时间，便于教学，但多用 O(n) 空间。
  • 矩阵快速幂：O(log n)，本题约束下实现成本高于收益。

常见错误

  • 把 dp[0] 与 dp[1] 的定义混用，造成整体偏移一位。
  • 更新滚动变量时顺序错误，提前覆盖仍需使用的旧值。
  • 把“走法数量”误当成组合，不区分 1 + 2 与 2 + 1 的顺序。
  • 使用裸递归却没有记忆化，导致大量重复子问题。

面试追问

如果每次可走 1、2、3 阶呢？
状态改为最近三项之和，并维护长度为 3 的滚动窗口。
某些台阶损坏不能落脚呢？
对损坏台阶令状态为 0，其余位置仍从可达前驱转移。
n 极大且要求取模呢？
每次加法后取模；若还要求对数级时间，可使用矩阵快速幂。

class Solution {
    public int climbStairs(int n) {
        if (n <= 2) {
            return n;
        }

        int prev2 = 1;
        int prev1 = 2;
        for (int floor = 3; floor <= n; floor++) {
            int current = prev1 + prev2;
            prev2 = prev1;
            prev1 = current;
        }
        return prev1;
    }
}
