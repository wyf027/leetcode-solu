数组异或操作

先生成一个步长固定为 2 的整数序列，再把全部元素按位异或。真正需要追踪的只有一个“累计结果”。

nums[i] = start + 2 × i，0 ≤ i < n
Problem

题目描述

给定两个整数 n 和 start。定义长度为 n 的数组 nums，其中下标从 0 开始，且 nums[i] = start + 2 * i。

返回数组 nums 中所有元素按位异或后的结果。

示例 1完整参数
输入：n = 5, start = 0
输出：8
解释：nums = [0, 2, 4, 6, 8]
      0 ^ 2 ^ 4 ^ 6 ^ 8 = 8
示例 2完整参数
输入：n = 4, start = 3
输出：8
解释：nums = [3, 5, 7, 9]
      3 ^ 5 ^ 7 ^ 9 = 8
示例 3单元素边界
输入：n = 1, start = 7
输出：7
示例 4完整参数
输入：n = 10, start = 5
输出：2

约束

  • 1 ≤ n ≤ 1000
  • 0 ≤ start ≤ 1000
  • n == nums.length

Solution

线性扫描：让累计值吸收每个元素

核心洞察无需真的保存数组。第 i 个数可以随用随算，再异或进答案。
状态设计只保留 ans；初始为 0，因为 0 ^ x = x。
顺序无关异或满足交换律与结合律，因此逐个累积不会改变结果。

完整过程

  1. 令 ans = 0。
  2. 让 i 从 0 遍历到 n - 1。
  3. 按公式得到当前元素 start + 2 * i，执行 ans ^= start + 2 * i。
  4. 遍历完成后返回 ans。

正确性证明

  1. 初始化：处理任何元素前，ans = 0，等于空前缀的异或值。
  2. 保持：假设处理前 i 个元素后，ans 等于它们的异或值。把 nums[i] 异或进去后，ans 就等于前 i + 1 个元素的异或值。
  3. 终止：循环结束时恰好处理 n 个元素，因此 ans 等于整个 nums 数组所有元素的异或值，也就是题目要求的答案。

边界与复杂度

当 n = 1 时，结果就是 start；当 start = 0 时算法仍按同一公式工作。时间复杂度为 O(n)，额外空间复杂度为 O(1)。

替代方案：O(1) 数学归约

令 s = start >> 1。原序列右移一位后变成连续整数 s, s+1, …, s+n-1，可用“0 到 x 的前缀异或”在 O(1) 时间求出主体；最低位只由 start 的奇偶性和 n 的奇偶性决定。该方案更快，但推导更绕，本题约束下线性扫描更直观、更不易写错。

常见错误

  • 把异或 ^ 误写成乘方；在这四种语言里，^ 都表示按位异或。
  • 循环写成 i <= n，导致多处理一个并不存在的元素。
  • 先创建完整 nums 数组，虽然正确，却多用了 O(n) 空间。
  • JavaScript 中误用逻辑或、逻辑与代替位运算。

面试追问

  • 能否利用前缀异或规律，把时间复杂度降到 O(1)？
  • 为什么 ans 可以安全地从 0 开始？
  • 如果步长不再是 2，哪些推导仍然成立？
  • 若数据规模超过语言的整数位宽，需要怎样处理？

四语言完整实现

JavaO(n) · O(1)
class Solution {
    public int xorOperation(int n, int start) {
        int ans = 0;
        for (int i = 0; i < n; i++) {
            ans ^= start + 2 * i;
        }
        return ans;
    }
}
