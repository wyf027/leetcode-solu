2116. 判断一个括号字符串是否有效

Check if a Parentheses String Can Be Valid

先读题并做出判断，再展开下方题解探索。所有内容本地运行。

题目说明

给定等长字符串 s 和 locked。s 只包含左右括号。位置 i 的锁定值为 1 时，该括号必须保留；为 0 时，可以把它设为任意一种括号，也可以保持原样。不能删除或增加字符。

判断是否存在一种修改方案，让整个字符串成为有效括号字符串，返回布尔值。有效字符串可以是 ()，也可以由两个有效字符串拼接而成，或在有效字符串外再包裹一对括号。

函数契约

canBeValid(s, locked) → boolean。只需判断可行性，不要求返回修改后的字符串。

约束

  • n == s.length == locked.length
  • 1 ≤ n ≤ 10⁵
  • s[i] 为 '(' 或 ')'。
  • locked[i] 为 '0' 或 '1'。

官方示例

示例 1

输入：s = "))()))", locked = "010100"
输出：true

下标 1、3 不可修改。将下标 0、4 改为左括号，其余保持原样，得到 ()()()。

示例 2

输入：s = "()()", locked = "0000"
输出：true

原字符串已经有效，可以不修改任何位置。

示例 3

输入：s = ")", locked = "0"
输出：false

唯一的字符可以修改，但单个左括号或右括号都不是有效字符串。

示例 4

输入：s = "(((())(((())", locked = "111111010111"
输出：true

允许修改下标 6、8，将这两处都改为右括号即可。

题解 · 保留所有仍可能的余额

把左括号记为 +1，右括号记为 −1。余额表示尚未匹配的左括号数。有效字符串要求每个前缀的余额都不为负，且最终余额为 0。

核心洞察

无需过早决定可修改位置使用哪种括号。对于已经处理的合法前缀，可达余额恰好是 low, low+2, …, high。只记录两端即可；所有余额与前缀长度具有相同奇偶性。这里保留的是精确可达集合，不是把区间内所有整数都算作可行。

完整过程

  1. 若长度为奇数，直接返回 false。初始化 low = high = 0。
  2. 可修改位置：low -= 1，high += 1。固定左括号：两端都加 1。固定右括号：两端都减 1。
  3. 若 high < 0，说明所有可能都出现了负前缀，立即失败。
  4. 若 low < 0，丢弃负余额，并令 low = (i + 1) % 2：偶数长度前缀最小合法余额为 0，奇数长度前缀为 1。
  5. 处理完全部字符，返回 low == 0。

正确性证明

不变式：处理长度为 k 的前缀后，所有从未出现负余额的修改方案，其余额集合精确等于从 low 到 high、公差为 2 的非负序列，且余额与 k 同奇偶。空前缀只有余额 0，不变式成立。

转移：固定字符把集合整体加 1 或减 1。可修改字符把集合分别加 1、减 1 后取并集，得到端点 low−1 和 high+1、公差仍为 2 的序列。删除负值即删除非法前缀；若最大值也为负，集合为空。否则最小合法值按当前前缀的奇偶性截到 0 或 1，恰好保留所有合法状态。因此每一步不变式仍成立。

终止：有效括号串必须有偶数个字符。对偶数长度，最终集合包含 0 当且仅当 low 为 0；由不变式，此时存在一个所有前缀均非负且总余额为 0 的方案，恰好满足有效括号串的条件。反之任何有效方案也必定被该集合保留。

边界与复杂度

  • 长度为 1 或其他奇数：无论锁定情况如何都不可能。
  • 全可修改且长度偶数：可以构造交替的 ()。
  • 固定右括号过早出现：可能中途 high 为负。固定左括号过多：可能最后 low 大于 0。
  • 不要用原字符串的左右数量代替可行性判断；可修改字符的原始方向不影响它的选择。
  • 时间 O(n)，额外空间 O(1)。教学演示保存逐步状态和渲染节点，与提交算法的空间消耗不同。

四种语言 · 完整提交代码

均采用相同的精确可达区间算法；下列代码未执行验证。

Java

class Solution {
    public boolean canBeValid(String s, String locked) {
        int n = s.length();
        if (n % 2 == 1) return false;
        int low = 0, high = 0;
        for (int i = 0; i < n; i++) {
            if (locked.charAt(i) == '0') {
                low--;
                high++;
            } else {
                int delta = s.charAt(i) == '(' ? 1 : -1;
                low += delta;
                high += delta;
            }
            if (high < 0) return false;
            if (low < 0) low = (i + 1) % 2;
        }
        return low == 0;
    }
}

#include <string>
using std::string;

class Solution {
public:
    bool canBeValid(string s, string locked) {
        int n = static_cast<int>(s.size());
        if (n % 2 == 1) return false;
        int low = 0, high = 0;
        for (int i = 0; i < n; ++i) {
            if (locked[i] == '0') {
                --low;
                ++high;
            } else {
                int delta = s[i] == '(' ? 1 : -1;
                low += delta;
                high += delta;
            }
            if (high < 0) return false;
            if (low < 0) low = (i + 1) % 2;
        }
        return low == 0;
    }
};

替代方案

  • 双向贪心：先检查偶数长度。从左往右把可修改位置视为左括号资源，保证固定右括号不缺匹配；再从右往左把可修改位置视为右括号资源，保证固定左括号不缺匹配。两次检查均不出现资源不足即可。O(n) 时间、O(1) 空间。
  • 下标栈：保存固定左括号和可修改位置。遇固定右括号优先配固定左括号，否则用先前的可修改位置。最后剩下的固定左括号只能与其右侧的可修改位置配对。O(n) 时间、O(n) 空间，便于构造方案。
  • 余额 DP：显式维护每个可达余额，最坏 O(n²) 时间、O(n) 空间。区间法正是对这组状态的压缩。

常见错误

  • 把 unlocked 当成可以删除的空串；本题只能替换为一个括号。
  • 只看最终左右数量，忽略前缀已经非法的情况。
  • 在 low 变负时直接失败；这是部分选择失败，只有 high 也为负才代表全部失败。
  • 将区间内所有整数视为可达，忽略奇偶性。本实现截断 low 时保留精确的奇偶下界。
  • 用一趟“尽量放左括号”的检查就返回 true，例如完全锁定的 (( 仍无法闭合。

面试追问

如何输出一个方案？设固定左括号数为 a，则可修改位置中必须恰有 n/2−a 个左括号。若这个数量超出可修改位置总数，直接失败；否则按下标顺序将最早的这些可修改位置设为左括号，其余设为右括号，再扫描检查前缀。这种安排使每个前缀的余额在固定总左括号数的方案中最大；若它失败，其他安排也无法修复该前缀。

如果位置还允许删除？这会改变奇偶性与状态转移，不能照搬本题的偶数长度判定或公差为 2 的不变式。

需要最少修改次数呢？当前算法只记录可达性，没有保留代价；需要增加最小代价状态或设计专门的优化算法，不能由 low/high 直接读出最优次数。
