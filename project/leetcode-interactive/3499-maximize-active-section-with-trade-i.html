01 / Problem

题意

查看官方题目 ↗

给定只含 '0' 与 '1' 的字符串 s。其中 1 表示活跃区段，0 表示非活跃区段。

最多执行一次完整交易：先把一段被 0 包围的连续 1 全部变成 0；再把一段被 1 包围的连续 0 全部变成 1。

处理时视作在两端添加哨兵 1，即 t = "1" + s + "1"；哨兵不计入答案。

Core insight

核心洞察：只看相邻两个零段

在 t = "1" + s + "1" 中，任意相邻两个零段之间必有一段连续 1。 先把中间的 1 段熄灭，三个区块会合并；再把整个合并零段点亮。中间 1 段先减后加相互抵消，净增益恰好是左右零段长度之和。

answer = 原始 1 数量 + max(相邻零段长度之和)

Complete process

完整过程

  1. 01统计原字符串中 1 的数量，作为不操作时的答案。
  2. 02在字符串两端加哨兵 1，避免对首尾零段做特殊判断。
  3. 03从左到右统计每个连续零段长度；保留上一个零段长度。
  4. 04遇到新的零段时，用“上一个 + 当前”更新最大增益。
  5. 05把最大增益加回原始 1 数量；若不足两个零段，增益保持 0。

边界情况

  • 全 1：没有零段，保持原答案。
  • 全 0：只有一个零段，无法先熄灭被 0 包围的 1 段。
  • 仅一个零段：不存在相邻零段，不能完成有效交易。
  • 首尾为 0：哨兵 1 让首尾零段可以统一参与判断。

复杂度

时间
O(n)
额外空间
O(n) / O(1)

示例代码显式构造 t，空间为 O(n)；用虚拟边界索引可降到 O(1)。

替代方案取舍

可以保存完整游程数组，逻辑直观但需要 O(n) 额外空间；也可枚举交易区间，但会退化到 O(n²)。滚动保存前一零段最适合面试。

常见错误

  • 忘记“两端补 1”，漏掉边缘零段。
  • 把中间 1 段也算作净增益。
  • 只有一个零段时仍执行交易。
  • 把“最多一次”误写成“必须一次”。

面试追问

为什么中间 1 段不影响增益？

它在第一步被减去，在第二步随合并区间被加回，贡献相互抵消。

如何做到 O(1) 额外空间？

不保存所有游程，只滚动记录前一零段长度与当前零段长度。

哨兵为什么不污染答案？

答案基数只统计原始 s；哨兵只提供“被 1 包围”的边界条件。
