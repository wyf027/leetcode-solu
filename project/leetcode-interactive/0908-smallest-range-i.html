最小差值 I

先把每个数字看作一个可移动区间，再观察两端之间还能剩下多少距离。交互演示只呈现问题机制，题解默认收起。

EASY Smallest Range I

题目

给定整数数组 nums 和整数 k。对每个下标至多操作一次：选择整数 x ∈ [-k,k]，把 nums[i] 改成 nums[i] + x。数组分数为最大值减最小值，返回操作后可能得到的最低分数。

约束

  • 1 ≤ nums.length ≤ 10⁴
  • 0 ≤ nums[i] ≤ 10⁴
  • 0 ≤ k ≤ 10⁴

官方示例

输入：nums = [1], k = 0 输出：0 解释：1 - 1 = 0。
输入：nums = [0,10], k = 2 输出：6 解释：可改为 [2,8]，分数为 8 - 2 = 6。
输入：nums = [1,3,6], k = 3 输出：0 解释：可改为 [4,4,4]。

Solution

题解

核心洞察

只有原数组的最小值和最大值决定答案。最小值最多向右移动 k，最大值最多向左移动 k，因此原跨度最多缩短 2k；若两端区间重叠，最低分数就是 0。

完整过程

  1. 一次遍历求 minVal 与 maxVal。
  2. 计算原跨度 maxVal - minVal。
  3. 返回 max(0, maxVal - minVal - 2k)。

正确性证明

任意元素最多改变 k，所以新的最大值不可能低于 maxVal-k，新的最小值不可能高于 minVal+k，分数至少为二者之差（并且不能小于 0）。将偏大的元素向左、偏小的元素向右移动可达到该下界；两侧区间重叠时可把极值移入公共区域。因此公式给出的下界可达，算法正确。

边界与复杂度

单元素、k=0、以及 2k 大于原跨度均由同一公式覆盖。时间复杂度 O(n)，额外空间 O(1)。

替代方案

先排序再看首尾也能求解，但时间为 O(n log n)，且排序并没有提供额外价值。

面试追问

  • 若每个元素的 k 不同，如何判断所有可达区间能否相交？
  • 若必须恰好操作一次，答案会改变吗？（不会，因为可选 x=0。）
  • 如何推广到连续实数和非对称移动范围？

常见错误

  • 忘记用 max(0, ...)，得到负分数。
  • 只减一次 k，忽略两端都能向中间移动。
  • 不必要地排序或逐个模拟所有 x。

Java

class Solution {
    public int smallestRangeI(int[] nums, int k) {
        int min = nums[0], max = nums[0];
        for (int value : nums) {
            min = Math.min(min, value);
            max = Math.max(max, value);
        }
        return Math.max(0, max - min - 2 * k);
    }
}

from typing import List

class Solution:
    def smallestRangeI(self, nums: List[int], k: int) -> int:
        return max(0, max(nums) - min(nums) - 2 * k)

C++

class Solution {
public:
    int smallestRangeI(vector<int>& nums, int k) {
        auto [minIt, maxIt] = minmax_element(nums.begin(), nums.end());
        return max(0, *maxIt - *minIt - 2 * k);
    }
};
