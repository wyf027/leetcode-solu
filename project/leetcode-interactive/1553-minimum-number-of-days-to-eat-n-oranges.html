吃掉 N 个橘子的最少天数

每天只能选一种吃法。真正的挑战不在“吃多少”，而在何时花一天把数量折半或缩到三分之一。

Minimum Number of Days to Eat N Oranges ·非付费题
n → 0

从最多 20 亿个橘子出发，在有限的三种动作中寻找最短路径。

一天 · 一次动作 · 目标最少天数
Problem

题目

厨房里有 n 个橘子。每天恰好选择下面一种合法操作，求吃完全部橘子的最少天数。

  1. 普通吃法
    吃掉 1 个橘子。
  2. 二等分吃法
    若当前数量能被 2 整除，吃掉当前数量的一半，剩下一半。
  3. 三等分吃法
    若当前数量能被 3 整除，吃掉当前数量的三分之二，剩下三分之一。

函数形式：int minDays(int n)，返回最少天数。

约束 1 ≤ n ≤ 2 × 10⁹

每天只能执行一种操作；输入是整数。

Solution

准备好看完整题解了吗？

题解默认收起，建议先用上方实验室观察几组数字，再核对递推关系和证明。

Core insight

不要一天一天走，直接付“凑整除”的费用

当选择除以 2 的捷径时，若 n 不是 2 的倍数，就必须先连续吃掉 n % 2 个；之后再花 1 天执行折半。除以 3 同理。于是无需展开每个 n - 1 状态，只比较两种必然的凑整成本。

f(n) = 1 + min(n % 2 + f(⌊n/2⌋), n % 3 + f(⌊n/3⌋))

边界：f(0) = 0，f(1) = 1。用哈希表记忆已经求过的状态。

完整过程

  1. 若 n ≤ 1，直接返回 n。
  2. 计算走“除以 2”路线所需的天数：先吃 n % 2 个，再花 1 天折半，最后解决 ⌊n/2⌋。
  3. 同样计算“除以 3”路线：先吃 n % 3 个，再花 1 天缩到三分之一，最后解决 ⌊n/3⌋。
  4. 取两条路线的较小值，并把结果写入记忆表。

正确性证明

归纳假设：对所有小于 n 的橘子数，f 都给出最少天数。

任意最优方案若不只使用“吃 1 个”，它第一次使用的批量操作只能是除以 2 或除以 3。使用前必须分别吃掉至少 n % 2 或 n % 3 个，递推式精确计入了这段不可避免的代价与批量操作的 1 天。操作后的规模更小，由归纳假设，其后缀代价最优。两类首次批量操作已被穷尽；全程只吃 1 个也不会优于递推中的路线。因此取最小值得到全局最优解。

边界与复杂度

  • n = 1 时必须再用 1 天吃完。
  • 接近 2 × 10⁹ 时不能建立线性 DP 数组；哈希记忆化只访问被 2、3 不断缩小的状态。
  • 不同状态形如 ⌊n / (2ᵃ3ᵇ)⌋。时间与空间复杂度均为 O(log² n)，递归深度为 O(log n)。

替代方案

Dijkstra / BFS：把橘子数视为节点、每天的操作视为边，可求从 n 到 0 的最短路；但状态管理更重。

线性动态规划：从 0 推到 n 思路直观，但 n 可达 20 亿，时间与内存都不可接受。

纯递归：递推方向正确，但没有记忆化会重复计算同一子问题。

Implementation

四种语言完整代码

JavaHashMap 记忆化
import java.util.HashMap;
import java.util.Map;

class Solution {
    private final Map<Integer, Integer> memo = new HashMap<>();

    public int minDays(int n) {
        if (n <= 1) {
            return n;
        }
        if (memo.containsKey(n)) {
            return memo.get(n);
        }

        int viaTwo = n % 2 + minDays(n / 2);
        int viaThree = n % 3 + minDays(n / 3);
        int answer = 1 + Math.min(viaTwo, viaThree);
        memo.put(n, answer);
        return answer;
    }
}
JavaScriptMap 记忆化
/**
 * @param {number} n
 * @return {number}
 */
var minDays = function(n) {
    const memo = new Map();

    const dp = (oranges) => {
        if (oranges <= 1) {
            return oranges;
        }
        if (memo.has(oranges)) {
            return memo.get(oranges);
        }

        const viaTwo = oranges % 2 + dp(Math.floor(oranges / 2));
        const viaThree = oranges % 3 + dp(Math.floor(oranges / 3));
        const answer = 1 + Math.min(viaTwo, viaThree);
        memo.set(oranges, answer);
        return answer;
    };

    return dp(n);
};
Python 3@cache 记忆化
from functools import cache


class Solution:
    def minDays(self, n: int) -> int:
        @cache
        def dp(oranges: int) -> int:
            if oranges <= 1:
                return oranges

            via_two = oranges % 2 + dp(oranges // 2)
            via_three = oranges % 3 + dp(oranges // 3)
            return 1 + min(via_two, via_three)

        return dp(n)
C++unordered_map 记忆化
class Solution {
private:
    unordered_map<int, int> memo;

public:
    int minDays(int n) {
        if (n <= 1) {
            return n;
        }
        auto found = memo.find(n);
        if (found != memo.end()) {
            return found->second;
        }

        int viaTwo = n % 2 + minDays(n / 2);
        int viaThree = n % 3 + minDays(n / 3);
        int answer = 1 + min(viaTwo, viaThree);
        memo[n] = answer;
        return answer;
    }
};

面试追问

  • 为什么不显式考虑 f(n - 1)？
    因为连续的减一操作已经被 n % 2 和 n % 3 计入；最优方案下一次批量操作只有这两类。
  • 能否改为迭代？
    可以用优先队列做最短路，但递归记忆化更短，也只访问必要状态。
  • 为什么不会栈溢出？
    每次递归至少把规模折半，深度是对数级。

常见错误

  • 把“除以 3”误解为吃掉三分之一；题目要求吃掉三分之二，最终剩 n / 3。
  • 忘记批量操作本身还需要 1 天，导致递推少加 1。
  • 用长度为 n 的数组做 DP，无法承受 20 亿的上界。
  • Python 把普通函数调用写进装饰器之外，导致缓存没有覆盖递归子问题。
