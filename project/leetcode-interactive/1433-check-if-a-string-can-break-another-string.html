1433 · Check If a String Can Break Another String

MEDIUM贪心字符串排序非付费题
Problem

题目描述

给你两个长度相等的字符串 s1 和 s2。判断是否存在 s1 的某个排列能够打破 s2 的某个排列，或者反过来，存在 s2 的某个排列能够打破 s1 的某个排列。

“打破”的定义：对于两个长度均为 n 的字符串 x、y，如果每个下标 i ∈ [0, n − 1] 都满足 x[i] ≥ y[i]（按英文字母顺序比较），则称 x 可以打破 y。

函数签名

checkIfCanBreak(s1: string, s2: string): boolean

官方示例

示例 1
输入：s1 = "abc", s2 = "xya"
输出：true
解释："ayx" 是 s2 的一个排列，
它可以打破 s1 的排列 "abc"。
示例 2
输入：s1 = "abe", s2 = "acd"
输出：false
解释：任取两边的排列，都无法让
其中一边在所有位置上不小于另一边。
示例 3
输入：s1 = "leetcodee",
      s2 = "interview"
输出：true

约束

  • s1.length == n
  • s2.length == n
  • 1 <= n <= 10^5
  • 两个字符串都只包含小写英文字母。

Solution

排序后逐位比较

核心洞察：分别将两个字符串升序排列。如果排好序的某一方在每个位置都不小于另一方，那么它就能打破另一方；只需同时维护两个可能方向即可。排序把“寻找两个合适排列”化成了同一排名位置的比较。

完整过程

  1. 将 s1、s2 的字符分别按升序排列，得到 a 与 b。
  2. 初始化两个方向：aCanBreakB = true 与 bCanBreakA = true。
  3. 对每个下标 i：若 a[i] < b[i]，第一个方向失效；若 b[i] < a[i]，第二个方向失效。
  4. 两个方向只要仍有一个成立就返回 true；若两者都失效，可以提前返回 false。

为什么正确

充分性：若升序后的 a[i] ≥ b[i] 对所有位置成立，直接选择这两个升序排列，就已经构造出一个满足定义的排列对，所以 s1 可以打破 s2。

必要性：设存在某个排列使 s1 逐位不小于 s2。任取最小的前 k 个字符，较强一方不能比另一方拥有更多落在更小字母区间内的字符；等价地，两边升序后第 k 个字符仍保持不小于关系。因此可行方向在升序配对下不会消失。

算法分别检查两个方向，所以恰好覆盖题目中的“或者反过来”。

边界情况

  • 长度为 1：直接比较，必有一个方向成立。
  • 两个字符串相同：两个方向都成立。
  • 大量重复字符：排序与逐位比较仍然有效。
  • 两方向在不同位置各自失败：结果为 false。

复杂度

  • 时间：O(n log n)，由两次排序主导。
  • 空间：通常为 O(n)，用于字符数组；具体也取决于语言的排序实现。

四语言完整代码

import java.util.Arrays;

class Solution {
    public boolean checkIfCanBreak(String s1, String s2) {
        char[] a = s1.toCharArray();
        char[] b = s2.toCharArray();
        Arrays.sort(a);
        Arrays.sort(b);

        boolean aCanBreakB = true;
        boolean bCanBreakA = true;
        for (int i = 0; i < a.length; i++) {
            if (a[i] < b[i]) aCanBreakB = false;
            if (b[i] < a[i]) bCanBreakA = false;
            if (!aCanBreakB && !bCanBreakA) return false;
        }
        return true;
    }
}

        a = sorted(s1)
        b = sorted(s2)
        a_can_break_b = True

        for left, right in zip(a, b):
            if left < right:
                a_can_break_b = False
            if right < left:

        return True

替代方案

由于字符只包含 a-z，可以用两个长度为 26 的计数数组模拟有序序列，并通过双指针或累计计数判断方向，把时间降为 O(n + 26)。实现更细碎，面试中先写排序版通常更稳妥。

面试追问

  • 能否利用 26 个字母把排序优化掉？
  • 若字符集扩展为 Unicode，方案和复杂度怎样变化？
  • 为什么只检查同排名字符，而不需要枚举排列？

常见错误

  • 只检查 s1 打破 s2，遗漏反方向。
  • 直接按原字符串逐位比较，没有先选择合适的排列。
  • 把“打破”误解为存在一个位置更大；实际要求所有位置都不小于。
  • 使用严格大于 >，错误排除相等字符；定义是 ≥。
