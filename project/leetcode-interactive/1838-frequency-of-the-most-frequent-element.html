1838. 最高频元素的频数

Frequency of the Most Frequent Element

把有限的递增次数，用在最值得的位置。

题目

给定整数数组 nums 和整数 k。每次操作可以选取一个下标，让对应的数增加 1。你可以执行至多 k 次操作，求最终某个数能够出现的最多次数。

返回的是频数，不是该数的值。操作可以少于 k 次，且不能将元素减小。

官方示例

示例 1：nums = [1,2,4], k = 5
输出：3

对 1 增加 3，对 2 增加 2，得到 [4,4,4]，频数为 3。

示例 2：nums = [1,4,8,13], k = 5
输出：2

可把 1 增至 4（3 次）、4 增至 8（4 次），或 8 增至 13（5 次）。三种方案都能得到频数 2。

示例 3：nums = [3,9,6], k = 2
输出：1

预算不足以使任意两个数相等。

约束与接口

  • 1 ≤ nums.length ≤ 10⁵
  • 1 ≤ nums[i] ≤ 10⁵
  • 1 ≤ k ≤ 10⁵

maxFrequency(nums, k) → integer

题解 · 排序后的补齐窗口

核心洞察

排序后，固定右端点 r，把一段连续窗口 [l,r] 都增至 nums[r]。柱子原高度的总和为 sum，补齐至同一水平线需要：

cost = nums[r] × (r - l + 1) - sum

固定目标和元素个数，选择离目标最近的较小元素最省操作，所以只需考虑排序后的连续窗口。

完整过程

  1. 按数值升序排序。令 l = 0，sum = 0，ans = 0。
  2. 依次移动 r，把 nums[r] 加入 sum。
  3. 只要补齐成本大于 k，就从 sum 减去 nums[l]，再把 l 右移一位。
  4. 成本合规后，用窗口长度更新 ans。遍历完所有 r 后返回 ans。

为什么正确

目标可取原数组中的值：对于任何被提升为同一数 T 的元素集合，其最大原值 M ≤ T。把目标降为 M 不会增加成本，也不改变集合大小，因此总有一个最优方案以原值为目标。

连续窗口足够：固定目标 nums[r] 和数量 m，选择不大于目标的最大 m 个数会使原值之和最大，成本最小；这些值在排序数组中构成以 r 结尾的窗口。

左边界不会后退：右端点从 r 移到 r+1 时，对于同一个 l，成本增加 (nums[r+1]−nums[r])×(r−l+1)，非负。因此之前已因超预算丢弃的左端点在后续也不可行。收缩至可行时得到当前右端点的最长可行窗口，取所有窗口长度的最大值即为最优答案。

边界与复杂度

单元素窗口成本恒为 0；全部相等时无需操作；成本恰好为 k 时仍合法。重复值无需去重。原题 k 至少为 1，算法也自然支持扩展情形 k = 0。

排序 O(n log n)，窗口扫描 O(n)，合计 O(n log n)。窗口本身额外空间 O(1)；总辅助空间取决于排序实现：下方 Python 的排序最坏 O(n)，C++ 常用排序栈 O(log n)，Java 与 JavaScript 的排序开销依赖运行库实现。代码均对输入原地排序；如需保留原数组，先复制，额外 O(n)。

乘积和总和可能达到 10¹⁰，Java 使用 long、C++ 使用 long long。JavaScript Number 在本题整数范围内精确，Python 整数无需特别处理。

四语言完整提交代码

Java

import java.util.Arrays;

class Solution {
    public int maxFrequency(int[] nums, int k) {
        Arrays.sort(nums);
        long sum = 0;
        int left = 0, answer = 0;
        for (int right = 0; right < nums.length; right++) {
            sum += nums[right];
            while ((long) nums[right] * (right - left + 1) - sum > k) {
                sum -= nums[left++];
            }
            answer = Math.max(answer, right - left + 1);
        }
        return answer;
    }
}

Python 3

from typing import List

class Solution:
    def maxFrequency(self, nums: List[int], k: int) -> int:
        nums.sort()
        left = total = answer = 0
        for right, target in enumerate(nums):
            total += target
            while target * (right - left + 1) - total > k:
                total -= nums[left]
                left += 1
            answer = max(answer, right - left + 1)
        return answer

C++

#include <algorithm>
#include <vector>
using namespace std;

class Solution {
public:
    int maxFrequency(vector<int>& nums, int k) {
        sort(nums.begin(), nums.end());
        long long sum = 0;
        int left = 0, answer = 0;
        for (int right = 0; right < (int)nums.size(); ++right) {
            sum += nums[right];
            while (1LL * nums[right] * (right - left + 1) - sum > k) {
                sum -= nums[left++];
            }
            answer = max(answer, right - left + 1);
        }
        return answer;
    }
};

替代方案

排序并计算前缀和，再二分答案长度 m：扫描所有长度 m 的窗口，若存在成本不超过 k 的窗口则 m 可行。较小长度也可行，故可以二分。总体 O(n log n) 时间、O(n) 额外空间；滑动窗口省去了前缀和数组与多次扫描。

常见错误

  • 把返回值写成目标数，而不是频数。
  • JavaScript 使用默认 sort，导致按字符串排序。
  • 成本等于 k 时仍收缩，错误丢弃合法窗口。
  • 只写一次 if 收缩，却仍把窗口当作可行状态；本实现使用 while 维护明确不变量。
  • 移动左端点时漏减窗口和，或把长度写成 r−l。
  • Java/C++ 先用 32 位做乘法再转型，溢出发生在转型之前。

面试追问

如果允许增加和减少？固定一组选中元素时，中位数使绝对距离之和最小，不能直接使用右端点补齐公式。

如果每个位置递增的单价不同？“最接近目标的元素最便宜”的交换论证不再成立，需要按加权成本重新选取，不能直接复用连续窗口结论。

如何恢复方案？更新答案时记录最优 l、r 及目标值，对该窗口中的元素分别递增目标值与原值的差；若需要原下标，排序时保存值与下标的对应关系。
