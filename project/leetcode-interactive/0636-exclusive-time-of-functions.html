函数的独占时间

Exclusive Time of Functions

读懂一串函数开始与结束日志，计算每个函数真正占用单线程 CPU 的时间。先理解时间戳语义，再亲手推进日志；题解不会在首屏提前揭晓。

开始读题 ↓ 打开交互演示
难度MEDIUM
付费限制免费题
核心对象调用栈
关键阅读点：end 时间戳包含在执行区间内。例如从 2 开始、到 5 结束，一共执行 4 个单位时间。

Problem

题目描述

一台单线程 CPU 运行含有 n 个函数的程序，函数编号为 0 到 n - 1。调用开始时函数编号入栈，调用结束时出栈；任意时刻只有栈顶函数在执行。

每条日志的格式为 function_id:start|end:timestamp。start 表示函数在该时间戳的起点开始执行，end 表示函数执行到该时间戳的末尾，因此结束点需要计入一整个单位时间。函数可以被多次调用，也可能递归调用自身。

函数的独占时间，是它处于栈顶并实际占用 CPU 的所有时间之和；调用其他函数的时间不能算入。请返回长度为 n 的数组，索引 i 处是函数 i 的独占时间。

官方示例

示例 1

嵌套调用
输入：n = 2,
logs = ["0:start:0","1:start:2",
        "1:end:5","0:end:6"]
输出：[3,4]

函数 0 先执行时间 0、1，再于时间 6 恢复；函数 1 独占时间 2 到 5。

示例 2

递归
输入：n = 1,
logs = ["0:start:0","0:start:2",
        "0:end:5","0:start:6",
        "0:end:6","0:end:7"]
输出：[8]

同一函数的初始调用与两次递归调用累计占用全部 8 个时间单位。

示例 3

递归 + 嵌套
输入：n = 2,
logs = ["0:start:0","0:start:2",
        "0:end:5","1:start:6",
        "1:end:6","0:end:7"]
输出：[7,1]

函数 0 的多个调用共执行 7 个单位；函数 1 在时间 6 独占 1 个单位。

函数签名

exclusiveTime(n, logs) → int[]
  • n：函数总数。
  • logs：按发生顺序给出的日志字符串列表。
  • 返回值：每个函数的独占时间。

约束

  • 1 ≤ n ≤ 100
  • 2 ≤ logs.length ≤ 500
  • 0 ≤ function_id < n
  • 0 ≤ timestamp ≤ 10⁹
  • 任意两个 start 事件不共享时间戳；任意两个 end 事件也不共享时间戳。
  • 每个 start 日志都有对应的 end 日志。

Solution

完整题解

先独立思考，再按需展开。展开后包含证明、复杂度与四种语言代码。

栈 + 上一个未结算时间点

洞察 1

只有栈顶在执行

遇到新调用时，旧栈顶在这一刻被暂停；遇到结束时，当前栈顶完成并出栈。

洞察 2

每段只结算一次

维护 prev，代表下一段尚未计入答案的起点。每条日志只结算 prev 到当前边界。

洞察 3

end 是闭区间

end:t 包含时间单位 t，所以本段长度是 t - prev + 1，结算后令 prev = t + 1。

完整过程

  1. 创建结果数组 answer[n]、空栈和变量 prev。
  2. 按顺序解析每条日志为 id、type、time。
  3. 若是 start：旧栈顶从 prev 执行到 time - 1，增加 time - prev；随后新函数入栈，并令 prev = time。
  4. 若是 end：栈顶从 prev 执行到 time，增加 time - prev + 1；弹栈，并令 prev = time + 1。
  5. 日志处理完毕后，结果数组就是每个函数跨所有调用累计的独占时间。

为什么这样是正确的

不变式：处理每条日志前，所有早于 prev 的 CPU 时间都已且仅已计入当时的栈顶函数，而从 prev 开始的时间尚未计入。

遇到 start 时，区间 [prev, time) 内运行者始终是旧栈顶；把这段计给它后，新函数从 time 开始运行，不变式继续成立。

遇到 end 时，区间 [prev, time] 内运行者始终是当前栈顶。闭区间长度为 time - prev + 1；弹栈后，下一个未结算时间是 time + 1，不变式仍成立。

全部日志结束时不存在未结束调用，因此所有执行时间都被恰好结算一次，且只计入实际占用 CPU 的函数，所得即独占时间。

时间复杂度O(L + n)

L 为日志数量；初始化答案需 O(n)。

空间复杂度O(n)

最深调用栈与答案数组。

单条日志O(1)

解析后只做一次栈操作和结算。

边界情况

  • 零长度看似相同的起止时间：0:start:6 与 0:end:6 仍贡献 1，而不是 0。
  • 递归调用：栈中可出现相同函数编号；每次结算给编号汇总即可。
  • 连续调用：前一个函数在 t 结束后，下一个未结算时刻必须是 t + 1。
  • 大时间戳：不要逐单位模拟；直接用区间长度计算。
  • 只有一个函数：栈机制无需特判，所有调用层的独占时间自然累加到同一位置。

四种语言完整代码

均为官方可提交签名

Java

List<String> → int[]
import java.util.ArrayDeque;
import java.util.Deque;
import java.util.List;

class Solution {
    public int[] exclusiveTime(int n, List<String> logs) {
        int[] answer = new int[n];
        Deque<Integer> stack = new ArrayDeque<>();
        int prev = 0;

        for (String log : logs) {
            String[] parts = log.split(":");
            int id = Integer.parseInt(parts[0]);
            int time = Integer.parseInt(parts[2]);

            if (parts[1].equals("start")) {
                if (!stack.isEmpty()) {
                    answer[stack.peek()] += time - prev;
                }
                stack.push(id);
                prev = time;
            } else {
                answer[stack.pop()] += time - prev + 1;
                prev = time + 1;
            }
        }
        return answer;
    }
}

JavaScript

string[] → number[]
/**
 * @param {number} n
 * @param {string[]} logs
 * @return {number[]}
 */
var exclusiveTime = function(n, logs) {
    const answer = new Array(n).fill(0);
    const stack = [];
    let prev = 0;

    for (const log of logs) {
        const [idText, type, timeText] = log.split(":");
        const id = Number(idText);
        const time = Number(timeText);

        if (type === "start") {
            if (stack.length > 0) {
                answer[stack[stack.length - 1]] += time - prev;
            }
            stack.push(id);
            prev = time;
        } else {
            answer[stack.pop()] += time - prev + 1;
            prev = time + 1;
        }
    }
    return answer;
};

Python 3

List[str] → List[int]
from typing import List


class Solution:
    def exclusiveTime(self, n: int, logs: List[str]) -> List[int]:
        answer = [0] * n
        stack = []
        prev = 0

        for log in logs:
            id_text, event_type, time_text = log.split(":")
            function_id = int(id_text)
            time = int(time_text)

            if event_type == "start":
                if stack:
                    answer[stack[-1]] += time - prev
                stack.append(function_id)
                prev = time
            else:
                answer[stack.pop()] += time - prev + 1
                prev = time + 1

        return answer

C++

vector<string> → vector<int>
#include <string>
#include <vector>
using namespace std;

class Solution {
public:
    vector<int> exclusiveTime(int n, vector<string>& logs) {
        vector<int> answer(n, 0);
        vector<int> stack;
        int prev = 0;

        for (const string& log : logs) {
            size_t first = log.find(':');
            size_t second = log.find(':', first + 1);
            int id = stoi(log.substr(0, first));
            string type = log.substr(first + 1, second - first - 1);
            int time = stoi(log.substr(second + 1));

            if (type == "start") {
                if (!stack.empty()) {
                    answer[stack.back()] += time - prev;
                }
                stack.push_back(id);
                prev = time;
            } else {
                answer[stack.back()] += time - prev + 1;
                stack.pop_back();
                prev = time + 1;
            }
        }
        return answer;
    }
};

替代方案

调用帧记录子调用耗时：栈里保存每次调用的开始时间与累计子调用时间。结束时先算调用总时长，再减去子调用时长，并把总时长累加给父帧。它同样是 O(L)，但状态更多，适合需要同时得到每次调用的总耗时与独占耗时。

逐时间单位模拟：概念直观，却在时间戳达到 10⁹ 时不可行。它只适合纸面检查极小示例，不应作为提交方案。

面试追问

  • 如果日志是流式到达，算法能否在线输出？可以维护栈、prev 和累计结果，但只有相关调用结束后结果才稳定。
  • 如果 CPU 不是单线程怎么办？单个调用栈不够，需要按线程分别维护栈与 prev，再按函数编号聚合。
  • 如何检测坏日志？可校验 end 的编号必须等于栈顶、时间戳不得倒退、最终栈必须为空。
  • 若时间戳改为连续时间且 end 不含端点？结束分支就不再加 1，语义会统一为半开区间。

常见错误

  • 在 end 分支漏掉 +1，导致每次调用都少算一个单位。
  • end 后仍令 prev = time，把结束时刻重复计算给恢复的父函数。
  • start 时只入栈却不先结算旧栈顶，丢失父函数在子调用前的时间。
  • 把栈帧各自的持续时间直接累加，未扣除嵌套调用时间。
  • 将函数编号当作调用实例；递归时相同编号可以同时出现在栈中多次。
