填满背包的最大价格

物品可以按任意比例切分。你能否把容量恰好装满，并让袋中物品的总价格尽可能高？先读题、动手推演，再决定你的策略。

MEDIUM Premium maxPrice(items, capacity) 返回 double
English title
Maximum Price to Fill a Bag

01 · Problem

先把问题说清楚

每个物品只提供一次，但允许切分；切分后的重量与价格按同一比例缩放。目标不是“至多装多少”，而是必须恰好达到给定容量。

题意转述

给定二维整数数组 items，其中 items[i] = [priceᵢ, weightᵢ] 表示第 i 件物品的总价格和总重量；另给正整数 capacity。

任意物品都能切成若干部分。若取原物品的比例为 r，则得到的重量为 weightᵢ × r，价格为 priceᵢ × r。在每件物品最多取完的前提下，让所取总重量恰好等于 capacity，返回可得到的最大总价格；若所有物品总重量仍不足以装满，返回 -1。

精度

与真实答案的误差不超过 10⁻⁵ 即可接受。

约束

  • 1 ≤ items.length ≤ 10⁵
  • items[i].length == 2
  • 1 ≤ priceᵢ, weightᵢ ≤ 10⁴
  • 1 ≤ capacity ≤ 10⁹
官方参数形式 double maxPrice(int[][] items, int capacity)

Solution · Revealed

按单位重量价格从高到低装入

这是连续型（可分割）背包。切分让“取多少”成为连续量，因此每一单位容量都应优先分配给回报最高的物品。

核心洞察

1

定义物品的单位重量价格 density = price / weight。密度越高，同样一单位容量带来的价格越大。

2

把物品按密度降序排列，依次取 min(weight, remainingCapacity) 的重量；最后一件可能只取一部分。

3

遍历结束后容量仍大于 0，说明物品总重量不足，返回 -1；否则返回累计价格。

完整过程

  1. 按 priceᵢ / weightᵢ 从大到小排序。比较器可用交叉乘法，避免只为排序引入浮点误差。
  2. 初始化 answer = 0，剩余容量为 capacity。
  3. 对当前物品取重量 take = min(weightᵢ, remaining)。
  4. 累加 priceᵢ × take / weightᵢ，并从剩余容量减去 take。
  5. 容量归零即可返回；遍历后仍未归零则返回 -1。

为什么正确：交换论证

  1. 设贪心顺序中物品 A 的密度不小于物品 B，即 dA ≥ dB。
  2. 若某个可行方案在 A 尚未取完时取了 B 的正重量 δ，把这 δ 重量从 B 换成 A，不改变总重量。
  3. 价格变化为 δ × (dA - dB) ≥ 0，因此交换后不会更差。
  4. 反复交换，就能把任意最优方案变为先取高密度、再取低密度的形式，且价格不降低。
  5. 所以按密度降序尽量取满每件物品的策略得到最优价格；若总重量不足容量，则任何方案都不可能恰好装满。

复杂度

时间：O(n log n)，排序占主导。

空间：除排序实现的栈或辅助数组外为 O(1)；实际语言库排序通常使用 O(log n) 到 O(n) 额外空间。

边界

  • 总重量小于容量：返回 -1。
  • 容量在某件物品内被填满：按比例计算价格后结束。
  • 密度相同：先后顺序不影响答案。
  • 恰好取完整件：比例为 1，公式仍成立。

替代方案

可以先求总重量快速判断可行性，再排序；这不会改善渐进复杂度。动态规划适用于不可分割的 0/1 背包，但这里容量可达 10⁹ 且物品可切分，既不必要也不合适。

四语言完整实现

均按官方函数语义实现；排序会改变 items 的顺序。

LeetCode Java 提交形式

import java.util.Arrays;

class Solution {
    public double maxPrice(int[][] items, int capacity) {
        Arrays.sort(items, (a, b) -> Long.compare(
            (long) b[0] * a[1],
            (long) a[0] * b[1]
        ));

        double answer = 0.0;
        int remaining = capacity;

        for (int[] item : items) {
            int price = item[0];
            int weight = item[1];
            int take = Math.min(weight, remaining);

            answer += (double) price * take / weight;
            remaining -= take;

            if (remaining == 0) {
                return answer;
            }
        }

        return -1.0;
    }
}

LeetCode JavaScript 提交形式

/**
 * @param {number[][]} items
 * @param {number} capacity
 * @return {number}
 */
var maxPrice = function(items, capacity) {
    items.sort((a, b) => b[0] / b[1] - a[0] / a[1]);

    let answer = 0;
    let remaining = capacity;

    for (const [price, weight] of items) {
        const take = Math.min(weight, remaining);
        answer += price * take / weight;
        remaining -= take;

        if (remaining === 0) {
            return answer;
        }
    }

    return -1;
};

LeetCode C++ 提交形式

#include <algorithm>
#include <vector>
using namespace std;

class Solution {
public:
    double maxPrice(vector<vector<int>>& items, int capacity) {
        sort(items.begin(), items.end(), [](const auto& a, const auto& b) {
            return (long long) a[0] * b[1] > (long long) b[0] * a[1];
        });

        double answer = 0.0;
        int remaining = capacity;

        for (const auto& item : items) {
            int price = item[0];
            int weight = item[1];
            int take = min(weight, remaining);

            answer += (double) price * take / weight;
            remaining -= take;

            if (remaining == 0) {
                return answer;
            }
        }

        return -1.0;
    }
};

常见错误

  • 把数组顺序看反：items[i] 是 [price, weight]，不是 [weight, price]。
  • 按总价格排序：价格高但重量更大的物品未必更划算，应比较单位重量价格。
  • 忘记切分：最后一件通常只取一部分，不能直接跳过超出剩余容量的物品。
  • 返回部分结果：总重量不足时必须返回 -1，不是当前累计价格。
  • 比较器溢出：使用交叉乘法时，在 Java/C++ 中先提升到 64 位。

面试追问

  1. 为什么 0/1 背包不能这样贪心？ 因为物品不可切分，局部最优密度可能阻塞更好的整体组合。
  2. 能否不排序？ 若只求一次通常排序最直接；也可反复选择最大密度，但朴素实现会退化为 O(n²)。
  3. 怎样避免浮点排序误差？ 比较 p₁ × w₂ 与 p₂ × w₁，累加价格时再使用浮点数。
  4. 如果每种物品数量无限？ 只要存在物品，永远重复取最高密度的那种即可填满；这已是另一种模型。
