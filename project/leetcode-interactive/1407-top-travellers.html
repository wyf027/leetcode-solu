Problem

题目

给定用户表 Users 与行程表 Rides，报告每个用户的累计旅行距离。结果先按 travelled_distance 降序；总距离相同时，再按 name 升序。

    Solution Vault

    准备好再揭开题解

    先走完上面的查询流水线，再用完整题解校准你的推理。

    核心洞察

    结果必须包含 Users 的所有人，因此从 Users 出发做 LEFT JOIN。按用户分组累加 distance；没有匹配行程时聚合结果可能是 NULL，用 COALESCE(..., 0) 补成 0。最后严格应用两个排序键。

    完整过程

    1. 保留全集：以 Users 为左表，按 u.id = r.user_id 关联 Rides。
    2. 按人聚合：以用户 id 与 name 分组，计算每组 SUM(r.distance)。
    3. 处理空组：使用 COALESCE 把无行程用户的 NULL 总和替换为 0。
    4. 命名结果：将表达式别名设为 travelled_distance。
    5. 稳定排序：先按总距离 DESC，再按 name ASC。

    正确性说明

    覆盖性：LEFT JOIN 保证 Users 的每一行至少出现在关联结果一次，因此无人会遗漏。累计正确：对每个用户分组后，组内恰好包含属于该用户的全部 Rides，SUM 等于其总旅行距离。空值正确：无匹配行程时 COALESCE 将空聚合解释为 0。顺序正确：ORDER BY 依次使用题目指定的主键与次键，所以输出顺序符合要求。

    边界情况

    • 用户没有任何行程：仍输出，距离为 0。
    • 多名用户总距离相同：按 name 升序打破平局。
    • 同一用户有多次行程：全部行程都计入 SUM。
    • Rides 为空：所有用户都输出 0，并按 name 升序。

    复杂度

    设用户数为 U、行程数为 R。数据库执行计划依索引和优化器而异；概念上扫描与聚合约为 O(U + R)，对 U 个聚合结果排序约为 O(U log U)，结果与聚合状态约占 O(U) 空间。若 Rides.user_id 有索引，关联通常更高效。

    主提交语言：SQL

    MySQL / PostgreSQL 兼容写法官方可提交
    SELECT
    u.name,
    COALESCE(SUM(r.distance), 0) AS travelled_distance
FROM Users AS u
LEFT JOIN Rides AS r
    ON u.id = r.user_id
GROUP BY u.id, u.name
ORDER BY travelled_distance DESC, u.name ASC;

    Java 17本地语义参考
    import java.util.*;

public class TopTravellers {
    record User(int id, String name) {}
    record Ride(int id, int userId, int distance) {}
    record Result(String name, long travelledDistance) {}

    public static List<Result> solve(List<User> users, List<Ride> rides) {
        Map<Integer, Long> totals = new HashMap<>();
        for (Ride ride : rides) {
            totals.merge(ride.userId(), (long) ride.distance(), Long::sum);
        }

        List<Result> answer = new ArrayList<>();
        for (User user : users) {
            answer.add(new Result(user.name(), totals.getOrDefault(user.id(), 0L)));
        }
        answer.sort(Comparator.comparingLong(Result::travelledDistance).reversed()
                .thenComparing(Result::name));
        return answer;
    }
}
    JavaScript ES2022本地语义参考
    function topTravellers(users, rides) {
  const totals = new Map();
  for (const { userId, distance } of rides) {
    totals.set(userId, (totals.get(userId) ?? 0) + distance);
  }

  return users
    .map(({ id, name }) => ({
      name,
      travelledDistance: totals.get(id) ?? 0,
    }))
    .sort((a, b) =>
      b.travelledDistance - a.travelledDistance ||
      a.name.localeCompare(b.name)
    );
}
    Python 3本地语义参考
    from collections import defaultdict
from typing import TypedDict

class User(TypedDict):
    id: int
    name: str

class Ride(TypedDict):
    id: int
    user_id: int
    distance: int

def top_travellers(users: list[User], rides: list[Ride]) -> list[dict]:
    totals: dict[int, int] = defaultdict(int)
    for ride in rides:
        totals[ride["user_id"]] += ride["distance"]

    answer = [
        {"name": user["name"], "travelled_distance": totals[user["id"]]}
        for user in users
    ]
    return sorted(answer, key=lambda row: (-row["travelled_distance"], row["name"]))
    C++17本地语义参考
    #include <algorithm>
#include <string>
#include <unordered_map>
#include <vector>
using namespace std;

struct User { int id; string name; };
struct Ride { int id; int userId; int distance; };
struct Result { string name; long long travelledDistance; };

vector<Result> topTravellers(const vector<User>& users,
                             const vector<Ride>& rides) {
    unordered_map<int, long long> totals;
    for (const auto& ride : rides) totals[ride.userId] += ride.distance;

    vector<Result> answer;
    answer.reserve(users.size());
    for (const auto& user : users) {
        answer.push_back({user.name, totals[user.id]});
    }
    sort(answer.begin(), answer.end(), [](const Result& a, const Result& b) {
        if (a.travelledDistance != b.travelledDistance)
            return a.travelledDistance > b.travelledDistance;
        return a.name < b.name;
    });
    return answer;
}

    替代方案

    可以先在子查询中按 user_id 聚合 Rides，再 LEFT JOIN 到 Users。这样能先压缩明细表，某些数据规模下更清晰或更快：

    SELECT u.name, COALESCE(r.total, 0) AS travelled_distance
FROM Users AS u
LEFT JOIN (
    SELECT user_id, SUM(distance) AS total
    FROM Rides
    GROUP BY user_id
) AS r ON r.user_id = u.id
ORDER BY travelled_distance DESC, u.name ASC;

    面试追问

    为什么不能用 INNER JOIN？

    它会删掉 Donald 这类无行程用户，违反“每个用户”都要报告的要求。

    为何 GROUP BY 带上 id？

    名字未声明唯一；按 id 区分用户更稳妥，同时选出 name。

    能写 SUM(COALESCE(distance, 0)) 吗？

    本题通常也可行，但 COALESCE 包住最终 SUM 更直接表达“空聚合补零”。

    若需要并列名次呢？

    可在聚合结果上使用 DENSE_RANK() OVER (ORDER BY total DESC)，再保留名字排序。

    常见错误

    • 使用 INNER JOIN，漏掉零行程用户。
    • 只按总距离排序，忽略 name 的升序平局规则。
    • 忘记 COALESCE，导致无行程用户显示 NULL。
    • 直接选择 name 却只按 user_id 分组，在严格 SQL 模式下可能报错。
    • 把 WHERE 中对 Rides 的过滤写坏，使 LEFT JOIN 退化成事实上的 INNER JOIN。
