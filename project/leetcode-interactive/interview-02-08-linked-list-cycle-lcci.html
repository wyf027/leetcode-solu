Problem / 题意

返回环路的开头节点

给定一个单链表。如果从某个节点开始沿 next 可以再次回到已访问节点，则链表存在环；请返回环的入口节点。若没有环，返回 null。

测试说明：pos 表示尾节点连接到的下标，只用来描述测试数据，不是 detectCycle 的参数。

示例 3

Solution / 题解

Core Insight / 核心洞察

相遇负责证明有环，等速负责定位入口

阶段一 · 追赶

慢指针每次走 1 步，快指针每次走 2 步。无环时快指针先到 null；有环时两者必在环内相遇。

阶段二 · 对齐

相遇后把一个指针放回头节点，两者都改为每次 1 步；下一次相遇点就是环入口。

为什么成立

设头到入口为 a、入口到相遇点为 b、环长为 L，相遇时可得 a = kL - b，两边等速恰好在入口汇合。

Full Process / 完整过程

面试时可直接复述的五步流程

  1. 初始化：slow = head、fast = head。
  2. 安全推进：仅在 fast != null 且 fast.next != null 时，让慢指针走 1 步、快指针走 2 步。
  3. 判定：如果循环结束仍未相遇，返回 null；否则记录环内相遇节点。
  4. 重置：把慢指针放回 head，快指针留在相遇点，两者都改为每次走 1 步。
  5. 返回入口：两指针再次相等时，当前节点就是环入口。

Boundary / 边界

短链表也必须先守住空指针

空链表 / 单节点无环

快指针无法走两步，直接返回 null。

单节点自环

第一次推进就相遇，重置后立即返回该节点。

入口就是头节点

第二阶段重置后两指针已经相等，直接返回 head。

Complexity / 复杂度

线性时间，常数额外空间

时间复杂度

O(n)

两阶段访问节点总次数仍为线性量级。

空间复杂度

O(1)

只维护两个节点指针。

Alternatives / 替代方案

哈希集合更直观，但不满足进阶空间目标

从头遍历并把节点引用放入集合；首次遇到已存在的节点时，它就是入口。时间也是 O(n)，但需要 O(n) 额外空间。它适合作为对拍基准，不是面试最推荐答案。

Interview Follow-ups / 面试追问

从入口继续追问环长与证明

如何求环长？

相遇后固定一个指针，另一个沿环走一圈并计数，回到相遇点时计数即环长。

为什么比较引用而不是值？

不同节点可能拥有相同值，只有节点对象身份相同才表示真正相遇。

能修改节点吗？

不应修改值或 next 做标记；这会破坏输入，也可能与业务值冲突。

Common Mistakes / 常见错误

四个高频失分点

  • 把 pos 当作函数参数使用，忽略真实链表结构。
  • 访问 fast.next.next 前没有检查 fast 与 fast.next。
  • 第一阶段相遇后直接返回相遇点；相遇点通常不是入口。
  • 比较节点值而不是节点引用，遇到重复值会误判。

public class Solution {
    public ListNode detectCycle(ListNode head) {
        ListNode slow = head;
        ListNode fast = head;

        while (fast != null && fast.next != null) {
            slow = slow.next;
            fast = fast.next.next;

            if (slow == fast) {
                slow = head;
                while (slow != fast) {
                    slow = slow.next;
                    fast = fast.next;
                }
                return slow;
            }
        }
        return null;
    }
}
