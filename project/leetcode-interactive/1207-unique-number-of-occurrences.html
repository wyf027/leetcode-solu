Unique Number of Occurrences

独一无二的
出现次数

有些数字反复出现，但它们各自出现的次数能否彼此不同？这道题要判断的不是元素是否重复，而是“重复的规模”是否重复。

先想一想： 如果两个不同的值都出现了 2 次，你需要用什么信息才能尽早发现冲突？
01 / Problem

题目要求

给定一个整数数组 arr。统计每个不同整数在数组中的出现次数；如果这些次数两两不同，返回 true，否则返回 false。

函数签名：uniqueOccurrences(arr)，参数为整数数组，返回布尔值。

约束
  • 1 <= arr.length <= 1000
  • -1000 <= arr[i] <= 1000
EXAMPLE 01
输入：arr = [1,2,2,1,1,3]
输出：true
解释：1、2、3 分别出现 3、2、1 次，次数互不相同。
EXAMPLE 02
输入：arr = [1,2]
输出：false
解释：1 和 2 都出现 1 次，次数发生重复。
EXAMPLE 03
输入：arr = [-3,0,1,-3,1,1,1,-3,10,0]
输出：true
解释：-3、0、1、10 分别出现 3、2、4、1 次。

03 / Solution

双哈希：值去重，次数也去重

第一张表回答“每个值出现几次”，第二个集合回答“这个次数以前是否出现过”。一旦某个次数无法加入集合，答案立即确定为 false。

01

统计频次

遍历 arr，用哈希表记录 value → count。

02

检查唯一

遍历全部 count，把它们依次放入哈希集合。

03

发现冲突

集合已含当前次数，说明至少两个不同值出现次数相同。

完整过程

  1. 创建空频次表 frequency。
  2. 逐个读取数组元素，把对应频次加一。
  3. 创建空集合 seen，遍历频次表中的所有次数。
  4. 若 seen 已包含当前次数，返回 false；否则加入。
  5. 全部次数都能成功加入时，返回 true。

正确性说明

频次表准确保存每个不同值的出现次数。检查第 k 个次数前，集合恰好包含前 k-1 个次数：若当前次数已存在，就构造出一对频次相同的不同值；若从未重复，则所有频次两两不同。因此算法返回值与题意完全一致。

循环不变量：集合中始终只保存已经检查过、且彼此不同的次数。

复杂度

时间 O(n)：统计数组一次，再检查至多 n 个不同值。

空间 O(n)：频次表与集合最坏保存所有不同元素。

边界情况

  • 只有一个元素：仅有频次 1，结果为 true。
  • 所有元素相同：仅有一种频次，结果为 true。
  • 所有元素不同且至少两个：多个值的频次都是 1，结果为 false。
  • 负数与 0：哈希键照常工作，不需要特殊处理。

四语言完整代码

import java.util.HashMap;
import java.util.HashSet;
import java.util.Map;
import java.util.Set;

class Solution {
    public boolean uniqueOccurrences(int[] arr) {
        Map<Integer, Integer> frequency = new HashMap<>();
        for (int value : arr) {
            frequency.put(value, frequency.getOrDefault(value, 0) + 1);
        }

        Set<Integer> seen = new HashSet<>();
        for (int count : frequency.values()) {
            if (!seen.add(count)) {
                return false;
            }
        }
        return true;
    }
}

var uniqueOccurrences = function(arr) {
    const frequency = new Map();
    for (const value of arr) {
        frequency.set(value, (frequency.get(value) || 0) + 1);
    }

    const seen = new Set();
    for (const count of frequency.values()) {
        if (seen.has(count)) {
            return false;
        }
        seen.add(count);
    }
    return true;
};
from collections import Counter
from typing import List


class Solution:
    def uniqueOccurrences(self, arr: List[int]) -> bool:
        frequency = Counter(arr)
        seen = set()

        for count in frequency.values():
            if count in seen:
                return False
            seen.add(count)

        return True
#include <unordered_map>
#include <unordered_set>
#include <vector>
using namespace std;

class Solution {
public:
    bool uniqueOccurrences(vector<int>& arr) {
        unordered_map<int, int> frequency;
        for (int value : arr) {
            ++frequency[value];
        }

        unordered_set<int> seen;
        for (const auto& entry : frequency) {
            int count = entry.second;
            if (!seen.insert(count).second) {
                return false;
            }
        }
        return true;
    }
};

替代方案

排序频次：统计后把所有频次放入数组并排序，再检查相邻项。逻辑直观，时间为 O(n + k log k)，其中 k 是不同值个数。

定长计数数组：因为值域仅为 [-1000, 1000]，可以用长度 2001 的数组代替频次哈希表；可读性与通用性略弱，但常数稳定。

面试追问

  • 如果数据以流的形式持续到达，如何支持动态查询？
  • 若内存受限但输入已排序，能否减少第一阶段的空间？
  • 为什么只比较集合大小与频次表大小也能得出结论？
  • 哈希碰撞会不会破坏算法的逻辑正确性？

常见错误

  • 检查的是“数组元素是否唯一”，而不是“元素的出现次数是否唯一”。
  • 用集合收集数组元素，得到的只是不同值数量，丢失了频次。
  • 遇到重复次数后仍继续遍历；虽然结果不一定错，但错过了提前返回。
  • 用对象实现 JavaScript 计数时忘记处理尚不存在的键；使用 Map 可让意图更清晰。
