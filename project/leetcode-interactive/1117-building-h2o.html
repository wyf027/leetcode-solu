LEETCODE 1117 · CONCURRENCY

H₂O 生成

用同步屏障将任意到达的线程组织成完整水分子。

MEDIUM · 多线程

题目

系统以任意顺序启动氢线程与氧线程。请实现 H2O，使 hydrogen(releaseHydrogen) 与 oxygen(releaseOxygen) 的回调按完整分子分批执行。

将输出每 3 个字符分组，每组必须恰有 2 个 H 和 1 个 O；组内顺序不限，但下一分子不能穿插进当前分子。

官方参数形式

H2O()
hydrogen(releaseHydrogen) // 回调输出 "H"
oxygen(releaseOxygen)     // 回调输出 "O"

示例与约束

示例 1
输入：water = "HOH"
输出："HHO"
说明："HOH"、"OHH" 也有效。

示例 2
输入：water = "OOHHHH"
输出："HHOHHO"
说明：任何连续三字符均为 2H + 1O 的排列都有效。
  • 3 * n == water.length
  • 1 <= n <= 20
  • water[i] 是 'H' 或 'O'
  • H 恰有 2*n 个，O 恰有 n 个

题解：元素配额 + 批次交接

核心洞察

每批只发放两个 H 许可；第二个 H 输出后开放一个 O 许可。O 输出完成才重新发放两个 H 许可。这样每轮天然是两氢一氧，且下一轮无法穿插。

完整过程

  1. H 信号量初值 2，O 初值 0。
  2. 每条 H 取得许可、输出，并向 O 贡献一次到达信号。
  3. O 必须取得两次到达信号，才输出并归还两个 H 许可。
  4. 循环形成严格、不交叉的分子批次。

正确性

O 需要两个 H 信号，因此每次 O 输出前已有且仅有两个 H 输出；H 许可在 O 输出后才恢复，所以第三个 H 或下一批 O 均不能提前执行。归纳每一批，输出按三字符切分必为 2H + 1O。

边界与复杂度

最小一个分子以及全部同类线程先到都只会等待，不影响配比。每线程常数次同步操作，总工作量 O(n)，共享空间 O(1)。

完整代码

Java、Python、C++ 对应官方提交语言；JavaScript 为本地异步语义参考，非本题官方提交语言。

import java.util.concurrent.Semaphore;
class H2O {
    private final Semaphore h = new Semaphore(2);
    private final Semaphore o = new Semaphore(0);
    public H2O() {}
    public void hydrogen(Runnable releaseHydrogen) throws InterruptedException {
        h.acquire(); releaseHydrogen.run(); o.release();
    }
    public void oxygen(Runnable releaseOxygen) throws InterruptedException {
        o.acquire(2); releaseOxygen.run(); h.release(2);
    }
}
// 本地异步语义参考
class Semaphore {
  constructor(n) { this.n=n; this.q=[]; }
  acquire() { return this.n ? (this.n--,Promise.resolve()) : new Promise(r=>this.q.push(r)); }
  release(n=1) { while(n--) this.q.length ? this.q.shift()() : this.n++; }
}
class H2O {
  constructor(){ this.h=new Semaphore(2); this.o=new Semaphore(0); }
  async hydrogen(out){ await this.h.acquire(); out(); this.o.release(); }
  async oxygen(out){ await this.o.acquire(); await this.o.acquire(); out(); this.h.release(2); }
}
from threading import Semaphore
class H2O:
    def __init__(self):
        self.h, self.o = Semaphore(2), Semaphore(0)
    def hydrogen(self, releaseHydrogen: 'Callable[[], None]') -> None:
        self.h.acquire(); releaseHydrogen(); self.o.release()
    def oxygen(self, releaseOxygen: 'Callable[[], None]') -> None:
        self.o.acquire(); self.o.acquire(); releaseOxygen()
        self.h.release(); self.h.release()
#include <condition_variable>
#include <functional>
#include <mutex>
using namespace std;
class H2O {
    mutex m; condition_variable cv; int h=0;
public:
    H2O() {}
    void hydrogen(function<void()> out) {
        unique_lock<mutex> g(m); cv.wait(g,[&]{return h<2;});
        out(); if(++h==2) cv.notify_all();
    }
    void oxygen(function<void()> out) {
        unique_lock<mutex> g(m); cv.wait(g,[&]{return h==2;});
        out(); h=0; cv.notify_all();
    }
};

替代方案

可用两个信号量配合 CyclicBarrier(3)；也可用互斥锁、条件变量与计数器显式建模。前者结构对称，后者更易控制输出顺序。

常见错误

  • 只统计总数，未阻止不同分子交叉。
  • 过早归还许可，让下一批提前输出。
  • 认为只能输出 HHO；HOH 与 OHH 也合法。
  • 无锁读写计数器，产生竞态或死锁。
