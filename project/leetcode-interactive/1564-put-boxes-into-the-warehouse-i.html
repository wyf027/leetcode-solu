Problem

题目描述

给你两组高度：若干箱子，以及从左到右排列的仓库房间。目标是在遵守入口与通行规则的前提下，放入尽可能多的箱子。

返回 integer

场景与规则

  • boxes[i] 是第 i 个箱子的高度；箱子的摆放顺序可以任意调整。
  • warehouse[j] 是从左到右第 j 个房间的高度，每个房间最多放一个箱子。
  • 所有箱子只能从仓库左侧推入。箱子要到达某个房间，必须能通过入口到该房间之间的所有房间。
  • 箱子一旦放入某个房间，就不能再移动。请返回最多能放入的箱子数。

函数签名与约束

maxBoxesInWarehouse(boxes, warehouse) → integer

  • 1 ≤ boxes.length, warehouse.length ≤ 10⁵
  • 1 ≤ boxes[i], warehouse[i] ≤ 10⁹
  • 数组元素均为整数。

Greedy Solution

前缀瓶颈 + 双指针

先把仓库的“可达高度”显式化，再让最小的箱子优先争取最深的房间。

核心洞察

房间本身再高也不代表箱子能到达：到达 warehouse[i] 前必须穿过所有更靠左的房间。因此第 i 个位置真正能接纳的最大高度是前缀最小值 min(warehouse[0...i])。这个有效高度从左到右单调不增。

完整过程

压低仓库

从左到右，把每个房间高度更新为它与前一有效高度的较小值。

箱子升序排序

先处理最矮箱子，避免高箱子抢占只有矮箱子才能深入的位置。

从最深房间向入口扫描

当前最小箱子能放入就匹配并换下一个箱子；放不下则跳过这个房间，继续向左。

返回匹配数

箱子用完或房间扫描完时，成功匹配数量就是答案。

正确性说明

引理 1：前缀最小值恰好是每个房间的最大可达箱高。因为箱子必须通过路径上的每个房间；高度不超过最小者时也一定能够通过。

引理 2：处理当前最深房间时，若最小未用箱子都放不下，则其他箱子更高，也都放不下，跳过该房间不会损失可行解。

引理 3：若最小箱子能放入当前最深房间，把它放入不会减少最优数量。任一最优方案中，若该房间放了更高箱子，可用当前最小箱子替换；被替换箱子保留给更靠左且有效高度不小的房间。

结论：每一步匹配或跳过都有最优解与之相容，归纳可得算法返回最大可放箱子数。

复杂度

设箱子数为 n、房间数为 m。

  • 时间：O(n log n + m)
  • 额外空间：取决于排序实现，通常为 O(log n) 到 O(n)
  • 仓库前缀最小值可原地更新

边界情况

  • 入口最低：后方高房间也无法发挥高度。
  • 所有箱子都太高：答案为 0。
  • 箱子或房间先耗尽：立即结束。
  • 高度相等：允许放入。
  • 重复高度：排序与双指针无需特殊处理。

替代方案

可以从左到右维护前缀最小值后，将有效房高排序，再用双指针匹配；同样正确，但多做了一次对仓库的排序，时间变为 O(n log n + m log m)。也可用多重集合为每个房间找可放的箱子，但实现更复杂。

import java.util.Arrays;

class Solution {
    public int maxBoxesInWarehouse(int[] boxes, int[] warehouse) {
        Arrays.sort(boxes);

        for (int i = 1; i < warehouse.length; i++) {
            warehouse[i] = Math.min(warehouse[i], warehouse[i - 1]);
        }

        int box = 0;
        for (int room = warehouse.length - 1;
             room >= 0 && box < boxes.length;
             room--) {
            if (boxes[box] <= warehouse[room]) {
                box++;
            }
        }
        return box;
    }
}

from typing import List


class Solution:
    def maxBoxesInWarehouse(
        self, boxes: List[int], warehouse: List[int]
    ) -> int:
        boxes.sort()

        for i in range(1, len(warehouse)):
            warehouse[i] = min(warehouse[i], warehouse[i - 1])

        box = 0
        for room in range(len(warehouse) - 1, -1, -1):
            if box == len(boxes):
                break
            if boxes[box] <= warehouse[room]:
                box += 1

        return box

class Solution {

        sort(boxes.begin(), boxes.end());

            warehouse[i] = min(warehouse[i], warehouse[i - 1]);
        }

        for (int room = static_cast<int>(warehouse.size()) - 1;
             room >= 0 && box < static_cast<int>(boxes.size());
             --room) {

                ++box;
            }
        }
        return box;
    }

常见错误

  • 只比较箱子和目标房间，忽略途中更低的房间。
  • 从入口向深处贪心，过早堵住房间。
  • 优先放最高箱子，使深处容量被浪费。
  • 把“严格小于”写成条件；高度相等其实可以放入。
  • 完成匹配后仍访问已越界的箱子下标。

面试追问

  • 为什么一定要从最深的房间开始安排？
  • 能否不修改输入数组？需要多少额外空间？
  • 若箱子也能从仓库右侧进入，策略会如何变化？
  • 若房间可以放多个箱子，问题会变成什么模型？
  • 如何输出具体的“箱子 → 房间”配对，而不只返回数量？
