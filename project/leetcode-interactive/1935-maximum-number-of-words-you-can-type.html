Maximum Number of Words You Can Type

01题目与输入

键盘上的部分小写字母键坏了，其他按键均可正常使用。给定一段文本 text 和损坏字母串 brokenLetters，返回文本中能被完整输入的单词数量。每次出现的单词分别计数；包含坏键的单词无法完整输入。

函数：canBeTypedWords(text, brokenLetters) → integer
text：待输入的字符串；brokenLetters：互不重复的坏键字母字符串；返回值：可完整输入的单词个数。

官方示例 1

text = "hello world"
brokenLetters = "ad"
输出：1

hello 可输入；world 中的 d 键损坏。

官方示例 2

text = "leet code"
brokenLetters = "lt"
输出：1

leet 需要损坏的 l、t 键，只有 code 可输入。

官方示例 3

text = "leet code"
brokenLetters = "e"
输出：0

两个单词都需要 e 键，均无法完整输入。

约束

  • 1 ≤ text.length ≤ 10⁴。
  • 0 ≤ brokenLetters.length ≤ 26。
  • 单词之间恰有一个空格，文本没有前导或尾随空格。
  • 每个单词仅包含小写英文字母。
  • brokenLetters 仅包含互不相同的小写英文字母，允许为空。

04独立题解

准备好后展开思路、证明与四语言代码。

核心洞察：只记住当前单词是否碰过坏键

一个单词可输入，当且仅当它的每个字母都不在坏键集合中。用 ok 表示当前单词仍可输入；遇到坏键后置为 false，在当前单词结束前都不能恢复。遇到空格或文本结尾时，若 ok 为真，答案加一，然后重置状态。

完整过程

  1. 将 brokenLetters 存入集合或长度为 26 的布尔表。
  2. 初始化 answer = 0、ok = true。
  3. 从左到右扫描字符。普通字母若命中坏键，将 ok 置为假。
  4. 遇到空格时结算当前单词：仅当 ok 为真才加一，再将 ok 设为真。
  5. 将索引等于文本长度的位置当作结束边界，再结算最后一个单词。这个边界不是输入里的字符，也不创建额外字符串。

以 text = "hello world", brokenLetters = "ad" 为例：扫描 hello 时没有命中坏键，在空格处计数变成 1；扫描 world 时 d 使状态变为不可输入，末尾结算不加一，返回 1。

为什么正确

循环不变式：处理当前单词的任意前缀后，ok 为真当且仅当该前缀没有坏键；answer 等于已结束单词中可完整输入的数量。开始时前缀为空、计数为零，不变式成立。普通好键不改变状态，坏键令状态永久变假，因此保持前缀判断准确。边界处前缀恰为整个单词，按 ok 计数正好判定该单词，再重置进入下一个单词。末尾边界确保所有单词都被结算一次，返回值因此正确。

边界与常见错误

  • 坏键集合为空：每个单词都计数；不是返回字符数。
  • 所有字母键都坏：没有任何非空单词可以输入。
  • 同一坏键在单词中出现多次：这个单词只被拒绝一次，不应反复扣减答案。
  • 不要写成 ok = !broken.has(c)：后续好字母会错误覆盖之前的失败状态。
  • 空格之后必须重置 ok；最后没有空格也必须结算。
  • 重复单词按出现次数计数，不能把文本单词去重。
  • 题目保证不存在连续空格或两端空格；通用文本版本需额外跟踪当前单词是否非空。

复杂度

设 n = text.length、b = brokenLetters.length。建坏键表 O(b)，扫描 O(n)，总时间 O(n + b)。字符集固定为 26 个字母，额外空间 O(26) = O(1)。下方实现没有按空格拆分文本。页面为了前后回放保存 O(n) 个演示状态，这不属于提交算法的空间消耗。

替代方案

按空格拆分，然后逐词检查是否有字母命中集合，代码直观，但分词结果通常占 O(n) 额外空间。也可用 26 位整数位掩码记录坏键，通过按位与判断；同样是线性扫描，本题规模下集合或布尔表更易读。

四语言完整代码

均采用官方函数签名；代码仅生成，尚未执行或提交验证。遇到文本末尾时使用短路逻辑，避免越界访问。

Java

class Solution {
    public int canBeTypedWords(String text, String brokenLetters) {
        boolean[] broken = new boolean[26];
        for (int i = 0; i < brokenLetters.length(); i++) {
            broken[brokenLetters.charAt(i) - 'a'] = true;
        }
        int answer = 0;
        boolean ok = true;
        for (int i = 0; i <= text.length(); i++) {
            if (i == text.length() || text.charAt(i) == ' ') {
                if (ok) answer++;
                ok = true;
            } else if (broken[text.charAt(i) - 'a']) {
                ok = false;
            }
        }
        return answer;
    }
}

JavaScript

/**
 * @param {string} text
 * @param {string} brokenLetters
 * @return {number}
 */
var canBeTypedWords = function(text, brokenLetters) {
    const broken = new Set(brokenLetters);
    let answer = 0;
    let ok = true;
    for (let i = 0; i <= text.length; i++) {
        if (i === text.length || text[i] === ' ') {
            if (ok) answer++;
            ok = true;
        } else if (broken.has(text[i])) {
            ok = false;
        }
    }
    return answer;
};

C++

#include <string>
using namespace std;

class Solution {
public:
    int canBeTypedWords(string text, string brokenLetters) {
        bool broken[26] = {};
        for (char c : brokenLetters) broken[c - 'a'] = true;
        int answer = 0;
        bool ok = true;
        const int n = static_cast<int>(text.size());
        for (int i = 0; i <= n; i++) {
            if (i == n || text[i] == ' ') {
                if (ok) ++answer;
                ok = true;
            } else if (broken[text[i] - 'a']) {
                ok = false;
            }
        }
        return answer;
    }
};

面试追问

  • 输入来自字符流怎么办？保留坏键表、当前单词状态和计数；读到空格或流结束时结算，无需保存整个文本。
  • 支持大小写或 Unicode 呢？先明确大小写是否等价，以及“按键”对应码点还是字素簇，再选择归一化与遍历方式，不能直接沿用 26 位映射。
  • 同一文本有大量不同坏键查询呢？可预计算每个单词的字母位掩码，每次查询用按位与判断。重复单词的掩码可以聚合频次，仍按出现次数累加。
  • 一个单词已经失败，还要读后面的字符吗？仍须找到单词边界，但可以跳过进一步的坏键查找；渐进复杂度仍为 O(n)。
