所有子序列和的按位或

Bitwise OR of All Subsequence Sums

一个数组，许多种选择。把每种选择的和写成二进制：哪些位曾经亮起？

01 / 题目

给定非负整数数组 nums。对它的每个子序列先计算元素之和，再把这些和全部做按位或（OR），返回最终整数。

子序列可以跳过任意位置，但保留的元素仍按原顺序排列，不要求连续。空子序列的和为 0，是否把它计入都不改变答案。这里是“先求和，再按位或”。

subsequenceSumOr(nums: integer[]) → long

官方示例 1

输入：nums = [2,1,0,3]
输出：7

可能的不同子序列和为 0、1、2、3、4、5、6。把它们按位或，得到 7。

官方示例 2

输入：nums = [0,0,0]
输出：0

所有选择的和都是 0，因此结果也是 0。

约束

  • 1 ≤ nums.length ≤ 105
  • 0 ≤ nums[i] ≤ 109

04 / 独立题解

核心洞察、交互推演与四语言代码

核心洞察：单元素与每个前缀就够了

从左向右遍历，维护前缀和 prefix 和答案 ans。读到 x 时，先让 prefix += x，再让 ans |= x | prefix。每个元素自身及每个前缀都是真实子序列，它们的和提供了需要的全部位。

前缀和会进位，甚至暂时清掉低位；累计 OR 会把曾经出现过的位留下。单元素则补足前缀可能错过的位，例如 [1,3] 的前缀为 1、4，仅看前缀得到 5，而正确结果是 7。

交互 / 二进制位的“记忆板”

绿色表示该位为 1，金色双边框表示本步首次记录的位。每次前进一步处理一个元素。

使用英文逗号或空格分隔，可带方括号。此长度限制仅用于教学界面。

Tab 切换控件，Enter / 空格激活按钮；减少动态效果偏好下，自动播放以较慢的离散步骤更新。

完整过程

  1. 初始化 prefix = 0、ans = 0。
  2. 读入当前元素并更新前缀和。
  3. 将当前元素的位与更新后前缀和的位合并进答案。
  4. 遍历结束，返回累计答案，无须保存子序列或前缀数组。

对 [2,1,0,3]，前缀和依次为 2,3,3,6，累计答案依次为 2,3,3,7。最后一步的 6 为 110₂，已有答案 3 为 011₂，合并为 111₂ = 7。

正确性：逐位证明，不靠“前缀覆盖全部和”

不会多算：算法合并的每个值都是单元素和或前缀和，都是合法子序列和，因此不会引入真正答案以外的位。

不会漏算：固定第 k 位。如果某个元素该位为 1，合并单元素就能记录它。否则所有元素该位均为 0，记每个元素的低 k 位数值为 rᵢ = nums[i] mod 2ᵏ，于是 0 ≤ rᵢ < 2ᵏ；更高位都是 2ᵏ⁺¹ 的倍数，不影响第 k 位。

如果某个子序列和的第 k 位为 1，其低位贡献的和至少为 2ᵏ。所有 rᵢ 非负，所以整个数组的低位贡献总和也至少为 2ᵏ。找到低位贡献累计和第一次达到 2ᵏ 的前缀：此前小于 2ᵏ，本次增加小于 2ᵏ，因此此刻累计值落在 [2ᵏ, 2ᵏ⁺¹)，这个真实前缀和的第 k 位必为 1，算法会记录它。k = 0 时所有低位贡献为 0，第二种情况不可能发生。

两种情形涵盖所有可出现的位，结合不会多算，得到答案恰好等于所有子序列和的 OR。

边界与复杂度

  • 全零返回 0；单元素返回自身；重复元素不能去重，因为重复选择能产生新的进位。
  • 非负条件是证明的关键。若允许负数，低位贡献跨越阈值的论证与固定宽度符号位需重新处理。
  • 总和最多 10¹⁴，小于 2⁴⁷；答案也小于 2⁴⁷。Java 使用 long，C++ 使用 long long，Python 整数无需另选类型。
  • JavaScript 的 Number 位运算会截为 32 位，必须以 BigInt 做累加与按位或。结果小于 2⁴⁷，返回时可安全转为 Number。
  • 在本题固定整数范围下，时间 O(n)，额外空间 O(1)。若推广至任意 B 位大整数，位运算成本需计入，约为 O(nB) 时间、O(B) 位空间。

四语言完整代码

按官方方法名与数组参数编写，无主程序；未编译、未提交。算法写法参考 walkccc 作者实现，下列版本统一保留 64 位或等效整数语义。

Java

class Solution {
    public long subsequenceSumOr(int[] nums) {
        long prefix = 0L;
        long ans = 0L;
        for (int x : nums) {
            prefix += x;
            ans |= (long) x | prefix;
        }
        return ans;
    }
}

JavaScript

/**
 * @param {number[]} nums
 * @return {number}
 */
var subsequenceSumOr = function(nums) {
    let prefix = 0n;
    let ans = 0n;
    for (const value of nums) {
        const x = BigInt(value);
        prefix += x;
        ans |= x | prefix;
    }
    return Number(ans);
};

替代方案

  • 枚举子序列：递归选择或跳过，维护和与全局 OR，时间 O(2ⁿ)、递归空间 O(n)。只适用于极小输入。
  • 可达和动态规划：按每个元素扩展可达和，朴素时间 O(nS)、空间 O(S)，S 是总和。本题 S 可达 10¹⁴，不实用。
  • 逐位累计进位：统计每一位的 1 数量，从低位向高位处理；当前计数大于 0 就记录该位，并将计数除以 2 的商传向更高位。这体现相同的低位累加跨阈值机制，时间 O(nB)、空间 O(B)，B 需覆盖总和位宽。本题前缀方法更简洁。

常见错误

  • 只 OR 原数组会遗漏进位：[2,2] 应为 6，不是 2。
  • 只 OR 前缀会漏单元素的位：[1,3] 应为 7，不是 5。
  • 只 OR 总和与元素也不够：[1,1,1,1] 会错误得到 5，中途出现的第 1 位丢失。
  • 把最高位以下全部填 1：[8] 的答案是 8，不是 15。
  • 把子序列理解为连续子数组，或者先将元素 OR 再求和，都会改变问题。
  • 用 32 位累计和，或在 JavaScript 中将 Number 直接用于 |，会丢失高位。

面试追问

  • 打乱输入会改变答案吗？不会。每种索引子集仍然可以按新顺序构成子序列，和不变；中途轨迹可以不同，最终 OR 相同。
  • 能在线处理吗？可以。持续保存 prefix、ans，追加一个非负数只需一次更新。
  • 为什么不是所有整数都可达？算法只保证位覆盖，例如 [2,2] 只有 0、2、4 可达，但 OR 为 6。
  • 如何扩展到超大整数？各语言改用大整数，保留相同逻辑，并按位宽重新描述复杂度。
