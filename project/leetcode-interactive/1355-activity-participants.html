活动参与者
Activity Participants

一次关于“中间值”的聚合查询：统计每项活动的参与人数，排除人数最多和最少的活动，返回剩余活动。

MEDIUM付费题SQL / Database题号 1355
Problem

题意与数据结构

有一张活动清单 Activities，以及记录朋友参加哪项活动的 Friends。请返回参与人数既不是所有活动中的最大值、也不是最小值的活动名称。结果顺序不限。

比较的是每个活动的参与人数；若多个活动并列最少或并列最多，它们都属于极值，均应排除。

约束与字段

  • Friends.id 标识一位朋友，activity 是其参加的活动。
  • Activities.id 标识活动，name 是活动名称。
  • 字段类型来自官方元数据：整数 ID，名称与活动字段均为 VARCHAR(30)。
  • 输出仅包含符合条件的 activity；顺序不限。

Solution

完整题解

核心洞察真正参与比较的不是原始行，而是 GROUP BY activity 产生的计数集合。答案恰好满足 min_count < cnt < max_count。
一句话方法先用公共表表达式得到每项活动的人数，再从同一份计数结果中取得最小值和最大值，筛掉两端。

完整过程

  1. 按 Friends.activity 分组，对每组执行 COUNT(*)。
  2. 在计数集合中求 MIN(cnt) 和 MAX(cnt)。
  3. 仅保留计数严格大于最小值且严格小于最大值的活动。
  4. 投影活动名称列，得到最终结果；输出顺序不影响正确性。

官方提交语言：MySQL

WITH activity_counts AS (
    SELECT activity, COUNT(*) AS participant_count
    FROM Friends
    GROUP BY activity
)
SELECT activity
FROM activity_counts
WHERE participant_count > (SELECT MIN(participant_count) FROM activity_counts)
  AND participant_count < (SELECT MAX(participant_count) FROM activity_counts);

本题是数据库题，LeetCode 正式提交应使用 SQL。以下四份代码是对同一算法的完整本地语义实现，不冒充官方可提交答案。

import java.util.*;

public class ActivityParticipants {
    public static List<String> middleActivities(List<String> activities) {
        Map<String, Integer> counts = new LinkedHashMap<>();
        for (String activity : activities) {
            counts.merge(activity, 1, Integer::sum);
        }
        if (counts.isEmpty()) return new ArrayList<>();

        int minCount = Collections.min(counts.values());
        int maxCount = Collections.max(counts.values());
        List<String> answer = new ArrayList<>();
        for (Map.Entry<String, Integer> entry : counts.entrySet()) {
            int count = entry.getValue();
            if (count > minCount && count < maxCount) {
                answer.add(entry.getKey());
            }
        }
        return answer;
    }
}
function middleActivities(activities) {
  const counts = new Map();
  for (const activity of activities) {
    counts.set(activity, (counts.get(activity) ?? 0) + 1);
  }
  if (counts.size === 0) return [];

  const values = [...counts.values()];
  const minCount = Math.min(...values);
  const maxCount = Math.max(...values);
  return [...counts]
    .filter(([, count]) => count > minCount && count < maxCount)
    .map(([activity]) => activity);
}
from collections import Counter
from typing import List


def middle_activities(activities: List[str]) -> List[str]:
    counts = Counter(activities)
    if not counts:
        return []

    min_count = min(counts.values())
    max_count = max(counts.values())
    return [
        activity
        for activity, count in counts.items()
        if min_count < count < max_count
    ]
#include <algorithm>
#include <limits>
#include <string>
#include <unordered_map>
#include <vector>
using namespace std;

vector<string> middleActivities(const vector<string>& activities) {
    unordered_map<string, int> counts;
    for (const string& activity : activities) ++counts[activity];
    if (counts.empty()) return {};

    int minCount = numeric_limits<int>::max();
    int maxCount = numeric_limits<int>::min();
    for (const auto& [activity, count] : counts) {
        minCount = min(minCount, count);
        maxCount = max(maxCount, count);
    }

    vector<string> answer;
    for (const auto& [activity, count] : counts) {
        if (count > minCount && count < maxCount) {
            answer.push_back(activity);
        }
    }
    return answer;
}

正确性说明

计数 CTE 为每个出现的活动生成且只生成一行，其 participant_count 等于该活动参与人数。两个子查询分别得到全体计数的最小值和最大值。WHERE 的两个严格不等式当且仅当一个计数不是两端极值时成立，因此结果恰好包含题目要求的全部活动，且不包含其他活动。

复杂度

设 Friends 有 n 行、不同活动有 k 个。概念上分组扫描为 O(n)，极值与过滤为 O(k)，额外空间为 O(k)。数据库实际代价取决于执行计划、索引和分组实现。

边界情况

  • 所有活动人数相同：最小值等于最大值，答案为空。
  • 只有两个不同人数层级：两层都是极值，答案为空。
  • 最少或最多并列：严格不等式会排除所有并列极值。
  • 若活动清单包含无人参加的活动，需先明确是否应计为 0；官方样例与常见题意按 Friends 中出现的活动聚合。

替代方案

可用窗口函数在分组结果上计算 MIN(COUNT(*)) OVER () 与 MAX(COUNT(*)) OVER ()，再在外层过滤。它只写一次逻辑扫描，但语法对数据库版本要求更高；CTE 版本通常更易读。

面试追问

为什么不能直接在 HAVING 中写 count 不等于某个固定值？极值由当前数据动态决定，必须从聚合后的计数集合中计算。
如果需要包含零参与者的活动怎么办？从 Activities 左连接 Friends，再按活动分组并使用 COUNT(Friends.id)，这样无人参与时计数为 0。
为什么用严格大于和严格小于？它自然覆盖并列极值；所有达到最小值或最大值的活动都会被排除。

常见错误

  • 对原始 Friends 行直接求 MIN/MAX，而不是对分组后的计数求极值。
  • 只排除一个最大活动和一个最小活动，遗漏并列极值。
  • 使用 >= 或 <=，错误保留边界。
  • 在需要统计零参与者时使用内连接或 COUNT(*)，导致计数含义变化。
