让数组像一排地形一样逐日趋于平缓。先读规则、亲手观察每一天的变化，再决定是否展开底部题解。

Problem

题目说明

函数：transformArray(arr)

给定一个整数数组 arr。每天同时检查所有非首尾元素，并严格依据它与当天左右相邻元素的大小关系更新；数组的第一个与最后一个元素始终不变。

  • ＋若 arr[i] 严格小于左右两个相邻元素，第二天将它增加 1。
  • −若 arr[i] 严格大于左右两个相邻元素，第二天将它减少 1。
  • ＝其他元素保持不变。重复上述过程，直到完整的一天没有任何元素发生变化，返回此时的数组。

同时更新：某一天所有判断都必须基于同一个旧数组，不能让先更新的元素影响当日后续判断。

Signature

参数形式

输入arr: integer[]待变换的整数数组
返回list<integer>达到稳定状态后的数组

首尾元素是固定边界；“严格大于 / 小于”意味着相等时不变化。

Examples & Constraints

示例与约束

输入arr = [6, 2, 3, 4]
输出[6, 3, 3, 4]
过程2 同时小于 6 和 3，增加一次后数组稳定。

示例 2

输出[1, 4, 4, 4, 4, 5]

  • 1 ≤ arr[i] ≤ 100

Solution

同步模拟，直到稳定

核心洞察

题目的规则已经直接给出了状态转移。关键不是寻找复杂公式，而是保留“昨天”的快照，用它一次性计算“今天”的每个位置。若一轮没有任何变化，就到达固定点。

读取旧数组，写入新数组：这两个角色在一轮内绝不能混用。

完整过程

  1. 复制当前数组作为下一天结果，首尾自然保持不变。
  2. 遍历下标 1 到 n - 2。
  3. 用当前数组的左右邻居判断谷底或山峰，并在副本中执行 +1 或 -1。
  4. 若本轮有变化，以副本替换当前数组并继续；否则返回。

正确性说明

单轮正确：对任意内部位置，算法只读取轮次开始时的数组，所以它执行的变化与题目要求的同步变化完全一致；首尾不被遍历，因此保持不变。

整体正确：每完成一轮，算法得到的正是题目定义的下一天数组。循环按天重复，直到一轮无变化；此时所有位置都不再满足变化条件，返回值恰为题目要求的稳定数组。

边界与复杂度

  • 首尾元素从不参与更新。
  • 等于任意一侧邻居时，不满足“严格”条件。
  • 长度为 3 时也按同一逻辑，只检查中间一个元素。
时间O(D · n)D 为发生模拟的天数
额外空间O(n)保存下一轮快照

替代方案

可以原地维护额外的变化标记，或用两个数组来回交换以减少重复分配；渐进空间仍为 O(n)。尝试单数组从左到右直接改值会破坏同步语义，除非另存上一轮所需信息，复杂度与出错风险都更高。

面试追问

  • 为什么循环一定会停止？可从值始终受初始最小值与最大值约束、状态逐步消除严格局部极值来说明。
  • 如何返回每一天的历史？在每轮结束后保存副本即可，空间变为 O(D · n)。
  • 若更新步长从 1 改为 k，会出现什么终止与振荡问题？

Pitfalls

常见错误

边遍历边覆盖

这会让右侧位置看到“今天已修改”的左邻居，结果不再是题目要求的同步更新。

把严格比较写成包含等于

<= 或 >= 会错误改变平台位置，甚至让稳定条件失真。

忘记稳定检测

只执行固定一轮无法覆盖第二个示例；应记录本轮是否有任何变化。

误改首尾元素

遍历范围必须从 1 开始，并在 n - 2 结束。
