分割数组的最大值

Split Array Largest Sum

把一个连续数组恰好切成 k 段。你能让最重的那一段，轻到什么程度？

非负整数连续子数组最小化最大值非付费题

Problem

题意

给定非负整数数组 nums 与整数 k，将数组分成恰好 k 个非空、连续的子数组。每种分法都有一个“最大段和”；请返回所有合法分法中，这个最大段和能达到的最小值。

函数形式

splitArray(nums: integer[], k: integer) -> integer

Constraints

约束

  • 1 ≤ nums.length ≤ 1000
  • 0 ≤ nums[i] ≤ 106
  • 1 ≤ k ≤ min(50, nums.length)

子数组必须连续，每一段都必须非空。

Binary search on answer

答案二分 + 贪心判定

核心洞察

不要直接枚举切割位置，而是先猜一个最大段和上限 limit。非负数组中，若某个上限能用不超过 k 段装下全部元素，那么更大的上限也一定可行；若它不可行，更小的上限也一定不可行。可行性因此具有单调性。

答案范围是 [max(nums), sum(nums)]：任何一段至少要容纳最大元素，而把全部元素放进一段时，上界就是总和。

为什么“至多 k 段”足够？

贪心判定得到的是在容量上限下所需的最少段数。若最少段数不超过 k，就能继续在已有的非空段内部切开，直到恰好得到 k 段；因为 k ≤ nums.length，总能找到足够的切点，且拆分不会增大段和。

完整过程

  1. 令 low = max(nums)，high = sum(nums)。
  2. 取 mid = low + floor((high - low) / 2) 作为候选最大段和。
  3. 从左到右累加。若加入当前元素会超过 mid，就在它之前切一刀，让当前元素成为新段首。这样得到满足上限所需的最少段数。
  4. 若所需段数 ≤ k，说明 mid 可行，令 high = mid；否则令 low = mid + 1。
  5. 当 low == high 时，区间唯一值就是最小可行上限。

正确性证明

引理 1：固定 limit 时，每段尽可能向右延伸的贪心策略产生最少段数。第一段不可能比贪心第一段包含更多元素，否则其和会超过上限；移除第一段后，对剩余后缀同理，归纳即得。

引理 2：可行性关于 limit 单调。提高容量不会让任何原本合法的分段失效，因此最少所需段数不会增加。

定理：二分始终保留最小可行值：候选可行时它及右侧无需再找，收缩右端；不可行时它及左侧都不可能是答案，抬高左端。循环结束时仅剩最小可行值，故返回结果正确。

复杂度与边界

时间：O(n · log(sum(nums) - max(nums) + 1))。每次判定扫描数组一次。

空间：O(1)，不计输入。

  • k = 1：答案是数组总和。
  • k = nums.length：答案是最大元素。
  • 数组全为 0：上下界均为 0，直接返回 0。
  • 累计和最大可达 10^9；Java/C++ 中间计算使用 64 位更稳妥。

四语言完整代码

class Solution {
    public int splitArray(int[] nums, int k) {
        long low = 0;
        long high = 0;

        for (int num : nums) {
            low = Math.max(low, num);
            high += num;
        }

        while (low < high) {
            long mid = low + (high - low) / 2;
            if (canSplit(nums, k, mid)) {
                high = mid;
            } else {
                low = mid + 1;
            }
        }
        return (int) low;
    }

    private boolean canSplit(int[] nums, int k, long limit) {
        int groups = 1;
        long currentSum = 0;

        for (int num : nums) {
            if (currentSum + num > limit) {
                groups++;
                currentSum = num;
                if (groups > k) {
                    return false;
                }
            } else {
                currentSum += num;
            }
        }
        return true;
    }
}

替代方案：动态规划

令 dp[i][j] 表示前 i 个数切成 j 段时的最小最大段和，枚举最后一刀位置 p：

dp[i][j] = min over p of max(dp[p][j-1], prefix[i]-prefix[p])

时间复杂度 O(k·n²)，空间复杂度 O(k·n)。它更直观地表达“切几刀”，但本题数据范围下通常不如答案二分高效。

常见错误

  • 把二分下界写成 0，导致候选容量连最大单个元素都容纳不了。
  • 可行时写成 high = mid - 1，破坏“闭区间最小可行值”的模板。
  • 判定函数统计的是“切刀数”，却拿它与“段数 k”直接比较，产生差一错误。
  • 误以为判定必须恰好生成 k 段；实际上最少段数不超过 k 即可。
  • 忽略题目非负条件；若允许负数，贪心装箱的单调判定不再直接成立。

面试追问

Q：为什么用答案二分？

因为答案值域可界定，而且“容量是否足够”的布尔结果随容量单调变化。

Q：如果数组含负数呢？

当前贪心判定失效，需要重新设计状态，通常转向前缀和与动态规划等方法。

Q：如何恢复具体切割方案？

得到最优上限后再次从右向左或从左向右贪心切割，并在剩余元素数等于剩余段数时强制切开，保证恰好 k 段。

Q：为何返回值仍可用 int？

题目最大总和是 1000 × 106 = 109，在 32 位有符号整数内；中间累加使用 64 位可避免修改约束后的隐患。
