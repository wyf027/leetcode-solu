01 / 题目

不必花光，也可以什么都不买

你有 total 元，一支钢笔的价格是 cost1 元，一支铅笔的价格是 cost2 元。两种笔都可以购买任意非负整数支，只要总花费不超过预算。返回不同购买方案的数量。

方案由“钢笔支数、铅笔支数”这对数量决定，购买顺序不影响方案；两种笔都买 0 支也算一种方案。

参数与约束

  • total：总预算，整数。
  • cost1：钢笔单价；cost2：铅笔单价，均为整数。
  • 1 ≤ total, cost1, cost2 ≤ 10⁶。
  • 返回方案总数；官方返回语义为长整数。

官方示例

EXAMPLE 01
输入：total = 20, cost1 = 10, cost2 = 5
输出：9

钢笔买 0 支时，铅笔可买 0～4 支；钢笔买 1 支时，铅笔可买 0～2 支；钢笔买 2 支时，铅笔只能买 0 支。合计 5 + 3 + 1 = 9 种。

EXAMPLE 02
输入：total = 5, cost1 = 10, cost2 = 10
输出：1

两种笔都比预算贵，只能买 0 支钢笔和 0 支铅笔，因此仍有 1 种方案。

04 / 独立题解

先想一想，再打开推导

思考：哪些购买选择天然属于同一组？

固定钢笔数量，直接数铅笔选择

核心洞察

设钢笔买 x 支，铅笔买 y 支。合法方案满足 x·cost1 + y·cost2 ≤ total，且 x、y 都是非负整数。固定 x 后，剩余预算 r = total − x·cost1，所以 y 可以取 0 … floor(r / cost2)，一共 floor(r / cost2) + 1 种。

“+1” 是零支铅笔。 不需要枚举每个 y，更不需要把预算恰好花光。

完整过程

  1. 将累计答案初始化为 0。
  2. 从 x = 0 到 floor(total / cost1)，枚举所有买得起的钢笔数量。
  3. 计算剩余预算，再将 floor(剩余预算 / cost2) + 1 加入答案。
  4. 循环结束后返回答案。代码用剩余预算从 total 开始每次减 cost1，等价地完成枚举，避免重复乘法。
total = 20, cost1 = 10, cost2 = 5
x = 0：剩余 20，y = 0..4，贡献 5，累计 5
x = 1：剩余 10，y = 0..2，贡献 3，累计 8
x = 2：剩余  0，y = 0..0，贡献 1，累计 9

为什么正确

合法性：对每个枚举的 x，剩余预算非负；计入的 y 不超过剩余预算除以铅笔价格的向下取整，故不会超支。

完整性：任意合法方案的 x 都在枚举范围内，其 y 必然落在对应组的合法区间内，因此一定被计入。

无重复：不同 x 的组互不相交，同组的每个 y 只对应一个数量对。累加所有组，就恰好得到全部合法方案。

边界与数值范围

  • 两种笔都买不起：x = 0 的组依然贡献 1，即 (0,0)。
  • 剩余预算为 0：仍需处理该组，因此循环条件是 remaining ≥ 0。
  • 单价相同也不能合并笔的类别；(1,0) 与 (0,1) 是不同方案。
  • 价格最小为 1 时方案最多。令 T = total，上界为 (T + 1)(T + 2) / 2；T = 10⁶ 时是 500001500001，超过 32 位有符号整数。
  • Java 使用 long，C++ 使用 long long。Python 整数自动扩展；JavaScript Number 在这里仍能精确表示整数，因为答案小于 2⁵³ − 1。

复杂度

下面四份代码统一固定钢笔数量：时间 O(⌊total / cost1⌋ + 1)，额外空间 O(1)。最坏约执行 10⁶ + 1 次。演示页面为了展示方案保存了可见节点，其空间不代表提交算法空间。

替代方案

  • 交换枚举方向：先交换两个价格，使枚举的那种笔更贵。答案具有对称性，时间降为 O(⌊total / max(cost1,cost2)⌋ + 1)。为保持钢笔含义直观，下方代码未交换。
  • 双重枚举：逐个枚举 x、y 并检查预算，容易理解但最坏 O(total²)，会浪费大量时间。
  • 整除求和：更大预算下可将求和转为 floor-sum，用欧几里得式递归优化；本题规模无需增加这类复杂度。

常见错误

  • 漏掉 +1，遗漏买 0 支铅笔的方案。
  • 使用“恰好花光”的等式，漏算留有零钱的购买方案。
  • 只循环到剩余预算大于 0，遗漏刚好买满预算的组。
  • 使用 32 位答案变量，或在 JavaScript 中用位运算将大答案截成 32 位。
  • 把买笔的顺序当成不同方案，错误地计算排列数。

面试追问

预算变为 10¹⁸ 怎么办？单层枚举可能仍太慢，需要整除求和，并重新审视结果类型；JavaScript 可考虑 BigInt。

要求恰好花完呢？固定 x 后，只有剩余预算能被 cost2 整除时才贡献 1，属于另一种计数条件。

每种笔最多只能买有限支呢？限制 x 的枚举上界，并将每组的 y 上界取为库存与 floor(r / cost2) 的较小值。

如果增加第三种笔呢？可以先固定前两种数量，再直接计算第三种选择数，但需要根据约束判断双层枚举是否可行。

四语言完整提交代码

使用官方函数名与参数形式；下列代码尚未编译或执行。

Java

class Solution {
    public long waysToBuyPensPencils(int total, int cost1, int cost2) {
        long answer = 0;
        for (int remaining = total; remaining >= 0; remaining -= cost1) {
            answer += remaining / cost2 + 1L;
        }
        return answer;
    }
}
