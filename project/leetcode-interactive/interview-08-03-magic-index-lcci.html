刻度任务

GAUGE 08—03

给定一个按非递减顺序排列的整数数组 nums。寻找满足 nums[i] == i 的下标；若有多个，返回最小下标；若不存在，返回 -1。

数组可能包含重复元素，长度范围为 [1, 1,000,000]。这使普通“命中即返回”的二分查找无法保证最小答案。

Core insight

核心洞察

从左到右检查下标 i。若 nums[i] == i，因为此前所有更小下标都已排除，所以它就是最小答案。否则前进到 max(i + 1, nums[i])。

Why the jump is safe

完整过程

当 nums[i] > i 时，对任意 i < j < nums[i]，有序性保证 nums[j] ≥ nums[i] > j，这些下标都不可能命中，因此可直接跳到 nums[i]。若 nums[i] < i，只能前进一格。

Limits

边界与复杂度

  • 重复值：不破坏跳跃证明，但让经典单路二分不再可靠。
  • 负数：max(i + 1, nums[i]) 仍确保严格前进。
  • 时间：最坏 O(n)，每个实际访问位置只检查一次。
  • 空间：O(1)。

Alternatives

替代方案

  • 普通线性扫描：最直接且同为 O(n)，但没有利用有序性跳过不可能区间。
  • 重复数组分治：递归搜索两侧，最坏仍为 O(n)，代码更复杂。
  • 严格递增数组：若保证无重复，可用二分在 O(log n) 内完成。

Interview follow-ups

面试追问

  • 为什么跳过 (i, nums[i]) 不会错过答案？
  • 若数组严格递增，如何改成二分并继续保证最小下标？
  • 为什么允许重复后，二分只搜一侧可能漏解？

Common mistakes

常见错误

  • 命中任意二分中点就返回，忽略“最小索引”。
  • 直接写 i = nums[i]，当值落后于下标时会倒退或死循环。
  • 跳过区间时忘记数组必须有序这一前提。

class Solution {
    public int findMagicIndex(int[] nums) {
        int i = 0;
        while (i < nums.length) {
            if (nums[i] == i) {
                return i;
            }
            i = Math.max(i + 1, nums[i]);
        }
        return -1;
    }
}
