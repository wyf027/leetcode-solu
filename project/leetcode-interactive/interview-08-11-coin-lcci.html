01 · 题意

组合计数，不是排列计数

有无限枚面值为 25、10、5、1 分的硬币。给定总金额 n，求组成它的不同方式数，并对 1,000,000,007 取模。

官方示例

输入 n = 5
输出 2

两种组合是 5，以及 1 + 1 + 1 + 1 + 1。

输入 n = 10
输出 4

四种组合分别以 10、两个 5、一个 5 加五个 1、十个 1 组成。

约束与口径

  • 0 <= n <= 1,000,000
  • 每种硬币数量不限。
  • 组合内部顺序不同不算新方案。
  • n = 0 时，空组合是一种有效方式。

    Solution · Complete Knapsack

    把“面值”放在外层循环

    外层按硬币种类推进，内层让金额从小到大增长，就能复用同一种硬币，同时不会把相同组合的不同排列重复计数。

    核心洞察

    令 dp[x] 表示使用“已经处理过的面值”凑成 x 的组合数。初始化 dp[0] = 1，因为不选硬币恰好构成 0 分。

    dp[x] = (dp[x] + dp[x - coin]) mod MOD

    当处理 coin 时，dp[x - coin] 已经包含继续使用当前硬币的方案，因此金额必须正向扫描。

    完整过程

    1. 创建长度为 n + 1 的数组，全部置 0。
    2. 设置 dp[0] = 1。
    3. 依次处理面值 [1, 5, 10, 25]。
    4. 对每个面值，让金额从 coin 正向走到 n。
    5. 把 dp[x - coin] 加入 dp[x] 并立即取模。
    6. 四条轨道结束后返回 dp[n]。

    为什么外层必须是硬币

    若金额在外层、硬币在内层，5 + 10 与 10 + 5 会沿不同选择顺序被重复统计。硬币在外层，相当于规定组合只按固定面值次序生成，每个多重集合只出现一次。

    边界

    • n = 0：返回 1。
    • 0 < n < 5：只有全用 1 分的一种方式。
    • 面值大于目标：对应内层循环不会执行。
    • 大规模输入：每次加法都取模，Java/C++ 用整型也安全。

    复杂度

    四种硬币固定，因此时间为 O(4n) = O(n)，空间为 O(n)。当 n = 1,000,000 时仍是线性扫描。

    替代方案

    可以枚举 25 分与 10 分硬币数量，再用算式计算 5 分与 1 分的方案，空间可降到 O(1)；也能继续推导计数公式。面试主线更推荐完全背包：语义清晰、易推广到任意硬币数组、出错面更小。

    面试追问

    • 若硬币数量有限，状态转移怎样改变？
    • 若要统计排列数，循环顺序应如何调整？
    • 为什么金额正向扫描代表“可重复取”，反向扫描代表“至多取一次”？
    • 能否输出一种具体组合，而不只输出数量？

    常见错误

    • 把金额放在外层，误算成排列数。
    • 忘记 dp[0] = 1，导致所有状态都保持 0。
    • 金额反向扫描，错误地把每种硬币限制为一次。
    • 只在最终返回时取模，造成中间值溢出。
