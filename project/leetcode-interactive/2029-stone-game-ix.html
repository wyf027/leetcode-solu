石子游戏 IX

Stone Game IX · 一次取石，改变整场游戏。

游戏规则

给定整数数组 stones，每个元素是一颗石子的价值。Alice 先手，两人轮流移除任意一颗石子。如果本次移除后，所有已移除石子的价值总和能被 3 整除，本次操作者立即输。若未触发该条件且石子已经取完，则 Bob 获胜，不论最后是谁操作。

双方都作最优决策。返回 Alice 能否获胜：能则为 true，否则为 false。

参数：stones: integer[] → boolean
约束：1 ≤ stones.length ≤ 10⁵；1 ≤ stones[i] ≤ 10⁴。

官方示例

示例 1

输入：stones = [2,1]
输出：true

无论 Alice 先取哪颗，Bob 取另一颗后总和为 3，Bob 输。

示例 2

输入：stones = [2]
输出：false

Alice 取 2 后没有触发整除，但石子耗尽，Bob 直接获胜。

示例 3

输入：stones = [5,1,2,4,3]
输出：false

Bob 可确保获胜。一条可能的路径是依次取 1、3、4、2、5，总和依次为 1、4、8、10、15；第五步 Alice 使总和被 3 整除而输。

题解 · 只统计三个余数

核心洞察

令 c0、c1、c2 分别为价值模 3 等于 0、1、2 的石子数。绝对价值与原数组顺序都不影响胜负。总和余数非零时，取余数 0 的石子不改变余数，却交换行动者；成对的此类石子只增加偶数个安全回合，因此只需关注 c0 的奇偶性。

c0 为偶数：Alice 获胜 ⇔ c1 > 0 且 c2 > 0
c0 为奇数：Alice 获胜 ⇔ |c1 - c2| > 2

完整过程

  1. 遍历 stones，把每颗石子按 x % 3 计数。
  2. 若 c0 为偶数，检查两种非零余数是否都存在。
  3. 否则，检查两类数量差是否严格大于 2。

示例 3 的计数是 (1,2,2)。c0 为奇数，差值 0 不大于 2，因此返回 false。

正确性说明

首步取余数 0 会立即输，所以 Alice 只能从 1 或 2 开始。忽略余数 0 后，若先取 1，为避免总和归零，之后的非零余数序列被迫为 1,1,2,1,2,…；先取 2 的情况完全对称。因为当前总和余数为 1 时只能安全取 1，为 2 时只能安全取 2，所以不存在其他安全的非零选择。

将两个余数 0 回合配对，它们不改变总和余数，也不改变后续行动者的奇偶位置；在非零余数开始之后，玩家可用配对回应保持这一性质。因而归约为没有或只有一个余数 0 的局面。必须另外保留“安全耗尽由 Bob 获胜”的终止规则。

没有余数 0 时，若两种非零余数都有，Alice 从数量较少的一类开始（相等任选）。沿强制序列推进，Bob 首先遇到所需类别耗尽，且仍有会使总和归零的石子，故 Bob 输。若只有一种非零余数，数量少时会安全耗尽，数量多时第三次非零操作就使 Alice 输，均为 Bob 胜。

有一个余数 0 时，它可翻转一次后续回合归属。设较多类别为 A，较少类别为 B。Alice 若从 A 开始，强制序列在不插入 0 时使用两个起始 A，再交替 B、A。若 A 至少比 B 多 3 个，在耗尽 B 后仍留有 A；Bob 无论何时使用 0，都无法避免轮到自己面对缺失的安全 B，此时取 A 必输。若差值至多 2，Bob 可把 0 留到需要调整回合的位置，使 Alice 遇到危险回合或使石子安全耗尽。若 Alice 从较少类别开始，Bob 同样可以利用这一次回合翻转保住胜局。由此得到奇数情形的严格差值条件，两种情形覆盖全部计数。

边界与常见错误

  • 只有余数 0：Alice 首步就输。单颗非零石子：安全取完仍是 Bob 胜。
  • 差值恰好 2 不够，不能把 > 2 写成 >= 2。
  • 检查的是所有已移除石子的总和，不是剩余总和或当前石子。
  • 先判断本回合是否输，再判断是否耗尽；不能把无子可取当作普通博弈的当前玩家输。

复杂度

时间 O(n)：只遍历一次；额外空间 O(1)：固定三个计数，不需要排序或修改输入。

替代方案

可枚举首步余数 1 或 2，再按上述强制非零序列与 0 回合奇偶分析安全步数。也可对状态 (c0,c1,c2,sum%3,turn) 做记忆化极小化极大搜索，但状态数量随三类计数乘积增长，不适合 n 达到 10⁵；仅适合小规模理解。搜索必须以“Alice 是否获胜”为目标，不能简单套用无合法动作即输。

面试追问

为什么只要余数？ 整除性由余数相加完全决定。
为什么不能仅统计总和？ 每一步的可选余数决定谁先触发失败。
改成模 k 呢？ 状态仍可按余数分组，但模 3 的非零安全选择唯一性消失，不能直接沿用这个公式。

Java

class Solution {
    public boolean stoneGameIX(int[] stones) {
        int[] c = new int[3];
        for (int x : stones) c[x % 3]++;
        if (c[0] % 2 == 0) return c[1] > 0 && c[2] > 0;
        return Math.abs(c[1] - c[2]) > 2;
    }
}
