Market Analysis II

市场分析 II

一张订单表记录了谁卖出了什么。现在要为每位用户判断：他按时间卖出的第二件商品，是否恰好属于自己的最爱品牌。

数据库 窗口函数 LEFT JOIN 条件判断

01 · Problem

题目说明

以下内容依据官方元数据中的表结构和示例做准确转述；付费题原始正文为空，因此不复刻受限题面。

任务：对 Users 中的每一位用户，按照订单日期从早到晚检查他作为卖家的订单。如果第二次卖出的商品品牌等于该用户的 favorite_brand，输出 yes；否则输出 no。没有卖出第二件商品的用户也必须保留，并输出 no。

返回列：seller_id 与 2nd_item_fav_brand。结果行顺序不影响判定。

输入表与完整字段

Users

  • user_idINT
  • join_dateDATE
  • favorite_brandVARCHAR(10)

用户编号、加入日期与最爱品牌。

Orders

  • order_idINT
  • order_dateDATE
  • item_idINT
  • buyer_idINT
  • seller_idINT

订单编号、日期、商品、买家与卖家。

Items

  • item_idINT
  • item_brandVARCHAR(10)

商品编号及其品牌。

约束与关系

  • user_id、order_id、item_id 分别标识对应实体。
  • Orders.item_id 指向商品，buyer_id 与 seller_id 指向用户。
  • “第二件”按卖家的 order_date 升序确定；实现中以 order_id 作为日期相同情况下的稳定次序。
  • 品牌字段最大长度由官方建表元数据给出，为 VARCHAR(10)；官方元数据未提供额外数值范围。

05 · Solution vault

准备好再揭晓

题解默认收起。你可以先独立思考如何既找出“第二单”，又保留完全没有第二单的用户。

Solution

窗口排名 + 保留全集

先在订单内部回答“每位卖家的第几单”，再从 Users 出发左连接第二单与商品品牌。

核心洞察 正确性 完整代码 追问与错误

核心洞察

1

分组排序

对 seller_id 分区，按日期与订单号排序。

2

锁定第二行

ROW_NUMBER() 生成序号，只让 rn = 2 参与后续连接。

3

从用户全集出发

使用左连接保留每位用户；第二单缺失时自然落入 no。

完整过程

  1. 在 CTE ranked_orders 中，为每个卖家的订单建立时间序号。
  2. 从 Users 开始，对排名为 2 的订单做 LEFT JOIN。筛选条件必须写在连接条件里，不能写到最终 WHERE。
  3. 用第二单的 item_id 左连接 Items，取得品牌。
  4. 用 CASE 比较商品品牌和用户最爱品牌；匹配才输出 yes，其余均为 no。

正确性证明

  1. 排名正确。对固定卖家，窗口按 order_date, order_id 升序遍历其订单，因此序号 1、2、… 与该卖家的售出先后次序一致，序号 2 恰为第二次售出。
  2. 用户不会丢失。最终查询以 Users 为左表。即使某用户没有订单或不足两单，左连接仍产生该用户的一行，只是第二单字段为 NULL。
  3. 判断正确。若第二单存在，连接到 Items 后得到该商品唯一对应的品牌；CASE 仅在该品牌等于用户最爱品牌时返回 yes。若不存在或不相等，返回 no。
  4. 结论。每位用户恰好被保留一次，且输出值准确刻画其第二次售出的商品是否属于最爱品牌，所以算法满足题意。

边界与复杂度

时间

设订单数为 O、用户数为 U。窗口排序通常为 O(O log O)；连接在合理索引下接近线性扫描。

额外空间

数据库为排序与窗口结果使用最多 O(O) 级别的中间空间，具体由执行计划决定。

  • 零单或一单：第二单为空，输出 no。
  • 恰好两单：直接比较较晚一单的品牌。
  • 多于两单：第三单及之后不影响答案。
  • 日期相同：本实现追加 order_id 作为稳定次序；若业务另有成交时间，应优先按真实时间排序。
  • 索引建议：Orders(seller_id, order_date, order_id) 可帮助分组排序，主键索引负责用户与商品连接。

MySQL 8.0 · 官方提交语言

窗口函数标号；从 Users 左连接，保证没有第二单的用户也出现。

WITH ranked_orders AS (
    SELECT
        order_id,
        order_date,
        item_id,
        seller_id,
        ROW_NUMBER() OVER (
            PARTITION BY seller_id
            ORDER BY order_date, order_id
        ) AS rn
    FROM Orders
)
SELECT
    u.user_id AS seller_id,
    CASE
        WHEN i.item_brand = u.favorite_brand THEN 'yes'
        ELSE 'no'
    END AS 2nd_item_fav_brand
FROM Users AS u
LEFT JOIN ranked_orders AS ro
    ON ro.seller_id = u.user_id
   AND ro.rn = 2
LEFT JOIN Items AS i
    ON i.item_id = ro.item_id;
JavaScript · 本地语义参考

输入为对象数组，输出结构与 SQL 结果一致。

/**
 * @typedef {{user_id:number, join_date:string, favorite_brand:string}} User
 * @typedef {{order_id:number, order_date:string, item_id:number,
 *            buyer_id:number, seller_id:number}} Order
 * @typedef {{item_id:number, item_brand:string}} Item
 */

/**
 * @param {User[]} users
 * @param {Order[]} orders
 * @param {Item[]} items
 * @returns {{seller_id:number, second_item_fav_brand:string}[]}
 */
function marketAnalysisII(users, orders, items) {
  const itemBrand = new Map(
    items.map((item) => [item.item_id, item.item_brand])
  );
  const soldByUser = new Map();

  for (const order of orders) {
    if (!soldByUser.has(order.seller_id)) {
      soldByUser.set(order.seller_id, []);
    }
    soldByUser.get(order.seller_id).push(order);
  }

  for (const soldOrders of soldByUser.values()) {
    soldOrders.sort((a, b) =>
      a.order_date.localeCompare(b.order_date) || a.order_id - b.order_id
    );
  }

  return users.map((user) => {
    const secondOrder = (soldByUser.get(user.user_id) || [])[1];
    const isFavorite = secondOrder !== undefined &&
      itemBrand.get(secondOrder.item_id) === user.favorite_brand;

    return {
      seller_id: user.user_id,
      second_item_fav_brand: isFavorite ? "yes" : "no"
    };
  });
}
Python 3 · 本地语义参考

使用 dataclass 描述三张表，不依赖第三方库。

from dataclasses import dataclass
from collections import defaultdict
from typing import List, Dict


@dataclass(frozen=True)
class User:
    user_id: int
    join_date: str
    favorite_brand: str


@dataclass(frozen=True)
class Order:
    order_id: int
    order_date: str
    item_id: int
    buyer_id: int
    seller_id: int


@dataclass(frozen=True)
class Item:
    item_id: int
    item_brand: str


def market_analysis_ii(
    users: List[User],
    orders: List[Order],
    items: List[Item],
) -> List[Dict[str, object]]:
    brand_by_item = {item.item_id: item.item_brand for item in items}
    sold_by_user = defaultdict(list)

    for order in orders:
        sold_by_user[order.seller_id].append(order)

    for sold_orders in sold_by_user.values():
        sold_orders.sort(key=lambda order: (order.order_date, order.order_id))

    result = []
    for user in users:
        sold_orders = sold_by_user[user.user_id]
        is_favorite = (
            len(sold_orders) >= 2
            and brand_by_item.get(sold_orders[1].item_id) == user.favorite_brand
        )
        result.append({
            "seller_id": user.user_id,
            "second_item_fav_brand": "yes" if is_favorite else "no",
        })

    return result
Java 17 · 本地语义参考

使用不可变 record 表示行；返回结果 record 列表。

import java.util.ArrayList;
import java.util.Comparator;
import java.util.HashMap;
import java.util.List;
import java.util.Map;

public class MarketAnalysisII {
    public record User(int userId, String joinDate, String favoriteBrand) {}

    public record Order(
        int orderId,
        String orderDate,
        int itemId,
        int buyerId,
        int sellerId
    ) {}

    public record Item(int itemId, String itemBrand) {}

    public record Result(int sellerId, String secondItemFavBrand) {}

    public static List<Result> solve(
        List<User> users,
        List<Order> orders,
        List<Item> items
    ) {
        Map<Integer, String> brandByItem = new HashMap<>();
        for (Item item : items) {
            brandByItem.put(item.itemId(), item.itemBrand());
        }

        Map<Integer, List<Order>> soldByUser = new HashMap<>();
        for (Order order : orders) {
            soldByUser
                .computeIfAbsent(order.sellerId(), key -> new ArrayList<>())
                .add(order);
        }

        Comparator<Order> chronological = Comparator
            .comparing(Order::orderDate)
            .thenComparingInt(Order::orderId);
        for (List<Order> soldOrders : soldByUser.values()) {
            soldOrders.sort(chronological);
        }

        List<Result> answer = new ArrayList<>();
        for (User user : users) {
            List<Order> soldOrders = soldByUser.getOrDefault(
                user.userId(), List.of()
            );
            boolean isFavorite = soldOrders.size() >= 2
                && user.favoriteBrand().equals(
                    brandByItem.get(soldOrders.get(1).itemId())
                );
            answer.add(new Result(
                user.userId(), isFavorite ? "yes" : "no"
            ));
        }
        return answer;
    }
}
C++17 · 本地语义参考

使用 unordered_map 建立商品索引和卖家订单分组。

#include <algorithm>
#include <string>
#include <unordered_map>
#include <utility>
#include <vector>

using namespace std;

struct User {
    int userId;
    string joinDate;
    string favoriteBrand;
};

struct Order {
    int orderId;
    string orderDate;
    int itemId;
    int buyerId;
    int sellerId;
};

struct Item {
    int itemId;
    string itemBrand;
};

struct Result {
    int sellerId;
    string secondItemFavBrand;
};

vector<Result> marketAnalysisII(
    const vector<User>& users,
    const vector<Order>& orders,
    const vector<Item>& items
) {
    unordered_map<int, string> brandByItem;
    for (const Item& item : items) {
        brandByItem[item.itemId] = item.itemBrand;
    }

    unordered_map<int, vector<Order>> soldByUser;
    for (const Order& order : orders) {
        soldByUser[order.sellerId].push_back(order);
    }

    for (auto& [sellerId, soldOrders] : soldByUser) {
        sort(soldOrders.begin(), soldOrders.end(),
            [](const Order& a, const Order& b) {
                if (a.orderDate != b.orderDate) {
                    return a.orderDate < b.orderDate;
                }
                return a.orderId < b.orderId;
            }
        );
    }

    vector<Result> answer;
    answer.reserve(users.size());

    for (const User& user : users) {
        const auto found = soldByUser.find(user.userId);
        bool isFavorite = false;

        if (found != soldByUser.end() && found->second.size() >= 2) {
            const int secondItemId = found->second[1].itemId;
            const auto brand = brandByItem.find(secondItemId);
            isFavorite = brand != brandByItem.end()
                && brand->second == user.favoriteBrand;
        }

        answer.push_back({
            user.userId,
            isFavorite ? "yes" : "no"
        });
    }

    return answer;
}

替代方案

相关子查询 + OFFSET：可以为每位用户单独按日期寻找第二条订单，写法直观，但可能对每个用户重复扫描或排序订单；大数据量时通常不如一次窗口排名清晰稳定。

自连接计数：统计某订单之前同卖家的订单数，等于 1 的就是第二单。它不依赖窗口函数，却容易产生二次规模的连接，并且同日次序处理更繁琐。

聚合日期：先求第二小日期再回表。若同一天有多单，单靠日期不能唯一定位订单，因此需要额外的稳定排序字段。

面试追问

为什么 rn = 2 不能放在最终 WHERE？
因为最终 WHERE 会过滤掉左连接产生的 NULL 行，使没有第二单的用户消失。把条件放进 ON，才能保留 Users 全集。
如果要判断第二个不同品牌，而不是第二张订单呢？
先按卖家时间线去除连续或全部重复品牌，再对保留下来的品牌事件编号。具体使用 LAG 还是 DISTINCT，取决于“不同”的业务定义。
怎样处理完全相同的成交时间？
业务上必须提供能表示先后的字段，例如精确时间或流水号。示例实现使用 order_id 作为稳定次序，但这只是工程约定，不应替代真实业务时间。

常见错误

  • 按 buyer_id 分组；题目问的是卖家，应使用 seller_id。
  • 使用 RANK()；并列日期可能产生多个排名 2。这里需要恰好一行，因此使用 ROW_NUMBER() 并提供稳定次序。
  • 从 Orders 开始内连接；这样无销售或只有一单的用户不会出现在结果里。
  • 比较第二单的 item_id 与 favorite_brand；必须先连接 Items，把商品编号转换为品牌。
  • 误把第二次购买当作第二次售出，或把第二小商品编号当作第二个时间节点。
