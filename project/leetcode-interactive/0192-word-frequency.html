任务
统计 words.txt 中每个单词的出现次数。
字符范围

题解仍处于隐藏状态

展开后查看命令职责、完整过程、兼容实现、边界、复杂度、追问与常见错误。

每个命令只做一件事，管道负责组合

核心洞察与完整过程

  1. tr 把所有连续空白压缩并转换成换行，使每行只剩一个单词。
  2. sed 删除可能由文件前后空白产生的空行。
  3. LC_ALL=C sort 把相同单词排到相邻位置。
  4. uniq -c 对连续重复行计数，因此它必须接在字典序排序之后。
  5. sort -nr 按行首数字进行数值降序排序。
  6. awk 把 count word 重排为题目要求的 word count。 
words.txt
  | tokenize whitespace
  | sort words
  | count adjacent duplicates
  | sort counts descending
  | print word count

官方 Bash 主提交与兼容实现

LeetCode 该题只提供 Bash 提交入口。下面不给出 Java、JavaScript、Python 或 C++，因为它们不是本题官方可提交语言。

Bash · LeetCode 提交
# Read from the file words.txt and output the word frequency list to stdout.
tr -s '[:space:]' '\n' < words.txt \
  | sed '/^$/d' \
  | LC_ALL=C sort \
  | uniq -c \
  | sort -nr \
  | awk '{print $2, $1}'
POSIX awk · 等价兼容实现
awk '{
  for (i = 1; i <= NF; i++) {
    count[$i]++
  }
}
END {
  for (word in count) {
    print word, count[word]
  }
}' words.txt | LC_ALL=C sort -k2,2nr

边界与复杂度

  • 连续空格、制表符和换行都应被视为分隔符。
  • 文件前后有空白时，不能把空字符串统计成单词。
  • 单个单词应输出该单词和 1。
  • 题目保证频次唯一，自定义输入出现并列时顺序不属于官方契约。
  • 设单词数为 n，排序主导时间为 O(n log n)。
  • 外部排序所需空间取决于 sort 实现与输入规模。

替代方案与取舍

  • 纯 awk 用哈希表计数，再按第二列排序，扫描过程更直接。
  • grep -o 可以抽取单词，但不同平台的选项兼容性较差。
  • sort | uniq -c 更贴合题目对 Unix pipes 的追问。

面试追问

  • 若大小写混合，应该在哪一段统一大小写？
  • 若频次可以相同，怎样指定稳定的第二排序键？
  • 超大文件无法放入内存时，外部排序如何工作？

常见错误

  • 没有先排序就使用 uniq -c，只能统计相邻重复行。
  • 使用普通 sort -r 排频次，把数字当字符串比较。
  • 只替换单个空格，没有处理连续空白、换行或制表符。
  • 忘记重排字段，输出成 count word。
  • 依赖 GNU 专属参数，导致 macOS 或 POSIX 环境不可运行。
