中心对称数 III

Strobogrammatic Number III：计数闭区间 [low, high] 内，旋转 180° 后外观不变的数。边界以字符串给出，不能依赖整数范围。

中心向两端 DFS合法旋转对字符串边界比较

题意

统计闭区间内的旋转不变数

给定两个表示整数的字符串 low、high，统计范围内的中心对称数。旋转 180° 后，0↔0、1↔1、8↔8、6↔9。

输入：low = "50"，high = "100"

输出：3（"69", "88", "96"）

low、high 的长度均为 1..15，无前导零（零自身除外），且 low ≤ high。

核心洞察

每次同时固定左右两位

枚举每一种长度，用 DFS 从外向内填入 (0,0)、(1,1)、(6,9)、(8,8)、(9,6)。首位不能为 0，中心位只能是 0/1/8；完成后再用字符串比较筛掉边界外候选。

为何字符串比较？ 边界可长达 15 位，构造和比较都无需冒整数溢出风险。

题解：定长 DFS + 边界过滤

对 low.length 到 high.length 每种长度，使用可变字符数组从两端填入映射对。填满时，若和低/高边界同长则词典序比较；数字字符串无前导零，所以同长词典序就是数值序。

完整过程

  1. 遍历范围内每一种长度。
  2. 两端选择五种旋转对。
  3. 跳过多位数的前导 0，中心跳过 6/9。
  4. 完成后按 low/high 筛选并计数。

复杂度与边界

候选数约为 5^(L/2)，每个候选 O(L) 比较。0 必须允许；多位数不得以 0 开头；同长度边界要精确比较。

替代方案

可先生成全部中心对称数列表再过滤，逻辑相同但占用更多内存。DFS 使用一个 buffer 原地填充更直接。

常见错误 / 追问

漏掉中心位限制会把 6/9 放入中间；允许首位 0 会重复且产生非法数；用数值转换可能在大边界溢出。
