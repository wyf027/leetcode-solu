01 · 题目

先把“同一棵树”说清楚

以下内容依据官方题面准确转述；答案不包含原数组自身这一种顺序。

给定数组 nums，它是整数 1 到 n 的一个排列。按数组顺序将元素逐个插入一棵初始为空的二叉搜索树。

统计有多少种不同的 nums 重排方式，能构造出与原顺序完全相同的 BST；返回方案数对 10⁹ + 7 取模后的结果。

例如 [2,1,3] 与 [2,3,1] 都会得到根为 2、左右孩子分别为 1 和 3 的树；但 [3,2,1] 得到的是另一棵树。

函数形式

numOfWays(nums: integer[]): integer

约束

  • 1 ≤ nums.length ≤ 1000
  • 1 ≤ nums[i] ≤ nums.length
  • nums 中所有整数互不相同
示例 1
输入：nums = [2,1,3]
输出：1
只有另一种顺序 [2,3,1] 得到同一棵 BST。
示例 2
输入：nums = [3,4,5,1,2]
输出：5
五种重排：[3,1,2,4,5]、[3,1,4,2,5]、[3,1,4,5,2]、[3,4,1,2,5]、[3,4,1,5,2]。
示例 3
输入：nums = [1,2,3]
输出：0
不存在另一个能得到同一棵 BST 的排列。

分治计数：保持两侧内部顺序，只选择交错位置

核心洞察

对任意非空子数组，第一个数字必然是这棵子树的根。之后，比根小的数字只会进入左子树，比根大的数字只会进入右子树。

为了让最终 BST 不变，左侧数字之间必须形成同一棵左子树，右侧数字之间也必须形成同一棵右子树；但左右两组数字可以互相穿插，因为它们进入彼此独立的分支。

ways(A) = C(|L| + |R|, |L|) × ways(L) × ways(R)

组合数选择左侧元素占据哪些位置。组内的相对顺序由各自递归方案决定。递归结果包含原顺序，所以最终答案要减去 1。

完整过程

  1. 预处理阶乘与逆阶乘，用 fact[n] × invFact[k] × invFact[n-k] 在常数时间求组合数。
  2. 递归处理当前序列。长度小于等于 2 时，能保持相同 BST 的顺序只有它自己，返回 1。
  3. 把首元素作为根，将剩余元素稳定划分为 left 与 right；稳定划分保留每一组原本的相对顺序。
  4. 递归得到左右子树各自的有效顺序数。
  5. 从根之后的所有位置中选择 left.length 个位置放左侧序列，再乘左右递归结果。
  6. 顶层结果减 1，排除原数组本身，并在每一步按 10⁹ + 7 取模。
示例 [3,4,5,1,2]：左序列为 [1,2]，右序列为 [4,5]。两侧各只有 1 种内部顺序，共有 C(4,2)=6 种交错；减去原数组得到 5。

正确性证明

根不可变要得到相同 BST，重排序列的首元素必须仍是当前子树的根，否则整棵子树的根节点已经不同。
子树独立根之后，小于根和大于根的元素分别只进入左、右子树；因此两组元素跨组穿插不会改变它们各自的插入路径。
计数无重无漏每个合法序列唯一对应“左侧占据的位置集合 + 左子树合法序列 + 右子树合法序列”，反向组合也一定合法，构成双射。

以序列长度归纳：基本情形长度不超过 2 时显然成立；假设更短序列的递归计数正确，根据上述双射，当前层乘法与组合数精确覆盖所有合法重排。因此递归式正确；顶层减去原序列后即为题目所求。

边界情况

  • 单节点或双节点：没有可交换且保持结构的另一种顺序，递归返回 1，顶层会变成 0。
  • 严格递增或递减：BST 退化成链，每层只有一侧非空，组合数恒为 1，最终答案为 0。
  • 取模减法：使用 (total - 1 + MOD) % MOD，避免出现负数。
  • 递归深度：最坏可达 1000；题目约束下一般语言可处理，但生产环境可改为显式栈。
  • 数值精度：JavaScript 必须用 BigInt 完成模乘，不能依赖普通 Number。

复杂度

O(n²)
最坏时间。退化 BST 中，每层都要扫描当前序列做划分。
O(n²)
最坏辅助空间。递归链中各层保留划分数组；阶乘表本身只需 O(n)。

平衡情形的划分总工作量更接近 O(n log n)，但上界仍按退化树计算。

Java · LeetCode 可提交factorial + inverse factorial
import java.util.*;

class Solution {
    private static final long MOD = 1_000_000_007L;
    private long[] fact;
    private long[] invFact;

    public int numOfWays(int[] nums) {
        int n = nums.length;
        fact = new long[n + 1];
        invFact = new long[n + 1];
        fact[0] = 1;
        for (int i = 1; i <= n; i++) {
            fact[i] = fact[i - 1] * i % MOD;
        }
        invFact[n] = modPow(fact[n], MOD - 2);
        for (int i = n; i > 0; i--) {
            invFact[i - 1] = invFact[i] * i % MOD;
        }

        List<Integer> values = new ArrayList<>(n);
        for (int value : nums) values.add(value);
        return (int) ((count(values) - 1 + MOD) % MOD);
    }

    private long count(List<Integer> values) {
        int size = values.size();
        if (size <= 2) return 1;

        int root = values.get(0);
        List<Integer> left = new ArrayList<>();
        List<Integer> right = new ArrayList<>();
        for (int i = 1; i < size; i++) {
            int value = values.get(i);
            if (value < root) left.add(value);
            else right.add(value);
        }

        long ways = combination(size - 1, left.size());
        ways = ways * count(left) % MOD;
        ways = ways * count(right) % MOD;
        return ways;
    }

    private long combination(int n, int k) {
        return fact[n] * invFact[k] % MOD * invFact[n - k] % MOD;
    }

    private long modPow(long base, long exponent) {
        long result = 1;
        while (exponent > 0) {
            if ((exponent & 1) == 1) result = result * base % MOD;
            base = base * base % MOD;
            exponent >>= 1;
        }
        return result;
    }
}

/**
 * @param {number[]} nums
 * @return {number}
 */
var numOfWays = function(nums) {
    const MOD = 1000000007n;
    const n = nums.length;
    const fact = Array(n + 1).fill(1n);
    const invFact = Array(n + 1).fill(1n);

    for (let i = 1; i <= n; i++) {
        fact[i] = fact[i - 1] * BigInt(i) % MOD;
    }

    const modPow = (base, exponent) => {
        let result = 1n;
        while (exponent > 0n) {
            if (exponent & 1n) result = result * base % MOD;
            base = base * base % MOD;
            exponent >>= 1n;
        }
        return result;
    };

    invFact[n] = modPow(fact[n], MOD - 2n);
    for (let i = n; i > 0; i--) {
        invFact[i - 1] = invFact[i] * BigInt(i) % MOD;
    }

    const combination = (total, chosen) =>
        fact[total] * invFact[chosen] % MOD * invFact[total - chosen] % MOD;

    const count = values => {
        if (values.length <= 2) return 1n;

        const root = values[0];
        const left = [];
        const right = [];
        for (let i = 1; i < values.length; i++) {
            (values[i] < root ? left : right).push(values[i]);
        }

        let ways = combination(values.length - 1, left.length);
        ways = ways * count(left) % MOD;
        ways = ways * count(right) % MOD;
        return ways;
    };

    return Number((count(nums) - 1n + MOD) % MOD);
};
Python 3 · LeetCode 可提交pow for modular inverse
from typing import List


class Solution:
    def numOfWays(self, nums: List[int]) -> int:
        mod = 10**9 + 7
        n = len(nums)
        fact = [1] * (n + 1)
        inv_fact = [1] * (n + 1)

        for i in range(1, n + 1):
            fact[i] = fact[i - 1] * i % mod

        inv_fact[n] = pow(fact[n], mod - 2, mod)
        for i in range(n, 0, -1):
            inv_fact[i - 1] = inv_fact[i] * i % mod

        def combination(total: int, chosen: int) -> int:
            return (
                fact[total]
                * inv_fact[chosen]
                % mod
                * inv_fact[total - chosen]
                % mod
            )

        def count(values: List[int]) -> int:
            if len(values) <= 2:
                return 1

            root = values[0]
            left = [value for value in values[1:] if value < root]
            right = [value for value in values[1:] if value > root]

            ways = combination(len(values) - 1, len(left))
            ways = ways * count(left) % mod
            ways = ways * count(right) % mod
            return ways

        return (count(nums) - 1) % mod
C++ · LeetCode 可提交long long modular arithmetic
class Solution {
private:
    static constexpr long long MOD = 1'000'000'007LL;
    vector<long long> fact;
    vector<long long> invFact;

    long long modPow(long long base, long long exponent) {
        long long result = 1;
        while (exponent > 0) {
            if (exponent & 1) result = result * base % MOD;
            base = base * base % MOD;
            exponent >>= 1;
        }
        return result;
    }

    long long combination(int n, int k) {
        return fact[n] * invFact[k] % MOD * invFact[n - k] % MOD;
    }

    long long count(const vector<int>& values) {
        if (values.size() <= 2) return 1;

        int root = values[0];
        vector<int> left;
        vector<int> right;
        for (int i = 1; i < static_cast<int>(values.size()); ++i) {
            if (values[i] < root) left.push_back(values[i]);
            else right.push_back(values[i]);
        }

        long long ways = combination(values.size() - 1, left.size());
        ways = ways * count(left) % MOD;
        ways = ways * count(right) % MOD;
        return ways;
    }

public:
    int numOfWays(vector<int>& nums) {
        int n = nums.size();
        fact.assign(n + 1, 1);
        invFact.assign(n + 1, 1);

        for (int i = 1; i <= n; ++i) {
            fact[i] = fact[i - 1] * i % MOD;
        }
        invFact[n] = modPow(fact[n], MOD - 2);
        for (int i = n; i > 0; --i) {
            invFact[i - 1] = invFact[i] * i % MOD;
        }

        return static_cast<int>((count(nums) - 1 + MOD) % MOD);
    }
};

替代方案

Pascal 三角形预处理组合数：使用 C[n][k] = C[n-1][k-1] + C[n-1][k]，思路直观，不需要费马小定理，但占用 O(n²) 额外空间。

先显式建 BST 再做树形 DP：插入所有节点后，根据左右子树大小计算组合数。朴素建树最坏仍为 O(n²)，但递归阶段不再复制子数组；若再用平衡/有序数据结构加速父节点定位，实现复杂度会显著上升。

面试追问

为什么左右组可以任意交错？

比较路径在根处分叉，左组永远不会进入右子树，反之亦然；跨组先后不影响组内节点的祖先关系。

为什么组合数是 C(L+R, L)？

根固定在第一位，余下 L+R 个位置只需选择其中 L 个给左序列，其余自动属于右序列。

有重复值怎么办？

当前证明依赖所有值互异。若允许重复，必须先规定重复值插入方向，并对相同值造成的不可区分排列去重。

能做到 O(n log n) 吗？

可以研究按值域与插入顺序构树，并避免每层线性划分；但需要更复杂的数据结构。此题 n≤1000，O(n²) 足够。

常见错误

忘记减去原数组

递归乘积天然把原有插入顺序算在内，而题目问的是“其他重排”。

只算顶层交错

左右子树内部也可能有多种合法重排，必须递归乘上两侧答案。

JavaScript 用 Number 模乘

乘积可能超过安全整数范围，精度丢失会在取模前发生，应使用 BigInt。

不保留组内相对顺序

当前层的交错只能决定左右两组的位置；每组具体顺序必须来自该子树自己的合法方案。
