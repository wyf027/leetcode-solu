二进制前缀

Binary Prefix Divisible By 5 · 让每个前缀逐位流过一个只有 5 个状态的余数机器。

题目

给定一个从下标 0 开始、仅由 0 和 1 组成的数组 nums。令 xᵢ 为二进制串 nums[0..i]（从最高位到最低位）所表示的整数。

返回布尔数组 answer；当且仅当 xᵢ 能被 5 整除时，answer[i] 为 true。

函数签名

prefixesDivBy5(nums: integer[]) → boolean[]

约束

  • 1 ≤ nums.length ≤ 10⁵
  • nums[i] 只能是 0 或 1

题解：只保存余数，不保存大数

核心洞察

向二进制末尾追加一位 b，新数就是 2 × old + b。判断是否被 5 整除只关心模 5 的余数，所以持续维护 remainder = (remainder × 2 + b) % 5 即可。余数为 0 时记录 true。

完整过程

  1. 令 remainder = 0，答案为空。
  2. 从左到右读每一位 bit。
  3. 按公式更新余数，把 remainder === 0 追加到答案。
  4. 扫描结束后返回答案。

正确性证明

不变式：处理完下标 i 后，remainder = xᵢ mod 5。初始尚无数字时余数为 0。假设处理上一位后不变式成立；追加当前位 b 得到 xᵢ = 2xᵢ₋₁ + b，因此更新式计算出的正是 xᵢ mod 5。于是 remainder === 0 当且仅当该前缀能被 5 整除。由归纳法，所有答案均正确。

边界情况

  • 单个 0：数值是 0，按数学定义可被 5 整除。
  • 前导零：不会影响公式和余数。
  • 长度达到 10⁵：不构造完整整数，因此不会溢出。
  • 连续多个可整除前缀：每个位置独立记录布尔值。

复杂度

扫描一次，时间复杂度 O(n)；除返回数组外只保存一个余数，额外空间 O(1)（返回结果占 O(n)）。

替代方案

可以用大整数保存每个完整前缀再取模，但数值位数随输入增长，会带来不必要的时间与空间成本；普通整数还会溢出。也可把 0～4 看作有限自动机的五个状态，本解法正是其紧凑实现。

四语言完整代码

class Solution {
    public List<Boolean> prefixesDivBy5(int[] nums) {
        List<Boolean> answer = new ArrayList<>(nums.length);
        int remainder = 0;
        for (int bit : nums) {
            remainder = (remainder * 2 + bit) % 5;
            answer.add(remainder == 0);
        }
        return answer;
    }
}

};

class Solution {
public:
    vector<bool> prefixesDivBy5(vector<int>& nums) {
        vector<bool> answer;
        answer.reserve(nums.size());
        int remainder = 0;
        for (int bit : nums) {
            remainder = (remainder * 2 + bit) % 5;
            answer.push_back(remainder == 0);
        }
        return answer;
    }
};

常见错误

  • 把新值写成 remainder + bit，忘记左移相当于乘 2。
  • 先构造完整整数，导致溢出或无谓的大整数开销。
  • 误认为 0 不能被 5 整除。
  • 返回字符串 "true"，而非布尔值 true。

面试追问

  • 改成判断能否被 k 整除？ 把模数 5 换成正整数 k，思路不变。
  • 输入改成十进制数字流？ 更新式改为 (remainder × 10 + digit) % k。
  • 为何不会溢出？ 余数始终在 0～4，乘 2 再加 1 最大为 9。
  • 能否在线处理？ 可以；每到一位立即输出一次判断，无需保存历史位。
