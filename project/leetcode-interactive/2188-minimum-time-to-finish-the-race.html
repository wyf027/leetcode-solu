完成比赛的最少时间

Minimum Time to Finish the Race

轮胎越跑越慢，进站又需要时间。你会在哪一圈换胎？

无限条轮胎每圈后可以进站起跑选胎免费

题目

给定二维整数数组 tires，每个元素 tires[i] = [fᵢ, rᵢ] 描述一种轮胎。同一条轮胎连续使用时，第 x 圈耗时为 fᵢ × rᵢ^(x − 1) 秒。这里的 x 是这条轮胎的连续使用圈数，不是整场比赛的圈号。

比赛共有 numLaps 圈。起跑时可免费选任意轮胎；每完成一圈，可花 changeTime 秒换上一条任意类型的新轮胎，包括相同类型。每种轮胎数量无限。返回完成所有圈数的最少总秒数。

例如 [3, 2] 连跑三圈，单圈时间依次为 3、6、12 秒；换上同类新胎后，单圈时间重新从 3 秒开始。到达终点后无需换胎。

参数与返回值

minimumFinishTime(tires, changeTime, numLaps) → integer
  tires: integer[][]    每种轮胎的 [首圈秒数, 衰减倍率]
  changeTime: integer  每次换胎秒数
  numLaps: integer     总圈数

约束

  • 1 ≤ tires.length ≤ 10⁵
  • tires[i].length = 2
  • 1 ≤ fᵢ, changeTime ≤ 10⁵
  • 2 ≤ rᵢ ≤ 10⁵
  • 1 ≤ numLaps ≤ 1000

官方示例

示例 1

tires = [[2,3],[3,4]]
changeTime = 5
numLaps = 4
输出：21

轮胎 0 跑两圈：2 + 6 秒；花 5 秒换同类新胎，再跑两圈：2 + 6 秒。总计 21 秒。

示例 2

tires = [[1,10],[2,2],[3,4]]
changeTime = 6
numLaps = 5
输出：25

轮胎 1 跑两圈，换同类新胎再跑两圈，最后换轮胎 0 跑一圈：2 + 4 + 6 + 2 + 4 + 6 + 1 = 25 秒。

先想一想：一条轮胎真的需要连续跑到第 1000 圈吗？

题解 · 把比赛切成短段

核心洞察：指数衰减让长段失去意义

对轮胎 [f, r]，如果下一圈旧胎耗时 lap > changeTime + f，换一条同类型的新胎并跑这一圈就更快。之后新胎也始终比继续使用旧胎快。因此可以截掉从这一圈开始的长段。

由于 r ≥ 2，被保留的第 k 圈满足 2^(k−1) ≤ 1 + changeTime/f ≤ 100001，所以每种轮胎最多保留 17 圈。实现通过阈值自然终止，不依赖魔法数组长度；相等时保留也正确。

完整过程

  1. 预处理 best[k]：任意一种新胎不换胎连跑 k 圈的最小累计时间。对每个轮胎累加等比增长的单圈时间，超过阈值后停止。
  2. 定义 dp[i] 为完成前 i 圈的最少时间，设 dp[0] = 0。
  3. 枚举最后一段长度 k。若前面还有圈数，进入最后一段前支付一次换胎费；若这是第一段，则不收费。
  4. 从小到大计算 dp[1…numLaps]，返回 dp[numLaps]。
dp[i] = min { dp[i − k] + best[k] + (i == k ? 0 : changeTime) }
1 ≤ k ≤ min(i, L)，且 best[k] 有限

为什么正确

  1. 截断不会失去最优解。 若一个连续段包含单圈耗时超过 changeTime + f 的圈，在该圈前换成同类新胎更便宜，而且直到原段末尾，每一圈都不会更慢。故可将该段拆短，得到更优合法方案。某个最优解必能仅由保留的短段组成。
  2. best 的含义成立。 每个保留长度的同胎连跑时间均被枚举，取所有轮胎的最小值，恰为该长度的最优段代价。段内没有换胎。
  3. 递推完备且合法。 每个最优方案都有某个最后一段长度 k。其前缀若非最优，可用更优前缀替换，故必对应 dp[i−k]；段与段之间只需一次固定换胎费。反过来，每个递推候选都能由前缀和一条新胎的末段组成合法方案。
  4. 归纳。 空前缀代价 0 正确。计算 dp[i] 时所依赖状态均已正确，枚举全部合法末段后取最小值，因此最终答案正确。

边界与数值

  • 一圈答案是最小 f；不得在起跑或终点额外计换胎费。
  • 相同轮胎类型可以反复使用，每次换的是新胎，不继承磨损。
  • 等于阈值时继续保留，不影响最优性；代码使用严格的超出条件停止。
  • 每个轮胎至少保留第一圈，因而所有 dp[i] 都可由单圈段到达。
  • 单圈每次换新胎提供上界 numLaps × min(f) + (numLaps−1) × changeTime ≤ 199900000，答案可用 32 位整数。增长过程的临时乘积可能超过 32 位，因此 Java / C++ 使用 64 位；JavaScript 的数值在本题计算范围内可精确表示整数。

复杂度

记轮胎种数为 m，圈数为 n，保留最大段长为 L ≤ min(n,17)。预处理 O(mL)，动态规划 O(nL)，总时间 O((m+n)L)。以下实现分配长度为 n+1 的数组，额外空间 O(n)。

替代方案

可将圈数 0…n 看作有向无环图的节点，每条边表示跑一段，按圈数顺序求最短路；本质上就是同一个 DP。记忆化搜索也能表达相同递推，但要注意递归深度。若直接记录轮胎种类与已连续使用圈数，状态数量随 m 膨胀；若不截断而预处理到 n，需 O(mn+n²) 时间并面临巨大等比数值。

常见错误

  • 只挑首圈最快的轮胎：忽略衰减倍率，示例 2 就需要不同类型组合。
  • 把 best[k] 写成第 k 圈耗时：它必须是前 k 圈的总和。
  • 对每段都加换胎费却忘记第一段免费，或误以为同类型换胎免费。
  • 先让整型乘法溢出再赋给 long：Java 应先用 long 保存单圈时间。
  • 把阈值当成完整贪心策略：它只证明可以截断，段长仍需全局 DP。

面试追问

  • 怎么输出换胎方案？ 记录每个 best[k] 对应轮胎及每个 dp[i] 选择的 k，从 n 回溯即可，演示轨迹采用此方式。
  • 如果 r 可以为 1？ 指数增长和 17 圈上界不再成立；常速轮胎可能适合跑完全部 n 圈，需要另行处理或放宽段长。
  • 换胎时间依赖前后类型呢？ 仅保留一个 best[k] 会丢失转移所需的类型信息，需要把末尾轮胎类型加入状态。

Java

import java.util.Arrays;

class Solution {
    public int minimumFinishTime(int[][] tires, int changeTime, int numLaps) {
        long inf = Long.MAX_VALUE / 4;
        long[] best = new long[numLaps + 1];
        Arrays.fill(best, inf);
        int maxLen = 0;
        for (int[] tire : tires) {
            long lap = tire[0], total = 0;
            long limit = (long) changeTime + tire[0];
            for (int k = 1; k <= numLaps && lap <= limit; k++) {
                total += lap;
                best[k] = Math.min(best[k], total);
                maxLen = Math.max(maxLen, k);
                lap *= tire[1];
            }
        }
        long[] dp = new long[numLaps + 1];
        Arrays.fill(dp, inf);
        dp[0] = 0;
        for (int i = 1; i <= numLaps; i++) {
            for (int k = 1; k <= Math.min(i, maxLen); k++) {
                if (best[k] == inf) continue;
                long fee = i == k ? 0 : changeTime;
                dp[i] = Math.min(dp[i], dp[i - k] + best[k] + fee);
            }
        }
        return (int) dp[numLaps];
    }
}

from typing import List

class Solution:
    def minimumFinishTime(self, tires: List[List[int]],
                          changeTime: int, numLaps: int) -> int:
        inf = float("inf")
        best = [inf] * (numLaps + 1)
        max_len = 0
        for f, r in tires:
            lap, total, k = f, 0, 1
            while k <= numLaps and lap <= changeTime + f:
                total += lap
                best[k] = min(best[k], total)
                max_len = max(max_len, k)
                lap *= r
                k += 1
        dp = [inf] * (numLaps + 1)
        dp[0] = 0
        for i in range(1, numLaps + 1):
            for k in range(1, min(i, max_len) + 1):
                if best[k] == inf:
                    continue
                fee = 0 if i == k else changeTime
                dp[i] = min(dp[i], dp[i - k] + best[k] + fee)
        return int(dp[numLaps])
