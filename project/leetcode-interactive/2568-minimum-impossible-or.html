LEETCODE 2568最小无法得到的或值

给定整数数组，哪些正整数能由某个子序列的按位或得到？先别急着看结论，用下面的位轨实验亲手找到第一个缺口。

Problem

题目要求

给你一个下标从 0 开始的整数数组 nums。如果能选取一个非空子序列，使其中元素的按位或等于 x，则称 x 可表达。返回无法表达的最小正整数。

形式化定义

存在下标严格递增的若干元素，且它们的按位或结果恰好为 x：

nums[index₁] | nums[index₂] | … | nums[indexₖ] = x

目标是在所有正整数中，找出最小的、无法由上述方式得到的值。

约束

  • 1 ≤ nums.length ≤ 10⁵
  • 1 ≤ nums[i] ≤ 10⁹
  • 返回值类型：integer
示例 1COMPOSABLE
输入nums = [2,1]
输出4

1 和 2 已在数组中，且 2 | 1 = 3，因此 1、2、3 均可表达；4 不可表达。

示例 2FIRST GAP
输入nums = [5,3,2]
输出1

无法从任意非空子序列得到 1，因此它就是最小无法表达的正整数。

Solution

准备好揭晓规律了吗？

题解、证明、复杂度与四种语言代码独立收起，避免在首屏直接泄露答案。

The Reveal

第一个缺失的 2 的幂

核心洞察

答案一定是最小的、不在数组中的 2 的幂。从 1 开始检查 1, 2, 4, 8, …，遇到第一个缺失值就返回。

完整过程

  1. 把 nums 放入哈希集合。
  2. 令候选值 answer = 1。
  3. 只要集合包含候选值，就将其翻倍。
  4. 返回第一个不在集合中的候选值。

正确性证明

为什么缺失的 2 的幂不可表达？要让 OR 结果恰为 2ᵏ，所选数字都不能含其他置位；又必须含第 k 位。因此所选数字只能是 2ᵏ 本身。它不在数组中就无法得到。
为什么更小的数都可表达？设第一个缺失幂为 2ᵏ，则 1,2,…,2ᵏ⁻¹ 这些幂都在数组中。任意小于 2ᵏ 的正整数，都能由其二进制中对应的这些幂按位或得到。
结论2ᵏ 自身不可表达，而所有更小的正整数均可表达，所以它正是最小无法表达的值。

边界与复杂度

  • 若 1 缺失，立即返回 1。
  • 重复元素不影响集合判断。
  • 非 2 的幂无需单独处理。
  • 在题目上界下，答案至多为 2³⁰。
时间 O(n)空间 O(n)

替代方案

可以遍历数组，仅把 2 的幂记录进位掩码，再找首个未记录的位，将额外空间压到 O(1)。不过哈希集合版本更直观，已满足线性时间。

常见错误

  • 枚举所有子序列或所有 OR 结果，复杂度失控。
  • 误以为答案是最小缺失正整数，而忽略 OR 的位结构。
  • 在 JavaScript 中反复左移到符号位；本题用乘 2 更清晰。

面试追问

  • 能否证明答案一定是 2 的幂？
  • 如何将额外空间优化到常数？
  • 若把 OR 改成 AND，结构会怎样变化？

四语言实现

Solution.javaHashSet
import java.util.HashSet;
import java.util.Set;

class Solution {
    public int minImpossibleOR(int[] nums) {
        Set<Integer> seen = new HashSet<>();
        for (int num : nums) {
            seen.add(num);
        }

        int answer = 1;
        while (seen.contains(answer)) {
            answer *= 2;
        }
        return answer;
    }
}

复盘问题

为什么数组里的 3 不能帮助表达 1 或 2？

按位或只能把位从 0 变成 1，不能清除 3 已有的置位，所以使用 3 得到的结果至少同时保留其两个低位。

为什么检查的候选值只需不断翻倍？

证明已经把答案限定为某个 2 的幂，因此按 1、2、4、8 的顺序检查即可覆盖所有可能答案。
