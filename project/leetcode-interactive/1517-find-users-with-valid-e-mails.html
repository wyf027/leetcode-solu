Problem

题意

返回顺序任意

给定用户表 Users，找出邮箱格式有效的用户，并返回这些用户的全部三列信息。有效邮箱由“前缀 + 固定域名”组成：

前缀 prefix

必须以英文字母开头；其余位置只允许英文字母、数字、下划线 _、点 . 或连字符 -。

域名 domain

必须严格等于小写 @leetcode.com，不能换域名、改变大小写或追加内容。

核心洞察

这是一道正则筛选题。整条字符串必须匹配：一个英文字母开头，随后是零个或多个允许字符，最后紧接固定小写域名。MySQL 可用 REGEXP，并用 ^ 与 $ 锚定整串。

^[A-Za-z][A-Za-z0-9_.-]*@leetcode[.]com$

把点写成 [.]，可直观表达“字面量点”，避免把 . 误当成任意字符。

完整过程

  1. ^ 从字符串开头开始，禁止前面出现额外字符。
  2. [A-Za-z] 强制前缀的第一个字符是英文字母。
  3. [A-Za-z0-9_.-]* 接受前缀剩余的合法字符；* 允许没有剩余字符。
  4. @leetcode[.]com 匹配唯一允许的、全小写域名。
  5. $ 锚定结尾，禁止域名后还有字符。

MySQL 官方可提交方案

SELECT user_id, name, mail
FROM Users
WHERE mail REGEXP '^[A-Za-z][A-Za-z0-9_.-]*@leetcode[.]com$';

正确性说明

充分性：若一行被返回，开头锚点和首字符类保证前缀以字母开头；中间字符类保证前缀余下部分只含允许字符；固定尾部与结尾锚点保证域名恰为小写 @leetcode.com。因此其邮箱有效。

必要性：任意有效邮箱的首字符必落在 [A-Za-z]，其余前缀字符都落在允许字符类中，且结尾正是固定域名，所以它一定能匹配该正则并被返回。

边界情况

  • 单字母前缀（如 a@leetcode.com）有效。
  • 以点、数字、下划线或连字符开头无效。
  • 前缀内部的点和连字符允许，包括域名前的连字符。
  • #、空格、加号等不在集合中的字符无效。
  • 域名大小写不同、域名后有多余字符、或使用其他域名均无效。

复杂度

设共有 n 行、邮箱平均长度为 m。正则扫描的时间复杂度为 O(nm)，除结果集外额外空间为 O(1)（数据库正则引擎内部开销不计）。

替代方案

PostgreSQL 可用 ~；SQL Server 没有等价的内建完整正则，通常需组合 LIKE/PATINDEX 或使用外部正则能力。拆分 LEFT、RIGHT、字符排除也能实现，但更冗长且更容易漏掉锚定或字符规则。

import java.util.*;
import java.util.regex.Pattern;

class Solution {
    record User(int userId, String name, String mail) {}
    private static final Pattern VALID = Pattern.compile(
        "^[A-Za-z][A-Za-z0-9_.-]*@leetcode[.]com$"
    );

    public List<User> validEmails(List<User> users) {
        List<User> answer = new ArrayList<>();
        for (User user : users) {
            if (VALID.matcher(user.mail()).matches()) answer.add(user);
        }
        return answer;
    }
}
function validEmails(users) {
  const valid = /^[A-Za-z][A-Za-z0-9_.-]*@leetcode[.]com$/;
  return users.filter((user) => valid.test(user.mail));
}

#include <regex>

struct User { int userId; string name; string mail; };

vector<User> validEmails(const vector<User>& users) {
    const regex valid(R"(^[A-Za-z][A-Za-z0-9_.-]*@leetcode[.]com$)");
    vector<User> answer;
    for (const User& user : users) {
        if (regex_match(user.mail, valid)) answer.push_back(user);
    }

面试追问

  • 为什么必须使用 ^ 和 $？去掉后可能只匹配字符串中的一段。
  • 为什么不能把第一个字符并入后面的字符类？那会错误接受数字或点开头。
  • 数据库的正则匹配是否区分大小写？不同数据库、排序规则与操作符行为不同，应明确写出字母范围，并对域名规则单独确认。
  • 生产环境如何优化？正则通常难以利用普通索引；高数据量场景可在写入时校验，或维护经约束的规范化字段。

常见错误

  • 使用 LIKE '%@leetcode.com'，遗漏首字符与非法字符限制。
  • 写 leetcode.com 却忘记转义点号，导致点可匹配任意字符。
  • 漏掉结尾锚点，错误接受 @leetcode.com.cn。
  • 用 \w 代替明确字符集；其跨引擎语义可能不同，而且不包含连字符与点。
  • 忽略域名必须是小写这一要求，受数据库默认不区分大小写的排序规则影响。
