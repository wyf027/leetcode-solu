示例 3

约束

  • 1 ≤ nums.length ≤ 10⁵

返回约定

若正确答案是元素 1 和 2，那么 [1,2] 与 [2,1] 均可接受。

04 / Solution

准备好后，再揭开完整题解

Bucket sort solution

桶排序：让“频率”成为下标

核心洞察：长度为 n 的数组中，一个元素的频率只可能落在 1…n。创建 n+1 个桶，把频率为 f 的元素放入 bucket[f]，再从 n 向 1 扫描，就会天然按频率从高到低访问元素，无需对全部不同元素排序。

完整过程

1
计数
用哈希表记录每个元素的出现次数。
2
入桶
遍历哈希表，将元素 x 放入 buckets[count[x]]。
3
逆序收集
从最高频率桶向下扫描，依次加入答案，得到 k 个元素时立即返回。

正确性证明

计数正确：哈希表对数组中每次出现都累加一次，因此 count[x] 等于元素 x 的真实频率。

归档正确：元素 x 被放在下标为 count[x] 的桶中，所以同一桶内元素频率相同。

选择正确：逆序扫描桶时，任何尚未访问的桶下标都不大于当前下标，因此先收集的元素频率不低于后收集的元素。收集前 k 个后，它们正是频率最高的 k 个元素。题目保证答案唯一，故返回集合唯一。

复杂度与边界

时间：O(n)。计数、入桶和扫描桶都至多线性。

空间：O(n)。哈希表、桶与结果合计线性空间。

  • 单元素：唯一元素进入频率 1 的桶。
  • 包含负数或零：哈希键不要求连续，不受影响。
  • k 等于不同元素数：最终收集全部不同元素。
  • 多个元素同频：可共存于同一桶；答案顺序无需固定。

替代方案

小顶堆：维护大小为 k 的堆，时间 O(n log k)，额外空间与不同元素数及 k 有关。适合 k 很小或流式扩展。

快速选择：对“元素—频率”对做 partition，平均 O(n)，但最坏可到 O(n²)；实现和证明更复杂。

全排序：O(m log m)（m 为不同元素数），直观但最坏为 O(n log n)，不满足进阶目标。

四语言完整代码

均采用相同的“哈希计数 + 频率桶”策略，可直接适配对应 LeetCode 签名。

Java 
import java.util.*;

class Solution {
    public int[] topKFrequent(int[] nums, int k) {
        Map<Integer, Integer> count = new HashMap<>();
        for (int num : nums) {
            count.put(num, count.getOrDefault(num, 0) + 1);
        }

        @SuppressWarnings("unchecked")
        List<Integer>[] buckets = new List[nums.length + 1];
        for (Map.Entry<Integer, Integer> entry : count.entrySet()) {
            int frequency = entry.getValue();
            if (buckets[frequency] == null) {
                buckets[frequency] = new ArrayList<>();
            }
            buckets[frequency].add(entry.getKey());
        }

        int[] answer = new int[k];
        int index = 0;
        for (int frequency = nums.length; frequency >= 1 && index < k; frequency--) {
            if (buckets[frequency] == null) continue;
            for (int value : buckets[frequency]) {
                answer[index++] = value;
                if (index == k) break;
            }
        }
        return answer;
    }
}

var topKFrequent = function(nums, k) {
    const count = new Map();
    for (const num of nums) {
        count.set(num, (count.get(num) || 0) + 1);
    }

    const buckets = Array.from(
        { length: nums.length + 1 },
        () => []
    );
    for (const [value, frequency] of count) {
        buckets[frequency].push(value);
    }

    const answer = [];
    for (let frequency = nums.length;
         frequency >= 1 && answer.length < k;
         frequency--) {
        for (const value of buckets[frequency]) {
            answer.push(value);
            if (answer.length === k) break;
        }
    }
    return answer;
};
Python 
from typing import List
from collections import Counter

class Solution:
    def topKFrequent(self, nums: List[int], k: int) -> List[int]:
        count = Counter(nums)
        buckets = [[] for _ in range(len(nums) + 1)]

        for value, frequency in count.items():
            buckets[frequency].append(value)

        answer = []
        for frequency in range(len(nums), 0, -1):
            for value in buckets[frequency]:
                answer.append(value)
                if len(answer) == k:
                    return answer

        return answer
C++ 
#include <vector>
#include <unordered_map>
using namespace std;

class Solution {
public:
    vector<int> topKFrequent(vector<int>& nums, int k) {
        unordered_map<int, int> count;
        for (int num : nums) {
            ++count[num];
        }

        vector<vector<int>> buckets(nums.size() + 1);
        for (const auto& [value, frequency] : count) {
            buckets[frequency].push_back(value);
        }

        vector<int> answer;
        answer.reserve(k);
        for (int frequency = static_cast<int>(nums.size());
             frequency >= 1 && static_cast<int>(answer.size()) < k;
             --frequency) {
            for (int value : buckets[frequency]) {
                answer.push_back(value);
                if (static_cast<int>(answer.size()) == k) {
                    return answer;
                }
            }
        }
        return answer;
    }
};

面试追问

  • 如果数据是流式输入？维护频率表，并讨论堆或专用 heavy-hitters 算法。
  • 如果只允许 O(k) 额外空间？哈希计数本身通常需要按不同元素数占用空间，需要进一步澄清输入模型。
  • 如何稳定处理同频元素？题目不要求顺序；若业务要求，可在桶内按指定规则排序，但会改变复杂度。
  • 为什么桶数组长度是 n+1？下标直接表示频率，最大下标是 n，下标 0 留空。

常见错误

  • 对原数组排序，得到的是数值顺序而不是频率顺序。
  • 只给每个频率保存一个元素，覆盖同频的其他元素。
  • 从低频桶向高频桶扫描，返回了最低频元素。
  • 收集整个桶后才判断长度，导致结果超过 k。
  • 误以为答案数组必须与示例顺序一致。
