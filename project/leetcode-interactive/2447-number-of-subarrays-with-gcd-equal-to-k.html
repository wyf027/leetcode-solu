COUNT THE CONTIGUOUS

最大公因数等于 K 的
子数组数目

Number of Subarrays With GCD Equal to K

给定整数数组 nums 和整数 k，统计其中有多少个连续且非空的子数组，其所有元素的最大公因数恰好等于 k，返回这个数量。

最大公因数：能够整除这些元素的最大正整数。不同位置的子数组分别计数，即使它们的元素相同。

输入：nums: int[], k: int返回：int官方题目 ↗

01 / 从示例理解目标

示例 1

输入：nums = [9,3,1,2,6,3], k = 3
输出：4

符合条件的区间（下标从 0 开始）为 [0,1]、[1,1]、[4,5]、[5,5]，对应 [9,3]、[3]、[6,3]、[3]。

示例 2

输入：nums = [4], k = 7
输出：0

只有一个非空子数组 [4]，其最大公因数是 4，因此没有符合条件的子数组。

03 / 题解 · 固定左端点，累积 GCD

核心洞察

区间向右增加一个数后，新的最大公因数是 gcd(旧 GCD, 新元素)。它一定整除旧 GCD。固定左端点后，不需要反复扫描整个区间，只更新一个变量 g 即可。

若 g % k ≠ 0，后续不可能得到 k，可以停止当前左端点的扩展。仅仅 g > k 并不能停止，例如 gcd(6,3) = 3。

已发现的区间

    完整过程

    1. 答案初始化为 0。依次枚举左端点 i。
    2. 每轮令 g = 0，利用 gcd(0,x) = x 自然处理首个元素。
    3. 右端点 j 从 i 到 n−1，更新 g = gcd(g, nums[j])。
    4. 若 g 等于 k，答案增加 1；仍继续向右，可能发现更多有效区间。
    5. 若 g 不是 k 的倍数，结束当前内层循环。否则继续扩展，最终返回答案。

    示例 1 中，i = 0 时 GCD 依次为 9 → 3（命中）→ 1（停止）。i = 1 时先命中单元素 3，遇到 1 后停止。i = 2、3 分别从 1、2 开始立即停止；i = 4 时 6 → 3 命中，i = 5 时单元素 3 再命中，总计 4。

    正确性

    区间不变式：处理 (i,j) 后，g 等于 nums[i..j] 的最大公因数。初始由 gcd(0,nums[i]) 得到；归纳步骤由最大公因数的结合律保证。

    剪枝安全：后续区间 GCD h 必须整除 g。若 h 能等于 k，则 k 必须整除 g。因此当 g % k ≠ 0 时，任何更长区间都无效，跳过它们不会漏计。

    不重不漏：每个非空区间由唯一的 (i,j) 确定。未剪枝的区间全部访问，且仅当 GCD 等于 k 才计数；被剪枝的区间已证明无效，所以最终计数准确。

    复杂度与边界

    • 设 M 为元素最大值。保守时间上界 O(n² log M)：最多枚举 n(n+1)/2 个区间，每次欧几里得算法为 O(log M)。
    • 提交算法额外空间 O(1)，不包含输入。演示为回放保留状态，额外空间 O(n²)。
    • 全部元素为 k 时，答案为 n(n+1)/2；n = 1000 时为 500500，32 位整数足够。
    • 单元素、k = 1、没有任何可行区间均直接覆盖。正整数约束保证取模除数 k 非零。

    替代方案

    按右端点维护“所有后缀的 GCD → 出现次数”。加入 x 后，将旧状态 (g,c) 合并到 gcd(g,x)，另加入单元素 x；累加 GCD 为 k 的次数。

    不同 GCD 构成整除链，严格下降时至少减半，所以每轮仅 O(log M) 个状态。计入每次 GCD 的成本，保守时间 O(n log² M)，额外空间 O(log M)。本题 n ≤ 1000，双循环更直接。

    也可在 k 的倍数形成的连续段内把元素除以 k，转为计数 GCD 等于 1 的区间，但不自动得到普通滑动窗口计数公式。

    常见错误

    • 把“每个元素都是 k 的倍数”当作充分条件：[6,12]、k = 3 的 GCD 是 6，答案为 0。
    • g 等于 k 后立即 break，会漏掉后续仍然为 k 的区间。
    • 每次换左端点忘记重置 g，导致不同区间混在一起。
    • 只用 g < k 剪枝虽然正确，但会错过 g > k 且不能被 k 整除的提前停止机会。
    • 只统计不同的元素序列，会漏掉不同位置的相同子数组。

    面试追问

    为什么不能像求和一样用前缀 GCD 相除？ GCD 没有对应的逆运算，前缀信息会丢失细节。例如 [2,6,3] 与 [2,2,3] 的前缀 GCD 都为 [2,2,1]，但后两项的区间 GCD 分别为 3、1。

    n 提高到 10⁵ 怎么办？ 使用后缀 GCD 状态压缩，并将答案升级为 64 位整数；JavaScript 在该规模下的计数仍处于安全整数范围内。

    GCD 变成 1 时是否总能停止？ 当 k > 1 可以停止；当 k = 1 时更长区间全都有效，可以一次累加剩余右端点数量。

    均采用官方方法签名。C++ 使用 C++17 的 std::gcd。代码仅生成，尚未编译或运行。

    Java

    class Solution {
    private int gcd(int a, int b) {
        while (b != 0) {
            int r = a % b;
            a = b;
            b = r;
        }
        return a;
    }

    public int subarrayGCD(int[] nums, int k) {
        int answer = 0;
        for (int i = 0; i < nums.length; i++) {
            int g = 0;
            for (int j = i; j < nums.length; j++) {
                g = gcd(g, nums[j]);
                if (g == k) answer++;
                if (g % k != 0) break;
            }
        }
        return answer;
    }
}

    let answer = 0;

        }
    }
    return answer;
};

    from math import gcd
from typing import List

class Solution:
    def subarrayGCD(self, nums: List[int], k: int) -> int:
        answer = 0
        for i in range(len(nums)):
            g = 0
            for j in range(i, len(nums)):
                g = gcd(g, nums[j])
                if g == k:
                    answer += 1
                if g % k != 0:
                    break
        return answer
