你可以工作的最大周数

Maximum Number of Weeks for Which You Can Work

每周推进一个阶段任务。如何安排项目，才能让工作持续更久？

官方题目 ↗

01 / 任务规则

给定整数数组 milestones，共有 n 个项目，编号为 0 … n − 1。milestones[i] 表示项目 i 需要完成的阶段任务数。

  • 每周必须工作，并且恰好完成某个项目的一个阶段任务。
  • 相邻两周选择的项目必须不同，不能通过休息一周来绕过限制。
  • 所有任务完成，或剩余任务无法满足相邻周规则时，工作结束。

返回可以连续工作的最大周数，不要求一定完成所有任务。

约束
n == milestones.length
1 ≤ n ≤ 10⁵
1 ≤ milestones[i] ≤ 10⁹

02 / 官方示例

示例 1 · 全部完成

输入：milestones = [1,2,3]
输出：6

可按项目编号 0 → 2 → 1 → 2 → 1 → 2 工作，每个箭头代表进入下一周，共 6 周。

示例 2 · 有任务留存

输入：milestones = [5,2,1]
输出：7

可按 0 → 1 → 0 → 1 → 0 → 2 → 0 工作 7 周。项目 0 还剩 1 个任务，但第 8 周继续选它会违反规则。

05 / 独立题解

先尝试找出限制工作周数的关键，再展开推导。

核心洞察：谁需要最多的“间隔”？

记任务总数为 S，单个项目的最大任务数为 M，其余项目总数为 R = S − M。最大的项目需要其他项目来隔开；R 个其他任务最多形成 R + 1 个放置位置。

最大项目： A · A · A · A
其他任务：   B   B   C

答案 = min(S, 2 × R + 1)

完整过程

  1. 遍历数组，同时累加 S 并更新 M，无需排序。
  2. 计算其他项目的任务总数 R = S − M。
  3. 若 M > R + 1，最大项目只能安排 R + 1 次，加上其他任务共 2R + 1 周。
  4. 否则可以安排全部任务，返回 S。

示例 2：S = 8，M = 5，R = 3，其他任务只能隔开 4 个最大项目任务，所以可工作 7 周，留下 1 个任务。示例 1：S = 6，M = 3，R = 3，可以全部完成。

正确性证明

上界。每周消耗一个任务，因此答案不超过 S。若安排了 a 个最大项目任务，相邻的这些任务之间至少要有 a − 1 个其他任务，所以 a ≤ R + 1，总周数也不超过 2R + 1。

最大项目过多时可达上界。当 M > R + 1，把所有其他任务任意排成 x₁…xR，构造 A,x₁,A,x₂,…,A,xR,A。其他任务之间都有 A 隔开，且它们都不是 A，因此整个序列合法，长度恰为 2R + 1。

较均衡时全部可排。当 M ≤ R + 1，即 M ≤ ⌈S/2⌉，使用经典的无相邻重复排列构造：按项目任务数从大到小分组，将任务依次填入下标 0,2,4,…,1,3,5,…。同一组在同一奇偶位置段中间隔为 2。若某组跨越偶数段末尾与奇数段开头，降序和每组不超过 ⌈S/2⌉ 的条件保证两部分不会落在相邻位置；首组恰好占满偶数段时也不会跨段。因此相邻位置的项目不同，可以用完所有 S 个任务。这一构造仅用于说明可行性，计数解法无需实际生成序列。

两个分支都达到对应上界，所以 min(S, 2R + 1) 是最大周数。

边界与复杂度

  • 仅有一个项目：R = 0，只能工作 1 周。
  • M = R + 1 恰好能用完，最大项目占据首尾。
  • 最大值并列无需特殊处理，任选一个作为 M 对应项目即可。
  • 时间复杂度 O(n)，额外空间 O(1)。
  • 总和最大为 10¹⁴：Java 用 long，C++ 用 long long；Python 整数自动扩展；JavaScript 的 Number 在此范围内可精确表示整数，避免位运算和大数组展开求最大值。

四语言完整实现

Java

class Solution {
    public long numberOfWeeks(int[] milestones) {
        long sum = 0, max = 0;
        for (int count : milestones) {
            sum += count;
            max = Math.max(max, count);
        }
        long rest = sum - max;
        return Math.min(sum, 2 * rest + 1);
    }
}

替代方案

若必须输出具体排程，可以使用最大堆，每次选择剩余任务最多且不等于上周的项目，把上周项目暂存一轮再放回。时间为 O(n + W log n)，堆空间为 O(n)，其中 W 是实际输出的周数。本题 W 可达 10¹⁴，逐周模拟无法适应完整约束，直接统计更合适。实验台只在小规模输入上采用线性扫描的逐周选择。

常见错误

  • 直接返回总和，忽略单项目任务占比过高的情况。
  • 把上界写成 2R，漏掉首尾可多放的一个任务。
  • 把其他项目只当成“项目个数”，而非它们的任务总数。
  • 用 32 位整数累加，或用 JavaScript 位运算截断大数。
  • 误以为可以空闲一周后继续做同一项目，题目要求连续工作。

面试追问

需要输出项目序列怎么办？使用暂存上周项目的最大堆，但必须考虑输出规模；也可输出压缩方案。同一项目需要间隔至少 k 周呢？本题的两个分支公式不能直接照搬，需要分析冷却约束及最大频次并列数量。允许空闲周呢？需先明确目标是完成的工作周数还是包含空闲的总时长；约束与优化目标都发生了变化。
