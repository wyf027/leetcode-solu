王位继承顺序

Throne Inheritance · 维护家族树，随时读出仍在世的合法继承序列

Problem

题意转述

王国由国王及其后代组成。孩子会按出生先后加入家族，成员也可能去世。继承顺序总是从国王开始：优先进入某人的子嗣分支，年长的孩子在年幼的孩子之前；一个分支处理完后，再回到上一代寻找后续分支。

死亡只表示该成员不再出现在最终名单中，不会删除这个人的家族位置，也不会阻断其后代。请设计一个支持出生、死亡标记和查询当前继承顺序的类。

关键语义
家族关系永久保留；查询时只过滤已死亡成员。
顺序语义
同一父母的孩子严格按出生先后排列，不能用无序集合代替。

类与方法

ThroneInheritance(string kingName)使用国王姓名初始化对象。
void birth(string parentName, string childName)记录 parentName 新增一个孩子 childName。
void death(string name)将 name 标记为死亡，不改变家族结构。
string[] getInheritanceOrder()返回当前继承顺序，排除所有已死亡成员。

独立题解

先完成观察，再展开完整算法、证明、复杂度与四语言代码。收起时焦点会回到本按钮。

核心洞察：家族树的先序遍历

1
结构与状态分离

出生只向父母的孩子数组末尾追加，形成有序多叉树；死亡只进入集合，不删除节点。

2
查询就是先序遍历

先处理本人，再按出生先后处理每个孩子的整棵子树。遇到死者时跳过输出，但仍继续进入其孩子。

完整过程

  1. 保存根节点 king。
  2. 用哈希表 children[name] 保存每个人按出生时间排列的孩子数组。
  3. birth 将新孩子追加到父母数组末尾，并初始化孩子自己的空数组。
  4. death 将名字加入死亡集合。
  5. 查询时从国王开始做迭代式先序遍历。栈后进先出，因此孩子必须逆序压栈，弹出时才会恢复从年长到年幼的顺序。
  6. 每次弹出姓名：若不在死亡集合中就加入答案；无论是否死亡，都继续压入其孩子。

正确性证明

局部顺序正确。孩子数组按出生先后保存。逆序压栈后，年长孩子先弹出，所以兄弟姐妹顺序符合规则。
分支顺序正确。栈先完整处理当前孩子的子树，再处理其弟妹，正是题目 Successor 规则的深度优先顺序。
死亡处理正确。死亡成员仅不加入答案，其子节点仍被压栈，因此只过滤本人而不破坏后代位置。
结论。从根开始每人恰好访问一次；由局部与分支顺序可知访问序列唯一合法，过滤死亡成员后即为答案。

复杂度

birth：O(1)数组尾部追加，均摊常数时间。
death：O(1)哈希集合插入，均摊常数时间。
query：O(N)访问全部 N 名成员；额外栈与答案 O(N)。

边界情况

  • 只有国王时，查询返回国王；若国王已死亡则返回空数组。
  • 死亡成员的后代仍参与继承。
  • 同一父母有许多孩子时必须保持出生顺序。
  • 家族可能退化成深链，迭代遍历可避免递归栈溢出。
  • 多次查询不应修改家族树或死亡集合。

四语言完整代码

import java.util.*;

class ThroneInheritance {
    private final String king;
    private final Map<String, List<String>> children = new HashMap<>();
    private final Set<String> dead = new HashSet<>();

    public ThroneInheritance(String kingName) {
        king = kingName;
        children.put(kingName, new ArrayList<>());
    }

    public void birth(String parentName, String childName) {
        children.get(parentName).add(childName);
        children.put(childName, new ArrayList<>());
    }

    public void death(String name) {
        dead.add(name);
    }

    public List<String> getInheritanceOrder() {
        List<String> order = new ArrayList<>();
        Deque<String> stack = new ArrayDeque<>();
        stack.push(king);
        while (!stack.isEmpty()) {
            String person = stack.pop();
            if (!dead.contains(person)) order.add(person);
            List<String> kids = children.get(person);
            for (int i = kids.size() - 1; i >= 0; --i) {
                stack.push(kids.get(i));
            }
        }
        return order;
    }
}

from collections import defaultdict
from typing import List

class ThroneInheritance:
    def __init__(self, kingName: str):
        self.king = kingName
        self.children = defaultdict(list)
        self.dead = set()

    def birth(self, parentName: str, childName: str) -> None:
        self.children[parentName].append(childName)

    def death(self, name: str) -> None:
        self.dead.add(name)

    def getInheritanceOrder(self) -> List[str]:
        order = []
        stack = [self.king]
        while stack:
            person = stack.pop()
            if person not in self.dead:
                order.append(person)
            stack.extend(reversed(self.children[person]))
        return order
class ThroneInheritance {
private:
    string king;
    unordered_map<string, vector<string>> children;
    unordered_set<string> dead;

public:
    ThroneInheritance(string kingName) : king(kingName) {
        children[kingName] = {};
    }

    void birth(string parentName, string childName) {
        children[parentName].push_back(childName);
        children[childName] = {};
    }

    void death(string name) {
        dead.insert(name);
    }

    vector<string> getInheritanceOrder() {
        vector<string> order;
        vector<string> stack{king};
        while (!stack.empty()) {
            string person = stack.back();
            stack.pop_back();
            if (!dead.count(person)) order.push_back(person);
            const auto& kids = children[person];
            for (auto it = kids.rbegin(); it != kids.rend(); ++it) {
                stack.push_back(*it);
            }
        }
        return order;
    }
};

替代方案

递归 DFS：更短且直接对应定义，但最坏家族深度可达 10^5，部分语言会栈溢出，因此这里采用显式栈。也可维护动态链表优化频繁查询，但插入位置与死亡管理更复杂；本题查询最多 10 次，按需 O(N) 遍历更稳妥。

面试追问

如果查询达到 10^5 次怎么办？

可维护可持久化顺序、欧拉序标签或支持子树插入的平衡树，并权衡出生更新与查询成本。

为什么不在 death 时删除节点？

因为其后代仍有继承权；删除会破坏血缘结构和相对顺序。

能否用 Set 保存孩子？

不能。集合通常不承诺题目需要的出生先后语义，必须使用有序数组或列表。

如何支持复活或撤销？

死亡状态改为布尔映射即可复活；通用撤销可保存操作日志并执行逆操作。

常见错误

  • 把死亡成员整棵子树跳过，错误移除其后代。
  • 孩子正序压栈，导致年幼者先访问。
  • 每次出生都重算全局名单，使大量更新代价过高。
  • 用深递归而忽略 105 深链的调用栈风险。
  • 查询时修改 children 数组，导致后续查询结果变化。
