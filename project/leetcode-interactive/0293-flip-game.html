Walkthrough

题解：枚举翻转起点

一次操作只影响两个相邻位置，因此候选操作天然对应字符串中的每一个相邻字符对。

核心洞察

合法操作的充分必要条件是某个位置 i 与 i + 1 都为 '+'。找到后复制原串，只把这两个位置改成 '-'，即可得到一个合法后继状态。

完整过程

  1. 创建空结果列表。
  2. 令 i 从 0 遍历到 n - 2。
  3. 若 currentState[i..i+1] == "++"，构造对应翻转结果并加入列表。
  4. 扫描结束后返回列表。

边界处理

  • 长度小于 2：循环不会执行，直接返回空列表。
  • 全是 '-' 或正号不相邻：没有结果。
  • 重叠的 "++" 也要分别考虑，例如 "+++" 有两个翻转起点。

为什么无需去重

不同起点翻转后，至少在其中一个起点位置上，一个结果是 '-'，另一个仍是 '+'（或翻转了别处），因此结果不会相同。

正确性证明

完备性：任意合法后继状态都来自某一对相邻 "++"；遍历检查了所有相邻起点，所以该状态必被加入。可靠性：算法只在字符对为 "++" 时生成结果，且只把该对改为 "--"，因此每个加入的状态都能由恰好一次合法操作得到。两者结合，返回列表恰好包含全部可能后继状态。

O(n²)时间：至多 O(n) 个结果，每次构造长度为 n 的字符串
O(n²)输出空间：保存全部结果；不计输出时额外空间依语言实现而定

替代方案

可以把字符串转为可变字符数组：遇到 "++" 时原地改成 "--"、复制结果，再恢复为 "++"。它避免为前后缀反复做拼接，写法适合 Java/C++；但由于每个返回字符串仍需完整复制，包含输出构造的渐进时间与空间上界仍是 O(n²)。

四语言完整代码

Java · LeetCode 可提交实现
import java.util.ArrayList;
import java.util.List;

class Solution {
    public List<String> generatePossibleNextMoves(String currentState) {
        List<String> nextStates = new ArrayList<>();
        char[] state = currentState.toCharArray();

        for (int i = 0; i + 1 < state.length; i++) {
            if (state[i] == '+' && state[i + 1] == '+') {
                state[i] = '-';
                state[i + 1] = '-';
                nextStates.add(new String(state));
                state[i] = '+';
                state[i + 1] = '+';
            }
        }

        return nextStates;
    }
}

/**
 * @param {string} currentState
 * @return {string[]}
 */
var generatePossibleNextMoves = function(currentState) {
    const nextStates = [];

    for (let i = 0; i + 1 < currentState.length; i++) {
        if (currentState[i] === '+' && currentState[i + 1] === '+') {
            const next = currentState.slice(0, i)
                + '--'
                + currentState.slice(i + 2);
            nextStates.push(next);
        }
    }

    return nextStates;
};
Python · LeetCode 可提交实现
from typing import List


class Solution:
    def generatePossibleNextMoves(self, currentState: str) -> List[str]:
        next_states: List[str] = []

        for i in range(len(currentState) - 1):
            if currentState[i:i + 2] == "++":
                next_state = currentState[:i] + "--" + currentState[i + 2:]
                next_states.append(next_state)

        return next_states

#include <string>
#include <vector>
using namespace std;

class Solution {
public:
    vector<string> generatePossibleNextMoves(string currentState) {
        vector<string> nextStates;

        for (int i = 0; i + 1 < static_cast<int>(currentState.size()); i++) {
            if (currentState[i] == '+' && currentState[i + 1] == '+') {
                currentState[i] = '-';
                currentState[i + 1] = '-';
                nextStates.push_back(currentState);
                currentState[i] = '+';
                currentState[i + 1] = '+';
            }
        }

        return nextStates;
    }
};

面试追问

如果要判断先手是否必胜呢？

那会变成 Flip Game II：不能只生成一步结果，需要在状态图上做递归搜索，并用记忆化缓存状态胜负，寻找是否存在一个让对手必败的后继状态。

能否把时间复杂度降到 O(n)？

若只统计合法操作数量，可以 O(n)。但本题必须返回每个完整字符串，最坏情况下输出本身就含 O(n²) 个字符，因此生成完整输出无法突破该输出下界。

结果有可能重复吗？

不会。两个不同的翻转起点会导致至少一个字符位置不同，所以它们生成的后继字符串互异，无需额外使用集合去重。

常见错误

  • 循环写到 i < n 后仍访问 i + 1，造成越界。
  • 使用可变数组生成结果后忘记恢复两个字符，污染后续候选状态。
  • 翻转一次后立即返回，遗漏其他合法起点。
  • 把重叠候选当成冲突；本题每个结果都从原始字符串独立执行一次操作。
  • 忽略构造输出字符串的成本，误报总时间复杂度为 O(n)。
