在下标间移动的最小代价

数组 nums 严格递增。每个位置可花 |nums[x]-nums[y]| 去任意位置，或以代价 1 去最近的相邻位置。对每个 queries[i] = [l, r] 求最小移动代价。

n, q ≤ 10⁵严格递增Medium
题意示例

当 nums = [-5, -2, 3] 时，最近相邻下标是 [1, 0, 1]。查询 l = 2, r = 0 可走 2 → 1 → 0，两次最近移动各花 1。

nums = [-5, -2, 3] queries = [[0, 2], [2, 0], [1, 2]] 期望 ans = [6, 2, 5]

题解：把每个方向压缩成相邻边费用

核心洞察

从 i 向右跨边 i → i+1 的最佳费用，要么是 1（若 closest(i)=i+1），要么是 nums[i+1]-nums[i]。严格递增使任意远跳的数值差等于沿途差值之和；逐边走从不更贵。向左同理，但是否可花 1 由出发下标决定。

完整过程

  1. 比较每个下标左右差，平局选左边。
  2. 建立 right[i] 与 left[i] 的单边最优费用。
  3. 对两组边分别做前缀和。
  4. l < r 查询用右向前缀差；否则用左向前缀差。

边界与复杂度

首尾的最近邻唯一；中间相等距离时必须选较小下标。预处理 O(n)，每个查询 O(1)，空间 O(n)。

替代方案 / 面试追问

完整图最短路会抹掉单调结构且无法处理 10⁵ 次查询。问到为何不用远跳：远跳可展开成相邻数值差之和，而每条边已有更优或相同费用。

常见错误

左右前缀不能共用：最近移动费用取决于出发点。相等差不能选右边，题意指定较小下标。
