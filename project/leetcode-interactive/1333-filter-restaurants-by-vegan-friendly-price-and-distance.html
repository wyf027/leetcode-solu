#1333 非付费题 最多 10⁴ 家餐厅 返回餐厅 ID
Problem

题目说明

官方参数形式

给定餐厅数组 restaurants，其中每一项都按 [id, rating, veganFriendly, price, distance] 记录餐厅编号、评分、是否对素食者友好、价格与距离。

使用三个条件过滤餐厅：当参数 veganFriendly = 1 时，只保留对应字段也为 1 的餐厅；当它为 0 时，不限制该字段。同时只保留 price ≤ maxPrice 且 distance ≤ maxDistance 的餐厅。

返回通过过滤的餐厅 ID。结果先按 rating 从高到低排列；评分相同时，再按 id 从高到低排列。

filterRestaurants(restaurants, veganFriendly, maxPrice, maxDistance) → List<Integer>

Solution

过滤后按二级关键字排序

核心洞察

每家餐厅是否保留只取决于三个互相独立的布尔条件。先线性过滤，再以 (rating 降序, id 降序) 为复合关键字排序，最后投影出 ID 即可。

完整过程

  1. 遍历每条 [id, rating, vegan, price, distance]。
  2. 素食条件写成 veganFriendly == 0 || vegan == 1。
  3. 同时检查 price ≤ maxPrice 与 distance ≤ maxDistance。
  4. 收集满足条件的整条记录，按评分降序、ID 降序排序。
  5. 按排序后的顺序提取每条记录的 id。

正确性说明

过滤正确：算法仅在三个条件全部成立时收集餐厅，因此收集集合中的每家餐厅都合法；反之，任意合法餐厅在遍历时也会通过全部判断并被收集，故没有遗漏。

顺序正确：比较器优先令评分大的记录靠前；评分相等时令 ID 大的靠前，恰好等于题目规定。最终映射不改变相对顺序，因此返回的 ID 序列正确。

边界情况

  • 没有餐厅通过时返回空数组。
  • veganFriendly = 0 表示忽略素食字段，而不是只选字段为 0 的餐厅。
  • 价格或距离刚好等于上限时仍应保留。
  • 多个餐厅评分相同时必须继续比较 ID。
  • 餐厅 ID 不一定等于数组下标。

复杂度

时间
O(n log n)
过滤 O(n)，排序占主导
空间
O(n)
保存至多 n 条候选记录

替代方案

也可以先对全部餐厅排序，再按顺序过滤和提取 ID，渐进时间复杂度仍为 O(n log n)。但先过滤通常让参与排序的数据更少，更贴合问题结构。

若评分与 ID 的取值范围非常小，可讨论桶排序；本题上限为 10⁵，普通比较排序更直接稳妥。

常见错误

  • 把 veganFriendly = 0 写成 vegan == 0。
  • 价格、距离使用严格小于，误删等于上限的记录。
  • 评分相同按 ID 升序排列。
  • 只保存 ID 后才排序，丢失评分信息。
  • 比较器使用布尔值而非负数、零、正数。

四种语言实现

Java
import java.util.*;

class Solution {
    public List<Integer> filterRestaurants(
            int[][] restaurants,
            int veganFriendly,
            int maxPrice,
            int maxDistance) {
        List<int[]> candidates = new ArrayList<>();

        for (int[] restaurant : restaurants) {
            boolean veganOk = veganFriendly == 0
                    || restaurant[2] == 1;
            boolean priceOk = restaurant[3] <= maxPrice;
            boolean distanceOk = restaurant[4] <= maxDistance;

            if (veganOk && priceOk && distanceOk) {
                candidates.add(restaurant);
            }
        }

        candidates.sort((a, b) -> {
            if (a[1] != b[1]) {
                return Integer.compare(b[1], a[1]);
            }
            return Integer.compare(b[0], a[0]);
        });

        List<Integer> answer = new ArrayList<>();
        for (int[] restaurant : candidates) {
            answer.add(restaurant[0]);
        }
        return answer;
    }
}

/**
 * @param {number[][]} restaurants
 * @param {number} veganFriendly
 * @param {number} maxPrice
 * @param {number} maxDistance
 * @return {number[]}
 */
var filterRestaurants = function(
    restaurants,
    veganFriendly,
    maxPrice,
    maxDistance
) {
    return restaurants
        .filter(([, , vegan, price, distance]) =>
            (veganFriendly === 0 || vegan === 1) &&
            price <= maxPrice &&
            distance <= maxDistance
        )
        .sort((a, b) => b[1] - a[1] || b[0] - a[0])
        .map(([id]) => id);
};

C++
#include <algorithm>
#include <vector>
using namespace std;

class Solution {
public:
    vector<int> filterRestaurants(
        vector<vector<int>>& restaurants,
        int veganFriendly,
        int maxPrice,
        int maxDistance
    ) {
        vector<vector<int>> candidates;

        for (const auto& restaurant : restaurants) {
            bool veganOk = veganFriendly == 0
                    || restaurant[2] == 1;
            bool priceOk = restaurant[3] <= maxPrice;
            bool distanceOk = restaurant[4] <= maxDistance;

            if (veganOk && priceOk && distanceOk) {
                candidates.push_back(restaurant);
            }
        }

        sort(candidates.begin(), candidates.end(),
            [](const auto& a, const auto& b) {
                if (a[1] != b[1]) return a[1] > b[1];
                return a[0] > b[0];
            });

        vector<int> answer;
        for (const auto& restaurant : candidates) {
            answer.push_back(restaurant[0]);
        }
        return answer;
    }
};

面试追问

为什么先过滤？

两种顺序都正确；先过滤可把排序规模从 n 降到候选数 k，实际代价变为 O(n + k log k)。

怎样扩展更多筛选器？

把每个条件封装为独立谓词并组合；排序规则则保持为独立比较器，减少两部分互相影响。

数据持续到达怎么办？

若只需前 K 个结果，可用大小为 K 的堆维护最佳候选，把保存空间降到 O(K)。
