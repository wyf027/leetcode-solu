01 / Problem

先读规则，再观察系统

题意转述

文件由 m 个小分块组成，分块编号为 1..m。每位在线用户拥有若干分块；系统为新用户分配当前未占用的最小正整数 ID，用户离开后该 ID 可以被再次使用。

当用户请求某个分块时，返回当前持有该分块的所有用户 ID，结果按升序排列。只有返回列表非空，请求者才算获取成功，并从此也持有该分块。

时序细节：先取得并返回“请求发生前”的持有者列表，再把请求者加入持有者集合；因此请求者若原本没有该分块，不会出现在本次返回值中。

接口契约

  • FileSharing(m)初始化一个包含 m 个分块的系统。
  • join(ownedChunks)用户携带若干分块加入；分配最小可用正整数 ID 并返回。
  • leave(userID)用户离开；移除其全部分块归属，并释放 ID。
  • request(userID, chunkID)返回该分块的升序持有者列表；若非空，请求者获得分块。

官方示例（完整参数形式）

输入： ["FileSharing","join","join","join","request","request","leave","request","leave","join"] [[4],[[1,2]],[[2,3]],[[4]],[1,3],[2,2],[1],[2,1],[2],[[]]] 输出： [null,1,2,3,[2],[1,2],null,[],null,1]

要点：用户 1 请求分块 3 时从用户 2 获得它；用户 1 离开后，分块 1 无人持有；用户 1、2 依次离开后，新的空分块用户复用最小 ID 1。

约束

  • 1 ≤ m ≤ 10⁵
  • 0 ≤ ownedChunks.length ≤ min(100, m)
  • 1 ≤ ownedChunks[i] ≤ m
  • ownedChunks 中的值互不相同
  • 1 ≤ chunkID ≤ m
  • 若 ID 分配正确，userID 保证是系统中的用户
  • join / leave / request 总调用次数至多 10⁴
  • 每次 leave 都对应先前的一次 join

04 / Solution

双向索引 + 最小堆

核心洞察

只记录“用户拥有什么”，请求时就要扫描所有用户；只记录“分块被谁持有”，用户离开时又不知道该从哪些集合中删除。维护两份互为镜像的索引，让两种方向都能直接定位。

user → chunks
↔
chunk → sorted users

离开的 ID 放入最小堆；堆为空时才使用递增的 nextID。这样每次加入都拿到全局最小的未占用正整数。

完整过程

  1. 初始化：为每个分块准备一个有序持有者集合；空闲 ID 堆为空，nextID = 1。
  2. 加入：优先弹出堆顶，否则取 nextID++；同步写入两份索引。
  3. 离开：沿用户的分块集合逐项删除反向归属，再移除用户并回收 ID。
  4. 请求：先复制有序持有者作为答案；答案非空时，再把请求者写入两份索引。

正确性说明

  • 索引一致性：初始化时两边都为空。join、成功的 request 都同时添加两边关系，leave 同时删除两边关系，因此任意时刻 c ∈ userChunks[u] 当且仅当 u ∈ chunkOwners[c]。
  • 请求结果：根据上述不变式，chunkOwners[c] 恰好包含当前全部持有者；有序集合的遍历顺序天然升序。先复制后添加请求者，严格符合返回时序。
  • 最小 ID：所有被释放且小于 nextID 的 ID 都在最小堆中。堆非空时堆顶是最小空闲 ID；堆为空时，1..nextID-1 均被占用，所以 nextID 最小。
  • 离开完整性：用户持有的每个分块都通过正向索引被枚举并从反向索引删除，因此离开者不会再出现在后续请求结果中。

复杂度

操作时间
joinO(log U + k log U)
leaveO(log U + d log U)
requestO(r + log U)
空间O(U + E + m)

U 为在线/已分配规模，k 为加入时携带分块数，d 为离开者持有分块数，r 为请求分块的持有者数，E 为当前“用户—分块”关系数。

四语言完整实现

import java.util.*;

class FileSharing {
    private final List<TreeSet<Integer>> chunkOwners;
    private final Map<Integer, Set<Integer>> userChunks;
    private final PriorityQueue<Integer> freeIds;
    private int nextId;

    public FileSharing(int m) {
        chunkOwners = new ArrayList<>(m + 1);
        for (int i = 0; i <= m; i++) {
            chunkOwners.add(new TreeSet<>());
        }
        userChunks = new HashMap<>();
        freeIds = new PriorityQueue<>();
        nextId = 1;
    }

    public int join(List<Integer> ownedChunks) {
        int userId = freeIds.isEmpty() ? nextId++ : freeIds.poll();
        Set<Integer> chunks = new HashSet<>(ownedChunks);
        userChunks.put(userId, chunks);
        for (int chunkId : chunks) {
            chunkOwners.get(chunkId).add(userId);
        }
        return userId;
    }

    public void leave(int userID) {
        for (int chunkId : userChunks.get(userID)) {
            chunkOwners.get(chunkId).remove(userID);
        }
        userChunks.remove(userID);
        freeIds.offer(userID);
    }

    public List<Integer> request(int userID, int chunkID) {
        TreeSet<Integer> owners = chunkOwners.get(chunkID);
        List<Integer> answer = new ArrayList<>(owners);
        if (!answer.isEmpty()) {
            owners.add(userID);
            userChunks.get(userID).add(chunkID);
        }
        return answer;
    }
}

class MinHeap {
  constructor() { this.data = []; }
  get size() { return this.data.length; }

  push(value) {
    const a = this.data;
    a.push(value);
    let i = a.length - 1;
    while (i > 0) {
      const parent = (i - 1) >> 1;
      if (a[parent] <= a[i]) break;
      [a[parent], a[i]] = [a[i], a[parent]];
      i = parent;
    }
  }

  pop() {
    const a = this.data;
    const root = a[0];
    const tail = a.pop();
    if (a.length > 0) {
      a[0] = tail;
      let i = 0;
      while (true) {
        let smallest = i;
        const left = i * 2 + 1;
        const right = left + 1;
        if (left < a.length && a[left] < a[smallest]) smallest = left;
        if (right < a.length && a[right] < a[smallest]) smallest = right;
        if (smallest === i) break;
        [a[i], a[smallest]] = [a[smallest], a[i]];
        i = smallest;
      }
    }
    return root;
  }
}

var FileSharing = function(m) {
  this.chunkOwners = Array.from({ length: m + 1 }, () => new Set());
  this.userChunks = new Map();
  this.freeIds = new MinHeap();
  this.nextId = 1;
};

FileSharing.prototype.join = function(ownedChunks) {
  const userId = this.freeIds.size ? this.freeIds.pop() : this.nextId++;
  const chunks = new Set(ownedChunks);
  this.userChunks.set(userId, chunks);
  for (const chunkId of chunks) this.chunkOwners[chunkId].add(userId);
  return userId;
};

FileSharing.prototype.leave = function(userID) {
  for (const chunkId of this.userChunks.get(userID)) {
    this.chunkOwners[chunkId].delete(userID);
  }
  this.userChunks.delete(userID);
  this.freeIds.push(userID);
};

FileSharing.prototype.request = function(userID, chunkID) {
  const owners = [...this.chunkOwners[chunkID]].sort((a, b) => a - b);
  if (owners.length > 0) {
    this.chunkOwners[chunkID].add(userID);
    this.userChunks.get(userID).add(chunkID);
  }
  return owners;
};

JavaScript 的 Set 不自动排序，因此请求时排序输出；最小堆负责回收 ID。

from typing import List
import heapq


class FileSharing:
    def __init__(self, m: int):
        self.chunk_owners = [set() for _ in range(m + 1)]
        self.user_chunks = {}
        self.free_ids = []
        self.next_id = 1

    def join(self, ownedChunks: List[int]) -> int:
        if self.free_ids:
            user_id = heapq.heappop(self.free_ids)
        else:
            user_id = self.next_id
            self.next_id += 1

        chunks = set(ownedChunks)
        self.user_chunks[user_id] = chunks
        for chunk_id in chunks:
            self.chunk_owners[chunk_id].add(user_id)
        return user_id

    def leave(self, userID: int) -> None:
        for chunk_id in self.user_chunks[userID]:
            self.chunk_owners[chunk_id].remove(userID)
        del self.user_chunks[userID]
        heapq.heappush(self.free_ids, userID)

    def request(self, userID: int, chunkID: int) -> List[int]:
        owners = sorted(self.chunk_owners[chunkID])
        if owners:
            self.chunk_owners[chunkID].add(userID)
            self.user_chunks[userID].add(chunkID)
        return owners

Python 用集合维护归属、heapq 维护空闲 ID；输出时对持有者排序。

#include <vector>
#include <set>
#include <unordered_map>
#include <unordered_set>
#include <queue>
#include <functional>
using namespace std;

class FileSharing {
private:
    vector<set<int>> chunkOwners;
    unordered_map<int, unordered_set<int>> userChunks;
    priority_queue<int, vector<int>, greater<int>> freeIds;
    int nextId = 1;

public:
    FileSharing(int m) : chunkOwners(m + 1) {}

    int join(vector<int> ownedChunks) {
        int userId;
        if (freeIds.empty()) {
            userId = nextId++;
        } else {
            userId = freeIds.top();
            freeIds.pop();
        }

        auto& chunks = userChunks[userId];
        for (int chunkId : ownedChunks) {
            chunks.insert(chunkId);
            chunkOwners[chunkId].insert(userId);
        }
        return userId;
    }

    void leave(int userID) {
        for (int chunkId : userChunks[userID]) {
            chunkOwners[chunkId].erase(userID);
        }
        userChunks.erase(userID);
        freeIds.push(userID);
    }

    vector<int> request(int userID, int chunkID) {
        auto& owners = chunkOwners[chunkID];
        vector<int> answer(owners.begin(), owners.end());
        if (!answer.empty()) {
            owners.insert(userID);
            userChunks[userID].insert(chunkID);
        }
        return answer;
    }
};

C++ 的 set 同时提供去重与升序遍历，priority_queue 配合 greater 构成最小堆。

边界情况

  • 用户可以携带空分块列表加入。
  • 无人持有的分块返回空数组，且请求者不会获得它。
  • 请求者原本就持有分块时，返回列表包含自己，集合不会重复添加。
  • 多个 ID 同时空闲时必须复用最小者，而非最近释放者。
  • 用户离开前通过请求获得的新分块也必须完整清理。

替代方案与取舍

按用户扫描：只维护 user → chunks，请求时扫描所有在线用户并排序。实现简单，但每次请求需要 O(U + r log r)，请求密集时更差。

有序空闲 ID 集合：可用 TreeSet / set 替代最小堆，同样能取最小值；它还支持删除任意 ID，但本题只需插入与取最小，堆更贴合需求。

懒删除反向索引：离开时不从分块集合清理、请求时过滤离线用户，会把成本推迟到请求并积累脏数据，不适合这里的清晰约束。

面试追问

如果用 IP 地址代替用户 ID，会发生什么？

同一 IP 可能对应 NAT 后的多个用户，也可能被断线重连者复用；IP 不是稳定身份。应使用独立会话/用户标识，并把网络地址仅视为连接属性。

用户频繁加入和离开、几乎不请求时是否高效？

最小堆让 ID 分配与回收为对数级；但离开仍与用户持有分块数成正比，这是清理精确反向索引所需的必要工作。

所有用户一次加入、请求全部分块、再离开呢？

关系数 E 可能显著增长，时间与空间都必须至少覆盖这些真实归属；可讨论位图、分片索引或批处理，但无法绕过输出本身的规模。

扩展到 n 个文件怎么做？

把分块键扩展为 (fileID, chunkID)，或为每个文件维护独立的分块索引；用户索引也记录复合键。用户 ID 管理仍可全局共享。

常见错误

  • 成功请求后只更新分块侧，忘记更新用户侧，导致离开时残留。
  • 先把请求者加入，再构造答案，使首次请求者错误地出现在返回值里。
  • 用栈或队列回收 ID，不能保证拿到最小空闲 ID。
  • 用户离开时只删除用户记录，没有从各分块持有者中移除。
  • 返回无序集合的遍历结果，遗漏“升序”要求。
