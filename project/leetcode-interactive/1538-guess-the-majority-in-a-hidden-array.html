Problem

题目转述

Guess the Majority in a Hidden Array

有一个长度为 n 的隐藏二进制数组 nums，其中每个元素只可能是 0 或 1。你不能直接访问数组，只能调用读取器的接口。

请返回数组中出现次数更多的那个值所对应的任意下标。如果 0 和 1 出现次数相同，返回 -1。评测器会根据隐藏数组验证下标，不要求返回固定位置。

交互约束：实现 guessMajority(reader)；通过 reader.length() 获取长度，通过 reader.query(a,b,c,d) 询问四个互不相同的有效下标。不要尝试直接读取隐藏数组。
Oracle

ArrayReader 如何回答

一次查询只透露四个位置的“组成形态”，不会告诉你具体的 0 / 1。

4
四个值完全相同

形态为 0000 或 1111。

2
三个相同、一个不同

例如 0001 或 1110。

0
两个 0、两个 1

四个位置刚好平分。

query(a,b,c,d)
四个下标必须互不相同，返回 0、2 或 4。
length()
返回隐藏数组长度 n。
提交函数
int guessMajority(ArrayReader reader)（各语言按其接口语法调整）。

Spoiler Gate

先想一想：怎样比较两个看不见的位？

下面的题解会揭示基准查询、逐位分类和计数方法，并提供可逐步播放的交互演示。

Solution

用同一组三个锚点做“等价比较”

核心洞察

固定三个下标 1、2、3，先查询 query(0,1,2,3)。之后把位置 0 替换为位置 i，查询 query(1,2,3,i)。

三个锚点完全不变，因此两次查询结果相等，当且仅当 nums[i] == nums[0]。我们不需要知道基准值究竟是 0 还是 1，只需要知道每个位置与它是否同类。

query(0, 1, 2, 3) == query(1, 2, 3, i)

⇔ nums[0] == nums[i]
  1. 查询 (0,1,2,3) 得到基准分数，把下标 0 计入“同类”。
  2. 对每个 i = 4 ... n-1，用 (1,2,3,i) 与基准分数比较，分类并记录一个“异类”下标。
  3. 用位置 4 作为新锚点，分别替换原查询中的 1、2、3，判断这三个位置是否与位置 0 同类。
  4. 比较同类和异类的数量：相等返回 -1；同类更多返回 0；异类更多返回保存的异类下标。

Reasoning

正确性、边界与复杂度

比较引理

两次查询共用相同的三个位置，只把 0 替换为 i。因为数组值是二进制，查询分数不变恰好表示被替换的两个值相同。

分类完备

循环分类 4...n-1，另外三次查询分类 1、2、3，而 0 预先属于同类。因此所有 n 个位置都恰好被统计一次。

返回正确

同类更多时，下标 0 指向多数值；异类更多时，保存的异类下标指向多数值；两类相同表示 0 和 1 数量相等。

复杂度

查询次数为 1 + (n-4) + 3 = n；时间复杂度 O(n)，额外空间复杂度 O(1)。

最短数组 n = 5：位置 4 同时承担比较对象和辅助锚点，所有四元查询仍由不同下标组成。若异类计数为 0，它不可能成为多数分支的返回候选。

// The ArrayReader API is provided by the judge.
// interface ArrayReader {
//     int query(int a, int b, int c, int d);
//     int length();
// }
class Solution {
    public int guessMajority(ArrayReader reader) {
        int n = reader.length();
        int base = reader.query(0, 1, 2, 3);
        int same = 1;
        int different = 0;
        int differentIndex = -1;

        for (int i = 4; i < n; i++) {
            if (reader.query(1, 2, 3, i) == base) {
                same++;
            } else {
                different++;
                differentIndex = i;
            }
        }

        int anchor = reader.query(1, 2, 3, 4);
        if (reader.query(0, 2, 3, 4) == anchor) same++;
        else { different++; differentIndex = 1; }
        if (reader.query(0, 1, 3, 4) == anchor) same++;
        else { different++; differentIndex = 2; }
        if (reader.query(0, 1, 2, 4) == anchor) same++;
        else { different++; differentIndex = 3; }

        if (same == different) return -1;
        return same > different ? 0 : differentIndex;
    }
}

Deep Dive

替代方案、面试追问与常见错误

替代思路

可以选择不同的四元基准，或先推导若干位置间的关系再做投票；但仍需让两次查询只替换一个位置。直接猜测查询分数对应 0 的数量会失败，因为 0000 与 1111 都返回 4。

与摩尔投票的关系

这里不是直接读取值后做经典 Boyer–Moore，而是先借助查询把每个位置投影成“与 nums[0] 同类 / 异类”，再比较两类规模。二进制性保证这两类正好对应 0 和 1。

追问：为什么分数相等就一定同值？

固定三位中 1 的数量设为 k。加入的位从 0 变 1 时，四位中的 1 数由 k 变为 k+1；在 k=0、1、2、3 的每种情况下，接口分数都会改变。反之加入值相同，组成当然不变。

追问：能否返回多数元素的值，而不是下标？

不能可靠地知道它是 0 还是 1，因为接口对整体取反完全对称；但题目只要求返回下标，所以关系分类已经足够。

常见错误：把位置 1、2、3 漏掉

主循环从 4 开始，只覆盖后缀。必须额外三次查询来分类下标 1、2、3，并把下标 0 的同类计数初始化为 1。

常见错误：返回任意“异类计数”而未保存下标

异类成为多数时必须返回实际下标，因此每次发现异类都应保存它；最后一个即可。

常见错误：查询中出现重复下标

接口要求四个下标互不相同。由于 n 至少为 5，辅助位置 4 始终存在，构造出的查询满足要求。
