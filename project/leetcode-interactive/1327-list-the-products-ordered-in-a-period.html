核心洞察与完整过程

WHERE 管行，HAVING 管组。先准确圈定二月订单，再按产品聚合，最后筛选总量。
  1. 以 product_id 连接 Products 与 Orders，取得产品名。
  2. 用左闭右开区间 [2020-02-01, 2020-03-01) 过滤订单。
  3. 按产品编号和名称分组，对每组 unit 求和。
  4. 用 HAVING SUM(unit) >= 100 保留达标组。

官方可提交语言：MySQL

MySQL可提交
SELECT p.product_name,
       SUM(o.unit) AS unit
FROM Products AS p
JOIN Orders AS o
  ON o.product_id = p.product_id
WHERE o.order_date >= '2020-02-01'
  AND o.order_date <  '2020-03-01'
GROUP BY p.product_id, p.product_name
HAVING SUM(o.unit) >= 100;

正确性、边界与复杂度

正确性证明

日期谓词保留所有且仅有二月订单。连接后，每条保留订单进入其唯一产品组，因此 SUM 等于该产品二月总量。HAVING 保留且仅保留总量不少于 100 的组，输出名称与总量正是题目所求。

边界

  • 2 月 1 日计入，3 月 1 日排除。
  • 总量恰好 100 应保留。
  • 重复订单逐行累计。
  • 二月无订单的产品不输出。
  • 产品名可能重复，分组带上 product_id 更稳妥。

复杂度：抽象地看，若扫描订单数为 n、产品组数为 k，时间 O(n)，聚合空间 O(k)；数据库实际代价取决于索引、连接与执行计划。

Java本地语义参考
import java.time.LocalDate;
import java.util.*;

public class ProductReport {
  record Product(int id, String name) {}
  record Order(int productId, LocalDate date, int unit) {}
  record Result(String productName, int unit) {}

  static List<Result> listProducts(
      List<Product> products, List<Order> orders) {
    Map<Integer, String> names = new HashMap<>();
    for (Product p : products) names.put(p.id(), p.name());
    LocalDate start = LocalDate.parse("2020-02-01");
    LocalDate end = LocalDate.parse("2020-03-01");
    Map<Integer, Integer> sums = new HashMap<>();
    for (Order o : orders) {
      if (!o.date().isBefore(start) && o.date().isBefore(end))
        sums.merge(o.productId(), o.unit(), Integer::sum);
    }
    List<Result> ans = new ArrayList<>();
    for (var e : sums.entrySet())
      if (e.getValue() >= 100)
        ans.add(new Result(names.get(e.getKey()), e.getValue()));
    return ans;
  }
}
JavaScript本地语义参考
function listProducts(products, orders) {
  const names = new Map(
    products.map(p => [p.product_id, p.product_name])
  );
  const sums = new Map();
  for (const o of orders) {
    if (o.order_date >= "2020-02-01" &&
        o.order_date < "2020-03-01") {
      sums.set(o.product_id,
        (sums.get(o.product_id) ?? 0) + o.unit);
    }
  }
  const ans = [];
  for (const [id, unit] of sums) {
    if (unit >= 100)
      ans.push({ product_name: names.get(id), unit });
  }
  return ans;
}

from collections import defaultdict

def list_products(products, orders):
    names = {
        p["product_id"]: p["product_name"] for p in products
    }
    sums = defaultdict(int)
    for order in orders:
        if ("2020-02-01" <= order["order_date"]
                < "2020-03-01"):
            sums[order["product_id"]] += order["unit"]
    return [
        {"product_name": names[pid], "unit": unit}
        for pid, unit in sums.items() if unit >= 100
    ]
C++本地语义参考
#include <string>
#include <unordered_map>
#include <vector>
using namespace std;

struct Product { int id; string name; };
struct Order { int productId; string date; int unit; };
struct Result { string productName; int unit; };

vector<Result> listProducts(
    const vector<Product>& products,
    const vector<Order>& orders) {
  unordered_map<int, string> names;
  for (const auto& p : products) names[p.id] = p.name;
  unordered_map<int, int> sums;
  for (const auto& o : orders)
    if (o.date >= "2020-02-01" && o.date < "2020-03-01")
      sums[o.productId] += o.unit;
  vector<Result> ans;
  for (const auto& [id, unit] : sums)
    if (unit >= 100) ans.push_back({names[id], unit});
  return ans;
}

替代方案、追问与常见错误

替代方案

  • BETWEEN 月初与月末可行，但左闭右开更适合时间戳，也不必计算月末。
  • 条件聚合适合同时展示多个时间段，本题会让表达更绕。
  • 可先在 Orders 子查询中聚合筛选，再连接 Products 取名称。

面试追问

  • 如何把起止月份参数化？
  • 若展示零销量产品，LEFT JOIN 的过滤条件应放在哪里？
  • 产品名称不唯一时为何不能只按名称分组？
  • 大表上如何依据选择性设计复合索引？
常见错误：在 WHERE 中写 SUM；只判断月份而漏掉年份；把 3 月 1 日包含进来；用 > 100 漏掉恰好 100；按单笔订单筛选而非月总量。
