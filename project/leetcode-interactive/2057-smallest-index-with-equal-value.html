值相等的最小索引

Smallest Index With Equal Value

01 / 题目

给定一个从 0 开始编号的整数数组 nums，找到满足 i mod 10 == nums[i] 的最小下标 i。如果没有任何下标满足条件，返回 -1。

mod 表示除法的余数。例如 12 mod 10 = 2。函数接收整数数组 nums，返回一个整数下标或 -1。

约束

  • 1 <= nums.length <= 100
  • 0 <= nums[i] <= 9

05 / 独立题解

准备好后，再展开推导与四语言代码。

核心洞察：第一个命中就是最小下标

按照 0、1、2…… 的顺序检查 i % 10 === nums[i]。遇到相等立即返回当前下标；全部检查完仍不相等，返回 -1。下标可能超过 9，比较的是它除以 10 的余数。

完整过程

  1. 从下标 i = 0 开始。
  2. 计算 i % 10，与 nums[i] 比较。
  3. 相等则返回 i；不等则检查下一个下标。
  4. 越过数组末尾仍未返回，则返回 -1。

以 nums = [4,3,2,1] 为例：0 % 10 = 0 ≠ 4；1 % 10 = 1 ≠ 3；2 % 10 = 2 = 2，返回 2，后面的元素无需继续检查。

正确性证明

循环不变式：开始检查 i 时，所有小于 i 的下标均不满足条件。初始 i = 0，前方没有下标，不变式成立。若当前不满足条件，进入 i + 1 时，所有更小下标仍已被排除；若当前满足条件，则它有效且不存在更小的有效下标，返回值就是最小答案。循环结束时，所有下标均被排除，因此返回 -1 正确。

边界与复杂度

  • 长度为 1 时，仅检查下标 0：元素为 0 返回 0，否则返回 -1。
  • 多个匹配时立即返回第一次命中的下标；最后一项命中也能正常返回。
  • 下标 10 的余数是 0，不能直接用 i 与 nums[i] 比较，也不能只检查前 10 项。
  • 最坏时间 O(n)，首项命中时为 O(1)；算法额外空间 O(1)。演示页面保存状态不属于提交算法的空间。

替代方案

遍历所有下标并维护最小匹配值也可行，仍为 O(n) 时间、O(1) 空间，但会做多余检查。JavaScript 的 nums.findIndex((value, i) => i % 10 === value) 同样从前往后寻找并在无结果时返回 -1。收集所有匹配再取最小值需要额外空间，没有必要。

常见错误

  • 将下标从 1 开始，导致错位。
  • 写成 nums[i] % 10 == i，交换了取余对象。
  • 返回 nums[i] 而非 i；在 i ≥ 10 时结果尤其容易出错。
  • 每遇到一次匹配都覆盖答案，最终得到最大匹配下标。
  • 在循环内遇到首次不匹配就返回 -1，遗漏后面的候选。

面试追问

取余基数改为正整数 k？把 10 改成 k，其余逻辑不变。要返回最大匹配下标？从末尾向前寻找首个匹配。能否保证次线性时间？一般不能：未检查的位置可能是唯一匹配，最坏必须扫描全部元素。输入是流？维护从 0 递增的下标，首次命中即可停止。

Java

class Solution {
    public int smallestEqual(int[] nums) {
        for (int i = 0; i < nums.length; i++) {
            if (i % 10 == nums[i]) {
                return i;
            }
        }
        return -1;
    }
}

    def smallestEqual(self, nums: List[int]) -> int:

            if i % 10 == value:
                return i
        return -1
