最佳直线

把每个点依次钉成“测量原点”，将射向其他点的方向约分成唯一刻度。 同一刻度收到的测量票越多，穿过锚点的直线就连接了越多点。

锚点枚举 方向哈希 最大公约数 O(n²)

题意

给定平面上的点列表，找出穿过点数最多的直线。答案不是直线方程，而是这条直线上编号最小的两个点。

任务

第 i 个点为 points[i] = [xᵢ, yᵢ]。若一条最优直线经过的全部点下标升序为 S，返回 [S[0], S[1]]。若多条直线经过相同数量的点，先比较 S[0]，再比较 S[1]，选择字典序更小者。

官方示例

输入 points = [[0,0],[1,1],[1,0],[2,0]]
输出 [0,2]
解释 编号 0、2、3 共线，直线经过 3 个点。

约束与返回规则

  • 2 <= points.length <= 300
  • 每个点恰有两个整数坐标。
  • 答案始终是两个原数组下标。
  • 并列时必须保留字典序最小的下标对。

橙色测量针是锚点，青色点是当前候选。每次把 (dy, dx) 除以最大公约数并统一符号，写入方向票槽。

题解封存区

核心洞察、完整推导、边界、复杂度、替代方案、面试追问、常见错误与四语言代码默认隐藏。

题解

主线：枚举锚点，把所有出射方向化成唯一整数对，用哈希表计数。

核心洞察

固定锚点 i 后，任意经过它的直线都由一个方向决定。对候选点 j 计算 dx = xⱼ - xᵢ、dy = yⱼ - yᵢ，除以 gcd(|dx|, |dy|)，再统一符号。相同最简方向的点必与锚点共线。

为什么不用浮点斜率

dy / dx 有精度风险，还要特殊处理垂直线。整数方向键既精确，也能把 (2,2)、(4,4) 稳定映射为同一个 (1,1)。

完整过程

循环按下标递增；计数更大时更新，计数相同则显式比较候选下标对。

  1. 初始化答案为 [0,1]、全局最大点数为 2。
  2. 令 i 从 0 到 n - 2 递增，清空当前锚点的方向哈希表。
  3. 令 j 从 i + 1 到 n - 1 递增，计算 dx、dy。
  4. 用最大公约数约分，并让 dx > 0；垂直方向固定为 (1,0)，水平方向固定为 (0,1)。
  5. 方向计数加一。第一次看到某方向时，记录它对应的首个 j，这就是该锚点下最小的第二下标。
  6. 该方向穿过点数为“方向票数 + 锚点”。若超过全局最大值就更新；若并列，则选择字典序更小的下标对。

边界与复杂度

方向规范化是正确性的闸门；显式比较候选下标对是字典序的闸门。

边界

  • 仅两个点：直接返回 [0,1]。
  • 垂直线：规范为 (1,0)。
  • 水平线：规范为 (0,1)。
  • 负方向：同时翻转 dx 与 dy，避免同一直线出现两个键。
  • 并列：仅当候选 [i, firstJ] 字典序更小时覆盖答案。

复杂度

项目 复杂度 说明
时间 O(n² log C) 两层枚举；每次 gcd 为 O(log C)
空间 O(n) 单个锚点最多有 n - 1 个方向键

替代方案

三点叉积适合做小规模正确性基准；不适合作为 n = 300 时的主线。

枚举点对 (i,j) 定义直线，再扫描所有 k，利用 (xⱼ-xᵢ)(yₖ-yᵢ) = (yⱼ-yᵢ)(xₖ-xᵢ) 判断共线。它完全避免除法，逻辑直观，时间却是 O(n³)。全局规范化直线方程 Ax + By + C = 0 也可做哈希，但键的规范化和下标集合维护更繁琐。

常见错误

这道题最常错在“同一直线用了不同键”和“并列答案被晚到结果覆盖”。

直接用浮点数作键

精度与垂直线都会制造不稳定。使用最简整数方向。

只约分，不统一符号

(1,1) 与 (-1,-1) 会被分进两个槽。

方向票数忘加锚点

哈希值统计的是其他点数量，直线总点数还要加 1。

相等计数不比较下标

“总是不更新”或“总是更新”都可能出错；并列时必须显式比较 [i,j]。

四语言提交代码

四份实现采用相同的不变量：最简方向键、记录方向首个下标、并列显式比较。 

class Solution {
    public int[] bestLine(int[][] points) {
        int n = points.length;
        int[] answer = {0, 1};
        int best = 2;

        for (int i = 0; i < n - 1; i++) {
            Map<String, Integer> count = new HashMap<>();
            Map<String, Integer> first = new HashMap<>();
            for (int j = i + 1; j < n; j++) {
                int dx = points[j][0] - points[i][0];
                int dy = points[j][1] - points[i][1];
                int g = gcd(Math.abs(dx), Math.abs(dy));
                dx /= g;
                dy /= g;
                if (dx < 0 || (dx == 0 && dy < 0)) {
                    dx = -dx;
                    dy = -dy;
                }
                String key = dy + "/" + dx;
                first.putIfAbsent(key, j);
                int total = count.merge(key, 1, Integer::sum) + 1;
                int candidateJ = first.get(key);
                if (total > best
                        || (total == best
                                && (i < answer[0]
                                        || (i == answer[0] && candidateJ < answer[1])))) {
                    best = total;
                    answer = new int[] {i, candidateJ};
                }
            }
        }
        return answer;
    }

    private int gcd(int a, int b) {
        while (b != 0) {
            int t = a % b;
            a = b;
            b = t;
        }
        return a;
    }
}

var bestLine = function (points) {
  const gcd = (a, b) => {
    while (b !== 0) [a, b] = [b, a % b];
    return a;
  };

  let answer = [0, 1];
  let best = 2;
  for (let i = 0; i < points.length - 1; i++) {
    const count = new Map();
    const first = new Map();
    for (let j = i + 1; j < points.length; j++) {
      let dx = points[j][0] - points[i][0];
      let dy = points[j][1] - points[i][1];
      const g = gcd(Math.abs(dx), Math.abs(dy));
      dx /= g;
      dy /= g;
      if (dx < 0 || (dx === 0 && dy < 0)) {
        dx = -dx;
        dy = -dy;
      }
      const key = `${dy}/${dx}`;
      if (!first.has(key)) first.set(key, j);
      const total = (count.get(key) ?? 0) + 2;
      count.set(key, total - 1);
      const candidate = [i, first.get(key)];
      const lexicographicallySmaller =
        candidate[0] < answer[0] ||
        (candidate[0] === answer[0] && candidate[1] < answer[1]);
      if (total > best || (total === best && lexicographicallySmaller)) {
        best = total;
        answer = candidate;
      }
    }
  }
  return answer;
};

面试追问

展开问题，检查能否说清正确性、并列规则与工程边界。

为什么同一最简方向就代表共线？

固定锚点后，两个点与锚点的位移向量若成比例，它们就在同一条过锚点的直线上。约分后的整数方向正是这个比例类的唯一代表。

为什么并列时仍要显式比较下标对？

不同方向达到同一最终计数的时刻可能不同：首个 j 较大的方向可能先达到最大值，首个 j 较小的方向稍后才追平。因此每个方向要记住首个 j，并在相等计数时比较候选 [i,j]。

坐标范围很大时要注意什么？

差值与叉积可能溢出 32 位整数。若题目把坐标扩大到 10⁹，Java/C++ 应用 long/long long 存 dx、dy 和键。

如果输入允许重复点怎么办？

重复点没有方向，应为每个锚点单独统计 duplicate，并把它加到所有方向的点数中。本题常规数据假设点坐标可用于定义直线，提交前仍应向面试官确认。
