小于 K 的
两数之和

Two Sum Less Than K
EASY数组排序双指针付费题

题目

给定整数数组 nums 和整数 k，从数组中选择两个不同下标的元素，使两数之和严格小于 k。返回所有可行两数之和中的最大值；若不存在可行的数对，返回 -1。

示例 1

输入：nums = [34,23,1,24,75,33,54,8], k = 60 输出：58 解释：34 + 24 = 58，这是严格小于 60 的最大和。

示例 2

输入：nums = [10,20,30], k = 15 输出：-1 解释：任意两个数之和都不小于 15。

约束

  • 1 <= nums.length <= 100
  • 1 <= nums[i] <= 1000
  • 1 <= k <= 2000

双指针实验台

数组排序后，左右指针从两端向中间收缩。观察每一步为什么只需移动一个指针。

左指针右指针当前最优涉及元素

题解：排序 + 双指针

核心洞察

排序带来了单调性。设左右指针为 left、right：若当前和小于 k，它是候选答案，同时只有增大较小的数才可能得到更大的和；若当前和大于或等于 k，必须减小较大的数。

完整过程

  1. 将 nums 升序排序，答案初始化为 -1。
  2. 令 left = 0、right = nums.length - 1。
  3. 当 left < right 时计算两数之和。
  4. 若和小于 k，更新答案并右移 left；否则左移 right。
  5. 指针相遇时返回答案。

正确性说明

当当前和不小于 k 时，固定右端点并选择任何更大的左端点，只会让和更大，因此当前右端点不可能参与可行解，可以安全丢弃。当前和小于 k 时，固定左端点的最大可行搭档就是当前右端点；记录它后，再保留该左端点也不可能产生更优结果，所以可安全右移左指针。每步至少排除一个不可能改善答案的端点，最终检查完所有潜在最优组合。

边界情况

  • 没有任何两数之和小于 k，答案保持 -1。
  • 恰好等于 k 不可接受，因为条件是严格小于。
  • 重复元素可以组成数对，但必须来自不同下标。
  • 两个元素的数组同样适用。

复杂度

排序耗时 O(n log n)，双指针扫描耗时 O(n)；总时间复杂度为 O(n log n)。额外空间取决于语言的排序实现，通常为 O(log n) 或 O(n)。

四语言代码

class Solution {
    public int twoSumLessThanK(int[] nums, int k) {
        java.util.Arrays.sort(nums);
        int left = 0, right = nums.length - 1, answer = -1;
        while (left < right) {
            int sum = nums[left] + nums[right];
            if (sum < k) {
                answer = Math.max(answer, sum);
                left++;
            } else {
                right--;
            }
        }
        return answer;
    }
}

替代方案

可以枚举每个元素，再对目标上界 k - nums[i] 做二分查找，时间复杂度同为 O(n log n)；也可以暴力枚举所有数对，时间复杂度为 O(n²)。双指针更简洁，并在线性扫描阶段充分利用排序后的单调性。

面试追问

  • 如果不能修改原数组，如何处理？复制后排序，或使用计数数组（值域较小时）。
  • 如何返回对应下标？排序时保存“值 + 原下标”的二元组。
  • 如果要统计满足条件的数对数量？当和小于 k 时，可一次加入 right - left 个数对。

常见错误

  • 把条件写成 sum <= k。
  • 找到第一个可行和就返回，遗漏更优解。
  • 未按数值排序，或 JavaScript 中省略数值比较函数导致字典序排序。
  • 指针循环条件写成 left <= right，错误地重复使用同一元素。
