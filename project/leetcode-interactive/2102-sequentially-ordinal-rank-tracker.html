题目与规则

维护一个最初为空的景点集合。每个景点有唯一名称 name 和整数评分 score。排名先比较评分，分数高的更好；同分时，名称字典序小的更好。第 i 次调用查询，要返回当时所有已添加景点中排名第 i的名称，i 包含当前调用。

SORTracker()

初始化空系统。

add(name, score)

添加一个景点；返回 void。

get()

无参数，返回本次目标名次的字符串。

查询不会移除景点。新景点会改变排名，因此一个名称可以在多次查询中被返回。

约束

  • name 仅含小写英文字母；所有景点名称互不相同。
  • 1 ≤ name.length ≤ 10。
  • 1 ≤ score ≤ 105。
  • 任意时刻，get 调用次数不超过 add 调用次数。
  • add 与 get 总调用次数不超过 4 × 104。

双堆：维护第 k 名的分界线

核心洞察

查询的目标名次只会加一。设已经调用 get 的次数为 k，用左堆 L 保存当前最好的 k 个景点，右堆 R 保存其余景点。L 的堆顶是其中最差者，R 的堆顶是其中最好者。于是一次 get 只需把 R 的最好者移到 L，再读 L 的堆顶。

这里 L 保存的是当前前 k 名，并非“曾经返回过的景点”。这一区别解释了为什么同一景点可以被返回多次。排名键可写成 (-score, name)，键越小越好。

分界线观察窗

与上方步骤同步。两个堆仅将堆顶放在首行，其余元素按排名展示，方便阅读；列表不是堆的底层数组。

左堆 L · 最好的 k 个

首行：左侧最差者 / 本次查询后的答案

右堆 R · 剩余景点

首行：右侧最好者 / 下一次查询的候选

完整过程

  1. 初始化：L、R 都为空，k = 0。
  2. add(name, score)：先将新景点放入 L，再把 L 的最差者弹出并放入 R。L 大小先变成 k + 1，随后恢复为 k；被弹出的也可能就是新景点。
  3. get()：从 R 弹出最好者并压入 L。此时 L 有 k + 1 个景点，增加查询次数。返回 L 堆顶名称，即第 k + 1 好的景点。

例如已经查询一次且只有 b:1 时，L = {b}。添加更好的 a:2 后，L = {a}，b 移到 R。第二次 get 将 b 移回 L 并返回 b。这不是重复消费，而是查询当前第 2 名。

正确性证明

用归纳法维护三个不变量：L 与 R 不重不漏地保存全部景点；|L| = k；L 中每个景点都优于 R 中每个景点。空系统显然满足。

执行 add 时，旧的前 k 名都在 L。新的前 k 名必在“旧 L 加新景点”中。移出其中最差者后，L 正好仍是前 k 名；移出者加入 R 不改变全集和边界顺序。因此三个不变量继续成立。

执行 get 时，R 堆顶是当前第 k + 1 名。把它移入 L 后，L 恰好是新的前 k + 1 名；其中最差者正是刚移入的景点，故 L 堆顶就是所需答案。将 k 增一后不变量恢复。归纳可知所有查询正确。

边界与复杂度

  • k = 0 时，每次 add 的景点都经 L 转移到 R；L 保持为空。
  • 合法 get 前必有 n ≥ k + 1，所以 R 不会为空。查询后 R 可以为空；此时必须再 add 才能继续 get。
  • 评分相同必须比较完整名称；前缀相同时较短名称在前。名称唯一使排序具有确定性。
  • 设 n 为当前景点数，名称最大长度为 ℓ：add、get 的堆调整均为 O(ℓ log(n + 1))；按本题 ℓ ≤ 10 视为常数时为 O(log(n + 1))。返回堆顶本身 O(1)，但整个 get 仍包含堆调整。
  • 总空间 O(n) 个记录；计入字符串存储为 O(nℓ)。两堆合计存储全部景点，无历史快照。

Java

import java.util.Comparator;
import java.util.PriorityQueue;

class SORTracker {
    private static class Place {
        final String name;
        final int score;
        Place(String name, int score) {
            this.name = name;
            this.score = score;
        }
    }

    // Negative means a ranks better than b.
    private static final Comparator<Place> BEST = (a, b) -> {
        int byScore = Integer.compare(b.score, a.score);
        return byScore != 0 ? byScore : a.name.compareTo(b.name);
    };
    private final PriorityQueue<Place> left;
    private final PriorityQueue<Place> right;

    public SORTracker() {
        left = new PriorityQueue<>(BEST.reversed());
        right = new PriorityQueue<>(BEST);
    }

    public void add(String name, int score) {
        left.offer(new Place(name, score));
        right.offer(left.poll());
    }

    public String get() {
        left.offer(right.poll());
        return left.peek().name;
    }
}

import heapq

class _WorstFirst:
    def __init__(self, key):
        self.key = key

    def __lt__(self, other):
        # Reverse the whole tuple, including the name tie-break.
        return self.key > other.key

class SORTracker:
    def __init__(self):
        self.left = []   # Worst of the best k at the root.
        self.right = []  # Best of the rest at the root.

    def add(self, name: str, score: int) -> None:
        key = (-score, name)
        heapq.heappush(self.left, _WorstFirst(key))
        moved = heapq.heappop(self.left).key
        heapq.heappush(self.right, moved)

    def get(self) -> str:
        key = heapq.heappop(self.right)
        heapq.heappush(self.left, _WorstFirst(key))
        return self.left[0].key[1]

C++

#include <functional>
#include <queue>
#include <string>
#include <utility>
#include <vector>
using namespace std;

class SORTracker {
    using Key = pair<int, string>;  // (-score, name), smaller is better.
    priority_queue<Key> left;       // Largest key: worst in the best k.
    priority_queue<Key, vector<Key>, greater<Key>> right;

public:
    SORTracker() {}

    void add(string name, int score) {
        left.emplace(-score, name);
        right.push(left.top());
        left.pop();
    }

    string get() {
        left.push(right.top());
        right.pop();
        return left.top().second;
    }
};

替代方案

  • 每次查询重新排序：最容易写；单次 get 为 O(n log n)，频繁查询时成本较高，适合作为小规模参考。
  • 有序数组 + 二分插入：查位置 O(log n)，移动元素 O(n)，get 取第 k 项为 O(1)。总插入成本可能 O(n²)。
  • 带子树大小的平衡搜索树：插入和任意第 k 小查询均为 O(log n)，能支持跳跃名次与删除，但实现更复杂。普通有序集合若每次从头走到第 k 项，查询仍为 O(k)。

面试追问

  • 如果查询能指定任意名次？双堆需逐个移动边界，代价随名次差增长；可改用顺序统计树。
  • 如果允许更新评分或删除景点？需能定位旧元素并删除，或维护惰性删除与有效大小；平衡树通常更直接。
  • 如果一次 get 都没调用？L 始终为空，所有景点都留在 R。
  • k 为什么不用变量保存？L 的大小已隐含 k。代码只做固定转移，避免计数与堆大小失步。

常见错误

  • 把 get 当成“返回并永久删除最好景点”，忽略查询名次递增。
  • 左、右堆使用同一比较方向，或只反转评分而没有反转同分名称顺序。
  • add 后未把 L 大小恢复为 k，导致查询返回错位。
  • 混用“左堆保存 k 个”和“左堆保存 k + 1 个”的两种不变量。
  • 认定已返回景点不会再次出现，从集合中删掉答案。
  • 把 JavaScript 的 localeCompare 当作任意场景下的题目字典序；本实现对小写英文使用直接字符串比较。
