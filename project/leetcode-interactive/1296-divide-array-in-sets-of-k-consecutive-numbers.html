划分数组为连续数字的集合

Divide Array in Sets of K Consecutive Numbers

中等贪心数组哈希表排序

题目

给定整数数组 nums 和正整数 k，判断能否将数组中的每个元素恰好使用一次，划分成若干个大小为 k 的集合；每个集合内的数字必须逐个相差 1。

关键语义：这里的“集合”不要求元素在原数组中相邻；允许重复数字，但同一组里必须是连续的不同整数。

函数签名

isPossibleDivide(nums, k) → boolean

约束

  • 1 ≤ k ≤ nums.length ≤ 105
  • 1 ≤ nums[i] ≤ 109

官方示例

示例 1
输入：nums = [1,2,3,3,4,4,5,6], k = 4
输出：true
解释：[1,2,3,4] 与 [3,4,5,6]
示例 2
输入：nums = [3,2,1,2,3,4,3,4,5,9,10,11], k = 3
输出：true
解释：[1,2,3]、[2,3,4]、[3,4,5]、[9,10,11]
示例 3
输入：nums = [1,2,3,4], k = 3
输出：false
解释：4 个元素无法拆成若干个大小为 3 的集合。

Solution

贪心：从当前最小值强制开组

核心洞察：设尚未使用的最小数字为 x。它不可能成为某个连续组的中间或结尾，因为比它更小、能排在它前面的数字已经不存在。因此，任何合法划分都必须让 x 开启一组 x, x+1, …, x+k-1。这个选择没有自由度，可以放心贪心。

完整过程

  1. 如果 nums.length % k !== 0，元素总数不可能被大小为 k 的组整除，直接返回 false。
  2. 统计每个数字的出现次数，并按数字从小到大访问。
  3. 找到仍有剩余的最小数字 x，尝试依次消耗 x 到 x+k-1 各一个。
  4. 中途任何数字计数为 0，说明这组无法补齐，返回 false；否则记录该组并继续。
  5. 当所有计数都归零时，每个元素都被恰好使用一次，返回 true。

正确性证明

引理：最小值必须开组对当前最小剩余值 x，合法组中不存在可放在它前面的剩余数字，所以该组只能从 x 开始。
贪心选择安全由引理，任一合法方案都必须消耗 x…x+k-1 各一个；算法的选择与所有合法方案一致，不会排除可行解。
归纳得出结论移除该组后，剩余问题形式不变。反复应用安全选择；若缺数则任何方案都失败，若清空则得到完整合法划分。

边界情况

  • k = 1：每个元素自成一组，必然可行。
  • 数组长度不能被 k 整除：立即失败。
  • 存在重复数字：频次表会让相同起点开启多组，重复本身不是问题。
  • 数值跨度很大：只遍历出现过的键，不创建从最小值到最大值的稠密数组。

复杂度

时间 O(n log n)空间 O(n)

排序键或维护有序映射需要对数代价；每个数组元素最终至多被消耗一次。不同语言的有序容器实现常数略有差异。

class Solution {
    public boolean isPossibleDivide(int[] nums, int k) {
        if (nums.length % k != 0) return false;

        java.util.TreeMap<Integer, Integer> count = new java.util.TreeMap<>();
        for (int value : nums) {
            count.put(value, count.getOrDefault(value, 0) + 1);
        }

        while (!count.isEmpty()) {
            int start = count.firstKey();
            for (int value = start; value < start + k; value++) {
                Integer frequency = count.get(value);
                if (frequency == null) return false;
                if (frequency == 1) count.remove(value);
                else count.put(value, frequency - 1);
            }
        }
        return true;
    }
}

var isPossibleDivide = function(nums, k) {
    if (nums.length % k !== 0) return false;

    const count = new Map();
    for (const value of nums) {
        count.set(value, (count.get(value) || 0) + 1);
    }

    const values = [...count.keys()].sort((a, b) => a - b);
    for (const start of values) {
        const groups = count.get(start) || 0;
        if (groups === 0) continue;

        for (let value = start; value < start + k; value++) {
            const remaining = count.get(value) || 0;
            if (remaining < groups) return false;
            count.set(value, remaining - groups);
        }
    }
    return true;
};
from collections import Counter
from typing import List


class Solution:
    def isPossibleDivide(self, nums: List[int], k: int) -> bool:
        if len(nums) % k != 0:
            return False

        count = Counter(nums)
        for start in sorted(count):
            groups = count[start]
            if groups == 0:
                continue

            for value in range(start, start + k):
                if count[value] < groups:
                    return False
                count[value] -= groups

        return True
class Solution {
public:
    bool isPossibleDivide(vector<int>& nums, int k) {
        if (nums.size() % k != 0) return false;

        map<int, int> count;
        for (int value : nums) ++count[value];

        while (!count.empty()) {
            int start = count.begin()->first;
            for (int value = start; value < start + k; ++value) {
                auto it = count.find(value);
                if (it == count.end()) return false;
                if (--it->second == 0) count.erase(it);
            }
        }
        return true;
    }

替代方案

最小堆 + 哈希表：将所有不同数字放进最小堆，每次查看堆顶作为起点；计数归零时清理堆顶。复杂度同样约为 O(n log n)，但需要谨慎处理堆中的过期键。若直接排序整个数组再配合计数表，逻辑也直观，只是会排序重复元素。

面试追问

为什么不能随便从一个数字开始？

非最小数字可能本应接在更早的组后面；先拿走它会破坏可行方案。最小剩余值没有这个歧义。

能否做到 O(n)？

若数值范围很小，可用桶计数近似做到 O(n + range)。但在本题 nums[i] 可达 10⁹，通用解需要排序键或有序映射。

一次消耗一组还是批量消耗？

都正确。Java/C++ 示例逐组消耗；JavaScript/Python 一次批量消耗以同一最小值开头的所有组，常数更小。

如果要求原数组中的连续子数组呢？

那会变成不同问题，必须保留原下标顺序；本题只关心多重集合中的数值频次。

常见错误

  • 只检查“不同数字是否连续”，忽略每个数字的出现次数。
  • 没有先检查长度能否被 k 整除。
  • 从任意数字开组，而不是从当前最小剩余值开组。
  • 批量消耗时只减 1；若起点频次为 groups，后续每个数字都必须至少减去 groups。
  • 用长度为最大值的计数数组，导致面对 10⁹ 的值域时内存失控。
