2169 / Count Operations to Obtain Zero

两个数字，一次相减。观察它们如何走向第一个 0。

01 / 问题

遵循规则，数出步数

给定非负整数 num1 和 num2。只要两者都不为 0，就执行一次操作：

  • 若 num1 ≥ num2，令 num1 = num1 − num2。
  • 否则，令 num2 = num2 − num1。

返回任意一个数字变成 0 时，累计执行的操作次数。初始已有 0 时，无须操作。

官方示例 1

输入：num1 = 2, num2 = 3
输出：3

依次得到 (2, 1)、(1, 1)、(0, 1)，共 3 次操作。

官方示例 2

输入：num1 = 10, num2 = 10
输出：1

两数相等，第一次操作把 num1 变为 0，立即结束。

约束：0 ≤ num1, num2 ≤ 10⁵，均为整数。

04 / 深入理解

先观察，再展开题解

题解 · 直接模拟

核心洞察

题目已指定唯一操作，没有策略选择。保存当前两个数，按大小相减，每执行一次就计数加一，直到任意一个为 0。

完整过程

  1. 初始化计数 count = 0。
  2. 当 num1 > 0 且 num2 > 0 时进入循环。
  3. 若 num1 ≥ num2，更新 num1；否则只更新 num2。
  4. 计数加一，重新检查终止条件；循环结束后返回 count。
次数   num1   num2   本次变化
0        2      3   初始状态
1        2      1   num2 = 3 - 2
2        1      1   num1 = 2 - 1
3        0      1   num1 = 1 - 1 → 停止

正确性

循环不变量：每次循环开始时，两个变量等于按题目规则执行 count 次后的状态。初始 count 为 0，显然成立；一次循环只按规定的比较结果修改一个变量并递增 count，因此仍成立。

终止性：循环内两数均为正整数，相减后非负，而且两数之和至少减少 1。非负整数和不能无限下降，所以过程必定终止。退出时至少一个数字为 0，由不变量，count 恰是题目要求的操作次数。

边界与复杂度

  • 任意输入为 0：返回 0，包括 (0, 0)。
  • 相等且非零：在 ≥ 分支执行一次后结束。
  • 一个数为 1：可能连续执行另一个数那么多次，这是线性最坏情况。
  • 设初始值为 a、b。时间上界为 O(a + b + 1)（通常简写 O(a + b)），额外空间为 O(1)。网页为支持回退而保存的历史不属于提交算法的空间开销。

替代方案：按整除批量计数

当 a ≥ b > 0 时，连续减 b 的次数可合并为 q = a // b，计数加 q，再令 a %= b；另一侧同理。若余数为 0，最后一次相减正好到 0，也要计入。每轮相当于欧几里得算法的一步，时间为 O(log(min(a,b) + 1) + 1)，空间 O(1)。直接模拟在本题范围内已足够，下面四份提交代码统一使用模拟。

面试追问

  • 输入升到 10¹⁸ 怎么办？用除法合并连续操作，并使用能准确表示输入与计数的整数类型；JavaScript 应改用 BigInt。
  • 最后剩下的非零数是什么？当初始两数不全为 0 时，是 gcd(a, b)，因为相减保持最大公约数不变。
  • 能否直接返回最大公约数？不能。它描述最终非零值，不描述步数；例如 (2, 3) 的 gcd 为 1，操作数为 3。

常见错误

  • 用“或”连接循环条件：已有一个 0 时会不断减 0，无法结束。
  • 连续写两个独立 if：后一个条件可能读取刚更新的数，一轮误做两次操作。应使用 if / else。
  • 漏掉相等情况，或到 0 的最后一次操作没有计数。
  • 优化时把“取模轮数”当作答案：一轮取模可能合并多次相减，应累加商。

Java

class Solution {
    public int countOperations(int num1, int num2) {
        int count = 0;
        while (num1 > 0 && num2 > 0) {
            if (num1 >= num2) {
                num1 -= num2;
            } else {
                num2 -= num1;
            }
            count++;
        }
        return count;
    }
}
