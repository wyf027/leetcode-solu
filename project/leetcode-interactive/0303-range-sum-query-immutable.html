01 · 题目

任务说明

给定整数数组 nums，需要处理多次区间求和。实现 NumArray 类：

04 · 题解

前缀和：把区间变成两个端点之差

核心洞察

重复部分只算一次

构造长度为 n + 1 的数组 prefix，令 prefix[i] 表示前 i 个元素之和。查询时用两个累计值相减，公共前段自动抵消。

统一公式

prefix[right + 1] - prefix[left]

prefix[right + 1] 包含下标 0..right，减去只包含 0..left-1 的 prefix[left]，剩下的正是闭区间。

为何多一个 0

消除 left = 0 的分支

定义 prefix[0] = 0 后，即使 left = 0，公式仍然成立，不需要单独判断。

完整过程

  1. 构造时创建长度 nums.length + 1 的 prefix，默认 prefix[0] = 0。
  2. 依次令 prefix[i + 1] = prefix[i] + nums[i]。
  3. 查询 [left, right] 时，直接返回 prefix[right + 1] - prefix[left]。
  4. 数组不会更新，所以预处理结果在所有后续查询中始终有效。

正确性证明

定义：prefix[k] = nums[0] + … + nums[k - 1]，即前 k 个元素之和。

推导：prefix[right + 1] 是 nums[0..right] 的和；prefix[left] 是 nums[0..left-1] 的和。二者相减后，索引小于 left 的项全部抵消，只保留 nums[left..right]。

结论：返回值恰好是目标闭区间的元素和，因此算法正确。

边界处理

  • 单元素数组：prefix = [0, nums[0]]。
  • left = right：两个相邻前缀值之差。
  • left = 0：减去 prefix[0] = 0。
  • 负数与零不影响加法和抵消关系。

复杂度

  • 构造时间：O(n)
  • 单次查询：O(1)
  • 额外空间：O(n)

最坏区间和可达 10⁹，在题目当前约束下 32 位有符号整数可容纳。

替代方案

逐项求和：不预处理，空间 O(1)，但每次查询 O(n)，面对 10⁴ 次查询会重复扫描。

树状数组 / 线段树：支持更新，但本题数组不可变，结构更复杂且没有收益。

Java

LeetCode 类签名
class NumArray {
    private final int[] prefix;

    public NumArray(int[] nums) {
        prefix = new int[nums.length + 1];
        for (int i = 0; i < nums.length; i++) {
            prefix[i + 1] = prefix[i] + nums[i];
        }
    }

    public int sumRange(int left, int right) {
        return prefix[right + 1] - prefix[left];
    }
}

JavaScript

LeetCode 原型签名
/**
 * @param {number[]} nums
 */
var NumArray = function(nums) {
    this.prefix = new Array(nums.length + 1).fill(0);

    for (let i = 0; i < nums.length; i++) {
        this.prefix[i + 1] = this.prefix[i] + nums[i];
    }
};

/**
 * @param {number} left
 * @param {number} right
 * @return {number}
 */
NumArray.prototype.sumRange = function(left, right) {
    return this.prefix[right + 1] - this.prefix[left];
};

Python 3

LeetCode 类签名
from typing import List


class NumArray:
    def __init__(self, nums: List[int]):
        self.prefix = [0] * (len(nums) + 1)

        for i, value in enumerate(nums):
            self.prefix[i + 1] = self.prefix[i] + value

    def sumRange(self, left: int, right: int) -> int:
        return self.prefix[right + 1] - self.prefix[left]

面试追问

如果数组允许修改怎么办？

使用树状数组可在 O(log n) 内完成单点更新和区间查询；若需要更复杂的区间更新或统计，可考虑线段树。

如果扩展到二维矩阵呢？

建立二维前缀和，矩形区域通过容斥：右下整体减去上方和左方，再加回被重复减去的左上区域。

为什么不是原地改写 nums？

原地累计能节省一个数组，但会破坏传入数据的原始语义；独立存储更稳妥，也能用额外的 0 统一边界公式。

常见错误

  • 少算右端点：误用 prefix[right] - prefix[left]。
  • 减错位置：误减 prefix[left + 1]，导致丢失 nums[left]。
  • 没有前导 0：被迫为 left = 0 增加分支，并更容易出现下标错误。
  • 每次重新扫描：结果正确，但没有利用“数组不可变、查询很多”的条件。
  • 把本题做成动态结构：树状数组或线段树可用但过度设计。
