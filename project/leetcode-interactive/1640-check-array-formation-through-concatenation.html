能否连接

把若干小数组当作不能拆开的“拼图片”。你可以改变拼图片之间的顺序，却不能改变任何一片内部的数字顺序。判断它们能否严丝合缝地组成目标数组。

简单数组哈希表非付费题
任务边界

片可换位，片内不可换位

每个整数都互不相同，因此每个位置只可能属于唯一的一块拼图片。

  • 01任意排列 pieces 中的小数组
  • 02保持每个 pieces[i] 内部原序
  • 03完整连接后必须与 arr 完全相同

Problem brief

先把规则看清楚

给定互不相同整数构成的目标数组 arr，以及整数同样全局互不相同的二维数组 pieces。若可按任意顺序连接所有小数组并得到 arr，返回 true，否则返回 false。

函数参数

canFormArray(arr: integer[], pieces: integer[][]): boolean
关键限制：只能调整小数组之间的先后关系，不能拆开或重排小数组内部元素。

约束

  • 1 ≤ pieces.length ≤ arr.length ≤ 100
  • sum(pieces[i].length) == arr.length
  • 1 ≤ pieces[i].length ≤ arr.length
  • 1 ≤ arr[i], pieces[i][j] ≤ 100
  • arr 中整数互不相同；展平后的 pieces 中整数也互不相同

Solution

从每块的“首数字”出发

核心洞察

当扫描到 arr[i] 时，下一块拼图片的首元素必须恰好等于 arr[i]。用哈希表记录“首元素 → 整块”，即可直接定位唯一候选，再逐个核对片内元素。

因为所有数字互不相同，不会出现两块拥有相同首元素的歧义。一次成功匹配会让指针跨过整块，无须枚举 pieces 的排列。

完整过程

  1. 遍历 pieces，将每块第一个数作为键、整块作为值存入哈希表。
  2. 令目标指针 i = 0。
  3. 当 i < arr.length 时，用 arr[i] 查询；查不到就返回 false。
  4. 按原顺序遍历查到的块。每项都须等于当前 arr[i]，否则返回 false。
  5. 每匹配一项就让 i 加一；完整覆盖目标后返回 true。

正确性证明

必要性：若能形成 arr，任意未覆盖位置 i 的下一块首元素必为 arr[i]，且块内顺序必须与目标连续片段一致。算法失败时不存在其他合法选择。
充分性：算法每次选中首元素等于当前目标值的块，并逐项确认整块与目标连续片段一致，因此始终保持“已拼前缀等于目标同长前缀”。
终止：每次成功比较都令 i 严格增加；当 i = arr.length 时，拼接结果与整个目标相同。

边界情况

  • 单元素：arr = [x] 与 pieces = [[x]] 可直接形成。
  • 起点不存在：没有以 arr[i] 开头的块，立即返回 false。
  • 片内冲突：块首匹配但后续不一致，返回 false。
  • 整块等于目标：一次比较覆盖全部位置。
  • 目标末端：比较前检查指针是否越界，保持实现稳健。

复杂度

设 n = arr.length，m = pieces.length。建立映射访问每块一次，比较阶段每个数字至多一次。

时间复杂度O(n + m)
空间复杂度O(m)

四语言完整代码

Java官方可提交签名
class Solution {
    public boolean canFormArray(int[] arr, int[][] pieces) {
        java.util.Map<Integer, int[]> byFirst = new java.util.HashMap<>();
        for (int[] piece : pieces) {
            byFirst.put(piece[0], piece);
        }

        int i = 0;
        while (i < arr.length) {
            int[] piece = byFirst.get(arr[i]);
            if (piece == null) return false;
            for (int value : piece) {
                if (i >= arr.length || arr[i] != value) return false;
                i++;
            }
        }
        return true;
    }
}

    const byFirst = new Map();
    for (const piece of pieces) {
        byFirst.set(piece[0], piece);
    }

    while (i < arr.length) {

            i++;
        }
    }
    return true;

class Solution:
    def canFormArray(self, arr: List[int], pieces: List[List[int]]) -> bool:
        by_first = {piece[0]: piece for piece in pieces}
        i = 0

        while i < len(arr):
            piece = by_first.get(arr[i])
            if piece is None:
                return False
            for value in piece:
                if i >= len(arr) or arr[i] != value:
                    return False
                i += 1
        return True
C++官方可提交签名
class Solution {
public:
    bool canFormArray(vector<int>& arr, vector<vector<int>>& pieces) {
        unordered_map<int, const vector<int>*> byFirst;
        for (const auto& piece : pieces) {
            byFirst[piece[0]] = &piece;
        }

        int i = 0;
        while (i < static_cast<int>(arr.size())) {
            auto it = byFirst.find(arr[i]);
            if (it == byFirst.end()) return false;
            for (int value : *it->second) {
                if (i >= static_cast<int>(arr.size()) || arr[i] != value) {
                    return false;
                }
                ++i;
            }
        }
        return true;
    }
};

替代方案

值域数组代替哈希表

数字仅在 1..100，可用长度 101 的数组保存首元素对应的块。复杂度相同、常数更小，但泛化性较弱。

枚举拼图片排列

尝试全部排列再连接比较，最坏为 O(m! · n)，忽略了当前位置能唯一确定下一块的结构。

面试追问

如果数字不再互不相同呢？

一个首元素可能对应多块，局部选择不再唯一。可保存候选列表，并根据约束使用回溯或记忆化搜索。

为什么不用记录某块是否已使用？

所有数字全局互不相同；一块匹配后，它的首元素不会再次出现。若移除该条件，就需要使用状态。

能否边读 pieces 边处理 arr？

若输入顺序任意，必须先拥有完整的首元素索引；只有数据流保证所需块先出现时才适合流式处理。

常见错误

  • 对小数组内部排序，破坏片内顺序限制。
  • 只比较元素集合，不比较连续顺序。
  • 每个位置都线性扫描所有块，错过首元素索引。
  • 匹配一块后只让指针加一，而非跨过全部元素。
  • 把推测结果写成实际输出；本页验证区明确保持“待补验证”。
