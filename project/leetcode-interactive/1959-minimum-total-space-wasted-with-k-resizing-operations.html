K 次调整数组大小
浪费的最小总空间

Minimum Total Space Wasted With K Resizing Operations

容量要够用，也要尽量少留空。如何在有限次调整中安排整段时间？

LeetCode 官方题目 ↗

01 / 题意

给定从 0 开始编号的整数数组 nums，nums[t] 表示时刻 t 动态数组需要容纳的元素个数。你可以在整个时间段内最多调整 k 次容量，每次可设为任意大小，但任何时刻的容量 size[t] 都必须满足 size[t] ≥ nums[t]。

该时刻浪费的空间是 size[t] − nums[t]。返回所有时刻浪费空间之和的最小值。

初始容量任意选择，不计入调整次数。容量可以变大，也可以变小；计算的是每个时刻空闲容量的总和。

参数与返回值

minSpaceWastedKResizing(nums, k) → integer

  • nums：整数数组，1 ≤ nums.length ≤ 200。
  • 1 ≤ nums[i] ≤ 10⁶。
  • k：整数，0 ≤ k ≤ nums.length − 1。

02 / 官方示例

示例 1

输入：nums = [10,20], k = 0
输出：10

容量可取 [20,20]，总浪费为 10 + 0 = 10。

示例 2

输入：nums = [10,20,30], k = 1
输出：10

容量可取 [20,20,30]，在时刻 2 调整一次，总浪费为 10 + 0 + 0 = 10。

示例 3

输入：nums = [10,20,15,30,20], k = 2
输出：15

容量可取 [10,20,20,30,30]，在时刻 1 和 3 调整，总浪费为 0 + 0 + 5 + 0 + 10 = 15。

04 / 题解 · 把调整变成连续分段

核心洞察

不调整容量的一段时间必须使用同一个容量。对于区间 [l,r]，最小可行容量就是区间最大值。因此这一段的最小浪费为：

cost(l,r) = max(nums[l..r]) × (r − l + 1) − sum(nums[l..r])

最多 k 次调整对应最多 k+1 段。把一段再切开，每个子段的最大值都不超过原容量，所以浪费不会增加。由于 k+1 ≤ n，可以求恰好 k+1 个非空段的最优值；相邻段容量相同也无需实际调整，因此仍符合“最多 k 次”。

完整过程与状态转移

  1. 枚举区间左端点，再向右扩展，维护最大值与区间和，预处理所有 cost。
  2. 令 dp[s][i] 表示前 i 个时刻划为恰好 s 段时的最小浪费。初值 dp[0][0] = 0，其余为无穷大。
  3. 枚举最后一段的起点 j；前面 j 个元素分为 s−1 段，最后一段是 [j,i−1]。
  4. 按段数从小到大填表，返回 dp[k+1][n]。
dp[s][i] = min(dp[s−1][j] + cost(j,i−1))
            s−1 ≤ j < i,  s ≤ i ≤ n

容量屋顶实验室

逐步枚举每个状态的最后一段。紫色为当前候选区间的实际需求，黄色斜纹为这一段的浪费，灰色属于其他时刻。状态表显示已处理候选的当前最优值；这只是演示计算，不是验证记录。

逗号分隔的 1–1000000 整数，0 ≤ k < 项数；输入上限仅用于演示可读性。

正确性证明

区间最优性：同一段的容量至少是最大需求；取更大值会让段内每个时刻的浪费同步增加，因此取最大值最优。

转移完备性：任意恰好 s 段的合法划分都有唯一的最后一段起点 j，范围是 s−1 到 i−1。枚举 j 覆盖所有划分。对于固定 j，最后一段代价已确定，前缀若不是最优，就可替换为更优前缀而不影响最后一段。由初值与段数归纳，转移得到每个状态的最优值。

次数约束：每个至多 k 次调整的方案能对应至多 k+1 段。继续细分直到 k+1 段不会增加成本；反向看，k+1 段最多需要 k 次容量变化。所以最终状态与原题最优值相同。

边界与复杂度

  • k = 0：整体最大值乘 n，再减总和。
  • n = 1、k = n−1 或所有需求相同：最优浪费为 0。
  • 需求下降时也可以缩容，不能只考虑单调增加容量。
  • 预处理时间 O(n²)；转移时间 O((k+1)n²)；空间 O(n² + (k+1)n)，由 k < n 可化简为 O(n²)。
  • 总浪费与中间乘积不超过 2×10⁸。Java/C++ 的有符号 32 位整数足够，代码使用 10⁹ 作为不可达哨兵并跳过不可达转移。

替代方案

可以使用记忆化搜索 dfs(start, segments) 枚举第一段终点，状态和复杂度相同；递归深度最多 n。也可在转移时向左扫描，现场维护最大值与区间和，并滚动保存两层 DP，将额外空间降为 O(n)，但需要更仔细地处理更新顺序。按最大落差贪心切分没有全局最优保证，因为一段的最大值会影响整段成本。

Java

import java.util.Arrays;

class Solution {
    public int minSpaceWastedKResizing(int[] nums, int k) {
        int n = nums.length, parts = k + 1;
        int[][] cost = new int[n][n];
        for (int l = 0; l < n; l++) {
            int max = 0, sum = 0;
            for (int r = l; r < n; r++) {
                max = Math.max(max, nums[r]);
                sum += nums[r];
                cost[l][r] = max * (r - l + 1) - sum;
            }
        }
        int inf = 1_000_000_000;
        int[][] dp = new int[parts + 1][n + 1];
        for (int[] row : dp) Arrays.fill(row, inf);
        dp[0][0] = 0;
        for (int s = 1; s <= parts; s++) {
            for (int i = s; i <= n; i++) {
                for (int j = s - 1; j < i; j++) {
                    if (dp[s - 1][j] == inf) continue;
                    dp[s][i] = Math.min(dp[s][i],
                        dp[s - 1][j] + cost[j][i - 1]);
                }
            }
        }
        return dp[parts][n];
    }
}

    const n = nums.length, parts = k + 1;
    const cost = Array.from({length: n},
        () => Array(n).fill(0));
    for (let l = 0; l < n; l++) {
        let max = 0, sum = 0;
        for (let r = l; r < n; r++) {
            max = Math.max(max, nums[r]);
            sum += nums[r];
            cost[l][r] = max * (r - l + 1) - sum;
        }
    }
    const dp = Array.from({length: parts + 1},
        () => Array(n + 1).fill(Infinity));
    dp[0][0] = 0;
    for (let s = 1; s <= parts; s++) {
        for (let i = s; i <= n; i++) {

    return dp[parts][n];

Python 3

from typing import List

class Solution:
    def minSpaceWastedKResizing(
        self, nums: List[int], k: int
    ) -> int:
        n, parts = len(nums), k + 1
        cost = [[0] * n for _ in range(n)]
        for l in range(n):
            maximum = total = 0
            for r in range(l, n):
                maximum = max(maximum, nums[r])
                total += nums[r]
                cost[l][r] = maximum * (r - l + 1) - total

        inf = float("inf")
        dp = [[inf] * (n + 1) for _ in range(parts + 1)]
        dp[0][0] = 0
        for s in range(1, parts + 1):
            for i in range(s, n + 1):
                for j in range(s - 1, i):
                    if dp[s - 1][j] == inf:
                        continue
                    dp[s][i] = min(
                        dp[s][i],
                        dp[s - 1][j] + cost[j][i - 1]
                    )
        return int(dp[parts][n])

C++

#include <algorithm>
#include <vector>
using namespace std;

class Solution {
public:
    int minSpaceWastedKResizing(vector<int>& nums, int k) {
        int n = nums.size(), parts = k + 1;
        vector<vector<int>> cost(n, vector<int>(n));
        for (int l = 0; l < n; ++l) {
            int maximum = 0, sum = 0;
            for (int r = l; r < n; ++r) {
                maximum = max(maximum, nums[r]);
                sum += nums[r];
                cost[l][r] = maximum * (r - l + 1) - sum;
            }
        }
        const int INF = 1000000000;
        vector<vector<int>> dp(
            parts + 1, vector<int>(n + 1, INF));
        dp[0][0] = 0;
        for (int s = 1; s <= parts; ++s) {
            for (int i = s; i <= n; ++i) {
                for (int j = s - 1; j < i; ++j) {
                    if (dp[s - 1][j] == INF) continue;
                    dp[s][i] = min(dp[s][i],
                        dp[s - 1][j] + cost[j][i - 1]);
                }
            }
        }
        return dp[parts][n];
    }
};

常见错误

  • 把初始容量也算作一次调整，误用 k 段而非 k+1 段。
  • 使用区间平均值作为容量，导致最大需求无法容纳。
  • 只取最高峰与当前需求的差，漏乘区间长度或漏减区间总和。
  • 允许空段，或忘记初始化无穷大，让不可达状态贡献虚假的 0。
  • 把“最多调整”误解为必须发生 k 次不同容量的变化。

面试追问

如何输出调整时刻？保存每个状态取得最小值的 j，从 (k+1,n) 反向恢复区间，取各段最大值为容量，相邻相同容量可合并。

每次调整还有固定费用怎么办？分别求 s 段的最优浪费，加上 (s−1)×fee 后在所有合法 s 上取最小值；此时不应直接固定使用最多段数。

若每个时刻权重不同？对于非负权重，段容量仍取最大需求；代价改为容量乘权重和减去需求与权重的乘积和，可使用前缀和预处理。
