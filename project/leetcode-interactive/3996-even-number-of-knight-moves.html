偶数次骑士移动

不必搜索 64 个格子。骑士每走一步都会翻转格子颜色，因此只需比较起点和终点的棋盘颜色。

一眼判定

同色 → 可以

偶数步恰好回到同色格。

题意

在标准 8 × 8 国际象棋棋盘上，start = [x, y] 与 target = [x, y] 分别表示两个格子。骑士每次横向走 2 格、纵向走 1 格（或相反）。判断能否从起点以偶数次移动抵达终点；0 次也算偶数。

示例 1：start = [1, 1]，target = [2, 2]，输出 true。两格同色，存在 4 步路线。

示例 2：start = [4, 5]，target = [6, 6]，输出 false。两格异色，任何路线步数都是奇数。

约束：start.length = target.length = 2

约束：0 ≤ start[i], target[i] ≤ 7

SOLUTION

题解区域

默认折叠，先自己观察棋盘颜色规律。

核心洞察：棋盘是二分图

把格子按 (x + y) % 2 染成两色。骑士的一步会让坐标和改变奇数，因此一定从一种颜色跳到另一种颜色。偶数步后颜色不变；棋盘骑士图连通，所以同色两格总能用偶数步连通。

完整过程

  1. 计算起点颜色 (start[0] + start[1]) % 2。
  2. 计算终点颜色。
  3. 颜色相同返回 true，不同返回 false。

边界与复杂度

起点等于终点时颜色相同，0 步直接成立。算法只做常数次加法和取模：时间 O(1)，额外空间 O(1)。

替代方案与常见错误

BFS 可求最短步数，但对固定棋盘是过度计算。常见错误是只检查能否到达（骑士图连通，几乎总能到达），却遗漏“偶数次”的颜色不变量；也别把坐标差的奇偶误当成唯一条件。

面试追问

若棋盘尺寸、棋子走法或障碍物改变，图不再保证连通，就要把“颜色相同”视为必要条件而非充分条件；此时可在状态图上 BFS，并记录步数奇偶。 

class Solution {
    public boolean canReach(int[] start, int[] target) {
        return ((start[0] + start[1]) & 1) == ((target[0] + target[1]) & 1);
    }
}
var canReach = function(start, target) {
  return ((start[0] + start[1]) & 1) === ((target[0] + target[1]) & 1);
};
