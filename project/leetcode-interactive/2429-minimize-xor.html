最小异或

MEDIUMMinimize XOR· 免费题

在固定的 1 的数量下，寻找与给定数字异或距离最小的那个数。

01 / PROBLEM

题目说明

给定两个正整数 num1 和 num2，返回一个正整数 x，使它同时满足：

  • x 的二进制中，1 的个数与 num2 一样。
  • 在所有满足这一条件的正整数中，x XOR num1 最小。

题目保证答案唯一。“置位数”就是二进制中 1 的个数；异或在两个对应位不同时得到 1，相同时得到 0。

约束
1 ≤ num1, num2 ≤ 10⁹
返回的是 x，而非最小的异或值。

官方接口：minimizeXor(num1, num2) → integer

官方示例

示例 1

输入：num1 = 3, num2 = 5
输出：3

3 = 0011，5 = 0101，均有两个 1。取 x = 3 时，3 XOR 3 = 0。

示例 2

输入：num1 = 1, num2 = 12
输出：3

1 = 0001，12 = 1100。x = 3（二进制 0011）有两个 1，3 XOR 1 = 2，为可取得的最小值。

04 / SOLUTION

独立题解

准备好后展开，阅读完整推导与四语言实现。

核心洞察：高位相同优先，低位补足数量

设 k = popcount(num2)。num2 的具体位位置不重要，它只规定 x 中 1 的数量。异或值的第 i 位为 1 会贡献 2ⁱ，而所有比它低的位的贡献之和至多为 2ⁱ − 1，所以高位匹配拥有绝对优先级。

完整过程

  1. 统计 num2 的置位数 k，令 x = 0。
  2. 从第 29 位到第 0 位扫描 num1。若该位为 1 且仍有配额，就在 x 的相同位放一个 1，k 减一。这样优先消掉最昂贵的异或位。
  3. 如果还有配额，从第 0 位到第 29 位扫描 x 的空位，每遇到一个 0 就将其置为 1，直到 k = 0。此时 num1 的所有 1 都已经被保留，新增 1 的代价就是该位的位权。
  4. 返回 x。

例：num1 = 26 = 11010，num2 = 3 = 00011，需要两个 1。先保留第 4 位得到 10000，再保留第 3 位得到 11000，配额用尽。x = 24，异或值为 00010 = 2。

补位例：num1 = 1，num2 = 12，需要两个 1。先保留第 0 位，再在最低空位（第 1 位）补一个 1，得到 x = 3。

正确性证明

可行性：每次只对 x 的一个 0 位置位，且配额减一。30 位足以容纳 num2 所需的至多 30 个 1，因此最终配额为 0，x 恰好具有目标置位数；num2 为正保证 x 为正。

当目标数量不多于 num1 的置位数：最优解不会把 1 放在 num1 的 0 位而漏掉一个 num1 的 1 位；交换这两个位置会同时消除两个异或中的 1，使值更小。在 num1 的 1 位中，若选择低位 j 而放弃高位 i，则交换可使异或值减少 2ⁱ − 2ʲ > 0。因此保留最高的 k 个 1 最优。

当目标数量多于 num1 的置位数：最优解必须保留 num1 的所有 1，否则总能从一个额外的 1 位移出配额去匹配被遗漏的 1，同时降低异或值。剩余配额只能放在 num1 的 0 位上，代价为对应位权，选择最低的空位最优。两个阶段恰好实现这些选择，故算法正确。

唯一性：对于不同 x，固定 num1 后的异或结果也不同，因为异或可逆。因此最小异或值对应唯一的 x。

边界与复杂度

  • 两个数的置位数相同，直接得到 x = num1，异或值为 0；两个数本身无需相等。
  • 目标只有一个 1，保留 num1 的最高置位。
  • 目标数量更多，补最低的空位；不能重复计算已设置的位。
  • 输入小于 2³⁰，扫描下标 0…29 足够。JavaScript 的位运算采用 32 位有符号整数，此范围不会触及符号位；扩展到更大整数时应使用 BigInt 并调整位宽。

令 B 为所用位宽，时间 O(B)，额外空间 O(1)。本题固定 B = 30，所以也可记为 O(1) 时间与空间。交互页面保存步骤用于回退，与提交代码的空间复杂度无关。

四语言完整实现

Java

class Solution {
    public int minimizeXor(int num1, int num2) {
        int k = Integer.bitCount(num2), x = 0;
        for (int i = 29; i >= 0 && k > 0; i--) {
            if ((num1 & (1 << i)) != 0) {
                x |= 1 << i;
                k--;
            }
        }
        for (int i = 0; i < 30 && k > 0; i++) {
            if ((x & (1 << i)) == 0) {
                x |= 1 << i;
                k--;
            }
        }
        return x;
    }
}

JavaScript

/**
 * @param {number} num1
 * @param {number} num2
 * @return {number}
 */
var minimizeXor = function(num1, num2) {
    let k = 0, x = 0;
    for (let n = num2; n; n &= n - 1) k++;
    for (let i = 29; i >= 0 && k > 0; i--) {
        if (num1 & (1 << i)) {
            x |= 1 << i;
            k--;
        }
    }
    for (let i = 0; i < 30 && k > 0; i++) {
        if ((x & (1 << i)) === 0) {
            x |= 1 << i;
            k--;
        }
    }
    return x;
};

Python

class Solution:
    def minimizeXor(self, num1: int, num2: int) -> int:
        k = bin(num2).count("1")
        x = 0
        for i in range(29, -1, -1):
            if k and (num1 & (1 << i)):
                x |= 1 << i
                k -= 1
        for i in range(30):
            if k and (x & (1 << i)) == 0:
                x |= 1 << i
                k -= 1
        return x

Python 的 bin 统计会产生 O(B) 长度的临时字符串；本题固定 30 位，空间为常数。若讨论可变位宽且要求避免字符串，可改用 n &= n − 1 循环统计。

C++

class Solution {
public:
    int minimizeXor(int num1, int num2) {
        int k = 0, x = 0;
        for (int n = num2; n; n &= n - 1) ++k;
        for (int i = 29; i >= 0 && k > 0; --i) {
            if (num1 & (1 << i)) {
                x |= 1 << i;
                --k;
            }
        }
        for (int i = 0; i < 30 && k > 0; ++i) {
            if ((x & (1 << i)) == 0) {
                x |= 1 << i;
                --k;
            }
        }
        return x;
    }
};

替代方案：直接调整 num1

令 x = num1，比较它的置位数与目标数量。过多时重复 x &= x − 1 清除最低的 1；过少时重复 x |= x + 1 将最低的 0 置为 1。它只修改必要的低位，原理与高位优先的构造相同，时间 O(B)，额外空间 O(1)。枚举所有具有 k 个 1 的数虽可作为小位宽参考，但组合数会迅速增大，不适合本题范围。

常见错误

  • 将 x 设成 num2：相同的是 1 的数量，不是它们的位置。
  • 从低到高匹配 num1 的 1：会把更昂贵的高位留在异或值中。
  • 补位也从高到低：增加了不必要的代价。
  • 返回 x XOR num1，或误把 XOR 写为乘方。
  • 以为 x 必须小于等于 num1：例如 (1, 12) 的答案为 3。

面试追问

  • 为什么低位无法抵消高位损失？因为 2ⁱ 大于所有更低位权之和。
  • num2 的排列是否影响答案？不影响，只看其置位数。
  • 若允许 num2 = 0？同置位数只能得到 x = 0，与题目要求 x 为正冲突，需先调整题目定义。
  • 若换成 64 位输入？扩大扫描范围并使用无符号或适当宽度类型；JavaScript 使用 BigInt，避免 32 位截断。
