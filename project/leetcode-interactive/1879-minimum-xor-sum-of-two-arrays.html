两个数组最小的异或值之和

Minimum XOR Sum of Two Arrays

每个数字只能配对一次。重新安排第二个数组，让所有对应位置的异或结果相加后尽可能小。

01 / 题目

输入两个长度相同的整数数组 nums1 和 nums2，长度为 n。保持 nums1 的顺序，允许任意重排 nums2。对每个下标计算两个数字的按位异或，再将这 n 个结果相加，返回能够得到的最小总和。

返回 min Σ (nums1[i] XOR rearrangedNums2[i])，0 ≤ i < n
参数：nums1: int[], nums2: int[]    返回：int

XOR 表示按位异或：相同位得 0，不同位得 1。这里相加的是各对的异或结果，最终聚合运算是加法。

约束

  • n == nums1.length == nums2.length
  • 1 ≤ n ≤ 14
  • 0 ≤ nums1[i], nums2[i] ≤ 10⁷

示例 1

输入：nums1 = [1,2], nums2 = [2,3]
输出：2

将 nums2 排为 [3,2]，总和为 (1 XOR 3) + (2 XOR 2) = 2 + 0 = 2。

示例 2

输入：nums1 = [1,0,3], nums2 = [5,3,4]
输出：8

将 nums2 排为 [5,4,3]，总和为 (1 XOR 5) + (0 XOR 4) + (3 XOR 3) = 4 + 4 + 0 = 8。

03 / 题解实验室

准备好后，展开推演、证明和四语言代码。

核心洞察：已用下标集合决定未来

依次为 nums1[0], nums1[1], … 选择搭档。若已经选用了 nums2 的同一组下标，无论此前的配对顺序如何，后续能选的下标都相同。因此只需保留这组下标对应的最小历史代价。

dp[mask]：使用 nums2 中 mask 标出的下标，匹配完 nums1 的前 popcount(mask) 个元素时的最小异或和。掩码按下标编码，重复数值仍是不同元素。

交互 / 一次选边，一次状态更新

绿色标出出发状态，琥珀色标出目标状态及本次配对。∞ 表示尚未到达。二进制掩码右侧最低位对应 nums2[0]。

完整过程


  1. 共有 2ⁿ 个子集。初始化 dp[0] = 0，其他状态为 ∞。
  2. 按 mask 从小到大遍历。令 i = popcount(mask)，下一个要匹配的是 nums1[i]。
  3. 枚举所有未使用的下标 j，令 next = mask | (1 << j)，尝试用 nums2[j] 与 nums1[i] 配对。
  4. 更新 dp[next] = min(dp[next], dp[mask] + (nums1[i] XOR nums2[j]))。
  5. 最终答案是 dp[(1 << n) - 1]。完整状态没有下一个 nums1 元素，不再扩展。


新增一个原来为 0 的位后，next 一定大于 mask，所以按数值递增遍历就是有效的拓扑顺序。四份代码都先递推计算位数：count[m] = count[m >> 1] + (m & 1)。


示例 2 的一条最优路径


mask 000：尚未配对，代价 0
000 → 001：nums1[0]=1 配 nums2[0]=5，增加 4，总计 4
001 → 101：nums1[1]=0 配 nums2[2]=4，增加 4，总计 8
101 → 111：nums1[2]=3 配 nums2[1]=3，增加 0，总计 8
重排 nums2 为 [5,4,3]，最小总和 8。


正确性证明


基础：mask=0 时没有配对，唯一合法代价为 0。


归纳：假设所有包含 k 个已用下标的状态已经得到最小值。任意 k+1 对配对方案，都能删除最后一对，得到某个 k 元素状态及一个未使用下标 j。算法枚举了这一次扩展，因此不会漏掉最优方案。反之，每次扩展都只使用一个新下标，生成的方案合法；取最小值不会产生不存在的代价。同一状态只保留最小历史代价也安全，因为未来可用下标与下一 nums1 下标完全相同。


结论：由归纳，所有状态的最小值均正确，全 1 掩码正好代表完整配对，返回值即全局最优。


复杂度与数值边界


时间 O(n · 2ⁿ)，辅助空间 O(2ⁿ)。有效扩展一共 n · 2ⁿ⁻¹ 次；n=14 时有 16384 个状态、114688 条有效扩展。位数数组和代价数组都是 2ⁿ 大小。


输入值小于 2²⁴，所以一次 XOR 至多 2²⁴−1，总和至多 234881010，32 位有符号整数足够。JavaScript 的位运算使用 32 位整数，这里的数值和至多 14 位的掩码都在安全范围内。Java/C++ 使用 10⁹ 作为不可达哨兵并跳过它。


边界与常见错误


  • n=1 时直接得到两个数字的 XOR；零与重复值不需要特殊分支。
  • 不可用“数值集合”代替“下标集合”，否则重复值会丢失。
  • 不要把 nums1 的下标写成 mask；它应为 mask 中 1 的数量。
  • 必须给整个 XOR 表达式加括号，避免与加法、比较混用时出现优先级错误。
  • 不能对所有状态初始化为 0；这会把尚未到达的状态当作免费路径。
  • 按位优化时不能让不同二进制位分别选择不同配对；所有位必须共享同一个排列。


替代方案


枚举 nums2 的全部排列需要 O(n · n!)，不适合 n=14。记忆化搜索以 mask 为键，复杂度与本解法相同，但多出递归调用。也可以把两数组作为二分图两侧，边权为 XOR，求最小权完美匹配；匈牙利算法可做到 O(n³)，适合规模更大时使用，本题规模下子集 DP 更容易实现。


排序后逐项匹配或每步挑最小 XOR 都不保证最优。例如 nums1=[0,3]、nums2=[2,4]：先选 0 XOR 2 会得到 2+7=9；改为 [4,2] 则得到 4+1=5。


面试追问


  • 如何返回具体排列？ 更新最优值时记录父状态和 j，从全 1 掩码逆向恢复，再反转。
  • 最优解不唯一怎么办？ 本题只要代价；若需字典序最小排列，应另行定义并实现平局处理，不能假定第一次更新满足要求。
  • 为什么不用 dp[i][mask]？ i 恒等于 popcount(mask)，增加这一维会重复记录信息。
  • 若 n 扩大到几百？ 指数规模已不可行，应考虑多项式时间的最小权完美匹配。

Java


import java.util.Arrays;

class Solution {
    public int minimumXORSum(int[] nums1, int[] nums2) {
        int n = nums1.length, size = 1 << n;
        int[] count = new int[size];
        for (int m = 1; m < size; m++) {
            count[m] = count[m >> 1] + (m & 1);
        }
        int inf = 1_000_000_000;
        int[] dp = new int[size];
        Arrays.fill(dp, inf);
        dp[0] = 0;
        for (int mask = 0; mask < size - 1; mask++) {
            if (dp[mask] == inf) continue;
            int i = count[mask];
            for (int j = 0; j < n; j++) {
                if ((mask & (1 << j)) != 0) continue;
                int next = mask | (1 << j);
                int candidate = dp[mask] + (nums1[i] ^ nums2[j]);
                dp[next] = Math.min(dp[next], candidate);
            }
        }
        return dp[size - 1];
    }
}

from typing import List

class Solution:
    def minimumXORSum(self, nums1: List[int], nums2: List[int]) -> int:
        n = len(nums1)
        size = 1 << n
        count = [0] * size
        for m in range(1, size):
            count[m] = count[m >> 1] + (m & 1)
        inf = 10**9
        dp = [inf] * size
        dp[0] = 0
        for mask in range(size - 1):
            if dp[mask] == inf:
                continue
            i = count[mask]
            for j in range(n):
                if mask & (1 << j):
                    continue
                nxt = mask | (1 << j)
                candidate = dp[mask] + (nums1[i] ^ nums2[j])
                dp[nxt] = min(dp[nxt], candidate)
        return dp[-1]
