车队 Car Fleet

每辆车都想抵达同一个终点，但这是一条不能超车的路。先观察车辆从终点向后“吞并”的过程，再决定怎样计数。

MEDIUM数组排序单调栈非付费题
Problem

先把规则说清楚

重点不是模拟每一秒，而是判断后车能否在终点之前追上前车。

一条从里程 0 通往里程 target 的单行道上有 n 辆车。position[i] 和 speed[i] 分别表示第 i 辆车的起始位置和恒定速度。

车不能超过前车；若追上，只能与前车并行并跟随整个车队中最慢的速度。单独一辆车也算一个车队。若恰好在 target 处追上，仍算同一车队。请返回抵达目的地的车队数量。

函数签名
carFleet(target: integer, position: integer[], speed: integer[]) → integer
示例 1
target = 12, position = [10,8,0,5,3], speed = [2,4,1,1,3]
输出：3

10 与 8 在终点汇合；5 与 3 在位置 6 汇合；位置 0 的车独立到达。

示例 2
target = 10, position = [3], speed = [3]
输出：1

只有一辆车，因此只有一个车队。

示例 3
target = 100, position = [0,2,4], speed = [4,2,1]
输出：1

后方快车逐次追上前方慢车，最后合并成一个车队。

约束

  • n == position.length == speed.length
  • 1 ≤ n ≤ 10⁵
  • 0 < target ≤ 10⁶
  • 0 ≤ position[i] < target
  • position 中所有值互不相同
  • 0 < speed[i] ≤ 10⁶

Solution

排序 + 单调到达时间

!
核心洞察
按起点从靠近终点到远离终点处理。对每辆车计算独自抵达终点所需时间 (target - position) / speed。后车到达时间不大于前方最后一个车队的时间，就一定能在终点前或终点处追上；否则它会形成新车队。

完整过程

  1. 把每辆车的起始位置与速度配对，并按位置降序排列。
  2. 从最靠近终点的车向后扫描，计算当前车独自到达终点的时间。
  3. 维护最靠后已确认车队的到达时间 lastTime。若当前时间大于 lastTime，后车更慢，无法追上，新增车队并更新 lastTime。
  4. 若当前时间小于或等于 lastTime，它会追上前方车队，车队数量不变。相等对应恰好在终点汇合。

正确性说明

不变量：扫描完位置更靠前的车辆后，计数等于这些车辆最终形成的车队数，lastTime 是最后一个（位置最靠后）已形成车队的到达时间。

处理下一辆后车时，若其独立到达时间 ≤ lastTime，它在前方车队到达前拥有足够时间追上；禁止超车使它只能并入该车队。不变量保持。若其时间 > lastTime，前方车队先到终点，后车不可能追上，因此必然新建一个车队，并将它的时间设为新的 lastTime。两种情况穷尽所有可能，扫描结束时计数即为答案。

复杂度

排序耗时 O(n log n)，扫描耗时 O(n)。配对数组占用 O(n) 额外空间；若原地组织数据，可视语言能力进一步优化。

边界情况

  • 仅一辆车：答案为 1。
  • 恰在终点追上：使用 ≤ 合并。
  • 所有车速度相同：互不追上。
  • 浮点精度：本题范围通常安全；也可用交叉相乘比较分数。

替代方案

可以显式维护一个“到达时间栈”：按位置升序入栈，再从靠近终点一侧比较并弹出会合并的后车，语义更贴近单调栈，但实现更长。逐时间模拟会产生难以控制的事件数量，不适合 n = 10⁵。也可将时间保存为分数并交叉相乘以完全避免浮点数。

四语言完整代码

import java.util.Arrays;

class Solution {
    public int carFleet(int target, int[] position, int[] speed) {
        int n = position.length;
        Integer[] order = new Integer[n];
        for (int i = 0; i < n; i++) order[i] = i;

        Arrays.sort(order, (a, b) -> Integer.compare(position[b], position[a]));

        int fleets = 0;
        double lastTime = -1.0;
        for (int index : order) {
            double time = (double) (target - position[index]) / speed[index];
            if (time > lastTime) {
                fleets++;
                lastTime = time;
            }
        }
        return fleets;
    }
}

 * @param {number[]} position

var carFleet = function(target, position, speed) {
    const cars = position.map((pos, i) => [pos, speed[i]]);
    cars.sort((a, b) => b[0] - a[0]);

    let fleets = 0;
    let lastTime = -1;
    for (const [pos, velocity] of cars) {
        const time = (target - pos) / velocity;
        if (time > lastTime) {
            fleets++;
            lastTime = time;
        }
    }
    return fleets;
};

#include <algorithm>
#include <utility>
#include <vector>
using namespace std;

class Solution {
public:
    int carFleet(int target, vector<int>& position, vector<int>& speed) {
        vector<pair<int, int>> cars;
        for (int i = 0; i < static_cast<int>(position.size()); ++i) {
            cars.push_back({position[i], speed[i]});
        }
        sort(cars.rbegin(), cars.rend());

        int fleets = 0;
        double lastTime = -1.0;
        for (const auto& [pos, velocity] : cars) {
            double time = static_cast<double>(target - pos) / velocity;
            if (time > lastTime) {
                ++fleets;
                lastTime = time;
            }
        }
        return fleets;
    }
};

面试追问

为什么必须从靠近终点的一侧开始？

因为一辆后车只会受它前面的最近车队约束。反向扫描时，这个车队的最终到达时间已经确定，决策无需回退。

如何避免浮点数？

将时间记作分数 distance / speed，比较 d1 × s2 与 d2 × s1；注意使用足够宽的整数类型。

若允许超车会怎样？

“追上即合并”的单调结构失效；若车辆保持原速度，最终每辆车可独立抵达，问题模型已经改变。

能否做到 O(n)？

如果输入已按位置排序，可以直接线性扫描；一般输入仍需要排序，因此比较模型下总复杂度为 O(n log n)。

常见错误

  • 按位置升序扫描，却只保存一个到达时间，导致前后关系反了。
  • 合并条件写成严格小于，漏掉恰好在终点追上的情况。
  • 按速度而非位置排序；能否追上还取决于剩余距离。
  • 把相遇后的车队速度继续数值模拟，增加复杂度并引入精度问题。
