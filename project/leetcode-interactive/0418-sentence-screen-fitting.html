01

Problem

题意与规则

给定字符串数组 sentence，它按顺序组成一句话；再给定屏幕尺寸 rows × cols。从屏幕左上角开始，按原顺序反复书写句子。

  • 一个单词必须完整处于同一行，不能跨行拆分。
  • 同一行的相邻单词之间至少保留一个空格。
  • 某个单词放不进当前行剩余位置时，从下一行行首继续。
  • 返回整句话完整出现的次数；不完整的最后一轮不计数。
官方函数形式：wordsTyping(sentence: string[], rows: integer, cols: integer) → integer

约束

  • 1 ≤ sentence.length ≤ 100
  • 1 ≤ sentence[i].length ≤ 10
  • sentence[i] 仅由小写英文字母组成
  • 1 ≤ rows, cols ≤ 2 × 10⁴

04

Solution

循环字符串指针法

核心洞察

把整句话拼成 S = "word1 word2 ... wordN "，特意在末尾保留一个空格。想象 S 无限循环，start 表示屏幕下一行开始前，在这条无限字符带上已经消费到的位置。

每一行先大胆前进 cols 个字符：若恰好落在空格上，就再越过这个空格；否则说明切进了单词内部，向左退到该单词之前的空格。这样既用满了能用的列，又绝不拆词。

为什么答案是 start / |S|？
每完整走过一段 S，就完整写下一遍句子；整数除法直接得到完整轮数。

一行的三步

  1. 先前进：start += cols
  2. 检查边界：落在空格上则 start++
  3. 修复截断：否则退到最近的单词边界

完整过程

  1. 用单个空格连接全部单词，并追加一个尾随空格，得到循环单元 S。
  2. 令全局位置 start = 0。
  3. 对每一行执行：先令 start += cols。
  4. 若 S[start mod |S|] 是空格，说明当前列范围正好容纳若干完整单词，再移动一格跳过分隔符。
  5. 否则，只要 S[(start - 1) mod |S|] 不是空格，就持续回退；最终 start 停在下一个完整单词的开头。
  6. 所有行结束后，返回 ⌊start / |S|⌋。

正确性证明

引理：处理完任意一行后，start 指向无限循环句子中下一个尚未书写的完整单词开头。

证明：前进 cols 后，若当前位置是空格，本行以完整单词结束，越过空格即到下一单词。否则候选位置位于某个单词之中或其末尾，向左退到最近的前置空格之后，正好丢弃放不下的整个单词。因此引理成立。

归纳：初始 start = 0 指向首词。由引理，每处理一行仍保持该不变量，所以算法逐行得到合法且能容纳最多前缀单词的排布。

结论：最终 start 是合法排布消费的字符总数。每跨过 |S| 个字符恰好完成一句，故整数商就是完整句子数。

复杂度

时间

O(R · W + L)

W 为最长单词长度，L 为拼接字符串长度。

空间

O(L)

用于保存拼接后的循环字符串。

因为每行的回退最多跨过一个单词，且题目中单词长度有上限，不需要逐格模拟整个屏幕。

Implementations

四语言完整代码

class Solution {
    public int wordsTyping(String[] sentence, int rows, int cols) {
        String s = String.join(" ", sentence) + " ";
        int length = s.length();
        long start = 0;

        for (int row = 0; row < rows; row++) {
            start += cols;

            if (s.charAt((int) (start % length)) == ' ') {
                start++;
            } else {
                while (start > 0
                        && s.charAt((int) ((start - 1) % length)) != ' ') {
                    start--;
                }
            }
        }

        return (int) (start / length);
    }
}

边界情况

  • 某个单词比列数还长：它在任何一行都放不下，指针会退回原位置，答案为 0。
  • 恰好放到单词末尾：候选位置落在空格上，需要再前进一步跳过分隔符。
  • 只有一个单词：尾随空格仍让循环边界处理保持统一。
  • 大量行列：使用全局字符位置；Java/C++ 采用 64 位整数，避免累计位置溢出。

常见错误

  • 把单词拆到两行，违反不可拆词条件。
  • 每行末尾无条件加空格，产生偏一错误。
  • 按 rows × cols 逐字符建屏幕，浪费时间和内存。
  • 忘记句子末尾的空格，导致一轮结束与下一轮开始需要额外分支。
  • 回退时检查 S[start] 而不是 S[start - 1]，停错单词边界。

替代方案与面试追问

替代方案

  • 逐词模拟：维护单词下标与当前列，逻辑直观，但一行可能放入很多短词，重复工作较多。
  • 预计算转移：为每个“行首单词下标”预先算出本行能完成几轮、下一行从哪个词开始；随后每行 O(1) 转移，适合扩展到更复杂统计。
  • 检测状态环：行首单词下标重复时出现周期，可一次跳过多轮；当 rows 远超本题范围时更有价值。

面试追问

  1. 如果每个空格的宽度不同，现有指针法还能直接使用吗？
  2. 如何用行首状态的周期，把复杂度降到与 rows 几乎无关？
  3. 如果允许连字符断词，状态需要增加哪些信息？
  4. 若需要返回每一行的实际内容，如何避免额外的整屏内存？
