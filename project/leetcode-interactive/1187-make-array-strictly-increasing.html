01 / Problem

挑战是什么？

下面是官方题意的准确转述。先关注“严格递增”和“替换来源不消耗”这两个条件。

题意

给定两个整数数组 arr1 和 arr2。一次操作可以选择任意合法下标 i、j，执行 arr1[i] = arr2[j]。同一个 arr2 元素可以被重复选用，因为操作并不会消耗它。

请返回使 arr1 变为严格递增数组所需的最少操作数；若无论如何都无法做到，返回 -1。

严格递增意味着对每个 i > 0，都必须满足 arr1[i] > arr1[i - 1]，相等也不允许。

函数签名与约束

makeArrayIncreasing(arr1, arr2) → integer
  • 1 ≤ arr1.length, arr2.length ≤ 2000
  • 0 ≤ arr1[i], arr2[i] ≤ 10⁹

主题：数组 · 二分查找 · 动态规划 · 排序 · 最长上升子序列

EXAMPLE 01 
输入：arr1 = [1,5,3,6,7]
      arr2 = [1,3,2,4]
输出：1

将 5 替换为 2，得到 [1,2,3,6,7]。

EXAMPLE 02 
输入：arr1 = [1,5,3,6,7]
      arr2 = [4,3,1]
输出：2

依次替换为 3、4，得到 [1,3,4,6,7]。

EXAMPLE 03 
输入：arr1 = [1,5,3,6,7]
      arr2 = [1,6,3,3]
输出：-1

可选替换值不足以构成一条完整的严格递增序列。

Core Insight

核心洞察：末值越小，未来越自由

从左到右处理 arr1。对于已经合法递增的前缀，未来真正关心的是“最后一个值”和“替换次数”。同样的末值只需保留最少操作数；如果状态 A 的末值更小、操作数还不更多，那么 A 对所有未来选择都不劣于状态 B，B 可以直接剪掉。

state = (lastValue, operations)

在每个位置 x = arr1[i]，从每个有效状态出发只有两类转移：

  1. 保留：若 x > lastValue，新状态为 (x, operations)。
  2. 替换：在排序去重后的 arr2 中二分查找第一个严格大于 lastValue 的值 y，新状态为 (y, operations + 1)。
为什么替换时只试“第一个更大值”？因为对同一个旧状态而言，更大的替换值操作数相同，却只会压缩后续空间，因此不会更优。

Process

完整过程

  1. 对 arr2 排序并去重，便于用 upper bound 找到最小可行替换值。
  2. 用哨兵状态 (-∞, 0) 初始化前沿，表示尚未选择任何元素。
  3. 依次扫描 arr1。对当前前沿中的每个状态，分别尝试合法的“保留”和“替换”。相同末值只留下更小操作数。
  4. 按末值从小到大扫描新状态。若某状态的操作数不小于此前见过的最小操作数，它已被更小末值支配，删除。
  5. 若某一轮没有任何状态，立即返回 -1；否则处理完全部位置后，返回前沿中的最小操作数。

示例 1 的前沿变化

(-∞,0) → (1,0) → {(2,1),(5,0)} → (3,1) → {(4,2),(6,1)} → (7,1)

Correctness

正确性证明

引理 1：转移覆盖所有必要选择

任一合法答案在位置 i 要么保留 arr1[i]，要么用 arr2 中某值替换。保留转移显式枚举前者。对后者，设答案选了 z > last；算法选择最小的 y > last，因此 y ≤ z，操作数相同且不减少后续可行选择。所以只保留 y 仍覆盖一条不劣路径。

引理 2：支配剪枝安全

若状态 A 满足 lastA ≤ lastB 且 costA ≤ costB，那么任何能接在 B 后面的值也能接在 A 后面。沿用 B 的所有后续操作到 A，可得到不更多操作的合法序列，因此 B 不可能产生更优答案。

定理

对位置数归纳。初始状态准确表示空前缀。假设当前前沿包含此前所有非支配的最优前缀状态，引理 1 保证下一轮不会漏掉最优选择，引理 2 保证剪枝不删除产生全局最优解所必需的状态。因此最终前沿中的最小操作数就是答案；前沿为空时不存在合法构造。

Bounds

复杂度与边界

设 n = arr1.length、m = unique(arr2).length、每轮剪枝前后的最大状态数为 S（不超过可出现的不同末值总数 n + m）。二分替换与状态排序带来最坏 O(n · S · (log m + log S)) 时间，空间为 O(m + S)。在本题 n,m ≤ 2000 的范围内可行。

  • 单元素 arr1：本来就严格递增，答案为 0。
  • 重复值：严格递增不允许相等；arr2 必须先去重，但其元素可重复使用。
  • 无需替换：保留路径会一直以 0 次操作存在。
  • 无解：某轮保留和替换都不可行，前沿变空，返回 -1。
  • 哨兵：题目值非负，使用 -1 或负无穷都安全；通用实现可用真正的负无穷。

import java.util.*;

class Solution {
    public int makeArrayIncreasing(int[] arr1, int[] arr2) {
        Arrays.sort(arr2);
        List<Integer> sorted = new ArrayList<>();
        for (int value : arr2) {
            if (sorted.isEmpty() || sorted.get(sorted.size() - 1) != value) {
                sorted.add(value);
            }
        }

        Map<Integer, Integer> states = new HashMap<>();
        states.put(-1, 0);

        for (int current : arr1) {
            TreeMap<Integer, Integer> next = new TreeMap<>();

            for (Map.Entry<Integer, Integer> entry : states.entrySet()) {
                int last = entry.getKey();
                int cost = entry.getValue();

                if (current > last) {
                    next.merge(current, cost, Math::min);
                }

                int index = upperBound(sorted, last);
                if (index < sorted.size()) {
                    int replacement = sorted.get(index);
                    next.merge(replacement, cost + 1, Math::min);
                }
            }

            Map<Integer, Integer> pruned = new HashMap<>();
            int bestCost = Integer.MAX_VALUE;
            for (Map.Entry<Integer, Integer> entry : next.entrySet()) {
                if (entry.getValue() < bestCost) {
                    pruned.put(entry.getKey(), entry.getValue());
                    bestCost = entry.getValue();
                }
            }
            states = pruned;
            if (states.isEmpty()) return -1;
        }

        return Collections.min(states.values());
    }

    private int upperBound(List<Integer> values, int target) {
        int left = 0, right = values.size();
        while (left < right) {
            int middle = left + (right - left) / 2;
            if (values.get(middle) <= target) left = middle + 1;
            else right = middle;
        }
        return left;
    }
}

var makeArrayIncreasing = function(arr1, arr2) {
    const sorted = [...new Set(arr2)].sort((a, b) => a - b);

    const upperBound = (target) => {
        let left = 0;
        let right = sorted.length;
        while (left < right) {
            const middle = left + Math.floor((right - left) / 2);
            if (sorted[middle] <= target) left = middle + 1;
            else right = middle;
        }
        return left;
    };

    let states = new Map([[-Infinity, 0]]);

    for (const current of arr1) {
        const next = new Map();
        const relax = (last, cost) => {
            const oldCost = next.get(last);
            if (oldCost === undefined || cost < oldCost) next.set(last, cost);
        };

        for (const [last, cost] of states) {
            if (current > last) relax(current, cost);

            const index = upperBound(last);
            if (index < sorted.length) relax(sorted[index], cost + 1);
        }

        const ordered = [...next.entries()].sort((a, b) => a[0] - b[0]);
        const pruned = new Map();
        let bestCost = Infinity;
        for (const [last, cost] of ordered) {
            if (cost < bestCost) {
                pruned.set(last, cost);
                bestCost = cost;
            }
        }
        states = pruned;
        if (states.size === 0) return -1;
    }

    return Math.min(...states.values());
};
from bisect import bisect_right
from math import inf
from typing import List


class Solution:
    def makeArrayIncreasing(self, arr1: List[int], arr2: List[int]) -> int:
        sorted_values = sorted(set(arr2))
        states = {-1: 0}

        for current in arr1:
            next_states = {}

            def relax(last: int, cost: int) -> None:
                next_states[last] = min(next_states.get(last, inf), cost)

            for last, cost in states.items():
                if current > last:
                    relax(current, cost)

                index = bisect_right(sorted_values, last)
                if index < len(sorted_values):
                    relax(sorted_values[index], cost + 1)

            pruned = {}
            best_cost = inf
            for last, cost in sorted(next_states.items()):
                if cost < best_cost:
                    pruned[last] = cost
                    best_cost = cost

            states = pruned
            if not states:
                return -1

        return min(states.values())

            if (states.empty()) return -1;

            answer = min(answer, cost);
        }
        return answer;

Alternatives

替代方案

方案 A：按替换次数定义 DP。在 arr1 两端加入哨兵，枚举相邻两个保留元素之间需要替换的区间，再用排序后的 arr2 判断是否能塞入足够多的递增值。它可做到更紧的复杂度分析，但下标和边界更绕。

方案 B：记忆化搜索。状态写成 dfs(i, last)，同样尝试保留或用 upper bound 替换。直观但状态键较多，递归与哈希开销更高；还需要认真处理大数哨兵。

为什么不能贪心地“冲突时才替换”？当前元素即便大于前一个，也可能太大而阻塞未来。示例前缀 [1,5] 同时保留 last=5,cost=0 和替换后的 last=2,cost=1，正说明必须保留多种权衡。

Interview Follow-ups

面试追问

为什么 arr2 可以去重？

相同数值的替换效果完全一致，而且 arr2 元素不会被消耗；保留多个副本不会产生新状态。

支配关系的方向是什么？

末值更小且操作数不更多的状态支配末值更大的状态。只比较操作数或只比较末值都不够。

若 arr2 元素只能使用一次呢？

当前状态不再足够，因为还要记录已使用集合或计数；问题会显著变难，去重也未必安全。

如何还原具体替换方案？

在每个新状态旁保存父状态、当前位置与动作，剪枝时同步保留最优来源，最后从最小成本状态回溯。

Pitfalls

常见错误

  • 用 lower_bound(last) 找到“大于等于”末值的数；本题必须严格大于，应使用 upper bound。
  • 只在当前元素不能保留时才尝试替换，漏掉“提前降低末值”为未来让路的最优路径。
  • 把 arr2 当成消耗品，错误地禁止重复使用同一个值。
  • 合并相同末值时没有取最小操作数，或支配剪枝时不按末值升序扫描。
  • 修改传入的 arr2 后仍假设它保持原顺序；若调用方依赖原数组，应先复制再排序。
  • 把“严格递增”写成大于等于，导致重复值被误判为合法。
