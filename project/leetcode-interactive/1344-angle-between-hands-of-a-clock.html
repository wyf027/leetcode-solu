Problem

题目说明

输入整数 hour 和 minutes，它们描述十二小时制钟面上的一个时刻。请计算时针与分针形成的两种夹角中较小的那个，并以度数返回。

精度要求：答案与标准值的误差不超过 10−5 即可。

约束

  • 1 ≤ hour ≤ 12
  • 0 ≤ minutes ≤ 59

核心洞察

关键不在分针，而在容易被忽略的时针连续移动：分钟增加时，时针也会在当前小时刻度与下一小时刻度之间前进。把两根指针都换算为“从 12 点方向顺时针转过的角度”，问题就变成两个数的距离。

hourAngle = (hour % 12) × 30 + minutes × 0.5
minuteAngle = minutes × 6

完整过程

  1. 用 hour % 12 将 12 点映射到圆周起点。
  2. 每小时跨过 30°，每分钟让时针继续前进 0.5°。
  3. 分针每分钟跨过 6°。
  4. 取两个绝对角度之差 diff。
  5. 圆上另一个夹角是 360 - diff，返回二者较小值。

正确性证明

  1. 位置准确：钟面一周 360°。12 个小时刻度等分一周，所以时针每小时移动 30°；60 个分钟刻度等分一周，所以分针每分钟移动 6°。时针又在 60 分钟内连续走完 30°，即每分钟 0.5°，故两个角度公式准确。
  2. 两条弧覆盖完全：两指针端点把圆周分成角度为 diff 与 360 - diff 的两段，它们之和为 360°。
  3. 返回值正确：题目要求较小夹角，因此取上述两值的最小值，恰好得到目标答案。

边界情况

  • 12:00：hour % 12 保证时针角度为 0°，结果为 0°。
  • 整点：分钟贡献为 0，但仍需比较顺、逆时针两条弧。
  • 非整数答案：如 3:15 的时针已越过 3，结果为 7.5°，必须使用浮点数。
  • 大于 180° 的直接差：应改取补角，例如直接差 205° 时答案为 155°。

复杂度

时间复杂度：O(1)，只执行固定次数的算术运算。
空间复杂度：O(1)，只使用常数个变量。

四语言完整代码

class Solution {
    public double angleClock(int hour, int minutes) {
        double hourAngle = (hour % 12) * 30.0 + minutes * 0.5;
        double minuteAngle = minutes * 6.0;
        double diff = Math.abs(hourAngle - minuteAngle);
        return Math.min(diff, 360.0 - diff);
    }
}

替代方案

也可以用“分钟刻度”统一建模：时针位置为 (hour % 12) × 5 + minutes / 12 个分钟刻度，分针位置为 minutes 个刻度；先求刻度差，再乘 6°。本质相同，但直接用角度通常更直观。

面试追问

  • 如果输入包含秒，两个角度公式分别怎样变化？
  • 怎样返回顺时针方向从时针到分针的有向角，而不是较小夹角？
  • 一天内两根指针重合多少次？如何推导相邻重合时刻？
  • 若输入可能超出合法范围，你会选择校验、归一化还是抛出异常？

常见错误

  • 把时针固定在整数小时刻度，漏掉 minutes × 0.5。
  • 没有将 12 点映射为 0°，导致 12:00 算错。
  • 只返回绝对差，没有与 360 - diff 比较。
  • 使用整数运算截断 0.5°，使 3:15 等用例失败。
  • 混淆 60 分钟制与角度单位；输出始终是度数。
