两个回文子字符串
长度的最大乘积

Maximum Product of the Length of Two Palindromic Substrings

在一条字符串上，挑出两段互不重叠的奇数长度回文。你能让它们的长度乘积有多大？

字符串奇数长度连续区间

01 / 题目

给定从下标 0 开始的字符串 s，选择两段连续子串 s[i…j] 和 s[k…l]，两端均包含，满足 0 ≤ i ≤ j < k ≤ l < s.length。两段必须正读、倒读相同，且长度都是奇数。返回 (j − i + 1) × (l − k + 1) 的最大值。

两段可以相邻，也可以留有间隔，但不能共享字符。单个字符也是合法回文。子串必须连续，不能跳过字符组成子序列。

参数与约束

  • 参数：s: string；返回：最大长度乘积，官方返回类型为 long。
  • 2 ≤ s.length ≤ 10⁵。
  • s 仅包含小写英文字母。

官方示例 1

输入：s = "ababbb"
输出：9

选择 s[0…2] = "aba" 和 s[3…5] = "bbb"，乘积为 3 × 3 = 9。

官方示例 2

输入：s = "zaaaxbbby"
输出：9

选择 s[1…3] = "aaa" 和 s[5…7] = "bbb"，乘积为 9，中间字符可以不选。

先独立思考：怎样确保两段不重叠？更长的回文是否总是更适合参与答案？

03 / 独立题解

准备好后，展开完整推导、分割线实验与四语言代码。

核心洞察：用分割线拆开两个选择

任意合法答案之间都存在一条分割线。令 L[t] 为前缀 s[0…t] 内最长奇回文长度，R[t+1] 为后缀 s[t+1…n−1] 内最长奇回文长度。答案是所有 L[t] × R[t+1] 的最大值。

使用奇回文 Manacher 半径，把每个中心的最大回文向内部收缩，最后累积前缀与后缀最大值，即可在线性时间内求出 L、R。

完整过程

  1. 求奇回文半径。d[c] 包含中心自身，半径 1 代表单字符。最大区间是 [c−d[c]+1, c+d[c]−1]，长度 2d[c]−1。维护最右回文窗口 [l,r]，窗口内从镜像复用 min(d[l+r−c], r−c+1)，窗口外从 1 开始，然后比较两侧字符继续扩展。
  2. 登记端点。left、right 均初始化为 1。每个最大回文的长度分别登记在右端点的 left 和左端点的 right，同端点取最大值。此时数组还不是 L、R。
  3. 收缩补齐。回文去掉一对首尾字符后仍是回文，长度减 2。因此从右往左做 left[t] = max(left[t], left[t+1]−2)，从左往右做 right[t] = max(right[t], right[t−1]−2)。得到恰好在各下标结束／开始的最长奇回文。
  4. 累积区域最优。left 从左往右取前缀最大值成为 L；right 从右往左取后缀最大值成为 R。必须先做收缩，再做累积，不可混淆端点语义与区域语义。
  5. 枚举分割线。对 t = 0…n−2 计算 L[t] × R[t+1]，记录最大值。

"aaaaaa" 中某些中心的最大回文长 5，但最优组合是 3 与 3。只登记最长回文而省略内部收缩，会漏掉关键候选。

正确性论证

  1. 半径准确。Manacher 在已知窗口内利用对称性复用半径，超出已知边界的部分逐字符确认，因此 d[c] 恰好代表该中心的最大奇回文。
  2. 端点完整。任意奇回文都可以由其中心的最大奇回文反复去掉首尾字符得到。指定扫描方向让新产生的候选继续传播，因此覆盖所有候选。同端点保留最大长度是安全的：较大回文每次收缩后的长度仍不小于较小候选的收缩长度。传播产生的每项也都是合法回文。
  3. 区域最优准确。前缀最大值覆盖所有不晚于 t 结束的候选，所以 L[t] 是前缀内最长奇回文；后缀 R 同理。
  4. 分割线充要。每个乘积来自分处两侧的不相交区间，必然合法。任意最优答案之间都有一条分割线，其左右长度分别不大于 L[t] 与 R[t+1]。枚举值既合法又不小于最优值，因此恰好等于最优答案。

边界与复杂度

Manacher 的右边界只向右推进，所有扩展的总工作量为 O(n)，后续为固定次数线性扫描。总时间 O(n)，额外空间 O(n)。演示重绘格子的开销不计入提交算法复杂度。

  • n = 2 时答案为 1；不存在多字符奇回文时也为 1。
  • 单字符合法，空串不合法，所以端点数组初始化为 1。
  • 左右最优区间可以远离分割线，也可紧邻；偶回文不能计入。
  • 乘积上界为 n²/4。全 a 且 n = 100000 时可选 49999 和 50001，乘积 2499999999，超过有符号 32 位整数。
  • Java 乘法前转 long，C++ 使用 1LL；JavaScript Number 在本题范围内精确，Python int 无此溢出问题。

替代方案

  • 中心扩展：逐中心枚举奇回文，再做前后缀最大值；最坏 O(n²)，全相同字符时不适合 10⁵。
  • 滚动哈希 + 半径二分：每个中心二分半径，再用相同的端点处理，约 O(n log n)；哈希可能碰撞，双哈希只能降低误判风险。
  • 回文树：逐字符维护回文后缀与前缀最优，反向再处理后缀，可做到线性，但实现更复杂。

常见错误

  • 误把子串当子序列，或把偶数回文计入。
  • 把半径 d 当作长度，忘记长度公式 2d−1。
  • 省略收缩传播、写反扫描方向，或先做区域累积再收缩。
  • 计算 L[t] × R[t]，使两段可能共享下标 t。
  • 先做 int 乘法再转 long，转换发生时溢出已经出现。

面试追问

  • 需要返回两段区间？在每个长度旁保存左右端点，收缩时两端内移，累积时复制最佳区间，更新答案时保存见证。演示采用了这种方式。
  • 允许偶数长度？额外计算偶回文半径，奇偶候选分别传播后合并，再求区域最大值。
  • 为什么不能先贪心选最长回文？它可能占据关键位置，阻挡两个较短但乘积更大的回文。
  • 改成三段？一条分割线不足，需要额外区间组合或动态规划，不能直接套用左右最大值公式。
