最小窗口子序列 Minimum Window Subsequence

在一条长字符串轨道上，保留顺序、允许跳跃，圈出能容纳目标序列的最短连续区间。 如果最短答案不止一个，取起点最靠左的那个。

DifficultyHARD
AccessPaid only

01 · Problem

题目要求

窗口必须连续，但目标字符只需按先后顺序出现，不要求彼此相邻。

给定两个字符串 s1 和 s2，请从 s1 中找出最短的连续子串 W，使 s2 是 W 的子序列。

若存在多个长度相同的最短窗口，返回 s1 中起点最靠左的窗口；若不存在满足条件的窗口，返回空字符串 ""。

字符串 动态规划 滑动窗口 子序列

约束与签名

  • 1 ≤ s1.length ≤ 2 × 10⁴
  • 1 ≤ s2.length ≤ 100
  • s1、s2 仅含小写英文字母
  • 函数：minWindow(s1, s2) → string

想清楚“连续窗口”和“非连续子序列”的区别后，再展开完整解法。

双向扫描：先找到，再收紧

对每个可能成为答案的右端点，反向找到它能配出的最靠右左端点；这恰好给出以该右端点结尾的最短可行窗口。

核心洞察

向右：只负责可行

用两个指针按序匹配 s2；一旦全部命中，当前 s1 位置就是本轮最早可行的右端点。

向左：只负责最短

从右端点倒着匹配 s2，直到再次完整命中。最后一次命中的位置就是本轮能取得的最靠右左端点。

完整过程

  1. 令 i 指向本轮在 s1 中的扫描起点，向右按序寻找 s2。
  2. 若走到 s1 末尾仍未完整匹配，之后也不会再产生答案，直接结束。
  3. 记完整匹配位置为 end，随后让 s2 指针从末字符开始，并在 s1 中反向匹配。
  4. 反向匹配完成后得到 start，比较窗口 s1[start..end] 与历史最优。
  5. 只在窗口严格更短时更新答案，因此同长情况下自然保留更早出现的窗口。
  6. 从 start + 1 重新开始，寻找左端点更靠右的下一位候选。

正确性说明

引理 1：本轮右端点最早

向右时每遇到所需字符就立刻推进 s2 指针，没有跳过任何更早的匹配机会，所以首次完整命中的 end 是从本轮起点出发可得到的最早右端点。

引理 2：本轮左端点最靠右

固定 end 后倒序贪心，每个目标字符都选不晚于当前位置的最右出现位置，因此最终 start 是该 end 下最大的可行左端点，窗口也就最短。

引理 3：重启不会漏掉更优解

当前 start 之前开始、却在更晚位置结束的窗口只会更长；从 start + 1 重启，只排除了不可能更优的起点，并继续枚举新的候选窗口。

结论

算法比较了所有可能改进答案的收紧窗口，保留其中长度最小者；相同长度不覆盖旧答案，所以最终结果同时满足最短与最靠左。

边界与复杂度

  • s2 中任意字符无法依次匹配时，返回空字符串。
  • s2 长度为 1 时，答案就是 s1 中该字符第一次出现的位置。
  • 当整个 s1 才能容纳 s2 时，反向收紧仍会得到正确的 0 号起点。
  • 同长候选只保留第一个：更新条件必须是严格小于，而不是小于等于。
时间：O(n × m) 最坏 额外空间：O(1) n = |s1|，m = |s2|

替代方案：动态规划

可令一维状态记录：当 s2 的前 j 个字符在当前位置完成匹配时，对应窗口的起点在哪里。逐个读取 s1 字符并倒序更新 j，遇到完整匹配就计算窗口长度。它同样可达 O(n × m) 时间，通常需要 O(m) 额外空间；状态转移规整，适合需要扩展计数、恢复更多路径或统一处理多个目标前缀的场景。

JavaLeetCode 提交形式
class Solution {
    public String minWindow(String s1, String s2) {
        int n = s1.length();
        int m = s2.length();
        int bestStart = -1;
        int bestLength = Integer.MAX_VALUE;
        int i = 0;

        while (i < n) {
            int j = 0;

            // 向右：寻找本轮最早可行的右端点。
            while (i < n) {
                if (s1.charAt(i) == s2.charAt(j)) {
                    j++;
                    if (j == m) {
                        break;
                    }
                }
                i++;
            }

            if (i == n) {
                break;
            }

            int end = i;
            j = m - 1;

            // 向左：固定 end，寻找最大的可行 start。
            while (j >= 0) {
                if (s1.charAt(i) == s2.charAt(j)) {
                    j--;
                }
                i--;
            }

            int start = i + 1;
            int length = end - start + 1;
            if (length < bestLength) {
                bestLength = length;
                bestStart = start;
            }

            i = start + 1;
        }

        return bestStart == -1
            ? ""
            : s1.substring(bestStart, bestStart + bestLength);
    }
}

var minWindow = function (s1, s2) {
  const n = s1.length;
  const m = s2.length;
  let bestStart = -1;
  let bestLength = Infinity;
  let i = 0;

  while (i < n) {
    let j = 0;

    // 向右：寻找本轮最早可行的右端点。
    while (i < n) {
      if (s1[i] === s2[j]) {
        j += 1;
        if (j === m) break;
      }
      i += 1;
    }

    if (i === n) break;

    const end = i;
    j = m - 1;

    // 向左：固定 end，寻找最大的可行 start。
    while (j >= 0) {
      if (s1[i] === s2[j]) j -= 1;
      i -= 1;
    }

    const start = i + 1;
    const length = end - start + 1;
    if (length < bestLength) {
      bestLength = length;
      bestStart = start;
    }

    i = start + 1;
  }

  return bestStart === -1
    ? ""
    : s1.slice(bestStart, bestStart + bestLength);

C++LeetCode 提交形式
class Solution {
public:
    string minWindow(string s1, string s2) {
        const int n = static_cast<int>(s1.size());
        const int m = static_cast<int>(s2.size());
        int bestStart = -1;
        int bestLength = n + 1;
        int i = 0;

        while (i < n) {
            int j = 0;

            // 向右：寻找本轮最早可行的右端点。
            while (i < n) {
                if (s1[i] == s2[j]) {
                    ++j;
                    if (j == m) {
                        break;
                    }
                }
                ++i;
            }

            if (i == n) {
                break;
            }

            const int end = i;
            j = m - 1;

            // 向左：固定 end，寻找最大的可行 start。
            while (j >= 0) {
                if (s1[i] == s2[j]) {
                    --j;
                }
                --i;
            }

            const int start = i + 1;
            const int length = end - start + 1;
            if (length < bestLength) {
                bestLength = length;
                bestStart = start;
            }

            i = start + 1;
        }

        return bestStart == -1
            ? ""
            : s1.substr(bestStart, bestLength);
    }
};

面试追问

为什么不能用经典频次滑窗？

频次只描述“有哪些字符”，而子序列还要求相对顺序。窗口收缩时必须保留匹配路径，不能只维护计数器。

如何返回所有同长最优窗口？

先维护全局最短长度；遇到更短时清空集合，遇到同长时追加区间，并按起点去重即可。

若要处理很多个 s2？

可为 s1 的每个字符预处理出现位置列表，再用二分跳转寻找各目标字符，减少重复扫描。

动态规划何时更合适？

当题目要求统计方案、恢复多条路径、或同时维护大量目标前缀状态时，DP 的状态表达更容易扩展。

常见错误

  • 把“子序列”误当成“子串”，要求 s2 字符在窗口内连续出现。
  • 向右完整匹配后直接比较窗口，没有反向压缩，导致窗口不是当前右端点下的最短解。
  • 反向循环结束后把 i 直接当作 start，出现一位偏差；正确位置是 i + 1。
  • 使用 length ≤ bestLength 更新，导致同长时错误覆盖为更靠右的窗口。
  • 下一轮仍从 end 后开始，漏掉与当前窗口重叠但更短的候选；应从 start + 1 重启。
