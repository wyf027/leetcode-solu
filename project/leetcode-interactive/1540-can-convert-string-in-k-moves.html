K 次操作
转变字符串

Can Convert String in K Moves — 字母可以绕过 z 回到 a，但每个操作编号只能出现一次。你能把每个位置需要的变化安排进有限的时间表吗？

Problem brief

题目说明

参数：s, t, k

给定两个仅含小写英文字母的字符串 s、t 和非负整数 k。目标是在不超过 k 次操作内把 s 变成 t。

  • 在第 i 次操作（1 ≤ i ≤ k），可以选一个此前从未选过的位置，并把该字符向后循环移动 i 位；也可以什么都不做。
  • 移动会在字母表中循环，例如 z 再移动 1 位变为 a。
  • 每个字符串下标最多被选择一次。若能完成转换返回 true，否则返回 false。
注意：题目限制的是“第几次操作”与“下标是否重复使用”，不是总共移动了多少个字母。

示例 1

输入：s = "input", t = "ouput", k = 9
输出：true
说明：第 6 次移动 i→o，第 7 次移动 n→u。

示例 2

输入：s = "abc", t = "bcd", k = 10
输出：false
说明：三个位置都需要移动 1 位，
但第 1 次操作只能分配给一个下标。

示例 3

输入：s = "aab", t = "bbb", k = 27
输出：true
说明：两个 a→b 分别安排在第 1、27 次操作。
1 ≤ 长度 ≤ 10⁵s.length 与 t.length
0 ≤ k ≤ 10⁹允许一次操作也不执行
a — zs、t 仅含小写英文字母

Complete solution

贪心安排同余操作

O(n) / O(1)

核心洞察

一个字符需要向后移动 d 位时，在第 d、d+26、d+52… 次操作执行，效果完全相同。相同的操作编号不能同时服务两个下标，所以同一种非零移动量必须依次领取这些编号。

第 c 个同类任务使用：move = d + 26 × c（c 从 0 开始）

完整过程

  1. 若 s.length !== t.length，无法逐位转换，直接返回 false。
  2. 对每个位置计算最小循环移动量 d = (t[i] - s[i] + 26) % 26。
  3. d = 0 时字符已相同，不必占用任何操作。
  4. 用计数器记录移动量 d 已出现几次，本次领取最早尚未占用的同余操作编号。
  5. 只要某个领取到的编号大于 k 就返回 false；全部可安排则返回 true。

正确性说明

必要性：需要移动 d（1 到 25）位的位置，只能在与 d 模 26 同余的操作中完成。同一操作不能选择两个位置，因此第 c 个此类位置最早只能使用 d + 26c。

充分性：算法为每类移动量依次选择上述最早操作编号。不同移动量模 26 不同，所以编号不会冲突；同一类通过递增 26 也不会冲突。若所有编号都不超过 k，按这些编号执行即可完成转换。

结论：算法返回 true 当且仅当存在合法操作序列。

时间复杂度O(n)

每个字符只处理一次。

空间复杂度O(1)

只使用固定大小 26 的计数数组。

边界情况

  • 长度不同：立即失败。
  • k = 0：只有 s 与 t 完全相同才成功。
  • 相同字符：移动量为 0，不应登记第 0 次操作。
  • 从 z 到 a：移动量为 1，必须正确处理环绕。
  • 大量相同移动量：最后一次可能达到 d + 26(c-1)。

常见错误

  • 只判断每个最小移动量是否小于等于 k，忽略同余操作编号冲突。
  • 把移动量 0 也放进计数器，错误占用不存在的“第 0 次操作”。
  • 直接计算 t[i]-s[i]，没有加 26 再取模。
  • 把“最多 k 次”误解为所有字符移动量之和不超过 k。

class Solution {
    public boolean canConvertString(String s, String t, int k) {
        if (s.length() != t.length()) return false;

        int[] used = new int[26];
        for (int i = 0; i < s.length(); i++) {
            int shift = (t.charAt(i) - s.charAt(i) + 26) % 26;
            if (shift == 0) continue;

            int move = shift + 26 * used[shift];
            if (move > k) return false;
            used[shift]++;
        }
        return true;
    }
}

    def canConvertString(self, s: str, t: str, k: int) -> bool:
        if len(s) != len(t):
            return False

        used = [0] * 26
        for source, target in zip(s, t):
            shift = (ord(target) - ord(source)) % 26
            if shift == 0:
                continue

            move = shift + 26 * used[shift]
            if move > k:
                return False
            used[shift] += 1

        return True

替代方案与面试追问

能否直接模拟 1 到 k？

理论上可以扫描每次操作寻找匹配位置，但 k 可达 10⁹，无法接受。按字符一次性计算最早操作编号才是线性做法。

为什么不用哈希表？

移动量只有 0 到 25，固定数组更简单、更快；哈希表也能表达同样的计数关系，但没有必要。

如果字母表大小变成 m？

把所有 26 替换为 m，使用大小为 m 的计数器；证明保持不变。

如何输出具体操作计划？

在计算 move 时记录二元组 (move, index)，再按 move 排序或直接放入映射即可。
