    State machine

    每笔交易只保留持仓与空仓的最优现金

    buy[t] 表示第 t 笔交易处于持仓时的最优现金，sell[t] 表示完成至多 t 笔交易且空仓时的最优现金。

    核心洞察与完整过程

    1. 对每个交易编号 t，维护买入后与卖出后的最好现金。
    2. buy[t] = max(buy[t], sell[t-1] - price)：继续持仓，或用前一笔已落袋现金买入。
    3. sell[t] = max(sell[t], buy[t] + price)：继续空仓，或卖出当前持仓。
    4. 每天依次更新所有 t，最终 sell[k] 就是至多 k 笔交易的最大利润。
    5. 当 k >= n / 2 时，交易预算不再构成约束，可直接累加所有正相邻差值。 
    buy[t]  = max(buy[t], sell[t - 1] - price)
sell[t] = max(sell[t], buy[t] + price)

answer = sell[k]

    边界

    • 只有一天时无法完成交易，利润为 0。
    • 价格单调下降时，最优选择是不交易。
    • k 很大时必须走不限次优化，避免无意义的 k 倍状态。
    • 允许少于 k 笔交易，因此 sell 状态初值为 0。

    复杂度

    • 一般情况时间 O(nk)，空间 O(k)。
    • 不限次优化时间 O(n)，额外空间 O(1)。
    • n 最多 1000、k 最多 100，状态压缩足够稳定。

    Java
    import java.util.Arrays;

class Solution {
    public int maxProfit(int k, int[] prices) {
        int n = prices.length;
        if (k >= n / 2) {
            int profit = 0;
            for (int i = 1; i < n; i++) {
                profit += Math.max(0, prices[i] - prices[i - 1]);
            }
            return profit;
        }

        int[] buy = new int[k + 1];
        int[] sell = new int[k + 1];
        Arrays.fill(buy, Integer.MIN_VALUE / 2);

        for (int price : prices) {
            for (int t = 1; t <= k; t++) {
                buy[t] = Math.max(buy[t], sell[t - 1] - price);
                sell[t] = Math.max(sell[t], buy[t] + price);
            }
        }
        return sell[k];
    }
}

    from typing import List


class Solution:
    def maxProfit(self, k: int, prices: List[int]) -> int:
        n = len(prices)
        if k >= n // 2:
            return sum(max(0, prices[i] - prices[i - 1])
                       for i in range(1, n))

        buy = [float("-inf")] * (k + 1)
        sell = [0] * (k + 1)
        for price in prices:
            for t in range(1, k + 1):
                buy[t] = max(buy[t], sell[t - 1] - price)
                sell[t] = max(sell[t], buy[t] + price)
        return sell[k]

    int maxProfit(int k, vector<int>& prices) {

            for (int i = 1; i < n; ++i) {

            }
        }
        return sell[k];
    }
};

    替代方案与取舍

    • 二维 DP 记录每个交易次数和每一天，容易推导，但需要 O(nk) 空间。
    • 枚举最后一次买入日会多一层循环，时间达到 O(kn²)。
    • 贪心只在 k 足够大时成立，一般 k 受限时不能独立使用。

    常见错误

    • 把“至多 k 笔”写成“恰好 k 笔”，导致下降行情出现负利润。
    • 买入使用 sell[t] 而不是 sell[t-1]，混淆交易编号。
    • 忘记 k 很大时的不限次优化，造成多余时间和内存。
    • 允许同时持有多股，违反必须先卖后买的限制。
    • 用局部最低价和最高价贪心处理一般 k，无法正确分配交易预算。
