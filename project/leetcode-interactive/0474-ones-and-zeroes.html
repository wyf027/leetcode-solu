Ones and Zeroes

在两种有限资源之间做选择：每个字符串会消耗若干个 0 与 1，目标是装下尽可能多的字符串。

题目描述

给定一个二进制字符串数组 strs，以及两个整数 m 和 n。请从数组中选出一个子集，使其中所有字符串合计包含的 0 不超过 m 个、1 不超过 n 个，并返回这个子集能包含的最大字符串数量。

这里的子集表示从原数组中挑选若干元素；每个位置至多选择一次。

示例 1

输入strs = ["10","0001","111001","1","0"], m = 5, n = 3

输出4

说明可选 {"10","0001","1","0"}，恰好使用 5 个 0 和 3 个 1。字符串 "111001" 单独就含 4 个 1，超出限制。

示例 2

输入strs = ["10","0","1"], m = 1, n = 1

输出2

说明选择 {"0","1"}，两类资源各使用 1 个，数量最大。

约束

  • 1 <= strs.length <= 600
  • 1 <= strs[i].length <= 100
  • strs[i] 仅由字符 '0' 和 '1' 组成
  • 1 <= m, n <= 100

完整题解

核心洞察：每个字符串都是一个只能选一次的物品，0 的数量和 1 的数量是两种独立容量，物品价值统一为 1。因此这是二维费用的 0-1 背包。

状态与转移

定义 dp[i][j]：在最多使用 i 个 0、j 个 1 的条件下，能够选取的最大字符串数量。初始时没有处理任何字符串，所有状态都是 0。

对于当前字符串，设其中有 zeros 个 0、ones 个 1。若选择它，答案可从容量 (i - zeros, j - ones) 的旧状态加 1 得到：

dp[i][j] = max(dp[i][j], dp[i - zeros][j - ones] + 1)

容量 i 与 j 都必须从大到小枚举。这样当前字符串不会在同一轮被重复使用。

完整过程

  1. 创建大小为 (m + 1) × (n + 1) 的二维数组，全部初始化为 0。
  2. 依次统计每个字符串中的 0 和 1 数量。
  3. 从 m 降序枚举到 zeros，内层从 n 降序枚举到 ones。
  4. 用“不选当前字符串”和“选择当前字符串”两种结果的较大值更新状态。
  5. 所有字符串处理完后，dp[m][n] 即为答案。

正确性证明

不变式：处理完前 k 个字符串后，dp[i][j] 等于从这 k 个字符串中，在 0/1 用量不超过 i/j 时可选的最大数量。

基础：k = 0 时没有字符串可选，所有状态为 0，不变式成立。

归纳：考虑第 k + 1 个字符串。任意最优子集要么不含它，此时值为更新前的 dp[i][j]；要么含它，移除该字符串后，剩余部分最优值为 dp[i-zeros][j-ones]，再加 1。转移取两者最大值，覆盖并选择了所有可能中的最优者。降序枚举保证右侧仍是只处理前 k 个字符串的状态。

结论：归纳到全部字符串后，不变式给出 dp[m][n] 正是题目要求的最大子集长度。

复杂度

时间：O(L × m × n)，其中 L = strs.length；另需线性扫描字符串统计字符，总字符数记为 S，完整写法是 O(S + Lmn)。

空间：O(m × n)。

边界处理

  • 全是 0 或全是 1 的字符串，另一类消耗为 0，循环边界仍然有效。
  • 单个字符串消耗超过容量时，本轮没有可更新状态。
  • 容量下标包含 0，因此数组两维长度分别是 m + 1 与 n + 1。

四种语言实现

class Solution {
    public int findMaxForm(String[] strs, int m, int n) {
        int[][] dp = new int[m + 1][n + 1];

        for (String str : strs) {
            int zeros = 0;
            int ones = 0;
            for (char ch : str.toCharArray()) {
                if (ch == '0') {
                    zeros++;
                } else {
                    ones++;
                }
            }

            for (int i = m; i >= zeros; i--) {
                for (int j = n; j >= ones; j--) {
                    dp[i][j] = Math.max(
                        dp[i][j],
                        dp[i - zeros][j - ones] + 1
                    );
                }
            }
        }
        return dp[m][n];
    }
}

var findMaxForm = function(strs, m, n) {
    const dp = Array.from(
        { length: m + 1 },
        () => Array(n + 1).fill(0)
    );

    for (const str of strs) {
        let zeros = 0;
        for (const ch of str) {
            if (ch === '0') zeros++;
        }
        const ones = str.length - zeros;

        for (let i = m; i >= zeros; i--) {
            for (let j = n; j >= ones; j--) {
                dp[i][j] = Math.max(
                    dp[i][j],
                    dp[i - zeros][j - ones] + 1
                );
            }
        }
    }
    return dp[m][n];
};
from typing import List


class Solution:
    def findMaxForm(self, strs: List[str], m: int, n: int) -> int:
        dp = [[0] * (n + 1) for _ in range(m + 1)]

        for string in strs:
            zeros = string.count("0")
            ones = len(string) - zeros

            for i in range(m, zeros - 1, -1):
                for j in range(n, ones - 1, -1):
                    dp[i][j] = max(
                        dp[i][j],
                        dp[i - zeros][j - ones] + 1,
                    )

        return dp[m][n]
class Solution {
public:
    int findMaxForm(vector<string>& strs, int m, int n) {
        vector<vector<int>> dp(m + 1, vector<int>(n + 1));

        for (const string& str : strs) {
            int zeros = count(str.begin(), str.end(), '0');
            int ones = static_cast<int>(str.size()) - zeros;

            for (int i = m; i >= zeros; --i) {
                for (int j = n; j >= ones; --j) {
                    dp[i][j] = max(
                        dp[i][j],
                        dp[i - zeros][j - ones] + 1
                    );
                }
            }
        }
        return dp[m][n];
    }
};

替代方案

可以使用三维状态 dp[k][i][j]，显式表示只看前 k 个字符串时的答案。它更贴近定义、便于第一次推导，但空间会增至 O(Lmn)。二维写法正是把只依赖上一层的第一个维度压缩掉。

暴力枚举全部子集需要 O(2^L)，在 L ≤ 600 时不可行；按某一种字符数量贪心，也会忽略另一种资源的组合影响，不能保证最优。

常见错误

  • 容量从小到大更新，导致同一字符串被重复选取，错误地变成完全背包。
  • 只统计 0，忘记用字符串长度减去 0 数得到 1 数，或反之。
  • 循环写成严格大于消耗量，漏掉容量恰好用完的状态。
  • 把目标理解为最大字符总数；题目要求最大“字符串数量”。

面试追问

  • 为什么两个容量都必须降序？能否只让其中一个降序？
  • 若每个字符串有不同价值，转移式怎样修改？
  • 若每个字符串可以重复选择，枚举顺序应怎样变化？
  • 若还要返回具体选中的字符串，应该保存哪些决策信息？
  • 资源种类扩展到三种时，时间与空间复杂度如何变化？
