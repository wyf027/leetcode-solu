01 · 问题

什么叫“美好”？

如果一个字符串中每种出现过的英文字母，其大写形式和小写形式都出现，它就是美好字符串。

给定字符串 s，返回它最长的美好连续子字符串；若最长答案不止一个，返回起点最靠前的那个；若不存在则返回空字符串。

只检查子串内部

例如 abABB 是美好的：a/A 与 b/B 都成对出现。abA 则不是，因为缺少 B。

官方示例

示例 1输入：s = "YazaAay"输出："aAa"

a/A 成对出现，且这是最长的美好子串。

示例 2输入：s = "Bb"输出："Bb"

整个字符串已经美好。

示例 3输入：s = "c"输出：""

没有任何非空美好子串。

示例 4输入：s = "dDzeE"输出："dD"

dD 与 eE 同长，按要求返回更早出现的 dD。

约束
  • 1 ≤ s.length ≤ 100
  • s 只包含大写和小写英文字母。

03 · 题解

用“不成对字符”做分治切口

核心洞察

观察当前区间。若字符 c 出现但它的大小写搭档没出现，那么任何包含 c 的子串都不可能美好。因此，可以从该位置切成左右两段，分别求解，再取更长者。

若区间里的所有字符都能找到搭档，整个区间就是答案，无需继续切分。

一句话不变量

递归函数返回其负责区间内的最长美好子串；长度相同时优先返回左边，天然满足“最早出现”。

完整过程

收集当前区间的字符集合。

集合同时承担“某个大小写形式是否出现”的查询。

从左到右寻找第一个不成对字符。

对字符 c，检查 lower(c) 与 upper(c) 是否都在集合中。

在断点两侧递归。

断点字符不属于任何合法答案，答案只能完整落在左段或右段。

合并答案。

左段更长或同长时返回左段，否则返回右段；若找不到断点，直接返回整个区间。

正确性证明

引理：若当前区间中字符 c 的另一种大小写形式不存在，则任何包含 c 的子串都不是美好字符串。因为 c 已出现而其搭档缺失，直接违反定义。

归纳：若没有这种 c，整个区间美好，返回它显然最优。否则算法在 c 处切分。由引理，合法答案不含 c，所以只能位于左区间或右区间。递归假设保证两侧各自返回最优解；比较长度即可得到当前区间的全局最优解。同长取左侧，又保证返回最早出现者。因此算法正确。

边界情况

  • 空区间或单字符区间返回空字符串。
  • 整个字符串已经美好时直接返回自身。
  • 多个答案同长时必须保留左侧答案。
  • 大小写转换只针对题目保证的英文字母。

复杂度

时间O(n²)最坏每层扫描近乎完整区间
空间O(n)递归栈与区间集合

替代方案

暴力枚举：枚举全部 O(n²) 个子串，用两个 26 位掩码检查大小写集合是否相等，总体 O(n²) 时间、O(1) 额外空间；在 n ≤ 100 时也足够直接。

按不同字符数滑窗：可枚举目标字母种数并维护计数，但实现更繁琐；这道题的“坏字符能切断答案”结构让分治更自然。

面试追问

  • 为什么同长时选左边，就能保证全局最早？
  • 能否用位掩码替换字符集合？
  • 如果字符集扩展到 Unicode，大小写映射会出现哪些问题？
  • 分治最坏何时退化，如何改成 O(n²) 的稳定枚举？

常见错误

  • 把子字符串误写成可跳字符的子序列。
  • 只检查某一方向，例如有小写却忘了检查大写。
  • 同长时返回右边，违反“最早出现”。
  • JavaScript 用 locale 大小写转换处理本题，徒增不确定性。
