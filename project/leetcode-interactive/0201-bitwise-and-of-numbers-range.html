Bitwise AND of Numbers Range

把区间内每一个数做按位与。与其逐个计算，不如找出所有数字都不变的那段二进制公共前缀；一旦某一位在区间中翻转过，它在 AND 的结果里必为 0。

⚙ 公共前缀 / 右端清零

题意

给定两个整数 left 与 right，它们代表闭区间 [left, right]。返回区间内所有整数的按位 AND。

官方样例 1left = 5 right = 7

二进制为 101、110、111；公共前缀是 1，剩余位都曾变化，答案为 4。

官方样例 2left = 0 right = 0

期望输出：0

官方样例 3left = 1 right = 2147483647

期望输出：0

约束：0 ≤ left ≤ right ≤ 2³¹ − 1。

公共前缀压缩器

准备就绪：从 5 到 7。

算法对拍

50,000 组随机小区间：公共前缀算法与逐项 AND 独立对拍一致；四种语言实现采用相同的右端清零机制。

题解默认折叠，先动手观察位的变化。

题解：把 right 最右侧的 1 清零

核心洞察

若 left < right，right 的最低位 1 在从 left 到 right 的过程中一定会经历 0/1 两种状态，所以结果该位为 0。执行 right = right & (right - 1) 正好清掉它。不断清零直到 right ≤ left，此时 right 就是共同前缀后面补零的答案。

完整过程（5 到 7）

  1. right=111，清最低位 1 → 110。
  2. 110 仍大于 101，清最低位 1 → 100。
  3. 100 ≤ 101，停止，返回 100 (=4)。

边界

相等区间直接返回本身；left=0 时答案必为 0；大范围通常很快跨过高位边界，因此答案可能为 0。

复杂度与替代方案

时间 O(k)，k 为被清掉的低位 1 数，最多 31；空间 O(1)。替代法是同时右移 left/right，直到相等后再左移回去；概念同为公共前缀，代码也很稳。

面试追问

为何不能循环 AND 所有数？区间长度可接近 2³¹，复杂度不可接受。若改为 OR，答案关注的是是否出现过 1，推导方向不同。

常见错误

把整数当作字符串比较；使用有符号 32 位溢出的移位；在 right 已不大于 left 时仍继续清位；遗漏 left=right。

四语言可提交实现

class Solution {
    public int rangeBitwiseAnd(int left, int right) {
        while (left < right) right &= right - 1;
        return right;
    }
}
