检查数组对是否可以被 k 整除

把偶数长度的数组拆成恰好一半数量的数对，并让每一对的和都能被 k 整除。先理解目标，再进入交互实验。

给定偶数长度数组 arr 与正整数 k，判断能否将所有元素恰好使用一次，组成 n / 2 对，使每对之和均可被 k 整除。

函数接收整数数组和除数，返回一个布尔值。数组允许出现负数与重复数字，不能遗漏或重复使用任何下标对应的元素。

余数计数：把配对问题压缩成桶数量匹配

核心洞察

若整数 x 除以 k 的规范余数为 r，它只能与余数为 (k-r) % k 的数配对。于是无需决定具体下标配对，只需检查互补余数桶的数量是否相等。

(r + complement) % k = 0

完整过程

  1. 建立长度为 k 的计数数组。
  2. 对每个 x 计算 ((x % k) + k) % k，兼容负数。
  3. 余数 0 的元素必须为偶数个。
  4. 对每个 r，要求 count[r] == count[k-r]。
  5. 若 k 为偶数，r = k/2 的桶也必须为偶数个。

正确性证明

必要性：任意合法数对的两个余数之和模 k 为 0，因此余数 r 的每个元素都必须消耗一个互补余数元素；两桶数量必须相等。余数 0 与 k/2（若存在）只能在本桶内部两两配对，所以计数必须为偶数。

充分性：若所有互补桶数量相等，可在每对互补桶之间逐一配对；自互补桶因计数为偶数，可在桶内任意两两配对。所有元素都被使用一次，因此形成合法划分。

边界与复杂度

  • 负数：不同语言的取模可能为负，必须规范化。
  • k = 1：所有数余数为 0；数组长度已保证为偶数。
  • 重复值：计数法天然支持。
  • 时间：O(n + k)。
  • 空间：O(k)。

四语言完整实现

Java官方签名
class Solution {
    public boolean canArrange(int[] arr, int k) {
        int[] count = new int[k];
        for (int x : arr) {
            int remainder = ((x % k) + k) % k;
            count[remainder]++;
        }

        if (count[0] % 2 != 0) return false;
        for (int r = 1; r * 2 < k; r++) {
            if (count[r] != count[k - r]) return false;
        }
        if (k % 2 == 0 && count[k / 2] % 2 != 0) return false;
        return true;
    }
}

from typing import List


class Solution:
    def canArrange(self, arr: List[int], k: int) -> bool:
        count = [0] * k
        for x in arr:
            count[x % k] += 1

        if count[0] % 2 != 0:
            return False
        for remainder in range(1, (k + 1) // 2):
            if count[remainder] != count[k - remainder]:
                return False
        if k % 2 == 0 and count[k // 2] % 2 != 0:
            return False
        return True

替代方案

可以维护哈希表并一边扫描一边尝试消耗互补余数，但匹配顺序和自互补桶更容易写错。排序后双指针也并不直接适配“模互补”关系。固定长度计数数组最直观，且复杂度稳定。

面试追问

  • 如果 k 极大而 n 很小，怎样改用哈希表降低空间？
  • 如何实际构造并返回所有下标对？
  • 若允许删除最少元素，问题如何变化？

常见错误

  • 直接使用可能为负的 x % k 作为数组下标。
  • 忘记余数 0 必须偶数个。
  • k 为偶数时漏掉 k/2 自互补桶。
  • 遍历全部余数时重复比较，继而写出错误的奇偶判断。

实现提示

循环条件 r * 2 < k 只检查真正成对的不同余数桶；余数 0 和偶数 k 下的 k/2 单独处理，代码结构与证明一一对应。
