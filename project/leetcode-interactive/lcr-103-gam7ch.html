LCR 103 · MEDIUM

零钱兑换

给你一个整数数组 coins 和整数 amount，计算凑成总金额所需的最少硬币个数；无法凑成则返回 -1。

开始推演

首屏只呈现问题与输入；题解默认隐藏。

题意

每种硬币可使用任意多次。目标是最少数量，不是所有组合数；同一金额可以由不同路径凑出，只保留其中最优答案。

示例 1

输入：coins = [1,2,5], amount = 11
输出：3
解释：11 = 5 + 5 + 1

示例 2

输入：coins = [2], amount = 3
输出：-1

约束

  • 1 <= coins.length <= 12
  • 1 <= coins[i] <= 2³¹ - 1
  • 0 <= amount <= 10⁴

先想一想

  1. 1金额 0 的最少硬币数是多少？
  2. 2凑金额 x 时，最后放入一枚硬币意味着什么？
  3. 3怎样区分“尚不可达”和“最优值很大”？

提示：把每个金额看作一个子问题，答案可由更小金额的最优答案转移而来。

INTERACTIVE WALKTHROUGH

分步推演：coins = [1, 2, 5]，amount = 11

第 1 / 3 步

001121516211?

初始化：dp[0] = 0，其余为不可达

第 1 步：建立状态

令 dp[x] 表示金额 x 的最少硬币数。金额 0 不需要硬币，是所有转移的起点。

第 2 步：尝试最后一枚硬币

对于每个金额 x，尝试每个不超过 x 的 coin：dp[x] = min(dp[x], dp[x - coin] + 1)。

第 3 步：得到目标答案

金额 11 可从金额 6 加一枚 5 转移而来，因此 dp[11] = 3。

SOLUTION

一维动态规划

洞察

最优方案的最后一枚硬币必然是 coins 中某个值。移除它后，剩余金额必须采用最优方案，否则原方案也不可能最优。

过程与边界

将 dp 初始化为 amount + 1 作为不可达哨兵；dp[0] = 0。若最终 dp[amount] 仍大于 amount，返回 -1。amount 为 0 时直接返回 0。

复杂度

遍历 amount 个状态，每个尝试 coins.length 种硬币：时间 O(amount × n)，空间 O(amount)。

替代与追问

BFS 可将金额看作图节点，首次到达目标即最少步数，但仍需访问状态。追问：若每种硬币数量有限，转移方向和状态含义需要调整。

四语言代码

class Solution {
    public int coinChange(int[] coins, int amount) {
        int[] dp = new int[amount + 1]; Arrays.fill(dp, amount + 1); dp[0] = 0;
        for (int x = 1; x <= amount; x++) for (int coin : coins) if (coin <= x) dp[x] = Math.min(dp[x], dp[x - coin] + 1);
        return dp[amount] > amount ? -1 : dp[amount];
    }
}

常见错误

  • 贪心地优先取最大硬币：对某些币值组合并不总是最优。
  • 把不可达状态初始化为 0，导致错误转移。
  • 忘记在返回前把哨兵转换为 -1。
