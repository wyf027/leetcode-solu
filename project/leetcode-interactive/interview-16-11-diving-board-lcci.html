SHORT → LONG
ENDPOINT + Δ

01 / Brief

先读任务，不偷看公式

有一堆长度为 shorter 的短板和长度为 longer 的长板。你必须正好使用 k 块，返回能拼出的所有不同总长度，并按从小到大排列。

题意拆解

  • 每个位置只能选短板或长板，但木板总数必须恰好为 k。
  • 结果只关心总长度，不关心木板排列顺序。
  • 输出要去重并升序；k = 0 时没有跳水板，返回空数组。

官方约束

  • 0 < shorter <= longer
  • 0 <= k <= 100000

示例 1

输入 shorter = 1, longer = 2, k = 3
期望输出 [3, 4, 5, 6]
含义 长板数量依次为 0、1、2、3

04 / Solution locker

准备好再打开题解

核心洞察

一个方案完全由“用了多少块长板”决定。设长板数为 i，短板数自然是 k - i。因此 i 只需从 0 枚举到 k。

length(i) = (k - i) × shorter + i × longer

相邻结果的差恒为 longer - shorter。因为题目保证 shorter <= longer，枚举顺序天然就是升序。

完整过程

  1. 若 k = 0，直接返回空数组。
  2. 若两种木板等长，只返回唯一值 shorter × k。
  3. 创建长度为 k + 1 的结果数组。
  4. 枚举 i = 0..k，写入对应的总长度。

也可以从 shorter × k 开始，每次直接加固定公差，避免重复乘法。

边界与不变量

  • k = 0：没有木板，不把长度 0 当成一块跳水板。
  • shorter = longer：所有选择产生同一长度，只能返回一个值。
  • 任意步骤都满足 短板数 + 长板数 = k。
  • 当两种木板不同，公差为正，结果严格递增且无需额外去重。

复杂度

时间：O(k)，最多生成 k + 1 个不同答案，已经达到输出规模下界。

额外空间：O(1)；若计入必须返回的结果数组，则为 O(k)。

替代方案

  • Set + 排序：枚举数量后加入集合，再排序；正确但多出哈希与排序成本。
  • 二进制枚举：枚举每块板的类型，复杂度 O(2^k)，忽略了排列不影响总长度。
  • 回溯：同样会产生大量重复长度，不适合 k 可达 100000 的约束。

面试追问

  • 如果不保证 shorter <= longer，如何仍然升序输出？先交换两者。
  • 为什么 O(k) 已经最优？答案本身最多就有 k + 1 项。
  • 若要求流式输出怎么办？维护当前值，每次加公差即可。
  • 若长度可能溢出 32 位怎么办？改用 64 位整数承接乘法。

常见错误

  • 把 k = 0 返回成 [0]，与题意要求的空数组不符。
  • 两种木板等长时仍返回 k + 1 个重复值。
  • 枚举每块木板的排列，误把相同计数组合当成不同长度。
  • 使用 HashSet 后忘记排序，导致输出顺序不满足要求。
  • 公式写成 i × shorter + i × longer，破坏“正好 k 块”的不变量。

class Solution {
    public int[] divingBoard(int shorter, int longer, int k) {
        if (k == 0) {
            return new int[0];
        }
        if (shorter == longer) {
            return new int[] {shorter * k};
        }

        int[] answer = new int[k + 1];
        int current = shorter * k;
        int difference = longer - shorter;
        for (int i = 0; i <= k; i++) {
            answer[i] = current;
            current += difference;
        }
        return answer;
    }
}
