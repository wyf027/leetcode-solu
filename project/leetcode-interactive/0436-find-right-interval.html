寻找右区间

Find Right Interval

给每个区间寻找起点不小于它的终点、且起点尽可能小的那个区间。结果必须保留原输入下标。

中等 数组 二分查找 排序

Problem

题目描述

给定区间数组 intervals，其中 intervals[i] = [startᵢ, endᵢ]，并且所有区间的起点互不相同。

区间 i 的右区间是某个区间 j：它满足 startⱼ ≥ endᵢ，并且在所有满足条件的区间中 startⱼ 最小。i 与 j 可以相同。

返回每个区间对应的右区间下标；若不存在，返回 -1。

示例 1

输入：intervals = [[1,2]]
输出：[-1]
解释：唯一的区间没有右区间。

示例 2

输入：intervals = [[3,4],[2,3],[1,2]]
输出：[-1,0,1]
解释：[3,4] 无右区间；[2,3] 找到下标 0；
[1,2] 找到下标 1。

示例 3

输入：intervals = [[1,4],[2,3],[3,4]]
输出：[-1,2,-1]
解释：只有 [2,3] 能找到起点为 3 的右区间。

约束

  • 1 ≤ intervals.length ≤ 2 × 10⁴
  • intervals[i].length == 2
  • -10⁶ ≤ startᵢ ≤ endᵢ ≤ 10⁶
  • 每个区间的起点互不相同。

Solution · Spoiler Gate

准备好再揭晓题解

先尝试从“终点”和“有序起点”的关系独立推导。

Editorial

排序起点 + 二分下界

核心洞察

对某个区间 [startᵢ, endᵢ]，答案只取决于所有区间的起点。将 (起点, 原下标) 排序后，要找的正是第一个不小于 endᵢ 的起点，也就是有序数组中的下界。保留原下标即可把答案写回原顺序。

为什么不能只排序 intervals？

输出位置与输出值都要求原下标。若原地排序却不携带索引，区间身份会丢失，结果便无法正确还原。

完整过程

  1. 遍历输入，构造 starts = [(startᵢ, i)]。
  2. 按起点从小到大排序 starts。
  3. 对每个原区间，用二分查找找到第一个满足 starts[k].start ≥ endᵢ 的位置。
  4. 若位置仍在数组内，答案为该项携带的原下标；否则答案为 -1。

正确性证明

引理 1：二分结果满足右区间条件

下界位置 k 的定义是第一个起点不小于 endᵢ 的位置，因此若 k 存在，其区间必满足 start ≥ endᵢ。

引理 2：二分结果的起点最小

起点数组已升序排列。下界之前的所有起点都严格小于 endᵢ，不能成为右区间；下界之后的起点均不小于下界起点。因此下界对应的可行起点最小。

定理：算法对每个区间返回正确答案

若下界存在，由引理 1 和引理 2，它正是定义要求的右区间；若下界不存在，说明所有起点都小于目标终点，确实没有右区间，应返回 -1。算法逐一处理所有原区间，所以整个答案数组正确。

时间复杂度

O(n log n)

排序一次，随后进行 n 次二分。

空间复杂度

O(n)

保存起点、原下标和答案。

关键不变量

答案 ∈ [low, high)

二分搜索始终保留可能的下界位置。

边界情况

  • 只有一个区间时，若 start < end 则通常返回 -1；若 start == end，它自身就是答案。
  • 目标终点大于最大起点时，下界位于数组末尾之外，返回 -1。
  • 目标终点不大于最小起点时，下界为排序后第一个元素。
  • 负数坐标不改变比较与排序逻辑。
  • 起点唯一保证答案对应唯一的最小起点；实现仍应返回其原下标。

四语言完整代码

import java.util.Arrays;

class Solution {
    public int[] findRightInterval(int[][] intervals) {
        int n = intervals.length;
        int[][] starts = new int[n][2];
        for (int i = 0; i < n; i++) {
            starts[i][0] = intervals[i][0];
            starts[i][1] = i;
        }
        Arrays.sort(starts, (a, b) -> Integer.compare(a[0], b[0]));

        int[] answer = new int[n];
        for (int i = 0; i < n; i++) {
            int target = intervals[i][1];
            int left = 0, right = n;
            while (left < right) {
                int mid = left + (right - left) / 2;
                if (starts[mid][0] >= target) {
                    right = mid;
                } else {
                    left = mid + 1;
                }
            }
            answer[i] = left < n ? starts[left][1] : -1;
        }
        return answer;
    }
}

class Solution:
    def findRightInterval(self, intervals: List[List[int]]) -> List[int]:
        starts = sorted(
            (interval[0], index)
            for index, interval in enumerate(intervals)
        )
        n = len(starts)
        answer = []

        for _, end in intervals:
            left, right = 0, n
            while left < right:
                mid = left + (right - left) // 2
                if starts[mid][0] >= end:
                    right = mid
                else:
                    left = mid + 1
            answer.append(starts[left][1] if left < n else -1)

        return answer
class Solution {
public:
    vector<int> findRightInterval(vector<vector<int>>& intervals) {
        int n = static_cast<int>(intervals.size());
        vector<pair<int, int>> starts;
        starts.reserve(n);
        for (int i = 0; i < n; ++i) {
            starts.push_back({intervals[i][0], i});
        }
        sort(starts.begin(), starts.end());

        vector<int> answer(n, -1);
        for (int i = 0; i < n; ++i) {
            int target = intervals[i][1];
            int left = 0, right = n;
            while (left < right) {
                int mid = left + (right - left) / 2;
                if (starts[mid].first >= target) {
                    right = mid;
                } else {
                    left = mid + 1;
                }
            }
            if (left < n) {
                answer[i] = starts[left].second;
            }
        }
        return answer;
    }

替代方案

  • 平衡搜索树：先将起点映射到原下标，再对每个终点做 ceiling 查询，同样为 O(n log n)；实现常数与语言依赖更强。
  • 暴力枚举：对每个区间扫描全部起点，时间为 O(n²)，仅适合解释定义，不满足最大数据规模。
  • 双排序 + 双指针：分别排序终点和起点后线性推进，整体仍为 O(n log n)，可减少二分次数，但索引管理更复杂。

常见错误

  • 查找“严格大于终点”的起点，漏掉 start == end。
  • 排序后没有携带原下标，输出的是排序位置。
  • 把右边界设为 n - 1，导致“无答案”的哨兵位置难以统一处理。
  • 找到任意可行起点就停止，没有继续寻找更小的可行起点。
  • 错误地排除区间自身；题目明确允许 i == j。

面试追问

如果起点不唯一？

需要先明确并列时的下标规则；可把排序键扩展为“起点、原下标”，或返回任意最小起点对应项。

如果区间动态加入？

静态数组排序不再合适，可使用支持 ceiling 查询与插入的平衡搜索树。

能否原地降低额外空间？

仍要保存原下标或编码身份；修改输入会增加还原成本。通常清晰的 O(n) 辅助数组更稳妥。
