不违反限制的最大请求数

把每位用户的时间线拆开：总是优先保留更早的请求，它更早“过期”，对未来的约束更小。

题意

给定 requests[i] = [userᵢ, timeᵢ]，以及整数 k、window。若某用户在任意闭区间 [t, t + window] 内的请求数严格大于 k，就违反限制。可丢弃任意请求，求最多能保留多少条。

示例 1

requests = [[1, 1], [2, 1], [1, 7], [2, 8]]
k = 1, window = 4

输出：4。两名用户各自的两个时间点相差都超过 4。

边界提醒

区间是闭区间：时间差恰好等于 window 的两条请求仍会同时计数。比如 window = 5 时，2 和 7 不能被当成过期。

题解区域

默认收起，先在上方亲自观察“保留更早时间”的贪心选择。

核心洞察

不同用户互不影响，先按用户分组。对同一用户排序后，从早到晚扫描。队首时间 < 当前时间 - window 才能移出；等号仍在闭区间内。若活跃保留数已是 k，丢弃当前（最新）请求。早的请求会更早过期，因此不比换成更晚请求差。

复杂度与替代方案

总排序成本为 O(n log n)，队列扫描为 O(n)，额外空间 O(n)。暴力枚举每个区间会重复统计；按时间排序后再用双指针也可实现同一逻辑。

完整过程、常见错误与面试追问

  1. 建立 user → times[] 映射并分别排序。
  2. 每个时间 t 到来前，弹出所有 old < t - window。
  3. 队列长度小于 k 就保留 t；否则丢弃它。

常见错误：写成 old ≤ t - window，会错误地把边界时间当成过期。追问：若请求已按用户、时间有序，可省去各组排序并把总时间降为 O(n)。
