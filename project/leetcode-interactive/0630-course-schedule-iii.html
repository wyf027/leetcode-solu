01 · Problem

题目说明

有 n 门互不相同的在线课程，编号为 1 到 n。数组 courses 中，courses[i] = [durationᵢ, lastDayᵢ]：第 i 门课需要连续学习 durationᵢ 天，并且必须在第 lastDayᵢ 天或之前完成。

学习从第 1 天开始，同一时间不能修读两门或更多课程。请返回最多能完成的课程数。

函数scheduleCourse(courses)
参数courses: integer[][]
返回integer

04 · Solution

贪心排序 + 大根堆

目标不是尽早做完某一门课，而是在每个截止日之前，用尽可能少的总时间保留同样多的课程。

↺

核心洞察：超期时撤掉最耗时的一门

按截止日从小到大处理课程。先暂时加入当前课程；若累计用时超过当前截止日，就从所有已加入课程中删除持续时间最长的一门。这样课程数量最多只减少 1，同时把累计用时压到最小，为后面的课程留下最多空间。

完整过程

  1. 排序：将 courses 按 lastDay 升序排列，让每一步只需满足当前最紧的截止条件。
  2. 暂时接纳：把当前课程时长加入累计时间，并压入大根堆。堆顶始终是已选课程里持续时间最长的一门。
  3. 修复超期：若累计时间大于当前课程的截止日，弹出堆顶课程，并从累计时间中减去它的时长。
  4. 读取答案：扫描结束后，堆中保留的课程都能按截止日顺序完成；堆大小就是最多课程数。

正确性说明

不变式：处理完前 i 门（按截止日排序）后，堆中保存的是可在相应截止日前完成的一组课程；在课程数量相同的候选方案中，它的总耗时不大于把其中最长课程保留下来的方案。

保持：加入当前课程后若不超期，可行性不变且课程数增加 1。若超期，任何想保留同样数量的方案都需要释放时间；删除已选集合中最长课程释放的时间最多，因此得到的总耗时最小。如果被删的是当前课程，就等价于拒绝它；否则就是用更短的当前课程替换过去的长课程。由于当前课程的截止日不早于此前课程，剩余课程按截止日顺序仍然可安排。

最优性：每个前缀中算法都保留了能达到的最大课程数，并在该数量下留下尽可能小的累计时间。归纳到全部课程，任何方案都不可能拥有更多课程，因此堆大小最优。

时间复杂度O(n log n)

排序与每门课一次堆操作。

空间复杂度O(n)

最坏情况下堆保存全部课程。

边界情况

  • 单门课程：只有 duration ≤ lastDay 时可选。
  • 所有课程自身都来不及完成：每次加入后都会被移除，答案为 0。
  • 截止日相同：顺序不影响最终数量；大根堆会优先淘汰较长课程。
  • 课程全部可完成：不会发生淘汰，答案为 n。
  • 相同课程时长：弹出其中任意一门都不影响累计时间和答案。

常见错误

  • 按持续时间排序，会忽略更早截止的课程。
  • 一旦超期就直接拒绝当前课程，错过“用短课替换旧长课”的机会。
  • 使用小根堆，超期时删掉最短课程，释放的时间最少。
  • 只弹出旧课程、不把当前课程先入堆，无法统一处理“当前课程本身最长”的情形。
  • 在 JavaScript 中直接用默认 sort() 排数字，得到字典序。

替代方案

截止时间 DP：按截止日排序后，可以令 dp[k] 表示完成 k 门课所需的最小时间，再逐门转移。它能表达同样的“相同数量时尽量缩短耗时”，但朴素实现通常需要 O(n²) 时间；若按时间维度做背包，则复杂度依赖最大截止日。面对 n = 10⁴，排序加大根堆更直接、高效。

面试追问

为什么必须按截止日排序？

排序后，每处理一门课，当前截止日就是已扫描前缀里最晚的限制。只要总耗时不超过它，再按截止日顺序学习，前缀日程就可行；交换才有统一的合法性基础。

为什么超期时只删除一门就够？

超期发生在刚加入一门课程之后。删除当前课程本身一定能恢复到加入前的可行状态；删除所有课程中最长的一门只会释放更多或相同时间，因此一次足够。

能否返回具体选择了哪些课程？

可以。把堆元素从“时长”扩展为“时长 + 原始下标”，扫描结束后堆内下标就是一个最优课程集合；再按截止日排序即可给出可执行顺序。

如果课程带有不同收益，目标改成最大总收益呢？

当前交换论证不再成立，因为删除最长课程未必保留最高收益。通常需要引入动态规划、时间维度背包或针对新约束设计其他优化。
