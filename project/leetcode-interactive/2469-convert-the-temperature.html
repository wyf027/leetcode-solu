温度转换

Convert the Temperature

一个温度，三种刻度。先理解输入与输出，再展开运算过程。

打开官方题目 ↗

01题目

给定非负浮点数 celsius，表示摄氏温度；输入已经四舍五入到两位小数。请计算对应的开尔文温度与华氏温度，并按固定顺序返回 [kelvin, fahrenheit]。

答案与真实值的误差不超过 10−5 即可接受。输出是两个数值组成的数组，不要求返回带固定小数位数的字符串。

参数：celsius: double　返回：double[]（长度为 2）

约束

0 ≤ celsius ≤ 1000，且输入精确到最多两位小数。

02官方示例

示例 1

输入：celsius = 36.50
输出：[309.65000, 97.70000]

36.50 摄氏度对应 309.65 开尔文与 97.70 华氏度。

示例 2

输入：celsius = 122.11
输出：[395.26000, 251.79800]

122.11 摄氏度对应 395.26 开尔文与 251.798 华氏度。

题目给出的换算关系

Kelvin = Celsius + 273.15
Fahrenheit = Celsius × 1.80 + 32.00

这些公式是题面已知条件。先思考：两个结果之间有依赖吗？返回顺序有要求吗？

04独立题解

包含分步刻度实验、证明与四语言实现。

核心洞察：两条独立的线性换算

开尔文只改变零点；华氏度既改变每度的大小，又改变零点。两个结果都直接从同一个 celsius 计算，无需循环、搜索或先算开尔文再算华氏度。

完整过程

  1. 保留原始摄氏温度 celsius。
  2. 计算 kelvin = celsius + 273.15。
  3. 计算 fahrenheit = celsius * 1.80 + 32.00。乘法先于加法。
  4. 返回 [kelvin, fahrenheit]，无需额外舍入。

以 celsius = 36.50 为例：开尔文为 36.50 + 273.15 = 309.65；华氏度先得到 36.50 × 1.80 = 65.70，再加 32 得到 97.70。

正确性说明

对任意满足约束的输入 C，数组第一个元素按题目规定的开尔文公式计算，故等于 C + 273.15；第二个元素按华氏度公式计算，故等于 C × 1.80 + 32.00。数组恰好包含这两个值且顺序符合要求，因此结果正确。各语言使用双精度数值，在本题范围内的浮点舍入误差远小于允许的 10−5。

边界与精度

  • 0 是有效输入，不是缺失值。
  • 1000 使用相同公式，不需特殊分支。
  • 输入两位小数不表示输出也只能两位；122.11 的华氏度为 251.798。
  • 演示用五位小数便于阅读；提交代码直接返回数值。

复杂度

时间 O(1)：一次乘法和两次加法。空间 O(1)：只返回长度为 2 的数组，不随输入值增大而变化。

替代方案

可用 celsius * 9.0 / 5.0 + 32 表达华氏度公式，数学含义相同。整数百分位或高精度十进制适合有严格十进制舍入规则的系统，本题无需引入。

常见错误

  • 把输出写成 [fahrenheit, kelvin]，颠倒位置。
  • 用开尔文结果计算华氏度，导致偏移重复累加。
  • 把 celsius * 1.80 + 32 写成 (celsius + 32) * 1.80。
  • Java / C++ 中使用整数表达式 9 / 5，得到 1；应使用浮点字面量。
  • 提前保留两位小数，或用 JavaScript toFixed 返回字符串。

面试追问

如何反向换算？ 摄氏度分别为 K − 273.15、(F − 32) / 1.80。

扩展到 n 个输入呢？ 对每个值独立换算，总时间 O(n)；若保存所有结果，输出空间 O(n)。

浮点结果为什么可能有很多尾数？ 有限二进制小数不能精确表示所有十进制小数；本题通过误差容限接纳这种表示误差，不能把格式化当作数值正确性的替代。
