最大相等频率

沿着数组逐步扩展前缀：每到一个位置，都问同一件事——能否恰好拿走一个元素，让仍然出现的所有数字拥有完全相同的频率？

任务

给定正整数数组 nums，返回满足条件的最长前缀长度。删除后若没有元素，也视为所有出现数字的次数相同。

先观察，后揭晓

先在实验室里移动前缀边界，寻找“异常频率”。完整推导与代码默认收起，位于页面底部。

Problem

题目说明

准确转述

选择数组从下标 0 开始的一段前缀，并从其中恰好删除一个元素。删除后，所有仍然存在的不同数字，其出现次数必须相等。求符合要求的最长前缀长度。

函数签名：

maxEqualFreq(nums: integer[]) → integer

约束

2 ≤ nums.length ≤ 10⁵
1 ≤ nums[i] ≤ 10⁵

示例 1

输入：nums = [2,2,1,1,5,3,3,5]
输出：7
解释：长度为 7 的前缀是
[2,2,1,1,5,3,3]。
删除其中的 5 后，1、2、3 均出现 2 次。

示例 2

输入：nums = [1,1,1,2,2,2,3,3,3,4,4,4,5]
输出：13

准备好核对推理了吗？

Solution

双层计数：值频率 × 频率频率

核心洞察：扫描每个前缀时，不必真的尝试删除每个位置。记录“每个值出现几次”和“有多少个值出现了这么多次”，就能用三个结构条件判定。

状态定义

  • count[x]：数字 x 在当前前缀中的出现次数。
  • freq[f]：当前有多少种数字恰好出现 f 次。
  • maxFreq：当前最大的出现次数；len 为当前前缀长度。

仅有的三种可行形状

① 全部频率为 1maxFreq == 1

任意删掉一个元素，其余数字仍各出现一次；长度 1 时删完为空也成立。

② 唯一单例maxFreq · freq[maxFreq] + 1 == len

除一个只出现一次的数字外，其余数字都出现 maxFreq 次；删除单例。

③ 唯一高频项(maxFreq−1) · (freq[maxFreq−1]+1) + 1 == len

恰有一个数字多出现一次；从它身上删除一个，频率便全部降齐。

完整过程

从左到右加入 nums[i]。设它的旧频率为 old，先令 freq[old] 减一（old = 0 时忽略）。
令 count[nums[i]] 加一，再令新频率对应的 freq[new] 加一，并更新 maxFreq。
用上面的三个条件判断长度 i + 1。若任一成立，就把答案更新为该长度。
继续扫描；因为答案只增不减，最终保存的就是最长可行前缀。

正确性证明

充分性：三种形状分别可删除任意元素、唯一单例、或唯一最高频数字的一次出现，删除后各非零频率相同。

必要性：一次删除只会让某一个值的频率减少 1，或让频率为 1 的值消失。因此删除前若可行，所有频率要么全为 1，要么由“共同频率 + 一个单例”构成，要么由“共同频率 + 一个高 1 的值”构成；除此之外，一次删除无法消除两个以上差异。三个条件穷尽所有情况。

算法在每个前缀精确维护两层计数，并只在必要且充分的条件成立时更新答案，所以返回值恰为最长合法前缀长度。

边界与复杂度

  • 只有一种数字：可从任意前缀删除一个，仍然满足定义。
  • 所有数字互不相同：maxFreq = 1，整个前缀合法。
  • 删除唯一元素后为空：按题意合法。
  • 更新频率桶时，不需要删除计数已变为 0 的键；判定式不会受其影响。

时间：O(n)。空间：O(k)，其中 k 是不同数字个数；使用定长数组时为 O(U)。

替代方案

对每个前缀枚举要删除的位置，再重新统计，最直观但最坏达到 O(n³)；复用计数也通常需要 O(n²)。还可以维护有序频率集合，判定最小/最大频率，但删除某个值后仍需验证桶数量，结构更重。双层哈希计数把判定压缩到常数时间，是这里最直接的线性方案。

面试追问

  • 若允许“至多删除一个”，长度 1 和已完全等频的前缀如何判定？
  • 若要求删除恰好 k 个元素，状态与判定怎样推广？
  • 数据流无限长时，如何只报告截至当前的答案？
  • 值域极小的情况下，数组计数与哈希表如何取舍？

常见错误

  • 把“恰好删除一个”误写成“不删除也可以”，遗漏单一数字或全为 1 的情况。
  • 只比较最小、最大频率，却没有确认异常频率只属于一个数字。
  • 更新 count[x] 后忘记从旧频率桶中减一，导致 freq 与真实分布不一致。
  • 公式使用数组下标 i 代替前缀长度 i + 1。

class Solution {
    public int maxEqualFreq(int[] nums) {
        int[] count = new int[100001];
        int[] freq = new int[100002];
        int maxFreq = 0;
        int answer = 0;

        for (int i = 0; i < nums.length; i++) {
            int value = nums[i];
            int oldFreq = count[value];
            if (oldFreq > 0) {
                freq[oldFreq]--;
            }

            int newFreq = ++count[value];
            freq[newFreq]++;
            maxFreq = Math.max(maxFreq, newFreq);
            int len = i + 1;

            boolean allOnce = maxFreq == 1;
            boolean oneSingleton = maxFreq * freq[maxFreq] + 1 == len;
            boolean oneTooFrequent =
                (maxFreq - 1) * (freq[maxFreq - 1] + 1) + 1 == len;

            if (allOnce || oneSingleton || oneTooFrequent) {
                answer = len;
            }
        }
        return answer;
    }
}

var maxEqualFreq = function(nums) {
    const count = new Map();
    const freq = new Map();
    let maxFreq = 0;
    let answer = 0;

    for (let i = 0; i < nums.length; i++) {
        const value = nums[i];
        const oldFreq = count.get(value) || 0;
        if (oldFreq > 0) {
            freq.set(oldFreq, (freq.get(oldFreq) || 0) - 1);
        }

        const newFreq = oldFreq + 1;
        count.set(value, newFreq);
        freq.set(newFreq, (freq.get(newFreq) || 0) + 1);
        maxFreq = Math.max(maxFreq, newFreq);
        const len = i + 1;

        const allOnce = maxFreq === 1;
        const oneSingleton =
            maxFreq * (freq.get(maxFreq) || 0) + 1 === len;
        const oneTooFrequent =
            (maxFreq - 1) * ((freq.get(maxFreq - 1) || 0) + 1) + 1 === len;

        if (allOnce || oneSingleton || oneTooFrequent) {
            answer = len;
        }
    }
    return answer;
};

快速复盘

为什么只看 maxFreq 就够？

因为一次删除只能影响一个值的频率。可行分布至多出现两种非零频率，而较高者必然是 maxFreq；配合对应桶中值的数量即可确认异常项是否唯一。

freq[0] 需要维护吗？

不需要。尚未出现的数字不属于当前前缀的不同数字集合，判定只关心正频率。
