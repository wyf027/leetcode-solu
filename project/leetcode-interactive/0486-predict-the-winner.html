Predict the Winner

预测
赢家

数字排成一列。两位玩家轮流从左端或右端取走一个数字；在双方都采用最优策略时，判断先手能否至少战平。

Rules at a glance

  1. 01
    玩家 1 先手双方初始得分均为 0
  2. 02
    只取数组两端所取数字加入自己的得分
  3. 03
    双方都最优不能假设对手会犯错
终局规则：玩家 1 得分大于或等于玩家 2 时，返回 true。
01 / Problem

题目说明

先理解游戏与胜负判定。题解被放在页面底部并默认收起，不会在首屏直接泄露。

准确转述

给定整数数组 nums。玩家 1 与玩家 2 轮流行动，玩家 1 先手。每回合只能取走当前数组最左端或最右端的数字，并把它加入自己的总分；所有数字取完后游戏结束。

假设两位玩家始终采用能使自己结果最优的策略。如果玩家 1 最终得分不少于玩家 2（平局也算玩家 1 获胜），返回 true，否则返回 false。

predictTheWinner(nums: integer[]) -> boolean

约束

  • 1 <= nums.length <= 20
  • 0 <= nums[i] <= 107

主题：递归、极小化极大、数组、数学、动态规划、博弈、零和博弈。

Example 01
输入nums = [1,5,2]
输出false

玩家 1 无论先取 1 还是 2，玩家 2 都能取到 5；最终玩家 1 得 3 分，玩家 2 得 5 分，因此玩家 1 无法获胜。

Example 02
输入nums = [1,5,233,7]
输出true

玩家 1 先取 1。之后玩家 2 只能在 5 与 7 中选择，无论取哪一个，玩家 1 都能拿到 233；最终为 234 比 12。

03 / Solution

题解：把总分变成分差

不同时维护两人的总分，直接问“当前行动方最多能比对手多多少分”。

Δ

核心洞察

拿走一个端点后，角色立即交换。当前选择的数字，减去对手在剩余区间能取得的最大分差，就是本选择带来的净优势。

状态与转移

定义 dp[i][j]：面对闭区间 nums[i..j] 时，当前行动方相对另一方最多能领先的分数。

只有一个数字时，当前玩家直接取走它：

dp[i][i] = nums[i]

有多个数字时，可取左端或右端：

dp[i][j] = max(nums[i] - dp[i+1][j], nums[j] - dp[i][j-1])

最终 dp[0][n-1] >= 0，就表示玩家 1 至少能战平。

完整过程

  1. 把一维数组 dp 初始化为 nums，此时每格对应长度为 1 的区间。
  2. 让左端点 i 从 n-2 递减到 0，确保下一行代表的更短区间已计算。
  3. 让右端点 j 从 i+1 递增到 n-1。
  4. 用旧的 dp[j] 表示 dp[i+1][j]，用刚更新的 dp[j-1] 表示 dp[i][j-1]。
  5. 返回 dp[n-1] >= 0。

正确性证明

  • 基础情形：当 i = j，当前玩家只能拿走 nums[i]，净领先正是该值，因此定义成立。
  • 归纳假设：假设所有长度小于 L 的区间都已得到最优分差。
  • 归纳步骤：长度为 L 时，合法动作仅有取左端与取右端。取数后对手成为剩余区间的当前行动方，其最优领先量必须从本次得分中扣除。转移取两个合法结果的最大值，恰好覆盖并选择当前玩家的最优策略。
  • 结论：由数学归纳法，dp[0][n-1] 是先手在全数组上的最优净领先；非负即至少战平，所以返回条件正确。

边界与复杂度

  • 只有一个数字：玩家 1 取走它，必胜或战平。
  • 所有数字为 0：最终分差为 0，平局按玩家 1 获胜。
  • 两个数字：先手直接取较大端点。
  • 数值虽可到 107，最多 20 个；四种实现中的整数类型均足够。
时间O(n²)
额外空间O(n)
状态数n(n+1)/2

四语言完整实现

Java · 一维区间 DP官方签名
class Solution {
    public boolean predictTheWinner(int[] nums) {
        int n = nums.length;
        int[] dp = nums.clone();

        for (int i = n - 2; i >= 0; i--) {
            for (int j = i + 1; j < n; j++) {
                int takeLeft = nums[i] - dp[j];
                int takeRight = nums[j] - dp[j - 1];
                dp[j] = Math.max(takeLeft, takeRight);
            }
        }
        return dp[n - 1] >= 0;
    }
}

from typing import List


class Solution:
    def predictTheWinner(self, nums: List[int]) -> bool:
        n = len(nums)
        dp = nums[:]

        for i in range(n - 2, -1, -1):
            for j in range(i + 1, n):
                take_left = nums[i] - dp[j]
                take_right = nums[j] - dp[j - 1]
                dp[j] = max(take_left, take_right)

        return dp[n - 1] >= 0
C++ · 一维区间 DP官方签名
class Solution {
public:
    bool predictTheWinner(vector<int>& nums) {
        int n = static_cast<int>(nums.size());
        vector<int> dp(nums.begin(), nums.end());

        for (int i = n - 2; i >= 0; --i) {
            for (int j = i + 1; j < n; ++j) {
                int takeLeft = nums[i] - dp[j];
                int takeRight = nums[j] - dp[j - 1];
                dp[j] = max(takeLeft, takeRight);
            }
        }
        return dp[n - 1] >= 0;
    }
};

替代方案

  • 记忆化搜索：完全沿用分差定义，递归直观；时间 O(n²)，空间 O(n²) 加递归栈。
  • 二维 DP：表意最清晰，转移与证明直接对应；时间、空间均为 O(n²)。
  • 总分 DP：求先手最大可得分，再与数组总和比较；可行，但角色与奇偶处理更容易写错。

面试追问

  • 为什么“自己的得分减去对手的最优分差”能表达角色交换？
  • 一维压缩时，dp[j] 和 dp[j-1] 分别代表哪个区间？
  • 若每次允许从两端各取至多两个数，状态与转移如何变化？
  • 若平局不算玩家 1 获胜，最终条件要如何修改？

常见错误

  • 贪心取较大的端点，忽略该选择会暴露什么数字给对手。
  • 把转移中的“减”误写成“加”，丢失零和博弈的角色交换。
  • 一维 DP 的遍历方向错误，覆盖了仍要使用的旧状态。
  • 用 > 0 判断胜利，错误排除了题目允许的平局。
