搜寻名人

Find the Celebrity

277

一场聚会中有 n 个人，编号为 0 到 n - 1。如果存在“名人”，那么其他每个人都认识他，而他不认识任何其他人。你只能通过系统提供的 knows(a, b) 接口询问“a 是否认识 b”，请返回名人的编号；不存在时返回 -1。

01 / Problem

题目约定

knows(a, b) 返回布尔值：当且仅当人物 a 认识人物 b 时为真。评测系统内部可用矩阵 graph 表示这种关系，其中 graph[a][b] = 1 等价于 knows(a, b) = true。 你不能直接访问 graph。

需实现 findCelebrity(n)。名人必须同时满足：对任意 i ≠ c，都有 knows(i, c) = true 且 knows(c, i) = false。

示例 1

输入：graph = [[1,1,0],[0,1,0],[1,1,1]] 输出：1

0 和 2 都认识 1，而 1 不认识 0 或 2，所以 1 是名人。

示例 2

输入：graph = [[1,0,1],[1,1,0],[0,1,1]] 输出：-1

没有人同时满足“所有其他人都认识他”和“他不认识其他人”。

约束

  • n == graph.length == graph[i].length
  • 2 ≤ n ≤ 100
  • graph[i][j] 只可能是 0 或 1
  • graph[i][i] == 1
  • 应尽量减少对 knows 的调用；进阶目标是不超过 3 × n 次。

03 / Solution

准备好揭晓了吗？

题解、证明、复杂度与四语言代码被独立收起，避免首屏泄题。

题解：两阶段候选淘汰

核心洞察

任取两个人 a、b。如果 knows(a, b) 为真，a 不可能是名人；否则 b 不可能是名人。一次询问至少能排除一人，因此先用一趟扫描只留下唯一候选，再对候选做完整验证。

完整过程

  1. 令 candidate = 0。
  2. 从 i = 1 扫描到 n - 1。若 candidate 认识 i，前者不可能是名人，改令 candidate = i；否则 i 不可能是名人，候选保持不变。
  3. 扫描结束后，除 candidate 外的人都已被至少一条必要条件排除，但这只说明他“可能”是名人。
  4. 对每个 i ≠ candidate 检查：候选不能认识 i，并且 i 必须认识候选。任一条件失败就返回 -1；全部成立则返回候选编号。

正确性证明

引理：淘汰阶段不会错过名人

比较当前候选 c 和人物 i：若 c 认识 i，则 c 违反名人“不认识别人”的条件；否则 i 违反“所有人都认识名人”的条件。被丢弃者一定不可能是名人。

定理：算法返回值正确

淘汰后若真实名人存在，他只能是最后候选。验证阶段逐一检查该候选的两条充要条件；失败说明不存在名人，全部成功说明该候选正是名人。因此返回值总是正确。

边界情况

  • 候选在首次比较中不断替换：仍由后续验证兜底。
  • 所有人互相认识：任何候选都违反“不认识别人”，返回 -1。
  • 除自己外谁也不认识谁：候选无法满足“所有人认识他”，返回 -1。
  • 官方约束为 n ≥ 2；实现也对非正数 n 防御性返回 -1。

复杂度

时间复杂度为 O(n)，额外空间复杂度为 O(1)。淘汰最多调用 n - 1 次 knows，验证最多调用 2(n - 1) 次，总计不超过 3n - 3 次（遇到失败可提前结束）。

替代方案

  • 全矩阵计数：统计每人的“认识别人”与“被别人认识”次数，容易理解，但要调用 O(n²) 次接口。
  • 栈式两两淘汰：每次弹出两人并保留可能者，本质与候选扫描相同，但需 O(n) 额外空间。
  • 缓存查询：可缓存淘汰阶段已问过的结果，减少少量重复调用，但空间会增至 O(n)，且不改变渐进复杂度。

面试追问

  • 为什么淘汰结束后仍必须验证？因为每次比较只证明一个人不可能，并没有证明保留者满足所有关系。
  • 能否少于线性调用？不能。要排除 n - 1 个非名人，至少需要获得线性数量的信息。
  • 接口有延迟时怎么做？淘汰阶段存在数据依赖，应顺序进行；验证候选时各人物的两类查询可在允许并发的系统中批量发出。
  • 若关系会在查询过程中变化怎么办？题目默认关系稳定；动态关系需要快照、版本号或一致性协议，已是不同的问题模型。

常见错误

  • 扫描后直接返回候选，漏掉“不存在名人”的情况。
  • 验证时只检查一个方向：两条定义缺一不可。
  • 把 knows(a, b) 的参数方向写反。
  • 验证自己与自己的关系，导致对题目无关的 graph[c][c] 产生依赖。
  • 直接读取内部矩阵；正式提交只能调用评测系统提供的 knows。

/* The knows API is defined in the parent class Relation.
   boolean knows(int a, int b); */
public class Solution extends Relation {
    public int findCelebrity(int n) {
        if (n <= 0) return -1;

        int candidate = 0;
        for (int i = 1; i < n; i++) {
            if (knows(candidate, i)) {
                candidate = i;
            }
        }

        for (int i = 0; i < n; i++) {
            if (i == candidate) continue;
            if (knows(candidate, i) || !knows(i, candidate)) {
                return -1;
            }
        }
        return candidate;
    }
}
