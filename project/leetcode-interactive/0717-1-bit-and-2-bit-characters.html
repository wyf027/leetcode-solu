01 / Problem

题目描述

一种字符只占一位，另一种字符固定占两位。数组保证以 0 收尾，你需要判断这个末位是否必然是前一种字符。

给定两种特殊字符的二进制编码：

  • 0一比特字符，只能表示为 0。
  • 10 / 11二比特字符，可以表示为 10 或 11。

给你一个以 0 结尾的二进制数组 bits。如果最后一个字符必须是一个一比特字符，返回 true；否则返回 false。

约束

  • 1 <= bits.length <= 1000
  • bits[i] 只能是 0 或 1
  • 题目保证 bits 的最后一位是 0
  • 函数签名：isOneBitCharacter(bits)，返回布尔值

Example 01

输入bits = [1, 0, 0]
输出true

唯一的解码是 10 | 0：一个二比特字符后接一个一比特字符，因此末位独立。

Example 02

输入bits = [1, 1, 1, 0]
输出false

唯一的解码是 11 | 10：末尾的 0 被前一位 1 带入二比特字符，并不独立。

04 / Solution Vault

准备好核对思路了吗？

题解与代码保持折叠，不会在首屏直接泄露。你可以先在实验室里建立自己的判断规则。

Greedy Scan

从左到右，跳到下一个字符

O(n) · O(1)

核心洞察

每个字符的首位已经决定它的长度：看到 0 就走 1 步，看到 1 就走 2 步。因此从索引 0 出发，整个解码过程没有分支。

我们不需要真的处理最后一位。只需在 i < n - 1 时持续跳跃：循环结束后，如果 i === n - 1，指针正好落在最后的 0 上，它就必须独立；如果 i === n，最后的 0 已被前一个 1 吞进二比特字符。

完整过程

  1. 令指针 i = 0。
  2. 只要 i < n - 1，读取当前位置。
  3. 若 bits[i] === 0，移动 1 位；否则移动 2 位。
  4. 退出循环后返回 i === n - 1。

正确性证明

循环不变式：每次循环开始时，i 都是尚未解码的下一个字符的起始位置。

初始化：尚未读取任何位时，第一个字符从索引 0 开始，所以不变式成立。

保持：若 bits[i] = 0，当前字符长度必为 1，令 i += 1 后恰好抵达下一字符；若 bits[i] = 1，当前字符必为 10 或 11，长度为 2，令 i += 2 后同样恰好抵达下一字符。因此不变式持续成立。

终止：循环结束时 i >= n - 1。由不变式，若 i = n - 1，末位是下一字符的起点，又因它是 0，所以必为一比特字符；若 i = n，末位已属于刚刚读完的二比特字符。返回条件因此正确。

复杂度与边界

时间O(n)
空间O(1)

边界情况

  • [0]：循环一次也不执行，指针已经位于末位，返回 true。
  • [1, 0]：一步跳到数组末端之外，返回 false。
  • 全是 0：每次只移动一位，最后一个 0 必然独立。
  • 长数组：指针每轮至少前进一位，不会出现死循环。

四种语言实现

class Solution {
    public boolean isOneBitCharacter(int[] bits) {
        int i = 0;
        int last = bits.length - 1;

        while (i < last) {
            i += bits[i] == 0 ? 1 : 2;
        }

        return i == last;
    }
}

替代方案：数末尾连续的 1

从倒数第二位开始向左数连续的 1。若数量为偶数，最后的 0 独立；若数量为奇数，最后一个 1 会与末尾 0 组成二比特字符。

该方法同样是最坏 O(n) 时间、O(1) 空间，代码可以更短；但从左到右跳跃与题目编码规则直接对应，证明和讲解通常更自然。

何时选择它

当数据以流的形式到达、你只关心最终结果时，可以只维护“当前末尾连续 1 的奇偶性”，无需保留整个数组。

常见错误

  • 把循环写成 i < n，导致最后一个 0 也被消费，丢失判断依据。
  • 认为“数组最后是 0”就直接返回 true，忽略它可能属于 10。
  • 尝试回溯所有拆分；这里每个字符的首位已经唯一决定长度，不存在分支。
  • 用 bits[i + 1] 决定跳几步，增加不必要的越界风险。

面试追问

  1. 为什么贪心没有选错的可能？ 因为首位 0 只能是一比特字符，首位 1 只能是二比特字符，当前字符长度是确定的。
  2. 如果编码集合改成 0、10、110、111，会怎样？ 仍可按前缀逐位判断，但需要更完整的状态机或前缀树；不能继续只看一位后固定跳两步。
  3. 能否在线处理？ 可以。若允许直到流结束才输出，维护末尾连续 1 的奇偶性即可。
  4. 如果题目不保证最后一位是 0？ 需要先明确“最后字符是一比特字符”的编码定义；在当前编码中，一比特字符只能是 0，因此末位为 1 时答案必为 false。
