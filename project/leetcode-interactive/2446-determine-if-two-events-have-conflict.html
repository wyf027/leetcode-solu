判断两个事件是否存在冲突

Determine if Two Events Have Conflict

两段日程，一个共同的时刻。先读题，再在时间轴上探索。

01 /题目

给定同一天的两个事件：event1 = [startTime1, endTime1] 和 event2 = [startTime2, endTime2]。每个时间都使用有效的 24 小时制 HH:MM 格式。

每个事件都包含开始和结束时刻。如果至少有一个时刻同时属于两个事件，返回 true；否则返回 false。

注意题意：这是闭区间，端点也属于事件；两个事件都不跨越午夜。

官方示例 1 · 端点相遇
event1 = ["01:15","02:00"]
event2 = ["02:00","03:00"]
输出：true

两个事件都包含 02:00。

官方示例 2 · 部分重叠
event1 = ["01:00","02:00"]
event2 = ["01:20","03:00"]
输出：true

共同时间段为 01:20 至 02:00，包含两端。

官方示例 3 · 相互分离
event1 = ["10:00","11:00"]
event2 = ["14:00","15:00"]
输出：false

两个事件没有共同的时刻。

约束

  • event1.length == event2.length == 2。
  • event1[i].length == event2[i].length == 5，其中 i ∈ {0, 1}。
  • startTime1 ≤ endTime1，startTime2 ≤ endTime2。
  • 所有时间都是有效的 HH:MM 格式，范围为 00:00 至 23:59。

04 /独立题解

核心洞察 · 让两个边界靠拢

把两个闭区间记作 [s1, e1]、[s2, e2]。共同时间必须不早于两个开始时刻，也不晚于两个结束时刻。因此交集候选是 [max(s1, s2), min(e1, e2)]。左边界不超过右边界时，交集非空。

max(s1, s2) ≤ min(e1, e2)
等价的提交代码条件：s1 ≤ e2 && s2 ≤ e1。

完整过程

  1. 读取两个事件的开始与结束时间，不必排序或修改输入。
  2. 可视化先确定较晚开始的时刻 L，再确定较早结束的时刻 R。
  3. 若 L ≤ R，则共同时间窗存在。L = R 时，交集是一个时刻，仍返回 true。
  4. 代码直接比较两对交叉端点：事件 A 的开始不晚于 B 的结束，且 B 的开始不晚于 A 的结束。

以示例 1 为例，L = 02:00，R = 02:00，因此存在单点交集；示例 3 中 L = 14:00、R = 11:00，左右边界倒置，交集为空。

为什么可以直接比较字符串？

题目保证固定五字符且小时、分钟都补零。字典序先比较两位小时，再越过相同的冒号比较两位分钟，顺序恰好与时间先后相同。比如 "09:50" < "10:00"。若输入是 "9:50"，则不再满足这一前提。

正确性证明

必要性：若存在共同的时刻 t，则 s1 ≤ t ≤ e2、s2 ≤ t ≤ e1，所以两个交叉比较都成立。

充分性：假设 s1 ≤ e2 且 s2 ≤ e1。取 t = max(s1, s2)。若 t = s1，根据自身区间合法性有 t ≤ e1，再由假设有 t ≤ e2；若 t = s2，同理有 t ≤ e1、t ≤ e2。t 又不小于任意开始时刻，所以同时属于两个闭区间。故条件成立当且仅当存在冲突。

边界与常见错误

  • 端点相等、零长度事件、完全相同或完全包含都可能有交集；不要把 ≤ 写成 <。
  • 事件数组的先后不代表发生顺序；不能只判断 event1[1] ≥ event2[0]。
  • Java 字符串比较应使用 compareTo，不能用 == 判断先后。
  • 无需 Date 对象、时区转换或逐分钟遍历；这些都不能替代闭区间语义。
  • 本题不跨日。像 23:00 到 01:00 的输入不合法，不能直接套用这里的条件。

复杂度

时间 O(1)，额外空间 O(1)：仅比较固定长度为 5 的字符串，且不复制事件数组。若推广到长度为 k 的时间字符串，比较耗时为 O(k)。

替代方案

把 HH:MM 转为 60 × HH + MM，再比较整数区间，适合后续需要计算分钟差的场景。也可判断“不相交”的反面：!(e1 < s2 || e2 < s1)。为两个事件建立分钟占用表会增加不必要的遍历与存储。

四语言完整提交代码

签名依据官方元数据；以下均为算法代码，执行验证待补。

Java

class Solution {
    public boolean haveConflict(String[] event1, String[] event2) {
        return event1[0].compareTo(event2[1]) <= 0
            && event2[0].compareTo(event1[1]) <= 0;
    }
}

面试追问

  • 如果结束时刻不属于事件？对于非空半开区间 [s, e)，使用严格小于；零长度半开区间为空，需单独处理。
  • 如果有 n 个事件，判断是否存在任意冲突？按开始时刻排序，扫描并维护此前最大的结束时刻；当前开始不晚于此前最大结束时刻即冲突，时间 O(n log n)。
  • 如果跨越午夜或有时区？先明确日期和时区，再转换为同一时间基准；周期性日程也可按午夜拆分后检查。
  • 如何返回共同时间段？条件成立时返回 [max(s1, s2), min(e1, e2)]，否则返回空结果；单点交集的持续时长可以为 0，但它仍是非空集合。
