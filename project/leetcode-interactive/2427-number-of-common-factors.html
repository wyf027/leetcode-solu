2427. 公因子的数目

Number of Common Factors

两个整数，哪些正整数能把它们都分得刚刚好？

01 / 题目

给定正整数 a 和 b，返回它们的正公因子数量。一个正整数 x 只有在同时整除 a 与 b 时，才算作它们的公因子。

参数：a: integer, b: integer

返回：integer，即不同正公因子的个数。

约束：1 ≤ a, b ≤ 1000

先独立思考：输出的是数量，还是最大的那个公因子？

02 / 官方示例

示例 1

输入：a = 12, b = 6
输出：4

共同的正因子是 1、2、3、6，共 4 个。

示例 2

输入：a = 25, b = 30
输出：2

共同的正因子是 1、5，共 2 个。

核心洞察：让每个候选数通过两道整除门

完整过程与正确性

  1. 把答案初始化为 0，枚举上限设为 min(a, b)。
  2. 从 1 开始逐一检查候选数，分别计算两个余数。
  3. 两个余数都为 0 时，答案加 1。
  4. 检查完上限后，返回答案。

以 a = 12, b = 6 为例：x = 1、2、3 时均计数；x = 4 不能整除 6，x = 5 不能同时整除两数；x = 6 再计一次，结果为 4。

循环不变式：检查完 x 后，计数恰好等于区间 [1, x] 内的公因子数量。初始区间为空，计数为 0。每轮只在当前数满足公因子定义时加 1，因此不变式保持。

完备性：任意正公因子 d 都满足 d ≤ a 且 d ≤ b，所以一定出现在 [1, min(a, b)] 中。每个数只访问一次，不会遗漏或重复；循环结束的计数就是答案。

复杂度：时间 O(min(a, b))，辅助空间 O(1)。交互页面为了回放保存和绘制候选状态，会使用 O(min(a, b)) 空间；这不属于提交算法。

边界与常见错误

  • 输入包含 1：答案只能是 1；正整数总有公因子 1，答案不会是 0。
  • a = b：统计该数全部正因子；两数互质时仅有 1。
  • 从 0 开始：0 不能作为除数，应从 1 开始。
  • 漏掉上限：循环必须包含 min(a, b)，例如 (6, 12) 中的 6。
  • 把“且”写成“或”：必须同时整除两个数，不能只通过一个通道。
  • 返回 gcd：最大公约数是一个数值，本题要它的正因子数量。

替代方案：最大公约数 + 成对枚举

先用欧几里得算法求 g = gcd(a, b)。公因子集合就是 g 的正因子集合：共同整除 a、b 的数也整除 gcd，而 g 的因子能整除 a 和 b。枚举 d 从 1 到 √g；若 d 整除 g，配对因子为 g / d，两者不同加 2，相同只加 1。

该方案时间 O(log(min(a, b)) + √g)，空间 O(1)。本题输入最多 1000，直接枚举更容易实现；大范围输入可以改用此方案。平方根处不要重复计数，固定宽度整数中可用 d ≤ g / d 避免 d * d 溢出。

面试追问

  • 推广到多个数？先求所有数的 gcd，再统计它的因子。
  • 同一批数要回答很多次？可预处理各整数的因子数量，每次求 gcd 后查表；应根据范围和查询量决定是否值得。
  • 已知 g 的质因数分解？若 g = p₁^e₁ · … · pₖ^eₖ，因子数量为 (e₁ + 1)…(eₖ + 1)，每个因子的各质因数指数可独立选择。

Java

class Solution {
    public int commonFactors(int a, int b) {
        int count = 0;
        for (int x = 1; x <= Math.min(a, b); x++) {
            if (a % x == 0 && b % x == 0) count++;
        }
        return count;
    }
}
