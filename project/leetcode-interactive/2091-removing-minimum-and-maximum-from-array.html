给定一个下标从 0 开始、元素互不相同的整数数组 nums。一次操作只能删除当前数组最前面或最后面的一个元素。求将原数组中的最小值和最大值都删除所需的最少操作次数，返回一个整数。

  • 1 ≤ nums.length ≤ 10⁵
  • −10⁵ ≤ nums[i] ≤ 10⁵

输入：nums = [2,10,7,5,4,1,8,6]

输出：3

最小值 −4、最大值 19 分别位于下标 1、2。删除前 3 个元素即可。

输入：nums = [101]
输出：1

04 / 独立题解

准备好后，展开推导与完整实现。

核心洞察：只需比较三种边界

删除操作最终只会移除一个前缀和一个后缀。设两个极值的原始下标从左到右为 a ≤ b，数组长度为 n。下标的左右顺序与值的大小无关。

① 全从左删b + 1

删到更靠右的极值，两个都被覆盖。

② 全从右删n − a

删到更靠左的极值，两个都被覆盖。

③ 左右各删一段(a + 1) + (n − b)

左侧覆盖 a，右侧覆盖 b。

答案 = min(b + 1, n − a, a + 1 + n − b)

完整过程

  1. 一次扫描，维护最小值、最大值对应的下标。
  2. 令 a 为较小下标、b 为较大下标。
  3. 分别计算三种删除次数，返回最小值。无需真正修改数组。

示例 1 中，n = 8，a = 1，b = 5。全从左删需要 6 次，全从右删需要 7 次，左右分别删除需要 2 + 3 = 5 次，因此答案是 5。

正确性证明

任意合法操作序列的删除集合都是原数组的一个前缀加一个后缀；操作先后顺序不会改变删除总数。考虑最终两个极值由哪些部分覆盖：

  • 若前缀覆盖两个极值，前缀长度至少 b + 1；只删除恰好 b + 1 个即可达到这个下界。
  • 若后缀覆盖两个极值，后缀长度至少 n − a；只删除恰好 n − a 个即可达到下界。
  • 否则两个极值分属前缀和后缀。前缀必须覆盖左侧位置 a，后缀必须覆盖右侧位置 b，至少需要 a + 1 + n − b 次，并可按此构造。若试图反向覆盖，前缀已覆盖两个极值，属于第一类。

所有合法方案均被这些情况覆盖，且每个有效候选均可达到对应下界，所以取最小值得到全局最优解。n = 1 时混合式计数为 2，会重复计算同一元素；两个单侧候选均为 1，最小值依然正确。

边界与复杂度

单元素返回 1；两个元素返回 2；极值在两端时 n ≥ 2 可各删一次。负数不改变算法，比较的是元素值，计算的是下标距离。扫描时间 O(n)，额外空间 O(1)。交互页面存储撤销历史所用空间不属于提交算法的空间复杂度。

四语言完整提交代码

Java

class Solution {
    public int minimumDeletions(int[] nums) {
        int n = nums.length, lo = 0, hi = 0;
        for (int i = 1; i < n; i++) {
            if (nums[i] < nums[lo]) lo = i;
            if (nums[i] > nums[hi]) hi = i;
        }
        int a = Math.min(lo, hi), b = Math.max(lo, hi);
        return Math.min(Math.min(b + 1, n - a), a + 1 + n - b);
    }
}

替代方案

可枚举删除的前缀长度，再计算为覆盖尚存极值所需的最短后缀，总体也能做到 O(n)，但这里三种情况已足够。暴力枚举左右删除数会达到 O(n²)；排序会丢失原始位置，保存位置再排序则需 O(n log n)，均无必要。

常见错误

  • 把最小值的下标直接当作 a。必须对两个下标按位置排序。
  • 左端距离写成 b：下标从 0 开始，覆盖 b 需要 b + 1 次。
  • 右端距离多加一次：从 n − 1 删到 a，一共 n − a 个。
  • 只给两个极值各选一个最近端点再相加：同侧删除有重叠，不能重复计数。
  • 只比较两个单侧方案会遗漏最优的两端组合。

面试追问

  • 如何输出实际操作？记录取得最小值的策略，生成对应次数的左删/右删操作即可。
  • 若左右删除单价分别是正数 L、R？比较 (b + 1)L、(n − a)R、(a + 1)L + (n − b)R。
  • 若允许重复值？先明确要删掉每种极值的一次出现，还是全部出现；单个极值下标不再能表达一般情况，需根据目标分析出现位置。
