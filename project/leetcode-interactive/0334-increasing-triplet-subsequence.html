Increasing Triplet Subsequence

从一列整数中判断：是否能按原下标顺序，挑出三个严格递增的数？先读题并动手观察，再决定是否展开底部题解。

Problem

题目描述

给定一个整数数组 nums。如果存在三个下标 i < j < k，并且对应元素满足 nums[i] < nums[j] < nums[k]，返回 true；否则返回 false。

这里要求的是子序列：三个元素保持原有先后顺序，但不必相邻；同时数值关系必须严格递增，相等不能算作递增。

示例 1

输入：nums = [1,2,3,4,5]
输出：true
解释：例如下标 (0,1,2) 对应 1 < 2 < 3。

示例 2

输入：nums = [5,4,3,2,1]
输出：false
解释：数组持续下降，无法按顺序选出严格递增的三个数。

示例 3

输入：nums = [2,1,5,0,4,6]
输出：true
解释：下标 (1,4,5) 对应 nums[1] = 1、nums[4] = 4、nums[5] = 6，且 1 < 4 < 6。

约束

  • 1 <= nums.length <= 5 * 105
  • -231 <= nums[i] <= 231 - 1
进阶要求

尝试设计时间复杂度 O(n)、额外空间复杂度 O(1) 的方案。

Solution

准备好核对思路了吗？

完整题解默认收起，不影响你先独立思考。

Greedy Insight

贪心维护两个最小结尾

first

扫描到当前位置时，长度为 1 的递增子序列能够拥有的最小结尾。

second

已经出现过的某个长度为 2 的严格递增子序列，其第二个元素能达到的最小值。

当前 x

一旦 x > second，此前那一对递增元素与当前元素构成合法三元组。

核心洞察：我们不必保存具体的所有子序列，只要让长度 1 和长度 2 候选的结尾尽可能小，就为后续第三个更大的数留下最大空间。

完整过程

1
初始化：令 first = +∞、second = +∞。
2
压低 first：若当前值 x <= first，更新 first = x。
3
压低 second：否则若 x <= second，此时已有 first < x，更新 second = x。
4
找到第三个数：否则必有 x > second，返回 true。
5
扫描结束：始终没有出现第三个数，则返回 false。

比较时必须使用 <= 更新哨兵，因为题目要求严格递增：相等的值只能替换候选，不能推进长度。

正确性证明

  1. 不变量 1：处理完每个前缀后，first 是该前缀中最小的元素，因此是长度 1 候选的最小结尾。
  2. 不变量 2：当 second 有限时，前缀中确实存在下标有序、值严格递增的一对元素，并且 second 是所有这种长度 2 候选结尾的最小值。只有在 x > first 时才更新它，所以存在对应的前驱。
  3. 充分性：若某次出现 x > second，形成 前驱 < second < x，且三者按扫描顺序出现，故合法三元组存在。
  4. 必要性：若存在递增三元组 a < b < c，扫描到 b 后必有 second <= b；扫描到 c 时有 c > second，算法必返回 true。

边界与复杂度

  • 数组长度小于 3：无法构成三元组，最终返回 false。
  • 重复元素：使用 <= 覆盖哨兵，不把相等误判为上升。
  • 负数与 32 位整数边界：比较逻辑不受符号影响。
  • 时间复杂度：O(n)，每个元素只处理一次。
  • 额外空间：O(1)，只维护两个哨兵。
注意：后续更小的值可能更新 first，它不必仍是当前 second 的实际前驱；但 second 在被写入时已有合法前驱，因此存在性证明不受影响。

class Solution {
    public boolean increasingTriplet(int[] nums) {
        int first = Integer.MAX_VALUE;
        int second = Integer.MAX_VALUE;

        for (int x : nums) {
            if (x <= first) {
                first = x;
            } else if (x <= second) {
                second = x;
            } else {
                return true;
            }
        }
        return false;
    }
}

替代方案

前后缀数组

预处理每个位置左侧最小值与右侧最大值，再判断是否存在中间值。时间 O(n)，空间 O(n)，直观但未达到常数空间进阶要求。

最长递增子序列

维护长度至多 3 的 tails 数组并二分替换，时间 O(n log 3)，空间 O(3)。它更通用，但本题双哨兵更简洁。

三重枚举

直接枚举下标三元组最容易想到，但最坏时间 O(n³)，在 5 × 10⁵ 的数据规模下不可行。

常见错误

  • 把“子序列”误读为“连续子数组”。
  • 使用 x < first 而不是 x <= first，导致重复值错误推进 second。
  • 第二个条件写成独立 if，使同一个元素在一次迭代中更新多个状态。
  • 只记录数组中最小的三个值，却忽略下标出现顺序。
  • 认为更新后的 first 必须是 second 的原始前驱，从而错误清空 second。

面试追问

为什么只保存值，不保存下标？

按从左到右扫描天然保证时间顺序；题目只要求判断存在性，两个最小结尾已经足够。

如果要求返回具体下标呢？

需要同步保存 first 的下标，以及 second 被更新时对应的 first 下标；找到第三个数时即可还原一组见证。

推广到长度 k 怎么做？

维护各长度递增子序列的最小结尾，并用二分查找替换位置，即经典 LIS 的 tails 方法。

能否提前排除长度不足？

可以在开头判断 nums.length < 3，但主循环自然也会返回 false；是否添加取决于可读性偏好。
