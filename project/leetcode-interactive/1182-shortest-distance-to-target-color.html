与目标颜色间的
最短距离

Shortest Distance to Target Color

MEDIUM付费题数组双向扫描多次查询

题目

给定整数数组 colors，其中每个元素只可能是 1、2 或 3，分别代表一种颜色。每个查询 [index, color] 要求：找到数组中颜色等于 color 的位置，使它与 index 的下标距离最小。

对每个查询返回这个最短距离；如果数组里根本不存在目标颜色，则返回 -1。距离按 |index - j| 计算，所以当前位置颜色已匹配时答案为 0。

函数形式：shortestDistanceColor(colors, queries) → 整数列表。查询互相独立。

示例 1

输入
colors = [1,1,2,1,3,2,2,3,3] queries = [[1,3],[2,2],[6,1]]
输出
[3,0,3]

位置 1 到最近的颜色 3（位置 4）距离为 3；位置 2 本身就是颜色 2；位置 6 到最近的颜色 1（位置 3）距离为 3。

示例 2

输入
colors = [1,2] queries = [[0,3]]
输出
[-1]

数组中没有颜色 3，因此这个查询的结果是 -1。

约束

  • 1 ≤ colors.length ≤ 5 × 10⁴
  • 1 ≤ colors[i] ≤ 3
  • 1 ≤ queries.length ≤ 5 × 10⁴
  • queries[i].length == 2
  • 0 ≤ queries[i][0] < colors.length
  • 1 ≤ queries[i][1] ≤ 3

Editorial

双向扫描：预计算每个位置的答案

核心洞察

目标颜色只有 3 种。建立 dist[i][c]：位置 i 到颜色 c 的最短距离。对每种颜色分别做一次从左到右、一次从右到左的扫描，之后每条查询只需查表。

状态如何更新

扫描时维护最近的目标颜色位置 last。若它存在，当前位置到该方向最近目标的距离就是 |i-last|，再与已有值取最小。

完整过程

  1. 创建 n × 4 的距离表，初值为无穷大；下标 1～3 对应三种颜色。
  2. 从左向右扫描。用 last[1..3] 记录每种颜色最近一次出现的位置，写入左侧最近距离。
  3. 清空 last，从右向左扫描；用右侧最近距离更新同一个表中的最小值。
  4. 对查询 [i,c] 读取 dist[i][c]；仍为无穷大说明颜色不存在，返回 -1。

正确性证明

引理 1：左向扫描结束后，dist[i][c] 等于 i 到其左侧（含 i）最近颜色 c 的距离；因为 last[c] 始终是扫描前缀中最大的匹配下标。

引理 2：同理，右向扫描在 i 处得到右侧（含 i）最近颜色 c 的距离。

结论：任意匹配位置只可能位于 i 左侧或右侧。两者最小值因此就是全数组内的最短距离；若两侧都不存在则正确返回 -1。

复杂度

设数组长度为 n、查询数为 q。预处理扫描固定 3 种颜色，可实现为一次扫描同时维护三种颜色，因此时间 O(n + q)，距离表空间 O(3n) = O(n)。

边界情况

  • 目标颜色完全不存在：返回 -1。
  • 当前位置正好是目标颜色：返回 0。
  • 数组长度为 1，或最近位置只在单侧。
  • 左右两侧同距：答案仍是同一个距离，无需选择具体位置。

class Solution {
    public List<Integer> shortestDistanceColor(int[] colors, int[][] queries) {
        int n = colors.length;
        int inf = n + 1;
        int[][] dist = new int[n][4];
        for (int[] row : dist) Arrays.fill(row, inf);

        int[] last = {-1, -1, -1, -1};
        for (int i = 0; i < n; i++) {
            last[colors[i]] = i;
            for (int c = 1; c <= 3; c++) {
                if (last[c] != -1) dist[i][c] = i - last[c];
            }
        }

        Arrays.fill(last, -1);
        for (int i = n - 1; i >= 0; i--) {
            last[colors[i]] = i;
            for (int c = 1; c <= 3; c++) {
                if (last[c] != -1) {
                    dist[i][c] = Math.min(dist[i][c], last[c] - i);
                }
            }
        }

        List<Integer> answer = new ArrayList<>();
        for (int[] q : queries) {
            int d = dist[q[0]][q[1]];
            answer.add(d == inf ? -1 : d);
        }
        return answer;
    }
}

        last.fill(-1);
        for (int i = n - 1; i >= 0; --i) {
            last[colors[i]] = i;

替代方案

按颜色保存有序下标 + 二分查找：预处理每种颜色出现的位置。每个查询在对应列表里二分，比较插入点两侧候选。空间 O(n)，预处理 O(n)，每次查询 O(log n)。当颜色种类很多时，这种方法通常比完整距离表更节省空间。

逐查询向两侧扩散：无需预处理，但最坏每次 O(n)，总计 O(nq)，无法承受上限数据。

面试追问

  • 颜色种类从 3 扩展到 10⁵ 时，如何权衡二分列表和距离表？
  • 如果数组会在线修改颜色，该用什么数据结构？可为每种颜色维护有序集合。
  • 如果只允许 O(1) 额外空间，能否离线重排查询并扫描回答？

常见错误

  • 只扫描一个方向，漏掉另一侧更近的目标。
  • 目标不存在时把无穷大直接返回，而不是 -1。
  • 错误地用值之差代替下标之差。
  • 每个查询都重新扫描整个数组，导致超时。
