把“借给谁”转换为“环图上该走哪条边”

使循环数组余额非负的最少移动次数 II

相邻一次转账只能移动 1 单位。余额可以绕环走两条方向；因此局部贪心很容易把后续最短路堵死。把盈余、亏空和相邻边放进最小费用流，答案就是补齐全部亏空的最小运输成本。

面试一句话

源连盈余、亏空连汇；环上的每次相邻转移是一条费用为 1 的边。

总和为负先判 -1；否则送出所有 deficit 的最小费用。

题意

每个人只能把 1 单位给左右邻居

给定环形数组 balance。一次操作选择某人，并向左或右邻居转出恰好 1 单位。要求最终所有位置非负；若总余额不足则无解，返回 -1。

约束：1 ≤ n ≤ 1000，−10⁵ ≤ balance[i] ≤ 10⁵。答案可能超过 32 位整数。

建图

  • S → i：balance[i] > 0，容量为盈余，费用 0。
  • i → T：balance[i] < 0，容量为亏空，费用 0。
  • i ↔ (i+1) mod n：容量足够大，费用 1。

一单位流经过 k 条环边，恰好对应 k 次相邻转账。

洞察过程

为什么不是“从最近盈余拿钱”？

  1. 先判可行性：转账不改变总和；总和 < 0 不可能。
  2. 再看路径：一个盈余同时服务多个亏空，且环上有顺、逆两条路；逐个就近决定会相互干扰。
  3. 统一选择：最小费用流在残量网络中保留反向边，后面的更短组合可撤销并重排早先流量。

边界与复杂度

  • n = 1：总和非负即 0，否则 -1。
  • 所有元素非负：没有需求，答案 0。
  • 环的双边：i 的左右邻居相同（n=2）时仍可保留平行边；建图不依赖去重。
  • 数值：实现使用 64 位累计费用。

这里的 SPFA 最短增广实现：保守上界 O(n³)，空间 O(n)。若要求更稳定的理论界，可改为势能 + Dijkstra，约 O(n² log n)。

隐藏题解

代码前先说清楚：流量就是转账次数

每次最短路找到一批可从某个盈余送至某个亏空的单位；批量推送瓶颈容量。反向边让后续路径可以回退旧方案，因此最终总费用是全局最优。

完整过程

  1. 总和小于 0 时，守恒意味着任何转账都无解。
  2. 从虚拟源向每个正余额点注入其盈余；负余额点向汇要求其亏空。
  3. 环的两侧相邻边费用都为 1。反复找残量网络中的最短增广路并批量推送。

边界、替代与面试追问

全非负直接为 0；n = 1 也只由总和决定。此题 n ≤ 1000，SPFA 最小费用最大流足够直观；追求稳定复杂度时可用势能 + Dijkstra。

常见错误：只按“最近盈余”贪心、漏掉环的反向边、或用 32 位累计费用。
