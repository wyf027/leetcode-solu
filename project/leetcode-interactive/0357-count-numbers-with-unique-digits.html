Combinatorics

组合计数：按数字长度拆分

核心洞察

不要逐个枚举数字。把答案拆成“0”以及长度恰好为 1、2、…、n 的互不重复数字数量，再分别计数并累加。

长度为 k 的正整数，最高位不能为 0，因此第一位有 9 种选择。第二位可以选 0，也可以选剩下的非零数字，共 9 种。此后每放入一位，都必须避开已经使用的数字，可选数依次减少。

f(1) = 9
f(k) = 9 × 9 × 8 × 7 × … × (10 - k + 1)，k ≥ 2
answer = 1 + f(1) + f(2) + … + f(n)

完整过程

  1. 若 n = 0，区间是 [0, 1)，直接返回 1。
  2. 对 n ≥ 1，先统计 0 到 9，共 10 个一位以内的数字。
  3. 令 unique = 9 表示上一轮长度的新增数，令 available = 9 表示新添一位时可选数字数。
  4. 从长度 2 循环到 n：执行 unique *= available，把结果加入答案，然后让 available--。
  5. 循环结束时，答案已经覆盖所有小于 10ⁿ 且各位不同的数字。

正确性证明

引理：对任意 1 ≤ k ≤ n，算法计算的 f(k) 等于所有 k 位且各位不同的正整数数量。

证明：第一位不能为 0，有 9 种选择；第二位只需避开第一位，因此在 0～9 中有 9 种选择；第 i 位需要避开前 i−1 个已用数字，所以有 10 − (i − 1) 种选择。根据乘法原理，各位选择数的乘积正好是全部合法 k 位数的数量，而且每个合法数只对应唯一的一条选择序列。引理成立。

定理：算法返回题目要求的总数。

证明：数字 0 单独计入。任意其余合法数字都有唯一的十进制长度 k，并被且仅被对应的 f(k) 计入。不同长度的集合互不相交，因此累加 1 与所有 f(k) 后，既无遗漏也无重复。故算法正确。

边界与复杂度

  • n = 0：必须返回 1，而不是 0，因为区间包含数字 0。
  • n = 1：0～9 全部合法，返回 10。
  • n > 10 的推广：十进制只有 10 个不同数字，不可能存在超过 10 位且各位不同的整数；本题约束 n ≤ 8，不会触及该限制。
  • 前导零：不能把它当成普通数位。最高位只有 1～9 可选，而第二位开始才允许使用 0。
时间复杂度
O(n)（推广写法可记为 O(min(n, 10))）
空间复杂度
O(1)

class Solution {
    public int countNumbersWithUniqueDigits(int n) {
        if (n == 0) {
            return 1;
        }

        int answer = 10;
        int unique = 9;
        int available = 9;

        for (int length = 2; length <= n; length++) {
            unique *= available;
            answer += unique;
            available--;
        }
        return answer;
    }
}

替代方案

  • 回溯：用一个 10 位 bitmask 标记已使用数字，逐位构造合法数字。思路直观，也方便枚举具体结果，但状态和递归开销更大。
  • 数位 DP：维护位置、已用数字集合、是否贴上界、是否已经开始构造。它能处理任意上界，而不仅是 10ⁿ，但对本题明显更复杂。
  • 动态规划表：令 dp[k] 表示恰好 k 位的合法数数量，再用相邻项关系递推。本质与组合计数相同，只是显式保存了中间状态。

面试追问

  • 若统计区间改成 0 ≤ x ≤ N，如何用数位 DP 解决？
  • 如果允许某个数字最多出现两次，状态应该如何扩展？
  • 如果进制从十进制改为 b 进制，公式如何变化？
  • 为何 n ≥ 10 后答案不再增加？能否让实现自然支持这个推广边界？

常见错误

  • 忘记单独计入数字 0，导致所有答案少 1。
  • 把第一位也算成 10 种选择，错误地允许前导零。
  • 第二位只算 8 种选择，忘记此时数字 0 可以使用。
  • 循环中先递减 available 再相乘，造成乘数错位。
  • 把“长度不超过 n”误写成“长度恰好为 n”，漏掉更短的合法数字。
