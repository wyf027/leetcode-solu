01 / 题目

把每条接受记录看成一条双向好友边

给定好友请求接受表，找出好友数最多的用户，并返回其编号 id 与好友数 num。官方生成用例保证最多好友者唯一。

表：RequestAccepted

列名类型含义
requester_idint发送请求的用户
accepter_idint接受请求的用户
accept_datedate请求被接受的日期

(requester_id, accepter_id) 是联合主键。一条记录表示请求已经接受，因此双方互为好友；日期不参与好友数计算。

官方示例 1

输入：RequestAccepted
+--------------+-------------+-------------+
| requester_id | accepter_id | accept_date |
+--------------+-------------+-------------+
| 1            | 2           | 2016/06/03  |
| 1            | 3           | 2016/06/08  |
| 2            | 3           | 2016/06/08  |
| 3            | 4           | 2016/06/09  |
+--------------+-------------+-------------+
输出：
+----+-----+
| id | num |
+----+-----+
| 3  | 3   |
+----+-----+

解释：用户 3 分别与 1、2、4 是好友，共有 3 位好友，多于其他用户。

完整约束与输出约定

  • requester_id、accepter_id 为整数用户 ID，accept_date 为日期。
  • (requester_id, accepter_id) 的组合唯一；每行描述一条已被接受的好友请求。
  • 好友关系是双向的：发送者与接受者的好友数都要增加 1。
  • 官方测试保证只有一位用户拥有最多好友，结果列名为 id、num。
  • 官方题面未给出额外的数值范围，本页不虚构 ID 或行数上限。

04 / 独立题解

准备好后，再揭开聚合方法

这里包含思路、证明、复杂度与完整代码，默认收起。

核心洞察

把两列用户 ID 纵向叠成一列，再按用户计数

每条好友记录必须为两个人各贡献一次。将发送者列与接受者列用 UNION ALL 保留重复地纵向合并，就把“数好友”转成了普通的单列频次统计。

完整过程

  1. 取每行的 requester_id，统一命名为 id。
  2. 再取每行的 accepter_id，也命名为 id。
  3. 用 UNION ALL 合并两批 ID；不能去重，因为每次出现都代表一次好友贡献。
  4. 按 id 分组，COUNT(*) 就是该用户的好友数。
  5. 按计数降序排列并取第一行。原题保证最大者唯一。

为什么正确

覆盖每条边的两端。 对任意接受记录 (u,v)，合并结果中恰好增加一个 u 和一个 v。
计数等于度数。 某用户在合并列中每出现一次，就对应一条以该用户为端点的好友边，因此分组计数恰好等于好友数。
最大值选择正确。 降序后的首行拥有所有分组中的最大计数；由唯一性保证，它就是题目要求的唯一用户。

边界与复杂度

  • 发送者和接受者角色不影响好友关系，两列必须同等处理。
  • 日期与计数无关，不必参与分组。
  • 若有 n 条接受记录，中间结果有 2n 行。
  • 概念时间复杂度为 O(n) 聚合，加上挑选最大值；排序实现可能达到 O(k log k)，其中 k 是用户数。
  • 中间聚合空间为 O(k)；数据库的实际执行计划和临时空间依引擎而定。

替代方案与进阶

  • 子查询求 MAX：先形成计数表，再与其最大 num 比较，可返回全部并列者。
  • 窗口函数：用 DENSE_RANK() OVER (ORDER BY num DESC)，筛选排名 1，表达并列最直观。
  • 避免完整排序：部分引擎会优化 ORDER BY ... LIMIT 1；不应只凭 SQL 外观假定执行成本。

SELECT id, COUNT(*) AS num
FROM (
    SELECT requester_id AS id
    FROM RequestAccepted

    UNION ALL

    SELECT accepter_id AS id
    FROM RequestAccepted
) AS endpoints
GROUP BY id
ORDER BY num DESC
LIMIT 1;
import java.util.HashMap;
import java.util.Map;

public class MostFriends {
    // 本地语义参考：返回 [id, num]
    public static int[] mostFriends(int[][] requestAccepted) {
        Map<Integer, Integer> count = new HashMap<>();

        for (int[] row : requestAccepted) {
            count.merge(row[0], 1, Integer::sum);
            count.merge(row[1], 1, Integer::sum);
        }

        int bestId = -1;
        int bestCount = -1;
        for (Map.Entry<Integer, Integer> entry : count.entrySet()) {
            if (entry.getValue() > bestCount) {
                bestId = entry.getKey();
                bestCount = entry.getValue();
            }
        }
        return new int[] {bestId, bestCount};
    }

    public static void main(String[] args) {
        int[][] rows = {{1, 2}, {1, 3}, {2, 3}, {3, 4}};
        int[] result = mostFriends(rows);
        System.out.println(result[0] + " " + result[1]);
    }
}
// 本地语义参考：返回 { id, num }
function mostFriends(requestAccepted) {
  const count = new Map();

  for (const [requesterId, accepterId] of requestAccepted) {
    count.set(requesterId, (count.get(requesterId) ?? 0) + 1);
    count.set(accepterId, (count.get(accepterId) ?? 0) + 1);
  }

  let answer = { id: null, num: -1 };
  for (const [id, num] of count) {
    if (num > answer.num) answer = { id, num };
  }
  return answer;
}

from collections import Counter
from typing import Iterable, Tuple


def most_friends(
    request_accepted: Iterable[Tuple[int, int]],
) -> Tuple[int, int]:
    """本地语义参考：返回 (id, num)。"""
    count: Counter[int] = Counter()

    for requester_id, accepter_id in request_accepted:
        count[requester_id] += 1
        count[accepter_id] += 1

    best_id, best_num = max(count.items(), key=lambda item: item[1])
    return best_id, best_num

#include <iostream>
#include <unordered_map>
#include <utility>
#include <vector>

using namespace std;

// 本地语义参考：返回 {id, num}
pair<int, int> mostFriends(const vector<pair<int, int>>& rows) {
    unordered_map<int, int> count;
    for (const auto& [requesterId, accepterId] : rows) {
        ++count[requesterId];
        ++count[accepterId];
    }

    pair<int, int> answer = {-1, -1};
    for (const auto& [id, num] : count) {
        if (num > answer.second) answer = {id, num};
    }
    return answer;
}

int main() {
    vector<pair<int, int>> rows = {{1, 2}, {1, 3}, {2, 3}, {3, 4}};
    auto [id, num] = mostFriends(rows);
    cout << id << ' ' << num << '\n';
    return 0;
}

面试追问

  • 为什么必须使用 UNION ALL，而不是 UNION？
  • 如果需要返回全部并列第一，怎样避免复制整段聚合逻辑？
  • 数据量极大时，会关注哪些索引、执行计划或分布式聚合问题？
  • 若输入可能出现重复或反向重复的好友边，业务上应在哪一层去重？

常见错误

  • 只统计 requester_id，漏掉作为接受者出现的好友。
  • 用 UNION 去重，导致同一用户的多次有效出现被吞掉。
  • 分别统计两列后没有正确合并同一个用户的两个计数。
  • 按日期分组，错误地把总好友数拆成每日好友数。
  • 进阶并列场景仍使用 LIMIT 1，只返回其中一人。
