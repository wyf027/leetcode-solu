Problem 1196 · Easy

最多可以买到的苹果数量

给每颗苹果一个重量，在固定承重的篮子里，尽可能装下更多苹果。先理解目标，再进入交互实验。

How Many Apples Can You Put into the Basket 函数：maxNumberOfApples

唯一硬限制

5,000

篮中苹果的总重量不能超过 5000。每颗苹果只能选择一次，目标是让数量最大。

01 · 题目

先把问题说清楚

下面是基于官方元数据的准确转述；付费题面未在元数据中返回，因此不复刻原文。

题意

给定整数数组 weight，其中 weight[i] 表示第 i 颗苹果的重量。篮子最多承重 5000。在不超过容量的前提下，返回能放进篮子的苹果的最大数量。

int maxNumberOfApples(int[] weight)

约束

  • 1 <= weight.length <= 1000
  • 1 <= weight[i] <= 1000
  • 篮子容量固定为 5000

示例 1

输入weight = [100, 200, 150, 1000]
输出4
说明四颗苹果总重为 1450，不超过 5000，因此全部可以装入。

示例 2

输入weight = [900, 950, 800, 1000, 700, 800]
输出5
说明可以选择重量为 700、800、800、900、950 的五颗苹果，总重 4150；六颗总重 5150，超过容量。

03 · 深入理解

准备好查看完整题解了吗？

完整思路、证明、四语言代码和面试追问被单独收起。展开后，焦点会进入题解区域，屏幕阅读器也会播报状态。

Solution

排序 + 贪心

为了让苹果数量尽可能多，每一次都优先支付最小的重量成本。

核心洞察

所有苹果带来的“收益”都相同：放入一颗，答案就加一。它们唯一的区别是重量。因此，对同样数量的苹果，选择最轻的那一组一定最省容量。

完整过程

  1. 将 weight 从小到大排序。
  2. 从最轻的苹果开始累加重量。
  3. 若加入后不超过 5000，就计数；否则立即停止。
  4. 返回已经装入的苹果数量。

正确性证明

引理：在所有包含 k 颗苹果的选择中，排序后最轻的前 k 颗具有最小总重量。因为若某个选择包含较重苹果，却遗漏一个更轻苹果，用更轻苹果替换后，数量不变，总重量不会增加。反复交换即可得到最轻的前 k 颗。

结论：算法成功装入前 k 颗，并在第 k + 1 颗处超过 5000。由引理，任何 k + 1 颗苹果的总重量都不会小于最轻的前 k + 1 颗，所以不存在能装入 k + 1 颗的方案。算法返回的 k 因而是最大值。

边界情况

  • 只有一颗苹果：根据约束其重量不超过 1000，必然能装入。
  • 全部苹果总重不超过 5000：返回数组长度。
  • 存在许多相同重量：排序后逐个处理，不影响结论。
  • 加入下一颗恰好达到 5000：仍然合法，应使用 <=。

复杂度

排序是主要开销；线性扫描最多访问每颗苹果一次。

时间 O(n log n) 额外空间 O(log n)～O(n)

空间取决于具体语言的排序实现。

替代方案：计数排序

由于单颗苹果重量最多为 1000，可以统计每个重量的出现次数，再从重量 1 扫到 1000，按容量尽量拿取。时间复杂度为 O(n + W)、空间复杂度为 O(W)，其中 W = 1000。它在理论上更线性，但排序方案更短、更通用，也更容易在面试中说明。

四语言完整代码

import java.util.Arrays;

class Solution {
    public int maxNumberOfApples(int[] weight) {
        Arrays.sort(weight);

        int totalWeight = 0;
        int count = 0;

        for (int appleWeight : weight) {
            if (totalWeight + appleWeight > 5000) {
                break;
            }
            totalWeight += appleWeight;
            count++;
        }

        return count;
    }
}

面试追问

  • 如果容量不是 5000？ 把容量作为参数，算法不变。
  • 为什么不是 0/1 背包？ 每件物品价值都等于 1，按重量选最轻者即可获得最优数量。
  • 能否不修改原数组？ 先复制数组再排序，代价是 O(n) 额外空间。
  • 数据流太大无法完整排序？ 重量上界较小时用频次数组边读边统计。

常见错误

  • 按原顺序装篮，错过后面更轻的苹果。
  • 把目标误解为“总重量最大”，而不是“苹果数量最多”。
  • 判断条件写成 < 5000，漏掉恰好装满的合法情况。
  • 在已排序数组中遇到第一颗放不下时仍继续扫描；后续只会更重。
