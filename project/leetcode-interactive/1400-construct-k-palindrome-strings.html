Construct K Palindrome Strings — 把全部字符分配进恰好 k 个非空回文串。先观察字符，再决定答案。

输入

规模

01 / Problem

题意

给定字符串 s 和整数 k，必须使用 s 中的每一个字符，且每个字符恰好使用一次，构造出恰好 k 个非空回文字符串。

如果存在这样的分配方式，返回 true；否则返回 false。各回文串的顺序与具体构造均不唯一，只需判断能否做到。

准备好核对思路了吗？

题解：只数奇数频次

Core insight

两个边界，夹住答案

设 odd 为出现次数为奇数的字符种类数，n = s.length。

下界：odd ≤ k
每个回文串至多容纳一个奇数频次字符作为中心，所以 odd 个奇数频次至少需要 odd 个回文串。
上界：k ≤ n
每个回文串必须非空，n 个字符不可能装出超过 n 个非空串。

因此：n ≥ k 且 odd ≤ k 时答案为 true。

Process

完整过程

  1. 检查非空限制
    若 n < k，立即返回 false。
  2. 统计 26 个小写字母
    扫描字符串，记录每种字符出现次数。
  3. 统计奇数频次
    计算频次为奇数的字符种类数 odd。
  4. 比较中心需求
    返回 odd ≤ k；前面的 n ≥ k 已保证有足够字符形成 k 个非空串。

正确性证明

必要性：长度为偶数的回文串没有奇数频次字符；长度为奇数的回文串只有中心字符频次为奇数。因此一个回文串至多吸收一种奇数频次，必须有 odd ≤ k。又因每串非空，必须有 k ≤ n。

充分性：先让每种奇数频次字符各占一个回文中心，成对字符对称放置。此时可得到至少 odd 个回文串。若串数不足 k，可继续从剩余字符对中拆出单字符回文串，或按需拆分已有构造；在 k ≤ n 的保证下，总能把数量增加到恰好 k。故两个条件同时满足时一定可行。

边界情况

  • k = 1：需要 odd 不超过 1。
  • k = n：每个字符单独成串，必然可行。
  • k > n：无法保证每串非空。
  • 所有频次为偶数：odd = 0，只需检查 k ≤ n。
  • 所有字符不同：odd = n，仅当 k = n 时可行。

复杂度

时间：O(n)，字符串只需扫描一次。

空间：O(1)，小写字母表固定为 26；若使用通用哈希表，可写作 O(Σ)，Σ 为不同字符数。

Implementations

四种可提交语言

Java

int[26]
class Solution {
    public boolean canConstruct(String s, int k) {
        if (s.length() < k) {
            return false;
        }

        int[] frequency = new int[26];
        for (char ch : s.toCharArray()) {
            frequency[ch - 'a']++;
        }

        int odd = 0;
        for (int count : frequency) {
            odd += count & 1;
        }
        return odd <= k;
    }
}

        return false;
    }

Counter
from collections import Counter


class Solution:
    def canConstruct(self, s: str, k: int) -> bool:
        if len(s) < k:
            return False

        odd = sum(count % 2 for count in Counter(s).values())
        return odd <= k

array<int, 26>
class Solution {
public:
    bool canConstruct(string s, int k) {
        if (static_cast<int>(s.size()) < k) {
            return false;
        }

        array<int, 26> frequency{};
        for (char ch : s) {
            ++frequency[ch - 'a'];
        }

        int odd = 0;
        for (int count : frequency) {
            odd += count & 1;
        }
        return odd <= k;
    }
};

Alternatives

替代方案

位掩码跟踪奇偶性：扫描每个字符时翻转对应二进制位，最终用位计数得到 odd。它同样是 O(n) 时间与 O(1) 空间，但可读性通常不如 26 长度数组。

集合开关：字符第一次出现加入集合，第二次移除，最终集合大小就是 odd。更通用，但固定字母表下常数与表达性不占优势。

真的构造 k 个串：可以实现，但本题只问可行性；维护实际字符串会增加复杂度与出错面。

Interview

面试追问

  • 如果字符集是完整 Unicode，空间复杂度如何表述？
  • 如果必须输出一种具体构造，如何分配中心与字符对？
  • 如果要求每个回文串长度相同，当前判定为何不再充分？
  • 若数据流持续加入字符，怎样 O(1) 更新 odd？
  • 能否用一个 32 位整数的位掩码记录所有奇偶状态？

常见错误

  • 只检查 odd ≤ k，遗漏 k ≤ n 的非空限制。
  • 误以为每个回文串必须恰好有一个奇数频次；偶数长度回文串可以有 0 个。
  • 统计奇数字符的总出现次数，而不是“出现次数为奇数的字符种类数”。
  • 试图枚举字符串分割或排列，导致指数级搜索。
  • 看到 odd = 0 就要求 k 必须为偶数；单字符也能成为回文串，因此这个限制不存在。
