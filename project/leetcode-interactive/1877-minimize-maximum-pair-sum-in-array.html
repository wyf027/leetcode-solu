数组中最大数对和的最小值

Minimize Maximum Pair Sum in Array

把所有数字两两分组。每一组都有一个和，你要让其中最大的那个和尽可能小。

输入：整数数组 nums输出：整数每个元素只用一次

01 / 问题与规则

给定长度为偶数 n 的数组 nums，把它分成 n / 2 个数对。每个数组元素必须恰好出现在一个数对里。一个数对 (a, b) 的和为 a + b；一种划分的分数是所有数对和中的最大值。返回所有合法划分中，能够达到的最小分数。

例如，数对 (1,5)、(2,3)、(4,4) 的和分别是 6、5、8，这种划分的分数为 8。题目求的是这个最大值的最优下限，不要求返回具体数对。

官方示例 1

输入：nums = [3,5,2,3]
输出：7

可分成 (3,3) 和 (5,2)，分数是 max(6,7) = 7。

官方示例 2

输入：nums = [3,5,4,2,4,6]
输出：8

可分成 (3,5)、(4,4)、(6,2)，三个数对和均为 8。

完整约束

  • n == nums.length
  • 2 ≤ n ≤ 105
  • n 为偶数
  • 1 ≤ nums[i] ≤ 105

03 / 准备好拆解了吗？

展开后查看配对实验、推导与四语言实现。

让最小值承接最大值

排序后，把最小的数与最大的数配在一起，再把剩余元素中的最小值与最大值配对，一直向中间收拢。答案是这些数对和中的最大值。

核心洞察：最大的元素必须有搭档。把最小元素留给它，可以通过交换数对实现，而且不会让当前最大数对和变大。

完整过程

  1. 将 nums 按数值升序排序。
  2. 令 L = 0、R = n − 1，最大和 answer = 0。
  3. 当 L < R 时，计算 nums[L] + nums[R]，用它更新 answer 的最大值。
  4. L 加一、R 减一。所有元素被使用一次后，返回 answer。

示例 1 排序后为 [2,3,3,5]：先配 (2,5)，answer = 7；再配 (3,3)，answer 仍为 7。注意 [1,7,7,9] 的外层数对和是 10，内层却是 14，因此必须检查每一对。

正确性 / 交换论证

考虑任意最优配对，设尚未处理的最小元素是 m，最大元素是 M。若它们已经配对，直接保留。否则它们分别属于 (m,x) 与 (y,M)。将这两对换成 (m,M) 与 (x,y)。

  • 因为 m ≤ y，所以 m + M ≤ y + M。
  • 因为 x ≤ M，所以 x + y ≤ M + y。
  • 新产生的两组和都不超过旧数对 (y,M) 的和，因此全局最大和不会上升。

这说明总存在一个最优方案包含 (m,M)。固定它后，对剩余元素重复同样的交换。由归纳可得，两端配对能构造最优方案。循环维护“answer 是所有已完成数对和的最大值”，最终返回值恰好是该最优方案的最大和。

边界与复杂度

  • n = 2：只有一种划分，返回两数之和。重复元素无需去重，它们是不同位置的元素。
  • 所有元素相等：每一组和相同。偶数长度保证最终不会留下单个元素。
  • 数对和最大为 200000，Java / C++ 的 int 足够。输入均为正数，answer 可初始化为 0。
  • 时间：排序 O(n log n)，双指针扫描 O(n)，总计 O(n log n)。
  • 扫描本身额外空间 O(1)。代码会原地排序并改变输入次序；总辅助空间取决于排序实现：C++ std::sort 通常 O(log n) 栈，Python list.sort 最坏 O(n)，Java 与 JavaScript 依实现而定，保守按 O(n) 预算。JavaScript 规范不承诺 sort 的时间、空间复杂度，O(n log n) 分析基于常用高效排序实现。

替代方案

利用值域 U = 100000，可以统计每个数出现的次数，再用值域两端指针消耗计数，仍然配最小与最大；时间 O(n + U)，空间 O(U)。如果左右指针相遇，剩余计数必为偶数，每对和为该值的两倍。排序写法更短，适合常规面试。

穷举所有配对可用于小规模推理，共有 (n − 1)!! 种完整配对，无法满足 n = 105。无需再二分答案，因为贪心已经直接构造最优方案。

常见错误

  • 排序后相邻配对：[1,2,3,4] 会得到最大和 7；两端配对可得到 5。
  • 只返回最小值与最大值的和：可能漏掉更大的中间数对和。
  • JavaScript 直接 sort()：默认按字符串排序，必须传入 (a,b) => a-b。
  • 把答案更新为最小数对和：目标是先对每种划分取最大值，再在划分之间最小化。
  • 去掉重复值或重复使用端点：每个原始位置必须恰好使用一次。

面试追问

  • 如果需要返回具体数对？每轮保存两端的值；需要原下标则排序 (值, 原下标) 记录。
  • 如果不允许修改输入？先复制数组再排序，额外增加 O(n) 存储。
  • 若允许负数？交换证明仍成立，但答案应初始化为负无穷或第一组数对和。
  • 每组改成三个数还能沿用吗？不能直接推广；这里的交换证明依赖每组恰好两个元素。

四语言完整提交代码

均使用官方 minPairSum 签名与排序双指针方案；会修改 nums 的排列。以下代码未运行，待补验证。

Java
import java.util.Arrays;

class Solution {
    public int minPairSum(int[] nums) {
        Arrays.sort(nums);
        int left = 0, right = nums.length - 1;
        int answer = 0;
        while (left < right) {
            answer = Math.max(answer, nums[left] + nums[right]);
            left++;
            right--;
        }
        return answer;
    }
}

class Solution:

        left, right = 0, len(nums) - 1
