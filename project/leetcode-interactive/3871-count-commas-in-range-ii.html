3871. 统计范围内的逗号 II

不用逐个格式化整数。把每一枚逗号看成一个“跨过 103k 门槛”的贡献；点击阈值，观察总数如何叠加。

主线：按逗号位的阈值累加贡献

题意

给定 n，把 1 到 n 的每个整数按标准千分位格式书写：从右起每三位插入一个逗号。返回一共出现了多少枚逗号。

官方示例

n = 1002，输出 3："1,000"、"1,001"、"1,002" 各贡献一枚逗号。
n = 998，输出 0。约束：1 <= n <= 1015。

逗号门槛

10³第 1 枚逗号
10⁶第 2 枚逗号
10⁹第 3 枚逗号

交互：累计各层门槛

当前总逗号数
3

只有第 1 层生效：1002 − 1000 + 1 = 3。

答案 = Σk≥1 max(0, n − 103k + 1)

完整过程：每层只数一次

第 k 枚逗号会出现在所有不小于 10^(3k) 的数中，因此这一层贡献 max(0, n - 10^(3k) + 1)。把有限的五层（10³ 至 10¹⁵）相加即可。

层 k 门槛 当 n = 1002 时的贡献

题解

默认折叠，避免首屏直接展示解法。

核心洞察

不要按“某个数有几枚逗号”逐个枚举。改为反向统计：第 k 个逗号只要数字到达 10^(3k) 就必定出现，故可独立计算其覆盖区间。

完整过程

  1. 令 threshold = 1000、answer = 0。
  2. 只要 threshold <= n，加入 n - threshold + 1。
  3. 令 threshold *= 1000，处理下一枚逗号。
  4. 用 64 位整数保存答案与门槛。
时间复杂度
O(log₁₀ n)，本题最多 5 次循环
空间复杂度
O(1)

边界、替代方案与常见错误

检查 n = 998、999、1000 与 10¹⁵。枚举 1..n 会超时；把门槛写成 threshold < n 会漏掉恰等于门槛的数；32 位整型会溢出。

面试追问

若分组宽度改为 d 位，只需把倍率 1000 换为 10d；若需要任意区间 [L, R]，答案为 count(R) - count(L - 1)。

可提交代码

class Solution {
    public long countCommas(long n) {
        long answer = 0, threshold = 1_000L;
        while (threshold <= n) {
            answer += n - threshold + 1;
            threshold *= 1_000L;
        }
        return answer;
    }
}
