在圆内
随机生成点

一张圆形画布，一次看似简单的随机抽样。真正的挑战不是“落在圆里”，而是让圆内每一小块面积拥有完全相同的被选中机会。

非会员题 系统设计型接口 最多 30,000 次调用
UNIFORM
AREA (x₀, y₀)
radius = r
01 · Problem

题目说明

先理解接口与“均匀”的含义。随机题的单次坐标不唯一，评测关注大量调用后的统计分布。

给定一个圆的半径与圆心坐标，请实现 Solution 类，使 randPoint() 能在这个圆的内部均匀随机地产生一个点。圆周上的点也属于圆内。

返回值为双精度数组 [x, y]。这里“均匀”是指：圆内任意两个面积相同的区域，被采样到的概率相同。

  • Solution(double radius, double x_center, double y_center)
    使用半径与圆心初始化对象。
  • double[] randPoint()
    返回圆内一个随机点的坐标。

约束

  • 0 < radius ≤ 10⁸
  • −10⁷ ≤ x_center, y_center ≤ 10⁷
  • randPoint 最多被调用 3 × 10⁴ 次
  • 圆周上的点被视为圆内点
关键语义：要求按面积均匀，不是让到圆心的距离均匀。

官方示例

Example 1 
输入
["Solution", "randPoint", "randPoint", "randPoint"]
[[1.0, 0.0, 0.0], [], [], []]

输出
[null, [-0.02493, -0.38077], [0.82314, 0.38945], [0.36572, 0.17248]]

解释
Solution solution = new Solution(1.0, 0.0, 0.0);
solution.randPoint(); // 可能返回 [-0.02493, -0.38077]
solution.randPoint(); // 可能返回 [0.82314, 0.38945]
solution.randPoint(); // 可能返回 [0.36572, 0.17248]
输出只是一次可能的随机结果；合法实现无需复现这些精确坐标。

03 · Editorial

准备好揭开面积均匀的秘密了吗？

题解默认收起，包含推导、证明、四语言代码与面试追问。

Core insight

核心洞察：半径必须开平方

√

极坐标里，角度可以直接均匀选择，但半径不能直接在 [0, R] 均匀选择。半径为 r 的圆盘面积与 r² 成正比；要让累计概率等于累计面积，应该令 ρ = R√V。

P(ρ ≤ r) = P(V ≤ r² / R²) = r² / R² = Area(r) / Area(R)

完整过程

  1. 独立生成两个服从 [0, 1) 均匀分布的随机数 U 与 V。
  2. 令角度 θ = 2πU，这样方向在整圈上均匀。
  3. 令到圆心的距离 ρ = R√V，这样半径不超过任意 r 的概率，正好等于半径 r 圆盘的面积占比。
  4. 把极坐标转成笛卡尔坐标并加上圆心偏移：x = x₀ + ρ cos θ，y = y₀ + ρ sin θ。
θ = 2πU　　ρ = R√V　　(x, y) = (x₀ + ρcosθ, y₀ + ρsinθ)

为什么不是 ρ = RV？

若半径本身均匀，半径区间宽度相同的同心环会获得相同概率。但外环面积远大于内环面积，于是单位面积上的点会越靠近圆心越密，形成明显偏差。

正确性证明

引理 1 · 方向均匀

U 在 [0,1) 均匀，线性映射 θ=2πU 使 θ 在 [0,2π) 均匀。

引理 2 · 面积累计正确

对任意 0≤r≤R，有 P(ρ≤r)=P(V≤r²/R²)=r²/R²，等于对应圆盘面积占比。

结论 · 圆盘均匀

角度与半径由独立随机数产生；任意扇形圆环的概率等于其角度占比乘面积占比，因此等于该区域的面积占比。

边界与数值细节

  • 极小或极大半径：双精度浮点足以覆盖题目给定范围；计算仍保持常数步数。
  • 圆心不在原点：先在原点圆内采样，最后统一加上 (x₀,y₀)，不会改变均匀性。
  • 圆心与圆周：V=0 时得到圆心；若随机源能取到 1，也可能得到圆周点，二者都合法。
  • 随机独立性：每次调用都要重新生成两个随机数；不要复用上次角度或半径。

复杂度

O(1)每次 randPoint 的时间复杂度
O(1)对象占用的额外空间

四语言完整实现

import java.util.Random;

class Solution {
    private final double radius;
    private final double xCenter;
    private final double yCenter;
    private final Random random;

    public Solution(double radius, double x_center, double y_center) {
        this.radius = radius;
        this.xCenter = x_center;
        this.yCenter = y_center;
        this.random = new Random();
    }

    public double[] randPoint() {
        double theta = 2.0 * Math.PI * random.nextDouble();
        double distance = radius * Math.sqrt(random.nextDouble());

        double x = xCenter + distance * Math.cos(theta);
        double y = yCenter + distance * Math.sin(theta);
        return new double[] {x, y};
    }
}

替代方案：拒绝采样

极坐标逆变换

每次固定生成两个随机数，直接得到答案。数学推导清晰，时间严格为常数，通常是本题最简洁的方案。

正方形内拒绝采样

在包围圆的正方形内均匀选点，若落在圆外就重试。它同样正确，单轮接受概率为 π/4，期望尝试次数为 4/π，但最坏尝试次数没有确定上界。

面试追问

如果扩展到三维球体，距离应该怎么取？

球体体积与半径的三次方成正比，因此距离应取 R·∛V；方向则需要在球面上均匀生成。

如何验证“均匀”，而不是只验证“在圆内”？

把圆盘切成若干等面积区域，采样大量点后比较频数；可进一步使用卡方检验。单点断言无法证明统计均匀性。

拒绝采样为什么不会引入偏差？

正方形内每个位置密度一致；条件化到“点位于圆内”这一事件后，圆内各位置的相对密度仍然一致。

常见错误

  • 直接写 distance = radius * random()，导致点向圆心聚集。
  • 分别在 [−R,R] 生成 x、y，却不拒绝圆外点，返回了正方形分布。
  • 忘记加圆心偏移，只能处理圆心为原点的情况。
  • 用角度制调用 sin/cos；主流语言的三角函数参数均为弧度。
  • 为“随机”测试硬编码某组坐标；正确测试应验证边界与统计性质。
