会议室

把会议按开始时间排好后，只需比较每对相邻会议：下一场是否在上一场结束之前开始？

题意

给定会议时间数组 intervals，其中 intervals[i] = [startᵢ, endᵢ]。若一个人能参加全部会议则返回 true，否则返回 false。在时间 t 结束、在时间 t 开始的两场会议不重叠。

官方样例 1

intervals = [[0,30], [5,10], [15,20]]

输出：false

官方样例 2

intervals = [[7,10], [2,4]]

输出：true

约束：0 ≤ intervals.length ≤ 10⁴，每项有两个数，0 ≤ startᵢ < endᵢ ≤ 10⁶。

为什么只比较相邻项

  1. 1. 先按开始时间升序排序。
  2. 2. 如果第 i 场的结束时间不晚于第 i+1 场开始时间，则这一对可兼容。
  3. 3. 如果有任意重叠，必会在排序后某一对相邻会议处首次出现。

题解

首屏默认隐藏，按按钮查看完整解法。

主线：排序 + 相邻冲突检查

排序之后，若存在重叠，按开始时间最早的重叠右端会议必与它的前一场产生重叠。因此只需检查 intervals[i][0] < intervals[i−1][1]。严格小于才是冲突，等于表示无缝衔接，可以参加。

排序主导时间复杂度：O(n log n)。扫描只需 O(n)，除排序外使用 O(1) 额外空间（具体取决于语言排序实现）。

完整过程：样例 1

  1. 1. 排序后仍为 [0,30], [5,10], [15,20]。
  2. 2. 检查 5 是否小于前一场结束 30：是，时间 [5,10] 落在 [0,30] 内。
  3. 3. 已发现一处冲突，立即返回 false；无需检查后续会议。

边界

空数组和单场会议可参加；[0,8] 与 [8,10] 不重叠；输入无序必须先排序。

替代方案

用事件扫描线也能检查峰值是否超过 1，但对仅判断能否参加全部会议而言，排序相邻比较更直接。

常见错误

把条件写成 start ≤ previousEnd 会把相接会议误判冲突；比较未排序的原数组也会漏掉冲突。

面试追问

若问最少需要几间会议室，问题升级为第 253 题，需要小顶堆或双指针追踪同时进行的会议数。 

import java.util.*;

class Solution {
    public boolean canAttendMeetings(int[][] intervals) {
        Arrays.sort(intervals, Comparator.comparingInt(a -> a[0]));
        for (int i = 1; i < intervals.length; i++) {
            if (intervals[i][0] < intervals[i - 1][1]) return false;
        }
        return true;
    }
}

class Solution:
    def canAttendMeetings(self, intervals: List[List[int]]) -> bool:
        intervals.sort(key=lambda meeting: meeting[0])
        return all(intervals[i - 1][1] <= intervals[i][0]
                   for i in range(1, len(intervals)))
