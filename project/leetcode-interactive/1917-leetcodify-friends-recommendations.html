相同的音乐品味，是否足以成为新的朋友？先观察数据，再展开底部题解。

题意与数据契约

找出不同用户之间可以新增的好友推荐：两人尚非好友，且存在某一天，他们各自听过的歌曲中有至少三首不同的共同歌曲。每组符合条件的用户都需输出两个推荐方向，同一方向只能出现一次；结果顺序不限。

Listens(user_id INT, song_id INT, day DATE)
Friendship(user1_id INT, user2_id INT)
输出：(user_id, recommended_id)
  • Listens 无主键，允许重复播放记录。
  • Friendship 的联合主键是 (user1_id, user2_id)，且 user1_id < user2_id；好友关系本身是双向的。
  • 共同歌曲必须属于同一天；自己不能推荐给自己。
  • 公开题面未提供行数或 ID 数值范围，不另行虚构上限。

题意为摘要转述；示例来自本地官方元数据。结构约束补充来源：公开题面存档 · 官方题目。

题解 · 先按天判断，再按用户去重

核心洞察与完整过程

  1. 自连接 Listens，只匹配日期和歌曲相同的记录。限定 a.user_id < b.user_id，每对只计算一次，并排除自身。
  2. 按两个用户和日期分组，以 COUNT(DISTINCT song_id) 判断共同的不同歌曲数是否至少为 3。
  3. 以规范化的小 ID、大 ID 查 Friendship，NOT EXISTS 排除已有好友。
  4. 去掉日期并去重；把每一对展开为两个方向，使用 UNION 合并。

正确性

自连接得到的每条匹配恰好代表两位用户同一天共同听过某首歌曲。分组保留同一天的证据，DISTINCT 让重复播放不影响歌曲数。因此阈值筛选恰好留下存在达标日期的用户对。规范化 ID 与好友表的存储顺序一致，反连接恰好删除已有好友。最后双向展开覆盖全部所需方向，集合去重消除多日达标的重复，故结果既无多余推荐，也无遗漏。

边界与常见错误

  • 不按日期分组会把跨天歌曲累加，导致误报。
  • COUNT(*) 会受重复播放及连接放大影响；必须对歌曲去重。
  • 推荐判定对称，但输出需要两行，不能只返回小 ID → 大 ID。
  • 仅按日去重仍会产生跨日重复；最终必须去除日期并去重。
  • 空表、只有一个用户、全部已是好友时，输出为空。

复杂度

设 N 为播放行数、F 为好友行数、J 为自连接匹配规模、P 为达标用户对数。SQL 执行计划取决于数据库：J 最坏为 O(N²)，排序聚合可达 O(J log J)，中间存储可达 O(J+F+P)；这不是数据库无条件保证。无索引的好友查找还可能产生 O(PF) 成本。可考虑 Listens(day,song_id,user_id) 与好友联合主键索引。

四语言参考先建立每日用户歌曲集合。设第 d 天有 U_d 个用户、每人最多 S_d 首歌；哈希集合实现期望时间 O(N+F+Σ U_d²S_d)，空间 O(N+F+P)。Python 的交集额外临时占用至多 O(S_d)。C++ 使用有序 map/set，构建和查询另带对数因子，配对歌曲查找为 O(Σ U_d²S_d log(S_d+1))，好友查询另计 O(Σ U_d² log(F+1))。

替代方案与面试追问

可先 SELECT DISTINCT user_id,song_id,day 减少重复记录，再连接并 COUNT(*)；也可按“日期、歌曲”建立用户倒排表，累计用户对的共同歌曲数。热门歌曲仍可能生成平方级配对。追问：为什么不能跨日累计？如何处理百万用户的热门歌曲？如何增量更新当天计数，同时对重复播放保持幂等？

SQL · MySQL 8 可提交

WITH pairs AS (
  SELECT a.user_id AS u, b.user_id AS v
  FROM Listens a
  JOIN Listens b ON a.day = b.day AND a.song_id = b.song_id
               AND a.user_id < b.user_id
  GROUP BY a.user_id, b.user_id, a.day
  HAVING COUNT(DISTINCT a.song_id) >= 3
), eligible AS (
  SELECT DISTINCT p.u, p.v
  FROM pairs p
  WHERE NOT EXISTS (
    SELECT 1 FROM Friendship f
    WHERE f.user1_id = p.u AND f.user2_id = p.v
  )
)
SELECT u AS user_id, v AS recommended_id FROM eligible
UNION
SELECT v AS user_id, u AS recommended_id FROM eligible;

// listens: [user_id, song_id, day][]; friendship: [user1_id, user2_id][]
function recommendFriends(listens, friendship) {
  const days = new Map(), result = new Map();
  const friends = new Set(friendship.map(([u,v]) => JSON.stringify([u,v])));
  for (const [u,s,d] of listens) {
    if (!days.has(d)) days.set(d, new Map());
    const users = days.get(d);
    if (!users.has(u)) users.set(u, new Set());
    users.get(u).add(s);
  }
  for (const users of days.values()) {
    const ids = [...users.keys()].sort((a,b) => a-b);
    for (let i=0; i<ids.length; i++) for (let j=i+1; j<ids.length; j++) {
      const u=ids[i], v=ids[j];
      if (friends.has(JSON.stringify([u,v]))) continue;
      let common=0;
      for (const s of users.get(u)) if (users.get(v).has(s)) common++;
      if (common>=3) for (const pair of [[u,v],[v,u]])
        result.set(JSON.stringify(pair), pair);
    }
  }
  return [...result.values()];
}

def recommend_friends(listens, friendship):
    # Rows: (user_id, song_id, ISO day); friendship: (smaller, larger)
    days, answer = {}, set()
    friends = set(map(tuple, friendship))
    for u, song, day in listens:
        days.setdefault(day, {}).setdefault(u, set()).add(song)
    for users in days.values():
        ids = sorted(users)
        for i, u in enumerate(ids):
            for v in ids[i + 1:]:
                if (u, v) not in friends and len(users[u] & users[v]) >= 3:
                    answer.add((u, v))
                    answer.add((v, u))
    return sorted(answer)

Java · 本地语义参考

import java.util.*;

public class Solution {
    public record Listen(int user, int song, String day) {}
    public record Pair(int user, int recommended) {}
    public static List<Pair> recommendFriends(List<Listen> listens,
                                               List<Pair> friendship) {
        Map<String, Map<Integer, Set<Integer>>> days = new HashMap<>();
        Set<Pair> friends = new HashSet<>(friendship);
        Set<Pair> answer = new HashSet<>();
        for (Listen row : listens)
            days.computeIfAbsent(row.day(), k -> new HashMap<>())
                .computeIfAbsent(row.user(), k -> new HashSet<>()).add(row.song());
        for (Map<Integer, Set<Integer>> users : days.values()) {
            List<Integer> ids = new ArrayList<>(users.keySet());
            Collections.sort(ids);
            for (int i=0; i<ids.size(); i++) for (int j=i+1; j<ids.size(); j++) {
                int u=ids.get(i), v=ids.get(j), common=0;
                if (friends.contains(new Pair(u,v))) continue;
                for (int song : users.get(u)) if (users.get(v).contains(song)) common++;
                if (common>=3) { answer.add(new Pair(u,v)); answer.add(new Pair(v,u)); }
            }
        }
        return new ArrayList<>(answer);
    }
} // Java 17+；Friendship 中 Pair 的两项按较小 ID、较大 ID 传入。

#include <map>
#include <set>
#include <string>
#include <tuple>
#include <vector>
#include <utility>
using namespace std;

vector<pair<int,int>> recommendFriends(
    const vector<tuple<int,int,string>>& listens,
    const vector<pair<int,int>>& friendship) {
    map<string, map<int, set<int>>> days;
    set<pair<int,int>> friends(friendship.begin(), friendship.end()), answer;
    for (const auto& [u,s,d] : listens) days[d][u].insert(s);
    for (const auto& [day,users] : days) {
        for (auto a=users.begin(); a!=users.end(); ++a) {
            auto b=a; ++b;
            for (; b!=users.end(); ++b) {
                int u=a->first, v=b->first, common=0;
                if (friends.count({u,v})) continue;
                for (int s : a->second) common += b->second.count(s);
                if (common>=3) { answer.insert({u,v}); answer.insert({v,u}); }
            }
        }
    }
    return vector<pair<int,int>>(answer.begin(), answer.end());
} // C++17；输入好友对满足 first < second。
