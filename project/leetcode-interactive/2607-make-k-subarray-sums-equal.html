Problem

题目描述

给定下标从 0 开始的整数数组 arr 和整数 k。arr 是循环数组：末尾之后回到开头，开头之前连接末尾。

一次操作可以选择任意元素，将它增加 1 或减少 1。请返回使所有长度恰好为 k 的循环子数组元素和都相等所需的最少操作次数。

函数签名：makeSubKSumEqual(arr, k)，返回 64 位整数语义的最少操作数。

示例 1

输入：arr = [1,4,1,3], k = 2
输出：1

将下标 1 的值从 4 减为 3，得到 [1,3,1,3]。四个长度为 2 的循环子数组之和都为 4。

示例 2

输入：arr = [2,5,5,7], k = 3
输出：5

把下标 0 的 2 增为 5（3 次），把下标 3 的 7 减为 5（2 次），得到 [5,5,5,5]，每个窗口和均为 15。

约束

  • 1 <= k <= arr.length <= 105
  • 1 <= arr[i] <= 109

Full Solution

最大公约数分组 + 中位数

核心洞察

令 Sᵢ 表示从下标 i 开始、长度为 k 的循环窗口和。相邻两个窗口只交换一个离开元素和一个进入元素：

Sᵢ = Sᵢ₊₁ ⇔ arr[i] = arr[(i + k) mod n]

因此，所有窗口和相等，当且仅当沿着“下标每次增加 k（模 n）”能够互达的位置最终取相同值。这些位置恰好形成 gcd(n, k) 个互不相交的组；等价地，它们按下标模 g = gcd(n,k) 分组。

每组必须改成同一个数，而把若干整数改成同一个数时，绝对差之和在中位数处最小。各组互不影响，分别取中位数并累加代价即可。

完整过程

  1. 计算 g = gcd(n, k)。
  2. 对每个 start ∈ [0, g)，收集 arr[start], arr[start+g], ...。这正是一条由步长 k 生成的循环等价类。
  3. 排序当前组，选择中位数 median。
  4. 把组内所有 |value - median| 加入答案。
  5. 返回所有组的代价总和。

正确性证明

引理 1：窗口和全部相等，当且仅当 arr[i] = arr[(i+k) mod n] 对每个 i 成立。

窗口从 i 向前滑一格时，删去 arr[i]，加入 arr[(i+k) mod n]，所以 Sᵢ₊₁ - Sᵢ = arr[(i+k) mod n] - arr[i]。差为零与这两个元素相等完全等价。对所有 i 应用即可。

引理 2：上述相等关系把下标划分为 gcd(n,k) 个组。

反复执行 i → (i+k) mod n 只会到达与 i 模 gcd(n,k) 同余的位置，并会遍历该同余类的全部下标。因此同一组内必须相等，不同组之间没有相等约束。

引理 3：一组数改成同一个整数的最小代价由中位数取得。

目标值每向右移动 1，左侧元素贡献增加、右侧元素贡献减少；在中位数位置两侧数量达到平衡，所以绝对差之和最小。偶数长度时两个中位数之间任一整数都同样最优。

定理

算法对每个必要且独立的等价类选择最优中位数，因此每组代价最小；组间操作不重叠，代价可直接相加。由引理 1，所得数组满足所有窗口和相等；由各组最优性，答案也是全局最小。

复杂度

  • 时间：排序所有组，总计 O(n log n)；更精确地说是各组排序复杂度之和。
  • 空间：当前实现保存分组数据，最坏 O(n)。
  • 答案可能达到约 10¹⁴，Java/C++ 必须使用 64 位整数；JavaScript 的安全整数范围足够覆盖本题约束。

边界情况

  • k = n：g = n，每组只有一个元素，答案为 0。
  • k = 1：只有一个组，所有元素必须相等，直接取全数组中位数。
  • 组长为偶数：选择上中位数或下中位数都能得到同一最小代价。
  • 已有重复值或整组相等：对应差值自然为 0，无需特殊分支。

Java

Java · 官方签名long
import java.util.*;

class Solution {
    public long makeSubKSumEqual(int[] arr, int k) {
        int n = arr.length;
        int g = gcd(n, k);
        long answer = 0;

        for (int start = 0; start < g; start++) {
            List<Integer> group = new ArrayList<>();
            for (int i = start; i < n; i += g) {
                group.add(arr[i]);
            }
            Collections.sort(group);
            int median = group.get(group.size() / 2);
            for (int value : group) {
                answer += Math.abs((long) value - median);
            }
        }
        return answer;
    }

    private int gcd(int a, int b) {
        while (b != 0) {
            int remainder = a % b;
            a = b;
            b = remainder;
        }
        return a;
    }
}

JavaScript

JavaScript · 官方签名Number
/**
 * @param {number[]} arr
 * @param {number} k
 * @return {number}
 */
var makeSubKSumEqual = function(arr, k) {
    const gcd = (a, b) => {
        while (b !== 0) [a, b] = [b, a % b];
        return a;
    };

    const g = gcd(arr.length, k);
    let answer = 0;

    for (let start = 0; start < g; start++) {
        const group = [];
        for (let i = start; i < arr.length; i += g) {
            group.push(arr[i]);
        }
        group.sort((a, b) => a - b);
        const median = group[Math.floor(group.length / 2)];
        for (const value of group) answer += Math.abs(value - median);
    }
    return answer;
};

Python

Python 3 · 官方签名int
from math import gcd
from typing import List


class Solution:
    def makeSubKSumEqual(self, arr: List[int], k: int) -> int:
        g = gcd(len(arr), k)
        answer = 0

        for start in range(g):
            group = sorted(arr[start::g])
            median = group[len(group) // 2]
            answer += sum(abs(value - median) for value in group)

        return answer

C++

C++ · 官方签名long long
class Solution {
public:
    long long makeSubKSumEqual(vector<int>& arr, int k) {
        int n = arr.size();
        int g = gcd(n, k);
        long long answer = 0;

        for (int start = 0; start < g; ++start) {
            vector<int> group;
            for (int i = start; i < n; i += g) {
                group.push_back(arr[i]);
            }
            sort(group.begin(), group.end());
            int median = group[group.size() / 2];
            for (int value : group) {
                answer += abs(static_cast<long long>(value) - median);
            }
        }
        return answer;
    }
};

替代方案

可以用快速选择而非完整排序来找每组中位数，把期望时间降到 O(n)；但实现更复杂，最坏时间也需要额外保证。本题 n ≤ 10⁵，排序更直接可靠。也可以显式按 +k mod n 访问每个环，但按模 g 收集更短、更不易重复访问。

面试追问

  • 为什么不是让整个数组都相等？ 因为只要求相隔 k 的位置相等；当 gcd(n,k) > 1 时存在多个独立组。
  • 若单次增加和减少的成本不同呢？ 目标值不再是普通中位数，可转化为带方向权重的分段线性最优化。
  • 能否做到线性时间？ 可对每组使用线性选择算法找到中位数，但工程上通常不如排序简洁。
  • 为什么滑窗等式是充分条件？ 若每对相邻窗口的差都为 0，循环上的所有窗口和沿链相等。

常见错误

  • 误按 k 分组，而不是按 gcd(n,k) 分组。
  • 只比较不循环的窗口，漏掉跨越数组末尾的窗口。
  • 用平均数作为目标；绝对差之和应取中位数，平方差才对应平均数。
  • Java/C++ 用 32 位整数累计答案而溢出。
  • JavaScript 忘记给 sort 传数值比较器，导致按字符串顺序排序。
