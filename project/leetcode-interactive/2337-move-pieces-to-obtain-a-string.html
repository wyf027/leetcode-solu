Move Pieces to Obtain a String

一条轨道，两种方向。
只与相邻空位交换，能抵达目标排列吗？

移动规则

← L　只向左

R →　只向右

_　可用空位

先操作轨道，再展开底部题解。索引从 0 开始。

01 / 题目与约束

给定等长字符串 start 与 target。L 和 R 是棋子，_ 是空位。每次操作可以把 L 与它左侧紧邻的空位交换，或把 R 与它右侧紧邻的空位交换。棋子不能跳跃。判断经过任意次操作（包括 0 次）能否从 start 得到 target，返回布尔值。

  • n == start.length == target.length
  • 1 ≤ n ≤ 10⁵
  • 两个字符串只包含 'L'、'R'、'_'。

接口：canChange(start: string, target: string) → boolean。题意、示例及约束依据本批次官方元数据转述。官方题目 ↗

示例 1

start = "_L__R__R_"
target = "L______RR"
输出：true

先将 L 左移一格，再将最右 R 右移一格，最后将另一个 R 连续右移三格，即可得到目标。

示例 2

start = "R_L_"
target = "__LR"
输出：false

唯一能做的第一步得到 _RL_；随后两枚棋子都无法移动。

示例 3

start = "_R"
target = "R_"
输出：false

R 不能向左移动，无法到达目标。

04 / 推导与实现

准备好后，展开条件、证明和四语言代码。

不追踪空位，匹配棋子

删除空位后，棋子序列必须相同；对应的 L 只能抵达更小或相等的索引，对应的 R 只能抵达更大或相等的索引。这三个条件合起来既必要又充分。

核心洞察

棋子只能与空位交换，因此任意两枚棋子都不能越过对方。从左到右的第 k 枚棋子必须对应目标的第 k 枚棋子。设起点索引为 i、目标索引为 j：L 要求 i ≥ j，R 要求 i ≤ j。我们无需真的删除字符，只要双指针跳过空位即可。

完整过程

  1. 令 i = j = 0，分别扫描 start 和 target。
  2. 两端分别跳过连续的 _。
  3. 若任意一端到达结尾，只有两端同时到达结尾才返回 true。
  4. 比较当前棋子；类型不同立即返回 false。
  5. 若是 L 且 i < j，或是 R 且 i > j，说明需要逆向移动，返回 false。
  6. 当前配对合法，两个指针各前进一步，继续扫描。

正确性证明

必要性：合法操作不会改变非空棋子的相对次序和数量；L 的索引只能减小，R 的索引只能增大。因此每个可达目标都满足以上配对条件，算法不会拒绝可达目标。

充分性：假设所有配对条件成立。先按从左到右的顺序把所有 L 移到各自目标。当前 L 左侧较早的 L 已就位，目标索引严格小于当前 L 的目标，不会挡住路径。左侧任意 R 的原索引不大于它自己的目标索引，且它的目标又在当前 L 目标的左边，因此它也不在移动区间内。于是每个 L 都能向左移到位。

然后按从右到左的顺序移动 R。右侧的 R 已在更右的目标位置；右侧的 L 也已在更右的目标位置。因此当前 R 到自己目标的区间为空，可以向右移动到位。这样构造出了完整合法过程，故条件充分。算法逐个检查所有配对并检查同时结束，返回 true 当且仅当目标可达。

边界与复杂度

  • 全空位时，双指针都到达 n，返回 true。
  • 数量不同时，一端提前结束；即使前面配对都相同也必须返回 false。
  • 相同字符串允许 0 次操作，索引相等合法。
  • 没有空位时，只有原排列本身可达。
  • 时间 O(n)：两个指针都只向前扫描一次。辅助空间 O(1)：不构造过滤字符串或位置数组。C++ 官方签名按值传入字符串可能产生输入副本，此处辅助空间不计参数副本。

替代方案

可以先生成两组 (字符, 原索引) 列表再逐项检查，思路更直观，时间 O(n)，辅助空间 O(n)。广度优先搜索能枚举合法移动并找到最短路径，但状态数随 n 急剧增长，只适合极短字符串；逐格构造移动也可能输出 Θ(n²) 次交换，本题仅判断可达性，不需要支付这个代价。

常见错误

  • 仅比较去空位后的字符串：忽略方向，例如 _R → R_。
  • 只比较 L/R 数量：忽略相对顺序，例如 R_L_ → __LR。
  • 把 L 和 R 的不等号写反，或把相等误判为非法。
  • 访问字符前没检查指针是否已到末尾。
  • 一端扫描完成就返回 true，没有处理另一端剩余棋子。

面试追问

  • 若要求最少交换次数？可达时为所有对应棋子的 Σ|i − j|。每步只移动一枚棋子一格，所有棋子方向固定，构造过程恰好达到这个下界；Java/C++ 求和应使用 64 位整数。
  • 如何输出一条路径？使用证明中的顺序：L 从左到右就位，再让 R 从右到左就位。输出成本至少与交换次数相同。
  • 若 L 和 R 都能双向移动？方向条件消失，但顺序仍不可改变；非空棋子序列相同即可。

Java

class Solution {
    public boolean canChange(String start, String target) {
        int n = start.length(), i = 0, j = 0;
        while (true) {
            while (i < n && start.charAt(i) == '_') i++;
            while (j < n && target.charAt(j) == '_') j++;
            if (i == n || j == n) return i == n && j == n;
            char c = start.charAt(i);
            if (c != target.charAt(j)) return false;
            if (c == 'L' && i < j) return false;
            if (c == 'R' && i > j) return false;
            i++;
            j++;
        }
    }
}

        if (c === 'L' && i < j) return false;
        if (c === 'R' && i > j) return false;
        i++;
        j++;
    }
};
