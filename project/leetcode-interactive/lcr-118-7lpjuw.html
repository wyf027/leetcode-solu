LCR 118·MEDIUM·并查集

冗余连接

无向图本应是一棵树；现在多了一条边。按输入顺序逐条合并节点，第一条把同一连通分量再次连起来的边，就是答案。

查看合并过程

题意

给定无向图的边集 edges。图原先是一棵含 n 个节点的树，额外添加一条边后形成环。找出可以删除的那条边；若有多个候选，返回输入中最后出现的。

约束

  • • edges.length = n。
  • • 节点编号在 [1, n] 范围内。
  • • 仅存在一个由额外边引入的环。

示例

[[1,2],[1,3],[2,3]]

[2,3]

[[1,2],[2,3],[3,4],[1,4]]

[1,4]

[[1,2],[2,3]]

没有环的树

分步交互：并查集合并

输入边列表，例如 1-2,1-3,2-3。每次处理一条边，查看根节点是否相同。

核心洞察

并查集维护已经连通的组件。处理边 (u, v) 前，如果 find(u) == find(v)，说明两端已有路径相连，再加入这条边必成环；否则把两个根合并。

完整过程

  1. 1. 初始化每个节点的父节点为自己。
  2. 2. 顺序枚举每条边，查找两个端点的根。
  3. 3. 根相同：直接返回当前边。
  4. 4. 根不同：合并两棵集合树，并继续扫描。

边界

  • • 节点从 1 编号，因此父数组可开到 n + 1。
  • • 自环与平行边也会因两端同根被识别。
  • • 需要按原输入顺序扫描，不能先排序边。

复杂度

路径压缩后，时间为 O(n α(n))，其中 α 极慢增长；空间为 O(n)。

替代方案

DFS 可在加入每条边前搜索是否已有路径，但反复搜索会达到 O(n²)。

追问与常见错误

追问

若图变为有向图，节点可能有两个父节点，需要额外处理入度冲突。

常见错误

每轮重建并查集会破坏顺序语义；未做路径压缩则在大数据下性能变差。

// Java
class Solution {
  public int[] findRedundantConnection(int[][] edges) {
    int[] p = new int[edges.length + 1];
    for (int i=1;i<p.length;i++) p[i]=i;
    for (int[] e: edges) { int a=find(p,e[0]), b=find(p,e[1]);
      if (a==b) return e; p[a]=b;
    } return new int[0];
  }
  int find(int[] p,int x){ return p[x]==x ? x : (p[x]=find(p,p[x])); }
}

# Python
class Solution:
    def findRedundantConnection(self, edges: List[List[int]]) -> List[int]:
        parent=list(range(len(edges)+1))
        def find(x):
            if parent[x]!=x: parent[x]=find(parent[x])
            return parent[x]
        for a,b in edges:
            x,y=find(a),find(b)
            if x==y: return [a,b]
            parent[x]=y
