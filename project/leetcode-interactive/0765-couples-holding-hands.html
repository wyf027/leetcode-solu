Couples Holding Hands

情侣牵手

一排座位、成对编号、任意交换。目标很直白：用尽可能少的换座，让每一对情侣最终相邻。

输入：整数数组 row 输出：最少交换次数 非付费题
先别急着看答案。 先在下方座位实验室中观察：当某个位置已经确定时，怎样的一次交换最“省事”？

目标：让情侣坐在同一个双人位

情侣按编号配对：(0,1)、(2,3)、(4,5)…… 每两个相邻座位视为一个双人位。

题目说明

准确理解任务

有 n 对情侣坐在一排连续的 2n 个座位上。整数数组 row 表示当前座次，row[i] 是第 i 个座位上的人的 ID。

情侣固定按连续 ID 配对：第一对为 (0, 1)，第二对为 (2, 3)，依此类推，最后一对是 (2n - 2, 2n - 1)。

一次交换可以任选两个人，让他们交换座位。请返回使每对情侣都相邻所需的最少交换次数。

函数形式： minSwapsCouples(row: integer[]) -> integer
约束

输入边界

  • 2n == row.length
  • 2 <= n <= 30
  • 0 <= row[i] < 2n
  • row 中所有元素互不相同

因此 row 恰好是 0..2n-1 的一个排列，数组长度在 4 到 60 之间。

官方示例 1
输入：row = [0,2,1,3] 输出：1 解释：交换 row[1] 与 row[2] 中的人即可。
官方示例 2
输入：row = [3,2,0,1] 输出：0 解释：所有情侣已经相邻，不需要交换。

独立题解

准备好再揭晓

下方内容包含核心算法、证明、复杂度、四语言代码与面试追问。

Greedy + Position Map

贪心固定每个双人位

从左到右处理：保留左边的人，把其伴侣直接换到右边。关键是用位置表在 O(1) 时间找到伴侣。

核心洞察

伴侣可 O(1) 得到

人的 ID 为 x 时，伴侣就是 x ^ 1：偶数加一，奇数减一。

局部问题必须付费

若位置 i+1 不是 row[i] 的伴侣，那么要修好这个双人位至少需要一次交换。

一次就能修好

直接把伴侣换到 i+1，恰好用一次交换达到局部下界，因此不会多花交换。

完整过程

  1. 建立位置数组 pos，使 pos[person] 表示这个人当前所在的座位。
  2. 按 i = 0, 2, 4, ... 扫描每个双人位，令左侧的人为 first = row[i]。
  3. 通过 partner = first ^ 1 找到其伴侣 ID，再由 pos[partner] 找到伴侣座位。
  4. 若伴侣已在 i+1，当前双人位无需操作；否则交换 row[i+1] 与伴侣。
  5. 交换后同步更新两人的 pos，交换计数加一。继续处理下一个双人位。

正确性证明

循环不变式：开始处理双人位 (i, i+1) 前，位置 0..i-1 中的每一对都已经相邻，之后也不会再被移动。

初始化：i=0 时，已处理前缀为空，不变式成立。

保持：若 row[i+1] 已是 row[i] 的伴侣，不操作即可扩展正确前缀。否则，任何最终方案都必须改变当前不匹配双人位，至少需要一次交换；贪心恰用一次交换把伴侣放到 i+1。交换只涉及未固定区域，所以旧前缀不受影响，新双人位被固定。

终止：所有双人位处理完后，每对情侣都相邻。每次贪心交换都达到当前步骤不可避免的一次交换下界，因此总交换次数最少。

复杂度

O(n)
时间复杂度

建立位置表一次，扫描 n 个双人位一次；查询与交换均为常数时间。

O(n)
空间复杂度

位置表长度为 2n。若每次线性搜索伴侣，可降为 O(1) 额外空间但时间变为 O(n²)。

四语言完整代码

四份实现都使用相同的“贪心 + 位置表”机制，并直接修改传入数组的局部排列。

Java官方签名
class Solution {
    public int minSwapsCouples(int[] row) {
        int[] pos = new int[row.length];
        for (int i = 0; i < row.length; i++) {
            pos[row[i]] = i;
        }

        int swaps = 0;
        for (int i = 0; i < row.length; i += 2) {
            int first = row[i];
            int partner = first ^ 1;
            int partnerIndex = pos[partner];

            if (partnerIndex == i + 1) {
                continue;
            }

            int displaced = row[i + 1];
            row[i + 1] = partner;
            row[partnerIndex] = displaced;
            pos[partner] = i + 1;
            pos[displaced] = partnerIndex;
            swaps++;
        }
        return swaps;
    }
}

from typing import List


class Solution:
    def minSwapsCouples(self, row: List[int]) -> int:
        pos = [0] * len(row)
        for index, person in enumerate(row):
            pos[person] = index

        swaps = 0
        for i in range(0, len(row), 2):
            first = row[i]
            partner = first ^ 1
            partner_index = pos[partner]

            if partner_index == i + 1:
                continue

            displaced = row[i + 1]
            row[i + 1] = partner
            row[partner_index] = displaced
            pos[partner] = i + 1
            pos[displaced] = partner_index
            swaps += 1

        return swaps

            pos[displaced] = partnerIndex;
            ++swaps;
        }
        return swaps;
    }
};

替代方案与边界

替代方案

  • 并查集：把每个双人位中的两个人所属情侣编号相连。若有 n 个情侣节点、c 个连通分量，答案为 n - c。
  • 图的环：座位关系形成若干环，一个含 k 对情侣的环需要 k - 1 次交换。
  • 原地线性查找：不建位置表，每轮寻找伴侣；实现直观，但时间复杂度为 O(n²)。

边界情况

  • 所有情侣一开始就相邻，答案为 0。
  • 情侣内部顺序不重要：[1,0] 与 [0,1] 都合法。
  • 最小规模 n=2 也按相同流程处理。
  • 最大长度只有 60，但仍应保持位置表与数组同步。

面试追问与常见错误

可能的追问

  • 为什么只固定左边的人，仍能保证全局最优？
  • 如何从并查集的连通分量数推导答案？
  • 如果交换只能发生在相邻座位，问题会变成什么？
  • 如果情侣关系由映射给出而非连续 ID，如何改写？

常见错误

  • 误写伴侣公式；正确写法是 x ^ 1。
  • 交换数组后忘记更新 pos，导致后续位置失真。
  • 把“任意两人交换”误读成“只能相邻交换”。
  • 遍历步长写成 1，重复处理已经固定的双人位。
