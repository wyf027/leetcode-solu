柠檬水找零

队伍不断向前，零钱只来自已经服务过的顾客。你能让每一笔交易都顺利完成吗？先亲手经营一次，再展开题解。

Problem

题目说明

非付费题 · 官方参数 bills

一杯柠檬水售价 5 美元。顾客按照数组 bills 给出的顺序逐一购买，每人只买一杯，并用 5、10 或 20 美元纸币付款。

你起初没有零钱。对每位顾客都必须正确找零，使其净支付恰好为 5 美元。如果能服务所有顾客，返回 true；否则返回 false。

输入整数数组 bills
返回boolean
顺序不可调整

约束

  • 1 <= bills.length <= 105
  • bills[i] 只能是 5、10 或 20

函数签名：lemonadeChange(bills)

核心洞察

把 5 美元钞票视为最关键的零钱。 收到 10 美元，只能找一张 5；收到 20 美元，需要找 15。此时若有 10，应优先找 10 + 5，从而少消耗两张珍贵的 5；否则才找 5 + 5 + 5。

完整过程

维护计数
只记录钱箱中 5 美元和 10 美元纸币的数量；20 美元不会用于后续找零。
按队列顺序扫描
收到 5 就存入；收到 10 必须消耗一张 5；收到 20 优先消耗一张 10 和一张 5，否则尝试三张 5。
即时失败
任何一步无法凑出所需零钱，立刻返回 false；完整扫描后返回 true。

正确性

不变式：处理完前 i 位顾客后，计数准确表示可用于后续找零的 5 与 10 美元纸币；且若算法未返回 false，则前 i 位均已正确找零。

收到 5 无需找零；收到 10 的找零方式唯一。收到 20 时，10 + 5 与三张 5 都能完成当前交易，但前者保留更多 5。每张 10 未来只能搭配 5 给 20 找零，而 5 还承担给 10 找零的唯一职责，所以优先使用 10 不会减少未来可行性。若两种方式均不可用，则不存在其他合法组合。由归纳法，算法返回 true 当且仅当所有顾客都能获得正确找零。

边界与复杂度

  • 首位顾客付 10 或 20：钱箱为空，立即失败。
  • 全是 5：无需找零，始终成功。
  • 钱箱总金额足够不代表能找零；纸币面额组合才关键。
  • 时间复杂度 O(n)，额外空间复杂度 O(1)。

替代方案

可以把钱箱保存为纸币列表，每次枚举找零组合，但会增加状态与搜索成本。由于面额固定且找零仅为 5 或 15，两个计数器已经足够。若面额或售价可变，则当前贪心规则未必成立，通常需要动态规划、搜索或由币值体系证明新的贪心性质。

class Solution {
    public boolean lemonadeChange(int[] bills) {
        int five = 0, ten = 0;
        for (int bill : bills) {
            if (bill == 5) {
                five++;
            } else if (bill == 10) {
                if (five == 0) return false;
                five--;
                ten++;
            } else {
                if (ten > 0 && five > 0) {
                    ten--;
                    five--;
                } else if (five >= 3) {
                    five -= 3;
                } else {
                    return false;
                }
            }
        }
        return true;
    }
}

面试追问

为什么不用记录 20 美元纸币？

售价为 5，顾客只付 5、10、20；后续所需找零最多是 15，20 无法参与任何合法找零。

如果先用三张 5 给 20 找零，会怎样？

当前交易虽能完成，却可能让下一位付 10 的顾客无法找零。优先花掉用途更窄的 10，保留用途更广且不可替代的 5。

能否重新排列顾客顺序？

不能。数组顺序就是队列顺序，改变顺序会改变题目语义。

常见错误

  • 只检查钱箱总额，没有检查纸币组合。
  • 收到 20 时先使用三张 5，破坏未来交易的可行性。
  • 收到纸币后才判断能否找零，导致把当前付款错误地当作零钱使用。
  • 无法找零时仍继续扫描，遗漏了可立即返回的条件。
