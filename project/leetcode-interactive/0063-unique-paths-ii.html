Cleared flight plan

题解

Core signal

核心洞察

普通格的路径数仍是上方与左侧之和；唯一新增的规则是：障碍物不可到达，因此它对应的状态必须立即归零。若不清零，这个位置上一行残留的 dp[c] 会错误地穿过障碍继续传播。

Interview choice

为什么主推一维 DP

逐行扫描时，旧 dp[c] 表示上方，已更新的 dp[c−1] 表示左侧。它与二维转移完全同构，却只需 O(n) 空间，也不会修改输入网格。

Full scan

完整过程

  1. 1. 创建长度为列数 n 的数组，并设 dp[0] = 1。
  2. 2. 按行从左到右扫描；若当前格是障碍，执行 dp[c] = 0。
  3. 3. 否则从上方旧值与左侧新值汇总： dp[c] += dp[c−1]。
  4. 4. 最后返回 dp[n−1]；终点若被封锁，扫描时自然归零。

Boundaries

边界

  • • 起点是障碍：第一次扫描就把 dp[0] 清零，答案为 0。
  • • 终点是障碍：最后一个状态归零，答案为 0。
  • • 单行或单列：障碍之后的所有位置都保持 0。
  • • [[0]]：不移动本身是一条有效路径，答案为 1。

Complexity

复杂度

时间
O(m × n)
额外空间
O(n)

Alternatives

替代方案取舍

二维 DP 最直观但占 O(mn) 空间；记忆化搜索同样正确，却有递归栈与函数调用成本；原地复用 obstacleGrid 能省数组，但会修改输入，且把障碍标记与路径数混在一起，可读性较差。

Follow-ups

面试追问

  • • 障碍物在线新增或移除？单次修改可能影响其右下区域，需要重算或使用更复杂的数据结构。
  • • 如果每格有代价并求最小代价？状态从“计数求和”改为“可达前驱取最小值”。
  • • 如果允许移除一个障碍？给 DP 增加“是否已使用移除机会”的维度。
  • • 如何输出一条路径？保留二维可达信息或父方向，再从终点反向恢复。

Common failures

常见错误

  • • 遇到障碍只跳过更新，却没有把旧的 dp[c] 清零。
  • • 无条件保留 dp[0] = 1，导致第一列障碍下方仍可达。
  • • 从右向左更新，使左侧状态仍来自上一行，破坏滚动数组语义。
  • • 单独写大量首行、首列初始化，增加分支并容易遗漏起点障碍。

class Solution {
    public int uniquePathsWithObstacles(int[][] obstacleGrid) {
        int rows = obstacleGrid.length;
        int cols = obstacleGrid[0].length;
        int[] dp = new int[cols];
        dp[0] = 1;

        for (int row = 0; row < rows; row++) {
            for (int col = 0; col < cols; col++) {
                if (obstacleGrid[row][col] == 1) {
                    dp[col] = 0;
                } else if (col > 0) {
                    dp[col] += dp[col - 1];
                }
            }
        }
        return dp[cols - 1];
    }
}
