LEETCODE 0768 最多能完成排序的块 II

把数组切成若干块，分别排序后再拼接。你的目标不是找到一种切法，而是让块数尽可能多。

↓ 先读题，再进入边界实验
First thought

什么时候可以放心切一刀？

不妨先想：切口左边与右边需要满足怎样的关系，才能保证各自排序后不会互相“越界”？题解被锁在页面底部。

Problem statement

题意与输入边界

给定整数数组 arr，将它分成若干连续的非空块。分别对每一块升序排序，再按原顺序连接；连接结果必须等于整个数组升序排序后的结果。返回可得到的最大块数。

你需要返回什么

函数接收参数 arr: integer[]，返回一个整数。块必须覆盖所有元素且不能重叠，块内可以包含重复值。

例如把 [2,1,3,4,4] 分为 [2,1]、[3]、[4]、[4]，各块排序并连接后得到 [1,2,3,4,4]。

约束

  • 1 <= arr.length <= 2000
  • 0 <= arr[i] <= 108
Example 01 输出 1
输入
arr = [5,4,3,2,1]
输出
1

切成两块或更多块都无法得到整体有序的结果。例如切成 [5,4]、[3,2,1]，排序并拼接后是 [4,5,1,2,3]。

Example 02 输出 4
输入
arr = [2,1,3,4,4]
输出
4

最优切分为 [2,1]、[3]、[4]、[4]；分别排序后连接，恰好得到整体升序数组。

Complete solution

前缀最大值 × 后缀最小值

一刀能否成立，只取决于切口两边会不会交叉：左边所有值都不大于右边所有值时，两边分别排序后仍能保持全局次序。

≤

核心洞察

在索引 i 与 i + 1 之间切开，当且仅当 max(arr[0..i]) <= min(arr[i+1..n-1])。每个满足条件的边界都可以同时保留，因此全部切开就是最大块数。

完整过程

  1. 从右向左构造 suffixMin[i]，表示区间 arr[i..n-1] 的最小值。
  2. 从左向右扫描，用变量 prefixMax 维护 arr[0..i] 的最大值。
  3. 若 prefixMax <= suffixMin[i+1]，就在 i 后新增一个块。
  4. 初始至少有整段这一个块；扫描完所有 n - 1 个边界后返回块数。

为什么要用 ≤

数组允许重复值。若左侧最大值等于右侧最小值，切开仍然安全；例如相邻两个 4 可以属于不同块。写成严格小于会漏掉合法切口。

prefixMax[i] ≤ suffixMin[i + 1]

正确性证明

必要性：若某切口左侧存在值大于右侧某值，那么各块内部排序后，较大值仍位于较小值之前，拼接结果不可能全局升序。所以合法切口必须满足左侧最大值不大于右侧最小值。

充分性：若左侧最大值不大于右侧最小值，则左块排序后的每个值都不大于右侧每个值。两侧各自能够递归按同样的合法边界分块，所有块排序后拼接仍是全局升序。

最优性：算法枚举所有相邻边界并保留全部合法边界。任何有效分块只能在这些合法边界处切开，因此算法得到的块数不小于且不大于最优值，故恰为最大值。

边界处理

  • n = 1：没有可检查的切口，答案就是 1。
  • 完全逆序：通常没有内部合法边界，只保留整块。
  • 已经非递减：每个相邻边界都合法，答案为 n。
  • 重复值：等号必须被接受。
  • 值可达 10^8，四种语言的普通整数类型都足够。

复杂度

时间复杂度：O(n)。一次构造后缀最小值，再一次扫描边界。

空间复杂度：O(n)，用于 suffixMin 数组。

若采用下方提到的单调栈方案，时间仍为 O(n)，最坏空间也为 O(n)。

替代方案

排序 + 频次差：复制并排序数组，同时扫描原数组与排序数组；维护两边前缀的计数差，当差异归零时可切块。复杂度 O(n log n)。

单调栈：栈中维护每个候选块的最大值。新值破坏单调性时合并前面的块，并保留被合并块的最大值。复杂度 O(n)，但证明更绕。

class Solution {
    public int maxChunksToSorted(int[] arr) {
        int n = arr.length;
        int[] suffixMin = new int[n];

        suffixMin[n - 1] = arr[n - 1];
        for (int i = n - 2; i >= 0; i--) {
            suffixMin[i] = Math.min(arr[i], suffixMin[i + 1]);
        }

        int chunks = 1;
        int prefixMax = arr[0];

        for (int i = 0; i < n - 1; i++) {
            prefixMax = Math.max(prefixMax, arr[i]);
            if (prefixMax <= suffixMin[i + 1]) {
                chunks++;
            }
        }

        return chunks;
    }
}

常见错误

  • 只比较 arr[i] 和 arr[i+1]，忽略更远处的交叉值。
  • 使用严格小于号，导致重复值边界被漏掉。
  • 把答案初始化为 0，忘记整个数组本身始终是一个合法块。
  • 访问 suffixMin[i+1] 时扫描到 i = n-1，造成越界。
