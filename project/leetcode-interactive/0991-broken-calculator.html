坏了的计算器

Broken Calculator MEDIUM

先亲手观察倒推过程，再决定是否展开完整题解。

题目

计算器初始显示整数 startValue。每次只能把当前数乘以 2，或将它减去 1。给定 startValue 与 target，返回显示出 target 所需的最少操作次数。

函数签名

brokenCalc(startValue: integer, target: integer) -> integer

约束

  • 1 <= startValue, target <= 10^9

官方示例

示例 1
输入：startValue = 2, target = 3
输出：2
解释：2 -> 4 -> 3
示例 2
输入：startValue = 5, target = 8
输出：2
解释：5 -> 4 -> 8
示例 3
输入：startValue = 3, target = 10
输出：3
解释：3 -> 6 -> 5 -> 10
Reverse gear lab

倒车档计算器

从目标反向走：偶数减半，奇数加一。这样每一步都在撤销正向操作。

第 0 / 3 步

Solution

从目标倒推的贪心

核心洞察

正向的“乘 2”会迅速产生分支；反向时却几乎没有选择：目标为偶数，只可能高效地撤销乘 2；目标为奇数，先加 1 变成偶数，正好撤销一次正向减 1。

完整过程

  1. 只要 target > startValue，持续倒推。
  2. 若目标为奇数，令它加一；若为偶数，令它减半。
  3. 当目标不大于起点后，不能再靠反向减半精确获益；正向只需连续减一，补上 startValue - target 步。

正确性

设当前倒推值为 t > startValue。若 t 为奇数，任何到达它的最后一步都不可能是乘 2，因此必为从 t+1 减一，倒推加一是必需的。若 t 为偶数，倒推减半一次就撤销乘 2；改走加一只会把值推得更远，随后仍需额外操作，不能更优。逐步采用必需或占优操作，直至不大于起点；剩余差只能由正向减一补齐，故总步数最少。

边界

  • startValue == target：答案为 0。
  • startValue > target：只能连续减一。
  • 奇数目标可能先加到 10^9 + 1；四种实现所用数值类型均可安全容纳。

复杂度

时间 O(log target + startValue - t)，其中 t 是倒推结束值；通常写作 O(log target + startValue)。额外空间 O(1)。

替代方案

BFS 能找到最短路，但状态上界大、内存昂贵；正向贪心难以判断何时减一。反向贪心利用了操作的奇偶结构。

面试追问

  • 为什么偶数时减半一定不劣？
  • 若操作改成“乘 3 / 减 1”，倒推规则如何变化？
  • 如何输出一条正向最短操作序列？可保存倒推动作并逆序翻转。

常见错误

  • 在正向过程盲目倍增，越过目标后无法保证最优。
  • 循环结束后漏加 startValue - target。
  • 把奇数倒推写成减一；正向减一的逆操作应是加一。

四种语言实现

Java

class Solution {
    public int brokenCalc(int startValue, int target) {
        int steps = 0;
        while (target > startValue) {
            target = (target % 2 == 0) ? target / 2 : target + 1;
            steps++;
        }
        return steps + startValue - target;
    }
}
