使数组 K 递增的
最少操作次数

Minimum Operations to Make the Array K-Increasing

从间隔为 k 的大小关系出发，思考哪些元素必须改变。

01 / 题目

给定一个从下标 0 开始的正整数数组 arr 和正整数 k。设数组长度为 n，若每个下标 k ≤ i < n 都满足下面的条件，就称数组为 K 递增：

arr[i − k] ≤ arr[i]

允许相等；比较的是相隔 k 个位置的元素。

一次操作可以选中一个元素，把它改为任意正整数。返回让数组满足 K 递增条件所需的最少操作次数。

参数与返回：kIncreasing(arr: integer[], k: integer) → integer

约束：1 ≤ arr.length ≤ 10⁵；1 ≤ arr[i], k ≤ arr.length。修改后的值只要求为正整数。

04 / 独立题解

准备好后，展开算法、可视化和代码。

核心洞察：尽可能多地保留原元素

把下标按 i % k 分成 k 组：第 r 组是 r, r+k, r+2k, …。约束只发生在组内相邻元素之间，因此各组独立，只需分别变成非递减序列。

组内最少修改数 = 组长度 − 最长非递减子序列长度（LNDS）。
总答案 = 所有组的最少修改数之和。

保留下来的原元素必须按原顺序非递减。最长非递减子序列允许相等；它不要求连续，也不允许重新排列原数组。

交互实验 / 同余轨道 → tails 工作台

逐元素观察组内二分：青色为当前元素，琥珀色为探测位置。tails[j] 表示长度 j+1 的非递减子序列可达到的最小末尾值；tails 本身不保证是原数组中的同一条子序列。

完整过程

  1. 枚举起点 r，从 r 开始每次向后跳 k 个位置，得到一条独立序列。
  2. 为当前组创建空的 tails，按原顺序读取值 x。
  3. 二分查找第一个严格大于 x 的 tails 元素：若 tails[mid] ≤ x，向右搜索；否则向左搜索。
  4. 若找到位置，替换它；若没有大于 x 的元素，则在末尾追加 x。相等时向右走才能允许重复值延长子序列。
  5. 处理完整组后，tails 的长度就是 LNDS 长度。把组长度减去该长度加入答案。

示例 3：三组分别是 [4,2]、[1,6]、[5,2]，LNDS 长度为 1、2、1，因此答案为 (2−1)+(2−2)+(2−1)=2。处理 [4,2] 时 tails 从 [] 变为 [4] 再变为 [2]：替换降低末尾值，不增加长度。

正确性说明

分组等价：每个不等式的两端下标相差 k，因此属于同一余数组；每组相邻元素的非递减关系恰好覆盖全部约束，各组可独立优化。

下界：某组长度为 m，任何合法修改方案中未被修改的元素，都构成原序列的非递减子序列。若最长长度为 L，最多保留 L 个，故至少修改 m−L 个。

下界可达：保留一条长度 L 的 LNDS。首个保留元素前的空位填它的值；两个保留元素之间填左端的值；最后一个保留元素后也填它的值。所有值为正且非递减，只需修改其余至多 m−L 个位置。结合下界，最优值恰为 m−L。

tails 不变量：处理任意前缀后，tails[j] 是该前缀长度 j+1 的非递减子序列的最小末尾值。找到首个大于 x 的位置 p 时，若 p > 0，则 tails[p−1] ≤ x，可把 x 接在该长度 p 的子序列后；替换 tails[p] 得到更小末尾。更短长度的最小末尾不会改善，更长子序列又不能由 x 延伸得到。若 p 等于当前长度，恰好形成更长子序列。因此长度始终等于该前缀的 LNDS 长度。

复杂度与边界

设最长组长度 M = ⌈n/k⌉。每个元素处理一次，二分代价 O(log(M+1))，总时间 O(n log(M+1))，通常写作 O(n log n)。逐组复用空间时，辅助空间 O(M)。

  • k = n：各组只有一个元素，答案 0。
  • k = 1：求整个数组的 LNDS。
  • 重复元素可以全部保留。
  • n 不能整除 k 时，直接以 i < n 控制遍历。
  • 答案在 0 到 n−k 之间，32 位整数足够。

替代方案与常见错误

  • 动态规划：dp[i] = 1 + max(dp[j])，要求 j < i 且 a[j] ≤ a[i]。分组总时间 O(Σm²)，最坏 O(n²)，大输入不适用。
  • 值域树状数组维护前缀最大值：查询 ≤ x，再更新 x；时间 O(n log n)，但每组需要隔离状态，实现更复杂。
  • 使用“第一个 ≥ x”会算成严格递增，误删重复值。
  • 直接排序破坏原位置；统计下降边数也不等于修改次数，如 [3,4,1,2]。
  • 每组必须清空 tails，替换 tails 不是实际修改 arr。

Java

class Solution {
    public int kIncreasing(int[] arr, int k) {
        int n = arr.length, answer = 0;
        int[] tails = new int[(n + k - 1) / k];
        for (int r = 0; r < k; r++) {
            int length = 0, count = 0;
            for (int i = r; i < n; i += k) {
                int x = arr[i], left = 0, right = length;
                while (left < right) {
                    int mid = left + (right - left) / 2;
                    if (tails[mid] <= x) left = mid + 1;
                    else right = mid;
                }
                tails[left] = x;
                if (left == length) length++;
                count++;
            }
            answer += count - length;
        }
        return answer;
    }
}

Python 3

from bisect import bisect_right
from typing import List

class Solution:
    def kIncreasing(self, arr: List[int], k: int) -> int:
        answer = 0
        for r in range(k):
            tails = []
            count = 0
            for i in range(r, len(arr), k):
                x = arr[i]
                p = bisect_right(tails, x)
                if p == len(tails):
                    tails.append(x)
                else:
                    tails[p] = x
                count += 1
            answer += count - len(tails)
        return answer

C++

#include <algorithm>
#include <vector>
using namespace std;

class Solution {
public:
    int kIncreasing(vector<int>& arr, int k) {
        int n = static_cast<int>(arr.size());
        int answer = 0;
        for (int r = 0; r < k; ++r) {
            vector<int> tails;
            int count = 0;
            for (int i = r; i < n; i += k) {
                auto it = upper_bound(tails.begin(), tails.end(), arr[i]);
                if (it == tails.end()) tails.push_back(arr[i]);
                else *it = arr[i];
                ++count;
            }
            answer += count - static_cast<int>(tails.size());
        }
        return answer;
    }
};

面试追问

如何给出实际修改方案？在 LNDS 算法中额外记录每个元素的前驱下标，以及 tails 各长度对应的末尾下标，回溯得到保留位置，再按正确性证明中的填充方法构造。记录下标需 O(n) 空间。

如果改为严格递增呢？不能仅替换二分比较符后沿用本证明：正整数的可用间隔会限制填充。例如 [2,1,2] 的普通 LIS 长度为 2，但只修改一个位置无法变成严格递增正整数序列。需要额外考虑位置间距与数值间距。

如果每个位置的修改代价不同呢？目标变成最大化保留元素的权重和，可在组内使用值域前缀最大值结构做加权非递减子序列 DP，普通 tails 长度已不足够。
