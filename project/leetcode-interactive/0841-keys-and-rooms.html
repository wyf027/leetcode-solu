钥匙和房间 Keys and Rooms

先别急着看答案。把每个房间当作一个小世界：进去、拿钥匙，再决定下一扇门能否打开。

01 / Problem

题目要求

共有 n 个房间，编号为 0 到 n - 1。一开始只有 0 号房间没有上锁。进入房间 i 后，可以拿走 rooms[i] 中所有互不相同的钥匙；钥匙上的数字表示它能打开的房间。

给定二维数组 rooms，判断从 0 号房间出发，最终能否进入全部房间。函数形式为 canVisitAllRooms(rooms)，返回布尔值。

示例 1 · 全部可达

输入：rooms = [[1],[2],[3],[]]
输出：true
解释：0 → 1 → 2 → 3，沿途获得下一把钥匙，
最终进入了全部四个房间。

示例 2 · 孤立房间

输入：rooms = [[1,3],[3,0,1],[2],[0]]
输出：false
解释：从 0 出发只能进入 1 和 3；
打开 2 号房间的钥匙只在 2 自己里面。

约束

  • n == rooms.length
  • 2 <= n <= 1000
  • 0 <= rooms[i].length <= 1000
  • 1 <= Σ rooms[i].length <= 3000
  • 0 <= rooms[i][j] < n
  • 每个 rooms[i] 内的值互不相同

    03 / Solution

    把房间关系看成一张有向图

    核心洞察

    把每个房间看作一个节点；房间 i 中出现钥匙 j，等价于存在一条从 i 指向 j 的有向边。题目因此变成：从节点 0 出发，能否访问图中的全部节点。

    使用 BFS 或 DFS 都可以。下面采用 BFS：队列保存已经拿到钥匙、但尚未检查其内部钥匙的房间；布尔数组 visited 同时防止重复入队并统计可达房间数。

    完整过程

    1. 创建长度为 n 的访问标记，将 0 号房间标记为已发现，并放入队列。
    2. 队列非空时取出一个房间，查看里面的每把钥匙。
    3. 若钥匙指向的房间尚未发现，立即标记并入队；提前标记能防止多把相同目标钥匙导致重复入队。
    4. 遍历结束后，比较已发现房间数与 n。相等返回 true，否则返回 false。

    正确性

    可达房间一定会被访问：0 号房间先进入队列。若某个可达房间 v 可由已访问房间 u 中的钥匙打开，那么处理 u 时会发现并入队 v。沿从 0 到任意可达房间的路径归纳，所有可达房间最终都会被访问。

    被访问的房间一定可达：除 0 以外，房间只会在处理某个已可达房间的钥匙时入队，因此它也从 0 可达。

    所以算法发现的集合恰好等于从 0 可达的房间集合；其大小为 n 当且仅当所有房间均可进入。

    边界与复杂度

    • 房间可能没有钥匙；此时只需继续处理队列。
    • 钥匙可能指回当前房间或先前房间；访问标记会忽略它。
    • 多个房间可能都有同一目标房间的钥匙；目标只入队一次。
    • 输入保证至少两个房间，且钥匙编号合法。
    时间复杂度O(n + k)每个房间和每把钥匙至多处理一次，k 为钥匙总数。
    空间复杂度O(n)访问数组与队列最多保存 n 个房间。

    替代方案

    递归 DFS：代码很短，沿钥匙一路深入；但最深可能达到 n 层，需要考虑语言的递归栈限制。

    迭代 DFS：用栈代替队列，复杂度不变，也避免递归限制。BFS、递归 DFS 和迭代 DFS 的访问顺序不同，但可达性结论完全相同。

    四语言完整代码

    class Solution {
    public boolean canVisitAllRooms(List<List<Integer>> rooms) {
        int n = rooms.size();
        boolean[] visited = new boolean[n];
        Queue<Integer> queue = new ArrayDeque<>();
        visited[0] = true;
        queue.offer(0);
        int count = 1;

        while (!queue.isEmpty()) {
            int room = queue.poll();
            for (int key : rooms.get(room)) {
                if (!visited[key]) {
                    visited[key] = true;
                    count++;
                    queue.offer(key);
                }
            }
        }
        return count == n;
    }
}
    /**
 * @param {number[][]} rooms
 * @return {boolean}
 */
var canVisitAllRooms = function(rooms) {
    const visited = new Array(rooms.length).fill(false);
    const queue = [0];
    visited[0] = true;
    let count = 1;

    for (let head = 0; head < queue.length; head++) {
        const room = queue[head];
        for (const key of rooms[room]) {
            if (!visited[key]) {
                visited[key] = true;
                count++;
                queue.push(key);
            }
        }
    }
    return count === rooms.length;
};
    from collections import deque
from typing import List


class Solution:
    def canVisitAllRooms(self, rooms: List[List[int]]) -> bool:
        visited = [False] * len(rooms)
        visited[0] = True
        queue = deque([0])
        count = 1

        while queue:
            room = queue.popleft()
            for key in rooms[room]:
                if not visited[key]:
                    visited[key] = True
                    count += 1
                    queue.append(key)

        return count == len(rooms)

    面试追问与常见错误

    可能的追问

    • 如果要输出实际访问顺序，如何修改？
    • 如果要输出无法进入的房间编号呢？
    • BFS 与 DFS 在这里的结果和资源消耗有何差别？
    • 若钥匙是一次性的，问题会发生什么变化？

    常见错误

    • 只统计拿到的钥匙数量，忽略重复目标。
    • 出队时才标记，导致同一房间重复入队。
    • 忘记 0 号房间一开始已经可进入。
    • 错误地把钥匙关系当作无向边。
    • 使用 shift() 实现 JS 队列，造成额外搬移开销。
