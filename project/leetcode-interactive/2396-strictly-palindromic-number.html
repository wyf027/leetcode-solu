严格回文的数字

Strictly Palindromic Number

同一个整数，换一种进制，左右还能对称吗？

01 / 问题

每一种进制都要满足

给定整数 n，把它分别写成从 2 到 n − 2（含两端）的每一种整数进制。如果所有表示都正读、反读相同，返回 true；只要有一种不是回文，就返回 false。

采用标准进制表示，不补前导零。比较的是完整的数位序列。

参数与返回值

isStrictlyPalindromic(n: integer) → boolean

约束：4 ≤ n ≤ 105

输出：false

二进制为 1001，是回文；三进制为 100，不是回文，因此返回 false。在 4、5、6、7 进制下也都不是回文。

示例 2

输入：n = 4
输出：false

只需考虑二进制：4 = (100)₂，不是回文。

04 / 独立题解

观察之后，再看推导

一个反例进制就够了

核心洞察

题目要求“所有进制”都成立。对每个合法 n，只需找到一个不回文的进制，就能否定它。选择区间右端 b = n − 2，会让表示变得非常简单。

n ≥ 5：n = 1 × (n − 2) + 2 → (12)n−2

此时 b ≥ 3，余数 2 小于 b，是合法数位；首位 1 与末位 2 不同。所以每个 n ≥ 5 都失败。

单独处理 n = 4：b = 2，表示为 100，同样不回文。不能把它写成二进制的 12。

当前输入的反例

上方载入新的 n 后，这条推导会同步更新。

完整过程与正确性

  1. 覆盖 n = 4：允许的唯一进制 2 已经给出反例 100。
  2. 覆盖 n ≥ 5：n − 2 位于题目要求的进制区间内，且 n = b + 2；因为 0 ≤ 2 < b，标准表示恰为两位 [1, 2]。
  3. [1, 2] 正读与反读不同。因此该 n 至少有一个允许的进制不满足回文条件。
  4. 两类覆盖全部合法输入，每种情况的答案都是 false，提交函数可直接返回 false。

边界与复杂度

约束下不需要运行时分支，证明里仍必须区分 n = 4。函数时间 O(1)，额外空间 O(1)；它并未实际执行进制转换。页面演示的开销不属于提交算法。

若将定义扩展到 n < 4，原进制区间可能为空，“对所有元素都成立”需要重新约定。不能把本题结论无条件迁移到约束外。

替代方案：按定义枚举

枚举 b = 2…n − 2。每次用除法和取余得到数位数组，再用双指针比较两端；遇到不相等立刻返回 false，全通过才返回 true。把数位存为整数，避免高进制字符编码问题。

不利用提前结束时，粗略时间上界为 O(n log n)，额外空间 O(log n)。进一步按进制分段可得完整扫描为 O(n)：b > √n 时最多两位，其余至多 √n 个进制各用 O(log n)。数学方法省去了这些扫描。

常见错误

  • 把“任意一个进制回文”当成“每个进制回文”。n = 9 的二进制是回文，但答案仍为 false。
  • 不加条件地说 n 在 n − 2 进制下总是 12，遗漏 n = 4 的余数合法性。
  • 只检查十进制，或加入前导零来制造对称。
  • 直接用 JavaScript 的 toString(b) 处理任意进制；它只支持 2 到 36，高进制应使用整数数位数组。
  • 只写 return false，却不能解释为什么覆盖全部输入。

面试追问

  • 为何选 n − 2，而不是 n − 1？n − 1 不在允许区间内，而且其表示 11 是回文，无法成为反例。
  • 为何不是 2 × b + …？当 n ≥ 5 时 n < 2(n − 2)，商恰为 1。
  • 改为只检查给定的一组进制呢？如果不保证含 n − 2，这个反例可能不可用，应逐个转换并检查。
  • 为什么不用反转字符串？普通小进制可以；用整数数位和双指针能直接支持任意合法 b。
