SOLUTION VAULT

题解区

核心洞察、完整过程、边界、复杂度、替代方案、面试追问、常见错误与四语言代码均收纳于此。

01 · INSIGHT

核心洞察

交换两个因子，让较小者 small 控制递归深度。令 half = multiply(small >> 1, large)： 偶数层答案是 half + half；奇数层还要再加一次 large。每层只递归一次，不产生重复子问题。

02 · TRACE

完整过程：9 × 13

  1. multiply(9, 13) 等待 multiply(4, 13)
  2. multiply(4, 13) 等待 multiply(2, 13)
  3. multiply(2, 13) 等待 multiply(1, 13)
  4. 基例返回 13
  5. 回溯得到 26 → 52 → 52 + 52 + 13 = 117

03 · LIMITS

边界与复杂度

  • 正整数：官方输入均为正数，基例 small === 1。
  • 因子为 1：立即返回另一个因子。
  • 不溢出：官方保证乘积在返回类型范围内。
  • 时间：O(log min(A, B))。
  • 空间：O(log min(A, B)) 递归栈。

04 · ALTERNATIVES

替代方案

  • 线性递归加法：写法短，但要做 O(min(A,B)) 次加法。
  • 迭代二进制乘法：同为对数级且无递归栈，但题目明确要求递归函数。
  • 双分支递归：分别算左右半份会重复工作；缓存虽可补救，仍不如一次递归直接。

05 · INTERVIEW

面试追问

若允许 0 或负数？
先记录符号并取绝对值，增加 small === 0 基例；同时谨慎处理最小负数绝对值溢出。
为何选较小因子减半？
递归层数与被减半的因子对数相关，选择较小者能得到更浅的调用栈。
还能减少加法吗？
偶数层只做一次 half + half；奇数层额外加一次 large，已避免重复递归。

06 · PITFALLS

常见错误

  • 递归调用两次同一个半规模问题，时间退化。
  • 奇数层只做 half + half，漏加一次固定因子。
  • 未交换因子，让超大的因子控制递归深度。
  • 为了“少写代码”偷偷使用乘号，违背题目限制。

class Solution {
    public int multiply(int A, int B) {
        int small = Math.min(A, B);
        int large = Math.max(A, B);
        return multiplySmall(small, large);
    }

    private int multiplySmall(int small, int large) {
        if (small == 1) {
            return large;
        }

        int half = multiplySmall(small >> 1, large);
        int result = half + half;
        return (small & 1) == 1 ? result + large : result;
    }
}
