01 / 题目

给定两个从下标 0 开始、只含非负整数的数组 nums1 和 nums2。从两个数组各取一个元素，每一种下标组合都恰好使用一次；将每对元素的按位异或结果组成数组 nums3。返回 nums3 中所有元素继续按位异或后的结果。

这里的“异或和”使用运算符 ^，不是算术加法。相同位不同为 1，相同为 0。相同数值在不同下标出现时，仍是不同的配对机会。

参数与返回值

xorAllNums(nums1: integer[], nums2: integer[]) → integer

官方示例 1

输入：nums1 = [2,1,3], nums2 = [10,2,5,0]
输出：13
nums3 = [8,0,7,2,11,3,4,1,9,1,6,3]

将这 12 个结果全部异或，得到 13。nums3 的排列顺序不影响最终异或结果。

官方示例 2

输入：nums1 = [1,2], nums2 = [3,4]
输出：0
nums3 = [2,5,1,6]

四个下标组合都被使用，最终为 2 ^ 5 ^ 1 ^ 6 = 0。

约束

  • 1 ≤ nums1.length, nums2.length ≤ 10⁵
  • 0 ≤ nums1[i], nums2[j] ≤ 10⁹

04 / 独立题解
准备好后展开推导与四语言代码。




核心洞察：按出现次数消去元素


异或满足交换律、结合律，且 x ^ x = 0、x ^ 0 = x。因此同一个数异或偶数次抵消，奇数次保留一次。设 m = nums1.length，n = nums2.length：每个 nums1 元素出现 n 次，每个 nums2 元素出现 m 次。决定一个数组是否贡献结果的是另一个数组的长度。


答案 = (n 为奇数 ? XOR(nums1) : 0)
     ^ (m 为奇数 ? XOR(nums2) : 0)


交互联动：从矩阵压缩到两组贡献
下方随“数对扫描台”的已应用输入更新，展示优化算法的完整分组；与枚举的当前步数无关。


完整过程
  1. 初始化答案 ans = 0。
  2. 若 nums2 的长度为奇数，将 nums1 的每个元素异或到 ans。
  3. 若 nums1 的长度为奇数，将 nums2 的每个元素异或到 ans。
  4. 返回 ans，不构造 nums3，也不枚举数对。


示例 1 中 m = 3，n = 4。nums1 的每个数出现 4 次，全部抵消；nums2 的每个数出现 3 次，各保留一次。故答案是 10 ^ 2 ^ 5 ^ 0 = 13。两边长度都是奇数时，需要同时执行两次遍历，不能写成 if / else。


正确性证明
原式为 ⊕ᵢ ⊕ⱼ (nums1[i] ^ nums2[j])。根据结合律和交换律，可将所有来自 nums1 的项与所有来自 nums2 的项分别收集。固定 i 时，nums1[i] 恰好出现 n 次；固定 j 时，nums2[j] 恰好出现 m 次。偶数次项的异或为 0，奇数次项的异或为原值，所以原式恰好化为上述两个条件贡献的异或。每次遍历后 ans 等于所有已处理保留项的异或；遍历结束后即为原问题答案。


边界与复杂度
  • 两边长度为偶数：返回 0，两个数组都无需遍历。
  • 两边长度为奇数：两个数组都参与。单元素数组自然退化为一次数对异或。
  • 零和重复元素正常处理，不去重；空数组不在题目约束内。
  • 最坏时间 O(m + n)，额外空间 O(1)。更精确为 O(1 + [n 为奇数]m + [m 为奇数]n)；双偶数长度为 O(1)，不含输入读取。
  • 值小于 2³⁰，异或结果也小于 2³⁰。Java / C++ 的 int 与 JavaScript 的 32 位位运算在本题范围内可用；不应将这一结论扩展到任意大整数。


替代方案
直接双循环边枚举边累积：时间 O(mn)、额外空间 O(1)，适合讲解数对含义，也就是上方扫描台的方式；最大规模有 10¹⁰ 对，无法满足效率要求。若显式保存 nums3，空间还会升至 O(mn)。逐位统计 1 的出现次数也可求解，但要处理约 30 个二进制位，推导和实现都比长度奇偶法繁琐。


常见错误
  • 把“异或和”写成加法，或将所有配对结果求和。
  • 判断本数组长度决定本数组贡献；正确条件来自对方数组长度。
  • 只配对相同下标，漏掉笛卡尔积中的其他数对。
  • 使用 else if，导致两边长度为奇数时漏掉一个数组。
  • 先去重或把 nums3 存起来；前者破坏次数，后者浪费空间。


面试追问
某个数更新后如何维护答案？固定数组长度时，只有对方长度为奇数，该更新才影响答案；用 ans ^= oldValue ^ newValue 更新。若允许追加元素，需维护两数组总异或与长度，再按公式重算，追加会改变奇偶条件。
扩展到三个数组的所有三元组呢？每个数组元素的重复次数等于另两个数组长度的乘积；仅当另外两个长度均为奇数时，这个数组的总异或才贡献一次。


Java
class Solution {
    public int xorAllNums(int[] nums1, int[] nums2) {
        int ans = 0;
        if (nums2.length % 2 == 1) {
            for (int x : nums1) ans ^= x;
        }
        if (nums1.length % 2 == 1) {
            for (int x : nums2) ans ^= x;
        }
        return ans;
    }
}
