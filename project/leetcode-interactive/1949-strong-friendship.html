01 / 任务

哪些好友，拥有足够多的共同好友？

输入表 Friendship 的每一行保存一对已经互为好友的用户。若一对好友至少共享 3 位好友，就将这对用户及其共同好友总数写入结果。

输入表：Friendship
列名类型
user1_idINT
user2_idINT
输出契约

三列：user1_id、user2_id、common_friend。每对用户仅出现一次，较小 ID 在前，结果行顺序不限。

约束与语义

  • (user1_id, user2_id) 是联合主键，原始关系不重复。
  • 每行满足 user1_id < user2_id，不包含自己与自己的关系。
  • 关系是双向的，表里只存其中一个方向。
  • 必须已经是好友；共同好友数恰好为 3 也应入选。
  • 公开题面未给出行数或 ID 数值范围，不额外虚构规模上限。

05 / 独立题解

准备好把关系写成查询了吗？

展开核心洞察、证明、复杂度与五份代码。

双向邻接表 + 以原始好友对为起点的连接

核心洞察

对于一条原始关系 (u, v)，共同好友就是邻居集合的交集 N(u) ∩ N(v)。先将每条单向存储的关系展开成两条邻接记录，再把同一个第三人 w 在两端对齐。每个合法的 w 恰好产生一行，分组计数即为答案。

完整过程

  1. 构造 CTE neighbors(user_id, friend_id)：原表正向记录加上反向记录，使用 UNION ALL。
  2. 从原表别名 f 出发，保证当前 (u, v) 本来就是好友，并天然满足 u < v。
  3. 连接 a 找到 u 的好友 w，再连接 b 要求 b 的用户是 v、好友仍然是 w。
  4. 按原始好友对分组，COUNT(*) 统计所有匹配的 w。
  5. 通过 HAVING COUNT(*) >= 3 保留结果，输出确切总数，不能数到 3 就停止。

示例 (1,2)：连接行分别为 (1,2,3)、(1,2,4)、(1,2,5)、(1,2,6)，分组得到 4；(2,3) 只产生 (2,3,1)、(2,3,6)，分组得到 2，因此被过滤。

MySQL 8+ · 正式可提交 SQL

WITH neighbors AS (
    SELECT user1_id AS user_id, user2_id AS friend_id
    FROM Friendship
    UNION ALL
    SELECT user2_id AS user_id, user1_id AS friend_id
    FROM Friendship
)
SELECT f.user1_id, f.user2_id, COUNT(*) AS common_friend
FROM Friendship AS f
JOIN neighbors AS a
  ON a.user_id = f.user1_id
JOIN neighbors AS b
  ON b.user_id = f.user2_id
 AND b.friend_id = a.friend_id
GROUP BY f.user1_id, f.user2_id
HAVING COUNT(*) >= 3;

正确性

邻接表示完整：每条无向边生成两个方向，故记录 (u,w) 存在当且仅当 u 与 w 是好友。主键和 u < v 的保证使每条有向记录仅生成一次。

计数准确：固定原始关系 (u,v)，连接条件同时要求 (u,w) 和 (v,w) 存在，所以每行必然对应共同好友。反过来，每位共同好友都能满足两次连接，且唯一记录使它只贡献一行。因此分组计数恰好等于共同好友数。

输出等价：候选来自原表，保证已有关系且方向唯一；聚合过滤恰好保留共同好友数至少为 3 的组合，所以不漏合法结果，也不输出不合法或重复组合。

边界与常见错误

  • 只有共同好友但没有直接关系：不能输出；不要删掉原始好友表的约束。
  • 只有正向邻居：会漏掉 ID 小于当前用户的好友；必须补齐反向记录。
  • 计数乘倍：不要在双向表中同时聚合 (u,v) 与 (v,u)。当前查询直接从原表选候选。
  • 阈值是 ≥ 3；输出是完整数量，不能用布尔值或固定数字 3 代替。
  • 聚合后的过滤使用 HAVING；不要把 COUNT 条件放进 WHERE。
  • 自环和重复行不属于官方合法输入；若用于脏数据，先规范方向、去重、去自环，再沿用计数逻辑。
  • 空表、单边或低度节点都不能产生合格结果；不应补零行。ID 不必连续，不宜按最大 ID 分配数组。

复杂度：区分语义算法与 SQL 执行计划

令 m 为边数、n 为出现的用户数、d(u) 为用户度数。下方四种集合参考实现建图耗时 O(n+m)，沿每条边遍历较小邻居集，哈希查询平均 O(1)，因此期望时间为 O(n+m+Σ(u,v)∈E min(d(u),d(v)))，宽松上界 O(n+mΔ)，Δ 为最大度数。辅助空间 O(n+m)，另有至多 O(m) 的输出。哈希退化时不保证此期望时间。

SQL 的 CTE 具有 2m 行。若执行计划先按 u 取邻居，再对 (v,w) 做索引/哈希探测，候选探测量约为 Σ(u,v)∈Ed(u)，不会自动采用较小集合策略。JOIN 顺序、索引、物化与聚合方式由数据库决定；不能将它笼统视为 O(m) 时间或 O(m) 空间。若物化中间连接，空间还包含中间结果。这里没有执行 EXPLAIN 或性能测量。

替代方案

  • 先按共同好友 w 自连接所有邻居对，再连接原表：语义等价，但高连接度的 w 会产生 O(d(w)²) 个候选对。
  • 相关子查询对每条边计数：书写直观，性能取决于索引及优化器对相关查询的处理。
  • 通用语言中用排序邻接数组加双指针：每边 O(d(u)+d(v))，避免哈希的期望性能前提；大量稠密节点可考虑位集合求交并计数。

面试追问

为什么这里不需要 COUNT(DISTINCT w)？联合主键与标准方向使双向邻接记录唯一，每个 w 只匹配一次。如何优化查询？检查真实执行计划；邻接结构的 (user_id, friend_id) 访问路径可加快探测，但 CTE 是否利用索引要看引擎，不能假定。阈值改为 k 呢？只改 HAVING；若还要总数，仍需完整计数。新增一条边会怎样？不仅新增边可能产生结果，它还可能为其他已有关系新增共同好友；增量维护要追踪这些受影响的三角形。

Java · 本地语义参考

import java.util.*;

class Solution {
    public List<int[]> strongFriendship(int[][] friendship) {
        Map<Integer, Set<Integer>> graph = new HashMap<>();
        for (int[] edge : friendship) {
            int u = edge[0], v = edge[1];
            graph.computeIfAbsent(u, k -> new HashSet<>()).add(v);
            graph.computeIfAbsent(v, k -> new HashSet<>()).add(u);
        }
        List<int[]> result = new ArrayList<>();
        for (int[] edge : friendship) {
            Set<Integer> a = graph.get(edge[0]);
            Set<Integer> b = graph.get(edge[1]);
            if (a.size() > b.size()) {
                Set<Integer> temp = a; a = b; b = temp;
            }
            int count = 0;
            for (int w : a) if (b.contains(w)) count++;
            if (count >= 3)
                result.add(new int[]{edge[0], edge[1], count});
        }
        return result;
    }
}

JavaScript · 本地语义参考

function strongFriendship(friendship) {
  const graph = new Map();
  for (const [u, v] of friendship) {
    if (!graph.has(u)) graph.set(u, new Set());
    if (!graph.has(v)) graph.set(v, new Set());
    graph.get(u).add(v);
    graph.get(v).add(u);
  }
  const result = [];
  for (const [u, v] of friendship) {
    let a = graph.get(u), b = graph.get(v);
    if (a.size > b.size) [a, b] = [b, a];
    let count = 0;
    for (const w of a) if (b.has(w)) count++;
    if (count >= 3) result.push([u, v, count]);
  }
  return result;
}

from collections import defaultdict
from typing import List


def strong_friendship(friendship: List[List[int]]) -> List[List[int]]:
    graph = defaultdict(set)
    for u, v in friendship:
        graph[u].add(v)
        graph[v].add(u)
    result = []
    for u, v in friendship:
        a, b = graph[u], graph[v]
        if len(a) > len(b):
            a, b = b, a
        count = sum(1 for w in a if w in b)
        if count >= 3:
            result.append([u, v, count])
    return result

#include <array>
#include <unordered_map>
#include <unordered_set>
#include <utility>
#include <vector>

std::vector<std::array<int, 3>> strongFriendship(
    const std::vector<std::array<int, 2>>& friendship) {
    std::unordered_map<int, std::unordered_set<int>> graph;
    for (const auto& edge : friendship) {
        graph[edge[0]].insert(edge[1]);
        graph[edge[1]].insert(edge[0]);
    }
    std::vector<std::array<int, 3>> result;
    for (const auto& edge : friendship) {
        const auto* a = &graph.at(edge[0]);
        const auto* b = &graph.at(edge[1]);
        if (a->size() > b->size()) std::swap(a, b);
        int count = 0;
        for (int w : *a) if (b->count(w)) ++count;
        if (count >= 3)
            result.push_back({edge[0], edge[1], count});
    }
    return result;
}
