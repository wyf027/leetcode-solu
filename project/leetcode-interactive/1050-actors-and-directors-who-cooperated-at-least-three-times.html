1050. 合作过至少三次的演员和导演

Actors and Directors Who Cooperated At Least Three Times

GROUP BYHAVING分组聚合

题目

ActorDirector 表记录演员与导演的每次合作。找出所有至少合作过三次的 (actor_id, director_id)，结果顺序任意。

列名类型说明
actor_idint演员 ID
director_idint导演 ID
timestampint主键，唯一标识一次合作

官方示例

输入：ActorDirector

+----------+-------------+-----------+
| actor_id | director_id | timestamp |
+----------+-------------+-----------+
| 1        | 1           | 0         |
| 1        | 1           | 1         |
| 1        | 1           | 2         |
| 1        | 2           | 3         |
| 1        | 2           | 4         |
| 2        | 1           | 5         |
| 2        | 1           | 6         |
+----------+-------------+-----------+

输出（任意顺序）

+----------+-------------+
| actor_id | director_id |
+----------+-------------+
| 1        | 1           |
+----------+-------------+

只有 (1, 1) 恰好合作 3 次。

约束

  • timestamp 是具有唯一值的主键。
  • 每行代表一次独立合作。
  • 输出合作次数大于或等于 3 的 ID 对。

交互可视化：合作计数器

分组状态

先想一想

我们过滤的不是原始行，而是聚合后的分组。应该使用哪个 SQL 子句？

题解

核心洞察

按 actor_id, director_id 分组，用 COUNT(*) 统计每组合作记录，再用 HAVING 保留至少 3 条的组。

完整过程

  1. 以演员 ID 和导演 ID 组成分组键。
  2. 统计各组行数。
  3. 保留 COUNT(*) >= 3 的分组。
  4. 输出两个 ID。

正确性

同一分组恰好包含该演员与该导演的全部合作行，所以组内行数就是合作次数。聚合条件保留且只保留次数至少为 3 的组合，故结果正确。

边界

  • 恰好 3 次必须保留。
  • 少于 3 次排除。
  • 不同演员或导演必须分别计数。

复杂度

设记录数为 n、不同组合数为 k。概念上的哈希聚合时间 O(n)，额外空间 O(k)；实际取决于数据库执行计划。

官方可提交 SQL

SELECT actor_id, director_id
FROM ActorDirector
GROUP BY actor_id, director_id
HAVING COUNT(*) >= 3;

替代方案

窗口函数加 DISTINCT 也可完成，但会保留中间行；三表自连接更复杂且容易产生组合爆炸，直接分组最清晰。

四语言本地语义参考

本题是数据库题，官方提交语言以 SQL（及 Pandas）为主。下列四份代码只演示内存数据的同等分组语义，并非本站 SQL 判题的可提交替代品。

import java.util.*;
class Solution {
  public List<int[]> solve(int[][] rows) {
    Map<String,Integer> c = new LinkedHashMap<>();
    for (int[] r : rows) {
      String k = r[0] + "," + r[1];
      c.put(k, c.getOrDefault(k, 0) + 1);
    }
    List<int[]> ans = new ArrayList<>();
    for (var e : c.entrySet()) if (e.getValue() >= 3) {
      String[] p = e.getKey().split(",");
      ans.add(new int[]{Integer.parseInt(p[0]), Integer.parseInt(p[1])});
    }
    return ans;
  }
}
function solve(rows) {
  const count = new Map();
  for (const [a, d] of rows) {
    const key = a + "," + d;
    count.set(key, (count.get(key) ?? 0) + 1);
  }
  return [...count].filter(([, n]) => n >= 3)
    .map(([key]) => key.split(",").map(Number));
}
from collections import Counter
from typing import List
class Solution:
    def solve(self, rows: List[List[int]]) -> List[List[int]]:
        counts = Counter((a, d) for a, d, _ in rows)
        return [[a, d] for (a, d), n in counts.items() if n >= 3]
#include <map>
#include <vector>
using namespace std;
class Solution {
public:
  vector<vector<int>> solve(const vector<vector<int>>& rows) {
    map<pair<int,int>, int> count;
    for (const auto& r : rows) ++count[{r[0], r[1]}];
    vector<vector<int>> ans;
    for (const auto& [p, n] : count)
      if (n >= 3) ans.push_back({p.first, p.second});
    return ans;
  }
};

面试追问

  • 为什么不用 WHERE COUNT(*)？ WHERE 在分组前过滤行，聚合值应由 HAVING 过滤。
  • COUNT(timestamp) 可以吗？ 可以，因为主键非空；COUNT(*) 更直观。
  • 如何优化？ 可考虑 (actor_id, director_id) 复合索引，实际收益需看执行计划。

常见错误

  • 只按一个 ID 分组。
  • 写成 > 3 漏掉恰好三次。
  • 把聚合条件放到 WHERE。
  • 误用 DISTINCT 计数改变语义。
