制造字母异位词的最小步骤数

两条等长字符串，一次替换一个字符。先别急着看答案：试着用下面的“字母账本”观察，究竟有哪些字符是 t 欠 s 的。

MEDIUM非付费题哈希表字符串计数

Problem brief

题目说了什么

给定两个长度相等的字符串 s 和 t。每一步可以在 t 中选择任意一个字符，并将它替换成另一个字符。返回使 t 成为 s 的字母异位词所需的最少步骤数。

字母异位词

两个字符串所含字符及每种字符的数量完全相同，排列顺序可以不同，也可以相同。

约束

  • 1 <= s.length <= 5 × 10⁴
  • s.length == t.length
  • s 与 t 仅含小写英文字母
EXAMPLE 01
输入：s = "bab", t = "aba"\n输出：1

将 t 中一个多余的 a 替换为缺少的 b，即可得到 s 的字母异位词。

EXAMPLE 02
输入：s = "leetcode", t = "practice"\n输出：5

t 需要补齐 s 所缺的 5 个字符，因此最少替换 5 次。

EXAMPLE 03
输入：s = "anagram", t = "mangaar"\n输出：0

两者的字符频次已经完全一致，无需替换。

01 · Core insight

核心洞察：只统计 t 的缺口

建立长度为 26 的频次数组。对每个位置，让 s[i] 对应计数加一，让 t[i] 对应计数减一。最终某个计数为正，表示 t 比 s 少了这么多个该字母；把所有正数相加，就是最少替换次数。

answer = Σ max(count[s 的字母] − count[t 的字母], 0)

为什么不把绝对值全部相加？因为一次替换同时消掉一个“多余”和一个“缺少”，只数缺少的一侧即可。

02 · Walkthrough

完整过程

  1. 创建 diff[26]，全部初始化为 0。
  2. 同步遍历 s 与 t：将 s 当前字符的槽位加 1，将 t 当前字符的槽位减 1。
  3. 遍历 26 个槽位，只将大于 0 的值加入答案。
  4. 返回答案。无需真的构造替换后的字符串。

以 s = "bab"，t = "aba" 为例：最终差值中 b = +1、a = −1。t 缺一个 b，同时多一个 a，把那个 a 替换成 b，只需 1 步。

03 · Correctness

正确性证明

下界

若 t 对某个字母 c 缺少 d 个，则任何最终成为 s 异位词的方案都必须在 t 中新产生至少 d 个 c。一次替换最多新产生一个所需字符，所以总替换次数至少是所有正缺口之和。

可达

因为两字符串等长，所有缺少字符的总数等于所有多余字符的总数。每次任选一个多余字符，把它替换为一个缺少字符，就能让总缺口减少 1。

结论

存在恰好用“正缺口之和”次替换完成目标的方案，并且任何方案都不能更少，因此算法返回最小步骤数。

04 · Bounds

边界与复杂度

  • 两字符串完全相同或已经互为异位词：所有正缺口之和为 0。
  • 长度为 1 且字符不同：一个槽位为 +1，答案为 1。
  • 大量重复字符：频次统计不受排列与重复影响。
时间复杂度 O(n)扫描两个字符串各一次，再扫描固定的 26 个字母。
空间复杂度 O(1)只使用固定长度 26 的数组，与输入规模无关。

05 · Implementations

四语言完整代码

class Solution {
    public int minSteps(String s, String t) {
        int[] diff = new int[26];

        for (int i = 0; i < s.length(); i++) {
            diff[s.charAt(i) - 'a']++;
            diff[t.charAt(i) - 'a']--;
        }

        int answer = 0;
        for (int value : diff) {
            if (value > 0) {
                answer += value;
            }
        }
        return answer;
    }
}

06 · Alternatives

替代方案

两个频次数组分别统计 s 与 t，再累加 max(freqS[i] - freqT[i], 0)。更直观，但多用一个固定数组。
哈希表适用于字符集不固定或包含 Unicode 的扩展版本。本题只有 26 个小写字母，数组更简单高效。

排序后比较并不能直接逐位置求不同：异位词允许重新排列。即便设计可行的排序方案，也会需要 O(n log n) 时间，不如计数。

07 · Follow-ups

面试追问

如果 s 和 t 不保证等长呢？

先明确操作定义。若仍只允许替换，长度不同则无解；若允许插入和删除，就会变成另一类编辑问题。

如果字符不只限于 a～z 呢？

使用哈希表记录 Unicode 字符频次。若按用户可见字符处理，还需要关注组合字符与 grapheme cluster。

为什么答案不是正负差值绝对值之和？

绝对值之和会把同一次替换的两端各数一次，因此需要除以 2；直接累加正差值更不易出错。

能否给出具体替换方案？

可以分别收集缺少字符与多余字符列表，一一配对；最小次数仍是缺少列表的长度。

08 · Pitfalls

常见错误

  • 逐位置比较 s[i] 与 t[i]；这忽略了异位词可以任意重排。
  • 累加所有差值的绝对值却忘记除以 2，导致答案翻倍。
  • 只统计 s，却没有用 t 抵消已有字符。
  • 真的反复修改字符串，造成不必要的构造与更复杂的逻辑。
  • 把空间复杂度写成 O(26) 而未说明它在渐进意义上是 O(1)。
