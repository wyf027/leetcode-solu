LeetCode 1357 · System Design

每隔 n 个顾客打折

设计一台会“记住顾客序号”的收银机：商品怎么计价很直接，真正的关键是跨调用维护状态，并在恰好的那一单触发折扣。

中等 设计 数组 哈希表 非付费题

Problem

题意与接口

一家超市用两个等长数组 products 和 prices 保存商品编号与单价。每位顾客的购物清单同样由两个等长数组 product 和 amount 表示，其中每个位置对应一种商品及其购买数量。

收银系统按结账顺序持续统计顾客数。每逢第 n 位顾客，该顾客整张账单享受 discount% 的折扣；之后继续按同样的周期计数。其余顾客按原价结算。

finalBill = subtotal × (100 − discount) / 100

实现 Cashier 类：构造函数保存折扣规则和商品价格；getBill 计算本次购物的小计，并根据当前顾客序号决定是否打折。浮点结果允许与标准答案存在不超过 10^-5 的误差。

构造函数

Cashier(
  int n,
  int discount,
  int[] products,
  int[] prices
)

结账方法

double getBill(
  int[] product,
  int[] amount
)

状态提醒

  • 商品价格在构造时确定。
  • 顾客计数必须跨方法调用保留。
  • 一次 getBill 就是一位新顾客。

Constraints

约束

  • 1 ≤ n ≤ 10^4
  • 0 ≤ discount ≤ 100
  • 1 ≤ products.length ≤ 200
  • prices.length == products.length
  • 1 ≤ products[i] ≤ 200
  • 1 ≤ prices[i] ≤ 1000
  • products 中的编号互不相同
  • 1 ≤ product.length ≤ products.length
  • amount.length == product.length
  • product[j] 一定存在于 products
  • 1 ≤ amount[j] ≤ 1000
  • product 中的编号互不相同
  • getBill 最多调用 1000 次

Solution

状态计数 + 商品价格映射

核心洞察：价格查询是“空间换时间”，折扣触发是“跨调用维护一个计数器”。两件事彼此独立。

完整过程

  1. 构造时建立 商品编号 → 单价 的映射。
  2. 保存 n、折扣比例和初始为 0 的顾客计数。
  3. 每次调用 getBill，遍历购物清单并累加 price × amount。
  4. 将顾客计数加一；若它能被 n 整除，则乘以 (100-discount)/100。
  5. 返回最终金额。

边界情况

  • n = 1：每一单都打折。
  • discount = 0：触发折扣也不改变金额。
  • discount = 100：第 n 单实付为 0。
  • 只买一种商品或买满全部商品，逻辑完全相同。
  • 使用浮点乘法计算百分比，避免整数除法截断。

正确性证明

引理 1：小计正确。价格映射保存了每个合法商品编号的唯一官方单价。遍历清单时，对第 i 项累加 price[product[i]] × amount[i]，因此遍历结束后的和恰好等于本单所有商品费用之和。
引理 2：折扣触发正确。计数器初始为 0，并在每次 getBill 中恰好增加 1，所以第 k 次调用后它等于已服务顾客数 k。当且仅当 k % n = 0 时，当前顾客是第 n, 2n, 3n, … 位顾客。
定理：返回金额正确。由引理 1 得到准确小计。若当前序号不是 n 的倍数，算法返回原小计；若是倍数，则按题意乘以 (100-discount)/100。结合引理 2，两种情况都与规则一致，因此算法总能返回正确账单。

复杂度

构造时间：O(P) 单次结账：O(K) 额外空间：O(P)

P 是超市商品种数，K 是当前顾客购买的商品种数。

Implementations

四语言完整代码

import java.util.HashMap;
import java.util.Map;

class Cashier {
    private final int n;
    private final double multiplier;
    private final Map<Integer, Integer> priceByProduct;
    private int customerCount;

    public Cashier(int n, int discount, int[] products, int[] prices) {
        this.n = n;
        this.multiplier = (100.0 - discount) / 100.0;
        this.customerCount = 0;
        this.priceByProduct = new HashMap<>();

        for (int i = 0; i < products.length; i++) {
            priceByProduct.put(products[i], prices[i]);
        }
    }

    public double getBill(int[] product, int[] amount) {
        double subtotal = 0.0;
        for (int i = 0; i < product.length; i++) {
            subtotal += priceByProduct.get(product[i]) * amount[i];
        }

        customerCount++;
        if (customerCount % n == 0) {
            subtotal *= multiplier;
        }
        return subtotal;
    }
}

from typing import List


class Cashier:
    def __init__(
        self,
        n: int,
        discount: int,
        products: List[int],
        prices: List[int]
    ):
        self.n = n
        self.multiplier = (100 - discount) / 100
        self.customer_count = 0
        self.price_by_product = dict(zip(products, prices))

    def getBill(self, product: List[int], amount: List[int]) -> float:
        subtotal = sum(
            self.price_by_product[item] * quantity
            for item, quantity in zip(product, amount)
        )

        self.customer_count += 1
        if self.customer_count % self.n == 0:
            subtotal *= self.multiplier
        return subtotal
class Cashier {
private:
    int n;
    int customerCount;
    double multiplier;
    unordered_map<int, int> priceByProduct;

public:
    Cashier(int n, int discount,
            vector<int>& products, vector<int>& prices)
        : n(n), customerCount(0),
          multiplier((100.0 - discount) / 100.0) {
        for (int i = 0; i < static_cast<int>(products.size()); ++i) {
            priceByProduct[products[i]] = prices[i];
        }
    }

    double getBill(vector<int> product, vector<int> amount) {
        double subtotal = 0.0;
        for (int i = 0; i < static_cast<int>(product.size()); ++i) {
            subtotal += priceByProduct[product[i]] * amount[i];
        }

        ++customerCount;
        if (customerCount % n == 0) {
            subtotal *= multiplier;
        }
        return subtotal;

替代方案

直接价格数组：由于商品编号最大为 200，可以建立长度 201 的数组，用编号直接索引。它常数更小，空间仍是 O(编号上界)，但哈希映射更通用，也更直接表达“编号到单价”的关系。

周期计数重置：计数器也可以只保存 1…n，打折后重置为 0。与取模方案等价；取模写法更短，重置写法则不会让计数持续增长。

面试追问

  • 如果不同商品折扣不同，数据结构怎么调整？
  • 若多个收银台共享顾客序号，如何保证并发下不重复或跳号？
  • 如果价格会动态变更，当前购物车应使用下单价还是结账价？
  • 金额必须精确到分时，为什么应使用整数分或十进制定点数？

常见错误

  • 把顾客计数写成 getBill 的局部变量，导致每次都从头开始。
  • 先判断再自增，造成第 n+1 位顾客才打折。
  • 用整数表达式 (100-discount)/100，折扣比例被截断成 0。
  • 错误地对第 n 件商品打折，而题目要求对第 n 位顾客整单打折。

一句话记忆

先查价求和，再给顾客编号；编号逢 n，整单乘折扣。
