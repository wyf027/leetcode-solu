    SIDE B1 · CORE INSIGHT

    核心洞察：i 定开头，j 找边界

    ANCHOR i

    锁定当前游程首字符

    i 指向还未处理的第一个字符，它决定这一组要“报什么”。

    SCAN j

    向右找到第一个不同字符

    只要 current[j] == current[i] 就继续右移；组长度就是 j - i。

    RECORD

    追加长度与字符

    输出追加 (j - i) 和 current[i]，再令 i = j 处理下一组。

    循环不变量

    每次外层循环开始时，索引 i 之前的所有字符都已被完整、且只被编码一次。

    SIDE B2 · PROCEDURE

    完整解题过程

    1. 1

      从基准字符串 "1" 开始

      若 n=1，直接返回；否则一共进行 n−1 轮编码。

    2. 2

      每轮建立空的 next

      next 只收集本轮编码结果，不要边读边修改 current。

    3. 3

      用 i、j 扫描一个极大连续组

      j 从 i+1 出发，直到越界或字符不同；当前组正好是区间 [i, j)。

    4. 4

      追加 count + digit

      把 j-i 转成字符串，再追加 current[i]，然后跳到 i=j。

    5. 5

      一轮结束后替换 current

      完成 n−1 轮后，current 就是第 n 项。

    COMPLEXITY

    O(Σ Lₖ)

    时间：逐字符扫描第 1 到 n−1 项；Lₖ 是第 k 项长度。

    O(Lₙ)

    空间：同时保存 current 与 next；输出本身长度为 Lₙ。

    EDGE TRACKS

    • • n=1：零轮转换，直接返回 "1"。
    • • 最后一组一直延伸到字符串末尾：j 可等于 length。
    • • 单字符组也要记录，长度为 1。
    • • 算法应支持多位组长度，不能把 count 当单个字符。

    SIDE B3 · ALTERNATIVES

    替代方案与取舍

    递归生成前一项

    定义贴近题面，但额外占用 O(n) 调用栈；官方追问更希望迭代。

    正则表达式分组

    写法短，但不同语言差异大，也掩盖了游程边界的核心逻辑。

    原地字符数组

    长度会变化，原地搬移复杂且没有收益；新建 next 更稳妥。

    SIDE B4 · INTERVIEW

    面试高频追问

    “极大连续组”是什么意思？
    组内字符相同，且它左边、右边若存在字符，都与组内字符不同。
    为什么总复杂度不是简单 O(n)？
    每轮处理的字符串长度不同，真实工作量是各轮长度之和。
    能只保存一项吗？
    每轮只依赖上一项，因此无需保存完整数列；current 与 next 足够。
    输入 "3322251" 怎么编码？
    分成 "33"、"222"、"5"、"1"，输出 "23" + "32" + "15" + "11" = "23321511"。

    SIDE B5 · BAD TAKES

    常见错误

    ERROR 01

    统计全局频次

    题目统计连续组，不能用哈希表合并分散字符。

    ERROR 02

    漏掉末尾一组

    用 [i,j) 统一处理，让 j 自然走到 length。

    ERROR 03

    少做或多做一轮

    第 1 项已存在，因此循环次数严格为 n−1。

    ERROR 04

    边读边改 current

    会破坏尚未扫描的输入，必须写入独立 next。
