字符串中最大的 3 位相同数字

Largest 3-Same-Digit Number in String

从一串数字中，找出符合条件的连续片段。先理解题目，再用可视化观察，最后展开题解。

题意交互实验测试与验证题解入口

01 / 题意与约束

给定仅含数字的字符串 num。请从中选出长度恰好为 3、且三个字符完全相同的连续子字符串，返回其中数值最大的一个，返回类型为字符串。如果不存在，返回空字符串 ""。

输入和答案都允许前导零，因此 "000" 是有效答案。子字符串必须连续，不能跳过中间字符。

参数：num: string　返回：string
约束：3 ≤ num.length ≤ 1000；字符仅为 0–9。

官方示例 1

输入：num = "6777133339"
输出："777"

不同的合格片段为 "777" 和 "333"，其中 "777" 最大。

官方示例 2

输入：num = "2300019"
输出："000"

只有 "000" 合格，返回时保留三个零。

官方示例 3

输入：num = "42352338"
输出：""

没有三个连续且相同的数字。

04 / 独立题解

准备好后，查看推导、四语言实现与面试延伸。

核心洞察：只检查连续三个字符

每个合法答案必然对应某个长度为 3 的窗口。枚举窗口起点 i = 0…n−3，检查 num[i] = num[i+1] = num[i+2]。三个字符相同时，取出片段，与已记录的答案比较。

所有候选片段都长 3 且只含十进制数字，因此字典序与数值大小一致。直接比较字符串即可，既不需要解析大整数，也能保留前导零。用空字符串表示“尚未找到”。

完整过程

  1. 初始化 best = ""。
  2. 从左到右枚举所有合法起点，每次向右移动一格，允许窗口重叠。
  3. 若三个字符相同，令 candidate 为这三个字符；当 best 为空或 candidate 更大时更新 best。
  4. 遍历结束，返回 best。

以 num = "6777133339" 为例，窗口依次是 677、777、771、713、133、333、333、339。第二个窗口使 best 变为 "777"；两个 "333" 窗口均更小，最终保留 "777"。

正确性证明

循环不变式：每处理完一个起点，best 都是目前处理过的所有合格窗口中最大的字符串；如果没有合格窗口，则为空。

初始未处理任何窗口，空字符串符合定义。处理新窗口时，不合格则无需更新；合格则与 best 取较大者，仍满足不变式。所有长度为 3 的连续子串恰好有一个起点，遍历覆盖全部起点，因此终止时 best 就是全局最大合格片段，或在无解时为空。

边界与复杂度

  • n = 3 时恰好检查一次；起点上限必须包含 n−3。
  • "000" 合法，不能用数值 0 表示“没找到”。
  • 四个相同数字包含两个重叠窗口，答案仍是三个字符。
  • 时间 O(n)：共有 n−2 个窗口，每次最多比较或复制 3 个字符。
  • 额外空间 O(1)：只保存固定长度的候选与答案。可视化为了回退保存历史，不计入提交算法空间。

四语言完整提交代码

以下实现均匹配官方函数名；仅生成，未编译或运行。

Java

class Solution {
    public String largestGoodInteger(String num) {
        String best = "";
        for (int i = 0; i + 2 < num.length(); i++) {
            if (num.charAt(i) == num.charAt(i + 1)
                    && num.charAt(i) == num.charAt(i + 2)) {
                String candidate = num.substring(i, i + 3);
                if (candidate.compareTo(best) > 0) {
                    best = candidate;
                }
            }
        }
        return best;
    }
}

var largestGoodInteger = function(num) {
    let best = "";
    for (let i = 0; i + 2 < num.length; i++) {
        if (num[i] === num[i + 1] && num[i] === num[i + 2]) {

            if (candidate > best) best = candidate;
        }
    }
    return best;

#include <string>
using std::string;

class Solution {
public:
    string largestGoodInteger(string num) {
        string best = "";
        for (int i = 0; i + 2 < static_cast<int>(num.size()); ++i) {
            if (num[i] == num[i + 1] && num[i] == num[i + 2]) {
                string candidate = num.substr(i, 3);
                if (candidate > best) best = candidate;
            }
        }
        return best;
    }
};

替代方案

按 "999"、"888"、…、"000" 的顺序检查字符串中是否包含候选。第一个存在的就是答案；全部不存在则返回 ""。这是官方提示提供的方向。最多进行 10 次固定长度模式查找，直接扫描实现的时间为 O(10n) = O(n)，额外空间 O(1)。也可维护连续相同字符的计数，计数达到 3 时更新最大数字。

常见错误

  • 先排序输入：会破坏连续性，产生原本不存在的片段。
  • 遇到第一个合格窗口就返回：后面可能出现更大值；只有 "999" 可安全提前返回。
  • 窗口每次移动 3 位：会漏掉起点不在 3 的倍数处的答案。
  • 把整串转为 Number 或整数：没有必要，且长输入会溢出或丢失精度。
  • 把结果转成整数："000" 会变成 0，违反字符串返回形式。

面试追问

  • 改成 k 个相同数字？维护当前字符和连续长度，在长度达到 k 时更新最大字符，最后重复 k 次；时间 O(n+k)，输出之外额外空间 O(1)。
  • 输入是数据流？保存上一字符、当前连续长度和已发现的最大数字即可，无需保留整串。
  • 为什么能用字典序？候选长度相同，字符范围为 0–9；首个不同位也决定数值大小。可变长度字符串则不能直接照搬。
