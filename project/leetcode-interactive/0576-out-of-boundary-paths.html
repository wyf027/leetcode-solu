576. 出界的路径数

Out of Boundary Paths——从一个落在网格里的球开始，逐步观察不同移动序列如何穿过边界。先读题、动手实验；完整思路保持收起。

难度 · Medium 非付费题 函数 · findPaths 取模 · 10⁹ + 7
01 / Problem

题目

球每次只能走向上、下、左、右四个相邻位置；一步跨过网格边界，就形成一条有效的出界路径。

任务描述

给定一个 m × n 的网格，球最初位于 [startRow, startColumn]。你最多可以移动球 maxMove 次，每次选择四个正交方向之一，移动后可以留在网格中，也可以越过边界。

返回能够让球在不超过 maxMove 次移动内离开网格的移动路径数量。答案可能很大，需要对 1,000,000,007 取模。

不同的方向序列视为不同路径；一旦球已经出界，该路径就结束，不再继续移动。

参数形式

m, n
网格的行数与列数
maxMove
允许移动的最大次数
startRow
起点行下标
startColumn
起点列下标
return
出界路径数取模后的整数

Core Insight

用“当前仍在网格内的路径数”逐层转移

枚举所有方向序列会产生指数级分支，但许多序列会在同一步汇合到同一个格子。后续行为只取决于当前位置和还可移动的次数，因此可以把汇合后的路径数量合并。

令 dp[r][c] 表示恰好完成当前步数后，仍留在格子 (r,c) 的路径数量。把这些数量沿四个方向推向下一层：

越界 → answer += dp[r][c]　｜　未越界 → next[nr][nc] += dp[r][c]

每一层只依赖上一层，所以保留 dp 与 next 两张二维表即可。

Process

完整过程

  1. 创建 m × n 的计数表，把起点设为 1，其余位置为 0。
  2. 从第 1 次移动迭代到第 maxMove 次移动，每轮新建全零的 next。
  3. 枚举所有格子。若某格的路径数为 ways，就尝试上、下、左、右四个目标。
  4. 目标在边界外时，把 ways 累加进答案；目标仍在网格内时，把 ways 累加到 next 的目标格。
  5. 本轮结束后令 dp = next，进入下一轮；所有加法都及时取模。
  6. 迭代完成后返回累计出界数量。
Correctness

正确性证明

不变式：第 t 轮开始时，dp[r][c] 等于恰好移动 t - 1 次后仍位于 (r,c) 的路径数；answer 等于至多移动 t - 1 次已经出界的路径数。

初始化：在任何移动发生前，只有一条空路径停在起点，其他格子计数为零，且没有路径出界，所以不变式成立。

保持：任意仍在格子内的路径下一步恰有四种选择。算法逐一处理：若目标越界，该路径唯一地加入答案；否则唯一地加入目标格的下一层计数。所有路径都被处理一次，且没有遗漏或重复，因此下一轮不变式仍成立。

终止：完成 maxMove 轮后，答案恰好包含在 1 到 maxMove 次移动中首次越界的全部路径，即题目要求的结果。

Edge Cases

边界处理

  • maxMove = 0：循环不会执行，球不可能离开，直接返回 0。
  • m = 1 或 n = 1：同一步可能有多个方向立即出界，每个方向都代表不同路径，必须分别计数。
  • 角落格子有两个直接出界方向，边缘非角落格子有一个；不需要特判，统一的坐标检查会自然覆盖。
  • 球一旦出界就不再进入后续状态，因此越界路径只累加答案，不写入 next。
  • 每次累加后取模，避免数值持续膨胀。
Complexity

复杂度

时间O(maxMove · m · n)

每轮扫描全部格子，每格只检查四个方向。

空间O(m · n)

滚动保存当前层与下一层两张计数表。

Implementation

Java、JavaScript、Python、C++

四份实现使用同一套滚动二维动态规划，并保持 LeetCode 官方函数签名。

Solution.java
class Solution {
    private static final int MOD = 1_000_000_007;
    private static final int[][] DIRS = {
        {-1, 0}, {1, 0}, {0, -1}, {0, 1}
    };

    public int findPaths(int m, int n, int maxMove,
                         int startRow, int startColumn) {
        long[][] dp = new long[m][n];
        dp[startRow][startColumn] = 1;
        long answer = 0;

        for (int move = 1; move <= maxMove; move++) {
            long[][] next = new long[m][n];

            for (int row = 0; row < m; row++) {
                for (int col = 0; col < n; col++) {
                    long ways = dp[row][col];
                    if (ways == 0) {
                        continue;
                    }

                    for (int[] dir : DIRS) {
                        int nextRow = row + dir[0];
                        int nextCol = col + dir[1];

                        if (nextRow < 0 || nextRow >= m
                                || nextCol < 0 || nextCol >= n) {
                            answer = (answer + ways) % MOD;
                        } else {
                            next[nextRow][nextCol] =
                                (next[nextRow][nextCol] + ways) % MOD;
                        }
                    }
                }
            }
            dp = next;
        }

        return (int) answer;
    }
}

var findPaths = function(m, n, maxMove, startRow, startColumn) {
    const MOD = 1_000_000_007;
    const directions = [[-1, 0], [1, 0], [0, -1], [0, 1]];
    let dp = Array.from({ length: m }, () => Array(n).fill(0));
    dp[startRow][startColumn] = 1;
    let answer = 0;

    for (let move = 1; move <= maxMove; move++) {
        const next = Array.from({ length: m }, () => Array(n).fill(0));

        for (let row = 0; row < m; row++) {
            for (let col = 0; col < n; col++) {
                const ways = dp[row][col];
                if (ways === 0) continue;

                for (const [dr, dc] of directions) {
                    const nextRow = row + dr;
                    const nextCol = col + dc;

                        nextCol < 0 || nextCol >= n) {
                        answer = (answer + ways) % MOD;
                    } else {
                        next[nextRow][nextCol] =
                            (next[nextRow][nextCol] + ways) % MOD;
                    }
                }
            }
        }
        dp = next;
    }

    return answer;

Solution.cpp
class Solution {
public:
    int findPaths(int m, int n, int maxMove,
                  int startRow, int startColumn) {
        static constexpr int MOD = 1'000'000'007;
        static constexpr int DIRS[4][2] = {
            {-1, 0}, {1, 0}, {0, -1}, {0, 1}
        };

        vector<vector<long long>> dp(m, vector<long long>(n));
        dp[startRow][startColumn] = 1;
        long long answer = 0;

        for (int move = 1; move <= maxMove; ++move) {
            vector<vector<long long>> next(
                m, vector<long long>(n)
            );

            for (int row = 0; row < m; ++row) {
                for (int col = 0; col < n; ++col) {
                    long long ways = dp[row][col];
                    if (ways == 0) continue;

                    for (const auto& dir : DIRS) {
                        int nextRow = row + dir[0];
                        int nextCol = col + dir[1];

                        if (nextRow < 0 || nextRow >= m ||
                            nextCol < 0 || nextCol >= n) {
                            answer = (answer + ways) % MOD;
                        } else {
                            next[nextRow][nextCol] =
                                (next[nextRow][nextCol] + ways) % MOD;
                        }
                    }
                }
            }
            dp = move(next);
        }

        return static_cast<int>(answer);
    }
};

Alternatives

替代方案

记忆化搜索

定义 dfs(r,c,movesLeft) 为从当前位置、剩余步数出发的出界路径数。越界返回 1，步数耗尽返回 0，其余递归四个方向并缓存。时间同为 O(maxMove·m·n)，表达直接，但递归与三维缓存的常数更高。

三维动态规划

保存 dp[move][r][c] 能完整保留每一层，便于回溯或展示，但本题返回值只依赖逐层累计，空间可从 O(maxMove·m·n) 压缩到 O(m·n)。

暴力枚举路径

每一步最多产生 4 个分支，最坏接近 O(4^maxMove)，在 maxMove = 50 时不可行。它只适合极小数据下理解题意。

矩阵快速幂

可以把每个格子视作状态并建立转移矩阵，但状态数最多 2500，矩阵代价远高于 50 次普通迭代，不适合本题约束。

Interview Follow-ups

面试追问

Q1：为什么答案是“至多”步而不是“恰好”步？

因为每一轮一旦越界就立刻累加答案，前面轮次的结果不会被丢弃；最终自然覆盖 1 到 maxMove 步。

Q2：能否原地更新同一张表？

不能直接原地推送，否则本轮刚写入的数量可能又在同一轮被使用，混淆移动层数。必须使用下一层表，或采用其他能隔离层次的结构。

Q3：如果每个方向概率不同呢？

把路径计数改成概率质量，转移时乘对应方向概率；越界时累计概率。状态结构仍然相同，但需考虑浮点误差。

Q4：如果有障碍格呢？

转移到障碍时按规则选择“禁止移动”或“路径终止”；只需在写入下一层前增加障碍判断，核心分层思想不变。

Common Mistakes

常见错误

只统计最后一轮

题目要求最多移动 maxMove 次，必须累计每一轮新增的出界路径。

让越界路径继续传播

一旦出界路径已经完成，不能再把它写进下一轮，否则会重复计数。

复用未清零的 next

下一层必须每轮重新置零，否则旧层数据会混入新层。

取模太晚

在每次累加时取模；尤其在定长整数语言里，可以避免中间值溢出。

把“方向”合并掉

角落向两个不同方向出界属于两条路径，即使它们都落在网格外。

起点层数偏一

初始表表示第 0 步，循环一次才表示完成第 1 次移动。
