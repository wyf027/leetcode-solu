Minimum Increment to Make Array Unique

只允许把元素加一，怎样用最少操作消除所有重复值？先试着观察下面的数组如何“向右让位”。

题目

给定整数数组 nums。一次操作可选择任意下标 i（0 ≤ i < nums.length），令 nums[i] 增加 1。返回让数组中每个值都互不相同所需的最少操作次数。题目保证答案处于 32 位整数范围内。

示例 1
输入：nums = [1,2,2]
输出：1
解释：把一个 2 增加为 3，得到 [1,2,3]。
示例 2
输入：nums = [3,2,1,2,1,7]
输出：6
解释：一种最优结果是 [3,4,1,2,5,7]；
总增量为 6，少于 6 次无法做到。

约束

  • 1 ≤ nums.length ≤ 105
  • 0 ≤ nums[i] ≤ 105

Solution

准备好后再揭晓

题解：排序 + 贪心占位

核心洞察：排序后，从左到右让每个数尽量小，但必须严格大于前一个最终值。对第 i 项，唯一最优的落点是 max(nums[i], nums[i−1] + 1)。

完整过程

  1. 将 nums 升序排序。
  2. 从第二项开始扫描。
  3. 若当前值 nums[i] ≤ nums[i-1]，需要增加 nums[i-1]+1-nums[i] 次。
  4. 把当前值更新为 nums[i-1]+1，继续处理后项。

示例轨迹

[3,2,1,2,1,7] 排序为 [1,1,2,2,3,7]，依次安置为 [1,2,3,4,5,7]，增量分别为 0,1,1,2,2,0，总计 6。

复杂度

排序耗时 O(n log n)，扫描耗时 O(n)；若原地排序，除排序栈外额外空间通常为 O(log n)（依语言实现而定）。

正确性证明

按排序后的顺序归纳。第一个数不动显然最优。假设前 i−1 项已经以最小代价占据了严格递增的位置，设最后位置为 p。第 i 个原值为 x：它既不能减少，也不能落在不大于 p 的位置，因此任何合法解都必须把它放到至少 max(x,p+1)。贪心恰好选择这个下界，没有多做任何操作。于是当前前缀仍最优；归纳至末尾，所得总操作数全局最小。

边界

  • 只有一个元素：无需操作。
  • 本来已唯一：排序后不会产生增量。
  • 全部相同：形成连续递增序列。
  • 累计答案用语言中足够大的整数类型承接；Java 使用 int 符合本题保证。

常见错误

  • 只用集合寻找空位，逐次加一会退化得很慢。
  • 只和原数组前一项比较，而不是和“调整后的”前一项比较。
  • 重复值统一加一，可能制造新的冲突。
  • 忘记排序就直接应用相邻贪心。

替代方案

可用计数数组把某个值的多余出现次数向右搬运，复杂度约为 O(n + U)，其中 U 覆盖最大值与可能的溢出区间；在值域有限时可避免比较排序。也可用并查集“找下一个空位”，但实现更复杂，面试中排序贪心通常最清楚。

面试追问

  • 如果既允许加一也允许减一，目标会变成什么？（需要为排序后元素选择互异整数，可讨论中位数、匹配或动态规划。）
  • 能否做到线性时间？（当值域有界时用计数搬运。）
  • 为什么交换两个排序后元素的最终位置不会更优？（交叉分配可交换为保持顺序且不增加总增量。）

四种语言实现

import java.util.Arrays;

class Solution {
    public int minIncrementForUnique(int[] nums) {
        Arrays.sort(nums);
        int moves = 0;
        for (int i = 1; i < nums.length; i++) {
            if (nums[i] <= nums[i - 1]) {
                int target = nums[i - 1] + 1;
                moves += target - nums[i];
                nums[i] = target;
            }
        }
        return moves;
    }
}
