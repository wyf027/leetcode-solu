Minimum Value to Get Positive Step by Step Sum

LeetCode 1413难度：简单非付费题单次线性扫描
Problem

题目描述

给定整数数组 nums，选择一个正整数 startValue 作为初始值。随后从左到右，把数组中的每个元素依次累加到当前值。

请返回最小的正整数 startValue，使得整个逐步累加过程中，当前和始终不小于 1。

函数签名
minStartValue(nums: integer[]) → integer

约束

  • 1 ≤ nums.length ≤ 100
  • -100 ≤ nums[i] ≤ 100
  • 返回值必须为正整数。
Examples

官方示例

示例 1

输入：nums = [-3,2,-3,4,2]

输出：5

若从 4 开始，第三次累加得到 0；从 5 开始则依次得到 2、4、1、5、7。

示例 2

输入：nums = [1,2]

输出：1

所有累加都向上增长，但初始值仍必须是正数。

示例 3

输入：nums = [1,-2,-3]

输出：5

Solution

准备好看题解了吗？

先用实验室感受哪些步骤把当前和拉得最低，再展开完整推导。

Walkthrough

用最低前缀和反推起点

核心洞察

令从 0 开始累计得到的前缀和为 prefix。真正运行时的当前值就是 startValue + prefix。因此只要照顾到其中最低的那个前缀，其余步骤也会自然满足要求。

答案 = max(1, 1 − minPrefix)

完整过程

  1. 把累计和 sum 与最低前缀 minPrefix 都初始化为 0。
  2. 从左到右累加每个元素，并持续更新 minPrefix。
  3. 选择 1 - minPrefix 即可让最低点恰好回到 1；若最低点本来不低于 0，答案就是 1。

正确性证明

可行性：记最低前缀和为 m。取 startValue = 1 - m 时，任意前缀和 p ≥ m，所以当前值 1 - m + p ≥ 1。若 m ≥ 0，取 1 同样满足。

最小性：当 m < 0 时，任何比 1 - m 更小的起点，在达到前缀 m 的那一步都会小于 1；当 m ≥ 0 时，正整数的下界就是 1。因此返回值必为最小可行值。

边界与复杂度

  • 全为非负数：最低前缀为 0，答案为 1。
  • 单个负数：答案恰好把该步抬到 1。
  • 最低点可出现在中间，不一定是数组总和。
  • 时间复杂度 O(n)，额外空间 O(1)。
Implementation

四种语言完整实现

Java
class Solution {
    public int minStartValue(int[] nums) {
        int sum = 0;
        int minPrefix = 0;

        for (int num : nums) {
            sum += num;
            minPrefix = Math.min(minPrefix, sum);
        }

        return 1 - minPrefix;
    }
}

from typing import List


class Solution:
    def minStartValue(self, nums: List[int]) -> int:
        prefix_sum = 0
        min_prefix = 0

        for num in nums:
            prefix_sum += num
            min_prefix = min(min_prefix, prefix_sum)

        return 1 - min_prefix

替代方案

可以二分 startValue，每次模拟验证是否安全。它利用了“起点越大越容易满足”的单调性，但一次验证需要 O(n)，整体会多一个对答案范围的对数因子。也可以先保存整个前缀和数组再取最小值，不过会使用 O(n) 空间。单次扫描更直接。

Pitfalls

常见错误

只检查最终总和

中间步骤可能先跌破 1，之后才被正数拉回。

忘记初始值必须为正

即使所有前缀和都非负，答案仍是 1，而不是 0。

少了偏移量 1

返回 -minPrefix 只会把最低点抬到 0，仍不满足题意。

把最低前缀初始化过大

初始化为 0 能把“还未取任何元素”的起点约束一并纳入。
