大小为 K 且平均值大于等于阈值的子数组数目

Number of Sub-arrays of Size K and Average Greater than or Equal to Threshold

数组滑动窗口非付费题

题意

给定整数数组 arr，以及整数 k 和 threshold。请统计所有长度恰好为 k 的连续子数组中，平均值大于等于 threshold 的子数组数量。

函数签名

numOfSubarrays(arr, k, threshold) → integer

约束

  • 1 ≤ arr.length ≤ 10⁵
  • 1 ≤ arr[i] ≤ 10⁴
  • 1 ≤ k ≤ arr.length
  • 0 ≤ threshold ≤ 10⁴

“子数组”必须连续。平均值可能不是整数。

官方示例

示例 1

输入：arr = [2,2,2,2,5,5,5,8], k = 3, threshold = 4
输出：3
解释：[2,5,5]、[5,5,5]、[5,5,8]
的平均值分别是 4、5、6，其余长度为 3 的窗口均不足 4。

示例 2

输入：arr = [11,13,17,23,29,31,7,5,2,3], k = 3, threshold = 5
输出：6
解释：前 6 个长度为 3 的子数组平均值都大于 5；
注意平均值不一定是整数。

Complete solution

完整题解

核心洞察：比较总和，不做除法

窗口平均值 sum / k ≥ threshold 等价于 sum ≥ k × threshold。把阈值预先变成目标总和，既省去重复除法，也完全避开浮点数误差。

完整过程

建立首个窗口

累加 arr[0..k-1]，得到第一个长度为 k 的窗口和。

判断是否达标

若窗口和不少于 k × threshold，答案加一。

向右滑动一格

减去离开窗口的 arr[i-k]，加上新进入的 arr[i]，再判断。

覆盖全部窗口

直到右端到达数组末尾。总计检查 n-k+1 个窗口。

正确性证明

不变式：每次判断前，变量 sum 恰好等于当前连续 k 个元素的总和。

初始化：算法直接累加前 k 个元素，因此不变式对首个窗口成立。

保持：窗口右移时，减去唯一离开的左端元素，再加上唯一进入的右端元素，所以新 sum 正是新窗口之和。

完备性：算法从起点 0 依次移动到 n-k，不重不漏地考察所有长度为 k 的连续子数组。由于 sum ≥ k×threshold 与平均值条件等价，最终计数正确。

复杂度

时间：O(n)。每个元素至多进入和离开窗口各一次。

空间：O(1)。只维护窗口和、目标和与计数器。

边界情况

  • k = 1：每个元素自身就是一个窗口。
  • k = arr.length：仅判断整个数组一次。
  • threshold = 0：在本题元素均为正数的约束下，全部窗口都达标。
  • 窗口和恰好等于目标和时也必须计数，因为条件是“大于等于”。
  • 最大窗口和为 10⁵ × 10⁴ = 10⁹，本题给定范围内 Java/C++ 的 32 位有符号整数仍可容纳。

常见错误

  • 每个窗口重新求和，退化为 O(nk)。
  • 用整数除法计算平均值，截断后导致边界判断错误。
  • 滑动时只加新元素，忘记减掉离开的元素。
  • 循环起止位置写错，遗漏最后一个窗口。
  • 把 ≥ 写成 >，漏掉刚好达标的窗口。

四种语言完整代码

JavaLeetCode 可提交
class Solution {
    public int numOfSubarrays(int[] arr, int k, int threshold) {
        int target = k * threshold;
        int windowSum = 0;

        for (int i = 0; i < k; i++) {
            windowSum += arr[i];
        }

        int answer = windowSum >= target ? 1 : 0;
        for (int right = k; right < arr.length; right++) {
            windowSum += arr[right] - arr[right - k];
            if (windowSum >= target) {
                answer++;
            }
        }
        return answer;
    }
}

from typing import List

class Solution:
    def numOfSubarrays(
        self, arr: List[int], k: int, threshold: int
    ) -> int:
        target = k * threshold
        window_sum = sum(arr[:k])
        answer = 1 if window_sum >= target else 0

        for right in range(k, len(arr)):
            window_sum += arr[right] - arr[right - k]
            if window_sum >= target:
                answer += 1

        return answer

class Solution {
public:
    int numOfSubarrays(vector<int>& arr, int k, int threshold) {
        const int target = k * threshold;
        int windowSum = 0;

        for (int i = 0; i < k; ++i) {
            windowSum += arr[i];
        }

        int answer = windowSum >= target ? 1 : 0;
        for (int right = k; right < static_cast<int>(arr.size()); ++right) {
            windowSum += arr[right] - arr[right - k];
            if (windowSum >= target) {
                ++answer;
            }
        }
        return answer;
    }
};

替代方案

前缀和：先构造 prefix[i+1] = prefix[i] + arr[i]，每个窗口和为 prefix[i+k] - prefix[i]。时间仍是 O(n)，但需要 O(n) 额外空间；适合后续还要大量查询不同区间的场景。

暴力枚举：对每个起点重算 k 个元素，总时间 O(nk)，只适合解释定义或极小数据，不满足本题最大规模下的理想效率。

面试追问

  • 为什么不直接算平均值？ 乘法等价变形更快，也没有浮点精度问题。
  • 若元素允许负数呢？ 固定长度窗口方法完全不变。
  • 若窗口长度不固定呢？ 不能直接套用本方法；若还含负数，双指针的单调性也可能消失，需要重新分析条件。
  • 若输入是数据流？ 用长度为 k 的队列保存当前窗口，持续维护总和即可。
  • 如何避免更宽数值范围下溢出？ Java/C++ 中把目标与窗口和升级为 long/long long。
