题目说明

节点编号为 0 到 n - 1；每个二元组表示一条有方向的边。

给你一个有向无环图（DAG），它有 n 个节点，以及边数组 edges。其中 edges[i] = [fromᵢ, toᵢ] 表示一条从 fromᵢ 指向 toᵢ 的有向边。

请找出一个规模最小的节点集合，使得从集合中的节点出发可以到达图中所有节点。题目保证答案唯一；节点编号可以按任意顺序返回。

函数参数：findSmallestSetOfVertices(n, edges)，返回 List<Integer> / 整数数组。

示例

1
输入：n = 6, edges = [[0,1],[0,2],[2,5],[3,4],[4,2]] 输出：[0,3] 解释：从 0 可到达 [0,1,2,5]；从 3 可到达 [3,4,2,5]。 单个起点不足以覆盖全部节点，因此返回 [0,3]。

示例

2
输入：n = 5, edges = [[0,1],[2,1],[3,1],[1,4],[2,4]] 输出：[0,2,3] 解释：0、2、3 都无法从其他节点到达，必须选入； 这些起点又能够覆盖节点 1 和 4。

约束

  • 2 ≤ n ≤ 10⁵
  • 1 ≤ edges.length ≤ min(10⁵, n × (n − 1) / 2)
  • edges[i].length == 2
  • 0 ≤ fromᵢ, toᵢ < n
  • 所有点对 (fromᵢ, toᵢ) 互不相同
  • 输入图为有向无环图，答案存在且唯一

Solution

零入度节点，就是全部答案

!

核心洞察

答案恰好是所有入度为 0 的节点。扫描每条边 u → v 时，只需标记 v 曾被指向；最后收集从未被标记的节点。

完整过程

  1. 建立长度为 n 的布尔数组 hasIncoming，初始全为 false。
  2. 遍历每条边 [from, to]，令 hasIncoming[to] = true。
  3. 再次遍历节点编号，把所有仍为 false 的节点加入答案。
  4. 返回答案；顺序不限，按编号扫描会自然得到升序结果。

正确性证明

  1. 必要性：任意入度为 0 的节点都没有来自其他节点的最后一条进入边，因此无法从别处抵达，必须把它自身选为起点。
  2. 充分性：在有限 DAG 中，从任意节点不断沿入边反向走，必然在某个入度为 0 的节点停止；反转这条路径，该零入度节点可以到达原节点。
  3. 最小性：所有零入度节点都必须选，而选中全部零入度节点已经覆盖全图，所以该集合既充分又不可再缩小。
时间复杂度O(n + m)m 为边数；扫边一次、扫节点一次
空间复杂度O(n)用于记录哪些节点存在入边

四语言完整代码

四份实现都严格匹配官方函数签名。使用布尔标记即可，无需构建邻接表或真的执行图遍历。

class Solution {
    public List<Integer> findSmallestSetOfVertices(
            int n, List<List<Integer>> edges) {
        boolean[] hasIncoming = new boolean[n];

        for (List<Integer> edge : edges) {
            int to = edge.get(1);
            hasIncoming[to] = true;
        }

        List<Integer> answer = new ArrayList<>();
        for (int node = 0; node < n; node++) {
            if (!hasIncoming[node]) {
                answer.add(node);
            }
        }
        return answer;
    }
}

    def findSmallestSetOfVertices(
        self, n: int, edges: List[List[int]]
    ) -> List[int]:
        has_incoming = [False] * n

        for _, to in edges:

        return [

        ]

边界情况与常见错误

  • 链式图：只有链头入度为 0，答案仅含一个节点。
  • 多个分支：一个源点可以覆盖许多分支，不要把“出度大”误当成筛选条件。
  • 共享终点：多条边指向同一节点时，布尔标记仍然足够；不必保存精确入度。
  • 方向看反：需要标记的是 to，而不是 from。
  • 过度计算：从每个点做 DFS/BFS 会重复遍历，最坏代价远高于线性扫描。
  • 忽略 DAG：“所有零入度节点足以覆盖全图”的充分性依赖无环条件。

替代方案

精确入度数组用整数数组累加入度，同样是 O(n + m)，但信息略多于所需。
HashSet 记录终点把所有 to 放入集合，再收集未出现的节点；可行，但常数与装箱成本更高。
逐点 DFS/BFS能验证可达性，却没有利用 DAG 结构，不适合本题的大规模输入。

面试追问

为什么不能选择“出度最大的节点”？

出度只描述一步能走向多少邻居，不能说明节点自身是否可由其他起点覆盖。必要起点由“没有入边”决定，与出度大小无关。

如果图中允许有环，结论还成立吗？

不成立。一个没有零入度节点的环仍需要至少选一个起点。一般有向图应先求强连通分量，缩点后在凝聚 DAG 中选择所有入度为 0 的分量，并从每个分量任选一个节点。

为什么题目说答案唯一？

在 DAG 中，每个零入度节点都强制入选，其他节点都不必入选，因此节点集合唯一；返回顺序仍可不同。

能否把额外空间降到 O(1)？

若允许修改输入或节点附带可写标记，可能复用已有存储；在只读 edges 且需线性时间的常规模型下，需要 O(n) 级信息来区分节点是否被指向。
