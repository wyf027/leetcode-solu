批量处理任务

按截止时间排序；当前任务缺多少开机时刻，就在线段树中从右向左补多少。越靠后，越可能被未来任务复用。

贪心动态线段树0…10⁹

题意

任务 [start,end,period] 要在闭区间内累计开机 period 个时刻，时刻不必连续。开机可同时服务所有任务，求最少开机时长。

tasks = [[1,3,2],[2,5,3],[5,6,2]]

选择 2、3、5、6，答案为 4。

快速生成模式：UI、算法对拍、四语言编译和交互验收待补。

交换论证

处理截止时间为 e 的任务时，把任意新选的较早时刻右移到区间内尚未选择的更晚位置，不会破坏已经处理的任务；更晚的位置还更可能落入后续任务区间。因此总存在一个最优解按此贪心补点。

题解：贪心 + 动态线段树

完整过程

  1. 按 end 升序排序。
  2. 查询区间内已选择数 used。
  3. 计算 need = period-used。
  4. 若仍缺时刻，在线段树中右子树优先补点。

线段树状态

sum 表示区间内已选择数。空节点代表全 0；若 sum == 区间长度，节点整段已满，部分查询可直接返回交集长度。完整覆盖且空位数不超过 need 时，整段标满。

边界与复杂度

时间坐标含 0，end 也包含在内。时间 O(n log n + n log 10⁹)，空间 O(n log 10⁹)。整数数组存左右儿子与 sum，避免数百万对象开销。

常见错误

  • 从左端补点。
  • 把闭区间写成半开区间。
  • 整段满时仍递归空孩子。
  • 逐时刻补点，无法处理 10⁹ 坐标。
