圆形赛道上
经过次数最多的扇区

把每段比赛还原成沿编号递增方向前进的轨迹。先在交互赛道里观察访问次数的变化，再决定何时展开完整题解。

Problem

题目

mostVisited(n, rounds)

一条圆形赛道包含 n 个扇区，编号为 1..n。比赛由 m 个阶段组成：第 i 段从 rounds[i-1] 出发，沿扇区编号递增方向行进，到 rounds[i] 结束；从 n 后继续到 1。

返回整场比赛中经过次数最多的全部扇区，并按编号升序排列。阶段连接处是同一个访问点，不应因阶段切换被重复计数。

示例 1

输入：n = 4, rounds = [1,3,1,2] 输出：[1,2] 轨迹：1 → 2 → 3 → 4 → 1 → 2

1 和 2 各经过两次，其余扇区各一次。

示例 2

输入：n = 2, rounds = [2,1,2,1,2,1,2,1,2] 输出：[2]

示例 3

输入：n = 7, rounds = [1,3,5,7] 输出：[1,2,3,4,5,6,7]

约束

  • 2 ≤ n ≤ 100
  • 1 ≤ m ≤ 100
  • rounds.length = m + 1
  • 1 ≤ rounds[i] ≤ n
  • rounds[i] ≠ rounds[i+1]

Spoiler Gate

准备好核对思路了吗？

完整洞察、证明、复杂度与四种语言代码默认收起。

Solution

端点区间：只看整场起点与终点

核心洞察：每个阶段的终点同时是下一阶段的起点。把所有阶段首尾相接后，中间完整绕过的圈会给每个扇区同样的访问增量；真正决定“谁比别人多一次”的，只是从整场起点 rounds[0] 到整场终点 rounds[m] 的最后一段编号区间。

完整过程

  1. 令 s = rounds[0]，e = rounds[rounds.length - 1]。
  2. 如果 s ≤ e，额外覆盖的是连续区间 [s, e]，按升序返回它。
  3. 如果 s > e，区间经过环的断点，额外覆盖 [s,n] 与 [1,e]；为了升序，先返回 1..e，再返回 s..n。

为什么中间端点可以消掉？

从一个端点走到下一个端点时，沿途扇区连续增加一次。把这些有向弧拼起来，就得到从 s 到 e 的连续总路程。每跨过完整一圈，所有扇区都同时加一，不改变最大值的并列关系。去掉所有完整圈后，余下的正是上述端点区间。

这也解释了为什么不需要保存每个扇区的计数。

正确性证明

引理：整场访问序列可分解为若干完整圆周与一条从 s 到 e 的剩余有向弧。因为相邻阶段在同一端点连接，拼接后与一次连续行进等价。

结论：每个完整圆周对所有扇区贡献相同次数；剩余弧上的每个扇区恰好多一次，弧外扇区没有这一次。因此且仅因此弧上的扇区达到最大访问次数。算法完整、无重复地列出该弧，并按升序排列，所以返回结果正确。

边界与复杂度

  • s = e：去掉完整圈后只余同一个端点，答案为 [s]。
  • s < e：不跨编号断点，直接输出一个连续区间。
  • s > e：跨过 n → 1，输出两个区间。
  • 时间复杂度 O(k)，其中 k 是答案长度，且 k ≤ n；额外空间 O(k) 用于返回值。

class Solution {
    public List<Integer> mostVisited(int n, int[] rounds) {
        int start = rounds[0];
        int end = rounds[rounds.length - 1];
        List<Integer> answer = new ArrayList<>();

        if (start <= end) {
            for (int sector = start; sector <= end; sector++) {
                answer.add(sector);
            }
        } else {
            for (int sector = 1; sector <= end; sector++) {
                answer.add(sector);
            }
            for (int sector = start; sector <= n; sector++) {
                answer.add(sector);
            }
        }
        return answer;
    }
}

class Solution:
    def mostVisited(self, n: int, rounds: List[int]) -> List[int]:
        start = rounds[0]
        end = rounds[-1]

        if start <= end:
            return list(range(start, end + 1))

        return list(range(1, end + 1)) + list(range(start, n + 1))

替代方案：逐步模拟

按照比赛轨迹逐扇区累加计数，最后扫描最大值。它直观、容易从题意写出，时间复杂度与实际走过的扇区数量有关，最坏可明显多于 n；空间复杂度为 O(n)。交互赛道演示的正是这个方案。

面试追问

  • 若行进方向每段都可能改变，端点区间结论是否仍成立？
  • 若需要返回确切访问次数，怎样用差分数组处理环形区间？
  • 若 n 极大而只允许流式读取 rounds，需要保存什么状态？

常见错误

  • 每个阶段都同时统计起点和终点，导致相邻阶段的连接点被重复计数。
  • 回绕时输出 [s,n] 再输出 [1,e]，结果没有按升序排列。
  • 误以为需要比较全部模拟计数，没有观察到完整圈给所有扇区的贡献相同。
  • 循环边界少包含终点，或在 s = e 时返回空数组。
