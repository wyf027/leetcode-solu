Count Special Quadruplets

四个位置，一条等式。先理解下标与数值的关系，再动手观察。

01题目说明

给定从下标 0 开始的整数数组 nums，统计不同下标组合 (a, b, c, d) 的数量，要求同时满足：

a < b < c < d
nums[a] + nums[b] + nums[c] = nums[d]

“不同”按下标区分。即使数值相同，只要下标组合不同，就分别计数；返回一个整数。

约束：4 ≤ nums.length ≤ 50；1 ≤ nums[i] ≤ 100。

官方示例

示例 1

输入：nums = [1,2,3,6]
输出：1

唯一组合为 (0,1,2,3)，因为 1 + 2 + 3 = 6。

示例 2

输入：nums = [3,3,6,4,5]
输出：0

没有满足两个条件的下标组合。

示例 3

输入：nums = [1,1,1,3,5]
输出：4

(0,1,2,3) 对应 1 + 1 + 1 = 3；(0,1,3,4)、(0,2,3,4)、(1,2,3,4) 各对应 1 + 1 + 3 = 5。

04独立题解

思考完再展开：推导、证明与四语言实现。

核心洞察：按顺序选位置，直接检查等式

长度最多为 50，合法下标组合只有 C(50,4) = 230300 个。直接枚举所有递增四元组已经足够，不需要改变原数组，也不需要为相同数值去重。

完整过程

  1. 令答案 ans = 0。
  2. a 从 0 到 n−4；b 从 a+1 到 n−3。
  3. c 从 b+1 到 n−2；d 从 c+1 到 n−1。
  4. 每次检查前三个位置的数值之和是否等于第四个；相等时答案加一。
  5. 全部枚举结束后返回答案。

观察台使用相同的枚举顺序。例如 [1,1,1,3,5] 依次检查 (0,1,2,3) ✓、(0,1,2,4) ×、(0,1,3,4) ✓、(0,2,3,4) ✓、(1,2,3,4) ✓，最终得到 4。回退时，账本同步移除被撤销步骤的命中记录。

正确性证明

合法性：循环的起点保证 a < b < c < d，仅在等式成立时累加，因此每次计数都对应合法答案。

完备性：任意合法的 (a,b,c,d)，其四个下标分别落在相应循环范围内，因此一定会被检查。

唯一性：嵌套循环对每个固定下标组合只访问一次，不会重复计数。结合三点，最终返回值恰好是所有特殊四元组的数目。

复杂度与边界

时间复杂度 O(n⁴)，精确检查次数为 C(n,4)；额外空间 O(1)，不修改输入。页面演示为支持回放另存步骤，空间不属于提交算法。

  • n = 4 时只检查一次；没有命中就返回 0。
  • 重复数值不能去重：不同下标是不同答案。
  • 每个数为正数，但原数组无序，不能因某次和过大就结束后续循环。
  • 三数之和最多 300，答案不超过 230300，Java / C++ 的 int 足够，JavaScript Number 也能精确表示。

Java

class Solution {
    public int countQuadruplets(int[] nums) {
        int n = nums.length, ans = 0;
        for (int a = 0; a < n - 3; a++)
            for (int b = a + 1; b < n - 2; b++)
                for (int c = b + 1; c < n - 1; c++)
                    for (int d = c + 1; d < n; d++)
                        if (nums[a] + nums[b] + nums[c] == nums[d])
                            ans++;
        return ans;
    }
}

class Solution:

        n = len(nums)
        ans = 0
        for a in range(n - 3):
            for b in range(a + 1, n - 2):
                for c in range(b + 1, n - 1):

                        if nums[a] + nums[b] + nums[c] == nums[d]:
                            ans += 1
        return ans

替代方案：用空间换时间

  • O(n³) 后缀频次：从右向左枚举 c，先加入 nums[c+1]，使频次表只包含 d > c 的值。枚举 a < b < c，查询三数之和的出现次数并累加。通用哈希表额外空间 O(n)，哈希操作按期望 O(1) 计。
  • O(n²) 差值统计：改写为 nums[a] + nums[b] = nums[d] − nums[c]。令 b 从 n−3 递减至 1，每轮先把 c = b+1 与所有 d > c 的差值加入表，再对每个 a < b 查询左侧和。保留前轮记录，就得到所有 b < c < d。通用值域下表最多存 O(n²) 个键；本题差值在 −99 到 99，可用 199 格计数数组。

本题数据量小，直接枚举更易解释与实现；若面试要求优化，再沿着上述等式变形展开。

常见错误

  • 先排序：会改变原始下标顺序，使本来不合法的组合被计数。
  • 用 Set 保存数值组合：会把重复数值对应的不同下标答案合并。
  • 四层循环都从 0 开始：可能重复使用同一位置，也会产生排列重复。
  • 把数组中的数值当成下标，或比较 a+b+c 与 d。
  • 优化时只记录差值是否存在：必须记录出现次数；每个右侧下标对都应计入。

面试追问

如果 n 很大？使用差值统计把时间降至 O(n²)，并重新评估计数是否需要 64 位整数。允许负数呢？枚举算法不变，固定范围计数数组应改为更宽的数组或哈希表。如果要输出所有下标？命中时保存组合，额外空间至少 O(k)，k 为输出数量。为什么不除以 24？下标递增已排除所有排列重复。
