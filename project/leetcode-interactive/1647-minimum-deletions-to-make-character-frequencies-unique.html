A frequency puzzle · 频次去重

字符频次唯一的最小删除次数

让每个仍然存在的字符拥有不同的出现次数。你只能删除字符，目标是让删除总数尽可能少。

先别急着展开答案。

先观察重复频次会怎样“争抢位置”，再用交互实验验证你的直觉。完整题解收在页面底部。

01 / PROBLEM

题目说了什么

如果字符串中不存在两个不同字符的频次相同，我们称它为“优质字符串”。频次降到 0 的字符已经消失，不参与比较。

任务

给定一个仅包含小写英文字母的字符串 s。每次操作可以删除任意一个字符，请返回让 s 变为优质字符串所需的最少删除次数。

官方函数形式

minDeletions(s: string): integer
f
字符频次

某个字符在字符串中出现的总次数。例如 "aab" 中 a 为 2，b 为 1。

≠
唯一

只比较正频次；所有仍存在字符的频次必须两两不同。

示例 1
输入：s = "aab"
输出：0

a 的频次为 2，b 为 1，已经互不相同。

示例 2
输入：s = "aaabbbcc"
输出：2

可删除两个 b 得到 "aaabcc"；也可各删除一个 b、c 得到 "aaabbc"。

示例 3
输入：s = "ceabaacb"
输出：2

可删除两个 c 得到 "eabaab"。频次为 0 的字符不参与唯一性判断。

  • 1 ≤ s.length ≤ 105
  • s 仅含小写英文字母
  • 返回值：最少删除次数

05 / SOLUTION

把每个频次放进最近的空位

核心洞察

字符只能被删除，因此某个频次只能保持不变或减小。处理一个字符时，为了少删，应把它安排到“不超过原频次的最大未占用正整数”；若不存在，只能删到 0。

为什么局部最优够用

给当前字符保留尽可能大的频次，不会挤占任何更大的位置，也不会让后续字符获得更好的可选位置；反而能直接最小化当前删除数。

完整过程

  1. 统计 26 个小写字母的出现次数，忽略频次为 0 的字符。
  2. 维护集合 used，记录已经被其他字符占用的正频次。
  3. 对每个原频次 f，只要 f > 0 且 used 已包含它，就让 f--，并把本次删除数加一。
  4. 若最终 f > 0，把它加入 used；若为 0，则字符完全删除，0 不需要加入集合。
  5. 所有字符处理完毕，累计删除数就是答案。字符处理顺序不影响这套“向下找最近空位”的正确性；排序仅便于观察。

正确性说明

可行性：每次只把正频次加入 used，且加入前保证该值未出现，因此结束时所有保留字符的正频次两两不同。

最优性：考虑处理当前原频次 F。所有大于当前选择值且不超过 F 的位置都已被占用，所以任何可行方案都不可能为当前字符保留更多出现次数。算法选择最大可用值，当前删除数最小；逐个应用这一结论，累计删除数也最小。

终止性：冲突时频次严格减一，并且下界为 0，因此每个字符都在有限步内完成。

时间复杂度O(n + Σf)

统计为 O(n)；向下调整总步数等于删除次数，至多 n。字母表固定时也可视为 O(n)。

空间复杂度O(Σ)

计数与集合最多保存字符种类数；本题仅 26 个小写字母，可视为 O(1)。

import java.util.HashSet;
import java.util.Set;

class Solution {
    public int minDeletions(String s) {
        int[] count = new int[26];
        for (char ch : s.toCharArray()) {
            count[ch - 'a']++;
        }

        Set<Integer> used = new HashSet<>();
        int deletions = 0;

        for (int frequency : count) {
            while (frequency > 0 && used.contains(frequency)) {
                frequency--;
                deletions++;
            }
            if (frequency > 0) {
                used.add(frequency);
            }
        }

        return deletions;
    }
}

边界情况

  • 只有一个字符或所有频次本就不同：返回 0。
  • 多个字符频次相同：除一个外，其余向下寻找空位。
  • 频次可能降到 0：字符完全删除，多个 0 不冲突。
  • 长度可达 105：不要构造或反复修改实际字符串。

替代方案

也可把正频次数组降序排序，然后令当前允许的最大频次不超过前一个保留频次减一。该写法同样是贪心，通常为 O(Σ log Σ)；本题 Σ=26，差异很小。集合方案更直观地表达“频次不能重复”。

常见错误

  • 把频次 0 放入集合，错误地认为两个被删空的字符冲突。
  • 冲突时只减一次，没有继续检查新的频次是否仍被占用。
  • 只统计重复频次数量，却忽略连续占用导致需要多删。
  • 试图增加频次；题目只允许删除，频次不能上升。

面试追问

进一步辨析

为什么不必真的删除字符串里的字符？

答案只取决于每个字符最终保留多少个，而与删掉的是哪些位置无关。直接修改频次数组即可，避免昂贵的字符串重建。

处理频次时一定要排序吗？

使用 used 集合向下探测时不需要排序，因为每个字符都取得自己可用的最大频次。排序能让演示更有层次，但不是集合写法正确性的前提。

如何理解最少删除？

总长度固定，最少删除等价于让最终保留的字符总数最大。每次把频次放到不冲突的最大位置，正是在最大化保留量。
