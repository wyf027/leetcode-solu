题解

从右向左结算 carry

核心洞察

真正需要知道的只有“当前位加上右侧传来的进位”：

  • 有效位为 0 或 2：当前数为偶数，只需一次除 2。
  • 有效位为 1：先加 1，再除 2，共两步，并向左保留进位。

因此无需修改字符串，也无需表示整个大整数。

完整过程

  1. 从最低位扫描到下标 1，最高位暂不处理。
  2. 令 bit = 当前字符 + carry。
  3. bit == 1 时答案加 2，并令 carry = 1；否则答案加 1。
  4. 扫描结束后，把最高位上方可能残留的 carry 加入答案。
有效位 = (s[i] - '0') + carry　｜　有效位为 1：+2 步　｜　否则：+1 步　｜　答案最后 + carry

正确性证明

循环不变式：处理下标 i 前，所有更低位已经按规则删除，steps 等于删除这些位所需的步骤数，carry 准确表示这些操作对当前位的进位。

若有效位为 0 或 2，数为偶数，一次除 2 即删除该位；进位状态无需新增。若有效位为 1，数为奇数，必须先加 1 再除 2，两步后该位被删除且向左产生进位。两种情况都恢复不变式。

循环终止时只剩最高位。无进位时它已经是 1；有进位时等价于二进制 10，还需一次除 2。因此返回 steps + carry 恰为总步骤数。

边界与复杂度

  • s = "1"：循环不进入，直接返回 0。
  • 全是 0 的尾部：每位各贡献一次除 2。
  • 连续尾部 1：一次进位会持续向左传播。
  • 长度 500：不转换成固定宽度整数，避免溢出。

时间复杂度：O(n)；额外空间：O(1)。

替代方案

可以直接用字符串模拟：偶数就删末位，奇数就从右向左执行二进制加一。这种写法更贴近题意，也适合做可视化；但同一位可能被多次访问，朴素实现最坏可到 O(n²)，并会频繁创建字符串。

常见错误

  • 把最长 500 位的 s 转成普通整数，导致溢出或精度丢失。
  • 扫描到下标 0 后仍机械计一次除 2，给 "1" 算出 1。
  • 看到字符 '0' 就认定有效位是 0，忘记叠加已有进位。
  • 有效位为 1 时只加一步；实际需要“加一 + 除二”两步。

面试追问

  • 为什么有效位 2 只贡献一步？ 因为它表示当前位受进位后是偶数，除 2 即可，已有进位会继续体现在更高位。
  • 能否从左向右？ 可以预判右侧是否会产生进位，但状态表达更绕；从右向左与进位传播方向天然一致。
  • 怎样返回操作序列？ 使用大整数字符串模拟并记录快照，代价是额外的时间和空间。

class Solution {
    public int numSteps(String s) {
        int steps = 0;
        int carry = 0;

        for (int i = s.length() - 1; i > 0; i--) {
            int bit = (s.charAt(i) - '0') + carry;
            if (bit == 1) {
                steps += 2;
                carry = 1;
            } else {
                steps += 1;
            }
        }
        return steps + carry;
    }
}
