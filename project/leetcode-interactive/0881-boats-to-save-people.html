救生艇

Boats to Save People · 在有限载重与两人座之间，寻找最少航次。

881中等数组排序双指针贪心

题目

给定整数数组 people，其中 people[i] 是第 i 个人的体重。救生艇数量不限，每艘船的最大载重为 limit，并且每艘船最多载两人；只有两人的体重和不超过 limit 时，才能同乘一船。

目标：返回运送所有人所需的最少救生艇数量。

函数签名

numRescueBoats(people: integer[], limit: integer) -> integer

官方示例

示例 1
输入：people = [1,2], limit = 3
输出：1
解释：1 艘船载 (1, 2)
示例 2
输入：people = [3,2,2,1], limit = 3
输出：3
解释：3 艘船分别载 (1, 2)、(2)、(3)
示例 3
输入：people = [3,5,3,4], limit = 5
输出：4
解释：4 艘船分别载 (3)、(3)、(4)、(5)

约束

  • 1 <= people.length <= 5 * 10^4
  • 1 <= people[i] <= limit <= 3 * 10^4

题解：排序 + 双指针贪心

核心洞察

每次先处理当前最重的人，因为他无论如何都必须占用一艘船。若他能与当前最轻的人同船，就应当配对；否则连最轻的人都无法同行，他只能独乘。

完整过程

  1. 将体重升序排序。
  2. 令 left 指向最轻的人，right 指向最重的人。
  3. 只要 left <= right，就为最重的人安排一艘船。
  4. 若两端体重之和不超过 limit，最轻者同行，移动 left。
  5. 无论是否配对，都移动 right，船数加一。

正确性

考虑当前最重者 H。若 H + L > limit，其中 L 是当前最轻者，则任何其他人都不轻于 L，所以 H 必须独乘。若 H + L <= limit，让 L 与 H 同乘不会妨碍剩余人：若某个最优方案让 H 与更重者 X 同乘，可以将 L 换入该船，而 X 接替 L 原来的位置或独乘，船数不会增加。因此每一步贪心选择都存在对应的最优方案；反复应用后得到全局最少船数。

复杂度

排序耗时 O(n log n)，双指针扫描耗时 O(n)；总体时间 O(n log n)。除排序所需空间外，指针使用 O(1) 额外空间；具体排序空间依语言实现而定。

边界情况

  • 只有一人：答案为 1。
  • 所有人都超过 limit / 2：无人能配对，答案等于人数。
  • 两端之和刚好等于上限：可以同船。
  • 大量重复体重：双指针逻辑不变。

替代方案

可以用计数数组替代比较排序：由于体重上限为 3 * 10^4，统计每种体重的频次，再从两端配对，可达到 O(n + limit) 时间，但实现更复杂且依赖数值范围。枚举所有配对或回溯会产生平方级甚至指数级开销，不适用于最大数据量。

面试追问

  • 为什么优先保证最重者登船，而不是先配最轻的两个人？
  • 若每艘船最多载三人，当前贪心还正确吗？（通常不再直接成立。）
  • 若无需排序且体重范围较小，如何使用计数数组？
  • 能否说明交换论证中“船数不增加”的具体重排方式？

常见错误

  • 写成 people[left] + people[right] < limit，漏掉刚好等于上限的合法配对。
  • 最重者独乘时误移动 left。
  • 循环条件用 left < right，漏算最后一个人。
  • 忘记排序便直接使用双指针。

四语言完整代码

import java.util.Arrays;

class Solution {
    public int numRescueBoats(int[] people, int limit) {
        Arrays.sort(people);
        int left = 0, right = people.length - 1;
        int boats = 0;

        while (left <= right) {
            if (people[left] + people[right] <= limit) {
                left++;
            }
            right--;
            boats++;
        }
        return boats;
    }
}
