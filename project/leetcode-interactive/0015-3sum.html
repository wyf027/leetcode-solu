SOLUTION ROOM · DEFAULT LOCKED

题解

核心洞察、完整过程、边界、复杂度、追问、错误清单与四语言代码默认隐藏。

CORE INSIGHT

排序把“往哪走”变成确定答案

固定 nums[i] 后，只需在右侧寻找两数之和 -nums[i]。数组有序时，当前和偏小就右移 L，偏大就左移 R；每次移动都排除一整片不可能区域。

DEDUP CONTRACT

锚点重复：跳过本轮 i

命中之后：跳过相同的 L / R

去重必须发生在正确时机：锚点在扫描前，左右值在记录答案后。

FULL WALKTHROUGH

完整解题过程

  1. 1. 排序：让指针移动具有单调方向。
  2. 2. 固定锚点：枚举 i 到 n - 3；若与前值相同则跳过。
  3. 3. 双指针夹逼：L = i + 1， R = n - 1。
  4. 4. 定向移动：和小则 L++，和大则 R--。
  5. 5. 命中并去重：记录三元组，跳过左右相同值，再同时收缩两端。

EDGE CASES

边界情况

  • • 全正或全负：不可能归零。
  • • 至少三个 0：只保留 [0,0,0]。
  • • 大量重复值：锚点与命中后的双端都要去重。
  • • nums[i] > 0：后面全为正数，可直接结束。

COMPLEXITY

复杂度

TIME
O(n²)
POINTER PHASE
O(1)

不计答案存储；总辅助空间取决于各语言排序实现，通常为 O(log n) 到 O(n)。

ALTERNATIVE

替代方案取舍

固定一个数后用哈希集合查另外两个数，同样可达 O(n²)，但去重逻辑更绕且需要 O(n) 额外空间。面试中排序双指针更容易证明、实现和复盘。

COMMON MISTAKES

常见错误

  • • 只用 Set 包结果，却没有处理内部三元组顺序。
  • • 命中后只移动一边，造成死循环或重复答案。
  • • 在比较之前盲目跳过 L / R 重复值，漏掉合法组合。
  • • 忘记数值排序使用比较器，JavaScript 得到字典序。

INTERVIEW FOLLOW-UPS

面试高频追问

为什么能定向移动？排序保证右移 L 不减、左移 R 不增。

为什么跳过重复锚点不会漏解？相同锚点的后一次扫描区间更小，只会生成已经出现过的数值组合。

能否优于 O(n²)？在一般整数模型下没有常用的通用更优面试解法；重点是将 O(n³) 降到 O(n²)。

class Solution {
    public List<List<Integer>> threeSum(int[] nums) {
        Arrays.sort(nums);
        List<List<Integer>> answer = new ArrayList<>();

        for (int i = 0; i < nums.length - 2; i++) {
            if (nums[i] > 0) break;
            if (i > 0 && nums[i] == nums[i - 1]) continue;

            int left = i + 1;
            int right = nums.length - 1;
            while (left < right) {
                int sum = nums[i] + nums[left] + nums[right];
                if (sum < 0) {
                    left++;
                } else if (sum > 0) {
                    right--;
                } else {
                    answer.add(Arrays.asList(nums[i], nums[left], nums[right]));
                    while (left < right && nums[left] == nums[left + 1]) left++;
                    while (left < right && nums[right] == nums[right - 1]) right--;
                    left++;
                    right--;
                }
            }
        }
        return answer;
    }
}
