合并靠近字符

同一个字符相距不超过 k 时，右侧字符并入左侧并从字符串中删除。每一次都必须优先选最靠左的可合并对。

关键不在“能不能合并”，而在严格复现题目的选对顺序：扫描左端点，再扫描离它最近的右端点。

推荐：直接模拟规则

长度最多 100。反复寻找第一个合法对、删除右端字符，天然符合并列时的两层优先级。

时间
O(n³)
空间
O(n)

题意与示例

给定小写字符串 s 和整数 k。当前字符串中，若两个相同字符的下标距离不大于 k，右边字符可合并到左边字符。重复操作直到不存在合法对。

  • s = "abca", k = 3：两端 a 距离为 3，删除右侧 a，结果是 "abc"。
  • s = "aabca", k = 2：先删除下标 1 的 a，此时余下两个 a 相距 3，不能继续合并。
选择规则：先挑最小左下标；若左下标相同，再挑最小右下标。这就是双层从左到右扫描。

题解

默认收起，先自己操作一遍再展开。

完整过程

  1. 从左到右枚举 i。
  2. 只需枚举 j = i + 1 ... min(i + k, n - 1)；第一个相同字符就是此轮应删的右端点。
  3. 删除 j，重新从头扫描，直到一轮没有删除。

边界

  • 没有可合并对时原样返回。
  • 删除会让远处字符靠近，所以每一次删除后都必须重新扫描。
  • 不能贪心保留“最后一次出现位置”：题目的优先级依赖当前字符串下标。

复杂度

每轮扫描最多 O(n²)，最多删除 n - 1 个字符，因此 O(n³)。在 n ≤ 100 时非常稳妥。

替代方案

可以尝试维护链表和每种字符的位置集合，但删除会改变距离和“最小左端点”的竞争关系，证明与实现都更复杂，不如模拟可靠。

面试追问

若 n 很大，应先澄清是否仍要逐轮遵循相同的 tie-break；这决定能否设计更复杂的数据结构。
