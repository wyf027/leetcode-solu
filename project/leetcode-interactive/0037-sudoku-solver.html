WORK ORDER · BRIEF

题意转述

给定一张 9×9 的部分数独棋盘，把所有 "." 原地替换成数字，使每行、每列、每个 3×3 小宫都恰好包含 1 到 9。函数不返回棋盘，答案直接写回参数 board。

题目保证：输入只有一个解，所以找到完整合法棋盘即可停止搜索，不必枚举所有方案。
别和第 36 题混淆：36 题只验证；37 题必须主动填满空格，因此需要搜索与撤销。

MANUAL A · CORE INSIGHT

核心洞察：递归承诺，失败撤销

FILTER

三张占用表剪枝

用 rows / columns / boxes 在 O(1) 时间判断候选是否合法，避免每次重扫整行整列。

CHOOSE

对当前空格逐个尝试

放入一个合法数字，同时更新棋盘和三张占用表，再递归处理下一个空格。

UNDO

下游失败必须恢复现场

递归返回 false 时，把棋盘改回 '.'，并清除三处占用标记，才能安全尝试下一个数字。

递归不变量

进入 backtrack(index) 时，编号小于 index 的空格都已合法填好，三张占用表与当前棋盘完全同步。

MANUAL B · PROCEDURE

完整解题过程

  1. 01

    预处理初始数字与空格

    扫描 81 格，把已填数字登记到行、列、宫占用表，同时按行优先收集所有空格坐标。

  2. 02

    定义递归状态 index

    index 指向当前待填空格；等于空格数量时，所有位置已填完，返回 true。

  3. 03

    枚举数字 1 到 9

    只要当前数字未被所在行、列和宫占用，就把它写入棋盘并标记三张表。

  4. 04

    递归下探并早停

    若后续成功，立即一路返回 true，保留棋盘中的最终答案。

  5. 05

    失败时完整撤销

    恢复点号并清除行、列、宫标记；所有候选都失败才向上一层返回 false。

WORST CASE

O(9ᴱ)

E = 初始空格数量；合法性剪枝会大量减少实际分支。

O(E)

递归栈最深 E；固定占用表本身为 O(1)。

BOUNDARY PANEL

  • • 已经完成的合法棋盘：空格列表为空，立即成功。
  • • 只剩一个空格：候选检查后直接写入唯一数字。
  • • 输入保证尺寸正确、字符合法且唯一解。
  • • 成功返回时不能撤销最终路径上的数字。

MANUAL C · ALTERNATIVES

替代方案与优化

MRV：优先填候选最少的空格

能显著缩小搜索树，但要动态选择和交换空格；适合追问优化，主线先保证经典回溯清楚。

位掩码保存占用状态

用 9 位整数替代布尔数组，候选可通过位运算得到，常数更小但可读性略差。

精确覆盖 / Dancing Links

把数独转成精确覆盖问题，适合批量高性能求解；面试现场实现成本远高于回溯。

MANUAL D · INTERVIEW

面试高频追问

为什么用空格列表，而不是每层重扫棋盘？
列表让递归状态只需一个 index，避免每层重新寻找下一个空格，也方便说明栈深。
为什么成功路径上的数字不会被撤销？
子调用返回 true 后立即继续返回 true，撤销代码只在子调用失败时执行。
如何把候选判断从 O(9) 降到 O(1)？
预处理三组占用表，直接用 rows[r][d]、columns[c][d]、boxes[b][d] 查询。
如何判断输入无解或有多个解？
无解时根调用返回 false；多解时不能在首个解早停，要继续回溯并累计解的数量。

MANUAL E · FAILURE SIGNALS

常见错误

FAULT 01

只恢复棋盘

忘记清除行、列、宫占用表，后续合法候选会被误判。

FAULT 02

成功后仍执行撤销

必须在子调用成功时立即返回，否则最终棋盘会被擦空。

FAULT 03

宫编号计算错误

正确公式是 (row / 3) * 3 + column / 3。

FAULT 04

返回新棋盘

题目签名返回 void，必须直接修改传入的 board。
