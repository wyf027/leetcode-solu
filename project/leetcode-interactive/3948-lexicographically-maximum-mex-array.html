字典序最大的 MEX 数组

把数组不断切掉一个非空前缀，记录每段的 MEX。目标是让记录数组在字典序上尽可能大。

示例输入：nums = [0, 1, 0]　空格若出现会以 ␠ 标出。

题意（先自己推一遍）

  1. 任选当前数组的前 k 个元素，且 1 ≤ k ≤ len(nums)。
  2. 把这段的 MEX（最小缺失非负整数）加入 result。
  3. 删除这一段，直到数组为空；返回字典序最大的 result。
策略问题：当前段若能得到更大的 MEX，后面所有选择都无法弥补首个不同位置的损失；相同 MEX 下则应尽量短切，为后缀留下更多选择。

三个官方示例

nums = [0, 1, 0] → [2, 1]

nums = [1, 0, 2] → [3]

nums = [3, 1] → [0, 0]

交互：最短覆盖前缀

当前样例 [0, 1, 0]。先求整个后缀 MEX=2，再只吃到凑齐 0,1 的最短前缀。

题解

默认收起，避免首屏直接暴露解法。

核心洞察

当前后缀的 MEX 是本轮能取得的最大首项。为了让后续字典序也最大，扫描到首次收齐 0..mex-1 时立即切段；这正是得到该 MEX 的最短前缀。

完整过程

  1. 从右向左维护频次，得到每个起点后缀的 MEX。
  2. 起点 left 的目标是 suffixMex[left]。
  3. 若目标为 0，当前一个元素就能形成 MEX 0，立即切出。
  4. 否则右指针向右扫描，直到本段包含每个 0..target-1；记录 target，清空本段标记，继续。

边界与复杂度

0 不在当前后缀时，MEX 为 0，必须单元素切分，才能在相同全零前缀时让结果更长。频次数组与标记数组大小为 n + 2；每个元素至多被两次扫描，时间 O(n)、空间 O(n)。

替代方案与常见错误

可以每段重算 MEX，但最坏会退化到 O(n²)。不要只取整个数组的 MEX；也不要在凑齐目标后继续吃元素，它会无谓地损害后缀。

面试追问

若只求第一段的最大 MEX，扫描整数组即可；若要最小字典序，则“优先最大 MEX”的贪心方向不再成立，需要重新定义局部目标。

class Solution {
  public int[] lexicographicallyMaximumMexArray(int[] nums) {
    int n = nums.length, mex = 0;
    int[] cnt = new int[n + 2], suffix = new int[n];
    for (int i = n - 1; i >= 0; --i) { if (nums[i] <= n) cnt[nums[i]]++; while (cnt[mex] > 0) mex++; suffix[i] = mex; }
    java.util.List<Integer> ans = new java.util.ArrayList<>();
    boolean[] seen = new boolean[n + 2];
    for (int l = 0; l < n;) { int target = suffix[l]; ans.add(target); if (target == 0) { l++; continue; } int r = l, need = 0; while (need < target) { if (nums[r] < target) seen[nums[r]] = true; while (need < target && seen[need]) need++; r++; } while (l < r) { if (nums[l] < target) seen[nums[l]] = false; l++; } }
    return ans.stream().mapToInt(Integer::intValue).toArray();
  }
}
