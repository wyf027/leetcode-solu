01 / PROBLEM

题目与输入边界

给定二进制字符串 s 和正整数 k。从 s 中删除任意数量的字符，保留剩余字符的相对顺序。将结果看作二进制数，要求数值不超过 k，返回能保留的最大长度。

  • 允许前导零，它们也计入长度。
  • 空子序列对应数值 0。
  • 子序列不要求连续，但不能重新排列字符。
1 ≤ s.length ≤ 1000；s[i] ∈ {'0', '1'}；1 ≤ k ≤ 10⁹。返回一个整数长度。

官方示例

输入：s = "1001010", k = 5
输出：5

可以保留 00010，数值为 2、长度为 5。00100（4）与 00101（5）也是最长解。

输入：s = "00101001", k = 1
输出：6

保留 000001，数值为 1、长度为 6。

04 / SOLUTION NOTES

独立题解

准备好再展开：思路、论证与四种语言实现。

核心洞察：零保长度，右侧的一更便宜

从右向左处理，已保留的字符构成低位。向它前面加一个 0 不改变数值；加一个 1 则增加 2^len，其中 len 是已保留长度。尽量保留右边的 1，并保留所有 0。

完整过程

  1. 初始化 len = 0, value = 0, weight = 1。
  2. 从 s 的最右端向左扫描。遇到 0，直接保留；遇到 1，仅在 value + weight ≤ k 时保留。
  3. 保留时：若字符为 1 则累加 weight；长度加 1；权重变成 min(weight × 2, k + 1)。跳过字符时不改变这些变量。
  4. 即使一个 1 放不下，也继续扫描并保留更左边的零。最终返回 len。

饱和值 k + 1 表示真实权重已经大于 k。后续的 1 必定不合法，无需继续计算巨大的 2 的幂；这不会影响零的选择。

以 s = "1001010", k = 5 为例：依次从右侧保留 0（值 0）、1（值 2）、0（值 2），下一位 1 的权重为 8，无法加入。继续保留两位 0，最后跳过最左侧的 1，得到 00010，长度 5。

正确性：交换论证

  1. 存在包含全部零的最优解。 假设某个零没被选中。如果它前面没有选中的 1，插入这个零只会增加前导零，不增大数值。如果它前面有选中的 1，取最近的一个，将其删除并选入当前零；这段选中字符由 10…0 变为 0…00，长度不变、数值下降。反复操作，就能让一个最优解包含全部零。
  2. 固定选 t 个 1 时，选最右边的 t 个最优。 已包含全部零时，把一个较左的已选 1 换成更右的未选 1，相当于让 1 穿过若干零向低位移动，数值不会增加。因此只需考虑“全部零 + 最右侧 t 个 1”。
  3. 扫描找到最大的可行 t。 在第一次拒绝 1 之前，扫描保留了经过的全部字符；每次加 1 的数值检查准确。第一次拒绝后，后续权重不减、剩余预算不增，所以更左侧的 1 也放不下。左侧的零仍能作为前导零加入。根据前两步，没有其他同样多 1 的选择能更便宜，因此得到最大长度。

边界与复杂度

  • 全零返回 n；全一选择最大 t，使 2ᵗ − 1 ≤ k；前导零全部计数。
  • 等于 k 时仍然可以选；只剩零时不要提前结束。
  • 时间 O(n)，算法额外空间 O(1)。交互轨道另需 O(n) 个显示节点。
  • 使用饱和权重后，中间算术不超过约 2 × (k + 1)，四份实现都保持安全整数范围。

JavaScript
/**
 * @param {string} s
 * @param {number} k
 * @return {number}
 */
var longestSubsequence = function(s, k) {
    let len = 0, value = 0, weight = 1;
    for (let i = s.length - 1; i >= 0; i--) {
        if (s[i] === '0' || value + weight <= k) {
            if (s[i] === '1') value += weight;
            len++;
            weight = Math.min(weight * 2, k + 1);
        }
    }
    return len;
};

替代方案

动态规划：从左到右扫描，令 dp[L] 为已扫描前缀中长度为 L 的子序列的最小数值。初始 dp[0] = 0，其余不可达。加入位 b 时倒序枚举 L，用 dp[L + 1] = min(dp[L + 1], 2 × dp[L] + b) 更新，超过 k 的值记为不可达；保留不选当前位的状态。最终取最大可达 L。时间 O(n²)、空间 O(n)，适合解释状态转移，但本题贪心更直接。

常见错误

  • 求成连续子串，或者重排字符。
  • 从左侧优先选择 1，过早占用高位预算。
  • 用原下标直接当作所选子序列的位权，却没有说明跳过字符后的含义。本文权重仅在保留时翻倍。
  • 遇到一个不能选的 1 就 break，漏掉更左侧的零。
  • 把一千位字符串转为普通整数，或在 JavaScript 中用位移维护大权重导致 32 位溢出。

面试追问

如何返回具体子序列？ 保存选中下标并按原顺序输出，增加 O(n) 空间。不允许前导零时？ “所有零都能选”的论证失效，需要重新处理起始非零位。字符选择具有不同收益时？ 最大长度的交换论证不再适用，可以考虑按收益或数值设计动态规划。
