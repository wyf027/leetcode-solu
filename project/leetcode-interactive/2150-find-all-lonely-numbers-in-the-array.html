Find All Lonely Numbers in the Array

只出现一次，就一定孤独吗？先读规则，在脑中判断每个数字，再展开下方的交互实验。

官方题目 ↗

01 / 题目

给定整数数组 nums。一个数 x 是“孤独数字”，当且仅当它在数组中恰好出现一次，而且数组中既没有 x − 1，也没有 x + 1。请返回所有孤独数字，顺序不限。

这里的“相邻”指数值相差 1，与元素在数组中的下标是否相邻无关。

示例 1

输入：nums = [10,6,5,8]
输出：[10,8]

10 只出现一次，9 和 11 均不存在；8 只出现一次，7 和 9 均不存在。5 与 6 彼此相邻，因此都不孤独。也可以返回 [8,10]。

示例 2

输入：nums = [1,3,5,3]
输出：[1,5]

1 的两侧 0、2 均不存在，5 的两侧 4、6 均不存在，且它们都只出现一次。3 出现两次，不满足条件。也可以返回 [5,1]。

约束与接口

  • 1 ≤ nums.length ≤ 10⁵
  • 0 ≤ nums[i] ≤ 10⁶
  • 参数：整数数组 nums；返回：整数列表；函数名：findLonely。

03 / 独立题解

准备好后，打开思路、交互和四语言实现。

核心洞察：一次计数，三项判定

为每个值记录出现次数 freq[x]。一个值是否孤独，只取决于自身的次数和数值两侧的存在性：

freq[x] == 1
且 x - 1 不在 freq 中
且 x + 1 不在 freq 中

必须先统计整个数组，再做判定：一个暂时没有邻居的数，可能在数组后面遇到邻居或重复值。

交互实验 / 三格邻域探测器

先逐项建立完整台账，再按首次出现顺序检查不同的值。每一步都可以回退。演示上限 30 项；提交代码支持完整题目约束。

1–30 项，每项为 0–1000000 的整数。修改后点击“载入数组”。

完整过程

  1. 遍历 nums，将每个值的计数加一，得到完整频次表。
  2. 遍历频次表中的不同值 x。次数不为 1，直接排除。
  3. 若 x − 1 或 x + 1 存在，也排除。
  4. 三项条件全部成立时收集 x，返回列表。

示例 1 的频次均为 1。检查 10 时两侧 9、11 缺失，收集 10；6 的左邻 5 存在，排除 6；5 的右邻 6 存在，排除 5；8 的两侧缺失，收集 8。

正确性证明

计数不变式：读完前 k 个元素后，表中每个值的次数等于它在这 k 个元素中的出现次数。初始空表成立；每次只给当前值加一，因此成立到数组结束。

可靠性：加入答案的 x 满足完整表中次数为 1，且两侧值都不存在，恰好满足孤独数字的定义。

完备性：任何孤独数字都在数组和频次表中，且满足这三项条件。遍历它时一定会被收集。每个键只检查一次，因此不会重复输出。

边界与复杂度

  • 单个元素总是孤独；同一值出现多次，即使没有邻居也不能入选。
  • 0 的左邻 −1 不在输入值域内；哈希表查询自然得到不存在。1000000 的右邻同理。
  • 邻居是否重复不影响其“存在”；相差 2 不算相邻；答案可以为空。

令 n 为数组长度，k 为不同值数量。哈希表插入和查询的平均／期望成本为 O(1)，总时间为 O(n + k) = O(n)，额外空间为 O(k)（最坏 O(n)，不含输出）；输出最多 O(k)。严重哈希碰撞时，不应将平均查询成本当作无条件最坏保证。

四语言实现

以下均采用官方 findLonely 接口；不同语言的哈希表迭代顺序可能不同，题目允许任意输出顺序。代码未执行验证。

Java

import java.util.ArrayList;
import java.util.HashMap;
import java.util.List;
import java.util.Map;

class Solution {
    public List<Integer> findLonely(int[] nums) {
        Map<Integer, Integer> freq = new HashMap<>();
        for (int x : nums) {
            freq.put(x, freq.getOrDefault(x, 0) + 1);
        }
        List<Integer> answer = new ArrayList<>();
        for (Map.Entry<Integer, Integer> entry : freq.entrySet()) {
            int x = entry.getKey();
            if (entry.getValue() == 1
                    && !freq.containsKey(x - 1)
                    && !freq.containsKey(x + 1)) {
                answer.add(x);
            }
        }
        return answer;
    }
}

JavaScript

/**
 * @param {number[]} nums
 * @return {number[]}
 */
var findLonely = function(nums) {
    const freq = new Map();
    for (const x of nums) {
        freq.set(x, (freq.get(x) || 0) + 1);
    }
    const answer = [];
    for (const [x, count] of freq) {
        if (count === 1 && !freq.has(x - 1) && !freq.has(x + 1)) {
            answer.push(x);
        }
    }
    return answer;
};

Python 3

from collections import Counter
from typing import List

class Solution:
    def findLonely(self, nums: List[int]) -> List[int]:
        freq = Counter(nums)
        return [
            x for x, count in freq.items()
            if count == 1 and x - 1 not in freq and x + 1 not in freq
        ]

C++

#include <vector>
#include <unordered_map>
using namespace std;

class Solution {
public:
    vector<int> findLonely(vector<int>& nums) {
        unordered_map<int, int> freq;
        for (int x : nums) ++freq[x];
        vector<int> answer;
        for (const auto& entry : freq) {
            int x = entry.first;
            if (entry.second == 1
                && freq.find(x - 1) == freq.end()
                && freq.find(x + 1) == freq.end()) {
                answer.push_back(x);
            }
        }
        return answer;
    }
};

替代方案

排序：排序后，对每个位置 i，要求左边不存在或 a[i] − a[i−1] > 1，且右边不存在或 a[i+1] − a[i] > 1。重复值差为 0，自然被排除；最近的左右值都足够远，就没有相差 1 的值。时间 O(n log n)，排序辅助空间依语言实现而定；如需保留原数组，拷贝额外占 O(n)。

值域计数数组：利用上界 U = 10⁶，建立带边界哨兵的计数数组，扫描值域筛选。时间 O(n + U)，空间 O(U)；值域稀疏时哈希表更节省空间。

常见错误

  • 只使用 Set：丢失重复次数，无法排除示例 2 中的 3。
  • 两侧缺失条件用 OR：必须两侧都不存在，所以用 AND。
  • 统计过程中立即给结论：后面的元素可能推翻它。
  • 检查数组相邻位置：题目检查的是 x±1 的值是否存在。
  • C++ 遍历哈希表时用 freq[x - 1] 查询邻居：会插入缺失键，可能触发 rehash 并使迭代器失效。使用 find。

面试追问

  • 必须升序返回？对 k 个结果排序，增加 O(k log k) 时间；也可以排序输入后筛选。
  • 数据流尚未结束，能定案吗？通常不能，后续值可使现有候选失效；若需动态维护，更新值 x 只影响 x−1、x、x+1 的资格。
  • 允许负数或更大的数？哈希方案仍成立，但有界整数类型需防止 x±1 溢出；JavaScript 超过安全整数范围时需改用 BigInt 并统一键类型。
  • 改为距离 d 内没有其他数？朴素查询 2d 个邻居成本会上升；排序后比较最近左右数值的距离更合适。
