小张刷题计划

二分每天最大耗时 T；每一天把最耗时的一题交给小杨，实际耗时就是“当天总和 − 当天最大值”。

题意

按题号顺序完成 n 道题，并在 m 天内完成。每天最多选择当天一道题求助小杨，使其耗时不计入小张当天总耗时。求所有天中最大耗时的最小可能值 T。

示例：time = [1,2,3,3], m = 2

第 1 天做前三题，求助耗时 3 的题，实际用时 1+2=3；第 2 天求助最后一题，用时 0。最小最大值为 3。

顺序约束

每天负责一段连续题目，所有天的分段首尾相接。

数据范围

n ≤ 10⁵，m ≤ 1000，单题耗时不超过 10⁴。

阈值分组实验台

固定 [1,2,3,3]，调整允许的单日最大实际耗时。

核心洞察与完整过程

固定候选 T，从左到右尽量把更多题装进当天。维护当天总和 sum 与最大值 max，实际耗时为 sum-max。加入新题后若超过 T，就在新题前结束当天，并以新题开始下一天。若所需天数不超过 m，则 T 可行。对 [0,sum(time)] 二分最小可行值。

为什么贪心正确

给定 T，延长当前段只要仍满足限制，就不会让后续题更难分配；它使用最少天数。且当天求助最大耗时题一定最优，因为这样 sum-max 最小。可行性随 T 增大保持成立，因此能二分。

复杂度与替代方案

每次判定 O(n)，二分约 log(sum) 次，总时间 O(n log sum)，额外空间 O(1)。动态规划分段可做但会达到 O(nm) 或更高，不适合 n=10⁵。

边界 / 追问 / 常见错误

若 m ≥ n，答案自然可为 0。常见错误：切分后没有把当前题放入新一天；每天减去全局最大值而非当天最大值；遗漏原顺序与连续分段要求；二分边界未包含 0。 

class Solution {
  public int minTime(int[] time, int m) {
    int left = 0, right = 0; for (int x : time) right += x;
    while (left < right) { int mid = left + (right - left) / 2; if (canFinish(time, m, mid)) right = mid; else left = mid + 1; }
    return left;
  }
  private boolean canFinish(int[] time, int m, int limit) {
    int days = 1, sum = 0, largest = 0;
    for (int x : time) { sum += x; largest = Math.max(largest, x); if (sum - largest > limit) { days++; sum = largest = x; } }
    return days <= m;
  }
}
