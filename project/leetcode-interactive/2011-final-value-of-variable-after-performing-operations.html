执行操作后的变量值

Final Value of Variable After Performing Operations

从零开始，跟随每一个操作，观察变量的旅程。

01 / 题目说明

有一个初始为 0 的变量 X。字符串数组 operations 记录了一串操作：++X、X++ 都让 X 增加 1；--X、X-- 都让 X 减少 1。按列表执行完毕后，返回 X 的最终整数值。

输入参数：operations: string[]
返回值：integer

约束与思考

  • 1 ≤ operations.length ≤ 100
  • 每项只能是 "++X"、"X++"、"--X" 或 "X--"。

先预测结果，再用下方操作台观察过程。实现思路和代码收在页面底部，默认不展开。

02 / 官方示例

示例 1

输入：operations = ["--X","X++","X++"]
输出：1

变化过程：0 → −1 → 0 → 1。

示例 2

输入：operations = ["++X","++X","X++"]
输出：3

变化过程：0 → 1 → 2 → 3。

示例 3

输入：operations = ["X++","++X","--X","X--"]
输出：0

变化过程：0 → 1 → 2 → 1 → 0。

    05 / 题解档案

    准备好后，再展开思路和四语言实现。

    观察中间字符，累计变化

    核心洞察

    四种操作只有两种影响：+1 或 −1。它们的下标 1 都是运算符：++X 与 X++ 的中间字符为 +，另外两种为 -。前缀、后缀写法不影响本题要求的变量最终值，因为没有使用表达式返回值。

    完整过程

    1. 令 x = 0。
    2. 遍历每个操作 op：若 op[1] == '+' ，则 x 加 1，否则 x 减 1。
    3. 遍历结束返回 x。

    以示例 1 为例：--X 的中间字符为减号，0 变为 −1；两个 X++ 分别将 −1 变为 0、0 变为 1，因此返回 1。

    正确性证明

    循环不变式：处理完前 k 个操作时，x 等于从初始值 0 依次执行这 k 个操作后的变量值。初始 k = 0 时 x = 0，成立。处理第 k + 1 个操作时，中间字符准确区分两种增量；程序与题意同样加 1 或减 1，因此不变式保持。最终 k = n，x 就是全部操作执行后的最终值。

    边界与复杂度

    只有一个操作时返回 1 或 −1；全是递增时返回 n，全是递减时返回 −n；递增递减数量相等时返回 0。合法输入不包含空数组或其他操作。n ≤ 100，结果范围为 [−100, 100]，四种语言的常用整数表示都足够。

    时间复杂度 O(n)，每个固定长度字符串只读取一个字符。额外空间 O(1)，只维护累加器；交互页面保存回放轨迹的空间不计入提交算法。

    替代方案

    可以显式比较 op == "++X" || op == "X++"，更直接但代码稍长；也可先统计递增次数 p，再返回 2 * p - n。两者时间均为 O(n)、额外空间为 O(1)。不需要解析表达式或调用 eval。

    四语言完整提交代码

    Java

    class Solution {
    public int finalValueAfterOperations(String[] operations) {
        int x = 0;
        for (String op : operations) {
            x += op.charAt(1) == '+' ? 1 : -1;
        }
        return x;
    }
}

    常见错误

    • 只检查首字符：X++ 和 X-- 首字符都是 X，不能区分。
    • 把前缀和后缀当作不同增量：本题不使用表达式求值结果。
    • 忘记从 0 初始化，或只返回最后一次操作的变化量。
    • 在循环内提前 return，导致没有处理完整数组。
    • 使用 eval：既不必要，也会给可编辑输入引入代码执行风险。

    面试追问

    顺序会改变最终结果吗？ 不会，最终值是所有 ±1 的和，但中间轨迹会改变。

    数据以流的形式到达怎么办？ 每收到一项就更新 x，不必保留整个数组。

    初始值不是 0 呢？ 从给定初始值开始累计即可。

    若操作可含乘法呢？ 顺序可能影响结果，不能再用递增次数公式，应依次执行定义好的操作。
