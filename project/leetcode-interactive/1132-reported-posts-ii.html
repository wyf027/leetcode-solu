报告的记录 II

MEDIUM数据库付费题reported-posts-ii

把每天“被举报为垃圾信息的帖子”看成一个集合：先求其中最终被移除的比例，再对所有发生过垃圾举报的日期取平均。

先自己想一想：为什么分母不能直接使用举报行数？如果同一帖子被多人举报，会发生什么？题解在页面底部默认收起。

Problem

题意转述

给定用户行为表 Actions 与帖子移除表 Removals。对每一个至少出现过一次“举报且原因为 spam”的日期，计算当天所有被举报为垃圾信息的不同帖子中，后来出现在 Removals 的帖子占比。最后返回这些每日占比的平均值，并四舍五入到小数点后两位，列名为 average_daily_percent。

官方元数据中的付费题面与代码片段为空；本页依据官方题名、slug、数据库 DDL 和官方样例数据作简洁转述，没有复制付费题面。

Actions

列类型含义
user_idINT执行行为的用户
post_idINT帖子
action_dateDATE行为日期
actionENUMview / like / reaction / comment / report / share
extraVARCHAR(10)举报时存放原因；其他行为通常为空

Removals

列类型含义
post_idINT被移除的帖子
remove_dateDATE移除日期

目标只判断帖子是否被移除，不要求移除发生在举报当天。

约束与结果约定

  • action 仅取表结构列出的六种行为。
  • 只有 action = 'report' 且 extra = 'spam' 的记录参与统计；其他举报原因与其他行为不参与。
  • 同一天同一帖子可能对应多条行为或举报，因此日期内应按 post_id 去重。
  • 仅对至少有一个 spam 举报帖子的日期计算每日比例；结果是这些每日比例的算术平均值，保留两位小数。

Solution

题解：先算每日百分比，再求平均

核心洞察

平均对象是“日期”，而不是帖子或举报记录。内层查询必须先产生一行一个日期的百分比；外层再对这些行做 AVG。两处 COUNT(DISTINCT ...) 让同一帖子被重复举报时仍只计一次。

过滤report + spam
分组action_date
聚合每日比例的平均

完整过程

  1. 从 Actions 只保留 action = 'report' 且 extra = 'spam' 的行。
  2. 按 action_date 分组，分母是当天被举报为 spam 的不同 post_id 数。
  3. 用 LEFT JOIN Removals 保留未被移除的帖子；分子只统计连接成功的不同帖子。
  4. 乘以 100.0 形成百分比，避免整数除法。
  5. 外层对每日百分比取平均，并用 ROUND(..., 2) 保留两位小数。

正确性说明

引理 1：对任一参与统计的日期，过滤后的行恰好对应当天被举报原因为 spam 的行为；对 post_id 去重后，分母恰好是当天的目标帖子集合大小。

引理 2：左连接后，仅当帖子存在于 Removals 时 r.post_id 非空，所以对它做不同值计数，恰好得到该日目标集合中后来被移除的帖子数。

定理：由引理 1 和 2，内层每行都是对应日期的正确移除百分比；外层对所有这些日期等权求平均并四舍五入，因此返回题目要求的结果。

边界情况

  • 同一帖子同一天被多名用户举报：不同值计数防止重复。
  • 某日没有帖子被移除：左连接保留这些帖子，分子为 0。
  • 举报原因不是 spam：在分组前排除，日期若只含其他原因则不进入平均。
  • 帖子在更晚日期才被移除：仍视为已移除，因为这里只检验其是否存在于 Removals。

复杂度

设过滤前 Actions 有 A 行，Removals 有 R 行。概念上的数据处理规模为 O(A + R)，实际代价受索引、哈希/排序聚合与执行计划影响。中间结果空间至多与 spam 举报涉及的不同“日期—帖子”对数量同阶。

官方提交语言：MySQL

SELECT ROUND(AVG(daily_percent), 2) AS average_daily_percent
FROM (
    SELECT
        a.action_date,
        100.0 * COUNT(DISTINCT r.post_id)
              / COUNT(DISTINCT a.post_id) AS daily_percent
    FROM Actions AS a
    LEFT JOIN Removals AS r
        ON a.post_id = r.post_id
    WHERE a.action = 'report'
      AND a.extra = 'spam'
    GROUP BY a.action_date
) AS daily_rates;

替代方案
可以先用 CTE 生成不同的 (action_date, post_id)，再连接 Removals。它更显式，也容易检查去重边界，但语句更长。还可以用 EXISTS 判断帖子是否被移除，再对 0/1 标记聚合；某些数据库优化器下计划会不同。

        
面试追问
  • 如果题目要求按举报数量加权，而不是每日等权，外层聚合应如何变化？
  • 若只统计举报后 7 天内被移除，连接条件需要增加什么？
  • 如何为大表设计索引？可从 Actions(action, extra, action_date, post_id) 与 Removals(post_id) 开始讨论，并结合执行计划验证。
  • COUNT(DISTINCT) 成本过高时，如何用预去重 CTE 或物化汇总降低代价？

        
常见错误
  • 用 INNER JOIN 后再以连接结果作为分母，导致未移除帖子消失。
  • 先把所有日期的分子、分母相加再相除，得到帖子加权比例，而不是每日比例的平均。
  • 使用 COUNT(*)，把同一帖子多次举报重复计算。
  • 遗漏 extra = 'spam'，把 racism 等其他原因混入。
  • 使用整数除法，导致非 100% 的比例被截断。
