Race Brief

题意转述

环路上有 n 个加油站。到达第 i 站可获得 gas[i] 升汽油，驶向下一站消耗 cost[i] 升。油箱初始为空、容量无限；返回能绕行一周的唯一出发索引，否则返回 -1。

把每站净收益记为 diff[i] = gas[i] − cost[i]。问题就变成：能否从某处开始，让循环前缀余额始终不为负。

官方样例 1

输入
gas = [1,2,3,4,5], cost = [3,4,5,1,2]
输出
3

官方样例 2

输入
gas = [2,3,4], cost = [3,4,3]
输出
-1

Core Insight

局部失败，整段起点一起淘汰

假设从 start 出发，到站 i 时油量首次为负。对区间内任意更晚的起点 k，它少了前面原本非负的积累，到达 i 只会更差。因此 start…i 全部不可能，下一候选直接设为 i + 1。

Complexity

时间
O(n)
空间
O(1)

Complete Process

  1. 初始化 total = tank = start = 0。
  2. 逐站累加 diff = gas[i] - cost[i]。
  3. tank < 0 时令 start = i + 1、tank = 0。
  4. 扫描结束：total < 0 返回 -1，否则返回 start。

Edges & Mistakes

  • 单站且 gas[0] == cost[0]，答案仍是 0。
  • 必须用 total 判断无解，不能只看最后一段 tank。
  • 失败后从 i + 1 开始，不是 i。
  • 不要真的模拟每个起点，否则最坏 O(n²)。

Alternatives

暴力模拟直观但最坏 O(n²)。前缀和最低点也能 O(n)：从全局最低前缀之后出发；证明优雅，但面试编码与逐站解释通常不如双余额贪心直接。

Interview Follow-ups

  • 为什么解唯一？ 这是题目保证；算法即便面对多解，也会返回扫描得到的一个可行起点。
  • 油箱有容量上限呢？ 简单净收益前缀不再充分，需要模拟截断后的库存。
  • 怎样恢复实际一圈轨迹？ 得到 start 后再走一圈记录每站余额即可。

Why the Reset Is Safe

从 start 到 i−1 的每段前缀都非负，却在加入 i 后变负。区间内部任意 k 出发都会丢掉一段非负贡献，所以走到 i 时不可能比 start 更好。这正是一次跳过整段的贪心依据。

class Solution {
    public int canCompleteCircuit(int[] gas, int[] cost) {
        int total = 0, tank = 0, start = 0;
        for (int i = 0; i < gas.length; i++) {
            int diff = gas[i] - cost[i];
            total += diff;
            tank += diff;
            if (tank < 0) {
                start = i + 1;
                tank = 0;
            }
        }
        return total >= 0 ? start : -1;
    }
}
