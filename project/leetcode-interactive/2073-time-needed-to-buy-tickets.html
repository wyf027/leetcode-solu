买票需要的时间

Time Needed to Buy Tickets

一秒，一张票，一次轮转。跟住最初编号为 k 的那个人。

01 / 读懂规则

排队的人会变，身份不会变

有 n 个人按编号 0 到 n − 1 排队，0 号在队首。数组 tickets[i] 表示 i 号还想买多少张票。每次队首用恰好 1 秒买 1 张；如果还要买，就立即回到队尾，否则离队。回到队尾不耗时。

返回最初编号为 k 的人买完所有票时，经过的总秒数。此时其他人可以还没买完。

参数：tickets 为整数数组，k 为整数；返回整数秒数。查看官方题目 ↗

输入边界

约束

  • n == tickets.length
  • 1 ≤ n ≤ 100
  • 1 ≤ tickets[i] ≤ 100
  • 0 ≤ k < n

编号从 0 开始。一次服务仅购买一张票。

02 / 官方示例

先预测，再观察

示例 1tickets = [2,3,2], k = 2

输出：6

每秒买票的原始编号依次为 0、1、2、0、1、2。第 6 秒，2 号买完第 2 张票；1 号仍需 1 张。

示例 2tickets = [5,1,1,1], k = 0

输出：8

第 1 秒由 0 号买票；接着 1、2、3 号各买一张并离队。第 4 秒后只剩 0 号，再花 4 秒买完。

05 / 独立题解

准备好换个角度了吗？

展开后查看推导、证明与四语言实现。

从排队过程到个人贡献

核心洞察

设目标最初需要 T = tickets[k] 张。目标的第 T 次买票就是终点。原始位置 i ≤ k 的人，在这一轮已经有机会买票，最多贡献 T 秒；i > k 的人还没轮到，最多贡献 T − 1 秒。任何人贡献的时间也不能超过自己的总需求。

answer = Σ min(tickets[i], T − (i > k ? 1 : 0))

完整过程

  1. 保存目标票数 T，初始化累计时间 answer = 0。
  2. 从左向右遍历原数组。i ≤ k 的上限为 T，i > k 的上限为 T − 1。
  3. 将当前人的实际需求和上限的较小值加入 answer。
  4. 遍历结束返回 answer，过程中不修改 tickets。

以 tickets = [2,3,2], k = 2 为例，T = 2。三人的贡献分别是 min(2,2) = 2、min(3,2) = 2、min(2,2) = 2，总计 6 秒。以 [5,1,1,1], k = 0 为例，贡献为 5、1、1、1，总计 8 秒。

正确性证明

把每个人第 r 次获得服务视为第 r 轮。尚未离队的人始终按原始编号的循环顺序获得服务；离队只会跳过已经满足需求的人，不会改变剩余人的相对顺序。目标在第 T 轮完成，而这一轮的终止点恰好是 k。

因此 i ≤ k 的人有前 T 轮的服务机会，i > k 的人只有前 T − 1 轮的服务机会。提前买完的人仅使用 tickets[i] 次机会，故每个人的真实服务次数恰为公式中的最小值。每次服务恰好耗时一秒，且等待期间不存在其他耗时动作，所以求和就是目标完成的准确时间。

边界与复杂度

  • T = 1 时，后方贡献为 0，答案是 k + 1。
  • 只有一个人时，答案为 tickets[0]。
  • k = n − 1 时没有后方人员，所有人的上限均为 T。
  • 需求较小的人提前离队，由 min 自然处理。
  • 时间 O(n)，额外空间 O(1)。答案最多 100 × 100 = 10000，四语言的常用整数表示均足够。

替代方案：直接模拟

用队列保存原始编号，每秒取出队首、减少一张；目标刚好归零则立即结束，否则按需将此人放回队尾。用支持 O(1) 出入队的容器时，时间 O(S)，空间 O(n)，S 是目标完成前售出的票数，且 S ≤ Σ tickets[i]。也可以反复扫描原数组、跳过零值，时间 O(nT)，复制数组时空间 O(n)。页面采用队列模拟方便观察，并保留历史快照支持撤销；历史所用空间不属于上面求和算法的 O(1)。

常见错误

  • 把后方上限也写成 T，多算了目标离开之后的服务。
  • 使用 i < k 而非 i ≤ k，导致目标自己少买一张。
  • 在模拟时把队列当前第 k 位误当成目标；必须保留原始编号。
  • 一直模拟到队列为空；终止条件应是目标买完。
  • 先修改 tickets[k] 再拿它计算上限，丢失初始 T。

四语言完整提交代码

以下实现采用同一贡献求和算法，签名对应官方接口；均待补验证。

Java

class Solution {
    public int timeRequiredToBuy(int[] tickets, int k) {
        int target = tickets[k];
        int seconds = 0;
        for (int i = 0; i < tickets.length; i++) {
            int limit = i <= k ? target : target - 1;
            seconds += Math.min(tickets[i], limit);
        }
        return seconds;
    }
}

from typing import List

class Solution:
    def timeRequiredToBuy(self, tickets: List[int], k: int) -> int:
        target = tickets[k]
        seconds = 0
        for i, count in enumerate(tickets):
            limit = target if i <= k else target - 1
            seconds += min(count, limit)
        return seconds

面试追问

  • 为什么可以忽略队列移动？相对顺序固定，只需统计每人在终止前能获得多少次服务。
  • 每张票固定需要 c 秒呢？在其他规则不变时，将服务次数之和乘 c。
  • 每人的单张服务耗时不同呢？若仍保持相同轮转规则，每人贡献次数乘其单张耗时后求和。
  • 运行中有人插队或新加入呢？本公式依赖固定初始顺序，规则变化后应重新建模，通常需要事件或队列模拟。
  • 能否优于 O(n)？对于未预处理的单次查询，每个人的票数都可能影响答案，通常必须读取所有元素。
