每台机器的进程
平均运行时间

一张活动日志表记录每个进程的开始与结束。你的任务是按机器汇总完成一个进程的平均耗时，并将结果四舍五入到 3 位小数。

EASY数据库Average Time of Process per Machine

先读题并操作过程实验室；完整题解默认收起，不会在首屏直接揭示。

题目描述

表 Activity 保存工厂中各机器上进程的活动事件。

machine_idINT · 机器编号
process_idINT · 进程编号
activity_typeENUM('start','end')
timestampFLOAT · 秒

对每台机器，计算它所运行的所有进程的平均完成耗时。单个进程的耗时是结束时间戳减去开始时间戳。返回 machine_id 与别名为 processing_time 的平均耗时，四舍五入保留 3 位小数；结果顺序不限。

数据保证： (machine_id, process_id, activity_type) 是主键；每个机器与进程组合恰有一条 start 和一条 end；开始时间不晚于结束时间；每台机器运行相同数量的进程。

完整题解

核心洞察：把 Activity 表按机器和进程自连接，让 start 行与对应的 end 行组成一对；对每对做差后，再按机器求平均。

完整过程

  1. 划分两种事件。令 a1 只代表开始行，a2 只代表结束行。
  2. 精确配对。连接条件同时匹配 machine_id 与 process_id，并限制两边活动类型，确保不会把不同进程串在一起。
  3. 计算单次耗时。每对事件贡献 a2.timestamp - a1.timestamp。
  4. 按机器聚合。使用 GROUP BY machine_id 与 AVG(...) 得到每台机器的平均值。
  5. 规范输出。通过 ROUND(..., 3) 保留 3 位小数，并命名为 processing_time。

正确性说明

配对唯一主键保证同一机器、进程和活动类型只有一行；题目又保证起止事件都存在，因此自连接为每个进程产生且仅产生一对。
差值正确结束时间减开始时间正是定义中的进程完成耗时，且题目保证该值非负。
平均正确分组后，每个机器组恰好包含该机器所有进程的耗时；AVG 因此等于题目要求的总耗时除以进程数。

边界情况

  • 开始与结束时间相同：耗时为 0，仍应计入平均数。
  • 不同机器可使用相同的 process_id：连接时不能遗漏 machine_id。
  • 浮点时间戳需要在最终平均后统一四舍五入，而不是先舍入每个进程。
  • 题目保证完整配对；若真实业务日志可能缺失事件，应改用条件聚合并显式处理空值。

复杂度

设 Activity 有 n 行。逻辑计算需要访问全部行，聚合为 O(n)；数据库执行自连接的实际代价取决于索引与优化器。主键索引可支持配对查找。聚合结果与中间状态占用至多 O(n) 级空间。

官方可提交语言：MySQL

MySQLLeetCode 可直接提交
SELECT
    s.machine_id,
    ROUND(AVG(e.timestamp - s.timestamp), 3) AS processing_time
FROM Activity AS s
JOIN Activity AS e
  ON s.machine_id = e.machine_id
 AND s.process_id = e.process_id
 AND s.activity_type = 'start'
 AND e.activity_type = 'end'
GROUP BY s.machine_id;

Java本地语义参考
import java.util.*;

class Solution {
    record Activity(int machineId, int processId,
                    String type, double timestamp) {}
    record Result(int machineId, double processingTime) {}

    public List<Result> getAverageTime(List<Activity> rows) {
        Map<String, Double> starts = new HashMap<>();
        Map<Integer, Double> total = new HashMap<>();
        Map<Integer, Integer> count = new HashMap<>();

        for (Activity row : rows) {
            String key = row.machineId() + ":" + row.processId();
            if (row.type().equals("start")) {
                starts.put(key, row.timestamp());
            }
        }
        for (Activity row : rows) {
            if (!row.type().equals("end")) continue;
            String key = row.machineId() + ":" + row.processId();
            double duration = row.timestamp() - starts.get(key);
            total.merge(row.machineId(), duration, Double::sum);
            count.merge(row.machineId(), 1, Integer::sum);
        }

        List<Result> answer = new ArrayList<>();
        for (int machineId : total.keySet()) {
            double avg = total.get(machineId) / count.get(machineId);
            avg = Math.round(avg * 1000.0) / 1000.0;
            answer.add(new Result(machineId, avg));
        }
        answer.sort(Comparator.comparingInt(Result::machineId));
        return answer;
    }
}
JavaScript本地语义参考
function getAverageTime(activity) {
  const starts = new Map();
  const totals = new Map();
  const counts = new Map();
  const keyOf = (row) => `${row.machine_id}:${row.process_id}`;

  for (const row of activity) {
    if (row.activity_type === "start") {
      starts.set(keyOf(row), row.timestamp);
    }
  }
  for (const row of activity) {
    if (row.activity_type !== "end") continue;
    const duration = row.timestamp - starts.get(keyOf(row));
    totals.set(row.machine_id,
      (totals.get(row.machine_id) ?? 0) + duration);
    counts.set(row.machine_id,
      (counts.get(row.machine_id) ?? 0) + 1);
  }

  return [...totals.keys()].sort((a, b) => a - b).map(machineId => ({
    machine_id: machineId,
    processing_time: Number(
      (totals.get(machineId) / counts.get(machineId)).toFixed(3)
    )
  }));
}

from collections import defaultdict
from dataclasses import dataclass

@dataclass(frozen=True)
class Activity:
    machine_id: int
    process_id: int
    activity_type: str
    timestamp: float

def get_average_time(activity: list[Activity]) -> list[dict]:
    starts: dict[tuple[int, int], float] = {}
    totals: defaultdict[int, float] = defaultdict(float)
    counts: defaultdict[int, int] = defaultdict(int)

    for row in activity:
        if row.activity_type == "start":
            starts[(row.machine_id, row.process_id)] = row.timestamp

    for row in activity:
        if row.activity_type != "end":
            continue
        key = (row.machine_id, row.process_id)
        totals[row.machine_id] += row.timestamp - starts[key]
        counts[row.machine_id] += 1

    return [
        {"machine_id": machine_id,
         "processing_time": round(totals[machine_id] /
                                  counts[machine_id], 3)}
        for machine_id in sorted(totals)
    ]
C++本地语义参考
#include <algorithm>
#include <cmath>
#include <map>
#include <string>
#include <tuple>
#include <vector>
using namespace std;

struct Activity {
    int machineId;
    int processId;
    string type;
    double timestamp;
};

struct Result {
    int machineId;
    double processingTime;
};

class Solution {
public:
    vector<Result> getAverageTime(const vector<Activity>& rows) {
        map<pair<int, int>, double> starts;
        map<int, double> totals;
        map<int, int> counts;

        for (const auto& row : rows) {
            if (row.type == "start")
                starts[{row.machineId, row.processId}] = row.timestamp;
        }
        for (const auto& row : rows) {
            if (row.type != "end") continue;
            auto key = make_pair(row.machineId, row.processId);
            totals[row.machineId] += row.timestamp - starts.at(key);
            ++counts[row.machineId];
        }

        vector<Result> answer;
        for (const auto& [machineId, total] : totals) {
            double avg = total / counts[machineId];
            avg = round(avg * 1000.0) / 1000.0;
            answer.push_back({machineId, avg});
        }
        return answer;
    }
};

替代方案

条件聚合

按机器与进程分组，用 MAX(CASE WHEN ...) 取出起止时间，再在外层按机器求平均。它避免自连接，但需要两层聚合。

正负号一次聚合

把 end 时间记为正、start 时间记为负，按机器求和后除以进程数。更短，但依赖每个进程恰有一对事件，表达意图也略弱。

面试追问

如果每台机器的进程数不同？

AVG 天然按各分组实际行数计算，因此主解仍然成立；“数量相同”的条件并非主解所必需。

如果日志可能重复或缺失？

需要先定义数据清洗规则，例如保留最早 start 和最晚 end，并在聚合前排除未完整配对的进程。

为什么不能只按 process_id 连接？

不同机器可能有同名进程编号；遗漏 machine_id 会产生跨机器的错误笛卡尔配对。

怎样优化大表？

题目主键已经覆盖连接键。真实场景还可按时间分区，并确保统计查询只扫描目标时间范围。

常见错误

  • 自连接时只匹配 machine_id，导致同一机器的不同进程互相组合。
  • 没有限制 start / end 角色，产生重复对称组合或负数耗时。
  • 用 SUM / COUNT(*) 时忘记自连接后的每一行才代表一个进程。
  • 先四舍五入每个进程再求平均，引入不必要的累计误差。
  • 输出列名不是题目要求的 processing_time。
