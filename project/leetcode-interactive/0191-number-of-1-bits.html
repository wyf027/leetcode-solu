    04 / Solution

    题解默认隐藏

    展开后查看核心洞察、证明、复杂度、替代方案与四语言代码。

    Brian Kernighan's algorithm

    每次只处理一个真正存在的 1

    n - 1 会把最右侧的 1 变成 0，并把其右边的 0 全变成 1；与原数相与后，恰好只清除那个最右侧的 1。

    核心洞察与完整过程

    1. 初始化 count = 0。
    2. 只要 n != 0，执行 n = n & (n - 1)。
    3. 该操作清除当前最右侧置位，因此计数加一。
    4. 当 n 变成 0，原数所有置位均已清除，count 即答案。

    以 1011000 为例，减一得到 1010111，相与得到 1010000：仅最低的那个 1 被清掉。

    正确性证明

    设 n 最右侧 1 的位置为 p。位置 p 右侧全为 0。n - 1 借位后，p 变为 0，低于 p 的位全变为 1，高于 p 的位保持不变。于是 n & (n - 1) 保留所有高位，只删除位置 p 的 1。每轮删除且仅删除一个置位，循环执行 s 次后 n=0，其中 s 正是原数置位数。

    复杂度、边界与替代方案

    主线复杂度

    • 若置位数为 s，时间复杂度 O(s)，且 s ≤ 31。
    • 只维护 n 与 count，额外空间 O(1)。
    • n = 1 与 2 的幂都只需一轮。
    • 2³¹ - 1 有 31 个 1。

    替代方案

    • 逐位检查固定 31 位：始终 O(31)。
    • 语言内建 popcount：生产代码简洁，面试需说明限制。
    • 高频调用可预计算 256 个字节的置位数，每次查 4 段。
    • 更大整数可按机器字分块处理。

    四语言可提交代码

    class Solution {
    public int hammingWeight(int n) {
        int count = 0;
        while (n != 0) {
            n &= n - 1;
            count++;
        }
        return count;
    }
}
    /**
 * @param {number} n
 * @return {number}
 */
var hammingWeight = function (n) {
    let count = 0;
    while (n !== 0) {
        n = (n & (n - 1)) >>> 0;
        count++;
    }
    return count;
};

    面试追问

    • 为什么 n & (n - 1) 必定少一个 1？
    • 高频调用怎样设计 8 位查表？
    • 若输入允许负数，循环是否仍会终止？
    • 硬件 POPCNT 与查表如何取舍？

    常见错误

    • 把十进制字符串中的字符 1 当作二进制置位。
    • 省略括号却不说明运算符优先级。
    • 循环中忘记更新 n，导致死循环。
    • 把答案写成循环后的 n；此时 n 必为 0。
    • JavaScript 泛化到无符号 32 位时忘记 >>> 0。
