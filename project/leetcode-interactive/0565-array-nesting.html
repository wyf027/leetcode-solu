565. 数组嵌套 Array Nesting

从一个数组位置出发，把“当前值”当成“下一站索引”。轨道最终会在哪里闭合？最长的一圈又有多长？

Problem

题目说明

给定一个长度为 n 的整数数组 nums。它恰好是 [0, n - 1] 中所有整数的一种排列。

对任意起点 k，依次取出 nums[k]、nums[nums[k]]、nums[nums[nums[k]]]……，并在下一个元素将造成重复之前停止，得到集合 s[k]。请返回所有起点中，最大集合长度。

官方示例 1 
输入：nums = [5,4,0,3,1,6,2]
输出：4
解释：从 k = 0 出发：
s[0] = {nums[0], nums[5], nums[6], nums[2]}
     = {5, 6, 2, 0}
再次前进会得到 5，发生重复，因此长度为 4。
官方示例 2 
输入：nums = [0,1,2]
输出：1
解释：每个位置都指回自身；
任一起点得到的集合长度都是 1。

约束

  • 1 <= nums.length <= 105
  • 0 <= nums[i] < nums.length
  • nums 中的所有值互不相同，因此它是合法排列。

Full Solution

题解：把排列看成若干互不相交的环

核心洞察

因为 nums 是 0..n-1 的排列，每个索引恰好有一条出边，也恰好被一个索引指向。 整张图因此只会由若干个互不相交的环组成。任一起点得到的 s[k]，长度正是它所在环的长度。

完整过程

  1. 创建长度为 n 的全局访问标记。
  2. 依次枚举每个索引；如果它已经访问过，直接跳过。
  3. 从未访问索引出发，反复令 current = nums[current]，同时标记并计数。
  4. 遇到已访问索引时，本环结束；用本环长度更新最大值。

为什么全局标记不会漏答案？

两个不同环不共享任何索引。某个索引一旦访问过，它所在环的完整长度已经被统计；之后从同环其他索引出发只会得到相同长度，重复计算没有意义。

正确性证明

引理 1：从任意索引出发一定回到已出现的索引，因为可选索引有限。

引理 2：排列中每个点入度和出度都为 1，因此一条轨迹不会汇入另一个带“尾巴”的环；每个连通分量本身就是一个环。

结论：算法对每个环恰好完整计数一次，并取所有环长度最大值，所以返回值等于最长 s[k] 的长度。

边界情况

  • 单元素排列 [0]：唯一环长度为 1。
  • 全部自环：答案仍为 1。
  • 所有索引构成一个大环：答案为 n。
  • 多个不同长度的环：必须取最大值，而不是环的数量。
时间复杂度 O(n) 每个索引最多被首次访问一次。
空间复杂度 O(n) 使用 visited 数组；若允许修改 nums，可降为 O(1) 额外空间。

替代方案

可以在走过某个索引后把 nums[current] 改成 -1，直接复用输入数组充当访问标记，额外空间降为 O(1)。代价是破坏输入；若调用方还需要原数组，就不应使用。

也可以从每个起点各建一个集合，但会重复遍历同一环，最坏时间复杂度退化到 O(n²)。

常见错误

  • 把数组值累加，而不是统计访问的节点数量。
  • 每个起点都清空 visited，导致重复计算和超时。
  • 在发现重复元素之后才加计数，造成多算 1。
  • 误以为一般函数图也全是环；本题依赖“排列”这一关键条件。

面试追问

  • 如果数组值允许重复，图结构会发生什么变化？
  • 怎样在不额外分配 visited 的前提下完成？副作用是什么？
  • 怎样返回最长环本身，而不只是长度？
  • 如果输入不是排列，如何区分环前的链与真正的环？

一句话记忆

排列 = 不相交的环；全局访问一次，边走边数环长。

四语言完整代码

Java int arrayNesting(int[] nums) 
class Solution {
    public int arrayNesting(int[] nums) {
        boolean[] visited = new boolean[nums.length];
        int answer = 0;

        for (int start = 0; start < nums.length; start++) {
            if (visited[start]) {
                continue;
            }

            int current = start;
            int length = 0;
            while (!visited[current]) {
                visited[current] = true;
                current = nums[current];
                length++;
            }
            answer = Math.max(answer, length);
        }

        return answer;
    }
}

from typing import List


class Solution:
    def arrayNesting(self, nums: List[int]) -> int:
        visited = [False] * len(nums)
        answer = 0

        for start in range(len(nums)):
            if visited[start]:
                continue

            current = start
            length = 0
            while not visited[current]:
                visited[current] = True
                current = nums[current]
                length += 1

            answer = max(answer, length)

        return answer

继续追问

为什么不是普通 DFS？
可以把它称作对函数图的深度优先遍历，但每个节点只有唯一下一站，根本不需要递归栈或邻接表。用一个 while 循环沿指针前进更直接，也避免深度达到 105 时递归栈溢出。
如果要返回最长环中的索引序列呢？
每次开始新环时维护当前路径数组；当它的长度超过历史最大值，就复制该路径作为答案。时间复杂度仍是 O(n)，保存答案及访问状态所需空间为 O(n)。
