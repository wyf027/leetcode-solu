清扫过的空间个数

Number of Spaces Cleaning Robot Cleaned

只能向前，遇阻右转。跟随机器人观察房间中的清扫轨迹，再思考无限运行后的覆盖范围。

01题目与规则

给定从 0 开始编号的 m × n 二进制矩阵 room。值为 0 的格子可通行，值为 1 的格子有障碍。机器人从 (0, 0) 出发，初始朝右，起点保证可通行。

前方可走时沿当前方向前进一步；前方越界或有障碍时，留在原地顺时针转 90°，然后继续按相同规则行动。机器人会清扫起点及经过的每个格子。返回它无限运行时清扫过的不同格子数量。

同一个格子重复经过只计一次。已清扫的格子仍可通行；机器人不会主动寻找未清扫的格子。

参数与返回值

numberOfCleanRooms(room) → integer

room：二维整数矩阵；返回值：清扫过的不同空格数量。

约束

  • m == room.length
  • n == room[r].length，每行等长
  • 1 ≤ m, n ≤ 300
  • room[r][c] ∈ {0, 1}
  • room[0][0] == 0

官方示例

示例 1 · 绕过障碍
room = [[0,0,0],
        [1,1,0],
        [0,0,0]]

输出：7

沿顶行、右侧及底行移动，覆盖七个空格。

room = [[0,1,0],
        [1,0,0],
        [0,0,0]]

输出：1

room = [[0,0,0],
        [0,0,0],
        [0,0,0]]

输出：8

沿外圈行走，中间格不会被经过。

04题解 · 位置与朝向共同决定未来

核心洞察

位置相同不意味着接下来的运动相同：朝右和朝下的机器人可能走向不同格子。完整状态应为 (r, c, d)，其中 d = 0,1,2,3 分别对应右、下、左、上。房间固定且转移确定，同一个完整状态再次出现后，未来轨迹必然重放。

用每格的四位掩码 seen[r][c] 同时记录访问状态和清扫情况。第 d 位为 1 表示曾在该格朝向 d；掩码为 0 表示该格尚未清扫。这样无需单独的清扫数组，也无需修改 room。

完整过程

  1. 创建全零掩码矩阵。设置 r = c = d = answer = 0。
  2. 检查当前方向位。若已设置，结束模拟；否则继续。
  3. 若当前格掩码为 0，将 answer 加 1；然后设置方向位 seen[r][c] |= 1 << d。
  4. 按当前方向计算前方坐标。若坐标合法且值为 0，前进一步；否则只令 d = (d + 1) % 4，位置不变。
  5. 回到状态检查，最终返回 answer。
转向本身就是一次状态变化。被完全围住时仍能依次记录四个方向，第五次看到相同状态便结束。

示例推演

示例 1 中，先访问 (0,0) → (0,1) → (0,2)；边界使朝向从右变为下，再到 (1,2) → (2,2)；向下越界后右转朝左，到 (2,1) → (2,0)。此时计数为 7。随后仍按规则行动，但只经过旧格，直到某个位置与朝向的组合重复才结束程序。

用例 7 中，机器人先沿顶行向右再折返，回到 (0,0) 时朝左，与初始朝右不同。继续转向后可以进入 (1,0)，因此只按位置判重会漏算。

正确性说明

  1. 轨迹一致：初始位置和方向与题目相同；每轮只在前方空闲时移动，否则原地顺时针转向。因此归纳可得每轮模拟状态等于真实状态。
  2. 计数准确：一个格子第一次被处理时掩码为 0，计数恰好加一，随后掩码一直非零；每个经过的空格都被计数且不会重复计数。
  3. 停止安全：每个完整状态的后继唯一。再次遇到已处理状态时，此后的所有状态都将沿此前轨迹循环，不会再访问新的格子。
  4. 必然终止：最多存在 4mn 个完整状态，每轮处理一个新状态，或发现重复并停止。结合准确计数与安全停止，返回值正是无限运行所清扫的格子数量。

复杂度与边界

时间 O(mn)，空间 O(mn)。掩码矩阵初始化占 O(mn)，每格最多处理四种朝向，每轮 O(1)。最大 300 × 300 时，最多处理 360,000 个不同状态，答案不超过 90,000，普通 32 位整数足够。

单格房间返回 1；单行或单列需要正确处理连续转向；障碍后的空格可能永远无法到达。空的 3 × 3 房间也只清扫外圈，不能把连通空格总数当答案。输入保证非空且起点可通行，以下提交代码采用题目给定的输入契约。

替代方案

  • 三维布尔数组：以 seen[r][c][d] 判重，再配一个二维 cleaned 数组计数。语义直观，同为 O(mn)，但存储常数更大。
  • 原地记录：可把空格扩展编码为清扫与方向信息，减少辅助存储，但会修改输入，且障碍判断必须同步调整。
  • Floyd 判环：把状态看作函数图，先求链长与环长，再遍历有限轨迹。去重清扫格子仍需额外记录，且多次遍历使实现更复杂，本题直接模拟更清晰。

常见错误

  • 只用坐标判重，忽略同一格不同朝向的后续路径。
  • 遇阻立刻移动到右边的格子，漏掉再次越界或障碍的情况；正确行为是先原地转向。
  • 将已清扫格子当障碍，改变了机器人的真实路线。
  • 在设置掩码之后才检查是否首次访问，导致计数永远不增长。
  • 认为所有连通空格都会被扫到，误用 BFS / DFS 的可达数量作为结果。
  • 使用递归模拟长轨迹，可能导致调用栈溢出；这里使用循环。

面试追问

如果改为逆时针？只改方向更新为 (d + 3) % 4，状态判重不变。

如果障碍会移动？仅记录位置与朝向不够，必须把影响后继的环境信息或周期相位加入状态。

能否只等机器人回到起点朝右？不能保证循环包含初始状态，轨迹可能先走一段再进入其他环；记录所有完整状态更稳妥。

如果运行恰好 K 步？记录各状态首次出现的步数以求周期，可跳过完整循环；清扫数量要对已访问格子去重。

Java

class Solution {
    public int numberOfCleanRooms(int[][] room) {
        int m = room.length, n = room[0].length;
        int[][] seen = new int[m][n];
        int[] dr = {0, 1, 0, -1};
        int[] dc = {1, 0, -1, 0};
        int r = 0, c = 0, d = 0, answer = 0;
        while ((seen[r][c] & (1 << d)) == 0) {
            if (seen[r][c] == 0) answer++;
            seen[r][c] |= 1 << d;
            int nr = r + dr[d], nc = c + dc[d];
            if (nr >= 0 && nr < m && nc >= 0 && nc < n
                    && room[nr][nc] == 0) {
                r = nr;
                c = nc;
            } else {
                d = (d + 1) % 4;
            }
        }
        return answer;
    }
}

Python

from typing import List

class Solution:
    def numberOfCleanRooms(self, room: List[List[int]]) -> int:
        m, n = len(room), len(room[0])
        seen = [[0] * n for _ in range(m)]
        directions = [(0, 1), (1, 0), (0, -1), (-1, 0)]
        r = c = d = answer = 0
        while not (seen[r][c] & (1 << d)):
            if seen[r][c] == 0:
                answer += 1
            seen[r][c] |= 1 << d
            dr, dc = directions[d]
            nr, nc = r + dr, c + dc
            if 0 <= nr < m and 0 <= nc < n and room[nr][nc] == 0:
                r, c = nr, nc
            else:
                d = (d + 1) % 4
        return answer
