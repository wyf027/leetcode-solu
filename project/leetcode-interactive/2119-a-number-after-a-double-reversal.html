A NUMBER AFTER A DOUBLE REVERSAL

反转两次的数字

把数字转过去，再转回来。它还会是原来的数字吗？

01 / 题目

给定非负整数 num，先将它的十进制数位逆序，得到整数 reversed1；再将 reversed1 的数位逆序，得到 reversed2。如果最终结果与 num 相等，返回 true，否则返回 false。

每次结果都按整数解释，前导零不保留。例如 2021 → 1202，而 12300 → 321。

参数：num: integer　返回：boolean　约束：0 ≤ num ≤ 10⁶

官方示例 1

输入：num = 526
输出：true

526 → 625 → 526，恢复原值。

官方示例 2

输入：num = 1800
输出：false

1800 → 81 → 18，与原值不同。

官方示例 3

输入：num = 0
输出：true

0 → 0 → 0，仍是原值。

04 / 独立题解

先做出你的判断，再展开推导与代码。

核心洞察：哪一步丢掉了信息？

单纯倒置一个数位序列两次，必定得到原序列。问题出在整数不会保留前导零：正数末尾的零在第一次倒置后成为前导零，并被永久移除。因此只需判断 num == 0 || num % 10 != 0。

完整过程

  1. 若 num = 0，两次反转仍为 0，返回 true。
  2. 对于正数，用 num % 10 取得个位。
  3. 个位非零，没有数位因第一次反转而丢失，返回 true；个位为零，返回 false。

以 1800 为例：数位倒置得到“0081”，保存为整数 81，再倒置得到 18。以 1001 为例：内部的两个零不会变为前导零，两次反转仍是 1001。

正确性证明

对任意正数，将其写为 num = a × 10ᵏ，其中 a 的个位非零，k 是末尾零的数量。第一次反转会去掉这 k 个零，剩余数位等于 a 的反转；由于 a 的首位和末位都非零，第二次反转不会再丢失数位，结果恰好为 a。因此结果等于原数当且仅当 k = 0，即个位非零。零单独满足要求。两类情况覆盖全部合法输入，判断式正确。

边界与复杂度

  • 0 必须单独处理；非零一位数一定成立。
  • 内部零不影响结论；一个或多个末尾零都会让正数不成立。
  • 上界 1000000 不成立。官方输入已保证合法，不需要在提交函数内解析或校验字符串。
  • 最优算法时间 O(1)，额外空间 O(1)；采用题目范围内的固定宽度整数运算模型。

替代方案

可以通过 rev = rev * 10 + x % 10 并令 x = floor(x / 10)，逐位反转两次后比较。初始化 rev = 0 可自然处理零。若位数为 d，时间为 O(d)，空间为 O(1)。字符串反转两次也可实现，但每次都要转换为整数以去掉前导零，时间和额外空间均为 O(d)。本题无需实际构造反转结果。

面试追问

  • 换成 b 进制呢？对于 b ≥ 2，条件变为 num == 0 || num % b != 0，原因仍是末尾零丢失。
  • 第三、第四次反转会怎样？第一次后已去掉原数末尾零，之后在剩余数字及其反转之间交替；所有正偶数次反转都得到原数去掉末尾零的结果。
  • 输入改为超长十进制字符串呢？先约定表示规范；若字符串是整数的规范表示，只需判断它是否为“0”或末字符是否非“0”。

常见错误

  • 只判断 num % 10 != 0，遗漏了零。
  • 只做字符串倒置并保留前导零，会误以为所有数字都能恢复。
  • 把“包含零”作为失败条件，错误排除 1001 等内部含零的数。
  • 把它当成回文数问题；526 并非回文数，但两次反转能恢复。
  • 扩展到更大数值时模拟反转可能溢出；这里的常数判断无需构造反转整数。
