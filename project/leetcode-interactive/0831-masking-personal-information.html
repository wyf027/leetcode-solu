Problem 831 · Medium

隐藏个人信息

同一条输入可能是邮箱，也可能是电话号码。目标不是“尽量多遮住”，而是严格按两套格式规则，生成稳定、可比较的脱敏字符串。

函数契约

maskPII(s: string): string

输入保证有效；只需判断类型、规范化字符，再按照对应模板输出。

01 / 题意

两种输入，两套脱敏规则

给定字符串 s，它表示一个有效的邮箱地址或电话号码。请返回按下列规则隐藏个人信息后的字符串。

@

邮箱地址

  • 邮箱由至少 2 个英文字母组成的名字、@ 和带一个中间点号的域名构成。
  • 名字与域名中的大写字母全部转成小写。
  • 名字只保留首尾字符；中间无论原来多长，都替换为固定的 *****。
+*

电话号码

  • 输入包含 10～13 位数字，并可能混有 + - ( ) 和空格。
  • 先移除分隔字符；后 10 位是本地号码，之前的 0～3 位是国家代码。
  • 本地号码固定输出 ***-***-XXXX；若有国家代码，前缀为 + 与等量星号，再接连字符。

官方示例

Example 01
输入
s = "LeetCode@LeetCode.com"
输出
"l*****e@leetcode.com"
说明
邮箱整体转小写，并隐藏名字中间部分。
Example 02
输入
s = "AB@qq.com"
输出
"a*****b@qq.com"
说明
即使名字只有 2 位，中间仍固定放 5 个星号。
Example 03
输入
s = "1(234)567-890"
输出
"***-***-7890"
说明
共 10 位数字，无国家代码，保留末 4 位。

约束

  • s 一定是有效的邮箱或电话号码。
  • 邮箱：8 <= s.length <= 40，由大小写英文字母、恰好一个 @ 和一个位于域名中间的 . 组成。
  • 电话：10 <= s.length <= 20，由数字、空格及 ( ) - + 组成；数字总数为 10～13。

03 / Solution

准备好看题解了吗？

先自己想一想：哪个字符可以无歧义地区分两类输入？

核心洞察

一次分流，按规则拼装

合法邮箱一定含有 @，合法电话一定不含。因此无需复杂正则：先用 @ 分流，再分别做最少的字符串处理。

01

识别类型

检查 s 中是否存在 @。

02

规范化

邮箱转小写；电话仅提取数字。

03

模板输出

保留必要边界字符，其他位置填入星号。

完整过程

邮箱 A整体转小写，找到 @ 的位置。
邮箱 B取第 1 个字符、固定 5 星、@ 前最后一个字符及完整域名。
电话 A遍历输入，只收集数字；设数字数为 n。
电话 B国家代码长 n - 10；拼接等量星号与固定本地模板，末尾取后 4 位。

正确性说明

邮箱分支：转小写保证名字和域名无大写；拼接中只保留名字首尾字符，中间恰好放置 5 个星号，域名保持完整，所以严格满足邮箱脱敏规则。

电话分支：过滤后序列恰好是原号码的全部数字，且顺序不变。前 n-10 位对应国家代码，等量星号准确隐藏它；固定模板隐藏本地号码前 6 位，切片得到的末 4 位保持不变。因此输出严格满足电话规则。

两类有效输入由是否含 @ 完全区分，故算法覆盖所有合法情况。

边界与复杂度

  • 名字恰好 2 位时，仍在两字符之间插入固定 5 个星号。
  • 电话恰好 10 位时没有国家代码，输出不能带 +。
  • 国家代码为 1～3 位时，前缀星号数量必须与其位数相同。
  • 电话分隔符出现位置不固定，不能依赖某一种排版格式。
时间
O(n)：至多线性扫描输入。
空间
O(n)：保存规范化字符串或数字序列。
可提交实现

四种语言

class Solution {
    public String maskPII(String s) {
        int at = s.indexOf('@');
        if (at >= 0) {
            String lower = s.toLowerCase();
            return lower.charAt(0) + "*****"
                    + lower.substring(at - 1);
        }

        StringBuilder digits = new StringBuilder();
        for (char c : s.toCharArray()) {
            if (Character.isDigit(c)) {
                digits.append(c);
            }
        }

        int countryLength = digits.length() - 10;
        StringBuilder answer = new StringBuilder();
        if (countryLength > 0) {
            answer.append('+');
            answer.append("*".repeat(countryLength));
            answer.append('-');
        }
        answer.append("***-***-");
        answer.append(digits.substring(digits.length() - 4));
        return answer.toString();
    }
}
/**
 * @param {string} s
 * @return {string}

var maskPII = function(s) {
    if (s.includes('@')) {
        const lower = s.toLowerCase();
        const at = lower.indexOf('@');
        return lower[0] + '*****' + lower.slice(at - 1);
    }

    const digits = s.replace(/\D/g, '');
    const countryLength = digits.length - 10;
    const country = countryLength > 0
        ? '+' + '*'.repeat(countryLength) + '-'
        : '';

    return country + '***-***-' + digits.slice(-4);
};
class Solution:
    def maskPII(self, s: str) -> str:
        if '@' in s:
            lower = s.lower()
            at = lower.index('@')
            return lower[0] + '*****' + lower[at - 1:]

        digits = ''.join(char for char in s if char.isdigit())
        country_length = len(digits) - 10
        country = (
            '+' + '*' * country_length + '-'
            if country_length > 0
            else ''
        )
        return country + '***-***-' + digits[-4:]

public:
    string maskPII(string s) {
        size_t at = s.find('@');
        if (at != string::npos) {
            transform(s.begin(), s.end(), s.begin(), ::tolower);
            return s.substr(0, 1) + "*****" + s.substr(at - 1);
        }

        string digits;
        for (char c : s) {
            if (isdigit(static_cast<unsigned char>(c))) {
                digits.push_back(c);

        string country = countryLength > 0
            ? "+" + string(countryLength, '*') + "-"
            : "";

                + digits.substr(digits.size() - 4);

替代方案

可以用正则分别完成邮箱捕获和电话清洗，但本题规则很窄：@ 判断加字符串切片更短、更容易证明，也避免复杂捕获组。若希望把额外空间降到更低，可边扫描电话边维护后 4 位和数字总数，但会牺牲可读性，且最终返回值本身仍需空间。

常见错误

  • 把邮箱名字中间替换成“等长”星号，而不是固定 5 个。
  • 忘记将域名一起转为小写。
  • 用原字符串长度推断国家代码，误把分隔符算进去。
  • 10 位电话仍拼接了 + 或额外连字符。

面试追问

  • 如果输入不再保证有效，验证层应如何设计？
  • 如何支持更多邮箱符号或可变长度的本地号码？
  • 如果数据量极大，能否流式处理并减少临时字符串？

回答要点

先明确格式契约，再分离“识别、规范化、呈现”三层。扩展规则时尽量让每种类型拥有独立策略；流式场景中，邮箱需保留边界，电话只需计数并保存最后 4 位。
