分汤Soup Servings

四把固定容量的勺子，两个逐渐见底的汤锅。目标不是追踪某一次随机过程，而是计算所有可能终局的加权概率。

数学 动态规划 概率与统计
每种操作概率 ¼

Problem

先把随机规则说清楚

下面是对官方题面的准确转述。A、B 两种汤初始各有 n 毫升，每轮独立且等概率地执行一种操作。

每轮从四个操作中随机选择一个，概率均为 0.25：

  1. 从 A 取 100 mL，从 B 取 0 mL
  2. 从 A 取 75 mL，从 B 取 25 mL
  3. 从 A 取 50 mL，从 B 取 50 mL
  4. 从 A 取 25 mL，从 B 取 75 mL

若某种汤的剩余量不足本轮所需，就取走它的全部剩余量。A、B 同时被取用；任意一种汤在一轮中耗尽后，过程立即停止。

返回：P(A 先耗尽) + ½ × P(A、B 同轮耗尽)

规则边界

  • 没有“从 A 取 0 mL、从 B 取 100 mL”的操作。
  • 每轮的随机选择与之前所有轮次相互独立。
  • 答案与真实值的误差不超过 10−5 即可。
参数形式

soupServings(n: integer) → double

约束

0 ≤ n ≤ 109

示例 1

输入n = 50
输出0.62500

前两种操作让 A 先空，第三种让两汤同轮空，第四种让 B 先空，因此加权结果为 0.25 × (1 + 1 + 0.5 + 0)。

示例 2

输入n = 100
输出0.71875

第一轮之后仍可能继续取汤，需要把四个后继状态的终局得分按各自的 ¼ 概率递归汇总。

Solution

准备好再揭开递推式

题解与四份完整代码默认收起，避免在首屏直接泄露思路。

Dynamic Programming

题解：缩放状态 + 记忆化搜索

这道题的关键不是模拟随机数，而是为每个“剩余汤量状态”计算从这里出发的期望得分。

INSIGHT 01

按 25 mL 缩放

所有取用量都是 25 的倍数，因此令 m = ceil(n / 25)，四种操作变为 (4,0)、(3,1)、(2,2)、(1,3)。

INSIGHT 02

终局就是分数

A 先空得 1 分；B 先空得 0 分；同时空得 0.5 分。这恰好等于题目要求的概率表达式。

INSIGHT 03

大输入提前收敛

A 每轮平均减少更多，随着初始量增大，A 先空的概率趋近 1。n > 4800 时直接返回 1，误差已在允许范围内。

状态定义与完整过程

定义 F(a, b) 为 A 剩余 a 个单位、B 剩余 b 个单位时，从该状态出发获得的目标概率。

F(a,b) = ¼ × [F(a−4,b) + F(a−3,b−1) + F(a−2,b−2) + F(a−1,b−3)]
  1. 若 a ≤ 0 且 b ≤ 0，两汤同轮耗尽，返回 0.5。
  2. 否则若 a ≤ 0，A 先耗尽，返回 1。
  3. 否则若 b ≤ 0，B 先耗尽，返回 0。
  4. 其余状态对四个后继状态求平均，并用记忆化缓存避免重复计算。
  5. 答案为 F(m, m)。当 n > 4800 时使用收敛剪枝。

正确性说明

终止状态正确：三个边界返回值分别对应题目对 A 先空、同时空、B 先空的计分规则。

状态转移正确：在任意非终止状态，下一轮恰有四个互斥且完备的操作，每个概率均为 ¼。依据全概率公式，当前状态的目标概率等于四个后继状态目标概率的等权平均。

归纳结论：以 a + b 为序。每次转移都会减少总剩余量，且更小状态的值由归纳假设正确；结合正确的终止状态和转移，可得 F(m,m) 正确。大输入分支利用概率向 1 的收敛性质，并满足题目允许的 10−5 误差。

边界处理

  • n = 0：初始即同时为空，返回 0.5。
  • 判断“同时为空”必须放在单独判断 A 或 B 之前。
  • 非 25 倍数要向上取整，因为不足一次取用量时会取走全部剩余。

复杂度

剪枝后 m ≤ 192。每个状态只计算一次，每次处理 4 条转移。

时间：O(m²)
空间：O(m²)，递归栈深度为 O(m)。

class Solution {
    private Double[][] memo;

    public double soupServings(int n) {
        if (n > 4800) {
            return 1.0;
        }

        int units = (n + 24) / 25;
        memo = new Double[units + 1][units + 1];
        return dfs(units, units);
    }

    private double dfs(int a, int b) {
        if (a <= 0 && b <= 0) {
            return 0.5;
        }
        if (a <= 0) {
            return 1.0;
        }
        if (b <= 0) {
            return 0.0;
        }
        if (memo[a][b] != null) {
            return memo[a][b];
        }

        memo[a][b] = 0.25 * (
            dfs(a - 4, b) +
            dfs(a - 3, b - 1) +
            dfs(a - 2, b - 2) +
            dfs(a - 1, b - 3)
        );
        return memo[a][b];
    }
}

var soupServings = function(n) {
    if (n > 4800) {
        return 1;
    }

    const units = Math.ceil(n / 25);
    const memo = Array.from(
        { length: units + 1 },
        () => Array(units + 1)
    );

    const dfs = (a, b) => {
        if (a <= 0 && b <= 0) {
            return 0.5;
        }
        if (a <= 0) {
            return 1;
        }
        if (b <= 0) {
            return 0;
        }
        if (memo[a][b] !== undefined) {
            return memo[a][b];
        }

        memo[a][b] = 0.25 * (
            dfs(a - 4, b) +
            dfs(a - 3, b - 1) +
            dfs(a - 2, b - 2) +
            dfs(a - 1, b - 3)
        );
        return memo[a][b];
    };

    return dfs(units, units);
};

class Solution {
private:
    vector<vector<double>> memo;

    double dfs(int a, int b) {
        if (a <= 0 && b <= 0) {
            return 0.5;
        }
        if (a <= 0) {
            return 1.0;
        }
        if (b <= 0) {
            return 0.0;
        }
        if (memo[a][b] >= 0.0) {
            return memo[a][b];
        }

        return memo[a][b] = 0.25 * (
            dfs(a - 4, b) +
            dfs(a - 3, b - 1) +
            dfs(a - 2, b - 2) +
            dfs(a - 1, b - 3)
        );
    }

public:
    double soupServings(int n) {
        if (n > 4800) {
            return 1.0;
        }

        int units = (n + 24) / 25;
        memo.assign(
            units + 1,
            vector<double>(units + 1, -1.0)
        );
        return dfs(units, units);
    }
};

替代方案

自底向上 DP：按 a + b 从小到大填表，避免递归；状态和复杂度相同，但边界下标处理更繁琐。

蒙特卡洛模拟：直观但有抽样误差，难以稳定保证 10−5，不适合作为本题提交方案。

面试追问

  • 为什么缩放时必须向上取整，而不是向下取整？
  • 如何不依赖固定的 4800，动态找到满足误差的截断点？
  • 若四种操作概率不同，递推式如何修改？
  • 若加入 (0,4) 操作，答案的极限还会是 1 吗？

常见错误

  • 把“同时耗尽”返回成 1 或 0，而不是题目要求的 0.5。
  • 先判断 a ≤ 0，导致同时耗尽的状态被错误计为 A 先耗尽。
  • 直接以毫升为状态，既浪费空间，也忽略所有操作都是 25 的倍数。
  • 对 n = 109 仍建立完整二维表，没有使用概率收敛剪枝。
  • 用随机模拟结果冒充精确 DP，无法稳定达到误差要求。
