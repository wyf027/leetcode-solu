Nim 游戏 II

Game of Nim · 从轮流取石子，理解必胜与必败局面。

题目

给定整数数组 piles，每个元素表示一堆石子的数量。Alice 先手，双方轮流行动；每次必须选一堆非空石子，取走其中至少一颗，可以整堆取完。轮到某人时若已无石子可取，此人输。假设双方都采取最优策略，返回 Alice 能否获胜的布尔值。

参数与返回：nimGame(piles: integer[]) → boolean

约束：n == piles.length；1 ≤ n ≤ 7；1 ≤ piles[i] ≤ 7。

注意：这是多堆游戏，每步只操作一堆。取走最后一颗石子的人获胜。

官方示例（完整参数）

输入：piles = [1]
输出：true

Alice 取走唯一的石子，Bob 无法行动。

输入：piles = [1,1]
输出：false

Alice 取一堆，Bob 取另一堆，Alice 输。

输入：piles = [1,2,3]
输出：false

一条对局路径为 [1,2,3] → [1,2,0] → [1,1,0] → [0,1,0] → [0,0,0]。Bob 取走最后一颗；最优对抗下 Bob 能确保获胜。

取石子实验台

按步观察双方的一条最优策略对局。先观察每次仅一堆发生变化，再到题解中查看选择依据。必败方存在多个等价选择，此处固定取第一堆的一颗。

输入逗号分隔整数，例如 3,4,5；也支持 [3,4,5]。

独立题解

准备好后，再展开策略与四语言实现。

核心洞察：每一位的奇偶性

把所有堆的数量按位异或，记为 S。S = 0 是当前行动方的必败局面；S ≠ 0 是必胜局面。因此答案就是所有元素异或后是否非零。

完整过程

  1. 累加器从 0 开始。
  2. 依次异或每堆数量，不改变输入数组。
  3. 遍历结束，返回累加器是否不等于 0。

例如 [3,4,5]：000 ⊕ 011 = 011；011 ⊕ 100 = 111；111 ⊕ 101 = 010。结果为 2，因此 Alice 必胜。把第一堆 3 改为 3 ⊕ 2 = 1，就把局面交为 [1,4,5]，其异或为 0。

当前实验台 · 位列透镜

二进制的每一列有偶数个 1，异或结果该位才是 0。实验台在非零局面选择一堆 x，使 y = x ⊕ S < x，取走 x − y 颗；零局面则固定选择一个合法动作。
正确性证明
终态：所有堆都是 0 时，异或为 0，行动方无合法动作而输。
零不能走到零：一次把某堆 x 减为 y，x ≠ y。新异或为 S ⊕ x ⊕ y。当 S = 0 时，新结果 x ⊕ y 必非零。
非零必能走到零：取 S 的最高置位，该位至少有一堆 x 为 1。令 y = x ⊕ S。更高位不变，该位由 1 变 0，所以 y < x，动作合法；新异或 S ⊕ x ⊕ y = 0。每步石子总数严格下降，游戏必终止。两类局面交替，持续把零局面交给对手即可保证对手最终无步可走。
边界与复杂度
单堆总能一次取完。两堆相等则异或为零。全是 1 时由堆数奇偶决定胜负。中途空堆贡献 0；初始输入不允许空堆或空数组。时间 O(n)，额外空间 O(1)；不需要模拟整场对局。
替代方案
记忆化搜索：若存在一个动作使对手进入必败状态，则当前状态必胜；无合法动作时必败。可用元组或八进制编码保存各堆数量。至多 8ⁿ 个状态，每个状态枚举至多 7n 个动作，粗略上界时间 O(8ⁿ·7n)，空间 O(8ⁿ+n)。它适合探索规则，异或法更适合本题的线性时间追问。
常见错误
  • 使用总石子数的奇偶，或误套单堆每次取 1–3 颗的取模规则。
  • 用逻辑或、按位或或加法代替按位异或。
  • 只给出非零结论，却没有证明存在合法的变零动作。
  • 把“拿最后一颗获胜”误读为“拿最后一颗失败”。
面试追问
如何输出获胜动作？先算 S，再找 x ⊕ S < x 的堆，返回堆下标与取走量，仍为 O(n)。若改成拿最后一颗输？这是反常 Nim；全为 1 的局面需要反转奇偶策略，其余局面仍按非零异或判断。若每次最多取 k 颗？单堆 Grundy 值为 x mod (k+1)，对这些值求异或，原堆数异或不再普遍适用。


Java
class Solution {
    public boolean nimGame(int[] piles) {
        int sum = 0;
        for (int pile : piles) sum ^= pile;
        return sum != 0;
    }
}

};
