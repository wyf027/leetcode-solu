4017. 数组中的峰值 II

动态更新下，统计区间内「内部含峰」的子数组数量。

打开题目
n, q
均可达 10⁵
峰
严格大于左右邻居
目标
含至少一个内部峰的子数组

题意：峰属于子数组内部

查询 [1,l,r] 问的是完全落在 nums[l..r] 的、长度至少为 3 的子数组中，有多少个存在 i < k < j 且 nums[k] 大于相邻两数。更新 [2,index,val] 会影响后续查询。

容易混淆：不是数峰的个数；一个峰可使许多不同左右端点的子数组成立。

例子

[1,3,2,4] 在 [0,3] 中：[1,3,2] 与 [1,3,2,4] 都由位置 1 的峰成立，答案是 2。

核心洞察

按“最左峰”给每个合格子数组唯一归属。区间内峰为 p₁ < p₂ < …：

  1. p₁ 的左端点有 p₁-l 种，右端点有 r-p₁ 种。
  2. 后续峰 p 的左端点只能在上一峰之后，有 p-prev(p) 种。

答案：(p₁-l)(r-p₁) + Σ (p-prev(p))(r-p)。

只需维护区间峰序列的首、尾，以及相邻峰距离的 Σd 与 Σ(d·p)。

交互实验室

修改数组或执行查询。黄色格是当前全局峰；范围查询仅把 l+1..r-1 的峰交给线段树。

准备就绪。

过程：可合并的线段树摘要

每个节点保存 {count, first, last, sumD, sumDP}。合并左右节点时，若两边都有峰，新增跨边相邻对： 

d = right.first - left.last
sumD  += d
sumDP += d * right.first

点更新只可能让 index-1, index, index+1 的峰状态改变；逐一重算叶子后向上合并。范围查询把节点摘要按顺序合并，首峰的“前驱”无需存储，公式会用 l 覆盖它。

边界与复杂度

  • r-l<2：没有长度 ≥ 3 的子数组，答案为 0。
  • 查询结果没有峰：摘要 count=0，答案为 0。
  • 端点本身不能当内部峰，查询范围固定为 [l+1,r-1]。
  • 相等不算峰，条件必须使用严格 >。
操作 复杂度
建树 O(n)
更新 O(log n)
查询 O(log n)
空间 O(n)

四语言实现

同一摘要模型；JavaScript 版用 BigInt 承载答案，避免乘法超出安全整数。

Java 
// SegmentTree 的 query(l + 1, r - 1) 返回 Node 聚合摘要
long count(Node x, int l, int r) {
  if (x.count == 0 || r - l < 2) return 0;
  return (long)(x.first-l)*(r-x.first) + (long)r*x.sumD-x.sumDP;
}
// update(i,v): nums[i]=v; for (j=i-1..i+1) set(j, peak(j));
JavaScript 
const answer = (x, l, r) => !x.count || r-l<2 ? 0n :
  BigInt(x.first-l)*BigInt(r-x.first) + BigInt(r)*x.sumD-x.sumDP;
// merge(a,b) 加入 b.first-a.last；每个叶子仅代表一个峰或空。
Python 
def count(x, l, r):
    if not x.count or r - l < 2: return 0
    return (x.first-l)*(r-x.first) + r*x.sum_d-x.sum_dp
# point-update 时重建 i-1, i, i+1 三个叶子
C++ 
long long count(const Node& x,int l,int r){
  if(!x.c || r-l<2) return 0;
  return 1LL*(x.first-l)*(r-x.first)+1LL*r*x.sd-x.sdp;
}

替代方案与取舍

有序集合 + 两棵 Fenwick：维护峰位置及 d、d·p 的前缀和，也能 O(log n)，但更新插删峰时需细心修复后继峰的 d。线段树把相邻关系封装在 merge 中，代码更统一。

常见错误

  • 把所有含同一峰的区间直接相加，重复计数。
  • 把 l/r 本身纳入峰集合。
  • 更新后只检查 index，漏掉两侧。
  • 用 32 位整数保存乘积。
