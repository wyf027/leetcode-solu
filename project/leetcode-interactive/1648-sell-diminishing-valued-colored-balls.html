销售价值减少的颜色球

Sell Diminishing-Valued Colored Balls

价格就是库存高度。每卖掉一颗，同色球的下一次售价便下降 1。真正的挑战不是“选最高”——而是如何把一整层最高价一次算完。

题号 1648非付费题取模 10⁹ + 7批次 184 / 300
01 / Problem

题目

函数：maxProfit(inventory, orders)

仓库里有若干种颜色的球，inventory[i] 是第 i 种颜色当前的数量。顾客购买某个颜色的一颗球时，它的价值恰好等于该颜色在出售前的剩余数量；卖出后库存减一，因此下一颗同色球也便宜一。

你可以自由决定出售顺序。请在恰好卖出 orders 颗球后，返回能够获得的最大总价值。结果需要对 1,000,000,007 取模。

参数形式
inventory: integer[]，orders: integer → 返回 integer。

官方示例

示例 1

输入：inventory = [2,5], orders = 4
输出：14
解释：选择价值 5、4、3 和 2 的球，
总价值为 5 + 4 + 3 + 2 = 14。

示例 2

输入：inventory = [3,5], orders = 6
输出：19
解释：可售出价值 5、4、3、3、2、2，
总价值为 19。

示例 3

输入：inventory = [2,8,4,10,6], orders = 20
输出：110

示例 4

输入：inventory = [1000000000], orders = 1000000000
输出：21
解释：原始总价值是 500000000500000000，
对 10⁹ + 7 取模后为 21。

约束

  • 1 ≤ inventory.length ≤ 10⁵
  • 1 ≤ inventory[i] ≤ 10⁹
  • 1 ≤ orders ≤ min(sum(inventory[i]), 10⁹)

03 / Editorial

先自己推一遍，再打开完整题解

Solution / Greedy by Layers

题解：从最高处按层收割

任意时刻都应该出售当前价值最大的球。排序以后，与其用堆逐颗取最大值，不如把若干根同高柱子一起降到下一个高度，并用等差数列一次结算。

核心洞察

假设降序库存中，当前高度为 high，下一档为 low，已有 width 种颜色达到 high。把它们全部降到 low 需要卖出 (high-low)×width 颗。若订单足够，就结算每种颜色的 high + (high-1) + … + (low+1)；若订单不够，则只卖若干完整层，再在同一层卖余数颗。

sum(from…to) = (from + to) × (from - to + 1) / 2 完整区间收益 = width × sum(low + 1 … high) 部分区间：orders = q × width + r 收益 = width × sum(high - q + 1 … high) + r × (high - q)

完整过程

降序排序并补哨兵 0。排序后，相邻元素定义了一个可整体削平的高度区间；尾部的 0 让最低一档也按相同逻辑处理。
逐档扩大颜色组。扫描到下标 i 时，前 i+1 种颜色构成当前最高组，即 width = i+1。
能卖完整区间就一次结算。若剩余订单不少于 (high-low)×width，用等差数列累加，扣除相应订单，进入下一档。
订单在区间中耗尽时拆商与余数。q = orders / width 表示能卖多少完整价格层，r = orders % width 表示还可按下一价格卖几颗；结算后立即返回。
每次乘法前使用宽整数。Java/C++ 用 long/long long，JavaScript 用 BigInt，Python 整数天然扩展，最后统一取模。

正确性证明

引理：最高价优先不劣

若某方案先卖价值较小的球，而当时存在价值更大的球，交换这两次出售不会影响可行性，且不会降低收益。不断交换可得到最高价优先的最优方案。

引理：分层结算等价

同组颜色从 high 降到 low 时，每个价格层都恰好出现 width 次。等差数列只是把这些逐颗出售的价值重排并求和，数量和收益均不变。

定理：算法返回最大收益

由第一个引理，存在按非增价值出售的最优方案；由第二个引理，算法逐段精确结算该序列。最后一个不完整区间也优先取其中最高层，故总收益最优。

边界情况

  • 只有一种颜色，退化为单个等差数列。
  • 多个颜色库存相同，扫描时高度差为 0，直接扩组即可。
  • 订单恰好用完整个区间，此时余数为 0。
  • 库存与订单达到 10⁹，乘积远超 32 位整数。
  • 最终结果取模，但比较和订单扣减必须使用未取模的真实数量。

复杂度

时间：O(n log n)，主要来自排序；扫描为 O(n)。

空间：取决于语言的排序实现；复制并排序时为 O(n)，原地排序的额外空间可视具体实现而定。

替代方案

最大堆逐颗出售是 O(orders log n)，订单达 10⁹ 时不可行。也可以二分最终价格阈值 k，统计高于 k 的球数并求和，复杂度约 O(n log V)；排序分层通常更直接。

import java.util.Arrays;

class Solution {
    private static final long MOD = 1_000_000_007L;

    public int maxProfit(int[] inventory, int orders) {
        Arrays.sort(inventory);
        long answer = 0;
        long remaining = orders;
        int n = inventory.length;

        for (int i = n - 1; i >= 0; i--) {
            long high = inventory[i];
            long low = i > 0 ? inventory[i - 1] : 0;
            long width = n - i;
            long capacity = (high - low) * width;

            if (remaining >= capacity) {
                answer = (answer + width * rangeSum(low + 1, high)) % MOD;
                remaining -= capacity;
            } else {
                long fullLevels = remaining / width;
                long extra = remaining % width;
                long bottom = high - fullLevels;
                answer = (answer + width * rangeSum(bottom + 1, high)) % MOD;
                answer = (answer + extra * bottom) % MOD;
                return (int) answer;
            }
        }
        return (int) answer;
    }

    private long rangeSum(long from, long to) {
        if (from > to) return 0;
        return (from + to) * (to - from + 1) / 2;
    }
}

var maxProfit = function(inventory, orders) {
    const MOD = 1000000007n;
    const values = inventory.map(BigInt).sort((a, b) => a > b ? -1 : a < b ? 1 : 0);
    values.push(0n);
    let remaining = BigInt(orders);
    let answer = 0n;

    const rangeSum = (from, to) => {
        if (from > to) return 0n;
        return (from + to) * (to - from + 1n) / 2n;
    };

    for (let i = 0; i < values.length - 1; i++) {
        const high = values[i];
        const low = values[i + 1];
        const width = BigInt(i + 1);
        const capacity = (high - low) * width;

        if (remaining >= capacity) {
            answer = (answer + width * rangeSum(low + 1n, high)) % MOD;
            remaining -= capacity;
        } else {
            const fullLevels = remaining / width;
            const extra = remaining % width;
            const bottom = high - fullLevels;
            answer = (answer + width * rangeSum(bottom + 1n, high)) % MOD;
            answer = (answer + extra * bottom) % MOD;
            break;
        }
    }
    return Number(answer);
};

class Solution:
    def maxProfit(self, inventory: List[int], orders: int) -> int:
        MOD = 10**9 + 7
        values = sorted(inventory, reverse=True) + [0]
        answer = 0

        def range_sum(start: int, end: int) -> int:
            if start > end:
                return 0
            return (start + end) * (end - start + 1) // 2

        for i in range(len(values) - 1):
            high, low = values[i], values[i + 1]
            width = i + 1
            capacity = (high - low) * width

            if orders >= capacity:
                answer += width * range_sum(low + 1, high)
                orders -= capacity
            else:
                full_levels, extra = divmod(orders, width)
                bottom = high - full_levels
                answer += width * range_sum(bottom + 1, high)
                answer += extra * bottom
                break

        return answer % MOD

面试追问

  1. 为什么只在相邻库存高度之间结算，不会漏掉某种颜色？
  2. 若不能修改输入数组，空间复杂度如何变化？
  3. 能否用二分阈值实现？怎样处理阈值层上的余数？
  4. 为什么收益取模可以随时做，而订单数量不能取模？
  5. 如果每种颜色还有不同的价格倍率，原贪心是否仍成立？

常见错误

  • 用最大堆逐颗模拟，复杂度依赖 orders。
  • 区间求和把 low 也算进去，产生 off-by-one。
  • 部分层余数使用了 high-q+1，正确单价是 high-q。
  • 乘法后才转宽整数，导致中间值已经溢出。
  • JavaScript 使用 Number 计算大额收益，超过安全整数。
  • 忘记相同库存高度的扫描步只扩组、不结算。
