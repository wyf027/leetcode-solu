分配给商店的
最多商品的最小值

Minimized Maximum of Products Distributed to Any Store

把商品分给商店，让最忙的那间店也尽量轻松。

官方题目 ↗

01 · 题目

给定整数 n，表示商店数量；给定下标从 0 开始的数组 quantities，其中 quantities[i] 是第 i 类商品的数量，商品种类数为 m。

  • 必须分配完所有商品；同一种商品可以分给多间商店。
  • 每间商店至多接收一种商品，接收数量不限，也允许空店。
  • 设所有商店的商品数量最大值为 x，返回能够达到的最小 x。

函数：minimizedMaximum(n, quantities) → integer

约束

  • m == quantities.length
  • 1 ≤ m ≤ n ≤ 10⁵
  • 1 ≤ quantities[i] ≤ 10⁵

02 · 官方示例

示例 1

输入：n = 6, quantities = [11,6]
输出：3

第 0 类分给 4 间店，数量为 2、3、3、3；第 1 类分给 2 间店，数量为 3、3。所有商店中最多为 3 件。

示例 2

输入：n = 7, quantities = [15,10,10]
输出：5

第 0 类分为 5、5、5；第 1 类分为 5、5；第 2 类分为 5、5。用满 7 间店，最大数量为 5。

示例 3

输入：n = 1, quantities = [100000]
输出：100000

只有一间商店，必须接收全部 100000 件商品。

04 · 题解：二分每店容量

核心洞察

先假设每间商店最多接收 x 件。第 i 类商品至少需要 ceil(quantities[i] / x) 间商店，因为不能混装，不同类别的需求必须相加。

need(x) = Σ ceil(quantities[i] / x)
可行 ⇔ need(x) ≤ n

容量越大，所需商店数越少或不变，因此可行性从“不行”单向变为“可行”。我们查找第一个可行的整数容量。

完整过程

  1. 设 left = 1，right = max(quantities)。右端一定可行：每类商品使用一间店即可。
  2. 取 mid = left + floor((right - left) / 2)，累计所需商店数；超过 n 后可以提前结束。
  3. 若所需商店数不超过 n，令 right = mid，继续寻找更小的可行容量。
  4. 否则令 left = mid + 1，排除容量过小的一侧。
  5. 当 left == right 时返回该值。

为什么正确？

必要性：每店最多放 x 件，同类 q 件至少占用 ⌈q/x⌉ 间店；类型不能混合，因此任何方案的店数都不少于各类需求之和。如果和大于 n，就不可能分完。

充分性：为每类分配 ⌈q/x⌉ 间独立商店，依次每店放 x 件，最后一店放余数（整除时放 x 件）。当总数不超过 n 时，这给出了合法方案，剩余商店留空。

单调性与区间不变式：容量增大不会增加任何一类的所需店数。最优答案始终位于闭区间 [left, right]。mid 可行时答案不大于 mid；mid 不可行时答案严格大于 mid。每次区间缩短，最终唯一保留的值就是最小可行容量。

边界与复杂度

  • n == m 时每类只能使用一间店，答案为最大商品数量。
  • n ≥ sum(quantities) 时每件商品都能独占一店，答案为 1。
  • 所有数量都为 1 时，初始左右边界相等，循环无需执行。
  • 设 m 为种类数，M = max(quantities)。时间 O(m log(M + 1))（通常写作 O(m log M)），额外空间 O(1)。互动页面的历史记录不计入提交算法。
  • 完整累计值最多 10¹⁰。Java 和 C++ 用 64 位累计；JavaScript Number 在该范围可精确表示整数，Python 整数无需额外处理。

替代方案

从 1 开始枚举容量并逐一判定，逻辑直接，但最坏需要 O(mM) 时间。也可从下界 ceil(sum(quantities) / n) 开始二分，略缩小搜索范围；该下界不一定就是答案，不影响主要复杂度。

常见错误

  • 直接返回总数除以店数的上取整：例如 n=3, quantities=[4,4]，平均下界是 3，但每类各需 2 店，答案是 4。
  • 用向下取整计算需求，会漏掉余数必须占用的商店。
  • 要求 need == n 才可行，忽略了允许空店。
  • 可行时写成 right = mid - 1 却继续使用本页闭区间模板，可能丢掉最优答案。
  • 让 left 从 0 开始导致除零；使用 32 位整数累计完整需求会有溢出风险。

面试追问

如何恢复分配方案？求得 x 后逐类分块，每块不超过 x，分别对应一间店，剩余店留空。

若允许商品混装？类型边界消失，答案直接是总数除以 n 的上取整。

若每店容量不同？简单的按类店数求和不足以判断可行性，需要重新定义分配判定，不能直接照搬本模板。

Java

class Solution {
    public int minimizedMaximum(int n, int[] quantities) {
        int left = 1, right = 0;
        for (int q : quantities) right = Math.max(right, q);
        while (left < right) {
            int mid = left + (right - left) / 2;
            long need = 0;
            for (int q : quantities) {
                need += (q + mid - 1) / mid;
                if (need > n) break;
            }
            if (need <= n) right = mid;
            else left = mid + 1;
        }
        return left;
    }
}

var minimizedMaximum = function(n, quantities) {
    let left = 1, right = 0;
    for (const q of quantities) right = Math.max(right, q);
    while (left < right) {
        const mid = left + Math.floor((right - left) / 2);
        let need = 0;
        for (const q of quantities) {
            need += Math.ceil(q / mid);
            if (need > n) break;
        }
        if (need <= n) right = mid;
        else left = mid + 1;
    }
    return left;
};

        left, right = 1, max(quantities)

            need = 0

                if need > n:
                    break
