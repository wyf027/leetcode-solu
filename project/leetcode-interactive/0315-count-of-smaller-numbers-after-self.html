计算右侧小于当前元素的个数
Count of Smaller Numbers After Self

给每个数字一个回望右侧的机会：它需要知道，身后究竟有多少个严格更小的元素。

困难 数组 树状数组 归并排序 非付费题

Problem

题目描述

给你一个整数数组 nums，返回同样长度的整数数组 counts。其中，counts[i] 等于 nums[i] 右侧严格小于它的元素数量。

“严格小于”很重要：与当前元素相等的值不能计入答案。

函数签名

countSmaller(nums: integer[]) → integer[]

约束

  • ✓1 ≤ nums.length ≤ 10⁵
  • ✓−10⁴ ≤ nums[i] ≤ 10⁴
  • ✓返回数组与 nums 等长
示例 1 
输入：nums = [5,2,6,1]
输出：[2,1,1,0]
解释：5 右侧有 2、1；2 右侧有 1；
6 右侧有 1；1 右侧没有更小元素。
示例 2 
输入：nums = [-1]
输出：[0]
示例 3 
输入：nums = [-1,-1]
输出：[0,0]

01 · Insight

核心洞察：把“右侧”变成“已经见过”

反向扫描

从右向左处理数组。轮到 nums[i] 时，数据结构中恰好存放它右侧的所有元素。因此，问题变成：已登记元素里，有多少个值严格小于当前值？

树状数组擅长维护“某段排名前缀中出现了多少元素”。查询当前排名之前的前缀，即可得到答案；随后把当前排名的频次加一。

坐标压缩

树状数组下标必须紧凑且为正，而原值可能是负数。将所有不同值排序后，令最小值排名为 1，第二小值排名为 2，以此类推。

rank(x) = lower_bound(sortedUnique, x) + 1
answer[i] = prefixSum(rank(nums[i]) − 1)

02 · Walkthrough

完整过程

1

压缩数值

复制数组、排序、去重。对 [5,2,6,1] 得到 [1,2,5,6]，排名依次为 1..4。

2

从右向左遍历

先处理 1，再处理 6、2、5。每次处理前，树中仅包含当前下标右侧的元素。

3

查询更小排名

若当前排名为 r，查询前缀 [1, r−1]。不能查询到 r，否则重复值会被错误计入。

4

登记当前元素

将排名 r 的频次加一。树状数组通过 index += index & -index 更新所有覆盖该排名的桶。

5

原位写答案

答案直接写到 counts[i]，因此虽然遍历方向相反，最终数组仍保持原下标顺序。

03 · Correctness

正确性证明

循环不变式：开始处理下标 i 前，树状数组记录且仅记录 nums[i+1..n−1] 中每个压缩排名的出现次数。

初始化：处理最右元素 n−1 前，右侧区间为空，树状数组全零，满足不变式。

保持：设当前值排名为 r。压缩保持大小关系，排名 1..r−1 恰好对应严格小于当前值的所有值。由不变式，其前缀频次和就是右侧严格更小元素数。查询后把当前排名频次加一，于是树中恰好记录 nums[i..n−1]，供下一轮使用。

终止：所有下标处理完毕，每个 counts[i] 都等于其右侧严格更小元素数量，算法正确。

04 · Complexity & Edges

复杂度与边界

O(n log n)总时间：排序 + n 次查询/更新
O(n)额外空间：答案、压缩数组、树
O(log n)单次查询或更新

单元素

右侧为空，答案为 0；树先查询空前缀，再登记自身。

重复值

相同值共享排名。查询 r−1 排除相等元素。

负数与极值

坐标压缩只依赖相对顺序，不需要对负值做偏移。

05 · Implementations

四语言完整代码

四份实现均采用“坐标压缩 + 树状数组”的同一机制，并保持官方函数签名。

import java.util.*;

class Solution {
    public List<Integer> countSmaller(int[] nums) {
        int n = nums.length;
        int[] sorted = nums.clone();
        Arrays.sort(sorted);

        int uniqueCount = 0;
        for (int value : sorted) {
            if (uniqueCount == 0 || sorted[uniqueCount - 1] != value) {
                sorted[uniqueCount++] = value;
            }
        }

        Fenwick tree = new Fenwick(uniqueCount);
        Integer[] answer = new Integer[n];
        for (int i = n - 1; i >= 0; i--) {
            int rank = lowerBound(sorted, uniqueCount, nums[i]) + 1;
            answer[i] = tree.query(rank - 1);
            tree.add(rank, 1);
        }
        return Arrays.asList(answer);
    }

    private int lowerBound(int[] values, int size, int target) {
        int left = 0, right = size;
        while (left < right) {
            int mid = left + (right - left) / 2;
            if (values[mid] < target) left = mid + 1;
            else right = mid;
        }
        return left;
    }

    private static class Fenwick {
        private final int[] tree;

        Fenwick(int size) {
            tree = new int[size + 1];
        }

        void add(int index, int delta) {
            while (index < tree.length) {
                tree[index] += delta;
                index += index & -index;
            }
        }

        int query(int index) {
            int sum = 0;
            while (index > 0) {
                sum += tree[index];
                index -= index & -index;
            }
            return sum;
        }
    }
}

var countSmaller = function(nums) {
    const sorted = [...new Set(nums.slice().sort((a, b) => a - b))];
    const tree = new Array(sorted.length + 1).fill(0);
    const answer = new Array(nums.length).fill(0);

    const lowerBound = (target) => {
        let left = 0;
        let right = sorted.length;
        while (left < right) {
            const mid = left + Math.floor((right - left) / 2);
            if (sorted[mid] < target) left = mid + 1;
            else right = mid;
        }
        return left;
    };

    const query = (index) => {
        let sum = 0;
        while (index > 0) {
            sum += tree[index];
            index -= index & -index;
        }
        return sum;
    };

    const add = (index) => {
        while (index < tree.length) {
            tree[index]++;
            index += index & -index;
        }
    };

    for (let i = nums.length - 1; i >= 0; i--) {
        const rank = lowerBound(nums[i]) + 1;
        answer[i] = query(rank - 1);
        add(rank);
    }
    return answer;
};
from bisect import bisect_left
from typing import List


class Solution:
    def countSmaller(self, nums: List[int]) -> List[int]:
        ordered = sorted(set(nums))
        tree = [0] * (len(ordered) + 1)
        answer = [0] * len(nums)

        def query(index: int) -> int:
            total = 0
            while index > 0:
                total += tree[index]
                index -= index & -index
            return total

        def add(index: int) -> None:
            while index < len(tree):
                tree[index] += 1
                index += index & -index

        for i in range(len(nums) - 1, -1, -1):
            rank = bisect_left(ordered, nums[i]) + 1
            answer[i] = query(rank - 1)
            add(rank)

        return answer
class Solution {
public:
    vector<int> countSmaller(vector<int>& nums) {
        vector<int> ordered(nums.begin(), nums.end());
        sort(ordered.begin(), ordered.end());
        ordered.erase(unique(ordered.begin(), ordered.end()), ordered.end());

        vector<int> tree(ordered.size() + 1, 0);
        vector<int> answer(nums.size(), 0);

        auto query = [&](int index) {
            int sum = 0;
            while (index > 0) {
                sum += tree[index];
                index -= index & -index;
            }
            return sum;
        };

        auto add = [&](int index) {
            while (index < static_cast<int>(tree.size())) {
                tree[index]++;
                index += index & -index;
            }
        };

        for (int i = static_cast<int>(nums.size()) - 1; i >= 0; --i) {
            int rank = static_cast<int>(
                lower_bound(ordered.begin(), ordered.end(), nums[i])
                - ordered.begin()
            ) + 1;
            answer[i] = query(rank - 1);
            add(rank);
        }
        return answer;
    }
};

06 · Alternatives

替代方案

归并排序计数

对“值 + 原下标”做归并。在合并阶段统计右半区已经移到前面的较小元素数。时间 O(n log n)，无需坐标压缩，但下标与计数 bookkeeping 更细。

线段树

同样压缩排名，维护区间频次。查询区间 [1,r−1]。复杂度相同、常数与代码量通常更大，适合扩展到更复杂区间信息。

平衡搜索树

需要支持重复值与 order statistic 的树。语言标准库往往不直接提供，手写难度高；普通有序集合无法在对数时间得到“小于 x 的数量”。

07 · Interview Follow-ups

面试追问

如果要统计“小于等于”呢？

查询从 prefix(r−1) 改为 prefix(r)，这样相同排名的历史频次也计入。

能在线处理持续到来的数据吗？

若值域边界已知，可用固定值域树；若完全未知且无法预压缩，可用支持秩查询的平衡树，或分批重建压缩映射。

为何不能从左向右用同样查询？

左向右时树里是左侧元素，回答的是“左侧更小”。除非换一种维护目标，否则与题意方向相反。

如何避免二分每次找排名？

预先建立“值 → 排名”的哈希映射，可把排名查找从 O(log n) 降到均摊 O(1)；总复杂度仍受排序与树操作支配。

08 · Pitfalls

常见错误

  • 把相等元素算进去：查询 query(rank) 而不是 query(rank−1)。
  • 扫描方向错误：从左向右登记会统计左侧，不是右侧。
  • 树状数组使用 0 下标：lowbit(0)=0 会让更新循环无法前进；压缩排名必须从 1 开始。
  • 先更新再查询：当前元素会把自己计入某些查询；应先查询，再登记。
  • 原数组排序后丢失下标：仅对副本排序压缩，答案仍写回原下标。
  • 使用二次复杂度：约束达到 10⁵，逐个扫描右侧的 O(n²) 方案不可取。
