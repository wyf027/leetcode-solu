Minimum Number of Operations to Convert Time

同一天的两个时刻，四种前进幅度。怎样用最少的操作到达目标？

01题目

给定字符串 current 和 correct，分别表示当前时刻和目标时刻。每次只能把当前时间向后推进 1、5、15 或 60 分钟，每种操作可以重复使用。返回恰好到达目标所需的最少操作次数。

  • 两个参数均为合法的 24 小时制 "HH:MM" 字符串；小时范围为 00–23，分钟范围为 00–59。
  • current <= correct，最早为 00:00，最晚为 23:59。无需跨日。

参数：current: string，correct: string；返回值：integer。

官方示例 1

输入：current = "02:30", correct = "04:35"
输出：3

02:30 → 03:30 → 04:30 → 04:35，依次增加 60、60、5 分钟，共 3 次，无法更少。

官方示例 2

输入：current = "11:00", correct = "11:01"
输出：1

增加 1 分钟即可从 11:00 到达 11:01。

04题解 · 把时间换成分钟

核心洞察

将 HH:MM 转为 60 × HH + MM，两个数相减得到待增加的分钟数 d。按 60 → 15 → 5 → 1 的顺序取尽可能多的操作，再处理余数。这里每个较大的增量都是下一级的整数倍，因此可以用交换论证保证最优。

不要直接分别减小时和分钟，也不要把时间当成以 100 为基数的数字。10:50 到 11:10 的间隔是 20 分钟。

    完整过程

    1. 分别解析两个时间，将它们转换为从午夜起的总分钟数。
    2. 计算非负差值 d = correctMinutes − currentMinutes，初始化答案为 0。
    3. 依次遍历 60、15、5、1。对当前增量 v，累加整数商 d / v，再令 d = d % v。
    4. 处理完 1 分钟后余数必为 0，返回累计次数。
    current = "02:30" → 150 分钟
correct = "04:35" → 275 分钟
d = 125
增量 60：取 2 次，余 5，累计 2
增量 15：取 0 次，余 5，累计 2
增量  5：取 1 次，余 0，累计 3
增量  1：取 0 次，余 0，累计 3

    正确性：把小操作合成大操作

    考虑任意最优方案。如果含有至少 5 个 1 分钟操作，就能把其中 5 个换成 1 个 5 分钟操作，减少次数，矛盾。同理，最优方案中 5 分钟操作至多 2 个，15 分钟操作至多 3 个。

    因此，小于 60 的操作合计至多 3×15 + 2×5 + 4×1 = 59 分钟，所以 60 分钟操作的个数必为 ⌊d/60⌋。去除这些操作后，5 和 1 分钟合计至多 14 分钟，故 15 分钟的个数也是当前余数除以 15 的整数商。依此类推确定 5 和 1 的个数，恰好与算法相同。算法构造了合法方案，且任何最优方案都有这些数量，因此返回最少次数。

    边界与复杂度

    • 相同时间：差为 0，四次整数商都是 0，答案为 0。
    • 跨小时：统一转换为分钟自然处理借位；不补加 24 小时。
    • 最大差为 1439，分解为 23×60 + 3×15 + 2×5 + 4×1，共 32 次。
    • 算法时间 O(1)，空间 O(1)：时间字符串固定长度，遍历四种固定增量。可视化为了展示过程另行保存每次操作。

    替代方案

    动态规划：令 dp[0] = 0，dp[x] = 1 + min(dp[x−v])，其中 v 取 1、5、15、60 且 v ≤ x。时间 O(4d)，空间 O(d)。对于本题更繁琐，但增量改成任意集合时仍然适用；不可达状态需初始化为无穷大。

    面试追问

    • 所有面额都能贪心吗？不能。例如增量为 1、3、4，差值为 6，贪心得到 4+1+1，最优却是 3+3。
    • 如果目标可能在次日？先明确日期和相同时间的语义；若明确目标为下一次该时刻，可按约定对差值做跨日处理。原题不需要。
    • 每种操作成本不同怎么办？操作次数不再代表成本，交换论证可能失效，可改为最小成本动态规划。

    常见错误

    • 把小时差乘以 100，或只计算分钟字段差。
    • 从小到大使用增量，得到很多可以合并的操作。
    • JavaScript / Python 使用普通除法累计小数；应使用 Math.floor / //。
    • 每轮忘记更新余数，重复计算已消耗的分钟。
    • 仅以“每次尽量大”作为正确性证明，忽略本题增量的整倍数关系。

    Java

    class Solution {
    public int convertTime(String current, String correct) {
        int d = minutes(correct) - minutes(current);
        int answer = 0;
        for (int step : new int[]{60, 15, 5, 1}) {
            answer += d / step;
            d %= step;
        }
        return answer;
    }

    private int minutes(String time) {
        return Integer.parseInt(time.substring(0, 2)) * 60
             + Integer.parseInt(time.substring(3, 5));
    }
}

    JavaScript

    /**
 * @param {string} current
 * @param {string} correct
 * @return {number}
 */
var convertTime = function(current, correct) {
    const minutes = time =>
        Number(time.slice(0, 2)) * 60 + Number(time.slice(3));
    let d = minutes(correct) - minutes(current);
    let answer = 0;
    for (const step of [60, 15, 5, 1]) {
        answer += Math.floor(d / step);
        d %= step;
    }
    return answer;
};

    Python 3

    class Solution:
    def convertTime(self, current: str, correct: str) -> int:
        def minutes(time: str) -> int:
            return int(time[:2]) * 60 + int(time[3:])

        d = minutes(correct) - minutes(current)
        answer = 0
        for step in (60, 15, 5, 1):
            count, d = divmod(d, step)
            answer += count
        return answer

    #include <string>
using namespace std;

class Solution {
    int minutes(const string& time) {
        return stoi(time.substr(0, 2)) * 60 + stoi(time.substr(3, 2));
    }
public:
    int convertTime(string current, string correct) {
        int d = minutes(correct) - minutes(current);
        int answer = 0;
        const int steps[] = {60, 15, 5, 1};
        for (int step : steps) {
            answer += d / step;
            d %= step;
        }
        return answer;
    }
};
