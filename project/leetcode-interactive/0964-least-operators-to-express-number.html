表示数字的
最少运算符

把目标数拆成 x 进制位，在每一位比较“直接凑”与“向上借一个幂再减回来”。先自己观察状态变化，再决定是否展开完整题解。

Least Operators to Express Number
输入x, target
输出最少运算符数
范围2 ≤ x ≤ 100
目标≤ 2 × 10⁸

题目

给定正整数 x 与 target，用若干个相同的 x，并只在它们之间放置 +、-、*、/，构造值等于 target 的表达式。返回表达式中运算符数量的最小值。

  • 除法得到有理数，不采用整数截断。
  • 表达式中不能出现括号。
  • 乘除优先于加减，遵循通常优先级。
  • 不能使用一元负号；x-x 合法，-x+x 不合法。

官方示例

示例 1
输入：x = 3, target = 19
输出：5
解释：3*3 + 3*3 + 3/3
示例 2
输入：x = 5, target = 501
输出：8
解释：5*5*5*5 - 5*5*5 + 5/5
示例 3
输入：x = 100, target = 100000000
输出：3
解释：100*100*100*100

题解：x 进制数位动态规划

1 · 幂是天然积木

x^k 只需 k−1 个乘号；但孤立的 x⁰=1 要写成 x/x，成本是 1 个除号。

2 · 每位只留两种状态

pos 表示低位按当前数值结算；neg 表示低位被补到下一个高位，随后用减法修正。

3 · 最后统一扣一

转移用“每个幂项的完整成本”计数，最外层第一个项前没有加减号，所以答案最后减 1。

完整过程

从低到高读取 target 的 x 进制位。设当前是第 k 位，数字为 d。使用一次 x^k 的计价为 cost(0)=2（把 1 看成 x/x），其余 cost(k)=k（k−1 个乘号和连接这一项的 1 个加减号）。

newPos = min(pos + d·cost(k), neg + (d+1)·cost(k)) newNeg = min(pos + (x-d)·cost(k), neg + (x-d-1)·cost(k)) answer = min(pos, neg + numberOfDigits) - 1

第一式分别表示直接放 d 份当前幂，或承接低位进位后放 d+1 份；第二式分别表示从当前数位向上补 x−d 份，或承接进位后再补 x−d−1 份。对于 k=0 单独初始化，因为 1 的表示成本不同。以 x=3、target=19=(201)₃ 为例，三轮后的 (pos, neg) 依次是 (2,4)、(2,5)、(6,4)，最终 min(6,4+3)-1=5。

正确性证明

不变式：处理完第 k 位后，pos 是只用不高于 x^k 的位使已处理部分精确匹配的最小计价；neg 是使已处理部分相对目标多出 x^(k+1) 的最小计价。

初始最低位枚举直接取 d 个 1 或补成 x 个 1 后再减，故不变式成立。转移时，任何合法方案在当前位要么直接使用 d（或承接进位后的 d+1）份 x^k，要么补到下一位；四种情况被两条转移完整覆盖，且各自取最小值。因此不变式归纳成立。处理所有位后，目标只能由精确状态结束，或由补数状态再加入一个最高幂结束；取二者最小并扣除虚拟的首项连接符，即得真实最少运算符数。

边界与复杂度

  • target=1：由 x/x 表示，答案为 1。
  • target 恰为 x 的幂：只需连续乘法。
  • 每次整除 x，轮数为 O(logₓ target)。
  • 时间 O(logₓ target)，额外空间 O(1)。

替代方案

可用记忆化搜索：找到不小于 target 的最小幂 p，在“从低幂加上去”和“从 p 减回来”两条分支中取小值。它更直观，但需要哈希缓存与递归边界；数位 DP 状态更紧凑。

四语言完整实现

class Solution {
    public int leastOpsExpressTarget(int x, int target) {
        long pos = 0, neg = 0;
        int k = 0;
        while (target > 0) {
            int digit = target % x;
            target /= x;
            if (k == 0) {
                pos = (long) digit * 2;
                neg = (long) (x - digit) * 2;
            } else {
                long nextPos = Math.min(pos + (long) digit * k,
                                        neg + (long) (digit + 1) * k);
                long nextNeg = Math.min(pos + (long) (x - digit) * k,
                                        neg + (long) (x - digit - 1) * k);
                pos = nextPos;
                neg = nextNeg;
            }
            k++;
        }
        return (int) Math.min(pos, neg + k) - 1;
    }
}

var leastOpsExpressTarget = function(x, target) {
  let pos = 0, neg = 0, k = 0;
  while (target > 0) {
    const digit = target % x;
    target = Math.floor(target / x);
    if (k === 0) {
      pos = digit * 2;
      neg = (x - digit) * 2;
    } else {
      const nextPos = Math.min(pos + digit * k, neg + (digit + 1) * k);
      const nextNeg = Math.min(pos + (x - digit) * k, neg + (x - digit - 1) * k);
      pos = nextPos;
      neg = nextNeg;
    }
    k++;
  }
  return Math.min(pos, neg + k) - 1;
};

面试追问

  • 为什么最低位的成本是 2，而不是 0 或 1？
  • 为什么只需保留 pos / neg 两个状态？
  • 末尾的 -1 对应哪个被多算的运算符？
  • 如何把迭代 DP 改写成按幂递归的记忆化搜索？

常见错误

  • 把除法误当成整数除法。
  • 忘记 k=0 时 1=x/x 的特殊计价。
  • 原地先更新 pos，导致 neg 使用了本轮新状态。
  • 只考虑每位直接凑，不考虑补数与进位。
  • 最后忘记扣掉首项前并不存在的连接符。
