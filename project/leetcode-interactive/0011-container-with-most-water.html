题意转述

CORE INSIGHT

淘汰短板，而不是猜答案

初始宽度最大。若左侧更短，固定左侧并把右侧向内移，宽度变小而水位最多仍是左侧高度，因此面积绝不可能增加；所以左侧可以安全淘汰。

GREEDY PROOF

宽度：每次移动后严格减小

水位：只有移动短板才可能升高

因此每一步都排除一整批不可能优于当前组合的候选，最终只需 O(n) 次比较。

FULL WALKTHROUGH

完整解题过程

  1. 1. 拉到最宽：left = 0，right = n - 1。
  2. 2. 计算容量：min(height[left], height[right]) × (right - left)。
  3. 3. 更新答案：把当前容量与历史最大值比较。
  4. 4. 淘汰短板：左侧较短则 left++，否则 right--。
  5. 5. 指针相遇：所有可能改善答案的组合都已检查，返回最大值。

边界情况

  • 仅两条线时直接计算唯一容器。
  • 高度含 0 时当前容量可能为 0。
  • 两侧等高时移动任意一侧都安全。
  • 最大答案不超过约 10⁹，Java/C++ int 可容纳。

复杂度

时间：O(n)

空间：O(1)

两个指针合计最多移动 n - 1 次。

替代方案

暴力枚举所有两条线需要 O(n²)，在 n = 10⁵ 时不可接受。双指针利用短板上界一次淘汰整批候选，是面试唯一推荐主线。

class Solution {
    public int maxArea(int[] height) {
        int left = 0;
        int right = height.length - 1;
        int best = 0;

        while (left < right) {
            int width = right - left;
            int waterLevel = Math.min(height[left], height[right]);
            best = Math.max(best, width * waterLevel);

            if (height[left] < height[right]) {
                left++;
            } else {
                right--;
            }
        }
        return best;
    }
}

面试高频追问

为什么不能移动较高的一侧？
短板不变而宽度缩小，面积上界只会下降，不可能产生更优答案。
两侧等高时移动哪边？
任意一边都可以；代码统一移动右侧，结论不变。
能否跳过连续更矮的墙？
可以做常数优化，但基础双指针已是 O(n)，面试先保证证明和代码简洁。

常见错误

  • 面积高度误用 max，正确是两侧的 min。
  • 宽度误写成 right - left + 1。
  • 机械移动较高一侧，丢失潜在最优解。
  • 循环条件写成 left ≤ right，多处理无效的零宽容器。
