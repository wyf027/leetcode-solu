敲击
计数器

为持续到来的敲击事件设计一个计数器：每次查询，都要回答“截至此刻的最近 5 分钟内，共发生了多少次敲击？”

MEDIUM 付费题 队列 数据流 设计
WINDOWLIVE / 300 SEC
300秒

不断向前的时间窗，只保留此刻仍然有效的敲击。

Problem

题意

实现 HitCounter 类。每一次敲击都带有一个以秒为单位的时间戳，系统需要随时返回当前时间点之前 300 秒窗口内的敲击总数。

  • HitCounter()：初始化计数器。
  • void hit(int timestamp)：记录发生在 timestamp 秒的一次敲击。同一秒可以发生多次。
  • int getHits(int timestamp)：返回最近 5 分钟内的敲击次数，也就是时间戳落在 [timestamp - 299, timestamp] 内的事件数。
调用按时间顺序到达；时间戳单调不减。边界上，恰好发生在 timestamp - 300 的敲击已经不属于最近 300 秒。

官方示例（完整参数形式）

Input / Output
输入：
["HitCounter", "hit", "hit", "hit", "getHits", "hit", "getHits", "getHits"]
[[], [1], [2], [3], [4], [300], [300], [301]]

输出：
[null, null, null, null, 3, null, 4, 3]

解释：在第 1、2、3 秒分别记录敲击，因此第 4 秒查询得到 3。第 300 秒新增一次敲击后查询得到 4。到第 301 秒，第 1 秒的敲击恰好离开窗口，只剩第 2、3、300 秒的三次敲击。

Contract

约束与接口

  • 1 <= timestamp <= 2 × 109
  • 所有调用按时间顺序发生，即 timestamp 单调不减。
  • hit 与 getHits 合计最多调用 300 次。
  • 同一个时间戳可记录多次敲击，也可进行查询。

Solution

用队列维护活动窗口

时间戳有序是关键条件：过期事件永远从最早的一端连续出现。

01

核心洞察

把同一秒的敲击压缩成 (timestamp, count)，按时间存入双端队列，并维护窗口内总数 total。

02

淘汰规则

每次调用先从队首删除满足 front.timestamp <= timestamp - 300 的桶，同时从 total 扣除其次数。

03

立即作答

hit 合并或追加一条记录后令总数加一；getHits 完成淘汰后直接返回 total。

完整过程

  1. 初始化空队列和整数 total = 0。
  2. 收到任意调用时，根据当前 timestamp 清理所有已经离开 300 秒窗口的队首桶。
  3. 执行 hit(timestamp) 时，若队尾时间等于当前时间则计数加一，否则追加新桶；同时 total++。
  4. 执行 getHits(timestamp) 时，清理之后直接返回 total。

为什么正确

  1. 不变式：完成清理后，队列只包含时间戳大于 timestamp - 300 且不晚于当前时间的敲击；它们恰好位于查询窗口内。
  2. 无遗漏：时间戳单调不减，所有新敲击从队尾加入，因此仍有效的旧敲击与新敲击都保留在队列中。
  3. 无多计：所有时间戳小于等于窗口左边界前一刻的桶都会从队首移除，其次数同步从总数扣除。
  4. 结论：total 始终等于队列内次数之和，所以查询返回的就是最近 300 秒敲击总数。

复杂度

单次操作均摊 O(1)
空间O(k)

每个时间桶至多入队、出队各一次；k 是活动窗口内不同时间戳的数量。

边界情况

  • 从未发生敲击时返回 0。
  • 同一秒多次敲击必须全部计入。
  • timestamp - 300 秒的敲击应被排除。
  • 长时间没有查询时，hit 也进行清理，避免保留无效历史。
  • 时间戳很大时不要预分配到时间戳大小的数组。

Implementations

四语言完整代码

Java · LeetCode 提交代码
import java.util.ArrayDeque;
import java.util.Deque;

class HitCounter {
    private final Deque<int[]> hits;
    private int total;

    public HitCounter() {
        hits = new ArrayDeque<>();
        total = 0;
    }

    public void hit(int timestamp) {
        evict(timestamp);
        if (!hits.isEmpty() && hits.peekLast()[0] == timestamp) {
            hits.peekLast()[1]++;
        } else {
            hits.offerLast(new int[]{timestamp, 1});
        }
        total++;
    }

    public int getHits(int timestamp) {
        evict(timestamp);
        return total;
    }

    private void evict(int timestamp) {
        while (!hits.isEmpty() && hits.peekFirst()[0] <= timestamp - 300) {
            total -= hits.pollFirst()[1];
        }
    }
}
JavaScript · LeetCode 提交代码
var HitCounter = function() {
    this.hits = [];
    this.head = 0;
    this.total = 0;
};

HitCounter.prototype.evict = function(timestamp) {
    while (
        this.head < this.hits.length &&
        this.hits[this.head][0] <= timestamp - 300
    ) {
        this.total -= this.hits[this.head][1];
        this.head++;
    }

    if (this.head > 1024 && this.head * 2 > this.hits.length) {
        this.hits = this.hits.slice(this.head);
        this.head = 0;
    }
};

HitCounter.prototype.hit = function(timestamp) {
    this.evict(timestamp);
    const last = this.hits.length - 1;
    if (last >= this.head && this.hits[last][0] === timestamp) {
        this.hits[last][1]++;
    } else {
        this.hits.push([timestamp, 1]);
    }
    this.total++;
};

HitCounter.prototype.getHits = function(timestamp) {
    this.evict(timestamp);
    return this.total;
};
Python · LeetCode 提交代码
from collections import deque


class HitCounter:
    def __init__(self):
        self.hits = deque()
        self.total = 0

    def hit(self, timestamp: int) -> None:
        self._evict(timestamp)
        if self.hits and self.hits[-1][0] == timestamp:
            self.hits[-1][1] += 1
        else:
            self.hits.append([timestamp, 1])
        self.total += 1

    def getHits(self, timestamp: int) -> int:
        self._evict(timestamp)
        return self.total

    def _evict(self, timestamp: int) -> None:
        while self.hits and self.hits[0][0] <= timestamp - 300:
            self.total -= self.hits.popleft()[1]
C++ · LeetCode 提交代码
#include <deque>
#include <utility>
using namespace std;

class HitCounter {
private:
    deque<pair<int, int>> hits;
    int total = 0;

    void evict(int timestamp) {
        while (!hits.empty() && hits.front().first <= timestamp - 300) {
            total -= hits.front().second;
            hits.pop_front();
        }
    }

public:
    HitCounter() = default;

    void hit(int timestamp) {
        evict(timestamp);
        if (!hits.empty() && hits.back().first == timestamp) {
            ++hits.back().second;
        } else {
            hits.emplace_back(timestamp, 1);
        }
        ++total;
    }

    int getHits(int timestamp) {
        evict(timestamp);
        return total;
    }
};

Trade-offs

替代方案

固定 300 桶循环数组

使用长度 300 的时间戳数组和计数数组，以 timestamp % 300 定位桶。若槽位记录的不是当前时间戳，就覆盖旧桶。这样即使每秒有海量敲击，空间仍是 O(300)。

何时选择哪一种？

  • 压缩队列：实现直观，窗口内稀疏时间点较少时更节省空间。
  • 循环数组：吞吐量巨大、需要严格固定内存时更稳妥；查询需扫描 300 个槽位，即固定的 O(300)。
  • 记录全部时间戳 + 二分：查询方便，但历史数据无限增长，不适合长期在线服务。

Pitfalls

常见错误

  • 把有效条件写成 timestamp - hit <= 300，错误保留第 300 秒前的事件。
  • 同一秒只记录布尔值，遗漏这一秒内的多次敲击。
  • 用数组 shift() 频繁删除队首，导致 JavaScript 实现潜在退化。
  • 只在查询时清理；如果长期只有写入，历史队列会无谓增长。
  • 假设调用时间戳乱序；本题保证单调不减，队列方案依赖这一条件。

Interview follow-ups

面试追问

每秒有数百万次敲击，如何控制空间？

把同一秒聚合成一个计数桶，或直接使用 300 槽循环数组。空间由时间窗口长度决定，而不是由敲击数量决定。

多台机器并发写入怎么办？

单机数据结构不再足够。可以按稳定键分片，各分片维护窗口计数，查询时聚合；同时明确时钟来源、允许的延迟与重复事件处理策略。

如果事件可能延迟或乱序到达呢？

队首淘汰依赖单调时间。乱序场景可采用按秒桶、基于事件时间的水位线，并设定允许迟到范围；超出范围的事件需按产品规则丢弃或补偿。

如何支持任意长度的时间窗口？

将 300 抽成窗口参数。少量固定窗口可分别维护；大量动态窗口可保留分层聚合桶，按精度和查询成本做权衡。
