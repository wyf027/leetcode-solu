最大得分

两条严格递增的数字路线，在公共节点处可以换轨。你能否规划一条从左到右的路径，让沿途只计一次的数字总和最大？

贪心双指针动态规划数组
Problem

题目

先理解规则，再用下方双轨演示观察路径选择。题解不会在首屏直接展开。

给定两个元素互不相同、并且都按严格递增顺序排列的整数数组 nums1 与 nums2。

一条合法路径需要选择其中一个数组，从下标 0 开始向右遍历。遇到同时存在于两个数组中的数时，可以留在当前数组，也可以切换到另一个数组的对应位置继续；这个公共值在整条路径里只计一次。

路径得分是其中不同数字之和。返回所有合法路径的最大得分，并对 10⁹ + 7 取余。

函数形式

maxSum(nums1, nums2) → integer

输入：两个严格递增的整数数组
输出：最大路径得分取模后的整数

官方示例

示例 1

输入：nums1 = [2,4,5,8,10]
      nums2 = [4,6,8,9]
输出：30
解释：最优路径为 [2,4,6,8,10]。

示例 2

输入：nums1 = [1,3,5,7,9]
      nums2 = [3,5,100]
输出：109
解释：最优路径为 [1,3,5,100]。

示例 3

输入：nums1 = [1,2,3,4,5]
      nums2 = [6,7,8,9,10]
输出：40
解释：两数组没有公共元素，选择
      nums2 的整条路径。

约束

  • 1 <= nums1.length, nums2.length <= 10⁵
  • 1 <= nums1[i], nums2[i] <= 10⁷
  • nums1 和 nums2 都严格递增，且各自内部没有重复元素。

Solution

准备好看题解了吗？

核心思路、证明、复杂度与四种语言完整实现都收在这里。

题解：在公共节点结算两段收益

公共值像一座桥：到达桥之前，两条路互不相通；到桥时，只需保留“两侧累计和中更大的一份”，再让两条路线从同一个最优状态继续。

核心洞察

因为两个数组严格递增，双指针可以按全局从小到大的顺序扫描。设 sum1、sum2 分别表示“当前到达两条轨道位置时的最大得分”。

  • 若 nums1[i] < nums2[j]，当前数字只能属于路线 1，将它加入 sum1。
  • 若 nums1[i] > nums2[j]，对路线 2 做对称处理。
  • 若二者相等，来到公共节点。无论此前在哪条路线，都能在这里切换，所以令两者同时等于 max(sum1, sum2) + common。

最后把未扫描的尾部加入对应累计和，答案是二者最大值。取模只在最终返回时进行；中间比较必须使用未取模的真实大小。

完整过程

1

向小者前进

比较两个指针，较小值不可能在另一数组后面再次出现，安全计入本路线。

2

公共点合流

相等时比较两边累计收益，保留更大者，并把公共值只加一次。

3

处理尾部

某条路线先结束后，另一条剩余数字只能顺序走完；最终取两条累计和的最大值。

公共值 x：next = max(sum1, sum2) + x；然后 sum1 = sum2 = next

正确性证明

不变式：每次处理指针之前，sum1（或 sum2）等于所有能到达当前路线已扫描末端的合法路径中的最大得分。

  1. 初始化：尚未扫描任何数字，两条路线得分均为 0，不变式成立。
  2. 非公共值：较小的当前值不可能在另一条严格递增数组的未扫描部分中出现，因此此处无法换轨。所有到达该路线的合法路径都必须追加这个值，累计和直接加上它仍然最优。
  3. 公共值：到达公共值时，路径既可从路线 1 来，也可从路线 2 来。两种来源覆盖全部可能；选择 max(sum1, sum2)，再把公共值加一次，就得到到达该节点的最优得分。由于可以换轨，这一最优状态同时适用于两条路线。
  4. 终止：扫描完后，最优合法路径必然结束在两条路线之一。不变式保证两个累计和分别是这两类路径的最优值，因此二者最大值就是全局最优。

边界与数值

  • 没有公共元素：算法退化为分别求两数组总和，再取较大者。
  • 每个位置都公共：两个累计和始终相等，每个公共值只加一次。
  • 公共元素位于开头或末尾：合流规则无需特判。
  • 最大总和可达约 10¹²；Java 用 long，C++ 用 long long，JavaScript 用安全整数范围内的 Number，Python 整数自动扩展。
  • 不要在比较累计和之前取模，因为取模会破坏大小关系。

复杂度

设两数组长度分别为 m、n。每个指针只向右移动，时间复杂度为 O(m + n)；只维护指针与累计和，额外空间复杂度为 O(1)。

四语言完整代码

Java
class Solution {
    public int maxSum(int[] nums1, int[] nums2) {
        final long MOD = 1_000_000_007L;
        int i = 0, j = 0;
        long sum1 = 0, sum2 = 0;

        while (i < nums1.length && j < nums2.length) {
            if (nums1[i] < nums2[j]) {
                sum1 += nums1[i++];
            } else if (nums1[i] > nums2[j]) {
                sum2 += nums2[j++];
            } else {
                long best = Math.max(sum1, sum2) + nums1[i];
                sum1 = best;
                sum2 = best;
                i++;
                j++;
            }
        }

        while (i < nums1.length) sum1 += nums1[i++];
        while (j < nums2.length) sum2 += nums2[j++];
        return (int) (Math.max(sum1, sum2) % MOD);
    }
}

替代方案

也可以把相邻公共元素之间的数字看成一个“区间段”：分别计算两条路线在该段的和，每段选择较大者，再加上公共元素。这与上面的双指针状态压缩本质相同。还可以写成显式动态规划，但若建立数组或哈希表保存每个位置状态，会增加不必要的空间。

面试追问

  • 为什么不能每一步都选眼前更大的数？ 因为只能在公共值处切换，单个局部值不能决定整个区间的累计收益。
  • 为什么最终才取模？ 算法需要比较真实累计和；两个数取模后的次序可能反转。
  • 如果数组不再有序怎么办？ 双指针前提失效；若仍要保持原路径顺序，需要重新定义可切换位置并使用映射或图上的动态规划。
  • 能否恢复具体路径？ 可以在每个公共节点记录来自哪一侧，并回溯区间选择，代价是 O(k) 额外空间，k 为公共元素数。

常见错误

  • 公共值被两侧各加一次，导致重复计分。
  • 相遇时只更新其中一个累计和，丢失“此后两边都能继承最优前缀”的事实。
  • 某个数组扫描结束后忘记累加另一数组的剩余尾部。
  • 使用 32 位整数保存中间总和而溢出。
  • 在每次加法后取模，再用取模结果判断哪条路线更优。
