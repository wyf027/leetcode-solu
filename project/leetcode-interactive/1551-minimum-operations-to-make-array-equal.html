使数组中所有元素相等的最小操作数

Minimum Operations to Make Array Equal

Problem

题目

给定整数 n，构造长度为 n 的数组，其中 arr[i] = 2 × i + 1，下标范围是 0 ≤ i < n。

每次操作可选择两个合法下标 x、y，令 arr[x] 减 1，同时令 arr[y] 加 1。求让数组所有元素相等所需的最少操作数。题目保证一定能做到。

函数形式： minOperations(n: integer) → integer

示例 1

输入：n = 3
输出：2
解释：arr = [1, 3, 5]
操作 1：选择 x = 2，y = 0 → [2, 3, 4]
操作 2：选择 x = 2，y = 0 → [3, 3, 3]

示例 2

输入：n = 6
输出：9

约束

1 ≤ n ≤ 10⁴

Solution

数学归纳：只计算低于平均值的缺口

核心洞察

数组是前 n 个正奇数，因此总和是 n²，平均值恰为 n。一次操作同时转出和转入一个单位；要达到平均值，只需统计所有小于 n 的元素还缺多少。每个缺少的单位都必须由一次操作补入，也能用一次操作从右侧富余元素搬来。

答案 = ⌊n² / 4⌋

完整过程

  1. 由 arr[i] = 2i + 1 得到数组 1, 3, 5, …, 2n−1。
  2. 前 n 个奇数之和为 n²，所以所有元素最终都等于 n。
  3. 关于 n 对称配对：1 与 2n−1、3 与 2n−3……每对的缺口和富余量相同。
  4. 当 n = 2k 时，低半部分的缺口为 1 + 3 + … + (2k−1) = k²。
  5. 当 n = 2k+1 时，中间值已等于目标，左右缺口为 2 + 4 + … + 2k = k(k+1)。
  6. 两种情况统一为 ⌊n² / 4⌋，使用整数除法即可。

正确性证明

下界：每个低于 n 的元素必须获得它与 n 的差值。一次操作只能向某个低位元素增加 1，所以任何方案至少需要“所有低位缺口之和”次操作。

可达性：数组总和等于 n × n，因此高于 n 的富余量总和与低位缺口总和相等。每次从仍有富余的元素转移 1 给仍有缺口的元素，恰好用上述数量的操作即可完成。

下界能够达到，所以该数量就是最少操作数；化简后等于 ⌊n² / 4⌋。

边界与复杂度

  • n = 1 时数组只有 [1]，答案为 0，公式仍成立。
  • n = 10⁴ 时答案为 25,000,000，32 位有符号整数足够；计算乘积时仍应关注语言的数值类型。
  • 时间复杂度 O(1)，空间复杂度 O(1)。

替代方案

可以遍历 i = 0 到 ⌊n/2⌋−1，累加 n − (2i+1)。它更直接地表达“补齐低半边”，时间复杂度是 O(n)；闭式公式更简洁。

面试追问

  • 为什么最终值只能是平均数？因为每次操作都保持总和不变。
  • 如果一次允许搬运任意正整数，最少操作次数如何定义？需要先明确“一次操作”的成本是否与搬运量无关，答案会随模型改变。
  • 如果数组不是等差数列？仍可先求平均数，再统计低于平均数的缺口；前提是总和可被元素个数整除。

常见错误

  • 同时统计缺口和富余，导致答案重复计算。
  • 把最终目标误判为中位数；这里操作守恒的是总和，所以目标是平均数。
  • 写成 n*n/4 却在不支持安全整数的更大约束下忽视溢出。
  • 真的构造并逐步修改数组，增加不必要的时间与空间开销。
