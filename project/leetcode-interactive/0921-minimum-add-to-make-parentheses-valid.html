Solution

贪心：只记录未匹配数量

核心洞察

从左到右扫描。balance 表示尚未匹配的左括号数；missing 表示此前遇到孤立右括号时必须补入的左括号数。右括号能匹配就消耗一个 balance，否则立刻令 missing + 1。最终答案是 missing + balance。

完整过程

  1. 初始化 balance = 0、missing = 0。
  2. 遇到 (，令 balance++。
  3. 遇到 ) 且 balance > 0，令 balance--；否则令 missing++。
  4. 扫描结束后，返回 missing + balance。

正确性说明

扫描到孤立的 ) 时，已有前缀中没有左括号可与它匹配；任何有效结果都必须在它之前插入至少一个 (，贪心补一个既必要又充分。扫描结束后的每个未匹配 ( 都需要一个后置 )，同样一一对应且不可省略。因此算法添加的两部分都是必需的下界，且添加后可构成有效串，答案最小。

边界情况

  • 本身有效：答案为 0。
  • 全是左括号：答案等于长度。
  • 全是右括号：答案等于长度。
  • 先右后左：两类缺口都会出现。

复杂度

时间复杂度 O(n)；只使用两个计数器，空间复杂度 O(1)。

替代方案

可用栈保存未匹配括号，最后取栈大小，但会使用 O(n) 空间；计数器更直接。

四语言完整代码

Java

class Solution {
    public int minAddToMakeValid(String s) {
        int balance = 0, missing = 0;
        for (char c : s.toCharArray()) {
            if (c == '(') {
                balance++;
            } else if (balance > 0) {
                balance--;
            } else {
                missing++;
            }
        }
        return missing + balance;
    }
}

常见错误

  • 让 balance 变成负数，却忘记统计孤立右括号。
  • 只返回剩余左括号数，遗漏前缀缺口。
  • 真的构造字符串，增加不必要的空间和索引复杂度。
