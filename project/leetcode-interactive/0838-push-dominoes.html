Push Dominoes · 让时间逐帧前进，观察力如何相遇、抵消与停止。

Problem statement

题目

n 张竖立的多米诺骨牌排成一行。起初，一部分骨牌被同时向左或向右推；其余骨牌保持竖立。

每过一秒，正在向左倒的骨牌推动左边相邻且仍竖立的骨牌，向右倒的骨牌同理。如果一张竖立骨牌在同一时刻同时受到左右两边的力，两股力抵消，它继续保持竖立。已经倒下或正在倒下的骨牌不会再因额外受力而改变方向。

字符串 dominoes 用 'L'、'R'、'.' 分别表示初始向左、初始向右和未推动。返回所有运动停止后的最终状态字符串。

函数形式：pushDominoes(dominoes: string) → string
Contract

输入与约束

  • n == dominoes.length
  • 1 ≤ n ≤ 10⁵
  • dominoes[i] 只可能是 'L'、'R' 或 '.'

输出与输入等长；保持竖立的骨牌仍用点号表示。

Editorial

题解：在相邻外力之间结算

核心洞察

真正决定一段连续点号的，只是它左右最近的两个非点字符。加入虚拟边界 L 和 R 后，每一段都能归入四种组合：

  • L...L：右侧的 L 一路向左传播，整段变成 L。
  • R...R：左侧的 R 一路向右传播，整段变成 R。
  • L...R：两股力背向而行，中间全部保持竖立。
  • R...L：两股力相向而行，从两端向中间填；若点号数为奇数，正中间受力抵消，仍为点号。

完整过程

  1. 构造 s = "L" + dominoes + "R"，这两个哨兵只负责自然处理首尾点号。
  2. 令 i 指向上一张非点骨牌，令 j 向右扫描下一张非点骨牌。
  3. 先把 s[i] 加入答案。若中间有 j-i-1 个点号，根据 s[i] 和 s[j] 的组合一次结算整段。
  4. 移动 i = j，继续扫描。最后不加入右侧虚拟哨兵。

正确性证明

引理 1：两张相邻非点骨牌之间的任意竖立骨牌，不会受到区间外骨牌的有效影响。因为两端的非点骨牌已经倒下，传播到它们的额外力不改变其方向，也无法穿透它们。

引理 2：算法对四类端点组合的填充恰好等于逐秒演化结果。同向端点中只有朝区间内部的一侧传播；背向端点都不向内部传播；相向端点以相同速度靠近，距离较近的一方先到，等距时抵消。

定理：所有点号被相邻非点字符划分成互不重叠的区间。由引理 1，各区间可独立处理；由引理 2，每个区间均被正确结算。因此拼接后的字符串就是全局最终状态。

边界情况

  • 全是点号：虚拟的 L...R 保证全部不动。
  • 开头为点号且首个力是 L：左哨兵与该 L 构成 L...L。
  • 结尾为点号且最后的力是 R：该 R 与右哨兵构成 R...R。
  • R...L 中间长度为奇数：中心点必须保留。
  • 长度为 1：三种字符都能由相同逻辑处理。

复杂度

每个字符只被扫描或写入常数次，时间复杂度 O(n)；构造返回字符串需要 O(n) 空间。除输出及哨兵字符串外，辅助变量为 O(1)。

替代方案

受力计分：从左向右记录 R 的递减影响，再从右向左减去 L 的影响，最终按正负号决定方向。也是 O(n) 时间、O(n) 空间，思路规整但额外数组更大。逐秒模拟最直观，却可能在长链上退化到 O(n²)。

class Solution {
    public String pushDominoes(String dominoes) {
        String s = "L" + dominoes + "R";
        StringBuilder ans = new StringBuilder();
        int i = 0;
        for (int j = 1; j < s.length(); j++) {
            if (s.charAt(j) == '.') continue;
            int middle = j - i - 1;
            if (i > 0) ans.append(s.charAt(i));
            char left = s.charAt(i), right = s.charAt(j);
            if (left == right) {
                ans.append(String.valueOf(left).repeat(middle));
            } else if (left == 'L' && right == 'R') {
                ans.append(".".repeat(middle));
            } else {
                ans.append("R".repeat(middle / 2));
                if (middle % 2 == 1) ans.append('.');
                ans.append("L".repeat(middle / 2));
            }
            i = j;
        }
        return ans.toString();
    }
}

var pushDominoes = function(dominoes) {
    const s = `L${dominoes}R`;
    const ans = [];
    let i = 0;
    for (let j = 1; j < s.length; j++) {
        if (s[j] === '.') continue;
        const middle = j - i - 1;
        if (i > 0) ans.push(s[i]);
        if (s[i] === s[j]) {
            ans.push(s[i].repeat(middle));
        } else if (s[i] === 'L' && s[j] === 'R') {
            ans.push('.'.repeat(middle));
        } else {
            ans.push('R'.repeat(Math.floor(middle / 2)));
            if (middle % 2 === 1) ans.push('.');
            ans.push('L'.repeat(Math.floor(middle / 2)));
        }
        i = j;
    }
    return ans.join('');
};

面试追问

  • 为何两个哨兵方向恰好是 L 和 R？ 它们分别代表左边界之外没有向右的力、右边界之外没有向左的力，从而不凭空推动边缘骨牌。
  • 能否原地修改？ 若语言支持可变字符数组，可以在数组内结算每段；仍需最终构造返回字符串，算法辅助空间可降为 O(1)。
  • 如果左右传播速度不同？ 不能再按段长对半分，需要比较到达时间，受力计分或事件模拟更容易扩展。

常见错误

  • 把 R...L 的中心点无条件改写，忽略奇数间隔时的抵消。
  • 误把 L...R 填满；两端实际朝区间外倒。
  • 把逐秒模拟写成每轮全数组扫描，导致最坏 O(n²)。
  • 把虚拟哨兵也追加进最终答案，造成长度多 1 或 2。
