Find the Duplicate Number

在不改动数组、额外空间恒定的限制下，找出唯一那个重复出现的整数。 先理解输入关系，再用下方探索器观察指针如何在数字映射中移动。

287
Problem

题目描述

给定整数数组 nums，它包含 n + 1 个整数，每个整数都位于闭区间 [1, n]。数组中恰好只有一种数值会重复出现两次或更多次，其余数值各出现一次；返回这个重复数。

限制条件

不得修改原数组，并且只能使用 O(1) 额外空间。

官方示例

输入：nums = [1,3,4,2,2]
输出：2
输入：nums = [3,1,3,4,2]
输出：3
输入：nums = [3,3,3,3,3]
输出：3

Input contract

约束

  • 1 <= n <= 105
  • nums.length == n + 1
  • 1 <= nums[i] <= n
  • 只有一个整数会重复，但它可以出现两次以上。

参数形式

findDuplicate(nums: integer[]) -> integer

Solution

Floyd 判圈：重复值就是环入口

把每个数组下标看作节点，并把边定义为 i → nums[i]。由于数组值始终落在 [1,n]， 从下标 0 不断沿边前进一定会进入环；重复数对应多条边汇入的节点，也正是这条可达路径的环入口。

核心洞察

问题不是在数组中直接“计数”，而是在一个有限函数图中找环入口。

  • 阶段一：慢指针每次走 1 步，快指针每次走 2 步，二者必在环内相遇。
  • 阶段二：一个指针回到起点 0，另一个留在相遇点；二者都改为每次走 1 步。
  • 再次相遇的位置就是环入口，其节点编号等于重复数。

完整过程

  1. 令 slow = nums[0]，fast = nums[nums[0]]。
  2. 循环推进 slow = nums[slow]、fast = nums[nums[fast]]，直到相遇。
  3. 令 finder = 0，保留相遇位置。
  4. 同时单步推进 finder 与相遇指针，直到二者相等。
  5. 返回相等的节点编号。

正确性证明

一定存在环。 从 0 出发，每一步都进入节点集合 [1,n]。无限前进而可选节点有限，必定再次访问某个节点。

第一阶段一定相遇。 两指针进入环后，快指针每轮相对慢指针多走一步，因此相对距离会遍历环长的所有余数，最终为 0。

第二阶段相遇于环入口。 设起点到环入口距离为 μ，环长为 λ。第一次相遇时慢指针走过的距离满足与 μ 同余于某个环内偏移；由快指针路程是慢指针两倍，可得相遇点再走 μ 步恰好到环入口。因此从 0 和相遇点同步单步前进，会在入口首次重合。

环入口就是重复值。 数组中只有一个数值拥有多个前驱下标；这正是路径首次汇入既有节点的位置，所以它与环入口一致。算法返回的就是题目要求的重复数。

边界情况

  • 最短数组如 [1,1]：环入口为 1。
  • 重复数出现多次，如 [3,3,3,3,3]：函数图仍有同一个入口。
  • 重复值为 1 或 n：无需特殊分支。
  • 实现时所有访问都由合法数组值产生，不会越界。

复杂度

时间：O(n)。两个阶段的移动次数都被路径长度与环长的常数倍限制。

额外空间：O(1)。只保存若干整数指针。

数组修改：无，满足题目限制。

替代方案

  • 按值域二分：统计 <= mid 的元素个数，利用抽屉原理缩小重复值范围；时间 O(n log n)，空间 O(1)，同样不改数组。
  • 排序：相邻比较直观，但通常会修改数组；复制后排序又需要 O(n) 空间。
  • 哈希集合：时间 O(n)，但需要 O(n) 空间，不符合本题硬约束。
  • 位运算计数：可按位比较数组与 1..n 的计数，空间恒定，但推导与实现更复杂。

面试追问

  • 为什么至少有重复？ n + 1 个元素放入 n 个可能值，按抽屉原理至少两个元素同值。
  • 为什么从 0 出发？ 0 不可能成为后继值，能提供一条进入 [1,n] 的确定路径，并避免起点本身有额外入边的歧义。
  • 若有多个不同重复值？ 当前“环入口等于答案”的唯一性不再足以返回所有重复值，需要更改问题模型或约束。

常见错误

  • 把 fast 写成 nums[fast]，导致两个指针同速，失去判圈意义。
  • 第二阶段仍让快指针走两步；此阶段两个指针都必须单步移动。
  • 用数组下标 0 与相遇点直接比较，却忘记每轮都通过 nums 跳转。
  • 采用原地排序或正负号标记，违反“不得修改数组”的条件。
  • 误以为重复数只出现两次；官方约束允许它出现两次以上。
Implementation

四种语言完整实现

JavaO(n) · O(1)
class Solution {
    public int findDuplicate(int[] nums) {
        int slow = nums[0];
        int fast = nums[nums[0]];

        while (slow != fast) {
            slow = nums[slow];
            fast = nums[nums[fast]];
        }

        int finder = 0;
        while (finder != slow) {
            finder = nums[finder];
            slow = nums[slow];
        }
        return finder;
    }
}
