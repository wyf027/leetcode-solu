找到最接近目标值的函数值

在所有连续片段中寻找一个按位与结果，使它与目标值的绝对差尽可能小。先理解任务，再亲手拨动每一步。

困难 数组 位运算 状态压缩 非付费题

Problem

题目说明

给定整数数组 arr、整数 target，以及下述函数 func(arr, l, r)：

若 l > r，先交换二者；随后从 arr[l] 开始，将区间内每个元素依次执行按位与。因此函数值就是非空连续子数组 arr[l..r] 的按位与。
min | (arr[l] & arr[l+1] & … & arr[r]) − target |

请返回这个最小绝对差。索引参数满足 0 ≤ l, r < arr.length。

约束

  • 1 ≤ arr.length ≤ 10⁵
  • 1 ≤ arr[i] ≤ 10⁶
  • 0 ≤ target ≤ 10⁷

返回值类型：整数。函数签名：closestToTarget(arr, target)。

示例 1 
输入：arr = [9,12,3,7,15], target = 5
输出：2

所有区间按位与中，3 和 7 都与 5 相差 2。

示例 2 
输入：arr = [1000000,1000000,1000000], target = 1
输出：999999

每个非空区间的函数值都是 1000000。

示例 3 
输入：arr = [1,2,4,8,16], target = 0
输出：0

存在按位与等于 0 的连续区间。

Solution

把所有左端点压缩成少量状态

从左向右扫描。对每个右端点 r，只保留“所有以 r 结尾的子数组”的不同按位与结果；不必保留产生它们的每一个左端点。

1

状态定义

prev 是所有以 r−1 结尾的不同按位与值。

2

状态转移

新集合为 {arr[r]} 与所有 v & arr[r] 的并集，然后去重。

3

为什么集合很小

区间向左扩展时，比特位只会从 1 变 0。每次出现新值至少清掉一位，因此不同值数量受有效位数约束。

完整过程

  1. 令 prev 为空，答案 ans 为正无穷。
  2. 遍历每个元素 x，建立 cur = {x}。
  3. 对 prev 中每个值 v，把 v & x 加入 cur；集合自动去重。
  4. 用 |v − target| 更新答案。若答案已为 0，可立即返回。
  5. 令 prev = cur，处理下一个右端点。

正确性证明

  1. 状态完备性：归纳假设 prev 恰好包含所有以 r−1 结尾的子数组按位与。以 r 结尾的子数组要么只有 arr[r]，要么由一个以 r−1 结尾的子数组追加 arr[r]；其结果正是 v & arr[r]。所以 cur 不漏不多。
  2. 去重安全性：目标只依赖按位与的数值。同一右端点下，相同数值来自哪个左端点不影响当前差值，也不影响下次与新元素后的结果。
  3. 全局最优性：每个非空连续子数组都有唯一右端点；算法在处理该右端点时会检查它的函数值。因此所有可行函数值都被检查，最终答案就是最小绝对差。

复杂度

设数值有效位数为 B（本题至多约 20）。每个位置的不同按位与值为 O(B)，时间 O(nB)，额外空间 O(B)。按本题取值范围，可视为接近线性。

边界处理

单元素数组由 {x} 覆盖；答案为 0 时已达绝对下界；重复元素会被集合自然合并；目标值可以大于所有函数值，也可以为 0。

替代方案

枚举区间是 O(n²)。也可用稀疏表或线段树查询区间按位与，再利用函数随右端点扩展单调不增的性质搜索变化点，但代码与常数都更复杂。

常见错误

把“不同状态数少”误写成固定魔法数字；更新集合时忘记加入单元素 x；原地修改 prev 导致重复扩展；只在集合外更新答案而漏掉当前值。

四语言完整实现

import java.util.HashSet;
import java.util.Set;

class Solution {
    public int closestToTarget(int[] arr, int target) {
        Set<Integer> prev = new HashSet<>();
        int answer = Integer.MAX_VALUE;

        for (int x : arr) {
            Set<Integer> current = new HashSet<>();
            current.add(x);
            for (int value : prev) {
                current.add(value & x);
            }

            for (int value : current) {
                answer = Math.min(answer, Math.abs(value - target));
            }
            if (answer == 0) return 0;
            prev = current;
        }
        return answer;
    }
}

面试追问

为什么每个位置的状态数不会增长到 O(n)？

固定右端点并向左扩展时，按位与只能清除比特，不能把 0 恢复为 1。连续两个不同结果之间至少有一个比特从 1 变 0，所以不同结果数由比特数控制。

如果把按位与换成按位或，还能用同一模式吗？

可以。按位或只会把 0 变 1，同样具有有限次变化；将转移改为 value | x 即可。

为什么不能用普通双指针直接逼近 target？

虽然固定左端点时按位与随右端点扩展单调不增，但移动左端点会以非线性方式恢复比特，无法建立普通滑动窗口所需的全局单调关系。
