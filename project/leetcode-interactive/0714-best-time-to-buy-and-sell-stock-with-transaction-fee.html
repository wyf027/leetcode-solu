714. 买卖股票的最佳时机含手续费

Best Time to Buy and Sell Stock with Transaction Fee

01 / Problem

题目描述

给定整数数组 prices，其中 prices[i] 表示第 i 天的股票价格；整数 fee 表示每笔完整交易的手续费。

你可以进行任意多次交易。一次交易由买入和随后卖出组成，且只收取一次手续费。任意时刻最多持有一股股票，因此必须先卖出当前股票，才能再次买入。

返回在遵守这些规则时能够获得的最大利润。

关键交易规则
手续费只在每次“买入—卖出”的完整交易中支付一次；下面的推演统一在卖出时扣除。

约束

  • 1 <= prices.length <= 5 × 104
  • 1 <= prices[i] < 5 × 104
  • 0 <= fee < 5 × 104

示例一

01
输入：prices = [1, 3, 2, 8, 4, 9], fee = 2
输出：8
解释：在第 0 天以 1 买入，第 3 天以 8 卖出；
      再在第 4 天以 4 买入，第 5 天以 9 卖出。
      总利润 = ((8 - 1) - 2) + ((9 - 4) - 2) = 8。

示例二

02
输入：prices = [1, 3, 7, 5, 10, 3], fee = 3
输出：6

函数签名

输入完整参数 prices: integer[] 与 fee: integer，返回 integer。

04 / Solution

动态规划：只记住今天结束时的两种可能

核心洞察

每天收盘后，合法状态只有两种：手里没有股票，或手里持有一股股票。我们不必保存完整交易历史，只需保存这两种状态各自能达到的最大利润。
cash = 今天结束时空仓的最大利润 hold = 今天结束时持有一股的最大利润 newCash = max(cash, hold + price - fee) newHold = max(hold, cash - price)

每个状态都只有“保持不动”或“在今天完成一次动作”两个来源。手续费放在卖出转移中扣除，能保证每笔完整交易恰好支付一次。

完整过程

  1. 初始化。还没看任何价格时，空仓利润为 0。看到第 0 天后，持有状态可以通过买入得到 -prices[0]。
  2. 更新空仓。今天结束时空仓，要么昨天已经空仓并保持不动，要么昨天持有、今天卖出，并扣除手续费。
  3. 更新持有。今天结束时持有，要么昨天已经持有并保持不动，要么昨天空仓、今天买入。
  4. 使用旧状态。两个新值必须都基于同一天开始前的 cash 与 hold。可保存旧值，或按证明安全的顺序更新。
  5. 返回空仓。最后仍持股的账面状态还没有把股票变回利润，最优答案是最终的 cash。

正确性证明

不变式

处理完第 i 天后，cash 等于所有以空仓结束的合法方案中的最大利润；hold 等于所有以持有一股结束的合法方案中的最大利润。

基础

第 0 天结束时，空仓只能什么都不做，利润是 0；持有只能买入一股，利润是 -prices[0]。不变式成立。

归纳

假设第 i - 1 天后不变式成立。第 i 天空仓的合法方案只可能来自“原本空仓且不操作”或“原本持有且卖出”，取两者最大值正是 newCash。同理，持有状态只可能来自“继续持有”或“原本空仓且买入”，取最大值正是 newHold。两种状态覆盖全部合法方案，且互不遗漏。

结论

归纳可知不变式在最后一天成立。任何已实现的利润方案最终都应空仓，因此最终 cash 就是最大利润。

边界情况

  • 只有一天：无法完成买入再卖出，答案为 0。
  • 价格持续下降：始终不交易，cash 保持 0。
  • 手续费很高：若涨幅不足以覆盖手续费，算法会选择保持空仓。
  • 手续费为 0：问题退化为不限次数买卖股票，转移式仍然成立。
  • 同一天不能持有多股：状态中只有“0 股”与“1 股”，天然满足限制。

复杂度

时间复杂度O(n)

每个价格只处理一次。

空间复杂度O(1)

只维护两个状态值。

替代方案

  • 二维 DP 表：使用 dp[i][0/1] 保存每天两种状态，更直观，也便于还原路径；空间为 O(n)，可进一步压缩为本题方案。
  • 贪心维护有效买入成本：把手续费并入买入成本，遇到更低成本就替换，遇到可盈利价格就兑现收益并把有效成本抬到当前价。能做到 O(n)/O(1)，但证明与手续费处理更容易出错。
  • 递归 + 记忆化：按“天数 × 是否持有”搜索所有选择，概念直接，但递归深度可达 5 × 104，不如迭代稳妥。

四语言完整代码

Java 
class Solution {
    public int maxProfit(int[] prices, int fee) {
        int cash = 0;
        int hold = -prices[0];

        for (int i = 1; i < prices.length; i++) {
            int previousCash = cash;
            int previousHold = hold;
            cash = Math.max(previousCash, previousHold + prices[i] - fee);
            hold = Math.max(previousHold, previousCash - prices[i]);
        }
        return cash;
    }
}

面试追问

手续费放在买入时扣可以吗？

可以。只要每笔交易恰好扣一次，令 hold = max(hold, cash - price - fee)、卖出时不扣费，最终答案相同。不要同时在买入和卖出两边扣。

如何还原具体买卖日期？

保留每天两种状态的来源选择，或在状态改善时记录前驱；最后从空仓状态反向追踪。这样需要 O(n) 的额外空间。

如果最多只能交易 k 次呢？

状态需增加交易次数维度，变成 dp[day][transactions][holding]，时间通常为 O(nk)，空间可滚动压缩。

为什么最终不返回 max(cash, hold)？

hold 表示仍持有股票的账面状态，未完成卖出。题目要求已实现的最大利润，因此最终必须空仓。

常见错误

  • 每次价格上涨都卖出，却没有考虑多次小额交易会重复支付手续费。
  • 买入与卖出时各扣一次手续费，导致一笔交易被收费两次。
  • 更新 cash 后，直接用新的 cash 计算 hold，却没有证明这种更新顺序的安全性。保存旧值最清晰。
  • 把 hold 初始化为 0，相当于凭空拥有一股免费股票。
  • 最终返回持有状态，或强制在每个局部高点交易。
