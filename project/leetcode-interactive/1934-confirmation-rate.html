01 / 题目与数据契约

输入两张关系表。对每个已注册用户，计算其 confirmed 请求数与所有确认请求数的比值；无请求时取 0。结果列为 user_id、confirmation_rate，四舍五入至两位小数，行顺序不限。

Signups · 注册表

列类型
user_idint
time_stampdatetime

user_id 为主键，每行是该用户的注册时间。

Confirmations · 请求表

列类型
user_idint
time_stampdatetime
actionENUM

联合主键为 (user_id, time_stamp)；user_id 外键指向 Signups。action 只能是 confirmed 或 timeout，分别表示确认与超时。

约束与提交形式

  • 同一用户可有多次请求，但同一用户与时间戳的组合唯一。
  • 注册时间与请求时间不构成题目要求的筛选条件；应使用全部请求记录。
  • 官方没有额外给出行数或 user_id 数值范围，不自行添加限制。
  • 这是数据库题。官方提供 MySQL、MS SQL Server、PostgreSQL、Oracle 与 Pandas 入口；主解采用 MySQL 查询，不设通用算法函数签名。

04 / 独立题解与交互实验

准备好后，展开连接、分组与舍入的完整过程。

保留每个用户，再对消息打分

核心洞察：给 confirmed 记 1，给 timeout 记 0，这些分数的平均值正好是确认率。以 Signups 为左表做 LEFT JOIN，才能保留没有请求的用户；对连接产生的空行记 0，其平均值也为 0。

完整过程

  1. 从 Signups 取全部用户，以 user_id 连接 Confirmations。
  2. 用户 3 对应 [0,0]，用户 7 对应 [1,1,1]，用户 2 对应 [1,0]。
  3. 用户 6 无匹配记录，LEFT JOIN 仍产生一行，其 action 为 NULL；CASE 的 ELSE 分支输出 0。
  4. 按 s.user_id 分组，分别取平均得到 0、1、0.5、0。
  5. ROUND(..., 2) 得到两位小数精度的结果；显示格式可能由数据库客户端决定。

正确性

设用户 u 有 m 条真实请求，其中 k 条 confirmed。若 m > 0，连接为它产生恰好 m 行，CASE 得分和为 k，因此 AVG = k/m。若 m = 0，左连接产生唯一空行，CASE 得分为 0，AVG = 0，符合无请求的定义。注册表的 user_id 唯一，分组后每位注册用户恰好一行；ROUND 保证所需精度，因此查询覆盖全部目标用户且数值符合题意。

边界与常见错误

  • INNER JOIN 会丢失无请求用户；在 WHERE 中过滤 c.action = 'confirmed' 还会删除超时行，让分母错误。
  • 直接 AVG(c.action = 'confirmed') 是 MySQL 特有简写，对空连接行产生 NULL，需要 COALESCE；CASE ... ELSE 0 的主解已处理空行。
  • 如果显式计算请求数，应 COUNT(c.user_id) 而非 COUNT(*)，后者会把空占位算作 1。主解使用空行得分 0 的平均值，语义已单独证明。
  • 全超时为 0，全确认为 1，两张空表返回空结果；同一用户的多个不同时间戳必须全部计入。
  • 先用小数参与除法，最后统一舍入。不要整数除法截断，也不要对每条请求提前舍入。
  • 参考实现中的两位小数字符串用于本地呈现；SQL 返回数值列。

复杂度

记注册数为 S、请求数为 C。在哈希连接与哈希分组模型下，扫描与聚合的期望时间为 O(S+C)，典型辅助空间为 O(S+C)（连接构建表与分组状态）。SQL 的真实成本取决于执行计划、索引、排序与内存限制，并非固定承诺。四语言参考实现先按用户计数，期望时间 O(S+C)，辅助计数空间 O(U)，输出空间 O(S)，其中 U 是有请求的用户数且 U ≤ S。

替代方案与面试追问

可先在 Confirmations 内按 user_id 预聚合确认数与总数，再 LEFT JOIN Signups，使用 COALESCE 补 0；当请求量很大时，这能缩小连接中间结果。也可用 SUM(CASE...)/NULLIF(COUNT(c.user_id),0) 配合 COALESCE，但更需留意小数除法。

  • 如果只算最近 30 天？把请求时间条件放在 ON 或预聚合子查询中，保留没有该时段请求的用户。
  • 如果新增 pending 状态？先明确它是否进入分母，再同时修改打分与计数规则。
  • 如何提升查询效率？查看实际执行计划，评估 Confirmations 的 user_id 索引与预聚合策略。
  • 能否使用窗口函数？可以，但每条请求都会保留一行，还需要去重；本题直接分组更清晰。

完整代码

SQL 为官方可提交形式；下面四份代码仅复现关系表的统计语义，不冒充本题的官方语言提交接口，输入均假设满足上面的表约束。

MySQL · 官方可提交语言

主解使用 CASE、LEFT JOIN、AVG 与 ROUND。

SELECT s.user_id,
       ROUND(AVG(CASE WHEN c.action = 'confirmed'
                      THEN 1.0 ELSE 0.0 END), 2)
         AS confirmation_rate
FROM Signups AS s
LEFT JOIN Confirmations AS c ON c.user_id = s.user_id
GROUP BY s.user_id;

Java · 本地语义参考

完整类与方法；Java 17+，输入为表行列表，不是本题官方提交入口。

import java.math.BigDecimal;
import java.math.RoundingMode;
import java.util.*;

// Local semantic reference, Java 17+. Timestamps do not affect this query.
public class Solution {
    public record Signup(int userId, String timeStamp) {}
    public record Confirmation(int userId, String timeStamp, String action) {}
    public record Result(int userId, BigDecimal confirmationRate) {}

    public static List<Result> confirmationRate(
            List<Signup> signups, List<Confirmation> confirmations) {
        Map<Integer, long[]> counts = new HashMap<>();
        for (Confirmation c : confirmations) {
            long[] count = counts.computeIfAbsent(c.userId(), k -> new long[2]);
            count[1]++;
            if (c.action().equals("confirmed")) count[0]++;
        }
        List<Result> result = new ArrayList<>();
        for (Signup s : signups) {
            long[] count = counts.getOrDefault(s.userId(), new long[2]);
            BigDecimal rate = count[1] == 0 ? new BigDecimal("0.00")
                : BigDecimal.valueOf(count[0]).divide(
                    BigDecimal.valueOf(count[1]), 2, RoundingMode.HALF_UP);
            result.add(new Result(s.userId(), rate));
        }
        return result;
    }
}

JavaScript · 本地语义参考

BigInt 精确舍入；user_id 使用可精确表示的整数。不是本题官方提交语言。

// Local semantic reference. Inputs use complete database row objects:
// signups: [{user_id, time_stamp}], confirmations: [{user_id, time_stamp, action}].
// Rates are fixed-decimal strings to preserve the two-digit display.
function confirmationRate(signups, confirmations) {
  const counts = new Map();
  for (const row of confirmations) {
    const pair = counts.get(row.user_id) ?? [0n, 0n];
    pair[1] += 1n;
    if (row.action === 'confirmed') pair[0] += 1n;
    counts.set(row.user_id, pair);
  }
  return signups.map(({user_id}) => {
    const [ok, total] = counts.get(user_id) ?? [0n, 0n];
    const cents = total === 0n ? 0n : (200n * ok + total) / (2n * total);
    return {user_id, confirmation_rate:
      `${cents / 100n}.${String(cents % 100n).padStart(2, '0')}`};
  });
}

Python · 本地语义参考

标准库字典行接口，不是官方 Pandas DataFrame 签名；结果率以两位小数字符串展示。

from decimal import Decimal, ROUND_HALF_UP

# Local semantic reference, not the official Pandas function.
# Each input row is a dict containing all database columns.
def confirmation_rate(signups, confirmations):
    counts = {}
    for row in confirmations:
        pair = counts.setdefault(row["user_id"], [0, 0])
        pair[1] += 1
        pair[0] += row["action"] == "confirmed"
    result = []
    for row in signups:
        ok, total = counts.get(row["user_id"], (0, 0))
        # Integer arithmetic gives exact half-up rounding for nonnegative rates.
        cents = (200 * ok + total) // (2 * total) if total else 0
        rate = Decimal(cents).scaleb(-2)
        result.append({"user_id": row["user_id"],
                       "confirmation_rate": format(rate, ".2f")})
    return result

C++ · 本地语义参考

完整数据结构及函数；C++17。不是本题官方提交语言。

#include <iomanip>
#include <sstream>
#include <string>
#include <unordered_map>
#include <utility>
#include <vector>
using namespace std;

// Local semantic reference, C++17; rates use fixed-decimal strings.
struct Signup { int user_id; string time_stamp; };
struct Confirmation { int user_id; string time_stamp, action; };
struct Result { int user_id; string confirmation_rate; };

vector<Result> confirmationRate(const vector<Signup>& signups,
                                const vector<Confirmation>& confirmations) {
    unordered_map<int, pair<long long, long long>> counts;
    for (const auto& row : confirmations) {
        auto& [ok, total] = counts[row.user_id];
        ++total;
        if (row.action == "confirmed") ++ok;
    }
    vector<Result> result;
    for (const auto& row : signups) {
        const auto [ok, total] = counts[row.user_id];
        // ponytail: 64-bit counts; use wider arithmetic beyond LLONG_MAX / 201 rows.
        long long cents = total ? (200 * ok + total) / (2 * total) : 0;
        ostringstream rate;
        rate << cents / 100 << '.' << setfill('0') << setw(2) << cents % 100;
        result.push_back({row.user_id, rate.str()});
    }
    return result;
}
