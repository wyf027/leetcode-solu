01 / Problem

先读懂规则，不急着看答案

两个数组

nums1 与 nums2 的长度可以不同；每个元素都是 1 到 6 的整数。

一次操作

任选任一数组中的一个元素，把它改成 1 到 6 范围内的任意整数。

返回目标

求让两数组元素和相等所需的最少操作数；若无法做到，返回 -1。

官方示例

示例 1输出 3
输入：nums1 = [1,2,3,4,5,6]
      nums2 = [1,1,2,2,2,2]
输出：3

一种 3 步方案：把 nums2[0] 改为 6，把 nums1[5] 改为 1，再把 nums1[2] 改为 2。

示例 2输出 -1
输入：nums1 = [1,1,1,1,1,1,1]
      nums2 = [6]
输出：-1

第一个数组的最小可能和仍大于第二个数组的最大可能和，因此无解。

示例 3输出 3
输入：nums1 = [6,6]
      nums2 = [1]
输出：3

例如把两个 6 分别改为 2，再把 1 改为 4，两边的和都变为 4。

约束

  • 1 <= nums1.length, nums2.length <= 105
  • 1 <= nums1[i], nums2[i] <= 6
  • 函数形式：minOperations(nums1, nums2) → integer

下方包含贪心策略、证明、复杂度和四种语言实现。

Solution Unlocked

把每次操作看成一张“收益卡”

核心洞察

假设 sum(nums1) < sum(nums2)。要消掉差值，只能让小和数组的元素增大，或让大和数组的元素减小。对小和侧元素 x，一次最多贡献 6-x；对大和侧元素 y，一次最多贡献 y-1。每次优先使用最大贡献，操作次数最少。

完整过程

  1. 先判定长度是否可能

    长度为 m 的数组和只能落在 [m, 6m]。若 6m < n 或 6n < m，两个区间不相交，直接返回 -1。

  2. 统一方向

    计算两边的和；若相等返回 0。令 low 始终是元素和较小的数组，high 是较大的数组。

  3. 统计所有单步收益

    low 中的 x 提供 6-x；high 中的 y 提供 y-1。收益只可能是 0～5，用长度为 6 的计数桶即可。

  4. 从收益 5 向 1 消除差值

    每次拿当前最大收益。某一桶可批量取 ceil(diff / gain) 个以内的元素，直到差值不大于 0。

为什么正确？

  • 每个元素只需要改一次：把同一元素改多次可以合并为一次从原值到终值的修改，不会更差。
  • 收益独立：每个候选操作能缩小的最大差值只由该元素原值与所在侧决定。
  • 交换论证：若某个方案先用了收益较小的操作，而还有更大收益可用，用大收益替换它不会增加操作数，也不会让已消除的差值变少。
  • 最少前缀：因此最优方案可按收益降序排列。首次让累计收益达到原差值的前缀长度，就是最少操作数。

复杂度

  • 时间：O(m+n)，求和与统计各扫描一次。
  • 空间：O(1)，收益桶长度恒为 6。

边界情况

  • 两数组初始和相等，返回 0。
  • 长度对应的可取和区间不相交，返回 -1。
  • 差值小于最大收益时，最后一次只需部分改变元素。
  • 长度上限为 105，整数和仍在常见 32 位整型范围内。

四种语言完整实现

class Solution {
    public int minOperations(int[] nums1, int[] nums2) {
        if (nums1.length * 6 < nums2.length ||
            nums2.length * 6 < nums1.length) {
            return -1;
        }

        int sum1 = 0, sum2 = 0;
        for (int x : nums1) sum1 += x;
        for (int x : nums2) sum2 += x;
        if (sum1 == sum2) return 0;

        int[] low = nums1, high = nums2;
        if (sum1 > sum2) {
            low = nums2;
            high = nums1;
            int temp = sum1;
            sum1 = sum2;
            sum2 = temp;
        }

        int diff = sum2 - sum1;
        int[] count = new int[6];
        for (int x : low) count[6 - x]++;
        for (int x : high) count[x - 1]++;

        int operations = 0;
        for (int gain = 5; gain >= 1 && diff > 0; gain--) {
            int take = Math.min(count[gain], (diff + gain - 1) / gain);
            operations += take;
            diff -= take * gain;
        }
        return operations;
    }
}

 * @param {number[]} nums1
 * @param {number[]} nums2

var minOperations = function(nums1, nums2) {
    if (nums1.length * 6 < nums2.length ||
        nums2.length * 6 < nums1.length) {
        return -1;
    }

    let sum1 = nums1.reduce((sum, x) => sum + x, 0);
    let sum2 = nums2.reduce((sum, x) => sum + x, 0);
    if (sum1 === sum2) return 0;

    let low = nums1;
    let high = nums2;
    if (sum1 > sum2) {
        [low, high] = [high, low];
        [sum1, sum2] = [sum2, sum1];
    }

    let diff = sum2 - sum1;
    const count = Array(6).fill(0);
    for (const x of low) count[6 - x]++;
    for (const x of high) count[x - 1]++;

    let operations = 0;
    for (let gain = 5; gain >= 1 && diff > 0; gain--) {
        const take = Math.min(count[gain], Math.ceil(diff / gain));
        operations += take;
        diff -= take * gain;
    }
    return operations;
};

public:

        int sum2 = accumulate(nums2.begin(), nums2.end(), 0);
        if (sum1 == sum2) return 0;

        vector<int> *low = &nums1, *high = &nums2;
        if (sum1 > sum2) {

            swap(sum1, sum2);

            operations += take;

替代方案：排序所有收益

  • 构造所有正收益后降序排序，再逐个消除差值。
  • 逻辑直观，但时间为 O((m+n) log(m+n))，空间为 O(m+n)。
  • 由于收益只有 1～5，计数桶更简洁高效。

常见错误

  • 只考虑增加较小和的一侧，漏掉降低较大和的一侧。
  • 把元素值本身当作收益；正确收益是 6-x 或 x-1。
  • 最后一次操作必须把收益用满；其实只要让差值归零即可。
  • 忽略长度区间不相交的无解情况。

面试追问

为什么不需要记录每次改成的具体值？

题目只问最少次数。对一个收益上限为 g 的元素，它可以贡献 1 到 g 的任意整数，因此最后一步可精确补齐剩余差值，无须预先构造终态数组。

如果数值范围从 1～6 改成 1～K 呢？

思路不变：小和侧收益为 K-x，大和侧收益为 x-1。若 K 较小可用大小为 K 的桶；若 K 很大，可排序收益或用有序映射。

能否真的输出一组修改方案？

可以。统计收益时同时保存元素的数组归属和下标；按收益从大到小选择，并把前几步改到极值，最后一步只调整剩余差值。
