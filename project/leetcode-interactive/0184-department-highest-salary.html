    04 / SQL solution

    题解默认隐藏

    展开后查看洞察、过程、边界、复杂度、方言与追问。

    Solution unlocked

    先聚合，再按键回连

    最大薪资只是“值”；要找出所有员工，必须用 (departmentId, max_salary) 回连明细行。

    核心洞察与完整过程

    1. 按 departmentId 对 Employee 分组。
    2. 为每组计算 MAX(salary)。
    3. 用部门 ID 与最高薪资同时回连 Employee，保留所有并列员工。
    4. 再连接 Department，把 ID 翻译为部门名。
    5. 投影并精确命名 Department / Employee / Salary；顺序任意。

    复杂度、边界与取舍

    设员工行数为 E、部门行数为 D。哈希聚合与连接的期望时间约 O(E + D)，中间最大值映射空间约 O(D)；真实代价由索引、统计信息和执行计划决定。

    • 并列最高必须全部返回；不要用 ROW_NUMBER 只选一行。
    • 没有员工的部门不会产生结果，因为题目寻找的是员工。
    • 窗口函数 RANK() OVER (PARTITION BY ...) 更直观，但可能给每行计算排名。
    • 相关子查询短小，却可能在不良计划下重复计算分组最大值。

    四种 SQL 方言

    这是 Database 题，提供 MySQL 主提交与等价 SQL 方言；Java、JavaScript、Python、C++ 不是本题 SQL Schema 的提交语言，不伪装成可提交答案。 

    WITH department_max AS (
  SELECT departmentId, MAX(salary) AS max_salary
  FROM Employee
  GROUP BY departmentId
)
SELECT d.name AS Department,
       e.name AS Employee,
       e.salary AS Salary
FROM Employee AS e
JOIN department_max AS m
  ON m.departmentId = e.departmentId
 AND m.max_salary = e.salary
JOIN Department AS d
  ON d.id = e.departmentId;

    面试追问

    • 为何 RANK 能保留并列，而 ROW_NUMBER 不能？
    • 如何改成每部门前 3 个不同薪资？
    • 该给哪些连接键建立索引？
    • salary 允许 NULL 时 MAX 的语义是什么？

    常见错误

    • 只 GROUP BY 部门却直接选择员工名。
    • 只按 salary 回连，串入其他部门同薪员工。
    • 用 LIMIT 1 或 ROW_NUMBER 丢失并列者。
    • 使用 LEFT JOIN 误输出空部门。
    • 遗漏规定的输出别名。
