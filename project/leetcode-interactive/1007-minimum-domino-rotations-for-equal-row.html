Minimum Domino Rotations For Equal Row

先观察，再推导。 下面的候选数字扫描器会展示“为什么只需检查极少的候选值”，但完整题解默认收起。

题目

一排多米诺骨牌中，第 i 张牌的上、下两半分别为 tops[i] 与 bottoms[i]，数值范围为 1 到 6。你可以旋转任意一张牌，使它的上下值交换。

求让上面一整行全部相同，或让下面一整行全部相同所需的最少旋转次数；若无法做到，返回 -1。

函数签名

minDominoRotations(tops: integer[], bottoms: integer[]) → integer

示例 1

输入：tops = [2,1,2,4,2,2]
      bottoms = [5,2,6,2,3,2]
输出：2
解释：旋转第 2、4 张牌（下标 1、3），
      可使 tops 全部变为 2。

示例 2

输入：tops = [3,5,1,2,3]
      bottoms = [3,6,3,3,4]
输出：-1
解释：不存在能覆盖每张牌的统一数字。

约束

  • 2 ≤ tops.length ≤ 2 × 10⁴
  • bottoms.length == tops.length
  • 1 ≤ tops[i], bottoms[i] ≤ 6

候选值通行证

逐张检查数字 2 能否穿过整排，并同步累计让上行或下行统一的代价。

准备
候选值来自第一张牌。按“下一步”开始检查。
目标值：2
统一 tops 的旋转数：0
统一 bottoms 的旋转数：0

完整题解

核心洞察：最终统一的数字必定出现在第一张牌上，因此候选至多是 tops[0] 与 bottoms[0]。

过程

  1. 选择一个候选值 x。
  2. 扫描每张牌。如果上下两面都不是 x，这个候选立即失败。
  3. 若上面不是 x，要让 tops 统一就必须旋转该牌；累计 rotateTop。
  4. 若下面不是 x，要让 bottoms 统一就必须旋转该牌；累计 rotateBottom。
  5. 候选可行时，代价为两种统一方向的较小值。分别尝试第一张牌的两个值并取最小。

正确性证明

候选完备性：若最终某一行统一为 x，第一张牌在旋转前后的该位置必来自它原有的上面或下面，所以 x 必为 tops[0] 或 bottoms[0]。

单候选最优性：固定 x 和目标行为 tops 后，每张 tops 不是 x 的牌都必须旋转，而 tops 已是 x 的牌无需旋转；计数恰好是必要且充分的最少次数。bottoms 同理。若某张牌不含 x，任何旋转都无法让它贡献 x，故判失败正确。

整体最优性：算法穷尽了所有可能的统一值，并对每个值计算上下两种目标行的最优代价，因此返回全局最小值；若均失败，则答案为 -1。

边界情况

  • 某一行起初已统一，答案为 0。
  • 第一张牌上下相同，只需检查一次该候选。
  • 扫描中出现一张不含候选值的牌，应立即淘汰候选。
  • 多个方向可行时必须取较小旋转数。

复杂度

至多扫描数组两次，时间复杂度 O(n)；只维护常数个计数器，额外空间 O(1)。

替代方案

可以统计 1～6 在上下两面的覆盖次数以及各自行内频次，再计算答案。它同样是 O(n)，但状态更多；直接验证两个候选更精炼。

面试追问

  • 为什么不能只尝试出现次数最多的数字？因为频次不等于逐牌覆盖。
  • 若牌面数字不再限制为 1～6，算法是否变化？不变，候选完备性仍来自第一张牌。
  • 如何返回具体旋转下标？在最优候选和方向确定后再扫描一次收集必旋转位置。

常见错误

  • 只计算统一 tops，漏掉统一 bottoms 的更优答案。
  • 将某个候选在上下两行的总出现次数当作可行性；同一张牌重复出现不能补偿另一张牌缺失。
  • 用 0 代表候选失败，和“无需旋转”的合法答案混淆。

四语言实现

class Solution {
    public int minDominoRotations(int[] tops, int[] bottoms) {
        int a = check(tops[0], tops, bottoms);
        int b = check(bottoms[0], tops, bottoms);
        if (a == -1) return b;
        if (b == -1) return a;
        return Math.min(a, b);
    }

    private int check(int x, int[] tops, int[] bottoms) {
        int rotateTop = 0, rotateBottom = 0;
        for (int i = 0; i < tops.length; i++) {
            if (tops[i] != x && bottoms[i] != x) return -1;
            if (tops[i] != x) rotateTop++;
            if (bottoms[i] != x) rotateBottom++;
        }
        return Math.min(rotateTop, rotateBottom);
    }
}

class Solution:
    def minDominoRotations(self, tops: List[int], bottoms: List[int]) -> int:
        def check(x: int) -> int:
            rotate_top = 0
            rotate_bottom = 0
            for top, bottom in zip(tops, bottoms):
                if top != x and bottom != x:
                    return -1
                rotate_top += top != x
                rotate_bottom += bottom != x
            return min(rotate_top, rotate_bottom)

        a = check(tops[0])
        b = check(bottoms[0])
        if a == -1:
            return b
        if b == -1:
            return a
        return min(a, b)
