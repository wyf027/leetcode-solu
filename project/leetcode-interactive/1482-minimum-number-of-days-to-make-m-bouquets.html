制作 m 束花所需的最少天数

Minimum Number of Days to Make m Bouquets

数组二分查找相邻分组非付费题

01题目

给定整数数组 bloomDay，以及整数 m 和 k。花园中第 i 朵花在第 bloomDay[i] 天盛开。

你要制作 m 束花，每束必须使用花园里连续相邻的 k 朵已盛开的花；每朵花至多属于一束花。返回至少等待多少天才能完成。如果无论等多久都无法完成，返回 -1。

函数形式： minDays(bloomDay, m, k) → integer

官方示例

示例 1
输入：bloomDay = [1,10,3,10,2], m = 3, k = 1
输出：3
解释：第 3 天的状态为 [开, 未开, 开, 未开, 开]，
恰好能制作 3 束、每束 1 朵的花束。
示例 2
输入：bloomDay = [1,10,3,10,2], m = 3, k = 2
输出：-1
解释：需要 3 × 2 = 6 朵花，花园却只有 5 朵。
示例 3
输入：bloomDay = [7,7,7,7,12,7,7], m = 2, k = 3
输出：12
解释：第 7 天只有一段长度 4 和一段长度 2，
只能做 1 束；第 12 天全部盛开，可以做 2 束。
示例 4
输入：bloomDay = [1000000000,1000000000], m = 1, k = 1
输出：1000000000
解释：必须等到第 1000000000 天才有花可用。
示例 5
输入：bloomDay = [1,10,2,9,3,8,4,7,5,6], m = 4, k = 2
输出：9

约束

  • bloomDay.length == n
  • 1 ≤ n ≤ 105
  • 1 ≤ bloomDay[i] ≤ 109
  • 1 ≤ m ≤ 106
  • 1 ≤ k ≤ n

04完整题解

核心洞察

固定一个等待天数 day 后，每朵花只有“已开”或“未开”两种状态。一次从左到右扫描，就能数出最多可做多少束花。如果第 day 天可行，那么更晚的任意一天也一定可行；如果不可行，更早的任意一天也不可行。可行性随天数单调，因此可以在天数范围上二分查找第一个可行值。

完整过程

  1. 先用 m × k > n 判断总花数是否不足。乘法应使用足够大的整数类型，避免溢出。
  2. 令搜索下界为数组最小值，上界为数组最大值。
  3. 检查某一天时，维护当前连续盛开数 consecutive。遇到未开的花就清零；达到 k 时完成一束并清零，确保花不会重复使用。
  4. 若候选日能做至少 m 束，将右边界收至候选日；否则将左边界移到候选日的下一天。
  5. 当左右边界相遇时，该值就是第一个可行天数。

正确性证明

引理 1：扫描得到固定日期下的最大花束数

每个连续盛开区间长度为 len 时，最多能贡献 floor(len / k) 束。扫描每积累 k 朵就立即切出一束并把计数归零，恰好得到这个数量；未开的花会切断区间。因此扫描结果是所有区间可制作花束数之和，也是最大值。

引理 2：可行性关于天数单调

若某朵花在第 d 天已开，则在任意 d' > d 时仍然已开。延后日期不会破坏已有的相邻盛开区间，所以第 d 天可行必推出更晚日期可行。

定理：算法返回最少可行天数

二分过程中，最少可行天数始终位于闭区间 [low, high]。候选日可行时，根据引理 2 可安全丢弃其右侧并保留候选日本身；不可行时可丢弃候选日及其左侧。区间最终收缩为一个值，该值可行，且所有更小值都不可行，所以它正是答案。

边界情况

  • m × k > n：直接返回 -1。
  • k = 1：相邻限制退化为选择任意已开的单朵花。
  • 所有花同一天开：答案就是该天，前提是总花数足够。
  • 花期值可达 10^9，不能按天逐日模拟。
  • 连续计数凑满一束后必须归零，避免一朵花被两束重复使用。

复杂度

设 n 为花朵数，花期跨度为 R = max(bloomDay) - min(bloomDay) + 1。每次可行性检查耗时 O(n)，二分检查 O(log R) 次，总时间 O(n log R)；仅使用常数个变量，额外空间 O(1)。

替代方案

  • 在排序后的不同花期上二分：先复制、排序并去重所有花期，再二分索引。检查次数可能减少，但增加 O(n log n) 预处理和 O(n) 空间，通常不如直接二分值域简洁。
  • 并查集按花期激活：按天从早到晚激活花朵并维护连续段贡献。可以做到接近 O(n log n)；状态更新与重复日期处理更复杂，不是本题首选。
  • 逐日枚举：在花期最大值可达 10^9 时不可接受。

class Solution {
    public int minDays(int[] bloomDay, int m, int k) {
        if ((long) m * k > bloomDay.length) return -1;

        int low = bloomDay[0], high = bloomDay[0];
        for (int day : bloomDay) {
            low = Math.min(low, day);
            high = Math.max(high, day);
        }

        while (low < high) {
            int mid = low + (high - low) / 2;
            if (canMake(bloomDay, m, k, mid)) {
                high = mid;
            } else {
                low = mid + 1;
            }
        }
        return low;
    }

    private boolean canMake(int[] bloomDay, int m, int k, int day) {
        int bouquets = 0;
        int consecutive = 0;
        for (int bloom : bloomDay) {
            if (bloom <= day) {
                consecutive++;
                if (consecutive == k) {
                    bouquets++;
                    if (bouquets == m) return true;
                    consecutive = 0;
                }
            } else {
                consecutive = 0;
            }
        }
        return false;
    }
}

var minDays = function(bloomDay, m, k) {
    if (m * k > bloomDay.length) return -1;

    let low = Math.min(...bloomDay);
    let high = Math.max(...bloomDay);

    const canMake = (day) => {
        let bouquets = 0;
        let consecutive = 0;
        for (const bloom of bloomDay) {
            if (bloom <= day) {
                consecutive++;
                if (consecutive === k) {
                    bouquets++;
                    if (bouquets === m) return true;
                    consecutive = 0;
                }
            } else {
                consecutive = 0;
            }
        }
        return false;
    };

    while (low < high) {
        const mid = low + Math.floor((high - low) / 2);
        if (canMake(mid)) high = mid;
        else low = mid + 1;
    }
    return low;
};

class Solution:
    def minDays(self, bloomDay: List[int], m: int, k: int) -> int:
        if m * k > len(bloomDay):
            return -1

        def can_make(day: int) -> bool:
            bouquets = 0
            consecutive = 0
            for bloom in bloomDay:
                if bloom <= day:
                    consecutive += 1
                    if consecutive == k:
                        bouquets += 1
                        if bouquets == m:
                            return True
                        consecutive = 0
                else:
                    consecutive = 0
            return False

        low, high = min(bloomDay), max(bloomDay)
        while low < high:
            mid = low + (high - low) // 2
            if can_make(mid):
                high = mid
            else:
                low = mid + 1
        return low

        if (1LL * m * k > static_cast<long long>(bloomDay.size())) {
            return -1;
        }

        int low = *min_element(bloomDay.begin(), bloomDay.end());

面试追问

  • 为什么二分天数而不是数组下标？ 因为目标是找最小可行的答案值，可行性在答案值上单调；花园原顺序还必须保留，用于判断相邻性。
  • 搜索边界能否写成 1 到 109？ 可以，但用实际最小和最大花期边界更紧，也更能表达不变量。
  • 如何把条件改成每束至少 k 朵？ 若花不可重复且多余花没有额外收益，仍可每满 k 朵切一束，判断逻辑不变。
  • 若花可以重复使用呢？ 题意和计数模型都会改变；当前达到 k 后清零正是用于保证不重复。

常见错误

  • 只统计已开的总花数，忽略花必须相邻。
  • 在未开花处没有把连续计数清零。
  • 完成一束后未清零，导致花束重叠。
  • 二分更新写成 high = mid - 1，却仍使用“左右相遇”模板，最终错过候选答案。
  • 在 Java/C++ 中直接用 32 位整数计算 m × k，发生溢出。
