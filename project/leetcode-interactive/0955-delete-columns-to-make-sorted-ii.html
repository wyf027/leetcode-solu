删列造序 II

Delete Columns to Make Sorted II

别急着找答案：先试着判断，一列字符出现逆序时，它是否一定要被删除？

题目

给定 n 个等长小写字符串 strs。你可以选若干列，并在每个字符串中同步删除这些列。求最少删除多少列，才能使剩余字符串满足 strs[0] ≤ strs[1] ≤ … ≤ strs[n-1] 的字典序。

比较的是字符串数组中相邻的行，不要求每一行内部的字符递增。

示例 1

输入：strs = ["ca","bb","ac"]
输出：1
解释：删除第 0 列后得到 ["a","b","c"]。

示例 2

输入：strs = ["xc","yb","za"]
输出：0
解释：原数组已经按字典序排列。

示例 3

输入：strs = ["zyx","wvu","tsr"]
输出：3
解释：每一列都必须删除。

约束

  • n == strs.length
  • 1 ≤ n ≤ 100
  • 1 ≤ strs[i].length ≤ 100
  • 所有字符串等长且仅含小写英文字母

题解：锁定已经排好序的相邻对

核心洞察

从左到右扫描列。对相邻行 i-1, i，一旦某个已保留列满足前者字符更小，这一对的字典序就永久确定，后面的列不再能破坏它。只有尚未确定的相邻对需要继续检查。

完整过程

  1. 用 fixed[i] 表示相邻行 i-1 与 i 是否已由更早的保留列确定为严格递增。
  2. 考察第 c 列：若存在未确定的行对且 strs[i-1][c] > strs[i][c]，这一列会制造无法挽回的逆序，必须删除；状态不变。
  3. 否则保留该列，并把所有满足 strs[i-1][c] < strs[i][c] 的未确定行对标记为已确定。
  4. 扫描结束后返回删除列数。

为什么正确

必须性：若当前列在某个未确定行对上下降，那么两行此前所有保留字符都相等；保留该列将让前一行字典序更大，后续字符无法改变首次差异，因此任何合法方案都必须删除此列。

安全性：若当前列没有使任何未确定行对下降，则保留它不会破坏已有顺序；其中严格上升的行对会被永久确定。算法只删除必删列，所以删除数最小。

边界情况

  • 只有一行：没有相邻约束，答案为 0。
  • 所有行相同：每列都可保留。
  • 首列已严格递增：所有相邻对立即确定，后续列都无需删除。
  • 每列都让至少一个未确定行对逆序：删除所有列。

复杂度

设行数为 n、列数为 m。时间复杂度 O(nm)，额外空间复杂度 O(n)。

替代方案

可以维护每行删除后的前缀字符串并逐列尝试，但反复构造和比较字符串通常达到 O(nm²)，也更容易写错。布尔状态正好压缩了我们真正需要的信息。

面试追问

  • 为何只检查相邻行？因为非降序是传递关系，相邻约束全部成立即可。
  • 为何发现逆序后不能靠删除早先列补救？算法已经证明当前列是在早先保留前缀相等的行对上首次产生差异；保留它必然非法。
  • 能否提前结束？所有相邻对都已确定后可直接结束，剩余列全部保留。

常见错误

  • 把题意误解成要求每一行内部有序。
  • 对已经确定顺序的行对继续检查，误删后续列。
  • 决定删除当前列后仍更新 fixed，污染状态。

完整代码

class Solution {
    public int minDeletionSize(String[] strs) {
        int n = strs.length, m = strs[0].length(), deleted = 0;
        boolean[] fixed = new boolean[n - 1];
        for (int c = 0; c < m; c++) {
            boolean bad = false;
            for (int i = 1; i < n; i++)
                if (!fixed[i - 1] && strs[i - 1].charAt(c) > strs[i].charAt(c)) bad = true;
            if (bad) { deleted++; continue; }
            for (int i = 1; i < n; i++)
                if (strs[i - 1].charAt(c) < strs[i].charAt(c)) fixed[i - 1] = true;
        }
        return deleted;
    }
}
