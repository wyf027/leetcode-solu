Problem

题意

任务描述

一位节食者第 i 天摄入 calories[i] 卡路里。给定整数 k，需要依次考察数组中每一段长度恰好为 k 的连续天数。

对于起点 i，记这一段的总热量为 T = calories[i] + … + calories[i+k-1]：

  • 若 T < lower，表现不佳，积分减 1。
  • 若 T > upper，表现良好，积分加 1。
  • 否则（含等于边界），表现正常，积分不变。

积分从 0 开始。考察完所有 n - k + 1 个连续片段后返回总积分；结果可以为负数。

Ready for the reasoning?

先想一想，再揭晓题解

你能否只更新“离开的一天”和“进入的一天”，而不重复计算整个周期？

Solution · Sliding Window

滑动窗口：复用相邻周期的总和

核心洞察

相邻两个长度为 k 的周期共享 k − 1 天。窗口右移时，只需减去离开的 calories[i-k]，再加上新进入的 calories[i]，就能在常数时间得到新总和。

完整过程

  1. 累加前 k 天，得到第一个窗口总和 sum。
  2. 将 sum 与 lower、upper 比较，更新积分。
  3. 从下标 k 开始右移：执行 sum += calories[i] - calories[i-k]。
  4. 每得到一个新窗口总和，就按相同规则更新积分。
  5. 处理完最后一个窗口后返回积分。

以示例 3 为例

[6,5]：sum = 11 > 5，score = 1。

[5,0]：sum = 11 − 6 + 0 = 5，score = 1。

[0,0]：sum = 5 − 5 + 0 = 0 < 1，score = 0。

每次移动只做一次减法和一次加法，没有重新遍历窗口。

Correctness

正确性说明

1 · 初始成立

初始化显式累加 calories[0..k-1]，所以 sum 正好等于第一个长度为 k 的周期总热量。

2 · 移动保持

假设 sum 是前一窗口之和。减去唯一离开的元素、加上唯一进入的元素后，它恰好成为下一窗口之和。

3 · 计分完整

算法从第一个到最后一个窗口各访问一次，并对准确的窗口和应用唯一一条计分规则，因此返回值就是所有周期的总积分。

时间复杂度O(n)

初始化 O(k)，随后处理 n − k 次移动，总计 O(n)。

额外空间O(1)

除几个整数变量外，不随输入规模增长。

边界情况

  • k = 1：每一天独立计分。
  • k = n：只评估整个数组一次。
  • T = lower 或 T = upper：都不加不减。
  • 所有窗口都偏低时，最终积分可以为负数。
  • 所有热量均为 0 时，仍按给定边界判断。

替代方案：前缀和

先构建 prefix[i+1] = prefix[i] + calories[i]，每个窗口和为 prefix[i+k] - prefix[i]。

它同样是 O(n) 时间，但需要 O(n) 额外空间。若还要回答许多不同区间或不同 k 的求和查询，前缀和更通用；本题只扫描一次，滑动窗口更精简。

常见错误

  • 把等于 lower 或 upper 误判为减分或加分；题目要求严格小于、严格大于。
  • 遗漏第一个窗口，或循环边界少处理最后一个窗口；窗口总数应为 n - k + 1。
  • 右移时减错元素：在新元素下标为 i 时，离开的是 i - k。
  • 对每个起点重新求和，退化为 O(nk)，在 n = 105 时可能超时。
  • 忽略答案可能为负数，或把积分错误地限制为非负。

Implementations

四种语言完整代码

Java · LeetCode 提交格式
class Solution {
    public int dietPlanPerformance(
            int[] calories, int k, int lower, int upper) {
        long windowSum = 0;
        for (int i = 0; i < k; i++) {
            windowSum += calories[i];
        }

        int score = evaluate(windowSum, lower, upper);

        for (int i = k; i < calories.length; i++) {
            windowSum += calories[i];
            windowSum -= calories[i - k];
            score += evaluate(windowSum, lower, upper);
        }

        return score;
    }

    private int evaluate(long sum, int lower, int upper) {
        if (sum < lower) {
            return -1;
        }
        if (sum > upper) {
            return 1;
        }
        return 0;
    }
}

Python · LeetCode 提交格式
from typing import List


class Solution:
    def dietPlanPerformance(
        self,
        calories: List[int],
        k: int,
        lower: int,
        upper: int,
    ) -> int:
        def evaluate(total: int) -> int:
            if total < lower:
                return -1
            if total > upper:
                return 1
            return 0

        window_sum = sum(calories[:k])
        score = evaluate(window_sum)

        for i in range(k, len(calories)):
            window_sum += calories[i] - calories[i - k]
            score += evaluate(window_sum)

        return score

#include <vector>
using namespace std;

class Solution {
public:
    int dietPlanPerformance(
        vector<int>& calories,
        int k,
        int lower,
        int upper
    ) {
        long long windowSum = 0;
        for (int i = 0; i < k; ++i) {
            windowSum += calories[i];
        }

        int score = evaluate(windowSum, lower, upper);

        for (int i = k; i < static_cast<int>(calories.size()); ++i) {
            windowSum += calories[i] - calories[i - k];
            score += evaluate(windowSum, lower, upper);
        }

        return score;
    }

private:
    int evaluate(long long sum, int lower, int upper) {
        if (sum < lower) return -1;
        if (sum > upper) return 1;
        return 0;
    }
};

Interview follow-ups

面试追问

如果 k 会频繁变化，怎么办？

预处理前缀和。每个指定起点和长度的区间和都能 O(1) 得到；若每次仍需枚举全部起点，单次查询仍是 O(n)。

如果 calories 是实时数据流呢？

用长度为 k 的队列保存当前窗口。每来一个值就入队并加入总和，队列超过 k 时弹出最旧值并从总和中减去；窗口装满后即可在线计分。

能否并行计算？

前缀和方案更容易分段并行，但本题的线性扫描已是最优数量级；并行开销通常不值得。超大离线数据可分块并处理块边界。

怎样避免整数溢出？

官方约束下最大窗口和为 2×10⁹，仍在 32 位有符号整数范围内；工程代码使用 64 位累加类型可以更稳健地应对约束变化。
