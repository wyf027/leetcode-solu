质数排列Prime Arrangements

把 1 到 n 放进同样多的座位中：所有质数都必须坐在质数编号的座位。先读懂规则，再用实验台观察排列结构。

简单题号 1175非付费题1-based 索引
Problem

题目要求

准确转述

给定整数 n，将 1 到 n 的每个整数恰好使用一次组成排列。要求排列中的每个质数都出现在质数索引上（索引从 1 开始）。返回符合条件的排列数量；答案对 109 + 7 取模。

质数：大于 1，且不能表示为两个都小于它的正整数之积。注意，1 不是质数。

约束与签名

  • 1 <= n <= 100
  • 函数：numPrimeArrangements(n)
  • 参数：n: integer
  • 返回：integer
示例 1

输入：n = 5
输出：12

例如 [1,2,5,4,3] 有效；[5,2,3,4,1] 无效，因为质数 5 位于非质数索引 1。

输入：n = 100
输出：682289015

Complete Solution

分组计数：两个阶乘相乘

核心洞察：设 p 是不超过 n 的质数个数。1 到 n 中恰有 p 个质数，同时 1 到 n 的索引中也恰有 p 个质数索引。因此质数内部任意排列有 p! 种，其余数字内部任意排列有 (n-p)! 种，答案是 p! × (n-p)! mod M。

完整过程

  1. 用埃氏筛标记区间 [2,n] 中的质数，并统计数量 p。
  2. 把 p 个质数一一放入 p 个质数索引，共有 p! 种放法。
  3. 把剩余 n-p 个非质数放入其余位置，共有 (n-p)! 种放法。
  4. 两个选择相互独立，按乘法原理相乘，并在每次乘法后对 M 取模。

边界与复杂度

  • n = 1：p = 0，答案为 0! × 1! = 1。
  • 1 归入“非质数”组，不能误判。
  • 筛法时间：O(n log log n)。
  • 阶乘时间：O(n)；总空间：O(n)。
  • Java / C++ 乘法必须使用 64 位整数承接中间值。

正确性证明

引理 1：任意合法排列中，p 个质数必须恰好占满 p 个质数索引。因为二者数量相同，而题目禁止质数出现在其他索引。

引理 2：剩余 n-p 个非质数必须恰好占满剩余 n-p 个非质数索引；质数位置已被全部占用。

计数：由引理 1，质数到质数索引的双射有 p! 个；由引理 2，非质数到非质数索引的双射有 (n-p)! 个。两类选择互不干扰，乘法原理给出 p! × (n-p)!。算法恰好计算该值，故返回结果正确。

替代方案

逐个试除：对每个 x 检查 2 到 √x 是否有因子。实现更短，复杂度约 O(n√n)；由于 n ≤ 100 也完全可行。筛法更能体现批量求质数的通用方法。

常见错误

  • 把 1 当成质数。
  • 只计算 p!，漏掉非质数的排列。
  • 用 0-based 数组索引理解题目的 1-based 位置。
  • 最后才取模，导致固定宽度整数溢出。

class Solution {
    private static final long MOD = 1_000_000_007L;

    public int numPrimeArrangements(int n) {
        boolean[] isPrime = new boolean[n + 1];
        java.util.Arrays.fill(isPrime, true);
        if (n >= 0) isPrime[0] = false;
        if (n >= 1) isPrime[1] = false;

        for (int i = 2; i * i <= n; i++) {
            if (isPrime[i]) {
                for (int multiple = i * i; multiple <= n; multiple += i) {
                    isPrime[multiple] = false;
                }
            }
        }

        int primeCount = 0;
        for (int value = 2; value <= n; value++) {
            if (isPrime[value]) primeCount++;
        }

        return (int) (factorial(primeCount) * factorial(n - primeCount) % MOD);
    }

    private long factorial(int value) {
        long result = 1L;
        for (int i = 2; i <= value; i++) {
            result = result * i % MOD;
        }
        return result;
    }
}

面试追问

为什么质数数量等于质数索引数量？

值域与索引域都是同一个集合 {1, 2, …, n}。判断“是否为质数”的规则相同，因此两边质数元素的数量天然一致。

如果规则改成“质数只能在偶数索引”呢？

先比较质数个数 p 与偶数位置数 floor(n/2)。若 p 更大则无解；否则还要选择 p 个偶数位置，再排列质数，并排列其余数字，计数结构会多出组合数。

能否只用 O(1) 额外空间？

可以逐个试除判断每个数是否为质数，只维护计数，额外空间 O(1)；在本题 n ≤ 100 时性能足够。
