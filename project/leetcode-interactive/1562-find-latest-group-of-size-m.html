查找大小为 M 的
最新分组

灯泡依次点亮，相邻的光连成组。你要找的不是“最长”，而是最后一次仍存在长度恰好为 m 的完整光带。

MEDIUM数组哈希表模拟非付费题
01 / Brief

题目档案

官方签名：findLatestStep

给定一个由 1..n 构成的排列 arr。长度为 n 的二进制串初始全为 0；第 i 步把位置 arr[i] 设为 1。

一组 1 指不能再向左或向右延伸的连续 1。返回最后一个仍存在长度恰好为 m的组的步骤；如果从未出现，返回 -1。

判断重点：长度为 m 的连续片段若嵌在更长的一组 1 中，不算“大小为 m 的组”。必须检查完整连通分组的长度。

函数参数

findLatestStep(arr: integer[], m: integer) → integer

约束

  • n == arr.length
  • 1 ≤ n ≤ 10⁵
  • 1 ≤ m ≤ n
  • 1 ≤ arr[i] ≤ n
  • arr 中所有整数互不相同
规模信号：n 达 10⁵，逐步扫描整个字符串会退化为 O(n²)。
示例 1
输入：arr = [3,5,1,2,4], m = 1
输出：4
说明：第 4 步仍有一个独立的 "1"；第 5 步只剩 "11111"。
示例 2
输入：arr = [3,1,5,4,2], m = 2
输出：-1

示例 3
输入：arr = [1], m = 1
输出：1

示例 4
输入：arr = [2,1], m = 2
输出：2

04 / Solution

只记录分组的两端

O(n) 时间 · O(n) 空间
核心洞察：新位置 p 被点亮时，它只可能连接左邻组和右邻组。我们无需保存组内每个位置的长度，只要在每组的左右端点保存该组长度，就能 O(1) 得到左右长度并更新。
STEP 01

读边界

令 left = len[p-1]、right = len[p+1]。哨兵位置 0 与 n+1 初始为 0。

STEP 02

更新组数账本

若 left 或 right 等于 m，相应旧组将被吞并，先把长度 m 的组数减一。

STEP 03

写新边界

新长度 size=left+1+right，写入新组左右端点；若 size=m，组数加一。

完整过程

初始化

创建长度 n+2 的 len 数组，全部为 0；groupsM=0，answer=-1。

按 arr 顺序点亮

第 step 步处理 p=arr[step-1]，读取相邻分组长度 left 与 right。

移除被合并的旧组贡献

left==m 就令 groupsM--；right==m 也同理。左右组不同，不会重复扣同一组。

建立合并后的组

计算 size，并令 len[p-left]=len[p+right]=size。也可写 len[p]，但算法后续只依赖端点。

记录最新步骤

若 size==m，令 groupsM++。只要 groupsM>0，就把 answer 更新为当前 step。

正确性证明

不变式：每步结束后，每个 1 分组的两个端点在 len 中都保存该组的准确长度，且 groupsM 等于长度恰为 m 的分组数量。

初始时没有分组，不变式成立。点亮 p 时，唯一受影响的是其左右相邻分组；先移除它们对 groupsM 的贡献，再将二者与 p 合并，并把新长度写到新端点。其他组未改变，因此不变式继续成立。于是 groupsM>0 当且仅当当前存在目标组；算法每次覆盖 answer，最终得到最后一步。

复杂度与边界

  • 时间：每个位置只处理一次，O(n)。
  • 空间：边界长度数组占 O(n)。
  • m=n：只有最终全亮时答案为 n。
  • n=1：哨兵让左右读取仍然安全。
  • 左右组长度都为 m：需要分别减一，因为确有两个旧组。

四语言完整实现

Java · LeetCode 可提交
class Solution {
    public int findLatestStep(int[] arr, int m) {
        int n = arr.length;
        int[] len = new int[n + 2];
        int groupsM = 0;
        int answer = -1;

        for (int step = 1; step <= n; step++) {
            int p = arr[step - 1];
            int left = len[p - 1];
            int right = len[p + 1];

            if (left == m) groupsM--;
            if (right == m) groupsM--;

            int size = left + 1 + right;
            len[p - left] = size;
            len[p + right] = size;

            if (size == m) groupsM++;
            if (groupsM > 0) answer = step;
        }
        return answer;
    }
}

        answer = -1

            if size == m:
                groups_m += 1
            if groups_m > 0:
                answer = step

        return answer

替代方案

反向删除：从全 1 开始逆序把位置变 0，维护剩余区间。可用有序集合或并查集变体，但实现更绕，JavaScript 中有序集合也不原生。

记录每个长度的最后时刻：同样基于边界合并，可维护 count[size]；本题只问一个 m，单独的 groupsM 更简洁。

常见错误

  • 只检查 size==m，忘记旧的 m 组可能仍存在。
  • 合并前没有把左右旧组从 groupsM 扣除。
  • 把“含有 m 个连续 1”误解为“完整组恰好为 m”。
  • 每一步重新扫描字符串，导致 O(n²)。
  • 数组没留两格哨兵，边界访问越界。

面试追问

为什么只写左右端点也够？

未来只有紧贴分组外侧的新位置会查询它；查询位置正好是该组端点。内部值永远不会被用作相邻组长度。

可以做到 O(1) 额外空间吗？

一般不能直接做到，因为需要区分尚未点亮的位置并快速获得相邻组长度；输入排列本身也不能安全承担全部边界状态而不破坏处理顺序。

如果要回答多个不同的 m 呢？

可维护每种长度的组数与其最后出现步骤，或离线记录每次组长度计数从 0 与非 0 之间切换的时刻，再回答查询。
