最短补全词

Shortest Completing Word

从一块混有字母、数字与空格的车牌中提取字母要求，再从候选单词中找出最短的补全者。 先读题并亲手推进检查流程；完整思路在页面底部单独揭晓。

01 / Problem

题意与规则

你需要返回什么？

给定字符串 licensePlate 和字符串数组 words，返回 words 中的最短补全词。

“补全词”必须包含车牌中的全部字母：车牌里的数字和空格不参与匹配，字母不区分大小写； 同一个字母若出现多次，候选词中也至少要出现相同次数。

答案保证存在。若多个补全词长度同为最短，返回它们在 words 中最先出现的一个。

函数参数

shortestCompletingWord(licensePlate, words) → string
  • licensePlate：待提取字母要求的车牌字符串。
  • words：候选小写英文单词数组。
  • 返回值：满足全部频次要求的最短单词。
官方示例 1
输入：licensePlate = "1s3 PSt", words = ["step", "steps", "stripe", "stepple"]
输出："steps"
解释：车牌需要 2 个 s、1 个 p、1 个 t。只有 steps 全部满足。
官方示例 2
输入：licensePlate = "1s3 456", words = ["looks", "pest", "stew", "show"]
输出："pest"
解释：只要求字母 s。三个长度为 4 的最短候选都满足，返回最先出现的 pest。

04 / Solution

题解：26 位字母频次数组

核心洞察

匹配关心的不是字母顺序，而是每个字母至少出现多少次。英文字母只有 26 个， 因而可以把车牌和候选词都压缩为长度为 26 的频次数组。

只要候选词对每个字母都有 have[i] >= need[i]，它就是补全词。

保持“最先出现”的关键

按原数组顺序扫描，只在新候选词严格更短时更新答案。 长度相等时不更新，自然保留第一个出现的最短补全词。

比较条件应是 word.length < answer.length，而不是小于等于。

完整过程

1. 提取要求遍历车牌，只统计字母，并统一转为小写。
2. 检查候选统计候选词频次，逐项验证是否覆盖车牌要求。
3. 维护最短补全且严格更短时更新；相同长度保持原答案。

还可以提前跳过长度不小于当前答案的单词：它即使是补全词，也不可能取代当前答案， 而相同长度又必须保留先出现者。

正确性证明

  1. 频次数组准确表达要求。
    车牌中数字和空格被忽略，字母统一为小写后计数，因此 need 恰好记录每个字母所需的最少次数。
  2. 匹配判断充要。
    候选词是补全词，当且仅当对所有字母都有 have[i] >= need[i]；逐项比较正好实现这个定义。
  3. 最终答案最短且顺序正确。
    扫描结束时，答案是所有已见补全词中严格最短者；遇到等长者不替换，所以同为最短时保留最先出现者。

复杂度

令 L 为车牌长度，S 为所有候选词长度之和。

时间 O(L + S)每个字符至多被统计一次，26 项比较视为常数。
空间 O(1)使用两个固定长度 26 的数组，与输入规模无关。

边界情况

  • 车牌大小写混合：统一小写后统计。
  • 同一字母重复：必须满足完整频次，不能只判断“是否出现”。
  • 多个最短答案：只在严格更短时更新。
  • 答案较早出现：后续更长或等长单词可以跳过。

替代方案

可以先把候选词按“长度、原下标”排序，再返回第一个满足频次要求的词。 这样思路直观，但排序需要 O(n log n)，还必须保存原下标来处理稳定性； 单次线性扫描更简单、更高效。

也可用哈希表或 Counter 表达频次。可读性不错，但本题字符集固定为 26 个小写英文字母， 固定数组的常数开销更小，也更容易跨语言实现。

class Solution {
    public String shortestCompletingWord(String licensePlate, String[] words) {
        int[] need = new int[26];
        for (char raw : licensePlate.toCharArray()) {
            char ch = Character.toLowerCase(raw);
            if (ch >= 'a' && ch <= 'z') {
                need[ch - 'a']++;
            }
        }

        String answer = null;
        for (String word : words) {
            if (answer != null && word.length() >= answer.length()) {
                continue;
            }

            int[] have = new int[26];
            for (char ch : word.toCharArray()) {
                have[ch - 'a']++;
            }

            boolean completes = true;
            for (int i = 0; i < 26; i++) {
                if (have[i] < need[i]) {
                    completes = false;
                    break;
                }
            }

            if (completes) {
                answer = word;
            }
        }
        return answer;
    }
}

from typing import List


class Solution:
    def shortestCompletingWord(
        self, licensePlate: str, words: List[str]
    ) -> str:
        need = [0] * 26
        for ch in licensePlate.lower():
            if "a" <= ch <= "z":
                need[ord(ch) - ord("a")] += 1

        answer = None
        for word in words:
            if answer is not None and len(word) >= len(answer):
                continue

            have = [0] * 26
            for ch in word:
                have[ord(ch) - ord("a")] += 1

            if all(have[i] >= need[i] for i in range(26)):
                answer = word

        return answer

常见错误

  • 只用集合判断字母存在，丢掉重复次数，例如误判只有一个 s 的 step。
  • 没有忽略数字和空格，或没有统一大小写。
  • 遇到等长补全词仍覆盖答案，破坏“返回第一个”的规则。
  • 为了找最短而排序，却忽略了原始下标的稳定性。

面试追问

  • 若字符集是 Unicode？ 改用按规范化字符键控的哈希表。
  • 若需处理大量车牌查询？ 可预计算每个候选词的频次向量，并按长度建立索引。
  • 能否减少候选统计？ 当前答案已确定后，长度不小于它的候选可直接跳过。
  • 若要返回所有并列答案？ 维护最短长度及结果列表；更短时清空，等长时追加。

06 / Quick Review

快速复盘

为什么不能只判断字母是否出现？

因为车牌中的同一个字母可能重复。比如需要两个 s 时，只有一个 s 的词并不能补全。

为什么相同长度时不能更新答案？

题目要求并列最短时返回数组中最先出现者。顺序扫描并拒绝等长替换，恰好保留先出现的答案。

固定数组为什么算 O(1) 空间？

数组长度始终是 26，不随车牌或单词数量增长，因此渐进空间复杂度是常数。
