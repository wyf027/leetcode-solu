K 件物品的最大和

K Items With the Maximum Sum

先读题，再动手。 首屏只保留问题本身；你可以先形成自己的判断，再用交互推演和底部题解核对。

Problem

题目描述

目标：恰好选择 k 件

一个袋子里只有三类物品，物品上的数字分别是 1 0 −1。

给定四个非负整数 numOnes、numZeros、numNegOnes 和 k。袋中分别有对应数量的 1、0、−1 物品。请从现有物品中恰好选出 k 件，返回所选数字之和能够达到的最大值。

函数形式

kItemsWithMaximumSum(numOnes, numZeros, numNegOnes, k) → integer

约束

  • 0 ≤ numOnes, numZeros, numNegOnes ≤ 50
  • 0 ≤ k ≤ numOnes + numZeros + numNegOnes

返回值

一个整数，表示选满 k 件后可得到的最大总和。

示例 1

输入：numOnes = 3, numZeros = 2, numNegOnes = 0, k = 2

输出：2

袋中是 {1, 1, 1, 0, 0}，取两个 1，和为 2。

示例 2

输入：numOnes = 3, numZeros = 2, numNegOnes = 0, k = 4

输出：3

取三个 1 和一个 0，恰好四件，和为 3。

Solution

贪心：先拿价值更高的物品

三种物品的价值固定为 1、0、−1。为了让恰好 k 件的总和最大，只需按价值从高到低填满名额。

核心洞察

选择一个更小的值而放弃仍可选择的更大值，只会让总和变差。于是先尽量取 1；名额仍未填满时取 0；最后才被迫取 −1。

min(numOnes, k) − max(0, k − numOnes − numZeros)

完整过程

  1. 从 1 类物品中取 min(numOnes, k) 件，并计入同等分数。
  2. 若还缺物品，用 0 类填充；它们不改变分数。
  3. 若穿过 0 类后仍有空位，剩下每件只能是 −1，从分数中扣除其数量。

正确性证明

设某个可行选择没有尽量选择 1，却选择了 0 或 −1。用一个未选的 1 替换它，总件数不变，而总和增加，因此原选择不可能优于替换后的选择。

取完所有可用的 1 后，同理，若仍需填名额，选择 0 总不会比选择 −1 差。重复交换后，任意最优选择都可变为“先 1、再 0、后 −1”的形式且结果不减，所以该贪心策略得到最大和。

边界情况

  • k = 0：不取物品，答案为 0。
  • k ≤ numOnes：全部名额都可由 1 填满。
  • k ≤ numOnes + numZeros：无需选择 −1。
  • 只有负数物品：答案为 −k。
  • 约束保证库存总量至少为 k，无需处理“物品不足”。

复杂度

时间：O(1)

空间：O(1)

公式只执行常数次比较和加减，不需要真的构造或排序物品数组。

替代方案

可以构造全部物品、降序排序后取前 k 件，时间复杂度为 O(n log n)；也可以按三个桶循环取值，时间复杂度为 O(k)。两者都正确，但忽略了值域只有三种这一条件。

Code

四语言提交代码

保持官方函数签名

JavaO(1) / O(1)
class Solution {
    public int kItemsWithMaximumSum(
        int numOnes,
        int numZeros,
        int numNegOnes,
        int k
    ) {
        return Math.min(numOnes, k)
            - Math.max(0, k - numOnes - numZeros);
    }
}

面试追问

  • 如果物品价值不止三种，但每种只有计数，怎样推广？按价值降序遍历计数桶。
  • 如果每类还有不同重量并受容量限制，会发生什么？问题将接近背包，当前贪心不再普遍成立。
  • 为什么参数 numNegOnes 没出现在公式里？它只保证库存可行，实际会选多少个 −1 已由缺口决定。

常见错误

  • 只返回 min(numOnes, k)，忘记必须恰好选 k 件以及 −1 的扣分。
  • 把 0 类物品错误地加入答案；0 只占名额，不改变总和。
  • 无视 k = 0 的合法边界。
  • 构造长度最多 150 的数组虽然可过题，但隐藏了常数时间解法。
