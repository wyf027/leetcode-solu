校园自行车分配

Campus Bikes — 把曼哈顿距离最短的“工人—自行车”组合依次取出，在全局且确定的优先级下完成分配。

MEDIUM付费题数组排序堆 / 优先队列

题目转述

校园里有若干工人和不少于工人数的自行车。坐标均为二维整数点。不断从尚未分配的组合中选择曼哈顿距离最小的一对；距离相同时，工人下标较小者优先；仍相同时，自行车下标较小者优先。若这一对中的工人和自行车都尚未使用，就将该车分给该工人。返回每位工人获得的自行车下标。

函数：assignBikes(workers, bikes) → integer[]

距离：|worker.x-bike.x| + |worker.y-bike.y|

约束

  • 1 ≤ workers.length ≤ bikes.length ≤ 1000
  • 每个坐标都在 [0, 999] 内
  • 工人位置两两不同，自行车位置两两不同
  • 每位工人最终恰好分配一辆不同的自行车
先自己思考：为什么不能让每个工人只挑自己最近的车？全局优先级如何消除冲突？

官方参数形式示例

示例 1
workers = [[0,0],[2,1]]
bikes   = [[1,2],[3,3]]
输出     = [1,0]
示例 2
workers = [[0,0],[1,1],[2,0]]
bikes   = [[1,0],[2,2],[2,1]]
输出     = [0,2,1]

题解：全局排序后的贪心扫描

核心洞察

题目给出的分配规则本身就是一个全序：每个组合都有键 (distance, workerIndex, bikeIndex)。把所有组合按这个键排序，随后从前往后扫描；只有双方都空闲时才接受该组合。这直接模拟题目规则。

完整过程

  1. 枚举每位工人与每辆自行车，计算曼哈顿距离并记录三元组。
  2. 按距离、工人下标、自行车下标升序排序。
  3. 准备答案数组和自行车占用数组。
  4. 顺序扫描三元组；若工人未分配且车未占用，则接受。
  5. 分配数达到工人数后立即结束。

正确性

引理：排序后，任意候选组合出现的顺序与题目规定的选择优先级完全相同。归纳：假设前若干个已接受的组合与规则执行结果一致。扫描到下一个双方均可用的组合时，所有排在它之前的组合都已处理，且因至少一方已占用而不再合法；因此它正是规则此刻会选的最小合法组合。接受后归纳条件继续成立。直到所有工人被分配，故算法输出与规定过程一致。

边界

  • 单个工人：仍按距离和车下标决胜。
  • 大量相同距离：必须严格使用工人、车下标两层 tie-break。
  • 自行车多于工人：达到工人数即可停止。

复杂度

设工人数为 W，车数为 B，组合数 P=W×B。时间 O(P log P)，空间 O(P+W+B)。坐标距离有小上界时可用桶按距离分组，将排序部分降为线性级别。

Java

class Solution {
    public int[] assignBikes(int[][] workers, int[][] bikes) {
        java.util.List<int[]> pairs = new java.util.ArrayList<>();
        for (int w = 0; w < workers.length; w++)
            for (int b = 0; b < bikes.length; b++)
                pairs.add(new int[]{Math.abs(workers[w][0]-bikes[b][0]) + Math.abs(workers[w][1]-bikes[b][1]), w, b});
        pairs.sort((a,c) -> a[0] != c[0] ? a[0]-c[0] : a[1] != c[1] ? a[1]-c[1] : a[2]-c[2]);
        int[] ans = new int[workers.length]; java.util.Arrays.fill(ans, -1);
        boolean[] used = new boolean[bikes.length]; int assigned = 0;
        for (int[] p : pairs) if (ans[p[1]] == -1 && !used[p[2]]) {
            ans[p[1]] = p[2]; used[p[2]] = true;
            if (++assigned == workers.length) break;
        }
        return ans;
    }
}

  const pairs = [];
  for (let w = 0; w < workers.length; w++)
    for (let b = 0; b < bikes.length; b++)
      pairs.push([Math.abs(workers[w][0]-bikes[b][0]) + Math.abs(workers[w][1]-bikes[b][1]), w, b]);

  const ans = Array(workers.length).fill(-1), used = Array(bikes.length).fill(false);
  let assigned = 0;

    ans[w] = b; used[b] = true;
    if (++assigned === workers.length) break;
  }
  return ans;
};

Python

from typing import List

class Solution:
    def assignBikes(self, workers: List[List[int]], bikes: List[List[int]]) -> List[int]:
        pairs = []
        for w, (wx, wy) in enumerate(workers):
            for b, (bx, by) in enumerate(bikes):
                pairs.append((abs(wx - bx) + abs(wy - by), w, b))
        pairs.sort()
        ans, used = [-1] * len(workers), [False] * len(bikes)
        assigned = 0
        for _, w, b in pairs:
            if ans[w] == -1 and not used[b]:
                ans[w], used[b] = b, True
                assigned += 1
                if assigned == len(workers): break
        return ans

替代方案

可以把每个工人的候选车按距离排序，再用最小堆维护每位未分配工人的当前最佳候选；也可利用最大曼哈顿距离有限这一事实建立距离桶。它们能减少一次性全排序成本，但实现与状态管理更复杂。

面试追问

  • 若坐标上界很小，怎样用桶避免 log P？
  • 若工人与车流式到达，如何维护动态匹配？
  • 规则改成最小化总距离时，为何当前贪心不再可靠？应考虑哪类匹配算法？

常见错误

  • 只为每位工人独立选最近车，忽略全局顺序。
  • 距离相等时漏掉工人下标或自行车下标。
  • 只标记车已使用，却没有标记工人已经得到车。
  • 比较器用布尔值而非有正负号的数值。
