增长的内存泄露

Incremental Memory Leak · 两根内存条，一次越来越大的请求。

每秒观察剩余空间如何变化。先读规则、手动预测下一步，再展开页面底部的题解。

01 / 任务说明

给定两个整数 memory1 和 memory2，分别代表两根内存条当前可用的位数。从第 1 秒开始，第 i 秒需要一次性占用 i 位：从剩余空间较多的内存条扣除；如果一样多，选择第一根。内存不会释放，也不能把一次请求拆到两根上。

如果两根内存条都无法单独满足本秒的请求，程序立即崩溃，且本秒不扣内存。返回 [crashTime, memory1_crash, memory2_crash]，依次为首次失败的秒数和两根内存条的最终剩余位数。

约束：0 ≤ memory1, memory2 ≤ 2³¹ − 1，输入均为整数。接口：memLeak(memory1, memory2)。

官方示例 1

输入：memory1 = 2, memory2 = 2
输出：[3, 1, 0]

第 1 秒从第一根扣 1，剩余 (1, 2)；第 2 秒从第二根扣 2，剩余 (1, 0)；第 3 秒两根都不足 3，程序崩溃。

官方示例 2

输入：memory1 = 8, memory2 = 11
输出：[6, 0, 4]

第 1～5 秒依次选择第二、第二、第一、第二、第一根，剩余依次为 (8, 10)、(8, 8)、(5, 8)、(5, 4)、(0, 4)。第 6 秒失败。

04 / 独立题解

准备好后，再看思路、证明和四语言实现。

核心洞察：按秒模拟已经足够

选择哪根内存条由题目完全决定，并不存在需要搜索的策略。只要较大剩余值至少为本秒需求，就从对应内存条扣除；若较大值都不够，小的自然也不够。相等时用 memory1 >= memory2 保证第一根优先。

完整过程

  1. 令 i = 1，两个变量保持当前剩余位数。
  2. 当 memory1 >= i || memory2 >= i 时，本秒可以执行。
  3. 若第一根剩余不少于第二根，则第一根减去 i，否则第二根减去 i。然后令 i++。
  4. 循环结束时 i 恰好是第一次无法分配的秒数，直接返回 [i, memory1, memory2]。

以 (8, 11) 为例：i=1 → (8,10)，i=2 → (8,8)；此时相等，i=3 从第一根扣除，得到 (5,8)；再得到 (5,4)、(0,4)。此时准备执行第 6 秒，但最大剩余只有 4，返回 [6,0,4]。

正确性证明

循环不变量：每轮开始时，两个内存变量等于前 i−1 秒合法分配后的真实剩余内存。初始时没有分配，不变量成立。若循环条件成立，至少一根足够，因此较大的一根必然足够；按大小和相等优先规则扣除 i 后，恰好完成第 i 秒，递增秒数保持不变量。退出时两根均小于 i，本秒必然失败；此前每秒都成功，因此返回的是首次失败时间及真实剩余内存。

复杂度与整数范围

令 S = memory1 + memory2 为初始总量。成功执行 t 秒至少消耗 t(t+1)/2 位，故 t = O(√S)。计入初始检查，时间为 O(1 + √S)，辅助空间为 O(1)。当两个输入都取上限时，S 小于 2³²，成功秒数小于 92,682；因此直接模拟的循环次数很小。

四份实现不计算总和或三角数，只比较和扣减非负剩余量，Java / C++ 使用 32 位 int 足够。若实现数学跳步，求和与乘法应使用 64 位整数。页面为了支持回退保存历史，额外占用 O(t) 空间，这不属于题解算法的空间开销。

边界与常见错误

  • 两个输入都是 0：第 1 秒直接崩溃，返回 [1,0,0]。
  • 只剩一根可用：继续从该根扣，直到它也不够。
  • 剩余恰好等于 i：允许扣到 0，不能用严格大于作为继续条件。
  • 不能检查总量是否足够后拆分请求。例如从 (4,4) 开始，第 3 秒之前为 (3,2)，第 3 秒扣第一根后为 (0,2)，第 4 秒失败；而从 (1,1) 开始，第 2 秒前为 (0,1)，也不能合并初始空间改变选择。
  • 循环条件应为“或”，写“且”会在一根不足而另一根仍足够时提前终止。
  • 相等时选择第一根；失败秒不扣内存、不再递增秒数，也不是返回最后成功的秒数。

替代方案

可以利用等差数列求和跳过多次分配：先计算初始较大内存条连续被选择多久，再处理两根交替承担的递增请求，用二分搜索寻找可承担的批次数。这能减少循环，但必须单独处理相等时第一根优先、阶段交界和最后一个请求。当前约束下模拟简洁且足够；只用总量解三角不等式不能得到准确崩溃时刻，因为请求不可拆分。

面试追问

  • 这是贪心吗？这里执行的是固定选择规则，没有优化目标，不需要交换论证。
  • 扩展为 k 根内存条呢？用最大堆维护剩余容量，容量相等按原编号排序，每次取出并扣减后放回，单次分配 O(log k)。
  • 若容量上限大幅增大呢？考虑分阶段的等差数列批处理，使用宽整数并处理精确边界，不能直接用浮点平方根替代全部流程。

Java

class Solution {
    public int[] memLeak(int memory1, int memory2) {
        int i = 1;
        while (memory1 >= i || memory2 >= i) {
            if (memory1 >= memory2) {
                memory1 -= i;
            } else {
                memory2 -= i;
            }
            i++;
        }
        return new int[] {i, memory1, memory2};
    }
}

from typing import List

class Solution:
    def memLeak(self, memory1: int, memory2: int) -> List[int]:
        i = 1
        while memory1 >= i or memory2 >= i:
            if memory1 >= memory2:
                memory1 -= i
            else:
                memory2 -= i
            i += 1
        return [i, memory1, memory2]
