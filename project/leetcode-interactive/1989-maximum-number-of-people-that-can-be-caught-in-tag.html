捉迷藏中可捕获的最大人数

Maximum Number of People That Can Be Caught in Tag

一条队列，两种身份。每个人只能参与一次捕获，怎样让被捕获的人尽可能多？

01 / 读懂规则

题目描述

给定从下标 0 开始的二进制数组 team，其中 1 表示捕获者，0 表示躲藏者。另给定整数 dist。下标为 i 的捕获者可以选择一个下标为 j 的躲藏者，前提是 |i − j| ≤ dist。

每名捕获者最多捕获一人；每名躲藏者最多被捕获一次。求可以被捕获的最大人数，返回整数。距离以数组下标之差计算，捕获范围包含端点，且只能选择数组中的人。

参数与返回值

catchMaximumAmountofPeople(team, dist) → integer

team: integer[] · dist: integer

约束

  • 1 ≤ team.length ≤ 10⁵
  • team[i] ∈ {0, 1}
  • 1 ≤ dist ≤ team.length

题解：让最早的两位候选先相遇

核心洞察：按原始下标从左到右处理两类人。用 i 指向尚未处理的最左捕获者，用 j 指向尚未处理的最左躲藏者。能配就配；距离太远时，舍弃更靠左的那位，因为未来另一类人只会更远。

完整过程

  1. 令 i = j = ans = 0。分别跳过 i 上的 0 和 j 上的 1，找到两类人的最左未处理下标。
  2. 任何指针到达数组末尾就结束；剩下一类人不能自行配对。
  3. 若 |i − j| ≤ dist，配成一对，答案加一，两个指针都右移。
  4. 否则若 i < j，该捕获者连最早的躲藏者都够不到，右移 i。
  5. 否则 j 太靠左，未来捕获者同样够不到它，右移 j。重复以上步骤。

官方示例可依次得到 (1 → 0)、(3 → 2)，答案为 2。配对方案与题目举例不同，但人数相同；题目只要求人数。

正确性：为什么不会错过更好的匹配？

不变量：两指针之前的人已经配对，或已证明不可能和剩余候选配对；固定的配对能扩展成原问题的某个最优方案。

距离太远：若 i < j − dist，所有剩余躲藏者下标都不小于 j，因此 i 不可能再捕获任何人。对称地，j < i − dist 时 j 不可能再被剩余捕获者捕获。舍弃更左者不减少最优值。

距离足够：设 i、j 是剩余最左的两类候选。取一个剩余问题的最优匹配。如果 i 与 j 都未使用，可增加这一对，与最优性矛盾。如果仅一人已使用，把涉及该人的一条边改为 (i,j)，人数不变。如果已互相匹配，无须调整。

剩下的情况是已有 (i,j′) 和 (i′,j)，其中 i′ ≥ i、j′ ≥ j。改成 (i,j) 与 (i′,j′)。因为 i′ − j′ ≤ i′ − j ≤ dist 且 j′ − i′ ≤ j′ − i ≤ dist，后一对依然有效。人数不变，所以总存在包含当前选择的最优匹配。

每一步都保持不变量。某类候选耗尽时，再也不能增加配对，因此累计人数就是全局最大值。

复杂度

时间 O(n)：两个指针各自最多移动 n 次，内部跳过角色的循环累计也是线性。

额外空间 O(1)：只有指针与计数，不构建下标数组，也不修改输入。页面为了回放保存快照，额外占用的空间不计入提交算法。

边界情况

  • 只有一种角色或长度为 1：答案是 0。
  • 距离恰好等于 dist：可以配对，必须使用 ≤。
  • dist ≥ n − 1：所有异类都互相可达，答案为两类人数的较小值。
  • n 可达 10⁵：不需要排序、递归或逐个窗口扫描。
  • dist = 0 不属于本题约束。

替代方案与取舍

  • 分离下标数组：分别收集 1 和 0 的下标，再用两个指针执行相同决策。时间 O(n)，空间 O(n)，讲解直观；这里直接遍历原数组，省掉两份列表。
  • 逐捕获者扫描：按捕获者从左到右，选择窗口内最左的未捕获躲藏者。可行，但反复扫描最多 O(n · min(n, 2dist + 1))，通常还需 O(n) 标记。
  • 通用二分图匹配：可用于更一般的可达关系，但本题显式建边最坏达到 O(n²)，没有利用位置顺序与统一距离。

常见错误

  • 只统计每个窗口里的 0：会让不同捕获者重复使用同一个人。
  • 配对后只移动一个指针：违反一人最多参与一次的规则。
  • 把 <= dist 写成 < dist：漏掉端点。
  • 距离过远时移动更靠右的一侧：留下已无机会的人，跳过仍有机会的人。
  • 先按 0、1 排序：改变原位置，破坏距离定义。
  • 随便选最近的人：team=[0,0,1,0,1], dist=2 中，若 i=2 在两个最近目标中选 j=3，i=4 就无目标；选 j=0 则还可配 (4,3)，共 2 人。

JAVA

class Solution {
    public int catchMaximumAmountofPeople(int[] team, int dist) {
        int n = team.length, i = 0, j = 0, ans = 0;
        while (true) {
            while (i < n && team[i] != 1) i++;
            while (j < n && team[j] != 0) j++;
            if (i == n || j == n) break;
            if (Math.abs(i - j) <= dist) {
                ans++;
                i++;
                j++;
            } else if (i < j) {
                i++;
            } else {
                j++;
            }
        }
        return ans;
    }
}

面试追问

  • 如何返回具体配对？在配对分支追加 (i,j)。时间仍为 O(n)，输出空间为 O(k)，k 是答案。
  • 每个捕获者的 dist 都不同呢？当前位置顺序不再保证窗口右端点顺序，交换证明可能失效；可考虑把捕获区间按右端点排序，并用有序集合选择区间中的最左可用目标。
  • 每人可捕获多名目标呢？需要显式记录剩余容量，并重新证明推进条件，不能沿用配对后无条件推进两个指针的代码。
  • 如何设计后续验证？小规模枚举合法配对求最大值，与双指针结果比较；再补齐全同角色、距离端点、长连续分组和最大规模输入。本轮尚未执行。
