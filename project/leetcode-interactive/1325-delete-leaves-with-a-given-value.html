叶子节点

有些叶子删掉后，父节点才刚刚成为新的目标叶子。关键不在“删一轮”，而在选择一种天然支持连锁反应的访问顺序。

1325Delete Leaves With a Given Value非付费题
Problem

题目说明

给定一棵以 root 为根的二叉树和整数 target，删除所有值等于 target 的叶子节点，并返回处理后的树根。

连锁规则：一次删除可能让父节点变成新的叶子；若这个新叶子的值也等于 target，它同样必须被删除。持续处理，直到不能再删。

removeLeafNodes(root: TreeNode, target: int) -> TreeNode

约束

  • 树中节点数在 [1, 3000] 内。
  • 1 <= Node.val, target <= 1000。
  • 输入为二叉树；返回值允许为 null。

Deep Dive

题解：后序遍历让父节点看到最终的孩子

核心洞察

是否删除当前节点，取决于它的左右孩子“清理完成后”是否都为空。因此必须使用后序顺序：左子树 → 右子树 → 当前节点。递归返回 null 就等价于从父节点上剪断这条边。

完整过程

  1. 空节点直接返回 null。
  2. 递归清理左子树，把返回值重新接到 root.left。
  3. 递归清理右子树，把返回值重新接到 root.right。
  4. 若此时当前节点无孩子且值等于 target，返回 null；否则返回当前节点。

正确性

归纳基础：空树返回空；单节点树会按“是目标叶子”与否得到正确结果。
归纳步骤：假设递归能正确清理左右子树。重新连接两个返回结果后，当前节点看到的是两棵已满足要求的子树。此时它若成为目标叶子就删除，否则保留；于是以当前节点为根的整棵子树也满足要求。对根节点成立，因此算法正确。

复杂度与边界

每个节点仅访问一次，时间复杂度 O(n)。递归栈与树高有关，空间复杂度 O(h)；最坏退化链为 O(n)。根节点也可能被删除；非目标叶子保留；值等于目标但仍有孩子的节点暂不删除。

Implementations

Java

官方可提交签名
/**
 * Definition for a binary tree node.
 * public class TreeNode {
 *     int val;
 *     TreeNode left;
 *     TreeNode right;
 *     TreeNode() {}
 *     TreeNode(int val) { this.val = val; }
 *     TreeNode(int val, TreeNode left, TreeNode right) {
 *         this.val = val;
 *         this.left = left;
 *         this.right = right;
 *     }
 * }
 */
class Solution {
    public TreeNode removeLeafNodes(TreeNode root, int target) {
        if (root == null) return null;

        root.left = removeLeafNodes(root.left, target);
        root.right = removeLeafNodes(root.right, target);

        if (root.left == null && root.right == null && root.val == target) {
            return null;
        }
        return root;
    }
}

替代方案

可以反复扫描整棵树，每轮删除当前目标叶子，直到没有变化。它更贴近题目文字，但链式树可能每轮只删一个节点，最坏达到 O(n²)。也可以手写带“访问标记”的栈模拟后序遍历，避免调用栈，但实现更繁琐。

常见错误

  • 在递归孩子之前判断叶子，遗漏删除后新出现的目标叶子。
  • 只递归但没有把返回值赋回 left/right，导致边没有真正断开。
  • 默认根一定保留，忽略整棵树可能被删空。
  • 用循环重复 DFS，虽可能正确，却把线性解写成平方级。
Interview Follow-ups

面试追问

如果树深可能达到几十万，递归有什么风险？

语言调用栈可能溢出。可用显式栈保存 (node, parent, visited)，第二次弹出节点时做后序判断并断开父子关系；还需单独处理根。

如果要删除满足任意谓词的叶子呢？

把 root.val == target 替换为谓词 shouldDelete(root)，后序结构完全不变。

为什么不是层序遍历？

层序天然从父到子，而本题的决定依赖孩子最终状态。若没有额外的父指针、度数与反向队列，层序很难自然地把变化向上反馈。
