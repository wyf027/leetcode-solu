这一题把“相邻元素不能相同”的局部限制，放进了一个有多种颜色可选的成本优化问题中。 先读清状态和输入，再用下方实验台观察每一栋房子的累计成本如何变化；完整解法默认收起。

Problem

题意

有 n 栋房子排成一列，可使用 k 种颜色。矩阵 costs 中，costs[i][j] 表示把第 i 栋房子刷成第 j 种颜色的费用。

请为每栋房子选择一种颜色，使任意两栋相邻房子的颜色不同，并返回粉刷全部房子的最小总费用。

函数签名

minCostII(costs: integer[][]) -> integer

Constraints

约束

  • n == costs.length
  • k == costs[i].length
  • 1 <= n <= 100
  • 2 <= k <= 20
  • 1 <= costs[i][j] <= 20

进阶目标：设计时间复杂度为 O(nk) 的算法。

Solution

核心洞察：每一行只保留最小与次小

定义 dp[i][j] 为粉刷到第 i 栋房子、且第 i 栋使用颜色 j 时的最小总费用。转移必须从上一行除 j 外的颜色中取最小值： 

dp[i][j] = costs[i][j] + min(dp[i-1][c])，其中 c != j

如果每个 j 都重新扫描上一行，复杂度会变成 O(nk²)。关键观察是： 记上一行的最小值为 min1、对应颜色为 color1，次小值为 min2。当 j != color1 时直接使用 min1；只有 j == color1 时，才改用 min2。这样每个状态都能在常数时间完成转移。

“次小值”按值更新即可，即使最小值出现并列也没有问题：另一个相同的最小值会成为 min2，正好代表可选的另一种颜色。

完整过程

1

初始化第一行

第一栋房子没有相邻前驱，所以 prev[j] = costs[0][j]。

2

扫描两个哨兵值

扫描 prev，得到最小值、其颜色下标，以及次小值。

3

构造当前行

对颜色 j，若撞上最小值颜色就加 min2，否则加 min1。

4

滚动并收尾

用当前行替换上一行，处理完所有房子后返回最后一行的最小值。

正确性证明

引理 1：状态转移覆盖全部合法方案

若第 i 栋使用颜色 j，则第 i-1 栋只能使用某个 c != j。任何粉刷到第 i 栋的合法方案，都能唯一拆成一个以颜色 c 结束的合法前缀与当前选择 j。因此对所有 c != j 取最小值，恰好得到 dp[i][j]。

引理 2：两个最小值足以完成排除

若上一行的最小值颜色不是 j，它属于允许集合且不会有更优值；若它正是 j，排除该颜色后，允许集合中的最小元素就是整行次小值。因此算法选择的前驱费用 始终等于 min(dp[i-1][c])（c != j）。

定理：算法返回全局最小总费用

基础情形中第一行状态显然正确。由引理 1 与引理 2，若上一行状态正确，算法构造的当前行也正确； 归纳可得最后一行的每个状态都正确。所有完整合法方案必以某种颜色结束，故最后一行最小值就是全局最优解。

复杂度与边界

时间复杂度

O(nk)

每一行两次线性扫描，常数项不影响量级。

空间复杂度

O(k)

只保存上一行与当前行；不计输入和返回值。

边界

一栋房子时取该行最小值；两种颜色时会自然交替；并列最小值由“次小值”正确承接。 官方约束保证 k >= 2。

class Solution {
    public int minCostII(int[][] costs) {
        int n = costs.length;
        if (n == 0) {
            return 0;
        }

        int k = costs[0].length;
        int[] prev = costs[0].clone();

        for (int i = 1; i < n; i++) {
            int min1 = Integer.MAX_VALUE;
            int min2 = Integer.MAX_VALUE;
            int minColor = -1;

            for (int color = 0; color < k; color++) {
                if (prev[color] < min1) {
                    min2 = min1;
                    min1 = prev[color];
                    minColor = color;
                } else if (prev[color] < min2) {
                    min2 = prev[color];
                }
            }

            int[] curr = new int[k];
            for (int color = 0; color < k; color++) {
                int bestPrevious = color == minColor ? min2 : min1;
                curr[color] = costs[i][color] + bestPrevious;
            }
            prev = curr;
        }

        int answer = Integer.MAX_VALUE;
        for (int total : prev) {
            answer = Math.min(answer, total);
        }
        return answer;
    }
}

    const n = costs.length;
    if (n === 0) {
        return 0;
    }

    const k = costs[0].length;
    let prev = costs[0].slice();

    for (let i = 1; i < n; i++) {
        let min1 = Infinity;
        let min2 = Infinity;
        let minColor = -1;

        for (let color = 0; color < k; color++) {
            if (prev[color] < min1) {
                min2 = min1;
                min1 = prev[color];
                minColor = color;
            } else if (prev[color] < min2) {
                min2 = prev[color];
            }
        }

        const curr = new Array(k);
        for (let color = 0; color < k; color++) {
            const bestPrevious = color === minColor ? min2 : min1;
            curr[color] = costs[i][color] + bestPrevious;
        }
        prev = curr;
    }

    return Math.min(...prev);
};

替代方案

直接枚举前驱

对每个 dp[i][j] 扫描所有 c != j。最直观，时间 O(nk²)，适合先验证状态定义。

前缀 / 后缀最小值

为上一行构造前缀与后缀最小值，排除某个颜色时组合左右两侧；同样是 O(nk)，但辅助结构更多。

原地更新

可把累计费用写回 costs，将额外空间降为 O(1)；代价是修改输入，面试时应先确认是否允许。

面试追问

  • 如果要求恢复具体颜色序列，需要额外保存哪些父指针信息？
  • 如果相邻距离不超过 d 的房子都不能同色，两个最小值还够吗？
  • 若每栋房子的可用颜色集合不同，如何表示不可用状态并防止溢出？
  • 如果费用在线追加，如何维护最新答案？

常见错误

  • 只记录最小值却没记录其颜色，导致无法判断是否需要排除。
  • 用 <= 随意覆盖最小值下标，且没有同步维护次小值。
  • 在当前行尚未算完时覆盖上一行，后续颜色读到了混合状态。
  • 误把答案写成所有行最小值之和；这可能重复选择相邻的同一颜色。
  • 使用固定小常数作为无穷大，在更宽约束下引发错误或溢出。
