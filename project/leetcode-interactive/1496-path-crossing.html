Path Crossing · 一次关于足迹的判断

判断路径
是否相交

从原点出发，沿着四个方向逐步行走。问题不在于你走了多远，而在于：是否曾回到一处熟悉的位置？

01 · Problem

先读懂路线规则

给定字符串 path，其中每个字符都是 'N'、'S'、'E' 或 'W'，分别表示向北、向南、向东、向西移动一个单位。

你从二维平面的原点 (0, 0) 出发，依次执行路径中的每一步。如果在任意时刻到达了一个此前已经到过的位置，返回 true；如果整条路径都没有重复到访任何位置，返回 false。

注意：“相交”按到达同一个坐标判断；起点也是已经访问过的位置。
  • 函数isPathCrossing(path)
  • 参数path: string
  • 返回boolean
  • 起点(0, 0)
  • 付费限制无

官方示例

1

不相交的路径

输入path = "NES"
输出false
解释该路径没有在任何位置相交。
2

回到原点

输入path = "NESWW"
输出true
解释该路径经过原点两次。

约束

  • 1 <= path.length <= 104
  • path[i] 只能是 'N'、'S'、'E' 或 'W'。

03 · Solution

准备好看题解了吗？

先在路径实验室里形成自己的判断方法，再展开下方的完整分析。

完整题解 · Hash Set

把每个坐标记进足迹册

核心洞察

路径是否相交，等价于“行走过程中是否第二次到达某个坐标”。因此不必比较线段，也不必保存完整地图；只要用哈希集合记录已经到达过的坐标。

最容易漏掉的一步：出发前先把原点 (0, 0) 放入集合，否则无法识别“后来回到原点”的情况。

完整过程

  1. 初始化坐标 x = 0, y = 0，把原点编码后加入已访问集合。
  2. 从左到右读取 path。根据字符更新一个坐标轴：北/南改变 y，东/西改变 x。
  3. 将新坐标编码为唯一键。如果键已存在，说明这个位置访问过，立即返回 true。
  4. 否则将新坐标加入集合，继续执行；所有指令结束仍未重复，则返回 false。

坐标编码

可把坐标写成字符串 "x,y"。逗号是分隔符，避免 (1, 23) 与 (12, 3) 产生歧义。

时间复杂度O(n)每个方向处理一次
空间复杂度O(n)最坏记录 n+1 个点

边界情况

  • 最短路径只有一步，不可能重复。
  • NS、EW 会回到原点。
  • 第一次发现重复即可提前结束。
  • 坐标可为负数，字符串键仍然有效。

正确性证明

不变式：处理完前 i 个字符后，集合恰好包含从起点到第 i 步结束为止访问过的全部不同坐标。

初始化：尚未处理字符时，只访问过原点，集合初始化为仅含原点，因此不变式成立。

保持：处理下一字符后得到唯一的新当前位置。若它已在集合中，路径确实到达了先前位置，返回 true 正确；若它不在集合中，将它加入后，集合仍恰好覆盖至此访问过的全部不同坐标，不变式继续成立。

终止：如果循环中返回 true，必然发现了重复坐标；如果循环正常结束，按不变式每个新坐标在到达时都未出现过，所以没有位置被重复访问，返回 false 正确。

Implementations

四种语言完整实现

JavaHashSet<String>
import java.util.HashSet;
import java.util.Set;

class Solution {
    public boolean isPathCrossing(String path) {
        int x = 0;
        int y = 0;
        Set<String> visited = new HashSet<>();
        visited.add("0,0");

        for (char direction : path.toCharArray()) {
            if (direction == 'N') {
                y++;
            } else if (direction == 'S') {
                y--;
            } else if (direction == 'E') {
                x++;
            } else {
                x--;
            }

            String key = x + "," + y;
            if (!visited.add(key)) {
                return true;
            }
        }
        return false;
    }
}

class Solution {

    bool isPathCrossing(string path) {
        int x = 0;
        int y = 0;
        unordered_set<string> visited;
        visited.insert("0,0");

        for (char direction : path) {
            if (direction == 'N') {
                ++y;
            } else if (direction == 'S') {
                --y;
            } else if (direction == 'E') {
                ++x;
            } else {
                --x;
            }

            string key = to_string(x) + "," + to_string(y);

                return true;
            }
            visited.insert(key);
        }
        return false;
    }
};

替代方案

整数编码坐标：题目最多走 10^4 步，可给坐标加偏移后压成一个整数，减少字符串创建。例如选择大于坐标跨度的基数。但字符串或坐标元组更直观，也更不易写错。

两两比较坐标：把每一步坐标存在数组，再线性搜索是否出现过。逻辑可行，但最坏时间复杂度为 O(n²)，没有利用哈希集合的常数时间查找。

线段相交检测：本题每次移动一个单位，而且“相交”定义为重复到达位置，维护点集合已经足够。通用线段求交会引入不必要的复杂度。

常见错误

  • 忘记预先记录原点，漏掉 NS 这类路径。
  • 更新坐标前就检查集合，检查到的是旧位置。
  • 坐标字符串不加分隔符，造成键碰撞。
  • 把“方向字符重复”误认为“位置重复”。
  • 发现重复后仍继续模拟，错过提前返回。

面试追问

如果路径是无限流，如何处理？

算法可以在线处理，每收到一个方向就更新位置并查询集合；一旦重复立即结束。若必须永远检测且路径不相交，集合会持续增长，需要讨论内存上限或问题额外约束。

能否做到 O(1) 额外空间？

在没有更多路径结构约束时，通常不能同时保持线性时间：为了判断当前位置是否在任意历史位置出现过，需要保留历史信息。可以牺牲时间，每次重扫前缀，将空间降至 O(1)。

如果每条指令能移动多个单位呢？

若“经过”中间位置也算访问，应逐单位展开，或升级为线段相交与重叠检测；需要先澄清端点接触、共线重叠是否算相交。
