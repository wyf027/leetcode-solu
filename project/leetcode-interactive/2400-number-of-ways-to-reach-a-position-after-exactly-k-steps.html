01 / Problem

题目与输入范围

给定正整数 startPos、endPos 和 k。你从无限整数数轴的 startPos 出发，每一步只能向左或向右移动 1 个单位。求恰好走 k 步后停在 endPos 的不同移动序列数，并对 1,000,000,007 取余。只要某一步的方向不同，就算不同方法。

数轴没有边界，可以经过 0 和负整数；途中可以重复经过任何位置，也可以提前经过终点后继续移动。

完整约束：1 ≤ startPos, endPos, k ≤ 1000

参数顺序：numberOfWays(startPos, endPos, k) → int

官方示例 1

输入：startPos = 1, endPos = 2, k = 3
输出：3

三条路径分别是：

1 → 2 → 3 → 2
1 → 2 → 1 → 2
1 → 0 → 1 → 2

官方示例 2

输入：startPos = 2, endPos = 5, k = 10
输出：0

不存在恰好走 10 步并从 2 到达 5 的移动序列。

03 / Solution lab

从左右步数，到选择步子的顺序

核心洞察

设有 r 步向右、l 步向左，位移为 d = endPos − startPos。必有 r + l = k、r − l = d，因此 r = (k + d) / 2。

  • 如果 |d| > k，步数不够，返回 0。
  • 如果 k + d 为奇数，左右步数无法取整数，返回 0。
  • 否则从 k 个时刻中选 r 个向右，答案为 C(k, r)。由对称性，只需计算 m = min(r, k − r) 列。
本页实现：使用杨辉三角的一维动态规划求组合数。只做加法和取模，无需阶乘、除法或模逆元；JavaScript 也能安全使用 Number。

逐层路径实验室

第 t 层表示已经走了 t 步。每个圆点合并所有到达同一位置的路径，圆内数字是方法数。向左下走表示左移，向右下走表示右移；每个节点从上方两个父节点汇总计数。橙色节点表示目标位置，绿色表示当前层。

完整求解过程

  1. 计算位移 d，先排除距离超出 k 或奇偶性不匹配的情况。
  2. 计算 r 和 m。建立长度 m + 1 的数组 dp，令 dp[0] = 1，其余为 0。
  3. 依次处理 t = 1…k。令 j 从 min(t, m) 递减到 1，执行 dp[j] = (dp[j] + dp[j − 1]) % MOD。
  4. 每次从右向左更新，保证右侧的 dp[j − 1] 仍属于上一层；dp[0] 始终是 1。
  5. 返回 dp[m]。动画为了展示完整路径保留了所有列；提交代码只保留所需的前 m + 1 列。

示例 1：d = 1，r = 2，m = 1。dp 从 [1, 0] 依次变成 [1, 1]、[1, 2]、[1, 3]，答案为 3。示例 2 的 k + d = 13 为奇数，直接返回 0。

正确性说明

可达条件：任意合法路径都满足上述两个方程，所以距离和奇偶条件是必要的；当它们满足时，r 与 l 都是非负整数且总和为 k，任意排列这两类方向都能到达终点，所以条件也充分。

一一对应：每条路径唯一决定向右的时刻集合；每个大小为 r 的时刻集合也唯一决定一条路径。因此合法路径数正好是 C(k, r) = C(k, m)。

递推不变量：处理完 t 层后，dp[j] = C(t, j) mod MOD。初始 t = 0 时成立。选取 j 个时刻时，按是否选第 t 个时刻分为互斥且完备的两类，计数分别为 C(t − 1, j) 与 C(t − 1, j − 1)。倒序更新保持两个操作数来自上一层，故归纳成立，最终返回正确结果。

复杂度

时间 O(k(m + 1))，空间 O(m + 1)，其中 m ≤ k / 2。最坏时间 O(k²)、空间 O(k)；不可达时 O(1)。m = 0 时本实现仍进行 k 次外层循环。

边界要点

|d| = k 时只有一种方向序列；起终点相同需 k 为偶数；目标在起点左边也适用。负位置只是正常位置，不需要特殊截断。

替代方案与选择

  • 按位置动态规划：dp[t][x] = dp[t − 1][x − 1] + dp[t − 1][x + 1]；滚动数组可做到 O(k²) 时间、O(k) 空间，负坐标需要偏移或映射。
  • 组合数 + 模逆元：阶乘与快速幂可将单次求解降到 O(k + log MOD)，但实现和数值处理更复杂。这里 k ≤ 1000 < MOD，阶乘在模意义下非零。JavaScript 的乘法版本应使用 BigInt。
  • DFS + 记忆化：状态用剩余步数和与目标的距离，可剪枝；状态最坏 O(k²)，并需注意递归深度。无记忆化的枚举为 O(2^k)。

常见错误

  • 把“恰好 k 步”写成“最多 k 步”，或到达终点就提前结束。
  • 漏掉奇偶判定，对 (k + d) / 2 直接向下取整。
  • 一维 dp 正序更新，误用本轮新值，导致重复计数。
  • 禁止走到负数，错误地给无限数轴加上边界。
  • 把模运算下的除法当普通整数除法；或在 JS 中直接计算大整数阶乘。

面试追问

  • 很多组查询怎么办？若 k 上限固定，可预计算阶乘和逆阶乘，在可达判定后 O(1) 求每次组合数。
  • 加入不能经过的位置呢？路径不再只由左右步数决定，改用按位置的动态规划并屏蔽障碍状态。
  • 允许原地不动呢？多一个方向选择，可用三路递推；也可枚举静止步数后计算多项式系数。
  • 为什么 JavaScript 不用 BigInt？本实现每次仅将两个小于 MOD 的数相加，最大为 2,000,000,012，小于 Number 的精确整数上限 2^53 − 1。

int 安全加法
class Solution {
    public int numberOfWays(int startPos, int endPos, int k) {
        final int MOD = 1_000_000_007;
        int d = endPos - startPos;
        if (Math.abs(d) > k || (k + d) % 2 != 0) return 0;
        int r = (k + d) / 2;
        int m = Math.min(r, k - r);
        int[] dp = new int[m + 1];
        dp[0] = 1;
        for (int t = 1; t <= k; t++) {
            for (int j = Math.min(t, m); j >= 1; j--) {
                dp[j] = (dp[j] + dp[j - 1]) % MOD;
            }
        }
        return dp[m];
    }
}
