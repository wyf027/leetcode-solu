Problem 887 · Strategy under uncertainty

鸡蛋掉落

你能承受的不是“摔几次”，而是每次结果出现后，仍然可以覆盖多少种未知情况。

困难Super Egg Drop非会员题
01 / Problem

题目

给定 k 枚相同的鸡蛋，以及一栋楼层编号为 1 到 n 的建筑。存在一个未知临界楼层 f，且 0 ≤ f ≤ n：

  • 从高于 f 的楼层扔下，鸡蛋一定会碎；
  • 从 f 或更低楼层扔下，鸡蛋一定不会碎。

每次可选一枚未碎的鸡蛋，从任意楼层 x（1 ≤ x ≤ n）扔下。碎掉的鸡蛋不能再用，未碎的可以继续使用。

返回：在最坏情况下，能够确定临界楼层 f 的最少操作次数。

关键语义：必须“确定无疑”，所以我们优化的是所有可能结果分支中最长的那一条。

约束

  • 1 ≤ k ≤ 100
  • 1 ≤ n ≤ 104

函数签名

superEggDrop(k, n) → integer

状态空间

f 一共有 n + 1 个候选值：从 0 到 n。

示例 1
输入：k = 1, n = 2
输出：2
解释：依次测试 1、2 楼；最坏需 2 次。
示例 2
输入：k = 2, n = 6
输出：3
示例 3
输入：k = 3, n = 14
输出：4

03 / Solution

准备好看题解了吗？

先用上面的模型形成直觉，再展开完整推导。

Core insight

反转动态规划的提问方式

传统状态 dp[k][n] 直接问“k 个蛋、n 层楼最少几次”，转移时还要枚举扔蛋楼层。更高效的状态是：

dp[e] = 用 e 个鸡蛋、m 次操作最多能确定的楼层数

当增加一次操作时，选择某层扔蛋：

  • 鸡蛋碎：下方可覆盖 dp[e-1] 层；
  • 鸡蛋不碎：上方可覆盖 dp[e] 层；
  • 当前测试楼层本身：1 层。
转移：newDp[e] = oldDp[e-1] + oldDp[e] + 1

为什么必须倒序更新？

一维压缩后，从 k 到 1 更新。这样右侧的 dp[e] 和 dp[e-1] 都仍属于上一轮操作次数。如果正序更新，dp[e-1] 已变成新值，会混用两个时间层。

停止条件

从全 0 开始，每轮令 m += 1 并更新所有鸡蛋数。当 dp[k] ≥ n 时，m 就是最小操作次数。

Process

完整过程

  1. 初始化。 dp[0..k] = 0，表示 0 次操作覆盖 0 层；答案计数 moves = 0。
  2. 扩充一次机会。 当 dp[k] < n，增加一次操作。
  3. 倒序转移。 对 e = k ... 1，执行 dp[e] = dp[e] + dp[e-1] + 1。
  4. 到达目标。 首次出现 dp[k] ≥ n 时退出；由于按操作次数从小到大枚举，此时即为最小值。
Correctness

正确性证明

引理：设 D(m,e) 为 m 次操作、e 个鸡蛋最多可确定的连续楼层数，则 D(m,e)=D(m-1,e-1)+D(m-1,e)+1。

证明：第一次在分界测试楼层扔蛋。若碎了，剩余 m−1 次、e−1 个蛋可确定其下方 D(m-1,e-1) 层；若未碎，剩余 m−1 次、e 个蛋可确定其上方 D(m-1,e) 层；再加上测试楼层本身。两个结果都能在预算内处理，因此总覆盖数等于三者之和；任何策略的首步也只能分成这两类分支，无法覆盖更多。

定理：算法返回确定 f 所需的最小操作次数。

证明：倒序更新准确计算各个 D(m,e)。循环在第一个满足 D(m,k) ≥ n 的 m 停止，说明存在 m 次完成的策略；而对 m−1 有 D(m-1,k) < n，根据引理不存在更少操作覆盖 n 层的策略。因此返回值最小。

边界

  • k = 1：覆盖数每轮只加 1，答案为 n。
  • n = 1：一次即可。
  • 鸡蛋很多时，覆盖增长接近二进制划分。

复杂度

设答案为 m。

  • 时间：O(k · m)
  • 空间：O(k)

在约束范围内 m 很小，远优于枚举楼层的三维思路。

组合解释

D(m,k) = Σ C(m,i)，其中 i=1..k。每种“在哪些操作中碎蛋”的模式对应一段可区分范围。

Implementations

四种语言完整代码

JavaLeetCode
class Solution {
    public int superEggDrop(int k, int n) {
        int[] dp = new int[k + 1];
        int moves = 0;

        while (dp[k] < n) {
            moves++;
            for (int eggs = k; eggs >= 1; eggs--) {
                dp[eggs] = dp[eggs] + dp[eggs - 1] + 1;
            }
        }
        return moves;
    }
}

class Solution {
public:
    int superEggDrop(int k, int n) {
        vector<int> dp(k + 1, 0);
        int moves = 0;

        while (dp[k] < n) {
            ++moves;
            for (int eggs = k; eggs >= 1; --eggs) {
                dp[eggs] = dp[eggs] + dp[eggs - 1] + 1;
            }
        }
        return moves;
    }
};
Alternatives

替代方案

  • 楼层状态 + 二分优化：令 dp[k][n] 表示最少次数，利用“碎/不碎”两项的单调性二分最佳楼层，通常为 O(kn log n)。
  • 组合数 + 二分答案：判断 ΣC(m,i) ≥ n，再二分 m；数学味更强，但实现需防溢出。
  • 朴素枚举落点：O(kn²)，便于推导但无法舒适通过大约束。
Interview follow-ups

面试追问

  • 如何从覆盖数反推出第一次应该在哪一层扔？
  • 为什么结果是组合数之和？
  • 如果每层的碎裂概率不同，目标改成期望次数，状态如何变化？
  • 如果每次扔蛋成本随楼层变化，还能否保留当前转移？
Pitfalls

常见错误

正序更新

会把本轮刚更新的 dp[e-1] 当作上一轮数据，导致覆盖数虚高。

忘记最坏情况

固定某个 f 模拟得出的次数，不等于能保证确定任意 f 的次数。

少算测试层

转移的 +1 是本次实际扔蛋的楼层，不能遗漏。
