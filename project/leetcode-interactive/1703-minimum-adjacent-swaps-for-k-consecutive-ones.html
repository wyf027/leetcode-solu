LeetCode 1703 · Minimum Adjacent Swaps for K Consecutive Ones

得到连续 K 个 1 的
最少相邻交换次数

把散落的 1 聚成一段。真正棘手的地方不是“移动到哪里”，而是如何消掉连续目标位置自带的间距。

困难 非付费题 数组长度 ≤ 100,000

问题

相邻交换，聚拢恰好 k 个 1

给定只含 0 和 1 的整数数组 nums，以及整数 k。一次操作可以交换任意一对相邻元素。求让数组中出现至少一段由 k 个连续 1 组成的最少操作次数。

minMoves(nums: integer[], k: integer) → integer

约束

  • 1 ≤ nums.length ≤ 10⁵
  • nums[i] 只能是 0 或 1
  • 1 ≤ k ≤ sum(nums)

完整题解

连续目标，转换为中位数问题

核心洞察

不要直接对 1 的原下标取中位数。

设所有 1 的下标依次为 p[0], p[1], ...。选择其中连续的 k 个，并令 q[i] = p[i] - i。扣掉序号后，“最终占据一段连续下标”就等价于“所有 q 移到同一点”。绝对值距离和在中位数处最小。

完整过程

  1. 扫描 nums，只保留所有 1 的下标数组 p。
  2. 构造去间距数组 q[i] = p[i] - i。因为 p[i+1] ≥ p[i] + 1，所以 q 仍然单调不降。
  3. 预处理 q 的前缀和。枚举长度为 k 的滑动窗口 [l, r)，其中位数下标为 m = l + ⌊k/2⌋。
  4. 利用前缀和 O(1) 求窗口中所有元素到 q[m] 的距离和，取所有窗口的最小值。
cost = q[m]·(m−l) − (S[m]−S[l]) + (S[r]−S[m+1]) − q[m]·(r−m−1)

为什么只枚举连续的 k 个 1？

1 在相邻交换中没有必要彼此穿越。若选择的两个 1 之间跳过了另一个 1，把被跳过的 1 纳入、换掉更远的那个，不会增加聚拢距离。因此某个最优方案总能对应 p 中长度为 k 的连续窗口。

正确性证明

1

窗口充分

由交换不穿越与就近替换可知，存在一个最优解选择次序连续的 k 个 1。

2

变换等价

若第 i 个被选中的 1 最终到达 x+i，其代价是 |p[i]-(x+i)| = |q[i]-x|。

3

中位数最优

绝对值距离之和在中位数处取得最小值；枚举全部长度 k 窗口后，取到全局最小代价。

边界与复杂度

  • k = 1 时无需交换，公式自然得到 0。
  • 已有连续 k 个 1 时，对应 q 全相等，代价为 0。
  • k 为偶数时取窗口内任一中位数都可；实现取右中位数。
  • 时间复杂度 O(n)，额外空间复杂度 O(s)，其中 s 是数组中 1 的总数。
  • 前缀和和乘法中间值应使用 64 位整数；JavaScript 的 Number 在本题范围内可精确表示。

替代方案比较

方案思路复杂度评价
去间距 + 前缀和p[i]-i 后求窗口到中位数距离O(n)公式统一，奇偶 k 都自然处理
原下标 + 修正项先求到原中位数的距离，再减去目标连续槽位自身的距离O(n)同样高效，但奇偶修正常数更易写错
逐次模拟交换真的把 1 一格格移动最坏远超 O(n)只适合手算或小数据演示

Java
Solution.java
class Solution {
    public int minMoves(int[] nums, int k) {
        int ones = 0;
        for (int value : nums) {
            ones += value;
        }

        long[] normalized = new long[ones];
        int index = 0;
        for (int i = 0; i < nums.length; i++) {
            if (nums[i] == 1) {
                normalized[index] = (long) i - index;
                index++;
            }
        }

        long[] prefix = new long[ones + 1];
        for (int i = 0; i < ones; i++) {
            prefix[i + 1] = prefix[i] + normalized[i];
        }

        long answer = Long.MAX_VALUE;
        for (int left = 0; left + k <= ones; left++) {
            int right = left + k;
            int mid = left + k / 2;
            long median = normalized[mid];
            long leftCost = median * (mid - left)
                    - (prefix[mid] - prefix[left]);
            long rightCost = (prefix[right] - prefix[mid + 1])
                    - median * (right - mid - 1);
            answer = Math.min(answer, leftCost + rightCost);
        }
        return (int) answer;
    }
}

/**
 * @param {number[]} nums
 * @param {number} k
 * @return {number}

var minMoves = function(nums, k) {
    const normalized = [];
    for (let i = 0; i < nums.length; i++) {
        if (nums[i] === 1) {
            normalized.push(i - normalized.length);
        }
    }

    const prefix = new Array(normalized.length + 1).fill(0);
    for (let i = 0; i < normalized.length; i++) {
        prefix[i + 1] = prefix[i] + normalized[i];
    }

    let answer = Number.POSITIVE_INFINITY;
    for (let left = 0; left + k <= normalized.length; left++) {
        const right = left + k;
        const mid = left + Math.floor(k / 2);
        const median = normalized[mid];
        const leftCost = median * (mid - left)
            - (prefix[mid] - prefix[left]);
        const rightCost = (prefix[right] - prefix[mid + 1])
            - median * (right - mid - 1);
        answer = Math.min(answer, leftCost + rightCost);
    }
    return answer;
};
Python
solution.py
from typing import List


class Solution:
    def minMoves(self, nums: List[int], k: int) -> int:
        normalized = []
        for index, value in enumerate(nums):
            if value == 1:
                normalized.append(index - len(normalized))

        prefix = [0]
        for value in normalized:
            prefix.append(prefix[-1] + value)

        answer = float("inf")
        for left in range(len(normalized) - k + 1):
            right = left + k
            mid = left + k // 2
            median = normalized[mid]
            left_cost = (
                median * (mid - left)
                - (prefix[mid] - prefix[left])
            )
            right_cost = (
                prefix[right] - prefix[mid + 1]
                - median * (right - mid - 1)
            )
            answer = min(answer, left_cost + right_cost)

        return int(answer)

class Solution {
public:
    int minMoves(vector<int>& nums, int k) {
        vector<long long> normalized;
        for (int i = 0; i < static_cast<int>(nums.size()); ++i) {
            if (nums[i] == 1) {
                normalized.push_back(i - static_cast<int>(normalized.size()));
            }
        }

        vector<long long> prefix(normalized.size() + 1, 0);
        for (int i = 0; i < static_cast<int>(normalized.size()); ++i) {
            prefix[i + 1] = prefix[i] + normalized[i];
        }

        long long answer = LLONG_MAX;
        for (int left = 0; left + k <= static_cast<int>(normalized.size()); ++left) {
            int right = left + k;
            int mid = left + k / 2;
            long long median = normalized[mid];
            long long leftCost = median * (mid - left)
                - (prefix[mid] - prefix[left]);
            long long rightCost = prefix[right] - prefix[mid + 1]
                - median * (right - mid - 1);
            answer = min(answer, leftCost + rightCost);
        }
        return static_cast<int>(answer);
    }
};

面试追问

  • 为什么减的是全局序号 i，而不是窗口内序号 i-l？ 二者只相差常数 l，所有 q 同移不会改变到中位数的距离和。
  • 如果要求恰好聚在指定区间呢？ 目标起点固定，不再取中位数，直接计算每个被选位置到对应槽位的距离。
  • 如果交换不同位置代价不同呢？ 普通中位数模型失效，需根据代价结构考虑加权中位数、最短路或动态规划。
  • 能否只用 O(k) 空间？ 可以维护滑窗的左右和，但实现更复杂；存全部 1 的位置通常更清晰。

常见错误

  • 直接对原下标求距离和，却忘记减去连续目标槽位之间本就存在的间隔。
  • 只尝试数组中心附近的 1；最优窗口可能出现在任意位置。
  • 偶数 k 手写修正项时少减或多减一次；使用 p[i]-i 可规避这类分支。
  • 使用 32 位变量保存前缀和或乘积，导致中间计算溢出。
