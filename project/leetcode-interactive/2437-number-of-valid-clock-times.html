01 / 题目

给定字符串 time，用 hh:mm 表示 24 小时制时间。某些数字被 ? 遮住了。将每个问号替换成一个 0–9 的数字，统计能形成多少个不同的有效时间，返回整数 answer。

有效范围为 00:00 到 23:59，已经给出的数字必须保持不变。

参数与约束

  • 参数：time: string；返回：整数。
  • time.length = 5，格式为 hh:mm，中间是冒号。
  • 小时满足 00 ≤ hh ≤ 23；分钟满足 00 ≤ mm ≤ 59。
  • 输入是有效时间格式，其中部分数位可能替换为 ?，每个问号需替换为 0–9 的数字。

官方示例

示例 1

输入：time = "?5:00"
输出：2

可得到 05:00、15:00；25:00 超过小时上限。

示例 2

输入：time = "0?:0?"
输出：100

两个问号各有 10 种选择，共 100 种。

示例 3

输入：time = "??:??"
输出：1440

小时有 24 种、分钟有 60 种，共 1440 种。

04 / 独立题解

准备好后再展开思路与四语言实现。

拆分小时与分钟，枚举合法值

核心洞察

先限定候选合法，再检查是否符合模板。小时只枚举 00–23，分钟只枚举 00–59。每个位置满足“模板是问号，或与候选数字相等”即可保留。小时与分钟之间没有额外约束，因此答案为匹配小时数 H × 匹配分钟数 M。

完整过程

  1. 枚举小时 h = 0…23。十位为 h / 10 的整数部分，个位为 h % 10，与 time[0]、time[1] 匹配。
  2. 枚举分钟 m = 0…59，用相同规则与 time[3]、time[4] 匹配。
  3. 分别累计 H、M，返回 H × M。无需生成所有完整时间字符串。

以 time = "?5:00" 为例：小时只留下 05、15，H = 2；分钟只留下 00，M = 1；答案为 2。25 不在小时候选范围内，根本不会进入筛选。

如何阅读演示

前 24 步逐个筛选小时，接着 60 步筛选分钟。每一步仅改变当前候选格与累计数；回退会恢复该步之前的累计状态。第 84 步完成后才展示 H × M。候选的绿色状态只表示模板匹配，不表示代码已通过验证。

正确性

筛选准确：候选范围保证值合法。两位分别匹配，恰好保证已知数字不变，未知数字可被对应候选数字替换。因此筛选保留且仅保留符合模板的小时或分钟。

完整且不重复：任意有效完整时间都有唯一的小时和分钟，它们必定分别在两组保留集合中。反过来，任意保留小时与任意保留分钟拼接，都在合法范围内且符合模板。完整时间与集合中的二元组一一对应，所以总数恰为 H × M。

边界与复杂度

  • 无问号时，合法固定时间的答案为 1；全问号时为 24 × 60 = 1440。
  • 小时十位为 2 时，个位只能是 0–3；分钟十位只能是 0–5。
  • 数值 0–9 也必须作为两位时间理解：十位为 0，不能丢失前导零。
  • 时间复杂度 O(24 + 60)，在本题固定范围下为 O(1)；额外空间 O(1)。演示网格所需的展示空间不计入提交算法。

四语言完整实现

以下采用官方 countTime 签名，均为 LeetCode 提交形式；未编译或运行。

Java

class Solution {
    private int count(String time, int start, int limit) {
        int total = 0;
        for (int x = 0; x < limit; x++) {
            if ((time.charAt(start) == '?' ||
                 time.charAt(start) - '0' == x / 10) &&
                (time.charAt(start + 1) == '?' ||
                 time.charAt(start + 1) - '0' == x % 10)) {
                total++;
            }
        }
        return total;
    }

    public int countTime(String time) {
        return count(time, 0, 24) * count(time, 3, 60);
    }
}

替代方案

可以枚举一天的 1440 个时间，逐位匹配四个数位，时间为 O(24 × 60)，空间为 O(1)，同样足够快。也可分类讨论每个问号的选择数，但小时两位存在关联，分支更易遗漏；分段枚举只需 84 个候选。

常见错误

  • 对每个问号直接乘 10：会包含 29:79 等无效时间。
  • 将小时上下界写成包含 24、分钟包含 60：它们不属于合法候选。
  • 只看小时个位是否未知，忽略十位为 2 的限制。
  • 用 H + M 而非 H × M；两段需要组合。
  • 在 JavaScript 中忘记对 x / 10 向下取整，导致十位比较错误。

面试追问

  • 如果加入秒？再独立计算 00–59 的匹配秒数，乘到答案中。
  • 如果仅统计某个跨小时区间？小时与分钟可能不再独立；枚举完整时间并检查区间，或分段统计。
  • 如果数字位数大幅增加？固定范围枚举不再合适，可考虑数位 DP；本题无需引入它。
