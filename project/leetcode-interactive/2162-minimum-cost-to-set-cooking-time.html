设置时间的
最少代价

Minimum Cost to Set Cooking Time

同样的加热时长，不同的按键路径。你能让手指少花一点力气吗？

01 / 题目规则

微波炉接收 1～4 个数字，不足四位时在左侧自动补零。四位数字的前两位表示分钟 mm，后两位表示秒数 ss，实际加热时长为 60 × mm + ss 秒。分钟与秒数都可以是 0～99，但总时长至少为 1 秒。

例如 954 → 0954 → 9 分 54 秒；0008 是 8 秒；8090 和 8130 都表示 4890 秒。秒数栏允许超过 59，一分钟仍然是 60 秒。

  • startAt：手指开始所在的数字。
  • moveCost：移到任意另一个数字的代价，与键盘上的距离无关；停在当前数字不收费。
  • pushCost：每按一个数字的代价，重复按同一数字也要收费。
  • targetSeconds：要求精确设置的总秒数。

返回所有可行输入方式中的最小总代价。无需计算“开始加热”按钮的费用。

约束
0 ≤ startAt ≤ 9
1 ≤ moveCost, pushCost ≤ 100000
1 ≤ targetSeconds ≤ 6039

02 / 官方示例

示例 1 · 600 秒

startAt = 1, moveCost = 2,
pushCost = 1, targetSeconds = 600
输出：6

输入 1000 是 10 分 0 秒：先按 1，再移到 0，连按三次 0。费用为 1 + 2 + 1 + 1 + 1 = 6。

另两种表示是 0960 和 960，均为 9 分 60 秒，费用分别为 12 和 9。

示例 2 · 76 秒

startAt = 0, moveCost = 1,
pushCost = 2, targetSeconds = 76
输出：6

输入 76：移到 7 并按下，再移到 6 并按下。费用为 1 + 2 + 1 + 2 = 6。

其他合法输入 0076、076、0116、116 的费用均更高。

04 / 题解 · 枚举表示，模拟手指

核心洞察

总秒数固定后，选定分钟数 m 就唯一确定秒数 s = targetSeconds − 60m。枚举 m = 0…99，仅保留 0 ≤ s ≤ 99 的表示。将 100m + s 转成十进制字符串，就得到了去掉前导零的最短按键串。

对每个按键串，从 startAt 重新开始：字符与手指位置不同则加移动费；每个字符都加按压费；更新手指位置，最后取最小值。

完整过程

  1. 令答案为无穷大，枚举 100 种分钟值。
  2. 计算秒数并过滤不合法的候选。
  3. 用 String(100m + s) 构造按键串，保留必要的内部零。
  4. 每个候选重置手指与费用，依次模拟移动与按压。
  5. 用候选费用更新最小值。

示例 1 合法候选按分钟升序为 960（9 分 60 秒，费用 9）、1000（10 分 0 秒，费用 6），最终选择后者。

正确性说明

穷尽表示：任何合法输入补零后都对应一个 0～99 的分钟值与秒数值，且满足时间方程。因此枚举不会漏掉其表示。

去前导零安全：删除前导零保留了时间。原路径先到 0 再到首个非零数字，删除后可直接到该数字，移动次数不会增加，且少付至少一次正的按压费。因此带前导零不会更优。

精确计费：输入串固定时，必须依序按下每个字符；不同数字间至少移动一次，同数字无需移动。模拟正好达到这一下界。比较所有候选的精确最小费用，得到全局最优。

边界与复杂度

  • 1 秒可只按 1，起点相同时无需移动。
  • 60～99 秒可直接放在秒数栏，不必强制进位。
  • 6039 秒只可表示为 9999；不能输出 100 分钟。
  • 重复数字每次收费，但不重复收移动费。
  • 单候选费用不超过 4 × (moveCost + pushCost) ≤ 800000，四语言的所用数值类型足够。

枚举 100 次，每个合法串至多 4 位：时间 O(100 × 4) = O(1)，额外空间 O(4) = O(1)。这里的常数来自题目固定上限。

替代方案与面试追问

设 q = targetSeconds // 60，r = targetSeconds % 60。合法候选只可能是 (q, r) 或 (q−1, r+60)，仍需逐个检查分钟、秒数范围；减少两分钟时秒数至少 120，已不合法。只检查这两个候选也为 O(1)。

为何不用动态规划？候选极少，确定顺序后无额外决策。

若移动费用依赖数字对？需重新审视去前导零证明。若费用不满足三角不等式，先按 0 可能充当更便宜的中转；可以枚举全部至多四位的输入串，或对数字图建模。

按键越少一定越省吗？不一定，移动费用也影响排序；示例 1 的四位串就胜过三位串。

常见错误

  • 只考虑秒数 0～59，漏掉更便宜的 60～99 秒表示。
  • 直接按总秒数，如 600 秒按 600 会被解释成 6 分钟。
  • 补足四位后全部按下，引入不必要的前导零费用。
  • 把所有零删除，破坏分钟与秒数的十进制位置。
  • 跨候选沿用上一次手指位置，或给相同数字重复计移动费。
  • 只按字符串长度选答案，忽略移动次数；误把秒数 99 当作非法。

四语言完整代码

Java

class Solution {
    public int minCostSetTime(int startAt, int moveCost, int pushCost, int targetSeconds) {
        int answer = Integer.MAX_VALUE;
        for (int minutes = 0; minutes <= 99; minutes++) {
            int seconds = targetSeconds - 60 * minutes;
            if (seconds < 0 || seconds > 99) continue;
            String digits = Integer.toString(minutes * 100 + seconds);
            int finger = startAt, cost = 0;
            for (char ch : digits.toCharArray()) {
                int digit = ch - '0';
                if (finger != digit) cost += moveCost;
                cost += pushCost;
                finger = digit;
            }
            answer = Math.min(answer, cost);
        }
        return answer;
    }
}
