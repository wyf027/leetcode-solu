01 · Problem

题意与边界

以下内容依据官方元数据准确转述。函数接收完整参数 edges: integer[][]，返回 integer[]。

题目描述

树是一张连通且没有环的无向图。现在有一棵包含 n 个节点的树，节点编号为 1 到 n；在它的基础上又加入了一条原本不存在、连接两个不同节点的边。

输入数组 edges 长度为 n，其中 edges[i] = [aᵢ, bᵢ] 表示一条无向边。请返回一条可删除的边，使剩余图重新成为一棵含 n 个节点的树；若存在多个可行答案，返回在输入中最后出现的那一条。

约束

  • n == edges.length
  • 3 ≤ n ≤ 1000
  • edges[i].length == 2
  • 1 ≤ aᵢ < bᵢ ≤ edges.length
  • aᵢ != bᵢ
  • edges 中没有重复边
  • 给定的图保证连通

官方示例 1

输入
edges = [[1,2],[1,3],[2,3]]
输出
[2,3]
说明
删除 [2,3] 后，三点仍连通且不再成环。

官方示例 2

输入
edges = [[1,2],[2,3],[3,4],[1,4],[1,5]]
输出
[1,4]
说明
删除 [1,4] 后，五个节点组成一棵树。

04 · Solution

并查集：边来之前先问一次

核心不是“删边后再检查”，而是按顺序建图：每条边加入之前，判断它的两个端点是否已经连通。

核心洞察

树中任意两点之间只有一条简单路径。如果准备加入边 [u, v] 时，u 与 v 已经连通，那么已有路径加上新边会构成一个环，这条新边就是当前扫描顺序下的冗余边。

并查集维护“哪些节点已经属于同一个连通分量”。find(x) 找到分量代表，union(a,b) 合并两个分量。若两个端点代表相同，直接返回当前边。

完整过程

  1. 初始化 parent[i] = i，每个节点自成一个集合；可选地维护秩或集合大小。
  2. 按照输入顺序遍历每条边 [u, v]。
  3. 分别求 u 和 v 的根。
  4. 若根相同，说明加入前已有一条路径连接二者，当前边闭合了环，返回它。
  5. 否则合并两个根，继续处理下一条边。

为什么“第一条检测到的”满足最后出现规则？

题目保证输入来自一棵树再加一条边，因此整张图只有一个环。沿输入顺序加入边时，在环上的最后一条输入边出现之前，已加入的图仍是森林；该边出现时，它的两端才首次已经连通。

所以扫描过程中唯一一次合并失败的边，恰好是环上按输入顺序最后出现的边，也就是题目要求的答案。

正确性证明

不变量：在处理第 i 条边之前，并查集中的两个节点属于同一集合，当且仅当它们在前 i-1 条已接纳边构成的图中连通。初始化时没有边且每点独立，不变量成立；接纳一条连接不同集合的边后，合并这两个集合，恰好反映新增的连通关系，因此不变量保持。

返回边的正确性：当算法遇到根相同的 [u,v]，由不变量可知已有路径连接 u 与 v。加入该边会形成环；删除它则保留此前所有连通关系，并继续保有原树结构，所以它是合法答案。

答案顺序：图只有一个环。环上最后出现的边加入时，其余环边已提供一条端点间路径；任何更早的环边加入时，环尚未闭合。因此算法返回的正是输入中最后可作为答案的边。

复杂度

O(n · α(n))时间：路径压缩 + 按秩合并；α 是反阿克曼函数，实际近似常数。
O(n)空间：父节点数组与秩/大小数组。

边界情况

  • 最小规模 n = 3，三条边构成三角形。
  • 冗余边可能出现在输入中间；它后面仍可能有连接新节点的树边，检测到时仍可立即返回。
  • 冗余边可能连接编号相差很大的两个节点；节点编号大小与连通关系无关。
  • 树可能退化成长链，路径压缩保证查找仍然高效。
  • 题目保证连通、无自环、无重复边，因此无需处理不存在答案或重复输入的情况。

class Solution {
    private int[] parent;
    private int[] rank;

    public int[] findRedundantConnection(int[][] edges) {
        int n = edges.length;
        parent = new int[n + 1];
        rank = new int[n + 1];

        for (int i = 1; i <= n; i++) {
            parent[i] = i;
        }

        for (int[] edge : edges) {
            int u = edge[0];
            int v = edge[1];
            if (!union(u, v)) {
                return edge;
            }
        }
        return new int[0];
    }

    private int find(int x) {
        if (parent[x] != x) {
            parent[x] = find(parent[x]);
        }
        return parent[x];
    }

    private boolean union(int a, int b) {
        int rootA = find(a);
        int rootB = find(b);
        if (rootA == rootB) {
            return false;
        }
        if (rank[rootA] < rank[rootB]) {
            parent[rootA] = rootB;
        } else if (rank[rootA] > rank[rootB]) {
            parent[rootB] = rootA;
        } else {
            parent[rootB] = rootA;
            rank[rootA]++;
        }
        return true;
    }
}

var findRedundantConnection = function(edges) {
    const n = edges.length;
    const parent = Array.from({ length: n + 1 }, (_, i) => i);
    const rank = new Array(n + 1).fill(0);

    const find = (x) => {
        if (parent[x] !== x) {
            parent[x] = find(parent[x]);
        }
        return parent[x];
    };

    const union = (a, b) => {
        let rootA = find(a);
        let rootB = find(b);
        if (rootA === rootB) return false;

        if (rank[rootA] < rank[rootB]) {
            [rootA, rootB] = [rootB, rootA];
        }
        parent[rootB] = rootA;
        if (rank[rootA] === rank[rootB]) {
            rank[rootA]++;
        }
        return true;
    };

    for (const [u, v] of edges) {
        if (!union(u, v)) {
            return [u, v];
        }
    }
    return [];
};
from typing import List


class Solution:
    def findRedundantConnection(self, edges: List[List[int]]) -> List[int]:
        n = len(edges)
        parent = list(range(n + 1))
        rank = [0] * (n + 1)

        def find(x: int) -> int:
            if parent[x] != x:
                parent[x] = find(parent[x])
            return parent[x]

        def union(a: int, b: int) -> bool:
            root_a = find(a)
            root_b = find(b)
            if root_a == root_b:
                return False

            if rank[root_a] < rank[root_b]:
                root_a, root_b = root_b, root_a
            parent[root_b] = root_a
            if rank[root_a] == rank[root_b]:
                rank[root_a] += 1
            return True

        for u, v in edges:
            if not union(u, v):
                return [u, v]
        return []
class Solution {
private:
    vector<int> parent;
    vector<int> rankValue;

    int find(int x) {
        if (parent[x] != x) {
            parent[x] = find(parent[x]);
        }
        return parent[x];
    }

    bool unite(int a, int b) {
        int rootA = find(a);
        int rootB = find(b);
        if (rootA == rootB) {
            return false;
        }
        if (rankValue[rootA] < rankValue[rootB]) {
            swap(rootA, rootB);
        }
        parent[rootB] = rootA;
        if (rankValue[rootA] == rankValue[rootB]) {
            rankValue[rootA]++;
        }
        return true;
    }

public:
    vector<int> findRedundantConnection(vector<vector<int>>& edges) {
        int n = static_cast<int>(edges.size());
        parent.resize(n + 1);
        rankValue.assign(n + 1, 0);
        iota(parent.begin(), parent.end(), 0);

        for (const auto& edge : edges) {
            if (!unite(edge[0], edge[1])) {
                return edge;
            }
        }
        return {};
    }
};

替代方案：DFS / BFS

也可以维护邻接表。处理每条边前，从 u 搜索是否能到达 v；能到达则当前边冗余，否则把边加入邻接表。

该方案直观，但每条边都可能遍历整张当前图，最坏时间复杂度为 O(n²)，空间复杂度为 O(n)。并查集更贴合“动态合并连通分量”。

面试追问

  • 若图中可能有多条额外边，怎样返回所有导致环的边？
  • 若边可以删除，普通并查集为什么不够？可否使用可回滚并查集？
  • 若图是有向图，问题会变成什么？入度冲突与有向环怎样组合判断？
  • 路径压缩与按秩合并分别解决什么退化问题？
  • 为什么这里数组大小可直接使用 edges.length + 1？

常见错误

先合并再判断。 合并后两个端点必然同根，会把每条边都误判。必须先比较根，再决定是否合并。
节点数组只开到 n。 节点编号从 1 开始且最大为 n，应开 n + 1。
只看节点度数。 环上的节点度数不一定能唯一标识冗余边，度数不是连通性证明。
忽略输入顺序。 题目要求多个答案时返回最后出现者；顺序扫描并返回闭环边恰好满足要求。
递归 find 不回写父节点。 仍可能正确，但失去路径压缩，树高可能造成性能退化。
