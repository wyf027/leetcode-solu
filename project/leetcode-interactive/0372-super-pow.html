题目是什么

给定正整数 a，以及用十进制数字数组表示的一个极大正整数 b，请返回 ab 对 1337 取模后的结果。

数组中的数字按通常的书写顺序排列。例如 b = [1, 0] 表示指数 10，而不是两个独立指数。

输入 1a：正整数
输入 2b：十进制数字数组
返回整数余数
ab mod 1337

关键挑战不是底数，而是指数最多有 2000 位，不能先把整个 b 转为普通整数。

题解：逐位处理十进制指数

核心洞察 完整过程 正确性 边界 复杂度 四语言代码 替代方案 面试追问 常见错误

核心洞察

!

不用构造完整指数。设已经读过的指数前缀为 p，下一位数字为 d，那么新前缀就是 10p + d。因此可以把一次巨大幂拆成两个指数很小的幂，并始终取模。

a10p+d = (ap)10 × ad

如果当前保存的是 r = ap mod 1337，读入数字 d 后只需更新：

r ← (r10 mod 1337) × (ad mod 1337) mod 1337

幂指数只会是 10 或 0—9，用快速幂计算即可。更一般地，即使不写快速幂，固定最多乘 10 次也仍是线性时间；快速幂让方法更规范、也便于迁移到更大基数。

完整过程

  1. 令模数 MOD = 1337，答案 result = 1，并先把 a 归一化为 a mod MOD。
  2. 从左到右遍历数组 b 中的每一位数字 digit。
  3. 把旧前缀在十进制中左移一位：对应把旧结果提升到 10 次方，即 powMod(result, 10)。
  4. 补上当前个位数字：乘上 powMod(a, digit)。
  5. 乘法后再次对 1337 取模；所有中间值都保持很小。
  6. 数组遍历结束时，前缀就是完整指数，返回 result。

正确性证明

循环不变式：处理完 b 的前 i 位后，result 等于 a 的该十进制前缀次方对 1337 的余数。

初始化

尚未读取任何数字时，指数前缀可视为 0；初始化 result = 1，而 a0 = 1，不变式成立。

保持

假设旧前缀为 p 且不变式成立。读入 d 后新前缀为 10p+d。更新式利用幂的乘法性质，所得余数正是 a10p+d mod 1337，所以不变式继续成立。

终止

遍历结束时，已处理前缀就是完整的 b，由循环不变式，result = ab mod 1337。

取模合法性

同余在乘法与非负整数次幂下保持，因此每一步用余数替换原值不会改变最终模 1337 的结果。

边界情况

  • a = 1：任意正指数的结果都为 1，通用流程自然得到该结果。
  • a 是 1337 的倍数：因为 b 是正整数，结果为 0；通用流程同样适用。
  • 指数含数字 0：a0 在某一步只是乘法因子 1，但前缀整体不一定为 0，不能跳过“十次方”部分。
  • 最大底数：先对 1337 取模；乘法中间值远小于 32 位有符号整数上限，但实现仍可用更宽类型表达意图。
  • 2000 位指数：只逐位扫描，不把指数拼成数字，因此长度不会造成整数溢出。

复杂度

时间O(n)
额外空间O(1)
nb.length

每个数字执行两次指数上界为 10 的模幂，属于常数工作量，因此总时间随数字个数线性增长。

四语言完整代码

以下均遵循官方可提交签名，采用相同的逐位递推。

JavaLeetCode signature
class Solution {
    private static final int MOD = 1337;

    public int superPow(int a, int[] b) {
        int base = a % MOD;
        int result = 1;

        for (int digit : b) {
            result = (powMod(result, 10) * powMod(base, digit)) % MOD;
        }
        return result;
    }

    private int powMod(int base, int exponent) {
        int result = 1;
        base %= MOD;

        while (exponent > 0) {
            if ((exponent & 1) == 1) {
                result = (result * base) % MOD;
            }
            base = (base * base) % MOD;
            exponent >>= 1;
        }
        return result;
    }
}

from typing import List


class Solution:
    MOD = 1337

    def superPow(self, a: int, b: List[int]) -> int:
        base = a % self.MOD
        result = 1

        for digit in b:
            result = (
                self._pow_mod(result, 10)
                * self._pow_mod(base, digit)
            ) % self.MOD

        return result

    def _pow_mod(self, base: int, exponent: int) -> int:
        result = 1
        base %= self.MOD

        while exponent > 0:
            if exponent & 1:
                result = result * base % self.MOD
            base = base * base % self.MOD
            exponent >>= 1

        return result

替代方案

从尾部递归分解

利用 a10q+d = (aq)10ad，从数组末尾取数字并递归处理剩余前缀。数学本质相同，但若修改输入数组或递归层数达到 2000，需要额外留意副作用与调用栈。

欧拉定理 / CRT

1337 = 7 × 191，可按因子分别处理再用中国剩余定理合并，也可在满足互质条件时缩减指数。这个方向能展示数论能力，但必须正确处理底数与模数不互质的情况，实现明显更复杂。

面试追问

为什么不能直接把 b 转成整数？

b 最长 2000 位，远超 64 位整数范围；即使用大整数，构造并对如此巨大的指数做常规幂运算也不是本题想要的线性扫描解法。

为什么可以在每一步提前取模？

若 x ≡ y (mod m)，则对非负整数 k 有 xk ≡ yk (mod m)，同余也对乘法封闭。因此提前取模不改变最终余数。

如果指数数组改成二进制位数组，递推如何变化？

新前缀从 10p+d 变成 2p+d，更新式相应变为 r ← r² × ad mod m。

模数不再固定为 1337，会影响方法吗？

逐位递推本身不依赖 1337 的因数结构，对任意正模数都成立；只需注意具体语言中乘法是否会在取模前溢出，必要时使用 64 位或安全模乘。

常见错误

  • 把数字数组误当成若干独立指数，或从右向左直接套用左到右的递推。
  • 遇到数字 0 就完全跳过本轮；实际上旧结果仍然必须提升到 10 次方。
  • 先拼出完整指数，再调用语言自带幂函数，导致溢出或不可接受的计算。
  • 只在最后取模，使中间幂和乘积迅速溢出。
  • 使用欧拉函数缩减指数时，忽略 a 与 1337 不互质的情形。
