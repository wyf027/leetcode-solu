Minimum Number of Keypresses

最少按键次数

九个按键，二十六个字母。怎样设计键盘，才能让一段文字输入得更省力？

离线单文件先思考 · 再展开所有验证待补

01 / PROBLEM

题目与输入约定

给定字符串 s，请设计一套固定的九键布局，使输入整个字符串的总按键次数最少，并返回这个最小值。

  • 按键编号为 1～9；每个按键可以按顺序放置至多 3 个字母。
  • 全部 26 个英文小写字母都要放入布局，每个字母只出现一次。
  • 输入一个字母的代价等于它在所属按键中的位置：第 1、2、3 位分别按 1、2、3 次。
  • 布局可在输入前设计，但输入过程中不能改变。连续相同字母也逐个计费，不额外计算停顿或分隔操作。

函数契约

minimumKeypresses(s: string) → integer

唯一参数 s；返回次数，不要求返回键盘布局。

约束

  • 1 ≤ s.length ≤ 100000
  • s 仅包含英文小写字母 a～z。

示例 1

输入：s = "apple"
输出：5

一种可行的最优布局使 a、p、l、e 分别位于不同按键的第一位；五个字符各按一次，总计 5 次，其余字母可放入剩余位置。

示例 2

输入：s = "abcdefghijkl"
输出：15

可让 a～i 位于九个按键的第一位，j、k、l 位于三个按键的第二位。总计 9 × 1 + 3 × 2 = 15 次，其余字母补齐布局。

04 / SOLUTION LAB

独立题解

展开后可查看核心推导、键盘实验室与四语言实现。

把高频字母放在便宜的位置

真正影响代价的是“出现频率 × 每次按键数”。九个按键各有一个只需按一次的位置，再各有一个需要按两次的位置，最后最多还有九个三次位置。26 个字母使用前 26 个槽位，留下一个空槽。

9 × [1次] → 9 × [2次] → 8 × [3次]

完整过程

  1. 扫描 s，用长度为 26 的数组统计每个字母出现次数。
  2. 按频率从大到小排列。频率相同的字母顺序任意；演示用字母序打破平局。
  3. 从 0 开始编号，第 i 个字母安排到按键 i % 9 + 1 的第 floor(i / 9) + 1 位。
  4. 累加 frequency[i] × (floor(i / 9) + 1)。零频率字母仍能补全布局，但贡献为零。

0

频率队列

字母 / 次数 / 每次成本；橙色为当前项。

正确性 · 交换论证

设两个字母频率为 f ≥ g，却分别被放在代价 p > q 的位置。交换前后代价之差为 fp + gq − (fq + gp) = (f − g)(p − q) ≥ 0。因此，把高频字母移到较便宜的位置不会让结果变差。

消除所有这样的逆序，就得到频率降序、代价升序的配对。所有浅层位置都能先于深层位置填满，按 i % 9 循环分配确保每键最多三个字母、每字母仅放一次，26 个字母都能容纳。因此该配对可实现且全局最优。

边界与复杂度

  • 不同字母不超过 9 个时，全部出现过的字母都能按一次输入，答案等于 s.length。
  • 第 10、19 种字母分别进入两次、三次区；同频字母的排列不影响答案。
  • 未出现的字母频率为 0。代码可以保留它们，它们自然排在最后；布局中也必须容纳它们。
  • 若字符集大小记为 σ，时间 O(n + σ log σ)，空间 O(σ)。本题 σ = 26 固定，所以为 O(n) 时间、O(1) 额外空间。
  • 答案不超过 3n ≤ 300000，四种语言的常用整数表示都足够。空串与大写字符不在官方输入范围内，实验室会拒绝。

替代方案

可以用最大堆依次取最高频字母，时间仍是 O(n + σ log σ)，但维护堆没有优势。也可按频率建桶做到 O(n + σ)，需要 O(n + σ) 空间；只有 26 个字母时直接排序更简单。穷举全部布局会产生阶乘数量级的候选，不适合本题。

常见错误

  • 把 9 个按键误记为常见电话键盘的 8 个字母键，本题明确使用 1～9。
  • 按字母序或首次出现顺序分配，忽略重复字母的频率。
  • 分组写成 i / 3；每层容量是 9，正确分母为 9。
  • JavaScript 的 sort() 未传数值比较器；默认按字符串排序。
  • 只加每个字母的成本，没有乘出现次数；或者误加同键相邻字符的等待代价。

面试追问

  • 如果有 k 个按键、每键 c 位？ σ ≤ kc 时使用 floor(i / k) + 1，否则无法容纳全部字符。
  • 如果每个键的按压代价不同？ 列出可用槽位的实际代价，按代价升序与频率降序配对；若还有位置先后限制，需先确认这种排列可实现。
  • 如何返回布局？ 排序时保留字符，按 i % 9 分到各键并按层追加即可。
  • 字符串排列是否重要？ 本题各字符独立计费，频率相同的任意排列答案相同；加入同键切换成本后，这个条件将不再成立。

四语言完整实现

按官方元数据中的 minimumKeypresses(s) 接口实现。元数据的代码模板为空，以下使用 LeetCode 常见提交形式，未编译或提交。

Java

import java.util.Arrays;

class Solution {
    public int minimumKeypresses(String s) {
        int[] frequency = new int[26];
        for (int i = 0; i < s.length(); i++) {
            frequency[s.charAt(i) - 'a']++;
        }
        Arrays.sort(frequency);
        int answer = 0;
        for (int i = 0; i < 26; i++) {
            answer += frequency[25 - i] * (i / 9 + 1);
        }
        return answer;
    }
}

/**

var minimumKeypresses = function(s) {
    const frequency = Array(26).fill(0);
    for (const ch of s) {
        frequency[ch.charCodeAt(0) - 97]++;
    }
    frequency.sort((a, b) => b - a);
    let answer = 0;
    for (let i = 0; i < 26; i++) {
        answer += frequency[i] * (Math.floor(i / 9) + 1);
    }
    return answer;
};

Python

class Solution:
    def minimumKeypresses(self, s: str) -> int:
        frequency = [0] * 26
        for ch in s:
            frequency[ord(ch) - ord('a')] += 1
        frequency.sort(reverse=True)
        answer = 0
        for i, count in enumerate(frequency):
            answer += count * (i // 9 + 1)
        return answer

            ++frequency[ch - 'a'];
        }
        sort(frequency.begin(), frequency.end(), greater<int>());
        int answer = 0;
        for (int i = 0; i < 26; ++i) {
            answer += frequency[i] * (i / 9 + 1);
        }
        return answer;
    }
