01题目与规则

给定从下标 0 开始的字符串 hamsters。字符 H 代表仓鼠，字符 . 代表空位。你只能在空位放置食物桶。

位于下标 i 的仓鼠，只能吃到紧邻的 i − 1 或 i + 1 位置上的食物；只要其中一侧有桶，就算被喂养。一个桶可以供左右两只相邻仓鼠使用。

返回喂养所有仓鼠所需的最少食物桶数；如果无法全部喂养，返回 -1。

参数 / 返回值

minimumBuckets(hamsters: string) → integer

完整约束

1 ≤ hamsters.length ≤ 10⁵
hamsters[i] ∈ {'H', '.'}

官方示例

示例 1
输入：hamsters = "H..H"
输出：2

在下标 1、2 各放一个桶。只放一个桶无法同时覆盖两只仓鼠。

示例 2
输入：hamsters = ".H.H."
输出：1

在下标 2 放一个桶，左右两只仓鼠都能吃到。

示例 3
输入：hamsters = ".HHH."
输出：-1

中间下标 2 的仓鼠两侧都是仓鼠，即使填满空位也无法喂养它。

依据随任务提供的官方元数据转述。中文源示例 2、3 的旧参数名 street 在此统一为签名参数 hamsters。

03题解 · 向右留一次共享机会

从左到右：先检查已喂养，再优先右边，最后尝试左边。
当前仓鼠尚未被覆盖时，右侧的桶既能喂它，也可能喂到下一只仓鼠；左侧的桶只能额外影响已经处理过的位置。

核心洞察与完整过程

  1. 维护桶数 ans = 0 和最后一个桶的位置 last = -2。使用 -2 是为了避免把下标 0 的左侧误判为已有桶。
  2. 按下标从左到右扫描；空位直接跳过。
  3. 若 last == i - 1，当前仓鼠已被左边的桶覆盖，无需加桶。
  4. 否则优先检查 i + 1 是否在界内且为空；可以就在那里放桶。
  5. 右边不行，再检查左侧 i - 1 是否为空；可以就在那里放桶。
  6. 两侧都不可用，立刻返回 -1；成功放桶就更新 last 并增加桶数。扫描结束返回桶数。

不必修改原字符串。已经放过的桶只可能通过左邻位置影响当前仓鼠；更早的桶不可能再次覆盖未来位置，所以仅记录最后一个桶即可。

过程示例：hamsters = ".H.H."

跳过下标 0 → 处理下标 1，在右侧下标 2 放桶，计数为 1 → 跳过原空位 2 → 处理下标 3，发现 last = 2 = i − 1，复用同一个桶 → 跳过下标 4 → 返回 1。

正确性：交换论证 + 扫描不变式

不变式：处理下标 i 前，所有更早的仓鼠均已被喂养，并且存在一个最优方案包含目前贪心放置的桶。初始时没有已处理仓鼠，显然成立。

如果当前仓鼠已有左桶，不新增桶即可保持不变式。否则任何可行方案都必须在它的某个空邻格放桶。如果右侧可放，而某个最优方案只选择左侧，就把该左桶换到右侧：它仍然喂养当前仓鼠；左桶唯一可能额外喂养的仓鼠位于 i − 2，已被此前贪心桶覆盖。该左桶也不是此前贪心桶，否则当前仓鼠本来就已被覆盖。因此交换不会破坏此前覆盖，桶数不增加，还可能覆盖 i + 2。

若右侧不可放，左侧是唯一可选位置，必须放；若两侧都不可放，则当前仓鼠无法被任何方案喂养，返回 -1 正确。归纳至扫描结束，所有仓鼠均被覆盖，且所用桶可包含在一个最优方案中，因此桶数最小。

边界与复杂度

  • 没有仓鼠返回 0；单独的 H 返回 -1；H. 和 .H 返回 1。
  • 连续两只仓鼠未必无解：.HH. 需要 2 个桶；三只连续仓鼠的中间一只一定无解。
  • 首尾不存在的邻格不能放桶；读字符前必须判断边界。
  • 时间 O(n)，额外空间 O(1)。下方四语言均采用只读输入与最后桶位置；C++ 参数按官方签名按值传入，若计入输入副本，函数调用另有 O(n) 字符串复制空间。教学动画为了可回退保存快照，不代表提交算法的空间开销。

Java

class Solution {
    public int minimumBuckets(String hamsters) {
        int n = hamsters.length(), last = -2, ans = 0;
        for (int i = 0; i < n; i++) {
            if (hamsters.charAt(i) != 'H' || last == i - 1) {
                continue;
            }
            if (i + 1 < n && hamsters.charAt(i + 1) == '.') {
                last = i + 1;
            } else if (i > 0 && hamsters.charAt(i - 1) == '.') {
                last = i - 1;
            } else {
                return -1;
            }
            ans++;
        }
        return ans;
    }
}

替代方案

可变字符数组：把放桶的位置标记为 B，检查左邻是否为 B，决策顺序相同；时间 O(n)，复制数组需要 O(n) 空间，直观但并非必要。

动态规划：逐格决定空位是否放桶，保留最近两个位置的占用状态；确定当前格后，检查前一格若有仓鼠是否得到左右覆盖。使用常数个状态维护最小桶数，在边界加不可放桶的虚拟格；时间 O(n)，滚动状态空间 O(1)。更适合扩展为各空位放桶费用不同的版本。

常见错误

  • 总是优先向左：.H.H. 可能放出两个桶，错过中间共享。
  • 不先检查已有桶：同一只仓鼠已经吃得到食物，却又放一个桶。
  • 遇到 HH 就返回 -1：忽略两端有空位的 .HH.。
  • 把 last 初始化为 -1：会把开头的仓鼠误认为左侧有桶。
  • Python 直接读取 hamsters[i - 1] 而不检查 i > 0：负下标会读取末尾。

面试追问

  • 为什么只存最后一个桶？覆盖半径为 1，扫描向右推进后，更早的桶无法再影响未处理仓鼠。
  • 如何返回放桶位置？每次新增桶记录 last；返回列表需 O(k) 输出空间，k 为桶数。
  • 若不同空位费用不同？右优先不再保证最低费用，可用最近两格状态的动态规划。
  • 如果桶只能供一只仓鼠吃？共享不再成立，需要把仓鼠与相邻空位的独占分配作为匹配问题处理。
