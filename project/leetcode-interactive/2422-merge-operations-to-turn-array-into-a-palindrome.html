使用合并操作将数组
转换为回文序列

Merge Operations to Turn Array Into a Palindrome

把相邻的两个数字变成一个和。怎样让两端最终互为镜像？

01 / PROBLEM

题目与约定

给定正整数数组 nums。一次操作可以选中两个相邻的元素，以它们的和替换这两个数，因此数组长度减少 1。你可以操作任意次，包括 0 次。请返回使数组成为回文序列所需的最少操作次数。

回文序列从左向右和从右向左读完全相同。只能合并相邻元素，不能重排、删除或拆分元素；单个元素也构成回文。

官方示例 1

输入：nums = [4,3,2,1,2,3,1]
输出：2

可先合并原数组第 4、5 个元素，再合并新数组最后两个元素：

[4,3,2,1,2,3,1]
→ [4,3,2,3,3,1]
→ [4,3,2,3,4]

结果左右对称，最少需要 2 次。

官方示例 2

输入：nums = [1,2,3,4]
输出：3

把整个数组合成一个元素 [10]，需要 3 次操作；无法用更少的操作得到回文。

约束与接口

1 ≤ nums.length ≤ 100000
1 ≤ nums[i] ≤ 1000000
minimumOperations(nums: integer[]) → integer

03 / SOLUTION

准备好拆解思路了吗？

核心洞察：从两端累加，较小的一侧继续合并

最终数组是原数组的一种连续分段，每个元素等于一段的和。若保留 k 段，就要合并 n − k 次。因此应尽可能早地找到和相等的左右外层段，保留它们，再解决中间部分。

两端不等

较小块必须吞入内侧相邻元素。所有数都为正，增大较大块无法消除差距；先扩展小块是不可避免的一步。

两端相等

把这两个块锁定为一对，向中间继续。锁定不执行合并，所以操作次数不增加。

完整过程

  1. 令 i = 0、j = n − 1，两端累加和为 left = nums[i]、right = nums[j]，答案为 0。
  2. 当 i < j：若 left < right，先递增 i，再把 nums[i] 加入 left，答案加 1；右端较小时对称处理。
  3. 若两端和相等，同时移动 i、j；若指针仍未交叉，重新加载下一对段的初始和。此分支不增加答案。
  4. 指针相遇或交叉后结束。相遇意味着中央只剩一个块；交叉意味着全部成对锁定。

示例 1 的贪心顺序可以是：右侧 3 + 1 = 4，锁定外层 4；右侧 1 + 2 = 3，锁定下一层 3；中间留下 2。合并顺序与题目示例不同，但都只需 2 次。

正确性：为什么不需要回头？

不变量：锁定的外层块两两等和；左右活动块由未锁定区间的前缀、后缀构成，块内的每次吸收恰好计为一次合并。

较小侧的扩展是必需的：设左右段和为 L、R，且 L < R。任何外层等和方案中，左段若不吸收下一个元素，其和仍为 L；右段只会变大，无法相等。因此先合并左段不会排除最优解。R < L 同理。

第一次相等可以立即固定：设最短匹配外层段和为 S。任一更大外层匹配方案都必须包含这两个最短段。把更大段两侧各减去 S，剩余部分仍然等和，可在内部继续保留为镜像块；若原方案把所有元素合成一个块，也可拆出这对外层块以及可能存在的中心块。故保留最短匹配段不会减少最终块数，也就不会增加合并次数。

归纳与终止：固定一对后，中间仍是相同类型的正整数数组问题。每轮至少移动一个指针，最终剩余 0 或 1 个块，本身已是回文。结合必需合并与安全锁定，得到最少操作数。

边界与复杂度

  • 单元素、已有回文、全相同数组：答案均为 0；两个不等元素：答案为 1。
  • 答案范围为 0 至 n − 1。段和最大为 1011，Java 使用 long，C++ 使用 long long；JavaScript 的 Number 可精确表示该范围整数，Python int 自动扩展。
  • 四份提交代码均不修改输入。指针只向内移动：时间 O(n)，额外空间 O(1)。
  • 演示为了回退保留整帧、使用数组拼接，最坏时间与空间为 O(m²)，m ≤ 32；该可视化开销不属于提交算法。

替代方案

可以直接把较小端累加到邻居，再移动指针，仍是 O(n) 时间，但会修改输入，且 Java 的 int[] 无法安全保存大段和。枚举所有连续分段有 2n−1 种，仅适合很短数组的理论穷举。区间动态规划需要更多状态与分割搜索，正整数条件已允许线性贪心，无需引入。

常见错误

  • 只比较原始单个元素、不保存累计段和，会漏掉跨多个元素才能相等的情况。
  • 给“锁定相等块”也计一次操作，混淆指针推进和实际合并。
  • 累加使用 32 位整数，长数组上会溢出。
  • 在正式算法里不断 splice 或删除中间元素，导致整体搬移、退化为 O(n²)。
  • 允许重排或合并不相邻元素，改变了问题本身。

面试追问

含负数还成立吗？不成立，扩展较大侧可能使其变小。例如 [2,−1,1] 只需合并前两项，得到 [1,1]；较小端优先会多做一次。
如何输出操作序列？跟踪每个块在原数组中的起止下标，每次记录合并的两个相邻区间；记录本身需要 O(n) 空间。
怎样解释最大保留块数？每次操作恰好减少一个块，最终 k 块的成本必为 n − k，与合并顺序无关。

完整提交代码

采用官方方法名 minimumOperations；使用两端累计和，不修改 nums。以下代码仅生成，尚未编译或运行。

Java
class Solution {
    public int minimumOperations(int[] nums) {
        int i = 0, j = nums.length - 1, operations = 0;
        long left = nums[i], right = nums[j];
        while (i < j) {
            if (left == right) {
                i++;
                j--;
                if (i <= j) {
                    left = nums[i];
                    right = nums[j];
                }
            } else if (left < right) {
                left += nums[++i];
                operations++;
            } else {
                right += nums[--j];
                operations++;
            }
        }
        return operations;
    }
}
