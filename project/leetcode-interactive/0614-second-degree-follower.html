二级关注者 Second Degree Follower

先观察，再揭晓

先从关注关系图中识别“既关注别人、又被别人关注”的人。完整查询与证明被收在页面底部。

01

题目转述

把每条关注关系看成一条有方向的边，目标是找出网络里的中间层。

表 Follow 记录社交网络中的关注关系： follower 关注 followee。请报告所有“二级关注者”及其粉丝数。

某人必须同时满足两件事：他至少关注了一个人；也至少被一个人关注。输出列为 follower 与 num，并按姓名升序排列。

数据保证

  • followee、follower 均为 VARCHAR(255)。
  • 同一对关注关系唯一，且没有人关注自己。
  • 粉丝数按不同的 follower 计数。

从“集合交集”到一次分组

一个人是二级关注者，当且仅当他的名字既出现在 follower 列，也出现在 followee 列。对后者分组即可顺手得到粉丝数。

核心洞察

followee IN (SELECT follower ...) 保证这个人关注过别人；当前按 followee 聚合的行则证明他被别人关注，并给出粉丝数量。

完整过程

  1. 收集所有出现在 follower 列的人。
  2. 仅保留 followee 属于该集合的关系。
  3. 按 followee 分组，计算不同粉丝数。
  4. 把名字别名设为 follower 并升序输出。

边界情况

  • 空表或只有单向、互不衔接的边：结果为空。
  • 长链：除首尾以外的中间节点可能成为结果。
  • 若数据源不能保证关系唯一，使用 COUNT(DISTINCT ...) 防止重复计数。
  • 姓名排序遵循数据库当前字符集与排序规则。

复杂度

设关系数为 n、结果人数为 k。哈希聚合的期望处理成本为 O(n)，最终排序为 O(k log k)，额外空间 O(k)；实际执行计划取决于索引与数据库优化器。

正确性证明。 查询输出的任意人 x 出现在 follower 子查询中，因此 x 至少关注一人；同时，x 作为某组的 followee 至少拥有一行，因此至少被一人关注。故输出者一定是二级关注者，计数恰为关注 x 的不同人数。 反过来，任意二级关注者 y 同时出现在两列：成员条件不会过滤 y，按 followee 的分组也一定包含 y，故 y 不会漏掉。因此查询结果恰好等于全部二级关注者。

替代方案

  • EXISTS：用相关子查询验证当前 followee 是否也出现为 follower，语义直观，并可在合适索引下高效执行。
  • 自连接：把“被关注关系”与“关注别人关系”按人名连接；必须处理连接放大，通常仍要 DISTINCT。
  • 集合交集后再聚合：表达最接近定义，但通常比单次分组多一层结构。

代码实现

官方可提交语言 · MySQL
SELECT
    followee AS follower,
    COUNT(DISTINCT follower) AS num
FROM Follow
WHERE followee IN (
    SELECT follower
    FROM Follow
)
GROUP BY followee
ORDER BY follower;

import java.util.ArrayList;
import java.util.HashMap;
import java.util.HashSet;
import java.util.List;
import java.util.Map;
import java.util.Set;
import java.util.TreeMap;

public class SecondDegreeFollower {
    public record Result(String follower, int num) {}

    public static List<Result> solve(List<String[]> follow) {
        Set<String> followsSomeone = new HashSet<>();
        Map<String, Set<String>> followersByPerson = new HashMap<>();

        for (String[] relation : follow) {
            String followee = relation[0];
            String follower = relation[1];
            followsSomeone.add(follower);
            followersByPerson
                .computeIfAbsent(followee, key -> new HashSet<>())
                .add(follower);
        }

        Map<String, Integer> sorted = new TreeMap<>();
        for (Map.Entry<String, Set<String>> entry : followersByPerson.entrySet()) {
            if (followsSomeone.contains(entry.getKey())) {
                sorted.put(entry.getKey(), entry.getValue().size());
            }
        }

        List<Result> answer = new ArrayList<>();
        for (Map.Entry<String, Integer> entry : sorted.entrySet()) {
            answer.add(new Result(entry.getKey(), entry.getValue()));
        }
        return answer;
    }
}

/**
 * @param {Array<[string, string]>} follow [followee, follower]
 * @returns {Array<{follower: string, num: number}>}
 */
function secondDegreeFollower(follow) {
  const followsSomeone = new Set();
  const followersByPerson = new Map();

  for (const [followee, follower] of follow) {
    followsSomeone.add(follower);
    if (!followersByPerson.has(followee)) {
      followersByPerson.set(followee, new Set());
    }
    followersByPerson.get(followee).add(follower);
  }

  return [...followersByPerson.entries()]
    .filter(([person]) => followsSomeone.has(person))
    .map(([follower, followers]) => ({
      follower,
      num: followers.size,
    }))
    .sort((a, b) => a.follower.localeCompare(b.follower));
}

from collections import defaultdict
from typing import List, Tuple, TypedDict


class Result(TypedDict):
    follower: str
    num: int


def second_degree_follower(
    follow: List[Tuple[str, str]],
) -> List[Result]:
    follows_someone = set()
    followers_by_person = defaultdict(set)

    for followee, follower in follow:
        follows_someone.add(follower)
        followers_by_person[followee].add(follower)

    answer: List[Result] = []
    for person in sorted(followers_by_person):
        if person in follows_someone:
            answer.append({
                "follower": person,
                "num": len(followers_by_person[person]),
            })
    return answer

#include <map>
#include <set>
#include <string>
#include <utility>
#include <vector>

using Relation = std::pair<std::string, std::string>;
using Result = std::pair<std::string, int>;

std::vector<Result> secondDegreeFollower(
    const std::vector<Relation>& follow
) {
    std::set<std::string> followsSomeone;
    std::map<std::string, std::set<std::string>> followersByPerson;

    for (const auto& [followee, follower] : follow) {
        followsSomeone.insert(follower);
        followersByPerson[followee].insert(follower);
    }

    std::vector<Result> answer;
    for (const auto& [person, followers] : followersByPerson) {
        if (followsSomeone.count(person) != 0) {
            answer.emplace_back(person, static_cast<int>(followers.size()));
        }
    }
    return answer;
}

面试追问

  • 如果允许重复关系？保留 COUNT(DISTINCT follower)，或先对关系去重。
  • 数据量很大如何优化？讨论 follower、followee 单列或复合索引，并用 EXPLAIN 核对执行计划。
  • 如果要第 k 级关注者？需要递归 CTE 或图遍历，并明确去重、环和最短距离定义。

常见错误

  • 把箭头方向读反，统计了一个人关注的人数。
  • 只按 followee 分组，没有验证该人也关注别人。
  • 自连接后直接 COUNT，导致一对多连接放大。
  • 遗漏 ORDER BY，未满足指定的升序输出。
