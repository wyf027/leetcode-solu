04 / Spoiler gate

准备好核对思路了吗？

完整题解默认收起，包含证明、复杂度、四语言实现与面试追问。

Core insight

用符号位保存“是否出现”

值映射到下标

因为每个值 v 都在 [1,n]，所以它可唯一映射到合法下标 v-1。

负号充当标记

访问值 v 时，把 nums[v-1] 改成负数，表示 v 已经出现。

正数暴露缺失

标记完成后，若 nums[i] 仍为正数，就说明值 i+1 从未出现。

完整过程

  1. 第一次遍历：对每个下标 i，读取 v = abs(nums[i])。必须取绝对值，因为当前位置可能已被此前的元素标成负数。
  2. 原地标记：令 nums[v-1] = -abs(nums[v-1])。重复值只会再次把同一位置保持为负，不会把它错误地翻回正数。
  3. 第二次遍历：检查所有位置 i。凡是 nums[i] > 0 的位置，都把 i+1 加入答案。
  4. 返回结果：下标按从小到大扫描，因此答案天然递增，无需额外排序。

正确性说明

引理：第一次遍历后，位置 v-1 为负，当且仅当值 v 在原数组中至少出现一次。

证明：若 v 出现，遍历到该元素时一定会把位置 v−1 设为负；反过来，算法只会在读取到绝对值为 v 的元素时修改位置 v−1，所以该位置变负必然对应 v 的一次出现。重复出现不会改变这一事实。

结论：第二次遍历中位置 i 仍为正，等价于值 i+1 没出现；收集全部这样的 i+1，恰好得到且只得到所有缺失值。

边界情况

  • n = 1：[1] 没有缺失值。
  • 全部相同：同一位置被重复标记，其余正数位置全部被收集。
  • 没有缺失：每个位置都会为负，返回空数组。
  • 输入被修改：若调用方需要保留原数组，应先复制；这会引入 O(n) 额外空间。

复杂度

TimeO(n)
两次线性扫描。
Extra spaceO(1)
不计返回数组；标记复用输入数组。

四种语言完整实现

实现均遵循官方函数签名，并会原地修改输入数组。

Java 
class Solution {
    public List<Integer> findDisappearedNumbers(int[] nums) {
        for (int i = 0; i < nums.length; i++) {
            int value = Math.abs(nums[i]);
            int index = value - 1;
            nums[index] = -Math.abs(nums[index]);
        }

        List<Integer> answer = new ArrayList<>();
        for (int i = 0; i < nums.length; i++) {
            if (nums[i] > 0) {
                answer.add(i + 1);
            }
        }
        return answer;
    }
}

替代方案

  • 哈希集合：先记录所有出现值，再扫描 [1,n]；思路直接，时间 O(n)，额外空间 O(n)。
  • 计数数组：以长度 n 的数组记录频次；同样是 O(n) 时间与 O(n) 空间。
  • 循环置换：不断把值 v 放到下标 v−1，最后找错位位置；可做到 O(n)/O(1)，但交换逻辑更容易写错。
  • 排序：排序后寻找间隙，通常需要 O(n log n) 时间，且可能修改输入。

常见错误

  • 直接使用 nums[i] 作为下标，没有先取绝对值。
  • 写成 nums[index] *= -1，重复值会把负号翻回正号。
  • 混淆值 v 与下标 v−1，造成越界或 off-by-one。
  • 第二次遍历收集 i，而不是 i+1。
  • 宣称 O(1) 空间却先复制了整个数组。

面试追问

  1. 如果不允许修改输入怎么办？ 使用哈希集合或计数数组，接受 O(n) 额外空间。
  2. 如果数值不保证位于 [1,n] 呢？ 先验证并过滤范围外数据；原地位置映射不再能完整表示任意值域。
  3. 如何恢复输入数组？ 答案收集后再遍历一次，把每项改为绝对值，仍是 O(n) 时间。
  4. 能否找出重复数字？ 标记前若目标位置已经为负，当前值就是一个重复值；需考虑同一值重复三次以上时如何去重输出。
  5. 为什么返回数组不计额外空间？ 这是题目对辅助空间的口径；答案本身最坏仍可能占 O(n)。
