Greenhouse brief

题意

一个机器人位于 m × n 网格的左上角。它每次只能向右或向下移动一步，求到达右下角共有多少条不同路径。

Solution beds

题解

Core insight

核心洞察

到达 (r, c) 的最后一步只能来自上方或左侧，因此 ways[r][c] = ways[r−1][c] + ways[r][c−1]。 当逐行计算时，数组里的旧 dp[c] 正是“上方”，刚更新的 dp[c−1] 正是“左侧”。

Interview choice

为什么主推一维 DP

它保留了最容易解释和扩展的状态转移，同时把二维表压缩为一行。将较短维作为列后，额外空间降为 O(min(m,n))；下一题加入障碍物时也能直接复用。

Full pass

完整过程

  1. 1. 若列数更长，就交换 m 与 n，让数组更短。
  2. 2. 建立长度为 n 的数组，只令 dp[0] = 1。
  3. 3. 每一行从第 1 列开始更新：dp[c] += dp[c−1]。
  4. 4. 扫描完成后，dp[n−1] 就是右下角的路径数。

Boundaries

边界

  • • m = 1 或 n = 1：只有一条直线路径。
  • • m = n = 1：机器人已经在终点，答案为 1。
  • • 题目保证答案不超过 2 × 10^9，四语言的 32 位有符号整数足够。

Complexity

复杂度

时间
O(m × n)
额外空间
O(min(m, n))

Alternative

替代方案取舍

每条路径恰有 m−1 次向下和 n−1 次向右，因此答案是组合数 C(m+n−2, m−1)。它可用更少时间求值，但乘除顺序与溢出处理更容易被追问，也不便扩展障碍物。

Follow-ups

面试追问

  • • 如果有障碍物？遇到障碍时令 dp[c] = 0，其余转移不变。
  • • 如果要输出一条路径？保存父方向，或根据二维计数表反向恢复。
  • • 为什么可以交换维度？原问题关于主对角线对称，路径数满足 f(m,n)=f(n,m)。
  • • 组合数学如何避免溢出？逐项乘除并使用更宽整数类型，保持每一步整除。

Common mistakes

常见错误

  • • 把 dp 全部初始化为 1，却又从第 0 列更新，导致重复计数。
  • • 从右向左更新，使 dp[c−1] 仍是上一行而非当前行。
  • • 认为起点没有移动所以答案为 0；空动作本身就是一条有效路径。
  • • 递归枚举所有路径，复杂度指数增长，未利用重复子问题。

class Solution {
    public int uniquePaths(int m, int n) {
        if (n > m) {
            int temp = m;
            m = n;
            n = temp;
        }

        int[] dp = new int[n];
        dp[0] = 1;

        for (int row = 0; row < m; row++) {
            for (int col = 1; col < n; col++) {
                dp[col] += dp[col - 1];
            }
        }
        return dp[n - 1];
    }
}
