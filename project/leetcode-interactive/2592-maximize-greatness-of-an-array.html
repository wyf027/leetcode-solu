最大化数组的
伟大值

同一组数字，换一种站位，就能让多少个位置上的新数字严格大于原数字？先理解目标，再进入配对实验。

MEDIUM 贪心 双指针 排序 非付费题

题目

你可以任意重排数组，但每个元素必须恰好使用一次。比较始终发生在重排前后的同一下标。

任务定义

给定一个下标从 0 开始的整数数组 nums，将它重新排列为 perm。若某个下标 i 满足 perm[i] > nums[i]，这个位置就贡献 1 点伟大值。

返回所有可能排列中，能够取得的最大伟大值。

maximize |{ i : perm[i] > nums[i] }|

约束

  • 1 <= nums.length <= 105
  • 0 <= nums[i] <= 109
  • perm 必须是 nums 的一个排列

示例 1

输入nums = [1,3,5,2,1,3,1]

输出4

解释一种最优排列是 perm = [2,5,1,3,3,1,1]。下标 0、1、3、4 满足 perm[i] > nums[i]。

示例 2

输入nums = [1,2,3,4]

输出3

解释可取 perm = [2,3,4,1]，前三个下标满足严格大于。

题解：排序 + 双指针

核心洞察

把数组排序后，将一份视为等待被超过的目标，另一份视为可使用的候选。对最小的未配对目标，只要找到最小的、严格大于它的候选，就立即配对。

使用更大的候选不会让当前配对更有价值，反而可能浪费它去帮助后续更大的目标。

完整过程

  1. 将 nums 升序排序。
  2. i 指向最小未配对目标，j 扫描候选。
  3. 若 nums[j] > nums[i]，配对成功，答案加一，两个指针都前进。
  4. 否则候选不够大，仅让 j 前进。

边界情况

  • 只有一个元素：没有元素能严格超过自己，答案为 0。
  • 全部相等：所有比较都失败，答案为 0。
  • 严格递增：除最大值外，其余目标都能被下一个值超过，答案为 n - 1。
  • 存在大量重复值：必须使用严格大于，不能把相等误判为成功。

复杂度

时间O(n log n)
额外空间O(log n)

空间复杂度按语言排序实现而异；若不计排序栈，双指针本身只使用 O(1) 额外空间。

正确性证明

贪心选择。设当前最小未配对目标为 x，算法选择最小的可用候选 y > x。任意最优方案若让另一个更大的候选 z 与 x 配对，则把 y 换到该位置仍然成功；释放出的 z 不会比 y 更难用于其他目标。因此存在一个同样最优、且包含算法当前选择的方案。

失败候选。若当前候选 y <= x，因为 x 已是最小未配对目标，y 也不可能超过任何后续目标，跳过它不会损失可行配对。

不断应用以上两点，算法的每次选择都可包含在某个最优方案中，最终得到的配对数就是最大伟大值。

四语言完整代码

Java 
import java.util.Arrays;

class Solution {
    public int maximizeGreatness(int[] nums) {
        Arrays.sort(nums);
        int i = 0;

        for (int j = 0; j < nums.length && i < nums.length; j++) {
            if (nums[j] > nums[i]) {
                i++;
            }
        }
        return i;
    }
}

Python 
from typing import List


class Solution:
    def maximizeGreatness(self, nums: List[int]) -> int:
        nums.sort()
        i = 0

        for value in nums:
            if i < len(nums) and value > nums[i]:
                i += 1
        return i
C++ 
#include <algorithm>
#include <vector>
using namespace std;

class Solution {
public:
    int maximizeGreatness(vector<int>& nums) {
        sort(nums.begin(), nums.end());
        int i = 0;

        for (int j = 0; j < nums.size() && i < nums.size(); ++j) {
            if (nums[j] > nums[i]) ++i;
        }
        return i;
    }
};

替代方案

也可以统计每个值的频次。该问题的答案等于 n - 最高频次，可用哈希表在平均 O(n) 时间求出；但这个结论的证明不如双指针直观，且哈希表需要 O(n) 空间。

二分查找每个目标的下一个更大值还要维护“已使用”状态，通常更复杂，没有必要。

常见错误

  • 把条件写成 >=，错误地接受相等值。
  • 配对失败时同时移动两个指针，导致目标被过早丢弃。
  • 配对成功后只移动候选指针，重复计算同一目标。
  • JavaScript 直接调用 sort()，得到字符串字典序。

面试追问

  • 为什么必须选择“最小可行候选”？请给出交换论证。

  • 如何从配对结果构造出一个实际的最优 perm？
  • 能否推导出 n - 最高频次 的等价公式？

构造最优排列

若题目要求返回排列而非数量，可在排序时保留原下标；把每个成功候选放到对应目标下标，其余未使用值填入剩余位置。计数题无需承担这部分实现复杂度。
