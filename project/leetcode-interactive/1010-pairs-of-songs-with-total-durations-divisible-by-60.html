60 整除的歌曲

Pairs of Songs With Total Durations Divisible by 60

MEDIUM

题目

给定整数数组 time，其中 time[i] 是第 i 首歌曲的秒数。返回满足 i < j 且 (time[i] + time[j]) % 60 == 0 的下标对数量。

示例 1
输入：time = [30,20,150,100,40]
输出：3
解释：(30,150)、(20,100)、(20,40)
示例 2
输入：time = [60,60,60]
输出：3
解释：三个下标对的和均为 120

约束

  • 1 <= time.length <= 6 × 10⁴
  • 1 <= time[i] <= 500

余数配对实验室

逐首扫描歌曲，观察当前余数需要什么“搭档”。先动手推演，再去看完整题解。

规则：余数 r 的补数是 (60-r)%60。当前歌曲只能与此前出现的歌曲组成下标有序的一对。

题解：边扫描，边寻找补数

核心洞察

整首歌曲的长度不重要，只有除以 60 的余数重要。维护大小为 60 的计数数组 count。遇到余数 r 时，此前每个余数为 (60-r)%60 的元素都能与它成对。

完整过程

  1. 初始化 60 个余数桶和答案 0。
  2. 计算当前时长的余数 r。
  3. 把 count[(60-r)%60] 加入答案。
  4. 再令 count[r]++，保证只配对先前元素。
正确性
对每个右端点 j，算法恰好统计此前所有满足余数互补的 i。每个合法对在处理其唯一右端点时被计一次；不合法对不满足互补条件，因此不会被计入。
边界与特殊余数
r=0 的补数仍是 0；r=30 的补数仍是 30。统一公式已覆盖二者，无需分支。答案最大约为组合数，题目范围内四种语言的整数类型均可承载。

复杂度

时间 O(n)；额外空间 O(60)，即常数空间。

替代方案

可先统计全部余数，再计算互补桶乘积，并对 0、30 使用组合数；同样是 O(n)，但更容易重复计数。暴力枚举所有歌曲对为 O(n²)，无法应对 6 × 10⁴ 的规模。

四语言完整实现

class Solution {
    public int numPairsDivisibleBy60(int[] time) {
        int[] count = new int[60];
        int answer = 0;
        for (int duration : time) {
            int remainder = duration % 60;
            answer += count[(60 - remainder) % 60];
            count[remainder]++;
        }
        return answer;
    }
}

常见错误

  • 先增加当前桶再查补数，导致余数 0 或 30 时把自己配给自己。
  • 直接查 count[60-r]，在 r=0 时越界。
  • 先统计全部桶后忘记除去重复计数。

面试追问

  • 若模数从 60 变成任意正整数 k，如何改？
  • 若歌曲流持续到达，能否在线返回累计答案？
  • 若要返回具体下标对，需要保存什么信息，空间会怎样变化？
