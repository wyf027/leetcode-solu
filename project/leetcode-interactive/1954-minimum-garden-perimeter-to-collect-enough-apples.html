题目 · 你要圈住什么？

无限二维平面上的每个整数坐标 (i, j) 都有一棵树，树上苹果数为 |i| + |j|。绝对值 |x| 在 x ≥ 0 时等于 x，在 x < 0 时等于 −x。

购买一块以原点 (0, 0) 为中心、边与坐标轴平行的正方形土地。土地内部和边界上的苹果都计入总数。

给定整数 neededApples，返回能够收集至少这么多苹果的最小周长。返回的是周长，不是面积。

参数：neededApples，所需苹果数量。
约束：1 ≤ neededApples ≤ 1015。返回值为整数周长。

从整数边界，到最小可行半边长

核心洞察与公式

令半边长为 r。整数点只会在 r 越过整数时增加，因此任何非整数半边长都能缩到其下取整而不减少苹果。最优解必可写为整数 r，边长为 2r，周长为 8r。

在正方形 [−r, r] × [−r, r] 中，横坐标的绝对值之和为 r(r + 1)，每个横坐标出现 2r + 1 次。纵坐标贡献完全相同，所以：

A(r) = Σ Σ (|i| + |j|)
     = 2 × (2r + 1) × r(r + 1)
     = 2r(r + 1)(2r + 1)
A(r) − A(r − 1) = 12r²   (r ≥ 1)
P(r) = 8r

A(r) 严格递增。所求就是第一个满足 A(r) ≥ neededApples 的整数 r，可用二分查找。

完整过程

  1. 设 lo = 1, hi = 100000。A(100000) = 4000060000200000，大于输入上限 10¹⁵，保证答案在范围内。
  2. 当 lo < hi，取中点 mid = lo + floor((hi − lo) / 2)。
  3. 如果 A(mid) 已够，保留 mid，令 hi = mid；否则令 lo = mid + 1。
  4. 两端相遇时，返回 8 × lo。

以 neededApples = 13 为例，A(1) = 12 不够，A(2) = 60 足够，所以最小半边长为 2，周长为 16。演示可以查看二分如何逐步收敛到这个边界。

正确性

公式逐点累加了横、纵坐标的绝对值贡献，覆盖了全部内部与边界点，故 A(r) 精确。由于每一圈新增 12r² 个苹果，A(r) 严格递增。

循环不变式：最小可行半边长始终在 [lo, hi]。初始范围包含答案；若 mid 可行，最小可行值不会大于 mid，保留左半区间；若 mid 不可行，不大于 mid 的值都不可行，舍弃它们。区间严格缩短直至唯一整数，该整数就是最小可行 r。周长 8r 随 r 增大，返回值也最小。

边界与数值安全

  • neededApples ≥ 1，所以 r = 0 不可行，从 1 开始。
  • “至少”包含恰好相等，判断必须使用 ≥，例如输入 12 仍返回 8。
  • Java / C++ 使用 64 位整数，并让乘法从 64 位常量开始，避免先发生 32 位溢出。
  • 当前上界下最大 A(r) 约为 4 × 10¹⁵，低于 JavaScript 的最大安全整数 2⁵³ − 1，表达式各中间整数也不超过该范围，可安全使用 Number。若扩大上界，应重新核对并考虑 BigInt。
  • 无需开平方、开立方或枚举二维坐标，避免浮点取整误差与大规模网格开销。

复杂度与替代方案

令 U = 100000，二分时间为 O(log U)，辅助空间为 O(1)，最多约 17 次迭代。交互演示为了回退而保存步骤，属于页面功能，不计入提交代码的空间。

也可从 r = 1 逐圈累加 12r²，首次足够时返回 8r，耗时 O(N1/3)、空间 O(1)，其中 N 为目标苹果数。还可以用立方根给出估计后用整数公式修正，但必须处理浮点误差。若不知道输入上界，可先倍增寻找可行上界，再二分，并处理乘法溢出。

四语言完整提交代码

Java

class Solution {
    public long minimumPerimeter(long neededApples) {
        long lo = 1, hi = 100000;
        while (lo < hi) {
            long mid = lo + (hi - lo) / 2;
            long apples = 2L * mid * (mid + 1) * (2 * mid + 1);
            if (apples >= neededApples) {
                hi = mid;
            } else {
                lo = mid + 1;
            }
        }
        return 8L * lo;
    }
}

常见错误

  • 把 r 当作边长返回 4r；r 是半边长，应返回 8r。
  • 漏算边界树，或在按四条边累加时重复计算角点。
  • 满足时使用 hi = mid − 1，却没有另存当前可行答案；本实现使用 hi = mid。
  • 把目标量“至少”写成严格大于，导致恰好满足时多买一圈。
  • 在 JavaScript 使用位运算截断苹果数，或在 Java / C++ 使用 int 进行乘法。

面试追问

为什么非整数半边长没有优势？点只在整数坐标上出现，缩到下取整不丢点，却能减少周长。

能解释每圈为什么是 12r² 吗？可以对相邻总量公式作差；也可按四边计数并扣除重复角点。

若允许矩形呢？半宽 a、半高 b 的总量变为 (2b + 1)a(a + 1) + (2a + 1)b(b + 1)，周长为 4(a + b)，需要重新分析两个变量，不能直接套用正方形二分。
