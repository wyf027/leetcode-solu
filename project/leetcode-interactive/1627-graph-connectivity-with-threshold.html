城市编号也是它的“数学身份”。当共同因数越过阈值，原本分散的城市便被一条看不见的道路接入同一张网络。

困难 HARD 并查集 数论 数组
01 · Problem

题意重新整理

有 n 座城市，编号为 1 到 n。不同城市 x、y 之间存在双向直达道路，当且仅当它们拥有某个公因数 z，且 z > threshold。给定多组查询，判断每对城市之间是否能通过一条或多条道路互相到达。

关键措辞：阈值是“严格大于”，查询问的是直接或间接连通。即使两城没有共同的大因数，也可能借助其他城市形成路径。
官方函数形式
areConnected(n: integer, threshold: integer, queries: integer[][]) → boolean[]

Full Solution

枚举公因数 + 并查集

不要枚举城市对，也不需要显式建出所有道路。反过来枚举每个合格因数 d，并把 d 的所有倍数合并到一个集合。

核心洞察

1 · 反向枚举

共享 d 的城市恰好是 d, 2d, 3d…，天然可以按倍数批量找到。

2 · 连通而非邻接

查询只关心是否属于同一连通块，并查集无需保存完整图。

3 · 严格阈值

只处理 d = threshold + 1 到 n；d 大于 n/2 时没有第二个倍数，可自然跳过。

完整过程

  1. 初始化并查集，让 1…n 各自成为一个集合。
  2. 枚举 d = threshold + 1 … ⌊n/2⌋。
  3. 依次枚举 2d, 3d, … ≤ n，将每个倍数与 d 合并。
  4. 对每个查询 [a,b]，比较 find(a) 与 find(b)，得到布尔答案。

正确性证明

  1. 每条直接道路都会被覆盖。 若 x、y 直接相连，则存在 d > threshold 同时整除二者。处理 d 时，x、y 都在 d 的倍数序列中，因此会进入同一并查集。
  2. 原图中的路径不会丢失。 一条路径上的每条道路都会让相邻城市进入同一集合；利用并查集的传递性，路径两端最终拥有相同根。
  3. 算法不会制造虚假连通。 每次 union(d, kd) 的两个城市都共享公因数 d，且 d > threshold，所以这次合并对应一条合法直达道路。若两城最终同根，合并链本身就是合法路径。

结论：查询两端同根，当且仅当它们在题目定义的图中连通，因此算法返回正确答案。

复杂度

时间O(n log n + q·α(n))倍数枚举的调和级数，加上 q 次近似常数的查询。
空间O(n)并查集的 parent 与 size/rank 数组。

边界情况

  • threshold = 0：因数 1 合法，所有城市最终连通。
  • threshold ≥ n / 2：任何合格因数都没有两个不同倍数，不会发生合并。
  • 重复与反向查询：并查集查询是幂等的，[a,b] 与 [b,a] 结果一致。
  • 严格大于：循环必须从 threshold + 1 开始，不能包含 threshold。

四语言完整代码

class Solution {
    public List<Boolean> areConnected(int n, int threshold, int[][] queries) {
        DSU dsu = new DSU(n);
        for (int divisor = threshold + 1; divisor * 2 <= n; divisor++) {
            for (int multiple = divisor * 2; multiple <= n; multiple += divisor) {
                dsu.union(divisor, multiple);
            }
        }

        List<Boolean> answer = new ArrayList<>(queries.length);
        for (int[] query : queries) {
            answer.add(dsu.find(query[0]) == dsu.find(query[1]));
        }
        return answer;
    }

    private static class DSU {
        private final int[] parent;
        private final int[] size;

        DSU(int n) {
            parent = new int[n + 1];
            size = new int[n + 1];
            for (int i = 1; i <= n; i++) {
                parent[i] = i;
                size[i] = 1;
            }
        }

        int find(int x) {
            if (parent[x] != x) parent[x] = find(parent[x]);
            return parent[x];
        }

        void union(int a, int b) {
            int rootA = find(a), rootB = find(b);
            if (rootA == rootB) return;
            if (size[rootA] < size[rootB]) {
                int temp = rootA; rootA = rootB; rootB = temp;
            }
            parent[rootB] = rootA;
            size[rootA] += size[rootB];
        }
    }
}
/**
 * @param {number} n
 * @param {number} threshold
 * @param {number[][]} queries
 * @return {boolean[]}

var areConnected = function(n, threshold, queries) {
    const parent = Array.from({ length: n + 1 }, (_, i) => i);
    const size = new Array(n + 1).fill(1);

    const find = (x) => {
        while (parent[x] !== x) {
            parent[x] = parent[parent[x]];
            x = parent[x];
        }
        return x;
    };

    const union = (a, b) => {
        let rootA = find(a);
        let rootB = find(b);
        if (rootA === rootB) return;
        if (size[rootA] < size[rootB]) [rootA, rootB] = [rootB, rootA];
        parent[rootB] = rootA;
        size[rootA] += size[rootB];
    };

    for (let divisor = threshold + 1; divisor * 2 <= n; divisor++) {
        for (let multiple = divisor * 2; multiple <= n; multiple += divisor) {
            union(divisor, multiple);
        }
    }

    return queries.map(([a, b]) => find(a) === find(b));
};
class Solution:
    def areConnected(
        self, n: int, threshold: int, queries: List[List[int]]
    ) -> List[bool]:
        parent = list(range(n + 1))
        size = [1] * (n + 1)

        def find(x: int) -> int:
            while parent[x] != x:
                parent[x] = parent[parent[x]]
                x = parent[x]
            return x

        def union(a: int, b: int) -> None:
            root_a, root_b = find(a), find(b)
            if root_a == root_b:
                return
            if size[root_a] < size[root_b]:
                root_a, root_b = root_b, root_a
            parent[root_b] = root_a
            size[root_a] += size[root_b]

        for divisor in range(threshold + 1, n // 2 + 1):
            for multiple in range(divisor * 2, n + 1, divisor):
                union(divisor, multiple)

        return [find(a) == find(b) for a, b in queries]
class Solution {
    class DSU {
        vector<int> parent, size;
    public:
        explicit DSU(int n) : parent(n + 1), size(n + 1, 1) {
            iota(parent.begin(), parent.end(), 0);
        }

        int find(int x) {
            if (parent[x] != x) parent[x] = find(parent[x]);
            return parent[x];
        }

        void unite(int a, int b) {
            a = find(a);
            b = find(b);
            if (a == b) return;
            if (size[a] < size[b]) swap(a, b);
            parent[b] = a;
            size[a] += size[b];
        }
    };

public:
    vector<bool> areConnected(
        int n, int threshold, vector<vector<int>>& queries
    ) {
        DSU dsu(n);
        for (int divisor = threshold + 1; divisor * 2 <= n; divisor++) {
            for (int multiple = divisor * 2; multiple <= n; multiple += divisor) {
                dsu.unite(divisor, multiple);
            }
        }

        vector<bool> answer;
        answer.reserve(queries.size());
        for (const auto& query : queries) {
            answer.push_back(dsu.find(query[0]) == dsu.find(query[1]));
        }
        return answer;
    }
};

替代方案

逐查询计算 gcd：只能判断两座城市是否直接相连，无法识别经第三座城市形成的间接路径，因此不正确。显式枚举城市对：可以建图后 DFS/BFS，但 O(n²) 的配对成本没有必要。按质因数建点：也能工作，但分解与建模更复杂；枚举合格因数的倍数更直接。

面试追问

为什么倍数循环从 2d 开始？

d 自己就是代表节点，无需与自己合并；从 2d 开始减少一次无效操作。

为什么外层最多到 n / 2？

若 d > n/2，则 2d 已超过 n，范围中只有 d 自己，不可能借此连接两座不同城市。

如果查询在线到达怎么办？

预处理并查集一次即可；之后每个在线查询只需两次 find，摊还复杂度接近 O(1)。

常见错误

  • 把 d ≥ threshold 写成合法条件，漏掉“严格大于”。
  • 只检查 gcd(a,b)，忽略间接连通。
  • 为每个 d 两两合并所有倍数，导致额外平方成本；只需都与 d 合并。
  • 并查集数组只开 n 个位置，却直接使用 1 到 n 的城市编号。
