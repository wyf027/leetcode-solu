LCR 141 简单 EASY 链表 · 双指针

训练计划 III

给定一个链表头节点 head，请将链表原地反转，并返回反转后的头节点。

试一试交互演示

题意与示例

把每一个节点的 next 指针方向反过来：原本的尾节点成为新头节点，原头节点成为新尾节点。

输入：head = [1,2,3,4,5]

输出：[5,4,3,2,1]

输入：head = [1,2]

输出：[2,1]

输入：head = []

输出：[]

约束

  • 节点数量范围为 0 ≤ n ≤ 5000。
  • 节点值范围为 -5000 ≤ Node.val ≤ 5000。
  • 期望以迭代方式做到常数额外空间。

分步交互：三指针翻转

每次保存后继节点，再反转当前连接，最后整体前进。

核心洞察

反转时最危险的是覆盖 curr.next 后丢失未处理的后半段。因此每轮先用 next 暂存它，再让 curr.next = prev。此时 prev 是已反转部分的头，curr 是尚未处理部分的头。

完整过程

  1. 1. 保存
    next = curr.next
  2. 2. 反向
    curr.next = prev
  3. 3. 前进
    prev = curr; curr = next

边界条件

  • 空链表：循环不进入，直接返回 null。
  • 单节点：一次也无需改向，返回原节点。
  • 循环结束后 prev 恰好指向新头节点。
时间复杂度

O(n)，每个节点访问一次。

空间复杂度

O(1)，仅使用三个指针。

替代方案与追问

递归：写法简洁，但调用栈为 O(n)，节点很长时有栈深风险。
追问：如何反转前 k 个节点？如何每 k 个一组反转？都可复用“保存后继 + 局部反向”的不变量。

常见错误

  • 未先保存 next 就覆盖 curr.next，导致链表断开。
  • 最后返回 curr；循环退出时它已是 null，应返回 prev。
  • 错误写成 prev.next = curr，这没有改变当前节点的方向。

官方签名代码

// Java
class Solution {
  public ListNode trainningPlan(ListNode head) {
    ListNode prev = null, curr = head;
    while (curr != null) {
      ListNode next = curr.next;
      curr.next = prev;
      prev = curr; curr = next;
    }
    return prev;
  }
}
// JavaScript
var trainningPlan = function(head) {
  let prev = null, curr = head;
  while (curr) {
    const next = curr.next;
    curr.next = prev;
    prev = curr; curr = next;
  }
  return prev;
};
# Python
class Solution:
    def trainningPlan(self, head: ListNode) -> ListNode:
        prev, curr = None, head
        while curr:
            nxt = curr.next
            curr.next = prev
            prev, curr = curr, nxt
        return prev
// C++
class Solution {
public:
  ListNode* trainningPlan(ListNode* head) {
    ListNode *prev = nullptr, *curr = head;
    while (curr) {
      ListNode* next = curr->next;
      curr->next = prev;
      prev = curr; curr = next;
    }
    return prev;
  }
};
