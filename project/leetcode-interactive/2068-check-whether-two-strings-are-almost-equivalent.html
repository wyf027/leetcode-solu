是否几乎相等

Check Whether Two Strings are Almost Equivalent

“几乎”的尺度：每一种字母，最多相差 3 次。

先读题、自己判断示例。页面底部可按需展开题解与交互演示。

题目说明

给定两个长度均为 n 的字符串 word1 和 word2。对于小写字母 a 到 z 中的每一个字母，如果它在两个字符串中出现的次数之差的绝对值都不超过 3，则两个字符串“几乎相等”。满足时返回 true，否则返回 false。

这里的“频率”表示出现次数，而非所占比例；是否相等与字母的位置无关。

参数与返回值
checkAlmostEquivalent(word1: string, word2: string) → boolean

约束

  • n == word1.length == word2.length
  • 1 ≤ n ≤ 100
  • word1 与 word2 都只包含小写英文字母。

官方示例

示例 1

输入：word1 = "aaaa", word2 = "bccb"
输出：false

字母 a 出现次数分别为 4 和 0，差为 4，超过允许的 3。

示例 2

输入：word1 = "abcdeef", word2 = "abaaacc"
输出：true

a：1 与 4，差 3；b：1 与 1，差 0；c：1 与 2，差 1；d：1 与 0，差 1；e：2 与 0，差 2；f：1 与 0，差 1。其余字母的差均为 0。

示例 3

输入：word1 = "cccddabba", word2 = "babababab"
输出：true

a：2 与 4，差 2；b：2 与 5，差 3；c：3 与 0，差 3；d：2 与 0，差 2。其余字母的差均为 0。

核心洞察：把两本账合成一本

只关心每个字母的次数，不关心位置。设置长度为 26 的数组 diff：在 word1 中读到一个字母就加 1，在 word2 中读到就减 1。统计结束后，diff[c] = count1[c] − count2[c]。

只有最终每个 |diff[c]| ≤ 3，才能返回 true。正负号只表示哪边更多。

完整过程与正确性
  1. 创建 26 个零，分别对应 a 到 z。
  2. 遍历位置 i，对 word1[i] 对应项加 1，对 word2[i] 对应项减 1。
  3. 统计结束后遍历全部数组项；任意一项绝对值大于 3 就返回 false。
  4. 没有超限项，返回 true。
为什么一定正确？
循环不变式：处理完前 i 个位置后，diff[c] 等于 word1 前 i 个字符中 c 的出现次数减去 word2 前 i 个字符中 c 的出现次数。初始 i = 0，两边都为 0；每轮的一加一减恰好计入新读到的两个字符，所以不变式保持。
当 i = n 时，数组记录整串的真实次数差。若存在绝对值大于 3 的项，该字母违反定义，返回 false 正确；否则 a 到 z 的所有字母都满足定义，返回 true 正确。这覆盖了所有返回路径。
复杂度
统计用 O(n)，检查用 O(26)，总时间 O(n + 26) = O(n)；额外空间为 26 个整数，即 O(26) = O(1)。交互页面为便于回退重新计算前缀，不代表提交算法的运行方式。


边界与常见错误
  • 差恰好为 3：仍然合法，判断应为 > 3，不能用 >= 3。
  • 负差值：如示例 2 的 a 为 −3，必须使用绝对值。
  • 只在一个字符串出现：另一个次数为 0；遍历完整 26 项即可覆盖。
  • 不能边统计边拒绝：中间差可能随后抵消。例如 aaaabbbb 与 bbbbaaaa，中途 a 的差达到 4，最终为 0。
  • 不要逐位置比较：顺序不同可以拥有完全相同的字母频率。
  • 不是差值总和：要求每个字母单独满足上限；等长字符串的有符号差值之和始终为 0，并不能决定结果。
  • n ≤ 3：每个字母的次数差最多为 n，因此一定满足。无需为此增加特殊分支。

Java
class Solution {
    public boolean checkAlmostEquivalent(String word1, String word2) {
        int[] diff = new int[26];
        for (int i = 0; i < word1.length(); i++) {
            diff[word1.charAt(i) - 'a']++;
            diff[word2.charAt(i) - 'a']--;
        }
        for (int d : diff) {
            if (Math.abs(d) > 3) return false;
        }
        return true;
    }
}

var checkAlmostEquivalent = function(word1, word2) {
    const diff = Array(26).fill(0);
    for (let i = 0; i < word1.length; i++) {
        diff[word1.charCodeAt(i) - 97]++;
        diff[word2.charCodeAt(i) - 97]--;
    }
    return diff.every(d => Math.abs(d) <= 3);
};

class Solution:
    def checkAlmostEquivalent(self, word1: str, word2: str) -> bool:
        diff = [0] * 26
        for a, b in zip(word1, word2):
            diff[ord(a) - ord('a')] += 1
            diff[ord(b) - ord('a')] -= 1
        return all(abs(d) <= 3 for d in diff)


C++
#include <string>
#include <cstdlib>
using namespace std;

class Solution {
public:
    bool checkAlmostEquivalent(string word1, string word2) {
        int diff[26] = {};
        for (int i = 0; i < static_cast<int>(word1.size()); ++i) {
            ++diff[word1[i] - 'a'];
            --diff[word2[i] - 'a'];
        }
        for (int d : diff) {
            if (abs(d) > 3) return false;
        }
        return true;
    }
};




替代方案与面试追问
还有哪些做法？
可以分别建立两个长度为 26 的计数数组，再逐项相减：时间同为 O(n)，空间同为 O(1)，更容易展示原始次数。也可使用字典统计并遍历键的并集，适合不固定的字符集。排序后统计各段次数需要 O(n log n)，本题没有必要。
如果字符集不再限于 a–z？
改用哈希映射存储差值；对于 k 个不同字符，预期时间 O(n + k)，空间 O(k)。Unicode 输入还需明确按码点还是用户感知字符计数。
如果上限改为 t，或字符串长度不同？
将 3 替换为非负 t 即可。长度不同仍可比较频率，但需要独立遍历两个字符串；不能使用依赖等长的单位置循环或会截断的 zip。
能否用流式输入完成？
可以，只保留 26 个计数器；读完两条流后再检查。流尚未结束时，中间的超限可能被后续字符抵消。
