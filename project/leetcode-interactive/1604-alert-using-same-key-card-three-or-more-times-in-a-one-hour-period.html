谁在一小时内，刷了三次员工卡？

把一整天杂乱的门禁记录交给你。你的任务不是数总次数，而是找出触发“一小时三次”警报的员工，并按字典序报告。

边界规则：10:00 → 11:00 恰好 60 分钟，仍算一小时内；相差 61 分钟则不算。

任务简报

题意

给定等长字符串数组 keyName 与 keyTime。第 i 对数据表示某位员工在同一天的某次刷卡，时间采用 24 小时制 HH:MM。若同一员工在任意不超过 60 分钟的区间内刷卡至少 3 次，该员工触发警报。

返回所有触发警报的员工姓名，去重后按字典序升序排列。

函数与约束

alertNames(keyName, keyTime) → List<String>

  • 1 ≤ keyName.length, keyTime.length ≤ 10⁵
  • 两个数组长度相同
  • keyTime[i] 格式为 HH:MM
  • 每对姓名与时间互不相同
  • 1 ≤ keyName[i].length ≤ 10
  • 姓名仅含小写英文字母
官方示例 1
输入：
keyName = ["daniel","daniel","daniel","luis","luis","luis","luis"]
keyTime = ["10:00","10:40","11:00","09:00","11:00","13:00","15:00"]

输出： ["daniel"]

解释： daniel 在 10:00、10:40、11:00 三次刷卡，首尾恰好相差 60 分钟。
官方示例 2
输入：
keyName = ["alice","alice","alice","bob","bob","bob","bob"]
keyTime = ["12:01","12:00","18:00","21:00","21:20","21:30","23:00"]

输出： ["bob"]

解释： bob 在 21:00、21:20、21:30 三次刷卡，均落在一小时内。

04 / DEBRIEF

题解：分组、排序、检查连续三次

核心洞察

同一员工的时间按分钟升序排列后，只需检查每个长度为 3 的连续片段。若第 i + 2 次与第 i 次相差不超过 60 分钟，就已经存在三次刷卡落在一小时内。

为什么只看连续三次？

若某个一小时区间包含至少三次刷卡，那么该区间内最早的三次在完整有序序列中必然构成某个连续三元组，它们的首尾跨度同样不超过 60 分钟。

完整过程

  1. 把每个 HH:MM 转成从当天 00:00 起的分钟数：60 × HH + MM。
  2. 用哈希表按员工姓名收集分钟数。
  3. 对每位员工的时间列表升序排序。
  4. 从左到右检查 times[i + 2] - times[i] ≤ 60；一旦成立，该员工加入答案，无需再检查。
  5. 将答案按姓名字典序升序排序并返回。

正确性证明

充分性：若算法找到连续三次的首尾相差不超过 60 分钟，那么中间一次必然也位于这两次之间，所以三次均在同一小时范围内，该员工应触发警报。

必要性：若员工应触发警报，则存在一个至多 60 分钟的区间包含至少三次记录。在排序后的列表中，取该区间内最早的三次，它们在全列表中连续，且第三次减第一次不超过 60。算法扫描所有连续三元组，必然发现它。

因此，算法返回且仅返回所有应触发警报的员工；最终排序保证输出顺序符合要求。

边界检查

  • 员工不足 3 次：不可能触发。
  • 恰好 60 分钟：使用 ≤ 60，应触发。
  • 相差 61 分钟：不触发。
  • 输入时间乱序：必须先排序。
  • 多于 3 次：任一连续三元组满足即可。
  • 记录都在同一天，不做跨午夜拼接。

复杂度

O(n log n)时间：所有分组排序的总上界
O(n)空间：保存按员工分组的时间

import java.util.*;

class Solution {
    public List<String> alertNames(String[] keyName, String[] keyTime) {
        Map<String, List<Integer>> timesByName = new HashMap<>();

        for (int i = 0; i < keyName.length; i++) {
            timesByName
                .computeIfAbsent(keyName[i], ignored -> new ArrayList<>())
                .add(toMinutes(keyTime[i]));
        }

        List<String> answer = new ArrayList<>();
        for (Map.Entry<String, List<Integer>> entry : timesByName.entrySet()) {
            List<Integer> times = entry.getValue();
            Collections.sort(times);

            for (int i = 0; i + 2 < times.size(); i++) {
                if (times.get(i + 2) - times.get(i) <= 60) {
                    answer.add(entry.getKey());
                    break;
                }
            }
        }

        Collections.sort(answer);
        return answer;
    }

    private int toMinutes(String time) {
        int hour = Integer.parseInt(time.substring(0, 2));
        int minute = Integer.parseInt(time.substring(3, 5));
        return hour * 60 + minute;
    }
}

var alertNames = function(keyName, keyTime) {
    const timesByName = new Map();

    for (let i = 0; i < keyName.length; i++) {
        if (!timesByName.has(keyName[i])) timesByName.set(keyName[i], []);
        const [hour, minute] = keyTime[i].split(":").map(Number);
        timesByName.get(keyName[i]).push(hour * 60 + minute);
    }

    const answer = [];
    for (const [name, times] of timesByName) {
        times.sort((a, b) => a - b);
        for (let i = 0; i + 2 < times.length; i++) {
            if (times[i + 2] - times[i] <= 60) {
                answer.push(name);
                break;
            }
        }
    }

    return answer.sort();
};
from collections import defaultdict
from typing import List


class Solution:
    def alertNames(self, keyName: List[str], keyTime: List[str]) -> List[str]:
        times_by_name = defaultdict(list)

        for name, time in zip(keyName, keyTime):
            hour, minute = map(int, time.split(":"))
            times_by_name[name].append(hour * 60 + minute)

        answer = []
        for name, times in times_by_name.items():
            times.sort()
            for i in range(len(times) - 2):
                if times[i + 2] - times[i] <= 60:
                    answer.append(name)
                    break

        return sorted(answer)

替代方案

逐分钟计数 / 前缀和：一天只有 1440 分钟，可为每位员工建立分钟频次数组，再用长度 61 的滑动窗口统计。但输入保证同一姓名与时间对唯一，排序方案更直接，额外常数也更小。

全局排序：也可以将记录按“姓名、时间”整体排序，再在线性扫描中检查；复杂度相同，但会重排完整记录结构。

常见错误

  • 只统计员工全天总刷卡次数。
  • 忘记先按员工分组或按时间排序。
  • 把恰好 60 分钟错误写成 < 60。
  • 比较字符串或小时、分钟字段，导致边界判断复杂化。
  • 找到警报员工后继续加入，产生重复姓名。
  • 忘记对最终姓名列表按字典序排序。

面试追问

  1. 如果数据是实时流，不能等一天结束再排序？ 可为每位员工维护最近 60 分钟的双端队列；新记录按时间到达时淘汰过期项，队列长度达到 3 即报警。
  2. 如果记录可能乱序到达？ 需要定义迟到容忍窗口，使用有序集合或事件时间水位线；仅用普通队列不再正确。
  3. 为什么不需要检查 4 次、5 次窗口？ 任意至少 3 次的合格区间必含一个合格的连续三元组。
  4. 若规则改成任意 K 次、T 分钟？ 检查排序列表中 times[i + K - 1] - times[i] ≤ T。
