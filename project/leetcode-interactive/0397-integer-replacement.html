题号 397 非付费题 正整数 最少操作数

Problem

题意与规则

给定正整数 n，按以下规则反复替换，返回将它变为 1 所需的最少操作次数。

一次操作可以做什么？

  1. 当 n 为偶数：只能把它替换为 n / 2。
  2. 当 n 为奇数：可以把它替换为 n + 1 或 n - 1。
≤
约束

Full Solution

位模式驱动的贪心

核心洞察

偶数没有分支，直接除以 2。奇数的目标是经过一次 +1 或 -1 后，制造尽可能多的末尾零，从而连续除以 2。通常可用 n mod 4 判断；唯一特例是 n = 3。

完整过程

  1. 初始化操作次数 steps = 0。
  2. 当 n > 1：若为偶数，令 n = n / 2。
  3. 若为奇数且 n = 3，或 n mod 4 = 1，令 n = n - 1。
  4. 其余奇数令 n = n + 1；每轮将 steps 加一。

为什么 3 是特例？

3 → 2 → 1 只需 2 步，而 3 → 4 → 2 → 1 需要 3 步。对更大的末两位为 11 的奇数，加一会消掉一串末尾的 1，更利于后续连续右移。

正确性说明

1
偶数步是强制的。

偶数只允许除以 2，因此任何合法最短路径的下一步都相同。

2
奇数先变偶数。

除 1 外，奇数无论加一还是减一都会成为偶数，下一步至少可以除以 2。

3
选择更多因子 2。

当 n mod 4 = 1 时，n - 1 可被 4 整除；当 n mod 4 = 3 时，n + 1 可被 4 整除。该选择不会比另一侧需要更多步骤，并为连续除二创造条件。

4
处理唯一小规模反例。

n = 3 时直接减一更短。结合此特例，每个奇数分支都保留一条最优后缀，故整个贪心序列最优。

边界与实现细节

  • n = 1 时循环不执行，答案为 0。
  • 输入可达 231 - 1，奇数加一会超出 32 位有符号整数；Java 使用 long，C++ 使用 long long。
  • JavaScript 的 number 对本题范围内整数仍能精确表示。

复杂度

每一到两步都会显著缩短二进制长度，因此时间复杂度为 O(log n)，额外空间复杂度为 O(1)。

替代方案

可以使用记忆化递归，同时尝试奇数的两个方向，再缓存结果。它更直接地表达“取最小值”，但会增加递归与哈希表空间；贪心在本题中更紧凑。

常见错误

  • 看到奇数总是加一，遗漏 3 以及末两位为 01 的情况。
  • 在 Java/C++ 中仍用 32 位变量承接 n + 1，导致溢出。
  • 用“数值变小”代替“后续二进制可快速缩短”作为选择标准。

面试追问

  • 如何从二进制末尾连续 1 的数量解释贪心？
  • 若两种奇数操作代价不同，当前规则还成立吗？
  • 如何写出记忆化递归，并避免 n + 1 溢出？

class Solution {
    public int integerReplacement(int n) {
        long value = n; // 防止 Integer.MAX_VALUE + 1 溢出
        int steps = 0;

        while (value > 1) {
            if ((value & 1) == 0) {
                value >>= 1;
            } else if (value == 3 || (value & 3) == 1) {
                value--;
            } else {
                value++;
            }
            steps++;
        }
        return steps;
    }
}
