题意与官方样例

给定每天的股票价格，可以完成任意多次交易，但任意时刻最多持有一股。 卖出后才能继续持有下一股；求最大总利润。

规则边界

  • 输入是整数数组 prices，下标表示交易日。
  • 同一天可以买入和卖出，但始终不能同时持有超过一股。
  • 可以不交易，因此答案不会小于 0。
  • 1 ≤ prices.length ≤ 3 × 10⁴， 0 ≤ prices[i] ≤ 10⁴。

题解

核心洞察、完整过程、复杂度、边界、追问与四语言代码默认隐藏。

核心洞察

任意一段从低点到高点的利润，都能拆成沿途每天的正向差价之和。 例如 1 → 2 → 5 的利润 5 - 1，等于 (2 - 1) + (5 - 2)。 因此不必显式寻找每个谷底和峰顶，逐日收集正差价即可。

复杂度

只扫描一次数组，时间复杂度 O(n)； 仅使用累计收益一个变量，额外空间复杂度 O(1)。

完整过程

  1. 令 profit = 0，准备累计所有已确认的上涨。
  2. 从下标 1 开始，计算 delta = prices[i] - prices[i - 1]。
  3. 若 delta > 0，把它加入 profit；否则保持不变。
  4. 扫描结束后返回 profit。

边界情况

  • 只有一天：没有差额票，返回 0。
  • 严格下降或价格不变：所有差值非正，返回 0。
  • 严格上升：相邻正差价之和等于首尾价差。
  • 价格可为 0，算法不需要特殊处理。

替代方案与取舍

可以用峰谷法显式寻找每段买卖点，复杂度同为 O(n)，但分支更多； 也可以用持有/空仓两状态动态规划，便于扩展手续费、冷冻期等变体， 对本题则略显冗余。面试主线优先选择累加正差价。

面试追问

  • 为什么拆成相邻正差价不会违反“最多持有一股”？
  • 如果每次交易收手续费，贪心还成立吗？
  • 如果最多只能完成 k 次交易，状态如何设计？
  • 怎样从累计答案恢复具体买卖区间？

常见错误

  • 沿用第 121 题，只寻找一次全局最大价差。
  • 把负差价也加入总收益，导致已赚利润被回撤抵消。
  • 循环从 0 开始却访问 prices[i - 1]。
  • 误以为必须保存所有买卖点，增加不必要空间。

class Solution {
    public int maxProfit(int[] prices) {
        int profit = 0;
        for (int i = 1; i < prices.length; i++) {
            if (prices[i] > prices[i - 1]) {
                profit += prices[i] - prices[i - 1];
            }
        }
        return profit;
    }
}
