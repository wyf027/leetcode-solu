检查句子中的数字
是否递增

Check if Numbers Are Ascending in a Sentence

把单词与数字组成的句子读一遍：数字的出现顺序，是否始终向上？先独立思考，再展开底部题解与演示。

输入：字符串 s输出：boolean主题：字符串官方题目 ↗

题目说明

字符串 s 由若干 token 构成，相邻 token 用一个空格隔开。每个 token 要么是小写英文字母组成的单词，要么是不含前导零的正整数。句首和句尾没有空格。

请判断句子中所有数字按照原来的从左到右顺序，是否严格递增。满足则返回 true，否则返回 false。相等也不满足严格递增；单词不参与数字顺序的判定。

约束

  • 3 ≤ s.length ≤ 200。
  • 只含小写英文字母、空格与数字 0–9。
  • token 总数为 2–100，其中至少有两个数字。
  • 每个数字均为 1–99 的整数，没有前导零。
  • token 之间恰好一个空格，没有首尾空格。

元数据中文约束将 token 总数译作“数字 token 的数目”；此处依英文原文说明总 token 数量。

官方示例

01 / 连续上升

输入：s = "1 box has 3 blue 4 red 6 green and 12 yellow marbles"
输出：true

数字依次为 1、3、4、6、12，满足 1 < 3 < 4 < 6 < 12。

02 / 相等不算递增

输入：s = "hello world 5 x 5"
输出：false

两个数字都是 5，严格递增不允许相等。

03 / 中途下降

输入：s = "sunset is at 7 51 pm overnight lows will be in the low 50 and 60 s"
输出：false

数字为 7、51、50、60，51 到 50 出现下降。

04 / 全部是数字

输入：s = "4 5 11 26"
输出：true

4 < 5 < 11 < 26。此例收录于官方中文题面。

题解 · 只记住上一个数字

核心洞察

严格递增只需保证每对相邻数字满足 previous < current，传递性会保证更远处的数字关系。按空格分词，跳过单词，保存最近一个数字即可。把 previous 初始设为 0，利用所有数字为正数的约束处理第一个数字。

数字阶梯 · 单词旁路

每一步读取一个 token：单词旁路，数字进入比较门；第一次出现 ≤ 就停下。阶梯高度按数字大小绘制，最低柱高用于保证标签可读。

完整过程

  1. 设置 previous = 0，用单个空格切分句子。
  2. 检查 token 首字符；题目保证 token 类型纯净，因此首字符是数字就表示整个 token 是数字。
  3. 把数字 token 转为整数 current；若 current ≤ previous，立即返回 false。
  4. 否则令 previous = current，继续读取。单词不修改 previous。
  5. 扫描结束没有违例，返回 true。

示例 3 中依次保存 7、51；读取 50 时有 50 ≤ 51，立刻返回 false。后面的 60 无法修复已经出现的违例。

正确性证明

循环不变式：每次处理 token 前，已读数字严格递增，且 previous 是最近的已读数字；尚无数字时为哨兵 0。初始时性质成立。遇到单词不改变数字序列；遇到比 previous 大的数字，追加后仍严格递增并更新 previous。遇到不大于 previous 的数字，已经找到相邻数字违例，返回 false 必然正确。若扫描结束，则由不变式可知全部数字严格递增，返回 true 正确。

边界与复杂度

重复值必须拒绝；两位数必须整体解析；句子可以全部为数字，单词可在开头或结尾。题目保证至少两个数字，因此无需为空序列单独分支。

设 n 为字符串长度。分词和扫描都是 O(n)，总时间 O(n)。下方 Java、JavaScript、Python 使用 split，额外空间 O(n)；C++ 使用字符串流，其内部字符串存储也是 O(n)，不能只因比较状态为常数就把完整实现写作 O(1)。

替代方案

逐字符扫描，在连续数字段中用 value = value * 10 + digit 累积，数字段结束时比较。这样可做到 O(n) 时间、O(1) 额外空间，但需要处理句末数字段。也可以正则提取全部数字再比较，代码短但会创建匹配结果。无需排序，原顺序就是要检查的信息。

四语言可提交代码

均使用官方函数名与参数 s；代码仅生成，尚未编译或运行。

Java

class Solution {
    public boolean areNumbersAscending(String s) {
        int previous = 0;
        for (String token : s.split(" ")) {
            char first = token.charAt(0);
            if (first >= '0' && first <= '9') {
                int current = Integer.parseInt(token);
                if (current <= previous) return false;
                previous = current;
            }
        }
        return true;
    }
}

C++

#include <string>
#include <sstream>
using namespace std;

class Solution {
public:
    bool areNumbersAscending(string s) {
        istringstream input(s);
        string token;
        int previous = 0;
        while (input >> token) {
            if (token[0] >= '0' && token[0] <= '9') {
                int current = stoi(token);
                if (current <= previous) return false;
                previous = current;
            }
        }
        return true;
    }
};

常见错误

  • 把数字作为字符串比较：字典序下 "10" 在 "9" 前面，数值比较则相反。
  • 只用 current < previous 拒绝下降，漏掉相等；应使用 ≤。
  • 每遇到单词就重置 previous，丢失跨单词的数字关系。
  • 逐个字符比较数字，把 12 当成 1、2；应识别完整 token。
  • 先排序再判断，破坏了原来的出现顺序。
  • 用 split 却把额外空间宣称为 O(1)。

面试追问

如果允许 0 或负数，初始值还可以是 0 吗？

不可以。改用“是否读过数字”的标记或可空的 previous，并扩展数字识别以处理符号；不要把正数约束下的首字符判别直接套用。

如果句子来自连续数据流？

逐字符解析，仅保存当前数值、是否在数字段中、previous 和是否已有数字。段结束时比较，流结束时也要结算最后一个数字，使用 O(1) 额外空间。

如何报告违例位置，而不是只返回布尔值？

同时保存前一个数字的 token 索引，遇到 ≤ 时返回这一对索引或值。仍是一遍扫描，时间复杂度不变。
