逃脱阻碍者Escape The Ghosts

在一张无限二维网格里，你与所有阻碍者同步行动。先理解这场追逐的规则，再亲手推进每一个回合。

[0, 0] target

01 / Problem

先读懂追逐规则

你从原点出发，阻碍者从各自坐标出发，大家每回合都能独立移动或停留。你的任务不是预测某一种走法，而是判断面对任意阻碍者策略时是否仍能逃脱。

在无限二维整数网格上，你位于 [0, 0]，目的地为 target = [xTarget, yTarget]。数组 ghosts 给出所有阻碍者的初始位置，其中 ghosts[i] = [xi, yi]。

每一回合，你和每个阻碍者同时选择：向上、下、左、右移动 1 个单位，或者原地不动。只有当你能在任何阻碍者抓住你之前到达目的地，才算逃脱成功；若你与某个阻碍者同时到达任意同一位置（包括目的地），都视为失败。

请返回一个布尔值：如果无论阻碍者如何行动，你都能成功逃脱，则返回 true；否则返回 false。

同步行动 同一回合内所有角色同时完成选择。
五种选择 四个正方向移动一步，或留在原地。
平局也失败 同时抵达同一格，不算成功逃脱。

    06 / Editorial

    准备好再揭晓题解

    完整推导、证明、复杂度与四种语言实现默认收起，避免在阅读题目时直接泄露关键结论。

    Core Insight

    核心洞察：只比较到终点的最短回合数

    这题不需要在无限网格上搜索。网格没有障碍，每回合只能沿一个坐标轴移动 1 格，所以两点间的最少回合数就是曼哈顿距离。
    player = |xTarget| + |yTarget|；ghostᵢ = |xi - xTarget| + |yi - yTarget|

    若存在任意阻碍者满足 ghostᵢ <= player，它就能在你之前或与你同时抵达目的地并等待，逃脱失败。只有所有阻碍者的距离都严格大于你的距离，答案才是 true。

    完整过程

    1. 计算你从 [0, 0] 到 target 的曼哈顿距离。
    2. 遍历每个 ghosts[i]，计算它到 target 的曼哈顿距离。
    3. 一旦某个阻碍者的距离小于或等于你的距离，立即返回 false。
    4. 遍历结束仍未被拦截，则返回 true。

    边界情况

    • 距离相同：平局也算失败，比较符号必须是 <=。
    • 阻碍者在终点：其距离为 0，必然无法逃脱。
    • 目标是原点：你的距离为 0；阻碍者距离均为正时可以立即成功。
    • 负坐标：绝对值会自然处理四个象限。
    • 重复位置：逐个比较即可，不影响结论。

    正确性证明

    记你到终点的最短距离为 D，第 i 个阻碍者到终点的最短距离为 Gi。

    必要性：若某个 Gi <= D，该阻碍者沿任意最短路径前往终点，就能在第 Gi 回合抵达，并可原地等待。你最早只能在第 D 回合抵达，因此会在终点遭遇阻碍者或被其提前占据，无法保证逃脱。

    充分性：若对所有阻碍者都有 Gi > D，你沿任意最短路径前进。设第 t 回合你位于该路径上的点 P，则 dist(P, target) = D - t。由三角不等式，阻碍者到 P 的距离至少为 Gi - dist(P, target) > D - (D - t) = t，所以它无法在第 t 回合前到达 P。这对路径上每个点均成立，你可以安全抵达终点。

    因此，算法返回 true 当且仅当你能保证逃脱，算法正确。

    复杂度

    • 时间复杂度：O(n)，其中 n 是阻碍者数量。
    • 空间复杂度：O(1)，只保存常数个距离变量。

    替代方案

    可以把状态建模成你与所有阻碍者的位置并做 BFS，但网格无限且联合状态巨大，完全没有必要。这里的无障碍网格与同步一步移动，使距离比较直接概括了所有对抗策略。

    Implementations

    四语言完整代码

    Java

    LeetCode 
    class Solution {
    public boolean escapeGhosts(int[][] ghosts, int[] target) {
        int playerDistance = Math.abs(target[0]) + Math.abs(target[1]);

        for (int[] ghost : ghosts) {
            int ghostDistance = Math.abs(ghost[0] - target[0])
                    + Math.abs(ghost[1] - target[1]);
            if (ghostDistance <= playerDistance) {
                return false;
            }
        }

        return true;
    }
}

    const playerDistance = Math.abs(target[0]) + Math.abs(target[1]);

    for (const [x, y] of ghosts) {
        const ghostDistance =
            Math.abs(x - target[0]) + Math.abs(y - target[1]);
        if (ghostDistance <= playerDistance) {
            return false;
        }
    }

    return true;
};

    面试追问

    • 如果网格中加入障碍物，曼哈顿距离还足够吗？应改用什么最短路算法？
    • 如果你每回合能移动 2 格，而阻碍者只能移动 1 格，判定式如何变化？
    • 如果阻碍者必须抓到你本人、不能只在终点等待，证明是否仍成立？
    • 若移动代价因方向不同而变化，应如何定义距离？

    常见错误

    • 只判断阻碍者是否位于你到终点的一条直线路径上。
    • 使用 < 而不是 <=，遗漏同时到达也失败。
    • 计算阻碍者到原点的距离，而不是到目的地的距离。
    • 真的在无限网格上做 BFS，导致状态规模失控。
    • 忘记对负坐标取绝对值。
