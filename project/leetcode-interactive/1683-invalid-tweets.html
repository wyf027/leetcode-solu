Invalid Tweets

无效的推文

从 Tweets 表中筛出内容字符数严格大于 15 的推文，并返回它们的编号。先读懂边界，再让查询动起来。

题目转述

社交媒体应用把推文保存在 Tweets 表中。请查询所有无效推文的 tweet_id。一条推文只有在 content 使用的字符数严格大于 15 时才无效；结果可以按任意顺序返回。

列名类型含义
tweet_idint主键，值唯一
contentvarchar(50)仅含字母、数字、感叹号与空格

判定规则

CHAR_LENGTH(content) > 15

注意“严格大于”：长度 15 仍然有效，长度 16 才无效。空格与 ! 也各算一个字符。

约束与返回

  • tweet_id 是唯一主键。
  • content 受 varchar(50) 约束。
  • 只返回一列 tweet_id，顺序不限。

官方示例

输入：Tweets =
+----------+-----------------------------------+
| tweet_id | content                           |
+----------+-----------------------------------+
| 1        | Let us Code                       |
| 2        | More than fifteen chars are here! |
+----------+-----------------------------------+

输出：
+----------+
| tweet_id |
+----------+
| 2        |
+----------+

推文 1 长度为 11，是有效推文；推文 2 长度为 33，严格大于 15，因此返回编号 2。

    Solution

    题解：在 WHERE 中直接过滤字符长度

    核心洞察

    目标列和筛选规则都来自同一张表，不需要连接、分组或子查询。对每行计算 content 的字符长度，仅保留大于 15 的行，再投影 tweet_id 即可。

    完整过程

    1. 扫描 Tweets 中的每一行。
    2. 用 CHAR_LENGTH(content) 得到字符数。
    3. 通过 WHERE ... > 15 丢弃有效推文。
    4. 返回剩余行的 tweet_id。

    正确性说明

    对任意一行，查询保留它当且仅当 CHAR_LENGTH(content) > 15。这与题目对“无效推文”的定义完全相同。因此所有返回的编号都属于无效推文，且每条无效推文都会被返回；结论成立。

    边界与复杂度

    • 长度 15：条件为假，不返回。
    • 长度 16：条件为真，返回。
    • 设表有 n 行、内容最大长度为 L：时间 O(n·L)，结果外额外空间 O(1)。数据库执行计划仍可能受存储与索引影响。

    MySQL（官方可提交语言）

    推荐
    SELECT tweet_id
FROM Tweets
WHERE CHAR_LENGTH(content) > 15;

    Java

    本地语义参考，不是本题官方提交语言
    import java.util.ArrayList;
import java.util.List;

class Solution {
    record Tweet(int tweetId, String content) {}

    public List<Integer> invalidTweets(List<Tweet> tweets) {
        List<Integer> result = new ArrayList<>();
        for (Tweet tweet : tweets) {
            if (tweet.content().length() > 15) {
                result.add(tweet.tweetId());
            }
        }
        return result;
    }
}

    from typing import Iterable, TypedDict

class Tweet(TypedDict):
    tweet_id: int
    content: str

def invalid_tweets(tweets: Iterable[Tweet]) -> list[int]:
    return [
        tweet["tweet_id"]
        for tweet in tweets
        if len(tweet["content"]) > 15
    ]

vector<int> invalidTweets(const vector<Tweet>& tweets) {
    vector<int> result;

            result.push_back(tweet.tweetId);

    }

    替代方案

    PostgreSQL 可写 LENGTH(content)；SQL Server 常用 LEN(content)，但它会忽略尾随空格，语义需要额外留意。MySQL 中不应使用 LENGTH 代替 CHAR_LENGTH 来泛化处理多字节字符，因为前者返回字节数。

    常见错误

    • 写成 >= 15，误收长度恰为 15 的推文。
    • 返回整行而不是只返回 tweet_id。
    • 在 MySQL 中用字节长度冒充字符长度。
