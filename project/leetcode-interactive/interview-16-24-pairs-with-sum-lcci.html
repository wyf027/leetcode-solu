Problem brief

题意

给定整数数组 nums 与整数 target，找出所有和等于目标值的整数对。每个数组元素最多只能进入一个数对；返回顺序不作要求。

重点不是“是否存在”，而是“最多能配出多少对”。因此等待区必须保存出现次数，不能只用集合。

[[5,6],[5,6]]

约束

nums.length <= 100000

-100000 <= nums[i], target <= 100000

Solution vault

题解

核心洞察、完整过程、复杂度与四语言实现默认隐藏。先完成中转站推演，再按需打开。

Core insight

核心洞察

扫描当前值 x 时，只让它与此前尚未使用的补数 target - x 配对。计数大于 0 就立即消耗一份；否则把 x 加入等待计数。这条顺序保证一个元素不会被重复使用。

Invariant

循环不变量

处理完前 i 个元素后，答案中的每个元素恰好使用一次；计数表中保存的恰好是这些元素里仍未配对的部分。下一元素只能从计数表消耗一个补数，或成为新的未配对元素。

Full process

完整过程

  1. 1. 初始化空答案与空哈希计数表 waiting。
  2. 2. 对每个 x 计算补数 y = target - x。
  3. 3. 若 waiting[y] > 0，输出 [y, x] 并令计数减一。
  4. 4. 否则令 waiting[x]++，等待未来的补数。

边界

  • 空数组与单元素数组返回空结果。
  • x == target - x 时仍需两次出现才能配对。
  • 重复值必须保存计数；奇数个相同值会剩下一份。
  • 负数、零和未配对元素不需要特殊分支。

复杂度

时间
O(n) 期望，每个元素一次哈希查询与更新。
空间
O(n)，最坏所有元素都无法配对。

替代方案

排序后双指针也能找到最多数对，额外空间可更低，但时间为 O(n log n)，且若原地排序会改变输入。面试中优先哈希计数；受限内存或输入已排序时再选双指针。

面试追问

  • 问：为什么不能用 Set？
    答：集合丢失重复次数，无法正确处理多组相同配对。
  • 问：能否先存当前值再查补数？
    答：当 2 * x == target 时会把同一元素与自己配对，因此必须先查后存。
  • 问：答案顺序如何保证？
    答：题目不要求顺序；若业务要求稳定顺序，需要定义排序规则后再整理结果。

常见错误

  • 补数命中后忘记将计数减一，导致元素被重复使用。
  • 计数减到零仍不断累积无效键，增加理解与调试成本。
  • 把“返回所有可行组合”误解成允许一个元素参与多个数对。
  • 使用双层循环后只标记一侧元素，产生重叠配对。

class Solution {
    public List<List<Integer>> pairSums(int[] nums, int target) {
        Map<Integer, Integer> waiting = new HashMap<>();
        List<List<Integer>> answer = new ArrayList<>();

        for (int x : nums) {
            int y = target - x;
            int count = waiting.getOrDefault(y, 0);
            if (count > 0) {
                answer.add(Arrays.asList(y, x));
                if (count == 1) {
                    waiting.remove(y);
                } else {
                    waiting.put(y, count - 1);
                }
            } else {
                waiting.put(x, waiting.getOrDefault(x, 0) + 1);
            }
        }
        return answer;
    }
}

var pairSums = function (nums, target) {
    const waiting = new Map();
    const answer = [];

    for (const x of nums) {
        const y = target - x;
        const count = waiting.get(y) || 0;
        if (count > 0) {
            answer.push([y, x]);
            if (count === 1) {
                waiting.delete(y);
            } else {
                waiting.set(y, count - 1);
            }
        } else {
            waiting.set(x, (waiting.get(x) || 0) + 1);
        }
    }
    return answer;
};
class Solution:
    def pairSums(self, nums: List[int], target: int) -> List[List[int]]:
        waiting = {}
        answer = []

        for x in nums:
            y = target - x
            if waiting.get(y, 0) > 0:
                answer.append([y, x])
                waiting[y] -= 1
                if waiting[y] == 0:
                    del waiting[y]
            else:
                waiting[x] = waiting.get(x, 0) + 1

        return answer
class Solution {
public:
    vector<vector<int>> pairSums(vector<int>& nums, int target) {
        unordered_map<int, int> waiting;
        vector<vector<int>> answer;

        for (int x : nums) {
            int y = target - x;
            auto it = waiting.find(y);
            if (it != waiting.end() && it->second > 0) {
                answer.push_back({y, x});
                if (--it->second == 0) {
                    waiting.erase(it);
                }
            } else {
                ++waiting[x];
            }
        }
        return answer;
    }
};
