878. 第 N 个神奇数字

Nth Magical Number — 在一个巨大但有序的答案空间里，用“计数”代替“枚举”。先理解问题，再亲手推动二分边界。

HARD数学二分查找容斥原理最小公倍数

题目

如果一个正整数能被 a 或 b 整除，就称它为神奇数字。给定整数 n、a、b，返回从小到大排列后的第 n 个神奇数字。

答案可能很大，最终返回其对 10⁹ + 7 取模的结果。

官方示例

示例 1输入：n = 1, a = 2, b = 3 输出：2
示例 2输入：n = 4, a = 2, b = 3 输出：6

约束

  • 1 ≤ n ≤ 10⁹
  • 2 ≤ a, b ≤ 4 × 10⁴

题解：计数函数上的二分查找

二分的对象是答案，而不是数组下标。

O(log(n · min(a,b)))

核心洞察

对任意候选答案 x，都能在 O(1) 时间内算出区间 [1, x] 中有多少个神奇数字。这个数量随 x 单调不减，因此可以二分寻找第一个让数量达到 n 的 x。

设 L = lcm(a,b)。被 a 整除的有 ⌊x/a⌋ 个，被 b 整除的有 ⌊x/b⌋ 个，同时被二者整除的 ⌊x/L⌋ 个被算了两次。

count(x) = ⌊x / a⌋ + ⌊x / b⌋ − ⌊x / lcm(a,b)⌋

完整过程

  1. 计算最大公约数与最小公倍数。 使用欧几里得算法求 gcd；按 a / gcd(a,b) × b 的顺序计算 lcm，降低中间乘积溢出风险。
  2. 建立搜索区间。 第 n 个神奇数字一定不超过 n × min(a,b)，因此搜索闭区间 [1, n × min(a,b)]。
  3. 检查中点。 若 count(mid) ≥ n，说明 mid 已经可行，但可能还不是最小值，令右边界等于 mid；否则令左边界等于 mid + 1。
  4. 收敛并取模。 当左右边界相等时，该值就是第 n 个神奇数字。只在最后对 10⁹ + 7 取模，不能用取模后的值参与二分比较。

正确性证明

计数正确：由容斥原理，两个倍数集合的并集大小为两者大小之和减交集大小，交集恰是 lcm(a,b) 的倍数。

二分正确：谓词 P(x) = [count(x) ≥ n] 单调。算法始终保留最小满足 P 的值：P(mid) 为真时丢弃 mid 右侧但保留 mid；为假时 mid 及其左侧都不可能是答案。区间收敛时唯一值即最小可行值，也就是第 n 个神奇数字。

边界处理

  • a = b 时，lcm = a，计数自然退化为 ⌊x/a⌋。
  • n 可达 10⁹，中间答案可超过 32 位整数。
  • Java/C++ 使用 64 位整数；JavaScript 使用 BigInt。
  • 取模只发生在搜索完成之后。

复杂度

时间复杂度为 O(log(n · min(a,b)))；除语言运行时的整数对象外，额外空间复杂度为 O(1)。

四语言完整代码

Java long 防溢出
class Solution {
    private long gcd(long x, long y) {
        while (y != 0) {
            long temp = x % y;
            x = y;
            y = temp;
        }
        return x;
    }

    public int nthMagicalNumber(int n, int a, int b) {
        final long MOD = 1_000_000_007L;
        long lcm = (long) a / gcd(a, b) * b;
        long left = 1L;
        long right = (long) n * Math.min(a, b);

        while (left < right) {
            long mid = left + (right - left) / 2;
            long count = mid / a + mid / b - mid / lcm;
            if (count >= n) {
                right = mid;
            } else {
                left = mid + 1;
            }
        }
        return (int) (left % MOD);
    }
}
JavaScript BigInt 精确整数
/**
 * @param {number} n
 * @param {number} a
 * @param {number} b
 * @return {number}
 */
var nthMagicalNumber = function(n, a, b) {
    const gcd = (x, y) => {
        while (y !== 0n) {
            [x, y] = [y, x % y];
        }
        return x;
    };

    const N = BigInt(n);
    const A = BigInt(a);
    const B = BigInt(b);
    const lcm = (A / gcd(A, B)) * B;
    let left = 1n;
    let right = N * (A < B ? A : B);

    while (left < right) {
        const mid = left + (right - left) / 2n;
        const count = mid / A + mid / B - mid / lcm;
        if (count >= N) right = mid;
        else left = mid + 1n;
    }
    return Number(left % 1000000007n);
};

class Solution:
    def nthMagicalNumber(self, n: int, a: int, b: int) -> int:
        MOD = 10**9 + 7

        def gcd(x: int, y: int) -> int:
            while y:
                x, y = y, x % y
            return x

        lcm = a // gcd(a, b) * b
        left, right = 1, n * min(a, b)

        while left < right:
            mid = left + (right - left) // 2
            count = mid // a + mid // b - mid // lcm
            if count >= n:
                right = mid
            else:
                left = mid + 1

        return left % MOD

class Solution {
public:
    int nthMagicalNumber(int n, int a, int b) {
        const long long MOD = 1000000007LL;
        long long g = std::gcd(a, b);
        long long lcm = (long long)a / g * b;
        long long left = 1;
        long long right = (long long)n * std::min(a, b);

        while (left < right) {
            long long mid = left + (right - left) / 2;
            long long count = mid / a + mid / b - mid / lcm;
            if (count >= n) {
                right = mid;
            } else {
                left = mid + 1;
            }
        }
        return (int)(left % MOD);
    }
};

替代方案

可以使用两个指针生成 a、b 的倍数并合并去重，时间复杂度 O(n)，只适合很小的 n；也可利用 lcm 周期做数学分块，但实现更绕，二分更稳健且足够快。

面试追问

  • 为什么右边界 n × min(a,b) 一定覆盖答案？
  • 若扩展到三个除数，容斥公式如何变化？
  • 为什么寻找的是第一个 count(x) ≥ n，而非 count(x) = n？

常见错误

  • 忘记减去同时被 a 与 b 整除的数。
  • 把 gcd 当作交集的除数；交集应使用 lcm。
  • 用 32 位整数计算上界、lcm 或 mid。
  • 搜索过程中提前取模，破坏大小关系。
  • 更新为 right = mid - 1 后直接返回 left，混用了两种二分模板。
