核心洞察

相等时只排除右端点

大于时最小值在 mid 右侧，小于时 mid 仍可能是最小值；若两值相等，无法判断旋转断点在哪边，但删除 right 不会丢掉唯一更小的答案，因为 mid 仍保留着同值副本。

完整过程

  1. 初始化 left = 0，right = n - 1。
  2. 循环条件为 left < right，计算中点 mid。
  3. 若 nums[mid] 大于 nums[right]，令 left = mid + 1。
  4. 小于则 right = mid；相等则 right-- 消除一个冗余副本。

边界与复杂度

  • 单元素数组不进入循环，直接返回 nums[0]。
  • 全相等数组每轮只能缩短一格，但答案仍正确。
  • 平均 O(log n)，最坏 O(n)，额外空间 O(1)。

替代方案取舍

线性扫描稳定 O(n) 且更简单；带相等分支的二分通常更快，并直接复用第 153 题框架。重复值造成的信息损失决定了最坏情况无法保证 O(log n)。

常见错误

  • 相等时直接 right = mid，可能跨过右侧旋转断点。
  • 相等时左右边界同时移动，误删唯一最小值。
  • 声称重复值场景仍保证 O(log n)。
  • 用 nums[mid] 与 nums[0] 比较，却没处理首尾重复。

面试追问

为什么相等时删 right？mid 提供了同值副本，right 不可能是唯一答案。
为什么不能删 mid？在“小于”分支，mid 可能正是旋转断点。
退化样例是什么？全相等数组会让每轮比较都无法区分方向。 
class Solution {
    public int findMin(int[] nums) {
        int left = 0, right = nums.length - 1;
        while (left < right) {
            int mid = left + (right - left) / 2;
            if (nums[mid] > nums[right]) left = mid + 1;
            else if (nums[mid] < nums[right]) right = mid;
            else right--;
        }
        return nums[left];
    }
}
