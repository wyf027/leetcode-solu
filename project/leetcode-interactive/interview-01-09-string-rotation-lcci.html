字符串轮转

同一串字符放上环形转盘，起点可以改变，环上的相邻顺序不能改变。给定两张字符行李牌，判断它们是否来自同一圈轨道。

Manifest / 题目清单

题意

轮转只改变切分点，不允许打乱字符相对顺序。

任务

给定两个字符串 s1 和 s2，检查 s2 是否由 s1 轮转得到。题目进一步要求：能否只调用一次“判断一个字符串是否为另一个字符串子串”的方法？

轮转示例：把 water | bottle 的切分点移到开头，可得到 bottlewater；字符顺序沿环连续。

官方示例

示例 1 输入 s1 = "waterbottle", s2 = "erbottlewat"
示例 1 输出 true
示例 2 输入 s1 = "aa", s2 = "aba"
示例 2 输出 false
约束：0 <= s1.length, s2.length <= 100000。页面用成对直引号表示字符串；真实空格显示为 ␠，例如 "ab␠cd" 代表 ab cd。

打开检验舱

先想一想：如果把同一个环从任意一点剪开，它会出现在怎样的一条直线字符带中？

Boarding pass / 核心票据

核心洞察

把环剪开两次，就覆盖了所有可能的起点。

长度相同，且 s2 是 s1 + s1 的子串。

若 s1 = xy，某次轮转得到 s2 = yx。双倍字符串 s1 + s1 = xyxy 必然包含 yx；反过来，等长窗口若出现在双倍串中，恰好对应一个环形起点。

Security lane / 完整过程

完整过程

以 "waterbottle" 与 "erbottlewat" 为例。

  1. 检查长度
    两个字符串长度都为 11，轮转仍有可能成立；长度不同可立即返回 false。
  2. 拼接两圈
    构造 "waterbottlewaterbottle"，让原字符串的尾部与头部在中间自然相接。
  3. 只查一次子串
    在双倍串中查找 "erbottlewat"，从索引 3 开始完整命中。
  4. 返回结果
    长度相同且查找成功，因此返回 true。

Edge gates / 边界闸门

边界

先处理长度，空串语义才能自然成立。

空串

s1 = "", s2 = "" 长度相同，空串也是空双倍串的子串，返回 true。

长度不同

轮转不增删字符，长度不同必为 false；必须在包含判断前短路。

重复字符

"aaaa" 有多个等价起点，但包含关系仍能一次处理，不需要枚举切分点。

空格与大小写

空格是普通字符，比较区分大小写；"ab␠cd" 中的 ␠ 代表真实空格。

Throughput / 复杂度

复杂度

设两个字符串等长为 n。

O(n)线性子串算法下的时间
O(n)双倍字符串额外空间
复杂度取决于语言库的子串实现：若底层使用 KMP 等线性匹配，整体时间 O(n)；朴素查找最坏可能 O(n²)。面试中应主动说明这一实现依赖。

Alternate routes / 替代路线

替代方案

题目追问强调“一次子串调用”，主线最简洁。

枚举切分点

生成每个轮转并比较，容易理解，但创建 n 个长度为 n 的字符串，时间和临时分配可能达到 O(n²)。

显式 KMP

对 s2 构建前缀函数，再在逻辑上的两圈 s1 中匹配，可保证 O(n) 时间；也可通过下标取模避免真实拼接。

Interview desk / 追问柜台

面试追问

不仅会写一行，还要能证明它为什么正确。

为何必须长度相同？

没有长度门槛，短字符串可能碰巧是双倍串子串，却不可能是完整轮转。

如何证明充分性？

双倍串中任意长度 n 的连续窗口都对应从某个环形位置出发读 n 个字符，因此就是一个轮转。

能否不创建 s1+s1？

可在 KMP 扫描时用 s1[i % n] 访问逻辑双倍串，把额外字符空间降为模式前缀表 O(n)。

Unicode 有什么风险？

某些语言按 UTF-16 代码单元切分；若业务要求按用户感知字符轮转，需要先按 Unicode 字素簇建模。

Lost baggage / 常见错误

常见错误

多数错误来自缺少长度门槛或拼接方向混乱。

只写 contains

若省略长度相等检查，s1 = "abc", s2 = "ab" 会被错误判为 true。

拼接错对象

搜索 s2 时应使用 s1 + s1；反过来也能在等长前提下成立，但解释和变量角色容易混乱。

排除零次轮转

s1 === s2 应返回 true；零次轮转也是合法情况。

忘记空串

约束允许长度为 0；两个空串应判 true，手写取模扫描时尤其要避免除以零。

        return s1.length() == s2.length()
                && (s1 + s1).contains(s2);
    }
}
