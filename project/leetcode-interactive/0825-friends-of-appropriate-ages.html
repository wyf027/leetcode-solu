825. 适龄的朋友

Friends Of Appropriate Ages — 一道关于“有向关系”的年龄判断题。先读规则，再进入年龄走廊亲手观察每个请求为何成立或被拒绝。

数组 双指针 二分查找 排序

01 / Problem

题目在问什么

社交网站上有 n 个用户，ages[i] 表示第 i 个用户的年龄。对两个不同的人 x 与 y，只要下面任意拒绝条件成立，x 就不会向 y 发送请求；否则会发送。请返回全部有向好友请求的数量。

01

目标太年轻

ages[y] <= 0.5 × ages[x] + 7

02

目标比发送者年长

ages[y] > ages[x]

03

跨过 100 岁限制

ages[y] > 100 && ages[x] < 100

↗
请求有方向。 x → y 成立，不代表 y → x 也成立；任何人都不能向自己发送请求。

02 / Samples

官方示例

示例 01

输入
ages = [16,16]
输出
2
解释
两人互相发送请求。

示例 02

输入
ages = [16,17,18]
输出
2
解释
17 → 16，18 → 17。

示例 03

输入
ages = [20,30,100,110,120]
输出
3
解释
110 → 100，120 → 110，120 → 100。

约束

  • n == ages.length
  • 1 <= n <= 2 × 104
  • 1 <= ages[i] <= 120

05 / Solution

题解：年龄计数 + 前缀和

年龄只可能是 1–120。与其逐人比较，不如把人按年龄分桶，再一次性计算每个发送者年龄能够覆盖多少人。

核心洞察

固定发送者年龄 x。第二条规则要求 y <= x；第一条规则要求 y > x / 2 + 7。因为年龄是整数，最小目标年龄为：

minAge = floor(x / 2 + 7) + 1 = floor(x / 2) + 8

于是合法目标落在 [minAge, x]。同时满足 y <= x 后，当 x < 100 时必有 y < 100，第三条拒绝条件不会再额外排除任何人。

复杂度

  • 时间：O(n + A)
  • 空间：O(A)
  • A = 120，可视为常数

最大答案为 n(n-1)，在本题约束下不超过 399,980,000。

完整过程

  1. 用 count[a] 统计年龄 a 的人数。
  2. 构造前缀和 prefix[a]，让一个区间的人数可在 O(1) 内取得。
  3. 枚举发送者年龄 x = 15..120。小于 15 岁时合法年龄区间为空。
  4. 令 minAge = x / 2 + 8（整数除法），区间人数为 prefix[x] - prefix[minAge - 1]。
  5. 对每个发送者减去自己：单个发送者可请求人数是上述区间人数减 1。
  6. 乘上 count[x]，累加本年龄组产生的请求数。
answer += count[x] × (prefix[x] - prefix[minAge - 1] - 1)

边界清单

  • x = 14：下界为 15，大于上界 14，无请求。
  • x = 15：只能请求其他 15 岁的人。
  • 同龄多人：每人可以请求同组其他人，贡献 c × (c - 1)。
  • 单人同龄组：区间人数含自己，减一后贡献为 0。
  • 请求是有向的，不能把双向关系除以 2。

正确性证明

  1. 区间等价。 对固定的 x，不触发规则一当且仅当整数年龄 y > x/2+7，即 y >= minAge；不触发规则二当且仅当 y <= x。规则三在这个区间内不会额外成立。因此所有且仅有合法目标年龄位于 [minAge, x]。
  2. 单个发送者计数正确。 前缀和精确给出该闭区间内的全部人数。发送者本人也在其中，减去 1 后，剩余人数恰好是这个人会发送请求的目标数。
  3. 按组累加无重无漏。 年龄为 x 的每个人都有相同目标人数，乘以 count[x] 得到本组全部有向请求。不同发送者属于唯一年龄组，所以对所有 x 求和既不重复也不遗漏。

由以上三点，算法返回的总数正是全部合法好友请求数。

四语言完整实现

class Solution {
    public int numFriendRequests(int[] ages) {
        int[] count = new int[121];
        for (int age : ages) {
            count[age]++;
        }

        int[] prefix = new int[121];
        for (int age = 1; age <= 120; age++) {
            prefix[age] = prefix[age - 1] + count[age];
        }

        int answer = 0;
        for (int x = 15; x <= 120; x++) {
            if (count[x] == 0) {
                continue;
            }
            int minAge = x / 2 + 8;
            int targetsPerPerson = prefix[x] - prefix[minAge - 1] - 1;
            answer += count[x] * targetsPerPerson;
        }
        return answer;
    }
}

替代方案

  • 排序 + 双指针：排序后，为每个发送者维护第一个大于阈值的位置和最后一个不大于发送者的位置。时间 O(n log n)，空间取决于排序实现。
  • 排序 + 二分查找：对每个年龄分别查上下界，思路直接，同样是 O(n log n)。
  • 枚举两人：O(n²)，只适合解释规则或极小输入，无法承受 n = 2 × 10⁴。

面试追问

  • 为什么第三条规则可以在推导后省略？
  • 为什么下界必须是严格大于，而上界可以取等？
  • 若年龄上限扩大到 10⁹，你会怎样改？
  • 为什么答案不能除以 2？

常见错误

  • 把 0.5 × x + 7 的严格边界写成包含阈值，导致 16 岁错误地向 15 岁发送请求。
  • 区间人数没有减去发送者自己，使每个合法年龄组都多算。
  • 只算不同年龄之间的请求，遗漏同龄人之间的 c × (c - 1)。
  • 把请求当成无向边，最终除以 2；但不同年龄之间通常只有一个方向成立。
  • 使用浮点数拼边界，增加不必要的精度与取整风险；整数式 x / 2 + 8 更稳妥。
