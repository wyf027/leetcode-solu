Sort Array by Increasing Frequency

按照频率将数组
升序排序

这里的排序依据不只看数值。先读懂两级规则，再用交互实验观察数组如何一步步落位；完整题解默认收在页面底部。

Problem

题目要求

给定整数数组 nums，请按每个数值在数组中出现的频率从低到高排列；当两个数值的出现频率相同时，数值较大的排在前面。返回排序后的完整数组。

比较规则有两层
  1. 出现次数少的数值优先。
  2. 出现次数相同，则数值更大的优先。
示例 1 
输入：nums = [1,1,2,2,2,3]
输出：[3,1,1,2,2,2]
解释：3、1、2 的频率依次为 1、2、3。
示例 2 
输入：nums = [2,3,1,3,2]
输出：[1,3,3,2,2]
解释：2 与 3 同为 2 次，因此 3 排在 2 前面。
示例 3 
输入：nums = [-1,1,-6,4,5,-6,1,4,1]
输出：[5,-1,4,4,-6,-6,1,1,1]

约束

  • 1 <= nums.length <= 100
  • -100 <= nums[i] <= 100

Solution

计数 + 自定义比较器

把“频率升序、数值降序”直接翻译成排序比较器。

核心洞察

排序时，一个元素 x 的主键是 frequency[x]，越小越靠前；只有主键相同，才使用次键 x，而次键要求降序。因此比较器可以写成：

frequency[a] !== frequency[b] ? frequency[a] - frequency[b] : b - a

完整过程

  1. 遍历 nums，用哈希表统计每个数的出现次数。
  2. 对原数组排序。先比较两个数的频率。
  3. 频率不同时，频率小者在前。
  4. 频率相同时，数值大者在前。
  5. 返回排序后的数组。

边界情况

  • 只有一个元素：无需特殊分支。
  • 所有元素相同：排序后数组不变。
  • 所有元素频率相同：整体按数值降序。
  • 包含负数或零：比较器仍然成立。
  • 多组相同频率：每组内部都按数值降序。

正确性证明

引理 1：若 frequency[a] < frequency[b]，比较器返回负值，所以 a 一定排在 b 前，满足频率升序。

引理 2：若两者频率相同且 a > b，则 b - a < 0，所以 a 排在 b 前，满足数值降序。

结论：任意两个元素都按题目规定的优先级确定相对次序，因此最终数组满足全部排序要求。

复杂度

时间：O(n log n)，计数为 O(n)，排序为主导项。

空间：O(k)（不计排序实现的额外空间），其中 k 是不同数值的个数，且 k ≤ n。

替代方案

约束给出数值范围 [-100, 100]，可以用长度 201 的数组代替哈希表；还可以先排序不同数值，再按频率重复写回。两者仍需正确处理同频时的降序规则。

四语言完整实现

JavaHashMap + boxed sort
import java.util.*;

class Solution {
    public int[] frequencySort(int[] nums) {
        Map<Integer, Integer> frequency = new HashMap<>();
        for (int value : nums) {
            frequency.put(value, frequency.getOrDefault(value, 0) + 1);
        }

        Integer[] boxed = Arrays.stream(nums).boxed().toArray(Integer[]::new);
        Arrays.sort(boxed, (a, b) -> {
            int byFrequency = Integer.compare(frequency.get(a), frequency.get(b));
            return byFrequency != 0 ? byFrequency : Integer.compare(b, a);
        });

        for (int i = 0; i < nums.length; i++) {
            nums[i] = boxed[i];
        }
        return nums;
    }
}
JavaScriptMap + comparator
/**
 * @param {number[]} nums
 * @return {number[]}
 */
var frequencySort = function(nums) {
    const frequency = new Map();

    for (const value of nums) {
        frequency.set(value, (frequency.get(value) || 0) + 1);
    }

    return nums.sort((a, b) => {
        const byFrequency = frequency.get(a) - frequency.get(b);
        return byFrequency !== 0 ? byFrequency : b - a;
    });
};
Python 3Counter + tuple key
from collections import Counter
from typing import List


class Solution:
    def frequencySort(self, nums: List[int]) -> List[int]:
        frequency = Counter(nums)
        return sorted(nums, key=lambda value: (frequency[value], -value))
C++unordered_map + lambda
class Solution {
public:
    vector<int> frequencySort(vector<int>& nums) {
        unordered_map<int, int> frequency;
        for (int value : nums) {
            ++frequency[value];
        }

        sort(nums.begin(), nums.end(), [&](int a, int b) {
            if (frequency[a] != frequency[b]) {
                return frequency[a] < frequency[b];
            }
            return a > b;
        });

        return nums;
    }
};

面试追问

为什么次键写成负数值或反向比较？

因为排序 API 通常默认按键升序。把次键设为 -value，或在比较器中比较 b - a，就能让更大的原数值先出现。

能否做到比 O(n log n) 更快？

本题频率最大为 n、数值范围也很小，可以按频率分桶并在桶内按数值降序组织；在利用约束时可接近 O(n + V)，其中 V 是数值范围，但实现更复杂。

如果数值范围非常大怎么办？

继续使用哈希表统计即可，空间只与实际出现的不同数值数量有关，不依赖数值范围。

常见错误

  • 同频时仍按数值升序，忘记题目要求的是降序。
  • 只对不同数值排序，却没有按其频率重复写入结果。
  • 在比较器执行期间修改频率表，导致比较关系不稳定。
  • 使用减法比较极大整数时忽略溢出；Java 中用 Integer.compare 更稳妥。
