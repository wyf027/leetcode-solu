Problem 1128

等价多米诺骨牌对的数量

Number of Equivalent Domino Pairs

题目描述

旋转后相同，也算同一种骨牌

给定二维整数数组 dominoes，其中 dominoes[i] = [a, b] 表示第 i 张多米诺骨牌。

若两张骨牌 [a,b] 与 [c,d] 满足 a=c 且 b=d，或满足 a=d 且 b=c，它们就是等价的；也就是将其中一张旋转 0° 或 180° 后可以与另一张完全一致。

请返回索引对 (i,j) 的数量，其中 0 ≤ i < j < dominoes.length，并且两张骨牌等价。

注意：统计的是“索引对”，不是不同骨牌种类的数量。同一类中每一对不同下标都应计入答案。
输入约束

参数形式

numEquivDominoPairs(dominoes) → integer

  • 1 ≤ dominoes.length ≤ 4 × 10⁴
  • dominoes[i].length = 2
  • 1 ≤ dominoes[i][j] ≤ 9
示例 1 
输入：dominoes = [[1,2],[2,1],[3,4],[5,6]]
输出：1

只有下标 (0,1) 构成等价骨牌对。

示例 2 
输入：dominoes = [[1,2],[1,2],[1,1],[1,2],[2,2]]
输出：3

三张 [1,2] 两两配对，共有 3 对。

完整题解

统一方向，边扫描边计数

核心洞察

骨牌 [a,b] 和 [b,a] 应进入同一类。把每张骨牌统一写成 [min(a,b), max(a,b)]，就得到不受旋转影响的“标准形”。

由于点数仅为 1～9，可以把标准形编码为 key = min × 10 + max。例如 [2,1] 与 [1,2] 都映射到键 12。

为什么扫描时直接累加？

处理当前骨牌前，若相同标准形已经出现 k 次，那么当前骨牌能分别与这 k 张旧骨牌组成新索引对，所以答案恰好增加 k。随后再把该类计数加一。

answer += count[key]; count[key]++;

完整过程

  1. 建立计数容器。记录每个标准形在已扫描前缀中出现了多少次。
  2. 归一化当前骨牌。取两个点数的较小值与较大值，生成唯一键。
  3. 结算新配对。读取该键之前的出现次数，将其加到答案中。
  4. 登记当前骨牌。该键的出现次数加一，继续扫描下一张。

复杂度

时间 O(n)；使用长度 100 的计数数组时，额外空间为 O(1)。

边界情况

单张骨牌答案为 0；双数相同如 [5,5] 无需旋转；大量相同骨牌按组合数自然累计。

答案范围

最坏约为 n(n-1)/2。本题上限 4×10⁴，结果为 799,980,000，32 位有符号整数可容纳。

正确性证明

引理 1：两张骨牌等价，当且仅当它们归一化后的有序对相同。因为归一化保留两个点数的多重集合，并消除了左右顺序；旋转只会交换左右位置，不会改变该多重集合。

引理 2：处理下标 j 时，count[key] 等于所有满足 i<j 且与 dominoes[j] 等价的下标 i 的数量。由引理 1，相同键恰好刻画等价关系；计数容器此时只含已处理下标。

定理：算法返回全部等价骨牌索引对的数量。每个合法对 (i,j) 在处理其较大下标 j 时由引理 2 恰好累加一次；它不会更早出现，也不会在之后重复。因此所有且仅有合法对被统计一次。

替代方案与取舍

  • 排序后分组：先归一化每张骨牌，再按键排序；每组大小为 k 时贡献 k(k-1)/2。正确但时间为 O(n log n)，还会修改或复制数据。
  • 哈希表：点数范围未知或很大时，可用字符串/二元组作为键，仍为平均 O(n)；本题范围很小，定长数组更简单。
  • 暴力枚举：检查所有下标对需要 O(n²)，在 4×10⁴ 的规模下不可接受。

常见错误

  • 把 [1,2] 与 [2,1] 记录成两个键，遗漏旋转等价关系。
  • 先将当前计数加一再累加，导致每张骨牌错误地与自己配对。
  • 每一类只加 1，误把“索引对数量”当成“存在等价关系的种类数”。
  • 使用 a+b 作为键；不同骨牌如 [1,4] 与 [2,3] 会碰撞。

Java
class Solution {
    public int numEquivDominoPairs(int[][] dominoes) {
        int[] count = new int[100];
        int answer = 0;

        for (int[] domino : dominoes) {
            int low = Math.min(domino[0], domino[1]);
            int high = Math.max(domino[0], domino[1]);
            int key = low * 10 + high;
            answer += count[key];
            count[key]++;
        }
        return answer;
    }
}
