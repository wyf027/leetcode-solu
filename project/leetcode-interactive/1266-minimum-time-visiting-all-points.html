访问所有点的
最小时间Minimum Time Visiting All Points

给定平面上的一串整数坐标，按数组顺序逐一到访。每秒可以横移、纵移，或同时在两个方向各移动一格。求完成整段旅程所需的最少秒数。

↔ 水平每秒横坐标改变 1
↕ 垂直每秒纵坐标改变 1
⤢ 对角每秒横、纵坐标各改变 1
Problem

题目要求

平面上有 n 个整数坐标点 points[i] = [xᵢ, yᵢ]。从 points[0] 出发，必须按照数组中的先后顺序访问所有点，返回最少总用时。

一秒内允许水平移动一格、垂直移动一格，或者沿对角线移动——即横纵方向同时各移动一格。途中即使经过尚未轮到的点，也不能提前算作已经访问。

函数形式： minTimeToVisitAllPoints(points)，参数为二维整数数组，返回整数秒数。

约束

  • points.length == n
  • 1 <= n <= 100
  • points[i].length == 2
  • -1000 <= xᵢ, yᵢ <= 1000
Official examples

官方示例

示例 1

输入：points = [[1,1],[3,4],[-1,0]]
输出：7

一种最优路线为：[1,1] → [2,2] → [3,3] → [3,4] → [2,3] → [1,2] → [0,1] → [-1,0]。两段分别用时 3 秒和 4 秒。

示例 2

输入：points = [[3,2],[-2,2]]
输出：5

两点纵坐标相同，只需连续水平移动 5 格。

Core insight

核心洞察：两种位移可以并行消化

从 A 到 B，先尽可能走对角线，同时缩小横向与纵向差；当较小的坐标差归零后，再直线走完剩余差值。因此一段路的最短时间，是两个坐标差绝对值中的较大者。

time(A, B) = max(|x₂ − x₁|, |y₂ − y₁|)

这正是二维平面上的切比雪夫距离。题目规定按顺序访问，所以整条路线没有重新排序或全局绕路的余地：把每一对相邻点的最短时间相加即可。

Walkthrough

完整过程

遍历相邻点对。 从下标 1 开始，将 points[i-1] 视为起点、points[i] 视为终点。
计算两轴差值。 令 dx = |x₂-x₁|、dy = |y₂-y₁|。
取较大差值。 可用 min(dx,dy) 次对角移动同时减少两轴差；余下 |dx-dy| 次直线移动，总计 max(dx,dy)。
累加答案。 每一段都独立达到最短，总和就是按序访问全部点的最少时间。

示例 1 推演

[1,1] → [3,4]: dx = 2, dy = 3, 用时 max(2,3) = 3
[3,4] → [-1,0]: dx = 4, dy = 4, 用时 max(4,4) = 4
总用时 = 3 + 4 = 7
Correctness

正确性证明

下界

设两点坐标差为 dx 和 dy。一次移动最多让横坐标差减少 1，也最多让纵坐标差减少 1。因此消除较大的那一维差值至少需要 max(dx,dy) 秒，任何路线都不可能更快。

可达上界

先走 min(dx,dy) 次正确方向的对角线，再沿差值未归零的轴走 |dx-dy| 次。总步数为 min(dx,dy)+|dx-dy|=max(dx,dy)，恰好达到下界。

所以每对相邻点的最短用时都是 max(dx,dy)。由于访问顺序固定，任意完整路线都由这些相邻段首尾相接；逐段取最优并求和，所得总时间全局最小。

Implementation

四种语言完整代码

Java · 官方签名O(n) time / O(1) space
class Solution {
    public int minTimeToVisitAllPoints(int[][] points) {
        int total = 0;
        for (int i = 1; i < points.length; i++) {
            int dx = Math.abs(points[i][0] - points[i - 1][0]);
            int dy = Math.abs(points[i][1] - points[i - 1][1]);
            total += Math.max(dx, dy);
        }
        return total;
    }
}

Complexity & edges

复杂度与边界

时间 O(n)

仅扫描一次相邻点对，每一段进行常数次运算。

空间 O(1)

除累计值和两个差值外，不随输入规模分配额外空间。

坐标安全

坐标范围为 ±1000，差值和总和在普通 32 位整数范围内。

需要留意的边界

  • 只有一个点时没有路段，答案为 0。
  • 相邻点重合时，该段贡献 0。
  • 水平或垂直对齐时，没有有效的对角收益，答案就是非零轴差。
  • 负坐标不影响计算；先相减再取绝对值。
Alternatives & interview

替代思路、追问与常见错误

替代方案：逐秒模拟

对每一段反复朝目标移动：两轴都未对齐时走对角，否则直走。这能得到正确答案，也适合输出具体路径，但用时与答案大小有关；只求时间时直接计算距离更简洁。

面试追问：如果不能走对角线？

每秒只能改变一个坐标，单段距离改为曼哈顿距离 dx + dy。

面试追问：如果允许任意顺序访问？

问题不再能逐段独立求和，会变成寻找访问顺序的路径优化问题；规模较小时可考虑状态压缩动态规划，规模较大时通常需要近似或启发式算法。

面试追问：怎样还原一条最短路线？

每秒将当前点的横坐标向目标靠近最多 1，同时也将纵坐标靠近最多 1，并记录新位置，直到到达目标。

常见错误

  • 误用 dx + dy，忽略一次对角移动能同时消除两个方向的差。
  • 误用欧氏距离或开平方；本题问离散移动所需秒数，并非直线几何长度。
  • 把 min(dx,dy) 当作整段答案，漏掉对角移动后剩余的直线部分。
  • 试图重新排列点，忽视“按给定顺序访问”的硬性条件。
