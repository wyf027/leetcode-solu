到达终点 Reaching Points

从一个正整数坐标出发，每一步只能把一个坐标加到另一个坐标上。给定起点和终点，判断是否存在一条合法路径。

每次二选一

(x, y)
→
(x, x+y)
(x, y)
→
(x+y, y)

坐标始终为正，且永不减小。怎样避开指数级的正向分叉？先保留这个问题。

Problem

题意与边界

给定四个整数 sx、sy、tx、ty。若从起点 (sx, sy) 经过零次或多次合法转换可以到达 (tx, ty)，返回 true；否则返回 false。

允许的转换

对当前点 (x, y)，每一步只能选择下列一种操作：

(x, y) → (x, x + y)
(x, y) → (x + y, y)

函数形式

reachingPoints(sx, sy, tx, ty) → boolean

约束
1 ≤ sx, sy, tx, ty ≤ 109
示例 01

可以到达

输入: sx = 1, sy = 1, tx = 3, ty = 5
输出: true

(1,1) → (1,2) → (3,2) → (3,5)

示例 02

无法到达

输入: sx = 1, sy = 1, tx = 2, ty = 2
输出: false

两个相等的正坐标无法由上一步的“一边加到另一边”产生。

示例 03

零步到达

输入: sx = 1, sy = 1, tx = 1, ty = 1
输出: true

    Editorial

    从减法倒推到取模

    正向选择会形成二叉分支；反向时，较大的坐标决定了唯一可能的上一类操作。再把连续减法压成一次取模，就得到欧几里得算法式的解法。

    核心洞察

    终点里较大的那一维，必然由“较小维 + 某个前值”得到。

    若 tx > ty，最后若干步只能不断给 x 加 y；因此可把 tx -= ty 的重复过程合并成 tx %= ty。

    1. 先做必要性剪枝

      正向操作只会增大坐标，所以一旦 tx < sx 或 ty < sy，必定不可达。

    2. 双方都未碰到起点边界时取模

      当 tx > sx 且 ty > sy，对较大坐标取模：tx %= ty 或 ty %= tx。

    3. 碰到一条边界后批量判断

      若 tx == sx，之后 x 必须保持不变，只能反复让 y 增加 sx；检查 ty ≥ sy 且 (ty-sy) % sx == 0。另一维同理。

    完整过程示例

    对 (1,1) → (3,5) 倒推：

    (3, 5)
ty %= tx  → (3, 2)
tx %= ty  → (1, 2)
tx == sx
(2 - 1) % 1 == 0
因此可达

    正确性证明

    引理：对一个正坐标点，若两维不相等，则它的前驱类型唯一。若 tx > ty，最后一步不可能是把 x 加到 y（那会令 y 更大），所以前驱只能是 (tx-ty, ty)；ty > tx 时对称成立。

    批量等价：连续执行唯一逆操作 tx -= ty，直到 x 不再大于 y，与 tx %= ty 得到相同余数。只要双方仍严格大于起点坐标，这些被跳过的中间值不可能是起点。

    边界：当一维等于起点对应维时，合法后续只能保持该维不变，并让另一维每次增加这个固定值；整除条件恰好刻画了可达性。算法每轮保持“当前点可由起点到达”的真假不变，最终判断因此充分且必要。

    边界情况

    • 起点等于终点：零次操作，返回 true。
    • 终点任一坐标小于起点对应坐标：返回 false。
    • 一维已经等于起点：不能继续无条件取模，必须用差值整除判断。
    • 坐标可能达到 109，正向枚举路径会爆炸。
    • 所有坐标均为正，不存在除数为零的问题；取模可能产生 0，但随后会自然判为不可达。
    O(log max(tx, ty))时间复杂度，等价于欧几里得算法
    O(1)额外空间复杂度

    替代方案

    • 正向 DFS / BFS：思路直观，但状态呈指数分叉；在 109 范围不可行。
    • 反向逐次相减：逻辑正确，却可能需要接近 109 次；取模是它的批量加速。
    • 只比较 gcd：操作确实保持最大公约数，但 gcd 相同只是必要条件，不足以判断带方向和下界的可达性。

    面试追问

    • 为什么反向路径几乎唯一，而正向路径有分支？
    • 为什么循环条件必须是双方都严格大于起点对应值？
    • 如何从“连续减法”严格推出取模优化？
    • 如果允许坐标为 0，算法的除零与边界该如何调整？

    常见错误

    • 从起点正向搜索，没有利用坐标单调性和唯一逆操作。
    • 写成 while (tx > sx || ty > sy)，导致越过一条已到达的起点边界。
    • 在边界处仅判断坐标相等，遗漏“剩余差值是固定坐标倍数”的情况。
    • 把“gcd 相等”当成充分条件。例如起点 (1,1) 与终点 (2,2) gcd 相同，但不可达。

    四语言完整代码

    Java · LeetCode 可提交实现
    class Solution {
    public boolean reachingPoints(int sx, int sy, int tx, int ty) {
        while (tx > sx && ty > sy) {
            if (tx > ty) {
                tx %= ty;
            } else {
                ty %= tx;
            }
        }

        return (tx == sx && ty >= sy && (ty - sy) % sx == 0)
            || (ty == sy && tx >= sx && (tx - sx) % sy == 0);
    }
}
