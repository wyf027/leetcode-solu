01 / Problem

题目与接口

每个元素必须且只能归入一个子集；元素的相对顺序不重要。

任务

输入整数数组 nums。如果存在一种分法，让两个子集覆盖数组中的全部元素，且两边元素和相同，返回 true；否则返回 false。

canPartition(nums: integer[]) -> boolean

示例 1

输入：nums = [1,5,11,5]
输出：true
解释：[1,5,5] 与 [11] 的和均为 11。

示例 2

输入：nums = [1,2,3,5]
输出：false
解释：不存在满足条件的两组划分。

约束

  • 1 <= nums.length <= 200
  • 1 <= nums[i] <= 100
  • nums 非空，且只含正整数。

准备好揭开完整解法了吗？

Complete Walkthrough

把分割问题改写成一次装载

设数组总和为 S。如果 S 为奇数，不可能均分；若为偶数，只需判断能否从数组中选出若干元素，使它们的和恰好为 S / 2。剩余元素自然组成另一半。

1

先看奇偶

相同的两个整数和必然产生偶数总和，所以奇数总和可以直接返回 false。

2

状态压缩

dp[j] 表示用已经处理过的数字，能否凑出子集和 j。初始只有 dp[0] = true。

3

容量倒序

处理数字 x 时从目标倒推到 x，令 dp[j] |= dp[j-x]，保证同一元素不会在本轮被重复使用。

完整过程

  1. 求出 sum；若为奇数，立即返回 false。
  2. 令目标容量 target = sum / 2，建立长度为 target + 1 的布尔数组。
  3. 设置 dp[0] = true，表示“不选任何数”可以得到和 0。
  4. 依次处理每个 num；容量 j 从 target 递减到 num。
  5. 若旧状态中 j - num 可达，则加入当前数后 j 也可达。
  6. 全部处理后返回 dp[target]；也可以一旦目标可达就提前返回。

复杂度

时间 O(n × target)空间 O(target)

由约束可知总和最多是 200 × 100 = 20000，目标最多 10000，因此一维布尔数组足够实用。

为什么不能正序？

若容量正序更新，本轮刚得到的 dp[j] 可能立即被更大的容量再次读取，相当于同一个数字可使用多次，问题会被错误地变成“完全背包”。

Correctness

正确性证明

状态不变式

处理完前 i 个元素后，dp[j] 为真，当且仅当能从这 i 个元素中选择一个子集，其元素和为 j。

初始化成立

尚未处理元素时，只有空集可选，和为 0，所以仅 dp[0] 为真，符合不变式。

转移保持不变式

处理 num 时，和为 j 的方案要么不选它（保留原 dp[j]），要么选择它（要求此前 j-num 可达）。倒序扫描确保“此前”只涉及尚未被本轮改写的状态，因此每个元素最多使用一次。

结论成立

处理所有元素后，不变式说明 dp[target] 精确表示是否存在和为总和一半的子集。若存在，补集之和也为一半；若不存在，则不可能等和分割。

Implementations

四语言完整代码

均采用一维 0-1 背包，并保留目标可达后的提前结束。

class Solution {
    public boolean canPartition(int[] nums) {
        int sum = 0;
        for (int num : nums) {
            sum += num;
        }
        if ((sum & 1) == 1) {
            return false;
        }

        int target = sum / 2;
        boolean[] dp = new boolean[target + 1];
        dp[0] = true;

        for (int num : nums) {
            for (int j = target; j >= num; j--) {
                dp[j] = dp[j] || dp[j - num];
            }
            if (dp[target]) {
                return true;
            }
        }
        return dp[target];
    }
}

class Solution:
    def canPartition(self, nums: List[int]) -> bool:
        total = sum(nums)
        if total % 2 == 1:
            return False

        target = total // 2
        dp = [False] * (target + 1)
        dp[0] = True

        for num in nums:
            for current in range(target, num - 1, -1):
                dp[current] = dp[current] or dp[current - num]
            if dp[target]:
                return True

        return dp[target]

边界情况

  • 总和为奇数：立即不可分。
  • 只有一个正整数：不可能形成两个等和子集。
  • 某个元素大于目标：它无法放进目标子集，整体也不可能成功。
  • 大量重复数字：仍按位置视作不同元素，各自只能使用一次。
  • 目标很早可达：可以提前返回，不影响正确性。

常见错误

  • 忘记先检查总和奇偶，导致非整数目标或错误下标。
  • 把容量从小到大更新，让同一元素被重复使用。
  • 遗漏 dp[0] = true，使所有转移都失去起点。
  • 误以为必须显式构造两个子集；判断题只需找到其中一半。
  • 使用整数最大值等数值型状态，徒增溢出与初始化风险。

替代方案

  • 二维 DP：dp[i][j] 记录前 i 个数能否凑出 j，更直观但空间为 O(n × target)。
  • 集合递推：维护所有可达和的集合，表达清晰，但哈希开销通常更大。
  • 位集 Bitset：用 bits |= bits << num 批量移动状态，常数很小；不同语言的大整数/位集写法差异较大。
  • 回溯：最坏指数级，只适用于很小输入或配合强剪枝。
