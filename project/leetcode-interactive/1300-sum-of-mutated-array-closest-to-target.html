转变数组后最接近目标值的数组和

给数组加一条可移动的“天花板”：高于它的数字被削平。你要找到一条整数高度，让新数组之和尽量靠近目标。

MEDIUM非付费题数组二分查找排序

Problem

题目要求

给定整数数组 arr 和整数 target。选择一个整数 value，把 arr 中每个大于 value 的元素都改成 value，其余元素保持不变。

返回使转变后数组和与 target 的绝对差最小的 value。若有多个值同样接近，返回其中较小者。答案不要求来自原数组。

函数形式： findBestValue(arr, target) → integer

官方示例

示例 1

输入：arr = [4,9,3], target = 10
输出：3
解释：转变为 [3,3,3]，和为 9。

示例 2

输入：arr = [2,3,5], target = 10
输出：5

示例 3

输入：arr = [60864,25176,27249,21296,20204],
      target = 56803
输出：11361

约束

  • 1 ≤ arr.length ≤ 104
  • 1 ≤ arr[i], target ≤ 105

Solution

二分答案：寻找单调和函数的交界

核心洞察

定义 S(v) = Σ min(arr[i], v)。当 v 增大时，S(v) 单调不减。因此可二分找到第一个令 S(v) ≥ target 的值 v。

最优答案只可能在交界两侧：v 或 v - 1。比较两者的绝对差；相等时按题意取较小的 v - 1。

完整过程

  1. 令搜索区间为 [0, max(arr)]。
  2. 取中点 mid，遍历数组计算 S(mid)。
  3. 若 S(mid) < target，说明上限偏低，令 left = mid + 1；否则令 right = mid。
  4. 收敛后比较 left 与 left - 1，差相等时返回后者。

正确性证明

  1. 单调性：对任意 v₁ < v₂，每个元素都有 min(aᵢ,v₁) ≤ min(aᵢ,v₂)，求和得到 S(v₁) ≤ S(v₂)。
  2. 二分边界：二分结束时，left 是满足 S(left) ≥ target 的最小整数；因此 S(left - 1) < target（若 left = 0，只需考虑 0）。
  3. 候选完备：所有小于 left - 1 的值，其和不超过 S(left - 1)，不会更接近；所有大于 left 的值，其和不小于 S(left)，也不会更接近。故最优解必在两者中。
  4. 平局规则：比较两个绝对差；严格更小时选 left，否则选更小的 left - 1。算法返回值满足题意。

边界情况

  • target 很小：答案可能小于数组最小值，甚至是 0。
  • target ≥ sum(arr)：取 max(arr) 已保持原数组不变；更大的值无额外作用。
  • 两个候选与目标等距：必须返回较小值。
  • 数组只有一个元素，单调性和交界判断仍成立。

复杂度

时间
O(n log M)空间
O(1)

其中 n = arr.length，M = max(arr)。每次判断扫描数组，最多进行 log M 次二分。

替代方案

排序 + 前缀思路：将数组排序，逐段确定哪些元素保留原值、哪些元素被截断，再从剩余目标均摊出候选上限。它可做到 O(n log n)，也能更直接解释答案为何不一定在数组中，但实现细节和舍入平局更容易出错。

枚举：枚举 0..max(arr) 并逐个求和，复杂度 O(nM)，在本题上界下不够稳妥。

class Solution {
    public int findBestValue(int[] arr, int target) {
        int left = 0, right = 0;
        for (int x : arr) right = Math.max(right, x);

        while (left < right) {
            int mid = left + (right - left) / 2;
            if (mutatedSum(arr, mid) < target) {
                left = mid + 1;
            } else {
                right = mid;
            }
        }

        int highDiff = Math.abs(mutatedSum(arr, left) - target);
        int low = Math.max(0, left - 1);
        int lowDiff = Math.abs(mutatedSum(arr, low) - target);
        return highDiff < lowDiff ? left : low;
    }

    private int mutatedSum(int[] arr, int value) {
        int sum = 0;
        for (int x : arr) sum += Math.min(x, value);
        return sum;
    }
}

var findBestValue = function(arr, target) {
    let left = 0;
    let right = Math.max(...arr);

    const mutatedSum = (value) =>
        arr.reduce((sum, x) => sum + Math.min(x, value), 0);

    while (left < right) {
        const mid = left + Math.floor((right - left) / 2);
        if (mutatedSum(mid) < target) {
            left = mid + 1;
        } else {
            right = mid;
        }
    }

    const low = Math.max(0, left - 1);
    const highDiff = Math.abs(mutatedSum(left) - target);
    const lowDiff = Math.abs(mutatedSum(low) - target);
    return highDiff < lowDiff ? left : low;
};

面试追问

  • 为什么不能在数组元素中二分，而要在值域中二分？
  • 如何用排序和前缀和把每次求和从 O(n) 降低到 O(log n)？
  • 若平局时要求返回较大值，最终比较该如何变化？
  • 若数组和可能超过 32 位整数，应怎样调整类型？

常见错误

  • 只比较二分收敛值，没有检查相邻的 value - 1。
  • 差值相等时返回较大候选，违反平局规则。
  • 把所有元素都改为 value，而不是只截断更大的元素。
  • 搜索上界随意设为 target，忽略数组本身的有效上界。

快速复盘

为什么答案可能不在 arr 中？

上限值代表截断高度。多个较大元素共同被截断时，最合适的高度可能落在相邻数组值之间。

为什么只比较两个相邻候选？

转变后的和关于 value 单调不减；离目标最近的位置就在第一次达到目标的交界两侧。

这里的二分查找对象是什么？

二分的是答案值域 [0, max(arr)]，判断条件是转变后数组和是否达到 target。
