黑板异或游戏

一局规则反直觉的擦除游戏：每一步都安全，并不代表最终能赢。先读规则，再亲手推进一盘对局。

题目

题意转述

黑板上写着非负整数数组 nums。Alice 和 Bob 轮流擦掉恰好一个数字，Alice 先手。

  • 若某次擦除后，黑板上所有剩余数字的按位异或等于 0，执行擦除的玩家立即失败。
  • 单个数字的异或就是它自身；空黑板的异或定义为 0。
  • 如果一名玩家回合开始时，当前黑板异或已经等于 0，这名玩家直接获胜。

双方都采取最优策略，返回 Alice 是否能够获胜。

函数与约束

xorGame(nums: integer[]) -> boolean
  • 1 <= nums.length <= 1000
  • 0 <= nums[i] < 216
别忽略特殊胜利条件

“回合开始时异或为 0”与“自己擦除后异或变为 0”，对应相反结果。

输出：false

完整题解

偶数长度与零异或，决定整局胜负

核心洞察

设当前全部数字的异或为 S，元素个数为 n。答案只依赖这两个量：

Alice 获胜 ⇔ S = 0 或 n 为偶数

情况 A：初始 S = 0

轮到 Alice 时黑板异或已经为 0，按题目规则她立刻获胜，不需要擦除。

情况 B：初始 S ≠ 0

此时胜负与长度奇偶交替：偶数长度是必胜态，奇数长度是必败态。

完整推导过程

  1. 擦掉 x 后的新异或是 S XOR x。
    因为 x XOR x = 0，从总异或中再次异或 x 等价于把它删除。
  2. 当 S ≠ 0 且 n 为偶数时，一定能找到安全的 x ≠ S。
    若所有元素都等于 S，偶数个相同值的总异或应为 0，与当前 S ≠ 0 矛盾。因此至少有一个元素不等于 S；擦掉它后 S XOR x ≠ 0，不会立即输。
  3. 安全擦除让长度奇偶翻转，同时保持异或非零。
    偶数非零局面可以交给对手一个奇数非零局面；奇数非零局面若选择安全步，只能交给对手一个偶数非零局面。
  4. 对剩余元素个数做归纳。
    基础情形 n = 1 且 S ≠ 0：唯一一次擦除得到空黑板，异或为 0，当前玩家失败。归纳地，偶数非零局面可走到奇数非零必败态；奇数非零局面的安全步只会走到偶数非零必胜态，不安全步则立即失败。

正确性证明

定理：对于任意合法输入，算法返回 true 当且仅当 Alice 在最优对局中获胜。

证明：若初始异或为 0，Alice 依据回合开始规则立即获胜，算法返回 true。以下只考虑初始异或非零。对黑板长度归纳：长度为 1 时，当前玩家唯一一次擦除会令异或为 0，故奇数非零局面为必败态。假设更短局面的结论成立。对偶数非零局面，上述反证说明存在一次安全擦除，使对手进入更短的奇数非零必败态，所以当前玩家必胜。对奇数非零局面，任何不安全擦除立即失败；任何安全擦除都会让对手进入更短的偶数非零必胜态，所以当前玩家必败。因此异或非零时，Alice 恰在长度为偶数时获胜。算法的判断与全部情形一致，定理得证。

边界情况

  • 只有一个非零数：擦除后为空，当前玩家失败。
  • 只有一个零：回合开始时异或为 0，Alice 直接获胜。
  • 包含多个零：零不会改变总异或，但仍计入长度奇偶。
  • 大量重复数：无需排序或计数，结论仍只看总异或与长度。
  • 最大值附近：nums[i] < 2^16，四种实现的整数按位异或均可安全表示。

常见错误

  • 把“擦除后异或为 0”误判为当前玩家获胜。
  • 遗漏“回合开始时异或已经为 0”的直接胜利。
  • 只计算异或，忘记数组长度的奇偶性。
  • 尝试寻找具体最优擦除值，导致不必要的博弈搜索。
  • 用和、奇偶数个数等普通算术量替代按位异或。

复杂度

O(n)时间复杂度：遍历数组一次计算总异或。
O(1)空间复杂度：只维护一个异或累积值。

替代方案与取舍

可以把“当前剩余集合 + 轮次”作为状态，用递归极小化极大搜索枚举每次擦除；加入位掩码记忆化后仍需要近似 O(n · 2^n) 的状态转移，远超 n ≤ 1000 的限制。它适合在很小数组上帮助理解规则，却不是可提交方案。利用零异或和长度奇偶的数学结论，才能把问题降到一次遍历。

class Solution {
    public boolean xorGame(int[] nums) {
        int totalXor = 0;
        for (int num : nums) {
            totalXor ^= num;
        }
        return totalXor == 0 || nums.length % 2 == 0;
    }
}
/**
 * @param {number[]} nums
 * @return {boolean}
 */
var xorGame = function(nums) {
    let totalXor = 0;
    for (const num of nums) {
        totalXor ^= num;
    }
    return totalXor === 0 || nums.length % 2 === 0;
};

面试追问

为什么偶数长度一定存在安全元素？

要求候选人独立复述“若所有元素都等于总异或，则偶数次异或为 0”的矛盾证明。

如果允许一次擦掉两个数呢？

长度奇偶不再每回合翻转，当前结论失效，需要重新分析可达状态与不变量。

如果异或变 0 的玩家获胜呢？

这会从 misère 风格改成普通达成目标，胜负状态和基础情形都必须重建。

能否返回 Alice 的一个安全首步？

当异或非零且长度为偶数时，线性扫描找到任意 nums[i] ≠ totalXor 即可。
