Minimum Replacements to Sort the Array

将数组排序的
最少替换次数

每次把一个数拆成两个和相同的数。怎样用最少的操作，让整个序列不再下降？

阅读官方题目 ↗

01 / 题目与输入

给定下标从 0 开始的整数数组 nums。一次操作可以选中一个元素，将它在原位置替换成两个数字，这两个数字之和必须等于原元素。其余元素的相对顺序不变。返回使最终数组满足非递减顺序所需的最少操作次数。

非递减表示相邻元素满足前一个 ≤ 后一个，允许相等。操作是拆分，不是交换或任意重排。例如 nums = [5,6,7]，将 6 拆为 2、4 后得到 [5,2,4,7]。

官方示例 1

输入：nums = [3,9,3]
输出：2

先把 9 拆成 3 和 6，得到 [3,3,6,3]；再把 6 拆成 3 和 3，得到 [3,3,3,3,3]。共操作 2 次。

官方示例 2

输入：nums = [1,2,3,4,5]
输出：0

数组已经非递减，不需要任何操作。

参数与约束

  • nums：整数数组，1 ≤ nums.length ≤ 10⁵。
  • 每个元素满足 1 ≤ nums[i] ≤ 10⁹。
  • 返回整数形式的最少替换次数；Java 使用 long，C++ 使用 long long。
先想一想：一次拆分只增加一个元素。“拆得更碎”和“保留大块”分别会对相邻位置造成什么影响？题解与交互演示位于下方，默认收起。

03 / 题解 · 从右向左，保留尽可能大的下界

核心洞察

一个数最终拆成 k 份，需要恰好 k − 1 次二分操作。已处理后缀的最左元素记为 b，当前值 x 拆出的每一份都不能超过它。最少需要 k = ⌈x / b⌉ 份；在这 k 份中尽量均分，才能让最小的一份尽可能大，为左侧保留空间。

k = ceil(x / b)
answer += k − 1
b = floor(x / k)

设 q = x // k、r = x % k，均分结果按序为 k − r 个 q，后接 r 个 q + 1。它们的和是 x，最大值不超过旧边界 b，新边界是 q。

完整过程

  1. 最后一个数保持不变，令 b = nums[n − 1]、答案为 0。
  2. 从倒数第二个数向左遍历，计算满足上限 b 的最少份数 k。
  3. 累加 k − 1，并用当前拆分的最小值 floor(x / k) 更新 b。
  4. 处理完第一个数后返回累加结果。实际提交只计数，不创建拆分后的长数组。

以 [12,7,3] 为例：从 b = 3 开始，7 拆为 [2,2,3]，增加 2 次，b = 2；12 拆为六个 2，增加 5 次。总计 7 次。

04 / 为什么一定最优

  1. 末尾不拆更好。末元素拆开会增加操作，其最小值不会大于原值，只会限制左边的元素。保持末元素提供最宽松的初始边界。
  2. 份数有硬下界。若每份最多为 b，k 份总和最多是 kb。要装下 x，必须满足 k ≥ ceil(x / b)。
  3. 均分达到下界。取最少份数并均分，最大份额为 ceil(x / k) ≤ b。按小到大排列后，块内以及它与后缀之间都非递减。
  4. 新边界也最优。固定 k 份，最小份额不可能超过 floor(x / k)，均分恰好达到它。多拆成更多份，这个上限只会不变或下降，同时操作变多。
  5. 归纳与交换。对固定的右侧合法后缀，本步选择同时最小化当前操作、最大化传给前缀的边界。更大的边界不会增加前缀所需的最少操作，因此任何方案都能把当前块替换成贪心构造而不增加总成本。从保持末元素开始，逐个向左交换，最终得到全局最优方案。

边界与数值安全

  • 单元素或已经有序：每处 k = 1，答案为 0。即使不拆，也必须将 b 更新为当前值 x。
  • 不能整除：x = 10、b = 3 时拆 4 份，可取 [2,2,3,3]；新边界为 2。
  • b = 1 时，左侧 x 拆成 x 个 1，增加 x − 1 次。b 始终为正，除法安全。
  • 答案不超过 Σ(nums[i] − 1) < 10¹⁴。Java / C++ 用 64 位整数；JavaScript 的 Number 可精确表示此范围内的整数；Python 使用任意精度整数。

复杂度

时间 O(n)，额外空间 O(1)。扫描一次，不修改输入。演示为回放保存快照，其开销与提交算法不同。

替代方案

直接模拟每一次拆分在逻辑上可行，但替换次数可能接近 10¹⁴，逐操作展开不可行。枚举份数或用动态规划记录边界会引入庞大的状态空间，份数下界和均分结构已经给出确定选择。对 k 二分虽可行，却把一次除法变为多次判断，没有收益。

常见错误

  • 从左向右决定拆分：真正的上限来自右侧，容易提前做出错误选择。
  • 用 floor(x / b) 计算份数：有余数时份数不足。
  • 把新边界设为旧 b、最大块或余数：应使用均分后的最小块。
  • 累加 k 而不是 k − 1；一次二分只让块数加一。
  • 使用 32 位答案类型，或真的展开全部拆分元素。

面试追问

  • 如何输出一种拆分方案？为每个原元素记录 q、r、k，用两个“值与次数”段表示并按原顺序拼接。完整展开需要与结果长度成正比的时间。
  • 为何不拆成若干个 b 加一个余数？小余数可能过度压低左边界，例如 [1,3,3,3] 不如 [2,2,3,3]。
  • 如果要求严格递增？允许相等的均分构造失效，需要重新考虑块内差异和可行性，不能套用当前证明。

Java

class Solution {
    public long minimumReplacement(int[] nums) {
        long answer = 0;
        long bound = nums[nums.length - 1];
        for (int i = nums.length - 2; i >= 0; i--) {
            long x = nums[i];
            long parts = (x + bound - 1) / bound;
            answer += parts - 1;
            bound = x / parts;
        }
        return answer;
    }
}

    for (let i = nums.length - 2; i >= 0; i--) {

    return answer;
