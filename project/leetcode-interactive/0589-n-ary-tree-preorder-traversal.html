04 / Solution

迭代前序：用栈守住孩子的顺序

核心洞察

前序要求“先记录当前节点，再从左到右处理每个孩子”。栈是后进先出，所以要把孩子按从右到左压栈，才能让最左孩子最先弹出。

完整过程

  1. 若 root 为空，直接返回空数组。
  2. 把根节点放入栈中。
  3. 循环弹出栈顶，将其值加入答案。
  4. 从右向左遍历该节点的孩子，依次压栈。
  5. 栈为空时，答案就是完整前序序列。

正确性说明

循环不变式：每次循环开始时，栈顶始终是所有已经发现但尚未访问的节点中，按照前序规则最应该被访问的那个节点。

弹出节点后先记录它，满足“根先于子树”。将孩子从右到左压栈后，最左孩子位于栈顶，因此各子树仍按从左到右的顺序展开。初始时根节点满足不变式；每轮操作保持它；栈为空时所有且仅有树中节点被记录一次，所以结果正确。

复杂度与边界

  • 时间：O(n)，每个节点入栈、出栈各一次。
  • 空间：O(n) 最坏情况，栈可能同时容纳大量待访问节点；不计输出数组。
  • 空树：不要把 null 放入栈，直接返回空结果。
  • 高树：高度可达 1000，迭代法避免依赖语言的递归深度限制。
  • 空孩子列表：叶子节点无需特殊分支，逆序循环自然跳过。

替代方案

递归 DFS：访问节点后，按原顺序递归每个孩子。代码更短，时间仍为 O(n)，额外空间为递归深度 O(h)；但极深树可能触发调用栈限制。

修改输入列表：某些写法把孩子插入队首，会产生额外移动成本，也可能意外修改节点数据，不推荐。

面试追问

  • 如果只能使用递归，怎样说明空间复杂度与树高的关系？
  • 如何把前序改成后序？可以借助“根—右—左”再反转结果。
  • 如果节点孩子是惰性迭代器，怎样在不一次性展开全部孩子的前提下维持顺序？
  • 输出非常大时，能否设计生成器逐个产出节点值？

常见错误

按从左到右压栈

由于后进先出，实际会先访问最右孩子，兄弟顺序被反转。

忘记空根节点

直接读取 root.val 会在空树输入上报错。

压入孩子值而非节点

后续无法继续访问孩子的孩子；栈里必须保存节点对象。

误解序列化中的 null

null 是题目展示树结构的分组符，不是树中需要访问的节点。

        if root is None:
            return []

        answer = []

            node = stack.pop()
            answer.append(node.val)
            stack.extend(reversed(node.children))

class Solution {
public:
    vector<int> preorder(Node* root) {
        if (root == nullptr) return {};

        vector<int> answer;
        stack<Node*> pending;
        pending.push(root);

        while (!pending.empty()) {
            Node* node = pending.top();
            pending.pop();
            answer.push_back(node->val);

            for (auto it = node->children.rbegin();
                 it != node->children.rend(); ++it) {
                pending.push(*it);
            }
        }
        return answer;
    }
};
