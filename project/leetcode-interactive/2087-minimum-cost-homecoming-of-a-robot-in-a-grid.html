MEDIUM · 中等 网格与代价

网格图中机器人
回家的最小代价

Minimum Cost Homecoming of a Robot in a Grid

每一次移动，都有一笔账。先读懂收费方式，再为机器人规划回家路线。

01 / MISSION

题目与收费规则

给定一个 m × n 的网格，左上角为 (0, 0)。机器人从 startPos = [startRow, startCol] 出发，要到达 homePos = [homeRow, homeCol]。每步只能向上、下、左、右移动一个格子，且不能越界。返回回家所需的最小总代价。

↕ 纵向移动

进入第 r 行时，支付 rowCosts[r]。

↔ 横向移动

进入第 c 列时，支付 colCosts[c]。

只按移动方向收取目标行或目标列的费用；一次移动不会同时收两种费用。初始站在起点不收费。

官方示例 1

startPos = [1, 0]
homePos = [2, 3]
rowCosts = [5, 4, 3]
colCosts = [8, 2, 6, 7]
输出：18

示例路线：(1,0) → (2,0) → (2,1) → (2,2) → (2,3)，费用依次为 3、2、6、7，总计 18。

官方示例 2

startPos = [0, 0]
homePos = [0, 0]
rowCosts = [5]
colCosts = [26]
输出：0

机器人已经在家，无需移动，也就没有费用。

完整约束

  • m == rowCosts.length，n == colCosts.length
  • 1 ≤ m, n ≤ 10⁵
  • 0 ≤ rowCosts[r], colCosts[c] ≤ 10⁴
  • startPos.length == homePos.length == 2
  • 0 ≤ startRow, homeRow < m
  • 0 ≤ startCol, homeCol < n

    04 / SOLUTION

    准备好之后，再看题解

    先想一想：什么费用是回家的途中无法避开的？

    核心洞察：只支付必经的行与列

    纵向移动的费用与当前列无关，横向移动的费用与当前行无关。要到达目标，必然要进入两个行坐标之间的每个目标方向上的行，也必然要进入两个列坐标之间的每个目标方向上的列。每笔费用非负，所以额外绕路不能让费用更低。

    起点行不因“出发”而收费，终点行在纵向进入时收费；列同理。方向决定区间端点，不要简单地对闭区间求和。

    完整过程

    1. 用局部变量 r、c 保存起点坐标，令累计值 ans = 0。
    2. 当 r 不等于目标行时，向目标行移动一步；更新 r 后加上 rowCosts[r]。
    3. 当 c 不等于目标列时，向目标列移动一步；更新 c 后加上 colCosts[c]。
    4. 返回 ans。先横向或先纵向都可；交错移动也可以，只要不反向绕路。

    示例 1：行坐标从 1 到 2，只收 rowCosts[2] = 3；列坐标从 0 到 3，收 colCosts[1] + colCosts[2] + colCosts[3] = 15，因此答案是 18。反向场景从 (2,3) 到 (0,1)，行费用为 4 + 5，列费用为 6 + 2，总计 17。

    正确性证明

    下界：若起点行小于终点行，任何合法路径都必须至少进入一次 startRow + 1 到 homeRow 中的每行；向上时同理，必须进入 homeRow 到 startRow − 1 的每行。列方向也存在相同的必经集合。纵向和横向是不同的移动事件，它们的必需费用可以相加。其他移动的代价非负，因此任何路径的总代价都不少于这个和。

    达到下界：算法始终沿坐标朝目标移动，每个必经行、列恰好进入一次，不产生额外移动，而且所有中间坐标都在网格内。它恰好支付上述下界，因此返回值就是最小总代价。

    边界与数值范围

    • 已经在家：两个循环均不执行，返回 0。
    • 同一行或同一列：仅另一个方向产生费用；单行、单列网格也自然覆盖。
    • 向上或向左：步长为 −1，依然先移动再计费，不会误收起点费用。
    • 零费用绕路可能与最优路线并列，但不会更优；无需假设最优路线唯一。
    • 答案最大为 (99999 + 99999) × 10000 = 1,999,980,000，Java/C++ 的 32 位有符号整数可以容纳，JavaScript Number 也可精确表示。
    • 代码只更新局部坐标，不修改输入数组。

    复杂度

    令 D = |startRow − homeRow| + |startCol − homeCol|。时间 O(D + 1)，通常写为 O(D)，最坏 O(m + n)；额外空间 O(1)。这不包括调用者提供的输入数组。交互页面为了回放保存了步骤，不属于下方算法的空间开销。

    替代方案

    可直接按方向遍历对应区间求和，本质与移动模拟相同。若同一组费用要回答大量起终点查询，可以先构建行列前缀和：P[k] 为下标小于 k 的费用之和。当 a < b，区间费用是 P[b+1] − P[a+1]；当 a > b，是 P[a] − P[b]；相等时为 0。预处理 O(m+n) 时间和空间，每次查询 O(1)。单次查询无需此额外存储。

    Dijkstra 可建模非负边权最短路，但显式网格有 m×n 个顶点，最大达到 10¹⁰，远超本题需要。普通 BFS 只保证步数最少，不能普遍解决带不同边权的最小代价问题。

    常见错误

    • 先加费用再更新坐标，导致收取出发行、列费用并漏掉目的行、列。
    • 每步同时加 rowCosts 和 colCosts，误解了按移动方向收费的规则。
    • 为了避开昂贵的行而绕到别的列：该行的纵向进入费用与列无关，绕行无法避开。
    • 把所有 rowCosts、colCosts 相加，算入根本不需要经过的区域。
    • 将零费用误写成正费用，从而断言“任何绕路都严格更贵”。

    面试追问

    为何无需比较先横向还是先纵向？两种顺序支付相同的必经费用，多笔加法的顺序不影响总和。加入障碍物呢？单调路线可能不可达，达到下界的构造失效，需要根据网格规模重新设计寻路。允许负费用呢？额外移动可能降低总价，甚至存在可重复的负环，本证明不再成立。费用被频繁修改且有很多查询呢？可用两棵树状数组分别维护行、列区间和。

    Java · 官方可提交实现

    class Solution {
    public int minCost(int[] startPos, int[] homePos,
                       int[] rowCosts, int[] colCosts) {
        int r = startPos[0], c = startPos[1], ans = 0;
        while (r != homePos[0]) {
            r += r < homePos[0] ? 1 : -1;
            ans += rowCosts[r];
        }
        while (c != homePos[1]) {
            c += c < homePos[1] ? 1 : -1;
            ans += colCosts[c];
        }
        return ans;
    }
}

class Solution:
    def minCost(self, startPos: List[int], homePos: List[int],
                rowCosts: List[int], colCosts: List[int]) -> int:

        ans = 0
