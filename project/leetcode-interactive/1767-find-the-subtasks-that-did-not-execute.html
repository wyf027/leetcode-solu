寻找没有被执行的任务对

先把每个任务应有的子任务完整展开，再从中减去已经执行过的记录。难点不是连接，而是从“数量”恢复出原本并不存在的行。

HARD数据库Paid Only递归 CTE

Problem brief

题意：找出“应该存在、却没有发生”的行

Tasks 记录任务编号以及该任务包含的子任务数量。若某任务的 subtasks_count = k，它应当拥有编号从 1 到 k 的全部子任务。

Executed 只记录已经成功执行的 (task_id, subtask_id)。请返回所有未执行的任务—子任务编号对；结果顺序不作要求。

输入 / 输出关系

输入是两张表，输出列严格为 task_id, subtask_id。候选全集不是现成表，必须先由 subtasks_count 生成。

表结构与约束

  • Tasks(task_id INT, subtasks_count INT)，task_id 唯一。
  • Executed(task_id INT, subtask_id INT)，二者组合唯一。
  • Executed.task_id 对应 Tasks.task_id。
  • 子任务编号从 1 开始，且不超过所属任务的 subtasks_count。
  • 每条 Executed 记录表示相应子任务已成功执行。

Complete solution

从隐式区间到缺失集合

核心洞察

缺失记录无法直接从 Executed 中查询；先生成每个任务的合法子任务区间，问题才变成一次标准的集合差。

Missing = {(task_id, 1..subtasks_count)} − Executed

完整过程

1
锚点。为每个任务生成 subtask_id = 1，同时保留上界 subtasks_count。
2
递归。只要当前编号小于上界，就生成同一任务的下一个编号。最终得到每个任务的完整候选集。
3
反连接。候选集左连接 Executed；连接失败的候选对正是未执行对子。
4
投影。仅输出题目要求的 task_id 与 subtask_id；排序只用于阅读，题目不要求固定顺序。

正确性证明

完备性：对任一任务，锚点生成编号 1，递归每次加 1，直到上界。因此从 1 到 subtasks_count 的每个合法编号恰好生成一次。任何未执行的合法对子都在候选集中，且无法匹配 Executed，所以一定被输出。

可靠性：输出行来自候选集，故任务和子任务编号合法；它又满足左连接右侧为空，说明 Executed 中不存在同一对子。因此每个输出对子确实未执行。

结合完备性与可靠性，查询返回且只返回所有未执行的任务对子。

复杂度与边界

候选规模 SS = Σ subtasks_count
时间 O(S + E)取决于连接计划与索引
空间 O(S)递归中间结果量级
  • 某任务完全未执行：其全部子任务都应输出。
  • 某任务全部执行：该任务不贡献输出行。
  • 只有一个子任务：锚点本身就是完整候选区间。
  • 结果为空：这是合法答案，不要用内连接制造或丢失额外行。

替代方案

数字表 / 序列表：若生产数据库已有永久 numbers 表，连接条件 n ≤ subtasks_count 往往比递归 CTE 更易优化、也避免递归深度限制。

窗口技巧：窗口函数适合从已有连续行里找间隙，却不能自然补出任务尾部从“最后执行编号 + 1”到上界的全部缺口，仍需数字来源。

NOT EXISTS：生成候选集后，可用相关子查询替代左连接判空；语义更直接，优化器通常能转成 anti join。

完整代码

MySQL 8 · 官方可提交语言递归 CTE + anti join
WITH RECURSIVE all_subtasks AS (
  SELECT task_id,
         subtasks_count,
         1 AS subtask_id
  FROM Tasks

  UNION ALL

  SELECT task_id,
         subtasks_count,
         subtask_id + 1
  FROM all_subtasks
  WHERE subtask_id < subtasks_count
)
SELECT a.task_id, a.subtask_id
FROM all_subtasks AS a
LEFT JOIN Executed AS e
  ON e.task_id = a.task_id
 AND e.subtask_id = a.subtask_id
WHERE e.task_id IS NULL
ORDER BY a.task_id, a.subtask_id;

function findSubtasks(tasks, executed) {
  const done = new Set(
    executed.map(([taskId, subtaskId]) => `${taskId}:${subtaskId}`)
  );
  const missing = [];

  for (const [taskId, count] of tasks) {
    for (let subtaskId = 1; subtaskId <= count; subtaskId += 1) {
      if (!done.has(`${taskId}:${subtaskId}`)) {
        missing.push([taskId, subtaskId]);
      }
    }
  }
  return missing;
}

import java.util.*;

class Solution {
  public List<int[]> findSubtasks(int[][] tasks, int[][] executed) {
    Set<String> done = new HashSet<>();
    for (int[] pair : executed) {
      done.add(pair[0] + ":" + pair[1]);
    }

    List<int[]> missing = new ArrayList<>();
    for (int[] task : tasks) {
      for (int subtaskId = 1; subtaskId <= task[1]; subtaskId++) {
        String key = task[0] + ":" + subtaskId;
        if (!done.contains(key)) {
          missing.add(new int[]{task[0], subtaskId});
        }
      }
    }
    return missing;
  }
}

from typing import List, Tuple

def find_subtasks(
    tasks: List[Tuple[int, int]],
    executed: List[Tuple[int, int]],
) -> List[Tuple[int, int]]:
    done = set(executed)
    missing: List[Tuple[int, int]] = []

    for task_id, count in tasks:
        for subtask_id in range(1, count + 1):
            pair = (task_id, subtask_id)
            if pair not in done:
                missing.append(pair)

    return missing

#include <set>
#include <utility>
#include <vector>
using namespace std;

class Solution {
public:
  vector<pair<int, int>> findSubtasks(
      const vector<pair<int, int>>& tasks,
      const vector<pair<int, int>>& executed) {
    set<pair<int, int>> done(executed.begin(), executed.end());
    vector<pair<int, int>> missing;

    for (const auto& [taskId, count] : tasks) {
      for (int subtaskId = 1; subtaskId <= count; ++subtaskId) {
        pair<int, int> candidate{taskId, subtaskId};
        if (!done.count(candidate)) missing.push_back(candidate);
      }
    }
    return missing;
  }
};

面试追问

  • 递归深度很大怎么办？使用永久数字表，或按数据库能力提高递归上限；生产上优先数字表。
  • 为什么连接两个字段？子任务编号只在所属任务内部有意义，完整业务键是二元组。
  • 能否用 NOT IN？拼接二元键既脆弱又可能受 NULL 语义影响，优先 NOT EXISTS 或 anti join。
  • 需要哪些索引？Tasks(task_id) 与 Executed(task_id, subtask_id) 的唯一或复合索引最关键。

常见错误

  • 从 Executed 出发，只能看到发生过的行，无法恢复完全未执行的任务。
  • 递归条件写成 <= subtasks_count 后再加一，造成越界编号。
  • 连接时遗漏 task_id，把另一个任务的同编号子任务误当成已执行。
  • 使用内连接后再找 NULL；内连接早已删除未匹配行。
  • 把四种通用语言参考误认为数据库题的在线可提交答案。
