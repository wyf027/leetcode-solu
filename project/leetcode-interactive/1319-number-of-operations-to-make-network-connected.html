连通网络的操作次数

Number of Operations to Make Network Connected

先观察线缆如何把计算机聚成若干网络。别急着看答案：在可视化里逐条处理连接，试着判断什么时候线缆是“多余”的。

题目描述

有 n 台编号为 0 到 n - 1 的计算机。connections[i] = [aᵢ, bᵢ] 表示一条连接两台计算机的以太网线缆；计算机可通过直接或间接路径互相访问。

一次操作可以拔下一条现有的直连线缆，再把它接到任意一对当前未直连的计算机之间。返回让全部计算机连通所需的最少操作次数；若无法做到，返回 -1。

函数形式： makeConnected(n, connections) → integer

先问自己三个问题

① 连接 n 台计算机至少需要几条线？

② 哪些边可以拔掉而不破坏原分组？

③ 若当前有 k 个连通分量，至少要连接几次？

官方示例

示例 1
输入：n = 4, connections = [[0,1],[0,2],[1,2]]
输出：1
解释：拔下 1—2 的线缆，改接到 1—3。
示例 2
输入：n = 6, connections = [[0,1],[0,2],[0,3],[1,2],[1,3]]
输出：2
示例 3
输入：n = 6, connections = [[0,1],[0,2],[0,3],[1,2]]
输出：-1
解释：线缆总数不足。
示例 4
输入：n = 5, connections = [[0,1],[0,2],[3,4],[2,3]]
输出：0

约束

  • 1 ≤ n ≤ 10⁵
  • 1 ≤ connections.length ≤ min(n × (n - 1) / 2, 10⁵)
  • connections[i].length == 2
  • 0 ≤ aᵢ, bᵢ < n，且 aᵢ != bᵢ
  • 没有重复连接，同一对计算机间至多一条线缆。

    准备好核对思路了吗？

    完整题解与四种语言实现默认收起，不会在首屏泄露。

    题解：线缆总量判定 + 并查集计数

    核心洞察

    答案只取决于两件事：总线缆是否至少为 n - 1，以及当前有多少个连通分量。若线缆够用，设分量数为 k，最少操作数就是 k - 1。

    任何包含 s 个点的连通分量只需 s - 1 条边维持连通；更多的边就是环上的冗余线，可以拔下用于连接其他分量。全网若有至少 n - 1 条线，所有分量内部的冗余线总数一定足以完成合并。

    完整过程

    先判不可能。 若 connections.length < n - 1，即使重新排列全部线缆也无法连通 n 个点，直接返回 -1。
    初始化并查集。 每台计算机的父节点是自己，连通分量数初始为 n。
    合并每条连接。 若两个端点根不同，就合并集合并将分量数减一；若根相同，这条边是冗余线。
    连接所有分量。 每次操作最多让两个分量合成一个，因此从 k 个分量变成一个恰需 k - 1 次。

    正确性证明

    引理 1：连接 n 个顶点至少需要 n - 1 条边。因此线缆少于 n - 1 时返回 -1 正确。

    引理 2：并查集在且仅在一条边连接两个不同分量时令分量数减一，所以全部边处理完后的计数恰为原图连通分量数 k。

    下界：一次重连至多把两个分量合并，故至少需要 k - 1 次。

    可达性：当总边数不少于 n - 1 时，各分量生成树之外的冗余边总数不少于 k - 1；逐条用它们连接不同分量即可在 k - 1 次内完成。

    结论：算法在不可行时返回 -1，可行时返回下界且能达到的 k - 1，因此答案正确。

    边界情况

    • 网络已经连通：分量数为 1，返回 0。
    • 恰好 n - 1 条线：若不连通则必有环，也必意味着另处缺线；重新连接仍可完成。
    • 大量成环边：并查集忽略同一集合内的合并，答案不受重复“合并”影响。
    • n = 1（通用语义边界）：无需线缆，返回 0；虽然当前官方连接数约束从 1 起，代码仍自然支持。

    复杂度

    设连接数为 m。并查集采用路径压缩与按大小合并，时间复杂度为 O(m α(n))，近似线性；空间复杂度为 O(n)。

    替代方案

    也可以构建邻接表后用 DFS 或 BFS 统计连通分量：时间复杂度 O(n + m)，空间复杂度 O(n + m)。并查集不需要保存完整邻接表，更贴合“逐条合并连接”的机制。

    四语言完整实现

    Java
    class Solution {
    private int[] parent;
    private int[] size;

    public int makeConnected(int n, int[][] connections) {
        if (connections.length < n - 1) return -1;

        parent = new int[n];
        size = new int[n];
        for (int i = 0; i < n; i++) {
            parent[i] = i;
            size[i] = 1;
        }

        int components = n;
        for (int[] edge : connections) {
            int rootA = find(edge[0]);
            int rootB = find(edge[1]);
            if (rootA != rootB) {
                if (size[rootA] < size[rootB]) {
                    int temp = rootA;
                    rootA = rootB;
                    rootB = temp;
                }
                parent[rootB] = rootA;
                size[rootA] += size[rootB];
                components--;
            }
        }
        return components - 1;
    }

    private int find(int x) {
        if (parent[x] != x) parent[x] = find(parent[x]);
        return parent[x];
    }
}
    JavaScript
    /**
 * @param {number} n
 * @param {number[][]} connections
 * @return {number}
 */
var makeConnected = function(n, connections) {
    if (connections.length < n - 1) return -1;

    const parent = Array.from({ length: n }, (_, i) => i);
    const size = Array(n).fill(1);

    const find = (x) => {
        while (parent[x] !== x) {
            parent[x] = parent[parent[x]];
            x = parent[x];
        }
        return x;
    };

    let components = n;
    for (const [a, b] of connections) {
        let rootA = find(a);
        let rootB = find(b);
        if (rootA === rootB) continue;
        if (size[rootA] < size[rootB]) [rootA, rootB] = [rootB, rootA];
        parent[rootB] = rootA;
        size[rootA] += size[rootB];
        components--;
    }
    return components - 1;
};

    from typing import List


class Solution:
    def makeConnected(self, n: int, connections: List[List[int]]) -> int:
        if len(connections) < n - 1:
            return -1

        parent = list(range(n))
        size = [1] * n

        def find(x: int) -> int:
            while parent[x] != x:
                parent[x] = parent[parent[x]]
                x = parent[x]
            return x

        components = n
        for a, b in connections:
            root_a, root_b = find(a), find(b)
            if root_a == root_b:
                continue
            if size[root_a] < size[root_b]:
                root_a, root_b = root_b, root_a
            parent[root_b] = root_a
            size[root_a] += size[root_b]
            components -= 1

        return components - 1
    C++
    class Solution {
    vector<int> parent;
    vector<int> size;

    int find(int x) {
        if (parent[x] != x) parent[x] = find(parent[x]);
        return parent[x];
    }

public:
    int makeConnected(int n, vector<vector<int>>& connections) {
        if (connections.size() < static_cast<size_t>(n - 1)) return -1;

        parent.resize(n);
        iota(parent.begin(), parent.end(), 0);
        size.assign(n, 1);
        int components = n;

        for (const auto& edge : connections) {
            int rootA = find(edge[0]);
            int rootB = find(edge[1]);
            if (rootA == rootB) continue;
            if (size[rootA] < size[rootB]) swap(rootA, rootB);
            parent[rootB] = rootA;
            size[rootA] += size[rootB];
            --components;
        }
        return components - 1;
    }
};

    面试追问

    • 为什么不用显式统计冗余边？ 总边数先保证不少于 n - 1，此时计出分量数就足以证明冗余线一定够。
    • 若连接动态加入呢？ 并查集可以在线合并并实时维护分量数；但删除边需要离线动态连通性或更复杂的数据结构。
    • 若每条重连代价不同呢？ 仅计分量已不够，问题会转向带权图上的最小生成树或更具体的代价模型。

    常见错误

    • 忘记先判断线缆总数，导致在根本不可能时仍返回 components - 1。

    • 每处理一条边都减少分量数，而没有检查两个端点是否已经同根。

    • 把答案误写成冗余线数量；冗余线只决定可行性，最少次数由分量数决定。

    • 递归 DFS 在 10⁵ 个点的链状图上可能触发语言栈深限制。
