Trail brief

题意与样例

给定非负整数数组 nums，你从下标 0 出发；nums[i] 表示在位置 i 最多能向右跳多少步。判断能否到达最后一个下标。

Official example 1

输入

nums = [2, 3, 1, 1, 4]

输出

true

可从 0 跳到 1，再由 1 覆盖到最后一个下标。

Official example 2

输入

nums = [3, 2, 1, 0, 4]

输出

false

最远只能到下标 3，而 nums[3] = 0，无法点亮终点。

约束：1 ≤ nums.length ≤ 10⁴，0 ≤ nums[i] ≤ 10⁵。

    Core insight

    维护覆盖范围，不模拟路线

    只要 i ≤ farthest，下标 i 就能由之前某个可达位置抵达；于是它也有资格用 i + nums[i] 扩张覆盖范围。若 i 越过 farthest，则此前所有选择都无法到达 i。

    Invariant

    循环不变量

    扫描下标 i 之前，区间 [0, farthest] 中的每个位置都处于“可由某条路径到达”的覆盖集合内。处理可达的 i 后，取最大值只会扩大或保持这个集合，绝不会错误缩小。

    Complete process

    完整过程

    1. CHECK

      若 i > farthest，当前营地不在覆盖范围内，直接返回 false。

    2. EXPAND

      更新 farthest = max(farthest, i + nums[i])。

    3. FINISH

      一旦 farthest ≥ n - 1，终点已覆盖，可提前返回 true。

    Boundary cases

    边界

    • 长度为 1：起点就是终点，直接 true。
    • 开头为 0 且长度大于 1：无法离开起点。
    • 中间的 0 不一定失败，只要此前边界越过它。

    Complexity

    复杂度

    Time

    O(n)

    Extra space

    O(1)

    Alternatives

    替代方案

    • 反向贪心：把终点视为 goal，能覆盖 goal 的位置成为新 goal，同样 O(n)/O(1)。
    • 动态规划：记录每个下标可达性，状态更多且通常为 O(n²)。
    • 回溯：枚举跳法会指数爆炸，不适合 10⁴ 规模。

    Common mistakes

    常见错误

    • 把 farthest 更新为 nums[i]，忘记加当前位置 i。
    • 先用不可达位置扩张边界，再检查 i > farthest。
    • 每一步都选择最大 nums 值，误把“局部跳跃选择”当成覆盖贪心。
    • 要求 farthest 恰好等于末尾，而不是大于等于。

    Interview follow-ups

    面试追问

    为什么不需要记录路径？
    问题只询问存在性，覆盖区间足以概括所有已知路径的可达能力。
    如何输出最少跳跃次数？
    改为分层维护当前层终点与下一层最远点，即 Jump Game II。
    反向贪心如何证明？
    若 i 能覆盖当前 goal，则到达 i 就等价于能到达旧 goal，可安全把 goal 前移。

    class Solution {
    public boolean canJump(int[] nums) {
        int farthest = 0;
        for (int i = 0; i < nums.length; i++) {
            if (i > farthest) {
                return false;
            }
            farthest = Math.max(farthest, i + nums[i]);
            if (farthest >= nums.length - 1) {
                return true;
            }
        }
        return true;
    }
}

                return False
            farthest = max(farthest, i + jump)

        return True
