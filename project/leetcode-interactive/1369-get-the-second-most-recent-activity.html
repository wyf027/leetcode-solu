获取最近第二次的活动

从每位用户的活动时间线中取出倒数第二条；如果他只有一条记录，就保留那条唯一记录。先在可视化里观察“按用户分组、按开始日期倒序编号”的过程，再决定是否展开题解。

窗口函数分组排序边界合并
01 · Problem

题意与数据表

任务转述

表 UserActivity 记录用户参加的活动及其起止日期。对每个用户：

  • 若有两条或更多活动，返回按 startDate 从新到旧排列后的第 2 条；
  • 若只有一条活动，返回这条活动本身。

结果包含原表的四个字段；题目不要求固定的最终行顺序。

关键语义：“最近”由开始日期决定，而不是活动结束日期；每个用户独立排名。

约束与判定口径

  • 输入表字段与类型以上述 schema 为准；每位出现的用户至少有一条活动记录。
  • 活动记录按 startDate 判断新旧，输出仍需保留 endDate。
  • 每位用户独立选择；只有一条记录是必须单独覆盖的边界情形。
  • 官方元数据未给出行数范围与同一用户开始日期相同的额外保证，因此生产实现应显式考虑并列日期的业务口径。

05 · Spoiler zone

独立题解

先自己写出“分区、排序、编号、筛选”再展开。

Core insight

把特殊边界压缩成一个筛选条件：rank = 2 或 count = 1

先按 username 分区，再按 startDate DESC 给每行编号。同时计算该用户的记录总数。于是“第二近”对应编号 2，“唯一活动”对应总数 1。

完整过程

  1. 窗口分区锁定当前用户。
  2. 开始日期倒序排列。
  3. ROW_NUMBER() 生成 1、2、3…。
  4. COUNT(*) OVER 得到分区大小。
  5. 保留 rn = 2 OR cnt = 1。

正确性

对任意用户，倒序后的第 1 行必为最近活动，第 2 行必为第二近活动。因此记录数至少为 2 时筛选 rn=2 正确。记录数为 1 时不存在第 2 行，而 cnt=1 恰好保留唯一行。两种情形覆盖所有用户且互不遗漏。

边界与复杂度

  • 单条活动：由 cnt=1 覆盖。
  • 恰好两条：较旧的一条编号为 2。
  • 不同用户：窗口分区互不干扰。
  • 同日并列：若题目无唯一性保证，应追加稳定排序键。
  • 排序主导时间约 O(n log n)；窗口结果占 O(n) 中间空间。

官方可提交语言 · MySQL

WITH ranked AS (
    SELECT
        username,
        activity,
        startDate,
        endDate,
        ROW_NUMBER() OVER (
            PARTITION BY username
            ORDER BY startDate DESC
        ) AS rn,
        COUNT(*) OVER (
            PARTITION BY username
        ) AS cnt
    FROM UserActivity
)
SELECT username, activity, startDate, endDate
FROM ranked
WHERE rn = 2 OR cnt = 1;

四语言本地语义参考

本题是数据库题，LeetCode 提交应使用 SQL。以下 Java、JavaScript、Python、C++ 仅演示同一语义在内存数据上的实现，不是该题官方提交语言。

import java.time.LocalDate;
import java.util.*;
import java.util.stream.Collectors;

class Solution {
    record Activity(String username, String activity,
                    LocalDate startDate, LocalDate endDate) {}

    public List<Activity> secondMostRecent(List<Activity> rows) {
        Map<String, List<Activity>> groups = rows.stream()
            .collect(Collectors.groupingBy(Activity::username));
        List<Activity> answer = new ArrayList<>();
        for (List<Activity> group : groups.values()) {
            group.sort(Comparator.comparing(Activity::startDate).reversed());
            answer.add(group.get(group.size() == 1 ? 0 : 1));
        }
        return answer;
    }
}
function secondMostRecent(rows) {
  const groups = new Map();
  for (const row of rows) {
    if (!groups.has(row.username)) groups.set(row.username, []);
    groups.get(row.username).push(row);
  }

  const answer = [];
  for (const group of groups.values()) {
    group.sort((a, b) => b.startDate.localeCompare(a.startDate));
    answer.push(group[group.length === 1 ? 0 : 1]);
  }
  return answer;
}
from collections import defaultdict
from dataclasses import dataclass
from datetime import date

@dataclass(frozen=True)
class Activity:
    username: str
    activity: str
    startDate: date
    endDate: date

def second_most_recent(rows: list[Activity]) -> list[Activity]:
    groups: dict[str, list[Activity]] = defaultdict(list)
    for row in rows:
        groups[row.username].append(row)

    answer = []
    for group in groups.values():
        group.sort(key=lambda row: row.startDate, reverse=True)
        answer.append(group[0] if len(group) == 1 else group[1])
    return answer
#include <algorithm>
#include <string>
#include <unordered_map>
#include <vector>
using namespace std;

struct Activity {
    string username;
    string activity;
    string startDate; // YYYY-MM-DD, lexicographic order is chronological.
    string endDate;
};

vector<Activity> secondMostRecent(const vector<Activity>& rows) {
    unordered_map<string, vector<Activity>> groups;
    for (const Activity& row : rows) groups[row.username].push_back(row);

    vector<Activity> answer;
    for (auto& [username, group] : groups) {
        sort(group.begin(), group.end(), [](const Activity& a,
                                             const Activity& b) {
            return a.startDate > b.startDate;
        });
        answer.push_back(group[group.size() == 1 ? 0 : 1]);
    }
    return answer;
}

替代方案

可以先求每个用户的最大开始日期，再在排除最大日期后求最大剩余日期，并与原表连接；同时用 COALESCE 处理单条记录。它能避开窗口函数，但查询更长、重复扫描更多，而且遇到并列日期时更难定义行为。

面试追问

  • 如果要求第 k 近，如何参数化筛选？
  • 并列开始日期要返回一条还是全部？
  • ROW_NUMBER、RANK、DENSE_RANK 的语义差异是什么？
  • 什么复合索引有利于按用户和日期读取？

常见错误

  • 全表排序后取第二行，忘记按用户分区。
  • 用 endDate 判断最近，偏离题意。
  • 只写 rn = 2，导致只有一条活动的用户消失。
  • 用 LIMIT 1 OFFSET 1，它无法一次为所有用户独立取值。
  • 无唯一性保证时只按日期排序，却假设同日记录一定有稳定先后。
