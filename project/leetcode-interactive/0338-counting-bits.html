01 / PROBLEM

题目

给定一个整数 n。对区间 0 ≤ i ≤ n 中的每个整数 i，计算其二进制表示中 1 的数量，返回长度为 n + 1 的数组 ans，其中 ans[i] 就是整数 i 的二进制置位数。

不要调用语言内置的位计数函数（例如 C++ 的 __builtin_popcount）。

示例 1

输入：n = 2
输出：[0,1,1]
解释：
0 → 0
1 → 1
2 → 10

示例 2

输入：n = 5
输出：[0,1,1,2,1,2]
解释：
0 → 0
1 → 1
2 → 10
3 → 11
4 → 100
5 → 101

约束

0 ≤ n ≤ 105

进阶

能否把常见的 O(n log n) 做法优化成一次扫描的 O(n) 解法？

SOLUTION / REVEALED

一次扫描的动态规划

核心洞察

把 i 右移一位得到 i >> 1，等价于删除二进制末位； 被删除的末位正是 i & 1。因此：

ans[i] = ans[i >> 1] + (i & 1)

由于 i >> 1 < i（当 i > 0），从小到大扫描时依赖项一定已经算好。

完整过程

  1. 建立状态

    ans[i] 表示 i 的二进制中 1 的个数。

  2. 设置基例

    ans[0] = 0，数组默认零值即可覆盖。

  3. 递推扫描

    对 i 从 1 到 n，复用折半结果，再加上当前末位。

  4. 返回数组

    扫描结束时，0 到 n 的每个位置都已填充。

正确性证明

命题：算法返回的每个 ans[i] 都等于 i 的二进制中 1 的个数。

基例：i = 0 时二进制为 0，含 0 个 1，初始化的 ans[0] = 0 正确。

归纳：假设所有小于 i 的位置都正确。右移一位删除 i 的末位，所得 i >> 1 小于 i，其计数已正确；末位是否为 1 由 i & 1 精确给出。二者之和就是 i 的全部 1 的数量。

结论：按数学归纳法，0 到 n 的全部答案均正确。

复杂度与边界

时间：O(n)。每个整数只进行常数次位运算和一次加法。

空间：O(n) 用于返回数组；除返回值外的额外空间是 O(1)。

n = 0：循环不执行，直接返回 [0]。

n = 105：线性扫描满足约束，不依赖递归，也不会产生深栈。

数值安全：题目范围内的 i 与计数值在四种语言的普通整数范围内都安全。

四语言完整代码

Java
class Solution {
    public int[] countBits(int n) {
        int[] ans = new int[n + 1];
        for (int i = 1; i <= n; i++) {
            ans[i] = ans[i >> 1] + (i & 1);
        }
        return ans;
    }
}

替代方案

逐位统计：对每个数不断右移并累计末位，直观但总时间为 O(n log n)。

清除最低位 1：反复执行 x &= x - 1，循环次数等于置位数，最坏仍是 O(n log n)。

最高位递推：维护最近的 2 的幂 highBit，使用 ans[i] = 1 + ans[i - highBit]，同样可达 O(n)。

常见错误

  • 数组只开 n 个位置，漏掉端点 n；正确长度是 n + 1。
  • 把 i & 1 写成逻辑与，得到布尔逻辑而非末位值。
  • 忘记位运算符与加法的优先级差异；用括号明确表达最稳妥。
  • 调用内置 popcount，违反题目明确限制，也绕开了进阶目标。
  • 为每个 i 单独转二进制字符串，增加不必要的时间与临时内存。

面试追问

  • 为什么依赖 ans[i >> 1] 不会形成循环？
  • 能否用偶数/奇数分别写出等价递推式？
  • 如果只询问单个超大整数的置位数，还会预计算整个数组吗？
  • 最高位递推与最低位递推分别复用了哪一段二进制结构？

追问简答

对偶数 2k，末位是 0，所以计数等于 k；对奇数 2k + 1，只比 k 多一个末位 1。

若只求单个整数，应优先使用逐位法或 Brian Kernighan 算法，避免构造 O(n) 数组。

本题必须返回 n + 1 个结果，所以输出本身已经需要 O(n) 空间，无法把总空间降到 O(1)。
