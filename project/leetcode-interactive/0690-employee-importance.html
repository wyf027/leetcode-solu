01 / Problem

任务说明

每位员工用三个字段描述：唯一 ID、重要度，以及直接下属的 ID 列表。给定员工 ID，需要把该员工和他层级之下所有员工的重要度相加。

数据结构与参数

输入为员工对象数组 employees 和整数 id。对第 i 位员工：

  • employees[i].id 是唯一员工编号；
  • employees[i].importance 是该员工自身的重要度，可为负数；
  • employees[i].subordinates 保存所有直接下属的有效 ID。
getImportance(employees: Employee[], id: number): number

约束

  • 1 ≤ employees.length ≤ 2000
  • 1 ≤ employees[i].id ≤ 2000
  • 所有员工 ID 互不相同
  • -100 ≤ importance ≤ 100
  • 一名员工最多有一名直接领导，可以有多名下属
  • 下属列表中的 ID 均有效
示例 1多名直接下属
输入
employees = [[1,5,[2,3]],[2,3,[]],[3,3,[]]], id = 1
输出
11

员工 1 的重要度是 5，直属员工 2 和 3 的重要度各是 3，因此总和为 5 + 3 + 3 = 11。

示例 2负重要度
输入
employees = [[1,2,[5]],[5,-3,[]]], id = 5
输出
-3

目标是员工 5。他的重要度为 -3，且没有直接下属，所以结果就是 -3。

04 / Solution

准备好看完整题解了吗？

展开后将看到核心洞察、证明、复杂度、边界分析与四种语言实现。

Core idea

索引一次，遍历一棵下属树

核心洞察

员工记录以数组给出，但下属关系只保存 ID。先用哈希表建立 ID → Employee 的索引，就能在遍历层级时常数时间取到员工详情。随后从目标 ID 出发做 BFS 或 DFS，将每位可达员工的重要度恰好累加一次。

为什么不能只看一层？

题目要求包含直接和间接下属。直接下属还可能拥有自己的下属，所以必须沿关系持续向下，直到待处理集合为空。

完整过程（BFS）

  1. 建立索引
    扫描 employees，用员工 ID 作为键保存员工对象。
  2. 初始化队列
    将目标 id 放入队列，累计和设为 0。
  3. 逐个处理
    取出一个 ID，找到员工对象，把其重要度加入总和。
  4. 继续向下
    把这名员工的全部直接下属 ID 加入队列。
  5. 返回结果
    队列为空时，所有可达下属均已计入，返回累计和。

正确性证明

要证：算法返回目标员工及其所有直接、间接下属的重要度之和。

覆盖性：目标员工先入队；每处理一名员工，就将他的所有直接下属入队。对层级深度做归纳，任意深度的下属最终都会入队并被处理。

不重复：有效组织结构中，每名员工至多有一名直接领导，因此从目标员工向下的层级中，每名可达员工只有一条父级来源，会被加入一次。

累加正确：每次出队只加入当前员工自身的重要度。结合覆盖性与不重复性，最终总和恰好包含目标员工和所有下属各一次。

复杂度

建立索引O(n)扫描全部员工
遍历时间O(k + e)k 名可达员工与 e 条下属关系
额外空间O(n)哈希索引与最坏队列

整体时间可写作 O(n + e)；树形组织关系中 e ≤ n - 1，因此也常简写为 O(n)。

边界与替代方案

需要留意

  • 目标员工没有下属：直接返回他本人的重要度。
  • 重要度可以为负：结果也可能为负，不能擅自截断。
  • 层级可能很深：递归 DFS 有调用栈溢出的风险，迭代 BFS/DFS 更稳妥。
  • 题目保证下属 ID 有效；无需为缺失记录设计额外兜底。

替代方案：递归 DFS

先建立相同的哈希索引，再定义 sum(id)：返回当前员工的重要度，加上对所有直接下属调用 sum 的结果。代码更贴近数学定义，但深层层级会消耗递归栈。

Python 3 · BFSgetImportance(employees, id)
"""
+# Definition for Employee.
+class Employee:
+    def __init__(self, id: int, importance: int,
+                 subordinates: List[int]):
+        self.id = id
+        self.importance = importance
+        self.subordinates = subordinates
+"""
+
+from collections import deque
+from typing import List
+
+
+class Solution:
+    def getImportance(
+        self, employees: List['Employee'], id: int
+    ) -> int:
+        by_id = {employee.id: employee for employee in employees}
+        queue = deque([id])
+        total = 0
+
+        while queue:
+            current = by_id[queue.popleft()]
+            total += current.importance
+            queue.extend(current.subordinates)
+
+        return total

+class Solution {
+public:

+        unordered_map<int, Employee*> byId;
+        for (Employee* employee : employees) {
+            byId[employee->id] = employee;
+        }
+
+        int total = 0;
+        queue<int> pending;
+        pending.push(id);
+
+        while (!pending.empty()) {
+            Employee* current = byId[pending.front()];
+            pending.pop();
+            total += current->importance;
+            for (int subordinateId : current->subordinates) {
+                pending.push(subordinateId);
+            }
+        }
+        return total;
+    }

面试追问

  • 如果组织关系可能有环？ 增加 visited 集合，只让每个 ID 入队一次。
  • 如果要回答很多次查询？ 保留 ID 索引；层级很少变化时还可缓存每名员工的子树总和。
  • 如果员工关系频繁调整？ 缓存会失效，需要沿上级链更新或每次查询重新遍历。
  • BFS 和 DFS 哪个更好？ 渐进复杂度相同；迭代 BFS 避免深递归，DFS 通常更短。

常见错误

  • 处理每个下属 ID 时都在线性数组里查员工，最坏会退化到 O(n²)。
  • 只累加目标员工和直属下属，漏掉更深层的间接下属。
  • 误以为重要度非负，错误地截断负值。
  • JavaScript 反复调用 shift() 删除数组首项，可能引入额外搬移；头指针更稳定。
