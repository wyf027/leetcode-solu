Minimum Number of Moves to Make Palindrome

相邻的一次交换，离对称更近一步。先独立思考，再展开过程。

题目

给定只含小写英文字母的字符串 s。每次操作只能交换两个相邻字符。求把它变为回文串所需的最少操作次数。回文串正着读与倒着读相同；题目保证存在可行的回文排列。

参数：s: string　返回：integer
函数：minMovesToMakePalindrome(s)

官方示例 1

输入：s = "aabb"
输出：2

可以用两次交换得到 abba：aabb → abab → abba；也能用两次得到 baab：aabb → abab → baab。最少需要 2 次。

官方示例 2

输入：s = "letelt"
输出：2

letelt → letetl → lettel，共两次相邻交换。tleelt 也是可能的回文结果，少于 2 次无法完成。

约束

  • 1 ≤ s.length ≤ 2000。
  • s 仅含小写英文字母。
  • 保证通过有限次相邻交换可以变为回文串。

从两端向中间，固定一对再处理下一对

贪心 · 双指针 · 相邻交换

把左端字符与区间内最靠右的相同字符配对，将后者一步步推到右端。如果左端字符没有同伴，它就是必须放在中心的孤字符：先向右让一步，暂不收缩区间。

核心洞察与完整过程

  1. 把字符串转成可修改的字符数组，维护尚未固定的区间 [l, r]。
  2. 令 k = r，向左找与 a[l] 相同的字符，直到找到或到达 l。
  3. 若 k > l，通过 r-k 次相邻交换，把它移动到 r。两端配对完成，令 l++、r--。
  4. 若 k == l，这个字符在剩余区间只出现一次，必须去中心。交换 a[l] 和 a[l+1]，答案加一，保持边界不动并重新搜索。
  5. 当 l ≥ r 时，所有位置已经对称，返回计数。

aabb：给左侧 a 找到索引 1 的同伴，把它推到末尾，经过 abab 得到 abba，耗费 2 次；里面的 bb 已经匹配。

ntiin：先固定外层 nn，剩余 tii。t 没有同伴，向右交换一步成为 iti，全串得到 nitin，答案为 1。

为什么这个贪心最优

不变式：区间外的字符已经两两对称；后续只交换区间内部的字符。剩余字符仍能构成回文，且最多只有一个奇数次字符。

配对选择：把同字符的各次出现按原位置编号。交换两个相同字符不改变字符串，因此最优过程可以保持同字符的相对次序。在回文中，同字符的最左出现应与最右出现配对，然后依次向内配对。于是当前左端的同伴可以选为区间中最靠右的同字符。

外层选择的交换论证：设该对的位置为 (l,k)，另一字符对为 (p,q)，且 l<p。若 q<k，另一对已被它包围，让该对继续在外层，两对之间不必交叉；反过来需要额外交叉。若 k<p，两对分离，不论哪对在外层，两对之间都需要两次交叉。若 p<k<q，两对交错，两种嵌套顺序都需要一次交叉。因此把最左位置所属的字符对放在最外层，不会增加与任何其他对之间的交换数。对中心孤字符也同理：在该对内部无需交叉，在其右侧则需跨过右成员一次。

实现达到该代价：将位置 k 的字符推到 r，恰好跨过它右侧的每个字符一次，总计 r-k。删除这两个已固定的端点后，其余字符保持原有相对次序；对子问题重复同一论证，即得全局最优。

孤字符分支：若找不到同伴，它必定是最终中心字符。从区间左端走到中心至少要跨过一个右侧字符；先执行这一次必要交换不会改变其他字符的相对顺序，之后重新求解即可。不能在此时收缩边界。

终止：配对分支使区间缩短 2；孤字符分支使唯一孤字符向中心推进，而下一轮可以处理新左端的字符对。最终只剩空区间或一个中心字符。

边界与复杂度

  • 长度为 1、全相同或已经回文时，答案都是 0。
  • 奇数长度的唯一奇数字符最终占据中心；偶数长度不会出现孤字符分支。
  • 每次实际的相邻交换才加一；搜索、比较和固定端点不计操作。
  • 最坏时间 O(n²)：搜索和移动都会累计到平方量级。字符数组需要 O(n) 空间；C++ 可直接改传值字符串，除字符串副本外只用 O(1) 工作空间。
  • 交换数不超过任意排列所需的 n(n-1)/2 上界；n=2000 时为 1,999,000，32 位有符号整数足够。
  • 题目保证可行，提交代码无需处理无解输入。演示入口额外检查频次，避免无效输入导致过程无法收敛。

Java

class Solution {
    public int minMovesToMakePalindrome(String s) {
        char[] a = s.toCharArray();
        int l = 0, r = a.length - 1, moves = 0;
        while (l < r) {
            int k = r;
            while (k > l && a[k] != a[l]) k--;
            if (k == l) {
                char t = a[l];
                a[l] = a[l + 1];
                a[l + 1] = t;
                moves++;
            } else {
                while (k < r) {
                    char t = a[k];
                    a[k] = a[k + 1];
                    a[k + 1] = t;
                    k++;
                    moves++;
                }
                l++;
                r--;
            }
        }
        return moves;
    }
}

#include <string>
#include <utility>
using namespace std;

class Solution {
public:
    int minMovesToMakePalindrome(string s) {
        int l = 0, r = static_cast<int>(s.size()) - 1;
        int moves = 0;
        while (l < r) {
            int k = r;
            while (k > l && s[k] != s[l]) --k;
            if (k == l) {
                swap(s[l], s[l + 1]);
                ++moves;
            } else {
                while (k < r) {
                    swap(s[k], s[k + 1]);
                    ++k;
                    ++moves;
                }
                ++l;
                --r;
            }
        }
        return moves;
    }
};

替代方案

删除式贪心：取当前末字符，在剩余序列中寻找它最靠左的同伴。若找到位置 i，将其移到开头需 i 次，再删除这一对；若它只出现一次，则先把它作为中心，计入当前长度的一半向下取整，再删除它。数组删除仍是 O(n²)，写法短但不直观展示实际交换。

树状数组 + 逆序对：先按同字符首尾配对，从左到右把尚未分配的字符对依次放到目标回文的两端，孤字符分配到中心。给每次出现分配目标位置后，最少相邻交换数就是该位置排列的逆序对数，用树状数组可在 O(n log n) 时间、O(n) 空间求出。不能随意选择一个回文目标，因为不同目标的代价可能不同。

常见错误

  • 把两个远距离字符直接交换却只计一次：题目只允许相邻交换。
  • 总是找最左的同伴：会引入不必要的跨越，当前左端应优先匹配最右同字符。
  • 孤字符交换后立即移动 l、r：会把没有配对的字符错误地锁在外层。
  • 只统计两端不等的数量：一个字符可能需要移动多个位置。
  • JavaScript 直接改字符串索引：字符串不可变，需要字符数组。

面试追问

如果题目不保证可行，怎么处理？

先统计字符频次。奇数频次超过一种则无解；否则可行。与面试官约定返回 -1 或其他无解表示。

为什么不是 O(n)？

每次固定一对字符之前，可能要线性搜索并移动同伴。区间长度逐步缩短，总工作量可能为 n+(n-2)+…，是平方量级。

如何返回具体操作和最终回文？

每次交换时记录索引对 (i,i+1)，最终字符数组就是构造出的回文。操作列表需要 O(答案) 额外空间，最坏 O(n²)；只求数量时无需存储它。

如果允许交换任意两个位置呢？

相邻距离不再代表代价，本题的移动距离与逆序对论证失效，需要针对任意位置交换重新建模。
