交替方向的最小路径代价 III

网格没有只向右下的拓扑顺序：等待、回退和“违反偏好方向”的罚金，让同一格在不同下一步奇偶下成为不同节点。

题意，精确一点

  • 从 (0, 0) 出发，先支付入口费 1；目标是 (m-1, n-1)。
  • 进入 (i, j) 的费用为 (i+1) × (j+1)。
  • 第 1、3、… 次行动偏好右/下；第 2、4、… 次偏好左/上。每次行动后奇偶都翻转。
  • 可以等待：付当前格 penalty 并翻转；逆偏好移动则在目标入口费之外，付离开格的 penalty。

约束：2 ≤ m × n ≤ 10⁵，0 ≤ penalty[i][j] ≤ 10⁵。累计费用用 64 位整数。

核心状态

dist[r][c][p]：已经站在 (r,c)，且下一次行动奇偶为 p 的最小费用。p=1 表示下一次是奇数行动。

起点是 dist[0][0][1] = 1。每一条边都连接到 p ^ 1，因为无论移动还是等待，行动号都加一。

状态数最多 2mn，每个状态至多 5 条非负边（四个邻居 + 等待）。这是标准 Dijkstra 的地盘。

推导过程：为什么不是普通 DP？

1

若只存 dp[r][c]，会混淆“下一步偏好右下”和“下一步偏好左上”。两者的未来边权不同。

2

等待能改变奇偶；逆向移动能回到已见格。因此状态图有环，无法按行列单调扫描。

3

把每个格复制成偶/奇两层。等待是同格跨层边；移动是跨格跨层边。

4

所有费用非负，堆中第一次弹出的目标状态已经是全局最优，可直接返回。

边界与常见错误

场景 正确处理
起点费用 初始距离是 1，不是 0。
罚金位置 付的是离开格 penalty[r][c]，不是目标格。
行动号 等待同样翻转奇偶；不是“只有移动才翻转”。
目标状态 终点两层都合法；第一次从最小堆弹出任一层即可返回。
溢出 Java/C++/Go/TS 使用 long long / long / int64 / number（上界安全）；不要用 32 位累计。

替代方案：何时才适用？

普通网格 DP

不适用：可以回退和等待，图不是 DAG。

0-1 BFS

不适用：入口费与罚金不是 0/1。

Dijkstra + 两层状态

适用：权非负，状态与边数都是 O(mn)。

别把「偏好方向」误读成「只能走该方向」：逆偏好仍可走，只是付离开格罚金。这正是路径选择发生变化的原因。
