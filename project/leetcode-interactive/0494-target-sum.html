目标和Target Sum

为每个数字选择正号或负号。看似只是一次次二选一，但相同的中间结果会悄悄汇合——先读懂问题，再亲手观察这些路径如何聚拢。

数组 动态规划 回溯 0-1 背包

Problem

题目描述

下面内容依据官方元数据准确转述，函数接收非负整数数组与目标值，返回满足条件的不同表达式数量。

给定一个非负整数数组 nums 和一个整数 target。需要在每个整数前放置 + 或 -，再将它们依次连接成一个表达式。

例如，对于 nums = [2, 1]，可以构造 +2-1。

请返回运算结果恰好等于 target 的不同表达式数量。

函数形式

findTargetSumWays(nums: integer[], target: integer) → integer

约束

  • 1 ≤ nums.length ≤ 20
  • 0 ≤ nums[i] ≤ 1000
  • 0 ≤ sum(nums[i]) ≤ 1000
  • -1000 ≤ target ≤ 1000

示例 1

输入：nums = [1,1,1,1,1], target = 3
输出：5
解释：恰有 5 种符号分配方式：
-1 +1 +1 +1 +1 = 3
+1 -1 +1 +1 +1 = 3
+1 +1 -1 +1 +1 = 3
+1 +1 +1 -1 +1 = 3
+1 +1 +1 +1 -1 = 3

示例 2

输入：nums = [1], target = 1
输出：1

Deep Dive

准备好揭开路径汇合的规律了吗？

Solution

用状态计数合并重复路径

与其保留指数级的完整表达式，只记录“处理到当前位置时，每个和出现了多少次”。

核心洞察

若处理前缀后，和 sum 有 count 种到达方式，那么读到数字 x 后，这些方式分别贡献给 sum + x 与 sum - x。相同新和的贡献直接相加。初始状态是 dp[0] = 1。

完整过程

  1. 建立起点。

    尚未选择任何符号时，只有空表达式，和为 0，计数为 1。

  2. 逐个读取数字。

    为当前 x 创建新的计数表，避免同一轮重复使用它。

  3. 扩展正负选择。

    对旧表中的每个 (sum, count)，把 count 加到新表的 sum+x 和 sum-x。

  4. 读取答案。

    全部数字处理完后，返回目标和对应的计数；若不存在则返回 0。

正确性证明

不变式：处理完前 i 个数字后，dp[s] 等于为这 i 个数字分配正负号、且表达式和为 s 的方案数。

基础：i = 0 时，唯一的空分配得到和 0，因此 dp[0] = 1，其他和的方案数均为 0。

归纳：假设不变式对 i 成立。对第 i+1 个数字 x，任一旧方案都唯一地扩展为加 +x 或 -x 的两种方案；反过来，每个新方案删除最后一个符号后，也唯一对应一个旧方案。转移完整且不重不漏。

结论：归纳至全部数字后，dp[target] 正是题目要求的表达式数量。

时间复杂度

设数组元素总和为 S。可达和位于 [-S, S]，因此最多有 2S+1 个状态，时间复杂度为 O(nS)。

空间复杂度

只保留当前层和下一层的状态，空间复杂度为 O(S)。

边界情况

空状态从 0 开始；元素为 0 时，正负选择落到同一和，必须把计数累加两次；目标超出 [-S,S] 时自然返回 0。

数值范围

最多有 2^20 个表达式，官方返回类型 integer 足够容纳该约束下的答案。

替代方案

回溯

枚举每个位置的正负号，时间复杂度 O(2^n)、递归栈 O(n)。直观，但没有合并重复的中间和。

转成 0-1 背包

设取正号元素和为 P，则 P = (S + target) / 2。当 |target| ≤ S 且 S + target 为偶数时，可统计和为 P 的子集数。需特别保留零元素造成的计数翻倍。

四语言完整代码

均沿用官方提交签名，使用“和 → 方案数”的滚动状态表。

import java.util.HashMap;
import java.util.Map;

class Solution {
    public int findTargetSumWays(int[] nums, int target) {
        Map<Integer, Integer> dp = new HashMap<>();
        dp.put(0, 1);

        for (int num : nums) {
            Map<Integer, Integer> next = new HashMap<>();
            for (Map.Entry<Integer, Integer> entry : dp.entrySet()) {
                int sum = entry.getKey();
                int count = entry.getValue();
                next.merge(sum + num, count, Integer::sum);
                next.merge(sum - num, count, Integer::sum);
            }
            dp = next;
        }

        return dp.getOrDefault(target, 0);
    }
}
/**
 * @param {number[]} nums
 * @param {number} target
 * @return {number}
 */
var findTargetSumWays = function(nums, target) {
    let dp = new Map([[0, 1]]);

    for (const num of nums) {
        const next = new Map();
        for (const [sum, count] of dp) {
            const plus = sum + num;
            const minus = sum - num;
            next.set(plus, (next.get(plus) || 0) + count);
            next.set(minus, (next.get(minus) || 0) + count);
        }
        dp = next;
    }

    return dp.get(target) || 0;
};
from collections import defaultdict
from typing import List


class Solution:
    def findTargetSumWays(self, nums: List[int], target: int) -> int:
        dp = {0: 1}

        for num in nums:
            next_dp = defaultdict(int)
            for total, count in dp.items():
                next_dp[total + num] += count
                next_dp[total - num] += count
            dp = next_dp

        return dp.get(target, 0)
class Solution {
public:
    int findTargetSumWays(vector<int>& nums, int target) {
        unordered_map<int, int> dp{{0, 1}};

        for (int num : nums) {
            unordered_map<int, int> next;
            for (const auto& [sum, count] : dp) {
                next[sum + num] += count;
                next[sum - num] += count;
            }
            dp = move(next);
        }

        auto it = dp.find(target);
        return it == dp.end() ? 0 : it->second;
    }
};

面试追问

为什么不能原地更新状态表？

原地写入会让本轮刚产生的状态再次使用当前数字，等价于一个元素被重复选择。每个数字只能选择一次正号或负号，因此必须建立下一层。

何时优先背包写法？

数组非负、只需计数且目标变换合法时，一维背包常数更小；若要直观支持正负状态或扩展到其他转移，映射状态更自然。

如何恢复一种具体表达式？

在状态转移时保存前驱和最后一次符号选择，命中目标后逆向回溯。若要恢复全部表达式，输出规模本身可能是指数级。

如果数字允许为负数呢？

映射计数法仍能按同样的正负选择转移；背包等价变换则依赖非负数组，不能直接套用。

常见错误

  • 把“不同表达式”误解为“不同结果”：路径即使得到相同的和，也必须分别计数。
  • 遇到 0 时只转移一次：+0 与 -0 是两种不同表达式。
  • 在同一张状态表上更新，导致当前数字被重复使用。
  • 使用背包转化时忘记先判断 |target| > S 或 S + target 的奇偶性。
