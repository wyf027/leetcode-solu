二叉树的坡度

Binary Tree Tilt

EASY树深度优先搜索树形 DP

题目

给定二叉树根节点 root，返回树中所有节点坡度的总和。某节点的坡度，是其左子树节点值之和与右子树节点值之和的差的绝对值；缺失的子树按和为 0 计算。

示例 1

输入：root = [1,2,3]
输出：1
解释：节点 1 的坡度为 |2-3|=1，叶节点坡度均为 0。

示例 2

输入：root = [4,2,9,3,5,null,7]
输出：15
解释：各节点坡度为 0、0、0、2、7、6，总和 15。

示例 3

输入：root = [21,7,14,1,1,2,2,3,3]
输出：9

约束

  • 树中节点数在 [0, 10⁴] 范围内。
  • -1000 ≤ Node.val ≤ 1000。

题解：一次后序遍历

核心洞察

计算当前节点坡度必须先知道左右子树之和。因此让递归函数返回“以当前节点为根的子树和”，并在回溯时把 |leftSum-rightSum| 加入答案。

完整过程

  1. 空节点返回子树和 0。
  2. 递归取得左右子树和。
  3. 累加两者差的绝对值。
  4. 向父节点返回 left + right + node.val。

正确性

对任意节点，后序遍历保证结算它时，左右递归已准确返回对应子树的节点值总和，所以加入的正是该节点坡度。每个非空节点恰好结算一次，最终累计值就是整棵树的坡度。

边界与复杂度

空树答案为 0；叶节点两侧和均为 0；负数节点仍可直接求和并取绝对值。时间复杂度 O(n)，递归栈空间 O(h)，最坏为 O(n)。

替代方案

可用显式栈模拟后序遍历，并用映射保存每个节点的子树和，避免递归栈溢出；代价是额外 O(n) 映射空间。若为每个节点重新遍历子树求和，会退化到最坏 O(n²)。

面试追问

  • 树深达到 10⁴ 时如何避免递归深度风险？使用“节点 + 是否访问完成”的显式栈。
  • 能否不使用全局变量？让递归返回二元组 (subtreeSum, tiltSum)。
  • 为什么前序遍历不自然？当前节点依赖尚未计算的两个子树结果。

常见错误

  • 只计算根节点坡度，没有累计所有节点。
  • 把左右孩子值当作左右子树和。
  • 递归返回了坡度，而父节点真正需要的是子树和。
  • 忽略空树，或忘记取绝对值。

四种语言完整代码

class Solution {
    private int answer = 0;

    public int findTilt(TreeNode root) {
        subtreeSum(root);
        return answer;
    }

    private int subtreeSum(TreeNode node) {
        if (node == null) return 0;
        int left = subtreeSum(node.left);
        int right = subtreeSum(node.right);
        answer += Math.abs(left - right);
        return left + right + node.val;
    }
}

    int subtreeSum(TreeNode* node) {

        int left = subtreeSum(node->left);
        int right = subtreeSum(node->right);
        answer += std::abs(left - right);
