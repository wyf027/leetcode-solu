最远建筑

砖块是精确消耗，梯子是一次性通行证。先沿城市天际线前进，亲手观察资源如何被重新分配；题解会留在页面底部，默认不揭晓。

题目

给定整数数组 heights、砖块数量 bricks 和梯子数量 ladders。你从下标 0 的建筑出发，每次尝试前往下一栋建筑。

若下一栋不更高，可以直接通过；若升高了 d = heights[i + 1] - heights[i]，必须使用 d 块砖或一架梯子。请在最优使用资源的前提下，返回能到达的最远建筑下标。

函数参数

furthestBuilding(heights, bricks, ladders) -> integer

示例 1
输入：heights = [4,2,7,6,9,14,12], bricks = 5, ladders = 1
输出：4
解释：0→1 免费；2→7 的落差用 5 块砖；7→6 免费；6→9 用梯子。之后的上升无法承担。
示例 2
输入：heights = [4,12,2,7,3,18,20,3,19], bricks = 10, ladders = 2
输出：7
示例 3
输入：heights = [14,3,19,3], bricks = 17, ladders = 0
输出：3
约束
1 <= heights.length <= 100000
1 <= heights[i] <= 1000000
0 <= bricks <= 1000000000
0 <= ladders <= heights.length

先想一想

当一次更大的上升晚些出现时，早先已经使用的梯子是否应该“换过去”？如果换过去，原来的小上升该由什么补上？

提示：你需要持续知道“目前由梯子承担的上升中，哪一个最小”。

题解：让梯子始终留给最大的上升

核心洞察：遍历途中，把见过的所有正上升先视为由梯子承担；一旦数量超过 ladders，就把其中最小的上升改用砖块支付。

用一个最小堆保存“当前由梯子覆盖”的上升。每遇到正上升就入堆；若堆大小超过梯子数量，弹出最小值并从砖块中扣除。砖块变成负数时，当前跨越无法完成，答案就是当前建筑下标。

完整过程

  1. 从左到右考察相邻建筑差值。非正差值无需资源，直接继续。
  2. 正差值 d 入最小堆，暂时认为它使用梯子。
  3. 若堆的元素个数大于 ladders，弹出最小的上升，用砖块支付它。
  4. 如果剩余砖块小于 0，说明即使采用当前最优分配也无法跨过这一步，返回 i。
  5. 若遍历结束仍未受阻，返回最后一栋建筑的下标。

为什么正确

交换论证：在任意已处理前缀中，假设梯子覆盖了较小上升 a，砖块却支付了较大上升 b，且 a < b。交换二者后，让梯子覆盖 b、砖块支付 a，砖块消耗减少 b-a，不会让方案更差。因此总存在一个最优方案，让梯子覆盖该前缀中最大的若干个正上升。

最小堆恰好维护这些最大上升：新上升加入后，若名额超限，就移除最小者。于是每一步结束时，砖块消耗都是当前前缀可达到的最小值。若此时砖块仍不够，任何其他分配都不可能跨过当前边界；反之，砖块非负就给出了一个可行分配。

边界情况

  • 只有一栋建筑：无需移动，返回 0。
  • 高度始终不升：不消耗资源，返回最后下标。
  • ladders = 0：所有正上升都从堆中弹出并由砖块支付。
  • bricks = 0：只有梯子覆盖的上升能通过；非正差值仍免费。
  • 砖块可能达到 10^9；四种实现使用的数值类型均可安全容纳本题范围。

复杂度

设建筑数量为 n，梯子数量为 L。堆最多保存 L + 1 个元素，时间复杂度为 O(n log(L + 1))，空间复杂度为 O(L)。当 L = 0 时可视为线性时间。

import java.util.PriorityQueue;

class Solution {
    public int furthestBuilding(int[] heights, int bricks, int ladders) {
        PriorityQueue<Integer> ladderClimbs = new PriorityQueue<>();

        for (int i = 0; i < heights.length - 1; i++) {
            int climb = heights[i + 1] - heights[i];
            if (climb <= 0) {
                continue;
            }

            ladderClimbs.offer(climb);
            if (ladderClimbs.size() > ladders) {
                bricks -= ladderClimbs.poll();
            }
            if (bricks < 0) {
                return i;
            }
        }
        return heights.length - 1;
    }
}
/**
 * @param {number[]} heights
 * @param {number} bricks
 * @param {number} ladders
 * @return {number}
 */
var furthestBuilding = function (heights, bricks, ladders) {
    const heap = [];

    const push = (value) => {
        heap.push(value);
        let i = heap.length - 1;
        while (i > 0) {
            const parent = Math.floor((i - 1) / 2);
            if (heap[parent] <= heap[i]) break;
            [heap[parent], heap[i]] = [heap[i], heap[parent]];
            i = parent;
        }
    };

    const popMin = () => {
        const min = heap[0];
        const last = heap.pop();
        if (heap.length > 0) {
            heap[0] = last;
            let i = 0;
            while (true) {
                let smallest = i;
                const left = i * 2 + 1;
                const right = left + 1;
                if (left < heap.length && heap[left] < heap[smallest]) smallest = left;
                if (right < heap.length && heap[right] < heap[smallest]) smallest = right;
                if (smallest === i) break;
                [heap[i], heap[smallest]] = [heap[smallest], heap[i]];
                i = smallest;
            }
        }
        return min;
    };

    for (let i = 0; i < heights.length - 1; i++) {
        const climb = heights[i + 1] - heights[i];
        if (climb <= 0) continue;

        push(climb);
        if (heap.length > ladders) bricks -= popMin();
        if (bricks < 0) return i;
    }
    return heights.length - 1;
};
from typing import List
import heapq


class Solution:
    def furthestBuilding(
        self, heights: List[int], bricks: int, ladders: int
    ) -> int:
        ladder_climbs = []

        for i in range(len(heights) - 1):
            climb = heights[i + 1] - heights[i]
            if climb <= 0:
                continue

            heapq.heappush(ladder_climbs, climb)
            if len(ladder_climbs) > ladders:
                bricks -= heapq.heappop(ladder_climbs)
            if bricks < 0:
                return i

        return len(heights) - 1

class Solution {
public:
    int furthestBuilding(vector<int>& heights, int bricks, int ladders) {
        priority_queue<int, vector<int>, greater<int>> ladderClimbs;

        for (int i = 0; i < static_cast<int>(heights.size()) - 1; ++i) {
            int climb = heights[i + 1] - heights[i];
            if (climb <= 0) {
                continue;
            }

            ladderClimbs.push(climb);
            if (static_cast<int>(ladderClimbs.size()) > ladders) {
                bricks -= ladderClimbs.top();
                ladderClimbs.pop();
            }
            if (bricks < 0) {
                return i;
            }
        }
        return static_cast<int>(heights.size()) - 1;
    }

替代方案

方案思路复杂度取舍
最大堆记录砖块先用砖块；不够时，把历史最大砖耗改成梯子O(n log n)，O(n)同样正确、直观，但堆可能更大
二分最远下标对每个前缀判断能否到达约 O(n log n)重复扫描，代码更复杂，通常没有必要
动态规划枚举资源分配状态取决于砖块量，最坏不可接受bricks 可达 10^9，状态空间过大

面试追问

  • 为什么最小堆只需保留至多 ladders 个上升？
  • 能否反过来先用砖块，再用最大堆撤销最大的砖块开销？
  • 如果每架梯子有不同的最大跨度，原贪心为什么不再直接成立？
  • 若需要返回具体的资源使用方案，应在堆元素中额外保存哪些信息？

常见错误

  • 按遇到的顺序固定使用梯子，忘记后来可以通过交换让梯子覆盖更大上升。
  • 把下降高度也加入堆或扣除砖块。
  • 砖块不足时返回 i + 1；实际尚未到达下一栋，应返回 i。
  • 用排序维护所有上升，导致每步代价过高；最小堆只维护梯子覆盖集合即可。
