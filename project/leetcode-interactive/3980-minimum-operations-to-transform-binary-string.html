LeetCode 3980 · Medium · 路径匹配

变换二进制字符串的最少操作次数

从 s1 变到等长 s2：可以把一个 0 变为 1，也可以把一对相邻 11 同时消成 00。这页将“必须消掉的 1”画成路径上的点，找能一次覆盖两个点的相邻边。

每个消元边的成本

用一条边执行 11 → 00。若边只覆盖一个必须清除的 1，另一端要先由 0 → 1 补出来，因此总成本反映为 Δ + 3 × edges。

推荐主线

把 s1=1,s2=0 的位置记为必覆盖点。最多将相邻必覆盖点两两配对；路径最大匹配越大，所需消元边越少。

题意、示例与约束

操作顺序可任意安排。目标是最少操作数；若做不到，返回 -1。

示例

s1 = "11"; s2 = "00"

期望输出：1。直接对下标 0, 1 使用一次相邻消元。

s1 = "01"; s2 = "10"

期望输出：3：先补第 0 位，再消去 11，最后补第 0 位。

约束

1 ≤ n = s1.length = s2.length ≤ 10^5；两个字符串只含 0/1。

长度为 1 且要求 1 → 0 时，没有相邻位置可参与消元，必定无解。

可视化实验室：把必消点用边覆盖

红色格是 1 → 0 的“必消点”。金色连线表示一次消元同时服务两个相邻必消点；单独的红点也能借邻居补出 1 后消掉，但要额外付补位成本。

题解（默认收起）

按需展开，不在首屏直接展示推导与代码。

核心洞察：每次消元都会使总 1 数减少 2；补位会增加 1。令 R 为必须从 1 变 0 的位置数，令 M 为相邻必消点能配成的最大匹配数，则最少消元次数是 R − M。总操作为 ones(s2) − ones(s1) + 3 × (R − M)。

完整过程

  1. 扫描每个下标；当 s1[i]='1' 且 s2[i]='0' 时，标记为必消点，并计入 R。
  2. 在必消点构成的路径上做最大匹配：遇到相邻的两个必消点就配成一组并跳过二者。这正是每段连续红点的 floor(length / 2)。
  3. 得到消元次数 B = R − M。如果 B>0 而 n=1，立即无解。
  4. 利用总 1 数变化 Δ：每个消元额外贡献 3 到操作表达式，答案为 Δ + 3B。

边界

源目标相同返回 0；全是补位只需数零到一；孤立必消点可借任一邻居补位；唯一不可借位的情况是长度为 1。

复杂度

一次扫描同时计数和贪心匹配：O(n) 时间，O(1) 额外空间。

替代方案、面试追问与常见错误

替代：可写两状态 DP（当前位置是否与前一位配对），但路径最大匹配的贪心已经最优。追问：如果消元允许任意两位，图变成完全图，匹配只看必消点数。常见错误：只按汉明距离计数；忽略“一个消元会改变 1 的总数 2”；把孤立点误判为无解（长度大于 1 时可先补邻居）。
