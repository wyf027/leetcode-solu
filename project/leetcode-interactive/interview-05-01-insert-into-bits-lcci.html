题意

替换一段，而不是简单追加

给定整数 N、M 与从最低位 0 开始编号的 i、j（i ≤ j）。将 M 的二进制位写入 N 的 [i,j] 区域；区域比 M 更宽时，高位补 0。题目保证该区域足以容纳 M。

示例 1

输入

N = 1024, M = 19, i = 2, j = 6

输出

1100

N = 10000000000₂，M = 10011₂，结果 = 10001001100₂。

示例 2

输入

N = 0, M = 31, i = 0, j = 4

输出

31

窗口正好是低 5 位，11111₂ 直接写入。

位编号约定

从右向左编号，最低位是第 0 位。交互轨道固定展示 32 位，并将第 i 到第 j 位染成橙色窗口。

题解

打开工作台内部

核心洞察、完整过程与四语言代码默认隐藏。

核心洞察：先清空，再合并

直接执行 N | (M << i) 会保留窗口里原有的 1，因此必须先构造一个仅在 [i,j] 为 1 的窗口掩码，取反后与 N 相与完成清空。之后再把 M 左移并 OR 进去。

完整过程

  1. 窗口宽度 w = j - i + 1。
  2. 窗口掩码 window = ((1 << w) - 1) << i。
  3. cleared = N & ~window。
  4. shifted = M << i。
  5. answer = cleared | shifted。

边界与复杂度

  • M = 0 时仍需清空整个窗口。
  • i = 0 时右侧保留掩码为空。
  • j = 31 时使用 64 位中间值，避免 32 位移位溢出。
  • 时间复杂度 O(1)，额外空间 O(1)。

替代方案

可以逐位扫描 32 个位置并重建答案，逻辑直观但冗长；面试中优先展示掩码方案。

面试追问

若区间不足以容纳 M，应先检测 M 的最高有效位；若允许任意宽整数，可直接沿用同一掩码公式。

常见错误

忘记清空窗口、把位编号当成从左开始、窗口宽度漏掉 +1，以及在 j = 31 时用 1 << 32。

可提交代码

四种语言，同一个掩码 

class Solution {
    public int insertBits(int N, int M, int i, int j) {
        int width = j - i + 1;
        long window = ((1L << width) - 1) << i;
        long cleared = ((long) N) & ~window;
        long shifted = ((long) M) << i;
        return (int) (cleared | shifted);
    }
}

 * @param {number} N
 * @param {number} M
 * @param {number} i
 * @param {number} j
 * @return {number}
 */
var insertBits = function (N, M, i, j) {
    const width = BigInt(j - i + 1);
    const shift = BigInt(i);
    const window = ((1n << width) - 1n) << shift;
    const result = (BigInt(N) & ~window) | (BigInt(M) << shift);
    return Number(result);
};
