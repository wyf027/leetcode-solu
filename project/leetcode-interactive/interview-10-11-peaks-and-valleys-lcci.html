PROBLEM BRIEF

把数组整理成峰谷交替

OFFICIAL INTENT

在整数数组中，峰不小于相邻元素，谷不大于相邻元素。给定数组 nums，请原地调整元素，使峰与谷交替出现；答案不唯一。

本页固定一种合法轮廓： nums[0] ≥ nums[1] ≤ nums[2] ≥ nums[3] …。 等号合法，因此重复值不会造成问题。

OFFICIAL EXAMPLE

输入
nums = [5, 3, 1, 2, 3]

输出
[5, 1, 3, 2, 3]

约束
nums.length <= 10000

GREEDY SURVEY

一次扫描，逐段校准坡向

O(n) / O(1)

CORE INSIGHT

只修当前相邻关系

从左到右扫描：奇数下标应是谷，必须不大于左邻；偶数下标应是峰，必须不小于左邻。若当前坡向违反目标，就交换这一对。

WHY IT HOLDS

交换不会破坏已经完成的左侧

修谷时，小值被换到右侧；修峰时，大值被换到右侧。留在左侧的新值只会让此前的不等式更宽松，因此前缀持续有效。

INPUT PROFILE

读取原始地形

准备从左向右检查每一对相邻测点。

奇数位 · 谷
nums[i-1] ≥ nums[i]
偶数位 · 峰
nums[i-1] ≤ nums[i]
等值
无需交换，仍满足不严格不等式

COMPLETE PROCESS

完整过程

  1. 令 i = 1，从第二个元素开始。
  2. 若 i 为奇数且右值更大，交换，使奇数位成为谷。
  3. 若 i 为偶数且右值更小，交换，使偶数位成为峰。
  4. 继续向右，直到数组末尾；原数组即为答案。

BOUNDARIES

边界情况

  • 空数组与单元素数组天然满足要求。
  • 重复值允许等号，因此无需特殊处理。
  • 负数只参与比较，算法不依赖数值范围。
  • 答案不唯一，只需保持一种稳定交替方向。

COMPLEXITY

复杂度

时间O(n)
额外空间O(1)

每个相邻边只检查一次，交换直接发生在原数组。

ALTERNATIVES

替代方案

  • 排序后两两交换：直观，但需要 O(n log n)。
  • 每个峰位取三者最大值：同为 O(n)，代码分支更多。
  • 构造新数组：可行，但增加 O(n) 空间。

COMMON MISTAKES

常见错误

  • 混用两种目标方向，导致奇偶位规则前后矛盾。
  • 把“峰/谷”误写成严格大于或小于，遗漏重复值。
  • 只检查局部却没有说明交换为何不破坏前缀。
  • 忘记题目要求原地修改，错误返回新数组。

INTERVIEW FOLLOW-UPS

面试追问

  • 为什么无需排序？目标只约束相邻关系，不要求全局有序。
  • 能改成奇数位为峰吗？可以，反转奇偶判断即可。
  • 若要求严格峰谷呢？重复值可能使问题无解，需要额外条件。 
class Solution {
    public void wiggleSort(int[] nums) {
        for (int i = 1; i < nums.length; i++) {
            boolean shouldSwap =
                (i % 2 == 1 && nums[i] > nums[i - 1])
                || (i % 2 == 0 && nums[i] < nums[i - 1]);
            if (shouldSwap) {
                int temp = nums[i];
                nums[i] = nums[i - 1];
                nums[i - 1] = temp;
            }
        }
    }
}

        const shouldSwap =
            (i % 2 === 1 && nums[i] > nums[i - 1])
            || (i % 2 === 0 && nums[i] < nums[i - 1]);
        if (shouldSwap) {
            [nums[i - 1], nums[i]] = [nums[i], nums[i - 1]];
        }
    }
