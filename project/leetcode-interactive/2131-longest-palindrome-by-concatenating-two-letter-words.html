连接两字母单词
得到的最长回文串

Longest Palindrome by Concatenating Two Letter Words

把两字母卡片重新排列，让整串文字从两端读来完全相同。你最多能用上多少个字符？

01 / 题目

给定字符串数组 words，每个元素都恰好由两个小写英文字母组成。你可以挑选其中一些元素，并以任意顺序拼接；数组中的每一个元素最多使用一次。目标是拼出最长的回文字符串，返回它的字符长度。如果无法组成任何非空回文串，返回 0。

回文字符串正读与倒读相同。允许重排整张单词卡片，但不能拆分或修改卡片内部的字母顺序。

参数与返回值

longestPalindrome(words: string[]) → integer

重复的单词代表不同元素，可以按各自出现次数使用。

约束

  • 1 ≤ words.length ≤ 10⁵
  • words[i].length == 2
  • words[i] 仅包含小写英文字母 a–z。

官方示例

输入：words = ["lc","cl","gg"]
输出：6

例如 "lc" + "gg" + "cl" = "lcggcl"，共 6 个字符；"clgglc" 也满足要求。

输入：words = ["ab","ty","yt","lc","cl","ab"]
输出：8

例如 "ty" + "lc" + "cl" + "yt" = "tylcclyt"，长度为 8；也可以得到 "lcyttycl"。

输入：words = ["cc","ll","xx"]
输出：2

选取 "cc"、"ll" 或 "xx" 中的任意一个，能得到长度为 2 的最长回文串。

核心洞察：每张卡片都有镜像位置

因为单词长度固定为 2，整个回文串在两端对齐的单词必须互为反转。ab 只能和 ba 配对，配成一对贡献 4 个字符。aa 也可以两张配对；所有配对完成后，最多还能把一张剩余的同字母单词放到中心，额外贡献 2 个字符。

完整过程

  1. 建立 26 × 26 计数表，记录尚未配对的单词数量，答案从 0 开始。
  2. 读取单词 ab。若待配池中有 ba，消耗一张 ba，答案加 4；否则把当前 ab 放入待配池。
  3. 扫描对角线 count[a][a]，只要存在正数，答案加 2 并立即结束扫描。
  4. 返回累计字符长度。单词如何安排不用实际保存；演示界面保存左右半边只是为了呈现构造。

为什么正确

必要条件：所有元素的长度都是 2，从字符串两端划分出的单词边界始终对齐。因此，每个非中心单词必有一个反转单词与之对应；中心若存在，必须是 aa 这样的自身回文单词。

配对最优：对于不同字母 ab 与 ba，最多使用 min(freq[ab], freq[ba]) 对。在线算法只要两者都存在就立即消耗一对，结束时不会同时剩下两种互为反转的单词，因此恰好达到该上限。对于 aa，算法恰好取出 floor(freq[aa] / 2) 对。

中心与构造：将所有配对中的一个单词按任意顺序放左侧，其反转单词按相反顺序放右侧，即可组成回文。剩余的同字母单词任选一张放中心，仍是回文。中心最多容纳一张两字母单词；算法在存在候选时恰好增加 2。各组都达到配对上限且中心也最优，所以总长度最大。

边界与复杂度

  • 只有一个 ab：无反转伙伴且不能放中心，结果为 0；只有一个 aa：结果为 2。
  • 同字母词出现偶数次：全部配对；出现奇数次：多余一张参与中心竞争。
  • 多种同字母词都剩一张时，只能选一个中心。某种非同字母词剩再多也不能当中心。
  • 设 n = words.length，字母表大小为 Σ = 26。时间 O(n + Σ²)（包括表初始化），固定字母表下为 O(n)；额外空间 O(Σ²)，本题为 O(1)。
  • 答案至多为 2n ≤ 200000，四语言的常规整数均可表示。

替代方案

先统计全部频次，再只遍历 a < b 的无序反转词组，贡献 4 × min(count[a][b], count[b][a])；对角线贡献 4 × floor(count[a][a] / 2)，有任意奇数对角线计数就再加 2。也可以用哈希表替代二维数组；固定小写字母表用数组更直接。枚举排列会产生阶乘级增长，不适合十万级输入。

JAVA
class Solution {
    public int longestPalindrome(String[] words) {
        int[][] count = new int[26][26];
        int answer = 0;
        for (String word : words) {
            int a = word.charAt(0) - 'a';
            int b = word.charAt(1) - 'a';
            if (count[b][a] > 0) {
                count[b][a]--;
                answer += 4;
            } else {
                count[a][b]++;
            }
        }
        for (int a = 0; a < 26; a++) {
            if (count[a][a] > 0) {
                answer += 2;
                break;
            }
        }
        return answer;
    }
}

from typing import List

class Solution:
    def longestPalindrome(self, words: List[str]) -> int:
        count = [[0] * 26 for _ in range(26)]
        answer = 0
        for word in words:
            a = ord(word[0]) - ord('a')
            b = ord(word[1]) - ord('a')
            if count[b][a] > 0:
                count[b][a] -= 1
                answer += 4
            else:
                count[a][b] += 1
        for a in range(26):
            if count[a][a] > 0:
                answer += 2
                break
        return answer
C++
#include <string>
#include <vector>
using namespace std;

class Solution {
public:
    int longestPalindrome(vector<string>& words) {
        int count[26][26] = {};
        int answer = 0;
        for (const string& word : words) {
            int a = word[0] - 'a';
            int b = word[1] - 'a';
            if (count[b][a] > 0) {
                --count[b][a];
                answer += 4;
            } else {
                ++count[a][b];
            }
        }
        for (int a = 0; a < 26; ++a) {
            if (count[a][a] > 0) {
                answer += 2;
                break;
            }
        }
        return answer;
    }
};

常见错误

  • 一对单词贡献 4 个字符，不是 2；返回的不是单词数量。
  • 先入池再匹配，会让 aa 与自身这同一个元素配对。必须先查询旧池，再决定是否入池。
  • 每种奇数次的同字母词都加 2，会重复使用中心；只加一次。
  • 离线统计时同时计算 ab 和 ba，会把同一对算两遍。
  • JavaScript 使用 Array(26).fill(Array(26).fill(0)) 会共享行；Python 的 [[0] * 26] * 26 同样错误。

面试追问

  • 如何返回实际字符串？每次配对记录当前词到左侧，对应反转词记录到右侧；最后反转右侧的单词序列并插入中心，额外空间为 O(n)。
  • 输入是流怎么办？配对阶段只需维护计数表和长度；流结束后选一次中心，无需保存全部输入。
  • 单词长度统一为 k 呢？仍能按单词边界镜像配对，一对贡献 2k；中心候选必须自身为回文。反转与哈希处理需计入 O(k) 成本。
  • 长度不统一呢？单词边界可能不再镜像对齐，这个按整词反转配对的证明不成立，需要重新建模。
