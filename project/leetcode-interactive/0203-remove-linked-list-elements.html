203. 移除链表元素

在不丢失链表开头节点的前提下，删除所有值等于目标值的节点。用一个“虚拟头结点”把边界情况变成普通情况。

虚拟头结点单链表原地修改O(n) 时间

题意

给定单链表的头节点 head 和整数 val，删除链表中所有 Node.val == val 的节点，并返回新的头节点。

官方样例 1
输入head = [1,2,6,3,4,5,6]val = 6
输出[1,2,3,4,5]
官方样例 2
输入head = []val = 1
输出[]
官方样例 3
输入head = [7,7,7,7]val = 7
输出[]

约束：链表节点数范围为 [0, 10⁴]；每个节点值与 val 均在 [1, 50] 内。

交互：让 prev 站在“待检查节点”的前一个位置

黄色框是当前检查节点。命中 val = 6 时，prev.next 直接跨过它；否则 prev 正常前进。

dummy → prev；检查第 1 个节点

题解：虚拟头结点（Dummy Node）

核心洞察

若头节点也要删除，直接维护 head 会出现特判。先构造 dummy.next = head 后，任何删除都是统一的“让前驱跳过当前节点”。

完整过程

  1. dummy 指向原头节点，prev = dummy。
  2. 检查 prev.next，而非检查 prev 自己。
  3. 命中目标：prev.next = prev.next.next，prev 不移动。
  4. 未命中：prev = prev.next。
  5. 返回 dummy.next。

边界与复杂度

空链表：dummy 使循环自然不执行。

连续命中：删除后 prev 不动，能继续检查新 prev.next。

全删：返回 null。

复杂度：每个节点最多检查一次，时间 O(n)，额外空间 O(1)。

替代方案取舍

递归写法很短，但会消耗 O(n) 调用栈，节点数到 10⁴ 时不如迭代稳妥。面试优先使用虚拟头结点迭代。

常见错误：删除命中节点后仍写 prev = prev.next，会跳过连续目标节点；或没有 dummy 而忘记更新 head。

面试追问

如果只删除第一个命中节点？删除后立即返回即可。若需要保留被删节点列表，可在断链前保存节点引用。若链表是双向链表，还需同步维护 prev 指针。

class Solution {
  public ListNode removeElements(ListNode head, int val) {
    ListNode dummy = new ListNode(0, head);
    ListNode prev = dummy;
    while (prev.next != null) {
      if (prev.next.val == val) prev.next = prev.next.next;
      else prev = prev.next;
    }
    return dummy.next;
  }
}
