CORE INSIGHT

减法组合只是局部逆序

规范罗马数字通常从大到小排列。唯一需要减法的信号，就是当前符号值小于右邻符号值；因此逐字符比较相邻值就能统一处理 IV、IX、XL、XC、CD、CM。

LOCAL RULE

current < next：total -= current

否则：total += current

末位没有下一位，可视为下一值 0，所以一定执行加法。

FULL WALKTHROUGH

完整解题过程

  1. 1. 建常量映射：保存七个符号对应的整数值。
  2. 2. 从左扫描：取当前字符值，并在存在时读取下一字符值。
  3. 3. 判断逆序：当前值较小就减去，否则加上。
  4. 4. 末位处理：没有下一字符时直接加当前值。
  5. 5. 返回总和：每个字符恰好被结算一次。

边界情况

  • 单字符直接返回其面值。
  • 连续相同字符全部执行加法。
  • 减法对会表现为先减小值、再加大值。
  • 输入保证合法，不需要验证非法排列。

复杂度

时间：O(n)

额外空间：O(1)

映射只有七个固定条目，不随输入增长。

替代方案

可以显式识别六种双字符组合并跳两步，也可以从右向左维护最大值。前瞻扫描分支最少、最贴近题意，是面试主线。

class Solution {
    public int romanToInt(String s) {
        int total = 0;

        for (int i = 0; i < s.length(); i++) {
            int current = valueOf(s.charAt(i));
            int next = i + 1 < s.length()
                ? valueOf(s.charAt(i + 1))
                : 0;
            total += current < next ? -current : current;
        }
        return total;
    }

    private int valueOf(char symbol) {
        return switch (symbol) {
            case 'I' -> 1;
            case 'V' -> 5;
            case 'X' -> 10;
            case 'L' -> 50;
            case 'C' -> 100;
            case 'D' -> 500;
            default -> 1000;
        };
    }
}

面试高频追问

为什么不需要验证当前小值能否放在该大值前？
题目保证输入合法；若题目不保证，则需要额外校验允许的六种组合与重复规则。
能否从右向左扫描？
可以；维护右侧最大值，当前小于最大值就减，否则加并更新最大值。
哈希表算 O(1) 空间吗？
算。它固定只有七个条目，与输入长度无关。

常见错误

  • 看到小值就减，却没有确认右侧值更大。
  • 循环只到倒数第二位，忘记补上最后一个字符。
  • 把合法输入验证混入主线，制造不必要的复杂分支。
  • 识别减法对后仍把两个字符各自再计算一次。
