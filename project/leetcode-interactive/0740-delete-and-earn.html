01 / Problem

每一次得分，都伴随一次相邻清场

给定整数数组 nums。你可以重复执行操作：选择一个 nums[i]，删除它并获得等值点数；同时必须删除数组中所有等于 nums[i] - 1 和 nums[i] + 1 的元素。返回能够获得的最大总点数。

函数形式

deleteAndEarn(nums) → integer

约束

  • 1 <= nums.length <= 2 × 104
  • 1 <= nums[i] <= 104

返回值

执行任意次操作后可获得的最大点数。

官方示例 1

输入：nums = [3,4,2]
输出：6
解释：先删除 4 得 4 分，3 随之删除；再删除 2 得 2 分，总分为 6。

官方示例 2

输入：nums = [2,2,3,3,3,4]
输出：9
解释：选择一个 3 会清除所有 2 和 4；剩余的三个 3 可依次取得，共得 9 分。

Solution unlocked

先聚合，再做“打家劫舍”

如果决定选择数值 x，选择一个 x 不会伤害剩余的 x，所以应该把所有 x 一起拿走，收益为 x × count(x)。冲突只发生在相邻数值之间。

核心洞察

  1. 把相同数值的收益合并到 points[x]。
  2. 选择 x 后不能选择 x-1 与 x+1。
  3. 于是数值轴上的每个点就像一排房屋：相邻不能同时拿。

状态定义

dp[x]：只考虑数值 0..x 时的最大收益。

dp[x] = max(dp[x-1], dp[x-2] + points[x])

完整过程

  1. 扫描 nums，求最大值 M，建立长度 M + 1 的收益数组。
  2. 对每个数字 x，累加 points[x] += x。
  3. 从 1 到 M 扫描，用两个变量保存前两项：prev1 表示上一位置最优值，prev2 表示上上位置最优值。
  4. 当前位置要么跳过，保留 prev1；要么选择，得到 prev2 + points[x]。取二者较大值。

以 [2,2,3,3,3,4] 为例

聚合后 points[2]=4、points[3]=9、points[4]=4。数值 3 的总收益 9 高于选择 2 与 4 的组合收益 8，因此答案为 9。

正确性证明

  1. 同值聚合正确。若一个解选择了某个 x，继续选择剩余的 x 不会引入新的冲突，却会增加收益。因此最优解中，同一数值要么全选，要么全不选。
  2. 转移覆盖所有可能。考虑数值 x。最优解要么不选它，此时收益不超过 dp[x-1]；要么选它，此时不能选 x-1，剩余部分最优为 dp[x-2]，总收益为 dp[x-2]+points[x]。
  3. 归纳成立。基础位置显然正确。假设更小位置的状态均为最优，转移取上述两个互斥且完备情形的最大值，故 dp[x] 也为最优。最终 dp[M] 即原问题答案。

边界与复杂度

  • 只有一个元素：直接获得该元素的值。
  • 只有一种数值：聚合后全部选择。
  • 某个数值没有出现：其收益为 0，转移自然跨过空位。
  • 大量重复值：只影响聚合收益，不增加状态数量。
时间复杂度O(n + M)
空间复杂度O(M)

其中 n 是数组长度，M = max(nums)。滚动状态本身只需 O(1)，收益数组占 O(M)。

class Solution {
    public int deleteAndEarn(int[] nums) {
        int maxValue = 0;
        for (int num : nums) {
            maxValue = Math.max(maxValue, num);
        }

        int[] points = new int[maxValue + 1];
        for (int num : nums) {
            points[num] += num;
        }

        int prevTwo = 0;
        int prevOne = 0;
        for (int value = 1; value <= maxValue; value++) {
            int current = Math.max(prevOne, prevTwo + points[value]);
            prevTwo = prevOne;
            prevOne = current;
        }
        return prevOne;
    }
}

替代方案

  • 排序唯一值：用哈希表聚合后排序，只遍历出现过的数值；相邻值按冲突转移，存在间隔时可直接叠加当前收益。复杂度为 O(n + U log U)，适合数值范围很大、不同值很少的情况。
  • 自顶向下记忆化：对数值轴递归选择“拿”或“不拿”。表达直观，但有递归开销。
  • 显式 DP 数组：保存每个位置的最优值，便于还原选择方案，但空间多于滚动变量。

常见错误

  • 按数组下标做状态，而没有先按“数值”聚合冲突。
  • 选择一个值后只删除一个相邻元素，忽略题目要求删除所有相邻值。
  • 聚合时写成计数 count[x]，却忘了收益应为 x × count[x]。
  • 滚动更新顺序错误，在计算当前状态前覆盖了 prevTwo。
  • 稀疏值排序方案中，把不连续的两个数值也误当成冲突。

面试追问

如果数值上限达到 109 呢？

改用哈希表聚合并排序唯一值，避免建立超大的稠密数组。

怎样返回具体选择了哪些数值？

保存完整 DP 数组，从最大值反向比较转移来源，恢复被选择的数值集合。

如果允许出现负数呢？

坐标需改用映射；由于操作可执行零次，状态基线保持 0，负收益通常跳过。

为什么相同数值一定全部选择？

它们产生相同冲突集合；一旦承担冲突代价，多选同值只会增加收益。
