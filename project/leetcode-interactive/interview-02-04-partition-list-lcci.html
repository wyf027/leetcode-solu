Route Book / Solution

两条稳定支线，一次接轨

核心洞察

不要在原链表中反复寻找插入位置。准备两个虚拟头：less 收集值小于 x 的节点，more 收集其余节点。每个节点只追加一次，遍历结束后把 less 的尾部接到 more 的首部。

为什么稳定

两条支线都只在尾部追加，因此同一分区内的节点顺序与原链表一致。拼接只改变两个分区之间的边界，不会重排支线内部。

完整过程

  1. 创建 lessDummy、moreDummy，并让 lessTail、moreTail 指向各自虚拟头。
  2. 保存当前节点的 next，再按 node.val < x 选择支线并尾插。
  3. 遍历完成后，先令 moreTail.next = null，切断原链可能残留的旧连接。
  4. 令 lessTail.next = moreDummy.next，返回 lessDummy.next。

边界

  • 空链表直接得到空链表。
  • 全部小于 x 时，右支线为空，原顺序不变。
  • 全部大于或等于 x 时，左支线为空，返回右支线。
  • 值等于 x 的节点必须进入右支线。
  • 必须把右支线尾部置空，避免意外形成环。

复杂度

O(n)时间：每个节点访问一次
O(1)空间：不计两个虚拟头

替代方案

可以把小于 x 的节点不断插到链表头部，空间同样是 O(1)，但会反转左分区顺序，证明与排错都更困难。也可以交换节点值，但那改变节点承载的数据，不如重连节点符合链表题语义。

常见错误

  • 忘记保存 next，重连后丢失后续节点。
  • 把等于 x 的节点错误放入左分区。
  • 只拼接两条链，却忘记终止右链尾部。
  • 返回虚拟头本身，而不是 dummy.next。

面试追问

  1. 为什么右链尾部必须显式置空？请构造会形成环或错链的输入。
  2. 如果要求三段分割：小于、等于、大于 x，该如何扩展？
  3. 如果禁止虚拟头节点，如何处理每条支线的首次插入？
  4. 若节点包含不可交换的业务对象，为什么交换 val 不是等价实现？

class Solution {
    public ListNode partition(ListNode head, int x) {
        ListNode lessDummy = new ListNode(0);
        ListNode moreDummy = new ListNode(0);
        ListNode lessTail = lessDummy;
        ListNode moreTail = moreDummy;

        while (head != null) {
            if (head.val < x) {
                lessTail.next = head;
                lessTail = lessTail.next;
            } else {
                moreTail.next = head;
                moreTail = moreTail.next;
            }
            head = head.next;
        }

        moreTail.next = null;
        lessTail.next = moreDummy.next;
        return lessDummy.next;
    }
}
