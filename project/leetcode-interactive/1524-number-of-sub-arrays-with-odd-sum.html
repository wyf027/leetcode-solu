挑战提示

不必知道每段子数组的精确和。

试着只记录前缀和的两种状态，观察何时能组成奇数。

Problem

题目描述

给你一个整数数组 arr，返回其中元素和为奇数的连续非空子数组数目。答案可能很大，需要对 109 + 7 取余。

函数签名：numOfSubarrays(arr: integer[]) → integer

示例 1
输入：arr = [1,3,5] 输出：4 解释：六个子数组的和依次为 1、4、9、3、8、5，其中四个为奇数。
示例 2
输入：arr = [2,4,6] 输出：0 解释：所有连续子数组的和都是偶数。
示例 3
输入：arr = [1,2,3,4,5,6,7] 输出：16

更多官方示例

输入：arr = [100,100,99,99] 输出：4
输入：arr = [7] 输出：1

约束

  • 1 ≤ arr.length ≤ 105
  • 1 ≤ arr[i] ≤ 100

Solution

题解：只统计前缀和的奇偶

下面给出完整推导。核心做法是把“连续区间和”转换成两个前缀和之差，并只保留奇偶性。

核心洞察

设 prefix[i] 是前 i 个数之和。区间 [l, r] 的和为 prefix[r+1] - prefix[l]。一奇一偶的两个前缀相减，结果才是奇数。

因此扫描到一个偶前缀时，它能和此前每个奇前缀组成答案；扫描到奇前缀时，则能和此前每个偶前缀组成答案。

状态与转移

  • even：已经出现的偶前缀数量，初始为 1（空前缀）。
  • odd：已经出现的奇前缀数量，初始为 0。
  • 当前前缀为奇：answer += even，再令 odd++。
  • 当前前缀为偶：answer += odd，再令 even++。

完整过程

  1. 用 parity = 0 表示空前缀为偶，并设置 even = 1、odd = 0、answer = 0。
  2. 从左到右扫描数组。只需计算 parity = (parity + value) % 2，无需保存完整前缀和。
  3. 若当前为奇数前缀，就把此前偶前缀数量加入答案；反之把此前奇前缀数量加入答案。
  4. 把当前前缀计入对应计数。每一步对答案取模，最后返回答案。

正确性证明

充分性：当前前缀与此前异奇偶前缀的差为奇数，所以每次加入的区间都符合要求。

必要性：任意奇数和子数组都对应一对奇偶性不同的边界前缀。扫描到右边界时，左边界已被计入相反奇偶计数，因此该子数组恰好被统计一次。

结论：算法不重不漏地统计了全部奇数和子数组。

边界与复杂度

  • 单个奇数：空前缀提供一个匹配，答案为 1。
  • 全为偶数：前缀始终为偶，答案为 0。
  • 长数组：答案可达平方量级，需使用足够宽的整数，并持续取模。
  • 时间复杂度 O(n)；额外空间复杂度 O(1)。

替代方案

动态规划：维护“以当前位置结尾”的奇数和与偶数和子数组数量。遇到偶数，两者数量保持；遇到奇数，两者互换，并额外产生一个只含当前元素的奇数和子数组。它同样是 O(n) 时间、O(1) 空间。

暴力枚举：枚举左右端点需要 O(n²)，只能用于小规模手算或对照，不满足 10⁵ 的数据范围。

class Solution {
    public int numOfSubarrays(int[] arr) {
        final int MOD = 1_000_000_007;
        long answer = 0;
        long even = 1;
        long odd = 0;
        int parity = 0;

        for (int value : arr) {
            parity = (parity + value) & 1;
            if (parity == 1) {
                answer = (answer + even) % MOD;
                odd++;
            } else {
                answer = (answer + odd) % MOD;
                even++;
            }
        }
        return (int) answer;
    }
}

面试追问

  • 如果要求偶数和子数组，匹配规则如何改变？
  • 为什么空前缀必须计入 even？
  • 能否用“以每个位置结尾”的动态规划解释同一过程？
  • 若元素允许负数，这个方法是否仍然成立？（成立，奇偶性不受影响。）

常见错误

  • 把 even 初始化为 0，漏掉从下标 0 开始的奇数和子数组。
  • 先增加当前前缀计数、再累加答案，造成把同一前缀和自己配对。
  • 只在最后取模，并在 Java/C++ 中使用 32 位整数承载累计答案。
  • 统计任意子序列，而不是连续子数组。
