切棍子的
最小成本

切在哪里已经确定，真正改变成本的是切割顺序。先观察一次切割如何改变后续成本，再决定何时打开完整题解。

英文标题Minimum Cost to Cut a Stick
难度HARD
函数minCost(n, cuts)
数组动态规划排序

Problem

题意

一根木棍长为 n，位置从 0 标到 n。整数数组 cuts 给出所有必须切开的位置；每个位置恰好切一次，顺序可以自由安排。

每次切割的成本等于当前被切那一段木棍的长度。切割后该段分成两段，之后的切割只在对应的小段中发生。请返回完成全部切割的最小总成本。

参数形式：minCost(n: integer, cuts: integer[]) → integer。输入数组中的切点互不相同，且都严格位于木棍内部。

Examples

官方示例

示例 1

输入n = 7, cuts = [1,3,4,5]
输出16

例如按 [3,5,1,4] 的顺序切，成本为 7 + 4 + 3 + 2 = 16；比照原输入顺序切得到的 20 更低。

示例 2

输入n = 9, cuts = [5,6,1,4,2]
输出22

原数组顺序的总成本是 25；重新安排为 [4,6,5,2,1] 可得到最小总成本 22。

约束

  • 2 ≤ n ≤ 10⁶
  • 1 ≤ cuts.length ≤ min(n − 1, 100)
  • 1 ≤ cuts[i] ≤ n − 1
  • cuts 中的整数互不相同

Deep Dive

区间动态规划

核心洞察

不要决定“下一刀”，而要决定“这个区间的第一刀”。

给切点补上两端 0 与 n 并排序。若区间两端已经分离，那么在其中选择第一刀 k，本次固定支付区间长度；左右两侧之后互不影响。

  1. 预处理。 构造 pos = [0, ...sorted(cuts), n]。
  2. 定义状态。 dp[i][j] 表示完成开区间 (pos[i], pos[j]) 内所有切割的最小成本。
  3. 枚举第一刀。 对每个 i < k < j，候选成本是左右子问题加本段长度。
  4. 按区间长度递增。 先算短区间，确保转移依赖的两个子区间已经得到答案。
dp[i][j] = min(dp[i][k] + dp[k][j] + pos[j] - pos[i])，i < k < j

完整过程

设补齐边界后的数组长度为 m。相邻位置之间没有待切点，所以 dp[i][i+1] = 0。随后令端点间距 gap 从 2 增加到 m−1；对每个区间 [i,j]，尝试其中所有切点 k。

以 n=7, cuts=[1,3,4,5] 为例，pos=[0,1,3,4,5,7]。短区间先求出，例如 [3,5] 内只有切点 4，费用为 2。最终 dp[0][5] 在第一刀取 3 时组合左右最优值，得到 16。

正确性

对区间包含的切点数归纳。空区间费用为 0。对非空区间，任意合法方案都有唯一第一刀 k，先支付整段长度，剩余切割被分成相互独立的左右子问题。归纳假设保证两侧的 dp 最优；枚举全部 k 取最小值，因此状态最优，最终 dp[0][m−1] 即全局最优。

边界

  • 只有一个切点：答案就是 n。
  • 切点无需预先有序，算法内部排序。
  • 端点不在输入中，要显式补 0 与 n。
  • 最多 100 个切点，三次方转移可接受。

复杂度

令 c = cuts.length。排序为 O(c log c)，动态规划为 O(c³) 时间；二维表占 O(c²) 空间。

LeetCode 官方签名 · 自底向上区间 DP
import java.util.Arrays;

class Solution {
    public int minCost(int n, int[] cuts) {
        Arrays.sort(cuts);
        int m = cuts.length + 2;
        int[] pos = new int[m];
        pos[0] = 0;
        pos[m - 1] = n;
        for (int i = 0; i < cuts.length; i++) {
            pos[i + 1] = cuts[i];
        }

        int[][] dp = new int[m][m];
        for (int gap = 2; gap < m; gap++) {
            for (int i = 0; i + gap < m; i++) {
                int j = i + gap;
                dp[i][j] = Integer.MAX_VALUE;
                for (int k = i + 1; k < j; k++) {
                    int candidate = dp[i][k] + dp[k][j]
                            + pos[j] - pos[i];
                    dp[i][j] = Math.min(dp[i][j], candidate);
                }
            }
        }
        return dp[0][m - 1];
    }
}

var minCost = function(n, cuts) {
    cuts.sort((a, b) => a - b);
    const pos = [0, ...cuts, n];
    const m = pos.length;
    const dp = Array.from(
        { length: m },
        () => Array(m).fill(0)
    );

    for (let gap = 2; gap < m; gap++) {
        for (let i = 0; i + gap < m; i++) {
            const j = i + gap;
            dp[i][j] = Number.POSITIVE_INFINITY;
            for (let k = i + 1; k < j; k++) {
                const candidate = dp[i][k] + dp[k][j]
                    + pos[j] - pos[i];
                dp[i][j] = Math.min(dp[i][j], candidate);
            }
        }
    }
    return dp[0][m - 1];
};

from typing import List


class Solution:
    def minCost(self, n: int, cuts: List[int]) -> int:
        pos = [0] + sorted(cuts) + [n]
        m = len(pos)
        dp = [[0] * m for _ in range(m)]

        for gap in range(2, m):
            for i in range(m - gap):
                j = i + gap
                dp[i][j] = min(
                    dp[i][k] + dp[k][j] + pos[j] - pos[i]
                    for k in range(i + 1, j)
                )

        return dp[0][m - 1]

class Solution {
public:
    int minCost(int n, vector<int>& cuts) {
        sort(cuts.begin(), cuts.end());
        vector<int> pos;
        pos.reserve(cuts.size() + 2);
        pos.push_back(0);
        pos.insert(pos.end(), cuts.begin(), cuts.end());
        pos.push_back(n);

        int m = static_cast<int>(pos.size());
        vector<vector<int>> dp(m, vector<int>(m, 0));

        for (int gap = 2; gap < m; ++gap) {
            for (int i = 0; i + gap < m; ++i) {
                int j = i + gap;
                dp[i][j] = INT_MAX;
                for (int k = i + 1; k < j; ++k) {
                    int candidate = dp[i][k] + dp[k][j]
                                    + pos[j] - pos[i];
                    dp[i][j] = min(dp[i][j], candidate);
                }
            }
        }
        return dp[0][m - 1];
    }
};

替代方案与面试追问

能否贪心选择中间切点？

不能保证最优。看似均分当前区间的切点，可能让子区间内部的切点分布很不均衡；局部平衡不等于全局成本最小。

可以写成记忆化搜索吗？

可以。递归函数 solve(i,j) 使用同一转移并缓存结果，复杂度不变；自底向上版本避免递归开销，依赖顺序也更直观。

为什么只看切点索引？

子问题边界一定来自原始端点或某个已切位置，所以离散化后的 pos 已包含所有可能边界，无需按长度 n 建表。

和矩阵链乘法有什么联系？

两者都是区间 DP：枚举区间最后形成结构中的分割点，用两个更小区间的最优值组合出当前答案。

常见错误

遗漏排序或两端哨兵；把一次费用错算成某一侧长度；错误地按 n 建立巨大数组；区间遍历方向导致子状态尚未计算；用 0 初始化非空区间后直接取最小值。
