830. 较大分组的位置

Positions of Large Groups。把连续相同字符看作一个个区间，找出长度至少为 3 的那些区间。

01 / PROBLEM

题目要求

下标从 0 开始，区间的起点和终点都计入分组。

给定一个仅由小写英文字母组成的字符串 s。相邻且相同的字符会组成一个连续分组，每个分组用闭区间 [start, end] 表示。

当分组包含至少 3 个字符时，它就是“较大分组”。请返回所有较大分组的区间，并按起始下标从小到大排列。

例如，s = "abbxxxxzyy" 中的分组依次是 "a"、"bb"、"xxxx"、"z"、"yy"；其中 "xxxx" 的区间是 [3, 6]。

参数与约束

  • 1 ≤ s.length ≤ 1000
  • s 只包含小写英文字母
  • 函数返回类型：List<List<Integer>>
  • 官方函数名：largeGroupPositions

官方示例

Example 01
输入s = "abbxxxxzzy"
输出[[3,6]]

"xxxx" 是唯一的较大分组，起止下标分别为 3 和 6。

Example 02
输入s = "abc"
输出[]

三个分组的长度都是 1，因此没有较大分组。

Example 03
输入s = "abcdddeeeeaabbbcd"
输出[[3,5],[6,9],[12,14]]

对应的较大分组是 "ddd"、"eeee" 和 "bbb"。

Example 04
输入s = "aba"
输出[]

相同的 "a" 不连续，不能合并成同一个分组。

准备好看完整题解了吗？

题解包含线性扫描的核心洞察、正确性证明、边界情况、复杂度、替代方案、面试追问与四种语言的完整代码。

SOLUTION UNLOCKED

一次扫描，按组结算

核心洞察

无需逐个位置向左右扩展。维护当前分组的起点 start，用 end 从左向右扫描；当 end 位于字符串末尾，或下一个字符与当前字符不同，当前分组就在 end 处结束。此时只要判断 end - start + 1 ≥ 3，然后令下一组起点为 end + 1。

完整过程

  1. 建立空答案 ans，把第一组的起点 start 设为 0。
  2. 令 end 从 0 扫描到 n - 1。
  3. 若 end == n - 1，或 s[end] != s[end + 1]，说明当前连续分组完整结束。
  4. 若 end - start + 1 ≥ 3，把 [start, end] 加入答案。
  5. 将 start 更新为 end + 1，继续处理下一组。
  6. 扫描结束后直接返回答案。发现顺序就是起点递增顺序，无需额外排序。

为什么正确

引理 1 · 找到完整边界

只在末尾或相邻字符发生变化时结算，所以 end 恰是当前连续相同字符分组的最后一个位置；而 start 是上一次结算后的下一个位置，恰是本组起点。

引理 2 · 不漏且不多

每个字符属于且仅属于一个连续分组，每个分组只在其终点结算一次。算法仅把长度至少为 3 的完整分组加入答案，因此不会漏掉较大分组，也不会加入不合格区间。

结论 · 顺序正确

扫描方向从左到右，后一组的起点一定大于前一组的起点。因此所有被加入的区间天然按起始下标递增，返回结果满足题意。

边界情况

  • 长度为 1 或 2：任何分组都不可能达到长度 3，返回空数组。
  • 整串字符相同：直到最后一个位置才结算，若长度至少为 3，答案为 [0, n - 1]。
  • 恰好长度 3：条件必须是 ≥ 3，不能误写为 > 3。
  • 较大分组位于末尾：必须显式把字符串末尾视为分组边界，否则最后一组会被遗漏。
  • 同字符不连续：如 "aba" 中两个 a 属于不同分组，不能合并。

复杂度

时间复杂度
O(n)

每个字符只被从左到右检查一次。

额外空间
O(1)

除返回结果外，只维护少量下标变量；答案本身占用 O(k)。

四语言完整代码

四份实现使用同一条边界判定：到达末尾，或下一个字符不同。

JavaList<List<Integer>> largeGroupPositions(String s)
class Solution {
    public List<List<Integer>> largeGroupPositions(String s) {
        List<List<Integer>> ans = new ArrayList<>();
        int start = 0;

        for (int end = 0; end < s.length(); end++) {
            boolean isGroupEnd = end == s.length() - 1
                    || s.charAt(end) != s.charAt(end + 1);

            if (isGroupEnd) {
                if (end - start + 1 >= 3) {
                    ans.add(Arrays.asList(start, end));
                }
                start = end + 1;
            }
        }

        return ans;
    }
}

替代方案

  • 显式双指针：固定左指针 left，让右指针持续跨过同字符，随后检查 right - left。逻辑等价，按组跳跃的写法也很直观。
  • 哨兵字符：在字符串末尾拼接一个不可能出现的字符，统一触发最后一组结算。但这会创建新字符串，并需谨慎选择哨兵；本题没有必要。
  • 语言分组工具：Python 可用 itertools.groupby，不过仍要累计下标；面试中手写边界扫描通常更清晰、跨语言也更通用。

面试追问

  • 如果阈值不是 3？ 把阈值作为参数 k，判断长度是否至少为 k，整体复杂度不变。
  • 如果输入是字符流？ 只需保存当前字符、分组起点、当前位置和输出；字符变化时即可结算上一组，因此可以在线处理。
  • 为什么无需排序？ 区间按扫描顺序发现，而扫描顺序严格对应起点递增顺序。
  • 能否做到原地？ 输入无需修改；除输出数组外，算法只用常数额外空间。

常见错误

  • 用 end - start 当作长度，忘记闭区间长度应为 end - start + 1。
  • 只在字符变化时结算，遗漏字符串末尾的最后一个分组。
  • 结算后没有把 start 更新为 end + 1。
  • 先收集所有分组再排序；虽然能做对，但排序完全多余。
  • 把“不连续的相同字符”错误地合并为一组。
