CORE INSIGHT

一半已经足够证明镜像

每次用 x % 10 取出原数最后一位，接到 reversedHalf。循环只进行到 x ≤ reversedHalf，因此不会完整反转，也规避了完整反转的溢出风险。

TWO FINISH LINES

偶数位：x === reversedHalf

奇数位：x === Math.floor(reversedHalf / 10)

奇数位时，reversedHalf 会多拿到中间数字；除以 10 丢掉它即可。

FULL WALKTHROUGH

完整解题过程

  1. 1. 快速排除

    负数必定不是回文；非零且末位为 0 的数也不是回文。

  2. 2. 搬运末位

    digit = x % 10；reversedHalf = reversedHalf × 10 + digit。

  3. 3. 缩短原数

    x = floor(x / 10)，直到原数不再长于反转半边。

  4. 4. 比较两种形态

    偶数位直接比较；奇数位先从反转半边删掉中心位。

边界情况

  • • x < 0 → false
  • • x = 0 → true
  • • x % 10 = 0 且 x ≠ 0 → false
  • • 一位正数 → true
  • • 偶数位回文比较两半
  • • 奇数位回文丢弃中心位

复杂度

O(log₁₀ n)

只处理约一半十进制位

O(1)

只维护两个整数

替代方案取舍

推荐：反转后一半

满足进阶要求，空间 O(1)，且避免完整反转溢出。

转字符串 + 双指针

最直观，但额外使用 O(d) 空间，也绕开了数学考点。

完整反转整数

可以比较原数与反转值，但必须额外处理 32 位溢出。

class Solution {
    public boolean isPalindrome(int x) {
        if (x < 0 || (x % 10 == 0 && x != 0)) {
            return false;
        }

        int reversedHalf = 0;
        while (x > reversedHalf) {
            reversedHalf = reversedHalf * 10 + x % 10;
            x /= 10;
        }

        return x == reversedHalf || x == reversedHalf / 10;
    }
}

面试高频追问

为什么非零末位 0 可以直接排除？
镜像后会要求最高位是 0，但整数表示不存在前导零。
为什么只反转一半不会漏判？
回文的左右半边互为逆序；获得任意完整一半就足够比较。
reversedHalf 会溢出吗？
它最多保存约一半十进制位；32 位输入下不会超过 int 范围。

常见错误

  • • 忘记负数的负号破坏镜像。
  • • 把 0 与所有末位为 0 的数一起排除。
  • • 奇数位时忘记用 reversedHalf / 10 丢弃中心位。
  • • 循环条件写成固定次数，边界容易出错。
  • • 完整反转后才比较，却没有处理溢出。

最后记忆钩子：负数和尾零先排除，末位搬到另一半，奇数位丢中心。
