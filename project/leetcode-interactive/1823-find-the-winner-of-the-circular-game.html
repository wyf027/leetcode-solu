找出游戏的获胜者

Find the Winner of the Circular Game

一圈朋友，一次次报数。先观察谁会离开，再思考如何只求最后留下的人。

01 · 游戏规则

给定整数 n 和 k，有 n 人按顺时针编号 1 到 n，n 的下一位是 1。起初从 1 号开始，沿顺时针数 k 个仍在圈内的人，起点也算第 1 个。第 k 个被数到的人离开；下一轮从他的顺时针下一位幸存者重新数起。允许绕圈并重复数到同一个人。只剩一人时结束，返回其原始编号。

参数：findTheWinner(n, k) → integer
约束：1 ≤ k ≤ n ≤ 500
进阶：能否在线性时间、常数额外空间内完成？

官方示例 1

输入：n = 5, k = 2
输出：3

依次报数 (1,2)、(3,4)、(5,1)、(3,5)，离开顺序为 2 → 4 → 1 → 5，最终留下 3。

官方示例 2

输入：n = 6, k = 5
输出：1

离开顺序为 5 → 4 → 6 → 2 → 3，最终留下 1。

04 · 独立题解

准备好后再展开推导和四语言代码。

从淘汰过程到下标映射

核心洞察

这是约瑟夫环。只关心获胜者时，不必保存淘汰列表。令 f(m) 是 m 人、从下标 0 开始游戏时，获胜者的零基下标。单人时 f(1) = 0；扩大到 m 人时，f(m) = (f(m - 1) + k) % m，最终返回 f(n) + 1。

为什么加 k，而不是 k − 1？

m 人时，第一个离场的是旧下标 (k - 1) % m。余下 m − 1 人从旧下标 k % m 开始新一轮。以这个新起点重编号为 0，剩余圆环与规模 m − 1 的同类问题完全一致。新下标 x 对应旧下标 (x + k) % m。k − 1 定位被删除的人，k 定位下一轮起点，二者用途不同。

完整过程：n = 5，k = 2

  1. 初始化 winner = 0，对应规模 1。
  2. m = 2：winner = (0 + 2) % 2 = 0。
  3. m = 3：winner = (0 + 2) % 3 = 2。
  4. m = 4：winner = (2 + 2) % 4 = 0。
  5. m = 5：winner = (0 + 2) % 5 = 2。
  6. 转换回题目的 1 基编号，得到 2 + 1 = 3。

这里从小规模累积的是“获胜下标”，并非模拟同一局游戏的时间顺序。上面的圆桌实验展示真实报数与淘汰；递推则倒着恢复每次缩小规模前的坐标。

正确性证明

基础：m = 1 时唯一的人下标为 0，初始化正确。归纳：假设变量保存了规模 m − 1 时的正确获胜下标。规模 m 的第一轮删除一人后，剩余顺序及报数规则保持不变，以旧下标 k % m 为新起点，构成规模 m − 1 的同类问题。根据归纳假设，新坐标下获胜者为 f(m − 1)，映射回旧坐标就是 (f(m − 1) + k) % m。因此更新后变量仍为正确获胜下标。循环结束得到 f(n)，加 1 即所求原始编号。

边界与复杂度

  • n = 1：循环不执行，返回 1。
  • k = 1：每轮起点被删除，最终编号为 n。
  • 即使初始 k ≤ n，后续规模 m 可能小于 k；取模正确处理多次绕圈。
  • 循环 n − 1 次：时间 O(n)，额外空间 O(1)。官方范围内整数相加不会溢出。

替代方案

数组模拟：维护幸存编号及起点下标 p，每轮删除 (p + k - 1) % size，删除位置在新数组中就是下一轮起点（越界时回到 0）。删除涉及搬移，最坏 O(n²) 时间、O(n) 空间。队列旋转 k − 1 次再出队，直观实现为 O(nk) 时间、O(n) 空间。递归直接套递推式是 O(n) 时间，但调用栈为 O(n)，不满足常数空间进阶要求。

Java

class Solution {
    public int findTheWinner(int n, int k) {
        int winner = 0;
        for (int size = 2; size <= n; size++) {
            winner = (winner + k) % size;
        }
        return winner + 1;
    }
}

常见错误

  • 漏数起点：模拟只需前进 k − 1 次，不是 k 次。
  • 误把递推写成加 k − 1：坐标映射的原点是淘汰者的下一位。
  • 始终对 n 取模：每次递推必须对当前规模 size 取模。
  • 忘记最后加 1，或中途混用零基下标与一基编号。
  • 数组删除后又把 p 加 1：后面的元素已经左移，会跳过应当报数的人。

面试追问

需要完整淘汰顺序？单个获胜下标不足以还原过程；小规模用数组或队列，大规模可用支持第 k 个存活元素查询的树状数组，做到 O(n log n) 时间、O(n) 空间。

起始编号变成 s？先求零基 f(n)，答案为 ((f(n) + s - 1) % n) + 1。

k 超大怎么办？同一递推仍然成立，但必须保证数值类型能精确表示 k；可先对当前规模取模，超出 JavaScript 安全整数范围时使用 BigInt。

k = 2 有特别规律吗？令 p 为不超过 n 的最大 2 的幂，一基答案为 2 × (n - p) + 1；这是特例，通用 k 使用上面的线性递推。
