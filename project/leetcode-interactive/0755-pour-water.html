倒水Pour Water

把每一滴水的选择变成可观察的地形变化。先自己操作模拟器建立直觉，再决定是否展开底部题解。

函数
pourWater(heights, volume, k)
输入
整数数组、体积、落点
输出
倒水后的高度数组

Problem

题意

给定非负整数数组 heights。每个元素表示对应位置的地面高度，所有位置宽度均为 1。现在有 volume 个单位的水，从索引 k 的正上方逐滴落下。

每一滴水都遵循相同规则：

  1. 先尝试向左流动，只能沿着不升高的地形前进；若能找到比落点更低的位置，就停在左侧可到达的最低位置。出现多个同高最低点时，选择更靠近水滴左侧流动终点的位置。
  2. 如果左侧没有更低的可达位置，再用对称规则尝试向右寻找更低位置。
  3. 若左右都不能降低水滴所在高度，则水滴留在索引 k。放置后，该位置高度增加 1，再处理下一滴。

返回全部水滴落下后的高度数组。数组中的高度始终表示“地面 + 已积水”的总高度。

关键语义：水滴不会越过途中更高的柱子；左侧具有优先级。搜索到同高平台时可以继续走，但只有遇到严格更低的高度才更新停留候选。

Examples

官方参数形式示例

示例 1
输入：heights = [2,1,1,2,1,2,2], volume = 4, k = 3

示例 3
输入：heights = [3,1,3], volume = 5, k = 1
输出：[3,6,3]

约束

  • 1 ≤ heights.length ≤ 100
  • 0 ≤ heights[i] ≤ 99
  • 0 ≤ volume ≤ 2000
  • 0 ≤ k < heights.length

Full solution

逐滴模拟：先左后右

O(volume × n)
核心洞察

对一滴水而言，最终位置只与当前高度数组有关。把当前位置记为候选点，从 k 向某个方向扫描：只要下一柱不高于当前柱，就仍然可达；每当遇到严格更低的柱子，就更新候选。左边找到更低候选就立即放水，否则再对右边做一次镜像扫描。

完整过程

1 · 向左扫描从 k - 1 开始。在 heights[i] ≤ heights[i+1] 时继续；若 heights[i] < heights[best]，令 best = i。一旦遇到上坡就停止。
2 · 必要时向右若左侧候选仍是 k，从 k + 1 开始。在 heights[i] ≤ heights[i-1] 时继续，并用相同的严格下降规则更新候选。
3 · 放置并重复将 heights[best] 增加 1。新的表面会影响下一滴，因此必须基于更新后的数组重新扫描，共重复 volume 次。

正确性证明

引理 1：左扫描得到的 best 正是当前水滴按规则能到达的左侧停留位置。扫描仅跨越不升高的相邻柱，因此检查的每个位置都可达；遇到上坡后，水滴不能越过，后面位置不可达。只在严格变低时更新候选，使候选始终是已扫描区间中规则要求的最低停留点。

引理 2：若左侧不存在更低候选，右扫描同理得到正确的右侧停留位置。

定理：算法对每滴水的放置都与题目规则一致。左侧候选存在时算法优先选它；否则选正确的右侧候选；两侧都没有更低位置时保留 k。放置后高度数组与真实状态相同。由对水滴数量的归纳，处理完 volume 滴后返回数组正确。

边界与复杂度

  • volume = 0 时循环不执行，直接返回原高度。
  • 单元素数组左右扫描都为空，每滴水均落在索引 0。
  • 同高平台可被扫描穿过，但不会因为“相等”替换候选；这保证停留位置符合流动方向。
  • k 在边界时，其中一个方向自然没有候选。
时间复杂度
O(volume × n)。每滴水最多向左和向右各扫描一次数组。
额外空间
O(1)。直接修改高度数组，不计返回数组与语言调用开销。

替代方案

可以尝试维护左右候选、低谷或批量填平区间，减少水量很大时的重复扫描；但每滴水都会改变局部表面，正确维护边界的实现明显更复杂。在本题 n ≤ 100 的约束下，逐滴模拟更直接、更可靠。用优先队列并不能自然表达“先左后右”和不可越过上坡的规则，通常得不偿失。

class Solution {
    public int[] pourWater(int[] heights, int volume, int k) {
        for (int drop = 0; drop < volume; drop++) {
            int best = k;

            for (int i = k - 1; i >= 0 && heights[i] <= heights[i + 1]; i--) {
                if (heights[i] < heights[best]) {
                    best = i;
                }
            }

            if (best == k) {
                for (int i = k + 1;
                     i < heights.length && heights[i] <= heights[i - 1];
                     i++) {
                    if (heights[i] < heights[best]) {
                        best = i;
                    }
                }
            }

            heights[best]++;
        }
        return heights;
    }
}

class Solution:

            best = k

            i = k - 1
            while i >= 0 and heights[i] <= heights[i + 1]:
                if heights[i] < heights[best]:
                    best = i
                i -= 1

class Solution {
public:
    vector<int> pourWater(vector<int>& heights, int volume, int k) {
        const int n = static_cast<int>(heights.size());

        for (int drop = 0; drop < volume; ++drop) {
            int best = k;

            for (int i = k - 1; i >= 0 && heights[i] <= heights[i + 1]; --i) {
                if (heights[i] < heights[best]) {
                    best = i;
                }
            }

            if (best == k) {
                for (int i = k + 1; i < n && heights[i] <= heights[i - 1]; ++i) {
                    if (heights[i] < heights[best]) {
                        best = i;
                    }
                }
            }

            ++heights[best];
        }

        return heights;
    }
};

常见错误

  • 用全局最小值代替“可达最低点”，从而让水滴穿过更高的柱子。
  • 右侧与左侧同时存在低点时选择了更低的一边；题意要求左侧优先，不是比较两边谁更低。
  • 扫描平台时遇到相等高度就停止，导致无法穿过平台找到后方下降处。
  • 用 ≤ 更新候选，错误改变同高平台上的停留位置。
  • 先计算所有水滴的目标再统一增加高度；后续水滴必须看到前一滴造成的新表面。

面试追问

如果右侧优先呢？

交换两段扫描顺序即可；每一段内部的可达条件和候选更新方式不变。

为什么不能二分查找？

地形没有全局单调性，而且每滴水都会修改数组；可达区间由局部相邻关系决定。

如何支持很大的 volume？

可识别封闭盆地并批量填充到下一层，但需要精确处理溢出方向和左优先规则。

可以不修改输入吗？

可以先复制 heights，再对副本执行相同模拟，额外空间变为 O(n)。
