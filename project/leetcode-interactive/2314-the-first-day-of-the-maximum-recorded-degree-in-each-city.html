The First Day of the Maximum Recorded Degree in Each City

01 / 题目与数据

从天气记录中挑出每座城市的一天

输入关系表 Weather(city_id INT, day DATE, degree INT)。每行表示某个城市在某一天的气温。对每个城市，返回该城市记录过的最高气温及对应日期；如果多天同为最高气温，选择最早日期。输出三列 city_id, day, degree，按 city_id 升序排列。

字段与约束

  • city_id：城市编号，整数。
  • day：记录日期，DATE 类型。
  • degree：气温，整数，可以为负。
  • (city_id, day) 是联合主键，同一城市同一天只有一条记录。
  • 所有记录日期均在 2022 年。
  • 题面未给出行数或气温的数值上下界，不额外假定。

数据库参数形式

CREATE TABLE Weather (
  city_id INT,
  day DATE,
  degree INT,
  PRIMARY KEY (city_id, day)
);
-- 参数是整张 Weather 表，而非一个整数数组。
-- 返回：结果表 (city_id, day, degree)。

题意为转述。题名、表结构及示例来自本地官方元数据；空缺题面中的约束参照公开题面记录补全。官方题目入口需订阅访问。

04 / 独立题解

准备好后，再展开思路

包含推导、SQL、正确性论证及四种语言的本地参考。

按城市分组，以两个条件确定第一名

核心洞察

想要“最高气温的最早日期”，就让气温大的记录排前面，同温时让日期早的记录排前面。城市内部的第一条记录即答案。排序键是 degree DESC, day ASC，分区键是 city_id。

完整过程

  1. 用 PARTITION BY city_id 将不同城市隔开。
  2. 区内按气温降序、日期升序排列，再用 ROW_NUMBER() 编号。
  3. 在外层查询保留 rn = 1。排名别名不能在同层 WHERE 中直接过滤。
  4. 只输出题目需要的三列，并在最外层按城市编号升序排列。
城市 2 的 37 度记录有两条：2022-08-07 排名 1，2022-08-17 排名 2。城市 3 的 −6 度排在 −7 度前；最大值并不需要是正数。

官方可提交方向 · MySQL 8 SQL

SELECT city_id, day, degree
FROM (
    SELECT city_id, day, degree,
           ROW_NUMBER() OVER (
               PARTITION BY city_id
               ORDER BY degree DESC, day ASC
           ) AS rn
    FROM Weather
) AS ranked
WHERE rn = 1
ORDER BY city_id ASC;

正确性

固定任意城市 c。其分区按温度降序排列，因此第一行温度不低于该城市任何其他行。对于所有达到该温度的行，日期升序又使第一行日期最早。联合主键保证同城同日不会出现两条记录，所以排序能确定唯一首行。ROW_NUMBER 只为这一行赋值 1，过滤得到的正是城市 c 所需记录。分区覆盖所有城市且互不干扰，最后的 ORDER BY 满足结果展示顺序。

边界与复杂度

  • 单行城市：唯一记录自然排第一。空表：无分区，无输出。
  • 全为负数：照常比较整数；不要把最大温度初始化为 0。
  • 温度全部相等：按日期选择最早一天，与插入顺序无关。
  • 日期按 DATE 比较。下方本地参考使用固定宽度 ISO 日期 YYYY-MM-DD，因此字符串顺序与日期顺序一致。
  • 题目按有效、非空天气值讨论；若业务表允许 NULL，应先定义 NULL 的筛选与排序语义，不能直接套用默认行为。
  • 设总行数 n、城市数 k。常规排序窗口执行约 O(n log n) 时间，排序及中间结果约 O(n) 空间；索引、执行引擎、磁盘排序会改变实际代价。最外层结果排序为 O(k log k)。

替代方案

先按城市聚合出 MAX(degree)，再与原表按城市和最高温度连接，只在这些最高温度行中取 MIN(day)。注意不能在全表同一次聚合中独立取 MIN(day) 和 MAX(degree)，它们可能来自两条不同记录。

SELECT w.city_id, MIN(w.day) AS day, m.degree
FROM Weather AS w
JOIN (
    SELECT city_id, MAX(degree) AS degree
    FROM Weather
    GROUP BY city_id
) AS m
  ON w.city_id = m.city_id AND w.degree = m.degree
GROUP BY w.city_id, m.degree
ORDER BY w.city_id;

也可用 NOT EXISTS 排除“同城存在更高温度，或同温更早日期”的行；没有合适索引时相关比较可能达到 O(n²)。在应用内单次扫描维护每城最佳记录，可用 O(n + k log k) 时间与 O(k) 额外空间，但这不替代题目要求的数据库查询。

Java · Main.java（Java 8+）
import java.util.*;

public class Main {
    static class Row {
        final int cityId, degree;
        final String day;
        Row(int cityId, String day, int degree) {
            this.cityId = cityId;
            this.day = day;
            this.degree = degree;
        }
        public String toString() {
            return "[" + cityId + ",\"" + day + "\"," + degree + "]";
        }
    }
    static List<Row> findFirstDay(List<Row> weather) {
        List<Row> sorted = new ArrayList<>(weather);
        sorted.sort((a, b) -> {
            int c = Integer.compare(a.cityId, b.cityId);
            if (c != 0) return c;
            c = Integer.compare(b.degree, a.degree);
            return c != 0 ? c : a.day.compareTo(b.day);
        });
        List<Row> result = new ArrayList<>();
        for (Row row : sorted) {
            if (result.isEmpty() ||
                result.get(result.size() - 1).cityId != row.cityId) {
                result.add(row);
            }
        }
        return result;
    }
    public static void main(String[] args) {
        List<Row> weather = Arrays.asList(
            new Row(1,"2022-01-07",-12), new Row(1,"2022-03-07",5),
            new Row(1,"2022-07-07",24), new Row(2,"2022-08-07",37),
            new Row(2,"2022-08-17",37), new Row(3,"2022-02-07",-7),
            new Row(3,"2022-12-07",-6)
        );
        System.out.println(findFirstDay(weather));
    }
}

function findFirstDay(weather) {
  const rows = [...weather].sort((a, b) =>
    a[0] - b[0] || b[2] - a[2] ||
    (a[1] < b[1] ? -1 : a[1] > b[1] ? 1 : 0)
  );
  return rows.filter((row, i) => i === 0 || rows[i - 1][0] !== row[0]);
}

def find_first_day(weather):
    rows = sorted(weather, key=lambda r: (r[0], -r[2], r[1]))
    result = []

        if not result or result[-1][0] != row[0]:

    return result

struct Row { int city_id; string day; int degree; };
vector<Row> findFirstDay(vector<Row> weather) {
    sort(weather.begin(), weather.end(), [](const Row& a, const Row& b) {
        if (a.city_id != b.city_id) return a.city_id < b.city_id;
        if (a.degree != b.degree) return a.degree > b.degree;
        return a.day < b.day;
    });
    vector<Row> result;
    for (const auto& row : weather) {
        if (result.empty() || result.back().city_id != row.city_id)
            result.push_back(row);
    }
    return result;
}

常见错误

  • GROUP BY city_id 后直接取未聚合的 day：无法保证它属于最高温度行。
  • 对整组同时取 MIN(day)、MAX(degree)：可能把最冷的一天与最高温度拼在一起。
  • 只对 degree 排名：最高温度重复时可能返回多行，或随机选择日期。
  • 忽略最外层 ORDER BY：窗口中的顺序并不保证最终结果顺序。
  • 先 MIN(day) 再看温度：得到的是最早记录，不是最高温度首次出现。

面试追问

  • 要所有最高气温日期？按 degree 降序用 RANK，保留排名 1；不把 day 放进这个排名键。
  • ROW_NUMBER 与 RANK 本题能否互换？完整排序键包含联合主键中的 day，同城不再有排序键并列，因此排名 1 都唯一；省略 day 后则不同。
  • 数据跨年怎么办？若要求每城每年一条，将年份加入分区；若要求所有年份的最高温度则无需变更。
  • 怎样优化？可评估 (city_id, degree DESC, day ASC) 索引，并通过数据库执行计划判断是否减少排序；不能仅凭索引存在就保证优化。
  • 流式数据怎么办？每城维护一个当前最佳记录，同温时比较日期；最终按城市排序。
