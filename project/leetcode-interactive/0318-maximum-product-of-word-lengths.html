最大单词长度乘积
Maximum Product of Word Lengths
MEDIUM 位运算 · 数组 · 字符串
LeetCode 318 · Pairing challenge

字母不相遇，长度才相乘。

给定一个只含小写英文字母的单词数组，寻找两个没有任何公共字母的单词，让它们的长度乘积尽可能大；若找不到这样的组合，返回 0。

先想一想： 当单词很长、配对很多时，怎样快速回答“这两个单词是否共享字母”，而不必反复逐字符比较？
先读题，再进入配对实验台
01 / Problem

题目与输入边界

目标值是两个合法单词的长度乘积，而“合法”意味着二者的字母集合没有交集。

函数定义

maxProduct(words: string[]) -> integer

参数 words 是字符串数组。对任意不同下标 i 与 j，若 words[i] 和 words[j] 不含公共字母，则它们构成候选对。返回所有候选对中最大的 words[i].length × words[j].length。

约束

  • 2 <= words.length <= 1000
  • 1 <= words[i].length <= 1000
  • words[i] 只由小写英文字母组成
01

示例 1

输入：words = ["abcw","baz","foo","bar","xtfn","abcdef"]
输出：16
解释：可选 "abcw" 和 "xtfn"，长度乘积为 4 × 4。
02

示例 2

输入：words = ["a","ab","abc","d","cd","bcd","abcd"]
输出：4
解释：可选 "ab" 和 "cd"，长度乘积为 2 × 2。
03

示例 3

输入：words = ["a","aa","aaa","aaaa"]
输出：0
解释：任意两个单词都共享字母 a，不存在合法单词对。

04 / Solution

用 26 位掩码压缩字母集合

每个单词真正影响“能否配对”的信息，不是字母顺序和重复次数，而是 26 个小写字母分别有没有出现。把这 26 个布尔状态装进一个整数，两个集合是否相交就能由一次按位与判断。

STEP 01

编码

字符 c 映射到第 c - 'a' 位；遍历单词并将相应位设为 1。

STEP 02

判交

若 mask[i] & mask[j] == 0，两个单词没有任何共同字母。

STEP 03

更新

枚举所有 i < j；只对无交集的单词对更新长度乘积最大值。

mask(word) = OR(1 << (character - 'a'))
compatible(i, j) ⇔ (mask[i] & mask[j]) == 0

完整过程

  1. 创建长度为 n 的掩码数组。对每个单词扫描全部字符，把出现过的字母位设为 1。
  2. 令答案 answer = 0。枚举每个无序下标对 (i, j)，其中 i < j。
  3. 计算 masks[i] & masks[j]。非零说明至少有一个公共字母，跳过该对。
  4. 结果为零时，计算 words[i].length × words[j].length 并更新答案。
  5. 全部配对检查结束后返回答案；若从未遇到合法单词对，初始值 0 会被直接返回。

正确性证明

L1
掩码准确表示字母集合

构造过程中，字母对应位只在该字母出现时被置为 1，且位不会被清除。因此构造后第 k 位为 1，当且仅当单词包含第 k 个小写字母。

L2
按位与准确判断公共字母

由 L1，两个掩码的同一位都为 1，当且仅当两个单词都含对应字母。所以按位与为 0，当且仅当不存在公共字母。

THM
算法返回最大合法乘积

双重循环恰好枚举每个不同下标组成的无序单词对一次。由 L2，算法只用合法对更新答案，也不会漏掉任何合法对。答案始终是已检查合法对中的最大乘积；循环结束时已检查全部对，因此返回值就是全局最大合法乘积。若无合法对，答案保持 0，仍符合题意。

复杂度、边界与替代方案

时间

设所有单词总字符数为 S、单词数为 n。编码是 O(S)，枚举配对是 O(n²)，总计 O(S + n²)。

空间

存储 n 个掩码需要 O(n) 额外空间；除结果数组外只使用常数个变量。

数值范围

单词长度至多 1000，乘积至多 10⁶；题目各官方语言的常规整数类型足够。

边界情况

  • 单词内部字母重复：重复置同一位不会改变掩码，单词原始长度仍参与乘积。
  • 不同单词拥有相同掩码：若掩码非零，它们必然共享字母，不能相互配对。
  • 所有单词都含某个共同字母：没有合法对，答案保持 0。
  • 只有两个单词：循环只检查唯一的一对。

替代方案

  • 字符集合：为每个词保存 Set，逻辑直观，但每次判交需要检查多个字符，常数更大。
  • 合并相同掩码：每个掩码只保留最大单词长度，再枚举不同掩码；重复字母集合很多时更快，最坏仍为 O(n²)。
  • 按长度降序并剪枝：可以较早得到大答案并跳过不可能超越的组合，但实现和证明更复杂；本题规模下基础位掩码已经足够稳健。

四语言完整实现

均采用“预处理 26 位掩码 + 枚举无序单词对”的同一逻辑。

class Solution {
    public int maxProduct(String[] words) {
        int n = words.length;
        int[] masks = new int[n];

        for (int i = 0; i < n; i++) {
            for (int k = 0; k < words[i].length(); k++) {
                int bit = words[i].charAt(k) - 'a';
                masks[i] |= 1 << bit;
            }
        }

        int answer = 0;
        for (int i = 0; i < n; i++) {
            for (int j = i + 1; j < n; j++) {
                if ((masks[i] & masks[j]) == 0) {
                    int product = words[i].length() * words[j].length();
                    answer = Math.max(answer, product);
                }
            }
        }
        return answer;
    }
}

 * @param {string[]} words

var maxProduct = function(words) {
    const masks = words.map((word) => {
        let mask = 0;
        for (const character of word) {
            mask |= 1 << (character.charCodeAt(0) - 97);
        }
        return mask;
    });

    let answer = 0;
    for (let i = 0; i < words.length; i++) {
        for (let j = i + 1; j < words.length; j++) {
            if ((masks[i] & masks[j]) === 0) {
                answer = Math.max(answer, words[i].length * words[j].length);
            }
        }
    }
    return answer;
};
from typing import List


class Solution:
    def maxProduct(self, words: List[str]) -> int:
        masks = []
        for word in words:
            mask = 0
            for character in word:
                mask |= 1 << (ord(character) - ord("a"))
            masks.append(mask)

        answer = 0
        for i in range(len(words)):
            for j in range(i + 1, len(words)):
                if masks[i] & masks[j] == 0:
                    product = len(words[i]) * len(words[j])
                    answer = max(answer, product)
        return answer

面试追问

如果字符集超过 32 位怎么办？

使用多个机器字组成的位集（如 Java BitSet、C++ 动态位集），或改用哈希集合。若仅是 52 个大小写字母，64 位整数即可。

如果还要返回具体的两个单词？

更新最大乘积时同步保存下标 i 和 j；不存在合法对时按新接口约定返回空结果。

能否减少重复掩码带来的比较？

建立 mask 到最大长度的映射。相同掩码只保留最长单词，因为对于任何外部兼容掩码，更短长度永远不会产生更优乘积。

流式接收单词时如何维护答案？

新单词到达后先编码，与已保存的每个代表掩码比较并更新答案，再更新该掩码对应的最大长度。

常见错误

  • 把字符重复次数写进状态；本题只关心是否出现，同一位重复置 1 即可。
  • 用按位或判断交集；公共位必须通过按位与 & 检测。
  • 把掩码中的 1 的数量当成单词长度；乘积必须使用原字符串长度，重复字符也计入长度。
  • 枚举 i == j 或同时枚举 (i,j) 与 (j,i)；从 j = i + 1 开始最清楚。
  • 在 JavaScript 中担心符号位而改用浮点幂；本题只使用低 26 位，标准位运算安全且直接。
