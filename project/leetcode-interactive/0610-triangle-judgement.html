04 · 完整题解

把几何定理翻译成 CASE WHEN

官方提交入口是数据库语言。核心查询放在最前面；Java、JavaScript、Python、C++ 仅用于本地理解同一判定语义，不能作为本题的官方提交代码。

核心洞察

三条线段能组成非退化三角形，当且仅当任意两边之和都严格大于第三边。“严格大于”很关键：相等时三点共线，不是三角形。

x + y > z AND x + z > y AND y + z > x

SQL 用 CASE WHEN 把这个布尔条件投影成题目要求的 Yes / No。

完整过程

  1. 从 Triangle 读取并原样保留 x、y、z。
  2. 在当前行内检查三组三角不等式，三者之间使用 AND。
  3. 三项全真时映射为 Yes，否则映射为 No。
  4. 把映射结果命名为 triangle；不需要排序，也不需要分组。

正确性说明

充分性：若三个不等式都成立，根据三角形存在定理，三条线段可以首尾相接形成非退化三角形，查询输出 Yes 正确。

必要性：若三条线段能形成非退化三角形，则任意两边之和必然严格大于第三边，所以三个条件都会成立。反之只要有一项不成立，线段无法闭合或只能退化为直线，查询输出 No 正确。

因此，查询对每一行给出的判断与题意完全一致。

边界与复杂度

  • 两边之和等于第三边：必须输出 No。
  • 三边相等且为正：三个条件都成立。
  • 三元组是主键，因此无需处理完全重复的行。
  • 官方元数据只声明 INT，没有给出具体数值范围；不要自行编造约束。
时间O(n)
额外空间O(1)

代码

本题可直接提交以下 MySQL 查询。
SELECT
    x,
    y,
    z,
    CASE
        WHEN x + y > z
         AND x + z > y
         AND y + z > x
        THEN 'Yes'
        ELSE 'No'
    END AS triangle
FROM Triangle;
public final class Solution {
    private Solution() {}

    // 本地语义参考；本题官方提交入口是数据库语言。
    public static String triangleJudgement(int x, int y, int z) {
        long a = x;
        long b = y;
        long c = z;
        boolean valid = a + b > c
                && a + c > b
                && b + c > a;
        return valid ? "Yes" : "No";
    }
}

class Solution {
public:
    // 本地语义参考；本题官方提交入口是数据库语言。
    static std::string triangleJudgement(int x, int y, int z) {
        const long long a = x;
        const long long b = y;
        const long long c = z;
        const bool valid = a + b > c
                           && a + c > b
                           && b + c > a;
        return valid ? "Yes" : "No";
    }
};

替代方案

如果先找出最大边 m，在已知边长为正的前提下，只检查“另外两边之和严格大于 m”也足够。可借助排序或 GREATEST 实现。

但本题直接写三组三角不等式更清晰、跨数据库兼容性更好，也不会引入排序或方言函数，优先推荐。

常见错误

  • 把 > 写成 >=，误把退化情况判为三角形。
  • 三项条件使用 OR；实际上必须全部成立，应使用 AND。
  • 只检查某一组两边之和，但没有先确认哪条是最大边。
  • 漏掉别名 triangle，导致结果列名不符合题目要求。
  • 使用 GROUP BY 或聚合，错误地改变了逐行输出语义。

面试追问

为什么必须检查三项？

在不知道最大边是谁时，三项共同表达“任意两边之和大于第三边”；只写一项会依赖未经证明的边长顺序。

如果允许先排序呢？

设排序后 a ≤ b ≤ c，对正边长只需检查 a + b > c；其余两项自然成立。

如何处理整数溢出？

在可能溢出的编程语言中先提升到更宽整数类型。本题 MySQL 整数表达式通常按更宽整数计算，但迁移到其他数据库时仍应核对类型规则。

为什么空间复杂度是 O(1)？

查询对每行只计算固定数量的表达式，没有随输入行数增长的辅助数据结构；不计结果表本身。
