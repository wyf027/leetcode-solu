不同性别每日分数总计

给定每位选手在某日获得的分数，按性别分别报告每个出现日期截至当天的累计分数。结果先按性别、再按日期升序排列。

数据库分区累计有序时间线

Problem

题目说明

表 Scores 记录选手姓名、性别、得分日期和当日获得的分数。对于表中每个 性别 × 日期，计算该性别从最早日期起到当前日期为止的总分，并按 gender ASC, day ASC 返回。

!
关键语义

女性和男性拥有彼此独立的累计值；切换性别时不能延续另一个分区的总分。只输出数据中实际存在的日期。

输出列

gender · day · total

其中 total 是相同性别、日期不晚于当前行的 score_points 之和。

player_nameVARCHAR(20)
genderVARCHAR(1)
dayDATE
score_pointsINT

约束与数据约定

  • (gender, day) 组合唯一；同一性别在同一天至多一条记录。
  • gender 仅取 'F' 或 'M'。
  • score_points 为该选手在对应日期获得的整数分数。
  • 输出必须按 gender、day 均为升序排列。

Editorial

题解：分区窗口中的前缀和

核心洞察

这不是一个全表前缀和，而是两个互不影响的前缀和。窗口函数以 gender 划分分区，在每个分区中以 day 排序，再把窗口帧固定为“分区首行到当前行”。

  1. 分区：相同性别的记录进入同一条时间线。
  2. 排序：每条时间线内部按日期升序。
  3. 累加：对从分区起点到当前行的 score_points 求和。
  4. 展示：最终结果再次按性别、日期排序，保证输出顺序。

一句话模型

PARTITION
→ ORDER
→ FRAME

把数据分成两本账，每本账按日期翻页，每页余额等于此前所有入账之和。

官方可提交语言：MySQL。显式 ROWS 窗口帧让“截至当前行”的语义一目了然。
SELECT
    gender,
    day,
    SUM(score_points) OVER (
        PARTITION BY gender
        ORDER BY day
        ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
    ) AS total
FROM Scores
ORDER BY gender ASC, day ASC;
本地语义参考，不能提交到数据库题判题器；输入视为内存行列表。
import java.time.LocalDate;
import java.util.*;

class Solution {
    record Score(String playerName, char gender,
                 LocalDate day, int scorePoints) {}
    record Result(char gender, LocalDate day, long total) {}

    public List<Result> runningTotal(List<Score> scores) {
        List<Score> ordered = new ArrayList<>(scores);
        ordered.sort(Comparator.comparing(Score::gender)
            .thenComparing(Score::day));

        List<Result> answer = new ArrayList<>();
        Character currentGender = null;
        long total = 0;
        for (Score row : ordered) {
            if (currentGender == null || currentGender != row.gender()) {
                currentGender = row.gender();
                total = 0;
            }
            total += row.scorePoints();
            answer.add(new Result(row.gender(), row.day(), total));
        }
        return answer;
    }
}

function runningTotal(scores) {
  const ordered = [...scores].sort((a, b) =>
    a.gender.localeCompare(b.gender) ||
    a.day.localeCompare(b.day)
  );

  let currentGender = null;
  let total = 0;
  return ordered.map((row) => {
    if (row.gender !== currentGender) {
      currentGender = row.gender;
      total = 0;
    }
    total += row.score_points;
    return { gender: row.gender, day: row.day, total };
  });
}

from typing import TypedDict

class Score(TypedDict):
    player_name: str
    gender: str
    day: str
    score_points: int

def running_total(scores: list[Score]) -> list[dict]:
    ordered = sorted(scores, key=lambda row: (row["gender"], row["day"]))
    answer: list[dict] = []
    current_gender: str | None = None
    total = 0

    for row in ordered:
        if row["gender"] != current_gender:
            current_gender = row["gender"]
            total = 0
        total += row["score_points"]
        answer.append({
            "gender": row["gender"],
            "day": row["day"],
            "total": total,
        })
    return answer

#include <algorithm>
#include <string>
#include <tuple>
#include <vector>
using namespace std;

struct Score {
    string playerName;
    char gender;
    string day;
    int scorePoints;
};

struct Result {
    char gender;
    string day;
    long long total;
};

vector<Result> runningTotal(vector<Score> scores) {
    sort(scores.begin(), scores.end(), [](const Score& a, const Score& b) {
        return tie(a.gender, a.day) < tie(b.gender, b.day);
    });

    vector<Result> answer;
    char currentGender = '\0';
    long long total = 0;
    for (const Score& row : scores) {
        if (row.gender != currentGender) {
            currentGender = row.gender;
            total = 0;
        }
        total += row.scorePoints;
        answer.push_back({row.gender, row.day, total});
    }
    return answer;
}

正确性说明

分区独立性：PARTITION BY gender 保证 F 与 M 的窗口互不包含，因此不会串账。

前缀完整性：在某性别分区内，行按日期升序排列。当前行的窗口从分区第一行开始并包含当前行，恰好覆盖该性别所有日期不晚于当前日期的记录。

结论：窗口中的求和结果正是题目要求的截至当日累计分数；外层排序保证返回顺序满足要求。

复杂度

  • 时间：通常为 O(n log n)，主要来自按分区和日期排序；数据库若能利用合适索引，执行计划可能更优。
  • 空间：概念上 O(n) 用于排序/窗口处理；实际由数据库执行器决定。

边界情况

  • 只有一个性别或只有一行时，累计值就是该行分数。
  • 日期不连续时不补日期，只对已有行累计。
  • 输入物理顺序无关；窗口内和最终输出都显式排序。

替代方案

可用相关子查询：对每行求相同性别且日期不晚于它的总和。表达直观，但朴素执行可能达到 O(n²)，通常不如窗口函数。

常见错误

  • 漏掉 PARTITION BY gender，把两种性别混加。
  • 只写最终 ORDER BY，没有定义窗口内部顺序。
  • 把每天分数当作累计值，或切换分区后没有重置。

面试追问

  • 如果同一性别同一天允许多行，如何先按天聚合？
  • ROWS 与默认的 RANGE 有何差别？
  • 怎样为查询设计索引并阅读执行计划？
+
同日多行扩展

若约束改为同一性别同一天可有多条记录，应先以 GROUP BY gender, day 得到每日合计，再对每日合计做窗口累计，避免输出重复日期。
