给定一个升序正整数数组，最少补入多少个数字，才能让从 1 到目标值的每个整数都能由数组中若干元素之和表示？先理解任务，再亲手推进覆盖边界。

官方题意 交互推演 四语言代码 验证待补

Problem

题目要求

给定一个按升序排列的正整数数组 nums 和正整数 n。可以向数组中补充任意正整数，使区间 [1, n] 内的每个整数，都能够表示为补充后数组中某些元素的和；每个数组元素至多使用一次。

返回满足要求所需补充元素的最少数量。

函数形式： minPatches(nums: integer[], n: integer) -> integer

官方示例

示例 1补 1 个
输入：nums = [1,3], n = 6
输出：1
解释：原数组可表示 1、3、4；
补入 2 后可覆盖 1 到 6。
示例 2补 2 个
输入：nums = [1,5,10], n = 20
输出：2
解释：可以补入 2 和 4。
示例 3无需补充
输入：nums = [1,2,2], n = 5
输出：0

约束

  • 1 <= nums.length <= 1000
  • 1 <= nums[i] <= 104
  • nums 按升序排列
  • 1 <= n <= 231 - 1

Core Insight

核心洞察：只盯住最小缺口

设 miss 是当前无法表示的最小正整数。于是所有小于 miss 的数都已可表示，即连续覆盖区间为 [1, miss - 1]。

若下一个数组元素 x <= miss，把它加入现有任意组合，就能把连续覆盖扩张到 [1, miss + x - 1]，因此令 miss += x。

若 x > miss 或数组已用完，缺口 miss 不可能由后续更大的数填上。此时补入 miss，能把覆盖区间最大化地扩张到 [1, 2 × miss - 1]。

不变量
已覆盖 [1, miss - 1]
使用 x ≤ miss ⇒ miss ← miss + x
补入 miss ⇒ miss ← 2 × miss

Walkthrough

完整过程

  1. 初始化：令 miss = 1、数组指针 i = 0、补丁计数 patches = 0。
  2. 循环条件：只要 miss <= n，说明目标区间内仍有未覆盖数字。
  3. 吸收原元素：若 i < nums.length 且 nums[i] <= miss，令 miss += nums[i] 并右移指针。
  4. 填补缺口：否则补入当前的 miss，令 miss += miss，并增加计数。
  5. 结束：当 miss > n 时，已经覆盖整个 [1, n]，返回补丁数。
以 nums = [1,5,10], n = 20 为例：吸收 1 后覆盖到 1；补 2 后覆盖到 3；补 4 后覆盖到 7；再吸收 5 和 10，最终覆盖到 22，共补 2 个。

Correctness

正确性证明

覆盖不变量：循环开始时，[1, miss - 1] 内所有整数均可表示。初始 miss = 1 时区间为空，不变量成立。

吸收原元素保持不变量：若 x <= miss，原覆盖区间提供 [0, miss - 1] 的和；加上 x 又提供 [x, x + miss - 1]。因为 x <= miss，两段相接或重叠，所以新区间连续覆盖到 miss + x - 1。

补丁选择是必要且最优的：若下一个原元素大于 miss，所有未使用原元素都不小于它，无法表示 miss，因此至少必须补一个不大于 miss 的数。设补入 y <= miss，新区间最多到 miss + y - 1；选择最大的合法值 y = miss 扩张最远，不会比任何其他选择使用更多补丁。

终止与最优性：每一步都会严格增大 miss，最终超过 n。所有补丁步骤都在不可避免地需要补数时发生，且每次取得最大覆盖，因此返回值为最少补丁数。

Edges & Complexity

边界与复杂度

关键边界

  • nums[0] > 1 时，第一块补丁必然是 1。
  • 原数组已经连续覆盖到 n 时，答案为 0。
  • 数组耗尽后，持续补入 miss，覆盖上界会近似翻倍。
  • n 可达 231 - 1，Java/C++ 的 miss 必须使用 64 位整数。
  • 重复元素完全合法，只要仍满足升序（非严格递增）。

复杂度

设数组长度为 m，补丁数为 p：

时间 O(m + p)
额外空间 O(1)

由于每次补丁至少让覆盖边界翻倍，p = O(log n)。

Alternatives

替代方案与取舍

子集和动态规划：可以维护所有可达和，但 n 高达约 21 亿，时间和空间都不可接受；而且仍需搜索补入哪些数，难以保证最少。

回溯枚举补丁：候选值和组合数量迅速爆炸，只适用于很小的输入，无法利用升序与连续覆盖结构。

贪心的优势：只维护一个覆盖边界，无需显式记录每个子集和；升序数组保证一旦下一个元素越过缺口，后面所有元素也都无法填补它。

Java 
class Solution {
    public int minPatches(int[] nums, int n) {
        long miss = 1;
        int index = 0;
        int patches = 0;

        while (miss <= n) {
            if (index < nums.length && nums[index] <= miss) {
                miss += nums[index];
                index++;
            } else {
                miss += miss;
                patches++;
            }
        }
        return patches;
    }
}

#include <vector>
using namespace std;

class Solution {
public:
    int minPatches(vector<int>& nums, int n) {
        long long miss = 1;
        int index = 0;
        int patches = 0;

        while (miss <= n) {
            if (index < static_cast<int>(nums.size()) &&
                nums[index] <= miss) {
                miss += nums[index];
                index++;
            } else {
                miss += miss;
                patches++;
            }
        }
        return patches;
    }
};

Interview Follow-ups

面试追问

为什么数组必须升序？

升序让我们能断定：若当前元素已大于缺口，后面元素更不可能填补缺口。若无序，可先排序，代价变为 O(m log m)。

如果元素可以重复使用？

问题会变为完全背包式可达性，当前“每个元素至多一次”的连续覆盖扩张公式不再直接适用。

能否返回具体补丁？

可以在补丁分支把当前 miss 追加到结果列表，计数逻辑不变，额外空间为 O(p)。

Pitfalls

常见错误

  • 把 miss 理解为“已覆盖上界”，导致 +1 的边界错误；它应是首个未覆盖值。
  • 判断写成 nums[i] < miss，遗漏元素恰好等于缺口时可直接吸收的情况。
  • 补入 miss - 1 或下一个数组元素；这不能保证最大化新的连续覆盖。
  • Java/C++ 使用 32 位变量保存 miss，在翻倍越过整数上限时溢出。
  • 循环条件写成 miss < n，从而漏掉目标值 n 本身。
