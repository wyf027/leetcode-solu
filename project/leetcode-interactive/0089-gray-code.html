One-bit relay protocol

格雷
编码

让所有 n 位状态排成一个闭环。每次只拨动一个开关，却要不重复地走遍每个状态，最终还要安全回到起点。

Relay specification

状态数量

2n

Mission brief

题意

给定整数 n，返回任意一个有效的 n 位格雷编码序列。序列要包含从 0 到 2n−1 的每个整数且不重复；首项必须是 0；任意相邻两项，以及末项与首项的二进制表示，都必须恰好只差一位。

  • 1 ≤ n ≤ 16
  • sequence.length = 2ⁿ
  • 0 ≤ sequence[i] < 2ⁿ

Core insight

核心洞察

按普通二进制顺序枚举 i，把它与右移一位后的自己异或： g(i) = i ^ (i >> 1)。 连续整数进位时会翻转一段后缀；右移后异或会抵消这段连锁变化，只留下一个变化位。

i = 6

i110 i >> 1011 XOR101 = 5

Full process

完整过程

  1. 01 准备长度为 2n 的答案，令 i 从 0 开始。
  2. 02 计算 i ^ (i >> 1)，把结果追加到答案。
  3. 03 重复直到 i = 2n−1；枚举顺序天然不重复且覆盖全部状态。
  4. 04 首项为 0，末项为最高位的 1，因此首尾也只差一位。

边界与正确性

  • n = 1：得到 [0,1]，相邻和首尾都合法。
  • n = 16：生成 65,536 个整数；32 位整数足够容纳位移与结果。
  • 唯一性：格雷变换可逆，所以不同的 i 不会映射到同一编码。
  • 闭环：最后一项等于 1 左移 n−1 位，与 0 只差最高位。

复杂度

时间

O(2ⁿ)

必须输出 2ⁿ 项

额外空间

O(1)

不计返回数组

替代方案取舍

镜像反射构造：从 [0] 开始，每增加一位就反向复制旧序列并加上新高位。直观、适合推导，但需要围绕已有结果做分轮扩展。

回溯搜索：把每个数看成超立方体节点，寻找哈密顿环。能验证定义，却需要 visited 集合与搜索控制，面试中远不如闭式位运算稳定。

推荐闭式公式：代码最短、证明清晰、常数小，也直接体现格雷码与二进制的关系。

面试追问

为什么结果不会重复？
格雷变换有逆变换；若两个结果相同，逆变换后对应的 i 也必然相同。
如何从格雷码还原二进制？
不断把当前格雷值右移并累积异或，直到值变为 0。
若要求从指定 start 开始？
先生成完整环，找到 start 的位置，再循环旋转序列即可。

常见错误

漏掉括号：1 << n 应明确作为循环上界，避免优先级误读。

只查相邻：题目还要求最后一项与第一项只差一位。

复杂度写 O(n)：输出本身有 2n 项，因此时间下界就是 O(2n)。

class Solution {
    public List<Integer> grayCode(int n) {
        List<Integer> answer = new ArrayList<>();
        int total = 1 << n;

        for (int i = 0; i < total; i++) {
            answer.add(i ^ (i >> 1));
        }
        return answer;
    }
}
