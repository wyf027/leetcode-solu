查询具有最多共同关注者的
所有两两结对组

All the Pairs With the Maximum Number of Common Followers

先读关系、预测用户对，再探索共同关注者如何累积。

01 / 题意

寻找全部并列最多的用户对

给定表 Relations。一行 (user_id, follower_id) 表示后者关注前者。请找出共同关注者数量达到全局最大值的所有用户对，结果仅包含 user1_id 和 user2_id，且前者小于后者。结果行顺序不限。

列类型含义
user_idint被关注的用户
follower_idint关注者

约束与数据语义

  • 联合主键为 (user_id, follower_id)，相同关系不会重复。
  • 每位用户可以有多个关注者，每位关注者也可以关注多个用户。
  • 没有被关注记录的用户，其关注者集合为空。
  • 公开题面未列出行数、ID 数值范围或保证存在共同关注者的条件；不补造约束。

官方元数据题面和代码签名为空。以下使用官方元数据中的表结构、示例输入，并参考公开题面简要转述；这是数据库查询题。

05 / 独立题解

准备好后，再查看推导

相同关注者，连接两条关系

若 (u,f) 和 (v,f) 都存在，f 就是 u、v 的一个共同关注者。按 follower_id 自连接，再按用户对分组计数，就把集合交集大小变成了 SQL 聚合。

完整过程

  1. 合并两列 ID，得到表中可识别的用户全集。
  2. 自连接 Relations，要求关注者相同、左侧 user_id 小于右侧 user_id。
  3. 按用户对分组，COUNT(*) 得到共同关注者数。
  4. 生成已知用户的全部规范对，左连接计数，缺失值用 0 补齐。
  5. 保留计数等于全局 MAX 的全部用户对。
为何补齐零值？常见简洁查询直接在正计数的自连接结果中取最大值；只要最大值大于 0，它与本页结果一致。公开题面未明确最大值为 0 时的用户全集，本页选择两列出现过的 ID 作为全集并补齐零计数。若有独立 Users 表，应以它为准；关系表无法恢复从未出现过的用户。

正确性

对于任意规范用户对 (u,v) 和共同关注者 f，联合主键保证 (u,f)、(v,f) 各唯一，自连接恰好产生一行。反之，每个匹配行都证明 f 同时关注 u、v。因此分组计数精确等于共同关注者数量。补齐候选对只引入真实的零计数对。最终等于 MAX 的筛选既保留所有并列最大者，又排除所有较小计数。

边界与复杂度

没有可配对的用户时返回空表；并列最大时全部返回；没有共同关注者时按上述已知用户全集语义处理。输出不包含计数列，行顺序不限。

设 N 为关系数、U 为已知用户数、df 为关注者 f 关注的用户数，J = Σ C(df,2)，P = C(U,2)。在合适索引或哈希连接下，SQL 的逻辑工作量约 O(N + J + P)，J 最坏 O(N²)。聚合、候选对及输入的空间规模约 O(N + P)，若物化匹配行可能再需要 O(J)。实际耗时还取决于数据库排序、索引与执行计划。

四语言参考使用集合交集，期望时间上界为 O(N + U log U + U² + UN)；辅助存储 O(N + U)，结果最坏 O(U²)。Python 求交集另有最多 O(N) 临时空间。这些参考与 SQL 语义一致，执行机制不同。

常见错误

  • 按 user_id 相等连接：算成了共同关注的人，方向反了。
  • 仅限制 !=：会重复返回反向用户对；应使用 <。
  • LIMIT 1 或 ROW_NUMBER() = 1：会丢失并列第一。
  • 在来源没有主键保证时直接计数：重复关系会放大数量，应先去重。
  • 只处理有匹配的用户对，却没有说明最大值为 0 时的语义。

替代方案与面试追问

可对 scores 使用 DENSE_RANK() OVER (ORDER BY cnt DESC)，再筛选排名 1。若保证最大值为正，可以只用 common CTE，省去零计数候选对。大表可考虑 (follower_id,user_id) 复合索引，但热门关注者带来的大量真实配对无法靠索引消除。

追问：如何返回前 K 个计数档位？一条关注关系新增或删除时，哪些用户对受影响？如何处理重复事件？若最大值为 0 且用户很多，如何分页输出所有用户对？

MySQL 8+ · 数据库主解

WITH users AS (
    SELECT user_id AS id FROM Relations
    UNION
    SELECT follower_id AS id FROM Relations
), common AS (
    SELECT a.user_id AS user1_id, b.user_id AS user2_id,
           COUNT(*) AS cnt
    FROM Relations a
    JOIN Relations b ON a.follower_id = b.follower_id
                    AND a.user_id < b.user_id
    GROUP BY a.user_id, b.user_id
), scores AS (
    SELECT a.id AS user1_id, b.id AS user2_id,
           COALESCE(c.cnt, 0) AS cnt
    FROM users a JOIN users b ON a.id < b.id
    LEFT JOIN common c ON c.user1_id = a.id AND c.user2_id = b.id
)
SELECT user1_id, user2_id
FROM scores
WHERE cnt = (SELECT MAX(cnt) FROM scores);

Java · 本地语义参考

import java.util.*;

class Solution {
    public List<List<Integer>> findPairs(int[][] relations) {
        Map<Integer, Set<Integer>> followers = new TreeMap<>();
        for (int[] row : relations) {
            followers.computeIfAbsent(row[0], k -> new HashSet<>()).add(row[1]);
            followers.computeIfAbsent(row[1], k -> new HashSet<>());
        }
        List<Integer> users = new ArrayList<>(followers.keySet());
        List<List<Integer>> result = new ArrayList<>();
        int best = -1;
        for (int i = 0; i < users.size(); i++) {
            for (int j = i + 1; j < users.size(); j++) {
                int u = users.get(i), v = users.get(j), count = 0;
                for (int f : followers.get(u)) {
                    if (followers.get(v).contains(f)) count++;
                }
                if (count > best) { best = count; result.clear(); }
                if (count == best) result.add(Arrays.asList(u, v));
            }
        }
        return result;
    }
}

JavaScript · 本地语义参考

function findPairs(relations) {
  const followers = new Map();
  for (const [u, f] of relations) {
    if (!followers.has(u)) followers.set(u, new Set());
    if (!followers.has(f)) followers.set(f, new Set());
    followers.get(u).add(f);
  }
  const users = [...followers.keys()].sort((a, b) => a - b);
  let best = -1;
  const result = [];
  for (let i = 0; i < users.length; i++) {
    for (let j = i + 1; j < users.length; j++) {
      const u = users[i], v = users[j];
      let count = 0;
      for (const f of followers.get(u)) {
        if (followers.get(v).has(f)) count++;
      }
      if (count > best) { best = count; result.length = 0; }
      if (count === best) result.push([u, v]);
    }
  }
  return result;
}

Python · 本地语义参考

def find_pairs(relations):
    followers = {}
    for user, follower in relations:
        followers.setdefault(user, set()).add(follower)
        followers.setdefault(follower, set())
    users = sorted(followers)
    best, result = -1, []
    for i, user in enumerate(users):
        for other in users[i + 1:]:
            count = len(followers[user] & followers[other])
            if count > best:
                best, result = count, []
            if count == best:
                result.append([user, other])
    return result

C++17 · 本地语义参考

#include <map>
#include <unordered_set>
#include <vector>
using namespace std;

class Solution {
public:
    vector<vector<int>> findPairs(const vector<vector<int>>& relations) {
        map<int, unordered_set<int>> followers;
        for (const auto& row : relations) {
            followers[row[0]].insert(row[1]);
            followers.try_emplace(row[1]);
        }
        vector<int> users;
        for (const auto& entry : followers) users.push_back(entry.first);
        int best = -1;
        vector<vector<int>> result;
        for (size_t i = 0; i < users.size(); ++i) {
            for (size_t j = i + 1; j < users.size(); ++j) {
                int u = users[i], v = users[j], count = 0;
                for (int f : followers.at(u))
                    if (followers.at(v).count(f)) ++count;
                if (count > best) { best = count; result.clear(); }
                if (count == best) result.push_back({u, v});
            }
        }
        return result;
    }
};
