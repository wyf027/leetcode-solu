One base. Up to two of each topping.

最接近目标价格的
甜点成本

Closest Dessert Cost

目标不是“越贵越好”，而是在价格轴上找到离 target 最近的甜点；距离相同时选择更便宜的那份。

阅读题目 打开甜点枚举器

Problem

题意

你有 n 种冰激凌基料和 m 种配料。制作一份甜点时，必须且只能选择一种基料；每种配料可以选择 0、1 或 2 份。甜点总成本等于基料成本与全部配料成本之和。

给定整数数组 baseCosts、toppingCosts 和目标价格 target，返回与目标价格差的绝对值最小的可行总成本。如果多个总成本同样接近，返回其中较小者。

函数参数

  • baseCosts: integer[]：每种基料的价格。
  • toppingCosts: integer[]：每份配料的价格。
  • target: integer：目标价格。

返回值

integer：最接近 target 的可行甜点成本；平局时取较低成本。

Examples

官方示例

示例 1

输入：baseCosts = [1,7], toppingCosts = [3,4], target = 10
输出：10
解释：选择成本 7 的基料和 1 份成本 3 的配料，
总成本 7 + 3 = 10。

示例 2

输入：baseCosts = [2,3], toppingCosts = [4,5,100], target = 18
输出：17
解释：3 + 1×4 + 2×5 + 0×100 = 17，
且无法得到总成本 18。

示例 3

输入：baseCosts = [3,10], toppingCosts = [2,5], target = 9
输出：8
解释：成本 8 和 10 都与 9 相差 1，
因此返回较低的 8。

示例 4

输入：baseCosts = [10], toppingCosts = [1], target = 1
输出：10
解释：可以不添加配料，但必须选择一种基料。

Constraints

约束

  • n == baseCosts.length，m == toppingCosts.length
  • 1 <= n, m <= 10
  • 1 <= baseCosts[i], toppingCosts[i] <= 10^4
  • 1 <= target <= 10^4

    Solution

    完整题解

    先独立思考，再按需展开。

    核心洞察

    每种配料只有 3 个选择：0、1、2 份。因为 m <= 10，所有配料组合最多只有 3^10 = 59049 个；再分别搭配至多 10 种基料，直接枚举完全可行。用一次深度优先搜索逐层决定每种配料的份数，到叶子时比较总成本即可。

    比较候选值 cost 与当前答案 best 时，先比较 |cost - target|；若距离相同，再比较成本本身，较小者胜出。这一比较器把题目的平局规则完整编码进去。

    完整过程

    1. 令 best 为任意合法初值，例如第一种基料成本。
    2. 对每个基料成本，调用 DFS，从第 0 种配料开始处理。
    3. 在第 i 层，递归尝试加入 0、1、2 份 toppingCosts[i]。
    4. 处理完全部配料后得到一个合法总成本，按“距离优先、成本次之”的规则更新 best。
    5. 所有基料及其配料组合枚举结束后返回 best。

    正确性证明

    完备性：外层循环遍历每一种基料。对固定基料，DFS 的第 i 层恰好尝试第 i 种配料的全部合法份数 0、1、2，因此从根到叶的每条路径与一个合法配料组合一一对应。故每个合法甜点都会被枚举，且不会漏掉。

    最优性：每到一个叶子，比较器都会在“与目标的距离更小”或“距离相同但成本更低”时更新答案。因此处理任意数量候选后，best 都是已处理候选中的题意最优值。由完备性，结束时已处理全部合法甜点，所以返回值就是全局最优答案。

    边界情况

    • 可以完全不加配料，基料本身也是合法候选。
    • 所有基料都超过目标时，仍需选一种基料，答案通常是最小基料成本。
    • 候选分列目标两侧且等距时，必须返回较小成本。
    • 不同组合得到相同总成本不影响结果。
    • 成本可超过目标，不能只保留不超过目标的方案。

    复杂度

    设基料数为 n、配料种类数为 m。

    • 时间复杂度：O(n × 3^m)。
    • 递归栈空间：O(m)。
    • 除递归栈外只维护常数个变量。

    替代方案

    方案思路取舍
    集合 DP从所有基料成本出发，针对每种配料把现有成本扩展为加 0 / 1 / 2 份。思路直观，但集合可能存很多重复值，需要额外空间。
    位集 / 背包将每种配料复制两次，用可达成本位集推进。当成本上界可控时很快；需要谨慎确定搜索上界。
    折半枚举把配料分两半，各自产生和并排序，再二分靠近目标。适合配料种类更大时；本题规模下实现复杂度不划算。

    面试追问

    • 能否剪枝？ 所有成本均为正数。当当前成本已经大于目标且不可能通过后续选择降低时，可以记录当前候选后停止向更贵分支深入；不过要确保仍正确处理目标上方最接近值。
    • 为什么不能遇到超过 target 就全部丢弃？ 最优答案可能在目标上方，例如所有基料都大于目标。
    • 若每种配料最多选 k 份？ DFS 的分支数改为 k + 1，时间复杂度变为 O(n × (k+1)^m)。
    • 如何复原配方？ 更新 best 时一并复制当前基料编号和配料份数路径。

    常见错误

    • 把每种配料误写成最多只能选 1 份，遗漏份数 2。
    • 平局时仍保留先遇到的答案，没有显式比较较小成本。
    • 只枚举配料，忘记每份甜点必须恰好选择一种基料。
    • 错误剪掉全部大于 target 的候选。
    • 使用全局答案但在多个基料之间错误重置。

    四语言完整代码

    Java

    class Solution {
    private int target;
    private int best;

    public int closestCost(int[] baseCosts, int[] toppingCosts, int target) {
        this.target = target;
        this.best = baseCosts[0];
        for (int base : baseCosts) {
            dfs(toppingCosts, 0, base);
        }
        return best;
    }

    private void dfs(int[] toppings, int index, int cost) {
        if (index == toppings.length) {
            if (isBetter(cost, best)) best = cost;
            return;
        }
        dfs(toppings, index + 1, cost);
        dfs(toppings, index + 1, cost + toppings[index]);
        dfs(toppings, index + 1, cost + 2 * toppings[index]);
    }

    private boolean isBetter(int candidate, int current) {
        int a = Math.abs(candidate - target);
        int b = Math.abs(current - target);
        return a < b || (a == b && candidate < current);
    }
}

    /**
 * @param {number[]} baseCosts
 * @param {number[]} toppingCosts
 * @param {number} target
 * @return {number}
 */
var closestCost = function(baseCosts, toppingCosts, target) {
    let best = baseCosts[0];

    const isBetter = (candidate, current) => {
        const a = Math.abs(candidate - target);
        const b = Math.abs(current - target);
        return a < b || (a === b && candidate < current);
    };

    const dfs = (index, cost) => {
        if (index === toppingCosts.length) {
            if (isBetter(cost, best)) best = cost;
            return;
        }
        dfs(index + 1, cost);
        dfs(index + 1, cost + toppingCosts[index]);
        dfs(index + 1, cost + 2 * toppingCosts[index]);
    };

    for (const base of baseCosts) dfs(0, base);
    return best;
};
