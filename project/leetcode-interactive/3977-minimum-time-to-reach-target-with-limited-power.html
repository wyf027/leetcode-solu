有限电量到达目标节点的最少时间

信号离开节点 u 时才消耗 cost[u] 电量。 在同一到达时间下，保留电量更大的状态永远不差：用 Dijkstra 按 (time ASC, remainingPower DESC) 排序即可同时得到两项答案。

输入

n 个节点、定向边 edges[i] = [u,v,t]、初始 power、离开费用 cost，以及 source / target。

主线

状态是 (node, time, remainingPower)；每个节点只保留已知最短时间中最大的剩余电量。

题意、示例与约束

给定起止时刻，返回从起点到终点实际经过的秒数。端点相同的答案为 0；题目保证不跨日、也不需要考虑时区或日期。

示例 1

startTime = "01:00:00"

endTime = "01:00:25"

输出：25，终点比起点晚 25 秒。

示例 2

startTime = "12:34:56"

endTime = "13:00:00"

输出：1504，即 25 分 4 秒。

约束：两个字符串长度均为 8；00 ≤ HH ≤ 23，00 ≤ MM, SS ≤ 59；endTime 不早于 startTime。

题解（默认收起）

首屏保留题意与实验；需要时再展开完整推导和代码。

核心洞察：时、分、秒不是三个需要借位的独立答案；它们是同一计数单位的不同位。用秒作为基准单位，格式字符串立即变成一个整数坐标。

完整过程

  1. 按固定位置读取 s[0..1]、s[3..4]、s[6..7]，或以 : 分割。
  2. 计算 hour × 3600 + minute × 60 + second，得到从 00:00:00 起的总秒数。
  3. 结束总秒数减起始总秒数，即为经过秒数。

边界

相同时间返回 0；整点、跨分钟、跨小时无需单独借位。题目保证格式合法且不跨日；若产品需求允许跨日，应额外加一天的 86400 秒。

复杂度

每个字符串长度固定为 8，解析与运算都是 O(1) 时间、O(1) 额外空间。

替代方案、面试追问与常见错误

替代方案：逐秒模拟直观但不必要，复杂度会变成 O(answer)。追问：若包含日期或时区，先把日期时间规范化到统一时间线。常见错误：漏乘 3600，把分钟误乘 3600，或用字符串字典序直接相减。
