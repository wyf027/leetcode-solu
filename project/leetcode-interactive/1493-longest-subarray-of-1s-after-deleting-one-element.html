全为 1 的最长子数组

Solution

滑动窗口：窗口内至多一个 0

核心洞察：删除一个元素后能连成全 1 的候选区间，在原数组中必然对应一个“至多包含一个 0”的窗口。窗口长度为 right - left + 1，删去那个 0；若没有 0，也仍须删掉一个 1，所以有效长度统一是 right - left。

完整过程

  1. 令左右边界 left = 0，让 right 从左到右扫描，并记录窗口内 0 的数量。
  2. 新元素进入窗口；若它是 0，就将计数加一。
  3. 当窗口中出现两个 0 时，不断右移 left，并在移出 0 时减少计数，直到窗口重新合法。
  4. 每次窗口合法后，用 right - left 更新答案。这个减一同时覆盖“删 0”和“全 1 时删 1”两种情况。

正确性证明

不漏解

任意可行答案对应原数组中的一段连续区间：其中若有 0，删除它后全为 1；若没有 0，就删除一个 1。因此该区间至多含一个 0，必会成为算法扫描到的合法窗口。

不会高估

算法维护的每个窗口至多含一个 0。删去该 0，或在全 1 窗口中删去任意一个 1，都能得到长度恰为 窗口长度 - 1 的全 1 子数组。因此每个候选值都可实现。

算法覆盖全部可行解，且记录的每个候选都真实可行，所以最终最大值就是正确答案。

边界情况

全是 1

必须删除一个 1，答案为 n - 1。

全是 0

不存在非空全 1 子数组，答案为 0。

只有一个元素

删掉后为空；公式自然给出 0。

多个 0

窗口遇到第二个 0 后收缩，保留至多一个 0。

复杂度

时间 O(n)额外空间 O(1)

class Solution {
    public int longestSubarray(int[] nums) {
        int left = 0;
        int zeros = 0;
        int answer = 0;

        for (int right = 0; right < nums.length; right++) {
            if (nums[right] == 0) zeros++;

            while (zeros > 1) {
                if (nums[left] == 0) zeros--;
                left++;
            }

            answer = Math.max(answer, right - left);
        }
        return answer;
    }
}

替代方案

前后缀连续 1 计数：对每个 0，计算其左侧连续 1 数量与右侧连续 1 数量之和，并额外处理全 1 数组。这个方案同样是 O(n)，但通常需要额外数组或更细的状态管理。

动态规划：维护“尚未删除”和“已经删除”两类以当前位置结尾的最长长度，也能做到 O(n) 时间、O(1) 空间，但状态转移不如滑动窗口直观。

面试追问

如果改成“最多删除一个元素”呢？

全 1 数组不必强制减一。可以区分窗口是否真的包含 0：含 0 时长度减一，不含 0 时保留完整窗口。

如果允许删除最多 k 个 0 呢？

把窗口约束改为“0 的数量不超过 k”。若删除仅针对 0，候选全 1 长度为窗口长度减去窗口内 0 的数量；具体公式还取决于是否必须恰好删除 k 个元素。

为什么不是记录 right - left + 1？

因为题目要求必须删除一个元素。合法窗口对应的是删除前的区间，删除后的有效长度必然少一。

常见错误

  • 把“必须删一个”误读成“可以删一个”，导致全 1 数组返回 n。
  • 窗口出现第二个 0 时只移动一次左边界，而不是持续移动到重新合法。
  • 更新答案时使用 right - left + 1，忘记扣除被删除的元素。
  • 只枚举 0，遗漏长度为 1 或全 1 等边界情况。
