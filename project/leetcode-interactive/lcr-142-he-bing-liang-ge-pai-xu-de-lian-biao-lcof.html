训练计划 IV

合并两个升序链表，产出同样按升序排列的新链表。先观察、再操作；首屏不直接给出解法。

题意

给定两个按升序排列的链表 l1 和 l2，将它们合并为一个新的升序链表并返回。新链表由全部节点组成。

Easy

示例 1

输入：l1 = [1,2,4], l2 = [1,3,4]
输出：[1,1,2,3,4,4]

示例 2

输入：l1 = [], l2 = []
输出：[]

约束

两个链表节点数均为 0 到 50；节点值为 -100 到 100；输入链表按非递减顺序排列。

分步互动

依次展开提示，自己决定下一次应连接哪个节点。

第 1 / 3 步

l1: 1 → 2 → 4l2: 1 → 3 → 4

先只看两个当前节点

两个候选值都是 1。任选一个都能保持有序；接入后只需让对应指针前移。

重复同一局部判断

接入一个 1 后，比较新的两个当前节点。结果尾部连接较小节点，并只推进它来源的指针。

其中一个链表耗尽时

另一条链表的剩余部分已经有序，可以整体接到结果尾部，不必逐个比较。

题解

默认收起，完成自己的推演后再展开。

核心洞察

下一个结果节点只可能是两个当前节点中较小者。虚拟头保存结果起点，尾指针持续追加。

过程

  1. 创建虚拟头节点与尾指针。
  2. 两条链表均未结束时，连接较小节点并推进其指针。
  3. 将未耗尽链表的剩余部分接到尾部。
  4. 返回虚拟头的下一节点。

边界

  • 两条链表都为空。
  • 只有一条链表为空。
  • 节点值相等。
  • 一侧先耗尽。

复杂度

时间 O(m + n)：每个节点最多处理一次。额外空间 O(1)：迭代方式只使用常量辅助指针。

替代方案与追问

递归写法更短，但使用 O(m+n) 调用栈空间。追问：要求稳定合并时，相等节点应优先选择哪条链表？链表很长时为什么更推荐迭代？

常见错误

  • 忘记连接剩余链表。
  • 连接后没有推进对应指针，造成死循环。
  • 返回虚拟头节点本身，而不是它的 next。
  • 错误丢失原节点链接。

参考实现

Java 
class Solution {
    public ListNode trainningPlan(ListNode l1, ListNode l2) {
        ListNode dummy = new ListNode(0), tail = dummy;
        while (l1 != null && l2 != null) {
            if (l1.val <= l2.val) { tail.next = l1; l1 = l1.next; } else { tail.next = l2; l2 = l2.next; }
            tail = tail.next;
        }
        tail.next = l1 != null ? l1 : l2;
        return dummy.next;
    }
}

class Solution {

    ListNode* trainningPlan(ListNode* l1, ListNode* l2) {
        ListNode dummy(0), *tail = &dummy;
        while (l1 && l2) { if (l1->val <= l2->val) { tail->next = l1; l1 = l1->next; } else { tail->next = l2; l2 = l2->next; } tail = tail->next; }
