第一个唯一数字First Unique Number

维护一条不断增长的整数流，并随时回答：按进入顺序看，最早只出现过一次的数字是谁？这是一道把“查询快”和“更新快”同时纳入设计的数据结构题。

Problem

题意与接口

请设计 FirstUnique 类。构造时接收初始整数序列；之后可以追加数字，并查询当前数据流中最先出现的唯一数字。若不存在，返回 -1。

“第一个”由进入数据流的先后顺序决定；“唯一”表示截至当前仅出现一次。每次调用都基于全部历史数据。
FirstUnique(int[] nums) int showFirstUnique() void add(int value)

约束

  • 1 ≤ nums.length ≤ 10⁵
  • 1 ≤ nums[i], value ≤ 10⁸
  • add 与 showFirstUnique 总调用次数不超过 5 × 10⁴

Solution vault

准备好再揭晓题解

先独立思考怎样同时保证追加与查询足够快。展开后可查看完整论证、四语言代码和面试延伸。

核心洞察

哈希表擅长回答“出现了几次”，队列擅长保存“谁先到”。将二者组合：每次追加都更新计数并入队；每次查询只清理队首中计数大于 1 的项，清理结束后，队首就是答案。

完整过程

  1. 构造器对初始数组逐个调用 add。
  2. add(value)：计数加一，并把值压入队尾。
  3. showFirstUnique()：当队首计数大于 1 时持续出队。
  4. 队列非空则返回队首，否则返回 -1。

正确性说明

  1. 计数表在每次到达时恰好增加一次，因此始终等于该数字在完整数据流中的出现次数。
  2. 队列按到达顺序保存记录；查询移除的队首均有计数大于 1，不可能成为唯一数字。
  3. 清理停止时，若队列非空，其队首计数为 1；更早的记录均已被证明重复，所以它正是第一个唯一数字。
  4. 若队列为空，所有到达记录都对应重复数字，因此返回 -1 正确。

复杂度与边界

add 为 O(1)。单次查询最坏 O(n)，但每个队列项最多出队一次，所以整个调用序列的均摊时间为 O(1)/次。空间为 O(n)。

重点边界：初始序列全部重复、唯一数在重复项之后、追加使当前答案失效、清理后队列为空，以及同一值多次重复。

替代方案

也可用“哈希表 + 双向链表”：链表只保存当前唯一值，第二次出现时 O(1) 删除节点，查询直接读表头。它避免队列中的旧记录，但实现更复杂，需要维护节点引用。

常见错误

  • 每次查询都扫描完整历史，导致总时间退化为 O(nq)。
  • 只用集合，丢失出现次数或到达顺序。
  • 只检查队首一次；连续多个重复项时必须循环清理。
  • 把队列中存在重复项误解为错误；惰性删除允许旧记录暂存。

四语言完整实现

Java · HashMap + ArrayDeque
class FirstUnique {
    private final Map<Integer, Integer> frequency = new HashMap<>();
    private final Queue<Integer> queue = new ArrayDeque<>();

    public FirstUnique(int[] nums) {
        for (int num : nums) {
            add(num);
        }
    }

    public int showFirstUnique() {
        while (!queue.isEmpty() && frequency.get(queue.peek()) > 1) {
            queue.poll();
        }
        return queue.isEmpty() ? -1 : queue.peek();
    }

    public void add(int value) {
        frequency.put(value, frequency.getOrDefault(value, 0) + 1);
        queue.offer(value);
    }
}
JavaScript · Map + 数组头指针
var FirstUnique = function(nums) {
    this.frequency = new Map();
    this.queue = [];
    this.head = 0;
    for (const num of nums) {
        this.add(num);
    }
};

FirstUnique.prototype.showFirstUnique = function() {
    while (
        this.head < this.queue.length &&
        this.frequency.get(this.queue[this.head]) > 1
    ) {
        this.head += 1;
    }
    return this.head < this.queue.length ? this.queue[this.head] : -1;
};

FirstUnique.prototype.add = function(value) {
    this.frequency.set(value, (this.frequency.get(value) || 0) + 1);
    this.queue.push(value);
};
Python · Counter + deque
from collections import Counter, deque
from typing import List


class FirstUnique:
    def __init__(self, nums: List[int]):
        self.frequency = Counter()
        self.queue = deque()
        for num in nums:
            self.add(num)

    def showFirstUnique(self) -> int:
        while self.queue and self.frequency[self.queue[0]] > 1:
            self.queue.popleft()
        return self.queue[0] if self.queue else -1

    def add(self, value: int) -> None:
        self.frequency[value] += 1
        self.queue.append(value)
C++ · unordered_map + queue
class FirstUnique {
private:
    unordered_map<int, int> frequency;
    queue<int> candidates;

public:
    FirstUnique(vector<int>& nums) {
        for (int num : nums) {
            add(num);
        }
    }

    int showFirstUnique() {
        while (!candidates.empty() &&
               frequency[candidates.front()] > 1) {
            candidates.pop();
        }
        return candidates.empty() ? -1 : candidates.front();
    }

    void add(int value) {
        ++frequency[value];
        candidates.push(value);
    }
};

面试追问

为什么单次查询最坏 O(n)，仍能说均摊 O(1)？

因为每个入队项只可能被移除一次。把所有清理成本分摊到对应的入队操作上，总清理次数不超过总入队次数。

如果必须保证每次查询严格 O(1) 呢？

使用哈希表配合双向链表，只把当前唯一值留在链表中；第二次出现时通过节点引用直接删除，查询读取链表头。

如果数据来自并发流怎么办？

需要让计数更新、入队和队首清理具备一致的同步边界；也可让单一消费者串行处理事件，通过消息队列保证顺序。
