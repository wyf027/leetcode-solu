01 · Problem

题目要求

给你一个由 n 个数对组成的数组 pairs，其中 pairs[i] = [leftᵢ, rightᵢ]，并且每个数对都满足 leftᵢ < rightᵢ。

跟随规则：若 p₁ = [a,b]、p₂ = [c,d]，只有当 b < c 时，p₂ 才能跟在 p₁ 后面。

你可以按任意顺序选择部分数对，不要求全部使用。请返回能形成的最长数对链的长度。

约束

  • n == pairs.length
  • 1 ≤ n ≤ 1000
  • -1000 ≤ leftᵢ < rightᵢ ≤ 1000

函数签名：findLongestChain(pairs) → integer

示例 1

输入pairs = [[1,2],[2,3],[3,4]] 输出2 解释最长链为 [1,2] → [3,4]。

示例 2

输入pairs = [[1,2],[7,8],[4,5]] 输出3 解释最长链为 [1,2] → [4,5] → [7,8]。

Solution Unlocked

贪心：尽早结束，给后面留空间

核心洞察

在当前能选的数对中，右端点越小，对后续数对的限制越弱。因此按右端点升序扫描，遇到左端点严格大于当前链尾的数对就选入。

完整过程

  1. 排序
    把所有数对按右端点从小到大排列。右端点相同的先后顺序不影响答案。
  2. 维护链尾
    令 chainEnd = -∞，答案 count = 0。
  3. 依次判断
    若当前数对 [left,right] 满足 left > chainEnd，选入它，并更新 chainEnd = right、count++。
  4. 返回答案
    扫描结束时，count 就是最长数对链长度。

为什么正确？

交换论证：设某个最优解选择的第一个数对为 x，贪心选择右端点最小的数对 g。必有 g.right ≤ x.right。

把最优解中的 x 换成 g，原来能接在 x 后的下一对，其左端点也一定严格大于 g.right，所以剩余链仍然合法且长度不变。

于是总存在一个以贪心选择开头的最优解。对剩余数对重复同样论证，最终贪心链必为最长链。

时间
O(n log n)
排序主导
空间
O(log n)
取决于排序实现

边界情况

  • 只有一个数对时答案为 1。
  • 端点相等不能连接：条件是 b < c，不是 b ≤ c。
  • 负数端点不影响排序与比较；初始链尾必须是真正的负无穷或足够小的值。
  • 输入顺序任意，不能直接按原顺序扫描。

替代方案：动态规划

也可按左端点排序，令 dp[i] 表示以第 i 对结尾的最长链，枚举所有 j < i，当 pairs[j][1] < pairs[i][0] 时转移。容易理解，但时间复杂度为 O(n²)。

面试追问

  • 为什么按左端点排序后“能接就选”不一定正确？
  • 若连接条件改为 b ≤ c，代码应修改哪里？
  • 如何恢复出一条具体的最长链，而不只返回长度？
  • 这与区间调度问题有什么对应关系？

常见错误

  • 按左端点排序，错过结束更早的数对。
  • 把严格比较 left > chainEnd 写成 left ≥ chainEnd。
  • 以 0 初始化链尾，导致全部为负数时出错。
  • 误以为必须保持原数组中的相对顺序。

import java.util.Arrays;

class Solution {
    public int findLongestChain(int[][] pairs) {
        Arrays.sort(pairs, (a, b) -> Integer.compare(a[1], b[1]));

        int count = 0;
        int chainEnd = Integer.MIN_VALUE;

        for (int[] pair : pairs) {
            if (pair[0] > chainEnd) {
                count++;
                chainEnd = pair[1];
            }
        }
        return count;
    }
}
