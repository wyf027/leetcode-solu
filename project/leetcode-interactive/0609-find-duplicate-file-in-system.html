在系统中查找重复文件

一批目录记录里，文件名各不相同，文件内容却可能悄悄“撞车”。请把内容完全相同的文件路径收进同一组。

Problem

题目说明

答案顺序任意

给定字符串数组 paths。每个字符串先给出一个目录路径，随后给出该目录下至少一个形如 文件名(文件内容) 的文件。请返回所有重复文件组：同一组内的文件内容必须完全相同，并且每组至少包含两个文件。每个结果项使用完整路径 目录路径/文件名。

参数形式

findDuplicate(paths: string[]) → string[][]
每条目录记录由单个空格分隔目录路径与各文件信息；每个目录只出现一次。

官方示例

示例 1

输入 
paths = [
  "root/a 1.txt(abcd) 2.txt(efgh)",
  "root/c 3.txt(abcd)",
  "root/c/d 4.txt(efgh)",
  "root 4.txt(efgh)"
]
输出 
[
  ["root/a/2.txt","root/c/d/4.txt","root/4.txt"],
  ["root/a/1.txt","root/c/3.txt"]

[

  ["root/a/1.txt","root/c/3.txt"]

说明：结果组之间、同一组内的顺序都不作要求，因此其他等价排列也正确。

约束

  • 1 ≤ paths.length ≤ 2 × 10⁴
  • 1 ≤ paths[i].length ≤ 3000
  • 1 ≤ Σ paths[i].length ≤ 5 × 10⁵
  • paths[i] 只包含英文字母、数字、/、.、(、) 和空格。
  • 同一目录中，文件与目录不会同名；每条目录信息对应唯一目录。
  • 目录路径与文件信息之间、相邻文件信息之间均由一个空格分隔。

Complete solution

题解：按内容建立反向索引

核心洞察

题目问的是“哪些路径拥有同一份内容”，因此自然的索引方向不是 路径 → 内容，而是 内容 → 所有完整路径。扫描时把每个文件路径追加到它的内容桶里，扫描完只保留大小至少为 2 的桶。

完整过程

  1. 拆目录。用空格切分每条记录，第 0 项是目录路径，其余项是文件描述。
  2. 拆文件。对每个 name(content) 找到左括号；左侧得到文件名，括号之间得到内容。
  3. 拼完整路径。生成 directory + "/" + fileName。
  4. 归入内容桶。在哈希表中以内容为键，把完整路径追加到对应数组。
  5. 过滤。遍历哈希表，只把长度大于 1 的路径数组加入答案。

正确性证明

引理 1：每个输入文件恰好进入一个桶。扫描会访问每条目录记录中的每个文件一次；该文件的内容是唯一确定的哈希键。
引理 2：同一桶中的任意两个路径对应内容相同的文件。因为它们只有在内容字符串相等时才使用同一个键。
引理 3：内容相同的任意两个文件一定进入同一桶。相等字符串在哈希表查找中对应同一个键。
结论：大小至少为 2 的桶恰好是一组重复文件；过滤掉单元素桶后，算法返回且仅返回全部重复文件组。

复杂度与边界

令 S 为所有输入字符串的总长度。拆分、解析和构造路径总计 O(S) 时间；保存内容键及所有路径需要 O(S) 空间（也可按文件总路径与内容长度更精细地表示）。

  • 只有一个文件：其桶大小为 1，不输出。
  • 没有重复：所有桶都会被过滤，返回空数组。
  • 同一内容出现多次：所有路径都保留在同一组。
  • 根目录记录：照常拼成 root/file.txt。
  • 结果顺序不要求固定，不要为题意之外的排序增加成本。

class Solution {
    public List<List<String>> findDuplicate(String[] paths) {
        Map<String, List<String>> byContent = new HashMap<>();

        for (String entry : paths) {
            String[] parts = entry.split(" ");
            String directory = parts[0];

            for (int i = 1; i < parts.length; i++) {
                String file = parts[i];
                int leftParen = file.indexOf('(');
                String name = file.substring(0, leftParen);
                String content = file.substring(leftParen + 1, file.length() - 1);
                String fullPath = directory + "/" + name;

                byContent
                    .computeIfAbsent(content, key -> new ArrayList<>())
                    .add(fullPath);
            }
        }

        List<List<String>> answer = new ArrayList<>();
        for (List<String> group : byContent.values()) {
            if (group.size() > 1) {
                answer.add(group);
            }
        }
        return answer;
    }
}

 * @param {string[]} paths

var findDuplicate = function(paths) {
    const byContent = new Map();

    for (const entry of paths) {
        const parts = entry.split(" ");
        const directory = parts[0];

        for (let i = 1; i < parts.length; i++) {
            const file = parts[i];
            const leftParen = file.indexOf("(");
            const name = file.slice(0, leftParen);
            const content = file.slice(leftParen + 1, -1);
            const fullPath = directory + "/" + name;

            if (!byContent.has(content)) {
                byContent.set(content, []);
            }
            byContent.get(content).push(fullPath);
        }
    }

    return Array.from(byContent.values())
        .filter(group => group.length > 1);
};
from collections import defaultdict
from typing import List


class Solution:
    def findDuplicate(self, paths: List[str]) -> List[List[str]]:
        by_content = defaultdict(list)

        for entry in paths:
            parts = entry.split(" ")
            directory = parts[0]

            for file in parts[1:]:
                left_paren = file.index("(")
                name = file[:left_paren]
                content = file[left_paren + 1:-1]
                full_path = directory + "/" + name
                by_content[content].append(full_path)

        return [
            group
            for group in by_content.values()
            if len(group) > 1
        ]
class Solution {
public:
    vector<vector<string>> findDuplicate(vector<string>& paths) {
        unordered_map<string, vector<string>> byContent;

        for (const string& entry : paths) {
            stringstream stream(entry);
            string directory;
            stream >> directory;

            string file;
            while (stream >> file) {
                size_t leftParen = file.find('(');
                string name = file.substr(0, leftParen);
                string content = file.substr(
                    leftParen + 1,
                    file.size() - leftParen - 2
                );
                byContent[content].push_back(directory + "/" + name);
            }
        }

        vector<vector<string>> answer;
        for (auto& [content, group] : byContent) {
            if (group.size() > 1) {
                answer.push_back(move(group));
            }
        }
        return answer;
    }
};

替代方案与真实文件系统

本题把内容直接放在输入字符串里，因此用完整内容作键最直接。真实文件系统中，直接读取并保存每个大文件的全部内容并不现实，可以采用分层筛选：

  1. DFS 或 BFS 遍历目录；二者都能覆盖全部文件，选择取决于目录规模与工程约束。
  2. 先按文件大小分组，大小不同必不重复。
  3. 对同大小候选文件分块读取（例如每次 1 KB）并计算强哈希。
  4. 对哈希相同的候选做逐字节比较，消除哈希碰撞造成的误报。

若只按文件名或只按短哈希分组，都不能保证内容真的相同。

面试追问

  • DFS 还是 BFS？ 两者时间均与目录项数量线性相关；DFS 通常实现简单，BFS 可逐层处理，但宽目录队列可能更大。
  • GB 级文件？ 文件大小预筛 + 流式强哈希，避免一次载入内存。
  • 每次只能读 1 KB？ 为候选文件维护流式哈希状态，按块更新。
  • 瓶颈？ 通常是磁盘 I/O；可先用大小和局部采样减少全量读取。
  • 如何避免误报？ 哈希仅用于候选筛选，最终逐字节比较。

常见错误

  • 把文件名当成键；重复的定义基于内容，而不是名字。
  • 忘记拼接目录，导致不同目录中的同名文件路径无法区分。
  • 把只有一个路径的内容桶也放进答案，违反“至少两个文件”。
  • 解析内容时把末尾右括号留在字符串中，造成看似相同的内容键不一致。
  • 强行排序后用固定顺序比对结果；题目允许任意顺序。
  • 真实文件系统场景只比较哈希，不做最终字节确认，存在碰撞误报风险。
